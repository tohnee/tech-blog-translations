# VeRL-Omni v0.2.0：更快的扩散 RL 与更稳定的 Omni 训练

> 原文：[VeRL-Omni v0.2.0: Faster Diffusion RL and Stable Omni Training](https://vllm.ai/blog/2026-08-20-verl-omni-v0-2-0) · vLLM 博客

作者：VeRL-Omni 团队

[#多模态](https://vllm.ai/blog/tags/multimodal)[#rlhf](https://vllm.ai/blog/tags/rlhf)[#生态](https://vllm.ai/blog/tags/ecosystem)[#性能](https://vllm.ai/blog/tags/performance)

继我们 5 月就 [VeRL-Omni](https://github.com/verl-project/verl-omni) 发布[公告](https://vllm.ai/blog/2026-05-14-verl-omni)之后，`v0.2.0` 为生产级全模态强化学习奠定了更坚实的基础。本次发布在 rollout 性能、模型集成、奖励支持、硬件覆盖与文档等方面全面改进了训练技术栈，其中两项改动影响最大：

- 更快的扩散 RL，核心是通过 vLLM-Omni 实现更高吞吐的 Qwen-Image FlowGRPO rollout，以及 verl V1 训练器支持。
- 稳定的 omni 训练，围绕 omni V1 训练器、可复用模型适配器、FSDP2 与 vLLM-Omni rollout 构建。

![](https://vllm.ai/blog-assets/figures/2026-08-20-verl-omni-v0-2-0/verl_omni_v0_2_0_blog_overview.png)

## 1. 更快的扩散 RL

扩散 RL 很昂贵，但昂贵的方式与自回归语言模型 RL 不同。单次 rollout 涉及多个去噪步、大型潜变量张量、提示嵌入、可选的无分类器引导（classifier-free guidance）、奖励模型打分、旧 log-prob 重算以及策略权重同步。对 Qwen-Image FlowGRPO 而言，性能画像中并没有单一元凶。步耗时由 rollout 生成、旧 log-prob 计算、奖励打分、actor 更新与 LoRA 权重同步共同决定。

### 关键特性

更快的扩散 RL 工作包含两个主要特性。

- 请求级批处理领衔 rollout 一侧。对受支持的扩散适配器，它成为 vLLM-Omni 的默认 rollout 路径。vLLM-Omni 不再通过串行循环发送扩散生成请求，而是把兼容的请求打包进更大的 transformer 前向，并暴露显式的并发旋钮来调度 rollout 工作。
- 训练器路径同样关键。扩散模型现在拥有 V1 训练器路径，使扩散 RL 更接近 VeRL-Omni 其他部分使用的现代训练器架构，并为解耦 rollout 与训练执行奠定基础。

更快的 rollout 只有在生成的轨迹与 log-prob 仍然描述同一个策略时才有意义。本次发布修复了若干对正确性敏感的环节：请求级批处理的扩散 log-prob、异步 rollout 语义、rank 本地的 LoRA 权重更新路径，以及可选 rollout 修正配方所使用的钩子。

### 配方与基准测试

Qwen-Image LoRA OCR 配方是观察这一变化的好例子。在 v0.1 系列中，rollout 是核心瓶颈：每个请求实际上以串行的 `B≈1` DiT 前向运行，10 个去噪步、True-CFG 把每步翻倍成两次前向。GPU 利用率徘徊在 `80%` 左右，不是因为模型小，而是因为引擎无法把足够的扩散工作打包在一起。

在 `v0.2.0` 中，vLLM-Omni 的请求级打包改变了这一形态。多个完整请求被打包进一次 transformer 前向，GPU 利用率升至约 `100%`，单独的生成时间从 `226s` 降至 `108s`，降幅 `52%`。同样的故事也出现在每张图像的生成延迟上，使用打包的 vLLM-Omni rollout 路径后随之下降。参考运行：[Qwen-Image OCR LoRA v0.1](https://wandb.ai/mikecheung/flow_grpo/runs/o7x44yrr) 与 [Qwen-Image OCR LoRA v0.2](https://wandb.ai/mikecheung/flow_grpo/runs/1vsrnhbd)。

生产风格的 Qwen-Image FlowGRPO LoRA 配方默认启用 vLLM-Omni 请求级批处理。基线 OCR 奖励设置的主入口是 `run_qwen_image_ocr_lora.sh`。加速来自关闭逐步执行，并让 vLLM-Omni 引擎调度多个 rollout 请求直至 `max_num_seqs`：

```
actor_rollout_ref.rollout.step_execution=false
++actor_rollout_ref.rollout.engine_kwargs.vllm_omni.max_num_seqs=32
```

对于 512 px、True-CFG 的 Qwen-Image LoRA，实用的调优范围是 `max_num_seqs=8` 到 `32`；更大的值可能遇到 HBM 压力。SD3.5 的请求级内存占用更轻，可以使用 `max_num_seqs=256`。

配方层面的步耗时数字与这个故事吻合：基线 Qwen-Image FlowGRPO LoRA 运行在 4 × H800 上每步约 `420s`，而异步奖励变体在 5 块 GPU 上达到每步约 `360s`。

## 2. 稳定的 Omni 训练

发布的另一半是稳定的 omni 训练。Omni 模型不只是更大的语言模型；它们是带有处理器、模态专属塔、可训练阶段，以及必须与 actor 保持一致的 rollout 行为的小型系统。`v0.2.0` 把项目从模型特定的集成推向可复用的 omni 训练栈，使多模态自回归训练更自然地融入 VeRL-Omni 的训练器、适配器、rollout 与配方结构。

### 关键特性

在这里，本次发布拉动了两个杠杆。

一个杠杆是 `verl` V1 训练器架构。Omni 配方获得更清晰的 worker 编排、标准的配置覆盖，以及与 vLLM-Omni rollout 更好的对齐。

另一个是可复用的 omni 模型适配器层。训练器不再把每个架构接成一次性路径，而是可以依靠一个共享接口完成模型设置、处理器设置、可训练阶段选择、FSDP 准备与 rollout 对齐。

仓库级的调用流程大致如下：

![Omni PPO trainer and OmniModelBase adapter call flow](https://vllm.ai/blog-assets/figures/2026-08-20-verl-omni-v0-2-0/omni-ppo-adapter-flow.svg)

Omni PPO 训练器与 OmniModelBase 适配器调用流程


Omni PPO 训练器与 OmniModelBase 适配器调用流程。

模块边界刻意保持很窄。`main_omni.py` 只负责判定一个在线 omni 作业应进入 verl PPO V1 路径。PPO 训练器随后掌管通用的 RL 循环：rollout 调度、优势计算与策略更新。构建 actor 模型时，FSDP omni 引擎加载 Hugging Face 模型，并让 `OmniModelBase` 为配置的架构与阶段解析适配器。适配器就是模型特定工作所在之处。对于 Qwen3-Omni thinker 训练，`Qwen3OmniThinkerAdapter` 会剥离未激活的模块、把 `forward` 重定向到 thinker 组件，并在控制权交还给 PPO 循环之前准备好处理器与 rollout 对齐钩子。

### 配方与基准测试

最值得突出介绍的单个配方是 **MMK12**。它以真实多模态输入演练了新的稳定 Qwen3-Omni 路径：图像加文本提示、文本答案、GSPO 优化、FSDP actor 训练与 vLLM-Omni rollout。

**MMK12 锚定配方。** `run_qwen3_omni_thinker_gspo_lora_mmk12_v1.sh` 用 GSPO、LoRA rank 32，在 4 × H800 80GB 上以共置的 actor-rollout worker 训练 Qwen3-Omni 完成 K12 视觉数学推理（`image -> text`）。rollout 形状为 128 提示 × 16 回答，即每次 rollout 2048 个样本。训练后，该运行达到 `0.833` 验证奖励、`0.998` actor-rollout Pearson 相关系数，以及约 `59 GB` GPU 内存占用。部分训练结果见参考运行：[`MMK12 (wandb)`](https://wandb.ai/mikecheung/gspo/runs/2j8hxr36)。

MMK12 数据流水线把原始 MMK12 parquet 分片转换为 verl RL parquet 布局。每行内联携带图像字节，并使用要求模型给出结构化答案的提示格式。奖励将 `math_verify` 准确性与基于 `<answer>...\boxed{}...</answer>` 模板的渐进式格式奖励相结合。

运行该配方：

```
python examples/gspo_trainer/data_process/mmk12.py \
    --local_dataset_path /path/to/mmk12/ \
    --local_save_dir ~/data/mmk12

TRAIN_FILE=$HOME/data/mmk12/train.parquet \
VAL_FILE=$HOME/data/mmk12/test.parquet \
bash examples/gspo_trainer/qwen3_omni/run_qwen3_omni_thinker_gspo_lora_mmk12_v1.sh
```

这为 `v0.2.0` 的稳定性故事提供了锚点：Qwen3-Omni 训练不再只是一个模型特定的启动路径。它是一个 V1 训练器配方，带有可复用的 omni 适配器、多模态数据处理、actor-rollout 一致性指标，以及一个有文档记录的图生文（image-to-text）基准测试。
