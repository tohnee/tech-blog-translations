# 信号决策驱动的架构：重塑大规模语义路由

> 原文：[Signal-Decision Driven Architecture: Reshaping Semantic Routing at Scale](https://vllm.ai/blog/2025-11-19-signal-decision) · vLLM 博客

vLLM Semantic Router 团队

[#生态系统](https://vllm.ai/blog/tags/ecosystem)

早期的 vLLM Semantic Router 版本依赖基于分类的路由：这是一种直观的方案，将用户查询分类到 14 个 MMLU 领域类别之一，然后路由到对应的模型。这在基础场景下可行，但在为企业构建生产级 AI 系统时，我们很快发现了它的局限。

设想这样一个真实场景：用户提问「我需要紧急帮助审查我认证代码中的安全漏洞」。基于分类的路由器会将其识别为「计算机科学」查询并路由到一个通用编码模型。但它遗漏了关键上下文：

- 需要立即关注的**紧急性**信号
- 需要专业知识和越狱防护的**安全**敏感性
- 能从推理能力中获益的**代码审查**意图
- 需要仔细分析的**认证**复杂性

这一个例子就揭示了根本性约束：**基于分类的路由只捕捉用户意图的一个维度——领域——而忽视了自然语言查询中蕴含的丰富的多维信号。**

今天，我们推出**信号决策架构（Signal-Decision Architecture）**——对语义路由的彻底重新构想，从 14 个固定类别扩展到无限的智能路由决策。这一新架构结合了多维信号提取、支持 AND/OR 运算符的灵活决策逻辑，以及内置的插件编排，交付可用于生产环境的语义智能。

![](https://vllm.ai/blog-assets/figures/semantic-router/signal-0.png)

## 问题：为什么基于分类的路由无法扩展

先前的 vLLM Semantic Router 架构遵循一条简单的流水线：

```
User Prompt → MMLU Domain Classification → Model Selection
```

这一方案存在若干根本性局限，使其无法满足企业级需求。

### 单维度分析

基于分类的路由只考虑查询的**领域**或**主题**。它无法捕捉：

- **紧急性信号**：「urgent」「immediate」「critical」
- **安全敏感性**：「vulnerability」「exploit」「breach」
- **意图类型**：代码审查、架构设计、故障排查
- **复杂度级别**：简单 FAQ 与复杂推理任务
- **合规要求**：PII 处理、监管约束

**实际影响**：一条关于「紧急患者数据泄露」的医疗查询会被路由到医疗模型，却缺乏 PII 保护和安全过滤——可能违反 HIPAA 合规。

### 固定类别约束

受限于 14 个预定义的 MMLU 类别（数学、物理、计算机科学、商业等），导致无法：

- 为特定业务领域创建自定义类别
- 在一个领域内定义细粒度的路由规则
- 扩展到学术学科分类之外

**实际影响**：一个拥有 50 多个专用用例（法律合同、金融合规、医疗诊断、代码安全审计）的企业，无法在 14 个类别之内表达其路由需求。

### 僵化的逻辑

无法组合多个条件或实现复杂的路由策略：

- 不支持 AND/OR 逻辑：「仅当查询既紧急又涉及安全时才路由到专家模型」
- 多个条件匹配时没有基于优先级的选择
- 无法基于信号组合有条件地应用插件

**实际影响**：无法实现分层路由策略，例如「高优先级安全问题获得推理 + 越狱防护，而一般问题直接返回缓存响应」。

![](https://vllm.ai/blog-assets/figures/semantic-router/signal.png)

## 介绍信号决策架构

信号决策架构从根本上重新构想语义路由：将信号提取与路由决策分离，并引入一个内置插件编排的灵活决策引擎。

### 架构概览

![](https://vllm.ai/blog-assets/figures/semantic-router/signal-1.png)

新架构带来三项关键创新：

1. **多信号提取**：同时捕捉用户意图的多个维度
2. **决策引擎**：使用灵活的 AND/OR 逻辑结合信号，并支持基于优先级的选择
3. **插件链**：为缓存、安全与优化提供内置智能

## 核心概念

### 信号：多维提示分析

信号决策架构不再仅依赖领域分类，而是从每个用户查询中提取三类互补的信号。每种信号类型利用不同的 AI/ML 技术，并在路由决策过程中承担不同的职责。

![](https://vllm.ai/blog-assets/figures/semantic-router/signal-3.png)

#### 关键词信号：可解释的模式匹配

关键词信号使用基于正则表达式的模式匹配来检测用户查询中的特定词语或短语。这一方案提供**人类可解释的路由逻辑**——通过检查关键词，你可以轻松理解某条查询为何匹配了某个规则。

**技术方案**：

- 预编译的正则模式，实现高效匹配
- 支持 AND/OR 布尔运算符
- 支持区分大小写与不区分大小写模式
- 无需模型推理（零 ML 开销）

**关键优势——可解释性**：与黑盒 ML 模型不同，关键词信号提供完全的透明度。调试路由决策时，你可以精确追踪哪些关键词触发了哪些规则。这对合规审计和生产问题排查至关重要。

**使用场景**：

- 检测紧急性标记：「urgent」「immediate」「asap」「critical」
- 识别安全关键词：「vulnerability」「exploit」「breach」「CVE」
- 标记合规术语：「HIPAA」「GDPR」「PII」「confidential」
- 识别意图模式：「code review」「architecture design」「troubleshooting」

#### 嵌入信号：可扩展的语义理解

嵌入信号使用神经嵌入模型计算用户查询与候选短语之间的语义相似度。这一方案提供**可扩展的语义匹配**，能够理解精确关键词之外的含义。

**技术方案**：

- 为候选短语离线预计算嵌入
- 运行时使用轻量模型（如 sentence-transformers）计算查询嵌入
- 带可配置阈值的余弦相似度计算
- 多种聚合策略：max（任一匹配）、mean（平均相似度）、any（基于阈值）

**关键优势——可扩展性**：基于嵌入的匹配可以高效扩展到数千个候选短语。新增路由模式无需重新训练模型——只需添加新的候选短语并计算其嵌入。这为特定业务领域的快速迭代与定制化提供了可能。

**使用场景**：

- 意图理解：「I need help」→「technical support request」
- 同义改写匹配：「How do I fix this bug?」≈「debugging assistance」
- 跨语言路由：借助多语言嵌入，语义相似度可以跨语言工作
- 模糊匹配：处理错别字、缩写与非正式表达

#### 领域信号：数据集驱动的分类

领域信号使用 MMLU 训练的分类模型来识别用户查询的学术或专业领域。这一方案提供**数据集驱动的领域专长**，并支持自定义领域扩展。

**技术方案**：

- 在 MMLU 数据集（14 个基础类别）上微调的分类模型
- 通过 **LoRA 适配器**支持自定义领域扩展
- 对跨多个领域的查询支持多标签分类
- 领域预测的置信度打分

**关键优势——通过 LoRA 实现可扩展性**：基础模型覆盖 14 个 MMLU 类别，而企业可以训练轻量的 LoRA 适配器来添加**私有领域类别**，无需重新训练整个模型。例如：

- 医疗健康：添加「medical\_imaging」「clinical\_trials」「pharmaceutical\_research」
- 金融：添加「risk\_modeling」「algorithmic\_trading」「regulatory\_compliance」
- 法律：添加「contract\_law」「intellectual\_property」「litigation\_support」

这让组织能够把领域分类扩展到自己的垂直行业，同时保留基础模型的通用知识。

![](https://vllm.ai/blog-assets/figures/semantic-router/signal-4.png)

**使用场景**：

- 路由到领域专属的专家模型（数学查询 → math-expert）
- 应用领域适用的策略（医疗查询 → PII 保护）
- 选择专门的知识库（法律查询 → 法律文档检索）
- 触发领域专属插件（代码查询 → 语法校验）

### 信号类型对比

| 信号类型 | 技术 | 可解释性 | 可扩展性 | 可扩展能力 |
| --- | --- | --- | --- | --- |
| 关键词 | 正则匹配 | 高（规则透明） | 中（手工编写模式） | 手工添加 |
| 嵌入 | 神经嵌入 | 低（黑盒相似度） | 高（数千个短语） | 动态添加短语 |
| 领域 | MMLU + LoRA | 中（领域标签） | 中（14+ 类别） | 用 LoRA 适配器添加自定义领域 |

### 为什么是三种信号类型？

这三种信号类型是**互补的**，而非冗余：

- **关键词信号**为已知模式提供快速、可解释的匹配
- **嵌入信号**处理语义变体，并可扩展到大规模短语集合
- **领域信号**利用学术数据集，提供领域专属专长

将三者结合，信号决策架构可以同时捕捉用户意图的多个维度，实现任何单一信号类型都无法企及的复杂路由逻辑。

### 决策：灵活的路由逻辑

决策是核心路由规则，它使用 AND/OR 逻辑组合多个信号，以确定模型选择与插件配置。

#### 决策结构

每个决策由以下部分构成：

**信号组合**：使用 AND/OR 逻辑组合多个信号条件

- AND：所有条件都必须匹配（高精度）
- OR：任意条件匹配即可（高召回）

**优先级**：用于多个决策同时匹配时的冲突消解的整数值

- 优先级更高者胜出
- 支持分层路由策略

**模型引用**：指定使用哪个模型（以及可选的 LoRA 适配器）

- 支持基础模型搭配领域专属 LoRA 适配器
- 配置推理模式与 effort 级别

**插件链**：按顺序应用的插件列表

- 用于成本优化的语义缓存
- 用于安全的越狱检测
- 用于合规的 PII 保护
- 用于行为控制的系统提示注入
- 用于元数据传递的头部改写

#### 决策评估流程

![](https://vllm.ai/blog-assets/figures/semantic-router/signal-5.png)

当多个决策匹配时，系统选择优先级最高的那个。如果没有决策匹配，系统回退到默认模型。

### 插件：内置智能

该架构包含五个内置插件，可在每个决策中单独配置：

| 插件 | 用途 | 关键特性 |
| --- | --- | --- |
| **semantic-cache** | 缓存相似查询 | 可配置相似度阈值、成本优化 |
| **jailbreak** | 检测提示注入攻击 | 基于阈值的检测、请求拦截 |
| **pii** | 保护敏感信息 | 脱敏/哈希/掩码模式、GDPR/HIPAA 合规 |
| **system\_prompt** | 注入自定义指令 | 替换或插入模式、角色定制 |
| **header\_mutation** | 修改 HTTP 头部 | 添加/更新/删除头部、元数据传递 |

插件按配置顺序执行，每个插件都可以修改请求、阻止执行，或为下游处理添加元数据。

## 从 14 扩展到无限

信号决策架构移除了固定类别的根本性约束。它的扩展方式如下：

### 传统方案（受限）

```
14 MMLU Categories → 14 Routing Rules → 14 Model Selections
```

**约束**：

- 无法创建自定义类别
- 无法组合多个条件
- 无法按规则应用不同策略
- 无法扩展到领域分类之外

### 信号决策方案（无限）

```
3 Signal Types × N Conditions × AND/OR Logic → Unlimited Decisions
```

**能力**：

- 创建无限的自定义路由规则
- 用灵活逻辑组合多个信号
- 为每个决策应用独特的插件链
- 扩展到企业级的复杂性

### 可扩展性示例

设想一个企业 IT 支持系统：

**传统路由**：仅限于 14 条基于领域的路由

- 「computer\_science」→ code-model
- 「engineering」→ engineering-model
- （另有 12 个固定类别）

**信号决策路由**：数百条专门化路由

- 紧急 + 安全 + 计算机科学 → security-expert + 推理 + 越狱防护
- 代码审查 + 高复杂度 → architecture-model + 推理
- FAQ + 一般 → cached-model + 语义缓存
- 医疗 + 检测到 PII → medical-expert + PII 保护 + 免责声明
- 法律 + 机密 → law-expert + PII 哈希 + 审计头部
- （还有数百种自定义组合）

每个决策都可以有独特的模型选择、推理配置和插件链——实现大规模下的细粒度控制。

## 真实世界应用

### 企业 IT 支持

**挑战**：根据紧急性、技术领域和安全敏感性路由支持工单。

**方案**：带优先级选择的多层决策

- 优先级 100：紧急 + 安全 + CS → security-expert + 推理 + 越狱防护
- 优先级 80：技术支持 + 调试 → code-expert + 语义缓存
- 优先级 60：一般问题 → general-model + 激进缓存

**结果**：恰当的模型选择、通过缓存实现的成本优化、针对敏感问题的安全防护。

### 医疗健康平台

**挑战**：HIPAA 合规要求 PII 保护和医疗免责声明。

**方案**：带强制合规插件的领域路由

- 健康领域 → medical-expert + PII 脱敏 + 免责声明提示 + 审计头部

**结果**：自动 PII 保护、一致的免责声明、满足合规要求的审计追踪。

### 金融服务

**挑战**：多层安全，包括 PII 保护、越狱检测和成本优化。

**方案**：面向金融查询的综合插件链

- 经济学领域 → finance-expert + 越狱防护 + PII 哈希 + 免责声明 + 缓存 + 合规头部

**结果**：企业级安全、监管合规、成本效益。

### 教育平台

**挑战**：基于学科和学习意图的个性化学习体验。

**方案**：带定制教学风格的意图路由

- 数学 + 学习意图 → math-expert + 推理 + 耐心导师提示 + 缓存
- 科学 + 教程 → science-expert + 生动的教育者提示

**结果**：个性化的教学方式、针对复杂主题的恰当推理、成本优化。

### 代码助手

**挑战**：不同复杂度级别需要不同的模型能力。

**方案**：带推理控制的复杂度感知路由

- 架构设计 → 推理模型 + 高 effort + 复杂度头部
- 代码审查 → code-expert + 中推理 + 缓存
- 简单问题 → code-expert + 仅缓存

**结果**：最优模型选择、高性价比的推理使用、简单查询的快速响应。

## 未来路线图

信号决策架构为多个维度的未来增强奠定了基础：

### 路由核心性能优化

**用于关键词匹配的基数树（Radix Tree）**：用基数树数据结构取代基于正则的关键词匹配，为数以千计的关键词模式实现更快的匹配。这将使企业能够以一致的性能定义 10,000+ 条关键词规则。

**用于嵌入搜索的 HNSW 索引**：实现分层可导航小世界（HNSW）图，用于嵌入空间的近似最近邻搜索。这将在支持数百万候选短语的同时，显著提升嵌入信号的性能。

**面向仅解码模型的并行 LoRA**：支持在解码阶段并行执行多个 LoRA 适配器，让单个基础模型同时服务多个专门化领域。这将减少模型切换开销，并提高多租户部署的吞吐量。

### 功能增强

**可视化配置控制台**：基于 Web 的 UI，无需编辑 YAML 即可创建和管理决策，并具备实时校验与测试能力。

**自定义插件框架**：用于开发自定义插件的 SDK，配套社区市场，让企业能够构建领域专属的智能层。

**高级分析**：实时监控决策性能、信号有效性以及成本优化机会，并给出 ML 驱动的建议。

**基于多轮对话的模型评估**：通过多轮对话评估实现智能模型选择。系统自动让多个候选模型进行并行对话，使用 LLM-as-a-Judge 从连贯性、相关性、安全性和领域专长等维度评估响应质量。这使路由优化能够基于实际模型表现而非静态规则进行动态调整。

**意图感知的内部/外部模型选择**：基于意图分析，在内部私有模型与外部 API（OpenAI、Anthropic 等）之间进行智能路由。敏感数据和专有信息自动路由到内部模型以满足隐私与合规要求，而一般查询则利用外部 API 获取更广泛的知识。成本、延迟与合规要求会根据查询特征进行动态权衡。
