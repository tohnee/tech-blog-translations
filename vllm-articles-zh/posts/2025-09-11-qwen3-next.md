# vLLM 现已支持 Qwen3-Next：极致高效的混合架构

> 原文：[vLLM Now Supports Qwen3-Next: Hybrid Architecture with Extreme Efficiency](https://vllm.ai/blog/2025-09-11-qwen3-next) · vLLM 博客

作者：vLLM 团队

[#模型支持](https://vllm.ai/blog/tags/model-support)

我们很高兴地宣布，**vLLM 现已支持 Qwen3-Next**——Qwen（通义千问）团队最新一代基础模型。Qwen3-Next 引入了**面向长上下文支持的极致高效混合架构**，vLLM 对其各项功能提供完整支持。

![](https://vllm.ai/blog-assets/figures/qwen3-next/qwen.png)

在这篇文章中，我们将探讨 Qwen3-Next 的创新——混合注意力、高稀疏 MoE 与多 token 预测——并展示 vLLM 如何高效地支持它们。

## **快速上手**

你可以通过 vLLM nightly 安装来运行 Qwen3-Next：

`uv pip install vllm --extra-index-url https://wheels.vllm.ai/nightly --torch-backend=auto`

然后启动：

`vllm serve Qwen/Qwen3-Next-80B-A3B-Instruct -tp 4`

更详细的安装与使用指南请参阅 [vLLM Model Recipes](https://docs.vllm.ai/projects/recipes/en/latest/Qwen/Qwen3-Next.html)。

## **混合注意力：高效的上下文建模**

Qwen3-Next 的核心是其**混合注意力（Hybrid Attention）**设计，用以下组合取代标准注意力：

- **Gated DeltaNet**（面向长上下文效率的线性注意力）
- **Full Attention**（面向高保真推理的完整注意力）

模型在各层之间交错使用这两种注意力形式，实现向 **65K 上下文长度**及以上的高效扩展。

为支持这一点，vLLM 集成了来自 [Flash Linear Attention](https://github.com/fla-org/flash-linear-attention) 的 Triton 内核，并采用[混合 KV 缓存管理器](https://arxiv.org/abs/2503.18292)来同时管理线性注意力层与完整注意力层，避免碎片化并最大化 GPU 利用率。

为了管理 Qwen3-Next 这类混合模型的状态，vLLM 会自动调整完整注意力层的"逻辑"块大小，确保完整注意力层与线性注意力层的状态占用等量的"物理"GPU 内存。这使得混合模型也能享受简单高效的分页内存管理，在 GPU 内存被完全占满的重负载场景下提升吞吐量。

![](https://vllm.ai/blog-assets/figures/qwen3-next/hybrid.png)

此外，Flash Linear Attention 基于 Triton。启动 Triton 内核可能带来显著的 CPU 开销，对纯解码（decode-only）批次的影响尤其不成比例。为克服这一点，vLLM 默认启用完整 CUDA Graph 模式，确保低延迟场景下依然有良好性能。

## **高稀疏 MoE：极致效率**

Qwen3-Next 把稀疏性推得更远：**MoE 层的激活比例为 1:50**。在旗舰 **80B-A3B 模型**中，每个 token 只有 **3B 参数被激活**。凭借内置的高效 MoE 实现，vLLM 能够同时获得出色的吞吐量与延迟。

## **多 token 预测（MTP）**

Qwen3-Next 的另一项创新是**多 token 预测（multi-token prediction）**，它同时提升预训练效率与推理速度。vLLM 原生支持这一模式，让 Qwen3-Next 每步解码多个 token，而无需修改应用代码。具体用法请参阅 recipe 文档。

## **展望未来**

我们的 Qwen3-Next 集成只是开始。路线图包括：

- 对 GatedDeltaNet 层的进一步内核优化。
- 更好的内存管理，以及为混合模型支持自动前缀缓存与 P/D 分离。
- 持续提升吞吐量并降低 CPU 开销。
