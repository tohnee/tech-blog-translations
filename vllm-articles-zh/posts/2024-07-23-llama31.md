# vLLM 正式支持 Llama 3.1

> 原文：[Announcing Llama 3.1 Support in vLLM](https://vllm.ai/blog/2024-07-23-llama31) · vLLM 博客

vLLM 团队

[#模型支持](https://vllm.ai/blog/tags/model-support)[#量化](https://vllm.ai/blog/tags/quantization)

今天，vLLM 团队很高兴与 Meta 合作，宣布对 Llama 3.1 模型系列的支持。Llama 3.1 带来了令人兴奋的新特性：更长的上下文长度（最高 128K token）、更大的模型规模（最高 405B 参数），以及更强大的模型能力。vLLM 社区为让更长、更大的 Llama 在 vLLM 上平稳运行添加了许多增强，其中包括分块预填充（Chunked Prefill）、FP8 量化和流水线并行（Pipeline Parallelism）。我们将在本篇博客中介绍这些新增强。

### 简介

vLLM 是一个快速、易用的大语言模型开源服务引擎。vLLM 支持 40 多种开源 LLM、多样的硬件平台（NVIDIA GPU、AMD GPU、AWS Inferentia、Google TPU、Intel CPU、GPU、Gaudi 等）以及各类推理优化。欲了解更多关于 vLLM 的信息，请点击[这里](https://docs.vllm.ai/)。

对于新的 Llama 3.1 系列，vLLM 可以以完整的 128K 上下文窗口运行这些模型。为了支持大上下文窗口，vLLM 会自动启用[分块预填充](https://www.linkedin.com/posts/joinanyscale_recently-weve-contributed-chunked-prefill-activity-7201277641490849792-lGqZ)。分块预填充不仅能将内存使用控制在合理范围内，还能减少长提示处理对正在进行中的请求造成的中断。你可以运行以下命令，或使用我们的官方 Docker 镜像（`vllm/vllm-openai`）来安装 vLLM：

```
pip install -U vllm
```

对于大型 Llama 405B 模型，vLLM 提供了多种运行方式：

- **FP8：** vLLM 可在 8xA100 或 8xH100 上原生运行官方 FP8 量化模型。
- **流水线并行（Pipeline Parallelism）：** vLLM 通过将模型的不同层放置在不同节点上，在多个节点上运行官方 BF16 版本。
- **张量并行（Tensor Parallelism）：** vLLM 也可以通过将模型切分到多个节点以及节点内的多块 GPU 上来运行。
- **AMD MI300x 或 NVIDIA H200：** vLLM 可在单台 8xMI300x 或 8xH200 机器上运行该模型，这两款 GPU 分别拥有 192GB 和 141 GB 显存。
- **CPU 卸载（CPU Offloading）：** 作为最后的手段，vLLM 可以在执行前向传播时将部分权重卸载到 CPU，让你在有限的 GPU 显存上以全精度运行大模型。

请注意，虽然 vLLM 支持上述所有方式，但其性能仍处于初步阶段。vLLM 社区正在积极进行优化，我们欢迎大家贡献。例如，我们正在积极探索更多模型量化方法，以及提升流水线并行吞吐量的途径。博客后文给出的性能数字仅作为早期参考；我们预计性能在未来几周内会显著提升。

在所有方式中，我们推荐单节点使用 FP8，多节点使用流水线并行。下面我们详细讨论这两者。

### FP8

FP8 用 8 个比特表示浮点数。当前一代 GPU（H100、MI300x）通过专用张量核心提供对 FP8 的原生支持。目前，vLLM 可以运行针对 KV 缓存、注意力层和 MLP 层的 FP8 量化模型。这可以减少内存占用、提高吞吐量、降低延迟，且精度损失极小。

目前，vLLM 支持通过 FBGEMM 量化的官方 Meta Llama 3.1 405B FP8 模型，利用 MLP 层中的逐通道（per-channel）量化。具体而言，up/gate/down 投影的每个通道都被量化并乘以一个静态缩放因子。结合跳过第一层和最后一层的量化，以及设置静态上限，这种方式对模型精度的影响极小。你可以在单台 8xH100 或 8xA100 上使用最新版 vLLM 运行该模型，命令如下：

```
$ vllm serve meta-llama/Meta-Llama-3.1-405B-Instruct-FP8 --tensor-parallel-size 8
```

使用 FP8 量化模型服务平均输入长度为 1024 token、平均输出长度为 128 token 的请求时，服务器可以维持每秒 2.82 个请求。相应的服务吞吐量分别为每秒 2884.86 个输入 token 和每秒 291.53 个输出 token。

我们还独立确认了 FP8 检查点的精度损失极小。例如，使用 lm-eval-harness 以 8-shot 和思维链（chain-of-thought）方式运行 GSM8K 基准测试，我们观察到精确匹配得分为 95.38%（+- 0.56% 标准差），相比 BF16 官方得分 96.8% 仅有极小下降。

### 流水线并行

如果你想在不对 Llama 3.1 405B 模型做量化的情况下运行它怎么办？你可以使用 16xH100 或 16xA100 GPU，借助 vLLM 的流水线并行来实现！

流水线并行将模型切分为更小的层组，以流水线方式在两个或更多节点上并行执行。与需要昂贵 all-reduce 操作的张量并行不同，流水线并行在层边界处对模型进行划分，只需廉价的点对点通信。当你拥有多个未必通过 Infiniband 等高速互连连接的节点时，这一点尤其有用。

vLLM 支持流水线并行与张量并行的组合。例如，在 2 个节点共 16 块 GPU 的情况下，你可以使用 2 路流水线并行和 8 路张量并行来优化硬件使用。这一配置将半个模型映射到每个节点，并将每一层切分到 8 块 GPU 上，使用 NVLink 执行 all-reduce 操作。你可以使用以下命令运行 Llama 3.1 405B 模型：

```
$ vllm serve meta-llama/Meta-Llama-3.1-405B-Instruct --tensor-parallel-size 8 --pipeline-parallel-size 2
```

如果你拥有 Infiniband 等高速互连，可以使用 16 路张量并行：

```
$ vllm serve meta-llama/Meta-Llama-3.1-405B-Instruct --tensor-parallel-size 16
```

![](https://vllm.ai/blog-assets/figures/llama31/perf_llama3.png)
在 16xH100 GPU 上使用合成数据集（平均输入长度 1024，平均输出长度 128）的服务吞吐量。

我们观察到，当节点之间没有通过 Infiniband 连接时，流水线并行至关重要。与 16 路张量并行相比，2 路流水线并行结合 8 路张量并行可带来 6.6x 的性能提升。另一方面，在配备 Infiniband 的情况下，两种配置的性能相近。

欲了解使用 vLLM 进行分布式推理的更多信息，请参阅[这份文档](https://docs.vllm.ai/en/latest/serving/distributed_serving.html)。关于 CPU 卸载，请参阅[这个示例](https://docs.vllm.ai/en/latest/getting_started/examples/cpu_offload.html)。
