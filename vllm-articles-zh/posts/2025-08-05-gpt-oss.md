# vLLM 现已支持 gpt-oss

> 原文：[vLLM Now Supports gpt-oss](https://vllm.ai/blog/2025-08-05-gpt-oss) · vLLM 博客

作者：vLLM 团队

[#模型支持](https://vllm.ai/blog/tags/model-support)[#性能](https://vllm.ai/blog/tags/performance)

我们很高兴地宣布，vLLM 现已支持 NVIDIA Blackwell 和 Hopper GPU 上的 gpt-oss，以及 AMD MI300x 和 MI355x GPU。在这篇博文中，我们将探讨 gpt-oss 的高效模型架构，以及 vLLM 如何支持它。

要快速上手 gpt-oss，你可以试试我们的容器：

```
docker run --gpus all \
    -p 8000:8000 \
    --ipc=host \
    vllm/vllm-openai:gptoss \
    --model openai/gpt-oss-20b

```

或将其安装到你的虚拟环境中：

```
uv pip install --pre vllm==0.10.1+gptoss \
    --extra-index-url https://wheels.vllm.ai/gpt-oss/ \
    --extra-index-url https://download.pytorch.org/whl/nightly/cu128 \
    --index-strategy unsafe-best-match

vllm serve openai/gpt-oss-120b

```

更多细节请参阅 [vLLM 用户指南](https://docs.vllm.ai/projects/recipes/en/latest/OpenAI/GPT-OSS.html)。

### **MXFP4 MoE**

gpt-oss 是一个稀疏 MoE 模型，拥有 128 个专家（120B）或 32 个专家（20B），每个 token 会被路由到 4 个专家（没有共享专家）。对于 MoE 权重，它使用 [MXFP4](https://arxiv.org/abs/2310.10537)——一种新颖的分组量化浮点格式，而注意力和其他层则使用标准 bfloat16。由于 MoE 占据了模型参数的绝大部分，仅对 MoE 权重使用 MXFP4 就将模型大小降至 63 GB（120B）和 14 GB（20B），使它们可以在单张 GPU 上运行（不过为了获得最佳性能，通常并不建议这样做）！

在 MXFP4 中，每个权重表示为 4 位浮点数（fp4 e2m1）。此外，MXFP4 为每组 32 个连续的 fp4 值引入一个 2 的幂次缩放因子，以表示宽广的数值范围。在硬件上运行时，两个 fp4 值被打包进内存中的单个 8 位单元，然后在 matmul 内核内即时解包用于计算。

为了高效运行 MXFP4 MoE，vLLM 通过与 OpenAI 和 NVIDIA 的合作集成了两个专用 GPU 内核：

- **Blackwell GPU（如 B200）：** 来自 [FlashInfer](https://github.com/flashinfer-ai/flashinfer) 的全新 MoE 内核。该内核由 NVIDIA 实现，使用 Blackwell 的原生 MXFP4 tensor core 以获得极致性能。
- **Hopper GPU（如 H100、H200）：** Triton [`matmul_ogs` 内核](https://github.com/triton-lang/triton/tree/main/python/triton_kernels)，由 OpenAI Triton 团队官方实现。该内核专门针对 Hopper 架构优化，包含 [swizzling](https://en.wikipedia.org/wiki/Swizzling_(computer_graphics)) 优化和内置启发式规则，无需手动调优。

### **高效注意力**

gpt-oss 拥有非常高效的注意力设计。它使用 GQA，具有 64 个 query 头和 8 个 KV 头。重要的是，该模型以 1:1 的比例交错全注意力与滑动窗口注意力（窗口大小为 **128**）。此外，模型的 head size 为 64，是标准 head size 128 的 50%。最后，每个 query 头都有一个训练得到的"注意力汇"（attention sink）向量。

为了高效支持这种注意力，vLLM 集成了来自 FlashInfer（Blackwell）和 FlashAttention 3（Hopper）的专用 GPU 内核。此外，我们还增强了 Triton 注意力内核，以便在 AMD GPU 上支持它。

此外，为了高效管理不同类型注意力（即全注意力和滑动窗口）下的 KV 缓存，vLLM 集成了[混合 KV 缓存分配器（hybrid KV cache allocator）](https://arxiv.org/abs/2503.18292)——这是由 vLLM 团队提出的一项新技术。借助混合 KV 缓存管理器，vLLM 可以在全注意力层和滑动窗口注意力层之间动态共享 KV 缓存空间，将潜在的内存碎片降至零。

### **内置工具支持：智能体循环与基于 MCP 的工具服务器**

gpt-oss 内置了对强大工具的支持，例如网页浏览和 Python 代码解释器。启用后，模型会自主决定何时以及如何调用这些工具，并无缝解读结果。

vLLM 通过集成 [OpenAI Responses API](https://platform.openai.com/docs/api-reference/responses) 和 gpt-oss 工具包，原生支持这些能力。通过这一集成，vLLM 实现了一个循环：解析模型的工具调用、实际调用搜索和代码解释器工具、解析其输出，并将其回传给模型。

另外，用户也可以启动一个符合 MCP 规范的外部工具服务器，让 vLLM 使用该工具服务器，而不是直接利用 gpt-oss 工具包。这种模块化架构简化了可扩展的工具调用库和服务的构建，且无需对 vLLM 进行任何内部改动。

### **展望未来**

本次发布只是 vLLM 持续优化 gpt-oss 的开始。我们正在进行中的路线图包括：

- 加固 Responses API
- 进一步增强注意力 DP 与 MoE EP 支持
- 降低 CPU 开销以最大化吞吐量
