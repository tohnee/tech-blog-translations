# AMD × vLLM Semantic Router：携手构建系统级智能

> 原文：[AMD × vLLM Semantic Router: Building the System Intelligence Together](https://vllm.ai/blog/2025-12-16-vllm-sr-amd) · vLLM 博客

AMD 与 vLLM Semantic Router 团队

[#硬件](https://vllm.ai/blog/tags/hardware)[#生态](https://vllm.ai/blog/tags/ecosystem)

## 引言

过去几个月里，AMD 与 vLLM SR 团队一直合作，将 **vLLM Semantic Router（VSR）** 带到 AMD GPU 上——这不仅仅是一次性能优化，更是我们对 AI 系统架构思考方式的一次根本转变。

AMD 长期以来一直是 vLLM 社区的技术合作伙伴，从在 AMD GPU 与 ROCm™ 软件上加速 vLLM 推理引擎，到如今共同构建 AI 技术栈的下一层：**面向混合模型（Mixture-of-Models, MoM）系统的智能路由与治理**。

随着 AI 从单一模型走向多模型架构，挑战不再只是「你的模型有多大」，而是**你能否智能且安全地编排众多模型**。VSR 的定位是这一新时代的**智能控制平面**——基于语义理解做路由决策、执行安全策略，并在系统向 AGI 级能力扩展的过程中维持信任。

![](https://vllm.ai/blog-assets/figures/semantic-router/amd-0.png)

这次合作聚焦三大战略支柱：

1. **基于信号的路由**：利用关键词匹配、领域分类、语义相似度和事实核验进行智能请求路由，适用于多 LoRA 与多模型部署
2. **跨实例智能**：通过集中式响应存储与语义缓存，在多个 vLLM 实例之间共享状态与优化
3. **安全护栏与治理**：从 PII 检测与越狱防范，到幻觉检测与对齐约束，提供企业级安全

我们正与 AMD 一起构建可高效运行于 AMD GPU 的 VSR，同时为**可信、可治理的 AI 基础设施**树立新的标准。

## 转变：从单一模型到混合模型（Mixture-of-Models）

在混合模型的世界里，企业 AI 技术栈通常包括：

- **路由 SLM**（小语言模型），负责分类、路由和策略执行
- **多个 LLM** 与领域专属模型（例如代码、金融、医疗、法律）
- **工具、RAG 流水线**、向量搜索和业务系统

没有健壮的路由层，这一切就会变成一张不透明且脆弱的网。AMD × VSR 合作的目标是让路由成为**一等公民、GPU 加速的基础设施组件**——而不是胶水般粘在服务之间的临时脚本。

## VSR 核心能力

### 1. 面向多 LoRA 部署的基于信号的路由

VSR 提供多种路由策略以匹配不同用例：

- **基于关键词的路由**：简单的模式匹配，实现快速、确定性的路由
- **领域分类**：使用训练好的分类器进行意图感知的适配器选择
- **基于嵌入的语义相似度**：基于语义理解的细致路由
- **事实核验与验证路由**：将高风险查询路由到专门的验证流水线

### 2. 跨实例智能

VSR 支持在所有 vLLM 实例之间共享状态与优化：

- **Response API**：集中式响应存储，支持有状态的多轮对话
- **语义缓存**：通过跨实例向量相似度匹配显著减少 token

### 3. 企业级安全护栏

从单轮到多轮对话，VSR 提供：

- **PII 检测**：防止敏感信息泄露
- **越狱防范**：阻断恶意提示注入尝试
- **幻觉检测**：为关键领域核验响应可靠性
- **超级对齐（Super Alignment）**：确保 AI 系统在向 AGI 能力扩展的过程中，始终与人类价值和意图保持一致

## 在 AMD GPU 上运行 VSR：两条部署路径

我们的近期目标以执行为导向：**交付一套可在 AMD GPU 上高效运行的生产级 VSR 方案**。我们正在构建两条互补的部署路径：

![](https://vllm.ai/blog-assets/figures/semantic-router/amd-1.png)

### 路径 1：基于 vLLM 的 AMD GPU 推理

在 AMD GPU 上使用 vLLM 引擎，我们运行：

**路由 SLM**，用于：

- 任务与意图分类
- 风险评分与安全门控
- 工具与工作流选择

**LLM 与专用模型**，用于：

- 通用辅助
- 领域专属任务（金融、法律、代码、医疗）

VSR 位于其上，作为决策织物（decision fabric），消费语义相似度、业务元数据、延迟约束和合规要求，在模型与端点之间执行**动态路由**。

AMD GPU 提供在同一集群中运行**路由 SLM + 多个 LLM** 所需的吞吐量与内存容量，支撑高 QPS 负载下的稳定延迟——而不只是一次性的演示。

### 路径 2：轻量级基于 ONNX 的路由

并非所有路由都需要完整的推理栈。对于系统「前门」处超高频、延迟敏感的环节，我们正在启用：

- 将路由 SLM 导出为 **ONNX**
- 通过 ONNX Runtime 在 AMD GPU 上运行它们
- 将复杂的生成任务转发给 vLLM 或其他后端 LLM

这条轻量路径面向：

- 漏斗前端的流量分类与分诊
- 大规模策略评估与离线实验
- 希望**在 AMD GPU 上实现标准化、同时保持模型提供商灵活**的企业

## 迈向 Semantic Router 的下一阶段

当我们最初构建 vLLM Semantic Router 时，目标清晰而务实：**智能模型选择**——根据任务类型、成本约束和性能要求，把请求路由到合适的模型。

![](https://vllm.ai/blog-assets/figures/semantic-router/amd-2.png)

**vLLM 引擎**提供基础——稳定高效地运行大模型。**vLLM Semantic Router** 提供调度器——将请求分派到合适的能力。

但随着 AI 系统迈向 AGI 级能力，这种框架显得不够完整。这就像只讨论发动机效率，却不谈刹车、交通法规或安全系统。

**真正的挑战不是让模型更强大——而是在它们变得更强大的过程中保持控制。**

### 从模型调度器到智能裁判

在与 AMD 的合作中，我们对 Semantic Router 的演进有了不同的认识。它的潜力不仅在于「路由」，更在于**治理**——从一个流量调度器转变为 AGI 时代的**智能控制平面**。

这一转变改变了我们对合作的思考。我们不只是在对 AMD 硬件上的吞吐量和延迟做优化。我们正在为 AI 系统构建一个**宪制层（constitutional layer）**——由职责而非仅仅由功能来定义。

### 必须守住的三条控制命脉

在 AMD 基础设施上构建 VSR 时，我们围绕三个关键控制点进行设计，它们决定了 AI 系统能否在规模化时保持可信：

![](https://vllm.ai/blog-assets/figures/semantic-router/amd-3.png)

**1. 世界输出（动作）**

强大模型最危险的能力不是推理——而是**执行**。每一个会改变世界的动作（工具调用、数据库写入、API 调用、配置变更）在执行前都必须经过一个外部检查点。

借助 AMD GPU，我们可以在生产规模下**内联**运行这些检查点——评估风险、执行策略、记录决策，而不成为瓶颈。

**2. 世界输入（输入）**

外部输入默认不可信。网页、检索结果、上传的文件和插件返回值都可能携带提示注入、数据投毒或权限提升攻击。

AMD 基础设施上的 VSR 在数据到达模型之前提供**边境检查**——运行分类器、净化器和核验检查，作为第一道防线，而非事后补救。

**3. 长期状态（记忆/状态）**

最难修复的故障不是错误的回答——而是**被写入长期记忆、系统状态或自动化工作流的错误回答**。

我们的合作聚焦于让状态管理成为一等关切：谁能写入、能写什么、如何撤销、如何隔离污染。AMD 的 GPU 基础设施让我们能够运行持续的核验与回滚机制，让状态随时间保持可信。

### 终极问题

当这三条命脉都被守住，Semantic Router 就不再只是一个模型选择器。它成为一个根本性问题的答案：

**我们如何把对齐从训练时的愿景，转变为运行时的制度？**

这正是 AMD × vLLM Semantic Router 合作真正要做的事：构建的不只是更快的路由，而是**可信、可治理的 AI 基础设施**，能够安全地扩展到 AGI 级能力。

## 长期愿景与持续工作

我们与 AMD 的合作不止于近期的部署，还包括为下一代 AI 基础设施奠定基础。我们正在推进几项长期计划：

### 在 AMD GPU 上训练下一代路由模型

作为一个更长期的目标，我们计划探索在 AMD GPU 上训练一个**基于 encoder-only 的下一代路由模型**，针对语义路由、检索增强生成（RAG）和安全分类进行优化。

尽管近期的编码器模型（如 ModernBERT）表现出色，但它们在上下文长度、多语言覆盖以及与新兴长上下文注意力技术的契合度上仍有局限。这项工作聚焦于利用 AMD 硬件推进编码器能力，特别是面向**长上下文、高吞吐的表示学习**。

其成果将是一个**开放的编码器模型**，设计上可与 vLLM Semantic Router 及现代 AI 流水线集成，强化 AI 系统的检索与路由层，同时为社区和产业拓展硬件多样化的训练与部署选择。

### AMD 基础设施上的社区公测

作为本次合作的一部分，vLLM Semantic Router 的每个主要版本都将伴随一个托管在 AMD 赞助基础设施上的**公测环境**，免费向社区开放。

这些公测将让用户能够：

- 验证新的路由、缓存与安全功能
- 获得在 AMD GPU 上运行 Semantic Router 的动手体验
- 提供早期反馈，帮助改进性能、易用性与系统设计

通过降低实验与验证的门槛，这一计划旨在强化 vLLM 生态、加速真实场景落地，并确保新的 Semantic Router 能力在更广泛的生产部署之前就吸收社区意见。

### AMD GPU 驱动的 CI/CD 与端到端测试床

从长远来看，我们希望用 AMD GPU 来支撑 **VSR 作为开源项目被构建、验证和交付**的方式，确保随着项目成长，VSR 始终与 AMD GPU 良好协同。

我们正在设计一个 GPU 支撑的 **CI/CD 与端到端测试床**，其中：

- 路由 SLM、LLM、领域模型、检索和工具一起运行在 AMD GPU 集群上
- 多领域、多风险级别的数据集作为流量回放
- 每一次 VSR 变更都会经过自动化评估流水线，包括：
  - 路由与策略回归测试
  - 新策略与旧策略的 A/B 对比
  - 延迟、成本与可扩展性的压力测试
  - 针对幻觉缓解与合规行为的专项测试套件

目标状态很明确：

> **每一次 VSR 发布都附带一份可复现的、GPU 驱动的评估报告，而不仅仅是一份变更日志。**

在这一模式下，AMD GPU 不仅用于服务模型；它们是**路由基础设施自身的验证引擎**。

### AMD 支撑的混合模型（MoM）游乐场

与此同时，我们正在规划一个由 AMD GPU 驱动的**在线混合模型游乐场**，面向社区与合作伙伴开放。

这个游乐场将让用户能够：

- 在真实负载下试验不同的路由策略与模型拓扑
- 以可视化的方式观察 VSR 如何决定调用哪个模型、何时检索、何时施加额外检查或回退
- 比较不同配置之间的**质量、延迟与成本权衡**

对模型厂商、工具构建者和平台提供商来说，这里成为一个**中立的、AMD GPU 支撑的测试环境**，可用于：

- 将其组件集成进 MoM 技术栈
- 在真实的路由与治理约束下进行基准测试
- 在一个透明、可观测的系统中展示能力

## 为什么这次合作重要

通过 AMD × vLLM Semantic Router 合作，我们的目标超越了「这个模型能不能跑在这块 GPU 上」。

共同的抱负是：

- 在 AMD 平台上定义**智能、GPU 加速路由的参考架构**，包括：
  - 基于 vLLM 的推理路径，
  - 基于 ONNX 的轻量路由路径，
  - 多模型协调与安全执行。
- 将路由视为**可信基础设施**，辅以：
  - GPU 驱动的 CI/CD 与端到端评估，
  - 幻觉感知与风险感知策略，
  - 在线学习与自适应策略。
- 为生态提供一个**长久的、AMD GPU 支撑的 MoM 游乐场**，让想法、模型和路由策略可以在开放中测试与演进。

简而言之，这是关于**共建可信、可演进的多模型 AI 基础设施**——以 AMD GPU 作为核心执行与验证层，以 vLLM Semantic Router 作为让整个系统可理解、可治理、能应对真实负载的智能控制平面。

技术路线图——幻觉检测、在线学习、多模型编排——都在服务于这一更大的使命。AMD 的硬件提供执行层。VSR 提供控制平面。我们正在共同奠定基础，让 AI 系统的对齐不再依靠侥幸，而是依靠**架构**。
