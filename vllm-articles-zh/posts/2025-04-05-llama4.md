# vLLM 中的 Llama 4

> 原文：[Llama 4 in vLLM](https://vllm.ai/blog/2025-04-05-llama4) · vLLM 博客

作者：vLLM 团队

[#模型支持](https://vllm.ai/blog/tags/model-support)[#多模态](https://vllm.ai/blog/tags/multimodal)

我们很高兴地宣布，vLLM 现已支持 [Llama 4 模型家族](https://ai.meta.com/blog/llama-4-multimodal-intelligence/)：**Scout**（17B-16E）和 **Maverick**（17B-128E）。只需升级到 v0.8.3 或更高版本，你今天就可以在 vLLM 中运行这些强大的长上下文、原生多模态（最多 8-10 张图像可获得良好效果）的混合专家模型：

```
pip install -U vllm

```

下面提供了入门示例命令。或者，你也可以把 CLI 命令替换为 docker run（[说明见此](https://docs.vllm.ai/en/latest/deployment/docker.html)），或使用我们的 Python 接口——[`LLM` 类](https://docs.vllm.ai/en/latest/getting_started/quickstart.html#offline-batched-inference)——进行本地批量推理。我们还建议查看 Meta 团队的[演示](https://github.com/meta-llama/llama-cookbook/blob/main/getting-started/build_with_llama_4.ipynb)，其中展示了 vLLM 的 1M 长上下文能力。

## 使用指南

以下是如何在不同的硬件配置下服务 Llama 4 模型。

使用 8xH100 时，vLLM 能够以 1M 上下文服务 Scout，Maverick 约为 430K。更多性能增强和长上下文利用的技巧见下文。

在 8x H100 GPU 上：

- Scout（最高 1M 上下文）：

```
VLLM_DISABLE_COMPILE_CACHE=1 vllm serve meta-llama/Llama-4-Scout-17B-16E-Instruct \
  --tensor-parallel-size 8 \
  --max-model-len 1000000 --override-generation-config='{"attn_temperature_tuning": true}'

```

- Maverick（最高约 430K 上下文）：

```
VLLM_DISABLE_COMPILE_CACHE=1 vllm serve meta-llama/Llama-4-Maverick-17B-128E-Instruct-FP8 \
  --tensor-parallel-size 8 \
  --max-model-len 430000

```

在 8x H200 GPU 上：

- Scout（最高 3.6M 上下文）：

```
VLLM_DISABLE_COMPILE_CACHE=1 vllm serve meta-llama/Llama-4-Scout-17B-16E-Instruct \
  --tensor-parallel-size 8 \
  --max-model-len 3600000

```

- Maverick（最高 1M 上下文）：

```
VLLM_DISABLE_COMPILE_CACHE=1 vllm serve meta-llama/Llama-4-Maverick-17B-128E-Instruct-FP8 \
  --tensor-parallel-size 8
  --max-model-len 1000000

```

**多模态：**

Llama 4 模型在图像理解方面表现出色，最多可处理 8-10 张图像。默认情况下，vLLM 服务器每个请求接受 1 张图像。请传入 `--limit-mm-per-prompt image=10`，以便通过 OpenAI 兼容 API 在每个请求中最多服务 10 张图像。我们还建议查看我们的 Llama-4 多图像离线推理示例（[见此](https://github.com/vllm-project/vllm/blob/v0.8.3/examples/offline_inference/vision_language_multi_image.py)）。

**性能：**

使用上述配置，我们观察到 Scout-BF16 和 Maverick-FP8 的输出 token/s 如下：

![](https://vllm.ai/blog-assets/figures/llama4/perf.png)

虽然更多性能增强仍在路上，但我们相信，Llama 4 模型高效的架构和相对较小的体量使其在今天就可以用于规模化部署。

**性能与长上下文技巧：**

- **提升性能与上下文长度：** 设置 `--kv-cache-dtype fp8` 有望将可用上下文窗口加倍并获得性能提升。我们在相关评测中观察到，该设置几乎没有精度损失。
- **最大化上下文窗口（最高 10M）：** 要充分利用最大上下文窗口（Scout 最高 10M），我们建议使用张量并行或流水线并行跨多个节点服务。请遵循我们的分布式推理指南（[见此](https://docs.vllm.ai/en/latest/serving/distributed_serving.html)）。

**其他硬件支持与量化：**

- A100：我们已验证模型的 bf16 版本在 A100 GPU 上运行良好。
- INT4：可放入单张 H100 GPU 的 Scout 模型检查点 INT4 量化版本目前正在开发中。敬请期待更新。
- AMD MI300X：你可以[从源码构建 vLLM](https://docs.vllm.ai/en/latest/getting_started/installation/gpu.html?device=rocm)，并使用与上文相同的命令在 AMD MI300X GPU 上运行 Llama 4。

**推理精度验证：**
我们使用 lm-eval-harness 对照 Meta 官方报告验证了推理精度。以下是 [meta-llama/Llama-4-Maverick-17B-128E-Instruct](https://huggingface.co/meta-llama/Llama-4-Maverick-17B-128E-Instruct) 的结果：

|  | MMLU Pro | ChartQA |
| --- | --- | --- |
| 官方报告值 | 80.5 | 90 |
| H100 FP8 | 80.4 | 89.4 |
| AMD MI300x BF16 | 80.4 | 89.4 |
| H200 BF16 | 80.2 | 89.3 |

## 高效架构与集群规模服务

Llama 4 的模型架构特别适合高效的长上下文推理，得益于以下特性：

- **混合专家（MoE）：** Scout 使用 16 个专家（17B 激活参数），Maverick 使用 128 个专家（17B 激活参数）。每个 token 只激活一个专家，从而保持效率。
- **交错 RoPE（iRoPE）：** Llama 4 以 1:3 的比例将全局注意力（不使用 RoPE）与分块局部注意力（使用 RoPE）交错。局部注意力层在不重叠的块内关注 token，显著降低了注意力随上下文长度扩展而产生的二次复杂度。

vLLM 近期发布了 [V1 引擎](https://blog.vllm.ai/2025/01/27/v1-alpha-release.html)，在单节点上带来了重大性能加速，并原生支持 torch.compile。我们的[第二季度路线图](https://github.com/vllm-project/vllm/issues/15735)聚焦于增强 vLLM 的多节点扩展能力，目标是分离式、集群规模的服务。我们正在积极添加对高效专家并行、多节点数据并行和集群级预填充分离的支持。
