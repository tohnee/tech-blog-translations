# Qwen3.8-2.4T-A95B 在 vLLM 上的 Day 0 支持

> 原文：[Day 0 Support for Qwen3.8-2.4T-A95B on vLLM](https://vllm.ai/blog/2026-08-12-qwen3.8) · vLLM 博客

作者：vLLM 团队与 Inferact

[#模型支持](https://vllm.ai/blog/tags/model-support)[#量化](https://vllm.ai/blog/tags/quantization)[#MoE](https://vllm.ai/blog/tags/moe)[#性能](https://vllm.ai/blog/tags/performance)[#硬件](https://vllm.ai/blog/tags/hardware)

我们宣布 vLLM 对 Qwen3.8-2.4T-A95B 的 Day-0 支持。这是 Qwen 家族首个以开放权重形式发布的 Qwen-Max 级模型。

Qwen3.8-2.4T-A95B 构建于 Qwen 3.5 架构之上，开箱即可在 vLLM 上运行。除了官方 FP8 与 BF16 检查点之外，Inferact 还发布了 MXFP4 与 NVFP4 量化权重，在显著降低内存与带宽开销的同时保持与全精度相当的质量。

Qwen3.8-2.4T-A95B 是一个 2.4 万亿参数的稀疏 MoE 模型，拥有 512 个专家。在其 92 层混合主干中，每第 4 层应用全注意力，其余 69 层运行线性注意力。作为迄今发布的最大开放权重模型之一，运行推理至少需要两个 NVIDIA B300 / AMD MI355X 节点（FP4 量化版本单节点即可）。

## TL;DR

- **Day-0 支持：** Qwen3.8-2.4T-A95B 复用 Qwen 3.5 架构，从第一天起即可在 vLLM 上运行，无需任何架构改动。
- **灵活的精度：** 提供 FP8、BF16、NVFP4 与 MXFP4 检查点。
- **多厂商优化：** 在包括 NVIDIA 与 AMD 在内的硬件合作伙伴上完成验证。

## 快速开始

NVFP4 版本：

```
# See recipes for the exact docker run command
vllm serve Inferact/Qwen3.8-2.4T-A95B-NVFP4 \
  --linear-backend flashinfer_cutedsl \
  --tensor-parallel-size 8 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --reasoning-parser qwen3 \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3}'
```

MXFP4 版本：

```
vllm serve Inferact/Qwen3.8-2.4T-A95B-MXFP4 \
  --tensor-parallel-size 8 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --reasoning-parser qwen3 \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3}'
```

完整服务指南与推荐标志请参见 [vLLM 配方](https://recipes.vllm.ai/)。

## FP4 量化：更低成本下的质量

为了最小化推理成本并最大化 GPU 内存效率，Inferact 团队使用带激活值校准（以启用 4 比特激活）的舍入到最近值（Round-to-Nearest，RTN）量化，把选定层——包括路由专家——的权重量化为 FP4。

我们进行了初步验证，确认量化后的精度保持完好。注意，要复现这些评估结果，需要增大推理预算。

| 基准测试 | FP8 | NVFP4 |
| --- | --- | --- |
| GSM8K（strict / flexible） | 89.61% / 90.52% | 90.37% / 91.05% |
| AIME25 @3（avg / pass） | 87.78% / 93.33% | 92.22% / 96.67% |

## 优化

为了让这个 2.4T 参数模型高效推理，我们与 NVIDIA 和 AMD 紧密合作，在既有 Qwen 3.5 支持的基础上开发了优化的内核。

在 NVIDIA 平台上，NVIDIA 与 Inferact 联合开发了面向线性注意力（门控增量规则）、注意力（GQA）、稠密 GEMM 与 MoE 路由的超快速内核，并新增了减少通信开销的融合内核。我们还投入大量精力寻找最佳的工作分解方式以最大化性能，包括在注意力上结合数据并行与张量并行、在 MoE 上使用专家并行。

在 AMD Instinct GPU 上，vLLM 用 AITER 融合的 Gated DeltaNet 解码、注意力与 MoE 内核加速 Qwen3.8，降低内核启动与数据搬运开销。对于共享专家 MoE，共享专家路径利用高度优化的 hipBLASLt GEMM 内核，路由专家则使用 AITER FusedMoE。AMD Quark 量化支持实现高效的 MXFP4 部署，在保持出色精度的同时大幅降低模型内存需求。

## 部署提示

Qwen 3.8 模型卡推荐使用以下生成参数以获得最佳性能：

```
temperature=1.0, top_p=0.95, top_k=20, min_p=0.0, presence_penalty=0.0, repetition_penalty=1.0

```

以下是 vLLM 服务器运行后用于查询模型的 Python 客户端代码片段。由于 Qwen 3.8 是一个推理模型，请确保通过设置较高的 `max_tokens` 值，为智能体工作流分配充足的 token 预算。

```
from openai import OpenAI

client = OpenAI(api_key="EMPTY", base_url="http://localhost:8000/v1", timeout=3600)

resp = client.chat.completions.create(
    model="Qwen/Qwen3.8-2.4T-A95B",
    messages=[{"role": "user", "content": "Give me three primes above 100."}],
    temperature=1.0, top_p=0.95, max_tokens=128_000,
)
print(resp.choices[0].message.content)
```
