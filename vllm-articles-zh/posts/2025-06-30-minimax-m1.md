## 引言

人工智能的快速进步催生了日益强大的大语言模型（LLM）。[MiniMax-M1](https://arxiv.org/pdf/2506.13585) 是一个广受欢迎的开源大规模混合专家（MoE）推理模型，自发布以来备受关注。其创新的混合架构预示着 LLM 的未来，实现了长上下文推理和复杂任务处理方面的突破。与此同时，vLLM 作为高性能 LLM 推理与服务库，为 MiniMax-M1 提供了强大的支持，使高效部署成为可能。

![MiniMax-M1 Benchmark Performance](https://vllm.ai/blog-assets/figures/minimax-m1/benchmark.png)

MiniMax-M1 基准测试性能

- **左：** 领先的商业与开源模型在数学、代码、软件工程、工具使用和长上下文理解等任务上的基准对比。MiniMax-M1 在开源模型中处于领先地位。
- **右：** 理论推理 FLOPs 随 token 长度的扩展情况。与 DeepSeek R1 相比，MiniMax-M1 在生成 100k token 序列时仅使用 25% 的 FLOPs。

## 使用 vLLM 部署 MiniMax-M1

我们推荐使用 **vLLM** 部署 **MiniMax-M1** 以获得最佳性能。我们的测试展示了以下关键优势：

- 出色的吞吐量
- 高效且智能的内存管理
- 对批量请求的稳健支持
- 深度优化的后端性能

### 模型下载

你可以从 Hugging Face 下载模型：

```
# Install the Hugging Face Hub CLI
pip install -U huggingface-hub

# Download the MiniMax-M1-40k model
huggingface-cli download MiniMaxAI/MiniMax-M1-40k
# For the 80k version, uncomment the following line:
# huggingface-cli download MiniMaxAI/MiniMax-M1-80k
```

### 部署

以下是使用 vLLM 和 Docker 部署 MiniMax-M1 的快速指南：

```
# Set environment variables
IMAGE=vllm/vllm-openai:latest
MODEL_DIR=<model storage path>
NAME=MiniMaxImage

# Docker run configuration
DOCKER_RUN_CMD="--network=host --privileged --ipc=host --ulimit memlock=-1 --rm --gpus all --ulimit stack=67108864"

# Start the container
sudo docker run -it \
    -v $MODEL_DIR:$MODEL_DIR \
    --name $NAME \
    $DOCKER_RUN_CMD \
    $IMAGE /bin/bash

# Launch MiniMax-M1 Service
export SAFETENSORS_FAST_GPU=1
export VLLM_USE_V1=0
vllm serve \
--model <model storage path> \
--tensor-parallel-size 8 \
--trust-remote-code \
--quantization experts_int8  \
--max_model_len 4096 \
--dtype bfloat16
```

## MiniMax-M1 混合架构亮点

### 混合专家（MoE）

MiniMax-M1 采用混合专家（MoE）架构，**总参数量达 4560 亿**。在推理过程中，动态路由算法根据输入 token 的语义特征激活专家的稀疏子集（约 45.9B 参数，即总量的 10%）。这种稀疏激活由一个计算专家选择概率的门控网络管理。

这种方式显著提升了计算效率：在分类任务中，它将计算成本降低多达 90%，同时保持与稠密（dense）模型相当的准确率。

![MoE vs. Dense Comparison](https://vllm.ai/blog-assets/figures/minimax-m1/moe.png)

MoE 与稠密模型对比

等 FLOPs（Isoflop）对比：MoE 与稠密模型在多个基准上的表现。两个模型均在 1 万亿 token 上训练。灰色虚线表示两个模型达到相同性能所需的计算量差异。

### Lightning Attention（闪电注意力）

**Lightning Attention** 通过引入线性化近似技术，解决了传统注意力的二次复杂度瓶颈。它将 softmax 注意力转化为**矩阵乘法的线性组合**，并辅以动态内存分块（tiling）和梯度近似。

在代码补全基准测试中，对于 100k token 的序列，Lightning Attention 将内存使用降低 **83%**，推理延迟降低 **67%**。

![Lightning Attention Algorithm](https://vllm.ai/blog-assets/figures/minimax-m1/lightning_attention.png)

Lightning Attention 算法

Lightning Attention 算法概览，它降低了长序列的内存使用和延迟。

### 高效的计算与激活策略

得益于其混合架构，MiniMax-M1 实现了高效计算和可扩展推理。Lightning Attention 机制大幅提升运行时性能，而稀疏专家激活策略避免了不必要的计算。这使得即使硬件资源有限，也能取得强劲的性能。

欲进一步了解 MiniMax-M1，请参阅[这篇论文](https://arxiv.org/pdf/2506.13585)。

## 用 vLLM 实现高效推理

### 先进的内存管理

vLLM 引入了 PagedAttention，这是一种更高效管理注意力键值缓存的技术。vLLM 不再连续存储 KV 缓存，而是将其划分为多个内存页，大幅减少碎片化和过度分配。这使 vLLM 将内存浪费降至 4% 以下，而传统方法为 60%-80%。

如此高效的内存处理对 MiniMax-M1 这类支持超长上下文长度的模型至关重要，可确保推理顺畅稳定而不触及内存瓶颈。

### 深度内核级优化

vLLM 集成了广泛的 CUDA 内核优化，包括与 FlashAttention、FlashInfer 的集成，以及对 GPTQ、AWQ、INT4、INT8 和 FP8 等量化格式的支持。

这些增强进一步提升了 MiniMax-M1 推理的底层计算效率。量化在几乎不损失精度的情况下减少了内存和计算开销，而 FlashAttention 加速了注意力计算本身——使真实应用中的推理显著提速。

### vLLM 中的 Lightning Attention

作为前沿的注意力机制，Lightning Attention 在 vLLM 中通过 Triton 实现，充分利用其灵活性和高性能计算特性。基于 Triton 的执行框架完整支持 Lightning Attention 的核心计算逻辑，使其能够在 vLLM 生态中无缝集成与部署。

## 后续工作

展望未来，vLLM 社区正在积极探索对混合架构支持的进一步优化。值得注意的是，混合分配器（hybrid allocator）的开发有望实现针对 MiniMax-M1 这类模型独特需求的更高效内存管理。

此外，我们还计划全面支持 [vLLM v1](https://blog.vllm.ai/2025/01/27/v1-alpha-release.html)，混合模型架构预计将迁移到 v1 框架中。这些进展有望带来进一步的性能提升，并为未来的发展提供更坚实的基础。

## 结语

MiniMax-M1 的混合架构为下一代大语言模型铺平了道路，在长上下文推理和复杂任务推理方面提供了强大能力。vLLM 则以高度优化的内存处理、稳健的批量请求管理和深度调优的后端性能与之相辅相成。

MiniMax-M1 与 vLLM 共同构成了高效、可扩展 AI 应用的坚实基础。随着生态系统的发展，我们期待这种协同效应能在广泛的用例中驱动更智能、更敏捷、更强大的解决方案，包括代码生成、文档分析和对话式 AI。
