# vLLM 的开放式治理与性能路线图

> 原文：[vLLM’s Open Governance and Performance Roadmap](https://vllm.ai/blog/2024-07-25-lfai-perf) · vLLM 博客

vLLM 团队

[#社区](https://vllm.ai/blog/tags/community)

我们想与 vLLM 社区分享两项更新。

### vLLM 的未来是开放的

![](https://vllm.ai/blog-assets/figures/lfai/vllm-lfai-light.png)

我们很高兴地看到 vLLM 正在成为 LLM 推理与服务的标准。在最近的 [Meta Llama 3.1 发布公告](https://ai.meta.com/blog/meta-llama-3-1/)中，10 家实时推理官方合作伙伴中有 8 家使用 vLLM 作为 Llama 3.1 模型的服务引擎。我们也耳闻 vLLM 正被用于日常生活中的许多 AI 功能。

我们相信 vLLM 的成功源于强大的开源社区的力量。vLLM 由 UC Berkeley、Anyscale、AWS、CentML、Databricks、IBM、Neural Magic、Roblox、Snowflake 等组成的团体积极维护。有鉴于此，我们也希望确保项目的所有权和治理是开放且透明的。

我们高兴地宣布，vLLM 已[启动加入 LF AI & Data Foundation 的孵化流程](https://lfaidata.foundation/blog/2024/07/17/lf-ai-data-foundation-mid-year-review-significant-growth-in-the-first-half-of-2024/?hss_channel=tw-976478457881247745)。这意味着任何一方都不会独占 vLLM 的未来。许可证和商标将不可撤销地保持开放。你可以放心，vLLM 会长期存在，并将持续得到积极维护和改进。

### 性能是首要任务

vLLM 的贡献者们正在加倍努力，确保 vLLM 是最快、最易用的 LLM 推理与服务引擎。

回顾我们的路线图，vLLM 聚焦于六大目标：广泛的模型覆盖、广泛的硬件支持、顶尖性能、生产级可用、繁荣的开源社区，以及可扩展的架构。

在性能优化这一目标上，我们迄今为止取得了以下进展：

- 发布基准测试
  - 在 [perf.vllm.ai](https://perf.vllm.ai) 上发布了针对我们公开基准测试的逐次提交（per-commit）性能追踪器，目标是跟踪性能的提升与回退。
  - 发布了 vLLM 与 LMDeploy、TGI、TensorRT-LLM 对比的可复现基准测试（[文档](https://docs.vllm.ai/en/latest/performance_benchmark/benchmarks.html)），目标是找出性能差距并将其消除。
- 开发与集成高度优化的内核
  - 集成了 FlashAttention2 与 PagedAttention，以及 [FlashInfer](https://github.com/flashinfer-ai/flashinfer)。我们计划集成 [FlashAttention3](https://github.com/vllm-project/vllm/issues/6348)。
  - 正在集成 [Flux](https://arxiv.org/abs/2406.06858v1)，它可将计算与集合通信重叠进行。
  - 开发了面向量化推理的最先进内核，包括 INT8 和 FP8 激活值量化（通过 cutlass），以及面向 GPTQ 和 AWQ 的 INT4、INT8、FP8 仅权重量化（通过 marlin）。
- 启动了多个工作流以降低关键开销
  - 我们发现 vLLM 的同步阻塞式调度器是模型在快速 GPU（H100）上运行的关键瓶颈。我们正在让调度变为异步，并提前规划后续步骤。
  - 我们发现 vLLM 的 OpenAI 兼容 API 前端开销高于理想水平。[我们正在将其从调度器和模型推理的关键路径中隔离出来。](https://github.com/vllm-project/vllm/issues/6797)
  - 我们发现 vLLM 的输入准备和输出处理随数据规模的扩展不够理想。其中许多操作可以矢量化，并通过移出关键路径来增强。

我们将持续向社区更新 vLLM 在缩小性能差距方面的进展。你可以[在这里](https://github.com/vllm-project/vllm/issues/6801)跟踪我们的整体进展。请继续提出新想法并贡献你的改进！

### 更多资源

我们想重点介绍以下正在积极开发中的 RPC：

- [单程序多数据（SPMD）Worker 控制平面](https://github.com/vllm-project/vllm/issues/6556)可降低复杂度并提升张量并行的性能。
- [在 vLLM 中使用 torch.compile 的图优化系统](https://github.com/vllm-project/vllm/issues/6378)为内核融合与编译引入 PyTorch 原生编译工作流。
- [通过 KV 缓存传输实现分离式预填充（disaggregated prefilling）](https://github.com/vllm-project/vllm/issues/5557)对长输入工作负载至关重要，并能降低逐 token 延迟的波动。

有一个繁荣的研究社区正在 vLLM 之上构建他们的研究项目。这些出色的工作令我们深感谦卑，我们期待合作与集成。相关论文列表包括但不限于：

- [Llumnix: Dynamic Scheduling for Large Language Model Serving](https://arxiv.org/abs/2406.03243)
- [CacheGen: KV Cache Compression and Streaming for Fast Large Language Model Serving](https://arxiv.org/abs/2310.07240)
- [vAttention: Dynamic Memory Management for Serving LLMs without PagedAttention](https://arxiv.org/abs/2405.04437)
- [Andes: Defining and Enhancing Quality-of-Experience in LLM-Based Text Streaming Services](https://arxiv.org/abs/2404.16283)
- [SGLang: Efficient Execution of Structured Language Model Programs](https://arxiv.org/abs/2312.07104)
