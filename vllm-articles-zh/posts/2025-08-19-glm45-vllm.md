# GLM-4.5 携手 vLLM：为智能体而生

> 原文：[GLM-4.5 Meets vLLM: Built for Intelligent Agents](https://vllm.ai/blog/2025-08-19-glm45-vllm) · vLLM 博客

作者：Yuxuan Zhang

[#模型支持](https://vllm.ai/blog/tags/model-support)[#多模态](https://vllm.ai/blog/tags/multimodal)

## 简介

[通用语言模型（General Language Model，GLM）](https://aclanthology.org/2022.acl-long.26/)是由智谱（Zhipu.ai，现已更名为 [Z.ai](https://z.ai/)）创建的基础模型系列。GLM 团队与 vLLM 团队有着长期合作，可以追溯到 vLLM 的早期以及广受欢迎的 [ChatGLM 模型系列](https://github.com/zai-org/ChatGLM-6B)。最近，GLM 团队发布了专为智能体设计的 [GLM-4.5](https://arxiv.org/abs/2508.06471) 与 [GLM-4.5V](https://arxiv.org/abs/2507.01006) 模型系列。它们是当前 Huggingface 模型中心上最受关注的热门模型。

GLM-4.5 总参数量为 3550 亿（355 billion），激活参数量为 320 亿（32 billion）；GLM-4.5-Air 采用更紧凑的设计，总参数量为 1060 亿，激活参数量为 120 亿。GLM-4.5 模型统一了推理、代码与智能体能力，以满足智能体应用的复杂需求。

GLM-4.5 和 GLM-4.5-Air 都是混合推理模型，提供两种模式：用于复杂推理与工具使用的思考模式，以及用于即时响应的非思考模式。

正如我们在 12 项行业标准基准上的全面评估所示，GLM-4.5 取得了 63.2 的优异得分，在所有闭源与开源模型中位列第三。值得注意的是，GLM-4.5-Air 以 59.8 的成绩保持了更高的效率，结果同样具有竞争力。

![bench_45](https://raw.githubusercontent.com/zai-org/GLM-4.5/refs/heads/main/resources/bench.png)

GLM-4.5V 基于 GLM-4.5-Air。它延续了 GLM-4.1V-Thinking 的技术路线，在 42 个公开视觉-语言基准上取得了同规模模型中的最先进水平（SOTA）。

![bench_45v](https://raw.githubusercontent.com/zai-org/GLM-V/refs/heads/main/resources/bench_45v.jpeg)

bench\_45v

欲了解 GLM-4.5 与 GLM-4.5V 的更多信息，请参阅 [GLM-4.5](https://github.com/zai-org/GLM-4.5) 和 [GLM-V](https://github.com/zai-org/GLM-V)。

本博客将指导用户如何在 NVIDIA Blackwell 与 Hopper GPU 上使用 vLLM 加速 GLM-4.5V 与 GLM-4.5 模型系列的推理。

## 安装

在最新的 vLLM main 分支中，GLM-4.5V 与 GLM-4.5 模型系列均已获得支持。你可以安装 nightly 版本，并手动更新 transformers 以启用模型支持。

```
pip install -U vllm --pre --extra-index-url https://wheels.vllm.ai/nightly
pip install transformers-v4.55.0-GLM-4.5V-preview
```

## 使用方法

GLM-4.5 与 GLM-4.5V 均提供 FP8 与 BF16 两种精度的模型。在 vLLM 中，无论哪种精度，你都可以使用同一命令运行推理。

对于 GLM-4.5 模型，你可以用以下命令启动服务：

```
vllm serve zai-org/GLM-4.5-Air \
    --tensor-parallel-size 4 \
    --tool-call-parser glm45 \
    --reasoning-parser glm45 \
    --enable-auto-tool-choice
```

对于 GLM-4.5V 模型，你可以用以下命令启动服务：

```
vllm serve zai-org/GLM-4.5V \
     --tensor-parallel-size 4   \
     --tool-call-parser glm45   \
     --reasoning-parser glm45   \
     --enable-auto-tool-choice  \
     --allowed-local-media-path / \
     --media-io-kwargs '{"video": {"num_frames": -1}}'
```

### 注意事项

- 模型输出的推理（reasoning）部分会被包裹在 `reasoning_content` 中，`content` 只包含最终答案。若要关闭推理，请添加如下参数：
  `extra_body={"chat_template_kwargs": {"enable_thinking": False}}`
- 如果你使用 8x H100 GPU 运行 GLM-4.5 模型时遇到内存不足，需要加上 `--cpu-offload-gb 16`。
- 如果遇到 `flash_infer` 相关问题，可以临时改用 `VLLM_ATTENTION_BACKEND=XFORMERS` 作为替代。你也可以指定 `TORCH_CUDA_ARCH_LIST='9.0+PTX'` 来使用 `flash_infer`；不同 GPU 的 TORCH\_CUDA\_ARCH\_LIST 取值不同，请相应查询。
- vLLM v0 不支持我们的模型。

### GLM-4.5V 的视觉定位（Grounding）能力

GLM-4.5V 具备精确的视觉定位（grounding）能力。给定一个要求定位特定物体的提示，GLM-4.5V 能够逐步推理并识别目标物体的边界框。查询提示支持对目标物体的复杂描述以及指定输出格式。示例提示如下：

- 帮我在图中定位 `<expr>` 并给出它的边界框。（Help me to locate `<expr>` in the image and give me its bounding boxes.）
- 请按照给定描述在图中精确标出边界框 `[[x1,y1,x2,y2], …]`。（Please pinpoint the bounding box `[[x1,y1,x2,y2], …]` in the image as per the given description.）

这里，`<expr>` 是对目标物体的描述。输出的边界框是一个四元组 $[x_{1},y_{1},x_{2},y_{2}]$，由左上角和右下角的坐标组成，其中每个值都按图像宽度（x）或高度（y）归一化，并乘以 1000。

在响应中，特殊 token `<|begin_of_box|>` 与 `<|end_of_box|>` 用于在答案中标记图像边界框。括号样式可能有所不同（[]、[[]]、()、<> 等），但含义相同：框住边界框的坐标。

## vLLM 与 GLM 团队的合作

在 GLM-4.5 与 GLM-4.5V 模型发布之前，vLLM 团队与 GLM 团队密切合作，为解决模型发布相关的问题提供了大量支持，确保在模型发布之前 vLLM `main` 分支已完整支持开源的 GLM-4.5 系列。
