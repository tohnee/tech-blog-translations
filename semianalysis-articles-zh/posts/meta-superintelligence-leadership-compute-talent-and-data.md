在技术层面，我们认为导致这次失败训练的主要因素如下：

2. 专家选择路由（Expert choice routing）

## 分块注意力

大语言模型的注意力机制若朴素实现，其开销随 token 数量呈平方级增长。为解决这一问题，研究者引入了各类节省内存的机制。Meta 为 Behemoth 选择了分块注意力，而这可能是个错误。

![](https://substack-post-media.s3.amazonaws.com/public/images/260ea969-4c47-4a7f-9e2f-a272923ca32d_300x300.png)
*来源：Awnihannun，SemiAnalysis*

**标准因果注意力（Standard Causal Attention）**：想象一系列从左上角扇形展开的渐扩三角形，代表每个后续 token 的注意力规模。token 数翻倍，三角形面积就变为四倍。

![](https://substack-post-media.s3.amazonaws.com/public/images/c6b82b02-dfbd-418d-b602-c69039489fa5_300x297.png)
*来源：Awnihannun，SemiAnalysis*

**分块注意力（Chunked Attention）**把这个三角形切分成固定大小的块。每个块都将注意力重置到一个新的「首」token 上。凭借内存占用的降低，它能支持更长的上下文。Meta 认为实现长上下文需要它，但代价并不划算。每块的第一个 token 无法访问之前的上下文。尽管模型中有一些全局注意力层，但正如下文展开所述，这远远不够。

![](https://semianalysis.com/wp-content/uploads/2025/07/Chart3.png)
*来源：Awnihannun，SemiAnalysis*

**滑动窗口注意力（Sliding Window Attention）**在其他模型中提供了更平滑的替代方案：注意力窗口逐 token 向前滑动。这保持了局部连续性，即便长程推理仍需多层才能传播上下文。

![](https://substack-post-media.s3.amazonaws.com/public/images/9a73738b-2f65-4b75-879f-64d2134289c7_296x300.png)
*来源：Awnihannun，SemiAnalysis*

Behemoth 为追求效率而采用的分块注意力实现造成了盲区，尤其是在块边界处。当思维链（chain of thought）长度超过一个块时，这会损害模型发展推理能力的能力——模型难以进行更长跨度的推理。如今回头看这似乎显而易见，但我们认为部分问题在于，Meta 当时甚至没有搭建合适的长上下文评估或测试基础设施，以判断分块注意力无法用于训练推理模型。Meta 在 RL 和内部评测上远远落后，但新挖来的员工将帮助大幅缩小推理差距。

## 专家选择路由

大多数现代 LLM 采用混合专家（Mixture of Experts）架构：在模型的每一层之间，token 依据路由器（router）被分发到不同专家。在现代 MoE 模型中，大多数采用 **token 选择路由（token choice routing）** 训练，即路由器输出一个形状为 T x E 的张量（T 为总 token 数，E 为 MoE 模型中的专家数），然后在 E 维度上执行 topK softmax，得到一个 T x K 的张量。这实际上意味着，路由器要为每个 token T 选出 K 个最可能的专家，K 可以是一个或多个专家。K 是研究员可以调节的超参数。

![](https://semianalysis.com/wp-content/uploads/2025/07/ffn-gimped.png)
*来源：Mixture-of-Experts with Expert Choice Routing 论文，图 1 token 选择路由*

这种方法的优势在于每个 token 都保证被 K 个专家处理，确保每个 token 的信息价值被相同数量的专家吸收。缺点是某些专家可能在 token 中异常「受欢迎」，而其他专家训练不足，导致各专家「智力」不均衡。这是一个已知问题，许多顶级实验室已开发出基于辅助损失（[或无损失](https://arxiv.org/abs/2412.19437)）负载均衡的修正方案。当使用专家并行（EP）训练时，这可能导致训练 MFU 下降，因为模型分散在不同 GPU 节点上，导致更多集合通信（NCCL）跑在横向扩展网络（InfiniBand 或 RoCE）而非纵向扩展网络（NVLink）上。这正是 NVIDIA NVL72 设计的一大动机——纵向扩展网络由此突破了标准 8 卡服务器的范畴。

**专家选择路由（Expert choice routing）**由 Google 于 2022 年提出，把逻辑反过来：由专家挑选 top-N 的 token。同样对路由器输出的 T x E 张量，专家选择路由在 T 维度上执行 topN softmax，得到一个 E x N 的张量。这实际上意味着 E 个专家各自选定了概率最高的 N 个 token 进行路由。超参数 N 可由研究员调节，但若要与 token 选择路由对齐，则 N = K * T / E。

![](https://substack-post-media.s3.amazonaws.com/public/images/9cbee1dd-3299-468a-a5a4-6b5c6718b8d7_908x590.png)
*来源：Mixture-of-Experts with Expert Choice Routing 论文，图 1 token 选择路由*

与 token 选择路由直接对比，专家选择路由保证专家以均衡方式被激活，避免了专家不均衡带来的性能退化。需要说明的是：两种情况下**做选择的都是路由器**。在 token 选择中，路由器的输入是 token，它挑选专家；在专家选择中，路由器的输入是专家，它挑选 token。

这均衡了专家训练的负载，并提升了分布式硬件上的 MFU。超大规模云厂商的网络正是为这类并行量身打造的，我们在[网络模型](https://semianalysis.com/ai-networking-model/)中有详尽覆盖。

这种方法的缺点与 token 选择架构恰好相反。专家选择路由可能导致某些「受欢迎」的 token 被多个专家处理。虽然这不会产生 token 选择路由那样的训练瓶颈，但可能导致模型泛化能力退化，因为 LLM 不再对所有 token 一视同仁。此外，大多数 EC 模型最后仍需用 TC 训练收尾，才能产出有效的 LLM。

推理是 EC 的另一个问题。推理分为两个步骤：预填充（Prefill）和解码（Decode）。预填充阶段将用户提示编码并载入 KV 缓存，这一步受算力（Flop）约束。解码阶段，模型逐层逐 token 计算注意力并穿过前馈网络。

在解码阶段，专家选择路由举步维艰：专家每层最初只能从 1 x batch size 个 token 中挑选，导致每个专家拿到的 token 集合相比训练时小得多（一次示例训练会有 8k 序列长度 x 16 batch size = 每轮 128k 个 token）。若像训练时那样看到完整序列，将破坏现代自回归模型的因果性，因此即便是 EC 模型也要混用 EC 与 TC。

Meta 在训练中途**从专家选择切换到 token 选择路由**，这对 EC 模型来说并不罕见。但切换带来的性能下降，导致最终模型明显差于全程用 TC 训练的模型。

## 数据质量：自酿的伤

Llama 3 405B 用 15T token 训练，而我们估计 Llama 4 Behemoth 需要多得多的 token——大 3-4 倍的量级。获取足够高质量的数据是重大瓶颈，西方超大规模云厂商也无法靠抄其他模型输出的「作业」走捷径。

在 Llama 4 Behemoth 之前，Meta 一直在用公开数据（如 Common Crawl），但训练中途切换到了自建的内部网页爬虫。虽然这一数据源总体更优，却也事与愿违。团队在新数据流的清洗和去重上焦头烂额，这些流程从未在大规模下经受过压力测试。

此外，与 OpenAI、DeepSeek 等所有其他顶级 AI 实验室不同，Meta 不使用 YouTube 数据。YouTube 课程字幕和其他视频是极佳的数据来源，缺少这些数据，公司可能难以打造多模态模型。

## 扩展实验

除上述技术问题外，Llama 4 团队还难以把研究实验顺利放大为完整的训练运行。研究方向彼此竞争，又缺乏领导力来裁定哪条路线最具产出前景。某些模型架构选择没有经过适当的消融（ablation）实验就被塞进了模型。这导致了管理混乱的扩展阶梯（scaling ladder）。

举一个扩展实验有多难的例子，看看 OpenAI [训练 GPT 4.5](https://www.youtube.com/watch?v=6nJZopACRuQ&t=2621s) 的过程。OAI 的内部代码 monorepo 对模型训练非常重要，因为在做训练消融时，他们需要一个已知未被污染的验证数据集来度量困惑度（perplexity）。在放大 GPT 4.5 训练实验时，他们一度看到模型泛化能力出现可喜进展，却在训练中途发现 monorepo 的一部分是直接从公开数据复制粘贴来的。模型不是在泛化，而是在背诵训练数据集里记忆的代码！大型预训练运行需要极度的审慎与准备才能有效执行。

尽管有这些技术问题，也并非全盘皆输。Meta 仍能将 logits 蒸馏到更小、更高效的预训练 Maverick 和 Scout 模型中，绕开大模型的某些缺陷架构选择。对较小模型而言，蒸馏远比强化学习高效。话虽如此，这些模型仍受限于其来源的短板：它们在同尺寸模型中并非最佳。

## Meta GenAI 2.0 第二部分：弥合人才差距

基础设施改造推进、技术教训吸收完毕，Meta 的 GenAI 2.0 战略现在转向超级智能的下一味原料：人才。

Mark Zuckerberg 清楚 Meta 相对顶级 AI 实验室的人才差距，并亲自接管招聘。他的使命是打造一支小而人才密度极高的团队，动辄开出数千万美元的签约奖金。目标是制造「飞轮效应」：顶级研究员加入这场冒险，为项目带来公信力与势头。近期的高调挖角已经奏效，包括：

- Nat Friedman，前 GitHub CEO
- Alex Wang，前 Scale AI CEO
- Daniel Gross，SSI（Ilya Sustkever 创办的初创公司）的 CEO 兼联合创始人。

招聘宣讲极具吸引力：人均算力无人能敌、有机会打造最好的开源模型家族、以及触达超过 **20 亿日活用户（DAU）**。普遍在 4 年 $200M 到 $300M 每人量级的报价更是强化了这一卖点。凭借这些，Meta 已从 OpenAI、Anthropic 及许多其他公司网罗了顶尖人才。

## 并购、Scale AI 等

据报道，Zuckerberg 曾向 **Thinking Machines** 和 **SSI** 两家公司发出收购要约，但均遭拒绝。虽然有人认为 Zuckerberg 是「退而求其次」选择了 Scale AI，我们不这么看。如前所述，Llama 4 诸多问题的核心是数据问题，收购 Scale 正是直击这一软肋的动作。

Alex 将带来 Scale 的众多顶级工程师，尤其是专注评测（evals）的 SEAL 实验室——这正是 Meta 迫切需要的。SEAL 开发了推理模型评测的顶级基准之一 [HLE（Humanity's Last Exam）](https://agi.safe.ai/)。随着 Nat Friedman 和 Daniel Gross 加入，Meta 得到的不只是精英操盘手，还有 AI 社区最多产、最受尊敬的两位投资人。Meta 顶层拥有非常强大的产品人才。
