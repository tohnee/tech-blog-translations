# DeepSeek-V3 技术报告

> 原文：[DeepSeek-V3 Technical Report](https://arxiv.org/abs/2412.19437) · DeepSeek-AI arXiv

DeepSeek-AI

research@deepseek.com

###### 摘要

我们发布了 DeepSeek-V3，一个强大的专家混合（Mixture-of-Experts，MoE）语言模型，总参数量为 671B，每个 token 激活 37B 参数。为了实现高效推理与高性价比训练，DeepSeek-V3 采用了多头潜在注意力（Multi-head Latent Attention，MLA）和 DeepSeekMoE 架构，二者均已在 DeepSeek-V2 中得到充分验证。此外，DeepSeek-V3 开创性地采用无辅助损失（auxiliary-loss-free）的负载均衡策略，并引入多 token 预测（Multi-Token Prediction）训练目标以获得更强的性能。我们在 14.8 万亿（14.8T）多样化、高质量的 token 上对 DeepSeek-V3 进行预训练，随后通过监督微调（Supervised Fine-Tuning）和强化学习（Reinforcement Learning）阶段充分挖掘其能力。全面的评测表明，DeepSeek-V3 优于其他开源模型，并取得了与领先闭源模型相当的性能。尽管性能出色，DeepSeek-V3 的完整训练仅需 2.788M H800 GPU 小时。此外，其训练过程非常稳定：在整个训练过程中，我们没有遇到任何不可恢复的损失尖峰（loss spike），也没有进行任何回滚。模型检查点可在 <https://github.com/deepseek-ai/DeepSeek-V3> 获取。

## 1 引言

近年来，大语言模型（LLM）经历了快速的迭代与演进（OpenAI, 2024a; Anthropic, 2024; Google, 2024），正逐步缩小与通用人工智能（Artificial General Intelligence，AGI）之间的差距。除闭源模型外，开源模型——包括 DeepSeek 系列（DeepSeek-AI, 2024b; DeepSeek-AI, 2024c; Guo et al., 2024; DeepSeek-AI, 2024a）、LLaMA 系列（Touvron et al., 2023a; Touvron et al., 2023b; AI@Meta, 2024a; AI@Meta, 2024b）、Qwen 系列（Qwen, 2023; Qwen, 2024a; Qwen, 2024b）以及 Mistral 系列（Jiang et al., 2023; Mistral, 2024）——也在大步前进，努力缩小与其闭源对手的差距。为了进一步突破开源模型能力边界，我们扩大了模型规模，推出 DeepSeek-V3：一个拥有 671B 参数的大型专家混合（MoE）模型，其中每个 token 激活 37B 参数。

秉持面向未来的视角，我们始终追求强大的模型性能与经济的成本。因此，在架构方面，DeepSeek-V3 仍然采用多头潜在注意力（MLA）（DeepSeek-AI, 2024c）以实现高效推理，采用 DeepSeekMoE（Dai et al., 2024）以实现高性价比训练。这两种架构已在 DeepSeek-V2（DeepSeek-AI, 2024c）中得到验证，证明了它们在实现高效训练与推理的同时保持稳健模型性能的能力。在基础架构之外，我们实施了两项额外策略以进一步增强模型能力。第一，DeepSeek-V3 开创性地采用无辅助损失的负载均衡策略（Wang et al., 2024a），旨在最小化为鼓励负载均衡而对模型性能造成的不利影响。第二，DeepSeek-V3 采用了多 token 预测训练目标，我们观察到该目标可以提升模型在评测基准上的整体表现。

为了实现高效训练，我们支持 FP8 混合精度训练，并对训练框架实施了全面优化。低精度训练已成为高效训练的一种有前景的方案（Kalamkar et al., 2019; Narang et al., 2017; Peng et al., 2023b; Dettmers et al., 2022），其演进与硬件能力的进步密切相关（Micikevicius et al., 2022; Luo et al., 2024; Rouhani et al., 2023a）。在这项工作中，我们引入了 FP8 混合精度训练框架，并首次在超大规模模型上验证了其有效性。通过支持 FP8 计算与存储，我们同时实现了训练加速与 GPU 显存占用的降低。在训练框架方面，我们设计了用于高效流水线并行的 DualPipe 算法，它具有更少的流水线气泡，并通过计算-通信重叠在训练期间隐藏了大部分通信。这种重叠确保了随着模型进一步扩展，只要我们保持恒定的计算通信比，就仍能跨节点使用细粒度专家，同时实现近乎为零的 all-to-all 通信开销。此外，我们还开发了高效的跨节点 all-to-all 通信内核，以充分利用 InfiniBand（IB）和 NVLink 带宽。再者，我们对内存占用进行了精细优化，使得无需使用代价高昂的张量并行即可训练 DeepSeek-V3。综合这些努力，我们实现了很高的训练效率。

在预训练阶段，我们在 14.8T 高质量且多样化的 token 上训练 DeepSeek-V3。预训练过程非常稳定：在整个训练过程中，我们没有遇到任何不可恢复的损失尖峰，也没有进行回滚。随后，我们对 DeepSeek-V3 进行了两阶段的上下文长度扩展：第一阶段将最大上下文长度扩展到 32K，第二阶段进一步扩展到 128K。接下来，我们在 DeepSeek-V3 的基座模型上进行后训练，包括监督微调（SFT）和强化学习（RL），使其与人类偏好对齐并进一步释放其潜力。在后训练阶段，我们从 DeepSeek-R1 系列模型蒸馏推理能力，同时谨慎地在模型准确率与生成长度之间保持平衡。

我们在一系列全面的基准上评测 DeepSeek-V3。尽管训练成本经济，全面评测显示 DeepSeek-V3-Base 已成为当前可用的最强开源基座模型，尤其是在代码和数学方面。其对话版本也优于其他开源模型，并在一系列标准化与开放式基准上取得与领先闭源模型（包括 GPT-4o 和 Claude-3.5-Sonnet）相当的性能。

我们的主要贡献包括：

**架构：创新的负载均衡策略与训练目标**

- 在 DeepSeek-V2 高效架构的基础上，我们首创了用于负载均衡的无辅助损失策略，它能够最小化为鼓励负载均衡而导致的性能下降。
- 我们研究了多 token 预测（Multi-Token Prediction，MTP）目标，并证明其对模型性能有益。它还可用于投机解码（speculative decoding）以加速推理。

**预训练：迈向极致训练效率**

- 我们设计了 FP8 混合精度训练框架，并首次在超大规模模型上验证了 FP8 训练的可行性与有效性。
- 通过算法、框架与硬件的协同设计，我们克服了跨节点 MoE 训练中的通信瓶颈，实现了近乎完全的计算-通信重叠。这显著提升了训练效率并降低了训练成本，使我们能够在不增加额外开销的情况下进一步扩大模型规模。
- 仅以 2.664M H800 GPU 小时的经济成本，我们在 14.8T token 上完成了 DeepSeek-V3 的预训练，得到当前最强的开源基座模型。预训练之后的后续训练阶段仅需 0.1M GPU 小时。

**后训练：从 DeepSeek-R1 蒸馏知识**

- 我们提出了一种创新方法，将长思维链（Chain-of-Thought，CoT）模型（具体为 DeepSeek R1 系列模型之一）的推理能力蒸馏到标准 LLM（尤其是 DeepSeek-V3）中。我们的流程将 R1 的验证与反思模式优雅地融入 DeepSeek-V3，并显著提升了其推理性能。同时，我们也对 DeepSeek-V3 的输出风格与长度保持了控制。

**核心评测结果总结**

- 知识：（1）在 MMLU、MMLU-Pro 和 GPQA 等教育类基准上，DeepSeek-V3 优于所有其他开源模型，在 MMLU 上取得 88.5、在 MMLU-Pro 上取得 75.9、在 GPQA 上取得 59.1 的成绩。其表现与 GPT-4o 和 Claude-Sonnet-3.5 等领先闭源模型相当，缩小了该领域中开源与闭源模型之间的差距。（2）在事实性基准上，DeepSeek-V3 在 SimpleQA 和 Chinese SimpleQA 上均表现出开源模型中的领先性能。虽然在英文事实知识（SimpleQA）上落后于 GPT-4o 和 Claude-Sonnet-3.5，但它在中文事实知识（Chinese SimpleQA）上超越了这些模型，凸显了其在中文事实知识方面的优势。
- 代码、数学与推理：（1）在所有非长 CoT 的开源与闭源模型中，DeepSeek-V3 在数学相关基准上取得了最先进（state-of-the-art）的表现。值得注意的是，它甚至在 MATH-500 等特定基准上超过了 o1-preview，展示了其稳健的数学推理能力。（2）在代码相关任务上，DeepSeek-V3 成为编程竞赛基准（如 LiveCodeBench）上表现最佳的模型，巩固了其在该领域的领先地位。在工程类任务上，虽然 DeepSeek-V3 略低于 Claude-Sonnet-3.5，但仍以显著优势领先于其他所有模型，展示了其在多样化技术基准上的竞争力。

## 2 架构

我们首先介绍 DeepSeek-V3 的基础架构，其特色是用于高效推理的多头潜在注意力（MLA）（DeepSeek-AI, 2024c）和用于经济训练的 DeepSeekMoE（Dai et al., 2024）。然后，我们介绍多 token 预测（MTP）训练目标，我们观察到它可以提升模型在评测基准上的整体表现。对于其他未明确提及的细节，DeepSeek-V3 遵循 DeepSeek-V2（DeepSeek-AI, 2024c）的设置。

### 2.1 基础架构

DeepSeek-V3 的基础架构仍处于 Transformer（Vaswani et al., 2017）框架之内。为了实现高效推理与经济训练，DeepSeek-V3 同样采用了已被 DeepSeek-V2 充分验证的 MLA 和 DeepSeekMoE。与 DeepSeek-V2 相比的一个例外是，我们额外为 DeepSeekMoE 引入了无辅助损失的负载均衡策略（Wang et al., 2024a），以缓解为确保负载均衡而导致的性能下降。图 2 展示了 DeepSeek-V3 的基础架构，本节将简要回顾 MLA 和 DeepSeekMoE 的细节。

#### 2.1.1 多头潜在注意力

在注意力部分，DeepSeek-V3 采用 MLA 架构。设 $d$ 表示嵌入维度，$n_{h}$ 表示注意力头数，$d_{h}$ 表示每头维度，$\mathbf{h}_{t}\in\mathbb{R}^{d}$ 表示给定注意力层中第 $t$ 个 token 的注意力输入。MLA 的核心思想是对注意力键和值进行低秩联合压缩，以减少推理期间的键值（KV）缓存：

$$\boxed{\color[rgb]{0,0,1}\mathbf{c}_{t}^{KV}} = W^{DKV}\mathbf{h}_{t}, \tag{1}$$

$$[\mathbf{k}_{t,1}^{C};\mathbf{k}_{t,2}^{C};...;\mathbf{k}_{t,n_{h}}^{C}]=\mathbf{k}_{t}^{C} = W^{UK}\mathbf{c}_{t}^{KV}, \tag{2}$$

$$\boxed{\color[rgb]{0,0,1}\mathbf{k}_{t}^{R}} = \operatorname{RoPE}({W^{KR}}\mathbf{h}_{t}), \tag{3}$$

$$\mathbf{k}_{t,i} = [\mathbf{k}_{t,i}^{C};\mathbf{k}_{t}^{R}], \tag{4}$$

$$[\mathbf{v}_{t,1}^{C};\mathbf{v}_{t,2}^{C};...;\mathbf{v}_{t,n_{h}}^{C}]=\mathbf{v}_{t}^{C} = W^{UV}\mathbf{c}_{t}^{KV}, \tag{5}$$

其中 $\mathbf{c}_{t}^{KV}\in\mathbb{R}^{d_{c}}$ 是键和值的压缩潜在向量；$d_{c}(\ll d_{h}n_{h})$ 表示 KV 压缩维度；$W^{DKV}\in\mathbb{R}^{d_{c}\times d}$ 表示下投影矩阵；$W^{UK},W^{UV}\in\mathbb{R}^{d_{h}n_{h}\times d_{c}}$ 分别是键和值的上投影矩阵；$W^{KR}\in\mathbb{R}^{d_{h}^{R}\times d}$ 是用于生成携带旋转位置编码（Rotary Positional Embedding，RoPE）（Su et al., 2024）的解耦键的矩阵；$\operatorname{RoPE}(\cdot)$ 表示应用 RoPE 矩阵的操作；$[\cdot;\cdot]$ 表示拼接。注意，对于 MLA，在生成期间只需缓存蓝框向量（即 $\mathbf{c}_{t}^{KV}$ 和 $\mathbf{k}_{t}^{R}$），这显著减少了 KV 缓存，同时保持了与标准多头注意力（MHA）（Vaswani et al., 2017）相当的性能。

对于注意力查询，我们同样进行低秩压缩，这可以减少训练期间的激活内存：

$$\mathbf{c}_{t}^{Q} = W^{DQ}\mathbf{h}_{t}, \tag{6}$$

$$[\mathbf{q}_{t,1}^{C};\mathbf{q}_{t,2}^{C};...;\mathbf{q}_{t,n_{h}}^{C}]=\mathbf{q}_{t}^{C} = W^{UQ}\mathbf{c}_{t}^{Q}, \tag{7}$$

$$[\mathbf{q}_{t,1}^{R};\mathbf{q}_{t,2}^{R};...;\mathbf{q}_{t,n_{h}}^{R}]=\mathbf{q}_{t}^{R} = \operatorname{RoPE}({W^{QR}}\mathbf{c}_{t}^{Q}), \tag{8}$$

$$\mathbf{q}_{t,i} = [\mathbf{q}_{t,i}^{C};\mathbf{q}_{t,i}^{R}], \tag{9}$$

其中 $\mathbf{c}_{t}^{Q}\in\mathbb{R}^{d_{c}^{\prime}}$ 是查询的压缩潜在向量；$d_{c}^{\prime}(\ll d_{h}n_{h})$ 表示查询压缩维度；$W^{DQ}\in\mathbb{R}^{d_{c}^{\prime}\times d},W^{UQ}\in\mathbb{R}^{d_{h}n_{h}\times d_{c}^{\prime}}$ 分别是查询的下投影与上投影矩阵；$W^{QR}\in\mathbb{R}^{d_{h}^{R}n_{h}\times d_{c}^{\prime}}$ 是用于生成携带 RoPE 的解耦查询的矩阵。

最终，注意力查询（$\mathbf{q}_{t,i}$）、键（$\mathbf{k}_{j,i}$）与值（$\mathbf{v}_{j,i}^{C}$）相结合，得到最终注意力输出 $\mathbf{u}_{t}$：

$$\mathbf{o}_{t,i} = \sum_{j=1}^{t}\operatorname{Softmax}_{j}(\frac{\mathbf{q}_{t,i}^{T}\mathbf{k}_{j,i}}{\sqrt{d_{h}+d_{h}^{R}}})\mathbf{v}_{j,i}^{C}, \tag{10}$$

$$\mathbf{u}_{t} = W^{O}[\mathbf{o}_{t,1};\mathbf{o}_{t,2};...;\mathbf{o}_{t,n_{h}}], \tag{11}$$

其中 $W^{O}\in\mathbb{R}^{d\times d_{h}n_{h}}$ 表示输出投影矩阵。

#### 2.1.2 采用无辅助损失负载均衡的 DeepSeekMoE

##### DeepSeekMoE 的基础架构。

在前馈网络（FFN）部分，DeepSeek-V3 采用 DeepSeekMoE 架构（Dai et al., 2024）。与 GShard（Lepikhin et al., 2021）等传统 MoE 架构相比，DeepSeekMoE 使用更细粒度的专家，并将部分专家隔离为共享专家。设 $\mathbf{u}_{t}$ 表示第 $t$ 个 token 的 FFN 输入，我们按如下方式计算 FFN 输出 $\mathbf{h}_{t}^{\prime}$：

$$\mathbf{h}_{t}^{\prime} = \mathbf{u}_{t}+\sum_{i=1}^{N_{s}}{\operatorname{FFN}^{(s)}_{i}\left(\mathbf{u}_{t}\right)}+\sum_{i=1}^{N_{r}}{g_{i,t}\operatorname{FFN}^{(r)}_{i}\left(\mathbf{u}_{t}\right)}, \tag{12}$$

$$g_{i,t} = \frac{g^{\prime}_{i,t}}{\sum_{j=1}^{N_{r}}g^{\prime}_{j,t}}, \tag{13}$$

$$g^{\prime}_{i,t} =\begin{cases}s_{i,t},&s_{i,t}\in\operatorname{Topk}(\{s_{j,t}|1\leqslant j\leqslant N_{r}\},K_{r}),\\ 0,&\text{otherwise},\end{cases} \tag{14}$$

$$s_{i,t} = \operatorname{Sigmoid}\left({\mathbf{u}_{t}}^{T}\mathbf{e}_{i}\right), \tag{15}$$

其中 $N_{s}$ 和 $N_{r}$ 分别表示共享专家和路由专家的数量；$\operatorname{FFN}^{(s)}_{i}(\cdot)$ 和 $\operatorname{FFN}^{(r)}_{i}(\cdot)$ 分别表示第 $i$ 个共享专家和第 $i$ 个路由专家；$K_{r}$ 表示被激活的路由专家数量；$g_{i,t}$ 是第 $i$ 个专家的门控值；$s_{i,t}$ 是 token 与专家的亲和度；$\mathbf{e}_{i}$ 是第 $i$ 个路由专家的中心向量；$\operatorname{Topk}(\cdot,K)$ 表示由第 $t$ 个 token 与所有路由专家计算得到的亲和度分数中最高的 $K$ 个分数所构成的集合。与 DeepSeek-V2 略有不同的是，DeepSeek-V3 使用 sigmoid 函数计算亲和度分数，并对所有被选中的亲和度分数进行归一化以生成门控值。

##### 无辅助损失的负载均衡。

对于 MoE 模型，专家负载不均衡会导致路由坍缩（Shazeer et al., 2017），并在专家并行场景下降低计算效率。传统解决方案通常依赖辅助损失（Fedus et al., 2021; Lepikhin et al., 2021）来避免负载不均衡。然而，过大的辅助损失会损害模型性能（Wang et al., 2024a）。为了在负载均衡与模型性能之间取得更好的权衡，我们首创了无辅助损失的负载均衡策略（Wang et al., 2024a）来确保负载均衡。具体而言，我们为每个专家引入偏置项 $b_{i}$，并将其加到相应的亲和度分数 $s_{i,t}$ 上以确定 top-K 路由：

$$g^{\prime}_{i,t} =\begin{cases}s_{i,t},&s_{i,t}+b_{i}\in\operatorname{Topk}(\{s_{j,t}+b_{j}|1\leqslant j\leqslant N_{r}\},K_{r}),\\ 0,&\text{otherwise}.\end{cases} \tag{16}$$

请注意，偏置项仅用于路由。将与 FFN 输出相乘的门控值仍然由原始亲和度分数 $s_{i,t}$ 得到。在训练期间，我们持续监控每个训练步整个批次上的专家负载。在每一步结束时，如果某偏置项对应的专家过载，我们就将该偏置项减小 $\gamma$；如果其对应的专家欠载，则将其增大 $\gamma$，其中 $\gamma$ 是一个称为偏置更新速度（bias update speed）的超参数。通过这种动态调整，DeepSeek-V3 在训练期间保持均衡的专家负载，并取得比通过纯辅助损失鼓励负载均衡的模型更好的性能。

##### 互补的序列级辅助损失。

尽管 DeepSeek-V3 主要依靠无辅助损失策略实现负载均衡，但为了防止单个序列内出现极端不均衡，我们还采用了一个互补的序列级平衡损失：

$$\mathcal{L}_{\mathrm{Bal}} = \alpha\sum_{i=1}^{N_{r}}{f_{i}P_{i}}, \tag{17}$$

$$f_{i}=\frac{N_{r}}{K_{r}T}\sum_{t=1}^{T}\mathds{1}\left(s_{i,t}\in\operatorname{Topk}(\{s_{j,t}|1\leqslant j\leqslant N_{r}\},K_{r})\right), \tag{18}$$

$$s^{\prime}_{i,t} = \frac{s_{i,t}}{\sum_{j=1}^{N_{r}}s_{j,t}}, \tag{19}$$

$$P_{i} = \frac{1}{T}\sum_{t=1}^{T}{s^{\prime}_{i,t}}, \tag{20}$$

其中平衡因子 $\alpha$ 是一个超参数，在 DeepSeek-V3 中它将被赋予一个极小的值；$\mathds{1}(\cdot)$ 表示指示函数；$T$ 表示一个序列中的 token 数量。序列级平衡损失鼓励每个序列上的专家负载保持均衡。

##### 节点受限路由。

与 DeepSeek-V2 使用的设备受限路由类似，DeepSeek-V3 同样使用受限路由机制来限制训练期间的通信成本。简言之，我们确保每个 token 至多被发送到 $M$ 个节点，这些节点依据分布在各节点上的专家的最高 $\frac{K_{r}}{M}$ 个亲和度分数之和选出。在此约束下，我们的 MoE 训练框架几乎可以实现完全的计算-通信重叠。

##### 不丢弃 token。

得益于有效的负载均衡策略，DeepSeek-V3 在整个训练期间保持良好的负载均衡。因此，DeepSeek-V3 在训练期间不丢弃任何 token。此外，我们还实施了专门的部署策略以确保推理负载均衡，因此 DeepSeek-V3 在推理期间也不丢弃 token。

### 2.2 多 token 预测

受 Gloeckle et al. (2024) 启发，我们为 DeepSeek-V3 研究并设定了多 token 预测（Multi-Token Prediction，MTP）目标，将每个位置的预测范围扩展至多个未来 token。一方面，MTP 目标可以加密训练信号，并可能提升数据效率；另一方面，MTP 可以让模型预先规划其表示，从而更好地预测未来 token。图 3 展示了我们的 MTP 实现。与 Gloeckle et al. (2024) 使用独立输出头并行预测 $D$ 个额外 token 的做法不同，我们串行地预测额外 token，并在每个预测深度上保持完整的因果链。本节介绍我们 MTP 实现的细节。

##### MTP 模块。

具体而言，我们的 MTP 实现使用 $D$ 个串行模块来预测 $D$ 个额外 token。第 $k$ 个 MTP 模块由共享嵌入层 $\operatorname{Emb}(\cdot)$、共享输出头 $\operatorname{OutHead}(\cdot)$、一个 Transformer 块 $\operatorname{TRM}_{k}(\cdot)$ 以及投影矩阵 $M_{k}\in\mathbb{R}^{d\times 2d}$ 组成。对于第 $i$ 个输入 token $t_{i}$，在第 $k$ 个预测深度，我们首先通过线性投影将第 $i$ 个 token 在第 $(k-1)$ 个深度的表示 $\mathbf{h}_{i}^{k-1}\in\mathbb{R}^{d}$ 与第 $(i+k)$ 个 token 的嵌入 $Emb(t_{i+k})\in\mathbb{R}^{d}$ 相结合：

$$\mathbf{h}_{i}^{\prime k}=M_{k}[\operatorname{RMSNorm}(\mathbf{h}_{i}^{k-1});\operatorname{RMSNorm}(\operatorname{Emb}(t_{i+k}))], \tag{21}$$

其中 $[\cdot;\cdot]$ 表示拼接。特别地，当 $k=1$ 时，$\mathbf{h}_{i}^{k-1}$ 指主模型给出的表示。注意，每个 MTP 模块的嵌入层与主模型共享。结合后的 $\mathbf{h}_{i}^{\prime k}$ 作为第 $k$ 个深度 Transformer 块的输入，以产生当前深度的输出表示 $\mathbf{h}_{i}^{k}$：

$$\mathbf{h}_{1:T-k}^{k}=\operatorname{TRM}_{k}(\mathbf{h}_{1:T-k}^{\prime k}), \tag{22}$$

其中 $T$ 表示输入序列长度，$i:j$ 表示切片操作（左右边界均包含）。最后，以 $\mathbf{h}_{i}^{k}$ 为输入，共享输出头将计算第 $k$ 个额外预测 token 的概率分布 $P_{i+1+k}^{k}\in\mathbb{R}^{V}$，其中 $V$ 是词表大小：

$$P_{i+k+1}^{k}=\operatorname{OutHead}(\mathbf{h}_{i}^{k}). \tag{23}$$

输出头 $\operatorname{OutHead}(\cdot)$ 将表示线性映射为 logits，随后应用 $\operatorname{Softmax}(\cdot)$ 函数计算第 $k$ 个额外 token 的预测概率。同样，每个 MTP 模块的输出头与主模型共享。我们保持预测因果链的原则与 EAGLE（Li et al., 2024b）类似，但 EAGLE 的主要目标是投机解码（Xia et al., 2023; Leviathan et al., 2023），而我们利用 MTP 来改进训练。

##### MTP 训练目标。

对于每个预测深度，我们计算交叉熵损失 $\mathcal{L}_{\text{MTP}}^{k}$：

$$\mathcal{L}_{\text{MTP}}^{k}=\operatorname{CrossEntropy}(P_{2+k:T+1}^{k},t_{2+k:T+1})=-\frac{1}{T}\sum_{i=2+k}^{T+1}\log P_{i}^{k}[t_{i}], \tag{24}$$

其中 $T$ 表示输入序列长度，$t_{i}$ 表示第 $i$ 个位置的真实 token，$P_{i}^{k}[t_{i}]$ 表示由第 $k$ 个 MTP 模块给出的 $t_{i}$ 的对应预测概率。最后，我们计算所有深度 MTP 损失的平均值，并乘以权重因子 $\lambda$，得到总体 MTP 损失 $\mathcal{L}_{\text{MTP}}$，作为 DeepSeek-V3 的附加训练目标：

$$\mathcal{L}_{\text{MTP}}=\frac{\lambda}{D}\sum_{k=1}^{D}\mathcal{L}_{\text{MTP}}^{k}. \tag{25}$$

##### 推理中的 MTP。

我们的 MTP 策略主要旨在提升主模型的性能，因此在推理时可以直接丢弃 MTP 模块，主模型仍可独立正常工作。此外，我们也可以将这些 MTP 模块用于投机解码，以进一步改善生成延迟。

## 3 基础设施

### 3.1 计算集群

DeepSeek-V3 在配备 2048 块 NVIDIA H800 GPU 的集群上训练。H800 集群中的每个节点包含 8 块 GPU，节点内通过 NVLink 和 NVSwitch 连接。在不同节点之间，则使用 InfiniBand（IB）互连来承载通信。

### 3.2 训练框架

DeepSeek-V3 的训练由 HAI-LLM 框架支持，这是一个由我们的工程师从零开始精心打造的高效轻量训练框架。总体而言，DeepSeek-V3 采用 16 路流水线并行（PP）（Qi et al., 2023a）、跨越 8 个节点的 64 路专家并行（EP）（Lepikhin et al., 2021）以及 ZeRO-1 数据并行（DP）（Rajbhandari et al., 2020）。

为了支撑 DeepSeek-V3 的高效训练，我们实施了细致的工程优化。首先，我们设计了用于高效流水线并行的 DualPipe 算法。与现有 PP 方法相比，DualPipe 的流水线气泡更少。更重要的是，它跨前向与反向过程重叠计算与通信阶段，从而解决了跨节点专家并行带来的沉重通信开销难题。其次，我们开发了高效的跨节点 all-to-all 通信内核，以充分利用 IB 与 NVLink 带宽，并节省专用于通信的流多处理器（Streaming Multiprocessor，SM）。最后，我们对训练期间的内存占用进行了精细优化，使我们无需使用代价高昂的张量并行（TP）即可训练 DeepSeek-V3。

#### 3.2.1 DualPipe 与计算-通信重叠

图 4：一对独立前向与反向 chunk 的重叠策略（Transformer 块的边界未对齐）。橙色表示前向，绿色表示「输入反向」，蓝色表示「权重反向」，紫色表示 PP 通信，红色表示屏障（barrier）。all-to-all 与 PP 通信均可被完全隐藏。

对 DeepSeek-V3 而言，跨节点专家并行带来的通信开销导致计算与通信之比约为 1:1，效率低下。为应对这一挑战，我们设计了一种名为 DualPipe 的创新流水线并行算法，它不仅通过有效重叠前向与反向的计算-通信阶段加速模型训练，还减少了流水线气泡。

DualPipe 的关键思想是在一对独立的前向和反向 chunk 内部重叠计算与通信。具体而言，我们将每个 chunk 划分为四个组件：注意力、all-to-all 分发（dispatch）、MLP 和 all-to-all 组合（combine）。特别地，对于反向 chunk，注意力和 MLP 都被进一步拆分为输入反向（backward for input）和权重反向（backward for weights）两部分，与 ZeroBubble（Qi et al., 2023b）中的做法类似。此外，我们还有一个 PP 通信组件。如图 4 所示，对于一对前向和反向 chunk，我们重新排列这些组件，并手动调整专用于通信与计算的 GPU SM 比例。在这种重叠策略下，我们可以确保 all-to-all 与 PP 通信在执行期间均被完全隐藏。基于这一高效的重叠策略，完整的 DualPipe 调度如图 5 所示。它采用双向流水线调度，同时从流水线的两端馈入微批次（micro-batch），相当大一部分通信可被完全重叠。这种重叠还确保了随着模型进一步扩展，只要我们保持恒定的计算通信比，就仍能跨节点使用细粒度专家，同时实现近乎为零的 all-to-all 通信开销。

图 5：8 个 PP rank 与 20 个微批次在两个方向上的 DualPipe 调度示例。反方向上的微批次与正方向上的对称，因此为简化示意我们省略了它们的批次编号。被同一条黑色边框包围的两个单元互为计算与通信重叠。其中 F&B 表示两个相互重叠的前向与反向 chunk 的执行时间。

此外，即便在没有沉重通信负担的更一般场景中，DualPipe 依然展现出效率优势。在表 2 中，我们汇总了不同 PP 方法下的流水线气泡与内存占用。如表所示，与 ZB1P（Qi et al., 2023b）和 1F1B（Harlap et al., 2018）相比，DualPipe 显著减少了流水线气泡，而峰值激活内存仅增加 $\frac{1}{PP}$ 倍。尽管 DualPipe 需要保留两份模型参数，但由于我们在训练中使用了较大的 EP 规模，这并不会显著增加内存消耗。与 Chimera（Li and Hoefler, 2021）相比，DualPipe 只要求流水线阶段数和微批次数可被 2 整除，而不要求微批次数可被流水线阶段数整除。此外，对 DualPipe 而言，无论微批次数量如何增长，气泡和激活内存都不会增加。

| 方法 | 气泡 | 参数 | 激活值 |
| --- | --- | --- | --- |
| 1F1B | $(PP-1)(F+B)$ | $1\times$ | $PP$ |
| ZB1P | $(PP-1)(F+B-2W)$ | $1\times$ | $PP$ |
| DualPipe（本文） | $(\frac{PP}{2}-1)(F\&B+B-3W)$ | $2\times$ | $PP+1$ |

表 2：不同流水线并行方法的流水线气泡与内存占用对比。$F$ 表示一个前向 chunk 的执行时间，$B$ 表示一个完整反向 chunk 的执行时间，$W$ 表示一个「权重反向」chunk 的执行时间，$F\&B$ 表示两个相互重叠的前向与反向 chunk 的执行时间。

#### 3.2.2 跨节点 All-to-All 通信的高效实现

为了确保 DualPipe 的计算性能，我们定制了高效的跨节点 all-to-all 通信内核（包括分发与组合），以节省专用于通信的 SM 数量。这些内核的实现与 MoE 门控算法以及我们集群的网络拓扑协同设计。具体来说，在我们的集群中，跨节点 GPU 之间通过 IB 全互连，节点内通信则经由 NVLink 处理。NVLink 提供 160 GB/s 的带宽，约为 IB（50 GB/s）的 3.2 倍。为了有效利用 IB 和 NVLink 的不同带宽，我们限制每个 token 至多被分发到 4 个节点，从而减少 IB 流量。对于每个 token，当其路由决策作出后，它会首先通过 IB 被传输到目标节点上具有相同节点内索引的 GPU。一旦到达目标节点，我们将尽力确保它经由 NVLink 即刻转发到承载其目标专家的具体 GPU，而不会被后续到达的 token 阻塞。通过这种方式，经由 IB 和 NVLink 的通信被完全重叠，每个 token 可以在每个节点上高效地平均选择 3.2 个专家，而不会引入来自 NVLink 的额外开销。这意味着，尽管 DeepSeek-V3 在实践中仅选择 8 个路由专家，它可以在保持相同通信成本的前提下将该数量最多扩展到 13 个专家（4 节点 $\times$ 每节点 3.2 个专家）。总体而言，在这样的通信策略下，仅 20 个 SM 就足以充分利用 IB 和 NVLink 的带宽。

在实现细节上，我们采用 warp 专用化（warp specialization）技术（Bauer et al., 2014），将 20 个 SM 划分为 10 个通信通道。在分发过程中，（1）IB 发送、（2）IB 到 NVLink 的转发、（3）NVLink 接收分别由各自的 warp 处理。分配给每个通信任务的 warp 数量会根据所有 SM 上的实际负载动态调整。类似地，在组合过程中，（1）NVLink 发送、（2）NVLink 到 IB 的转发与累加、（3）IB 接收与累加也由动态调整的 warp 处理。此外，分发与组合内核都与计算流重叠，因此我们也考虑了它们对其他 SM 计算内核的影响。具体来说，我们采用定制的 PTX（Parallel Thread Execution）指令并自动调优通信分块（chunk）大小，显著减少了对 L2 缓存的占用以及对其他 SM 的干扰。

#### 3.2.3 以极小开销实现极致内存节省

为了减少训练期间的内存占用，我们采用了以下技术。

##### RMSNorm 与 MLA 上投影的重计算。

我们在反向传播期间重算所有 RMSNorm 操作和 MLA 上投影，从而无需持久存储它们的输出激活。以很小的开销，该策略显著降低了存储激活所需的内存。

##### CPU 中的指数移动平均。

在训练期间，我们保留模型参数的指数移动平均（Exponential Moving Average，EMA），用于在学习率衰减后对模型性能进行早期估计。EMA 参数存储在 CPU 内存中，并在每个训练步之后异步更新。该方法使我们能够在不产生额外内存或时间开销的情况下维护 EMA 参数。

##### 多 token 预测的共享嵌入与输出头。

借助 DualPipe 策略，我们将模型的最浅层（包括嵌入层）与最深层（包括输出头）部署在同一个 PP rank 上。这种安排使 MTP 模块与主模型之间可以在物理上共享嵌入与输出头的参数和梯度。这种物理共享机制进一步提升了我们的内存效率。

### 3.3 FP8 训练

![Refer to caption](2412.19437v2/fp8-frameworkv3.png)

图 6：采用 FP8 数据格式的总体混合精度框架。为清晰起见，仅以 Linear 算子为例进行说明。

受近期低精度训练进展的启发（Peng et al., 2023b; Dettmers et al., 2022; Noune et al., 2022），我们提出了一种采用 FP8 数据格式的细粒度混合精度框架来训练 DeepSeek-V3。虽然低精度训练前景广阔，但它常常受到激活、权重和梯度中离群值（outlier）的制约（Sun et al., 2024; He et al.; Fishman et al., 2024）。尽管推理量化已取得显著进展（Xiao et al., 2023; Frantar et al., 2022），但在大规模语言模型预训练中成功应用低精度技术的研究相对较少（Fishman et al., 2024）。为了应对这一挑战并有效扩展 FP8 格式的动态范围，我们引入了一种细粒度量化策略：按 $1\times N_{c}$ 个元素进行 tile 级分组，或按 $N_{c}\times N_{c}$ 个元素进行块级（block-wise）分组。在我们的提高精度累加流程下，相关的反量化开销得到了大幅缓解，而这对实现精确的 FP8 通用矩阵乘法（GEMM）至关重要。此外，为了进一步降低 MoE 训练中的内存与通信开销，我们以 FP8 缓存和分发激活，并以 BF16 存储低精度优化器状态。我们在与 DeepSeek-V2-Lite 和 DeepSeek-V2 规模相近的两种模型规模上验证了所提出的 FP8 混合精度框架，各训练约 1 万亿 token（更多细节见附录 B.1）。值得注意的是，与 BF16 基线相比，我们 FP8 训练模型的相对损失误差始终保持在 0.25% 以下，完全处于训练随机性的可接受范围之内。

#### 3.3.1 混合精度框架

基于低精度训练中被广泛采用的技术（Kalamkar et al., 2019; Narang et al., 2017），我们提出了一种用于 FP8 训练的混合精度框架。在该框架中，大多数计算密集型操作以 FP8 进行，而少数关键操作则策略性地保持其原始数据格式，以平衡训练效率与数值稳定性。总体框架如图 6 所示。

首先，为了加速模型训练，大多数核心计算内核（即 GEMM 操作）以 FP8 精度实现。这些 GEMM 操作接受 FP8 张量作为输入，并输出 BF16 或 FP32 结果。如图 6 所示，与 Linear 算子相关的三个 GEMM，即 Fprop（前向传播）、Dgrad（激活反向传播）和 Wgrad（权重反向传播），均在 FP8 下执行。这一设计在理论上使计算速度相比原有的 BF16 方法翻倍。此外，FP8 Wgrad GEMM 允许激活以 FP8 格式存储以供反向传播使用，这显著降低了内存消耗。

尽管 FP8 格式具有效率优势，但某些算子由于对低精度计算敏感，仍然需要更高的精度。此外，一些低成本算子也可以采用更高精度，而对整体训练成本的影响可以忽略不计。因此，经过仔细研究，我们对以下组件保持原始精度（如 BF16 或 FP32）：嵌入模块、输出头、MoE 门控模块、归一化算子和注意力算子。这些有针对性的高精度保留确保了 DeepSeek-V3 训练动力学的稳定性。为了进一步保证数值稳定性，我们以更高精度存储主权重（master weight）、权重梯度和优化器状态。尽管这些高精度组件会带来一些内存开销，但通过我们分布式训练系统中跨多个 DP rank 的高效分片，其影响可以被最小化。

#### 3.3.2 通过量化与乘法提升精度

在我们的混合精度 FP8 框架基础上，我们引入了几种提升低精度训练准确性的策略，同时着眼于量化方法和乘法过程。

##### 细粒度量化。

在低精度训练框架中，由于 FP8 格式的动态范围受限（由其较少的指数位决定），上溢和下溢是常见挑战。作为标准做法，需要将输入张量的最大绝对值缩放至 FP8 的最大可表示值，从而使输入分布与 FP8 格式的可表示范围对齐（Narang et al., 2017）。这种方法使低精度训练对激活离群值高度敏感，而离群值会严重降低量化准确性。为解决这一问题，我们提出了一种在更细粒度上应用缩放的细粒度量化方法。如图 7 (a) 所示：(1) 对于激活，我们以 1x128 的 tile 为基础分组并缩放元素（即每个 token 每 128 个通道）；(2) 对于权重，我们以 128x128 的块为基础分组并缩放元素（即每 128 个输入通道乘每 128 个输出通道）。这种方法确保量化过程能够通过根据更小的元素组自适应调整缩放因子，更好地容纳离群值。在附录 B.2 中，我们进一步讨论了当以与权重量化相同的方式按块分组并缩放激活时出现的训练不稳定问题。

我们方法中的一项关键改动是在 GEMM 操作的内维（inner dimension）上引入每组缩放因子。标准 FP8 GEMM 并不直接支持这一功能。然而，结合我们精确的 FP32 累加策略，它可以被高效实现。

值得注意的是，我们的细粒度量化策略与微缩放格式（microscaling formats）（Rouhani et al., 2023b）的思想高度一致，而 NVIDIA 下一代 GPU（Blackwell 系列）的 Tensor Core 已宣布支持具有更小量化粒度的微缩放格式（NVIDIA, 2024a）。我们希望我们的设计能为未来的工作提供参考，以跟上最新 GPU 架构的步伐。

##### 提高累加精度。

低精度 GEMM 操作常常面临下溢问题，其准确性在很大程度上依赖于高精度累加，后者通常以 FP32 精度执行（Kalamkar et al., 2019; Narang et al., 2017）。然而，我们观察到 NVIDIA H800 GPU 上 FP8 GEMM 的累加精度被限制为仅保留约 14 位，明显低于 FP32 累加精度。当内维 K 较大时（Wortsman et al., 2023），这一问题会变得更加明显——而增大批大小和模型宽度的大规模模型训练正是这种典型场景。以 K = 4096 的两个随机矩阵的 GEMM 操作为例，在我们的初步测试中，Tensor Core 中受限的累加精度导致近 2% 的最大相对误差。尽管存在这些问题，受限的累加精度仍在少数 FP8 框架中作为默认选项（NVIDIA, 2024b），严重制约了训练准确性。

为了解决这一问题，我们采用提升至 CUDA Core 以获得更高精度的策略（Thakkar et al., 2023）。该过程如图 7 (b) 所示。具体而言，在 Tensor Core 上执行 MMA（矩阵乘累加）期间，中间结果以有限的位宽累加。一旦达到 $N_{C}$ 的间隔，这些部分结果就会被复制到 CUDA Core 上的 FP32 寄存器中，在那里执行全精度 FP32 累加。如前所述，我们的细粒度量化沿内维 K 应用每组缩放因子。这些缩放因子可以在 CUDA Core 上作为反量化过程高效地完成乘法，仅需极少的额外计算成本。

值得注意的是，这一改动会降低单个 warpgroup 的 WGMMA（Warpgroup 级矩阵乘累加）指令发射率。然而，在 H800 架构上，通常可以同时维持两个 WGMMA：当一个 warpgroup 执行提升操作时，另一个可以执行 MMA 操作。这种设计使两种操作得以重叠，保持了 Tensor Core 的高利用率。根据我们的实验，设置 $N_{C}=128$ 个元素（相当于 4 个 WGMMA）是能够显著提升精度而又不引入实质性开销的最小累加间隔。

##### 尾数优先于指数。

与先前工作采用的混合 FP8 格式（NVIDIA, 2024b; Peng et al., 2023b; Sun et al., 2019b）——即在 Fprop 中使用 E4M3（4 位指数、3 位尾数）、在 Dgrad 和 Wgrad 中使用 E5M2（5 位指数、2 位尾数）——不同，我们在所有张量上采用 E4M3 格式以获得更高精度。我们将这种做法的可行性归因于我们的细粒度量化策略，即 tile 级和块级缩放。通过在更小的元素组上操作，我们的方法有效地在这些成组元素之间共享指数位，缓解了动态范围受限的影响。

##### 在线量化。

张量级量化框架采用延迟量化（delayed quantization）（NVIDIA, 2024b; Peng et al., 2023b），即维护先前迭代中最大绝对值的历史记录来推断当前值。为了确保缩放因子准确并简化框架，我们对每个 1x128 激活 tile 或 128x128 权重块在线计算最大绝对值。基于此，我们推导出缩放因子，然后在线将激活或权重量化为 FP8 格式。

#### 3.3.3 低精度存储与通信

结合我们的 FP8 训练框架，我们通过将缓存的激活和优化器状态压缩为更低精度格式，进一步降低了内存消耗和通信开销。

##### 低精度优化器状态。

我们采用 BF16 而非 FP32 数据格式来跟踪 AdamW（Loshchilov and Hutter, 2017）优化器中的一阶矩和二阶矩，而没有观察到明显的性能下降。然而，主权重（由优化器存储）和梯度（用于批次大小累积）仍以 FP32 保留，以确保整个训练过程的数值稳定性。

##### 低精度激活。

如图 6 所示，Wgrad 操作以 FP8 执行。为了降低内存消耗，很自然的选择是以 FP8 格式为 Linear 算子的反向传播缓存激活。然而，为了实现低成本低高精度训练，我们对若干算子进行了特殊处理：

> （1）注意力算子之后 Linear 的输入。这些激活同时用于注意力算子的反向传播，这使其对精度敏感。我们专为这些激活采用定制的 E5M6 数据格式。此外，这些激活在反向传播中会从 1x128 的量化 tile 转换为 128x1 的 tile。为避免引入额外的量化误差，所有缩放因子均取整为 2 的整数次幂。
>
> （2）MoE 中 SwiGLU 算子的输入。为了进一步降低内存开销，我们缓存 SwiGLU 算子的输入，并在反向传播中重算其输出。这些激活同样以我们的细粒度量化方法存储为 FP8，在内存效率与计算准确性之间取得平衡。

##### 低精度通信。

通信带宽是 MoE 模型训练的关键瓶颈。为缓解这一难题，我们将 MoE 上投影之前的激活量化为 FP8，然后执行分发组件，这与 MoE 上投影中的 FP8 Fprop 兼容。与注意力算子之后 Linear 的输入类似，该激活的缩放因子为 2 的整数次幂。类似策略也应用于 MoE 下投影之前的激活梯度。对于前向和反向的组合组件，我们将其保留为 BF16，以在训练流程的关键部分保持训练精度。

### 3.4 推理与部署

我们将 DeepSeek-V3 部署在 H800 集群上，其中每个节点内的 GPU 通过 NVLink 互连，集群中所有 GPU 通过 IB 全互连。为了同时确保在线服务的服务级别目标（Service-Level Objective，SLO）和高吞吐量，我们采用将预填充（prefilling）与解码（decoding）阶段分离的如下部署策略。

#### 3.4.1 预填充

预填充阶段的最小部署单元由 4 个节点、32 块 GPU 组成。注意力部分采用 4 路张量并行（TP4）加序列并行（SP），并结合 8 路数据并行（DP8）。较小的 TP 规模 4 限制了 TP 通信的开销。对于 MoE 部分，我们使用 32 路专家并行（EP32），确保每个专家处理足够大的批次，从而提升计算效率。对于 MoE 的 all-to-all 通信，我们采用与训练相同的方法：先通过 IB 跨节点传输 token，再通过 NVLink 在节点内 GPU 之间转发。特别地，我们对浅层的稠密 MLP 使用 1 路张量并行，以节省 TP 通信。

为了在 MoE 部分的不同专家之间实现负载均衡，我们需要确保每块 GPU 处理大致相同数量的 token。为此，我们引入了一种冗余专家的部署策略，即复制高负载专家并进行冗余部署。高负载专家基于在线部署期间收集的统计信息检测，并周期性调整（例如每 10 分钟一次）。在确定冗余专家集合后，我们会基于观测到的负载，精心重排节点内各 GPU 上的专家，力求在不增加跨节点 all-to-all 通信开销的前提下尽可能均衡各 GPU 的负载。在 DeepSeek-V3 的部署中，我们为预填充阶段设置了 32 个冗余专家。对于每块 GPU，除其原本承载的 8 个专家外，还将额外承载 1 个冗余专家。

此外，在预填充阶段，为了提升吞吐并隐藏 all-to-all 与 TP 通信的开销，我们同时处理两个计算工作量相近的微批次，将一个微批次的注意力和 MoE 与另一个微批次的分发和组合相重叠。

最后，我们正在探索一种专家动态冗余策略：每块 GPU 承载更多专家（例如 16 个），但每次推理步只激活其中 9 个。在每层的 all-to-all 操作开始之前，我们即时计算全局最优的路由方案。鉴于预填充阶段涉及大量计算，计算该路由方案的开销几乎可以忽略。

#### 3.4.2 解码

在解码期间，我们将共享专家视为一个路由专家。从这个视角看，每个 token 在路由时将选择 9 个专家，其中共享专家被视为一个始终被选中的高负载专家。解码阶段的最小部署单元由 40 个节点、320 块 GPU 组成。注意力部分采用 TP4 加 SP，并结合 DP80，而 MoE 部分使用 EP320。对于 MoE 部分，每块 GPU 仅承载一个专家，另有 64 块 GPU 负责承载冗余专家和共享专家。分发与组合部分的 all-to-all 通信通过 IB 上的直接点对点传输执行，以实现低延迟。此外，我们利用 IBGDA（NVIDIA, 2022）技术进一步降低延迟并提升通信效率。

与预填充类似，我们基于在线服务的专家负载统计，按一定间隔周期性地确定冗余专家集合。不过，由于每块 GPU 只承载一个专家，我们无需重排专家。我们也在探索用于解码的动态冗余策略。然而，这需要对计算全局最优路由方案的算法以及与分发内核的融合进行更谨慎的优化，以降低开销。

此外，为了提升吞吐并隐藏 all-to-all 通信的开销，我们也在探索在解码阶段同时处理两个计算工作量相近的微批次。与预填充不同，解码阶段注意力占用的时间比例更大。因此，我们将一个微批次的注意力与另一个微批次的分发+MoE+组合相重叠。在解码阶段，每个专家的批次规模相对较小（通常在 256 个 token 以内），瓶颈在于访存而非计算。由于 MoE 部分只需加载一个专家的参数，访存开销极小，因此使用更少的 SM 并不会显著影响整体性能。于是，为避免影响注意力部分的计算速度，我们可以仅分配一小部分 SM 给分发+MoE+组合。

### 3.5 对硬件设计的建议

基于我们在 all-to-all 通信和 FP8 训练方案上的实践，我们向 AI 硬件厂商提出以下芯片设计建议。

#### 3.5.1 通信硬件

在 DeepSeek-V3 中，我们实现了计算与通信之间的重叠，以在计算期间隐藏通信延迟。与串行的计算和通信相比，这显著降低了对通信带宽的依赖。然而，当前的通信实现依赖昂贵的 SM（例如，我们从 H800 GPU 可用的 132 个 SM 中分配 20 个用于此目的），这会限制计算吞吐。此外，使用 SM 进行通信会导致显著的低效，因为 Tensor Core 完全未被利用。

目前，SM 主要为 all-to-all 通信执行以下任务：

- 在 IB（InfiniBand）与 NVLink 域之间转发数据，同时将单一 GPU 发往同一节点内多个 GPU 的 IB 流量聚合。
- 在 RDMA 缓冲区（已注册的 GPU 内存区域）与输入/输出缓冲区之间搬运数据。
- 执行 all-to-all 组合的归约（reduce）操作。
- 在向跨 IB 和 NVLink 域的多个专家分块传输数据期间，管理细粒度的内存布局。

我们期待未来的厂商开发能够将这些通信任务从宝贵的计算单元 SM 上卸载下来的硬件，使其作为 GPU 协处理器或类似 NVIDIA SHARP 的网络协处理器（Graham et al., 2016）。此外，为了降低应用编程复杂度，我们希望这种硬件能从计算单元的视角统一 IB（横向扩展）与 NVLink（纵向扩展）网络。借助这种统一接口，计算单元只需基于简单原语提交通信请求，即可轻松完成整个 IB-NVLink 统一域上的读取、写入、多播和归约等操作。

#### 3.5.2 计算硬件

##### 在 Tensor Core 中实现更高的 FP8 GEMM 累加精度。

在当前 NVIDIA Hopper 架构的 Tensor Core 实现中，FP8 GEMM 受限于累加精度：在按最大指数对 32 个尾数乘积进行右移对齐后，Tensor Core 仅使用每个尾数乘积最高的 14 位进行加法，并截断超出该范围的位。加法结果向寄存器的累加同样采用 14 位精度。我们的实现通过在 CUDA core 中以 FP32 精度将 128 个 FP8$\times$FP8 乘法的加法结果累加到寄存器，部分缓解了这一限制。尽管这有助于成功完成 FP8 训练，但它只是针对 Hopper 架构在 FP8 GEMM 累加精度上硬件缺陷的一种折中。未来的芯片需要采用更高的精度。

##### 支持按 tile 和按块的量化。

当前 GPU 仅支持逐张量（per-tensor）量化，缺乏对我们这种 tile 级和块级细粒度量化的原生支持。在当前实现中，当达到 $N_{C}$ 间隔时，部分结果会从 Tensor Core 复制到 CUDA core，乘以缩放因子，并累加到 CUDA core 上的 FP32 寄存器。尽管结合我们精确的 FP32 累加策略，反量化开销已得到显著缓解，但 Tensor Core 与 CUDA core 之间频繁的数据搬运仍然限制了计算效率。因此，我们建议未来的芯片通过让 Tensor Core 能够接收缩放因子并实现带组缩放的 MMA，来支持细粒度量化。这样，整个部分和累加与反量化都可以直接在 Tensor Core 内部完成直至产生最终结果，避免频繁的数据搬运。

##### 支持在线量化。

尽管在线量化的有效性已在我们的研究中得到证明，当前实现仍难以有效支持它。在现有流程中，我们需要从 HBM（高带宽内存）读取 128 个 BF16 激活值（上一次计算的输出）进行量化，量化后的 FP8 值再写回 HBM，随后又要再次读取才能进行 MMA。为解决这一低效问题，我们建议未来的芯片将 FP8 类型转换与 TMA（Tensor Memory Accelerator）访存整合为单一融合操作，使量化能够在激活从全局内存传输到共享内存的过程中完成，避免频繁的内存读写。我们还建议支持 warp 级的类型转换指令以加速，这进一步促进层归一化与 FP8 转换的更好融合。或者，也可以采用近存计算方案，将计算逻辑置于 HBM 附近。在这种情况下，BF16 元素在被从 HBM 读入 GPU 时即可直接转换为 FP8，将片外内存访问减少约 50%。

##### 支持转置 GEMM 操作。

当前架构使得将矩阵转置与 GEMM 操作融合十分繁琐。在我们的工作流程中，前向传播期间的激活被量化为 1x128 的 FP8 tile 并存储。在反向传播期间，需要将矩阵读出、反量化、转置、重新量化为 128x1 的 tile，并存入 HBM。为了减少内存操作，我们建议未来的芯片对于训练和推理中所需的精度，支持在 MMA 操作之前从共享内存直接转置读取矩阵。结合 FP8 格式转换与 TMA 访存的融合，这一增强将显著简化量化工作流程。

## 4 预训练

### 4.1 数据构建

与 DeepSeek-V2 相比，我们通过提高数学和编程样本的比例，并扩展中英文之外的多语言覆盖，优化了预训练语料。同时，我们改进了数据处理流程，在保持语料多样性的同时最大限度降低冗余。受 Ding et al. (2024) 启发，我们实施了文档打包（document packing）方法以保证数据完整性，但在训练期间不引入跨样本注意力掩码。最终，DeepSeek-V3 的训练语料按我们的分词器计量由 14.8T 高质量且多样化的 token 组成。

在 DeepSeekCoder-V2（DeepSeek-AI, 2024a）的训练过程中，我们观察到中间填充（Fill-in-Middle，FIM）策略不会损害下一 token 预测能力，同时使模型能够基于上下文线索准确预测中间文本。与 DeepSeekCoder-V2 保持一致，我们也在 DeepSeek-V3 的预训练中引入了 FIM 策略。具体而言，我们采用前缀-后缀-中间（Prefix-Suffix-Middle，PSM）框架，将数据组织为如下形式：

$$\texttt{<|fim\_begin|>}f_{\text{pre}}\texttt{<|fim\_hole|>}f_{\text{suf}}\texttt{<|fim\_end|>}f_{\text{middle}}\texttt{<|eos\_token|>}. $$

该结构在文档级别应用，作为预打包过程的一部分。FIM 策略的应用比例为 0.1，与 PSM 框架保持一致。

DeepSeek-V3 的分词器采用字节级 BPE（Shibata et al., 1999），词表扩展至 128K token。我们修改了分词器的预分词器（pretokenizer）和训练数据，以优化多语言压缩效率。此外，与 DeepSeek-V2 相比，新的预分词器引入了结合标点与换行符的 token。然而，这一技巧可能在模型处理不带末尾换行的多行提示时引入 token 边界偏差（token boundary bias）（Lundberg, 2023），尤其体现在少样本评测提示中。为了解决这一问题，我们在训练期间随机拆分一定比例的此类组合 token，使模型接触到更多样的特殊情况，从而缓解该偏差。

### 4.2 超参数

##### 模型超参数。

我们将 Transformer 层数设为 61，隐藏维度设为 7168。所有可学习参数以标准差 0.006 随机初始化。在 MLA 中，注意力头数 $n_{h}$ 设为 128，每头维度 $d_{h}$ 设为 128。KV 压缩维度 $d_{c}$ 设为 512，查询压缩维度 $d_{c}^{\prime}$ 设为 1536。对于解耦的查询和键，我们将每头维度 $d_{h}^{R}$ 设为 64。除前三层外，我们将所有 FFN 替换为 MoE 层。每个 MoE 层由 1 个共享专家和 256 个路由专家组成，其中每个专家的中间隐藏维度为 2048。在路由专家中，每个 token 将激活 8 个专家，并确保每个 token 至多被发送到 4 个节点。多 token 预测深度 $D$ 设为 1，即除精确的下一个 token 外，每个 token 还将预测一个额外 token。与 DeepSeek-V2 一样，DeepSeek-V3 也在压缩潜在向量之后添加额外的 RMSNorm 层，并在宽度瓶颈处乘以额外的缩放因子。在此配置下，DeepSeek-V3 共包含 671B 总参数，其中每个 token 激活 37B。

##### 训练超参数。

我们采用 AdamW 优化器（Loshchilov and Hutter, 2017），超参数设为 $\beta_{1}=0.9$、$\beta_{2}=0.95$、$\mathrm{weight\_decay}=0.1$。我们将预训练期间的最大序列长度设为 4K，并在 14.8T token 上预训练 DeepSeek-V3。在学习率调度方面，我们首先在前 2K 步内将其从 0 线性增至 $2.2\times 10^{-4}$。然后，我们保持 $2.2\times 10^{-4}$ 的恒定学习率，直到模型消耗 10T 训练 token。随后，我们按照余弦衰减曲线，在 4.3T token 内将学习率逐渐衰减至 $2.2\times 10^{-5}$。在最后 500B token 的训练中，我们在前 333B token 保持 $2.2\times 10^{-5}$ 的恒定学习率，并在其余 167B token 切换到 $7.3\times 10^{-6}$ 的另一恒定学习率。梯度裁剪范数设为 1.0。我们采用批次大小调度策略：在前 469B token 的训练中，批次大小从 3072 逐步增至 15360，随后在剩余训练中保持 15360。我们利用流水线并行将模型的不同层部署在不同 GPU 上，并且对于每一层，路由专家均匀部署在属于 8 个节点的 64 块 GPU 上。对于节点受限路由，每个 token 至多被发送到 4 个节点（即 $M=4$）。对于无辅助损失的负载均衡，我们将偏置更新速度 $\gamma$ 在前 14.3T token 设为 0.001，在其余 500B token 设为 0.0。对于平衡损失，我们将 $\alpha$ 设为 0.0001，仅为了避免任何单个序列内的极端不均衡。MTP 损失权重 $\lambda$ 在前 10T token 设为 0.3，在其余 4.8T token 设为 0.1。

### 4.3 长上下文扩展

我们采用与 DeepSeek-V2（DeepSeek-AI, 2024c）类似的方法为 DeepSeek-V3 赋予长上下文能力。在预训练阶段之后，我们应用 YaRN（Peng et al., 2023a）进行上下文扩展，并进行两个各含 1000 步的额外训练阶段，将上下文窗口从 4K 逐步扩展到 32K，再到 128K。YaRN 配置与 DeepSeek-V2 中使用的保持一致，仅应用于解耦共享键 $\mathbf{k}^{R}_{t}$。两个阶段的超参数完全相同：缩放因子 $s=40$、$\alpha=1$、$\beta=32$，缩放因子 $\sqrt{t}=0.1\ln{s}+1$。在第一阶段，序列长度设为 32K，批次大小为 1920。在第二阶段，序列长度增至 128K，批次大小降至 480。两个阶段的学习率均设为 $7.3\times 10^{-6}$，与预训练阶段的最终学习率保持一致。

通过这种两阶段扩展训练，DeepSeek-V3 能够处理最长 128K 的输入并保持强劲性能。图 8 表明，经过监督微调后，DeepSeek-V3 在「大海捞针」（NIAH）测试上取得了显著成绩，在最长 128K 的上下文窗口长度上展现出一致的稳健性。

#### 4.5.3 批次级负载均衡 VS 序列级负载均衡

无辅助损失均衡与序列级辅助损失之间的关键区别在于均衡范围：批次级（batch-wise）与序列级（sequence-wise）。与序列级辅助损失相比，批次级均衡施加了更灵活的约束，因为它不强制要求每个序列内部保持均衡。这种灵活性使专家能够更好地在不同领域实现特化。为验证这一点，我们记录并分析了一个 16B 基于辅助损失的基线模型和一个 16B 无辅助损失模型在 Pile 测试集不同领域上的专家负载。如图 9 所示，我们观察到无辅助损失模型如预期般表现出更强的专家特化模式。

为了进一步研究这种灵活性与模型性能优势之间的关联，我们额外设计并验证了一种批次级辅助损失，它在每个训练批次而非每个序列上鼓励负载均衡。实验结果表明，当达到相近水平的批次级负载均衡时，批次级辅助损失也能取得与无辅助损失方法相近的模型性能。具体来说，在我们使用 1B MoE 模型的实验中，验证损失分别为：2.258（使用序列级辅助损失）、2.253（使用无辅助损失方法）和 2.253（使用批次级辅助损失）。我们在 3B MoE 模型上也观察到类似结果：使用序列级辅助损失的模型取得 2.085 的验证损失，而使用无辅助损失方法或批次级辅助损失的模型均取得 2.080 的相同验证损失。

此外，尽管批次级负载均衡方法表现出一致的性能优势，它们在效率上也面临两个潜在挑战：（1）某些序列或小批次内的负载不均衡；（2）推理期间由领域偏移引起的负载不均衡。第一个挑战由我们使用大规模专家并行和数据并行的训练框架天然解决，它保证了每个微批次的规模足够大。对于第二个挑战，我们也设计并实现了一个采用冗余专家部署的高效推理框架（如第 3.4 节所述）来加以克服。

## 5 后训练

### 5.1 监督微调

我们精心构建的指令微调数据集包含 1.5M 个实例，跨越多个领域，每个领域都采用针对其特定需求量身定制的数据构建方法。

##### 推理数据。

对于推理相关的数据集，包括专注于数学、编程竞赛题目和逻辑谜题的数据集，我们利用内部的 DeepSeek-R1 模型生成数据。具体而言，虽然 R1 生成的数据表现出很强的准确性，但它存在诸如过度思考、格式不佳和篇幅过长等问题。我们的目标是在 R1 生成推理数据的高准确率与常规格式推理数据的清晰简洁之间取得平衡。

为确立我们的方法论，我们首先针对特定领域（如代码、数学或通用推理）开发一个专家模型，使用监督微调（SFT）与强化学习（RL）相结合的训练流程。该专家模型作为最终模型的数据生成器。训练过程为每个实例生成两种不同类型的 SFT 样本：第一种将问题与其原始回答以 <问题, 原始回答> 的格式配对；第二种则在问题和 R1 回答之外加入系统提示，以 <系统提示, 问题, R1 回答> 的格式呈现。

系统提示经过精心设计，包含引导模型生成富含反思与验证机制的回答的指令。在 RL 阶段，模型利用高温采样生成融合了 R1 生成数据与原始数据二者模式的回答，即便在没有显式系统提示的情况下也是如此。经过数百个 RL 步之后，中间 RL 模型学会了融入 R1 模式，从而策略性地提升了整体性能。

在完成 RL 训练阶段后，我们实施拒绝采样（rejection sampling）为最终模型精选高质量 SFT 数据，其中专家模型被用作数据生成源。这种方法确保最终训练数据在保留 DeepSeek-R1 优势的同时，生成简洁而有效的回答。

##### 非推理数据。

对于非推理数据，如创意写作、角色扮演和简单问答，我们利用 DeepSeek-V2.5 生成回答，并聘请人工标注员验证数据的准确性与正确性。

##### SFT 设置。

我们使用 SFT 数据集对 DeepSeek-V3-Base 进行两个 epoch 的微调，学习率调度采用余弦衰减，从 $5\times 10^{-6}$ 开始并逐渐降至 $1\times 10^{-6}$。训练期间，每个单条序列由多个样本打包而来。不过，我们采用样本掩码策略，以确保这些样本保持隔离、彼此不可见。

### 5.2 强化学习

#### 5.2.1 奖励模型

我们在 RL 过程中采用基于规则的奖励模型（Reward Model，RM）和基于模型的 RM。

##### 基于规则的 RM。

对于可以用特定规则验证的问题，我们采用基于规则的奖励系统来确定反馈。例如，某些数学问题具有确定性的结果，我们要求模型以指定格式（例如放在框中）给出最终答案，从而可以应用规则验证正确性。类似地，对于 LeetCode 题目，我们可以利用编译器基于测试用例生成反馈。通过在尽可能多的场景利用基于规则的验证，我们确保了更高的可靠性，因为这种方法不易被操纵或利用。

##### 基于模型的 RM。

对于具有自由形式标准答案的问题，我们依靠奖励模型判断回答是否与预期的标准答案一致。反之，对于没有确定标准答案的问题（如涉及创意写作的问题），奖励模型的任务是基于问题和相应回答作为输入提供反馈。该奖励模型从 DeepSeek-V3 的 SFT 检查点训练而来。为了增强其可靠性，我们构建的偏好数据不仅提供最终奖励，还包含通向该奖励的思维链。这种方法有助于降低在特定任务中出现奖励作弊（reward hacking）的风险。

#### 5.2.2 组相对策略优化

与 DeepSeek-V2（DeepSeek-AI, 2024c）类似，我们采用组相对策略优化（Group Relative Policy Optimization，GRPO）（Shao et al., 2024），它省去了通常与策略模型规模相同的 critic 模型，转而从组得分中估计基线。具体而言，对于每个问题 $q$，GRPO 从旧策略模型 $\pi_{\theta_{old}}$ 中采样一组输出 $\{o_{1},o_{2},\cdots,o_{G}\}$，然后通过最大化以下目标来优化策略模型 $\pi_{\theta}$：

$$
\begin{split}
\mathcal{J}_{GRPO}(\theta)&=\mathbb{E}{[q\sim P(Q),\{o_{i}\}_{i=1}^{G}\sim\pi_{\theta_{old}}(O|q)]}\\
&\frac{1}{G}\sum_{i=1}^{G}\left(\min\left(\frac{\pi_{\theta}(o_{i}|q)}{\pi_{\theta_{old}}(o_{i}|q)}A_{i},\text{clip}\left(\frac{\pi_{\theta}(o_{i}|q)}{\pi_{\theta_{old}}(o_{i}|q)},1-\varepsilon,1+\varepsilon\right)A_{i}\right)-\beta\mathbb{D}_{KL}\left(\pi_{\theta}\|\pi_{ref}\right)\right),
\end{split} \tag{26}
$$

$$\mathbb{D}_{KL}\left(\pi_{\theta}\|\pi_{ref}\right)=\frac{\pi_{ref}(o_{i}|q)}{\pi_{\theta}(o_{i}|q)}-\log\frac{\pi_{ref}(o_{i}|q)}{\pi_{\theta}(o_{i}|q)}-1, \tag{27}$$

其中 $\varepsilon$ 和 $\beta$ 是超参数；$\pi_{ref}$ 是参考模型；$A_{i}$ 是优势（advantage），由对应每组内各输出的奖励 $\{r_{1},r_{2},\ldots,r_{G}\}$ 得出：

$$A_{i}=\frac{r_{i}-{\operatorname{mean}(\{r_{1},r_{2},\cdots,r_{G}\})}}{{\operatorname{std}(\{r_{1},r_{2},\cdots,r_{G}\})}}. \tag{28}$$

我们在 RL 过程中纳入了来自多种领域的提示，如编程、数学、写作、角色扮演和问答。这种方法不仅使模型更贴近人类偏好，还提升了基准测试上的表现，尤其是在可用 SFT 数据有限的场景下。

### 5.4 讨论

#### 5.4.1 从 DeepSeek-R1 蒸馏

我们基于 DeepSeek-V2.5 对来自 DeepSeek-R1 的蒸馏贡献进行消融。基线模型在短 CoT 数据上训练，而其对手使用上述专家检查点生成的数据。

表 9 展示了蒸馏数据的有效性，在 LiveCodeBench 和 MATH-500 两个基准上均有显著提升。我们的实验揭示了一个有趣的权衡：蒸馏带来了更好的性能，但也大幅增加了平均回答长度。为了在模型准确率与计算效率之间保持平衡，我们为 DeepSeek-V3 的蒸馏精心选择了最优设置。

我们的研究表明，从推理模型进行知识蒸馏是后训练优化的一个有前景的方向。虽然我们目前的工作聚焦于从数学和编程领域蒸馏数据，但该方法在各类任务领域都有更广泛应用的潜力。在这些特定领域所展示的有效性表明，长 CoT 蒸馏对于提升模型在其它需要复杂推理的认知任务上的表现也可能很有价值。对这一方法在不同领域的进一步探索仍是未来研究的重要方向。

#### 5.4.2 自我奖励

奖励在 RL 中扮演着关键角色，引导着优化过程。在可以通过外部工具轻松验证的领域（如某些编程或数学场景），RL 展现出卓越的效果。然而，在更一般的场景中，通过硬编码构建反馈机制是不切实际的。在 DeepSeek-V3 的开发过程中，针对这些更广泛的场景，我们采用了宪法式 AI（constitutional AI）方法（Bai et al., 2022），利用 DeepSeek-V3 自身的投票评估结果作为反馈源。这种方法产生了显著的对齐效果，大幅提升了 DeepSeek-V3 在主观评测中的表现。通过纳入额外的宪法式输入，DeepSeek-V3 可以朝宪法方向进行优化。我们相信，这种将补充信息与 LLM 相结合作为反馈源的范式至关重要。LLM 作为一个多功能处理器，能够将来自多样场景的非结构化信息转化为奖励，最终促进 LLM 的自我改进。除自我奖励外，我们还致力于发掘其它通用且可扩展的奖励方法，以在一般场景中持续提升模型能力。

#### 5.4.3 多 token 预测评测

DeepSeek-V3 借助 MTP 技术不仅预测下一个单个 token，而是预测接下来的 2 个 token。结合投机解码框架（Leviathan et al., 2023; Xia et al., 2023），它可以显著加快模型的解码速度。一个自然的问题是额外预测 token 的接受率如何。根据我们的评估，第二个 token 预测的接受率在各类生成主题下介于 85% 到 90% 之间，表现出一致的可靠性。如此高的接受率使 DeepSeek-V3 的解码速度得到显著提升，实现 1.8 倍的 TPS（每秒 token 数，Tokens Per Second）。

## 6 结论、局限性与未来方向

本文介绍了 DeepSeek-V3，一个总参数量 671B、激活参数量 37B 的大型 MoE 语言模型，在 14.8T token 上训练而成。除 MLA 和 DeepSeekMoE 架构外，它还开创性地采用无辅助损失的负载均衡策略，并引入多 token 预测训练目标以获得更强性能。得益于 FP8 训练支持和细致的工程优化，DeepSeek-V3 的训练成本十分经济。后训练也成功从 DeepSeek-R1 系列模型蒸馏了推理能力。全面评测表明，DeepSeek-V3 已成为当前可用的最强开源模型，并取得与 GPT-4o 和 Claude-3.5-Sonnet 等领先闭源模型相当的性能。尽管性能强大，它仍保持了经济的训练成本：包括预训练、上下文长度扩展和后训练在内，完整训练仅需 2.788M H800 GPU 小时。

在肯定其强大性能与成本效益的同时，我们也认识到 DeepSeek-V3 存在一些局限，尤其是在部署方面。首先，为确保高效推理，DeepSeek-V3 的推荐部署单元相对较大，这可能对小型团队构成负担。其次，尽管我们对 DeepSeek-V3 的部署策略已实现超过 DeepSeek-V2 两倍的端到端生成速度，但仍有进一步提升的空间。幸运的是，随着更先进硬件的发展，这些局限有望被自然解决。

DeepSeek 始终坚持开源模型的长期主义（longtermism）路线，旨在稳步接近 AGI（通用人工智能）的终极目标。未来，我们计划在以下方向进行战略性研究投入。

- 我们将持续研究和改进我们的模型架构，力求进一步提升训练与推理效率，努力实现对无限上下文长度的高效支持。此外，我们将尝试突破 Transformer 的架构局限，从而拓展其建模能力边界。
- 我们将持续迭代训练数据的数量与质量，并探索纳入额外的训练信号来源，力求在更全面的维度上推动数据扩展（data scaling）。
- 我们将持续探索和迭代模型的深度思考能力，通过扩展其推理长度与深度来增强其智能和问题求解能力。
- 我们将探索更全面、更多维度的模型评测方法，以避免研究过程中出现向固定基准集合优化的倾向——这种倾向可能对模型能力造成误导性印象，并影响我们的基础评估。

### B.1 FP8 与 BF16 训练对比

我们在两个不同规模的基线模型上，通过与 BF16 训练的对比来验证我们的 FP8 混合精度框架。在小规模上，我们在 1.33T token 上训练一个包含约 16B 总参数的基线 MoE 模型。在大规模上，我们在约 0.9T token 上训练一个包含约 230B 总参数的基线 MoE 模型。我们在图 10 中展示了训练曲线，并证明借助我们的高精度累加与细粒度量化策略，相对误差始终保持在 0.25% 以下。

### B.2 关于块级量化的讨论

尽管我们的 tile 级细粒度量化有效缓解了由特征离群值引入的误差，但它要求激活量化在前后向采用不同的分组方式，即前向传播中为 1x128，反向传播中为 128x1。激活梯度也需要类似的过程。一种直接的策略是像量化模型权重那样，按每 128x128 个元素进行块级量化。这样，反向传播就只需要转置。因此，我们进行了一项实验，其中与 Dgrad 相关的所有张量均按块级量化。结果揭示：以链式方式计算激活梯度并向浅层反向传播的 Dgrad 操作对精度高度敏感。具体而言，在一个包含约 16B 总参数、训练约 300B token 的 MoE 模型上，激活梯度的块级量化会导致模型发散。我们推测这种敏感性源于激活梯度在 token 之间高度不均衡，从而产生与 token 相关的离群值（Xi et al., 2023）。这些离群值无法通过块级量化方法被有效管理。
