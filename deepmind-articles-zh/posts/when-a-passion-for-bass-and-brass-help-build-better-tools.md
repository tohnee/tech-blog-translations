# 当对低音与铜管的热爱助力打造更好的工具

> 原文：[When a passion for bass and brass help build better tools](https://deepmind.google/blog/when-a-passion-for-bass-and-brass-help-build-better-tools/) · Google DeepMind

在我们的第一期"五分钟访谈"中，我们与 DevTools 团队的软件工程师 Kevin Millikin 聊了聊。本周他在盐湖城出席 [PyCon US](https://us.pycon.org/2022/)——使用和开发开源 Python 编程语言的人们的年度最大聚会。

## 在 DeepMind……

我为我们的开发者构建定制的软件工具。例如，我们目前正在开发一个基于网页的编辑器，以支持远程办公、需要用 Python 编程的人——Python 是我们工程师常用的语言之一。为我们自己的工作方式和所依赖的 Google 基础设施打造工具，让我们在解决团队真正关心的问题时拥有更大的灵活性。

## 一名 DeepMind 软件工程师的一天从……开始

伦敦园区——它太棒了。我们采用每周 3:2 的混合办公模式——周一到周三在办公室，周四和周五在任何地方。我非常享受与同事们面对面的交流。

我一直在周四和周五居家办公。我是一名音乐人，我的家庭办公室同时也是我的音乐室。我会演奏低音吉他、粗管短号和中音萨克斯。疫情期间远程办公时，演奏音乐给了我巨大的帮助。那是一种不同类型的创造性能量——它给我留出空间去反思手头要解决的问题，帮助我从不同的方向去攻克它。

## 在 PyCon US……

我要做一个题为"[Beyond Subtyping](https://us.pycon.org/2022/events/typing-summit/)"的演讲，这是 Python 的一项特性。我的议题着重展示实现子类型化的各种工具彼此意见不一致的多种情形。作为 Python 的设计者，你也许以为这些都是已有定论的问题，但其实不然，因为在语言如何运作这些基础问题上我们尚未达成一致。

在类型工作组里有来自微软、Facebook 和 Google 等公司的几十位参与者——这是一个非常合作、非常同僚化的团体。我们都在努力让 Python 朝着支持各自用户的方向演进。我们发现彼此面对的问题相似，目标也相似。我们要开发的是所有人都能使用的工具，所以必须以高度协作的方式来设计。

## 我特别期待的是……

与那些我已经远程合作多年、同属 Python 语言社区的人面对面相见。我在这个领域算是个新人，我有兴趣扩展我们的关系网络，让它对外部贡献者更加开放包容。实际上，这个社区往往像一个封闭的小圈子，我认为很多工作如果更加开放会受益良多。

## 语言的未来……

虽然 Python 不断加入新特性来帮助解决某些人遇到的具体问题，但它们并不总能与其他新特性以连贯一致的方式相互配合。我所倡导的事情之一，就是退后一步，先确定我们演进编程语言这一部分的原则。很多原则都只存在于开发者的脑子里，但我的问题是——我们能不能把它们写下来，作为语言演进应当遵循的宣言？如果我们有一份未来 2-5 年的发展路线图，是否能更有思考性地对语言做出更改？这将确保我们是在为未来而构建，也是在打造加速 AI 研究所需的各种工具。
