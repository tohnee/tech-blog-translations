# SGLang Day-0 支持搭载稀疏注意力的 DeepSeek-V3.2

> 原文：[SGLang Day 0 Support for DeepSeek-V3.2 with Sparse Attention](https://lmsys.org/blog/2025-09-29-deepseek-V32/) · LMSYS Blog · The SGLang Team

我们很高兴地宣布：**SGLang 已于发布首日（Day 0）支持 DeepSeek-V3.2**！根据 DeepSeek 的[技术报告](https://github.com/deepseek-ai/DeepSeek-V3.2-Exp/blob/main/DeepSeek_V3_2.pdf)，DeepSeek-V3.2 通过持续训练，为 DeepSeek-V3.1-Terminus 加装了 [DeepSeek Sparse Attention（DSA，DeepSeek 稀疏注意力）](https://arxiv.org/pdf/2502.11089)。借助 DSA 这一由 lightning indexer（闪电索引器）驱动的细粒度稀疏注意力机制，DeepSeek-V3.2 在训练和推理两端都获得了显著的效率提升，在长上下文场景下尤为突出。关于后续特性的更多细节，请查看我们的[路线图](https://github.com/sgl-project/sglang/issues/11060)。


## 安装与快速上手

要开始使用，只需拉取容器镜像，并按如下方式启动 SGLang：

```bash
docker pull lmsysorg/sglang:v0.5.3-cu129

python -m sglang.launch_server --model deepseek-ai/DeepSeek-V3.2-Exp --tp 8 --dp 8 --enable-dp-attention
```

AMD（MI350X/MI355X）：

```bash
docker pull lmsysorg/sglang:dsv32-rocm

SGLANG_NSA_FUSE_TOPK=false SGLANG_NSA_KV_CACHE_STORE_FP8=false SGLANG_NSA_USE_REAL_INDEXER=true SGLANG_NSA_USE_TILELANG_PREFILL=True python -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V3.2-Exp --disable-cuda-graph --tp 8 --mem-fraction-static 0.85 --page-size 64 --nsa-prefill "tilelang" --nsa-decode "aiter"

SGLANG_NSA_FUSE_TOPK=false SGLANG_NSA_KV_CACHE_STORE_FP8=false SGLANG_NSA_USE_REAL_INDEXER=true SGLANG_NSA_USE_TILELANG_PREFILL=True python -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V3.2-Exp --disable-cuda-graph --tp 8 --mem-fraction-static 0.85 --page-size 64 --nsa-prefill "tilelang" --nsa-decode "tilelang"
```


NPU：

```bash
# NPU A2
docker pull lmsysorg/sglang:dsv32-a2
# NPU A3
docker pull lmsysorg/sglang:dsv32-a3

python3 -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V3.2-Exp --trust-remote-code --attention-backend ascend --mem-fraction-static 0.85 --chunked-prefill-size 32768 --disable-radix-cache --tp-size 16 --quantization w8a8_int8
```


## 详细介绍

### DeepSeek 稀疏注意力（DSA）：解锁长上下文效率

DeepSeek-V3.2 的核心是 **DeepSeek Sparse Attention（DSA）**——一种重新定义长上下文效率的细粒度稀疏注意力机制。

![figure1](/images/blog/deepseek_v32/DSA.png)

DSA 没有对所有 token 执行平方复杂度的全量注意力，而是引入了：

* **Lightning Indexer**（超轻量 FP8 打分器），用于为每个 query 找出最相关的 token。
* **Top-k Token 选择**，只把计算集中在影响最大的键值条目上。

这一设计将核心注意力的复杂度从 **O(L^2) 降至 O(Lk)**，在最高 **128K** 上下文长度下同时大幅提升训练与推理效率，而模型质量几乎没有损失。

为支持这一突破性设计，SGLang 实现并集成了：

* **Lightning Indexer 支持**——在内存池中为 `key&key_scale` 配备专用缓存，实现超高速的 token 打分。
* **原生稀疏注意力（NSA）后端**——专为稀疏负载打造的新后端，包含：
    * **FlashMLA**（DeepSeek 优化的 multi-query attention 内核）
    * **FlashAttention-3 Sparse**（为兼容性与最大化内核复用而适配）
* 额外工作：在同一个注意力后端内支持不同的 page size：
    * Indexer 的 `key&key_scale` 缓存要求 page size = 64（源自 DeepSeek 提供的内核）
    * token 级稀疏前向算子要求 page size = 1

这些创新共同让 DeepSeek-V3.2-Exp 得以提供 **GPU 优化的稀疏注意力**与**动态缓存管理**，在无缝扩展到 128K 上下文的同时削减内存开销。

其结果是一个既保持最先进推理质量、又能**大幅降低推理成本**的运行时——让长上下文 LLM 部署不仅成为可能，而且能够大规模落地。

## 后续工作

后续工作将在[这里](https://github.com/sgl-project/sglang/issues/11060)跟踪。具体而言，我们计划：

* **多 token 预测（MTP）**支持即将推出：MTP 将加速解码，在批大小不大时尤其有效。
* **FP8 KV 缓存**：与传统 BF16 KV 缓存相比，KV 缓存中可容纳的 token 数量几乎翻倍，注意力内核的内存访问压力减半，从而更快地服务更长或更多的请求。
* **TileLang** 支持：TileLang 内核有助于灵活开发。
