# 在 GB200 NVL72 上以 PD 分离与大规模专家并行部署 DeepSeek（第一篇）：解码吞吐提升 2.7 倍

> 原文：[Deploying DeepSeek on GB200 NVL72 with PD and Large Scale EP (Part I): 2.7x Higher Decoding Throughput](https://lmsys.org/blog/2025-06-16-gb200-part-1/) · LMSYS Blog · The SGLang Team

GB200 NVL72 是目前世界上最先进的 AI 训练与推理硬件。在这篇博客中，我们很高兴分享在 GB200 NVL72 上以预填充-解码分离（PD 分离）与大规模专家并行运行 DeepSeek 671B 的初步结果。通过利用 Blackwell 特有的特性来增强现有组件，**在 2000 token 输入长度下，SGLang 在 GB200 NVL72 上实现了每 GPU 每秒 7,583 个 token 的解码吞吐——相比每 GPU 的 H100 配置加速 2.7 倍**（[链接](https://lmsys.org/blog/2025-05-05-large-scale-ep/)）。随着优化的持续推进，性能还有望进一步提升。复现说明见[此处](https://github.com/sgl-project/sglang/issues/7227)。

## 方法

作为前期工作，我们将以下组件集成到了 SGLang 中：

* **Blackwell DeepGEMM**：一个面向 FP8 精度的高性能通用矩阵乘法（GEMM）库，为充分发挥 Blackwell 架构而重写。新 API 为输入缩放因子引入了量化与打包，并利用新引入的 UMMA 特性实现快速矩阵乘法。
* **Blackwell DeepEP**：一个通信库，专为在专家混合（MoE）模型中向被路由到的专家分发 token 而设计。通过将远程 GPU 内存映射到本地虚拟地址空间，它支持了全新的纯 NVLink 环境。我们还将 DeepEP 的性能小幅提升了 15%。
* **FlashInfer Blackwell FMHA**：面向 DeepSeek 预填充的高性能融合多头注意力（FMHA）kernel，经重写以支持 Blackwell 架构。
* **Blackwell CUTLASS MLA**：针对 Blackwell 架构优化的多头潜在注意力（MLA）kernel。它利用新引入的 UMMA 特性，并为 TMA 启用 [2-SM](https://github.com/NVIDIA/cutlass/blob/main/examples/77_blackwell_fmha/kernel/sm100_fmha_mla_tma_warpspecialized.hpp#L119) cluster 模式，从而减少对 KV 缓存的 L2 读流量。
* **Blackwell Mooncake**：一个传输引擎，用于 PD 分离中的键值（KV）缓存传输。它同样采用了与 DeepEP 类似的技术来支持 NVLink。

## 实验

### 端到端性能

为了评估 DeepSeek 在 GB200 NVL72 上的解码性能，我们进行了与 H100 对比的端到端实验。由于我们获得了一个 GB200 NVL72 中的 14 个节点，我们使用其中 12 个节点执行解码，其余节点用于预填充。这一场景大致模拟了真实世界中用户拥有 18 个节点、以 6 个节点做预填充、12 个节点做解码的情形。为确保一致性，实验设置与我们此前的[博客文章](https://lmsys.org/blog/2025-05-05-large-scale-ep/)保持一致，基线数据也直接沿用其中。我们还沿用了前一篇博客中的减速 API（slow-down API）来使解码节点达到饱和。图中黄色基线柱表示前一篇博客中模拟的 MTP，其余柱状均未启用 MTP。因此，若采用相同配置，实际加速比将高于图中所示。

结果显示，在各种序列长度下，GB200 NVL72 相比 H100 取得了 2.5-3.4 倍的性能加速，主要归因于以下几个关键因素：

* **更强的内存带宽与算力**：相比 H100，GB200 NVL72 提供更高的内存带宽与计算 FLOPS，从而加速 kernel 执行。
* **更大的内存容量，支持更大的批大小**：更大的内存容量允许更大的 KV 缓存，从而支持更大的批大小，提升 kernel 效率。结合前述 kernel 加速，系统仍能满足与 H100 相近的每 token 生成时间（ITL）要求。
* **更大的 NVLink 域**：H100 集群中跨节点通信依赖 RDMA，而 GB200 NVL72 的纯 NVLink 方案显著降低了通信延迟。这使得可以关闭双批次重叠（two-batch overlap），既带来 kernel 性能提升，也避免了重叠通信时长超过计算时造成的浪费。
* **PD 分离与大规模专家并行**：与原始的 TP16 基线相比，PD 分离可以灵活地解耦预填充与解码阶段，优化资源利用。大规模专家并行（EP）通过降低内存访问压力来增强 MoE 性能。

### 消融实验：批大小

为了更好地理解批大小对系统的影响，我们测试了一系列批大小进行消融实验（该系统尚未针对小批大小做优化）。输入与输出长度分别设为 2000 和 100。结果显示，更大的批大小能够提升吞吐量。同时，在相同批大小下，GB200 NVL72 硬件相比 H100 展现出更快的性能。

## 未来工作

我们的初步结果已展现出 2.5-3.4 倍的加速，但仍存在巨大的进一步优化空间：

* **其他硬件与并行配置**：不使用大规模专家并行的执行场景——例如单节点上的小批大小（这在 B200 和 RTX 5090 等硬件上十分常见）——尚未经过优化，预计当前性能远非最优。
* **预填充性能增强**：当前工作的重点是解码性能，下一阶段将优先优化预填充阶段。
* **面向延迟的优化**：本文聚焦吞吐量，最小化延迟是未来的工作方向。
* **Kernel 优化**：许多 kernel 尚未充分利用 GB200 的内存带宽或计算能力。
* **通信重叠**：鉴于 GB200 NVL72 中通信硬件的变化，可以采用与 H100 上相似或不同的技术将通信与计算重叠，进一步降低延迟并提升吞吐量。
* **多 token 预测（MTP）**：在一次前向传播中预测多个 token 大有裨益，尤其是当批大小过小、kernel 无法充分发挥性能时。
