# SGLang v0.4：零开销批调度器、缓存感知负载均衡器与更快的结构化输出

> 原文：[SGLang v0.4: Zero-Overhead Batch Scheduler, Cache-Aware Load Balancer, Faster Structured Outputs](https://lmsys.org/blog/2024-12-04-sglang-v0-4/) · LMSYS Blog · The SGLang Team

我们很高兴地发布 [SGLang v0.4](https://github.com/sgl-project/sglang)，它带来了显著的性能提升与新特性：

- 零开销批调度器：吞吐量提升至 1.1 倍。  
- 缓存感知负载均衡器：吞吐量最高提升至 1.9 倍，缓存命中率提高至 3.8 倍。  
- DeepSeek 模型的数据并行注意力：解码吞吐量最高提升至 1.9 倍。  
- 基于 xgrammar 的快速结构化输出：最高快 10 倍。

本文将逐一介绍这些更新。欢迎你的反馈与贡献！

## 零开销批调度器

虽然 LLM 推理运行在 GPU 上，但仍有大量工作需要由 CPU 完成，例如批调度、内存分配和前缀匹配。一个未经优化的推理引擎可能有多达[一半的时间耗费在 CPU 开销上](https://mlsys.wuklab.io/posts/scheduling_overhead/)。SGLang 的高效批调度器从一开始就广为人知。在这个新版本中，我们把它推向了极致，实现了接近零开销的批调度器。这一思路很简单，[NanoFlow](https://arxiv.org/abs/2408.12757) 中已经提出过。基本做法是让 CPU 调度与 GPU 计算重叠执行：调度器提前一个批运行，为下一个批准备好所需的全部元数据。这样一来，GPU 就能始终保持忙碌，并掩盖基数树缓存（radix cache）操作等昂贵开销。相关代码见[这里](https://github.com/sgl-project/sglang/blob/85e1a6f3aa5a2288ca85fe3fe922c733b6533fa7/python/sglang/srt/managers/scheduler.py#L399)。实现细节包括通过创建 future token 来解决依赖关系，以及仔细安排 CUDA 事件与同步。下面是重叠执行的 CPU 调度器与 GPU worker 的示意图。

<img src="/images/blog/sglang_v0_4/scheduler.jpg" style="display: flex; margin-top: auto; margin-left: auto; margin-right: auto; margin-bottom: auto; width: 100%;"></img>

我们使用 Nsight 性能分析系统验证了"零开销"的说法。在下图中，有 5 个连续的解码批，可以看到 GPU 上没有出现任何空闲时间。（注意：这份分析图是在 Triton 注意力后端下获得的；使用 FlashInfer 后端时仍有一个小间隙，将在下一个 FlashInfer 版本中解决。）

<img src="/images/blog/sglang_v0_4/nsys_no_idle.jpg" style="display: flex; margin-top: auto; margin-left: auto; margin-right: auto; margin-bottom: auto; width: 90%;"></img>

有了这项优化，SGLang v0.4 现在能够榨取 GPU 的最后一点性能，相比上一版本取得 1.1 倍加速，相比其他最先进的基线取得 1.3 倍加速。这一加速在小模型和较大的张量并行规模下最为显著。

<img src="/images/blog/sglang_v0_4/llama_3_2_3b.svg" style="display: flex; margin-top: auto; margin-left: auto; margin-right: auto; margin-bottom: auto; width: 60%;"></img>


**用法**：该功能默认开启，你无需更改任何设置！

**复现基准测试**：
```
# zero-overhead batch scheduler (v0.4)
python3 -m sglang.launch_server --model meta-llama/Llama-3.2-3B-Instruct
python3 -m sglang.bench_serving --backend sglang --dataset-name random --num-prompts 500 --random-input 4096 --random-output 2048

# old batch scheduler (v0.3)
python3 -m sglang.launch_server --model meta-llama/Llama-3.2-3B-Instruct --disable-overlap
python3 -m sglang.bench_serving --backend sglang --dataset-name random --num-prompts 500 --random-input 4096 --random-output 2048
```

## 缓存感知负载均衡器

SGLang v0.4 为 LLM 推理引擎引入了缓存感知负载均衡器。该负载均衡器会预测各 worker 上前缀 KV 缓存的命中率，并选择匹配率最高的 worker。测试显示**吞吐量最高提升至 1.9 倍、命中率提高至 3.8 倍**，且 worker 数量越多收益越大。下图展示了缓存感知负载均衡器与数据并行中朴素轮询（round-robin）负载均衡器的区别。缓存感知负载均衡器会针对 worker 上的实际 radix tree 维护一棵近似 radix tree。这棵树以惰性方式更新，几乎没有开销。

<img src="/images/blog/sglang_v0_4/cache_aware.png" style="display: flex; margin-top: auto; margin-left: auto; margin-right: auto; margin-bottom: auto; width: 90%;"></img>

以下是一些基准测试结果。新的缓存感知路由器显著提升了吞吐量。

|  | SGLang v0.3 | SGLang v0.4 |
| :---- | :---- | :---- |
| 吞吐量（token/s） | 82665 | 158596 |
| 缓存命中率 | 20% | 75% |

> 该基准测试使用的[负载](https://github.com/sgl-project/sglang/pull/1990)包含多个长前缀组，且每个组都是完全均衡的。实际性能可能因负载特征而异，但它应当能显著提升缓存命中率。

该路由器的关键特性包括：
- **多节点支持**：将 worker 部署在多台机器上，由单个路由器连接分布式 worker，从而在分布式部署中保持缓存感知的同时轻松实现横向扩展。
- **缓存感知路由**：请求会被发送到命中率更高的 worker，同时执行负载均衡以避免不均衡。
- **免通信设计**：缓存状态无需任何 worker 间同步；路由器利用传递过来的信息模拟一棵"近似树"。
- **高性能实现**：采用纯 Rust 编写以支持高并发，设计开销极低，相比基于 Python 的替代方案有 2 倍提速。
- **独立软件包**：以 "sglang-router" 为名发布，包含 Python 绑定，并提供易于使用的 CLI 接口。
   
 ### 用法 
安装：
```
pip install sglang-router
```

1. Worker 与路由器一同启动

可作为现有 --dp-size 参数的直接替代：
```
python -m sglang_router.launch_server \
  --model-path meta-llama/Meta-Llama-3.1-8B-Instruct \
  --dp-size 8
```

2. 仅启动路由器
适用于多节点分布式处理：
```
python -m sglang_router.launch_router \
  --worker-urls http://worker1:8000 http://worker2:8000
```

 ### 复现基准测试：
 ````
# Hardware: 8x A100 80GB GPUs
# Run benchmark
python bench_serving.py \
  --host 127.0.0.1 \
  --port 30000 \
  --dataset-name generated-shared-prefix

# Launch with router
python -m sglang_router.launch_server \
  --model-path meta-llama/Meta-Llama-3.1-8B-Instruct \
  --dp-size 8

# Launch without router (baseline)
python -m sglang.launch_server \
  --model-path meta-llama/Meta-Llama-3.1-8B-Instruct \
  --dp-size 8
````

欲了解更多细节，可阅读这条[深入解读推文串](https://x.com/hsu_byron/status/1864449841239347341)。此外还有一篇相关论文（采用了不同的设计与实现）[Preble](https://arxiv.org/abs/2407.00023)，它同样构建在 SGLang 之上。

## DeepSeek 模型的数据并行注意力

推理中最常见的并行策略是张量并行（TP）。然而，对于某些模型，它可能并非最高效的策略。例如，DeepSeek 模型使用 MLA，且只有一个 KV head。如果在 8 张 GPU 上使用张量并行，会导致 KV 缓存被复制，带来不必要的内存占用。

为了解决这一问题，我们为多头潜在注意力（MLA）机制实现了数据并行（DP），以提升 DeepSeek 模型的吞吐量。对注意力部分采用 DP 后，KV 缓存显著减少，从而可以支持更大的批大小。在我们的 DP 注意力实现中，每个 DP worker 独立处理不同类型的批（prefill、decode、idle）。经过注意力处理的数据会在进入专家混合（MoE）层之前在所有 worker 之间执行 all-gather，而经过 MoE 处理后，数据会重新分发回各个 worker。下图展示了这一思路。

<img src="/images/blog/sglang_v0_4/dp_attention.svg" style="display: flex; margin-top: auto; margin-left: auto; margin-right: auto; margin-bottom: auto; width: 50%;"></img>

以下是在 8 x H100 80GB GPU 上的基准测试结果。有了这项优化，SGLang v0.4 的解码吞吐量达到了 SGLang v0.3 的 1.9 倍。我们正在为 MoE 层集成专家并行（EP），以进一步提升吞吐量。相关 PR 可参阅[数据并行](https://github.com/sgl-project/sglang/pull/1970)与[专家并行](https://github.com/sgl-project/sglang/pull/2203)。

<img src="/images/blog/sglang_v0_4/deepseek_coder_v2.svg" style="display: flex; margin-top: auto; margin-left: auto; margin-right: auto; margin-bottom: auto; width: 60%;"></img>

**用法：** 添加 `--enable-dp-attention` 选项即可开启该功能。目前仅支持 DeepSeek 模型。

**复现基准测试：**
```
# Hardware: 8x H100 80GB GPUs
# If you see out-of-memory, please try to reduce `--mem-fraction-static` to a smaller value such as 0.75.

# SGLang w/ DP attention (v0.4)
python3 -m sglang.launch_server --model-path neuralmagic/DeepSeek-Coder-V2-Instruct-FP8 --disable-radix-cache --trust-remote-code --tp 8 --enable-dp-attention --mem-fraction-static 0.78
python3 -m sglang.bench_serving --backend sglang --dataset-name random --random-input 1 --random-output 512 --random-range-ratio 1 --num-prompts 10000

# SGLang w/o DP attention (v0.3)
python3 -m sglang.launch_server --model-path neuralmagic/DeepSeek-Coder-V2-Instruct-FP8 --disable-radix-cache --trust-remote-code --tp 8 --mem-fraction-static 0.78
python3 -m sglang.bench_serving --backend sglang --dataset-name random --random-input 1 --random-output 512 --random-range-ratio 1 --num-prompts 10000
```

## 基于 XGrammar 的快速结构化输出

凭借[压缩有限状态机](https://lmsys.org/blog/2024-02-05-compressed-fsm/)，SGLang 一直是 JSON 解码速度最快的推理引擎。在本次新版本中，通过集成更快的语法后端 xgrammar，它变得更快了。  
根据基准测试结果，**在 JSON 解码任务上，SGLang \+ xgrammar 最高可比其他开源方案快 10 倍**。更多信息请参阅 xgrammar 的博客文章：  
[https://blog.mlc.ai/2024/11/22/achieving-efficient-flexible-portable-structured-generation-with-xgrammar](https://blog.mlc.ai/2024/11/22/achieving-efficient-flexible-portable-structured-generation-with-xgrammar)。

**用法**：启动服务器时添加 \`--grammar-backend xgrammar\`。
```
python3 -m sglang.launch_server --model-path meta-llama/Llama-3.1-8B-Instruct --grammar-backend xgrammar
```

之后你就可以通过 OpenAI 兼容 API 进行查询。示例见 [https://sgl-project.github.io/backend/openai\_api\_completions.html\#JSON](https://sgl-project.github.io/backend/openai\_api\_completions.html#JSON)。
