# Mini-SGLang：小而精的高效推理引擎

> 原文：[Mini-SGLang: Efficient Inference Engine in a Nutshell](https://lmsys.org/blog/2025-12-17-minisgl/) · LMSYS Blog · Ziyi Xu

我们很高兴推出 **Mini-SGLang**——一个轻量级却高性能的大语言模型（LLM）推理框架。Mini-SGLang 源自 [SGLang](https://github.com/sgl-project/sglang) 项目，旨在揭开现代推理服务系统的复杂面纱。尽管代码库精简，它仍保留了定义最先进性能的各项高级特性，包括用于高效 KV 缓存复用的 **Radix Attention**、用于控制内存占用的 **Chunked Prefill（分块预填充）**、用于降低 CPU 开销的 **Overlap Scheduling（重叠调度）**，以及用于可扩展分布式服务的 **Tensor Parallelism（张量并行）**。凭借 OpenAI 兼容 API 和对 Llama-3、Qwen-3 等模型的开箱即用支持，Mini-SGLang 既是能力完备的推理引擎，也是面向研究者和开发者的透明参考实现。

源代码可在 [https://github.com/sgl-project/mini-sglang](https://github.com/sgl-project/mini-sglang) 获取。

<!-- ![Header](/images/blog/minisgl/logo.png) -->

## 动机：为什么需要 Mini-SGLang？

尽管 SGLang 凭借全面的特性集实现了最先进的推理性能，但其代码库已经十分庞大，接近 300k 行 Python 代码。为了降低学习者与研究者的复杂度门槛，我们构建了 Mini-SGLang，聚焦两个主要目标：提供学习资源，以及支持面向研究的快速原型开发。

### 教学用途

Mini-SGLang 拥有干净、高度模块化的代码库，仅 **5k 行 Python 代码**，让初学者更容易理解现代 LLM 推理服务引擎的核心组件。

虽然简单，Mini-SGLang 同时支持在线与离线推理，并实现了关键的现代优化，包括 **Tensor Parallelism（张量并行）**、**Overlap Scheduling（重叠调度）**、**Chunked Prefill（分块预填充）**、**Radix Cache（基数树缓存）**和 **JIT CUDA 算子**。这使它成为一个全面的学习资源。

### 快速研究原型

许多机器学习与系统研究者都苦恼于把自己的优化整合进现有框架。一方面，往 SGLang 这类复杂框架中注入新逻辑是有风险的：很容易破坏系统的隐式不变量（implicit invariants），从而引入隐蔽的 bug。另一方面，从零开始构建推理引擎又十分繁琐：光是处理基础设施细节（如前端服务器、分词、NCCL 通信）就需要投入大量精力，才能追平最先进的基线。

Mini-SGLang 在两者之间取得了平衡。它最初是一个研究原型，我们用它来快速验证新的系统想法，而无需花数周时间应对一个完整规模的代码库，也不必从零重新实现基础设施。它提供了一个开箱即用、易于检视、扩展和优化的高性能框架，既承担了基础设施的重活，又保持足够的灵活性以支持快速原型开发。此外，Mini-SGLang 提供 **OpenAI 兼容的基准测试工具**，便于进行端到端性能分析，并与 [SGLang](https://github.com/sgl-project/sglang)、[vLLM](https://github.com/vllm-project/vllm)、[TensorRT-LLM](https://github.com/NVIDIA/TensorRT-LLM) 等各类推理服务引擎进行对比。对于算子开发者，Mini-SGLang 还提供细粒度的 **NVTX 标注**，对算子调试和性能剖析非常有价值。

## 特性

Mini-SGLang 与 SGLang 共享相同的高层系统架构：一个前端 API 服务器、一个分词器服务器，以及每块 GPU 一个的后端调度器。

![系统设计图](/images/blog/minisgl/design.drawio.png)

### 重叠调度

LLM 推理不只是 GPU 计算；相当一部分工作由 CPU 承担，包括批调度、内存管理和 token 处理。如果不做优化，这些 CPU 开销会导致 GPU 空转，拖累整体性能。

Mini-SGLang 实现了与 SGLang 类似的 **重叠调度（overlap scheduling）**机制来缓解这一问题。通过在 GPU 忙于当前批的同时，在 CPU 上准备下一批请求，它有效地隐藏了 CPU 开销。如下方 Nsight Systems 剖析图所示，这使 GPU 持续保持满载，消除了 GPU 空闲，最大化了吞吐量。更多技术细节见我们[之前的博客文章](https://lmsys.org/blog/2024-12-04-sglang-v0-4/)。

![重叠执行](/images/blog/minisgl/overlap.png)

> 重叠执行的示例。CPU 执行开销被完全重叠掩盖。

![非重叠执行](/images/blog/minisgl/no-overlap.png)

> 非重叠执行的示例。CPU 执行开销导致大量 GPU 停顿。

如需在关闭重叠调度的情况下运行消融实验，请设置环境变量 `MINISGL_DISABLE_OVERLAP_SCHEDULING=1`。

### 高性能算子

Mini-SGLang 集成了最先进的注意力算子以确保顶级性能。在 NVIDIA Hopper 架构上，它使用 [FlashAttention-3](https://github.com/Dao-AILab/flash-attention) 作为预填充算子，使用 [FlashInfer](https://github.com/flashinfer-ai/flashinfer) 作为解码算子。

沿袭 [FlashInfer](https://github.com/flashinfer-ai/flashinfer) 与 [SGLang](https://github.com/sgl-project/sglang) 的做法，Mini-SGLang 也集成了即时（JIT）编译算子，以获得更好的运行时性能。我们采用 [TVM FFI](https://github.com/apache/tvm-ffi) 实现 Python 绑定，其轻量设计使其比默认的 PyTorch 接口快得多。

### 交互式 Shell 模式

为方便直接交互与测试，Mini-SGLang 内置了简单的 shell 模式。用户可以直接在命令行与大模型对话，无需单独的客户端即可便捷地测试模型并观察其行为。

![Shell 示例](/images/blog/minisgl/shell.png)

## 性能基准测试

为评估 Mini-SGLang 的性能，我们开展了涵盖离线吞吐量与在线服务延迟的全面实验。

### 离线推理吞吐量

我们在单块 NVIDIA H200 GPU 上，将 Mini-SGLang 的离线吞吐量与 Nano-vLLM 进行了对比。参照 [Nano-vLLM](https://github.com/GeeeekExplorer/nano-vllm/) 的测试方法，我们使用了 [Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B/) 模型，并额外测试了更大的 [Qwen3-14B](https://huggingface.co/Qwen/Qwen3-14B/) 模型以评估更大规模下的表现。之所以聚焦 Qwen3 模型，是因为 Nano-vLLM 基线目前存在一些限制。

吞吐量结果（单位：token/秒）如下所示：

![离线基准测试](/images/blog/minisgl/offline.png)

结果表明，得益于有效隐藏 CPU 开销的 **重叠调度**机制，Mini-SGLang 在两个 Qwen3 模型上均始终优于 Nano-vLLM 基线。

**可复现性**：离线基准测试脚本见[此链接](https://github.com/sgl-project/mini-sglang/blob/main/benchmark/offline/bench.py)。

### 在线服务延迟

为评估真实场景下的服务性能，我们使用来自 [Qwen trace](https://github.com/alibaba-edu/qwen-bailian-usagetraces-anon/blob/main/qwen_traceA_blksz_16.jsonl) 的真实负载，对 Mini-SGLang 与 SGLang 进行了基准测试。我们向部署在 4 块 H200 GPU 上、采用 4 路张量并行的 [Qwen3-32B](https://huggingface.co/Qwen/Qwen3-32B) 模型重放了 1,000 条请求，测量了吞吐量、90 分位（P90）首 token 延迟（TTFT）和 token 间延迟（TBT）。

![在线基准测试](/images/blog/minisgl/online.png)

结果表明，Mini-SGLang 的性能与 SGLang 几乎完全一致，证明其轻量化设计没有在吞吐量或延迟上做出妥协。

**可复现性**：使用以下命令分别启动两个系统：

```bash
# Mini-SGLang
python -m minisgl --model "Qwen/Qwen3-32B" --tp 4 --cache naive 

# SGLang
python3 -m sglang.launch_server --model "Qwen/Qwen3-32B" --tp 4 \
    --disable-radix --port 1919 --decode-attention flashinfer
```

在线基准测试脚本见[此链接](https://github.com/sgl-project/mini-sglang/blob/main/benchmark/online/bench_qwen.py)。

## 结论

Mini-SGLang 成功将一个最先进推理引擎的强大能力浓缩进精简且易于理解的代码库。通过保留重叠调度、高性能注意力算子等关键优化，它在提供出色性能的同时，还是一个宝贵的教学工具和灵活的研究平台。

我们邀请你探索[源代码](https://github.com/sgl-project/mini-sglang)、运行基准测试，亲自体验 Mini-SGLang 如何让高性能 LLM 推理变得前所未有地触手可及。
