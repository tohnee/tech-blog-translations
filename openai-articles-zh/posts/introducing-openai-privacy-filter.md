# OpenAI Privacy Filter 简介

> 原文：[Introducing OpenAI Privacy Filter](https://openai.com/index/introducing-openai-privacy-filter/) · OpenAI 博客

今天，我们发布 OpenAI Privacy Filter——一个用于检测并删改文本中个人可识别信息（PII）的开放权重模型。此次发布是我们更广泛努力的一部分：通过为开发者提供安全使用 AI 进行构建的实用基础设施，支持一个更有韧性的软件生态，包括让强大的隐私与安全防护更容易从源头落地的[工具](https://openai.com/index/codex-security-now-in-research-preview/)和[模型](https://openai.com/index/scaling-trusted-access-for-cyber-defense/)。

Privacy Filter 是一个具备前沿个人数据检测能力的小型模型。它为高吞吐隐私工作流而设计，能够对非结构化文本中的 PII 进行上下文感知检测。它可以在本地运行，这意味着 PII 可以在不离开你的机器的情况下被掩码或删改。它能高效处理长输入，通过快速的单趟处理做出删改决策。

在 OpenAI，我们在自己的隐私保护工作流中使用 Privacy Filter 的微调版本。我们开发 Privacy Filter，是因为我们相信借助最新的 AI 能力，可以把隐私标准提升到超越市场上已有产品的水平。今天发布的 Privacy Filter 版本，在校正了我们在评测中发现的标注问题之后，在 PII-Masking-300k 基准测试上达到了最先进（state-of-the-art）的性能。

通过这次发布，开发者可以在自己的环境中运行 Privacy Filter、针对自己的用例进行微调，并把更强的隐私保护内建到训练、索引、日志和审查流水线中。

## 一个具备前沿个人数据检测能力的小型模型

现代 AI 系统中的隐私保护，靠的不只是模式匹配。传统的 PII 检测工具通常依赖针对电话号码、电子邮箱等格式的确定性规则。它们在狭窄场景下可以工作良好，但常常漏掉更隐蔽的个人信息，并且难以处理上下文。

Privacy Filter 以更深层的语言与上下文感知构建，以实现更细腻的表现。通过把强大的语言理解能力与隐私专用的标签体系结合，它可以在非结构化文本中检测更大范围的 PII，包括那些正确决策取决于上下文的情形。它能更好地区分两类信息：一类因为是公开信息而应当保留，另一类因为涉及私人个体而应当被掩码或删改。

最终得到的模型足够强大，能够提供前沿级别的隐私过滤性能；同时它又足够小，可以在本地运行——这意味着尚未过滤的数据可以留在设备上，暴露风险更低，而无需发送到服务器进行去标识化。

## 模型概览

Privacy Filter 是一个带跨度解码（span decoding）的双向词元分类模型。它从自回归预训练检查点出发，随后被改造为在固定隐私标签体系上的词元分类器。它不逐 token 生成文本，而是一次性标注整个输入序列，再通过受限的 Viterbi 程序解码出连贯的跨度。

这种架构赋予 Privacy Filter 几个对生产使用很有用的特性：

- **快速高效：** 所有 token 在单次前向传播中完成标注。
- **上下文感知：** 语言先验使模型能够根据周围上下文检测 PII 跨度。
- **长上下文：** 发布的模型支持最多 128,000 token 的上下文。
- **可配置：** 开发者可以根据自己的工作流调整运行点，在召回率与精确率之间权衡。

发布的模型总参数量为 1.5B，激活参数量为 50M。

Privacy Filter 预测八个类别的跨度：

- `private_person`
- `private_address`
- `private_email`
- `private_phone`
- `private_url`
- `private_date`
- `account_number`
- `secret`

`account_number` 类别有助于掩码各种账号，包括信用卡号和银行账号等银行信息，而 `secret` 则有助于掩码密码和 API 密钥等内容。

这些标签通过 BIOES 跨度标签解码，有助于产生更干净、更连贯的掩码边界。

## 掩码个人标识符后的文本

主题：Q2 规划跟进

你好，`[PRIVATE_PERSON]`：

再次感谢你今天早些时候抽空会面。我想跟进一下 Q2 推出的修订时间表，并确认产品发布定于 `[PRIVATE_DATE]`。供参考，项目文件的编号是 `[ACCOUNT_NUMBER]`。如果你那边有任何变化，可以直接回复本邮件（`[PRIVATE_EMAIL]`），或拨打 `[PRIVATE_PHONE]` 联系我。

此致

**[PRIVATE_PERSON]**

## 我们如何构建它

我们分几个阶段开发了 Privacy Filter。

首先，我们构建了一个隐私分类体系，定义模型应检测的跨度类型。其中包括个人标识符、联系方式、地址、私人日期、多种不同的账号（如信用卡和银行信息），以及 API 密钥和密码等机密信息。

其次，我们把一个预训练语言模型改造成双向词元分类器：将语言建模头替换为词元分类头，并以监督分类目标进行后训练。

第三，我们在公开可得数据与合成数据的混合数据上进行训练，这些数据兼顾了真实文本与困难的隐私模式。在公开数据中标注不完整的部分，我们使用模型辅助的标注与审查来提升覆盖率。我们还生成了合成样本，以提高格式、上下文和隐私子类型上的多样性。

在推理时，模型的词元级预测通过受限序列解码被解码为连贯的跨度。这种方法既保留了预训练模型的广泛语言理解能力，又使其专门化于隐私检测。

## Privacy Filter 的表现

我们在标准基准测试以及额外的合成与对话式评测上评估了 Privacy Filter，后者专门用于测试更难、更依赖上下文的情形。

在 [PII-Masking-300k](https://huggingface.co/datasets/ai4privacy/pii-masking-300k) 基准测试上，Privacy Filter 取得 96% 的 F1 分数（精确率 94.04%，召回率 98.04%）。在我们审阅中发现了数据集标注问题并做了校正的基准版本上，F1 分数为 97.43%（精确率 96.79%，召回率 98.08%）。

我们还发现该模型可以高效适配。即使用少量数据进行微调，也能快速提升领域特定任务的准确率——F1 分数从 54% 提高到 96%，并在我们评测的领域适配基准上接近饱和。

除了基准测试表现，Privacy Filter 还为嘈杂的真实世界文本中的实用隐私过滤而设计，包括长文档、模糊指代、混合格式字符串以及软件相关机密。[模型卡片](https://cdn.openai.com/pdf/c66281ed-b638-456a-8ce1-97e9f5264a90/OpenAI-Privacy-Filter-Model-Card.pdf)还报告了针对代码库中机密信息检测的专项评测，以及在多语言、对抗性和依赖上下文样本上的压力测试。

## 局限性

Privacy Filter 不是匿名化工具，不是合规认证，也不能替代高风险场景中的人工政策审查。它是更广泛的隐私优先设计（privacy-by-design）系统中的一个组成部分。

它的行为反映了其训练时所用的标签体系与决策边界。不同组织可能需要不同的检测或掩码策略，而这些策略可能需要进行领域内评测或进一步微调。在不同语言、文字系统、命名惯例以及偏离训练分布的领域中，表现也可能存在差异。

与所有模型一样，Privacy Filter 也可能出错。它可能漏掉罕见的标识符或模糊的私人指代；在上下文有限时，尤其是在短序列中，它可能对实体删改过多或过少。在法律、医疗、金融等高敏感度工作流中，人工审查以及领域专属的评测与微调仍然十分重要。

## 获取方式

我们发布 OpenAI Privacy Filter，是为了支持整个生态系统中更强的隐私保护。

模型今天以 Apache 2.0 许可证在 [Hugging Face](https://huggingface.co/openai/privacy-filter) 和 [Github](https://github.com/openai/privacy-filter) 上发布。它可用于实验、定制和商业部署，并可以针对不同的数据分布和隐私策略进行微调。

随模型一同发布的还有文档，涵盖模型架构、标签体系、解码控制、预期用例、评测设置和已知局限性，帮助团队既了解模型擅长什么，也了解哪些地方需要谨慎使用。

## 展望未来

AI 系统的隐私保护是一项横跨研究、产品设计、评测与部署的持续努力。

Privacy Filter 体现了我们认为重要的一个方向：在真实世界 AI 系统真正在乎的、定义狭窄的任务上具备前沿能力的小型高效模型。我们之所以发布它，是因为我们认为隐私保护基础设施应当更容易被检查、运行、适配和改进。

我们的目标是让模型了解世界，而不是了解私人个体。Privacy Filter 有助于让这一点成为可能。

我们发布 Privacy Filter 的这个预览版本，是为了收集研究与隐私社区的反馈，并进一步迭代模型性能。
