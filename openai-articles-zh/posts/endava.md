# Endava 如何用 Codex 构建智能体式组织

> 原文：[How Endava builds an agentic organization with Codex](https://openai.com/index/endava/) · OpenAI 博客

Endava 是一家全球软件外包公司，工程师遍布欧洲、美洲和亚洲，它一直是 Codex 的早期采用者。对于一家以为银行、保险公司、零售商和媒体公司交付高质量软件为核心业务的企业来说，由此带来的改进是巨大的。

「我们从过去大量亲自编写代码，转变为现在监督 Codex 产出的工作，」Endava 欧洲区区域 CTO Joe Dunleavy 说，「产出质量呈指数级提升。」

Endava 如今把自己定义为一种*智能体式组织（agentic organization）*：在这类公司里，资深专家的经验被固化成智能体，与团队并肩工作，贯穿客户项目的整个生命周期——从需求受理到创意构思，再到最终交付。

> 「Codex 真正帮到我们的地方在于，它让小团队的人在非常紧凑的时间窗口内交付巨大的价值。」

## 放大团队中的每一项技能

Codex 改变了资深工程师与初级工程师协作的方式，Endava 全球智能体架构高级副总裁（Global SVP of Agentic Architecture）Mike Krolnik 说。「像我这样出身于复杂环境的资深架构师，能够把自己想要的东西清晰地表达出来，而 Codex 会把它变成团队里较初级成员也容易获取的信息。而从初级工程师的角度看，他们能够上手这个工具，产出资深、成熟水准的成果。」

在实践中，这意味着把通常留给资深工程师的工作交给初级开发者，由 Codex 在最佳实践和架构决策上充当向导。「我可以给 Codex 一个观点，当他们工作时，它会帮助他们理解这个观点，」Krolnik 解释道，「他们可以就自己不理解的地方提问。作为开发过程中的学习工具，我可以把自己的经验固化下来，让 Codex 与团队一起工作，向他们传授软件架构与开发中更好的实践。」

这种知识传承最终成为智能体式组织的核心价值和优势之一。资深判断力——通常需要多年的结对编程、代码评审和言传身教才能获得——变成了团队可以实时协同共事的东西。这改变了组织中初级开发者接受指导的方式。一位资深专家的视角，一经编码进 Codex，就可以并行指导多个经验尚浅的团队。

> 「Codex 作为工具已经成熟。我们把它用于需求分析、设计、规格说明、开发和运维；它是覆盖我们整个生命周期的通用桌面智能体。」

## 数周的工作，压缩到数天

当资深判断力随时可得时，交付的每一个步骤都可以得到改进。Endava 不再把分析、设计和构建视为在各专项角色之间依次交接的顺序阶段。「这些阶段过去每个都要花上几天或几周的分析，」Krolnik 说，「现在 Codex 把分析、设计和构建打包在一起，我们可以用一个统一的工具完成。」

最近的一次跨团队协作展示了这在实践中是什么样子。Endava 的法务团队给工程部门带来了一个复杂问题：对照一套特定标准审查数千页的合同。要把律师的需求转换成工程团队能够据此开发的东西，通常需要数周的来回沟通。而 Krolnik 的团队录下了与法务相关方进行的两小时深入会议，把会议记录交给 Codex，用它生成了一份可用的需求规格说明。原本可能需要一两周反复修订的工作，被压缩成两次一小时的会议，并产出了一份可用的规格文档。

同样的时间节省也体现在客户工作中。Endava 的团队如今会在客户会议上现场生成设计文档、图表和规格说明来阐述想法。「你可以让它画出所提议软件架构的示意图，这样客户理解起来更容易，」Krolnik 说，「它极大地加速了来回沟通，也确实打开了很多扇门。」

## 领导力经验

- **把资深专家的经验固化下来。**最大的杠杆来自把资深架构师的判断力沉淀到 Codex 中，让初级团队成员在执行时获得资深层面的指导。
- **把 Codex 当作桌面智能体，而不是编码助手。**Endava 迎来的最大突破，来自把 Codex 应用到需求、设计、客户沟通和运维上，而不只是写代码。
- **不要只是想，真正上手试！**「第一条建议是，你必须越过『想想自己要做什么』这一步，真正动手去尝试，」Dunleavy 说。Endava 给刚起步团队的建议是：先挑选一个非编码工作流——需求分析、设计文档或客户沟通。见识 Codex 全部价值最快的方式，就是把它用在你的团队从未用过编码工具的地方。
