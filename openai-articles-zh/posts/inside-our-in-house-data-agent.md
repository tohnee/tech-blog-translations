# 走进 OpenAI 的自研数据智能体

> 原文：[Inside OpenAI’s in-house data agent](https://openai.com/index/inside-our-in-house-data-agent/) · OpenAI 博客

数据驱动着系统的学习、产品的演进以及公司的决策。但要快速、正确、并带着恰当的上下文获得答案，往往比应有的更难。为了让 OpenAI 在规模扩张的过程中把这件事变得更简单，我们构建了**一个自研的定制化内部 AI 数据智能体**，让它在我们自己的平台上进行探索与推理。

我们的智能体是一个仅限内部使用的定制工具（并非对外产品），专门围绕 OpenAI 的数据、权限与工作流构建。我们将展示如何构建与使用它，以帮助呈现 AI 支持各团队日常工作的一些真实而有影响力的方式。我们用来构建与运行它的 OpenAI 工具（[Codex](https://openai.com/index/introducing-codex/)、[GPT‑5 旗舰模型](https://openai.com/index/introducing-gpt-5-2/)、[Evals API](https://platform.openai.com/docs/guides/evals) 与 [Embeddings API](https://platform.openai.com/docs/guides/embeddings)）与我们提供给全球开发者的工具完全相同。

我们的数据智能体让员工能在几分钟而非几天内从问题走向洞察。这降低了各部门拉取数据与进行精细分析的门槛，而不再只是数据团队的专利。如今，OpenAI 的工程、数据科学、市场推广（Go-To-Market）、财务与研究团队都依赖这个智能体来回答**高影响力的数据问题**。例如，它可以帮助回答如何评估产品发布、如何理解业务健康状况，而这一切都通过自然语言这一直观形式完成。该智能体将 Codex 驱动的表级知识与产品及组织上下文相结合，其持续学习的记忆系统意味着它每一轮都在进步。

在本文中，我们将拆解为什么我们需要一个定制的 AI 数据智能体、其代码增强的数据上下文与自我学习为何如此有用，以及我们一路走来汲取的经验教训。

## 为什么我们需要一个定制工具

OpenAI 的数据平台服务于 **3500 多名内部用户**，他们分布在工程、产品与研究等领域，数据规模横跨 **70,000 个数据集**、超过 **600 PB**。在这样的规模下，仅仅找到正确的表，就可能成为分析工作中最耗时的环节之一。

正如一位内部用户所说：

*“我们有很多彼此相当相似的表，我花了大量时间试图弄清它们有何区别、该用哪一张。有的包含未登录用户，有的不包含；有的字段相互重叠，很难分辨谁是谁。”*

即便选对了表，产出正确的结果仍然充满挑战。分析师必须对表数据与表关系进行推理，确保转换与过滤器被正确应用。常见的失败模式——多对多连接（join）、过滤条件下推错误、未处理的空值——会在无声无息中让结果失效。以 OpenAI 的规模，分析师不应把时间耗在调试 SQL 语义或查询性能上：他们的重心应当是定义指标、验证假设并做出数据驱动的决策。

## 它是如何工作的

我们将逐一介绍我们的智能体是什么、它如何整理上下文，以及它如何持续自我改进。

我们的智能体由 [**GPT‑5.2**](https://openai.com/index/introducing-gpt-5-2/) 驱动，旨在对 OpenAI 的数据平台进行推理。它出现在员工工作的每个角落：作为 Slack 智能体、通过网页界面、内嵌于 IDE、在[通过 MCP 使用的 Codex CLI](https://developers.openai.com/codex/mcp/) 中，以及[通过 MCP 连接器直接嵌入 OpenAI 内部 ChatGPT 应用](https://platform.openai.com/docs/guides/tools-connectors-mcp)。

用户可以提出复杂的开放式问题，这类问题通常需要多轮手动探索。以下面的提示词为例（它使用的是一个测试数据集）：*“对于纽约出租车行程，哪些上车—下车 ZIP 邮编组合最不可靠（典型行程时间与最坏情况之间的差距最大），以及这种波动发生在什么时候？”*

**智能体端到端地完成整个分析**：从理解问题，到探索数据、运行查询，再到综合结论。

这是智能体对该问题的回答。

这个智能体的一大超能力是它推演问题的方式。它不是按固定脚本行事，而是评估自身的进展。如果中间结果看起来不对（例如，由于错误的 join 或过滤条件导致结果为零行），智能体会排查问题所在，调整方法并再次尝试。在整个过程中，它始终保留完整上下文，并在步骤之间传递经验。这种**闭环、自学习的过程**把迭代从用户一侧转移到了智能体自身，从而带来更快的产出和比人工工作流持续更高的分析质量。

智能体用于识别最不可靠的纽约出租车上下车组合的推理过程。

该智能体覆盖完整的分析工作流：发现数据、运行 SQL、发布 notebook 与报告。它理解公司内部知识，可以进行网络搜索获取外部信息，并通过学习到的用法与记忆随时间不断改进。

## 上下文就是一切

高质量的回答取决于**丰富而准确的上下文**。缺乏上下文时，即便是强大的模型也可能产出错误结果，例如对用户数量做出严重失实的估计，或误解内部术语。

没有记忆的智能体，无法有效查询。

智能体的记忆通过定位正确的表来加快查询。

为了避免这些失败模式，该智能体围绕**多层上下文**构建，这些上下文将其锚定在 OpenAI 的数据与组织知识之上。

### 第 1 层：表的用法

- **元数据锚定（grounding）：** 智能体依赖模式（schema）元数据（列名与数据类型）来指导 SQL 编写，并利用表血缘（lineage，即上下游表关系）来提供不同表之间如何关联的上下文。
- **查询推断：** 摄取历史查询有助于智能体理解如何编写自己的查询，以及哪些表通常会被连接在一起。

### 第 2 层：人工标注

- 由领域专家提供的、经过精心整理的表与列**描述**，捕捉意图、语义、业务含义，以及那些不易从模式或历史查询中推断出的已知注意事项。

仅靠元数据并不够。要真正区分不同的表，你需要了解它们是如何被创建的、源自何处。

### 第 3 层：Codex 增强

- 通过推导表的代码级定义，智能体对数据实际包含的内容建立起更深入的理解。关于表中存储了什么、以及它如何从某个分析事件派生而来的细节，提供了额外的信息。例如，它可以提供取值的唯一性、表数据的更新频率、数据的范围（例如，如果表排除了某些字段，那么它的粒度就是这一层级）等方面的上下文。
- 这通过展示该表在 Spark、Python 及其他数据系统中超越 SQL 的用法，提供了增强的使用上下文。
- 这意味着智能体能够区分那些看起来相似、却在关键之处不同的表。例如，它能判断某张表是否只包含第一方 ChatGPT 流量。这些上下文还会自动刷新，因此无需人工维护就能保持最新。

### 第 4 层：组织知识

- 智能体可以访问 Slack、Google Docs 与 Notion，其中记录着关键的公司背景，例如产品发布、可靠性事故、内部代号与工具，以及关键指标的权威定义与计算逻辑。
- 这些文档经过摄取、嵌入（embedding）并连同元数据与权限一起存储。检索服务在运行时处理访问控制与缓存，使智能体能够高效且安全地拉取这些信息。

### 第 5 层：记忆

- 当智能体收到纠正，或发现某些数据问题中的细节时，它能够把这些经验保存下来供下次使用，从而与用户一起不断改进。这样一来，未来的回答就能从更准确的基线出发，而不是反复踩同样的坑。记忆的目标是保留并复用那些对数据正确性至关重要、却难以仅凭其他层推断出的非显而易见的纠正、过滤条件与约束。例如，有一次智能体不知道该如何为某个分析实验设置过滤（它需要匹配实验门控（experiment gate）中定义的特定字符串）。记忆在这里至关重要，确保它能够正确过滤，而不是模糊地尝试字符串匹配。
- 当你给智能体一个纠正，或它从你的对话中发现经验时，它会提示你把这条记忆保存下来供下次使用。用户也可以手动创建与编辑记忆。记忆分为全局与个人两个层级，智能体的工具让编辑变得十分简单。

### 第 6 层：运行时上下文

- 当某张表没有既有上下文、或已有信息过时的时候，智能体可以向数据仓库发出实时查询，直接检查和查询该表。这使它能够验证模式、实时理解数据，并据此做出响应。
- 智能体还能按需与数据平台的其他系统（元数据服务、Airflow、Spark）通信，以获取仓库之外存在的更广泛的数据上下文。

我们运行一个每日离线流水线，把表的用法、人工标注与 Codex 推导的增强信息聚合成一个统一的规范化表示。这些增强上下文随后通过 [OpenAI Embeddings API](https://platform.openai.com/docs/api-reference/embeddings) 转换为嵌入向量并存储起来供检索使用。查询时，智能体通过检索增强生成（retrieval-augmented generation，[RAG](https://en.wikipedia.org/wiki/Retrieval-augmented_generation)）只拉取最相关的嵌入上下文，而不是扫描原始元数据或日志。这使得表理解快速且可扩展，即便横跨数万张表也是如此，同时保持运行时延迟可预测且低廉。运行时查询会按需实时发往我们的数据仓库。

这些层共同确保智能体的推理锚定于 OpenAI 的数据、代码与组织知识，大幅减少错误并提升回答质量。

## 设计得像队友一样思考与工作

当问题清晰时，一问一答式的回答就够用了，但大多数问题并非如此。更多时候，得到正确结果需要反复打磨与一些中途纠正。

该智能体被设计为像一个可以与之商讨的队友。它是对话式的、随时在线的，既能快速作答，也能进行迭代式探索。

它在多轮之间延续完整上下文，用户可以提出后续问题、调整意图或改变方向，而无需重新陈述一切。如果智能体开始走上错误的道路，用户可以在分析中途打断并重新定向它——就像与一位善于倾听、而不是闷头蛮干的人类协作者共事。

当指令不清晰或不完整时，智能体会主动提出澄清性问题。如果没有得到回应，它会采用合理的默认值继续推进。例如，如果用户询问业务增长却没有指定日期范围，它可能会默认采用最近 7 天或 30 天。这些先验假设让它既能保持响应灵敏、不阻塞流程，又能最终收敛到正确的结果。

最终得到的是一个这样的智能体：当你**确切知道自己想要什么**时（例如“介绍一下这张表”）它表现良好，而当你**正在探索**时（例如“我看到这里有个下滑，能按客户类型和时间范围拆解一下吗？”）它同样出色。

上线后，我们观察到用户经常为日常重复性工作运行同样的分析。为了加速这一过程，该智能体的工作流把周期性分析打包成可复用的指令集。例子包括每周业务报告与表校验的工作流。通过一次性编码上下文与最佳实践，工作流简化了重复分析，并确保不同用户之间结果的一致性。

## 快速推进，而不辜负信任

构建一个随时在线、不断演进的智能体，意味着质量既可能提升，也同样容易漂移。没有紧密的反馈回路，回退就不可避免且难以察觉。要在不辜负信任的前提下扩展能力，唯一的途径是系统化的评测。

在本节中，我们将讨论如何利用 [OpenAI Evals API](https://platform.openai.com/docs/guides/evals) 来衡量并守护智能体的回答质量。

其评测建立在精心整理的问答对集合之上。每个问题都针对一个我们格外在意是否答对的重要指标或分析模式，并配有一条人工编写的“黄金”（golden）SQL 查询，该查询能产出预期结果。对于每个评测，我们把自然语言问题发送到其查询生成端点，执行生成的 SQL，并将输出与预期 SQL 的结果进行比较。

评估并不依赖朴素的字符串匹配。生成的 SQL 可能在语法上不同却仍然正确，结果集也可能包含并不实质影响答案的额外列。为了应对这一点，我们同时比较 SQL 与结果数据，并将这些信号输入 OpenAI 的 Evals 评分器（grader）。评分器会给出最终分数及解释，同时捕捉正确性与可接受的差异。

这些评测就像在开发期间持续运行的单元测试，并在生产环境中作为金丝雀（canary）识别回退；这让我们能够在智能体能力不断扩展时及早发现问题、自信地迭代。

## 智能体安全

我们的智能体直接接入 OpenAI 现有的安全与访问控制模型。它纯粹作为接口层运行，继承并执行与管辖 OpenAI 数据相同的权限与安全防护机制。

**智能体的所有访问都是严格透传（pass-through）的**，这意味着用户只能查询自己已有权限访问的表。当权限缺失时，它会予以标记，或回退到用户被授权使用的其他数据集。

最后，它为透明而生。与任何系统一样，它也会犯错。它通过在每条答案旁边总结假设与执行步骤来**公开其推理过程**。查询执行时，它会直接链接到底层结果，让用户能够检查原始数据并核实分析的每一步。

## 经验教训

从零开始构建我们的智能体，让我们得到了关于智能体如何行事、在哪里遇到困难、以及什么才能真正让它们在规模化时保持可靠的实践性经验。

#### 经验 #1：**少即是多**

早期，我们把完整的工具集开放给智能体，很快遇到了功能重叠的问题。虽然这种冗余在特定定制场景中可能有用、对人工手动调用的人来说也更容易分辨，但它会让智能体感到困惑。为了减少歧义并提升可靠性，我们限制并合并了某些工具调用。

#### 经验 #2：**引导目标，而非路径**

我们还发现，高度规定性的提示会降低结果质量。虽然许多问题共享大致相同的分析形态，但细节差异足以让僵硬的指令把智能体推上错误的道路。通过转向更高层级的引导、并依靠 GPT‑5 的推理来选择合适的执行路径，智能体变得更稳健，产出了更好的结果。

#### 经验 #3：**语义藏在代码里**

模式与查询历史描述了表的形状与用法，但表的真正语义存在于生成它的代码之中。流水线逻辑捕捉了那些永远不会在 SQL 或元数据中显形的假设、新鲜度保证与业务意图。通过用 Codex 爬取代码库，我们的智能体理解数据集究竟是如何构建的，从而能更好地推理每张表实际包含什么。对于“这里面有什么”与“什么时候可以用它”这类问题，它的回答远比仅凭数仓信号准确得多。

## 同一愿景，新的工具

我们在持续改进我们的智能体：增强它处理模糊问题的能力，用更强的校验提升其可靠性与准确性，并将其更深入地集成到工作流中。我们相信，它应当自然地融入人们已有的工作方式，而不是像一个孤立的工具那样运作。

虽然我们的工具会持续受益于智能体推理、校验与自我纠正方面的底层进步，但我们团队的使命始终如一：在 OpenAI 的数据生态中无缝交付快速、可信的数据分析。
