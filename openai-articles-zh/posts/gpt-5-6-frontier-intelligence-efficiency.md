# GPT‑5.6 如何将前沿智能与前沿效率融为一体

> 原文：[How GPT‑5.6 fuses frontier intelligence with frontier efficiency](https://openai.com/index/gpt-5-6-frontier-intelligence-efficiency/) · OpenAI 博客

我们设计 GPT‑5.6 模型家族，是为了在人们使用我们模型处理的各类任务中[平衡能力与成本](https://openai.com/index/gpt-5-6/)。我们的旗舰模型 GPT‑5.6 Sol 在最大推理力度下，以不到一半的成本在 Artificial Analysis Coding Agent Index 上超越 Claude Fable 5。Terra 以一半的价格在智力基准测试上达到 GPT‑5.5 的水平，而 Luna 是我们最快、最实惠的模型，价格比 Sol 低 80%。为实现这些效率，我们的研究与技术团队在技术栈的每一个主要层面都进行了重大优化。这些改进涵盖我们的模型、推理（我们如何运行模型来生成输出），以及我们的智能体执行框架（agentic harness）——Codex 和 ChatGPT Work 都在使用它。

在过去四年里，随着我们的模型扩展到 10 亿活跃用户和超过 200 万家企业，效率一直是让智能惠及每个人的核心。我们的使命是确保通用人工智能造福全人类。这些年来，我们持续在技术栈中解锁更大程度的优化，以便在成本-智能曲线的每个点上提供表现最好的模型。通过 GPT‑5.6，我们实现了迄今最高的每 token 智能效率——它经过训练，能够[用每个 token 完成更多工作](https://openai.com/index/gpt-5-6/)。在训练中，我们同时优化任务成功率和效率，引导模型以更直接的路径完成任务。

本文将目光越过模型本身，分享我们如何通过技术栈另外两个主要部分的进步来实现效率设计：1) **推理**——通过优化负载均衡、投机解码（speculative decoding）、缓存和内核优化等流程，从同样的硬件中获得更多输出；2) 我们的**智能体执行框架（agentic harness）**——包括更好地管理上下文膨胀、工具使用和重复工作。我们还将分享 GPT‑5.6 Sol 在自主落地其中若干收益方面所扮演的角色。任何孤立的改进看起来可能都有限，但这些收益相互叠加，使我们能够在智能与效率两个前沿上同时交付。

## 用 GPT‑5.6 Sol 加速推理

在一个算力受限、模型需求增长快于产能的世界里，效率是每个系统设计的核心。在我们的推理栈——负责运行训练好的模型以生成响应——中尤其如此。我们的首要目标是用同样的硬件服务更多 token，同时保持用户所期望的智能水平、延迟、可用性和可靠性。

实现这一点需要对整个系统进行优化。一个模型在孤立状态下可以非常高效，但如果请求分配不当、硬件闲置，或者数据搬运拖慢了计算，服务的成本仍然可能很高。每一层的改进都会相互叠加，收益来自路由（请求被发送到哪里）、调度（请求何时被发送）、内核（运行在 GPU 上的软件）、缓存（保存并复用的工作）以及模型实现（GPU 代码的编排方式）等方面的优化。Codex 中的 GPT‑5.6 Sol 在所有这些优化中都发挥了关键作用。

第一个重要的例子是负载均衡。在全球层面，我们根据地理位置、可用容量和加速器类型（运行模型的 GPU 或专用芯片的类型）等因素来路由请求。在集群内部，我们根据负载、上下文长度、缓存可用性和其他请求属性，在模型实例之间分配工作。而在每个实例内部，工作还必须在加速器、模型的子网络和计算核心之间高效切分。Codex 中的 GPT‑5.6 Sol 帮助我们分析生产流量、识别此前被忽视的不均衡来源、测试新的路由策略，并持续调优这些启发式规则。仅这些负载均衡方面的改进，就大幅降低了我们模型的服务成本。

我们还用 GPT‑5.6 Sol 优化了模型的前向传播（forward pass）：把输入转换为下一个 token 预测的计算。即使单个操作都很快，过多的内存搬运、同步和低效的数据布局仍可能让 GPU 闲置。为了避免这种情况，GPT‑5.6 Sol 找出了可以预计算、可以避免或可以并行化的工作。借助 Codex，GPT‑5.6 Sol 自主重写并优化了我们的生产内核——执行构成模型的数学运算的核心代码。这之所以可行，部分原因是我们训练 GPT‑5.6 使其擅长编写和改进 [Triton](https://triton-lang.org/main/index.html) 和 [Gluon](https://triton-lang.org/main/gluon/index.html) 内核——这两种都是由 OpenAI 维护的开源 GPU 编程语言。这些努力，加上 GPT‑5.6 Sol 带来的更广泛的内核进步，将端到端服务成本降低了 20%。我们还大力投入验证工具，例如开源工具 [FpSan](https://triton-lang.org/main/programming-guide/chapter-3/fpsan.html)（浮点检查器，Floating-Point Sanitizer），以帮助验证 GPT‑5.6 Sol 所写内核的正确性。

投机解码是提升速度与效率的另一个抓手。这项技术会让一个较小的草稿（或称「投机者」，speculator）模型与主模型并行运行，由它提出若干 token，供主模型并行验证。当这些提议被接受时，系统可以从主模型的一次前向计算中产出多个输出 token，从而减少昂贵的串行计算量。GPT‑5.6 Sol 通过在其草稿模型的架构上设计并运行数百个实验，改进了自己的草稿模型，测试了规模、结构和特征方面的变化。此外，GPT‑5.6 Sol 还启动并监控了投机者模型的训练过程，在出现问题时自主介入，包括硬件故障和训练不稳定。由此带来的改进将 token 生成效率提升了 15% 以上。

在处理未缓存的输入 token 时，模型会通过一次计算密集的过程构建键值（KV）缓存；在生成输出时，它反复读取并扩展该缓存。服务的最优配置——例如批处理（batching）、分片（sharding）和 KV 管理——在很大程度上取决于工作负载：提示与输出长度、批大小、缓存命中率、查询特征等等。然而，此前的配置空间过于庞大，无法系统地调优，工程师只能依赖粗粒度的启发式方法。借助 Codex 中的 GPT‑5.6 Sol，我们得以分析生产工作负载、生成并评估候选配置，并对每个场景下引擎和模型的配置方式进行超优化。这使得针对特定工作负载的优化达到了一个新的可行水平，从同样的硬件中提取出更多有用的推理。

推理优化是一个持续的反馈循环。我们测量生产行为、识别最大的差距、实施变更，并验证这些变更改善的是整个系统，而不是某个孤立的基准。GPT‑5.6 Sol 和 Codex 加速了这个循环的每一个环节。这意味着我们的团队可以探索更多想法、更快响应不断变化的工作负载，并为用户打造一个延迟更低、容量更大、成本更低的推理栈。

## 我们的智能体执行框架如何精简重复工作

ChatGPT Work 和 Codex 通过一系列模型请求和工具调用来完成复杂任务。在单独一轮中——从用户的请求到最终响应——Codex 可能要检查源代码、搜索部署历史、阅读事故报告、编辑文件并运行测试。每一步都可能需要一次请求。

准备上下文、传输数据、运行推理、调用工具和启动进程都需要时间和算力。如果一个任务需要 30 次模型请求，每次请求多出一秒就会累积起来。提升整体性能意味着减少整个系统中重复的工作，而不只是让模型更快。

*一次用户交互轮次可能包含多次模型与工具迭代。重复区域内的任何成本都可能被支付很多次。*

这些倍增效应影响了我们设计智能体执行框架的方式——它是一个 Rust 编排层，连接我们的模型、工具和用户的环境。接下来，我们将介绍如何通过避免上下文膨胀、加载工具和复用工作来让每次请求更高效。

#### 避免上下文膨胀

随着智能体被授予访问更多工具、技能、插件和对话历史的权限，上下文窗口很容易膨胀。这会增加成本、分散模型的注意力，并引发不必要的推理。执行框架可以通过延迟发现（deferred discovery）来减少这种开销：集成、自定义 MCP 工具、技能和插件只在需要时才会显现。执行框架还会防止单个工具和 MCP 集成意外占用上下文窗口。除非模型请求不同的上限，工具输出默认上限为 10,000 token。

#### 为提示缓存保留精确前缀

如前所述，智能体循环可能在一轮中把相同的指令、对话历史、工具定义和先前结果多次发送给 GPU。处理这些重复输入代价高昂，因此提示缓存（prompt caching）会复用与此前处理过的提示前缀相关联的计算。为了保留该前缀，执行框架将所有对模型可见的历史视为只追加（append-only）：新消息、工具结果和环境更新都添加在末尾，而不是插入到较早的上下文中。工具也以确定的顺序呈现，而审批策略等运行时设置则在执行期间应用，而不是嵌入工具定义中。这一设计选择是 Codex 和 ChatGPT Work 整体提示缓存命中率如此之高的原因之一。

*增量传输改变的是什么跨越网络；提示缓存改变的是模型可以避免重新计算什么。宽度仅为概念示意，额外的压缩层未在图中显示。*

## 跨越智能曲线的效率

我们随 GPT‑5.6 带来的效率收益，是多年来技术栈各层面改进相互叠加的结果，涵盖研究、推理和我们的智能体执行框架。GPT‑5.6 在落地其中许多改进中所扮演的角色，让我们对优化步伐的加速感到乐观。我们将继续在内核优化等领域实现更大的优化，同时对技术栈进行基础性改进。我们期待把这些持续进行的底层改进，以更普及、更具成本效益的智能的形式回馈给我们的用户和客户。
