# 在 API 中推出 GPT‑4.1

> 原文：[Introducing GPT‑4.1 in the API](https://openai.com/index/gpt-4-1/) · OpenAI 博客

今天，我们在 API 中发布三款新模型：GPT‑4.1、GPT‑4.1 mini 和 GPT‑4.1 nano。这些模型在各方面都优于 GPT‑4o 和 GPT‑4o mini，在编程和指令遵循方面有重大提升。它们还拥有更大的上下文窗口——支持多达 100 万 token 的上下文——并且凭借改进的长上下文理解能力，能够更好地利用这些上下文。它们的训练数据截止时间更新至 2024 年 6 月。

GPT‑4.1 在以下行业标准指标上表现卓越：

- **编程**：GPT‑4.1 在 [SWE-bench Verified](https://openai.com/index/introducing-swe-bench-verified/) 上得分 54.6%，比 GPT‑4o 高出 21.4%abs，比 GPT‑4.5 高出 26.6%abs——使其成为编程领域的领先模型。
- **指令遵循**：在衡量指令遵循能力的 [Scale MultiChallenge](https://scale.com/leaderboard/multichallenge) 基准测试上，GPT‑4.1 得分 38.3%，比 GPT‑4o 提高 10.5%abs。
- **长上下文**：在多模态长上下文理解基准测试 [Video-MME](https://video-mme.github.io/home_page.html) 上，GPT‑4.1 创下新的最先进（SOTA）结果——在 long、无字幕（no subtitles）类别中得分 72.0%，比 GPT‑4o 提高 6.7%abs。

虽然基准测试提供了有价值的洞见，但我们在训练这些模型时侧重于真实世界的实用性。与开发者社区的密切协作与合作，使我们能够针对对他们的应用最重要的任务来优化这些模型。

为此，GPT‑4.1 模型家族以更低的成本提供卓越的性能。这些模型在延迟曲线的每个点上都将性能向前推进。

GPT‑4.1 mini 是小模型性能的一次重大飞跃，在许多基准测试中甚至胜过 GPT‑4o。它在智力评测中持平或超过 GPT‑4o，同时将延迟减少近一半、成本降低 83%。

对于要求低延迟的任务，GPT‑4.1 nano 是我们目前最快、最便宜的模型。它以小巧的体积提供卓越性能，拥有 100 万 token 上下文窗口，在 MMLU 上得分 80.1%、GPQA 上得分 50.3%、Aider polyglot 编程上得分 9.8%——甚至高于 GPT‑4o mini。它非常适合分类或自动补全等任务。

指令遵循可靠性和长上下文理解方面的这些改进，也使 GPT‑4.1 系列模型在驱动智能体（agent，即能够代表用户独立完成任务的系统）方面明显更加有效。结合 [Responses API](https://platform.openai.com/docs/api-reference/responses) 等原语，开发者现在可以构建在真实世界软件工程、从大型文档中提取洞见、以最少的手把手引导解决客户请求以及其他复杂任务方面更加有用、更加可靠的智能体。

请注意，GPT‑4.1 将仅通过 API 提供。在 ChatGPT 中，指令遵循、编程和智力方面的许多改进已被逐步纳入 [GPT‑4o 的最新版本](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)，我们将在未来的发布中继续纳入更多改进。

我们还将开始弃用 API 中的 GPT‑4.5 Preview，因为 GPT‑4.1 在许多关键能力上以低得多的成本和延迟提供了更好或相当的性能。GPT‑4.5 Preview 将于三个月后、即 2025 年 7 月 14 日关闭，以便开发者有时间完成迁移。GPT‑4.5 最初作为研究预览[发布](https://openai.com/index/introducing-gpt-4-5/)，旨在探索和试验一个大型、计算密集型的模型，我们从开发者的反馈中学到了很多。你们告诉我们，你们欣赏 GPT‑4.5 的创造力、写作质量、幽默感和细腻之处——我们会把这些特质继续传承到未来的 API 模型中。

下面，我们将拆解 GPT‑4.1 在多个基准测试上的表现，并给出来自 Windsurf、Qodo、Hex、Blue J、Thomson Reuters 和 Carlyle 等 alpha 测试者的实例，展示它在生产环境中处理特定领域任务时的表现。

## 编程

在多种编程任务上，GPT‑4.1 都明显优于 GPT‑4o，包括以智能体方式解决编程任务、前端编程、更少做出无关编辑、可靠地遵循 diff 格式、确保一致的工具使用等等。

在衡量真实世界软件工程技能的 SWE-bench Verified 上，GPT‑4.1 完成了 54.6% 的任务，而 GPT‑4o（2024-11-20）为 33.2%。这反映出模型在探索代码仓库、完成任务以及生成既能运行又能通过测试的代码方面的能力提升。

*在 [SWE-bench Verified](https://openai.com/index/introducing-swe-bench-verified/) 中，模型会得到一个代码仓库和问题描述，必须生成补丁来解决问题。表现高度依赖于所使用的提示和工具。为帮助复现我们的结果并为其提供背景，我们在[此处](https://cookbook.openai.com/examples/gpt4-1_prompting_guide)描述了 GPT‑4.1 的设置。我们的分数未计入 500 道题中 23 道其解答无法在我们的基础设施上运行的题目；如果将这些题保守地计为 0 分，54.6% 的得分将变为 52.1%。*

对于需要在 API 中编辑大文件的开发者，GPT‑4.1 在多种格式下的代码 diff 都可靠得多。GPT‑4.1 在 [Aider 的 polyglot diff 基准测试](https://aider.chat/docs/leaderboards/)上的得分是 GPT‑4o 的两倍以上，甚至比 GPT‑4.5 高出 8%abs。这项评测既衡量跨多种编程语言的编程能力，也衡量模型以 whole 和 diff 格式生成变更的能力。我们专门训练了 GPT‑4.1 来更可靠地遵循 diff 格式，这让开发者只需让模型输出变更的行、而不必重写整个文件，从而节省成本和延迟。要获得最佳的代码 diff 表现，请参阅我们的[提示指南](http://platform.openai.com/docs/guides/text?api-mode=responses#prompting-gpt-4-1-models)。对于偏好重写整个文件的开发者，我们已将 GPT‑4.1 的输出 token 上限提高到 32,768 token（此前 GPT‑4o 为 16,384 token）。我们还建议使用 [Predicted Outputs](https://platform.openai.com/docs/guides/predicted-outputs) 来降低整文件重写的延迟。

*在 Aider 的 polyglot 基准测试中，模型通过编辑源文件来解答来自 [Exercism](https://exercism.org/) 的编程练习，允许重试一次。「whole」格式要求模型重写整个文件，这可能既慢又昂贵。「diff」格式要求模型写出一系列[搜索/替换块](https://aider.chat/docs/more/edit-formats.html)。*

GPT‑4.1 在前端编程方面也大幅超越了 GPT‑4o，能够创建功能更完善、更美观的 Web 应用。在我们的正面对比中，付费的人类评分员有 80% 的时间更偏好 GPT‑4.1 生成的网站。

## 真实世界示例

[**Windsurf**](https://windsurf.com/editor)**：** GPT‑4.1 在 Windsurf 的内部编程基准测试上比 GPT‑4o 高出 60%，该基准与代码变更在首次审查时被接受的频率密切相关。其用户注意到，它在工具调用上的效率提高了 30%，而不必要的编辑重复、或以过窄的增量步骤阅读代码的可能性降低了约 50%。这些改进转化为工程团队更快的迭代和更顺畅的工作流。

[**Qodo**](https://www.qodo.ai/)**：** Qodo 采用受其微调基准启发的方法，让 GPT‑4.1 与其他领先模型在根据 GitHub 拉取请求生成高质量代码评审方面进行了正面对比。在 200 个具有现实意义的真实拉取请求上、使用相同的提示与条件，他们发现 GPT‑4.1 在 [55% 的案例](https://www.qodo.ai/blog/benchmarked-gpt-4-1/)中给出了更好的建议。值得注意的是，他们发现 GPT‑4.1 在精确度（知道何时不提建议）和全面性（在必要时提供详尽分析）两方面都很出色，同时始终聚焦于真正关键的问题。

## 指令遵循

GPT‑4.1 更可靠地遵循指令，我们在多种指令遵循评测中测量到了显著改进。

我们开发了一个指令遵循内部评测，用于跨多个维度、在若干关键指令遵循类别中跟踪模型表现，包括：

- **格式遵循。**提供为模型响应指定自定义格式的指令，例如 XML、YAML、Markdown 等。
- **否定指令。**指定模型应避免的行为。（示例：“不要让用户联系支持团队”）
- **有序指令。**提供一组模型必须按给定顺序遵循的指令。（示例：“先询问用户的姓名，再询问他们的电子邮箱”）
- **内容要求。**输出包含特定信息的内容。（示例：“撰写营养计划时必须包含蛋白质含量”）
- **排序。**以特定方式对输出排序。（示例：“按人口数量对回答排序”）
- **过度自信。**指示模型在所请求的信息不可用或请求不属于给定类别时回答“我不知道”或类似内容。（示例：“如果你不知道答案，请提供支持团队的联系邮箱”）

这些类别源自开发者的反馈——即指令遵循的哪些方面对他们最相关、最重要。在每个类别内，我们划分了简单、中等和困难提示。GPT‑4.1 尤其在困难提示上显著优于 GPT‑4o。

*我们的内部指令遵循评测基于真实的开发者用例与反馈，涵盖不同复杂度的任务，并配有关于格式、详略程度、长度等方面的指令。*

多轮指令遵循对许多开发者至关重要——模型需要在对话深处保持连贯，并记住用户此前告诉它的内容。我们训练 GPT‑4.1 更善于从对话的过往消息中提取信息，从而实现更自然的对话。Scale 的 MultiChallenge 基准是衡量这一能力的有效指标，GPT‑4.1 比 GPT‑4o 高出 10.5%abs。

*在 [MultiChallenge](https://scale.com/leaderboard/multichallenge) 中，模型在多轮对话中接受挑战，需要正确使用此前消息中的四类信息。*

GPT‑4.1 在 IFEval 上得分 87.4%，而 GPT‑4o 为 81.0%。IFEval 使用包含可验证指令的提示（例如指定内容长度，或避免使用某些词语或格式）。

*在 [IFEval](https://arxiv.org/abs/2311.07911) 中，模型必须生成符合各种指令的回答。*

更好的指令遵循让现有应用更可靠，也让此前受制于低可靠性的新应用成为可能。早期测试者指出 GPT‑4.1 可能更为「字面化」，因此我们建议在提示中明确而具体。有关 GPT‑4.1 提示最佳实践的更多内容，请参阅提示指南。

## 真实世界示例

[**Blue J**](https://www.bluej.com/)**：** 在 Blue J 最具挑战性的真实税务场景内部基准上，GPT‑4.1 的准确率比 GPT‑4o 高出 53%。这一准确率的跃升——既是系统性能也是用户满意度的关键——凸显了 GPT‑4.1 对复杂法规的更好理解，以及在长上下文中遵循细微指令的能力。对 Blue J 的用户而言，这意味着更快、更可靠的税务研究，以及更多时间投入高价值的咨询工作。

[**Hex**](https://hex.tech/)**：** GPT‑4.1 在 Hex 最具挑战性的 [SQL 评测集](https://hex.tech/blog/im-sorry-but-those-are-vanity-evals)上带来了接近 2 倍的提升，展示了指令遵循和语义理解方面的显著进步。该模型在从大型、含混的模式中选择正确表时更加可靠——这是一个直接影响总体准确率的上游决策点，而且很难仅靠提示来调优。对 Hex 而言，这带来了人工调试的可测量减少，以及更快通往生产级工作流的路径。

## 长上下文

GPT‑4.1、GPT‑4.1 mini 和 GPT‑4.1 nano 可以处理多达 100 万 token 的上下文——此前的 GPT‑4o 模型为 128,000。100 万 token 相当于整个 React 代码库的 8 份以上，因此长上下文非常适合处理大型代码库或大量长文档。

我们训练 GPT‑4.1 在完整的 100 万上下文长度内可靠地关注信息。我们还训练它在长、短上下文长度下都比 GPT‑4o 可靠得多地注意到相关文本并忽略干扰项。长上下文理解是法律、编程、客户支持及许多其他领域应用的一项关键能力。

下面，我们展示 GPT‑4.1 检索隐藏在上下文窗口中不同位置的小块信息（「针」，needle）的能力。GPT‑4.1 在所有位置、所有上下文长度下都能始终如一地准确检索到「针」，直到 100 万 token。无论相关细节在输入中的位置如何，它都能有效地提取出与当前任务相关的细节。

*在我们的内部「大海捞针」评测中，GPT‑4.1、GPT‑4.1 mini 和 GPT 4.1 nano 都能在直至 1M 的上下文中所有位置检索到「针」。*

然而，很少有真实世界任务像检索单一、明显的「针」那样简单直接。我们发现，用户常常需要我们的模型检索并理解多条信息，并理解这些信息彼此之间的关系。为展示这一能力，我们正在开源一个新的评测：OpenAI-MRCR（多轮共指，Multi-Round Coreference）。

OpenAI-MRCR 测试模型找出并区分多个深藏于上下文中的「针」的能力。该评测由用户与助手之间的多轮合成对话组成，用户请求就某个主题写一段文字，例如“写一首关于貘的诗”或“写一篇关于岩石的博客文章”。然后我们在整个上下文中插入两、四或八个完全相同的请求。模型随后必须检索出与特定实例对应的响应（例如“给我第三首关于貘的诗”）。

挑战在于这些请求与上下文其余部分之间的相似性——模型很容易被细微差异误导，例如是一篇关于貘的短篇小说而非诗歌，或是一首关于青蛙而非貘的诗。我们发现，GPT‑4.1 在最高 128K token 的上下文长度上优于 GPT‑4o，并且即便到 100 万 token 也保持强劲表现。

但这项任务依然困难——即使对先进的推理模型也是如此。我们分享该[评测数据集](https://huggingface.co/datasets/openai/mrcr)，以鼓励在真实世界长上下文检索方面开展进一步工作。

*在 [OpenAI-MRCR](https://huggingface.co/datasets/openai/mrcr) 中，模型必须回答一个需要在散布于干扰项之间的 2、4 或 8 个用户提示之间消歧的问题。*

我们还在发布 [Graphwalks](https://huggingface.co/datasets/openai/graphwalks)，一个用于评估多跳长上下文推理的数据集。开发者的许多长上下文用例需要在上下文内进行多次逻辑跳转，例如编写代码时在多个文件之间跳转，或回答复杂法律问题时交叉引用文档。

模型（甚至人类）理论上可以通过对提示做一次通读来解决 OpenAI-MRCR 问题，但 Graphwalks 的设计要求在上下文的多个位置之间进行推理，无法按顺序逐步解决。

Graphwalks 用一个由十六进制哈希组成的有向图填满上下文窗口，然后要求模型从图中一个随机节点出发执行广度优先搜索（BFS）。我们随后要求它返回某一深度上的所有节点。GPT‑4.1 在该基准上达到 61.7% 的准确率，与 o1 持平，并轻松胜过 GPT‑4o。

*在 [Graphwalks](https://huggingface.co/datasets/openai/graphwalks) 中，模型被要求从一个大图中的随机节点出发执行广度优先搜索。*

基准测试并不能说明全部情况，因此我们与 alpha 合作伙伴一起，在他们真实世界的长上下文任务上测试了 GPT‑4.1 的表现。

## 真实世界示例

[**Thomson Reuters：**](https://blogs.thomsonreuters.com/en-us/innovation/legal-ai-benchmarking-evaluating-long-context-performance-for-llms) Thomson Reuters 用 CoCounsel——他们面向法律工作的专业级 AI 助手——测试了 GPT‑4.1。与 GPT‑4o 相比，在内部长上下文基准上使用 GPT‑4.1 时，他们将多文档审阅准确率提升了 17%——这是衡量 CoCounsel 处理涉及多份长文档的复杂法律工作流能力的关键指标。他们特别发现，该模型在跨来源保持上下文、并准确识别文档之间细微关系（例如相互冲突的条款或额外的补充背景）方面高度可靠——这些任务对法律分析和决策至关重要。

[**Carlyle**](https://www.carlyle.com/)**：** Carlyle 使用 GPT‑4.1 从多份长文档——包括 PDF、Excel 文件和其他复杂格式——中准确提取细粒度的财务数据。根据他们的内部评估，它在从数据密集的超大文档中进行检索时的表现好出 50%，并且是第一个成功克服其他现有模型关键局限的模型，这些局限包括「大海捞针」式检索、「迷失在中间」错误以及跨文档的多跳推理。

除了模型性能和准确率之外，开发者还需要响应迅速的模型，以跟上并满足用户的需求。我们改进了推理栈以缩短首 token 时间（time to first token），而借助提示缓存（prompt caching），你还能进一步削减延迟并节省成本。在我们的初步测试中，GPT‑4.1 在 128,000 token 上下文下的首 token 延迟约为 15 秒，100 万 token 上下文下约为 1 分钟。GPT‑4.1 mini 和 nano 更快，例如 GPT‑4.1 nano 在 128,000 输入 token 的查询中，多数情况下能在 5 秒内返回首个 token。

## 视觉

GPT‑4.1 家族在图像理解方面极为出色，其中 GPT‑4.1 mini 尤其代表了一次重大飞跃，经常在图像基准测试中胜过 GPT‑4o。

*在 [MMMU](https://mmmu-benchmark.github.io/) 中，模型回答包含图表、示意图、地图等的问题。（注：即使不含图像，许多答案仍可根据上下文推断或猜测出来。）*

## 定价

GPT‑4.1、GPT‑4.1 mini 和 GPT‑4.1 nano 现已向所有开发者开放。

通过对推理系统的效率改进，我们得以将 GPT‑4.1 系列的价格调低。对于中位查询，GPT‑4.1 比 GPT‑4o 便宜 26%，而 GPT‑4.1 nano 是我们有史以来最便宜、最快的模型。对于反复传递相同上下文的查询，我们将这些新模型的提示缓存折扣提高到 75%（此前为 50%）。最后，我们提供的长上下文请求在标准每 token 费用之外不收取任何额外费用。

## 结论

GPT‑4.1 是 AI 实际应用中的一个重大进步。通过紧密聚焦开发者的真实世界需求——从编程到指令遵循再到长上下文理解——这些模型为构建智能系统和复杂的智能体应用开启了新的可能。开发者社区的创造力不断激励着我们，我们期待看到你用 GPT‑4.1 构建出什么。
