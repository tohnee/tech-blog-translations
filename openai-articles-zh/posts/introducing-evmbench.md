# EVMbench 亮相

> 原文：[Introducing EVMbench](https://openai.com/index/introducing-evmbench/) · OpenAI 博客

智能合约日常守护着价值超过 1000 亿美元的开源加密资产。随着 AI 智能体在阅读、编写和执行代码方面的能力不断提升，在具有经济意义的环境中衡量它们的能力变得越来越重要，同时也要鼓励以防御性方式使用 AI 系统来审计并加固已部署的合约。

我们与 [Paradigm](https://www.paradigm.xyz) 合作，推出 EVMbench——一个评估 AI 智能体检测、修补和利用高危智能合约漏洞能力的基准测试。EVMbench 收录了来自 40 次审计的 117 个精选漏洞，其中大多数源自公开的代码审计竞赛。EVMbench 还包含若干取自 [Tempo](https://tempo.xyz/) 区块链安全审计过程的漏洞场景，Tempo 是一条专为通过稳定币实现高吞吐、低成本支付而打造的 L1 区块链。这些场景将基准测试延伸到面向支付的智能合约代码——我们预计智能体稳定币支付将在这一领域不断增长——并帮助该基准扎根于一个新兴且具有实际重要性的领域。

在创建任务环境时，凡是已有概念验证（proof-of-concept）利用测试和部署脚本的，我们都加以改造，没有的则由我们手动编写。对于 **'patch'** 模式，我们确保漏洞确实可被利用，并且能够在不引入会导致编译失败的变更的前提下得到缓解——这类变更会破坏我们的测试设置。对于 **'exploit'** 模式，我们编写了自定义评分器（grader），并对环境进行红队测试，以发现并封堵智能体可能用来欺骗评分器的手段。除了借助 Paradigm 提供的领域专业知识对任务进行质量控制之外，我们还使用自动化任务审计智能体来帮助提高环境的可靠性。

EVMbench 评估三种能力模式：

- **Detect（检测）**：智能体审计一个智能合约代码仓库，并依据其对真实漏洞（ground-truth vulnerabilities）的召回率及相关审计奖励进行评分。
- **Patch（修补）**：智能体修改存在漏洞的合约，必须在消除可利用性的同时保留预期功能，并通过自动化测试和漏洞利用检查加以验证。
- **Exploit（利用）**：智能体在沙箱化的区块链环境中对已部署的合约执行端到端的资金窃取攻击，评分通过交易重放和链上验证以程序化方式完成。

为支持客观、可复现的评估，我们开发了一个基于 Rust 的执行框架（harness），负责部署合约、以确定性方式重放智能体交易，并限制不安全的 RPC 方法。Exploit 任务在隔离的本地 Anvil 环境中运行，而非在真实网络上；所涉及的漏洞均为已公开记录的历史漏洞。

我们在全部三种模式下评估了前沿智能体。在 **'exploit'** 模式下，通过 Codex CLI 运行的 GPT‑5.3‑Codex 取得 71.0% 的分数。相比 GPT‑5 等前代模型，这是显著提升——GPT‑5 仅在六个多月前发布，得分为 33.3%。检测召回率和修补成功率仍低于全覆盖水平，因为相当大一部分漏洞对智能体而言仍然难以发现和修复。

EVMbench 还揭示了模型在不同任务上行为方式的有趣差异。智能体在 exploit 设定下表现最好，因为目标非常明确：持续迭代，直到资金被完全取走。相比之下，detect 和 patch 任务上的表现较弱。在 **'detect'** 中，智能体有时在发现单个问题后就停止，而不是对代码库进行彻底审计。在 **'patch'** 中，如何在移除隐蔽漏洞的同时保持完整功能仍然充满挑战。

## 局限性

EVMbench 并不能代表真实世界智能合约安全任务的全部难度。其中收录的漏洞取自 Code4rena 审计竞赛。虽然这些漏洞真实且高危，但许多被大量部署、广泛使用的加密合约会接受严格得多的审视，利用难度可能更高。

我们的评分系统健壮但并非完美。在 **'detect'** 模式中，我们检查智能体是否找到了与人类审计员所识别的相同漏洞。如果智能体还发现了其他问题，我们目前没有可靠的方法来判断这些问题究竟是人类遗漏的真实漏洞，还是误报。

**'exploit'** 设定也存在结构性限制。交易在评分容器中按顺序重放，因此依赖精确时序机制的行为不在覆盖范围内。链状态是一个干净的本地 Anvil 实例，而非主网分叉，且我们目前仅支持单链环境。在某些情况下，这意味着必须使用模拟合约（mock contracts）来替代主网部署。

## 为什么这件事很重要

智能合约守护着数十亿美元的资产，而 AI 智能体很可能给攻击者和防御者双方都带来变革性影响。在这个领域衡量模型能力，有助于追踪新兴的网络风险，并凸显以防御性方式使用 AI 系统来审计和加固已部署合约的重要性。

EVMbench 既是一个测量工具，也是一份行动号召。随着智能体能力不断提升，开发者和安全研究人员将 AI 辅助审计纳入自己的工作流程变得越来越重要。

近几个月来，我们看到模型在网络安全任务上的表现取得了实质性提升，惠及开发者和安全专业人员。与此同时，我们一直在[着手准备强化的网络安全防护机制](https://openai.com/index/strengthening-cyber-resilience/)，以支持防御性用途和更广泛的生态系统韧性。

由于网络安全本质上具有双重用途属性，我们采取基于证据、持续迭代的方法：加速防御者发现和修复漏洞的能力，同时拖慢滥用行为。我们的缓解措施包括安全训练、自动化监控、高级能力的[可信访问](https://openai.com/index/trusted-access-for-cyber/)（trusted access），以及包含威胁情报在内的强制执行流程。

我们正在投资生态系统层面的安全防护措施，例如扩大 [Aardvark](https://openai.com/index/introducing-aardvark/)（我们的安全研究智能体）私测（private beta）的覆盖范围，并与开源维护者合作，为广泛使用的项目提供免费的代码库扫描。

在 2023 年启动的网络安全资助计划（Cybersecurity Grant Program）基础上，我们还承诺投入 1000 万美元的 API 额度，以借助我们最强大的模型加速网络防御，尤其面向开源软件和关键基础设施系统。从事善意安全研究的组织可以通过我们的[网络安全资助计划（Cybersecurity Grant Program）](https://openai.com/form/cybersecurity-grant-program/)申请 API 额度和支持。

我们公开 EVMbench 的任务、工具和评估框架，以支持对新兴 AI 网络能力进行测量与管控的持续研究。
