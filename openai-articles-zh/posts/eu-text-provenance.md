# 我们对欧盟文本溯源规则的应对方式

> 原文：[Our approach to EU text provenance rules](https://openai.com/index/eu-text-provenance/) · OpenAI 博客

[内容溯源](/index/advancing-content-provenance/)帮助人们了解内容来自哪里、是如何创作或编辑的，以及其中是否包含与我们的模型相关的信号。我们已经公开发布了用于识别由我们模型生成的图像和音频的工具。今天，我们分享针对欧盟《人工智能法案》（EU AI Act）的文本水印应对方案，以及它如何融入我们更广泛的工作。

欧盟《人工智能法案》要求生成式 AI 提供方以机器可读的方式标识其生成的文本。文本水印与检测仍处于早期阶段，存在显著局限，围绕其益处与负责任使用的看法也仍在发展。我们的分阶段方案既反映了欧盟《人工智能法案》的要求，也反映了这项技术的局限，重点在于保持透明度——让人们清楚文本水印能说明什么、不能说明什么：

- 从今天起，全球的 API 客户可以对特定模型选择启用文本水印。API 中文本水印将默认保持关闭。
- 未来几周内，我们将为欧盟境内符合条件的 ChatGPT 与 Codex 文本输出添加不可见水印。
- 我们将开放文本水印检测器的访问申请。访问权限初期仅限于经批准的研究人员和专家组织，他们可以帮助我们评估并改进这项技术。

  - 以上仅适用于文本溯源——我们针对音频与图像的验证工具，包括 [openai.com/verify](https://openai.com/verify) 网页工具与我们的 [Content Provenance API](https://developers.openai.com/api/docs/guides/content-provenance)，仍将向希望了解某张图像或某个音频文件是否由我们系统生成的组织公开开放。

## 我们的水印技术如何工作、性能如何

我们的文本水印技术 textGrain 会在模型的用词选择中加入一个不可见的统计信号。我们的检测器寻找这一信号，以判断一段文字中是否包含 OpenAI 水印。关于 textGrain 工作原理的更多细节见我们的[技术报告](https://cdn.openai.com/pdf/e9508624-d767-41b6-a26d-e34ca798ada6/textgrain-entropy-calibrated-watermarking-for-language-model-text.pdf)，该报告将在未来几周内补充更多细节。我们还计划以开源方式提供这项技术，让其他人可以在其基础上继续开发。

在我们的评测中，textGrain 达到或超过了我们测试的其他方案的性能，包括面向文本的 SynthID。即便如此，理想条件下的出色表现并不能保证日常使用中的可靠检测。

检测器可能犯两类错误：在没有水印时报告存在水印——即误报（false positive）；或者漏掉确实存在的水印——即漏报（false negative）。我们下面的评测展示了其中一些挑战：

- **更短或约束更强的文本更难检测。** 在目标误报率为 1% 时，对于心理学等内容，我们的检测器在 200 token 段落中识别出水印的比例约为 80%，而在 400 token 段落中约为 95%。对于数学这类用词灵活性较低的内容，检测率则明显更低。
- **编辑会削弱水印。** 在对 400 token 段落的评测中，将 10% 的词语替换为同义词会使检测率从约 92% 降至 66%；替换 25% 的词语则使其降至 17%。

这些局限性促成了我们的决定：初期仅向经批准的研究人员和专家组织提供检测器访问权限，他们可以帮助我们评估其可靠性与负责任的使用方式。

### 水印对输出质量的影响

在我们用于评估最新前沿模型 Astra 的各项基准测试中，未观察到加水印与否之间存在有意义的性能差异。

## 文本水印无法告诉你什么

文本水印只能提供关于我们的系统在某段文字中所起作用的有限信号。理解从检测结果中能得出什么结论、不能得出什么结论，这一点非常重要。

- **水印无法衡量人的贡献。** 它可以表明某个 OpenAI 系统生成或处理了段落的一部分，但无法表明其中投入了多少人类判断、编辑或创造力。
- **水印不能确立所有权或责任。** 它无法确定文本归谁所有、其使用是否合法、是否需要披露，以及谁对其负责。
- **水印无法识别用户。** 它不会将任何个人、组织、账户、提示词（prompt）或对话与文本关联起来。
- **水印无法验证准确性。** 它不会告诉你一段文字是否真实、是否具有误导性、是否有害，或是否在正确的语境中呈现。
- **未检测到水印并不证明是人工创作。** 使用 OpenAI 工具生成的文本可能因过短、经过编辑或经过翻译而无法可靠检测。它也可能来自不支持的模型、产生于水印技术推出之前，或由其他公司的工具生成。

## 我们的下一步

- **在欧盟推出文本水印。** 未来几周内，我们将仅为欧盟境内所有套餐中符合条件的 ChatGPT 与 Codex 用户引入文本水印。发布时我们不会将文本水印设为全球默认。这种区域性做法为我们留出了从真实使用与反馈中学习的空间。
- **为 API 客户提供选择启用的水印。** 从今天起，全球的 API 客户可以对特定模型选择启用带水印的文本输出。这让客户能够自行决定水印如何契合其透明度义务以及他们为用户提供的产品体验。我们也在与云合作伙伴合作，在未来几周内让通过其服务访问的 OpenAI 模型输出同样可以使用水印。
- **向研究人员与专家组织提供检测器访问权限。** 经批准的研究人员和专家组织可从今天起[提交申请](/form/content-provenance-api/)。依照该[行为准则](https://digital-strategy.ec.europa.eu/en/policies/code-practice-ai-generated-content)（Code of Practice），访问权限初期将逐案授予，以支持文本溯源的评估与改进。该工具只会报告是否检测到 OpenAI 水印，不会识别用户，也不会泄露其提示词或对话内容。鉴于漏检与误报的风险，发布时我们不会将其向公众开放。

随着技术、标准与证据的发展，我们预计会对这一方案的每个部分进行重新审视。

## 我们在内容溯源方面更广泛的方案

任何单一的溯源技术都不足以独立发挥作用，因此我们采取分层方法，结合开放标准、持久水印与验证工具。

我们为受支持的图像输出添加 Content Credentials，符合 [C2PA 一致性标准](https://c2pa.org/conformance/)，在受支持的图像和音频中嵌入不可见的 [SynthID](https://deepmind.google/models/synthid/) 水印，并通过 [openai.com/verify](https://openai.com/verify) 与我们的 [Content Provenance API](https://developers.openai.com/api/docs/guides/content-provenance) 提供图像与音频验证。这些技术互为补充：Content Credentials 可以记录文件的来源与历史，而不可见水印可以在元数据被移除时保留信号。

正如我们在[选举安全防护工作](/index/election-safeguards-2026/)中所描述的，溯源可以帮助人们与平台评估可能具有误导性的 AI 生成内容，包括深度伪造。我们将这些信号与政策、滥用检测、举报、调查与执行措施相配合，并与研究人员、标准组织、平台和公民社会合作，让溯源在整个生态系统中发挥更大作用。

将溯源扩展到文本，需要考虑文本被改写、翻译或编辑的容易程度。正如我们在[6 月](/index/supporting-eu-trustworthy-ai-ecosystem/)所讨论的，我们的方案必须反映当前技术的实际局限。我们将继续改进检测技术，研究水印在编辑与翻译下的存续能力，并探索更有意义地区分 AI 辅助与 AI 创作的方式。我们会随着证据、标准与监管要求的发展调整方案，并在认为检测结果能够被负责任地解读时扩大检测器的访问范围。
