# Qwen3 技术报告

> 原文：[Qwen3 Technical Report](https://arxiv.org/abs/2505.09388) · Qwen 团队 arXiv

Qwen 团队

###### 摘要

在本工作中，我们发布 Qwen3，即 Qwen 模型家族的最新版本。Qwen3 包含一系列大语言模型（LLM），旨在提升性能、效率与多语言能力。Qwen3 系列同时涵盖稠密（dense）与专家混合（MoE）两种架构，参数规模从 0.6B 到 235B 不等。Qwen3 的一项关键创新是将思考模式（面向复杂的多步推理）与非思考模式（面向快速的、上下文驱动的响应）整合进统一框架。这消除了在不同模型之间来回切换的需要——例如对话优化模型（如 GPT-4o）与专用推理模型（如 QwQ-32B）——并支持基于用户查询或聊天模板动态切换模式。同时，Qwen3 引入了思考预算机制，允许用户在推理过程中自适应地分配计算资源，从而依据任务复杂度在延迟与性能之间取得平衡。此外，通过利用旗舰模型的知识，我们显著降低了构建较小规模模型所需的计算资源，同时确保其极具竞争力的性能。实证评估表明，Qwen3 在多种基准测试上取得最先进成果，涵盖代码生成、数学推理、智能体任务等，足以与更大的 MoE 模型及专有模型竞争。与前代 Qwen2.5 相比，Qwen3 将多语言支持从 29 种语言和方言扩展至 119 种，通过更强的跨语言理解与生成能力提升了全球可及性。为促进可复现性以及社区驱动的研究与开发，所有 Qwen3 模型均在 Apache 2.0 许可下公开可得。

## 1 引言

对通用人工智能（AGI）或超级人工智能（ASI）的追求长期以来都是人类的目标。大型基础模型的最新进展，例如 GPT-4o（[OpenAI, 2024](#bib.bib41)）、Claude 3.7（[Anthropic, 2025](#bib.bib5)）、Gemini 2.5（[DeepMind, 2025](#bib.bib16)）、DeepSeek-V3（[Liu et al., 2024a](#bib.bib36)）、Llama-4（[Meta-AI, 2025](#bib.bib40)）以及 Qwen2.5（[Yang et al., 2024b](#bib.bib70)），展现了朝着这一目标的显著进步。这些模型在覆盖多样领域与任务、规模达数万亿 token 的数据集上训练，有效地将人类的知识与能力蒸馏进其参数之中。此外，推理模型的最新发展（经由强化学习优化）凸显了基础模型增强推理时扩展（inference-time scaling）、达到更高智能水平的潜力，例如 o3（[OpenAI, 2025](#bib.bib44)）、DeepSeek-R1（[Guo et al., 2025](#bib.bib23)）。尽管大多数最先进模型仍为专有模型，开源社区的快速成长已显著缩小了开放权重模型与闭源模型之间的性能差距。值得注意的是，越来越多的顶级模型（[Meta-AI, 2025](#bib.bib40)；[Liu et al., 2024a](#bib.bib36)；[Guo et al., 2025](#bib.bib23)；[Yang et al., 2024b](#bib.bib70)）如今正以开源形式发布，推动着人工智能领域更广泛的研究与创新。

在本工作中，我们介绍 Qwen3——我们基础模型家族 Qwen 的最新系列。Qwen3 是一组开放权重的大语言模型（LLM），在广泛的任务与领域中取得最先进性能。我们同时发布了稠密与专家混合（MoE）模型，参数量从 0.6B 到 235B 不等，以满足不同下游应用的需求。值得注意的是，旗舰模型 Qwen3-235B-A22B 是一个 MoE 模型，共有 235B 参数，每个 token 激活 22B。这一设计兼顾了高性能与高效推理。

Qwen3 引入了若干关键进展以增强其功能与易用性。首先，它将两种不同的运行模式——思考模式与非思考模式——整合进单一模型。这使得用户无需在不同模型之间切换，例如从 Qwen2.5 切换到 QwQ（[Qwen Team, 2024](#bib.bib49)）。这种灵活性确保开发者与用户能够高效地调整模型行为以适应特定任务。此外，Qwen3 引入了思考预算（thinking budget），让用户能够细粒度地控制模型在执行任务时所投入的推理努力程度。这一能力对于计算资源与性能的优化至关重要，可使模型的思考行为契合真实应用中复杂度各异的需求。再者，Qwen3 在覆盖多达 119 种语言和方言、总计 36 万亿 token 的数据上完成预训练，有效增强了其多语言能力。这种更广泛的语言支持放大了其在全球用例与国际应用中的部署潜力。这些进展共同确立了 Qwen3 作为前沿开源大语言模型家族的地位，能够有效应对跨领域、跨语言的复杂任务。

Qwen3 的预训练过程使用了约 36 万亿 token 的大规模数据集，并经过精心整理以确保语言与领域的多样性。为高效扩充训练数据，我们采用多模态方法：对 Qwen2.5-VL（[Bai et al., 2025](#bib.bib8)）进行微调，用于从海量 PDF 文档中提取文本。我们还使用领域专用模型生成合成数据：用 Qwen2.5-Math（[Yang et al., 2024c](#bib.bib71)）生成数学内容，用 Qwen2.5-Coder（[Hui et al., 2024](#bib.bib29)）生成代码相关数据。预训练过程遵循三阶段策略。第一阶段，模型在约 30 万亿 token 上训练，以构建扎实的通用知识基础。第二阶段，进一步在知识密集型数据上训练，以增强科学、技术、工程与数学（STEM）以及编程等方向的推理能力。最后，第三阶段在长上下文数据上训练，将最大上下文长度从 4,096 扩展到 32,768 个 token。

为了让基础模型更好地对齐人类偏好与下游应用，我们采用多阶段后训练方法，同时赋能思考（推理）与非思考两种模式。在前两个阶段，我们通过长思维链（long CoT）冷启动微调以及聚焦数学与编程任务的强化学习，着力培养强大的推理能力。在后两个阶段，我们将带推理路径与不带推理路径的数据合并为统一数据集以进一步微调，使模型能够有效处理两类输入，随后施加通用领域强化学习，以提升其在广泛下游任务上的表现。对于较小的模型，我们采用强到弱蒸馏（Strong-to-Weak Distillation），利用来自更大模型的离策略（off-policy）与在策略（on-policy）知识迁移来增强其能力。从先进教师模型进行蒸馏，在性能与训练效率上均显著优于强化学习。

我们在覆盖多任务与多领域的一整套基准上评估了模型的预训练版与后训练版。实验结果表明，我们的基础预训练模型取得了最先进的性能。后训练模型无论处于思考模式还是非思考模式，均可与 o1、o3-mini、DeepSeek-V3 等领先的专有模型及大型专家混合（MoE）模型相竞争。值得注意的是，我们的模型在编程、数学与智能体相关任务上表现卓越。例如，旗舰模型 Qwen3-235B-A22B 在 AIME'24 上取得 85.7、在 AIME'25 上取得 81.5（[AIME, 2025](#bib.bib2)），在 LiveCodeBench v5（[Jain et al., 2024](#bib.bib30)）上取得 70.7，在 CodeForces 上取得 2,056 的评分，在 BFCL v3（[Yan et al., 2024](#bib.bib68)）上取得 70.8。此外，Qwen3 系列中的其他模型相对于其规模也表现出强劲性能。而且我们观察到，增大思考 token 的预算会带来模型在各种任务上的一致提升。

在接下来的章节中，我们将描述模型架构的设计、提供训练流程的细节、给出预训练与后训练模型的实验结果，最后总结关键发现并展望未来的研究方向，以此作为本技术报告的收尾。

## 2 架构

Qwen3 系列包括 6 个稠密模型，即 Qwen3-0.6B、Qwen3-1.7B、Qwen3-4B、Qwen3-8B、Qwen3-14B 与 Qwen3-32B，以及 2 个 MoE 模型：Qwen3-30B-A3B 和 Qwen3-235B-A22B。旗舰模型 Qwen3-235B-A22B 总参数量为 235B，激活参数量为 22B。下面我们详述 Qwen3 模型的架构。

Qwen3 稠密模型的架构与 Qwen2.5（[Yang et al., 2024b](#bib.bib70)）类似，包括分组查询注意力（GQA，[Ainslie et al., 2023](#bib.bib3)）、SwiGLU（[Dauphin et al., 2017](#bib.bib15)）、旋转位置编码（RoPE，[Su et al., 2024](#bib.bib57)）以及带预归一化的 RMSNorm（[Jiang et al., 2023](#bib.bib31)）。此外，我们移除了 Qwen2（[Yang et al., 2024a](#bib.bib69)）中使用的 QKV 偏置，并在注意力机制中引入 QK-Norm（[Dehghani et al., 2023](#bib.bib17)），以确保 Qwen3 训练的稳定性。模型架构的关键信息见表 1。

Qwen3 MoE 模型与 Qwen3 稠密模型共享相同的基础架构。模型架构的关键信息见表 2。我们沿袭 Qwen2.5-MoE（[Yang et al., 2024b](#bib.bib70)），实现了细粒度专家切分（[Dai et al., 2024](#bib.bib14)）。Qwen3 MoE 模型共有 128 个专家，每个 token 激活 8 个专家。与 Qwen2.5-MoE 不同，Qwen3-MoE 的设计不包含共享专家。此外，我们采用全局批次的负载均衡损失（[Qiu et al., 2025](#bib.bib47)）以促进专家专门化。这些架构与训练上的创新为模型在下游任务上的表现带来了显著提升。

Qwen3 模型使用 Qwen 的分词器（[Bai et al., 2023](#bib.bib7)），它实现了字节级字节对编码（BBPE，[Brown et al., 2020](#bib.bib10)；[Wang et al., 2020](#bib.bib60)；[Sennrich et al., 2016](#bib.bib53)），词表大小为 151,669。

## 3 预训练

在本节中，我们描述预训练数据的构建、预训练方法的细节，并给出基础模型在标准基准上的评测结果。

### 3.1 预训练数据

与 Qwen2.5（[Yang et al., 2024b](#bib.bib70)）相比，我们显著扩充了训练数据的规模与多样性。具体而言，我们收集了两倍于以往的预训练 token——覆盖的语言数量达到三倍。所有 Qwen3 模型都在一个大规模、多样化的数据集上训练，该数据集包含 119 种语言和方言，总计 36 万亿 token。数据集包含多个领域的高质量内容，如编程、STEM（科学、技术、工程、数学）、推理任务、书籍、多语言文本与合成数据。

为进一步扩充预训练语料，我们首先使用 Qwen2.5-VL 模型（[Bai et al., 2025](#bib.bib8)）对大量类 PDF 文档执行文本识别，再用 Qwen2.5 模型（[Yang et al., 2024b](#bib.bib70)）对识别文本加以精修，从而提升其质量。通过这一两步流程，我们获得了额外的一批高质量文本 token，总量达数万亿。此外，我们使用 Qwen2.5（[Yang et al., 2024b](#bib.bib70)）、Qwen2.5-Math（[Yang et al., 2024c](#bib.bib71)）与 Qwen2.5-Coder（[Hui et al., 2024](#bib.bib29)）模型合成了数万亿不同格式的文本 token，包括教科书、问答、指令与代码片段，覆盖数十个领域。最后，我们通过纳入更多多语言数据、引入更多语言来进一步扩展预训练语料。与 Qwen2.5 所用的预训练数据相比，支持的语言数量从 29 显著增加到 119，增强了模型的语言覆盖面与跨语言能力。

我们开发了一套多语言数据标注系统，旨在同时提升训练数据的质量与多样性。该系统已被应用于我们的大规模预训练数据集，从教育价值、领域、科目、安全性等多个维度对超过 30 万亿 token 进行了标注。这些细粒度标注支持更有效的数据过滤与组合。与以往在数据源或领域层面优化数据配比的研究（[Xie et al., 2023](#bib.bib66)；[Fan et al., 2023](#bib.bib20)；[Liu et al., 2024b](#bib.bib38)）不同，我们的方法借助细粒度数据标签，通过对小型代理模型的大量消融实验，在实例层面优化数据配比。

### 3.2 预训练阶段

Qwen3 模型通过三阶段流程进行预训练：

1. 通用阶段（S1）：在第一个预训练阶段，所有 Qwen3 模型在超过 30 万亿 token 上以 4,096 token 的序列长度训练。在此阶段，模型在语言能力与通用世界知识上完成充分预训练，训练数据覆盖 119 种语言和方言。

2. 推理阶段（S2）：为进一步提升推理能力，我们通过提高 STEM、编程、推理与合成数据的比例来优化该阶段的预训练语料。模型以 4,096 token 的序列长度在约 5T 更高质量的 token 上继续预训练。我们还在此阶段加快了学习率衰减。

3. 长上下文阶段：在最后一个预训练阶段，我们收集高质量长上下文语料以扩展 Qwen3 模型的上下文长度。所有模型都以 32,768 token 的序列长度在数千亿 token 上预训练。长上下文语料中 75% 的文本长度在 16,384 到 32,768 token 之间，25% 的文本长度在 4,096 到 16,384 之间。沿袭 Qwen2.5（[Yang et al., 2024b](#bib.bib70)），我们使用 ABF 技术（[Xiong et al., 2023](#bib.bib67)）将 RoPE 的基础频率从 10,000 提升到 1,000,000。同时，我们引入 YARN（[Peng et al., 2023](#bib.bib46)）与双块注意力（DCA，[An et al., 2024](#bib.bib4)），在推理时实现四倍的序列长度容量提升。

与 Qwen2.5（[Yang et al., 2024b](#bib.bib70)）类似，我们基于上述三个预训练阶段制定了用于预测最优超参数（如学习率调度器与批大小）的缩放定律。通过大量实验，我们系统研究了模型架构、训练数据、训练阶段与最优训练超参数之间的关系。最终，我们为每个稠密或 MoE 模型设定了预测得到的最优学习率与批大小策略。

### 3.3 预训练评测

我们对 Qwen3 系列的基础语言模型进行了全面评测。基础模型的评测主要聚焦于通用知识、推理、数学、科学知识、编程与多语言能力方面的表现。用于预训练基础模型的评测数据集包括 15 个基准：

- 通用任务：MMLU（[Hendrycks et al., 2021a](#bib.bib25)）（5-shot）、MMLU-Pro（[Wang et al., 2024](#bib.bib62)）（5-shot，CoT）、MMLU-redux（[Gema et al., 2024](#bib.bib21)）（5-shot）、BBH（[Suzgun et al., 2023](#bib.bib58)）（3-shot，CoT）、SuperGPQA（[Du et al., 2025](#bib.bib18)）（5-shot，CoT）。

- 数学与 STEM 任务：GPQA（[Rein et al., 2023](#bib.bib51)）（5-shot，CoT）、GSM8K（[Cobbe et al., 2021](#bib.bib13)）（4-shot，CoT）、MATH（[Hendrycks et al., 2021b](#bib.bib26)）（4-shot，CoT）。

- 编程任务：EvalPlus（[Liu et al., 2023a](#bib.bib37)）（0-shot；取 HumanEval（[Chen et al., 2021](#bib.bib12)）、MBPP（[Austin et al., 2021](#bib.bib6)）、Humaneval+、MBPP+（[Liu et al., 2023a](#bib.bib37)）的平均值）、MultiPL-E（[Cassano et al., 2023](#bib.bib11)）（0-shot；Python、C++、JAVA、PHP、TypeScript、C#、Bash、JavaScript）、MBPP-3shot（[Austin et al., 2021](#bib.bib6)）、CRUXEval 的 CRUX-O（1-shot）（[Gu et al., 2024](#bib.bib22)）。

- 多语言任务：MGSM（[Shi et al., 2023](#bib.bib55)）（8-shot，CoT）、MMMLU（[OpenAI, 2024](#bib.bib42)）（5-shot）、INCLUDE（[Romanou et al., 2024](#bib.bib52)）（5-shot）。

作为基础模型的基线，我们在参数规模意义上将 Qwen3 系列基础模型与 Qwen2.5 基础模型（[Yang et al., 2024b](#bib.bib70)）以及其他领先的开源基础模型进行比较，后者包括 DeepSeek-V3 Base（[Liu et al., 2024a](#bib.bib36)）、Gemma-3（[Team et al., 2025](#bib.bib59)）、Llama-3（[Dubey et al., 2024](#bib.bib19)）与 Llama-4（[Meta-AI, 2025](#bib.bib40)）系列基础模型。所有模型均使用相同的评测流程与广泛使用的评测设置，以确保公平比较。

##### 评测结果总结

基于整体评测结果，我们着重指出 Qwen3 基础模型的几个关键结论。

1. 与此前开源的最先进稠密与 MoE 基础模型（如 DeepSeek-V3 Base、Llama-4-Maverick Base 与 Qwen2.5-72B-Base）相比，Qwen3-235B-A22B-Base 以显著更少的总参数量或激活参数量，在大多数任务上胜过这些模型。

2. 对于 Qwen3 MoE 基础模型，实验结果表明：(a) 使用相同的预训练数据，Qwen3 MoE 基础模型仅以 1/5 的激活参数即可达到与 Qwen3 稠密基础模型相当的性能。(b) 得益于 Qwen3 MoE 架构的改进、训练 token 规模的扩大以及更先进的训练策略，Qwen3 MoE 基础模型能以不到 1/2 的激活参数量和更少的总参数量胜过 Qwen2.5 MoE 基础模型。(c) 即使激活参数量只有 Qwen2.5 稠密基础模型的 1/10，Qwen3 MoE 基础模型也能取得相当的性能，这为我们在推理与训练成本上带来了显著优势。

3. Qwen3 稠密基础模型的整体性能可与更高参数规模的 Qwen2.5 基础模型相当。例如，Qwen3-1.7B/4B/8B/14B/32B-Base 分别取得了与 Qwen2.5-3B/7B/14B/32B/72B-Base 相当的性能。尤其在 STEM、编程与推理基准上，Qwen3 稠密基础模型甚至超越更高参数规模的 Qwen2.5 基础模型。

## 4 后训练

图 1：Qwen3 系列模型的后训练流程。

Qwen3 的后训练流程围绕两个核心目标进行设计：

1. 思考控制：这涉及整合「非思考」与「思考」两种不同模式，让用户可以灵活选择模型是否进行推理，并通过为思考过程指定 token 预算来控制思考深度。

2. 强到弱蒸馏：旨在为轻量模型简化并优化后训练流程。通过利用大规模模型的知识，我们大幅降低了构建较小规模模型所需的计算成本与开发投入。

如图 1 所示，Qwen3 系列的旗舰模型遵循一个精心设计的四阶段训练流程。前两个阶段专注于培养模型的「思考」能力；后两个阶段旨在将强大的「非思考」功能融入模型。

初步实验表明，将教师模型的输出 logits 直接蒸馏到轻量学生模型，能够在保持对推理过程细粒度控制的同时有效提升其性能。这一方法免除了为每个小规模模型逐一执行完整四阶段训练的必要。它带来了更好的即时性能（更高的 Pass@1 得分），也提升了模型的探索能力（Pass@64 结果的改善）。此外，它以更高的训练效率实现这些收益——所需的 GPU 时数仅为四阶段训练方法的 1/10。

在接下来的小节中，我们将介绍四阶段训练流程，并详细解释强到弱蒸馏方法。

### 4.1 长 CoT 冷启动

我们首先整理了一个覆盖广泛类别的综合数据集，包括数学、代码、逻辑推理与通用 STEM 问题。数据集中的每个问题都配有经过验证的参考答案或基于代码的测试用例。该数据集作为长思维链（long-CoT）训练「冷启动」阶段的基础。

数据集的构建包含严格的两个阶段过滤流程：查询过滤与响应过滤。在查询过滤阶段，我们使用 Qwen2.5-72B-Instruct 识别并移除不易验证的查询，包括含多个子问题的查询或要求一般性文本生成的查询。此外，我们排除 Qwen2.5-72B-Instruct 无需 CoT 推理即可正确回答的查询，这有助于防止模型依赖表面的猜测，确保只保留需要更深推理的复杂问题。另外，我们使用 Qwen2.5-72B-Instruct 标注每个查询的所属领域，以保持数据集各领域表示的均衡。

在保留一个验证查询集之后，我们使用 QwQ-32B（[Qwen Team, 2025](#bib.bib50)）为其余每个查询生成 N 个候选回复。当 QwQ-32B 始终无法生成正确解答时，由人工标注员人工评估回复的准确性。对于 Pass@N 为正的查询，进一步施加严格的过滤标准，以移除满足以下情形的回复：(1) 最终答案错误；(2) 包含大量重复；(3) 明显是缺乏充分推理的猜测；(4) 思考内容与总结内容不一致；(5) 存在不恰当的语言混杂或文风突变；或 (6) 疑似与潜在验证集条目过度相似。随后，从精修后的数据集中精心挑选一个子集，用于推理模式的初始冷启动训练。这一阶段的目标是为模型植入基础推理模式，而不过度强调即时的推理表现。这种做法确保模型的潜力不被限制，为后续强化学习（RL）阶段留出更大的灵活性与提升空间。为有效达成该目标，在此准备阶段应尽量减少训练样本数与训练步数。

### 4.2 推理 RL

推理 RL 阶段所使用的「查询-验证器」对必须满足以下四条标准：(1) 未在冷启动阶段使用过；(2) 对冷启动模型而言可学习；(3) 尽可能具有挑战性；(4) 覆盖广泛的子领域。我们最终共收集了 3,995 个「查询-验证器」对，并采用 GRPO（[Shao et al., 2024](#bib.bib54)）更新模型参数。我们观察到，使用大批次大小、每查询大量 rollout，并结合离策略训练以提升样本效率，对训练过程有益。我们还通过控制模型熵使其稳步上升或保持稳定，来解决探索与利用的平衡问题，这对维持训练稳定至关重要。结果是，在单次 RL 运行中，训练奖励与验证性能均持续提升，且无需对超参数进行任何人工干预。例如，Qwen3-235B-A22B 模型的 AIME'24 得分经过总共 170 步 RL 训练后从 70.1 提升到 85.1。

### 4.3 思考模式融合

思考模式融合阶段的目标是将「非思考」能力整合进此前已具备「思考」能力的模型。这一做法让开发者能够管理和控制推理行为，同时降低为思考与非思考任务分别部署不同模型的成本与复杂度。为此，我们对推理 RL 模型进行持续的监督微调（SFT），并设计了融合两种模式的聊天模板。此外，我们发现能够熟练处理两种模式的模型在不同的思考预算下均表现稳定。

##### SFT 数据的构建。

SFT 数据集同时包含「思考」与「非思考」数据。为确保阶段 2 模型的性能不因额外的 SFT 而受损，「思考」数据是使用阶段 2 模型本身对阶段 1 查询进行拒绝采样生成的。而「非思考」数据则经过精心整理，覆盖多样化的任务，包括编程、数学、指令遵循、多语言任务、创意写作、问答与角色扮演。此外，我们采用自动生成的检查清单来评估「非思考」数据的回复质量。为提升低资源语言任务上的表现，我们特别提高了翻译任务的占比。

##### 聊天模板设计。

为了更好地融合两种模式并让用户能够动态切换模型的思考过程，我们为 Qwen3 设计了聊天模板，如表 9 所示。具体而言，对于思考模式与非思考模式的样本，我们分别在用户查询或系统消息中引入 /think 与 /no_think 标志。这使模型能够遵循用户输入并相应选择合适的思考模式。对于非思考模式样本，我们在助手回复中保留一个空的思考块。这一设计确保了模型内部格式的一致性，并允许开发者通过在聊天模板中拼接空 think 块来阻止模型进行思考。默认情况下，模型以思考模式运行；因此，我们加入了一些用户查询不含 /think 标志的思考模式训练样本。对于更复杂的多轮对话，我们随机在用户查询中插入多个 /think 与 /no_think 标志，模型回复遵循最后出现的标志。

##### 思考预算。

思考模式融合的一个额外优势是：一旦模型学会了以非思考与思考两种模式回应，它便自然发展出处理中间状态的能力——基于不完整的思考生成回复。这一能力为对模型思考过程实施预算控制奠定了基础。具体而言，当模型思考的长度达到用户定义的阈值时，我们手动中止思考过程并插入停止思考指令："Considering the limited time by the user, I have to give the solution based on the thinking directly now.\n</think>.\n\n"。在该指令插入后，模型会基于截至那一刻所累积的推理继续生成最终回复。值得注意的是，这种能力并非经显式训练获得，而是应用思考模式融合后自然涌现的结果。

表 9：思考模式融合阶段中思考与非思考模式的 SFT 数据示例。对于思考模式，/think 标志可以省略，因为它代表默认行为。该特性已在 Hugging Face tokenizer 所支持的聊天模板（<https://huggingface.co/Qwen/Qwen3-32B/blob/main/tokenizer_config.json>）中实现，可通过附加参数 enable_thinking=False 关闭思考模式。


### 4.4 通用 RL

通用 RL 阶段旨在广泛提升模型在多样场景中的能力与稳定性。为此，我们建立了一套覆盖 20 余个不同任务的精细奖励体系，每个任务都有定制的评分标准。这些任务专门针对以下核心能力的增强：

- 指令遵循：该能力确保模型准确理解并遵循用户指令，包括与内容、格式、长度及结构化输出使用相关的要求，给出符合用户期望的回复。

- 格式遵循：除显式指令外，我们期望模型遵守特定的格式约定。例如，它应通过在思考与非思考模式之间切换来恰当地响应 /think 与 /no_think 标志，并一致地使用指定 token（如 <think> 与 </think>）在最终输出中分隔思考与回复部分。

- 偏好对齐：对于开放式查询，偏好对齐聚焦于提升模型的有用性、吸引力与风格，最终带来更自然、更令人满意的用户体验。

- 智能体能力：这涉及训练模型通过指定接口正确调用工具。在 RL rollout 期间，允许模型与真实环境执行反馈进行完整的多轮交互循环，从而提升其在长时程决策任务中的表现与稳定性。

- 专门场景能力：在更专门的场景中，我们设计贴合具体情境的任务。例如在检索增强生成（RAG）任务中，我们引入奖励信号来引导模型生成准确且贴合上下文的回复，从而将幻觉风险降到最低。

为对上述任务提供反馈，我们使用了三种不同类型的奖励：

1. 基于规则的奖励：基于规则的奖励已在推理 RL 阶段被广泛使用，对指令遵循（[Lambert et al., 2024](#bib.bib32)）与格式遵守等通用任务同样有效。设计良好的规则型奖励能够以很高的精度评估模型输出的正确性，防止奖励欺骗（reward hacking）等问题。

2. 带参考答案的模型奖励：在这种方法中，我们为每个查询提供参考答案，并提示 Qwen2.5-72B-Instruct 基于该参考为模型回复打分。这种方法能够更灵活地处理多样任务而无需严格格式，避免纯规则型奖励可能出现的假阴性。

3. 不带参考答案的模型奖励：利用人类偏好数据，我们训练一个奖励模型来为模型回复赋予标量分数。这一不依赖参考答案的方法能够处理更广泛的查询，同时有效提升模型的吸引力与有用性。

### 4.5 强到弱蒸馏

强到弱蒸馏流程专为优化轻量模型而设计，涵盖 5 个稠密模型（Qwen3-0.6B、1.7B、4B、8B、14B）与 1 个 MoE 模型（Qwen3-30B-A3B）。该方法在提升模型性能的同时，有效赋予其稳健的模式切换能力。蒸馏过程分为两个主要阶段：

1. 离策略蒸馏：在初始阶段，我们将教师模型以 /think 与 /no_think 两种模式生成的输出组合起来用于回复蒸馏。这帮助轻量学生模型培养基础推理技能以及在不同思考模式间切换的能力，为下一阶段的在策略训练打下坚实基础。

2. 在策略蒸馏：在该阶段，学生模型生成在策略序列用于微调。具体而言，对提示进行采样，学生模型以 /think 或 /no_think 模式生成回复；随后通过将其 logits 与教师模型（Qwen3-32B 或 Qwen3-235B-A22B）的 logits 对齐以最小化 KL 散度，从而对学生模型进行微调。

### 4.6 后训练评测

为全面评估指令微调模型的质量，我们采用自动化基准来评估模型在思考与非思考两种模式下的表现。这些基准可归为几个维度：

- 通用任务：我们使用的基准包括 MMLU-Redux（[Gema et al., 2024](#bib.bib21)）、GPQA-Diamond（[Rein et al., 2023](#bib.bib51)）、C-Eval（[Huang et al., 2023](#bib.bib28)）与 LiveBench（2024-11-25）（[White et al., 2024](#bib.bib63)）。对于 GPQA-Diamond，我们对每个查询采样 10 次并报告平均准确率。

- 对齐任务：为评估模型与人类偏好的一致程度，我们使用一组专门的基准。对于指令遵循表现，我们报告 IFEval（[Zhou et al., 2023](#bib.bib73)）的 strict-prompt 准确率。为评估通用话题上与人类偏好的对齐，我们使用 Arena-Hard（[Li et al., 2024](#bib.bib33)）与 AlignBench v1.1（[Liu et al., 2023b](#bib.bib39)）。对于写作任务，我们依靠 Creative Writing v3（[Paech, 2024](#bib.bib45)）与 WritingBench（[Wu et al., 2025](#bib.bib64)）来评估模型的熟练度与创造力。

- 数学与文本推理：为评估数学与逻辑推理技能，我们采用高水平数学基准，包括 MATH-500（[Lightman et al., 2023](#bib.bib34)）、AIME'24 与 AIME'25（[AIME, 2025](#bib.bib2)），以及文本推理任务，包括 ZebraLogic（[Lin et al., 2025](#bib.bib35)）与 AutoLogi（[Zhu et al., 2025](#bib.bib74)）。对于 AIME 问题，每年的题目包含 Part I 与 Part II，共 30 题。每道题我们采样 64 次并取平均准确率作为最终得分。

- 智能体与编程：为测试模型在编程与智能体任务上的能力，我们使用 BFCL v3（[Yan et al., 2024](#bib.bib68)）、LiveCodeBench（v5，2024.10-2025.02）（[Jain et al., 2024](#bib.bib30)）以及来自 CodeElo（[Quan et al., 2025](#bib.bib48)）的 Codeforces 评分。对于 BFCL，所有 Qwen3 模型均使用 FC 格式评测，并使用 yarn 将模型部署到 64k 上下文长度以进行 Multi-Turn 评测。部分基线取自 BFCL 榜单，取 FC 与 Prompt 两种格式中的较高分；对于榜单未报告的模型，则评测 Prompt 格式。对于 LiveCodeBench，非思考模式使用官方推荐提示词；而思考模式下，我们通过移除 You will not return anything except for the program 这一限制来调整提示模板，使模型能够更自由地思考。为衡量模型与竞赛编程专家之间的差距，我们使用 CodeForces 计算 Elo 评分。在我们的基准中，每道题通过生成最多八次独立推理尝试来求解。

- 多语言任务：对于多语言能力，我们评估四类任务：指令遵循、知识、数学与逻辑推理。指令遵循使用 Multi-IF（[He et al., 2024](#bib.bib24)）评估，聚焦 8 种关键语言。知识评估包含两类：通过 INCLUDE（[Romanou et al., 2024](#bib.bib52)）评估区域性知识，覆盖 44 种语言；通过 MMMLU（[OpenAI, 2024](#bib.bib42)）评估通用知识，覆盖 14 种语言（不含未优化的约鲁巴语）；对这两个基准，我们仅采样原始数据的 10% 以提升评测效率。数学任务采用 MT-AIME2024（[Son et al., 2025](#bib.bib56)），涵盖 55 种语言，以及 PolyMath（[Wang et al., 2025](#bib.bib61)），涵盖 18 种语言。逻辑推理使用 MLogiQA 评估，覆盖 10 种语言，取自 [Zhang et al. (2024)](#bib.bib72)。

##### 评测结果总结

从评测结果中，我们总结出最终版 Qwen3 模型的若干关键结论：

1. 我们的旗舰模型 Qwen3-235B-A22B 在思考与非思考两种模式下都展现出开源模型中最先进的整体性能，超越了 DeepSeek-R1、DeepSeek-V3 等强力基线。Qwen3-235B-A22B 与 OpenAI-o1、Gemini2.5-Pro、GPT-4o 等闭源领先模型也极具竞争力，彰显了其深厚的推理能力与全面的通用能力。

2. 我们的旗舰稠密模型 Qwen3-32B 在大多数基准上优于我们此前最强的推理模型 QwQ-32B，并与闭源的 OpenAI-o3-mini 表现相当，显示出其过硬的推理能力。Qwen3-32B 在非思考模式下同样表现出色，超越了我们此前旗舰非推理稠密模型 Qwen2.5-72B-Instruct。

3. 我们的轻量模型，包括 Qwen3-30B-A3B、Qwen3-14B 及其他更小的稠密模型，相对于参数量相近或更多的开源模型均保持一贯的优越表现，证明了我们强到弱蒸馏方法的成功。

详细结果如下。

##### Qwen3-235B-A22B

## 5 结论

在本技术报告中，我们介绍了 Qwen 系列的最新版本 Qwen3。Qwen3 同时具备思考模式与非思考模式，允许用户动态管理用于复杂思考任务的 token 数量。该模型在一个包含 36 万亿 token 的大型数据集上预训练，使其能够理解并生成 119 种语言和方言的文本。通过一系列全面评估，Qwen3 在预训练与后训练模型的一系列标准基准上均展现出强劲表现，包括代码生成、数学、推理与智能体相关任务。

在不久的将来，我们的研究将聚焦若干关键方向。我们将继续扩大预训练规模，使用质量更高、内容更多样的数据。与此同时，我们将致力于改进模型架构与训练方法，以实现有效压缩、扩展到极长上下文等目标。此外，我们计划增加用于强化学习的计算资源，尤其侧重于从环境反馈中学习的智能体 RL 系统。这将使我们能够构建可应对需要推理时扩展的复杂任务的智能体。
