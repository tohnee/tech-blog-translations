# 智能体编码入门

> 原文：[Introduction to agentic coding](https://claude.com/blog/introduction-to-agentic-coding/) · Claude 博客

过去几年，AI 辅助编码发展迅猛。曾经只能建议下一行代码的工具，如今已能通过分析你代码中的模式来预测整个函数。

最新的演进更进一层：这些系统不再预测你接下来要输入什么，而是自主执行多步骤开发任务——读取代码库中的文件、运行测试，并不断迭代直到目标完成。

## 什么是智能体编码？

智能体编码让 AI 从自动补全转变为自主任务执行者。传统编码助手等待你逐行输入，然后建议接下来的内容。智能体系统则接收一个高层次目标，将其拆分为离散的步骤，独立执行这些步骤，并根据环境反馈调整自己的方法。

关键区别在于自主性与作用范围。传统 AI 工具只分析编辑器中可见的代码，建议下一个片段。智能体编码工具则读取整个代码库，理解跨目录的文件关系，执行命令来验证改动是否有效，并不断迭代直到测试通过、需求满足。这种自主性贯穿整个开发周期，每一步都无需你手动编排工作流。

## AI 编码工具的演进历程

### 代码预测与补全

诸如 IDE 自动补全插件之类的工具会分析编辑器中可见的代码，预测你可能输入的下一行。这类系统擅长处理重复性模式，比如生成 REST 端点样板代码、按照既有约定创建测试结构、实现常见算法。

预测模型会考虑你的即时上下文。当你写下一个函数签名时，工具会根据函数名、参数类型和周边代码建议一个实现。当你开始输入 import 语句时，它会根据已导入的内容和常见使用模式推荐包。

局限在于作用范围。自动补全工具的上下文窗口有限，通常只分析当前文件或少数邻近文件。它们无法追踪数据在应用架构中的流动，也无法理解某个服务的改动会如何影响依赖它的服务。

### 对话式 AI 聊天界面

以 claude.ai 为代表的浏览器端编码助手为 AI 编码工具增添了对话能力。这类工具不再在你输入时建议代码，而是通过分析粘贴的代码片段、bug 描述和优化问题，围绕你的代码问题展开对话。

这类界面擅长分析与指导。粘贴一条缓慢的数据库查询，获得优化建议；描述一个架构决策，得到权衡分析；分享一条错误信息，一起探索排障思路。

对话形式支持迭代式细化。你先问一个宽泛的问题，收到初步回答，再根据回答澄清需求，逐步收敛到具体方案。这种来回交互在问题尚未完全定义清楚时，或在你需要先探索不同方案再决定实现路径时非常有效。

但对于涉及多个文件的任务，这种方式就不切实际了。重构一个被三十个其他文件引用的模块，意味着要把每个文件粘贴进聊天窗口、手动追踪哪些文件需要更新、把建议的修改逐一复制回各个文件，并确保所有修改彼此一致。聊天界面能提供指导，但实现过程的编排仍然靠手动。这正是智能体编码系统要填补的空白。

## 智能体编码的工作原理

### 上下文收集与规划

智能体编码系统在项目层面而非文件层面运作。当你给出一个目标时，系统会分析完成该目标所需的相关上下文：读取配置文件以了解项目设置，检查测试文件以了解现有的覆盖模式，并追踪 import 关系以绘制模块间的依赖图。

然后，系统会为达成目标制定一个计划。这不是一份静态清单，而是一种会随着系统收集更多信息而不断演进的自适应方法。如果你的目标是「为 API 添加身份验证」，计划可能是先分析现有的路由定义，识别哪些端点需要保护，检查身份验证中间件是否已经存在，并确定用户会话管理应该实现在哪里。

### 实现与协调

实现阶段需要在整个代码库中读写文件。与只在单个文件内建议改动的自动补全工具不同，智能体系统会修改多个相关文件以保持一致性。添加身份验证可能需要更新路由处理器、创建中间件函数、修改数据库 schema、调整 API 客户端代码、更新文档，并为上述所有改动补充测试覆盖。

这种自主工作流把开发从「写代码、跑测试、读报错、改代码、再重复」转变为「定义目标、审查建议的改动、批准实现」。你通过审查计划、批准文件改动来保持控制，而系统负责处理迭代调试循环、对既有代码模式的调研，以及跨多个文件的改动协调。

## 用 Claude Code 进行智能体编码

[**Claude Code**](https://claude.com/product/claude-code) 把智能体能力带到你的终端环境。不同于需要不断复制代码的浏览器端工具，也不同于只分析可见文件的 IDE 插件，Claude Code 直接在你的项目目录中运行，可以完整访问你的代码库。

### 安装与启动

在终端中安装 Claude Code：

```
npm install -g @anthropic-ai/claude-code
```

然后在你的项目目录中启动它，开始编码：

```
claude
```

### Claude Code 的工作方式

Claude Code 会按需读取你的整个项目上下文。当你询问架构或请求改动时，它会分析文件结构，理解 package.json 或 requirements.txt 中声明的依赖，追踪模块之间如何交互，并识别代码库中已经建立的既有模式。

多文件操作变得轻而易举。请求「把这些基于回调的代码重构为 async/await」，Claude Code 会找出所有使用回调模式的文件，逐一改写为 async/await 语法，把错误处理修改为 try/catch 块，更新相关测试以处理异步模式，并验证整个测试套件依然通过。

### 文件系统访问与权限

文件系统访问让基于 Web 的工具无法处理的工作流成为可能。Claude Code 能按恰当的命名约定创建新文件，把代码组织到合理的目录结构中，在添加依赖时更新配置文件，并与你项目既有的组织模式保持一致。

权限模型确保你始终保持控制。默认情况下，Claude Code 在修改文件之前会请求批准，并准确展示它计划做出的改动。你审查这些拟议的修改，批准你认可的改动，对不符合要求的改动要求修改。

### 与开发工作流集成

与开发工作流的集成意味着 Claude Code 能与你已在使用的工具交互。它会运行 npm 命令安装依赖，执行 Jest 或 pytest 等测试运行器，使用 Git 进行提交和分支管理，并启动开发服务器以验证改动在运行中的应用里是否生效。

你还可以通过连接 MCP（Model Context Protocol）服务器进一步扩展这些能力，它们能为 Claude Code 提供来自开发环境中其他工具与系统的更全面的上下文。

FAQ（常见问题）

传统 AI 编码工具基于即时上下文建议单个函数或代码片段。集成、测试以及确保代码符合项目约定，都由你来完成。

智能体编码工具理解你的整个项目，规划实现方案，并自主执行完整的工作流。它们交付的是经过测试、已集成、遵循你既有模式的功能。

智能体编码工具（如 Claude Code）可以长时间工作，保持上下文并在已有成果之上继续推进。Rakuten 那次七小时的自主重构会话就展示了无需人工干预的持续技术工作。具体时长取决于你的任务复杂度和项目要求。

[Claude Code](https://claude.com/product/claude-code) 通过终端集成与你的现有开发工作流结合。你可以循序渐进地把它纳入当前实践，先从测试或文档等具体任务开始，再扩展到完整的功能开发。

智能体编码适用于各类项目类型和语言。对于模式与约定成熟、集成要求复杂，或需要耗费大量时间做例行开发任务的项目，它尤其有价值。

你的 TypeScript/JavaScript、Python、Go 和 Rust 项目能立刻受益，同时 [Claude Code](https://claude.com/product/claude-code) 也支持所有主流语言和框架。

Claude Code 使用 **CLAUDE.md** 配置文件来记录你的编码规范、架构决策和项目特定要求。这些文件在你的各次会话之间持久存在，确保实现始终一致、遵循你已建立的实践。
