# Anthropic 各团队如何使用 Claude Code

> 原文：[How Anthropic teams use Claude Code](https://claude.com/resources/articles/how-anthropic-teams-use-claude-code) · Claude 博客

Anthropic 各部门的团队都在使用 Claude Code，从调试生产环境问题、熟悉陌生的代码库，到构建自定义自动化工具，用途不一而足。以下是他们的做法。

像 [Claude Code](https://claude.com/product/claude-code) 这样的智能体编码工具，能帮助开发者加速工作流、自动化重复性任务、攻克复杂的编程项目。随着这一领域不断演进，我们每天都在从用户那里了解到新的用法——其中也包括我们自己的员工。

为了深入了解，我们与 Anthropic 各部门的员工坐下来聊了聊，了解他们在工作中如何使用 Claude Code。

他们的许多用例在意料之中——调试、浏览代码库、管理工作流——但也有些让我们意外。法务人员搭建了电话树系统。市场人员几秒钟内生成了数百个广告变体。数据科学家在不懂 JavaScript 的情况下做出了复杂的可视化。

规律逐渐清晰：智能体编码不只加速了传统开发。它正在消解技术性工作与非技术性工作之间的边界，把任何能描述问题的人，变成能构建解决方案的人。

以下是我们了解到的情况。

### **代码库导航与理解**

公司各团队都用 Claude Code 帮助新员工乃至资深员工快速熟悉我们的代码库。

基础设施团队的新数据科学家把整个代码库喂给 Claude Code，以便快速上手。Claude 会读取代码库中的 [CLAUDE.md](http://claude.md) 文件，识别出相关的那些，解释数据管线的依赖关系，并说明哪些上游数据源供给仪表盘——取代了传统的数据目录工具。

产品工程团队把 Claude Code 称为任何编程任务的「第一站」。他们让它识别修复 bug、开发功能或做分析时该查看哪些文件，从而省去了在开发新功能前手动收集上下文这一耗时过程。

### **测试与代码审查**

智能体编码工具尤其受欢迎的一点，是它们能自动化两项关键但枯燥的编程任务：编写单元测试和审查代码。

产品设计团队用 Claude Code 为新功能编写全面的测试。他们通过 GitHub Actions 自动化了 Pull Request 评论的生成，由 Claude 自动处理格式问题和测试用例重构。

安全工程团队把工作流从「设计文档 → 粗糙代码 → 重构 → 放弃测试」改成了：让 Claude 给出伪代码，引导它走测试驱动开发，并定期检查。这让代码更可靠、更易于测试。

智能体编码还可以用来把测试迁移到其他编程语言。例如，当推理团队需要在 Rust 这样不熟悉的语言中测试某项功能时，他们说明想测什么，Claude 就用代码库的原生语言写出逻辑。

### **调试与故障排查**

生产环境问题要求快速解决，但在压力之下试图推理陌生代码，往往导致延误。对公司里的许多团队来说，Claude Code 通过实时分析堆栈跟踪、文档和系统行为，加速了诊断与修复。

事故发生时，安全工程团队把堆栈跟踪和文档喂给 Claude Code，以在代码库中追踪控制流。过去通常需要 10 到 15 分钟手动排查的问题，现在的解决速度快了 3 倍。

借助 Claude Code，产品工程团队有了信心去处理陌生代码库里的 bug。他们问 Claude：「你能修一下这个 bug 吗？我观察到的行为是这样的」，然后审阅它提出的方案，无需再依赖其他工程团队协助。

有一次，Kubernetes 集群停止调度 Pod，数据基础设施团队用 Claude Code 来诊断问题。他们把仪表盘截图喂给它，Claude 便逐个菜单地引导他们浏览 Google Cloud 界面，直到发现是 Pod IP 地址耗尽。随后 Claude 给出了创建新 IP 池并将其加入集群的确切命令，在系统故障期间为他们省下了宝贵的 20 分钟。

### **原型开发与功能开发**

开发新功能传统上需要深厚的技术知识和大量时间投入。Claude Code 支持快速原型开发乃至完整的应用开发，让团队无论编程水平如何都能快速验证想法。

产品设计团队的成员会把 Figma 设计文件喂给 Claude Code，然后搭起自主循环，让 Claude Code 编写新功能的代码、运行测试并持续迭代。他们给 Claude 一个抽象问题，让它自主工作，然后在最终打磨前审查方案。有一次，他们让 Claude 在几乎没有人工审查的情况下为自己构建了 Vim 键位绑定。

借助 Claude Code，产品设计团队还发现了一个意想不到的用法：在设计阶段就梳理出错误状态、逻辑流程和系统状态，从而识别边缘情况，而不是等到开发时才发现。这从根本上提升了他们初始设计的质量，也为日后省下了数小时的调试时间。

数据科学家虽然并不精通 TypeScript，却用 Claude Code 构建完整的 React 应用来可视化 RL 模型的表现。在沙箱环境中做一次提示（one-shot prompting）之后，该工具就能从零写出完整的 TypeScript 可视化，而他们自己并不理解这些代码。考虑到任务本身简单，如果第一次提示不够理想，他们会稍作调整再试一次。

### **文档与知识管理**

技术文档常常散落在 wiki、代码注释和团队成员的脑子里。Claude Code 通过 MCP 和 CLAUDE.md 文件把这些知识整合成易于获取的形式，让每个需要的人都能用上这些专业经验。

没有机器学习背景的推理团队成员依靠 Claude 来解释模型特有的函数。过去通常需要一小时 Google 搜索的工作，现在只需 10 到 20 分钟——研究时间减少了 80%。

安全工程团队让 Claude 摄取多个文档来源，生成 markdown 运行手册和故障排查指南。这些浓缩后的文档成为调试真实生产问题时的上下文，往往比在完整知识库中搜索更高效。

### **自动化与工作流优化**

智能体编码工具能帮助团队构建自定义自动化——传统上，这需要专职的开发资源或昂贵的软件。

增长营销团队构建了一个智能体工作流：处理包含数百条广告的 CSV 文件，找出表现不佳的广告，并在严格的字符限制内生成新的变体。借助两个专门的子智能体，该系统在几分钟而非几小时内就能生成数百条新广告。

他们还开发了一个 Figma 插件：识别画框，并通过替换标题和描述以编程方式生成最多 100 个广告变体，把数小时的复制粘贴缩短为每批广告半秒钟。

在一个尤其独特的用例中，法务团队搭建了原型「电话树」系统，帮助团队成员联系上 Anthropic 内部合适的律师——这说明各部门在没有传统开发资源的情况下也能构建自定义工具。

### **用 Claude Code 解锁新的可能**

这些故事揭示了一个规律：当你聚焦于 Claude Code 能够增强的人类工作流时，它的效果最好。最成功的团队把 Claude Code 当作思考伙伴，而不是代码生成器。

他们探索可能性、快速做原型，并在技术与非技术用户之间分享发现。这种人与 AI 的协作方式，正在创造出我们才刚刚开始理解的机遇。
