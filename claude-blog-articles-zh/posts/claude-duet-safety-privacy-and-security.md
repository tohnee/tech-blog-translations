# Claude Duet 的安全、隐私与防护

> 原文：[Claude Duet Safety, Privacy, and Security](https://claude.com/resources/articles/claude-duet-safety-privacy-and-security) · Claude 博客

*Claude Duet 是一个主动型智能体（proactive agent）：即使你不在，它也在为你工作。它建立在两层保护之上——Claude 模型自身的安全训练，以及 Claude Code、Claude Managed Agents 等产品中已有的防护措施。在此之上，我们新增了针对跨账户操作和代你行事的保护。*

[Claude Duet（在新标签页打开）](https://claude.com/resources/articles/claude-duet)是一个智能体，目前处于研究预览（research preview）阶段，它使用云端计算机为你完成工作。它可以调用你选择连接到 Claude 的所有应用与服务，并且在你关闭应用之后仍持续运行。它可以读取你的收件箱、起草回复、预订事项，并在你不在时运行例行任务（routines）。我们团队每天在自己的账户上使用 Claude Duet 工作。

我们遵循三项原则来构建并约束 Claude Duet 的行为：

1. 你的信息，以及其他人在你连接的应用中分享的内容，都会被谨慎处理；我们使用一个新的分类器，在 Claude Duet 起草的消息发出之前进行检查。
2. 它代表你执行的操作，始终由你掌控。
3. Claude Duet 永远看不到你的密码、浏览器 cookie、登录令牌或其他凭据。

Claude Duet 是新的，但背后的思路并不新。2025 年，我们[发布了安全可信智能体框架（在新标签页打开）](https://www.anthropic.com/news/our-framework-for-developing-safe-and-trustworthy-agents)，该框架把人置于掌控地位，并把隐私和安全交互视为基本要求。自那以后，我们撰文解释了为什么[没有哪一种防御足够（在新标签页打开）](https://www.anthropic.com/research/trustworthy-agents)，以及为什么[模型内部的保护无法独自成立（在新标签页打开）](https://www.anthropic.com/engineering/how-we-contain-claude)。我们还通过 [Claude Managed Agents（在新标签页打开）](https://www.anthropic.com/engineering/managed-agents)构建并运营企业用于在生产环境中运行智能体的基础设施，而 Claude Duet 以同样的方式让凭据与智能体保持分离。它建立在这些工作之上，补充了一个代你行事的智能体所需要的保护。本文将逐一说明我们新增了什么，以及仍在推进什么。

## 重要操作由你批准

一个在你不在时行动的智能体，必须知道何时停下来、先征求许可，而且要以恰当的频率这样做。在 Claude Duet 执行发送可能敏感的消息、付款、删除任何内容等操作之前，它会向你展示这项操作、目标位置和内容，包括每一位收件人。然后它等待你批准。

每一项操作都会同时经过一项独立的自动化检查；该检查基于 [Claude Code 的自动模式分类器（在新标签页打开）](https://www.anthropic.com/engineering/claude-code-auto-mode)构建，并为 Claude Duet 做了扩展。它评估这项操作是否符合你的意图。检查在真正执行工作的模型之外运行，因此页面中隐藏的指令无法影响结果。

有些操作即使得到你的批准也仍然禁止，例如证券交易、在账户之间转移资金这类银行操作，以及访问他人的账户。还有些步骤永远不适用"别再问我"的规则，无论你批准过多少次——比如付款或转账、删除订单、创建账户。你不在时运行的例行任务享有同样的防护。

我们花了大量时间校准 Claude Duet 征求批准的频率。批准疲劳（approval fatigue）是一个严肃的问题：请求太多会训练人们一路点过去，有时甚至没有充分考虑。我们会持续调整这一校准。

购物时，Claude Duet 使用来自 Link from Stripe 等钱包的一次性卡号支付，并限定于该商户和该金额。你会看到商品和总价，然后在 Link 应用中批准这笔购买。你的真实卡号不会与 Claude Duet 或商户共享。

图 1. 批准流程：批准卡片和独立检查都位于模型之外，因此智能体读取的任何内容都无法替它回答这张卡片。

## 你的信息会被谨慎处理

一个读取你的邮件、替你发送消息的智能体，时刻都在判断不同类型的信息应当流向何处。如果你让 Claude Duet 给团队发一份每周摘要，它应该只包含团队成员本来就有权访问的内容，绝不包含隐私细节——比如你的绩效面谈记录。

为此，我们构建了一个新的安全分类器：它与主模型分开运行，检查 Claude Duet 即将发送的每条消息是否包含潜在敏感信息。我们把这类信息分为两级：

* **绝不分享：** 对于登录凭据、完整的银行卡号和银行账号、政府证件号码等信息，我们给予最高级别的保护。Claude Duet 被指示绝不与任何人分享这些信息，即使你要求也不行。
* **需经同意才能分享：** 其他私密信息——例如健康或财务信息——只有在你明确批准后，Claude Duet 才会分享。你本人的请求即视为同意，因此"给我的牙医发条消息说我牙疼"通常不需要额外批准。

![展示在 Claude Duet 中你的信息可以流向何处的示意图](https://assets.claude.com/6cf6546eabf0f7bdccd66fa93e407941f9e50947.png)

图 2. 你的信息可以流向哪里：在任何内容发出之前，检查会权衡信息的敏感程度，以及你是否已给出同意。

如果 Claude Duet 因上述任一原因被拦截，它可以决定重写消息、去掉敏感信息，然后交给你批准。

Claude Duet 仍处于研究预览阶段，这些防护偶尔会漏掉某些内容，或把一条无害消息标记为风险。正因如此，它们与上文的批准机制协同工作——这些机制的目的，是让你始终掌控 Claude Duet 代表你发送的内容。随着我们对人们如何使用 Claude Duet 的了解加深，我们会持续迭代分类器。

## 任务与已连接的应用对你可见

你可以在任务列表中看到 Claude Duet 做过什么、正在做什么——每个任务都有自己的页面——并且可以在任务进行中随时纠偏。Claude Duet 会保留你的对话历史及其记忆，以便在任务之间延续上下文，直到你删除或重置历史记录。删除账户会清除 Claude Duet 存储的一切。

![Claude Duet 任务列表外观的截图](https://assets.claude.com/2ea9a7ae6dfe5a96c7e3e0fb759df5a0703704b1.png)

你连接到 Claude 的应用会延续到 Claude Duet；在一处关闭某个应用，两处都会关闭。断开某个应用的连接会从那一刻起停止新的访问，但 Claude Duet 已经从中学到的内容会保留下来，直到你重置它的记忆——你可以随时在该应用的设置中操作。Claude Duet 也会使用你 Claude 账户中的记忆，因此 Claude 从你早前对话中记住的细节对它可见。

## 凭据与浏览器都与模型隔离

Claude Duet 永远看不到你的密码、浏览器 cookie，或已连接应用的登录令牌，也无法把它们存入自己的记忆。它们只会经过模型无法访问的独立机器，而管理其行为的批准流程和安全检查也在那里运行。

**密码**

当某个网站要求输入密码时，你在 Claude 应用内的表单中输入。表单会用一次性密钥加密密码，该密钥只存在于我们安全的云端浏览器机器上，且仅用于这一次。加密后的密码在未被解密的状态下传递到浏览器，由浏览器输入到网站中。模型看不到密码，也无法保存或重复使用。不久后你还可以使用 1Password 登录：Claude Duet 会请求一项凭据，你在 1Password 中批准该请求，凭据便会送达浏览器，而不经过模型。

替你登录的智能体从两个方面改变了网络钓鱼的攻防。一方面，Claude Duet 不持有你的凭据，因此无法被钓取密码，任何隐藏指令也无法让它泄露它并不拥有的秘密。另一方面，登录表单本身成了攻击目标，因为任何索取密码的东西都可能被仿冒。因此，Claude Duet 的登录表单只会在应用内、且在你主动发起的登录过程中出现。它绝不会以链接、短信、邮件或 claude.ai 以外网站的形式出现。如果有任何自称 Claude Duet 的东西在其他地方索要你的密码，那一定是假冒的。

**登录令牌**

当 Claude Duet 在已连接的应用中工作时，它遵循[我们的 Claude Managed Agents 设计（在新标签页打开）](https://www.anthropic.com/engineering/managed-agents)，让凭据始终处于智能体工作范围之外。智能体代表你使用的凭据——例如某个已连接服务的登录令牌——永远不会进入智能体工作的那台机器。机器上放置的是凭据的占位符，只有发起请求时，机器之外的代理才会填入真实值。

**浏览器**

Claude Duet 中的浏览器运行在云端一台专用虚拟机中，与模型、与智能体工作的云端计算机彼此隔离。智能体只能通过一组固定命令驱动浏览器：*打开这个页面、点击这里、输入这些内容*。网站运行的所有东西都[留在浏览器所在的机器上（在新标签页打开）](https://www.anthropic.com/engineering/managed-agents)。网站的代码和 cookie 不会进入 Claude Duet 的记忆或你连接的应用，智能体的任何命令也都无法从浏览器中读出 cookie。回传的是页面文本和下载内容，因为智能体必须读取它们才能完成工作。这正是其他检查存在的原因，也是 Claude Duet 采用我们[浏览器使用研究（在新标签页打开）](https://www.anthropic.com/research/prompt-injection-defenses)中所描述的提示注入防护的原因。它通过浏览器上传的文件，会与它发送的消息一样接受敏感信息检查。

![展示哪些内容发生在 Claude 的计算机上、哪些留在你的设备上的示意图](https://assets.claude.com/7df447f5c9bcaa1b3424f88f94d623be1383b637.png)

图 3. 浏览器边界：固定命令穿行而过，页面文本返回，网站代码、cookie 和下载内容都留在浏览器机器上。

Claude Duet 还被设计为主动表明自己是智能体。目前，其网页浏览器发出的请求会带有一个独特的 User-Agent 头，我们也会公开它浏览时使用的公网 IP 地址，让网站能够识别它并决定如何对待它。上线前，我们还联系了若干大型网站，让它们可以选择阻止 Claude Duet 访问其站点，有些网站选择了阻止。随着从研究预览中积累经验，我们会继续改进 Claude Duet 表明自身身份的方式。

![展示密码凭据路径的示意图](https://assets.claude.com/3073b7d3f85e65f58bd4a7627eb5f5ff9c2af4af.png)

图 4. 凭据路径：密码在你的手机上加密，只在浏览器机器上解密，永不经过模型。

## 我们如何测试 Claude Duet

测试远早于研究预览就已经开始，并持续至今。我们的安全防护团队根据例行任务的实际形态构建评估，每个任务有三种变体：一个无害版本、一个注入了指令的版本，以及一个诱导智能体做超出所托之事的版本。这些评估与来自真实使用的影子流量一同运行。

红队进一步测试了 Claude Duet 是否会泄露信息、未经批准就行动，或遵循恶意提示。我们为整个系统建立了威胁模型，覆盖它触及的各个代码仓库和信任边界。一家外部渗透测试公司在我们提供源码访问权限的条件下测试了 Claude Duet，一项覆盖云端浏览器和登录表单的后续工作正在进行中。每一项新的凭据功能在向任何人发布之前，都会在隔离装置上进行红队测试。

Claude Duet 也在 Anthropic 公开漏洞赏金计划的范围内：该计划对有效报告给予奖励，并根据我们的负责任披露政策，为善意研究提供安全港。如果你发现安全漏洞，我们希望听到——请通过 [HackerOne（在新标签页打开）](https://hackerone.com/anthropic)上的 Anthropic 漏洞赏金计划报告。

## 与你一起构建

我们以研究预览的形式发布 Claude Duet，是因为我们想了解你在一个个人智能体身上看重什么，包括你希望接下来看到哪些保护和控制。本文描述的部分内容仍在变化中：它征求批准的频率、你的登录方式，以及敏感信息检查区分私密内容与无害内容的准确程度。用平实的语言告诉 Claude Duet 你希望看到什么，或哪里出了问题，它就会为我们的团队提交报告。
