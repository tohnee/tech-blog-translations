# AI 如何帮助打破 COBOL 现代化的成本壁垒

> 原文：[How AI helps break the cost barrier to COBOL modernization](https://claude.com/blog/how-ai-helps-break-cost-barrier-cobol-modernization/) · Claude 博客

COBOL 无处不在。据估计，美国 [95% 的 ATM 交易](https://aisel.aisnet.org/cgi/viewcontent.cgi?article=1090&context=treos_icis2022)由 COBOL 处理。每天有数千亿行 COBOL 代码在生产环境中运行，支撑着金融、航空和政府领域的关键系统。

尽管如此，能看懂它的人数每年都在萎缩。

构建这些系统的开发者多年前就已退休，他们掌握的组织知识也随之流失。生产代码在几十年间被反复修改，但文档却没有跟上。与此同时，我们也没有培养出接替者——只有少数几所大学还在教授 COBOL，能读懂它的工程师一个季度比一个季度难找。

面对这些障碍，组织如何在不丢失数十年积累的可靠性、可用性和数据的前提下[现代化](https://claude.com/solutions/code-modernization)自己的系统？而且不出任何差错？

# **什么是 COBOL 现代化？**

COBOL 现代化是更新遗留 COBOL 应用的过程——方式包括将其重新托管到新基础设施、重构代码、用 Java 等现代语言重写，或者完全替换整个系统——同时保留其中沉淀了数十年的业务逻辑。成本历来是那道壁垒：理解代码究竟在做什么，是最昂贵的一步。

## 为什么 COBOL 现代化与众不同

COBOL 现代化与典型的遗留代码重构有根本区别。你不是在把熟悉的代码更新为更好的模式，而是在对尼克松担任总统时期构建的系统做业务逻辑的逆向工程。你要理清几十年间演化出来的依赖关系，翻译如今只存在于代码本身之中的组织知识。

过去，现代化一个 COBOL 系统需要成群的顾问耗费数年时间梳理工作流。其结果是周期漫长、成本高昂，鲜有组织愿意承接。

AI 改变了这一点。

1. 在数千行代码之间映射依赖关系
2. 为无人记得的工作流编写文档
3. 识别人类分析师需要数月才能暴露的风险
4. 为团队提供做出明智决策所需的深刻洞察

借助 AI，团队可以在几个季度而非几年内完成 COBOL 代码库的现代化。

## **COBOL 现代化的四种方式：重新托管、重构、重写、替换**

大多数现代化工作会从四种方式中选择。

*重新托管（rehosting）*把 COBOL 原封不动地搬到更廉价的基础设施上——快，但可维护性问题依然存在。

*重构（refactoring）*在不改变行为的前提下调整代码结构。*重写（rewriting）*则把它转换成 Java 或 Python 等现代语言——回报最高，而历史上其成本和风险也最高。

*替换（replacing）*在恰好有合适的商业产品时，用产品换下整个系统。AI 改变最大的是重写路径的经济学，这也是本文余下部分的焦点。

## AI 如何改变 COBOL 现代化

AI 擅长精简那些曾让 COBOL 现代化成本高到令人望而却步的任务。有了它，你的团队可以专注于战略、风险评估和业务逻辑，而代码分析与实现则交由 AI 自动完成。

### 自动化探索与发现

AI 的起点是通读你的整个 COBOL 代码库并映射其结构。

它会识别程序入口点，追踪经由被调用子程序的执行路径，映射模块间的数据流，并记录横跨数百个文件的依赖关系。

这种映射超越了简单的调用图。共享数据结构、在模块间造成耦合的文件操作、影响运行时行为的初始化序列——这些隐式依赖不会出现在静态分析中，因为它们涉及通过文件、数据库或全局状态共享的数据。而它们也恰恰是 COBOL 现代化风险的来源，这正是自动化发现如此重要的原因：它能在这些隐藏关系于迁移期间引发问题之前将其找出。

工作流文档也从这种分析中自然涌现。

通过追踪数据从输入到输出如何在系统中流动，AI 可以生成处理流水线的图表和文字说明——这些流水线没人记得是谁构建的，但人人都依赖。

### 风险分析与机会映射

代码库映射完成后，AI 可以评估哪些组件可以安全迁移、哪些需要谨慎处理。高耦合的模块现代化起来风险更高。孤立的组件会浮现出来，成为早期独立现代化的候选。重复的逻辑指向重构机会。技术债积压的区域则会在变成迁移中的意外之前被记录在案。

### 专家监督下的战略规划

这正是人类判断力变得不可或缺的地方。你的 COBOL 工程师带来的是 AI 无法具备的对监管要求、业务优先级、运营约束和风险容忍度的理解。

**规划阶段**制定一份详细路线图，对现代化工作进行战略性排序：

- AI 基于其在分析阶段识别出的风险、依赖关系和复杂度提出优先级建议。
- 你的团队评审这些建议，并基于业务价值、技术风险和组织优先级，决定先现代化哪些组件。
- 也是在这个阶段，你的团队要为现代化后的组件定义目标架构、代码标准和集成要求。

**代码测试与验证**也要在任何代码改动之前定义清楚：

- AI 设计初步的功能测试，验证迁移后的代码产出与遗留 COBOL 完全一致的输出。
- 你的团队决定这些测试是否足够、哪些业务场景需要主题专家的人工验证，以及现代化后的组件需要达到哪些性能基准。

### 持续验证下的增量实施

执行每次只处理一个组件，每一步都伴随验证。AI 将 COBOL 逻辑翻译成现代语言，为原地保留的遗留组件创建 API 包装层，并搭建脚手架，让新旧代码在过渡期间并行运行。

每一步要么成功并通过验证，要么在影响范围还小时失败并被纠正。

你永远不会面临大规模改动悬而未决、一旦失败就要回滚数周工作的局面。随着团队看到现代化后的组件通过测试，他们会获得信心，去攻克系统中日益复杂的部分。

上述方法适用于任何规模的 COBOL 系统。

从一个边界清晰、复杂度适中的单一组件或工作流入手。用 AI 对其进行彻底的分析和文档化，与你的工程师一起规划现代化方案，以增量方式实施并在每一步进行测试，然后仔细验证。这将建立组织信心，并暴露出你的系统所需的调整。
