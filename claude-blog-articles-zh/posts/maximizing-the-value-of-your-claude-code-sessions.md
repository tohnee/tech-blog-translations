# 让你的 Claude Code 会话价值最大化

> 原文：[Maximizing the value of your Claude Code sessions](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions/) · Claude 博客

## TL;DR

- **在任务之间运行 `/clear`。**这能防止先前不相关的上下文被再次发回给模型，从而降低 token 用量。
- **开工前先设好模型和努力等级（effort level）。**在对话中途更改其中任何一项都可能击穿你的提示缓存，进而推高 token 成本。
- **用 @ 提及文件，而不是只写出文件名。**文件会直接附在你的消息上，省去一次 Read 调用，也省去 Claude 不得不自行搜索的过程。
- **给吵闹的命令加静默标志，或者放到子智能体里运行。**命令输出会像文件一样附加进对话，并在会话的剩余时间里一直待在那里。
- **在新会话中运行一次 `/context`。**它会展示当前加载了什么（`CLAUDE.md`、MCP 工具定义），你就能把不必要的东西裁掉。
- **离开键盘休息之前，先运行 `/compact`。**提示缓存一小时后就会过期，趁对话还在缓存里时做摘要要便宜得多。

## 价值最大化

就在不久之前，你写代码所用的工具还是一口价（甚至免费）。无论你那个下午修了一个测试还是五十个，编辑器的费用都一样，所以单个任务本身并没有什么价格可言。

而使用 Claude Code 这类智能体编码工具时，价格是存在的。同一个已完成的任务，成本也会随你的使用方式而不同。

在一种会话里，Claude 读完测试及其覆盖的文件，做出修改，几个回合就完事。在另一种会话里，它先在整个仓库里 grep 一圈，绕路读了十几个文件才抵达同样那两个，而且每一个回合还会把今天上午以来读进对话的所有其他内容一并拖着走。

修复是同一个修复，但你为它花费的 token 数量不同，而且整个过程里模型还得一直惦记着十个它并不需要的文件。

高效使用 token 并不意味着总量上用得更少，而是确保你用掉的每一个 token 都花在你真正要求的事情上。

那么我们就来看看：是什么决定了单个 token 的价格，是什么决定了一次会话发送多少 token，以及在这一路上，这对你会话的运行方式意味着什么。

## **什么决定了 token 的价格**

你按 token 计费，但你真正支付的是推理：GPU（或 TPU，或模型恰好运行在什么上面）把模型跑过你的 token 所花的时间。

有三件事决定一个 token 占用多少这样的时间：你运行的是哪个模型，它是输入 token（进入）还是输出 token（输出），以及它是否被缓存。

### 模型

更大的模型会在输入和输出 token 上做更多工作。哪种工作值得用哪个模型，这本身就是一个独立话题，我们在[*在 Claude Code 中选择 Claude 模型与努力等级*](https://claude.com/blog/claude-model-and-effort-level-in-claude-code)一文中讨论过。

就本文而言，你只需要知道：我们接下来要讲的其余一切，都会乘以模型的价格——问题真正困难或模糊时用更大的模型，工作是例行公事时用小一点的。

*曲线仅用于示意，不代表真实基准测试数据。*

### 输入与输出 token

一个请求分两个阶段经过 GPU，两个阶段的成本不同。

第一阶段是预填充（prefill），模型读取你的请求和上下文：系统提示、你的 `CLAUDE.md`、你的消息，以及此后加入对话的一切（Claude 读过的文件和它运行命令的输出）。这些是你的输入 token。

然后是解码（decode），模型写出输出 token：它的思考、它发起的工具调用，以及你看到的文本。这是一次一个 token 进行的；一段 200 token 的回复就是模型接连运行 200 次。就单个 token 而言，解码让 GPU 忙碌的时间长得多，这也是输出定价约为输入 5 倍的原因。

会话中相当一部分输出 token 是思考 token，而模型每一轮做多少思考，正是努力等级所控制的。和模型一样，你用 `/effort` 选定的等级也会作为默认值延续到下一次会话。

> **提示：**在新会话中运行一次 `/model` 和 `/effort`，看看你实际在用什么。两者都会记住你上次的选择，而你会希望这个决定是深思熟虑的。

> **提示：**如果你已经知道某个会话就是枯燥的体力活，`MAX_THINKING_TOKENS=0` claude 可以为那一个会话关闭思考（Fable 5 除外），这比 `/effort` low 还要再低一档。

### 提示缓存

如果一个请求的开头 token 与服务器刚处理过的某个请求完全一致，那么这段共享开头的状态也会是一样的，服务器就可以把它保留下来复用，只对后面的新增内容做预填充。这就是提示缓存（prompt caching）。

从缓存读取只需输入价格的 0.1 倍，因为服务器是加载现成的状态而不是重新计算。把 token 写入缓存则比普通输入略贵，最高可达 2 倍，因为服务器之后还要保存这些状态。但写入对每个 token 只发生一次，而 0.1 倍的读取发生在其后的每一轮。

Claude Code 会在每个请求上自动管理提示缓存，你无需打开任何开关。不过缓存是可以被你弄坏的，所以知道如何避免这些成本尖峰很重要。

假设我们输入「修复 `utils.test.ts` 里失败的测试」。以下是 Claude Code 为此发送的内容：

1. Claude Code 用系统提示（含工具定义）、你的 `CLAUDE.md` 和你的消息组装出第一个请求并发送（输入 token）。此时缓存里还什么都没有，因此全部内容都要预填充并写入缓存。

2. 模型没法修一个它没见过的测试，于是思考片刻，回复一个针对 `utils.test.ts` 的 Read 调用（输出 token）。Claude Code 读取该文件，把它附加到对话中，然后把整段内容再发一遍（输入 token）。这一次，请求 1 的一切都以十分之一的价格从缓存读回，唯一以全价预填充的是新增部分：Read 调用和那个文件。

3. 现在模型想要被测试的那个文件（输出）。又是一次 Read、一次附加，然后一切再发一遍：请求 1 和 2 走缓存，第二个文件按全价（输入）。

4. 模型回复一个 Edit（输出）。Claude Code 应用它，附加结果，再发送一切。同样的剧情：Edit 及其结果是新的，它们前面的一切都是缓存读取（输入）。

5. 模型运行 `npm test`（输出）。Claude Code 附加测试输出并再发送一切，测试输出是唯一的新增部分（输入）。

6. 测试通过，模型回复一段简短总结（输出）。没有工具调用就意味着没有可附加的内容，也没有第 6 个请求，到此结束。

一个小修复发了五个请求，而其中每一个都包含截至当时点的整段对话。一个典型的回合是极不平衡的：数以万计的 token 进入，几百个 token 输出。但只有该回合中新增的内容才按全价预填充。

这就是每一轮的全部账单：历史部分是缓存读取，新增部分按输入全价，回复部分按输出价格。

> 这一点在订阅套餐上同样适用。你不会直接看到这些价格，但正是同样的请求在消耗你的用量额度。

缓存必须从请求的最开头开始匹配，而请求总是按同样的顺序发出：工具定义，然后是系统提示，然后是对话（`CLAUDE.md` 位于对话最前面）。

如果这个前缀中的任何内容变了，它后面的一切都要重新预填充。附加在对话末尾的工具结果是理想情况，因为它后面什么都没有。而任何在更靠前的位置改动请求、或改变缓存键的内容，都会让缓存作废：

- **`/model`**：每个模型都有自己独立的缓存，所以下一轮整段对话都要按全价重新预填充。（opusplan 也是如此，它每次进出计划模式都会切换模型。）
- **`/effort:`** 努力等级也是缓存键的一部分，所以情况相同。这就是为什么 `/model` 和 `/effort` 在对话中途切换时都会要求你确认。
- **快速模式（Fast mode）**：同样是键的一部分，而且重新预填充按快速模式的价格计费，所以如果你要开，就在会话开始时开。（再关掉它，缓存层面是免费的。）
- **`/compact`**：对话被一段更短的对话替换，于是其中任何内容都不再匹配（它前面的系统提示得以幸存）。只要旧对话还在缓存里，写入摘要本身就很便宜，所以长时间休息之前做压缩要比休息之后便宜得多。
- **时间：**每一轮都会重置计时器，但缓存在订阅上一小时后过期，在 API key 上五分钟后过期（`ENABLE_PROMPT_CACHING_1H=1` 可延长为一小时）。超过这个时间再回来，下一轮就要把整段对话重新预填充。恢复旧会话几乎也是如此：那时缓存通常早已失效，而且系统提示在启动时反正也会重建。

这一切并不是说你永远不该切换模型或努力等级。它的意思是：有便宜的时刻——会话开始时或 `/clear` 之后，也有昂贵的时刻——一段长对话的中途。

> **提示：**如果最近几轮走上了你不想要的方向，用 `/rewind` 回退到它们之前，而不是运行 `/compact`。回退只从末尾剪掉那几轮，它们之前的一切仍在缓存里，不花一分钱。压缩会重写整段对话，所以总是有成本的。

## **什么决定了一次会话发送多少 token**

这里要了解的关键是：没有任何东西只被发送一次。凡是进入对话的内容——Claude 读过的文件、它运行命令的输出——在其后的每一轮都会被再发一遍，直到会话结束。

它们是缓存的，所以每一次重发都很便宜，但便宜不等于免费，而且它们也占着上下文的空间，模型每一轮都得围着这些内容思考。

这基本上就是一次会话的全部成本模型：有多少 token 最终进入上下文，它们在那里停留多少轮，以及你同时在跑多少个上下文。

### **什么会进入上下文**

上下文中有一部分在你输入任何内容之前就已经在了：工具定义、系统提示、`CLAUDE.md`，以及启动时加载的其他一切。

> **提示**：在全新会话中运行 `/context`，看看你还没输入任何东西时里面有什么。把 `CLAUDE.md` 保持在具体指令上，把工作流相关的内容移进 Skills，它们只在使用时才会加载。如果某个 MCP 服务器在这个会话里用不上，用 `/mcp` 把它关掉。

会话期间加入的几乎所有其他内容都是工具结果：Claude 读的文件，和它运行的命令的输出。

Claude 读多少，主要取决于它需要自己搞明白多少。如果你说「测试挂了」，它首先得弄清楚是哪些测试：一两次 grep、打开几个文件看哪个相关，而这些结果在早已失去用处之后还会在上下文里停留很久。

「修复 `utils.test.ts` 里失败的测试」跳过了搜索，只花一次针对该文件的 Read 调用；而「修复 `@utils.test.ts` 里失败的测试」连这次 Read 调用都省了。

> **提示：**引用文件时，用 @ 提及它，而不是手打路径。Claude Code 会在发送任何内容之前就把文件附加到你的消息上，所以它出现在第一个请求里，不需要 Read 调用。无论哪种方式，文件本身占用的上下文空间是一样的，所以每次对话只需提及一次：它会一直待在那里，之后的回合再次 @ 提及它通常会附上第二份副本。

另一个把上下文填满的是 Claude 运行命令的输出。它每次运行你的测试、构建或 git log，打印出来的东西都会像它读过的文件一样附加到对话中，并停留同样的轮数。

特别大的输出其实没问题：超过 30,000 字符后，Claude Code 会把输出写入文件，对话里只留一段简短预览和路径（想改这个阈值可用 `BASH_MAX_OUTPUT_LENGTH`）。

问题出在阈值之下的所有输出。一个逐行打印 400 条通过测试的测试运行器，总量恰好低于上限，于是这 400 行就成了其后每一轮的一部分。

Claude 常常会自己用标志和 tail 处理好这件事；如果你不想把这交给 Claude，文档里有一个小 hook，可以在吵闹的命令运行前改写它们，只让重要的行返回。

> **提示**：把你整天反复运行的两三个命令写进 `CLAUDE.md`，静默标志带上，就按你自己会敲的样子写（「用一个命令跑单个测试文件：`npx vitest run <file> --reporter=dot`」）。这只是很小的一段补充，但它在其后的每个会话里都能省下一个回合和几百行输出。

### **它们会停留多少轮**

一个长会话的成本，高于把同样的工作分摊到几个短会话里，而且高出的程度超出你的想象——因为第 40 轮还要把前面的 39 轮重新读一遍。你要让会话中的上下文保持简短且相关，所以不要把上一个任务的上下文带进下一个：开始新任务时 `/clear`，同一任务的前半段完成时 `/compact`。

> **提示**：如果以后可能还想找回这个会话，`/clear` 之前先 `/rename`。运行 `/compact` 时，告诉它要保留什么；如果每次都一样，就在 `CLAUDE.md` 里放一个「Compact instructions」小节。如果你用的是 1M 上下文模型，并且希望把自动压缩的安全网放回原来的位置，`/autocompact 200k` 可以做到（需要 Claude Code v2.1.221 或更高版本）。

也要留意那些在你没有输入时发生的回合。一个 `/loop` 会在你设置它的那个会话里作为完整的一回合触发，每次都拖着整段对话走；而且如果距离上一轮已超过一小时，还要再叠加一次缓存未命中。在另一个终端开一个全新会话，把 loop 放在那里运行。

### **子智能体**

把某样东西挡在你的上下文之外的另一种办法，是让它发生在另一个上下文里——这正是子智能体（subagent）的用途。子智能体拥有自己的上下文窗口，带有自己的系统提示、各种工具和你的 `CLAUDE.md`，但没有你的对话。它运行自己的回合，返回主会话的只有它的答案。其余一切在它完成时都被丢弃。

不带你的对话的坏处是，子智能体有时不得不重新阅读主会话里已有的内容，而且它在这么做的同时也在为自己的回合付费。对小活儿来说，这就是纯粹的额外开销。

而当一项工作会产生大量你不需要保留的输出时——比如翻一遍日志——它就值回票价。Claude 常常会自己主动使用子智能体做这类事，在它没这么做时你也可以直接要求（「在一个子智能体里过一遍这份日志」）。只要记住：主会话只能拿回子智能体选择汇报的内容。

> **提示**：如果有一项你反复交接的吵闹任务，就给它一个专属的子智能体定义，并指定 model: haiku（或 sonnet）。否则它会跑在你主会话所用的任何模型上。
