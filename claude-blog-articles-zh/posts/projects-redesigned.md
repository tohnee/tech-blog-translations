# 重新设计的 Projects：从文件夹到对话

> 原文：[Projects redesigned: from folder to conversation](https://claude.com/resources/articles/projects-redesigned) · Claude 博客

Claude 项目的全新体验，现已在 Claude Code 中以 beta 形式提供

过去，在一次构建中管理多个会话，需要你自己拆分工作、应付交接，再把结果拼接回去。现在，在 Claude Code 项目中，你只需描述需要完成什么，Claude 会管理工作本身。

Claude 会界定请求的范围、分派任务、协调并行线程、审查产出，并汇总最终结果。你可以全程引导进度——甚至可以在手机上操作——而且在你离开电脑之后，它仍会继续工作。

例如，配置一个项目并设定目标：降低应用结账流程的 p75 延迟。然后让 Claude 对每个端点做性能剖析、测试优化方案，并在并行线程中提交 PR。或者连接你的 API、Web 和移动端仓库，设定目标：淘汰已弃用的 v1 端点。Claude 会为每个仓库创建一个线程，迁移调用方、运行测试、提交 PR，然后告诉你哪些需要优先合并。

从今天起，更新后的项目以 beta 形式面向部分 Claude Pro 和 Max 订阅者开放，前提是他们在 Claude Code 中使用云会话，且尚未在 Web 或桌面端创建任何项目。

在接下来的一周里，我们将向这些套餐中更多的 Claude Code 用户扩大开放范围。之后，更新后的项目将覆盖整个 Claude 以及 Team 和 Enterprise 套餐。如果你是 Pro 或 Max 用户但尚未获得访问权限，可以加入[等待名单](https://claude.com/form/projects)。

Pro 和 Max 套餐中的现有项目将继续按当前方式工作。随着推广扩展到聊天和 Cowork，我们会对这些项目进行升级。

## 线程做事，Claude 指挥

项目由负责实际工作的线程和一个指挥它们的协调器组成。

开始一个项目时，你会选择一个目标，以及仓库或上下文。Claude 会先提出它可以立即着手的工作。你可以配置项目的云环境、连接器、插件、指令和模型。

![](https://assets.claude.com/e51d818a287f89b01a7a308b5f01c3779ef7791c.png)

你可以在项目主聊天中监控和引导进度，也可以进入每个单独的线程查看并把握细节。像给幕僚长交代工作一样向项目中的 Claude 交代任务，它就会把工作分派到新的或已有的线程中。

Claude 还会主动同步进展并落实工作。连接仓库后，线程会提交拉取请求并运行你的测试；处理文档时，它会阅读文档并起草内容。

在底层，每个线程都是一个 Claude Code 云会话，在各自的分支和仓库副本上工作。协调器负责让工作保持有序，但如果多个线程修改了相同的代码，重叠部分会像任何其他 PR 一样作为合并冲突解决。

每个线程在需要时还可以用子智能体、loops 和工作流把分派到的工作进一步拆分，让大型任务更快完成。

## 上下文随时间累积

项目是为长时间运行或智能体式的工作流设计的：也就是耗时超过一次回复、且包含多个部分的工作。

随着时间推移，Claude 会了解更多的项目细节，并将其应用到工作中。现在，每个线程都会向共享记忆中添加内容，并从中读取内容，从而减少了对复杂提示词工程的依赖。

例如，Claude 可以记住发布改到了周五、某个导出功能为何被砍掉，或者在改动计费服务前应该先和谁确认。

![](https://assets.claude.com/5648108ea67905e6ce7975fd9a60ded1a45b1b9d.gif)

一个项目跨越一周。每个请求都会在右侧打开一个线程；记忆、决策和结果则在下方逐步累积。

Claude 还会记住你的工作和沟通风格。你可以要求它调整同步的频率、启动新线程的频繁程度，或每次更新的详细程度。

除了记忆之外，项目现在还包含一个资料库，收集你添加的文件和 Claude 产出的 artifacts。这让查找相关材料更容易，也让新工作可以在过往成果的基础上继续推进。

## 下一步

项目可以同时运行多个线程，而每个线程都是一个完整的 Claude Code 会话。因此，项目可能会更快达到用量上限。你可以查看项目专属用量，并为协调器聊天以及工作线程分别选择所用的模型和努力等级。

线程目前运行在云端；很快它们将可以在你自己的机器上运行，与本地工具和代码并行，并处于你的网络之内。

开始使用[项目](https://claude.ai/projects)。
