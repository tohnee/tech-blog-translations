# Anthropic 网络安全团队如何用 Claude Code 构建威胁检测平台

> 原文：[How Anthropic's cybersecurity team built a threat detection platform with Claude Code](https://claude.com/resources/articles/how-anthropic-uses-claude-cybersecurity) · Claude 博客

*Jackie Bow 是 Anthropic 检测平台工程团队的技术负责人，她分享团队如何使用 Claude Code 构建工具，自动完成告警分诊、加速调查，并改变安全分析师的工作方式。*

在整个职业生涯中，Jackie Bow 一直在设想这样的工具：它们能接入真正重要的上下文——不只是日志和告警，还有 Slack 对话、内部文档，以及那些能告诉你某件事是真实威胁还是只是噪音的机构知识——而无需人类承担手工翻查数据的重负。

加入 Anthropic 后，她终于有机会把它们做出来——而 Claude 是她的协作者。Jackie 领导 Anthropic 的检测平台工程团队，专注于防御性网络安全：检测威胁、响应潜在入侵，而不是主动探测漏洞。这项工作包括监控系统中的可疑活动、分诊安全告警，以及在异常演变为安全事件之前展开调查。

对一家构建日益强大 AI 模型的公司来说，这项工作是基础性的。[Anthropic 的《负责任扩展政策》](https://www.anthropic.com/news/anthropics-responsible-scaling-policy)把产品发布直接与安全承诺挂钩，这意味着 Bow 的团队在帮助决定公司可以安全地发布什么。

「我觉得现在是安全工程师的黄金时代，」Bow 说，她担任 Anthropic 检测平台工程团队的技术负责人。「我终于能构建我一直希望拥有的工具了。」

## **问题：淹没在数据和告警之中**

安全领域的负责人对这种模式再熟悉不过。

一条告警触发。分析师打开终端，开始那套熟悉的仪式：在五六个不同工具之间来回跳转，每个工具都有自己的查询语言和心智模型。他们必须在多个平台上都保持专业能力，同时在不同界面和查询语法之间不断切换上下文。

每一次调查都变成一场数据考古，要把散落在互不相连的系统中的碎片拼凑起来。对大多数团队而言，简单调查要耗上数小时，复杂调查则可能拖上好几天。

「一个人一天能看的告警数量是有限的，超过这个量，他们深入分析的细致程度就会下降，」Jackie 解释道。

她的团队决定做点什么。他们问自己：什么在消耗我们的精力？什么让人感觉重复乏味？什么阻碍了我们做有影响力的工作？

答案很清楚。在分析师判断出威胁是否真实存在之前，告警分诊可能先吃掉数小时。跨互不相连系统的手动关联拖慢了所有环节。而在查询语言与界面之间的持续切换造成了认知负担，并在一天之中不断累积。

随着公司成长，攻击面在扩大，对安全团队的要求也在提高。

「如果不借助 Claude 这样的东西来增强，我们无法扩展出满足 Anthropic 需求的能力，」Jackie 说。

## **解决方案：CLUE（Claude 查找证据）**

在几个月里，Bow 的团队构建了 CLUE——一个重新构想安全团队如何调查威胁的检测与响应平台。CLUE 没有在技术栈里再加一块仪表盘，而是提供一个由 Claude 驱动的自然语言界面，通过工具使用直接连接 Anthropic 的内部系统。

用 Claude Code 构建 CLUE，把传统软件开发周期指数级地压缩了，让他们得以在日常工作之外额外构建这套系统。Bow 的团队一天之内就做出了可运行的概念验证。设计文档、开发步骤和实现在一周内完成。

「我们构建的东西，很大一部分其实就是我们和 Claude Code 对话，」Jackie 回忆道。「它既是设计伙伴，也是协作者。」

改变她认知的那一刻，是她让 Claude Code 给 CLUE 界面加一个按钮。她本以为又要经历 JavaScript 框架和 CSS 调试那套熟悉的苦役。Claude Code 立刻实现了该功能，而且比她做得更好。

「那一刻我意识到，我不再受自己技术能力的限制。只要我能想到，我就能做出来，」她说。

### **CLUE 分诊**

当告警涌入时，CLUE 分诊会在人类分析师看到之前完成第一轮分诊。Claude 使用工具从 Anthropic 各系统中补充每条告警的上下文——包括 Slack 消息、内部文档、代码仓库和数据仓库。它会给出处置结论（disposition）：误报、真阳性、恶意，或预期行为。每条告警都会获得一个置信度评分，让分析师知道该把注意力放在哪里。

这一步上下文补充解决了一个所有安全分析师都认得出的问题：告警作为孤立信号到达。一次失败的登录尝试。一次异常的 API 调用。一次配置变更。没有上下文，这些事件只是噪音。有了上下文（用户是谁、当时在做什么、这是否符合他们团队以往的模式），清晰的信号就会浮现。

「那些内部上下文正是缺失的一环，它真正帮助把告警放到你的环境里来理解，」Jackie 解释道。

### **CLUE 调查**

借助 CLUE，安全分析师现在可以用自然语言查询所有安全关键日志。想知道「过去一天这个系统所有失败的登录记录是什么？」直接问 CLUE，Claude 会执行必要的 SQL 查询。

「Claude 在写精确查询方面比人类强得多，」Jackie 说。这个工具运行一个智能体循环：一个编排器向子智能体下达命令，子智能体并行执行查询、收集发现，并把结果综合成条理清晰的调查摘要。过去需要数小时手动关联的工作，现在三到四分钟就能跑完。

数字可以证明这一点。在所有调查中，CLUE 平均每个会话调用 25 次工具、执行近 11 次查询——远超分析师合理的手工操作量，而且精确度更高。这些工具调用中的每一次，在别的情况下都需要打开一个独立控制台或切换到另一个界面。

然而真正的差异化在于内部上下文。CLUE 通过工具直接连接 Anthropic 的系统，让 Claude 获得外部安全平台永远无法访问的机构知识。当告警触发时，Claude 可以查 Slack，看团队是否讨论过计划内维护。它可以查询数据仓库以理解基线行为。它可以检查代码仓库以了解某个服务实际在做什么。

### **数据治理审查**

团队用一个常见的数据治理场景演示了 CLUE 的能力：检查三名承包商在过去两个月里是否访问过任何他们本不该访问的文档。

据 Bow 说，这类调查通常至少要花半天手工工作，包括查询访问日志、交叉核对权限、审阅文档密级。有了 CLUE，Claude 会读取请求、制定计划，并生成冗长的查询——这些查询把技术复杂性封装了起来。调查几分钟内结束，产出摘要和建议，并且对执行过的每一条查询都有完全透明的记录。

## **衡量影响**

团队在着手构建 CLUE 时，想弄清楚的不仅是它「感觉」更快，还包括能否量化结果。

**更少的误报**：在 CLUE 分诊之前，大约每三条告警中就有一条最终是误报。这一比例已降至 7%，意味着分析师把时间花在真正重要的信号上。\*

**更广的覆盖**：也许比速度更重要的是团队现在能够检查的范围。在 CLUE 之前，置信度较低的信号不会被检查，因为根本没有时间。现在，CLUE 分诊会对每条进来的告警进行上下文补充，批处理则能处理成千上万个过去只会成为仪表盘噪音的信号。

**规模化的时间节省**：基于 30 天的使用数据，CLUE 自动化执行了约 12,000 次查询和 27,000 次工具调用——这些工作若手工完成，估计需要 1,870 小时（234 人天）。相比人工分诊，这相当于 5 到 10 倍的时间节省。\*

**他们仍在学习如何衡量的东西**：准确率比速度更难量化。团队会审阅 CLUE 的处置结论并跟踪分歧，但他们仍在构建反馈闭环，以理解 Claude 有多大比例发现了分析师本会漏掉的东西——以及反过来，分析师发现了 Claude 漏掉的东西。对话记录有所帮助：每一次调查都可以被审计，确切看到 Claude 检查了什么、又是如何得出结论的。

## **前进方向：让 Claude 像 Claude 那样调查**

AI 研究中有一个概念叫「[苦涩的教训](http://www.incompleteideas.net/IncIdeas/BitterLesson.html)」——其观察是：把人类特有的推理方式编码进模型，其效果始终不如给模型通用能力、让它们自己寻找方法。Bow 和她的团队一直在思考这对检测与响应意味着什么。

「在 CLUE 开发的早期，团队争论过应该对 Claude 的调查路径施加多少约束，」Bow 说。「SOAR 时代的本能告诉我们：构建剧本（playbook）、定义每一步、让流程确定化。但我们不断注意到一件事。当我们给 Claude 探索的自由度——给它工具和一个目标，而不是一条固定序列——它常常走出我们不会规定的调查路径。有时这些路径会揭示出我们本会错过的上下文。」

关键在于给 Claude 划定边界（它能用哪些工具、能访问哪些数据），同时让策略保持开放。这一洞见也塑造了 CLUE 接下来的方向。

**从被动到主动**：今天，CLUE 响应告警。一个事件触发，Claude 展开调查。但这套架构支持更具野心的目标：持续探索。不必等待检测规则触发，Claude 智能体可以主动搜寻可疑模式——那些不匹配团队已写任何规则的异常，那些单独看很正常、聚合起来却不寻常的行为。

**从自身学习**：团队存储了每一次调查的完整记录。这个语料库正在成为一个知识库，Claude 可以查询其中过往调查如何展开的模式。随着时间推移，CLUE 会发展出任何人类分析师都无法维护的组织记忆。

**拥抱非确定性**：传统安全工具把不一致视为 bug，CLUE 把它视为特性。同一条告警在不同日期可能以不同方式被调查，这没问题——有时第二条路径会发现第一条漏掉的东西。团队正在试验并行运行多种调查策略并比较结果。

「安全运营的苦涩教训是什么？我们花了多年时间构建那套编码了『人类如何调查』的系统。下一代工具应该赋予模型调查的能力，让它们找到比我们规定更好的方法，」Bow 补充道。
