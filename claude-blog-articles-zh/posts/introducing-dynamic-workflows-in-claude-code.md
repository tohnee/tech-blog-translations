# 推出动态工作流

> 原文：[Introducing dynamic workflows](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code/) · Claude 博客

**更新：**动态工作流现已正式发布（generally available）。

今天，我们在 Claude Code 中推出动态工作流（dynamic workflows），帮助 Claude 端到端地承担最具挑战性的任务。过去需要按季度规划的工作，如今几天内就能完成。Claude 会动态编写编排脚本，在单个会话中运行数十到数百个并行子智能体，并在任何结果送达你之前先检查自己的工作。

有些问题对单个智能体的一次执行来说太过庞大，尤其是在复杂的遗留代码库中：横跨整个服务的 bug 排查、涉及数百个文件的迁移、一份你希望在拍板之前从各个角度经受压力测试的计划。动态工作流都能端到端地处理。

动态工作流已在 Claude Code CLI、Desktop 和 VS Code 扩展上面向 Pro、Max、Team 和 Enterprise 计划正式发布，同时在 Claude API、Amazon Bedrock、Vertex AI 和 Microsoft Foundry 上也可用。

注：动态工作流消耗的 token 可能远多于一次典型的 Claude Code 会话，因此我们建议先从一个范围明确的任务入手，感受一下它在你工作中的用量。

要获得最佳体验，请在使用动态工作流时开启自动模式（auto mode）。在此基础上，有两种启动工作流的方式：

1. 直接让 Claude 创建一个动态工作流（例如「创建一个工作流」），或者
2. 打开 Claude Code 专属的新设置 `ultracode`。可以通过努力等级（effort level）菜单访问它，它会将努力等级设为 xhigh，同时让 Claude 自动决定何时使用工作流来处理你的任务。

## **动态工作流的实战应用**

抢先体验用户和 Anthropic 内部团队已经在众多场景中使用动态工作流，包括：

- **全代码库 bug 排查、性能分析器（profiler）引导的优化审计以及安全审计：**Claude 并行搜索某个服务或仓库，然后对每一条发现都运行独立验证，确保报告呈现的是真实问题。同样的模式也适用于加固扫描：对整个代码库做认证检查、输入校验和不安全模式排查。
- **大型迁移与现代化改造：**Claude 可以端到端处理跨越数千个文件的框架更换、API 弃用迁移和语言移植。
- **需要复核的关键工作：**当错误答案的代价很高时，工作流会让 Claude 以相互独立的尝试去解决问题，并让对抗性智能体在你看到结果之前设法推翻它。

「动态工作流在大代码库的探索和审查任务中尤其有价值。我们用它识别死代码、发现传统静态分析遗漏的清理机会，效果很好，帮助我们的工程师更快地推进维护和重构工作。」

「动态工作流填补了『派出单个子智能体』与『搭建完整智能体团队』之间的空白。从规划到实现一气呵成，我们既能信任更长时间的运行，又不会失去可见性。」

### **用动态工作流重写 Bun**

动态工作流在大规模场景下能解锁什么，最近对 Bun 的重写就是一个例子。Jarred Sumner 用动态工作流把 Bun 从 Zig 移植到 Rust，现有测试套件通过率达 99.8%，产出约 75 万行 Rust 代码，从首次提交到合并只用了十一天。一个工作流为 Zig 代码库中的每个结构体字段找出合适的 Rust 生命周期；下一个工作流把每个 .rs 文件写成与其对应 .zig 文件行为完全一致的移植版，数百个智能体并行工作，每个文件配两名审查者。随后一个修复循环驱动构建和测试套件，直到两者都干净通过。移植落地之后，一个通宵运行的工作流处理了不必要的数据拷贝，并为每一处分别开了一个 PR 供最终审查。虽然尚未投入生产，但这一切都由动态工作流完成。Jarred 之后还会就此撰写更多内容。

## **工作原理**

工作流启动时，Claude 会根据你的提示动态规划，把任务拆解为子任务，并把工作分派给并行运行的多个子智能体。结果在被合并之前会先经过检查，你最终得到的是一个经过统筹的单一答案。各个智能体从相互独立的角度处理问题，另一些智能体则设法推翻它们的发现，运行过程持续迭代，直到答案收敛——这正是工作流能得出单次执行无法企及的结果的原因。

动态工作流为可延续数小时乃至数天的并行、长时任务而生，承担以往需要数周才能完成的复杂工程工作。运行过程中会持续保存进度，因此被中断的任务会从断点继续，而不是从头再来。由于协调发生在对话之外，无论任务规模多大，计划都不会跑偏。

需要注意的是，动态工作流消耗的用量明显高于典型的 Claude Code 会话。工作流第一次触发时，Claude Code 会展示即将运行的内容并请你确认。组织管理员也可以选择通过托管设置（managed settings）禁用工作流。

## **开始使用**

动态工作流对 Max、Team 和 Enterprise 计划默认开启，通过 API 使用 Claude Code 时同样默认开启。Pro 计划用户可以在 `/config` 中启用。让 Claude 创建一个工作流，或打开 Claude Code 专属设置 `ultracode`，即可开始。管理员可以在[设置](https://code.claude.com/docs/en/settings)中管理可用性。

阅读[文档](https://code.claude.com/docs/en/workflows)了解更多。
