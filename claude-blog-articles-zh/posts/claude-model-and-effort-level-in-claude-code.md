# Claude Code 中的努力等级与模型选择

> 原文：[Claude Code effort level and model selection | Claude](https://claude.com/blog/claude-model-and-effort-level-in-claude-code/) · Claude 博客

**核心要点**：

- 模型选择决定的是模型所使用的那一组固定权重，也就是模型整体的能力范围。虽然可以为模型提供上下文、对模型进行引导，但模型的整体知识库与能力是设定好的。
- 努力（effort）的含义远不止「思考时间」。它控制 Claude 在处理你的请求时总共投入多少工作，包括读取多少文件、使用多少工具，以及在回头向你确认之前要走多少步。
- 例行任务选更小的模型，复杂或模糊的任务选更大的模型。从每个模型的默认努力等级（effort level）开始，再根据你从事的工作类型将其作为总体偏好来调整，而不是逐任务调整。
- 如果 Claude 已经掌握了所有相关上下文、也明显尽力了，却仍然出错，这是换用更强模型的信号。如果 Claude 出错的方式是漏掉了某个文件、没有运行测试，或在重构中途放弃，那就选更高的努力等级。

## **Claude Code 中的努力等级与模型选择**

Claude Code 提供了两项看似都能「让答案变更好」的设置：模型设置与努力等级。你或许会以为，Claude Fable 5 这样更大的模型会比 Claude Sonnet 给出更聪明的输出，而更高的努力等级意味着 Claude 在回答之前思考得更久。

第一个假设是准确的。按照行业标准基准测试，我们最大的模型确实能力更强。

但努力（effort）的含义远不止「思考时间」。努力等级控制的是 Claude 在处理你的请求时总共投入多少工作。这确实包括模型思考多久，但也包括：

- 它读取多少文件；
- 它做多少验证；以及
- 在回头向你确认之前，它会把一个多步骤任务推进到多远。

在更高的努力等级下，Claude 会执行更多这类动作（例如读文件、运行测试、反复核对）之后才回到你这里。在更低的努力等级下，它宁可向你索要更多上下文，也不愿花 token 自己琢磨。

## **模型选择是如何工作的**

当你按下回车，Claude Code 会把你的消息与系统提示、工具定义、你的 CLAUDE.md、对话历史以及上下文中的所有文件组装在一起，作为一次请求发送给 API。

Claude Code 拥有的一切都被打包进同一次 API 请求。在服务器端，文本在到达模型之前会先被分词（tokenization）。

不过，模型从未把这些内容当作纯文本看到。服务器上发生的第一件事是**分词（tokenization）**：文本被切分成一个个片段，每个片段被映射为模型训练时所用的固定词表（vocabulary）中的一个整数。const 可能映射为 1978，await 可能映射为 4293。从这一刻起，你的提示就是一个整数数组。

分词器把你的文本切分成片段，并将每个片段映射为固定词表中的一个整数。上行的每个片段都成为下行的对应 token ID；图中 ID 仅为示意。

模型的任务是拿这个数组预测下一个 token。它为词表中的每一个 token 计算一个*概率*，然后从最靠前的候选中挑选。在 const x = await 之后，训练良好的模型会给 fetch 赋予很高的概率（非常可能出现），而给 banana 赋予接近零的概率（根本不可能）。

模型的预测是词表中每个 token 各自的概率。最可能的猜测与一个无关猜测之间的差距是巨大的。

把你的输入 token 变成这些概率的，是**权重**（weights，也称*参数*（parameters））。权重是数十亿个数字，被组织成一个个巨大的矩阵。要预测一个 token，模型会让输入经过这些矩阵——一长串矩阵乘法——并在最后读取概率。模型「知道」的一切都存在于权重之中。

**每个模型的权重都在训练期间确定，等你开始发送请求时，它们已经是只读的了。**你的提示、你的 CLAUDE.md 或上下文中的任何内容都无法改变它们。（如果你见过「推理」（inference）这个词，它的全部含义就是：训练完成后使用模型，权重保持固定。）

你的提示进入，概率输出。中间的权重不会改变。

Claude 所了解的一切——TypeScript、流行框架、地道的 Go，或任何其他通用编程知识——都是在训练时编码进这些权重的。

你的提示与上下文仍然可以*引导*（steer）预测——把你真实的代码放在 Claude 面前就是*引导*，而且效果非常好——但它们并不会给权重本身增加任何东西。

如果某个库在模型训练时还不存在，它就不在权重里。你可以把文档放进上下文，Claude 会使用它们，但那是*引导*，不是*教导*。Claude 的响应只会在这一次请求中受到影响；底层模型并没有记住这些信息。

所以，当 Claude 自信地调用一个并不存在的 API（即幻觉（hallucination））时，那是权重按照训练模式生成了*看起来*合理的 token 序列，而不是一次失败的查询。

那么，更换模型究竟改变了什么？它更换的是处理你请求的**那一组冻结权重**。

模型不会一次性生成完整的答案。它一次预测一个 token，把它追加到序列上，再重新执行整个计算来得到下一个 token。一段 200 token 的响应就是对权重进行的 200 次独立计算。你的等待时间和输出成本大部分都来自这个循环。

序列每一步恰好增长一个 token。模型每次都会重新读取整个数组，来预测接下来是什么。

所以，**模型设置**决定由*哪组权重*处理你的请求，同时也决定每个输出 token 的成本。

它不决定的是生成多少个 token。同一个提示，这个数字可能差异很大，取决于 Claude 决定投入多少工作。

这正是**努力等级**所控制的：Claude 在每一轮中决定投入*多少工作*。

## **Claude Code 努力等级是如何工作的**

当 Claude Code 处理任务时，它生成的 token 可以分为几类：

- **思考（Thinking）**：你在各个动作之前和之间看到的流式推理内容。
- **工具调用**：指名某个工具（如 Read 或 Edit）及其参数的结构化块，由 Claude Code 解析并执行。
- **发给你的文本**：计划、进度更新，以及最后的总结。

这些都是同一个循环产生的普通输出 token，按相同费率计费。例如，思考 token 的生成方式与其他输出 token 完全相同，并会在这一轮的剩余时间里留在上下文中。

当 Claude 接下来开始写代码时，它早先的推理就如同它读过的某个文件一样，成为输入的一部分。

Claude 的全部输出都是 token。思考、工具调用和发给你的文本都来自同一个循环。

努力等级如何改变这一切？努力等级会作为请求的一部分，与你的提示一起发送给模型。模型经过训练，懂得在每个努力等级下该如何表现，这种习得的行为已固化在冻结的权重之中。

当你的请求到达时，努力等级只是模型响应的又一个输入，与它响应你的提示文本的方式相同。它为 Claude 设定了行为标准：在认定任务完成之前，需要做到多彻底、多有把握。

**每一轮交互都会将努力等级纳入考量**，并会生成更多 token，以得出置信度更高的答案。

同一提示，两种努力等级。高努力路径生成了约 7 倍的 token，以得出置信度更高的答案。

在更高的努力等级下，Claude 通常会先制定一份计划，努力等级会影响这份计划的深度与广度。不过，计划并非一成不变。随着 Claude 收到各项动作的结果，它会更新目前已取得的进展，以及它对累积结果的把握程度。

所以，当一个「三假设」调试计划的第 1 步就找到了 bug 时，「调查假设 2 和 3」可能就不再是必要的动作了。Claude 通常会明确说出这一点——「第一次检查就找到了，所以剩下的检查不需要了」——然后直接跳过。当任务列表在执行中途被修订时，你就能在 Claude Code 中看到这种情况的发生。

在更高的努力等级下，Claude 会更倾向于复核其他假设或验证正确性，但对于简单任务，它在高努力等级下一般不会人为拉高用量。事实上，我们的团队在模型训练过程中非常关注「过度思考」（overthinking），因为它会损害效果。

## **如何选择努力等级**

我们的建议是：**对大多数任务，使用模型的默认努力等级**。默认等级指的是：Claude 会按照大多数人愿意在某项任务上投入的量，来伸缩自己的 token 用量。

把努力等级当作一个手动调节的开关，用来控制 Claude 工作的强度与时长。当你基于自己的领域或工作类型，对彻底性或速度有强烈偏好时，再有意识地选择它。这更应该被视为一种总体偏好，而不是逐任务的决定。

关于 [Claude Opus 4.8 发布](https://www.anthropic.com/news/claude-opus-4-8)后的一点实用参考：在测试中我们发现，对同一任务使用 Opus 4.8 的默认努力设置，与使用 Opus 4.7 的默认努力设置相比，可以在大致相同数量的 token 下产出更好的结果。

## **当 Claude 出错时，该调整什么**

当 Claude 出错时，你的第一反应不应该是去拧某个旋钮，而是检查你所提供的上下文。你的提示是否太模糊？Claude 是否连接了正确的工具？是否配备了合适的技能？

如果你在一个*本不该*调高努力等级的任务上调高了它，修复方法往往在上游：在你的上下文、你的 CLAUDE.md，或任务的界定方式里。

但假设你已经提供了清晰的上下文，而 Claude 仍然出错，那么要问自己的问题是：它是*不够努力*，还是*了解不够*？

两个问题，一个兜底判断。把这套启发式方法当作起点来选，而不是硬性规则。

### **模型：问题本身太难**

当问题真正困难时，选更大的模型。例如微妙的 bug、不熟悉的领域，或架构决策这类问题。当小模型无论你给它多少上下文都自信地答错时，更大的模型会有帮助。

更大的模型也更擅长处理模糊性；而明确指示执行方式的指令，则是在更小的模型上更可靠的取胜之道。

当工作是例行性的，选更小的模型。例如你可以精确描述的修改、机械性的改动，或关于已在上下文中的代码的问题。没有理由为任务用不到的能力付费。

如果 Claude 掌握了所有相关上下文、明显尽力了，却仍然出错，这是换更大模型的信号。如果你已经在更大的模型上，而工作在一段时间内都是例行性的，那么降级会提升速度，通常会降低成本，且不影响输出质量。

### **努力：Claude 没有足够努力**

如果 Claude 出错的方式是跳过了某个文件、没有运行测试，或没有复核自己的工作，就选更高的努力等级。当你把努力等级设在模型默认值以下时，这一点最为相关。

Fable、Opus 与 Sonnet：专才、专家与通才

我喜欢用这样一种方式理解这两个设置的关系：Fable 是一位见过的难题几乎无人能比的专才（specialist），Opus 是专家（expert），而 Sonnet 是一位非常出色的通才（generalist）。努力等级决定的是他们中的任何一位在你的任务上花多少时间。

**低努力等级的 Opus** 就像你获得了一位专家五分钟的指点，他对类似你的问题有着深厚经验。他带来的知识在你的代码库中任何地方都找不到：他见过的模式、他知道要去排查的坑，是只有解决过大量同类问题才能积累的那种东西。但只给他五分钟，意味着对你的代码只是快速扫一眼，而非仔细研读。

**高努力等级的 Sonnet** 就像你把整个下午交给一位非常出色的通才。他会读完所有东西、运行程序、复核自己的工作，最终彻底理解*你的这段具体代码*。他欠缺的，是那种「我以前恰好见过这个问题」的识别力。

**Fable，哪怕在低努力等级下**，也是那位瞥一眼所有人都卡住的问题、仍能发现别人发现不了的症结所在的专才。这种识别力正是你花最多钱买来的东西，所以值得把它留给真正需要的任务。

没有哪一个是全面更优的。模型设置大致决定*能力多强*；努力设置大致决定*多彻底*。大多数真实任务两者都需要一些。

## **努力等级、模型与 token 消耗**

那么，模型选择、努力等级和 token 消耗究竟是如何相互作用的？这取决于任务。

在同一努力等级下处理例行工作时，两个模型通常都能做对。更大的模型会以更高的单 token 价格，通过额外的验证步骤消耗更多 token。这就是为什么在例行性的工作段落里切换到更小的模型，能在不损失质量的前提下省下真金白银。

曲线仅用于示意，展示的是某一项简单到两个模型都能快速完成的任务。它们不代表真实基准测试数据。

在更困难的多步骤工作上，等式就不一样了。更小的模型必须艰难地逼近自身能力的极限，烧掉一轮又一轮迭代；而更大的模型用更少的步数就达到了同样的质量标准。

你为更大的模型付出了更高的单 token 价格，但在那些真正让小模型吃力的任务上，每任务总成本反而可能更低。而且更重要的是，更大的模型能完成小模型即使在最高努力设置下也无法完成的任务。

这一点在 Fable 上最为明显。在漫长的多步骤工作上，它领先得最多。在我们的测试中，它完成了 Opus 和 Sonnet 在任何努力等级下都无法企及的工作。它的单 token 成本也最高，这是把它留给真正需要的工作的另一个原因。

曲线仅用于示意，展示的是某一项难到能让两个模型都吃力的任务。它们不代表真实基准测试数据。

另一个细微之处：努力等级会塑造 token 消耗，但并不限制它。系统中唯一的硬性上限是 [max_tokens](https://platform.claude.com/docs/en/build-with-claude/extended-thinking#max-tokens-and-context-window-size-with-extended-thinking)，一旦触顶，它会在流式输出中途截断响应。这是一件粗钝的工具，主要与 API 开发者相关。更柔和的控制手段，比如[任务预算](https://platform.claude.com/docs/en/build-with-claude/task-budgets#task-budgets-are-advisory-not-enforced)（task budgets），或在提示中让 Claude 长话短说，是更有用的工具。它们是模型经过训练会遵循的指引——如果接近限额，模型会倾向于收尾结束任务——而不是一堵撞上才停的墙。

## **先用默认值，再去拧旋钮**

大多数时候，你根本不需要考虑这两项设置。当结果不达预期时，问一句「Claude 是了解不够，还是努力不够？」然后按需调整。
