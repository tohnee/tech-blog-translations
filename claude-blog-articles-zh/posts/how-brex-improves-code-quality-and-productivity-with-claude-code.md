# Brex 如何借助 Claude Code 提升代码质量与生产力

> 原文：[How Brex improves code quality and productivity with Claude Code](https://claude.com/resources/articles/how-brex-improves-code-quality-and-productivity-with-claude-code) · Claude 博客

了解 Claude Code 如何通过让编程更简单、更可及，打破技术团队与非技术团队之间的壁垒。

两年前，Andy Reed 以内容设计师的身份加入 [Brex](https://www.brex.com/) 时，从没想过自己会写代码、做 Figma 插件。

「没有 [Claude Code](https://claude.com/product/claude-code)，我根本不知道过去一个月里连一半的工作要怎么完成，」Reed 说。

但这恰恰就是 Reed 用上 Claude Code——Anthropic 的智能体编码解决方案——之后发生的事。而他的故事，只是这个智能金融平台如何改变公司工作方式的一个例子。

为了解更多，我们与三位 Brex 团队成员聊了聊他们如何使用 Claude Code：

* Hércules Gimenes，产品 AI 团队软件工程负责人
* Sumeet Marwaha，数据与分析负责人
* Andy Reed，高级内容设计师

这些对话呈现的，不只是生产力提升的故事——尽管各团队报告在特定任务上取得了 3 到 4 倍的提升。它关乎从根本上重新构想公司如何协同工作，以精简工作流、激发创造性的问题解决，并推动大规模协作。

## 以智能体编码完成一次思维转变

对 Hércules Gimenes 和产品 AI 团队来说，Claude Code 代表的东西比一个新工具更深刻。

「Claude Code 带来的是一种思维方式的转变，」他解释道，「你不再坐在驾驶座上，而是成为 Claude 所引入变更的审查者。你在引导愿景和方向。」

Anthropic 自己对这一转变的实践，见[《AI 原生 SDLC 手册》](/resources/articles/the-ai-native-sdlc-playbook)

关于 Claude Code 团队自身如何处理审查，见[《Claude Code 团队如何做代码审查》](https://claude.dev/blog/solving-code-review-at-anthropic/)

这一转变重新定义了「写代码」在 Brex 的含义——这也是公司「AI 优先」原则的实践体现。工程师不再把时间花在实现细节上，而是聚焦于架构和问题解决。结果如何？更好的代码，而不只是更快的代码。

「我不觉得自己用 Claude Code 是在省时间，」Gimenes 说，「我更多是在打磨问题本身。你可以在同样的时间里针对同一个问题尝试三种方案，到第三种之后，你对问题的理解和接口设计都清晰干净得多。」

## 打破技术与非技术角色之间的壁垒

当产品 AI 团队在探索迭代代码质量的新方法时，Reed 也经历了自己的顿悟。

作为一名内容设计师，他在 Claude Code 中找到了意想不到的东西：独立性。

以前，改一个简单的字符串就意味着提工单、等工程师。现在，Reed 直接提 PR。但真正的转变发生在他啃下一个长期躺在待办列表里的项目时：把全面的内容规范整合进 Brex 设计系统的每一个组件。

「如果手工做，大概要几周甚至几个月，」Reed 解释说。使用 Claude Code，他几天就完成了这个项目，系统性地加入了从内部风格指南、无障碍标准和外部最佳实践中提炼出的内容专属规范。

影响波及其他团队。工程师和设计师如今在工具中就能直接看到内容规范，不必再反复交叉核对，错误也在发生之前就被减少。这是智能金融在运转的一个小而有力的例子：系统在后台运行，让人们专注于价值更高、更有创造性的工作。

## 让数据访问在整个组织内民主化

与此同时，Sumeet Marwaha 的数据与分析团队正在解决另一个不同但同样重要的挑战：让 Brex 的每个人都能访问数据，而不只是 SQL 专家。

团队构建了 Brex Explorer，一个由 Claude Code 和 MCP 服务器驱动的 text-to-SQL 界面。现在，销售经理可以用自然语言提问：「在佛罗里达州杰克逊维尔，Brex 账户里有超过 1000 万美元、且在过去一年内完成入驻的客户有多少？」系统会转译查询、执行并总结结果。

真正的倍增效应来自他们的 AI 数据工程智能体。过去需要专业知识才能完成的任务，比如添加数据表以及所有必要的文件修改和测试配置，现在任何工程师都能完成。

「这相当于在参与贡献的人数大约翻倍的同时，速度提升了 4 倍，」Marwaha 指出。Claude Code 在整个组织的采用率已达 50%，Marwaha 希望月底能达到 100%。

## 拥有一个「万能工具」的意外收益

随着 Brex 各团队采用 Claude Code，一些令人意外的用例浮现出来。在一次公司黑客松上，Gimenes 用 Claude Code 的无头模式（headless mode）在几个小时内构建了一个复杂的提交智能体——通常这需要数天的开发。

Reed 发现自己如今能构建从前不敢想象的工具，比如一个按照 Brex 标准自动审查设计的 Figma 插件。「感觉就像拥有了世界上最好的实习生，」他说。

但或许最重要的意外收益，是 Claude Code 充当了组织知识库的角色。Brex 使用 Kotlin 和 Bazel 的复杂单体仓库结构，理解不同系统之间如何连接一直是个挑战。现在，Claude Code 就像一个「神谕」，能即时回答有关代码库功能的问题。

「传统上，设计会议会讨论某个东西应该怎样工作，但没人真正了解它是怎么做出来的，」Reed 解释道，「现在，我的另一台显示器上就坐着一个神谕。」

## 在全公司推广 Claude Code 最佳实践

随着 Claude Code 在 Brex 的普及，各团队形成的最佳实践已成为标准：

* **结构化上下文管理**：单体仓库中的每个主要目录现在都有自己的 [CLAUDE.md 文件](/resources/articles/using-claude-md-files)，包含领域专属上下文。新工程师无需依赖口口相传的经验，就能理解 Mastercard 集成细节或银行监管规定。
* **自动化文档**：产品 AI 团队实现了 CI/CD 检查，在代码变更可能使文档过时的时候进行验证并提示更新。「拥有最新的文档，是你可以信赖的一件事——这太强大了，」Gimenes 强调。
* **上下文感知命令**：各团队创建了自动加载相关上下文的自定义命令。例如 /submit-pr 命令会在执行前获取 git status、最近的改动和相关 PR 信息。
* **从发现开始**：「你需要的东西，已经不再只存在某位资深工程师的脑子里了，」Marwaha 观察到，「它在代码库里，人人都能获取。」

## Claude Code 在 Brex 的未来

Brex 各团队已经在规划下一代应用：

* 数据团队正准备攻坚过去不可触碰的项目，比如分析数以万亿计的信用卡交易明细数据点——在 Claude Code 让它变得可行之前，这项工作繁琐到不值得投入。他们还在开发角色专属的智能体，其中一个用于支撑 RevOps 任务。
* 产品 AI 团队则设想更精细的上下文管理：文档自动更新，上下文保持去中心化却又随时可获取。

从内容设计师构建技术工具，到数据分析师让数据访问民主化，Claude Code 已经成为 Gimenes 所说的「万能工具」——用来把 Brex 的领域知识与外部最佳实践整合起来。

这也凸显了一种有力的二元性：Brex 交付给客户的智能金融——帮助客户更聪明地花钱、更快地行动——与塑造 Brex 团队内部工作方式的理念是同一个：让每位员工都能以速度和信心去创造，无论其技术背景如何。
