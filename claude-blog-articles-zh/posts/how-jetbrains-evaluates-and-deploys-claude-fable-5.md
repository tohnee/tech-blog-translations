# 守护前沿：JetBrains 如何评估与部署 Claude Fable 5

> 原文：[Securing the frontier: How JetBrains evaluates and deploys Claude Fable 5](https://claude.com/resources/articles/how-jetbrains-evaluates-and-deploys-claude-fable-5) · Claude 博客

JetBrains 智能体系统 CTO Vladislav Tankov 谈公司如何用私有代码仓库评估前沿模型、团队在什么情况下会选用 Claude Fable 5，以及为什么他把保障机制与数据保留视为使用前沿模型的核心。

JetBrains 打造的是全球开发者日常使用的工具，从 IntelliJ IDEA、PyCharm 到 Kotlin 编程语言，服务超过 1250 万活跃用户以及《财富》全球 100 强中的 88 家。JetBrains 的 CTO Vladislav Tankov 与 Anthropic 分享了其团队如何评估新模型、如何决定何时使用 Claude Fable 5，以及在使用前沿模型时如何看待数据保留与保障机制。

## 对 JetBrains 而言，前沿 AI 在 2026 年发生了哪些变化？

我在 JetBrains 已经 10 年了，我们是最早一批 LLM 供应商的客户。过去一年里，我们从客户和公司内部都有人对 AI 持怀疑态度，转变为普遍认识到 AI 已经站稳脚跟。这是技术产业一次重大的、基础性的变化。公司里可以说每一个原本的怀疑者都改变了看法。

## 你们如何评估新模型，并决定何时使用它们？

我们是一家做编码工具的公司，所以有一套庞大的评估流水线：在私有代码仓库上跑大规模评估集，其中包括我们的单体仓库（monorepo）。我们会仔细核查一个模型在真实工作中是否配得上它的基准测试分数——有些模型经过调优，在公开基准上得分很高，一到实际任务上就掉链子。用私有仓库来检验，这一点要容易得多。我们还会维护排行榜，分别评选质量最佳、每任务成本最低和速度最快的模型。Claude Fable 5 虽然每 token 价格更高，但在某些情况下每任务成本反而更低，尤其是更复杂、耗时更长的工作。

## 相比之前的模型，Claude Fable 5 在你们的评估中表现如何？

Claude Fable 5 比此前的模型既更准确也更高效。它在我们的评测套件中拿下最高的 Python 通过率 44.3%，而 Opus 4.8 为 28.2%，高出 16 个百分点。在两两对比中，Claude Fable 5 解出了 18 个 Opus 4.8 没解出的 Python 任务，只输掉 2 个。它的答案也更值得信任：它的代码跑起来之后，通过我们测试的频率远高于两个 Opus 模型。这一点很重要，因为代码能运行却给出错误答案，是最昂贵的一类失败——最难被发现。

效率方面的表现同样有意思。Claude Fable 5 找到解决方案所需的步骤比 Opus 4.8 少约 22%，因此它能用更少的试错走到可运行的代码。它还会把力气用在正确的地方。在 Java 任务上，Opus 4.8 反复尝试引入外部资源，而在我们的环境里这些资源几乎从来帮不上忙；Claude Fable 5 则完全跳过了这一步，直接处理眼前的代码。总体而言，它表现出更好的工程习惯。

## 什么情况下你们会用 Claude Fable 5 而不是其他模型？

Opus 被视为一匹可靠的「干将」：你可以相当确定它会把活干完。而当你确实需要出色的推理、几乎需要一个伙伴、并且你自己也不确定该怎么做时，才会转向 Claude Fable 5。举个例子，我们的一位技术负责人决定实现一个富文本编辑器组件，这个组件我们过去几年尝试过好几次，而 Claude Fable 5 几乎一次就搞定了。

Claude Fable 5 另一个很受欢迎的用例，是长时间运行的智能体编码实验。我们给一个运行 Claude Fable 5 的智能体提供规格说明（以文本和图片的形式），让它实现复杂的类 IDE 应用。有意思的地方在于，规格说明也可以由智能体基于现有应用自行生成。把这两个部分接起来，我们就能在近乎黑盒的环境中，把应用从一个运行时、框架或语言重写到另一个。

## 面对当今的前沿模型，你们如何看待安全与数据保留？

我们并不是一家想要自己造出最安全模型的公司。我们相信，Anthropic 一侧所做的红队测试以及其他工作，已足以让人相信模型是安全的。然后我们在部署环节采取系统化方法，把安全性建立在能够保证的地方：围绕模型和执行框架（harness）构建基础设施与安全网，而不是去调整模型本身。

安全也是 Claude Fable 5 最大的用途之一。我们对自己的产品做白盒测试来发现漏洞，而我们的安全团队正在为这样一种情况做准备：不只是我们在运行这个模型——公司外部的人也会运行 Claude Fable 5 或同级别模型，来探测我们所有产品的漏洞。由于我们服务于受监管行业的大型企业，做好准备对我们很重要。Claude Fable 5 是在支持我们的工作，而不是阻碍它。

所以这是一个微妙的平衡：你这一侧的分类器越不激进，别人在我们的产品里找到的漏洞就越多——包括那些此前无人知晓的漏洞。

这也不是秘密：我们更希望是零数据保留。但除此之外，我看不到还有什么办法能让你理解当时问了什么、以及分类器可能在什么地方判断有误。只要审查仅限于调查被标记出的最严重案例，我就可以接受。我认为，为了获得让我的团队发挥出最佳水平的前沿智能，这是一个公平的取舍。

## JetBrains 的 AI 路线图下一步是什么？

我们预期各家 LLM 供应商构建的底层模型会持续变得更强。现在真正重要的，是一种面向软件开发的「驾驶舱」：一个智能体与人协作的空间，同时人们也能在其中管理整个开发过程。

对 JetBrains 来说，这是一场重大的转型。我们看到一个机会：围绕驱动这个驾驶舱的智能体化软件开发生命周期，构建下一代产品。开发者将借助智能体交付更多、更好的代码；非技术岗位将在软件创造中扮演更大的角色；组织也将获得所需的治理能力，并清楚看到投资回报。
