# 把 Claude Opus 5.5 用作知识工作的日常主力模型

> 原文：[Using Claude Opus 5.5 as your daily driver for knowledge work](https://claude.com/resources/articles/using-claude-opus-5-5-as-your-daily-driver-for-knowledge-work) · Claude 博客

*Opus 5.5 是 Claude 在 Pro、Max、Ultra 和 Team 方案中的默认模型。本文介绍它与其他模型相比如何，以及如何在知识工作中充分发挥它的作用。*

Claude Opus 5.5 现已成为 Claude 在 Pro、Max、Ultra 和 Team 方案中的默认模型。我们推荐把它作为你知识工作的日常主力模型——也就是当你用 Claude 做研究、分析、写作，或制作备忘录、报告、电子表格和演示文稿（deck）时，始终留在选中状态的那个模型。

如果你或你的团队一直用 Sonnet 做日常工作、把 Opus 留给重分析与复杂项目，那值得重新考虑：能力更强的模型可以用更少的工作量完成一个任务，而[这往往能抵消其较高单 token 价格中的很大一部分](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)。

以下是当前各模型的对比：

我们的模型在知识工作上的对比

| **模型** | **适用于** | **每百万 token 价格（输入 / 输出）\*** | **相对速度** |
| --- | --- | --- | --- |
| Claude Haiku 5.5 | 快速查询，以及速度最重要的高并发工作 | $0.10 / $0.50 | 最快 |
| Claude Sonnet 5.5 | 范围明确的快速任务，以及根据清晰简报产出精修的文档、幻灯片和电子表格 | $2 / $10 | 快 |
| Claude Opus 5.5 | 大多数知识工作：研究、分析，以及需要判断力的成品文档、演示文稿和电子表格 | $4 / $20 | 中等 |
| Claude Fable 5.2 | 最有野心、开放式的技术工作，如编程、金融和科学领域 | $8 / $40 | 中等 |

*\*价格适用于按 token 计费的用量（[模型对比](https://platform.claude.com/docs/en/models/opus-5-5/overview)）。Haiku 5.5 的价格适用于不超过 10 万 token 的提示，更长的提示价格为 $0.50 / $2.50。在 Pro、Max、Ultra 和 Team 方案中，价格更高的模型会更快消耗你的限额。在限时发布优惠之外，Pro 方案以及 Team 和基于席位的 Enterprise 方案的标准席位不把 Fable 5.2 计入限额，因此它会消耗用量点数（usage credits）。*

[**Haiku 5.5**](https://www.anthropic.com/claude-haiku-5-5) 是我们最快、最便宜的模型，专为快速查询以及撰写摘要、整理数据这类高并发工作而构建。这是我们的首个带努力等级控制（effort controls）的 Haiku 模型，因此你可以在切换到更大的模型之前，先让它做一次更仔细的处理。它最适合简短、范围狭窄的任务。如需更长的分析，请切换到 Opus 5.5。

[**Sonnet 5.5**](https://www.anthropic.com/claude-sonnet-5-5) 在简报清晰、范围明确的任务上比 Opus 5.5 更快也更便宜。这类任务例如让 Claude 把已完成的笔记整理成一份精修文档，或按幻灯片模板搭建一套演示文稿。不过，在更高努力等级下，Sonnet 5.5 的单任务成本会接近 Opus 5.5，所以如果你发现自己把 Sonnet 推到 Extra high 或 Max 努力等级，就应该考虑改用 Opus 5.5。

**[Opus 5.5](https://www.anthropic.com/claude-opus-5-5)** 为需要审慎判断的复杂工作而构建，例如研究、财务分析，以及产出成品文档、演示文稿和电子表格。我们为什么推荐把 Opus 5.5 用于日常知识工作，后文会详细说明。

[**Fable 5.2**](https://www.anthropic.com/claude-fable-and-mythos-5-2) 最适合要求最高的推理和长时间运行的工作，例如深入的多步骤研究，或可以交给一大群运行数小时的子智能体来完成的编程任务。对大多数知识工作，从 Opus 5.5 起步，当项目的范围和复杂度确有需要时再转到 Fable 5.2。Fable 5.2 在所有付费方案中可用，不过[它如何消耗你的用量](https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan)取决于你的方案。

无论你用哪个模型，如果 Claude 的表现不如预期，先尝试提高努力等级，再考虑升级模型。如果它已具备上下文、明显努力尝试过，却仍然出错，那就该升级模型了。

## **Opus 5.5 在文档、研究、金融和图表上表现最佳**

Opus 5.5 精确遵循指令并保持在范围内，因此它产出的电子表格、幻灯片和文档往往几乎不需要修改。它对数字和来源也很谨慎。在一次内部研究测试中，Opus 5.5 仅凭一份保存下来的网页快照撰写某公司季度业绩报告，而该公司的财报公告在快照里很难找到。一个自动评分器会对照快照中的页面核对每一个数字和引文，规则是只要出现哪怕一个编造的数字或引文，报告即判定失败。在各档努力等级下，它的 18 份报告中有 16 份通过。

它的写作也比早期模型更清晰。Opus 5.5 把最重要的信息放在最前面，少用行话，并遵循你给它的写作规则；在较长的任务中，它会直白说明自己做了什么、发现了什么，以及需要你提供什么。这也让它的工作更容易被检查——我们把这既视为实用上的好处，也视为安全性上的好处。

Ramp 的资深软件工程师 John Ruelas [表示](https://www.anthropic.com/claude-opus-5-5)：「它写得像个好同事，而且遵循我们的写作规则。一份设计规格文档出来时几乎不需要怎么改就能用；当它重写我们的某个提示时，我更喜欢它的版本，而不是我自己写的。」

财务分析是另一项强项。Opus 5.5 能准确阅读密集的申报文件、财务模型和图表，并在整个项目或交易中持续跟踪上下文。在另一次内部测试中，它分析了两家虚构 HR 软件公司之间的一项拟议合并：先在 Excel 中搭建财务模型，再把它转化为一份高管演示文稿，回答这笔交易在其价格下是否合理。它用 63 分钟完成，而 Opus 5 在相同任务上需要 93 分钟；成本只有一半，模型更详尽，演示文稿也更易读。

投资公司 Walleye Capital 中央股票量化研究工程负责人 Frank Corrao [表示](https://www.anthropic.com/claude-opus-5-5)，在更高努力等级下，Opus 5.5「发现我们自己指令中的分钟索引差了 1，并做了修正，还指出这会让你在评分器那里丢分。它是对的，而我们测试过的模型此前没有一个捕捉到并据此行动过。」

Opus 5.5 是我们视觉能力最强的 Opus 模型。它能准确读取密集的文档、图表、截图和示意图，因此在从文档中提取数据方面很可靠。即使在最低努力等级下，它从密集图表中读取数值的准确度也高于 Opus 5 在最高等级下的表现。

## **更充分地利用 Opus 5.5**

每代新模型都是一次重新检验你交给 Claude 的东西、并丢掉为旧模型养成的提示习惯的理由。

### **先试试这些任务**

* **直接要一个成品文件。** 如果你想要电子表格或文档，就直接要电子表格或文档，而不是要一个大纲自己去搭建。多数情况下，Opus 5.5 能一次从你的请求走到成品文件。
* **让它检查长文档。** 给它一份长计划、报告或演示文稿，让它找出错误和不一致之处。Opus 5.5 能捕捉长文档中容易遗漏的细节，例如演示文稿里的某张图表与其源数据不符。
* **交给它一个研究问题。** 提出一个没有既定答案的问题，让它汇集来源、通读长文档，并把发现写成备忘录、报告或演示文稿。
* **试试视觉类工作。** 它的视觉能力进步可以迁移到设计上，所以可以试着用它做界面原型、搭建网站或为某个概念配图。

![claude opus 5.5 适用任务的示意图](https://assets.claude.com/43af7ca2d9f20a0722825b0c207cd80af4d3fdab.png)

### **改变这些提示习惯**

* **把 Claude 连接到你的工作文件与系统。** 这是让产出贴合你工作实际的最有用步骤之一，因为当 Claude 能通过连接器访问你的文件和系统时，它就能自己去获取任务所需的东西，而不是只依赖你粘贴进来的内容。在 Team 和 Enterprise 方案中，连接器需要由所有者开启后成员才能使用。
* **在第一条消息里说明「完成」是什么样子。** 与其一条一条地给 Claude 下指令，不如描述你的目标、最终产出，以及你希望它在何时停下来向你确认。相比 Opus 5，Opus 5.5 更能把冗长的多部分工作推进到底。
* **删掉「认真思考」「仔细想想」这类话。** Opus 5.5 的思考始终开启，它会根据你的请求和努力等级决定思考多少。在我们的测试中，删掉这些句子后回复启动更快，质量没有明显下降。
* **从中等（Medium）努力等级开始。** Medium 是 Opus 5.5 的默认设置，在我们的编码和知识工作评估中，Opus 5.5 在 Medium 下追平或超过了 Opus 5 在 High 下的表现。更高的设置会思考更久、花费更多，却不一定产出更好的工作，所以只在 Medium 卡住时才升到 High。要更改设置，点击发送按钮旁边的模型名称，然后选择 Effort。
* **直接附图，而不是重新录入。** 把图表、截图或示意图本身发过来，而不是把其中的数字复制到提示里。为早期模型设计的变通做法——比如把图表数值逐项转写——可能已经不再需要。
* **点名你不想要的风格。** 做设计工作时，像「避免平庸感」这样的笼统指令，往往只是把一种默认风格换成另一种。具体指出要避免的样式——比如米色背景或药丸形按钮——效果更好。
* **把你们自己的风格规范给它。** 把品牌或写作规范粘贴到请求里，或让 Claude 参考你现有的最佳演示文稿（比如放在它能通过连接器访问的 Google Drive 文件夹里），并要求它与之保持一致。要做好来回几轮才能完全到位的准备。

![claude opus 5.5 提示习惯的示意图](https://assets.claude.com/d61fa79e1e1a38bd6ad4547ddb66c993ef569705.png)

关于努力等级的这一发现在早期测试者那里同样成立。Factory 的技术员工成员（Member of Technical Staff）Zimu Li [表示](https://www.anthropic.com/claude-opus-5-5)：「Claude Opus 5.5 是我们第一个会默认开中等努力等级的模型。在我们的测试中，它以少 20% 到 25% 的输出 token 追平了 Opus 5 在高努力等级下的表现。」

## **在一个演示项目中测试 Opus 5.5**

以下这些，在一次演示中我们完整走过的一个项目里是什么样子。在一家假想的零售公司，过去一年营收增长放缓，管理层对原因有四种推测，而一位分析师手头有一个文件夹的材料：按门店划分的销售电子表格、最近一次管理层线下务虚会（off-site）的 PDF，以及其他文件。用 Opus 5.5 在中等努力等级下，提示词大致是这样的：

`今年增长放缓得很厉害。管理层对原因有几个推测；都记在[我经理]的便签里。我手头所有东西都在上传的文件夹里。请用数据逐一检验这四种推测，并告诉我哪些站得住脚。`

这条提示没有要求 Claude 认真思考，也没有说明某个推测该查哪个文件。它陈述了目标和最终产出是什么样，把方法交给 Claude 自己决定。

Claude 发现数据不支持这四种推测中的任何一种，不过其中一个无法完全排除。随后它提出了一个没有人想到的解释：新店开得离既有的门店太近，把销售额从后者那里吸走了。当门店按城市列出时，这一模式有些模糊；而按与新店的距离筛选之后，就变得清晰了。Claude 还做了一次销售额影响与距离之间的回归分析，作为该发现的支撑。

接下来，Claude 把分析转成了一份文档，其中在文字之外还包含图表和交互元素，包括一个滑块，用来展示销售额如何随新店与既有门店之间的距离而变化。一位同事同时在审阅这份文档。

随后经理让 Claude 把这份文档转成董事会幻灯片，并且开篇就给出结论。对于不使用 Claude 的同事，文档可以导出为 Word、PDF 或 Google Docs，演示文稿可以导出为 PowerPoint、PDF 或 Google Slides。

想看到包括问答环节在内的完整项目，可[点播观看 Opus 5.5 for Work 场次](https://claude.com/resources/webinars/opus-5-5-for-work)。

## **在你自己的工作里试用 Opus 5.5**

挑一件你平时会拆成多次请求来完成的事，比如一份研究备忘、一次差异分析（variance analysis），或一套基于既有文档搭建的演示文稿。在一条消息里把文件和成品描述交给 Opus 5.5，保持中等努力等级，然后把它给出的结果与你在其他模型上习惯得到的结果做比较。
