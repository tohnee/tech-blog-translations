# Curative 如何用 Claude 上的智能体构建全国性医疗提供者网络

> 原文：[How Curative is building a national provider network with agents on Claude](https://claude.com/resources/articles/how-curative-is-building-a-national-provider-network-with-agents-on-claude) · Claude 博客

Curative 负责交易的智能体每周谈判 2,000 多份医疗提供者合同。

*在「初创公司如何用 Claude 构建产品」系列中，我们介绍初创公司如何用 AI 改造自己的行业。本文分享 Curative 如何在 Claude 上构建一套层级化的智能体体系，使提供者合同的签署速度比其团队 2025 年的水平快约 50 倍。*

| 快速概览 |
| --- |
| 名称 | Curative |
| 成立时间 | 2020 年；2022 年推出其健康保险计划 |
| 创始人 | Fred Turner（CEO）、Isaac Turner（CTO）、Tami Wilson-Ciranna（总裁） |
| 技术栈 | Claude Platform、Claude Code、自研理赔系统 |
| 增长 | [以 12.75 亿美元估值完成 1.5 亿美元 B 轮融资](https://www.businesswire.com/news/home/20251202857803/en/Curative-Raises-$150-Million-in-Series-B-Funding-to-Redefine-the-Future-of-Health-Insurance)（2025 年 12 月）。165,000+ 会员、1,200+ 雇主。与 Gwen 签署了 23,000 份提供者合同。每周新增 2,000 至 2,400 份合同，而 2025 年全年为 2,100 份。 |

[Curative](https://curative.com/) 向雇主销售健康保险：会员完成一次 Baseline Visit 后，网络内诊疗的共付额为 0 美元、免赔额为 0 美元。Curative 并非从保险业务起家，它最初是一家实验室初创公司，据其内部估算，最终处理了全美 10% 的新冠检测。也正因如此，它开始与全美几乎所有保险公司合作。

它的英国创始人习惯了患者无需为诊疗付费的体系，从中看到了低效之处，于是着手打造一家以预防为核心的支付方。他们随后意识到，自己严重低估了建设全国性网络的难度。

「在初创公司里，天真有时是件好事，因为你不知道这件事是不可能的。然后一路走来，你会想办法让它变得并非不可能，」Curative CEO Fred Turner 说。「去年我们签了 2,100 份合同，是前一年的两倍，但按每年 2,000 份计算，我们意识到这仍将是一项需要 30 年才能完成的工程。全国性网络屈指可数，而且它们都是在约 30 年前建成的，这是有原因的。」

Curative 需要加速合同签署，但仅靠招聘无法弥合如此巨大的缺口。

他们的解决方案是 Gwen：一个从初次接触到签约全程负责单笔提供者交易的智能体，周围环绕着若干更小的智能体，负责审查其费率、检查其消息、回答其问题，并在遇到非标准定价时上报给人类。

以下是他们的构建过程，以及途中遇到的问题。

## **Gwen：医疗提供者合同智能体**

Gwen 同时处理入站和出站线索。Gwen 的每次运行只处理一个提供者，主要运行在 Claude Opus 上，因此其他交易的信息不会影响它。

例如，如果一家诊所在 Curative 网站上填写表单，Gwen 会调研该诊所，并基于采购的理赔数据集以及支付方如今被要求公布的价格透明度文件，回复建议费率。Gwen 会向提供者展示这些市场费率数据，以协助谈判。

费率审查员运行在 Sonnet 上。当 Gwen 想要超出标准费率模板时，它会写出理由，由审查员判断该费率是否合理。

「很长一段时间里，Gwen 如果想在模板基础上高出一定幅度，就必须经过一个庞大的审批队列；但随着时间推移，我们放宽了限制。让第二个智能体来审查费率，比直接给 Gwen 更大权限效果更好，」Fred 说。

Sonnet 费率审查员会通过 Gwen 大约三分之二的请求，其余非标准的请求则提交给 Fred 审批。

「我看到的请求要么来自大型医疗集团，要么是一些奇怪的请求——即使这件事不由智能体主导，这些请求也照样会找到我，」Fred 说。

出站交易需要更多坚持，因为诊所都很忙。有些提供者的回复出现在第十四封邮件和第九份传真之后。

图片经 Curative 授权使用。

一个运行在 Haiku 上的审核智能体（judge）会在每条消息发出前通读一遍。Curative 是在 Gwen 把「最高可让到多少」的内部笔记抄送给提供者之后才加上它的。被拦截的消息会连同原因一起返回，Gwen 可以据此重写并再次尝试。

每份合同完成约需 2,000 万 token，成本约为最初方案的十分之一。这些效率提升支撑起 Curative 的一项核心战略：签下那些常被大型网络忽视的小型提供者。

「无论你是大型医院系统，还是单人诊所，这个智能体都会乐于给予同等程度的关注，」Fred 解释道。「从那个智能体的视角看，这家提供者就是它唯一的焦点。」

谈判过程中，Gwen 会对照 Curative 的政策文件检查诊所提出的红线修订，然后编写 Python 代码把双方的修改合并为最终文档。

从填表到签约，整个过程最快可以在一小时内完成。合同签署后，另一个独立的资质审核智能体会核验提供者的执照，随后由各智能体加载提供者的数据和合同，使理赔能够据此定价。

自 Gwen 上线以来，Curative 的合同团队从 45 人增长到约 55 人，人均效率约为原来的 2.5 倍。他们把冷启动外联和文书工作交给 Gwen，自己通过电话接手有意向的线索（warm leads）。Gwen 促成的交易同样计入合同团队的绩效，因此人与智能体共享同一个目标。

「人们的工作更多转向关系维护，而不再是文书处理，」Fred 说。

Fred 还认为，更快的签约有助于小型诊所保持独立。「如果你开了一家诊所，却要花三个月才能进入网络并完成资质审核，那这三个月你就是拿不到钱，」他说。

Gwen 并不是 Curative 唯一的智能体。另一个基于 Opus 的智能体 Brad 帮助向雇主销售 Curative 的计划，主要经由经纪人渠道。Brad 会就每份报价跟进经纪人，并通过从核保人员过去手工清洗的电子表格中提取员工数据，帮助核保环节提速。

借助人机团队，Curative 现在能在 30 分钟内答复通过电子邮件或传真提交的理赔争议，而且回复是针对该笔理赔专门撰写的函件。「过去理赔争议的回复大约要 90 天，现在通过邮件或传真，30 分钟内就能完成，」Fred 说。「大多数支付方使用的是一组模板，再做邮件合并。这会让提供者非常不满，因为模板通常并没有真正解释清楚发生了什么。现在提供者收到的是一封定制函件，说明这笔具体理赔的细节、当前是什么情况、以及为什么。」

他们的所有智能体都构建在自研的理赔、事前授权和财务系统之上，这些系统由 13 名工程师今年用 Claude Code 重建。团队此前估算，仅建设一套理赔系统就需要 100 个工程师年。

「我们并不是想把（这些智能体）插进某个理赔系统，」Fred 说。「理赔系统就是跑在 AWS 上的 Python，它有 MCP，也有 API，而且是 Claude 写的，所以它理解它。」

## **Curative 从构建「与人谈判的智能体」中学到了什么**

以下是 Curative 团队在如何构建与人谈判的智能体方面的经验。

* **从一个通用工具开始。** 「我们一开始想的是『噢，我们要有一堆工具』，但那样效果不太好，因为红线修订相当复杂，」Fred 说。「我们发现最有效的方式是让模型只拥有一个工具——运行 Python——并用 docx 库完成所有红线修订工作。效果非常好。」
* **在人们所在的渠道上与人们接触。** 一个传真工具让 Gwen 的成交率翻了一倍多。许多提供者现在会在打印出来的传真上手写内容，再传真回来。「这是到人们所在的地方去，」Curative CTO Isaac Turner 说。「没错，他们有电子邮件，但他们真正习惯的是传真。」
* **让每次运行相互隔离。** Gwen 的一次运行只面对一个提供者，且不跨交易保留记忆。Curative 的销售智能体 Brad 确实保留记忆，这种方式有效，但需要谨慎。「你可能会写下错误的笔记，然后陷入死亡循环——它有一条永远无法清除的错误记忆，」Fred 指出。
* **从运行之外改进系统。** 每隔几天，Fred 会给 Claude Code 同一段提示：抽样最近 10,000 次运行，标记任何异常，并开一个 PR 来修复它。「改进循环来自用 Claude Code 跑大量历史对话，并问：这本来可以怎样变得更好，」他说。
* **先在远离 PHI 的场景中试验。** 很长一段时间里，Gwen 被禁止接触受保护健康信息（PHI），因此早期的失误都发生在风险较低的场景中。在如今智能体接触 PHI 的地方，后端控制会限制进入对话的内容，智能体的活动会被记录以供审计。「我们在那里学会了怎么做，然后把它移植到 PHI 领域，」Fred 说。签署商业伙伴协议（BAA）——HIPAA 要求在供应商处理 PHI 之前必须签订的合同——也变得更容易了。「尤其是 Anthropic，在非常快地推出符合 HIPAA 的最新服务版本方面做得很好，」Isaac 说。「尽管这项技术受到监管，我们仍能非常快地接入这些新技术。」
* **留意智能体自行开始做的事，并确保它们与你的风险偏好相符。** 当提供者索要一份可在内部传阅的宣传单时，Gwen 用自己的 Python 工具做了一份，并没有任何政策要求它这么做。当某家网络内诊所的前台把一位会员拒之门外时，Gwen 要求该诊所培训员工，随后又核实那位会员是否顺利就诊。

## **Curative 的下一步**

接下来，Curative 计划把智能体引入护理导航（care navigation），扩展 130 名会员指导与教练人员的覆盖范围。

Fred 预计提供者一侧也会用上智能体。目前很大一部分理赔争议似乎已由智能体撰写，他希望提供者也能用智能体来谈判合同。「存在一个清算价格，你越快找到清算价格，大家就能越快回去做诊疗服务，」他说。

| Curative 团队的最佳实践 |
| --- |
| 智能体一开始应该拥有多大权限？ | 比你认为它能承受的更少。Gwen 最初对任何高于模板的费率都设有人工审批队列。Curative 分步放宽限制，并更多地面向确定性决策，随后加入了费率审查员，未通过审查的仍由 Fred 审批。 |
| 智能体出错时怎么办？ | 提前规划，并与替代方案作比较。「标准不是完美，」Isaac 说。「标准是：如果你有一千个人在签合同，他们会犯多少让你后悔的错误？」 |
| 如何审计数十万条消息？ | 记录一切，对每条外发消息都设置审核智能体，并让 Claude Code 抽样检查运行记录。 |
