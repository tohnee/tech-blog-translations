# Block 如何用 Claude Fable 编排数千个拉取请求

> 原文：[How Block orchestrates Claude Fable across thousands of pull requests](https://claude.com/resources/articles/how-block-orchestrates-claude-fable-across-thousands-of-pull-requests) · Claude 博客

*Block 的 AI 能力负责人 Bradley Axen 谈他的团队如何评估新的大语言模型、Claude Fable 5 如何编排全公司范围的代码迁移，以及为什么在规模化、负责任地部署前沿智能时，安全保障机制是不可或缺的一环。*

Block 构建的工具帮助企业和个人参与经济活动，包括面向卖家的 Square 和面向消费者的 Cash App。Bradley Axen 负责 Block 的 AI 能力，他的团队构建端到端的 AI 产品，包括 [Buzz](https://claude.com/blog/building-effective-human-agent-teams)——一个面向人机团队（human-agent teams）的开源工作区——并与 Square 和 Cash App 团队合作构建面向客户的 AI 功能。Brad 与 Anthropic 聊了 Claude Opus 5、Claude Fable 5 等前沿模型如何改变“工程师”的含义、Block 如何用 Fable 落地智能体编排模式，以及当每位员工都能访问前沿模型时安全保障机制所扮演的角色。

## 前沿模型在 2026 年取得了实质性进展。这项技术如何影响了你们的工作方式？

AI 对 Block 工作的最大影响，在于我们**如何**构建东西，这一点怎么强调都不为过。2025 年我们看到了它的开端，当时像 Claude Code 这样的工具还需要多得多的人工介入。随着模型变得更智能，设计和工程工作已经转向设计迁移方案本身、审阅智能体的行为，以及构建更多面向客户的功能——而这始终是我们的目标。

下一阶段是把这些变革性技术通过 Block 的产品带给客户。AI 同样能在帮助小企业处理它们不愿花时间的后台运营（back-of-house）事务，或帮助 Cash App 用户管理财务方面带来巨大价值。有了 Claude，我们在技术上拥有了一个全新的杠杆，可以改变人们对软件能为自己做什么的期待。想象一下，如果 AI 能响应客户需求、即时构建新的界面会怎样？我越来越觉得，我们的产品将越来越多地借助 AI 按需构建，以解决具体问题。

## 随着前沿智能不断演进，你的团队现在能做哪些几个月前还做不到的事？

Claude 更新的前沿模型带来的最大变化，是我们构建软件的规模。写代码仍然是核心环节，但现在我们会用 AI 做全公司范围的迁移。我们所有人都做了很久这个梦，而 2025 年它很少真正实现。在 Claude Fable 5 之前，你必须有一个形状特别规整的问题，前沿模型才能真正发挥。

2026 年，AI 已成为我们执行所有大规模代码迁移的主要方式。对我们来说，一次迁移可能意味着横跨多个仓库、数百万行代码的数百甚至数千个独立拉取请求。过去，这项工作必须由人来协调，模型一次只能承接一个或少数几个 PR。有了 Fable，我们看到它能在许多会话之间编排工作。一名人类工程师负责掌舵，Fable 专注于更高层的设计工作：数据模型、API 规格、算法。随后它指挥最多数十个更小、更具成本效益的模型（如 Opus 或 Sonnet）执行具体任务，比如实际修改文件、运行测试。

经济账也算得过来。早期结果显示，编排器把前沿模型的 token 用在复杂的、前置的规划上，随后把更高比例的 token 交给更小的 worker 模型，而质量并未下降。整套设置都跑在 Buzz 上——我们的开源协作工作区，人类和 AI 智能体在共享频道和线程中并肩工作。它让我们能很好地看清团队的进展。

在任何一次迁移中，我们可能合并上千个由 Fable 编排的拉取请求。这让工程师能够专注于困难的设计决策，而不是机械性工作。

## 你们在什么情况下会选择 Claude Fable 模型而非其他选项？

自那以后，很多模型开始缩小差距，Opus 也非常出色，但 Fable 问世的那一刻，你能一次性承接多大的问题发生了显著的跃迁。Block 的各团队被这一点吸引，并开始思考上到另一层抽象、另一层规模意味着什么。

现在，我们的很多讨论都围绕模型效率。模型编排正是为此而生：Fable 的前沿智能在你用它处理大问题时最具价值，随后我们再让更小的模型去填补代码变更中的大量细节。这可以说是我记忆中自我们开始用 LLM 写代码以来，第一次答案不再是“100% 的时间都用最强的前沿模型”。

模型编排如今是我们构建方式的重要组成部分，这也意味着我们需要新工具。有些工具非常聚焦于单次对话，其界面跟不上你随时有 45 个智能体在与你并行工作的情况。这又是 Buzz 的用武之地。我们在 Buzz 中有多智能体工作流，我们确实认为未来是多人同时与多个智能体对话，由组织为日常任务选用高效模型、为更大的问题选用前沿模型。

## 你们交给 Fable 最难的问题是什么？

第一个是大规模迁移：数千个 PR 规模的迁移，由 Fable 编排完成这些工作的整个系统。

第二个是拿一个大型代码库——大约一百万行的量级——确保它不会每天都在累积技术债。我们交付的 PR 比以往任何时候都多。人们交付的功能和变更多得多，因此我们的系统积累技术债的速度也前所未有，而我们一直缺少与之匹配、能加快维护能力的对应手段。这件事终于发生了。我们有智能体每天或每周对整个代码库做一遍巡检，问：“这里情况怎么样？有哪些需要清理和整合？”

## 在广泛开放访问的情况下，你们如何推动前沿模型的高效使用？

我们让任何技术岗位的人都能完全访问最前沿的模型，因为我们战略的很大一部分就是始终在可能性的边缘工作。

用 Fable 去修 README 里的一个拼写错误，是对资源的极大浪费。所以我们需要更好的系统，为特定任务推荐该用哪个模型。为此，我们一直在构建一个自动选择器（auto-selector），帮助员工决定何时使用哪个模型。我们由大小前沿模型混合驱动的多智能体系统也有帮助。

作为一家公司，我们目标的一大部分就是默认高效运转，而这正是我们当下在培养的能力。我们有非常多优秀的模型可选。如果每个人都能熟练地为合适的任务挑选合适的模型，我们的成本效益就能大幅提升，而不必牺牲速度。

## 你会建议某些具体的优化策略吗，比如努力等级（effort level）？

即便我整天和 LLM 打交道，我几乎觉得同一个模型在 xhigh 努力等级下和在 medium 下是不同的模型。我不把努力等级看作一条你沿着走的谱线。Fable 在 low 下可能就比另一个模型在 xhigh 下更好。所以我把它看作一个更大的、需要我们去优化的网格。我们做的每一个用例基准测试，不仅检查每个模型，还检查每个模型的每个努力等级。

作为在中心层面负责我们如何做 AI 的人，我想要非常明确的推荐，比如：“这类任务的默认选择是把这个模型设在 high。”我们必须尽可能让工具自动做到这一点，然后让专家在想探索时去探索。

## 你们如何看待在当前前沿模型上引入安全保障机制？

有些事情至关重要，必须要有保证，而我们还没准备好让 LLM 在我们的代码库上放手行动。合入 main 和部署到生产，以及功能开关这类相关变更，我们始终交由人来决定。智能体可以做代码变更，但这些变更必须通过我们的安全检查，然后要有两个人批准部署。这一双重审批层使得 LLM 不可能自行推动这类变更。

在更低的层面上，如果员工不留神，他们能在自己的笔记本上做出多少事情是令人吃惊的——那些你本以为人类因为知道不该做就不会去做的事。这把我们推向了一些有趣的方向。我认为未来工作形态的很大一部分是远程工作站，因为它们更容易加固安全（也顺带缓解 LLM 的其他问题，比如把磁盘空间塞满）。我们安全叙事的一大部分，是构建默认安全的系统：用网络允许列表（allow list）而不是拒绝列表（deny list），诸如此类，从而挡住最糟糕的那类问题。

我们还尽量把尽可能多的东西移出模型循环。我们的许多安全防护栏其实是非常廉价、高效的检查，运行时根本不需要模型参与。我们把它们内建到人们做事所用的界面里。有时甚至只是一个正则表达式。越来越常见的是，更小的分类器也成了其中一环。

而在日常中，还有一整类为了让人们更高效而希望开放的事情，为它们设置阻塞并不划算。我们有意让模型开 PR、审查代码、查询我们的日志系统和分析数据库，全都是为了帮助人们走得更快。

这正是模型内建安全保障机制真正关键的地方。我指的是 Fable 和其他前沿模型被调校为不参与危险活动的方式，再加上 [Anthropic 自己的安全分类器](https://www.anthropic.com/news/claude-fable-5-mythos-5)。在我们的测试中，即便有人让 Claude “绕过”我们的双重审批系统，它也会拒绝尝试。我们也会把这一点纳入基准测试。

## 对其他使用前沿模型的工程团队有什么建议？

我们有数千人在与 AI 协作，推动着它能做什么的边界。他们作为个体在摸索哪些方法有效，也在改进身边的系统。比如，我的笔记本上装了一堆本地 skills，让我能在 Square 的 Web 前端里工作，尽管我并非科班前端开发者。当所有这些上下文和组织知识都在系统层面、而非个人层面被记住时，组织成熟度就到来了。

我们的目标是把从一线做事的人那里学到的一切都记录下来，放进一个让所有人受益的系统，这样每次你运行智能体时，都知道它掌握着能为你工作贡献力量的最佳上下文。
