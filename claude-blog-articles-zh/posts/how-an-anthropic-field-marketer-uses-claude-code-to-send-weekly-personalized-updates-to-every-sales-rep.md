# Anthropic 的一位现场营销人员如何用 Claude Code 向每位销售代表发送每周个性化更新

> 原文：[How an Anthropic field marketer uses Claude Code to send weekly personalized updates to every sales rep](https://claude.com/resources/articles/how-an-anthropic-field-marketer-uses-claude-code-to-send-weekly-personalized-updates-to-every-sales-rep) · Claude 博客

*Anthropic 营销团队的 Adam Ward 分享他如何用 Claude 把一份每周销售报告，变成针对他所支持的每一位客户经理的个性化周一简报。*

作为营销人员，我面临的最大挑战之一，是让销售团队随时了解一线正在发生的一切。大多数营销人都熟悉走廊里的那种对话：一位销售代表说，“哦，那个活动我从来没听说过”（或者那份新白皮书、那场网络研讨会），然后你意识到自己错过了把最新工作分享给销售代表、进而分享给客户的机会。

我最初的解决方案，是许多营销人都会认得的做法：周一早上和销售团队开 15 分钟站会。我花周日晚上的时间汇总整个业务的更新，做成能拿得出手的幻灯片，在会上现场讲一遍，再把幻灯片分享到 Slack。大功告成，对吧？并不尽然：在能用 Claude 的情况下，这一切显得过于手工；而随着团队扩张、我开始支持多个销售团队，我那套幻灯片流程跟不上了。这些更新也变得越来越没用了，因为我已经没有时间挑出适合每个团队的机会。

我希望让 Claude 来做这些工作，并为每位销售代表做一个更好的“产品”：一份每周简报，针对他们的客户量身定制，并与我们在营销上推进的所有事情相匹配。

幸运的是，我们组织了一场营销黑客松：专门留出时间，用 Claude Code 重建可重复的流程和工作流。我和团队凑在一起，为这个问题投入了一个小时，而这带来了一切不同。像黑客松这样轻松的、往往由同伴主导的学习机会，能带来你在日常工作中不会特意挤出时间进行的实验与探索，我们团队也不例外。

## 你不需要会写代码，你需要会讲清楚

同行营销人问我最多的问题之一是：“我该怎么开始用 AI？”我的做法，尤其是在 Claude Code 上，是先写一个提示词，向 Claude 说明：虽然我不是技术背景，但我有这样一个具体挑战，请把它当作一位深度理解业务问题的产品经理来对待我，并一步步和我一起做。我是那种边想边说的人，所以我经常会录下自己解释问题的过程，把转录文本交给 Claude；这样 Claude 就掌握了全部业务上下文。

以我们团队的每周客户经理（AE）简报为例，我先向 Claude 说明目标：每周给每位代表发一条 Slack 消息，讲清楚营销上正在发生什么，以及这会如何帮助他们的客户。然后我写了一份假的每周更新，给 Claude 一个可以对齐的模板。我知道销售代表是行动导向的，所以开头是“本周三件要事”清单，列出三项行动项，比如即将举办的活动或近期内容，供他们分享给客户。我还单独写了一个面向经理的汇总模板，因为经理通常想要的是团队的整体视图，而不只是单个客户的情况。

接下来，我通过 MCP 把 Claude 连接到 BigQuery；BigQuery 是我们营销团队的唯一可信数据源，能提供来自 HubSpot、Clay 和 Salesforce 的细粒度数据洞察。我想从简单的开始，所以先用了我们关于活动和网络研讨会的唯一可信数据源。为了个性化每份更新，我让 Claude 从 CRM 中拉取该代表负责的区域，以及 Slack 中沟通的相关客户更新。这样 Claude 就能把两者结合，生成个性化的每周更新。

随着时间推移，我和营销其他团队合作丰富了数据，所以现在这份简报还包括博客文章、电子书、客户案例、网络研讨会，甚至合作伙伴生态中的活动等新内容。

## 用户反馈才是真正的提示词工程

为了在销售一线推广，我先从一个同意做测试组的销售团队开始。发给 10 个人感觉没那么可怕，万一出错也有回旋余地，而且这个小组愿意提供反馈。第一次发送之后，我做了几处调整。

有些问题就是错误。例如，某个活动在源表格里没有 URL，Claude 就编了一个看起来合理的链接，点进去却什么都没有。我们立刻把它写成提示词中的硬性规则：绝不编造 URL。现在只有当地址逐字符来自源表格时，链接才会被渲染出来。后来的版本干脆把没有链接的活动从简报中完全移除，因为我们意识到，卖家无法为任何人报名的活动只是噪音。

到第一周结束时，提示词里已经有九条内容规则，每一条都对应一条来自卖家或经理的反馈。有位卖家指出，一场面向知识工作者的工作坊却推荐了一位工程副总裁，所以现在联系人头衔会与活动的目标受众核对，不匹配就直接剔除，不做说明。一道行业门槛规则把零售客户挡在金融晚宴邀请之外；还没有客户账号的全新卖家，收到的则是一段简短的欢迎语，而不是一条空消息。

另一些问题则是数据问题。做营销的人都知道维护唯一可信数据源有多难。例如，现场活动表在六周内被重排了三次列。为了应对这一点，我们改了提示词：每次运行开始时先读取表格的表头行，在生成任何内容之前先核对列映射。指令不再是硬编码的“看 C 列”，而变成类似“看那个放着活动 URL 的列”。

## 在全公司推广这份简报

经过最初几次运行，我把这份简报扩展到我所支持的每一个团队，现在现场营销部门为整个销售组织运行它。每周一早上，Anthropic 多个销售分部的客户经理打开 Slack，会收到一条私信，列出本周三项优先行动、他们客户相关的现场活动、已经注册即将举行网络研讨会的联系人、可以分享的相关营销内容，以及其他跟进建议。

每条消息都基于收件人自己的客户名单生成，所以没有两条是一样的。这份简报确实有效；我们最近一周内把一场高管晚宴的报名人数翻了一倍，纯粹是因为合适的销售代表在周一早上看到了合适的活动。

当 Anthropic 的业务拓展代表（BDR）想要自己版本的简报时，我们为他们复制了提示词，只改了一个字段，因为 BDR 在我们的 CRM 中通过不同于客户经理的关系映射到客户。提示词结构和内容规则原样沿用，BDR 版本两天内就上线了。后来我也为客户成功团队和联盟团队做了同样的事，此外我还为销售之外的跨职能伙伴提供所有营销活动的概览。

无论业务节奏多快，我和我的团队在 Claude 的帮助下，都确保销售代表在周一上班时就清楚知道本周发生什么、该优先跟进哪些客户和活动。每周一的发送都会完整归档，所以我能调出任何一位卖家在任何一天收到的确切内容，经理也能在一份汇总里看到整个团队的建议。我仍然会读发出的内容，尽管系统已经不再等我审批。几周前我休假时，周一的发送自己跑了出去，毫无差错。

## 用 Claude 起步的最佳实践

下面分享一些来自我个人使用 Claude Code 经验的技巧：

1. **从小处开始，从你已经在手工做的事情开始。** 当关于人们用 AI 做什么的噪音如此之多时，起步可能很难。我的建议是：挑出你亲手花费时间最多的重复性任务，让 Claude 把它重建一遍。这样你就能评判输出，因为你已经知道“好”是什么样。如果这个问题仍然显得太大，就把 Claude 当作思考伙伴，把它拆成步骤。如果这件事你要和别人分享，先把早期运行结果只发给自己，这样你能在别人之前发现错误。
2. **用平实的语言写指令，并给每份文档做版本管理。** 像给新同事交代工作那样向 Claude 说明，剩下的它来做。指示 Claude 把每次更新保存为带编号的版本，并用一行说明改了什么，这样你就有记录，知道过去每次运行是由哪版提示词产生的。我们的版本是一个 markdown 文件，同事们会为自己的分部运行它；我们最初从共享的 Google Doc 起步，后来更多人需要编辑时迁到了 GitHub。
3. **先用一个小而投入的群体试点。** 我们最初的测试是和一小组客户经理一起做的，我们知道他们愿意花时间给我们反馈、持续改进这份报告，帮我们发现问题，或就如何扩大覆盖、如何个性化提出建议。
4. **用反馈改进提示词，把每一条纠正都写成明确规则。** 当收件人开始给我们反馈、每一条纠正都变成 Claude 的明确规则时，这份营销简报才真正变得有用。
