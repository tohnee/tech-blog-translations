## **智能体化的进攻需要智能体化的防御**

攻击者在锁定一家公司时，通常走同一套流程：把公开数据武器化 → 构建仿冒页面作为诱饵 → 利用内部系统。AI 加速了这一过程。

在侵入任何系统之前，他们会先收集关于一个组织及其高管、员工的公开信息。

然后他们把这份情报变成诱饵，比如一个带有欺诈登录页的假网站，诱使受害者交出凭据。通过这些诱饵获得的访问权限，帮助攻击者进入边界内部，触达组织最有价值、最敏感的资产。

这个三段式序列是可预测的，但传统安全工具每次只守其中一段：

* 威胁情报工具监控公开数据阶段，
* 品牌保护工具盯防仿冒，
* 终端工具守护内部系统。

Outtake 的 Recon Agent 调查的是一次仿冒背后的完整网络。例如，它不只是下掉一个克隆的登录页，而是从该仿冒事件中收集并分类证据。

它顺着这些线索追踪到相连的基础设施——比如一个自称"客户支持"的假 Telegram 账号——并用图（graph）把这一对抗性网络映射出来。智能体的最后一步产出一份报告，说明调查过程、威胁行为者的画像，以及攻击者行为的重建时间线。

为了执行这套复杂的工作流，Recon Agent 能够读取、编写和运行代码。它甚至能直接与恶意登录页交互，看看被窃取的凭据究竟流向何处。

这类调查可能要求智能体长时间自主运行。智能体会话的中位数是 16 分钟，但经常延长到一小时甚至更久；目前最长的一次持续了两个小时的智能体工作才返回结果。

## **Outtake 如何用 Claude 构建复杂的长时间运行智能体**

Outtake 分大约四个阶段构建 Recon Agent。每个阶段的核心，都是弄清一次好的调查是什么样子，然后逐步把这种判断交给智能体。

![](https://assets.claude.com/c0095c91335295c423d1b1be3e7df8180e0d4303.png)

### **第 1 步：先成为专家。**

在构建智能体的任何部分之前，Outtake 的工程师亲自执行真实的网络调查，并从客户和设计合作伙伴那里汲取领域专业知识。

目标是定义"好"是什么样子。对于这类调查，这意味着确定哪些证据重要、如何组织证据，以及什么能把可行动的结论与猜测区分开来。这个标准成为固定的参照点，他们在之后的每个阶段都会回到它。

"构建长时间运行智能体最重要的一点，是你真的必须理解*好是什么样子？智能体应该做什么？*"Outtake 智能体平台工程负责人 Jack Hayford 说。"因为最终你要确保的是，智能体每一次都能做到那一点。"

### **第 2 步：在 Claude Code 中做原型**

起初，Outtake 团队使用传统的智能体框架，来逐步自动化他们正在标准化的调查流程。

但他们很快意识到，Recon Agent 不能只是一个简单的调查器。它需要编写并运行代码、临时构建工具，并真正与恶意域名交互。

"每一次调查都不同，而且技术性很强，"Hayford 说。"智能体需要编程的肌肉和能力，而 Claude Code 当时是我们验证这些假设、开始越来越多地实验的一个强有力的初始执行框架（harness）。"

正是在 Claude Code 中做原型的过程中，他们形成了核心设计原则：在编排层面对智能体严加约束（*"调查域名时始终执行 X、Y、Z"*），但在需要判断的地方，让它自由发挥。

### **第 3 步：升级到生产级执行框架**

"我们很喜欢 Claude Code 引入的那些模式，但我们需要额外访问更底层的原语，而这些我们并不想自己造，"Hayford 说。

使用 Claude [Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview)是把 Recon Agent 投入生产的自然下一步。沿用 Claude Code 中的技能和模式，确保团队在获得对 Recon Agent 记忆、上下文和文件系统更紧密控制的同时，没有丢掉任何速度，也无需在智能体循环和会话处理上重复造轮子。

### **第 4 步：构建由评估驱动的紧密迭代循环**

在网络安全领域，能够低成本、快速响应地迭代尤其关键，因为攻击者一旦得知某个防御工具存在，就会立刻适应。团队从一开始就集成了智能体评估（eval），并形成了一套能在同一时间运行多种场景的强评估套件。这让他们能够安全、自信地做大规模改动，例如模型升级和完整的记忆系统重构。

这也让团队把自己从智能体循环中抽身出来。例如，当 Recon Agent 完成一次调查并回报说，如果有某个它当时没有的工具，本可以做得更好时，另一个编码智能体会读取这些建议、编写新工具，并构建一个测试场景来试用它。

只有在最后，人类才会介入查看结果：有了那个工具，智能体把调查做得更好了吗？"我们是瓶颈，而当你构建这些长而复杂的智能体时，把反馈回路自动化非常重要。这快得多，作为开发者也满足得多，"Hayford 说。

## **构建长时间运行智能体的经验**

在智能体的早期，构建者用硬编码的、确定性的、逐步的路径预先编排智能体行为，以防它跑偏。如今，精心设计的工作流正被执行框架（harness）取代：一个由记忆、工具、技能和防护栏组成的支持性环境。

以下是 Outtake 团队在实施 Recon Agent 构建过程中的一些收获。

### **工具：一个文件系统加 bash 就够了**

文件系统让记忆在压缩（compaction）后依然存活。智能体通常会被赋予非常具体、细致的工具，但给智能体一个文件系统，外加写、读、运行代码的能力，能帮助它应对障碍。

"把那些极其强大的开放式工具和能力交给智能体，是一次巨大的跨越。我们观察到很多案例：智能体的某个工具因网络抖动或其他原因失败，它就直接找到正确的变通方法继续下去，"Hayford 说。"因为我们构建的执行框架其余部分足够强大，又因为它给智能体留下了用这些强大的开放式工具即兴发挥的空间，它仍然能取得成功的结局。"

### **提示只是建议**

提示在需要时提供灵活性，但尽可能硬编码才能保证稳定性。"当你构建这些随时间变得越来越复杂的长时间运行智能体时，提示只是建议，"Hayford 说。"当智能体没有做你想要的事，自然的反应是往智能体最可塑的那个部分添加内容。往系统提示里塞一句'当 X 发生时，务必执行 Y'起初也许有效，但随着这个智能体运行得越久，提示里的每一个词最终大概都会被忽略。"

正确的做法是围绕这种可能性来设计：找出智能体每次都必须做到的事，把它们变成智能体防护栏的一部分。"把这些东西从提示里抽出来，放进执行框架，"他说。"这样智能体就不必再想着它们，它有更多的上下文空间和注意力，投入到真正能发挥所长的地方。"

### **评估是为了速度，不只是可靠性**

把人工"反思"当作路线图，走向自动化的评估，从而压缩开发周期。传统观点认为评估是保证可靠性的质量关口。但对长时间运行的智能体来说，更大的回报在于速度。

早期，Recon Agent 每运行一次，团队都会人工复盘它的表现。但读完智能体 30 分钟的全部操作记录是件苦差事，而且无法规模化。

"在现代智能体开发中，评估输出是循环中最昂贵的一步，"Jack 说。

评估不过是那次反思的结构化、可打分、可自动化的版本。一旦你把"好"是什么样子固化成可重复的检查，你就可以让一个智能体坐在评审席上，读那 30 分钟的记录，并给这次运行打分。

"我觉得有些工程师对构建评估感到不安，因为那有点像'构建一个完美案例'的念头，"Jack 说。"但从一开始就构建某种版本的评估，会让你更快地造出那个智能体，无论它有多正式、多'完美'。"

### **保护你的智能体**

[提示注入](https://www.anthropic.com/research/prompt-injection-defenses)是真实的威胁，因此把智能体放进沙箱或给它穿上盔甲至关重要。Outtake 团队选择 Claude，部分原因正是它在抵御提示注入方面的强度。

"安全对我们构建 Recon Agent 来说是重中之重，"Hayford 说。"我们给了它文件系统加 bash，又把它送进对抗性环境，所以我们必须解决的最重要问题，是构建某种'防爆箱'（blastbox），让你可以把智能体与敏感内部隔开，同时又不真正妨碍它。"

他们的方法假设智能体可能被劫持，因此周围的系统被设计成能遏制损害。不过，安全措施因智能体的用途而异，并非所有智能体都适合放进防爆箱。

Outtake 现在正在智能体接触互联网的确切点上评估信任级别，实施一个检查点来评估智能体即将触碰的任何东西："这个页面是仿冒吗？是恶意软件吗？它此刻是不是想对智能体做提示注入？"随着智能体穿行于一个日益对抗性的互联网，这可能正是它们所需要的盔甲。
