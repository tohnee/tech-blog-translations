# Opus 5.5 上一个任务的成本

> 原文：[What a task costs on Opus 5.5](https://claude.com/blog/what-a-task-costs-on-opus-5-5/) · Claude 博客

## 一个任务的成本，与一次重试的成本

你出发的目的从来不是去买几百万个 token。你出发是为了构建一个功能、完成一次迁移，或者运行一个任务。token 数量只是模型完成目标所需要的东西。

两个每 token 成本相同的模型，在同一个任务上可能花掉差别很大的成本。一个模型把代码读一遍。另一个读了代码、试了一个修复、再读一遍。这些步骤中的每一步都是一个回合（turn），而每个回合都会把目前为止的整个对话重发一遍。所以需要更多回合的模型成本更高，即使单价相同。

读完这篇文章，你应该能回答关于自己工作的三个问题：

- 我典型的任务在 Opus 5.5 上要花多少钱？
- 哪些设置会改变这个成本，改变多少？
- 我怎么查看自己会话的用量？

有一个权衡需要开门见山地说明：每一种少花 token 的办法，也可能让你付出「任务没能完成」的代价。更低的 effort、更小的模型、更少的上下文，确实都能省 token。但一次重试（retry）的成本会超过这些省下来的钱。这篇文章试图给每一种权衡标上价格。

本文的一些数字是牌价（list price），另一些是由此构建的示意数字。文中的图表是交互式的，你可以在阅读时更改输入。这些都是尽力而为的示意，所以请务必查证我们的文档，并自己核算。

## 一个任务要花多少钱？

Claude Code 里的任务是一个循环。模型读取对话、调用一个工具、读取结果，然后再绕一圈，直到任务完成。绕一圈就是一次请求。有四个因素决定这个循环的成本。

**回合数。** 每个回合都会重发目前为止的整个对话。回合越少，需要处理的输入就越少。

**缓存读取。** 一个回合重发的内容，大部分是模型在上一个回合已经看过的文本。它们按缓存读取（cache read）计费，价格只有输入价的一小部分。

**输出 token 类型。** 最贵的 token，价格是输入价的五倍。[思考（Thinking）](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)按输出计费，所以在到达答案的路上推理更少的模型，成本更低。

**模型。**每个模型有自己的价格，列在定价页上，所以你选的模型决定了每一个 token 的价格。

我们的示例使用 Opus 5.5 的 API 牌价：每百万输入 token 4 美元、每百万输出 token 20 美元、每百万缓存读取 0.20 美元。与下文的计算器一致，示例中缓存命中的输入按读取价计费，其余按输入价计费，且不计缓存写入。token 数量均为示意。

### 回合数

假设一个任务以 20K token 的上下文开始，随着模型读取文件和工具结果增长到 120K。40 个回合时，平均每个回合发送约 70K token。这相当于整个任务约 2.8M 输入 token，尽管对话本身从未超过 120K。在 90% 从缓存读取的情况下，输入成本约 1.62 美元。同一个任务用 25 个回合完成，处理约 1.75M token，输入成本约 1.02 美元。

一个回合的成本高于它新增的 token，因为它要把它之前的所有内容重发一遍。所以最便宜的回合，是你根本不需要的那个。

一个能减少回合数的习惯，是给模型一种检查自己工作的手段。比如一个可以运行的测试、一次构建，或者一个调用接口的脚本。能检查自己工作的模型，会更早发现自己的错误。

一个能一次性收集齐所需信息、并把工具调用打包成批的模型，需要付「重发」代价的次数也更少。

### 缓存读取

同样 2.8M 输入 token，如果完全没有一个来自缓存，成本是 11.20 美元。命中率 90% 时是 1.62 美元，96% 时约 0.99 美元。没有任何其他设置能这样大幅左右输入成本。一个持续进行的会话自然会保持高命中率。后文会介绍一些避免打断缓存的操作。

### 输出 token

在 Opus 5.5 上，一个输出 token 的价格是一个缓存读取的 100 倍。一个典型任务的 60K 输出 token 要花 1.20 美元，相当于从缓存读取 6M token。输出包含思考。你要为全部输出付费，即使 Claude Code 只给你显示摘要。这就是为什么 effort——它主要改变模型思考的多少——对账单的影响如此之大。

### 模型

缓存读取更便宜的模型，主要惠及长会话。输出更便宜的模型，主要惠及需要大量推理的任务。

## Opus 5.5 变了什么

两件事变了：价格，以及模型做的工作量。

**每一条价格线都更低了。** 输入和输出 token 比 Opus 5 便宜 20%，缓存读取便宜 60%。输入价下降，读取价随之下降，从输入价的十分之一降到二十分之一。图 A 按每百万 token 比较了两个模型。这些是 API 牌价。在 Pro、Max 或 Team 计划上，Opus 5.5 更低的价格会传导到你的额度中，包括缓存上下文，因此额度比在 Opus 5 上多撑约 25%。缓存读取的额外降价是一次 API 价格变更。

*图 A. 每百万 token 的价格。*

在 API key 上，缓存读取的降价对 Claude Code 影响最大。一个长的智能体会话，其输入的大部分都花在缓存读取上。在下文图 B 计价的会话中，缓存一行从 1.00 美元降到 0.40 美元，是整个账单上最大的一笔降幅。

你能省多少取决于你工作的形态。一个以缓存读取为主的会话，输入最多可省 60%。一个没有缓存的短问题加上一个长回答，最多可省 20%，因为输出占主导。大多数 Claude Code 任务介于两者之间。下面的计算器会显示你的任务落在哪个位置。

Opus 5.5 在一个回答上可能用更多 token，因为它在回复前总会思考。我们预期人们在 Opus 5.5 上能完成更多工作，但这因任务而异，所以请在自己的工作上度量。图 C 比较了两个模型上单个任务的成本。这一部分对你工作的依赖，远比价格要大。

在一个范围明确的任务上，两个模型用差不多的回合数完成，你得到的就只是降价。差距应该在开放式任务上最大，因为模型可能在错误的方向上花掉很多回合。没有一个数字对所有代码库都成立，所以请自行度量（见最后一节）。

**长任务的收尾是一份报告。** Opus 5.5 结束一次长任务时，会报告它改了什么、发现了什么、以及需要你做什么。这也能省钱，因为当你能看清发生了什么，就更少需要重开会话。

试试你自己的数字

设置你的某个任务消耗的量，或从预设开始。这些预设相当有代表性，但我仍建议你自己算一算。缓存命中的输入按缓存读取价计费，新输入按输入价计费，因此缓存滑块显示了差距中有多大一部分来自缓存读取。

要用真实会话的数据填充这些滑块，请在任务结束时运行 /usage。Session 区块会给出输入、输出和缓存数字。最后一个滑块，是你对「Opus 5.5 在你的任务上少做多少工作」的假设。只想看价格变更就把它设为 0%。要根据你自己的工作来设定，方法如下：在 Opus 5 和 Opus 5.5 上分别运行同一个任务，比较回合数和输出 token。「自己动手度量」一节会走一遍流程，「解读一个会话」则说明在 /usage 里该看什么。

## 最大化会话价值的技巧

Opus 5.5 更低的价格让每个 token 更便宜。而你怎么运行一个会话，决定了你会用掉多少 token，以下这些步骤会有帮助。

### **先提高 effort，再考虑换模型**

effort 决定了模型在每个回合上花多少 token 的总体倾向：它的思考、它写的文字，以及它的工具调用。在更低的 effort 下，它做的工具调用更少，也更短。Opus 5.5 有四个等级（low、medium、high 和 xhigh），外加一个仅用于单个会话的 max。选择下方的一个等级，可以查看何时使用它以及设置它的命令。

Claude Code 为每个模型设置了默认等级，/effort status 会显示你当前的等级。对范围明确的日常工作，试试 **medium**。当 medium 停滞不前时，试试 **high**。它每个回合的花费比 medium 多，但比换更大的模型少。机械性工作用 **low**，比如重命名，或在多个文件中套用一个已知模式。

一个粗略估算 effort 定价的方式：假设 high 在一个任务全程多出 20K 思考 token，在 Opus 5.5 上是 0.40 美元。而一段十个回合的重试循环、100K 缓存上下文、共 10K 输出 token，成本与之相当。所以在能省下一次重试的任务上，high 是回本的。在一个 medium 本可一次完成的任务上，这钱就白花了。

#### **当 medium 只修好一层的时候**

你需要更高 effort 的最清晰信号，是一个修复停在了某一层。

假设 API 处理器里有一个字段被重命名。在 medium 下，模型更新了处理器，处理器的测试通过了，而客户端仍在发送旧字段。它完成了被要求的事，只是没有读得足够远、没找到第二个调用方。在 high 下，它会在动手写之前花更多回合阅读调用点，一次性把两层都改掉。

一个检查手段也能抓到同样的 bug。如果模型能运行一个经过客户端的测试，那么在 medium 下，旧字段在被写入的那个回合就会让测试失败。所以在提高 effort 之前，先看看模型有没有办法检查自己的工作。运行一次测试的成本是一个回合加上它的输出。而更高的 effort 会给每一个回合都增加思考。

如果提高 effort 等级并添加检查都无效，那就换更大的模型。

#### **在会话中途更改 effort**

在 Claude Code 中，带等级运行 /effort，例如 /effort high。/effort status 打印当前等级。你可以在任务中途更改，新等级对下一次请求生效。

更改 effort 或思考设置会清空缓存的对话，因为这些设置是缓存所匹配的提示的一部分。下一次请求要为整个对话支付缓存写入价格。

### **为你的工作选择合适的模型**

模型选择决定了会话中每一个 token 的价格，所以它对账单的影响比 effort 更大。它的影响面也更广。每个继承主模型的子智能体，也继承了它的价格。大多数日子需要三个模型：一个用于查询的小模型，一个用于你密切监督的工作的 Opus 5.5，以及一个用于最难任务的大模型。

#### **Opus 5.5 作为日常主力**

把你监督的工作交给 Opus 5.5：跨几个文件的功能开发、调试，以及带后续修改的代码审查。你阅读它的操作，在它偏航时介入，所以循环保持得很短。升级到 Fable 5.1

**当结果比 token 价格更重要时，升级到 Fable 5.1。例如**你不会监督的长任务、代码库中没有现成模式的问题，以及需要协调多个子智能体的大型变更。不要等到第三次失败。如果 Opus 5.5 在 high 上两次撞到同一个问题，就切换，解决后再切回来。交互式工作上，Opus 5.5 更合适，因为它延迟更低、成本更少。

Fable 5.1 的牌价是每百万输入 token 10 美元、每百万输出 token 50 美元，是 Opus 5.5 价格的两倍半。它的缓存读取为每百万 0.25 美元，只有 Opus 5.5 费率的 1.25 倍，因为按其输入价的 0.025 倍计费。所以差距在长的、重缓存的运行上最小，在大量写内容的任务上最大。

在自然的间歇处切换。缓存属于上一个模型，所以新模型的第一个回合要为整个对话支付写入价格。先运行 /compact，或者带着一份简短的书面计划开一个新会话，来缩小那个回合。运行 [/model](https://code.claude.com/docs/en/model-config) 并传入别名或模型名即可切换。/model 还会把你的选择保存为新会话的默认值，所以难题解决后记得切回来。

#### **降级处理查询类工作**

**为查询类工作降到 Sonnet 或 Haiku，而不是为写代码：**做搜索和摘要的子智能体、读日志和测试输出，以及「这是在哪里定义的」这类问题。跨很多文件的机械性修改，请保持 Opus 5.5 并把 effort 设为 low。这样修改仍留在为你编写其余代码的模型上，而每回合成本更低。

要让一个[子智能体](https://code.claude.com/docs/en/sub-agents)用更小的模型，在其定义中设置 model: haiku 或 model: sonnet。要让所有子智能体统一用一个模型，设置 CLAUDE_CODE_SUBAGENT_MODEL 环境变量。子智能体定义中指定的模型会覆盖该变量。未设置模型的子智能体运行在你的主模型上，除非设置了该变量。

每个子智能体在它自己的上下文窗口中运行并交回一份摘要，所以它的文件读取不会进入你的主对话。它仍然要为自己的 token 付费，所以模型设置决定了这笔花费的价格。

权衡在于：小模型读错一个搜索结果，会让主模型追错文件，而主模型要为这段弯路买单。让小模型留在错误容易低成本暴露的工作上，比如找文件、跑测试和读日志。

把判断类决策留在主模型上。opusplan 别名用另一种方式拆分工作：Opus 在计划模式（plan mode）下做规划，Sonnet 执行计划。这把代码修改放到了 Sonnet 上，与上面的建议正好相反。先在你自己的任务上度量，再决定是否设为默认。

### **迁移时检查你的提示**

为旧模型编写的指令，可能让 Opus 5.5 写得更多、重复工具调用。在 Claude Code 中运行 /claude-api prompt-audit，检查你的 Claude Code 配置——比如你的 skills 和 CLAUDE.md 文件——是否存在这些[提示反模式（prompting anti-patterns）](https://claude.com/blog/reducing-cost-and-improving-performance-with-claude-platform)。它还会检查你在 Claude Platform 上构建的应用的代码。

我们在一次从 Opus 4.8 到 Opus 5.5 的迁移上做了测试，使用一个包含 44 个工单的内部客服支持基准，其提示中带有上述模式中的几种。迁移到 Opus 5.5 并使用 low effort，将该基准的成本降低约 18%。运行 prompt-audit 又进一步降低 9%，降到比 Opus 4.8 起点低约 25%。这次审计移除了让模型多写、重复工具调用的仪式性指令：一个强制的六步流程、一条草稿区（scratchpad）规则、一条二次验证规则，以及互相矛盾的指令。

*图 D. 在客服支持基准上，从默认 effort 的 Opus 4.8 迁移到 low effort 的 Opus 5.5，并使用 prompt-audit。*

这个结果来自单个基准，所以把它当作一个例子，而不是一个可期望的数字。运行审计，然后在一个真实任务上对比前后的 /usage（见「自己动手度量」）。

### **缓存与压缩（compaction）**

Claude Code 会替你处理缓存和压缩。而你怎么运行会话，决定了它们能省多少。

#### **缓存如何工作**

Claude Code 会缓存请求中重复出现的部分，比如系统提示、工具定义，以及目前为止的对话。

在 Opus 5.5 上，一次缓存读取的价格是全新输入 token 的 5%。写入缓存比全新读取更贵：按当前定价，五分钟缓存为输入价的 1.25 倍，一小时缓存为输入价的两倍。每次缓存命中都会免费重置存活期。

在 Claude Code 中，存活期取决于你的付费方式。Claude 订阅上是一小时。API key 或云厂商上默认五分钟，而订阅一旦开始消耗用量额度（usage credits），也会降为五分钟。

在 120K token 上下文下，Opus 5.5 一次五分钟缓存写入约 0.60 美元，一次读取约 0.02 美元。一次写入抵得上 25 次读取。在 API key 上，六分钟的咖啡休息会把下一次 0.02 美元的读取变成 0.60 美元的写入。同样大小的一小时写入约 0.96 美元，在 API 上你可以支付这笔溢价，来覆盖一天中的空档。

#### **会话形态与命中率**

缓存存储的是一个前缀，所以它只能复用请求中从头开始与上一个请求匹配的部分。

一个平稳推进的会话每个回合都往对话末尾追加内容，从而保持高命中率。任何更改请求靠前部分的操作都会拉低命中率。更改工具定义会清空整个缓存，而系统提示的更改会从该点开始清空缓存——这几乎等于清空一切。

实践中，以下情况会发生缓存写入：

- 你暂停的时间超过缓存存活期；
- 你更改了 effort 或思考设置（见 effort 一节），这可能清空缓存的对话；
- 你连接或断开了 MCP 服务器，这可能改变每次请求开头加载的内容；
- 你切换了模型，因为新模型从空缓存开始；
- 对话被压缩（compaction），这会改写缓存此前匹配的历史。

所以这些事情要在会话开始时设置好，在会话运行期间就不要再动它们。

#### **为什么长会话每回合更贵**

每个回合都重发整个上下文，所以随着上下文增长，每个回合更贵，即使缓存是热的。在 20K token 上下文下，Opus 5.5 一个回合的缓存读取约 0.004 美元。150K 时约 0.03 美元，该规模下 30 个回合仅读取就花 0.90 美元。同样 30 个回合在 20K 下约 0.12 美元。在 Claude 4.6 及之后的模型上，更大的上下文窗口并不改变每 token 价格，所以成本完全来自重发对话。

这些上下文中有不少是早前工作的遗留：一小时前的堆栈跟踪、一个你已经用完的文件、一次你后来已修好的测试输出。它们在每个回合仍然被全部发送。

#### **压缩、/compact 与 /clear**

当会话接近上下文上限时，Claude Code 会对较早的历史做摘要，让之后的回合发送得更少。运行 /autocompact 并传入一个 token 数，可以更改触发前上下文允许被填到多满。

有两个命令可以让你自己动手。/clear 清空对话且不花钱，所以在转入不相关的工作时使用它。/compact 保持连续性，代价是一次请求。它会读取它要摘要的对话，你可以指定保留什么，例如 /compact keep the failing test names and the schema change。

在 150K token 时做一次压缩的粗略价格约 0.25 美元。这包括那次读取、几千输出 token 的摘要，以及在更短上下文上的一次新缓存写入。之后每个回合在读取上省约 0.025 美元，所以压缩在大约十个回合内回本。临收尾前的一次压缩，成本大于节省。

摘要还会丢失细节。调试会话中途的一次压缩，可能丢掉那条真正关键的日志。请在自然的间歇处压缩；当下一步依赖某个具体信息时，在 /compact 指令里说清楚。

#### **你输入之前加载了什么**

你的 [CLAUDE.md 文件](https://code.claude.com/docs/en/memory)在每个会话开始时加载进上下文，所以其中每一行都是每个回合重发内容的一部分。[成本文档](https://code.claude.com/docs/en/costs)建议把它保持在 200 行以内。MCP 工具定义是延迟加载的：一开始只加载工具名和服务器说明，完整的定义在工具被使用时才加载。运行 /mcp 查看连接了哪些服务器，并关掉你不用的那些。

## 自己动手度量

本文的数字都是示意。你的代码库、提示和习惯都不同，所以请在你自己的任务上度量成本。方法如下。

1. **在会话中，运行**[**/usage**](https://code.claude.com/docs/en/costs)**。**/cost 做的是同一件事。Session 区块显示 token 用量和按牌价估算的美元成本。一行提示缓存（prompt-cache）数据会显示你的输入有多少来自缓存。在 Pro、Max、Team 或 Enterprise 计划上，同一界面还会显示你的计划用量条。美元数字是在你本机按牌价计算的，所以在订阅上它只是你工作量多少的参考，不是账单。
2. **把同一个任务跑两遍。**从你的待办里挑一个真实任务，别用玩具示例。用 /model 在 Opus 5 和 Opus 5.5 之间切换。记录每次运行的回合数、输出 token 和成本。做完三四个任务再下结论。
3. **团队用户，请使用用量与成本报告。**[Claude Code Analytics API](https://platform.claude.com/docs/en/manage-claude/claude-code-analytics-api) 给出每个用户的估算成本。[Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api) 按模型、按缓存与非缓存 token 拆分支出。
4. **试试 effort 阶梯。**把一个难任务先用 medium 再用 high 各跑一次。把一个机械任务用 low 跑一次。

### 解读一个会话

任务结束时，在 /usage 里检查三件事。

- **缓存占比。**对长会话，它应该很高。如果很低，找找长时间暂停、effort 或模型的变更，或者中途连接的 MCP 服务器。
- **输出对比输入。**一个很小的改动伴随大量输出，通常意味着 effort 等级对这个任务过高，或者模型在重试。
- **总输入对比对话大小。**如果总输入是对话大小的很多倍，说明会话跑了很多回合，这段对话值得读一读，找出循环在哪里打转。

作为基线参考，Claude Code 成本文档给出的企业部署平均值约为每个活跃日每开发者 13 美元，90% 的用户低于每活跃日 30 美元。一个成本远高于你自己正常水平的会话，值得复盘。

## 牢记在心

- 范围明确的日常工作，用 medium effort。
- 给模型一种检查自己工作的手段，跨文件的修改从计划模式（plan mode）开始。
- medium 停滞时，把 effort 提到 high。在间歇处更改，因为更改可能带来一次缓存写入。
- 如果 high 两次撞到同一个问题，切换到 Fable 5.1。解决后切回来。
- 把搜索和读日志的子智能体放到 Sonnet 或 Haiku 上。代码修改保留在 Opus 5.5 上。
- 让长会话保持推进，这样它的缓存一直是热的。
- 在不相关的任务之间用 /clear；在间歇处用 /compact，并注明要保留什么。
- **最重要的一条：**在每个模型上各跑一个真实任务，对比 /usage 的报告。你自己的数字才是最可信的。
