# 为什么要从零实现机器学习算法？

从零实现算法可能有用，原因有如下几种：

1. 它可以帮助我们理解一个算法的内部工作原理
2. 我们可以尝试更高效地实现一个算法
3. 我们可以为算法添加新功能，或者对核心思想的不同变体进行实验
4. 我们可以规避许可问题（例如 Linux 与 Unix 之争）或平台限制
5. 我们想发明新算法，或者实现尚未有人实现/分享过的算法
6. 我们对现有 API 不满意，或者想把它更「自然地」集成到某个现有的软件库中

结合上面提到的 6 点，让我们把「从零实现」这个说法进一步具体化。谈论「从零实现」时，我们需要先缩小范围，这个问题才有实际的讨论意义。我们选一个特定的算法——简单的逻辑回归——用具体例子来逐一说明上述几点。我敢说逻辑回归已经被实现过上千次了。

即便如此，我们仍然想从零实现逻辑回归的一个理由可能是：我们觉得自己还没有完全理解它的工作原理；我们读了一堆论文，大致理解了核心概念。借助一门原型语言（例如 Python、MATLAB、R 等），我们可以把论文中的想法一步步用代码表达出来。而像 scikit-learn 这样成熟的库，则可以帮助我们复核结果，检验我们的实现——也就是我们对算法应当如何运作的理解——是否正确。在这种情况下，我们并不真正在意效率；尽管花了那么多时间实现这个算法，如果要在研究实验室或公司里做严肃的分析，我们多半还是会用成熟的库。成熟的库通常更值得信赖——它们经过了许多人的实战检验，这些人可能早已遇到过某些边界情况，并确保不会出现奇怪的问题。此外，这类代码也更有可能随着时间的推移在计算效率上被高度优化。在这里，从零实现的意义仅仅在于自我检验。读懂一个概念是一回事，把它付诸实践是另一个层次的理解——而能向别人讲清楚它，则是锦上添花。

我们想从零重新实现逻辑回归的另一个原因，可能是对其他实现的「功能」不满意。让我们天真地假设其他实现没有正则化参数，或者不支持多分类设置（即通过 One-vs-All、One-vs-One 或 softmax）。又或者，如果计算（或预测）效率是个问题，也许我们想换一种求解器来实现（例如 Newton 法、梯度下降、随机梯度下降等）。但计算效率上的改进并不一定非要通过修改算法本身来实现，我们还可以使用更底层的编程语言，比如用 Scala 代替 Python、用 Fortran 代替 Scala……一路下探到汇编或机器码，甚至设计一款为这类分析做过优化的芯片。不过，如果你是机器学习（或「数据科学」）从业者或研究者，这种事大概应该交给软件工程团队。

回到最初的问题：不同的人出于各种原因从零实现算法。就我个人而言，我从零实现算法，是为了那份学习体验。
