# 从宏观上看，RLHF 与 DPO 有何不同？

经典的**基于人类反馈的强化学习（RLHF）**会从偏好数据中训练一个单独的奖励模型，然后在策略优化过程中用该模型为生成的响应打分。**直接偏好优化（DPO）** 则去掉了显式的奖励模型和强化学习阶段，直接根据被选中的响应和被拒绝的响应来更新语言模型。

两种方法通常都从一个已经过监督指令微调的模型出发。它们也可以使用同一种人类偏好记录：

- 一个提示（x）
- 一个被选中的响应（y\_w）
- 一个被拒绝的响应（y\_l）

区别在于这种比较如何转化为策略更新。

| 属性 | 经典 RLHF | DPO |
| --- | --- | --- |
| 偏好数据 | 排序或「选中-拒绝」响应对 | 「选中-拒绝」响应对 |
| 单独的奖励模型 | 有 | 无 |
| 策略训练数据 | 随策略优化过程采样得到的响应 | 通常是固定的离线偏好数据集 |
| 更新方式 | 强化学习目标，通常是 PPO | 成对分类式损失 |
| 参考策略 | 通常通过 KL 惩罚来使用 | 直接用于偏好损失 |
| 主要系统工程挑战 | 协调 rollout、奖励、参考模型与策略等组件 | 计算并调节策略与参考模型的似然比 |

在由 [InstructGPT 论文](https://arxiv.org/abs/2203.02155)推广、用于 LLM 后训练的经典 RLHF 流水线中，首先通过监督微调产生一个初始策略。该策略为选定的提示生成多个响应，再由人们对它们进行排序或比较。一个**奖励模型**学习为更受偏好的响应赋予更大的标量分数。

随后，策略在强化学习更新过程中生成新的响应。诸如近端策略优化（PPO）之类的算法会提高期望奖励。KL 惩罚则阻止策略偏离冻结的参考模型太远，这个参考模型通常就是监督微调后的检查点。

![经典 RLHF 流水线包括监督微调、偏好收集、学习得到的奖励模型，以及 PPO 等强化学习更新。](https://sebastianraschka.com/images/LLMs-from-scratch-images/dpo/4.webp)

这套设置之所以强大，是因为奖励模型可以为不在原始比较数据集中的响应打分。当前策略可以在自身变化的同时不断采样新的输出。但这种在线组件也带来了困难：训练必须协调生成、奖励打分、策略更新、KL 控制，往往还有一个价值模型。学习得到的奖励只是期望行为的代理，因此过于激进的优化可能会钻奖励模型的空子。

DPO 从同一个 KL 正则化偏好学习的视角出发，把优化问题改写为一个作用在响应对上的损失。对于策略（\pi\_\theta）、冻结的参考策略（\pi\_{\text{ref}}）和尺度系数（\beta），标准的 DPO 损失为

[
\mathcal{L}*{\text{DPO}}
= -\log \sigma \left(
\beta
\left[
\log \frac{\pi*\theta(y\_w \mid x)}
{\pi\_{\text{ref}}(y\_w \mid x)}
-
\log \frac{\pi\_\theta(y\_l \mid x)}
{\pi\_{\text{ref}}(y\_l \mid x)}
\right]
\right).
]

其中的响应概率是序列级概率，通常表示为 token 对数概率之和。训练会提高策略对被选中响应（相对于被拒绝响应）的相对胜率，并且是以参考策略下的同一胜率为基准来衡量的。这比单纯提高被选中响应的似然更有针对性。

参数（\beta）设定该偏好 logit 的尺度，它源自 KL 正则化的推导过程。它需要与学习率、数据以及训练步数一起调节。冻结的参考策略为更新提供锚点。一些后来的偏好优化方法移除或改变了这一参考项，但标准 DPO 保留了它。

![DPO 对「选中-拒绝」响应对直接应用一个目标函数，避免了单独训练奖励模型外加 PPO 循环。](https://sebastianraschka.com/images/LLMs-from-scratch-images/dpo/5.webp)

标准 DPO 是一种**离线**方法。偏好对在训练之前就已固定，因此策略不必在每个优化迭代内部生成新的响应。训练过程类似于普通的监督学习，通常比完整的基于 PPO 的 RLHF 技术栈更容易实现和复现。

DPO 仍然有不小的计算与内存开销。它需要同时得到可训练策略和参考策略下两个响应的对数概率。对于固定数据集，参考对数概率可以预先计算，但策略仍要对被选中和被拒绝的序列进行前向评估。显存占用、序列长度、填充掩码以及响应 token 掩码都仍是需要关注的实际问题。

离线数据集也限制了 DPO 能直接观察到的内容。随着策略发生变化，它可能产生与存储对中两个响应都不相似的输出。经典在线 RLHF 可以从不断变化的策略中采样，并用奖励模型评估这些新输出。这种灵活性是否有帮助，取决于奖励模型的质量和强化学习过程的稳定性。

两种方法都继承了各自偏好数据的局限。标注者可能偏爱更长的回答、熟悉的写作风格、过度的顺从，或其他表面属性。一个被选中的响应如果只是比一个糟糕的替代品略好，它本身仍然可能是错的。DPO 可能过拟合这些成对信号，而 RLHF 则可能过度优化学习得到的奖励。

**RLHF** 这个术语在使用上也较为宽泛。有些讨论用它泛指任何基于人类偏好的后训练方法，包括 DPO。在本页面中，RLHF 指经典的「奖励模型 + 强化学习」流水线，而 DPO 指 [DPO 论文](https://arxiv.org/abs/2305.18290)提出的离线直接目标函数。

对于小型或追求透明的训练技术栈，我通常会从监督微调和 DPO 开始。固定的成对数据集让失败更容易复现和检查。当全新的策略探索、可复用的标量奖励模型或多个奖励来源能够证明额外机制的价值时，经典 RLHF 流水线才会更有吸引力。

方法选择不能替代评估。请在留出的偏好对、任务正确性、格式、安全标准、响应长度以及希望从起始模型保留的能力等维度上比较最终检查点。相关 FAQ [什么是 DPO，它与监督微调有何不同？](https://sebastianraschka.com/faq/docs/dpo-vs-supervised-finetuning.html) 解释了在此之前从 SFT 过渡到 DPO 的环节。
