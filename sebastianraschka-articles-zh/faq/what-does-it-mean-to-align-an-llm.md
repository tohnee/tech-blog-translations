# 对齐一个大语言模型（LLM）意味着什么

**对齐一个大语言模型（LLM）**意味着让模型的行为更可靠地符合一份为其预期用途制定的明确规范。这份规范可能涵盖指令遵循、事实准确性、不确定性表达、回复风格、安全策略以及工具使用边界。

对齐永远是相对于某个目标而言的。用户、应用开发者、标注员以及受影响的第三方可能各有所求。因此，除非我们同时说明模型应当遵循谁的指令或偏好、在什么条件下遵循、以及冲突如何解决，否则称一个模型"已对齐"是不完整的。

## 对齐是一种行为目标

基座模型（base model）接受训练的目的，是预测从其预训练分布中抽取的文本的下一个 token。它可能拥有广博的知识和有用的能力，却仍可能接着续写请求的措辞、模仿一段不良文本，或者在证据不足时给出自信满满的回答。

后训练（post-training）会改变这些可能回复的概率分布。对于一个无害的问题，期望的行为可能是直接而准确的回答。对于一个有害的请求，期望的行为可能是拒绝、同时仍提供安全的信息。对于一个含糊的提示，模型可能需要声明一个假设或请求澄清。

这种行为视角让两个区分变得有用。**微调（finetuning）描述的是一种训练方法，而对齐（alignment）描述的是一个训练或系统目标。**一个教模型法律术语的领域微调并不自动构成对齐步骤。此外，安全只是多个对齐目标之一。一个拒绝所有请求的模型可能在某个狭窄的有害请求测试中得分很高，但对普通用户而言对齐得很差。

能力与对齐之间的边界并不干净利落。指令数据可以教会模型新的操作流程，而带可验证奖励的强化学习可以提升问题求解能力。尽管如此，"对齐"一词通常强调的是：模型在可用的行为中选择了哪一种，以及它在多大程度上始终如一地遵循既定规范。

| 目标 | 不良行为示例 |
| --- | --- |
| 指令遵循 | 无视要求的格式，或把提示当作纯文本续写 |
| 有用性 | 给出无关、回避或不必要冗长的回复 |
| 真实性与校准 | 以高置信度陈述一个缺乏依据的断言 |
| 安全性 | 协助有害请求，或拒绝无害请求 |
| 可控性 | 无视工具权限、角色指令或应用约束 |

经典的 [InstructGPT 论文](https://arxiv.org/abs/2203.02155)将这个问题表述为让语言模型与用户意图对齐。其流程使用了示范数据以及对模型输出的排序，来改进指令遵循、真实性与毒性相关行为。该论文把对齐落实为一种部署场景下可度量的目标。这些目标并不能穷尽"人类价值观"可能具有的全部含义。

## 指令微调确立基本策略

有监督的指令微调通常提供第一个后训练阶段。每个样本包含一个提示和一个期望的回复。下一个 token 损失会提高模型在看到类似提示时生成该回复的似然。

![指令微调使用示范数据，把请求与模型应学习的回复行为配对。](https://sebastianraschka.com/images/LLMs-from-scratch-images/ch07_compressed/instruction-following.webp)

这一阶段教会模型基本的助手行为、任务格式、回复风格以及聊天模板。它可以展示如何回答问题、总结文档、生成 JSON，或拒绝一个被禁止的请求。[预训练与指令微调 FAQ](https://sebastianraschka.com/faq/docs/pretraining-vs-finetuning-vs-instruction-finetuning.html) 解释了这与基座模型原始目标的区别。

一条示范只给出一个目标答案。它并不直接表达"这个回复比另一个同样合理的回复更好"。这正是偏好数据补充信息的地方。

## 偏好优化在多个回复之间精炼选择

一条偏好记录会给出同一个提示下的两个或多个回复，并指明哪一个更受偏好。差异可能涉及正确性、清晰度、简洁性、语气或策略合规性。

经典的基于人类反馈的强化学习（RLHF）会为这些排序拟合一个奖励模型，然后针对这个学到的奖励来优化语言模型。直接偏好优化（Direct Preference Optimization，DPO）则以一个参考策略为锚点，直接根据被选中和被拒绝的回复来更新策略。[RLHF 与 DPO 对比](https://sebastianraschka.com/faq/docs/rlhf-vs-dpo.html)详细介绍了这两种目标。

![经典 RLHF 流程结合了有监督微调、人类回复排序、奖励模型以及策略优化。](https://sebastianraschka.com/images/LLMs-from-scratch-images/dpo/4.webp)

反馈不必只来自单一来源。人类评审可以依据评分细则（rubric）打分。一个模型可以依据书面原则来评判回复，例如 [Constitutional AI](https://arxiv.org/abs/2212.08073) 所展示的做法。代码测试、数学答案校验器和格式校验器可以为较窄的任务提供可验证奖励。每个来源都编码了对期望行为的一种不同代理。

在模型层面，所有这些方法最终都在改变 token 概率。它们并没有安装一条能保证在所有上下文中触发的符号化规则。一个在训练分布上行之有效的回复模式，在新的语言、不同寻常的表述、长对话或对抗性提示下仍可能失效。

## 奖励信号可能是错的

人类偏好是嘈杂且依赖上下文的。评审们可能意见相左，或缺乏验证技术答案所需的专业知识。成对标签可能偏向一个润色得好却不正确的回复，而一个被选中的答案也可能只是比被拒绝的备选"没那么差"而已。

一个学到的奖励模型又增加了一层近似。如果它奖励长度、自信程度或某种熟悉的写作模式，强力的策略优化就可能利用这条捷径。这种行为常被称为**奖励作弊（reward hacking）**或**过度优化（overoptimization）**。DPO 避免了单独的奖励模型，但它仍可能学到偏好对中存在的伪迹与偏差。

若干显性的对齐失败正源于不完善的目标。

- **谄媚（sycophancy）**：模型附和用户的前提而不去纠正它。
- **过度拒绝（overrefusal）**：安全训练把与高风险请求相似的无害请求也一并拦下。
- **形式重于实质（style over substance）**：即使正确性并未改善，润色过的格式仍获得偏好。
- **能力回退（capability regression）**：后训练损害了初始检查点中原本有用的行为。

针对参考模型的正则化、保守训练、均衡的数据以及能力保留测试可以减少这些失败。但它们无法免除对实际输出的检查。

## 模型对齐只是系统安全的一层

权重更新只是已部署助手的一部分。系统提示在推理时规定角色与优先级。检索可以让答案立足于经过批准的来源。工具权限与沙箱限制可能的操作。输入输出过滤器、速率限制、日志记录以及人工升级机制，处理那些仅靠模型策略无法可靠控制的风险。

这些组件应当被一起评估。一个模型可能单独测试时很好地遵循工具指令，而如果应用授予了过多权限，它仍然不安全。反过来，一个强有力的访问控制边界可以在模型提出某个操作时阻止它。

## 对齐应当如何评估

并不存在单一的对齐分数。我会把预期规范拆解为若干独立的评估：任务成功率、事实正确性、校准、指令冲突处理、有害请求处理、误拒率以及能力保留。人类评审适合开放式判断，而只要结果是可验证的，就应尽量使用单元测试、引用核对、schema 校验等直接检查。

评估集还需要后训练分布之外的提示。多语言输入、长对话、提示注入尝试、微妙的策略边界以及陌生领域，往往能揭示被平均基准分数掩盖的失败。[LLM 评估 FAQ](https://sebastianraschka.com/faq/docs/evaluating-llm-outputs.html) 讨论了如何组合直接检查、人工评审与基于模型的评判。

在实际的大语言模型开发中，对齐是一个迭代过程。团队撰写行为规范，收集示范或偏好数据，训练模型，评估失败案例，然后同时更新数据和周边系统。由此得到的模型可能对那个应用对齐得更好，而对另一个应用而言仍不完美甚至并不适用。
