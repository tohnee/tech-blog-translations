# 分词与字节对编码

分词（tokenization）把文本转换为 LLM 能够处理的整数 token ID 序列。字节对编码（byte pair encoding，BPE）这类子词方法用单个 ID 表示常见的文本片段，而用若干更小的片段表示不常见的文本。这样分词器无需为每个可能的词都准备一个词表条目，就能覆盖广泛的文本。

分词器位于 transformer 之外。它在模型运行前对文本编码，在生成 ID 之后再把 ID 解码回文本。

![分词把输入文本切分成 token 片段，并在嵌入查表之前把每个片段映射为整数 ID。](https://sebastianraschka.com/images/LLMs-from-scratch-images/bonus/bpe-from-scratch/bpe-overview.webp)

## 从文本到 token ID

分词器有一个词表，把 token 片段与整数 ID 关联起来。例如，一个分词器可能把 `This is an example.` 编码为五个 token ID。模型用这些整数从它的 token 嵌入矩阵中选取行。[嵌入层 FAQ](https://sebastianraschka.com/faq/docs/embedding-linear-onehot.html)更详细地讲解了这一查表过程。

整数值本身没有数值含义。token ID 500 并不天生比 token ID 20 更接近 token ID 501。每个 ID 都只是模型学得的嵌入矩阵和输出矩阵的一个索引。

这也是为什么预训练检查点必须与配套的分词器一起使用。如果另一个分词器把不同的文本分配给 ID 500，模型就会取到错误的嵌入行。添加 token 则需要调整大小并训练相应的模型参数。

## 为什么整词和单字节都不好用

词级分词器可以让常见词保持紧凑，但它的词表无法容纳所有人名、拼写变体、术语或新词。词表之外的文本就会塌缩成 `[UNK]` 这样的未知 token，丢掉了原始拼写。

![词级词表在输入词没有匹配条目时需要一个未知 token。](https://sebastianraschka.com/images/LLMs-from-scratch-images/ch02_compressed/09.webp)

在另一个极端，分词器可以把文本表示为单个字符或 UTF-8 字节。覆盖能力极佳，但序列会变得很长。字符串 `This is some text` 在 UTF-8 中占 17 个字节，而 GPT-2 的 BPE 分词器只用 4 个 token 表示它。更长的序列会占用更多上下文位置，并增加 transformer 的工作量。

子词分词提供了折中方案。高频词和片段获得紧凑表示，罕见字符串仍可用较短的片段表示。

![子词分词器通过把生词拆成已知片段来保留它，而不是用单个未知符号替代。](https://sebastianraschka.com/images/LLMs-from-scratch-images/ch02_compressed/11.webp)

## BPE 如何学习词表

训练 BPE 分词器与训练 LLM 是分开的。通常先拟合分词器，然后在预训练模型期间保持它固定不变。

一个简化版的 BPE 训练过程如下。

1. 用一初始集合的小符号表示训练语料。字节级分词器从 256 种可能的字节值开始。
2. 在整个语料中统计相邻符号对的出现次数。
3. 把出现最频繁的符号对替换为新符号，并记录这次合并（merge）。
4. 重复统计与合并，直到达到选定的词表大小或其他停止条件。

考虑玩具语料 `low lower lowest`。相邻符号对 `l` 和 `o` 出现了三次，所以一次训练可以把它合并成 `lo`。随后 `lo` 和 `w` 这个对会出现三次，可以合并成 `low`。后续的合并可能产生 `er` 或 `est` 这样的片段，取决于它们的频率和并列时的裁决规则。

得到的词表包含最初的小符号和合并出的片段。BPE 并不知道 `er` 有时是英文后缀，它是从符号对频率中学到这个片段的。因此 token 边界不一定要与语言学语素或单词对齐。

真实的分词器还有许多预处理细节。它们可能做 Unicode 规范化、用正则表达式把输入切分成区域、把前导空格保留为 token 的一部分，或者禁止跨特定边界合并。这些选择属于分词器的一部分，即使合并算法都叫 BPE，它们也可能改变最终的 ID。

我的[BPE 从零实现教程](https://sebastianraschka.com/blog/2025/bpe-from-scratch.html)用 Python 展示了训练循环、合并表和解码过程。

## 编码使用学得的合并

分词器训练完成后，编码新文本时不再统计符号对。它从小符号出发，按存储的优先级（通常称为合并秩，merge rank）应用固定的已学得合并。当没有任何已学得规则可应用时停止合并。剩余的片段在词表中查表得到 token ID。

这一区别很重要，因为 BPE 训练依赖全语料频率，而编码对单个输入字符串必须是确定性的。模型及使用它的每个应用都需要在同一分词器配置下产出相同的 ID。

解码遵循反向映射。每个 token ID 解析回它存储的字节序列，这些序列被拼接起来，再作为文本解码字节。在字节级 BPE 中，单个 token 可能只包含多字节 Unicode 字符的一部分。因此解码完整序列比假定每个 token 都是独立合法的文本更稳妥。

## 为什么字节级 BPE 不会遇到未知文本

UTF-8 用 0 到 255 的字节值表示文本。字节级 BPE 词表保留了这些基础值，并添加频繁出现的合并字节序列。因此，任何可以表示为 UTF-8 的输入都可以回退到它的单个字节，即使它的较长片段都没有在分词器训练中出现过。

这消除了常规的词表外（out-of-vocabulary）问题，但并不意味着所有文本的效率相同。一个主要用英语训练的分词器处理另一种语言可能要用多得多的 token。代码、空白字符、大小写和不常见的 Unicode 字符也会显著改变 token 数量。

## 词表大小是一种权衡

更小的 BPE 词表要求嵌入矩阵和输出矩阵的行数更少，但通常会产生更长的序列。更大的词表可以用更少的 token 编码常见文本，同时会增大这些矩阵，并产生更多需要足够训练样本的 token 条目。

上下文限制以 token 而不是词或字符为单位度量。因此两个字符数相同的文档可能占用不同量的上下文窗口。应当用检查点实际使用的分词器来度量 token 数。

特殊 token 同样需要谨慎对待。序列开始、序列结束、填充和对话控制 token 都是保留的 ID，具有模型特定的含义。它们通常与常规 BPE 合并分开处理。即使普通文本分词完全正确，用错结束 token 或对话模板也可能导致生成和停止上的错误。

其他常见的子词方法还包括 WordPiece 和 Unigram 分词。它们在学习词表和切分字符串的方式上做出了不同选择。使用这些方法的实际理由是相似的：让常见文本保持紧凑，同时保留编码陌生文本的路径。
