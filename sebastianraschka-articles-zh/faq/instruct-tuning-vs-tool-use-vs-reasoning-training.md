# 指令微调、工具使用与推理式训练有什么区别？

这些术语描述的是 LLM 系统的不同层面。**指令微调**是一个训练阶段。**工具使用**是模型与其运行时之间的交互协议，训练可以改善这一行为。**推理训练**是对面向多步问题求解的后训练方法的统称。同一个模型可以兼具三者。

在指令微调期间，每条训练记录通常包含一个提示和一个期望的回复。监督微调会提高在给定提示下回复 token 的似然。模型由此学会如何理解请求、遵循对话模板、遵守输出格式，并以助手的方式作答。偏好优化可能在这一阶段之后进行，但它是一个独立的目标。

指令微调本身并不能让模型获得计算器、网络搜索或私有数据库的访问能力。这些能力需要工具接口。应用程序向模型提供工具描述和参数模式（schema）。模型随后可以发出一个结构化请求，例如带 JSON 参数的函数名。应用程序验证并执行该请求，把结果加入对话，然后再次调用模型。

这一分工很关键，因为模型自己并不执行工具。工具使用依赖于周围的运行时。一个预训练模型或指令微调模型也许能通过提示和上下文示例学会简单的工具调用。监督式的调用轨迹则能教会模型更可靠地选择工具、构造参数、解读结果，以及从工具错误中恢复。

![Qwen 的资料展示了同一个模型家族如何把指令遵循、编程、推理和面向智能体的工具行为打包成相关但各自独立的能力](https://sebastianraschka.com/images/LLMs-from-scratch-images/bonus/qwen/qwen3-coder-flash-overview.webp)

推理训练的标准化程度较低。一种做法是使用包含完整解题过程的监督样本，或从更强模型蒸馏来的轨迹。另一种是使用带可验证奖励的强化学习（RLVR），由一个校验器对数学、代码或其他可验证任务的最终答案打分。训练还可以纳入生成的搜索轨迹、自我纠错样本或借助工具的解法。

更长的解释并不足以证明推理能力得到了提升。模型可以在很早就出错的情形下，模仿出一份完整解题过程的样子。因此评估应当检查最终结果，并在任务需要时检查中间步骤或工具调用的有效性。

本书代码库中的反思微调（reflection tuning）示例展示了如何先对草稿回复进行批评和修订，再将其作为训练数据。这是构造更强监督示范的一种方式。应当把它与 RLVR 区分开来——后者的奖励信号基于采样的结果来更新模型。

![反思微调在监督训练之前先打磨生成的回复；它是一种数据构造方法，与 RLVR 的优化目标并不相同](https://sebastianraschka.com/images/LLMs-from-scratch-images/bonus/reflection-tuning/reflection-tuning.webp)

举一个实际例子：某个请求要求使用最新财务数据进行计算。指令微调帮助模型遵循所要求的格式。工具使用能力让运行时得以获取数据并执行计算。面向推理的训练则可能帮助模型规划步骤、检查单位，并注意到不一致的结果。最终行为来自模型训练、工具协议与应用循环三者的组合。
