# 滑动窗口注意力

**滑动窗口注意力（sliding-window attention，SWA）** 是一种自注意力机制，其中每个查询只能访问键和值的一个固定局部范围。在因果 LLM 中，这通常指当前 token 加上数量有限的前文 token。标准因果注意力则可以访问完整的上文。

对于序列位置 \(i\) 和包含 \(W\) 个位置的窗口，一个简单的因果局部掩码为

\[M\_{ij} =
\begin{cases}
0, & 0 \leq i-j < W, \\
-\infty, & \text{otherwise}.
\end{cases}\]

该掩码会在 softmax 之前加到查询-键得分上。未来位置以及足够久远的位置因此获得零注意力权重。不同实现对「名义窗口大小是否计入当前 token」的处理不一样，所以在边界附近做一次差一（off-by-one）测试是值得的。

![滑动窗口注意力为每个查询提供一个移动的局部邻域，而不是完整的因果前缀。](https://sebastianraschka.com/images/LLMs-from-scratch-images/bonus/swa-memory/1.webp)

窗口随查询位置移动。这不同于把序列切分成相互独立的块。落在固定块边界两侧的两个 token，只要处于同一个滑动窗口内，仍然可以相互作用。

对于序列长度 \(T\)，全注意力需要计算约 \(T^2\) 个查询-键得分。当 \(T\) 远大于 \(W\) 时，因果滑动窗口注意力约计算 \(TW\) 个得分。对于固定窗口，这使得注意力得分的计算量随 \(T\) 从平方增长变为线性增长。

节省程度取决于实现方式。先构造稠密的 \(T \times T\) 得分矩阵、再对大多数条目做掩码，可以得到局部注意力的结果，但保留了全注意力的大部分开销。高效的局部注意力核（kernel）只计算允许的条带。FlashAttention 改善了精确注意力的内存行为，但除非使用局部窗口选项，完整的 FlashAttention 计算的仍是全注意力。

训练和推理以不同方式受益。在训练或提示预填充（prefill）阶段，局部核减少了得分对的数量。在自回归解码期间，局部层只需要其最近窗口内的键和值。较旧的条目可以从该层的 KV 缓存中驱逐（evict），从而将该层的缓存长度限制在 \(W\) 以内。

再说一遍，驱逐必须有人实现。一个运行时可以应用局部掩码但保留完整的 KV 历史，这样节省的是注意力计算量，而几乎不节省缓存容量。此外，驱逐旧条目也会改变一个按全注意力训练的模型的输出。SWA 是一种应当与检查点匹配的架构属性，而不是适用于任意模型的无损服务开关。

![局部层的 KV 缓存优势随上下文长度增长，因为每一层都可以停止保留其窗口之外的键和值。](https://sebastianraschka.com/images/LLMs-from-scratch-images/bonus/swa-memory/4.webp)

单个局部层无法直接检索其窗口之外的 token。堆叠多层可以扩大感受野，因为邻近的 token 在前一层中已经携带了聚集来的信息。对于 \(W\) 个位置的因果窗口，\(L\) 个连续局部层的理论感受野约为 \(1 + L(W-1)\) 个位置。这是经由中间隐藏状态的间接传播，与一个能将当前查询与每个保留的键直接比较的全局注意力层不同。

因此架构常常交替使用局部层与全局层。局部层以较低成本处理大多数 token 交互，而周期性的全局层恢复对完整上下文的直接查找。局部-全局比例和窗口大小是两个独立的选择。

Gemma 体现了这一设计。Gemma 2 以 1 比 1 的模式交替使用局部与全局注意力，并使用 4,096 token 的局部窗口。Gemma 3 每个全局层配五个局部层，并把局部窗口缩小到 1,024 token。[Gemma 3 报告](https://arxiv.org/abs/2503.19786)包含一项消融实验，显示这种更激进的局部模式对所测试模型和设置下的困惑度影响很小。这一结果不应被解读为对需要精确检索远距离 token 的任务的保证。

SWA 与分组查询注意力针对 KV 缓存的不同维度。SWA 限制一个局部层保留多少个 token 位置。GQA 减少每个保留位置上存储的键头和值头数量。一个模型可以独立使用其中一种方法，也可以两者结合。

当邻近上下文携带了大部分有用信号、上下文长度使全注意力代价高昂、或缓存容量限制并发服务时，局部注意力是合适的选择。当每一层都需要直接访问任意更早的细节时，它就不那么合适了。长文档比较、跨仓库代码查询和精确检索可能暴露这一局限，尤其是当技术栈中没有全局层或其他长程机制时。

配置的上下文窗口仍可以远大于局部窗口。位置编码覆盖更长的序列，信息可以经由堆叠的局部层或周期性的全局层传递。确切的模式需要纳入评估，因为两个最大上下文长度相同的模型，其直接访问路径可能大不相同。

因此，当滑动窗口注意力的局部性偏置与工作负载匹配、且系统能真正实现稀疏计算和有界缓存时，它就是有用的。我会检查窗口边界处的注意力掩码、在短序列上把局部核与稠密参考实现对比、测量实际保留的缓存长度，并在局部窗口内外的距离上分别评估检索能力。
