# LLM 预训练教会了模型什么

预训练教会大语言模型（LLM）预测 token 序列的可能续写。为了在众多类型的文本上把这件事做好，模型学到了对语言结构、含义、事实关联、写作格式以及反复出现的操作流程的有用表示。

"教会"这个词只是方便的速记。模型并没有被上一堂关于语法的课，也没有收到一张事实表。每当它的下一个 token 预测与训练批次中的文本不一致时，基于梯度的优化就会改变它的数值参数。最终得到的表示正是从千千万万次这样的更新中涌现出来的。

## 训练信号从哪里来

对于一个 token 序列 (x\_1, x\_2, \ldots, x\_T)，因果语言模型估计的是

[
p(x\_t \mid x\_1, \ldots, x\_{t-1}).
]

输入序列与目标序列错开一个 token。如果输入是 `[The, sky, is]`，对应的目标就是 `[sky, is, blue]`。每个位置的预测都与语料中真正跟在该前缀之后的 token 进行比对计分。

![一个 token 序列通过把 token ID 左移一位来自行提供训练目标](https://sebastianraschka.com/images/LLMs-from-scratch-images/ch07_compressed/inputs-targets.webp)

交叉熵在模型给观测到的 token 分配低概率时给出更大的损失。反向传播计算每个参数对该损失的贡献，优化器随后应用一次小幅更新。一段包含 (T+1) 个 token ID 的文本块可以在一次前向传播中提供 (T) 个下一个 token 目标，因为因果掩码阻止每个位置读取更晚的 token。

这种设置被称为**自监督学习（self-supervised learning）**。人类标注员不必为每个 token 写标签。文本中已经存在的续写就是目标。把数据称为"无标签"并不意味着数据集的诞生没有经过人类决策。收集、过滤、去重、语言配比、文档边界和剔除策略，都会影响模型能学到什么。

[输入-目标构造 FAQ](https://sebastianraschka.com/faq/docs/input-target-pretraining-examples.html) 更详细地跟踪了分批与移位的过程。

## 为什么下一个 token 预测教的不只是局部词序

正确的续写往往取决于多个层面的信息。预测一个动词词尾可能需要与前面名词的语法一致。补全一个函数可能需要跟踪变量名和缩进。续写一段技术解释可能需要几段之前给出的定义。

一个在宽泛语料上降低下一个 token 损失的模型，可以获得几类规律性。

| 规律性 | 模型可以用来做什么 | 重要边界 |
| --- | --- | --- |
| 语法与形态 | 词序、一致关系、屈折变化和合乎语法的句子 | 罕见结构和陌生语言可能仍然困难 |
| 语义 | 词、短语、实体和概念之间的关系 | 措辞相似并不保证含义相同 |
| 事实关联 | 文本中常见的名称、日期、属性和关系 | 关联可能过时、相互冲突或本来就是错的 |
| 篇章与风格 | 段落结构、语气、体裁和文档格式 | 风格模仿并不能确立事实准确性 |
| 任务模式 | 问答、翻译、分类、摘要和代码补全 | 提示可以暴露一个模式，但不能使其变得可靠 |
| 操作流程 | 多步计算、算法和反复出现的问题求解轨迹 | 近似的模式学习在新的组合或更长的序列上可能失败 |

这些类别是相互关联的。要预测 `The capital of France is` 的下一个 token，模型既需要这个短语模式，也需要法国与巴黎之间的关联。要续写一个 Python 函数，它可能同时需要语法、局部变量关系和操作流程模式。

![一个预训练的 GPT 风格模型把每个 token 前缀变成可能词表续写上的分布](https://sebastianraschka.com/images/LLMs-from-scratch-images/ch05_compressed/gpt-process.webp)

庞大而多样的数据集为同一底层关系提供了许多相互重叠的例子。参数共享让来自一个上下文的更新影响相关上下文中的预测。正因如此，模型才能生成在训练数据中从未逐字出现过的合理续写。

## 泛化与记忆都可能发生

预训练有时被描述为统计压缩。模型无法在权重里保留一份可普通检索的超大语料副本。它学到的是能很好预测众多序列的参数配置。因此，常见模式往往以跨样本适用的方式被表示。

精确记忆仍可能发生。模型可能复述一段被反复重复的段落、一个独特的罕见字符串，或一个获得了足够有效曝光的训练样本。模型大小、重复、数据复制和序列独特性都会影响这一行为。

这两种结果并不能截然分开。一句生成的句子可能把一个记忆下来的片段和一个泛化出的语法或事实模式结合在一起。这正是数据集去重、污染检查和保留评估集（held-out evaluation）之所以重要的原因。仅凭低下一个 token 损失，无法说明一个正确答案出自哪种机制。

## 预训练并不直接优化什么

预训练目标奖励的是分给观测续写的概率。用户关心的若干属性却不在这个目标之内。

- **真实性：** 训练文本包含错误、虚构内容、过时材料和相互矛盾的断言。损失并不会把每句话标记为真或假。
- **来源归属：** 模型通常被训练成只预测文本，而不返回支撑每个 token 的文档。
- **校准：** 即使模型缺乏可靠证据，流畅的文本仍可能获得高概率。
- **指令遵循：** 基座模型学到了许多文档和对话格式，但它并没有因为满足用户请求而持续获得奖励。
- **安全与应用策略：** 语料并没有定义已部署助手应当产出什么的一条统一策略。
- **持久记忆：** 预训练把统计信息存进模型参数。上下文移除之后，它并不记得一场新对话，除非另一个系统把它记录下来。

数据集也限制了能学到什么。语料中不存在的信息无法从目标中可靠地恢复，训练截止之后的信息也不可用，除非模型通过更新训练、检索或工具获得它。更多参数和算力可以改善对可用信号的拟合。它们无法修正源数据中的每一处错误。

## 为什么预训练得到的模型叫基座模型

预训练产生一个**基座模型（base model）**，其核心行为是文本续写。像 `Question: What is the capital of France? Answer:` 这样的提示与熟悉的文档模式相似，所以模型可能正确地续写它。一个带有多条格式约束的陌生请求则可能产生不一致的结果。

指令微调提供明确的提示-回复示范。偏好优化随后可以偏向更好地满足正确性、有用性或风格等标准的回复。这些后训练阶段改变的是预训练能力被选择和呈现的方式。

![指令微调把用户请求与期望回复配对，教会宽泛文本预训练无法一致指定的行为](https://sebastianraschka.com/images/LLMs-from-scratch-images/ch07_compressed/instruction-following.webp)

后训练也可以增加窄域的知识或技能，所以各阶段并非完全隔离。有用的区分在于主要训练信号：预训练学习文本上的宽泛分布；指令数据和偏好数据则塑造人们期望助手具有的回复策略。[基座模型指令遵循 FAQ](https://sebastianraschka.com/faq/docs/pretrained-answer-questions-but-bad-instructions.html) 用具体提示示例考察了这一差异。

在评估某个特定预训练模型学到了什么时，我会去检查比生成样本更多的东西。验证损失度量预测拟合，任务基准测试探测选定的能力，污染检查测试评估完整性，定向提示揭示行为边界。这些检查合在一起，比把下一个 token 预测简单看作死记硬背或通用智能保证，能给出更准确的图景。
