# 机器学习模型评估：第一部分

> 原文：[ML Model Evaluation: Part 1](https://sebastianraschka.com/blog/2016/model-evaluation-selection-part1.html)

**模型评估第 1–4 部分的单文件 PDF 版本可在 arXiv 上获取：<https://arxiv.org/abs/1811.12808>**

## 引言

机器学习已经成为我们生活中重要的一部分——无论是作为消费者、客户，还是（但愿如此）作为研究者和从业者！无论我们是把预测建模技术应用于研究问题还是业务问题，我相信我们有一点是共同的：我们希望做出"好"的预测！把模型拟合到训练数据上是一回事，但我们如何知道它在未见过的数据上泛化良好？我们如何知道它不是简单地把喂给它的数据背了下来，从而无法在未来的样本——那些它从未见过的样本——上做出好的预测？另外，我们最初又该如何挑选一个好模型呢？也许换一种学习算法会更适合手头的问题？

![Model evaluation selection part1 intro](https://sebastianraschka.com/images/blog/2016/model-evaluation-selection-part1/intro.webp)

模型评估显然不只是机器学习流程的终点。在处理任何数据之前，我们就应该提前规划，选用适合自身目的的技术。在本文中，我们将介绍其中的若干*技术*，并看看它们如何融入更大的图景——一个典型的机器学习工作流。

## 性能估计：泛化性能与模型选择

让我们以一个简单的问答开始这一节：

问："我们如何估计一个机器学习模型的性能？"

答："第一步，把训练数据喂给学习算法，让它学出一个模型。第二步，预测测试集的标签。第三步，统计测试集上错误预测的次数，计算出模型的预测准确率。"

且慢！很遗憾，取决于我们的目标，估计一个模型的性能并没有*那么*简单。也许我们应该换一个角度来审视前面的问题：***"我们究竟为什么要关心性能估计？"*** 理想情况下，一个模型的估计性能告诉我们它在未见过的数据上表现如何——对未来的数据做出预测，往往正是我们在机器学习应用或新算法开发中想要解决的主要问题。不过，机器学习通常伴随着大量的实验——例如，拧动学习算法内部的各种旋钮，也就是所谓的超参数。用不同的超参数设置在同一个训练数据集上运行学习算法，会得到不同的模型。由于我们通常想从这个模型集合中选出性能最好的那一个，我们需要找到一种方法来估计它们各自的性能，以便相互排名。比单纯微调算法更进一步的是，我们通常并不只是对那一个我们*认为*在给定条件下是"最佳解决方案"的算法做实验。更多时候，我们想把不同的算法放在一起比较，往往同时考量预测性能*和*计算性能。

让我们总结一下评估模型预测性能的主要原因：

1. 我们想估计泛化性能，即我们的模型在未来（未见过的）数据上的预测性能。
2. 我们想通过调整学习算法、从给定的假设空间中选出性能最好的模型，来提高预测性能。
3. 我们想找出最适合手头问题的机器学习算法；因此，我们想比较不同的算法，选出表现最好的那一个，同时从该算法的假设空间中选出表现最好的模型。

虽然上面列出的三项子任务都涉及估计模型的性能，但它们各自需要不同的方法。我们将在本文中讨论解决这些子任务的若干不同方法。

当然，我们希望尽可能准确地估计模型的未来性能。然而，如果说本文有一个关键的要点，那就是：只要偏差对所有模型的影响是均等的，带偏差的性能估计在模型选择和算法选择中完全没有问题。如果我们将不同的模型或算法相互排名以选出表现最好的那一个，我们只需要知道"相对"性能。例如，如果我们所有的性能估计都带有 10% 的悲观偏差、低估了它们的性能，这并不会影响排名顺序。更具体地说，如果我们有三个模型，其预测准确率估计如下

M2: 75% > M1: 70% > M3: 65%,

那么即使加上 10% 的悲观偏差，我们仍然会以同样的方式排名：

M2: 65% > M1: 60% > M3: 55%.

相反，如果我们把排名第一的模型（M2）的未来预测准确率报告为 65%，这显然就相当不准确了。估计一个模型的绝对性能，可能是机器学习中最具挑战性的任务之一。

## 假设与术语

模型评估无疑是一个复杂的主题。为了确保我们不偏离核心信息太远，让我们做出一些假设，并过一遍本文将要用到的一些技术术语。

***i.i.d.***

我们假设样本是 *i.i.d.*（独立同分布，**i**ndependent and **i**dentically **d**istributed）的，这意味着所有样本都抽取自同一个概率分布，且彼此在统计上相互独立。样本不独立的情形之一是处理时间数据或时间序列数据。

***监督学习与分类***

本文将聚焦于监督学习——机器学习的一个子类，其特点是可用数据集中的目标值是已知的。虽然许多概念同样适用于回归分析，我们将聚焦于分类，即为样本赋予类别型的目标标签。

***0-1 损失与预测准确率***

在下文中，我们将聚焦于预测准确率，其定义为所有正确预测的数量除以样本数量。我们把预测准确率计算为正确预测数除以样本数 *n*。或者用更正式的表述，我们把预测准确率 ACC 定义为

\[ACC = 1 - ERR,\]

其中预测误差 ERR 计算为 0-1 损失在数据集 *S* 中 *n* 个样本上的期望值：

\[\text{ERR}\_S = \frac{1}{n} \sum\_{i=1}^{n} L(\hat{y\_i}, y\_i).\]

0-1 损失 \(L(\cdot)\) 定义为

\[L(\hat{y\_i}, y\_i) :=
\begin{cases}
0 &\text{if } \hat{y\_i} = y\_i \\\\
1 &\text{if } \hat{y\_i} \neq y\_i,
\end{cases}\]

其中 \(y\_i\) 是第 *i* 个真实类别标签，\(\hat{y\_i}\) 是第 *i* 个预测类别标签。

我们的目标是学到一个具有良好泛化性能的模型 *h*。这样的模型使预测准确率最大化，或者反过来说，使做出错误预测的概率 *C(h)* 最小化

\[C(h) = \underset{(\mathbf{x}, y) \sim D}{\text{Pr}}[h(\mathbf{x}) \neq y],\]

其中 \(D\) 是我们数据抽取自的生成分布，\(\mathbf{x}\) 是类别标签为 \(y\) 的样本的特征向量。

最后，由于在这一系列文章中我们主要引用预测准确率（而不是误差），我们将使用[狄拉克 δ 函数](https://en.wikipedia.org/wiki/Dirac_delta_function)

\[\delta \big( L(\hat{y\_i}, y\_i)\big) = 1 - L(\hat{y\_i}, y\_i),\]

使得

当 \(\hat{y\_i} = y\_i\) 时，\(\delta\big( L(\hat{y\_i}, y\_i)\big) = 1\)；

而当

\(\hat{y\_i} \neq y\_i\) 时，\(\delta\big( L(\hat{y\_i}, y\_i)\big) = 0\)。

（*请注意，我们使用"准确率"作为性能指标，是为了让讨论保持一般性和简洁，不旁生枝节地去讨论不同的性能指标。根据你的应用，你可能需要考虑不同的性能指标。*）

***偏差***

当我们在本文中使用"偏差"（bias）一词时，指的是*统计*偏差（而不是机器学习系统中的偏见）。一般而言，估计量 \(\hat{\beta}\) 的偏差是其期望值 \(E[\hat{\beta}]\) 与被估计参数的真实值 \(\beta\) 之间的差。

\[Bias = E\big[\hat{\beta}\big] - \beta\]

因此，如果 \(E\big[\hat{\beta}\big] - \beta = 0\)，那么 \(\hat{\beta}\) 就是 \(\beta\) 的无偏估计量。更具体地说，我们把预测偏差计算为模型的期望预测准确率与真实预测准确率之差。例如，如果我们在训练集上计算预测准确率，这就是对模型绝对准确率的一个乐观偏差估计，因为它会高估真实准确率。

***方差***

方差就是估计量 \(\hat{\beta}\) 相对其期望值 \(E[\hat{\beta}]\) 的统计方差

\[\text{Variance} = E\bigg[\big(\hat{\beta} - E[\hat{\beta}]\big)^2\bigg]\]

方差衡量的是：如果我们让训练集发生微小波动、多次重复学习过程，模型预测的变动程度。模型构建过程对这些波动越敏感，方差就越高。

最后，让我们厘清*模型*、*假设*、*分类器*、*学习算法*和*参数*这几个术语：

- ***目标函数：***在预测建模中，我们通常感兴趣的是对某个特定过程建模；我们想学习或逼近一个具体的、未知的函数。目标函数 \(f(x) = y\) 是我们想要建模的真实函数 \(f(\cdot)\)。
- ***假设：***假设是我们认为（或希望）与真实函数——即我们想要建模的目标函数——相似的某个具体函数。在*垃圾邮件*分类的语境下，它就是我们所想出的、能把垃圾邮件与非垃圾邮件区分开来的分类规则。
- ***模型：***在机器学习领域，*假设*与*模型*这两个术语经常互换使用。在其他科学领域，它们可能有不同的含义：假设可以是科学家的"有根据的猜测"，而模型则是这一猜测的具体体现，用于检验该假设。
- ***学习算法：***同样，我们的目标是找到或逼近目标函数，学习算法就是一组指令，它尝试利用我们的训练数据集对目标函数建模。学习算法带有一个假设空间，即为建模未知目标函数、形成最终假设而探索的可能假设的集合。
- ***分类器：***分类器是假设的一种特例（如今通常由机器学习算法学得）。分类器是用来为特定数据点赋予（类别型）类别标签的假设或离散值函数。在电子邮件分类的例子里，这个分类器可以是把电子邮件标注为垃圾邮件或非垃圾邮件的假设。然而，假设并不必然是*分类器*的同义词。在另一个应用中，我们的假设可以是一个把学生的学习时间和教育背景映射到其未来连续值 SAT 分数的函数——一个连续目标变量，适合回归分析。
- ***超参数：***超参数是机器学习算法的*调节参数*——例如，线性回归均方误差代价函数中 L2 惩罚项的正则化强度，或者用于设置决策树最大深度的取值。与之相对，模型参数是学习算法拟合训练数据得到的参数——模型自身的参数。例如，一条线性回归直线的权重系数（或斜率）及其偏置（或 y 轴截距）项就是*模型参数*。

## 重代入验证与留出法

留出法（holdout method）无疑是各项模型评估技术中最简单的一种。我们取带标签的数据集，把它拆成两部分：一个训练集和一个测试集。然后，我们把模型拟合到训练数据上，并预测测试集的标签。正确预测所占的比例就构成我们对预测准确率的估计——当然，预测期间我们扣住已知的测试标签不放。我们实在不想在同一个训练数据集上既训练又评估模型（这称为*重代入评估*，resubstitution evaluation），因为过拟合会引入非常乐观的偏差。换句话说，我们无法判断模型究竟只是记住了训练数据，还是真的能很好地泛化到新的、未见过的数据。（顺带一提，我们可以把这个所谓的*乐观偏差*估计为训练准确率与测试准确率之差。）

通常，把数据集拆分为训练集和测试集是一个简单的*随机子采样*过程。我们假设所有数据都抽取自同一个概率分布（就每个类别而言）。然后我们随机选出约 2/3 的样本作为训练集，约 1/3 的样本作为测试集。注意到这里的两个问题了吗？

### 分层

我们必须记住，我们的数据集代表从概率分布中抽取的一个随机样本；而且我们通常假设这个样本或多或少能代表真实总体。现在，进一步做不放回的子采样会改变样本的统计量（均值、比例和方差）。不放回子采样对样本统计量影响的程度与样本规模成反比。让我们用[Iris 数据集](https://archive.ics.uci.edu/ml/datasets/Iris)看一个例子，我们把它随机分为 2/3 训练数据和 1/3 测试数据：

![Model evaluation selection part1 iris dist](https://sebastianraschka.com/images/blog/2016/model-evaluation-selection-part1/iris-dist.webp)

（源代码可以在[这里](https://github.com/rasbt/pattern_classification/blob/master/data_viz/model-evaluation-articles/iris-random-dist.ipynb)找到。）

当我们把数据集随机划分为训练集和测试集时，就违反了*统计独立性*假设。Iris 数据集由 50 朵 Setosa、50 朵 Versicolor 和 50 朵 Virginica 鸢尾花组成；花的种类是均匀分布的：

- 33.3% Setosa
- 33.3% Versicolor
- 33.3% Virginia

如果我们的随机函数把 2/3 的花（100 朵）分给训练集，把 1/3 的花（50 朵）分给测试集，可能得到如下结果：

- 训练集 → 38 x Setosa, 28 x Versicolor, 34 x Virginica
- 测试集 → 12 x Setosa, 22 x Versicolor, 16 x Virginica

假设 *Iris* 数据集能够代表真实总体（例如，假设花在自然界中均匀分布），我们刚刚制造了两个类别分布不均匀的失衡数据集。学习算法用来学习模型的类别比例是"38.0% / 28.0% / 34.0%"。然后，我们在一个类别比例朝着"相反"方向失衡的数据集上评估模型："24.0% / 44.0% / 32.0%"。除非我们的学习算法对这些小扰动完全不敏感，否则这显然不理想。如果我们的数据集本身就存在高度类别不均衡，问题会变得更糟。在最坏的情况下，测试集可能根本不包含任何少数类的实例。因此，常见的做法是以分层的方式划分数据集。***分层***（stratification）的意思很简单：随机切分数据集，使得每个类别在得到的子集——训练集和测试集——中都得到正确的体现。

在处理相对较大且均衡的数据集时，非分层方式的随机子采样通常不是什么大问题。不过，在我看来，分层重采样在机器学习应用中通常（只）有好处。此外，分层采样实现起来极其简单，而且 Ron Kohavi 提供了经验证据（Kohavi 1995）表明分层对 k 折交叉验证中估计的方差和偏差有积极影响——k 折交叉验证是我们将在本文后面讨论的一种技术。

### 留出法

在我们深入探讨留出验证法的优缺点之前，先来看一下整个流程的可视化总结：

![Model evaluation selection part1 testing](https://sebastianraschka.com/images/blog/2016/model-evaluation-selection-part1/testing.webp)

① 第一步，我们把可用数据随机划分为两个子集：训练集和测试集。把测试数据放在一边，是我们在一个不理想的世界（例如数据与资源有限、无法从生成分布收集更多数据）中应对种种不完美的变通办法。在这里，测试集对于我们的学习算法而言代表新的、未见过的数据；重要的是我们只碰一次测试集，以确保在估计泛化准确率时不引入任何偏差。通常我们把 2/3 的数据分给训练集，1/3 分给测试集。其他常见的训练/测试划分还有 60/40、70/30、80/20，甚至 90/10。

![Model evaluation selection part1 testing 01](https://sebastianraschka.com/images/blog/2016/model-evaluation-selection-part1/testing_01.webp)

② 把测试样本放在一边之后，我们挑选一个我们认为可能适合给定问题的学习算法。那么，上图中描绘的*超参数值*（Hyperparameter Values）是怎么回事呢？简单回顾一下，超参数是我们学习算法的参数，或者可以称为元参数。而且我们必须*手动*指定这些超参数的值——与实际的模型参数不同，学习算法不会从训练数据中*学习*它们。

由于超参数不是在模型拟合期间学到的，我们需要某种"额外流程"或"外部循环"来单独优化它们——而留出法并不适合这项任务。所以，眼下我们只能用某些固定的超参数值——如果使用现成的机器学习库，我们可以靠直觉或算法的默认参数。

![Model evaluation selection part1 testing 02](https://sebastianraschka.com/images/blog/2016/model-evaluation-selection-part1/testing_02.webp)

③ 我们的学习算法在上一步拟合了一个模型。下一个问题是：它得到的模型有多"好"？这就轮到我们的测试集发挥作用了。由于我们的学习算法之前没有"见过"这个测试集，它应该能给我们一个相当无偏的估计，反映模型在新的、未见过的数据上的表现！所以，我们要做的就是拿这个测试集，用模型预测类别标签。然后，我们把预测出的类别标签与"ground truth"（正确类别标签）进行比较，以估计它的泛化准确率。

![Model evaluation selection part1 testing 03](https://sebastianraschka.com/images/blog/2016/model-evaluation-selection-part1/testing_03.webp)

④ 最后，我们得到了模型在未见数据上表现如何的估计。所以，再也没有理由对这个算法继续扣住这些数据了。

由于我们假设样本是 i.i.d. 的，没有理由认为喂入全部可用数据之后模型反而会变差。根据经验，如果算法使用更多有信息量的数据——前提是它尚未达到其容量极限——模型的泛化性能会更好。

![Model evaluation selection part1 testing 04](https://sebastianraschka.com/images/blog/2016/model-evaluation-selection-part1/testing_04.webp)

### 悲观偏差

还记得前面谈到测试集与训练集划分时我们提到过***两个***问题吗？第一个问题是独立性的违背以及子采样带来的类别比例变化。第二个问题则在我们走过留出法图解时提到了。在第四步中，我们谈到了模型的容量，以及额外的数据是否有用。继续说容量问题：如果我们的模型尚未达到其容量，我们的性能估计就会带有悲观偏差。假设算法本可以从更多数据中学到更好的模型，而我们却为了估计泛化性能而扣住了宝贵的数据（即测试数据集）。虽然在第四步中我们把模型拟合到了完整的数据集上；但此时我们已经无法估计它的泛化性能了，因为测试数据集已经被我们"烧掉"了。这是现实应用中难以真正回避的两难，但我们应该意识到，我们对泛化性能的估计可能是悲观偏差的。

### 置信区间

使用如上所述的留出法，我们计算了模型泛化准确率的一个点估计。当然，围绕这个估计的置信区间不仅在某些应用中信息量更大、更可取，而且我们的点估计可能对特定的训练/测试划分相当敏感（即遭受高方差之苦）。

另一种"更简单"的方法在实践中经常被使用（尽管我不推荐它），即使用*熟悉的公式*，假设[正态分布](https://en.wikipedia.org/wiki/Normal_distribution)，在中心极限定理下计算单个训练-测试划分上均值的置信区间。

> 在概率论中，中心极限定理（CLT）指出，在一定条件下，大量独立随机变量（每个都具有明确的期望值和明确的方差）的迭代取值的算术平均值将近似服从正态分布，而与底层分布无关。[来源：<https://en.wikipedia.org/wiki/Central_limit_theorem>]

这个相当朴素的方法就是所谓的"[正态近似区间](https://en.wikipedia.org/wiki/Binomial_proportion_confidence_interval)。"它是如何工作的？记住，我们如下计算预测准确率

\[ACC\_S = \frac{1}{n} \sum\_{i=1}^{n} \delta(L(\hat{y\_i}, y\_i)),\]

其中 \(L(\cdot)\) 是 0-1 损失函数，\(n\) 是测试集中的样本数；\(\hat{y}\) 是第 *i* 个样本的预测类别标签，\(y\) 是其实际类别标签。所以，我们现在可以把每次预测看作一次伯努利试验，正确预测的次数 \(X\) 服从[二项分布](https://en.wikipedia.org/wiki/Binomial_distribution) \(X \sim B(n, p)\)，其中 \(n\) 为样本数、\(k\) 为试验次数，\(n \in \mathbb{N} \text{ and } p \in [0,1]\)：

\[f(k;n,p) = \Pr(X = k) = \binom n k p^k(1-p)^{n-k},\]

对 \(k = 0, 1, 2, ..., n\)，其中

\[\binom n k =\frac{n!}{k!(n-k)!}.\]

（记住，\(p\) 是成功的概率，\((1-p)\) 是失败的概率——即一次错误预测。）

现在，期望的成功次数计算为 \(\mu = np\)，更具体地说，如果估计量有 50% 的成功率，我们期望 40 次预测中有 20 次正确。该估计的方差为 \(\sigma^2 = np(1-p) = 10\)，标准差为

\[\sigma = \sqrt{np(1-p)} = 3.16.\]

由于我们感兴趣的是成功次数的*平均*值而非其绝对值，我们把准确率估计的方差计算为

\[\sigma^2 = \frac{1}{n} ACC\_S (1 - ACC\_S),\]

以及相应的标准差

\[\sigma = \sqrt{ \frac{1}{n} ACC\_S (1 - ACC\_S)}.\]

在正态近似下，我们可以把置信区间计算为

\[ACC\_S \pm z \sqrt{\frac{1}{n}ACC\_S \left(1 - ACC\_S \right)},\]

其中 \(\alpha\) 是误差分位数，\(z\) 是标准正态分布的 \(1 - \frac{alpha}{2}\) 分位数。对于典型的 95% 置信区间（alpha=5%），我们有 z=1.96。

不过在实践中，我更建议多次重复训练-测试划分，以计算均值估计的置信区间（即对各次运行取平均）。无论如何，这里一个有意思的要点是：测试集样本越少，方差越大（见上面分母中的 *n*），置信区间因此越宽。
