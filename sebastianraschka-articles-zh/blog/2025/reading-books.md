# 如何从技术书中获得最大收益

> 原文：[How to Get the Most from Tech Books](https://sebastianraschka.com/blog/2025/reading-books.html)

以下是此前读者问我如何从我的“从零构建大语言模型”系列图书中获得最大收益时，我分享过的一些笔记。

我自己读技术书时也遵循类似的方法。它并非万能配方，但或许是一个有用的起点。

就这本书而言，我强烈建议按顺序阅读，因为每一章都依赖前一章。对于每一章，我推荐以下步骤。

## 1）第一遍阅读（离线）

我建议从头到尾读完这一章，暂时不要写任何代码。
第一遍通读的目标是先把握整体图景。

理想情况下，我建议离开电脑来读这一章。纸质书很合适，
没有干扰的电子设备（不开浏览器、社交媒体或邮件）也可以。

就我个人而言，我既读纸质书，也用电子墨水平板阅读。虽然我从 2018 年就开始使用电子墨水平板，也总是努力多在电子墨水上阅读，但我仍然发现纸质书能帮助我更好地专注。这也是为什么我有时会把那些有挑战性、或者我真心想深入理解的论文打印出来。

我的建议是：把第一遍通读变成一次简短而专注的 20 分钟阅读，尽量减少干扰，不过度思考，也不被细节卡住。

划线或批注那些令人困惑或有趣的部分是可以的，但在这一阶段我并不去查资料。我只建议阅读，还不要运行任何代码。第一遍的目的是理解更大的图景。

## 2）第二遍阅读（配合代码）

第二遍通读时，我建议把这一章的代码亲手敲出来并运行。复制粘贴代码很有诱惑力，因为重新敲一遍实在太费功夫，但在我读其他技术书时，亲手敲代码通常能促使我更认真地思考代码（而不是一眼扫过）。

如果我得到的结果和书里不一致，我会先查看这本书的 GitHub 仓库，用仓库里的代码再试一次。如果结果仍然不同，我会看看是不是包版本、随机种子、CPU/CUDA 等差异造成的。如果到那时还是搞不明白，去问作者也是个不错的选择（通过图书论坛、公开 GitHub 仓库的 issue 或讨论区，实在不行再发邮件）。

## 3）练习题

在完成第二遍通读、重新敲完并运行了代码之后，通常是做练习题的好时机。这对巩固理解，或者以半结构化的方式琢磨一个问题，都非常有益。如果练习题太难，看一眼答案也没关系。不过我仍然建议先认真尝试一下。

## 4）回顾笔记并深入探索

现在，在读完章节、运行了代码、做完练习之后，我建议回头看看前两遍阅读时划的重点和批注，看看是否还有不清楚的地方。

这也是查阅更多参考文献、或快速搜索来澄清任何悬而未决之处的好时机。不过即便一切都说得通，多读一些感兴趣主题的相关内容也不是坏事。

在这一阶段，把有用的洞见、代码片段等记录下来，或转移到你常用的笔记应用中，也是很有意义的。

## 5）把想法用在自己的项目中

前面的步骤都是在吸收知识。现在，看看你能不能把某一章的某些内容用在自己的项目中。或者以书中的代码为起点，构建一个小项目。想找灵感的话，可以看看随书附赠的附加材料——它们基本上就是我为了满足自己的好奇心而做的迷你项目。

例如，在读完多头注意力机制并实现了 LLM 之后，你可能会好奇：采用分组查询注意力（GQA）的模型表现如何？[RMSNorm](https://sebastianraschka.com/glossary/#rmsnorm "Root Mean Square Layer Normalization (RMSNorm)") 相比 LayerNorm 究竟能带来多大差异？诸如此类。

也可能是一些更小的方面会对你的项目有用。例如，有时候某个微小的细节最终派上用场，比如测试一下显式调用 `torch.mps.manual_seed(seed)`，与仅使用 `torch.manual_seed(seed)` 相比，是否会有任何不同。

## 补充想法

当然，以上建议并非铁律。如果某个主题总体上非常熟悉或简单，而我读这本书主要是为了后面章节的某些信息，那么快速浏览一遍章节也是可以的（免得浪费时间）。

另外，对于没有任何代码的章节（例如作为导论的 第 1 章），跳过与代码相关的步骤自然也是合理的。

无论如何，希望这些内容对你有用。祝你阅读愉快、学习顺利！
