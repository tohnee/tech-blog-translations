# Horizon：首个面向大规模产品与服务的开源强化学习平台

> 原文：[Horizon: The first open source reinforcement learning platform for large-scale products and services](https://ai.facebook.com/blog/horizon-the-first-open-source-reinforcement-learning-platform-for-large-scale-products-and-services) · Meta AI（Wayback 存档）

2018 年 11 月 1 日

Horizon 是首个使用应用强化学习（RL）来优化大规模生产环境中系统的开源端到端平台。此次发布包含的工作流和算法构建于开放框架——PyTorch 1.0、Caffe2 和 Spark——之上，让任何大规模使用 RL 的人都能用上 Horizon。

过去一年，我们在内部将 Horizon 用于广泛的应用场景，包括帮助个性化 M 助手的建议、提供更有意义的通知，以及优化流媒体视频质量。

今天我们开源 Horizon——一个使用 RL 优化数十亿人使用的产品与服务的端到端应用强化学习平台。我们开发这一平台，是为了弥合 RL 在研究中日益增长的影响力与其在生产中传统上狭窄用途之间的鸿沟。过去一年我们在 Facebook 部署 Horizon，提升了该平台把 RL 基于决策的方法适配到大规模应用的能力。虽然其他人也在研究强化学习的应用，但 Horizon 是首个面向生产的开源 RL 平台。

虽然我们正在开展多个利用反馈改进性能的强化学习项目，但 Horizon 专注于把 RL 应用于大规模系统。此次发布既包含面向仿真环境的工作流，也包含一个用于在生产中预处理、训练和导出模型的分布式平台。该平台已经在 Facebook 带来性能收益，包括提供更相关的通知、优化流媒体视频码率，以及改进 Messenger 中 M 助手的建议。而 Horizon 的开放设计和工具集也有潜力惠及业内其他人，尤其是那些有兴趣用应用 RL 从海量信息中学习策略的公司和研究团队。Horizon 不仅是我们持续投入 RL 的证明，也证明了这一前景广阔的 AI 研究领域如今可以用于实际应用。

## 大规模决策：Horizon 如何为生产驾驭 RL

机器学习（ML）系统通常生成预测，然后需要工程师把这些预测转换为策略（即采取行动的战略）。而 RL 创建的是会做决策、采取行动、并根据收到的反馈自我调整的系统。这种方式有望在无需手工设计策略的情况下优化一系列决策。例如，RL 系统可以在视频播放过程中，基于其他 ML 系统的估计和视频缓冲区的状态，直接为该视频选择高或低的码率。

尽管 RL 的策略优化能力在研究中展现了可喜的成果，但 AI 社区一直难以把这些模型适配到生产环境截然不同的现实要求。在 Horizon 中，我们聚焦于弥合两类截然不同的应用：研究与仿真器的复杂但终究有限的环境；以及依赖天然带噪、稀疏且任意分布数据的基于 ML 的策略优化系统。RL 驱动的机器人可以应对受限的、可预测且可重复的规则的游戏，而现实世界领域无法被完美仿真，反馈也更难并入已部署的代码——在那里，任何改动都必须比在受控的实验环境中更加谨慎。

正如深度学习曾经革命化了神经网络的应用，Horizon 这样的项目有望定义科学家和工程师如何把 RL 应用于生产环境、用策略优化产生影响力。具体而言，Horizon 考虑了生产环境特有的问题，包括特征归一化、分布式训练、大规模部署与服务，以及包含数千种特征类型和分布各异、还有高维离散与连续动作空间的数据集。

Horizon 的流水线分为三个部分：（1）时间线生成，运行于数千个 CPU 之上；（2）训练，运行于多个 GPU 之上；（3）服务，同样横跨数千台机器。这一工作流让 Horizon 能扩展到 Facebook 规模的数据集。对于在线策略学习（on-policy learning，例如使用 OpenAI Gym），Horizon 可以选择以闭环方式把数据直接送入训练。

Horizon 还应对了大规模构建和部署 RL 系统的独特挑战。RL 通常以在线方式训练：系统先随机选择动作，然后实时更新。鉴于这些系统在 Facebook 的规模和影响，这种随机性和实时更新目前并不可行。相反，我们的模型从产品工程师设计的策略开始训练。模型必须离线训练，使用离策略（off-policy）方法和反事实策略评估（CPE）来估计：如果由 RL 模型来做那些过去的决策，它会怎么做。一旦 CPE 结果可以接受，我们就在一个小型实验中部署 RL 模型并收集结果。有趣的是，我们发现与以往相对恒定的系统不同，RL 系统会随着时间持续学习和改进。

工业数据集往往包含数十亿条记录，以及数千个分布任意的状态特征和高维离散与连续动作空间。根据我们的研究和观察，应用 RL 模型对带噪和未归一化数据比传统深度网络更敏感。Horizon 使用 Apache Spark 并行预处理这些状态和动作特征，我们的 Spark 流水线也包含在开源发布中。训练数据完成预处理后，我们使用基于 PyTorch 的算法在 GPU 上进行归一化和训练。虽然 Horizon 可以在单个 GPU 或 CPU 上运行，但该平台的设计聚焦于大型集群——在多个 GPU 上同时进行分布式训练，让工程师能解决包含数百万样本的问题，并更快地迭代模型。我们使用 PyTorch 的数据并行和分布式数据并行特性来做分布式训练。此次发布包含深度 Q 网络（DQN）、参数化 DQN 以及深度确定性策略梯度（DDPG）模型。训练期间，我们还会运行 CPE 并把评估结果记录到 TensorBoard。训练完成后，Horizon 使用 ONNX 导出这些模型，以便大规模高效服务。

在许多 RL 领域，你可以通过实际尝试来衡量模型性能。在 Facebook，我们希望确保在大规模部署前充分测试模型。由于 Horizon 解决的是策略优化任务，训练工作流还会自动运行若干最先进的策略评估技术，包括序列双重稳健（sequential doubly robust）策略评估和 MAGIC。生成的策略评估报告在训练流程中导出，可通过 TensorBoard 查看。该评估还可以与异常检测结合：在策略公开部署之前，如果模型的新一轮迭代与上一版性能差异悬殊，就自动向工程师告警。

## 在岗学习：Horizon 对 Messenger、360 度视频等的影响

自我们开始在内部使用 Horizon 的一年里，该平台展示了 RL 如何利用即时反馈做出提升性能的决策，从而影响生产应用。例如，Horizon 让我们通过实时优化码率参数，提升了 Facebook 上 360 度视频的画质。该平台同时考虑可用带宽量和已缓冲的视频量，来判断是否可以切换到更高质量的视频。这一过程利用了 RL 即时创建激励、使用全新且无监督数据的能力——它在视频播放的同时工作，而不是事后分析性能和精心标注的数据。（反事实策略评估为离线部署 RL 模型的工程师提供洞见。图中比较了几种 CPE 方法与日志策略（最初生成训练数据的系统）：1.0 分表示 RL 与日志策略性能相当；这些结果表明 RL 模型应能获得约为日志系统 2 倍的累积奖励。）（这张高层示意图解释了 Horizon 的反馈回路：首先，我们预处理现有系统记录的数据；然后训练模型并在离线环境下分析反事实策略结果；最后把模型部署给一组用户并测量真实策略。新模型产生的数据反馈到下一轮迭代，大多数团队每天都会部署一个新模型。）

Horizon 还为 M——Messenger 中的智能助手——过滤建议。M 在人们的对话中主动建议相关内容和能力，丰富人们在 Messenger 中的沟通和办事方式。Horizon 使用 RL——相比基于规则的对话策略学习方法更具可扩展性、前瞻性并对用户反馈更敏感——帮助 M 随时间学习。例如，如果人们与某条建议互动更频繁，M 可能会更常展示它。借助 Horizon，M 在每天帮助数百万人沟通的过程中变得更聪明、高度个性化。

该平台还改进了我们用 AI 决定发送哪些 Facebook 通知以及发送频率的方式。过去，我们并非发送所有可能的通知（提示新帖子、新评论等），而是使用 ML 模型帮助预测哪些通知最可能有意义或最相关，并过滤掉其余的。但这些模型依赖有监督学习，没有考虑发送通知的长期价值。例如，一天多次访问平台的人可能不需要一条他们反正都会看到的帖子的通知，而不太活跃的人则可能受益于通知，以确保不错过家人和朋友的重要帖子。为了更好地处理这些长期信号——让通知按设计初衷发挥作用、为平台上所有人提供价值——我们使用 Horizon 训练了一个用于发送推送通知的离散动作 DQN 模型。当有人在他本来会错过的帖子上互动时，该模型获得奖励；发送通知则受到惩罚。只有当通知对这个人的价值（例如提醒他们亲密好友或家人的重要帖子）高于惩罚（他们设备上多弹出的一条提醒）时，RL 模型才会放行通知。该模型还定期用大批状态转移更新，使其能渐进改进并最终调节通知的量。自从用 Horizon 的 RL 版本替换此前基于有监督学习的系统以来，我们观察到通知相关性的提升，而发送的通知总量并未增加。我们不再以点击通知来定义相关性，而是可以更宏观、更深入地审视，确保这些信息带来真正的价值。

## 人人可用的生产级 RL 部署工具

这些收益凸显了 RL 能为行业带来的能力：直接从次优策略下收集的样本中学习最优策略。尽管我们已经识别出适合 RL 的具体用例和应用，但这只是一段激动人心的旅程的开始。凭借 AI 社区集体的才华与创造力，我们迫不及待想看到 Horizon 激发出的想法、功能和产品。

任何使用机器学习做决策的人都可以尝试 Horizon。第一步是记录倾向（propensity，采取该动作的概率）和备选项（当时还有哪些其他动作可选）。Horizon 利用倾向和备选项来学习何时存在更好的动作。第二步是定义并记录奖励（采取该动作所获得的价值）。收集到这些数据后，就可以运行 Horizon 的训练循环，并导出一个会做出新决策、最大化总奖励的模型。

Horizon 是我们对 AI 开放开发承诺的一部分——它原本是 Facebook 的内部平台，现在由我们开源，并且与我们已向社区提供的工具（包括 PyTorch 1.0 和 Caffe2）协同工作。尽管 Horizon 面向生产目的调优，但我们使用该平台的过程也揭示了把 RL 集成到其他系统中的重要研究。我们正利用 Horizon 平台发现基于模型的 RL 和奖励塑形（reward shaping）方面的新技术，并用该平台探索 Facebook 内更多的应用，例如数据中心资源分配和视频推荐。
