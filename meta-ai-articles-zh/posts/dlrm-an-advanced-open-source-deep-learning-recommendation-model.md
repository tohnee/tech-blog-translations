# DLRM：先进的开源深度学习推荐模型

> 原文：[DLRM: An advanced, open source deep learning recommendation model](http://ai.facebook.com/blog/dlrm-an-advanced-open-source-deep-learning-recommendation-model) · Meta AI（Wayback 存档）

2019 年 7 月 2 日

随着深度学习的到来，基于神经网络的个性化和推荐模型已成为在生产环境（包括 Facebook 内部）构建推荐系统的重要工具。然而，这些模型与其他深度学习模型差异显著，因为它们必须能处理类别数据（categorical data），后者用于描述更高层的属性。神经网络要高效处理这类稀疏数据颇具挑战，而具有代表性的模型和数据集的公开细节匮乏，也拖慢了研究社区的进展。为帮助推进这一子领域的理解，我们正在开源一个最先进的深度学习推荐模型（DLRM），它用 Facebook 的开源平台 PyTorch 和 Caffe2 实现。DLRM 结合了协同过滤与基于预测分析的方法的原理，因而能够高效处理生产规模的数据并提供最先进的结果，从而超越其他模型。通过发布该模型并在此处和配套论文中详述其功能，我们希望能帮助社区找到应对这类模型独特挑战的新途径。我们也希望鼓励进一步的算法实验、建模、系统协同设计和基准测试。这将反过来催生新模型和更高效的系统，为使用各种数字服务的人们提供更相关的内容。

## 理解 DLRM 模型

在 DLRM 模型中，类别特征用嵌入处理，而连续特征用底部多层感知机（MLP）处理。然后，显式计算不同特征的二阶交互。最后，结果经顶部 MLP 处理并送入 sigmoid 函数，以给出点击概率。（该模型的示意图曾在 Open Compute Project 峰会主题演讲中详细讨论。）

（原文此处附图：DLRM 模型处理描述用户和产品的连续（稠密）与类别（稀疏）特征。它调用广泛的硬件和系统组件，如内存容量与带宽，以及通信和计算资源。）

## 基准测试与系统协同设计

DLRM 的开源实现可用作基准，度量：模型（及相关算子）执行的速度；各种数值技术如何影响其准确率。这可以在不同硬件平台上进行，例如 BigBasin AI 平台。DLRM 基准提供两个版本的代码，一个使用 PyTorch，另一个使用 Caffe2 算子。此外还提供使用 Glow C++ 算子的一个变体。（各框架的代码略有差异以适应其特性，但整体结构相似。）这些实现让我们可以对比 Caffe2 框架与 PyTorch 框架，以及目前面向加速器的 Glow 实现。或许最重要的是，我们随后可以凸显各自的最佳特性，未来将其整合进单一框架。

（原文此处附图：Big Basin 采用模块化、可扩展的架构。开源设计在此可得。）

DLRM 基准支持生成随机和合成输入。支持自定义生成与类别特征对应的索引有许多理由。例如，如果我们的应用使用某个特定数据集但出于隐私原因不愿分享，我们可以选择用分布来表达类别特征。此外，如果想考察系统组件（例如研究内存行为），我们可能希望在合成 trace 中捕捉原始 trace 访问的基本局部性。再者，Facebook 的各项服务根据用例使用多种个性化推荐模型。例如，为了在规模上实现高性能，服务可以通过批量输入以及将多个模型并置在单台机器上，跨不同平台并行化推理。另外，Facebook 数据中心中服务器的多样性带来了架构异构性，从不同的 SIMD 宽度到缓存层次的不同实现。这种架构异构性带来了额外的软硬件协同设计和优化机会。（关于 Facebook 神经推荐系统的系统架构含义的深入分析见这篇论文。）

## 并行性

如上面第一张图所示，DLRM 基准由计算主导的 MLP 和受内存容量限制的嵌入组成。因此很自然地，依靠数据并行来提升 MLP 性能，依靠模型并行来满足嵌入的内存容量需求。DLRM 基准提供了遵循这一方法的并行实现。（它在功能上正确，但目前未针对性能优化。）我们注意到，在计算交互时它需要一个高效的全对全通信原语，我们称之为蝶式洗牌（butterfly shuffle）。它把每个设备上整个 minibatch 的嵌入查找结果，洗牌成所有设备上 minibatch 各部分的嵌入查找。下图展示了这一点，每种颜色表示 minibatch 的不同元素，每个数字表示设备及分配给它的嵌入。（我们计划优化系统，并在未来的博文中分享详细的性能研究。）

（原文此处附图：DLRM 蝶式洗牌的图示。）

## 建模与算法实验

DLRM 基准用 Python 编写以实现灵活，模型架构、数据集和其他参数由命令行参数定义。DLRM 既可用于推理也可用于训练。在后一种情况下，反向传播算子会被加入计算图以支持参数更新。代码是自包含的，可与公开数据集对接，包括 Kaggle 展示广告挑战数据集。该数据集包含 13 个连续特征和 26 个类别特征，它们定义了 MLP 输入层的规模以及模型中使用的嵌入数量，其他参数可在命令行定义。例如，以下列命令行参数运行 DLRM 的结果见下图。

```bash
python dlrm_s_pytorch.py --arch-sparse-feature-size=16 --arch-mlp-bot="13-512-256-64-16" --arch-mlp-top="512-256-1" --data-generation=dataset --data-set=kaggle --processed-data-file=./input/kaggle_processed.npz --loss-function=bce --round-targets=True --learning-rate=0.1 --mini-batch-size=128 --print-freq=1024 --print-time
```

（原文此处附图：左图展示训练和测试的二值交叉熵损失；右图展示训练和测试准确率。）

该模型在真实数据集上运行，使我们能够度量模型的准确率——这在试验不同数值技术和其他模型时尤其有用。我们计划在后续工作中提供量化影响和算法实验对该模型的更深入分析。

通过提供对 DLRM 这一最先进个性化推荐系统的详细描述及其开源实现，我们希望引起对该类模型独特挑战的关注。我们期待与 AI 社区的其他人合作，在算法实验、建模、系统协同设计和基准测试方面取得进展。从长远来看，开发更新更好的方法，将深度学习用于推荐和个性化工具（并提升模型效率与性能），将带来把人与最相关内容连接起来的新途径。
