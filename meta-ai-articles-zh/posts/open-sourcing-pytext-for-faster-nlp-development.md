# 开源 PyText，加速 NLP 开发

> 原文：[Open-sourcing PyText for faster NLP development](https://ai.facebook.com/blog/open-sourcing-pytext-for-faster-nlp-development) · Meta AI（Wayback 存档）

为了让自然语言处理（NLP）系统的构建和部署更加容易，我们开源 PyText——一个模糊实验与大规模部署之间界限的建模框架。PyText 是一个构建在我们统一的开源深度学习框架 PyTorch 之上的库。它为 NLP 开发提供了多项好处：

- 简化的工作流，实现更快的实验迭代。
- 提供丰富的预构建模型架构以及用于文本处理和词汇表管理的工具，便于大规模部署。
- 能够利用 PyTorch 生态系统，包括 NLP 社区的研究人员和工程师创建的预构建模型和工具。

AI 研究人员和工程师现在可以使用 PyText 更快速、更容易地实验并部署执行文档分类、序列标注、语义解析、多任务建模等任务的系统。在 Facebook，我们用这个框架把 NLP 模型从想法到完整实现的周期缩短到只需几天（而非数周或数月），并部署了依赖多任务学习的复杂模型。如今在 Facebook，PyText 每天用于超过十亿次预测，证明它可以在生产规模下运行，同时满足严格的时延要求。

从事神经网络工作的工程师历来面临一个权衡：为实验优化的框架与为生产优化的框架之间只能二选一。这对 NLP 系统尤为突出——它可能需要创建、训练和测试几十个模型，而且使用本质上动态的结构。面向研究的框架可以提供简单、即时执行（eager execution）的接口，加快编写高级动态模型的过程，但在生产中会带来更高的时延和内存占用；为生产优化的框架或许通过把模型表示为静态图来便于部署，但这种方式很难创建文本序列的动态表示。PyTorch 1.0 通过提供单一统一框架加速了从研究到生产的路径；PyText 则在这一基础上解决 NLP 建模的具体需求。我们现在发布我们的工作，开源 PyText 框架，并分享用于大规模训练和部署 PyText 模型的预训练模型与教程。

## 更好的 NLP 工具的需求

AI 研究人员和工程师手中的、能理解人类语言的系统，应用范围广泛且不断扩大。在 Facebook，NLP 被用来向人们提供更相关的内容、提供强大的无障碍功能、标记违反政策的帖子、执行翻译等等。对话式 AI 的最先进水平正在快速进步，PyText 正在帮助我们更快地把这些新进展落地，提升产品质量。

PyText 目前已应用于 Portal——我们的新视频通话设备——以及 Messenger 的 M 建议功能中。我们还在探索把 PyText 用于对话式 AI 的其他方式。借助 PyText，Portal 支持「Hey Portal」语音命令中的组合式和嵌套式通话查询。该功能允许人们使用「给我爸打电话」这样的语音命令，这要求系统理解呼叫者与其所呼叫之人之间的关系。它利用了最初在这篇论文中分享的语义解析工作，而我们得以用 PyText 快速把该技术带入生产。

我们使用 PyText 快速迭代 Portal NLP 模型的渐进式改进，例如模型集成、条件随机场，以及覆盖所有领域的合并模型。这使核心领域的模型准确率提升了 5% 到 10%。我们还利用 PyText 对分布式训练的支持，把 Portal 的训练时间缩短了 3-5 倍。

PyText 带来的快速迭代还帮助我们提升 NLP 模型的效率和可扩展性。对于 Portal、Messenger 和许多其他用例，我们需要实时运行模型以提供快速响应，也需要能在超大规模下高效运作的 NLP 系统。PyText 让 Facebook 的工程师更容易在为数十亿使用多种语言的人服务的系统中部署先进的实时 NLP。

PyText 构建并补充了 Facebook 的其他 NLP 系统。例如，它可以与我们的 fastText 库配合使用：研究人员和工程师可以在 fastText 中训练词嵌入，然后在 PyText 中使用。PyText 还在若干重要方面改进了 DeepText——例如后者无法实现动态图。PyText 中的一些语义解析和多任务学习模型无法用 DeepText 构建，因为模型中存在条件执行和自定义数据结构。PyText 还加快了训练，因为它可以利用 GPU，并更容易实现分布式训练。我们计划把 PyText 作为今后主要的 NLP 平台。

## 灵活的模块化设计

PyText 构建在 PyTorch 之上，并连接到 ONNX 和 Caffe2。借助 PyText，AI 研究人员和工程师可以把 PyTorch 模型转换为 ONNX，然后导出为 Caffe2 以进行大规模生产部署。它提供灵活、模块化的工作流，具有可配置的层和可扩展的模型组件接口。PyText 可以作为端到端平台，开发者开箱即用即可创建完整的 NLP 管线；但其模块化结构也允许工程师把单个组件纳入现有系统。

每个组件的角色及其与其他模块的交互取决于具体任务。例如，数据处理器（data handler）组件与训练器、损失和优化器组件协作来训练模型；但数据处理器也与预测器和模型交互以进行推理（在真实流量上运行训练好的模型）。这种模块化方式强化了 PyText 的通用性——该平台几乎可以用于从研究到生产过程的任意环节——从头构建完整的 NLP 系统，或对现有系统进行修改。

PyText 还包含其他一些改进 NLP 工作流的特性。该框架支持分布式训练，可以显著加快需要多次运行的 NLP 实验；它还支持一次训练多个模型的多任务学习。其他面向训练的优化包括：

- **可移植性。**PyText 模型构建在 PyTorch 之上，可以在 AI 社区的不同组织之间轻松共享。
- **预构建模型。**凭借聚焦常见 NLP 任务（如文本分类、词标注、语义解析和语言建模）的模型动物园，PyText 让你只需极少的额外工作就能在新数据上使用预构建模型。
- **上下文模型。**为了在各类 NLP 任务中改进对话理解，我们可以用 PyText 利用上下文信息，例如对话线程的前文。我们在 PyText 中构建了两个上下文模型：用于意图标注任务的 SeqNN 模型，以及用于两任务联合训练的 Contextual Intent Slot 模型。在我们的测试中，引入上下文信息在 Messenger M 建议的多个数据集上带来了显著的性能提升。

为了在生产中进行优化推理，PyText 利用 PyTorch 1.0 的能力，通过优化过的 Caffe2 执行引擎导出模型用于推理。原生 PyTorch 模型需要 Python 运行时，由于 Python 全局解释器锁（GIL）的多线程限制，其可扩展性不足。导出到 Caffe2 则提供了高性能、高效多线程的 C++ 后端，能够以高吞吐量高效服务海量流量。

PyText 的其他特性也让把模型推向生产并部署变得容易，包括：

- 统一的资源，同时适用于面向研究和面向生产的 NLP 工作，例如用于训练和推理的简单 API，以及训练与推理一致的文本预处理。
- 词汇表管理，使 PyText 可以在模型导出到 Caffe2 之后把词汇表附着到模型上。
- 新增对字符串张量的支持，以便在训练和推理中高效处理文本。

## 更轻松地从研究走向生产

从一个新 NLP 模型的想法出发，PyText 提供了必要的抽象，轻松编写新模型或编辑现有模型。训练和评估它们很简单，然后可以进行参数扫描以确定最佳模型。PyText 的设计让 AI 开发者可以专注于他们想改动的特定组件或模型，系统的其余部分使用开箱即用的组件。这会产生一个可在 Python 环境中运行的 PyTorch 模型。借助 PyText 的 Python 服务，AI 开发者可以部署模型并接收小比例产品用户的流量，快速获得在线指标。一旦工程师对模型表现满意，就可以使用 PyText 中的导出器模块，经 ONNX 把模型转换为 Caffe2。随后可以评估 Caffe2 模型，并部署到能处理生产流量的 C++ 推理服务中。

## PyText 与 NLP 工具的未来

我们的内部部署已经证明，PyText 让工程师能够更快地迭代新颖的 NLP 建模想法，并快速将其扩展到生产。NLP 领域庞大且演进迅速，我们将继续提升 PyText 的能力，以测试新的最先进模型并大规模高效部署。由于把复杂 NLP 模型放到移动设备上仍然充满挑战，我们正在构建面向设备端模型的端到端工作流。我们的近期计划包括支持多语言建模及其他建模能力、让模型更易调试，以及为分布式训练添加进一步优化。

PyText 一直是 Facebook AI 各团队协作的成果，包括专注于 NLP 和对话式 AI 的研究人员与工程师，我们期待携手继续增强它的能力。关于 PyText 的更多细节，请阅读我们的完整论文。
