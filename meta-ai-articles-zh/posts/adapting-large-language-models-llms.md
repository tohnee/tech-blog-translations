# 适配大语言模型（LLM）的方法

> 原文：[adapting-large-language-models-llms](https://ai.meta.com/blog/adapting-large-language-models-llms) · Meta AI（Wayback 存档）

这是关于适配开源大语言模型（LLM）三部分系列博文的第一篇。在这篇文章中，我们将介绍把 LLM 适配到领域数据的各种可用方法。在第 2 部分中，我们将讨论如何判断微调是否适合你的用例。在第 3 部分中，我们将探讨一些策划优质训练数据集的经验法则。

## 引言

大语言模型（LLM）已在大量语言任务和自然语言处理（NLP）基准上展现出卓越能力。基于这些「通用化」模型的产品用例正在不断增长。在这篇博文中，我们将为希望适配并把 LLM 集成到项目中的小型 AI 产品团队提供指导。我们先厘清围绕 LLM 的（常常令人困惑的）术语，然后简要比较不同的适配方法，最后推荐一张循序渐进的流程图，帮助你为自己的用例确定正确的方法。

## LLM 适配的方法

### 预训练

预训练是指使用数万亿个数据词元从头训练一个 LLM 的过程。模型使用自监督算法训练，最常见的是以自回归方式预测下一个词元（即因果语言建模）。预训练通常需要数千 GPU 小时（10^5 – 10^7，参见来源 1、来源 2），分布在多块 GPU 上。预训练得到的模型被称为基础模型（foundation model）。

### 继续预训练

继续预训练（continued pre-training，又称第二阶段预训练）是指用新的、未见过领域数据进一步训练基础模型。它使用与初始预训练相同的自监督算法。通常所有模型权重都会参与训练，并把一部分原始数据混入新数据。

### 微调

微调是指以监督方式使用标注数据集，或使用基于强化学习的技术，来适配一个预训练语言模型的过程。与预训练相比有两个主要区别：

- 在包含正确标签/答案/偏好的标注数据集上进行监督训练，而非自监督训练；
- 所需词元更少（数千或数百万，而非预训练所需的数十亿或数万亿），其主要目的是增强指令遵循、人类对齐、任务表现等能力。

理解当前微调格局有两个维度：被改变的参数比例，以及微调带来的新能力。

**被改变的参数比例**

根据被改变的参数数量，算法可分为两类：

- **全量微调（full fine-tuning）：**顾名思义，这涵盖了改变模型全部参数的做法，既包括在 XLMR、BERT 等较小型模型（1 亿 – 3 亿参数）上进行传统微调，也包括对 Llama 2、GPT3 等大模型（10 亿以上参数）的微调。
- **参数高效微调（PEFT）：**PEFT 算法不对全部 LLM 权重做微调，而是只微调少量新增参数，或更新预训练参数的一个子集，通常占总参数的 1% – 6%。

**为基础模型增添的能力**

微调的目的是为预训练模型增加能力——例如指令遵循、人类对齐等。Chat 版 Llama 2 就是一个增加了指令遵循和对齐能力的微调模型示例。

### 检索增强生成（RAG）

企业还可以通过添加领域专属知识库来适配 LLM。RAG 本质上是「由搜索驱动的 LLM 文本生成」。RAG 于 2020 年提出，它使用根据用户问题检索到的动态提示上下文并将其注入 LLM 提示，引导模型使用检索到的内容而非其预训练的（可能过时的）知识。Chat LangChain 是一个基于 RAG 驱动的、面向 LangChain 文档的问答聊天机器人。

### 上下文学习（ICL）

使用 ICL 时，我们通过在提示中放入示例样本来适配 LLM。多项研究表明「以示例演示」是有效的。示例可以包含不同种类的信息：

- 仅输入与输出文本——即小样本学习（few-shot learning）；
- 推理轨迹：加入中间推理步骤，见思维链（Chain-of-Thought，CoT）提示；
- 规划与反思轨迹：加入教会 LLM 规划并反思其解题策略的信息，见 ReACT。

还有多种其他修改提示的策略，《提示工程指南》（Prompt Engineering Guide）提供了全面的综述。

## 选择合适的适配方法

要决定上述哪种方法适合特定应用，应考虑多种因素：目标任务所需的模型能力、训练成本、推理成本、数据集类型等。下面的流程图总结了我们的建议，帮助你选择合适的 LLM 适配方法。

### ❌ 预训练

预训练是 LLM 训练的重要环节，使用词元预测变体作为损失函数。其自监督特性允许在海量数据上训练。例如，Llama 2 在 2 万亿词元上训练。这需要庞大的计算基础设施：Llama 2 70B 耗时 1,720,320 GPU 小时。因此，对于资源有限的团队，我们不推荐把预训练作为 LLM 适配的可行方法。

既然预训练在计算上令人望而却步，那么更新一个已预训练模型的权重，理应是让 LLM 适配特定任务的有效方式。任何更新预训练模型权重的方法都容易出现一种称为「灾难性遗忘」（catastrophic forgetting）的现象，这个术语指的是模型遗忘先前学到的技能和知识。例如，该研究表明，在医疗领域微调的模型在指令遵循和常见问答任务上出现性能退化。其他研究也表明，通过预训练获得的通用知识可能在后续训练中被遗忘。例如，该研究从领域知识、推理和阅读理解的角度，提供了 LLM 知识遗忘的一些证据。

### ❌ 继续预训练

在考虑过灾难性遗忘之后，近期的进展表明，继续预训练（CPT）能以远低于预训练的计算成本带来进一步的性能提升。CPT 对那些需要 LLM 掌握新转换技能的任务有益。例如，有报告称继续预训练在增添多语言能力方面取得了成功。但 CPT 仍然是一个昂贵的过程，需要大量数据和计算资源。例如，Pythia 系列经历了第二阶段预训练，催生了 FinPythia-6.9B。这个专为金融数据设计的模型，使用包含 240 亿词元的数据集进行了 18 天的 CPT。此外，CPT 也容易出现灾难性遗忘。因此，对于资源有限的团队，我们不推荐把继续预训练作为 LLM 适配的可行方法。

总而言之，像预训练和继续预训练那样，用自监督算法和未标注数据集来适配 LLM，资源与成本消耗巨大，不是推荐的可行方法。

### ✅ 全量微调与参数高效微调（PEFT）

使用较小型标注数据集的微调，与使用未标注数据集的预训练相比是更经济的方法。通过把预训练模型适配到特定任务，微调模型已被证明能在广泛应用以及法律、医疗、金融等专业领域取得最先进的结果。微调——尤其是参数高效微调（PEFT）——所需的计算资源仅为预训练/继续预训练的一小部分。因此，对于资源有限的团队，这是适配 LLM 的可行方法。在本系列的第 3 部分，我们将深入微调细节，包括全量微调、PEFT 以及如何进行微调的实用指南。

### ✅ 检索增强生成（RAG）

RAG 是另一种流行的 LLM 适配方法。如果你的应用需要从动态知识库中提取信息（例如问答机器人），RAG 可能是很好的解决方案。基于 RAG 的系统的复杂度主要在于检索引擎的实现。这类系统的推理成本可能更高，因为提示中包含检索到的文档，而多数提供商按词元计费。在本系列的第 2 部分，我们将更全面地讨论 RAG，并与微调做比较。

### ✅ 上下文学习（ICL）

这是适配 LLM 最经济的方式。ICL 不需要任何额外训练数据或计算资源，因而性价比高。不过，与 RAG 类似，随着推理时处理的词元增多，推理成本和延迟可能上升。

## 总结

构建基于 LLM 的系统是一个迭代过程。我们建议从简单方法入手，逐步增加复杂度，直到达成目标。上面的流程图勾勒了这一迭代过程，可作为你 LLM 适配策略的坚实基础。
