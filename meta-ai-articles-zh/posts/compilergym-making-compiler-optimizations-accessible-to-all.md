# CompilerGym：让人人都能做编译器优化

> 原文：[CompilerGym: Making compiler optimizations accessible to all](https://ai.facebook.com/blog/compilergym-making-compiler-optimizations-accessible-to-all) · Meta AI（Wayback 存档）

**它是什么**

我们发布 CompilerGym——一个面向编译器优化任务的高性能、易用强化学习环境库。CompilerGym 由 Facebook AI 基于 OpenAI Gym 构建，提供强大工具，让机器学习（ML）研究社区用熟悉的语言和术语来处理生产级编译器优化问题。CompilerGym 把重要的编译器优化问题打包成强化学习问题的样子。我们收录的编译器优化问题规模庞大。例如，其中一个的搜索空间为 10^4461，远大于棋类游戏围棋；另一个的搜索空间则是无限的。此类规模的问题之所以现在首次有可能取得进展，全赖强化学习的最新进展。CompilerGym 让任何有 ML 或编译器背景的人都能直接上手、开始解决这些问题，无需往常所需的数月枯燥环境搭建时间——因为我们已经替你做好了！

在首个版本中，我们提供三个编译器问题的强化学习环境：使用 LLVM 的阶段排序（phase ordering）、使用 GCC 的标志调优（flag tuning）、以及使用 CUDA 的循环嵌套生成。我们还提供用于训练的大规模程序数据集、验证结果可复现性的脚本、公开排行榜以及一个 Web 前端。随着时间推移，我们计划支持其他成熟的编译器问题，包括寄存器分配、窥孔优化和循环优化。我们也预期增加更多任务、奖励、观测和动作，希望借此让编译器与 ML 两个研究社区走得更近。我们的目标是成为「用 ML 让编译器更快」的催化剂——这一点很重要，因为优化不佳的程序运行缓慢，消耗过多计算资源和能源，限制了高能效边缘设备的应用，也让数据中心不够环保。

## 特性

我们把 CompilerGym 设计得让为编译器研究问题构建 ML 模型像玩电子游戏一样容易。该库的亮点包括：

- **API**：我们使用 OpenAI 的 Gym 接口，因此你可以用 Python 编写智能体。
- **任务与动作**：我们提供 LLVM 阶段排序、GCC 标志调优以及使用 loop_tool 的 GPU 循环嵌套优化的环境。
- **数据集**：我们提供数千个真实世界程序用于训练和评估智能体，覆盖多种编程语言和领域。
- **表示**：我们提供程序的原始表示和多种预计算特征，让你既可以专注于端到端深度学习，也可以用特征加提升树，一直到图模型。
- **奖励**：我们开箱即用地支持针对运行时间和代码体积的优化。
- **测试**：我们提供验证流程以确保结果可复现。
- **基线**：我们提供大量基线算法并报告其性能。
- **竞赛**：提交你的结果，并在社区排行榜上查看。
- **易用性**：我们提供一套命令行工具，无需编写任何代码即可与环境交互，还提供一个交互式 Web 前端，让你通过浏览器探索优化空间。

## 工作原理

我们把编译器优化问题暴露为 Gym 环境，每个环境代表一个具体问题。每个环境提供适合该编译器优化问题的一组观测空间、奖励信号和动作空间。我们的观测是被编译程序的表示，我们提供奖励来指示智能体何时改进了代码质量。这些环境可以像其他 Gym 环境一样使用，例如可以与 RLlib 等库无缝集成（见此示例）。以下是对 LLVM 阶段排序的优化空间执行随机游走所需的全部代码：

```
import compiler_gym
import gym

env = gym.make("llvm-autophase-ic-v0")  # 预打包的编译器环境
observation = env.reset()

for _ in range(1000):
    action = env.action_space.sample()  # 你的智能体（这里随机采取动作）
    observation, reward, done, info = env.step(action)
    if done:
        observation = env.reset()

env.render()
env.close()
```

在上面讨论的 LLVM 阶段排序环境的每一步，智能体必须从 123 种不同的优化中选择下一个要运行的优化pass。一个动作示例是让编译器运行 -dce——一个用于死代码消除的 LLVM pass，它从程序中移除不可达代码。LLVM 环境支持针对运行时间、编译器二进制体积和指令数进行优化。

为了直观感受动作空间，我们通过对一组程序的随机试验，计算出可归因于每个动作的指令数奖励。上图提供了对编译器动力学的洞见：-reg2mem pass 似乎给出的奖励最少（增加了指令数），而 -mem2reg 和 -sroa pass 似乎给智能体带来最大奖励。这与对 LLVM 内部机制的理解相符：-reg2mem 和 -mem2reg 是对称的 pass，分别负责把寄存器访问降级为内存访问、或把内存访问提升为寄存器访问。同时，-instsimplify 似乎通过移除冗余指令来缩减程序体积，而 -float2int 似乎始终不产生奖励——这很合理，因为它只是在改写指令，并不增删指令。

**为什么重要**

编译器是计算技术栈的关键组成部分，它把人类编写的程序翻译成可执行二进制文件。但所有编译器在优化这些程序时都依赖大量人工创造的启发式规则。因此，人们所写下的与最优解之间存在巨大差距。虽然 ML 可以帮助弥合这一差距，但很少有 ML 从业者想成为编译器专家。有了 CompilerGym，我们为 ML 从业者提供了改进编译器优化的工具——无需了解编译器内部机制，也不必摆弄底层 C++ 代码。这一切都由我们的新库代劳。

我们认为，机器可以学会如何优化代码，而不只是依赖人类专家。得益于深度学习和强化学习的最新进展，我们预见这样一个时代：机器在针对性能和能耗调优程序方面会远比现在高效。如果我们成功了，数据中心将消耗更少能源，手机和电脑将运行得更快、更凉爽，我们将能用更少的资源做更多的事。我们相信这是一个有益于社会的结果，我们的目标就是加速迈向这一未来。
