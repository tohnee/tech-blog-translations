## 概述

Large language models，大语言模型，在各项任务中展现了强大的能力，而其模型效果受到数据、模型结构与参数量、计算资源等多方面因素的影响。如下图所示，学术界、工业界都在不断尝试训练更大规模的模型，而模型规模（参数量）的不断增大对 Pre-train、Post-train 等阶段的计算资源，包括算力和显存，提出了更高要求。

![](https://pic3.zhimg.com/v2-ed57c088d5c45d2f9097f8ecab332e76_r.jpg)
*Refs: A survey of large language models*

在 LLM 预训练阶段，通常采用多种分布式并行策略，将整个模型的训练分配到多张 GPU 上，包括数据并行（Data Parallel）、张量模型并行（Tensor Model Parallel）、流水线并行（Pipeline Model Parallel）、序列并行（Sequence Parallel/Context Parallel）、专家并行（Expert Parallel）等。其中。张量模型并行和流水线并行，分别在 张量层次（切开每一个张量）和 网络层次（切整个模型成若干个子模型），对模型进行切分，如下图所示，以达到在有限显存下开展模型训练的目的。

![](https://pic3.zhimg.com/v2-c994235a3cdd4686d25593c7045eb880_r.jpg)
*左侧：流水线并行，层间切分网络；右侧：张量模型并行，层内切分网络*

本文主要介绍，分布式训练中的流水线并行技术，包括（1）朴素流水线并行（2）1F1B（3）Interleave（4）Zero-Bubble（5）DualPipe（6）DualPipeV，均基于 Nvidia Megatron-LM 探讨其实现。

## Megatron-LM 流水线调度流程

Megatron-LM 流水线并行调度时，可分为：（1）执行前向，forward_step，主要问题是 input_tensor 来源在哪；（2）缓存每一步的 input_tensor, output_tensor；（3）执行反向，backward_step，主要问题是 input_tensor, output_tensor, output_tensor_grad 来源于哪；（4）通信，send/recv，需要确定好插在哪个位置，以保证流水线的正确编排。

- forward_step，Megatron-LM schedules.py 中对用户自定义的 forward_step_func 进行了封装，包括确定输入、执行用户自定义 forward_step，最后一个 pp stage 执行 loss_func，执行 loss_scale，返回 output_tensor 等过程。其中，确定输入时，分两种情况，一种是 first pp stage/last pp stage，一种是 middle pp stage。由于每个 stage 都会执行用户自定义 get_batch() 和 forward_step()，用户在 get_batch() 函数中自定义 first pp stage/last pp stage 返回 input_id/labels 即可在 pp 调度时确定正确输入；但 middle stage 的输入来源于上一个 pp stage，即 last pp stage output tensor -> current pp stage input tensor，即需要通过 send/recv 通信来完成，所以在 forward_step 中，包含一个参数 input_tensor，并调用 module.set_input_tensor，将通信获得的 input_tensor 传递给 transformer block 的中间层，从而实现所有 stage 输入的确定。
- 缓存 input_tensor/output_tensor 比较简单，直接保存到 List 中即可，由于每个 micro_batch 中，forward_step/backward_step 按序执行，后续执行 backward_step 需要 input_tensor/output_tensor 时，直接 List.pop(0) 即可获得该 micro_batch 上缓存的 input_tensor 和 output_tensor。
- backward_step，从缓存的 List 中获取到该 micro_batch 对应的 input_tensor/output_tensor 后，直接调用 backward_step 即可，其中 output_tensor_grad 在最后一个 pp stage 的 backward_step 中初始化为全1，其余 pp stage 通过 recv_backward 从下一个 pp stage 获取到。

## 1F1B

1F1B 流水线并行，相比朴素流水线并行，减少了 peak memory usage（bubble没有减少）。减少每个 activation 的保存时间，即每个 micro-batch 数据尽可能早的完成后向计算，从而让每个 activation 尽可能早释放。

## Interleave

interleave 流水线并行，相比 1F1B，在这个 schedule 中，每个设备可以对多个层的子集进行计算，而不是一个连续层的集合。具体来看，之前设备1拥有层1-4，设备2拥有层5-8，以此类推；但现在设备1有层1,2,9,10，设备2有层3,4,11,12。可以更极致的压缩 pipeline bubbles

## DualPipe

DualPipe 是 DeepSeek V3 中使用的流水线并行策略，结合其大规模专家并行，保证了较高的训练效率，主要创新点如下：

- 双流：双通道数据交叉排布，减少气泡[3]。但由于每个 pp stage 需要保存两通道数据训练所需的参数，会导致增加一倍显存。但因为 DeepSeek V3 大稀疏 MOE 配合大 EP，模型参数显存 double 不会显著增加内存消耗
- Backward 分离：将 backward 过程拆分成 backward for input 和 backward for weight，从而实现前向、反向计算过程更细粒度的排列，进一步减少气泡
- 计算/通信交叠：DeepSeek 采用大 MoE，因此引入了all to all 通信，而双流正好可以在 bwd 的同时做另一个流 的 fwd，并且把 all to all 通信 overlap，而单流则无法实现
- Dispatch/Combine vs MLP/Attention 使用不同的 SM

## DualPipeV

在dualpipe的基础之上，一种改进流水排布DualPipeV被提出[2](https://gitee.com/link?target=https%3A%2F%2Fzhuanlan.zhihu.com%2Fp%2F26915547331)。它在流水上从PP维度截取Dualpipe的一半，同时将模型在PP切分的基础上进行进一步地切分，流水呈V字形排布。它解决了Dualpipe冗余参数的问题，算法启动规模也只需要Dualpipe的一半。下图以PP4，10个microbatch为例展示DualPipeV流水排布。
