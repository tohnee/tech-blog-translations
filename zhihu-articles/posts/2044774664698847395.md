## 0、前言

之前听说这一代千问本地部署大模型能力非常强，看了Qwen3.6 27B以及Qwen3.6-35B-A3B的测评，觉得可以尝试折腾一下，遂有了这次的内容。

在安装过程中可以，一边安装一边开一个大模型的网页聊天窗口。当遇到命令行出现错误或者不知道下载哪个文件等问题时，都可以截图问在线大模型，它可以帮你处理掉绝大多数问题。

**关键词：Windows系统，本地部署，Qwen3.6，llama.cpp**

## **1、硬件环境**

本次测试环境如下：

- 操作系统：Windows 11
- GPU：RTX4060Ti 16GB
- CUDA Driver Version：13.1
- 推理框架：llama.cpp
- 模型：Qwen3.6-35B-A3B-IQ3_S.gguf

## 2、需下载内容

### 1）CUDA准备

CUDA的安装可以参照其他教程安装，现有资源非常丰富，在本文章中不再赘述。安装完成后，在命令行窗口中输入

```text
nvidia-smi
```

观察输出确认CUDA是否安装成功，以及确认CUDA的版本号。下图是我的输出结果，可以看到红框中的版本号是13.1.

![](https://pic2.zhimg.com/v2-7c39e6ad407261ce29250ef5df8eaf8b_r.jpg)
*CUDA版本号为13.1*

### 2）lamma.cpp下载解压

ollama虽然使用起来更为简单，但是考虑到单推理场景下llama.cpp 的推理速度通常比 Ollama 快 30% 到 80%，还是决定使用llama.cpp。

lamma.cpp的项目地址为：[lamma.cpp的github地址](https://github.com/ggml-org/llama.cpp)。打开后选择右侧Releases一栏（下图中红框内）

![](https://pic1.zhimg.com/v2-b7f1aab8bab2f5c182c6f702c4e4941c_r.jpg)
*lamma.cpp项目页面，红框内为Releases*

在接下来的页面继续选择适合自己硬件的版本，我选择的是以下两个支持cuda的版本<br>（PS:虽然我的CUDA版本是13.1但是我使用CUDA 13版本的并不能将显卡调用起来，反而CUDA 12的版本可以。大家在遇到使用CPU推理的时候也可以试试换一个版本）

![](https://pic2.zhimg.com/v2-c5bf1ff99b7378340a6fde5d0aa0e131_r.jpg)
*选择合适的版本下载*

下载后为一个压缩包，解压到自己设定的文件夹中即可。我将它解压到了D:\Llama\llama124目录下，为了便于后续讲述将会一直使用该绝对路径，读者在后续可以换为自己lamma.cpp解压目录。

### 3）Qwen模型下载

接下来要选择模型，一般而言这种本地部署的模型中，稠密模型（Qwen3.6 27B）是要优于MoE模型（Qwen3.6-35B-A3B）的。但是囿于硬件的限制，本次下载Qwen3.6-35B-A3B。

模型下载主要有两个网站：

1. [HuggingFace](https://huggingface.co/)：是全球最通用的大模型下载网站，但是在国内速度下载速度有些受限；
2. [魔搭社区](https://modelscope.cn/)：由阿里巴巴达摩院与中国计算机学会（CCF）开源发展委员会共同发起的AI模型开源社区，也有着十分丰富的资源。

本次就是从[魔搭社区](https://modelscope.cn/)进行下载，按照下图中红框的顺序依次点击模型库，搜索Qwen，然后点进红框的模型中（或者可以直接点击链接进入：[Qwen3.6-35B-A3B-GGUF](https://modelscope.cn/models/unsloth/Qwen3.6-35B-A3B-GGUF/summary)）。

![](https://picx.zhimg.com/v2-d887f2c8094af479435f7c416273501b_r.jpg)
*魔搭社区Qwen模型选择*

（PS：搜索结果前两个是官方的文件，但是是safetensors格式的原始模型文件;而lamma.cpp使用的是GGUF量化版本。原始模型文件要像使用还要经过量化甚至微调，才能被lamma.cpp使用。所以建议直接下载GGUF文件）

虽然内存中也可以加载模型，但是速度会降低很多，所以选择本地模型时可以从显存角度考虑。我的硬件是4060Ti 16G，大致就选择比显存小2~3G大小的模型就行。下载位置如下图所示，本次选择了3bit量化的IQ3_S版本。

![](https://pic1.zhimg.com/v2-23222f4340e10ca113d13171aae29a00_r.jpg)
*选择比显存小2~3G的版本，本次选择IQ3_S版本，点击即下载*

下载完成后是一个.gguf文件，存放位置需要记得后需要用，我存放在了D:\LLM_Model\Qwen，后续也将使用此绝对路径讲述。

## 3、开始测试

使用命令行，进入lamma.cpp解压的目录，我的是D:\Llama\llama124，大家可以替换成自己llamma.cpp解压的目录。切换目录后，首先使用cli进行测试整个流程是否能跑通，在命令行中输入

```text
llama-cli.exe ^
-m 模型存放目录 ^
-ngl 999 ^
-p "你好"
```

其中，-ngl 999表示尽可能把模型层放入GPU；模型存放目录则替换为Qwen3.6的gguf文件目录，依照我的目录，命令行中输入的就是

```text
llama-cli.exe ^
-m D:\LLM_Model\Qwen\Qwen3.6-35B-A3B-UD-IQ3_S.gguf ^
-ngl 999 ^
-p "你好"
```

这时一方面要观察命令行窗口是否进入了对话中，Qwen开始进行思考和回答；另一方面，也要打开任务管理器，看以下GPU的显存（任务管理器中是专用GPU内存）占用是不是明显上升了。如果没显存占用没变化，反而是内存占用和CPU负载急剧上升，那就没有使用到GPU。可以换一下llama.cpp的版本（我就是CUDA13.1版本，但是使用lamma.cpp的CUDA 12版本才能正常运行）或者尝试排查下其他的问题。

正常情况如下图所示，就可以使用llama-server建立本地API，可以网页聊天或者接入其它工具中

![](https://pic4.zhimg.com/v2-a24ace07c106aff3db50cdc4bcac69b7_r.jpg)
*加载模型正常的显示*

在命令行窗口中输入：

```text
llama-server.exe ^
-m D:\LLM_Model\Qwen\Qwen3.6-35B-A3B-UD-IQ3_S.gguf ^
-ngl 999 ^
-c 8192 ^
--host 127.0.0.1 ^
--port 8086
```

其中-c 8192是上下文长度设定为8k，如果内存够大可以继续增大上下文长度；--port 8086是随便填的端口，可以自己更换。运行成功后可以在浏览器中输入

```text
http://127.0.0.1:8086
```

便能打开聊天页面进行聊天，如下图所示，效果还不错，速度能达到72token/s，就是上下文有点短

![](https://pic2.zhimg.com/v2-4d44c8bc673caff1fed5710b75020209_r.jpg)
*实际网页对话效果*

## 4、扩展操作

### 1）命令行参数

本部分搬运自站内文章：[【16G显存】最高200+tok/s，用llama.cpp跑qwen3.6-35b-a3b](https://zhuanlan.zhihu.com/p/2040709598194160423)中的表格。在后续命令行和脚本步骤中提供参考，读者可以根据自己使用场景自由设置。

**基础配置参数**

| 参数 | 含义 | 作用 |
| --- | --- | --- |
| –host 0.0.0 | 监听地址 | 允许外部设备（如局域网内的其他电脑）通过 IP 访问你的服务。如果是 127.0.0.1，则只能本机访问。 |
| –port 1234 | 端口号 | 服务运行的端口。客户端（如浏览器、API 调用）需连接 localhost:1234。 |
| –timeout 600 | 超时时间 | 如果 API 请求超过 600 秒（10 分钟），则强制断开客户端连接。 |
| -m “…” | 模型路径 | 最关键参数。指定 GGUF 模型文件的位置。 |
| –alias qwen3.6… | 模型别名 | 在 API 调用中，可以用这个名字代替长路径，方便识别。 |

**上下文参数**

| 参数 | 含义 | 作用 |
| --- | --- | --- |
| -c 43008 | 上下文窗口 | 允许模型记忆的最长 Token 数（42K）。注意：这决定了模型能”记住”多长的对话或文档。 |
| -cb | 上下文缓存优化 | 是否启用连续分批（也称为动态分批）功能，有助于在批量请求时更高效地管理内存。 |
| -b 1024 | 逻辑批次大小 | 每次推理处理的 Token 批大小。1024 较大，适合吞吐量，但占用更多显存。 |
| -ub 512 | 实际批次大小 | GPU/CPU 在底层实际计算时，单次内核调用所处理的最大 Token 数，此值不要超过逻辑批次大小。 |
| -t 12 | CPU 线程数 | 使用 12 个 CPU 线程进行数据处理，通常设为物理核心数或略少。 |
| -ngl 99 | GPU 层数 | 强制将 99 层加载到 GPU。对于小模型而言，这通常意味着全模型入显存，速度最快。如果模型装不下显存时，llama.cpp 也尽可能多地加载 GPU，剩余部分回退 CPU。 |
| -ncmoe 16 | CPU 专家数 | 仅对 MoE 混合模型有效。保留前 N 层混合专家（MoE）权重在 CPU 中推理。这个参数与 ngl 参数互为配合。 |

**推理参数**

| 参数 | 含义 | 作用 |
| --- | --- | --- |
| –reasoning off | 推理模式关闭 | 禁用思维链（CoT）模式的特殊处理。 |
| –reasoning-budget 0 | 推理预算 | 设为 0 表示不限制推理步数（配合 off 使用）。 |
| –flash-attn on | 快速注意力 | 启用快速注意力，显著降低显存占用并提升速度，尤其对长上下文有效。 |
| –repeat-penalty 1.0 | 重复惩罚 | 1.0 表示无惩罚。模型可能会重复啰嗦。建议设为 1.1 - 1.2 以抑制重复。 |
| –temp 0.7 | 温度系数 | 控制随机性。0.7 是平衡创意和准确性的常用值。0 最确定，1 最随机。 |
| –top-k 40 | Top-K 采样 | 每次只从概率最高的前 40 个词中选择。有助于避免生成生僻词。 |
| –top-p 0.95 | Top-P 采样 | 累积概率达到 95% 的词被纳入候选集。与 Top-K 配合使用，控制多样性。 |
| –min-p 0.0 | 最小概率 | 过滤掉概率低于 0.0 的词。0.0 表示不额外过滤。 |

**高级配置参数**

| 参数 | 含义 | 作用 |
| --- | --- | --- |
| –spec-type ngram-mod | N-gram 推测解码* | 类似于 MTP，用于提前推测解码，加快推理速度。 |
| –parallel 1 | 并行请求数 | 同时处理 1 个请求。增加此值可提高吞吐量，但需更多显存。 |
| -dio | 直接 I/O | 绕过操作系统缓存，直接读写磁盘/显存。可能提升大文件加载性能，但增加系统负担。 |
| –no-mmproj | 禁用多模态投影器 | 如果是多模态模型则移除多模态能力，如果是纯文本模型，则无影响。 |
| –mlock | 内存锁定 | 防止模型数据被交换到硬盘（Swap）。对大模型性能至关重要，但会占用更多物理内存。 |
| –no-mmap | 禁用内存映射 | 不使用内存映射文件加载模型。配合 –mlock 使用，确保数据常驻内存。 |

### 2）bat文件

每一次运行命令行感觉麻烦可以写一个bat文件执行。新创建一个空的记事本，然后将后缀名改为bat。使用VSCode等工具编辑该文件，例如最基础的可以写：

```text
@echo off

cd /d D:\Llama\llama124

start "" http://127.0.0.1:8086

llama-server.exe ^
-m D:\LLM_Model\Qwen\Qwen3.6-35B-A3B-UD-IQ3_S.gguf ^
-ngl 999 ^
-c 8192 ^
--host 127.0.0.1 ^
--port 8086
pause
```

其中模型目录要填成自己的。保存该bat文件后，就可以双击该bat文件，自动打开浏览器页面，等待模型加载完成后进行聊天了。

也可以用KV Cache来减小一点内存使用，来换取更长一点的上下文，例如bat文件可以写成

```text
@echo off

cd /d D:\Llama\llama124

start "" http://127.0.0.1:8086

llama-server.exe ^
-m D:\LLM_Model\Qwen\Qwen3.6-35B-A3B-UD-IQ3_S.gguf ^
-ngl 999 ^
-c 16384 ^
--cache-type-k q4_0 ^
--cache-type-v q4_0 ^
--threads 12 ^
--host 127.0.0.1 ^
--port 8086
pause
```

### 3）接入Cherry Studio

在bat文件启动后，可以使用Cherry Studio等第三方工具。以上述bat文件+Cherry Studio为例，本机接口地址为[http://127.0.0.1:8086](http://127.0.0.1:8086)，那在Cherry Studio的设置中选择“添加供应商→类型OpenAI”，然后API地址填写

```text
http://127.0.0.1:8086/v1
```

API秘钥随便填写

模型选择Qwen3.6-35B-A3B-UD-IQ3_S.gguf

设置完成后便可以在Cherry Studio跟本地模型对话了。
