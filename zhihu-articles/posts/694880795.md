## 前言：

如果刚开始接触训练大模型，首先一定会碰到DeepSpeed，ZeRO有三个阶段:ZeRO 1，ZeRO 2，ZeRO 3。如果想要理解这三个阶段的不同，需要明白下面两件事：

1.大模型训练过程中的显存占用都有哪些？

2.DeepSpeed **ZeRO的**三个阶段分别是如何节省显存的？

本篇文章希望用通俗易读的语言来介绍清楚这两件事，让你使用DeepSpeed更加得心应手。

## 大模型的训练过程中的显存占用

常见的大模型如llama 7b、llama 34b、llama 70b。这里的7b，指的是模型的参数，本质上是存储在Tensor矩阵里面的weight和bias。其中b是billion，是10亿。7b，代表有70亿个参数。

**模型参数在计算机中常用的存储类型有fp32和fp16。**

以fp32存储表示：每个参数在计算机中用32 位(bit) 浮点数存储。

以fp16存储表示：每个参数在计算机中用16 位(bit) 浮点数存储。

**计算机基础知识：**

而1 字节(bytes)=8 位(bit)。因此一个16 位(bit) 浮点数的参数就相当于2个字节（bytes）

1 GB= 10^9 字节(bytes)。

模型常说的B是十亿，也就是1 B= 10^9 个参数。

**最终：**

llama 7b有70亿参数，如果使用fp16，因此，我们把llama 7b的权重加载到GPU中。那么需要

70亿*2(bytes)=140亿(bytes)=14GB的显存。

**训练过程中的显存占用包括以下四种：**

**1.模型参数占用。**

**2.梯度占用。**

**3.优化器占用。**

**4.激活值占用。**

**大模型训练中值得注意的两点：**

**一般训练用混合精度训练**: 即模型权重采用fp16(16位浮点数)存储，但是在反向传播更新的时候，混合精度的优化器会维持fp32的模型权重以及fp32优化器参数()的副本，因为使用32位更准确。

**优化器状态**：一般LLM训练使用adamw优化器，其需要维护一份fp32的模型权重(4 bytes * 7B=28 GB),以及梯度的移动平均值(m)和梯度平方的移动平均值(v),这两个都是fp32存储，因此是2*(4 bytes * 7B=28 GB)，共56GB。

1.模型参数：

--fp16存储，2 bytes *7 B =14GB.

2.梯度：

--fp16存储，2 bytes *7 B =14GB.

3.激活值:

--和batch_size和序列长度有关。

4.优化器状态：

--*fp32 模型参数: 4 bytes * 7B = 28GB*

*--fp32*梯度的移动平均值*(m): 4 bytes * 7B = 28GB*

*--fp32*梯度平方的移动平均值*(v): 4 bytes * 7B = 28GB*

**因此，如果不考虑训练过程中的激活值，训练过程中总的内存占用是：Total memory required = 14GB (fp16 Parameters) + 14GB (fp16 Gradients) + 28GB (fp32 Parameters) + 28GB (fp32 Gradients mean) + 28GB (fp32 Gradients variance) = 112GB**

**简单计算是fp16 模型参数14GB的 8 倍。**

到此为止，我们将大模型训练过程中的显存占用分析讲解清楚了。下面介绍deepspeed的三个阶段。

## DeepSpeed ZeRO的三个阶段是如何节省显存的？

一个最简单和直观的训练大语言模型的方法是：

**ZeRo-DP：数据并行训练**

数据并行非常简单，如下图所示-只需使用多个 GPU（每个 GPU 超过 112GB 内存），将模型训练所需要的所有参数全部加载到每个 GPU 上，然后在它们之间分配不同的数据批次。 前向计算完各自的梯度后，通过all gather的操作来累积来自所有GPU的梯度，然后更新各自的模型参数。然而这种方法，需要一个GPU有112GB的显存。

![](https://pic1.zhimg.com/v2-17a88bb84657cda0a4d63d16b066967e_r.jpg)
*数据并行*

这种方法看起来需要特别大的显存，成本高昂，因此研究者们相处了新的方法。也就是DeepSpeed **ZeRO的**三个阶段。

总的思想： ZeRO 通过在分布式训练硬件中的可用设备（GPU 和 CPU）上划分各种模型训练状态（权重、梯度和优化器状态）来减少每个 GPU 的显存消耗，可以在有限的显存中训练更大的模型。

![](https://pica.zhimg.com/v2-e7eab9607917ae8d13d0d94ea7a9c1c6_r.jpg)
*与标准数据并行基线相比，ZeRO 三个阶段的内存节省和通信量。 在内存消耗公式中，Ψ 指模型中的参数数量，K 是优化器特定的常数项。 作为一个具体示例，我们展示了使用 Adam 优化器（其中 K=12）在 64 个 GPU 上的 7.5B 参数模型的内存消耗。 我们还显示了 ZeRO 相对于基线的通信量。*

**ZeRO 1:切分优化器状态。**

如上文所属，我们观察到，在训练LLM的时候，优化器状态是主要的内存占用者（占据了84 GB的显存）。因此，ZeRO 1的思路是将这些优化器状态分布或“分区”到多个 GPU 上。

在此设置中，每个 GPU 运行模型的完整前向和后向传递，但仅更新分配给它的优化器状态。 重要的是，当每个 GPU 执行整个前向和后向传递时，它会从其他 GPU 的参数广播中访问参数以进行更新。

这种方法确实增加了 GPU 间的通信，因为 GPU 需要更频繁地广播更新的梯度和参数。 然而，这种增强的通信负载并不比标准数据并行中的通信负载大得多，在标准数据并行中，梯度和参数更新的 GPU 间通信已经发生。

这种分区技术可以显着节省内存。 通过分配这些状态，我们只需要存储它们一次，从而节省了大量的显存。

**优化器状态分区 (Pos)：我们将优化器状态分布在多个 GPU 上。 此策略可将内存使用量减少 4 倍，同时保持通信量与传统数据并行相同。**

**ZeRO 2:切分梯度。**

**梯度划分（Pos+g）：优化的下一步不仅涉及优化器状态的划分，还涉及梯度的划分。 这种方法再次将内存需求减少了一半，总体减少了 8 倍，同时仍保持与标准数据并行相同的通信水平。**

**ZeRO 3:切分模型参数**

**参数分区 (Pos+g+p)：最后阶段包括对优化器状态、梯度以及现在跨多个 GPU 的参数进行分区。 此阶段的内存减少与使用的 GPU 数量 (Nd) 成正比。 例如，分布在 64 个 GPU (Nd = 64) 上将导致内存需求减少 64 倍。 然而，值得注意的是，这确实导致通信量适度增加了 50%。**

此外，ZeRO-3还包含 infinity offload engine，形成ZeRO-Infinity（论文），可以卸载模型参数或者优化器状态到CPU和NVMe内存，从而连分区也不用，节省大量显存。
