[仓库 · Qeeweew/sglang（dsv4.1-npu-opt）](https://github.com/Qeeweew/sglang/tree/dsv4.1-npu-opt)

> 910B这卡很老了，不支持FP8，更不支持FP4，8卡要运行DeepSeek V4.1之前就要做int4量化，但这样就有精度损失，特别很多甚至都是w4a8量化😅。<br>如何几乎无损适配原始权重又达到比较好的性能，这几天配合GPT 6.1-sol在sglang上完整搞了一下，感觉有点意思，这里分享出来。

Eco-Tech 发布的 W4A8 版本使用 ModelSlim 量化。[Eco-Tech 模型卡](https://www.modelscope.cn/models/Eco-Tech/DeepSeek-V4.1-Flash-1017-w4a8) 虽然采用了quarot等量化算法，但还是会有精度损失，特别是现在都是 agent 长程任务，有些损失甚至测试分数也不一定体现的出来。

当前dsv4.1-npu-opt分支尝试在 910B 上直接用原生 MXFP4 权重计算 MoE，已在 8 张 64 GiB 的昇腾 910B3 上跑通正式版 **DeepSeek V4.1 Flash-1017**。[正式版模型权重](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017)

### 权重怎么处理

| 组件 | 910B 上的处理 |
| --- | --- |
| 路由专家 | 保留原始 MXFP4 权重值和尺度，加载时重排布局，压缩驻留 NPU |
| 部分 dense 层和共享专家 | FP8 解码后按 K 维每 256 个元素量化为 INT8，激活和输出用 BF16 |
| Engram 大表 | 保留 FP8/E8M0，放在主机内存，设备按需取行 |

MXFP4 每组 32 个 E2M1 权重共享一个 E8M0 尺度，平均占 4.25 bit/权重。专家前向只把当前权重 tile 展开为 FP16，剩余权重继续以 4 位格式驻留。[OCP MX 规范](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf)

新增的权重量化集中在 W8A16 路径。对 target 的 Q、KV、Indexer Q、共享专家和 draft Q 共五个矩阵复算，以原 FP8 解码到 BF16 的结果为基准，相对 L2 权重重构误差为 **0.73%–0.79%**。[W8A16 参考实现](https://github.com/Qeeweew/sglang/blob/dsv4.1-npu-opt/test/ascend/dsv41/kernels/references/w8a16.py)

### SGLang 的 910B 适配

SGLang 负责请求调度和 Radix 前缀缓存，910B 后端处理权重装载、Attention、MoE 和 DSpark。Attention 支持 DP8/TP1 与 DP4/TP2，MoE 均使用 EP8。[910B 后端说明](https://github.com/Qeeweew/sglang/blob/dsv4.1-npu-opt/python/sglang/srt/hardware_backend/npu/dsv41/README.md)

![](https://pic1.zhimg.com/v2-98323c6a1097c7181c14c55c31b8d828_r.jpg)
*910B 上的权重装载和推理链路*

Prefill 命中前缀时复用全局 KV，并回放滑窗状态。主 KV 和滑窗 KV 用 BF16，Indexer K 用 INT8。Decode 通过 DSpark 提议草稿，由目标模型验证。目标和草稿路径均可使用 NPU Graph。[DeepSeek V4.1 Flash 技术报告](https://arxiv.org/html/2609.19969)

算子通过 C++ 扩展注册到 Torch，设备核由 DeepJIT 和 CANN 按算子形状编译并缓存。Graph 捕获前准备好设备核和工作区，重放时复用。[算子集成代码](https://github.com/Qeeweew/sglang/tree/dsv4.1-npu-opt/python/sglang/srt/hardware_backend/npu/dsv41/kernels)

![](https://pic4.zhimg.com/v2-e676606a28545337b48cac7ec05f989d_r.jpg)
*Ascend C 算子的集成和执行*

### MXFP4 grouped GEMM

每个 MoE 层有 384 个路由专家，每个 token 选 6 个。EP8 下每卡负责 48 个专家。路由先把各专家的 token 排成连续区间，再交给 grouped GEMM。空专家跳过。[DeepSeek V4.1 Flash-1017 模型配置](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/blob/main/config.json)

![](https://picx.zhimg.com/v2-77c89e3139ac3b7abdbafca33b4d27c7_r.jpg)
*MXFP4 向量解码与并行流水线*

AIV 把预排好的 4 位幅值编号批量转成 FP16，再用向量位操作得到 `2 × E2M1`。另一条路径恢复 `s/2` 尺度，沿 K 维每 32 个值广播相乘，得到 FP16 权重 tile。[向量解码实现](https://github.com/Qeeweew/sglang/blob/dsv4.1-npu-opt/python/sglang/srt/hardware_backend/npu/dsv41/kernels/native/quant_grouped_gemm/decode_pipeline.h)

两路 AIV 各处理一半输出列，通过两块 GM 缓冲交给 AIC。AIC 搬完一个 tile 就归还缓冲，让 AIV 准备后续权重。Cube 同时对已搬入片上的 tile 做 FP16 矩阵乘和 FP32 累加。[Cube 流水线实现](https://github.com/Qeeweew/sglang/blob/dsv4.1-npu-opt/python/sglang/srt/hardware_backend/npu/dsv41/kernels/native/quant_grouped_gemm/cube_pipeline.h)

### 八卡实测

![](https://picx.zhimg.com/v2-0cd26a4749aac7e00e3808e2c240588b_r.jpg)
*Decode 单用户速度与单卡吞吐，及 128K 冷 Prefill*

Decode 图沿用 DeepInfer 的口径，横轴是每用户生成速度，纵轴是单卡输出吞吐，点旁数字是整机并发数。固定 5 个草稿 token，按 **75% 逐 token 草稿接受率**折算。横轴为 `步频 × (1 + 5 × 0.75)`，纵轴为 `横轴 × 整机并发 ÷ 8`。[DeepInfer 绘图脚本](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/examples/sweep/plot_pareto.py)

| 负载 | DP8/TP1 + EP8 | DP4/TP2 + EP8 |
| --- | --- | --- |
| 32K decode，并发 128，每用户速度（75% 折算） | 39.65 tok/s/user | 34.57 tok/s/user |
| 32K decode，并发 128，单卡吞吐（75% 折算） | 634.47 tok/s/NPU | 553.06 tok/s/NPU |
| 32K decode，并发 128，整机实测吞吐 | 5,855.3 tok/s | 4,789.3 tok/s |
| 128K 单请求冷 prefill，首 token 响应 | 14.60 s | 13.36 s |
| 128K 单请求冷 prefill，输入吞吐 | 8,980 tok/s | 9,809 tok/s |

并发 128 时，DP8 和 DP4 的实际草稿接受率分别为 89.6% 和 82.8%。整机实测吞吐按实际提交的 token 计。Prefill 从发出请求计到首个生成响应，两套配置的本地 chunk 不同。[完整实测数据](https://github.com/Qeeweew/sglang/blob/dsv4.1-npu-opt/examples/ascend/deepseek_v41/README.md)

该分支的 Ascend C kernel 和适配代码均由 **GPT 6.1 Sol** 完成。适配代码参考了 DeepInfer、SGLang 的 CUDA 路径和 vLLM Ascend。[DeepInfer](https://github.com/deepseek-ai/DeepInfer) · [SGLang CUDA 实现](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/models/deepseek_v4.py) · [vLLM Ascend](https://github.com/vllm-project/vllm-ascend)

代码和运行方式见 [SGLang 分支的 910B 使用说明](https://github.com/Qeeweew/sglang/blob/dsv4.1-npu-opt/examples/ascend/deepseek_v41/README.md)。
