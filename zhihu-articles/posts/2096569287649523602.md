## 一、提示词工程

提示词工程（Prompt Engineering）的核心，是在已有 Prompt 的基础上不断进行改进，从而获得更加可靠、质量更高的模型输出。这个过程通常不是一次完成的，而是一个持续迭代的过程：先从一个基础 Prompt 开始，对其表现进行评估，再系统地应用不同的提示词工程技巧进行优化。

提示词评估与提示词工程之间存在紧密联系。提示词评估负责衡量 Prompt 当前的实际表现，而提示词工程则根据评估结果对 Prompt 进行改进。常见的优化方式包括让指令更加清晰、更加具体、明确输出格式、使用 XML 标签组织结构，以及使用多示例提示等。

本文主要使用 OpenAI SDK 的 Chat Completions API 访问模型，并使用兼容 OpenAI 接口的模型服务作为实验环境。首先完成客户端、模型以及环境变量等基础配置：

```python
import os
import re
import ast
import json
import concurrent.futures
from textwrap import dedent
from statistics import mean
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
API_KEY = os.getenv("MY_ALI_API_KEY")
BASE_URL = os.getenv("MY_ALI_BASE_URL")
MODEL_ID = "qwen3.7-plus"

client = OpenAI(api_key=API_KEY, base_url=BASE_URL)
```

为了方便后续构建多轮对话消息以及统一模型调用方式，本文进一步定义了一组辅助函数。其中， `add_user_message` 、 `add_assistant_message` 和 `add_system_prompt` 分别负责向消息列表中添加不同角色的消息，而 `chat` 函数则用于封装 Chat Completions API 的具体调用过程。

```python
def add_user_message(messages, text):
    user_message = {"role": "user", "content": text}
    messages.append(user_message)

def add_assistant_message(messages, text):
    assistant_message = {"role": "assistant", "content": text}
    messages.append(assistant_message)

def add_system_prompt(messages, text):
    system_prompt = {"role": "system", "content": text}
    messages.append(system_prompt)

def chat(messages, temperature=1.0):
    params = {
        "model": MODEL_ID,
        "max_tokens": 1024,
        "messages": messages,
        "temperature": temperature,
    }

    completion = client.chat.completions.create(**params)
    return completion.choices[0].message.content
```

### 1. 提示词的迭代优化过程

一个典型的 Prompt 优化流程可以概括为以下五个步骤：

1. 设定目标（Set a goal）：明确希望 Prompt 完成什么任务。
2. 编写初始 Prompt（Write an initial prompt）：先构建一个基础版本。
3. 评估 Prompt（Evaluate the prompt）：根据预先设定的标准测试其表现。
4. 应用提示词工程技术（Apply prompt engineering techniques）：针对评估中发现的问题进行优化。
5. 重新评估（Re-evaluate）：验证修改后的 Prompt 是否真正取得了更好的效果。

其中，最后两个步骤通常需要不断重复，直到 Prompt 的表现达到预期。理想情况下，每一次修改都应该能够在评估分数或其他指标上体现出可以量化的提升。

### 2. 设置评估流程

为了演示这一过程，可以使用一个具体任务作为案例：根据运动员的身高、体重、目标以及饮食限制，为其生成一天的饮食计划。理想的输出不仅需要给出具体食物，还应包含总热量、三大营养素比例、每餐时间以及对应的食物分量。

评估流程可以通过一个 `PromptEvaluator` 类实现，该类负责测试数据生成、Prompt 执行以及模型评分等工作。在创建评估器时，可以通过 `max_concurrent_tasks` 参数控制并发任务数量：

```python
evaluator = PromptEvaluator(max_concurrent_tasks=5)
```

为了避免 API 的速率限制，开发阶段可以先使用较低的并发数量，例如 3。当 API 配额允许时，可以逐步提高并发数量，以加快整体评估速度。

`PromptEvaluator` 类代码如下：

```python
# PromptEvaluator Implementation
class PromptEvaluator:

    def __init__(self, max_concurrent_tasks=3):
        self.max_concurrent_tasks = max_concurrent_tasks

    def render(self, template_string, variables):
        placeholders = re.findall(r"{([^{}]+)}", template_string)

        result = template_string

        for placeholder in placeholders:
            if placeholder in variables:
                result = result.replace("{" + placeholder + "}", str(variables[placeholder]))

        return result.replace("{{", "{").replace("}}", "}")

    def generate_unique_ideas(self, task_description, prompt_inputs_spec, num_cases):
        """根据任务描述生成一组唯一的测试用例创意"""

        prompt = """
        请生成 {num_cases} 个独特且多样化的测试创意，用于测试一个能够完成以下任务的提示词：

        <task_description>
        {task_description}
        </task_description>

        该提示词将接收以下输入：

        <prompt_inputs>
        {prompt_inputs_spec}
        </prompt_inputs>

        每个创意都应代表一个不同的测试场景或示例，用于测试该任务的不同方面。

        输出格式：

        请仅返回一个合法的 JSON 数组，其中每个元素都是测试创意的字符串。

        输出将被 Python 的 json.loads() 直接解析，因此：
        - 不要使用 Markdown 代码块
        - 不要输出 ```json 或 ```
        - 不要添加解释、标题、注释
        - 不要输出 JSON 数组之外的任何内容

        示例：

        [
            "使用计算机科学领域的专业术语进行测试",
            "使用医学研究结论进行测试",
            "使用复杂的数学概念进行测试"
        ]

        请确保每个创意都满足以下要求：

        - 与其他创意明显不同
        - 与任务描述相关
        - 足够具体，能够用于进一步生成完整的测试用例
        - 能够快速完成，不需要大量计算或复杂的多步骤处理
        - 最终答案可以在不超过 400 个 token 的范围内完成

        请仅生成 {num_cases} 个唯一的测试创意。
        """

        system_prompt = (
            "你是一名测试场景设计专家，"
            "专门负责创建多样化且独特的测试场景。"
        )

        example_prompt_inputs = ""

        for key, value in prompt_inputs_spec.items():
            val = value.replace("\n", " ")
            example_prompt_inputs += f'"{key}": {val}\n'

        rendered_prompt = self.render(
            dedent(prompt),
            {
                "task_description": task_description,
                "num_cases": num_cases,
                "prompt_inputs_spec": example_prompt_inputs,
            },
        )

        messages = []
        add_system_prompt(messages, system_prompt)
        add_user_message(messages, rendered_prompt)

        text = chat(messages, temperature=1.0)

        return json.loads(text)

    def generate_test_case(self, task_description, idea, prompt_inputs_spec=None):
        """根据任务描述和具体测试创意生成单个测试用例"""

        if prompt_inputs_spec is None:
            prompt_inputs_spec = {}

        example_prompt_inputs = ""
        input_descriptions = ""

        keys = list(prompt_inputs_spec.keys())

        for i, (key, value) in enumerate(prompt_inputs_spec.items()):
            comma = "," if i < len(keys) - 1 else ""

            example_prompt_inputs += (f'        "{key}": "EXAMPLE_VALUE"{comma}\n')

            val = value.replace("\n", " ")
            input_descriptions += f"- {key}: {val}\n"

        allowed_keys = ", ".join([f'"{key}"' for key in prompt_inputs_spec.keys()])

        prompt = """
        根据以下信息，为提示词评估生成一个详细的测试用例：

        <task_description>
        {task_description}
        </task_description>

        <specific_idea>
        {idea}
        </specific_idea>

        <allowed_input_keys>
        {allowed_keys}
        </allowed_input_keys>

        <input_descriptions>
        {input_descriptions}
        </input_descriptions>

        输出格式：

        {{
            "prompt_inputs": {{
        {example_prompt_inputs}
            }},
            "solution_criteria": [
                "标准1",
                "标准2"
            ]
        }}

        其中：

        - solution_criteria 应为一个简洁的评估标准列表，包含 1 到 4 项。

        重要要求：

        - 你必须且只能在 prompt_inputs 中使用以下输入键：
          {allowed_keys}
        - 不要在 prompt_inputs 中添加任何额外的键
        - allowed_input_keys 中列出的所有键都必须包含在回答中
        - 测试用例应真实、合理，并具有实际使用价值
        - solution_criteria 应简洁、明确，并且可以进行客观评估
        - solution_criteria 只能针对任务描述以及当前生成的 prompt_inputs
          所直接要求的内容
        - 不要加入超出核心任务范围的额外要求
        - 评估标准应简单、聚焦，并与任务的基本要求直接相关
        - 测试用例必须针对给定的 specific_idea 进行设计
        - 测试用例应能够快速完成，不需要大量计算或复杂的多步骤处理
        - 最终解决方案应能够在不超过 400 个 token 的范围内完成
        - 除输出格式中指定的字段外，不要包含任何其他字段

        输出要求：

        - 只返回一个合法的 JSON 对象
        - 不要使用 Markdown 代码块
        - 不要输出 ```json 或 ```
        - 不要添加任何解释、标题、注释、前缀或后缀
        - 不要在 JSON 中使用 // 或其他形式的注释
        - 输出必须能够被 Python 的 json.loads() 直接解析

        下面给出一个示例输入及其理想输出：

        <sample_input>

        <sample_task_description>
        从一段文本中提取主题
        </sample_task_description>

        <sample_specific_idea>
        使用包含多个主题和子主题的文本进行测试，
        例如一段关于可再生能源的文章，
        同时涉及太阳能经济性、风力涡轮机技术和政策影响。
        </sample_specific_idea>

        <sample_allowed_input_keys>
        "content"
        </sample_allowed_input_keys>

        </sample_input>

        <ideal_output>

        {{
            "prompt_inputs": {{
                "content": "向可再生能源转型涉及许多相互关联的方面。太阳能光伏技术的成本已显著下降，同时风能技术也通过创新的涡轮机设计不断发展。政府政策也会影响不同能源技术的推广速度。"
            }},
            "solution_criteria": [
                "包含文本中提到的所有主要主题"
            ]
        }}

        </ideal_output>

        之所以这是一个理想输出，是因为 solution_criteria
        简洁明确，并且没有提出任何超出任务描述范围的要求。
        """

        system_prompt = ("你是一名测试用例设计专家，专门负责设计评估场景。")

        rendered_prompt = self.render(
            dedent(prompt),
            {
                "allowed_keys": allowed_keys,
                "task_description": task_description,
                "idea": idea,
                "example_prompt_inputs": example_prompt_inputs,
                "input_descriptions": input_descriptions,
            },
        )

        messages = []
        add_system_prompt(messages, system_prompt)
        add_user_message(messages, rendered_prompt)

        text = chat(messages, temperature=0.7)

        test_case = json.loads(text)

        test_case["task_description"] = task_description
        test_case["scenario"] = idea

        return test_case

    def generate_dataset(self, task_description, prompt_inputs_spec=None, num_cases=1, output_file="dataset.json",):
        """根据任务描述生成测试数据集并保存到文件"""

        if prompt_inputs_spec is None:
            prompt_inputs_spec = {}

        ideas = self.generate_unique_ideas(task_description, prompt_inputs_spec, num_cases)

        dataset = []

        completed = 0
        total = len(ideas)
        last_reported_percentage = 0

        with concurrent.futures.ThreadPoolExecutor(max_workers=self.max_concurrent_tasks) as executor:

            future_to_idea = {
                executor.submit(
                    self.generate_test_case,
                    task_description,
                    idea,
                    prompt_inputs_spec,
                ): idea
                for idea in ideas
            }

            for future in concurrent.futures.as_completed(future_to_idea):
                try:
                    result = future.result()

                    completed += 1

                    current_percentage = int((completed / total) * 100)

                    milestone_percentage = (current_percentage // 20) * 20

                    if (milestone_percentage > last_reported_percentage):
                        print(f"Generated {completed}/{total} test cases")

                        last_reported_percentage = (milestone_percentage)

                    dataset.append(result)

                except Exception as e:
                    print(f"Error generating test case: {e}")

        with open(output_file, "w", encoding="utf-8") as f:
            json.dump(dataset, f, indent=2, ensure_ascii=False)

        return dataset

    def grade_output(self, test_case, output, extra_criteria=None):
        """使用模型评估单个测试用例的输出"""

        prompt_inputs = json.dumps(test_case["prompt_inputs"], ensure_ascii=False,indent=2)

        extra_criteria_section = ""

        if extra_criteria:

            extra_criteria_template = """
            强制要求——任何违反以下要求的情况都将被视为自动失败
            （评分不得高于 3 分）：

            <extra_important_criteria>
            {extra_criteria}
            </extra_important_criteria>
            """

            extra_criteria_section = self.render(
                dedent(extra_criteria_template),
                {
                    "extra_criteria": extra_criteria
                },
            )

        eval_template = """
        你的任务是以极其严格的标准评估以下由 AI 生成的解决方案。

        原始任务描述：

        <task_description>
        {task_description}
        </task_description>

        原始任务输入：

        <task_inputs>
        {prompt_inputs}
        </task_inputs>

        待评估的解决方案：

        <solution>
        {output}
        </solution>

        用于评估该解决方案的标准：

        <criteria>
        {solution_criteria}
        </criteria>

        {extra_criteria_section}

        评分标准：

        * 1-3 分：
          解决方案未满足一个或多个强制要求

        * 4-6 分：
          解决方案满足所有强制要求，
          但在次要评估标准上存在明显不足

        * 7-8 分：
          解决方案满足所有强制要求以及大部分次要评估标准，
          仅存在少量问题

        * 9-10 分：
          解决方案满足所有强制要求和次要评估标准

        重要评分说明：

        * 只能依据上面列出的评估标准进行评分，
          不要自行添加额外要求。

        * 如果解决方案满足所有强制要求和次要评估标准，
          应给予 10 分。

        * 不要因为解决方案“只满足”了强制要求和次要评估标准而扣分。
          解决方案无需超出要求，只需准确满足列出的标准。

        * 任何违反强制要求的情况都必须被评为 3 分或以下。

        * 应充分使用 1-10 分的完整评分范围；
          当解决方案确实存在严重问题时，不要犹豫给予较低分数。

        输出格式：

        请按照以下字段和固定顺序返回一个结构化 JSON 对象：

        {{
            "strengths": [
                "优点1"
            ],
            "weaknesses": [
                "不足1"
            ],
            "reasoning": "整体评估说明",
            "score": 8
        }}

        输出要求：

        - 只返回合法的 JSON 对象
        - 不要使用 Markdown 代码块
        - 不要输出 ```json 或 ```
        - 不要添加解释、标题、注释或其他额外文字
        - 输出必须能够被 Python 的 json.loads() 直接解析
        - 回答应简洁、直接
        """

        eval_prompt = self.render(
            dedent(eval_template),
            {
                "task_description": test_case[
                    "task_description"
                ],
                "prompt_inputs": prompt_inputs,
                "output": output,
                "solution_criteria": "\n".join(
                    test_case["solution_criteria"]
                ),
                "extra_criteria_section": (
                    extra_criteria_section
                ),
            },
        )

        messages = []
        add_user_message(messages, eval_prompt)

        eval_text = chat(messages,temperature=0.0)

        return json.loads(eval_text)

    def run_test_case(self, test_case, run_prompt_function, extra_criteria=None):
        """运行单个测试用例并进行评分"""

        output = run_prompt_function(test_case["prompt_inputs"])

        model_grade = self.grade_output(test_case, output, extra_criteria)

        model_score = model_grade["score"]
        reasoning = model_grade["reasoning"]

        return {
            "output": output,
            "test_case": test_case,
            "score": model_score,
            "reasoning": reasoning,
        }

    def run_evaluation(self, run_prompt_function, dataset_file, extra_criteria=None, json_output_file="output.json", html_output_file="output.html"):
        """对数据集中的所有测试用例运行评估"""

        with open(dataset_file, "r", encoding="utf-8") as f:
            dataset = json.load(f)

        results = []

        completed = 0
        total = len(dataset)
        last_reported_percentage = 0

        with concurrent.futures.ThreadPoolExecutor(max_workers=self.max_concurrent_tasks) as executor:

            future_to_test_case = {
                executor.submit(
                    self.run_test_case,
                    test_case,
                    run_prompt_function,
                    extra_criteria,
                ): test_case
                for test_case in dataset
            }

            for future in concurrent.futures.as_completed(future_to_test_case):
                try:
                    result = future.result()

                    completed += 1

                    current_percentage = int((completed / total) * 100)

                    milestone_percentage = (current_percentage // 20) * 20

                    if (milestone_percentage > last_reported_percentage):
                        print(f"Graded {completed}/{total} test cases")

                        last_reported_percentage = (milestone_percentage)

                    results.append(result)

                except Exception as e:
                    print(f"Error grading test case: {e}")

        if results:
            average_score = mean([result["score"] for result in results])

            print(f"Average score: {average_score}")

        with open(json_output_file, "w", encoding="utf-8") as f:
            json.dump(results, f, indent=2, ensure_ascii=False)

        html = generate_prompt_evaluation_report(results)

        with open(html_output_file,"w",encoding="utf-8") as f:
            f.write(html)

        return results
```

### 3. 生成测试数据

评估系统可以根据 Prompt 的任务要求自动生成测试样例。首先需要描述任务目标，并指定 Prompt 所需要的输入字段，例如运动员的身高、体重、训练目标以及饮食限制。

```python
dataset = evaluator.generate_dataset(
    task_description="为一名运动员生成简洁的一日饮食计划",
    prompt_inputs_spec={
        "height": "运动员的身高，单位为 cm",
        "weight": "运动员的体重，单位为 kg",
        "goal": "运动员的目标",
        "restrictions": "运动员的饮食限制"
    },
    output_file="dataset.json",
    num_cases=3
)
```

在开发阶段，测试样例的数量通常不需要太多，可以先使用 2～3 个测试案例，以缩短每次修改后的评估时间。等 Prompt 基本稳定后，再扩大数据集规模进行最终验证。

### 4. 编写初始 Prompt

在开始优化之前，可以先编写一个非常简单的初始 Prompt，作为后续比较的基准。例如：

```python
def run_prompt(prompt_inputs):
    prompt = f"""
    这个人应该吃什么？
    - 身高：{prompt_inputs["height"]}
    - 体重：{prompt_inputs["weight"]}
    - 目标：{prompt_inputs["goal"]}
    - 饮食限制：{prompt_inputs["restrictions"]}
    """

    messages = []
    add_user_message(messages, prompt)
    return chat(messages)
```

这个 Prompt 只简单提供了用户信息，并直接询问“这个人应该吃什么”。它很可能无法稳定生成完整的饮食计划，但正因为它足够简单，所以可以作为后续 Prompt 优化的初始基线。

### 5. 添加评估标准

在执行评估时，还可以额外指定评分模型需要关注的标准。例如，对于饮食计划任务，希望模型输出包含总热量、三大营养素以及每餐的具体食物、分量和时间。

```python
results = evaluator.run_evaluation(
    run_prompt_function=run_prompt, 
    dataset_file="dataset.json",
    extra_criteria="""
    输出应包括：
    - 每日总热量
    - 宏量营养素分配
    - 具体餐食，包括准确的食物、份量和进餐时间
    """
)
```

通过增加这些评价标准，可以让评估模型更加准确地判断当前 Prompt 是否真正满足业务需求，而不仅仅是判断回答内容是否大致合理。

### 6. 分析评估结果

## 二、提示词优化技术

### 1. 清晰且直接地表达任务

Prompt 的第一句话通常非常重要，因为它决定了模型对整个任务的初始理解。一个清晰、直接的开头能够帮助模型快速识别任务目标，减少歧义，从而提高输出结果的稳定性和准确性。

所谓“清晰”，就是尽量使用简单、明确的语言，直接说明希望模型完成什么任务，避免冗长铺垫或模糊表达。例如，与其写“我想了解一下人们安装在屋顶上的、利用太阳能的那些东西”，不如直接写“写三段内容，介绍太阳能板的工作原理”。

所谓“直接”，则是优先使用明确的动作指令来组织 Prompt，例如 `Write` 、 `Create` 、 `Generate` 、 `Identify` 等，让模型一开始就知道需要执行什么操作。例如，与其询问“哪些国家正在使用地热能？”，不如直接要求“列出三个使用地热能的国家，并给出每个国家的发电数据”。

以前面的饮食计划任务为例，可以将开头的问题改为“为一名运动员生成一份符合其饮食限制的一日饮食计划。”：

### 2. **提高提示词的具体性**

除了保证任务表达清晰、直接之外，还需要进一步明确 Prompt 的具体要求。相比让模型自行判断输出内容、结构和处理方式，提前给出明确的约束和执行要求，可以显著提高结果的一致性和质量。

提高具体性通常有两种方式。第一种是明确规定输出应该具备哪些特征，例如回答长度、结构与格式、必须包含的内容，以及语气或风格等。第二种是为模型提供具体的处理步骤，引导其按照一定顺序分析问题，这种方式尤其适合复杂决策、故障排查和需要综合多个因素的任务。

以前面的饮食计划任务为例，可以进一步加入如下要求：

```text
指南：
1. 包含准确的每日总热量
2. 给出蛋白质、脂肪和碳水化合物的摄入量
3. 明确每餐的进餐时间
4. 只使用符合饮食限制的食物
5. 所有食物份量均以克为单位列出
6. 如果提到预算要求，则应尽量经济实惠
```

### 3. 使用 XML 标签

当 Prompt 中包含大量上下文、代码、文档或多组变量时，可以使用 XML 标签对不同内容进行结构化划分。明确的边界能够帮助模型区分任务指令与输入数据，减少不同内容之间的混淆。

例如，可以使用 `<sales_records>` 、 `<my_code>` 、 `<docs>` 等具有描述性的标签，将不同类型的信息分别包裹起来。相比使用 `<data>` 这类过于宽泛的标签，更具体的名称能够让模型更容易理解每一部分内容的作用。

以前面的饮食计划任务为例，可以将运动员信息统一放入 XML 标签中：

```text
<athlete_information>
- 身高：188 cm
- 体重：82 kg
- 目标：增肌
- 饮食限制：素食
</athlete_information>
```

### 4. 提供示例

在 Prompt 中提供示例，是提升模型输出稳定性和准确性的有效方法之一。这种方式通常称为 One-ShotPrompting（单示例提示） 或 Multi-Shot Prompting（多示例提示），即通过给出一组或多组输入与理想输出，让模型更直接地理解任务模式和期望结果。

示例尤其适合处理边界情况、复杂输出格式、特定语气或存在歧义的输入。例如，在情感分析任务中，可以同时提供普通正面表达和讽刺性负面表达，让模型学习如何处理容易误判的情况。

```text
<sample_input>
今晚的比赛太精彩了！
</sample_input>

<ideal_output>
Positive
</ideal_output>

<sample_input>
太棒了，我今晚正好需要一次航班延误！
</sample_input>

<ideal_output>
Negative
</ideal_output>
```

当任务较简单时，可以只提供一个示例；当任务包含多个边界情况或多种有效输出形式时，则更适合使用多个示例。实际应用中，还可以从评估结果中挑选高分输出，将其作为理想示例加入 Prompt，从而进一步引导模型生成更符合要求的结果。

## 三、总结

提示词优化的核心，是让模型更准确地理解任务目标和输出要求。本文主要介绍了四种常用方法：清晰且直接地表达任务、提高提示词的具体性、使用 XML 标签组织内容，以及通过 One-Shot 或 Multi-Shot 示例展示理想输出。这些方法并不是彼此独立的，而是可以组合使用。通过持续修改 Prompt，并结合前面的评估流程进行验证，可以逐步提升模型输出的准确性、完整性和稳定性。
