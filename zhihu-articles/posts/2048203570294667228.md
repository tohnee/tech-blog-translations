### 1. FSDP 是什么？

### 1.1 动机

训练大模型时，单个 GPU 显存放不下整个模型。FSDP（Fully Sharded Data Parallelism，全分片数据并行）的核心思想是：**将模型参数切分到多个 GPU 上，仅在需要计算时才通过通信收集完整的参数**。

### 1.2 与 DDP 的对比

| 特性 | DDP | FSDP |
| --- | --- | --- |
| 参数存储 | 每个 GPU 完整副本 | 每个 GPU 只有 1/N 分片 |
| 通信时机 | 反向传播后 All-Reduce 梯度 | 前向/反向前 All-Gather 参数，反向后 Reduce-Scatter 梯度 |
| 显存节省 | 无 | 显著（参数、梯度、优化器状态都分片） |

### 1.3 FSDP2 与 FSDP1 的区别

FSDP2（`_fully_shard`）是 PyTorch 全新的 FSDP 实现，与 FSDP1 完全独立：

- FSDP1：基于 `FlatParameter`（将所有参数拍平成一个一维张量），使用 `FullyShardedDataParallel` 包装类
- FSDP2：基于 `DTensor`（分布式张量），使用 `fully_shard()` 函数，**以参数组（param group）为单位通信**，更灵活

### 2.3 分层设计理念

FSDP2 的设计核心是**分层**和**分组**：

- **参数组（FSDPParamGroup）**：一次 `fully_shard` 调用创建一个参数组。同一组的参数**一起 All-Gather**，**一起 Reduce-Scatter**。分组越细，内存越省但通信次数越多。
- 推荐用法：从底向上逐层调用 `fully_shard`，每个子模块/每一层作为一个组。

### 3. 核心数据结构

### 3.1 TrainingState（训练状态）

```text
class TrainingState(Enum):
    FORWARD = auto()        # 前向中
```

### 4. 训练生命周期（核心流程）

> 这是最重要的章节。我们将按时间顺序走完一次前向+反向的全流程。

### 4.1 初始化阶段

**入口**：`_fully_shard.py:85` 的 `fully_shard()` 函数

1. 确定 `mesh_info`（1D → FSDP, 2D → HSDP）
2. 确定 `post_forward_mesh_info`（根据 `reshard_after_forward` 参数）
3. 创建 `FSDPState` 并调用 `state.init()`
4. 收集管理的参数，创建 `FSDPParamGroup`
5. 对每个参数创建 `FSDPParam`，调用 `_init_sharded_param()` 进行切分

**切分过程**（`_fsdp_param.py:259`）：

```text
原始参数 → 按 shard_world_size 切分 → 取当前 rank 的分片 → padding 对齐 → 注册到模块
```

### 4.2 前向阶段

### 4.2.1 Root Pre-Forward（根模块前向预处理）

文件：`_fsdp_state.py:111` `_root_pre_forward()`

```text
1. 等待优化器事件（post_optim_event）或同步当前流
2. 等待 all_gather 流（确保之前的通信完成）
3. 将输入张量移动到设备
```

### 4.2.2 Module Pre-Forward（模块前向预处理）

文件：`_fsdp_param_group.py:332` `pre_forward()`

```text
1. 设置 training_state = FORWARD
2. 调用 unshard()     → 启动 All-Gather 通信
3. 调用 wait_for_unshard() → 等待 All-Gather 完成，Copy-Out
4. 注册后向 hook
```

### 4.2.3 Module Post-Forward（模块前向后处理）

文件：`_fsdp_param_group.py:344` `post_forward()`

```text
1. 调用 reshard() → 释放完整参数（或重切分到更小的 world size）
2. 记录前向顺序（用于反向预取）
3. 设置 training_state = IDLE
```

### 4.3 反向阶段

### 4.3.1 Pre-Backward（反向预处理）

由 `_register_pre_backward_hook`（`_fsdp_state.py:318`）触发的 hook：

```text
1. 设置 training_state = PRE_BACKWARD
2. 注册 root post-backward final callback
3. 调用 unshard() + wait_for_unshard() → 重新收集参数
4. 执行反向预取（prefetch 上一个参数组）
```

> **为什么反向要再次 All-Gather？** 因为前向后可能已经 reshard 释放了参数，反向计算梯度需要完整的参数做梯度计算。

### 4.3.2 Post-Backward（反向后处理）

由 `RegisterPostBackwardFunction` 的 backward 或 root callback 触发：

```text
1. 设置 training_state = POST_BACKWARD
2. 累积梯度（accumulate_unsharded_grad_if_needed）
3. 收集有梯度的参数
4. 调用 foreach_reduce() → 执行 Reduce-Scatter
5. 如果开启 reshard_after_backward，释放完整参数
```

### 4.3.3 Root Post-Backward Final Callback

文件：`_fsdp_state.py:275`

```text
1. 对所有状态调用 post_backward()（处理未触发 hook 的情况）
2. 调用 finalize_backward() → 等待所有通信完成
3. 清理状态
```

### 5. All-Gather 详解

### 5.1 概念

**All-Gather** 是一个集体通信操作：每个 rank 把自己的分片发给所有其他 rank，最后每个 rank 都拥有完整的参数。

```text
Rank 0: [A0]     Rank 1: [A1]     Rank 2: [A2]     Rank 3: [A3]
                    ↓               All-Gather
所有 Rank: [A0, A1, A2, A3]
```

### 5.2 实现分析

文件：`_fsdp_collectives.py:137` `foreach_all_gather()`

```text
所有参数组 → 收集 all_gather_inputs
    ↓
在 all_gather_copy_in_stream 上：
    1. 计算输入元数据（dtype, numel）
    2. 调用 all_gather_copy_in 内核
       → 分配输出缓冲区
       → 把各参数的输入拷贝到对应 rank 的位置
    ↓
在 all_gather_stream 上：
    3. 等待 copy-in 流完成
    4. 调用 dist.all_gather_into_tensor()
    5. 记录 all_gather_event
    ↓
等待完成 → foreach_all_gather_copy_out()
    1. 调用 split_with_sizes_copy 把连续的输出拆回给各个参数
    2. 对非 dim-0 切分的参数做 chunk-cat 重排
    3. 调用 fsdp_param.init_unsharded_param() 构造完整参数
```

### 5.3 关键细节

- **All-Gather 的输入来自**：`FSDPParam.all_gather_inputs` 属性（第 687 行）

- **All-Gather 的输出是**：`all_gather_outputs` 列表（每个参数一个缓冲区）

### 6. Reduce-Scatter 详解

### 6.1 概念

**Reduce-Scatter** 是两个操作的组合：先 All-Reduce（求和），再 Scatter（分发）。在 FSDP 中，反向传播计算出的完整梯度需要被切分回各个 rank。

```text
所有 Rank 有完整梯度: [g0, g1, g2, g3] （每个 rank 一样）
                    ↓    Reduce-Scatter
Rank 0: [g0_sum]   Rank 1: [g1_sum]   Rank 2: [g2_sum]   Rank 3: [g3_sum]
```

### 6.2 实现分析

文件：`_fsdp_collectives.py:339` `foreach_reduce()`

```text
1. 收集有梯度的参数和梯度张量
2. 对非 dim-0 切分的参数：chunk 后 cat 到 dim-0
3. 计算 padding 后的大小
4. 在当前流上做 Copy-In：
   → 分配 reduce_scatter_input 缓冲区
   → 用 chunk_cat 把梯度拷入（foreach_reduce_scatter_copy_in）
5. 清除梯度引用（释放内存）
6. 切换到 reduce_scatter_stream，等待当前流
7. 执行 dist.reduce_scatter_tensor()
8. 对 HSDP：在 all_reduce_stream 上执行 all-reduce
9. 在 post_reduce_stream 上：
   → divide（除分片数）
   → dtype 转换（如 reduce_dtype → orig_dtype）
   → 把结果 view 成 sharded_size 的梯度
   → 赋值到 fsdp_param.sharded_param.grad
   → 如果开启 CPU offload：D2H 拷贝
```

### 7. 通信掩盖（Communication Overlap）

> 通信掩盖是 FSDP 性能优化的核心。目标是：**让通信（All-Gather / Reduce-Scatter）和计算（前向/反向）同时进行，互不阻塞。**

### 7.1 不被掩盖的情况（朴素实现）

```text
时间 →    
┌─────────┐  ┌──────────────┐  ┌─────────┐
│ AllGather│→ │   Forward    │→ │ Reshard │
└─────────┘  └──────────────┘  └─────────┘
                  GPU 空闲等待通信
```

### 7.2 FSDP2 的掩盖策略

FSDP2 通过**多流（multi-stream）** 实现三种重叠：

### 7.2.1 前向重叠：Copy-In 与 All-Gather 重叠

```text
Stream 1 (all_gather_copy_in_stream):  Copy-In[组2]  │
Stream 2 (all_gather_stream):          AllGather[组1] │
                                             时间重叠！
```

关键代码（`foreach_all_gather` 第 147-188 行）：

```text
with device_handle.stream(all_gather_copy_in_stream):
    # 1. Copy-In
    all_gather_input, all_gather_output = torch.ops.fsdp.all_gather_copy_in(...)

all_gather_stream.wait_stream(all_gather_copy_in_stream)  # 同步

with device_handle.stream(all_gather_stream):
    # 2. All-Gather 集体通信
    dist.all_gather_into_tensor(...)
```

### 7.2.2 前向重叠：All-Gather 与下一个组的 Copy-In 重叠

这就是**隐式前向预取**（见第 10 节）。关键代码（`wait_for_unshard` 第 276-311 行）：

```text
def wait_for_unshard(self):
    if self._training_state == TrainingState.FORWARD:  # 隐式预取
        if prev_all_gather_state := self.comm_ctx.all_gather_state:
            # 等待前一组完成 Copy-Out
            self._wait_all_gather_streams_on_event(prev_all_gather_state.event)
            self.comm_ctx.all_gather_state = None  # 释放前一组结果
    
    foreach_all_gather_copy_out(...)  # 当前组的 Copy-Out
    
    if not async_op and self._training_state == TrainingState.FORWARD:
        # 保留当前结果，供下一组使用
        self.comm_ctx.all_gather_state = AllGatherState(
            self._all_gather_result, all_gather_copy_out_event
        )
```

**原理**：

- 组 N 的 `wait_for_unshard` 会先检查 `all_gather_state`，如果有前一组（N-1）的结果，就等它
- 同时，组 N+1 的 `unshard()` 已经开始在 `all_gather_copy_in_stream` 上做 Copy-In
- 因此：**组 N Copy-Out ↔ 组 N+1 Copy-In ↔ 组 N+1 All-Gather ↔ 组 N+2 Copy-In** 形成流水线

```text
组1:     |Copy-In|AllGather|Copy-Out|
组2:               |Copy-In|AllGather|Copy-Out|
组3:                         |Copy-In|AllGather|Copy-Out|
                                 ↑ 时间 →
```

### 7.2.3 反向重叠：Reduce-Scatter 与计算重叠

在反向中，当前参数组计算梯度时，上一个参数组的 Reduce-Scatter 已经在 `reduce_scatter_stream` 上运行：

```text
def post_backward(self):
    # ... 收集梯度 ...
    if self.comm_ctx.reduce_scatter_state:
        # 等待上一个 RS 完成
        self.device_handle.current_stream().wait_event(
            self.comm_ctx.reduce_scatter_state.event
        )
        self.comm_ctx.reduce_scatter_state = None
    
    # 启动当前 RS（在 RS 流上）
    foreach_reduce(..., reduce_scatter_stream=self.comm_ctx.reduce_scatter_stream)
    
    # 保存当前 RS 状态供下一组等待
    self.comm_ctx.reduce_scatter_state = ReduceScatterState(
        reduce_scatter_input, reduce_scatter_event
    )
```

### 8. Copy-In 和 Copy-Out

### 8.1 Copy-In（通讯前拷贝）

**定义**：将 All-Gather 的输入数据从各参数的分片内存拼接到一块连续的缓冲区中。

**为什么需要 Copy-In？**

- All-Gather 操作要求输入是连续的张量
- 多个参数可能在不同的内存位置，需要统一拷贝到一起
- 混合精度时需要在拷贝过程中做 dtype 转换

**实现**：`all_gather_copy_in_cuda()`（`_fsdp_collectives.py:73`）

```text
def all_gather_copy_in_cuda(all_gather_inputs, inp_split_sizes, ...):
    all_gather_output = torch.empty((numel * world_size,), ...)  # 分配输出
    all_gather_input = all_gather_output.narrow(0, numel * rank, numel)  # 当前 rank 的位置
    foreach_copy_dsts = torch.split(all_gather_input, inp_split_sizes)
    torch._foreach_copy_(foreach_copy_dsts, all_gather_inputs)  # 批量拷贝
    return all_gather_input, all_gather_output
```

**注意**：`all_gather_input` 和 `all_gather_output` 是**同一个张量不同视图**！`all_gather_input` 指向 `all_gather_output` 中当前 rank 对应的切片。

### 8.2 Copy-Out（通讯后拷贝）

**定义**：将 All-Gather 的输出数据从连续缓冲区拆分回各个参数对应的位置。

**实现**：`foreach_all_gather_copy_out()`（`_fsdp_collectives.py:244`）

```text
# 完整的 all_gather_output → 按参数拆分
torch.ops.fsdp.split_with_sizes_copy(
```

### 9. Stream 和 Event 机制

### 9.1 CUDA Stream 概念回顾

- **Stream（流）**：GPU 上串行执行的操作序列。不同流的操作可以并行执行。
- **Event（事件）**：标记某个流中某个时间点的标记。用于跨流同步。
- **`wait_stream()`**：让当前流等待另一个流中已提交的所有操作完成。
- **`wait_event()`**：让当前流等待某个事件完成。
- **`record_event()`**：在流中记录一个事件。

### 9.2 FSDP2 使用哪些流？

`FSDPCommContext.lazy_init()`（`_fsdp_param_group.py:52`）：

| 流名 | 优先级 | 用途 |
| --- | --- | --- |
| all_gather_copy_in_stream | 高 | All-Gather 的 Copy-In（dtype 转换、数据拷贝） |
| all_gather_stream | 高 | All-Gather 集体通信 |
| reduce_scatter_stream | 高 | Reduce-Scatter 集体通信 |
| all_reduce_stream | 普通 | HSDP 的 All-Reduce |

**为什么 All-Gather 相关流要设高优先级？** 为了避免 Copy-In/Out 被延迟从而阻塞计算。

### 9.3 FSDP2 使用哪些事件？

| 事件 | 类型 | 作用 |
| --- | --- | --- |
| all_gather_event | AllGatherResult | 标记 All-Gather 完成，Copy-Out 等待 |
| all_gather_copy_out_event | AllGatherState | 标记 Copy-Out 完成，下一组 Copy-In 等待 |
| reduce_scatter_event | ReduceScatterState | 标记 Reduce-Scatter 完成 |
| post_reduce_event | FSDPParamGroup | 标记 Reduce-Scatter 后的所有操作（divide、dtype 转换等）完成 |
| reshard_after_forward_event | FSDPParamGroup | 标记重切分完成，下次 Unshard 前等待 |
| grad_offload_event | FSDPParam | 标记梯度 D2H 拷贝完成 |
| all_reduce_event | AllReduceState | 标记 HSDP All-Reduce 完成 |
| post_optim_event | FSDPStateContext | 优化器步骤完成事件，Root Pre-Forward 等待 |

### 9.4 典型同步模式

```text
All-Gather 流同步：

all_gather_copy_in_stream:
   [Copy-In 操作]
        ↓ (wait_stream)
all_gather_stream:
   [All-Gather 操作] → record_event(all_gather_event)
        ↓ (wait_event on main stream)
Main Stream / 计算流:
   [Copy-Out 操作] → record_event(all_gather_copy_out_event)
        ↓ (wait_event on all_gather_copy_in_stream)
all_gather_copy_in_stream（下一轮）:
   [下一个 Copy-In]
Reduce-Scatter 流同步：

Main Stream:
   [Copy-In: 梯度 → reduce_scatter_input] → wait_stream(reduce_scatter_stream)

reduce_scatter_stream:
   [Reduce-Scatter] → record_event(reduce_scatter_event)
   [Divide, dtype转换, 赋值梯度]
        ↓ (wait_event on main stream)
Main Stream（下一个组）:
   [使用梯度 / 继续反向]
```

### 12. HSDP（混合分片）

### 12.1 概念

**HSDP（Hybrid Sharded Data Parallel）** = FSDP（分片）+ DDP（复制）。

对于 2D mesh：

- dim-0：**复制维度**（Replicate），每个 rank 有完整副本
- dim-1：**分片维度**（Shard），参数在 dim-1 上切分

```text
mesh = (R0, R1, R2, ...) × (S0, S1, S2, ...)

例：2×4 mesh
      S0  S1  S2  S3
R0:  [P0] [P1] [P2] [P3]    同一行（R0）内部 FSDP 分片
R1:  [P0] [P1] [P2] [P3]    不同行之间（R0/R1）复制
```

### 12.2 HSDP 的通信

HSDP 有两轮通信：

1. **Reduce-Scatter**（在 shard 维度，dim-1）：每个复制组内部做
2. **All-Reduce**（在 replicate 维度，dim-0）：所有复制组之间做

```text
Rank mapping (2×3 mesh):
         S0    S1    S2
R0:    (0,0) (0,1) (0,2)
R1:    (1,0) (1,1) (1,2)

Reduce-Scatter: 每组 R × (S0,S1,S2) 内部做
All-Reduce:     每组 S × (R0,R1) 内部做
```
