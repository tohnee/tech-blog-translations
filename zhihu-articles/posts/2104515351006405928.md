**RAG（Retrieval-Augmented Generation，检索增强生成）**，用最通俗的一句话解释就是：**让大模型在回答问题前，先去你的“专属资料库”里翻出最相关的参考资料，然后“开卷考试”作答。**

前面学的**向量（Embedding）**、**余弦相似度**、**向量数据库**和**条件过滤**，全部都是为了给 RAG 服务的——它们共同组成了 RAG 的“检索引擎”。

### 一、 为什么需要 RAG？（大模型有三大天然缺陷）

通用大模型（如 GPT、DeepSeek、Claude、Gemini）虽然读过海量互联网公开数据，但直接拿来做企业或个人业务时，有三个致命硬伤：

1. **不知道你的私有数据**：它没见过你们公司的报销制度、内部代码库、产品手册，也看不到你电脑里的本地笔记。
2. **知识有时间截止线**：模型训练完之后发生的新闻、最新颁布的法规，它一概不知。
3. **一本正经地胡说八道（幻觉 Hallucination）**：当遇到不知道的问题时，大模型为了凑出通顺的句子，经常会自己编造规定或数据；而 RAG 强迫它“只能根据查到的资料回答”，并能附上原文出处，大幅降低幻觉。

> **生活类比**：没有 RAG 的大模型，就像一个**博学但只能靠脑子硬背参加“闭卷考试”的学霸**（遇到没背过的公司内部规定就会瞎猜）；而接上 RAG 后，它变成了**允许随时翻阅最新内部手册的“开卷考试”专家**。

### 二、 RAG 的完整工作流

RAG 分为左右两大阶段：**离线建库（准备考场资料）** 和 **在线问答（开卷答题）**。

```text
【阶段一：离线知识入库（只做一次）】
原始文档 (PDF/Word/网页)
   │
   ▼  1. 文本切分 (Chunking) —— 把几百页文档切成 300~500 字的小段落
文档切片 (Chunks) + 元数据 (部门、年份等)
   │
   ▼  2. 向量化 (Embedding) —— 用 BGE 等模型把文字变成 512 维数字
高维向量 (Vectors)
   │
   ▼  3. 建索引存储 —— 用 HNSW 等索引存入 Qdrant / Milvus / pgvector
[ 向量数据库 ]

============================================================

【阶段二：在线实时问答（每次用户提问触发）】
用户提问：“买显卡服务器怎么报销？”
   │
   ▼  4. 问题向量化 —— 用同一个 Embedding 模型把问题也变成 512 维向量
提问向量 + 过滤条件 (如: department == "研发部")
   │
   ▼  5. 向量检索 (Retrieval) —— 算出余弦相似度 Top-K，捞出最相关的几段原文
参考资料片段 (Context)
   │
   ▼  6. 组装提示词 (Prompt) —— 把“参考资料 + 用户提问”拼在一起发给大模型
大模型 (LLM) 理解资料并总结生成 (Generation)
   │
   ▼
最终回答：“根据2025年研发部规定，购买算力服务器和GPU云主机凭发票全额实报实销。”
```

### 三、 既然可以“微调（Fine-tuning）”大模型，为什么绝大多数场景首选 RAG？

初学者常问：“为什么不直接把公司文档拿去重新训练/微调大模型，让它把知识背下来？”

| 对比维度 | RAG（检索增强生成 / 外挂知识库） | Fine-tuning（模型微调 / 修改模型权重） |
| --- | --- | --- |
| 核心本质 | 给模型配一本可随时翻阅的参考书 | 让模型把知识死记硬背刻进脑子里 |
| 知识更新速度 | 秒级生效（数据库里改一条记录即可） | 极慢（改一个数字都要重新准备数据集跑训练） |
| 开发与硬件成本 | 极低（普通 CPU + 向量库即可运行） | 高（需要多张高端 GPU 显卡训练） |
| 可解释性 / 溯源 | 强（能明确指出答案出自哪份文档第几页） | 弱（黑盒输出，很难知道它从哪学来的） |
| 权限隔离 | 极易实现（靠向量数据库的 Metadata 过滤即可） | 极难实现（模型一旦学会，很难控制只对部分人说） |
| 最擅长解决的问题 | “知道新知识、查事实”（知识库问答、客服、法务检索） | “学会新行为、固定说话风格或格式”（如严格输出特定 JSON、模仿特定文风） |

**工业界黄金法则**：**90% 以上的企业 AI 应用都是“RAG 优先”**，只有在需要固化特定输出格式、行业黑话或把大模型蒸馏成小模型降本时，才会配合使用微调。

### 四、 从“能跑通”到“工业级好用”的三个进阶关键点

把最简版 RAG 搭出来只要半小时，但真正上线时，决定回答准不准的往往不是大模型本身，而是检索链路上的三个工程细节：

1. **文档切分（Chunking）**：不能按固定字数（比如每 500 字硬切一刀）把表格或完整段落劈成两半，否则语义会破碎；通常要结合标题层级、段落边界做**语义切分**，并保留前后重叠（Overlap）。
2. **重排序（Reranking）**：向量检索（粗排）追求速度，有时会把“字面像但没回答问题”的段落排到第一。工业界标准做法是：**先用向量库快速捞出前 20 条，再用一个专门的 Rerank 模型（如 `bge-reranker`）逐字精读打分，挑出最准的前 3~5 条喂给大模型**。
3. **混合检索（Hybrid Search）**：把“向量语义搜索”和“传统关键词搜索（BM25）”结合，既能懂同义词，又不会漏掉产品型号、错误码等精确字符。
