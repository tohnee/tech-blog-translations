### 1.3 GPU的层次结构和内存分布

以常用的A100为例，它采用​英伟达的**Ampere架构**，每个SM（流式多处理器）配备 ​**192 KB L1缓存**​（共享内存+寄存器），全芯片共享 ​**40 MB L2缓存**，结合 ​**40 GB HBM2显存**，通过多级缓存大幅减少显存访问延迟，提升计算密集型任务（如AI训练/高性能计算HPC）的吞吐效率。其层次结构和内存分布见下图1-3。同时，笔者常用的A10、V100、A100-40G、A100-80G、V100等型号的GPU参数也总结在图中。

![](https://pic4.zhimg.com/v2-381330414d927e5b3970de47624f59af_r.jpg)
*图1-3：GPU层次缓存结构&各常用显卡参数*

GPU常见术语：

- **Streaming Processor（SP）：**是最基本的处理单元，从fermi架构开始被叫做CUDA core。
- **Streaming MultiProcessor（SM）：**一个SM由多个CUDA core（SP）组成，每个SM在不同GPU架构上有不同数量的CUDA core，例如Pascal架构中一个SM有128个CUDA core。
- **thread：**一个CUDA并行程序由多个thread来执行，thread是最基本的执行单元（the basic unit of execution）；
- **warp：**一个warp通常包含32个thread。每个warp中的thread可以同时执行相同的指令，从而实现SIMT（单指令多线程）并行。warp是SM中最小的调度单位（the smallest scheduling unit on an SM），一个SM可以同时处理多个warp；
- **thread block：**一个thread block可以包含多个warp，同一个block中的thread可以同步，也可以通过shared memory进行通信。thread block是GPU执行的最小单位（the smallest unit of execution on the GPU）。一个warp中的threads必然在同一个block中，如果block所含thread数量不是warp大小的整数倍，那么多出的那个warp中会剩余一些inactive的thread。也就是说，即使warp的thread数量不足，硬件也会为warp凑足thread，只不过这些thread是inactive状态，但也会消耗SM资源。
- **NVLink：**NVIDIA开发的高速GPU互连技术，专为多GPU系统设计，替代传统PCIe总线。
- **NVSwitch：**NVIDIA的GPU互连交换机芯片，用于扩展NVLink连接规模，实现多GPU全带宽互连。
- **InfiniBand（IB）：**高性能网络协议，用于跨服务器/节点的大规模数据通信，常见于HPC和AI集群，当前主流的HDR IB单端口约50GB/s。

由上图可知，GPU里面有些模块的计算吞吐量巨高但内存少（这是芯片设计上，trade-off的结果），十分适合用来临时计算。在实际中，许多优化算法也是借助了这些模块，如Flash Attention，本次不展开介绍，仅对GPU的结构有个基本认识即可。

### 1.4 常见分布式术语

- **node：**物理/虚拟计算单元（如服务器），比如2个节点，每个节点运行4个GPU
- **rank：**进程的唯一标识符（0到N-1），Rank 0通常为主进程，负责协调任务
- **world：**所有进程的总数，比如8个进程（2节点×4 GPU/节点）→ world_size=8
- **RT：**响应时间，即用户请求到系统响应的延迟
- **Throughput：**吞吐量，即单位时间处理的请求量，通常与并发能力相关

### 2.2 数据并行（DP）

为了理清DP方法的脉络，笔者将从 DP->DDP->ZeRO1->ZeRO2->ZeRO3 逐步展开介绍。

**1）简单DP（Data Parallelism）**

- **方法：**每个 GPU 保留一份完整的模型，把每个 batch 拆成 mini-batch 分给各个 GPU，在优化器优化前，将各个GPU的梯度加（即reduce）到主 GPU，优化器状态则是只由主GPU维护。在主 GPU 更新完参数后，再分发（dispatch）给各个 GPU。
- **缺点：**整体效率受到主 CPU 的通信带宽限制，负载不均衡。

**2）DDP（Distributed Data Parallelism）**

为了解决DP的限制（主GPU通信带宽问题），DDP方案如下：

- **方法：**每个GPU保留一份完整的模型，把每个batch拆成 mini-batch 分给各个GPU，然后将DP任务变成"GPU之间执行梯度传递+GPU各自更新权重"。梯度传递采用 Ring All-Reduce，即GPU两两之间的循环传递（详见前文1.2所示 Ring All-Reduce = Scatter-Ruduce + All-Gather，Scatter-Ruduce 就是接收梯度并进行加法，一个循环就能得到模型各部分的全局梯度；All-Gather 是将模型各部分全局梯度逐步分发给其他GPU）。
- **缺点：**虽然负载均衡了，但GPU的总通讯量几乎不变，具体见下面图解2-8。

![](https://pic4.zhimg.com/v2-3b0f8466b5446afac36b9db438a13d7f_r.jpg)
*图2-8：从DP到DDP流程和通讯量对比*

**3）ZeRO1->ZeRO2->ZeRO3**

DP 和 DDP 成功实现了数据并行，但由于每个 GPU 都要加载完整模型，导致模型大小难以被扩展，基于此，诞生了 ZeRO1~ZeRO3。

ZeRO 与 DP/DDP 相比：

- **相同点**：每块 GPU 依旧负责整个模型的所有运算；
- **不同点**：每一层的参数都拆成 N 份，分别存在 N 块 GPU 上，用到的时候，再通过 All-Gather 操作获取。

**4）FSDP（Full-Shared-Data-Parallel）**

[FSDP](https://arxiv.org/pdf/2304.11277)是Meta 提出的一个针对LLM 训练的解决方案，即一个数据并行的策略，通过对模型参数（parameters)，梯度（gradients) 和优化器状态（optimizer states) 在多gpu上点切分实现并行。API简单易用：fsdp_module = FullyShardedDataParallel(module)。

> 与ZeRO相比，FSDP包括了NO_SGARD（等效于DDP)；SHARD_GRAD_OP（对标ZeRO2）；FULL_SHARD （对标ZeRO3）；HYBRID_SHARD（Node内shard，node间replicate，对标ZeRO++ stage3），同时还有_HYBRID_SHARD_ZeRO2（node内ZeRO2 shard，node间replicate）。FSDP提供的默认API是**fully_shard。**

### 2.4 序列并行（SP，又叫CP）

序列并行是一种沿序列维度进行划分的并行策略，是训练长文本序列的有效方法。成熟的序列并行化方法包括Megatron的序列并行化、DeepSpeed-Ulysses序列并行化和环形注意力序列并行化。

**1）Ring Attention（环形注意力）**

环形注意力在概念上类似于Flash Attention。每个GPU仅计算局部注意力，最后将注意力块进行All-Reduce以计算总注意力。在环形注意力中，输入序列沿序列维度被拆分成多个块，每个块由不同的GPU或处理器处理。环形注意力采用了一种称为“环形通信”的策略，其中kv子块通过点对点通信在GPU之间传递进行迭代计算，使得多GPU训练超长文本成为可能。在这个策略中，每个处理器仅与其前驱和后继交换信息，形成一个环形网络。这允许中间结果在处理器之间高效传递，而不需要全局同步，从而减少通信开销。

**2）Megatron的序列并行**

这种SP方法是在TP的基础上实现的。在模型并行中的每个GPU上，样本是独立且被复制的。对于无法利用TP的部分，如LayerNorm等非线性操作，可以沿序列维度将样本数据分成多个部分，每个GPU计算一部分数据。然后，在线性部分如ATTN和MLP中使用张量并行，其activation（激活值）需要被聚合。当模型被划分时，这种方法进一步减少了激活内存的使用。需要注意的是，这种SP方法只能与TP方法结合使用。

**3）DeepSpeed-Ulysses**

该方法将样本沿序列维度拆分，并采用All-to-All通信操作，使每个GPU能够接收到完整的序列，但只计算不重叠的注意力头子集（non-overlapping subset of attention heads），从而实现序列并行化。这种并行策略支持完全通用的注意力机制，同时支持稠密和稀疏两种注意力模式。All-to-All是类似分布式转置操作的全交换通信（见前文1.1小节）：在 Attention 计算之前，样本沿序列维度被拆分，因此每个设备只有长度为N/P的序列；然而，在使用All-to-All之后，q、k、v子部分形状变为[N, d/p]，确保在Attention计算过程中考虑到整个序列。

### 2.5 专家并行（EP）

专家并行是分布式训练中针对混合专家模型（MoE）的并行策略，通过将模型中不同的专家子网络分配到不同设备（即GPU）上独立计算，提升训练效率。其核心机制是门控网络动态路由输入样本到特定专家，仅同步必要的中继梯度（如门控权重），减少设备间通信开销。这种策略可显著扩展模型容量，同时保持计算资源的合理利用，适用于大规模稀疏模型训练。图示可参考前文图2-6。
