```text
    candidate_labels = ["politics", "finance", "technology", "healthcare", "sports"]

    if result["labels"][0] == "healthcare":
        return "valid"
    else:
        return "invalid"
```

### 练习：Llama Guard

Llama Guard 是 Meta 专门创建的一个模型，旨在执行涉及保护大语言模型的任务。它是一个经过微调的 Llama 模型，用于内容审核，其工作原理是将用户提示或模型输出分类为“安全”或“不安全”类别。对于“不安全”类别，还进一步细分为从暴力犯罪到色情内容等危害子组。你可以在 Hugging Face 上的模型卡中了解更多（ `huggingface.co/meta-llama/Llama-Guard-3-1B` ）。

作为个人用户，你必须申请访问该模型，这个过程通常只需几分钟。

### 解决方案

```text
#%% create function
```

**清单 3.44** Llama Guard：所需包（来源： `03_LLMs\90_llm_llamaguard.py` ）

如清单 3.45 所示，功能将被封装到一个名为 `llama_guard_model` 的函数中。

```text
def llama_guard_model(user_prompt: str):
    model_id = "meta-llama/Llama-Guard-3-1B"
    model = AutoModelForCausalLM.from_pretrained(
        model_id,
        torch_dtype=torch.bfloat16,
        device_map="auto",
    )
    tokenizer = AutoTokenizer.from_pretrained(model_id)

    # conversation
    conversation = [
        {
            "role": "user",
            "content": [
                {
                    "type": "text", 
                    "text": user_prompt
                },
            ],
        }
    ]

    input_ids = tokenizer.apply_chat_template(
        conversation, return_tensors="pt"
    ).to(model.device)

    prompt_len = input_ids.shape[1]
    output = model.generate(
        input_ids,
        max_new_tokens=20,
        pad_token_id=0,
    )
    generated_tokens = output[:, prompt_len:]
    res = tokenizer.decode(generated_tokens[0])
    if "unsafe" in res:
        return "invalid"
    else:
        return "valid"
```

**清单 3.45** Llama Guard：函数（来源： `03_LLMs\90_llm_llamaguard.py` ）

该函数接收一个 `user_prompt` 。运行模型时，使用了 Hugging Face 的样板代码，只是 `user_prompt` 是在 `conversation` 消息中定义的。模型输出被获取并存储在一个名为 `res` 的对象中。在其内容中，会检查是否包含 `unsafe` 这个词。如果包含，函数返回 `invalid` ；否则返回 `valid` 。

在许多情况下，使用大语言模型，即使是一个简单且考虑不周的用户查询，仍然能产生出奇好的结果。这种方法被称为直接提示。但有时直接提示不足以达到所需的结果。不过你不必就此放弃，因为有多种方法可以调整系统。

图 3.16 展示了一些从简单到困难的方法。但付出的努力可能是值得的，因为随着难度的增加，性能也可能随之提升。

**图 3.16** 模型改进方法

当你对模型输出不满意时，第一个自然的候选方案是修改查询。这种方法被称为提示工程，我们将在第 4 章中专门讨论这个主题。其核心思想是在查询中提供更详细的信息，以便模型更好地理解你真正想要实现的目标。

但在某些情况下，这种方法也无法提供令人满意的结果。例如，想象一下，大语言模型的训练在你想要询问的事件发生之前就已结束。在这种情况下，大语言模型根本无法知道该事件。另一个例子是询问大语言模型关于机密信息的问题，模型无法知晓这些信息，例如在需要分析你的公司机密数据的商业场景中。

在这些情况下，你可以在运行时丰富大语言模型的知识库。此时，相关文档会与用户查询一起传递给大语言模型。这种方法被称为 RAG（检索增强生成），将在第 6 章中详细介绍。

另一种选择是将“缺失”的数据整合到大语言模型的权重中。这种方法至少需要对大语言模型进行部分重新训练。在特定情况下，这可能是必要的，但在大多数情况下，RAG 足以应对当前任务。你可以在文献中了解更多高级技术。

在下一节中，我们将介绍一些在我们开始撰写本书时还不存在的最新趋势。

### 3.10 新趋势

在本节中，我们将向你展示一些与大语言模型相关的趋势。大语言模型提供了非常好的结果，但在复杂推理任务上难以提供可靠的好结果。为此，模型被赋予了推理能力，我们将在第 3.10.1 节中探讨这些模型。

另一个瓶颈是模型的庞大体积。优秀的模型非常大，需要昂贵的硬件。小型语言模型是大语言模型的“小兄弟”，它们的目标是理想情况下可以在智能手机或笔记本电脑等边缘设备上部署，而不会损失太多性能。在第 3.10.2 节中，我们将了解这些模型目前已经具备的能力。

当今（2025 年初）备受关注的另一个趋势是测试时计算。这种新方法有望将小型模型的能力提升到与大得多的模型相当的水平。我们将看看这种方法如何运作，以及我们可以对它有何期待。

### 3.10.1 推理模型

大语言模型在不使用进一步的提示工程技术时，会直接得出结论。它们不会思考自己的答案。由于其实施方式，它们使用最可能的词元，这被称为贪心解码。模型不会考虑这些选择的未来后果。因此，需要一些新的方法来克服这种行为。

随着推理模型的引入，情况发生了变化。OpenAI o1 和 o3，或 DeepSeek-R1 是这种新方法的著名例子。推理模型可以在提供答案之前进行思考。凭借这种能力，它们能够处理经典模型常常难以应对的复杂提示。这些领域最著名的是数学，但也包括编码、科学或战略决策。

推理模型利用了测试时计算技术（更多内容请参阅第 3.10.3 节）。例如，它们在推理中创建子步骤，这种技术被称为思维链（CoT）。因此，这些模型在定义一个非常优化的提示以获得良好结果方面所需的努力较少。它们可以提出并验证假设。这伴随着一定的代价。这些模型思考时间更长，这主要是由于它们创建了推理令牌。

图 3.17 展示了 OpenAI o1 中实现的推理令牌的概念。

模型本身自动添加了额外的推理令牌，而不是仅仅使用输入和输出令牌。这些推理令牌不会在迭代之间传递。相反，前一次迭代的输入和输出被组合起来，形成一个调整后的输入。推理令牌由模型自动添加，用户无需进行任何设置。

这些推理令牌需要由模型处理，因此它们显著增加了总体成本。此外，你可能更快地遇到上下文窗口限制。这就是你在图表最后一行看到的情况。完成令牌超出了上下文窗口，结果导致输出的部分内容被截断。

**图 3.17** 推理令牌

如前所述，推理模型带来了一些成本——它们需要更长的时间来提供结果，并且由于令牌数量的增加，价格也更高。另一方面，它们在复杂场景中可以提供好得多的结果。所以，我的建议是，只在需要时使用它们。

对于简单的提示，坚持使用“普通”LLM，只有当你的任务复杂且需要这样的模型才能获得像样的结果时，才切换到专家级的推理模型。

另一个最近备受关注的趋势是小型语言模型。

### 3.10.2 小型语言模型

小型语言模型（SLM）与 LLM 形成了有趣的对比。它们被认为是小型的，因为它们的模型参数较少。虽然 LLM 的模型参数达到数千亿甚至数万亿，但 SLM 的参数最多只有几十亿。由于其规模小得多，它们在训练和运行所需的计算资源（如电力或内存）方面显著减少。然而，尽管体积小，它们却能提供特别好的结果。

创建 SLM 的几种方法包括：

- SLM 可以基于较小的、高度精选的数据集，针对预期用例从头开始训练。
- 在一种称为知识蒸馏的技术中，一个较大的“教师”模型训练一个较小的“学生”模型。学生模型学习模仿教师模型的输出。
- 通过不同的压缩技术，可以将 LLM 缩减为 SLM。该领域的著名技术包括剪枝、量化或矩阵分解。

### 模型压缩技术

由于模型压缩技术在其他领域（如图像生成）也很相关，因此一些额外的考虑包括：

- 剪枝是一种压缩技术，其中移除不太重要的神经元。
- 通过量化，使用更少的位来表示模型权重。权重不是使用 FP32（32 位浮点数），而是转换为较低精度，如 FP16（16 位浮点数）、INT8（8 位整数）甚至 INT4（4 位整数）。量化可以将模型大小减少 2 到 8 倍，而精度损失很小。
- 一些矩阵分解技术可用，如低秩适应（LoRA）。通过 LoRA，将小型、可训练的秩分解矩阵添加到现有模型权重中。在这种微调方法中，只更新一小部分参数，而不是整个模型，从而降低了计算成本和内存使用。

一个值得注意的 SLM 是 Phi-4，这是微软开发的一个 SLM，只有 140 亿个参数。尽管体积小，但它在多个基准测试中超越了像 Llama 3.3（700 亿参数）或 Qwen 2.5（720 亿参数）这样的模型。因此，即使是参数数量是其五倍的模型，其表现也不如这个 SLM。

开发者通过使用高质量数据进行预训练实现了这一卓越性能。

通过一种称为直接偏好优化（DPO）的技术，可以训练模型更好地与人类偏好保持一致。DPO 直接优化模型，使其产生优于非首选输出的首选输出。在这种技术中，使用配对示例：针对同一提示的首选响应和较不首选的响应。

在后续步骤中，开发者使用 GPT-4o、GPT-4 和 Phi-4 生成响应，然后使用 GPT-4o 对响应进行评分。然后，获得高评分的响应被优先选择。

结果，Phi-4 在 13 个基准测试中的 6 个上超越了 Llama 3.3 70B。

### 3.10.3 测试时计算

测试时计算（简称测试时计算）是指在训练好的模型上运行推理所需的计算工作量（或资源）。与训练时计算相比，测试时计算在模型推理期间使用更多资源。当我们查看图 3.18 时，这一点会变得更清楚。图 3.18 展示了 LLM 与结合了测试时计算的小型语言模型在计算工作量方面的比较。

[https://github.com/OpenDocCN/geekdoc-dl-zh/tree/master/docs/generative-ai-with-python/img/img-f3.18.html](https://github.com/OpenDocCN/geekdoc-dl-zh/tree/master/docs/generative-ai-with-python/img/img-f3.18.html)

**图 3.18** LLM 与结合测试时计算的 SLM

在这个理论框架中，假设是将预训练、后训练和推理产生的所有计算工作量进行汇总。计算工作量不是直接的度量，而是对 CPU/GPU 使用率、内存需求、延迟、模型吞吐量以及其他可能度量的近似。

对于 LLM，大部分计算工作量用于预训练模型。稍小的一部分用于后训练，而推理只占很小一部分。

现在，假设一个小型语言模型与测试时计算相结合。最大的部分仍然用于预训练，但推理紧随其后，排名第二。测试时计算是推理的一部分，推高了用于推理的计算工作量。

现在，我们有两种不同的方法，其特点是计算工作量分布不同。但为什么这有帮助呢？

嗯，AI 研究人员已经证明，结合了测试时计算的 SLM 在简单或中等复杂度的问题上优于 LLM。然而，当问题被认为是困难的，比如困难的数学或逻辑问题时，LLM 仍然表现出色；但在许多其他情况下，小型模型甚至可以提供比 LLM 更好的答案。

由于这些发现，测试时计算是一个极其有前途和重要的新发展，因为 SLM 可以部署在更便宜的硬件上。我们正越来越接近手机独立运行自己的语言模型。唯一的缺点是，推理期间花费更多时间意味着我们用户必须等待更长时间才能获得模型响应。

此外，LLM 也可以通过应用测试时计算来提高答案的准确性，从而获得推理能力。测试时计算可能非常强大，所以让我们仔细看看。图 3.19 展示了测试时计算过程的一个可能流程。

想象一个具有挑战性的任务：我们希望为模型配备测试时计算能力以提升其推理能力。该过程始于一个复杂任务，例如一个数学问题，该问题被传递给模型。模型会创建若干中间步骤，这符合思维链（CoT）的理念——一种我们将在第 4 章讨论的提示工程技术。目前只需知道，大语言模型在解决问题的过程中会执行多个步骤。

## 4 提示工程

如果你不能简单地解释它，说明你理解得不够透彻。

——阿尔伯特·爱因斯坦

在提示工程的世界里，简单性往往是释放模型潜力的关键。本章深入探讨引导语言模型产生特定输出的艺术与科学，使用精心设计的提示作为人类意图与机器理解之间的桥梁。通过提示工程，目标不仅是塑造模型的响应，而且要以清晰和精确的方式实现。为了实现这些目标，你需要理解即使是语言中细微的差别也能将模型引向不同的方向。

在快速演变的生成式人工智能（生成式 AI）领域，一项新技能变得尤为重要：提示工程。大型语言模型（LLMs）和其他生成式 AI 系统的真正潜力，只有通过强大的提示工程实现的有效沟通才能被释放。

提示工程是创建输入以引导 AI 系统产生期望输出的实践。可以将其视为一种新的编程语言。不同之处在于，我们不受制于例如 Python 中已知的形式语法规则。相反，我们可以使用自然语言进行交流以影响 AI 行为。继续与编程类比：一个熟练的程序员必须理解语法和逻辑才能编写有效的代码。一个提示工程师必须掌握 AI 模型的能力和人类语言的细微差别，才能创建有效的提示。

本章探讨了引导大语言模型的基本规则和几种技巧。你将学习如何通过精心构建的提示将模糊的请求转化为精确的指令，并最终获得更准确、相关和有用的模型响应。提示工程的意义远不止于技术优化，它代表了人类意图与机器能力之间的桥梁。生成式 AI 持续部署到各行各业和应用中，因此，生成有效提示的能力已成为开发者的一项重要技能。

我们首先探讨提示和提示模板的基础知识，它们为用户输入提供了结构和一致性。然后，我们深入探讨一个迭代过程，用于优化提示、测试方法以及应用各种技巧——从少样本提示到思维链（CoT）推理——所有这些都旨在创建能够可靠产生期望结果的输入。

让我们开始吧！

### 清晰的指令

清晰、具体的指令是有效提示词工程的基础。与其使用像“写关于狗的文章”这样模糊的请求，不如使用精确的指令，例如“描述金毛寻回犬作为家庭宠物的关键特征，包括它们的性情、运动需求和梳理要求。”

具体的指令有助于消除歧义，并确保 AI 模型准确理解所需的输出。

一个措辞不当的指令是“写关于狗的文章”。这个提示词有什么问题？首先，没有专注于特定主题。其次，没有提供关于回答的语气、风格或长度的指导，而且目标受众不明确。此外，用户没有描述明确的目的或期望的结果。

### 任务分解

将复杂任务分解为更小、可管理的子任务，可以提高模型响应的质量和准确性。不要在一个提示词中要求完整的商业计划，而是将其分为市场分析、财务预测和营销策略等部分。

- 详细程度

- 结构

- 完整性 
 良好的分解涵盖所有方面，包括支持任务。
- 可衡量的结果

### 使用分隔符

分隔符（如三引号、XML 标签或特殊字符）有助于清晰地构建输入和输出。它们将提示的不同部分分隔开来，例如将上下文与指令分开，使模型更容易理解一个元素在哪里结束，另一个元素在哪里开始。

### 请求解释

要求模型解释其推理或思考过程有助于确保获得更可靠、更周全的回复。通过包含“解释你的推理”或“逐步说明你的方法”等短语，你可以鼓励模型在分析中更加彻底和有条理，从而产生更高质量的输出，并帮助你理解模型是如何得出结论的。

大语言模型（LLMs）已经显示出在解决数学方程方面存在问题。结果已经有了很大改善，但较小的模型仍然存在问题。你可以用以下提示测试任何模型：

```text

```

尝试不同的模型，看看它们是否得出正确答案：

`x[1] = 2` 和 `x[2] = −4` 。

拥有 700 亿参数的 Llama 3 模型在此任务上失败了。与此同时，gemma-7B 找到了确切的答案，所以问题不在于模型大小。大语言模型被认为遵循丹尼尔·卡尼曼在其著名著作《思考，快与慢》中定义的系统 1 思维模式。系统 1 思维的特点是快速、自动和快速回答。在这种模式下，模型会在没有深思熟虑的情况下得出结论。相比之下，系统 2 思维是缓慢的、深思熟虑的，并且需要有意识的努力。

### 4.4 编码：自洽性思维链

确保自洽性涉及使用相同的提示多次运行思维链模型。理想情况下，会采样不同的路径。分析所有结果，并选择最常见的答案。图 4.5 展示了自洽性思维链的过程。

[https://github.com/OpenDocCN/geekdoc-dl-zh/tree/master/docs/generative-ai-with-python/img/img-f4.5.html](https://github.com/OpenDocCN/geekdoc-dl-zh/tree/master/docs/generative-ai-with-python/img/img-f4.5.html)

**图 4.5** 自洽性思维链

用户提示触发基于思维链的多个独立模型运行。在投票步骤中分析不同的结果，并选择最一致的答案作为最终回复。

这种方法是机器学习（ML）中集成学习的 LLM 等价物。集成学习训练多个“弱”算法，聚合不同的输出，并选择多数响应。

现在，让我们来实现这个能力。我们将使用这种方法来解决 24 点游戏，这是一个定义了四个数字的数学游戏。模型必须找到正确的算术运算（如加法、减法、乘法或除法），使方程的结果为 24。你自己试试看，用数字 3、4、6 和 8。

```python
#%% 思维链提示函数
def chain_of_thought_prompting(prompt: str, model_name: str = "gemma2-9b-it") -> str:
    model = ChatGroq(model_name=model_name)
    prompt = ChatPromptTemplate.from_messages(messages=[
        ("system", "You’re a helpful assistant and answer precise and concise."),
        ("user", f"{prompt} \n think step by step")
    ])
    # print(prompt)
    chain = prompt | model
    return chain.invoke({}).content
```

**代码清单 4.14** 自洽性思维链函数（来源： `04_PromptEngineering\30_self_consistency.py` ）

如代码清单 4.15 所示，我们现在可以定义一个自洽性思维链函数。该函数应多次运行思维链，存储不同的模型响应，并将所有这些响应作为上下文传递给最终的 LLM 调用，以确定最一致的答案。该函数接受一个 `prompt` 和一个 `number_of_runs` 参数，并返回最终的模型响应。

```python
# %% 自洽性思维链
def self_consistency_cot(prompt: str, number_of_runs: int = 3) -> str:
    # 多次运行思维链
    res = []
    for _ in range(number_of_runs):
        current_res = chain_of_thought_prompting(prompt)
        print(current_res)
        res.append(current_res)

    # 连接所有结果
    res_concat = ";".join(res)
    self_consistency_prompt = f"You will get multiple answers in <<>>, separated by ; <<{res_concat}>> Extract only the final equations and return the most common equation as it was provided originally. If there is no common equation, return the most likely equation."
    self_consistency_prompt_concat = ";".join(self_consistency_prompt)
    messages = [
        ("system", "You are a helpful assistant and answer precise and concise."),
        ("user", f"{self_consistency_prompt_concat}")
    ]
    prompt = ChatPromptTemplate.from_messages(messages=messages)
    model = ChatGroq(model_name="gemma2-9b-it")
    chain = prompt | model
    return chain.invoke({}).content
```

### 4.6 编码：自我反馈

在本节中，我们将探讨一种技术，它使生成式 AI 系统能够迭代地评估和优化自身的输出。自我反馈使大语言模型能够根据预期结果评估响应，从而在无需任何人工干预的情况下有效提升其自身输出的质量。

这个过程由结构化的输入和输出驱动，这些输入输出请求对生成内容进行评估或改进，能够显著优化应用程序中的响应。通过实施自我反馈循环，我们可以引导模型生成更准确、更符合上下文且更贴合用户需求的输出，从而使该方法在实际任务中非常有效。图 4.7 展示了实现自我反馈能力的流程图。

[https://github.com/OpenDocCN/geekdoc-dl-zh/tree/master/docs/generative-ai-with-python/img/img-f4.7.html](https://github.com/OpenDocCN/geekdoc-dl-zh/tree/master/docs/generative-ai-with-python/img/img-f4.7.html)

**图 4.7** 自我反馈流程图

该过程基于大语言模型的一次调用产生多个输出。模型会生成一个评分（可能以百分比形式呈现）和书面反馈，两者都基于现有内容。它还会创建一个修订后的输出内容。

由于我们从空内容开始，评分最初会很低，甚至为零。停止标准通常通过两个检查来定义，当其中任何一个检查为真时，迭代循环就会停止。这些标准可以是，例如，目标评分。每当大语言模型评估内容超过目标评分时，迭代循环就会停止。为避免无限循环，应定义迭代次数上限，这样模型在经过一定次数的循环后会被强制停止优化。

第一次迭代循环完成，目标评分较低，因此下一次迭代开始。模型评估其先前的内容，并提供详细的反馈以及评分。它还会创建修订后的内容。如果停止标准检查仍然不满足，则开始下一轮迭代。

让我们实现这个逻辑，并在一个关于美国内战的文本上进行测试。该文本将通过模型进行迭代式的自我改进。

首先，我们需要一些包。除了已经熟悉的那些，我们还需要 `pydantic` 的一些功能。这个包与 `JsonOutputParser` 结合使用，可以引导模型提供结构化输出。由于我们希望模型提供三种不同的输出（而不是仅仅一段文本），我们需要能够分离这些项目的功能。你可以强制模型返回有效的 JSON 对象，这正是我们提取三个不同对象所需要的。你总是需要这样的方法来确保一致性并减少后期处理的工作量。


### 4.7 总结

本章深入探讨了提示工程的核心要素，这是一门设计输入以引导语言模型产生特定、期望输出的学科。其核心在于，提示工程允许用户有效地塑造响应，解决生成输出的可变性问题。

我们从基础概念开始，探索了提示和提示模板，它们为一致地构建输入提供了结构。特别是提示模板，有助于简化重复或类似任务的输入格式，降低复杂性并增强可预测性。

接下来，我们讨论了提示工程流程，这是一个动态且迭代的过程。该流程涉及实验和优化提示，直到模型持续生成与预期目标一致的输出。通过试验和优化，这个循环对于平衡模型响应的精确性、清晰度和创造性至关重要。

为了进一步引导模型输出，我们介绍了几种关键技术，包括以下内容：

- 少样本提示 
 在少样本提示中，示例被包含在提示中，通过上下文来引导模型。
- 思维链（CoT） 
 通过 CoT，我们提示模型遵循逐步推理路径，增强对复杂任务的响应。我们还描述了零样本 CoT，这是 CoT 提示的一种变体，它在没有先前示例的情况下鼓励逻辑步骤，推动模型自主推断多步逻辑。
- 提示链 
 在这种技术中，创建了一系列相互关联的提示，以逐步完善响应。

### 自洽性 CoT

使用此技术，创建多个响应，并从中选择最一致的答案以提高可靠性。

### 自我反馈

自我反馈允许模型批评和修订其自身的输出，促进自我纠正和迭代改进。

每种技术在塑造输出方面都具有独特的优势，从增强逻辑连贯性到培养响应的一致性。

本章强调，掌握提示工程不仅在于设计有效的输入，还在于通过创造性的实验和迭代来理解模型行为的细微差别。

### 5.1 引言

让我们从什么是向量数据库以及为什么你可能首先需要它开始。也许你了解像 SQL 或 PostgreSQL 这样的数据库。为什么我们不能直接使用这些数据库？这些数据库在存储和检索结构化数据方面非常强大，例如具有明确定义列和行的表格。但这并不能反映你在互联网上可能遇到的各种格式，如图 5.1 所示。你会发现文本数据，还有图像、音频文件或视频。所有这些不同的格式都应该以类似的方式处理，并在同一个数据库中处理。

因此，现有数据库无法高效地处理所有这些不同类型的数据。需要一些新的东西来处理各种信息。这种新范式被称为向量数据库。

为什么这种新的数据库类型被称为向量数据库？嗯，因为所有数据类型都可以表示为向量。回想一下数学课：向量只是你画在坐标系中的一条带箭头的线。那时，你必须画这些线，它们可以用两个数字来表示。

图 5.2 中显示了一个简单的例子。这个虚构的图表显示了生物，以及它们在二维图表中的位置，该图表代表了腿的数量和体型。通过以这种方式表示信息，我们了解了世界和词语的语义含义，例如，猫和狗在这两个属性上非常相似。

作为人类，我们可以想象二维空间中的一个点，就像本示例中展示的那样，或者三维空间。只需想象我们在该图中添加第三个维度，比如智能。但我们无法想象 1536 维或 3072 维的空间。计算机可以，这很有帮助，因为词语、图像、声音或任何其他类型信息的语义含义都可以在高维空间中表示。在此背景下，关键方面是相似的概念比差异很大的概念在空间中位置更接近。在我们的示例中，请注意，根据我们选择的属性，猫和狗，或者蛇和蜗牛是可比较的。随着每个额外维度的增加，计算机算法能更好地理解词语的含义。

我们使用英语或德语等语言来交流和阐明概念。计算机不直接使用我们的语言，而是使用其数值等价物，即所谓的嵌入向量。

在我们的示例中，对于计算机算法，狗由 `[4, 1]` 定义，猫由 `[4, 0.5]` 定义，人类由 `[4, 2]` 定义。一个映射示例如表 5.1 所示。

### 5.2 数据摄入过程

让我们从数据如何摄入向量数据库的高层概述开始。每当您想向向量数据库添加数据时，都会遇到这些步骤：

- 数据加载
- 数据分块
- 嵌入
- 存储

您总是从数据源开始。我们已经提到了许多数据类型选项——通常，任何基于文本的源都可以使用，如 Markdown 文件、Word 文档或原始文本文件。但您也可以使用更特定的数据类型，例如您想从中提取转录文本的 YouTube 视频，或维基百科文章。选项几乎是无穷无尽的。幸运的是，贡献特定数据处理程序的用户社区也很庞大，因此只需一行代码就可以开箱即用地使用数百种不同的源。因此，您始终拥有一致的数据加载方法。这种一致性很重要，因为存在许多不同的数据源，而您希望以一致的方式导入数据。结果，您将获得导入为长字符串的数据。

这个长文本字符串必须被分割成更小的部分，因为最终，我们想在干草堆中找到针。基于一些用户输入，我们希望访问与用户输入最相关的特定信息片段，而不是完整的信息干草堆。因此，您必须将文本分割成更小、更易于管理的部分，这个过程称为分块。此时，我们得到了一个文本文档列表。

如前所述，这些文本文档对人类来说是可理解的，但对计算机则不然。您必须将此信息转换为计算机可理解的格式，这个过程称为嵌入。对于每个文本，您将有一个对应的向量来表示该文本的语义含义。

我们已经到达数据摄入的最后阶段，现在可以将这些向量（文本/数字对）存储到我们的向量数据库中。完整的数据摄入管道如图 5.3 所示。

### 5.4 分割文档

通常，你需要将数据分割成更小的块。为什么需要这一步？原因包括以下几点：

- 通过分割，你可以获得更细粒度的结果，因为较小的文档块更可能包含集中且相关的信息。
- 你可以绕过嵌入模型的限制。别担心，我们将在第 5.5 节更深入地介绍这一点。回想一下，所有嵌入模型都有一个有限的令牌上下文窗口可供使用。我们将在下一个信息框中进一步讨论令牌。
- 分割在数据库大小和查询方面可以更高效，因为你处理和存储的是更小的块。
