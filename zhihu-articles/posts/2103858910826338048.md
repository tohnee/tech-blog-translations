## 一、先明确约束，再谈技术

高校做私有化大模型，需求往往一句话就能说完："要能用，还要安全。"但这句话拆开是四个互相牵制的约束：

1. 数据不出校。培养方案、成绩学籍、科研数据、评审材料、校内公文，都不允许离开校园网络边界；<br>
2. 要真的用得起来。部署完如果只有两三个人会调，项目就失败了；<br>
3. 要能出活。不能只做问答玩具，要能产出通知、纪要、汇报材料、进度表这类真实交付物；<br>
4. 要能长期维护。学校没有专职的模型运维团队，方案必须让信息中心接得住。<br>

这四条决定了方案形态：本地部署解决边界，定制客户端解决使用率，两者缺一不可。

## 二、部署：我们实际搭了什么

很多单位对"本地部署"的想象是买一台服务器把模型装上去。真正的工程量在下面四层，我们逐层展开。

### 1. 算力：从并发倒推，而不是从参数表买卡

大模型的权重显存是可估算的——7B 模型 INT8 约 7GB、INT4 约 4GB，32B 模型 FP16 约 64GB、INT4 约 20GB。但决定配置的从来不是权重，而是 KV Cache：10 个人同时对话和 100 个人同时对话，显存需求可能差好几倍。

所以我们的第一步不是报价，是问三个问题：同时在线多少人、单次输入多长、能接受多长的等待。这三个数出来，卡型和数量才有依据。

### 2. 模型：按任务选，不按排行榜选

中文长文档理解、结构化抽取、多轮问答、公文改写，各自的最优解不一样。我们先用学校真实材料做横向测试，选定主模型；高频且边界清晰的任务（比如固定格式的表格抽取），再考虑蒸馏一个小模型专攻，又快又省。

70B 不一定比 32B 更适合学校场景。垂直任务上，一个调好的小模型经常更划算——这一点我们在方案里写得很直白，因为选大了是客户长期买单。

### 3. 知识库：这一层最容易糊弄，也最容易翻车

把文档传上去不等于知识库可用。文档切分粒度、更新机制、权限隔离、检索与重排模型的搭配，直接决定"答得准不准"。

我们在这个项目里花的调试时间，知识库占了一半以上。原因是校内材料结构差异极大：培养方案是长表格，通知是短文本，制度文件层级深。一套切分策略通吃，结果就是稳定地给出错误答案，而且看上去很自信。

### 4. 服务与运维：让信息中心接得住

交付不是把模型跑起来就结束。我们交给校方的是：部署文档、监控指标（显存、QPS、首字延迟、检索命中率）、日志审计、版本回滚流程，以及一次面向管理员的实操培训。

目标很具体——我们撤场之后，学校自己能重启、能扩容、能换模型。

## 三、客户端：入口决定这套东西有没有人用

这是项目里最容易被低估的一半。

如果只做本地部署，师生仍然要打开浏览器、记地址、登录、在内网外切换，然后把校内材料复制到公网页面里——这条路径本身就与"数据不出内网"的目标相冲突。技术上闭环了，行为上没有闭环。

所以我们给学校做了一套专属桌面客户端，重点不在"换个皮肤"，而在四件事：

| 设计决策 | 解决的问题 |
| --- | --- |
| 校徽、校名、配色按学校视觉规范定制 | 师生一眼认得出这是学校自己的工具，而不是第三方页面 |
| 首页直接给出四类场景入口（教务与学分、科研与论文、校园服务、公文写作） | 用户不必先想"该怎么问"，打开就能用 |
| 输出格式可选：PPT 大纲 / Excel 表格 / 图片描述 / 正式文档 | 从"聊天"变成"出活"，产出可以直接进工作流 |
| 支持图片上传与语音输入 | 纸质材料、会议记录可以拍照或口述进来 |
| 指向校内服务地址，不依赖公网 | 断网、隔离环境下同样可用 |

其中"输出格式可选"是我们坚持加的一项。一个只会输出大段文字的工具，用户拿到之后还要自己转成 PPT、自己排版成表格——那一步转化损耗，往往就是"用一次就不用了"的原因。

## 四、交付节奏：四步，每步都有验收物

我们把项目拆成四段，避免"演示很惊艳、上线不能用"：

1. 需求调研：定场景优先级、数据边界、并发规模、合规要求；<br>
2. 小规模验证（POC）：用真实校内数据跑 1–2 个核心场景，出效果报告——这一阶段允许失败，失败比上线后失败便宜得多；<br>
3. 试点院系：选一个院系或职能部门先行使用，跑通"提问—产出—归档"的完整链路；<br>
4. 推广与运维：管理员培训、使用手册、监控告警、迭代支持。<br>

每一段的交付物都是可验收的文档或指标，而不是"感觉差不多了"。

## 五、几句实话

不是所有场景都值得本地部署。调用量低、数据敏感度不高的场景，公有云 API 依然更便宜也更省心。本地部署的经济性来自"高频 + 敏感 + 长期"三个条件叠加——三条不齐，我们会直接建议客户先别做。

客户端不能替代治理。装了客户端，不等于数据就安全了；权限、审计、离职回收这些事，仍然要靠制度和技术一起管。

项目真正的难点不在模型。模型是现成的，算力是能买的，难的是把学校真实的材料、真实的流程、真实的人，接进这套系统里。
