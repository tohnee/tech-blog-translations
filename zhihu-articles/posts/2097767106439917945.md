### 0. 定义与大纲

**RAG（Retrieval-Augmented Generation，检索增强生成）** ：把 **信息检索** 与 **LLM 文本生成** 结合——先从文档语料中检索相关段落，再用它们生成答案（Gao et al., 2023 综述，arXiv:2312.10997）。

大纲：① RAG 动机；② RAG 流水线（分块、嵌入/索引、检索与重排、查询扩展/分解、生成）；③ RAG 工作流与 RAG 智能体；④ RAG 评测。

---

### 1. RAG 的动机

LLM 的四大缺口，RAG 各补一块：

**① 幻觉** ：LLM 可能生成看似有理实则错误的输出；RAG **把输出与证据连接起来** （可引用、可核查）。

**② 长尾实体** ：LLM 尤其容易对 **预训练数据覆盖很少的长尾实体** 产生幻觉；RAG 能从互联网/内网检索这些稀有实体的知识（Mallen et al., ACL 2023）。

![](https://pic2.zhimg.com/v2-86392375502e484342d359859cd1188d_r.jpg)

*图 1　两类知识的权衡（Mallen et al., 2023）：参数化知识存权重、非参数化知识存语料——RAG 的实质是给模型接上”非参数化记忆”。*

**③ 知识截止（Knowledge Cutoff）** ：模型训练于特定时间点，不知道此后的事件——RAG 的语料可以持续更新。

**④ RAG 自身的短板** ：另一方面，RAG 系统也可能被 **关于错误实体的无关证据误导** （Yoran et al., ICLR 2024 Workshop）——所以”检索质量”与”过滤”是 RAG 工程的核心命题（见 2.3 节）。

**产业采用** ：RAG 让公共网页上的知识工作更高效，也让公司内部信息的发现与利用更高效——2025 年以来企业知识库问答的标配架构。

### 2.1 分块（Chunking）

把长文档切成块（chunk）用于嵌入。策略：

- **定长块** ：固定 token/词/字符数 + 重叠（overlap）；
- **句子块** ：按句子分组 + 少量重叠；
- **段落块** ：以段落边界为块边界；
- **语义块** ：用 LLM 把文档切成”连贯”的内容块。

> **【补充知识】** 分块是 RAG 里最被低估的环节：块太大 → 嵌入信号被稀释、检索不精准；块太小 → 语义不完整、上下文碎片化。经验值：英文 200–500 token、重叠 10–20%。 **父子块检索（parent-document retriever）** 是常见改良：嵌入小块用于检索、返回时带上它所属的大块（或原文段落）供 LLM 阅读——兼顾检索精度与上下文完整。

### 2.2 嵌入与索引（Embedding / Indexing）

**任务** ：找到与 query 最相关的块 → 输出 top-k 排名列表。两条路线： **稠密检索（dense）** 与 **稀疏检索（sparse）** ，可并行使用。

**稠密检索** ：

![](https://pic1.zhimg.com/v2-a72abd939136f2f8558f592d0c1ef9d0_r.jpg)

*图 4　稠密检索两步：① 块与 query 嵌入同一空间；② 在嵌入空间做最近邻搜索 $z_1,\ldots,z_k=\operatorname{argTop-k}(\mathbf{x}\cdot\mathbf{z})$。*

**嵌入向量的生成** （两种方式）：

![](https://pic3.zhimg.com/v2-d0dc552ab14a7a8ac75973bceb72eb62_r.jpg)

*图 5　DPR 双塔（[CLS] 池化）vs SBERT（mean pooling）——现代文本嵌入模型基本是 SBERT 路线的放大版。*

**嵌入模型选型** （本讲写作时点）：

- 向量维度 **384（SBERT）到 3072（OpenAI large）** ；
- **text-embedding-3-small** （RAG 常用，1536 维（ **译注** ：原片写 1532，应为 1536），约 6KB/向量，每百万 token 0.02 美元）；
- **text-embedding-3-large** （高端，3072 维，约 12KB/向量，每百万 token 0.13 美元）；
- 开源权重模型看 **MTEB 排行榜** （ [http://huggingface.co/spaces/mteb/leaderboard](http://huggingface.co/spaces/mteb/leaderboard) ）；LangChain 有 20+ 集成。

**向量库（Vector Stores）** ：存嵌入、提供 **近似最近邻（ANN）** 搜索（相似度：余弦、点积）。索引技术：乘积量化（PQ）、局部敏感哈希（LSH）、 **HNSW** （分层可导航小世界图）。常见向量库： **FAISS** （Meta 开源库）、 **Weaviate** （开源）、 **Pinecone** （商业云服务）。LangChain 有 15+ 集成。

**稀疏检索** ：① 为块中的词建 **倒排索引** ；② 用倒排索引找与 query 最相似的块。相似度计算可用 **词袋 + Jaccard 相似度** ：

$$
 sim_{jaccard}(x,y)=\frac{|tok(x)\cap tok(y)|}{|tok(x)\cup tok(y)|} 
$$

![](https://picx.zhimg.com/v2-48ab254be724f594a016825ecd1e06f3_r.jpg)

*图 6　词袋表示与 Jaccard 相似度示意。*

实际稀疏检索器用 **加权词项分数** ：

$$
 \mathrm{TF}(t,d)=\frac{\mathrm{freq}(t,d)}{\sum_{t'}\mathrm{freq}(t',d)},\qquad \mathrm{IDF}(t)=\log\left(\frac{|D|}{\sum_{d'\in D}\delta(\mathrm{freq}(t,d')>0)}\right) 
$$

$$
 \mathrm{TF\text{-}IDF}(t,d)=\mathrm{TF}(t,d)\times\mathrm{IDF}(t) 
$$

$$
 \mathrm{BM25}(t,d)=\mathrm{IDF}(t)\cdot\frac{\mathrm{freq}(t,d)\cdot(k_1+1)}{\mathrm{freq}(t,d)+k_1\cdot\left(1-b+b\cdot\frac{|d|}{\mathrm{avgDL}}\right)} 
$$

（Robertson et al., 2009；$k_1\approx1.2$、$b\approx0.75$ 为常用超参。）

**稠密 vs 稀疏对比** （两者可并行）：

| 准则 | 稠密检索 | 稀疏检索 |
| --- | --- | --- |
| 匹配方式 | 语义（Semantic） | 词法（Lexical） |
| 域外表现 | 可能退化 | 鲁棒 |
| 稀有实体 | 强 | 弱 |
| 同义改写 | 需要（隐含处理） | 无（字面匹配） |
| 训练 | 需要 | 不需要 |

> **【补充知识】** 生产系统普遍用 **Hybrid（混合检索）** ：BM25 保字面精确匹配（型号、编号、专有名词）与稠密检索保语义召回，两路分数融合（常用 RRF, Reciprocal Rank Fusion）。2019 年以来的趋势： **学习型稀疏检索（SPLADE）** 把两者合流——用 MLM 预测每个词的权重做”扩展词表 + 词项加权”，既有稀疏性又可语义扩展。

**LLM 查询扩展** （提高召回）：让 LLM 生成同一信息需求的多种替代表述：

![](https://picx.zhimg.com/v2-7d2cf5855fd569676a95e515183e4365_r.jpg)

*图 7　Query Expansion 提示：同义改写 + 术语变体，提升召回。*

**LLM 查询分解** （复杂问题拆成多个聚焦检索步骤）：

![](https://pic1.zhimg.com/v2-6f57adea3a2a7a77697ccf48a9f64a16_r.jpg)

*图 8　Query Decomposition：一个多跳问题 → 多个单跳查询，逐个检索再综合。*

**假设文档生成（Hypothetical Document Generation，HyDE 思路）** ：缓解 query 与文档之间的语义/结构鸿沟——① 让 LLM 生成一篇”可能是答案”的文档；② **用这篇假设文档去检索** （而不是用原始 query）——问题与答案文档在嵌入空间中更近。

### 2.4 重排与过滤（Reranking and Filtering）

**为什么要重排** ：初检排名常不理想；无关块会 **分散 LLM 注意力** ：

![](https://pica.zhimg.com/v2-7cbf894193dc8bb3721447e3419c025c_r.jpg)

*图 9　检索的阴暗面：对热门实体，模型参数化知识本已足够，无关检索反而干扰（”Sam Altman” 被误配到 “Samuel Adams”）。*

**交叉编码器重排（Cross-Encoder）** ：query 与候选段落 **联合编码** （输入格式 `[CLS] query [SEP] passage [SEP]` ），BERT 类模型微调预测相关性分数。

- 优点：捕捉细粒度语义交互、能处理同义与上下文相关性；
- 局限：计算昂贵，通常只用于重排初检的 **top 20–200** 个块。

**其他排序准则** ：

- **可信度** ：按来源排（白名单或 PageRank）；按内容排（与 ground truth 的重叠——知识驱动的信任，Dong et al., 2015）；
- **时效性** ：按时间戳过滤过时内容；
- **重复内容** ：用 LLM 去重、或把相似块摘要成一块。

**多阶段排序（级联）** ：通常由一系列检索模型组成——

1. **候选生成阶段** （快而简单，求 recall）：稠密和/或稀疏检索取 top ~200 块；
2. **排序阶段** （准而慢，求 precision）：按可信/时效过滤 + cross-encoder 重排；
3. **结果** ：top-k 块（通常 10–20）送入生成。

### 2.5 生成（Generation）

检索到的块加入提示，LLM 基于额外上下文生成答案。

### 4. RAG 评测

两大类： **有参考（reference-based）** ——与 ground truth 比； **无参考（reference-free）** ——全靠 LLM-as-a-Judge。

### 4.1 有参考指标

**检索侧** ：需要”哪些块相关”的 ground truth； **nDCG@10** 被广泛使用（BEIR 基准）。

> **【补充知识】** nDCG（归一化折损累积增益）把”相关文档排在多前面”折算成分数：DCG 按排名位置对相关性分级打折扣（$\frac{2^{rel_i}-1}{\log_2(i+1)}$），再除以理想排序的 IDCG 归一化到 0–1。@10 表示只看前 10 个结果。检索侧另常用 Recall@k、MRR；企业场景还看”答案支持文档是否被检索到”（Answer Recall）。

**生成侧** ：需要正确答案作 ground truth；评分用句法指标（BLEU、ROUGE）或语义指标（BERTScore、LLM-as-a-Judge）。

### 4.2 无参考指标：RAG 三角（RAG Triad）

用 LLM-as-a-Judge、无需 ground truth； **结果可能有噪声** ；但因比有参考评测更便宜灵活而被广泛使用。三个维度：

**① 上下文相关性（Context Relevance）** ：检索到的块对 query 是否相关（无关块可能导致幻觉）。Judge 提示：给定 Question 与 Context，打 0–1 分（0=完全无关，1=完全相关且有用）， **先解释后打分** 。

**② 有据性/忠实度（Groundedness / Faithfulness）** ：生成的回答是否被检索上下文支持（LLM 可能动用参数化知识作答）；有时逐句评估。Judge 提示：0=含上下文不支持的声明，1=每个声明都被支持。

**③ 答案相关性（Answer Relevance）** ：回答是否真正回应了 query（LLM 可能被上下文带偏）。Judge 提示：0=答非所问，1=完整直接回答；先推理后打分。

> **【补充知识】** RAG Triad 出自 TruEra 的实践，本质是把 RAG 的故障模式拆开定位：Context Relevance 低 → **检索** 有问题；Groundedness 低 → **生成** 不忠实（幻觉）；Answer Relevance 低 → **生成** 跑题。工程上建议三者一起监控，并抽样人工校准 judge 的打分（见第 3 讲的人机一致性）。

### 4.3 RAG 基准

**检索基准** ：

- **BEIR** （Thakur et al., 2021）：跨多数据集评测检索模型；有参考（检索排名 vs ground truth 相关性）； **不评测生成** ；
- **MTEB** ：覆盖更广 NLP 任务的嵌入基准，开源权重模型的权威榜单。

**端到端 RAG 基准** （经典开放域 QA）：

|  | HotpotQA (2018) | Natural Questions (2019) |
| --- | --- | --- |
| 问题来源 | 众包问题 | 真实 Google 搜索查询 |
| 知识源 | Wikipedia | Wikipedia |
| 问题类型 | 多跳推理问题 | 单跳事实问题 |
| 检索要求 | 检索多个支撑文档 | 检索一个相关段落/文章 |
| 核心挑战 | 跨文档推理 | 大规模开放域检索 |
| 典型指标 | Exact Match、F1 | Exact Match、F1 |
| RAG 评测角色 | 多跳检索+推理+生成 | 检索+答案生成 |

**QA 基准越来越难** ：OpenAI Web RAG 基准包含 **难解但易验证** 的问题（如 BrowseComp 类：需要多轮搜索才能答、但答案唯一可自动判定）。

**事实核查基准** ： **AVERITEC** （2024，真实世界声明 + 开放网页证据，标签：支持/反驳/冲突/证据不足，多跳跨源推理）vs **FEVER** （2018，从 Wikipedia 句子生成的合成声明，标签：支持/反驳/信息不足）。

**Deep Research 智能体基准** ：用 LLM-as-a-Judge + **量规（rubric）式 ground truth** 评长文质量。量规规定评价维度与打分指南，让人或 LLM judge 一致地给系统输出打分：

*图 14　量规式基准：ResearchQA 与 HealthBench——把”什么是好报告”写成可逐条打分的条目。*
