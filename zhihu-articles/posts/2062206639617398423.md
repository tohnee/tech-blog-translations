今天看了一篇挺不错的文章 *[《Controlling Reasoning Effort in LLMs》](https://magazine.sebastianraschka.com/p/controlling-reasoning-effort-in-llms)* ，主要聊的是：

> *为什么同一个模型 GPT 可以提供 Light、Low、Medium、High、Max 这些不同推理档位？这些档位究竟是怎样训练出来、又怎样在推理时生效的？*

简单来说， **Reasoning Effort 简单说就是一种经过后训练学会的、可以条件控制的计算策略** ，也就是说，模型必须提前在 SFT（微调）、RLVR（可验证奖励） 或蒸馏阶段就已经学会：

- 低思考的时候怎样快速作答
- 高思考的时怎样展开搜索、验证、回溯和纠错
- 在不同 token 成本约束下，怎样分配有限的推理资源

> 然后在推理阶段，系统提示词或者 Chat Template 再告诉模型：“ *这次用低档* ”、“ *这次尽量想深一点* ”。

这里在原作者看来有一个明确的结论： **Low、Medium、High  就是同一个模型的不同预算策略，是因为模型已经在监督微调和强化学习中见过不同的预算，然后学会了在不同预算下怎么采用不同的解题行为** 。

![](https://pic4.zhimg.com/v2-44d492018d536cd034f9548ffed8efd1_r.jpg)

也就是真正的推理强度控制， **是模型在后训练阶段学会的一套计算资源分配策略** ：

> *当系统告诉模型当前是 Low、Medium、High 或 Max 时，它不仅要生成不同长度的思维链，还要改变搜索深度、验证次数、回溯意愿、工具调用方式和停止时机* 。

**那为什么 Kimi K3 首发时只先发了 Max，而 Low 和 High 后面才加入呢** ？

![](https://pic4.zhimg.com/v2-bff013d199b6d328c26b3f4a7da260a9_r.jpg)

我们结合 Kimi 以前公布的训练方法和目前 K3 官方的信息，可以有到一个猜测：

> ***因为 Max 能把模型的能力充分释放出来，而 Low 是要求模型在受限计算预算下还能保持智商输出完整结果，所以 low 模型更容易暴露稳定性问题，需要先验证  K3 的能力和进一步调教*** 。

所以推理强度是同一个模型下的不同策略调校方向，而且还需要结合当前工具设定的 Token 预算，比如最多 8000 token 预算的场景：

- 高档位推理下，模型可以计划执行多轮验证，直到接近 8000 token 上限才停止
- 低档位下模型需要主动选择一条短路径，争取在 2000 token 内就要结束任务

> *当然这里的 8000 Token 是 Token 预算，不是推理预算，只是通过这个例子能简单理解* 。

举个例子，我们用一道代码修复任务理解这个过程，假设模型要修复一个数组越界问题，那么在低 effort 下，它可能倾向于：

```text
看到异常栈
→ 定位下标计算
→ 添加边界检查
→ 给出补丁
```

在高 effort 下，它可能选择：

```text
查看异常栈
→ 分析数组生命周期
→ 检查调用链
→ 构造边界输入
→ 发现不仅是下标问题，还存在并发修改
→ 修改实现
→ 添加测试
→ 重新验证
```

所以，所谓的推理能力是来自模型在训练中学会的：

- 什么时候需要分解问题
- 什么时候值得尝试第二种方案
- 什么时候应该检查中间结果
- 什么时候继续推理的收益已经不大
- 什么时候应该调用工具而不是继续猜测

然后在这个基础上， **推理强度控制，本质上控制的是这套策略的“积极程度”，而恰好，目前官方说 K3 默认积极程度太高** 。

比如让一个代码 Agent 排查 “ *支付接口偶尔重复扣款* ” 的问题：

- 在 Low 模式下，它可能先检查最常见的两个问题： *幂等键是否缺失，数据库事务是否正确* ，找到明显问题后，运行几个针对性测试，然后完成任务
- 到了 High 模式，它可能继续向外排查： *消息队列是否重复投递、客户端是否自动重试、事务隔离级别是否产生竞态、多个服务实例是否同时处理同一笔订单*
- Max 模式就可能进一步 *构造并发压力测试，模拟服务崩溃和消息重放，比较三种修复方案，验证旧数据兼容性* ， *再检查修复是否引入新的死锁*

**当然，最后三个档位给出的修复补丁也可能很接近，也就是输出结果差别可能不会很大** ，但是区别在于模型在得出答案前做了什么：

- 保留了多少种可能性
- 检查了多少条路径
- 愿不愿意推翻第一个方案
- 进行了多少次测试和工具调用
- 在多早的时候认为“已经足够可靠”

这就是推理档位在做的事情，所以不是说你用  GPT Sol，没事就开  Ultra 就能受益最大，这种做法无疑是过度思考，直接看这个预算图，有意思的地方在于：

> **不同模型和推理强度，成本和性能曲线可能重叠** ，也就是小模型开高档，有时可能接近大模型开低档的成绩 。

![](https://pic2.zhimg.com/v2-a74f9249248605f7688217e4f80ec0ef_r.jpg)

所以不是推理强度越强就越好，你需要根据实际场景来选择有效推理档位和模型， **不然你什么都 Sol Ultra ，不仅浪费钱还浪费时间** 。

> *在 Sol Ultra 下，它的推理轨迹会允许更多路径和边界尝试，系统允许它更高的预算，如果任务简单，那么它就可能因为“想太多”，反而污染了修复的边界* 。

然后，我们要理解推理档位，就需要知道模型为什么会产生长推理？

比如在数学和代码任务中，训练系统很容易判断最终结果是否正确，数学题也可以用规则或计算器验证，而代码可以运行单元测试，所以模型可以尝试很多种回答，答对获得奖励，答错没有奖励。

![](https://pic2.zhimg.com/v2-9cafad98108c58caf559f45a1cfeb8af_r.jpg)

例如 DeepSeek-R1 的 RLVR 训练就没有逐句监督模型的思考过程，训练系统主要检查最后的答案和格式，模型在反复试错中逐渐发现：

> *先列步骤、检查结果、发现错误后回退，如果发现能够提高最后答对的概率，这些行为就会被保留下来* 。

**但这只能教会模型「怎样通过更多推理提高正确率」，但是没办法学会「什么问题值得投入多少推理」。**

这就是第一代推理模型容易出现的问题，而要得到 Low、Medium、High， **训练时就必须再加入“预算意识”** ，可以把训练过程想象成一个积分游戏：

- 模型答对一道题可以获得 100 分，但生成推理 token 也需要付出成本
- 在 Low 模式下，每多写一步都会比较贵，模型如果绕了两千个 token 才答对，虽然获得正确性奖励，却可能因为过程太长损失很多分，所以它会逐渐学会寻找更短的可靠路径
- 在 High 或 Max 模式下，推理 token 的成本更低，只要额外检查能够提高成功率，模型就愿意继续搜索、验证和回溯

这也是最近美国的开源大模型 Inkling 的公开训练方法：

> 系统把目标 effort 写进系统消息，并根据 effort 改变生成 token 的成本，较低 effort 对长度惩罚更重，较高 effort 允许模型使用更多 token。

![](https://pic3.zhimg.com/v2-8e4b351c854c95a6d8caf07c50ccee3a_r.jpg)

另外还可以使用 SFT （监督微调），训练数据里，同一个问题分别配上不同答案：

- `Reasoning: low` ， 就给使用最短的可靠路径回答
- `Reasoning: high` ，就给展开分析、检查边界情况并验证结果

![](https://pica.zhimg.com/v2-8b6b6536e626092b4cbc94ae9355c230_r.jpg)

模型看过大量这类成对数据后，就会把 Low 和 High 理解成两种不同的工作方式，所以简单总结起来就是：

- 一类是在强化学习中改变长度奖励
- 另一类通过监督数据直接教授不同档位

**所以推理强度不是说模式天生就能力支持的，它本身就是后训练额外的一部分** 。

而在 Kimi 2.5 的就提到过一种 Token Efficient RL 的训练方法，在当时 Kimi 团队发现，如果长期使用固定的小 token 预算训练，模型会产生“长度过拟合”：

> *它确实变短了，但遇到复杂问题时，就算给它更多 token，也不会再深入思考* 。

所以 Kimi 想了个拆分方法叫 Toggle ：

- 在有预算阶段，让模型只在预算内完成问题
- 在无约束阶段，恢复完整 token 上限，让模型继续学习长推理

![](https://pic4.zhimg.com/v2-3404a80b382e85103abf9a2edcadf53f_r.jpg)

**然后预算约束只会在模型已经能较稳定答对问题后启用，避免模型还不会做题就先被迫压缩步骤** ，然后官方发现，训练后的模型在性能不变的情况下，可以减少25% 到 30% 的输出 token。

![](https://picx.zhimg.com/v2-8d85a001e7cd3c5c1562b224aadeee71_r.jpg)

**虽然这个  Toggle 对于 Kimi 不是完整意义上的档位调整，但是可以看出来，这也类似推理预算的变化** ，比如 Kimi 这个，它让模型学会在减少 token 的同时保留长推理能力，只是本身并没有直接提供 Low、High、Max 这样的推理时档位接口。

所以也可以理解，为什么 Kimi 先突出了 Max ，因为从训练角度看，可以假设 Max 更接近模型原本的长推理策略？

> *给它足够上下文，降低长度惩罚，不要过早打断，让它把已经学到的搜索、验证和纠错能力充分发挥出来* 。

但是 Low 要解决的问题要精细得多：

- 它不能只是少生成一点 token，因为简单截断可能让模型来不及完成推理
- 也不能长期只奖励短答案，否则模型可能逐渐失去长程推理能力

比如 Kimi K2.5 的 Toggle 方法就是为了解决这个矛盾，训练 low 推理的目标一直都不是「把一篇一万字的思考裁成三千字」，对于 Kimi K3 来说， 中档位和低档位的定位应该是：

> **让模型在一开始就选择一条更经济的解题路线，同时保留必要时展开成长推理的能力** 。

比如英伟达的  Nemotron 模型使用了另一种方法： **把完整推理随机截断，然后要求模型仍然学会收尾并输出答案** 。

![](https://pic1.zhimg.com/v2-37854da491e99259d16cd2fa0037a226_r.jpg)

也就是教模型就算预算突然耗尽，也不要停在半条思维链中，而 Qwen3 则是把 Thinking 和 No-thinking 两类样本混在一起训练，让同一组权重同时学会直接回答和展开推理。

> *所以，如果要想 OpenAI 一样，发布时就具备完整推理档位能力，就需要模型训练时就已经具备多档位策略的训练、评测和产品校准* 。

最后， Kimi 官方也在 Limit 里说了， **K3 不太会及时收手** ，由于特别强化了长周期、高难度任务，它会表现得过于主动，也就是会有一种非常典型的 Max 策略倾向， **但是这对于 low 档位来说会是预算隐患** ：

![](https://pic4.zhimg.com/v2-b91499cd33e44f0b34a6b5cd687d3ddf_r.jpg)

所以，简单来说， **推理档位不是模型天生就具备的，都需要在后训练里进行调教的，不同推理力度更多代表的不是模型智力，它只是代表了模型被调教过后的预算管理** 。

比如在 GPT 5.6 里，Ultra 就代表着模型近乎放飞自我的狂欢，一个问题它可以开发和调试几个小时不带停的， **不是说开了 Ultra 的智力就高了，这反而有种”初号机断电解开了封印“的感觉** ，因为 Ultra 默认就会协调四个并行子 Agent 进行工作，这种情况下和 Kimi K3 的 Agent Swarm  集群也类似，也就是 Ultra 和 Swarm Max 不只是推理强度，还默认增加了多 Agent 的横向计算扩展。

![](https://pic2.zhimg.com/v2-f05eaeac9beb09cfac2cc92886823a49_r.jpg)

所以，不同模型支持推理强度的方式可能不同，甚至类似 Inkling 直接通过数值控制， **但是核心需要知道的就是，推理强度不代表模型的本身智商，它更多是代表了模型这一次会话的预算和策略，通过不同策略影响最终成功率** 。

> 也就是说，不要动不动就 Sol Ultra ，Sol Max ，实际上大部分时候 Medium 其实就够了。
