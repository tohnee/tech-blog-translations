## 1. 这个方向在研究什么

核心不是模型算法，而是 `serving runtime` 怎么联合优化：

- Request scheduling
- Prefill / decode orchestration
- KV / prefix locality
- Disaggregated serving
- Memory tier / KV transfer
- MoE execution scheduling
- Operator scheduling & kernel fusion
- Agent / workflow-level scheduling

近两年的主线很清楚：`scheduler` 正在从”排队器”变成”状态感知的资源协调器”，粒度从单次请求扩展到整个 Agent 工作流、算子执行图。

## 2. 主线划分

### A. 请求调度

关注 batching / priority & fairness / SLO & tail latency / admission & rejection / response length prediction。

- [Locality-aware Fair Scheduling](https://arxiv.org/abs/2501.14312) — DLPM/D²LPM，首个 locality-aware 且保证公平性的调度器，吞吐 2.87× vs VTC
- [SLO-Aware Scheduling for LLM Inferences](https://arxiv.org/abs/2504.14966) — 模拟退火调度器，多 SLO 场景，SLO 达标率 5×
- [PROSERVE](https://arxiv.org/abs/2512.12928) — SlideBatching（引擎层）+ GoRouting（集群层）两层多优先级调度
- [ELIS](https://arxiv.org/abs/2505.09142) — BGE 预测 response length + ISRTF 调度，JCT 降 19.6%
- [Optimal Scheduling Algorithms (RAD/SLAI)](https://arxiv.org/abs/2508.01002) — 理论框架：RAD 吞吐最优 + SLAI SLO 感知，POMACS
- [Throughput-Optimal Scheduling](https://arxiv.org/abs/2504.07347) — 排队论证明 work-conserving 最大稳定，vLLM vanilla 不是
- [SageSched](https://arxiv.org/abs/2603.07917) — 不确定性感知调度，效率提升 28.7%
- [Predictive Scheduling for Inference-Time Reasoning](https://arxiv.org/abs/2602.01237) — MLP/LoRA 预测最优推理 token 数，贪心分配
- [Past-Future Scheduler](https://arxiv.org/abs/2507.10150) — 历史分布预测未来内存需求，goodput 提升 2–3×

### B. Cache-aware / Prefix-aware 调度

关注 prefix sharing / cache locality / distributed prompt placement / 复用-公平性 tradeoff。

- [Preble](https://arxiv.org/abs/2407.00023) — **ICLR 2025**。首个分布式 prefix 共享调度平台，延迟降 1.5–14.5×
- [MemServe](https://arxiv.org/abs/2406.17565) — context caching + disaggregated serving，elastic memory pool
- [Mooncake](https://arxiv.org/abs/2407.00079) — **FAST 25**。Kimi 的 KVCache-centric 架构，显式 early rejection
- [LLM Query Scheduling with Prefix Reuse](https://arxiv.org/abs/2502.04677) — 证明前缀复用调度 NP-hard，k-LPM 算法

### C. Prefill / Decode 解耦与分层调度

关注 P/D disaggregation / router-engine 协同 / KV transfer cost / 动态 P/D 比例。

- [DistServe](https://arxiv.org/abs/2401.09670) — **OSDI 2024**。首个 P/D 分离到独立 GPU 的系统，服务 4.48× 更多请求
- [NexusSched](https://arxiv.org/abs/2509.23384) — LENS（引擎层）+ PRISM（集群层）跨层预测性编排
- [FlowKV](https://arxiv.org/abs/2504.03775) — KV 传输延迟降 96% + load-aware 调度
- [P/D-Serve](https://arxiv.org/abs/2408.08147) — 数万 NPU 规模 P/D orchestration，动态比例 + D2D KV 传输
- [Arrow](https://arxiv.org/abs/2505.11916) — 无状态实例自适应调度，服务速率最高 7.78×
- [Kairos](https://arxiv.org/abs/2605.02329) — prefill 紧急度优先级 + decode slack-guided batching
- [PLA-Serve](https://arxiv.org/abs/2601.11589) — 按 prompt 长度双队列 + CUDA Graph 聚簇
- [FairBatching](https://arxiv.org/abs/2510.14392) — P/D 公平资源分配，TTFT 尾延迟降 2.29×
- [DOPD/DOPO](https://arxiv.org/abs/2511.20982) — 动态 P/D 比例最大化 Goodput

### D. 多模型与平台型调度

关注 multi-model colocation / GPU pooling / bursty marketplace / 多 Adapter 推理。

- [MuxServe](https://arxiv.org/abs/2404.02015) — **ICML 2024**。空间 colocate + 时间 P/D 分离，吞吐提升 1.8×
- [Aegaeon](https://dl.acm.org/doi/10.1145/3731569.3764815) — **SOSP 2025**。Token 级自动扩缩容，单 GPU 服务 7 模型，GPU 用量降 82%
- [Chameleon](https://arxiv.org/abs/2411.17741) — **MICRO’25**。多 Adapter 自适应缓存与调度，P99 TTFT 降 80.7%
- [HydraInfer](https://arxiv.org/abs/2505.12658) — 多模态 Encode-Prefill-Decode 三阶段分离，吞吐 3.7×

### E. 更细粒度执行调度

关注 MoE expert scheduling / activation & KV movement / execution overlap / 长上下文并行度自适应。

- [Janus](https://arxiv.org/abs/2512.13525) — attention 与 MoE expert 分离到不同 GPU pool，微秒级 activation scheduler
- [FinDEP](https://arxiv.org/abs/2512.21487) — 细粒度 Disaggregated Expert Parallelism，通信-计算 overlap
- [LoongServe](https://arxiv.org/abs/2404.09526) — Elastic Sequence Parallelism，并行度在线可调
- [Layered Prefill](https://arxiv.org/abs/2510.08055) — 按层（非 token）分块调度 MoE，TTFT 降 70%
- [Medha](https://arxiv.org/abs/2409.17264) — 细粒度抢占式，消除长上下文 convoy 效应，P99 延迟降 174×
- [Astraea](https://arxiv.org/abs/2512.14142) — 按 I/O-wait/compute/tool-call 分类请求，HRRN 调度

### F. 算子调度与 Kernel 融合

关注 kernel 执行顺序与融合 / 通信-计算协同 / mega-kernel 编译 / CUDA Graph 物化。

- [ClusterFusion](https://arxiv.org/abs/2508.18850) — **NeurIPS 2025**。ClusterReduce/ClusterGather 集群级通信原语，Attention 全流程单 kernel
- [Mirage Persistent Kernel (MPK)](https://arxiv.org/abs/2512.22219) — 多 GPU 推理编译为单个 mega-kernel，SM 级任务图调度，延迟降 1.7×
- [Foundry](https://arxiv.org/abs/2604.06664) — CUDA Graph 模板化持久化，加速冷启动

### G. Agent / 工作流级调度

关注 Agent 程序作为调度单元 / 跨步骤 KV cache 共享 / 多模型路由 / DAG 拓扑路由。

- [SAGA](https://arxiv.org/abs/2605.00528) — **HPDC’26**。Agent Execution Graph 预测 KV cache 复用，KV cache 命中接近 Bélády 最优
- [Autellix](https://arxiv.org/abs/2502.13965) — PLAS/ATLAS 算法消除程序级队首阻塞，吞吐提升 4–15×
- [KVFlow](https://arxiv.org/abs/2507.07400) — Agent Step Graph 驱动 KV 逐出 + 预取
- [Aragog](https://arxiv.org/abs/2511.20975) — Just-in-time 模型路由
- [AdaptOrch](https://arxiv.org/abs/2602.16873) — DAG 驱动的多 Agent 拓扑路由
- [TokenDance](https://arxiv.org/abs/2604.03143) — 多 Agent 集体 KV cache 共享

## 3. 如何看

1. 先看综述，建立问题地图。
2. 看单引擎请求调度，明确目标函数。
3. 看 cache-aware 与 P/D 解耦，理解 stateful serving。
4. 再看多模型、长上下文、MoE，把视角推进到 execution layer。
5. 最后看算子融合与 Agent 工作流调度，理解最前沿的两个方向：向下到硬件，向上到应用。

## 6. 对最近进展的判断

最值得注意的不是又多了一个 scheduler，而是问题边界在变：

1. `scheduler` ：要同时考虑 request、KV、phase、memory tier、transfer。
2. `router` 和 `engine scheduler` 正在融合。
3. 热点正在从单纯 request scheduling 转向：

- scheduling + KV offloading
- scheduling + disaggregated memory
- scheduling + multi-model pooling
- scheduling + MoE execution graph

1. 算子调度从”逐个 kernel launch”走向”mega-kernel 融合”（ClusterFusion、MPK），与上层调度形成纵向协同。
2. 调度粒度从请求级提升到 Agent 工作流级（SAGA、Autellix、KVFlow），KV cache 复用从”巧合命中”变成”可预测、可规划”的调度资源。
3. 理论化趋势明显—从 2025 年下半年开始，排队论最优性证明（RAD）、NP-hard 归约（Prefix Reuse Scheduling）、位置论文（Mathematical Optimization）密集出现，说明领域正从经验驱动进入理论驱动的阶段。

如果要继续深挖，优先盯这几个交叉点：

- scheduling + KV offloading
- scheduling + disaggregated memory
- scheduling + multi-model pooling
- scheduling + MoE execution graph
- scheduling + operator fusion（向下到硬件）
- scheduling + Agent workflow（向上到应用）
