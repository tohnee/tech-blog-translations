### 4. `tools/call` 的完整生命周期

Server.cpp:1198-1440 是全插件最密的一段。**校验顺序是刻意设计的**：

```text
1. params 存在
 2. name 非空字符串
 3. RequestId 有效
 4. arguments 是 object
 5. FindTool（大小写不敏感）
 6. 同 id 已在飞 → 拒绝（"would orphan the existing callback and leak its POST"）
 7. 同 id 已取消但仍在完成 → 拒绝，要求换新 id
 8. 模态/slow task 阻塞 → 拒绝
    ↑ 放在 header 校验之前、任何 request state 之前
      "so a refusal runs no tool code and leaves nothing behind"
 9. 2026-07-28 的参数 header 校验
10. 取 _meta.progressToken → bUseStreaming = Session有效 && Token有效
11. 建 Context，分配 InvocationSerial（session 内 ++NextInvocationSerial；无会话为 0）
12. 建 FToolInvocation GC 锚
13. 若 streaming：先写一个空 SSE 响应头占位
14. Tool->RunAsync(..., SelectedVersion, HandleToolResult)
```

流式前置写出的头：`Connection: keep-alive`、`Cache-Control: no-cache`、`Mcp-Session-Id`，flags = `MultipleWriteStream | HasAdditionalWrites`；写完再复查一次 serial 与 liveness。

**`HandleToolResult` 的层层防护**

- `checkf(IsInGameThread())` —— 硬断言
- `ON_SCOPE_EXIT` 调 `Complete()`
- **`WeakServerLifetimeToken` 失效 → 直接返回**（服务器已被销毁）
- **比对 `InvocationSerial` 而非仅比 id** —— 防止复用 id 的新调用被旧调用的迟到结果应答
- 清理 `CancelledRequestsPendingCompletion`
- **`ConnectionLiveness` 弱引用失效 → 移除请求、不回写**（客户端已断连）
- 发 `ToolCall` 遥测；若 `ResolvedInnerToolName` 非空则**再发一条**
- **非 streaming**：`CompleteWithResult`，Content-Length 分帧，一次写完，连接不被 park
- **streaming**：`AddProtocolFieldsToResult` + 紧凑 JSON + `FormatSSEMessage`，flags = `MultipleWriteStream | SkipHeaderWrite`；**清掉 `HasAdditionalWrites`** 让引擎发出 chunked 终止符，这样 HTTP/1.1 客户端能识别消息结束而不必关 socket

**线程跳转就在这里**

Server.cpp:1425-1437：

```cpp
Tool->RunAsync(InvocationRequestId, ToolArguments, SelectedVersion,
  [HandleToolResult](const FModelContextProtocolToolResult& Result) {
    if (IsInGameThread()) { HandleToolResult(Result); return; }   // 省一个 tick 延迟
    AsyncTask(ENamedThreads::GameThread,
              [HandleToolResult, Result]{ HandleToolResult(Result); });
  });

```

派发前还有一条断言：`checkf(!IsExecutionBlockedByModalOrSlowTask(), "Tool code must not run inside a modal or slow-task scope...")`。

**没有串行队列** —— 多个 `tools/call` 可以同时在飞。也**没有任何超时/deadline 机制**（grep timeout/deadline 全模块无命中）。工具挂死就是挂死，只能靠客户端断连或取消。

### 5. 线程与生命周期安全模型

这一层最值得学的部分：如何处理「外部异步请求 × UE 游戏线程 × GC × 模态循环」的四角冲突。

| 机制 | 作用 |
| --- | --- |
| FToolInvocation : FGCObject（Server.cpp:48-79） | 每次调用创建一个，ctor check(IsInGameThread())，通过 Tool->AddReferencedObjects 保住工具引用的 UObject 不被 GC；Complete() 必须在游戏线程 UnregisterGCObject（注释：retained callback 副本可能在 worker 线程销毁，GC 期间注销不安全） |
| ServerLifetimeToken（TSharedPtr<bool>） | 弱引用捕获进所有回调。取消代码可能反过来销毁服务器，token 失效就静默退出。头文件注释：”Late async completions can outlive the server” |
| bStopping + ON_SCOPE_EXIT | 防重入 Stop；static 的 bIsTickingDuringModalLoop 便于 handler 销毁服务器后复位 |
| InvocationSerial | 防 id 复用串号 |
| CancelledRequestsPendingCompletion | 上限 1024/会话（MaxCancelledRequestsPendingCompletionPerSession），防止慢工具或永不完成的工具让取消 id 表无限膨胀 |
| DeferredToolCancellations | 模态期间推迟 CancelAsync，下次 Tick 或 Stop 时排空；独立函数持有队列，因为 CancelAsync 可能重入或销毁服务器 |
| SweepDisconnectedRequests() | 每次 Tick 清扫断连请求，跑在进度门之外（无 progress 的调用也会掉线） |

`Stop()`（Server.cpp:594+）的顺序：`MoveTemp` 出 RequestState / Sessions / DeferredCancellations → 移除 ticker → 解绑路由。注释：”Remove session routing before cancellation so synchronous completions cannot reply through a stopped session.”

模态循环泵

ModelContextProtocolModalDialogPump.h 解决”编辑器弹了个模态框，core ticker 停了，MCP 就死了”的问题。

三条驱动源：

| 场景 | 驱动 |
| --- | --- |
| Slate 模态 | modal-loop tick（TickDuringModalLoop） |
| 原生对话框 | FCoreDelegates::PreModal / PostModal 之间的平台定时器（NativeModalDepth 计数，支持嵌套） |
| Slow task | 进度更新回调 |

**明确不覆盖 `FPlatformMisc::MessageBoxExt`** —— 它不广播 PreModal。仅游戏线程；`bIsServicing` 防重入。

阻塞判定：`IsInInteractiveEditorSlowTask() = GIsEditor && !IsRunningCommandlet() && FSlowTask::IsInSlowTask()`（Server.cpp:42-45）。

**模态期间的方法白名单**（Server.cpp:107-112）：

- `ping` 和 `initialize` 在检查之前就路由，**永远服务** —— 这样会话过期的客户端能在阻塞期间重新初始化
- 此外只服务 `notifications/initialized`、`tools/list`、`notifications/cancelled`
- 其余会跑工具或资源 provider 代码的方法一律返回**可重试错误**

拒绝点放在会话校验之后（Server.cpp:953-958），这样过期会话拿到 404 而非阻塞错误，可以去重新初始化。`tools/call` 在自己的 handler 内再拒一次。

编辑器侧的 `TickServerDuringModalLoop` **每次调用都重新取 module + server**（ModelContextProtocolEditor.cpp），注释：”the runtime module can destroy or replace the server at any time”。
