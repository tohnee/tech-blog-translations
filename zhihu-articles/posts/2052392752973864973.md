最近随着 *Redis 作者，GLM 5.2 的火爆，加上马斯克关于中国大模型 Q1 追平美国* 的讨论，中国大模型崛起的话题在技术圈还相当火热，其中有一个观点是：

> **美国前沿模型（Claude、GPT等）因为太贵，企业会不会大规模转向中国开源模型,， 自己建推理服务？**

![](https://pic3.zhimg.com/v2-51b7371f32bbcf7aa43d55d498c3088a_r.jpg)

比如这位的观点就是，美国前沿模型的 API 价格太贵了，而这种情况下，**中国开源模型（GLM-5.2、DeepSeek等）质量表现已经相当不错，但是 serving 成本只有美国模型的几分之一**。

这时候企业会发现：

- 自己买 8 张 B200 或 MI300X 显卡，在美国托管服务上跑开源模型，能省下**大概 10 倍**成本
- **成本高低极度依赖推理引擎的优化水平**（kernel调优、speculative decoding、模型shape适配等）
- 因此会产生新的需求：企业愿意花重金请 inference/kernel 工程师做优化

> 从他的角度，可以构建大量 RL 环境配合推理优化/内核工程的 RL 基础设施，用小模型 “ hyperspecialize”（高度专业化）这些技术任务，从而服务远超现在数量的客户。

简单说，**他相信 “中国模型 + 极致自建/优化推理” 可以成为主流趋势**，巧合的是，最近微软就考虑在特定产品 Copilot Cowork 里面，把经过微软 fine-tune（微调）、托管在 Azure 上的 DeepSeek V4 模型作为可选的低成本后端选项：

![](https://picx.zhimg.com/v2-361938199fde5286924ce029137f7f07_1440w.jpg)

Copilot Cowork 是微软 365 企业套件里的 agentic AI 代理，类似 Claude Cowork ，能自主执行多步任务，比如整理邮件、准备会议、生成 Excel 报告、处理 Teams 聊天等等，它目前主要用 的是 OpenAI 和 Anthropic 的模型。

但是问题是，Agentic AI 会反复调用模型，导致 token 消耗很高，微软 Copilot 负责人 Charles Lamanna 说：

> 用户每周做几百个的成本会非常高，所以考虑转向性价比模型。

然后这个话题也引来了不少反驳者，比如这位：

![](https://pic4.zhimg.com/v2-bf21a1ccf12a99461d7dd23c77fd3251_r.jpg)

他的意见很明确：

- **美国模型贵，不是因为服务成本高，更多原因是因为利润率高**，因为这些模型明显表现更好，目前 OpenRouter上 “中国模型用量已经主导” 的说法是假象
- 蒸馏不是万能药，有强模型后，确实可以蒸馏成小模型来便宜服务（你拥有 logprobs、隐藏状态和训练数据），但现在大家想要的是最好模型，所以 Anthropic 不在乎降价
- 美国公司在硬件上有很大优势，NVL72 这类机架级系统在调度和互联速度上有明显优势
- Sparse MoE 模型的扩展性极强，但门槛很高，要把 MoE 模型拆到几百张 GPU 上，让每个“专家”都忙起来，需要持续数百万请求（最好跨时区接近24/7满载），只有 Big Tech 能做到，否则你就是在为大量闲置 GPU 买单，而 GPU 价格还在上涨

> 也就是在他的观点，推理领域确实有钱赚，但“公司自己买 B200 跑 SGLang ” 这种模式，在能赚到数十亿美元的规模上很难成立。

**而另外一个观点认为，蒸馏要做到 GLM 5.2 根本不可能**：

![](https://pic3.zhimg.com/v2-0a5037863a1c5b0ac1eceb9d6f2958d6_r.jpg)

**如果只是蒸馏，是没办法同时做到“便宜 + 同等质量”**，如果蒸馏真能实现 cheap-and-equivalent ，那 Claude Haiku 4.5 就不会既比 Sonnet 便宜约10倍、又明显能力更弱。

蒸馏只是在现有的“成本-质量权衡曲线”（Pareto frontier）上移动，而不是把这条曲线往外推， 当你已经训练出更大更强的模型时，你就已经完成了根本性的提升。

> 通俗例子的说，**蒸馏就像让学霸把知识精华教给普通学生，普通学生成绩会大幅提升，但几乎不可能变成新的学霸。**

在他看来，GLM-5.2 已经很能强了，而且适配了华为芯片的情况下，成本还可能可以更低，**同时 MoE 模型也不需要那么夸张的规模** ：

> 以 DeepSeek 这类 MoE 模型为例，最优 batch size 主要是通过稀疏率决定，大约 2400 个并发序列就够了，所以这远不是“数百万请求”，普通公司也能做到。

![](https://pic2.zhimg.com/v2-cf6c9cd6d32a4e34d8dfb3446d6d8937_r.jpg)

**虽然这种讨论不会有最终结论，大家都是捍卫自己的观点，但是有一个现象很明确，中国的模型比以前更被重视了，至少这次 GLM 5.2 确实收获了不少肯定，能引起讨论，已经说明了问题**。
