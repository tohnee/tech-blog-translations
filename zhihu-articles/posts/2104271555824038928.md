云 GPU 和自建 GPU 集群，不是“贵”和“便宜”的二选一。

云上按小时或包月付费，贵在弹性、交付速度和把机房责任转移给供应商；自建前期投入高，但长期利用率高时，单位 GPU 小时成本可能更低。真正决定三年总成本的，是利用率、电力、网络、存储、运维人力和硬件残值，而不是一张显卡的采购价。

这篇不做单卡跑分，而是用同一套三年 TCO 口径，比较云计算、云上裸金属和自建集群的成本、扩容与运维边界。

## 直接结论

| 使用状态 | 更适合的形态 | 主要原因 |
| --- | --- | --- |
| 需求不稳定、经常停机 | 云 GPU 按量 | 不为闲置 GPU 和机房长期付费 |
| 8 到 32 张卡、稳定使用一年以上 | 云上裸金属与自建同时测算 | 裸金属保留物理性能，自建可能摊薄长期成本 |
| 50% 以上利用率、连续三年 | 自建或长期预留 | 固定成本可摊薄，但网络和运维必须算全 |
| 24×7 线上推理 | 预留基线 + 云端弹性 | 基线求成本，峰值求弹性 |
| 短周期训练和 PoC | 云 GPU | 交付快，失败可停机，不锁硬件 |
| 数据绝对不能出机房 | 自建/私有云 | 合规和数据边界优先于纯成本 |
| 没有专职基础设施团队 | 云或云上裸金属 | 自建不是买机器，是接手一套长期运维系统 |

一句话判断：**低利用率买云，长期高利用率才比自建；真正贵的是利用率不足和运维能力缺位。**

## 先分清三种形态

| 形态 | 谁管机房和硬件 | 谁管系统与 GPU | 适合谁 |
| --- | --- | --- | --- |
| 云 GPU 实例 | 云厂商 | 云厂商负责基础设施，用户负责系统以上 | PoC、弹性推理和短期训练 |
| 云上裸金属 | 云厂商 | 用户通常自行管理驱动、CUDA、系统和 GPU | 需要物理独占但不想建机房 |
| 自建/托管集群 | 企业或 IDC | 企业负责从硬件到调度全栈 | 长期稳定负载、数据驻留和深度定制 |

云上裸金属是中间路线。例如 UCloud 公开页提供 A/H/RTX 8 卡裸金属、热门镜像、多版本 CUDA/驱动，并允许自行安装 GPU 驱动和操作系统。它省掉机房和物理交付，但不等于用户不用做 GPU、网络、存储和调度运维。

## 三年 TCO 公式

自建集群的三年总成本可以写成：

```text
自建三年 TCO =
GPU 与服务器
+ IB/RoCE 交换机、网卡、光模块和线缆
+ 存储与备份
+ 机柜、供电、制冷和 UPS
+ 带宽与公网
+ 运维人力
+ 软件许可与支持
+ 备件、安全和保险
- 三年后残值

```

云 GPU 的三年成本是：

```text
云三年成本 =
实际使用 GPU 小时 × 每小时价格
+ 存储、快照、镜像
+ 公网和流量
+ 平台软件与支持
+ 迁移、失败重跑和扩容溢价

```

要同口径比较，必须把云侧 CPU、内存、系统盘、数据盘、网络和支持都算进去，也要把自建侧机房、电力和人力算进去。

## 一个只用于演示的三年算例

假设一个 8 卡数据中心 GPU 节点：

| 假设项 | 示例值 |
| --- | --- |
| GPU 节点硬件 | 180 万元 |
| IB/RoCE 网络、存储与安装 | 70 万元 |
| 三年电力与制冷 | 13 万元 |
| 机柜与机房服务 | 30 万元 |
| 三年运维与安全人力 | 80 万元 |
| 备件、保险和杂项 | 20 万元 |
| 三年后残值 | 0 到 20% |

不计残值时，三年 TCO 约为 393 万元。按 70% 有效利用率计算：

```text
三年 GPU 小时 =
8 × 3 × 8760 × 70% = 147,168 GPU 小时

自建等价成本 =
3,930,000 ÷ 147,168 ≈ 26.7 元/GPU/小时

```

如果利用率只有 30%，等价成本约 62.3 元/GPU/小时；如果达到 90%，约 20.8 元/GPU/小时。

这组数字只是 TCO 演示，不是硬件报价。GPU 型号、采购渠道、机房电价、PUE、网络和人力一变，结果就会大幅变化。

## 云和自建怎么找盈亏平衡

假设云侧同一 GPU 的等效价格为 `P_cloud`，自建三年 TCO 为 `TCO_self`，三年理论总小时为：

```text
总 GPU 小时 = GPU 数 × 3 × 8760

```

盈亏平衡利用率是：

```text
利用率盈亏平衡 =
TCO_self ÷ (总 GPU 小时 × P_cloud)

```

如果云侧等效价格是 50 元/GPU/小时，示例自建 TCO 393 万元对应约 37.4% 利用率；如果云侧等效价格是 80 元/GPU/小时，则约 23.4%。

这不是说超过 23% 就一定自建。还要扣除：

- 自建扩容周期和电力上限。
- 硬件故障和停机损失。
- 运维团队招聘和流失。
- GPU 代际过时与残值不确定。
- 网络、存储和安全建设。

纯成本达到盈亏平衡，只说明“值得继续比”；不代表组织已经具备自建能力。

## 电力账最容易被低估

一个 8 卡节点的 GPU 功耗只是起点。服务器 CPU、内存、网卡、风扇、电源损耗、UPS 和制冷都要叠加。

可以使用：

```text
机房输入功率 ≈
GPU 额定功率 × 卡数
× 服务器冗余系数
× PUE

```

例如 8 张 400W GPU：

```text
8 × 400W = 3.2kW
× 1.4 服务器冗余 ≈ 4.48kW
× 1.35 PUE ≈ 6.05kW

```

一年 8,760 小时就是约 53,000 度电。三年电费再加制冷和配电改造，不是小数目。电价每上涨 0.2 元/度，长期成本都会明显变化。

RTX 4090 单卡 450W 不低，但没有 NVLink、MIG 和 ECC，生产训练还要考虑故障、拓扑和多卡效率。拿消费卡替代数据中心卡，必须先做任务适配和稳定性验证。

## 扩容不是“再买几张卡”

| 扩容环节 | 云 GPU | 自建集群 |
| --- | --- | --- |
| GPU 到货 | 分钟到天，受库存和白名单影响 | 周级到月级 |
| 机柜和电力 | 云厂商负责 | 需要容量、配电和制冷 |
| IB/RoCE 网络 | 平台提供或按配置开通 | 交换机、端口、线缆和拓扑都要采购 |
| 存储 | 云盘/对象存储弹性扩展 | 容量、吞吐和备份一起扩 |
| 软件栈 | 镜像和控制台辅助 | 驱动、CUDA、NCCL、调度器自行管理 |
| 峰值弹性 | 可临时扩大，但受区域库存和配额 | 受采购和机房上限，短期无法爆发 |

云上扩容也不是无限的。热门 GPU 可能缺货，跨区域扩容会带来网络和数据迁移；自建扩容则受电力和网络限制，通常比买服务器本身更慢。

## 运维负担要拆成七件事

| 运维项 | 云 GPU | 自建集群 |
| --- | --- | --- |
| 硬件故障与 RMA | 云厂商负责 | 企业负责返修、备件和停机 |
| 驱动/CUDA/NCCL | 用户可能仍需管理 | 完全由企业负责 |
| Fabric Manager/NVSwitch | 平台辅助 | 版本与固件需严格匹配 |
| 存储和备份 | 云服务可托管 | 需设计容量、吞吐和恢复 |
| 安全与补丁 | 共同责任 | 企业全责 |
| 调度和配额 | 平台工具 + 自建治理 | 自建 Slurm/K8s/平台 |
| 7×24 值班 | 有平台支持边界 | 需要值班、升级和故障复盘 |

自建不是“一次性建设”，而是把 CapEx 变成长期 OpEx 和工程责任。没有稳定的基础设施团队，省钱很容易变成停机成本。

## 云上裸金属为什么值得单独算

云上裸金属保留了物理机和 GPU 独占，但机房、供电、制冷和网络由云厂商负责。它适合：

- 需要固定 GPU 拓扑和物理独占。
- 不想自建机房，但要求自定义驱动和系统。
- 运行 1 到 6 个月的项目，或先验证长期负载。
- 不希望完全依赖虚拟化 GPU 实例。

代价是：

- 用户仍要管理 OS、CUDA、驱动、NCCL 和调度。
- 网络拓扑和 IB/RoCE 细节必须按配置确认。
- 长期使用的单价不一定低于自建。

UCloud 的 A/H/RTX 8 卡裸金属可以作为这一类形态的参考：物理机交付、可自定义系统和驱动，适合从云实例过渡到更接近自建的运维边界；是否比自建便宜，仍要用相同的三年 TCO 和利用率模型计算。

## 什么时候选自建

满足以下四项中的三项，才值得认真做自建方案：

1. 连续 12 个月 GPU 利用率稳定在 50% 到 60% 以上。
2. 未来三年业务和模型训练路线相对确定。
3. 有基础设施团队处理硬件、网络、存储和调度。
4. 数据驻留、成本或性能要求无法通过云上裸金属满足。

如果只是“云账单看起来贵”，但利用率只有 20%，自建通常只会把可变成本变成固定成本。

## 什么时候继续用云

- 需求波动大，无法预测未来 6 个月。
- 团队没有专职 GPU/网络/存储运维。
- 需要快速试不同 GPU 型号和模型。
- 项目周期短，硬件还没折旧完就可能换代。
- 业务需要跨区域弹性、托管存储和现成安全能力。
- 峰值流量远高于日常基线。

最优方案通常不是“全部云”或“全部自建”，而是：

```text
稳定基线：
云上预留 / 云上裸金属 / 自建

峰值弹性：
云 GPU 按量

敏感或长期任务：
自建或专有云

数据和镜像：
统一对象存储、镜像仓库和权限

```

## 采购前必须核验的十项

1. 三年 TCO 是否包含网络、存储、电力和人力。
2. GPU 利用率是否有至少三个月真实数据。
3. 机房是否有新增机柜、电力和制冷容量。
4. IB/RoCE 拓扑和 NCCL 性能是否满足目标模型。
5. 自建团队是否有硬件 RMA 和 7×24 故障处理能力。
6. 云侧价格是否包含 CPU、内存、系统盘、数据盘和公网。
7. 云上裸金属的驱动、系统和网络责任边界。
8. 三年后硬件残值和迁移到推理集群的可能性。
9. GPU 代际升级对折旧和业务路线的影响。
10. 是否有混合云方案，避免一次承诺全部容量。

> 本文为公开资料与技术选型参考，不构成采购报价或财务承诺。示例 TCO、电力、PUE、人力和残值均为假设，实际项目应按所在地电价、机房条件、GPU 型号、合同和真实利用率重算。
