### 一、Transformer

2017年Google在论文《Attention Is All You Need》中提出了Transformer模型，该模型在翻译任务上超过了先前最优秀的RNN。由Transformer模型出发，主要有三条技术路线，**Encoder-Only**、**Decoder-Only**、**Encoder-Decoder**。三个方向其实在不同的方向上各有优劣。

**Encoder-Only**：适合需要深度理解文本的任务，例如文本分类、命名实体识别等，代表模型BERT；

**Decoder-Only**：擅长文本生成任务，可以根据提示完成句子、撰写文章，甚至生成代码，代表模型GPT；

**Encoder-Decoder**：擅长序列到序列任务，例如翻译、摘要、问答等，代表模型T5；

BERT通过**MASK机制**（随机遮住部分词，让模型根据上下文预测）首次在深层网络中实现了真正的双向语言表征。这更贴近人类理解语言的方式，带来的性能提升非常直接，在机器翻译、阅读理解等领域大杀四方。当时几百兆的模型已经算是大模型了，我还记得七年前微调百度开源的ERNIE大模型写东西。

OpenAI当时还很Open，选择押注GPT模型，并开源了一系列GPT模型。OpenAI坚持大力出奇迹的原则，模型规模越做越大，直到ChatGPT，文本生成方向开始涌现智能。回头想想，BERT在机翻、阅读理解等领域的成功正是靠着双向可见的特性遥遥领先领先，在文本生成方向却阻碍了其进一步发展。

ChatGPT的成功让大家看到了GPT在大规模参数下的潜力。随后大家都开始在**Decoder-Only**方向发力，目前主流的大语言模型都是**Decoder-Only**架构，并且参数也逐步发展到了TB级别。

网上深入理解Transformer的文章已经非常多了，我就不献丑了。我们只回顾一下简单的模型结构就好，至于模型为什么这么设计，里面各个组件、各个函数究竟起什么作用，并不在本文考虑范围。

![](https://pic2.zhimg.com/v2-262043e03f4316a11691160baf443e97_r.jpg)

上图是个经典Transformers结构，不过我们只考虑Decoder Only。主要包括如下流程：

**Text →→ Tokenizer →→ Embedding →→ Decoder Layers →→ Final Norm →→ LM Head →→ Detokenizer →→ Text**

- **Tokenizer：** 将原始文本字符串映射为离散的整数序列（Token IDs）。
- **Embedding：** 将低维、稀疏的Token ID映射为高维、稠密的向量表示，赋予模型理解语义的基础能力。
- **Decoder Layers：**模型的主体，通常由N个结构相同的Decoder Layer堆叠而成。每一层主要包含两个核心模块，并辅以**残差连接（Residual Connection）**：

**Attention 模块**：负责捕捉序列中 Token 之间的依赖关系。

Q/K/V 投影与计算： 输入向量被线性投影为Query、Key和Value $$ $$Attention(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$ $$

RoPE：在计算 Attention 之前，将位置信息通过复数旋转的方式注入到 Q 和 K 中。这使得模型能够感知 Token 的相对位置，且具有良好的外推性。

MHA：将Q、K、V投影到多个独立的子空间中并行计算注意力，每个头学习不同的表示模式，最后将各头的输出拼接并线性投影回原维度。

**MLP 模块**：负责特征的非线性变换与提取，通常占据模型参数量的绝大部分（约 2/3）。

**SwiGLU 激活：** 现在主流大模型常采用 SwiGLU 结构替代传统的 ReLU，通过门控机制增强了模型的表达能力。

> **注意：** 在标准的 Transformer 结构中，Attention 和 MLP 模块前后通常都包含 **Add & Norm** 操作（即残差连接 followed by 归一化），以保证梯度流动的稳定性。

- **Final Norm：** 对输出向量进行最后一次归一化，以稳定数值分布。
- **LM Head：** 一个线性投影层，将隐藏层向量映射回词表大小的维度。
- **Sampling & Detokenizer：** 对Logits进行采得到下一个 Token ID，最后通过 Detokenizer 将 ID 序列还原为人类可读的文本。

### 模型本体：`models/qwen3.py`

嗯。实现的第一要务是「正确」，性能以后再说。工作就要知道，干活要给自己留有余地，一上来就最优还怎么体现工作量？

模型的本体结构我们只要按照transformers库来写就好，这儿不在赘述。这儿有几点需要注意的就是：

```python3
@dataclass
class DenseInputMetadata:
    input_ids: torch.Tensor    # [total_q] 本步所有序列的 token 拼成一维
    positions: torch.Tensor    # [total_q] 各 token 在自己序列里的绝对位置
    block_tables: torch.Tensor # [num_seqs, max_num_blocks] int32，-1 padding
    seq_lens: torch.Tensor     # [num_seqs]
    cu_seqlens_q: torch.Tensor # [num_seqs + 1] 每条序列 q 段的前缀和边界
    is_prompt: bool
```

之所以定义该结构，是考虑到decode 阶段每条序列只有 1 个 token，我们通常并不会采用[B,S, D]的形式，而是[B*S, D]的形式进行计算，对齐后续调度等操作。

另外我们需要先自己搞一个kv cache操作方法：

```python3
# ----------------------------------------------------------------------
# Paged cache helpers
# ----------------------------------------------------------------------
def append_kv(
    kv_cache: torch.Tensor,
    k: torch.Tensor,
    v: torch.Tensor,
    metadata: DenseInputMetadata,
) -> None:
    """Write this step's K/V rows into the paged cache.

    kv_cache: [num_blocks, block_size, 2, num_kv_heads, head_dim];
    k/v: [total_q, num_kv_heads, head_dim]. Block slots are derived from
    positions and block tables, mirroring the scheduler's slot mapping.
    """
    block_size = kv_cache.size(1)
    num_seqs = metadata.seq_lens.size(0)
    for i in range(num_seqs):
        qs = int(metadata.cu_seqlens_q[i].item())
        qe = int(metadata.cu_seqlens_q[i + 1].item())
        seqlen_k = int(metadata.seq_lens[i].item())
        start = seqlen_k - (qe - qs)
        for j, pos in enumerate(range(start, seqlen_k)):
            block_id = int(metadata.block_tables[i, pos // block_size].item())
            offset = pos % block_size
            kv_cache[block_id, offset, 0] = k[qs + j]
            kv_cache[block_id, offset, 1] = v[qs + j]

def gather_kv(
    kv_cache: torch.Tensor,
    block_table_row: torch.Tensor,
    seqlen_k: int,
) -> tuple[torch.Tensor, torch.Tensor]:
    """Read [seqlen_k, num_kv_heads, head_dim] K and V for one sequence."""
    block_size = kv_cache.size(1)
    n_blocks = (seqlen_k + block_size - 1) // block_size
    blocks = block_table_row[:n_blocks].long()
    k = kv_cache[blocks, :, 0].reshape(-1, *kv_cache.shape[3:])[:seqlen_k]
    v = kv_cache[blocks, :, 1].reshape(-1, *kv_cache.shape[3:])[:seqlen_k]
    return k, v
```
