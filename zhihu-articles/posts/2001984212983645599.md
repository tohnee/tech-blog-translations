## 写在前面的话

## 为什么想写这个系列的文章

大约两年前，一次偶然的机会，我接触到了量化交易。在这两年里，我陆续学习了相关的理论和工具，阅读了不少书籍，也动手做了很多实验，逐渐掌握了启动量化交易所必需的基础知识和技能。

去年 10 月，我使用开源软件搭建了自己的第一套系统，并开始用它进行 A 股实盘交易。

这个系统非常简单，用现在流行的话说，就是“先做个垃圾出来”。幸运的是，它运行得还算稳定，达到了我设定的底线——不把本金亏光，并且在绝大多数月份中都能略微跑赢大盘。

在学习的过程中，我发现一个有趣的矛盾：**程序员其实非常适合从事量化交易，但程序员的某些思维定式，也可能成为入坑的阻碍**。

先不说为什么适合，这里列举几个可能阻碍程序员入坑量化交易的点：

**1. 容易陷入策略细节，忽视体系与方法论**

程序员习惯于写代码，因此看到网上各种代码实现的交易策略时，会感到亲切，容易一头扎进去，开始研究各种策略、进行回测、对比收益，不知不觉中将量化交易变成了“LeetCode 式”的刷题游戏。

更有一些有机器学习背景的程序员，会习惯性地将量化交易建模为预测问题——有的预测收益率，有的甚至直接预测股价，然后搬出各种模型进行尝试，把量化交易变成了 Kaggle 竞赛。

但从我的经验来看，在启动阶段，具体的策略和模型其实是最不重要的，也不值得投入过多精力。初期，策略和模型更多是起到“占位符”的作用，够用即可。真正关键的是以下几点：

- 一套简洁、自洽的思维与方法论体系
- 一个能快速跑起来的系统
- 基于这个系统用真金白银进行实盘交易，快速建立量化交易的实感

**2. 一提到“交易系统”，就想到全自动交易**

这是职业背景带来的思维惯性。在工作中，“系统”往往意味着自动化、高频执行的系统，所以一想到“量化交易系统”，脑中就容易浮现这样的画面：程序根据策略自动买入卖出，屏幕上跳动着交易日志与指标看板。

这种想象很容易让人高估搭建一个简单交易系统的复杂度。例如，一想到全自动，就会觉得必须接入交易 API，而很多交易所或第三方平台的 API 不仅集成复杂，还有高昂的费用和门槛，容易让初学者望而却步。

实际上，量化交易系统并不一定是全自动的。它可以是半自动，甚至完全手动。我就见过有人用 Excel 搭配交易软件手动执行量化策略。尤其是在起步阶段，完全可以不用 API，手动完成交易——并且我建议最初就这样做。

量化交易系统的核心，是能够**量化**交易的系统，而不一定是**自动**交易的系统。入门阶段完全可以用很轻量的方式跑通流程，具体方法后续章节会详细展开。

**3. 现有资料对程序员不够友好**

我学习时翻阅了不少资料，从传统书籍到网络文章，大致可分为三类：

**金融领域的量化交易论文与书籍**

这部分内容非常重要，甚至是前期学习中不可或缺的。但它们大多面向经济、金融专业的“正规军”，对我们这些“野路子”来说，重要的是理解其中的核心思维与抽象方法，而非具体细节。往往读完整本书，只有 10%–20% 的内容是当前阶段真正需要的，学习效率较低。

在这个系列的前几篇，我会整理出我认为最需要掌握的思维框架与方法论。

**程序员群体分享的策略与模型**

这类资料也很常见，大多是代码、模型甚至完整系统的分享。

但与上一类相反，它们往往过于“程序员思维”，停留在“我有一个好想法”的层面，很多只是玩具项目，甚至会出现回测年化收益超过 500% 这种自娱自乐的策略。

**割韭菜类内容**

这一类就不多说了，本质上与量化交易无关，只是打着教学的旗号收割而已，大家看到直接忽略就好。

基于以上原因，我萌生了写这个系列文章的想法。

说实话，写文章主要目的是对我这两年学习的总结与梳理，顺便实践一下费曼学习法。当然，如果这些内容能对也想入门量化交易的朋友有所帮助，那就更好了。

## 对文章受众的假设

显然，我无法写出一篇适合所有人的文章，因此有必要明确这个系列文章的目标读者画像。

尽管这个系列的主题是“写给程序员的量化交易入坑指南”，但它并不仅仅面向程序员。只是**程序员群体更可能符合我所设定的知识背景和能力假设**。

具体来说，我会假设读者已具备以下知识与能力。为了使说明更具体，我会在每项能力下列出一些案例，供读者自我评估（注意：这不是闭卷考试，可以借助书籍、网络、工具甚至 AI 来辅助，只要最终有能力解决下列问题并理解原理即可）。

**基本的工程级代码能力**

- 给一个 GitHub 仓库地址，可以按照 README 的指引，自行折腾并成功运行该项目
- 给一个 Python 库的名称，知道如何查找它在 PyPI 上的正式名称，并通过 pip、poetry、uv 等工具完成安装
- 能将一个 JSON 对象序列化为字符串，并将该字符串作为另一个 JSON 对象的属性值，最后将整个结构序列化为字符串
- 给一个需要 Cookie 鉴权、返回 JSON 的接口地址，知道如何生成 Cookie、从哪里复制 Cookie，并编写代码调用该接口获取数据
- 能够理解编译器或解释器的错误信息，并根据报错定位代码中的问题与原因

**大学工科水平的概率与数理统计知识**

- 理解什么是无偏估计
- 能够证明样本方差的无偏估计分母是 n−1，而不是 n
- 理解频率学派与贝叶斯学派在统计推断视角上的差异
- 能够准确解释“三门问题”及其背后的概率逻辑
- 能理解以下表述：当假设检验拒绝原假设而接受备择假设时，并不意味着原假设一定不成立，而是说明在原假设成立的前提下，观察到当前样本（或更极端样本）的概率非常低，低到我们认为原假设不太可能成立，因而有理由选择备择假设

当然，如果你在某些方面不完全符合上述假设，也依然欢迎阅读本系列文章。只是在某些具体环节上，可能会遇到不同程度的理解和实操障碍。

## 系列文章的结构

在动笔之前，我先用思维导图列出了这个系列文章的结构：

![](https://pic4.zhimg.com/v2-0c03036efb1ebf020e314b13ac2c9897_r.jpg)

整个系列将分为**抽象思维篇**、**理论策略篇**和**技能实战篇**三部分。

**抽象思维篇**

在这一部分，我会先讲述一些方法论和思想层面的内容。或许有人会觉得这些内容比较“虚”，但从我的视角看，它们是必要的。在处理任何实际问题之前，理清思想框架、在哲学层面上对齐认知，都是重要的一步。很多时候争论的产生，恰恰是因为双方没有在这个层面上达成共识。在量化交易这个问题上，理性主义者、经验主义者和实证主义者很可能会得出完全不同的结论。

接着，我会围绕量化交易本身，给出一些定义、分类维度以及不同流派的介绍。这里我会尽量避免使用金融领域复杂的专业术语，而是更多从程序员的角度，用第一性原理的方式来解释：量化交易是什么、能做什么、有哪些常见的做法。

此外，我还会讨论一些对入门量化交易至关重要的思想问题，比如：

- 在专业量化机构林立的市场中，个人或小团队为什么仍有机会？
- 如何看待市场有效性理论？
- 回测的必要性及其局限何在？

最后，我会分享一些入门阶段应当遵循的原则，帮助大家建立风险意识，避免走向“不可挽回”的局面。相比于简单一句“投资有风险，本文不构成投资建议”，这些原则更具实际指导意义。

**理论策略篇**

这一部分会简要介绍量化策略的分类，并讨论技术分析流派和资产组合流派的一些基础理论与常见策略。

由于我本人在策略研究方面也还在持续学习，内容不会特别深入，但足以支持大家顺利入门。正如前文所说，我认为在入门阶段，策略本身并不是最重要的，它更多是起到一个“占位验证”的作用。

本篇还会重点讲解如何评估交易效果。在入门阶段，建立适合自己的评估体系远比纠结某个具体策略更重要。只有明确了评估标准，才知道策略该往哪个方向优化。某种程度上，量化交易也可以看作是一门在收益与风险之间寻找平衡的技术（或艺术）。

此外，我还会讨论**交易成本、滑点、流动性风险**等实际问题。这些因素在程序员入门时特别容易被忽略——因为大家往往更关注策略本身的逻辑和系统的稳定性。然而在实盘交易中，它们的影响可能远超预期，甚至直接导致策略失效，因此必须提前有所认识。

**技能实战篇**

最后一部分围绕技能与实战展开。我会推荐一些可投资的标的，并介绍一些常用的开源工具和框架，用于数据获取、技术指标计算、回测等环节。

对程序员来说，这部分可能是最简单的——即使我不介绍，大家也有能力自己找到合适的工具并学会使用。因此，我的目标不是深入讲解某个工具，而是帮助大家节省时间，尽快跑通一个可用的系统。这些组件并非唯一选择，后续大家完全可以根据自己的偏好进行替换。

最后，我也会展示我基于开源工具搭建的“简陋版”系统。虽然简单，但能够运行起来就是第一步——何况它至今还没让我亏钱，我个人还是比较满意的。

在写作过程中，我可能会根据实际情况对内容进行微调，但整体框架与方向不会改变。

最后，为这个系列立几个 **flag**，也算是对自己的提醒：

- **说人话**：涉及金融与交易的内容，尽量从第一性原理出发，用直白的语言解释，避免堆砌术语、掉书袋。专业名词都会配易懂的说明（但程序员熟悉的概念可能直接使用，还请谅解）。
- **保持简单**：始终记得本系列的目标是帮助读者快速入坑、尽早跑通自己的系统，而不是撰写一本大而全、深而精的量化交易巨著（当然我也没那个能力）。
- **保持更新**（嗯……我尽力……）
