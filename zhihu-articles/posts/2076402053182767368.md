2018 年计算机体系结构国际研讨会（ISCA）上， **John Hennessy** 与 **David Patterson** 做了图灵奖讲座：《计算机体系结构的新黄金时代》。

1980 年代，他们做那项后来拿图灵奖的研究时，单线程 CPU 性能一年涨 **52%** 。到 2018 年，摩尔定律和 Dennard Scaling 走到头，这个数字掉到 **3%** 。

他们给出的出路是 **领域专用架构（DSA）** 。课堂上的例子是已经量产的 Google **TPU v1** ：神经网络推理吞吐是 CPU 的 **29×** ，能效 **80×** 。收尾预言是：

> 下一个十年，会看到新型计算机体系结构的寒武纪大爆发。

预言兑现了。今天认真在做的架构有几十种： **GPU、TPU、LPU、NPU、DPU、ASIC、晶圆级引擎、可重构数据流、神经形态、光子、模拟** 。焦点几乎都对准了 AI 计算。

真正打进规模部署的，是这几条线：

- • **GPU** （NVIDIA、AMD）
- • **脉动阵列加速器** （TPU、Trainium）
- • **Cerebras 晶圆级引擎**
- • **Groq LPU**

NVIDIA 是明确的领跑者；AMD 跟在后面，手里有 OpenAI 和 Meta 各 **6 GW** 的承诺。TPU 训练 Gemini，也将给 Anthropic 最多约 **100 万颗** ；Anthropic 的 Claude 同时还跑在超过 **100 万颗 Trainium** 上。Cerebras 已经承接 OpenAI 推理；Groq LPU 以约 **200 亿美元** 的 acquihire 收进 NVIDIA。

## 问题

AI 计算被 **矩阵乘法** 统治。一个 Transformer 就是一串 matmul： **Q/K/V 投影、注意力、输出投影、FFN** ，中间插着逐元素运算：归一化、激活、残差相加。训练一个前沿模型要做大约次乘加（matmul 本身就是一串 MAC）。

matmul 的 **形状** 取决于负载。

**训练** 把一批序列推过每一层，再反传损失、更新权重，成千上万个 token 同时穿过同一张权重矩阵。

**Prefill** 是推理的提示词吞入阶段：整段输入一次投影完，第一个输出 token 还没产生。训练和 prefill 都是很多 token 压同一张权重，所以每一层都是大的 **矩阵×矩阵（GEMM）** ，算术强度高，算力墙。

**Decode** 是自回归：一次吐一个 token，第 N+1 个必须等第 N 个出来。每步只投影一个 token，matmul 退化成 **矩阵×向量（GEMV）** 。产出一个 token，要把模型全部权重读一遍，还要把注意力的 KV Cache 读一遍。算术强度比 prefill 掉几个数量级。

推理系统会把这些 GEMV 再叠回 GEMM：

- • **连续批处理** 把很多用户的 decode 步叠在一起
- • **投机解码** 每个请求先起草 K 个 token，再一次验证
- • **多 token 预测** 把同一招写进模型内部

目标都是提高 matmul 单元利用率，把 Ops/B 抬上去。连续批处理里，每个用户要读自己的 KV Cache，所以长上下文 decode 会从 **权重带宽墙** 滑向 **KV 带宽墙** 。

架构问题是 **把数字搬到 matmul 发生的地方，够不够快** 。这就是 **内存墙** ：计算指数涨，内存带宽没有。

计算指数涨、HBM 线性涨、SRAM 几乎增长停滞。

## NVIDIA GPU

NVIDIA GPU 是一台 **大规模并行处理器** 。哲学是：一颗可编程芯片，几千个线程，由宿主机 CPU 编排，通过 **CUDA** 暴露出来，就是跑 **可并行负载** 的机器。每一代都在可编程 **Streaming Multiprocessor（SM）** 上增加加速原语，编程模型不动。同一颗芯片训练 Transformer、做推理、渲染图形、跑科学仿真（ **加速计算** ）。

### 发展

### 架构

一颗 NVIDIA GPU 是： **吞吐导向的核 + 喂饱它们的深内存层次 + 刚好够用的调度芯片，让几千个线程同时在飞** 。核就是 SM：V100 80、A100 108、H100 132、B200 148、B300 160、Rubin 224。

每个 SM 配方一样：四个 **SM 子分区** ，各自有 warp 调度器、发射单元、16k×32-bit 寄存器堆、标量 CUDA Core 通道、超越函数 SFU，以及通往 Tensor Core 的私有端口。四个分区共享一块 L1/共享内存，以及 TMA。线程按 32 个一捆组成 **warp** ，SIMT 锁步执行；每个分区驻留几十个 warp，调度器靠切换藏访存/算术停顿。

#### 计算

这些核在小矩阵块上做融合乘加：

完整 matmul 被切成输出块：要产出一块输出，kernel 沿共享内维 K 走，从左矩阵抽一行条带 A、从右矩阵抽一列条带 B，把部分积折进累加器。C 是目前的部分和，D 是带入下一步的更新值。内环走完，D 就是完整输出矩阵的一块；整次 matmul 由许多次这样的块 MMA 拼起来。

块形状写成 **M × N × K** 。是输出块大小，K 是一条指令一次收缩的内维长度；剩下的 K 轴由 kernel 内环走完。累加器在这段循环里是黏的：这次 MMA 的 D 变成下次的 C，所以方程其实是原地乘加

直到 K 轴走完。

图7分块 MMA 沿 K 轴折叠

图7 每次发射收缩一段 K，D 写回后变成下一次的 C。

V100 第一代（每 SM 8 个）是 warp 级 16×16×16 FP16 MMA。A100 第三代加上 TF32、BF16、FP64 matmul 和 2:4 结构化稀疏。H100 第四代加上原生 FP8，并把抽象从 warp 抬到 **warp group** ：128 个线程协作，异步 `wgmma` ，形状 64×256×16，后台跑着，发射 warp 去装下一块。B200 第五代再往前： **双 SM MMA** 256×256×16，操作数拆到一对 SM 上，原生 FP4，每 SM 专设 256 KB **Tensor Memory（TMEM）** 放累加块，不再挤寄存器堆。Rubin 第六代继续抬 FP4，加上原生 FP6，配第三代 Transformer Engine，在硬件里做自适应 NVFP4 微块缩放，把每块量化元数据留在 Tensor Core 路径上，不绕 CUDA Core。

六代不变的是：matmul 仍活在 **线程/warp 层次** 里，但 **发射一条指令需要的线程数在变少** ，发射本身也和执行脱钩。

Volta 的 `mma.sync` 是 warp 集体、同步的：32 个线程一起执行，每条 lane 拿着 A、B **以及累加器 D** 的寄存器碎片，warp 阻塞到算完。Hopper 的 `wgmma.mma_async` 把发射者扩到 128 线程，B 放进共享内存描述符（A 可选寄存器或描述符）， **立刻返回** ：matmul 在后台跑，完成用 `wgmma.commit_group` / `wgmma.wait_group` 跟踪。

Blackwell 的 `tcgen05.mma` 走完这趟迁移： **A 也和 B 一样走共享内存描述符** （或直接从 TMEM 来），累加器 **D 落进 TMEM** 而不是寄存器堆。操作数都离开 lane 之后，没有需要协调的每线程状态，于是 **一条线程发射、立刻返回** ，完成由消费者 warp 等的 `mbarrier` 通知。CTA-pair 变体把同一模型扩到两颗 SM：配对 cluster 里每颗 SM 各有一条线程发协调 MMA，拼出 256×256×16 的双 SM 块。

matmul 变大了，对发射线程却变轻了：从 32 条 lane 锁步，变成一条描述符驱动的命令——仍从 warp 模型里发出，不再由 warp 执行。

这种脱钩，才让 Transformer 注意力 kernel 在 GPU 上高效。warp 可以在 matmul 飞行时跑 softmax、加 mask、预取下一块；matmul 与周围逐元素工作重叠，就是现代注意力 kernel（FlashAttention-3、FA4）的结构。前提是：矩阵指令 **不阻塞 warp** 。

#### 内存

片上层次是 **每一级都有硬件管理的 cache，再叠软件提示** 。片外是 **HBM** ：V100 32 GB HBM2，H100 80 GB HBM3，B200 192 GB HBM3e，B300 288 GB，Rubin 288 GB HBM4。芯片级 **L2** 夹在 HBM 和 SM 之间：V100 6 MB，A100 40 MB，H100 50 MB，B200 60 MB（两颗 die 上各 30 MB，可把热块cache在近端 die）。每个 SM 里 256 KB 统一 **L1/SMEM** ，kernel 启动时在硬件 L1 和程序员暂存之间分区。寄存器堆大约再 256 KB / SM，四份切开。

Blackwell 加了第五层： **TMEM** ，每 SM 256 KB，只给 Tensor Core 寻址，把操作数驻留压力从通用寄存器堆里抽走。

#### Warp 特化

Hopper 时代的编程习语是 **warp 特化** ：一个 block 里，一部分 warp 当 **生产者** ，连续发 TMA load；另一部分当 **消费者** ，对新到的块发 `wgmma` 。同步不再是整 SM 的 `__syncthreads()` ，而是共享内存里的 `mbarrier` ，以及挂在 TMA 完成上的异步事务屏障。现代注意力 kernel（FlashAttention-3、 **CUTLASS** ping-pong GEMM、Blackwell FA4）是同一套思路：TMA 驱动的生产者管道，经 SMEM 和 TMEM 喂给 wgmma 消费者，再用 **thread-block cluster** （Hopper+）把多颗 SM 绑成一个协作计算单元，Blackwell 的双 SM MMA 自然叠上去。

#### 数值

FP32 是历史默认；Volta 带来 **FP16** （FP32 累加）和可训练的 loss scaling；Ampere 加上 **TF32** 、 **BF16** 和 2:4 **结构化稀疏** 。Hopper 引入原生 **FP8** （E4M3 / E5M2），配 **Transformer Engine** 按层自动缩放激活。Blackwell 再砍一半到 **FP4** ，并带上微缩放 MX 格式（块级共享指数），配第二代 Transformer Engine。Rubin 第三代加上 **NVFP4** 和原生 **FP6** 。芯片布局本身也进入拼数值增长阶段：B100/B200/B300 是两颗已经顶到光刻上限的硅片，用约 **10 TB/s** 的 **NV-HBI** 连在一起，对软件呈现为一颗逻辑 GPU，封装上 8 堆 HBM；Rubin 把 chiplet 扩到双 die、约 3360 亿晶体管、8 堆 HBM4。每一代大致用 **位数减半 + 更细缩放** 提升 2× 每瓦吞吐，并且越来越多地把更多硅键合进同一封装。

#### 五条路径

1. 1. **可编程性。** 负载是变化（注意力变体、新模型），所以每一块都保持可编程，让开发者写 CUDA。专用单元也通过这个模型暴露，而不是做成固定功能块。
2. 2. **用海量多线程藏延迟。** 延迟不可预测、数据相关，所以不用静态调度，而用线程过提交——每 SM 最多 64 个驻留 warp，硬件调度器每周期挑一个就绪的。
3. 3. **包在 warp 里的 matmul。** 矩阵单元是吞吐主体，但必须活在同一套 warp/线程抽象后面： `mma.sync` -> `wgmma` -> `tcgen05.mma` 。这样单 kernel 就能把 matmul、softmax、逐元素算一次融完。
4. 4. **异步内存层次。** 层次显式、程序员管理，而不是编译器对已知延迟暂存做静态调度。留下 L2，但把 SMEM、TMEM 做成具名暂存，再叠 TMA、TMEM、 `mbarrier` 。
5. 5. **摊销 SIMT 的额外成本。** 花在 warp 调度器、寄存器堆、相干 cache 上的晶体管，就不是 MAC。接受这笔成本，再用更大的 Tensor Core 和 TMEM 把它摊薄。

### 扩规模

两种体制： **scale-up** 和 **scale-out** 。

AI 基础设施两套都用：非常占带宽的集合通信（张量并行、MoE expert 路由）留在 scale-up 域里；数据并行和流水并行穿过 scale-out 网络。

#### Scale-up

Rubin 分两步。 **NVL144** （2026）仍在 Oberon 级机柜里：72 个 Rubin 封装，按 NVIDIA 新的 die 计数口径叫 144 GPU。真正的机柜跃迁是 2027 的 Rubin Ultra： **NVL576** 把 144 个四 die Rubin Ultra 封装装进新的 **Kyber** 机箱，一个相干域里 576 个 GPU die。

图11NVL72 机柜

图11 NVL72。72 颗 Blackwell GPU 坐在一排 NVSwitch ASIC 下面，构成非阻塞交叉开关；整张网络走无源铜背板：约 5184 根盲插电缆，约 130 TB/s 全互连。

这种密度靠 **无源铜** 撑住。NVL72 的 NVLink 网络经背板盲插 5184 根电缆（每柜约 2 英里线，线内无 retimer，SerDes 活在 GPU 和交换机 ASIC 上），72 颗 GPU 之间约 130 TB/s 全互连。NVIDIA 估计，相对每条链路都插光模块的方案，铜大约省 **20 kW / 柜** 。两米以内，铜在功耗、成本和每美元信号完整性上仍赢；再远，比特必须上玻璃。

NVL144 仍在 Oberon 里，封装数还是 72，线不用加长，只要 Gen 6 SerDes 传得更快。Rubin Ultra 的 NVL576 用把机柜做高一倍的 Kyber，把 576 个 GPU die 收进一个机箱，让每条 NVLink 路径仍落在无源铜够得着的距离里。

#### Scale-out

图12DGX SuperPOD

图12 DGX SuperPOD。8 个 NVL72（共 576 GPU）坐在 Quantum-X800 InfiniBand 脊下。每 GPU 的 scale-out 是 ConnectX-8、800 Gbps；跨柜走 OSFP-RHS 可插拔光模块，n微秒延迟。

每颗 GPU 自己有一张 ConnectX 网卡互联进这张网络。Blackwell 节点是 ConnectX-8、每 GPU 800 Gbps，比每 GPU 的 NVLink 低一个数量级，延迟从纳秒提高到微秒。Rubin 换成 ConnectX-9、每 GPU 1.6 Tbps。BlueField DPU，用 ARM 核把存储、网络、安全从宿主机 CPU 卸下来。更喜欢以太网的客户，走无损以太 Spectrum-X。

铜到玻璃的边界在 **机柜** 。NVL72 内部网络是铜；800 Gbps 一旦要跨柜，就是光。无源铜 DAC 在 200 G/lane 大约只能跑 1.5–2 米，跨柜不行。SuperPOD 还是通过 OSFP-RHS 可插拔光模块互联：每个模块自带激光器、调制器、光电探测器和 DSP。扇出到几千颗 GPU 的脊，几万个可插拔模块，激光器就要抽几十千瓦。

**Quantum-X Photonics** （IB）和 **Spectrum-X Photonics** （以太）用共封装光学替换可插拔：激光器、调制器、探测器经 TSMC COUPE 键到交换机封装上。NVIDIA 称激光器约少 4×，链路功耗约低 3.5×。

**NVLink Fusion** 最近把 scale-up 网络本身打开了：第三方 CPU 和 XPU 可以加入 NVLink 域，超大规模可以围着 NVIDIA 互连做半定制机柜，不用从零设计自己的Fabric网络。

### 软件

CUDA 是大规模并行处理器的自然编程模型。写一个 kernel（每条线程执行一次的同一段代码），再把它发射到按 block 和 warp 组织的几千条线程上；程序决定共享什么、何时同步、每条线程扛问题的哪一块。

这种连续性是英伟达的护城河，也可能是约束。每一代都把新硬件（Tensor Core、TMA、TMEM）接到同一套 kernel-and-warps 模型上，通过 PTX / SASS 暴露： `mma.sync` 、 `wgmma.mma_async` 等等。NVIDIA 不能彻底重构了,因为软硬件依赖太庞大了。

PTX 之上是我们直接调用的cuBLAS / cuDNN；GEMM 可以直接调用模板-> C++ 的 CUTLASS；TensorRT-LLM 做分页注意力、飞行中批处理、投机解码；框架绑定走 PyTorch、Triton、JAX。

FlashAttention 是现代 AI 里最重要的算法改写之一：把注意力分块，避免物化矩阵。四代（FA1–FA4）各自为最新 NVIDIA 芯片手调（FA3 对 Hopper 异步管道，FA4 对 Blackwell），移植到其他硬件要落后几年。

## Google TPU

TPU 是一台 **矩阵乘法机器** 。让 **XLA 编译器** 提前编译固定好每一个周期、每一字节内存。没有硬件调度器，没有 cache，没有线程/warp。大集群是通过ICI互联几千颗芯片。TPU 主要服务Google 自己的负载（搜索、翻译、推荐、Gemini）。

### 发展

### 架构

一颗 TPU 芯片是一台 matmul 引擎。计算单元是 **TensorCore** ：v2 起旗舰每封装两颗；能效款（v4i、v5e、v6e）一颗。每个 TensorCore 五件套：一个或多个做矩阵的 **MXU** 、做逐元素的 **VPU** 、当指挥的 **Scalar Unit** 、做跨 lane 规约的 **XLU** 、外加 Transpose/Permute，以及喂进/排出 MXU 的累加队列。v4 起每颗芯片还在 TensorCore 旁边加了专用的 **SparseCore** （v4 / v5p / Ironwood 每芯片 4 个，Trillium 2 个），用来做脉动阵列不擅长的 embedding 查表，下文单独说明。所有块处于 VLIW 发射平面上， **Core Sequencer** 每周期填满 322-bit 包的八个功能槽。没有 I-cache miss，没有 warp 调度器，没有乱序引擎，没有分支预测,编译器就是调度器。

#### TensorCore

MXU 就是脉动阵。v1 一颗 256×256 INT8 推理阵；v2 第一次能训练，改成 128×128 格，BF16 乘、FP32 累加（INT8 从 v4 起以同等吞吐回到 MXU）。每 TensorCore 的阵数：v2 的 1 -> v3 的 2 -> v4/v5e/v5p 的 4。Trillium 回到 256×256（每周期每阵 65536 个 MAC），Ironwood、8t、8i 都是这个形状。

算时，矩阵 B 的值预装进每个格子一权： **权值驻留（weight-stationary）** 。激活从左缘进入，每周期推进一列，在每个格子与驻留权相乘，部分和向下流入底部累加队列。数据一旦进入阵列，计算过程中就不必再去读内存：每个权重会被所有经过它的激活反复用到，每个激活沿这一行也会被用 128 次（更大的阵是 256 次）。代价是：如果在 256×256 的阵上只跑 128×128 的矩阵乘，大约四分之三的格子在空转，所以 XLA 会把矩阵边长补齐或切成 128 的倍数（v6e 以后是 256 的倍数）。

图15TPU 权值驻留脉动阵

图15 B 预先铺进格子；A 从左沿列前进，部分和向下流入累加队列。

每颗 TPU 是一台 **2D 向量机** ，不是 1D SIMD。VPU 寄存器堆拿的是 2D VREG。v4/v5p 形状是 `(8, 128)` ：128 lane 宽、8 sublane 深。lane 轴对齐脉动阵输入宽度。现代 TPU 程序的大部分加速，来自 VPU/MXU 重叠：量化、layernorm、softmax、激活、bias-add 都在 VPU 上跑，同一周期 MXU 在后面跑 matmul。跨 lane 规约交给 XLU：慢、贵，是已知的编译器热点。和 2D 形状对不齐的布局变换，由 Transpose/Permute做。

#### 内存

片上内存层次和计算侧同一思路： **没有 cache，每一级都是软件管理** 。片外是 HBM（v2/v5e 16 GB，v3/v4/v6e 32 GB，v5p 95 GB，Ironwood 192 GB，v8 代 216–288 GB）。片上是手工叠的scratchpad。离计算最近的是 **VMEM** ，喂 VPU 和 MXU 输入队列：v4 32 MiB，v5e 128 MiB，推理向的 v8i 拉到 384 MiB，就是为了把整份 KV Cache 留在片上。上面是 v4 引入的 **CMEM** （128 MiB）：HBM 与 VMEM 之间更慢、更大的 SRAM 暂存，吸收融合算子中间结果。每个张量在编译期放在某一层；XLA 的 buffer-assignment 调度跨层 DMA，让数据刚好在消费周期前到达。

#### SparseCore

推荐、排序这类模型要经常做 **embedding 查表** ：用户 ID、商品 ID 是一个编号，模型里有一张非常大的表，每个编号对应一行向量。表可以有几十亿行，一次请求真正用到的只有很少几行，而且是哪几行要等请求来了才知道。于是内存访问变成东抽一条、西抽一条，不是整块连续读。

TPU 的主计算是 256×256 的脉动阵列，擅长大块、整齐的矩阵乘法。embedding 查表不是这种活：索引不规则，抽出来的几条向量往往还要再加总。硬塞给脉动阵列，大部分格子会空转。

所以从 TPU v4 起，芯片在 TensorCore 旁边加了 **SparseCore** 。它不做大矩阵乘，专门做三件事：按编号从高带宽内存里把需要的行取出来（gather）、按编号把结果写回去（scatter）、把同一条请求相关的几条向量加总。如果这张大表被切开存在很多芯片上，芯片之间因此要交换的数据，也由 SparseCore 处理。

一块 SparseCore 里大约有 16 个计算小块，各自带一块专用暂存 SRAM，并且有自己连到高带宽内存的通道，不跟 TensorCore 抢同一条内存通路。查表和密集矩阵乘可以同时进行。面积和功耗大约只占芯片的 5%，但 embedding 很重的模型能快 5 到 7 倍。

面向推理的 TPU v8i（Zebrafish）主矛盾不再是 embedding 查表，而是解码时芯片之间的集合通信。所以 v8i 拿掉 SparseCore，在 I/O 小芯片上换成 **CAE（集合通信加速引擎）** ，专做 all-reduce 这类规约。换的是加速对象，思路一样：主计算阵列不擅长的事情，单独用一小块硬件做。

#### 数值

v1 只有 INT8 推理；v2 把规范训练格式换成 **BF16** （和 FP32 一样的动态范围，一半内存，不用 loss scaling）。v4 重新引入原生 INT8。Ironwood 加上原生 FP8（E4M3 / E5M2），同面积约 2× BF16 吞吐。v8 加上原生 FP4，以及 MXU 内部的块缩放乘法，删掉 Ironwood 的 VPU 反量化开销。现代 TensorCore 都有硬件 **随机舍入** ：用低位尾数当概率做舍入，在长训练里保住低精度累加的期望值。

芯片边界是 ICI （2D torus 的 v2/v3/v5e/v6e 是 4 口，3D torus 旗舰 v4/v5p/v7/8t 是 6 口），以及 scale-out 的 DCN NIC。ICI 口看起来只是 Core Sequencer 能在 VLIW 包里瞄准的又一套 DMA：远程张量发送和 VMEM->HBM 传输是同一类指令，编译器把集合通信作为调度的一部分。

#### 五个路径

1. 1. **脉动阵列。** matmul 统治负载，芯片面积在脉动阵上。
2. 2. **软件暂存。** 计算便宜、内存贵，在阵列中复用数据，用软件管理暂存替换 cache。
3. 3. **编译器调度。** 负载静态可预测，编译器调度：VLIW 发射，无推测，无乱序，无动态调度器。
4. 4. **只留 MAC 面积。** 功耗比峰值重要，删掉不必要的子模块：cache tag、分支预测、重排序缓冲。
5. 5. **阵列旁边的专用引擎。** 密集矩阵乘阵列做不好 embedding 查表和集合通信，所以另外做了 SparseCore 和 CAE。

### 增加规模

Google 的 **ICI 是消息传递** 。没有远程 load 语义。每次多芯片操作都是 XLA 编出来的显式集合通信。scale-up 域是用 **torus** ，并在机柜边界用 **光电路交换机** 。

#### Scale-up

ICI 链路直接从 TPU die 出来：高速串行 lane，64 芯片 Cube（一个液冷柜里的 4×4×4）内部是铜线直连，Cube 之间走光。每芯片聚合 ICI 带宽从 v2 约 250 GB/s，到 Ironwood 双向 1.2 TB/s，v8t 再 2×。能效款 2D torus（v2、v3、v5e、v6e），旗舰 3D torus（v4、v5p、v7、v8t）。

**Palomar OCS** 是位于 Cube 之间的 3D-MEMS 光电路交换机。微小镜子物理旋转，把任意输入光纤映射到任意输出。v4 superpod 用 48 台 Palomar 把 64 个 Cube（4096 芯片）组成一个 3D torus；v5p 和 Ironwood 按同一方案放大。OCS 是电路交换,任务开始时选好拓扑，跑一周，再为下一类负载重配。按负载重配拓扑、按需切 sub-pod、容错。

**superpod** 是TPU的 scale-up 单位,和NVIDIA 的 NVL72是等价的，规模大两个数量级。v4 是 4096 芯片；v5p 8960；Ironwood（TPU v7）是 9216 芯片，144 个 64 芯片 Cube，提供 1.77 PB HBM（约 68 PB/s）和 42.5 ExaFLOPS FP8。

图16TPU Ironwood superpod

图16 TPU Ironwood superpod。左：一个 64 芯片 Cube（4×4×4）三维环面。右：144 个 Cube 经 Palomar 光电路交换机连成一个 ICI 域。

TPU 8t（Sunfish）可以达到 9600 芯片、2 PB HBM（约 62 PB/s）、121 ExaFLOPS FP4。TPU 8i（Zebrafish）是 1024 芯片、约 295 TB HBM（8.8 PB/s）、约 10 ExaFLOPS FP4。8i 用新的分层高基数拓扑 **Boardfly** 替换 torus（4 芯片环 ->8 板组 ->最多 36 组经 OCS 相连），把 all-to-all 延迟砍半。为 MoE 推理设计的3D torus 擅长最近邻集合通信（ring all-reduce 每周期用满每条链路），MoE expert 路由是all-to-all模型。1024 芯片 3D torus 直径 16 跳；Boardfly 可以降低到 7跳。

#### Scale-out

TPU v7，scale-out 跑在一张网络上： **Jupiter** ，Apollo OCS，和 Palomar 同一家 3D-MEMS，只是铺到整栋楼。Google 从机柜到数据中心脊交换机用的是同一种原语（光电路交换）。

到了 TPU 8t，scale-out 拆成两张网络。东西向 TPU–TPU 流量搬到 **Virgo** ，专用加速器网络；Jupiter 用于南北向：存储、通用计算、跨站点。Virgo 是平坦两层非阻塞，高基数交换机：任何 TPU 到任何其他最多两跳。一个 Virgo 集群能连超过 13.4 万颗 TPU 8t。把这张网络从中间对半切开，切开面两侧之间的互连带宽合计 47 Pb/s（相对上一代数据中心网络，每芯片带宽大约 4 倍，空载延迟低约 40%）。好处是：柜内互连、加速器之间的横向网络、以及存储和通用计算那张网，可以按各自的节奏升级，不用每次一起重布线。

图17TPU 8t 向外扩展

图17 TPU 8t 的向外扩展。东西向走 Virgo：两层、任意两颗 TPU 最多两跳（超过 13.4 万颗 TPU，对半切开时切开面两侧合计 47 Pb/s）。南北向——存储、通用计算、跨机房——仍走 Jupiter；2022 年起脊柱已经经 Apollo 光电路交换机做成全光。

每芯片 scale-out 带宽 Ironwood 大约 100 Gbps 量级，v8t 4×，但仍比每芯片 ICI 低两个数量级。这条带宽差距决定了怎么切分：张量并行和 MoE expert 路由留在 ICI；数据并行和流水并行穿过 scale-out。

#### Multislice

一个 **slice** 是一组用芯片间互连（ICI）连在一起的 TPU，也是云上一次能整块预约的训练单元。过去一份训练作业只能跑在一个 slice 里，规模被这个 slice 能装下多少芯片卡住。以 Cloud TPU v4 为例，单个 slice 最大大约三千多颗，再大就装不进去。

**Multislice** 让一份作业同时用多个 slice。同一个 slice 里面，芯片之间仍走很快的 ICI；不同 slice 之间走数据中心网络（Google 这边是 Jupiter，TPU 8t 的加速器横向流量则走 Virgo）。开发者不用自己写跨 slice 的通信代码。XLA 看到这张「快互连 + 慢网络」的混合拓扑后，会自动生成分层的集合通信：slice 内部先做一轮规约（常见是环形 all-reduce），slice 之间再在数据中心网络上做第二层规约。通信可以和计算重叠。

跨 slice 的网络比 ICI 慢一个数量级以上，所以 Google 的建议很具体：slice 之间主要做数据并行，或者把参数切开的 FSDP；不要把张量并行的激活切开、再跨 slice 传来传去。从 2 个 slice 扩到两千个 slice，主要是改分片轴，而不是重写模型。

#### Pathways

Multislice 解决的是「编译器怎么把一份程序铺到多个 slice 上」。上面还要有人真正把作业跑起来，这就是 **Pathways** 。

常见的 GPU 训练栈是多控制器：每个节点一个进程，NCCL 做通信，Slurm 做排队，Megatron 一类框架把模型切开。大家各自启动，再商量着对齐。Pathways 是单控制器：一个 JAX 客户端就能调度整份作业，把很多各自有 ICI 域的 TPU pod 看成一块可用的加速器池。

它主要做三件事。

第一，成组调度。TPU 一次只跑一个不能被中途打断的内核。如果几颗芯片要一起做集合通信，指令必须按同一顺序下发，否则会死锁。Pathways 在每一组加速器里放一个集中调度器，保证这个顺序。

第二，弹性训练。某个 slice 挂了，光电路交换机可以改接线。Pathways 从上一检查点出发，按新的芯片数量把作业拉起来，不必整份作业从头再来。

第三，跨机房编排。Gemini Ultra 是第一批跨多个数据中心训练的前沿模型。Pathways 支持把需要同步的 SPMD 作业（同一份程序、数据切开后在很多芯片上同时跑）铺到多个机房。

编译器负责把程序排进每一拍，环面负责芯片怎么连，光交换机负责机柜到机房都能改接线。Pathways 负责在这套硬件上把作业真正跑起来。

### 软件

TPU 栈是 **编译器驱动** ，CUDA 是 **kernel 驱动** 。TPU 上开发者用 JAX 写数值程序，XLA 负责下面的一切：哪些算子融合、每个张量住哪、如何在 2D 向量寄存器上铺、HBM->VMEM 的 DMA 何时发、322-bit VLIW 包怎么排、程序如何在几千颗芯片上分片。没有 warp 调度器、没有 cache、没有乱序引擎在运行时把排错的指令再纠正一遍。编译器就是系统。XLA 能在不手调的情况下更接近理论上限。

编译路径是 JAX ->JAXpr ->StableHLO ->HLO ->LLO ->VLIW 包。程序每周期在同一包里重叠 MXU 脉动执行、VPU 逐元素、以及 HBM<->VMEM DMA。

多芯片执行是 **SPMD** ：一份程序、数据分片、分层集合通信，由 GSPMD 发出（2026 年初默认换成 MLIR 原生的 **Shardy** ）。用户用 Mesh + PartitionSpec 在少数关键张量上声明式写分片；编译器把分片传到图的其余部分，并在布局变化的地方插入 all-reduce / all-gather / reduce-scatter。编译器选错集合通信时， `shard_map` 让用户手工调 SPMD，组合在 `jit` 里。

JAX 的写 kernel 语言，是 TPU 上的 Triton。Pallas kernel 用 JAX 味的 Python 写，经 Mosaic 降到 LLO，再作为自定义算子嵌回 HLO。它存在，是因为 XLA 并不总能给新注意力变体、融合 MoE dispatch、或任何需要手工 VMEM 分块和 DMA 调度的东西合成最优的,像FlashAttention 那一类，赢在调度。

TPU 生态是 **中心化** 的，不是分布式的。都是 Google 自己开源（XLA、JAX、Flax、Optax、Pallas、MaxText、Pathways、Shardy、Mosaic），和自己的芯片演进。

## AMD GPU

AMD Instinct GPU 和 NVIDIA 不同：NVIDIA 每一代都在扩大每颗 SM 能做的事；AMD 从 GCN（2012）起一直采用 **Compute Unit（CU）** ,2021 年起每一代 HBM 容量都追平或超过同期 NVIDIA 旗舰；第一颗 3D 堆叠数据中心 GPU（CDNA 3）；第一颗相干 CPU+GPU APU（MI300A）；以及开放生态（ROCm、HIP、OCP MX、UALink）。

### 架构

AMD 的架构重点在 CU **之间** ,把多颗 CU 键进一个封装。CU 本身相对保守,四个 16-lane SIMD、一个共享标量单元、64 KB LDS、L1 向量 cache、每 SIMD 一份 VGPR，外加（CDNA 1 起）跑 MFMA 的 Matrix Core。形状从 2012 年 GCN 起没有实质变化；变的是数量（MI100 120 CU，MI250X 220，MI300X 304，MI355X 256）和把它们键合在一起的封装。64 线程的 wavefront 用 4 个周期流过 16 条 SIMD lane。

#### 计算

NVIDIA 的 Tensor Core 沿线程层次往上是Volta 32 线程 warp，Hopper 128 线程 warp-group，Blackwell 单线程加可选双 SM cluster。AMD 的 Matrix Core 原地不动。从 2020 的 MI100 到 2025 的 MI355X，每一代 MFMA 都是 **wavefront 作用域** ,一个 wave64 发一条矩阵指令（ `V_MFMA_` ），四个 SIMD 协作驱动，操作数来自 wavefront 寄存器堆。指令更快了，格式集更宽了，发射者和作用域没有动。

CDNA 1（2020）FP32 / FP16 / BF16 / INT8 为每 CU 每周期 256 / 1024 / 512 / 1024 FLOP。CDNA 2 把 FP64 路径加倍到满速率矩阵 256 FLOP/CU/周期。CDNA 3 在 FP8 上和 H100 持平（4096 FLOP），加上 2:4 结构化稀疏。CDNA 4 再到 FP4 的 16384 FLOP 和带 OCP MX 块缩放的 FP6，一条 MFMA 里 A/B 精度可混（例如 FP8 × FP4）。

**发散。** 半空的 wave64 浪费 32 条 lane，半空的 warp32 只浪费 16。

**重叠。** NVIDIA 异步、描述符驱动的 matmul 把发射和执行脱钩,发射线程开火就走，Tensor Core 后台跑，warp 可以同时做 softmax、mask、预取。AMD 的 wavefront 集体 MFMA不行,发出 matmul 的同一个 wave，不能在挂起时经过调度做向量工作。overlap 只能跨不同 wavefront，用显式 wavefront 屏障在软件里搭，更占 wave 槽和寄存器。

纯稠密 GEMM（大批训练内环）在 matmul 期间没什么有用的事可做，两边都能喂饱。这些正好是 AMD 在超算 HPC 历史上领先的负载（Frontier 上的 MI250X，El Capitan 上的 MI300A）。Transformer 注意力（FlashAttention-3、FA4）把 matmul 和 softmax、mask、KV 读交错，特征是异步重叠。AMD 必须手工搭建这个管道，但是NVIDIA 是硬件级支持的。

#### 内存

AMD 的内存层次通用层比 NVIDIA 少，但有一个巨大 cache。从 CU 往外：64 KB LDS（软件管理，32 bank，对标 SMEM），向量 L1（早期 CDNA 16 KB，MI300X 起 32 KB），每 XCD 几 MB 的 L2。

**Infinity Cache** 有巨大的cache,MI300X 上 256 MB，分布在四颗 IOD 上，16 路组相联，大概12 TB/s，超过 MI300X 5.3 TB/s HBM3 的两倍。它起源于 RDNA 游戏 GPU，用来补偿 GDDR 总线；AMD 在 CDNA 3 上把这套 IP 复用到 AI,注意力 KV 复用和权重复用。

片外 HBM 容量跟随HBM演进持续增长：MI100 / MI210 / MI250X / MI300X / MI325X / MI350X 一路 32 ->64 ->128 ->192 ->256 ->288 GB，2021 年起每一代都追平或超过同期 NVIDIA 旗舰。

#### Chiplet

Chiplet 的意思是：不再把所有功能刻在一块巨大的硅片上，而是拆成多颗较小的芯片，再在同一个封装里叠起来、连起来。AMD Instinct 从 CDNA 2 开始走这条路，CDNA 3 起这是架构重点。

CDNA 1 的 MI100 还是 7 纳米单片。CDNA 2 的 MI250X 第一次用两颗计算芯并排放在基板上，封装里用 4 条 Infinity Fabric 相连，合计 400 GB/s。但对软件来说，这仍是两颗独立 GPU，程序要自己看见两张卡。

CDNA 3（MI300X）把封装做成上下两层：

- • 上面是 8 颗计算芯 **XCD** （Accelerator Complex Die，加速器复合芯），台积电 N5，每颗大约 115 mm²，Compute Unit 就在这里。
- • 下面是 4 颗 I/O 底芯 **IOD** （I/O Die），台积电 N6。底芯不做矩阵乘，负责三件事：末级 Infinity Cache、HBM 内存接口、以及 Infinity Fabric 和 PCIe。
- • 每颗底芯头顶两颗计算芯，旁边接两堆 HBM。计算芯用台积电 SoIC 混合键合垂直焊在底芯上：硅通孔间距到亚微米，中间没有焊球。

四颗底芯之间再用 **Infinity Fabric AP** （封装内部把多颗底芯连在一起的高速总线）连成一块。把整个封装从中间对半切开，切开面两侧之间的互连带宽合计 4.8 TB/s。整颗封装大约 1530 亿个晶体管。跑在上面的程序看到的是一颗 GPU，不用自己去管数据在哪颗计算芯、哪颗底芯上。

NVIDIA 到 H100 仍是单片；B200 才用 2.5D 把两颗已经顶到光刻上限的硅片拼在一起。AMD 早一代就做到 3D 堆叠，而且每一颗小芯片面积更小，良率更好做。

CDNA 4 的 MI355X 上，8 颗计算芯仍垂直焊在底芯上，但计算芯改台积电 N3P，每颗 32 个活动 CU，一共 256 个（MI300X 是 304）。每颗计算芯上 CU 变少，是为了把 Matrix Core 做大，并把本地共享内存 LDS 做到 160 KB。底芯从四颗收成两颗，每颗在 N6 上做得更宽：一颗底芯上面四颗计算芯、旁边四堆 HBM3E。两颗底芯之间仍用 Infinity Fabric AP 相连；把封装对半切开，切开面两侧合计 5.5 TB/s。封装一共大约 1850 亿个晶体管，对程序来说仍然是一颗 GPU。

#### 五个路径

1. 1. **先 HPC，再 AI。** CDNA 2 到 CDNA 3 出满速率 FP64 矩阵，到 CDNA 4 明确推理场景。
2. 2. **内存容量。** 2021 年起每一代 HBM 追平或超过同期 NVIDIA 旗舰，再加 256 MB 末级 Infinity Cache。
3. 3. **早走 3D 堆叠。** 2023 年就用 TSMC SoIC 把计算堆到 cache 和 I/O 上。
4. 4. **相干 CPU+GPU。** MI300A 是出过货的最激进 chiplet 产品，在El Capitan 证明过。
5. 5. **开放 scale-up 互联网络。** UALink 和 OCP MX，对 NVLink 和私有 FP4。

### 扩规模

8 颗 MI300X 有 1.5 TB HBM，8 颗 MI350X 有 2.3 TB，一个 8 GPU 盒子就能放下 FP8 的 405B 模型（权重、KV、长上下文和更大 batch 的余量）；同一模型在 8×H100（640 GB）上必须仔细分片。2024–2025 的推理，AMD 的 scale-up 不必在机柜上追 NVL72，在盒子上就有竞争力。前沿训练不行。AMD 直到 2026 才有可能赶上。

到 MI355X，AMD 的 scale-up 是 8 GPU OAM 平台上的 Infinity Fabric。每颗 MI300X 7 条 IF 链路（盒内每个对等一条），双向 128 GB/s，全互连 mesh 每 GPU 896 GB/s。MI350X 把每条链路提高到 153.6 GB/s（约 1075 GB/s / GPU），形状仍是 8 GPU。平台符合 OCP UBB 2.0,和 NVIDIA HGX 同一机械插座，服务器厂商可以在同一机箱上出 AMD 或 NVIDIA。

MI355X 之前 AMD 没出过 NVL72 的机柜级等价物。更大模型在 MI300X 集群上跨多个 8 GPU 盒子走以太。

Helios 是 AMD 第一个机柜级 scale-up 域，2026 下半年随 MI455X 出货。每柜 72 GPU，约 31 TB HBM4，1.4 PB/s 聚合 HBM 带宽，2.9 ExaFLOPS FP4 / 1.4 ExaFLOPS FP8，260 TB/s scale-up，43 TB/s scale-out。形态是 **Open Rack Wide（ORW）** （Meta 2025 年提交 OCP 的双宽液冷），不是 AMD 私有机箱。任何已经标准化 ORW 的超大规模，部署 Helios 不用定制机房。

网络是 **UALink** , Ultra Accelerator Link，AMD 和 Apple、AWS、Cisco、Google、HPE、Intel、Meta、Microsoft、Synopsys 搞的开放联盟标准。UALink 200G 1.0（2025 年 4 月）定义 200 GT/s lane、每向 800 Gbps，交换拓扑可扩到每 pod 1024 个加速器。一套与 NVLink 相当的缓存互连域。

原生 UALink 交换芯片要到 2027 年才上量。Helios 上市用 **UALoE** （Infinity Fabric 隧道过标准以太）顶着，保住编程模型，等原生 UALink 网络。上市时的 Helios，更接近快速以太隧道集群，而不是 NVL72 那种真正的缓存相干 NVLink 域。

#### Scale-out

AMD 不出 InfiniBand。整套 scale-out 是以太，用另一套开放标准： **Ultra Ethernet Consortium（UEC）** 。

UEC 1.0（2025 年 6 月）定义 **Ultra Ethernet Transport（UET）** ：标准以太上的新 RDMA 传输，带 packet spraying、基于 SACK 的选择重传、现代拥塞控制。UET 为 scale-out AI 网络重写的 RDMA 语义。网卡是 AMD 2022 年收购的 **Pensando** ,当前 AI 网卡是 Pollara 400（400 GbE）；Vulcano 800 2026 年随 MI455X 出货。交换机芯片不是 AMD 的。Helios 的 43 TB/s scale-out 走 Broadcom **Tomahawk 6** （102.4 Tbps，带共封装光学 “Davisson”）。AMD 没有自研 CPO，也没有自研交换机 ASIC；光学层是伙伴芯片。NVIDIA 整栈自有；AMD 自有一层（经 Pensando 的 NIC + DPU），开放标准加伙伴芯片能跑赢垂直整合。

行业在往 AMD 这边走。Dell'Oro 报 2025 年以太承载的 AI scale-out 网络量是 InfiniBand 的两倍以上；AWS、Microsoft、Meta、Oracle、xAI 都已在基于 AMD 的 AI 集群上标准化以太。Helios 能不能够快地补上与 NVL72 的机柜级差距?

### 软件

ROCm 是 CUDA 的开源对位。NVIDIA 栈专有、垂直整合（cuBLAS、cuDNN、TensorRT-LLM 以二进制 blob 出货，只由 NVIDIA 维护）；ROCm 原生在 GitHub 上，走开放标准（PyTorch、Triton、vLLM、OCP MX）。开源与闭源竞争。

栈底是 **HIP** ，AMD 的 CUDA 兼容 C++ 运行时。 `hipify` 自动把 CUDA 源译成 HIP。HPC 代码开箱 80–95% 能移植。AI kernel 有差距：相对成熟的 Hopper/Blackwell 专用原语（TMA 描述符、 `wgmma` 、 `tcgen05.mma` ）的东西，没有比较完善的 ROCm 可以对位，必须手写。

对标NVIDIA的库,AMD有：rocBLAS、hipBLASLt、MIOpen、RCCL、Composable Kernel（以及 ck-tile DSL）、rocprof 家族。AMD 主要做的框架是 **vLLM** 开源服务引擎，并做专用算子（AITER）。

PyTorch 路径是一等的。Eager-mode PyTorch 从 2018 年就能在 ROCm 上跑； `torch.compile` 经 Triton 下降，Triton 的 ROCm 后端在上游。没有 XLA 式中间 IR；ROCm 直接编到 HIP / Triton / CK。随着 Triton 成为 PyTorch 默认 kernel 路径，移植成本大幅度降低：经 `torch.compile` 跑的 kernel，CUDA 和 ROCm 不用改源。Triton 的 Python DSL 成为跨厂商通预言。

独立基准（Phoronix，2026 年 3 月）把 ROCm 7.2 放在标准 PyTorch / vLLM / SGLang 负载上比等价 CUDA 慢 10–25%，同等精度、等价芯片。ROCm 7 到了功能持平，不是性能持平。FlashAttention-4 这条尾巴（用上 Blackwell 最新硬件原语的研究代码）是 NVIDIA 护城河最硬的地方。

## Cerebras WSE

Cerebras 认为 **内存墙是晶圆切割的后果** 。晶圆厂在 300 mm 晶圆上印几十颗 die，再切割开；工业界随后把最奇特的工程（HBM、NVLink、CoWoS、每柜 5184 根铜缆）花在以片上带宽的一小零头把碎片再接回去。Cerebras 的 **晶圆级引擎** 是一块晶圆：84 个光刻场，46225 mm²，90 万个数据流核，片上每一字节内存都是离计算单元一个周期的 SRAM。

### 发展

### 架构

GPU 是层次化的调度, 线程在 warp 里，warp 在 SM 里，die 在封装里，封装在机柜里，每一道边界有自己的带宽、延迟、编程构造；从 die 拼起来的加速器都继承某种版本。WSE 是一个 **平坦平面** ：90 万个相同的核边对边铺成 2D mesh，没有共享 cache，没有全局内存，一颗核和另外 899999 颗之间没有任何边界。每颗核很小，WSE-2 上约 38000 µm²，大约一半 SRAM 一半逻辑，峰值 30 mW：48 kB 本地 SRAM，16 个通用寄存器，六级流水，4 宽 FP16 FMAC SIMD（WSE-3 8 宽），以及进网络的五端口路由器。执行是数据流：核空闲，直到一个 wavelet 到达，wavelet 里的控制位选择哪个 handler 开火，八个硬件微线程按张量操作数到达和排空逐周期切换。没有 warp，没有 warp 调度器，没有会 miss 的 cache，没有重排序缓冲： **数据到达就是调度** 。

图23 一颗 Cerebras 核。五端口网络路由器接到跑八个微线程的数据流任务调度器；下面是 GPR 和 44 个张量描述符寄存器，48 kB 本地 SRAM 分八个单周期 bank 坐在 FMAC SIMD 旁边，发送侧还有收割非结构化稀疏的零过滤器。

步进机一次曝光一个光刻场，约 850 mm²，所以每颗常规芯片都活在这个天花板下（也是 B200 在 NVIDIA 顶到极限时变成两颗 die 的原因）。Cerebras 把同一颗约 550 mm² 的 die 印 84 次，排成 12×7，和其他 TSMC 客户一样；然后，在与 TSMC 共研的工艺里，在通常跑的 <1 mm 划片槽上再铺一层高层金属。mesh 以源同步并行接口跨过每条缝（WSE-3 上每 die 2880 GB/s），整个 die 间层大约 97 W。对软件，互联区域不存在：一张均匀 mesh，一颗芯片。

晶圆级以前试过，败在良率：整片单片晶圆计算机上一个缺陷就杀死整片，1980 年代把这个想法埋了。Cerebras 的回答是粒度。H100 上一个缺陷废掉整颗约 6 mm² 的 SM；WSE 上同一个缺陷废掉一颗 0.05 mm² 的核。WSE-3 做出约 97 万核，出货 90 万：让硬件绕开每个缺陷，恢复完整逻辑 mesh。

16 个通用寄存器旁边坐着 44 个数据结构寄存器（DSR），每个拿着一个张量描述符：基址、范围、步长，最多四维。指令按 DSR 点名操作数，所以一条 FMAC 说的是：把到达的流和这份驻留张量相乘，累加到那一份里，硬件按张量长度一直流。没有围着乘法的软件循环，也没有每元素取指；循环活在描述符里。NVIDIA 花了五代 Tensor Core 才把 matmul 走向单条描述符驱动命令；在 WSE 核上，张量指令没有别的形态。

排序是网络的工作。一种 **color** 是编译期绑定了 handler 的静态路由虚通道，所以在一种 color 上发 wavelet 就是在目的核上调代码：16 位控制是调用，16 位数据是参数。任务调度器拿着核上八个微线程的在飞张量运算，按操作数可用性每周期切换。这是 warp 调度器用 64 个驻留 warp 做的同一份藏 stall 工作，用八个上下文做完，因为要藏的延迟是忙的 SRAM bank 或邻居一跳，不是一次 HBM 往返。

晶圆上没有矩阵单元。NVIDIA、Google、AMD 都把浮点运算集中在专用矩阵乘引擎（Tensor Core、MXU、Matrix Core），差别主要在怎么把数据喂进去；Cerebras 用片上网络把矩阵乘拼出来。一次矩阵乘是整张晶圆协同：每个到达的权重沿一行、向仍拿着激活的核广播，每颗核对本地那一块激活做一次乘加，部分和在网格上汇总。GPU 靠寄存器块反复用同一块数据，TPU 靠阵列里权值不动、激活往前传；WSE 则让激活留在本地，飞行中的操作数只有正在被乘的那一个。

WSE-3 头条 125 PFLOPS 是 **稀疏 FP16** ：假定硬件在理想稀疏张量上大约 8× 跳零收益。稠密大约 15.8 PFLOPS FP16（推导：90 万核 × 8 宽 FMAC × 1.1 GHz；Cerebras 没有公布官方稠密数字）。

层次只有一层：核内 48 kB 切片里的 44 GB SRAM，晶圆上再没有别的。没有 HBM，没有 L2，没有驱逐策略；每一字节离 FMAC 一个周期。带宽 21 PB/s，它是 90 万个本地 SRAM 口的总和，晶圆上聚合。诚实比较是 **每个浮点运算能喂进多少字节** ：晶圆大约能喂 1.3 字节 / 稠密 FP16 运算，B200 从 HBM 只拿到约 0.002。WSE 是少数计算和带宽对得上的机器。

另一面是边缘。晶圆连向外部的是 12×100 GbE：1.2 Tb/s，勉强多于一颗 Blackwell GPU 上的一张 ConnectX-8。片上 SRAM 和片外以太之间差五个数量级。NVIDIA 从片上到片外是一层层变慢；WSE 只有这两层，中间没有过渡。

而且晶圆面积不再长大。先进节点上 SRAM 密度实际上停缩放了：WSE-3 只比 WSE-2 多 10% SRAM，尽管整整缩了一代节点、晶体管数增加 54%。逻辑继续缩；六管 SRAM 单元不缩。

#### 权值流过

GPU 或 TPU 上权值驻留、激活流过；WSE 上 **激活驻留、权值流过** 。主权重住在集群旁边的 DRAM+闪存设备 **MemoryX** 里。一层层，权值流过晶圆，对在 SRAM 里的激活触发乘加，然后离开；反向时梯度流出，优化器步进在 MemoryX 里的 CPU 上跑。晶圆从不存权值，连暂时也不（Cerebras 的原话）。模型大小受 MemoryX 限制，不受 44 GB 限制；44 GB 限制的是激活和 batch。

一张晶圆拿下一层全部激活，所以没有张量并行、没有流水并行、没有 FSDP 分片：70B 模型写成单设备程序，多系统扩展是经 **SwarmX** 的纯数据并行。

图24 GPU/TPU 权值驻留、激活流过；WSE 激活在 SRAM，权值从 MemoryX 一层层流过。

披露过的最大集群是 64（Condor Galaxy 3）。平台上披露过的最大从零训练模型是 G42 的 Jais 2，70B 参数、2.6T token。CS-1 以来七年，没有任何人在上面训过 70B 以上。

FP16 和 BF16，FP32 累加，外加（WSE-3 起）一条 16 宽 8-bit 整数路径。没有 FP8，没有 FP4，没有微缩放。别人每代把精度砍半再用块缩放买回来时，Cerebras 仍按 16-bit 算，并把它当作品质差异化（「原来的 16-bit 权重」）。SRAM 容量是架构最稀缺的资源，8-bit 权重会把模型需要的晶圆数砍半。

#### 五个路径

1. 1. **不切晶圆。** 切开会在 die 边界上多出一串成本：高速串行口、中介层、HBM 堆、电缆、交换机。
2. 2. **SRAM 是唯一的内存。** 44 GB，晶圆上聚合 21 PB/s。
3. 3. **数据流核，没有矩阵单元。** 90 万颗小核由到达的 wavelet 触发，matmul 由广播、FMAC 和 mesh 规约拼成。
4. 4. **权值动，激活留。** 权值流过把模型大小（MemoryX）和晶圆内存（44 GB）解耦。
5. 5. **卖延迟，不卖吞吐。** 晶圆每个 token 重读整份模型，比任何存在 HBM 上的东西更快。

### 扩规模

这里的 scale-up 和 scale-out 意思不同。NVIDIA 的 scale-up 问题（让 72 个封装表现得像一台设备）在 WSE 上由光刻解决：高速域出厂就是一块。剩下的是晶圆外的互联。

晶圆内部网络没有 SerDes、没有电缆、没有收发器、没有每条链路的边际成本：路由是编出来的，每跳一个周期，广播是原生网络原语。NVL72 花 5184 根铜缆和一托盘 NVSwitch ASIC，给 72 颗 GPU 130 TB/s 全互连；WSE 的等价域是一个晶圆. NVIDIA 的 scale-up 域每代都在长（三年里从 NVL72 到 NVL576）；晶圆从 2019 年起就是 46225 mm²，以后也还是。300 mm 是工业界跑的最大晶圆（450 mm 过渡十年前死了），所以 Cerebras 的 scale-up 路线图就是下一节点在密度上能挤出什么。

训练 scale-out 是 SwarmX，它只做一件事：复制。把权值流广播到 N 张晶圆，回路上规约梯度；batch 随系统数涨，模型大小不涨。

每个 decode token 从 MemoryX 经约 150 GB/s 的管子流 70B 模型的 140 GB，大约要一秒一个 token。所以推理把权值停在 SRAM 里，在层边界跨系统分片模型：Llama 70B 少则四台CS-3，经以太做流水并行，每多一张晶圆贡献 44 GB 权值+KV 容量和 23 kW 负载。

Artificial Analysis 在 2024 年 8 月发布时测到 Llama 3.1 8B 1850 tokens/s、70B 446；Llama 405B 969（首 token 240 ms）；2025 年 Llama 4 Maverick 2522，约当时最好公开 Blackwell 数字的 2.4×。

SemiAnalysis 估计 1.6T 参数级模型约 24 台 CS-3，同一模型在少数 GPU 机柜里就能放下；分析师估每系统物料成本计约 45 万美元，标价约 200–300 万美元。decode 时晶圆巨大的 FLOP 大多闲着。每 token API 定价对同一开源模型大约是 GPU 供应商的 3–5×。

### 软件

栈像 TPU 一样编译器驱动, Cerebras 编译器是 **kernel 匹配器** ，不是通用代码生成器。 `cerebras.pytorch` 把训练步经 lazy tensor 追进 Torch-MLIR 和图 IR，再把子图对一套手写 kernel 库做匹配，没有匹配的算子落到更慢的自动生成路径. 只接受静态图，没有动态形状，没有数据相关控制流，步中不能 eager 访问张量，PyTorch 版本在上游后面。没有用户 kernel 逃生舱。CUDA 对新注意力变体的回答是写 kernel；TPU 是 Pallas；ROCm 是 Triton。Cerebras ML 栈完全没有用户 kernel 路径。

batch-1 decode的速度,是客户愿意付费的点. 和其他GPU的差距是,每 token 3–5× 定价、2025 年收入仍约 86% 集中在两家与阿布扎比相关的客户（据 2026 年 5 月 IPO 前后的 S-1）。WSE 是最极端的寒武纪大爆发形态，Cerebras认为内存墙是封装选择的结果。

## AWS Trainium

Annapurna Labs 是 AWS Nitro 卡和 Graviton CPU 的核心研发团队。Trainium 的设计目标是在云端提供高性价比的 AI 训练芯片。其计算核心采用 128×128 权值驻留型脉动阵列、软件管理的暂存和整程序编译方式，并兼容使用 Google 的 XLA 编译器。芯片的 scale-out 网络与 AWS Nitro 网络集成。Trainium 集成了专用集合通信芯片和与 AWS 云端基础设施的深度垂直整合，整体设计聚焦于在 AWS 生态内实现高效可扩展的模型训练，优化性价比和易用性。

### 发展

### 架构

Trainium 芯片的核心设计采用软件管理的 SRAM 作为暂存区，由编译器提前调度数据流，没有硬件 cache，也没有线程调度器。每颗 Trainium 芯片包含少量 NeuronCore（Trn1 为 2 个，Trn2 和 Trn3 为 8 个）。每个 NeuronCore 包含多种专用引擎，包括 Tensor Engine（128×128 脉动阵列，用于矩阵乘加）、Vector Engine（用于归约运算）、Scalar Engine（用于逐点操作）、以及由八个 512-bit 向量处理器组成的可编程 GPSIMD Engine，用于执行不适合前三类引擎的运算。外围辅助单元包括 128 个 DMA 引擎用于数据搬运、Sync Engine 用于传输排序，以及从 Trn2 起引入的专用 CC-Core 实现集合通信。体系结构不采用 warp 或 wavefront，每类引擎按照静态调度的数据流管道独立运行。架构设计的重点在于脉动阵列周围配套的各类引擎与单元协同支撑整体计算流程。

#### 计算

Tensor Engine 负责实现矩阵乘加（matmul）计算，提供计算峰值 FLOP 性能，另外三台引擎分别负责向量规约、逐点（scalar）运算和通用可编程向量处理。Tensor Engine 包含一个 128×128 的处理元阵列（共 16384 个乘加单元），采用权值常驻（LoadStationary）模式，将一组操作数加载并保持在阵列中，另一组操作数按行或列流过（MultiplyMoving），中间计算结果（partial sum）被存入累加器 SRAM（PSUM），并支持通过读-加-写方式直接在芯片上沿 K 轴实现高效收缩。矩阵乘累加（MMA）计算通过一组显式指令直接对暂存区进行操作，架构设计明确、指令接口清晰。

三代架构都用物理 128×128 阵列，提升的是单个处理元可处理的低位宽数据量。Trn1 的 NeuronCore-v2 支持 BF16/FP16/FP32 累加，FP8 以 BF16 速率运行。Trn2 的 v3 阵列实现 FP8 双泵机制，有效支撑 256×128 阵列，提升 FP8 计算吞吐。Trn3 的 v4 增加微缩放模块，对 BF16 实现四倍吞吐（有效为 512×128 阵列）。物理阵列规模保持不变，通过更有效率的数据路径，提升低精度数据的并行度。

Vector Engine 负责执行跨元素规约操作（如 layernorm、softmax、pooling）；Scalar Engine 负责一对一逐点运算（如激活函数、GELU）；GPSIMD Engine 包含八个可编程、基于 C 语言的向量处理器，用于执行无法落到前三类引擎的其他算子。各引擎协同工作，可以实现流水线并行：当 Tensor Engine 正在执行矩阵乘加时，Vector Engine 可以并行处理上一块数据的 softmax，DMA 控制器并行为下一块数据做准备，充分利用硬件资源，提高整体吞吐。如果有算子无法映射到前三类专用引擎，则由 GPSIMD Engine 低效完成这些任务，这部分常成为限制新架构适配性的瓶颈，也是所有非 GPU AI 加速器均需面对的通用挑战。

#### 内存

Trainium 的内存体系分为三级，由软件完全管理，无任何硬件 cache。与 CPU 和 GPU 不同，NeuronCore 没有缓存，所有内存搬运操作均需在程序中显式指定。片外存储为 HBM，其容量分别为 Trn1 32 GB、Trn2 96 GB HBM3、Trn3 144 GB HBM3e。片上靠近计算引擎的为 State Buffer（SBUF），作为主要暂存区，带宽约为 HBM 的 20 倍，分为 128 个分区，每个 NeuronCore 在 v2/v3/v4 上分别配置 24 / 28 / 32 MiB。Tensor Engine 与 SBUF 之间为 PSUM，容量为 2 MiB，用于矩阵乘加（matmul）结果累加。数据流经 HBM->SBUF->Tensor Engine->PSUM->SBUF，所有数据移动由编译器发出，没有任何硬件预取或驱逐机制。

该设计采用全部显式调度和暂存，依赖编译器生成最优的数据流指令，因此没有硬件缓存机制对应的容错路径。只要调度正确，计算引擎不会停顿，否则会因调度问题直接影响性能。Trainium 配置的大容量 HBM 相比同代 NVIDIA 芯片，在单位 FLOP 下具备更高存储带宽。不过在绝对内存容量上，Trn2 的 96 GB 低于 H200 和 B200，Trn3 的 144 GB（2025）低于 B200 的 192 GB 和 B300 的 288 GB。AWS 提供大模型推理和训练服务时，核心优势不在于单芯片的最大内存容量，而是依赖自研芯片的自有供应和整体性价比，降低单位计算与内存成本。

#### 数值

Trainium 支持和行业主流相同的数值精度演化路径，包括 FP32、BF16、FP8 和 FP4。Trainium 在数值支持上有两个特点。第一，FP8 支持可配置指数格式，Tensor Engine 可以根据需求选择 E5M2、E4M3 或 E3M4，不局限于 NVIDIA Hopper 的固定 E4M3/E5M2 配置，编译器可以据此按张量需求权衡数值范围和精度。第二，Trn3 支持的 OCP MXFP4 精度，在操作过程中并不提升计算吞吐，因为输入为 FP4 的操作数进入阵列前被上转换为 MXFP8，在硬件上以 FP8 速度执行，所以 FP4 只减少内存和带宽消耗，并不减少计算消耗。从 Trn3 起，硬件引入块级缩放指数机制，以及每一代都实现了硬件级的随机舍入优化数值表现。

#### 芯片内集合通信

Trainium 芯片在硬件层面内建了集合通信单元 CC-Core，支持 all-reduce、all-gather、reduce-scatter 和 all-to-all 等分布式操作。每块 Trn2 芯片集成 20 个 CC-Core，直接连接 NeuronLink，实现通信操作时 Tensor 和 Vector 引擎可并行计算，不需要将通信任务分配给主计算单元，也需要在软件层重叠调度。这种设计减少了计算和通信之间的资源争用，提高芯片利用率。类似的硬件分工在 Google TPU 中称为 SparseCore，在 Cerebras 是专用核外处理模块。Trainium 选择专用硬件而不是通过计算核心分时处理集合通信任务，减少对主计算单元的干扰。

#### 设计原则

1. 1. **以云端服务为主要产品，芯片作为底层组件** 。Annapurna 团队将芯片、服务器、机柜、网络和云 API 集成为统一堆栈，Trainium 优先优化在 AWS 内部的性价比,和卖芯片不是一个优先级。
2. 2. **复用现有架构，不做重复发明** 。128×128 权值驻留阵列、软件管理暂存（SBUF/PSUM）、整程序编译等架构源自 TPU，并与 Google OpenXLA 兼容，优势是更多精力用于系统级创新如云端网络和基础设施。
3. 3. **集合通信为芯片级硬件任务** 。专用 CC-Core 硬件在物理上处理 all-reduce 和 all-to-all 操作，无需占用主计算单元的 FLOP。
4. 4. **采用自有云网络进行扩展** 。scale-out 使用支持 SRD 传输的 Elastic Fabric Adapter（EFA），与 Nitro 卡、packet-spray RDMA 等 AWS 基础设施模块配合，没有采用 InfiniBand 等第三方专用方案。
5. 5. **拓扑配置依据负载需求调整** 。Trn1、Trn2 采用 TPU 风格的 torus 拓扑，Trn3 引入 NeuronSwitch 全互连交换，针对 MoE 路由这种高基数通信负载优化，在不同阶段根据负载特性灵活选择拓扑。

### 扩规模

Trainium 的扩规模结构分为紧耦合的 scale-up 域和通用 scale-out 域。单台服务器内部的芯片通过 NeuronLink 进行连接，不实现 NVLink 式的缓存一致共享内存，而是基于消息传递，类似 TPU 的 ICI 接口。Trn2 时代，NeuronLink 采用 2D/3D torus 结构连接芯片：单实例为 16 芯片 4×4 2D torus，每芯片约 1.28 TB/s，UltraServer 由四个实例三维拼接成 64 芯片 4×4×4 3D torus，汇聚 83 PFLOPS（FP8）和 6 TB HBM。第三轴带宽相对低（每芯片 256 GB/s），带宽集中于实例内通信，体现 torus 架构通过增加跳数降低互连成本的典型特性。AWS 将 Trn2 UltraServer 的 64 芯片对应 NVIDIA NVL72 的同级别产品，在非最近邻流量和延迟上有很大区别。

Trn3 阶段，传统 torus 架构已不适应 MoE 等高基数全互连需求，改用 NeuronSwitch-v1，支持完全交换全互连网络，芯片间带宽提升到每芯片约 2 TB/s，并且所有芯片之间为单跳连接，无需多次转发。Trn3 UltraServer 扩展至 144 芯片，计算能力是 362 PFLOPS（稠密 FP8），带宽为 20.7 TB HBM3e。设计针对 all-to-all 负载和 MoE 推理场景进行优化。

scale-out 网络采用 AWS 通用的数据中心网络，每个 Trainium 实例通过 EFA 网卡（如 Trn2 单实例 3.2 Tbps）接入。数据传输基于 Scalable Reliable Datagram（SRD）协议，实现包级并行与乱序交付，并由 Nitro 网卡完全卸载数据面。SRD 不是传统 RoCE 或 InfiniBand RDMA，单条消息分散到最多 64 条物理网络路径上，提高吞吐能力并避开队头阻塞，重组操作在集合通信库中完成。scale-out 网络复用 AWS 云数据中心的网络基础设施，实现可扩展大规模集群通信。

### 软件

Trainium 的软件栈采用与 TPU 类似的编译器优先架构，核心组件为 Neuron SDK。Neuron 编译器（ `neuronx-cc` ）基于 Google OpenXLA，接收 XLA HLO 图，生成可在 NeuronCore 上运行的 NEFF 二进制。前端 IR 和 TPU 保持高度兼容，Google 官方公告把 Trainium 作为 OpenXLA PJRT 的后端设备。PyTorch 支持通过 torch-neuronx 结合 PyTorch/XLA 的 LazyTensor 路径，JAX 支持通过 jax-neuronx 与 StableHLO 降级。整个系统采用和 TPU 高度类似的整程序编译方案，不依赖 kernel–driver 风格接口，主要通过编译器实现运算映射和优化。

Trainium 提供 NKI（Neuron Kernel Interface），一种基于 Python 的块级 kernel 描述语言，允许开发者直接调用四类专用引擎和 SBUF/PSUM 暂存功能。NKI 的设计理念与 Pallas 或 Triton 类似，适用于需要更细致调度、依赖硬件性能优化的 kernel 开发。

Trainium 软件栈的主要限制体现在生态成熟度上。NKI、JAX 支持和分布式训练工具不是非常成熟，移植的模型仅能在 AWS 生态内运行，没有跨厂商兼容性，vLLM 后端功能落后上游版本。部分核心客户（如 Anthropic）直接参与底层 kernel 的开发与体系修复，向官方 SDK 贡献改进。Trainium 编译器系统架构成熟，但外围生态和工具链处于发展期。

## Groq LPU

Groq LPU 是一台确定性芯片。其它架构使用 cache 掩盖内存延迟、用调度器填补运算间隙、用仲裁器处理资源争用和延迟不确定性， LPU 剔除了这类反应式硬件组件，没有 cache、分支预测、仲裁器、重排序缓冲和片上交叉开关。LPU 的全部调度、数据流、通信顺序均由编译器静态决定，每条指令和每个数据流在精确的周期和位置上。芯片的整个计算和通信流程可在运行前完全确定。与 TPU 只静态调度计算部分不同，Groq LPU 芯片所有内存均为 SRAM，网络通信也静态编排，多个芯片之间时钟和数据同步，经编译后全系统行为周期确定。

### 发展

### 架构

LPU 采用空间功能切片设计，将传统核心中的指令控制、向量 ALU、矩阵单元、片上内存与网络逻辑拆分为多个纵向排列的功能切片。这些切片横向并排覆盖整块芯片，数据以注册流水线方式从芯片东端或西端输入，在每个周期按切片依次流动。所有操作均按时钟驱动的同步运转，编译器精确规划每一个操作数的路径。

LPU 芯片包含 320 条 SIMD lane，分为 20 个 superlane（第 21 个为备件），每个切片可同时作用于所有 lane。每 lane 有 64 个逻辑流寄存器（32 向东，32 向西），每周期流式前进。芯片使用双半球镜像结构，中央为向量单元（VXM），两侧分布着矩阵单元（MXM）、交换切片（SXM）、以及片上存储（MEM）切片。指令控制单元（ICU）部署在芯片南边，将 VLIW 指令包注入功能切片，控制各流水流的数据转移和运算。

#### 计算

LPU 的计算体系分为矩阵运算（MXM）和向量运算（VXM）。MXM 单元设置为四个独立的 320×320 矩阵乘加阵列，共有 409,600 个乘法器，可执行 INT8 或 FP16 运算，并以 INT32 或 FP32 累加。权重可一次性装载至阵列，计算过程大致为 900 MHz 时钟下，支持 750 INT8 TOPS 或 188 FP16 TFLOPS。LPU 只支持密集计算路径，不支持数据相关的稀疏跳过，保证确定性。

向量路径通过中央 VXM 单元完成，320×16 ALU 支持激活、归一化、量化等常见算子。切片间的数据流连续通过 VXM，再入 MXM，实现高效的算子融合。SXM（交换切片）用于处理数据重排，如 lane 移动、跨 lane permute、转置和芯片间通信。所有数据流和算子执行次序均由编译器决定，没有硬件调度干预。

#### 内存

LPU 不集成 HBM、DRAM 或任何分层 cache。芯片内存全部由 88 条 MEM 切片（每半是 44 条）组成，总计 230 MB SRAM。数据访问为单周期、固定延迟，芯片内存带宽约 80 TB/s（片上聚合）。无任何硬件预取、驳出、驱逐、或一致性管理，内存层次完全平坦。单颗 LPU 装不下大型模型，需要多个芯片分布式承载模型权值。例如 Llama-2 70B 的 FP16 权重约 140 GB，需在 576 颗 LPU 上扩展部署。

#### 数值

LPU 支持 FP16、INT8 数据格式，累加采用 FP32 或 INT32。芯片未集成 FP8、FP4。数值处理采用 TruePoint 技术，将 320 元素点积整合至单次舍入与 FP32 累加，实现 FP16 算子的高精度点积运算，典型最大误差低于 FP32 基线的 0.05%。片上未实现更低精度数据通路，降低精度可减小模型所需容量，但 LPU 的实现未做低精度折中。

#### 确定性

LPU 芯片所有路径、计算和通信延迟均由编译器静态推出，完全无动态变化。ISA 明确规定每条指令的延迟，数据通路严格固定周期。硬件中不存在 cache miss、仲裁冲突、分支预测误判等会增加非确定性调度的现象。Groq 运行 BERT-Large，24,240 次测试结果延迟满足编译器预测范围，偏差控制在 2% 内。确定性机制适用于跨整个芯片网络，调度覆盖全系统。LPU 静态时钟同步和周期性 deskew 指令确保多芯片集群的全局时钟一致。

#### 主要设计选择

1. 1. **确定性优先。** 移除所有动态和反应式部件（cache、仲裁、预测、重排序），完全由编译器静态调度。
2. 2. **空间功能切片结构。** 按功能将核心硬件切片，数据以流式方式穿过不同计算与内存切片，实现算子融合和高效数据复用。
3. 3. **仅采用片上 SRAM。** 不依赖 HBM 和分层存储，全部模型权重放在片上 SRAM，容量需求靠横向扩展芯片满足。
4. 4. **静态调度芯片间网络。** 每颗芯片兼任计算和路由器角色，所有芯片间通信由编译器周期级调度完成。
5. 5. **优化最小时延推理。** 主要针对单 batch、极低 token 推理延迟场景，不以总吞吐量或每 token 成本为主要优化目标。

### 扩规模

LPU 的扩展方式依赖芯片自带路由能力，无独立的 scale-up 网络。每颗 LPU 芯片支持最多 16 条 RealScale 芯片间高速链路（典型卡上开放 11 条），集群内所有芯片既是计算节点，也是网络路由器，无需 NIC、外部交换机或传统 Top-of-Rack 网络交换设备，扩展结构准确受编译器调度控制。

标准节点为 8 颗 LPU 芯片全互连，不经任何额外网络设备。每颗芯片用 7 条链路与其它 7 芯片直接互联，剩余链路汇聚成逻辑虚拟路由器，用于不同节点间的互连和扩展。节点间通过 Dragonfly 拓扑连接，9 个节点可形成 72 芯片的机柜（实际 64 颗活动、9 号作为备份），Dragonfly 网络可扩展至 10,440 颗 LPU，任意两点间不超过 6 跳。所有网络通信调度和流控在编译期静态确定，运行时链路由 Hardware-Aligned Counters 保持周期级全局同步。链路采用前向纠错，避免重传扰动，保证时间一致性和调度准确。这个设计可以把大模型按容量需求跨多芯片部署，例如 Llama-2 70B 在 576 颗 LPU 上实现，宿主服务器与其他 GPU 集群结构不同，采用更大数量的服务器和内存资源。

图32Groq 机柜

图32 Groq scale-out。8 颗 LPU 全互连形成一个节点（一个 Dragonfly 组，呈现为一台高基数虚拟路由器）；9 个节点形成 72 芯片机柜，一个节点热备。芯片就是路由器：没有 NIC，没有交换机。编译器按周期调度每一次芯片间传输（Scheduled, Not Routed），准同步链路由每 256 周期交换的 Hardware-Aligned Counters 锁步，FEC 代替重传，这样一次重试永远不扰动调度。70B 模型跨整柜 SRAM。

### 软件

LPU 的软件栈以编译器为核心，所有模型源代码由编译器直接转换为底层张量算子，并对每条指令、流、以及芯片间通信进行静态调度。不存在 kernel 概念，无需进行手动 kernel 优化。用户直接将 PyTorch、TensorFlow 或 ONNX 模型输入 Groq 编译工具链，编译器生成全系统调度策略。编译器以外的软件组件包括一套分析器、运行时和封闭式自动部署工具链 GroqFlow。2025 年，GroqFlow 停止维护，公司业务转向按 token 计费推理 API。

Groq LPU 架构在推理任务场景下可获得极低单 token 延迟，适用于单用户延迟敏感型推理服务，在第三方评测（如 Artificial Analysis）排名领先。架构不适合大模型无法装配进单柜 SRAM、大规模 batch 吞吐场景，或需要表达动态控制流的场合。对于包含数据相关 expert 路由的 MoE 结构，架构兼容性受限，编译器无法高效表达所有动态调度情况。

在 2025 年 12 月，NVIDIA 获得 LPU 技术非独占许可，并招聘了核心团队成员。NVIDIA 公告交易不是并购，不包含现有产品、客户或股权转移，但公开的交易金额为 130 亿美元。2026 年 GTC，NVIDIA 以 NVIDIA Groq 3 LPU 形式推出该技术，发布了基于 256 颗 SRAM-only LPU 的推理柜，配合 Rubin NVL72 服务器分工协同，GPU 执行注意力计算，LPU 负责前馈与 MoE，交由编排程序管理。GroqCloud 继续在原版 14 nm LPU 芯片上提供在线 token 服务。

### 表总结

- • **每芯片 FP8 已经收敛。** B200（4.5 PF）、Ironwood（4.6 PF）、MI355X（10 PF）彼此大约在 2× 以内。每芯片军备竞赛接近；机柜和 pod 才是架构分叉的地方。
- • **HBM 容量是 AMD 持续的赢。** 2023–2025 的 192 ->256 ->288 GB 每一代都追平或超过 NVIDIA。NVIDIA 直到 B300（2025 年末）才在 288 GB 追上；Rubin Ultra 2026 年以每封装 1 TB 重新领先。
- • **机柜级 scale-up 在 2026 年之前是 NVIDIA 的赢。** GB200 / GB300 NVL72 是 2024–2025 唯一出货的相干机柜级域；AMD 在盒子上扩，直到 Helios 才到机柜。TPU 绕开这个问题：它的 torus 同时是机柜和集群。
- • **TPU pod 在芯片数上压过任何 NVIDIA 机柜。** Ironwood pod = 9216 芯片、42.5 ExaFLOPS FP8；NVL576 = 576 GPU、约 5 ExaFLOPS FP8。TPU「平坦每芯片费率 × 巨大 pod」的配方给出更多系统级聚合计算，代价是每芯片带宽。
- • **每芯片功耗涨得很快。** 700 W（Hopper） ->1000 W（Blackwell、MI325X） ->1400 W（B300、MI355X） ->约 1800 W（Rubin Ultra，分析师）。约 1000 W 以上液冷成为强制；风冷实际上随 Hopper 结束。
- • **Scale-out NIC 带宽每代 NVIDIA 翻倍。** 400 Gbps（CX-7，Hopper） ->800 Gbps（CX-8，Blackwell） ->1.6 Tbps（CX-9，Rubin）。AMD 落后一代（Pollara 400 ->Vulcano 800）。
- • **Cerebras 拆掉表的坐标轴。** 完全没有 HBM：44 GB 片上 SRAM，聚合 21 PB/s，约 1.3 字节 / 稠密 FLOP，GPU 行靠近 0.002。同一行里看得见代价：总内存不如单颗 H200，每瓦稠密 FLOP 落后每一颗当代 GPU，scale-up 列空着，因为相干域就是晶圆本身。
- • **Trainium 拼经济，不拼规格表。** 每芯片落后（Trn2 的 1.3 PF FP8 大约是 MI355X 的四分之一），但 Trn2 UltraServer 在 2024 年和 NVL72 同期走到 64 芯片机柜级 scale-up，作为消息传递 torus 而不是相干交叉开关；Trn3 转到交换 NeuronSwitch。AWS 从 Nitro 卡到 API 拥有每一层，一个锚定租户（Anthropic，超过 100 万颗 Trainium2）在前沿规模上验证它。
- • **Groq 用 SRAM 带宽换容量，再用芯片数把内存池做大。** 第一代 GroqRack 64 颗芯片只有 14 GB；Groq 3 LPX 扩到 256 芯片、128 GB，聚合 SRAM 带宽 40 PB/s。
