## 4.游戏开发

这里我用同样的提示词让模型分别制作一款经典游戏

提示词如下：

```c
请帮我用 HTML5 + JavaScript 制作一款类似《超级马里奥》的横版卷轴跳跃小游戏，要求全部代码写在一个 HTML 文件里（HTML + CSS + JS 内联），双击即可在浏览器运行，无需任何外部依赖。
核心要求：
1.画面与风格：使用 Canvas 2D 绘制，像素风或简约卡通风格、分辨率 960×540，自适应缩放居中，背景有蓝天、白云、远山视差滚动
2.玩家角色：可用方向键 / A、D 左右移动，空格 / W / ↑ 跳，支持二段跳，有重力、加速度、摩擦力、下落速度上限，踩到敌人头顶可消灭敌人并反弹，碰到敌人侧面则扣血/死亡，3 条命，掉入坑或碰敌人扣 1 条命，归零则 Game Over

4.关卡元素：地面平台、悬浮砖块、问号方块（顶到后出现金币或道具），水管/障碍物，深坑（掉下去死亡），金币（收集加分），蘑菇道具（吃到后变大，可多挨一次伤害），旗杆/终点，到达后进入下一关
5.游戏系统：分数、金币数、生命数、当前关卡显示在顶部 UI，摄像机跟随玩家横向滚动，关卡结束/死亡有简单动画或提示文字，按 R 键重新开始，至少设计 3 个关卡，难度递增
```

## 结语

经过这几轮测试，其实很难简单地说 GPT-6.1-sol 或 DeepSeek-V4.1 Flash 谁是绝对胜者，因为两者展现出的优势方向并不完全相同。

DeepSeek 给我的最大感受是： **执行力非常强，而且对于明确目标有极强的贯彻能力。**

它在看到需求之后会努力把每一个关键词都实现出来，它会快速堆叠大量符合要求的元素，让第一眼效果非常惊艳。在一些规则明确、目标清晰、功能列表详细的任务中，DeepSeek 的表现非常稳定，尤其是在代码生成和开发方面，已经达到了非常高的水平。

但是问题也同样明显：它有时候过于关注“完成需求”，而忽略了很多东西。总之就是不耐看，在一些与审美相关的还需要提升

而 GPT-6.1-sol 就不一样。

相比于单纯满足提示词，它似乎会进一步思考：“这个东西真实存在时应该是什么样？” 
 所以它生成的作品往往不会堆砌大量视觉元素，而是更加注重比例、留白、信息组织和整体体验。这也是为什么很多时候它第一眼可能没有 DeepSeek 那么震撼，但仔细观察，会发现它更加耐看。

尤其是在网页设计和复杂产品构建中，这种差距会更加明显。优秀的作品并不是把所有功能都放进去，而是在有限的空间里做出合理取舍。GPT 在这方面表现出了更强的“产品意识”。

不过，3D 建模这一部分也让我重新认识了 DeepSeek。

之前我认为 DeepSeek 在视觉生成方面可能存在明显不足，但 Three.js 建模测试中，它的一句话生成效果其实非常惊艳。

同时不同任务下，模型能力的表现并不是固定的。有时候过度优化提示词反而会限制模型发挥，而简单的目标描述可能更容易激发模型自身的创造能力。
