因为这次大版本动了四样底层依赖，任何一样不对容器都起不来。CUDA 12.9 的预编译包和镜像不再发布，PyTorch 提到 2.14，两个投机解码方案被删，旧的 Ray 执行器也删了。

vLLM 项目在 2026 年 11 月 2 日发布 v0.33.0 正式版，927 次提交、389 位贡献者。GitHub 标签还挂着

![](https://pic2.zhimg.com/v2-561b72b5425fdb0b292d6ed17202b52b_r.jpg)

v0.33.0rc3，发布页标题写 v0.33.0，预发布标记是 false，按正式版对待就行。

## 报错为什么看起来像镜像坏了

最典型的现场是 `nvidia-container-cli` 或者驱动加载失败，日志里根本不提 vLLM。

原因在发布件。这一版只发 CUDA 13.0 一档，CUDA 12.9 的 `-cu129` 轮子与 `-cu129-ubuntu2404` 镜像停止发布。照老脚本 `docker pull` 带 cu129 的标签，拉不到。

宿主机驱动要能支撑 CUDA 13.0。国内不少自建集群的驱动停在 12.x。这一步绕不过去。

还有一个细节。CUDA 轮子这版改成了与 libtorch ABI 稳定，以前升级时二进制不匹配那类怪报错会少。只在新版轮子上有这个性质。

## 代码层被删掉的两样东西

Medusa 和 MLP speculator 两个投机解码实现被移除。启动参数里还留着 `--speculative-config` 指向它们的，进程直接起不来。

老的 Ray 编译图执行器删了，`VLLM_USE_RAY_V2_EXECUTOR_BACKEND` 这个环境变量也没了，剩下 `RayExecutorV2` 一种。多机部署里手写配置的人要注意，安静失效比报错更麻烦。

AMD 卡那边有四个环境变量被删，`VLLM_ROCM_MONO_DECODE` 换成了 `--monokernel` 命令行参数。用国产外的 AMD 集群，`docker pull vllm/vllm:v0.33.0-rocm` 起手，默认是 ROCm 10.0，要留在 7.2 得显式用 `-rocm72` 标签。

## 不报错但行为变了的几处

推理暂停期间进来的请求，现在返回 HTTP 503。以前的行为不一样，监控里盯状态码分布的告警阈值要跟着调，不然灰度的时候会冒出一片红线。

GLM-5.3-Flash 的 KV cache 默认换成 FP8，release notes 里给的是该 pull request 自己的端到端吞吐提升 9.8%。省显存、也省带宽，但精度上的差异要自己测。

多机 KV 传输用 NIXL 连接器的，要求 NIXL 1.5 以上，低于这个版本启动就挂。`kv_transfer_params` 和 `ec_transfer_params` 从渲染输出里的嵌套位置挪到了顶层。

EAGLE 与 MTP 的前缀缓存默认开了前瞻块哈希，Cohere2MoE 默认走双流，FA4 稀疏 MLA 解码在 Blackwell 上、每个 rank 的查询头不超过 16 时默认开启。这些不写在升级步骤里，`--mamba-cache-mode` 还被标成弃用且不再生效。

## 性能数字的适用条件

release notes 里最吸引眼球的一行，是 DeepSeek-V4.1-Flash 配 DSpark 在 GB300 上从每秒 1373 个输出 token 提到 3390 个。

条件堆得很厚。GB300、DSpark 投机解码、DFlash 与 DSpark 不再在 token 预算里预留草稿槽位这个改动，数字来自对应 pull request 作者提交的基准。

国内大多数团队手里是 A100、H20、A800，或者国产卡。这些数字拿到自己机器上基本对不上，参考价值在于知道官方在往哪个方向优化，不在于预期提升几倍。

Kimi-K3 在 GB300 上 1.5 到 2 倍的延迟特化解码、DeepSeek-V4.1-Flash 在 MI300X 上 2.32 倍的 MonoKernel 响应性，都是同一类。

## 反方的话

有人会说，我们小团队单机部署，没上 Ray、没用多机 KV 传输，犯不着为这次升级折腾驱动。

这个判断在单机、单卡、纯粹跑推理 API 的场景里站得住。预编译包的 CUDA 门槛仍然在，你至少得找一份能配上的镜像。

躲不开的是环境维护这一层。拖到 v0.34.0 再升，`--ir-op-priority` 已经在移除计划里，LM Format Enforcer 在 v0.35.0 取消。参数是分批删的，攒着一次升，查的成本会翻几倍。

## 迁移顺序

我自己的做法是先把测试机驱动升到能装 CUDA 13.0，再拉新镜像，只验起不灌流量。

然后 grep 一遍配置文件，清掉 Medusa、MLP speculator、老 Ray 执行器和被删的环境变量。再用 `pip install vllm` 或 `uv pip install vllm --torch-backend=auto` 这种方式让包管理器自己配 torch 后端，比手写版本号稳。

NIXL 升到 1.5 以上再测多机 KV 传输，最后才动生产。急不下来的把当前版本 pin 住，等驱动和运维窗口一起排。
