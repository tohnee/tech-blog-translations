## 一句话总结

长上下文推理里，KV cache（键值缓存）是最硬的显存瓶颈。把每个通道压到约 1 bit 的向量量化（VQ, vector quantization）方法一直有个尴尬：到了 1-bit 这个极限区间，每个码本要覆盖的通道数变多、质心数却有限，量化误差会急剧放大。首尔大学与斯坦福的这篇论文给出一条直接的路子——**不改 VQ 的查表结构，而是先把「键」搬到一个人为定制的空间里再量化**。这个定制空间由三步构成：query 引导的通道加权、跨头共享尺度的归一化、协方差感知的通道分组。搬进去之后，两个关键量同时变好：

> **在 Llama-3.1-8B 上用 1.266 bit/通道（键）压缩，通用任务平均分从 CQ 的 48.03 拉到 59.21（BF16 是 63.94）；在 Qwen3-4B-Thinking 的长链推理上从 CQ 的 28.52 拉到 60.55（BF16 是 67.18）。单张 RTX 6000 Ada 上，KV cache 池扩大 12.48×，最大 batch 从 6 提升到 84，峰值吞吐 220.8 → 412.6 tok/s（1.87×）。**

作者把方法命名为 **TaSQ**（**Ta**ilored **S**pace Vector **Q**uantization），代码已开源在 （Apache-2.0，附带一份 SGLang 分支）。

## 一、背景：KV cache 为什么是长上下文推理的硬骨头

decoder-only Transformer 自回归生成时，由于因果掩码，前面所有 token 的 key 和 value 一经算出就不再改变，于是被缓存下来跨解码步复用。问题是这份缓存随序列长度线性增长，而且**每一步解码都要把它整份读一遍**。序列一长，显存容量和显存带宽这两个约束同时逼近极限——静态的模型权重反而退居其次。

压缩 KV cache 的路子有三类：token 淘汰（如 H2O、SnapKV）、缓存合并、以及量化。其中量化应用最广。而在「每通道 1 bit」这种极端低比特下，**向量量化（VQ）**比标量量化更有优势：它把一个通道组当整体，用一个学出来的码字（codeword）联合表示，从而利用通道之间的联合结构。代价是索引开销——一个 g 维向量用 K 个码字之一表示，每个通道的索引成本是 log₂K / g bit。

既有 VQ 方法要么在连续的通道组上学习码本（CQ），要么把激活归一化后用免标定的全局码本（NSNQuant）。但当码率逼近 1 bit/通道，问题就来了：每个码本要代表更大的通道组，质心数却有限，如何把码本容量用在刀刃上变得非常困难。论文正是冲着这一点去的。

## 二、三个动机观察：为什么可以「定制空间」

TaSQ 的出发点是两条洞见：

- **不同通道的重建误差，对 QKᵀ 的影响并不相等。**
- **VQ 只有在相关通道被分进同一个码本时，才能利用它们之间的依赖。**

围绕这两条，论文在 Llama-3.1-8B 上做了一组观察（统一用一段 2,048 token 的 GPQA 窗口，图 1）：

![](https://pic4.zhimg.com/v2-f9dce752cd59001b380cfae76c7dcbb7_1440w.jpg)

图 1：TaSQ 的四个动机观察（Llama-3.1-8B，2,048-token GPQA 窗口）。(a) 各通道 query 激活的中位数与 P10–P90 区间——分布宽度差异极大；(b) key 通道之间的绝对相关性（自相关已掩掉）——强弱不一；(c) 通道 44/45 在 RoPE 前后的 key 分布——RoPE 后明显铺开；(d) 32 层上 k-means 重建 MSE 的 RoPE 前后对比——pre-RoPE 整体低 35%。

- **通道敏感度不均（图 1a）。** 在 query–key 点积里，某个 key 通道的误差会被对应的 query 激活值缩放。而各通道的 query 激活分布差异很大，有些通道的取值范围特别宽。这意味着不同 key 通道对量化误差的敏感度天差地别——这是「加权」的动机。
- **通道间相关性强弱不一（图 1b）。** 有些通道对高度相关，有些近乎独立。VQ 用共享码本联合表示多个通道，能不能吃到这些依赖，取决于哪些通道被分到一起——这是「分组」的动机。
- **RoPE 前后差异巨大（图 1c、1d）。** RoPE（旋转位置编码）按位置相关的角度旋转 key，会把原本紧凑的分布明显铺开。图 1c 里通道 44/45 的 pre-RoPE 分布很集中，post-RoPE 后铺得很开；图 1d 进一步量化：**pre-RoPE 的 VQ 在全部 32 层上重建误差都更低，总重建误差低 35%**。所以 TaSQ 选择在 **pre-RoPE 的 key 上做 VQ**。

论文还对比了 key 与 value 的通道特性（见附录 C，正文图 6）：value 的通道敏感度更均匀（头内变异系数 0.176 vs key 的 0.841）、通道间相关性也更弱（平均绝对相关 0.067 vs key 的 0.136）。因此论文**只对 key 定制空间，value 保持普通连续分组 VQ**，把 value 侧的定制留作未来工作。

## 三、TaSQ 方法：把 key 搬进定制空间

整体流程见论文图 2。标定阶段，对 pre-RoPE key 依次施加 query 引导加权、跨头共享尺度归一化、协方差感知分组（保持 RoPE 对结构），然后在得到的空间里为每个分组拟合一个 VQ 码本；推理时，key 被编码成码本索引加一个尺度，注意力计算前在线重建并施加 RoPE。三层变换可以记成 W（加权）→ N（归一化）→ P（置换）。

![](https://pic2.zhimg.com/v2-9903a5b343a2be8cb040488a9d6f38c5_1440w.jpg)

图 2：TaSQ 总览。对 key 依次施加 W（query 引导加权）、N（跨头共享尺度归一化）、P（保持 RoPE 对的协方差感知分组），把「原始目标空间」（平均误差 0.093）变成「定制目标空间」（平均误差 0.026）。入框小图分别是各步的效果：加权让 logit 误差降到 0.61×、分组让群体体积目标降到 0.40×、归一化压掉 token 尺度离群点。

### 3.1 Query 引导的通道加权（W）

令 δ_{p,h} = k_{p,h} − k̂_{p,h} 是位置 p、KV 头 h 的 pre-RoPE key 量化误差。对一个 post-RoPE query q̄_{t,h}，点积误差的平方是 δᵀ A δ，其中 A_{t,p,h} = R_pᵀ q̄_{t,h} q̄_{t,h}ᵀ R_p。为得到一个与位置、token 无关的敏感度摘要，论文把 A 在标定数据的所有有效因果 query–key 对上取平均，得到 Ã_h，再用它的**对角阵**近似：

W_h = diag(Ã_h)

于是把每个 pre-RoPE key 变换成加权空间：

kw_{p,h} = W_h^(1/2) k_{p,h}

这样，加权空间里的（平方）重建误差就等价于原来的 QKᵀ 点积误差的代理量——**在加权空间做欧氏 VQ，等价于把「query 敏感度」直接写进了 VQ 的重建目标**。

这里有个关键的工程取舍：为什么用**对角**而不是稠密的 Ã_h^(1/2)？因为 A 是稠密阵时，解码端要先做 A_h⁻¹（d×d 乘法）才能恢复 key 再施加位置相关的 RoPE，而这一步无法预先合并进 query 投影（R_p 依赖位置）。论文实测：稠密恢复的开销从 1k token 时占注意力时间的 36%，涨到 16k token 时的 **103%**（Qwen3-4B，RTX 3090）。而对角近似可以直接吸收进码本，运行时零额外变换。更妙的是，虽然稠密变换在标定语料上误差略低，但在 GSM8K 上**误差反而高约 4×**（相对 logit 误差 0.00933 vs 对角的 0.00234）——那些非对角的通道耦合并没有迁移过来。所以对角近似既快又更准。

### 3.2 跨头共享尺度的归一化（N）

为了压制离群的 token 幅度，论文沿用 token 级归一化。但先前工作（NSNQuant）是**每个头**存一个尺度，而论文发现：**所有 H 个 KV 头共享同一个 RMS 尺度就够了**。

s_p = ( (1/(Hd)) Σ_h ‖kw_{p,h}‖² )^(1/2)

kwn_{p,h} = kw_{p,h} / s_p

省下来的元数据是可观的：b_s 位尺度下，逐头归一化每通道花 b_s/d bit，共享后只要 b_s/(Hd)，**省了一个因子 H**。论文用 FP16（b_s=16）存 s_p，代价仅 16/(8×128) = 0.0156 bit/通道，换来高尺度分辨率。论文进一步用实验说明：等 K 下池化（pooled）与逐头（per-head）的失真几乎不变（各层相对 SSE 在 ±4% 以内），却省了 0.109 bit/通道；把省下的比特用于加倍码本（K: 1024→2048），68 层里相对 SSE 至少再降 20%。

### 3.3 协方差感知的通道分组（P）

既然只有同组通道才能共享码本、吃到相互依赖，那么「怎么分组」就成了关键。论文对每个头，从标定数据估计加权归一化后 key 的协方差 Σ_h。对一个候选分组 G，定义代价：

c_h(G) = det( Σ_h[G, G] + εI )^(1/|G|)

这是有理论依据的：在高斯模型下，高码率量化理论给出最优 K 质心码本的平均重建误差渐近正比于 K^(−2/|G|) · det(Σ_h[G,G])^(1/|G|)。由于 |G| 和 K 在各组间固定，唯一与分组有关的就是协方差行列式，于是 det 成了量化误差的天然代理。于是分组问题变成：把 d 个通道划分为若干大小为 g 的分组，最小化各组代价之和，且**约束每个 RoPE 对必须在同一组**（这样在线施加 RoPE 才高效）。

遍历所有合法划分是不可能的（组合数巨大），论文用一个**分层最小权完美匹配**近似求解（算法 1）：从单个 RoPE 对出发，每轮给当前各组两两之间赋合并代价 c_h(G_a ∪ G_b)，求最小权完美匹配，合并，重复到每组含 g 个通道。

### 3.4 定制空间里的 VQ 与运行时吸收

最终的 key 是 kwnp_{p,h} = P_h · W_h^(1/2) · k_{p,h} / s_p，落在加权、归一化、分组后的空间里，为每个（层、KV 头、通道组）拟合一个 K 质心码本。码本拟合用 **Fisher 加权 k-means**（沿用 CQ/KVQuant 的做法）：给每个通道组一个 Fisher 权重 ω = Σ_{i∈G} F_{p,h,i}，其中 F 是损失对 key 的平方梯度，让标定 token 按其对语言建模损失的影响加权。

推理时的巧妙之处在于**把变换吸收掉**：加权和置换 P_h W_h^(1/2) 合并进 key 投影矩阵，逆加权合并进解码码本；于是 key 和 query 全程都待在「置换后的坐标系」里，只需按置换后的 pair 布局重排 RoPE 频率即可。最终码字查表、尺度恢复、成对 RoPE、QK 点积全部融合进注意力 kernel——**不需要运行时通道重排、稠密变换或额外 kernel 启动**，额外开销可忽略。

论文还验证了「协方差代价」确实是好代理：代价与真实 VQ 重建 MSE 的 Pearson 相关高达 **r = 0.994**，且跨层都强相关（图 3b/3c）；用协方差感知分组替代连续分组，分组目标和实际重建误差都下降（图 3d）。

![](https://pic1.zhimg.com/v2-b96c6cb7cb02737e6856683c1cf5c4fc_1440w.jpg)

图 3：(a) 有无 query 引导加权时的 QKᵀ MSE（上）与注意力 KL 散度（下）——加权一致更低；(b) 组代价 c_h(G) 与 VQ 重建 MSE 的关系（第 15 层、KV 头 0），Pearson r = 0.994；(c) 跨层组代价与重建 MSE 的 Pearson 相关（8 个 KV 头平均）；(d) 连续分组 vs 协方差感知分组的组代价（上）与 VQ 重建 MSE（下）。

实验在 SGLang 里实现（含 Triton 注意力 kernel），效率实验跑在 RTX 6000 Ada 上。标定统一用 64 段 2,048-token 窗口（48 段 gpqa main + 16 段 CodeParrot 代码）。位宽换算见下表（论文表 5）：TaSQ 的 key 是 1024 质心 VQ 加一个 16-bit 跨头尺度，即 10/8 + 16/(8·128) = **1.266 bit/通道**；value 保持 1024 质心 VQ 的 1.250 bit/通道。

- 相对 BF16，KV cache 池从 235,257 token 扩到 2,935,184 token（**12.48×**），最大 batch 从 6 提到 84（**14×**），峰值吞吐从 220.8 提到 412.6 tok/s（**1.87×**）。
- VQ 编码让首 token 延迟（TTFT）增加 10%–14%（8k–32k prompt），但这笔一次性的 prefill 成本能在长生成里摊薄。
- **推理稳定性**是这篇的一个亮点：低比特 KV 压缩常把推理模型带崩，生成内容重复/语无伦次，一直吐到长度上限。图 4c 显示 TaSQ 的生成长度分布和「撞上限」率都贴近 BF16（平均 11,439 vs 9,625 token；撞上限率 3.8% vs 0.2%），而 CQ 平均吐到 19,022 token、撞上限率 20.0%。避免撞上限同时改善准确率和效率，因为没结束的生成几乎必然失败、还吃满解码预算。

## 五、工程启示与批判性评估

**能直接用的结论：**

- **在 pre-RoPE 空间量化 key 是一条性价比很高的选择。** 免去了 RoPE 位置相关旋转对分布的「摊平」，重建误差天然更低（低 35%），而且天然对超长上下文更鲁棒——NovaKV 的惨败就是反面教材。
- **变换要选能被「吸收」的形式。** TaSQ 的全部定制（加权、置换）都能合并进投影权重和码本，运行时零额外 kernel；而稠密 Ã^(1/2) 那种看似更强的方案，光恢复 key 就要在 16k 上下文下多吃 103% 的注意力时间，还会在 GSM8K 上更差。**「能离线吸收」比「理论上更优」重要。**
- **元数据比特要抠。** 把逐头尺度改成跨头共享，每通道省 0.109 bit——在 1.25 bit 的总盘子里这是近 9%，用来加倍码本后失真再降 20%。
- **别只看平均分，要看长上下文和推理稳定性。** NovaKV 在通用任务上不差，但长上下文崩、推理模型撞上限率高；TaSQ 相对 BF16 的平均生成长度（11,439 vs 9,625 token）和撞上限率（3.8% vs 0.2%）都接近。

**需要留意的点（含论文未写、从开源仓库扒到的信息）：**

- **复现需要他们的 SGLang 分支，不是主线 SGLang。** 仓库 `python/` 目录是他们 fork 的 SGLang（NOTICE 标明基于上游修订 0bdb71d33），KV 存储、量化与注意力 kernel 都做了改造（含 nsn 系列的量化/读取模块、QuantKernel/fused_hadamard_int2_kv.py、vq_codebook.py、unified_kv_pool.py 等）。想直接套到自家推理栈，得自己移植这些 kernel。
- **环境要求偏重、且有个坑。** 需要建两个 conda 环境：`tasq-serve`（transformers 5.x）用于标定与推理，`tasq-eval`（transformers 4.53.x）专门给评测客户端——因为 lm_eval 0.4.9 在 transformers 5.x 下无法 import（它会读已被移除的 `AutoModelForVision2Seq`）。论文正文完全没提这一点，但这是复现时第一个会撞上的墙。
- **标定语料/超参是「论文外信息」。** 默认标定 = KVQuant 侧的 `gpqa_code` 语料，64 段 2,048-token 窗口其中 16 段来自 CodeParrot；CQ 基线配置 num_coupled=8、abits=10、稀疏度 0.99；开关 `SGLANG_VQ_OPT_KMAP`。这些都是论文正文一笔带过、仓库里才写全的。
- **效率数据只在 RTX 6000 Ada 单卡上测**（除表 8 的稠密恢复在 RTX 3090）。Ada 是 48 GB 的消费级/工作站卡，没有 NVLink，也没有 Hopper/Blackwell 的 FP8 tensor core 路径；论文的「1.87× 吞吐、14× batch」是单卡结论，扩展到多卡张量并行、以及 Hopper/Blackwell 上的表现都还没验证。
- **1.87× 不是纯收益。** prefill 的 TTFT 增加 10%–14%（VQ 编码成本）。短 prompt、短输出的场景里这笔账未必划算，论文的收益建立在「长 prompt + 长生成」的摊薄之上。

## 六、结论

TaSQ 的核心论点很干净：**在 1-bit 这种极限码率下，与其改 VQ 的查表结构，不如先把 key 的目标空间「定制」成与误差敏感度和统计结构对齐的样子**。三个变换——query 引导加权（对齐敏感度）、跨头共享尺度归一化（压离群、省元数据）、协方差感知分组（把相关通道塞进同一码本）——全部可以离线吸收进投影与码本，因而保留了传统 VQ 的查表结构、运行时几乎零开销。它在通用、长链推理、长上下文检索三类任务上一致优于既有低比特 VQ 基线，还在单张 RTX 6000 Ada 上把 batch 提升 14×、吞吐提升 1.87×，同时保住推理稳定性。

对做 LLM 推理 Infra 的同行，这篇值得看的不是某个具体 kernel，而是**「变换要能离线吸收」这条设计原则**——它决定了你是拿到 1.87× 的净收益，还是被运行时恢复成本吃掉全部好处。
