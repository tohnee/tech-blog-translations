## 简介

topk是目前大模型中很重要的算子，topk的主要使用场景：

- MoE中

例如：从 N 个专家 FFN 中挑 k 个（如deepseek V3 的 256 选 8）

- DSA（deepseek sparse attention）中

例如：从128K的历史token中选2048<br>[https://arxiv.org/pdf/2512.02556](https://arxiv.org/pdf/2512.02556)

在MoE中可能并不是性能瓶颈点，但随着sparse attention的广泛应用，topk的性能压力也开始变大，逐渐成为性能热点。

## topk主流算法

### Wrap select TopK

基于分治的思想，很naive的加速方式就是把topk分块并发来加速，具体思想如下：

分为两个阶段 two-stage：<br>stage1: 每个 block 处理 input 的一个 tile 每个 block 输出自己的 top K<br>stage2: 合并所有 block 的 top K 得到全局 top K<br><br>对于任意两个集合 A、B：<br>TopK⁡(A∪B)=TopK⁡(TopK(A)∪B)TopK(A∪B)=TopK(TopK(A)∪B)<br>如果某个元素 a∈A 连 A自己的 TopK 都进不去，那么在 A内至少已经有 K 个元素优于 a。加入 B后，这K个元素仍然存在，因此a不可能进入A∪B的TopK。

### Bucket select TopK

在分治的思想上，Bucket select topk是进一步对topk进行优化；topk是一个比较耗时的算法且性能与候选集和K有关；直方图统计，或者campare + count的方式可以用较小的开销将候选集进行缩小。因此Bucket select topk本质上是通过较小开销来减少候选集大小，以提升topk整体性能。

算法流程如下：

1. 初始化，找到输入数据的min，max值（可选步骤，目标是为了快速收敛，也可以通过采样来获取近似min，max）。
2. 选桶（例如16个桶），在min，max之间切段，分出16个阈值。每个阈值为：threshold_i = min + (max - min)/16 * (i + 1)。
3. Histogram 计算每个threshold_i 的inclusive的前缀和cumsum_i。
4. 找到第一个cumsum_i >= K 对应的threshold_i
5. 那么topk的K个元素应该在threshold_i，threshold_i+1之间。extract提取出此区间的数据。如果threshold_i，threshold_i+1之间的元素个数大于某个阈值M，那么threshold_i=min，threshold_i+1=max重复2~4的步骤，直到threshold_i，threshold_i+1之间的元素个数小于阈值M时，初筛结束，进入topk主流程中，topk的主流程可以是Wrap select TopK算法实现。

桶数选择：通常来说，桶的数量会影响算法的收敛速度和性能，具体来说，16个桶对应要分出16个阈值，如果数据类型是fp16，那么每次分出16个阈值除16的操作等效于右移4位，因此4次迭代后阈值不能再缩小。同样的道理，如果是4个桶，那么每次相当于右移2位，最多可以迭代8次。

阈值M的选择：通常来说，阈值M的选择需要balance再做一轮筛选和直接调用后续topk算法的性能。假设再做一轮迭代的性能开销为T_h_nk，对应此时直接调用topk的开销为T_topk_nk。如果迭代后再调用topk的开销为T_topk_mk。如果T_h_nk < T_topk_nk - T_topk_mk。那么再做一次筛选是值得的。

### Radix Select TopK

Radix Select TopK算法和Bucket Select TopK算法在思想上几乎一致，只是初筛的方式稍微变换了一些。

需要注意，Radix Select TopK只能处理无符号整数，如果输入是浮点类型，需要先做一个保序映射（单调变换，保证变换后的整数类型大小关系与原浮点数一致），核心是为每种 dtype 定义正确的 sortable key 映射。<br><br><br>算法流程如下：<br>设当前已确定的高位前缀是 `prefix`，候选集为 C，要在 C 中找第 kk 大：

1. 提取位段：取键的第 p 个 r-bit 窗口（从Most Significant Bit最高有效位数起），`b = (key >> shift) & (2^r − 1)`，共 2^r 个桶；
2. 建直方图：统计 C 中每个桶的元素个数 H[b]；
3. 从高端累计：因为我们找的是第 k 大，从最大的桶往下累加，得到 `cum(b) = 比桶 b 高的所有桶的元素总数`；
4. 定位目标桶：找到 b* 满足 `cum(b*) < kk ≤ cum(b*) + H[b*]` —— 第 kk 名必在此桶；
5. 更新并收缩：`kk ← kk − cum(b*)`，`C ← {x ∈ C : 位段(x) == b*}`，进入下一轮。

候选集每轮都会缩小，直到 |C| 小于阈值M时，初筛结束，进入topk主流程中，topk的主流程可以是Wrap select TopK算法实现。<br>

## Topk K值优化

通常来说，对于topk算法而言，K值越大，耗时越大。我们可以找到一个topk算法的甜点区，例如N/2（N是候选集大小），如果K大于N/2，则将问题转换为从N中找出topk变成，从N中剔除top_N-K，N-K作为新的K值，此时新的K'是小于N/2，同时largest变成smallest，smallest变成largest。并标记上此时最终结果需要做剔除。注意：此方法需要要求topk的输出不要求排序的情况，否则最终结果还需要做一次排序可能耗时更大。
