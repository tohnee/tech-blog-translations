## 混合精度算法

### FFN 层可以按中间维度切开为神经元

在展开之前，先明确一个基本逻辑：FFN 层是可以拆的。Transformer 里的 FFN，大家都知道是两个线性层中间夹一个激活函数：up_proj → act → down_proj。中间维度的每一行（或者说每一对 up/down 的对应维度），就可以看作是一个神经元。你给它输入，它算一个标量输出，然后再投影回去。这个 dense 模型和 MoE 模型是一样的。

![](https://pic4.zhimg.com/v2-72b8d1fce0c7aab06a622b57b139041d_r.jpg)

为什么要讲这个呢？因为今天说的 MoE 的混合精度，本质上就是选择把 FFN 切成多大的块来分配位宽：

- 最粗的：整个 FFN 一个位宽：也就是**层粒度**
- 细一点：每个专家一个位宽：**专家粒度**
- 再细一点：每个专家的 FFN 切成 N 份，每份一个位宽：**微专家（micro-expert）粒度**
- 最细的：每个神经元一个位宽：**神经元粒度**
- （一个特殊的：专家内部按三个投影块（gate/up/down）分开，各一个位宽：**投影块粒度**）

理论上越细越灵活，精度也越高。但工程上越细越难实现，调度开销也越大。所以不同的工作选了不同的折中。后面聊到的各种方法，不管叫什么名字，本质上都是在这条粒度轴上选了一个点，然后设计了一套对应的分配算法。

### MoE 又怎么进行混合精度量化

我们先看看 MoE 结构下的异构情况，理解了异构才容易进行差异化混合嘛。

第一层异构是**专家之间的差异**。不同专家的激活频率差很多，有的专家每个 token 都被路由到，有的专家半天不开张。激活频率高的专家，它的量化误差会被更多次地放大到最终输出里，自然就更重要。

第二层异构是**专家内部的差异**。同一个专家的 FFN 里面，不同神经元的重要性也差很多。这个在 dense 模型里也存在，但是 MoE 专家因为本身就是稀疏激活的，内部的差异可能更大。

![](https://picx.zhimg.com/v2-a2db6d69cff993c1be6e2628a79cba5f_r.jpg)
*DartMoQP 论文中对不同 bit （不同颜色）的所有神经元（横轴）在按 profile 重要性（可以是 loss 也可以是 energe）排序的展示，这说明在每个专家内部都存在神经元对结果贡献度的差异。*

第三层异构是**层级的差异**。浅层和深层的专家对量化的敏感度不一样。这个 dense 模型也有，但是 MoE 因为参数量大，调整空间也更大。

第四层异构，多模态模型里还有一层：**token 模态的差异**。视觉 token 和文本 token 对专家的使用模式完全不同，视觉 token 内部还有关键和冗余之分。这层异构纯语言模型里没有，是多模态 MoE 特有的，后面 MODE 会展开。

所以问题就来了：**给定一个总的位宽预算（比如平均每个权重 1.5 bit），怎么分配这些 bit 才能让模型精度损失最小？**这就是混合精度量化要回答的问题。

更进一层的问题是：**在量化时有些神经元实在是太不重要了，给 1 bit 都是浪费，能不能直接剪掉？**这就引出了量化和剪枝的统一问题。CAMERA 没有把两者统一起来做：CAMERA-P 只做剪枝，CAMERA-Q 只做量化，两者共享一套神经元排序方法。

再进一步：**不同的量化算法（per-row 的 GPTQ 和向量量化的 TurboQuant），它们的误差特性完全不一样，敏感度排序也不一样，能不能用同一个搜索框架来搞定？**

这篇笔记就简单看看能不能梳理清楚这几个问题。

### 专家级混合精度

先从最粗的粒度说起——专家级混合精度。也就是每个专家作为一个整体，分配一个位宽，专家内部所有参数用同样的精度。专家级的好处是简单、规整，也最容易工程落地，kernel 好写的很。因为专家本身就是 MoE 里的天然单元，路由、加载、计算都是以专家为单位的，混合精度只需要在专家层面做个映射表就行。

**GEMQ**

GEMQ 是比较有代表性的全局专家级混合精度方法。核心思路就是全局搜索：在所有专家中搜索一个最优的位宽分配方案，使得总的量化误差最小，同时满足平均位宽的约束。

![](https://pic4.zhimg.com/v2-de861feb0c919ffe50810d060c499591_r.jpg)

它用了自己的敏感度指标来衡量每个专家的重要性，然后做全局的最优分配。和简单的按激活频率排序不一样，GEMQ 的指标考虑了更多因素，比如权重的分布、Hessian 信息等等。搜索过程也更系统，不是贪心的而是全局最优的。

不过坏处就是粒度太粗了。一个专家里面可能有非常重要的神经元，也有打酱油的，但是都被绑在一起分配同一个位宽，不够灵活。

**ExQuant**

ExQuant 也是专家级搜索的路线。和 GEMQ 类似，也是在专家层面做混合精度的分配。区别主要在于敏感度的衡量方式和搜索策略。这两篇论文差不多时间出来的，思路也比较接近，都是在专家这个粒度上做全局搜索的优化。

![](https://pica.zhimg.com/v2-ce3b15160b4d7b7e29e71236a1c40972_r.jpg)

**MODE**

MODE 是 EMNLP 2026 的工作。粒度上和 GEMQ、ExQuant 一样是专家级，但切入点很特别：专家级混合精度在纯语言的 MoE 上挺好使，搬到多模态 MoE（MoE-MLLM）上就不太行了。为什么？因为专家重要性的估计本身有偏。

![](https://pica.zhimg.com/v2-3f78dd1d89ad0d6eb6c31279db02621e_r.jpg)

它发现了两层偏差。第一层是跨模态偏差：一张图编码出来几百上千个视觉 token，文本 prompt 往往只有十几个 token。全局的频率统计基本被视觉 token 主导，那些主要被文本 token 路由的专家，虽然对文本推理很关键，但在总频率里排得很靠后，直接被低精度干掉了。论文里给了个例子：Qwen3-VL-30B 第 12 层的 E56，文本侧激活频率数一数二，总频率却低于层平均。第二层是视觉内部偏差：视觉 token 里大概 80% 是冗余的（背景、重复内容这些），它们在频率统计中同样占权重。更麻烦的是，关键视觉 token 和冗余视觉 token 路由到的专家群是不一样的，冗余 token 把统计结果进一步搅浑了。针对这两层偏差，MODE 分三步。第一步，把专家选择频率按模态分开统计。第二步，测模态分开的量化敏感度。第三步，把频率和敏感度的乘积扔进 ILP 求最优分配。分配完之后还是走 GPTQ 校准（对称、group 128），attention 和 router 固定在 4 bit。

![](https://pic3.zhimg.com/v2-0a5d93b8c3068e3251e9fc9b6d667f10_r.jpg)

我的感觉是，MODE 的贡献不在粒度也不在搜索算法——它和 MxMoE 用的是同一套 ILP（整数线性规划）框架（论文自己也引了相关工作），贡献在于把"专家重要性"这个测量环节修正了：不是换一个敏感度指标，而是指出原来的测量方式在多模态下有系统性的偏差。

**总结：**专家级的方法，提升是有限的。毕竟 MoE 本身专家就很多了，但是你再怎么调配，也只能在专家之间调，调不动专家内部的。不过好处也还是有的，混合粒度相对容易调度和加速。

### 投影块粒度：专家内的混合

MxMoE 的搜索粒度与其他方法都不相同，它是专家内部的三个投影块——gate/up/down 各分配一个位宽。这个粒度介于专家级和微专家级之间，还有个天然的好处：三个投影块正好对应三个 GEMM，和硬件的计算单元天然对齐。再往细做，channel 甚至 element 级的混合精度，MxMoE 论文里明确说会带来不规则访存和位宽查表开销。所以投影块是一个特意选在硬件友好位置的粒度。

![](https://pic4.zhimg.com/v2-efa511f3cc82514c249d0b78a0f43a6d_r.jpg)

一个有意思的分配结果：论文附录里 Qwen1.5-MoE 的 W5A5 方案，gate 和 up 基本都是 4 bit，down_proj 一大半是 8 bit。原因是 down_proj 的输入激活里有大量 outlier，附录里有一张位宽-激活位宽的 PPL 表，W5A5 是 38.7，W5A4 是 12305，激活位宽从 5 降到 4 直接爆炸。这说明投影块这个粒度正好抓到了 down_proj 的特殊性——如果是专家粒度，gate/up 就被 down 绑架着一起提精度，浪费预算。

### 微专家粒度：更细的混合

如果说专家级是粗粒度，那微专家（micro-expert）就是细粒度了。粒度细了，预算就可以更精准地投放到重要的地方。

**CAMERA**

CAMERA 是比较早做到微专家粒度的工作。图在前面。

它的核心排序思路是**能量 energy ：**根据每个微专家的激活能量（大概就是被激活的频率乘以权重的大小）来排序，然后分配不同的位宽。能量高的多给 bit，能量低的少给 bit。这个方法很直观，不需要复杂的校准和搜索，统计一下就完事儿了。不过能量排序毕竟是个启发式指标，它不一定能精确反映真正的量化敏感度。比如有些神经元虽然激活频率不高，但是一旦激活就是大数值，对输出影响很大。能量排序可能就低估了它的重要性。

值得提一下的是，CAMERA 的排序是**跨专家全局**的：所有专家的所有微专家放在一起排，统一分配，不是每个专家自己内部排。这样预算可以在专家之间流动，不重要的专家那里省出来的 bit 可以给重要的专家用。具体的分配方式也比较简单：三档混合精度 [b+1, b, b-1]，按一个比例超参 r 来切分，排前面的给高位宽，排后面的给低位宽。论文中直接使用了 1/10、8/10、1/10 的分配比例。

CAMERA 还做了量化和剪枝：能量最低的那部分微专家直接剪掉（0-bit），剩下的按能量高低分配不同位宽。但是不是同时做的，两者是分开用的：CAMERA-P 做剪枝，CAMERA-Q 做量化，共享一套能量排序的结果，但两者并没有统一到同一个损失空间里去。

**DartMoQP**

DartMoQP 也是微专家粒度的路线，在 CAMERA 的基础上往前走了几步。主要有两个不同的地方：一个是把量化和剪枝统一起来做，一个开始使用 TurboQuant 等向量量化方法（前面大家用的主要是 GPTQ、AWQ 等量化方法）。

![](https://pica.zhimg.com/v2-68fa934c311fcccc14a9a904b93c3fd0_r.jpg)

![](https://pic1.zhimg.com/v2-c53e1ef4159c5a0363874fec9a131e1e_r.jpg)

这里有个挺有意思的问题：**剪枝和量化，到底是一回事还是两回事？**直觉上，剪枝就是 0-bit 的量化嘛，把位宽设为 0 剪掉，但哪些剪掉，哪些低比特，哪些高比特呢？实际上之前的方法都把它们分开处理，因为量化误差和剪枝误差不在同一个度量空间里。或者换个角度说，量化是连续的失真，剪枝是阶跃式的跳变，很难直接放一起比较。

但是 DartMoQP 提出了一个观察：不管是 per-row 的 GPTQ 还是向量量化的 TurboQuant，**量化损失在对数域上都符合一个二次函数：log L(b) = p·b² + q·b + r**。其中 b 是位宽，L(b) 是对应位宽下的量化损失。这个拟合的 R² 超过了 0.99，在常用的 1~4 bit 范围内非常稳。出发点很简单：既然 1、2、3、4 bit 的损失都在这条曲线上，那把曲线外推到 b=0 的位置，不就得到了 0-bit 的损失估计了吗？换句话说，剪枝损失可以通过量化损失曲线外推得到，并且和量化损失处在同一个连续的损失空间里。这样一来，量化和剪枝就统一了，搜索的时候，0-bit（剪枝）和 1、2、3、4 bit 一样，都是候选方案，搜索算法不需要知道哪个是剪枝哪个是量化。当然，这个假设只是一个经验发现，缺乏严格的理论证明，论文也只是通过实验验证了这个趋势。

论文通过实验发现，**在超低比特位宽下（比如 1 bpw 以下），这个统一建模的收益特别大**。因为这时候很多不重要的神经元，给 1 bit 不如直接剪掉——剪掉还省了量化参数（scale、zero point、codebook 这些），把省下来的 bit 预算给更重要的单元。实验里关闭 0-bit 剪枝之后，PPL 上升了 15%~30%。

这个外推方法并不是所有神经元 100% 严格遵守的，论文里在多个模型上做了验证，整体来看 R² 都挺高，但不同模型、不同层之间还是有差异的。几个 16B 以内的模型每一层都在 99% 以上，不过 Qwen3-30B-A3B 模型例外多一些。还有一个规律：越不重要的神经元，外推越不准。因为不重要的神经元本身损失就小，量化误差的波动也大，曲线的形状没那么规整。不过反过来说，这些神经元本来就不重要，外推不准对最终结果的影响也有限。

**搜索方法**

而在统一了搜索空间之后，具体的分配算法用的是动态规划（DP）。和 CAMERA 那种排序后按比例切三档的 rule-based 方式不同，这里是在预算约束下找最优解，不需要手工调比例超参，而且 {0,1,2,3,4} bit 都可以选，粒度更细。搜索也是跨专家全局做的，这一点和 CAMERA 的思路是一致的。

一个细节：不同 bit 下相同神经元 profile 出来的 loss，也就是排序依据，其实都不相同。而方法先把所有微专家按敏感度排序，然后加一个非递增分配约束，排前面的微专家分配的位宽不能比排后面的低。这个约束看起来有点强，但是其实验证明是合理的：因为敏感度排序在不同位宽下基本是稳定的，重要的单元在各个位宽下都重要，不重要的都不重要。所以最优分配很少违反单调性。

这里 DartMoQP 还只在层内进行搜索，没有做全模型的同时搜索。这个当然可以做，看来是可以作为一个优化点，从 GEMQ 的结果看收益应该还是可观的，不过方法上就没有什么创新性了。

![](https://picx.zhimg.com/v2-08008ca161c7ed8205a18f88113e7815_r.jpg)
*左边三个是相对较平均的专家，右边三个是差异较大的。每三个一组中，左边是专家内自己排序按 1.5 bpw 分配，中间是 1-4 bit 分配，右边是有 0bit 一起分配。*

例如，搜索出来之后的微专家分布，图上每个专家都被切分成了八个微专家。有些搜索出来专家差异不大，有些则比较大。

### 不同量化器下的敏感度

前面讲的都是"怎么分配 bit"的问题。

还有一个同样重要的问题："怎么衡量一个单元重要不重要"——也就是敏感度指标的问题。CAMERA 采用的是 energy importance 的方法，论文宣称其代表的物理含义是激活系数的 L2/L∞ 范数（调用频率与峰值强度）× 基向量范数（知识储备规模），用来回答"谁重要、谁不重要"。DartMoQP 采用的是 profile 神经元 loss 的方法。不过从最终结果来看，两者对分配结果的影响不大。

还有一个维度：换了数据分布，指标也会失效。前面 MODE 在多模态场景下也有类似发现：同样的激活频率统计，放到图文输入上会被视觉 token 主导，按模态分解之后才能找回文本侧的关键专家。所以敏感度指标这件事，量化器是一方面，数据分布是另一方面。

那么一个新问题：如果换了不同的量化器之后，loss 可以直接平移吗？

**per-row 量化时代的指标**

在 per-row 量化（GPTQ、AWQ 这类）的时代，敏感度指标相对直接。权重空间的 MSE、Hessian 加权误差、激活频率乘以权重大小，这些指标基本都能用。虽然各有优劣，但至少都能区分出重要和不重要的单元。其实我认为 CAMERA 的能量排序本质上也属于这一类，就是看权重和激活的乘积，大致反映一个单元的贡献。

但是到了向量量化这里，事情就变了。

**TurboQuant 带来的新问题：输入流形感知损失建模**

TurboQuant（以及类似的 QuaRot）的核心操作是随机正交旋转。把权重矩阵乘一个随机正交矩阵，把异常值摊平到所有维度上，然后就可以用向量量化（VQ）来压到很低的比特。这个方法本来是用在 KV Cache 压缩上的，不过很多工作实测用在权重上效果也挺好，在很多模型上都比 GPTQ 好。但是它带来了一个副作用：旋转之后，权重空间的 MSE 在不同神经元之间变得几乎一样了。

![](https://pica.zhimg.com/v2-aacd1022d5936c09ebc18d40d95940d8_r.jpg)
*图上是不同神经元在不同 bit 下的 loss，GPTQ （左图）是比分散的，TurboQuant 的 mse （右图）则是集中在一起的，bit 间没有 overlap，这造成了 DP 搜索时没有区分度，搜不出好的方案，而中图是使用内积损失的 TurboQuant。*

因为正交旋转是几何各向同性的，转完之后每个维度的能量都差不多。你再算每个神经元的权重 MSE，大家都一个样，分不出谁重要谁不重要。

这就麻烦了。混合精度搜索的前提是你能给单元排个序，现在排序信号没了，还怎么搜？针对这个问题，DartMoQP 提出了一个思路：不要在权重空间衡量，要在**输入流形**上衡量。什么意思呢？就是量化误差的影响，不应该看权重本身变了多少，而要看它对前向输出的影响有多大。具体来说，用校准数据跑一遍，计算量化误差在输入分布方向上的投影：也就是内积损失（inner product error），这在 TurboQuant 论文中是已经明确说明的。这个指标的直觉是：一个神经元就算权重变化很大，如果它很少被输入激活，那它对输出的实际影响也不大。反过来，一个神经元虽然权重变化不大，但是如果输入经常激活它，那影响就大。在 TurboQuant 的旋转下，权重空间的差异被抹平了，但是输入分布的差异没有被抹平。不同神经元被校准数据激活的频率和强度还是不一样的。所以用输入流形感知的损失，就能重新把敏感度排序给找回来。

实验里这个方法的意义非常明显：如果还按 TurboQuant 的权重 MSE loss 来排序，混合方案的效果甚至不如随机分配。

这也是为什么 DartMoQP 说自己是**量化器无关（quantizer-agnostic）**的框架——不同的量化器有不同的误差特性，敏感度指标也要跟着变。per-row 的 GPTQ 用 Hessian 感知的损失，向量量化的 TurboQuant 用输入流形感知的损失。搜索框架是同一个，只是换个损失函数就行。

**顺带一提：种子敏感性**

这个是 DartMoQP 论文里发现的一个挺有意思的副产物。

TurboQuant 因为有随机旋转，所以不同的随机种子会导致不同的量化效果。有的种子下效果很好，有的种子下效果很差，PPL 波动可能挺大。这个问题其实挺烦人的，你量化一个模型，还得碰运气吗？DartMoQP 的混合精度分配，还意外地缓解了这个问题。为什么呢？因为种子导致的波动，主要是因为某些关键的高敏感度神经元，在某些种子下被旋转得"不好"，损失变大了。而混合精度会给这些高敏感度神经元分配更高的位宽，相当于给它们上了个保险——不管怎么转，高精度下的损失都是可控的。

实验里，DeepSeek-MoE-16B 上 6 个种子的 PPL 范围从 16.5~33.8 被压缩到了 11.4~11.5，几乎抹平了种子波动。

### 混合精度量化中的共性问题

以上是几篇论文的核心内容，不过主要针对的是它们之间有差异的部分，其实还有很多共性问题没有涵盖到。

**MoE 混合精度模型中 attention 和其他模块的量化问题**

现在 MoE 在成为事实大模型标准之后，attention 占实际参数量的比例越来越小。大部分模型 attention 参数量不到 3%，更大的模型可能只有 1% 了，但是 2-bit 全量化会直接崩掉，几篇论文都有所涉及。attention 保 4-bit 之后平均分能从 34.99 拉回到 50.88，相对涨了 45%。参数量小但是很重要，并且在 MoE 场景下压缩低比特的收益实在是太小。

attention 之外还有一堆"边角料"：router、embedding、lm_head，多模态模型还有视觉模块。这部分参数占比小，敏感度却极高，各家的处理五花八门。MxMoE 干脆只管 MoE block，attention 保持全精度；DartMoQ-Qwen3.5 是 attention 8 bit、lm_head 和 CLIP 保持 FP16；MODE 是 attention 和 router 固定 4 bit、视觉模块保持全精度。现在暂时没有一家给出过系统分析，都是"试出来这样不掉点"。

其实这笔账是可以算的：MODE 附录里算过，attention 从 2 bit 提到 4 bit 的代价，等价于每层 8 个专家各降 1 bit。预算在"专家 vs 非专家"之间怎么切分最优，还没有人系统做，直觉上这可能比专家内部的分配还要值钱。

**专家激活对量化的影响**

MoE 模型的统一量化问题，很多论文都已经深入讨论过了，其中有一些问题在混合精度场景下同样存在，比如专家激活情况的影响，上面几篇论文都或多或少有所涉及。第一层是频率。激活频率高的专家，量化误差被放大更多次，所以更重要。这是所有专家级方法的根基——CAMERA 的能量、GEMQ 和 MODE 的频率、MxMoE 的扰动加权，本质都在数"被用了多少次"。MxMoE 测出专家激活频率最高差 15.3 倍，说明这层信号确实强。反之，激活频率低的专家，校准集覆盖少，可能没有被准确统计到；但是为了少数冷专家而增加整体校准集的数据，又会带来不可忍受的校准时间和 profile 时间。

**"精度-预算"帕累托曲线**

混合精度方法的公平对比其实很难。在同一个平均位宽下比 PPL 是单点对比，但各家"平均位宽"的口径根本对不齐：MxMoE 拿 5-bit 混合去打 QuaRot 的 4-bit 统一，MODE 把 attention 锁在 4 bit 再让专家混合，量化参数的额外开销有的算进 budget 有的不算。一个可以对齐的正确姿势是画帕累托曲线：横轴是预算，纵轴是精度，方法之间的优劣就看谁的曲线更靠左上——任意预算下都不被别的曲线压住，才是真的强。更好的方法，整条曲线都在外面。

![](https://pic4.zhimg.com/v2-406be57f96c22cd99be791a7f45f2385_r.jpg)
*左图是 exllamav3 中的帕累托最优曲线，中图是一篇 dense 混合精度搜索论文 AMQ 中的穷举搜索的空间，其边界就是个帕累托最优曲线，右图则是 DartMoQP 的对比曲线，也是帕累托最优曲线。*

而我觉得比较有趣的是，混合精度因为可以在任意 budget 下搜索，大部分方法都能画出一条连续且光滑的曲线。这代表着在相同算法下，一分 budget 一分货，给一点精度预算就能拿到一定的性能提升。同时这条帕累托曲线也是一条边际效用递减曲线：极低比特下，给一点预算就能提升很多；超过某个比特数之后，更多的预算已经带来不了什么提升了。

**极低比特下，量化参数开销愈发明显**

位宽越低，scale、zero point、codebook 这些量化参数的占比越高，混合精度让这笔账更不好算。ExLlamaV3 的 16x16 trellis 强制补零，codebook 还大；DartMoQ-Qwen3.5 在 2 bpw 下量化参数开销是 0.127；DartMoQP 反过来把量化参数当成了剪枝的收益——0-bit 剪掉之后连参数都不用存，省出来的 bit 挪给重要单元。MxMoE 的分配表里还有个容易被忽略的细节：gate/up 用 group 128，down 用 per-channel，group size 本身也是跟着分配走的。所以混合精度的搜索空间其实还有一个维度：group size。同一个位宽下，group 大小的选择同时影响精度和参数开销，目前只有 MxMoE 顺带做了，其他方法都是固定的。

## 工程落地

聊了这么多算法，也得说说工程上的事。

算法上的混合精度方案再好，推理的时候跑不快、不好部署，也是白搭。工程上做混合精度，最大的挑战不是算法，而是**内存布局和调度**。

算法层面你只需要说"这个组 1 bit、那个组 4 bit"就行了。但是工程上，你得考虑：

1. **内存对齐**。不同位宽的数据怎么存？怎么对齐到硬件要求的边界？
2. **kernel 调度**。一个 kernel 里如果有不同位宽的数据，是写一个通用 kernel 还是每个位宽写一个？通用的效率低，专用的 code size 大。
3. **反量化等额外开销**。混合精度意味着反量化的参数（scale、zero point、codebook）也更复杂，读取和计算的开销都会增加。WxA16 时明显严重，A8 A4 时也有激活值现场量化的开销等。另外还有向量量化方法的旋转矩阵等额外开销。
4. **batching 和 padding**。混合精度下 padding 怎么处理才能不浪费计算？

这批工作里，工程上正好凑齐了三种姿势：MxMoE 的 kernel 自动生成、ExLlamaV3 的手写 CUDA 引擎、DartMoQ-Qwen3.5 的纯 Triton 落地。一个个看，正好对比对比。

**MxMoE：kernel 自动生成**

前面 MxMoE 的算法部分聊过了，这里看它系统侧的另外一半，自动生成适合论文方案的混合精度 Group-GEMM kernel。动机很实在：现有推理引擎的 kernel 要么不支持混合精度，要么逐个专家串行调用（vLLM 的 Marlin-MoE 就是这么干的），GPU 利用率上不去。其做法是三层：

1. **micro-kernel 特化**。每个量化方案写一个 CTA 级的 CUDA device function，模板参数配置。专门化的收益很实在：论文里同形状下，W4A4 group128 的专用 kernel 是 667 TFLOPS，统一兼容 kernel 只有 412。
2. **资源配置**。不同精度的 tile 强制 warp 数一致、shared memory 取最大值、k 维切分补齐并行度，这样不同精度的 micro-kernel 才能横向融合进同一个 kernel。
3. **tile 调度**。把不同精度的 tile 混排到 SM 上，贪心做 makespan 最小化，优先调度计算密集的 tile。

自动生成是冲着组合爆炸去的：5 种量化方案的组合，论文估算手写要 120 个 kernel，自动生成只需要写 5 个 micro-kernel。效果上，混合精度的 MoE block 吞吐比 FP16 最高 3.4 倍，同等精度水平下比统一位宽的 W8A8 还快 29.4%。不过这条路线的代价也明显：CUDA 模板元编程，门槛高，而且生成的 kernel 只服务自己的那套量化方案和形状，通用性一般。

**ExLlamaV3**

ExLlamaV3 是目前工程上混合权重量化做得比较好的推理引擎之一。它主要支持的是一种叫做 QTIP 的量化方法下的混合精度，同一个模型里不同层、不同组可以用不同的位宽。QTIP 简单不严谨的理解是，它是 TurboQuant 和 GPTQ 各取其优的一个结合体：既有正交/Hadamard 旋转预处理 + 旋转域量化，又有 GPTQ 的 Hessian 感知误差补偿机制，和它比较像的量化方法还有 QuIP。同时 ExLlamaV3 的额外量化参数开销相比前面两种方法要小，约在 0.05。原因有两个：第一，它的量化 group 不是 row 或者 column，而是 16x16 的 tile（它叫 trellis），且没有额外的 norm——如果和 GPTQ、TurboQuant 的量化参数方式对齐，相当于 256 的 group 配一个 FP16 量化参数，就是 0.0625；第二，它的 trellis 网格本质上是一种 PQ（乘积量化）的方法，需要金字塔树状路径解码，所以 codebook 较大。然后因为强制 16x16 对齐，补零的部分也要存储，这部分 overhead 在 MoE 小专家的情况下还挺明显的。（它这里量化方法本身也比较有趣，但是人家没有发表论文，回头我写一个专门的介绍讲讲）

ExLlamaV3 的混合精度量化搜索层级是专家级的，和 GEMQ 一样。区别是 GEMQ 用 global LP 做严格的跨专家最优分配，EXL3 则不是 DP 搜索，而是先量化出多个固定 bpw 的候选，再按测量结果拼装。

工程实现方面 ExLlamaV3 的做法是在 CUDA kernel 层面支持位宽的混合，通过 bit packing 的方式把不同位宽的权重紧凑地存起来，在 kernel 内部做解包和反量化。

效果上来看的话，我们自己实测出来精度和速度都挺能打。还挺值得深入研究的。有点麻烦就是因为 bpw 不同，相同 budget 就不好对的齐。

从某种程度上说 ExllamaV3 的通用性就不太好，它从量化方法、算法搜索、配置方法、存储格式等等方面，都是独树一帜，并且人家也不发表论文，就是服务开源社区不玩虚的，也是有意思。

**DartMoQ-Qwen3.5**

其实最开始，我认为这种微专家级别的混合精度量化方法，在工程优化层面就是灾难。但通过具体的实践发现，少数几个低比特档位的混合，开发潜力还是很大的，可以做到不错的加速效果——基于 Triton 的 WxA8 推理效率比原始 FP16 快接近一倍。现在 2 bpw + 0.127 量化开销的模型，参数大约占 12 GB 磁盘空间；WxA16 相比 FP16 baseline，wikitext2（bs = 145）快 35.6%、c4（bs = 256）快 23%，WxA8 在这个基础上再快 7% 左右，两者的 PPL 都没有进一步退化。

DartMoQP 对应的落地项目是 ([[DartMoQ-Qwen3.5]](https://github.com/zzningxp/DartMoQ-Qwen3.5))，针对 Qwen3.5-35B-A3B 这种 grouped_gemm 权重格式的 MoE（同架构的 Qwen3.6/3.7/3.8 也适用）中的 TurboQuant 量化方法。项目最近还在开发中，基于 Triton 的 WxA16 和 WxA8 两种方法应该已经支持好了，WxA4 还需要其他库依赖，暂时还没看到开发。落地项目和算法项目的区别主要是没有 3 bit。

首先，项目设计中单独支持了按 bit 分区而不是简单的按专家分区：同一个 bit 的权重从所有专家里抽出来全局拼接成一个大张量，专家内部用 offset 切片。这样 kernel 只需要按 bit 处理，一个通用融合 kernel 支持 1/2/4/8 bit，kernel 内做位宽解包、码本查表、矩阵乘、norm rescale，一次 kernel 完成，中间结果不落地（attention 8 bit 走不解包的快速路径）。

![](https://picx.zhimg.com/v2-a98c62144befb6464e2d1f3e67fca87d_r.jpg)

几个关键的工程点（不完全）：

1. **循环布局**。混合精度方法增加了 bit 循环，让整个优化难度激增。但目前其实只有两层循环：expert 在外、bit 在内；up/gate/down 不是第三层循环，而是 bit 循环体内的两个顺序 matmul。
2. **Group-First 布局**。权重按量化分组连续存储，提升 L2 缓存命中率。
3. **旋转提升（rotation hoisting）**。TurboQuant 中 codebook 和 norms 是 bit 级共享的，而其分组 QR 旋转原本在 per-expert 循环里做，现在提升到循环外：全 token 按 bit 预旋转一次，per-expert 只做切片，零旋转开销。WxA8 下旋转还和激活量化融合成了一个 kernel。
4. **kernel 自动调优**。BlockN、BLOCK、warps、stages 网格搜索，WxA16 和 WxA8 各有一套独立调优表，两者的最优点完全不同。可以针对不同的 GPU 进行自动搜索调优。
5. Qwen3.5 特有的**交替 attention（linear_attn / self_attn）**也做了适配，linear attention 的 chunk delta rule 全路径 Triton 化，pad-skip、WY 闭式解、wy_prep 融合这些细节都抠了。

推理支持两档精度模式，共用同一份 packed checkpoint，一个参数切换：

1. **WxA16**（已完成）：FP16 激活 + FP16 Tensor Core，w1a16/w2a16/w4a16/w8a16 混合权重。
2. **WxA8**（已完成）：INT8 激活矩阵 + INT8 Tensor Core、INT32 累加，attention 还是 W8A16。码本在加载期原地转 INT8，checkpoint 格式不变，零拷贝切换。WxA8 的收益大头来自输入 tile 的访存减半，而不是 MMA 变快，现在矩阵乘并没有吃满 Tensor Core。

不过，kernel launch 开销，GPU 排队，还有 Python 调度开销，目前还存在很多需要优化的地方。<br>

### 结论

当然，离 ExLlamaV3 那种成熟度还有明显距离，现在还是 eval 评测层面的落地：attention 还没进 WxA8；MoE forward 里 per-expert 循环的开销还占 80% 左右的 wall time，下一步要往多 expert 合并 kernel 走；serving 那套（continuous batching、KV cache 管理）也还没接，目前只有 PPL 评测管线。但至少说明一件事：TurboQuant + 混合 bit 这条算法路线，不靠手写 CUDA、纯 Triton 也能在消费级显卡上把速度做上去，精度和 FP16 打平。前面说的算法与工程的 gap，落到这个项目上就是"保留微专家粒度"和"kernel 简单性"之间的平衡，目前这个平衡点看起来是可以接受的。

三种姿势摆一起看挺有意思：ExLlamaV3 手写 CUDA 最成熟，但量化方法、存储格式全部自成一派，通用性最差，自动化程度也最低；DartMoQ 纯 Triton 最灵活，开发效率最高，再靠自动调优把性能追上来；MxMoE 自动生成最省人力，但模板元编程门槛高，生成的 kernel 也绑死了自己的量化方案。三个项目正好是自动化程度由低到高的三个台阶，没有绝对的好坏，还是看需求。算法和工程之间，还是有个 gap 的：算法追求的是精度最优，工程追求的是在能接受的精度损失下把速度做上去。两者的平衡点，还得在实际部署中慢慢摸。

## 总结对比

总体趋势还是挺清楚的：

- 粒度从专家级往投影块、微专家级、神经元级走，越来越卷
- 量化和剪枝从分离走向统一
- 从只支持一种量化器，走向量化器无关的框架
- 从层内/专家内搜索，走向跨层跨专家的全局搜索
- 敏感度指标从单一模态的频率/损失统计，走向按模态分解的修正

当然，越走越复杂，工程落地的难度也越大。

未来估计还有什么方向可以挖？其实也不多了：感觉如果去做也就主要是系统层面的 co-design 了：量化算法和推理引擎、调度系统深度绑定，一起做优化。MxMoE 已经在 MoE 上做了一版（kernel 自动生成），DartMoQP-Qwen3.5 做了一个 autotune 搜索的方法。

先这样吧，混合精度量化在 MoE 上的水还是挺深的，这篇笔记也只是挑了几个代表性的工作聊聊。后面有新的再补充。
