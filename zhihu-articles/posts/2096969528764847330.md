事情是这样的。上周我在折腾 DeepSeek Harness（下面简称 dsh）的配置，想把几个常用模型接进来轮换着用。结果光是注册账号、申请 API Key、绑卡、填 base URL 就耗掉了一个下午，最后还有一个渠道的 Key 死活调不通。

然后我刷到了这个项目。它的 GitHub 简介只有一句话，但杀伤力极强：

![](https://pica.zhimg.com/v2-d4e17378476a5dc96877db05a7952276_r.jpg)

“装上这个插件，无需登录、注册或填 API Key，就能用包括 DeepSeek V4.1 Flash、Kimi K3 在内的前沿模型——完全免费，不限量。”

我第一反应是“又来了，经典画饼”。但看了一眼 Star 曲线，沉默了。上线不到一个月，Star 冲到 **36,951** ，日均增长约 **1,905** ，还拿过 Trendshift JavaScript 周榜第 1。最近它身上还发生了一件更有节目效果的事：收到了一份“律师事务所、承办律师、联系方式全部写着‘待填’、连签章都没有”的两万字符律师函。一个开源插件能被人用这种方式“重视”，本身就说明它戳到了什么东西。

## 它到底解决了什么：不是“又一个聚合器”，是把配置税直接抹掉

市面上聚合免费模型的工具不少，但大多数仍然要你 **自己去找渠道、自己去注册、自己去填 Key** ，本质上是把“多个 Key”变成了“一个地方管理多个 Key”。dsh-our-free-model 走的是另一条路： **插件挂载，零配置接入** 。

它的免费车道来源写得非常清楚：OpenCode 的 Zen 网关、Kilo AI 的公共网关，均直连上游，不经第三方中转。模型清单 **跟随上游刷新** ，每次打开都重新拉取，不保存静态快照，所以不会出现“README 里写着有某个模型，装完发现早就没了”的尴尬。

更细的一点是 **选择器只广播实际可用的模型** 。上游清单声明了但网关明确拒绝路由的模型，会从下拉框里移出，只在设置页留下记录并注明拒因；而网关 5xx、429 限流、超时断网这类“临时故障”，不会误判模型不可用，照样保持可达。这个设计思路很“工程”，它不假装一切永远可用，但尽量不让你在“模型明明挂了”和“只是上游抖了一下”之间做出错误判断。

装好之后，输入框的模型选择器里会多出一个 **“Our Free Model”** 分组，点进去选就行，按会话持久。

## 几个真正让我意外的细节

第一个是 **思考强度下发的是真实预算，不是提示词** 。很多工具在“深度思考”上做的是 system prompt 文章，告诉你“请仔细想”。这个插件对声明了思考档位的模型（比如 DeepSeek V4.1 Flash），直接控制实际的推理预算，菜单里有 Light / Balanced / Deep 三档，回答被截断先切 Deep。至少在机制层面，它没有糊弄你。

第二个是 **本地 OpenAI 兼容转发端口** 。在设置里启用后，它会给你一个 base URL 和一把 Key，你本机的 Claude Code、Codex、curl，任何兼容 OpenAI 格式的工具，都能直接调这些免费模型。这等于把“dsh 里的免费池”变成了“整台机器的免费池”，价值一下子从插件级跳到了基础设施级。

第三个是 **应用内升级的严谨程度** 。下载 → SHA-256 校验 → 备份 → 原子替换 → 校验回读 → 热重载，任一步失败自动回滚上一版本。一个“白嫖”项目把升级回滚做成这样，说实话比不少商业软件的更新流程都靠谱。

## 怎么装：有手就行，但别跳过自检

前提条件： **已安装 dsh 桌面端** ，有 Node.js 环境，网络出口能访问上游网关。

安装的核心逻辑是把插件挂进目标 profile。用 `--dump-config` 确认只挂载了一个 `our-free-model` ，避免重复加载；然后跑一下桌面端自带的 **profile 升级闸门代码** ，检查兼容性再启动，不要盲试。如果遇到 `ERR_PNPM_VIRTUAL_STORE_DIR_MAX_LENGTH_DIFF` ，关掉 dsh，删掉 profile 的 `node_modules` 和锁文件重建即可。

装完打开模型选择器，选中 Our Free Model 分组下的模型，再按需调一下 Effort 档位，就能用了。想给别的本地工具用，去设置里开 **本地转发** ；想在局域网里共享，开 **局域网访问** （默认关闭，开启后需要单独的局域网 Key）。

完整的安装命令、自检脚本和配置项，README 里写得比大多数教程都清楚。如果你懒得翻 GitHub，项目的结构化数据和教程整理在这里可以直接看：

## 值不值得试？我的判断

如果你 **已经在用 dsh** ，并且受够了“接一个模型配一次 Key”的循环，这个插件几乎没有不试的理由。零配置、零 Key、MIT 协议，装上就有几十个模型在输入框里等着，试错成本是几分钟。

但有两件事需要清醒。第一，它的免费车道依赖上游公共网关， **可用性最终取决于你的网络出口和上游策略** ，不是“保证永远免费无限”的服务承诺。第二，那个“待填律师函”虽然没有法律效力，但它指向的问题不是完全空穴来风：这类聚合免密渠道的项目， **长期稳定性天然带有不确定性** 。把它当作“低成本探索前沿模型”的入口，而不是“替代付费 API 的生产级方案”，心态会稳很多。

一个 Star 日均增长近两千、能让别人用假律师函来“回应”的开源项目，本身就值得花五分钟看一眼。至于它能不能一直活下去，没人能保证，但至少现在，它是“零 Key 用前沿模型”这件事上，工程完成度最高的那个答案。
