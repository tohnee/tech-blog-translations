周末趁我们休息的时候，DeepSeek 又突然放出一个王炸：Super-agent（超级 Agent 系统）。

平时一个人的精力始终是有限的，即便现在有了 AI，可能最多就同时管理 3 到 5 个活跃的对话。

这个痛点也深深戳中了 DeepSeek Harness 团队内部的人。

于是他们基于日常实践，打造出了一套能够持续在线、跨平台自主干活的 Agent 系统。

![](https://pic4.zhimg.com/v2-2d5d7b57bf7b80ffa93d7a3d5c965d7b_r.jpg)

其最核心目的就是，让 AI 自己管理多任务工作，减少人盯着 AI 干活的时间。

我们主要负责定目标、做决策、验收结果，AI 自己安排任务、记住前后聊过的内容，同时推进几件事。

系统背后有一个 AI 负责接活和派活，然后多个 AI 开始分工干活，最后再统一回复。

我们还能提前定好规则，当 AI 碰到符合条件的问题，它就会主动处理，不用每次都喊它开工。

按这套系统的设计，它可以持续在线，后台的活还没干完，也能接着处理新的要求。

开发者可以利用它来处理线上问题的反馈和 Bug 的修复，产品经理和设计师也能参与需求调整。

项目已经开源，并配套一篇技术文章详细介绍了这个架构，正在做 Agent 开发的朋友可以看下。

GitHub：[https://github.com/deepseek-ai/dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype)

![](https://pic1.zhimg.com/v2-71a9a30d25ca16d1e6dc6a9c2f5c6e04_r.jpg)

另外，最近我还在 GitHub 上偶然发现了一款功能强大的 AI 编辑器：**Oleafly**。

平时写报告、改简历，哪句话写得不太好，丢给 AI 改一改就行。

改完还得复制回去，看看数字有没有动过，原来的格式有没有乱，改几段还好，多了就有点烦。

碰到有图表、有引用的报告，又得把前后的内容交代一遍，只发几段话，AI 也不知道别处写了什么。

而 Oleafly 正好能解决这些痛点，支持创建编辑 LaTeX、Typst、Markdown 等格式的文件。

![](https://picx.zhimg.com/v2-a64bb3f72451b08817047145ca8a59dd_r.jpg)

它主要面向研究写作，也可以用来写项目报告、技术文档，或者制作求职简历。

我看了一圈支持的功能，还有实时多人协作编辑、评论、排版和版本记录等实用功能。

下面跟大家一起了解下。

我比较喜欢的一点，它可以让我们把平时用的 Claude Code、Codex 等 Agent 接进来。

![](https://pica.zhimg.com/v2-2a307973203c8acb97d7fe0df949265c_r.jpg)

接上后，Agent 能直接读取项目的文档源码，还能查看生成的 PDF，编译报错还有日志可以看。

比如一份项目报告，可以让 AI 精简背景介绍，保留里面的数据和结论，再检查其他章节有没有重复表述。

如果要改的地方比较多，可以让它先看看项目，写一份计划出来，我们觉得没问题了再让它去改。

它改了什么也能看得清楚，新增和删掉的内容都有标记，可以一处一处检查，合适的再留下。

要是改得不满意，单个文件可以撤销，整轮的修改也能一起撤回。

![](https://pica.zhimg.com/v2-a9e208783112aef2bc7c8e8191b5f614_r.jpg)

内容改得差不多，还得看一下排版，Oleafly 把 PDF 预览也放进了编辑器。

写好的内容就在旁边预览，生成一次 PDF，就能看到这一版的分页、公式和图表。

看到哪里不对，点一下 PDF，就能跳回对应的源码位置，改起来方便一些。

编译出了错，会标出相关行，把报错交给 AI 就能让它帮忙排查。

而且修错的时候，旁边仍然留着上一次生成成功的 PDF，可以接着看。

至于报告里常见的流程图、结构示意图，它还内置了一个绘图工具，可以在画布上编辑。

![](https://picx.zhimg.com/v2-68663abcc442ca747c1e7f4fff70c7c7_r.jpg)

画出来的图会保留为 TikZ、Typst 或 Mermaid 代码，画布和代码可以联动修改。

下次流程多了一个步骤、节点名称要调整，就能接着改原图。

自己写得差不多了，还可以请同事进来一起修改，彼此能看到对方的光标和选区。

哪段话有疑问，就选中留下评论，可以回复，也能直接提及某位合作者。

涉及正文调整，还能切到建议修改模式，保留意见，等负责人决定是否采纳。

多人协作需要连接 Oleafly Server，团队可自行私有部署，服务器费用需要自己承担。

![](https://pic4.zhimg.com/v2-2473d54368b3d4aa9d7b6db103c18b9d_r.jpg)

人一多，另一个麻烦就是版本，谁改了哪段、前一版是什么内容，得有地方查。

在共享项目的历史里，可以比较不同版本，给某一版起名字，或者恢复到之前的状态。

另外，每个项目本身也是一个 Git 仓库，提交记录、文件差异、推送到 GitHub，这些都能在编辑器里操作。

就连每次成功编译之后，也会自动留一份本地快照，不用为了保存进度专门提交一次。

暂时断网还能继续编辑，联网后再合并，若和同事的修改冲突，会把两个版本摆出来让我们确认。

![](https://pic4.zhimg.com/v2-0dfe3a55d4f6fdd615b592e7f96e9cc1_r.jpg)

除了上面这些，它还有几项功能可以顺带了解一下：

**模板库**有 31 套模板，论文、简历、演示文稿和海报都有，可以先看预览再选。

**文献引用**支持连接 Zotero，在编辑器里输入 @ 就能查找条目，也能检索论文。

**格式转换**支持 Word 与 LaTeX、Typst 之间互转，工具库目前是实验功能，需要在设置里开启。

**云同步**可以连接 Dropbox、Google Drive 或 S3，换台电脑也能接着编辑项目。

![](https://pic2.zhimg.com/v2-1ee11bd0954a8f0a0d28fec1c27d2043_r.jpg)

想上手的话，去项目的 Releases 页面，按系统下载对应安装包，Windows、macOS 和 Linux 都支持。

安装好之后，可以从模板新建项目，也可以导入已有的 Word 文档，转换后继续编辑。

编译工具已经内置，Mac 按 Cmd+Enter，Windows 和 Linux 按 Ctrl+Enter，就能生成 PDF。

要让 AI 帮忙，再接入已安装的 Claude Code、Codex，或者配置自己的模型 API，本地 Ollama 模型也能用。

![](https://picx.zhimg.com/v2-46bd492ee3bc74ec23c28aabcba6a2f5_r.jpg)

本地编辑和编译不用注册账号，接入外部 AI 的费用按相应模型 API 服务商计算。

项目采用 AGPL 协议开源，允许商用，编辑器和协作服务端的代码均已公开。

### **写在最后**

我觉得这类编辑器比较有用的地方，是写文档和让 AI 改文档，可以在同一个项目里接着做。

写报告时让它帮忙调整结构，改简历时检查措辞，和别人合写论文时把意见留在具体段落，都有相应的功能能用。

经常处理这些文档的朋友，可以先拿一份现成材料，试试让 AI 改一小节，再对着差异和 PDF 看看是否合适。
