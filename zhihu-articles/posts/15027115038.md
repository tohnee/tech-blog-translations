## Thunder Kitten

TK也是基于(Warp级别的）Tensor抽象，用户就不用管最里面那两层无聊的Loop了。`sv`是1D的**S**hared **V**ector，`st`是自带Swizzle的2D **S**hared **T**ile。`rv`是1D的**R**egister **V**ector，`rt`是2D的**R**egister **T**ile，用在mma operand和output上。rv和rt是按照单个Warp来的，同时TK没有提供Triton那样Block/Cluster级的Tensor，用TK封装的warp_group操作的时候，我们要自己注意每个warp拿到了哪块数据。

[GitHub - HazyResearch/ThunderKittens: Tile primitives for speedy kernels](https://github.com/HazyResearch/ThunderKittens)

下面这个是最基本，只用上了async load不带pipelining的Matmul Kernel，编译flags可以参考TK例子里的[Makefile](https://github.com/HazyResearch/ThunderKittens/blob/main/kernels/matmul/H100/Makefile)。不熟悉TK的语法的话，建议开启VSCode/C++的Inlay Hints。需要注意的是TK的load，store，slice shared memory自动会帮你乘上block size，和Triton的`desc.load/store`不一样，TK里再乘一次就会爆炸。

```cpp
#include "kittens.cuh"
using namespace kittens;
#include <cuda.h>
#include <cuda_runtime.h>
typedef bf16 InType;
typedef float AccType;
typedef bf16 OutType;

constexpr int WARP_M = 64;
constexpr int WARP_N = 64;
constexpr int BLOCK_M = WARP_M * 1;
constexpr int BLOCK_N = WARP_N * 1;
constexpr int BLOCK_K = 64;

constexpr int M = BLOCK_M * 1;
constexpr int K = BLOCK_K * 1;
constexpr int N = BLOCK_N * 1;

__global__ void
kernel(const __grid_constant__ gl<InType, 1, 1, M, K> desc_lhs,
       const __grid_constant__ gl<InType, 1, 1, K, N> desc_rhs,
       const __grid_constant__ gl<OutType, 1, 1, M, N> desc_out) {
  extern __shared__ alignment_dummy smem[];
  shared_allocator al((int *)&smem[0]);

  using block_group = kittens::group<BLOCK_M * BLOCK_N / WARP_N / WARP_M>;
  int block_start_m = 0;
  int block_start_n = 0;
  int warp_id_m = warpid() / (BLOCK_N / WARP_N);
  int warp_id_n = warpid() % (BLOCK_N / WARP_N);
  auto smem_buffer_lhs = al.allocate<st<InType, BLOCK_M, BLOCK_K>, 1>();
  auto smem_buffer_rhs = al.allocate<st<InType, BLOCK_K, BLOCK_N>, 1>();

  barrier<WARP_M * WARP_N> bar(1);
  rt<AccType, WARP_M, WARP_N> acc;
  zero(acc);

  for (int k = 0; k < K / BLOCK_K; k++) {
    block_group::load_async(smem_buffer_lhs[0], desc_lhs,
                            {0, 0, block_start_m, k});
    block_group::load_async(smem_buffer_rhs[0], desc_rhs,
                            {0, 0, k, block_start_n});
    block_group::load_async_wait(0);
    arrive_and_wait(bar);

    rt<InType, WARP_M, BLOCK_K, ducks::rt_layout::row> reg_buffer_lhs;
    rt<InType, BLOCK_K, WARP_N, ducks::rt_layout::col> reg_buffer_rhs;
    load(reg_buffer_lhs,
         subtile_inplace<WARP_M, WARP_N>(smem_buffer_lhs[0], {warp_id_m, 0}));
    load(reg_buffer_rhs,
         subtile_inplace<WARP_M, WARP_N>(smem_buffer_rhs[0], {0, warp_id_n}));
    mma_AB(acc, reg_buffer_lhs, reg_buffer_rhs, acc);
  }

  rt<OutType, WARP_M, WARP_N> out;
  copy(out, acc);

  shared_allocator al_out((int *)&smem[0]);
  auto smem_buffer_out = al_out.allocate<st<OutType, BLOCK_M, BLOCK_N>, 1>();
  auto smem_out_slice = subtile_inplace<acc.rows, acc.cols>(
      smem_buffer_out[0], {warp_id_m, warp_id_n});
  store(smem_out_slice, out);
  __syncthreads();
  block_group::store(desc_out, smem_buffer_out[0],
                     {0, 0, block_start_m, block_start_n});
}

int main() {
  InType *lhs, *rhs;
  OutType *out;

  cudaMallocManaged(&lhs, sizeof(InType) * M * K);
  cudaMallocManaged(&rhs, sizeof(InType) * K * N);
  cudaMallocManaged(&out, sizeof(OutType) * M * N);
  for (int m = 0; m < M; m++)
    for (int k = 0; k < K; k++)
      lhs[m * K + k] = 1;
  for (int k = 0; k < K; k++)
    for (int n = 0; n < N; n++)
      rhs[k * N + n] = InType(k);

  auto smem_size = 160 * 1024;
  cudaFuncSetAttribute(kernel, cudaFuncAttributeMaxDynamicSharedMemorySize,
                       smem_size);
  // BLOCK_M / WARP_M * BLOCK_N / WARP_N
  kernel<<<dim3(M / BLOCK_M, N / BLOCK_N, 1),
           BLOCK_M / WARP_M * BLOCK_N / WARP_N * 32, smem_size>>>(
      {lhs, {}, {}, {}, {}}, {rhs, {}, {}, {}, {}}, {out, {}, {}, {}, {}});
  cudaDeviceSynchronize();

  OutType *outHost;
  cudaMallocHost(&outHost, sizeof(OutType) * M * N);
  cudaMemcpy(outHost, out, sizeof(OutType) * M * N,
             cudaMemcpyKind::cudaMemcpyDeviceToHost);
  printf("%f", float(outHost[0 * N + 0]));
}

```

## TMA Multicast

之前折腾WGMMA的时候，我就隐隐约约感觉纯L2带宽好像满足不了拉满的Tensor Core。Hopper前的Memory Hierachy是HBM->L2->Shared Memory->Warp。Turing以后的NVGPU L2都不小，做矩乘的时候基本不会重复读取。接下来两步，来自HBM的带宽逐层放大，但问题是数据在总线上跑（L2->Shared Memory）也是一个挺耗电的操作。拉大Matmul Kernel的Block Size可以降低L2的带宽需求，但Block Size又被Register File/Problem Size卡死了。

NV在Hopper/Blackwell的解法是TMA Multicast，用户可以用TMA让一份Load写到Cluster的多个SM里。AMD在MI300的解法是在Cluster这个层面上再加一层Cache。我觉得TMA Multicast上限更高，加一层Cache只解决了L2->Cluster Cache这一步的问题，而Multicast直接把Cluster Cache Lookup还有Cluster->Shared Memory的流量一起砍了。当然TMA Multicast在软件层面上也是有代价的，我们在后面也能看到。

### 简单例子

我们先从一个Warp开始练练手，读到的数据做一些象征性的运算（Sum Reduce，把32x32xf32压成32xf32，减少检查时要读的数据量）。TMA Load要求用mbarrier管理。mbarrier放行要求expected tx归零（数据传完了）+expected arrival归零（producer和consumer都到了）。wait和arrive是分开的，单独的wait不会改变arrival count。

TK的TMA API有些坑。对比CUDA Programming Guide里的例子（放在下一节里了），expect实际上对应的是ptx里的`mbarrier.arrive.expect_tx`，设置expect bytes的同时自带（lane0的）一个arrival。这里有几个解决思路。

- 像CUDA Programming Guide里给剩下31个Thread补一下arrive，这样每个Warp每次Arrive都是32的Count，这种做法多少有点麻烦。
- 简化一些，我们就把mbarrier当成单向同步的semaphore用，一方只arrive，另一方只wait，这样就避免了两方arrival count不一样的麻烦。但不同的mbarrier还是得分别考虑，有的是整个Warp Arrive，有的是单个Thread Arrive（dsmem）。

```cpp
#include "kittens.cuh"
using namespace kittens;
#include "zzy.cuh"
#include <cuda.h>
#include <cuda_runtime.h>
typedef float InType;
typedef float OutType;

constexpr int NumCtas = 4;
constexpr int NumWarps = 1;
constexpr int BlockM = 32;
constexpr int BlockK = 32;
constexpr int SizeM = BlockM;
constexpr int SizeK = BlockK * 4;

using LhsST = st<InType, BlockM, BlockK>;
using LhsRT = rt<InType, BlockM, BlockK>;
using LhsGL = gl<InType, 1, 1, SizeM, SizeK, LhsST>;
using OutGL = gl<OutType, 1, 1, NumCtas, SizeM>;

__global__ void __cluster_dims__(NumCtas)
    kernel(const __grid_constant__ LhsGL desc_lhs,
           const __grid_constant__ OutGL desc_out) {
  extern __shared__ alignment_dummy __shm[];
  tma_swizzle_allocator al((int *)&__shm[0]);
  auto lhs_shared = al.allocate<LhsST, 1>();
  LhsRT lhs_tile;
  LhsRT::col_vec lhs_sum;

  int warpid = kittens::warpid();
  int warpgroupid = warpgroup::groupid();
  int ctaid = zzy::cluster_ctarank();

  __shared__ semaphore input_ready[1];
  init_semaphore(input_ready[0], 1, 0);
  // 确保Cluster里的每个Block都准备好了semaphore
  tma::cluster::sync();
  // 第一个Block发起TMA请求
  if (ctaid == 0)
    tma::cluster::load_async(lhs_shared[0], desc_lhs, {0, 0, 0, 0},
                             input_ready[0], (1 << NumCtas) - 1);
  // 每个Block自己设置期望的Bytes，同时自带一个Arrival
  // 清空input_ready的expected arrival
  tma::expect(input_ready[0], lhs_shared[0]);
  // 等
  wait(input_ready[0], 0);
  // 算
  load(lhs_tile, lhs_shared[0]);
  row_sum(lhs_sum, lhs_tile);
  // 存
  store(desc_out, lhs_sum, {0, 0, ctaid, 0});
}

int main() {
  InType *lhs;
  cudaMallocManaged(&lhs, sizeof(InType) * SizeM * SizeK);
  for (int i = 0; i < SizeM; i++)
    for (int j = 0; j < SizeK; j++)
      lhs[i * SizeK + j] = j;
  OutType *out;
  cudaMallocManaged(&out, sizeof(OutType) * NumCtas * SizeM);
  cudaMemset(out, 0, sizeof(OutType) * NumCtas * SizeM);

  dim3 grid(NumCtas);
  dim3 block(NumWarps * kittens::WARP_THREADS);

  auto desc_lhs = LhsGL(lhs, {}, {}, {}, {});
  auto desc_out = OutGL(out, {}, {}, {}, {});

  cudaFuncSetAttribute(kernel, cudaFuncAttributeMaxDynamicSharedMemorySize,
                       MAX_SHARED_MEMORY);
  kernel<<<grid, block, MAX_SHARED_MEMORY - 1024>>>(desc_lhs, desc_out);
  cudaDeviceSynchronize();
  for (int i = 0; i < NumCtas; i++) {
    printf("%d:\n", i);
    for (int j = 0; j < SizeM; j++)
      printf("%f ", out[i * SizeM + j]);
    printf("\n");
    printf("\n");
  }
}

```

我们再来给Kernel加上一个循环。

- 现在我们知道了expect实际上是一个arrival，那每一轮要重新expect/让lane0去arrive就很合理了。
- 同时每一轮我们都要考虑到整个cluster的进度，万一有哪个Block在摸鱼还没load shared memory，而Producer又issue了下一轮的Cluster load，刚好这个Cluster Load很快就拿到了一些数据，那摸鱼的那个Block计算就炸了。所以我们每轮k都得做一次cluster sync。
- 同一个mbarrier，wait的时候需要交替使用0/1当parity bit。如果一直用同一个parity bit，整个Kernel就会卡死。

```cpp
__shared__ semaphore input_ready[1];
  init_semaphore(input_ready[0], 1, 0);

  for (int k = 0; k < SizeK / BlockK; k++) {
    tma::cluster::sync();
    if (ctaid == 0) {
      tma::cluster::load_async(lhs_shared[0], desc_lhs, {0, 0, 0, k},
                               input_ready[0], (1 << NumCtas) - 1);
    }
    tma::expect(input_ready[0], lhs_shared[0]);
    wait(input_ready[0], k % 2);
    load(lhs_tile, lhs_shared[0]);
    row_sum(lhs_sum, lhs_tile, lhs_sum);
  }
  store(desc_out, lhs_sum, {0, 0, ctaid, 0});

```

barrier/mbarrier/cluster barrier虽然都能同步warp，但是细节上有一些差别。假设Warp ABC需要靠Barrier X同步，我们用cuda-gdb/vscode的debugger手动操作warp的运行顺序，让Warp C保持不动，Warp A多次Arrive，之后Warp B再去Arrive&Wait。（arrive了不wait算UB吧）

- 正常的barrier就进不去下一轮，B还是会被卡着。也就是说正常的barrier不会把多出来的Arrival当成是别的Warp的Arrival，更像是一个bitset。进入下一轮以后，Warp A之前的Arrival会被忽略。
- mBarrier会把Warp A多出来的Arrival记下来，毕竟Programming Guide就说了mBarrier记的是arrival数量，这样mBarrier扩展到管一个Cluster的所有Warp也没有多大的代价。安全性上有parity bit，应该还算安全。
- Cluster Barrier要求cluster里的所有Warp同步，不能每个Block选一个Warp去同步。Cluster Barrier这里，Warp A第二次Arrive的时候就会卡死，等到BC过了才能放行。

```cpp
__global__ void kernel() {
  barrier<NumWarps> barrier(1);
  if (kittens::warpid() == 0) {
    for (int i = 0; i < 256; i++) {
      arrive(barrier);
    }
  } else {
    for (int i = 0; i < 256; i++) {
      arrive_and_wait(barrier);
    }
  }
}

__global__ void kernel() {
  __shared__ semaphore barrier;
  if (kittens::warpid() == 0) {
    init_semaphore(barrier, NumWarps * 32, 0);
    __syncthreads();
    for (int i = 0; i < 256; i++) {
      arrive(barrier);
    }
  } else {
    __syncthreads();
    for (int i = 0; i < 256; i++) {
      arrive_and_wait(barrier, i % 2);
    }
  }
}

__global__ void __cluster_dims__(NumCtas) kernel() {
  if (kittens::warpid() == 0) {
    for (int i = 0; i < 256; i++) {
      tma::cluster::arrive_aligned();
    }
  } else {
    for (int i = 0; i < 256; i++) {
      tma::cluster::wait_aligned();
    }
  }
}

```

### 使用限制

估计是为了简化TMA的硬件实现，TMA对memory stride和size有不少[限制](https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__TENSOR__MEMORY.html#group__CUDA__TENSOR__MEMORY_1ga7c7d2aaac9e49294304e755e6f341d7)，毕竟还有正常的load/store兜底。写几个印象深刻的坑。

- ptr，stride（按bytes算），innermost block size（乘上sizeof(elem)后）都要求至少16 byte aligned，和128bit load/store要求一致。在Kernel里动态提供的Index也需要保证初始地址16 byte aligned。
- `cuTensorMapEncodeTiled`里，最连续的dimension在C++ Array的最左边，和Pytorch的习惯相反。
- `globalStrides`从第二连续的dimension开始，强制在最里面一维上coalesce。所以不能靠TMA直接白嫖Transpose。如果要strided load最里面一维，可以设置`elementStrides`。
- Shared Memory Swizzle是在最里面一维做的，对每次load的block size（boxDim）有限制，要求`boxDim[0] * sizeof(elem) < SwizzleSize`。最大的Swizzle Size = 128 Byte = 128 fp8 = 64 bf16，矩乘放在k上还行，放在n上不一定够。
- TK[现在的做法](https://github.com/HazyResearch/ThunderKittens/blob/1595bb33cd99e9cd7ddaa7c52e02aa79da59566e/include/types/global/tma.cuh#L69)是多开一维，把External Memory当成`[dim0 / swizzle_elem, dim1, swizzle_elem]`（shared memory也会变成这个layout）。但是这样会影响TMA Out-Of-Bound的判断，比如`128x(8*128+32)`是能保证16 byte alignment的，但是最后`+32`就没办法判断成OOB，会出现比较诡异的行为。
- Triton的做法是[多次Load](https://github.com/triton-lang/triton/blob/7380904496abc8e86ed2234113637bd8929f11eb/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/LoadStoreOpToLLVM.cpp#L1196)，每次在最里面一维只读取`swizzle_elem`，这样不需要reshape external memory，也不影响OOB Padding。
- interleave完全不知道干什么用的。
- 在Kernel里创建CUTensorMap似乎还有[额外的限制](https://docs.nvidia.com/cuda/parallel-thread-execution/#tensormap-new-val-validity)。

TMA OOB Padding可以选择0或者是OOB NaN(`0x7ff7`)。在NVGPU上处理不规则的形状一般靠Padding，如果在计算的时候用dynamic sized loop，那每算一次都得花8 Cycle去Jump，再加上MMA指令已经有了一个最小的形状要求。Zero Pad可以用在矩乘上，Nan Padding可以配合Nan Propagate Mode用在Min Max Reduction上。这里的OOB Nan(`0x7ff7`)和FMA/SFU算出来的Canonical Nan(`0x7fff`)不是同一个，所以真有什么0/Nan都不行的情况，判断bitwise equal应该也比n次compare来的快。（所以TMA为什么不能手动指定fill value呢？）。FP16 FMA PTX里有一个奇怪的[oob模式](https://docs.nvidia.com/cuda/parallel-thread-execution/#half-precision-floating-point-instructions-fma)，我想不清楚怎么用。（用fp16当accumulator会不会精度爆炸啊）

```cpp
#include "kittens.cuh"
using namespace kittens;
#include "zzy.cuh"
#include <cuda.h>
#include <cuda_runtime.h>
typedef float InType;
typedef float OutType;

constexpr int NumWarps = 1;
constexpr int BlockM = 16;
constexpr int BlockK = 16;
constexpr int SizeM = BlockM;
constexpr int SizeK = BlockK * 2 + 8;

using cbar = cuda::barrier<cuda::thread_scope_block>;
namespace cde = cuda::device::experimental;

__global__ void kernel(const __grid_constant__ CUtensorMap desc_lhs) {
  alignas(1024) __shared__ InType data[BlockM * BlockK];

  int warpid = kittens::warpid();
  int warpgroupid = warpgroup::groupid();
  int ctaid = zzy::cluster_ctarank();

  __shared__ cbar barrier;
  if (threadIdx.x == 0) {
    init(&barrier, 32);
    cde::fence_proxy_async_shared_cta();
  }
  __syncthreads();

  for (int k = 0; k < zzy::ceildiv(SizeK, BlockK); k++) {
    cbar::arrival_token token;
    if (threadIdx.x == 0) {
      for (int i = 0; i < BlockM * BlockK; i++)
        data[i] = 0xffffffff;
      cde::cp_async_bulk_tensor_2d_global_to_shared(&data, &desc_lhs,
                                                    k * BlockK, 0, barrier);
      token = cuda::device::barrier_arrive_tx(barrier, 1, sizeof(data));
    } else {
      token = barrier.arrive();
    }
    barrier.wait(std::move(token));
    printf("Ready for Check");
  }
}

int main() {
  InType *lhs;
```

## Warp Specialize

NV在Hopper上推荐用Warp Specialize管理TMA/Tensor Core。原来NVGPU上，同一个Warp可以一先一后发射两条不相关的指令，遇到要等的数据依赖，NVGPU可以切换运行的warp来填满计算单元（那几个xLP我一直记不清名字）。TMA和Tensor Core大颗粒度的计算相当于给并行再增加了一个维度。当然TMA也不是必须要Warp Specialize才能用，现在的[Triton](https://github.com/triton-lang/triton/blob/7380904496abc8e86ed2234113637bd8929f11eb/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/LoadStoreOpToLLVM.cpp#L1177)就是把TMA用在Software Pipelining里。如果只考虑最简单的Kernel，WASP的好处可能没有那么明显。所以我们到后面根据实际应用，来考虑Warp Specialize的好处。

### Producer-Consumer Model

我们把上面的Kernel改写成Warp Specialized的形式，先把TMA Load分出来。

![](https://pica.zhimg.com/v2-f4c3129851bb5753e577bba27c29ae16_r.jpg)

```cpp
__shared__ semaphore input_ready[1];

  if (threadIdx.x == 0) {
    // Arrive：同一个Block的Load Warp，Count=1*1
    //   Wait: 同一个Block的Compute Warp
    init_semaphore(input_ready[0], 1, 0);
  }
  // 每个Warp都会hit这里的cluster barrier
  tma::cluster::sync();

  if (warpid == 0) {
    for (int k = 0; k < SizeK / BlockK; k++) {
      if (ctaid == 0) {
        tma::cluster::load_async(lhs_shared[0], desc_lhs, {0, 0, 0, k},
                                 input_ready[0], (1 << NumCtas) - 1);
      }
      tma::expect(input_ready[0], lhs_shared[0]);
      // 每轮Loop后同步
      // Cluster Barrier需要拦住下一轮的TMA Load
      tma::cluster::sync();
    }
  }

  if (warpid == 1) {
    for (int k = 0; k < SizeK / BlockK; k++) {
      wait(input_ready[0], k % 2);
      load(lhs_tile, lhs_shared[0]);
      row_sum(lhs_sum, lhs_tile, lhs_sum);
      // 每轮Loop后同步
      // 相当于通知Cluster，这个Block的这一轮计算已经做完
      tma::cluster::arrive_aligned();
    }
    store(desc_out, lhs_sum, {0, 0, ctaid, 0});
  }

```

我们再把Store拿出来用TMA做。（假设我们要输出好几轮的结果）为了避免Store Warp/TMA存到一半，Compute Warp就拿下一轮的结果覆盖掉了上一轮的结果，我们要添加两个mBarrier来双向同步Compute Warp和Store Warp。

![](https://picx.zhimg.com/v2-ac24f3636dec02a1054518ee7e02f80d_r.jpg)

```cpp
__shared__ semaphore input_ready[1];
  __shared__ semaphore output_ready, output_used;

  if (threadIdx.x == 0) {
    // 这段没变
    init_semaphore(input_ready[0], 1, 0);
    init_semaphore(output_ready, WARP_THREADS, 0);
    // Arrive：同一个Block的Store Warp，Count=32*1
    //   Wait: 同一个Block的Compute Warp
    init_semaphore(output_used, WARP_THREADS, 0);
    // 让Output Buffer一开始就能写
    arrive(output_used, WARP_THREADS);
  }
  tma::cluster::sync();

  if (warpid == 0) {
    // 这个没变
    for (int k = 0; k < SizeK / BlockK; k++) {
      if (ctaid == 0) {
        tma::cluster::load_async(lhs_shared[0], desc_lhs, {0, 0, 0, k},
                                 input_ready[0], (1 << NumCtas) - 1);
      }
      tma::expect(input_ready[0], lhs_shared[0]);
      tma::cluster::sync();
    }
  }

  if (warpid == 1) {
    for (int k = 0; k < SizeK / BlockK; k++) {
      wait(input_ready[0], k % 2);
      load(lhs_tile, lhs_shared[0]);
      row_sum(lhs_sum, lhs_tile, lhs_sum);
      tma::cluster::arrive_aligned();
    }
    // 确保output buffer可以写，不会影响上一轮的TMA Store
    wait(output_used, 0);
    // 把结果存到Shared Memory里的Output Buffer里
    OutRV lhs_out;
    copy(lhs_out, lhs_sum);
    store(out_shared[0], lhs_out);
    // 通知Store Warp，Output Buffer里有新的结果
    arrive(output_ready);
  }

  if (warpid == 2) {
    // 陪Load/Compute Warp在k上cluster barrier sync
    for (int k = 0; k < SizeK / BlockK; k++) {
      tma::cluster::arrive_aligned();
    }
    wait(output_ready, 0);
    // 发射TMA Store
    tma::store_async(desc_out, out_shared[0], {0, 0, ctaid, 0});
    // 在TMA读完Shared Memory后
    // 允许Compute Warp写下一轮的结果
    tma::store_async_read_wait<0>();
    arrive(output_used);
    // 退出前确保所有的TMA Store都写完了
    tma::store_async_wait<0>();
  }

```

Cluster Barrier要求每个Block的每个Thread参与，用来一开始同步Block很方便。但这也导致了在后续的计算里，Compute Warp和Store Warp也需要参与Cluster Barrier。就算Store Warp不参与k loop上的计算，但还是得加一个k loop来参加k loop里的Cluster Barrier。要是Producer Consumer关系再复杂一点，Cluster Barrier就很麻烦了。我们可以用dsmem版的mbarrier替换掉计算过程中的Cluster Barrier，让一个Warp跨Block Arrive另一个SM上的mbarrier，进一步我们可以让整个Cluster共用同一个Producer Warp。

![](https://pic1.zhimg.com/v2-4a78347a6380ccb051ba5c2a9eb45c48_r.jpg)

```cpp
__shared__ semaphore input_ready[1], input_used[1];
  __shared__ semaphore output_ready, output_used;

  if (threadIdx.x == 0) {
    // Arrive：Block 0的Load Warp (dsmem,expect)，Count=1*1
    //   Wait: 当前Block的Compute Warp
    init_semaphore(input_ready[0], 1, 0);
    // Arrive: Cluster里所有Block的Compute Warp (dsmem)，Count=NumCtas*1
    //   Wait: Block 0的Load Warp
    // 只有Block 0的input_used mbarrier会被用上。
    init_semaphore(input_used[0], NumCtas, 0);
    // 这段没变
    init_semaphore(output_ready, WARP_THREADS, 0);
    init_semaphore(output_used, WARP_THREADS, 0);
    arrive(output_used, WARP_THREADS);
  }
  tma::cluster::sync();

  if (warpid == 0 && ctaid == 0) {
    for (int k = 0; k < SizeK / BlockK; k++) {
      tma::cluster::load_async(lhs_shared[0], desc_lhs, {0, 0, 0, k},
                               input_ready[0], (1 << NumCtas) - 1);
      // 用dsmem版的expect，通知Cluster里的每个Block需要读的bytes
      for (int i = 0; i < NumCtas; i++) {
        tma::cluster::expect(input_ready[0], i, lhs_shared[0]);
      }
      // 等待所有Compute Warp都用完了Buffer
      wait(input_used[0], k % 2);
    }
  }

  if (warpid == 1) {
    for (int k = 0; k < SizeK / BlockK; k++) {
      wait(input_ready[0], k % 2);
      load(lhs_tile, lhs_shared[0]);
      // 通知Block 0 Load Warp，当前Warp已经用完Buffer
      // dsmem版的arrive只能一个thread参与，TK没有加这个predicate
      if (laneid == 0)
        tma::cluster::arrive(input_used[0], 0, 1);
      row_sum(lhs_sum, lhs_tile, lhs_sum);
    }
    // 这段没变
    wait(output_used, 0);
    OutRV lhs_out;
    copy(lhs_out, lhs_sum);
    store(out_shared[0], lhs_out);
    arrive(output_ready);
  }

  if (warpid == 2) {
    // 这个没变
    wait(output_ready, 0);
    tma::store_async(desc_out, out_shared[0], {0, 0, ctaid, 0});
    tma::store_async_read_wait();
    arrive(output_used);
    tma::store_async_wait();
  }

```

如果要做Prefetch，那我们就得为每一个Input Buffer准备一个mBarrier。把k映射到parity bit的时候要特别当心，因为每个mBarrier的parity都是分开计算的。假如`Buffers=3`，那么前3次的TMA Load都是每个Buffer的第一次Load，mbarrier的phase是0，第4次才开始改变phase。还有Load Warp实际上等的是`Buffer`轮前`input_used`，parity需要变一下。

![](https://picx.zhimg.com/v2-fad61d54022006af977ba025743d9667_r.jpg)

```cpp
if (threadIdx.x == 0) {
    // 给每一个buffer都准备一个ready和used barrier。
    for (int i = 0; i < Buffers; i++) {
      // Arrive：Block 0的Load Warp (dsmem,expect)，Count=1*1
      //   Wait: 当前Block的Compute Warp
      init_semaphore(input_ready[i], 1, 0);
      // Arrive: Cluster里所有Block的Compute Warp (dsmem)，Count=NumCtas*1
      //   Wait: Block 0的Load Warp
      // 只有Block 0的input_used mbarrier会被用上。
      init_semaphore(input_used[i], NumCtas, 0);
    }
    // 这段没变
    init_semaphore(output_ready, WARP_THREADS, 0);
    init_semaphore(output_used, WARP_THREADS, 0);
    arrive(output_used, WARP_THREADS);
  }
  tma::cluster::sync();

  if (warpid == 0 && ctaid == 0) {
    for (int k = 0; k < SizeK / BlockK; k++) {
      // 我们把Buffer当成是Ring Buffer
      // 找到这一轮要读到Ring Buffer里的哪一个
      auto bid = k % Buffers;
      // 确保这个Buffer已经用完了
      // Parity Bit需要用Buffer轮前的k计算
      // 同时前Buffer次不应该被这个mbarrier卡死
      auto pbit = (k - Buffers) / Buffers % 2;
      if (k >= Buffers)
        wait(input_used[bid], pbit);
      // 这一段没变
      tma::cluster::load_async(lhs_shared[bid], desc_lhs, {0, 0, 0, k},
                               input_ready[bid], (1 << NumCtas) - 1);
      for (int i = 0; i < NumCtas; i++) {
        tma::cluster::expect(input_ready[bid], i, lhs_shared[bid]);
      }
    }
  }

  if (warpid == 1) {
    for (int k = 0; k < SizeK / BlockK; k++) {
      // 计算这一轮要用ring buffer里的哪一个
      auto bid = k % Buffers;
      auto pbit = k / Buffers % 2;
      // 剩下的除了用上了bid替代hardcode的0，应该都一样
      wait(input_ready[bid], pbit);
      load(lhs_tile, lhs_shared[bid]);
      if (laneid == 0)
        tma::cluster::arrive(input_used[bid], 0, 1);
      row_sum(lhs_sum, lhs_tile, lhs_sum);
    }
    wait(output_used, 0);
    OutRV lhs_out;
    copy(lhs_out, lhs_sum);
    store(out_shared[0], lhs_out);
    arrive(output_ready);
  }

  if (warpid == 2) {
    // 这一段没变
    wait(output_ready, 0);
    tma::store_async(desc_out, out_shared[0], {0, 0, ctaid, 0});
    tma::store_async_read_wait();
    arrive(output_used);
    tma::store_async_wait();
  }
```

### Matmul

回头再云一次Matmul。Matmul用上Multicast收益巨大，假如我们把Cluster Size拉到16，Block排成4x4，那么L2上的读取就从`16*2`变成了`4+4`，省了4倍的L2带宽+对应的功耗（省下来的功耗不知道能不能给SM多拉点频率）

![](https://pic2.zhimg.com/v2-5597d086ad5f3dd3966336b2f18c2e6f_r.jpg)

```cpp
int mpos = ctaid % NumBlocksM;
  int npos = ctaid / NumBlocksM;
  int mleader = mpos;
  int nleader = npos * NumBlocksM;

```

TMA Load Mask需要根据Leader的位置动态计算，偷懒的话可以用Loop写，也可以用位运算（这玩意Compiler应该不好优化）。不过一个Block也就算一次，影响不大。

```cpp
// LHS Mask
  if (ctaid == mleader && warpid == (NumGroupsM + 1) * WARPGROUP_WARPS) {
    int mask = 0;
    for (int dst = 0; dst < NumBlocksN * NumBlocksM; dst++)
      if (ctaid % NumBlocksM == dst % NumBlocksM)
        mask += 1 << dst;
    // ...
  }

// RHS Mask
  if (ctaid == nleader && warpid == (NumGroupsM + 1) * WARPGROUP_WARPS + 1) {
    int mask = 0;
    for (int dst = 0; dst < NumBlocksN * NumBlocksM; dst++)
      if (ctaid / NumBlocksM == dst / NumBlocksM)
        mask += 1 << dst;
    // ...
  }

```

看起来那么好，那为什么Hopper出来了两年，巨大尺度的Multicast Kernel用的并不多呢。Multicast导致了更大的Block Size，如果我们用`m(4x128)n(4x128)`的Cluster Size去算`m(5x128)n(16x128)`的矩乘，我们在m上就要浪费3/8的算力在Out Of Bound的计算上。有两个大概的解决思路。一个是Block上要处理的m和n不一定要2的幂次，[DeepGEMM](https://github.com/deepseek-ai/DeepGEMM?tab=readme-ov-file#unaligned-block-sizes-)提到了这一点。在我们的例子里，可以用m64n160的wgmma，`5x128=4x160`刚好匹配Matmul Size。（所以Triton的Power of 2限制也是麻烦啊，底层代码.webp）wgmma上的n维不一定是原来不好切的那一维，所以可能还得做个in-kernel transpose。另一个思路是Cluster不一定要组成正方形/长方形，完全可以在运行时扭成一个更灵活的形状。

我们再来考虑Warp Specialize。TMA Load是需要分Warp/Warpgroup去做的。不然的话，有些Warp就需要同时Issue TMA Load和计算，配合上Global Memory Prefetch，这个Warp的代码大概长这样。

```python
Issue TMA Load(lhs, 0)
...
for k:
  Compute(lhs, rhs)
  Wait(lhs_used[k])
  Issue TMA Load(lhs, k + Buffers)
```

如果Cluster里有几个Block跑得比较慢，这个`wait(input_used[k])`就会卡住这个下一轮的计算。但实际上因为有Global Memory上的Prefetch，这时候下一轮的lhs和rhs大概率已经读完了。（如果这个WarpGroup总是最后一个就还好？）如果我们把Load Warp分出来，这个wait就不会卡住计算。（写到这里才发现，我们现在的Kernel用上了TMA+mBarrier以后，loop内是没有barrier/cluster barrier的，所以各个Warp Group是可以k上相差个`Buffers`的。）

我们还需要手动指定Load Warp的Register Count（[PTX](https://docs.nvidia.com/cuda/parallel-thread-execution/#miscellaneous-instructions-setmaxnreg)，[TK](https://github.com/HazyResearch/ThunderKittens/blob/34b84d88545599df7c599b841f177a10150827ff/kernels/attn/h100/h100.cu#L106)）。这个Kernel里，MMA Group用了巨量的Register，按默认的行为，Load Group也会用同样数量的Register，然后Launch Kernel的时候就会爆炸。因为Block的thread数量是可以动态指定的，NVCC在编译并不会检查Kernel的Register数量。（在C++/SSA IR里，Reg Allocation之前，要用户给一个Register Quota是真的逆天。）

那Matmul Epilogue和TMA Store要不要也分出去？一种做法是MMA Group把fp32 acc写到Shared Memory里，Epilogue Group去读Shared Memory再计算。配合Persistent Schedule，MMA Group可以更早去算下一轮。Epilogue Group也不需要太多Register。

```python
if MMA Group:
  for m, n:
    for k:
      ...
    shared_store(acc_buffer, acc)

if Epilogue Group:
  for m, n:
    shared_load(acc_buffer)
    out = epilogue(out)
    global_store(out)
```

如果原来的Epilogue计算量比较小，比如说就是把fp32降到fp16，分Epilogue Group可能没多大收益，原来（downcast+存fp16）花的cycle可能比新的（存fp32 acc）花的cycle多不了多少。但如果Epilogue计算量比较大，比如说是[SwiGLU](https://github.com/meta-llama/llama3/blob/a0940f9cf7065d45bb6675660f80d305c041a754/llama/model.py#L219)这样要用两次SFU（exp2,rcp）+一堆Mul/Add+downcast，分出去Epilogue Warp就可以减少Tensor Core的bubble。Blackwell不做精度提升的话，我们总是要把最后的Accumulator从Tensor Memory到Register的，必然会把epilogue当成一个stage。

快速算一下Shared Memory够不够。128x128的block size是完全够的，128x256就不太够了。

```cpp
(128x64xfp16+64x128xfp16)*3 + 128x128xfp32 + 128x128xfp16 = 192KB
(128x64xfp16+64x256xfp16)*2 + 128x256xfp32 + 128x256xfp16 = 288KB

```

### FA

FA也能用上Multicast。FA的KV不分LHS和RHS，Cluster有多大就能省几倍L2带宽。麻烦点在于LLM场景下的Attention要带Causal Mask，假如`block_q = block_kv`，那第i个q block只需要attend同一组head上的前i个kv block。MHA head与head之间不共享KV，所以我们只能把同一个head上相近的block捆到Cluster里。但是因为结束的地方不一样，有的SM就会摸鱼，所以MHA的Cluster Size不方便拉太大？如果是MQA/GQA这种，一组（8/16个）q head共享同一组kv head，所以我们可以直接拿q group来组Cluster，避免了上面的问题。（有必要把两种混起来吗？）

![](https://pic2.zhimg.com/v2-9c368b1756b878f2e7770a99aab4a257_r.jpg)

FA3 Paper里用Warp Specialization的地方其实就两个。一个是TMA Load Warp，另一个在Backward Pass做dQ Reduction。和Triton Tutorial里的FA不一样，FA3里dq和dkdv是一起算的，省去了第二次重算`qk`和`pv`。但是dq要扫kv，dkdv要扫q。FA是扫kv，这样（2个）dkdv可以在Register里累加，剩下的1个dq就需要像Matmul Split-K/FA Split-KV那样做Block之间的Reduction。FA3用上了[TMA Atomic Reduction](https://github.com/Dao-AILab/flash-attention/blob/27f501dbe011f4371bff938fe7e09311ab3002fa/hopper/mainloop_bwd_sm90_tma_gmma_ws.hpp#L629)。

我们还是来过一下FA3提出的3种Forward并行策略。FA3主要动机是要尽可能并行Tensor Core（qk，pv）和SFU（p，alpha1D）的计算。NVGPU上SFU跑的并不快（用FMA展开exp2也快不到哪去），虽然在`FP16 QKV，head_dim=128`下大概是WGMMA一半的Cycle，不算瓶颈。但p会卡pv的计算，所以就要避免p的latency暴露出来。

- （基操版）两个WarpGroup，第一个WarpGroup在算p的时候，第二组WarpGroup可以算qk。
- （自己Overlap自己版）用Software Pipelining的方法给qk做Double Buffering，就像Matmul里并行Load和MMA一样。这样在同一个WarpGroup里，也能并行qk和p。（编译器要认出来[这](https://github.com/Dao-AILab/flash-attention/blob/27f501dbe011f4371bff938fe7e09311ab3002fa/hopper/mainloop_fwd_sm90_tma_gmma_ws.hpp#L1168-L1185)是个Double Buffering还挺不容易的？）
- （自己Overlap自己版--）给p也加一层Buffering，这样理论上可以并行p和pv，但跑起来效果不好。

虽然论文里没明着提，FA3里应该也是用到了[TMA Multicast](https://github.com/Dao-AILab/flash-attention/blob/27f501dbe011f4371bff938fe7e09311ab3002fa/hopper/mainloop_fwd_sm90_tma_gmma_ws.hpp#L642-L644)的。我是不太熟cute（还有那一堆C++ template），等一个大佬的FA v3的代码解析。
