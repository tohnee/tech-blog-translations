国庆期间，Claude 账号被封了。后面这段时间，我把整个开发流程大幅调整了一遍。

现在主要用 Codex CLI 干活，代码库放在 GitHub。Claude 还在用，只是为了继续用它，我得单独准备一台机器，再远程连过去。而且手上只有一个 Pro 号，额度有限，已经没法让它承担太多工作。

折腾到现在，对各家模型、套餐，还有最近用的 OMP，都攒了一些感受。

### 为了留住 Claude，我专门准备了一台机器

为了用 Claude，我专门给那台机器配了日本 IP，改了时区，也调整了网络路由。出口做了限制：必须从日本 IP 出去，一旦走不了这个出口，就直接断网。

然后配好 VNC，远程连接到那台机器，在 Claude 网页端接上 GitHub 仓库，用它编程，或者帮忙做评审。

于是，我现在的流程就成了：平时主要在 Codex CLI 里做开发，通过 GitHub 管代码，需要 Claude 的时候，再远程过去用网页端。

这套流程能跑，但为了用一个编程工具，前面要准备这么多东西，确实费劲。好不容易配完了，真正开始干活，还得惦记那个 Pro 号的额度。

**所以 Claude 现在能做多少就做多少，大部分工作还是交给 Codex。**

### 主力换成 6.1 sol：能用，但慢，也会突然停

我现在的主力是 6.1 sol。经常看到别人说 6.1 不行，我自己用下来，感觉还算中规中矩，没到不能用的程度。

当然，它也有让人头疼的时候。比如给它一张参考图，希望它照着做，图已经摆在那里了，它还是非要给你做出一个不一样的版本。你想要的那个效果没出来，后面就得接着改。

这种时候，看它写了多少代码意义不大，页面打开之后到底像不像，才是我关心的。

但它慢也是真慢。这两天还经常做到一半，突然显示“该模型不可用”。让它继续，又好了。过一会儿再来一次，反反复复。

单次能恢复还好，次数多了，就得时不时回来看看，它到底还在干，还是又停在那里了。

偏偏额度这两天又给得挺有意思，动不动就重置。我好不容易把额度用到 60%，一觉起来，又满了。

有时候都想吐槽，这重置得这么勤，不会已经成了 OpenAI 留住用户的办法吧。当然，我也不知道它背后的安排，只知道醒来额度又满了，今天可以接着用。

**一边嫌它慢，一边又觉得额度够用，那就继续干吧。** 我现在对 Codex 的态度，大概就是这样。

### OMP、Qoder、Qwen：试过一圈，还是回到 6.1 sol

之前一直主要使用 OMP，Claude 缺席后，整个组合也和以前不一样了。看起来代码跑得很欢，过程挺热闹，但实际做出来，也就那样。

至少在我最近做的这些事情里，没感觉它比我现在这套模式好多少，可用的模型还少了很多。

可能别人有别人用得顺的方式，我目前的体感就是这样。折腾一套流程，总得看最后交到手里的东西怎么样。过程再忙，效果没明显变好，我也很难说服自己继续往上加东西。

中间我还订了一个月的 Qoder CN，当时另外送了 6000 积分。看见这个数字，原本觉得应该能用一阵。

结果那额度，真不经用。稍微用用就没了，体感甚至还没智谱的 Lite 多。

这里说的是我自己的实际消耗感受，各家的计费口径不一样，不能拿积分数直接横着比。但对我来说，订阅买回来，能不能支撑手头的开发工作，用一阵就知道了。额度耗得太快，后面的活还是得换地方接着做。

Qwen 的 3.8 Flash 和 3.8 Max，我用下来也不太满意，幻觉确实有点大。在我碰到的这些任务里，感觉还是达不到 GLM 和 K3。

试过一圈，主力还是回到了 6.1 sol。

### 封号之后，挑工具只盯三件事

国庆这次封号之后，挑工具时会更在意一些很具体的事：今天能不能正常打开，做到一半会不会停，套餐额度能不能撑完手里的活。

Claude 我还愿意用，否则也不会专门准备机器、配网络，再远程过去。但现在只有一个 Pro，能分给它的工作有限， **开发主力暂时还是 Codex CLI 加 6.1 sol。**

希望 OpenAI 再争口气，把速度和稳定性弄好一点。也希望国产模型继续追上来，多几个能长期干活的选择。

Claude 用起来，实在太费劲了。
