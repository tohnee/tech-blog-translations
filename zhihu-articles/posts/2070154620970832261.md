最近 <u>[《How to Steal Reasoning Without Reasoning Traces》](https://arxiv.org/pdf/2603.07267)</u> 这篇论文感觉还挺有意思的，名字也很直接，它研究的是近两年一个挺有趣的现象：

> OpenAI、Anthropic、Google 这些闭源模型， API 对用户现在慢慢只开放一份压缩过的 reasoning summary，甚至直接隐藏，这种情况下为什么还会被“蒸馏”？

**而在论文里，攻击方甚至可以没有目标模型的真实 CoT，只拿到「题目 + 最终答案」，有 reasoning summary 时再加上一份 summary，然后就可以训练另一个模型把缺失的长推理过程“反推”出来** 。

**论文里把这个过程叫做 Trace Inversion，也就是推理轨迹反演** ，生成出来的东西未必真的是目标模型脑子里推理过的那条路径，但拿去训练学生模型，效果却非常好。

是不是挺有意思的，这也是整篇论文里最关键的一点：

> 所谓的“偷到 reasoning”， **真正被偷走的是能够训练出推理能力的监督信号** ，实际上并不是真的要求逐 token 恢复商业模型真实隐藏的内部 CoT，只要这些 synthetic traces 能让学生模型学会更强的推理能力，攻击就已经成立。

![](https://pic3.zhimg.com/v2-5033a5a984fcbfb9f001caf22c449d54_r.jpg)

比如上图这里：

- 左边是商业模型能够公开给用户的东西：题目、Reasoning Summary、Final Answer
- 右边的 Trace Inversion 模型根据这三个东西，生成一条几千 token 的 *Synthesized Reasoning Trace*

论文用一个向量题作为例子：

> GPT-5.4 mini 的 summary 只简单说“先计算两个向量，再建立比例关系，最后求解”，真正的详细计算步骤没有开放，然后反演模型把“ *向量平行意味着存在比例系数* ”“ *建立两个分量方程* ”“ *判断比例系数符号* ”等这些过程重新补全。

反演模型要学习的是在这种输入、summary 和答案约束下，什么样的详细推理过程通常能够把 x 合理地连接到 y ，所以它本质上带有很强的 *answer-conditioned reasoning reconstruction* 特征。

更有意思的是， **合成出来的 reasoning 有时甚至比原始 reasoning 更适合训练模型** ，而在论文里，整个攻击过程如图所示，它把攻击分成三个阶段。

![](https://pica.zhimg.com/v2-3048c9415c0e62395e6e7dfa9178d4f6_r.jpg)

Stage 1：先拿一个自己能控制的开源模型，学习“如何反演 reasoning”，攻击方首先找一个公开的 reasoning model，论文用的是：

- DeepSeek-R1
- 很弱的 DeepSeek-R1-Distill-Qwen-1.5B，论文叫它 R1-Weak

然后准备一批公开题目，例如 OpenThoughts，然后询问自己的 surrogate model：

> 这道题怎么做？

由于 surrogate 是自己能够访问完整输出的模型，所以这里可以得到：

> Question → Full CoT → Answer

接着再拿一个压缩模型，把 Full CoT 压缩成类似商业 API 的 summary：

> Full CoT → Summary。

然后最终就可以构造出这样的训练对：

> Question + Summary + Answer → Full CoT

然后用这些数据训练一个 *Inversion Model* ，这个设计最有意思的是，攻击方完全不需要知道 GPT-5.4 mini 内部究竟怎样生成 reasoning summary。

比如攻击方不知道 victim 真正使用的压缩函数 `C` ，但是攻击方自己构造一个 `C'` ， **只要生成出来的 summary 分布和目标 API 的 summary 足够接近就可以了** 。

也就是这一步学习的是一个更通用的问题：

> 已知问题、答案和一份压缩的解题线索，如何恢复一条足够完整的解题轨迹。

然后 Stage 2  才才开始碰商业模型，攻击方拿另一批 OpenThoughts 问题去调用目标模型，例如 GPT-5.4 mini，然后就可以得到：

> x + reasoning summary + answer。

随后只需要把它送进刚才训练好的 inverter，就可以通过有限的内容推理出 CoT：

> GPT 输出  ↓  Inversion Model  ↓  Synthetic CoT

最后  Stage 3 有了 `Question + Synthetic CoT + GPT Answer` 之后，就可以进行传统的 SFT。

**当然，这里首先需要解决了一个很现实的问题：GPT 的 Summary 和训练 Summary 分布不一样怎么办？**

因为攻击方不知道 GPT 如何产生 summary，所以作者自己用 Qwen2.5-7B 把 R1 CoT 压缩，但这样马上会产生 domain shift：

> 自己生成的 summary 风格 ≠ GPT summary 风格。

所以论文作者特意研究了 GPT-5.4 mini reasoning summary 的统计特征：

![](https://pic1.zhimg.com/v2-58104c43f5c239b36937633f4b989b3e_r.jpg)

作者甚至专门调整 compression prompt，让生成的 summary 长得像 GPT 的 summary，比如：

- 第一人称
- 带粗体小标题
- 带探索式表达
- 保留数学 LaTeX
- 长度大概 600～900 token

所以实际上 **Inversion 不要求知道 victim 的真实 summarizer，只需要做好 distribution matching** ，这很像机器学习里的 domain adaptation。

> 因为如果训练时看到的是一种 summary，攻击 GPT 时突然换成另一种完全不同格式的 summary，Inverter 会掉性能。

**然后就是到底能恢复多少 R1 的真实 reasoning？**

为了判断 Inversion 是否真的能够恢复出类似的 reasoning，作者先拿开源 R1 当 victim，因为 R1 的完整 trace 是能拿到的，所以可以比较 `R1 Ground Truth Trace` vs `Synthesized Trace` 。

论文用了 BLEU、Token F1、ROUGE、长度这些指标，可以看出来，单纯 0-shot 让 Qwen 「看题目、summary、答案来推理出完整 reasoning」 的效果很差：

![](https://pic2.zhimg.com/v2-f49c5c0c0b6ac27c599af08f207f0cc7_r.jpg)

生成长度只有 978 token，而 R1 的真实 reasoning 平均长度达到 6130.6 token，也就是说普通 prompt inversion 会直接塌缩成普通“解题说明”。

然后在进行结果测试的时候，可以看出来得到的 Synthetic Trace  是可以有效传递能力。

![](https://pic2.zhimg.com/v2-c05f01f1b5fcb4a07f3def2680b6e4c7_r.jpg)

比如这里学生模型有两个：

- Qwen2.5-7B-Instruct
- Llama-3.1-8B-Instruct

然后测试 MATH500、JEEBench、LiveCodeBench 这三个 benchmark，这里出现一个很有意思的现象：

- Qwen 原始 MATH500 71.2% 

也就是“拥有强模型输出”不等于这些输出天然适合做 reasoning distillation，而使用 R1-Weak 训练出来的 Inverter，把 R1 的回答重新展开成 synthetic traces 后：

- MATH500：71.8%
- JEEBench：36.3%
- LiveCodeBench：30.9%

> 尤其 JEEBench 下 Summary+Answer 只有 24.0%，但是带上 Synthetic Trace 之后就有了 36.3%。

然后更有意思的是 Llama，使用弱 surrogate 的 reasoning 直接训练 JEEBench 11.3%，但是用同一批弱 surrogate 去训练 Inverter，然后 Inverter 再处理 R1 输出能有 24.2%。

> 也就是两者差了一倍以上。

所以这里已经可以非常直观地看到：

> R1-Weak 的价值是让 Inverter 学会“怎样形成一条 reasoning trace”，然后 Victim Answer 则是把这种 reasoning structure 锚定到更强模型的能力上。

所以 synthetic trace 是“模拟真实 reasoning”，那为什么会比原版更好？因为真实 CoT 可能恰恰不是最好的训练教材

![](https://pic4.zhimg.com/v2-9553edc7286636336c867965cc92bb57_r.jpg)

比如如图可以看到，左边是真正的 R1 reasoning，可以明显看到大量：

- Wait...
- Maybe this isn't useful...
- Let's step back...
- x=y+k，发现很复杂
- 再尝试另一个不等式
- 继续回退

这其实很符合 RL reasoning model 的真实推理形态，模型在 test-time search，它会探索、犯错、撤销、重新开始。

但是右边的 Synthetic Trace 就明显更直接很多，整条路径基本一直向答案前进，Inverter 已经提前知道 final answer，所以它没有必要真的经历 victim 当时经历过的搜索过程。

> 它在做的是事后重构一条：如果我早就知道正确方向，最合理的推导路径应该是什么？

这样的 trace 更接近solution trace，而 SFT 恰恰可能更喜欢这种数据，也就是：

> **用于推理的最优训练数据，不一定是推理模型推理时产生的原始轨迹。经过 answer-conditioned reconstruction 后的“事后整理版 reasoning”，有时反而更适合作为训练信号。**

当然，前面用 R1多少存在一个问题， **R1 本身开放 reasoning，所以论文又对 GPT-5.4 mini 做了一次实验：**

![](https://pic4.zhimg.com/v2-8d30806717b2b0f9afeea96f196ead53_r.jpg)

结果效果更有意思，比如先看 Qwen 学生：

- 只训练 GPT Final Answer： 

- 直接训练 GPT Summary + Answer，得分反而只有 **19.8 / 1.6 / 0.0** ，几乎把模型训坏了
- GPT Summary + Answer 先经过 R1-trained Inverter 的，可以得到 76.0 / 43.7 / 28.9 的分数
- 如果 Inverter 只用更小的 R1-Distill-1.5B 训练，得分也有 73.2 / 31.6 / 25.6

如果再看 Llama 的话，差距就更夸张了：

- GPT Final Answer MATH500：13.0%
- GPT Summary + Answer：16.4%
- Synthetic Trace：52.4%

**也就是 Llama 从 GPT summary + answer 的 16.4% 上升到 synthetic trace 的  52.4%** ，可以看到效果也很明显。

**而且这种攻击方式还存在明显的 Scaling Law ，比如调 GPT 的次数越多，攻击效果就会继续变强** 。

![](https://picx.zhimg.com/v2-753439aa3527676f378925fae620ef87_r.jpg)

比如  GPT victim query：

- 5K：MATH500 67.0 / JEEBench 38.8。
- 10K： **77.6 / 43.7**
- 15K： **80.8 / 44.5**

再之后 MATH 基本进入 80% 附近的平台区，JEE 还有点缓慢提升，也就是 **攻击可以随 victim query budget 扩展，同时这种扩展高度依赖训练数据和目标 domain 是否匹配。**

**所以，一个高质量模型只需要持续提供正确答案，本身就可以不断产生可用于训练其他模型的信息，CoT 只是让这个信息密度更高，隐藏  Chain-of-Thought可以降低信息密度，但是不会彻底切断 capability transfer** 。

只要攻击者还能大量获得高质量的 input-output pairs，就可以借助弱 reasoning model 学到的推理先验，把强模型的答案重新展开成高密度的训练信号。
