在 Linux 系统中，调度器（Scheduler）决定了哪个线程能够获得 CPU 的执行权。作为开发者，编写高性能或实时程序时，理解调度策略与优先级控制是不可或缺的底层基本功。

本文将分为两部分，带你彻底搞懂 Linux 的调度策略原则以及如何在用户态进行修改。

## 一、 Linux 内核调度策略的种类与原则

Linux 内核以线程为单位进行调度，调度策略主要分为三大类：**普通调度策略**、**实时调度策略**以及特殊的**限期调度策略**。

讲正文之前，先指明以下两点：

- **硬中断打断**：Linux 是一个抢占式操作系统。**所有调度策略的任务**在运行过程中，**都可以被硬件中断（如定时器中断、网卡中断）无条件打断**。即使是优先级最高的实时任务，也无法阻止硬件中断的执行。
- **线程间抢占**：其余线程被打断，要么就是被更高优先级抢占，要么就是线程运行时间结束。

Linux 内核采用模块化调度框架，将所有任务划分为不同的“调度类”（Scheduling Classes），并在挑选执行任务时硬性按照如下阶级顺序进行遍历查找。

```text
【Linux 内核调度类顶级大权链条（源码级 pick_next_task 顺序）】
   │
   ├── 1. Stop (`stop_sched_class`) 
   │      └── 无用户态策略。专门负责 CPU 热插拔、线程迁移等内核绝对紧急任务。
   │
   ├── 2. Deadline (`dl_sched_class`)
   │      └── 管理【SCHED_DEADLINE】策略。看表算账的硬实时。
   │
   ├── 3. Real-Time (`rt_sched_class`)
   │      └── 管理【SCHED_FIFO】和【SCHED_RR】策略。传统霸道实时任务。
   │
   ├── 4. Fair (`fair_sched_class` / CFS或EEVDF)
   │      ├── 管理【SCHED_OTHER】：普通人用的默认策略。
   │      ├── 管理【SCHED_BATCH】：不追求交互、只追求缓存吞吐的打螺丝策略。
   │      └── 管理【SCHED_IDLE】：比 Nice 19 还卑微的超级后台挂机策略。
   │
   └── 5. Idle (`idle_sched_class`)
          └── 无用户态策略。专门用于跑系统的0号进程，当全天下没事干时让 CPU 睡觉省电。
```

### 1. 限期调度策略（Deadline Policy）

- **策略名称：**SCHED_DEADLINE
- **基本原则：**基于 EDF（最早截止时间优先）算法。它不看传统优先级，而是看任务的三个参数：周期（Period）、截止时间（Deadline）和运行时间（Runtime）。谁的截止时间最近，谁就最先跑。
- **优先级**：它是整个 Linux 系统中除了Stop Schedual任务外最高级别的调度策略，地位超越所有实时和普通任务。
- **是否能被线程打断**：不能被任何实时或普通线程打断，只有更紧急的 SCHED_DEADLINE 任务才能抢占它。

### 2. 实时调度策略（Realtime Policies）

实时策略专门用于对时间延迟敏感的任务。**实时任务的优先级永远高于普通任务**。

- **SCHED_FIFO (先进先出)**
- **SCHED_RR (时间片轮转)**

### 3. 普通调度策略（Non-Realtime Policies）

普通进程由内核的 CFS（完全公平调度器）或 EEVDF 调度器进行管理。

- **SCHED_OTHER (或称 SCHED_NORMAL)**
- **SCHED_BATCH (批处理)**
- **SCHED_IDLE (空闲后台)**

**注意**：普通调度策略中，也是按以上从上到下的顺序进行任务执行选择的。即，即使Nice 值完全相同，SCHED_OTHER 可以主动抢占 SCHED_BATCH；但是 SCHED_BATCH 几乎无法主动抢占 SCHED_OTHER。

### 4. 内核优先级规则说明

实际内核运行时，进行任务优先级管理时，是根据task_struct->prio 字段，范围 0~139，数值越小优先级越高。0-99对应实时调度优先级，100-139对应普通调度优先级。内核默认创建的普通线程优先级为120。Deadline任务的prio字段值为-1。

## 二、 用户态修改任务策略与优先级

在用户态，我们可以通过命令行工具或C语言系统调用来动态修改进程/线程的策略和优先级。在修改时，我们需要注意它们与内核底层真实现状的映射关系。

### 1. 命令行修改普通任务的Nice值和idle任务

- nice值配置

```text
# 以高权重（Nice = -20）启动程序
nice -n -20 ./my_program

# 将正在运行的 PID 为 1234 的进程 Nice 值修改为 5
renice -n 5 -p 1234

# 改变策略为 BATCH
chrt -b -p 0 1234
# 将其 Nice 值降低到 -10（提高排队权重）
renice -n -10 -p 1234
```

**与内核态的对应关系**： $内核 prio=120+\text{Nice值}$ 。

内核普通任务的基准优先级是 120。当你执行 renice -n 5 时，内核底层的 prio 变为了 125；设置为 -20 时，内核 prio 变为 100。

- **命令设置sched_idle任务**

该类任务比任何普通调度策略中的任务优先级都低，均可抢占它。

```text
chrt -i 0 ./my_background_job
```

### 2. 命令行修改实时优先级（chrt）

```text
# 将进程 1234 修改为 SCHED_FIFO 策略，实时优先级设为 50
sudo chrt -f -p 50 1234

# 以 SCHED_RR 策略、实时优先级 10 启动新程序
sudo chrt -r 10 ./my_rt_program
```

**与内核态的对应关系**： $内核prio=99-\text{用户态实时优先级}$

当执行 chrt -f -p 50 时，内核底层的 prio 会被修改为 49。如果设为最高级的 99，内核 prio 则变为 0（全系统最高实时权）。

### 3. C 语言系统调用接口修改

- **传统经典接口：sched_setscheduler**

适用于修改 SCHED_OTHER、SCHED_FIFO、SCHED_RR。

```c
#include <sched.h>
#include <stdio.h>

struct sched_param param;
param.sched_priority = 80; // 设置用户态实时优先级为 80

// 将当前线程(pid=0)设置为 SCHED_FIFO 先进先出策略
if (sched_setscheduler(0, SCHED_FIFO, &param) == -1) {
    perror("sched_setscheduler failed");
}
```

- **现代全功能接口：sched_setattr**

这是 Linux 核心推荐的新接口，也是唯一可以设置 SCHED_DEADLINE 策略的系统调用（需通过 syscall 触发）。

```c
#include <sys/syscall.h>
#include <unistd.h>
#include <sched.h>
#include <stdio.h>
#include <stdint.h>

struct sched_attr {
    uint32_t size;
    uint32_t sched_policy;
    uint64_t sched_flags;
    int32_t  sched_priority; // 针对 FIFO/RR 的实时优先级
    uint32_t sched_nice;     // 针对 OTHER/BATCH 的 Nice 值
    uint64_t sched_runtime;  // Deadline 参数：运行时间
    uint64_t sched_deadline; // Deadline 参数：截止时间
    uint64_t sched_period;   // Deadline 参数：周期
};

struct sched_attr attr = {
    .size = sizeof(attr),
    .sched_policy = SCHED_DEADLINE,       // 设置为限期调度策略
    .sched_runtime = 10 * 1000 * 1000,    // 运行时间 10ms
    .sched_deadline = 30 * 1000 * 1000,   // 截止时间 30ms
    .sched_period = 30 * 1000 * 1000,     // 周期 30ms
};

if (syscall(SYS_sched_setattr, 0, &attr, 0) == -1) {
    perror("sched_setattr failed");
}
```

与内核态的对应关系：当设置为 SCHED_DEADLINE 策略时，任务直接挂载到最高级的 Deadline 调度器（dl_sched_class）上。此时内核不再参考传统优先级，在底层将其内核 prio 赋值为 -1（代表超越 0~139 的天花板状态），完全依靠截止时间驱动抢占。
