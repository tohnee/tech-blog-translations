### 0x01 TensorRT MHA Kernel

这里先说一下背景。TRT 8.6之后，原先的一些plugin放到了TensorRT的内部，包含MHA/FMHA等。这里直接贴一下8.6的release notes。这样的好处就是，不需要手动接plugin也能用上MHA优化了，但是坏处也有，就是，用户失去了一些自主性，是否命中MHA完全由TensorRT内部控制，不好判断当前这个engine是否已经跑在MHA上了。

### 0x02 TensorRT Myelin Optimization

Myelin是TRT内部的一个概念（神秘），并且目前TensorRT暂时没有提供任何关于Myelin文档的打算，issue见：

[[Docs] Detail when Myelin is used and why](https://github.com/NVIDIA/TensorRT/issues/2576)

TensorRT图优化阶段，除了会执行手工写的一些Fusion外（比如ConvBNFusion、PWN等），还会通过Myelin进行进一步优化，被命中的Nodes会被组合成一个大的layer。如果trtexec build engine阶段，把layer info dump下来看，可以看到这个layer会拥有一个神秘的名字"Myelin"，并且被标记为ForeignNode（似乎ForeignNode在Tactic阶段会被Skip，TacticValue为0x000000000）：

```json
{ForeignNode[/Constant_7_output_0 + ONNXTRT_Broadcast.../Einsum_1]}
"LayerType": "Myelin"
```

相对于FusedMHA，官方推荐使用Myelin（似乎没也没有办法不使用？官方没有提供关掉Myelin的API，除非把图的某部分手动替换成自己写plugin），相关issue

[Difference of Myelin optimization and FusedMHA plugin](https://github.com/NVIDIA/TensorRT/issues/3108)

由于关于Myelin优化的资料实在是太少了，这里这整理一下自己搜索到的资料：

### 0x03 确认TensorRT是否使用了MHA

答案：使用nsys profile, ncu profile。根据TensorRT官方issue，如果需要判断Myelin优化后的layer是否使用了 MHA kernel，目前只能通过Nsight System进行profile，如果有出现名为`_mha`的kernel，则说明是跑在了MHA/FMHA上，否则，就是没有利用到MHA。也就是说，就算attention被Myelin命中优化，但是底层跑的kernel还不一定是MHA？这部分代码是闭源的，只能通过profile来验证了...头大...，附相关issue：

### 0x06 无法被MHA命中的Attention

为了便于测试对比，这里抄一个最简单的Attention，代码如下。这个Attention的实现由于使用了einsum op，在TensorRT 9.2中会无法命中MHA v2（个人觉得可能是TRT对Attn各种pattern的支持还不是很完善，einsum本身又太复杂，暂时无法匹配到MHA v2的pattern）。这个Attention可以用来对比naive Attention with Myelin Optimize 和 FlashAttention2的性能。

```python
# attn.py 
import math
import torch
import torch.nn as nn  
import argparse 

class QKVAttention(nn.Module):
    def __init__(self, n_heads=1):
        super().__init__()
        self.n_heads = n_heads
    
    @torch.no_grad()
    def forward(self, qkv):
        """
        Apply QKV attention.
        :param qkv: an [b,3c,h*w] tensor of Qs, Ks, and Vs.
        :return: an [b,c,h*w] tensor after attention.
        """
        bs, width, length = qkv.shape
        assert width % (3 * self.n_heads) == 0
        ch = width // (3 * self.n_heads) # ch 就是head_dim，width需要刚好是3*ch（Q、K、V）
        q, k, v = qkv.chunk(3, dim=1) # [b,c,h*w], [b,c,h*w], [b,c,h*w]
        scale = 1 / math.sqrt(math.sqrt(ch))
        weight = torch.einsum(
            "bct,bcs->bts",
            (q * scale).view(bs * self.n_heads, ch, length), 
            (k * scale).view(bs * self.n_heads, ch, length),
        ) # [b,h*w,h*w]
        weight = torch.softmax(weight.float(), dim=-1).type(weight.dtype) # [b,h*w,h*w]
        a = torch.einsum("bts,bcs->bct", weight,
                      v.reshape(bs * self.n_heads, ch, length)) # [b,h*w,h*w] * [b,c,h*w] -> [b,c,h*w]
        return a.reshape(bs, -1, length) # [b,c,h*w]

def get_args():
    parser = argparse.ArgumentParser()
    parser.add_argument("--head_num", type=int, default=1)
    parser.add_argument("--h", type=int, default=128)
    parser.add_argument("--w", type=int, default=128)
    parser.add_argument("--bs", type=int, default=1)
    parser.add_argument("--channel", type=int, default=128)
    parser.add_argument("--warmup", type=int, default=1)
    parser.add_argument("--repeat", type=int, default=100)
    args = parser.parse_args()
    return args

if __name__ == "__main__":
    args = get_args()
    print(args)

    attn_model = QKVAttention(args.head_num)
    qkv = torch.randn((args.bs, 3*args.channel, args.h*args.w)).half().cuda() 
    attn_model = attn_model.cuda().half()  

    # warmup
    import time
    st = time.time()
    for i in range(args.warmup):
        a = attn_model(qkv)
    torch.cuda.synchronize()
    print(f"warmup mean time(ms): {((time.time() - st)) * 1000 / args.warmup}")
    # repeat
    st = time.time()
    for i in range(args.repeat):
        a = attn_model(qkv)
    torch.cuda.synchronize()
    print(f"repeat mean time(ms): {((time.time() - st)) * 1000 / args.repeat}")

    # python3 attn.py --head_num 1 --h 128 --w 128 --bs 1 --channel 128
```

简单说明下，这是一个Diffusion中使用的Attention，对pixel level的feature进行注意力计算。更多的的说明，可以参考Diffusion的一些文章，比如[小小将：扩散模型之DDPM](https://zhuanlan.zhihu.com/p/563661713) 。

- 替换FlashAttention

```python
import torch
import torch.nn as nn  
from flash_attn import flash_attn_qkvpacked_func, flash_attn_func
import argparse  

class FlashQKVAttention(nn.Module):
    def __init__(self, n_heads=1):
        super().__init__()
        self.n_heads = n_heads
    
    @torch.no_grad()
    def forward(self, qkv):
        """
        Apply QKV attention.

        :param qkv: an [b,3c, h*w] tensor of Qs, Ks, and Vs.
        :return: an [b,c,h*w] tensor after attention.
        """
        qkv = qkv.permute(0, 2, 1).contiguous() # [b,h*w,3c]
        bs, seqlen, headdims = qkv.shape
        assert headdims % (3 * self.n_heads) == 0
        headdim = headdims // (3 * self.n_heads) # headdims需要刚好是3*headdim（Q、K、V） 
        q, k, v = qkv.chunk(3, dim=-1) # [b,h*w,c], [b,h*w,c], [b,h*w,c]
        q = q.view(bs, seqlen, self.n_heads, headdim)
        k = k.view(bs, seqlen, self.n_heads, headdim)
        v = v.view(bs, seqlen, self.n_heads, headdim)
        a = flash_attn_func(q, k, v) # [b,h*w,1,c] (batch_size, seqlen, nheads, headdim).
        a = a.view(bs, seqlen, self.n_heads * headdim) # [b,h*w,1*c]
        return a.permute(0, 2, 1).contiguous() # [b,1*c,h*w]

def get_args():
    parser = argparse.ArgumentParser()
    parser.add_argument("--head_num", type=int, default=1)
    parser.add_argument("--h", type=int, default=128)
    parser.add_argument("--w", type=int, default=128)
    parser.add_argument("--bs", type=int, default=1)
    parser.add_argument("--channel", type=int, default=128)
    parser.add_argument("--warmup", type=int, default=1)
    parser.add_argument("--repeat", type=int, default=100)
    args = parser.parse_args()
    return args

if __name__ == "__main__":
    args = get_args()
    print(args)

    flash_attn_model = FlashQKVAttention(args.head_num)
    qkv = torch.randn((args.bs, 3*args.channel, args.h*args.w)).half().cuda() 
    flash_attn_model = flash_attn_model.cuda().half()

    # warmup
    import time
    st = time.time()
    for i in range(args.warmup):
        a = flash_attn_model(qkv)
    torch.cuda.synchronize()
    print(f"warmup mean time(ms): {((time.time() - st) * 1000) / args.warmup}")
    # repeat
    st = time.time()
    for i in range(args.repeat):
        a = flash_attn_model(qkv)
    torch.cuda.synchronize()
    print(f"repeat mean time(ms): {((time.time() - st) * 1000) / args.repeat}")
```

补充：最后发现没有命中mha_v2 kernel，是由于图匹配的问题。本次测试用的attn中使用了einsum这个op，似乎没有被当前的Attention Pattern匹配到。按照，上边这个issue的回答，只要将重新修改一下Attn，使用torch.matmul来做矩阵乘，TensorRT的Attention pattern就能match，从而使用mha_v2 kernel。直接用github中的老哥提供的onnx文件，在TensorRT 9.2 下可以复现这个结论：

如图所示，只要按照这个pattern来改Attention，就可以用上mha_v2 kernel。Q,K,V 进入后有各自一个 MatMul，这是做线性变换，真正进入 Attention 部分，是从三个分支的 Reshape,Transpose Op 开始的，Div 是在做 scale，QK 第一个 MatMul +Softmax 就是在算 Attention，最后一个 MatMul 就是将 V 按照 Attention 进行融合。大概就这么多内容， 之后有空再补档一篇专门讲TensorRT MHA Pattern Match的文章吧。溜了溜了....

以下符合MHA pattern的Attention代码，来自评论区，感谢[lavita](https://www.zhihu.com/people/5d0e41ab23e925f02e478674b6f29ed2)提供的[Pastebin.com](https://pastebin.com/TpkPT6Wv)：

```python
class QKVAttention(nn.Module):
    def __init__(self, n_heads=1):
        super().__init__()
        self.n_heads = n_heads
    
    @torch.no_grad()
    def forward(self, qkv):
        """
        Apply QKV attention.
        :param qkv: an [b,3c,h*w] tensor of Qs, Ks, and Vs.
        :return: an [b,c,h*w] tensor after attention.
        """
        bs, width, length = qkv.shape
        assert width % (3 * self.n_heads) == 0
        ch = width // (3 * self.n_heads) # ch 就是head_dim，width需要刚好是3*ch（Q、K、V）
        qkv = qkv.transpose(-2, -1)
        q, k, v = qkv.chunk(3, dim=2) # [b,h*w,c], [b,h*w,c], [b,h*w,c]
        scale = 1 / math.sqrt(math.sqrt(ch))
        weight = torch.matmul(
            (q * scale).view(bs, self.n_heads, length, ch),
            (k * scale).view(bs, self.n_heads, length, ch).transpose(-2, -1)
        ) # [b,n,h*w,h*w]
        weight = torch.softmax(weight.float(), dim=-1).type(weight.dtype) # [b,n,h*w,h*w]
        a = torch.matmul(
            weight,
            v.reshape(bs, self.n_heads, length, ch)
        ) # [b,n,h*w,h*w] * [b,n,h*w,c] -> [b,n,h*w,c]
        return a.reshape(bs, length, -1).transpose(-2, -1) # [b,c,h*w]
```

### 0x0a FA2 IO-Accesses分析

本文对比了TensorRT 9.2下的Attention优化（有Myelin优化和MHA v2两种）与FlashAttention-2之间的差异，从这个测试结果看，FA2相对于TensorRT的Myelin优化，并不是在所有的配置下都有优势的。在head_dim=128时，128x128，128x96、64x64的seqlen下，FA2比TRT大概有20~25%的提升。而在head_dim=256时，这个结论就反过来了，是TensorRT要优于FA2。对于head_dim=512，FA2不支持，TensorRT MHA v2也不会命中，但是会使用xmma_gemm kernel直接计算。关于head_dim>256的问题，提了个issue咨询了FA2的作者大佬，详见：

[May support headdim>256? such as 512. · Issue #801 · Dao-AILab/flash-attention](https://github.com/Dao-AILab/flash-attention/issues/801)

意思就是当headnum=1, headdim>256时，可能使用原生的Attn会比flash-attn更快。

> with numhead = 1 and large headdim i think it's faster to compute attention naively rather than using flash-attn.

![](https://pic4.zhimg.com/v2-1c93dc2c6d5997f5a67106dc8cb5ca1b_r.jpg)
*FA1 Effect of Block Size*

![](https://pic3.zhimg.com/v2-11d9e918daf6752a2a03ee63ec201178_r.jpg)
*FA2 Forward Pass*

个人理解：根据论文中的算法（FA1+FA2），headdim=d越大时，意味着Br和Bc会越小，也就是Block Size会越小。Block Size越小，Runtime耗时会越大，这是由于每个thread block的SRAM能放的数据是有限的，这限制了系统中活跃的SM上限。d越大，意味着，对于相同的seqlen，需要遍历更多的次数，也就是更多的thread block。在相同的occupancy下，需要schedule更多次才能将计算算完，耗时就变高了。并且，由于Br变小，意味着外层Q循环的次数变多了，对于每一次Q的循环，都要分块加载全部的K、V到SRAM，也就是说，Memory Accesses也会增加，这也会导致耗时的增加，同时也远离了FA2优化Memory Accesses的目标。我们可以看到论文中给的FA需要的Memory Accesses计算公式：

![](https://pic4.zhimg.com/v2-277a08f995c4b45a2a72ac1c5ebd1f73_r.jpg)
*FA HBM Memory Accesses*

Memory Accesses和d的平方成正比关系，当d越大，FA的Memory Accesses会增长剧烈。比如对于N=2K, M=192KB, 当d=256时，依然满足 FA IO Acesses < Naive Attention，但是**当d=512时，这个结论就会反过来**，变成是 **FA IO Acesses > Naive Attention IO Acesses**，并且由于FA本身的FLOPS就是比Naive Attention高的，于是，此时无论是IO还是FLOPS，FA都会比Naive Attention高，无论是访存还是计算量都没有优势，唯一剩下的优势，应该就只剩节省显存了（不需要保存中间的S和P矩阵，O(N^2)的内存复杂度）

```python
# N=2048, d=256, M=192KB(A100) FA IO Acesses < Naive Attention IO Acesses
>>> 2048*256 + 2048*2048  # Naive Attention 
4718592
>>> 2048*2048*256*256/(192*1024) # FA
1398101.3333333333 
# N=2048, d=512, M=192KB(A100) FA IO Acesses > Naive Attention IO Acesses
>>> 2048*512 + 2048*2048  # Naive Attention 
5242880
>>> 2048*2048*512*512/(192*1024) # FA
5592405.333333333
```
