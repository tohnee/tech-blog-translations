1. 我为什么要自己写一遍

我一开始对张量并行（TP）的理解停留在这句话：”把权重矩阵切开，每张卡算一部分，最后 all-reduce 一下。”

然后我被一个问题问住了：

“MLP 的两个 Linear，第一个按列切、第二个按行切。为什么不能都按列切？如果都按列切会怎样？”

我当时的回答是”那样通信会变多”。追问”多多少”，我答不出来。

于是我决定不看 Megatron 的实现，先只用纸笔把公式推一遍，再用 40 行 PyTorch 实现出来，最后跑一个真实的 Llama 结构验证数值对齐。这个过程让我彻底想明白了几件事，其中最关键的是：

TP 的设计根本不是”怎么切矩阵”，而是”怎么摆放 all-reduce”。 矩阵怎么切是自由的，但每一次 all-reduce 都要付 $2\frac{N-1}{N}S$ 字节的带宽和一次全局同步。Megatron 的 Column→Row 组合之所以是”标准答案”，就是因为它把一层 MLP 的通信次数压到了理论下限：1 次。

1. 从 $Y = XA$ 开始：只有两种切法

设 $X \in \mathbb{R}^{b \times h}$（batch×hidden），$A \in \mathbb{R}^{h \times h'}$，$Y = XA$。GPU 数 $N=2$。

1.1 列切（Column Parallel）

$$ A = \begin{bmatrix} A_1 & A_2 \end{bmatrix},\quad A_i \in \mathbb{R}^{h \times h'/2} $$

$$ Y = XA = \begin{bmatrix} XA_1 & XA_2 \end{bmatrix} = \begin{bmatrix} Y_1 & Y_2 \end{bmatrix} $$

输入：每张卡都需要完整的 $X$；

输出：每张卡拿到 $Y$ 的一部分列；

前向通信：0 次（如果下游能接受切开的输出）。

1.2 行切（Row Parallel）

$$ A = \begin{bmatrix} A_1 A_2 \end{bmatrix},\quad X = \begin{bmatrix} X_1 & X_2 \end{bmatrix} $$

$$ Y = XA = X_1A_1 + X_2A_2 = Y^{(1)} + Y^{(2)} $$

输入：每张卡只需要 $X$ 的一部分列；

输出：每张卡拿到一个部分和，必须 all-reduce 才能得到 $Y$；

前向通信：1 次 all-reduce。

```text
    direction LR
    RX0["GPU0: X1 (b×h/2)"] --> RG0["X1·A1 -> 部分和"]
    RX1["GPU1: X2 (b×h/2)"] --> RG1["X2·A2 -> 部分和"]
```

看到了吗？列切的输出（被切开的列）恰好就是行切需要的输入（被切开的列）。 这就是 Column→Row 组合的全部秘密——中间那一次通信被消掉了。

1. 反向传播：那对被很多人忽略的 $f$ 和 $g$

Megatron 论文里画了两个算子 $f$ 和 $g$，很多博客直接抄图但不解释。我自己推了一遍导数才明白它们是对偶的。

2.1 列切的反向需要 all-reduce

前向：$Y_i = XA_i$。已知 $\frac{\partial L}{\partial Y_i}$，求 $\frac{\partial L}{\partial X}$：

$$ \frac{\partial L}{\partial X} = \sum_{i=1}^{N} \frac{\partial L}{\partial Y_i} A_i^{\top} $$

注意这个求和号：每张卡只能算出自己那一项 $\frac{\partial L}{\partial Y_i} A_i^{\top}$，它是完整梯度的部分和。因为前向时 $X$ 被复制到了每张卡，反向就必须把各卡的贡献加起来 —— 复制的反向是求和，这是自动微分的基本对偶律。

所以列切前需要插一个算子 $f$：

前向：identity（$X$ 已经完整，什么都不做）

反向：all-reduce

2.2 行切的反向不需要通信

前向：$Y = \sum_i X_iA_i$（all-reduce 后）。

$$ \frac{\partial L}{\partial X_i} = \frac{\partial L}{\partial Y} A_i^{\top} $$

每张卡拿着完整的 $\frac{\partial L}{\partial Y}$（因为 all-reduce 后大家都一样），乘上自己的 $A_i^\top$ 就得到自己那片输入的完整梯度。零通信。

所以行切后需要插一个算子 $g$：

前向：all-reduce

反向：identity

2.3 对偶表

| 算子 | 前向 | 反向 | 用在哪 |
| --- | --- | --- | --- |
| $f$ = CopyToModelParallelRegion | identity | all-reduce | ColumnParallelLinear 之前 |
| $g$ = ReduceFromModelParallelRegion | all-reduce | identity | RowParallelLinear 之后 |
| $f'$ = ScatterToModelParallelRegion | split | all-gather | 需要手动切输入时 |
| $g'$ = GatherFromModelParallelRegion | all-gather | split | 需要完整输出时（如 lm_head） |

```text
X["X 完整"] --> F["f<br/>fwd: identity<br/>bwd: all-reduce"]
F --> CPL["ColumnParallelLinear<br/>A 按列切"]
CPL --> ACT["GELU / SiLU<br/>逐元素，天然并行"]
ACT --> RPL["RowParallelLinear<br/>B 按行切"]
RPL --> G["g<br/>fwd: all-reduce<br/>bwd: identity"]
G --> Y["Y 完整"]
```

整个 MLP：前向 1 次 all-reduce，反向 1 次 all-reduce。这是理论下限。

2.4 回答开头那个问题：都按列切会怎样

如果第二个 Linear 也按列切，它需要完整的输入。而第一个 Linear 的输出是切开的 → 必须先 all-gather。于是：

![](https://pica.zhimg.com/v2-42affb082be2457ecc5e0897f5390988_r.jpg)

Llama 结构里 $h'=\frac{8}{3}h$ 左右（如 7B：$h=3584, h'=18944$，比值 5.3），所以 Column→Column 的通信量是 Megatron 方案的 2.6 倍以上，而且多了一次同步点。这就是我当时该说出的答案。

1. Attention 怎么切：按 head，天然优雅

多头注意力有一个绝佳性质：不同 head 之间完全独立。

$$ \text{MHA}(X) = \text{Concat}(\text{head}_1, \ldots, \text{head}_n)W^O,\quad \text{head}_j = \text{Attn}(XW_j^Q, XW_j^K, XW_j^V) $$

把 $n$ 个 head 平分给 $N$ 张卡：

$W^Q, W^K, W^V$ → 列切（按 head 维度切，等价于列切）

$W^O$ → 行切（因为它的输入是 concat 起来的 head 输出，天然是切开的）

flowchart TB

```text
X["hidden states (完整)"] --> F["f: bwd all-reduce"]
F --> Q0["GPU0: W_qkv 的 head 0..13"]
F --> Q1["GPU1: W_qkv 的 head 14..27"]
Q0 --> A0["Attention (本地 14 个 head)<br/>KV cache 也只存本地 head"]
Q1 --> A1["Attention (本地 14 个 head)"]
A0 --> O0["W_o 行切片 0"]
A1 --> O1["W_o 行切片 1"]
O0 --> G["g: fwd all-reduce"]
O1 --> G
G --> Y["hidden states (完整)"]
```

额外收益（我觉得比省计算更重要）：KV cache 也按 head 切了。7B 模型 TP=4 时，每张卡只需要存 1⁄4 的 KV cache → 可服务的上下文总长度 ×4。在长上下文场景，这往往是上 TP 的首要动机，而不是算力。

3.1 GQA 的坑

现代模型都用 GQA。以 Qwen2.5-7B 为例：num_q_heads=28, num_kv_heads=4。

![](https://picx.zhimg.com/v2-235ff6b9c57010c508013b1f8466370d_r.jpg)

TP=8 时的两种处理：

复制 KV head：每张卡都存一份完整/部分复制的 KV head。代价是 KV cache 显存不再随 TP 线性下降（vLLM 就是这么做的：num_kv_heads 不足时向上复制到 TP 数）。

不整除就报错：Megatron 的默认行为，要求 num_heads % tp == 0。

我实测 Qwen2.5-7B 在 TP=8 下，KV cache 每 token 占用不降反升（因为 4 个 kv head 被复制成 8 个），这是个很容易踩的反直觉坑。

1. Embedding 和 LM Head

4.1 输入 Embedding：按 vocab 切

$$ E \in \mathbb{R}^{V \times h},\quad E = \begin{bmatrix} E_1 \vdots E_N \end{bmatrix} $$

每张卡只持有一段词表。查表时：

落在本卡区间的 token → 正常查表

不在本卡区间的 token → 输出 0

最后 all-reduce → 得到正确结果（因为每个 token 只有一张卡贡献非零）

def forward(self, input_ids):

```text
mask = (input_ids >= self.start) & (input_ids < self.end)
local = (input_ids - self.start).clamp(0, self.num_local - 1)
out = F.embedding(local, self.weight)
out[~mask] = 0.0                    # 关键：不属于本卡的置零
dist.all_reduce(out)
return out
```

4.2 LM Head：按 vocab 切 + 并行 CE

$V=152064$，$h=3584$，logits 张量是 $b \times s \times V$。这是全模型最大的激活张量：batch=8, seq=2048, bf16 → $8 \times 2048 \times 152064 \times 2 = 4.98$ GB。如果 all-gather 成完整 logits，显存直接炸。

所以 Megatron 用 vocab-parallel cross entropy：logits 保持切开状态，只通信两个标量级别的量：

$$ \text{CE} = -\log \frac{e^{z_{y}}}{\sum_v e^{z_v}} = \log\left(\sum_v e^{z_v}\right) - z_y $$

$\max_v z_v$：all-reduce（MAX），通信量 $b\cdot s$

$\sum_v e^{z_v - \max}$：all-reduce（SUM），通信量 $b\cdot s$

$z_y$：目标 token 的 logit，只有持有它的那张卡有，all-reduce（SUM），通信量 $b\cdot s$

通信量从 $O(bsV)$ 降到 $O(bs)$，降低 15 万倍。

推理场景（比如 vLLM）反而通常会 all-gather logits，因为要做 top-p/top-k 采样、logit bias、logprobs。但推理时 $s=1$（decode），$b\times 1 \times V$ 只有几 MB，可以接受。训练和推理在这里的取舍完全相反，我觉得这是个很好的面试话题。

1. 40 行代码

先写核心（下面这段就是我数的 40 行，不含 import 和注释）：

## tp.py —— 核心 40 行

import torch import torch.nn as nn import torch.nn.functional as F import torch.distributed as dist

def _ws() -> int:

```text
return dist.get_world_size() if dist.is_initialized() else 1
```

class _Copy(torch.autograd.Function): # f: fwd identity / bwd all-reduce

```text
@staticmethod
def forward(ctx, x):
    return x

@staticmethod
def backward(ctx, g):
    if _ws() > 1:
        dist.all_reduce(g)
    return g
```

class _Reduce(torch.autograd.Function): # g: fwd all-reduce / bwd identity

```text
@staticmethod
def forward(ctx, x):
    if _ws() > 1:
        dist.all_reduce(x)
    return x

@staticmethod
def backward(ctx, g):
    return g
```

class ColumnParallelLinear(nn.Module):

```text
"""A 按列切：out_features / world_size。输入需完整，输出被切开。"""

def __init__(self, in_f, out_f, bias=True, gather_output=False):
    super().__init__()
    assert out_f % _ws() == 0, f"out_features {out_f} 不能被 TP={_ws()} 整除"
    self.part = out_f // _ws()
    self.weight = nn.Parameter(torch.empty(self.part, in_f))
    self.bias = nn.Parameter(torch.zeros(self.part)) if bias else None
    self.gather_output = gather_output

def forward(self, x):
    y = F.linear(_Copy.apply(x), self.weight, self.bias)
    if self.gather_output and _ws() > 1:
        buf = [torch.empty_like(y) for _ in range(_ws())]
        dist.all_gather(buf, y)
        y = torch.cat(buf, dim=-1)
    return y
```

class RowParallelLinear(nn.Module):

```text
"""A 按行切：in_features / world_size。输入已切开，输出需 all-reduce。"""

def __init__(self, in_f, out_f, bias=True):
    super().__init__()
    assert in_f % _ws() == 0, f"in_features {in_f} 不能被 TP={_ws()} 整除"
    self.part = in_f // _ws()
    self.weight = nn.Parameter(torch.empty(out_f, self.part))
    self.bias = nn.Parameter(torch.zeros(out_f)) if bias else None

def forward(self, x):
    y = _Reduce.apply(F.linear(x, self.weight))   # bias 不能进 all-reduce
    return y if self.bias is None else y + self.bias
```

5.1 这 40 行里我认为最容易写错的 3 处

① RowParallelLinear 的 bias 必须在 all-reduce 之后加。 如果每张卡都加自己的 bias 再 all-reduce，bias 会被加 $N$ 遍。所以行切层的 bias 是完整复制的、且只在归约后加一次。（这就是为什么 Megatron 的 RowParallelLinear 有个 skip_bias_add 参数。）

② _Reduce.forward 里的 all-reduce 是原地操作。 它作用在 F.linear 的输出上（一个全新张量），linear 的反向只需要 input 和 weight，不需要 output，所以原地安全。但如果你把 _Reduce 用在别的地方，可能触发 autograd 的版本检查错误——保险写法是 x = x.clone() 后再 reduce，代价是一次拷贝。

③ gather_output=False 是默认值，而且必须是。 如果 ColumnParallelLinear 默认 gather，那 Column→Row 的组合优势就全没了（凭空多一次 all-gather）。只有整个 TP region 的最后一层（如 lm_head）才需要 gather。

5.2 用它拼一个 Llama Block

class TPLlamaMLP(nn.Module):

```text
def __init__(self, hidden, ffn):
    super().__init__()
    self.gate = ColumnParallelLinear(hidden, ffn, bias=False)
    self.up   = ColumnParallelLinear(hidden, ffn, bias=False)
    self.down = RowParallelLinear(ffn, hidden, bias=False)

def forward(self, x):
    # SiLU 是逐元素的，作用在切开的张量上完全等价
    return self.down(F.silu(self.gate(x)) * self.up(x))
```

class TPLlamaAttention(nn.Module):

```text
def __init__(self, hidden, n_heads, n_kv_heads, head_dim):
    super().__init__()
    tp = _ws()
    assert n_heads % tp == 0
    # GQA：kv head 不够就复制（与 vLLM 策略一致）
    self.n_kv_rep = max(1, tp // n_kv_heads)
    n_kv_global = max(n_kv_heads, tp)

    self.n_local_q  = n_heads // tp
    self.n_local_kv = n_kv_global // tp
    self.head_dim = head_dim
    self.qkv = ColumnParallelLinear(
        hidden, (n_heads + 2 * n_kv_global) * head_dim, bias=False)
    self.o = RowParallelLinear(n_heads * head_dim, hidden, bias=False)

def forward(self, x, rope):
    B, S, _ = x.shape
    qkv = self.qkv(x)
    q, k, v = qkv.split([self.n_local_q * self.head_dim,
                         self.n_local_kv * self.head_dim,
                         self.n_local_kv * self.head_dim], dim=-1)
    q = q.view(B, S, self.n_local_q,  self.head_dim).transpose(1, 2)
    k = k.view(B, S, self.n_local_kv, self.head_dim).transpose(1, 2)
    v = v.view(B, S, self.n_local_kv, self.head_dim).transpose(1, 2)
    q, k = rope(q, k)
    out = F.scaled_dot_product_attention(q, k, v, is_causal=True,
                                         enable_gqa=True)
    out = out.transpose(1, 2).reshape(B, S, -1)
    return self.o(out)
```

注意 LayerNorm / RMSNorm 我没有切。 因为它作用在完整的 hidden 维度上（需要跨整个 $h$ 求均值方差），而 TP region 的边界处 hidden 是完整的。所以 norm 层的参数在每张卡上完整复制，这也意味着 norm 的梯度必须在优化器步之前 all-reduce（Megatron 通过把它们放进 _allreduce_layernorm_grads 处理）——这是我第一次写时忘掉的地方，导致多卡训练 loss 曲线和单卡对不上。

import os, torch, torch.distributed as dist

def setup():


def shard_(module, full_state):

```text
"""把单卡 checkpoint 切给当前 rank。"""
r, n = dist.get_rank(), dist.get_world_size()
for name, p in module.named_parameters():
    w = full_state[name]
    if isinstance(_owner(module, name), ColumnParallelLinear):
        p.data.copy_(w.chunk(n, dim=0)[r])      # 列切 -> 切 out_features
    elif isinstance(_owner(module, name), RowParallelLinear):
        if name.endswith("weight"):
            p.data.copy_(w.chunk(n, dim=1)[r])  # 行切 -> 切 in_features
        else:
            p.data.copy_(w)                     # bias 复制
    else:
        p.data.copy_(w)                         # norm 等复制
```

权重切分的方向极易搞反：PyTorch 的 nn.Linear.weight 形状是 [out_features, in_features]（转置存储）。所以”按列切 $A$“在代码里是切 weight 的 dim=0，”按行切 $A$“是切 weight 的 dim=1。我第一次写反了，结果不报错、能跑、loss 就是不降——这类 bug 最难查，所以数值对齐验证是必须的第一步。

1. 通信量分析：TP 到底能扩到几张卡

6.1 公式推导

Ring all-reduce 传输 $S$ 字节需要移动 $2\frac{N-1}{N}S$ 字节（reduce-scatter + all-gather 各 $\frac{N-1}{N}S$）。

每个 Transformer layer 前向有 2 次 all-reduce（attention 的 $g$ + MLP 的 $g$），每次数据量 $S = b \cdot s \cdot h \cdot \text{bytes}$。

每层前向通信量：

$$ C_{\text{layer}} = 2 \times 2\frac{N-1}{N} \cdot bsh \cdot \text{bytes} $$

全模型（$L$ 层）：

$$ C_{\text{fwd}} = 4L\frac{N-1}{N} \cdot bsh \cdot \text{bytes} $$

代入 Qwen2.5-7B（$L=28, h=3584$），bf16，$N=4$：

![](https://pic3.zhimg.com/v2-5aa05947f69c98e7ba556e07496d09b2_r.jpg)

6.2 关键洞察：decode 阶段是”延迟敏感”，不是”带宽敏感”

$b=1$ decode 时，单次 all-reduce 只有 7 KB。7 KB 在任何互联上都是”零带宽消耗”，但它要付 一次固定延迟。

NVLink（A800）：小消息 all-reduce 约 8~12 µs

PCIe Gen4 x16 + 无 P2P（L20 常见配置）：约 25~45 µs

$28$ 层 × 2 次 = 56 次 all-reduce：

![](https://pic2.zhimg.com/v2-5eb9e45ce0308bd52b26fbbae399d2d3_r.jpg)

6.4 什么时候该上 Sequence Parallel

TP 有个明显的浪费：LayerNorm 和 Dropout 的输入输出（$bsh$ 大小的激活）在每张卡上完整复制。Sequence Parallel（SP）把这部分按 seq 维度也切开：

flowchart LR

```text
subgraph TP["纯 TP"]
    T1["Norm 输入: b×s×h 完整<br/>每卡都存一份"] --> T2["all-reduce"] 
end
subgraph SP["TP + SP"]
    S1["Norm 输入: b×(s/N)×h<br/>激活显存 /N"] --> S2["reduce-scatter 替代 all-reduce"] --> S3["all-gather 替代 identity"]
end
```

替换规则：

![](https://pic2.zhimg.com/v2-e85e06e6be6275d2e97def4f399c734b_r.jpg)

通信总量完全不变（因为 all-reduce = reduce-scatter + all-gather），但激活显存降为 $1/N$。代码改动只有那两个 autograd.Function：

class _GatherSeq(torch.autograd.Function): # 替代 f 的 forward

```text
@staticmethod
def forward(ctx, x):
    buf = [torch.empty_like(x) for _ in range(_ws())]
    dist.all_gather(buf, x)
    return torch.cat(buf, dim=1)           # dim=1 是 seq 维
@staticmethod
def backward(ctx, g):
    return g.chunk(_ws(), dim=1)[dist.get_rank()].contiguous()
```

这是我觉得最”划算”的一个改动：十几行代码，换 $1/N$ 的激活显存，零额外通信。

1. 我踩过的 6 个坑（按痛苦程度排序）

坑 1：权重切分方向反了，不报错、loss 不降

如前所述，nn.Linear.weight 是 [out, in] 转置存储。唯一防御手段是写数值对齐测试，不要相信”能跑起来”。

坑 2：RowParallel 的 bias 被加了 N 遍

症状：TP=2 时输出比单卡大一点点，TP=4 大更多。定位方法：把 bias 全置 0 再对比，如果对上了就是 bias 问题。

坑 3：Dropout 的随机数种子

TP region 内部（切开的部分）的 dropout mask 必须每卡不同，否则等价于只 dropout 了 $1/N$ 的模式，正则强度不对。 TP region 外部（完整复制的部分，如 norm 之后）的 dropout mask 必须每卡相同，否则不同卡的”完整”激活会不一致，直接分叉。

Megatron 用两个独立的 RNG state 来管：model-parallel-rng（每卡不同 seed）和 data-parallel-rng（每卡相同）。我认为这是整个 TP 实现里最反直觉、也最容易被面试官问到的细节。

坑 4：norm / embedding 的梯度忘了 all-reduce

复制的参数（RMSNorm 权重、tied embedding）在每张卡上算出的梯度是不同的（因为反向传入的梯度经过了不同的本地权重）。必须在 optimizer.step 前 all-reduce，否则各卡权重会缓慢分叉。

自查方法：训练几百步后 all-gather 所有 rank 的 norm 权重比对，应该完全一致。

坑 5：vocab 不能被 TP 整除

$V=152064$，$152064 / 8 = 19008$ ✓，但很多模型的 vocab 是奇怪的数（如 32000 / 3 不整除）。做法是 pad 到 $N$ 的倍数，pad 位置的 logits 设为 $-\infty$。Megatron 有个 make_vocab_size_divisible_by=128 参数就是干这个的（128 是为了 tensor core 对齐）。

坑 6：all-reduce 的 dtype

如果用 bf16 做 all-reduce，$N$ 个部分和相加会累积舍入误差。大规模训练建议梯度 all-reduce 用 fp32（或用 NCCL 的 avg op + fp32 累加）。推理场景 bf16 all-reduce 完全够用。

1. 给自己准备的追问清单

MLP 为什么是 Column→Row？都 Column 会怎样？

→ 因为列切的输出形状恰好是行切的输入形状，中间那次通信被消掉了；都列切要多一次 all-gather，通信量涨 2.6 倍（按 Llama 的 $h'/h$ 比值算）。

$f$ 和 $g$ 的反向为什么是那样？

→ 自动微分对偶律：复制的反向是求和，求和的反向是复制。列切前复制了 $X$ → 反向必须 all-reduce；行切后求和了 $Y$ → 反向直接分发。

TP 为什么一般不跨机？

→ 每层 2 次 all-reduce，全模型几十次同步。跨机 RDMA 小消息延迟 5~10 µs 起，加上不能走 P2P，56 次同步的固定开销会直接吃掉几毫秒。TP 只在 NVLink 域内用，跨机用 PP 或 DP（通信次数是 $O(1)$ 或 $O(L/\text{stage})$）。

LayerNorm 为什么不切？

→ 它需要在完整 hidden 维度上统计均值方差；而且它在 TP region 边界处，那里 hidden 本来就是完整的。参数复制，但梯度要 all-reduce。

TP=8 跑 GQA(kv_heads=4) 模型，KV cache 显存变化？

→ 不降反升。kv head 会被复制到 8 份，每卡 1 个 head，总量是原来的 2 倍。

decode 阶段 TP 的瓶颈是带宽还是延迟？

→ 延迟。$b=1$ 时单次 all-reduce 只有 7 KB，纯粹在付固定延迟；这也是 vLLM 要写 custom one-shot all-reduce 的原因（NCCL 的 ring 算法对小消息不友好）。

Sequence Parallel 省了什么，代价是什么？

→ 省 $1/N$ 的激活显存（norm/dropout 那部分），通信总量不变（all-reduce 拆成 reduce-scatter + all-gather），代价是实现复杂度和更多的同步点。

为什么 dropout 需要两套 RNG？

→ TP region 内切开的张量要不同 mask（否则等效 dropout 率变成 $1/N$）；region 外复制的张量要相同 mask（否则各卡状态分叉）。

权重怎么从单卡 checkpoint 切到 TP=8？

→ 列切层切 weight 的 dim=0，行切层切 dim=1，norm/bias 复制，融合层（qkv、gate_up）要先按子矩阵拆再各自切（这是最容易错的：不能直接对融合大矩阵整体 chunk）。

怎么验证 TP 实现是对的？

→ 数值对齐测试（相对误差同阶于 dtype eps）+ 长训练后各 rank 复制参数的一致性检查 + 通信量的理论值 vs nsys 实测值对照。
