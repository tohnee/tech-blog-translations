10 月 21 日，国内文档智能团队 SoMark 开源了文档解析模型 OXR（Optical Everything Recognition）。

主模型只有 **1.3B**参数，官方口径在 OmniDocBench、olmOCR-Bench、DocParsingBench 三项基准全部登顶，100 页文档单张 RTX PRO 6000 端到端跑出 101 秒，官方称是开源模型里的最快速度。

更难得的是验货方式：官方免费 API 免注册、免申请 Key，一条命令就能把自己的 PDF 丢进去；想本地部署，1.3B 的体量消费级显卡就能跑。已有上手实测显示，手写数学笔记、化学结构式、双栏论文甚至数学试卷，都能直接转成结构化 Markdown。

榜单是它自己跑的，代码也一并开源了——这是近期 AI 发布里少见的、允许你当场验货的"第一"。

**先说清楚：三榜第一，都是官方口径**

先把这次发布的核心事实列清楚。

**三项基准成绩（厂商自报）：**

· OmniDocBench：**97.18 分，第一（官方测试）**。该基准由上海人工智能实验室开源，覆盖 10 类复杂文档。

· olmOCR-Bench：**87.84 分，第一（官方测试）**。由海外机构 Ai2 团队推出，包含 7000 多道单元测试级题目。

· DocParsingBench：**87.76 分，第一（官方测试）**。覆盖 5 大行业、14 个真实业务场景。

这三个分数全部来自 SoMark 自己的测试，目前缺少第三方独立复测。好的一点是，整套评测流程和代码随模型一起开源，任何人都可以复现验证。

**能力范围：**OXR 能解析 13 类文档元素——表格、公式、代码块、图片、化学方程式、脚注、页眉、页脚、印章等，输出带版面坐标的 Markdown 或 JSON。这个输出格式是奔着 RAG 和 Agent 工作流去的，不只是把图变成字。

**真正的变化之一：RSI 被用进了 OCR 训练**

榜单之外，OXR 真正值得看的是训练方法。

文档解析领域有个思维定势：要极致精度，就得堆大模型、堆人工标注。但文档排版千奇百怪，人工标注成本高、错误率也不低，真实世界的长尾 Bad Case 永远穷尽不了——数据准备的速度，卡死了模型进化的脖子。

SoMark 的解法基于一个常被忽视的特性：文档解析的每份输入，都有客观确定的标准答案。文字对不对、表格跨行跨列有没有错、公式符号有没有漏，都能被精确测量。既然能客观判断对错，就不需要等人来标注。

于是 OXR 在后训练阶段引入了递归自我改进（RSI）范式：不依赖新增人工标注，让模型自己找错、自己分析原因、自己准备下一轮训练数据。整个闭环分三步。

**第一步，预测与分类。**OXR 先解析海量无标签真实文档，再由一个通用多模态模型（General VLM）当裁判，把样本分成 Correct、Wrong、Uncertain 三档。保留“不确定”这一档是个反直觉的设计：如果只给对和错两个选项，裁判的犹豫会被强行包装成确定标签，把噪声喂给下一轮训练。此外 OXR 还会对自己做多次 rollout 采样，同一份文档跑几次结果差异很大，直接进 Uncertain；再对高分歧样本做轻微图像扰动（缩放、压缩、模糊、平移），分歧进一步扩大的，当场记为模型的一条视觉脆弱点。

**第二步，归因与聚类。**General VLM 逐个样本诊断错因——是跨列单元格对齐失败，还是手写连笔识别错误——诊断出的自然语言原因经 SigLIP2 提取特征后聚类，形成“原因簇”。一张财务报表和一张化学实验记录表，外观八竿子打不着，如果都死在某种罕见的跨行跨列结构上，就会被提炼成同一个数据构造方向。

**第三步，数据生成。**原因簇提供结构难点，真实样本池提供版式风格锚点，扰动测试发现的视觉脆弱点也被系统性编进合成管线。生成的数据经过规范校验后，直接回流训练下一代 OXR。一轮跑完短板被补齐，新一轮真实文档又会暴露新短板，驱动下一轮迭代。

![](https://pic3.zhimg.com/v2-962a179d7436232ce1f2a96c16f867da_r.jpg)
*图 3｜OXR 的 RSI 训练闭环：预测分类、归因聚类、数据生成三个阶段，生成数据回流训练下一代模型*

按官方的说法，这正是 OXR 只用 1.3B 参数就做到高精度的原因：数据质量足够高，模型就不需要靠臃肿的参数量去死记硬背。需要提醒，RSI 带来的具体收益比例和迭代轮数，官方没有公开量化数据。

**真正的变化之二：精度速度双第一，靠一次架构重构**

准确率第一可以靠数据堆出来，速度同时第一，就不是模型小能解释的了。

先看行业走过的路。最早的 Pipeline 方案，检测、识别、排序各用一个独立模型，臃肿难维护；后来流行端到端大模型一锅端，优雅但自回归生成长序列太吃算力；这两年成为标准解法的是 PaddleOCR-VL 的两阶段方案——把版面分析（LA）和阅读顺序（RO）合并成一个小模型，后接识别模型。问题也随之而来：每增加一条版面标注，必须同时绑定一条阅读顺序标注，数据处理难度直接翻倍。

OXR 反着走了一步：**独立的轻量模型只负责版面分析，OXR 主模型同时负责内容识别与阅读顺序判断**。

这个拆法带来两个直接收益。其一，阅读顺序判断的耗时原本就远小于文本识别，并入主模型几乎不增加时间，反而因为主模型具备语义理解能力，排序准确率还提升了；卸下排序包袱的版面分析模型任务极度纯粹，可以采用更轻的检测模型，整体吞吐量上去了。其二，版面分析模块完全可插拔——不同业务对版面划分的需求常常打架，业务方可以用自己训练的私有版面模型无缝替换，继续复用 OXR 的识别能力。

![](https://pic1.zhimg.com/v2-2f8bb6500118b13b388acb4c6ab6dcda_r.jpg)
*图 4｜OXR 的可插拔架构：版面分析模块独立，识别与阅读顺序合并进同一主模型*

落到数字上：官方测试口径，单张 RTX PRO 6000 端到端解析 100 页文档耗时 **101 秒（官方测试）**，快于同场参测的 PaddleOCR-VL-1.6 和 MinerU2.5-Pro。同样提醒，这是厂商自报成绩。

**这些数字，先打个问号再用**

把证据等级摆清楚。

**可以采信的：**开源行为本身（GitHub 仓库公开、权重可下载）、10 月 21 日的发布时间、免费 API 的存在、官方演示与量子位作者的上手实测、GitHub Star 与 X 热榜等社区反馈。

**属于厂商自述的：**三项基准得分、101 秒速度、快过 PaddleOCR-VL 与 MinerU 的对比、RSI 范式的实际收益。还有一个细节：官方海报把柱状图纵轴从约 85 分起画，视觉上放大了领先幅度，实际与第二名的分差在 0.2 到 1 分的量级。

**目前未知的：**OXR 在你自己文档上的真实准确率；免费 API 的负载上限和长期维护承诺——官方原话是“至少在服务器负载仍能承受的区间内”维护；开源版与商业引擎 SoMark 的具体能力差，目前只知道商业版支持 Word、PPT、Excel 等更多格式和更完善的后处理定制。

**现在就能验证，但别急着接生产**

给想上手的开发者一条低成本验证路径。

**第一步，零成本验货。**用官方免费 API 或在线 Demo，直接跑你业务里最头疼的那批 PDF——双栏论文、跨页表格、扫描件。文档解析的好坏高度依赖真实文档分布，自己的样本比任何榜单都有说服力。

**第二步，本地部署压测。**OXR 适配了主流推理框架，用官方 Docker 或 CLI 挂载插件即可拉起服务，不需要重新编译 vLLM。1.3B 的体量，RTX 3060 级别的显卡就能跑，适合对数据私密性有要求的场景。

**第三步，评估是否上生产。**重点观察三个指标：自有文档集上的准确率、并发与延迟表现、版面分析模块是否需要替换成自己的模型。如果还要处理 Word、PPT、Excel 等格式或更深的后处理定制，再去评估商业引擎 SoMark。

回到开头那句话：这个"第一"允许你当场验货。那就去验——拿自己最难的那批文档。

卡了 RAG 两年的从来不是技术，是没人肯让你便宜地试错。OXR 把入场券降到了零，剩下的问题只有一个：你的文档，它读不读得懂。榜单说了不算，你的 PDF 说了算。
