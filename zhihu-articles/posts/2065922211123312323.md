## 最近两周，微调模型的时候，被 LoRA 坑得有点惨。

### 前情提要

我们公司要做一个垂域模型。对于小公司来说，想要真正交付一个模型，SFT 基本还是最现实的路线。

而且我们做的是知识类模型，不是数学、代码类模型。现在模型跑分上不去，我个人觉得，主要问题不是推理能力不够，而是缺少领域知识。

简单来说：

- **全量 SFT** ：相当于把整个大模型的大脑从头到脚全部回炉重造一遍，让它适应新的领域和任务。效果通常比较好，但烧钱、烧显存、烧时间，而且每个任务都要保存一份完整模型，切换任务比较麻烦。
- **LoRA** ：相当于大脑主体不动，只在旁边挂一个微型助听器，训练这个助听器，让模型听懂新任务。它显存占用小、训练速度快、存储成本低，切换任务时只需要更换 LoRA 权重，效果有时也不输全量微调。

我们的目标是训练一个知识类模型。

我先洗了一批知识点。通过一些比较“邪修”的数据处理方法，我基本可以保证，这批数据如果真的训进模型，benchmark跑分一定会提升。

一上来，我先用 LoRA 训练，一点都没效果。

我判断是数据多样性不够，于是混了各种数据，benchmark 分数还是波动不大，甚至基本保持不变。我以为是数据质量不够，然后我又洗了很多数据，继续训练，还是没什么明显效果。

这里还有一个原因：我听了同事的话，觉得 SFT 一个 epoch 基本就差不多了。

这个时候我开始怀疑：

> 是不是这些知识根本没有训进模型？

### 先做一个最直接的实验

为了确认知识到底有没有被训进去，我用同一批数据分别训练 LoRA 和 Full SFT，在关闭 thinking 的情况下直接让模型回答训练的问题，并对比 1、2、5 轮训练后的输出与参考答案。

预期结果是：如果 LoRA 真正把知识训进去了，那么模型的输出和训练的参考答案应该是差不多的，如果差很多，就是没训进去。

实验中：

- `full` 表示全量微调；
- `lora` 表示 LoRA 微调；
- `ep` 表示 epoch，也就是完整遍历训练集的次数；
- `ep1` 表示训练 1 轮；
- `ep2` 表示训练 2 轮；
- `ep5` 表示训练 5 轮。

这次实验一共评测了 4,739 条问答数据。

### 指标说明

**Exact Match** ：答案和参考答案进行严格字符串匹配，完全一致才算正确。

**ROUGE-1 F1** ：统计答案和参考答案之间单词或字词级别的重合程度。

**ROUGE-2 F1** ：统计连续两个字词之间的重合程度，比 ROUGE-1 更关注局部表达是否一致。

ROUGE 主要反映答案和参考答案的文本相似程度，并不等价于答案一定正确。

基座模型是 Qwen3.5 9B，以下结果均为关闭 thinking 的结果。

| 模型 | Exact Match | ROUGE-1 | ROUGE-2 |
| --- | --- | --- | --- |
| base | 0.00% | 0.1579 | 0.0998 |
| LoRA ep1 | 2.45% | 0.6122 | 0.4684 |
| LoRA ep2 | 3.84% | 0.6471 | 0.5079 |
| LoRA ep5 | 23.04% | 0.8153 | 0.7336 |
| Full ep1 | 11.44% | 0.7380 | 0.6300 |
| Full ep2 | 43.62% | 0.8899 | 0.8405 |
| Full ep5 | 95.80% | 0.9917 | 0.9880 |

结果基本证明了我的猜测：

> LoRA 训练一轮，确实很难把知识稳定地训进去。

我当时看到这个结果是真的吐了。前面浪费了这么多时间，最后发现问题可能只是训练轮数不够。回头得找同事“线下battle”一下。

### 实验结果分析

### 1. LoRA 不是完全学不进，而是单轮学得非常慢

严格 Exact Match 的结果中：

- LoRA ep1：2.45%
- LoRA ep2：3.84%
- LoRA ep5：23.04%

所以更准确的说法不是“LoRA 完全学不进知识”，而是：

> 在这组知识型数据和当前 LoRA 参数下，训练一轮几乎不足以让关键事实形成稳定记忆。

LoRA ep1 的 ROUGE-1 已经达到 0.6122，说明模型输出的表达形式、句式和参考答案已经比较接近了。

但是 Exact Match 只有 2.45%，说明“看起来像答案”和“关键事实完全正确”之间，仍然有很大差距。

### 2. 全量微调的知识注入速度明显更快

Full ep1 的结果已经超过 LoRA ep2：

| 模型 | Exact Match | ROUGE-1 | 语义正确率 |
| --- | --- | --- | --- |
| LoRA ep2 | 3.84% | 0.6471 | 54.17% |
| Full ep1 | 11.44% | 0.7380 | 68.66% |

Full ep1 的 Exact Match 接近 LoRA ep2 的 3 倍，语义正确率也高出 14.49 个百分点。

进一步看：

- Full ep2 的 Exact Match 是 43.62%；
- LoRA ep5 的 Exact Match 是 23.04%。

也就是说，在这组实验中，全量训练 2 轮的效果，仍然明显超过 LoRA 训练 5 轮。

因此，“全量微调一轮至少比 LoRA 两轮强”这个判断，在当前数据和参数设置下是成立的。不过它不是一个普遍适用于所有数据集和模型的定律。

### 3. LoRA 需要更多训练轮数，才能逐渐补齐关键知识

LoRA 从 ep1 到 ep5，语义正确率从 47.52% 提升到了 81.64%，说明它并不是没有学习能力。

它的问题更像是：

- 前几轮先学会了回答格式；
- 然后逐渐学到问题和答案之间的对应关系；
- 经过更多轮训练后，才开始稳定记住具体知识点。

而全量微调由于所有参数都可以直接更新，知识注入速度更快，前几轮就能明显提升。

这也解释了为什么我之前用 LoRA 训练一个 epoch，benchmark 几乎没有变化。不是数据没用，而是模型还没有训练到能够稳定调用这些知识的程度。

### 4. ROUGE 高，不代表关键知识点正确

这个实验里最典型的现象就是：

> ROUGE 提升得很快，但 Exact Match 提升得很慢。

这通常说明模型已经学会了：

- 回答的整体格式；
- 句子的长度和风格；
- 领域术语；
- 参考答案中的常见表达。

但是它不一定已经记住了真正决定答案正确与否的那个数字、概念或结论。

只记住了格式没啥用，benchmark没啥提升，该错还是错。

所以，LoRA 确实比较容易先学会“怎么回答”，但不代表它已经完全学会“回答什么”。

### 举一个具体例子

case by case分析确实能看出点问题

问题：

> 三通道 24 小时动态心电图（Holter）检查时，通常需要使用多少个电极？

参考回答：

> 通常使用 7 个电极。

模型输出如下：

| 模型 | 输出 |
| --- | --- |
| base | 通常需要使用 3 个电极。 |
| LoRA ep1 | 通常需要使用 3 个电极。 |
| LoRA ep2 | 通常需要使用 3 个电极。 |
| LoRA ep5 | 通常使用 7 个电极（包括地线）。 |
| Full ep1 | 通常使用 7 个电极。 |
| Full ep2 | 通常使用 7 个电极（包括参考电极）。 |
| Full ep5 | 通常使用 7 个电极。 |

这个例子非常典型。

LoRA ep1 和 LoRA ep2 的回答形式已经非常像标准答案了，回答也很简洁，但核心数字仍然是错的。

到了 LoRA ep5，模型才把“3 个电极”改成了“7 个电极”。

这就是为什么 LoRA 的 ROUGE 可能已经很高，但 benchmark 中对应的题目仍然会错：格式学到了，关键事实没有完全学到。

当然，这个例子中的医学答案具体还可能受到导联配置和教材口径影响。这里主要是按照本次数据集中的参考答案，观察模型是否能够复现指定知识点。

### 用DeepSeek来做校核

Exact Match 这个指标有一个明显缺点：它要求答案和参考答案逐字一致。

比如参考答案是：

> 通常使用 7 个电极。

模型回答：

> 通常使用 7 个电极（包括参考电极）。

这两个答案从语义上看基本一致，但 Exact Match 仍然会判错。

因此，我又使用 DeepSeek 对模型答案进行语义正确性判断，得到下面的结果：

| 模型 | 正确数 | 错误数 | 语义正确率 |
| --- | --- | --- | --- |
| base | 2,144 | 2,595 | 45.24% |
| LoRA ep1 | 2,252 | 2,487 | 47.52% |
| LoRA ep2 | 2,567 | 2,172 | 54.17% |
| LoRA ep5 | 3,869 | 870 | 81.64% |
| Full ep1 | 3,254 | 1,485 | 68.66% |
| Full ep2 | 4,264 | 475 | 89.98% |
| Full ep5 | 4,722 | 17 | 99.64% |

这组结果和 Exact Match 的趋势基本一致：

- LoRA ep1 只有小幅提升；
- LoRA ep2 开始逐渐提升；
- LoRA ep5 已经有比较明显的知识注入；
- Full ep1 的提升速度明显快于 LoRA；
- Full ep5 基本可以复现这批数据中的绝大多数知识点。

这里也能看到，base 模型的 Exact Match 是 0%，但语义正确率有 45.24%。这说明基座模型并不是完全不会回答，而是经常使用了不同的表达、单位或更长的解释，导致严格字符串匹配失败。

从侧面说明，base模型其实也是具有一部分相关知识的。

### 最后展示一下实验参数

### LoRA

- LoRA rank：16
- LoRA alpha：32
- LoRA dropout：0.05
- Global batch size：120
- 学习率： `1e-4`
- 训练轮数：1、2、5

### Full SFT

- Global batch size：120
- 学习率： `1e-5`
- 训练轮数：1、2、5

### 最后总结一下

第一，SFT 确实可以把知识训进模型。哪怕这种学习有一定的死记硬背成分，对于知识型垂域模型来说也并不是坏事，因为我们的目标本来就是补充基座模型缺失的领域知识，或者错误的知识。

第二，在当前这组数据和参数下，全量微调的知识注入速度明显快于 LoRA。Full ep1 已经超过 LoRA ep2，Full ep2 也超过了 LoRA ep5。

第三，LoRA 不是完全学不进知识，而是需要更多训练轮数。LoRA 训练一轮可能主要学到回答格式和表达方式，关键知识点还没有形成稳定记忆。

所以，这篇文章的标题虽然叫“LoRA 微调学不进知识？”，但更准确的结论应该是：

> LoRA 不是学不进知识，而是在当前实验设置下，单轮 LoRA 对知识的注入速度明显慢于全量微调。它可能很快学会回答格式，但需要更多训练轮数，才能稳定记住关键事实。

当然Full SFT可能会造成灾难性遗忘，我目前能做到，垂直领域的分提升，通用领域掉一点，但这是后话，关注我，我之后继续分享。
