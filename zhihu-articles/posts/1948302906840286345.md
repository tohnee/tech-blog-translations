上篇文章 [《GraphRAG多智能体工作流编排》](https://zhuanlan.zhihu.com/p/1946962533769512172) 介绍了在Dify平台上通过Chatflow实现对多个GraphRAG问答智能体的智能路由与调用，构建统一入口的多领域智能问答助手，本篇介绍一下Coze Studio平台上的实现。

在扣子平台上，用“智能体”类应用来实现，因为它可以提供内置的对话上下文管理，作用类似于Dify的Chatflow。“应用”类则属于工作流，与Dify的workflow类似，它不提供内置的对话上下文管理，虽然通过它的用户变量也可以实现对话上下文的管理，但对智能问答的支持没有“智能体”类多，本篇先用“智能体”类来实现。

一、智能体定义

这是智能体的定义（编排）和测试界面：

![](https://pica.zhimg.com/v2-bd7bb9de33609d38ca4d4e8fc099c6dc_r.jpg)
*图1 扣子智能体编排和测试界面*

它引用了一个GraphRAG_Agents工作流工具调用多个GraphRAG智能体来回答问题。它也可以直接调用插件工具来通过GraphRAG方法检索数据，然后自己回答问题，这应该是该框架中GraphRAG最高效的用法，但是有两个问题限制了对这类插件工具的直接调用：

1、插件工具需要验证用户的身份，通常这需要先执行一个login操作。

2、原来设计的那些GraphRAG智能体，是完整的GraphRAG Agent，收到问题后完成GraphRAG检索，然后直接回答问题，输出的是问答API，并没有单独输出各个检索方法的API。用业务的视角来说，就是由领域专家直接回答了问题。

所以这里要像Dify平台一样，定义一个工作流工具来完成多个GraphRAG智能体的路由与调用。这是定义好的工作流工具，后面会详细介绍。

![](https://picx.zhimg.com/v2-ab73f2294aa04e01d22bb9a04556c06b_r.jpg)
*图2 智能体中调用的工作流*

智能体的系统提示词，指示智能体根据需要调用GraphRAG_Agents工具来回答问题，如果根据上下文可以直接回答，就直接回答，对GraphRAG_Agents返回的答复原样输出。

你是一个{#InputSlot placeholder="智能体人设"#}资深银行业务专家{#/InputSlot#}，能够熟练调用{#LibraryBlock id="7546790653955407872" uuid="irBggKA2En6ELH4XmobrJ" type="workflow"#}GraphRAG_Agents{#/LibraryBlock#}工具，回答用户{#InputSlot placeholder="智能体工作目标"#}各类银行业务问题{#/InputSlot#}。

## 技能
### 技能 1: {#InputSlot placeholder="智能体技能"#}按用户的需求回答业务问题{#/InputSlot#}
你有4个可以调用的GraphRAG问答智能体，你要根据用户的问题和用户问答的上下文调用{#LibraryBlock id="7546790653955407872" uuid="fW_VO6-bp5EtuABUusjmb" type="workflow"#}GraphRAG_Agents{#/LibraryBlock#}来回答问题。
如果根据用户问答的上下文可以直接回答问题，就直接回答问题。
如果用户要求清空智能体会话记录或重置会话，也调用{#LibraryBlock id="7546790653955407872" uuid="lNNyW0Y2gNDVT3gJV4BvU" type="workflow"#}GraphRAG_Agents{#/LibraryBlock#}，把用户的指令转发给该工具。

## 可用GraphRAG智能体列表
1、 银行软件开发业务规则文档智能体，可以根据用户的问题检索相关的银行软件开发文档，包括各种业务规则的文档。
2、 银行工作流智能体，可以根据银行的工作流检索与工作流中特定节点相关的银行业务规则。
3、 银行会计核算规程智能体，可以回答《银行会计核算规程》有关的问题。

## 限制:
- 调用{#LibraryBlock id="7546790653955407872" uuid="RyAy2zQSmrl1mM3utHlEe" type="workflow"#}GraphRAG_Agents{#/LibraryBlock#}工具时，直接转发用户的问题给它即可，它知道该调用哪个智能体来回答问题。
- 如果调用了{#LibraryBlock id="7546790653955407872" uuid="i7Mrkmb5drkUzeWC6JnwU" type="workflow"#}GraphRAG_Agents{#/LibraryBlock#}工具来回答问题，直接原样输出该工具的回复，包括其中的数据引用信息。你不必再进行总结，也不需要作任何的修改或附加任何的信息。

三、GraphRAG_Agents工作流工具

这是一个根据用户问题路由到适合的GraphRAG智能体并回答的问题的单次工作流，它没有对问答记录上下文的引用，只回答与GraphRAG智能体领域相关的单个问题。流程全图见前面图2。

开始节点是用户提交的问题。

![](https://pic3.zhimg.com/v2-174c1e491a5e54cdcea780e748788a24_1440w.jpg)
*图6 开始节点*

login节点引用了2个用户变量username和password，返回的Authoriztion token在data["token"]中。

![](https://pica.zhimg.com/v2-5708ed43062086b12e3baff6dd17269a_1440w.jpg)
*图7 用户身份验证节点*

用户变量可以在“智能体”编排的主界面中定义，然后工作流中就可以引用，它们定义了访问智能体总线的用户名和MD5密码。

![](https://picx.zhimg.com/v2-1923c7e82d7488bc6cd873017aa29147_r.jpg)
*图8 定义用户变量*

然后用一段小的Python代码，为提取的Authorization token加上"Bearer "前缀，它的输入是login节点输出的data["token"]变量，映射为变量名token，输出合并好的token变量。

![](https://pic2.zhimg.com/v2-ad682ed56f856202b5e049bf247e1aed_1440w.jpg)
*图9 拼装Authorization token*

```text
async def main(args: Args) -> Output:
    params = args.params
    # 构建输出对象
    ret: Output = {
        "token": "Bearer "+params['token'], # 为token加上"Bearer "头。
        }
    return ret
```

然后是智能体路由器，根据用户的问题选择合适的智能体来回答。

![](https://pica.zhimg.com/v2-e58996fe95716784138c14b06ab38890_1440w.jpg)
*图10 智能体路由节点*

**注意这里没有找到可以引用对话历史的地方，“智能体”应用里没有输出对话历史的变量，这是它的不足之处。** 实际上，在前面“智能体”的系统提示词中，已经指示它如果根据对话历史可以回答问题，就直接回答，其它需要调GraphRAG智能体的才会调用工作流，所以在工作流里不会有直接回答这种情况。但是能够根据对话历史来决定该路由到那个智能体应该还是有好处的，特别是在智能体文档覆盖范围有重叠的时候。

*银行会计核算规程中现金存入分录是什么？*

```text
根据银行会计核算规程，现金存入（现金收款业务）的会计分录如下：

**借：1001010101 库存现金**  
**贷：XX存款**  

### 分录说明：
- **借方**：记录在“库存现金”科目（科目代码1001010101），表示银行收到了现金。
- **贷方**：记录在相应的存款科目（“XX”根据具体存款类型而定），表示客户的存款账户增加了相应金额。

### 业务处理流程：
1. **审核凭证**：核对收款凭证的真实性和完整性。
2. **核验大数**：确认现金金额与凭证金额一致。
3. **清点现金**：确保现金的实际清点无误。

六、进一步探讨

开源版扣子的智能体实现乃至工作流实现，有一个很大的限制，就是智能体或工作流的定义不能导入导出，在开发环境测试好后，到生产环境部署要重建一次，这非常麻烦，也很容易出错。没有提供这个功能更多的应该是商业上的考虑。与此相对，Dify开源版在用户使用授权上虽然作了限制，但Chatflow和workflow都是可以导出导入的，这为生产部署提供了很大的方便。软件开发运维需要巨大的投入，需要形成正反馈才能让生态维持及繁荣壮大，商业上获取相应的回报是很合理的。如何平衡通过开源免费来迅速扩大生态与通过商业运作来维持生态，是各厂商都需要平衡和取舍的问题，也许对每个厂商来说都不是个容易的问题。作为开源社区的用户和支持者，人们能做的只是多作贡献，企业能够付费使用的时候就尽量支持一下。希望在AI agent落地的风口下，大家都能乘上这股东风，都能有好的发展。
