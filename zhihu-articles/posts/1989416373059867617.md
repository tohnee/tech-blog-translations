为了将这个LLM计算图切分到物理设备上，我们需要在不同维度上下刀。

常见到的几种并行切分策略：

- **张量维度：** 张量并行 (**TP**, Tensor Parallelism) 和 序列并行 (**SP**, Sequence Parallelism)
- **数据维度：** 数据并行 (**DP**, Data Parallelism)
- **模型/层间维度：** 流水线并行 (**PP**, Pipeline Parallelism)
- **模型结构特化：** 专家并行 (**EP**, Expert Parallelism, 用于 MoE)

另外，这几篇文章也尽量给大家讲清楚Reduce-Scatter、All-Gather、All-Reduce 和 All-to-All这几个大模型分布式部署常见的操作。这篇文章的TP主要和All-Reduce有关，其他通信原语后续结合 SP、EP具体聊聊。

**TP**是其中最基础也最重要的并行方法，我们从这个入手。

其核心在于将原本无法装入单卡显存的大规模GEMM，沿特定维度拆分至多个设备上协同计算。其本质是对模型参数和中间激活值的分布式存储与计算。如果用N张卡做TP，好处是每张卡上只用存储1/N的权重，并承担 1/N 的计算任务。代价是All-Reduce操作，这会带来额外的卡间通信开销。但在大模型时代分布式部署已经是一个必选项。

我们以Qwen 7B模型作为例子（只是个例子，Qwen 7B单卡就足够了），具体看看 TP 在 MLP 层和 Attention 层的运作机制。

## MLP

先来看相对简单的MLP。Qwen 7B中的 MLP 包含三个线性投影层：

1. **Gate Projection (W_g)**: 输入维度 4096，输出维度 11008
2. **Up Projection (W_u)**: 输入维度 4096，输出维度 11008
3. **Down Projection (W_d)**: 输入维度 11008，输出维度 4096

假设我们有2张 GPU，TP会这样进行切分。

![](https://pic2.zhimg.com/v2-5dd421539f1b8d4430467dcfd50d4fef_r.jpg)
*TP策略的MLP切分*

MLP 的输入是上一层（Attention 层）的输出，记为 X。在 TP 模式下，每张 GPU 都持有完整的输入 X 副本。（除非开启了 SP，此处暂讨论纯 TP）首先需要计算 Gate 和 Up 两个Projection。对于这两层，TP会采用**列并行（Column Parallel）**策略，即沿着输出维度（11008）垂直切分权重矩阵。也就是将 11008 维的输出特征平分给 2 张卡，每张卡负责计算 5504 个特征。在此阶段，GPU 之间不需要通信。因为这里的 Swish 激活函数和逐元素乘法都是 Element-wise 操作。

对于之后的Down Projection，输入数据是被切分的，GPU 0 持有前 5504 列，GPU 1 持有后 5504 列，TP会采用 **行并行（Row Parallel）** 策略，即沿着输入维度（11008）水平切分权重矩阵。此时两张卡计算出的结果都是Batch*Token*4096，但是它们都只是Partial Sum。

为了得到最终输出并进入下一层，必须将分布在各卡上的Partial Sum相加，并将结果同步给所有卡。 这就是 **All-Reduce** 操作。系统调用 NCCL 通信原语，将所有 GPU 上的 Partial Sum 进行reduce sum。通信完成后，GPU 0 和 GPU 1 都获得了完整的输出。

这也就是MLP处理的一个典型过程：

1. 每张卡都有完整的输入
2. Col方向切分MLP的两个down prj的全连接层（不需要卡间通信）
3. 各卡完成计算（不需要卡间通信）
4. Row方向切分up prj的全连接层（此时每张卡只有部分和）
5. All-Reduce，将部分和相加，同步给所有卡。

最后值得一提的是，MLP层的最前面输入地方一般还有Norm，TP 主要切分 Linear 层，对于输入前的 Norm 层通常在各卡上复制参数并独立计算，也就是会各卡重复计算。

## Attention

Attention 层的逻辑与 MLP 类似，但Column Parallel切分维度变成了Head。

![](https://picx.zhimg.com/v2-98d2416f26694ac469c5dcc826dc15d7_r.jpg)
*TP策略的Attention层切分*

还是假设我们有2张 GPU。纯TP下的切分策略是，将 32 个 Head 平均分配。GPU 0 负责 Head 0-15，GPU 1 负责 Head 16-31。GPU 0 仅存储生成前 16 个 Head 所需的权重，GPU 1 仅存储生成后 16 个 Head 所需的权重。每张卡独立计算自己负责的 Head 的 Q, K, V，并计算 Attention （P=softmax(QK^T)和O=P*V)。计算attention score这一部分是天然无需通信的，因为 Multi-Head Attention 中，Head 与 Head 之间的计算是天然独立的。

Attention 的最后一步是将所有 Head 的输出concat起来，并送入O projection 。此时，GPU 0 手里有前 16 个 Head 的结果，GPU 1 有后 16 个 Head 的结果。这天然构成了后面W_O的Row Parallel的输入状态。

之后，GPU 0 用 W_O 的上半部分乘以它持有的 Head 0-15 的结果，GPU 1 用 W_O 的下半部分乘以它持有的 Head 16-31 的结果。两张卡分别得到一部分Partial Sum。之后使用**All-Reduce**将两张卡计算出的 Partial Sum 相加，得到最终 Attention 层的输出。

关于Attention层的TP还有一个注意点，就是在GQA的情况下当 TP 卡的大小超过 KV Head 数量时会怎么做。比如TP = 8，KV Heads = 4，Q Heads = 32的GQA。

此时我们有 8 张卡，但只有 4 个 KV Head。解决方案是replication的权重存储与计算。KV Head 0同时分配给 GPU 0 和 GPU 1。此时，GPU 0 和 GPU 1 上存储了完全相同的 KV Head 0 的Projection Weight。在计算 QKV 时，GPU 0 和 GPU 1 都会重复计算 KV Head 0 的输出。尽管计算和存储浪费了，但这避免了在 Attention 内部进行复杂的 All-Gather 通信，但总体上是划算的。如果只在 GPU 0 计算 KV，GPU 1 需要 KV 时就必须跨卡通信。对于 Query Heads，依然可以平均分。GPU 0 负责 Q-Head 0-3，GPU 1 负责 Q-Head 4-7，它们共享同一份（各自计算的）KV Head 0 数据进行 Attention。

## Megatron-LM 代码

我们最后来看看Megatron-LM中的TP具体实现。TP的代码在megatron/core/tensor_parallel目录下。

在 [layers.py](http://layers.py/) 中，定义了两个基础类：ColumnParallelLinear 和 RowParallelLinear。这也就是我们上文提到的Column Parallel和Row Parallel具体实现的地方。

还有两个重要function，在 megatron/core/tensor_parallel/mappings.py 中，CopyToModelParallelRegion 和 ReduceFromModelParallelRegion。

以前向过程为例：CopyToModelParallelRegion直接将输入传给后续的线性层。因为在 Column Parallel 中，每个 GPU 都需要完整的输入，且假设输入已经在各卡上由 All-Reduce 同步好了。ReduceFromModelParallelRegion实现All-Reduce，将 Row Parallel 产生的 Partial Sum 相加，得到完整的输出。这里硬件行为，就是调用 NCCL AllReduce。
