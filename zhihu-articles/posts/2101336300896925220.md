一个很经典的问题：两台一模一样的电脑，同一个模型，并且温度设为0，输入同一句话，比如“中国的首都在哪里”，为什么一台输出的是“北京”，另外一台输出的是“北京市”？

这叫做“训练推理不一致”的问题，在MoE （混合专家模型）中尤其容易出现。这也是算法岗面试中常见的问题。本文我从以下三个角度来讲：

第一，什么是训练推理不一致；

第二，为什么会产生训练推理不一致；

第三，为什么这个问题很重要、它有什么后果。

什么叫做训练推理不一致？通俗来说就是，我现在有两台电脑，两台电脑的芯片、显卡等硬件一模一样，都加载着同一个模型，当前模型的参数也一模一样。第一台电脑装的是训练框架（比如 Megatron），第二台电脑装的是推理框架（比如 vLLM）。我们分别给两个模型输入同一句话，模型的解码策略也是一模一样的，温度为 0，没有任何随机性。那么按照道理来说，模型是一模一样的，解码策略是一模一样的，硬件也是一模一样的。同样的输入，输出是不是得一模一样？按照数学来说确实得是这样的。比如说我问中国的首都在哪里，那么第一台电脑回答中国的首都在北京，第二台电脑也应该回答中国的首都在北京。但是在实际的过程中，就很有可能出现不一样的情况。没准第二台电脑蹦出来的答案是：中国的首都在北京市，多了那么一个字。

为什么会产生这个问题？有两个原因。第一个原因，也是最根本的原因就是，在计算机的世界里，浮点数不一定满足结合律。什么是结合律？就是比如说三个数相加，A+B+C。按道理来说，我们先算 A+B，然后用 A+B 的结果去加上 C，得出来的结果应该等于先算 B+C，然后用 B+C 的结果再去加上 A。这个应该是天经地义的，但是在计算机的世界里，它不一定会满足。我们可以举一个具体的例子，比如说 A 等于 0.0004，B 等于 0.0005，C 等于 0.0006。我们假设每做一次运算，都只能四舍五入到小数点后三位。你可能会觉得这个假设很荒唐，怎么只能够四舍五入到小数点后三位？现在的计算机效果有这么差吗？这个问题我在后面会补充，我们先接受这个假设。

如果我们先算 A 加 B，然后再加上 C，A 加 B 等于 0.0009，四舍五入变成 0.001，然后再加上 C 等于 0.0016，四舍五入变成 0.002。但是如果先算 B 加 C，等于 0.0011，四舍五入变成 0.001，然后再加上 A，结果是 0.0014，四舍五入变成 0.001。所以你可以看到，不同的相加顺序，最终的结果是不同的。一个是 0.002，一个是 0.001。

回到刚刚那个问题，我这里做了一个假设，就是每次运算之后必须要四舍五入到小数点后三位。这个假设不是天方夜谭，在计算机的世界中，浮点数小数点后面的精度是有限的。以最常见的 FP16 为例，它的有效数字只有 3 到 4 位。

可能有同学会说，我这里只是做了一个理论化的实验，好像没什么说服力，需要眼见为实。我们直接用 NumPy 的 FP16 试一下。我们先引入一个 NumPy 的包，然后 A 是用 FP16 表示的 1 万，B 是用 FP16 表示的 -1 万，C 是用 FP16 表示的 1。你可以看到，如果先算 A 加 B，然后再算 C，它是等于一，这也符合常理。但是如果你先算 B 加 C，然后再加上 A，你会发现它等于零。为什么？我们来看 B 加 C 等于多少，等于 -9999。但是在 FP16 的世界里面，-9999 它就是等于 -10000。为什么？它被四舍五入了，就好比你 9999 买一台 iPhone，你会说这是你花了 1 万购买的。至于为什么 -9999 会被四舍五入成 -1 万，你先记住，FP16 的世界其实是很单薄的世界，是很单调的世界，很多数字其实是会被近似成另一个数字的。所以这里 B 加 C 它仍然等于 -10000，然后再加上 A，又变成零了。

所以走到这里我们就知道了，为什么会产生训练推理不一致的原因是，在计算机中，浮点数的加法不一定满足结合律。但能不能再往深更问一层？凭什么在计算机中，有时候会先算 A 加 B，有时候会先算 B 加 C？因为计算机执行加法的时候，并没有规定一定要按照某种顺序来。它首先和计算框架有关系，训练框架中矩阵乘法是一套运算逻辑，推理框架中的矩阵乘法又是另外一套逻辑。我们退一步说，就算我们在同一套框架里面，有些并行算法会按各组结果到达的顺序来加：A 和 B 先来了，那就先算 A 加 B，有时候 B 和 C 先来了，那么就先算 B 加 C。谁先谁后的顺序是不一定的。

我们已经讲完了第一个原因，如果仅有第一个原因，会导致训练推理不一致的问题吗？其实很难。MOE 模型存在训练推理不一致这个问题，那么非 MOE 模型，比如传统的 dense 模型有没有这个问题？有，那远远没有 MOE 那么严重。大家如果有深度学习基础的话，就应该知道，对于传统的非 MOE 架构的神经网络，我的输入，或者说哪怕我神经元有细微的不同，某个参数从 0.138 改成 0.139，它最终的输出基本上都不会变的。我就举个简单的例子，比如说我现在有一个猫狗识别分类的网络，输入的图片是一张猫，那么它分类结果就是一张猫。那我往这个猫上面丢几帧黑色的像素，或者甚至涂黑一整块区域，它大概率也能识别出来图片中是猫，这个就叫做鲁棒性。哪怕对输入和内部的神经元做一些非常微小的改动，它也不会对我们的结果有非常大的影响，它是鲁棒的。

但是 MOE 模型就娇气的多了。我们知道 MOE 的一个特点就是它是一个路由网络，它每一个 token，会进入不同的专家。我举个例子，比如我们的模型只选择得分最高的一个专家。比如说我们在电脑 A 里面，同样的输入，中国的首都在北京，我们输到某一层了，然后它对应的专家 1 的得分是 0.5001，专家 2 的得分是 0.4999，那么进入专家 1。

但是我们在电脑 B 里面算到这里的时候，发现它专家 1 的得分是 0.4999，专家 2 的得分是 0.5001。这个时候就进入专家 2 了。那不同的专家，它后续的结果是很大不同的。有些专家可能是比较适合语法、句法，有些专家可能是比较适合地理。一旦你进入到了不适合的专家，那后面的结果就千差万别了，我电脑 A 可能会输出北京这两个字，电脑 B，虽然可能不会离谱到输出"中国的首都在上海"，但是可能会输出"北京市"这三个字。

*图2 细微的分数变化，可能翻转 Top-1 专家路由。*

所以归根结底，因为它是有个路由机制，就相当于一个分叉口。比如说我们爬山，如果只有一条路的话，哪怕这条路坑坑洼洼的，你稍微左一脚右一脚，左一脚右一脚，你最终还是从同一条路走能够爬到山顶。但是如果你爬山的路上有一个分叉口的话，那么另外一条分叉口可能就不会把你带到山顶去了。

这就是训练推理不一致。其实说到这里，我觉得还有一种角度，就是说它不一定是训练推理不一致，它还有一种表现方法叫做推理推理不一致。啥意思？还是说我们有两个相同的电脑，这两台电脑所有的条件一模一样，包括模型的参数、解码的机制、甚至芯片也一模一样，输入一模一样，然后同样去走推理的流程。它的输出也有可能不一样。也就是说，其实它本质上不是说训练推理不一致，它也有可能是推理推理不一致。

然后最后我们要考虑一个很实际的问题。这个训练推理不一致的问题很重要吗？当然重要，不重要的话，面试中也不会老问。为什么它很重要？它到底会带来什么后果？最大的后果就是说在强化学习中，会影响训练。在强化学习里，PPO 的训练过程中，Actor 模型，有一个 rollout 的阶段，又叫做采样的阶段。比如说中国的首都在哪里？这是一条训练数据。那么 Actor 模型它在 rollout 的阶段，会去对这个问题回答出一个结果出来。那回答这个过程，其实是推理的过程，是现场采样的过程。它这个时候用到的是推理框架，比如说 vLLM，它是一个推理框架。这个过程它不仅会产生回答，而且它会产生每个 token 的概率。比如 中国的 首都 在北京 分成了三个 token，它不仅产生了 中国的首都在北京 这条回答，它还会给出这三个 token 对应的概率。

它这样之后不是万事大吉了，后面我们在计算损失的时候，会重新跑一遍训练的过程，以训练的视角，再去计算"中国的首都在北京"中每一个 Token，它的概率。这个时候用到的训练框架就不是 vLLM 了，而是有可能是 Megatron。

推理阶段先把回答生成出来，记录生成时的概率。训练时，再把这条已经生成的回答送进去，重新计算概率，因为这次计算还要参与反向传播、更新参数。PPO会用到新旧概率的比值。

我们这里讨论的是，参数还没有更新，仅仅换了计算框架，概率就已经对不上了。真正更新参数以后，概率发生变化，那是正常的。

打个比方，训练的时候，模型先自己猜一遍答案，记下每个实际选出来的 token 在当时的概率；回头算账、要更新参数的时候，又把这个答案重新算一遍概率。这两次算，用的是不同的框架，所以哪怕参数一点没动，算出来的概率都可能对不上。账要是从一开始就对不上，后面更新参数时该往哪调、调多少，就全被带偏了。

*图3 参数尚未更新时，框架差异也可能影响概率比值（数值仅作示意）。*

按照理论上来说，这个时候模型参数还没有变化，我从推理框架得出来的概率和从训练框架得出来的概率得是一样的。但是正如我们上面所说到的，有可能会产生训练推理不一致的情况，那么两个概率就不一样了，那这两个概率不一样，它会影响我们的损失函数，使得我们的损失函数失真。那损失函数产生了错误的指示，使得我们的训练往错误的方向走，这就会切切实实地影响到了强化学习的训练。
