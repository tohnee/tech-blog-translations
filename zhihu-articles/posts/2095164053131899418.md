## 一、总览：当前进展与几条主线

半年多读下来，上下文工程已经从”prompt 技巧集合”升格为一门有分类体系的工程学科 [1][2]。综合各方向，当前进展可归为五条主线：

1. **学科化** ：A Survey of Context Engineering（166 页、1411 篇引用）把它正式立为一门学科，拆成”基础组件（检索/处理/管理）→ 系统实现（RAG/记忆/工具/多 Agent）”两层 [1][2]。
2. **一记底层暴击** ：CL-bench 把问题从”上下文工程”推进到”上下文学习”，并给出最锋利的负结果——十个前沿模型平均解决率仅 17.2%，失败主因是 **忽略或误用上下文** 而非信息缺失 [3]。这条决定了下面所有工程手段的底色：别指望模型自己从长上下文里悟出任务条件。
3. **排序与约束** ：既然模型不可靠，就在”内容/顺序/约束”上做工程——任务状态要前置（Trace as State）[11]，事实要钉成断言让模型”照抄而非自由发挥”（约束解码/确定性注入）。
4. **控制膨胀（本周热点）** ：长上下文不是免费的——工具定义和工具输出会把窗口撑爆。Manus 的 KV 缓存/掩码/文件系统外存 [5]、context-mode 的沙箱只回传 stdout（约 98% 缩减）[6]、微软”一键清空对话”（跑得久≠想得多）[7]，共同指向”上下文要主动瘦身”。
5. **自进化与模型换代** ：ACE 把上下文当作可演化文档（generate→reflect→curate）[4]；而 GPT-6 时代 OpenAI/Anthropic 都提醒—— **为旧模型写的约束，到新模型上会变成过度约束** ，该删就删 [8]。

贯穿五条线的工程层还有一块地基： **检索质量** 。Embedding/向量库选型 [9] 与混合检索+重排 [10] 决定了”放进上下文的东西”本身准不准——召回错了，后面排序和约束都救不回来。

### 二、逐篇展开

### 2.1 A Survey of Context Engineering for LLMs [1]

Mei et al.，arXiv:2507.13334，166 页 / 1411 篇引用。把”推理时喂给模型的信息载荷”系统化，提出分类体系：基础组件（检索与生成 / 处理 / 管理）→ 系统实现（RAG / 记忆系统 / 工具集成推理 / 多 Agent）。 **核心发现（Core Asymmetry）** ：在先进上下文工程加持下模型”理解”复杂上下文已很强，但”生成”同等复杂度长文仍有明显局限——理解与生成的根本不对称是未来重点。意义：这是目前该领域最全面的路线图，也是”上下文工程 = 一门学科”这一说法的出处。

### 2.2 中文全景综述：上下文工程 — 大模型的下一个前沿 [2]

对 [1] 的中文系统解读。重点讲清与”提示工程”的本质区别（模型/目标/状态性/扩展性四个维度），并把基础组件和系统实现架构逐层展开。作为中文读者的入门主干最合适，可与英文原survey 对读。

### 2.3 CL-bench：从上下文工程到上下文学习 [3]

腾讯混元 × 复旦，arXiv:2602.03587，78 页，姚顺雨主导。 **问题重定义** ：当前模型主要靠”参数化知识”（预训练压进权重的静态记忆），推理时多在调用已知；CL-bench 要求解题所需新知识 **完全来自上下文、且预训练中不存在** ，逼模型现场学。 **防作弊** ：全虚构/反事实知识（编造星际法律、假 SDK、改写史实），无上下文时 GPT-5.1 正确率 %。 **结果** ：10 个前沿模型平均解决率仅 **17.2%** ，最好的 GPT-5.1(High) 也仅 23.7%，主因是忽略/误用上下文。 **展望** ：上下文学习是临时的（窗口清空即忘）→ 下一关是 Memory Consolidation；人类角色从”训练数据提供者”转为”上下文提供者”。这是全篇最该记住的一刀。

### 2.4 ACE：Agentic Context Engineering [4]

arXiv:2510.04618，ICLR’26。把上下文当作一份 **可演化的文档** 而非写死的 prompt，三阶段循环 generate → reflect → curate，让上下文在任务间持续生长、复利累积。效果：编码基准 +10.6%、金融推理 +8.6%；小开源模型 + ACE 可追平不带 ACE 的顶级闭源模型。意义：代表上下文工程向”运行时自进化”演进的一支，和 RSI 那条线接上了。

### 2.5 Manus 构建之谜（季逸超）[5]

生产级 Agent 的上下文工程实战，几条经验极其具体：

- **KV 缓存命中率是最重要的单一指标** ：直接决定延迟和成本（Claude Sonnet 缓存 vs 未缓存差 10 倍）。推论：提示前缀要稳定（别放精确到秒的时间戳）、上下文 append-only、序列化要确定性（JSON 键序别乱）。
- **工具用掩码而非增删** ：动态加载工具会让 KV 缓存全失效、还会让模型困惑；Manus 用”上下文感知状态机”在解码阶段对 logits 掩码，靠统一前缀（browser */shell* ）强制选某类工具。
- **文件系统作为外部上下文** ：容量无限、持久、可被 Agent 直接读写，当结构化外部记忆用。
- **复述（Recitation）操控注意力** ：用不断更新的 todo.md 把目标反复拉回注意力末端。

### 2.6 context-mode：把编码 Agent 的上下文砍掉约 98% [6]

开源项目 mksglu/context-mode。诊断两大杀手：工具定义膨胀（81 个工具光描述就占 143K/200K token 的 72%）+ 工具输出堆积（一次页面快照 56KB…）。主张： **工具原始输出不进上下文** ，先在沙箱子进程跑完、只回传 stdout；项目自述约 98% 缩减（315KB→5.4KB，官方数字无第三方验证，但数量级合理）。和 Manus”文件系统外存”同一思路的工程化落地。

### 2.7 微软：Autoresearch 一键清空对话 [7]

反直觉负结果。同配置 Agent 同起点独立跑 8 次，最好 100 分、最差 68.3 分；落后的 Agent 很早陷进某类解法附近反复优化，再烧预算也追不上。做法： **保留已写好的代码/实验成果，让 Agent 清空对话重新探索，可能比一直跑下去更好** 。呼应 RSI 那条”复杂进化不如多跑几遍”——上下文不是越长越好，有时该清零。

### 2.8 OpenAI 官方 Prompt 指南升级（GPT-6）[8]

Codex 团队 Eric Provencher + Anthropic（Claude Fable 5.1 指南）同期指出：过去一年为弥补旧模型短板写的 Skill / AGENTS.md / 任务指令，到新模型上 **有些不再适用、甚至帮倒忙** ——旧约束会让响应更慢、上下文更拥挤、解题路径被限死。换模型时除了看能力提升，还要主动检查”哪些旧指令可以删了”。对任何自己维护一堆 skill/规则的系统都尤其对口。

### 2.9 Embedding 与向量库选型 [9]

RAG 工程地基之一。Embedding 决定”像不像”、向量库决定”找不找得到/快不快/贵不贵”；Embedding 选错后面调索引救不回来；中文/多语言/短 query/长文档/代码/表格都会改变模型表现，不能只看单一榜单分。

### 2.10 混合检索与重排 [10]

RAG 工程地基之二。纯向量召回在编号/术语/缩写/错误码上会飘；生产级检索是多路召回（BM25 管关键词+稀有词、向量管语义、过滤管权限范围）+ 融合 + 重排。重排决定模型最终看到什么（Cross-Encoder 准但慢、Late Interaction 兼顾、LLM-as-Reranker 另一档）。

### 三、归纳：共识、争议、红线

**几条正在固化的共识**

- 上下文工程 ≠ Prompt 工程：它是对”喂给模型的整个信息载荷”做系统设计（检索→处理→管理），有状态、可扩展 [1][2]。
- “喂得好 ≠ 学得会”：模型的上下文学习能力当前并不可靠（17.2%），这是所有工程手段的前提 [3]。
- 长上下文不是免费午餐：工具定义、工具输出、历史堆积都会撑爆窗口并拖慢/带偏模型，必须主动瘦身 [5][6][7]。

**一组反直觉结论（最值钱的部分）**

- **顺序 > 内容** ：同样的内容，任务状态前置 vs 后置，效果可天差地别（Trace as State：DeepSeek V4 Pro 29.2%→81.8%）[11]。因果注意力下，靠后的信息改不动已形成的靠前表示。
- **强约束 > 指望它学会** ：既然上下文学习不可靠，把事实钉成断言让模型”照抄”反而比让它自由发挥更稳 [3]。
- **跑得久 ≠ 想得多** ：长程探索会陷进局部解，清空重开可能更好 [7]。
- **旧约束会变成过度约束** ：换模型要做减法而非只做加法 [8]。

**工程红线**

- 别在系统提示里放秒级时间戳 / 别随意增删工具 / 别破坏序列化确定性——都会让 KV 缓存失效，直接涨延迟涨成本 [5]。
- 工具原始输出不要直接进上下文 [6]。
- 检索这层若选错 Embedding / 只用单路召回，上层再怎么排序约束都救不回来 [9][10]。

**落地方向**

- 对话/改写类场景：确定性候选注入 + 断言/任务状态前置（Trace as State），把”代词=哪一项、来自第几轮”的断言放到提示最前 [11]。
- 长期记忆/RAG：召回片段排序即上下文工程——把”当前任务状态 + 用户意图”放到检索内容之前；多轮先总结状态 T 再前置重读。
- 自维护的 skill/规则库：按 [8] 的提醒，定期审查”为旧模型写的约束是否已成负担”。

### 四、趋势判断

一句话：这半年主语在变——从”把资料塞进更长的窗口”，变成” **把理解和执行约束成可控的工程过程** “，并且开始分化出两个下游方向：① **上下文自进化** （ACE 那条，和 RSI 合流）；② **记忆巩固** （CL-bench 指出的”临时学会→如何固化”）。谁先把”现场学会的东西可靠地沉淀下来”，谁就接住了上下文工程的下一棒。
