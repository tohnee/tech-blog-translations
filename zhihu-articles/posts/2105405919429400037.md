BIT 市场观察｜Meta 给小模型定低价

Meta 新发布的 Muse Ember 是它目前体量最小的模型，定价也压得很低：每百万输入 Token 0.10 美元，缓存输入 0.004 美元，输出 0.50 美元。模型支持 100 万 Token 上下文，原生理解文本、图像、音频和视频，已经通过 Meta Model API 和 Muse Code 开放。扎克伯格在 X 上说，它专为智能体全天反复执行、大量消耗 Token 的工作打造。

Meta 拿来比较的单位是单项任务成本。第三方机构 Artificial Analysis 的智能指数 v5 里，最高推理强度下 Muse Ember 得 35.8 分，Claude Haiku 5.5 得 36.2 分，只差 0.4 分；完成一项任务的成本，Muse Ember 约 0.136 美元，Haiku 5.5 约 0.411 美元，前者约为后者三分之一。和自家的 Muse Spark 1.3 比，得分差 1 分，成本是 0.14 美元对 2.39 美元，Ember 不到后者的 5.9%。另一家评测机构 Vals AI 的数据接近：每项测试 0.15 美元，是其榜单里单项成本最低的模型，成绩 60.5%。

对智能体来说，缓存单价比标价更要紧。智能体在长流程里反复读同一批文件和上下文，命中缓存的部分按 0.004 美元计，是普通输入的 4%。一位用户通过 OpenRouter 调用时，界面显示缓存命中率 75%；粗算按这个命中率，每百万输入 Token 的实际花费约 0.028 美元，不到标价的三成。Meta 的描述是，智能体的单步工作并不复杂，读文件、调工具、跑测试、改代码，但在长工作流里会持续消耗 Token，Ember 就是接这一类活的。

这也是 Meta 模型线的新分工。Muse Wonder 处理难度最高的问题，Muse Spark 面向编程和智能体工作流，Ember 负责大规模、重复性的执行任务，Meta 的原话是 Wonder 负责规划、Ember 负责大量执行。Ember 是首款用 10 月 12 日发布的 Muse Wonder Full 训练出来的模型，从大模型发布到小模型上线不到一个月。早期测试方 Cloudflare 说部分任务的尾部延迟最多降低 30%；[http://You.com](http://You.com) 称 P95 延迟 2.2 秒，输出 Token 数量少了 36% 到 48%。输出 Token 越少，同一任务的账单越低。

智能体测试是 Ember 的强项，端到端业务流程测试 AutomationBench-AA 里它得 37.8%，Claude Haiku 5.5 是 13.9%。短板同样清楚，在 Artificial Analysis 衡量真实工程任务的 FrontierCode 2.0-AA 里，Haiku 5.5 得 34.9%，Ember 只有 27.2%。同一天 Anthropic 发布的 Claude Fable 5.2 在智能指数上拿到 65 分，比 Ember 高 29 分，复杂任务仍要交给大模型。产品体验也有批评，有用户说 Meta AI 的安全限制太多，已经取消订阅，连当前运行的是哪个模型都答得前后不一。另有开发者提醒，便宜但要重试三次的模型，实际成本可能高过一次做对的贵模型，三分之一的成本优势要在真实工作负载里复现才算数。

我们的看法：Meta 把定价对准了智能体里调用次数最多、单次最简单的那部分工作。这一层对模型能力的要求不算高，对单价和速度很敏感，便宜的一方更容易拿到调用量。用大模型训练小模型，也让 Meta 推新型号的节奏更快。如果开发者在 OpenRouter 等平台上对 Ember 的实际调用量明显增加，Meta Model API 会成为 Meta 新的对外收入来源；如果企业仍把执行层留在已经在用的 Anthropic 或 OpenAI 体系里，低价换来的只是评测榜上的名次。

接下来看三项：Ember 在 OpenRouter 等第三方平台上的调用份额；开发者补测的 GPT-6 Luna 和 Haiku 5.5 横向结果；Meta 会不会继续用 Wonder 系列训练面向其他场景的专用小模型。

以上为 BIT 证券港美市场研究整理，数据来自公司公告及公开报道，仅供参考，不构成投资建议。
