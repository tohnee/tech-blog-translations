### 引言：慢的不是算，而是搬

Transformer 类模型有一个绕不开的魔咒：假设输入序列长度为 $N$，那么自注意力部分的计算复杂度和存储开销都是 $O(N^2)$。序列越长，计算和存储的压力增长得越快，长序列建模因此成为大模型时代最昂贵的环节之一。

一个自然的想法是：能不能把 $O(N^2)$ 降到 $O(N)$？如果能降下来最好，哪怕逼近 $O(N)$ 也有巨大价值。社区沿着”减少计算量”的思路做过很多尝试，比如用稀疏 Attention 做近似计算。但 FlashAttention 走了一条完全不同的路——**它的总计算量一 FLOPs 都没少，却依然快了一个数量级**。

这件事成立的前提是发现了一个被长期忽视的事实：Attention 计算慢的卡点不在运算能力，而在**读写速度**上。FlashAttention 的全部设计，都是围绕”如何少搬数据”展开的。

### 一、FlashAttention 在做什么：名字里藏着答案

FlashAttention 的全称是 **Fast and Memory Efficient Exact Attention with IO-Awareness**，四个关键词逐个拆开，就是它要做的事情：

![](https://pic1.zhimg.com/v2-c08e6bbfbc8dfa869656f4ed14ec8c04_r.jpg)

其中（1）和（2）靠的是两项核心技术：**分块计算（Tiling）** 和 **核函数融合（Kernel Fusion）**，这也是全文的主线。（3）则依赖于一个精巧的数学构造——在线更新 rowmax 和 rowsum 的分块 Safe Softmax，让”不落地中间矩阵”和”结果精确”可以同时成立。

要理解这些设计为什么有效，必须先弄清楚：硬件的读写瓶颈到底是怎么定义、怎么量化的。

### 二、瓶颈分析：计算限制与内存限制

### 2.1 四个基础量

一个算法运行在某个硬件上，其耗时由”算”和”搬”两部分共同决定。先定义四个基本量：

| 符号 | 含义 | 单位 |
| --- | --- | --- |
| \pi | 硬件算力上限：平台倾尽全力每秒能完成的浮点运算数 | FLOP/s |
| \beta | 硬件带宽上限：平台倾尽全力每秒能完成的内存交换量 | Byte/s |
| \pi_t | 某个算法所需的总运算量（下标 t 表示 total） | FLOPs |
| \beta_t | 某个算法所需的总数据读取存储量 | Byte |

注意区分一对容易混淆的术语：**FLOPS**（等价于 FLOP/s）指每秒执行的浮点操作次数，衡量**硬件**计算性能；**FLOPs** 指某个算法的总浮点运算次数，衡量**算法**复杂度。前者是”车速”，后者是”路程”。

### 2.2 时间由谁决定

有了四个基本量，就能算出两种耗时：

$$ T_{cal} = \frac{\pi_t}{\pi}, \quad T_{load} = \frac{\beta_t}{\beta} $$

$T_{cal}$ 是纯计算耗时，$T_{load}$ 是纯数据读写耗时。由于数据在读取的同时可以计算、计算的同时也可以读取，二者是并行的，所以完成整个计算的总时间为：

$$ T = \max(T_{cal}, \; T_{load}) $$

**总时间取决于计算时间和数据读写时间中的较大值**——这是全文最重要的一个直觉。据此可以给算法分两类：

- 当 $T_{cal} > T_{load}$，即 $\frac{\pi_t}{\beta_t} > \frac{\pi}{\beta}$ 时，瓶颈在计算上，称为**计算限制（math-bound）**；
- 当 $T_{cal} < T_{load}$，即 $\frac{\pi_t}{\beta_t} < \frac{\pi}{\beta}$ 时，瓶颈在数据读取上，称为**内存限制（memory-bound）**。

其中比值 $\frac{\pi_t}{\beta_t}$ 被称为算法的**计算强度（Operational Intensity）**：每搬运 1 Byte 数据能捎带做多少次浮点运算。计算强度越高，算法越”偏算”；越低，越”偏搬”。

### 2.3 用 A100 算一笔账

以 A100-40GB SXM 为例，采用混合精度训练（fp16，一个元素占 2 Byte），硬件的”算搬比”为：

$$ \frac{\pi}{\beta} = \frac{312 \times 10^{12}}{1555 \times 10^9} \approx 201 \; FLOPs/Bytes $$

也就是说，硬件每秒的算力是带宽的 201 倍。一个算法要想不吃带宽的亏，计算强度必须不低于 201。

现在考察 Attention 的核心运算 $S = QK^T$，其中 $Q, K \in \mathbb{R}^{N \times d}$。计算量为 $2N^2 d$ FLOPs（矩阵乘法计算量的算法见第六节），而需要读写的数据量是 $Q$、$K$ 读入（各 $2Nd$ Byte）加 $S$ 写出（$2N^2$ Byte），所以：

$$ \frac{\pi_t}{\beta_t} = \frac{2N^2 d}{2Nd + 2Nd + 2N^2} = \frac{N^2 d}{2Nd + N^2} $$

当 $N$ 较大时（比如 $N \gg 2d$），这个比值趋近于 $d$，远小于 201。结论很清晰：**Attention 中的矩阵运算（尤其是后续的 softmax、mask 等逐点操作）普遍是 memory-bound 的**，这正是 FlashAttention 的重点优化对象。

两类瓶颈的典型代表：

| 瓶颈类型 | 典型算子 | 特点 |
| --- | --- | --- |
| 计算限制（math-bound） | 大矩阵乘法（N 和 d 都非常大）、通道数很大的卷积 | 读得快，算得慢 |
| 内存限制（memory-bound） | 逐点运算：激活函数、dropout、mask、softmax、BN、LN | 算得快，读得慢 |

当然，”Transformer 计算受限于数据读取”不是绝对的，要综合硬件本身和模型大小综合判断。但 memory-bound 的情况普遍存在，所以 FlashAttention 的改进思想在很多场景下依然适用。

### 2.4 Roofline 模型：一张图看懂瓶颈

Roofline 模型把上面的分析画成一张图，回答”一个运算量为 $\pi_t$、读写量为 $\beta_t$ 的算法，在算力上限 $\pi$、带宽上限 $\beta$ 的硬件上，能达到的最大性能 $P$ 是多少”。

![](https://pic4.zhimg.com/v2-3809d44d61f501dac4b2f01772321723_r.jpg)

图中横坐标 $I$ 表示计算强度（$I = \frac{\pi_t}{\beta_t}$），纵坐标 $P$ 表示算法运行在硬件上的实际性能。算法的运行性能不会超过硬件本身的算力上限，所以 $P$ 的最大值取到 $\pi$，形似”屋顶”——Roofline 由此得名。当 $I > \frac{\pi}{\beta}$ 时存在计算限制；当 $I < \frac{\pi}{\beta}$ 时存在内存限制。

这张图也直接指明了优化方向：对 Attention 这种 memory-bound 算子，光减少 FLOPs 没用（瓶颈根本不在算），**必须提高计算强度——少搬数据，或者搬一次数据多干点活**。这正是下一节 GPU 存储结构要展开的内容。

### 三、GPU 上的存储与计算：FlashAttention 的物理舞台

### 3.1 两级存储：快而小 vs 大而慢

GPU 上的存储按是否在芯片上分为两类：

| 类型 | 代表 | 容量（A100） | 带宽 | 定位 |
| --- | --- | --- | --- | --- |
| 片上内存（on-chip） | SRAM（L1 cache / shared memory） | 约 20 MB | 约 19 TB/s | 缓存，快但小 |
| 片下内存（off-chip） | HBM（即显存） | 40 GB | 约 1.5 TB/s | 全局存储，大但慢 |

SRAM 的带宽是 HBM 的十倍以上，但容量差了三个数量级。**每次计算的数据都要从显存（HBM）加载到片上（SRAM），在片上完成计算后，再把结果写回显存**——这个”搬进搬出”的过程，就是 memory-bound 算法的时间大头。

### 3.2 片上是怎么算的：SM 与线程层级

负责 GPU 计算的核心组件叫 **SM（Streaming Multiprocessors，流式多处理器）**，可以把它理解成 GPU 的计算单元，好比 CPU 中的一个核。但有一个关键区别：一个 CPU 核一般运行一个线程，而一个 SM 可以运行多个轻量级线程。SM 由若干 **SMP（SM Partition）** 组成（例如 4 个），每个 SMP 内的 Warp Scheduler 会抓一束 32 个的线程（即一个 **warp**）放入 cuda core 中执行。

把计算核心和存储层级综合起来，一张简化图如下：

![](https://pic2.zhimg.com/v2-54a25b20ce50074886ea43b7b2754961_r.jpg)

几个关键点：

- **L1 缓存 / shared memory**：每个 SM 有自己的 L1，被 SM 内所有 cuda cores 共享，SM 之间不能互相访问。NV Volta 架构后 L1 和 shared memory 合并（目的是进一步降低延迟），合并后用户能直接控制的依然是 shared memory，并可控制从 L1 中分配多少给它。**FlashAttention 中说的 SRAM 指的就是 L1 cache / shared memory**。
- **L2 缓存**：所有 SM 共享，不直接由用户代码控制。L1/L2 带宽都比显存大，但容量更小。

### 3.3 kernel 融合：既然 SRAM 装得下，就别来回搬

现在把 GPU 计算流程再理一遍：**数据从显存（HBM）加载至片上 SRAM，由 SM 读取计算，结果再经 SRAM 返回显存**。显存带宽小、读一次数据很费时，而 SRAM 又太小、装不下太多数据。于是有两条朴素的优化原则：

1. **以 SRAM 的存储为上限，尽量保证每次加载都把 SRAM 装满**，摊薄读取时间；
2. 在 SRAM 容量允许的情况下，**能合并的计算尽量合并在一起**，避免重复读写显存。

第二条就是 **kernel 融合**。举例来说：要做计算 A 和计算 B，老方法是做完 A 得到中间结果写回显存，再从显存加载到 SRAM 做计算 B；但若 SRAM 完全能存下中间结果，就可以把 A 和 B 放在一起做，省去中间的两次显存搬运。这里 kernel 可以粗略地理解为”函数”，它包含对线程结构（grid-block-thread）的定义以及结构中具体计算逻辑的定义。

**kernel 融合和尽可能利用 SRAM，正是 FlashAttention 的两大重要优化点**：分块之后，FlashAttention 把矩阵乘法、mask、softmax、dropout 操作合并成一个 kernel，做到了只读一次、只写回一次。

舞台搭好了。接下来进入正题：FlashAttention 究竟怎么在 SRAM 里”见缝插针”地算完整个 Attention。

### 四、Forward 流程：分块计算的正确打开方式

### 4.1 标准 Attention 计算回顾

设共有 $N$ 个 token，每个 token 向量维度为 $d$，标准 Attention 的计算流程为：

![](https://pic4.zhimg.com/v2-dab4de649530f7dc57cee519ab4a93dd_r.jpg)

其中 $S = QK^T$，$P = \text{softmax}(S)$，$O = PV$。GPT 类模型中还要对 $P$ 做 mask 处理（为表达方便，mask、dropout 等零碎操作在下文推导中暂且省略，最后统一加回）。

注意中间那个 $N \times N$ 的矩阵——**标准实现里，$S$ 和 $P$ 都要在显存中落地**：forward 时算出并保存它们，backward 时又要读回来算梯度。这个 $O(N^2)$ 的读写，就是 memory-bound 的元凶，也是 FlashAttention 要”消灭”的对象。

### 4.2 Safe Softmax：分块计算的前置知识

对 $S$ 做 softmax 时，如果某一行的某个元素 $x_i$ 过大，计算 $e^{x_i}$ 可能数值上溢。解决方法是 **safe softmax**：先求该行最大值 $m(x) = \max_i x_i$，再计算

$$ \text{softmax}(x_i) = \frac{e^{x_i - m(x)}}{\sum_{j=1}^{d} e^{x_j - m(x)}} $$

由于指数分子分母同减一个常数，结果不变，但避免了溢出。

这里引入两个关键记号：$\widetilde{P}$（归一化前的结果，即只减了 rowmax、没除 rowsum）和 $P$（归一化后的结果）。**请记住 $\widetilde{P}$ 和 $P$ 的区别，后面分块计算中会反复出现**。

### 4.3 分块计算整体流程（Tiling）

FlashAttention 的核心优化技术是分块计算。切分方式如下：

1. 将 $Q$ 切成 $T_r$ 块，每块长度 $B_r$，$Q_i$ 的维度为 $(B_r, d)$，存储着某 $B_r$ 个 token 的 query 信息；
2. 将 $K^T$ 切成 $T_c$ 块，每块长度 $B_c$，$K_j^T$ 的维度为 $(d, B_c)$，存储着某 $B_c$ 个 token 的 key 信息；
3. 将 $V$ 同样切成 $T_c$ 块，$V_j$ 的维度为 $(B_c, d)$，存储着某 $B_c$ 个 token 的 value 信息；
4. 做分块的 attention 计算：

- **计算初始 attention 分数**：$S_{ij} = Q_i * K_j^T = (B_r, d) * (d, B_c) = (B_r, B_c)$，表示前 $B_r$ 个 token 和前 $B_c$ 个 token 间的原始相关性分数；
- **Safe softmax + mask + dropout**：对 $S_{ij}$ 做 safe softmax、mask 和 dropout，得到 $\widetilde{P}_{ij}$。注意：这里用的其实是”归一化前”的 $\widetilde{P}$ 而不是 $P$，原因在后文分块细节中详解；
- **计算 output**：$O_{ij} = \widetilde{P}_{ij} * V_j = (B_r, B_c) * (B_c, d) = (B_r, d)$。

第三步的等式乍看之下”不太对劲”：正常情况下，前 $B_r$ 个 token 过 attention 后的输出，应该是它和**所有** token 做完注意力计算后的结果；可这里的 $O_{ij}$ 只是前 $B_r$ 个 token 和前 $B_c$ 个 token 的结果——shape 对了，但内容还不是最终想要的。**$O$ 的正确更新方式，正是分块计算的精髓所在**，见 4.5 与第五节。

在计算这些分块时，GPU 可以并行计算，这也提升了计算效率。

### 4.4 循环结构：K、V 外循环，Q 内循环

把整个流程流转起来：论文中注明 $j$ 是外循环、$i$ 是内循环，即**对每个 $j$，把所有的 $i$ 遍历一遍**，也称为 K、V 外循环、Q 内循环：

```text
# Tc: K 和 V 的分块数；Tr: Q 的分块数量
for 1 <= j <= Tc:
    for 1 <= i <= Tr:
        do...
```

这个循环方向有一个重要推论：每遍历一个 $j$（即一块新的 K、V），所有 $Q$ 块都会与之做一次交互，产生一批”局部结果”。这些局部结果如何汇集成全局正确的 $O$，靠的就是下节介绍的在线更新技巧。

### 4.5 分块场景下的 Safe Softmax 难题

标准 safe softmax 中，$m$、$l$ 都是对完整的一行做 rowmax、rowsum 后的结果。切换到分块场景后，问题来了：分别算出 $S_{00}$ 和 $S_{01}$，再对它们**分别**做 rowmax、rowsum，能得到和标准场景一模一样的结果吗？

答案是否定的。标准场景下的 $m(x)$ 是每行的**全局最大值**，分块后如果也这么算，它就变成了**局部最大值**，显然不等价。

FlashAttention 的作者们在这里使用了一种巧妙的计算方式，核心思想是：**局部统计量可以带着”修正项”拼接成全局统计量**。假设标准场景下 $S$ 某一行的向量为 $x = [x_1, x_2, \ldots, x_d]$，因为分块，它被切成两部分 $x = [x^{(1)}, x^{(2)}]$。逐层定义：

**（1）最大值的可拼接性**

- $m(x)$：标准场景下，该行的全局最大值；
- $m(x^{(1)})$、$m(x^{(2)})$：分块 1、分块 2 的局部最大值。

那么易知 $m(x) = m([x^{(1)}, x^{(2)}]) = \max(m(x^{(1)}), m(x^{(2)}))$——全局最大就是局部最大取 max，这一步天然可拼。

**（2）指数项的修正**

- $f(x)$：标准场景下 $\exp(x - m(x))$ 的结果；
- $f(x^{(1)})$、$f(x^{(2)})$：分块场景下 $\exp(x^{(1)} - m(x^{(1)}))$、$\exp(x^{(2)} - m(x^{(2)}))$ 的结果。

易知 $f(x) = [e^{m(x^{(1)}) - m(x)} f(x^{(1)}), \; e^{m(x^{(2)}) - m(x)} f(x^{(2)})]$。直觉：每个分块当初是拿自己的局部 max 做减法的，要换算到全局 max 基准下，只需乘一个 $e^{\text{局部}max - \text{全局}max}$ 的修正因子。

**（3）rowsum 的可拼接性**

- $l(x)$：标准场景下 $\text{rowsum}[f(x)]$ 的结果；
- $l(x^{(1)})$、$l(x^{(2)})$：分块场景下对应的 rowsum 结果。

由（2）易知：$l(x) = e^{m(x^{(1)}) - m(x)} l(x^{(1)}) + e^{m(x^{(2)}) - m(x)} l(x^{(2)})$——把每个分块的局部 rowsum 各自修正到全局基准，再相加。

**（4）最终结果**

现在就可以用分块计算的结果来表示标准场景下 safe softmax 的结果了：

$$ \text{softmax}(x) = \frac{f(x)}{l(x)} = \frac{[e^{m(x^{(1)}) - m(x)} f(x^{(1)}), \; e^{m(x^{(2)}) - m(x)} f(x^{(2)})]}{e^{m(x^{(1)}) - m(x)} l(x^{(1)}) + e^{m(x^{(2)}) - m(x)} l(x^{(2)})} $$

**数值实例**：设某行 $x = [2, 4, 1, 3]$，切成 $x^{(1)} = [2, 4]$、$x^{(2)} = [1, 3]$。

- 局部 max：$m(x^{(1)}) = 4$，$m(x^{(2)}) = 3$；全局 $m(x) = 4$；
- 局部指数和：$f(x^{(1)}) = [e^{-2}, e^0] = [0.135, 1]$，$f(x^{(2)}) = [e^{-2}, e^0] = [0.135, 1]$；局部 rowsum：$l(x^{(1)}) = 1.135$，$l(x^{(2)}) = 1.135$；
- 修正：$e^{4-4} \times 1.135 + e^{3-4} \times 1.135 = 1.135 + 0.368 \times 1.135 = 1.553$；
- 验证：直接按全局算 $l(x) = e^{-2} + e^0 + e^{-3} + e^{-1} = 0.135 + 1 + 0.05 + 0.368 = 1.553$ ✓。两种路径结果完全一致，拼接公式成立。

这套”$m$、$l$ 可在线修正”的性质，就是 FlashAttention 分块计算正确性的全部数学基础。下一节看它在伪代码中的完整落地。

### 五、伪代码逐行精读与 Output 的推导

### 5.1 先解决符号”晕圈”问题

FlashAttention 论文伪代码的数学符号繁多，但有一个简单的解读 trick：

- 所有以 $j$ 作为下标的，都表示**当前分块**的计算结果；
- 所有以 $i$ 作为下标的，都表示**截止到前一个分块（包含前一个分块）**的计算结果；
- 所有以 $new$ 为上标的，都表示**引入当前分块做更新后**的结果；
- 所有没有下标的，都表示**全局结果**。

对照图例：固定内圈 $i$，循环外圈 $j$，$S_{00} \to \widetilde{P}_{00}$、$S_{01} \to \widetilde{P}_{01}$、$S_{02} \to \widetilde{P}_{02}$ 依次被处理，各符号的层级关系为：

- $\widetilde{m}_{ij}$：对当前分块 $S_{ij}$ 来说每行的**局部最大值**（对应 4.5 节的 $m(x^{(k)})$）；
- $\widetilde{P}_{ij}$：分块场景下各块的 P 矩阵（归一化前）结果（对应 $f(x^{(k)})$ 的矩阵版）；
- $\widetilde{l}_{ij}$：分块场景下的 rowsum 结果（对应 $l(x^{(k)})$）；
- $m$、$l$：标准场景下对 $S$ 的全局 rowmax、全局 rowsum；
- $m_i$：$\max(\widetilde{m}_{i0}, \widetilde{m}_{i1}, \ldots, \widetilde{m}_{i(j-1)})$，即固定 $i$ 时前 $j-1$ 个分块的局部最大值；当固定 $i$ 遍历完 $j$ 后，$m_i$ 就是全局最大值；
- $m_i^{new}$：$\max(\widetilde{m}_{i0}, \ldots, \widetilde{m}_{i(j-1)}, \widetilde{m}_{ij})$，固定 $i$ 时**截止到当前分块**为止的局部最大值；
- $l_i^{new}$：与 $m_i^{new}$ 对应，用分块更新 $l(x)$ 的步骤；
- $l_i$：与 $m_i$ 同理，$j$ 遍历完后得到针对 $i$ 的全局 rowsum。

### 5.2 一个尖锐的问题与 O 更新公式的动机

读到这里你可能会发现一个问题：之前是否一直以为，在这一顿操作后，分块计算出的 $\widetilde{S}, \widetilde{P}$ 应该和标准场景下的完全一致？但现在看来，**每个分块 $S_{ij}, \widetilde{P}_{ij}$ 依然是用自己局部的 rowmax 和 rowsum 做计算的，并没有达到理想中的效果**。

别急。还记得伪代码第 12 行说的更新 $O_i$ 的公式吗？**分块计算的真正意义不在于得到正确的 $S, P$，而在于得到正确的 $O$**。然后你再来看伪代码 5~13 行，会发现：在整个计算过程中，只有 $m_i, l_i, O_i$ 被从片上 SRAM 写回到显存（HBM）中。把 $i$ 都遍历完后，读写量也不过是 $m, l, O$。相比于标准场景下要读写 $S, P, O$，读写量一下就少了很多——**这就解决了 memory-bound 的问题**。分块计算 safe softmax 的意义，就是抹去对 $S, P$ 的读写。

### 5.3 O 更新公式的完整推导

现在到了最烧脑也最关键的部分：伪代码第 12 行更新 $O_i$ 的公式。目标是：**每遍历一个分块就更新一次 $O_i$，遍历完全部分块后，得到的 $O_i$ 和标准场景下完全一致**。

先明确推导中符号的上下标含义：$i$ 是 query 分块编号；$i(j+1)$ 表示当前分块的相关结果；$i{:}j+1$ 表示**截止到当前分块（包含当前分块）**的相关结果，$i{:}j$ 表示截止到前一分块（包含前一分块）。

推导链条（共九行，每行都有明确的变换依据）：

$$ \begin{aligned} O_i^{(j+1)} &= P_{i:j+1} V_{j+1} \\ &= \text{softmax}(S_{i:j+1}) V_{j+1} \\ &= \text{diag}(l^{(j+1)})^{-1} \left[ \exp([S_{i:j}, S_{i(j+1)}] - m^{(j+1)}) \right] \begin{bmatrix} V_{:j} \\ V_{j+1} \end{bmatrix} \\ &= \text{diag}(l^{(j+1)})^{-1} \left[ \exp(S_{i:j} - m^{(j+1)}) V_{:j} + \exp(S_{i(j+1)} - m^{(j+1)}) V_{j+1} \right] \\ &= \text{diag}(l^{(j+1)})^{-1} \left[ e^{-m^{(j+1)}} \exp(S_{i:j}) V_{:j} + e^{-m^{(j+1)}} \exp(S_{i(j+1)}) V_{j+1} \right] \\ &= \text{diag}(l^{(j+1)})^{-1} \left[ \text{diag}(l^{(j)}) e^{m^{(j)} - m^{(j+1)}} \text{diag}(l^{(j)})^{-1} \exp(S_{i:j} - m^{(j)}) V_{:j} + e^{-m^{(j+1)}} \exp(S_{i(j+1)}) V_{j+1} \right] \\ &= \text{diag}(l^{(j+1)})^{-1} \left[ \text{diag}(l^{(j)}) e^{m^{(j)} - m^{(j+1)}} P_{i:j} V_{:j} + e^{-m^{(j+1)}} \exp(S_{i(j+1)}) V_{j+1} \right] \\ &= \text{diag}(l^{(j+1)})^{-1} \left[ \text{diag}(l^{(j)}) e^{m^{(j)} - m^{(j+1)}} O_i^{(j)} + e^{\widetilde{m} - m^{(j+1)}} \exp(S_{i(j+1)} - \widetilde{m}) V_{j+1} \right] \\ &= \text{diag}(l^{(j+1)})^{-1} \left[ \text{diag}(l^{(j)}) e^{m^{(j)} - m^{(j+1)}} O_i^{(j)} + e^{\widetilde{m} - m^{(j+1)}} \widetilde{P}_{i(j+1)} V_{j+1} \right] \end{aligned} $$

逐行解读：

- **（1）第一行**：期望的结果是每遍历一个分块就更新一次 $O_i$，遍历完全部分块后得到与标准场景完全一致的 $O_i$。基于此有 $O_i^{(j+1)} = P_{i:j+1} V_{j+1}$。其中 $P_{i:j+1}$ 表示从第 0 个分块到当前分块，**用当前最新的 rowmax、rowsum 更新一次所有分块的 $P$ 结果**（因为做过归一化，所以是不带波浪号的 $P$）；$V_{j+1}$ 表示当前分块及之前所有分块对应的 $V$ 部分。
- **（2）第二行**：将 $P_{i:j+1}$ 改写成 $\text{softmax}(S_{i:j+1})$。**特别注意 $S_{i:j+1}$ 所代表的各个分块间是相互独立的**——只有在做 softmax 这个操作时，才考虑对这些独立的 $S$ 用最新的 rowmax、rowsum 去更新 $P$。
- **（3）第三行**：把（2）中的 softmax 展开写。即用当前最新的 rowmax 和 rowsum 去计算 $P$：减去全局 max（放进 $\exp$），除以全局 rowsum（写成 $\text{diag}(l^{(j+1)})^{-1}$）。同时将 $S_{i:j+1}$ 拆成 $[S_{i:j}, S_{i(j+1)}]$ 两部分（[之前所有的分块， 当前分块]），同理拆 $V$。
- **（4）~（5）第四、五行**：简单变式。第五行用 $e^{-m^{(j+1)}} \exp(S) = \exp(S - m^{(j+1)})$ 的反向提公因子，把 $-m^{(j+1)}$ 从每一项的指数里提到括号外。
- **（6）第六行**：观察到中括号式子的前半部分与之前所有分块的结果密切相关。联想到最终目标是**不断更新 $O_i$**——在上一个 $O_i$ 的基础上引入当前分块的信息做更新。基于这个思想做递推：$O_i^{(j)}$ 就是之前所有分块用上一分块的 rowmax、rowsum 做更新后求得 $P$，再乘上对应的 $V$ 得到的结果。据此攒出了 $\text{diag}(l^{(j)})^{-1} \exp(S_{i:j} - m^{(j)}) V_{:j}$ 这一项（就是 $O_i^{(j)}$），然后再用 $\text{diag}(l^{(j)}) e^{m^{(j)} - m^{(j+1)}}$ 去抵消在”攒它”的过程中引入的项——这正是 4.5 节修正因子的矩阵版。
- **（7）~（9）第七至九行**：明确了（6）以后，剩下的部分就好理解了。至于为什么要把 $\widetilde{m}$ 放进去（毕竟有了 $S_{i(j+1)}$、$m^{(j+1)}$ 都是已知的，已经可以算了）：因为在求解 rowsum 相关的数据时，还是要把数据从 $S$ 转为 $\widetilde{P}$ 才能求，因此避不开算 $\widetilde{P}$；另外也是为了让表达更统一，因此引入 $\widetilde{m}$，进而引入 $\widetilde{P}$ 进行计算。

这个最终公式就是伪代码第 12 行。它的结构可以浓缩成一句话：

$$ O_i^{new} = \underbrace{e^{m_i - m_i^{new}} O_i}_{\text{旧结果修正到新基准}} + \underbrace{e^{\widetilde{m}_{ij} - m_i^{new}} \widetilde{P}_{ij} V_j}_{\text{当前分块贡献}} \cdot \text{diag}(l_i^{new})^{-1} $$

每遍历完一块 $S_{ij}$，就执行一次”旧结果乘衰减因子 + 新结果乘修正因子”的更新；遍历到最后一块时，$O_i$ 恰好等于标准 Attention 的精确结果——**不落地任何一块完整的 $S$ 或 $P$，却分毫不差地把 $O$ 算了出来**，这就是 Exact 的含义。

### 六、Backward 流程：不存中间矩阵，就重算它

### 6.1 Forward 回顾与 Backward 的困境

先总结 forward 中做的操作（省略 mask、dropout 等零碎操作，假设 $f(.)$ 是损失函数）：

$$ S = QK^T, \quad P = \text{softmax}(S), \quad O = PV, \quad L = f(O) $$

标准 backward 的前提是：计算开始时，显存（HBM）上已经存放着 $Q, K, V, O, S, P$ 这些数据——标准 forward 把 $S, P$ 都落地了，backward 直接拿来用。

但 FlashAttention 的 forward **没有保存 $S$ 和 $P$**，只存了 $m$、$l$。backward 要用 $S$、$P$ 怎么办？答案是：**重计算（recompute）**。既然有了全局的 $m, l$，那么对任意一块 $S_{ij}$，就能基于 $m, l$ 算出和标准场景下完全一致的 $P_{ij}$。因此 backward 过程中，FlashAttention 将采用重计算的方式重新算出 $S_{ij}, P_{ij}$，并把它们运用到 backward 的计算中去。**在接下来的讲解中，可以把 $S, P$ 理解成完全等同于标准场景下的结果**，而不是像分块 forward 那样的局部版本。这个”用重计算换显存”的取舍，正是时间换空间策略的经典应用——多算一遍 $QK^T$，省下整个 $N \times N$ 矩阵的存储与读写。

此外，backward 之前显存上存的数据包括：全局 rowmax $m$、全局 rowsum $l$、$Q,K,V$（等同标准场景）、$O$（等同标准场景的输出），以及 loss 对 $O$ 的梯度 $dO$。有了这些，就能按链式法则分块地求出别的矩阵的梯度了。

### 6.2 前置知识一：softmax 求导

backward 中会频繁接触 softmax 求导，这里做一个快速复习。设：

$$ \begin{cases} y = \text{softmax}(z) \\ L = f(y) \end{cases} $$

其中 $y = [y_1 \; y_2 \; y_3]$，$z = [z_1 \; z_2 \; z_3]$。根据链式法则，$\frac{\partial L}{\partial z_j} = \frac{\partial L}{\partial y} \frac{\partial y}{\partial z_j}$。

**(1) $\frac{\partial y_i}{\partial z_j}$**：对某个 $z_j$ 来说，在 softmax 操作下它参与了 $y_1, y_2, y_3$ 三者的计算，分成两种情况：

$$ \begin{cases} \frac{\partial y_i}{\partial z_j} = y_i (1 - y_i), & \text{当 } i = j \\ \frac{\partial y_i}{\partial z_j} = -y_i y_j, & \text{当 } i \neq j \end{cases} $$

据此有 $\frac{\partial y}{\partial z_j} = \sum_{i=1}^{l} \frac{\partial y_i}{\partial z_j}$（$l$ 代表向量元素个数，本例 $l = 3$）。例如求 $\frac{\partial y}{\partial z_1}$：$\frac{\partial y}{\partial z_1} = y_1(1-y_1) - y_2 y_1 - y_3 y_1$。

**(2) 用 Jacobian 矩阵表达**：基于 $y = \text{softmax}(z)$ 的 Jacobian 矩阵为 $\text{diag}(y) - y^T y$。以 $3 \times 3$ 为例：

$$ \text{diag}(y) - y^T y = \begin{bmatrix} y_1 - y_1^2 & -y_1 y_2 & -y_1 y_3 \\ -y_2 y_1 & y_2 - y_2^2 & -y_2 y_3 \\ -y_3 y_1 & -y_3 y_2 & y_3 - y_3^2 \end{bmatrix} $$

容易发现只要把每行（或每列）相加，就能得到对应 $z$ 的偏导——对角元素是 $y_i - y_i^2$，非对角元素是 $-y_i y_j$，与分段公式完全对应。

**(3) 完整链式**：$\frac{\partial L}{\partial z_j} = \frac{\partial L}{\partial y} \frac{\partial y}{\partial z_j}$。有了（1）（2）的结果，推导 $\frac{\partial L}{\partial z_j}$：

$$ \frac{\partial L}{\partial z_j} = \frac{\partial L}{\partial y} \frac{\partial y}{\partial z_j} = \sum_{i=1}^{l} \frac{\partial L}{\partial y_i} \frac{\partial y_i}{\partial z_j} = y_j \left( dy_j - \sum_{j=1}^{l} y_j dy_j \right) $$

**举例验证**：若 $\frac{\partial L}{\partial y} = [m_1 \; m_2 \; m_3]$（不指定具体 Loss，直接假设），则 $\frac{\partial L}{\partial z_1} = m_1(y_1 - y_1^2) - m_2 y_1 y_2 - m_3 y_1 y_3$。针对所有的 $z$，将 $\frac{\partial L}{\partial z}$ 写成矩阵表达式，就得到那个最重要的结论：

$$ \frac{\partial L}{\partial z} = \frac{\partial L}{\partial y} \frac{\partial y}{\partial z} = dy(\text{diag}(y) - y^T y) $$

### 6.3 前置知识二：softmax 与交叉熵一起求导

分块 backward 中还会用到 softmax 和交叉熵联合求导。设 $\hat{y} = [\hat{y}_1, \hat{y}_2, \hat{y}_3]^T$ 为输入 $x$ 真实类别的 one-hot encoding，交叉熵定义为（log 底数为 $e$）：

$$ H(\hat{y}, y) = -\hat{y}^T \log y = -\sum_{t=1}^{m} \hat{y}_t \log y_t $$

对交叉熵求偏导：$\frac{\partial H(\hat{y}, y)}{\partial y_i} = -\frac{\hat{y}_i}{y_i}$。注意 $\hat{y}$ 是确定的值（真实 one-hot 标签），不受模型预测标签 $y$ 的影响。

现在把交叉熵的梯度和 softmax 的 Jacobian 串起来。设 $\frac{\partial L}{\partial y} = [m_1 \; m_2 \; m_3]$，代入链式公式：

$$ \frac{\partial L}{\partial z_1} = m_1(y_1 - y_1^2) - m_2 y_1 y_2 - m_3 y_1 y_3 $$

代入交叉熵的梯度（one-hot 标签下 $m_i = -\hat{y}_i / y_i$，即只有真实类别对应位置非零），化简后得到一个极简的结论：

$$ \frac{\partial L}{\partial z} = y - \hat{y} $$

即 **softmax + 交叉熵的联合梯度 = 预测概率 − 真实标签**。这个结论虽不直接出现在 FlashAttention 的 $dS_{ij}$ 公式里，但它是理解”softmax 行向量梯度可写成 $p_i \odot [dp_i - \text{rowsum}(\cdot)]$ 形式”的直接铺垫——两者都来自同一套 Jacobian 运算。

### 6.4 标准 backward 计算

有了前置知识，先看标准 backward 怎么算（对应论文 Algorithm 2 的五个步骤）。由链式法则和矩阵求导法则（若 $Y = AX$，则 $Y$ 对 $X$ 求导为 $A^T$；对 $A$ 求导为 $X^T$）：

**(1) 计算 $dV$**：已知 $O = PV$，设损失函数 $L$ 关于 $O$ 的梯度为 $dO$。根据链式法则 $\frac{\partial L}{\partial V} = \frac{\partial L}{\partial O} \frac{\partial O}{\partial V}$。对 $O = PV$ 关于 $V$ 求偏导，$\frac{\partial O}{\partial V} = P^T$，所以：

$$ dV = \frac{\partial L}{\partial V} = P^T dO \in \mathbb{R}^{N \times d} $$

对应算法第 1 步：”Load $P, dO$ by blocks from HBM, compute $dV = P^T dO$, write $dV$ to HBM.”

**(2) 计算 $dP$**：由 $O = PV$，对 $P$ 求偏导 $\frac{\partial O}{\partial P} = V^T$，所以：

$$ dP = \frac{\partial L}{\partial P} = dO V^T \in \mathbb{R}^{N \times N} $$

对应算法第 2 步：”Load $dO, V$ by blocks from HBM, compute $dP = dO V^T$, write $dP$ to HBM.”

**(3) 计算 $dS$**：已知 $P = \text{softmax}(S)$，设 $P_{ij}$ 是 $P$ 中第 $i$ 行第 $j$ 列的元素。标准 softmax 函数的梯度公式为 $\frac{\partial P_{ij}}{\partial S_{kl}} = P_{ij}(\delta_{ik} - P_{il})$，其中 $\delta_{ik}$ 是克罗内克（Kronecker）符号（$i = k$ 时为 1，否则为 0）。根据链式法则（注意 $\frac{\partial L}{\partial P_{kl}} = dP_{kl}$）：

$$ \frac{\partial L}{\partial S_{ij}} = \sum_k \sum_l dP_{kl} P_{ij} (\delta_{ik} - P_{il}) = P_{ij} dP_{ij} - P_{ij} \sum_l P_{il} dP_{il} $$

用矩阵形式表示为 $dS_{ij} = P_{ij}(dP_{ij} - \sum_l P_{il} dP_{il})$，对应算法第 3 步：”Read $P, dP$ from HBM, compute $dS \in \mathbb{R}^{N \times N}$, write $dS$ to HBM.”

**(4) 计算 $dQ$**：由 $S = QK^T$，对 $Q$ 求偏导 $\frac{\partial S}{\partial Q} = K^T$，所以：

$$ dQ = \frac{\partial L}{\partial Q} = dS K $$

（$dS$ 是 $N \times N$ 矩阵，$K$ 是 $N \times d$ 矩阵，$dSK$ 符合矩阵乘法规则。）对应算法第 4 步：”Load $dS$ and $K$ by blocks from HBM, compute $dQ = dSK$, write $dQ$ to HBM.”

**(5) 计算 $dK$**：由 $S = QK^T$，对 $K$ 求偏导 $\frac{\partial S}{\partial K} = Q^T$，所以：

$$ dK = \frac{\partial L}{\partial K} = dS^T Q $$

对应算法第 5 步：”Load $dS$ and $Q$ by blocks from HBM, compute $dK = dS^T Q$, write $dK$ to HBM.” 最后返回 $dQ, dK, dV$，用于后续模型参数更新。

标准 backward 的问题一目了然：$dP$ 和 $dS$ 都是 $N \times N$ 矩阵，每一步都要从 HBM 读写它们——又是 memory-bound。分块 backward 的目标是同样的计算，但 $dP, dS$ 永远只存在于 SRAM 中。

### 6.5 分块 backward 计算

分块 backward 的伪代码整体结构与 forward 类似：

- **初始化**：将伪随机数生成器状态设置为 forward 中的状态 $\mathcal{R}$（保证 Dropout 等随机操作前后向一致）；计算块大小 $B_r = \lceil \frac{M}{4d} \rceil$ 和 $B_c = \lceil \frac{M}{4d} \rceil$，其中 $M$ 是片上 SRAM 的大小，$d$ 是矩阵维度；将 $Q$ 划分为 $T_r = \lceil \frac{N}{B_r} \rceil$ 个大小为 $B_r \times d$ 的块，$K$ 和 $V$ 划分为 $T_c$ 个大小为 $B_c \times d$ 的块，$dO$ 划分为 $T_r$ 个 $B_r \times d$ 的块；向量 $l, m$ 各划分为 $T_r$ 个大小为 $B_r$ 的块；初始化 $dQ = (0)_{N \times d}$、$dK = (0)_{N \times d}$、$dV = (0)_{N \times d}$ 并分块。
- **外层循环（处理 $K$ 和 $V$ 的块）**：对 $j$ 从 1 到 $T_c$，将 $K_j, V_j$ 从 HBM 加载到 SRAM，并在 SRAM 中初始化中间变量 $\widetilde{dK}_j = (0)_{B_c \times d}$、$\widetilde{dV}_j = (0)_{B_c \times d}$。
- **内层循环（处理 $Q$ 的块）**：对 $i$ 从 1 到 $T_r$，将 $Q_i, O_i, dO_i, l_i, m_i$ 从 HBM 加载到 SRAM；然后按顺序计算 $S_{ij} = \tau Q_i K_j^T$（$\tau$ 是 softmax 缩放常数）→ $S_{ij}^{masked} = MASK(S_{ij})$ → $P_{ij} = \text{diag}(l_i)^{-1} \exp(S_{ij}^{masked} - m_i)$（本质是一个变形的 softmax）→ Dropout 操作（生成与 $P_{ij}$ 同大小的矩阵 $Z_{ij}$，每个元素以概率 $1 - p_{drop}$ 取值为 $\frac{1}{1-p_{drop}}$、以概率 $p_{drop}$ 取 0，计算 $P_{ij}^{dropped} = P_{ij} \odot Z_{ij}$）。

之后就是逐个求梯度。观察下面所有不带波浪号的 $S, P$——它们都等同于标准场景下的结果（因为经过了重计算）。

**(1) 求 $dV_j$ 梯度**

假设 $j = 0$，怎么求 $dV_0$ 呢？先看 $V_0$ 都参与了 $O$ 哪些部分的计算：由图例可知，$P_{00}$ 和 $V_{00}$ 参与了 $O_0$ 的计算，$P_{10}$ 和 $V_{00}$ 参与了 $O_1$ 的计算，$P_{20}$ 和 $V_{00}$ 参与了 $O_2$ 的计算。所以有：

$$ dV_0 = (P_{00})^T dO_0 + (P_{10})^T dO_1 + (P_{20})^T dO_2 $$

进而在固定 $j$ 时，对 $i$ 累加：

$$ dV_j = \sum_i (P_{ij})^T dO_i $$

考虑 Dropout 的情况下，用 $P_{ij}^{dropped}$ 替代 $P$：$\widetilde{dV}_j \leftarrow \widetilde{dV}_j + (P_{ij}^{dropped})^T dO_i$。这就是伪代码第 16 行做的事情：按这个方法分块计算并累积 $dV_j$。

**逐元素推导 $\frac{\partial O}{\partial V} = P^T$**：设 $O_{mn}$ 是 $O$ 中第 $m$ 行第 $n$ 列的元素，$P_{mk}$ 是 $P$ 中第 $m$ 行第 $k$ 列的元素，$V_{kn}$ 是 $V$ 中第 $k$ 行第 $n$ 列的元素，根据矩阵乘法规则 $O_{mn} = \sum_{k=1}^{N} P_{mk} V_{kn}$。求 $O_{mn}$ 关于 $V_{ij}$ 的偏导：当 $n \neq j$ 时，$O_{mn}$ 的计算式中不包含 $V_{ij}$ 这个变量，所以 $\frac{\partial O_{mn}}{\partial V_{ij}} = 0$；当 $n = j$ 时，只有当 $m = i$ 时 $V_{kn}$ 才是 $V_{ij}$，此时根据求导公式（常数 $c = P_{ik}$ 对变量 $x = V_{in}$ 的导数为 $c$）可得 $\frac{\partial O_{in}}{\partial V_{ij}} = P_{ik}$。将所有偏导组合成矩阵形式，其维度由 $O$ 的行维度 $N$ 和 $V$ 的列维度 $d$ 决定：对于 $V$ 的每一列元素关于 $O$ 的偏导，会得到一个与 $P$ 的对应行向量转置形式相同的结果。例如 $V$ 的第 $j$ 列元素关于 $O$ 的偏导数组成的向量，正好是 $P$ 的第 $i$ 行向量的转置形式。从整体矩阵求导角度即可表示为 $\frac{\partial O}{\partial V} = P^T$。

**(2) 求 $dP_{ij}$ 梯度**

观察图例可发现，$P_{ij}$ 只与 $V_j, O_i$ 相关（例如 $P_{10}$ 只与 $V_0, O_1$ 相关）。因此有：

$$ dP_{ij} = dO_i V_j^T $$

这就是伪代码第 17 行做的事情。逐元素推导与 $dV$ 同理：对 $O = PV$ 关于 $P$ 求偏导，$\frac{\partial O_{in}}{\partial P_{ij}}$ 只在 $m = i$ 时有非零值，此时为 $V_{jn}$，所以从矩阵整体求导角度 $\frac{\partial O}{\partial P} = V^T$。由于 $dO \in \mathbb{R}^{B_r \times d}$、$V_j^T \in \mathbb{R}^{d \times B_c}$，可得 $dP_{ij} \in \mathbb{R}^{B_r \times B_c}$。

**(3) 求 $dS_{ij}$ 梯度**

这一块是令许多人感到迷惑的，先回顾 6.2 节的重要结论：

$$ \frac{\partial L}{\partial z} = \frac{\partial L}{\partial y} \frac{\partial y}{\partial z} = dy(\text{diag}(y) - y^T y) $$

假设 $s_i, p_i, o_i$ 分别为矩阵 $S, P, O$ 的某一行（注意这里 $i$ 不是表示第 $i$ 块的意思，是表示第 $i$ 行，所以用小写的 $s, p, o$ 表示），那么根据这个结论有：

$$ \begin{aligned} ds_i &= dp_i (\text{diag}(p_i) - p_i^T p_i) \\ &= dp_i \text{diag}(p_i) - dp_i p_i^T p_i \\ &= dp_i \text{diag}(p_i) - do_i V^T p_i^T p_i \\ &= dp_i \text{diag}(p_i) - do_i o_i^T p_i \\ &= p_i \odot [dp_i - \text{rowsum}(do_i \odot o_i)] \end{aligned} $$

对最后一步可能有疑问：为什么要大费周章将 $ds_i$ 改写成这么复杂的形式？因为在最后一步之前都是针对”某一行”来求导，而引入最后一步的目的，是为了**延展至对”某一块（多行）”的求导**。也就是说针对某一块 $dS_i$（注意这里是大写的 $S$，$i$ 的含义也回归至”第几块”），有：

$$ dS_i = P_i \odot [dP_i - \text{rowsum}(dO_i \odot O_i)] $$

进而可以推知：$dS_{ij} = P_{ij} \odot [dP_{ij} - \text{rowsum}(dO_i \odot O_i)]$。

**行推导的四个环节**（从哪里来 → 做了什么 → 得到什么）：

- 根据乘法分配律 $A(B - C) = AB - AC$ 展开（这里 $A = dp_i$，$B = \text{diag}(p_i)$，$C = p_i^T p_i$）；
- 已知 $O = PV$，对其关于 $P$ 求导可得 $\frac{\partial O}{\partial P} = V$，根据链式法则即 $dP = dOV^T$。对于某一行有 $dp_i = do_i V^T$，代入上式得 $ds_i = dp_i \text{diag}(p_i) - do_i V^T p_i^T p_i$；
- 因为 $o_i = p_i V$，所以 $do_i V^T p_i^T p_i = do_i o_i^T p_i$；
- 对于向量 $a$ 和 $b$，$a^T b = \text{rowsum}(a \odot b)$（$\odot$ 表示逐元素相乘），那么 $do_i o_i^T p_i = \text{rowsum}(do_i \odot o_i) p_i$，所以 $ds_i = p_i \odot [dp_i - \text{rowsum}(do_i \odot o_i)]$。

**逐元素实例演算**：假设一个简单的情况，$S, P, O$ 都是 $2 \times 2$ 的矩阵，且分为一个块（即 $i = 1, j = 1$）。设 $P = \begin{bmatrix} p_{11} & p_{12} \\ p_{21} & p_{22} \end{bmatrix}$，$dP = \begin{bmatrix} dp_{11} & dp_{12} \\ dp_{21} & dp_{22} \end{bmatrix}$，$O = \begin{bmatrix} o_{11} & o_{12} \\ o_{21} & o_{22} \end{bmatrix}$，$dO = \begin{bmatrix} do_{11} & do_{12} \\ do_{21} & do_{22} \end{bmatrix}$。首先计算 $dO \odot O = \begin{bmatrix} do_{11}o_{11} & do_{12}o_{12} \\ do_{21}o_{21} & do_{22}o_{22} \end{bmatrix}$；然后 $\text{rowsum}(dO \odot O) = \begin{bmatrix} do_{11}o_{11} + do_{12}o_{12} \\ do_{21}o_{21} + do_{22}o_{22} \end{bmatrix}$；最后 $dS = P \odot [dP - \text{rowsum}(dO \odot O)]$，即：

$$ dS = \begin{bmatrix} p_{11}(dp_{11} - (do_{11}o_{11} + do_{12}o_{12})) & p_{12}(dp_{12} - (do_{11}o_{11} + do_{12}o_{12})) \\ p_{21}(dp_{21} - (do_{21}o_{21} + do_{22}o_{22})) & p_{22}(dp_{22} - (do_{21}o_{21} + do_{22}o_{22})) \end{bmatrix} $$

**两个配套步骤**（对应伪代码 19~20 行）：

- 结合 Dropout 更新 $dP_{ij}$ 梯度：$dP_{ij} = dP_{ij} \odot Z_{ij}$，考虑 Dropout 对梯度的影响（与 forward 中 dropout 的掩码保持一致）；
- 计算 $D_i$：$D_i = \text{rowsum}(dO_i \odot O_i)$，即对 $dO_i$ 和 $O_i$ 逐元素相乘后按行求和，用于后续计算。这个 $D$ 正是原论文 Algorithm 2 里的辅助变量——先算好它，后面算 $dS$ 时就不用重复算 rowsum。

**(4) 求 $dQ_i$ 梯度**

至此已知道 $dS_{ij}$，那么现在就可以根据链式法则继续求 $dQ_i$ 了。把目光聚焦在 $Q_0$ 身上，由 forward 过程可知：

$$ S_{00} = Q_0 K_0^T, \quad S_{01} = Q_0 K_1^T $$

因此针对 $Q_0$，有 $dQ_0 = dS_{00} K_0 + dS_{01} K_1$。推广到任意 $Q_i$：

$$ dQ_i = \sum_j dS_{ij} K_j $$

这就是伪代码第 21 行做的事情。注意累加方向：固定 $i$，沿 $j$ 方向累加（每个 $j$ 内层循环算一次，直接累加进 $dQ_i$ 对应的显存位置）。

**(5) 求 $dK_j$ 梯度**

这一步很简单。如果被复杂的分块推导弄晕了脑袋，不妨再复习一下前面提过的 trick：对照图例，取出某一块 $K_j$。由于是从 $dS_{ij}$ 链式推向 $K_j$，所以只要搞明白这块 $K_j$ 和哪些 $Q$ 一起计算出了哪些 $S$，再把相关结果相加即可。某块 $K_j$ 和对应的 $Q_i$ 共同计算出了对应的 $S_{ij}$，因此有：

$$ dK_j = \sum_i dS_{ij}^T Q_i $$

这就是伪代码第 22 行做的事情。

**分块 backward 小结**：当感到迷茫时，一定记得画图；在碰到需要累加才能计算出梯度的步骤中，画图也可以帮助快速理解是按 $i$ 维度还是按 $j$ 维度进行累加。整个 backward 中，$dK_j, dV_j$ 沿 $i$ 方向累加（固定外层 $j$），$dQ_i$ 沿 $j$ 方向累加（固定内层 $i$），而 $dS_{ij}, dP_{ij}$ 只与当前 $(i, j)$ 相关、用完即弃——它们从未离开过 SRAM。

### 七、账本核算：计算量、显存需求与 IO 复杂度

### 7.1 矩阵相乘的计算量

先明确一个统计口径：假设有两个矩阵 $A$ 和 $B$，维度分别为 $(m, n)$ 和 $(n, p)$，则这两矩阵相乘的运算量为 $2mnp$（每个乘法搭配一个加法）。一般在矩阵运算中，乘法运算的时间要高于加法运算的时间，因此有时统计计算量时只考虑乘法运算的次数，则运算量可近似为 $mnp$。

矩阵相乘运算占据了运算量的大头，因此把分析目光集中到所有的矩阵运算上。对照 forward 伪代码：

**(1)** 伪代码第 9 行有 $S_{ij} = Q_i K_j^T$，其中 $Q_i \in \mathbb{R}^{B_r \times d}$，$K_j^T \in \mathbb{R}^{d \times B_c}$，求 $S_{ij}$ 的计算量为 $O(B_r B_c d)$。

**(2)** 伪代码第 12 行有 $\widetilde{P}_{ij} V_j$，其中 $\widetilde{P}_{ij} \in \mathbb{R}^{B_r \times B_c}$，$V_j \in \mathbb{R}^{B_c \times d}$，则这里的计算量同样为 $O(B_r B_c d)$。

**(3)** 接下来看一共计算了多少次（1）和（2），也就是执行了多少次内循环：

$$ T_c T_r = \frac{N}{B_c} \cdot \frac{N}{B_r} $$

**(4)** 综合以上三点，FlashAttention 的 forward 计算量为：

$$ O\left(\frac{N^2}{B_c B_r} \cdot B_r B_c d\right) = O(N^2 d) $$

注意，因为计算量是用大 O 阶表示的，所以这里把常数项都省略了。同理可自行推一下 backward 中的计算量，论文里给出的结论是 $O(N^2)$（$d$ 远小于 $N$，因此 $d$ 也可以略去不表达）。

**结论：FlashAttention 的计算量与标准 Attention 完全一样，一个 FLOPs 都没少。** 它省的不是算，是搬——这正好呼应第一节的名字里 “Fast” 靠的是 IO-Awareness 而非 FLOPs 缩减。

### 7.2 显存需求

和标准 attention 相比，如果不考虑 $O$ 的话，Flash Attention 只需要存储 $m, l$，其显存需求为 $O(N)$；而标准 attention 需要存储 $S, P$，其显存需求为 $O(N^2)$。

| 实现方式 | 需落地的中间量 | 显存需求 |
| --- | --- | --- |
| 标准 Attention | S, P（各 N \times N） | O(N^2) |
| FlashAttention | m, l（各 N 维向量） | O(N) |

相比于标准 attention，FlashAttention 明显降低了对显存的需求。这一收益直接来自第五节的结论：中间的 $S, P$ 全程不落地。

### 7.3 IO 复杂度：最终的胜利

显存省了，读写到底省了多少？分别数一数两种实现的 HBM 读写量。

**标准 attention 的 IO 复杂度**（对照 Algorithm 0）：

- 从 HBM 中读取 $Q, K \in \mathbb{R}^{N \times d}$，计算 $S = QK^T$，$S \in \mathbb{R}^{N \times N}$ 并将 $S$ 写回 HBM。一读一写的 IO 复杂度为 $O(Nd + N^2)$；
- 从 HBM 中读取 $S \in \mathbb{R}^{N \times N}$，同时计算 $P \in \mathbb{R}^{N \times N}$ 并将其写回 HBM。一读一写的 IO 复杂度为 $O(N^2)$；
- 从 HBM 中读取 $P \in \mathbb{R}^{N \times N}, V \in \mathbb{R}^{N \times d}$，计算 $O = PV$ 并将 $O$ 写回 HBM。一读一写的 IO 复杂度为 $O(Nd + N^2)$。

所以**标准 attention 的 IO 复杂度为 $O(Nd + N^2)$**——$N^2$ 项正是 $S, P$ 三个来回的读写贡献的。

**FlashAttention 的 IO 复杂度**：

- 伪代码第 6 行：每个外循环都会加载 $K, V$ 的 block，所有外循环结束后，相当于加载了完整的 $K, V \in \mathbb{R}^{N \times d}$，IO 复杂度为 $O(Nd)$；
- 伪代码第 8 行：每个内循环都加载了部分 $Q, O, m, l$ block，由于 $m, l$ 本身比较小（IO 复杂度是 $O(N)$）暂时忽略，只考虑 $Q, O$（原论文也是这么分析的）。固定某个外循环，所有内循环结束后相当于完整遍历了 $Q, O \in \mathbb{R}^{N \times d}$；同时会经历 $T_c$ 次外循环，因此这里最终的 IO 复杂度为 $O(T_c N d)$；
- 将 $O, m, l$ 写回 HBM，近似后 IO 复杂度为 $O(Nd)$（原论文的分析中没有考虑写回的复杂度，不过省略一些常数项不会影响最终的分析）。

所以**总体的 IO 复杂度为**：

$$ O(T_c N d) = O\left(\frac{N}{B_c} N d\right) = O\left(\frac{4Nd}{M} N d\right) = O\left(\frac{N^2 d^2}{M}\right) $$

其中 $M$ 是 SRAM 大小（$B_c \approx \frac{M}{4d}$，见 6.5 节的块大小计算）。论文中提过，一般 $d$ 的取值在 64~128，$M$ 的取值在 100KB 左右，因此有 $\frac{d^2}{M} \ll 1$。**可以看出，FlashAttention 的 IO 复杂度是要显著小于标准 attention 的 IO 复杂度的**：$O(N^2)$ 的读写降到了 $O\left(\frac{N^2 d^2}{M}\right)$，而降低幅度恰好由 SRAM 容量 $M$ 决定——硬件 SRAM 越大，分块可以越大，读写次数越少。算法与硬件由此真正耦合，这正是 “IO-Awareness” 的落点。

### 八、FlashAttention v1 精简版：把主线串起来

前面各节按细节展开，这里给出 v1 的整体串讲，作为一份浓缩的完整逻辑。

### 8.1 伪代码骨架

v1 forward 的伪代码骨架可以浓缩为：

```text
初始化: m = -inf, l = 0, O = 0
for j = 1 to Tc:            # 外循环：K, V 分块
    从 HBM 加载 K_j, V_j 到 SRAM
    for i = 1 to Tr:        # 内循环：Q 分块
        从 HBM 加载 Q_i, O_i, l_i, m_i 到 SRAM
        S_ij = Q_i * K_j^T                        # 第 9 行：当前分块分数
        计算 m̃_ij, P̃_ij, l̃_ij                     # 第 10 行：局部统计量
        m_i^new = max(m_i, m̃_ij)                  # 第 11 行：在线更新 rowmax
        l_i^new = e^(m_i - m_i^new) * l_i + e^(m̃_ij - m_i^new) * l̃_ij
        O_i = diag(l_i^new)^-1 * (diag(l_i) * e^(m_i - m_i^new) * O_i
                                  + e^(m̃_ij - m_i^new) * P̃_ij * V_j)   # 第 12 行
        m_i = m_i^new;  l_i = l_i^new             # 第 13 行：滚动前进
    写回 O_i, m_i, l_i 到 HBM
```

整个计算过程中只有 $m_i, l_i, O_i$ 在 SRAM 与 HBM 之间往返，$S$ 和 $P$ 始终留在 SRAM 里。

### 8.2 中间过程分块计算：m(x), l(x)

分块计算的核心是两个”滚动统计量”：

- **$m(x)$（rowmax）**：每处理一个新分块，就执行 $m^{new} = \max(m^{old}, \widetilde{m})$，把当前块的局部最大值合并进来。随着 $j$ 推进，$m$ 从”前几块的 max”逐步逼近”全局 max”；
- **$l(x)$（rowsum）**：每处理一个新分块，就执行 $l^{new} = e^{m^{old} - m^{new}} l^{old} + e^{\widetilde{m} - m^{new}} \widetilde{l}$。注意第一项的衰减因子 $e^{m^{old} - m^{new}}$——因为基准 max 变大了，之前攒的 rowsum 必须按比例缩小，才能保持在同一基准下。

这两个量正是 4.5 节推导的（1）～（4）步的工程实现：数学上证明了”局部统计量 + 修正因子 = 全局统计量”，工程上把它们变成了 $O(1)$ 空间的在线更新。

### 8.3 Output 的推导

Output 的更新公式（即 5.3 节九行推导的最终形态）：

$$ O^{new} = \text{diag}(l^{new})^{-1} \left[ \text{diag}(l^{old}) e^{m^{old} - m^{new}} O^{old} + e^{\widetilde{m} - m^{new}} \widetilde{P} V \right] $$

三项各自的含义：$O^{old}$ 是之前所有分块攒下的部分和；乘上 $\text{diag}(l^{old})$ 是为了”退归一化”——它当初是除以旧 rowsum 存的，现在要换到新基准下重新除；$e^{m^{old} - m^{new}}$ 把旧的 max 基准修正到新的；当前分块的贡献 $e^{\widetilde{m} - m^{new}} \widetilde{P} V$ 也修正到同一基准；最后统一除以新的 rowsum $l^{new}$ 完成归一化。当最后一个分块处理完，全局 rowmax 和 rowsum 就是真正的全局值，$O$ 也就精确等于标准 Attention 的输出。

至此，FlashAttention v1 的完整逻辑链闭合：**发现瓶颈（memory-bound）→ 理解硬件（HBM/SRAM 两级存储 + kernel 融合）→ 数学突破（在线 softmax 分块修正）→ 工程落地（tiling 伪代码）→ 收益核算（FLOPs 不变、显存 $O(N)$、IO 大幅下降）**。

### 九、FlashAttention v2：从”算法对”到”跑得满”

v1 解决了”算法正确且省 IO”的问题，但把它跑在真实 GPU 上，SM 的利用率并不理想。**v2 的改进没有一个动了数学——分块逻辑、在线 softmax 的公式都没变，改的全是”怎么把这些计算组织到 GPU 上跑得更满”。** 从这个意义上说，v2 的三个改进都可以归结为 CUDA GEMM 层面的优化。

### 9.1 v2 伪代码与两个细节修正

v2 的 forward 伪代码与 v1 整体同构，但有几处关键差异值得注意：

- **第 8 行**：计算分块 $S_i^{(j)}$；
- **第 9 行**：$m_i^{(j)}$ 表示截止到当前分块 $S_i^{(j)}$（包含当前分块）为止的 rowmax；$\widetilde{P}_i^{(j)}$ 表示使用当前每行最大值计算归一化前的 $P_i^{(j)}$（沿用 v1 的记号约定：不带波浪号的 P 表示 (s−rowmax)/rowsum 的结果，带波浪号表示 (s−rowmax)）；$l_i^{(j)}$ 表示截止到当前分块的 rowsum；
- **第 10 行**：$O_i^{(j)}$ 表示截止到当前分块为止计算出的 O 值。固定 Q 循环 KV 时，每个分块都是用当前最新的 rowmax 和 rowsum 计算的，对应的 $O_i^{(j)}$ 也是；遍历完所有 KV 后，$O_i^{(j)}$ 就等于最终全局的结果（证明同 v1）。

关于第 10 行有额前提两点：

- 可能在有些朋友下载的 v2 论文中，第十行 O 前面的因子项是 $\text{diag}(\ldots)^{-1}$，**这个公式应该是错误的**（动手推一下就可知；初次看到时让不少人困扰了很久）。在作者个人主页的论文链接中，这个 typo 已被修正；
- 你可能已发现这个 O 的计算中缺少归一化的一项 $\text{diag}(l_i^{(j)})^{-1}$，这一项其实放到了第 12 行做统一计算。**这也是 v2 优化的一个点：尽量减少非矩阵的计算，因为在 GPU 中，非矩阵计算比矩阵计算慢 16 倍**——把逐元素的除法从循环体内挪出去、攒到最后做一次，循环内就只剩下 Tensor Core 擅长的矩阵乘和指数运算。

### 9.2 改进一：置换内外循环 + 精简统计量

**Forward 侧：v2 把循环换成 Q 外循环、KV 内循环**。这个置换的收益有两层：

1. **省存储**：v1 中每个 Q 分块要维护对应的 $m_i$ 和 $l_i$；v2 改为 Q 外循环后，每个 thread block 只处理一个 Q 块，这两个统计量成了 block 内的局部变量，不必再全局保存；
2. **配合并行**：Q 外循环意味着”每个 block 独立负责 O 的一部分”，这正好与 9.3 节新增的 seq_len 维度并行配套。

**Backward 侧：内外循环又换回来了，即还是 KV 外循环、Q 内循环**。这是为什么呢？

backward 中主要求 $dV_j, dK_j, dQ_i$（还需要中间结果 $dS_{ij}, dP_{ij}$），总结这些梯度需要沿哪些方向 AllReduce：

| 梯度 | 累加方向 | 说明 |
| --- | --- | --- |
| dV_j | 沿 i 方向 | 需要每行的结果加总 |
| dK_j | 沿 i 方向 | 需要每行的结果加总 |
| dQ_i | 沿 j 方向 | 需要每列的结果加总 |
| dS_{ij}, dP_{ij} | 无 | 只与当前 (i, j) 相关 |

基于此，如果还是保持 Q 外循环、KV 外循环不变的话，这种操作其实是固定行、遍历列的，那么在这些梯度中只有 $dQ_i$ 从中受益了，K 和 V 的梯度则进入了别扭的循环（也意味着要在 shared memory 上写更多的中间结果）；**但如果采用 KV 外循环、Q 内循环，这样 K 和 V 都受益，只有 Q 独自别扭，因此是一种更好的选择**（S 和 P 的计算不受循环变动影响）。

**用 $L_i$ 合并 $m_i, l_i$，进一步减少 shared memory 读写**：backward 过程中，仍需要 $m_i, l_i$ 来做 $S_i^{(j)}$ 和 $P_i^{(j)}$ 的重计算，这样才能用链式求导法则把 dQ、dK、dV 正常算出来。backward 中要用全局的 $m_i^{(j)}, l_i^{(j)}$ 重新计算 $P_i^{(j)}$：

$$ P_i^{(j)} = \text{diag}(l_i^{(j)})^{-1} \exp(S_i^{(j)} - m_i^{(j)}) $$

但如此一来，就要从 shared memory 上同时读取 $m_i^{(j)}, l_i^{(j)}$，似乎有点消耗读写。所以在 v2 中，只存储一个东西：

$$ L_i = m_i^{(T_c)} + \log(l_i^{(T_c)}) $$

等式中的小写 m 和 l 可以理解成是全局的 rowmax 和 rowsum，然后计算 $P_i^{(j)} = \exp(S_i^{(j)} - L_i)$。推导依据是初等恒等式 $\frac{e^{s - m}}{l} = e^{s - m - \log l} = e^{s - (m + \log l)}$：一个除法和一个减法被合并成了一次减法，两个向量 $m_i, l_i$ 被压缩成一个向量 $L_i$。**这个等式又能进一步减少 shared memory 的读写**——它的妙用在 backward 讲解中体现得最充分：重计算时只需读一个 $L_i$，就能同时还原出减 max 和除 rowsum 两步的效果。

### 9.3 改进二：thread block 排布，新增 seq_len 维度并行

**V1 和 V2 的 block 划分差异**（代码整合自 FlashAttention GitHub 下的 cutlass 实现，为方便讲解做了一点改写）：

```cpp
// V1 中：按 batch_size 和 num_heads 划分 grid
// params.b = batch_size, params.h = num_heads
dim3 grid(params.b, params.h);

// V2 中：额外新增 num_m_block 维度（沿 Q 的 seq_len 方向切分）
const int num_m_block = (params.seqlen_q + Kernel_traits::kBlockM - 1) /
                        Kernel_traits::kBlockM;
dim3 grid(num_m_block, params.b, params.h);

```

这段代码告诉我们：V1 中按 batch_size 和 num_heads 来划分 block，一共有 batch_size * num_heads 个 block，每个 block 负责计算 Q 矩阵的一部分；V2 中按 batch_size、num_heads 和 num_m_block 来划分 block，其中 num_m_block 可理解成沿着 Q 矩阵行方向做的切分（例如 Q 矩阵行方向长度为 seqlen_q，也就是熟悉的输入序列长度 seq_len，即图例中的 N），将其划分成 num_m_block 份，每份长度为 kBlockM（每份维护 kBlockM 个 token），一共就有 batch_size * num_heads * num_m_block 个 block。

**为什么要新增 Q 的 seq_len 维度上的划分？先说结论：这样做的目的是尽量让 SM 打满。** block 是会被发去 SM 上执行的。以 1 块 A100 GPU 为例，它有 108 个 SM，如果 block 数量比较大（例如论文中所说 >= 80），就认为 GPU 的计算资源得到了很好的利用。当 batch_size 和 num_heads 都比较大时，block 也比较多，SM 利用率较高；**但如果 seq_len 比较长，往往对应着较小的 batch_size 和 num_heads，这时就会有 SM 在空转了**。为了解决这个问题，就在 Q 的 seq_len 上再切一刀。

假设 batch_size = 1、num_heads = 2，用不同颜色表示不同的 head。Multihead Attention 中各个 head 是可以独立进行计算的，计算完后将结果拼接起来即可。所以将 1 个 head 划分给 1 个 block，就能实现 block 间的并行计算，每个 block 只要计算完后把结果写入自己所维护的 O 的对应位置即可。而每个 block 内，就能执行”KV 外循环，Q 内循环”的过程了，这个过程由 block 的再下级 warp level 层面进行组织、thread 实行计算。

继续假设 batch_size = 1、num_heads = 2，与 V1 不同的是在 Q 的 seq_len 维度上也做了切分，将其分成四份，即 num_m_block = 4，所以现在共有 1 * 2 * 4 = 8 个 block 在跑。**这些 block 之间的运算是独立的**，因为：

- head 的计算是独立的，所以红色 block 和蓝色 block 互不干扰；
- 采用 Q 做外循环、KV 做内循环时，行与行之间的 block 是独立的，因此不同行的 block 互相不干扰。

每个 block 从 Q 上加载对应位置的切块，同时从 KV 上加载 head 对应的切块，计算出自己所维护的那部分 O，然后写入 O 的对应位置。

**为什么只对 Q 的 seq_len 做切分，而不对 KV 的 seq_len 做切分呢？** 在 V2 的 cutlass 实现中确实也提供了对 KV 的 seq_len 做切分的方法。但除非认为 SM 真的打不满，否则尽量不要在 KV 维度上做切分：因为这样一来，不同的 block 之间是没法独立计算的（比如对于 O 的某一行，它的各个部分来自不同的 block，为了得到全局的 softmax 结果，这些 block 的结果还需要汇总再做一次计算）。

**seq 并行不是 V2 特有**：V1 后期也引入过 seq parallel。V1 源码中 num_splits 也是由 Q 的 seq_len 维度切分来的，并且给出了一个启发式函数 num_splits_heuristic_fwd 来决定切几份。这个函数的作用概括起来就是：先提供一连串 num_splits 值的备选，然后由这个函数计算出每个备选值下 SM 的利用率；计算完之后先找到最高的利用率，然后再找出满足利用率 >= 0.95 * max(利用率) 的那个最小的 num_split 值作为最终选择。作者在 V1 后期引入 seq_len 维度切分的原因是：**V1 也需要解决 seq_len 过长时，batch_size 和 num_heads 较小而造成 SM 打不满的问题**。

**grid 组织顺序的调换**：细心的你可能已经观察到了，虽然 V1 也引进过 seq parallel，但是它的 grid 组织形式是 (batch_size, num_heads, num_m_blocks)，而 V2 的组织形式是 (num_m_blocks, batch_size, num_heads)，这种顺序调换的意义是什么呢？直接说结论，**这样的调换是为了提升 L2 cache hit rate**：对于同一列的 block，它们读的是 KV 的相同部分，同一列 block 在读取数据时，有很大概率可以直接从 L2 cache 上读到自己想要的数据（别的 block 之前取过的）。

### 9.4 Forward 与 Backward 中的 thread block 划分

worker 表示 thread block，不同的 thread block 用不同颜色表示；整个大方框表示输出矩阵 O。

**Forward pass（左图）**：每一行都有一个 worker，它表示 O 矩阵的每一行都是由一个 thread block 计算出来的（假设 num_heads = 1），这对应 9.3 节说的划分方式。那么白色的部分表示什么？如果采用的是 casual attention，那么有一部分是会被 mask 掉的，所以这里用白色来表示。但这不意味着 thread block 不需要加载白色部分数据对应的 KV 块，只是在计算过程中它们会因被 mask 掉而免于计算（论文中的 casual masking 一节有提过）。

**Backward pass（右图）**：每一列对应一个 worker。这是因为 BWD 中是 KV 做外循环、Q 做内循环，这种情况下 dK、dV 都是按行累加的，而 dQ 是按列累加的；少数服从多数，因此这里 thread block 是按 $K^T$ 的列划分的。

### 9.5 改进三：Warp 级别并行

讲完 thread block，就可以再下一级，看到 warp level 级别的并行了。**不管是 V1 还是 V2，在 Ampere 架构下每个 block 内进一步被划分为 4 个 warp，在 Hopper 架构下则是 8 个 warp**。V1 和 V2 的区别在于 warp 之间怎么分工：

| 维度 | V1 | V2 |
| --- | --- | --- |
| 每个 warp 从 shared memory 读取 | 相同的 Q 块 + 自己所负责计算的 KV 块 | 相同的 KV 块 + 自己所负责计算的 Q 块 |
| 中间结果 | 每个 warp 只计算出列方向上的结果，必须汇总才能得到最终 O 矩阵行方向上的对应结果 | 行方向上的计算完全独立 |
| warp 间通讯 | 需要：每个 warp 把自己的中间结果写到 shared memory 上，再由一个 warp（例如 warp1）进行统一整合 | 不需要：每个 warp 把自己计算出的结果写到 O 的对应位置即可 |
| 效率 | warp 间通讯、写中间结果，影响了计算效率 | 减少 warp 间的通讯和读取 shared memory 的次数，提升计算效率 |

不过这种 warp 并行方式在 V2 的 BWD 过程中就有缺陷了：**由于 BWD 中 dK 和 dV 是在行方向上的 AllReduce，所以这种切分方式会导致 warp 间需要通讯**。

针对 V2 warp 切分影响 BWD 这点，作者在论文中依然给出了”BWD 过程相比 V1 也有提升”的结论。作者在 GitHub issue 中的一条回复解释了这是多个因素组合的结果：

- **不使用 split-k**，减少了 shared memory 的需求量和 shared memory 的读写次数。作者的意思想必是：之前需要反复读取 KV 的数据，现在只用反复读取 Q 的数据，因此从一定程度上节省了 shared memory 的读写次数；
- **更好的 warp 间任务划分**，可以使用更”方正”的 block 尺寸（V2 中如 128×128 或 64×128，而非 V1 的 16×128 或 16×256）。将 warp 处理的 tile 划分得更像方形，好处是在做 casual mask 时可以大块丢掉被 mask 掉的 tile（见论文 casual masking 部分），进一步加速计算；
- 一些更底层的优化，例如使用 Ampere 的 cp.async 特性。

### 9.6 v2 相对于 v1 的改进点总结

总体来说，V2 从以下三个方面做了改进：

1. **置换内外循环位置，同时减少非矩阵的计算量**（9.1、9.2 节）；
2. **优化 Attention 部分 thread blocks 的并行化计算，新增 seq_len 维度的并行**，使 SM 的利用率尽量打满（9.3 节）——这其实也是内外循环置换这个总体思想配套的改进措施；
3. **优化 thread blocks 内部 warp 级别的工作模式**，尽量减少 warp 间的通讯和读取 shared memory 的次数（9.5 节）。

第二和第三点都可以归结为 CUDA GEMM 层面的优化。至此可以看到一条清晰的演进脉络：v1 回答”怎样让 Attention 算得快”，v2 回答”怎样让 GPU 里的每一块算力都吃饱”。

### 十一、总结

把全文的逻辑主线串起来，FlashAttention 的故事可以讲成四步：

1. **发现真相**：Attention 慢不是因为算不过来，而是数据在显存和片上之间来回搬运太慢。用 Roofline 的语言说，它是典型的 memory-bound 算子——总时间 $T = \max(T_{cal}, T_{load})$，而 Attention 的 $T_{load}$ 远大于 $T_{cal}$。
2. **理解硬件**：GPU 的存储是两级的——HBM 大而慢、SRAM 快而小，计算数据必须搬进 SRAM 才能算。优化的两条铁律由此而来：每次搬就搬满 SRAM；SRAM 装得下的计算就合并成一个 kernel，避免中间结果落地。
3. **数学突破**：分块计算最大的障碍是 softmax 依赖整行的全局统计量。safe softmax 的可修正性（$m$ 取 max 拼接、$l$ 带衰减因子累加）让”分块算、在线更新”成为可能；$O$ 的九行推导保证每遍历一块就修正一次、最后一块算完时结果与标准 Attention 分毫不差。backward 侧则用重计算换掉 $S, P$ 的存储，$dS$ 的行梯度结论 $dS_i = P_i \odot [dP_i - \text{rowsum}(dO_i \odot O_i)]$ 让梯度也留在片上。
4. **账本与进化**：最终成绩单——FLOPs 一个不少（$O(N^2 d)$）、显存 $O(N^2) \to O(N)$、HBM 读写 $O(N^2) \to O\left(\frac{N^2 d^2}{M}\right)$。v2 不改数学，只改组织方式：内外循环按 forward/backward 的累加方向各取所需、新增 seq_len 维度并行把 SM 填满、warp 级并行消除 warp 间通讯、用 $L_i = m_i + \log l_i$ 再省一半统计量读写。

**一句话收束**：FlashAttention 教给算法工程师最重要的一课是——当算力增长持续快于带宽增长时，衡量算法好坏的标准不再只是 FLOPs，而是每一次数据搬运换来了多少次计算。IO-Awareness 不是工程补丁，而是一等公民的算法设计原则。

### 附录 B：softmax 与交叉熵的补充说明

- **safe softmax 的数值意义**：fp16 的最大值约为 65504，当 logit 值较大时 $e^{x_i}$ 极易上溢；减去行最大值后所有指数项的值域被压到 $(0, 1]$，分子分母同时缩小不影响商。
- **softmax + 交叉熵联合求导**：交叉熵 $H = -\sum_t \hat{y}_t \log y_t$ 对 $y_i$ 的偏导为 $-\hat{y}_i / y_i$；与 softmax 的 Jacobian 相乘后化简得 $\frac{\partial L}{\partial z} = y - \hat{y}$（预测概率减真实标签）。多分类例子：真实标签 $y_{true} = [0, 1, 0]$、预测概率 $y = [y_1, y_2, y_3]$ 时，$L = -\log(y_2)$，此时 $\frac{\partial L}{\partial y_1} = 0$、$\frac{\partial L}{\partial y_2} = -\frac{1}{y_2}$、$\frac{\partial L}{\partial y_3} = 0$；但使用链式法则计算 $\frac{\partial L}{\partial z_2}$ 时仍按通用形式对所有 $i$ 求和，因为不同的真实标签或模型结构下，$z_2$ 的变化可能会通过 $y$ 的所有元素对 $L$ 产生影响。
