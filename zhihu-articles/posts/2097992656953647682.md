**EAGLE-4 的核心是把“继续生成多少草稿、验证多少候选”变成收益与硬件时间成本共同决定的运行时决策，同时让每次自回归 draft forward 更便宜。** 它沿用轻量自回归 drafter，新增硬件感知的 EAGLE-Harness 和“两阶段检索、重算”的 Efficient LM Head，并调整 attention/cache 等实现。（§3.1–3.4，pp.5–6）

### 1. 先抓住论文真正要解决的问题

投机解码通常把一个小模型的若干次 drafting，换成 target 的一次并行 verification。小 batch 时，target 每步处理的 token 少，搬运参数可能占主要时间；增加一些验证 token，往往能更充分使用计算资源。大 batch 时，draft 与 target 的计算成本都可能变高，额外猜出的长后缀就未必划算。论文因此要求同时考虑接受收益与执行成本。（§1、§1.1，pp.1–3）

### 1.1 memory-bound 指搬运速度受限，compute-bound 指算术吞吐受限

**小 batch 常 memory-bound，大 batch 更 compute-intensive。**一个 kernel 处理给定数据，既要搬数据，也要做运算。设：

| 符号 | 含义 | 单位 |
| --- | --- | --- |
| F | 运算量；一次乘加按两次浮点运算计 | FLOP |
| Q | HBM 与计算单元之间需要传输的数据量 | byte |
| P | 假设同类计算可达到的持续计算吞吐上限 | FLOP/s |
| BW | 可达到的持续内存带宽 | byte/s |

理想化下界是

$$ t_{kernel}\gtrsim\max\left(\frac FP,\frac Q{BW}\right). $$

- 若 $Q/BW$ 更大，主要在等待数据，称为 **memory-bandwidth-bound，内存带宽受限**。
- 若 $F/P$ 更大，主要受运算吞吐限制，称为 **compute-bound，计算受限**。

真实耗时还受 kernel launch、同步、通信、低并行度、访存模式等影响，未必只由上式的两项主导；这里的 $P,BW$ 也不能直接用硬件宣传峰值代替实测可达值。

### 1.2 用算术强度判断更接近哪一侧

定义算术强度

$$ I=\frac FQ\quad(\mathrm{FLOP/byte}),\qquad I_*=\frac P{BW}. $$

在这个模型里，$I<I_*$ 更接近带宽受限区域，$I>I_*$ 更接近计算受限区域。由时间下界也能写出计算吞吐上界：

$$ \mathrm{attainable\ FLOP/s}\lesssim\min(P,BW\cdot I). $$

直觉理解是：**每搬进一份权重，能反复用它算多少 token。** 重用越多，每 byte 对应的 FLOP 越多；直到计算单元开始成为约束。

### 1.3 batch 与 target verification 怎样增加权重重用

看一个 dense 矩阵乘法：

$$ Y=XW,\qquad X\in\mathbb R^{m\times d_{in}},\quad W\in\mathbb R^{d_{in}\times d_{out}}. $$

记矩阵参数个数 $N=d_{in}d_{out}$，每个参数 $b$ byte。假设权重恰好从 HBM 读取一遍，并暂时忽略 activation、KV 等流量，则

$$ F\approx2mN,\qquad Q\approx bN,\qquad \boxed{I\approx\frac{2m}{b}}. $$

BF16/FP16 的 $b=2$，于是这个权重主导模型中 $I\approx m$ FLOP/byte。**m 是同一次矩阵乘法中共享权重的 token 行数。** 普通 decode 时它常近似为请求 batch 大小；一次 target verification 可将每个请求的多个已知候选 token 一起评估，因此增加 m。

若 batch 为 $B$，每请求实际交给 target 的 token 行数为 $s$，则 $m\approx Bs$。它不是“被接受的 token 数”：送入验证但最后被丢弃的候选也支付了计算。

**沿一条 AR draft 路径的未来步，不能直接合并成同一 GEMM 的 m 行**：下一 token 输入依赖上一步输出。多个请求、同深度分支可以 batch；target verification 的候选输入已知，能使用 causal/tree mask 一次评估。这是 drafting 与 verification 的并行机会差异。（§2.2，pp.4–5；教学展开）

### 1.4 同样多验证一些 token，在两种负载下可以得到相反结果

假设某个权重主导 dense 部分有：

$$ N=10^9,\quad b=2\ \mathrm{byte},\quad P=100\ \mathrm{TFLOP/s},\quad BW=1\ \mathrm{TB/s}. $$

使用十进制单位，权重为 2 GB，读一遍要 2 ms；处理 m 行的计算时间为

$$ t_{compute}=0.02m\ \mathrm{ms},\qquad t_{memory}=2\ \mathrm{ms},\qquad I_*=100\ \mathrm{FLOP/byte}. $$

| 同次前向 token 行数 m | 计算时间 | 权重搬运时间 | 两项最大值 | 模型中的主导项 |
| --- | --- | --- | --- | --- |
| 1 | 0.02 ms | 2 ms | 2 ms | 带宽 |
| 8 | 0.16 ms | 2 ms | 2 ms | 带宽 |
| 128 | 2.56 ms | 2 ms | 2.56 ms | 计算 |
| 1,024 | 20.48 ms | 2 ms | 20.48 ms | 计算 |

为了单独看清这两项成本，下面将该理想 dense 部分视作 target 主体，额外开销仅按设定的 draft 时间计入；这不是完整 Transformer 延迟预测。

先比较**小 batch**。令 $B=1$，baseline 每步处理 1 行，target 时间 2 ms。投机每轮验证 $s=8$ 行，平均实际提交 $G=5$ 个 token，假设整个 batch 的一轮 drafting 额外花 0.5 ms。target 验证时间仍近似 2 ms，则生成同样 token 量的加速比为

$$ S\approx\frac{G\,t_{base}}{t_{draft}+t_{verify}} =\frac{5\times2}{0.5+2}=4. $$

再比较**大 batch**。令 $B=128$，baseline 每步已处理 128 行，时间 2.56 ms。仍按每请求验证 8 行，总行数变成 1,024，target 时间升至 20.48 ms。假设每请求平均仍提交 5 个 token，而整个 batch 的 drafting 用时 1 ms：

$$ S\approx\frac{5\times2.56}{1+20.48}\approx0.596. $$

这里 $G$ 是实际提交量的平均值，包含所采用轮次计数中的纠正/bonus。

这个算例说明：小 batch 可利用原本闲置的计算能力，一次搬权重评估多个候选；大 batch 已经提高了权重重用，继续扩大验证量时，更容易按候选行数支付计算。它**不预言所有大 batch 投机都变慢**，只是说明最佳预算会变化。

### 1.5 与 EAGLE-4 新增机制接起来

Harness 通过 warm-up 获得真实 draft 与 verification 成本，用

$$ \frac{\text{额外预期接受收益}}{\text{额外实测时间成本}}\ge\text{阈值} $$

来调整预算。Harness 的查表把这种变化落实到决策中，而路径 confidence 提供收益估计。

另一项新增机制 Efficient LM Head 同时影响每步的算术和数据访问：低秩头扫描全词表的较短向量，再只读取少量完整 W 行来重算候选。（§3.2.1，p.6）在理想权重流量模型下，head 从触及约 $bVd$ byte，变成约

$$ b(Vr+rd+Kd)\ \mathrm{byte}, $$

与投影算术 $O(Vd)\to O(Vr+rd+Kd)$ 一起减少。

因此，**Harness 决定当前值得做多少计算，efficient head 降低每步成本**；后者又会改变前者的最优预算，两个组件有相互作用。

### 1.6 EAGLE-4 围绕上述问题做了三层工作

| 层次 | 具体机制 | 想解决的成本 |
| --- | --- | --- |
| 运行时预算 | warm-up 测成本；按负载调整 draft 深度、宽度和验证节点数 | 不值得继续生成或验证的候选 |
| 每步计算 | 低秩头在全词表召回少量候选，再用完整权重精确重算候选 logits | 轻量 drafter 中占比很高的 LM head |

**one drafter的解读：针对一个 target model 使用同一套 drafter 权重，改变运行时草稿预算以适应不同负载和硬件**。

### 2. EAGLE-4 在 EAGLE 家族里改了哪一层

论文自身对前代的回顾，可以压缩成下面这张机制表。（§2.2，pp.4–5）

| 版本 | 论文回顾的关键变化 | 读 EAGLE-4 时要保留的认识 |
| --- | --- | --- |
| EAGLE | target feature 与前移一位的 token embedding 辅助轻量 drafter；同时训练 feature regression 和 token prediction | feature 来源和 token 位置要对齐 |
| EAGLE-2 | 用路径 draft 概率给节点打分，构造随上下文变化的动态树 | 已经存在动态树，不能把动态树本身算作 EAGLE-4 首创 |
| EAGLE-3 | 取消 feature regression；融合低、中、高层 target hidden；用 training-time test 暴露递归输入 | 后续 draft 步使用自身 hidden，训练要覆盖这种输入 |
| EAGLE-3.1 | captured hidden 分别做 RMSNorm，drafter hidden 做 post-normalization | 属于本文沿用的架构基础 |
| EAGLE-4 | 在上述自回归架构上加入硬件成本驱动的预算和高效 LM head 等机制 | 新重点在执行成本与预算控制 |

这里的 training-time test，是在训练中让 drafter 输出反馈到后续训练步，模拟测试时递归使用自身 hidden 的情形；它不表示部署时对每个用户请求做梯度更新。（§2.2，p.5）

### 2.1 用 `a b c` 对齐一轮中的 token 位置

假设已确定前缀为 `a b c`。target 的 prefill 得到位置 `c` 的特征 $f_c$，并由其输出分布确定下一 token `d`。这个 `d` 是当前轮的 root token。

![](https://pica.zhimg.com/v2-b4cbd0997d43c1d166158ac60654c15c_r.jpg)

抽象写成：

$$ f_c=F(h_c^{\rm low},h_c^{\rm mid},h_c^{\rm high}), $$

$$ g_d=D(f_c,\operatorname{Emb}(d),\mathrm{KV}_{draft}),\qquad \hat e\sim Q(\cdot\mid g_d), $$

$$ g_e=D(g_d,\operatorname{Emb}(\hat e),\ldots),\qquad \hat f\sim Q(\cdot\mid g_e). $$

$F$ 表示融合与必要的归一化、投影；$D$ 表示轻量 drafter；这里只刻画数据依赖，不指定真实层索引或源码接口。

关键有两点：**第一步用真实 target feature，后续步递归用 drafter 自身 hidden；输入 token `d` 的 hidden/logits 用于预测下一个 token `e`。** 验证前，target 尚未为这些未验证后续 token 提供可直接替代递归 hidden 的真实特征。（§2.2，p.5）

### 2.2 自回归仍可以在分支间并行

沿着同一条路径，`e` 影响 `f` 的分布，因此有自回归依赖。不同分支在同一层可以组成 batch；target 则用 tree attention 的可见性限制，一次计算多个候选分支，让每个节点只看到共享前缀和自己的祖先。（§2.2，p.4；§1.1，p.3）

### 3. 吞吐由接受收益和整轮成本一起决定

### 3.1 先区分 accepted tokens 与本轮实际推进 tokens

对链式 speculative decoding，若提出 $m$ 个候选，接受了前 $\ell$ 个：首次拒绝时会补一个 target 纠正 token；全部通过时会补一个 target bonus token。因此在常见的单链描述下，实际推进量是 $\ell+1$。

**推导：** 用 $G$ 表示一轮平均实际推进 token 数，$C$ 表示平均总耗时：

$$ \mathrm{throughput}\approx\frac{G}{C},\qquad C=C_{draft}+C_{verify}+C_{other}. $$

所以，更长的接受前缀只改善分子；更多 draft 步、更大的验证树也可能增加分母。论文据此强调应报告整体吞吐，而不能仅按 acceptance length 排名。（§4.1，p.7）

### 3.2 一条链的期望接受长度如何算

**推导：** 设 $a_i$ 是“此前均接受时，第 $i$ 个候选也接受”的条件概率，则

$$ P(\ell\ge i)=\prod_{j=1}^{i}a_j, \qquad \mathbb E[\ell]=\sum_{i=1}^{m}\prod_{j=1}^{i}a_j. $$

这里用的是条件概率链式法则，不要求各个接受事件独立。

若 $a_1=0.8,a_2=0.7,a_3=0.6$，各深度 survival 为

$$ 0.8,\quad0.8\times0.7=0.56,\quad0.8\times0.7\times0.6=0.336, $$

因此 $\mathbb E[\ell]=1.696$，计入纠正/bonus 后为 $G=2.696$。越深位置带来的边际收益受到此前整条路径存活的限制。

### 3.3 论文用路径 draft 概率近似节点收益

论文延续 EAGLE-2 的思路，把节点 $v$ 的打分写成沿分支 draft 概率的乘积，可用教学记号表示为

$$ \hat p(root)=1,\qquad \hat p(v)=\prod_{u\in\mathrm{path}(root\to v)\setminus\{root\}} q(x_u\mid\text{共享前缀},\text{祖先 token}). $$

它估计节点被接受的可能性，用来分配树预算。（§2.2，p.4；Algorithm 1 caption，p.6）这里与前文位置算例采用同一教学计数约定：root 已由 target 确定，故其分数设为 1，只对后续提议节点乘 draft 概率；PDF 没有展开统一的 root 计数公式。

**这个 $\hat p$ 是启发式估计，不能与上一节真实 $a_i$ 连乘混同。** greedy 下是否匹配由 target 的 greedy token 决定；随机采样下真实接受还取决于 target/draft 比值。仅知道 drafter 很自信，不足以知道它和 target 一致。

**解读者推导：** 将求和限定为待验证的非 root 提议节点，若 $I_v$ 表示最终接受路径是否包含节点 $v$，则

$$ A(\mathcal T)=\mathbb E\left[\sum_{v\ne root} I_v\right] =\sum_{v\ne root}P(I_v=1). $$

用 $\hat p(v)$ 代替未知真实概率，可解释为什么增加一个验证节点的估计收益近似为它的分数

### 4. EAGLE-Harness：将继续 drafting 变成边际决策

### 4.1 warm-up 测量的是时间成本

Harness 在 warm-up 中测量不同 batch size、context length、生成/验证 token 数下 draft 与 target 的执行延迟，缓存成 lookup tables。运行时据当前 batch $B$、平均 context length $L$ 等条件读取成本，再结合候选收益做决策。

这说明硬件感知不只依赖 GPU 型号：**相同硬件在不同负载、上下文和验证规模下，也有不同成本。** 论文没有公布 profiling 网格、插值、表刷新策略或 warm-up 时间，不能凭正文完全复刻。

### 4.2 公共判据与三个控制位置

论文的公共判断是：

$$ \boxed{\frac{\Delta A}{\Delta C}\ge\tau} $$

$\Delta A$ 是预期接受增益，$\Delta C$ 是增加的 profiled 时间，$\tau$ 是阈值。

![](https://pic2.zhimg.com/v2-6e79cde396cd21ac78a7aa270b4c3373_r.jpg)

具体实验仍有自己的 width 上限，不能认为所有实验都用宽度 8。

验证预算判据尤其容易被 PDF 文本断行读错：

$$ \boxed{\frac{\hat p_{n+1}}{c_{ver}(n+1)-c_{ver}(n)}\ge\tau_v} $$

分母是**增加一个节点的验证时间差**，不是总验证时间，也不是先除以 $c_{ver}(n+1)$ 再减去 $c_{ver}(n)$。（Algorithm 1，p.6；已核对原图括号）

> **Algorithm 1：一轮 Harness 的高层流程。** 先 expand 一层，再判断是否继续更深层；随后按边际验证收益选 top-n 节点。它没有展开正文全部的宽度控制与随机采样深度规则。（p.6）<br>

![](https://pic3.zhimg.com/v2-ae095542e5e7814d8ac86d7e76665e2e_r.jpg)

### 4.3 为什么这个判据与吞吐相连

当前推进量与成本为 $G,C$，增加一次扩展带来 $\Delta G,\Delta C>0$。

$$ \frac{G+\Delta G}{C+\Delta C}\ge\frac GC \iff C\Delta G\ge G\Delta C \iff\frac{\Delta G}{\Delta C}\ge\frac GC. $$

额外计算的 token/time 不低于当前平均 token/time 时，扩展才改善这个简化目标。

但**论文没有定义 $\tau=G/C$，也没有给出全局最优树证明**。实际 $\tau_d$ 还随深度改变。

**例：** 当前一轮推进 3 token，用时 1 ms，即 3 token/ms。

![](https://pic4.zhimg.com/v2-5a9f93df8c6ce28c3dd92e2d582e3f73_r.jpg)

收益相同，硬件或负载改变了额外耗时，就足以改变预算。这是“同一 drafter，生成不同树”的关键直觉。

### 4.4 T>0 时，停止规则也属于采样算法

论文特别规定：随机采样时，若按本轮已经抽到的 token 来决定何时停止，可能使输出偏置。因此**本轮深度要预先固定，使用上一轮“本会停止”的深度**，在追踪成本变化时保持采样正确性。（§3.1，p.5 右栏末段）

**反例**：target=draft，两个 token `A/B` 各有 0.5 概率。先抽一个候选；看到 `A` 就保留，看到 `B` 就取消候选，改为从 target 重抽。最后

$$ P(A)=0.5+0.5\times0.5=0.75,\qquad P(B)=0.25. $$

即使两个模型本来完全一致，错误的候选取消规则也会引入偏置。

**解** 如果轮长由已提交历史决定，且在抽本轮候选前就选定；每个固定轮长的 verifier 又各自保持 target 分布，那么按预先选定轮长做混合仍保持该分布。论文用上一轮信息决定本轮深度，正是在避免本轮样本反过来影响本轮选择。

### 5. Efficient LM Head：让低秩近似负责召回

### 5.1 轻量 drafter 的瓶颈可能已经移到词表投影

当 drafter backbone 只有一层，完整词表 LM head 反而可能占很大比例。Figure 2 的特定测量中，完整 head 方案一次 draft forward 为 574 μs，其中 head 占 65.4%。换成 rank-512、rank-128 的 efficient head 后，总延迟分别是 326 μs、255 μs，下降 43.2%、55.6%。（Figure 2，p.4；§3.2，p.5）

> **Figure 2：单次 draft forward 的成本分解。** 低秩方案显著降低 LM-head 部分，其他部分约保持不变。图中的 μs 指单次 forward，不是整轮 verification cycle，也不是用户请求总延迟。<br>

![](https://pic3.zhimg.com/v2-9eb22d0f3c807cf2210bfde41007680e_r.jpg)

### 5.2 两个阶段的张量形状

论文定义：

$$ h\in\mathbb R^d,\quad W\in\mathbb R^{V\times d},\quad z=Wh, $$

其中 $h$ 是 drafter 的输出 hidden，$V$ 是词表大小。完整投影为每个词计算一个 logit。

新增低秩因子

$$ A\in\mathbb R^{V\times r},\qquad B\in\mathbb R^{r\times d},\qquad r\ll d. $$

**第一阶段：便宜地找候选。**

$$ u=Bh\in\mathbb R^r,\quad \tilde z=Au\in\mathbb R^V,\quad \mathcal C=\operatorname{TopK}(\tilde z,K). $$

**第二阶段：精确算候选分数。**

$$ W_{\mathcal C}\in\mathbb R^{K\times d},\qquad z_{\mathcal C}=W_{\mathcal C}h\in\mathbb R^K. $$

最后从这些精确候选 logits 中进行 draft selection。论文使用 $K\in\{128,256,512\}$。（§3.2.1，p.6）

代码示例：

```python
coarse_logits = A @ (B @ h)                 # [V]，只用于召回
candidate_ids = topk_indices(coarse_logits, K)  # [K]
exact_logits = W[candidate_ids] @ h         # [K]，候选内精确重算
chosen_id = candidate_ids[argmax(exact_logits)]  # greedy 示例
```

### 5.3 手算一次成功召回，以及一次漏召回

**举个🌰：**

$$ h=\begin{bmatrix}1\\1\end{bmatrix},\qquad W=\begin{bmatrix} 2&0\\ 0&1\\ 1.5&1\\ -1&0 \end{bmatrix}. $$

完整 logits 为

$$ Wh=[2,1,2.5,-1]^\top, $$

所以 token `C`（第三行）是全词表 top-1。

取 rank-1 的 $B=[1,0]$，故 $Bh=1$。若低秩因子 $A=[1.9,0.8,2.1,-0.5]^\top$，检索 top-2 为 `C/A`；重算精确 logits 得到 `2.5/2`，最后仍选 `C`。

若检索分数变为 `[2,2.2,1.8,-1]`，top-2 就成为 `B/A`；精确重算只能在 `B/A` 中选 `A`，无法找回被排除的 `C`。

所以，**精确重算能修正候选内部的排序，却不能补救候选外的漏召回。** 训练检索头要让重要候选尽量进入 shortlist，这也解释了论文强调 candidate recall。

### 5.4 计算量为什么下降

论文给出的投影算术复杂度是

$$ O(Vd)\longrightarrow O(dr+Vr+Kd), $$

其中不包含 TopK 和 row gathering 的开销。（§3.2.1，p.6）

**例：** 设 $V=128000,d=4096,r=128,K=128$，只计矩阵乘法中的乘法次数：

$$ Vd=524,288,000, $$

$$ dr+Vr+Kd=17,432,576. $$

两者约差 30.08 倍。

### 6. 精确候选 logits、精确采样分布与无损验证

这是本篇最需要分清的一组概念。

### 6.1 候选 logits 精确，不代表归一化后仍是完整分布

**推导：** 完整 drafter softmax 是

$$ q_{full}(v)=\frac{e^{z_v}}{\sum_{u\in\mathcal V}e^{z_u}}. $$

若只在 $\mathcal C$ 内归一化，则

$$ q_{\mathcal C}(v)= \begin{cases} \dfrac{e^{z_v}}{\sum_{u\in\mathcal C}e^{z_u}}, &v\in\mathcal C,\\ 0,&v\notin\mathcal C. \end{cases} $$

raw logit 相同，分母却不同。

### 6.2 标准拒绝采样为什么能保持 target 分布

论文给定同一前缀下 target 分布 $p$、实际 draft 分布 $q$，候选 $\hat x\sim q$ 的接受概率为

$$ \alpha(\hat x)=\min\left(1,\frac{p(\hat x)}{q(\hat x)}\right). $$

首次拒绝后从

$$ p^{corr}(v)=\frac{[p(v)-q(v)]_+}{\sum_u[p(u)-q(u)]_+} $$

采样替代 token；全部接受则补一个 target token。这是论文用于保持 target 输出分布的标准机制。（§2.1，p.4）

**推导：** 接受分支给 token $v$ 的概率质量是

$$ q(v)\min(1,p(v)/q(v))=\min(p(v),q(v)). $$

拒绝总质量是 $R=\sum_u[p(u)-q(u)]_+$，纠正分支对 $v$ 的贡献为 $[p(v)-q(v)]_+$。两者相加：

$$ P(\text{输出 }v)=\min(p(v),q(v))+[p(v)-q(v)]_+=p(v). $$

只在 $q(v)>0$ 的已抽候选上计算接受比率；$q(v)=0$ 的 token 可以由纠正分支补回。

**算例：**

$$ p=(0.6,0.3,0.1),\qquad q=(0.4,0.6,0). $$

接受分支质量为 `(0.4,0.3,0)`，总接受概率 `0.7`；拒绝质量为 `0.3`，纠正分布为 `(2/3,0,1/3)`。最终分布恢复 `(0.6,0.3,0.1)`，尽管第三个 token 从未进入 draft 的提议支持集。

这说明 draft shortlist 的近似首先影响效率。**严格正确性要求 target 的 $p$ 正确、用实际生成候选的 $q$，并正确执行接受/纠正、分支选择和停止规则。** 不能把候选内重算或 98.2% recall 当作这些条件的替代。

### 6.3 greedy 与采样的“无损”也要区分

在相同数值语义和正确验证下，greedy 关心 token 序列一致；随机采样关心输出**分布**一致。即使分布一致，随机数消费顺序不同，也不保证同一 seed 生成逐 token 完全相同的文本。

### 7. 自回归、并行与混合 drafting 的准确比较

### 7.1 关键区别在于决定停止时，哪些成本已经支付

论文把 DFlash 类方法描述为一个多层 block pass 联合生成多个位置；把 DSpark 描述为 parallel backbone 加轻量 sequential head 的混合方法。完整自回归 drafter 则在每步显式条件于同分支已经生成的 token。（§1.1，pp.2–3）

| 维度 | EAGLE-4 自回归 drafting | block / hybrid drafting：本文讨论的情况 |
| --- | --- | --- |
| 条件依赖 | 每步使用实际生成的分支前缀 | block 联合建模，或由较轻的 sequential head 引入条件依赖 |
| 停止机会 | 当前步提供信息后，可停止后续 backbone draft 步 | 已生成 block 的后缀即使不验证，相关生成成本也已付出 |
| 小 batch 机会 | 可花更多步构造深/宽树 | 少量 sequential pass 联合出多个位置，降低 sequential drafting latency |
| 高负载风险 | 每步本身仍有成本，需缩短或收窄 | block 长于有效验证前缀时会支付弃用后缀成本 |

### 7.3 attention/cache 与 FFN：有机制描述，缺贡献拆分

- **DSA / SWA**：对 sparse 或 linear-attention target，full-attention drafter 在长上下文可能成为瓶颈；论文考虑更轻 attention，其中 SWA 只看局部窗口。（§3.3.1，p.6）
- **draft phase append-only**：草稿阶段只追加新 cache entries，暂不逐步驱逐最老条目，以简化 DSA/SWA 管理。（§3.3.2，p.6）
- **MoE / dense 对齐 target**：作者称 MoE 改善不同 draft steps 与 context lengths 的泛化，但增加内存和训练开销，最终使 drafter FFN 类型与 target 对齐。（§3.4，p.6）

### 8.对这篇工作的判断

EAGLE-4 值得学习的机制是：用接受收益与时间成本一起分配 speculation 预算；把逐步自回归的停止机会用起来；并让低秩近似承担候选召回，而把候选分数交给完整权重重算。三个环节分别对应“做多少”“何时停止”“每步多贵”。本文最可靠的收获是一个可检验的工程设计方向：**把草稿生成、验证和接受分别计量，在当前硬件与负载下，只为预期值得的后续计算支付成本。** 对自回归和并行 drafting 的最终选择，仍应由匹配模型、数据、预算和 serving 配置的实验决定。
