## 二、 FlashAttention V1：IO 感知的起点

### **2.1 解决的问题**

传统的注意力机制实现（如 PyTorch）由于频繁在显存（HBM）和片上缓存（SRAM）之间读写巨大的 *N*×*N* 注意力矩阵，导致计算速度受限于内存带宽，而非 GPU 算力。Split-K 方案，Oi需要频繁读在 B，Head 并行，在大 seqlen ，小 batch时不好并行。

### **2.2计算原理**

![](https://pic3.zhimg.com/v2-8e4e4caa28917c106c16c975ba35e82c_r.jpg)
*V1计算过程*

![](https://pic1.zhimg.com/v2-6f2cd248e92b555e8ca0407393ecde7e_r.jpg)

1. **分块（Tiling）：** 将输入 *Q*,*K*,*V* 划分为小块加载到 SRAM 中计算。

2. **重计算（Recomputation）：** 反向传播时不存储 *N*×*N* 矩阵，而是通过存储前向传播的归一化统计量，在反向传播时重新计算注意力分块。

3. **在线 Softmax（Online Softmax）：** 这是 V1 的灵魂。它允许算法在不知道全局最大值的情况下，通过增量更新统计量来计算精确的 Softmax。

## 三、 FlashAttention-2：效率与并行的极限

### **3.1 解决的问题：** V1 虽然减少了 IO，但硬件利用率仍不理想（A100 上约为 30-50%）。主要在以下几点优化：

1. FlashAttention 使用分块（Tiling）避免了在 HBM 中实例化 *Seq*×*Seq* 矩阵, 对 seq 较大的场景收益大

2. 解决Split-K 方案重复加载 O 的问题，切分后的Oi可放在 SRAM

3. GPU 在 Seq len Warp 并行，增大了并行维度，对 Seq Len 大，batch 小的场景友好

4. 不需要对那些行索引严格小于列索引的块应用因果掩码。这意味着对于每一行，我们只需要对1个块应用因果掩码: 左下角不需要，右上角是无效数据，只有对角线需要应用 maskfill

5. 反向是只需要一个归一化统一量 LogSumExp（反向没仔细研究）。

### **3.2 计算原理：**

![](https://pica.zhimg.com/v2-550d1f86f232634baee0252cb025278c_r.jpg)

![](https://pic1.zhimg.com/v2-16c6761ca87dcb99c897fb1ab6e31470_r.jpg)

1. **减少非矩阵乘法（Non-matmul）开销：** GPU 的矩阵乘法单元（Tensor Cores）速度远高于其他运算。V2 调整算法逻辑，**避免了每次迭代都进行缩放**，而是维护一个“未缩放”的输出，仅在循环结束时统一缩放一次。

2. **更强的并行性：** 引入了对**序列长度维度**的并行化，将不同行的计算任务分配到不同的线程块（Thread Blocks），提高了在长序列下的 GPU 占用率。

3. **Warp 级别优化：** 改变了分工方式（从 Split-K 改为 **Split-Q**），让所有线程束（Warp）共享 K 和 V，减少了跨线程束的同步通信。

**针对学习记录的整合：** 在 V2 中，统计量存储从 (*m*,ℓ) 进化为单一的 **LogSumExp (***L*<!-- -->**)**，计算公式为 *L*=*m*+log(ℓ)。正如我们在问答中讨论的，**LogSumExp 是反向传播的“钥匙”**。在前向传播结束时存储 *L*，反向传播时通过 *P*=exp(*S*−*L*) 即可精确还原注意力概率，从而减少了 HBM 的读取量。

FlashAttention v2 (简称 FA2) 在其 Online Softmax 的设计上延续了分块计算的思路，但相比于 v1 版本，它通过**改进数学逻辑**减少了非矩阵乘法（non-matmul）的运算量，同时保证了数值结果与标准 Softmax 的完全一致（即“数值不变”）。

### 3.3 数值不变性的原理解释及数据验证

1. 原理解释：增量更新与延迟归一化

标准 Softmax 需要获取整行数据的最大值 *m* 和总指数和 *L* 才能开始计算。而 FA2 采用的是一种**增量更新**的策略：

• **分块处理 (Tiling)**：将长向量划分为多个小块（如 *S*(1),*S*(2)），逐块加载到 SRAM 中计算。

• **维护统计量**：在处理每个新块 *j* 时，实时维护两个统计量：当前的局部最大值 *m*(*j*) 和累计的指数和 ℓ(*j*)。

• **指数底数对齐（关键因子** $e^{m^{\text{old}} - m^{\text{new}}}$ **）**： 当新块的局部最大值比之前记录的最大值更大时（即 *m*(*j*)>*m*(*j*−1)），为了让之前计算出的部分和（基于旧最大值 *m*(*j*−1)）能与当前块相加，必须将其乘以一个缩放因子 *em*(*j*−1)−*m*(*j*)。这样，所有的项最终都相当于统一以当前的全局最大值为基准进行计算。

• **延迟归一化 (V2 的核心改进)**： 在 FA1 中，每一步循环都会执行除以当前 ℓ 的操作。而 **FA2 维护一个“未缩放（un-scaled）”版本的输出** *O*。在每一轮循环中，它只进行指数缩放和加法，直到**所有分块都处理完毕后，才在最后执行一次统一的除法（归一化）**。

2. 简单数据验证

![](https://pic3.zhimg.com/v2-99675436edbc715dad93b21a12ec6650_r.jpg)

结论：

可以看到，通过引入对齐因子$e^{m^{\text{old}} - m^{\text{new}}}$ ​，分块计算的结果与标准算法在数学上是**恒等**的。FA2 巧妙地利用了加法的结合律和指数函数的性质，将全局计算拆解为可以在受限的 SRAM 空间内完成的增量步骤。**比喻说明**：这就像是两队学生分别在两个教室统计分数。第一组说他们的最高分是 2 分，总分（指数化后）是 1.36；第二组说他们的最高分是 4 分。当你要合并统计时，不能直接相加，因为分母不同。你需要让第一组把他们的分数“折算”一下（乘以对齐因子），统一转换到以 4 分为基准的水平，然后再和第二组的分数合并，这样得到的结果就和把所有学生放在一个教室统计完全一样。

## 四、 FlashAttention-3：Hopper 架构的异步艺术

### **4.1 解决的问题：** 针对 NVIDIA H100 (Hopper) 架构，FA2 无法充分利用其新硬件特性（如 TMA 和 WGMMA 指令）。有如下几个关键点：

1. 在 Hopper 架构上的性能优化，使用了 TMA 和Tensor Core 的异步计算

2. 通过 Warp-spec 实现计算和搬运并行

3. 交替块计算 MatMul 和 Softmax

4. FP8 块量化和非相干处理，融合到 Mem-Bound 算子中不增加开销

### **4.2 计算原理：**

1. **生产者-消费者异步化（Warp-Specialization）：** 将线程束分为“生产者”（负责数据搬运）和“消费者”（负责计算），利用 TMA 异步搬运数据，隐藏内存访问延迟。

![](https://pic3.zhimg.com/v2-1b4cc6b4a005cd869c17988118480fc0_r.jpg)

2. **流水线交叠：** 在 Tensor Core 计算当前块的矩阵乘法时，并行地在多功能单元（Multi-function Unit）上处理前一块的 Softmax 指数运算。

![](https://pic1.zhimg.com/v2-9c7a415b1cf852245330be44622acc3e_r.jpg)

![](https://pica.zhimg.com/v2-5ab9a0318c8858515b1b13b573d8c344_r.jpg)

3. **FP8 低精度支持：** 为了解决 FP8 离群值（Outliers）带来的精度损失，引入了**不相干处理（Incoherent Processing）**——利用随机正交矩阵（Hadamard 变换）平滑特征值分布。

## 五、 FlashDecoding++ ：大模型推理的专项加速

### **5.1 解决的问题：**

1. 专门针对推理设计

2. Softmax 采用一个统一的 max value，减少更新和重计算；出现异常的时候重算 Softmax

3. GEMM 补padding的优化，用补 8 替代补 64

4. **扁平矩阵利用率低：** 推理时（Decode 阶段）输入往往是极薄的向量（*M*=1 或很小），传统库（如 cuBLAS）填充至 64 会导致严重浪费。类似 GEMV 的运算，CUDA Core 计算会比 Tensor Core 更快，采用启发式搜索方法动态选择不同的 kernel 函数。

![](https://pic3.zhimg.com/v2-51b1e0e7c29b7e6411e296202cf90b12_r.jpg)

### **5.2 计算原理：**

1. **异步 Softmax 与统一最大值 (***ϕ*<!-- -->**)：**

◦ 通过统计学发现 99.99% 的注意力得分在特定范围内。

◦ 设定一个**预定义的统一最大值***ϕ*，各分块基于 *ϕ* 独立计算，**彻底取消同步等待**。

![](https://pic2.zhimg.com/v2-3b6dbeb90a92ed8db9f96b43430826bd_r.jpg)

![](https://pica.zhimg.com/v2-246326721befc40af0a075d04a972cee_r.jpg)

![](https://picx.zhimg.com/v2-bef6bea59035a3ae3583a0114f8c5c39_r.jpg)

2. **分块优化：** 将矩阵填充细化至 **8** 而非 64，显著提升了扁平矩阵（Flat GEMM）的计算效率。

3. **启发式动态调度：** 根据 Batch Size 动态决定使用 CUDA Core（适合小 Batch）还是 Tensor Core（适合大 Batch）。

![](https://pic2.zhimg.com/v2-6cbb4f0f775eec60fb904df15184ba57_r.jpg)

## 六、总结与展望

从 V1 到 FlashDecoding++，FlashAttention 的演进体现了对硬件特性的极致压榨：

• **V1/V2** 关注减少 HBM 访问和优化并行模式；

• **V3** 迈向了复杂的异步指令调度和低精度优化；

• **FlashDecoding++**则精准打击推理侧的长序列延迟痛点。

**比喻说明：** 如果将 Attention 计算比作**工厂加工零件**：

• **V1** 是学会了不要把零件在车间和仓库之间搬来搬去；

• **V2** 是优化了生产线分工，让更多工人（Warp）同时开工；

• **V3** 是引入了自动化传送带（TMA），让搬运和加工完全重叠；

• FlashDecoding则是为小额订单（推理）定制了专门的微型生产线，并规定了统一的加工标准（*ϕ*），让工人不需要互相询问进度就能直接出货。
