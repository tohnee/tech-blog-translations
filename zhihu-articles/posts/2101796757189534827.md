**比赛回顾：赛场实战验证**

本次大赛由上海人工智能实验室 DeepLink 团队主办，围绕国产模型与国产芯片开展算子生成、迁移和性能调优，探索跨芯片开发与优化方法。大赛共吸引 800 余名来自海内外高校、企业与科研机构的选手参与。

其中，“赛道一：Triton 优化赛道”，一共设置了10 道算子赛题，涵盖 GroupedTopk、FusedMoE、FlexAttention 等任务。**每个算子都面向昇腾、沐曦、天数、燧原、平头哥、寒武纪、海光、摩尔、昆仑芯和英伟达十款指定芯片开展适配与性能优化，形成“10 道赛题 × 10 款芯片”的跨平台优化矩阵。**参赛作品须先通过正确性校验，再按相对 PyTorch 参考实现的加速比在各芯片上排名；每道赛题汇总各芯片积分，单独排名、设奖。这既考验单芯片上的性能调优深度，也考验同一套算子代码在不同芯片架构与编译工具链的适配能力。面对这些要求，北京智源人工智能研究院的参赛选手们利用**FlagOS 社区旗下 KernelGen 产品**，通过多智能体协同，将算子分析、代码生成、编译验证与性能调优串联为自动化闭环，在统一开发流程下探索适配不同芯片的高性能算子实现。这业界开展跨硬件平台算子优化提供了有效的工具支撑。

mhc_post 是面向新型大模型架构的专用算子，负责子层输出与多路残差的加权融合，其背后的 mHC（流形约束超连接）架构由 DeepSeek 于 2025 年底提出。这类新架构带来的计算与访存模式，为底层算子的融合、调度和硬件适配提出了新的优化需求。

下面，文章会详细介绍智源参赛团队是如何使用 KernelGen 完成「KernelSwift 算子创新大赛」中 Task07 mhc_post 算子的开发和优化工作。

比赛中，智源参赛团队使用 deepseek-v4-flash-0731 驱动 KernelGen 的 Agent 工作流，以算子定义、测试用例和目标芯片信息为输入，由 Analyzer 分析计算结构与平台约束，组织多个 Coder 并行探索实现方案。候选代码通过统一执行接口提交至 KernelGen Server，由目标平台的原生工具链完成编译、正确性校验和性能测量，并按需提供性能剖析信息。硬件执行结果持续返回搜索环节，指导下一轮代码修改与候选筛选。

在 mhc_post 的优化中，KernelGen 围绕向量乘加、任务切分和访存分块等方向持续迭代，逐步筛选出满足精度要求、性能更优的实现。最终，在昇腾 910B4 上运行官方评测脚本，提交实现通过精度校验，将算子耗时从 2.345 ms 降至 0.446 ms，相对参考实现取得 5.26× 加速。团队最终摘得该算子题奖项。

这些代码、评测结果和搜索轨迹，也是当前 Kernel Memory 提炼经验的依据。Distiller 从运行产物中总结优化策略，Reviewer 审查证据归因与适用边界，再以“策略、适用条件、执行证据”的形式组织经验，供后续算子按目标硬件和工作负载检索、适配与复用。

**核心能力：跨平台开发与经验复用**

**1、跨平台算子开发：统一流程，面向不同芯片优化**

面对不同芯片，算子开发既要理解计算逻辑，也要应对编译工具链、存储层次和并行方式的差异。KernelGen 将这项工作拆分为相互协作的两部分：主机侧的智能体负责分析算子、提出优化方向和生成代码；目标芯片上的 KernelGen Server（KGS）负责原生编译、正确性验证、性能计时与诊断。**双方通过统一接口协作，让同一套开发流程连接不同硬件，同时保留各平台的专用优化能力。**

在这套框架中，Analyzer 分析算子结构与瓶颈，多个 Coder 并行探索不同实现。KGS 将编译错误、数值检查和实测性能返回给智能体，推动下一轮修改；系统再从通过验证的候选中选出最佳实现，继续迭代。遇到性能瓶颈时，智能体还可以按需查看性能计数器、编译中间表示和底层诊断信息，用真实执行反馈指导分块、融合和流水线等优化。

开发者因此可以沿用统一流程，针对目标平台生成 Triton/Triton-TLE、CUDA 或 Ascend C 等实现，并在相应设备上验证效果。这为赛事中同一算子面向十款芯片的适配与调优提供了共同的开发基础。

**2、经验复用：把一次优化的积累用于新算子**

算子优化中的经验能否复用，取决于它在什么条件下有效。Kernel Memory 将优化策略与实测证据一同保存，记录适用芯片、编程语言、算子和工作负载，以及失败条件和重新尝试的依据，让一次搜索的积累能够被后续任务检索和利用。

每轮探索结束后，Distiller 从成功与失败中总结经验，Reviewer 对照执行记录审核并反馈修改，避免把多项改动的共同收益归因于单一因素，或将某个配置的失败扩大成对整类方法的否定。面对新算子，智能体围绕当前优化目标检索经验，先阅读摘要，再按需展开代码与证据，结合目标条件调整实现，并重新验证。
