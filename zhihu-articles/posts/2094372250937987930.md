## 把所有开源模型归为高风险，会影响团队本地部署的决策

很多团队还在算本地部署会不会被合规卡死。Guillaume Princen 是 Anthropic 的国际业务负责人。10 月 14 日，他在都柏林国际 AI 峰会接受了彭博电视采访。他先提醒这家闭源大模型公司的客户，对开源模型在安全上要非常小心。他甚至直接说“根据定义它们带有更高风险”。问题是，他下一句就呼吁企业“永远要投资在最前线模型”。他说是一两年后成本也会降下来。接着他就顺手推销自家的 Claude Opus 5.5 便宜 40%。在我看来，把所有开源模型直接按定义定罪，根本不该成为公司禁止本地部署的理由。

更好笑的是，这番话连他自家老板的说法都对不上。外媒 The Next Web 指出，这位美国以外的最高业务主管比老板激进得多。今年 7 月，首席执行官 Dario Amodei 才公开写文章表过态。他说公司从未主张禁止把参数公开、允许开发者下载到本地运行的开放权重模型。Amodei 当时明确表示，不具备危险能力的开放权重模型属于公共财。

这完全是前脚刚吓唬完客户，后脚就递上报价单。Reddit 网友 Hugoacfs 嘲讽得很到位。他说这像可口可乐宣称在家做汽水危害你和邻居健康，所以应该禁止。平时自己配显卡和内存跑本地模型、算 API 账单的工程师，对这套路都很眼熟。云端厂商一边吓唬法务说本地跑模型太危险，一边把长期订阅合同递过来。一旦合规部门因此卡死开源模型，团队就只能留在闭源 API 里继续付账单。

## 宣称降价四成与欧洲合规豁免，看懂安全警告背后的账单算术

为什么一位最高业务主管会在都柏林峰会上，突然把所有开源模型打成高风险？把这场采访里的定价数字和欧洲市场背景拆开来看，背后的商业算盘其实非常清楚：

![](https://pic1.zhimg.com/v2-b48a80c16083b03c674319687e354e22_r.jpg)
*宣称降四成，牌价仅降两成，其余靠少耗token*

- Princen 口头宣称新模型典型成本便宜 40%。The Next Web 与 Quartz 核对发现，实际牌价只降了 20%。另一半降幅是靠少消耗 token 算出来的，官方却没公开具体测试条件。
- 根据 The Next Web 报道，Anthropic 正准备在纳斯达克上市。他们目前的估值高达 9650 亿美元。都柏林是它在欧盟的首个办公室，欧洲、中东及非洲又是它增长最快的市场。在这个节骨眼上，付费购买前沿模型的企业客户占了公司很大一块业务。
- 就在发言前 8 天，法国初创公司 Mistral 刚发布了 Large 4。这是一个在欧洲训练的一万亿参数模型，预计 10 月 27 日放出开放权重。
- 欧盟《人工智能法案》第 53 条对开源模型给出了明确豁免。只要没有发现系统性风险，真正免费且开源的模型可以免交部分合规文件。

这账算得真精。把上市营收压力、欧洲对手发模和法规豁免放在一起看，动机就很清楚了。这场高调警告，其实就是为了守住欧洲企业客户的防御话术。正在评估 AI 成本的团队，千万别把“先买最贵模型、等以后降价”当真。毕竟那一半降幅完全取决于 token 的实际消耗量。团队如果不拿真实任务去测一遍，光听宣传根本算不出能不能省钱。

## 小模型自动搭服务与蠕虫复制实验，哪些安全风险确实存在

但这不代表所有安全警告都是推销话术，里面确实有值得警惕的技术信号。Anthropic 研究员在 10 月 12 日发表过一份物联网自我复制报告。把它和第三方机构 SaferAI 的安全评测放在一起看，有几个关键结果：

![](https://picx.zhimg.com/v2-a150f7a403b5688caa5be5e2f1a05087_r.jpg)
*五次里四次铺满八节点，其余模型端到端失败*

- SaferAI 测试了中国开放权重模型 GLM-5.2。结果显示，它在攻击性网络安全任务中是零拒绝。在既能用于医药研发、也可能制造生物危害的双重用途生物任务里，它同样零拒绝。相比之下，Claude 因为持续拒绝回答，导致这项基准测试根本没法跑完。
- 在 10 月 12 日的实验里，研究员测试了 90 亿参数的 9B 开源小模型。它在 9 种测试硬件中的 8 种上面，自己解决了环境与依赖问题并架起推理服务。
- 研究团队还在 8 个云端节点上跑起了安卓模拟器。这些节点都开着未设密码验证的 ADB 远程调试接口。简化渗透后，GLM-5.2 在 5 次实验里有 4 次复制到全部 8 个节点。剩下 1 次实验，它也成功复制到了 7 个节点。

这些实验确实说明，开放权重模型一旦放出，原厂就没法再靠集中式护栏拦截恶意用途。不过翻看同一份报告的细节，情况并没有那么夸张。其他 300 亿参数以下的开源模型，在端到端复制测试中全都失败了。而且在真实的白牌安卓电视盒上，完整架设一次推理环境要花约 11 小时到 6 天。连研究员自己都写道，这种按天计算的缓慢扩散更像没有中心节点的“数字黏菌”。

## 公开权重才让测试得以进行，现阶段算账与管设备的具体做法

哪怕物联网蠕虫的风险确实存在，在这场争论里我依然反对把整个开源类别按定义定罪。正如 The Next Web 所说，这套实验能做出来，恰恰因为模型公开了权重。真正决定风险高低的是模型外的权限与防线，跟权重有没有公开是两码事。

只因原厂没法远程关停就否定所有开放权重模型，其实是在替闭源 API 守住生意。要让我改观，除非未来有一份不靠公开权重、把闭源模型放在同条件下对照的评估。只有证明开源模型在同等外部防护下依然更容易失控，才算得上是“按定义风险更高”。

现阶段我会建议开发团队和普通用户先做好两件实事。算 API 账单时别轻信口头折扣，先拿真实任务去测 token 总消耗。只有实测过输入和输出量，才能算清闭源 API 与本地开源模型的真实价差。管办公室和家里的联网设备时，要把白牌电视盒这类物联网设备隔离到独立网段。同时记得关掉设备上没设密码验证的 ADB 远程调试端口。这次我站开源模型这边，因为公开权重才能让工程师看清风险、把防线做在模型外面。
