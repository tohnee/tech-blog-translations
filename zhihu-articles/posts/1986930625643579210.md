## 引言

在训练万亿参数级别的混合专家模型（MoE, Mixture of Experts）时，单一的并行策略往往难做平衡。数据并行（DP/FSDP）能解决显存墙问题，但面对 MoE 巨大的总参数量时通信开销过大；专家并行（EP）能有效降低通信，但单卡显存又容易爆掉。

开源框架 **VeOmni** 提供了一个精妙的解决方案：**FSDP2 + EP 的混合并行策略**。本文将深入剖析其核心函数 `parallelize_model_fsdp2`，带你理解它是如何在 PyTorch FSDP2 的基础上，“嫁接”出高效的专家并行的。

## 核心架构：2D Device Mesh

在进入代码之前，我们需要先建立一个心理模型。

假设条件如下：

- **GPU 总数量 (World Size):** 16
- **专家总数量 (Total Experts):** 32
- **EP Size (Expert Parallel Size):** 8
- **EP_FSDP Size (DP for Experts):** $16 / 8 = 2$

我们不想让它们仅仅排成一列（纯 FSDP），而是组成一个二维网格：

- **EP Size = 8**: 将专家分成 8 组，每组处理不同的专家（降低计算量）。
- **EP_FSDP Size = 2**: 每组内部有 2 张 GPU，它们分摊存储同一组专家的参数（降低显存占用）。

这个架构贯穿了整个实现的逻辑。

## parallelize_model_fsdp2 源码深度拆解

函数 `parallelize_model_fsdp2` 代码配了详细的注释，其工作流可以被清晰地划分为三个阶段。

### 第一阶段：处理专家维度

在 FSDP 介入之前，必须先处理专家维度的逻辑切分。

```python
# Step 1: Apply expert parallelism
if parallel_state.ep_enabled:
    parallel_plan = model.get_parallel_plan()
    # 这一步是逻辑切分：将大张量 [128, H, I] 切片为本地张量 [16, H, I]
    ep_fqn2spec_info = parallel_plan.apply(model, parallel_state.ep_fsdp_device_mesh)
    
    # 获取专家模块的映射表，用于后续精准定位
    experts_map = parallel_plan.get_fsdp_no_shard_info(model)
```

`parallel_plan` 的细节在下一个部分，这里简单介绍下，`parallel_plan.apply` 并不是物理上把模型拆了，而是让每张卡只加载**它所属 EP 组**对应的专家权重。

- **输入**：所有 128 个专家。
- **输出**：当前 GPU 显存中只存在 16 个专家（假设 EP=8）。
- **注意**：同一个 EP Group 内的 GPU（如 GPU0 和 GPU1），此时拥有**完全相同**的 16 个专家副本。这为下一步的 FSDP 组内切分埋下了伏笔。

### 第二阶段：分离专家与普通层

MoE 最大的难点在于：**Decoder Layer 内部既有需要 EP 的专家层，又有只需要普通 FSDP 的 Attention 层。**

VeOmni 使用了一段非常 Pythonic 的代码来做提取：

```text
# 遍历每一个 Decoder Block
for layer_fqn, layer_mod in decoder_blocks:
    if experts_map is not None:
        # 在当前 Layer 的子模块中，寻找路径匹配的专家模块
        experts_mod = next(
            (exp_mod for exp_fqn, exp_mod in experts_map.items() 
             if exp_fqn.startswith(layer_fqn + ".")),
            None,
        )
        layer_pairs.append((layer_fqn, layer_mod, experts_mod))
```

### 第三阶段：差异化切分 (The Hybrid Sharding)

这是整个函数的灵魂所在。我们根据模块的身份，分发不同的“并行身份证”。

### 1. 准备两套配置

- **普通 FSDP 配置 (`fsdp_kwargs`)**:

- **专家 FSDP 配置 (`expert_fsdp_kwargs`)**:

```text
# 专家专用配置
ep_fsdp_mesh = parallel_state.ep_fsdp_device_mesh["ep_fsdp"]
expert_fsdp_kwargs = dict(fsdp_kwargs)
expert_fsdp_kwargs["mesh"] = ep_fsdp_mesh

# 强制专家参数在 Dim-1 (Hidden Dim) 上切分，而非 Dim-0
def _experts_shard_placement_fn(param):
    return Shard(1)
expert_fsdp_kwargs["shard_placement_fn"] = _experts_shard_placement_fn
```

### 2. 执行切分

代码由内而外地应用 `fully_shard`：

```text
for layer_fqn, layer_mod, experts_mod in layer_pairs:
    # A. 先切分专家 (如果存在)
    if parallel_state.ep_enabled and experts_mod is not None:
        fully_shard(experts_mod, **expert_fsdp_kwargs)
        # 注册梯度除法因子，处理 EP 带来的梯度累积问题
        experts_mod.set_gradient_divide_factor(parallel_state.ep_size)
        
    # B. 再切分整个 Layer (包裹住剩余部分，如 Attention)
    fully_shard(layer_mod, **fsdp_kwargs)
```

**可视化流程：**

1. **专家层**：先被“拿出来”，在 EP 组内（2张卡）按 Hidden 维度切开。此时，GPU0 存左半边权重，GPU1 存右半边权重。
2. **Attention层**：随后，整个 `layer_mod` 被视为普通层，在所有 16 张卡上按 Dim-0 统一切分。

## 总结：数据在 GPU 上的最终分布

![](https://pic2.zhimg.com/v2-ef7daf853fea5e5ed03b96dd7f72f08f_r.jpg)

让我们回到最开始的例子（16 GPU, EP=8）。经过这个函数的处理，你的模型参数分布如下：

1. **Attention / LayerNorm 参数**：

- **分布范围**：16 张 GPU 全局分布。
- **切分方式**：被切成 16 份，每张卡持有 1/16。

**MoE Expert 参数**：

- **Step 1 (EP)**：根据卡号，只保留了属于本组的 1/8 专家（例如 Expert 0-3）。
- **Step 2 (FSDP)**：这 1/8 的专家，在组内（2张卡）进一步被切成两半。
- **最终状态**：每张卡持有 (总专家数 / 8 / 2) 的参数量。
