Anthropic、OpenAI、xAI 都在争着做一件事：

**让 AI 不只是一个聊天机器人，而是能和人一起工作的 AI 同事。**

想象一下：

你把一个复杂任务交给 AI，它不再是一个模型从头干到尾，而是可以让多个 AI 分工合作。

一个负责写代码，一个负责分析架构，一个负责测试。它们之间还能互相沟通、共享信息，甚至你可以随时加入讨论，调整方向。

听起来很理想，但这里有个问题👇

## 1. 不同厂商的 AI，为什么很难一起工作？

现在很多 AI 产品都把模型、运行环境、记忆和任务调度绑定在自己的生态里。

比如：

- 你用 Claude Code 写代码
- 用 Codex 处理另一个开发任务
- 用 OpenCode 跑本地模型
- 还有自己开发的内部 AI Agent

这些工具各自都很好用，但想让它们互相配合，往往需要自己开发一套连接系统。

这就是所谓的 **厂商锁定（Vendor Lock-in）** 。

![](https://picx.zhimg.com/v2-9829d54285f6776513a9c08ce88357bf_r.jpg)

说白了，AI 越来越强，但不同 AI 之间还缺一个能够协调工作的“中间层”。

## 2. Switch：让不同 AI 在一个工作空间里协作

最近发现一个开源项目叫 **Switch** ，它想解决的就是这个问题。

它提供了一个可以自己部署的 AI 协作层，让不同厂商的 AI Agent 和人类进入同一个工作空间。

![](https://pica.zhimg.com/v2-ab52a2a8dd371f39820431b82acea2a4_r.jpg)

支持接入的沟通平台包括：

- Slack
- Microsoft Teams
- Discord
- Telegram
- Mattermost

它的核心思路是：

**不管 AI 来自哪家厂商，都可以通过 Switch 进行协作。**

人类可以直接和 Agent 对话，Agent 之间也可以互相沟通。任务执行过程中，你还可以随时补充信息、提出要求，或者调整执行方向。

## 3. Manager：像项目经理一样调度 AI

![](https://pic1.zhimg.com/v2-f0f5ae5bce0868cf2d7b7535bdb2d624_r.jpg)

Switch 还有一个比较有意思的设计：Manager（管理者）。

你可以给不同的 Agent 设置角色，例如：

- Software Engineer：软件工程师，负责代码和技术排查
- Architect：架构师，负责分析系统设计
- QA Lead：测试负责人，负责验证问题和检查结果

当你把任务交给 Manager，它可以创建对应的讨论空间，拉入需要的 Agent，并负责在不同任务之间传递上下文。

最后再把结果汇总，返回给你。

相当于你只需要提出目标，Manager 就能组织一支 AI 团队来完成工作。

## 4. 实际案例：两个故障，多个 Agent 并行排查

我们给 Manager 提供了两个线上故障：

**问题 A：** 上午发布新版本后，推理 API 开始频繁返回 500 错误。

**问题 B：** 推荐模型的训练任务已经卡住 6 个小时。

![](https://pica.zhimg.com/v2-b75a2b7f488632377fd0e5cc33acf862_r.jpg)

Manager 收到消息后，直接创建了两个关联的任务空间，并安排软件工程师、架构师和 QA 负责人并行调查。

有意思的是：

在排查训练任务时，工程师查看了另一个推理故障的讨论空间，发现两个问题可能都与同一次配置推送有关。

最终，Manager 将两边的调查结果整合，生成了一份统一的 RCA（根因分析报告），并返回最初的沟通频道。

这就不只是多个 AI 各自回答问题了，而是开始尝试让它们 **共享上下文、交叉验证，并共同推进一个复杂任务。**

## 5. 为什么说这是 Agents 2.0？

过去我们使用 AI，通常是：

提问 → AI 回答 → 人工整理 → 再交给另一个 AI。

而 Agent 2.0 想实现的是：

提出任务 → 自动分工 → 多 Agent 协作 → 人类随时介入 → 汇总交付。

整个过程中，你可以查看不同 Agent 的对话，也可以通过 Switch Console 检查底层的 Agent 会话。

项目使用 Docker 和 Mattermost 进行本地部署，强调让协作层独立于某一个模型供应商。

毕竟模型会不断更新，今天用 Claude，明天可能换成 OpenAI，后天又可能接入本地模型。

**真正有价值的，不只是某一个 AI 有多聪明，而是能不能把不同 AI 组织起来，形成一套可持续运行的工作流程。**

对于正在开发 AI Agent、自动化研发流程，或者想搭建多智能体系统的开发者来说，这个项目值得研究。
