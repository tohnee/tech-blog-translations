> 本系列第十四篇，模块三第一篇。大模型无法放在单张卡上训练，必须分布式训练。本文系统讲解数据并行、模型并行、张量并行、流水线并行，以及它们如何组合使用。

---

### 一、为什么需要分布式训练？

### 1.1 模型太大

现代大模型参数量惊人：

| 模型 | 参数量 | FP32 模型大小 |
| --- | --- | --- |
| GPT-2 | 15 亿 | 6 GB |
| GPT-3 | 1750 亿 | 700 GB |
| LLaMA 3 405B | 4050 亿 | 1.6 TB |
| GPT-4 | 估计 >1 万亿 | 数 TB |

单张 GPU 的显存只有 40GB–192GB，放不下这些模型。

### 1.2 数据太多

训练数据也极大：

- GPT-3 训练数据约 5000 亿 token；
- LLaMA 3 训练数据超过 15 万亿 token。

单张卡处理这些数据需要数年，必须并行加速。

### 1.3 目标

分布式训练有两个目标：

1. **加速训练**：用更多卡一起算，缩短时间；
2. **支持大模型**：把模型切分到多张卡，解决显存不足。

---

### 二、数据并行（Data Parallelism, DP）

### 2.1 核心思想

每张 GPU 都保存一份完整的模型副本，但处理不同的数据子集。

```text
GPU 0: batch_0 → forward → backward → gradient_0
GPU 1: batch_1 → forward → backward → gradient_1
GPU 2: batch_2 → forward → backward → gradient_2
GPU 3: batch_3 → forward → backward → gradient_3
```

然后所有 GPU 同步梯度，更新各自的模型副本。

### 2.2 梯度同步：AllReduce

数据并行的核心是 **AllReduce** 操作：

```text
gradient_avg = (gradient_0 + gradient_1 + gradient_2 + gradient_3) / 4
```

每个 GPU 都得到平均梯度，然后各自更新模型。

### 2.3 优点

- 实现简单；
- 扩展性好；
- 通信量只和模型大小有关，和 batch size 无关。

### 2.4 缺点

- 每张卡都要存完整模型，模型太大时显存不够；
- AllReduce 通信可能成为瓶颈。

### 2.5 适用场景

模型能放进单卡，但训练数据太多，需要加速。

---

### 三、模型并行（Model Parallelism, MP）

### 3.1 核心思想

模型太大，单卡放不下，把模型切分到多张卡。

例如一个 10 层的网络：

```text
GPU 0: 层 1–3
GPU 1: 层 4–6
GPU 2: 层 7–9
GPU 3: 层 10
```

数据依次流过各张卡，每张卡只计算自己负责的部分。

### 3.2 缺点

- 每张卡必须等待前一张卡的结果，利用率低；
- 通信频繁；
- 扩展性不如数据并行。

### 3.3 适用场景

模型太大，单卡放不下。

---

### 四、张量并行（Tensor Parallelism, TP）

### 4.1 核心思想

同一层内的矩阵运算切分到多张卡。

例如一个线性层：

```text
Y = X × W
```

W 是 d_in × d_out 的矩阵。可以把 W 按列切成两块：

```text
W = [W_0 | W_1]
```

然后：

```text
GPU 0: Y_0 = X × W_0
GPU 1: Y_1 = X × W_1
```

最后把 Y_0 和 Y_1 拼接起来。

### 4.2 优点

- 减少单卡显存占用；
- 同一层内可以并行计算。

### 4.3 缺点

- 需要频繁通信（每次矩阵乘后都要同步）；
- 通常只在同一台服务器内的 GPU 之间使用（NVLink 带宽高）。

### 4.4 适用场景

单层太大，需要切分。常见于 Transformer 的 FFN 和 Attention 投影层。

---

### 五、流水线并行（Pipeline Parallelism, PP）

### 5.1 核心思想

把模型按层分成多段，每段放在不同 GPU 上，像工厂流水线一样处理多个 micro-batch。

```text
GPU 0: 层 1–3
GPU 1: 层 4–6
GPU 2: 层 7–9
GPU 3: 层 10
```

但和数据流式模型并行不同，流水线并行一次推进多个 micro-batch，让 GPU 尽量忙碌。

### 5.2 气泡问题

流水线中存在“气泡”（bubble）：前面的 GPU 等后面的 GPU 完成，或者后面的 GPU 等前面的数据。

例如：

```text
时间 →
GPU 0: F1 F2 F3 F4 _  _  B1 B2 B3 B4
GPU 1: _  F1 F2 F3 F4 _  _  B1 B2 B3
GPU 2: _  _  F1 F2 F3 F4 _  _  B1 B2
GPU 3: _  _  _  F1 F2 F3 F4 _  _  B1

F = 前向，B = 反向，_ = 空闲（气泡）
```

### 5.3 减少气泡的方法

| 方法 | 思想 |
| --- | --- |
| GPipe | 把 batch 分成很多 micro-batch，填满流水线 |
| PipeDream | 前向和反向交错，进一步减少气泡 |
| 1F1B | 一个前向接一个反向，平衡内存和效率 |

### 5.4 优点

- 通信量小（只传相邻阶段的激活值）；
- 适合跨服务器扩展。

### 5.5 缺点

- 有气泡，利用率不是 100%；
- 需要保存多个 micro-batch 的激活值，增加内存。

### 六、混合并行：3D 并行

实际大模型训练通常组合多种并行：

```text
数据并行（DP） + 张量并行（TP） + 流水线并行（PP）
```

### 6.1 组合方式

| 并行类型 | 切分维度 | 通信范围 |
| --- | --- | --- |
| 数据并行 | 数据 batch | 服务器之间 |
| 张量并行 | 模型层内 | 服务器内部（NVLink） |
| 流水线并行 | 模型层间 | 服务器之间或机架之间 |

### 6.2 一个例子

假设有 64 张 GPU：

- 张量并行 TP=4：同一台服务器内 4 张卡处理同一层；
- 流水线并行 PP=4：4 台服务器组成流水线；
- 数据并行 DP=4：4 个这样的流水线组处理不同数据。

总卡数 = 4 × 4 × 4 = 64。

### 七、更高效的优化：ZeRO 和 FSDP

### 7.1 ZeRO（Zero Redundancy Optimizer）

ZeRO 是 DeepSpeed 提出的数据并行优化方法。

传统数据并行中，每张卡都保存：

- 完整模型参数；
- 完整梯度；
- 完整优化器状态。

ZeRO 把它们切分到不同卡上，每张卡只存一部分：

```text
ZeRO-1: 切分优化器状态
ZeRO-2: 切分优化器状态 + 梯度
ZeRO-3: 切分优化器状态 + 梯度 + 参数
```

这样可以用数据并行训练更大的模型。

### 7.2 FSDP（Fully Sharded Data Parallel）

PyTorch 推出的类似 ZeRO 的技术。

- 把模型参数、梯度、优化器状态切分到所有 GPU；
- 需要时动态收集参数；
- 训练完成后可以转换回普通模型。

---

### 八、如何选择并行策略？

| 场景 | 推荐策略 |
| --- | --- |
| 模型能放进单卡，数据多 | 数据并行 |
| 模型太大，单卡放不下 | 张量并行 + 流水线并行 |
| 要训练超大模型 | 3D 并行 + ZeRO/FSDP |
| 同一服务器内 GPU 多 | 张量并行 |
| 跨服务器扩展 | 流水线并行 + 数据并行 |

---

### 九、小结

> **分布式训练通过数据并行、模型并行、张量并行、流水线并行等策略，把大模型和大规模数据分散到多张 GPU 上。数据并行最简单，但受限于单卡显存；张量并行和流水线并行可以支持更大模型，但增加了通信和调度复杂度。实际大模型训练通常采用 3D 混合并行，配合 ZeRO/FSDP 等技术进一步减少显存占用。理解这些并行策略，是理解大规模 AI 训练系统设计和 AI 芯片互联需求的基础。**
