### **多面体优化**

1. 用仿射变换不等式将多层循环中的下标组合映射为高维空间中的多面体中的点的集合。
2. 再用仿射变换可以得到下标到 statement 用到的 memory 的映射关系。
3. 通过分析依赖关系确定哪些可以并行，以及如何利用 cache。
4. 对相同或不同的 statement，不同的下标映射后的 memory 相同，则说明该或这些 statement 不同的循环中访问的是相同的 memory，可以尽量缩短执行间隔，或改成同样的下标，增加 cache hit rate。
5. 使用仿射变换改变循环结构（将老的下标映射为新的下标），实现优化。

## 四 个人优势

**熟悉 GPU 软件和硬件架构：**

1. UMD 管理所有创建的和每个 Pipeline 用到的 Memory，处理 Pipeline 间的同步，打包 CMD 到 Queue。
2. KMD 为所有 UMD 分配 Memory 和调度所有的 Queue。
3. GPU 的 Command processor 通过 Queue 读 CMD （多线程，异步读取），配置其他 Block 的寄存器，并通过 Signal 和 Wait event 来实现同步。
4. GPU 的 shader launch block 负责 launch shader 到 Compute unite (CU) 的 wave slot 中。
5. 每个 CU 中由 SQ （类似 NV GPU 中的 SM）负责不同 Wave（NV 中的 Warp） 中不同种类指令的执行，如不同 Wave 中的 VALU，SALU 和 memory operation（也分 scalar 和 vector） 可以并行执行，且若某个 Wave 在等待 Memory 返回或 Export ready，也可以优先调度其他 Wave。
6. 每个 Wave 有多个（32）Thread，不同的 Thread 共用同样的程序和 PC，针对 Scalar 操作所有 Thread 使用同样的数据，针对 Vector 操作，所有 Thread 拥有自有数据，并可通过 VALU 并行计算，通过 EXEC mask 决定是否写回计算结果。
7. ALU 级别的并行，每个 ALU 的执行也是 multi state pipeline，如典型的取指令、译码、读取操作数、指令执行、数据写回。如果后一个操作输入依赖上一个操作输出，则会卡在读操作数阶段，破坏 pipeline 并行结构，尤其是有些操作的指令执行需要多个周期。

**熟悉 GPU 端的程序：**

1. 图像相关的程序如 VS，PS，CS，在写程序时便要考虑到这个程序是在多个 Thread 上并行执行的。尤其是 CS，需要指定 thread group 大小，把大的计算分解为不同 thread group 上的计算，同时要考虑单个 group 中不同 thread 的计算，以及数据同步的问题。
2. 熟悉 AMD GPU instruction，如 SALU，VALU，Memory 相关指令，各种 Wait 以及各种 Cross lane 操作。

**有大量 Shader Debug 经验**

1. **Codeing 容易，Debugging 难。**
2. 知道看哪些内容，如看 IB status，看 Cmd buffer，看 Shader 地址和 User data，看 Cmd buffer 卡在哪里了（和 GPU Core 异步的，不容易看到的），看 Shader 状态，Hang 在哪个 Shader，哪些 Thread 是存活的，了解 SGPR，VGPR 初始状态等。
3. 掌握各种调试技巧，如何 Narrow down issue。 如何排除 UMD 的问题，如何替换 Pipeline，手动更改 ISA，Halt shader，甚至加条件断点 Halt shader，dump shader 中间运行数据，设置 Shader 每次 memory 操作等待结果返回，单步调试 Shader 等。

**熟悉 GPU User Mode 驱动**

现有 UMD 主要负责 Memory 的管理，Pipeline 的同步，Cmd buffer 的生成管理，个人认为编译器和驱动是分不开的，接口分的再细也还是需要互相了解彼此的架构和实现，且架构也应该是与时俱进的，很多驱动的职责或许未来可以由编译器自动生成。

## 六 模型和 CUDA 复习

CUDA 矩阵乘法示例：

```cpp
#include <iostream>
#include <cuda_runtime.h>

// 定义矩阵乘法的 CUDA 内核
__global__ void matrixMul(float *C, float *A, float *B, int width) {
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;

    if (row < width && col < width) {
        float sum = 0.0f;
        for (int i = 0; i < width; ++i) {
            sum += A[row * width + i] * B[i * width + col];
        }
        C[row * width + col] = sum;
    }
}

int main() {
    const int width = 256; // 矩阵的大小
    const int size = width * width * sizeof(float);

    // 在主机上分配矩阵
    float *h_A = (float *)malloc(size);
    float *h_B = (float *)malloc(size);
    float *h_C = (float *)malloc(size);

    // 在设备上分配矩阵
    float *d_A, *d_B, *d_C;
    cudaMalloc((void **)&d_A, size);
    cudaMalloc((void **)&d_B, size);
    cudaMalloc((void **)&d_C, size);

    // 将数据从主机复制到设备
    cudaMemcpy(d_A, h_A, size, cudaMemcpyHostToDevice);
    cudaMemcpy(d_B, h_B, size, cudaMemcpyHostToDevice);

    // 定义网格和块大小
    dim3 blockSize(16, 16);
    dim3 gridSize((width + blockSize.x - 1) / blockSize.x, (width + blockSize.y - 1) / blockSize.y);

    // 调用 CUDA 内核
    matrixMul<<<gridSize, blockSize>>>(d_C, d_A, d_B, width);

    // 将结果从设备复制回主机
    cudaMemcpy(h_C, d_C, size, cudaMemcpyDeviceToHost);

    // 释放设备和主机内存
    cudaFree(d_A);
    cudaFree(d_B);
    cudaFree(d_C);
    free(h_A);
    free(h_B);
    free(h_C);

    return EXIT_SUCCESS;
}

```

单看 CUDA 内核函数的话，和 Compute Shader 如出一辙，所有 Thread 执行相同的程序，区别仅在于 Thread ID 不同。

## 七 Triton，XLA， TVM

Triton 矩阵乘法示例：

```python3
import torch
import triton
import triton.language as tl

@triton.jit
def simple_matmul_kernel(
    A, B, C,  # 输入/输出矩阵指针
    M, N, K,  # 矩阵维度
    BLOCK_SIZE: tl.constexpr,  # 分块大小
):
    # 获取当前线程块处理的输出位置 (i, j)
    pid = tl.program_id(axis=0)
    row = pid // (N // BLOCK_SIZE)
    col = pid % (N // BLOCK_SIZE)

    # 计算当前块的起始坐标
    rm = row * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    rn = col * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)

    # 初始化累加器
    acc = tl.zeros((BLOCK_SIZE, BLOCK_SIZE), dtype=tl.float32)

    # 分块计算
    for k in range(0, K, BLOCK_SIZE):
        a = tl.load(A + rm[:, None] * K + k)  # 加载 A 的块
        b = tl.load(B + k * N + rn[None, :])  # 加载 B 的块
        acc += tl.dot(a, b)  # 矩阵乘累加

    # 存储结果
    tl.store(C + rm[:, None] * N + rn[None, :], acc)

def simple_matmul(a: torch.Tensor, b: torch.Tensor):
    assert a.shape[1] == b.shape[0], "维度不匹配"
    M, K = a.shape
    K, N = b.shape
    c = torch.zeros((M, N), device=a.device, dtype=a.dtype)

    # 定义网格和块大小
    grid = lambda meta: (triton.cdiv(M, meta['BLOCK_SIZE']) * triton.cdiv(N, meta['BLOCK_SIZE']), )
    simple_matmul_kernel[grid](
        a, b, c, M, N, K, BLOCK_SIZE=32  # 分块大小设为32
    )
    return c

# 测试
a = torch.randn(64, 32, device='cuda')
b = torch.randn(32, 64, device='cuda')
c = simple_matmul(a, b)
print(c.shape)  # 输出: torch.Size([64, 64])
```

可以看到 Triton 内核函数是以 block 为单位的，即每次计算是以 block size 大小的 range 为单位的。
