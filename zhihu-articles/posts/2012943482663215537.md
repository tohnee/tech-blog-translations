参考文章 [大模型分布式训练并行技术（四）-张量并行](https://zhuanlan.zhihu.com/p/657921100) 图片也来自于这篇文章

在vllm中，张量并行分为两部分，给attn的和给gemm运算的，给gemm运算的又分为两部分，RowParallelLinear和ColumnParallelLinear，先看一下这个。

这里的行列都是对参数矩阵来说的，其实linear的参数层一直都比较混乱，在大部分情况下，它保存为(output_size, input_size), 计算是y=x W_T + b，当然W实际上不需要转置，gemm kernel是比较灵活的。

我们看一下基础的非量化gemm计算，包装为linear层：

注意这里是sum(output_partition_sizes) 和input_size_per_partition，这里涉及tp分割：

```text
            weight = Parameter(torch.empty(sum(output_partition_sizes),
                                           input_size_per_partition,
                                           dtype=params_dtype),
                               requires_grad=False)
```

进行计算时，会调用

```text
    def apply(self,
              layer: torch.nn.Module,
              x: torch.Tensor,
              bias: Optional[torch.Tensor] = None) -> torch.Tensor:

        return dispatch_unquantized_gemm()(layer, x, layer.weight, bias)
```

对于cuda,会走到这里：后续一般调用cublas进行计算。

```text
def default_unquantized_gemm(
    layer: torch.nn.Module,
    x: torch.Tensor,
    weight: torch.Tensor,
    bias: torch.Tensor | None = None,
):
    return torch.nn.functional.linear(x, weight, bias)
```

这里注意到维度是sum(output_partition_sizes)，output_partition_sizes是列表而不是一个值，有两种使用场景。一个是对于qkv的投影计算，往往是将它们合并成一个大矩阵运算：

```text
        self.output_sizes = [
            self.num_heads * self.head_size * tp_size,  # q_proj
            self.num_kv_heads * self.head_size * tp_size,  # k_proj
            self.num_kv_heads * self.head_size * tp_size,  # v_proj 
        ]
```

除了像qkv这种本身逻辑是分着的但是可以合着计算，MergedColumnParallelLinear和这个逻辑一样，gate_up_proj可以合并到一起。

上面和张量并行并没有太大关系，下面看下张量并行的逻辑，先看下RowParallelLinear

RowParallelLinear 里这个行是针对权重矩阵来说的，我认为这块有点乱是因为虽然说权重矩阵保存为(output_size, input_size)，但是它的行其实指的是input_size这一个维度，在切分时往往是将其看做(input_size, output_size)的，参考注释：

```text
    The linear layer is defined as Y = XA + b. A is parallelized along
    its first dimension and X along its second dimension as:
               -   -
              | A_1 |
              | .   |
          A = | .   |        X = [X_1, ..., X_p]
              | .   |
              | A_p |
               -   -
```

这里借用[大模型分布式训练并行技术（四）-张量并行](https://zhuanlan.zhihu.com/p/657921100) 的一张图片：观察下部，有多个结果矩阵(Y1 Y2)，每个结果矩阵的shape和最终结果矩阵(Y)shape是一样的，Y需要Y1和Y2再进行all reduce得到，也就是Y1 + Y2 = Y, 为什么是all reduce，因为每个rank都需要一个Y。

![](https://pica.zhimg.com/v2-39c136176eee46784a90919d672471a0_r.jpg)

这里再简单涉及一下rank的概念，在多级多卡场景，它们作为一个通信group，总是需要一些id之类的找准自己的位置，一般这个id就是rank，有几张卡就有多少个进程，就有多少个rank，GroupCoordinator就是管理这些信息的数据结构，其注释给了下面的例子：

```text
    # if we have a group of size 4 across two nodes:
    # Process | Node | Rank | Local Rank | Rank in Group
    #   0     |   0  |  0   |     0      |       0
    #   1     |   0  |  1   |     1      |       1
    #   2     |   1  |  2   |     0      |       2
    #   3     |   1  |  3   |     1      |       3
```

有这些rank，底层就知道一些任务是怎么处理了，比如让rank0给rank1发送数据，rank2接收rank3的数据之类的，rank就是id。

node是节点，一般情况下一个节点代表一个机器，local rank自然就是在单独一个机器上的“rank”了，不加local的话，默认rank是全局的。

GroupCoordinator 是一个通信group，注意的是给tp的group和给dp, ep，pp等都是不同的group，不同的并行方式可以有自己不同的通信group，它们的初始化都在initialize_model_parallel->init_model_parallel_group中：

```text
    _TP = init_model_parallel_group(group_ranks,
                                    get_world_group().local_rank,
                                    backend,
                                    use_message_queue_broadcaster=True,
                                    group_name="tp")

    _PP = init_model_parallel_group(group_ranks,
                                    get_world_group().local_rank,
                                    backend,
                                    group_name="pp")

    _DP = init_model_parallel_group(group_ranks,
                                    get_world_group().local_rank,
                                    backend,
                                    group_name="dp")
```

_TP 这种作为一个global数据结构，可以靠各自的获取方法调用：

```text
_TP: Optional[GroupCoordinator] = None

def get_tp_group() -> GroupCoordinator:
    assert _TP is not None, ("tensor model parallel group is not initialized")
    return _TP
```

然而GroupCoordinator也不是真正工作的地方，它会根据设备不同，调用不同的DeviceCommunicatorBase，对于cuda，就是CudaCommunicator

gpu上一般使用nccl后端，调用nccl的allreduce:

```text
    def all_reduce(self,
                   in_tensor: torch.Tensor,
                   out_tensor: torch.Tensor = None,
                   op: ReduceOp = ReduceOp.SUM,
                   stream=None) -> torch.Tensor:
        if self.disabled:
            return None
        # nccl communicator created on a specific device
        # will only work on tensors on the same device
        # otherwise it will cause "illegal memory access"
        assert in_tensor.device == self.device, (
            f"this nccl communicator is created to work on {self.device}, "
            f"but the input tensor is on {in_tensor.device}")

        if out_tensor is None:
            out_tensor = torch.empty_like(in_tensor)

        if stream is None:
            stream = current_stream()
        self.nccl.ncclAllReduce(buffer_type(in_tensor.data_ptr()),
                                buffer_type(out_tensor.data_ptr()),
                                in_tensor.numel(),
                                ncclDataTypeEnum.from_torch(in_tensor.dtype),
                                ncclRedOpTypeEnum.from_torch(op), self.comm,
                                cudaStream_t(stream.cuda_stream))
        return out_tensor
```

有了上面这些工程准备，最后的RowParallelLinear的allreduce就很简单了： 也就是运算完结果allreduce一下就行。

```text
        output_parallel = self.quant_method.apply(self, input_parallel, bias_)

        if self.reduce_results and self.tp_size > 1:
            output = tensor_model_parallel_all_reduce(output_parallel)
        else:
            output = output_parallel

def tensor_model_parallel_all_reduce(input_: torch.Tensor) -> torch.Tensor:
    """All-reduce the input tensor across model parallel group."""
    return get_tp_group().all_reduce(input_)
```

RowParallelLinear 是相对比较简单的，因为input和output大小是一致的，也就是Y1.shape == Y2.shape == Y.shape, shape[0] 是output_size， shape[1] 是input_size_per_partition， input_size_per_partition就是input_size // self.tp_size

```text
        self.input_size_per_partition = divide(input_size, self.tp_size)
        self.output_size_per_partition = output_size
        self.output_partition_sizes = [output_size]
```

这里有一个小细节，就是RowParallelLinear输入矩阵也是需要在input_size维度切分一下的，但是有时候不需要显示切分，这里后面说。

```text
        if self.input_is_parallel:
            input_parallel = input_
        else:
            splitted_input = split_tensor_along_last_dim(
                input_, num_partitions=self.tp_size)
            input_parallel = splitted_input[self.tp_rank].contiguous()
```

下面看一下ColumnParallelLinear，它的Y1和Y2，本身就是Y的一部分了，不需要再聚合，而是all gather ，通讯原语这部分参考[分布式训练中All-Reduce、All-Gather、Reduce-Scatter原理介绍](https://zhuanlan.zhihu.com/p/17201336684)

首先这个dist是pytorch的内容，一般最终还是以nccl做后端。看出来这里以比较多的tensor操作，这里的input_就是Y1或Y2。

```text
import torch.distributed as dist

    def all_gather(self, input_: torch.Tensor, dim: int = -1) -> torch.Tensor:
        if dim < 0:
            # Convert negative dim to positive.
            dim += input_.dim()
        input_size = input_.size()
        # NOTE: we have to use concat-style all-gather here,
        # stack-style all-gather has compatibility issues with
        # torch.compile . see https://github.com/pytorch/pytorch/issues/138795
        output_size = (input_size[0] * self.world_size, ) + input_size[1:]
        # Allocate output tensor.
        output_tensor = torch.empty(output_size,
                                    dtype=input_.dtype,
                                    device=input_.device)
        # All-gather.
        dist.all_gather_into_tensor(output_tensor,
                                    input_,
                                    group=self.device_group)
        # Reshape
        output_tensor = output_tensor.reshape((self.world_size, ) + input_size)
        output_tensor = output_tensor.movedim(0, dim)
        output_tensor = output_tensor.reshape(input_size[:dim] +
                                              (self.world_size *
                                               input_size[dim], ) +
                                              input_size[dim + 1:])
        return output_tensor
```

input_size[0] 是output_size_per_partition， input_size[1:]是input_size： 上面的input_size[0] * self.world_size， 就是得到了完整的output_size。

这里的命名比较乱，不过还好逻辑简单，output_size有时候当做shape, 有时候当做输出维度的大小，分场景理解吧。output_tensor 就是Y，Y1和Y2可以拼接成Y

```text
        self.input_size_per_partition = input_size
        self.output_size_per_partition = divide(output_size, self.tp_size)
        self.output_partition_sizes = [self.output_size_per_partition]
```

但是事实上，这里的all gather很少使用，为什么？因为vllm中往往是下面的形式：

首先通过ColumnParallelLinear，结果是Y1和Y2多个结果，这时候不需要进行all gather，而是直接将Y1 Y2作为已经分割好的输入，进行RowParallelLinear，这样我们就节省了一次all gather。

这里就涉及到我们上面提到的RowParallelLinear 的 input_is_parallel参数，默认是True，代表输入已经是分割好的Y1 Y2了，不需要再分割一次了。

相对的，ColumnParallelLinear的对应参数是gather_output，默认为False，代表不需要gather输出。

![](https://picx.zhimg.com/v2-2422b35d768dd9d0b2734ca4bd03076d_r.jpg)

我们看一个实际的例子，首先MergedColumnParallelLinear 就是ColumnParallelLinear的子类，类似qkv融合在一起计算，这里将gate和up放到一起计算了，注意到gather_output 和input_is_parallel全是默认，输出gate_up其实是已经分割过的，知道down_proj才聚合成完整的结果。

```text
class Qwen2MLP(nn.Module):

    def __init__(
        self,
        hidden_size: int,
        intermediate_size: int,
        hidden_act: str,
        quant_config: Optional[QuantizationConfig] = None,
        prefix: str = "",
    ) -> None:
        super().__init__()
        self.gate_up_proj = MergedColumnParallelLinear(
            hidden_size,
            [intermediate_size] * 2,
            bias=False,
            quant_config=quant_config,
            prefix=f"{prefix}.gate_up_proj",
        )
        self.down_proj = RowParallelLinear(
            intermediate_size,
            hidden_size,
            bias=False,
            quant_config=quant_config,
            prefix=f"{prefix}.down_proj",
        )
        if hidden_act != "silu":
            raise ValueError(f"Unsupported activation: {hidden_act}. "
                             "Only silu is supported for now.")
        self.act_fn = SiluAndMul()

    def forward(self, x):
        gate_up, _ = self.gate_up_proj(x)
        x = self.act_fn(gate_up)
        x, _ = self.down_proj(x)
        return x
```

除了在MLP处tp，tp也会用在attention层上，原理上基本是一致的，但是有一些小细节，最重要的是，要以head粒度分割。

之前我们使用ColumnParallelLinear时，self.output_size_per_partition = divide(output_size, self.tp_size) ，这是在基于输出维度互不影响的前提下，但是对于attn计算，我们必须考虑一下实际的逻辑意义，例如，两个头，每个头维度是128，把它分割成两个128没有问题，要是分割成127和129，MLP计算倒是无所谓，attn就没法计算了。

同时，考虑到很多模型是MQA, GQA之类的，我们要是把q分割了，它对应的kv应该如何分割？

看一下vllm的实现，total_num_heads 是q的头数，将其除tp_size，就是每个rank上q的头数num_heads，total_num_kv_heads是 k或v的头数，如果tp_size >= self.total_num_kv_heads，每个rank就留一个kv头，一个kv头会同时存在于num_kv_head_replicas个rank上。如果tp_size < self.total_num_kv_heads, 每个rank上有num_kv_heads个kv头，kv头不会重复。

最后计算output_size = (self.num_heads + 2 * self.num_kv_heads) * tp_size * self.head_size，剩下都是差不多的，QKVParallelLinear更多的是确定下head可以被分割整除开，剩下的仍然是ColumnParallelLinear的逻辑，至于整除不开？那就不管了。

```text
class QKVParallelLinear(ColumnParallelLinear):

    def __init__(
        self,
        hidden_size: int,
        head_size: int,
        total_num_heads: int,
        total_num_kv_heads: Optional[int] = None,
        bias: bool = True,
        skip_bias_add: bool = False,
        params_dtype: Optional[torch.dtype] = None,
        quant_config: Optional[QuantizationConfig] = None,
        prefix: str = "",
        *,
        return_bias: bool = True,
        disable_tp: bool = False,
    ):
        self.hidden_size = hidden_size
        self.head_size = head_size
        self.total_num_heads = total_num_heads
        if total_num_kv_heads is None:
            total_num_kv_heads = total_num_heads
        self.total_num_kv_heads = total_num_kv_heads
        # Divide the weight matrix along the last dimension.
        tp_size = (get_tensor_model_parallel_world_size()
                   if not disable_tp else 1)
        self.num_heads = divide(self.total_num_heads, tp_size)
        if tp_size >= self.total_num_kv_heads:
            self.num_kv_heads = 1
            self.num_kv_head_replicas = divide(tp_size,
                                               self.total_num_kv_heads)
        else:
            self.num_kv_heads = divide(self.total_num_kv_heads, tp_size)
            self.num_kv_head_replicas = 1
        input_size = self.hidden_size
        output_size = (self.num_heads +
                       2 * self.num_kv_heads) * tp_size * self.head_size
        self.output_sizes = [
            self.num_heads * self.head_size * tp_size,  # q_proj
            self.num_kv_heads * self.head_size * tp_size,  # k_proj
            self.num_kv_heads * self.head_size * tp_size,  # v_proj 
        ]
```

剩下该做什么做什么，qkv就是已经按头粒度分割的数据，它仍然保存了完整的部分qkv头，可以正常attn计算等，最后通过o_proj 这个RowParallelLinear再聚合起来。

```text
    def forward(
        self,
        positions: torch.Tensor,
        hidden_states: torch.Tensor,
    ) -> torch.Tensor:
        qkv, _ = self.qkv_proj(hidden_states)
        q, k, v = qkv.split([self.q_size, self.kv_size, self.kv_size], dim=-1)
        q, k = self.rotary_emb(positions, q, k)
        attn_output = self.attn(q, k, v)
        output, _ = self.o_proj(attn_output)
        return output
```

可以发现，tp的核心就是ColumnParallelLinear + RowParallelLinear，借助矩阵运算的特性，每个rank只需要保存部分参数，代价是多了一个all reduce, 单个需要传输的数据量，对于MLP来说，是tokens * hidden_size，对attn也是tokens * hidden_size，会发现没有intermediate_size 和 heads*head_dim 的事，中间维度再大也不需要传输数据，只需要传输最后的结果就可以了。

然而，受限于带宽，all reduce仍然是性能优化的一个大头，很多都设计了边传输边计算的方式，不知道现在有啥成熟的开源实现没。
