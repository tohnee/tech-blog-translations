### 1. 学习目标

读完并做完本文的 4 个 Lab，你应该能够:

1. **量化而不是感觉** —— 用可复现的脚本画出自己任务上的「步数 vs 成功率」衰减曲线，判断当前失败是 context rot、context overflow 还是 goal loss。
2. **拆解 harness** —— 说清 harness 的 5 个组成部分（仓库地图 / 运行时控制 / 清理循环 / 护栏 / 状态持久化），并能指出自己系统里缺哪一块。
3. **做 token 预算会计** —— 给 agent 循环加上上下文占用审计，知道每一轮里 system prompt、工具定义、历史消息、工具输出各占多少比例。
4. **实现目标锚定** —— 用 todo list + 计划重述 + 外部 verifier 三件套，把「目标丢失」从不可见故障变成可检测事件。
5. **跨会话续接** —— 设计一个可续写的状态文件契约，让第二个进程能在第一个进程崩溃后接着干，而不是重新摸索。

⚠️ 本文 **不** 教你怎么训练模型。所有手段都在模型之外的 harness 层。

### 3. 核心概念精讲

### 3.1 Context Rot（上下文腐烂）

**定义** : 任务本身不变，仅仅因为输入 token 变多，模型表现下降。

Chroma 2025 年 7 月的技术报告是这个词被广泛采用的起点。它测了 18 个前沿模型（含 GPT-4.1、Claude 4、Gemini 2.5、Qwen3），结论是 **没有一个模型例外** ，而且衰减发生在远未触及硬上下文上限的时候，即使任务极其简单。

报告里最值得记住的三个结构性发现:

- **不是均匀衰减** 。表现下降的形状是非线性的、跳跃的，不是一条平滑斜线。
- **needle-question 相似度决定衰减速度** 。当找到答案需要语义推理而非词面匹配时，衰减明显更快。标准 NIAH 基准用的是词面匹配，所以它 **低估** 了真实问题。
- **同一个问答对，仅因为周围堆了更多无关文本就变难了** 。这是「干扰物成本」，跟信息是否在窗口内无关。

> 📌 工程含义: 「装得进上下文窗口」和「模型能用上」是两件事。把 1M 窗口当成免费仓库是错的。

### 3.2 一个关键的反直觉结论: 是步数还是长度？

2026 年一项针对生产决策场景的长程 agent 实证研究给出了和 context rot 叙事不完全一致的结论: **衰减主要由步数（step count）驱动，而不是上下文长度** 。更刺眼的是，它报告限制上下文窗口反而让衰减 **更陡** （logit 斜率 −0.69 vs −0.44，p=3×10⁻⁶），作者据此反对把截断当成生产环境的省事方案。

另一条线的工作则报告 **阈值式崩塌** : 在某个临界长度附近，表现从 0.55~0.56 掉到 0.3（约 45.5% 的相对下降），即使所有信息都仍然相关。

三种曲线形状放在一起对比:

| 曲线形状 | 自变量 | 观察到的现象 | 对策方向 |
| --- | --- | --- | --- |
| 平滑 logit 衰减 | 步数 | 每多一步，成功对数几率线性下降 | 减少步数、提高单步信息密度 |
| 长度相关衰减 | 输入 token 数 | 干扰物越多越差，语义检索先崩 | 隔离无关内容、按需检索 |
| 阈值崩塌 | 输入 token 数 | 临界点附近断崖式下降 | 找到自己任务的临界点并停在它下方 |

⚠️ 这三条结论来自不同论文、不同任务族， **不要假设它们在你的任务上会同时成立** 。Lab 1 的存在就是为了让你测自己的那条曲线。

### 3.3 Harness: 模型周围的那套系统

一个常见的等式: **agent = 模型 + harness** 。harness 是把 LLM 和世界耦合起来的那层确定性运行时——它验证、授权、执行、记录模型提出的每一个动作。

OpenAI 在 2026 年 2 月把 “harness engineering” 提为一个范式，涵盖约束设计、反馈回路、文档结构、lint 规则、可观测性管线、生命周期管理。原报告里提到的三个词组，展开是这样:

| 组成 | 含义 | 最小实现 |
| --- | --- | --- |
| 仓库地图（repo map） | 让 agent 不靠遍历就知道代码在哪 | 预生成的符号索引 / 目录摘要，按需展开（progressive disclosure） |
| 运行时控制（runtime controls） | 轮次预算、超时、并发、审批门 | turn budget + token cap + graceful exit |
| 清理循环（cleanup loops） | 每步之后把上下文恢复到可持续状态 | 工具输出落盘换指针、周期性摘要、临时文件回收 |
| 护栏（guardrails） | 靠软件而非提示词措辞保证可靠性 | 写操作白名单、schema 校验、只读沙箱、动作日志 |
| 状态持久化 | 跨窗口/跨进程续接 | 外部状态文件 + 原子写 + 恢复协议 |

harness 的杠杆有多大，一个被反复引用的数字: 同一个模型在 SWE-bench 上，基础 scaffold 约 23%，优化到 250 轮的 scaffold 能到 45% 以上。⚠️ 这个对比来自工程博客的二手转述，不同 scaffold 的工具集和检索能力差异巨大， **不能当作干净的控制变量实验** 。

### 3.4 两类长任务失败模式

原报告点出朴素的「LLM + 工具 + 循环」会在两处崩溃。这里把它们展开成可检测的形式。

### (1) Context Overflow（上下文溢出）

**本质** : 工具输出超过单次能处理的 token 量。

关键特征是 **它不报错** 。agent 不会崩，它会静默截断数据、丢掉早期上下文、或者返回不完整结果。最常见的三个肇事者: 服务器日志、数据库结果集、整个文件内容。

| 表现 | 可观测信号 | 检测方法 |
| --- | --- | --- |
| 工具输出被静默截断 | 输出末尾无结构结束符 | 对比返回长度与声明长度 |
| 早期消息被挤出 | 模型忘了第 3 步的决定 | 记录每轮被驱逐的消息 id |
| 结果不完整但语气自信 | 「已处理全部文件」但只有 12⁄200 | 外部计数 verifier |
| 护栏看到的 ≠ 模型看到的 | 输入侧安检器自己也在截断 | 分别记录两侧 token 数 |

有一条容易被忽略的安全推论: 前置的安全检查器有自己更紧的上下文约束，它处理超长输入的方式也是截断或分段，于是 **护栏检查的内容和模型实际推理的内容不一致** 。

### (2) Goal Loss / Goal Drift（目标丢失与目标漂移）

**本质** : agent 仍在合法地调用工具，但已经不在做你要求的事，或者提前宣布完成。

这类失败的共同性质是: **无法从单次输出判断** 。你必须有跨步的参照物。

| 子类型 | 具体表现 | 检测方法 |
| --- | --- | --- |
| 提前终止 | 要 20 条，交了 7 条就宣布完成 | 外部 verifier 数「不同的有效条目」 |
| 承诺漂移（commitment drift） | 违反自己第 4 步立下的约束 | 把约束抽成显式列表，每轮校验 |
| 绑定漂移（binding drift） | 术语/变量指代对象悄悄换了 | 关键实体绑定表 + 一致性检查 |
| 退化循环 | 同一动作反复调用无进展 | 动作签名去重 + 无进展计数器 |
| 层级丢失 | 「这一步是为哪个目标服务」答不出 | todo 项带 parent goal id |

学术上最可操作的定义是 **Quantitative Goal Persistence (QGP)** : agent 是否持续工作直到 **外部 verifier** 确认已经拿到足够多的不同有效条目。这个设计的价值在于把漂移从「主观判断」变成「对可核查目标的提前终止」。

> ⚠️ 诚实说明: 现有工作基本都是 **事后** 通过 verifier 失败来推断漂移， **运行中实时检测** 仍是空白。Lab 3 里的做法是工程近似，不是论文级方法。

### 3.5 三类现象的对照表

| 维度 | Context Rot | Context Overflow | Goal Loss |
| --- | --- | --- | --- |
| 触发条件 | token 增多 / 步数增多 | 单次输出超限 | 长程 + 多子目标 |
| 是否报错 | 否 | 否（静默截断） | 否 |
| 典型症状 | 答案变模糊、放弃、给不确定答案 | 数据不全但语气自信 | 提前完成、违反自设约束 |
| 检测手段 | 分档对比实验 | token 会计 + 长度断言 | 外部 verifier + 约束校验 |
| 主要对策 | 上下文管理、并行采样、隔离检索 | 指针化、分页、落盘 | 目标锚定、计划重述、todo 层级 |
| 对策的反面 | ❌ 粗暴截断（可能更糟） | ❌ 摘要（丢完整性） | ❌ 在 prompt 里多写「别忘了目标」 |

关于对策，长程搜索场景的研究测过两种缓解: **上下文管理** 和 **事后拒绝采样 / 并行采样** 。另一条线（自适应压缩）报告在数学任务上比无摘要基线高出最多 18.1 分、agentic search 上 5~9 分，同时 per-question 成本低 30~70%。⚠️ 后者是单篇论文的自报结果，未见独立复现。

4 个 Lab 递进: 先测量 → 再会计 → 再锚定 → 最后续接。

### Lab 1: 画出你自己的衰减曲线

**目标** : 不相信任何论文的数字，测出 **你的任务** 上步数和上下文长度各自的影响。

**设计要点** : 要区分「步数效应」和「长度效应」，必须让它们 **解耦** 。做法是构造一个固定难度的可验证任务，然后用两个独立旋钮控制: 注入的无关文本量（长度旋钮）、强制的最小工具调用次数（步数旋钮）。

```python
# lab1_decay_curve.py
# 依赖: pip install openai tiktoken
#   （换成 anthropic SDK 也行，只需改 call_model）
# 环境变量: OPENAI_API_KEY

import itertools, json, os, random, statistics
from dataclasses import dataclass, field, asdict

import tiktoken
from openai import OpenAI

MODEL = "gpt-4.1-mini"          # 换成你实际用的模型
ENC = tiktoken.get_encoding("cl100k_base")
client = OpenAI()

# ---------- 可验证的固定难度任务 ----------
# 在一堆记录里找出满足条件的 id 并求和。答案唯一、可程序化校验。
def make_task(seed: int, n_records: int = 40):
    rng = random.Random(seed)
    records = [{"id": i, "dept": rng.choice(["eng", "ops", "sales"]),
                "cost": rng.randint(10, 999)} for i in range(n_records)]
    target = sum(r["cost"] for r in records if r["dept"] == "ops")
    return records, target

# ---------- 长度旋钮: 注入语义相关但无用的干扰文本 ----------
# 注意: 干扰物要"语义接近"才有意义。纯 lorem ipsum 会低估 rot。
DISTRACTOR = (
    "内部备注: 上季度 ops 团队的预算复核已归档, 相关成本条目不纳入本次统计。"
    "财务口径调整说明见附件, 历史 cost 字段含税, 已于上期完成对齐。"
)

def pad(tokens_wanted: int) -> str:
    if tokens_wanted <= 0:
        return ""
    unit = len(ENC.encode(DISTRACTOR))
    return "\n".join([DISTRACTOR] * max(1, tokens_wanted // unit))

# ---------- 步数旋钮: 强制多轮工具调用 ----------
# 用一个"必须逐页读取"的假工具, pages 越多, 步数越多, 但信息总量不变。
def paginate(records, pages: int):
    size = max(1, len(records) // pages)
    return [records[i:i + size] for i in range(0, len(records), size)]

@dataclass
class Trial:
    pad_tokens: int
    steps: int
    seed: int
    ok: bool = False
    used_steps: int = 0
    prompt_tokens: int = 0

def call_model(messages, tools=None):
    kwargs = {"model": MODEL, "messages": messages}
    if tools:
        kwargs["tools"] = tools
        kwargs["tool_choice"] = "auto"
    return client.chat.completions.create(**kwargs)

TOOLS = [{
    "type": "function",
    "function": {
        "name": "read_page",
        "description": "读取一页记录。必须逐页读完所有页才能回答。",
        "parameters": {"type": "object",
                       "properties": {"page": {"type": "integer"}},
                       "required": ["page"]},
    },
}]

def run_trial(pad_tokens: int, steps: int, seed: int) -> Trial:
    records, target = make_task(seed)
    pages = paginate(records, steps)
    t = Trial(pad_tokens=pad_tokens, steps=steps, seed=seed)

    sys = ("你是数据分析 agent。用 read_page 逐页读取, 共 %d 页 (page 从 0 开始)。"
           "读完所有页后, 只输出 dept 为 ops 的所有 cost 之和, 格式: ANSWER=<整数>\n\n"
           "参考材料:\n%s") % (len(pages), pad(pad_tokens))
    messages = [{"role": "system", "content": sys},
                {"role": "user", "content": "开始统计。"}]

    for _ in range(len(pages) + 6):          # 留一点余量, 超出即判失败
        resp = call_model(messages, TOOLS)
        msg = resp.choices[0].message
        t.prompt_tokens = max(t.prompt_tokens, resp.usage.prompt_tokens)
        messages.append(msg.model_dump(exclude_none=True))

        if msg.tool_calls:
            for tc in msg.tool_calls:
                t.used_steps += 1
                p = json.loads(tc.function.arguments).get("page", 0)
                payload = pages[p] if 0 <= p < len(pages) else []
                messages.append({"role": "tool", "tool_call_id": tc.id,
                                 "content": json.dumps(payload, ensure_ascii=False)})
            continue

        text = msg.content or ""
        if "ANSWER=" in text:
            try:
                t.ok = int(text.split("ANSWER=")[1].strip().split()[0]) == target
            except (ValueError, IndexError):
                t.ok = False
            return t
    return t

if __name__ == "__main__":
    # 2x2x... 网格: 长度旋钮 x 步数旋钮, 每格多个 seed 求平均
    PAD = [0, 4_000, 16_000, 64_000]
    STEPS = [2, 5, 10, 20]
    SEEDS = range(5)                          # 生产上请用 20+, 方差很大

    rows = []
    for pad_t, st in itertools.product(PAD, STEPS):
        trials = [run_trial(pad_t, st, s) for s in SEEDS]
        rate = statistics.mean(1.0 if x.ok else 0.0 for x in trials)
        rows.append({"pad": pad_t, "steps": st, "pass_rate": round(rate, 3),
                     "avg_prompt_tokens": int(statistics.mean(
                         x.prompt_tokens for x in trials))})
        print(rows[-1])

    with open("lab1_results.json", "w") as f:
        json.dump(rows, f, indent=2)
```

**预期观察结果** :

- `pad=0` 那一列: 成功率随 steps 单调下降。这是 **纯步数效应** ，因为信息量完全没变。
- `steps=2` 那一行: 成功率随 pad 下降，并且 `pad=64_000` 掉得比线性预期更多。这是 **长度效应 + 干扰物成本** 。
- 最差的格子是右下角（长 + 多步），而且通常 **比两个效应各自的乘积还差** 。这就是超线性衰减。
- 失败的形态值得单独看: 你会看到模型 **提前给答案** （少读几页就下结论）而不是报错。这正是 3.4 节说的静默失败。
- 如果你把干扰物换成 lorem ipsum，衰减会明显变轻——这验证了 Chroma 关于「语义相似度影响衰减速度」的结论。

### Lab 2: 给循环装上 token 预算会计

**目标** : 回答「这一轮 128k 上下文里，到底谁吃掉了多少」，并在触线前主动处置而不是等截断。

核心原则一句话: **上下文里的每个 token 都要挣得它的位置** 。

```python
# lab2_budget.py
# 依赖: pip install tiktoken
# 纯本地, 不调 API。可以直接接到 Lab 1 的循环里。

from dataclasses import dataclass, field
from enum import Enum
import json

import tiktoken

ENC = tiktoken.get_encoding("cl100k_base")

def ntok(x) -> int:
    if not isinstance(x, str):
        x = json.dumps(x, ensure_ascii=False)
    return len(ENC.encode(x))

class Bucket(str, Enum):
    SYSTEM = "system_prompt"
    TOOLDEF = "tool_definitions"
    HISTORY = "assistant_history"
    TOOLOUT = "tool_outputs"
    USER = "user_turns"

@dataclass
class Budget:
    limit: int                      # 模型硬上限
    reserve_output: int = 8_000     # 给输出留的空间
    warn_ratio: float = 0.70        # 触发清理的水位
    hard_ratio: float = 0.85        # 触发强制降级的水位

    @property
    def usable(self) -> int:
        return self.limit - self.reserve_output

@dataclass
class Audit:
    budget: Budget
    by_bucket: dict = field(default_factory=dict)
    truncation_events: int = 0
    evicted_ids: list = field(default_factory=list)

    def measure(self, system: str, tooldefs: list, messages: list) -> dict:
        b = {k.value: 0 for k in Bucket}
        b[Bucket.SYSTEM.value] = ntok(system)
        b[Bucket.TOOLDEF.value] = ntok(tooldefs)
        for m in messages:
            role = m.get("role")
            if role == "tool":
                b[Bucket.TOOLOUT.value] += ntok(m.get("content", ""))
            elif role == "user":
                b[Bucket.USER.value] += ntok(m.get("content", ""))
            else:
                b[Bucket.HISTORY.value] += ntok(m)
        self.by_bucket = b
        return b

    @property
    def total(self) -> int:
        return sum(self.by_bucket.values())

    @property
    def utilization(self) -> float:
        return self.total / self.budget.usable

    def state(self) -> str:
        u = self.utilization
        if u >= self.budget.hard_ratio:
            return "HARD"
        if u >= self.budget.warn_ratio:
            return "WARN"
        return "OK"

    def report(self) -> str:
        lines = [f"total={self.total} usable={self.budget.usable} "
                 f"util={self.utilization:.1%} state={self.state()}"]
        for k, v in sorted(self.by_bucket.items(), key=lambda kv: -kv[1]):
            share = v / max(1, self.total)
            lines.append(f"  {k:<20} {v:>8} tok  {share:>6.1%} "
                         f"{'#' * int(share * 40)}")
        return "\n".join(lines)
```

现在是关键的一半: **超限时不要截断，要指针化** 。把大工具输出落盘，上下文里只留摘要 + 一个可再次取回的句柄。

```python
# lab2_budget.py (续)
import hashlib, os, pathlib

STORE = pathlib.Path("./.agent_blobs")
STORE.mkdir(exist_ok=True)

INLINE_MAX = 1_200          # 超过这个 token 数就落盘

def stow(content: str) -> dict:
    """把大输出落盘, 返回给模型看的指针 + 摘要。"""
    h = hashlib.sha256(content.encode()).hexdigest()[:12]
    path = STORE / f"{h}.txt"
    path.write_text(content)
    lines = content.splitlines()
    return {
        "ref": h,
        "bytes": len(content),
        "lines": len(lines),
        "head": "\n".join(lines[:15]),
        "tail": "\n".join(lines[-5:]),
        "hint": f"用 fetch_ref(ref='{h}', start=, end=) 读取任意区间, 全文未丢失",
    }

def fetch_ref(ref: str, start: int = 0, end: int = 200) -> str:
    """模型可调用的工具: 按行区间取回。这是 overflow 的正解。"""
    lines = (STORE / f"{ref}.txt").read_text().splitlines()
    return "\n".join(lines[start:end])

def wrap_tool_output(content: str) -> str:
    if ntok(content) <= INLINE_MAX:
        return content
    return json.dumps(stow(content), ensure_ascii=False)

# ---------- 水位处置策略 ----------
def enforce(audit: Audit, messages: list) -> list:
    """WARN: 把最老的大 tool 输出指针化。HARD: 只保留骨架。"""
    st = audit.state()
    if st == "OK":
        return messages

    for m in messages:
        if m.get("role") == "tool" and ntok(m.get("content", "")) > INLINE_MAX:
            m["content"] = wrap_tool_output(m["content"])
            audit.truncation_events += 0        # 注意: 这不是截断, 信息未丢
            if st == "WARN":
                break                           # WARN 时一次只处置一条
    return messages

if __name__ == "__main__":
    tooldefs = [{"name": "read_page", "description": "x" * 400}]
    msgs = [
        {"role": "user", "content": "统计 ops 成本"},
        {"role": "assistant", "content": "我先读第 0 页"},
        {"role": "tool", "content": "LOG LINE\n" * 5000},   # 故意的巨型输出
        {"role": "assistant", "content": "继续"},
    ]
    a = Audit(Budget(limit=128_000))
    a.measure("你是分析 agent", tooldefs, msgs)
    print(a.report())
    print("--- 处置后 ---")
    msgs = enforce(a, msgs)
    a.measure("你是分析 agent", tooldefs, msgs)
    print(a.report())
```

- 第一份报告里 `tool_outputs` 会占到 95% 以上， `state=HARD` 。 **这是绝大多数真实 agent 的实际分布** ，第一次看到自己的直方图通常都会意外。
- 处置后 util 从 HARD 掉回 OK，但注意 `truncation_events` 仍是 0 —— 因为全文在磁盘上，模型可以用 `fetch_ref` 拿回任意区间。这是「指针化」和「截断」的本质区别。
- 把 `INLINE_MAX` 调大到 50_000 再跑，你会看到 util 重新爆掉。这条线的位置就是你需要调的旋钮。
- 接到 Lab 1 的循环里跑一遍: 成功率通常会回升，但 **不会回到 pad=0 的水平** ，因为步数效应没被解决。

### Lab 3: 目标锚定与漂移检测

**目标** : 实现 todo list + 计划重述 + 外部 verifier，让「提前完成」和「违反自设约束」变成可捕获的事件。

三个设计决定，每个都对应 3.4 节的一个子类型:

1. **todo 项带 `parent_goal` 字段** —— 平铺 todo 会丢层级，于是「这一步为哪个目标服务」永远答不出。
2. **约束抽成显式列表，每轮校验** —— 对付承诺漂移。
3. **停止条件交给外部 verifier，不给模型** —— 这是 QGP 的核心思想: 模型说完成了不算完成。

```python
# lab3_goal_anchor.py
# 纯标准库。可与 Lab 1/2 组合。

import json, time
from dataclasses import dataclass, field, asdict
from typing import Callable, Optional

@dataclass
class Todo:
    id: str
    text: str
    parent_goal: str                 # 关键: 保住层级
    status: str = "pending"          # pending | in_progress | done | blocked
    evidence: Optional[str] = None   # done 必须有证据, 否则不算 done

@dataclass
class Constraint:
    id: str
    text: str
    source_step: int                 # 第几步立下的
    check: Optional[str] = None      # 可选的程序化校验表达式

@dataclass
class GoalState:
    goal: str                        # 原始目标, 逐字保留, 永不改写
    success_criteria: str            # 可核查的完成标准
    todos: list = field(default_factory=list)
    constraints: list = field(default_factory=list)
    step: int = 0
    action_signatures: list = field(default_factory=list)

    # ---------- 计划重述 ----------
    def restate(self, max_todos: int = 8) -> str:
        """每轮注入的目标锚。刻意放在消息序列末尾: 近端位置最不易被忽略。"""
        open_todos = [t for t in self.todos if t.status != "done"][:max_todos]
        done_n = sum(1 for t in self.todos if t.status == "done")
        parts = [
            "=== 目标锚定 (每轮重述, 请勿改写原始目标) ===",
            f"原始目标: {self.goal}",
            f"完成标准: {self.success_criteria}",
            f"进度: {done_n}/{len(self.todos)} 已完成, 当前第 {self.step} 步",
        ]
        if self.constraints:
            parts.append("必须遵守的约束 (你自己在前面步骤立下的):")
            parts += [f"  - [C{c.id} @step{c.source_step}] {c.text}"
                      for c in self.constraints]
        parts.append("待办 (每项标注它服务的目标):")
        parts += [f"  - [{t.id}] {t.text}  → 服务于: {t.parent_goal}"
                  for t in open_todos]
        parts.append("规则: 只有外部校验通过才算完成, 不要自行宣布完成。")
        return "\n".join(parts)

class DriftDetector:
    """工程近似的漂移检测。⚠️ 不是论文级方法, 见 3.4 节说明。"""

    def __init__(self, state: GoalState, no_progress_limit: int = 3):
        self.s = state
        self.no_progress_limit = no_progress_limit
        self.no_progress = 0
        self.findings: list = []

    def _flag(self, kind: str, detail: str):
        self.findings.append({"step": self.s.step, "kind": kind,
                              "detail": detail, "ts": time.time()})

    # (1) 提前终止: 模型宣布完成, 但 verifier 不同意
    def check_premature_stop(self, claims_done: bool,
                             verifier: Callable[[], tuple]) -> bool:
        if not claims_done:
            return False
        ok, detail = verifier()
        if not ok:
            self._flag("premature_stop", f"模型宣称完成, verifier 拒绝: {detail}")
            return True
        return False

    # (2) 退化循环: 相同动作签名重复且无新的 done
    def check_degenerate_loop(self, signature: str, done_count: int) -> bool:
        prev_done = getattr(self, "_prev_done", -1)
        self._prev_done = done_count
        if signature in self.s.action_signatures[-4:] and done_count == prev_done:
            self.no_progress += 1
        else:
            self.no_progress = 0
        self.s.action_signatures.append(signature)
        if self.no_progress >= self.no_progress_limit:
            self._flag("degenerate_loop", f"动作 {signature} 重复无进展")
            return True
        return False

    # (3) 约束违反: 对有程序化 check 的约束逐条跑
    def check_constraints(self, world: dict) -> list:
        violated = []
        for c in self.s.constraints:
            if not c.check:
                continue
            try:
                if not eval(c.check, {"__builtins__": {}}, dict(world)):  # noqa: S307
                    violated.append(c)
                    self._flag("constraint_violation", f"C{c.id}: {c.text}")
            except Exception as e:      # 约束本身写错了也要知道
                self._flag("constraint_error", f"C{c.id} 无法求值: {e}")
        return violated

    # (4) done 无证据: 最常见的自欺
    def check_unevidenced_done(self) -> list:
        bad = [t for t in self.s.todos if t.status == "done" and not t.evidence]
        for t in bad:
            self._flag("unevidenced_done", f"{t.id} 标记完成但无证据")
        return bad

# ---------- 外部 verifier: QGP 风格的计数停止条件 ----------
def make_count_verifier(collected: list, required: int,
                        is_valid: Callable[[object], bool]):
    """停止条件掌握在 harness 手里, 不交给模型。"""
    def verify():
        distinct = {json.dumps(x, sort_keys=True, ensure_ascii=False)
                    for x in collected if is_valid(x)}
        n = len(distinct)
        return (n >= required,
                f"有效且互不相同的条目 {n}/{required}")
    return verify
```

### Lab 4: 跨会话续接（状态文件契约）

**目标** : 让进程 B 在进程 A 崩溃后接着干，而不是重新摸索。

关键概念是 **handoff debt（交接债务）** : agent 看起来有进展，但留下的状态后继者无法接续——无解释的改动、散落的临时文件、隐含假设、缺失的验证证据。交接产物要当成 **有契约的交付物** ，而不是一条进度备注。

一个被多个项目采用的轻量三件套是 `BOOT.md` + `STATE.json` + `NEXT.md` : 分别承载「怎么启动」「机器可读的事实」「下一步做什么」。下面实现它的最小可用版本，重点在 **原子写** 和 **恢复协议** 。

```python
# lab4_handoff.py
# 纯标准库。演示: 原子写、恢复、交接契约校验。

import json, os, pathlib, tempfile, time, uuid
from dataclasses import dataclass, field, asdict

ROOT = pathlib.Path("./.agent_session")
ROOT.mkdir(exist_ok=True)
STATE = ROOT / "STATE.json"
NEXT = ROOT / "NEXT.md"

def atomic_write(path: pathlib.Path, data: str):
    """崩溃安全: 先写临时文件再 rename。直接 open('w') 会在崩溃时留下半截文件。"""
    fd, tmp = tempfile.mkstemp(dir=str(path.parent))
    try:
        with os.fdopen(fd, "w") as f:
            f.write(data)
            f.flush()
            os.fsync(f.fileno())
        os.replace(tmp, path)          # POSIX 上是原子的
    finally:
        if os.path.exists(tmp):
            os.unlink(tmp)
# lab4_handoff.py (续)

@dataclass
class Handoff:
    """交接契约。每个字段的存在都是为了消掉一类 handoff debt。"""
    session_id: str
    goal: str                                   # 逐字的原始目标
    success_criteria: str
    phase: str                                  # 当前阶段
    step: int
    verified_facts: list = field(default_factory=list)   # 已验证, 不必重做
    open_questions: list = field(default_factory=list)   # 未解决的
    assumptions: list = field(default_factory=list)      # 隐含假设显性化
    artifacts: list = field(default_factory=list)        # 产出文件路径
    validation_evidence: list = field(default_factory=list)  # 怎么证明它对
    next_actions: list = field(default_factory=list)
    blocked_by: list = field(default_factory=list)
    updated_at: float = field(default_factory=time.time)

    # ---------- 契约校验: 不满足就不许交接 ----------
    REQUIRED = ("goal", "success_criteria", "phase", "next_actions")

    def validate(self) -> list:
        errs = []
        for f in self.REQUIRED:
            if not getattr(self, f):
                errs.append(f"缺少必填字段: {f}")
        if self.artifacts and not self.validation_evidence:
            errs.append("有产出物但无验证证据 (典型 handoff debt)")
        if self.step > 0 and not self.verified_facts:
            errs.append("已执行多步但无已验证事实, 后继者会重复劳动")
        return errs

    def save(self):
        errs = self.validate()
        if errs:
            raise ValueError("交接契约不满足: " + "; ".join(errs))
        self.updated_at = time.time()
        atomic_write(STATE, json.dumps(asdict(self), ensure_ascii=False, indent=2))
        atomic_write(NEXT, self.to_next_md())

    def to_next_md(self) -> str:
        def lst(xs):
            return "\n".join(f"- {x}" for x in xs) or "- (无)"
        return f"""# NEXT — session {self.session_id}

## 原始目标 (勿改写)
{self.goal}

## 完成标准
{self.success_criteria}

## 当前位置
阶段 `{self.phase}`, 第 {self.step} 步

## 已验证的事实 (不要重做)
{lst(self.verified_facts)}

## 显性假设 (可能是错的, 优先质疑)
{lst(self.assumptions)}

## 未解决的问题
{lst(self.open_questions)}

## 产出物
{lst(self.artifacts)}

## 验证证据
{lst(self.validation_evidence)}

## 下一步动作
{lst(self.next_actions)}

## 阻塞
{lst(self.blocked_by)}
"""

    @classmethod
    def resume(cls) -> "Handoff | None":
        """恢复协议: 读不到或读坏了都要能安全降级。"""
        if not STATE.exists():
            return None
        try:
            return cls(**json.loads(STATE.read_text()))
        except (json.JSONDecodeError, TypeError) as e:
            print(f"[warn] 状态文件损坏, 需人工介入: {e}")
            return None

def bootstrap_prompt(h: Handoff) -> str:
    """新进程的开场上下文。注意: 不回放历史消息, 只给结论。"""
    return (
        "你正在接续一个未完成的任务。以下是上一个会话留下的交接文件。\n"
        "规则: 已验证的事实不要重做; 显性假设要先质疑; 从下一步动作开始。\n\n"
        + h.to_next_md()
    )

if __name__ == "__main__":
    h = Handoff.resume()
    if h is None:
        print("=== 无状态, 新建会话 ===")
        h = Handoff(
            session_id=uuid.uuid4().hex[:8],
            goal="把 ingest 服务的 p99 延迟从 1.8s 降到 500ms 以下",

            next_actions=["对 ingest 热路径做 CPU profile"],
        )
        h.verified_facts = ["p99 瓶颈在 JSON 反序列化, 占 62% CPU (py-spy 采样 300s)"]
        h.assumptions = ["假设流量分布与上周一致 —— 未验证"]
        h.artifacts = ["./profiles/ingest-20260925.svg"]
        h.validation_evidence = ["py-spy 火焰图 + 3 次独立采样一致"]
        h.step = 4
        h.next_actions = ["用 orjson 替换 stdlib json, 本地基准对比",
                          "确认 orjson 对 NaN 的行为与现有契约兼容"]
        h.save()
        print("已写入, 再运行一次本脚本即可看到续接。")
    else:
        print("=== 续接已有会话 ===")
        print(bootstrap_prompt(h))

    # 反例: 演示契约拒绝
    bad = Handoff(session_id="x", goal="g", success_criteria="c",
                  phase="p", step=9, next_actions=["a"],
                  artifacts=["out.txt"])
    print("\n契约校验拒绝的原因:", bad.validate())
```

**预期观察结果** :

- 第一次运行创建状态， **第二次运行** 打印出完整的 bootstrap 上下文。这就是续接: 新进程从结论开始，而不是从原始历史开始。
- `bootstrap_prompt` 的 token 数通常只有原会话的 2~5%。这是 Lab 1 里步数效应的直接解药——续接会话的 **步数计数器归零** 了。
- 反例会报两条: 有产出物无验证证据、多步无已验证事实。这两条是最高频的 handoff debt 形态。
- 把 `save()` 调用放进循环里每 N 步执行一次，然后在中途 `kill -9` 。你会发现 `STATE.json` 永远是完整的 JSON——这是 `os.replace` 的功劳。直接 `open('w')` 写会在这个测试里留下半截文件。

📌 一个重要的判断准则: **compaction 适合在一条线程里继续，跨越边界时应该干净重启** 。里程碑完成、阶段切换、或者发现漂移时，从显式文件重启比无限 compaction 更可靠。因为 compaction 是有损的，损失会累积；从文件重启的损失是一次性的、可审查的。

### 5. 常见陷阱

### 陷阱 1: 把截断当成 context rot 的解药

**为什么错** : 直觉上上下文越短越好，所以超限就砍掉最老的消息。但生产场景的实证研究报告， **限制上下文窗口让衰减变得更陡** （logit 斜率 −0.69 vs −0.44）。作者明确把这当成反对把截断作为生产捷径的证据。而且截断是静默的: 模型不知道它丢了什么，于是会基于残缺信息自信作答。

**怎么改** : 用 Lab 2 的指针化。落盘 + 摘要 + 可取回句柄，让「不在上下文里」和「不可获得」分开。需要完整输出的工作流，摘要和截断都会失败。

### 陷阱 2: 在 prompt 里写「不要忘记目标」来治目标漂移

**为什么错** : 目标漂移是长程状态管理问题，不是措辞问题。提示词里的告诫在第 3 步有效，在第 80 步会被淹没在干扰物里——这正是 Chroma 报告的干扰物成本。可靠性要靠软件护栏，不是提示词措辞。

**怎么改** : 三件事。(a) 每轮机械地重述目标并放在消息序列 **末尾** ；(b) 停止条件交给外部 verifier，模型没有宣布完成的权力；© 约束写成可执行校验。见 Lab 3。

### 陷阱 3: 平铺的 todo list

**为什么错** : 扁平的 todo 项丢掉了层级，于是「这一项服务于哪个目标」永远恢复不出来。第 40 步时 agent 在勤奋地做一件与主目标已经无关的事，而 todo list 看起来一切正常。同样的问题还有: 会话笔记跨重启就蒸发了；外部 kanban 和 agent 的推理是断开的；厂商提供的 memory 记住的是事实，不是 **意图** 。

**怎么改** : todo 项带 `parent_goal` ，重述时一起打印。区分「事实记忆」和「意图记忆」——后者包括目标、决策、承诺。

### 陷阱 4: 用标准 NIAH 结果给自己的长上下文能力背书

**为什么错** : 标准 Needle-in-a-Haystack 用的是词面匹配，因此系统性地 **低估** 问题。Chroma 的报告专门针对这点: 当 needle 和 question 的相似度低、需要语义推理才能取回时，衰减明显更快。你的真实任务几乎总是低相似度的那一类。而且真实应用比这些受控设置复杂得多，实际影响只会更明显。

**怎么改** : 自己造语义 NIAH 变体——干扰物要 **语义接近** 目标信息（像 Lab 1 里那段「ops 预算已归档，不纳入统计」的备注），而不是随机文本。用你自己任务的数据分布。

### 陷阱 5: 让模型自己决定什么时候完成

**为什么错** : 这是最贵的一类失败，因为它 **看起来是成功** 。agent 做了一堆局部合理的工具调用，然后宣布完成，而实际条目数远未达标。你的监控看到的是「任务成功」，用户看到的是结果不全。这类失败无法从单次输出判断，必须有跨步参照物。

**怎么改** : QGP 模式——停止条件是「外部 verifier 确认拿到了足够多的 **不同的有效** 条目」。三个词都重要: 外部、不同、有效。Lab 3 的 `make_count_verifier` 是最小实现。

### 陷阱 6: 护栏放在模型前面但自己也会截断

**为什么错** : 输入侧的安全检查器有自己更紧的上下文约束，处理超长输入时它也会截断或分段。结果是 **护栏检查的内容 ≠ 模型推理的内容** 。一段恶意指令可以恰好落在检查器截断之后、模型上下文之内。

**怎么改** : 分别记录两侧的 token 数并断言相等；检查器超限时 **拒绝请求** 而不是截断放行（fail closed 而非 fail open）；对分段检查要确认分段边界不会切断需要整体判断的模式。

### 陷阱 7: 没有轮次预算和优雅退出

**为什么错** : ReAct 的 happy path（推理 → 调工具 → 观察 → 重复）在生产环境不够用。模型无限循环怎么办、token 成本超预算怎么办、输出格式一直不对怎么办，都需要答案。一份跨 21 个编排框架、2023 到 2026 年的目录收录了 **63 起已确认的生产预算超支事故** ，每起都有 GitHub issue 加维护者或用户陈述佐证，部分附有金额损失。

**怎么改** : turn budget + token cap + 明确的退出原因码。退出时 **必须** 写出交接状态（Lab 4），否则超支之后你还得从零重来。把 `exit_reason` 作为一个必须上报的指标。

### 陷阱 8: 把 compaction 当成无限续命手段

**为什么错** : compaction 是有损的，而损失会累积。第 5 次 compaction 之后，第 1 次就丢掉的那个约束已经无从恢复。上下文被当成静态产物、靠原始累积或被动摘要来管理时，早期的错误或错位的重点会一直保留下去。

**怎么改** : 设边界。里程碑完成、阶段切换、检测到漂移时，从显式状态文件干净重启。判据是: compaction 用于 **同一阶段内** 延长；跨阶段用重启。另外考虑主动式管理——在检测到错位或退化时 **重组** 工作上下文，而不是只做被动摘要。

### 陷阱 9: 只看终局成功率，不看过程指标

**为什么错** : 终局 pass/fail 掩盖了所有可操作的信息。同样 60% 的成功率，可能是「稳定地在第 15 步卡住」或者「随机分布的偶发失败」，两者的修复动作完全不同。可观测性上被点名的具体缺口就是 **无法监控上下文窗口被使用的效率** ，导致 token 浪费、截断和检索配置次优。

**怎么改** : 至少上报这 5 个: 每轮 token 数、上下文按来源的成分构成、上下文利用率、截断事件计数、轮次/预算触顶次数及退出原因。Lab 2 的 `Audit.report()` 覆盖了前四个。

### 一致性风险提示

1. **步数 vs 长度的矛盾没有解决。** 「限制窗口使衰减更陡」与「输入越长表现越差」看似冲突，可能都对（不同机制、不同任务族），也可能其中一个的实验设计有问题。本文采取的立场是: **不站队，让你在 Lab 1 里测自己的** 。
2. **arXiv 标识符与日期存在不一致。** 检索结果中同一篇论文出现过不同的年份标注。正式引用前请到 arXiv 核对标识符与发表场所。
3. **本文所有 Lab 代码未在真实 API 上跑过完整网格。** 代码是按文中逻辑写的、结构完整可读，但「预期观察结果」是基于上述文献推断的 **预测** ，不是我实测的数字。跑出来和预测不一致时，相信你自己的数据。
4. **Lab 3 的漂移检测是工程近似。** 现有研究基本都是通过 verifier 事后失败来推断漂移， **运行中对原始目标的连续检测在文献里仍是空白** 。不要把 `DriftDetector` 当成有理论保证的方法。
