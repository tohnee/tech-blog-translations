## FlashAttention + PagedAttention 源码精读

### 一、FlashAttention

### 问题：标准 Attention 为什么慢？

```text
# 标准 Attention: O(n²) 显存 + 多次 HBM 读写
def standard_attention(Q, K, V):          # Q,K,V: [seq, dim]
    S = Q @ K.T                            # [seq, seq] → 写入 HBM (大!)
    P = softmax(S, dim=-1)                 # 读 S → 写 P → HBM 来回
    O = P @ V                              # 读 P,V → 写 O → HBM 来回
    return O

# 问题: 如果 seq=2048, dim=128:
#   S = [2048, 2048] × 2 bytes = 8MB
#   每个 head 都要写 8MB → 12 heads × 28 层 = 2.7GB HBM 写
```

### FlashAttention 的 3 个核心思想

**1. Tiling (分块)**

```text
Q: [seq, d]   K: [seq, d]   V: [seq, d]

不要一次算完整 S:
  把 Q 切成 Q_blocks [Br, d]  (Br << seq)
  把 K,V 切成 blocks [Bc, d]  (Bc << seq)

  外层循环 Q_blocks:
    内层循环 K/V_blocks:
      只算一个 block 的 attention
      → 中间结果全程在 SRAM (128KB) 中，不写 HBM
```

**2. Online Softmax (关键!)**

```text
标准 softmax:
  m = max(S)           ← 需要完整 S
  exp_S = exp(S - m)   ← 需要完整 S
  sum = Σ exp_S         ← 需要完整 S
  P = exp_S / sum

Online softmax (一边算一边更新):
  处理 K block 0:
    m_old = -∞, sum_old = 0
    S_block_0 = Q_block @ K_block_0^T     → [Br, Bc]
    m_new = max(m_old, max(S_block_0))
    sum_new = sum_old * exp(m_old - m_new) + Σ exp(S_block_0 - m_new)
    O = O * sum_old/sum_new * exp(m_old - m_new) + exp(S_block_0 - m_new)/sum_new @ V_block_0
    m_old = m_new, sum_old = sum_new

  处理 K block 1:
    同样的公式，用上次的 m_old, sum_old, O 继续累加
  
→ 不需要保存完整 S, 不需要等所有 block 算完
→ 常数量级 SRAM (O(Br × Bc) 而非 O(seq²))
```

**3. Kernel Fusion**

```text
标准方法: 3 个 kernel
  Kernel 1: Q @ K^T → 写 S 到 HBM
  Kernel 2: softmax(S) → 读 S, 写 P 到 HBM
  Kernel 3: P @ V → 读 P, 写 O 到 HBM

FlashAttention: 1 个 kernel
  Q,K,V 从 HBM 读 → [在 SRAM 中 tiling + online softmax + matmul] → O 写回 HBM

节省: 2 次巨大的 HBM 读写 (S 和 P 不存到 HBM)
```

### 二、PagedAttention

### 问题：传统 KV Cache 浪费显存

```text
传统 KV Cache (连续分配):
  seq1: [K1][K2]...[K2048]          ← 预分配 2048 tokens 空间
  seq2: [K1]...[K2048]               ← 即使 seq2 只有 100 tokens
  seq3: [K1]...[K2048]               ← 也要预留满

浪费: (2048 - 实际长度) × 2(K,V) × head_dim × heads × layers
     短序列浪费 > 50% 显存
```

### PagedAttention 的虚拟内存类比

```text
OS 虚拟内存:                     PagedAttention:
  物理页框 (4KB)                   KV Block (16 tokens)
  页表 (虚拟→物理)                  Block Table
  缺页中断 → 分配新页               Request → allocate new block
  换页 (swap)                       Prefix caching (共享前缀)
```

### 推理时的 Block Table

```text
请求 A: "今天天气怎么样"  → 5 tokens → 需要 1 个 block (16 tokens 容量)

  Block Table: [block_5]  ← 引用 block 5

  GPU 上的 KV Cache:
    Block 5: [K_0, K_1, K_2, K_3, K_4, 0, 0, ..., 0,  V_0, ..., V_4, 0, ...]
             └─ 有效 ─┘  └─ 预分配但未使用 ─┘

请求 A 继续生成 "今天天气真好":
  6 tokens → 还是 1 个 block (block_5 有 16 个 slot)
  
  生成到第 17 个 token:
  需要新 block → allocate → block_12
  Block Table: [block_5, block_12]

FlashAttention 计算时:
  for block_id in block_table:       ← 按顺序遍历
      K_block = load_block(block_id)
      V_block = load_block(block_id)
      partial_attn(Q, K_block, V_block)
```

### 为什么省显存

```text
1536 个请求，每个 < 16 tokens:
  传统: 1536 × 2048 tokens × 28.7KB = 90 GB → 不可能!
  PagedAttention: 1536 × 1 block × 16 tokens × 28.7KB = 672 MB ✓

Prefix caching:
  请求 A: "请用中文解释..."
  请求 B: "请用中文翻译..."
  共同前缀 "请用中文" → 共享同一个 block → ref_cnt = 2
```

### vLLM 中的关键 kernel

```text
# model_runner.py: compute_slot_mapping()
# 把逻辑位置 (req_id, token_pos) 映射到物理位置 (block_id, block_offset)

def compute_slot_mapping(block_table, seq_lens):
    slot_mapping = []
    for req_id in range(num_reqs):
        for pos in range(seq_lens[req_id]):
            block_idx = pos // 16
            block_offset = pos % 16
            physical_block = block_table[req_id][block_idx]
            slot_mapping.append(physical_block * 16 + block_offset)
    return slot_mapping
```

> “FlashAttention 解决了标准 Attention 的 O(n²) 显存问题。核心三个点: tiling 把 Q 分块，和 K/V 逐块计算；online softmax 让每块可以增量更新，不需要等所有块算完； kernel fusion 把 QK^T、softmax、PV 三个操作合并成一个 kernel，中间结果不写 HBM。<br> PagedAttention 把 OS 的虚拟内存思想用到 KV Cache 上。KV 不存连续数组，存成固定大小的 block， 用 block table 做逻辑到物理的映射。好处是零内部碎片，不同请求的短序列不用预留满 2048 长度， 还可以共享前缀的 block。vLLM 用这个把并发数从几十个提到了几百个。”
