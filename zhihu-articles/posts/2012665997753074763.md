### **简介**

LM Studio 是一款支持在本地运行 AI 大模型的工具，支持 Mac、Linux 和 Windows 全平台。和 Ollama 不同，LM Studio 自带一个漂亮的图形界面，入门门槛极低——下载、搜索模型、点击运行，三步搞定。

![](https://picx.zhimg.com/v2-261526e98bf95949cc2fc6b2d1201bd1_r.jpg)
*LM Studio 主界面*

目前支持的主流模型相当多：gpt-oss、Qwen3、Gemma 3、DeepSeek 等等，基本上 Hugging Face 上热门的 GGUF 和 MLX 模型都能跑。

### **0.4 版本：全面进化**

1 月，LM Studio 发布了 0.4.0 大版本更新，这不是一个小修小补的版本，而是一次架构级的重构。

核心变化有四个：

![](https://pic1.zhimg.com/v2-92281c143d4af5b0fe8cf54b8f34d8ec_r.jpg)
*llmster 无头部署模式*

**1. llmster：无 GUI 的守护进程**

这是 0.4 最炸裂的更新。LM Studio 把 GUI 和核心推理引擎拆开了，推出了 `llmster` —— 一个可以脱离桌面界面独立运行的守护进程

什么意思？就是你现在可以把 LM Studio 的核心部署到**任何没有图形界面的机器上**：云服务器、GPU 算力机、CI/CD 流水线、甚至 Google Colab。

安装一行命令搞定：

```text
# Linux / Mac
curl -fsSL https://lmstudio.ai/install.sh | bash

# Windows
irm https://lmstudio.ai/install.ps1 | iex

```

启动也很简单：

```text
lms daemon up         # 启动守护进程
lms get        # 下载模型
lms server start      # 启动本地 API 服务器
lms chat              # 打开交互式聊天

```

这意味着什么？意味着你家里那台 4090 机器可以当 API 服务器用了，不需要开桌面、不需要一直盯着屏幕。`llmster` + `lms` CLI，就是一套完整的无头部署方案。

**2. 并行请求 + 连续批处理**

之前 LM Studio 同时只能处理一个请求，后面的排队

0.4 之后，基于 llama.cpp 2.0 的连续批处理实现，支持同一模型的多个并发推理请求

加载模型时有两个新选项：

- **Max Concurrent Predictions**：设置最大并发请求数（默认 4）
- **Unified KV Cache**：统一 KV 缓存，硬件资源不会按请求硬分区，几乎不增加内存开销

对于需要对外提供 API 服务的场景，这个能力直接让 LM Studio 从"玩具"变成了"生产工具"

**3. 全新的有状态 REST API：`/v1/chat`**

这个端点和传统的 Chat Completions 不一样。`/v1/chat` 是**有状态的**：你发一条消息，会拿到一个 `response_id`，下次请求把 `previous_response_id` 带上就能继续对话。

这样的好处是：

- 每次请求体很小，不用来回传整个聊天记录
- 方便构建多步骤工作流
- 响应自带 token 统计和速度数据（tokens in/out、首 token 时间等）
- 还能通过 permission keys 访问本地 MCP 工具

**4. UI 大刷新**

聊天导出（PDF/Markdown/纯文本）、分屏视图、Developer Mode、应用内文档——这些都是锦上添花，但确实让整个用户体验上了一个台阶。

### **核心：LM Studio 不为人知的开发者用法**

好，下面进入今天的重头戏

大部分人只把 LM Studio 当个聊天工具，但它其实提供了一整套开发者生态

### **用法一：OpenAI 兼容 API —— 不改代码，换个 URL 就行**

这是我觉得最实用的功能之一

LM Studio 提供了完整的 OpenAI 兼容端点：

| 端点 | 功能 |
| --- | --- |
| /v1/models | 列出可用模型 |
| /v1/responses | Responses API（Codex 也用这个） |
| /v1/chat/completions | 传统的 Chat Completions |
| /v1/embeddings | 文本嵌入 |
| /v1/completions | 文本补全 |

啥意思呢？**你现在用 OpenAI SDK 跑的代码，只需要改一行 base_url，就能切到本地模型**

Python 示例：

```text
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:1234/v1"
)

response = client.chat.completions.create(
    model="use the model identifier from LM Studio here",
    messages=[{"role": "user", "content": "Say this is a test!"}],
    temperature=0.7
)

```

TypeScript 示例：

```text
import OpenAI from 'openai';

const client = new OpenAI({
    baseUrl: "http://localhost:1234/v1"
});

```

cURL 也一样：

```text
curl http://localhost:1234/v1/chat/completions \\
  -H "Content-Type: application/json" \\
  -d '{
    "model": "openai/gpt-oss-20b",
    "messages": [{"role": "user", "content": "Hello!"}],
    "temperature": 0.7
  }'

```

这对开发者来说太友好了

你写好的 Agent、RAG 应用、AI 工作流，测试阶段完全可以用本地模型跑，零成本。上线时再切回 OpenAI 或 DeepSeek 的 API

甚至连 OpenAI 的 Codex 都支持直接对接 LM Studio

### **用法二：Anthropic 兼容 API —— Claude Code 也能白嫖**

这个就更骚了。从 0.4.1 开始，LM Studio 还提供了 **Anthropic 兼容的 `/v1/messages` 端点**。

什么意思？Claude Code 不需要用 Anthropic 的 API Key 了，直接指向 LM Studio 就行！

三步搞定：

**第一步**：启动 LM Studio 的本地服务器

```text
lms server start --port 1234

```

**第二步**：设置环境变量

```text
export ANTHROPIC_BASE_URL=http://localhost:1234
export ANTHROPIC_AUTH_TOKEN=lmstudio

```

**第三步**：运行 Claude Code

```text
claude --model openai/gpt-oss-20b

```

![](https://pic2.zhimg.com/v2-fcea3f6b765fbeb59807dfac2d0feb21_r.jpg)
*Claude Code 配合 LM Studio 使用*

就这么简单。你用本地的 GGUF 或 MLX 模型，就能驱动 Claude Code

建议上下文窗口设到 25K tokens 以上，因为 Claude Code 消耗上下文比较猛

如果你在 VS Code 里用 Claude Code，也可以直接在设置里配：

```text
"claudeCode.environmentVariables": [
    {
        "name": "ANTHROPIC_BASE_URL",
        "value": "http://localhost:1234"
    },
    {
        "name": "ANTHROPIC_AUTH_TOKEN",
        "value": "lmstudio"
    }
]

```

支持的功能也很完整：Messages API、SSE 流式传输、Tool Use 都能用

用 Anthropic 的 Python SDK 也可以直接对接：

```text
from anthropic import Anthropic

client = Anthropic(
    base_url="http://localhost:1234",
    api_key="lmstudio",
)

message = client.messages.create(
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "Hello from LM Studio"}
    ],
    model="ibm/granite-4-micro",
)
print(message.content)

```

同时兼容 OpenAI 和 Anthropic 两大 API，这在本地部署工具里几乎是独一份

### **用法三：CLI 工具 `lms` —— 命令行控的福音**

LM Studio 自带命令行工具 `lms`，从 0.2.22 版本就有了。但到了 0.4，CLI 的体验完全焕然一新

安装很简单，会随 LM Studio 桌面端或 `llmster` 一起安装

```text
npx lmstudio install-cli

```

常用命令速查：

```text
lms status          # 检查 LM Studio 状态
lms server start    # 启动 API 服务器
lms server stop     # 停止 API 服务器
lms ls              # 列出已下载模型
lms ls --json       # JSON 格式输出（适合脚本处理）
lms ps              # 查看当前加载的模型
lms load     # 加载模型
lms load  -y # 最大 GPU 加速加载，跳过确认
lms unload --all    # 卸载所有模型
lms get      # 下载模型
lms chat            # 交互式聊天（新！）
lms create          # 创建 SDK 项目
lms log stream      # 实时查看日志
lms runtime survey  # 打印 GPU 信息
lms runtime update llama.cpp  # 更新推理引擎

```

重点说下 `lms chat`，0.4 新增的命令。

直接在终端里开聊，支持斜杠命令、思考过程高亮、粘贴大段内容。可用的斜杠命令：`/model`、`/download`、`/system-prompt`、`/help`、`/exit`

对于喜欢 Terminal 的同学来说，完全不需要打开图形界面就能完成下载模型 → 加载模型 → 聊天 → 调试 的全部流程。

### **用法四：原生 SDK —— TypeScript 和 Python 都安排了**

除了兼容 OpenAI/Anthropic 的 API，LM Studio 还提供了自己的原生 SDK

**TypeScript SDK**：

```text
npm install @lmstudio/sdk

import { LMStudioClient } from "@lmstudio/sdk";

const client = new LMStudioClient();
const model = await client.llm.model("openai/gpt-oss-20b");
const result = await model.respond("Who are you, and what can you do?");
console.info(result.content);

```

**Python SDK**：

```text
pip install lmstudio

import lmstudio as lms

with lms.Client() as client:
    model = client.llm.model("openai/gpt-oss-20b")
    result = model.respond("Who are you, and what can you do?")
    print(result)

```

原生 SDK 的好处是能力更全面：除了聊天和文本生成，还支持 Tool Calling、MCP 支持、结构化输出（JSON Schema）、Embedding 和 Tokenization、模型管理（加载、下载、列表）等高级功能

**LM Studio 的 REST API**：

```text
lms server start --port 1234

curl http://localhost:1234/api/v1/chat \\
  -H "Content-Type: application/json" \\
  -H "Authorization: Bearer $LM_API_TOKEN" \\
  -d '{
    "model": "openai/gpt-oss-20b",
    "input": "Who are you, and what can you do?"
  }'

```

### **用法五：LM Link —— 远程加载你的模型**

这是 LM Studio 最新推出的功能，目前还在 Preview 阶段，但思路很超前

![](https://picx.zhimg.com/v2-1c1c025ccb5768705944ff1591207e41_r.jpg)
*LM Link 设备连接示意*

LM Link 的核心思想：**你可能有好几台机器（家里的 GPU 机器、公司显卡、云服务器），LM Link 让你在任何一台设备上，像使用本地模型一样使用远程设备上的模型。**

- 基于 **Tailscale** 的 mesh VPN，端到端加密，不暴露公网端口
- 聊天数据保留在本地，重活累活交给远端的 GPU
- 连你的 `localhost:1234` 接口都通用——也就是说 Codex、Claude Code、OpenCode 这些工具也能通过 LM Link 使用远程模型

价格方面，免费版支持 2 个用户、每人 5 台设备（总共 10 台），家用和工作都可以

这个功能对多机用户太香了

**比如你家里放一台 4090 算力机，上班时用 MacBook 通过 LM Link 无缝调用家里的模型**

---

说实话，如果你只是想快速跑个模型聊天，Ollama 的 `ollama run` 确实更简单。但如果你有以下需求，LM Studio 更合适：

- 需要同时兼容 OpenAI 和 Anthropic 两套 API
- 多台机器之间共享模型资源
- 需要有状态的 REST API + MCP 工具调用
- 想用原生 SDK 做开发

### **总结**

LM Studio 在 0.4 之后，已经不是一个简单的"本地聊天工具"了。它是一个完整的本地 AI 推理平台：

- 桌面端给新手用，CLI + llmster 给开发者用
- OpenAI + Anthropic 双兼容，几乎所有 AI 开发工具都能无缝对接
- LM Link 打通多设备，远程模型像本地一样用
- 有状态 API + MCP + SDK，想怎么玩就怎么玩
