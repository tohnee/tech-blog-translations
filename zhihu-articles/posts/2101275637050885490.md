前面聊了 MCP 是什么，这次直接动手，给助手接两个工具：一个用来读写本地文件，一个用来联网搜索。

最后我们让它做件具体的事：查一下今天的天气，把结果整理成一份 Markdown 文件，保存到电脑上。跑通这个过程，也就知道 MCP Server 该怎么接了。

### 先选一个支持 MCP 的客户端

接入 MCP Server，需要有个支持 MCP 的应用来使用它，这类应用通常叫 **MCP Host**。常见的有下面几种：

| 客户端 | 平时怎么用 |
| --- | --- |
| Cursor | 在编辑器里写代码，通过 MCP 接入外部工具和数据源。 |
| VS Code + Cline | 给 VS Code 装上 Cline 扩展，再按需要添加 MCP Server。 |
| Claude Desktop | 在桌面聊天客户端里接入工具、读取资源，不一定非得写代码。 |

这篇用 **VS Code + Cline** 来演示。Cline 扩展本身免费、开源，不过模型 API 和外部服务可能收费，这几笔费用要分开看。

### 一、先把 Cline 用起来

### 1. 安装 VS Code 和 Cline

还没装 VS Code 的话，先去[官网下载](https://code.visualstudio.com/)，选自己系统对应的安装包。

装好之后，按下面这条路径操作：

```text
打开 VS Code
  → 点击左侧“扩展”图标，也可以按 Ctrl + Shift + X
  → 搜索 Cline
  → 找到发布者为 Cline 的扩展
  → 点击 Install
  → 如果提示重载或重启扩展，按提示操作
```

搜索结果里可能有汉化版或其他衍生版本。为了方便对照，这里先用官方 Cline，扩展标识是 `saoudrizwan.claude-dev`。

安装完成后，左侧活动栏会出现 Cline 的机器人图标，点开就能进入对话面板。

### 2. 配好大模型

Cline 需要连接一个大模型才能工作。点击面板右上角的齿轮，进入模型设置。

如果你用的是阿里云百炼，可以通过 OpenAI 兼容接口接入。下面以中国内地地域的兼容接口为例：

| 设置项 | 填什么 |
| --- | --- |
| API Provider | OpenAI Compatible |
| Base URL | [https://dashscope.aliyuncs.com/compatible-mode/v1](https://dashscope.aliyuncs.com/compatible-mode/v1) |
| API Key | 自己在百炼控制台申请的模型 API Key |
| Model ID | 例如 qwen-plus，以账号实际可调用的模型为准 |

如果账号使用的是其他地域，Base URL 要跟着换，别把不同地域的地址和 Key 混用。用其他模型服务也一样，按服务商提供的地址、密钥和模型名填写。

保存设置后，先发一句简单的问题：

> 你能帮我做哪些事？简单介绍一下。

能正常收到回复，说明模型连接基本没问题。先过这一关，再配 MCP，出了问题也好判断是哪一层没接上。

顺便说一句，Cline 本来就带有读写文件、执行命令等工具，不是接了 MCP 才能干活。我们接 MCP，是为了继续补充它的能力，比如接一个搜索服务，或者用一套指定的文件工具。

### 二、准备 Node.js 环境

下面用到的两个 MCP Server 都通过 `npx` 启动，所以要先安装 Node.js。

去 [Node.js 官网](https://nodejs.org/)安装满足这些服务要求的 LTS 版本即可；Tavily 当前的本地运行说明要求 Node.js 20 或以上。安装 Node.js 时通常会一起装好 `npm` 和 `npx`。装完后重新打开终端；如果 VS Code 之前一直开着，也重启一下，让它拿到更新后的环境变量。

在 Windows 的命令提示符里执行：

```bat
node -v
npm -v
npx -v
```

三个命令都能输出版本号，就说明这些命令已经能找到了，不必和别人电脑上的版本号完全一致。如果在 PowerShell 里遇到 `npm.ps1` 或 `npx.ps1` 的执行策略报错，可以改用 `npm.cmd -v`、`npx.cmd -v` 检查，不用急着修改系统执行策略。

这里别弄混：**stdio 只是通信方式，不代表 MCP Server 必须用 Node.js 开发。** 服务也可以用 Python、Java 等语言实现，具体装什么环境，要看它自己的说明。

### 三、接入一个文件操作工具

先接文件工具，效果比较直观：让助手往指定文件夹里写一份文件，打开就能看到结果。

### 1. 在哪里找 MCP Server？

点击 Cline 面板顶部的 MCP Servers 图标，通常是一个像服务器堆叠起来的图标。带有 Marketplace 的版本，可以在市场里搜索 `File System`。

这个工具提供的能力包括：

- 读取、写入和编辑文件。
- 列出目录、查找文件。
- 创建目录、移动文件等。

对应的项目说明在这里：[Filesystem MCP Server](https://github.com/modelcontextprotocol/servers/tree/main/src/filesystem)。

市场里的 Install 按钮很方便，但有些安装过程会让模型阅读文档，再生成命令去执行。这个过程不一定每次都顺利，尤其是本地终端和模型预想的不一样时。

比如，它可能生成这样的命令：

```powershell
cd C:\mcp-work\filesystem-server && npx @modelcontextprotocol/create-server filesystem
```

这里有两个地方值得留意：

- `&&` 能不能用，取决于终端。Windows PowerShell 5.1 不支持这种写法，PowerShell 7 和 cmd 则支持，不能笼统地说 Windows 都不支持。
- `@modelcontextprotocol/create-server` 是创建服务项目的脚手架，不是我们要接入的现成文件服务。我们要用的包是 `@modelcontextprotocol/server-filesystem`，没必要先创建一个项目。

所以这次直接按项目文档手动配置。要启动什么、能访问哪个目录，都能看得清楚，也省得让模型来回试命令。

### 2. 打开 MCP 配置文件

在 Cline 的 MCP Servers 页面找到 **Configure MCP Servers**。常见的界面入口是：

```text
Cline → MCP Servers → Installed → Configure MCP Servers
```

有些新版会把入口放在 **Configure** 标签页下。按钮位置可能变，找到它打开的 MCP 配置文件就行，通常名为 `cline_mcp_settings.json`。

注意，这不是 VS Code 的普通 `settings.json`。第一次打开时，内容可能只有：

```json
{
  "mcpServers": {}
}
```

如果里面已经有其他服务，保留原有内容，把新服务加到同一个 `mcpServers` 对象下，不要直接全部覆盖。

### 3. 写入文件服务配置

先在本地建一个专门用于演示的文件夹，例如 `C:/mcp-demo`，也建议在 VS Code 中打开这个文件夹作为演示工作区。下面通过启动参数指定这个目录，没必要一上来就开放整个桌面或磁盘。

Windows 下，可以用下面这份配置：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "cmd",
      "args": [
        "/c",
        "npx",
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "C:/mcp-demo"
      ],
      "disabled": false,
      "autoApprove": []
    }
  }
}
```

这几项其实不复杂：

| 配置项 | 作用 |
| --- | --- |
| filesystem | 这个服务在 Cline 里的名字，可以自定义。 |
| command | 启动程序。这里通过 Windows 的 cmd 执行命令。 |
| args | 传给启动程序的参数，按数组顺序排列。 |
| /c | 让 cmd 执行后面的命令。 |
| npx -y | 运行指定的 npm 包；-y 用来跳过 npx 自己的安装确认。 |
| @modelcontextprotocol/server-filesystem | 文件操作 MCP Server 的包名。 |
| C:/mcp-demo | 允许这个文件服务访问的目录，需要提前建好。 |
| disabled: false | 启用这个服务。 |
| autoApprove: [] | 不在此配置中指定自动批准的工具；演示时也先关掉界面里的 MCP 自动批准。 |

Windows 下的 `npx` 通常由 `.cmd` 脚本提供，通过 `cmd /c` 启动可以避开一些客户端直接启动时的兼容问题，不是说所有客户端都只能这么写。

macOS、Linux 一般可以直接把 `command` 设成 `npx`，同时去掉参数开头的 `/c` 和 `npx`，并把目录换成自己机器上的绝对路径。

JSON 里的 Windows 路径建议像示例这样用 `/`。如果用反斜杠，要写成 `C:\\mcp-demo`。另外，JSON 不能夹带 `//` 注释，也别多留逗号。

还有一点：新版 filesystem 服务支持 MCP Roots。如果客户端提供了 Roots，服务会用它更新允许访问的目录，而不只是使用启动参数。连接后要核对实际目录范围，可以调用服务提供的 `list_allowed_directories` 工具查看。这些限制只针对 filesystem 服务，不会顺带限制 Cline 的内置文件工具，更不等于给整个助手加了系统级沙箱。

### 4. 确认服务真的连上了

保存配置后，Cline 通常会尝试启动并连接服务。第一次运行时，npx 可能要下载依赖，需要能访问 npm 仓库，稍微等一下。

连接正常后，应该能在服务列表里看到 `filesystem` 处于已连接状态，并能查看它提供的工具。有些版本会用绿色圆点表示连接成功。

有些版本还会出现这样一条提示：

```text
Client does not support MCP Roots, using allowed directories set from server args
```

它的意思是：客户端不支持通过 MCP Roots 提供目录范围，服务改用启动参数里指定的目录。对于上面的示例，就是使用 `C:/mcp-demo`。确认目录正确、服务已连接且工具可用后，这条提示本身不代表连接失败。

但不是所有红字都能忽略。找不到命令、目录不存在、进程退出或连接断开，仍然要看日志排查。

### 四、再接一个联网搜索工具

文件工具有了，再加上搜索，就能把“查资料”和“保存结果”连起来。这次用 Tavily。

先打开 [Tavily 控制台](https://app.tavily.com/home)，注册并登录，在 **API Keys** 区域创建或复制自己的 Key。控制台里也能看到用量和套餐，具体额度以账号页面为准。

接着回到刚才的 MCP 配置文件，在 `mcpServers` 下增加 `tavily-search`。加完后，完整配置如下：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "cmd",
      "args": [
        "/c",
        "npx",
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "C:/mcp-demo"
      ],
      "disabled": false,
      "autoApprove": []
    },
    "tavily-search": {
      "command": "cmd",
      "args": [
        "/c",
        "npx",
        "-y",
        "tavily-mcp"
      ],
      "env": {
        "TAVILY_API_KEY": "替换成你自己的 Tavily API Key"
      },
      "disabled": false,
      "autoApprove": []
    }
  }
}
```

`env` 是传给这个服务进程的环境变量。把 `TAVILY_API_KEY` 的值换成真正的密钥后再保存；这个 Key 和前面配置模型用的 Key 不是一回事。

真实密钥别发进聊天记录、截图或代码仓库。这里是在演示本地配置，也要注意保护这个文件。

配置保存后，确认两个服务都已连接，搜索工具也已经出现在列表中。Tavily 的其他接入方式可以看[项目说明](https://github.com/tavily-ai/tavily-mcp)，这里先把本地 stdio 方式跑通。

### 五、让它搜索一次，再把结果写进文件

回到对话界面，新建一个任务。要让 Cline 实际执行工具，需要处于可执行任务的 Act 模式，而不是只讨论方案的 Plan 模式。

可以这样提问：

> 请使用 tavily-search 里的搜索工具，查一下杭州今天的天气，标明具体日期，整理天气概况、温度和出门建议，并附上来源链接。然后使用 filesystem 的文件工具，把结果保存到 C:/mcp-demo/杭州天气.md，再读回文件确认内容。如果查不到可靠的当天信息，就在文件里说明，不要猜。这个任务不要用内置文件工具或终端命令代替 MCP 工具。

为什么把要求写得这么细？因为 Cline 自带文件工具。如果只说“保存到电脑上”，它可能直接调用内置工具，文件虽然生成了，却没有验证到刚配好的 filesystem 服务。

正常情况下，你能在执行记录里看到类似的过程：

```text
收到任务
  → 调用 Tavily 的搜索工具，查询杭州当天的天气
  → 根据搜索结果整理内容，保留日期和来源
  → 调用 filesystem 的写入工具，创建杭州天气.md
  → 调用 filesystem 的读取工具，核对文件内容
  → 回复文件保存位置
```

具体工具名、调用次数和顺序可能随版本、模型而变化。有些模型会先检查目录，有些会补搜一次，重点是确认搜索和文件操作确实走了对应的 MCP Server。

执行中如果弹出授权请求，先看看它准备搜什么、写到哪里、写入什么内容，再批准。尤其是覆盖已有文件时，别不看就点同意。

任务结束后，打开 `C:/mcp-demo`，检查有没有 `杭州天气.md`，再打开看看内容。文件可以按下面的结构组织，这里只是格式示意，不是实时天气结果：

```text
# 杭州天气

## 查询日期
写明本次查询对应的具体日期。

## 天气概况
整理搜索结果中的天气、温度等信息；没有查到的部分注明缺失。

## 出门建议
根据查到的天气给出简短建议。

## 信息来源
列出本次实际采用的网页标题和链接。
```

天气这种信息有时效性，搜到网页不代表内容一定是今天的，日期和来源还得核对。我们这里主要验证接入流程，不能把“工具成功调用”直接当成“结果一定准确”。

如果两个服务都参与了调用，文件也确实写入、读回成功，这次接入就算跑通了。整个过程中，我们没有自己写搜索接口，也没有自己实现文件操作方法，用的是已经做好的 MCP Server。

### 六、还有哪些地方能找 MCP Server？

后面想接数据库、代码仓库或其他业务系统，可以先看看有没有现成的服务。

找工具这件事，和 Java 开发时去 Maven 仓库找依赖有点像：不必每次都从零写起。不过，MCP 生态里的入口并不都一样，有的是源码仓库，有的是工具目录或托管市场，不是一个统一的依赖仓库。

下面整理了一些常见入口，方便直接打开：

| 名称 | 地址 | 可以看什么 |
| --- | --- | --- |
| MCP 官方服务器仓库 | modelcontextprotocol/servers | 参考实现和服务索引，本文的 filesystem 就在这里。 |
| Awesome MCP Servers | punkpeye/awesome-mcp-servers | 社区整理的 MCP Server 清单。 |
| GitHub MCP Server | github/github-mcp-server | GitHub 自己的 MCP Server 项目，不是综合工具市场。 |
| Cline MCP 市场 | cline.bot/mcp-marketplace | 查找可供 Cline 接入的服务。 |
| [http://mcpservers.org](http://mcpservers.org) | [http://mcpservers.org](http://mcpservers.org) | 浏览不同用途的 MCP Server。 |
| 阿里云百炼 | 百炼控制台 | 从控制台查找 MCP 服务相关入口。 |
| Cursor Directory | cursor.directory/mcp | 社区整理的 MCP 资源，不等于 Cursor 官方仓库。 |
| Smithery | smithery.ai | 查找 MCP Server 及其接入说明。 |
| mcp.so | mcp.so | 按分类查找社区服务。 |
| Glama | glama.ai/mcp/servers | 查看 MCP Server 集合和介绍。 |
| Portkey MCP Servers | portkey.ai/mcp-servers | 浏览 MCP Server 相关资源。 |
| ModelScope 社区 | [http://modelscope.cn/mcp](http://modelscope.cn/mcp) | 查找社区提供的 MCP 服务。 |

这些入口收录的服务，维护情况、权限要求和收费方式不一定相同。找到之后，先看项目来源、最近的维护记录、启动方式，以及它需要访问什么数据，再决定要不要接。

**接入 MCP 的好处，就是把已经有人做好的工具接过来用，不必为了每个助手再写一套同样的逻辑。** 先配好启动命令和权限，再用一次真实调用验证。以后换成别的服务，按它的说明检查运行环境、参数和凭证，接入思路还是一样的。
