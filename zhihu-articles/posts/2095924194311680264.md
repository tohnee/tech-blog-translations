### 读完你会得到：搞懂 RAG（检索增强生成）到底在做什么，并能在本地跑通一个最小可用版本。 
 
 一、为什么需要 RAG 
 大模型的知识停在训练那天，也不认识你的公司文档、笔记和合同。直接把几百页资料塞进提示词，要么装不下，要么又贵又慢。RAG 的思路很朴素：先从资料里找出最相关的几段，再连同问题一起交给模型，让它“开卷考试”。 
 
 二、流程只有四步 
 1. 切块：把文档切成 300～500 字的小段，相邻段落保留一点重叠，避免一句话被切断。 
 2. 向量化：用嵌入模型（embedding，把一段文字变成一串数字，意思相近的文字数字也相近）给每一段生成向量。 
 3. 检索：把问题也向量化，找出和它最相似的 3～5 段。 
 4. 生成：把这几段作为“参考资料”拼进提示词，让模型只依据资料回答。 
 
 三、动手：本地最小版本 
 先装好 Ollama（本地运行模型的工具），拉取两个模型： 
 
 ollama pull nomic-embed-text 
 ollama pull qwen2.5:7b 
 pip install ollama numpy 
 
 代码如下（把 notes.txt 换成你自己的文本文件）： 
 
 import ollama, numpy as np 
 
 text = open("notes.txt", encoding="utf-8").read() 
 chunks = [text[i:i+400] for i in range(0, len(text), 350)] 
 
 def embed(s): 
 return np.array(ollama.embeddings(model="nomic-embed-text", prompt=s)["embedding"]) 
 
 vecs = [embed(c) for c in chunks] 
 
 def ask(q, k=3): 
 qv = embed(q) 
 sims = [v @ qv / (np.linalg.norm(v) * np.linalg.norm(qv)) for v in vecs] 
 top = np.argsort(sims)[-k:][::-1] 
 ctx = "\n---\n".join(chunks[i] for i in top) 
 prompt = f"只根据下面资料回答，资料里没有就说不知道。\n资料：\n{ctx}\n\n问题：{q}" 
 r = ollama.chat(model="qwen2.5:7b", messages=[{"role": "user", "content": prompt}]) 
 return r["message"]["content"] 
 
 print(ask("这份文档里提到的退款规则是什么？")) 
 
 这里用余弦相似度（衡量两个向量方向有多接近）来排序，这就是检索的全部核心。 
 
 四、效果不好时先查这三处 
 1. 切块太大或太小：太大会混入无关内容，太小会丢上下文。先试 300～500 字。 
 2. 检索没找对：打印 top 几段看看。八成的“模型胡说”其实是资料没检索到。 
 3. 提示词没约束：一定要写“资料里没有就说不知道”，否则模型会凭印象编。 
 
 五、进阶方向 
 文档多了就换向量数据库（如 Chroma、FAISS）；想更准可加“重排序”，先多取 20 段再用重排模型挑最好的 3 段；中文资料建议选对中文友好的嵌入模型。 
 
 总结 
 RAG = 切块 + 向量检索 + 带资料提问。它不让模型变聪明，而是让模型有资料可查。先用上面的小脚本跑通，再逐步替换成自己的组件。
