## 第 0 章 引言与方法论：为什么要按”演进因果链”讲 RAG

---

### 0.1 本章定位与读者对象

本文不是”RAG 技术名词表”，而是一条 **因果链** ：每一项技术为什么出现、它解决了谁的坑、又留下了什么新坑。之所以这样组织，是因为 RAG 领域的常见失败—— **“每个术语都认识，连起来不知道在讲什么”** ——根源就在于把技术当成孤立的点来背。

**目标读者** ：

- 需要 **落地** RAG 的工程师：关心”用哪个、代价多少、怎么复现”。
- 需要 **理解** RAG 的学习者：关心”为什么这样设计、推导是什么”。
- 需要 **调研/选型** 的研究者：关心”证据在哪、边界在哪”。

**前置知识** ：线性代数（向量、内积、SVD）、基础概率（条件概率、期望）、基础 NLP（分词、词袋）。不具备也可阅读，公式处会给出数值手算示例（见 §0.6 与各章 P9）。

**三种读法** ：

- **速读** ：只读每节的”出现理由 + 一句话结论”。
- **精读** ：按 P1–P10 逐条读原理，按 R1–R10 亲手复现。
- **选型** ：直接跳到第 14 章的选型决策树（后续章节）。

### 0.2 锚点问题与锚点案例

全文围绕 **一个锚点问题** 展开：

> **在一次问答里，如何让模型拿到”刚好够用、且正确”的资料？**

并复用 **一个锚点案例** ：企业「制度助手」，员工提问——

> **“年假怎么请？”**

**没有 RAG 时** ：模型只能凭训练时的记忆作答。它可能编出一个公司根本不存在的系统名，或给出过时的流程。这种”看似合理、实为杜撰”的输出即 **幻觉（hallucination）** 。

**有 RAG 时** ，系统做四件事：

1. **找资料** ：在制度文档中检索与”年假/请假”相关的内容；
2. **挑资料** ：从候选中选出最相关的若干段；
3. **拼资料** ：把这几段与问题一起组织成提示（prompt）；
4. **照资料答** ：约束模型”只依据给定资料回答”，并在必要时给出出处。

这四步，就是 RAG 的全部骨架。 **后续每一章，都会回到这个案例，指明”本章的进步落在四步里的哪一步”。**

---

### 0.3 RAG 四动作框架（本文的分类骨架）

RAG 可形式化为四类操作 **串联** 而成。设输入查询为 `x` ，则：

```text
answer = Generate( PostProcess( Retrieve( OptimizeQuery(x) ) ) )
```

四个动作及其输入/输出/失败模式：

| 动作 | 专业名称 | 输入 | 输出 | 典型失败模式 |
| --- | --- | --- | --- | --- |
| ① 问清楚 | 查询优化 Pre-Retrieval | 原始查询x | 改写/扩展后的查询集合{x'} | 口语化、指代、意图不明 → 翻不到 |
| ② 找资料 | 检索 Retrieval | {x'} | 候选文档集D_k | 召回不足、语义鸿沟、精确匹配弱 |
| ③ 排重点 | 检索后处理 Post-Retrieval | D_k | 精排/压缩后的上下文C | 噪声污染、关键信息被埋、超长 |
| ④ 照着答 | 生成 Generation | (x, C) | 答案y | 幻觉、漏答、不忠实 |

**为什么用这四步做分类** ：因为 **任意一项 RAG 技术都能被归位到其中一步** 。例如 `HyDE` 属于①（它改变了”拿什么去检索”）， `Rerank` 属于③（它改变了”哪些资料被保留、如何排序”）。这个”归位”是本文组织内容的依据，也是读者判断”某个新技术到底动的是哪一环”的工具。

**误差的累积（木桶效应）** ：把 RAG 看成串联系统，端到端质量不是四步的简单相加，而是 **受最弱一环支配** 。形式上，若某一步的”信息保持率”为 `p_i ∈ (0,1)` ，则端到端信息保持率近似为 `Π_i p_i` —— **任何一环接近 0，整条链都会失败** 。这就是为什么”检索这一步决定了 90% 的效果”：②的 `p` 一旦很低，后面再精妙的生成也救不回来。

## 第 1 章 底座：检索技术是怎么长出来的（1990s–2020）· 上

### 1.0 本章导览

RAG 由”检索”与”生成”两半组成。生成那一半来自大模型， **检索这一半则继承自半个世纪的信息检索（IR）研究** 。本章按技术出现顺序，讲清检索的底色：

```text
关键词时代            语义时代                 检索+生成            索引规模化
─────────────        ─────────────          ────────────        ────────────
布尔/倒排 (1.1)  →   LSI/LDA (1.4)     →   REALM/RAG/FiD (1.7) → HNSW/IVF-PQ/DiskANN (1.8)
TF-IDF    (1.2)      Word2Vec/       ↑      稠密检索 DPR (1.6)
BM25      (1.3)      SBERT (1.5)     └──────┘
```

**要点** ：这些技术 **今天仍活在生产线里** （Elasticsearch 用 BM25，向量库用 HNSW），不是历史陈列。理解它们，才能理解后面每一代 RAG 技术在”补什么”。

### 1.1 布尔检索与倒排索引

### 出现理由

最初的文章检索是”逐篇逐字扫描”，当文档量增大时完全不可扩展（复杂度随文档数线性增长）。要让检索可行，必须 **预先建立索引** ，把”扫描”变成”查表”。

### 事实陈述

布尔检索与倒排索引是 IR 的经典理论，源自 1960 年代（Salton 等），系统化于教科书《Introduction to Information Retrieval》（Manning, Raghavan, Schütze, 2008）。

### 原理（P1–P10）

**P1 形式化定义**

- 文档集 `D = {d_1, …, d_N}` ， `N` 为文档总数。
- 词项表（词汇表） `V = {t_1, …, t_M}` 。
- 倒排索引 `I: t ↦ ⟨(doc_id, tf, [positions]) , …⟩` ，即每个词项映射到一张 **倒排列表（posting list）** ，元素记录”出现在哪篇文档、出现几次、出现在哪些位置”。
- 正向索引（forward index） `F: doc_id ↦ {词项集合}` ，与倒排互为转置。

**P2 核心结构**

```text
词典(term dictionary)          倒排文件(posting lists)
 t1 ────────────────►  [ (d3,2,[1,7]), (d9,1,[4]) ]
 t2 ────────────────►  [ (d1,1,[0]), (d3,1,[5]), (d5,3,[2,6,9]) ]
 ...
```

**P3 处理与推导（建索引与查询）**

- 建索引：对每篇文档分词、归一化（小写、词干化、去停用词），对每个词项在 `I` 中追加 `(doc_id, tf, positions)` 。
- 布尔 AND 查询 `t_a AND t_b` ：取 `posting(t_a)` 与 `posting(t_b)` 的 **交集** ，由于两者都按 `doc_id` 有序，可用 **双指针归并** 在线性时间内完成。
- 布尔 OR： **并集** ；NOT： **补集** 。

**P4 假设与成立条件**

- 假设”用户能用精确词项表达需求”；对同义词/拼写变体无能为力。
- 假设”匹配即相关”（因此只给集合、不给序）。

**P5 关键机制与参数**

- **倒排列表压缩** ：

- **跳表（skip pointers）** ：在长倒排列表上每 `√L` 个元素设一个跳跃指针（ `L` 为列表长度），跨步比较，把交集从 `O(L)` 降到近似 `O(√L)` 。

**P6 复杂度**

- 建索引： `O(T)` ， `T` 为语料总词数（一次性）。
- 布尔查询： `O(∑_{t∈Q} |posting(t)|)` （归并）。

**P7 推导级差异** 与后面的”排序检索”本质不同：布尔检索的查询算子（交/并/补） **不含相关性打分** ，输出是无序集合；TF-IDF/BM25 则输出带分数的 **排序列表** 。

**P8 边界与常见误解**

- 误解：以为倒排能解决”意思相近”的检索——它只做字面匹配。
- 边界：无法回答”哪个更相关”。

**P9 数值手算示例** 取 `D = {d1, d2, d3}` ：

```text
d1: 年假 申请
d2: 年假 制度
d3: 报销 申请
```

建倒排：

- `年假 → [d1, d2]`
- `申请 → [d1, d3]`
- `制度 → [d2]`
- `报销 → [d3]`

查询 `年假 AND 申请` ：双指针求交 `[d1,d2] ∩ [d1,d3] = [d1]` → 结果 `{d1}` 。 查询 `年假 OR 申请` ： `[d1,d2] ∪ [d1,d3] = [d1,d2,d3]` 。 **注意** ：三个结果都只是”集合”，没有排出谁最相关——这正是它的天花板。

**P10 可视化**

```text
词项           倒排列表(按doc_id有序)
        ┌──────┐
        │ 年假 │──►  d1 ──► d2
        ├──────┤
        │ 申请 │──►  d1 ──► d3
        ├──────┤
        │ 制度 │──►  d2
        ├──────┤
        │ 报销 │──►  d3
        └──────┘
   AND(年假,申请): 两条链双指针 → d1
跳表示意(在长链上):
 head ──skip──► ... ──skip──► ...
   │            │            │
   └─步进比较────┴────────────┘   (步长≈√L)
```

### 流程步骤

1. 输入：文档集 `D` 。
2. 分词/归一化：得到每篇文档的词项序列。
3. 建倒排表：对每个词项追加 `(doc_id, tf, positions)` ，并按 `doc_id` 排序。
4. 查询：解析布尔表达式 → 对每个词项取 posting list → 归并求交/并/补。
5. 输出：满足布尔条件的文档集合（无序）。

**R6 核心源码（ `rag/repro/inverted_index.py` ，可直接运行）**

```python
from collections import defaultdict

def tokenize(s):
    return s.split()  # 已用空格分隔，便于演示

def build_index(docs: dict):
    index = defaultdict(list)
    for doc_id, text in docs.items():
        for pos, term in enumerate(tokenize(text)):
            # 同一 (term,doc) 只记一次 doc_id，tf 累加，positions 收集
            if index[term] and index[term][-1][0] == doc_id:
                _, tf, poses = index[term][-1]
                index[term][-1] = (doc_id, tf + 1, poses + [pos])
            else:
                index[term].append((doc_id, 1, [pos]))
    return index

def intersect(a, b):
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            out.append(a[i]); i += 1; j += 1
        elif a[i] < b[j]:
            i += 1
        else:
            j += 1
    return out

if __name__ == "__main__":
    docs = {
        "d1": "年假 申请",
        "d2": "年假 制度",
        "d3": "报销 申请",
    }
    index = build_index(docs)
    posts = {t: [x[0] for x in plist] for t, plist in index.items()}
    print("倒排表:", dict(posts))
    print("年假 AND 申请 ->", intersect(posts["年假"], posts["申请"]))
    print("年假 OR  申请 ->", sorted(set(posts["年假"]) | set(posts["申请"])))
    print("NOT 年假     ->", sorted(set(docs) - set(posts["年假"])))
```

### 差异对比

| 维度 | 布尔检索/倒排 | 排序检索(TF-IDF/BM25) |
| --- | --- | --- |
| 输出 | 无序集合 | 带分数排序 |
| 相关性 | 无 | 有 |
| 典型实现 | Lucene 布尔查询 | Lucene 打分查询 |

### 证据与实践

- 【证据】Lucene、Elasticsearch、Anserini、PISA 均以倒排为核心数据结构。
- 【实践】精确短语、代码、法条、编号检索仍首选倒排/关键词路。
- 【连贯】 **它的天花板（无排序）逼出了 TF-IDF** 。

### 1.2 TF-IDF

### 出现理由

布尔检索只会回答”命不命中”，无法回答”谁更相关”。设想查询 `"年假"` 命中了 100 篇文档，其中”年假”只是顺带提及的和整篇都在讲年假的，被同等对待——这显然不合理。

### 事实陈述

TF-IDF 由 Salton 与 Buckley 于 1988 年系统阐述（ *Term-Weighting Approaches in Automatic Text Retrieval* ）。

### 原理（P1–P10）

**P1 形式化定义**

- `tf(t,d)` ：词项 `t` 在文档 `d` 中的频次。
- `df(t)` ：含 `t` 的文档数； `N` ：文档总数。
- `idf(t) = log(N / df(t))` ：逆文档频率，词越稀有、值越大。

**P2 核心公式**

```text
tf-idf(t, d) = tf(t, d) · idf(t) = tf(t, d) · log(N / df(t))          (2-1)
score(q, d)  = Σ_{t ∈ q} tf-idf(t, d)                                  (2-2)
```

**P3 推导（为什么是”乘积”）**

- `tf` 越大 → 该词对这篇文档越重要（局部重要）。
- `df` 越小 → 该词越能区分文档（全局稀有）。极端地，若 `df=N` （如”的”）， `idf=0` ，该词被自动”消权”。
- 两个直觉独立，故以乘积组合为权重；式(2-1) 把”局部频次×全局稀有度”合为一个分数。
- 变体： `tf` 可替换为对数形式 `1+log(tf)` 或二值 `1[tf>0]` ，用于压制高频词的过度影响。

**P4 假设与成立条件**

- **词袋假设** ：忽略词序与语法。
- 假设”词项间独立”；因此它无法处理短语与语义。

**P5 参数敏感性**

- `idf` 是否平滑（ `log(N/(1+df))` ）、是否加 `+1` ，会改变绝对分数，但不改变一般排序。
- 是否做 **L2 归一化** ：使长文档与短文档可比（否则长文档天然占优）。

**P6 复杂度**

- 向量化： `O(文档非零词项数)` ；查询打分： `O(|q|)` 次查表。

**P7 推导级差异** 与 BM25 的差异在”tf 的处理”：TF-IDF 的 tf 项 **线性无上界** ，BM25 用饱和函数把 tf 的影响 **压到有界** （见 1.3）。

**P8 边界与常见误解**

- 误解：以为 `idf` 是概率——它是启发式权重。
- 边界：对长文档、极高频词、同义词处理均不佳。

**P9 数值手算示例** 取 `N = 3` ：

```text
d1: cat dog
d2: cat
d3: dog fish
```

统计： `df(cat)=2, df(dog)=2, df(fish)=1` 。 计算 `idf = log(N/df)` （自然对数）：

- `idf(cat) = log(3/2) = 0.405`
- `idf(dog) = log(3/2) = 0.405`
- `idf(fish) = log(3/1) = 1.099`

查询 `q = cat fish` ，按式(2-2)：

- `d1` ： `tf(cat)=1 → 0.405` ； `fish` 未出现 → 0。得分 **0.405**
- `d2` ： `cat → 0.405` 。得分 **0.405**
- `d3` ： `fish → 1.099` 。得分 **1.099**

排名： `d3 > d1 = d2` 。 **结论** ：尽管 `d1/d2` 也含 `cat` ，但 `fish` 更稀有（ `idf` 更大），因此含 `fish` 的 `d3` 反超——这就是”稀有词主导排序”。

**P10 可视化**

```text
idf(t) = log(N/df)        分数构成
 ^                           score(q,d) = Σ tf·idf
 │                            ┌───────────────┐
 │ 1.099 ─── fish(稀有)       │ tf  (局部重要) │
 │                            │  ×            │  → 乘起来
 │ 0.405 ─── cat / dog(常见)  │ idf (全局稀有) │
 │                            └───────────────┘
 └────────────────► df(出现文档数)
```

### 流程步骤

1. 输入：文档集与查询。
2. 建词表，统计 `df` ，计算每个词项 `idf` 。
3. 文档向量化： `d ↦ [tf-idf(t_1,d), …]` （可 L2 归一化）。
4. 查询向量化： `q ↦ [tf-idf(t, q)]` 。
5. 打分排序：对候选文档算 `score(q,d)` （式 2-2），降序输出。

### 1.3 BM25（含 BM25+ / BM25F）

### 出现理由

TF-IDF 有两个明显缺陷：① **tf 线性无界** ——一个词出现 10 次未必比 1 次相关 10 倍；② **长度处理粗糙** ——靠向量归一化，但检索排序中长度应显式影响打分。BM25 用 **概率检索模型** 同时修正这两点。

### 事实陈述

BM25 出自 Okapi 系统，由 Robertson 与 Zaragoza 等人在 1994–2004 年间完善；现代实现见 Lucene/Elasticsearch 的 `BM25Similarity` 。

### 原理（P1–P10）

**P1 形式化定义**

- 相关性： `R ∈ {0,1}` ；检索状态价值 `RSV = log[P(R=1|d)/P(R=0|d)]` 。
- 词项 `t` 的文档频数 `n_t = df(t)` ，语料 `N` ； `tf_t(d)` 为词频， `|d|` 为文档长度， `avgdl` 为平均文档长度。

**P2 核心公式**

```text
score(q, d) = Σ_{t ∈ q} IDF(t) · [ tf_t(d)·(k1+1) / ( tf_t(d) + k1·(1 − b + b·|d|/avgdl) ) ]   (3-1)

IDF(t) = log( (N − n_t + 0.5) / (n_t + 0.5) + 1 )                                              (3-2)
```

**P3 推导（从二元独立模型到 BM25）**

1. **从相关性比值出发** ：由贝叶斯， `RSV = log[P(R=1|d)/P(R=0|d)]` 。
2. **词项独立假设** ：文档由词项构成，各词项出现与否相互独立 → 比值可分解为各词项贡献之 **乘积** ，取对数后变为 **求和** ： `RSV = Σ_t log[ P(t|R=1)/P(t|R=0) ]` （对出现与未出现两种情况）。
3. **用列联表估计概率** ：以 `n_t` 、 `N` 、以及相关文档中含 `t` 的数目 `r` 表达各概率。忽略 `r` （相关文档数）的小量后，得到 **Robertson–Spärck Jones 权重** ，其常见实用形式即式(3-2) 的 `IDF(t)` 。
4. **引入词频饱和** ：纯二元模型只看”出现/未出现”。Okapi 引入 **饱和函数** ——词频从 0 增长时分数快速上升，之后趋缓并趋于上界 `(k1+1)` 。这一步使 `tf=1→2` 的增益远大于 `tf=10→11` 。
5. **引入长度归一化** ：长文档天然含更多词，需要抑制。用 `|d|/avgdl` 与参数 `b` 调节， `b=1` 完全归一化、 `b=0` 不归一化。
6. 合并 3–5 步，得式(3-1)。

> **诚实说明** ：式(3-1) 的 `k1` 、 `b` 属于 Okapi 的 **经验参数** （工程化发明），其函数形态（饱和 + 长度归一化）是实践产物，而非严格从概率模型推出；但 **整体骨架（求和形式的词项权重）来自二元独立模型** 。

**P4 假设与成立条件**

- 词项独立性；非相关词项的出现分布近似均匀。
- 未考虑词序、短语、语义。

**P5 参数敏感性**

- `k1` （典型 1.2–2.0）：越大，词频饱和越慢（更看重高频）。
- `b` （典型 0.75，范围 [0,1]）： `b=0` 不做长度归一化（长文档占优）； `b=1` 完全归一化。
- 极限： `k1→0` 时， `tf` 项趋于常数， **退化为”是否出现”的二元模型** 。

**P6 复杂度**

- 与倒排一致：查询每词项在其 posting list 上累加， `O(∑|posting|)` 。

**P7 推导级差异**

- vs TF-IDF： `tf` 项由线性 `tf` 变为 **饱和函数** `tf·(k1+1)/(tf+…)` ，且有上界 `k1+1` 。
- vs BM25+：长文档补偿项，分母加 `δ` ， `tf·(k1+1)/(tf + k1·(1−b+b·|d|/avgdl) + δ)` ，缓解长文档的过度惩罚。
- vs BM25F：面向 **多字段** （标题/正文/锚文本），先对各字段的 `tf` 做加权与”加权长度”归一，再求和。

**P8 边界与常见误解**

- 误解：把 `b` 当作”学习率”（它只是长度归一化强度）；把 `k1` 当”必须调优”（多数场景 1.2–2.0 够用）。
- 边界：仍是 **字面匹配** ，对同义词无解 → 逼出语义/稠密检索。

**P9 数值手算示例** 语料（ `N=3` ）：

```text
d1: cat cat dog      (len 3)
d2: cat fish         (len 2)
d3: dog dog dog      (len 3)
avgdl = (3+2+3)/3 = 2.667
```

`df(cat)=2, df(dog)=2` ；取 `IDF(cat)=IDF(dog)=log((3−2+0.5)/(2+0.5)+1)=log(1.6)=0.470` 。 参数 `k1=1.2, b=0.75` 。

- 长度因子 `L(d)=1−b+b·|d|/avgdl` ：

查询 `q = cat dog` ，逐文档手算：

**d1** （ `tf_cat=2, tf_dog=1` ）

- cat：分子 `2×(1.2+1)=4.4` ，分母 `2+1.3125=3.3125` ，比值 `1.328` ，贡献 `×0.470=0.624`
- dog：分子 `1×2.2=2.2` ，分母 `1+1.3125=2.3125` ，比值 `0.951` ，贡献 `×0.470=0.447`
- **d1 = 1.071**

**d2** （ `tf_cat=1, tf_dog=0` ）

- cat：分子 `2.2` ，分母 `1+0.975=1.975` ，比值 `1.114` ，贡献 `×0.470=0.524`
- **d2 = 0.524**

**d3** （ `tf_cat=0, tf_dog=3` ）

- dog：分子 `3×2.2=6.6` ，分母 `3+1.3125=4.3125` ，比值 `1.530` ，贡献 `×0.470=0.719`
- **d3 = 0.719**

**排名：d1 (1.071) > d3 (0.719) > d2 (0.524)** 。可见 `d3` 虽然 `dog` 出现 3 次，但因 **词频饱和** ，其单串贡献（0.719）并未是 `d1` 的 dog（0.447）的 3 倍——这正是饱和函数的作用。

**P10 可视化**

```text
饱和函数 f(tf)=tf(k1+1)/(tf+k1)    （k1=1.2 → 上界 2.2）
 f
 2.2 |‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾  ← 上界 k1+1
     |        ___------
     |    _---
     |  _-
     | /
     └──────────────────► tf
      1   2   3   5   10      （增长越来越慢）

长度归一化因子 L(d) = 1 − b + b·|d|/avgdl
 b=0 → L 恒为 1（不归一化）
 b=1 → L = |d|/avgdl（完全按长度归一化）
```

### 流程步骤

1. 输入：文档集、查询、 `k1` 、 `b` 。
2. 预处理：分词、统计 `n_t` 、 `avgdl` 。
3. 建倒排：记录每文档每词项 `tf` 、 `|d|` 。
4. 打分：对查询每个词项，按式(3-1) 计算并累加（跳过 `tf=0` 的文档）。
5. 排序：按总分降序输出 top-k。

**R6 核心源码（ `rag/repro/bm25_repro.py` ）**

```python
import argparse, math
from rank_bm25 import BM25Okapi

DOCS = {"d1": "cat cat dog", "d2": "cat fish", "d3": "dog dog dog"}

def manual_bm25(docs, query, k1, b):
    N = len(docs)
    toks = {d: docs[d].split() for d in docs}
    avgdl = sum(len(v) for v in toks.values()) / N
    # 统计 df
    df = {}
    for t in set(query.split()):
        df[t] = sum(1 for d in docs if t in toks[d])
    idf = {t: math.log((N - df[t] + 0.5) / (df[t] + 0.5) + 1) for t in df}
    scores = {}
    for d, tt in toks.items():
        L = 1 - b + b * len(tt) / avgdl
        s = 0.0
        for t in query.split():
            tf = tt.count(t)
            if tf == 0:
                continue
            s += idf[t] * (tf * (k1 + 1)) / (tf + k1 * L)
        scores[d] = s
    return scores

if __name__ == "__main__":
    ap = argparse.ArgumentParser()
    ap.add_argument("--k1", type=float, default=1.2)
    ap.add_argument("--b", type=float, default=0.75)
    a = ap.parse_args()

    q = "cat dog"
    manual = manual_bm25(DOCS, q, a.k1, a.b)
    lib = BM25Okapi([DOCS[d].split() for d in DOCS], k1=a.k1, b=a.b)
    lib_scores = dict(zip(DOCS, lib.get_scores(q.split())))

    print("手算:", {k: round(v, 3) for k, v in sorted(manual.items(), key=lambda x: -x[1])})
    print("库算:", {k: round(float(v), 3) for k, v in sorted(lib_scores.items(), key=lambda x: -x[1])})
```

| BM25+ | 分母加δ，补偿长文档 | 长短文档差异大 |
| BM25F | 按字段加权 + 加权长度 | 标题/正文/锚文本多字段 |

### 1.4 从词袋到语义：LSI / LDA

### 出现理由

TF-IDF/BM25 都是 **字面匹配** ：查询”如何请假”，找不到写”休假申请流程”的文档，因为字面不重叠（ **词汇鸿沟** ）。LSI/LDA 试图把文档映射到 **潜在语义/主题空间** ，使”意思相近”的文档靠近。

### 事实陈述

- LSI（潜在语义索引）：Deerwester 等，1990。
- LDA（隐含狄利克雷分布）：Blei 等，2003。

### 原理（P1–P10）

**P1 形式化定义**

- 词-文档矩阵 `A ∈ R^{M×N}` （ `M` 词项、 `N` 文档），元素为 TF-IDF 权重。
- LSI：寻找低维表示 `A ≈ U_k Σ_k V_k^T` ， `k ≪ min(M,N)` 。
- LDA：生成式模型，文档-主题分布 `θ_d ~ Dir(α)` ，主题-词分布 `φ_k ~ Dir(β)` 。

**P2 核心公式**

```text
A ≈ U_k Σ_k V_k^T                    （截断 SVD，式 4-1）
A_k = argmin_{rank(B)=k} ||A − B||_F  （最优低秩近似，式 4-2）
```

**P3 推导（Eckart–Young 定理）**

- 对 `A` 做 SVD： `A = U Σ V^T` ，奇异值 `σ_1 ≥ σ_2 ≥ …` 。
- **Eckart–Young 定理** ：在所有秩不超过 `k` 的矩阵中， `A_k = U_k Σ_k V_k^T` 使 Frobenius 范数误差 `||A − A_k||_F` **最小** ，且最小误差为 `sqrt(Σ_{i>k} σ_i^2)` 。
- 直觉：SVD 按”能量（奇异值）”排序，保留前 `k` 个即保留主要语义方向，丢弃的尾部多为噪声/修辞差异。
- LDA 则是 **生成式** ：为文档先抽主题分布，再由主题抽词；用变分推断或吉布斯采样估计后验。

**P4 假设与成立条件**

- LSI 假设语义是词项的 **线性子空间** 结构；无法表达非线性与上下文。
- LDA 假设词由少数主题混合生成；忽视词序。

**P5 参数敏感性**

- `k` （主题数）：过小 → 语义混叠；过大 → 过拟合噪声。常用 100–300。

**P6 复杂度**

- SVD： `O(MN·min(M,N))` ，且 **新增文档需重算** （增量困难），是其被神经嵌入取代的重要原因之一。

**P7 推导级差异**

- LSI（线性代数降维）vs LDA（概率生成模型）vs 神经嵌入（非线性、上下文相关）：三者的表示能力依次增强。

**P8 边界与常见误解**

- 误解：以为 LSI 的”语义”能处理同义词——它只能通过共现间接捕捉，效果有限。
- 边界：非线性、多义、上下文均无法建模。

**P9 数值手算示例（最小 SVD，2×2）** 取 `A = [[1, 0], [0, 1]]` （两篇文档正交、两个词各只出现一次）。

- `A^T A = [[1,0],[0,1]]` ，特征值均为 1，奇异值 `σ_1=σ_2=1` 。
- 若取 `k=1` ： `A_1 = U_1 Σ_1 V_1^T` ，误差 `||A−A_1||_F = sqrt(σ_2²) = 1` 。
- 换一个更”低秩”的例子 `A = [[1, 1], [1, 1]]` ：奇异值 `σ_1=2, σ_2=0` 。取 `k=1` 时 **误差为 0** ——说明该矩阵本质是一维的，SVD 精准捕捉了这一点。
- **结论** ：奇异值越小，越可安全丢弃； `k` 的选择就是”保留多少能量”。

**P10 可视化**

```text
原始词-文档矩阵 A           低维主题空间 (k=2)
   ┌  词1 词2 词3 ┐             主题2
d1 │  tf  tf  0  │                 ▲     • d3
d2 │  0   tf  tf │      SVD ──►    │  • d1
d3 │  tf  0   tf │                 │ • d2
   └             ┘                 └─────────► 主题1
                        文档在主题空间中的坐标(节点更靠拢=语义相近)

能量谱：  σ1 ▇▇▇▇▇▇▇▇   σ2 ▇▇▇▇   σ3 ▇   σ4 ▏
          └─保留前k个(实线)─┘   └─丢弃(多为噪声)─┘
```

### 流程步骤

1. 输入：文档集。
2. 构建词-文档矩阵 `A` （TF-IDF 加权）。
3. LSI：对 `A` 做 SVD，取前 `k` 个奇异值/向量 → 文档与查询投到低维空间 → 计算余弦相似度检索。 或 LDA：估计 `θ_d, φ_k` → 用主题分布作文档表示。
4. 输出：按低维空间相似度排序的文档。

**R6 核心源码（ `rag/repro/lsi_lda_repro.py` ）**

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.decomposition import TruncatedSVD
from sklearn.metrics.pairwise import cosine_similarity
from gensim import corpora, models

docs = [
    "年假 申请 审批 流程",

    "报销 发票 财务 到账",
    "加班 调休 有效期",
    "请假 病假 医院 证明",
    "年假 折现 离职 结算",
]
query = "休假 怎么 申请"

# --- LSI ---
tfidf = TfidfVectorizer()
X = tfidf.fit_transform(docs)
svd = TruncatedSVD(n_components=2, random_state=42)
Zdoc = svd.fit_transform(X)
Zq = svd.transform(tfidf.transform([query]))
sim = cosine_similarity(Zq, Zdoc).ravel()
print("LSI 相似度:", [round(float(s), 3) for s in sim])
print("LSI 排序:", [f"d{i+1}" for i in sim.argsort()[::-1]])

# --- LDA ---
tokens = [d.split() for d in docs]
dic = corpora.Dictionary(tokens)
corpus = [dic.doc2bow(t) for t in tokens]
lda = models.LdaModel(corpus, num_topics=2, id2word=dic, passes=20, random_state=42)
print("LDA 主题:")
for k, words in lda.print_topics(num_words=3):
    print(f"  主题{k}: {words}")
```

### 1.5 词向量与句向量：Word2Vec / GloVe / Sentence-BERT

### 出现理由

LSI/LDA 的语义是”线性、无上下文”的。真正的语义表示需要满足两点： **稠密** （低维、连续，便于计算相似度）与 **可迁移** （从海量无标注语料中获得）。词向量与句向量由此而来。

### 事实陈述

- Word2Vec：Mikolov 等，2013。
- GloVe：Pennington 等，2014。
- Sentence-BERT（SBERT）：Reimers & Gurevych，2019。

### 原理（P1–P10）

**P1 形式化定义**

- 词 `w` 映射为向量 `v_w ∈ R^d` （ `d` 常为 100–300）。
- 上下文词 `c` 的向量 `v_c` ；共现计数 `X_{ij}` 。

**P2 核心公式**

```text
Skip-gram 目标： max Σ_t Σ_{j≠0} log P(w_{t+j} | w_t)                       (5-1)
P(o|c) = exp(v_o · v_c) / Σ_{w∈V} exp(v_w · v_c)                            (5-2)

负采样目标（NEG，K 个负样本）：
 log σ(v_o·v_c) + Σ_{k=1}^{K} E_{w_k ~ P_n(w)} [ log σ(−v_{w_k}·v_c) ]      (5-3)
其中 σ(x) = 1/(1+e^{−x})

GloVe 目标（加权最小二乘）：
 J = Σ_{i,j} f(X_{ij}) ( v_i·ṽ_j + b_i + b̃_j − log X_{ij} )²               (5-4)

SBERT 对比损失（InfoNCE / 多重负例）：

 L = −log [ exp(sim(u, v⁺)/τ) / ( exp(sim(u,v⁺)/τ) + Σ_j exp(sim(u,vⱼ⁻)/τ) ) ]   (5-5)
```

**P3 推导**

- **Skip-gram → 负采样** ：式(5-2) 的分母需对全词表归一化，代价 `O(|V|)` ，海量语料不可行。负采样把它替换为”1 个正例 + K 个负例”的二分类任务（式 5-3），复杂度降到 `O(K)` 。

- **GloVe 与词向量的联系** ：理论分析表明，Skip-gram（含负采样）的隐式目标近似于共现矩阵 `PPMI` 的低秩分解，而 GloVe（式 5-4）是 **显式** 对 `log X_{ij}` 做加权分解。二者殊途同归： **词向量 ≈ 共现统计的低秩分解** 。
- **SBERT 的动机** ：原始 BERT 判断两句相似需把两句话 **拼接** 送入，10,000 句两两比较要算 5×10⁷ 次前向——不可行。SBERT 用 **双塔** （Siamese）分别编码、训练时用对比损失（式 5-5）把语义相同/相关的句子拉近，推理时只需各自编码后算余弦， **可预计算** 。

**P4 假设与成立条件**

- **分布假设** ：上下文相似的词，语义相似。
- SBERT 假设相似度可由”句向量的余弦”近似（将句子压成单向量，细节有损）。

**P5 参数敏感性**

- 窗口大小：小窗口偏语法（功能相近），大窗口偏主题（语义相近）。
- 负采样数 `K` 、温度 `τ` ：影响表示分布的”松紧”。

**P6 复杂度**

- 训练：Skip-gram 朴素 `O(|V|)` ，负采样后 `O(K)` ；GloVe 为对非零共现的加权回归。
- SBERT 推理：编码 `O(句数)` + 余弦 `O(句数²·d)` （但相似度计算极廉价）。

**P7 推导级差异**

| 表示 | 上下文相关 | 粒度 | 是否需微调 |
| --- | --- | --- | --- |
| Word2Vec/GloVe | 否（静态） | 词 | 直接训练 |
| 上下文嵌入（如 BERT 原始用法） | 是 | 词/句 | 交叉编码，慢 |
| SBERT | 是 | 句 | 双塔，可预计算 |

**P8 边界与常见误解**

- 误解：把 Word2Vec 当作”万能语义”——它无法表达一词多义（”苹果”公司 vs 水果）。
- 边界：SBERT 把句子压成单向量，对长文本/细节有损。

**P9 数值手算示例**

1. **余弦相似度** ： `u=(1,2)` ， `v=(2,1)` ： `cos(u,v) = (1·2+2·1)/(√5·√5) = 4/5 = 0.8` 。 而 `w=(−2,−1)` ： `cos(u,w) = −4/5 = −0.8` 。可见 **方向** 决定语义， **大小** 不影响余弦。
2. **负采样梯度** ：令 `v_c=(1,0)` ，正例 `v_o=(1,0)` （内积 1），一个负例 `v_{w1}=(0,1)` （内积 0）。

- 正例项： `σ(1)=0.731` → 梯度 `(0.731−1)·v_o = −0.269·(1,0) = (−0.269, 0)`
- 负例项： `σ(0)=0.5` → 梯度 `0.5·v_{w1} = (0, 0.5)`
- 合计 `∂ℓ/∂v_c = (−0.269, 0.5)` 。以学习率 `0.1` ： `v_c ← (1,0) − 0.1·(−0.269,0.5) = (1.027, −0.05)` 。 **解读** ： `v_c` 沿 `v_o` 方向微增（被拉近），沿 `v_{w1}` 方向下降（被推远）。

**P10 可视化**

```text
Word2Vec/GloVe(静态词向量)         SBERT(句向量-双塔)
   king ─ queen                     句A ─► 编码器A ─► u ╮
     │  (向量代数:                    句B ─► 编码器B ─► v ╯──► cos(u,v)
     │  king−man+woman≈queen)                    (可各自预计算!)
   man ─ woman
SBERT 训练(对比损失):
   锚句 ──► u
   正句 ──► v⁺     loss 让 sim(u,v⁺)↑
   负句 ──► v⁻     loss 让 sim(u,v⁻)↓
```

### 流程步骤（以 SBERT 为例）

1. 输入：句对（相似/不相似）。
2. 双塔编码： `u=E(A), v=E(B)` 。
3. 对比训练：按式(5-5) 优化（正例拉近、批内负例推远）。
4. 推理：分别编码语料与查询 → 算余弦 → 排序（可预计算语料向量）。

### 1.6 稠密段落检索 DPR

### 出现理由

BM25 的 **词汇鸿沟** ：查询与文档用词不重合时召回失败。SBERT 证明句向量可做语义相似度，DPR 把这一思路用于 **大规模段落检索** 。

### 事实陈述

Karpukhin 等，2020（EMNLP）， *Dense Passage Retrieval for Open-Domain Question Answering* ，arXiv:2004.04906。

### 原理（P1–P10）

**P1 形式化定义**

- 问题编码器 `E_Q(·)` 、段落编码器 `E_P(·)` （两个独立的 BERT）。
- 相似度用 **内积** ： `sim(q, p) = E_Q(q)^T E_P(p)` 。

**P2 核心公式**

```text
sim(q, p) = E_Q(q)^T · E_P(p)                                               (6-1)

训练目标（对每个问题，正段落 p⁺，负段落集 {p⁻}）：

 L = −log [ exp(sim(q, p⁺)) / ( exp(sim(q,p⁺)) + Σ_{p⁻} exp(sim(q,p⁻)) ) ]  (6-2)
```

**P3 推导**

- 检索被建模为 **最大内积搜索（MIPS）** ：给定 `q` ，找 `argmax_p E_Q(q)^T E_P(p)` 。
- 式(6-2) 是对比损失（softmax 形式）：把正段落当作”正确类别”，其余段落当作”干扰类别”。
- **in-batch negatives 原理** ：一个 batch 有 `B` 个 (q, p⁺) 对。计算 `Q·Pᵀ` （B×B 矩阵）后，第 `i` 行的正例是 `P_i` ，其余 `B−1` 个段落自动成为 `q_i` 的负例。

**P4 假设与成立条件**

- 双塔可分解： `q` 与 `p` 独立编码（因此可 **预计算** 所有段落向量）。
- 假设”内积越大越相关”可通过训练学到。

**P5 参数敏感性**

- 向量维度 `d` （常用 768）；批大小 `B` （越大负例越多）；负例挖掘策略（随机/难负例）。

**P6 复杂度**

- 离线： `O(|语料|)` 次编码（一次性）。
- 在线： `O(1)` 次查询编码 + ANN 检索（亚线性）。

**P7 推导级差异**

- vs BM25：字面 vs 语义；DPR 对同义改写鲁棒，但 **对精确术语/编号弱** 。
- vs 交叉编码器（Cross-Encoder）：交叉编码器把 (q,p) 拼接联合编码，精度更高，但 **无法预计算** （每次查询对每个候选都要前向），故只能用于 **重排少量候选** ；DPR 双塔可预计算，用于 **大规模召回** 。

**P8 边界与常见误解**

- 误解：以为 DPR 全面优于 BM25——实际在精确匹配、域外数据上常不如 BM25，故需 **混合检索** 。
- 边界：MIPS + ANN 存在近似误差。

**P9 数值手算示例（in-batch negatives）** 设 batch `B=3` ，相似度矩阵（行=问题，列=段落）：

```text
p1     p2     p3
   q1        3.0    1.0    0.5
   q2        0.8    2.5    1.2
   q3        1.1    0.9    2.2
```

对 `q1` ：正例为 `p1` （对角）。 `exp` 得 `e^{3.0}=20.09, e^{1.0}=2.72, e^{0.5}=1.65` 。 `L_1 = −log(20.09 / (20.09+2.72+1.65)) = −log(20.09/24.46) = −log(0.821) = 0.197` 。 若把 `q1` 与 `p2` 的相似度从 1.0 抬到 2.8（更难负例），则分母含 `e^{2.8}=16.44` ， `L_1 = −log(20.09/(20.09+16.44+1.65)) = −log(20.09/38.18) = 0.642` —— **损失增大** ，模型被迫把正例与负例拉开。这就是 in-batch negatives 的作用。

**P10 可视化**

```text
离线(建库)                          在线(查询)
 段落1 ─► E_P ─► v1 ┐              问题 q ─► E_Q ─► u
 段落2 ─► E_P ─► v2 ├─► 向量库(FAISS)         │
   ...              │                          ▼
 段落N ─► E_P ─► vN ┘              内积 Top-k (MIPS) ─► 段落
in-batch negatives (B=3):
        p1   p2   p3
   q1 [ ✓    ✗    ✗ ]   ✓=正例
   q2 [ ✗    ✓    ✗ ]   ✗=in-batch 负例(免费获得)
   q3 [ ✗    ✗    ✓ ]
```

### 流程步骤

1. 离线：把全部段落用 `E_P` 编码 → 存入向量库（FAISS）。
2. 在线： `q → E_Q(q)` 。
3. MIPS：ANN 检索 top-k 段落。
4. 输出：top-k 段落（供生成或重排）。

**R6 核心源码（ `rag/repro/dpr_repro.py` ）**

```python
import numpy as np, faiss
from sentence_transformers import SentenceTransformer

passages = [
    "员工入职满一年可享年假五天",          # 与查询同义但少字面重叠
    "年假天数随工龄递增，满三年增至十天",
    "报销流程：发票粘贴后提交财务",
    "请假流程：调休需提前一天申请",
    "加班可折算调休，有效期三个月",
    "公司组织架构与部门职责说明",
]
query = "休假能休几天？"

enc = SentenceTransformer("shibing624/text2vec-base-chinese")
D = enc.encode(passages, normalize_embeddings=True).astype("float32")
q = enc.encode([query], normalize_embeddings=True).astype("float32")

index = faiss.IndexFlatIP(D.shape[1])     # 内积索引(等价 MIPS; 已归一化则=余弦)
index.add(D)
scores, idx = index.search(q, k=3)
print("查询:", query)
for rank, (i, s) in enumerate(zip(idx[0], scores[0]), 1):
    print(f"  top{rank}: {passages[i]}  (score={s:.3f})")
```

- 【证据】DPR 原文在 NQ/TriviaQA 上以 Top-k Retrieval Accuracy 大幅超越 BM25（自然问题）。
- 【实践】现代向量检索 RAG 的核心；与 BM25 组成 Hybrid。
- 【连贯】有了”检索器”，还需把它与”生成器”耦合——即 1.7。

### 1.7 检索与生成的耦合：REALM / RAG / FiD

### 出现理由

检索到资料后，必须让 **资料影响生成** 。早期做法是把资料简单拼接进提示，但如何 **训练** “检索+生成”的联合系统，是三篇里程碑论文要回答的。

### 事实陈述

- REALM：Guu 等，2020（ICML）。
- **RAG：Lewis 等，2020（NeurIPS），arXiv:2005.11401** 。
- FiD：Izacard & Grave，2020。

### 原理（P1–P10）

**P1 形式化定义**

- 检索器分布： `p_η(z | x)` ， `z` 为被检索到的文档。
- 生成器： `p_θ(y | x, z)` ， `y` 为答案序列。

**P2 核心公式**

```text
RAG-Sequence（整条答案用同一批文档做边缘化）：
   p(y|x) ≈ Σ_{z ∈ top-k} p_η(z|x) · Π_t p_θ(y_t | x, z, y_{<t})            (7-1)

RAG-Token（每个 token 可基于不同文档边缘化）：
   p(y|x) ≈ Π_t Σ_{z ∈ top-k} p_η(z|x) · p_θ(y_t | x, z, y_{<t})            (7-2)

FiD（在解码器端融合 k 篇文档）：
   p(y|x) = Π_t p_θ( y_t | z_1,…,z_k, x, y_{<t} )                           (7-3)
```

**P3 推导（RAG-Sequence vs RAG-Token 的差异）**

- 两者都在对潜变量 `z` 做边缘化（把”用哪篇文档”这个未知量 sum 掉），但 **求和的位置不同** ：

- **复杂度差异** ：RAG-Sequence 对每个 `z` 生成一次完整答案（ `k` 次解码）；RAG-Token 每个 token 都要对 `k` 篇做加权（需 `k` 次前向取 logits 后加权）。
- **REALM 的路径** ：把检索器当作 **潜变量** ，用 EM/最大似然联合 **预训练** （先验来自检索）；它更强调”从零预训练”。
- **FiD 的路径** ：不做边缘化，而是 **编码所有 k 篇文档** ，让解码器在每一步 attention 到全部，相当于”把选择权交给注意力”。

**P4 假设与成立条件**

- 假设 top-k 文档足以覆盖答案依据。
- 假设检索器与生成器可 **分别预训练** 再联合微调。

**P5 参数敏感性**

- `k` （检索文档数）：RAG 原文常用 5–10； `k` 越大召回越高但成本越高、噪声越多。

**P6 复杂度**

- 生成成本 ≈ `k` 倍（RAG-Sequence/Tokendiametrically 解码）或”一次解码 + k 篇编码”（FiD）。

**P7 推导级差异** （见 P3；核心是”求和位置”与”是否边缘化”。）

**P8 边界与常见误解**

- 误解：RAG 就是”把检索结果拼进 prompt”—— **那是推理时的做法** ；原论文的贡献是 **联合训练** 检索器与生成器。
- 边界：参数多、训练难；现代多改为”冻结检索器 + 提示工程”的工程实现。

**P9 数值手算示例（边缘化）** 设 `k=2` ，检索器给出 `p_η(z1)=0.7, p_η(z2)=0.3` ；某答案 `y="五天"` 在两篇下的生成概率 `p_θ(y|z1)=0.8, p_θ(y|z2)=0.4` 。

- **RAG-Sequence** ： `p(y|x)=0.7×0.8 + 0.3×0.4 = 0.56 + 0.12 = 0.68` 。
- **RAG-Token** （假设答案两个 token `y=(五)(天)` ）：

- **对比** ：Sequence 得 0.68，Token 得 0.655。两者不同，正体现”求和位置不同”。

**P10 可视化**

```text
RAG-Sequence:  Σ_z [ p_η(z|x) · 生成(整条答案|z) ]
        z1 ─► 生成整条 ─► 0.8 ┐
                              ├─ 加权和 0.68
        z2 ─► 生成整条 ─► 0.4 ┘
   (先选文档，再生成整条)

 RAG-Token:     Π_t Σ_z [ p_η(z|x) · 生成(token_t|z) ]
        z1 ─►(0.9, 0.9)┐
                         ├─ token1:0.78, token2:0.84 → 乘积
        z2 ─►(0.5, 0.7)┘
   (每个 token 都可加权不同文档)
```

### 流程步骤（RAG）

1. 输入：问题 `x` 。
2. 检索： `p_η(z|x)` 取 top-k 文档。
3. 拼接：把 `(x, z_i)` 送入生成器。
4. 生成：按 (7-1)/(7-2) 边缘化得到答案分布。
5. 输出：答案（可附出处）。

**R6 核心源码（ `rag/repro/rag_marginalize.py` ，(A) 机制复现）**

```python
def rag_sequence(p_z, p_y_given_z):
    """p_z: 检索权重; p_y_given_z: 每篇文档生成整条答案的概率"""
    return sum(pz * py for pz, py in zip(p_z, p_y_given_z))

def rag_token(p_z, token_probs):
    """token_probs[z] = [p(token1|z), p(token2|z), ...]"""
    num_tokens = len(token_probs[0])
    total = 1.0
    for t in range(num_tokens):
        total *= sum(pz * token_probs[z][t] for z, pz in enumerate(p_z))
    return total

if __name__ == "__main__":
    p_z = [0.7, 0.3]
    # Sequence: 每篇生成整条答案的概率
    p_y_given_z = [0.8, 0.4]
    print("RAG-Sequence:", round(rag_sequence(p_z, p_y_given_z), 3))
    # Token: 每篇生成两个 token 的概率
    token_probs = [[0.9, 0.9], [0.5, 0.7]]
    print("RAG-Token:", round(rag_token(p_z, token_probs), 3))
```

### 1.8 ANN 索引：HNSW / IVF-PQ / ScaNN / DiskANN

### 出现理由

DPR 时代，语料可达亿级段落；逐个计算内积是 `O(N·d)` ，完全不可行。需要在 **可接受的召回损失** 下把检索降到亚线性——这就是 **近似最近邻（ANN）** 。

### 事实陈述

- HNSW：Malkov & Yashunin，2016/2018，arXiv:1603.09320。
- PQ（乘积量化）：Jégou 等，2011。
- ScaNN：Guo 等，2020。
- DiskANN：Subramanya 等，2019（NeurIPS）。

### 原理（P1–P10）

**P1 形式化定义**

- 给定查询 `q` 与向量集 `X={x_1,…,x_N}` ，精确最近邻为 `argmin_i ||q − x_i||` （或 `argmax_i q·x_i` ）。
- ANN 返回 `k` 个近似结果，用 **召回率** 衡量： `Recall@k = |ANN@k ∩ 精确@k| / k` 。

**P2 核心结构与公式**

- **HNSW** ：多层图。第 `ℓ` 层的每个点连接 `M_ℓ` 个近邻；点出现在第 `ℓ` 层的概率按指数衰减（如 `P(level ≥ ℓ) = e^{−ℓ}` ）。搜索从顶层贪心下降，到底层用宽度 `efSearch` 的候选池。
- **IVF** ：用 k-means 把向量聚成 `nlist` 个簇，查询只搜索最近的 `nprobe` 个簇。
- **PQ** ：把 `d` 维向量切成 `m` 段，每段用一张 `2^{nbits}` 码本量化；用 **非对称距离计算（ADC）** 通过查表近似距离。
- **ScaNN** ：量化时按 **内积方向** 加权误差（各向异性），对 MIPS 更友好。
- **DiskANN** ：把 Vamana 图索引放在 SSD 上，以少量内存 + 磁盘 IO 完成十亿级检索。

**P3 推导（为何近似有效 / 误差从哪来）**

- **HNSW 的贪心为何有效** ：图具”小世界”性质——任意两点间存在短路径，且每层是下层的粗粒度”导航图”。从顶层向下贪心，每步移动到更近的邻居，可在 `O(log N)` 量级逼近目标。 **风险** ：贪心可能陷入局部最优（漏掉真正最近邻），故用 `efSearch` 扩大候选池，以延迟换召回。
- **PQ 的误差** ： `x` 被替换为最近的码字 `x̂` ，距离 `||q−x|| ≈ ||q−x̂||` 。误差上界与 **量化误差** `||x−x̂||` 相关； `m` 越大、 `nbits` 越多，误差越小但存储越大。ADC 用查表把”每对 (q_seg, codeword_seg)“的距离预存，避免逐维计算。
- **IVF 的召回** ：真实最近邻若落在未被访问的簇，就漏召回； `nprobe` 越大召回越高、延迟越大。

**P4 假设与成立条件**

- 假设向量分布可聚类（IVF）或可低维逼近（PQ）。
- 假设”近似可接受”——ANN **不保证** 返回真实最近邻。

**P5 参数敏感性**

| 算法 | 关键参数 | 影响 |
| --- | --- | --- |
| HNSW | M（邻居数） | 越大召回越高、内存越大 |
| HNSW | efConstruction | 建图质量 |
| HNSW | efSearch | 查询时候选池，越大召回越高、越慢 |
| IVF | nlist / nprobe | 簇数 / 探测簇数 |
| PQ | m / nbits | 分段数 / 每段比特 |

**P6 复杂度**

- HNSW 查询近似 `O(log N)` ；建索引 `O(N·M·log N)` 。
- IVF 查询 `O(nprobe·(N/nlist))` ；PQ 距离用查表 `O(m)` 。

**P7 推导级差异**

- **图法（HNSW）** ：召回高、内存大、需常驻内存。
- **量化法（PQ）** ：内存极小（压缩数十倍）、召回略低。
- **磁盘法（DiskANN）** ：内存小、可十亿级，但依赖 SSD 吞吐。

**P8 边界与常见误解**

- 误解：以为 ANN 结果是”最相似的 k 个”——它是 **近似** ，可能漏掉真最近邻。
- 边界：召回-延迟-内存构成”不可能三角”，必须按场景取舍。

**P9 数值手算示例**

1. **PQ 压缩比** ：8 维 `float32` 向量 = `8×4 = 32` 字节。取 `m=2` 段、 `nbits=8` （每段 256 码字，用 1 字节编码）→ 存储 `2` 字节。压缩比 `32/2 = 16×` 。
2. **IVF 召回直觉** ： `N=100万` ， `nlist=1000` ，每簇约 1000 点。若真实最近邻落在前 10 个最近簇中的概率为 0.95，则 `nprobe=10` 的 `Recall@1` 上限约 **0.95** ； `nprobe=1` 时可能降到约 0.6。
3. **HNSW 的 efSearch** ：经验上 `efSearch` 从 16 → 64， `Recall@10` 可从约 0.70 → 0.95，但查询延迟约线性上升。

**P10 可视化**

```text
   L2:  ●───────●────────●            ← 粗导航
        │        │
```

```python
import numpy as np, faiss, time

d, nb, nq, k = 128, 50000, 200, 10
rng = np.random.default_rng(42)
xb = rng.standard_normal((nb, d)).astype("float32")
xq = rng.standard_normal((nq, d)).astype("float32")

# 精确检索(基线)
flat = faiss.IndexFlatL2(d); flat.add(xb)
_, gt = flat.search(xq, k)

def evaluate(name, index, nprobe=None, efSearch=None):
    if nprobe is not None and hasattr(index, "nprobe"):
        index.nprobe = nprobe
    if efSearch is not None and hasattr(index, "hnsw"):
        faiss.ParameterSpace().set_index_parameter(index, "efSearch", efSearch)
    t = time.time()
    _, I = index.search(xq, k)
    ms = (time.time() - t) / nq * 1000
    recall = np.mean([len(set(I[i]) & set(gt[i])) / k for i in range(nq)])
    print(f"{name}: Recall@{k}={recall:.3f}, {ms:.2f} ms/query")

# IVF-PQ
quant = faiss.IndexFlatL2(d)
ivfpq = faiss.IndexIVFPQ(quant, d, 256, 16, 8)   # nlist=256, m=16, nbits=8
ivfpq.train(xb); ivfpq.add(xb)
evaluate("IVF-PQ(nprobe=8)", ivfpq, nprobe=8)

# HNSW
hnsw = faiss.IndexHNSWFlat(d, 32)                # M=32
hnsw.add(xb)
evaluate("HNSW(efSearch=64)", hnsw, efSearch=64)
```

> **【连贯】** 第 1 章备好了”检索”（BM25/DPR/ANN）与”检索+生成”的耦合范式（REALM/RAG/FiD）。本章把它们拼成 **工程化的三段式** ，并检验它会暴露哪些坑——这些坑定义了后面每一代技术的存在理由。

### 2.1 三段式流水线（Indexing → Retrieval → Generation）

### 出现理由

RAG 论文（Lewis 等, 2020）证明”检索+生成”联合可行，但它是一个训练框架，不是一个工程骨架。工业界需要一个 **可落地、可维护** 的通用流程：把”准备资料”与”在线问答”分离，从而把昂贵的编码计算放到离线。

### 事实陈述

Lewis 等（2020, NeurIPS, arXiv:2005.11401）提出 RAG；三段式作为工程范式由 LangChain（ `RetrievalQA` ）与 LlamaIndex（ `VectorStoreIndex` ）在 2023 年推广。本仓库 `../../rag/rag_test.py` 即该范式的实现。

### 原理（P1–P10）

**P1 形式化定义**

- 文档集 `D = {d_1,…,d_N}` ；分块函数 `chunk(·)` ，把每篇文档切成块集合 `C = {c_1,…,c_M}` ；
- 编码器 `E(·)` （把文本映射到 `R^d` ）；相似度 `sim(a,b)` （内积或余弦）；
- 生成器 `G(x, C_k)` 。
- 检索结果： `C_k = topK_{c∈C} sim(E(x), E(c))` 。
- 答案： `y = G(x, C_k)` 。

**P2 核心公式**

```text
y = G( x, topK_{c ∈ C} sim( E(x), E(c) ) )                              (2-1)

余弦相似度： sim(a,b) = (a·b) / (||a||·||b||)                            (2-2)
```

**P3 推导（为何”先建库后检索”能省成本）**

- 若不做预计算，每次查询都要对全部 `N` 篇文档编码并比较：在线成本 `O(N·L_enc)` （ `L_enc` 为编码单篇的算力）。
- 三段式把编码移到 **离线** ：一次 `O(N·L_enc)` 建库；在线只需编码查询 `O(L_enc)` + ANN `O(log N)` 。
- 结论：省成本的关键是” **把与查询无关的计算提前做掉** “。式(2-1) 中 `E(c)` 与 `x` 无关，故可预计算。

**P4 假设与成立条件**

- **块自洽假设** ：一个块能被独立理解（不依赖前后文）。
- **单跳假设** ：答案依据落在少数几个块中。
- **相似度≈相关性假设** ：向量更近者更相关。

**P5 参数敏感性**

- `chunk_size` ：过小 → 语义不完整；过大 → 噪声多、精度降。
- `overlap` ：块间重叠，缓解”答案跨边界被切断”。
- `top_k` ：过大 → 召回高但噪声多、上下文超长；过小 → 漏证据。

**P6 复杂度**

- 建库： `O(N)` 次编码（离线，一次性）。
- 在线： `O(L_enc)` （查询编码）+ `O(log N)` （ANN，见 1.8）。

**P7 推导级差异**

- vs「全量塞入长上下文」（第 8.2 节）：三段式的在线成本与资料总量 `N` **弱相关** （只取 `k` 个块），而全量入窗的成本与 `N` **强相关** （ `O(L²)` 注意力）；三段式可 **增量更新** （改一个块只动索引局部），全量需重传。

**P8 边界与常见误解**

- 误解：以为 `top_k` 越大越好——实际会引入噪声并触发”Lost in the Middle”（2.2）。
- 边界：多跳、表格、超长文档、需要全局摘要的任务，三段式均失效。

**P9 数值手算示例** 设查询向量（已归一化） `E(x) = q = (1, 0)` ，5 个块（已归一化）：

```text
c1: 年假制度说明        E(c1) = (1.00, 0.00)
c2: 请假申请流程        E(c2) = (0.80, 0.60)
c3: 年假天数与工龄      E(c3) = (0.60, 0.80)
c4: 报销流程            E(c4) = (0.00, 1.00)
c5: 加班调休            E(c5) = (-1.0, 0.00)
```

按式(2-2) 手算余弦：

- `c1: (1·1+0·0)/(1·1) = 1.00`
- `c2: (1·0.8+0·0.6)/1 = 0.80`
- `c3: 1·0.6 = 0.60`
- `c4: 1·0 = 0.00`
- `c5: 1·(−1) = −1.00`

排序： `c1 > c2 > c3 > c4 > c5` 。取 `top_k=3` → `{c1, c2, c3}` ，正好是”年假/请假”相关块。 **注意** ： `c5` （加班调休）得负分——说明方向相反的向量会被”推开”，这是余弦的特性。

**P10 可视化**

```text
┌───────────── 离线(Indexing) ─────────────┐   ┌──── 在线(Query) ────┐
  │ 文档 ─► 解析 ─► 分块(chunk) ─► 编码(E) ─► │   │ 查询 x ─► 编码 E(x) │
  │                    │                     │   │        │            │
  │                    ▼                     │   │        ▼            │
  │              ┌───────────┐               │   │   ┌─────────┐       │
  │              │ 向量库(ANN)│◄──────────────┼───┼───│ top-k 检索│      │
  │              └───────────┘               │   │   └────┬────┘       │
  └──────────────────────────────────────────┘   │        ▼            │
                                                  │  拼( x + C_k ) ─► G ─► y
                                                  └──────────────────────┘
```

### 流程步骤

1. 输入：文档集 `D` 、查询 `x` 、参数 `chunk_size/overlap/top_k` 。
2. 解析与分块： `D → C = chunk(·)` 。
3. 编码入库： `{E(c) : c ∈ C}` 存入向量库（建 ANN 索引）。
4. 查询编码： `E(x)` 。
5. 检索：ANN 取 `top_k` 块 `C_k` 。
6. 组装提示：把 `x` 与 `C_k` 拼成 prompt。
7. 生成： `y = G(x, C_k)` （可选附出处）。

**R6 核心源码（ `rag/repro/ch2_naive/naive_rag.py` ）**

```python
import argparse, json, os
from sentence_transformers import SentenceTransformer
import chromadb

DOCS = [
    "公司年假制度：员工入职满一年可享年假五天，需在系统提交申请并经理审批。",
    "年假天数随工龄递增，满三年增至十天，满五年增至十五天。",
    "请假流程：调休需提前一天申请；病假需提供医院证明。",
    "报销流程：发票粘贴后提交财务，通常两周内到账。",
    "加班可折算调休，调休有效期三个月。",
    "员工离职时未休年假可按日薪折算结算。",
]

def main():
    ap = argparse.ArgumentParser(); ap.add_argument("--top_k", type=int, default=3)
    a = ap.parse_args()
    model = SentenceTransformer("shibing624/text2vec-base-chinese")

    # 1) 编码入库
    client = chromadb.EphemeralClient()
    col = client.get_or_create_collection("policy")
    embs = model.encode(DOCS, normalize_embeddings=True).tolist()
    col.add(documents=DOCS, embeddings=embs, ids=[str(i) for i in range(len(DOCS))])

    # 2) 检索
    query = "年假怎么请？"
    q = model.encode([query], normalize_embeddings=True).tolist()
    res = col.query(query_embeddings=q, n_results=a.top_k)
    hits = res["documents"][0]
    dists = res["distances"][0]

    # 3) “生成”（离线：拼接模板，避免依赖网络/API）
    answer = "根据以下资料回答：\n" + "\n".join(f"- {h}" for h in hits)
    out = {"query": query, "hits": hits, "distances": [round(d,4) for d in dists], "answer_template": answer}
    os.makedirs("rag/repro/ch2_naive/out", exist_ok=True)
    json.dump(out, open("rag/repro/ch2_naive/out/naive_result.json","w"), ensure_ascii=False, indent=2)
    print(json.dumps(out, ensure_ascii=False, indent=2))

if __name__ == "__main__":
    main()
```

### 2.2 关键失败模式

### 出现理由

要改进系统，先要知道它 **会在哪里坏** 。三段式虽可用，却有一组系统性的失败模式；后续所有技术都可以被视为”针对某一种失败模式的补丁”。因此本节是全书后续章节的”靶子清单”。

### 事实陈述

- **Lost in the Middle** ：Liu 等（2023, TACL, arXiv:2307.03172）——关键信息放在长上下文 **中部** 时，模型准确率显著下降。
- 事实性/幻觉的系统化度量：RAGAS（Es 等, 2023, arXiv:2309.15217）。
- 抗噪评测：RGB 基准（Chen 等, 2023, arXiv:2309.01431）。

### 原理（P1–P10）

**P1 形式化定义** 把 RAG 视为串联系统 `S = G ∘ Post ∘ Ret ∘ Pre` 。定义每个环节的 **信息保持率** `p_i ∈ [0,1]` （进入该环节的相关信息，有多少被完整、正确地传递到下一环节）。失败模式即某 `p_i` 显著下降。

**P2 核心公式**

```text
端到端信息保持率 ≈ Π_i p_i        (2-3)
```

（假设各环节近似独立；这是”木桶效应”的形式化。）

**P3 推导（为何最弱一环主导）**

- 若 `p_Ret = 0.5` 、其余各 0.95： `Π p_i = 0.5×0.95×0.95×0.95 ≈ 0.43` 。
- 反之，若检索 `p_Ret = 0.95` 、生成 `p_Gen = 0.5` ： `≈ 0.43` 。
- **结论** ：无论哪一环塌陷，端到端都塌陷；且 **改善最弱一环的边际收益最大** 。这就是”90% 的效果问题出在检索”的数学直觉来源之一（检索往往是最弱环）。

**P4 假设与成立条件**

- 各环节近似独立（实际存在耦合，如检索噪声会放大生成幻觉）。
- 假设”相关信息可被有限 `k` 个块覆盖”。

**P5 参数敏感性**

- `top_k` 双向影响： `↑` 提升 `p_Ret` （少漏），但降低 `p_Gen` （噪声、中间遗忘）。
- 块大小同理：小块精度高但完整性低。

**P6 复杂度**

- 诊断成本：固定 `G` ，分别扰动检索（换嵌入/top_k）与上下文（加/去重排），观察端到端指标变化，定位瓶颈环节。每次实验 `O(查询数)` 次推理。

**P7 推导级差异**

- **检索失败** ：相关块未被召回 → 无论生成多强都无解。
- **生成失败** ：相关资料已在上下文，但模型未采纳/被噪声带偏 → 需约束忠实度或压缩噪声。
- 二者 **修法不同** （改检索器 vs 改提示/后处理），故必须区分。

**P8 边界与常见误解**

- 误解：把”检索到相关资料但答错”当成检索问题——实为生成问题。
- 边界：当上下游强耦合时， `Π p_i` 会低估损失（噪声传播）。

**P9 数值手算示例（Lost in the Middle 的位置效应）** 把一段关键证据分别放在 10 个块的第 1、5、10 位，其余为干扰块。假设模型对第 `pos` 位证据的”采纳率”近似为一条 U 形函数（两端高、中间低）： `f(1)=0.95, f(5)=0.55, f(10)=0.90` 。

- **结论** ：同一份资料， **位置不同，端到端质量差近 0.4** 。这解释了为什么”重排序（第 3.3.5 节）”是低成本高回报的优化。

```python
import json, os
import numpy as np

# 模拟“模型对第 pos 位关键信息的采纳率”为 U 形（示意，非真实模型）
def adopt_rate(pos, n):
    x = (pos - 1) / (n - 1)          # 0..1
    return 0.55 + 0.40 * (2 * x - 1) ** 2   # 两端高，中部低

def main():
    n = 10
    key = "关键证据：年假需在系统提交申请并经理审批。"
    distract = [f"干扰块{i}" for i in range(1, n)]
    results = {}
    for pos in range(1, n + 1):
        ctx = distract[:pos-1] + [key] + distract[pos-1:]
        results[pos] = round(adopt_rate(pos, n), 3)
    worst = min(results, key=results.get)
    out = {"n": n, "adopt_by_position": results, "worst_position": worst}
    os.makedirs("rag/repro/ch2_naive/out", exist_ok=True)
    json.dump(out, open("rag/repro/ch2_naive/out/position_result.json","w"), ensure_ascii=False, indent=2)
    print(json.dumps(out, ensure_ascii=False, indent=2))

if __name__ == "__main__":
```

### 2.3 与纯 LLM / 纯微调的定位对比

### 出现理由

RAG 不是唯一的知识注入方式。选错工具会造成资源浪费（如为一个只需改风格的场景去搭建复杂检索）。

### 事实陈述

Lewis 等（2020）确立 RAG 路线；微调/检索对比实践在 2023–2025 年形成共识（RAG 管知识、微调管风格/格式）。

### 原理（P1–P10）

**P1 形式化定义**

- 参数化知识：存储在模型权重中的知识（微调改变之）。
- 非参数化知识：存储在外部库中、检索时注入的知识（RAG 改变之）。
- 三个决策维度： **知识时效性** `T` 、 **可溯源要求** `A` 、 **成本** `C` 。

**P2 核心公式（成本模型）**

```text
RAG 月成本  ≈ 建库一次性 N·c_enc  +  月度 查询量 × (检索c_ret + 生成c_gen)
微调月成本  ≈ 训练一次性 D·c_train  +  月度 查询量 × c_inf     (需重复，当知识更新)
```

**P3 推导**

- 知识每月更新 `ΔN` 条时：

- 因此： **知识更新越频繁，RAG 越划算** ；反之，若知识几乎不变、但要求固定格式/风格，则微调更优。

**P4 假设与成立条件**

- 知识可外置、可被检索覆盖。
- 微调数据充分且质量可控。

**P5 参数敏感性**

- `ΔN` （更新频率）与 `D` （微调数据量）决定分界线。

**P6 复杂度**

- RAG 更新 `O(ΔN)` ；微调更新 `O(D)` 训练。

**P7 推导级差异**

- 二者 **不是二选一** ：常组合——用微调固定”风格/格式/领域术语”，用 RAG 注入”时效知识”。RAG 管”知道什么”，微调管”怎么说”。

**P8 边界与常见误解**

- 误解：以为微调能让模型”学到新事实”——效果有限且易过时； **新事实更适合 RAG** 。
- 边界：需要强推理（非知识）的问题，二者皆非最优。

**P9 数值手算示例** 设：知识 1000 条、每月新增 100 条；编码一条成本 `c_enc=0.001` 元；微调一次 `c_train=5` 元/条 × 1000 条 = 5000 元。

- RAG 每月增量成本： `100 × 0.001 = 0.1` 元。
- 微调每月重训： `1000 × 5 = 5000` 元。
- **比值 ≈ 50000:1** 。→ 高频更新场景，RAG 完胜。
- 反之，若知识 0 更新、只要求输出统一 JSON 格式：微调一次 ~ 几十元即可长期使用，而 RAG 每条查询都要额外检索+更长的 prompt，成本更高。

**P10 可视化**

```text
可溯源要求 A
            ▲
     高     │   [RAG]        [RAG + 溯源]
            │
     低     │   [直接答/微调] [微调+RAG]
            └────────────────────────► 知识时效性 T
               低                高
   （越靠右上，越应选 RAG；左下可选微调/直接答）
```

### 流程步骤

1. 明确三问：知识 **多久变** ？是否 **必须可溯源** ？ **成本预算** 多少？
2. 若知识高频变/需溯源 → RAG。
3. 若只需固定格式/风格 → 微调（或提示工程）。
4. 若两者都要 → 微调模型 + RAG 混合。
5. 输出：方案与成本估算。

**R6 核心源码（ `cost_estimator.py` ）**

```python
import argparse
def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--n", type=int, default=1000)      # 知识总条数
    ap.add_argument("--delta", type=int, default=100)   # 每月新增条数
    ap.add_argument("--c_enc", type=float, default=0.001)  # 单条编码成本
    ap.add_argument("--c_train", type=float, default=5.0)  # 单条微调成本
    a = ap.parse_args()
    rag_month = a.delta * a.c_enc
    ft_month = a.n * a.c_train
    print(f"RAG 每月增量成本 = {rag_month:.3f} 元")
    print(f"微调每月重训成本 = {ft_month:.3f} 元")
    print(f"比值 = {ft_month/rag_month:.0f} : 1")
if __name__ == "__main__":
    main()
```
