## AI Agent 应用（demo）

前几个demo里模型会说话、会查资料、会调函数。这个让它**自己把一件事做完**——多步、有状态、中途没人指挥。

### 写在前面

```text
  1、AI Agents 让 LLM 通过拥有 **state** 和 **tools** 来完成任务，而且让每一步都看得见。
  2、demo 不装任何框架，把内核写出来，然后把一些框架的招牌做法各自落成一个能跑的小脚本，就知道框架在替我们做什么了。
  3、工具不能全塞给LLM ：**贵**（每个 schema 都占 token）、**乱**（选项多容易选错）、**慢**。要留个白名单永远可用，因为检索会漏，核心能力不能靠运气。
  4、一个任务能不能变成模型动态规划，看三个条件：
      步骤结构是否可变：每次执行需要的步骤数、顺序是否不同。如果每次都一样，工作流就够了。
      失败代价是否可接受：模型规划错了，后果是“多跑几步”，还是“资金损失、合规事故”。前者可以试，后者不行。
      是否需要可审计：出了问题，需不需要追溯到“哪一步为什么这么走”。动态规划的路径是模型生成的，追溯成本高；工作流的路径是写死的，天然可审计。
  5、真实系统是分层的
      外层用工作流：保证关键步骤的顺序、合规检查、人工审批点。这部分不能动态。
      内层用任务图或循环：在某个节点内部，允许模型根据情况动态拆解子任务。这部分可以灵活。
  6、企业工作流不会“都变成动态规划”，而是“把适合动态的部分交给 Agent，把必须确定的部分留给工作流”。
  7、循环式：灵活，能根据中间结果改主意；但容易跑偏、难控成本。任务图：路线先定好，可并行、成本可预估；但中途发现需求变了不好改。
```

```python
  def run(
    task: str,
    *,
    on_event: EventHook | None = None,
    tool_top_k: int | None = None,
    use_plan: bool = True,
    use_experience: bool = True,
  ) -> AgentState:
    """跑一个任务，直到模型说完成，或者撞上预算上限。"""
    state = AgentState(task=task)

    def emit(event: dict[str, Any]) -> None:
        if on_event is not None:
            on_event(event)

    if use_plan:
        # 先规划，把计划记进 state ，并汇报出去。
        state.plan = plan_steps(task)
        emit({"type": "plan", "plan": state.plan})

    system = SYSTEM
    # 最近3条跑过的任务摘要
    if use_experience:
        hint = experience_hint(load_experience())
        if hint:
            # 把上次的经验压成一句话，拼进 system message。
            system = system + "\n\n" + hint

    messages: list[dict[str, Any]] = [
        {"role": "system", "content": system},
        {"role": "user", "content": "任务：" + task},
    ]

    while True:
        # 检查 步数上限、工具调用上限、token预算
        reason = state.over_budget()
        if reason:
            state.stopped_reason = reason
            emit({"type": "limit", "reason": reason})
            state.answer = "停在预算上限了（" + reason + "）。已完成 " + str(len(state.steps)) + " 步。"            
            return state
        
        # 按任务文本检索工具，不是把所有工具都塞进去。 这是"工具太多"问题的工程解法。
        selected, ranking = select_tools(task, top_k=tool_top_k)
        state.steps_used += 1

        try:
            reply = chat(messages, tools=selected)
        except DeepSeekError as exc:
            state.stopped_reason = "模型调用失败：" + str(exc)
            emit({"type": "error", "message": str(exc)})
            return state

        state.tokens += reply.total_tokens

        # 汇报"模型这一步做了什么、给了它哪些工具、花了多少 token"。
        emit({
            "type": "model",
            "step": state.steps_used,
            "content": reply.content,
            "tool_calls": [call.to_dict() for call in reply.tool_calls],
            "tools_offered": [schema["function"]["name"] for schema in selected],
            "tokens": reply.total_tokens,
            "elapsed": round(reply.elapsed, 2),
        })

        if not reply.tool_calls:
            state.answer = reply.content
            state.add(Step(index=state.steps_used, kind="final", detail=reply.content[:200]))
            emit({"type": "final", "answer": reply.content})
            # 模型不调工具了，说明它认为任务完成，循环结束。
            return state
      
        # 把模型的调用意图塞回历史。
        messages.append({
            "role": "assistant",
            "content": reply.content or "",
            "tool_calls": [call.to_dict() for call in reply.tool_calls],
        })

        for call in reply.tool_calls:
            state.tool_calls += 1
            # 执行模型指定的工具
            outcome = tools.dispatch(call.name, call.arguments)

            try:
                arguments = json.loads(call.arguments) if call.arguments.strip() else {}
            except ValueError:
                arguments = {"_raw": call.arguments}

            payload = json.dumps(
                outcome["result"] if outcome["ok"] else {"error": outcome["error"]},
                ensure_ascii=False,
            )

            # 执行工具，按 tool_call_id 回填结果。
            messages.append({"role": "tool", "tool_call_id": call.id, "content": payload})

            if outcome["ok"] and call.name == "save_note":
                saved = (outcome["result"] or {}).get("saved")
                if saved:
                    # 如果保存了笔记，把路径记进 artifacts。
                    state.add_artifact(str(saved))
            
            state.add(Step(
                index=state.steps_used,
                kind="tool",
                tool=call.name,
                arguments=arguments if isinstance(arguments, dict) else {},
                ok=outcome["ok"],
                observation=payload[:300],
            ))

            emit({
                "type": "tool",
                "step": state.steps_used,
                "name": call.name,
                "arguments": arguments,
                "ok": outcome["ok"],
                "error": outcome["error"],
                "result": outcome["result"],
```

### 第 2 步：工具要检索，不能一股脑塞

TaskWeaver 的做法是：把插件**存成向量**，让 LLM 按语义检索该用哪个。为什么不能全塞：**贵**（每个 schema 都占 token）、**乱**（选项多容易选错）、**慢**。

这个项目用「IDF 加权的词法打分」代替向量（省一个 embedding 依赖），并且把**命中词**也打印出来——这就是 visibility，不然它选错你根本查不出来：

```text

======================================================================

  read_note(name)
  search_notes(query)
  save_note(name, content)
  calc(expression)
  text_stats(text)
  today()
  quick_summary(text, max_chars)
```

```python
    def plan_graph(task: str) -> list[dict[str, Any]]:
      """让模型把任务拆成带依赖的图。解析失败就退化成一条直线。"""
      reply = chat(
          [
              {"role": "system", "content": "你是一个善于做任务分解的规划器。"},
              {"role": "user", "content": "任务：" + task + "\n\n" + GRAPH_PROMPT},
          ],
          # 温度设低 （0.2） ，因为规划是"结构化输出"，不需要创造性。
          temperature=0.2,
          max_tokens=500,
      )
      ...
      cleaned: list[dict[str, Any]] = []
      for index, item in enumerate(nodes, 1):
          ...
          cleaned.append({
              "id": node_id,
              "task": str(item.get("task") or "").strip() or ("步骤 " + str(node_id)),
              "dep": deps,
          })

      return cleaned or [{"id": 1, "task": task, "dep": []}]
      
    def execution_order(nodes: list[dict[str, Any]]) -> list[list[dict[str, Any]]]:
      """按依赖排出批次：同一批里的节点互不依赖，可以并行。"""

      remaining = list(nodes)
      finished: set[int] = set()
      batches: list[list[dict[str, Any]]] = []

      while remaining:
          # 找出所有依赖都已完成的节点。它们是这一批可以一起跑的。
          ready = [node for node in remaining if all(dep in finished for dep in node["dep"])]
          if not ready:
              # 出现环，或者依赖了不存在的节点：把剩下的塞一批，别把程序卡死。这是"优雅降级"——依赖关系有问题也不能让执行器死循环。
              batches.append(remaining)
              break
          batches.append(ready)
          finished.update(node["id"] for node in ready)
          # 把这一批标记为完成，从剩余列表里移除，继续下一批。
          remaining = [node for node in remaining if node["id"] not in finished]

      return batches

    def execute(
        nodes: list[dict[str, Any]],
        *,
        tools: list[dict[str, Any]] | None = None,
        on_event: Callable[[dict[str, Any]], None] | None = None,
    ) -> tuple[list[dict[str, Any]], dict[int, str]]:
        """按批次执行整张图，返回 (每步结果, id 到输出的映射)。"""

        results: list[dict[str, Any]] = []
        # context 存每个节点的输出，供下游节点读取。
        context: dict[int, str] = {}

        for batch_index, batch in enumerate(execution_order(nodes), 1):
          
            if on_event is not None:
                # 汇报"这一批有哪些节点、是否可并行"。
                ...

            for node in batch:
                try:
                    # 执行一个节点。把上游节点的结果作为上下文喂进去。
                    result = run_node(node, context, tools=tools)
                except DeepSeekError as exc:
                    # 单个节点失败不中断整张图，记录失败原因后继续。
                    result = {
                        "id": node["id"],
                        "task": node["task"],
                        "dep": node["dep"],
                        "output": "执行失败：" + str(exc),
                        "tokens": 0,
                    }
                context[node["id"]] = result["output"]
                results.append(result)
                if on_event is not None:
                    # 汇报"这个节点执行完了，输出是什么"。
                    on_event({"type": "node", **result})

        return results, context
```

### 预算：agent 必须有刹车

agent 会自己转圈，所以 `config.py` 里设了三道闸：

```text
AGENT_MAX_STEPS=8          最多几轮
AGENT_MAX_TOOL_CALLS=12    最多调几次工具
AGENT_MAX_TOKENS=20000     最多花多少 token
```

撞上任一道就停下来，并在 `state.stopped_reason` 里写明原因。没有刹车的 agent 就是一台会自己烧钱的机器。

### 常见问题

**它不调工具、直接自己编怎么办？** system 里写死”需要信息就调工具，不要编造”（本项目已经写了）。还不行就检查工具的 `description` 是不是太含糊。

**跑着跑着停了？** 看 `stopped_reason`。多半是撞了预算上限，调大 `AGENT_MAX_STEPS` 就行。

**`memory/experience.json` 是干什么的？** 记录跑过的任务，下次开工时会把最近几次的摘要塞进 system message，这就是 TaskWeaver 的 `experience` 概念。
