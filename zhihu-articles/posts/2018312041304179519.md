本文分析Triton教程的前三个算子的主要部分。

先看第一个kernel：向量加法

相关定义：

x_ptr, y_ptr, output_ptr: 指向GPU内存的指针，分别对应输入向量x、输入向量y和输出向量。n_elements: 向量中元素的总数量。BLOCK_SIZE: tl.constexpr: 编译时常量，定义每个线程块处理的元素数量。

```text
pid = tl.program_id(axis=0)  
block_start = pid * BLOCK_SIZE
offsets = block_start + tl.arange(0, BLOCK_SIZE)
mask = offsets < n_elements
x = tl.load(x_ptr + offsets, mask=mask)
y = tl.load(y_ptr + offsets, mask=mask)
output = x + y
tl.store(output_ptr + offsets, output, mask=mask)
```

pid 获取当前线程块在x轴上的索引，即blockIdx.x。block_start 计算当前线程块的起始位置。tl.arange(0, BLOCK_SIZE) 创建从0到BLOCK_SIZE-1的连续整数序列，加上block_start后，得到当前块要处理的全局索引数组。例如：BLOCK_SIZE=256，pid=1，则表示第一个块要处理 offsets = [256, 257, ..., 511]。

当数据总量不是BLOCK_SIZE的整数倍时，使用 mask 去除超出的偏移量。从全局内存加载x和y向量的数据，使用掩码确保只加载有效元素（越界位置不会加载）。执行向量加法（逐元素相加）。将结果存储回全局内存。

然后看第二个kernel：Softmax。

相关定义：

output_ptr, input_ptr: 输出和输入张量的GPU内存指针。input_row_stride, output_row_stride: 行跨度，表示从一行到下一行的元素偏移量（通常等于n_cols）。n_rows, n_cols: 矩阵的行数和列数。BLOCK_SIZE: tl.constexpr: 编译时常量，每个线程块处理的列数。num_stages: tl.constexpr: 流水线阶段数，用于优化内存访问。

```text
row_start = tl.program_id(0)
row_step = tl.num_programs(0)
for row_idx in tl.range(row_start, n_rows, row_step, num_stages=num_stages):
    row_start_ptr = input_ptr + row_idx * input_row_stride
    col_offsets = tl.arange(0, BLOCK_SIZE)
    input_ptrs = row_start_ptr + col_offsets
    mask = col_offsets < n_cols
    row = tl.load(input_ptrs, mask=mask, other=-float('inf'))
```

tl.program_id(0): 获取当前程序（线程块）的ID。tl.num_programs(0): 获取程序的数目（与CUDA中 blockDim.x 线程块数目类似），从row_start开始，步长为row_step。例如：有4个程序，程序0处理行0,4,8...；程序1处理行1,5,9...

row_start_ptr: 计算当前行的起始地址，input_row_stride可理解为有多少列，col_offsets: 创建从0到BLOCK_SIZE-1的列偏移。mask: 边界掩码，最后一行的列数可能不是BLOCK_SIZE的整数倍，对于超出边界的元素，填充负无穷other=-float('inf')（确保softmax计算中这些位置贡献为0）

```text
row_minus_max = row - tl.max(row, axis=0)
numerator = tl.exp(row_minus_max)
denominator = tl.sum(numerator, axis=0)
softmax_output = numerator / denominator
output_row_start_ptr = output_ptr + row_idx * output_row_stride
output_ptrs = output_row_start_ptr + col_offsets
tl.store(output_ptrs, softmax_output, mask=mask)
```

这是标准的数值稳定softmax实现：

1. 减去最大值: row - max(row) 防止指数爆炸；2. 指数运算: exp(x - max)；3. 求和: 计算分母（归一化常数）；4. 除法: 得到概率分布。最后存储结果计算输出行的起始地址，使用相同的列偏移和掩码存储结果。

接着看第三个kernel：矩阵乘法

这里有一个分块的思想，看下面的图。上面的方式需要读取90个块，而下面的只需要读54个块。下面分析分块后的一些参数。

```text
pid = tl.program_id(axis=0)
num_pid_m = tl.cdiv(M, BLOCK_SIZE_M)
num_pid_n = tl.cdiv(N, BLOCK_SIZE_N)
num_pid_in_group = GROUP_SIZE_M * num_pid_n

group_id = pid // num_pid_in_group
first_pid_m = group_id * GROUP_SIZE_M
group_size_m = min(num_pid_m - first_pid_m, GROUP_SIZE_M)

pid_m = first_pid_m + ((pid % num_pid_in_group) % group_size_m)
pid_n = (pid % num_pid_in_group) // group_size_m
```

num_pid_m 和 num_pid_n 分别得到矩阵长宽两个维度各自分成多少个小块.图中一个矩阵分成了9x9个小块。num_pid_in_group 是说1个group 里总共有多少个小块。对图中下面的A矩阵来说（黄色框 ）高是3，宽是9。

![](https://pica.zhimg.com/v2-cbdfd66a87bdc93d1bf59cdfc7741e84_r.jpg)

group_id 当前的这次 "循环", 是在第几个group内。比如图中A矩阵的黄色小块都在第一个。first_pid_m 当前所在的 group 中的第一个黄色小块, 它在全局m维度是第几个黄色小块 。group_size_m是因为有时最后一个group的m维度不到GROUP_SIZE_M。假设图中不是9行，而是8行，那最后一个group_size_m就取2。

pid_m是当前程序在全局 M 方向上的索引，pid_n是当前程序在全局 N 方向上的索引

下面开始计算，为得到C矩阵的0号元素，我们需要取A矩阵的一行以及B矩阵的一列元素。

```text
offs_am = (pid_m * BLOCK_SIZE_M + tl.arange(0, BLOCK_SIZE_M)) % M
offs_bn = (pid_n * BLOCK_SIZE_N + tl.arange(0, BLOCK_SIZE_N)) % N
offs_k = tl.arange(0, BLOCK_SIZE_K)
a_ptrs = a_ptr + (offs_am[:, None] * stride_am + offs_k[None, :] * stride_ak)
b_ptrs = b_ptr + (offs_k[:, None] * stride_bk + offs_bn[None, :] * stride_bn)
```

offs_am 和 offs_k 是 A 矩阵每个小块中的每个元素在整个 A 矩阵中的坐标 (也就是 m 维度的 index 和 k 维度的 index).

有了 m 维度 和 k 维度的 index, 就可以让它们各自和 m 维度 和 k 维度的 stride 相乘（stride_am 是行偏移，2个行之间差一个列数，stride_ak 是列偏移，2个列之间差一个数），然后和 a_ptr 相加, 就可以得到 A 矩阵每个小块中的每个元素的地址。

这里举例解释使用取模运算 % M 和 % N 而不用掩码的作用：

# 假设 M=100, BLOCK_SIZE_M=32 pid_m=3: 起始位置 = 96。则：

offs_am = [96, 97, 98, 99, 100, 101, ...] % 100 -> = [96, 97, 98, 99, 0, 1, ...]

当数据超出边界时，循环回到矩阵开头，所以后面只需用掩码检查K，而无需检查M和N，因为已经处理过了。

```text
accumulator = tl.zeros((BLOCK_SIZE_M, BLOCK_SIZE_N), dtype=tl.float32)
for k in range(0, tl.cdiv(K, BLOCK_SIZE_K)):
    a = tl.load(a_ptrs, mask=offs_k[None, :] < K - k * BLOCK_SIZE_K, other=0.0)
    b = tl.load(b_ptrs, mask=offs_k[:, None] < K - k * BLOCK_SIZE_K, other=0.0)
    accumulator = tl.dot(a, b, accumulator)
    a_ptrs += BLOCK_SIZE_K * stride_ak
    b_ptrs += BLOCK_SIZE_K * stride_bk
```

tl.load中的K - k * BLOCK_SIZE_K表示剩余需要处理的K维度元素数量。mask含义：只加载索引小于剩余元素数量的数据。加载完A和B块之后做矩阵乘法累加，接着移动到下一个块。

```text
if ACTIVATION == "leaky_relu":
        accumulator = leaky_relu(accumulator)
    c = accumulator.to(tl.float16)

    offs_cm = pid_m * BLOCK_SIZE_M + tl.arange(0, BLOCK_SIZE_M)
    offs_cn = pid_n * BLOCK_SIZE_N + tl.arange(0, BLOCK_SIZE_N)
    c_ptrs = c_ptr + stride_cm * offs_cm[:, None] + stride_cn * offs_cn[None, :]
    c_mask = (offs_cm[:, None] < M) & (offs_cn[None, :] < N)
    tl.store(c_ptrs, c, mask=c_mask)
```

Leaky ReLU是ReLU的改进版本，解决了"神经元死亡"问题： LeakyReLU(x) = x, if x > 0 ；= α·x, if x ≤ 0

与标准ReLU对比：ReLU: 负数直接变为0 → 可能导致梯度消失。Leaky ReLU: 负数保留一个小斜率（通常α=0.01） → 梯度可以继续传播

accumulator: 通常使用 float32 进行累加，防止精度损失。输出: 转换为 float16 存储，节省显存和带宽。

输出坐标没有使用取模，而是使用标准索引。输入可能来自周期边界（如循环卷积），需要循环读取，输出是标准矩阵，需要写入连续的正常位置。
