## 背景

过去几年，视觉语言模型的一条重要发展主线是 **Scaling** ：更大的模型、更多的数据和更强的算力，不断抬高通用图文理解与检索的能力上限。但在真实的工业系统中，我们关心的往往是另一组问题：模型能否在手机、摄像头等边缘设备上运行？能否在有限的算力、内存和功耗下保持足够低的时延？面对安防、零售、相册等特定领域，它是否真的理解业务所关心的细粒度差异？这就是我们近一年多关注的方向—— **端侧的垂域文搜图** 。它并不是简单地把一个通用 CLIP 模型压缩后部署到设备上。“端侧”意味着严格的资源约束；“垂域”意味着图片整体相似、有效差异更加细微。模型结构、训练数据、优化目标与评测方式，都需要围绕这些特点设计。

感兴趣的小伙伴可以taste我们近期的工作：我们围绕垂直领域，从评测与训练两个层面对工业场景下的文搜图任务进行了更贴近真实业务场景的建模：

本系列文章会逐步分享我们在这个方向上的理解和实践。本文先从轻量化视觉骨干讲起：从 MetaFormer、MobileOne 到 FastViT，再到使用这些结构思想的 MobileCLIP，以及它背后的训练方法。

## 1. Backbone网络结构演进

### 1.1 MetaFormer

MetaFormer重新思考了"attention is all you need"在视觉任务中的权威性。它精髓在于下图，把我们熟知的transformer结构抽象成了MetaFormer，即把Token Mixer作为一个可以实例化的组件，它可以是self-attention、Spatial MLP、也可以是最简单的Pooling层。这个Token Mixer的作用就是做特征提取。而作者想要argue的就是：token mixer 组件选取什么或许不是最重要的（self-attention，Conv，Pooling），真正work的是transformer中下图左一这个骨架结构。

### 1.2 MobileOne（Apple）

端侧模型的多个评价维度：flops，parameter，latency。MobileOne强调 **latency** 是模型在端侧运行效率的主要参考指标，而非flops和parameter，因为这两者都没有考虑到实际的 **访存** 和 **并发** 。

影响Latency的主要因素

- 产生 **synchronization cost** 的算子（尽量使用element wise算子）。例如SE结构或者各种复杂的激活函数。举个SE的例子，SE结构中的Global Pooling需要对整个feature map进行计算，它会强制synchronization 。
- **访存消耗** ：各种各样的branch，比如skip connection会产生更多的访存消耗。

关于 **访存消耗** ，需要先了解kernel的计算特点：完整的tensor（权重，激活值）开始存在于activation buffer中，它是设备上的可寻址内存，对于独立的GPU通常是显存（global memory）；对于手机SoC通常是CPU/GPU/NPU共享的统一内存。 某个计算单元（kernel）把tensor（其中的一小块） **读进** 寄存器/shared memory/片上缓存，然后执行计算，最后把计算结果重新 **写入** activation buffer中。这里的访存消耗就体现在读写上。

在实际的计算中：对于F(x)，在实际执行过程中，先 **读入** x，再执行kernel **计算** ，最后再 **写入** 。对于x+F(x)，这是两个kernel：add和F。实际执行过程为： **读入** x，执行F-kernel **计算** ， **写入** buffer； **读入** x和F-kernel的输出，执行add-kernel **计算** ， **写入** buffer。这里x读入两次，因为分别读入到F和add不同的寄存器上。所以可以看出，两者公式上虽然只差了一个point-wise add，但实际上访存消耗却相差很多。

网络结构设计的大体思路就是：using a **linearly over-parameterized model** at train-time and **re-parameterizing the linear structures** at inference。对于FFN，把激活层取出来放在残差外面；对于tokenmixer，用卷积而非self-attention结构，因为self-attention中的softmax非线性，没法做re-param。每个skip connection结构中全部是线性计算，这样就可以重参数化成为一个卷积。

mobileone在mobilenet-V1基础上融合了RepVGG的“reparameterizable skip connection”思想。具体地将mobilenet-V1的DWConv按照RepVGG的结构扩展出DW conv1*1 和 identity两个分支，DWConv3*3扩展出K份（小模型k=4，大模型k=1）。这个block可以用RepVGG的重参数化方法，压缩成一个DWConv。

```text
**********************************MobileNet-V1**********************************
3×3 Depthwise Conv
        ↓
1×1 Pointwise Conv

**********************************RepVGG**********************************
训练：
             ┌── 3×3 Dense Conv-BN ──┐
x ───────────├── 1×1 Dense Conv-BN ──┼── Add → ReLU
             └── Identity-BN ────────┘

推理：
x → 单个 3×3 Dense Conv → ReLU

**********************************MobileOne**********************************
DW 部分
                  ┌─ 3×3 DW + BN ─┐
                  ├─ ……共 k 路…… ┤
输入 x ───────────┼─ 1×1 DW + BN ─┼─ 相加 → ReLU → z
                  └─ Identity+BN ─┘
                      按条件存在
PW 部分
                  ┌─ 1×1 PW + BN ─┐
                  ├─ ……共 k 路…… ┤
输入 z ───────────┤               ├─ 相加 → ReLU → 输出
                  └─ Identity+BN ─┘
                      按条件存在

```

通过多分支结构和调整width提升 **模型容量** ；多分支的结构重参数化成一个conv-bn-act。重参数化后的模型，激活函数用的是最简单的RELU，减少synchronization；没有各种各样的branch，减少访存消耗。最终达到的效果是：参数量高于mobilenetv2，但是latency却更低，acc更高。

model scale的消融实验主要是在模型的width上做的，通过增加width来提升模型的表达能力。我理解是考虑到并发，depth和width都影响模型容量，但是depth是增加串行的长度，而width并发的更好。

### 1.3 FastViT（Apple）

MetaFormer证明了transformer的优势很大程度上来自于 Y=X+TokenMixer(X)，Z=Y+FFN(Y) 这种block框架。在此基础上FastViT结合CNN轻量级特点和Transformer的global attention优势，搞了一个CNN-Transformer Hybrid网络。FastViT也是Apple出品，依然是非常关注Latency，它将MetaFormer token-mixing 部分的 skip connection 通过重参数化吃进 DWConv 里（类似mobileone结构）。

![](https://pic1.zhimg.com/v2-8065f5fd251126f348288982047ae7ce_r.jpg)

网络结构特点为：

- 它是一种 **CNN-Transformer Hybrid** 网络，结合CNN的轻量级和Transformer的global attention优势。
- 它是一种典型的 **stem/patch embedding -> stage** 级联结构。stem/patch embedding主要作用是降维，其结构为多分支的DW-BN的可重参数化的卷积组合；stage的结构是将MetaFormer中的token mixer设置为3*3 DW卷积，将Norm-FFN替换成ConvFFN。ConvFFN的激活层没有独立出来，所以这部分不能做重参数化。
- 为了弥补CNN的local特性，网络在ConvFFN和PatchEmbedding中加了7*7大的卷积核，由于是DW卷积，所以计算量增加的不多；另外在最后一层采用了self-attention结构，对前面层提取的local feature做一次global attention。
- 为了减少计算量（feature分辨率），在前面的stage中block数量少；在stage3中安排了最多的block。

总结下，这个网络依然是CNN的 降维 -> 特征提取的结构，其中降维使用了可重参数化的结构（类似mobileoneblock），特征提取采用了MetaFormer的结构并在它基础上做了调整。

## 2. MobileCLIP （Apple）

### **2.1 MCi（Image Encoder）**

整体框架类似FastVit，采用PatchEmbedding-Stage（3组）和Self-Attention（最后一组）的Hybrid结构，依然是采用了大量的mobileone中的重参数化技巧。有一些细节上的调整。例如：

- 当时的工作发现FFN在width上存在信息冗余，于是MCi在ConvFFN中降低了width（expansion），增加了depth（block数量变多了），但是整体上参数量保持一致，发现模型容量提升。
- 在低分辨率的后期patch embedding中添加了SE-Layer，采用每个patch embedding一个SE的稀疏排布。

### 2.4 消融实验重要结论

要注意这些实验结论适用于大量数据pretrain foundation model，对sft可能并不适用。

1. Synthetic Captions 与 Real Caption混用，能大幅提升retrieval性能，对zero-shot cls性能提升也不小。其中Real Caption的特点是噪声大、经常不描述视觉内容，文本和视觉内容之间的关联性经常很弱，但是词汇丰富，长尾数据多（对zero-shot和openset很重要），描述中包含大量细粒度词汇，能够保留开放世界知识和多样性；synthetic caption的缺点是经常出现幻觉，语义压缩到更小的范围上，表达同质化（粗粒度），但是它能够提供更好的图文对齐关系。在mobileclip和《Revisit Large-Scale Image-Caption Data in Pre-Training Multimodal Foundation Models》等工作中都验证了两者混用的优势。这里有个问题，coca实测有严重的幻觉问题，经常出现mscoco中的常见文本，比如skateboard。不过由于训练方法倾向于蒸馏，所以当用到幻觉synthetic caption的时候，并不是完全在学习错误的对齐关系。
2. Image Aug比较剧烈的情况下，性能提升较大，我理解这里是因为训练方法倾向于蒸馏，teacher提供的是soft-label，一定程度上解决了aug后文本-图像不对齐的问题。
3. Ensemble teachers有3个结论：首先，用多个teacher组合计算embedding，计算平均cos sim，直接用于retrieval和cls任务，通常就能得到更好的性能指标；第二，用ensemble teachers蒸馏student，确实比用单独teacher蒸馏student性能更好；第三，teacher ensembles / 单独的teacher 排名与学生蒸馏后的排名顺序并不单调，也就是更强大的teacher蒸馏出来的student可能不如差一点的teacher蒸馏出来的student，需要做大量的消融实验找到teacher model之间能够互补且最适合student模型容量的最优组合。

## 总结

在模型选型的过程中，我们要兼顾性能和端侧推理的latency。我们发现在同级别大小的模型中，mobileclip的表现最佳。这与它的网络特性、训练方法与合成数据有直接关系。
