## 为什么要流水线

RISC-V 的五级流水线，每条指令分五步：

| 阶段 | 全称 | 做什么 |
| --- | --- | --- |
| IF | Instruction Fetch | 从内存取指令 |
| ID | Instruction Decode | 译码，读寄存器 |
| EX | Execute | ALU 运算，或计算访存地址 |
| MEM | Memory Access | 读/写数据内存 |
| WB | Write Back | 结果写回寄存器 |

流水线的作用如下：

| 周期 → | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 指令 1 | IF | ID | EX | MEM | WB |  |  |
| 指令 2 |  | IF | ID | EX | MEM | WB |  |
| 指令 3 |  |  | IF | ID | EX | MEM | WB |

一个指令需要5个周期，三个指令却只需要7个周期！流水线提高了处理器指令的吞吐量（单位时间内完成的指令数），但不会缩短单条指令的执行时间。实际上，由于流水线控制会产生开销（overhead），它还会延迟指令完成的时间。

*下面开始量化研究。*

## 基本变量CPI

Cycles Per Instruction (CPI): 每条指令所需要的时钟周期数。

流水线CPI = 理想流水线CPI + 流水线冒险的代价。

### Q问题：流水线冒险

**流水线冒险的代价= 结构化停顿+数据冒险停顿+控制停顿。**

结构冒险是什么？简单来说，就是硬件资源不够用。在重叠执行指令的情况下，如果硬件不能支持这些组合，就会出现资源冒险，从而导致结构冒险。由于这类基本由硬件决定，不是优化的主要目标。真要解决需要动硬件，比如增加资源或者将指令Cache和数据Cache分开等。

数据冒险是什么？后面的指令需要前面指令的结果，就会出现数据冒险。解决方法可以是在得到中间结果的时候就转发。

控制冒险是什么？首先我们需要注意到流水线的特点是不会停（想想工厂流水线）。所以，每个周期，取指阶段都要读一个新的指令。如果遇到分支指令，流水线不知道下一步会读哪个（不一定是顺序执行）。这就是控制冒险。解决方法之一就是等。

以上三种冒险都可以通过停顿（等）来解决。于是，我们就有了方法和冒险的代价。

**数据依赖和冒险**

数据依赖有三种类型：数据依赖、名称依赖、控制依赖。这里需要注意下名称依赖指的是若干条指令使用相同的寄存器或者存储地址（名称），但与这些名称相关的指令没有数据流动。所以，这是“假”冲突。

### A解决办法：编译器优化

```text
for (i = 999; i >= 0; i--)
    x[i] = x[i] + s;
```

这里每次迭代都没有相关性。（判断方法：看某次迭代读读数据，是不是别的迭代写的）

```text
RISC-V：

Loop: fld    f0, 0(x1)      # 读 x[i]
      fadd.d f4, f0, f2     # 加上 s（s 存在 f2）
      fsd    f4, 0(x1)      # 写回 x[i]
      addi   x1, x1, -8     # 指针前移一个元素（8 字节）
      bne    x1, x2, Loop   # 没到头就继续
```

### 逐条解释

| fld f0, 0(x1) |
| --- |
| 名字拆解：float + load + double，即"加载一个双精度浮点数"<br>作用：从内存地址 x1 处读出 8 字节，放进 f0<br>对应 C：取出 x[i] |
| fadd.d f4, f0, f2 |
| 名字拆解：float add，.d 表示双精度<br>作用：f4 = f0 + f2<br>对应 C：x[i] + s<br>注意格式：第一个是目的寄存器，后两个是源操作数 |
| fsd f4, 0(x1) |
| 名字拆解：float + store + double<br>作用：把 f4 的值写回内存地址 x1<br>对应 C：x[i] = ……<br>注意：store 的格式反过来，第一个 f4 是要存的数据（源），不是目的 |
| addi x1, x1, -8 |
| 名字拆解：add immediate，加一个立即数（写在指令里的常数）<br>作用：x1 = x1 − 8<br>对应 C：i--<br>为什么是 8？ 一个 double 占 8 字节，相邻元素地址差 8。i 减 1，地址就减 8 |
| bne x1, x2, Loop |
| 名字拆解：branch if not equal<br>作用：如果 x1 ≠ x2，跳回 Loop 标签继续循环；相等就往下走，循环结束<br>对应 C：判断 i >= 0 是否成立 |

### 延迟假设：

"延迟"指两条指令之间**需要隔开的停顿周期数。**

| 产生结果的指令 | 使用结果的指令 | 需停顿周期 |
| --- | --- | --- |
| 浮点运算 | 浮点运算 | 3 |
| 浮点运算 | 浮点存储 | 2 |
| 浮点加载 | 浮点运算 | 1 |
| 整数运算 | 分支 | 1 |

那么真实的情况就是这样：

```text
                         周期
Loop: fld    f0, 0(x1)    1
      停顿                 2    ← fld → fadd 要隔 1
      fadd.d f4, f0, f2   3
      停顿                 4
      停顿                 5    ← fadd → fsd 要隔 2
      fsd    f4, 0(x1)    6
      addi   x1, x1, -8   7
      停顿                 8    ← addi → bne 要隔 1
      bne    x1, x2, Loop 9
```

我们最终需要九个周期来执行。

**第一步：指令调度，降到 7 个周期**

把 addi 往前挪，填补 fld 后面的空位：

```text
Loop: fld    f0, 0(x1)    1
      addi   x1, x1, -8   2    ← 挪上来填空
      fadd.d f4, f0, f2   3
      停顿                4
      停顿                5
      fsd    f4, 8(x1)    6    ← 注意偏移从 0 改成 8！
      bne    x1, x2, Loop 7
```

**第二步：循环展开**

既然一次迭代的指令不够用，那就**把多次迭代合并成一次**。展开 4 次：

```text
Loop: fld    f0,  0(x1)
      fadd.d f4,  f0,  f2
      fsd    f4,  0(x1) //去掉了addi, bne
      fld    f6,  -8(x1)
      fadd.d f8,  f6,  f2 
      fsd    f8,  -8(x1) //去掉了addi, bne
      fld    f10, -16(x1)
      fadd.d f12, f10, f2
      fsd    f12, -16(x1) //去掉了addi, bne
      fld    f14, -24(x1)
      fadd.d f16, f14, f2
      fsd    f16, -24(x1)  
      addi   x1, x1, -32     # 一次处理 4 个，减 32
      bne    x1, x2, Loop
```

这轮循环展开获得两个好处：

1. 节约了3组addi和bne。
2. 每个副本使用了不同的寄存器f0/f6/f10/f14....。避免了寄存器重名导致的依赖。

**第三步：展开 + 调度，14 个周期**

现在 4 份副本互相独立，可以**交错排列**，用一份的指令去填另一份的空位。

```text
                           周期
Loop: fld    f0,  0(x1)      1
      fld    f6,  -8(x1)     2
      fld    f10, -16(x1)    3
      fld    f14, -24(x1)    4
      fadd.d f4,  f0,  f2    5
      fadd.d f8,  f6,  f2    6
      fadd.d f12, f10, f2    7
      fadd.d f16, f14, f2    8
      fsd    f4,  0(x1)      9
      fsd    f8,  -8(x1)    10
      addi   x1,  x1, -32   11
      fsd    f12, 16(x1)    12    ← addi 后偏移要修正：-16+32=16
      fsd    f16, 8(x1)     13    ← -24+32=8
      bne    x1,  x2, Loop  14
```

最后，我们看下优化了哪些内容：

- 每个元素的周期 = 每次迭代的周期 ÷ 每次迭代处理的元素数
- 每次迭代的周期 = 指令条数 + 停顿周期数

| 版本 | 周期/迭代 | 每个元素的周期 |
| --- | --- | --- |
| 原始 | 9 | 9 (9/1) |
| 只调度 | 7 | 7 (7/1) |
| 只展开 | 27 | 6.75 (27/4) |
| 展开 + 调度 | 14 | 3.5 （14/4） |
