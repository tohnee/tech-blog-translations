千亿参数的推荐大模型，线上打分居然卡在“重复做无用功”上？抖音同款技术给出了一个反常识的解法：只要把用户特征和商品特征强行物理隔离，主打 **只计算一次** ，线上推理延迟就能瞬间暴降 20%！这就是字节跳动最新开源的 **UG-Sep** 框架，一个能把稠密特征交互计算复杂度直接打到 $O(1)$ 的“黑科技”。

> Compute Only Once: UG-Separation for Efficient Large Recommendation Models<br> 字节跳动 arXiv 2026: [https://arxiv.org/abs/2602.10455](https://arxiv.org/abs/2602.10455)

在搜广推（Search, Ads, and Recommendation）工业界，推荐大模型（Large Recommender Models, LRMs）在特征交互的深度与细粒度上表现优异，但它们最大的痛点在于 **特征纠缠** ——在网络每一层中，用户侧特征与商品侧特征都在进行深度地融合与交互。这意味着，用户侧的表征无法独立地被缓存与复用。一旦候选商品发生改变，所有跨层的特征交互都必须从头重新计算！这种强烈的商品依赖性使得 dense 特征交互模型的推理复杂度随着候选商品数量 $C$ 呈线性增长（ $O(C)$ ）。

为了打破这一工程困局，**字节跳动 AML（应用机器学习）团队**在 2026 年发表了重磅论文《Compute Only Once: UG-Separation for Efficient Large Recommendation Models》。在这篇论文中，字节的研究人员首次提出了一种面向 TokenMixer 架构的 **用户-组分离（User-Group Separation, 简称 UG-Sep）** 技术。通过显式地将用户侧和商品侧的信息流在网络层级中进行解耦与掩码，UG-Sep 实现了 **在 dense 交互大模型中首次重用用户侧的中间计算结果** ！这使得用户侧的推理算力复杂度成功从 $O(C)$ 降到了 $O(1)$ 级别。

## 1. 传统架构的痛点：大厨的“无用功”泥潭

传统的 dense 交互模型就像是一个个性化定制餐厅。每来一个新顾客（用户），大厨（模型）就要针对桌上的每一道候选菜品（商品），从洗菜、切菜到炒菜（跨层特征融合）全部从头做一遍。如果一次要上 100 道菜，大厨就得重复做 100 遍基础工序，厨房直接瘫痪。

在目前主流的 LRM 中，不同的特征域（如 `User_Age`、`Item_Category`、`User_Click_Seq` 等）首先会被转换成统一的 Token 形式，送入多层 TokenMixer 中进行交互。典型的 TokenMixer 架构（如 **RankMixer**）由两个核心组件组成：

- **Multi-Head Token Mixing（多头 Token 混合层）**：在 Token 维度上进行信息跨域的打碎与混合，实现高阶交互。
- **Pertoken FeedForward Network（单 Token 前馈网络层，即 PertokenFFN）**：在每个 Token 内部进行非线性映射与通道融合。

在标准的 TokenMixer 模块中，特征交互公式通常可以写为：

$$ \begin{align} P_{k-1} &= LN\bigl(Mixup (X_{k-1}) \bigr) \\ X_{k} &= LN\bigl(PFFN(P_{k-1}) + X_{k-1}\bigr) \end{align} $$

在此公式中：

- $LN(\cdot)$ 表示层归一化（Layer Normalization）函数；
- $Mixup(\cdot)$ 是多头 Token 混合操作，负责在各个 Token 维度间进行高阶信息的融合与交叉；
- $PFFN(\cdot)$ 表示针对每个单独 Token 独立计算的前馈网络模块；
- $X_k \in \mathbb{R}^{T \times D}$ 是第 $k$ 个 TokenMixer 交互块的输出矩阵，其中 $T$ 为输入的 Token 总数，$D$ 为模型的隐藏层维度大小。

一旦进入 $Mixup$ 之后，用户特征与商品特征就被深度绑定、融为一体了。线上打分时，系统不得不为每一个候选视频发射一整套完整的计算图，完全无法实现计算的跨样本复用。

既然长序列模型能够通过 KV Cache 来重用用户侧的编码，那么我们能不能在 TokenMixer 内部，把用户特征与候选商品特征在物理上区分开，让用户侧的 Token 计算只执行一次呢？这就是 UG-Sep 诞生最核心的动机。

### 2.1 用户与商品 Token 的解耦

为了确保输入到后续交互模块的 Token 具有纯净的归属属性，UG-Sep 首先在网络的底层将特征提取模块（如 SENet、DCN 等）拆分为两个独立的计算分支：

- **U-tokens（用户侧 Token）** ：仅包含与用户自身静态画像、长期兴趣、设备及上下文相关的纯用户侧信息。
- **G-tokens（组侧 Token，即 Group-tokens，在文中与 Item-tokens 等价）** ：包含候选商品（或广告）属性，以及由于复杂结构而无法干净剥离的用户-商品交叉信息。

通过这一层底部的划分，我们的输入 Token 矩阵 $X$ 可以被显式地拼接并表示为：

$$ \begin{equation} X = Concat(x_{u^0}, x_{u^1}, \cdots, x_{u^{n-1}}, x_{g^0}, x_{g^1}, \cdots, x_{g^{m-1}}) \end{equation} $$

其中：

- $x_u$ 代表纯净的用户侧 Token；
- $x_g$ 代表包含商品侧信息的组 Token；
- $n$ 为用户 Token 的总个数；
- $m$ 为组 Token 的总个数；
- $T = n + m$ 为所有 Token 的总数。

### 2.2 隔离的 Mixup 注意力掩码

在底部分离了 Token 之后，真正的挑战来到了 $Mixup$ 模块。因为 $Mixup$ 的本质是对 Token 矩阵进行转置并按照多头进行通道分割和重组，这会导致信息跨 Token 混合。

为了捕获这种混合机制下的交互同时维持用户侧的独立性，多头 $Mixup$ 首先将每个 Token 切分为 $H$ 个头：

$$ \begin{align} Split(x_{u^0})=(x_{u^0}^0, x_{u^0}^1,\cdots, x_{u^0}^{H-1}) \end{align} $$

定义每个头的表征维度大小为 $D'$ ，满足 $D' = D / H$ 。对于第 $h$ 个头（其中 $h \in [0, H-1]$ ），每个 token 被切分后的片段满足 $x_{u^0}^{H-1} \in \mathbb{R}^{1 \times D'}$ 。

接下来，通过在 Token 维度上进行物理转置 and 拼接，我们生成了 $H$ 个全新的 Token：

$$ \begin{equation} \begin{aligned} L^h = Concat(x_{u^0}^h, x_{u^1}^h,\cdots,x_{g^{T-1}}^h), h \in [0,H-1] \\ L^h \in \mathbb{R}^{1 \times D'*T} \end{aligned} \end{equation} $$

在拼接后的新表征 $L^h$ 中，既包含了来自用户侧的特征分量，也包含了来自商品侧的特征分量。通过在通道维度上将这 $H$ 个新 Token 拼接起来，就得到了 $Mixup$ 操作的完整输出结果：

$$ \begin{align} Mixup(X) = Concat(L^0,L^1,\cdots, L^{H-1}) \end{align} $$

此时，在转置和拼接得到的一组新 Token 中，我们假设前 $c_u$ 个 Token 归属于用户侧 Token，后 $c_g$ 个 Token 归属于商品侧 Token，满足 $c_u + c_g = H$ 。

为了保证前 $c_u$ 个用户 Token **绝对不掺杂** 任何商品侧的信号，UG-Sep 引入了一个精心设计的掩码机制（Masking Mechanism），其数学定义如下：

$$ \begin{align} mask_{i,j} = \begin{cases} 0, \quad i<c_u,\quad j>n*D', \quad \\ 1, \quad otherwise \end{cases} \end{align} $$

这里的索引 $i \in [0, H-1]$ 表示生成的新 Token 索引， $j \in [0, T \times D']$ 表示转置拼接后的通道维度索引。

根据这一公式，我们通过广播乘法对原始的 $Mixup$ 输出进行强行掩码，将用户 Token 对应于商品 Token 分量的全部通道值直接清零：

$$ \begin{equation} X_{masked} = Mixup(X) * broadcast(mask) \end{equation} $$

在这个极其干净的乘法操作后，前 $c_u$ 个 Token 成为了绝对独立的纯用户 Token，后 $c_g$ 个 Token 作为商品 Token 照常保留了全局的特征交互信息。这一机制完美实现了“物理隔离”，阻断了商品特征向用户 Token 的反向污染。

### 2.3 单 Token 前馈网络（PertokenFFN）的拆分与缓存

既然用户 Token 的特征与候选商品无关，那么在处理同一个用户的多个候选商品打分时，这一部分用户 Token 经过 **可重用的 PertokenFFN** 的计算结果就应该是完全相同的！

因此，我们只需要在 serving 推理时发射一次计算图，将前 $c_u$ 个用户 Token 的计算结果缓存下来，在处理后续的 $C$ 个候选商品时直接用 `Gather` 算子拿来复用即可。这就将这部分计算的复杂度从 $O(C)$ 降低为了 $O(1)$ ！其请求内的缓存重用算法细节如算法 1 所示：

## 3. 解决金字塔与层级网络瓶颈：Separated Residual（分离残差）

在实际的大规模工业推荐模型中，通常不会全盘使用等维度的 TokenMixer。为了提高计算与参数效率，模型往往会采用层级金字塔结构（Pyramidal settings）。也就是说，随着网络层数的加深，我们希望输出的 Token 数量小于输入的 Token 数量。

在金字塔 TokenMixer 中，由于输入的用户 Token 数 $n$ 不再等同于输出的用户 Token 数 $c_u$ ，常规的直接残差连接在数学上就无法实现了。如果强行把输入和输出进行不规则的拼接加权，很容易把商品侧的特征通过残差通路泄露到用户 Token 中，彻底摧毁 UG 分离的物理边界。

针对这一层级网络的特殊痛点，UG-Sep 设计了 **分离残差（Separated Residual）** 机制，如图 2 所示：

![](https://pica.zhimg.com/v2-7d72eac6f5490ac22042e3adc0e71d52_r.jpg)

*图2：支持金字塔架构的分离残差（Separated Residual）机制。通过引入交叉注意力机制与带有 UG Mask 的掩码算子作为残差通路，成功消除了金字塔降维带来的泄露风险，解耦了输入输出 Token 的维数限制。*

具体而言，我们并不采取直接按位相加的残差形式，而是引入了一个轻量级的 **交叉注意力机制（Cross-Attention）** ：

- 以经过 $Mixup$ 和 $PertokenFFN$ 的输出矩阵作为 Query（查询）；
- 以前面一层的输入 Token 矩阵 $X_{k-1}$ 作为 Key（键） 和 Value（值）。

在进行 Attention 的注意力矩阵计算时，系统强制使用一个额外的 **UG Mask 掩码矩阵** 进行阻断，确保用户侧的 Query 绝对只能 attend 到输入的用户侧 Key，绝对不会看到商品侧的任何 Key。计算出的 Attention 结果再作为残差项与主干网络输出相加。这一巧妙的设计彻底解耦了输入和输出 Token 之间的固定物理比例。

## 4. 稳定模型表达：Information Compensation（信息补偿）

任何形式的掩码（Masking）本质上都是在对信息进行裁剪。

通过 UG 掩码，我们将用户 Token 对应商品特征分量的通道值全部强制置零了。在 U 侧和 G 侧 Token 数量相对均衡的情况下，由于这部分被掩码的特征空间占比极小，再加上残差通路的支撑，模型几乎不会产生精度波动。

但是在实际调优中，我们经常希望调整用户 Token 与商品 Token 的比例（即 U:G 比例，比如 2:1、3:1 甚至 5:1 ），以便在大模型中倾斜更多算力去深度表征用户兴趣。此时，问题出现了：当 U:G 比例极度倾斜时，被置零的商品特征空间占比过大，会导致严重的特征交互信息丢失，使得模型预估的 AUC 出现显著下跌。

为了在享受加速红利的同时保住精度底线，UG-Sep 进一步提出了 **信息补偿（Information Compensation）** 策略，其原理如图 3 所示：

![](https://pic2.zhimg.com/v2-29979ec33dcc01aaaa9e58585eb1e9a9_r.jpg)

*图3：信息补偿（Information Compensation）机制。通过引入一个可学习的投影层，将已被物理隔离的纯用户 Token 表征映射并显式叠加到商品 Token 分支上，成功在不破坏用户独立性的前提下，重建了关键的用户-商品交互特征。*

其数学表达非常优雅。首先，我们定义经过掩码和 $Mixup$ 操作后的纯用户 Token 表征矩阵为 $U \in \mathbb{R}^{c_u \times d}$ ，对应的商品 Token 表征矩阵为 $G \in \mathbb{R}^{c_g \times d}$ 。

接着，我们使用一个可学习的线性投影算子（Linear Projection），将用户表征投影至与商品 Token 相同的特征维度空间中：

$$ \begin{equation} \hat{U} = \mathrm{Proj}(U) \end{equation} $$

最后，我们将这一投影后的用户信号显式地 **投影-相加** 回商品 Token 上：

$$ \begin{equation} G_{\mathrm{comp}} = G + \hat{U} \end{equation} $$

通过这种“投影-相加”的轻量级桥梁，被剥离的用户特征信号以全新的形态补偿回了商品 Token 分支中，确保了商品侧能够完整地进行高阶的“用户-商品”特征交互。与此同时，因为我们**没有**将任何商品信号注入回用户 Token，用户 Token 依然保持了绝对的纯净性，可以直接进行缓存复用。这就像大厨把底料做成可重用的浓缩包，每次要上新菜时，只需把这包做好的底料（用户表征）注入具体的食材（商品特征）中即可。

## 5. 跨越内存墙：W8A16 权重量化

当我们在 GPU 上部署了 UG-Sep 之后，字节跳动的系统工程师们观察到了推荐大模型领域一个非常经典的“尴尬”现象： **由于 UG-Sep 极其成功地砍掉了 U 侧大量的多余计算，整个模型的算力需求（FLOPs）瞬间打折。此时，模型的计算性能瓶颈悄然发生转移，从“计算受限（Compute-bound）”变为了“内存带宽受限（Memory-bound）”** 。

这就像大厨的手速已经快到飞起，但出菜速度却卡在了小工“从冰箱拿食材”的极慢速度上。

为了打破内存带宽瓶颈，UG-Sep 引入了 **W8A16 权重量化** 方案：

- **8-bit Weight（8位权重量化）** ：将模型的所有静态参数以 FP8 格式压缩存储，从而使权重加载所需的显存带宽直接降低了一半！在矩阵乘法执行时，硬件在片上（On-chip）将 FP8 权重即时反量化（Dequantize）为正常的 FP16。
- **16-bit Activation（16位激活值）** ：由于动态的激活值（Activation）依然保持了 16-bit（BF16/FP16）的完整精度，这有效保留了深度推荐模型的表达精细度与数值稳定性，几乎做到了精度无损。

由于反量化带来的额外开销相对于减少的一半访存时间来说微乎其微，W8A16 与 UG-Sep 形成了强烈的协同效应，双键合璧真正释放了 GPU 架构的线上推理极限。

## 8. 总结

《Compute Only Once: UG-Separation for Efficient Large Recommendation Models》为 dense 特征交互模型的扩展开辟了一条全新的康庄大道。它打破了“序列模型才能做 KV Cache，交互模型只能硬算”的思维定势，巧妙地用 **UG 分离与掩码机制** ，将深度特征交互中的用户侧计算彻底独立出来，实现了 $O(1)$ 的重用开销。

配合 **分离残差** 与 **单向信息补偿** ，它在工程实现上成功保住了预估精度；进一步叠加 **W8A16 权重量化** ，更是横扫了 GPU 的内存带宽瓶颈，使算力削减最终完全转化为了线上延迟的显著降低。
