在传统数学规范中，向量一般表示为列向量，向量线性变换一般表示为列向量左乘变换矩阵，变换矩阵的每一行对应着变换后向量的每一维；而在PyTorch中，向量是行向量，向量线性变换表示为行向量右乘变换矩阵，变换矩阵的每一列对应着变换后向量的每一维。

张量并行的表示和分析借助于分块矩阵是非常清晰的，相关内容可参考：[分块矩阵及运算规则 - 马同学](https://www.matongxue.com/parts/2246/)。

假设 transformer 的层数是 $l$，transformer 输入输出的维度是 $d$，MHA 的头数是 $h$，query、key、value 的维度分别是 $d_q$、$d_k$、$d_v$（通常有 $d=hd_q=hd_k=hd_v$），GQA 头的分组数是 $g$ ，FFN 中间层的维度是 $d_{ffn}$ ，词表大小（决定了嵌入层和输出 softmax 的结构）是 $v$ 。

假设张量并行度是 $N_t$ 。

## 2. 大模型的张量并行训练

张量并行并不只适用于 Transformers 结构，讨论大模型张量并行的各方面细节却离不开 Transformers 的结构特点。

### 2.1 前馈网络层的张量并行

[Megatron-LM 论文1](http://arxiv.org/abs/1909.08053) 还以 Model Parallelism 的名称代指张量并行，该论文具体以 GeLU 版本 FFN 为例（可参考[大模型结构基础（四）：前馈网络层的升级](https://zhuanlan.zhihu.com/p/702190813)）介绍前馈网络层的张量并行。

![](https://picx.zhimg.com/v2-0b32e9f517492fd6d6aa079b968e05cd_r.jpg)
*GeLU FFN 的张量并行示意，摘自：Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism*

第一层全链接+GeLU的张量并行是将变换矩阵沿列划分，前向过程的分块矩阵表示如下（记号与论文保持一致）：

$Y=GeLU(XA)=GeLU(X[A_1,A_2])=GeLU([XA_1,XA_2])=[GeLU(XA_1),GeLU(XA_2)]$

简化表示为：$Y=[Y_1, Y_2]$ ，可见**该层各并行张量的前向过程互相完全独立**。

第二层全链接张量并行前向过程的分块矩阵表示如下（忽略 dropout ，一对分析无影响，二现如今已不使用）：

$Z=[Y_1, Y_2]\times[B_1,B_2]^T=Y_1B_1+Y_2B_2$

可见**该层各并行张量的前向过程在最后需要一次 AllReduce 操作**（可参考[大模型效率工程（二）：训练消耗评估纪要](https://zhuanlan.zhihu.com/p/706675657)的5.1节）

**现在结合前向过程的分块矩阵表示脑补反向过程，第二层各并行分区输入激活值梯度和参数梯度互相完全独立，第一层各并行分区的参数梯度互相独立，但是第一层输入激活值，也就是X的梯度，需要一次 AllReduce 操作。**

如果是 GeGLU 和 SwiGLU 版本的FFN呢？脑补一下，除了第一层多了个变换矩阵，门控机制的 element-wise 乘法对前向过程和反向过程在并行分区之间的计算独立性都没有影响，关键细节与 GeLU 版本 FFN 没有质的差别。

### 2.2 多头自注意力机制的张量并行

![](https://pic2.zhimg.com/v2-cec920780e59c795b427a30156329deb_r.jpg)
*MHA 的张量并行示意，摘自：Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism*

MHA在 O 变换之前各头本来就是完全独立的，因此只要在各头的参数“边界”进行 Q、K、V 三个变换矩阵的张量并行，各并行分区的前向过程就是互相完全独立的。O 变换实际上和 FFN 的第二层是一样的，**前向过程需要一次 AllReduce 操作**。

脑补一下反向过程，尽管相比 FFN 的第一层复杂得多，但是也没有质的差别，**反向过程对输入激活值的梯度计算需要一次 AllReduce 操作**。

### 2.3 词嵌入和输出层 Softmax 的张量并行

[Megatron-LM 论文1](http://arxiv.org/abs/1909.08053) 是在 Tied Embeddings 的设定下描述的这部分张量并行，因此，两个位置采用了相同的并行划分方式。

首先，无论是词嵌入还是输出层 Softmax 矩阵，都是沿着 Vocabulary 的方向进行列划分，换句话说，就是每个并行分区只包含一部分词对应的向量。

此时**考虑前向过程，两个位置也都需要一次 AllGather 操作。**词嵌入后接 AllGather 操作的总通信量（此处先不按字节算，按浮点数量算）是 $btd$ ，而 Softmax 运算之前 AllGather 操作的总通信量则是 $btv$ 。考虑到词表大小一般都比较大，Megatron-LM 对 Softmax 位置的 AllGather 操作进行了优化。（*看论文之后不保准的个人理解，没有看代码确认，总通信量对得上。*不再 AllGather Logits，而是先 AllReduce Softmax 运算的中间结果，即每个并行分区 logits e指数的和，然后计算每个并行分区部分的交叉熵，最后 AllReduce 交叉熵。事实上变成了标量的通信，总通信量从 $btv$ 下降为了 $4bt$ ，直接到了可以忽略的程度）

**考虑反向过程**，词嵌入位置应该不需要额外通信量，而**输出层输入激活值梯度需要一次 AllReduce 操作**（与 FFN 第一层本质上相同）。

现如今大模型已经普遍不采用 Tied Embeddings 的操作了，实际上放松了对于词嵌入和输出层 Softmax 的张量并行的约束，两个位置不需要采用相同的并行划分方式了，词嵌入可以选择沿行划分，这个要以后具体看代码才知道，暂不深究。

### 2.4 其余层的处理方式

对于 Transformer Block 中的其余层，重点是有参数的层归一化，最基本的张量并行选择在每个并行分区都冗余配置一份完整参数。因为每个张量并行分区的批数据是一样的，层归一化参数也是相同的，所以每个并行分区的层归一化前向反向都是独立且相同的计算过程，不涉及额外通信量。

```python3
class FeedForward(nn.Module):
    def __init__(
        self,
        dim: int,
        hidden_dim: int,
        multiple_of: int,
        ffn_dim_multiplier: Optional[float],
    ):
        super().__init__()
        hidden_dim = int(2 * hidden_dim / 3)
        # custom dim factor multiplier
        if ffn_dim_multiplier is not None:
            hidden_dim = int(ffn_dim_multiplier * hidden_dim)
        hidden_dim = multiple_of * ((hidden_dim + multiple_of - 1) // multiple_of)

        self.w1 = ColumnParallelLinear(
            dim, hidden_dim, bias=False, gather_output=False, init_method=lambda x: x
        )
        self.w2 = RowParallelLinear(
            hidden_dim, dim, bias=False, input_is_parallel=True, init_method=lambda x: x
        )
        self.w3 = ColumnParallelLinear(
            dim, hidden_dim, bias=False, gather_output=False, init_method=lambda x: x
        )

    def forward(self, x):
        return self.w2(F.silu(self.w1(x)) * self.w3(x))
```

### 2.5 降低显存占用的效果

只考虑占主体的 $l$ 层 Transformer Block 的部分。

首先考虑 Model States 显存占用。考虑到多头注意力机制和前馈网络层是 Transformer Block 参数量的绝对主体（可参考[大模型效率工程（二）：训练消耗评估纪要](https://zhuanlan.zhihu.com/p/706675657)第2节），因此，张量并行能够将 Model States 显存占用量降低为原来的 $1/N_t$ 。

下面考虑 Activations 显存占用。按照[大模型效率工程（二）：训练消耗评估纪要](https://zhuanlan.zhihu.com/p/706675657)的设定，如下图所示，所有没有进行张量并行层的激活值和前向过程需要 AllReduce 操作的激活值都需要在每个并行分区上完整保存。两个归一化层的输出、FFN层的输出、o的输出，一共4处。

![](https://pic4.zhimg.com/v2-1550ecba6e9a64350e02e94aa08680a3_r.jpg)

因此，使用张量并行后， $l$ 层的激活值显存占用大概会下降为 $(8+16/N_t)btdl$ 。如果张量并行度是8，激活值显存占用将大约下降至原来的一半不到，离 $1/N_t$ 还有很大距离。这正是张量并行后续改进的主要入手点。

### 2.6 额外通讯量的引入

同样只考虑占主体的 $l$ 层 Transformer Block 的部分，且使用混合精度技术。

![](https://pica.zhimg.com/v2-9946487f83dfc927eda3ae675d6874e4_r.jpg)
*摘自：Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism*

每层 Transformer Block 在一个 Step 中，需要执行4次 AllReduce，每次待操作的数据都是 $N_t$个并行分区上的$b\times{t}$ 个 $d$ 维半精度格式向量。因此，张量并行引入的总额外通讯量是 $8N_tbtdl$ Bytes/Step。在实际应用中，张量并行是最内层的并行，并行度等于卡数，平均每卡的额外通讯量就是 $8btdl$ Bytes/Step。

以 Llama-7B为例（2048卡训练，全局 Batch Token 是 4M，上下文长度2K）全局 Batch Size 是 2048（序列），单卡 Batch Token $bt\approx2K$ ， $d=4096$， $l=32$ 。平均每卡的额外通讯量是 $8*2K*4096*32\approx2.1G$ Bytes/Step。

相比于卡间甚至机间通讯的带宽，这个通讯量是非常巨大的，会严重影响每秒可执行的Step数，降低计算吞吐量。因此，张量并行只能在同一个机器（节点）内进行，还得利用 NVLINK，PCIE 带宽只是个位数* GB/s 级别。

## 3. 大模型的序列并行训练

### 3.1 并行操作

![](https://pic4.zhimg.com/v2-f242377ca173c1b4d129eb1a6d114fbb_r.jpg)
*增加序列并行的张量并行，摘自：Reducing Activation Recomputation in Large Transformer Models*

[Megatron-LM 论文3](http://arxiv.org/abs/2205.05198) 包含对 Sequence Parallelism 详细介绍，序列并行完全针对于张量并行在降低 Activations 显存占用方面的不足。

> We notice that in the non-tensor parallel regions of a transformer layer, the operations are independent along the sequence dimension.

除了 MHA，也就是包含了所有不进行张量并行的层，Transformer Block 的计算都是在 Sequence 维度上 Token 之间独立的。因此，可以沿 Sequence 方向对 non-tp 层的 Activations 进行划分，在进入TP层之前增加执行一次 AllGather 操作，在TP层结束后增加执行一次划分。

这里把序列并行的分块矩阵表示放在3.2节。

### 3.2 额外通信量的魔法

序列并行设计最精妙的地方是：相较于张量并行，看起来好像增加了通信方面的需求，实际上却几乎没有增加额外的通信量。

![](https://pic1.zhimg.com/v2-9033d29b2a4834cc508da12ee6290696_r.jpg)
*FFN 的张量并行+序列并行示意图，摘自：Reducing Activation Recomputation in Large Transformer Models*

在这方面 MHA 和 FFN 没有差别，下面跟随原文以 FFN 为例，给出前向过程的分块矩阵形式。

![](https://picx.zhimg.com/v2-29a7a4c9040b8ac166a9fa7cff1e7d61_r.jpg)
*FFN 的张量并行+序列并行的分块矩阵形式，摘自：Reducing Activation Recomputation in Large Transformer Models*

第一行：将输入沿 Sequence 方向划分，然后进行层归一化。**第二行**：在 FFN 层前执行 AllGather 操作。第三、四：与张量并行 FFN 执行 AllReduce 操作前完全一致。**第五行**：包含了张量并行 FFN 的 AllReduce 操作和 序列并行沿 Sequence 方向的划分操作。第六行：现在已经基本不使用的 dropout（并不影响序列并行的分析）。

关键就在于第五行，实际不需要先 AllReduce 再划分，使用一个 ReduceScatter 操作即可。这里为了准确，还是上原文：

> These two tensors (W_1, W_2) are not parallel anymore and need to be summed as W = W_1 + W_2 before they are fed into the dropout layer. However, dropout needs its input to be parallel in the sequence dimension s. **Instead of summing and then parallelizing in the sequence dimension, we combine these two operations into a reduce-scatter operation.**As a result, ¯g can be a single reduce-scatter operation in the forward pass.

这样一来，**FFN 张量并行+序列并行的前向过程是 1 次 AllGather + 1 次 ReduceScatter，通讯量等于 FFN 张量并行的 1 次 AllReduce**（为什么可参考[大模型效率工程（二）：训练消耗评估纪要](https://zhuanlan.zhihu.com/p/706675657)的第5节）。

与张量并行类似，**反向过程和前向过程是“共轭”的**（原文是 are conjugate of）。也就是说，梯度在 FFN 输出位置先执行一次 AllGather 操作（张量并行这里原本不需要操作），在 FFN 输入位置要执行一次 ReduceScatter 操作（张量并行在这里原本是 AllReduce 操作）。

![](https://picx.zhimg.com/v2-595c99b771a411ad9b2fe22ada47de67_r.jpg)
*反向过程和前向过程是“共轭”的，摘自：Reducing Activation Recomputation in Large Transformer Models*

**这样一来，序列并行+张量并行的额外通讯量=张量并行的额外通讯量。**

![](https://pic4.zhimg.com/v2-d6a28c86be51e0b95ef25e6451ae9679_r.jpg)
*序列并行+张量并行额外通讯量=张量并行额外通讯量，摘自：Reducing Activation Recomputation in Large Transformer Models*

<br>这里巧妙得让我感到喜悦。

如果足够细心的话，在本小节的开始，我的叙述是“几乎“没有增加额外的通信量。为什么这么说？这是因为序列并行为了降低显存占用，最后还是稍微增加了一些通讯量。

### 3.3 降低显存占用的效果

序列并行对于降低 Model States 的显存占用没有效果，张量并行叠加序列并行的目标效果是将 Activations 显存占用降低为使用张量并行前的 $1/N_t$ 。唯一值得一说的就是前向过程的第二行，这里Y是一个没有划分的激活值，实际上序列并行没有选择保存这个激活值，而是采用在反向过程中增加 1 次 AllGather 操作来实现。这次额外的 AllGather 操作能够与梯度计算相互并行，从而没有造成时间的额外损失。

![](https://pic3.zhimg.com/v2-7c82a18b71ffcd3711bfc035606936bc_r.jpg)
*用 AllGather 操作换取激活值显存占用的降低，摘自：Reducing Activation Recomputation in Large Transformer Models*

## 4. ZeRO-R

ZeRO-R出自[ZeRO: Memory Optimizations Toward Training Trillion Parameter Models](http://arxiv.org/abs/1910.02054)

### 4.1 激活值划分操作

ZeRO-R 与序列并行有一定相似之处，但是没有序列并行设计的精细。

> ZeRO eliminates this redundancy by partitioning the activations, and only materializes them in a replicated form one activation layer at a time, right before the activation is used in computation. More speciﬁcally, **once the forward propagation for a layer of a model is computed, the input activations are partitioned across all the model parallel process, until it is needed again during the backprogation.** At this point, **ZeRO uses an all-gather operation to re-materialize a replicated copy of the activations.**

ZeRO-R 在前向过程中，计算完整的激活值，然后将激活值划分，直到在反向过程中通过 AllGather 操作恢复完整的激活值。

### 4.2 与序列并行的异同

与序列并行的相同点：

- 序列并行在效果上也是对激活值进行划分，而且序列并行指定了在 Sequence 维度上划分，所以ZeRO-R也能将激活值显存占用降低为使用张量并行之前的 $1/N_t$ ；
- ZeRO-R 采用了与序列并行（3.3节所述）相同的用 AllGather 操作恢复完整激活值的操作，所以ZeRO-R和序列并行在额外通信量的引入方面是一致的。

与序列并行的不同点：

- ZeRO-R没有指定激活值划分的维度，大概率不是 Sequence 维度，而是跟 ZeRO-DP 保持相同;
- 序列并行不仅对激活值进行划分，前向过程和反向过程的计算也是沿 Sequence 维度划分的，ZeRO-R和基础张量并行一样在non-tp层存在重复计算。

**这实际揭示了序列并行一个没有特别强调的设计优势：减少了non-tp层的重复计算，尽管non-tp层的计算量都不大。**

另外，ZeRO-R包含了Offload技术的使用，这就不再本篇笔记的描述范围内了，在工业环境我理解应该也用不上。
