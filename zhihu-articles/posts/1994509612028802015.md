## 1. 并行度概述

### 1.1 并行度类型

Megatron-LM 支持多种并行策略，每种都有对应的并行度（parallel size）：

| 并行类型 | 缩写 | 参数名称 | 说明 |
| --- | --- | --- | --- |
| Tensor Parallel | TP | tensor_model_parallel_size | 张量并行，将模型的权重矩阵切分到多个GPU |
| Pipeline Parallel | PP | pipeline_model_parallel_size | 流水线并行，将模型的层切分到多个GPU |
| Data Parallel | DP | data_parallel_size | 数据并行，在多个GPU上复制模型，切分数据 |
| Context Parallel | CP | context_parallel_size | 上下文并行，将序列长度切分到多个GPU |
| Expert Parallel | EP | expert_model_parallel_size | 专家并行（MoE），将专家切分到多个GPU |

### 1.2 并行度之间的关系

所有并行度的乘积必须等于总的 GPU 数量（world_size）：

```text
world_size = TP × PP × DP × CP × EP
```

**重要约束**：

- TP、PP、CP、EP 由用户显式指定
- DP 由系统自动计算：`DP = world_size / (TP × PP × CP × EP)`

## 2. 核心计算公式

### 2.1 基础并行度计算

### 2.1.1 数据并行度（Data Parallel Size）

**计算公式**：

```text
# 基础公式
model_size = tensor_model_parallel_size × pipeline_model_parallel_size × context_parallel_size
data_parallel_size = world_size // model_size

# 在代码中的实现（megatron/training/arguments.py:386）
total_model_size = (
    args.tensor_model_parallel_size * 
    args.pipeline_model_parallel_size * 
    args.context_parallel_size
)
args.data_parallel_size = args.world_size // total_model_size
```

**说明**：

- `model_size` 是单个模型副本需要的 GPU 数量
- `data_parallel_size` 是模型副本的数量
- 每个数据并行组内的模型是完全相同的

**示例**：

```text
# 配置
world_size = 32
tensor_model_parallel_size = 4
pipeline_model_parallel_size = 2
context_parallel_size = 1

# 计算
model_size = 4 × 2 × 1 = 8
data_parallel_size = 32 // 8 = 4

# 解释：32个GPU上有4个完全相同的模型副本，每个副本使用8个GPU
```

### 2.1.2 专家数据并行度（Expert Data Parallel Size）

对于 MoE（Mixture of Experts）模型，还需要计算专家层的数据并行度：

**计算公式**：

```text
# 专家层的模型并行度
expert_tensor_model_pipeline_parallel_size = (
    expert_tensor_parallel_size * 
    expert_model_parallel_size * 
    pipeline_model_parallel_size
)

# 专家数据并行度
expert_data_parallel_size = world_size // expert_tensor_model_pipeline_parallel_size
```

**说明**：

- `expert_tensor_parallel_size`：专家层的张量并行度（默认等于 `tensor_model_parallel_size`）
- `expert_model_parallel_size`：专家并行度，将不同专家分配到不同 GPU
- 专家层和非专家层可以有不同的数据并行度

**示例**：

```text
# 配置
world_size = 64
expert_tensor_parallel_size = 2
expert_model_parallel_size = 4
pipeline_model_parallel_size = 2

# 计算
expert_tensor_model_pipeline_parallel_size = 2 × 4 × 2 = 16
expert_data_parallel_size = 64 // 16 = 4
```

### 2.2 虚拟流水线并行（Virtual Pipeline Parallel）

虚拟流水线并行允许每个 GPU 处理多个流水线阶段，以提高效率：

**配置**：

```text
virtual_pipeline_model_parallel_size = 2  # 每个GPU处理2个stage

# 例如：4层模型，2个PP GPU，每个GPU处理2个stage
# GPU 0: [Layer 0, Layer 2]
# GPU 1: [Layer 1, Layer 3]
```

**说明**：

- 不影响并行度的计算
- 只影响层在 GPU 上的分布方式
- 用于减少流水线气泡（pipeline bubble）

## 4. Rank 分组机制

### 4.1 RankGenerator 类

`RankGenerator` 类负责生成不同并行类型的 GPU 分组。

**类定义**（parallel_state.py:424）：

```text
class RankGenerator(object):
    """A class for generating rank groups for different modes of parallelism."""

    def __init__(
        self, tp: int, ep: int, dp: int, pp: int, cp: int, 
        order: str, rank_offset: int = 0
    ) -> None:
        self.tp = tp
        self.ep = ep
        self.dp = dp
        self.pp = pp
        self.cp = cp
        self.rank_offset = rank_offset
        self.world_size = tp * dp * pp * cp * ep  # 总GPU数量

        self.name_to_size = {
            "tp": self.tp,
            "pp": self.pp,
            "dp": self.dp,
            "ep": self.ep,
            "cp": self.cp,
        }
        self.order = order  # 例如 "tp-cp-ep-dp-pp"
```

### 4.2 Rank 分组算法

### 4.2.1 正交并行分组

Megatron 使用**正交并行分组**算法来生成各种并行组。核心思想是：

**全局 Rank 计算公式**：

```text
global_rank = (
    tp_rank + 
    cp_rank * tp_size +
    ep_rank * tp_size * cp_size +
    dp_rank * tp_size * cp_size * ep_size +
    pp_rank * tp_size * cp_size * ep_size * dp_size
)
```

这个公式根据 `order` 参数的不同而变化。

### 4.2.2 生成特定并行组

**函数**：`generate_masked_orthogonal_rank_groups()`（parallel_state.py:248）

**算法原理**：

```text
def generate_masked_orthogonal_rank_groups(
    world_size: int, 
    parallel_size: List[int], 
    mask: List[bool]
) -> List[List[int]]:
    """
    生成正交并行组
    
    参数:
        world_size: 总GPU数量
        parallel_size: 各并行度的大小列表，如 [tp, cp, ep, dp, pp]
        mask: 布尔掩码，指定要包含哪些并行度
        
    返回:
        List[List[int]]: 每个子列表是一个并行组的rank列表
    """
```

**示例**：

```text
# 配置
world_size = 24
parallel_size = [tp=2, cp=1, ep=1, dp=3, pp=4]
order = "tp-cp-ep-dp-pp"

# 生成 DP 组（mask = [False, False, False, True, False]）
# 结果：[[0,2,4], [1,3,5], [6,8,10], [7,9,11], ...]
# 每个DP组包含3个rank，它们的tp、cp、ep、pp相同，只有dp不同

# 生成 TP 组（mask = [True, False, False, False, False]）
# 结果：[[0,1], [2,3], [4,5], [6,7], ...]
# 每个TP组包含2个rank，它们的cp、ep、dp、pp相同，只有tp不同

# 生成 PP 组（mask = [False, False, False, False, True]）
# 结果：[[0,6,12,18], [1,7,13,19], [2,8,14,20], ...]
# 每个PP组包含4个rank，它们的tp、cp、ep、dp相同，只有pp不同
```

### 4.3 组合并行组

可以通过组合 mask 来生成复合并行组：

```text
# TP-DP 组（mask = [True, False, False, True, False]）
# 每个组包含 tp_size × dp_size 个 rank

# TP-CP-DP 组（mask = [True, True, False, True, False]）
# 每个组包含 tp_size × cp_size × dp_size 个 rank
```

**配置**：

```text
--world-size 64 \
--tensor-model-parallel-size 4 \
--pipeline-model-parallel-size 2 \
--context-parallel-size 2 \
```

**计算过程**：

```text
# 输入
```

### 5.3 示例 3：MoE 模型

**配置**：

```text
--world-size 128 \

--pipeline-model-parallel-size 2 \
--context-parallel-size 1 \
--expert-model-parallel-size 8 \
--expert-tensor-parallel-size 2
```

**计算过程**：

```text

pp_size = 2
```

## 6. 特殊场景处理

### 6.1 Order 参数的影响

`order` 参数控制并行度的嵌套顺序，影响 rank 的分配方式。

**常见 order**：

```text
# 默认：tp-cp-ep-dp-pp
order = "tp-cp-ep-dp-pp"
global_rank = (
    tp_rank +
    cp_rank * tp +
    ep_rank * tp * cp +
    dp_rank * tp * cp * ep +
    pp_rank * tp * cp * ep * dp
)

# PP-last：tp-dp-pp（推荐用于大规模训练）
order = "tp-dp-pp"
global_rank = (
    tp_rank +
    dp_rank * tp +
    pp_rank * tp * dp
)
```

**选择建议**：

- **tp-dp-pp**：适合大规模训练，PP 组的 rank 分散在不同节点
- **tp-pp-dp**：适合单节点多卡，PP 组的 rank 在同一节点
- **tp-cp-ep-dp-pp**：支持所有并行类型的默认顺序

### 6.2 约束条件验证

### 6.2.1 基础约束

```text
# 约束1：world_size 必须能被 model_size 整除
assert world_size % (tp × pp × cp) == 0, \
    "world_size must be divisible by (tp × pp × cp)"

# 约束2：专家并行的约束
assert world_size % (expert_tp × expert_ep × pp) == 0, \
    "world_size must be divisible by expert parallel size"

# 约束3：PP-last order 的约束
if not order.endswith("pp"):
    assert expert_dp_size == dp_size, \
        "Expert DP must equal regular DP when not using pp-last order"
```

### 6.2.2 分布式优化器约束

```text
# 约束：DP × CP 必须能被分布式优化器实例数整除
assert (dp_size × cp_size) % num_dist_opt_instances == 0, \
    "Data parallel size should be divisible by partial DistOpt shard factor"
```

### 6.2.3 虚拟流水线约束

```text
# 约束：必须使用流水线并行
if virtual_pipeline_model_parallel_size is not None:
    assert pipeline_model_parallel_size > 1, \
        "pipeline-model-parallel size should be greater than 1 with interleaved schedule"
```

### 6.3 动态调整并行度

在某些情况下，可以在运行时动态调整并行度：


**使用场景**：

- 动态调整专家并行度
- 适应不同的模型层配置
- 测试和调试

## 7. Context Parallel 与 Sequence Parallel 的关系

### 7.1 两者的区别

Context Parallel (CP) 和 Sequence Parallel (SP) 是两种不同的序列优化策略，它们可以**同时使用**，各自解决不同的问题。

### 7.1.1 Context Parallel (CP)

**定义**（来自 `docs/api-guide/context_parallel.md`）：

> Context Parallelism (“CP”) is a parallelization scheme on the dimension of sequence length. Unlike prior SP (sequence parallelism) which only splits the sequence of Dropout and LayerNorm activations, CP partitions the network inputs and all activations along sequence dimension.

**核心特点**：

- **分割范围**：分割**所有**的序列数据和激活值
- **影响模块**：影响所有层，特别是 Attention 层需要通过 all-gather 收集完整的 KV
- **主要目的**：支持超长上下文（8K+ tokens），减少单个 GPU 的激活内存
- **通信模式**：在 CP 组内进行 all-gather（KV）和 reduce-scatter（梯度）

### 7.1.2 Sequence Parallel (SP)

**定义**（来自 `megatron/core/model_parallel_config.py`）：

> Makes tensor parallelism more memory efficient for LLMs (20B+) by parallelizing layer norms and dropout sequentially.

**核心特点**：

- **分割范围**：只分割 LayerNorm 和 Dropout 的输出
- **影响模块**：只影响 TP 组内的内存优化，不改变计算逻辑
- **主要目的**：在使用 TP 时减少激活内存，避免重复存储
- **通信模式**：在 TP 组内进行 scatter 和 gather 操作
- **参数设置**：`--sequence-parallel`（布尔标志）
- **前置条件**：**必须启用 TP（TP > 1）**

**代码位置**：

### 7.2.1 可以同时启用


### 7.2.2 作用域不同

| 特性 | Context Parallel (CP) | Sequence Parallel (SP) |
| --- | --- | --- |
| 作用域 | 跨 TP 组，在 CP 组内 | 仅在 TP 组内 |
| 分割对象 | 所有序列数据和激活 | 仅 LayerNorm/Dropout 输出 |
| 影响计算 | 改变计算分布（每个 GPU 处理部分序列） | 不改变计算，只优化内存 |
| 通信组 | CP 组（跨 TP 组的对应 rank） | TP 组 |
| 主要收益 | 支持超长序列，减少激活内存 | 减少 TP 中的内存冗余 |
| 前置条件 | CP > 1 | TP > 1 |

### 7.2.3 通信模式对比

**Context Parallel 的通信**：

```text
# CP 组的构成（parallel_state.py:582-595）
# 每个 GPU 和其在其他 TP 组中的对应位置组成 CP 组
# 例如：TP=4, CP=2, 则 CP 组为：
# [GPU0, GPU4], [GPU1, GPU5], [GPU2, GPU6], [GPU3, GPU7]

# Attention 层中的通信
# Forward: all-gather KV from CP group
# Backward: reduce-scatter KV gradients to CP group
```

**Sequence Parallel 的通信**：

```text
# SP 在 TP 组内进行
# Forward: scatter LayerNorm/Dropout output along sequence dim
# Backward: gather gradients from TP group

# 示例：mappings.py:276-293
class _ScatterToSequenceParallelRegion(torch.autograd.Function):
    """Split the input and keep only the corresponding chunk to the rank."""
    
    @staticmethod
    def forward(ctx, input_, group):
        """Forward: split along first dim (sequence)."""
        return _split_along_first_dim(input_, group)
    
    @staticmethod
    def backward(ctx, grad_output):
        """Backward: gather along first dim."""
        return _gather_along_first_dim(grad_output, ctx.group), None
```

### 7.3 并行度计算的影响

### 7.3.1 CP 影响并行度计算

CP 参与 `world_size` 的分解：

```text
# CP 影响 model_size 和 DP 的计算
model_size = TP × PP × CP
DP = world_size / (TP × PP × CP × EP)

# 示例
world_size = 64
TP = 4, PP = 2, CP = 2, EP = 1
model_size = 4 × 2 × 2 = 16
DP = 64 / 16 = 4
```

### 7.3.2 SP 不影响并行度计算

SP 是一个**优化标志**，不参与并行度的数值计算：

```text
# SP 只是一个布尔标志
sequence_parallel = True  # 或 False

# 不影响 world_size 的分解
world_size = TP × PP × CP × DP × EP  # SP 不在这个公式中
```

### 7.4 使用场景

### 7.4.1 何时使用 Context Parallel

**适用场景**：

- 训练超长上下文模型（8K, 16K, 32K+ tokens）
- 激活内存不足，无法容纳完整序列
- 需要在多个 GPU 上分布序列处理

**示例配置**：

```text
# 长上下文训练（32K tokens）
--seq-length 32768 \
--context-parallel-size 4 \           # 每个 GPU 处理 8K tokens
--tensor-model-parallel-size 8 \
--pipeline-model-parallel-size 2
```

**性能考虑**：

- CP 增加了 Attention 层的通信开销（all-gather KV）
- 但大幅减少了激活内存（CP 倍）
- 适合长序列场景，短序列不建议使用

### 7.4.2 何时使用 Sequence Parallel

**适用场景**：

- 已经使用 TP（TP > 1）
- 大模型（20B+ 参数）
- 需要进一步减少激活内存

**示例配置**：

```text
# 大模型训练，结合 TP 和 SP
--tensor-model-parallel-size 8 \      # 必须 > 1
--sequence-parallel \                 # 启用 SP
--pipeline-model-parallel-size 4
```

**性能考虑**：

- SP 的通信开销很小（只在 TP 组内）
- 内存节省显著（避免 LayerNorm/Dropout 的重复存储）
- **推荐在使用 TP 时始终启用 SP**

### 7.4.3 同时使用 CP 和 SP

**适用场景**：

- 超长上下文 + 大模型
- 需要最大化内存效率

**示例配置**：

```text
# 最大化内存优化：CP + SP + TP
--seq-length 65536 \                  # 64K 超长上下文
--context-parallel-size 8 \           # CP=8，每个 GPU 处理 8K
--tensor-model-parallel-size 8 \      # TP=8
--sequence-parallel \                 # SP 进一步优化内存
--pipeline-model-parallel-size 4
```

**效果**：

- CP：将序列切分为 8 份，激活内存减少 8 倍
- SP：在 TP 组内优化 LayerNorm/Dropout，进一步减少内存
- 两者协同工作，实现最大内存效率

### 7.6 配置建议总结

| 场景 | TP | PP | CP | SP | 说明 |
| --- | --- | --- | --- | --- | --- |
| 小模型，短序列 | 1 | 1 | 1 | ❌ | 单 GPU 训练，不需要并行 |
| 中等模型 | 2-4 | 2-4 | 1 | ✅ | 使用 TP+SP 优化内存 |
| 大模型 | 8 | 8 | 1 | ✅ | TP+PP+SP，SP 必须启用 |
| 长上下文 | 4-8 | 2-4 | 2-8 | ❌ | 使用 CP 处理长序列 |
| 长上下文 + 大模型 | 8 | 4 | 4-8 | ✅ | CP+TP+SP，最大化内存效率 |

**关键原则**：

1. **SP 依赖 TP**：只有 TP > 1 时才能启用 SP
2. **CP 独立于 TP**：CP 可以单独使用，也可以与 TP 结合
3. **CP + SP 协同**：两者可以同时使用，分别优化不同方面
4. **推荐配置**：使用 TP 时总是启用 SP；处理长序列时考虑 CP
