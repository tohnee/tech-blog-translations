### 3. 协议实现

### 3.1 传输：复用引擎 HTTPServer，四条路由同一路径

ModelContextProtocolServer.cpp:514 的 `Start()`：

```cpp
FHttpServerModule::Get().StartAllListeners();
auto Router = FHttpServerModule::Get().GetHttpRouter(Port, /*bFailOnBindFailure=*/true);
// 同一路径绑 POST / GET / DELETE / OPTIONS
PostRouteOptions.bDetectClientDisconnect = true;   // 只有 POST 开启断连检测

```

三个工程细节：

- **先获取新 router 再拆旧的**。注释解释：`Stop()` 会取消所有在飞调用并结束所有会话，所以在新 listener 确认可用前不能放弃正在服务的端口。请求不同端口时旧 listener 不受影响。
- 绑定失败区分两种日志：**“keeps serving port N”**（重启失败，旧端点还在）vs **“could not start”**（什么都没在服务）。
- 启动时打一条 **EULA 警告**：通过本插件传给你所连 LLM 服务的数据属于 UE EULA 下的 Licensed Technology，你有责任确保供应商不拿它做训练输入（EULA 第 6(e) 条）。

**GET 直接返回 405**（Server.cpp:1703-1721），`Allow` 头是 `POST, DELETE, OPTIONS`。

所以**没有常驻 SSE 通道** —— SSE 只在「有 session 且请求带 `_meta.progressToken`」时，针对那一次 POST 开流。

服务器由 **`FTSTicker` core ticker** 驱动（延迟 0.0f），不是独立线程。

### 3.2 会话生命周期

```text
POST initialize                 → 协商版本、建 Session（GUID）、状态 Initializing
                                ← 响应带 Mcp-Session-Id 头
POST notifications/initialized  → 状态 Initialized，发 SessionStart 遥测，返回 202
POST tools/call ...             → 带 Mcp-Session-Id 头
DELETE                          → 移除会话 + 取消在飞调用，202（未知 id 返回 400）
```

会话结构见 ModelContextProtocolSession.h:172：

```cpp
ID / Status / NegotiatedProtocolVersion(const) / ClientAddress
ClientCapabilities / RequestState

```

`EModelContextProtocolSessionStatus{Initializing, Initialized}`。

**DELETE 的处理顺序有讲究**（Server.cpp:1747-1800）：**先摘路由再取消**，否则同步完成的回调可能通过已停止的会话回写。而且只对真正到达过 Initialized 的会话发 `SessionEnd`（先快照 `bWasInitialized`），避免客户端乱传 session id 产生幽灵事件。模态阻塞时把取消推迟到 `DeferredToolCancellations`。

请求身份模型：

```cpp
FModelContextProtocolToolRequestId{SessionId, InvocationSerial, InvocationId(FGuid)}
// 两个 ctor：(RequestId, SessionId="", InvocationSerial=0) 与 (RequestId, FGuid) 无会话版

FModelContextProtocolRequestState{
    ActiveRequests,
    NextInvocationSerial,                  // 预自增，0 永不发出
    CancelledRequestsPendingCompletion
}

```

`FModelContextProtocolToolContext` 的关键注释：

- :141-143 —— 取消时**写 `EventStreamWrite`（若已设置）否则写 `OnComplete`，绝不同时写两者**（避免 park 住的 POST 被双写）。
- :150-152 —— `InvocationSerial` 防止用已取消 invocation 的迟到结果应答一个复用 id 的新调用。

### 3.3 版本协商：四个版本，两种选择模式

ModelContextProtocolVersion.cpp:12 的目录（**顺序即语义**，从新到旧）：

| 版本 | Schema dialect | Selection |
| --- | --- | --- |
| 2026-07-28 | draft 2020-12 | RequestMetadata |
| 2025-11-25 | draft 2020-12 | Initialization |
| 2025-06-18 | draft-07 | Initialization |
| 2024-11-05 | draft-07 | Initialization |

```cpp
enum class EProtocolVersion : uint8 { Version2024_11_05, Version2025_06_18,
                                      Version2025_11_25, Version2026_07_28 };
inline constexpr EProtocolVersion DefaultMaximumProtocolVersion = Version2026_07_28;
inline constexpr const TCHAR* ProtocolVersion = TEXT("2025-11-25");  // 兼容标识
enum class EProtocolVersionSelection { Initialization, RequestMetadata };

```

三个要点：

1. `IsProtocolVersionSupported`（:62-74）**不是日期比较**，而是从新到旧遍历目录、看是否已经”路过”了 `MaximumProtocolVersion` —— **前缀语义**。注释明写：”Catalogue order selects the initialization fallback without inferring compatibility from enum values or date strings.”
2. `SelectInitializationProtocolVersion`（:76-91）在 Initialization 型条目里精确匹配，否则回落到第一个受支持的 Initialization 条目。**`2026-07-28` 永远不能成为 initialize 版本** —— 这就是 `ProtocolVersion` 兼容常量取 `"2025-11-25"` 的原因。
3. 客户端请求的版本若受支持就用它，否则回落到服务器首选的 Initialization 版本。

**`2026-07-28` 走无会话的 header 模式**（`Mcp-Protocol-Version` 头）。Server.cpp:928-948 的白名单：仅当版本为 `2026_07_28` + RequestId 有效 + 方法 ∈ `{server/discover, tools/list, tools/call, resources/list, resources/read}` 才受理，否则 404 MethodNotFound。

- `server/discover` 返回 `{supportedVersions: [...], capabilities: {resources:{}, tools:{}}}`
- **工具参数 header 校验**：`DoParameterHeadersMatch(Request, InputSchema, Arguments)`，不匹配返回 `HeaderMismatch` 错误（Server.cpp:1260）

initialize 的完整校验（Server.cpp:999-1075）：要求 `protocolVersion` 是字符串 → 协商 → `IsObjectMetadataValid` → 要求并校验 `capabilities` 与 `clientInfo` → session ID = `FGuid::NewGuid().ToString(EGuidFormats::DigitsLower)` → 解析 `roots.listChanged` / `sampling` / `elicitation`（**elicitation 仅 2025_06_18 与 2025_11_25 解析**）。

响应：`ServerInfo.Name = "unreal-mcp"`，`Version = FEngineVersion::Current().ToString(EVersionComponent::Changelist)`，`Tools.ListChanged = true`，Resources 默认，`Instructions = FString::Join(GatherInstructions(), TEXT("\n\n"))`。

### 3.4 分页与进度

- **分页**由 cvar `ModelContextProtocol.PaginationPageSize` 控制，**默认 0 = 不分页，返回全部**。cursor 是 base64 编码的偏移量。
- **进度通知是纯心跳**（Server.cpp:1685-1696）：仅当 ProgressToken 有效 + `EventStreamWrite` 已设置 + 距上次 ≥ `ProgressIntervalSeconds` 时，`++LastProgressValue` 然后发出，**不带 total**。注释：”Not sending a total progress value, so this is simply a heartbeat as the total duration is unknown.”
- **`tools/list_changed` 延迟到下一次 Tick 广播，且只送达当前有活跃 SSE 流的会话** —— 静默会话会漏收。这是实现层面的真实限制。
