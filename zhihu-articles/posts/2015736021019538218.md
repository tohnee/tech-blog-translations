### 一：问题的提出

### 1.1 为什么要投机采样？

大语言模型的推理，本质上是一个“一个接一个蹦词”的**自回归（Autoregressive）**过程。这个过程看似简单，却隐藏着深刻的性能瓶颈。

1. **内存墙**：LLM 的参数量动辄百GB，远超GPU核心的SRAM缓存。每一次生成 Token，都意味着海量模型权重需要从高带宽显存（HBM）加载到计算核心。当我们的请求批量（Batch Size）很小时，GPU的计算单元（Tensor Cores）大部分时间都在“等米下锅”，性能被显存带宽死死卡住。这就是典型的 **Memory-bound** 状态。
2. **串行依赖的诅咒**：生成第 $N$ 个 Token，必须知道第 $N-1$ 个 Token 是什么。这种固有的串行性，使得我们无法通过简单的并行化来加速单个序列的生成过程。

在这种背景下，一个天才的想法诞生了：既然一次前向计算 1 个 Token 和并行计算 5 个 Token，对于 Memory-bound 的负载来说，**延迟几乎没有差别**，那我们为什么不一次性多算几个呢？

### 1.2 核心范式：Draft-then-Verify（先草拟，后验证）

这就是投机采样的核心思想，可以精确地总结为 **“Draft-then-Verify”**。

- **草拟（Draft）**：我们用一个**更快、更弱、或更便宜**的“草拟模型（Drafter/Draft Model）”，让它快速地猜出接下来可能的一小段文本（例如 5 个 Token）。
- **验证（Verify）**：然后，我们把这一小段猜测的文本，交给目标大模型（Target Model），让它利用其强大的并行计算能力，做**一次前向传播**，来并行地、一次性地验证这些猜测是否“合理”。

关键在于，通过一套精妙的概率学校验机制，不仅能判断猜测的对错，还能在猜错时进行“无痕修复”，确保最终输出的文本分布与完全由大模型自己一个一个生成时，**在统计学意义上完全一致**。这种“无损性（Lossless）”是投机采样能够被广泛接受的理论基石。

### 二：数学原理—— 无损性与期望加速的推导

这一部分将深入数学细节，打消对于“投机采样会不会影响模型效果”的疑虑。

### 2.1 符号系统与终极目标

- 设词表为 $\mathcal{V}$，当前已生成的前缀序列为 $x_{1:t}$。
- **目标模型分布 $p_t(v)$**：代表目标大模型在给定前缀 $x_{1:t}$ 后，生成下一个词为 $v$ 的真实概率，即 $p(v \mid x_{1:t})$。这是我们追求的“黄金标准”。
- **草拟模型分布 $q_t(v)$**：代表草拟模型在同样前缀下，生成下一个词为 $v$ 的近似概率，即 $q(v \mid x_{1:t})$。它计算得很快，但可能不准。

**目标**：设计一个采样算法，其最终输出的任意 Token $v$ 的概率，都严格等于 $p_t(v)$，同时尽可能减少调用目标模型进行前向计算的次数。

### 2.2 单步改造拒绝采样（Modified Rejection Sampling）

我们从最经典的拒绝采样说起，虽然它无法直接用于LLM，因为“拒绝”后重新采样再验证，意味着大模型的又一次完整前向，成本太高。投机采样对此进行了魔改。此处参考论文《Accelerating Large Language Model Decoding with Speculative Sampling》，原文链接:

[https://arxiv.org/pdf/2302.01318](https://arxiv.org/pdf/2302.01318)

**算法三部曲：**

1. **草拟（Propose）**：从草拟分布中采样一个候选 Token $\tilde{y} \sim q_t(v)$。
2. **验证（Accept/Reject Decision）**：

- 我们已经通过一次目标模型的前向，获取了所有 $v \in \mathcal{V}$ 的真实概率 $p_t(v)$。
- 生成一个随机数 $r \sim U$。
- 如果 $r < \min\left(1, \frac{p_t(\tilde{y})}{q_t(\tilde{y})}\right)$，则**接受** $\tilde{y}$，输出它，本轮结束。

3. **残差重采（Residual Resampling）**：

**无损性证明（The Proof of Losslessness）**

我们要证明，经过上述流程，任何一个 Token $v_0 \in \mathcal{V}$ 被最终输出的概率 $P(\text{output} = v_0)$，不多不少，正好就是 $p_t(v_0)$。

输出 $v_0$ 只有两条互斥的路径：

- **路径 A：草拟的就是 $v_0$，并且被接受了。**<br>

- **路径 B：草拟的 Token 被拒绝了，然后在残差重采中抽中了 $v_0$。**<br>

**最终合并概率：**

$$ P(\text{output} = v_0) = P(A) + P(B) = \min(p_t(v_0), q_t(v_0)) + \max(0, p_t(v_0) - q_t(v_0)) $$

这个等式的结果恒为 $p_t(v_0)$。证明完毕。这个推导直接支撑了投机采样底层的逻辑。

---

*这里的推到可能有点复杂，我简单解释一下，目标大模型的分布*$p(v)$*是我们真正想要的**完美拼图**，而草拟模型的分布*$q(v)$*是我们手里的**初稿拼图**。 对于词表中的某一个具体单词*$v$*（比如单词 apple）：*

- ***情况 1：草拟模型低估了它（***$q(v) < p(v)$***）** 比如大模型认为下个词是 apple的概率是 60%，但草拟模型只给出了 20%。 因为草拟模型给的太少了（20%），所以只要草拟模型猜了 apple，大模型**100%全盘接受**（接受率*$\min(1, \frac{0.6}{0.2}) = 1$*）。 **但是，**我们最终需要 apple出现的总概率是 60%，现在通过草拟并接受只贡献了 20% 的概率。剩下的 40% 从哪里来？**从残差重采里补回来**这缺少的 40%，刚好就是*$p(v) - q(v)$*。*
- ***情况 2：草拟模型高估了它（***$q(v) \ge p(v)$***）** 比如大模型认为 apple 的概率只有 30%，但草拟模型脑子一热，给出了 80% 的概率。 这时候大模型不能全盘接受，只能**打折接受**。打多少折？打*$\frac{30\%}{80\%}$*的折（即接受率为*$\min(1, \frac{0.3}{0.8}) = \frac{3}{8}$*）。 那么，apple 被（草拟且接受）的实际总概率 =*$80\% \times \frac{3}{8} = 30\%$*。 **概率已经完美达标了（30%）。** 既然已经达标，在残差重采阶段，就**绝对不能**再选到 apple 了，否则它的概率就超标了。所以，此时它的残差权重必须是 **0**。*

*如果还不是特别理解，就记住一个目标：对于词表里的任意一个词*$v$*，它最终被输出的概率*$P_{\text{final}}(v)$*必须严格等于*$p_t(v)$*。*

*一个词被输出，有且只有**两条路径**：*

- ***路径 A**：被草拟模型选出*$\rightarrow$*并且被大模型接受。*
- ***路径 B**：草拟模型选了某个词*$\rightarrow$*大模型拒绝了它*$\rightarrow$*从残差分布*$w(v)$*中重新采到了*$v$*。*

### **2.3 链式验证（Chain Verification）与“红利 Token（Bonus Token）”**

实践中，一次草拟 $K$ 个 Token: $\tilde{x}_{t+1}, \dots, \tilde{x}_{t+K}$。 目标模型一次前向，并行计算出所有 $K+1$ 个位置的 logits。验证过程是链式的：

1. 在位置 $t+1$，用 $p(\cdot|x_{1:t})$ 和 $q(\cdot|x_{1:t})$ 验证 $\tilde{x}_{t+1}$。
2. 若接受，则在位置 $t+2$，用 $p(\cdot|x_{1:t}, \tilde{x}_{t+1})$ 和 $q(\cdot|x_{1:t}, \tilde{x}_{t+1})$ 验证 $\tilde{x}_{t+2}$。
3. 以此类推，**一旦在第 $i$ 位发生拒绝**，我们就在该位进行残差重采得到一个确定的 Token，然后**立即停止本轮验证**，丢弃后续所有草拟 Token。

![](https://pic2.zhimg.com/v2-a975f91cee15deebc454f2dcc3dc0ef5_r.jpg)
*参考图*

**Bonus Token - Chen 等人画龙点睛的一笔** 如果运气爆棚，$K$ 个草拟 Token 全部被接受了，会发生什么？ 这意味着我们已经免费获得了 $K$ 个正确的 Token。同时，我们的大模型在并行验证时，实际上已经计算出了第 $K+1$ 个位置的概率分布 $p(\cdot|x_{1:t}, \tilde{x}_{t+1}, \dots, \tilde{x}_{t+K})$。这个分布是基于一个完全被验证过的正确前缀计算出来的，完全可信。 因此，我们可以**直接从这个分布中正常采样一个 Token**，作为“红利”送出。 这使得一轮投机，最多可以产出 **K+1** 个 Token，极大地提高了理论加速上限。

### 2.4 期望加速比的量化分析

Leviathan 等人给出了期望生成 Token 数的分析公式。假设平均接受率为 $\alpha$，每轮生成的 Token 数 $N$ 是一个被 $K+1$ 截断的几何随机变量。 来自论文《Fast Inference from Transformers via Speculative Decoding》原文链接：

[https://arxiv.org/pdf/2211.17192](https://arxiv.org/pdf/2211.17192)

$$ E[N] = \sum_{i=1}^{K} i \cdot \alpha^{i-1}(1-\alpha) + (K+1)\alpha^K = \frac{1 - \alpha^{K+1}}{1 - \alpha} $$

这个公式清晰地告诉我们：**草拟模型与目标模型的分布对齐程度（即接受率 $\alpha$）是决定加速效果的生命线。**

### 三：草拟器架构演进

最直接的实现，用一个小尺寸的同族模型（如 Llama-7B）来为大模型（如 Llama-70B）草拟。

### 3.3 流派三：结构化草拟——Medusa vs. EAGLE

这是当前工业界（vLLM、TensorRT-LLM）支持的重点，它通过修改目标模型结构来实现高效的内置草拟。

在传统的投机采样中，我们需要加载一个 LLaMA-7B 去给 LLaMA-70B 打下手。这带来了巨大的显存开销和不可忽视的分布式通信延迟。

**“能不能让大模型自己给自己当草拟器，完全不引入额外的网络结构？”** 带着这个灵魂拷问，2023年末到2024年初，开源社区跑出了两匹最大的黑马：**Medusa** 和 **EAGLE**。它们都使用了**树形验证**，但在“如何预测未来”这个问题上，走上了完全不同的分岔路。

### Medusa —— 简单暴力的多头并行预测 (The Shotgun Approach)

*参考来源：[FasterDecoding/Medusa GitHub](https://github.com/FasterDecoding/Medusa)*

**核心理念：既然大模型的最后一层隐藏状态（Hidden State）包含了极其丰富的上下文信息，我们为什么不直接用它来预测未来多个词？**

- **架构设计（简单即正义）**： Medusa 的改动极其轻量。它在目标大模型的顶层（原来的 Language Model Head 旁边），并排插上 $k$ 个额外的、非常轻量级的 MLP（多层感知机）预测头。<br>

![](https://picx.zhimg.com/v2-5bef2402b8b66644d3aee0c35c0b0cbd_r.jpg)
*Medusa adds extra &quot;heads&quot; to LLMs to predict multiple future tokens simultaneously. When augmenting a model with Medusa, the original model stays untouched, and only the new heads are fine-tuned during training. During generation, these heads each produce multiple likely words fo*

- **草拟与建树逻辑**： 在推理时，大模型前向传播一次，不仅得到了 $t+1$ 的概率，还同时通过 Medusa Heads 得到了未来好几步的概率分布。 如何用这些分布构建草拟树？Medusa 采用的是**笛卡尔积**组合。例如，Head 1 取 Top-2 候选，Head 2 取 Top-3 候选… 组合起来形成一棵包含多条分支的候选树（例如 `[I, am, glad]`，`[I, feel, sad]`），然后交给大模型进行一次 Tree Attention 验证。
- **Medusa 的瓶颈：特征不确定性（Feature Uncertainty）** Medusa 的 Head 2 在预测 $t+3$ 的词时，它的输入**仅仅是第 $t$ 步的隐藏状态**。这意味着，它在**完全不知道 $t+1$ 和 $t+2$ 到底生成了什么词**的情况下，就要强行预测 $t+3$。 这在数学上是一个极其发散的分布。举个例子，前文是 “The capital of France is”，第 $t$ 步是 “is”。下一个词可能是 “Paris” 也可能是 “space“。在不知道下一个词的情况下预测下下个词，模型只能给出极其模糊的概率分布。这导致 Medusa 不得不构建非常庞大的候选树来“碰运气”，极大地浪费了验证阶段的算力。
- **工程妥协：放宽的接受标准（Relaxed Acceptance）** 为了弥补预测不准导致的低接受率，Medusa 在仓库中提出了一种非严谨的 **Typical Acceptance**（典型截断接受）策略。它通过放宽阈值来换取速度，这在严格意义上**放弃了理论无损（Lossless）**的保证，可能会导致生成分布与原模型产生微小偏移。

### EAGLE —— 降维打击的特征级自回归 (The Sniper Approach)

*🔗 参考来源：[Lihui-Gu/EAGLE GitHub](https://github.com/Lihui-Gu/EAGLE)*

**核心理念：不要直接预测未来的 Token，而是去预测大模型下一层的上下文特征向量（Contextual Feature Vectors）**

EAGLE 的作者精准地抓住了 Medusa “特征不确定性”的痛点，给出了一个解法：**Extrapolation Algorithm for Greater Language-model Efficiency**。

![](https://picx.zhimg.com/v2-de5834b098afe8d99f6d8827b1c12f83_r.jpg)
*Pipeline of EAGLE.*

1. **架构设计**： EAGLE 没有像 Medusa 那样弄一堆并行的头。它引入了一个极其轻巧的**单层 Transformer Block**（作为 Auto-regressive Head）。 它的目标不是预测词，而是预测**目标大模型倒数第二层的隐藏状态向量。**
2. **精妙的自回归草拟过程（解决不确定性）**： EAGLE 的草拟过程是一个极速的、微型的自回归循环，每一步只需极其微小的算力：

- **Step 1**：拿大模型当前的隐藏状态 $h_t$，加上当前采样出的 Token Embedding $e_t$，输入给 EAGLE Head，预测出下一个未来的隐藏状态 $h_{t+1}$。
- **Step 2**：把预测出的 $h_{t+1}$ 送入大模型的 LM Head，立刻得到下一个词 $x_{t+1}$ 的概率分布，并采样出一个猜测的词。
- **Step 3（绝杀）**：拿预测出的 $h_{t+1}$，**加上刚刚猜测出的词的 Embedding $e_{t+1}$**，再次输入给 EAGLE Head，预测 $h_{t+2}$。

发现了吗，EAGLE 在草拟未来时，**把当前猜测的 Token 重新注入回了预测链路中！** 它在特征空间里模拟了大模型的思维过程，消除了 Medusa 的“闭着眼睛瞎猜”的窘境。

3. **极致的性能与无损承诺**：

![](https://pic4.zhimg.com/v2-6945e15cd3546e6fab745e657f893b01_r.jpg)
*EAGLE效果*

4. **vLLM 官方的偏爱**： 在 vLLM V1 Engine 的源码中（`init_speculator`），目前官方 API 示例**唯一显式支持并硬编码返回的 Speculator 就是 `EagleSpeculator`**（其他会抛出 `NotImplementedError`）。这足以说明 EAGLE 架构在工业界落地时的稳定性和工程认可度。

| 维度 | FasterDecoding / Medusa | Lihui-Gu / EAGLE |
| --- | --- | --- |
| 预测目标 | 并行预测未来的 Token | 自回归预测未来的 Feature |
| 草拟网络结构 | 多个并行的 MLP Head | 单个轻量级 Transformer 模块 |
| 特征不确定性 | 严重（后置Head不知前置Token） | 彻底解决（将猜测Token重新注入） |
| 草拟树形态 | 庞大、宽阔的笛卡尔积树（试错型） | 稀疏、细长的连通树（精准型） |
| 输出质量保证 | 采用 Typical Acceptance（近似无损） | 严格遵循 Rejection Sampling（绝对无损） |
| vLLM 工程集成 | 早期支持 / 需自行处理复杂语法同步 | V1 Engine 官方主推 |

### 3.4 验证的革命：树形验证（Tree Verification）

链式验证一旦拒绝，整条链都会被丢弃，效率低下。SpecInfer 和 EAGLE 等工作引入了**树形验证**。

1. **草拟 Token 树**：草拟器生成一个包含多个分支的候选 Token 树。
2. **展平与定制掩码**：将树上所有节点按拓扑序展平为一个一维序列。然后，为这次前向传播**动态生成一个定制的 Attention Mask**，确保每个 Token 在计算注意力时，只能看到它在树中的祖先节点，而看不到它的兄弟或叔侄节点。
3. **一次前向，全树验证**：目标模型通过一次带定制掩码的前向传播，并行地计算出树上所有节点的真实概率。
4. **最长路径提取**：最后，从树的根节点开始，沿着所有被接受的边，找到那条最长的路径作为本轮的输出。

这使得一次验证可以覆盖更多候选，平均接收长度显著增加，极大提升了吞吐量。

### 四：2025-2026 一些研究—— 投机采样的未来形态

### 4.1 异构词表无损投机（Lossless SD for Heterogeneous Vocabularies）

- **历史难题**：传统投机采样强行要求草拟和目标模型拥有**完全一致的词表（Tokenizer）**，这极大地限制了模型的组合。
- **破局之道**：通过在加载时预计算两个词表的交集，并在推理时动态地将草拟 logits mask 到交集空间，再将采出的 Token ID 映射回目标模型空间，实现了不同词表模型间的无损投机。这是工程上的重大解放。

### 4.2 投机式投机解码（Speculative Speculative Decoding, SSD）

- **现有瓶颈**：“草拟-验证”依然是串行依赖的。草拟器必须**等待**验证结果。
- **极致并行**：在目标模型进行验证的“空窗期”，让草拟器**不要等**，而是去**预测**所有可能的验证结果（例如，在第1位拒绝、在第2位拒绝…），并为每一种可能性**提前准备好后续的草拟分支**，并缓存起来。当真实验证结果一出来，直接从缓存中取出对应的分支，几乎消除了草拟阶段的延迟。

### 六：工程实践指南

### 6.1 配置与调参圣经

1. **`num_speculative_tokens` (K 值)**：K 越大，理论加速上限越高，但被拒绝的概率也越大，浪费也越多。一些工作提出了动态 K 调节，vLLM 社区 PR 讨论中将其作为 `eagle_dynamic` 的目标。
2. **草拟器选择**：Chen 等人的实验表明，草拟器不必非常强大，只要它生成的 logits 和目标模型的延迟差异足够大即可。
3. **采样策略一致性**：必须确保草拟和目标模型在**相同的采样语义**下（同 `temperature`，`top-p`）进行概率比较和残差采样。
4. **与流水线并行的组合**：vLLM 文档和源码都提示，这二者的组合存在限制，需要注意版本兼容性和模型支持情况。
