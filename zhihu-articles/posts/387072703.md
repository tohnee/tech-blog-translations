## 1 为什么要int8量化

其实做深度学习模型做量化主要也就是以下三个目的：

- 加快推理速度
- 减少推理内存
- 减少模型文件存储空间

唯一需要解释的可能就是减少模型文件存储空间，在实际应用中也十分重要。例如人脸验证模型随支付宝手机App一起打包发布，那么模型越小用户下载App越快，明显提升用户体验。

当然量化也有副作用，就是会降低推理精度咯。从下图可以看出，无论是表示范围还是精度，float32都远远高于int8。如果量化的不好会出现数据溢出和精度丢失，所以量化算法直接决定量化效果的好坏！

## 2 ncnn中的fp32与int8推理

### 2.1 使用fp32推理

![](https://picx.zhimg.com/v2-ba0a9d6158031e2caa71b6137df6d52f_r.jpg)
*ncnn fp32推理模式*

对于fp32推理，卷积核weight和偏置bias为float32类型，且输入bottom_blob也是float32类型，所以直接进行进行计算即可。

### 2.2 使用int8推理

在fp32推理计算卷积时，卷积核weight需要与输入bottom_blob做float32乘法运算；而偏置bias只需要与inner_blob做float32加法运算。实际中int8乘法远比float32乘法速度运算快，float32加法则速度相对可以忍受。

所以对于int8推理，ncnn框架使用了一种折中办法：**只量化卷积核weight并使用int8计算，偏置bias仍然使用float32计算**。

![](https://pica.zhimg.com/v2-a9065e73bbaac2fcf999be466982a694_r.jpg)
*ncnn int8推理模式*

假设网络中某个卷积层有 $K$ 个卷积核，那么对于该层卷积会有2个量化参数：

- bottom_scale

是一个数值（记为 $s_b$ ），负责将该卷积层输入的bottom_blob从fp32量化到int8：

$\text{bottom_blob}_{\text{int8}}=\text{float2int}(s_b\times\text{bottom_blob}_{\text{fp32}})\tag{1}$

- weight_scales

是一个长度为 $K$ 的数组，里面每个数负责量化该卷积层第 $k$ 个卷积核权重weight：

$\text{weight_scales}=[s^1_w, s^2_w, ...,s^k_w, ..., s^K_w]\tag{2}$

$\text{weight}_{\text{int8}}=\text{float2int}(s^k_w\times\text{weight}_{\text{fp32}})\tag{3}$

因为bottom_blob和weight都是int8数据，为了防止溢出，计算获得的inner_blob使用int32数据。其中上述bottom_scale和weight_scales都是通过量化算法计算而来，后面分析。

另外由于bias使用fp32计算，所以要将卷积计算的inner_blob从int32数据反量化到fp32。反量化使用参数 $s_b$ 和 $s^k_w$ 即可完成：

$\text{inner_blob}_{\text{fp32}}=\frac{1}{s^k_w\cdot s_b}\times\text{inner_blob}_{\text{int32}}\tag{4}$

**明显可以看到这是一种逐通道处理的“per-channel”量化方式。**

其实对于ncnn只量化卷积核weight而不量化bias的方法也不必担心。因为大部分经典网络（如ResNet、DenseNet、MobileNet）都没有使用卷积中的bias参数，自然也不需要考虑。

![](https://pica.zhimg.com/v2-b710c2797d6b08242f9ed5dfcfb9eea2_r.jpg)
*MobileNetV2没有使用conv bias*

需要特别注意的是，模型中的所有卷积核weight会在推理前（即模型转换时）就完成量化并保存下来；而bottom_blom和inner_blob是在推理时完成量化与反量化。

![](https://pic2.zhimg.com/v2-6ba43edb2fc193d124cb9fd17a0026e9_r.jpg)

## 3 int8量化基本原理介绍

### 3.1 int8量化到底在做什么？

所谓的int8量化，核心内容就是计算bottom_blob和weight对应的量化权重。只要计算出每一层的量化权重，就保存在模型文件中，即完成了量化。如下图所示。

![](https://picx.zhimg.com/v2-42c66609fb2263b18a38970da3b0006b_r.jpg)

但是在开始计算bottom_scale和weight_scales前，我们先来看看量化有哪些套路。

### 3.2 int8量化的基本套路

- 训练后量化与量化感知训练

训练后量化（PTQ=Post-Training Quantization）是指先用全精度float32数据训练好模型后，再将训练好的模型量化至int8。PTQ主要由MNN/NCNN/TensorRT这类推理框架实现。

量化感知训练（QAT=Quantization Aware Training）是指在网络训练的过程中就插入量化模块，边训练边完成量化，从而让网络参数能更好地适应量化带来的信息损失。QAT主要由TensorFlow/PyTorch这类训练框架实现。

相比来说，量化感知训练理论上精度更高（实际不一定），但是实现难度更大，而且使用操作更加复杂。

- 对称量化与非对称量化

![](https://pica.zhimg.com/v2-699ef103f93def39f89128105e1ab4fc_r.jpg)

对称量化是将输入范围为 $-\max(|x|)\sim+\max(|x|)$ 范围的浮点数沿着零点对称映射到-127～+127；非对称量化将输入范围为 $\min\sim\max$ 范围的浮点数映射到-127～+127，这个应该比较好理解。

相比来说，非对称量化理论上精度更高（仍然实际不一定），但是实现难度更大。

- 线性量化与非线性量化

$\text{bottom_blob}_{\text{int8}}=s_b\times\text{bottom_blob}_{\text{fp32}}\tag{5}$

在2.2节中，都使用了线性函数 $f(x)=a\cdot x+b$ 将进行Quantize和Dequantize转换映射，即线性量化；当然也可以使用其他非线性函数转换（如tanh），即非线性量化。

相比来说，非线性量化理论上精度更高（仍然实际不一定），但是实现难度更大。

```text
TensorRT与ncnn框架都选择了最简单粗暴的“训练后量化+对称量化+线性量化”方式！
```

### 3.3 对称线性量化的问题

既然选择了对称量化+线性量化模式，享受简单粗暴优势的同时，该背的黑锅也要一起背了。

将float32数据从$-\max(|x|)\sim+\max(|x|)$ 通过线性函数 $f(x)=\frac{127}{\max(|x|)}x$ 量化到-127～+127的过程中，如果输入数据不是沿着零点对称分布，就必然会造成int8有一部会被浪费掉。由于int8数据本身就范围小，浪费太多必然导致量化精度急剧下降。

![](https://pic4.zhimg.com/v2-8c301d303bf6206362300148ebd9f903_r.jpg)

那么能否通过截断float32一部分数据，使得量化到int8尽量饱和？即**由于卷积神经网络一般情况下特征值主要分布在零点附近，可以考虑截断一些出现频率低的** $|x|$ **大的值**。所以可以考虑使用如下 $f(x)$ 进行量化：

$f(x) = \begin{cases} -127& x<-T \\ \frac{127}{T}x & -T\leq x \leq T \\ +127 & x > T \end{cases} \tag{6}$

即大于 $T$ 的浮点数都量化为 $127$ ，小于 $-T$ 的都量化为 $-127$ 。那么截断多少合适（即 $T$ 如何选取）？接下来分析ncnn如何建立数学模型解决这个问题。

![](https://pic4.zhimg.com/v2-08af944c01b6f381f7d4b034db06124b_r.jpg)

## 4 卷积核weight量化（weight_scales计算）

一旦网络训练完成并保存下来后，网络中的卷积核weight就固定了。一般情况下，网络卷积核中的数值都近似对称均匀分布在0附近（不信你可以print torchvision.models中随便某个模型某层权重）。

所以卷积核量化相对比较简单（线性量化即可，不需截断）

- 统计每个卷积核weight绝对值的最大值 $\text{absmax}=\max(|\text{weight}|)$

![](https://pic2.zhimg.com/v2-10de62bedf911b61710a64fc5a9654e5_1440w.jpg)

- 对于某层卷积，每个卷积核的量化权重为 $\text{weight_scales}[n]=\frac{127}{\text{absmax}}$

```cpp
const int weight_data_size_output = convolution->weight_data_size / num_output;
weight_scales[i].create(num_output);
for (int n = 0; n < num_output; n++)
{
    // 第n个weight卷积核
    const ncnn::Mat weight_data_n = convolution->weight_data.range(
        weight_data_size_output * n, weight_data_size_output);

    float absmax = 0.f;
    for (int k = 0; k < weight_data_size_output; k++)
    {
        // 遍历卷积输出第k个通道，找到max(|x|)
        absmax = std::max(absmax, (float)fabs(weight_data_n[k]));
    }

    weight_scales[i][n] = 127 / absmax;
}

```

这样就获得了每个卷积核weight的所有量化参数。

## 5 输入bottom_blob量化（bottom_scale计算）

与网络训练完成后卷积核weight就固定了不同，bottom_blob会随着网络输入不断变化。

那么bottom_blob相比卷积核weight：

- 每个bottom_blob都随着网络输入变化，不是固定的（如输入图片A和图片B不一样）
- 每个bottom_blob中的数据可能布差异很大（如行人检测网络输入白天和夜间图片差异大）

所以bottom_blob不能用简单的 $f(x)=\frac{127}{\max(|x|)}x$ 公式量化，需要进行3.3节中的截断操作。本节介绍bottom_blob具体量化流程。

### 5.1 Kullback-Leibler散度

在开始介绍量化原理前，先了解一下KL散度，之后用得到。

假设有两个长度的为N的离散概率分布 $P\sim p(x_i)$ 和 $Q\sim q(x_i)$ ，那么他们之间的离散KL散度定义如下：

$KL(P||Q)=\sum_{i=1}^{N}{P(i)\log\frac{P(i)}{Q(i)}}\tag{7}$

KL散度表示两个分布之间的距离，越小代表分布越相似。相关Python代码如下：

```python3
import numpy as np
def compute_kl_divergence(P, Q):
    assert(P.shape == Q.shape)
    P = P[:]
    Q = Q[:]
    KL = 0.0
    for p, q in zip(P, Q):
        KL += p * np.log(p / q)
    return KL

x = [np.random.uniform(1, 11) for i in range(10)]
x_norm = x / np.sum(x)
y = [np.random.uniform(1, 11) for i in range(10)]
y_norm = y / np.sum(y)
KL = compute_kl_divergence(x_norm, y_norm )
print(KL)
```

从下图直观可以看出两个分布越相似时KL散度越小。

![](https://pic2.zhimg.com/v2-083b67b6739bb5c72e5df9b3246aa7bb_r.jpg)

### **5.2 int8量化的数学模型建立**

之前提到NCNN使用对**称量化①**+**线性量化②**，且会进行**截断③**。那么从这三个关键词看看N如何建立数学模型。

- **对称量化**

之前提到可以截断一些出现频率低的 $|x|$ 大的值，由于是**对称量化**，那么不妨先来统计一下bottom_blob中 $|x|$ 的数量具体分布情况。

将原始float32数据 $0\sim \max(|x|)$ 量化为 $n_b$ 个区间（一般情况下设置超参 $n_b=2048$ ），计算当前 $|x|$ 所属区间并投票，然后统计直方图。

![](https://pic1.zhimg.com/v2-bd70e5be92ece6ae445040abfffbd1fe_r.jpg)

$P(i)=\frac{\text{histogram}_i}{\sum_{i=0}^{n_b-1}{\text{histogram}_i}}\tag{8}$

这样就完成 $n_b$ 个bin的统计直方图histogram；再对histogram进行归一化，即可获得第一个分布 $P(i)$ ，表示bottom_blob数值的数量分布情况。

- **截断**

这时选择从第 $T_b$ 个直方图**截断**bottom_blob中的数据，那么截断后的 $|x|$ 分布变为 $P_\text{clip}(i)$ ，即将后面的bin全部加在第 $T_b-1$ 个bin上。

$P_\text{clip}(i) = \begin{cases} P(i)& 0\leq i< T_b-1 \\ \sum_{i=T}^{n_b-1}{P(i)} & i= T_b-1 \end{cases} \tag{9}$

![](https://pic1.zhimg.com/v2-a2aacc4b83595c06c59722a7af9f57ba_r.jpg)

```cpp
std::vector<float> clip_distribution(threshold, kl_eps);
for (int j = 0; j < threshold; j++)
{
    clip_distribution[j] += stat.histogram_normed[j];
}
for (int j = threshold; j < num_histogram_bins; j++)
{
    clip_distribution[threshold - 1] += stat.histogram_normed[j];
}

```

这里threshold即 $T_b$ ，代表在第 $T_b$ 个bin截断；num_histogram_bins即为 $n_b$ ，代表原始直方图中bin的总数。

- **线性量化**

接下来还要计算量化后的数据分布 $Q$ 。最简单的办法就是先把网络量化一遍，然后再统计量化后的直方图。但是这样做计算量太大了，为了算个分布这么大动干戈完全不划算。

这里考虑由于我们使用**线性量化**将float32数据量化为int8，那么数据分布也会对应的从 $T_b$ 个bin被**线性**压缩到128个bin，所以可以通过插值的方式直接缩小 $P$ 计算出 $Q$ 分布（类似于图像缩小，只不过图像是二维，这里是更简单的一维）。

![](https://pica.zhimg.com/v2-1692d0c4362b5dabab336e29dc5ee2be_r.jpg)

先计算缩放比例，然后通过**插值**的方式从 $P$ 计算出 $Q$ 分布。

$\text{num_per_bin}=T_b/128\tag{10}$

即对于 $Q$ 中第 $j$ 个bin，首先计算出该bin对应的插值的左右边界：

$\text{start}=j\cdot\text{num_per_bin}=j\cdot\frac{T_b}{128}\tag{11}$

$\text{end}=(j+1)\cdot\text{num_per_bin}=(j+1)\cdot\frac{T_b}{128}\tag{12}$

通过左右边界与整数的差值，计算出实际插值的边界权重left_scale和right_scale：

$\text{left_scale}=\text{ceil}(\text{start})-\text{start}=\text{left_upper}-\text{start}\tag{13}$

$\text{right_scale}=\text{end}- \text{floor}(\text{end})=\text{end}-\text{right_lower}\tag{14}$

其中ceil和floor分别代表向上和向下取整。然后计算$Q$ 中第 $j$ 个bin：

![](https://picx.zhimg.com/v2-6f635cb6f6779625dc2cfcb1113fc827_r.jpg)

最后对 $Q(j)$ 进行一个简单的归一化：

$Q(j)=\frac{Q(j)}{\text{end}-\text{start}}\tag{16}$ 为了帮助理解，这里举个双线性插值的例子，如下图所示求P点，已知Q11、Q11、Q21、Q22四点像素值。

![](https://pic1.zhimg.com/v2-d1284b5cb0fcc07600ea96025d3a27c2_r.jpg)

先在x轴插值，去分别计算R1、R2

$R_1=\frac{x_2-x}{x_2-x_1}Q_{11}+\frac{x-x_1}{x_2-x_1}Q_{21}\tag{17}$$R_2=\frac{x_2-x}{x_2-x_1}Q_{12}+\frac{x-x_1}{x_2-x_1}Q_{22}\tag{18}$ 然后计算P

$P=\frac{y_2-y}{y_2-y_1}R_1+\frac{y-y_1}{y_2-y_1}R_2\tag{19}$

参考公式17，这里 $(x_2-x)$ 是对 $Q_{11}$ 的未归一化插值权重， $(x-x_1)$ 是对 $Q_{21}$ 的权重。而公式13中的left_scale就是对left_upper-1点的权重，公式14中的right_scale是对right_lower点的权重。

考虑到篇幅长度，对 $j=0$ 和 $127$ 边缘情况处理代码未贴出，有兴趣的朋友请参考源码。

```cpp
const int target_bin = 128;
const float num_per_bin = (float)threshold / target_bin;
std::vector<float> quantize_distribution(target_bin, 0.f);
// 对j=0和j=127边缘情况处理代码略去未贴出
for (int j = 1; j < 128 - 1; j++)
{
    const float start = j * num_per_bin;
    const float end = (j + 1) * num_per_bin;

    const int left_upper = (int)ceil(start);
    const float left_scale = left_upper - start;

    const int right_lower = (int)floor(end);
    const float right_scale = end - right_lower;

    if (left_scale > 0)
    {
        quantize_distribution[j] += left_scale * stat.histogram_normed[left_upper - 1];
    }

    if (right_scale > 0)
    {
        quantize_distribution[j] += right_scale * stat.histogram_normed[right_lower];
    }

    for (int k = left_upper; k < right_lower; k++)
    {
        quantize_distribution[j] += stat.histogram_normed[k];
    }

    quantize_distribution[j] /= right_lower - left_upper + left_scale + right_scale;
}

```

**由于 $P_\text{clip}$ 代表原始float32数据截断后的分布情况， $Q$ 代表原始float32数据量化为int8后的分布情况，我们希望两个分布越相似越好，也就是KL散度越小越好。**这样就建立了数学模型，将如何量化的问题转化为通过选取 $T_b$ 最小化 $P_\text{clip}$ 和 $Q$ 的KL散度值。

### 5.3 bottom_scale计算

上文提到可以最小化 $P_\text{clip}$ 和 $Q$ 两个分布的KL散度值求解。但是需要注意，KL散度要求两个分布长度一致，但是 $P_\text{clip}$ 是一个长度为 $T_b$ 的离散分布，而 $Q$ 是一个长为 $128$ 的离散分布。所以需要将 $Q$ 上采样成和 $P_\text{clip}$ 一样长的 $Q_\text{expand}$ ，然后再计算KL散度。

![](https://pica.zhimg.com/v2-4742d9669cd9666a8e932cd692e2fdd0_r.jpg)

此时依然使用插值方法，将长度为 $128$ 的离散分布 $Q$ 拉伸成 $Q_\text{expand}$，具体代码如下

```cpp
std::vector<float> expand_distribution(threshold, kl_eps);
// 对j=0和j=127边缘情况处理代码略去未贴出
for (int j = 1; j < 128 - 1; j++)
{
    const float start = j * num_per_bin;
    const float end = (j + 1) * num_per_bin;

    const int left_upper = (int)ceil(start);
    const float left_scale = left_upper - start;

    const int right_lower = (int)floor(end);
    const float right_scale = end - right_lower;

    if (left_scale > 0)
    {
        expand_distribution[left_upper - 1] += left_scale * quantize_distribution[j];
    }

    if (right_scale > 0)
    {
        expand_distribution[right_lower] += right_scale * quantize_distribution[j];
    }

    for (int k = left_upper; k < right_lower; k++)
    {
        expand_distribution[k] += quantize_distribution[j];
    }
}

```

## 写在后面

首先，int8量化肯定会导致精度下降，下降多少和网络结构、量化方式、校准图片等都有关系；其次，有很多网络结构天生不适合量化，无论怎么做精度都不会很好（如MobileNet）；还有，本文介绍的“均匀+线性+对称+KL”量化只是众多方法中的一种，除此之外还有很多种方法。

本篇文章分析了ncnn中conv int8量化的实现方式。网络加速还有很多，比如winograd卷积，CBR合并，ReQuant、指令集优化等，这些内容都不在范围内，望悉知。
