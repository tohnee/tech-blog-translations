### 用单卡 CPU“推演”千卡集群性能：SimuMax 实战指南

### 导读

面试 AI Infra 岗位时，面试官经常会问：

- 万卡集群下，TP 和 PP 如何切分？
- 网络瓶颈通常出现在哪里？
- 并行策略变化后，MFU 和显存水位会如何变化？

但普通开发者很难接触到上百张 GPU/NPU，更不用说万卡集群。问题在于：**如果不理解规模扩大后的瓶颈，就很难做好单机优化和系统设计。**

本文介绍一个适合学习和方案预研的工具：**SimuMax**。它是一个开源的分布式静态性能仿真器，可以在本地 CPU 上推演大模型训练在千卡规模下的吞吐、通信耗时和显存水位等指标。

本文以 Llama3-70B 为例，演示如何用 SimuMax 快速跑通一次“千卡集群性能推演”。

---

### 一、痛点：没有集群，如何理解分布式瓶颈？

大模型分布式训练的性能，不只取决于单卡算力，还高度依赖：

- 并行策略：TP、PP、DP、EP 如何组合；
- 节点内互联：NVLink、昇腾 HCCS 等；
- 节点间网络：InfiniBand、RoCE、普通以太网等；
- 通信库与网络配置：如 RoCE 下的 PFC/ECN 是否配置正确；
- 模型结构、batch size、序列长度等。

没有真实集群时，我们仍然可以通过静态性能仿真工具，对上述因素进行建模和对比，提前判断瓶颈所在。SimuMax 的价值就在这里：**不等有了集群才学分布式，而是先用仿真工具建立规模感。**

---

### 二、三步跑通 SimuMax 千卡推演

### Step 1：安装与环境准备

```bash
git clone https://github.com/MooreThreads/SimuMax.git
cd SimuMax
pip install -r requirements.txt
pip install -v -e .
```

建议先阅读仓库中的 README 和 examples，确认 Python 版本、依赖和示例配置。

---

### Step 2：定义硬件与网络拓扑

这一步是推演准确性的关键。建议优先使用官方模板，不要从零手写 JSON：

- 到 `configs/system` 下查找相近的硬件与网络拓扑模板；
- 根据目标集群修改节点内、节点间网络参数；
- 重点检查 `networks` 节点。

需要重点关注两类通信：

1. **high_intra_node**<br>节点内卡间通信，例如 NVLink、昇腾 HCCS。它通常影响 TP、EP 等高频通信的效率。
2. **inter_node**<br>节点间通信，例如 InfiniBand、RoCE。它通常影响 DP、PP 以及跨节点通信效率。

在 `inter_node` 中，应尽量填入贴近真实环境的带宽和延迟。**这些参数会直接影响通信耗时、迭代总耗时和 MFU 的推演结果。**

---

### Step 3：编写推演脚本并运行

新建一个 `run.py`，加载硬件配置、模型参数和并行策略，然后调用 `perf.run_estimate()` 进行推演。

示例骨架如下，具体参数名请以官方示例为准：

```python
# run.py
# 注意：以下为流程示意，具体 import 和参数名请参考 SimuMax 官方 examples
from simumax import perf

# 1. 加载系统配置：硬件、节点内/节点间网络拓扑
system_cfg = "configs/system/your_system.json"

# 2. 加载模型配置：如 Llama3-70B
model_cfg = "configs/model/llama3_70b.json"

# 3. 设置并行策略，例如 TP=8, PP=4
parallel_cfg = {
    "tp": 8,
    "pp": 4,
    # "dp": ...,
}

# 4. 执行静态性能推演
result = perf.run_estimate(
    system=system_cfg,
    model=model_cfg,
    parallel=parallel_cfg,
)

print(result)
```

运行：

```bash
python run.py
```

推演时建议记录以下信息，便于复现实验：

- 模型：参数量、层数、hidden size、序列长度；
- 并行策略：TP、PP、DP 的具体切分；
- 全局 batch size 和 micro batch size；
- 节点内互联类型与带宽；
- 节点间网络类型、带宽、延迟；
- 是否启用 RoCE 无损配置，如 PFC/ECN。

---

### 三、示例推演结果：64 卡昇腾 910B

下面是一组示例对比数据：在 64 卡昇腾 910B 环境下，对比“普通以太网”和“DCN RoCE 无损网络”对训练性能的影响。

| 网络配置 | DP 通信耗时 | 单次迭代总耗时 | MFU |
| --- | --- | --- | --- |
| 普通以太网 | 10.26 秒 | 13.56 秒 | 9.02% |
| DCN RoCE 无损网络 | 0.57 秒 | 3.35 秒 | 36.50% |

> 注：以上结果受模型配置、并行策略、batch size、拓扑和网络参数影响，主要用于说明网络配置对分布式训练性能的影响趋势。复现时请以实际配置和官方示例为准。

---

### 四、结果解读：网络是规模扩展的关键变量

从示例结果可以看到：

- 在普通网络下，DP 通信耗时达到 10.26 秒，单次迭代总耗时 13.56 秒，MFU 仅 9.02%；
- 在 RoCE 无损网络下，DP 通信耗时降至 0.57 秒，单次迭代总耗时 3.35 秒，MFU 提升至 36.50%。

这说明：**在大模型分布式训练中，算力并不是唯一成本，把算力高效连接起来的网络同样关键。** 如果底层 RoCE 没有正确配置 PFC/ECN，或者拓扑、拥塞控制设计不合理，昂贵的算力卡可能只能发挥很低的利用率。

---

### 五、结语

不要等到拥有真实集群后才开始学习分布式。使用 SimuMax 这类静态性能仿真工具，可以提前预判瓶颈，结合网络与拓扑知识进行方案对比，从而建立从单机优化到集群架构的完整视角。

对于 AI Infra 工程师而言，**先用仿真建立规模感，再用真实集群验证假设**，是一种成本更低、效率更高的学习与设计方式。
