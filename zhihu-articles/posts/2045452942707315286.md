***「AI agent到底在卷什么？」***

今年5月，OpenAI 发布了 GPT-5。但与一年前 GPT-4o 发布时的全民狂欢不同，这次行业的反应异常【 **平静】** 。

不是因为 GPT-5 不够强大。而是大模型本身，已经不再是 AI 竞争的核心壁垒了。

**而是：Agent。**

很多人以为，Agent 就是"能联网的 GPT"，就是"大模型加几个工具"。

**这是对 Agent 最大的误解。**

今天这篇文章，我们将用通俗易懂的语言来聊聊，构建一个强大的 AI Agent，需要的 7 大核心工程模块（全文较长，建议收藏阅读）：

**Token、Skill、Prompt、RAG、MCP、SDD、Harness**

![](https://pic4.zhimg.com/v2-e250904670a0f430546099850fb63dc5_r.jpg)

## ***01   Token：AI系统运行的基础信息载体***

**Token：没错，那个按个数收费的东西。**

一个汉字大约等于 1.3 个 Token，一个英文单词大约等于 1 个 Token，一张 1024x1024 的图片大约等于 768 个 Token。

**Token中文称作词元，也是大模型可以识别和处理的最小信息单位。**

就像我们人类的大脑是用神经元的电信号来思考的，AI 的大脑是用 Token 来思考的。

大模型无法直接读懂文字符号，只能识别数字化编码信息。分词器承担着语言翻译与拆分的作用，会把我们输入的文字、系统预设的指令、检索获取的资料文本，统一切割成一个个细碎的词元，再为每一个独立词元分配专属的数字编号。

模型后续所有的理解、推理、计算和文字生成工作，都依托这些数字编码完成，词元的拆分与读取过程，是AI所有交互行为的前置基础。

**所有的环节都在消耗 Token，所有的信息都以 Token 的形式存在。**

![](https://pic3.zhimg.com/v2-292c2dd1893961f94e752126b5283eb2_r.jpg)

**Token的管控水平，会关联AI** **agent运行过程中的多项基础指标。**

可以将Token理解为AI工作的 **“工作量计量单位与资源配额”** ，用户每一次提问、每一份上传文件、每一次资料检索、每一段模型输出内容，都会消耗对应数量的Token。 

**Token 的数量，决定了 AI 的思考深度。**

Token的使用规模，直接关联AI运行的资源成本，同时限定模型能够承载的上下文信息长度，对模型的信息留存能力和内容响应速度产生影响。

很多人以为，大模型的思考深度只和它的参数数量有关。其实不然。

**大模型的思考深度，同样和它能处理的 Token 数量密切相关。**

一个简单的数学题："1+1 等于几？"，只需要几个 Token 就能解决。但一个复杂的商业问题："请分析具身智能行业未来三年的战略方向，包括市场趋势、竞争格局等"，可能需要几万甚至几十万 Token 才能完整地思考清楚。

大模型的思考过程，本质上是一个 Token 一个 Token 地生成下一个最可能的 Token 的过程。它每生成一个 Token，就相当于完成了一步推理。所以，Token 的数量，就是 AI 推理步数的上限。

这就是为什么上下文窗口越大的大模型，能解决越复杂的问题。

**不是因为它更聪明，而是因为它能进行更多步的推理。**

![](https://pica.zhimg.com/v2-1075bd83dcc607a8c526d3d7c582182c_1440w.jpg)

如果Token消耗管控粗放，冗余文本过多，会占用大量资源，造成响应变慢、对话上下文截断、运行成本增加等情况。

在实际应用场景中，通过 **精简无效话术、优化提示文本、筛选有效检索内容** 等方式调控Token使用规模，可以让AI agent在固定资源配额内，承载更长的任务链路与更多的有效信息，维持平稳高效的运行状态。

**因此，对于规模化落地的AI agent产品而言，Token的精细化管控，是优化产品使用体验、降低运行成本的基础手段。**

Token 压缩技术的价值。它不仅能降低成本，更能提高 AI 的思考质量。

## ***02    Skill：是“血液”，也是钱***

很多人对Agent有一种不切实际的幻想。觉得它像个神仙，念个咒语“帮我把这个文件转成PDF发给XX邮箱”，它就能凭空完成。

其实，Agent不能凭空做任何事。

**它能做的，全依赖Skill。**

**Skill是经过规整整理的本地操作指令合集** （本质是文本，而不是可执行程序） **，是依托大模型打造的专业化能力整合形式。**

简单来说，Skill，就是一个一个已经封装好、能被大模型调用的功能模块 **。**

查询天气是个Skill，发邮件是个Skill，在CRM系统里创建工单也是个Skill。

基础大模型拥有通用的语言理解与逻辑推理能力，却不熟悉各行各业的具体工作流程，也没有适配专属场景的作业工具与标准。Skill的存在，就是用来补齐这类场景化短板， **把行业工作流程、专业知识、实操工具整套整合起来** ，可供AI agent在对应场景中主动调用或按需调取使用，让通用AI可以快速适配垂直岗位的工作模式。

![](https://pic4.zhimg.com/v2-0af8d295e9a00b0eecbef6e1dcc3cd77_r.jpg)

Skill的内容构成具备较强的完整性与实用性，内部会收纳对应场景的说明文档、标准化工作流程、落地模板案例、实操脚本工具以及各类参考学习资料。

**安装对应Skill后的AI agent，相当于掌握了对应岗位的工作技能。**

常见的Skill类型包含 **代码编写、文档总结、PPT制作、数据检索、内容校对** 等多个类别，覆盖办公、研发、运营等诸多领域，能够适配不同岗位的常态化工作需求。

**行业内多数AI agent的迭代升级，不在于基础模型的算法精进，而在于Skill能力库的持续扩充与优化。**

业内玩笑话评判一个Agent有没有真本事，别看它的聊天界面多华丽，直接问一句话： **“你的Skill清单有多少项？”**

Skill最要命的是本身是个指令文本，包含完整某项任务的一系列指令，必须要有接受指令的执行程序来执行才有效。

**否则就是一滩废品。**

如果要类比，老计算机用户最接近的类比是shell脚本或者DOS批处理程序，比如.bat .sh文件最类似skill。

值得一提的是，在过去，每个大模型厂商都有自己的 Skill 标准。OpenAI 有 Function Calling，Anthropic 有 Tool Use，谷歌有 Tools。

**这导致 Skill 无法在不同的大模型之间通用。**

**而 2026 年，行业终于形成了统一的 Skill 标准：**

——OpenAI 的 Function Calling 格式。现在，几乎所有的大模型和 Agent 框架都支持这个标准。

## ***03   Prompt：最被低估，却最关键***

**Prompt，也就是提示词，是用户或系统赋予大模型的行为指令内容。** 

但Prompt不属于简单的问答语句，是一套用来规范AI角色定位、工作规则、执行目标、工具用法、输出格式与约束条件的完整设定内容，相当于给AI编写专属的运行程序。

简单来说，在AI Agent时代，Prompt是 AI 的“编程语言” **。**

很多人对 Prompt 的理解，还停留在 "怎么提问才能让大模型给出更好的答案" 的层面。

**这是对 Prompt 最大的误解。**

在传统的计算机时代，我们用 Python、Java、C++ 这些编程语言来告诉计算机要做什么。在 AI 时代，我们用自然语言来告诉大模型要做什么。

**这种用自然语言编写的程序，就是 Prompt。**

传统的编程语言，是精确的、确定的。你写的每一行代码，计算机都会严格执行。而 Prompt，是模糊的、概率性的。你写的每一句话，大模型都会根据它的理解，生成一个最可能的结果。

这就是为什么很多人觉得 Prompt 很难写。因为你不是在给一个听话的下属下命令，而是在和一个有自己想法的同事沟通。你需要用清晰、准确、无歧义的语言，告诉它你的需求、你的目标、你的约束条件。

**一个好的 Prompt，能让一个普通的大模型变成一个强大的 Agent。一个差的 Prompt，能让一个最先进的大模型变成一个傻子。**

![](https://pic1.zhimg.com/v2-31cffd9160793722b3e0238fff7f49c8_r.jpg)

大模型本身具备基础的理解与生成能力，但没有固定的行为逻辑和工作范式，输出内容的风格、方向、标准完全依托接收的Prompt内容决定。日常使用中， **设** 定AI的职业身份、划定任务范围、明确输出版式、限制违规内容、标注工具使用规则等操作， **都属于Prompt搭建的范畴** 。

合理的Prompt设定，可以让AI摆脱随机、泛化的输出状态，按照既定规则完成标准化、规范化的任务作业。

**在AI agent的整套运行体系中，Prompt是串联各类能力模块的前置基础。**

模型的任务拆解逻辑、Skill技能的调用规则、RAG检索的筛选标准、外部工具的使用方式，都可以通过Prompt进行提前定义与约束。

**Prompt，也分几种。**

- **任务 Prompt ：是最基础的 Prompt，它告诉大模型要完成什么具体的任务。**

比如："请帮我写一封邮件"

任务 Prompt 的核心是清晰、准确、无歧义。你需要明确地告诉大模型，你的输入是什么，输出是什么，格式要求是什么。

- **角色 Prompt：是告诉大模型，它应该扮演什么角色来完成任务。**

**比如："你是一个经验丰富的医生"**

角色 Prompt 的核心是给大模型一个身份认同。当大模型认同了自己的角色，它就会用这个角色的思维方式、知识体系和语言风格来完成任务。

- **思维 Prompt ：是最高级的 Prompt，它告诉大模型应该如何思考来完成任务。**

比如："请先列出所有可能的方案，然后逐一分析它们的优缺点"

思维 Prompt 的核心是引导大模型的推理过程。很多时候，大模型不是不会解决问题，而是不知道应该如何思考问题。一个好的思维 Prompt，能让大模型的推理能力提升一个数量级。

**没有万能的 Prompt。**

不同的任务、不同的大模型、不同的场景，需要不同的 Prompt。最好的 Prompt，永远是针对具体问题定制的 Prompt。

## ***04    RAG：让它不一本正经的胡说八道***

**RAG全称为检索增强生成，是一种辅助大模型完成高质量内容生成的技术方式。**

它的全称是检索增强生成（Retrieval-Augmented Generation）。

**这个名字很拗口，但道理极其简单。**

大模型有一个致命的生理缺陷：它的知识是在训练那一刻被冻死的，而且它有个坏毛病，喜欢不懂装懂。这在行业里叫 **“幻觉”** 。

**怎么解决？让他开卷考试。**

可以将这项技术理解为 **给AI配备了一套实时查阅的资料书架** ，该技术的运行逻辑，是让大模型在生成作答内容之前，先主动检索、筛选、调取相关参考资料，用真实、专属的外部信息辅助自身完成内容输出，模式类似于学生开卷答题，依托参考资料保障答案的准确性与专业性。

**基础大模型的知识储备，全部来源于前期海量通用数据的预训练过程，这类知识存在一定的局限性：**

预训练数据多为公开通用内容，不仅难以覆盖企业内部的专属私有资料、私密业务数据，也无法适配小众行业的细分专业内容，同时无法实时跟进更新的行业政策、市场数据与技术规范。

RAG技术可以有效改善这类问题，技术落地过程中，工作人员会把企业私有文档、行业数据库、实时资讯、专属案例、业务规范等各类增量信息，进行结构化处理并统一存储， **搭建专属的私有知识库，为AI提供专属资料来源** 。

**RAG的底层逻辑，是对大模型“知识边界”的无限拓展。**

它让一个只有7秒记忆的金鱼，瞬间拥有了整个图书馆的阅历。

这种运行方式，可以弥补大模型知识覆盖范围有限、更新不及时的不足，减少模型输出内容老旧、脱离业务场景、凭空编造信息的情况，让AI agent在处理专业化、个性化、实时性任务时，输出内容的适配度与可信度得到提升，是AI agent深度落地各行业场景的重要支撑技术。

按照二八原则来说： **RAG的效果，80%取决于你知识库的切片质量和检索策略，剩下20%才是模型本身。**

**都是为了扩展模型的知识，RAG比模型微调更吃香。**

原因就好像在知识快速更新的时代，每次去查新知识（RAG）比把新知识牢牢记忆进头脑改变神经元（微调）划算多了。只有最根本、最高价值的知识才值得记入头脑（神经网络），别的不值得。

## ***05    MCP：AI世界的USB-C***

**MCP即模型上下文协议，是为各类AI应用搭建的统一连接标准，作用是协助AI便捷对接各类外部数据资源与实操工具。**

很多人问：Agent 和普通大模型到底有什么区别？

直观答案是： **有没有 MCP** 。

没有 MCP，大模型只是一个被动的问答工具。你问它，它才答。你不问，它什么也不会做。它不会主动思 **考，不会主动行动** ，不会主动解决问题。

**有了 MCP，大模型才能变成一个主动的智能体。**

**这就是 MCP 的核心价值：它赋予了大模型自主性。**

可以将MCP理解为AI世界通用的标准化接口规范，为模型和所有外部设备、数据、工具搭建统一的沟通语言。

**MCP的优点是，它是个协议。**

在MCP协议未普及的阶段，AI agent的外部对接存在明显短板，每一类外部工具、每一类数据库、每一类文件系统，都需要开发单独的适配接口才能实现连通。不仅开发工作量大、周期长，不同资源之间的通信规则不统一，兼容性较差，会大幅限制AI agent的能力拓展范围。MCP协议统一了AI与所有外部资源的通信规则，所有支持该协议的工具与资源，都可以直接与AI完成对接，无需重复开发适配程序。

**MCP的缺点，也是它是个协议。**

协议需要双方都遵守才有用，一方不遵守或者不响应（后台设置下就封了）的话，用户得不到任何结果。所以MCP和skill一样，往往被绑定在一个体系（它们原生开发的体系）中，挪到另外一个体系就失效了。这成了一种绑定客户的手段。

## ***06   SDD：整个 Agent 生态系统的基础***

**SDD也就是规格驱动开发，是一套适配AI agent开发迭代的标准化工作模式。**

SDD 的全称是 Skill Definition Document，即技能定义文档。

**它是标准化描述 Skill 的格式。**

很多人会忽略 SDD 这个概念，觉得它只是一个无关紧要的文档。但实际上，SDD 是整个 Agent 生态系统的基础。

没有标准化的 SDD，不同开发者开发的 Skill 就无法互相调用。就像如果每个国家都有自己的语言，全世界就无法交流一样。

SDD 则让不同的 MCP、不同的 Skill、不同的大模型之间，能够互相理解、互相通信、互相协作。

**AI agent的开发工作本身具备较强的灵活性。**

容易受到模糊需求、零散规划、临时调整的影响，出现开发进度混乱、功能适配偏差、迭代方向偏移、功能重复冗余等各类问题。

SDD模式可以将模糊笼统的用户需求、开发目标梳理为规整、稳定、可落地的工作依据，为后续全流程开发、迭代、优化工作提供统一的执行标准，让人工开发与AI自主开发都有固定依据可循。

![](https://pic3.zhimg.com/v2-c0f3ce0c3b7f6b3c4c00dffdd41265d6_r.jpg)

传统的 SDD 只能描述文本输入输出的 Skill。

而最新的多模态 SDD，能够描述支持图像、音频、视频输入输出的 Skill。

## ***07   Harness：企业级 Agent 的必备组件***

Harness工程也叫作驾驭工程，是一套专门为AI Agent搭建适配运行环境的实用性工程思路，是保障AI agent从功能落地到稳定商用的重要工程体系。

**谁驾驭谁？**

用户驾驭AI，驾驭工程就像人驾驭马的缰绳，你叫它缰绳工程也没错。

可以将Harness理解为AI agent的专属运维管控中心，负责统筹、调度、监管AI的所有运行行为，让零散的技术模块、工具能力、对话流程形成一套稳定运转的整体系统。

很多个人开发者做的 Agent，都没有 Harness。他们直接把大模型和 Skill 连起来，就开始运行了。

**但如果要把 Agent 放到生产环境中运行，特别是在企业环境中运行，Harness 是必不可少的。**

**Harness工程的内容覆盖范围较为全面：**

包含对话上下文统筹、工具调用管理、独立运行沙箱、使用权限划分、内容测试核验、运行日志记录、内容审核标准以及问题调整机制等多项内容。整套工程体系的搭建目的，是让AI Agent可以平稳融入各类实际工作系统，让整体运行状态更加稳定可控，支撑AI agent完成各类周期较长、流程复杂、步骤繁琐的持续性工作任务。

- **上下文统筹：** 可以规整AI agent的对话与任务信息，及时梳理冗余无效内容、长期留存有效关键信息，规避信息堆叠混乱、内容污染带来的遗忘、逻辑错乱等运行问题。
- **工具调用管理：** 可以规范各类外部工具的调用顺序、调用频次与调用权限，统筹多工具协同作业的节奏，减少调用冲突、调用异常、重复调用等情况。
- **独立运行沙箱：** 可以为AI agent的测试、实操工作提供隔离环境，将测试操作与正式业务系统分隔开，规避异常操作对整体系统造成的影响。权限划分、内容审核与日志记录等机制，能够规范AI agent的运行行为，完整留存运行数据，为后续问题排查、功能优化、风险管控、迭代升级提供有效依据。

当前行业发展过程中，基础大模型的基础能力趋于同质化，AI产品的比拼重心逐步脱离基础模型规模的对比，慢慢转向Harness工程搭建质量、上下文管理能力、工具系统稳定性、任务工作流成熟度等工程化维度的比拼。

**完善的Harness驾驭工程，是AI agent摆脱实验性Demo属性、实现规模化、常态化、稳定化落地应用的关键支撑。**

一个典型的驾驭工程场景就是生成代码，用户事先设置好测试用例套、代码标准（比如圈复杂度，代码层次，变量命名标准等等），然后让编程类LLM不停生成，不断产生反馈来优化下一轮生成，直到代码质量和代码功能（能通过所有测试用例）都达标为止。

**为什么你个人的驾驭工程效果不好？**

因为你的大模型太弱，算力太差，不管迭代多少次都不能达标。

## ***08    AI Agent的多维协同体系***

一个强大的AI Agent，其核心竞争力在于一个协同工作的多层技术栈，而非单一的LLM。这七个关键模块构成了它的骨架：

- **资源层** (Token)：精细化管理AI运行的“燃料”与“内存”。
- **能力层** (Skill, Prompt, RAG, MCP)：赋予AI场景技能、行为指令、外部知识和连接世界的手脚。
- **工程层** (SDD, Harness)：确保其开发过程规范、运行状态稳定可控。

随着大模型基础能力趋于同质化，AI行业的竞争焦点已从模型本身，转移到如何将这些模块高效整合的系统工程能力上。

正是这种全链路的工程优化，推动着AI Agent从简单的聊天工具，进化为能够承担复杂任务的“数字员工”。

写到这里，这篇数千字长文也已接近尾声了。

**很多人在想："AI Agent 这么强大，会不会取代我的工作？"**

**答案或许是："AI Agent 不会取代你，但会用 AI Agent 的人会取代你"。**

而行业竞争的下半场，已经不再是“谁的模型更强”的军备竞赛。

**而是“谁能把这组「七巧板」拼得更快、更稳、成本更低”的效率之争。**

谁先搭建起这套体系，谁就能把AI从“一个有趣的新奇玩意儿”，变成“一台持续稳定输出价值的商业机器”。
