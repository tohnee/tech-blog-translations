原图结构拆解

原始需求（用户一句话）：

> Generate a prompt for an image of a cat secretly running a coffee shop at night<br>生成一张图：一只猫在夜里偷偷经营一家咖啡店

优化后的提示词：

> Whimsical nighttime café run by a clever orange cat wearing a tiny apron, brewing espresso behind the counter, cozy café interior, cartoon style..

分成三大模块：

1. **Setting（场景 / 环境，蓝色框）**<br>`Whimsical nighttime café`、`cozy café interior`<br>👉 在哪里、什么时间、背景环境：夜晚、温馨咖啡店环境<br>
2. **Character details（角色细节，黄色框）**<br>`clever orange cat wearing a tiny apron, brewing espresso behind the counter`<br>👉 主体是谁、长什么样、穿什么、正在做什么：聪明橘猫、小围裙、在吧台萃浓缩咖啡<br>
3. **Mood /style（氛围 & 画风，红色框）**<br>`Whimsical`、`cartoon style`<br>👉 画面情绪、美术风格：奇幻童趣感、卡通画风

✅ 通用万能公式（你可以直接套用写提示词）

**【场景 Setting】 + 【主体角色细节 Character details】 + 【氛围画风 Mood/style】**

举个套用例子：<br>原始想法：一个魔法师在森林里看书

- Setting：misty ancient forest at dusk（黄昏雾气缭绕的古老森林）
- Character details：old wizard in a blue robe, sitting on a mossy stone, reading glowing magic book（穿蓝长袍老巫师，坐在长满青苔石头上，读发光魔法书）
- Mood/style：soft watercolor painting, dreamy atmosphere（柔和水彩，梦幻氛围）

拼起来：

> Misty ancient forest at dusk, old wizard in a blue robe, sitting on a mossy stone, reading glowing magic book, soft watercolor painting, dreamy atmosphere

💡 这个模板的核心好处

普通人很容易只写一句简单描述（比如 “猫开咖啡店”），AI 理解很模糊；<br>按三块分开写，强制你补全：**地点时间 → 主体动作外貌 → 画风情绪**，AI 生成的可控性会高很多。

### （4）图像生成

![](https://pic1.zhimg.com/v2-993d6dd635f77d54c7173b7c8419d8f0_r.jpg)

标题：**How image generation works（图像生成是怎么工作的）**

> 重点对比：文本大模型（自回归） vs 图像扩散模型

两条要点翻译 + 解释

1. **Text models: produce output piece by piece**<br>文本模型（GPT 这类自回归大模型）：**逐块、逐个 token 依次生成**<br>比如写一句话，先出第一个词，再根据前面的词预测下一个，串行一个一个往外吐。<br>
2. **Image models: generate the image all at once**<br>图像模型（扩散模型，这里是通俗说法）：**整张图是作为一个整体来建模**

> ✅ 注意：不是一瞬间一步直接出成品！<br>它是**在每一步降噪的时候，整张图所有像素一起更新**（和文本 “先写完前面再写后面” 有本质区别），也就是图里展示的：从纯噪声 → 多次降噪 → 清晰盆栽图。

图里的训练流程（Training）

- Caption（文本提示）：`Small potted plant on a wooden table` 木桌上的小盆栽
- 正向加噪（训练阶段）：干净图片，一点点加噪声，最后变成纯白噪声；模型学习：**给定文字 + 带噪图，预测里面的噪声**
- 反向生成（推理）：从纯随机噪声开始，配合提示词，**反复去噪**，一步步变清晰（就是图里从左到右 5 张图）

一句话对比记忆

- 文本自回归：**串行，先有前面，才有后面**（像打字，一个字一个字敲）
- 扩散图像：**并行整体更新**，每一轮降噪，整张画面像素同步调整（像对焦，整张图一起慢慢清晰）

> 补充小坑：<br>严格来说扩散也是多步迭代降噪，吴恩达这句话 `all at once` 是为了和自回归做区分，不是说一步直接出图。

### （5）扩散模型导致ai图片生成的问题

![](https://pic1.zhimg.com/v2-72d5977067c4458d3e4af5ff6d3eb956_r.jpg)

**翻译：扩散模型会生成随机结果，并且存在缺陷 / 错误**<br>这是吴恩达课里讲扩散模型的固有短板一页

上半部分：随机性

同一提示词「小盆栽」，每次跑出来的图都不一样：花盆样式、画风、配色、细节全都有差别。<br>👉 根源：生成起点是**随机噪声**，所以每次输出天然带随机性。<br>好处：可以多抽几张挑最好的；坏处：你没法保证每次结果一模一样。

下半部分：三大经典缺陷（必考、提示词工程高频坑）

1. **Weird hands 畸形的手**<br>AI 很容易把手指数错、手指粘连、多长 / 少长手指，手部结构崩坏。<br>原因：手部骨骼、关节组合复杂，训练数据里手部的姿态组合太多，模型很难精准学到全部拓扑结构。<br>
2. **Garbled text 乱码文字**<br>图里的文字字母错乱、拼写错误（图里 `Hanpoday`、`Birt·hday`）。<br>原因：扩散模型不是专门为 OCR / 文字生成设计的，对文字编码、字形理解弱，很难稳定输出正确可读文字。

> 小知识点：想在图里出正确文字，一般要用专门的文字模型、ControlNet 或者后期 P 图。

1. **Inconsistent characters 人物不一致**<br>同一个角色，在连续多格漫画里，脸、发色、五官、体型前后变样。<br>原因：扩散模型默认**没有内置独立角色 ID 记忆**，每一次生成都是独立采样，不会自动记住上一张图这个人长什么样。

> 解决办法：角色图用图生图、IP-Adapter、Lora、角色参考图来固定形象。

一句话总结笔记

扩散模型两大特点：<br>✅ 输出天然随机（随机噪声初始化）<br>❌ 常见故障：畸形手、文字乱码、角色形象不统一

### （6）nanobanana模型

标题分成两大目标：**Good quality text**、**Consistent characters**

左侧：Good quality text（高质量文本内容 / 信息图）

用户需求：

> Generate an infographic of the key points in this paper<br>把这篇论文的要点，生成一张信息图（infographic）

✅ 目标：让 AI**准确理解文字资料里的信息**，把论文里的数据、图表、结论，做成结构清晰的可视化信息图。

- 重点：AI 不是随便画画，它要**忠实提取原文信息**，保留图表、坐标轴、结论，不能乱改论文数据
- 适用场景：论文摘要图、知识点海报、数据可视化

右侧：Consistent characters（角色一致性）

例子：四格漫画，**同一只绿色飞松鼠**，在 4 张分镜里：脸型、毛色、耳朵、外形特征全程不变，只是动作、场景变了。<br>✅ 目标：连续多图里，同一个角色长相稳定不崩坏

> 刚好对上上一页讲的缺陷：`Inconsistent characters`（角色不一致），这一页就是对应的解决方向。

实现角色一致的常用方案（课内隐含考点）

1. 角色参考图（Image reference / 图生图）
2. IP-Adapter、角色 LoRA
3. 固定角色描述词，配合 seed、controlnet
4. 漫画分镜提示词：强制写明 “保持角色外观不变”

对比总结（串接上一页）

上一页是扩散模型痛点：畸形手、乱码文字、角色变样<br>这一页是我们**想要达成的两个高级目标**：

1. 图里的文字、图表信息准确可靠（解决 garbled text）
2. 多图连续生成时，同一个角色长相稳定统一（解决 inconsistent characters）

## 4.ai代码生成

### 计算机项目自上而下构成

这需要一定的项目基础，和计算机软件的基础理解。

先别慌，看不懂没关系，看下面

| 层级 | Python 术语 | 通俗类比（操作系统 / 工程） | 定义 & 说明 | 定义域 / 作用域说明 |
| --- | --- | --- | --- | --- |
| 1（最大） | 项目 Project | 整个总工程文件夹（根目录） | 一个完整业务 / 程序工程，里面包含多个包、普通文件、配置、资源、README、requirements.txt 等；不是 Python 语法概念，是工程管理概念 | 项目本身没有语法层面的作用域；是 IDE、git、pip 管理的边界，所有代码都在这个工程内组织 |
| 2 | 包 Package | 带__init__.py的文件夹（Python 识别为包，区别于普通文件夹） | 一组功能相近模块的集合，用来分类收纳模块；分为常规包（有__init__.py）、命名空间包（Python3.3+，可以没有__init__.py）；可以嵌套：包里面再放子包 | 包的作用域：import 包名，会执行__init__.py，在这个文件里定义的变量，属于包级别变量，包名.变量访问 |
| 3 | 模块 Module | 单个 .py 文件 | 一个.py源码文件就是一个模块，是 Python 原生的组织单元；一个模块可以包含变量、函数、类、可执行代码 | 模块作用域（全局作用域 module global）：直接写在文件顶层、不在函数 / 类里面的变量，属于模块全局；同一个模块内随处访问，跨模块需要 import |
| 4 | 类 Class（补充，你没提到但夹在模块和函数之间非常关键） | 文件里的模板 / 数据结构封装块 | 面向对象封装，把属性、方法打包在一起；一个模块里可以写多个类 | 类作用域：类里面直接定义的类变量（class A: x=1）；类内可见，通过A.x或者实例访问；和函数局部域隔离 |
| 5 | 函数 Function | 一段独立可调用的代码块 | def xxx(): 包裹的代码，用来封装复用逻辑；函数可以嵌套（内部函数） | 函数局部作用域 local：函数内部定义的变量，默认只能在这个函数里面使用；内部函数可以闭包读取外层函数变量（nonlocal） |
| 6 | 代码行 / 语句 Statement | 函数里面的一行或多行代码 | 赋值、判断if、循环for、调用等语句；一行代码是最小执行语句单元 | 语句本身没有独立作用域；⚠️ Python 里：if/for/while不会开辟新作用域（和 C/Java 巨大区别！），里面定义变量仍然属于外层（模块 / 函数域） |
| 7（最小） | 表达式 Expression | 一行代码里的计算片段 | 比如 a + b * 2，是可以算出值的片段，是组成语句的零件 | 表达式没有独立作用域，只在当前语句上下文求值 |

- 普通文件夹 ≠ 包；只有被 Python 识别的才叫包
- 模块一定是 `.py` 文件；但不是所有文件都是模块（txt、图片、yaml 不是模块）
- if/for/while 不产生新作用域！只有 **def、class** 才会开辟新作用域

其实理解他很简单，自上而下是：

根目录（框架原点）-子目录（框架主体）-特殊文件（初始化/其实就是填写表格）-文件内写的模板（打好小抄）-模板的应用（抄小抄，并写到试卷上）-具体代码

| 层级 | 名称 | 类比 | Python 对应概念 | 作用 & 说明 | 作用域 |
| --- | --- | --- | --- | --- | --- |
| 1 | 根目录 Root | 整个项目总文件夹（项目 Project） | 项目根 | 整个工程起点，放 README、依赖、入口、顶层包；git 仓库一般以此为根 | 无语法作用域，是工程、版本管理边界 |
| 2 | 子目录 Subdir | 根下面的文件夹，分两类：普通文件夹 / Python 包 | 包 Package / 普通资源目录 | ① 带__init__.py：Python 包，用来归类模块；② 普通子目录（static/assets/docs）：放图片、配置、文档，不是包，不能 import | 包才有包级命名空间；普通目录无 |
| 3 | 特殊文件 Special file | 目录里的标记 / 配置文件 | __init__.py、__main__.py、.env、requirements.txt、README.md | - __init__.py：标记文件夹为包，定义包导出内容；- __main__.py：python -m 包名的启动入口；其他是工程配置、说明文件，不参与代码导入 | __init__.py内顶层变量属于包域 |
| 4 | 文件内模板 Template | 在.py模块里面写好的抽象模板 | 类 Class、抽象基类 ABC、函数模板 | 模板是抽象、还没填具体参数的封装：类就是数据 + 方法的模板；也可以是通用函数模板（固定逻辑，接收参数） | 类作用域：类变量属于类域；方法内是局部域 |
| 5 | 模板的应用 Template usage | 拿模板去实例化、调用 | 实例化对象、调用函数 | 把抽象模板变成可使用的实体：obj = MyClass() 实例化类；func(arg) 调用函数模板 | 实例有自己的实例属性域 |
| 6 | 具体代码 Concrete code | 模板内部、调用时的语句 / 表达式 | 函数内部语句、分支、循环、赋值、运算 | 真正跑的逻辑，一行行语句、表达式，完成计算、判断、循环 | 语句本身不开辟新作用域；Python：if/for/while不新建作用域，只有def/class新建 |

页面笔记：Getting insights from data（从数据中挖掘洞察｜吴恩达 AI 工程课）

> 业务场景：奶茶店销售表 `sales.xlsx`<br>用户提问：**Which drinks had the biggest changes in sales? Graph it.**<br>翻译：哪些饮品销量波动最大？把它画出来。

左侧 AI执行步骤（标准数据分析链路）

1. **Inspecting the data...** 检查、探查数据<br>先看原始数据长什么样，理解字段、范围、脏数据。
2. **Calculating month-by-month changes...** 按月计算环比变化<br>算每个饮品每个月销量的增减幅度，量化波动。
3. **I’m noticing some clear patterns. Most drinks are flat, but four stand out. I’ll graph those.**<br>发现规律：大部分饮品销量平稳，只有 4 款波动明显，决定只绘制这 4 款。
4. **Generating graph...** 生成可视化图表

图表解读

✅ 这个例子核心想传递的思路（提示词 + 数据分析）

AI 不是上来直接画图：<br>**探查数据 → 计算指标 → 识别异常 / 重点对象 → 筛选重点 → 绘图展示**<br>而不是一股脑把所有几十种饮品全部塞进一张图（图会拥挤、看不清重点）。

> 这是数据分析里很重要的一步：**先做筛选，聚焦有变化的子集再可视化**，避免图表信息过载。

一句话考点总结

用 AI 做数据分析洞察，顺序：看数据 → 计算变化量 → 识别异常样本 → 筛选 → 绘图。

### 何时进行编码

| Question（用户问题） | Source（调用方式） | Reason（判断理由） | 翻译 + 解释 |
| --- | --- | --- | --- |
| Why do cats stare at walls? | 🧠 内置知识库 | Common knowledge on the Internet | 猫咪为什么盯着墙看？属于互联网通用常识，直接用大模型已有知识回答，不用搜、不用写代码 |
| Find me a highly rated gym nearby | 🔍 搜索工具 | Location-specific | 帮我找附近高分健身房和地理位置强相关，实时、本地信息，需要联网搜索，不用代码 |
| Build me a plan for a haunted house | 🔬 综合创作 | Synthesis needed | 给我做一个鬼屋方案需要整合、创意、综合多类信息，模型直接生成文本方案，不需要计算绘图代码 |
| What are my sales trends? | >_ 代码执行器 | Calculation & graphing needed | 我的销售趋势是什么？需要读取表格、做数值计算、画图，必须写代码来完成，所以 AI 选择编码 |
