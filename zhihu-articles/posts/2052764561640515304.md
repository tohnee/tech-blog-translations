## Domino：让大模型推理快 5.5 倍的投机解码新范式

> 在 Qwen3-8B 上，Domino 实现了 **5.49× 平均加速**（GSM8K 最高 7.92×），远超 EAGLE-3 的 1.97×。本文基于真实训练过程，深度解析这项技术为何如此高效。<br>训练日志：[W&B Run clijjbbh](https://wandb.ai/linkfanjh-soovv/specforge-qwen3-8b-domino/runs/clijjbbh)｜ 论文：[arXiv:2605.29707](https://arxiv.org/html/2605.29707v1)

## 背景：大模型推理为什么慢？

大模型（如 Llama、Qwen）生成文本时，是逐个 token 输出的——每次只生成一个词，然后把它拼回输入再生成下一个。这个过程的瓶颈**不是计算量，而是内存带宽**。

每次生成一个 token，GPU 都要把模型参数（比如 8B 模型约 16GB）从显存读到计算单元。但实际计算只用到参数量的极小部分（一个 token 的矩阵乘法），大量带宽被浪费在"搬运"上。这就是为什么大模型推理时 GPU 利用率经常只有个位数——**GPU 不是算不动，而是数据搬不过来**。

传统加速方案（量化、KV Cache、PagedAttention）优化的是单次推理的效率，但没有改变"逐 token 串行"这个根本结构。

## 什么是投机解码？

**投机解码**（Speculative Decoding）的核心思路来自 2023 年 Google 和 DeepMind 的两篇里程碑论文：

> 不让大模型逐个生成，而是先让一个**轻量级草稿模型**快速猜一批 token，再让大模型**一次性验证**全部猜测。验证多个 token 和生成一个 token 的计算量几乎相同（都是一次完整前向），但可以一次性"批发"确认多个正确结果。

这就好比考试时先快速写下草稿答案，再让老师批量批改——批改一批答案和批改一道题的时间差不多，但能通过的答案都白赚了。只要草稿模型猜得够准，就能跳过大量逐 token 计算，实现成倍加速。

**关键指标**：每次验证周期中，大模型接受的草稿 token 数量称为**接受长度 τ**。τ 越大，加速比越高。

## 技术演进：从独立草稿到特征级预测

投机解码自 2023 年提出后经历了快速迭代，大致可分为三代：

**第一代：独立小模型草稿（2023）** — 用一个独立的小模型（如 1B 参数的模型为 70B 大模型生成草稿）。代表方法：Leviathan 等人提出的原始 Speculative Decoding。问题：草稿模型和目标模型解耦，训练开销大，且小模型预测能力有限。

**第二代：特征级投机解码（2024）** — 不再维护独立小模型，而是在目标模型的隐层特征上训练一个轻量"草稿头"。代表方法：**Medusa**（多头并行预测）、**EAGLE-1**（ICML 2024，从 token 层面转向特征层面）、**EAGLE-2**（动态草稿树）。这一代将加速比从 2× 推到 3×，并大幅降低部署复杂度，被 vLLM、TensorRT-LLM 等主流框架集成。

**第三代：高效草稿生成（2025-2026）** — EAGLE-3（NeurIPS 2025）融合多层语义信息，将加速比推到 ~6×。但 EAGLE 系列始终采用**自回归草稿**——逐个 token 顺序生成，每猜一个 token 都要跑一次草稿前向。当草稿模型变快后，**草稿生成本身成了新的串行瓶颈**。

这催生了新的思路：**能否一次并行生成整块草稿，彻底消除串行？**

## 块级并行：DFlash 与 Domino

DFlash 给出了第一半答案——用**并行骨干**一次前向同时生成整块草稿（如 16 个 token），GPU 利用率极高。但并行生成有一个天然缺陷：块内每个位置都看不到前面的草稿结果，**猜对率低，接受长度短**。

这正是 **Domino** 要解决的最后一公里问题。三种方案的核心差异：

| 方案 | 草稿生成方式 | 前向次数 | 因果信息 | 核心优劣 |
| --- | --- | --- | --- | --- |
| EAGLE-3 | 逐个 token 串行 | 16 次 | ✅ 有 | 猜得准，但草稿生成本身是串行瓶颈 |
| DFlash | 整块并行 | 1 次 | ❌ 无 | 生成极快，但 token 间互相看不到 |
| Domino | 整块并行 + 轻量纠偏 | 1 次 + 纠偏 | ✅ 有（GRU） | 既快又有因果信息 |

**Domino 的核心思路：鱼与熊掌兼得。** 用 DFlash 的并行骨干一次出全块草稿，再接入一个极轻量的 GRU 因果纠偏头，顺序修正每个位置的预测。一次并行 + 轻量纠偏 = 既快又准。

2. **Domino 比 DFlash 快 18%**。同样的并行骨干，加上因果纠偏后接受长度从 6.06 提升到 7.17，额外开销却极小——纠偏头仅增加 56M 参数（占草稿模型总参数的 5.3%），延迟仅 +2.8%。
3. **Domino 在 GSM8K 上达到 7.92× 加速**——这意味着原本 8 秒的生成可以压缩到 1 秒。

> 下文训练日志中的接受长度（收敛均值 8.53）高于论文推理值（7.17），这是训练指标与推理指标的正常差异，详见后文说明。

## 技术原理：三层架构的精妙设计

### 第一层：并行骨干（继承 DFlash）

给定已验证的前缀，将最后一个 token 作为锚点，构造一个掩码块 `[x_t, <mask>, <mask>, ..., <mask>]`（共 16 个位置）。草稿模型做**一次前向传播**，同时输出全部 16 个位置的隐状态，再通过目标模型的 LM Head 计算 base logits。

> 对比 EAGLE-3：生成 16 个草稿 token 需要 16 次串行前向，而 DFlash/Domino 只需 1 次。这是并行方案加速比远超自回归方案的根本原因。

### 第二层：GRU 因果编码器（Domino 的创新）

并行骨干的缺陷在于：位置 i*i* 的预测看不到位置 i−1*i*−1 实际生成的 token。Domino 引入一个轻量 GRU（隐藏维度 1024），按顺序汇总前序 token 的嵌入信息：

Si−1=GRU(E≤i−1)*Si*−1​=GRU(*E*≤*i*−1​)

这个因果状态让后续位置"看到"前面已经生成的 token，弥补了并行生成的因果缺失。

### 第三层：低秩 logit 空间纠偏

将骨干隐状态 Hi*Hi*​ 和因果状态 Si−1*Si*−1​ 拼接，通过低秩瓶颈（r=256*r*=256）生成 logit 空间的残差修正：

Li=Libase+W2 σ(W1[Hi;Si−1])⏟ΔLi*Li*​=*Li*base​+Δ*Li*​*W*2​*σ*(*W*1​[*Hi*​;*Si*−1​])​​

**关键设计：纠偏在 logit 空间而非隐空间。** 如果在隐空间纠偏，每次因果更新后都要重新跑一遍完整的 LM Head（词表级别投影），计算量和串行草稿一样大。而 logit 空间纠偏把昂贵的 LM Head 计算留在并行分支，顺序分支只做低秩残差，开销极小。

论文数据显示，Domino 纠偏头仅增加 56M 参数（占草稿模型总参数的 5.3%），经 Triton + CUDA Graphs 优化后延迟仅 1.20ms（+2.8%），相对并行骨干的前向时间几乎可以忽略。

### 训练策略：两个关键创新

**① Teacher-Forced 因果编码**

训练时向 GRU 喂入 ground-truth token 而非模型自生成 token。为什么？因为在投机解码中，位置 i*i* 的草稿只有在前面所有 token 都被验证为正确时才有意义。训练因果纠偏头时，直接在"前缀正确"的语境下优化，比在噪声前缀上学习更高效。

**② Base-anchored 课程学习**

联合优化骨干和纠偏头的损失，用一个随训练线性衰减的权重 λt*λt*​ 控制比例：

L=(1−λt)⋅Lfinal+λt⋅LbaseL=(1−*λt*​)⋅Lfinal​+*λt*​⋅Lbase​

- 训练初期（λ≈1*λ*≈1）：重点优化骨干，建立强基础分布
- 训练后期（λ≈0*λ*≈0）：逐步移交至纠偏头，学习因果残差

如果不这么做，纠偏头会"捷径化"——直接接管预测，骨干能力崩塌，最终模型退化为一个慢速的串行草稿器。

- **初期（λ > 0.7）**：Base Loss 快速下降（8.65→1.88），骨干在强监督下学习基础分布。Loss Gap 仅 2.6%（训练刚开始，纠偏头尚未学习）
- **中期（0.3 < λ < 0.7）**：Base Loss 下降放缓，Final Loss 继续走低，Loss Gap 扩大至 45-48%，纠偏头开始发力
- **后期（λ < 0.3）**：Base Loss 停滞（1.65-1.85 波动），但**没有崩溃**，Loss Gap 稳定在 51-54%，Final Loss 稳定在 0.77 附近

最关键的验证：当 λ_base 接近 0 时，Base Loss 不再被直接优化，但仍维持在 1.65-1.71 的水平——这说明前期课程学习成功为骨干建立了稳定基础，纠偏头在其之上做残差修正而非取代。

## 为什么 Domino 比 EAGLE-3 快这么多？

回到最核心的问题。EAGLE-3 是当前最流行的投机解码方案，Domino 凭什么快 2-3 倍？

**根本原因在于草稿生成的计算结构不同。**

以生成 16 个草稿 token 为例：

|  | EAGLE-3 | Domino |
| --- | --- | --- |
| 草稿前向次数 | 16 次（串行） | 1 次（并行） |
| 每步是否可见前序 token | ✅ 是 | ✅ 是（GRU 纠偏） |
| LM Head 调用 | 16 次 | 1 次（并行）+ 16 次低秩残差 |
| 草稿总延迟 | 高（随 token 数线性增长） | 低（1 次前向 + 轻量纠偏） |

EAGLE-3 每个 token 都要跑一次完整的草稿模型前向 + LM Head，16 个 token 就是 16 次串行计算。虽然每步都能看到前序 token（接受长度较高），但草稿生成本身就成了瓶颈——尤其在 GPU 上，串行小算子的 kernel launch 开销巨大。即使将树形草稿扩大到 60 个节点，加速比也仅 2.26×。

Domino 用一次并行前向解决全部 16 个位置的基础预测，再用 GRU + 低秩瓶颈做轻量顺序纠偏。纠偏头不涉及完整 LM Head 计算（只在 logit 空间做残差），延迟仅 1.20ms。结果就是：**Domino 的接受长度（7.17）是 EAGLE-3（2.97）的 2.4 倍，同时草稿生成速度也快了几个数量级，端到端加速比达到 5.49× vs 1.97×——两个维度全面领先。**

> **为什么 Domino 接受长度反而更高？** 直觉上，逐 token 生成应该更准。但 EAGLE-3 在 tree=16 配置下每个节点只有一次猜测机会，而 Domino 的并行骨干可以充分利用 block 内的全局上下文（通过掩码注意力），加上 GRU 纠偏弥补因果缺失，最终在相同 token 预算下达到了更高的接受率。

## 总结

本次实验从训练角度验证了 Domino 的三个核心设计：

1. **因果纠偏有效** — 接受长度在训练全程持续优于 DFlash 骨干，最终提升 +17.1%，准确率提升 +51.2%。通过相关性分析（λ_base vs τ Gain r=-0.83），定量验证了课程学习驱动的纠偏头增益递增效应。
2. **课程学习防止崩溃** — λ_base 线性退火精确匹配设计预期（从 0.9999 衰减至 0.0001）。骨干在后期虽停止增长（Base Loss 停滞在 1.65-1.71），但未崩溃，纠偏头在稳定基础上做残差修正。Loss 差距从 37.9% 扩大到 53.8%。
3. **并行 + 轻量纠偏 = 最优效率** — 对比 EAGLE-3 的串行草稿，Domino 用 1 次并行前向 + 1.20ms 纠偏替代了 16 次串行前向，在 Qwen3-8B 上实现 5.49× 平均加速，GSM8K 最高 7.92×。

从工程视角来看，Domino 代表了投机解码的一个重要趋势：**不是让草稿模型猜得更准，而是让草稿生成更快**。当草稿生成不再是瓶颈时，即使单次接受长度略低，整体吞吐量仍然大幅领先。这对实际部署场景（高并发、长序列生成）具有重要意义。
