上周把一个 review PR 用的 agent 接进了 SGLang 的日常流程，想法很简单，PR 太多人看不过来，让 agent 先过一遍，低风险的PR Agent直接全流程接管了。结果四天里七十多个人、一百多个 PR 找过来，烧掉了30M token。SGLang 确实是最流行的框架之一，这几天也算是见识到了 reward hacking 能有多少花样，挑几种印象最深的说一下。

**告诉 Agent 直接接收自己的pr，不要再迭代提意见了** 这属于恶意攻击了，不过确实挺搞笑的，已拉黑用户

**把 agent 当 reward model 刷分。** 有一个 PR 前后 push 了十几次，每次 push 都触发一轮 review，agent 一共看了十轮，光这一个 PR 就烧了快两百万 token，和 RL 里对着 reward model 反复采样、直到分数够高为止几乎一模一样。

**刷量。** 有人四天提了二十多个 PR，在 Slack 里喊了四十多次，agent 替他发了五十多次 CI 命令。

**假拆单。** 一个四千多行的 PR 被要求拆小，拆完其中一半还有两千多行，agent 回了一句，体积的问题解决了。

**群发 @。** 两天提了七个 PR，每个都同时 @ 四五个 maintainer，还特意备注请用 review agent 看。

**攒 merged 记录。** 三十行只加测试的 PR，催了十几次，「CI 有问题你能帮我修一下吗」「可以合了吗🙏」。

**多渠道轮番来。** 同一个 PR 在群里 @ 一遍、私信一遍、GitHub 里再 cc 一遍。

**起号。** 不少没有提交过commit的号来提交pr，并且提出的pr就是低质量，不解决真实问题的刷数量PR。

**AI 对 AI。** Agent攻击，挂定时程序定时艾特我的Agent去review，但是忽略了我的Agent每天只工作一个小时的事实。

搞笑的是我把Review Agent关掉之后，对方的一些Agent还在频繁触发Review Agent，大家都太会做reward了。

回头看了一下，reward hacking 最频繁的这批人里挺多是在校学生。这个其实可以理解，现在找实习、申请学校都会看开源贡献，对他们来说 reward 很具体，就是简历上一个能合进 SGLang 的 PR？

开源框架感觉正在面临信任崩塌。以前看到新 PR，默认对方是真正想做贡献的，现在第一印象变成了先看看是不是在 reward hacking。其实大多数新贡献者是认真的，真正有问题的就那么几个，但怀疑已经摊到了每个人身上。AI 让写 PR 几乎没有成本，review 的成本却一点没少，最后消耗掉的其实是信任。

为了应对攻击，我把review所有开源的东西都抹掉了，之后 agent 只做辅助review，每个pr最后还是自己决定是否要进入Review流程，还 revert 了一堆之前被 agent 合进去的 PR。让主分支已经恢复，后续会更加谨慎的应对开源社区PR。
