3. 方式 A（推荐）：精度最高的在线抓取

思路：nsys 只看 cudaProfilerStart/Stop 之间的数据，而这两个调用由客户端的 /start_profile、/stop_profile 触发，完全不需要猜 delay。

3.1 终端 1：server 在 nsys 下启动

nsys profile \

--force-overwrite=true \

-o /tmp/fwd_tp8 \

--trace-fork-before-exec=true \

--cuda-graph-trace=node \

--capture-range=cudaProfilerApi \

--capture-range-end=stop \

--sample=none --cpuctxsw=none \

python -m sglang.launch_server \

--model-path <你的模型路径> \

--tp-size 8 \

--port 30000 \

--disable-radix-cache

参数解释：

- --trace-fork-before-exec=true：必须，否则 8 个 TP 子进程抓不到，只能抓到一个不跑 GPU 的父进程。

- --cuda-graph-trace=node：必须。不开的话，decode 的整个 CUDA graph replay 在图里只有一条 cudaGraphLaunch，你根本看不到 kernel，会误以为“没空隙”。

- --capture-range=cudaProfilerApi：只录 cudaProfilerStart→cudaProfilerStop 之间。

- --capture-range-end=stop：收到 stop 就结束采集（不杀进程）。

- --sample=none --cpuctxsw=none：关掉 CPU 采样，减小 trace 体积、降低干扰（只看 kernel 空隙时不需要）。

等它打印 The server is fired up and ready to roll!（http_server.py:4190）。

3.2 终端 2：确认就绪

until curl -sf [http://127.0.0.1:30000/health](http://127.0.0.1:30000/health) >/dev/null; do sleep 5; done; echo READY

3.3 终端 2：打流量（带 profile 开关）

python -m sglang.benchmark.serving \

--backend sglang\

--model <你的模型路径> \

--host 127.0.0.1 --port 30000 \

--dataset-name random \

--random-input-len 4096 --random-output-len 512 --random-range-ratio 1.0 \

--num-prompts 200 --max-concurrency 32 \

--profile --profile-activities CUDA_PROFILER

- --profile --profile-activities CUDA_PROFILER 会让客户端在开始打请求前调用 /start_profile（服务器执行 cudaProfilerStart），所有请求跑完后调用 /stop_profile（cudaProfilerStop）。nsys 采集窗口 = 这段压测，精确。

- --num-prompts / --max-concurrency 决定窗口长度和 batch 形态，请调成和你线上一致的并发，否则看到的空隙不具代表性。

- --random-range-ratio 1.0 让每个请求长度固定，便于比较不同轮次。

- 注意：不要加 --profile-steps，它的语义是采到 N 步自动停，会让请求还没发就结束。

采集结束后，ls -lh /tmp/fwd_tp8.nsys-rep 应该有几百 MB～1GB。

已知限制：cudaProfilerStart 只由 gpu_id 0 的 rank 调用（profiler_manager.py:278 的 guard）。nsys 的 capture range 是会话级的，一般 8 个 rank 都会同步采集；万一你打开发现只有 rank0 有数据，就退回第 4 节的延时法。
