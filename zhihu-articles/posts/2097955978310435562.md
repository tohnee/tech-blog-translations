最近硬件圈有个事挺魔幻：一个 10 月 18 日才建的 GitHub 空仓库，七天攒了三千多颗星。作者 Zagitta 做了个叫 **gpu-unlock** 的 Linux 内核模块，把 RTX 3090 Ti 的 BF16 算力从 87.5 TFLOPS 直接干到 157.4 TFLOPS——涨了 80%。消息传开后，海外二手平台上原本 1000 美元的 3090 Ti，一周内被炒到 2650 美元。

但网上传着传着就变味了，什么”破解核心”“刷 BIOS 开核”“游戏帧率翻倍”，全是错的。

**先说结论：它既不是超频，也不是开核，更没有改任何硬件。** 它做的只有一件事——把英伟达在固件里写死的一个”半速”开关，改回专业卡的”全速”。硬件一个字节都没动，断电即失效。

下面把整件事的来龙去脉拆开讲清楚。

---

### 一、英伟达锁的到底是什么？不是核心数，是发射速率

很多人第一反应是”是不是把屏蔽的核心解开了”——不是。

RTX 3090 和专业卡 A6000 用的是**同一颗 GA102 芯片**，CUDA 核心数量、Tensor 核心硬件一模一样，没有任何物理阉割。 那差别在哪？

在于英伟达在固件里留了一组叫**速度选择器（Speed Selector，SS0/SS1）**的寄存器：

- 专业卡出厂写的是**全速**
- 消费卡出厂写的是**半速**

这直接卡住了 **FP16/BF16 输入 + FP32 累加**这条混合精度路径上，FMA（融合乘加）指令的**发射速率（issue rate）**——只有满血的一半。

打个比方：同样的肌肉，游戏卡被固件要求”每秒只能出一半的拳”。

注意这条路径，**不是** Tensor 核心专用的 FP16/TF32 单元，而是 SM 里 CUDA 核心上的 FP16/BF16 FMA 单元。[citation:1] 这也解释了后面那个很反直觉的现象：为什么有的算力翻倍、有的一动不动。

---

### 二、工具是怎么得手的？抢在驱动加载前的那个窗口

gpu-unlock 的精妙之处，在于**不碰驱动、不刷 VBIOS、不打补丁**。它是一个被塞进 initramfs 的 Linux 内核模块，卡在一个极其关键的时间窗口里动手：

1. **抢先介入**——开机早期，模块在 nvidia 驱动绑定显卡之前先跑起来；
2. **拿到寄存器写权限**——利用 GPU 启动固件链里的漏洞（结合此前解锁 CMP 矿卡的 **V67 / PLM（Platform Lock Manager）** 手法），底层是英伟达 **Falcon 微控制器 BootROM 的 DMA 缓冲区溢出**，进而构造 ROP 链，拿到底层寄存器的写入能力；
3. **改写速度选择器**——把 SS0/SS1 写成解锁值（例如 SS0 = `0x88888888` 对应 BF16 全速）；
4. **功能级复位（FLR）**——做一次 PCIe Function Level Reset，让改动生效；
5. **交还原版驱动**——驱动照常加载、初始化，它”看到”的已经是一张满血卡。

**这个先后顺序是精髓。** 以前想解锁得手动给每个驱动版本打补丁，英伟达发一版新驱动就得重来一遍；现在是开机时解锁、驱动照常加载，官方驱动一个字节都不用动。英伟达想通过软件更新封堵，除非改硬件行为。

用 Zagitta 在 HN 上的原话说：**“这个漏洞翻转的是两个 bit，而这两个 bit 把某些指令的发射速率砍成了专业卡的一半。”**

### 三、实测：什么变快了，什么纹丝不动

这是全网最容易产生误解的地方。看一份 PNY RTX 3080 10GB 的**同卡、同 VBIOS、同 320W 功耗墙**对照数据，最说明问题：

| 运算路径 | 原始吞吐 | 解锁后 | 变化 |
| --- | --- | --- | --- |
| BF16 输入 + FP32 累加 | 65.41 TFLOPS | 113.44 TFLOPS | +73.4% |
| FP16 输入 + FP32 累加 | 64.88 TFLOPS | 110.14 TFLOPS | +69.8% |
| TF32 路径 | 32.63 TFLOPS | 54.69 TFLOPS | +67.6% |
| 普通 CUDA FP32 | 22.07 TFLOPS | 21.89 TFLOPS | 基本不变 |
| FP16 输入 + FP16 累加 | 112.51 TFLOPS | 112.02 TFLOPS | 基本不变 |
| INT8 矩阵计算 | 52.22 TOPS | 51.66 TOPS | 基本不变 |

其他型号的提升幅度也差不多：3090 Ti 的 TF32 从 42.6 涨到 82.6 TFLOPS（+94%）；3080 Ti 在 315W 下 BF16 从 71.59 涨到 113.98；3060 也能涨约 80%——**解锁幅度和型号关系不大**。[citation:1][citation:15]

### 一定会涨的

FP16/BF16 + FP32 累加、TF32 这两条路。也就是大模型训练、部分 AI 推理的 prefill 场景。

### 完全不会涨的（别信谣言）

- **游戏帧率**——游戏渲染根本不走这条通路；
- **CUDA FP32、INT8、纯 FP16 累加**——这个寄存器不控制它们；
- **FP8**——40 系新增的 FP8 不在它的管辖范围；
- **显存带宽受限的任务**，比如 llama.cpp 跑量化模型、LLM 的 token 生成（decode）阶段。[citation:18]

所以你会看到一个”跑分翻倍、实测没那么神”的落差：**4090 在寄存器层面发射上限翻倍，但真实 AI 任务往往只涨 12%~34%。** 原因很简单——闸门打开只是打通了一个瓶颈，实际速度还会被显存带宽、显存容量、功耗和调度卡住。**上限翻倍 ≠ 实际翻倍。**

### 四、一个更底层的认知：什么锁能撬，什么锁撬不动

借这个话题，把”GPU 解锁”的两类锁彻底分清。以后看到类似的宣传，你就能自己判断真假。

### 固件锁 —— 可以撬

就像这次的速度选择器。芯片本身是完好的，只是出厂配置被写低。只要锁在软件/固件层面，理论上就有被撬开的可能，而且往往是”断电即失效”的软解锁。

### 物理熔断 —— 撬不动

厂商处理残次品核心，用的是 **eFuse（电子熔丝）或激光熔断**，在晶圆阶段就永久烧断了内部电路。更要命的是，现代 GPU 的固件每次启动都会校验哪些资源”被认证”可用——被熔断的块，固件根本不初始化它。

而且很多时候 PCB 上连配套的硬件都没留：供电相数不够、去耦电容空贴、VDDCI 电压轨缺失、显存通道只布了一半。这种情况下强行刷所谓”解锁 BIOS”，结果只能是 VGA BIOS 校验失败、GPU 初始化异常、PCIe 链路中断，严重的直接变砖。

> 所以老式那种”刷个 BIOS 把 4830 开成 4850”的黄金时代，早就结束了。gpu-unlock 能成，恰恰是因为它面对的是**一颗完好芯片上的人为固件限速**，而不是物理阉割。

顺带说一句，这背后其实是芯片行业”良率筛选 + 用户分级”的组合拳：好的 die 人为切档多赚钱，残的 die 屏蔽坏块少亏钱。**只要是软件层面的刀法，就有被反向刀回来的那一天。**

### 五、想动手？先把这五个风险看完

1. **没有正规保障**——内核模块直接改 GPU 寄存器，存在无效果、效果不佳、系统不稳定、蓝屏死机甚至硬件损坏的风险；
2. **必须关闭 Secure Boot 安全启动**——这会为入侵攻击留下漏洞；
3. **目前仅支持 Linux**——暂无 Windows 计划（社区出现过 Windows 版，但已删库 404）；
4. **会被封堵**——英伟达后续的固件、驱动更新仍有可能让破解失效；
5. **钱包风险**——二手 30⁄40 系已经被这波消息炒起来了，现在入手基本是高位接盘。

---

### 最后

这件事最值得玩味的，其实不是”白捡 80% 算力”，而是它证明了**英伟达消费卡和专业卡之间那道墙，很大程度上是固件画的，不是硅做的**。

那位开发者把整个项目总结成一句话：把 Nvidia 3000 系显卡的 FP/BF16 指令发射速率，解锁到专业卡的同等水平。

至于要不要上车——如果你是 Linux 用户、手上有张 30 系/40 系老卡、主要跑大模型训练或 prefill 密集的推理，那确实值得一试；如果你只是打游戏，这事儿跟你半毛钱关系没有，反而还得跟着承受二手涨价的代价。
