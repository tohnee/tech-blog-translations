背景：大模型推理优化

1、推理是LLM应用的重要一环，在部署服务的环节影响重大。它在部署（推理）时需要消耗大量的算力资源，因此，加快模型的推理是一项重要的挑战。

2、现阶段主流的大模型优化包含以下几个方向：

（1）分布式优化：并行化（Parallelism）当前的推理并行技术包括数据并行、张量并行、流水线并行。数据并行通过增加设备以提升吞吐量；张量并行横向增加设备以减少延迟；流水线并行纵向增加设备以支持更大模型。例如DeepSpeed、FlexFlow等框架都支持各种并行方式的组合使用。

（2）服务化schedule：动态批处理（Dynamic batching）动态批处理通过优化不同序列的批处理，避免填充并提高GPU利用率。例如ORCA、FastServer、vLLM、TGI 等工具和框架都实现按照需求分配内存，就地插入序列等技术来实现动态批处理调度，大大提升了推理吞吐量。

（3）低精度加速：模型压缩（Model compression）主要包括剪枝稀疏化、量化和知识蒸馏等方法。剪枝稀疏化通过修建权重连接以减少模型大小；量化则将权重量化为低精度表示以实现压缩；知识蒸馏通过让小模型从大模型中学习提高推理速度。例如 SparseGPT、LLM-pruner、DistilBERT 等。这些方法可单独使用或结合应用。

（4）计算优化：子图融合（Subgraph fusion）通过将多个算子合并成一个算子，以减少kernel的调用次数，从而减少内存读写次数和开销。主要方案包括英伟达的FasterTransofmer、Microsoft的DeepSpeed inference和TVM的MLC LLM。这些方案通过融合多层网络，使用单一内核计算，减少数据传输并增加运算密度，从而加速推理计算。

（5）模型算法层面优化：Transformer 结构优化，这类方法通过优化Transformer的结构来提升推理加速，例如 FlashAttention、PagedAttention和FLAT Attention等，他们采用类似的tiling和scheduling策略来提升计算和内存访问效率。此外还有一些框架如Colossal-AI也在研究新的Transformer结构。

（6）显存优化：硬件系统升级，例如 NVIDIA 的 H100、AMD 的 MI300 和苹果的 M2 Ultra 等最新芯片都在 AI 推理性能上有显著提升。此外，一些专用 AI 芯片如 Graphcore 的 IPU 和壁仞的 BR100 等也展现了在 AI 推理方面的优势。

1. vllm（[GitHub - vllm-project/vllm: A high-throughput and memory-efficient inference and serving engine for LLMs](https://github.com/vllm-project/vllm)）

1）vllm是一款易于使用、快速且廉价的LLM（Language Model）服务库。

2）它的吞吐量比Hugging Face Transformer高出最多24倍，比Text Generation inference高出最多3.55倍，具有出色的推理吞吐量、对注意力键和值内存的高效管理、动态批处理、优化的CUDA内核等特点。

3）vllm能够与流行的huggingface模型无缝集成，支持高吞吐量的服务和各种解码算法，并提供Tensor并行支持和流式输出。

4）vllm的核心技术是 PagedAttention，解决了LLM服务中的内存瓶颈问题。传统的注意力算法在自回归解码过程中，需要将所有输入Token的注意力键和值张量存储在GPU内存中，以生成下一个Token。这些缓存的键和值张量通常称为KV缓存。

5）PagedAttention 算法的研发基于操作系统中虚拟内存和内存分页技术，在此基础上设计一个LLM服务系统vLLM，采用集中式调度器来协调分布式GPU工作线程的执行。PagedAttention算法将KV缓存分成块，然后PagedAttention内核将分别识别和获取不同的KV块，使得KV块存储在非连续物理内存上，从而让vLLM中的分页内存管理更加灵活。

6）通过PagedAttention划分出的KV块，vllm利用虚拟内存机制将KV缓存表示为一系列逻辑KV块，并在生成新的Token和KV缓存时，从左到右进行填充；最后一个KV块的未填充位置预留给后续生成操作。vllm在KV缓存上实现了几乎零浪费，并且可以在请求内部和请求之间灵活共享KV告诉缓存，进一步减少了内存的使用量。

存在的问题：同样的模型、参数和prompt条件下，vllm和huggingface推理结果不一致。

7. Flash-Decoding（[https://github.com/Dao-AILab/flash-attention](https://github.com/Dao-AILab/flash-attention)）

1）Flash Decoding 由 Flash Attention V1 和 V2 的作者推出，Flash-Decoding 借鉴了 FlashAttention 的优点，将并行化维度扩展到 keys/values 序列长度。这种方法几乎不受序列长度影响（这对 LLM 模型能力很重要），可以充分利用 GPU，即使在 batch size 较小时（inference 特点），也可以极大提高了 encoding 速度。

2）Flash Decoding 主要包含以下三个步骤：

- 将 keys 和 values 分成较小的 block；
- 使用 FlashAttention 并行计算 query 与每个 block 的注意力（这是和 FlashAttention 最大的区别）。对于每个 block 的每行（因为一行是一个特征维度），Flash Decoding 会额外记录 attention values 的 log-sum-exp（标量值，用于第 3 步进行 rescale）
- 对所有 output blocks 进行 reduction 得到最终的 output，需要用 log-sum-exp 值来重新调整每个块的贡献。

3） 特点：

- 动态更新上下文（Dynamic context updating）：Flash-Decoding 可以实时更新上下文向量，使解码器及时感知到最新的上下文信息，增强解码质量。
- 跨句连贯（Cross-sentence coherence）：Flash-Decoding 考虑跨句信息，利用注意力保证生成连续的段落，而不是独立句子。
- 训练速度快（Faster training）：相比传统方法，Flash-Decoding 训练速度更快，在有限数据下收敛更好。
- 多任务统一（Multi-task unification）：Flash-Decoding 统一了抽取式任务和生成式任务，一个模型即可完成不同任务。
- 低内存占用（Low memory footprint）：Flash-Decoding 网络结构简单，不需要额外模块，内存占用较小。

4）效果：作者对 CodeLLaMa-34b 的 decoding throughput 进行了基准测试。该模型与 Llama 2 具有相同的架构。作者在各种序列长度（从 512 到 64k）上测试了 decoding 速度，并比较了多种 attention 计算方法。

5） Flash-Decoding 在处理非常大的序列时速度可以提高 8 倍，并且比其他方法具有更好的可扩展性。

8. Extension for Transformers（[https://github.com/intel/intel-extension-for-transformers](https://github.com/intel/intel-extension-for-transformers)）

1）Extension for Transformers 是英特尔推出的一个针对 CPU 的 Transformer 模型推理优化框架，包含两个部分：自动 INT4 量化流程及高效的 Transformer 优化。通过量化和运行时优化，可以显著提升 Transformer 类模型在 CPU 上的推理性能。

2）核心思路：首先，利用量化工具自动生成 INT4 量化模型，大幅降低模型大小，减少内存访问时间；然后，基于 CPU 指令集实现优化的张量运算库，构建高效的 Transformer 运行时，通过线程并行、内存优化、KV Cache 等方式进一步提升推理速度。

3）特点：

- 自动 INT4 量化流程：使用 Intel Neural Compressor 等工具，支持多种量化算法，自动搜索最佳量化配置，生成质量较高的 INT4 量化模型；
- CPU 优化的张量运算库：支持各种主流 CPU 指令集，如 AVX2. AVX512. AMX 等。实现各种 INT4 量化核函数；
- Transformer 运行时优化：线程调度优化，内存管理优化，针对 Decoder 的 KV Cache 优化等；
- 支持主流 Transformer 模型：提供了对 BERT、GPT、Transformer-XL 等模型的支持；
- 性能优化：相比 FP32 模型，INT4 量化模型减小了 16 倍的模型大小。推理速度较 FP32/FP16 实现提升 3-5 倍；

4）效果：

- 在相同的 CPU 环境下，基于 Extension for Transformers 的 INT4 量化 BERT 模型实现了如下性能：
- 相比 FP32 模型，INT4 量化模型降低了内存带宽需求，提升了内存访问效率；
- 在 vCPU 核心上，INT4 量化模型的平均推理吞吐较 FP32/FP16 实现提升了 3-5 倍；
- 在单个 CPU 套接字中，吞吐从每秒 1000 词达到了 3000 词，延迟降低 2 倍以上；
- 总体上，INT4 量化模型与高效运行时相结合，可以在不影响（或轻微影响）准确率的情况下，将 Transformer 类模型的 CPU 推理速度提升 3-5 倍。
