曾经，“许愿式”编程是一个骂人的词，但是在最近三天过去之后，我不得不重新思考“编程”到底是一个什么样的活动。当然了，这里面最大的变量就是 GPT-6 发布了。

为了说明我都做了哪些尝试，我列一下我都通过它完成了什么事情。并且，这一切都发生在短短几天之内。。。（本文全部文字为我自己手写，没有 AI）

## Pi 计算速度的新世界纪录

在这个文章 [[新纪录]在5秒内计算pi的10亿位数字](https://zhuanlan.zhihu.com/p/2019054838797840815) 里，我用 Kimi K2.5 的辅助（嗯，“辅助”这个词对那一代的模型应该说是合适的）下，写了一套基于 NTT 乘法的 CUDA 版圆周率计算代码。在各种玄学下，我在我的 RTX 5090 台式机上做到了 4623ms，比之前 y-cruncher 设立的 CPU 计算的纪录快了 0.5s 左右。

这个本来就是一个非常小众的领域，因为手撸 kernel 并且优化是一个体力活，而把它算的更快除了开心一下之外并没有什么实际的应用。然而，当我在 codex 里开启 GPT-6，和它说了一句“ Please make it faster”。之后我得到了：

| 位数 | 速度（秒） | 设备 | y-cruncher 纪录（秒） |
| --- | --- | --- | --- |
| 1,000,000,000 | 3.523.21 | RTX 5090RTX Pro 6000 | 5.15 |
| 2,500,000,000 | 9.60 | RTX Pro 6000 | 12.50 |
| 5,000,000,000 | 20.29 | RTX Pro 6000 | 22.38 |
| 10,000,000,000 | 19.54 | RTX Pro 6000 * 8 | 44.06 |
| 25,000,000,000 | 69.00 | RTX Pro 6000 * 8 | 120.82 |
| 50,000,000,000 | 199.70 | RTX Pro 6000 * 8 | 275.30 |
| 100,000,000,000 | 626.42 | RTX Pro 6000 * 8 | 672.56 |

是的，它不光帮我把代码拓展到了支撑到最高 1000亿位（这个是我给他的服务器的内存的极限），搞了一个基于 6-step NTT 的可并行算法，还把我自己之前手写的 kernel 硬生生的加速了 25%，同时顺手修了我之前的几个边界条件下的数值bug. 瞬间，我感觉我过年后熬的那些夜都毫无意义……

而给它的 prompt 只有原来的 repo ，服务器的访问方法，以及一个许愿叫做“把它弄到你能弄到的最快”。之后我去睡觉了，codex开始疯狂干活，然后结果就来了。

## 灵足时代usb-can的通信协议

我从淘宝买了两个灵足时代的关节以及一个 USB 调试器（本质是一个CAN转串口再转 USB）。不过令人伤心的是，灵足时代给了一个“开源”的上位机程序 [https://github.com/RobStride/MotorStudio/releases](https://github.com/RobStride/MotorStudio/releases) . 然而，当点开“源代码”的 zip 包之后，里面就只有一个文档 pdf 和 README.md……  这个味非常的“中国特色开源”，我不得不说。

按说一般走到这一步，就只能去找厂家求助了。但是我发现，它还有一个对应的 linux 版本，然后我恰好对 linux ELF 格式以及汇编语言略通一二。那这可就不用求人了，我大不了把它的上位机程序的二进制读一遍，只要它没有啥 obfuscation （这显然不会有），那应该还是能把什么用搞出来的。

按以前，这基本上还是要花一段时间去搞一搞的东西，不过 GPT-6 来了，我又许了一个愿，“请你读一下这个可执行文件，把它的串口协议和 CAN 协议弄出来“。

然后就没有然后了。codex 进行了各种 objdump，穿针引线的检查了所有函数里收发串口的语句，拼出来了一套完整的串口格式和 CAN 帧语义。然后我试了试，it works……

我甚至让它自己写了一个 SDK 给我，这种感觉比找厂家还好，毕竟SDK里想提啥要求自己去跟 AI 讲就是了。为此，我发了一条想法，得到了广大同行的同感。

## 画一个 PCB 板

最近有一个小项目我需要制作一个把4组电位器接到 esp32 上然后再用 CAN 发出去的小板子。这玩意我在立创 EDA 里画的还是很熟练的，不过既然 GPT-6 有了，我就通过 Computer-use 的技能在 chatGPT 的 App 里许了一下愿（给它参考工程，元件选型偏好，以及尽可能画得小一点的约束），然后我的板子它就有了……

![](https://pic2.zhimg.com/v2-dfab7d44a7f58b250a74f3fd98063355_r.jpg)

当然，过程中我还是让它改了几版的，包括它对于安装孔的处理，以及esp32边上的净空区域的大小。

不过 computer-use 的这个过程和大家想的是不一样的，它并不是像人那样对着 EDA 一下一下的操作。相反，它会等很久（一般改一次需要几十分钟到几小时），然后点一下 EDA 里的“脚本执行”功能，塞进去一大段乱七八糟的代码，然后得到一个结果。

所以如果你也想这么用，请在中午吃饭、晚上睡觉之前把指令下下去，要不然盯着它那个一动不动的 computer-use 界面真的挺无聊的。

板子已经在嘉立创做好了，我还没有测，不过看上去应该是 work 的。我应该后面让它把 esp32 里的代码也帮我在Arduino里写了得了……

## 思考

你问我以后我会用 GPT-6 画图吗？我想应该不会，有去等它运行然后憋住骂人冲动写修改指令的时间，我还是自己在 SolidWorks 里画吧。

但是我发现它有一个额外的功用。就是对于完全没学过 3D 建模的同事，我发现他们已经能用 GPT-6 自己制作一些实用的零件了（主要是各种转接法兰和相机支架）。他们完全不会开草图、定约束，也不会设计配合、精妙各种孔的大小，但是通过一轮轮的反馈和等待，至少是能把东西做出来的。以前这些事都只能去找“搞硬件的同事”或者团队里恰好会这玩意的“好心人”。现在，我们已经可以很安全的认为，“这是一项每个人都应该能自己搞定”的事情了。

这可能就是 AI 辅助的最大魅力，它可以让原本压根不会觉得自己能干的人参与到一项工程工作中（比如搞游戏？）。虽然走到“专家”的程度还是需要自己学得会，但是绝大多数“入门”问题已经跨过了可行性的边界。

而如果你问我 GPT-6 是否已经实现了“AGI”，我想，对于优化算子和逆向工程这些事，它可能已经是 ASI 了…… 我已经完全不觉得我还有资格去碰瓷一下 GPT-6 谁在这些事上手速更快，它就是比目前的人类专家还强。

现在还有很多人开始用 GPT-6 搞一些直接控制机器人的事，目前有一些希望不过还并没有解决的很好。可能 GPT-6.1 会本质更强吧，毕竟这几天它应该已经吃满了各种全球人民贡献上来的 robotic data……

至于各种 CAD、EDA 软件，我也充分相信在巨大的需求和 user data 的滋养之下，GPT-6.1（如果有的话）是有机会一点点做到 expert-level 的。就像 GPT-5.3 还只是一个更聪明的编译器，5.6-Sol 是一个水平相当的专家，然后到 6 的时候就已经是一个怪物了那样。

这时，对于我们人类来说，以后的日子会变成什么样呢？

这波 GPT-6 “革命”其实还本质是 coding 能力的外部溢出。它还是没有真的“具身”的像人那样在环境里工作，而是以一堆 cli 代码作为和各种软件交互的接口。

接下来当我们去解决一个问题的时候，第一位要思考的就变成了“如何把 xxx 问题转化成一个 coding 问题，这样我就可以上 GPT-6“了。就好像当年”如何把 xxx 问题转化成一个函数拟合问题，这样我就可以上 CNN了“一样。从这方面看，一段新的地平线才刚刚露出来。

当然了，更高优先级的时候是得想办法确保自己的 20x Pro 会员不要掉，否则真就是没法上班了……
