## Q：Paged Attn能解决什么问题？

来自2023年10月，伯克利论文《Efficient Memory Management for Large Language Model Serving with PagedAttention》。

核心思想是用操作系统**虚拟内存分页**的思想，重构KV Cache存储。将预分配连续大空间改为动态分页按需分配/释放，通过**页内等价计算+页间轻量聚合**保证结果正确，最终解决LLM推理**显存碎片化、利用率低、共享难**三大痛点，在不改动模型结构的前提下，实现高显存利用率与高吞吐量。

1. **显存碎片化**：传统KV Cache 需为每个请求**预分配**连续的最大长度显存，导致严重内部（每个序列最后1个页不满 页token数） / 外部碎片（物理页无需连续），实际利用率仅 20.4%-38.2%，浪费率高达 99.8%。
2. **共享困难**：并行采样、束搜索（beam search）等场景下，同一请求的多序列（始终维护K个候选序列，生成全局最优序列）无法复用KV Cache，显存冗余大。
3. **长序列受限**：超长序列（如 100K+ token）需预留大规模连续显存，传统框架难以支持。

## Q：Paged Attn计算过程

输入x=[B,S,D]，分页数num_page，每个分页的token数P=S/num_page。

Paged Attention 对这个过程的改造集中在Q@K（注意力分数计算）和后续的加权求和score @ V阶段，核心是**按页分组计算，再聚合结果**。

- **步骤1：token数据分页**。

注意这里分页的维度是token维度，非batch维度；分页数num_page，最后1个不满分页的token进行padding。

- **步骤2：intra-page页内注意力计算**。

标准self attn，可用fa优化。要点：

这里为了演示，使用for循环，实际可以并行。

```text
def paged_attention(q, page_table):
    """
    q: 当前Query token，shape [1, d_k]
    page_table: 页表，每个元素是 (K_page, V_page)，K_page.shape [b_i, d_k], V_page.shape [b_i, d_v]
    """
    # 1. 页内计算：收集每个页的临时结果
    page_results = []
    for K_page, V_page in page_table:
        b_i = K_page.shape[0]
        # 页内注意力分数计算（等价于标准计算）
        scores = torch.matmul(q, K_page.T) / torch.sqrt(torch.tensor(d_k, dtype=torch.float32))  # [1, b_i]
        # 页内数值稳定处理
        max_i = torch.max(scores)
        exp_scores = torch.exp(scores - max_i)  # [1, b_i]
        sum_exp_i = torch.sum(exp_scores)
        sum_v_i = torch.matmul(exp_scores, V_page)  # [1, d_v]
        # 保存页内临时结果
        page_results.append({
            "max_i": max_i,
            "sum_exp_i": sum_exp_i,
            "sum_v_i": sum_v_i
        })
```

- **步骤3：inter-page页间注意力计算。**

页间计算的核心是**聚合所有页的临时结果**，而非重复计算注意力分数，这就是「非等价逻辑」—— 页间不重新计算Q@K，只做全局归一化和结果合并。要点：

```text
    # 2. 页间聚合：非等价逻辑（只聚合，不重新计算分数）
    # 全局最大值
    max_global = torch.max(torch.tensor([r["max_i"] for r in page_results]))
    # 全局指数和与V和
    sum_exp_global = 0.0
    sum_v_global = torch.zeros_like(page_results[0]["sum_v_i"])
    for r in page_results:
        # 转换到全局最大值基准
        exp_diff = torch.exp(r["max_i"] - max_global)
        sum_exp_global += r["sum_exp_i"] * exp_diff
        sum_v_global += r["sum_v_i"] * exp_diff
    
    # 3. 最终输出
    output = sum_v_global / sum_exp_global
    return output
```

## **Q：Paged Attn实现版本有哪些**

通常有2个版本：

1）**等价版本**。与标准attn的实现数学等价，核心是必须保证注意力分数的计算范围是**全局的**（每个 token 能看到所有 token），即**每个分页的Q与所有分页的K进行计算**，分页仅作为计算优化手段。

相对FA，性能没优势，使用场景仅仅是因为序列token太大，必须要用TP并行（切分若干个[batch, 子序列]）。

2）**非等价版本**。本质上是**局部+全局的混合注意力**，页内注意力用标准attn（可用FA优化），页间注意力**仅对页面级特征计算**，融合方式是简单的逐元素相乘。是一种注意力机制的改进，牺牲少量精度换取计算效率，不过生产环境需要与推理测保持计算一致性（比如训练triton，推理全c++）。

## Q：FA和PA都是解决标准attn的问题，区别是什么？

1）FA：**从GPU硬件特性为出发点做的优化**，利用SRAM（shared memory）的高带宽，对计算分块tile，注意力计算全部在tile上（shared memory+寄存器），创新点在于不用保存attn score计算的[S,S]中间结果，避免显存爆炸。

2）PA：从**推理KV存储角度**做的attn分页计算，降低显存峰值。

## Q：Paged Attn在推荐模型的应用场景？

**推荐场景基本不用到**。不同于LLM的自回归模型，会用到kv cache缓存第i个token之前的token kv向量，并且使用PagedAttention(与这里的分页注意力不是一个东西)将之前的token按页存储，解决原始kv cache依赖连续大显存带来的「显存碎片」问题，提升显存利用率，叠加**连续批处理（Continuous Batching）**提升推理单卡的请求数（QPS）。

- 传统 KV Cache 是**连续内存预分配**：每个请求需要一块完整的连续显存来存 K/V。高并发时，显存会被切成大量小碎片（比如一个请求释放 2GB 连续显存后，可能拆成多个 512MB 碎片），这些碎片无法被新请求利用，导致「显存没满但无法接新请求」。
- PagedAttention 把 KV Cache 拆成**固定大小的小页**（比如 16KB/64KB），用页表管理地址映射。

当前CTR的HSTU推荐模型基本不用自回归模型（用户序列和候选item list都存在），因此用不到kv cache和PagedAttention。

**注意：因果Mask是自回归模型的必要不充分条件。**

**1）Attention存在Mask != 自回归模型，自回归模型一定含有因果Mask；**

**2）判断生成式模型or判别式模型，根据建模目标确定，生成-序列联合概率，判别-候选item的条件概率；**

**3）推荐精排模型，Attention（FA/GQA）使用mask，是为了防止信息泄漏，一种正则约束的手段，保证时序因果合理性，避免穿越作弊。**

具体见论文《Efficient Memory Management for Large Language Model Serving with PagedAttention》和vLLM框架 关于PagedAttention工作。

## 之前关于训练的理解

### Q：应用于训练长序列

Page Attention 最早出自论文《PageAttention: Simplifying Long Context Modeling with Pagewise Processing》2023年。核心定位是 **解决LLM超长序列的训练显存瓶颈**问题**。**

主要特点：

**1）大模型长文本训练** 论文提出的背景是大模型处理 **万级以上超长序列**（如整本书、长文档、多轮对话历史）时，标准 Attention的O(S^2) 计算与显存开销会让训练无法推进（后续的Flash Attention应该也解决不了）。它的核心思路是把超长序列切分为「页」，通过**页内精细注意力 + 页间轻量化聚合**的混合模式，在精度损失可控的前提下，把训练的显存峰值从O(S^2)降到O(P^2 + NP^2),让单卡/ 小集群也能训练长上下文模型。

**2）Attn计算的分布式框架**

因为对Attn的token分页（注意**分页是在S序列维度，非batch维度**），可以适配分布式TP并行，进行页划分，适配LLM分布式训练。

### Q：Qwen和Deepseek满血版模型 大集群训练 是否用PA？

不用。还是FA + 稀疏激活MOE 架构，加上TP/EP等模型并行。

**1）优先用FA**：片上SRAM分tile，无中间attn矩阵，配合fp8量化，单卡可高效**处理32K序列**，显存与速度更优。

**2）适配MOE架构**：DeepseekV3用多头潜在注意力+deepseek MOE；Qwen用GQA，两种都在注意力层做稀疏化和专家并行。

**3）分布式并行成熟：**TP/EP拆分张量与专家，配合Deepspeed/，比PA更是配超大规模训练。
