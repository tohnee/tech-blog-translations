最近跟朋友聊大模型，发现一个现象： **人人都在聊 Agent、MCP、RAG、Fine-tune，但十个人里有八个说不清楚它们到底是干嘛的、互相什么关系。**

我自己也是从一脸懵过来的。这篇文章用尽量通俗的方式，把现在大模型圈最热的一串概念串起来讲清楚。不堆术语，每个概念都给你一个”它到底解决了什么问题”的视角。

读完你应该能回答这三个问题：

- 别人提到 MCP / Tools / ReAct / FineTune，你知道他在说哪一层；
- 自己做项目时，知道该用哪一招；
- 跟人吹水时，不至于把 RAG 和 Fine-tune 搞混。

---

### 0. 先建立全局观：这些概念到底在叠什么buff？

在逐个讲之前，先给你一张”心智地图”。你可以把大模型（LLM）想象成一个 **刚毕业的超级聪明人** ：

- 他读过海量书（预训练），知识面广，但 **不能上网、不能查资料、不能动手干活、记忆只有一小段** ；
- 你跟他说话，他只能在”短暂记忆”里思考（上下文窗口）；
- 他嘴很严， **没有计算器就心算，没有地图就瞎猜** 。

后面所有概念，本质上都是在给这个”毕业生”补能力：

| 你想让他…… | 用什么技术 |
| --- | --- |
| 回答得更像你公司的人、懂你的专业术语 | Prompt Engineering / Few-shot |
| 查最新资料、读你的私有文档 | RAG（检索增强） |
| 查天气、订机票、调你家接口 | Tools / Function Calling |
| 自己规划步骤、反复试错完成复杂任务 | ReAct / Agent |
| 长期记住你是谁、聊过什么 | Memory |
| 从骨子里变成某个垂直专家（医疗/法律/代码） | Fine-tune（微调） |
| 不用给每个工具单独写对接代码，统一接入 | MCP（模型上下文协议） |
| 按固定流程完成一套复杂操作（做报表、发邮件） | Skills（技能） |

下面逐个拆。

---

### 1. 地基：LLM、Token、上下文窗口

**LLM（Large Language Model）** 就是那个”超级毕业生”本身。它做的事只有一件： **根据你给的上文，一个词一个词地预测下一个最合理的词** 。注意，它不是在”查数据库”，是在”凭语感续写”——这就是为什么它会一本正经地胡说八道（幻觉）。

**Token** ：模型处理文字的最小单位。中文大概 1 个字 ≈ 1~2 个 Token，英文大概 0.75 个单词 ≈ 1 个 Token。你可以粗暴理解为”模型眼里的字数”。

**上下文窗口（Context Window）** ：模型一次能”同时看到”的 Token 上限。比如 128K 窗口，就是它这一轮思考最多能”记住”前面 12 万 Token 的内容。 **超出的部分它就真的看不见了** ——这就是为什么长文档要做 RAG、要做总结压缩。

> 一句话：LLM 是脑子，Token 是它的字数单位，上下文窗口是它的”短期记忆容量”。

---

### 2. 让模型”动手”：Tools / Function Calling

模型再会说，它也只是一张嘴。你问它”现在上海几度”，它不可能真的知道。

**Function Calling（函数调用，俗称 Tools）** 就是：你提前告诉模型”我这里有几个工具可以用”，比如：

```text
get_weather(city: string) → 返回天气
send_email(to: string, body: string) → 发邮件
```

当你问”上海今天几度，顺便把结果发我邮箱”，模型不会瞎编天气，而是会 **输出一个结构化的调用请求** ：

```json
{ "name": "get_weather", "arguments": { "city": "上海" } }
```

你的程序拿到这个请求，真正去调天气 API，把结果喂回给模型，模型再继续组织语言、调用发邮件工具。

> 类比：给那个”毕业生”配了一个万能遥控器，他自己按不动按钮，但会告诉你”帮我按这个键”。

**关键认知** ：Tools 不是模型自己执行的，是 **你的程序在背后真正执行** 。模型只负责”决定该调哪个工具、传什么参数”。

---

### 3. 让模型”边想边做”：ReAct 与 Agent

普通对话是”你问一句，他答一句”。但如果任务是”帮我规划一次3天的东京旅行，要考虑天气、预算、我的喜好”，一步是答不出来的。

**ReAct = Reasoning（推理） + Acting（行动）** 。它让模型形成一个循环：

![](https://pic4.zhimg.com/v2-1b32cdaec63777b60475de54571d102b_r.jpg)
*Thought → Action → Observation 循环，Action 通过 MCP 调用 Tools / RAG / Memory / Skills*

1. **Thought（思考）** ：我现在该干嘛？还差什么信息？
2. **Action（行动）** ：调用某个工具（查天气、搜酒店）；
3. **Observation（观察）** ：拿到工具返回的结果；
4. 回到 Thought，基于新信息继续想下一步……
5. 直到觉得信息够了，输出 **Answer** 。

**Agent（智能体）** 就是把这个循环跑起来的整体系统。它不只是”聊天”，而是 **有目标、能拆解任务、能调用工具、能根据反馈调整路径** 的程序。

> 类比：普通 LLM 是”你问他答”的顾问；Agent 是”你扔给他一个目标，他自己当项目经理，拆解、动手、复盘、交付”。

现在很火的”Computer Use”（让 AI 操作电脑）、”Manus 类通用 Agent”，本质都是 ReAct 循环在跑，只是工具从 API 变成了鼠标键盘屏幕。

---

### 4. 让模型”开卷考试”：RAG、Embedding、向量数据库

模型训练有截止日期，它不知道今天的新闻，更不知道你公司内网里那份 200 页的产品手册。怎么办？

最朴素的办法：每次提问时，把相关文档全塞进上下文窗口。但文档太长塞不下，怎么办？

**RAG（Retrieval-Augmented Generation，检索增强生成）** 就是解决这个问题的：

![](https://pic2.zhimg.com/v2-b3368b220de555acdf7e1dbda309014b_r.jpg)
*上半部分是离线索引，下半部分是在线查询，向量库在中间把两段连起来*

完整 pipeline 是这样的：

1. **Document** ：你有一堆文档（PDF、Wiki、代码、聊天记录）；
2. **Chunk（分块）** ：把长文档切成一段段小块（比如每 500 字一块）；
3. **Embedding（向量化）** ：用 Embedding 模型把每块文字变成一串数字（向量）， **语义相近的文字，向量距离也近** ；
4. **Vector DB（向量数据库）** ：把这些向量存起来（Milvus、Pinecone、pgvector 等）；
5. **Retrieve（检索）** ：用户提问时，把问题也变成向量，去向量数据库里找”语义最接近”的几块内容；
6. **LLM Generate** ：把检索到的相关段落 + 用户问题，一起塞给大模型，让它 **基于这些资料** 回答。

几个常听到的子概念：

- **Embedding 模型** ：专门干”文字转向量”这一件事的小模型（如 BGE、text-embedding-3）；
- **Chunk 策略** ：怎么切分文档很讲究——按固定长度切会切断语义，按标题/段落切效果更好；
- **Rerank（重排序）** ：粗检索召回 50 条后，再用一个更精的模型挑出最相关的 top 3~5 条，显著提升准确率。

> 类比：RAG 就是 **开卷考试** 。模型不再靠死记硬背回答，而是先翻到课本相关页码，再照着课本答题。好处是答案可溯源、知识更新快（换文档就行）、不用重新训练模型。

### 5. 让模型”记事”：Memory

Agent 聊久了会发现一个问题：上次聊过”我儿子叫樊小果，对芒果过敏”，这次再问就忘了。

**Memory（记忆）** 就是在 Agent 外面挂一个存储系统，把重要信息（用户画像、历史决策、偏好）存下来，下次对话时检索出来塞进上下文。常见做法就是”长期记忆 = 一个跑在后台的 RAG”。

---

### 6. 让模型”换脑子”：Pre-train、SFT、Fine-tune、RLHF

这一组概念是关于 **模型本身怎么训练出来** 的。

- **Pre-training（预训练）** ：在海量互联网文本上”读书”，得到一个什么都懂一点、但不太会好好说话的”基座模型”（Base Model）。这一步成本极高（几百万到几千万美元），普通公司玩不起。
- **SFT（Supervised Fine-Tuning，监督微调）** ：用几万到几十万条”高质量问答对”教模型”怎么好好回答问题”。ChatGPT 之所以叫 ChatGPT，就是在 GPT 基座上做了 SFT。
- **RLHF（人类反馈强化学习）** ：让人类给模型的多个回答打分，训练一个”奖励模型”，再用强化学习让模型朝着”人类更喜欢的回答”优化。这一步让模型从”能说”变成”说得讨人喜欢、符合价值观”。
- **Fine-tune（微调）** 是个宽泛的词，泛指在基座模型基础上继续训练。现在工业界说”做个垂直模型”，通常指用自己领域的数据（病历、代码、合同）继续 SFT。

![](https://pic1.zhimg.com/v2-cdbee364097043494f1f6eac74f0f204_r.jpg)

**那 RAG、Prompt、Fine-tune 到底怎么选？** 一张表说清楚：

| 维度 | Prompt Engineering | RAG | Fine-tune |
| --- | --- | --- | --- |
| 解决什么 | 让现有模型按格式/风格回答 | 接入私有/实时知识 | 改变模型骨子里的能力和风格 |
| 成本 | 几乎为零 | 中（要搭检索系统） | 高（数据+算力+反复试） |
| 知识更新 | 改提示词即可 | 换文档即可 | 要重新训练 |
| 可解释性 | 高 | 高（能引用出处） | 黑盒 |
| 适合场景 | 格式要求、简单任务 | 企业知识库、客服、问答 | 垂直领域专家、特定文风、代码 |
| 见效速度 | 当天 | 1~2 周 | 数周~数月 |

> 经验法则： **能用 Prompt 解决就别 RAG，能用 RAG 解决就别 Fine-tune** 。Fine-tune 是大招，不是入门选项。

### 7. 让模型”接万物”：MCP（Model Context Protocol）

前面说了 Tools 很好用，但问题来了：你想让 Claude 读你的文件、查你的数据库、调你的 Jira，得给 Claude 写一套对接代码；想让同一个 Agent 支持 10 个工具，就写 10 套；换个模型（比如从 Claude 换到 GPT），又得重写一遍。

**MCP（Model Context Protocol，模型上下文协议）** 是 Anthropic 在 2024 年底推出的一个开放标准，你可以把它理解为 **“大模型世界的 USB-C 接口”** ：

![](https://picx.zhimg.com/v2-559e4133f435b3faccaf430ba7136df1_r.jpg)

从图上可以看到完整的数据流向：

- **Host** ：用户直接交互的应用（Claude Desktop、Cursor、你自己写的 Agent），里面跑着 LLM 和 MCP Client；
- **MCP 协议层** ：Host 和 Server 之间的统一”插头”，支持 stdio（本地进程）和 HTTP+SSE（远程服务）两种传输；
- **Server** ：按 MCP 规范暴露能力的服务，可以是文件系统、数据库、GitHub、Slack，也可以是你公司内部的业务系统。

一个 MCP Server 可以暴露三类能力：

- **Tools** ：可执行的函数（发邮件、查数据库）；
- **Resources** ：可读取的数据文件（你的笔记、代码仓库）；
- **Prompts** ：预置好的提示词模板。

> 类比：MCP 不是一个新模型，也不是一个新功能，而是 **一套”插头标准”** 。它让模型和外部工具之间的对接从”每对情侣单独写情书”变成”大家都用微信”。

对普通开发者的意义：你以后写一个工具，按 MCP 规范暴露一次，所有支持 MCP 的 AI 客户端都能用你的工具了。

---

### 8. 让模型”学一门手艺”：Skills

最后说一个最近很火的词—— **Skills（技能）** 。

如果说 Tools 是给模型一个”扳手”，那 **Skills 就是给模型一本”操作手册”** ，教它一套 **有流程、有判断、有规范的复杂操作** 。

举几个例子：

- “简历润色 Skill”：知道该问你要什么信息、按什么结构改、改完要自查哪些点；
- “生成海报 Skill”：知道先读需求、再选风格、再出图、最后校验；
- “合同审查 Skill”：知道先读合同全文、再对照法规、再输出风险清单。

在产品形态上，一个 Skill 通常是一个文件夹，里面装着：

- 一份 `SKILL.md` （给模型看的说明书：什么时候用、怎么用、有什么规范）；
- 配套的脚本、模板、参考资料；
- 可调用的工具和数据。

> 类比：Tools 是”给你一把手术刀”；Skills 是”给你一个外科医生的培训课程 + 手术流程 SOP + 器械包”。模型读完 Skill，就知道”遇到这类事，我应该按这个 SOP 一步步做”。

### 9. 串起来：它们是怎么一起工作的？

一个完整的现代 AI 应用，大概是这样组装的：

```text
用户提问
   ↓
[Agent 主循环]（ReAct：Thought → Action → Observation 循环）
   ├── 读 Memory（长期记忆：你是谁、偏好什么）
   ├── 查 RAG（知识库：公司文档、历史数据）
   ├── 调 Tools（通过 MCP 协议：天气、邮件、数据库、API）
   ├── 按 Skill 执行（如果是已知的复杂任务，走 SOP）
   └── 必要时调用代码 / 浏览器 / 文件系统
   ↓
输出答案
```

而底层的”脑子”（LLM），可能是一个经过 Fine-tune 的垂直模型，也可能是直接调 GPT/Claude 这种通用大模型。

### 10. 一张表收尾：这些词你该什么时候想起它？

| 听到这个词 | 你应该联想到 |
| --- | --- |
| Token / Context Window | “这次对话能塞多少字” |
| Function Calling / Tools | “让 AI 调外部 API” |
| ReAct | “AI 边想边干的循环” |
| Agent | “有目标、自己拆任务的 AI 员工” |
| RAG / Embedding / Vector DB | “让 AI 查你的资料” |
| Chunk / Rerank | “RAG 的调优点” |
| Memory | “让 AI 记住你” |
| Pre-train / SFT / RLHF | “模型是怎么训出来的” |
| Fine-tune | “花大钱让模型换脑子” |
| MCP | “AI 接工具的统一插头” |
| Skills | “给 AI 的操作手册/SOP” |
| Prompt Engineering | “最便宜的提升手段” |

---

大模型这圈词看起来多，其实核心逻辑特别朴素：

> **LLM 是一个聪明但受限的脑子，整个生态都在围绕”怎么补它的短板”做文章** ——补知识（RAG）、补动手能力（Tools/MCP）、补规划能力（ReAct/Agent）、补记忆（Memory）、补专业能力（Fine-tune）、补做事规范（Skills）。

学习路径建议：

1. 先把 Prompt Engineering 玩明白（零成本，当天见效）；
2. 动手写一个 Function Calling 的小 demo（10 行代码的事）；
3. 搭一个最小 RAG（用开源 embedding + 一个 sqlite-vec 就能跑）；
4. 玩一玩 ReAct Agent（LangGraph 或直接手写循环）；
5. 再去看 MCP 和 Skills 的生态——你会发现前面学的东西全都串起来了。
