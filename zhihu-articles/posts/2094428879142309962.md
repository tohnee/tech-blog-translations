我们平时会使用不同的 AI 客户端，比如 VS Code、WorkBuddy 等。如果我有自己的工具，希望可以在多个 Agent 中使用同一组工具，应该如何实现呢？

可以用 MCP 。

![](https://pica.zhimg.com/v2-f9912a3bafabe538cb4516759114655e_1440w.jpg)

**本篇使用 python 和 FastMCP ，创建一个简单的 MCP Server，再接入 VS Code 和 WorkBuddy，看看 mcp 是如何配置，以及工具调用是怎么完成的。**

## 1 同一个 MCP Server 接入两个客户端

我们先看看在 VS Code 或 WorkBuddy 中调用同一个 MCP Server 的实际结果。

VS Code：检索到 `file_server` 的 MCP，成功调用工具 `add(12, 13)` ，返回结果 `25` 。调用工具 `now` , 返回当前时间。

![](https://pica.zhimg.com/v2-d76f3499581b4a9a7687a66fbc274452_1440w.jpg)

WorkBuddy：检索到 MCP，向 `add` 传递参数，返回结果。调用 `now()` ，返回当前时间。

![](https://pica.zhimg.com/v2-f2fa092d8d31dc489432fa519d17d81e_1440w.jpg)

## 2 用 FastMCP 创建服务

我在已有的 Python 环境中，安装了 FastMCP 等相关依赖，创建 `file_server.py` ，注册两个工具： `add` 和 `now` 。

```text
# file_server.py
from datetime import datetime, timezone
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("hello-demo")

@mcp.tool()
def add(a: int, b: int) -> int:
    """两个整数相加，返回和。"""
    return a + b

@mcp.tool()
def now() -> str:
    """返回当前 UTC 时间，ISO 格式，精确到秒。"""
    return datetime.now(timezone.utc).isoformat(timespec="seconds")

if __name__ == "__main__":
    mcp.run()  # 默认 stdio。改成mcp.run(transport="streamable-http") 服务可常驻 
```

| 功能 | 代码 | 作用 |
| --- | --- | --- |
| 注册工具 | @mcp.tool() | 告诉 FastMCP 这是一个工具。函数名和下面的文字是工具名称和工具描述。是否准确很重要。 |
| 定义参数 | a: int, b: int | 说明两个参数都是整数。FastMCP 把它转成标准参数格式，让 AI 理解：传两个整数，名字叫 a 和 b。 |
| 定义返回值 | -> int | 说明函数返回整数。调用后，结果有两种结果。content：是返回的内容块，structuredContent 提供结构化结果。 |

**为什么工具描述很重要？** 模型通常不需要读取工具的实现代码。客户端通过 MCP Server 获取工具名称、描述和参数结构，再将工具信息提供给模型。所以函数描述和类型注解写得好不好，直接影响 AI 能不能正确调用。

启动命令验证 `python3 file_server.py` ,运行 `mcp.run()` ，启动服务，当前代码启动使用 `stdio` 方式通信。如果在终端运行会发现没反应，这是正常的，因为当前在等待客户端输入。

## 3 MCP 是怎么完成工具调用的？

工具定义好后，还需要让 AI 客户端知道有哪些工具、每个工具怎么使用。MCP 是如何完成这一步的呢？

我们可以先通过下图了解 AI 应用和 MCP Server 之间发生了什么。

![](https://pic3.zhimg.com/v2-5de4cbe212dbe6d6770a82dc5d174126_1440w.jpg)

可以把 MCP 想成一个帮忙传话的人。

模型想计算 `2 + 3` ，但它需要使用 `add` 工具。客户端会先获取工具清单，再把模型的调用请求发送给 MCP Server。

整个过程可以简单理解为三步：

1. **初始化 `initialize` ：** 双方先确认协议版本和能力。客户端向 Server 查询有哪些工具。
2. **列工具 `tools/list` ：** 客户端问服务端，你有哪些工具？服务返回工具名称 `add` 和 `now` ，以及参数结构。
3. **调工具 `tools/call` ：** 客户端请求执行其中一个工具 `add(2,3)` 返回 `5` 。客户端再把结果交给模型。

Stdio 模式下，客户端关闭输入流后，服务进程随之退出。

客户端和 Server 之间使用约定好的消息格式进行通信。MCP 使用 JSON-RPC 格式描述请求和响应。可以把它理解成一张格式统一的消息单，写清楚要做什么，以及结果是什么。

理解这个过程后，再来看客户端配置以及每项配置在解决什么问题。

## 4 在 VS Code 和 WorkBuddy 中配置

客户端连接 MCP Server，主要是为了 **发现工具和调用工具** 。

常见的传输方式有 `stdio` 和 HTTP。

| 对比 | stdio | HTTP |
| --- | --- | --- |
| 怎么连接 | 客户端启动本地程序 | 客户端连接服务地址 |
| 服务在哪里 | 通常在自己的电脑上 | 通常运行在独立服务器上 |
| 需要配置什么 | command、args，以及必要的 env | url，以及必要的认证信息 |
| 适合什么情况 | 自己电脑上的本地工具 | 需要通过网络访问的服务 |

以下展示基于 `stdio` 的传输方式，在 vscode 和 workbuddy 中 MCP Server 的配置流程。

**在 VSCode 里面配置文件**

写配置文件，新建了 `/root/.copilot/mcp-config.json` ，可以问 AI 获取 MCP 文件配置具体路径。

*说明：此路径下的用户级配置，对所有 Copilot CLI 和 Chat Agent 会话都生效。不用这个 mcp 时可以选择停止 mcp 服务或者删除该文件。*

![](https://picx.zhimg.com/v2-0052f6089271442488d54a7e17137025_1440w.jpg)

1. 使用快捷键 `Ctrl+Shift+P` , 运行 mcp list servers->显示本地配置的服务器->选择 `file-server` mcp 的名称，点击启动。
2. 按 `Ctrl+Shift+P` ，运行 **Developer: Reload Window** 。
3. 再打开 **MCP: List Servers** ，应该能看到 `file-server` 。它如果显示“已停止”，选中后点 **Start Server** 。

![](https://picx.zhimg.com/v2-44c004172f2caf1e08908c0e9f3f9887_1440w.jpg)

**在 workbuddy 里面配置文件**

在 workbuddy 中，点击左侧“专家-技能-连接器”->选择“连接器”->“自定义连接器”->配置 MCP->点击保存->点击运行 MCP。配置后即可在对话框提问。

## 5 实测中遇到的问题

- `stdio` 传输方式下，不要 `print()` ：stdout 是协议通道，随便 print 会破坏 JSON 格式。要打日志需要写到 stderr。
- 我在之后在 vscode 中使用 `http` 时，出现过连接失败的现象。我当时定位到是代理环境导致的，需要在配置中给服务器 ip 添加白名单。具体解决方式是：把 MCP Server 关掉重启，重新加载窗口，新建 agent 对话框再次连接 mcp。这里需要注意如果当前对话框 mcp 连接出错，在此之后的连接都会按上次的错误方式连接，所以需要新开一个对话框。

*为什么需要重新加载窗口？配置后如果客户端没有识别到 MCP Server，可以尝试重新加载窗口，让客户端重新读取配置并刷新状态。*

## 6 写在最后

本次实践用两个简单工具，跑通了 MCP Server 的创建、配置和调用。

MCP 的价值在于让不同的 AI 客户端能够按照统一的协议使用它们。

如果把工具换成查询数据库、读取文件或调用业务 API，思路是一样的。
