TensorRT 10 之后模型部署接口发生很大变化，所以总结一篇新的部署指南。老版本的指南为[利用TensorRT部署模型](https://zhuanlan.zhihu.com/p/517005702)。用于举例的代码为TensorRT官方样例 [SemanticSegmentation/tutorial-runtime.cpp](https://github.com/NVIDIA/TensorRT/blob/main/quickstart/SemanticSegmentation/tutorial-runtime.cpp)

## 1 模型转换

模型部署的流程依然时pytorch模型转onnx，再将onnx转换为tensorrt engine格式。

pytorch转换onnx过程中需要注意的点包括

- 模型设置为eval模式，避免模型权重参数被修改。
- 设置合理的onnx算子版本，一般越高的onnx算子对新算子支持越好。让算子导出为一个融合后的结构而不是一连串小算子。
- 设置onnx动态维度，设置动态维度时比较合理的选择是仅设置batch size维度动态。

```python
#https://github.com/NVIDIA/TensorRT/blob/main/quickstart/SemanticSegmentation/export.py
torch.onnx.export(
    model,
    input_tensor,
    output_onnx,
    opset_version=12,
    do_constant_folding=True,
    input_names=["input"],
    output_names=["output"],
    dynamic_axes={"input": {0: "batch", 2: "height", 3: "width"}, "output": {0: "batch", 2: "height", 3: "width"}},
    verbose=False,
)
```

pytorch转换onnx使用torch.onnx.export，实际过程中常常遇到问题，现列举常见问题

1、类似mmcv提供一些deploy脚本，用户指定后端部署模型类型比如trt，就可以完成pytorch到onnx再到tensorrt engine转换，但实际使用由于模型依赖库或者其他原因导致deploy运行失败。此时就回归到pytorch转换onnx的原理，构造伪输入pytorch模型完成前向执行部署动态图并转换为onnx。

2、pytorch转换onnx中选择在gpu还是cpu端运行模型捕获动态图？从确保pytorch导出的onnx计算图完整性角度推荐使用cpu，因为gpu端常常有用户自定义的pytorch算子，但他们可能忘记为自定义算子添加onnx下的表示，导致gpu端导出的onnx图不完整。

3、我们有时候需要为pytorch算子封装onnx算子表示，这相当于手动完成小算子的算子融合，注意这需要确保新的onnx算子在后端有对应实现。具体做法是在自定义pytorch算子中实现symbolic函数。

```python
#https://github.com/OpenGVLab/InternImage/blob/master/segmentation/ops_dcnv3/functions/dcnv3_func.py
    def symbolic(g, input, offset, mask, kernel_h, kernel_w, stride_h,
                 stride_w, pad_h, pad_w, dilation_h, dilation_w, group,
                 group_channels, offset_scale, im2col_step):
        """Symbolic function for mmdeploy::DCNv3.

        Returns:
            DCNv3 op for onnx.
        """
        return g.op(
            'mmdeploy::TRTDCNv3',
            input,
            offset,
            mask,
            kernel_h_i=int(kernel_h),
            kernel_w_i=int(kernel_w),
            stride_h_i=int(stride_h),
            stride_w_i=int(stride_w),
            pad_h_i=int(pad_h),
            pad_w_i=int(pad_w),
            dilation_h_i=int(dilation_h),
            dilation_w_i=int(dilation_w),
            group_i=int(group),
            group_channels_i=int(group_channels),
            offset_scale_f=float(offset_scale),
            im2col_step_i=int(im2col_step),
        )
```

4、我们转换模型时一般会通过onnxruntime验证转换出来的onnx模型精度，如果精度无误再将onnx转换trt engine，但如果遇到算子不支持时，建议不实现onnxruntime算子直接实现tensorrt算子插件，避免重复工作。

到这里已经有onnx模型接下来完成onnx到trt engine模型转换。特别注意针对设置onnx的动态维度，在转换trt engine时需要通过minShapes、optShapes、maxShapes确定动态变化的范围，其中input表示onnx模型中输入节点名称。

另外很有用的参数是verbose，他可以将模型转换trt engine中onnx层匹配到的trt算子，转换后的trt模型大小给出。

```text
trtexec --onnx=fcn-resnet101.onnx 
--saveEngine=fcn-resnet101.engine
--minShapes=input:1x3x224x224
--optShapes=input:2x3x448x448
--maxShapes=input:4x3x1024x1024
--fp16
--noTF32
--verbose
```

## 2 模型部署

接下来部署tensorrt engine，首先模型转换和模型部署环境需要保持一致即相同的硬件相同版本的tensorrt。

tensorrt engine file：转换出来的trt模型文件。

Logger：日志模块。

nvinfer1::IRuntime：运行时结构，使用Logger初始化。

nvinfer1::ICudaEngine：引擎，包含模型信息，通过解序列化的trt模型文件初始化。

nvinfer1::IExecutionContext：模型执行上下文，包含模型输入输出节点信息。在执行模型以前需要将提前分配好的输入输出空间绑定到上下文的输入输出节点。

```cpp
    //设置上下文中输入张量的尺寸，对于动态输入必须告诉模型当前输入的尺寸具体是多少
    char const* input_name = "input";
    auto input_dims = nvinfer1::Dims4{1, /* channels */ 3, height, width};
    context->setInputShape(input_name, input_dims);
    //为输入和输出张量分配GPU显存空间
    void* input_mem{nullptr};
    if (cudaMalloc(&input_mem, input_size) != cudaSuccess)
    {
        gLogError << "ERROR: input cuda memory allocation failed, size = " << input_size << " bytes" << std::endl;
        return false;
    }
    void* output_mem{nullptr};
    if (cudaMalloc(&output_mem, output_size) != cudaSuccess)
    {
        gLogError << "ERROR: output cuda memory allocation failed, size = " << output_size << " bytes" << std::endl;
        return false;
    }
    //将分配的输入和输出空间绑定到模型输入输出节点
    context->setTensorAddress(input_name, input_mem);
    context->setTensorAddress(output_name, output_mem);

```

执行

```cpp
bool status = context->enqueueV3(stream);

```

## 3 同老版本差别

输入输出张量的空间提前绑定到上下文，不需要显式的传递给接口

```cpp
//老版本接口
void* bindings[] = {input_mem, output_mem};
bool status = context->enqueueV2(bindings, stream, nullptr);

```
