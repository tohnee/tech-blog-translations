> 原文： [AI Chip Architectures](https://www.jacobpeake.com/ai-chip-architectures) 
>  作者：Jacob Peake

2018 年的 ISCA 上，John Hennessy 与 David Patterson 发表了题为 [A New Golden Age for Computer Architecture](https://dl.acm.org/doi/10.1145/3282307) 的图灵奖演讲。

20 世纪 80 年代，两人开展日后使其获得图灵奖的研究时，单线程 CPU 性能每年增长 52%。到 2018 年，随着摩尔定律与 Dennard Scaling 接近极限，年增速已经降至 3%。

计算领域由此转向领域专用架构（DSA）。两人以已经投入生产的 Google TPU v1 为例：它的神经网络推理吞吐量是 CPU 的 29 倍，能源效率高出 80 倍。演讲最后预言，未来十年将迎来新型计算机架构的寒武纪大爆发。

这项预测已经兑现。如今，业界正在投入数十种架构：GPU、TPU、LPU、NPU、DPU、ASIC、wafer-scale engine、可重构数据流、神经形态计算、光子计算和模拟计算，其中相当一部分专门面向 AI。

目前实现大规模部署的架构包括 NVIDIA 与 AMD GPU、TPU 与 Trainium 代表的脉动阵列加速器、Cerebras Wafer-Scale Engine，以及 Groq LPU。

NVIDIA 明显领先。AMD 紧随其后，OpenAI 与 Meta 均已承诺部署 6 GW AMD 算力。TPU 用于训练 Gemini，并将以最多一百万枚芯片服务 Anthropic；Anthropic 也使用超过一百万枚 Trainium 芯片运行 Claude。Cerebras 已为 OpenAI 提供推理服务；Groq LPU 团队与技术通过一笔约 200 亿美元的 acquihire 并入 NVIDIA。

本文从设计哲学、芯片架构、scale-up、scale-out 和软件栈五个方面，逐一拆解这些路线。

这里先说明三个贯穿全文的概念。 **Scale-up** 指把同一台服务器或同一个数据中心机柜（rack）内的多枚芯片连接成一个高速计算系统，重点是低延迟和高带宽。 **Scale-out** 指继续连接多台服务器、多个机柜甚至多个数据中心，规模更大，通信延迟也更高。 **数据中心机柜（rack）** 是安装服务器、交换机、电源和液冷设备的标准柜体。 **Pod** 专指 Google TPU 集群，一个 pod 通常跨越多台机柜，包含数千枚 TPU。

## 问题

AI 计算以矩阵乘法为主。一个 Transformer 由连续的 matmul 构成：Q/K/V 投影、attention、输出投影、FFN，其间穿插归一化、激活值、残差加法等逐元素运算。训练一个前沿模型需要执行约 $10^{25}$ 次乘加，matmul 本身就是一系列乘加。

matmul 的形状取决于负载。训练时，一批序列会前向通过所有层，再反向传播损失并更新权重；同一权重矩阵一次要处理数千个 token。Prefill 是推理中的提示词处理阶段，完整输入序列会在第一枚输出 token 生成前一次性通过模型。训练和 Prefill 都会把大量 token 叠加到同一个权重矩阵上，因此每层执行的都是大型矩阵-矩阵乘法（GEMM），算术强度很高，性能主要受计算能力约束。

Decode 采用自回归方式，每次只生成一枚 token，并依赖此前的全部 token；token $N+1$ 必须等到 token $N$ 生成后才能开始。由于每一步只投影一枚 token，matmul 会退化为矩阵-向量乘法（GEMV）。生成一枚 token 需要遍历模型的全部权重，attention 还要完整读取 KV Cache，算术强度比 Prefill 低几个数量级。

推理系统通过 token batching 恢复部分算术强度，把 GEMV 提升回 GEMM。Continuous batching 堆叠多个用户的 decode step；speculative decoding 为每个请求堆叠 $K$ 枚 draft token，并在一次前向中完成验证；multi-token prediction 把同样的方法放入模型内部。这些方法提高 matmul 单元的利用率，同时提高 Ops/B。Continuous batching 中，每个用户仍然读取自己的 KV Cache，因此长上下文 decode 会从权重带宽受限转为 KV Cache 带宽受限。

架构问题的核心，是以足够快的速度把数字搬到执行 matmul 的位置。这就是 memory wall（内存墙）：计算能力呈指数扩张，内存带宽的增速更慢。

每种架构都提出了一套数据搬运策略。理解一枚芯片可以归结为四个问题：数据存在哪里，数据怎样移动到计算单元，计算单元长什么样，以及大量芯片如何互联。

## NVIDIA GPU

NVIDIA GPU 是大规模并行处理器。它的核心判断是：由主机 CPU 编排、通过 CUDA 暴露、拥有数千个线程的可编程芯片，适合执行可并行负载。每一代产品都在可编程 Streaming Multiprocessor（SM）上增加 acceleration primitive，同时延续原有编程模型。同一枚芯片可以训练 Transformer、提供推理、渲染图形并执行科学模拟，这套路线被称作 accelerated computing。

### 架构

NVIDIA GPU 由面向吞吐的核心、持续供数的深层存储层次，以及足以维持数千个线程同时在途的调度芯片组成。核心单元是 Streaming Multiprocessor，每个封装复制一百余个：V100 有 80 个，A100 有 108 个，H100 有 132 个，B200 有 148 个，B300 有 160 个，Rubin 有 224 个。

每个 SM 内部沿用同一配方：四个 SM Sub-Partition，各自拥有 warp 调度器、dispatch 单元、16k×32-bit 寄存器文件、标量 CUDA Core lane、负责 transcendental function 的 Special Function Unit，以及通往 SM Tensor Core 的独立端口。四个 sub-partition 共享 L1/shared memory block 与 TMA。线程以 32 个一组组成 warp，按 SIMT lock-step 执行；每个 partition 驻留数十个 warp，调度器可在它们之间切换，隐藏内存与 arithmetic stall。

### 计算

CUDA Core 提供最初的计算吞吐量，在 AI 中负责 matmul 之外的工作：激活值、残差加法、归一化与地址计算。Transformer block 约 99% 的 FLOPs 来自 matmul，绝大部分计算吞吐量因而由 Tensor Core 提供。

Tensor Core 在小型矩阵 tile 上执行 fused matrix 乘加：

$D=A\cdot B+C \\$

完整 matmul 被拆成多个 output tile。为了生成一个 output tile，kernel 沿共享 inner 维度 $K$ 前进，从左侧输入矩阵的一条 row-strip 取出 $A$，从右侧矩阵的一条 column-strip 取出 $B$，把每个 partial product 累加到持续更新的累加器。$C$ 保存当前部分和，$D$ 是传入下一步的更新值。inner loop 结束后，$D$ 就是完整输出矩阵的一个完成 tile；完整 matmul 由许多此类 tile MMA 组成。

Tile 形状记作 M × N × K，其中 $M\times N$ 是 output tile size，$K$ 是一条指令单次 contraction 覆盖的 inner 维度长度，其余 $K$ 轴由 kernel inner loop 逐步走完。累加器在整个 loop 中持续存在：每次 MMA 的输出 $D$ 成为下一次 MMA 的输入 $C$，实际执行的是原地更新 $C\leftarrow A\cdot B+C$。连续指令把 partial product 折叠进同一块存储，直到完整遍历 K-axis。

V100 第一代单元每个 SM 有 8 个，执行 warp-level 16×16×16 FP16 MMA。A100 第三代加入 TF32、BF16、FP64 matmul 与 2:4 结构化稀疏。H100 第四代加入原生 FP8，并把抽象从 warp 提升到 warp group：128 个线程协同发出 64×256×16 的异步 `wgmma` ，该操作在后台运行，发出指令的 warp 同时加载下一个 tile。

B200 第五代进一步引入 256×256×16 two-SM MMA，操作数分布在一对 SM 上；它还支持原生 FP4，并为每个 SM 配置 256 KB Tensor Memory（TMEM）scratchpad，用来存放 accumulator tile，降低寄存器文件压力。Rubin 第六代提高 FP4 吞吐量、加入原生 FP6，并配合第三代 Transformer Engine 在硬件中完成 adaptive NVFP4 micro-block scaling，让每个 tile 的量化 metadata 留在 Tensor Core 路径上。

六代架构始终把 matmul 放在线程与 warp hierarchy 中；发出一次 matmul 所需的线程数量持续减少，issue 也逐渐与执行解耦。Volta `mma.sync` 是 warp-collective synchronous 指令：一个 warp 的 32 个线程一起执行，每条 lane 在寄存器中持有 A、B 和累加器 D 的 fragment，整个 warp 等待操作完成。

Hopper `wgmma.mma_async` 把 issuer 扩展到 128 个线程的 warp group，将 B 放进 shared memory 描述符；A 可由 kernel 选择寄存器或描述符。指令发出后立即返回，matmul 在后台执行，warp group 可继续排入下一个 tile，完成状态由 `wgmma.commit_group` 与 `wgmma.wait_group` 跟踪。

Blackwell `tcgen05.mma` 完成了这次迁移：A 与 B 都进入 shared memory 描述符，A 也可以直接来自 TMEM；累加器 D 落在 TMEM。所有操作数都离开 lane 后，issue 无需协调每线程状态，一个线程即可发出指令并立即返回。完成事件通过 `mbarrier` 通知，consumer warp 在 barrier 上等待。其余 warp 与发出指令的线程可以继续处理其他工作。

CTA-pair variant 把同一模型扩展到两个 SM：paired 集群中每个 SM 各有一个线程发出协同 MMA，pair 共享操作数，组成 256×256×16 two-SM tile；异步执行与 `mbarrier` 机制保持一致，barrier 提升到集群级以维持两个 SM 同步。

matmul 指令同时变得更大、对 issuing 线程更轻。它从 32 条 lane lock-step 执行的操作，演化为在 warp 模型内发出、由描述符驱动、执行过程脱离 warp 的命令。

这种解耦让 Transformer attention kernel 能够高效运行。matmul 在途时，warp 可以执行 softmax、施加 mask 或预加载下一个 tile。matmul 与外围逐元素计算的重叠构成现代 attention kernel 的基本结构，包括 FlashAttention-3 与 FA4，其前提就是矩阵指令不阻塞 warp。

### 存储

片上 hierarchy 每一层都使用硬件管理的缓存，并叠加软件提示。片外采用 HBM：V100 为 32 GB HBM2，H100 为 80 GB HBM3，B200 为 192 GB HBM3e，B300 为 288 GB，Rubin 为 288 GB HBM4。芯片级 L2 缓存位于 HBM 与 SM 之间：V100 为 6 MB，A100 为 40 MB，H100 为 50 MB，B200 为 60 MB。B200 的 60 MB 分布在 two-die 封装的两个 30 MB bank 中，locality-aware residency control 可把 hot tile 固定在相邻 die。

每个 SM 内有 256 KB unified L1/SMEM，在 kernel launch 时划分为硬件管理的 L1 与程序员控制的 scratchpad。寄存器文件每个 SM 约 256 KB，分给四个 partition。Blackwell 加入第五层 TMEM，每个 SM 256 KB，专用于 MMA 累加器，只能由 Tensor Core 寻址，由此释放通用寄存器文件的操作数 residency 压力。

不同层级之间的数据移动逐代脱离 warp。Ampere 以前，加载 tile 是 synchronous 操作：每个线程发出自己的 global load，warp 等待全部 fragment 进入寄存器，再执行第二轮复制送入 shared memory；每个 tile 都消耗 warp lane 完成地址计算与等待。

Ampere 引入 `cp.async` ：每个线程可异步执行 HBM → SMEM copy，并完全绕过寄存器；warp 提交一组 in-flight copy，只在 consumer 需要数据时等待。Hopper 以 TMA 取代这套方式。TMA 是专用 DMA 引擎，一个线程提交 multidimensional tile 描述符，base address、leading 维度、swizzle，引擎负责全部地址计算并写入 shared memory，通过 `mbarrier` 发出完成信号。整个 warp 从 load issue 与 address math 中释放出来，kernel 只需排入描述符。

TMA 还支持集群级 multicast：一次 HBM read 可扇出到 thread block 集群内的每个 SM，把过去的 $N$ 次独立 load 合并为一次。Blackwell 再次扩展 TMA，支持直接加载到 TMEM，使 accumulator tile 无需经 SMEM staging 即可流入。每一代都让 warp 每个 tile 少承担一项工作。

### Warp specialisation

Hopper 时代的典型 programming idiom 是 warp specialisation。一个 block 内，一部分 warp 充当 producer，连续发出 TMA load；另一部分 warp 充当 consumer，对刚到达的 tile 发出 `wgmma` 。同步机制采用 shared memory 中的 `mbarrier` ，以及绑定 TMA completion 的 asynchronous transaction barrier，实现 warp granularity 的 producer/consumer handshake。

FlashAttention-3、CUTLASS ping-pong GEMM 与 Blackwell FA4 kernel 都采用同一套参考结构：TMA-driven producer 流水线通过 shared memory 与 TMEM 向 wgmma consumer 流水线供数，二者用 mbarrier handshake；Hopper 以后，thread block 集群把多个 SM 连接成一个 cooperative 计算单元，Blackwell two-SM MMA 可以自然叠加在这套结构上。

### 数值格式

FP32 是历史默认格式。Volta 带来 FP16、FP32 累加，以及使 FP16 可用于训练的 loss scaling。Ampere 加入 TF32，FP32 range、FP16 mantissa，可直接替换 FP32 matmul，以及 BF16 和 2:4 结构化稀疏，后者让 pruned 权重的 effective 吞吐量翻倍。

Hopper 引入 E4M3 与 E5M2 两种原生 FP8，并配合 Transformer Engine 逐层自动缩放激活值，使其保持在 FP8 动态范围内。Blackwell 再把精度减半到 FP4，并提供 microscaling MX 格式：一个 block 共享 exponent，恢复 FP4 损失的大部分精度；第二代 Transformer Engine 把 auto-scaling流水线转向 FP4。Rubin 第三代 Transformer Engine 加入 NVFP4，NVIDIA 收紧后的 FP4 variant，原生 FP6 与更激进的 sparsity。

芯片布局也成为 numerics 的一部分。B100、B200、B300 由两枚 reticle-limit die 构成，通过约 10 TB/s NV-HBI 链路拼接，软件看到的是一枚 logical GPU；封装上放置 8 个 HBM 栈。Rubin 延续 dual-die chiplet 路线，约 3360 亿枚 transistor，并配备 8 个 HBM4 栈。每一代通过精度减半、更加细粒度的 scaling scheme 恢复 accuracy，并在封装内键合更多芯片，换取约 2 倍每瓦吞吐量。

### 五项押注

1. **Programmability** ：负载持续变化，包括 attention variant 与新模型架构，因此每个 block 保持可编程，由开发者编写 CUDA。Specialised 单元也通过这一编程模型暴露。
2. **用 massive multithreading 隐藏延迟** ：延迟具有不可预测性且依赖数据，每个 SM 最多超额驻留 64 个 warp，硬件 warp 调度器每个周期选择一个 ready warp。
3. **Warp-wrapped matmul** ：矩阵单元提供绝大部分计算吞吐量，并隐藏在统一的 warp/线程 abstraction 后，通过 `mma.sync` → `wgmma` → `tcgen05.mma` 逐代演进。一枚 kernel 因而可以在一次 pass 中融合 matmul、softmax 与逐元素运算。
4. **Async 存储层次** ：保留 L2 缓存，把 SMEM 与 TMEM 暴露成具名 scratchpad，并叠加 async machinery，TMA 负责 bulk copy，TMEM 保存 matmul 累加器， `mbarrier` 负责 producer/consumer handshake。Programmable kernel 内部以软件流水线驱动整个 hierarchy。
5. **摊薄 SIMT 成本** ：warp 调度器、寄存器文件与 coherent cache 都占用本可用于 MAC 的 transistor。更大的 Tensor Core 把 SIMT machinery 成本摊到更大的 MAC 数量上；TMEM 等单元用部分通用性换取 MAC 密度。

### 扩展

Scale-up 会把多枚 GPU 连接成一个一致性内存域，也就是让它们共享统一地址空间。任意 GPU 都能通过 NVLink 以纳秒级延迟直接 load 或 store 另一枚 GPU 的 HBM，整个域使用一个地址空间，也无需显式传输。

Scale-out 再把多台服务器和多个数据中心机柜连接起来。数据通过显式 RDMA 跨域，延迟进入微秒级，各节点保有独立地址空间，一个集群可容纳数万枚芯片。

AI 基础设施同时使用两种方式。tensor parallelism 与 MoE expert 路由等 bandwidth-hungry 集合通信留在 scale-up 互连域；数据并行与流水线并行穿过 scale-out 互连网络。

### Scale-up

Scale-up 栈由 NVLink 与 NVSwitch 组成。NVLink 在 GPU 之间实现 cache-coherent 互连网络，一枚 GPU 的 load/store 可以指向另一枚 GPU 的 HBM，硬件负责 address translation 与 coherence。NVLink 是 point-to-point 链路，每条链路连接两枚芯片。NVSwitch 是所有 GPU 都会连接的专用 crossbar 芯片，负责路由流量，使任意 GPU 能够同时以完整 NVLink 带宽与其他 GPU 通信，形成 non-blocking all-to-all。

二者共同构成 HGX 8-GPU 主板：八个 H100 SXM 模块通过 PCIe Gen5 连接 AMD EPYC 或 Intel Xeon x86 主机。Hopper 也提供 Grace 配对形态。GH200 Grace Hopper Superchip 用 900 GB/s NVLink-C2C 把一枚 Grace ARM CPU 与一枚 H100 绑定，消除 PCIe 主机与设备之间的 hop；模块进一步组成 GH200 NVL2 pair 与机柜级 GH200 NVL32。

Blackwell 把 CPU-GPU 配对变成默认形态。GB200 模块通过 NVLink-C2C 把一枚 Grace 与两枚 B200 融合；NVL72 将 36 个 GB200 连接成一个液冷 scale-up 互连域，包括 72 枚 GPU、36 枚 Grace CPU、13.5 TB HBM 与 17 TB LPDDR5X，呈现为平坦的一致性地址空间。

Rubin 分两步扩展。2026 年 NVL144 继续使用 Oberon-class 机柜，包含 72 个 Rubin 封装；按照 NVIDIA 新的 die counting 方式，它被标为 144 枚 GPU，HBM4 与 NVLink 6 让每个封装的带宽翻倍。2027 年 Rubin Ultra 继续扩大机柜级系统：NVL576 在新的 Kyber 机柜中放入 144 个 four-die Rubin Ultra 封装，共 576 枚 GPU die，组成一个一致性互连域。

*图 3　NVL72：72 枚 Blackwell GPU 位于一排 NVSwitch ASIC 下方，构成 non-blocking crossbar；任意 GPU 都能以完整 NVLink bandwidth 访问其他 GPU 的 HBM；passive copper 背板上约有 5,184 条 blind-mated cable，all-to-all bandwidth 约 130 TB/s，相比光学方案节省约 20 kW transceiver power*

这套密度由 passive copper 支撑。NVL72 NVLink 互连网络通过背板 blind-mate 5,184 条 cable，每机柜约 2 mile；SerDes 直接位于 GPU 与交换 ASIC，省去 cable 内 retimer，为 72 枚 GPU 提供约 130 TB/s all-to-all 带宽。NVIDIA 估计，若每条链路改用 pluggable transceiver，光学方案每机柜会多消耗约 20 kW。

在短于 2 m 的距离上，copper 在功耗、成本与每美元 signal integrity 上具有优势，将整个机柜视为一枚 GPU 因而具备经济可行性。更长距离需要光链路。NVL144 沿用 Oberon，封装数量仍为 72，cable 无需增长，只需在 Gen 6 SerDes 上提高传输速度。Rubin Ultra NVL576 通过改变机柜形态继续使用 copper：Kyber 高度约为 Oberon 两倍，把 576 枚 GPU die 装入同一 enclosure；即使包含 144 个 four-die 封装和数万条 cable，每条 NVLink 路径仍保持在 passive-copper reach 内。

### Scale-out

Scale-out 栈源于 NVIDIA 对 Mellanox 的收购。Scale-out 互连网络采用分离地址空间，数据只能由软件发起显式 RDMA 跨节点传输，通常封装在 NCCL all-reduce、all-to-all 等集合通信中。参考集群是 DGX SuperPOD：八个 NVL72 机柜通过 Quantum-X800 InfiniBand 连接，让 576 枚 Blackwell GPU 置于一个调度器下；更大的训练集群继续平铺多个 SuperPOD。

2026 年 Rubin SuperPOD 沿用八机柜结构并换用 NVL144，每个 SuperPOD 从 576 枚扩到 1,152 枚 GPU。2027 年 Rubin Ultra 把规模提高一个数量级：每个 Kyber 机柜包含 576 枚 GPU die，机柜之间通过 Quantum-X Photonics CPO 连接，一个调度器管理数千枚 GPU。

![](https://pic1.zhimg.com/v2-09c19443b32154d1ed69bcab63cc294c_r.jpg)
*图 4　DGX SuperPOD：八个 NVL72 机柜、共 576 枚 GPU 连接到 Quantum-X800 InfiniBand 骨干交换层；每枚 GPU 通过 800 Gbps ConnectX-8 NIC scale-out；跨机柜 hop 使用 OSFP-RHS pluggable optical transceiver，latency 从机柜内 NVLink 的纳秒级进入微秒级*

每枚 GPU 都通过自己的 ConnectX NIC 接入互连网络。Blackwell 每枚 GPU 使用 800 Gbps ConnectX-8，带宽比 NVLink 低一个数量级，延迟也从纳秒级升至微秒级。Rubin 改用每枚 GPU 1.6 Tbps 的 ConnectX-9；机柜内 scale-up 互连域从 72 枚扩至 576 枚 GPU 时，每枚 GPU 的 scale-out 带宽也翻倍。每个 NIC 旁还有 BlueField DPU，通过 ARM 核心与加速器从主机 CPU 卸载存储、网络和安全任务。偏好 Ethernet 的客户可使用为 AI 流量优化的 lossless-Ethernet 方案 Spectrum-X。

Copper 与光链路的分界发生在机柜边界。NVL72 内部骨干交换层使用 copper；链路以 800 Gbps 跨机柜时转为光链路。200 G/lane 条件下，passive copper DAC reach 约 1.5–2 m，无法覆盖跨机柜距离，因此当前 SuperPOD 骨干交换层使用 OSFP-RHS pluggable transceiver，每个模块自带 laser、modulator、photodetector 与 DSP。连接数千枚 GPU 的 SuperPOD 骨干交换层需要数万枚 pluggable，仅 transceiver laser 就消耗数十 kW。

Rubin 把光链路层收进交换 ASIC。Quantum-X Photonics（InfiniBand）与 Spectrum-X Photonics（Ethernet）以共封装光学取代 pluggable，通过 TSMC COUPE 把 laser、modulator 与 photodetector 键合到交换机封装。NVIDIA 宣称 laser 数量约减少 4 倍，链路功耗约降至 OSFP pluggable 方案的 1/3.5。GPU two-die 封装与 HBM stacking 使用的 chiplet 逻辑由此延伸到网络层，在一个 substrate 上垂直整合计算、内存与 photonics。

NVLink Fusion 进一步开放 scale-up 互连网络，第三方 CPU 与 XPU 可以加入 NVLink 互连域。Hyperscaler 可以围绕 NVIDIA 互连技术构建 semi-custom 机柜，并复用现成的一致性互连网络。

### 软件

CUDA 是大规模并行处理器的自然编程模型。开发者编写 kernel，每个线程执行一次的代码，并把它 launch 到由 block 与 warp 组织的数千个线程上；开发者决定共享哪些数据、何时同步，以及每个线程处理问题的哪一部分。这一 abstraction 在 18 年间基本保持稳定，2007 年以来编写的 CUDA kernel 仍能在 Blackwell 上编译运行。

这份连续性同时形成 moat 与 constraint。每一代新硬件，Tensor Core、TMA、TMEM，都进入同一 kernel-and-warp 模型，通过 PTX 与 SASS intrinsic 暴露，例如 `mma.sync` 、 `wgmma.mma_async` 。大量既有代码依赖 SM，架构演进必须维持兼容；相应地，每一笔 CUDA 软件投资都会跨代累积。

PTX 之上是一套建设二十年的软件栈：cuBLAS 与 cuDNN 提供数学和 DNN primitive；CUTLASS 用 templated C++ 编码数十年的 GEMM 经验；TensorRT-LLM 提供 paged attention、in-flight batching 与 speculative decoding；PyTorch、Triton 与 JAX 提供框架 binding。

FlashAttention 是现代 AI 最重要的 algorithmic rewrite 之一。它对 attention 做 tiling，避免 materialise $O(N^2)$ 矩阵。FA1 到 FA4 四代分别为最新 NVIDIA 芯片手工优化：FA3 面向 Hopper async 流水线，FA4 面向 Blackwell；其他硬件的 port 通常晚数月或数年。

这套栈的大部分代码来自 NVIDIA 之外的开发者。真正的 moat 由二十年的 third-party kernel、库、tooling，以及数百万掌握 API 的开发者共同构成。

NVIDIA 在交付芯片的同时，也会提供工程支持。数十名 NVIDIA engineer 长期驻场 frontier lab 和 hyperscaler team，为新的模型架构编写 kernel，并针对每代芯片调优。因此，实验室准备训练的新模型通常能更快地在 NVIDIA 平台上获得良好性能。迁移到其他平台还需要工程团队重新建立整套技术认知，也会失去这些驻场工程师的支持。

## Google TPU

TPU 是矩阵乘法机器。它专注于一个 primitive：在大型脉动阵列上执行稠密矩阵乘法，并由 XLA 编译器提前规划每个周期和每一个字节的内存。硬件调度器、缓存与线程/warp 的面积全部转为计算。每一代 TPU 都会扩大 TPU 集群（pod）。一个 pod 通常跨越多台机柜，数千枚芯片通过 ICI 互连成一个整体。TPU 服务 Google 的 search、translation、recommendation 与 Gemini 负载，追求更高的每瓦效率。

### 架构

一枚 TPU 是被少量供数芯片包围的 matmul 引擎。Compute 单元是 TensorCore：v2 以后的旗舰芯片每个封装配置两个，v4i、v5e、v6e 等效率-tuned 芯片配置一个。每个 TensorCore 都包含五类部件：执行矩阵 math 的一个或多个 MXU、执行逐元素计算的 VPU、负责整体控制的 Scalar Unit、执行跨 lane 归约的 XLU，以及连接其后的 Transpose/Permute Unit；累加器 queue 负责向 MXU 送入和排出数据。

从 v4 开始，芯片还在 TensorCore 外配置独立 SparseCore 数据流引擎：v4、v5p 与 Ironwood 每枚四个，Trillium 每枚两个，用于承接脉动阵列形状难以匹配的 embedding lookup。所有 block 位于同一个 VLIW issue plane 上，由 Core Sequencer 驱动；每个周期，它填满一个 322-bit bundle 的八个 functional slot。Compiler 承担调度器工作，节省下来的指令缓存、warp 调度器、乱序执行引擎与分支预测器面积用于放置更多 MAC。

### TensorCore

MXU 就是脉动阵列。v1 配置一个 256×256 INT8 推理阵列。v2 首次支持训练，引入 128×128 单元，执行 BF16 乘法与 FP32 累加；从 v4 起，INT8 以相同吞吐量回到 MXU。每个 TensorCore 的 MXU 数量由 v2 的 1 个增至 v3 的 2 个，再增至 v4、v5e、v5p 的 4 个。Trillium 恢复 256×256 形状，每个阵列每周期有 65,536 个乘加单元；Ironwood、8t、8i 都沿用这一形状。

计算 $C=A\times B$ 时，矩阵 B 预先把每个权重装入一个单元，形成weight-stationary 数据流。激活值从左缘进入，每周期向右传播一列，在每个单元与驻留权重相乘，部分和向下流入底部累加器 queue。数据进入阵列后不再访问内存：每个权重被所有经过的激活值复用，每个激活值在一行内复用 128 或 256 次。数据复用由硬件布线固化。

一次乘法只消耗数 pJ，内存读写的单次 energy 成本可高出 100–1000 倍，脉动阵列从结构上消除了大量访问。相应代价是 underfill：在 256×256 阵列上运行 128×128 matmul 会闲置 75% 芯片。XLA 会把维度 tile、pad、调度成 128 的倍数，v6e 以后是 256 的倍数；模型代码也按这些 quantum 编写。

VPU 负责辅助计算，同时也是更独特的微架构对象：每枚 TPU 都是 2D 向量机器。VPU 寄存器文件保存 2D VREG。v4/v5p 的形状为 `(8, 128)` ：宽 128 lane、深 8 sublane，每核心有 32 个 v4 寄存器或 64 个 v5p 寄存器，每个 `(lane, sublane)` 配置 4 个独立浮点 ALU。Lane axis 与脉动阵列输入宽度对齐，因此 Trillium 与 Ironwood 随 MXU 扩宽后，lane count 很可能也增至 256；Google 尚未公布 v5p 之后的 VPU 维度。

Sublane 轴让 VPU 以每 X 个 clock 一次 matmul 的速度向 MXU 数据流 tile，X 就是 sublane 维度。现代 TPU 程序的主要加速来自 VPU/MXU overlap：MXU 执行 matmul 的同一批周期，VPU 同时处理量化、layernorm、softmax、激活值与 bias-add。2D 向量 ISA 中较难处理的跨 lane 归约交给 XLU，它速度较慢、成本较高，是已知编译器 hot spot。与 2D 形状错位的布局变换交给专用 Transpose/Permute Unit，省去一次内存 round-trip。

Scalar Unit 体积最小，影响极大。它是一枚单线程、双发射的整数 ALU，拥有 32 个 32-bit 寄存器与 4 KiB SMEM 控制状态，并配有保存程序的 Imem。整枚芯片只有它执行指令取指。每个周期，它取出 322-bit VLIW bundle，在本地执行两个 scalar slot，地址计算、循环计数器、分支、sync register 检查，再把六个 slot 分派到其余部分：两个向量 ALU slot 发给 VPU，两个向量 load/store slot 执行 HBM↔VMEM DMA，两个矩阵 slot 执行 MXU queue push/pop。

Block 间同步完全显式：sync flag 记录 MXU 与 VPU 流水线的繁忙状态，编译器插入 barrier check 来表达依赖。每个周期都由 Scalar Unit 决定八项操作，TensorCore 的其余部分由此呈现固定功能数据流特征；错误决策只能由编译器调度修正。

### 存储

片上存储层次延续计算侧的思想，各层全部由软件管理。片外 HBM 容量为：v2/v5e 16 GB，v3/v4/v6e 32 GB，v5p 95 GB，Ironwood 192 GB，v8 代际 216–288 GB。片上由可显式寻址的 scratchpad 分层组成。

距离计算最近的是 VMEM，这块向量 scratchpad 同时向 VPU 与 MXU 输入 queue 供数：v4 为 32 MiB，v5e 为 128 MiB，面向推理的 v8i 扩到 384 MiB，目标是把完整 KV Cache 放在片上。VMEM 之上是 v4 引入的 128 MiB CMEM，一块位于 HBM 与 VMEM 之间、速度较低且容量较大的 SRAM staging area，用来容纳融合算子的中间结果。Scalar Unit 拥有独立 SMEM，v4 约 10 MiB 控制状态，以及很小的 scalar 寄存器文件。

程序中每个张量都在编译期固定到某一层。XLA buffer assignment pass 负责跨层安排 DMA，使数据恰好在消费它的周期前到达。硬件不负责 prefetch、eviction 与 coherence；优秀调度可以让阵列持续运行，错误调度会直接形成 stall。

### SparseCore

SparseCore 是 TensorCore 之外打破 systolic 形态的单元，首次出现于 v4。推荐模型与排序模型大量执行 embedding lookup，也就是对超大 table 中数十亿 index 的访问；它们的 pattern 是 irregular、indirect、all-to-all，与稠密 matmul 完全相反，无法有效填充 256×256 脉动阵列。

SparseCore 是数据流处理器，含 16 个计算 tile 与专用 SPMEM scratchpad，位于 TensorCore 旁，负责 scatter、gather、segmented-reduce primitive，以及 sharded embedding table 产生的数据依赖的 all-to-all 流量。它占 die 面积与功耗约 5%，可让 embedding-heavy 模型加速 5–7 倍。

v4 与 v5p 每枚芯片有 4 个 SparseCore，Trillium 减为 2 个，Ironwood 恢复 4 个，在 dual-die 布局上每 chiplet 2 个。v8i Zebrafish 推理芯片用 I/O chiplet 上的 CAE（Collectives Acceleration Engine）承接自回归 decode 中的集合通信归约。同一设计原则是：为脉动阵列难以匹配的负载划出小型专用加速器。

### 数值格式与 I/O

TPU v1 使用 INT8 推理。v2 选择 BF16 作为标准训练格式，它拥有与 FP32 相同的动态范围、占用一半内存，并简化 loss scaling。v4 重新加入原生 INT8。Ironwood 支持 E4M3 与 E5M2 原生 FP8，在相同面积下吞吐量约为 BF16 的 2 倍。v8 加入原生 FP4，并在 MXU 内完成 block-scale multiplication，消除 Ironwood 仍由 VPU 承担的反量化开销。

现代 TensorCore 均在硬件中支持随机舍入：低位尾数根据概率决定舍入方向，长时间训练中的低精度 accumulation 因而保持期望值，这是 BF16/FP8 缩小与 FP32 精度差距的关键细节之一。

芯片边界上是 ICI port 与用于 scale-out 的 DCN NIC。v2、v3、v5e、v6e 这类 2D-torus 芯片有 4 个 ICI port，v4、v5p、v7、8t 这类 3D-torus 旗舰有 6 个。对芯片而言，ICI port 就像 Core Sequencer 可在 VLIW bundle 内寻址的另一组 DMA 引擎：remote tensor send 与 VMEM-to-HBM 传输属于同一指令 class，编译器把集合通信与计算、local memory 一起纳入统一调度。

### 五项押注

1. **脉动阵列** ：matmul 主导负载，因此把芯片投入脉动阵列。
2. **Software scratchpad** ：计算便宜，内存昂贵；在阵列布线内复用数据，并以软件管理的 scratchpad 组织内存。
3. **Compiler 调度** ：负载可以静态预测，把调度移入编译器；使用 VLIW issue，省去 speculation、out-of-order 与动态调度器。
4. **MAC-only 硬件** ：功耗优先级高于 peak，缓存 tag、分支预测器与重排序缓冲区占用的 transistor 转为 MAC 资源。
5. **Dedicated off-array engine** ：embedding 与集合通信等真实负载难以映射到稠密 matmul 阵列，因而划出 SparseCore、CAE 等小型专用引擎。

### 扩展

TPU 的 scale-up 采用消息传递。ICI 将全部多芯片操作表达为 XLA 编译的显式集合通信，省去 remote-load 语义、缓存一致性与 crossbar。scale-up 互连域由 torus 连接：芯片直接连接相邻芯片，并在边界执行环回；机柜边界再由光路交换机拼接。

Scale-up 通过 ICI 把芯片直接连成 2D 或 3D torus。XLA 生成 SPMD 集合通信，精确编排数千枚 TPU 执行同一个程序，在低延迟下提供极高对分带宽。Scale-out 通过数据中心互连网络连接多个 TPU 集群（pod），以较低每枚芯片带宽容纳更多芯片。当前 v8t 以后的东西向 TPU 流量由 Virgo 承担，南北向流量由 Jupiter 承担；Multislice 与 Pathways 跨 pod 编排 SPMD。

### Scale-up

ICI 链路直接从 TPU die 引出。一个液冷机柜内放置由 64 枚芯片组成的计算单元（cube），内部排列为 4×4×4，相邻芯片使用直连铜缆，cube 之间使用光链路。每枚芯片总 ICI 带宽从 v2 的约 250 GB/s 增至 Ironwood 的 1.2 TB/s 双向，v8t 再翻倍。效率型 v2、v3、v5e、v6e 使用 2D torus，旗舰 v4、v5p、v7、v8t 使用 3D torus。

Palomar OCS 是这套系统中特有的部件：位于这些 64 芯片计算单元（cube）之间的 3D-MEMS 光路交换机。微型 mirror 通过物理旋转，把任意输入 fibre 映射到任意输出。v4 superpod 使用 48 个 Palomar 交换机，把 64 个计算单元（cube），共 4,096 枚芯片连接成一个 3D torus；v5p 与 Ironwood 继续扩大同一方案。

Reconfiguration 需要 millisecond 级时间，适合电路交换场景：作业开始时选择拓扑，运行一周，再为下一项负载重新配置。一个部件由此同时解决三个问题：按负载重配置拓扑，twisted torus 可将对分带宽最多提高 70%；按需 sub-pod slicing；容错，芯片失效时，OCS 通过光链路换入 spare cube，run 可在原 ICI 互连域中继续。

*图 7　TPU Ironwood superpod：左侧为一个 4×4×4、共 64 枚芯片的 cube，nearest neighbour 通过 direct-attach copper 组成 3D torus，各面执行 edge wrap；右侧为 144 个 cube，通过可按 workload 重配 topology 的 3D-MEMS 光路交换机 Palomar OCS 连接成一个 ICI 互连域*

Superpod 成为 scale-up 单元，其角色对应 NVL72，规模大两个数量级。v4 有 4,096 枚芯片，v5p 有 8,960 枚；Ironwood v7 把 9,216 枚芯片组织成 144 个 64 芯片计算单元（cube），在一个 ICI 互连域中提供 1.77 PB HBM、约 68 PB/s HBM 带宽与 42.5 ExaFLOPS FP8。

TPU 8t Sunfish 扩至 9,600 枚芯片、2 PB HBM、约 62 PB/s HBM 带宽与 121 ExaFLOPS FP4。TPU 8i Zebrafish 包含 1,024 枚芯片、约 295 TB HBM、8.8 PB/s HBM 带宽与约 10 ExaFLOPS FP4。

8i 使用新的分层高基数拓扑 Boardfly：4 芯片 ring → 8-board group → 最多 36 个由 OCS 连接的 group，将 all-to-all 延迟减半。这套设计面向 MoE 推理。3D torus 适合 nearest-neighbour 集合通信，ring all-reduce 可以每个周期使用所有链路；MoE expert 路由采用 all-to-all，每枚芯片都向其他芯片发送不同 fragment，round-trip 延迟取决于最长 hop pair。1,024 芯片 3D torus 的 diameter 是 16 hop，Boardfly 的 ring → group → OCS hierarchy 把它压缩到 7 hop。

### Scale-out

TPU v7 及以前由 Jupiter 单一互连网络承担 scale-out。2022 年起，Jupiter 骨干交换层通过 Apollo OCS 实现全光网络。Apollo 与 Palomar 同属 3D-MEMS family，只是规模覆盖整座机房。Google 在机柜到数据中心骨干交换层的每一层都使用光路交换，这形成了其独特架构特征。当前每座机房的 Jupiter 对分带宽为 13 Pb/s。

TPU 8t 把 scale-out 拆成两套互连网络。东西向 TPU-to-TPU 流量转移到专用加速器互连网络 Virgo；Jupiter 保留南北向角色，负责存储访问、通用计算和跨站点扩展。Virgo 使用高基数交换机构成扁平的两层non-blocking拓扑，任意 TPU 之间最多经过两个交换机。

一个 Virgo 集群连接超过 134,000 枚 TPU 8t，对分带宽达 47 Pb/s；相比上一代 DCN，每枚芯片带宽提高到 4 倍，空载延迟降低 40%。Multi-planar fault isolation 和 sub-millisecond telemetry 让调度器能在慢节点拖累训练 step 前将其终止。Scale-up、东西向 scale-out 和前端网络可以分别演进。

![](https://pic2.zhimg.com/v2-563c979c6ffeee5b480d2d5e1e7f714d_r.jpg)
*图 8　TPU 8t scale-out：东西向 TPU traffic 通过 Virgo，一套由 high-radix switch 组成的 flat two-layer non-blocking fabric，使任意 TPU 间最多经过两个 switch；系统连接超过 134,000 枚 TPU，对分带宽为 47 Pb/s；storage、通用计算和跨站点等南北向流量继续走 Jupiter，后者自 2022 年起通过 Apollo OCS 实现 all-optical 骨干交换层*

Ironwood 每枚芯片 scale-out 带宽约 100 Gbps，v8t 为其 4 倍，仍比每枚芯片 ICI 低两个数量级。这一差距决定 partitioning：张量并行与 MoE expert 路由保留在 ICI 内，数据并行与流水线并行穿过 scale-out 互连网络。

Google Multislice 集成进 XLA，让一个 SPMD 程序跨越不同 TPU 集群（pod）中的多个计算切片（slice）。编译器生成分层集合通信：slice 内执行 ring all-reduce，slice 间执行上层 reduce。大部分工作留在快速 ICI 互连的 slice 内，只有跨 slice 的剩余数据需要经过较慢的 scale-out 网络。

Pathways 位于其上。NCCL、Slurm、Megatron 式调度器往往由多个控制器驱动 SPMD，Pathways 则由一个客户端驱动完整作业，并把多个通过 DCN 互联的 TPU 集群虚拟成统一资源。它负责 gang scheduling、elastic training 和跨区域编排。Slice 失效时，OCS 重塑拓扑，Pathways 在新拓扑上从最近 checkpoint 恢复。Gemini Ultra 是第一款跨多个数据中心训练的前沿模型，Pathways 将这些数据中心组织成一个 synchronous SPMD 作业。

这套哲学可以表述为：编译器是调度器，torus 是拓扑，光交换机是从机柜到数据中心每一层通用的 reconfigurable substrate。

### 软件

TPU 栈由编译器驱动。开发者用 JAX 编写数值程序，XLA 负责其下全部工作：选择算子融合，决定每个张量的 residence 与在 2D 向量寄存器上的布局，安排 HBM → VMEM DMA 发出时机，调度 322-bit VLIW bundle，并把程序 shard 到数千枚芯片。低效调度只能通过编译器改进，编译器本身就是系统。XLA 可以在缺少手工调优时接近理论上限，进一步缩小剩余 gap 需要更深入的编译器优化。

编译路径为 JAX → JAXpr → StableHLO → HLO → LLO → VLIW bundle。JAX 在 `jit` 下把 Python 函数 trace 成带类型的函数式 IR JAXpr，再降低为 StableHLO。StableHLO 是 OpenXLA 标准化、带版本的约 100 个 statically-shaped primitive op-set，各种前端都可生成。

XLA 把 StableHLO 作为 HLO 接收并执行一系列 pass：

1. **算子融合** ：把逐点、归约与 matmul 合成一个 kernel，intermediate 无需写回 HBM。
2. **布局分配** ：决定每个张量的 2D tiling，使其直接送入 MXU。寄存器与 MXU 输入都是 2D，这项工作比 1D SIMD 机器更复杂。
3. **缓冲区分配** ：把每个张量固定到 VMEM、CMEM 或 HBM，并预先计算 overlap window。
4. **SPMD partitioning** ：完成跨 device partition。
5. **VLIW 调度** ：填满每个 bundle 的八个 slot。

随后 HLO 降低到 TPU-specific IR LLO（Low-Level Optimizer），LLO 生成最终 VLIW 指令流。高质量程序在每个周期的同一 bundle 中重叠 MXU 脉动阵列计算、VPU 逐元素计算与 HBM↔VMEM DMA。

多芯片执行采用 SPMD：一个程序、sharded data、分层集合通信，由 GSPMD 生成。MLIR-native 后继方案 Shardy 正在替代 GSPMD，并于 2026 年初成为默认。用户只需在少量关键张量上用 Mesh + PartitionSpec declarative annotation 表达 sharding；编译器会把 sharding 传播到 graph 其余部分，并在布局变化处插入 all-reduce、all-gather 与 reduce-scatter。

当编译器选择了低效集合通信， `shard_map` 允许用户进入 manual SPMD：编写带显式 local shape 与显式集合通信的 per-device code，同时保持在 `jit` 内组合。这样可以手工 partition 一个 kernel，其余部分继续 auto-partition。PyTorch FSDP 与 DeepSpeed 在运行时中包裹模型，并在模块边界发出集合通信；GSPMD/Shardy 把整个 graph partition 视为编译问题。

Pallas 是 escape hatch，也是 JAX 中编写 kernel 的语言，其角色大致对应 GPU 上的 Triton。Pallas kernel 使用 JAX 风格 Python，经基于 MLIR 的 TPU backend Mosaic 降低到 LLO，再作为自定义算子嵌回 HLO。Novel attention variant、fused MoE dispatch，以及需要手动 VMEM tiling 与 DMA 调度的负载，往往要求 FlashAttention 级优化，性能来自调度，代数表达保持相同，Pallas 提供这种控制。

Pallas:Mosaic-GPU 以同一前端支持 H100/Blackwell，让 kernel 开发者可以一次编写并降低到两类 substrate。其上的库层全部采用 JAX：Flax NNX 提供模块，Optax 提供 optimizer，Orbax 提供 asynchronous distributed checkpointing，Grain 提供输入流水线，Tunix 提供 post-training/RL，Qwix 提供量化。Google 参考训练栈包括面向 LLM 与 DeepSeek-V3-class MoE 的 MaxText，以及面向 Flux、Wan 2.1 的 MaxDiffusion，顶层均使用纯 JAX。Pathways 位于下层，通过 pathwaysutils 暴露，一个 Python 客户端能驱动跨数千枚芯片与多个 TPU 集群（pod）计算岛的作业，同时保留 JAX 编程模型。

PyTorch 路径已经可用，成熟度仍落后于 JAX。torch_xla 使用 LazyTensor：每个 PyTorch op 记录到 HLO graph，在下一次 barrier 时编译，compiled artifact 按 graph-shape hash 缓存。PyTorch/XLA 2.x 加入 GSPMD-style sharding annotation、经 XLA backend 的 `torch.compile` integration、JAX bridge，以及 PyTorch/XLA 2.7 的 C++11-ABI build 与显著更快的 tracing。

JAX primitive 与 StableHLO 的映射更直接，复杂 parallelism strategy 的覆盖也更完整。因此 vLLM TPU，由 Cloud Next 2025 公布的 tpu-inference 插件驱动，无论模型用 JAX 还是 PyTorch 定义，都会统一经 JAX → XLA 路径降低。2026 年 4 月公布的 TorchTPU 提供原生 PyTorch 体验，包括 eager mode、 `torch.distributed` 与基于 XLA 的 `torch.compile` ，计划接替 torch_xla。

相比 CUDA，TPU 生态更集中。Framework 以下的 XLA、JAX、Flax、Optax、Pallas、MaxText、Pathways、Shardy、Mosaic 几乎都由 Google 自己开源，并与芯片同步演进。第三方 kernel 的积累规模较小，特殊负载上的 moat 较薄；与 Gemini 相似的负载上，软硬件共设计更深。

Ironwood v7 使用软硬件协同设计的 AI 栈来概括这一思路：芯片、ICI 互连网络、OCS、XLA、Pathways、Pallas、MaxText、vLLM 一起作为产品发布；v8t/v8i 继续使用统一 tpu-inference lowering 路径。Triton 与 `torch.compile` 也在推动 NVIDIA 的 kernel-driven 路线向编译器驱动方向靠近。两个哲学极点依然清晰：TPU 以编译器作为唯一关键接口，GPU 则同时保留多种接口。

### 计算

CU 内，SIMD 与 Matrix Core 并行工作。四个 SIMD 负责激活值、归一化、residual、地址计算等逐元素运算；Matrix Core 负责 matmul。分工对应 NVIDIA 的 CUDA Core / Tensor Core，矩阵 abstraction 的演进路径差异很大。

NVIDIA Tensor Core 的 issuer 从 Volta 32-线程 warp，演进到 Hopper 128-线程 warp group，再到 Blackwell single 线程与可选 two-SM 集群。AMD Matrix Core 始终保持 wavefront scope。从 2020 年 MI100 到 2025 年 MI355X，每代 MFMA 都由一个 wave64 发出一条矩阵操作 `V_MFMA_*` ，四个 SIMD 协同驱动，操作数来自 wavefront 寄存器文件：A、B 来自 VGPR，C、D 通常来自专用 AGPR。Instruction 吞吐量与格式 set 持续升级，issuer 与 scope 保持不变。CDNA 4 在 feeder 侧加入专用 MFMA transpose-load from LDS，把操作数以 Matrix Core 所需布局送入；矩阵操作继续由 wave 发出。

Throughput 直接反映格式演进。CDNA 1 在 2020 年为 FP32 / FP16 / BF16 / INT8 分别提供每 CU 每周期 256 / 1024 / 512 / 1024 FLOPs，与 A100 同期支持原生 BF16。CDNA 2 把 FP64 路径翻倍为 full-rate 矩阵，每 CU 每周期 256 FLOPs，这项 AMD 特有押注让 MI250X 进入 Frontier。

CDNA 3 的 E4M3、E5M2 FP8 达到每 CU 每周期 4,096 FLOPs，与 H100 相当，同时加入 2:4 结构化稀疏，以及类似 TF32 的路径：截断 mantissa，以 FP64-matrix rate 执行 FP32 matmul。CDNA 4 的 FP4 再翻倍至 16,384 FLOPs，加入 FP6、OCP MX block scaling与一条 MFMA 内可混合的 A/B 精度，例如 FP8 × FP4。与此同时，per-CU FP64 吞吐量减半，AMD 第一次用 HPC 密度换取 AI 密度。

Wavefront scope 带来两项成本。第一是 divergence：半空 wave64 浪费 32 条 lane，半空 warp32 浪费 16 条，irregular 负载影响更明显。第二是 overlap：NVIDIA 描述符驱动的 asynchronous matmul 发出后立即执行，issuing 线程可以继续，warp 能在上一项 matmul 在途时完成 softmax、mask 或预加载下一个 tile。AMD 发出 wavefront-collective MFMA 的 wave 在等待期间无法同时执行有效向量 work。系统可以让不同 wavefront overlap，但需要软件显式安排 wavefront barrier，也会占用更多 wave slot 与寄存器。

影响程度取决于负载。Pure 稠密 GEMM 在 matmul 期间没有额外工作，两类引擎都可饱和，async 收益较小；AMD 因而长期领先 exascale HPC，Frontier 使用 MI250X，El Capitan 使用 MI300A。Transformer attention 需要把 matmul 与 softmax、mask、KV Cache read 交错，async overlap 正是 FlashAttention-3、FA4 的结构，AMD 需要手工重建流水线。MoE dispatch、paged attention 与 speculative decode 同样包含希望与 matmul 并行的 address-irregular work。

### 存储

AMD 的通用内存层级较少，同时拥有 NVIDIA 架构中缺少的大型缓存。从 CU 向外依次是：64 KB、32-bank 软件管理的 LDS scratchpad；early CDNA 16 KB、MI300X 起 32 KB 的向量 L1；每个 XCD 数 MB L2。不同 XCD 的 L2 之间不 coherent，coherence 在更高一层完成。

这一层是 Infinity Cache：MI300X 为 256 MB，分布在四个 IOD 上，16-way set-associative，实测约 12 TB/s，超过 MI300X 5.3 TB/s HBM3 的两倍。Infinity Cache 最初用于 RDNA gaming GPU，以弥补较窄 GDDR bus；CDNA 3 把它用于 AI，attention KV reuse 与权重 reuse 很适合大型 LLC。NVIDIA 选择提高 HBM 带宽，B200 为 8 TB/s，Rubin 继续随 HBM4 增长，AMD 选择大型缓存。

HBM 容量按 MI100 / MI210 / MI250X / MI300X / MI325X / MI350X 顺序从 32 → 64 → 128 → 192 → 256 → 288 GB 增长。2021 年以来每代都达到或超过同期 NVIDIA 旗舰。其判断是推理负载越来越受容量约束，内存更多的芯片会占据优势。

### 数值格式

数值格式同样沿 FP32 → FP16 → FP8 → FP4 逐次减半，并用更细粒度的 scaling恢复 accuracy。AMD 特有轴线是 openness。CDNA 4 FP4 与 FP6 使用 OCP MX block-scale multiplication，与 Blackwell MXFP4、TPU v8 MXU 使用同类数值格式，由 AMD、NVIDIA、Intel、Meta、Microsoft、Qualcomm、ARM 共同参与的 open consortium 制定。MI355X、B200 与 TPU v8 使用一致格式。

CDNA 4 的分界标志是 per-CU FP64 吞吐量减半。MI300X 同时服务训练、HPC、推理，MI355X 以 AI 为主。驱动 Frontier 的 full-rate FP64 矩阵继续保留在面向 HPC 的产品线上。

### Chiplet

封装方式让 CDNA 呈现出独特形态。CDNA 1 MI100 是 monolithic 7 nm。CDNA 2 MI250X 是 AMD 第一款多芯片 GPU：两个 Aldebaran GCD 并排放在 2.5D EFB organic substrate 上，以四条封装内 Infinity Fabric 链路提供 400 GB/s 总；软件将其识别为两枚独立 GPU。

CDNA 3 做出关键跃迁。八个 TSMC N5、约 115 mm² 的 XCD，通过 TSMC SoIC 3D hybrid bonding，sub-micron-pitch TSV，无 microbump，堆叠到下方四个 TSMC N6 IOD。IOD 承载 Infinity Cache、HBM3 PHY、Infinity Fabric 链路与 PCIe Gen 5；每个 IOD 上方有两个 XCD，旁边有两个 HBM 栈。四个 IOD 通过 4.8 TB/s 对分带宽的 Infinity Fabric AP 连接，1,530 亿 transistor 封装对 kernel 呈现为一枚 GPU，缓存与地址空间在 IOD 层统一。

NVIDIA 到 H100 仍使用 monolithic die，B200 才通过 2.5D CoWoS-L 转向两枚 reticle-limit die。AMD 提前一代进入 3D stacking，单 die 面积也更小，两家在 packaging frontier 上选择了不同实现。

MI300A APU 进一步推进这项押注：把八个 XCD 中的两个替换成三个 Zen 4 CCD，保留 HBM、Infinity Cache 与 IOD，让 CPU 和 GPU 共享 HBM3 backing 的同一物理地址空间，并由硬件保持 coherence。Host-device copy、pinned 内存与 PCIe 数据路径都被消除，Zen 4 核心与 CDNA 3 XCD 读取同一批 page。Grace-Hopper 通过 NVLink-C2C bridge 连接两个封装，MI300A 集成在一个封装内。El Capitan 部署 11,039 个节点，每个节点配置 4× MI300A，验证了这套设计。

CDNA 4 MI355X 继续把八个 XCD 通过 SoIC 通过 3D stacking 连接到 base die。XCD 转为 TSMC N3P，每个有 32 个 active CU，共 256 个；MI300X 为 304 个。减少的 CU 面积用于更大 Matrix Core 与 160 KB LDS。MI300X 的四个 IOD 合并为两个宽度翻倍的 TSMC N6 IOD，每个上方承载四个 XCD，旁边配置四个 HBM3e 栈。

每个 IOD 保存 128 MB Infinity Cache，总计 256 MB，并承载一半 HBM PHY、Infinity Fabric 链路与 PCIe Gen 5。两个 IOD 间 Infinity Fabric AP 对分带宽为 5.5 TB/s，比 CDNA 3 高约 15%。八个栈升级为 12-Hi HBM3e，在同等 pin count 下提供 288 GB、8 TB/s，容量比 MI300X 高 50%。完整封装有 1,850 亿 transistor，对 kernel 仍呈现为一枚 GPU。

### 五项押注

1. **HPC 之后转向 AI** ：CDNA 2、CDNA 3 提供 full-rate FP64 矩阵；推理经济性转向 low 精度后，CDNA 4 把产品线分化。
2. **内存容量** ：2021 年以来每代 HBM 容量都达到或超过同期 NVIDIA 旗舰，并加入 256 MB last-level Infinity Cache，吸收 H100 需要访问 HBM 的 reuse。
3. **提前采用 3D stacking** ：2023 年以 TSMC SoIC 把 XCD hybrid-bond 到 IOD，早于 NVIDIA 的 multi-die 转型。
4. **Coherent CPU+GPU** ：MI300A 是 chiplet 使用最激进的量产产品之一，El Capitan 提供实际部署证明。
5. **Open scale-up 互连网络** ：选择 UALink 与 OCP MX，推动互连与低精度格式的开放标准。

### 扩展

内存容量策略会直接影响扩展。8 枚 MI300X 有 1.5 TB HBM，8 枚 MI350X 有 2.3 TB；单个 8-GPU 服务器可以用 FP8 容纳 405B-parameter 模型，并留出权重、KV Cache、长上下文与更大 batch 所需空间。8× H100 只有 640 GB，需要精细 sharding。2024–2025 年推理负载中，AMD 只需在单服务器层面保持竞争力；前沿训练要求机柜级互连系统，AMD 到 2026 年才以 Helios 补齐。

Scale-up 通过 Infinity Fabric 把 GPU 绑定成一致性内存域。MI355X 及以前止于 8-GPU OAM 服务器，每枚 GPU mesh 带宽为 896 GB/s；Helios 通过 UALink 扩到 72-GPU 机柜，launch 时在 Ethernet 上 tunnel UALoE，2027 年转为原生 UALink。Scale-out 全部使用 Ethernet，Pensando Pollara 400 与 Vulcano 800 NIC 实现 Ultra Ethernet Consortium UET RDMA transport，Broadcom Tomahawk 6 提供交换 ASIC 与 CPO。

### Scale-up

MI355X 以前的 AMD scale-up 是基于 Infinity Fabric 的 8-GPU OAM platform。每枚 MI300X 有七条 IF 链路，分别连接服务器内其他 peer，每条 128 GB/s 双向，形成 fully-connected all-to-all 拓扑，每枚 GPU mesh 带宽 896 GB/s。MI350X 把每条链路提高到 153.6 GB/s，每枚 GPU 约 1,075 GB/s，继续保持 8-GPU 形状。

平台符合 OCP UBB 2.0，机械接口与 NVIDIA HGX 主板一致，服务器厂商可在同一机柜中部署 AMD 或 NVIDIA。MI355X 以前缺少 NVL72 对应的机柜级互连系统，更大的 MI300X 集群需要通过 Ethernet 连接多个 8-GPU 服务器，训练负载因而承担 scale-out 延迟。Helios 的目标就是关闭这项差距。

![](https://pic1.zhimg.com/v2-6af72b53d92e808ca7aca5027918df06_r.jpg)
*图 11　AMD Helios：Open Rack Wide 机柜内，72 枚 MI455X GPU 位于 UALink switch 下方，组成 coherent UALink memory domain；launch 时互连网络使用 UALoE，将 Infinity Fabric tunnel 到 Ethernet，等待 2027 年 native UALink switching silicon；每枚 GPU 通过 Pensando Vulcano 800 NIC scale-out*

Helios 是 AMD 第一款机柜级 scale-up 互连域，与 MI455X 一起于 2026 年下半年交付。每机柜 72 枚 GPU、约 31 TB HBM4、1.4 PB/s 总 HBM 带宽、2.9 ExaFLOPS FP4 / 1.4 ExaFLOPS FP8、260 TB/s scale-up 带宽、43 TB/s scale-out 带宽。Form factor 使用 Meta 在 2025 年提交 OCP 的 Open Rack Wide：double-wide、液冷。采用 Meta reference design 让已经标准化 ORW 的 hyperscaler 直接部署 Helios，减少定制数据中心 facility 工作。

互连网络使用 UALink（Ultra Accelerator Link），AMD 与 Apple、AWS、Cisco、Google、HPE、Intel、Meta、Microsoft、Synopsys 共同创立的 open consortium standard。2025 年 4 月发布的 UALink 200G 1.0 定义 200 GT/s lane、每方向 800 Gbps，交换式拓扑最多扩至每个互连集群 1,024 个加速器。任何厂商都可构建 UALink 交换机，任何加速器都可支持 UALink，标准归 consortium 所有。

原生 UALink 交换芯片预计 2027 年形成规模。Astera Labs Scorpio，以及 Auradine、Enfabrica、Xconn 的竞品都瞄准 2026 年末至 2027 年。Helios launch 时使用 UALoE，把 Infinity Fabric tunnel 到 standard Ethernet，以保留编程模型；MI500 于 2027 年引入原生 UALink 交换机。首发 Helios 是高速 Ethernet-tunnelled coherent 集群，时间安排让 AMD 能在 2026 年下半年推出具竞争力的机柜。

### Scale-out

AMD scale-out 栈完全采用 Ethernet，并围绕 Ultra Ethernet Consortium（UEC）开放标准构建。2025 年 6 月发布的 UEC 1.0 定义 Ultra Ethernet Transport（UET）：在 standard Ethernet 上重新设计 RDMA semantics，支持 packet spraying、SACK-based selective retransmit 与现代 congestion control。RoCEv2 把 InfiniBand transport 封装到 Ethernet frame，UET 则面向 scale-out AI 互连网络重新设计。AMD 与 Broadcom、Cisco、Meta、Microsoft 都是 founding member。

![](https://pica.zhimg.com/v2-9f37219300652a57e0a4a1e44f9ed214_r.jpg)
*图 12　AMD scale-out：Helios 机柜通过基于 Ultra Ethernet 开放标准的 standard Ethernet 互联，UET 重做 RDMA semantics；每枚 GPU 配置 Pensando Vulcano 800 NIC，PCIe Gen 6、800 GbE、UEC 1.0；机柜间 switching 使用带共封装光学的 Broadcom Tomahawk 6；AMD 掌握 NIC 层级，switch 与 optics 来自 partner silicon*

NIC 来自 AMD 于 2022 年收购的 Pensando。当前 Pollara 400 AI NIC 提供 400 GbE、P4 programmability、UEC readiness、PCIe Gen 5，与 MI300X / MI355X 配套。Vulcano 800 在 2026 年随 MI455X 交付，符合 UEC 1.0，采用 PCIe Gen 6，提供原生 UALink 接口，每枚 GPU scale-out 带宽为 Pollara 的 8 倍。Salina 400 是存储 / SDN / firewall 前端 DPU，拥有 16× Arm Neoverse-N1 与 dual 400 GbE，对应 NVIDIA BlueField，职责与 AI 后端 NIC 分开。

Helios 43 TB/s scale-out 互连网络使用 Broadcom Tomahawk 6，一枚 102.4 Tbps Ethernet 交换 ASIC，配套 Davisson 共封装光学。AMD 自己掌握 Pensando NIC 与 DPU，交换 ASIC 与光链路层使用合作伙伴芯片；NVIDIA 则内部拥有 InfiniBand、Spectrum-X Ethernet、ConnectX、BlueField、Quantum-X Photonics CPO。AMD 押注开放标准加 best-of-breed 合作伙伴芯片相结合的方案。

2025 年 Dell'Oro 数据显示，Ethernet 承载的 AI scale-out 互连网络 volume 超过 InfiniBand 两倍；AWS、Microsoft、Meta、Oracle、xAI 都在 AMD AI 集群上标准化 Ethernet。UEC 已覆盖 RDMA semantics，剩余问题是 Helios 能否足够快地缩小与 NVL72 的机柜级差距，赢得当前默认选择 NVIDIA 的前沿训练负载。

### 软件

ROCm 是 AMD 面向 CUDA 构建的开源软件体系。NVIDIA 通过专有、垂直整合的软件栈交付 cuBLAS、cuDNN 和 TensorRT-LLM 二进制库；ROCm 则在 GitHub 上开放开发，并依托 PyTorch、Triton、vLLM、OCP MX 等开放标准。AMD 希望借助开源社区缩小软件差距。

栈底是 HIP，一套兼容 CUDA 编程风格的 C++ 运行时。hipify 可以自动把 CUDA 源码转换成 HIP。CORAL-2 数据显示，HACC、Laghos、QMCPack 等大型 HPC 项目的自动移植成功率为 80–95%。使用 Hopper 或 Blackwell 专有 TMA 描述符、 `wgmma` 、 `tcgen05.mma` 的现代 AI kernel 仍需手工重写，因为 ROCm 缺少直接对应的 primitive。

HIP 之上的库与 NVIDIA 基本一一对应：rocBLAS 对应 cuBLAS，hipBLASLt 对应 cuBLASLt，MIOpen 对应 cuDNN，RCCL 对应 NCCL，Composable Kernel 和新版 ck-tile DSL 对应 CUTLASS，rocprofv3、rocprof-sys、rocprof-compute 对应 Nsight 工具族。AMD 以开源推理引擎 vLLM 承接 TensorRT-LLM 的角色，并提供可插入 vLLM 的 AMD-specific 算子 AITER。2026 年初，专用 ROCm CI 将 vLLM 测试通过率从 37% 提高到 93%。

PyTorch 是 ROCm 的一等支持路径。Eager-mode PyTorch 自 2018 年起支持 ROCm； `torch.compile` 通过 Triton lowering，包含 AOTriton ahead-of-time math kernel 的 Triton ROCm backend 也已进入 upstream。ROCm 直接编译到 HIP、Triton 或 CK，中间不经过 XLA 风格的 IR。随着 Triton 成为 PyTorch 默认 kernel 路径，经 `torch.compile` 生成的 kernel 可以用同一份源码运行在 CUDA 和 ROCm 上。AMD 押注 Triton Python DSL 会成为跨厂商的通用 kernel 语言。

FlashAttention 是关键案例。FA2 通过 Composable Kernel 在 MI300X 上投入生产，PyTorch on ROCm 默认使用 CK 或 AOTriton。Hopper-tuned FA3 由 AITER + CK 部分支持，Dao-AILab canonical implementation 仍以 CUDA 为主。2026 年 3 月面向 Blackwell 的 FA4 尚无 ROCm port。Hazy Research 在 2025 年 11 月发布 MI355X HipKittens，ThunderKittens 的移植版，约 500 行代码即可让 forward pass 达到 hand-tuned AITER 的水平。Open-source academic kernel 通常在 NVIDIA 发布后数月补齐 AMD tail。

生产环境部署已验证这项策略。Microsoft Azure ND MI300X v5 于 2024 年 5 月 GA，OpenAI 在其上运行 GPT 推理。Meta 通过 Grand Teton platform 在 MI300X 上提供 Llama 3 / Llama 4 推理。Oracle OCI BM.GPU.MI300X.8 于 2024 年 9 月 GA，MI355X 于 2026 年跟进。这些都是 hyperscaler-scale 推理集群。

Phoronix 在 2026 年 3 月发布的独立基准测试显示，在相同精度与对应芯片上，ROCm 7.2 运行标准 PyTorch、vLLM、SGLang 负载时，比对应 CUDA 慢 10–25%。ROCm 7 已基本补齐功能，性能差距仍在缩小。FlashAttention-4 这类使用 Blackwell 最新 primitive 的研究代码，需要等待手写 AITER kernel 或 HipKittens 一类社区移植。Llama 推理、attention、稠密 Transformer 训练等常见负载正在逐渐收敛；新型研究代码的长尾仍会增加 MI300X 和 MI355X 的部署成本。

## Cerebras WSE

Cerebras 制造了有史以来投入交付的最大芯片。它把 memory wall（内存墙）视为切割晶圆的结果：fab 在 300 mm 芯片上印出数十枚 die，再用锯片分开；行业随后投入 HBM、NVLink、CoWoS 和每机柜 5,184 条 copper cable，以远低于 on-die 带宽的速度重新连接这些碎片。Cerebras 省略切割步骤。Wafer-Scale Engine 是一整块晶圆：84 个 reticle field、46,225 mm²、900,000 个数据流核心，每个字节的片上 SRAM 都距离计算单元一个周期。

### 架构

GPU 是层级结构：线程位于 warp，warp 位于 SM，die 位于封装，封装位于机柜，每层边界都有独立带宽、延迟与 programming construct。WSE 是 flat plane：900,000 个相同核心在 2D mesh 上首尾相接，核心之间没有 shared 缓存、global 内存与结构边界。

每个核心很小，WSE-2 约 38,000 µm²，面积近一半 SRAM、一半 logic，peak 功耗 30 mW。它包含 48 kB local SRAM、16 个通用寄存器、six-stage 流水线、4-wide FP16 FMAC SIMD，WSE-3 为 8-wide，以及接入互连网络的 five-port router。

Execution 采用数据流：核心等待 wavelet 到达，wavelet control bit 选择要触发的 handler task，八个硬件 microthread 随张量操作数到达与排出按周期切换。Data arrival 本身就是调度。

### Wafer

Stepper 每次曝光一个 reticle，每 shot 约 850 mm²，因此 conventional 芯片都受这一上限约束，B200 触及上限后转为 two-die。Cerebras 也像其他 TSMC 客户一样，在 12×7 grid 中重复印制 84 个约 550 mm² die；随后用一套与 TSMC 共同开发的工艺，在通常用于切割、宽度小于 1 mm 的 scribe line 上铺设额外高层 metal。

Mesh 通过 source-synchronous parallel 接口跨越每条 seam，WSE-3 每 die 为 2,880 GB/s，完整 inter-die 层约消耗 97 W。软件看到一张 uniform mesh、一枚芯片。

历史上的wafer-scale integration 败在 yield：monolithic 晶圆 computer 任意 defect 都可能让整块晶圆报废。Cerebras 通过细粒度冗余解决。H100 上一个 defect 会禁用约 6 mm² 的完整 SM，同样 defect 在 WSE 上只影响一个 0.05 mm² 核心。WSE-3 实际制造约 970,000 个核心，交付 900,000 个；约 7% spare pool 加 redundant 互连网络链路，可让硬件绕过每个 defect，恢复完整 logical mesh。

### Core

Core 最特别之处是指令形态。16 个通用寄存器旁有 44 个 data-structure 寄存器（DSR），每个保存最多四维的张量描述符：base address、extent、stride。Instruction 通过 DSR 指定操作数。一条 FMAC 指令可以表达：把 arriving 数据流与这个 resident 张量相乘，并累加到另一个张量；硬件持续数据流 element，直到张量结束。Multiply 周围无需软件 loop，每个 element 也无需独立指令取指，loop 被编码在描述符中。NVIDIA 用五代 Tensor Core 把 matmul 推向 single 描述符驱动的 command，WSE 的张量指令天生就采用这种形式。

Sequencing 由互连网络完成。Color 是 statically-routed virtual channel，编译期绑定 handler task；向某种 color 发送 wavelet，就相当于在 destination 核心调用代码：16 个 control bit 是 call，16 个 data bit 是 argument。Task 调度器把 in-flight 张量操作放在八个 microthread 上，并按操作数 availability 每周期切换。它承担与 warp 调度器相同的 stall hiding 工作，只需八个 context，因为需要隐藏的是繁忙 SRAM bank 或相邻芯片 hop，而非 HBM round-trip。

48 kB local SRAM 按数据路径组织。八个 single-ported 6 kB bank 每周期提供两个 64-bit read 和一个 64-bit write，恰好输入两个 4-element FP16 操作数并输出一个 result，与 WSE-2 FMAC 宽度一致。256-字节软件管理的缓存，WSE-3 为 512 B，把最热 value 放在流水线旁。每个核心的内存带宽与计算精确匹配，这种平衡在晶圆上复制 900,000 次。

### 计算

晶圆通过互连网络拼出 matmul，专用矩阵单元的职责被分散到 mesh。NVIDIA、Google、AMD 把 FLOPs 集中在 Tensor Core、MXU、Matrix Core。执行 GEMM 时，arriving 权重沿一行持有激活值的核心 broadcast；每个核心对自己的 resident slice 执行乘加，也就是每个权重做一次 AXPY；部分和再通过 mesh reduce。Tensor Core 通过寄存器 tile、MXU 通过布线获得数据复用，WSE 则通过 geometry 获得：激活值保持静止，只有参与乘法的另一操作数移动。

Cerebras headline 125 PFLOPS 指 sparse FP16，假定理想 sparse 张量上硬件 zero-skipping 带来约 8 倍收益。Dense FP16 约 15.8 PFLOPS，由 900,000 核心 × 8-wide FMAC × 1.1 GHz 推算，Cerebras 没有发布官方稠密数值。Wafer 的设计重点是带宽，FLOPs 用于匹配 SRAM。

Zero-skipping 体现数据流的优势。计算由 arriving data 触发，zero 在 sender 侧直接 filter，receiver 核心看不到它，也无需消耗周期。这是 unstructured、element-granular sparsity，覆盖范围比 NVIDIA 2:4 结构化稀疏更广。实际应用仍处早期：Cerebras 自己的 sparse pretraining 结果 SPDF 在 1.3B parameter 上做到 75% sparsity，后续扩到 6.7B；两项均由厂商撰写且低于 7B。平台上最大的 Jais 2 训练 run 使用稠密模型，尚未公开旗舰客户的 sparse-trained 模型。

### 存储

存储层次只有一层：44 GB SRAM，以每核心 48 kB 分布在晶圆上，每个字节距离 FMAC 一个周期。HBM、L2 与 eviction policy 全部被这一层取代。21 PB/s 是 900,000 个 local SRAM port 的晶圆上总计，口径属于片上总计，需要与 HBM 分开解读。

更有意义的指标是 bytes per FLOP。Wafer 每个稠密 FP16 FLOP 可获得约 1.3 字节，B200 从 HBM 获得约 0.002 字节。GPU 与 TPU 在这一轴线上受内存限制，WSE 保持 balance。Decode 每枚 token 都要完整读取权重，是纯带宽问题，也正好符合晶圆形态。

另一面是晶圆 edge。它与外部世界只通过 12×100 GbE 连接，共 1.2 Tb/s，略高于一枚 Blackwell GPU 配置的单个 ConnectX-8 NIC。On-wafer SRAM 与晶圆外 Ethernet 相差五个数量级。NVIDIA hierarchy 每层比上一层慢数倍，WSE 两层之间形成巨大 cliff，晶圆因而成为计算岛，这同时赋予能力并形成边界。

Island 面积固定在 300 mm 晶圆上。先进工艺节点的 SRAM 密度已基本停止增长。WSE-3 相比 WSE-2 完成一次完整制程升级、transistor count 增加 54%，SRAM 只增加 10%。Logic 继续缩小，six-transistor SRAM 单元缩放有限，下一代工艺节点已难以扩张架构最稀缺的资源。

### Weight streaming

晶圆训练反转了常见 flow。GPU 与 TPU 让权重 resident、激活值数据流；WSE 让激活值 resident、权重数据流。Master 权重存在集群旁的 DRAM-and-flash appliance MemoryX。权重逐层流过晶圆，与固定在 SRAM 的激活值触发乘加，随后离开；backward pass 的 gradient 数据流回 MemoryX，optimizer step 在 MemoryX CPU 上执行。权重更新是 O(parameters) 的逐元素计算，缺乏 reuse，CPU-class 计算足以跟上。Weight streaming 贯穿全过程，晶圆只保留激活值。

模型规模受 MemoryX 容量约束，44 GB 约束激活值与 batch。编程模型因而非常直接：一块晶圆保存完整层激活值，无需张量并行、流水线并行与 FSDP sharding。70B 模型可以写成 single-device 程序，多系统扩展只使用数据并行。

SwarmX 是 broadcast/reduce tree，把一条权重数据流扇出到 N 块晶圆，并在返回路径汇总 gradient。GPU 训练中复杂的 parallelism strategy spreadsheet 在 Cerebras 上基本消失。

市场部署反映了这条路线的扩展上限。规格支持 2,048 个 CS-3，已公开最大集群是 64-system Condor Galaxy 3。已公开最大的 from-scratch 模型是 G42 与驻场 Cerebras engineer 训练的 Jais 2，70B parameter、2.6T token。CS-1 发布七年以来尚无 70B 以上公开训练；Cerebras 也尚未公布任何 run 的 MFU，而 GPU lab 通常公开 35–45% MFU。

### 数值格式

WSE 使用 FP16、BF16 与 FP32 累加；WSE-3 另有一条 16-wide 8-bit integer 路径，Hot Chips disclosure 将其标为fixed-point。数值格式集合止于 16-bit floating point，尚未加入 FP8、FP4 与 microscaling。其他厂商每代将精度减半并通过 block scaling恢复 accuracy，Cerebras 继续以 16-bit 计算和原始 16-bit 权重作为质量优势。

SRAM 容量是最稀缺资源，8-bit 权重理论上可将模型所需晶圆数减半。16-bit-only 究竟代表 numerical conviction 还是数据路径 roadmap gap，目前仍是开放问题；Cerebras primary source 尚未展示晶圆上的 floating-point 8。

### 五项押注

1. **保留完整晶圆** ：die 边界带来 SerDes、interposer、HBM 栈、cable、交换机成本；用 metal 拼接 84 个 reticle field，直接消除竞品最高带宽边界。
2. **SRAM 是唯一内存** ：用容量换取极高带宽，44 GB 晶圆上 SRAM 提供 21 PB/s 总带宽，让整机保持 balance。
3. **Dataflow 核心，不设矩阵单元** ：900,000 个由 arriving wavelet 触发的小核心，以 broadcast、FMAC、mesh 归约拼出 matmul，zero skipping 是自然行为。
4. **权重移动，激活值驻留** ：权重 streaming 将模型规模与 44 GB 晶圆内存解耦，集群扩展简化为纯数据并行。
5. **出售延迟** ：晶圆每枚 token 重读完整模型的速度超过 HBM 系统，产品以 premium 延迟定价。

### 扩展

WSE 的一致性互连域由 lithography 一次制造，NVIDIA 需要连接 72 个封装的 scale-up 问题已经在 fab 内完成。Scale-up 就是晶圆：900,000 个核心位于一个 2D mesh，32-bit 链路、单周期 hop、24 种 color 静态路由、原生 broadcast、214 Pbit/s 总互连网络带宽，面积由 300 mm 晶圆固定为 46,225 mm²。

Scale-out 从晶圆 edge 立即进入 Ethernet，每套系统为 12×100 GbE、1.2 Tb/s。Training 通过 SwarmX 在 RoCE 上完成 data-parallel broadcast/reduce；推理在系统间按层边界 shard 模型，采用流水线并行。

### Scale-up

晶圆内部互连网络直接使用 metal 布线，省去 SerDes、cable、transceiver 与每链路 marginal 成本；路由在编译期决定，每个 hop 一个周期，broadcast 是原生互连网络 primitive。NVL72 使用 5,184 条 copper cable 与一 tray NVSwitch ASIC 为 72 枚 GPU 提供 130 TB/s all-to-all，WSE 对应域是一个 lithographic object。

互连域规模是常数。NVIDIA scale-up 互连域在三年间由 NVL72 扩到 NVL576，WSE 自 2019 年起保持 46,225 mm²。产业仍以 300 mm 作为最大晶圆，450 mm 转型十年前已经终止，Cerebras scale-up roadmap 只能依赖下一工艺节点提升密度，无法增加 area。

### Scale-out 与推理

训练时，SwarmX 只执行 data parallel replication：将同一条权重数据流广播到 N 块晶圆，返回时再归约 gradient。系统数量增加后，batch 随之扩大，单个模型的规模保持不变。官方规格支持最多 2,048 套系统和 256 sparse ExaFLOPS，实际公开部署的最大规模为 64 套系统。

推理时会停止 weight streaming。假如每生成一枚 token，都要通过约 150 GB/s 的链路从 MemoryX 传输一次 70B 模型的 140 GB 权重，单枚 token 就需要约一秒。实际方案会把权重固定在 SRAM 中，再按模型层将模型 shard 到多块晶圆。Llama 70B 最少使用四台 CS-3，通过 Ethernet 执行流水线并行；每增加一块晶圆，就增加 44 GB 的权重与 KV Cache 容量，同时增加 23 kW 功耗。

独立测量验证了这项速度优势。Artificial Analysis 在 2024 年 8 月发布时测得，Llama 3.1 8B 达到 1,850 token/s，70B 达到 446 token/s；Llama 405B 达到 969 token/s，time to first token 为 240 ms；2025 年 Llama 4 Maverick 达到 2,522 token/s，约为同期最佳公开 Blackwell 结果的 2.4 倍。厂商标称峰值更高，speculative decoding 下的 70B 为 2,100 token/s，GPT-OSS-120B 标称 3,000 token/s，实时独立测量接近 2,000 token/s。单用户 decode 速度明显高于 GPU 服务商。

经济性形成尖锐约束。每块晶圆只有 44 GB，前沿规模模型需要大量系统。SemiAnalysis 估算，1.6T-parameter-class 模型约需 24 台 CS-3，而它可以放进少数 GPU 机柜；每台系统的分析师估算 bill of materials 约 45 万美元，list price 约 200–300 万美元，官方从未披露。

Decode 时晶圆大量 FLOPs 闲置。Cerebras 拒绝披露 batch size，也未公布每套系统吞吐量。同一 open 模型的 API 每 token 价格约为 GPU provider 的 3–5 倍；Llama 405B 后来从 API 下架，SemiAnalysis 将其解读为 serving 经济性未达要求。KV Cache 与权重共享 44 GB SRAM，长上下文会占用容量，迫使每个 replica 增加系统；API 上下文上限为 131K token，frontier provider 已提供 256K–1M。

MoE 也可运行，例如厂商宣称 Qwen3-235B 约 1,500 token/s，但其特性最不利于这一内存格式：巨大 parameter footprint 驻留最昂贵的内存，每步只访问少数 expert。

市场愿意为延迟付费。Mistral Le Chat 约 1,100 token/s、Perplexity Sonar、Meta Llama API 都使用 Cerebras。2026 年 1 月，OpenAI 签约到 2028 年部署 750 MW CS-3 容量，签约时报道金额超过 100 亿美元，之后增长到超过 200 亿美元，是wafer-scale 获得的最大背书。首个在这批容量上提供的旗舰是 2026 年 7 月发布的 GPT-5.6 Sol，标称 750 token/s。

### 软件

Cerebras 软件栈同样由编译器驱动，但开放给用户的入口更窄。它的编译器本质上是 kernel matcher。 `cerebras.pytorch` 通过 lazy tensor 把训练 step trace 成 Torch-MLIR 和 graph IR，再将 subgraph 匹配到手写 kernel 库；缺少匹配实现的算子会回退到较慢的自动生成 kernel。

公开限制包括静态图、静态 shape 和固定控制流；训练 step 执行期间无法用 eager mode 读取 tensor；支持的 PyTorch 版本也落后 upstream。荷兰国家计算中心 SURF 的独立使用报告还记录了不受支持的层类型，标准 PyTorch 代码也缺少一对一移植路径。

Cerebras 没有向 PyTorch 用户开放 kernel escape hatch。Compiler matcher 性能不佳时，需要 Cerebras engineer 介入。另一套 SDK 语言 CSL 可以直接操作底层 task、wavelet 和 color，曾取得很强的 HPC 结果，例如 TotalEnergies stencil code 约为 A100 的 228 倍，48 台 CS-2 的工作成为 Gordon Bell finalist。CSL 与 PyTorch 流程彼此独立。平台上的 Jais、BTLM、Med42 等旗舰模型都由 Cerebras 团队深度参与开发。

FlashAttention 的核心是针对存储层次对 attention 做 tiling，WSE 的 single-层级内存让这类 optimisation 失去适用条件，也省去 AMD 经历的 porting lag。代价来自同一点：CUDA 上持续累积的 third-party kernel 生态在这里缺少可附着的 surface，平台历史上每项 kernel improvement 都来自同一家作者。

Wafer 赢得了清晰 niche：batch-one decode 速度经过独立验证，客户愿意为延迟支付 premium。周围存在硬边界：每 token 价格高 3–5 倍；七年间公开训练上限为 70B；2025 年约 86% revenue 集中在两家与 Abu Dhabi 关联的客户，数据来自 2026 年 5 月 IPO 前后的 S-1 filing；最稀缺的 SRAM 密度在模型继续增长时停止增长。WSE 是这场架构寒武纪中最极端的形态，它把 memory wall（内存墙）定义为封装选择，并用 46,225 mm² 晶圆面积坚持这一判断。

## AWS Trainium

Trainium 出自负责 AWS Nitro card 和 Graviton CPU 的 Annapurna Labs，是一条典型的 fast-follower 路线。计算核心沿用 TPU 已验证的方案，包括 128×128 weight-stationary 脉动阵列、软件管理的 scratchpad 和全程序编译，编译器也直接建立在 Google XLA 之上。Scale-out 复用 AWS 现有的 Nitro-offloaded 网络。Amazon 新增的关键设计有两项：一是专用集合通信逻辑，二是芯片、服务器、网络和云服务的垂直整合。

### 架构

Trainium 可以看作在另一家 cloud 中重建 TPU thesis：脉动阵列从软件管理的 SRAM 取数，由编译器提前调度，缓存与线程调度器的职责全部转入软件。Assembly 方式有所不同。一枚 Trainium 只含少量 NeuronCore，Trn1 为 2 个，Trn2、Trn3 为 8 个，每个 NeuronCore 是一组 decoupled specialised 引擎：128×128 脉动阵列 Tensor Engine、执行归约的 Vector Engine、执行逐点 math 的 Scalar Engine，以及由八个 512-bit 向量处理器组成、处理长尾操作的可编程 GPSIMD Engine。

外围数据搬运单元包括 128 个 DMA 引擎、为传输排序的 Sync Engine，以及 Trn2 起加入、处理集合通信的 dedicated CC-Core。所有引擎以静态调度的数据流流水线运行。决定架构的关键，是脉动阵列周围布置了什么。

### 计算

Tensor Engine 提供 matmul FLOPs，其余三个引擎处理外围操作。Tensor Engine 是 128×128 processing element grid，共 16,384 个 MAC，采用weight-stationary：一块操作数 tile 通过 `LoadStationary` 装入阵列并保持，另一块通过 `MultiplyMoving` 流过，部分和落入小型累加器 SRAM PSUM。Engine 可对 PSUM read-add-write，让长度超过 128 的 contraction 沿 K axis 累积。

其核心同样是 $D=A\cdot B+C$ tile MMA。NVIDIA 把它包在 warp hierarchy，Google 从 VLIW bundle 发出，Trainium 将其暴露成针对具名 scratchpad 的两条 explicit 指令。

三代 physical 阵列都固定为 128×128，变化来自每个单元同时容纳的 product 数。Trn1 NeuronCore-v2 执行 BF16/FP16 与 FP32 累加，FP8 仍以 BF16 rate 运行。Trn2 v3 double-pump FP8，对外呈现 effective 256×128 阵列，8-bit 首次真正获得 2 倍速度。Trn3 v4 pack microscaling 操作数，呈现 effective 512×128，达到 BF16 rate 的 4 倍。Physical 乘加单元数量保持不变，数据路径持续输入更窄数值格式。

Vector Engine 执行 layernorm、softmax、pooling 等跨元素归约；Scalar Engine 执行激活值、GELU 等单输入单输出逐点操作；GPSIMD Engine 的八个完全可编程的向量处理器运行 C，承接其他引擎无法映射的操作。

编译器会把四个引擎 overlap：Tensor Engine 执行 matmul，Vector Engine 同时处理上一 tile 的 softmax，DMA 引擎 stage 下一 tile。这与 TPU、GPU attention kernel 的 producer/consumer overlap 相同，只是通过独立 physical 引擎表达。Transformer 层通常可以清晰分解到四类引擎，因此这套设计效率很高。Novel architecture 中无法映射到 specialised 引擎的算子会落到更慢的 GPSIMD 路径，成为这类加速器的长尾成本。

### 存储

存储层次有三层，全部由软件管理。片外 HBM 容量：Trn1 32 GB，Trn2 96 GB HBM3，Trn3 144 GB HBM3e。片上最接近引擎的 State Buffer（SBUF）是 main scratchpad，带宽约为 HBM 的 20 倍，分成 128 个 partition；每 NeuronCore 容量为 v2 24 MiB、v3 28 MiB、v4 32 MiB。Array 与 SBUF 之间有 2 MiB PSUM，专门保存 matmul 输出累加器。

数据流是 HBM → SBUF → Tensor Engine → PSUM → SBUF，每个 hop 都由编译器发出，prefetch 与 eviction 也由软件调度取代。这与 Google VMEM 的押注一致：显式 scratchpad 要求编译器精确调度，正确调度让引擎持续运行，错误调度会直接造成 stall。相对 modest peak FLOPs，Trainium 配置较充裕 HBM，每单位计算携带的内存多于相近 NVIDIA part。

绝对容量仍低于同期 NVIDIA：Trn2 96 GB 低于 H200、B200，2025 年 Trn3 144 GB 低于 B200 192 GB 与 B300 288 GB。AWS 为 large 模型 serving 提供的经济性主要来自 price，即自研并自行出租芯片上每单位计算与 HBM 的成本。

### 数值格式

Trainium 同样沿 FP32 → BF16 → FP8 → FP4 减半精度，有两项独特细节。第一是 configurable FP8：Tensor Engine 采用 adjustable exponent bias，支持 E5M2、E4M3、E3M4，编译器可对每个张量选择 range 与精度。

第二是 Trn3 FP4 不增加计算吞吐量。OCP MXFP4 操作数在进入阵列前 up-convert 到 MXFP8，因此 FP4 以 FP8 rate 执行，只节省内存与带宽。Trn3 使用 microscaling block exponent，所有代际都在硬件中支持随机舍入。AWS headline sparse peak 声称 FP8 加速 4 倍，其 architecture page 将稠密 FP8 标为 2 倍；4 倍数字是相对稠密 BF16，marketing acceleration 与数据路径口径存在差别。

### Collective 芯片

集合通信核心是 GPU 中缺少直接对应物的 block。分布式训练与推理很大一部分 wall-clock 消耗在集合通信：每个 gradient step 执行 all-reduce，每个 MoE 层执行 all-to-all。GPU 把这些集合通信作为 NCCL kernel 运行在执行 math 的同一批 SM 上，通信与计算争用同一批硬件资源，重叠执行依赖软件安排。

Trainium 将其独立成硬件。每枚 Trn2 有 20 个 CC-Core，直接连接 NeuronLink port，在 Tensor 与 Vector 引擎持续运行时执行 all-reduce、all-gather、reduce-scatter、all-to-all。思路与 Google SparseCore、Cerebras off-core zero filter 相同：为 main 引擎难以匹配的负载分配少量 purpose-built area。Communication 成为芯片并发执行的工作。

### 五项押注

1. **Cloud 是产品，芯片是部件** ：Annapurna 把芯片、服务器、机柜、Nitro 网络、cloud API 作为一套栈设计，Trainium 只需在 AWS 内部赢得性价比。
2. **复用计算 thesis** ：128×128 weight-stationary 阵列、软件管理的 SBUF/PSUM scratchpad、全程序编译复用 TPU 与 OpenXLA，把工程投入网络与机柜。
3. **把 collective 固化进硬件** ：dedicated CC-Core 在硬件中 overlap all-reduce、all-to-all 与计算，避免集合通信 kernel 占用 matmul FLOPs。
4. **复用 cloud 网络** ：scale-out 使用 EFA 与 SRD transport，也就是 AWS 已广泛运行、由 Nitro offload、通过 packet spraying 实现的 RDMA。
5. **让拓扑适应负载** ：Trn1、Trn2 使用 TPU 式 torus；MoE 流量超出 nearest-neighbour 后，Trn3 改用 NeuronSwitch switched all-to-all 互连网络。

### 扩展

Trainium 使用两层互连网络：NeuronLink tightly-coupled 域连接需要共同工作的芯片，外围使用 AWS 通用 EFA。UltraServer 对外呈现 pooled multi-terabyte 内存，底层采用 point-to-point 消息传递，语义更接近 TPU ICI。

Trn2 以前的 scale-up 使用 torus：一个 Trn2 instance 以 4×4 2D torus 连接 16 枚芯片；64 芯片 UltraServer 用 4×4×4 3D torus 连接四个 instance。Trn3 改用 NeuronSwitch all-to-all 互连网络。Scale-out 通过 Nitro-offloaded Elastic Fabric Adapter over Ethernet；SRD 把每个 flow 喷射到多条路径，以可靠但乱序的方式交付；UltraCluster 通过 10p10u 互连网络扩至数十万枚芯片。

### Scale-up

NeuronLink 对 Trainium 的角色对应 NVIDIA NVLink 与 TPU ICI。一个 Trn2 instance 中 16 枚芯片通过 4×4 2D torus 连接，每枚芯片约 1.28 TB/s。Trn2 UltraServer 把四个 instance 连接成 64 芯片、4×4×4 3D torus，在一个 scale-up 互连域中提供 83 稠密 FP8 PetaFLOPS 与约 6 TB HBM。

第三条 torus axis 刻意设计得较窄：inter-instance ring 每枚芯片约 256 GB/s，instance 内为 1.28 TB/s。Torus 布线成本低、nearest-neighbour 带宽高，diameter 流量需要经过多 hop。AWS 将 64 芯片 UltraServer 对标 72-GPU NVL72，总计算位于同一级别；crossbar 与 torus 在非 nearest-neighbour 流量上表现差异明显。

Trn3 因此转向 NeuronSwitch-v1，一套 switched all-to-all 互连网络，芯片间带宽约翻倍，更重要的是把 diameter 压平，任意芯片之间通过一个 switched hop 到达。Trn3 UltraServer 扩到 144 枚芯片，提供 362 稠密 FP8 PetaFLOPS 与 20.7 TB HBM3e。MoE expert 路由是 all-to-all，也是 torus 最差场景；交换机把 longest-hop pair 变成一次 crossing。Trainium interconnect roadmap 复现了行业路径：nearest-neighbour 负载使用 torus，all-to-all 负载增长后转向 crossbar。

### Scale-out

每个 Trainium instance 都用 Elastic Fabric Adapter NIC 接入数据中心网络，Trn2 每 instance 为 3.2 Tbps。传输协议是由 Nitro card offload 的 SRD（Scalable Reliable Datagram）。RoCE 或 InfiniBand 使用单条 ordered flow，SRD 把一条 message 喷射到最多 64 条 parallel 路径，以可靠但乱序的方式交付，把 reassembly 交给集合通信库，避免单条拥塞路径引发 head-of-line blocking。这是 AWS 为整个 cloud 构建、再复用于加速器互连网络的 transport。

![](https://pica.zhimg.com/v2-e10cce53e4be71ee93d660a9095e9c44_r.jpg)
*图 18　AWS Trainium scale-out：UltraServer 通过 offload 到 Nitro card 的 EFA NIC 在 standard Ethernet 上互联；SRD 把每个 flow 喷射到最多 64 条 path，以可靠但乱序的方式交付，避开 head-of-line blocking；10p10u UltraCluster 在低于 10 µs latency 下提供约 10 Pb/s，连接数十万枚 chip；Project Rainier 为 Anthropic 跨多个美国 datacenter 部署约 500,000 枚 Trainium2*

系统顶层是 UltraCluster，由 10p10u 网络连接。10p10u 是 AWS 对数据中心内约 10 Pb/s 带宽、低于 10 µs 延迟的简称，整套网络可以扩展到数十万枚芯片。Project Rainier 是实际案例：约 500,000 枚 Trainium2 分布在美国多个数据中心，2025 年末为 Anthropic 上线；到 2026 年初，Claude 已运行在超过一百万枚 Trainium 芯片上。这是外部模型公司对 NVIDIA 之外训练平台做出的最大规模承诺。

这项部署依靠端到端成本优势。AWS 宣称，Trainium2 相比自家的 Hopper-class GPU instance 可提供高 30–40% 的性价比。该数据由 AWS 提供，对比对象是上一代 NVIDIA Hopper。Amazon 掌握从 Nitro card 到云 API 的每一层，也掌握最终定价空间。

### 软件

Neuron SDK 是 compiler-first 软件栈，建立在与 TPU 相同的 OpenXLA 基础之上。Neuron 编译器 `neuronx-cc` 接收 XLA HLO graph，再生成由 Neuron 运行时加载到 NeuronCore 的 NEFF 二进制文件。Front-end IR 来自 Google，OpenXLA 也把 Trainium 与 TPU 一同列为 first-class PJRT device。

`torch-neuronx` 通过 PyTorch/XLA LazyTensor tracing 运行 PyTorch，先记录操作，再在 step 边界编译计算图。 `jax-neuronx` 则通过 StableHLO lowering JAX。Trainium 与 TPU 都位于全程序编译这一端，而且大量复用了同一套编译器基础设施。

底层编程接口是 NKI（Neuron Kernel Interface），一套 Python tile-level kernel language，直接暴露四个引擎和 SBUF/PSUM scratchpad。它在 Trainium 上承担类似 Pallas 或 Triton 的角色。全程序编译器无法为新型 attention variant、fused MoE dispatch 生成最优实现时，开发者可以通过 NKI 手工控制 tile 与调度。

下层集合通信库把 all-reduce、all-to-all 映射到 CC-Core 与 NeuronLink 拓扑，承担 NCCL 对应角色；NeuronX Distributed 提供 sharded-training 层。

Trainium 与 CUDA、TPU 软件栈的差距主要来自成熟度。到 2024 年末，NKI、JAX 路径和 distributed 库仍处于 beta；移植后的模型只能在 AWS 上运行，缺少跨厂商 fallback；vLLM backend 也落后 upstream。Anthropic 采用深度协作方式，与 Annapurna 团队共同编写 low-level NKI kernel，并把修复 upstream 到 Neuron 栈。Trainium 已能支撑前沿模型生产负载，外围生态仍处于较早阶段。

## Groq LPU

Groq LPU 是 deterministic 机器。其他芯片用缓存隐藏内存延迟、调度器填补 stall、arbiter 处理不可预测 contention；LPU 把这些 reactive component 的职责全部交给编译器，由它把每条指令与每个字节放在精确周期上。Cache、分支预测器、arbiter、重排序缓冲区与片上 crossbar 都被移出硬件，延迟在运行前即可确定。

TPU 把调度移入编译器，同时保留 HBM 与动态网络；Groq 进一步移除最后的 nondeterminism source：全部内存使用 SRAM，网络也纳入调度，数百枚芯片共同执行一份 clock-exact 程序。

### 架构

其他架构通常先设计一种核心，例如 SM、TensorCore、CU 或数据流核心，再把大量相同核心平铺到 die 上。LPU 采用另一种组织方式：它把传统核心拆成 instruction control、向量 ALU、矩阵单元、内存和网络等 functional slice。每个 slice 是一列贯穿芯片高度的同类硬件，不同功能的 slice 再横向并排。

数据像流水线上的部件一样，在 slice 之间向 East 和 West 横向移动，每周期前进一个寄存器 hop。Control slice 同时向 North 发出 VLIW 指令，让指令与数据在预定位置相遇。编译器提前知道每个操作数在每个周期的位置，硬件只需按照时钟推进。产品最初因此得名 Tensor Streaming Processor，2024 年改名 Language Processing Unit。

![](https://pic3.zhimg.com/v2-857cf606338a016b5a0496e61e7824b4_r.jpg)
*图 19　Groq LPU floorplan：中央 VXM vector slice 两侧为镜像 East/West hemisphere；向外依次是 MXM matrix plane、SXM switch slice、夹在 VXM 两侧的 MEM SRAM slice；南侧 ICU 向 North 给每个 slice 发 VLIW bundle，operand 每 cycle 一个 register hop 向 East/West 流动；320 lane 纵向组织成 20 个 superlane*

纵轴表示 SIMD 宽度。芯片纵向有 320 条 lane，组成 20 个 16-lane superlane；第 21 个 superlane 用作 yield spare，出厂时会 fuse 掉，对软件不可见。每个 slice 同时作用于全部 320 条 lane。横轴表示时间。每条 lane 有 64 个 logical stream register，其中 32 个向 East 流动，32 个向 West 流动；每个 tick 前进一个 slice，直到数据被消费或离开 die。Slice 从经过的数据流中读取操作数，完成计算，再把结果写回前往下一 slice 的数据流。Die 以中央向量单元为轴镜像布局，同一个结果可以被两侧 slice 使用。

### 计算

LPU 同样由专用矩阵单元和向量引擎分工，只是两者都以 slice 形式存在。矩阵路径称为 MXM，由四个独立的 320×320 乘加 plane 组成，每个 hemisphere 两个，共有 409,600 个 multiplier。INT8 或 FP16 操作数进入 INT32 或 FP32 累加器。全部权重可以在 40 个周期内装入 plane，激活值随后流过并累加乘积。900 MHz 下的峰值约为 750 INT8 TOPS 和 188 FP16 TFLOPS。TSP 会照常计算零值，因为 data-dependent skip 会让执行时间随数据变化，破坏 determinism。

向量路径是 die 中央的 VXM。每条 lane 有 16 个 ALU，排列成 4×4 mesh，全芯片合计 5,120 个 32-bit ALU，用于执行激活函数、归一化、量化和残差加法。计算采用空间化方式，操作数可以连续穿过多个 VXM ALU，再直接进入 MXM plane，全程无需访问内存。GPU kernel 需要手工完成的算子融合，在这里由 slice 的物理排列顺序直接实现。

第三类 SXM slice 负责直线数据流难以表达的数据移动，包括 lane shift、320-lane permute、transpose 和芯片间通信。跨 lane 重排成为硬件原生操作，无需经过 SRAM 往返。

### 存储

存储由 88 个 MEM slice 组成，每个 hemisphere 44 个，共 230 MB SRAM。每个字节距离计算 slice 只有一个周期，总带宽约 80 TB/s。整枚芯片只有这一层存储，由软件直接寻址；HBM、DRAM、缓存，以及可能引入可变延迟的 eviction、prefetch 和 coherence 逻辑都被省去。

230 MB 无法容纳完整模型。Llama-2 70B 的 FP16 权重约为 140 GB，只能 shard 到数百枚芯片，分散存放在一个或多个机柜的 SRAM 中，实际部署约使用 576 枚 LPU。GPU 把模型放进少量封装的 HBM，再让 token 流过；LPU 则把模型分散到整个集群的 SRAM 中，让 token 穿过集群。所需芯片数量由权重容量决定。

这与 Cerebras 都选择 SRAM-only，只是方向相反：Cerebras 使用一枚巨大 die，晶圆容量仍有限；Groq 使用 normal-sized die，每枚芯片从一开始就无法容纳完整模型。

### 数值格式

TSP 始终使用 FP16、INT8 与 FP32 累加，现有芯片的低精度 roadmap 止于 INT8。它的 numeric 创新是 TruePoint：320-element dot product 只执行一次 fused 舍入，并使用 FP32 accumulation，让 FP16 multiplier 阵列在归约上接近 FP32 accuracy；Groq 报告相对 FP32 baseline 的 max error 约 0.05%。

第二代芯片最终停在交付前，16-bit 既可能来自设计信念，也可能来自尚待低精度 refresh 的数据路径。SRAM 容量是最稀缺资源，8-bit 权重可让模型所需芯片减半，容量受限的机器对 FP8 有很强需求，现有芯片仍停留在更宽格式。这与 Cerebras 16-bit-only 数据路径面临同一 tension：最缺容量的厂商使用最宽精度。

### Determinism

LPU 把延迟完全暴露给编译器。ISA 记录每条指令的执行延迟，数据路径也采用固定延迟，因此编译器可以提前算出每个结果出现的精确周期。Cache miss、arbiter stall、分支预测错误和 speculation unwind 都已从硬件中移除。Groq 的测量显示，BERT-Large 连续运行 24,240 次，延迟波动范围约为 75 µs；编译器预测值与实测值相差低于 2%。

TPU 把芯片内部调度移入编译器，LPU 又把静态调度扩展到整个集群，连网络通信也按周期编排。Cerebras 核心在操作数到达时触发，LPU 则完全按照时钟预先排程。WSE 用数据到达事件驱动执行，LPU 用全局时钟驱动执行。

### 五项押注

1. **Determinism 优先** ：删除缓存、arbiter、predictor、重排序缓冲区等 reactive component，让编译器掌握每个周期。
2. **Spatial functional slice** ：把核心拆成 slice，操作数依次流过，fusion 由 floorplan 表达，数据复用位于布线。
3. **SRAM 是唯一内存** ：用单周期固定延迟 access 换取片上模型容量，接受模型必须跨数百枚芯片。
4. **连网络也调度** ：芯片自身充当 router，communication 按周期编译，千芯片集群作为一个 deterministic 程序运行，省去交换机与 congestion。
5. **出售延迟** ：针对 GPU 最弱的 batch 1，优化每用户 token/s，以速度作为产品。

### 扩展

LPU 无需独立 scale-up 互连网络，因为芯片本身就是交换机。每枚 LPU 最多有 16 条 RealScale 芯片间链路，card 暴露 11 条，同时充当计算 endpoint 与 router。芯片直接互联形成 glueless multiprocessor，不需要 NIC、交换 ASIC 与机柜顶部交换机。Determinism 覆盖这些链路，完整集群使用一份编译期调度表。

Scale-up 单元是节点：8 枚 LPU 通过 RealScale C2C fully connect，构成一个 Dragonfly group，并呈现为高基数 virtual router。它由软件调度，采用消息传递 semantics。Scale-out 继续延伸同一互连网络：每机柜 9 个节点、72 枚芯片，其中一个节点是 hot spare；specification 最多扩到 10,440 枚芯片，每个 hop 仍执行 compiled deterministic 调度。

### Scale-up

一个节点的 8 枚 LPU fully connect。每枚芯片七条链路分别连接其他七枚，节点内任意芯片之间都是 one hop。每枚芯片剩余四条链路，全节点共 32 条，组成 ISCA paper 所称的 32-port virtual router，作为节点到大型互连网络的 uplink。

这里用 direct 链路与 scheduled message 取代主板交换机和一致性地址空间。Remote 操作数通过调度到达：source 芯片在编译器指定的周期注入，destination 在落地周期消费。

*图 20　Groq scale-out：8 枚 LPU fully connect 成一个 node，也就是呈现为 high-radix virtual router 的 Dragonfly group；9 个 node 组成 72-chip 机柜，其中一个为 hot spare；chip 同时承担 NIC 与 switch 职责；compiler 逐 cycle 安排 transfer，即 Scheduled, Not Routed；plesiochronous link 每 256 cycle 交换 Hardware-Aligned Counter 保持 lockstep，以 FEC 代替 retransmission，避免 retry 破坏 schedule；70B model 占用整个机柜 SRAM*

### Scale-out

节点继续连接成 Dragonfly。9 个节点组成 72 芯片机柜，第九个作为 hot spare，因此有 64 枚工作芯片。Topology specification 最多扩到 10,440 枚芯片，任意两点相距少于 6 hop。互连网络使用software-scheduled networking，路由与 flow control 移到编译期，论文称之为 Scheduled, Not Routed。

编译器已经证明 receiver 会在指定周期 ready，因此系统不需要 back-pressure 与动态 arbitration。链路使用 forward error correction 取代 retransmission，因为 retry 会扰乱调度。独立 clock 芯片要维持机柜 lockstep，链路采用 plesiochronous 方式；互连网络每 256 周期通过 spanning tree 交换 Hardware-Aligned Counter，维护 global consensus time，并用 periodic deskew 指令短暂停顿芯片，让它们重新对齐。

Groq 报告 8-way all-reduce 在 large 张量上达到 A100/NVSwitch 节点水平，在 small 张量上更快，因为 scheduled 互连网络省去动态互连网络 handshake 延迟。

内存容量策略的物理成本也直接显现。Model replica 是一个或多个机柜。某项分析显示，Llama-2 70B 在约 576 枚芯片上运行，同时配置 144 枚主机 CPU 与 144 TB 主机 RAM；8-GPU 服务器只需两枚 CPU。每枚 14 nm GlobalFoundries 芯片成本较低，据报低于 6,000 美元，H100-class part 约 16,000 美元；完整系统需要数百枚，decode 时大量计算闲置，SRAM 承担主要工作。

SemiAnalysis 的结论是：以延迟为目标时，LPU 的每 token bill of materials 有优势；开始 batching 并优化单位成本吞吐量后，GPU 大约领先一个数量级。Groq 直接以 speed 竞争。

### 软件

Groq 的编程模型可以概括为“编译器就是机器”。系统不向开发者暴露 kernel 接口。开发者把 PyTorch、TensorFlow 或 ONNX 模型交给 Groq 编译器，编译器将其降低成一组小型张量操作，并静态安排每条指令、每条数据流和每次芯片间传输。硬件行为完全静态，开发者也无需编写 `wgmma` 或手工调整 tile。

Groq 的案例是由不足十人的团队在四天内 bring up LLaMA；同一模型在 GPU 上往往需要数月 hand-kernel tuning。编译器周围只有较小且 closed 的 profiler、运行时与 `GroqFlow` bring-up 路径。公司停止售 card、转向售 token 后， `GroqFlow` 于 2025 年 archive。

LPU 从结构上专注推理。独立测量支持 single-user decode 延迟的领先地位，Artificial Analysis 将 Groq 列为 open 模型上 token/s 最快的 provider 之一。它的边界也很明确：模型超过一机柜 SRAM、负载需要大 batch 追求单位成本吞吐量、动态 control flow 无法由静态调度表表达时，匹配度很低。MoE 已经投入服务，但 data-dependent expert 路由与预先掌握全部信息的编译器存在张力，Groq 很少公开具体协调机制。

2025 年 12 月，NVIDIA 获得 LPU technology non-exclusive license，并聘用 Ross 与大部分团队。依据 NVIDIA 10-K，产品、customer contract 与 equity 均未转移，因此这笔交易属于 license + hiring；closing payment 约 130 亿美元，媒体常将其称作 acquisition。

GTC 2026 上，技术以 NVIDIA Groq 3 LPU 重新出现：256 枚 SRAM-only 推理芯片组成机柜，位于 Rubin NVL72 旁，并把 Transformer 分拆执行。GPU 运行 attention，LPU 运行 feed-forward 与 MoE 层，Dynamo 编排交接。AI 中最 deterministic 的架构最终成为最可编程架构内部的延迟协处理器。GroqCloud 仍在原始 14 nm 芯片上提供 token。

### 未来趋势

- **每枚芯片 FP8 已趋于接近。** B200 4.5 PF、Ironwood 4.6 PF、MI355X 10 PF，相差约 2 倍。单芯片算力已经接近，真正拉开差距的是单个机柜和整个 TPU 集群能连接多少芯片。
- **HBM 容量是 AMD 的持续优势。** 2023–2025 年从 192 → 256 → 288 GB，每代都达到或超过 NVIDIA。NVIDIA 到 2025 年末 B300 才追到 288 GB；Rubin Ultra 在 2026 年以每个封装 1 TB 重新领先。
- **2024–2025 年机柜级 scale-up 由 NVIDIA 领先。** GB200 / GB300 NVL72 是当时唯一交付的一致性机柜级互连系统。AMD 此前只能在单台服务器内连接 8 枚 GPU，直到 Helios 才扩展到完整机柜。TPU 选择了更大的扩展单元，直接用 torus 连接多台机柜中的数千枚芯片。
- **TPU 以数千芯片集群扩展，NVIDIA 以单机柜系统 scale-up。** Ironwood TPU 集群（pod）有 9,216 枚芯片、42.5 ExaFLOPS FP8；NVL576 有 576 枚 GPU、约 5 ExaFLOPS FP8。TPU 依靠数千枚芯片组成的大型集群获得更高总算力，但分摊到每枚芯片的互连带宽较低。
- **每枚芯片功耗快速增长。** Hopper 700 W → Blackwell 与 MI325X 1,000 W → B300 与 MI355X 1,400 W → Rubin Ultra 分析师估算约 1,800 W。超过约 1,000 W 后液冷成为必需，风冷基本止于 Hopper。
- **NVIDIA scale-out NIC 带宽每代翻倍。** Hopper CX-7 400 Gbps → Blackwell CX-8 800 Gbps → Rubin CX-9 1.6 Tbps。AMD Pollara 400 → Vulcano 800 落后一代，反映 Pensando 装机规模较小、整合时间较晚。
- **Cerebras 采用完全不同的存储方式。** 它有 44 GB 晶圆上 SRAM、21 PB/s 总带宽，每稠密 FLOP 约 1.3 字节；GPU 约 0.002。代价也在同一行：总内存少于单枚 H200，稠密 FLOPs/W 落后同期 GPU，scale-up 一栏为空，因为一致性互连域就是晶圆。
- **Trainium 主要依靠云服务成本竞争。** Trn2 每枚芯片 1.3 PF FP8，约为 MI355X 的四分之一。2024 年，Trn2 UltraServer 与 NVL72 同期实现由 64 枚芯片组成的机柜级互连系统，采用基于消息传递的 torus；Trn3 随后转为 NeuronSwitch 交换式互连网络。AWS 掌握从 Nitro card 到 API 的完整技术栈，Anthropic 超过一百万枚 Trainium2 的部署已经验证了它支撑前沿模型的能力。
- **Groq 牺牲单芯片容量来换取 SRAM 带宽，再通过增加芯片数量扩大内存池。** 第一代 GroqRack 的 64 枚工作芯片合计只有 14 GB；Groq 3 LPX 扩到 256 枚芯片、128 GB SRAM、40 PB/s SRAM 总带宽。12 TB DDR5 层级与 Rubin 配对说明，LPU 用于补充大内存 GPU 机柜。
