## 45.解释 KV Cache 的原理，为什么能加速自回归推理？高频

答案要点<br>**原理：** 在自回归生成中，生成第 t+1 个 token 时，需要计算所有前 t 个 token 的 Attention。如果不缓存，每次都要重新计算所有前序 token 的 K 和 V 矩阵。KV Cache 将之前计算好的 K、V 矩阵缓存起来，每次只需计算新 token 的 K、V。<br>**加速效果：** 将 Attention 的计算复杂度从 O(n²·d) 降到 O(n·d)（n 为已生成 token 数）。生成第 t 个 token 时，只需 O(t·d) 而非 O(t²·d)。<br>深度解释<br>KV Cache 是**推理优化的基础**，几乎所有推理框架都使用。但 KV Cache 的显存占用随序列长度线性增长，成为长上下文推理的瓶颈。PagedAttention、GQA、MLA 等技术都是为了优化 KV Cache 的显存效率。

## 46.什么是 Speculative Decoding（推测解码）？如何加速推理？2026 新题进阶

答案要点<br>**原理：** 使用一个小的"草稿模型"（draft model）快速生成多个候选 token，然后用大模型并行验证这些 token 的正确性。如果草稿模型的预测正确，一次前向就可以验证多个 token。<br>**加速效果：** 在理想情况下（草稿模型准确率高），可以实现 2-3 倍加速。因为大模型的前向计算是瓶颈，而小模型的前向计算快得多。<br>深度解释<br>Speculative Decoding 的**关键 trade-off**：草稿模型越快，单次验证的 token 越多，但准确率可能越低（拒绝率高）。需要找到速度和准确率的平衡点。Medusa 等改进方法使用多个预测头替代草稿模型。

## 47.什么是 Prompt Caching？在什么场景下效果最好？2026 新题进阶

答案要点<br>**Prompt Caching：** 缓存 System Prompt 或用户 Prompt 的 KV Cache，当多个请求共享相同的前缀时，可以复用缓存的计算结果，避免重复计算。<br>**最佳场景：** ① 共享 System Prompt 的多轮对话；② 大量请求使用相同的指令模板；③ RAG 场景中，检索到的上下文片段可能被多个请求复用。

深度解释<br>Prompt Caching 在**实际部署中效果显著**。对于包含长 System Prompt 的应用（如 Agent 场景），缓存可以节省 50-80% 的 Prefill 计算。OpenAI、Anthropic 等 API 提供商已经支持自动 Prompt Caching。

## 48.什么是 Disaggregated Prefill（分离式预填充）？为什么能提升吞吐？2026 新题高阶

答案要点<br>**原理：** 将推理过程分为 Prefill（预填充）和 Decode（解码）两个阶段，分别部署在不同的 GPU 集群上。Prefill 阶段计算密集（处理整个 Prompt），Decode 阶段访存密集（逐 token 生成）。<br>**为什么能提升吞吐：** ① Prefill 和 Decode 的计算特征不同，分离后可以针对性地优化硬件利用；② Prefill 节点不需要 KV Cache 缓存（只需传输到 Decode 节点）；③ 可以独立扩缩容（Prefill 节点少而强，Decode 节点多而均衡）。<br>深度解释<br>Disaggregated Prefill 是 2025-2026 年**大规模推理部署的趋势**。Google、DeepSeek 等公司都在使用。核心 insight：Prefill 受计算瓶颈（compute-bound），Decode 受显存带宽瓶颈（memory-bound），混合部署会导致资源浪费。

## 49.什么是 Continuous Batching（连续批处理）？vLLM 如何实现？高频

答案要点

**Continuous Batching：** 传统批处理需要等整个 batch 所有序列生成完成后才返回。连续批处理允许动态地将新请求加入正在运行的 batch，当一个序列生成完成时立即返回并加入新序列。<br>**vLLM 的实现：** ① 使用迭代级调度（iteration-level scheduling），每步 Attention 计算后检查是否有序列完成；② 新请求的 Prefill 与已有请求的 Decode 可以混合在一个 batch 中计算；③ 通过 PagedAttention 管理不同序列的 KV Cache。<br>深度解释<br>Continuous Batching 是**vLLM 的核心竞争力**。相比传统批处理，吞吐量可以提升 2-4 倍。因为 GPU 利用率更高——传统批处理中，短序列完成后 GPU 空闲等待；连续批处理中，GPU 始终在处理有效计算。

## 50.解释 Decoding 策略：Greedy Search、Beam Search、Top-k、Top-p、Temperature 的原理与选择？高频

答案要点

- **Greedy Search**：每一步选概率最高的 token。确定性高但可能陷入局部最优。
- **Beam Search**：维护 k 个候选序列，每一步扩展后保留总分最高的 k 个。适合翻译等需要全局最优的任务。
- **Top-k Sampling**：从概率最高的 k 个 token 中采样。k 越大越随机。
- **Top-p (Nucleus) Sampling**：从累积概率达到 p 的最小 token 集合中采样。动态调整候选集大小。
- **Temperature**：缩放 softmax 前的 logits。T→0 趋近 greedy，T→∞ 趋近均匀采样。

**选择：** 创意写作用 Top-p (0.9) + Temperature (0.7-0.9)；事实问答用 Temperature (0.1-0.3)；代码生成用 Temperature (0.1-0.2)。

## 51.什么是 Test-Time Scaling？推理时增加计算量如何提升模型性能？2026 新题高阶

答案要点<br>**Test-Time Scaling（测试时缩放）：** 在推理阶段增加计算量来提升模型性能。与训练时的 Scaling Law 对应。<br>**实现方式：**

- **Chain-of-Thought 扩展**：让模型生成更长的推理链，增加思考深度
- **多次采样 + 投票**：对同一个 prompt 采样多个回答，通过投票选择最佳答案
- **Best-of-N**：生成 N 个候选，用验证器（Verifier）选择最佳
- **Tree Search**：在推理过程中进行树搜索，探索多条推理路径

深度解释<br>Test-Time Scaling 是 2025-2026 年**最重要的趋势之一**。OpenAI o1/o3 和 DeepSeek-R1 都展示了"推理时思考更久"可以显著提升复杂任务性能。这改变了传统的"训练好模型后推理就是固定成本"的认知。
