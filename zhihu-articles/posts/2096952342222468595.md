> 目标：把业务世界变成可复现、可回溯、可切分的训练素材。 本层的核心矛盾：数据是活的，训练要求数据是死的。

### 1. 数据层的五个职责

| 职责 | 输出 | 失败后果 |
| --- | --- | --- |
| 采集 | 原始数据落湖，带来源与时间戳 | 无数据可训练 |
| 脱敏 | 合规的数据，带分级与审计 | 合规风险 |
| 清洗 | 无缺失、无重复、无异常的数据 | 模型学到错误信号 |
| 标注 | 带标签的样本集，带标注规范与一致性 | 模型学到错误信号 |
| 存储 | 列存文件，带统计信息与版本 | 查询慢、无法回溯 |
| 切分 | 训练集、验证集、测试集，边界正确 | 评测结果虚高 |
| 校验 | 阻断式的质量门禁 | 脏数据静默流入 |
| 特征 | 离线在线一致的特征，带时间点 | 线上线下效果不一致 |

### 2. 数据采集与隐私

### 2.1 采集的三个原则

1. 来源可追溯。每条数据必须能回答「从哪来、什么时候来、谁负责」。
2. 写入幂等。同一事件重复投递不得产生重复记录。
3. 模式稳定。schema 变更必须显式声明，不得静默失败。

### 2.2 PII 的分类

脱敏前必须先分类。不同类别用不同手段。

| 类别 | 示例 | 敏感等级 | 允许的处理 |
| --- | --- | --- | --- |
| 直接标识符 | 姓名、身份证、护照号 | 高 | 必须假名化或删除 |
| 间接标识符 | 地址、生日、邮编、设备 ID | 中 | 泛化或分桶 |
| 准标识符组合 | 生日加性别加邮编 | 高 | 必须评估再发布 |
| 敏感属性 | 健康、宗教、政治倾向、性取向 | 极高 | 默认禁止采集 |
| 自由文本 | 评论、日志、客服记录 | 高 | 需正则加分类器扫描 |
| 数值型敏感字段 | 收入、病史、消费额 | 中 | 差分隐私加噪 |

推论：自由文本是最容易漏的一类。正则只能覆盖已知格式。必须叠加分类器。

### 2.3 六种脱敏手段

| 手段 | 做法 | 可逆 | 适用 |
| --- | --- | --- | --- |
| 假名化 Pseudonymization | 原始 ID 换成随机令牌 | 用映射表可逆 | 主标识符 |
| 掩码 Masking | 部分字符替换 | 否 | 展示层 |
| 泛化 Generalization | 精确值换成区间 | 否 | 年龄、地理 |
| 分桶 Bucketing | 连续值离散化 | 否 | 收入、时长 |
| 抑制 Suppression | 稀有类别直接删除 | 否 | 高基数的准标识符 |
| 加噪 Perturbation | 数值加随机噪声 | 否 | 统计型敏感字段 |

关键区别：假名化不是匿名化。假名化数据仍属于个人数据，受同等法规约束。

### 2.4 PII 处理流程

PII 处理必须在数据落地前完成，不在训练时完成。

| 阶段 | 动作 | 说明 |
| --- | --- | --- |
| 采集侧 | 假名化 | 直接用哈希或令牌替代原始标识 |
| 采集侧 | 格式归一 | 去除空格、全半角、大小写，避免绕过扫描 |
| 存储侧 | 掩码 | 姓名、证件、手机号按规则掩码 |
| 存储侧 | 分类分级 | 标注每列的敏感等级 |
| 存储侧 | 原文隔离 | 自由文本原文放隔离区，训练库只存脱敏版 |
| 使用侧 | 最小必要 | 只取模型需要的列 |
| 使用侧 | 准标识符评估 | 计算 k-匿名性与 l-多样性 |
| 使用侧 | 差分隐私 | 对数值型敏感字段加噪 |
| 出口侧 | 二次扫描 | 训练完成前再扫一次，防止链路遗漏 |
| 出口侧 | 审计 | 记录谁在何时访问了敏感表 |

### 2.5 差分隐私的噪声量

差分隐私通过给查询结果加噪，使单条记录的存在与否不影响整体结论。

$$ \varepsilon = \frac{\Delta_1}{\delta}, \quad \Delta_1 \le \frac{1}{N} \left(1 + \ln\frac{1}{\delta}\right) $$

变量含义：$\varepsilon$ 为隐私预算，$\Delta_1$ 为敏感度，$N$ 为样本量，$\delta$ 为失败概率。

| 配置 | 噪声强度 | 模型效果 | 适用 |
| --- | --- | --- | --- |
| \varepsilon 为 10 | 很小 | 几乎无损 | 内部数据 |
| \varepsilon 为 1 | 中等 | 轻微下降 | 一般场景 |
| \varepsilon 为 0.1 | 大 | 明显下降 | 严格合规场景 |

推论：样本量越大，加噪越小。数据量不足时，差分隐私不可用。

### 2.6 k-匿名性与 l-多样性

准标识符组合可能间接重标识。必须评估。

k-匿名要求：任一条记录至少与另外 k-1 条记录在准标识符上不可区分。

l-多样性要求：每个等价类内的敏感属性至少有 l 种不同取值。

| k-匿名 | 风险 | 行动 |
| --- | --- | --- |
| 小于 5 | 高 | 泛化或抑制 |
| 5 到 10 | 中 | 可接受 |
| 大于 10 | 低 | 安全 |

推论：只做 k-匿名不够。若等价类内敏感属性全相同，仍可推断。需要同时满足 l-多样性。

### 2.7 脱敏的常见失效方式

| 失效方式 | 说明 | 对策 |
| --- | --- | --- |
| 哈希可被彩虹表反查 | 邮箱、手机号等低熵值哈希可逆 | 加盐哈希，盐存 KMS |
| 泛化过度导致信息全失 | 全部年龄都变成 0 到 100 | 按业务需要定分桶粒度 |
| 多表关联后重标识 | 单表安全，联合查询泄漏 | 关联前评估联合风险 |
| 日志泄漏 | 训练日志中打印原始样本 | 日志脱敏，加扫描 CI |
| 标注平台泄漏 | 标注界面显示真实姓名 | 标注平台用假名 |
| 导出未脱敏 | 分析师导出的原始表 | 导出走审批与审计 |

### 3. 标注质量

### 3.1 一致性系数 Kappa

Kappa 衡量标注者之间的一致程度，同时修正随机一致带来的虚高。

$$ \kappa = \frac{P_o - P_e}{1 - P_e} $$

变量含义：$P_o$ 为实际一致率，$P_e$ 为随机一致率。

| Kappa 区间 | 解读 | 行动 |
| --- | --- | --- |
| 小于 0.40 | 一致性差 | 重写标注规范，重新培训 |
| 0.40 到 0.60 | 一般 | 补充边界案例，返工一部分 |
| 0.60 到 0.80 | 良好 | 可接受 |
| 大于 0.80 | 优秀 | — |

### 3.2 Cohen’s Kappa 与 Fleiss’ Kappa

| 指标 | 适用 | 说明 |
| --- | --- | --- |
| Cohen’s Kappa | 两个标注者 | 简单，但只覆盖两两 |
| Fleiss’ Kappa | 多个标注者 | 更稳健，推荐 |

### 3.3 标注流程的设计要点

1. 规范先行。规范必须含正例、反例、边界案例。
2. 试点先行。先标 200 条测 Kappa，达标再铺量。
3. 抽检持续。每批抽 5% 复标，监控 Kappa 是否下降。
4. 分歧入库。分歧样本单独入库，用于后续主动学习。
5. 标注者对结果负责。标注者能看到模型的历史表现。

### 3.4 分歧仲裁

| 层级 | 触发条件 | 处理方式 |
| --- | --- | --- |
| 自动对齐 | Kappa 大于 0.8 | 直接接受 |
| 人工复核 | Kappa 0.6 到 0.8 | 资深标注者复核 |
| 专家仲裁 | Kappa 小于 0.6 或争议样本 | 领域专家裁定并写入规范 |

### 4. 数据清洗与去重

数据层最容易被跳过的一章。跳过它，训练层和评估层会持续为它付账。

### 4.1 清洗的六个维度

| 维度 | 处理对象 | 典型动作 |
| --- | --- | --- |
| 完整性 | 缺失值 | 填充、删除、标记 |
| 一致性 | 冲突值 | 统一格式、裁决 |
| 有效性 | 越界值 | 裁剪、剔除 |
| 唯一性 | 重复记录 | 去重 |
| 时效性 | 过期数据 | 按时间窗过滤 |
| 异常 | 离群点 | 截断、隔离 |

### 4.2 缺失值的四种处理

选择取决于缺失机制。机制判断错误会引入偏差。

| 机制 | 特征 | 处理方式 |
| --- | --- | --- |
| 完全随机 MCAR | 缺失与任何变量无关 | 直接删除或填充 |
| 随机缺失 MAR | 缺失依赖已观测变量 | 用观测变量建模填充 |
| 非随机 MNAR | 缺失依赖未观测变量 | 只能做敏感性分析 |
| 信息缺失 | 缺失本身是信号 | 保留缺失标记作为特征 |

关键判断：缺失比例超过 30% 的列通常应考虑删除，而不是填充。

```python
import numpy as np
import pandas as pd

def handle_missing(df, col, strategy="auto"):
    """按缺失机制选择填充策略。"""
    missing_rate = df[col].isna().mean()

    # 缺失过多直接删列
    if missing_rate > 0.30:
        return df.drop(columns=[col]), "drop_column"

    if strategy == "auto":
        if df[col].dtype in (np.float64, np.int64):
            strategy = "median"
        else:
            strategy = "special"

    if strategy == "median":
        # 数值型：中位数填充，不用均值，抗离群
        df[col] = df[col].fillna(df[col].median())
    elif strategy == "special":
        # 类别型：用显式标记，不要用众数
        df[col] = df[col].fillna("__MISSING__")

    # 关键：额外加一个缺失标记列，让模型自己学
    df[f"{col}_was_missing"] = df[col].isna().astype(int)

    return df, strategy
```

推论：均值填充会拉低分布方差。用中位数。中位数填充会掩盖「缺失」这一信号。因此必须额外加标记列。

### 4.3 重复的四种类型

| 类型 | 定义 | 判别方法 | 处理 |
| --- | --- | --- | --- |
| 完全重复 | 整行相同 | 全部字段哈希 | 保留一条 |
| 主键重复 | 实体 ID 相同内容不同 | 按 ID 分组 | 按规则裁决 |
| 内容近似重复 | 字段有微小差异 | 相似度哈希 | 相似度超阈值则合并 |
| 语义重复 | 表达不同含义相同 | 嵌入向量 | 向量检索去重 |

### 4.3.1 完全重复

```python
import hashlib

def dedup_exact(df, subset=None):
    """去除完全重复的行。"""
    before = len(df)
    # subset 指定参与判重的列，None 表示全部列
    df = df.drop_duplicates(subset=subset, keep="first")
    return df, before - len(df)
```

### 4.3.2 内容近似重复

SimHash 把高维向量压成固定长度的指纹。相似内容的指纹汉明距离小。

```python
import hashlib
import numpy as np

def simhash(tokens, bits=64):
    """对 token 序列计算 SimHash。"""
    vector = np.zeros(bits)
    for token in tokens:
        h = int(hashlib.md5(token.encode()).hexdigest(), 16)
        for i in range(bits):
            vector[i] += 1 if (h >> i) & 1 else -1
    # 取每一位的正负作为 0/1
    return np.where(vector > 0, 1, 0)

def hamming(a, b):
    return int(np.count_nonzero(a != b))

def dedup_near(df, text_col, threshold=6, bits=64):
    """按 SimHash 近似去重。threshold 为汉明距离阈值。"""
    seen = {}          # simhash -> 首个出现的行索引
    drop_idx = []

    for idx, text in zip(df.index, df[text_col]):
        if not isinstance(text, str) or not text.strip():
            continue
        sig = simhash(text.lower().split(), bits)
        found = False
        for prev_sig, prev_idx in seen.items():
            if hamming(sig, prev_sig) <= threshold:
                drop_idx.append(idx)
                found = True
                break
        if not found:
            seen[sig] = idx

    return df.drop(index=drop_idx), len(drop_idx)
```

| 汉明距离阈值 | 去重强度 | 误杀风险 |
| --- | --- | --- |
| 小于等于 3 | 只删几乎相同 | 低 |
| 4 到 6 | 删近似重复 | 中 |
| 7 到 10 | 激进 | 高，会误杀合法样本 |

### 4.3.3 语义重复

语义重复指表达不同但含义相同。用于客服问答、FAQ、指令数据。

```python
import numpy as np

def dedup_semantic(embeddings, threshold=0.95):
    """按嵌入余弦相似度去重。"""
    n = len(embeddings)
    norm = embeddings / (np.linalg.norm(embeddings, axis=1, keepdims=True) + 1e-8)
    sim = norm @ norm.T

    drop = set()
    for i in range(n):
        if i in drop:
            continue
        for j in range(i + 1, n):
            if j in drop:
                continue
            if sim[i, j] >= threshold:
                drop.add(j)      # 保留 i，丢弃 j

    return drop
```

| 相似度阈值 | 语义 | 建议 |
| --- | --- | --- |
| 0.99 | 几乎同义 | 删 |
| 0.95 | 高度相似 | 删或合并 |
| 0.90 | 相关但不同 | 保留 |

### 4.4 主键重复的裁决规则

| 场景 | 裁决规则 |
| --- | --- |
| 特征表多次更新同一实体 | 取 feature_time 最新的一条 |
| 标签表有冲突标注 | 取多数票，或取最新标注 |
| 冲突无法自动裁决 | 保留全部，打上冲突标记，交人工处理 |
| 交易流水类 | 不能去重。重复可能是真实业务事件 |

关键区分：事实表重复通常是真实业务。去重会丢信息。维表重复才是数据问题。

### 4.5 去重对训练的影响

去重不是无害操作。每一次删除都改变数据分布。

| 影响 | 机制 | 后果 |
| --- | --- | --- |
| 类分布偏移 | 重复样本常集中在少数类别 | 去重后该类别占比下降 |
| 长尾被削弱 | 罕见样本更容易重复 | 长尾样本进一步减少 |
| 评测方差增大 | 有效样本数减少 | 置信区间变宽 |
| 数据泄漏风险 | 同一实体多行被删剩一行 | 影响小于跨集合重复 |
| 记忆效应 | 原始数据中重复样本被强化 | 去重后泛化可能反而提升 |

结论：对 LLM 训练，适度去重通常提升泛化。对小样本分类任务，去重可能有害。

### 4.6 异常值处理的四条边界

| 处理 | 适用 | 破坏 |
| --- | --- | --- |
| 裁剪到分位数 | 数值特征有明显异常值 | 丢失尾部信息 |
| 对数变换 | 严重长尾 | 改变分布，需重新评估 |
| IQR 剔除 | 明确的多重离群 | 正态分布上会误删 0.3% |
| 隔离到单独表 | 需要保留但不参与训练 | 需建立回流机制 |

绝对阈值只在业务硬约束时使用。例如金额必须为正。

```python
import numpy as np

def handle_outliers(df, col, method="clip", lower_q=0.001, upper_q=0.999):
    """处理异常值。返回处理后的列与被影响的记录索引。"""
    s = df[col]
    lo, hi = s.quantile(lower_q), s.quantile(upper_q)

    if method == "clip":
        df[col] = s.clip(lo, hi)
        affected = df.index[(df[col] != s)]
        return df, affected

    if method == "log":
        if (s <= 0).any():
            raise ValueError("对数变换要求列全为正，请先处理非正值")
        df[col] = np.log1p(s)
        return df, df.index[~np.isclose(df[col], np.log1p(s))]

    if method == "isolate":
        mask = (s < lo) | (s > hi)
        return df, df.index[mask]

    raise ValueError(f"未知方法：{method}")
```

推论：裁剪必须记录原值。没有原值就无法事后分析被裁剪的样本。

### 4.7 清洗的顺序

顺序不可颠倒。有依赖关系。

```text
1. 格式归一 → 2. 合法性校验 → 3. 缺失处理 → 4. 类型转换
→ 5. 异常处理 → 6. 主键去重 → 7. 近似去重 → 8. 标签核对
```

| 顺序错误 | 后果 |
| --- | --- |
| 先去重后归一 | 格式差异使重复识别不出来 |
| 先填充后类型转换 | 填充值类型不匹配 |
| 先标准化后去重 | 已污染的均值被算入 |
| 先切分后去重 | 测试集样本被删，测试集变小 |

推论：切分必须在所有清洗完成之后。清洗本身会使用统计量，会引入信息泄漏。

### 4.8 清洗的可追溯性

每一条清洗操作必须留痕。

| 记录内容 | 用途 |
| --- | --- |
| 操作类型 | 知道做了什么 |
| 涉及列 | 定位影响范围 |
| 影响行数 | 评估影响面 |
| 前后样本 | 抽查质量 |
| 参数配置 | 可复现 |
| 操作代码版本 | 可回滚 |

推论：无法复现的清洗等于数据损坏。清洗逻辑必须与数据一起版本化。

### 5. 数据切分

### 5.1 三种切分方式

| 方式 | 做法 | 适用 | 风险 |
| --- | --- | --- | --- |
| 随机切分 | 打散后按比例切 | 各样本独立同分布 | 有实体泄漏风险 |
| 实体切分 | 按用户或设备分组切 | 有重复实体 | 组必须完整落在同一侧 |
| 时间切分 | 按时间先后切 | 有时间依赖 | 需要时间点正确的特征 |

### 5.2 三种切分必须同时满足

1. 同一实体不得跨集合。
2. 训练集时间必须早于验证集时间。
3. 特征取值不得依赖预测时点之后的信息。

违反任意一条，评测结果不可信。

### 5.3 类别不平衡的切分

分层切分：按标签比例分层，保证各集合的正负比例一致。

```python
from sklearn.model_selection import train_test_split

# 分层切分，保持正负比例一致
train, temp = train_test_split(
    df, test_size=0.30, random_state=42,
    stratify=df["label"]
)
val, test = train_test_split(
    temp, test_size=0.50, random_state=42,
    stratify=temp["label"]
)
```

实体切分加分层切分：先按实体分组，再在组内分层。

6.1 为什么 ML 必须用列存

ML 的分析型查询只用到少数列。行存会把整行读入，浪费绝大部分 IO。

查询示例：

```sql
SELECT SUM(age) FROM users WHERE city = '上海';
```

该查询只用到两列。列存只读两列，行存要读全部列。

### 6.2 Parquet 文件结构

| 组件 | 内容 | 用途 |
| --- | --- | --- |
| Row Group | 一个独立可读的列式块 | 并行读取的最小粒度 |
| Column Chunk | 某列在某个 Row Group 内的数据 | 压缩与编码单位 |
| Page | 一段连续数据，128 KB 左右 | 谓词下推的最小粒度 |
| Footer | 每列每页的 min 与 max、偏移量 | 下推与随机访问 |

### 6.3 谓词下推的工作方式

1. 读取 Footer，取出每页的 min 与 max。
2. 对过滤条件求值，跳过不可能匹配的页。
3. 只解压需要的列。

示例：条件 `age > 30`，某页 min 18、max 25，则该页必然不满足，直接跳过。

### 6.4 为什么 ML 数据集 IO 常常很差

随机分布的 float32 特征列，其 min 与 max 接近全值域，谓词下推失效。

| 问题 | 原因 | 对策 |
| --- | --- | --- |
| 逐行读慢 100 倍 | 逐行读触发随机访问 | 顺序读加内存 shuffle |
| 压缩率低 | float32 高熵 | 转 float16 或缩放为 int16 |
| 小文件过多 | 分区过细 | 合并小文件，目标 128 MB 到 1 GB |
| Shuffle 慢 | 分区不均 | 重分区加数据倾斜处理 |

### 6.5 编码方式

| 编码 | 适用列 | 原理 |
| --- | --- | --- |
| Dictionary | 低基数类别 | 建哈希表，列内只存下标 |
| RLE | 大量连续相同值 | 记录重复次数 |
| Bit Packing | 低位宽整数 | 每值只存有效位 |
| Delta | 单调或近似等差序列 | 只存相邻差值 |

ML 数据集中，低基数类别列极常见。Dictionary 编码是收益最高的单项优化。

### 6.6 关键参数

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| parquet.block.size | 128 MB 到 256 MB | 太大则下推粒度粗，太小则元数据开销大 |
| parquet.enable.dictionary | 开启 | 类别列必开 |
| parquet.compression | ZSTD 或 Snappy | ZSTD 压缩率高，Snappy 解压快 |
| Row Group 大小 | 128 MB 到 512 MB | 与单核读取粒度匹配 |

### 8. 分布式计算：Spark

### 8.1 Shuffle 的代价

Shuffle 是分布式计算的主要性能瓶颈。

Shuffle 的数据量：

$$ \text{shuffle bytes} \approx \sum_{i=1}^{N} \text{shuffle write}_i \times (N - 1) $$

变量含义：$N$ 为分区数，shuffle write 为各分区写出的数据量。

结论：数据倾斜会被放大 N 倍。这是倾斜处理的核心依据。

### 8.2 数据倾斜的三种处理

| 方法 | 做法 | 适用 | 代价 |
| --- | --- | --- | --- |
| 过滤 | 直接剔除热点 key | 热点占比极低 | 丢失样本 |
| 加盐 Salting | 热点 key 拆成 N 份随机后缀 | 热点但不能丢 | 需下游二次聚合 |
| 两阶段聚合 | 先局部聚合，再全局聚合 | 热点不极端 | 多一个阶段 |

加盐的 Python 实现：

```python
from pyspark.sql import functions as F

# 第一阶段：加盐打散，只做局部聚合
salted = df.withColumn(
    "salt",
    F.when(F.col("user_id") == "hot_user",
           F.rand(1000).cast("string"))
    .otherwise(F.lit("0"))
)

partial = salted.groupBy("user_id", "salt") \
                .agg(F.sum("amount").alias("amt_sum"))

# 第二阶段：去掉盐，合并同一 key 的所有分片
final = partial.groupBy("user_id") \
               .agg(F.sum("amt_sum").alias("amount"))
```

### 8.3 Spark 调优要点

| 项 | 建议 | 说明 |
| --- | --- | --- |
| 分区数 | 约为任务并行度的 2 到 3 倍 | 太多导致小文件，太少导致倾斜 |
| Shuffle 分区数 | 设为上游分区数的 2 到 3 倍 | 缓解数据倾斜 |
| AQE | 开启 | 自动合并小分区，处理倾斜 |
| 广播连接 | 小表小于 512 MB 时广播 | 避免大表 shuffle |
| 数据倾斜处理 | 开启 AQE skew join | 自动处理 |

### 9. 流计算：Flink

### 9.1 事件时间与水位线

事件时间指事件实际发生的时间。水位线是处理系统对「当前时间」的估计。

| 概念 | 定义 | 作用 |
| --- | --- | --- |
| 事件时间 | 事件携带的业务时间戳 | 保证乱序数据的结果正确 |
| 处理时间 | 系统收到事件的时间 | 延迟最低，但结果不可复现 |
| 水位线 | 事件时间的进度估计 | 触发窗口计算 |

水位线的关系：

$$ W = \max(\text{已到达事件时间}) - \text{最大乱序延迟} - \epsilon $$

变量含义：$\epsilon$ 为容差，通常取毫秒级。

### 9.2 开窗的三种策略

| 策略 | 触发条件 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 滚动窗口 Tumbling | 固定长度，对齐时间边界 | 简单 | 可能跨边界切断事件 |
| 滑动窗口 Sliding | 固定长度，按步长滑动 | 无边界问题 | 计算量放大 |
| 会话窗口 Session | 不活动间隔划分 | 贴近用户行为 | 结果依赖不活动阈值 |

### 9.3 状态管理

| 机制 | 用途 | 容量 |
| --- | --- | --- |
| Keyed State | 按 key 保存的中间状态 | 随数据量增长 |
| Operator State | 算子级别的状态 | 通常较小 |
| Checkpoint | 周期性快照 | 可配置间隔 |
| Savepoint | 手动快照 | 可长期保存 |

Watermark 落后阈值的作用：水位线落后超过阈值时判定为流异常，避免无限等待。

### 9.4 批流一体的真正含义

批流一体不是「同一套代码」。批流一体是「同一份状态定义和同一份时间语义」。

| 维度 | 批 | 流 |
| --- | --- | --- |
| 数据边界 | 明确 | 持续追加 |
| 时间语义 | 按分区时间 | 按水位线 |
| 回溯方式 | 重跑分区 | 从保存点恢复 |
| 状态 | 无或简单 | 有状态 |
| 结果确定性 | 天然确定 | 依赖水位线 |

推论：批流共用的代码必须显式传入时间语义，不能依赖框架默认值。

### 10. 特征工程与特征存储

### 10.1 离线在线一致性问题

![](https://pic2.zhimg.com/v2-65a80286663bf7e995954dcd29656335_r.jpg)
*图 5 · 数据层三大静默故障*

**训练与服务偏斜**：训练时用的特征值与线上推理时算出的特征值不一致。

根因是特征逻辑写了两遍。离线用 Python 或 Spark，在线用 Java 或 Go。

两类实现必然在六个点上产生差异：

| 差异点 | 离线 Spark | 在线服务 | 对齐方法 |
| --- | --- | --- | --- |
| 空值表示 | NaN | null 或业务默认值 | 统一编码值 |
| 时间边界 | 左闭右开 | 两端都闭 | 统一半开区间 |
| 浮点精度 | double | float | 统一精度并做容差比较 |
| 时区 | UTC | 本地时区 | 全链路统一 UTC |
| 数值溢出 | 不溢出 | 可能溢出 | 统一取值范围 |
| 聚合触发 | 按窗口批量 | 按事件实时 | 统一聚合语义 |

**时间点正确性**：训练时用的特征值必须是「预测那一刻」真实存在的值。

```sql
-- 错误：普通 join，会用到预测时点之后的标签
SELECT o.*, l.label
FROM orders o
JOIN labels l ON o.user_id = l.user_id;

-- 正确：时间点 join
SELECT o.*
FROM orders o
JOIN labels l ON o.user_id = l.user_id
  AND l.feature_time <= o.predict_time;
```

**特征穿越**：特征里含预测时点不可用的信息。

| 穿越类型 | 表现 | 修复 |
| --- | --- | --- |
| 目标编码泄漏 | 统计编码时用了全量标签 | 用折外编码 |
| 归一化穿越 | 先 fit 再切分，导致测试集信息进入训练 | 先切分再 fit |
| ID 泄漏 | 模型记住用户编码，换用户即失效 | 不用原始 ID，或加嵌入平滑 |
| 时间穿越 | 用未来信息预测过去 | 严格时间点约束 |

折外目标编码：

```python
from sklearn.model_selection import KFold
import numpy as np

def out_of_fold_target_encode(df, col, target, n_splits=5, seed=42):
    """折外目标编码，避免泄漏。"""
    oof = np.full(len(df), np.nan)
    kf = KFold(n_splits=n_splits, shuffle=True, random_state=seed)

    for train_idx, val_idx in kf.split(df):
        # 只用训练折统计均值，赋给验证折
        means = df.iloc[train_idx].groupby(col)[target].mean()
        oof[val_idx] = df.iloc[val_idx][col].map(means).fillna(
            df.iloc[train_idx][target].mean()
        )

    return pd.Series(oof, index=df.index)
```

### 10.2 Point-in-time 正确性

Point-in-time join 的规则：取特征表中 `feature_time <= predict_time` 的最新一行。

```python
import pandas as pd

def point_in_time_join(features, labels, time_col="ts"):
    """对每个标签行，取该时刻之前最近的一条特征。"""
    features = features.sort_values(time_col)
    merged = pd.merge_asof(
        labels.sort_values(time_col),      # 左表必须按时间排序
        features,                          # 右表必须按时间排序
        on=time_col,
        direction="backward",              # 只往回看，绝不往前取
    )
    return merged
```

推论：`direction="backward"` 是关键。用 `nearest` 或 `forward` 会引入未来信息。

### 10.5 特征一致性校验

上线前必须做一次采样对比。

```python
import pandas as pd
import requests, time, uuid

def verify_consistency(n_samples=1000, tol=1e-4):
    """采样 n_samples 条线上请求，与离线计算结果对比。"""
    records = fetch_recent_inference_log(n_samples)
    mismatches, checked = [], 0

    for rec in records:
        offline = compute_features_offline(rec["context"])
        online = rec["features_online"]

        for k in offline:
            checked += 1
            a, b = float(offline[k]), float(online[k])
            # 容差比较：浮点精度差异不算错误
            if abs(a - b) > tol * max(1.0, abs(a)):
                mismatches.append({
                    "feature": k, "offline": a, "online": b,
                    "request_id": rec["request_id"],
                })

    return {
        "checked": checked,
        "mismatch_rate": len(mismatches) / max(1, checked),
        "samples": mismatches[:20],
    }
```

判定标准：不一致率必须小于 0.1%。超过则禁止上线。

### 11. 数据质量与校验

### 11.1 六个质量维度

| 维度 | 检查项 | 阻断条件 |
| --- | --- | --- |
| 完整性 | 必填列非空率 | 低于 99% |
| 唯一性 | 主键重复率 | 高于 0.1% |

### 11.2 数据契约

数据契约是上下游之间的书面约定，内容包括字段定义、类型、枚举、更新频率、责任人。

| 契约要素 | 说明 | 违约后果 |
| --- | --- | --- |
| Schema | 字段名、类型、是否可空 | 静默失败或崩溃 |
| 语义 | 每个字段的业务含义 | 用错字段 |
| 枚举 | 合法取值列表 | 下游处理失败 |
| 频率 | 更新频率与延迟 SLA | 特征陈旧 |
| 质量门禁 | 上线前的校验规则 | 脏数据流入 |
| 责任人 | 谁负责修复 | 无人修复 |

### 11.3 数据校验的七个层次

校验不是一层。分层校验才能覆盖全链路。

| 层次 | 检查类型 | 示例 | 典型频率 |
| --- | --- | --- | --- |
| L1 存在性 | 表与分区是否存在 | 表缺失、分区缺失 | 每次 |
| L2 Schema | 字段名、类型、可空 | 字段类型变更 | 每次 |
| L3 业务规则 | 值域、逻辑约束 | 金额必须为正 | 每次 |
| L4 统计分布 | 均值、分位数、基数 | 空值率突增 | 每次 |
| L5 参照完整性 | 外键、跨表一致 | 用户在维表中不存在 | 每次 |
| L6 业务对账 | 与上游或财务核对 | 日活与埋点差异 | 每天 |
| L7 时序连续性 | 指标是否突变 | 转化率一夜跌 50% | 每天 |

推论：L1 到 L4 是技术校验，能自动判定。L5 到 L7 需要业务规则定义与人工确认。

```python
import great_expectations as ge
from datetime import datetime, timedelta

def run_suite(df, dt):
    """按层次执行校验套件。"""

    # L1 存在性
    assert df is not None, f"表缺失 dt={dt}"

    # L2 Schema
    d = ge.from_pandas(df, expectations_suite_name="features")
    d.expect_column_values_to_not_be_null("user_id")
    d.expect_column_values_to_not_be_null("dt")
    # 显式声明类型，防止上游静默改类型
    d.expect_column_values_to_be_between("dt",
        min_value=dt - timedelta(days=1),
        max_value=dt + timedelta(days=1))

    # L3 业务规则
    d.expect_column_values_to_be_between("amount", 0, 1_000_000)
    d.expect_column_values_to_be_in_set(
        "channel", ["app", "web", "mini_program"]
    )
    d.expect_column_pair_values_A_to_be_greater_than_B(
        "end_time", "start_time"
    )

    # L4 统计分布（对照历史基线）
    stats = df["amount"].describe()
    assert stats["mean"] < 50_000, f"均值异常：{stats['mean']}"

    # L5 参照完整性
    known = set(read_dim_users().keys())
    missing = set(df["user_id"].unique()) - known
    assert len(missing) / max(1, df["user_id"].nunique()) < 0.001, \
        f"用户不存在比例过高：{len(missing)}"

    # L7 时序连续性
    today_rate = df["label"].mean()
    base_rate = read_baseline_rate(days=7)
    drift = abs(today_rate - base_rate) / (base_rate + 1e-9)
    assert drift < 0.5, f"标签率漂移 {drift:.2%}"

    result = d.validate()
    if not result.success:
        raise ValueError("校验失败，阻断下游")
    return result
```

### 11.4 校验的三个放置点

| 位置 | 时机 | 作用 |
| --- | --- | --- |
| 入口 | 数据落湖时 | 拦截上游错误 |
| 出口 | 训练取数时 | 拦截中间环节错误 |
| 在线 | 特征写出时 | 拦截服务侧错误 |

三个位置缺一不可。只在入口校验，无法发现中间环节引入的问题。

### 11.5 校验的边界条件

| 场景 | 常见错误 | 正确做法 |
| --- | --- | --- |
| 空表 | 校验全部通过 | 空表必须显式失败 |
| 单行数据 | 统计类校验失效 | 数据量小于阈值时跳过统计校验并标记 |
| 全为同一值 | 标准差为 0，除零 | 显式检查方差 |
| 新类别出现 | 枚举校验全量失败 | 允许未知类别进监控区，不进训练 |
| 时间戳精度 | 秒级与毫秒级混用 | 在契约中显式声明单位 |
| 时区缺失 | 跨时区计算错误 | 契约要求带时区的时间戳 |
| 极端值 | 均值被拉高 | 用中位数与分位数判断，不用均值 |
| 上游延迟 | 误判为数据缺失 | 区分「还没到」与「不该有」 |

```python
def validate_with_boundaries(df, min_rows=1000):
    """带边界条件的数据校验。"""

    # 边界一：空表必须失败，不能静默通过
    if df is None or len(df) == 0:
        raise ValueError("空数据集：拒绝放行")

    # 边界二：数据量过小时，统计类校验不可靠
    if len(df) < min_rows:
        # 只做硬性规则校验，跳过分布类
        return run_hard_rules_only(df), "partial_validated"

    # 边界三：方差为 0 时不做比值类判断
    for col in numeric_cols:
        if df[col].std() == 0:
            continue          # 常数列，跳过比值计算

    # 边界四：未知类别分流，不直接失败
    new_categories = check_categories(df)
    known_part = df[~df[col].isin(known_values)]
    quarantine(known_part, reason="unknown_category")

    return run_full_suite(df), "validated"
```

### 12. 数据版本与可复现

### 12.1 四维版本标识

一次训练运行必须绑定四个标识。

| 维度 | 标识方式 | 说明 |
| --- | --- | --- |
| 代码 | Git commit 加依赖锁文件 | 精确到依赖版本 |
| 数据 | 数据指纹 | 内容哈希或分区快照 ID |
| 配置 | 配置哈希 | 超参与运行参数的完整序列化 |
| 环境 | 镜像 digest 加框架版本 | 精确到镜像层 |

### 12.2 数据指纹

```python
import hashlib

def dataset_fingerprint(df):
    """对数据集生成稳定指纹，用于可复现与去污染。"""
    hasher = hashlib.sha256()
    # 按列名排序，保证顺序无关
    for col in sorted(df.columns):
        hasher.update(col.encode("utf-8"))
        # 按行排序后取值，保证行顺序无关
        values = sorted(df[col].astype(str).unique())
        for v in values:
            hasher.update(v.encode("utf-8"))
    return hasher.hexdigest()[:32]
```

推论：指纹应忽略行顺序但不能忽略内容。否则同一份数据不同读取顺序会产生不同指纹。

### 13. 数据缺陷对下游的影响链

这一章回答：数据层的一个问题，最终会以什么形式在训练层、评估层、推理层暴露出来。

### 13.1 影响链总表

| 数据缺陷 | 训练层表现 | 评估层表现 | 推理层表现 | 修复位置 |
| --- | --- | --- | --- | --- |
| 标签错误 | 损失不收敛或有下限 | 离线高分，线上低分 | 输出错但自信 | 标注流程 |
| 标签缺失 | 模型学不到该类 | 该类指标虚高 | 该场景无响应 | 标注流程 |
| 重复样本 | 记忆而非泛化 | 评测集含重复则虚高 | 遇重复输入过度自信 | 去重 |
| 类别不平衡 | 偏向多数类 | 总体指标掩盖 | 少数类质量差 | 重采样或加权 |
| 分布漂移 | 在旧分布上过拟合 | 评测集与线上不一致 | 效果随时间衰减 | 持续训练 |
| 特征穿越 | 训练收敛极快 | 离线极高，线上随机 | 完全不可用 | 切分与时间点 |
| 时间点错误 | 学到不存在的规律 | 离线虚高 | 线上崩塌 | PIT join |
| 训练服务偏斜 | — | 离线无法发现 | 线上低于离线 | 特征存储 |
| 空值填充不当 | 引入伪相关 | 指标虚高 | 遇到真实空值失效 | 缺失处理 |
| PII 未脱敏 | 合规风险 | — | 可能被套取 | 脱敏流程 |

### 13.2 一个真实故障的完整链条

假设一个推荐模型离线 AUC 0.89，上线后 CTR 下降 30%。

| 排查步骤 | 检查项 | 实际发现 | 判断 |
| --- | --- | --- | --- |
| 1 | 推理服务延迟、错误率 | 正常 | 排除系统问题 |
| 2 | 特征空值率 | 某特征空值率从 0 升到 60% | 输入分布漂移 |
| 3 | 变更记录 | 三天前上游改了埋点 | 找到根因 |
| 4 | 校验新埋点 | 该字段已改语义 | 数据契约未同步 |
| 5 | 回滚或修复 | 字段映射纠正 | 恢复 |

结论：这个故障从「上游埋点变更」开始，在「数据契约未同步」处失效，在「推理层」被感知，中间隔了三天。链路长是这类故障难以定位的根本原因。

### 13.3 每类缺陷的可检出性

| 缺陷 | 能否自动检出 | 检出手段 | 检出延迟 |
| --- | --- | --- | --- |
| Schema 变更 | 能 | Schema 注册比对 | 分钟级 |
| 类型变更 | 能 | 类型断言 | 分钟级 |
| 空值率突增 | 能 | 质量门禁 | 小时级 |
| 枚举值新增 | 能 | 枚举校验加监控 | 小时级 |
| 分布缓慢漂移 | 部分 | PSI 监控 | 天级 |
| 标签错误 | 难 | 人工抽检 | 周级 |
| 语义变更 | 难 | 人工确认加对账 | 月级 |
| 训练服务偏斜 | 部分 | 一致性采样校验 | 上线前 |
| 特征穿越 | 部分 | 消融实验加时间切分 | 上线前 |
| 上游业务规则变更 | 难 | 业务对账 | 月级 |

推论：越靠近「语义」层的问题，自动检出越难。必须配置人工确认环节。

### 13.4 每类缺陷的修复优先级

| 优先级 | 缺陷类型 | 理由 |
| --- | --- | --- |
| P0 | 特征穿越、训练服务偏斜 | 导致模型完全不可用 |
| P0 | PII 泄漏 | 合规风险，可能造成处罚 |
| P1 | 时间点错误、标签错误 | 导致模型学错目标 |
| P1 | Schema 与类型变更 | 导致流水线断裂 |
| P2 | 分布漂移 | 效果衰减，可通过重训缓解 |
| P2 | 重复样本、类别不平衡 | 影响上限，不致失效 |
| P3 | 空值填充、统计口径 | 细微影响 |

### 14. 训练-服务偏斜的系统性防治

### 14.1 五道防线

| 防线 | 手段 | 拦截时机 |
| --- | --- | --- |
| 第一道 | 特征定义单一来源 | 编码阶段 |
| 第二道 | 单元测试覆盖特征逻辑 | CI 阶段 |
| 第三道 | 一致性采样校验 | 上线前 |
| 第四道 | 线上特征分布监控 | 运行时 |
| 第五道 | 端到端效果监控 | 上线后 |

### 14.2 效果下降的排查顺序

按此顺序排查。不要跳步。

1. 上游数据源是否变更。用数据契约核对。
2. 服务侧代码是否发版。查变更记录。
3. 特征分布是否漂移。算 PSI。
4. 特征是否全部为空值。查空值率。
5. 用户结构是否变化。分层看效果。
6. 概念是否漂移。人工抽检。
7. 是否有漏斗前置环节改动。

前四项可在两小时内完成。第五项到第七项需要业务参与。
