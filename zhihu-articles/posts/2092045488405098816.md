> 有没有想过一个问题：同一个算法，换个循环写法，速度能差好几倍。现代编译器里藏着一套几乎像"魔法"的技术，它能把你的双重循环自动重排成最快的形态——这套技术的名字叫**多面体优化（Polyhedral Optimization）**。这篇文章用最朴素的方式，把它从头讲清楚。

## 一、一个"看起来很傻"的问题

先看两段几乎一样的代码，都是把数组 `A` 的每个元素，用左边和上边两个邻居的平均值更新：

```text
// 写法 A：先走 i 再走 j
for (i = 1; i < N; ++i)
  for (j = 1; j < N; ++j)
      A[i][j] = 0.5 * (A[i-1][j] + A[i][j-1]);
```

```text
// 写法 B：改成"反对角线"顺序
for (s = 2; s <= 2*N-2; ++s)
  for (i = 1; i < N; ++i) {
      j = s - i;
      if (j >= 1 && j < N)
          A[i][j] = 0.5 * (A[i-1][j] + A[i][j-1]);
  }
```

两段代码算出的结果**一模一样**，但写法 B 有个写法 A 没有的本事：**每一行内层循环（同一个 s）里的所有迭代互相独立，可以丢给不同 CPU 核心并行执行**。写法 A 就做不到——因为 `A[i][j]` 用到 `A[i][j-1]`，右边必须等左边算完。

于是问题来了：**编译器能不能自己发现写法 B 比写法 A 好，并自动做完这个改写？**

答案是能，而且它用的方法非常漂亮——它不再把循环当成"循环"，而是当成**几何图形**。这就是多面体优化。本文会带你一步步看它是怎么做到的，并且每一步都配上真正跑得起来的代码。

## 二、为什么需要多面体：传统循环优化的三座大山

在讲怎么做到之前，先说说为什么难。

传统的循环优化是一堆"各管各"的招式：循环交换、循环反转、循环倾斜、循环分块、循环融合、循环分裂……每一种都单独实现、单独判断。这会带来三个麻烦：

| 难题 | 具体表现 |
| --- | --- |
| 依赖难判 | 改写合不合法，取决于数组访问之间有没有"依赖"。人肉分析遇到复杂下标（比如 a[i+4-j]）就抓瞎 |
| 招式互不相干 | 每种变换各写一套合法性检查，组合起来谁先谁后、能不能叠加，全靠经验 |
| 收益靠猜 | 分块大小多大最好？交换哪两层？基本靠试参数（auto-tuning） |

多面体模型的洞见是：**这些看起来五花八门的变换，本质上是同一个数学动作**。只要换一个视角，把它们统一起来，合法性判断和收益估算就都能变成一个可以自动求解的数学问题。

这个视角就是——几何。

## 三、从循环到几何：迭代域与多面体

多面体模型做的第一件事，是把"循环"翻译成"几何"。

关键在于：**每一次迭代，就是空间里的一个整数点。**

拿写法 A 来说，外层 `i`、内层 `j` 组合出一个个坐标 `(i, j)`。把所有合法的 `(i, j)` 画在一个二维平面上，你会得到一块整整齐齐的点阵：

![](https://pic3.zhimg.com/v2-bf1217b77308c41bde084a9b585fdb68_1440w.jpg)

这里有几个必须记住的名词，它们是后面一切的基础：

- **迭代域（Iteration Domain）**：所有合法迭代点的集合。它可以用一组线性不等式紧凑地描述，例如 `1 ≤ i ≤ N-1`、`1 ≤ j ≤ N-1`——这就是一个二维多面体里的整数点集。哪怕 N 是十亿，也只是这一个多面体，不用把点一个个列出来。
- **访问函数（Access Function）**：数组下标表示的也是迭代变量的仿射（线性）表达式。比如 `A[i-1][j]` 的下标就是 `(i-1, j)`。注意它是**直线的**——这正是"仿射"二字的含义，也是整个模型能成立的前提。
- **语句实例（Statement Instance）**：某个具体坐标上的那一次迭代，比如 `(3,5)` 这一次循环。

所以"重写循环"这件事，被翻译成了"**对一块几何体做变形**"。这句话是整篇文章的钥匙，请记住它。

## 四、依赖：谁挡了谁的路

要把几何体变形成功，先得知道哪些点被"拴"在一起了。拴住它们的东西叫**依赖（Dependence）**。

依赖的定义很朴素：**两次访问命中同一块内存，且生产者在程序序里更早**，就构成一条依赖边。为什么这么重要？因为只要存在依赖，这两次访问的先后顺序就**不能**被打破，否则程序结果就错了——它正是所有变换的"红线"。

我们把写法 A 的两条访问关系找出来（脚本 V1，见第九章），会得到两个**距离向量**：

![](https://pica.zhimg.com/v2-96e7a8aafd0044bcc243aa091f3665f8_1440w.jpg)

- `A[i][j]` 用到 `A[i][j-1]` → 同一行里"右边依赖左边" → **距离向量 (0, 1)**
- `A[i][j]` 用到 `A[i-1][j]` → 同一列里"下面依赖上面" → **距离向量 (1, 0)**

（"距离向量"= 消费者迭代坐标 − 生产者迭代坐标。）

依赖还分三类，只有第一类是"铁律"，其余两类通常可以想办法消除：

| 类型 | 含义 | 例子 | 能否消除 |
| --- | --- | --- | --- |
| 真依赖 RAW | 先写后读 | a[i]=1; ... x=a[i]; | 不能，本质顺序 |
| 反依赖 WAR | 先读后写 | x=a[i]; ... a[i]=1; | 能，重命名/私有副本 |
| 输出依赖 WAW | 先写后又写 | a[i]=1; ... a[i]=2; | 能，保留最后一次写 |

写法 A 倒霉就倒霉在：**两个方向都有真依赖**，距离向量集合是 `D = {(1,0), (0,1)}`。所以它完全串行——这不是实现问题，是数学上的必然。想加速，就必须找到一个能"绕开"这些依赖的合法变换。

## 五、一个矩阵，走遍所有循环变换

现在进入多面体模型最优雅的部分。

前面说"重写循环 = 对几何体做变形"。那用什么做变形？答案是：**给每个迭代向量左乘一个整数矩阵**。

> **新迭代 = T · 旧迭代**

就这么简单。那些传统编译器里一个个独立的招式，在这里统统变成了"选一个不同的矩阵 T"：

![](https://pic2.zhimg.com/v2-112f4e1f5a3d6aea8e8839b3fdec1b13_1440w.jpg)

| 变换 | 矩阵 T | 效果 |
| --- | --- | --- |
| 循环交换 Interchange | [0 1; 1 0] | 内外层对调，改变访存方向 |
| 循环反转 Reversal | [-1 0; 0 1] | 把某一维方向倒过来 |
| 循环倾斜 Skewing | [1 0; 1 1] | 造出反对角线波前，让内层可以并行 |
| 循环分块 Tiling | 拆成 (ii,ti, jj,tj, kk,tk) | 切成能塞进缓存的小块 |

**合法性怎么判？** 一句话：变换后，每一条依赖都必须仍然"指向未来"。用数学说就是：对每条依赖距离 `d`，要求 `T·d` 在字典序上仍是正方向。

拿倾斜验证一下（脚本 V2）：

```text
变换矩阵 T = [[1, 0], [1, 1]] , det(T) = 1   (|det|=1 => 迭代集合与原来一一对应)
合法性检查:
  d=(1, 0)  ->  T·d=(1, 1)  合法(指向未来) OK
  d=(0, 1)  ->  T·d=(0, 1)  合法(指向未来) OK
  两条依赖的第二分量都 > 0  => 新内层循环(走 i)完全不携带依赖  => 可并行
```

这里 `det(T) = 1` 很关键：行列式绝对值为 1 的整数矩阵，是整数格上的一一映射，**迭代集合本身没有被改变**，只是换了描述方式。

倾斜之后，依赖被"推"到了新的时间轴上，每个"时刻"（即 `i+j` 相同的反对角线）上的迭代互相独立。这就是写法 B 的来历：

```text
倾斜后每个调度时刻(= i+j)可同时执行的迭代数(波前宽度):
   {2:1, 3:2, 4:3, 5:4, 6:5, 7:6, 8:7, 9:6, 10:5, 11:4, 12:3, 13:2, 14:1}
   最大波前宽度 = 7  => 最多同时 7 个迭代并行; 原始程序该值恒为 1 (完全串行)
```

而且脚本还做了最硬的检验——把变换后程序真的跑一遍，和原程序**逐位比对**：`逐位一致 ✅`。变换不是"看着对"，是真的算对了。

## 六、分块：把局部性变成几何问题

倾斜解决的是"能不能并行"，分块解决的是另一个痛点：**内存墙**。

现代 CPU 的算力远快于内存带宽，程序大部分时间其实在等数据。矩阵乘法就是典型：同一块数据被反复读写，如果每次都从内存拉一遍，缓存形同虚设。

分块的思想是：把大迭代空间切成小块（tile），让"当前正在用的一小块数据"在被换出缓存之前被**用满**。它同样是一个仿射变换。

到底有多大差别？我们写一个**真实的缓存模拟器**来数——不是估算（脚本 V3）：

```text
缓存: 64 行 x 64 字节 = 4096 字节 (4.0 KB), 矩阵 64x64 double
访存总次数(两种写法相同): 528384

不分块 (i-j-k 顺序): 命中 229376  缺失 299008  缺失率 56.6%
分块   (B=16):       命中 520192  缺失   4096  缺失率  0.8%

分块把缺失从 299008 降到 4096, 减少 98.6%
```

![](https://pica.zhimg.com/v2-a8000d8c26abffc29bb71736d4e7344a_1440w.jpg)

请看这个数字：两种写法的**访存总次数一模一样**（都是 528,384 次），变的只是**顺序**。这就是多面体模型最独到的能力——它把"局部性"也变成了一个几何问题：只要选对迭代点的遍历顺序，数据自然就会在缓存里待久一点。

## 七、调度：给每次迭代发一张"时刻票"

到这里，我们已经知道"变换 = 矩阵"，"合法性 = 依赖指向未来"。但还有最后一个问题：**怎么自动找到最好的那个矩阵？** 总不能靠人一个个试吧。

答案是：把它变成一个**约束优化问题**。核心概念叫**调度（Schedule）**。

调度做的事，是给每一次迭代分配一个"逻辑时刻"：

```text
θ(i, j) = c1·i + c2·j
```

规则只有两条：

- **合法性**：对每条依赖距离 `d`，都要求 `c·d > 0`——生产者必须严格早于消费者；
- **目标**：在合法调度里，挑"并行度最大、总时延最小"的那个。

同一时刻的迭代互不依赖，可以并行；时刻递增，依赖自然被满足。于是"找最优变换"就变成了"在一堆候选系数里挑一个最好的"——这完全可以自动算。

我们写一个迷你调度器，把小范围的系数 `(c1, c2)` 全枚举一遍（脚本 V4）：

```text
候选调度 (按 并行度 降序 / 时延 升序, 取前 8):
  (c1,c2)    调度 theta     时延    最大并行度
  (1, 1)     1*i+1*j        13      7
  (2, 2)     2*i+2*j        25      7
  (3, 3)     3*i+3*j        37      7
  (1, 2)     1*i+2*j        19      4
  (2, 1)     2*i+1*j        19      4

最优调度: (1, 1)   theta(i,j) = 1*i + 1*j   并行度=7 时延=13
```

看看它给出的答案和对比，你会心一笑：

```text
对比: 常见的'直觉'写法为什么不行/更差
  c=(0, 1)   非法 —— 它把某条依赖丢在了身后, 变换后结果会错
  c=(1, 0)   非法 —— 它把某条依赖丢在了身后, 变换后结果会错
  c=(1, 1)   合法, 但 并行度=7   时延=13
  c=(2, 1)   合法, 但 并行度=4   时延=19
  c=(2, 2)   合法, 但 并行度=7   时延=25
```

- 直觉的 `θ=i` 或 `θ=j` 竟然**非法**——因为它们等于"不改"，仍然带着那条依赖；
- `θ=2i+2j` 虽然也合法，但时延翻倍（时刻被拉长了两倍）；
- **`θ=i+j` 同时拿下最大并行度和最小时延**——它对应的正是我们在第五章手工做的那个"倾斜"！

![](https://pic2.zhimg.com/v2-51ac379c8aefe93f9a1298f6be8a5f73_1440w.jpg)

看，多面体模型最精华的一幕出现了：**我们并没有"发明"倾斜，是合法性约束和优化目标自动把它推了出来**。Polly、 Pluto 这些真实工具，做的就是这件事——只不过它们的候选空间更大（多维调度），求解用的是整数线性规划。

## 八、走进真实世界：多面体编译器长什么样

理论讲完了，看看工业界的实现。一个多面体编译器把优化拆成六步：

![](https://pica.zhimg.com/v2-1a8d6f39cc8283b1964fe3a477828558_1440w.jpg)

- **SCoP 抽取**：不是所有代码都能分析。只有"静态可分析"的循环段（称为 SCoP，Static Control Part——下标是仿射函数、循环边界是常数或外层变量）才有资格进入模型。工具：Clan、PET、Polly 前端。
- **依赖分析**：算出依赖多面体。工具：ISL、candl，底层是整数规划。
- **调度**：求合法且最优的仿射调度。算法：Feautrier、PluTo、isl。
- **代码生成**：把变换后的多面体"扫"回真实循环（这一步叫 polyhedra scanning）。工具：CLooG、ISL 的 AST 生成器。
- **后端**：交给 LLVM / GCC 做向量化、寄存器分配、指令发射。

几个你一定会遇到的名字：

![](https://pic1.zhimg.com/v2-68785ccadc1a88f9981fa31d1997d964_1440w.jpg)

| 工具 | 定位 |
| --- | --- |
| Polly | LLVM 的高层循环与数据局部性优化器，基于整数多面体，能挖出 OpenMP 并行与 SIMD 机会 |
| GCC Graphite | GCC 的多面体框架，开关 -floop-nest-optimize |
| Pluto | 研究级自动并行器，C 源码 → OpenMP C，PLDI 2008 的经典工作 |
| Tiramisu | 面向稠密/稀疏深度学习的多面体编译器，性能可对标甚至超过 hand-tuned 库 |
| ISL / CLooG | 底层积木：整数集合运算 + 多面体扫描，被上面几乎所有人共用 |
| MLIR affine | 把多面体思想带进现代编译器基础设施 |

**它不是什么都能干。** 三个主要局限要说清楚：

- 只对 **SCoP** 有效——含指针别名、非仿射下标（如 `a[b[i]]`）、复杂控制流的循环进不了模型；
- **代价模型（cost model）** 一直是难点：怎么估"哪个调度更快"没有完美答案，所以现在有大量研究用机器学习来预测（比如 LOOPer 这类工作）；
- **归约（reduction）** 曾被当作"禁止并行的依赖"而错过优化，后来才有专门支持。

## 九、动手验证：四段代码的完整输出

本文所有结论都来自可以真跑的四段 Python 代码（无需 GPU），源码在 `~/output/polyhedral-opt/code/`。它们构成一条**递进阶梯**，每一级都由上一级的结论驱动：

| 脚本 | 干什么 | 关键结论 |
| --- | --- | --- |
| v1_dependence_analysis.py | 枚举迭代域，找全部真依赖 | 距离向量 {(1,0),(0,1)}，原始程序完全串行 |
| v2_affine_transform.py | 用矩阵做倾斜，验证合法性+等价性 | 逐位一致；波前宽度从 1 提到 7 |
| v3_tiling_cache.py | 真实 LRU 缓存模拟器 | 分块把缺失率从 56.6% 降到 0.8% |
| v4_mini_scheduler.py | 穷举调度系数，自动选最优 | 在合法调度里自动选出 θ = i + j |

跑法很简单：

```text
cd ~/output/polyhedral-opt/code
python3.10 v1_dependence_analysis.py
python3.10 v2_affine_transform.py
python3.10 v3_tiling_cache.py
python3.10 v4_mini_scheduler.py
```

V1 的核心逻辑，短到可以一眼看懂：

```text
# 迭代域：所有 (i,j) 整数点；程序序 = 字典序
iters = [(i, j) for i in range(1, N) for j in range(1, N)]

# 依赖：m 写 A[i][j]，n 读 A[i-1][j] 或 A[i][j-1]，且 m 在前
for m in iters:
    for n in iters:
        for rf in (A_read_top, A_read_left):
            if A_write(*m) == rf(*n) and order[m] < order[n]:
                dist = (n[0]-m[0], n[1]-m[1])   # 距离向量
```

V4 的核心逻辑，则是把"选变换"变成一个搜索：

```text
def evaluate(c):
    for d in deps:                       # 合法性: 每条依赖都要被推向未来
        if c[0]*d[0] + c[1]*d[1] <= 0:
            return (False, None, None)
    thetas = [c[0]*i + c[1]*j for (i, j) in domain]
    return (True, max(thetas)-min(thetas)+1,  # 时延
            max(Counter(thetas).values()))    # 并行度
```

从"依赖分析"到"自动调度"，四段加起来不到 200 行，但已经把多面体模型最核心的骨架跑通了。

## 十、总结与学习路径

**一句话总结整篇文章**：

> 多面体模型把循环里的每次迭代看成几何空间里的整数点，把循环变换看成整数矩阵，于是"怎么改写循环最快"就从一个靠经验的玄学，变成了一个可以自动求解的数学问题。

回头看，它的三个关键词是：

- **几何化**：循环 → 迭代域多面体；
- **统一化**：所有变换 → 左乘整数矩阵；
- **自动化**：找最优变换 → 约束优化 + 调度搜索。

**如果你想继续深入，一条循序渐进的路：**

| 层次 | 内容 | 材料 |
| --- | --- | --- |
| 入门 | 看懂依赖、仿射变换、调度三个概念 | 本文 + Wikipedia: Polytope model |
| 动手 | 把本文四段代码改一改，试试其他内核 | 本地跑 code/ 里的脚本 |
| 进阶 | 真实系统的设计 | Polly 官方文档；Pluto 的 PLDI'08 论文 |
