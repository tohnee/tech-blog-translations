每个 AI agent 都存在记忆问题。问它一个众所周知的事实，它回答得非常出色。但问它你公司特定的流失率公式、内部 API schema，或数据库故障转移的生产运行手册，它就会自信地编造出一个听起来完美但完全错误的答案。

这就是幻觉问题，也是阻碍企业放心让 AI agent 承担真实工作的最大单一障碍。

过去两年，业界的答案是RAG：把 AI 连接到装满公司文档的向量数据库，让它搜索相关上下文，再粘贴进提示词。

RAG 对大型非结构化文档语料效果很好，但它有一个关键缺陷：它是概率性的。它找到的是与你的问题语义相似的文档，而不是事实上具有权威性的文档。对于任务关键型数据——比如计算营收的精确公式，或支付端点的精确 API 契约——"相似"还不够好。

2026 年 6 月，Google Cloud 推出了开放知识格式（Open Knowledge Format，OKF），这是厂商中立、开放的规范，用简单的 Markdown 文件存储经过整理的权威知识。通过把 OKF 的确定性精度与 RAG 的概率性覆盖范围结合起来，得到了许多人所说的终极 AI Agent 架构。

## **两套记忆系统**

想象一位人类专家第一天加入你的公司。

有人交给他两样东西：

1. 一份公司 Wiki（OKF）：一个经过整理、组织良好的内部 wiki，包含权威定义、API 文档、指标公式和运行手册。里面的一切都经过评审、批准和版本控制。当你需要官方答案时，就来这里。
2. 一个用于其余一切的搜索引擎（RAG）：访问数千条 Slack 消息、邮件线程、支持工单和会议记录。当你需要查找人们对某个话题说了什么，或发现埋藏在非结构化档案中的信息时，就在这里搜索。

任何一套系统单独都不够。合在一起，它们完整覆盖了组织知识。

## **什么是 OKF？（开放知识格式）**

OKF 设计上极其简单。一个 OKF "知识包"不过是一个存放在 Git 中的 Markdown 文件目录。每个文件代表一个概念——一张数据库表、一个指标、一个 API 端点、一份运行手册——顶部包含一块 YAML frontmatter 用于机器可读的元数据。

下面是一个业务指标 OKF 文件的示例：

```text
---
type: metric
title: "Monthly Churn Rate"
description: "Official formula for calculating monthly customer churn."
owner: "data-engineering"
tags: [revenue, kpi, board-report]
timestamp: 2026-06-20T10:00:00Z
---

# Monthly Churn Rate

The official churn rate formula used in all board reports and investor decks:

    Churn Rate = (Customers Lost During Month / Customers at Start of Month) × 100

### Rules
- **Do NOT** use trial accounts in the denominator.
- **Do NOT** count plan downgrades as churn.
- Source of truth: `analytics.monthly_churn_summary` table.

### Related
- [Monthly Active Users](mau.md)
- [Revenue Dashboard](revenue_dashboard.md)
```

## **为什么这很重要**

- 没有向量数学。没有幻觉。当 agent 需要流失率公式时，它直接读取这个文件。没有嵌入，没有余弦相似度，没有"top-k 最近邻"。它每次都得到精确的、已批准的答案。
- Git-Ops 原生。因为 OKF 知识包存放在 Git 中，每一次变更都通过 pull request、代码评审和提交历史被追踪。你对谁在何时、为何修改了流失率公式拥有完整的审计轨迹。
- 零基础设施。没有向量数据库。没有嵌入流水线。没有分块策略。没有重建索引的任务。只是文件夹里的文件。

## **什么是 RAG？**

RAG 是把 LLM 连接大型非结构化数据的行业标准模式。它的工作方式是：

- 摄入数千份文档（PDF、邮件、Confluence 页面、Slack 消息）。
- 将它们分块为更小的片段。
- 用嵌入模型把每个片段嵌入到高维向量中。
- 把向量存储在向量数据库（如 Pinecone、Weaviate 或 pgvector）中。
- 查询时搜索：用户的问题被嵌入到同一个向量空间中，数据库返回语义最相似的片段。
- 用这些片段增强 LLM 的提示词，使其能生成有依据的答案。

RAG 擅长覆盖范围——它能从数千份无人能手动整理的非结构化文档中找出相关信息。

但 RAG 在精确性上吃力。因为它依赖语义相似度，它可能返回与你的问题相关但不具权威性的文档。如果三个不同的 Slack 线程对流失率的定义略有不同，RAG 可能检索到错误的那一个。

## **混合架构：OKF + RAG**

终极 agent 架构使用一个智能路由器，对传入查询进行分类，并将其导向合适的记忆系统。

## **实现示例**

下面是一个混合路由器的简化 Python 实现：

```python3
from openai import OpenAI
import os
import glob
import yaml

client = OpenAI()

# 1. 从本地目录加载 OKF 知识包
def load_okf_bundle(bundle_path: str) -> dict:
    """把 OKF 目录中的所有 Markdown 文件读入一个可搜索的字典。"""
    knowledge = {}
    for filepath in glob.glob(f"{bundle_path}/**/*.md", recursive=True):
        with open(filepath) as f:
            content = f.read()
            # 从 YAML frontmatter 中提取标题
            if content.startswith("---"):
                _, frontmatter, body = content.split("---", 2)
                meta = yaml.safe_load(frontmatter)
                title = meta.get("title", os.path.basename(filepath))
                knowledge[title.lower()] = body.strip()
    return knowledge

# 2. 搜索 OKF（确定性，基于关键词）
def search_okf(query: str, okf_knowledge: dict) -> str | None:
    """对 OKF 标题做简单的关键词匹配。"""
    for title, content in okf_knowledge.items():
        if title in query.lower():
            return content
    return None

# 3. 搜索 RAG（概率性，基于向量）
def search_rag(query: str) -> str:
    """你的向量数据库搜索的占位符（Pinecone、Weaviate 等）。"""
    # results = vector_db.similarity_search(query, top_k=5)
    return "RAG 上下文：[检索到的片段会出现在这里]"

# 4. 智能路由器
def answer_query(query: str, okf_bundle_path: str) -> str:
    okf_knowledge = load_okf_bundle(okf_bundle_path)
    
    # 先尝试 OKF（确定性路径）
    okf_result = search_okf(query, okf_knowledge)
    
    if okf_result:
        context = f"[来源：官方知识库（OKF）]\n{okf_result}"
    else:
        # 回退到 RAG（概率性路径）
        context = f"[来源：文档搜索（RAG）]\n{search_rag(query)}"
    
    # 带着检索到的上下文发送给 LLM
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "仅使用提供的上下文来回答。"},
            {"role": "user", "content": f"上下文：\n{context}\n\n问题：{query}"}
        ]
    )
    return response.choices[0].message.content
```

## **结论**

企业 AI agent 的未来不是要在 OKF 和 RAG 之间做选择——而是一种同时利用两者的混合架构。

OKF 给你的 agent 一份经过整理、防幻觉的记忆，用于最重要的事实：你的 KPI、API 契约、运维运行手册。RAG 给你的 agent 探索庞大非结构化知识档案的能力，那是无人能手动整理的。

通过把确定性的、Git 受控的知识库与概率性的向量搜索引擎结合起来，构建出的 AI agent 既能在需要时保持精确，又能在需要发现时进行探索。
