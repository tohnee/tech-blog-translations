本地推理工具如果直接依赖 llama.cpp 的库，更新时需要分别看接口能否接上、原有模型能否继续跑。11月13日，项目团队给出了新的版本规则。

## 01 llama.cpp 与 ggml 的库发布 1.0.0

ggml-org 团队于11月13日宣布 libllama 和 libggml 发布 1.0.0。团队说明，后续公共 C API 的破坏性变更提升主版本号，向后兼容的新功能或 API 新增提升次版本号，不改 API 的错误修复提升补丁版本号。团队同时表示会用主版本变更标记 API 和 ABI 的不兼容。

观点：给依赖这两个库的工具升级时，先用现有应用做一次加载和推理冒烟测试，再固定 GGUF、推理后端和上下文长度，对比旧版本与新版本的首 token 时间、生成速度和峰值内存。若部署多个硬件后端，各留一个代表配置。

接下来盯什么：记录两个库版本和分发渠道，保留一个可回滚的构建。使用第三方图形界面时，可先查应用实际内置的版本。本文未运行新版或测量性能。
