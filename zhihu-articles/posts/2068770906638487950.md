## 投机解码原理（含公式）以及相关研究方向详细介绍

![](https://picx.zhimg.com/v2-a438bb1b54a49db6b29b8d0bab87fb53_r.jpg)

> **🔑 一句话说透 · 读懂这句，全文就通了**<br> 大模型为什么推理慢、投机解码为什么能加速，本质就一句话：**把矩阵维度调大，GPU 要做的乘法确实变多了；但无论矩阵多大，一次矩阵乘法自始至终只搬运一次权重——多算，不需要多搬。** 而在大模型推理里，“搬”（把权重从显存搬进计算单元）才是耗时的大头、“算”相对几乎不花时间，所以“多算几个 token”在时间上近乎免费。这不是某个算法的技巧，而是 **GPU 硬件特性决定的物理事实**——投机解码全部的加速，都是在兑现这一条硬件红利。

**举个例子：一句「今天天气怎么样」，其实就是一个矩阵。** 每个字先被转成一行数字（它的 embedding，比如 d 维），7 个字叠起来，就是一个 7 × d 的矩阵 X：

```bash
       ┌                              ┐
   今  │  0.12  -0.83   0.05   0.47  … │
   天  │ -0.31   0.22   0.68  -0.10  … │
   天  │ -0.31   0.22   0.68  -0.10  … │
   气  │  0.55   0.09  -0.42   0.33  … │
   怎  │ -0.07   0.61   0.18  -0.25  … │
   么  │  0.29  -0.14   0.52   0.40  … │
   样  │  0.44   0.37  -0.20   0.08  … │
       └                              ┘
              = 矩阵 X（7 行 × d 列）
```

**行数 = 字数（这里是 7）**：句子越长，矩阵的行就越多、要算的乘法也越多——但这一整块 X 乘权重 W，**W 只从显存搬 1 次**。这就是“多算，不需要多搬”最直观的样子。（小彩蛋：两个“天”那两行完全一样——同一个字，进注意力之前就是同一行数字。）

![](https://pic1.zhimg.com/v2-176667c31861178711233cbd99349080_r.jpg)

### 一、大模型推理慢的根本原因：两个正交的瓶颈

要理解投机解码为何有效，**必须先看清大模型推理慢的真实成因**。这一节虽然不直接讲算法，但是后面所有讨论的地基，**面试时把这个讲清楚，立刻就能区别于”只背了算法”的候选人**。

### 1.1 瓶颈 A：自回归生成的串行依赖

主流大模型基于因果 Transformer [15]，采用**自回归**方式生成：

$$ P(x_1, x_2, \dots, x_n) = \prod_{i=1}^{n} P(x_i \mid x_{<i}) $$

通俗讲：**每个 token 的生成需要前面所有 token 作为输入**。生成 100 个 token，必须做 100 次串行的模型调用。

这是算法层面的本质串行性，**无法在不改变模型范式的前提下绕过**——除非根本性改造（这正是 Lookahead Decoding、扩散语言模型等更激进路线的来源）。

### 1.2 瓶颈 B：Memory-Bandwidth Bound（重点）

这一条**反直觉，也是面试高频考点**：**大模型推理的瓶颈不是 GPU 的算力（FLOPs），而是显存带宽**。

GPU 的内存是**分层的**：

| 层级 | 容量 | 带宽 | 角色 |
| --- | --- | --- | --- |
| HBM（显存） | ~80 GB | ~3 TB/s | 模型权重住这里 |
| L2 缓存 | ~50 MB | ~10 TB/s | 中转站 |
| SRAM（片上） | ~100 KB | ~30 TB/s | 真正算矩阵乘的地方 |

![](https://pic4.zhimg.com/v2-0aad640ecf4c25788ca7837ae7b56ff1_r.jpg)

GPU 的计算核心只能在 SRAM 里干活。每次前向计算，**所有模型权重必须从 HBM 流到 SRAM 才能参与运算**——这是 GPU 硬件物理层决定的，软件层省不掉。

**具体数字感受一下**：70B 模型（FP16）的权重大小约 **140 GB**，按 H100 的 ~3 TB/s 显存带宽算，**单次前向的”地板时间”约 47 ms**——这就是大模型 token 生成延迟的物理下限。

但更关键的事实是：**这 140 GB 的搬运成本，几乎不随你”算多少个 token”变化**。算 1 个 token，要搬一遍；算 7 个 token，还是搬一遍。所以多算几个位置，几乎不增加这一次前向的耗时。

**为什么“多算几个位置”几乎不增加耗时？** 一次前向的核心运算是矩阵乘法 $Y = X \cdot W$：输入 $X$ 形状 `[N, d]`（N 个位置、每个 d 维），权重 $W$ 形状 `[d, d']`。GPU 把 $W$ 从 HBM 搬进 SRAM 后，用这**同一份** $W$ 去乘 $X$ 的全部 N 行。

要说准一点：行数从 1 变 7，**GPU 的计算量（FLOPs）确实变大了**——多算 6 行乘加，这部分不是零。但关键在于，**一次矩阵乘只把 $W$ 搬进来一次，搬运量不随行数变化**。而大模型推理是 memory-bound——算力极度充裕、显存带宽才是瓶颈——于是多出来的这点计算被**藏进了搬权重的时间里**：计算核心在等 $W$ 到位时本来就闲着，顺手多算几行几乎不占额外的墙钟时间。**所以”多算免费”不是计算真的不花钱，本质是 GPU”算力 ≫ 带宽”这一计算特性直接决定的。**

### 1.3 把双重瓶颈拼起来：核心痛点

**瓶颈 A（算法）**：必须做 N 次串行前向。

**瓶颈 B（硬件）**：每次前向加载成本固定，但只产出 1 个 token。

![](https://picx.zhimg.com/v2-9ad235e4c7b068960610d23e16a71d05_r.jpg)

合起来就是大模型推理慢的本质：**用每次”搬 140 GB 权重”的代价，只换回 1 个 token，性价比极低**。

**投机解码的精妙之处在于：它利用 B 来部分缓解 A**——既然多算几个 token 不要钱，那就想办法让一次前向校验多个 token。理解了这一点，整个领域的论文都能贯穿起来。

### 1.4 关键澄清：一次前向到底产出了什么？

这里要专门戳破一个**高频误区**——理解清楚这一点，是后面所有内容的钥匙。

**很多人以为 Transformer 一次前向只算 1 个 token。事实不是。**

> 💡 **关键机制**：一次前向 = 一次权重搬运 + 一次矩阵乘法，而这一次矩阵乘法**把输入的所有位置一次算完**。“搬”和“算”是**绑死的一对**——你没法“只搬一次、然后分开算 N 次”。所以“算 N 次”这个操作在物理上根本不存在，存在的只有“前向 1 次”“前向 2 次”……每次前向都是“搬一次 + 算完当时所有位置”的绑定包，拆不开。

![](https://pica.zhimg.com/v2-0e89bb6b1df7fc9f52e217adef1cc8e6_r.jpg)

Transformer [15] 采用**因果自注意力**（causal self-attention）：给定长度为 N 的输入序列，**一次前向就在所有 N 个位置同时输出”下一个 token 的概率分布”**。换句话说，每个输入位置 $i$ 都得到一个分布 $P(x_{i+1} \mid x_{\le i})$。这就是 Transformer 比 RNN 训练快的核心原因——所有位置并行计算。

那为什么普通解码看起来”一次只产 1 个 token”？因为：

- 位置 0 预测的是”输入第 1 个 token 之后是什么” → 答案就是输入位置 1 的 token，**我们已经知道**
- 位置 1 预测的是”输入第 2 个 token 之后是什么” → 答案就是输入位置 2 的 token，**我们已经知道**
- ……
- 位置 N-1 预测的是”输入最后一个 token 之后是什么” → **这才是唯一的新信息**

所以**前 N-1 个位置的预测全部被浪费了**——它们在预测我们已经看见的输入。普通解码只取最后一个位置的结果，于是从外部看”一次前向只产 1 个新 token”。

**投机解码恰好利用这个浪费**：让小模型把那些”未来位置”提前用猜测填上，于是大模型那一次前向**同时产出的 N 个分布全部变得有意义**——

- 前 $\gamma$ 个分布用来校验对应位置的草稿 token（”我（大模型）是否同意小模型的猜测”）
- 最后 1 个分布白嫖作为奖励 token（如果前 $\gamma$ 个全部接受）

**把普通解码和投机解码放在一起，就彻底清楚了**（都以产出 7 个 token 为例）：

| 解码方式 | 前向次数 | 权重搬运 | 那几次矩阵乘在算什么 |
| --- | --- | --- | --- |
| 普通解码 | 7 次 | 7 次（≈ 7 × 47 ms） | 第 k 次算 k 个位置，但只保留最后 1 个，其余白算 |
| 投机解码 | 1 次 | 1 次（≈ 47 ms） | 一次算 7 个位置，全部用于校验草稿 |

一个反直觉但关键的点：**普通解码的第 7 次前向其实也在算 7 个位置**——只是前 6 个位置在预测“我们早就知道的输入”，输出被直接丢掉。所以两种解码的矩阵乘**总工作量相差不大**，真正的差别不在“算多少”，而在“搬几次”：普通解码搬了 7 次权重，投机解码把它压缩成 1 次。而搬运才是延迟的主体（≈ 47 ms/次），所以**把 7 次搬运压成 1 次，就等于把时间压掉一大截**。

而在这一次前向的内部，成本也高度不对称：

| 阶段 | 谁做 | 内容 | 成本 |
| --- | --- | --- | --- |
| 校验前向 | 大模型（GPU） | 一次前向，权重搬一次，所有位置并行算出分布 | 主要成本（~47 ms） |
| 接受/拒绝判决 | 算法层（CPU 或 GPU 小 kernel） | 拿一批分布查表 + 修正拒绝采样 | 几乎免费 |

> ⚠️ 一个常见的错误说法是”在一次前向里做多次校验”或”多次前向”。这两种说法都不准确。**前向是 1 次**，搬运是 1 次，校验是**一次前向产出的多个分布被外层算法并行使用**。这是 Transformer 因果结构带给我们的免费红利。

把这个机制吃透，下一节的算法证明、研究方向、面试题，都会变得非常直观。

### 二、投机解码的核心算法

### 2.1 算法流程

![](https://pic2.zhimg.com/v2-22b09770a886cb48eb3a510660df7fd5_r.jpg)

设：

- **目标模型** $M_p$，概率分布 $p(\cdot \mid \text{context})$（大、慢，比如 70B）
- **草稿模型** $M_q$，分布 $q(\cdot \mid \text{context})$，参数量远小于 $M_p$（小、快，比如 1B）

每一轮投机解码包含 4 步 [1, 2]：

1. **草拟**：$M_q$ 自回归生成 $\gamma$ 个候选 token $x_1, \dots, x_\gamma$（典型 $\gamma = 4$–$7$）
2. **并行校验**：把这 $\gamma$ 个 token 与前缀一起喂给 $M_p$，**做一次前向**得到所有位置的条件分布 $p(\cdot \mid x_{<i})$
3. **修正拒绝采样**：从左到右对每个 $x_i$ 决策——

- 以 $\min\!\left(1, \dfrac{p(x_i)}{q(x_i)}\right)$ 的概率**接受**
- 否则**拒绝**，从修正分布 $p'(x) \propto (p(x) - q(x))_+$ 重新采样替换，并**丢弃后续草稿**（其中 $(\cdot)_+ = \max(0, \cdot)$）

1. **奖励 token**：若 $\gamma$ 个全部接受，额外从 $p(\cdot \mid x_{\le \gamma})$ 采样一个 “bonus” token（这个位置的分布反正也算在前向里了，白嫖）

### 2.2 关键问题：为什么输出严格等于直接用 $M_p$ 采样？

这是投机解码**最神奇也最重要**的性质：**它不是”近似无损”，而是数学上严格等价**。这一点非常违反直觉，但证明其实并不复杂——**面试现场推这个证明，立刻能把”看过论文”和”懂”区分开**。

**目标**：证明输出某 token $x$ 的概率严格等于 $p(x)$。

输出 $x$ 有两条路径：

**路径 1（$x$ 被接受）：**

$$ \Pr(\text{输出}=x,\ \text{接受}) = q(x) \cdot \min\!\left(1,\ \frac{p(x)}{q(x)}\right) = \min(p(x), q(x)) $$

**路径 2（被拒绝后从修正分布重采到 $x$）：**

$$ \Pr(\text{输出}=x,\ \text{拒绝}) = \Pr(\text{拒绝}) \cdot \frac{(p(x)-q(x))_+}{\sum_y (p(y)-q(y))_+} $$

这里需要一个**关键恒等式**：

$$ \sum_y (p(y)-q(y))_+ = \sum_y \big[p(y) - \min(p(y), q(y))\big] = 1 - \sum_y \min(p(y), q(y)) = \Pr(\text{拒绝}) $$

也就是说，**修正分布的归一化常数恰好等于拒绝概率**！两者相消，得：

$$ \Pr(\text{输出}=x,\ \text{拒绝}) = (p(x)-q(x))_+ $$

合并两条路径：

$$ \Pr(\text{输出}=x) = \min(p(x), q(x)) + (p(x)-q(x))_+ $$

分两种情况验证：

- 若 $p(x) \ge q(x)$：$\min = q(x)$，$(p-q)_+ = p(x) - q(x)$，加起来 $= p(x)$ ✓
- 若 $p(x) < q(x)$：$\min = p(x)$，$(p-q)_+ = 0$，加起来 $= p(x)$ ✓

**所以输出严格服从 $p$**。$\square$

**这个证明为什么很美**：修正分布的归一化常数 $\sum_y (p(y)-q(y))_+$ 本来需要遍历整个词表（几万个 token）才能算出，但通过这个恒等式，**它在公式里被拒绝概率自动抵消了**——算法不需要显式计算它，但结果依然精确正确。这正是修正拒绝采样的精妙之处。

> 💡 **面试建议**：把上面 5 行公式背下来，面试时现场推。瞬间从”看过”变成”懂”。

### 2.3 效率分析：接受率决定加速天花板

定义**接受率**：

$$ \alpha = \mathbb{E}_{x\sim q}\big[\min(1, p(x)/q(x))\big] = 1 - \mathrm{TV}(p, q) $$

其中 $\mathrm{TV}$ 是总变差距离。直觉上，$\alpha$ 就是目标和草稿分布的**“重合度”**——两者越像，接受率越高，加速越大。

![](https://pica.zhimg.com/v2-9ba2a686c27a86ba692c9ccabb210eb8_r.jpg)

每轮期望产出的 token 数 [1]：

$$ \mathbb{E}[\#\text{tokens}] = \frac{1 - \alpha^{\gamma+1}}{1 - \alpha} $$

设草稿与目标前向成本比为 $c$（典型 $c \in [0.02, 0.1]$），则每轮加速比：

$$ S(\gamma) = \frac{1 - \alpha^{\gamma+1}}{(1-\alpha)\,(1 + \gamma c)} $$

**核心结论**：当 $c \to 0$、$\gamma$ 最优时，加速上界趋近 $\dfrac{1}{1-\alpha}$。vLLM 官方报告生产环境最高 **2.8×** [3]，EAGLE 类方法可达 **3-4×**。

### 三、主要研究方向（5 个子领域）

![](https://pic2.zhimg.com/v2-a43d2300c7a52a05c765df5b710aa63b_r.jpg)

vanilla 投机解码定下来后，过去两年涌现了若干活跃的研究分支。这些**就是当前大厂招聘看重的具体技术栈**。

### 3.1 自我投机：Medusa & EAGLE 系列

Vanilla 方案需要部署一个独立的小模型，**运维成本和显存开销较大**。**自我投机**让目标模型自己充当草稿生成器：

- **Medusa** [4]：在目标模型最后一层后接 $K$ 个**独立预测头**，分别预测未来第 1 到第 $K$ 个 token。共享主干特征，训练成本低，部署简单
- **EAGLE** [5]：核心洞察是 token 级投机的不确定性主要源于**特征层**，提出在 **hidden state 级别**做投机（预测下一个 hidden state，再 decode 成 token），接受率显著高于 token 级方法
- **EAGLE-2 / EAGLE-3** [6]：引入**动态草稿树**（dynamic draft tree），是当前学术 benchmark 上的 SOTA，已被 vLLM 集成 [7]

EAGLE 系列的加速通常 **3-4×**，是当前生产环境最主流的选择。

### 3.2 Token Tree 验证：SpecInfer

Vanilla 每轮只验证一条线性草稿，首位被拒后续全部丢弃，**浪费严重**。

**SpecInfer** [8] 让草稿模型生成**多条候选分支**，组织成树状结构，目标模型通过定制的 **tree attention** 一次校验整棵树，显著提升期望接受 token 数。EAGLE-2 等后续工作进一步引入**动态深度调整**。

> 💡 **小贴士**：SpecInfer **发表于 ASPLOS（系统会议）而不是 ML 会议**——这本身就反映了投机解码的本质属性（详见第 4 节）。

### 3.3 Multi-Token Prediction（MTP）

MTP [9, 10] 和 spec decoding 思路不同，但常被并列讨论。

核心是**修改训练目标**，让模型在每个位置同时预测未来 $k$ 个 token：

$$ \mathcal{L}_{\text{MTP}} = -\sum_{i=1}^{N} \sum_{j=1}^{k} \log P_j(x_{i+j} \mid x_{\le i}) $$

MTP 有**两重价值**：

1. 配合 spec decoding 提供高质量草稿（一种自我投机）
2. **改善基础模型的表示质量**（Meta 论文实证）——这是相对其他加速方法的独特副产品

**DeepSeek-V3 大规模采用了 MTP** [10]，目前是工业界最受关注的方向之一。

> 💡 **进阶洞察**：MTP 和 spec decoding 攻击的是**不同瓶颈**——前者借硬件红利（瓶颈 B）来缓解算法瓶颈（A），后者直接攻击 A。如果未来出现存算一体（compute-in-memory）等新硬件让 B 消失，spec decoding 红利大幅缩水，但 **MTP 仍然有效**。面试时把这个区别讲清楚是高级信号。

### 3.4 Lookahead Decoding

**Lookahead Decoding** [11] 提出了一个**完全不依赖草稿模型**的方案：把自回归解码看成求解一个非线性方程组，用 **Jacobi 迭代**并行更新多个位置的预测，最终收敛到与自回归一致的输出。

**优势**：无需任何辅助模型或训练。 **劣势**：加速通常低于投机解码（1.5-2×）。

适合资源受限场景或不便维护额外草稿模型的部署。

### 3.5 在线学习与生产部署

**Online Speculative Decoding** [12] 注意到草稿模型在不同 query 分布下接受率会**漂移**——比如训练时草稿在通用语料上表现很好，但生产中遇到代码 query 接受率掉一半。论文提出在服务过程中**持续微调草稿模型**以适应实时流量。

工程侧的代表是 **vLLM Speculators** [7]，把 spec decoding 的训练和部署做成了产品化框架，支持 EAGLE-3 等主流变体，已被 Amazon Rufus、LinkedIn AI 等大规模生产系统使用 [13]。

### 四、关键定位：本质上是软件工程，而非算法创新

**理解这一点，能让你在面试时显得真正懂这个领域，而不是只读过论文**。

回顾整个领域，可以发现一个重要事实：

1. **不改变模型本身**。Vanilla spec decoding 完全使用现成的目标模型，没有任何参数更新或架构修改
2. **不改变渐近复杂度**。生成 N 个 token 在最坏情况下仍是 $O(N)$ 串行步骤，只是**常数因子降低了几倍**
3. **核心数学是经典的修正拒绝采样**——这是采样理论的教科书内容，并非新发明
4. **加速的物理来源是 GPU 体系结构的红利**——HBM 带宽和 SRAM 速度的巨大差异，创造了 memory-bound 的窗口期

这有几个推论：

- **依赖特定硬件代际**。若未来存算一体（PIM / CIM）等新硬件消除 memory wall，spec decoding 的红利会大幅缩水
- **更接近”系统工程”贡献**。SpecInfer 发表于 ASPLOS、vLLM 发表于 SOSP [14]，都是这一性质的反映
- **算法纯度有限**——没有提出新的学习范式、新的表示能力，或新的优化目标

**这并不削弱其价值**——恰恰相反，它体现了**工程洞察**对 LLM 落地的关键作用：识别”被浪费的硬件能力”，并用巧妙的方案兑现之。

**对找工作的同学来说，这是好消息**：你不需要发顶会，不需要深 ML 理论功底，你需要的是：

- 扎实的系统知识（GPU 架构、内存层级、并发）
- 读代码的能力（能看懂 vLLM 内部实现）
- 有数据支撑的实操项目（实测加速比、接受率分布等）

**这正是普通学校但工程能力强的同学的机会窗口**。

### 5.2 实操建议（最能拉开差距）

至少做完一项：

1. **用 HuggingFace `transformers` 跑投机解码 demo**：`model.generate(..., assistant_model=...)`，几行代码就能跑
2. **测量接受率 $\alpha$**：换不同 size 的草稿模型（如 1B vs 3B），观察接受率变化
3. **阅读 vLLM 投机解码模块源码**：[github.com/vllm-project/vllm](https://github.com/vllm-project/vllm)
4. **画接受位置分布**：分析哪些 token 容易被拒（命名实体、数字常被拒；”the/a/of” 接受率超高）

面试时一句”**我实测过 … 模型组合，加速比 … ，接受率 …，发现 … 类型的 token 更容易被拒**“，分数立刻拉开。

### 5.3 面试题清单

**浅层（每个面试都会问）：**

1. 一句话解释投机解码
2. 加速从哪里来？
3. 为什么输出严格无损？**现场推证明**
4. 接受率 $\alpha$ 的定义和影响因素

**中层（这一层最常筛人）：**

1. 既然 Transformer 是并行的，为什么大模型一次只能输出 1 个 token？（关键：看清每个位置预测的是 $P(\cdot \mid \text{前缀}_i)$）
2. KV cache 在 spec decoding 里怎么处理？被拒草稿怎么从 cache 里”回滚”？
3. 草稿长度 $\gamma$ 怎么选？为什么不是越大越好？给出 $\mathbb{E}[\#\text{tokens}]$ 公式并讨论
4. **什么场景下 spec decoding 不能加速？**（大 batch、低 $\alpha$、草稿模型相对太重——这题特别常考）
5. Medusa 和 EAGLE 各自的核心创新？解决了什么问题？

**深层（区分顶尖候选人）：**

1. Spec decoding 和 MTP 的**本质区别**？什么场景该用哪个？
2. 如果硬件变成 compute-bound（大 batch、PIM），spec decoding 还有意义吗？
3. Token tree 验证相比单分支验证好在哪？
4. 投机解码和 continuous batching 之间有什么张力？

**开放设计题：**

1. 设计一个 70B 模型 + QPS 1000 的生产 spec decoding 系统：草稿选型、$\gamma$ 动态调整、内存预算
2. 发现 acceptance rate 只有 50%，分析可能原因（tokenizer 不一致 / domain 漂移 / 温度 / 模型 family 不匹配）

### 5.4 给实习生的几个 trick

1. **三个关键概念主动用**：memory-bound、acceptance rate $\alpha$、修正拒绝采样。面试官听到这三个词就知道你真懂
2. **证明会推不要背**：现场推 $\min(p,q) + (p-q)_+ = p$，瞬间提升档次
3. **主动承认局限**：”在 high-batch serving 场景下收益会缩水，因为大 batch 已经不再 memory-bound”——这种表述会让面试官眼前一亮
4. **想清楚 spec decoding vs MTP 的区别**：能讲”前者借 memory-bound 来打瓶颈 A，后者直接打 A”，就是顶尖候选人的信号

### 结语

投机解码不是 ML 神秘学，**它是一个清晰、可学的工程优化技术**。整个领域的核心 idea 用一句话就能概括：

> **大模型每次”搬 140 GB 权重”只换回 1 个 token 太亏；让小模型先猜出多个 token，大模型一次搬运并行批改，用修正拒绝采样保证输出无损。**

抓住这条主线，所有变体（Medusa、EAGLE、SpecInfer、MTP、Lookahead……）都是同一棵树的不同枝。

希望这两篇文章能帮到正在准备大厂面试的同学。**这个方向真的没那么难，关键是动手做出可量化的项目。**

非顶尖学校的同学，这是一条**完全可走的路**——大厂极度需要懂推理优化的工程师，而这个领域的入门门槛远低于”训练大模型”。把这两篇文章里的内容认真过一遍，再做 1-2 个有数据支撑的小项目，你就已经超过大多数候选人了。
