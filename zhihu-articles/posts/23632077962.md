**我们将重点关注LLM 的*推理*方面，即：已训练好的模型如何根据用户提示词生成响应。**

这篇文章是为那些有兴趣更好地理解大模型 (LLM) 领域的工程师撰写的。**它从工程角度而非 AI 角度关注大模型 (LLM) 的内部结构。因此，它不要求具备丰富的数学或深度学习知识。**

## 1、从提示词到输出的高层视图（High-level flow）

作为一个大型语言模型，LLaMA 通过输入文本“提示词”并预测下一个token或单词来工作。

[为了说明这一点，我们将使用维基百科关于量子力学的文章](https://en.wikipedia.org/wiki/Quantum_mechanics)中的第一句话作为示例。我们的提示词是：

```python3
Quantum mechanics is a fundamental theory in physics that
```

LLM 尝试根据训练结果来继续句子，使其相信这是最有可能的延续。使用 llama.cpp，我们得到以下延续：

```text
provides insights into how matter and energy behave at the atomic scale.
```

让我们首先了解一下这个过程的高层视图。**从本质上讲，LLM 每次只预测一个 token。通过将 LLM 模型反复应用于同一提示词，并将先前的输出 token 附加到提示词中，可以生成一个完整的句子（或更多句子）。这种类型的模型称为*自回归模型*。**因此，我们将主要关注单个 token 的生成，如下方的高层视图所示：

![](https://picx.zhimg.com/v2-62a06f24c565e176e8387065d8439c29_r.jpg)
*根据用户提示词生成单个 token 的完整流程包括 token 化、embedding、Transformer 神经网络和采样等各个阶段。*

按照该图，流程如下：

1. *Tokenizer*将提示拆分为*token*列表。根据模型的*词汇表*，某些单词可能会拆分为多个token。每个token都由一个唯一的数字表示。
2. 每个数字编号的token都转换为一个embedding向量，它是一个固定大小的向量，它以更适合 LLM 处理的方式表示token。所有embedding向量一起形成一个embedding向量*矩阵*。
3. *embedding矩阵作为Transformer*的输入。Transformer 是一个神经网络，是 LLM 的核心。Transformer 由多层链组成。每层都接受一个输入矩阵，并使用模型参数对其执行各种数学运算，其中最值得注意的是自注意力机制。该层的输出用作下一层的输入。
4. 最终的神经网络将 Transformer 的输出转换为*logit*。每个可能的下一个token都有一个对应的 logit，它表示该token是句子的“正确”延续的概率。
5. *使用几种采样*技术之一来从 logit 列表中选择下一个token。
6. 所选的token将作为输出返回。要继续生成token，所选的token将附加到步骤 (1) 中的token列表中，然后重复该过程。此过程可以持续进行，直到生成所需数量的token，或者 LLM 发出特殊的流结束 (EOS)token 。

在接下来的章节中，我们将详细探讨每个步骤。但在此之前，我们需要熟悉张量。

## 2、基于 ggml 理解张量（tensor）

***张量*是用于在神经网络中执行数学运算的主要数据结构。llama.cpp 使用**[ggml](https://github.com/ggerganov/ggml)**，这是张量的纯 C++ 实现，相当于 Python 生态系统中的 PyTorch 或 Tensorflow。**我们将使用 ggml 来了解张量的运行方式。

张量表示多维数字数组。张量可以保存单个数字、向量（一维数组）、矩阵（二维数组）甚至三维或四维数组，实践中不需要更多。

区分两种类型的张量很重要。有些张量保存实际数据，包含多维数字数组。另一方面，有些张量仅表示一个或多个其他张量之间的计算结果，并且在实际计算之前不保存数据。我们将很快探讨这种区别。

### *2.1、张量的基本结构*

在 ggml 中，张量由结构表示`ggml_tensor`。为了我们的目的，它稍微简化了一下，如下所示：

```cpp
// ggml.h
struct ggml_tensor {
    enum ggml_type    type;
    enum ggml_backend backend;

    int     n_dims;
    // number of elements
    int64_t ne[GGML_MAX_DIMS];
    // stride in bytes
    size_t  nb[GGML_MAX_DIMS];

    enum ggml_op op;

    struct ggml_tensor * src[GGML_MAX_SRC];

    void * data;

    char name[GGML_MAX_NAME];
};

```

前几个字段很简单：

- `type`包含张量元素的原始类型。例如，`GGML_TYPE_F32`表示每个元素都是一个 32 位浮点数。
- `enum`包含张量是 CPU 支持还是 GPU 支持。我们稍后会讨论这一点。
- `n_dims`是维数，范围是1至4。
- `ne`包含每个维度中的元素数量。ggml 按行主序排列，这意味着`ne[0]`表示每行的大小、ne[1]表示每列的大小，以此类推。

`nb`稍微复杂一些。它包含*步长*：每个维度中连续元素之间的字节数。在第一个维度中，这将是原始元素的大小。在第二个维度中，它将是行大小乘以元素的大小，依此类推（从高维的角度来看，低维空间被看作是高维空间下的一个“元素”，所以需要按上述方式计算步长）。例如，对于 4x3x2 张量：

![](https://pic3.zhimg.com/v2-f8732f11104070c24d88d57fae6784f4_r.jpg)
*维度为 {4,3,2}、步长为 {4,16,48} 的 32 位浮点张量示例。*

使用步长的目的是允许某些张量操作在不复制任何数据的情况下执行。例如，将行转换为列的二维转置操作可以通过翻转`ne`和`nb`指向相同的基础数据来执行：

```cpp
// ggml.c (the function was slightly simplified).
struct ggml_tensor * ggml_transpose(
        struct ggml_context * ctx,
        struct ggml_tensor  * a) {
    // Initialize `result` to point to the same data as `a`
    struct ggml_tensor * result = ggml_view_tensor(ctx, a);

    result->ne[0] = a->ne[1];
    result->ne[1] = a->ne[0];

    result->nb[0] = a->nb[1];
    result->nb[1] = a->nb[0];

    result->op   = GGML_OP_TRANSPOSE;
    result->src[0] = a;

    return result;
}

```

在上面的函数中，`result`是一个新的张量，初始化为指向与源张量相同的多维数字数组`a`。通过交换ne中的维度和nb中的步长，它执行转置操作而不复制任何数据。

### *2.2、张量操作和视图*

如前所述，一些张量保存数据，而另一些张量则表示其他张量之间运算的理论结果。回顾`struct ggml_tensor`：

- `op`可以是张量之间支持的任何操作。将其设置为`GGML_OP_NONE`表示该张量保存数据，其他值可以标记操作。例如，`GGML_OP_MUL_MAT`表示该张量不保存数据，而仅表示两个其他张量之间的矩阵乘法的结果。
- `src`是指向要进行运算的张量的指针数组。例如，如果`op == GGML_OP_MUL_MAT`，`src`则将包含指向要进行乘法运算的两个张量的指针。如果`op == GGML_OP_NONE`，则将`src`为空。
- `data`指向实际张量的数据，或者`NULL`。如果该张量是一个操作。它也可能指向另一个张量的数据，那么它被称为视图*。*例如，在`ggml_transpose()`上面的函数中，结果张量是原始张量的视图，只是维度和步幅翻转了。`data`指向内存中的相同位置。

矩阵乘法函数很好地说明了这些概念：

```cpp
// ggml.c (simplified and commented)
struct ggml_tensor * ggml_mul_mat(
        struct ggml_context * ctx,
        struct ggml_tensor  * a,
        struct ggml_tensor  * b) {
    // Check that the tensors' dimensions permit matrix multiplication.
    GGML_ASSERT(ggml_can_mul_mat(a, b));

    // Set the new tensor's dimensions
    // according to matrix multiplication rules.
    const int64_t ne[4] = { a->ne[1], b->ne[1], b->ne[2], b->ne[3] };
    // Allocate a new ggml_tensor.
    // No data is actually allocated except the wrapper struct.
    struct ggml_tensor * result = ggml_new_tensor(ctx, GGML_TYPE_F32, MAX(a->n_dims, b->n_dims), ne);

    // Set the operation and sources.
    result->op   = GGML_OP_MUL_MAT;
    result->src[0] = a;
    result->src[1] = b;

    return result;
}

```

在上面的函数中，`result`不包含任何数据。它只是表示将`a`与 b 相乘的理论结果。

### *2.3、计算张量*

**上述函数`ggml_mul_mat()`或任何其他张量运算都不会计算任何内容，而只是为运算准备张量。从另一个角度来看，它构建了一个计算图，其中每个张量运算都是一个节点，运算的源是节点的子节点。**在矩阵乘法场景中，该图有一个带有运算的父节点`GGML_OP_MUL_MAT`，以及两个子节点。

作为来自 llama.cpp 的真实示例，以下代码实现了自注意力机制，它是每个 Transformer 层的一部分，稍后将进行更深入的探讨：

```cpp
// llama.cpp
static struct ggml_cgraph * llm_build_llama(/* ... */) {
    // ...

    // K,Q,V are tensors initialized earlier
    struct ggml_tensor * KQ = ggml_mul_mat(ctx0, K, Q);
    // KQ_scale is a single-number tensor initialized earlier.
    struct ggml_tensor * KQ_scaled = ggml_scale_inplace(ctx0, KQ, KQ_scale);
    struct ggml_tensor * KQ_masked = ggml_diag_mask_inf_inplace(ctx0, KQ_scaled, n_past);
    struct ggml_tensor * KQ_soft_max = ggml_soft_max_inplace(ctx0, KQ_masked);
    struct ggml_tensor * KQV = ggml_mul_mat(ctx0, V, KQ_soft_max);

    // ...
}

```

该代码是一系列张量运算，并构建了一个与[原始 Transformer 论文](https://arxiv.org/pdf/1706.03762.pdf)中描述的计算图相同的计算图：

![](https://pic4.zhimg.com/v2-d6f365042ecff13c686bb98e016c9015_1440w.jpg)

为了实际**计算**结果张量（这里是`KQV`），采取以下步骤：

1. 数据被加载到每个叶张量的`data`指针中。在示例中，叶张量为`K`、`Q`和`V`。
2. 输出张量 ( `KQV`) 使用`ggml_build_forward()` 转换为计算图。此函数相对简单，按深度优先顺序对节点进行排序[。1](https://www.omrimallis.com/posts/understanding-how-llm-inference-works-with-llama-cpp/#user-content-fn-1)
3. 计算图使用`ggml_graph_compute()`运行，它以深度优先的顺序在每个节点上运行`ggml_compute_forward()`。`ggml_compute_forward()`完成繁重的计算，它执行数学运算并用结果填充张量的`data`指针。
4. 在这个过程结束时，输出张量的`data`指针指向最终结果。

### *2.4、将计算卸载到 GPU*

由于 GPU 具有高并行性，许多张量运算（如矩阵加法和乘法）都可以在 GPU 上更高效地计算。当 GPU 可用时，张量可以标记为`tensor->backend = GGML_BACKEND_GPU`。在这种情况下，`ggml_compute_forward()`将尝试将计算卸载到 GPU。GPU 将执行张量运算，结果将存储在 GPU 的内存中（而不是`data`指针中）。

考虑之前显示的自注意力估算图。假设`K`、`Q`、`V`是固定张量，则计算可以卸载到 GPU：

![](https://pic3.zhimg.com/v2-0bbdbc53ce40c6a763cec5c782c26516_r.jpg)

该过程首先将`K`、`Q`复制`V`到 GPU 内存。然后，CPU 逐个张量地向前驱动计算，但实际的数学运算被卸载到 GPU。当图中的最后一个操作结束时，结果张量的数据将从 GPU 内存复制回 CPU 内存。

**注意：**在实际 transformer 中，`K,Q,V`不是固定的，`KQV`也不是最终输出。稍后会详细介绍。

通过对张量的理解，我们可以回到 LLaMA 的流程。

## 3、Tokenization

推理的第一步是 tokenization，*它是将提示词拆分为称为token的*较短字符串列表的过程。token必须是模型词汇表的一部分，该词汇表是 LLM 训练所用的token列表。例如，LLaMA 的词汇表由 32K 个token组成，并作为模型的一部分进行分发。

对于我们的示例提示，tokenization将提示词拆分为 11 个token（空格被特殊元符号 ' ' (U+2581) 替换）：

```text
|Quant|um|_mechan|ics|_is|_a|_fundamental|_theory|_in|_physics|_that|
```

对于tokenization，LLaMA 使用带有字节对编码 (BPE) 算法的[SentencePiece tokenizer](https://github.com/google/sentencepiece)。此tokenizer很有趣，因为它是基于子词的，这意味着单词可能由多个token表示。例如，在我们的提示词中，“Quantum”被拆分为“Quant”和“um”。**在训练期间，当词汇表派生时，BPE 算法确保常用词作为单个token包含在词汇表中，而罕见词则被分解为子词。在上面的例子中，单词“Quantum”不是词汇表的一部分，但“Quant”和“um”是两个单独的token。空格不会被特殊处理，如果它们足够常见，则会作为元字符包含在token本身中。**

基于子词的tokenization功能强大，原因如下：

- **它允许大模型学习“Quantum”等罕见词的含义，同时通过将常见的后缀和前缀表示为单独的token来保持词汇量相对较小。**
- 它学习特定语言的特征，而不采用特定语言的tokenization方案。引用[BPE 编码论文](https://aclanthology.org/P16-1162.pdf)：“*考虑诸如德语 Abwasser|behandlungs|anlange ‘sewage water treatment plant’之类的复合词，对于它来说，分段、可变长度的表示在直观上比将单词编码为固定长度的向量更具吸引力。“*
- 同样，它在解析代码时也很有用。例如，名为`model_size`的变量将被tokenized为`model|_|size`，允许 LLM“理解”变量的用途（这也是为变量赋予指示性名称的另一个原因！）。

在 llama.cpp 中，使用`llama_tokenize()`函数执行tokenization 。此函数将提示词字符串作为输入并返回一个token列表，其中每个token由一个整数表示：

```cpp
// llama.h
typedef int llama_token;

// common.h
std::vector<llama_token> llama_tokenize(
        struct llama_context * ctx,
        // the prompt
        const std::string & text,
        bool   add_bos);

```

tokenization 过程首先将提示词分解为单字符token（single-character token）。然后，它会迭代尝试将每两个连续token合并为一个更大的token，只要合并的token是词汇表的一部分。这可确保生成的token尽可能大。对于我们的示例提示词，tokenization 步骤如下：

```text
Q|u|a|n|t|u|m|_|m|e|c|h|a|n|i|c|s|_|i|s|_a|_|f|u|n|d|a|m|e|n|t|a|l|

Qu|an|t|um|_m|e|ch|an|ic|s|_|is|_a|_f|u|nd|am|en|t|al|

Qu|ant|um|_me|chan|ics|_is|_a|_f|und|am|ent|al|

Quant|um|_mechan|ics|_is|_a|_fund|ament|al|

Quant|um|_mechan|ics|_is|_a|_fund|amental|

Quant|um|_mechan|ics|_is|_a|_fundamental|
```

请注意，每个中间步骤都包含根据模型词汇进行的有效tokenization。但是，只有最后一个步骤用作 LLM 的输入。

## 4、Embedding

这些 token 被用作 LLaMA 的输入，以预测下一个 token。这里的关键函数是`llm_build_llama()`：

```cpp
// llama.cpp (simplified)
static struct ggml_cgraph * llm_build_llama(
         llama_context & lctx,
     const llama_token * tokens,
                   int   n_tokens,
                   int   n_past);

```

此函数将由`tokens`和`n_tokens`参数表示的token列表作为输入。然后，它构建 LLaMA 的完整张量计算图，并将其作为`struct ggml_cgraph`返回。此阶段实际上不进行任何计算。`n_past`参数目前设置为零，现在可以忽略。我们稍后在讨论 KV 缓存时会重新讨论它。

除了token之外，该函数还利用了*模型权重*或*模型参数，它们*是在 LLM 训练过程中学习到的固定张量，并包含在模型中，这些模型参数在推理开始之前预先加载到`lctx`。

我们现在开始探索计算图结构。该计算图的第一部分涉及将token转换为*embedding*。

*embedding*是每个token的固定向量表示，它比纯整数更适合深度学习，因为它可以捕捉单词的语义。**此向量的大小是*模型维度*，不同模型的维度不同。**例如，在 LLaMA-7B 中，模型维度为`n_embd=4096`。

模型参数包括一个将token转换为embedding的 *token-embedding 矩阵，*由于我们的词汇量为`n_vocab=32000`，因此这是一个`32000 x 4096`矩阵，每行包含一个token的embedding向量：

![](https://pic4.zhimg.com/v2-921bc848cd79bb934c0d61e596cfecf7_r.jpg)
*每个token都有一个相关的embedding，该embedding是在训练期间学习的，并且可以作为token-embedding矩阵的一部分访问。*

计算图的第一部分是从每个token的token-embedding矩阵中提取相关行：

```cpp
// llama.cpp (simplified)
static struct ggml_cgraph * llm_build_llama(/* ... */) {
    // ...

    struct ggml_tensor * inp_tokens = ggml_new_tensor_1d(ctx0, GGML_TYPE_I32, n_tokens);
    memcpy(
        inp_tokens->data,
        tokens,
        n_tokens * ggml_element_size(inp_tokens));

    inpL = ggml_get_rows(ctx0, model.tok_embeddings, inp_tokens);
}
//

```

代码首先创建一个新的一维整数张量，称为`inp_tokens`，用于保存数字编号的token。然后，它将token值复制到此张量的`data`指针中。最后，它创建一个新的`GGML_OP_GET_ROWS`张量操作，将token-embedding矩阵`model.tok_embeddings`与我们的token结合起来。

此操作在稍后计算时，从embeddings矩阵中提取行（如上图所示），以创建一个新`n_tokens x n_embd`矩阵，该矩阵仅包含按原始顺序排列的token的embedding：

![](https://pic3.zhimg.com/v2-2853261abb4644f9e1d00f48ff78389a_1440w.jpg)
*embedding过程会为每个原始token创建一个固定大小的embedding向量。当它们堆叠在一起时，它们就构成了提示词的embedding矩阵。*

## 5、Transformer

计算图的主要部分称为*Transformer*。Transformer 是一种神经网络架构，是 LLM 的核心，并执行主要的推理逻辑。在下一节中，我们将从工程角度探讨 Transformer 的一些关键方面，重点关注自注意力机制。如果你想了解 Transformer 架构背后的直觉，我建议你阅读[The Illustrated Transformer](https://jalammar.g</u>ithub.io/illustrated-transformer/)<u>[</u>[2](https://www.omrimallis.com/posts/understanding-how-llm-inference-works-with-llama-cpp/#user-content-fn-2)<u>]。</u>

### *5.1、自注意力（Self-attention）*

我们首先放大来看一看什么是自注意力；然后我们再缩回来看一看它是如何融入整体 Transformer 架构[[3]](https://www.omrimallis.com/posts/understanding-how-llm-inference-works-with-llama-cpp/#user-content-fn-3)。

自注意力机制是一种机制，它采用一系列token并生成该序列的紧凑向量表示，同时考虑到token之间的关系。它是 LLM 架构中唯一计算token之间关系的地方。因此，它构成了语言理解的核心，这需要理解单词关系。由于它涉及跨token计算，因此从工程角度来看它也是最有趣的地方，因为计算量可能会变得非常大，尤其是对于较长的序列。

**（1）**自注意力机制的输入是`n_tokens x n_embd`的embedding矩阵，每行或每个向量代表一个单独的token[[4](https://www.omrimallis.com/posts/understanding-how-llm-inference-works-with-llama-cpp/#user-content-fn-4)<u>]</u>。然后，每个向量被转换成三个不同的向量，分别称为“key”、“query”和“value”向量。转换是通过将每个token的embedding向量与固定的`wk`、`wq`和`wv`矩阵相乘来实现的，这些矩阵是模型参数的一部分：

![](https://pic1.zhimg.com/v2-40e7c320c5eed39fbb4a2f2f5149c942_r.jpg)
*将token的embedding向量与 wk、wq 和 wv 参数矩阵相乘，会生成该token的“key”、“query”和“value”向量*

这个过程对每个 token 重复，即`n_tokens`次。理论上，这可以在循环中完成，但为了提高效率，使用矩阵乘法在单个操作中转换所有行，这正是这样做的。相关代码如下所示：

```cpp
// llama.cpp (simplified to remove use of cache)

// `cur` contains the input to the self-attention mechanism
struct ggml_tensor * K = ggml_mul_mat(ctx0,
    model.layers[il].wk, cur);
struct ggml_tensor * Q = ggml_mul_mat(ctx0,
    model.layers[il].wq, cur);
struct ggml_tensor * V = ggml_mul_mat(ctx0,
    model.layers[il].wv, cur);

```

我们最终得到`K`、`Q`和`V`：三个矩阵，大小也为`n_tokens x n_embd`，每个token的key、query和value向量堆叠在一起。

**（2）**自注意力的下一步是将`Q`（包含堆叠query向量）的矩阵 与`K`（包含堆叠key向量）的矩阵的转置相乘。对于那些不太熟悉矩阵运算的人来说，此操作本质上是计算每对query和key向量的联合得分。我们将使用符号`S(i,j)`来表示query `i 对 key j`的得分。

此过程产生`n_tokens^2`分数，每个query-key对一个得分，打包在一个名为`KQ`的矩阵中。随后对该矩阵进行屏蔽，以删除对角线上方的条目：

![](https://pic4.zhimg.com/v2-c5571a52d8860d29e501bea7ee87da8d_r.jpg)
*通过将 Q 与 K 的转置相乘，为每个query-key对计算联合得分 S(i,j)。此处显示的结果针对前四个token以及每个得分所代表的token。掩码步骤可确保仅保留token与其前一个token之间的得分。为简单起见，省略了中间的缩放操作。*

**掩码操作是关键步骤。对于每个token，它仅保留其前面那些tokens的分数。在训练阶段，此约束可确保 LLM 学会仅根据过去的token而不是未来的token来预测token。此外，正如我们稍后将详细探讨的那样，它允许在预测未来token时进行重大优化。**

**（3）**自注意力的最后一步是将掩码得分`KQ_masked`矩阵与之前的V矩阵相乘[[5](https://www.omrimallis.com/posts/understanding-how-llm-inference-works-with-llama-cpp/#user-content-fn-5)]。这样的矩阵乘法运算会创建所有前面token的value向量的加权和，其中权重是得分`S(i,j)`。例如，对于第4个token`ics`，它会创建`Quant、um、_mechan和ics`的value向量的加权和，权重为`S(3,0)到S(3,3)`，而这些权重本身是根据 ics 的query向量和所有前面的key向量计算出来的。

![](https://pic4.zhimg.com/v2-1b93b740fc5d95de7d75e67487bee1c1_r.jpg)
*KQV 矩阵包含值向量的加权和。例如，高亮的最后一行是前四个值向量的加权和，其中权重是高亮的分数。*

矩阵`KQV`总结了自注意力机制。实现自注意力的相关代码[之前已经在一般张量计算的背景下介绍过了](https://www.omrimallis.com/posts/understanding-how-llm-inference-works-with-llama-cpp/#computing-tensors)，但现在你能够更好地完全理解它了。

【**理解一下**】：

**QKV 很类似于搜索系统的检索行为：可以类比Q矩阵是输入的查询（转化成隐空间向量矩阵的形式，每一行表示一个query），K矩阵是隐空间中的语义向量索引（每一列表示一个key），V矩阵是对应K矩阵中每条索引的具体内容（具体内容使用隐空间中的向量形式表示，每一列表示一个value）。**

**（1）首先计算QK的联合概率分布即Q对K的匹配度分布：计算Q矩阵中每个query和K矩阵中每个key（类比索引）的联合概率（类比匹配度或打分或权重），即每个query分别对每个key的打分（权重），输出的结果是一个打分矩阵，其中每一行表示一个query对每个key的打分，即对一个query_i，输出是（query_i * key_0, query_i * key_1, …, query_i * key_n)。**

**（2）接着计算QKV即QK对V的加权和，上一步的QK作为加权权重(相当于query对value的加权权重)，从而最终得出Q中任意一个query对V中每个value的加权和，写成矩阵的形式就是QKV。**

### *5.2、Transformer 的各层*

*自注意力机制是 Transformer层*中的组成部分之一。除了自注意力机制之外，每一层还包含多个其他张量运算，主要是矩阵加法、乘法和激活，它们是前馈神经网络的一部分。我们不会更详细地探讨这些，但只需注意以下事实：

- 前馈网络使用大型固定参数矩阵。在 LLaMA-7B 中，它们的大小为`n_embd x n_ff = 4096 x 11008`。
- 除了 self-attention，其他操作都可以认为是按row-by-row 或 token-by-token进行的。**如前所述，只有 self-attention 包含跨 token 的计算。这在后面讨论 KV-Cache 时很重要。**
- **输入和输出的大小始终是`n_tokens x n_embd`：每个token一行，每行的大小为模型的尺寸。**

为了完整性，我在 LLaMA-7B 中附上了单个 Transformer 层的图表。请注意，确切的架构在未来的模型中很可能会略有不同。

![](https://pic4.zhimg.com/v2-83fd0bd229204c8c891699f1784e948d_r.jpg)
*LLaMA-7B 中 Transformer 层的完整计算图，包含自注意力和前馈机制。每层的输出作为下一层的输入。在自注意力阶段和前馈阶段都使用了大型参数矩阵。这些构成了模型 70 亿个参数中的大多数。*

Transformer 架构中有多个层。例如，LLaMA-7B 中有`n_layers=32`层。这些层完全相同，只是每个层都有自己的一组参数矩阵（例如，`wk、wq、wv`用于自注意力机制的矩阵）。第一层的输入是如上所述的embedding矩阵。然后，第一层的输出用作第二层的输入，依此类推。我们可以认为每个层都会生成一个embedding列表，但每个embedding不再直接与单个 token 相关联，而是与某种更复杂的 token 关系理解相关联。

### *5.3、计算 logits*

Transformer 的最后一步是计算 *logit。logit*是一个浮点数，表示某个 token 是“正确”的下一个 token 的概率。logit 的值越高，对应的 token 越有可能是“正确”的 token。

logit 的计算过程是：通过将最后一个 Transformer 层的输出与固定的`n_embd x n_vocab`参数矩阵（在 llama.cpp 中也称为`output`）相乘来计算的。此操作会为我们词汇表中的每个token生成一个 logit。例如，在 LLaMA 中，它会生成`n_vocab=32000`logit：

![](https://picx.zhimg.com/v2-0aea5de144cb6b2fa6ca54f6da06cb5d_r.jpg)
*Transformer 的最后一步是通过将最后一层的输出与固定的参数矩阵（也称为“输出”）相乘来计算logit。只有结果的最后一行（高亮显示）才是我们感兴趣的，它包含词汇表中每个可能的下一个token的logit。*

logits 是 Transformer 的输出，它告诉我们最有可能的下一个 token 是什么。通过这种方式，所有张量计算都结束了。以下简化和注释的`llm_build_llama()`函数版本，总结了本节中描述的所有步骤：

```cpp
// llama.cpp (simplified and commented)

static struct ggml_cgraph * llm_build_llama(
         llama_context & lctx,
     const llama_token * tokens,
                   int   n_tokens,
                   int   n_past) {
    ggml_cgraph * gf = ggml_new_graph(ctx0);
    struct ggml_tensor * cur;
    struct ggml_tensor * inpL;

    // Create a tensor to hold the tokens.
    struct ggml_tensor * inp_tokens = ggml_new_tensor_1d(ctx0, GGML_TYPE_I32, N);
    // Copy the tokens into the tensor
    memcpy(
        inp_tokens->data,
        tokens,
        n_tokens * ggml_element_size(inp_tokens));

    // Create the embedding matrix.
    inpL = ggml_get_rows(ctx0,
        model.tok_embeddings,
        inp_tokens);

    // Iteratively apply all layers.
    for (int il = 0; il < n_layer; ++il) {
        struct ggml_tensor * K = ggml_mul_mat(ctx0, model.layers[il].wk, cur);
        struct ggml_tensor * Q = ggml_mul_mat(ctx0, model.layers[il].wq, cur);
        struct ggml_tensor * V = ggml_mul_mat(ctx0, model.layers[il].wv, cur);

        struct ggml_tensor * KQ = ggml_mul_mat(ctx0, K, Q);
        struct ggml_tensor * KQ_scaled = ggml_scale_inplace(ctx0, KQ, KQ_scale);
        struct ggml_tensor * KQ_masked = ggml_diag_mask_inf_inplace(ctx0,
            KQ_scaled, n_past);
        struct ggml_tensor * KQ_soft_max = ggml_soft_max_inplace(ctx0, KQ_masked);
        struct ggml_tensor * KQV = ggml_mul_mat(ctx0, V, KQ_soft_max);

        // Run feed-forward network.
        // Produces `cur`.
        // ...

        // input for next layer
        inpL = cur;
    }

    cur = inpL;

    // Calculate logits from last layer's output.
    cur = ggml_mul_mat(ctx0, model.output, cur);

    // Build and return the computation graph.
    ggml_build_forward_expand(gf, cur);
    return gf;
}

```

为了实际执行推理，[使用前面描述的](https://www.omrimallis.com/posts/understanding-how-llm-inference-works-with-llama-cpp/#computing-tensors)`ggml_graph_compute()`方法计算此函数返回的计算图。然后将 logit 从最后一个张量的`data`指针复制到浮点数组中，为下一步（称为采样）做好准备。

## 6、Sampling

有了 logit 列表，下一步就是根据它们选择下一个 token。这个过程称为*抽样*。有多种抽样方法可用，适用于不同的用例。在本节中，我们将介绍两种基本抽样方法，而语法抽样等更高级的抽样方法留待以后的帖子介绍。

### *6.1、贪婪采样（Greedy sampling）*

贪婪抽样是一种直接的方法，它选择与之相关的具有最高logit值的token。

对于我们的示例提示，以下token具有最高的logit值：

| token | logit |
| --- | --- |
| _describes | 18.990 |
| _provides | 17.871 |
| _explains | 17.403 |
| _de | 16.361 |
| _gives | 15.007 |

因此，贪婪采样将确定性地选择`▁describes`作为下一个token。**当重新评估相同提示词时需要确定性输出时，贪婪采样最有用。**

### *6.2、温度采样（Temperature sampling）*

温度采样是概率性的，这意味着相同的提示词在重新评估时可能会产生不同的输出。它使用一个名为*temperature*的参数，该参数是 0 到 1 之间的浮点值，会影响结果的随机性。过程如下：

1. 对 logit 从高到低进行排序，并使用[softmax 函数](https://en.wikipedia.org/wiki/Softmax_function)进行归一化，以确保它们的总和为 1。此转换将每个 logit 转换为一个概率。
2. 应用阈值（默认设置为 0.95），仅保留排名靠前的 token，使其累积概率保持在阈值以下。此步骤可有效删除低概率 token，防止“坏”或“不正确”的 token 被极少采样。
3. 将筛选通过的 logits 除以 *temperature*参数并再次标准化，使得它们的总和为 1 并表示概率。
4. 根据这些概率随机抽取一个 token。例如，在我们的提示词中，token`▁describes`的概率为`p=0.6`，这意味着它将被选中的概率约为 60%。一旦重新评估，可能会选择不同的 token。

**步骤 3 中的温度参数用于增加或减少随机性。较低的温度值会抑制较低概率的token，使得在重新评估时更有可能选择相同的token。因此，较低的温度值会降低随机性。相反，较高的温度值往往会“拉平”概率分布，强调较低概率的token。这增加了每次重新评估产生不同token的可能性，从而增加了随机性。**

![](https://picx.zhimg.com/v2-e4337ac4c518421d6bd42969f8782bfb_r.jpg)
*我们的提示词示例标准化下一个token的概率。较低的温度会抑制低概率token，而较高的温度会强调它们。temp=0 本质上与贪婪采样相同。*

采样一个 token 会结束 LLM 的完整迭代。采样初始 token 后，会将其添加到 token 列表中，然后整个过程再次运行。输出迭代地成为 LLM 的输入，每次迭代增加一个 token。

理论上，后续迭代可以以相同的方式进行。但是，为了解决随着token列表的增长而导致的性能下降问题，我们采用了某些优化措施。这些措施将在下文中介绍。

## 7、优化推理（Optimizing inference）

随着 LLM 输入 token 列表的增长，Transformer 的自注意力阶段可能成为性能瓶颈。更长的 token 列表意味着需要将更大的矩阵相乘。每个矩阵乘法都包含许多较小的数值运算，称为浮点运算，这些运算受到 GPU 每秒浮点运算能力 (flops) 的限制。在[Transformer 推理算法](https://kipp.ly/transformer-inference-arithmetic/)中，计算得出，对于 A100 GPU 上的 52B 参数模型，由于过多的 flops，性能在 208 个 token 时开始下降。解决此瓶颈最常用的优化技术称为 *KV 缓存*。

### *7.1、KV缓存*

回顾一下，每个 token 都有一个关联的embedding向量，通过将其与参数矩阵`wk`和`wv`相乘，可以进一步将其转换为key和value向量。KV 缓存是这些key和value向量的缓存。通过缓存它们，我们可以节省每次迭代时重新计算它们所需的浮点运算。

缓存的工作原理如下：

- 在迭代初始化时，将为所有token计算key和value向量，如前所述，然后保存到 KV 缓存中。
- 在后续迭代中，只需要计算最新token的key和value向量。缓存的 KV 向量与新token的 KV 向量连接在一起，形成`K`和`V`矩阵。这可以节省重新计算所有先前token的 KV 向量的时间，这可能很重要。

![](https://pica.zhimg.com/v2-8f593dd0c8c2356924f9623c086f7810_r.jpg)
*在后续迭代中，仅计算最新 token 的 key 向量。其余的从缓存中拉取，它们一起形成 K 矩阵。新计算的 key 向量也会保存到缓存中。对 value 向量也应用相同的过程。*

**能够利用缓存来存储key和value向量，是因为这些向量在迭代之间保持不变。**例如，如果我们首先处理4个token，然后处理5个token，其中前4个token保持不变，那么前4个key和value向量在第一次迭代和第二次迭代之间将保持不变。因此，在第二次迭代中无需重新计算前4个标记的key和value向量。

**这一原则适用于Transformer 中的所有层，而不仅仅是第一层。在所有层中，每个 token 的key和value向量仅依赖于先前的token。因此，随着新 token 在后续迭代中被添加，已存在 token 的key和value向量保持不变。**

对于第一层，这个概念相对容易验证：一个 token 的 key 向量由 token 的固定embedding与固定`wk`参数矩阵相乘来确定。因此，无论引入了多少额外的 token，key 向量在后续迭代中都保持不变。同样的原理也适用于 value 向量。

对于第二层及以后的层，这个原则不太明显，但仍然适用。要理解原因，请考虑第一层的`KQV`矩阵，即自注意力阶段的输出。`KQV`矩阵中的每一行都是一个加权和，取决于：

- 先前token的value向量。
- 根据先前token的key向量计算出分数。

因此，`KQV`中的每一行都完全依赖于先前的token。这个矩阵经过一些额外的基于行的操作后，作为第二层的输入。这意味着第二层的输入在未来的迭代中将保持不变，除了添加新行。归纳起来，同样的逻辑扩展到其余层。

![](https://pica.zhimg.com/v2-e9d0d5763d6f7a465103f390c7e9b4b8_r.jpg)
*再看一下 KQV 矩阵的计算方式。高亮显示的第3行仅基于第3个query向量和前3个key和value向量（高亮显示）确定。后续token不会影响它。因此它将在未来的迭代中保持不变。*

### *7.2、进一步优化后续迭代*

您可能想知道，既然我们缓存了K和V向量，为什么我们不缓存Q向量呢？**答案是，事实上，除了当前 token 的query向量之外，在后续迭代中不需要先前 token 的query向量。**有了 KV 缓存，我们实际上可以只使用最新 token 的query向量来提供给自注意力机制。将此query向量与缓存的矩阵`K`相乘，以计算最后一个 token 和所有先前 token 的联合分数。然后，将其与缓存矩阵`V`相乘，仅计算矩阵`KQV`最新的一行。事实上，在所有层中，我们现在传递`1 x n_embd` 大小的向量，而不是在第一次迭代中计算使用的`n_token x n_embd`矩阵。为了说明这一点，请将下图（高亮显示后续迭代）与上一次迭代进行比较：

![](https://pic2.zhimg.com/v2-959ec90e8aa467f611ac05eec428f9ef_r.jpg)
*后续迭代中的自注意力。在此示例中，第一次迭代中有4个token，第2次迭代中添加了第5个token“is”。最新的token的key、query和value向量以及缓存的key和value向量用于计算 KQV 的最后一行，这是预测下一个token所需的全部内容。*

此过程在所有层上重复，利用每一层的 KV 缓存。因此，在这种情况下，Transformer 的输出是一个大小为`n_vocab`的logit向量（预测下一个 token）。

通过这种优化，我们节省了计算和中不必要行的浮点运算`KQ和KQV`，随着token列表的大小不断增长，这些运算可能会变得非常重要。

### *7.3、实践中的 KV 缓存*

我们可以深入研究 llama.cpp 代码，看看 KV 缓存在实践中是如何实现的。不出所料，它是使用张量构建的，一个用于key向量，一个用于value向量：

```cpp
// llama.cpp (simplified)

struct llama_kv_cache {
    // cache of key vectors
    struct ggml_tensor * k = NULL;

    // cache of value vectors
    struct ggml_tensor * v = NULL;

    int n; // number of tokens currently in the cache
};

```

当初始化缓存时，会分配足够的空间来保存每层的 512 个key和value向量：

```cpp
// llama.cpp (simplified)
// n_ctx = 512 by default
static bool llama_kv_cache_init(
    struct llama_kv_cache & cache,
    ggml_type   wtype,
    int   n_ctx) {
    // Allocate enough elements to hold n_ctx vectors for each layer.
    const int64_t n_elements = n_embd*n_layer*n_ctx;

    cache.k = ggml_new_tensor_1d(cache.ctx, wtype, n_elements);
    cache.v = ggml_new_tensor_1d(cache.ctx, wtype, n_elements);

    // ...
}

```

回想一下，在推理过程中，计算图是使用函数`llm_build_llama()`构建的。此函数有一个我们之前忽略的参数`n_past`。在第一次迭代中，`n_tokens`参数包含token数并设置`n_past`为 0。在后续迭代中，`n_tokens`设置为 1，因为只处理最新的token，并且`n_past`包含过去token的数量。`n_past`然后用于从KV 缓存中提取正确数量的query和value向量。

该函数的相关部分如下所示，利用缓存来计算矩阵`K`。我稍微简化了它以忽略多头注意力，并为每个步骤添加了注释：

```cpp
// llama.cpp (simplified and commented)

static struct ggml_cgraph * llm_build_llama(
    llama_context & lctx,
    const llama_token * tokens,
    int   n_tokens,
    int   n_past) {
    // ...

    // Iteratively apply all layers.
    for (int il = 0; il < n_layer; ++il) {
         // Compute the key vector of the latest token.
         struct ggml_tensor * Kcur = ggml_mul_mat(ctx0, model.layers[il].wk, cur);
         // Build a view of size n_embd into an empty slot in the cache.
         struct ggml_tensor * k = ggml_view_1d(
            ctx0,
            kv_cache.k,
            // size
            n_tokens*n_embd,
            // offset
            (ggml_element_size(kv_cache.k)*n_embd) * (il*n_ctx + n_past)
         );

         // Copy latest token's k vector into the empty cache slot.
         ggml_cpy(ctx0, Kcur, k);

         // Form the K matrix by taking a view of the cache.
         struct ggml_tensor * K =
             ggml_view_2d(ctx0,
                 kv_self.k,
                 // row size
                 n_embd,
                 // number of rows
                 n_past + n_tokens,
                 // stride
                 ggml_element_size(kv_self.k) * n_embd,
                 // cache offset
                 ggml_element_size(kv_self.k) * n_embd * n_ctx * il);
    }
}

```

首先，计算新的key向量。然后，`n_past`用来查找缓存中的下一个空slot，并将新的key向量复制到那里。最后，通过将具有正确数量的token的视图放入缓存中来形成`K`矩阵（`n_past + n_tokens`）。

KV 缓存是 LLM 推理优化的基础。值得注意的是，在 llama.cpp 中实现的版本（截至本文撰写时）并不是最优的。例如，它预先分配了大量内存来保存支持的最大数量的key和value向量（在本例中为 512）。更高级的实现，如[vLLM](https://vllm.ai/)，旨在提高内存使用效率，并可能提供进一步的性能改进。这些高级技术留待以后的文章。此外，随着该领域以闪电般的速度向前发展，未来可能会出现新的和改进的优化技术。
