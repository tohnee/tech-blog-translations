## 摘要

**FlashAttention 是什么。** FlashAttention [[2]](https://arxiv.org/abs/2205.14135) 是 Transformer [[1]](https://arxiv.org/abs/1706.03762) 中 self-attention 算子的一种精确（exact）GPU 实现。它算的还是标准的 $O=\mathrm{softmax}(QK^\top/\sqrt d)\,V$，在数学上与常规实现完全一致，但计算速度更快，attention 的额外显存占用也从 $O(N^2)$ 降到了 $O(N)$。这套思路已经成为大模型训练和推理中高性能 attention 的基础。比如，PyTorch 的 `scaled_dot_product_attention` 在形状、精度和硬件满足条件时，就会自动选择 FlashAttention 后端 [[17]](https://pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html) [[22]](https://pytorch.org/blog/pytorch2-2/)。

**它解决的问题。** GPU 算力的增长远快于显存带宽的增长。对于越来越多的算子来说，时间花在了等数据上，这就是 memory wall。标准 attention 会把 $N\times N$ 的分数矩阵 $S$ 和概率矩阵 $P$ 完整写入 GPU 显存（HBM），再读出来进行下一步计算。softmax、mask、dropout 每读取一个数，只需要做少量运算，真正拖慢速度的是这些 $N^2$ 级别的显存读写。上下文变长以后，这两个矩阵还会超出显存容量。

**它具体怎么做。** 核心思路是让中间结果只在片上 SRAM 中暂时保留，不再写入 HBM。这需要三件事配合：

1. **Tiling（分块）**：把 $Q,K,V$ 切成小块，搬入 SRAM。一个 $K,V$ 块可以被多个 query 块复用，矩阵乘法、softmax、mask 则融合到一个 kernel 中，在片上完成。
2. **Online softmax（在线归一化）**：softmax 的分母依赖整行数据，不能直接按块分别计算。FlashAttention 为每一行只维护两个标量：当前最大值 $m$ 和指数和 $\ell$。每处理一个新块，就通过缩放因子把旧结果调整到新的基准上，再精确合并各块的结果，不需要重新查看之前的分数。
3. **Recomputation（重计算）**：反向传播原本需要保存 $P$。FlashAttention 只保存每行的 $L=m+\log\ell$，反向时再用 $Q,K$ 在片上重新算出概率块。虽然多做了一些运算，但节省的显存读写更多，因此整体速度反而更快。

下面先从 LLM 推理中的 memory wall 说起，说明为什么需要 FlashAttention。然后逐步推导 online softmax 和分块算法，结合流程图解释每一步，再用一个 $N=4$ 的小例子完整手算一遍。最后讨论 I/O 复杂度、反向传播，以及后续工作的演化。

## 1. 从 LLM 推理的 memory wall 说起

### 1.1 算力跑在前面，带宽落在后面

过去 20 年，GPU 峰值算力大约每 2 年增长 3.0 倍，DRAM 带宽每 2 年只增长约 1.6 倍，芯片之间的互连带宽增长更慢，约为 1.4 倍 [[23]](https://arxiv.org/abs/2403.14123)。长期累积下来，算力和带宽之间的增长差距达到了两到三个数量级。这就是 **memory wall**：计算单元越来越快，数据传输却没有跟上。

![](https://pica.zhimg.com/v2-85b882ab7928c30d0b01ac73b89b7bda_r.jpg)

以 A100 为例 [[12]](https://images.nvidia.com/aem-dam/en-zz/Solutions/data-center/nvidia-ampere-architecture-whitepaper.pdf)：FP16 Tensor Core 的峰值算力约为 312 TFLOPS，HBM 带宽约为 1.5–2.0 TB/s。两者相除，得到约 150–200 FLOP/Byte。也就是说，**每从显存读取 1 个字节，至少需要做 150 次以上浮点运算，才能充分利用算力**。这个比值就是 roofline 模型 [[11]](https://doi.org/10.1145/1498765.1498785) 中的“拐点”。如果一个算子的运算强度（FLOPs ÷ 读写字节数）低于这个拐点，它就是 memory-bound，运行速度主要由带宽决定，Tensor Core 的算力再高也发挥不出来。

### 1.2 LLM 推理里的两堵墙

LLM 推理分为两个阶段 [[16]](https://arxiv.org/abs/2211.05102) [[25]](https://arxiv.org/abs/2402.16363)：

- **Prefill**：一次性处理整个 prompt，让 $N$ 个 token 并行计算，生成每一层的 K、V，并存入 KV cache。
- **Decode**：每一步只生成 1 个新 token，需要读取全部模型权重，以及之前所有 token 的 KV cache。

这两个阶段遇到的带宽瓶颈有所不同，可以理解为两堵墙。

**第一堵墙：decode 阶段的“读权重、读 KV cache”。** 以 Llama-2-7B [[24]](https://arxiv.org/abs/2307.09288) 为例，它的 FP16 权重约为 13.5 GB。当 batch size 为 1 时，每生成一个 token，都要从 HBM 读取一遍这 13.5 GB 的权重，而计算量只有约 $2\times7\text{B}=14$ GFLOP。在 A100 80GB（2.0 TB/s）上，仅仅读取权重就至少需要 6.7 ms，完成 14 GFLOP 的计算却只需要约 0.05 ms。运算强度约为 1 FLOP/Byte，比拐点低了两个数量级，GPU 大部分时间都在等数据。KV cache 也有同样的问题：每个 token 在每一层的 K、V，都需要在后续每一步中重新读取。这类瓶颈主要通过 batching、PagedAttention [[9]](https://arxiv.org/abs/2309.06180)、KV cache 量化等 serving 层技术来缓解。

**第二堵墙：attention 的 $N\times N$ 中间矩阵。** 在 prefill 和训练阶段，$N$ 个 token 共享权重矩阵乘法，运算强度已经足够高。但 attention 内部还会生成 $N\times N$ 的分数矩阵 $S$ 和概率矩阵 $P$，带来两个问题：

**1.** **流量问题**：softmax、mask、dropout 都需要完整读写一遍这些 $N^2$ 矩阵，运算强度只有个位数 FLOP/Byte，是典型的 memory-bound 操作。

**2.** **容量问题**：$S$ 的规模随 $N^2$ 增长，而 KV cache 随 $N$ 增长。前者对显存容量的需求增长得更快。

![](https://picx.zhimg.com/v2-679789257cb75e316c18f141729d496f_r.jpg)

图 B 按 Llama-2-7B 的结构进行了估算。$N=2$K 时，一层 32 个 head 的 $S$ 只占 256 MiB；当序列长度增加到 $N=32$K，就需要 64 GiB，几乎占满一张 80 GB 的 A100；到 128K 时，则需要 1 TiB。上下文长度每增加到原来的 4 倍，KV cache 增加到 4 倍，$S$ 却增加到 16 倍。因此，长上下文模型如果仍然完整生成并保存 $S$，显存就无法承受。

### 1.3 FlashAttention 瞄准的是第二堵墙

FlashAttention 不减少 KV cache，也不改变模型。它要做的是：**让 $S$ 和 $P$ 始终不写入 HBM**。这样既减少了流量，不再需要 $N^2$ 级别的中间矩阵读写，也降低了容量需求，把额外显存占用降到 $O(N)$。

在整个 LLM serving 系统中，FlashAttention 位于最底层的算子层。调度器、continuous batching、PagedAttention、prefix caching 等 serving 层技术决定这一轮计算哪些 token，以及 KV 存放在哪里；FlashAttention 则负责这一轮 attention 在 GPU 上如何算得更快、更省。下图展示了它与这些 serving 技术之间的关系：

### 1.4 一个直觉类比：小灶台和远仓库

我们可以把 GPU 想象成一个厨房：

- **厨师**是 Tensor Core，切菜、炒菜的速度很快。
- **灶台**是 SRAM，就在手边，但只能放下几个盘子。
- **仓库**是 HBM，能存放所有食材，只是每次取用都要走很远。

标准 attention 的过程是：先切完所有菜（算出完整的 $S$），把整盘菜送回仓库；再全部取出来调味（softmax），然后送回仓库；最后再取出来下锅（乘 $V$）。这样一来，厨师的大部分时间都花在往返搬运上。

FlashAttention 则是每次只取一小份食材（一个 $Q$ 块和一个 $K,V$ 块），在灶台上连续完成切菜、调味和下锅，只把做好的菜（输出 $O$）和一张记录当前进度的小纸条（每行的 $m,\ell$）送回仓库。中间产物始终留在灶台上。这也有代价：部分食材需要多取几次（$Q$ 和 $O$ 会被重复读写），但节省下来的搬运更多。

这里的难点在“调味”：softmax 需要整行所有元素才能完成归一化，而灶台上每次只有一小份。第 4–6 节会具体解释，为什么只保存那张“小纸条”就足够了。

## 2. Attention 的标准实现慢在哪里

Transformer [[1]](https://arxiv.org/abs/1706.03762) 的每一层都包含 multi-head self-attention。对于单个 head，计算分为三步：

$$ S=\tau QK^\top + A,\qquad P=\mathrm{softmax}_{\text{row}}(S),\qquad O=PV,\qquad \tau=1/\sqrt d $$

其中，$Q,K,V\in\mathbb R^{N\times d}$，$N$ 表示序列长度，$d$ 表示 head 维度（常见为 64 或 128），$A$ 是 mask 或 bias。GPT 系列 [[15]](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf) 这类自回归语言模型使用 causal mask，使每个 token 只能看到它之前的 token。

可以把第 $i$ 行的输出 $o_i$ 理解为所有 value 向量的加权平均。权重来自 query $q_i$ 与各个 key $k_j$ 的相似度，再经过 softmax 归一化。softmax 保证这些权重非负，并且总和为 1。

常规实现，例如直接用 PyTorch 写出这三步计算，会在每一步结束后把中间结果完整写回 HBM：

| 阶段 | 计算 | HBM 行为 |
| --- | --- | --- |
| 第一次矩阵乘 | S = QKᵀ | 读 Q, K，写完整 S（N² 个数） |
| Softmax | P = softmax(S) | 读完整 S，写完整 P |
| 第二次矩阵乘 | O = PV | 读完整 P、读 V，写 O |

仅写入 $S$、读取 $S$、写入 $P$、读取 $P$ 这四步，就需要 $4N^2$ 次标量搬运。如果再加入 mask、dropout [[14]](https://jmlr.org/papers/v15/srivastava14a.html) 等逐元素操作，每个操作还需要把 $N^2$ 矩阵完整读写一遍。

> **直观量级**：取 $N=4096,\ d=64$，使用 FP16，考虑单个 head。一个 $N\times N$ 矩阵占 32 MiB，而一个 $N\times d$ 矩阵只占 0.5 MiB。四次中间矩阵搬运合计 128 MiB，$Q,K,V,O$ 加起来却只有 2 MiB。也就是说，中间矩阵的流量是输入输出的 64 倍。即使乘法次数不变，只调整中间结果存放在哪里、保留多久，也有很大的优化空间。

## 3. GPU 两级存储与三个指标

GPU 的存储可以简化为两级 [[12]](https://images.nvidia.com/aem-dam/en-zz/Solutions/data-center/nvidia-ampere-architecture-whitepaper.pdf) [[21]](https://docs.nvidia.com/cuda/cuda-c-programming-guide/)：

- **HBM**（High Bandwidth Memory）：容量较大（A100 为 40–80 GB），带宽约为 1.5–2.0 TB/s，用于存放模型参数、激活值，以及 LLM 推理中的 KV cache。
- **SRAM**：这里指每个 SM（Streaming Multiprocessor）上的 shared memory 与寄存器，位于芯片内部。它的带宽比 HBM 高一个数量级，但每个 SM 只有约 192 KB。A100 全芯片约 20 MB 的 SRAM 是 108 个 SM 的合计，一个 thread block 只能使用所在 SM 的那一部分。

![](https://picx.zhimg.com/v2-88fc76bd9b7a780142eecd22c34f41ab_r.jpg)

Tensor Core 只能直接计算 SRAM 和寄存器中的数据，因此计算前需要先把数据从 HBM 搬入片上。一个 kernel 结束后，它在 SRAM 中的数据就不再保留；下一个 kernel 如果还需要这些数据，就要重新从 HBM 读取。这解释了为什么三个独立 kernel 会带来大量中间读写，也解释了为什么要把多步计算融合到一个 kernel 中，也就是 kernel fusion。

理解 FlashAttention 时，需要分清三个指标：

| 指标 | 含义 | FlashAttention 对它做了什么 |
| --- | --- | --- |
| FLOPs | 浮点运算次数，前向约 4N²d | 不减反增（反向重算多约 2N²d） |
| I/O | HBM 与 SRAM 之间搬运的元素数 | 主要优化对象：Θ(Nd + N²) → Θ(N²d²/M) |
| 峰值存储 | 某一时刻同时存活的数据量 | 额外内存从 O(N²) 降到 O(N) |

我们容易把优化理解为减少 FLOPs，但 FlashAttention 多做了一些计算，同时大幅减少了 I/O。下图从 roofline 的角度说明这一点：标准 attention 的运算强度约为 1.9 FLOP/Byte，处于 memory-bound 区；FlashAttention 的读写字节数减少约 8 倍，运算强度提高到约 17 FLOP/Byte，工作点沿着屋顶线向右上方移动。

![](https://pic3.zhimg.com/v2-3c2ee3f74fa54ac8ad5d7dfca8b156f8_r.jpg)

## 4. 为什么“每块做 softmax 再相加”是错的

如果不把整个 $S$ 写入 HBM，就需要分块计算。矩阵乘法可以直接分块，但 softmax 有一个问题：**它的分母依赖整行所有元素**。

先固定一条 query，把对应的 key 分成两个互不相交的集合 $A,B$。记：

$$ Z_A=\sum_{j\in A}e^{s_j},\qquad o_A=\frac{\sum_{j\in A}e^{s_j}v_j}{Z_A},\qquad o_{A\cup B}=\frac{Z_A\,o_A+Z_B\,o_B}{Z_A+Z_B} $$

因此，合并各块的局部输出时，需要按各自的**未归一化概率质量** $Z$ 进行加权平均。只保存 $o_A,o_B$，还不足以得到正确结果。

![](https://pic1.zhimg.com/v2-e85d2756e886fad639fbf0a47b5cedfc_r.jpg)

**直觉**：这类似于合并两个班级的平均分。A 班有 3 人，平均分为 2/3；B 班有 5 人，平均分为 11/5。计算全年级的平均分时，需要按人数加权，不能直接把两个平均数再平均。$Z$ 就对应每个块的“人数”。从概率的角度看，这就是全期望公式：局部 softmax 给出条件分布 $\Pr(j\mid j\in A)$，还需要保留计算 $\Pr(j\in A)$ 所需的信息。

## 5. 可合并的归一化状态 (m, ℓ, u)

直接保存 $Z_A$ 会遇到数值溢出。例如，把所有分数加上 1000，$e^{1000}$ 就超出了 float64 的范围。因此，可以利用 softmax 的平移不变性，同时保存指数的基准点 [[3]](https://arxiv.org/abs/1805.02867)：

$$ m_A=\max_{j\in A}s_j,\qquad \ell_A=\sum_{j\in A}e^{s_j-m_A},\qquad u_A=\sum_{j\in A}e^{s_j-m_A}v_j $$

这样就有 $o_A=u_A/\ell_A$，$Z_A=e^{m_A}\ell_A$。参与指数运算的数都 $\le 0$，不会发生上溢。**每条 query 只需保存 $d+2$ 个标量**，就能继续合并新的 key/value。

**直觉**：$m$ 可以看作“记账单位”。两个块各自以最大值为基准，相当于用了不同的记账单位。合并之前，需要先换算到同一个单位，就像合并人民币和美元的账目时需要先按汇率换算。换算过程中，分子 $u$ 和分母 $\ell$ 必须乘以相同的汇率，这样比值 $o=u/\ell$ 的含义才不会改变。

### 5.1 两个块的精确合并

$$ m=\max(m_A,m_B),\qquad \alpha=e^{m_A-m},\qquad \beta=e^{m_B-m} $$

$$ \ell=\alpha\ell_A+\beta\ell_B,\qquad u=\alpha u_A+\beta u_B,\qquad o=u/\ell $$

这个过程是把同一个指数和换算到统一尺度上，并没有做近似。新块的最大值更大时，旧的分子和分母要**同时**乘以同一个缩放因子 $\alpha<1$。如果保存的是归一化后的 $o$，而不是 $u$，更新式就写成 $o=\dfrac{\alpha\ell_Ao_A+\beta\ell_Bo_B}{\alpha\ell_A+\beta\ell_B}$。这两种写法在代数上是等价的。

### 5.2 从合并到 online 更新，以及结合律

把每次新读入的块看作 $B$，反复使用上面的合并规则，就是 online 更新。合并运算 $\oplus$ 满足 $T(A)\oplus T(B)=T(A\cup B)$，而且**满足结合律**，空状态 $m=-\infty,\ \ell=0,\ u=0$ 是它的单位元。因此，既可以串行地逐块处理，也可以进行树形归约，或者跨设备分片计算后再合并。后面的 Flash-Decoding [[8]](https://pytorch.org/blog/flash-decoding/) 和多卡 attention 都利用了这一性质。不过，浮点加法本身并不严格满足结合律，所以不同的划分方式会在舍入层面产生微小差异。

> **边界情况**：实现时不能无条件计算 $e^{-\infty-(-\infty)}$，否则会得到 NaN。旧状态为空时，直接接收新块；新块被 mask 完全屏蔽时，保持旧状态。如果整行都没有有效 key，softmax 就没有定义，需要由接口提前约定如何处理。Causal attention 始终保留对角线，因此每行至少有一个有效 key。<br> **这个摘要依赖当前 query**：$(m,\ell,u)$ 是针对一条固定 query $q$ 得到的摘要，不能把它当作适用于未来任意 query 的 KV 压缩。换成 $q'$ 后，所有分数都会改变。这也是 FlashAttention 不能替代 KV cache 的原因。

## 6. 先用一行数据手算 online 更新

先看一行数据，手算一下 online 更新是否确实精确。取 4 个 key，分数为 $(s_1,\dots,s_4)=(0,\log2,\log4,0)$，标量 value 为 $(v_1,\dots,v_4)=(2,0,3,-1)$。未归一化权重是 $(1,2,4,1)$，因此正确结果为 $o=\frac{2+0+12-1}{8}=\frac{13}{8}=1.625$。逐项进行 online 更新，得到：

| 已处理 | m | 旧状态缩放 a | ℓ | u | o = u/ℓ |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 | – | 1 | 2 | 2 |
| 1, 2 | log 2 | 1⁄2 | 3⁄2 | 1 | 2⁄3 |
| 1, 2, 3 | log 4 | 1⁄2 | 7⁄4 | 7⁄2 | 2 |
| 1, 2, 3, 4 | log 4 | 1 | 2 | 13⁄4 | 13⁄8 |

![](https://pic1.zhimg.com/v2-c2a6b27c35c8a557ac80148d122bb548_r.jpg)

处理第三项时，最大值从 $\log2$ 变为 $\log4$。旧分子 1 先缩放为 1/2，再加上新项的 3；旧分母 3⁄2 先缩放为 3/4，再加上新项的 1。**online rescaling 就是这样调整旧状态的。**

再看直接平均为什么不对。如果按 $A=\{1,2\}$、$B=\{3,4\}$ 分块，就有 $o_A=2/3$，$o_B=11/5$。直接平均得到 $43/30\approx1.433$，并不是正确答案；按块质量 3 和 5 加权，才能得到 $13/8$。如果把所有分数都加上 1000，状态表中只有 $m$ 列整体平移，$\ell,u,o$ 都不变。

## 7. 前向算法：Tiling + Online Softmax

### 7.1 第一步：决定片上工作集

把 $Q$ 按行切成 $T_r=\lceil N/B_r\rceil$ 个大小为 $B_r\times d$ 的块 $Q_i$；再把 $K,V$ 切成 $T_c=\lceil N/B_c\rceil$ 个大小为 $B_c\times d$ 的块 $K_j,V_j$。设 SRAM 能容纳 $M$ 个元素，片上需要同时存放：

$$ \underbrace{2B_cd}_{K_j,V_j}+\underbrace{2B_rd}_{Q_i,O_i}+\underbrace{B_rB_c}_{S_{ij}\text{ 或 }\tilde P_{ij}}+\underbrace{O(B_r)}_{m_i,\ell_i}\ \le\ M $$

一种常用的选择是 $B_c=\lceil M/4d\rceil$，$B_r=\min(\lceil M/4d\rceil,d)$ [[2]](https://arxiv.org/abs/2205.14135)。把 $B_r\le d$ 作为限制，是为了保证 $B_rB_c\le dB_c=O(M)$，让分数块也能放进 SRAM。实际 kernel 还需要考虑寄存器、FP32 累加 [[20]](https://arxiv.org/abs/1710.03740) 和流水缓冲，因此常数会有所不同。

### 7.2 第二步：KV 在外层、Q 在内层的双重循环

![](https://pic4.zhimg.com/v2-7ac81034c662d70d2b5b6ed7ff93ec79_r.jpg)

**1.** 先在 HBM 中初始化 $O=0,\ \ell=0,\ m=-\infty$。

**2.** **外层**遍历 $j=1..T_c$：把 $K_j,V_j$ 搬入 SRAM，并在整个内层循环中复用。

**3.** **内层**遍历 $i=1..T_r$：读入 $Q_i,O_i,\ell_i,m_i$，在片上计算 $S_{ij}=\tau Q_iK_j^\top$，然后统计块内的 $\tilde m_{ij}=\mathrm{rowmax}(S_{ij})$，$\tilde P_{ij}=\exp(S_{ij}-\tilde m_{ij})$，$\tilde\ell_{ij}=\mathrm{rowsum}(\tilde P_{ij})$。

**4.** 合并新旧统计量：$m_i^{new}=\max(m_i,\tilde m_{ij})$，$\ell_i^{new}=e^{m_i-m_i^{new}}\ell_i+e^{\tilde m_{ij}-m_i^{new}}\tilde\ell_{ij}$。

**5.** 更新输出，写回 HBM，并丢弃 $S_{ij},\tilde P_{ij}$：

$$ O_i\leftarrow \mathrm{diag}(\ell_i^{new})^{-1}\Big(\mathrm{diag}(\ell_i)\,e^{m_i-m_i^{new}}O_i+e^{\tilde m_{ij}-m_i^{new}}\tilde P_{ij}V_j\Big) $$

**6.** 处理完所有 KV 块后，HBM 中的 $O$ 就是精确输出。同时保存 $L=m+\log\ell$，供反向传播使用。

这里需要注意两点。第一，$Q$、$O$ 并不会一直全部留在 SRAM 中，每个元素也不一定只读取一次：$K,V$ 各读取一次，但 $Q$ 和 $O,m,\ell$ 在每一轮外层循环中都要重新扫描一遍。省掉的是 $N^2$ 中间矩阵的写入和读取。第二，公式中的 diag 表示逐行缩放，实际实现不会真的构造一个对角矩阵。

**正确性**可以通过归纳法证明。处理完前 $j-1$ 个 KV 块后，每行状态就是这些块并集的精确摘要；第 $j$ 步的更新，则是第 5 节合并规则的逐行应用。这个证明不依赖块大小，也不要求注意力分布是稀疏的。总 FLOPs 仍然为 $O(N^2d)$，输入输出之外只需要 $O(N)$ 的额外内存。

> **为什么不让每行单独 online 扫一遍 K、V？** 单行 online softmax 的状态确实只有 $O(d)$，但如果 $N$ 行各自读取一遍全部 $K,V$，总读取量就会达到 $\Theta(N^2d)$。online 状态解决归一化的问题，跨 query 的分块复用则负责减少 **I/O**。同时，$B_r\times B_c$ 的块形状也适合 Tensor Core 进行矩阵乘法。因此，逐行的 Python 循环可以验证数学结果，却不能获得这里的性能优势。

## 8. 前向流程图逐块讲解

下图把第 7 节的算法分为 9 个方块，按 U 形顺序阅读：第一行从左到右（①→③），第二行从右到左（④→⑥），第三行再从左到右（⑦→⑨）。每个方块都列出了**核心功能**和**要解决的问题**。标有“外层 j / 内层 i”的方块，属于相应的循环。

![](https://pic3.zhimg.com/v2-f0ffcb7963b03449b36b926bf5310afc_r.jpg)

**循环结构**：方块 ③ 开始外层循环（$j=1..T_c$），方块 ④–⑧ 构成内层循环（$i=1..T_r$）。完成 ⑧ 后，如果 $i<T_r$，就回到 ④ 处理下一个查询块。内层循环结束后，如果 $j<T_c$，就回到 ③ 加载下一个 KV 块。全部处理完成后进入 ⑨。

下面按几个阶段来看：

**准备阶段（① ②）：确定分块，并准备记录状态的“小纸条”。**

- ① 确定块大小。需要保证 $K_j,V_j,Q_i,O_i,S_{ij}$ 能同时放进一个 SM 的 SRAM，这就对应“灶台只能放下几个盘子”的容量限制。
- ② 为每一行初始化 $m_i=-\infty$、$\ell_i=0$、$O_i=0$。这 $O(N)$ 个数就是第 1.4 节中的“小纸条”，用于保存跨块的归一化信息，替代完整的 $N\times N$ 矩阵 $S$ 和 $P$。

**数据搬运阶段（③ ④）：确定哪些数据保留在片上，哪些需要重复读取。**

- ③ 一个 $K_j,V_j$ 块搬入 SRAM 后，会在整个内层循环中保留，供所有查询块使用。这就是 tiling 带来的数据复用：同一份 KV 数据可以参与 $T_r$ 次计算。
- ④ 查询块 $Q_i$ 及其当前的累积状态 $O_i,\ell_i,m_i$，在每一轮外层循环中都需要重新读取。FlashAttention 付出这部分重复读取的代价，从而避免把 $S,P$ 写入 HBM。

**片上计算阶段（⑤ ⑥ ⑦ ⑧）：在一个 kernel 中连续完成计算，中间结果保留在 SRAM 中。**

- ⑤ 用 Tensor Core 计算大小为 $B_r\times B_c$ 的分数块 $S_{ij}$。标准实现会在这一步之后把完整的 $S$ 写回 HBM，而这里不需要写回。
- ⑥ 在块内先减去行最大值，再取指数，得到 $\tilde P_{ij}$ 和行和 $\tilde\ell_{ij}$。mask 和 dropout 也在这里完成，不需要再单独调用 kernel。
- ⑦ 这是算法的关键步骤。新块的最大值可能大于旧状态，也可能小于旧状态，因此需要用 $e^{m_i-m_i^{new}}$ 和 $e^{\tilde m_{ij}-m_i^{new}}$ 两个缩放因子，把新旧两部分调整到同一个基准上，再进行相加。
- ⑧ 使用相同的缩放因子更新输出 $O_i$，并加入新块的贡献 $\tilde P_{ij}V_j$。$\tilde P_{ij}$ 算出后，直接用于这次矩阵乘法，用完就丢弃。写回 HBM 的只有 $O_i,\ell_i,m_i$。

**收尾阶段（⑨）：** 处理完所有 KV 块后，每行状态都已经包含全部 key 的信息，$O$ 就是精确的 attention 输出。每行再额外保存一个 $L=m+\log\ell$，用于反向传播时重新计算概率。

对应第 1.4 节的厨房类比，①② 是准备灶台和纸条，③④ 是取食材，⑤–⑧ 是在灶台上连续完成处理，⑨ 则是上菜。

## 9. 小型例子 walk-through：一步一步跑完 FlashAttention

下面用一个可以手算的小例子，把第 7 节的算法完整跑一遍。为了方便计算，这里省略缩放系数 $\tau$，可以理解为它已经并入 $Q$，同时不使用 mask。

### 9.1 设定

设 $N=4$，$d=2$，块大小为 $B_r=B_c=2$，因此 $T_r=T_c=2$。也就是说，$Q$ 分成 2 个查询块，$K,V$ 分成 2 个键值块。

$$ Q=\begin{bmatrix}1&0\\0&1\\\hline 1&1\\0&0\end{bmatrix} \quad K=\begin{bmatrix}0&1\\1&0\\\hline 2&0\\0&0\end{bmatrix} \quad V=\begin{bmatrix}1&0\\0&1\\\hline 1&1\\2&0\end{bmatrix} $$

矩阵中的横线表示分块边界：$Q_1$ 对应第 1、2 行，$Q_2$ 对应第 3、4 行；$K_1,V_1$ 对应第 1、2 行，$K_2,V_2$ 对应第 3、4 行。

为了方便对照，先列出完整的分数矩阵。FlashAttention **不会**整体计算或保存这个矩阵：

$$ S=QK^\top=\left[\begin{array}{cc|cc}0&1&2&0\\1&0&0&0\\\hline 1&1&2&0\\0&0&0&0\end{array}\right] $$

这个矩阵分成 4 个大小为 $2\times2$ 的块，按照外层遍历 KV 块、内层遍历 Q 块的顺序处理：

![](https://pica.zhimg.com/v2-4966bff11e3661d13e6df5015d48ad78_r.jpg)

**初始化**（在 HBM 中）：每行设置 $m=-\infty$，$\ell=0$，$O=(0,0)$。

以下数值保留 4 位小数，其中 $e^{-1}\approx0.3679$，$e^{-2}\approx0.1353$。

### 9.2 外层 $j=1$：加载 $K_1,V_1$ 到 SRAM

$K_1=\begin{bmatrix}0&1\\1&0\end{bmatrix}$，$V_1=\begin{bmatrix}1&0\\0&1\end{bmatrix}$。这两个块会在接下来的两次内层循环中一直保留在 SRAM，**只从 HBM 读取一次**，对应流程图中的方块 ③。

**内层 $i=1$：处理第 1、2 行（块 ①）**

**1.** 从 HBM 读入 $Q_1$ 和这两行的旧状态（$m=-\infty,\ \ell=0,\ O=0$），对应方块 ④。

**2.** 在片上计算分数块：$S_{11}=Q_1K_1^\top=\begin{bmatrix}0&1\\1&0\end{bmatrix}$，对应方块 ⑤。

**3.** 计算块内统计量，对应方块 ⑥：

- 第 1 行：$\tilde m=1$，$\tilde P=(e^{-1},\ 1)=(0.3679,\ 1)$，$\tilde\ell=1.3679$
- 第 2 行：$\tilde m=1$，$\tilde P=(1,\ e^{-1})=(1,\ 0.3679)$，$\tilde\ell=1.3679$

**4.** 合并新旧状态。由于旧状态为空，直接接收新块，得到 $m^{new}=1$，$\ell^{new}=1.3679$，对应方块 ⑦。

**5.** 更新输出：计算 $\tilde P_{11}V_1$，再除以 $\ell^{new}$，对应方块 ⑧：

- 第 1 行：$(0.3679,\ 1)/1.3679=(0.2689,\ 0.7311)$
- 第 2 行：$(1,\ 0.3679)/1.3679=(0.7311,\ 0.2689)$

**6.** 将 $O,m,\ell$ 写回 HBM，并**丢弃 $S_{11}$ 和 $\tilde P_{11}$**。

**内层 $i=2$：处理第 3、4 行（块 ②）**

$K_1,V_1$ 仍然保留在 SRAM 中，不需要重新读取。此时 $S_{21}=Q_2K_1^\top=\begin{bmatrix}1&1\\0&0\end{bmatrix}$。

- 第 3 行：$\tilde m=1$，$\tilde P=(1,1)$，$\tilde\ell=2$，$O=(1,1)/2=(0.5,\ 0.5)$
- 第 4 行：$\tilde m=0$，$\tilde P=(1,1)$，$\tilde\ell=2$，$O=(0.5,\ 0.5)$

将状态写回 HBM，并丢弃 $S_{21},\tilde P_{21}$。

外层循环 $j=1$ 结束后，HBM 中保存了以下状态：

| 行 | m | ℓ | O（只看过前 2 个 key） |
| --- | --- | --- | --- |
| 1 | 1 | 1.3679 | (0.2689, 0.7311) |
| 2 | 1 | 1.3679 | (0.7311, 0.2689) |
| 3 | 1 | 2 | (0.5, 0.5) |
| 4 | 0 | 2 | (0.5, 0.5) |

此时的 $O$ 只包含对前两个 key 做 softmax 加权的结果，还不是最终输出。对应厨房的类比，菜只完成了一半，纸条记录了当前的处理进度。

### 9.3 外层 $j=2$：加载 $K_2,V_2$ 到 SRAM

$K_2=\begin{bmatrix}2&0\\0&0\end{bmatrix}$，$V_2=\begin{bmatrix}1&1\\2&0\end{bmatrix}$。这时 $K_1,V_1$ 已经被换出，后面不再读取。

**内层 $i=1$：处理第 1、2 行（块 ③），分别看两种情况**

重新从 HBM 读入 $Q_1$ 和第 1、2 行的状态，这就是 FlashAttention 需要付出的重复读取。然后在片上计算 $S_{12}=Q_1K_2^\top=\begin{bmatrix}2&0\\0&0\end{bmatrix}$。

**第 1 行：新块的最大值更大，需要缩放旧状态**

- 块内统计量：$\tilde m=2$，$\tilde P=(1,\ e^{-2})=(1,\ 0.1353)$，$\tilde\ell=1.1353$，$\tilde PV_2=1\cdot(1,1)+0.1353\cdot(2,0)=(1.2707,\ 1)$
- 更新后的基准：$m^{new}=\max(1,2)=2$
- 旧状态的缩放因子：$a=e^{1-2}=0.3679$；新块的缩放因子：$b=e^{2-2}=1$
- 合并后的分母：$\ell^{new}=0.3679\times1.3679+1\times1.1353=0.5032+1.1353=1.6386$
- 合并后的分子：旧的未归一化输出为 $\ell\cdot O=1.3679\times(0.2689,0.7311)=(0.3679,\ 1)$，乘以 $a$ 后得到 $(0.1353,\ 0.3679)$；再加上新块的贡献 $(1.2707,\ 1)$，得到 $(1.4060,\ 1.3679)$
- 更新后的输出：$O=(1.4060,\ 1.3679)/1.6386=(0.8581,\ 0.8348)$

**第 2 行：最大值不变，保留旧状态，缩放新块**

- 块内统计量：$\tilde m=0$，$\tilde P=(1,1)$，$\tilde\ell=2$，$\tilde PV_2=(3,\ 1)$
- 更新后的基准：$m^{new}=\max(1,0)=1$
- $a=e^{1-1}=1$（旧状态保持不变），$b=e^{0-1}=0.3679$（新块需要缩放）
- $\ell^{new}=1.3679+0.3679\times2=2.1036$
- 合并后的分子：$1.3679\times(0.7311,0.2689)+0.3679\times(3,1)=(1,\ 0.3679)+(1.1036,\ 0.3679)=(2.1036,\ 0.7358)$
- 更新后的输出：$O=(1.0000,\ 0.3498)$

将状态写回 HBM，并丢弃 $S_{12},\tilde P_{12}$。

**内层 $i=2$：处理第 3、4 行（块 ④）**

按照相同步骤处理 $S_{22}=Q_2K_2^\top=\begin{bmatrix}2&0\\0&0\end{bmatrix}$，结果如下：

| 行 | 旧 m | 块内 m̃ | mⁿᵉʷ | a | b | ℓⁿᵉʷ | 最终 O |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 3 | 1 | 2 | 2 | 0.3679 | 1 | 1.8711 | (0.8757, 0.7311) |
| 4 | 0 | 0 | 0 | 1 | 1 | 4 | (1.0000, 0.5000) |

### 9.4 核对结果

处理完所有 KV 块后，HBM 中的输出为：

$$ O_{\text{FA}}=\begin{bmatrix}0.8581&0.8348\\1.0000&0.3498\\0.8757&0.7311\\1.0000&0.5000\end{bmatrix} $$

再用标准方法直接计算 $\mathrm{softmax}(S)V$ 进行核对。以第 1 行为例，$\mathrm{softmax}(0,1,2,0)=(0.0826,\ 0.2245,\ 0.6103,\ 0.0826)$，乘以 $V$ 得到 $(0.8581,\ 0.8348)$。四行结果都一致，已用 NumPy 逐元素核对。

### 9.5 为反向保存 $L$，并演示重计算

前向计算结束后，每行保存 $L=m+\log\ell$。对于第 1 行，有 $L=2+\log1.6386=2.4938$。

如果反向传播需要第 1 行在第 1 个 KV 块上的概率，不必读取预先保存的 $P$。只需要在片上重新计算 $S_{11}$ 的第 1 行 $(0,1)$，然后计算：

$$ P=\exp\big((0,\ 1)-2.4938\big)=(0.0826,\ 0.2245) $$

这个结果与完整 softmax 的前两项正好一致。这里要注意，减去的是**整行**的 $L$，而不是当前块的最大值，因此恢复出来的是全局归一化后的正确概率。

### 9.6 这个例子点出的 FlashAttention 核心特征

**1.** **不生成并保存完整的 $N\times N$ 矩阵**：$S$ 和 $P$ 只以 $2\times2$ 的块形式出现在 SRAM 中，用完就丢弃。HBM 中始终只有 $Q,K,V,O$，以及每行的两个标量 $m,\ell$。

**2.** **Online rescaling 是精确的**：第 1 行在 $j=2$ 时，最大值从 1 变成 2，旧分子和旧分母同时乘以 $e^{-1}$；第 2 行的最大值没有变化，因此缩放的是新块。两种情况最终都得到与标准 softmax 完全相同的结果，没有引入近似。

**3.** **每个 KV 块只读取一次，供多个查询块复用**：$K_1,V_1$ 被 $Q_1$ 和 $Q_2$ 使用后才换出。代价是 $Q$ 和 $O,m,\ell$ 在每一轮外层循环中都需要重新读写一次。

**4.** **反向传播通过重计算恢复概率**：只需保存一个 $L$，就可以恢复任意概率块。

**5.** **小规模例子还体现不出 I/O 优势**：在这个 $N=4$ 的例子中，按标量计算，FlashAttention 的 HBM 访问量为：$K,V$ 共 16，$Q$ 共 16，$O$ 读写共 32，$m,\ell$ 读写共 32，合计约 96，实际上比标准实现读写 $S,P$ 的 64 还多。这是因为标准实现的中间矩阵流量按 $N^2$ 增长，而 FlashAttention 的流量按 $N^2d^2/M$ 增长。只有当 $N$ 较大、$M\gg d^2$ 时，优势才会体现出来。在实际场景中，$N$ 从几千到几十万不等，第 10 节会给出具体的访问量计算。

## 10. I/O 复杂度

在理想的两级存储模型下，设 SRAM 容量为 $M$，且 $d\le M\le Nd$，前向计算的 HBM 访问量如下：

| 对象 | 访问量 | 原因 |
| --- | --- | --- |
| K, V | 2Nd | 每个外层块各读一次 |
| Q | Nd · T_c | 每个 KV 块扫一遍全部 query |
| O | 2Nd · T_c | 每次扫描读旧输出、写新输出 |
| m, ℓ | 4N · T_c | 两个逐行标量各读写一次 |
| 完整 S, P | 0 | 只在片上产生和消费 |

根据 $T_c=\Theta(Nd/M)$，可以得到 [[2]](https://arxiv.org/abs/2205.14135)：

$$ \text{标准实现：}\ \Theta(Nd+N^2)\qquad\text{FlashAttention：}\ \Theta\!\left(\frac{N^2d^2}{M}\right) $$

当 $d=64\sim128$、每个 SM 的 SRAM 约为 100 KB 量级时，有 $d^2\ll M$。在理想情况下，I/O 可以减少约 $M/d^2$ 倍。

**直觉**：$T_c$ 表示 $Q$ 和 $O$ 需要重复扫描多少次。SRAM 容量越大，每个 KV 块就可以越大，块数 $T_c$ 就越少，也就减少了重复扫描。这是 $M$ 出现在分母中的原因。

> **具体账本**：取 $N=4096,\ d=64,\ M=65536$ 个标量槽，可以得到 $B_c=256,\ B_r=64,\ T_c=16,\ T_r=64$。访问量为 $2Nd+(3Nd+4N)T_c=13{,}369{,}344$ 个标量，按每个标量 2 字节折算，约为 25.5 MiB。标准实现仅 $S,P$ 的往返读写就需要 128 MiB，两者相差约 5 倍。这里计算的是抽象模型下的访问量，不是 GPU 实测数据。第 1.4 节末尾的对比图使用的就是这组计算。

### 10.1 三个容易误读的地方

**1. 仍然随 $N$ 的平方增长。** 当 $d,M$ 固定时，$\Theta(N^2)\cdot d^2/M$ 仍然随 $N^2$ 增长，密集 attention 的 FLOPs 也仍然是 $\Theta(N^2d)$。变为线性的是**存储量**。因此，在长上下文场景中，解决了内存限制以后，计算量会成为新的瓶颈。

**2. 下界应该如何理解。** 可以证明，不存在一种精确 attention 算法，能在**整个** $d\le M\le Nd$ 区间内都只需要 $o(N^2d^2/M)$ 次访问。因为在端点 $M=\Theta(Nd)$ 处，仅写出输出就需要 $Nd$ 次访问 [[2]](https://arxiv.org/abs/2205.14135)。但这并不意味着对每个固定的 $M$ 都是最优的。Saha 与 Ye [[10]](https://proceedings.mlr.press/v235/saha24a.html) 后来给出了逐区间的紧界 $\Theta\big(Nd+\min\{N^2d/\sqrt M,\ N^2d^2/M\}\big)$：当 $M\ge d^2$ 时，FlashAttention 最优；当 $M<d^2$ 时，经典的矩阵乘法分块更好。

**3. 块越大，不一定越快。** 增大块可以降低 $T_c$，从而减少账面上的 I/O。但同时，寄存器和 shared memory 的占用会上升，活跃线程块的数量会减少，也就是 occupancy 下降，还可能出现寄存器溢出。实测中，块大小超过约 256 后，收益开始趋缓 [[2]](https://arxiv.org/abs/2205.14135)，说明此时 HBM 已经不是唯一的瓶颈。

## 11. 反向传播：为什么重计算能同时更快、更省

训练还需要反向传播。标准实现会在前向阶段保存 $P$，留给反向使用，因此需要保留一个 $N\times N$ 矩阵。FlashAttention 则不保存这个矩阵，在反向需要时重新计算。

### 11.1 第一步：标准梯度

设上游梯度为 $dO=\partial L/\partial O$。根据 $O=PV$ 和 softmax 的 Jacobian $\mathrm{diag}(p)-pp^\top$，可以得到：

$$ dV=P^\top dO,\qquad dP=dO\,V^\top,\qquad dS=P\odot(dP-D\mathbf 1^\top),\qquad dQ=\tau\,dS\,K,\qquad dK=\tau\,dS^\top Q $$

其中，$D_i=\sum_jP_{ij}dP_{ij}$。从这个表达式看，似乎需要整行 $P$ 才能计算 $D_i$。

### 11.2 第二步：关键恒等式

$$ D_i=\sum_jP_{ij}\sum_a dO_{ia}V_{ja}=\sum_a dO_{ia}\Big(\sum_jP_{ij}V_{ja}\Big)=\langle dO_i,\,O_i\rangle $$

这样，长度为 $N$ 的归约就变成了长度为 $d$ 的点积。利用已保存的 $O$ 和 $dO$，只需 $O(Nd)$ 就能计算所有 $D_i$。这与前向的思路一致：保存后续计算真正需要的归约量，避免为了得到一个标量而保存整个大矩阵。

### 11.3 第三步：不存 $P$，用 $L$ 恢复

前向阶段为每行保存 log-sum-exp $L_i=m_i+\log\ell_i$。反向访问块 $(i,j)$ 时，重新计算：

$$ S_{ij}=\tau Q_iK_j^\top,\qquad P_{ij}=\exp(S_{ij}-L_i\mathbf 1^\top) $$

这里使用的是**整行**的前向归一化常数，第 9.5 节已经演示过，不能对当前块单独做 softmax。接下来逐块计算：

$$ dV_j \mathrel{+}= P_{ij}^\top dO_i,\quad dP_{ij}=dO_iV_j^\top,\quad dS_{ij}=P_{ij}\odot(dP_{ij}-D_i),\quad dQ_i \mathrel{+}= \tau\, dS_{ij}K_j,\quad dK_j \mathrel{+}= \tau\, dS_{ij}^\top Q_i $$

局部概率和梯度在使用后就可以丢弃。

### 11.4 反向流程图逐块讲解

![](https://picx.zhimg.com/v2-71c074ebcf191ccf8a76f21899e0946d_r.jpg)

**循环结构**：方块 ⑫ 开始外层循环（$j=1..T_c$），方块 ⑬–⑰ 构成内层循环（$i=1..T_r$）。完成 ⑰ 后，如果 $i<T_r$，就回到 ⑬。内层循环结束后，在 ⑱ 写回 $dK_j,dV_j$；如果 $j<T_c$，就回到 ⑫。

反向与前向的循环结构相同，都是 KV 在外层、Q 在内层，可以对照前向流程图理解：

**准备阶段（⑩ ⑪）：利用前向留下的“小纸条”。**

- ⑩ 反向的输入是 $Q,K,V,O,dO$，以及每行一个 $L$。与标准实现相比，这里**没有**保存 $S$ 和 $P$，因此节省了 $O(N^2)$ 的激活显存。
- ⑪ 利用第 11.2 节的恒等式，先算出所有 $D_i=\langle dO_i,O_i\rangle$。这一步只需要 $O(Nd)$，后面每个块都可以直接使用这个全局的 $D_i$。

**数据搬运阶段（⑫ ⑬）：** 与前向过程对称。⑫ 将 $K_j,V_j$ 保留在 SRAM 中，并在片上设置两个累加器 $dK_j,dV_j$。整个内层循环都在片上累加，只在结束时写回一次。⑬ 读入查询块 $Q_i$、上游梯度块 $dO_i$，以及统计量 $L_i,D_i$。

**片上重算与求导阶段（⑭ ⑮ ⑯ ⑰）：**

- ⑭ **重计算**：用 $Q_i,K_j$ 重新计算 $S_{ij}$，再利用整行的 $L_i$ 恢复精确的 $P_{ij}$。如果前向使用了 dropout，还需要用相同的随机种子重建同一张掩码。这一步额外增加了约 $2N^2d$ FLOPs，但省去了从 HBM 读取 $N^2$ 级别的 $P$。
- ⑮ 计算 $dV_j$ 的贡献 $P_{ij}^\top dO_i$，累加到片上的 $dV_j$，同时计算 $dP_{ij}=dO_iV_j^\top$。
- ⑯ 计算 softmax 的反向：$dS_{ij}=P_{ij}\odot(dP_{ij}-D_i)$。由于 $D_i$ 已经在 ⑪ 中提前算好，这里不需要整行的概率。
- ⑰ 将 $dS_{ij}$ 分别乘以 $K_j$ 和 $Q_i$，累加到 $dQ_i$ 和 $dK_j$。$dK_j$ 保留在片上，而 $dQ_i$ 需要在不同的外层轮次中反复累加，因此要写回 HBM，实际实现需要使用原子加或额外归约。

**收尾阶段（⑱）：** 内层循环结束后，将 $dK_j,dV_j$ 写回 HBM。完成全部外层循环后，就得到完整的 $dQ,dK,dV$。

### 11.5 Dropout：分母不丢弃，掩码必须重现

Dropout [[14]](https://jmlr.org/papers/v15/srivastava14a.html) 在 softmax 之后应用：$\hat P=P\odot R$，$R_{ij}=\xi_{ij}/(1-p_{drop})$。$\ell$ 仍然按全部有效分数计算，不会对剩余权重重新归一化。反向时有 $dV=\hat P^\top dO$，$dP=(dO\,V^\top)\odot R$，$D_i=\langle dO_i,O_i\rangle$ 仍然成立。**反向必须重建前向使用的同一个随机掩码**。具体做法是保存随机数生成器的 seed 和 offset，按照固定的元素索引规则重新生成，而不必保存整个掩码矩阵。

### 11.6 运算账本：多算却更快

标准前向约需要 $4N^2d$ FLOPs，反向约需要 $8N^2d$，合计为 $12N^2d$。重新计算 $QK^\top$ 会再增加 $2N^2d$，总计约为 $14N^2d$。只要标准实现受 HBM 带宽限制，而新增计算能够由 Tensor Core 承担，节省的搬运时间就会超过重计算的代价。从第 1 节的 roofline 角度看，在 memory-bound 区，多做的计算几乎是“免费”的，因为 Tensor Core 原本就在等待数据。

这与普通的 gradient checkpointing [[13]](https://arxiv.org/abs/1604.06174) 有所不同。普通 checkpointing 用时间换显存，重计算会增加运行时间；FlashAttention 重新算出的块会直接在片上使用，不需要先把完整的 $P$ 写回 HBM，因此能同时提高速度并节省显存。

### 11.7 两键反向手算例子

设 $q=1$，$k_1=0,\ k_2=\log3$，$v_1=1,\ v_2=5$，$d=1,\ \tau=1$，损失为 $L=o$，因此 $dO=1$。前向结果为 $p=(1/4,\ 3/4)$，$o=4$。

有 $D=dO\cdot o=4$，$dP=(1,\ 5)$，$dS=p\odot(dP-D)=(-3/4,\ 3/4)$。因此，$dV=(1/4,\ 3/4)$，$dK=(-3/4,\ 3/4)$，$dq=\tfrac34\log3>0$。增大 $q$ 会加强对 $k_2$ 的匹配，而 $k_2$ 对应的值 5 更大，所以输出会增加。两个分数梯度的和为零，说明 softmax 对分数的整体平移不敏感。

如果两个 key 分别位于两个块中，前向只保存 $L=\log4$ 和 $o=4$。反向访问第一块时恢复 $p_1=e^{0-\log4}=1/4$，访问第二块时恢复 $p_2=e^{\log3-\log4}=3/4$，两个块都使用同一个全局的 $D=4$。

## 12. Causal mask 与块稀疏扩展

**Causal mask 将块分为三类**：完全位于允许区域的块，直接做密集计算；完全位于禁止区域的块，整块跳过；跨越对角线的块，在块内对未来位置施加 $-\infty$。

![](https://pica.zhimg.com/v2-c9fa313f762503662614dbcdbccc4c9c_r.jpg)

因此，causal attention 可以省去接近一半的计算，对角线附近有多少无效计算则取决于块大小。屏蔽未来 token 本来就是自回归模型 [[15]](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf) 的定义，所以这里仍然是精确计算。在 LLM 的 prefill 阶段，能够整块跳过，也是 FlashAttention 比逐元素 mask 快得多的重要原因。

**块稀疏 attention**：Sparse Transformer [[18]](https://arxiv.org/abs/1904.10509)、BigBird [[19]](https://arxiv.org/abs/2007.14062) 等方法只计算部分 attention 连接。如果给定块级二值掩码，非零块比例为 $\rho$，FlashAttention 就可以跳过零块，将 I/O 降为 $\Theta(Nd+\rho\,N^2d^2/M)$ [[2]](https://arxiv.org/abs/2205.14135)。对于给定的稀疏模式，计算仍然是精确的。但与原来的密集 attention 相比，删除块改变了 softmax 的归一化集合，相当于换了一个模型。当 $\rho$ 固定时，复杂度仍然是二次的；只有 $\rho$ 随 $N$ 减小，例如 $\rho\asymp\log N/N$，才会接近线性。

近似 attention 的 FLOPs 虽然更少，但索引、数据重排和多次 kernel 调用的固定开销，仍然可能拖慢实际运行速度。FlashAttention 因此提供了一个很强的精确计算基线：近似方法需要在实际速度上超过它，才能体现出性能收益。

## 13. 前置工作与后续演化

这些工作都是先判断当前限制速度的资源是什么，再围绕这个瓶颈重新组织计算：

| 工作 | 瓶颈诊断 | 核心改动 |
| --- | --- | --- |
| Online normalizer（2018）[3] | softmax 需要多遍扫描 | 运行最大值 + 指数和，3 读 1 写变 2 读 1 写 |
| Rabe & Staats（2021）[4] | attention 的 O(N²) 内存 | 分块累加 + 重计算，省内存但未必更快 |
| FlashAttention（2022）[2] | HBM 读写 | tiling + online softmax + recomputation |
| FlashAttention-2（2023）[5] | 非矩阵乘运算、并行度、warp 间通信 | 最后才除以 ℓ；只存 L；沿 query 块并行；块内改为切分 Q；A100 上约为 FA1 的 2 倍 |
| FlashAttention-3（2024）[6] | Hopper GPU 上异步硬件闲置 | TMA 异步搬运与 WGMMA 异步矩阵乘、producer–consumer warp、矩阵乘与 softmax 交错；FP8 块缩放 + 正交旋转 |
| FlashAttention-4（2026）[7] | Blackwell GPU 上指数单元与 shared memory 跟不上矩阵乘 | TMEM 流水、部分指数用 FMA 模拟、延迟 rescale、2-CTA 协同反向 |
| Flash-Decoding（2023）[8] | LLM decode 阶段 query 太少、并行度不足 | 沿 KV 长度切分，各段算 (oₐ, Lₐ) 后用 log-sum-exp 合并 |

从这张表可以看到，memory wall 的问题仍然在延续。FlashAttention 减少了 HBM 读写以后，瓶颈逐渐转移到片上的非矩阵运算、并行度和异步调度。后续各代工作也就围绕这些新的瓶颈继续优化。

**回到 LLM serving。** 第 1.2 节提到，decode 阶段每一步、每个 head 通常只有一个新 query，却需要读取完整的历史 KV cache。按 query 分块无法提供足够的并行度，因此 Flash-Decoding 改为沿 KV 长度方向切分并行。vLLM 的 PagedAttention [[9]](https://arxiv.org/abs/2309.06180) 则处理 KV cache 的显存碎片和预留浪费。PagedAttention 的 page 用于管理显存分配，FlashAttention 的 tile 用于组织一次计算中的数据复用。两者的尺寸不需要相同，也可以组合使用。

Flash-Decoding 的合并公式为：

$$ o=\frac{\sum_ae^{L_a-L^*}o_a}{\sum_ae^{L_a-L^*}},\qquad L^*=\max_aL_a $$

这个公式与第 5 节的合并规则具有相同结构，只是把串行更新改成了并行归约。FlashAttention-4 的“延迟 rescale”也利用了同一个代数性质：对于任意公共参考数 $c$，$\sum_je^{s_j-c}v_j\big/\sum_je^{s_j-c}$ 的结果都相同。跟踪最大值是为了保证数值稳定；只要分子和分母始终使用同一个参考数，就可以稍后再进行修正。
