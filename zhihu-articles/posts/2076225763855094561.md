## 2. 错误原因与解决措施

部署过程中依次遇到 4 个问题：

### 2.1 TypeError: type ‘array.array’ is not subscriptable

- **现象** ：EngineCore 启动失败， `flashinfer/comm/fd_exchange.py:55` 抛出 `TypeError`
- **原因** ：flashinfer 在该文件中把 `array.array[int]` 写在了运行时会被求值的类型注解里（ `array.array` 在 Python 中不是泛型类），且文件没有 `from __future__ import annotations`
- **解决** ：在文件顶部（模块 docstring 之后）加一行：

```python
from __future__ import annotations
```

文件路径： `/home/ubuntu/miniconda3/envs/vllm_serve/lib/python3.11/site-packages/flashinfer/comm/fd_exchange.py`

- **注意** ： `pip` 重装/升级 flashinfer 会覆盖此补丁，需重新检查

### 2.2 RuntimeError: Could not find nvcc and default cuda_home=‘/usr/local/cuda’ doesn’t exist

- **现象** ：profile 阶段 flashinfer 采样 kernel 现场编译（JIT）失败
- **原因** ：flashinfer 的 top-k/top-p 采样 kernel 需要本机 CUDA toolkit（nvcc），但系统只有 pip 版 torch 自带的 CUDA runtime
- **解决** ：设置环境变量禁用 flashinfer 采样器，回退到 vLLM 原生采样实现：

```bash
VLLM_USE_FLASHINFER_SAMPLER=0
```

### 2.3 torch.OutOfMemoryError（CUDA graph 内存 profiling 阶段）

- **现象** ： `profile_cudagraph_memory` → `_init_minimal_kv_cache_for_profiling` 时分配 528 MiB 失败（当时仅剩 356 MiB 空闲）
- **原因** ：12 GB 显存装不下 8.61 GiB 权重 + torch.compile 产物 + CUDA graph 捕获缓冲 + 混合注意力模型的最小 KV/状态缓存
- **解决** ：关闭 CUDA graph、保留 torch.compile（ `--enforce-eager` 会把两者都关掉，牺牲编译加速；用 `-cc` 只关 graph 是更优解）：

```bash
-cc '{"cudagraph_mode": "none"}'
  PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
```

> 实测对比（512 tokens 生成）：compile + 无 graph **6.57s** vs 完全 eager **8.73s** ，约快 25%；128 tokens：2.33s vs 2.44s。 完全去掉该配置（compile + CUDA graph 全开）会复现 OOM，即使 `gpu_memory_utilization=0.95` 也不行（graph profiling 阶段的分配不受该参数控制）。

### 2.4 ValueError: KV cache 不足（8192 上下文差 0.03 GiB）

- **现象** ：

```text
To serve at least one request with the model's max seq len (8192),
  (0.31 GiB KV cache is needed, which is larger than the available
  KV cache memory (0.28 GiB). ... the estimated maximum model length is 7392.
```

- **原因** ：默认 `gpu_memory_utilization=0.9` 下留给 KV cache 的显存不足（该混合线性注意力模型的状态缓存较大）
- **解决** ：提高显存利用率：

```bash
--gpu-memory-utilization 0.95
```

## 3. 启动方法

```bash
conda activate vllm_serve
cd /home/ubuntu/zhuwl/LLaMA-Factory

VLLM_USE_FLASHINFER_SAMPLER=0 PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
python -m vllm.entrypoints.openai.api_server \
    --model /home/ubuntu/zhuwl/LLaMA-Factory/models/qwen3.5-4b-4qlora-merged \
    --served-model-name qwen3.5-4b-4qlora-merged \
    --host 0.0.0.0 --port 8000 \
    --trust-remote-code \
    --max-model-len 8192 \
    --gpu-memory-utilization 0.95 \
    -cc '{"cudagraph_mode": "none"}' \
    --enable-auto-tool-choice \
    --tool-call-parser qwen3_coder
    --enable-thinking false
```

### 4.3 Python 客户端测试

下面是一个api_test.py脚本

```python
import json
import urllib.request
from urllib.error import URLError
import argparse
import sys

def _stream_request(url, payload, timeout=120):
    """流式请求的内部生成器"""
    req = urllib.request.Request(
        url,
        data=json.dumps(payload).encode('utf-8'),
        headers={'Content-Type': 'application/json'}
    )
    try:
        resp = urllib.request.urlopen(req, timeout=timeout)
    except Exception as e:
        print(f"⚠️ 流式请求失败: {e}", file=sys.stderr)
        return

    try:
        for line in resp:
            line = line.decode('utf-8').strip()
            if not line:
                continue
            if line.startswith("data: "):
                data = line[6:]
                if data == "[DONE]":
                    break
                try:
                    obj = json.loads(data)
                    delta = obj['choices'][0]['delta']
                    yield delta
                except (KeyError, json.JSONDecodeError):
                    continue
    except Exception as e:
        print(f"⚠️ 流式读取过程中出错: {e}", file=sys.stderr)
    finally:
        resp.close()

def send_request(messages, tools=None, model="qwen3.5-4b-4qlora-merged",
                 temperature=0.7, max_tokens=2048, stream=False, base_url=None, **kwargs):
    """
    发送请求到 OpenAI 兼容 API

    参数:
        base_url: str
            - 例如: http://localhost:8000 (本地)
            - 例如: https://xxxx.cpolar.cn (内网穿透公网)
    """
    if base_url is None:
        base_url = 'http://localhost:8000'  # 默认直连工作站（同局域网）
    
    # 拼接完整 URL
    url = f"{base_url.rstrip('/')}/v1/chat/completions"
    
    payload = {
        'model': model,
        'messages': messages,
        'temperature': temperature,
        'max_tokens': max_tokens,
        'stream': stream,
        'tool_choice': 'none',  # ⚠️ 关键修复：强制模型直接生成文本，避免触发 tools 导致 content: null
        **kwargs
    }
    if tools:
        payload['tools'] = tools
    print("payload:", payload)
    # ---------- 非流式 ----------
    if not stream:
        req = urllib.request.Request(
            url,
            data=json.dumps(payload).encode('utf-8'),
            headers={'Content-Type': 'application/json'}
        )
        try:
            with urllib.request.urlopen(req, timeout=120) as resp:
                result = json.loads(resp.read())
            return result['choices'][0]['message']
        except URLError as e:
            print(f"⚠️ API 请求失败: {e}", file=sys.stderr)
            return None
        except Exception as e:
            print(f"⚠️ 发生错误: {e}", file=sys.stderr)
            return None

    # ---------- 流式 ----------
    return _stream_request(url, payload, timeout=120)

if __name__ == "__main__":
    parser = argparse.ArgumentParser(description="调用本地/公网 OpenAI 兼容模型 API")
    parser.add_argument(
        "--stream", "-s",
        action="store_true",
        help="启用流式输出"
    )
    parser.add_argument(
        "--prompt", "-p",
        type=str,
        default="你好，请简单介绍一下你自己。",
        help="提问内容"
    )
    parser.add_argument(
        "--max-tokens", "-m",
        type=int,
        default=2048,
        help="最大生成 token 数"
    )
    parser.add_argument(
        "--temperature", "-t",
        type=float,
        default=0.7,
        help="温度参数"
    )
    parser.add_argument(
        "--model",
        type=str,
        default="qwen3.5-4b-4qlora-merged",
        help="模型名称"
    )
    parser.add_argument(
        "--base-url", "-u",
        type=str,
        default="http://localhost:8000",
        help="API 基础地址，例如: https://xxxx.cpolar.cn"
    )
    args = parser.parse_args()

    messages = [{"role": "user", "content": args.prompt}]

    if args.stream:
        print("🔍 启用流式输出模式...")
        try:
            for delta in send_request(
                messages,
                max_tokens=args.max_tokens,
                temperature=args.temperature,
                model=args.model,
                stream=True,
                base_url=args.base_url,
                extra_body={"enable_thinking": False}
            ):
                if "content" in delta and delta["content"] is not None:
                    print(delta["content"], end="", flush=True)
            print("\n✅ 流式输出完成")
        except Exception as e:
            print(f"❌ 流式调用出错: {e}", file=sys.stderr)
    else:
        print("🔍 启用非流式输出模式...")
        response = send_request(
            messages,
            max_tokens=args.max_tokens,
            temperature=args.temperature,
            model=args.model,
            stream=False,
            base_url=args.base_url
        )
        if response:
            content = response.get("content")
            if content is not None:
                print("✅ 成功获取响应：")
                print(content)
            else:
                print("⚠️ 响应中没有 content，可能触发了工具调用。完整响应:", response)
        else:
            print("❌ 请求失败，请检查：")
            print("  1. cpolar/ngrok 是否正在运行")
            print("  2. 公网地址是否正确")
            print("  3. 工作站模型服务是否正常启动")
            print("  3. 是否可以用 curl 测试本地 9000 端口", file=sys.stderr)
```

## 5. 备注

- 该模型（LoRA 训练产物）回复以 <think> 开头输出思考过程，属正常行为
- 12 GB 显存下 CUDA graph 无法启用（详见 2.3）；如需进一步提速可考虑对权重做 AWQ/GPTQ 4-bit 量化后重新启用 graph
- 首次启动因 torch.compile 会慢约 30s（后续同配置启动可复用编译缓存，位于 `~/.cache/vllm/torch_compile_cache` ）
- 若 8000 端口被占用，改用 `--port` 换端口
- **vLLM / TGI（服务端渲染）** ：模板渲染 **强制发生在服务端** 。你发给它 `messages` 和 `extra_body` ，vLLM 的 API 服务器拿到后，先用内部的 Jinja2 引擎渲染成字符串，再送给 Tokenizer。 **这意味着：客户端无法绕过服务端设定的模板逻辑。** 如果想修改模型的删除格式，最好直接修改models/qwen3.5-4b-4qlora-merged/chat_template.jinja模板文件。
