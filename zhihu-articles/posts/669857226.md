## 1. 大语言模型训练中遇到的挑战

① 有限的GPU内存容量。百亿参数级别的大模型无法在单卡（最大的内存的A100 GPU为80GB）中加载。例如一个普通的7B模型，使用FP16存储的话就是14GB（7.1B * 2bytes）模型参数空间，从而梯度也是14GB，优化器状态

- `exp_avg`: exponential moving average of gradient values
- `exp_avg_sq`: exponential moving average of squared gradient values

用FP32存储的话需要是64GB。另外我们还需要存储FP32的模型权重，用于在混合精度的时候进行更新，所以又多了32GB的存储空间。所以，一共需要是124GB的存储空间。

② 即使我们能够把模型放进单个GPU中（例如，通过在主机和设备内存之间交换参数），但是其所需的大量计算操作会导致漫长训练时间。所以，我们需要使用各种并行算法。

3D 并行最早由微软在 DeepSpeed 中提出，目前 DeepSpeed 和 Megatron-LM 中都有针对 3D 并行的算法实现。具体来说，3D 并行结合了**模型并行、流水线并行、数据并行** 3 种并行策略。如何能够综合利用三种并行方法，在多机多卡上达到**近似线性scaling，提高吞吐、降低内存消耗**，是一门学问。不仅要依据算法特点对模型做合理切割，还需要做软硬件一体的系统架构设计，需要仔细推理以获得良好的性能。

为了达到一个比较高的TFLOPS，需要在不同维度进行细致的工程处理：

- 在设备上对计算图进行智能分割，以减少通过网络发送的字节数，同时也限制设备的空闲时间。
- 实施特定领域的通信优化和使用高速硬件（比如最先进的GPU，并且同一服务器内和不同服务器GPU之间使用高带宽链接）。

***在这个系列里，我将详细介绍模型并行、流水线并行、数据并行、序列并行的4D并行训练方法，并且结合Megatron-LM的代码进行详细解读。和以前一样，我会使用尽可能简单精炼的语言讲解，一般不会涉及复杂的数学计算~（尽量一周一更！）***

## 2.张量并行

我们先来介绍大模型中最特殊、也是最重要的并行方法 – 张量并行(Tensor Parallel)，就是把模型每一层的参数切开，放到不同的GPU上进行独立计算，然后再聚合。

### 2.1 矩阵乘法

我们先来看一下矩阵乘法是如何计算的。为了计算 XA，我们可以纵向切割矩阵X，横向切割矩阵A，分别计算X1A1、X2A2，然后再将二者相加：

![](https://picx.zhimg.com/v2-0b27dc12b071e1ebb59ce50e938cf353_r.jpg)

另一种方法是纵向切割矩阵A，然后分别计算XA1, XA2, 再将二者拼接。

![](https://pic3.zhimg.com/v2-b6f6ae4f245f8f479f0462c9e767a3ea_r.jpg)

这两种方法在数学上都是等价的，那么哪种方法在效率上更高呢？

### 2.2 MLP层计算

一种经典的MLP层计算方法就是先经过一个H->4H的线性层+GELU激活函数+4H->H的线性层+Dropout:

![](https://pic3.zhimg.com/v2-14eeaffcac6fcd04ae286e0a9799c2fc_r.jpg)

用公式表示为： $~~~~~~~~~~~~~~~~~~~~~~~~~~Y=GELU(XA) \\ ~~~~~~~~~~~~~~~~~~~~~~~~~~Z = Dropout(YB)$

如果使用第一种方式切割：

![](https://pic1.zhimg.com/v2-55c5f242fc354f31819398a17bfe3652_r.jpg)

如果我们在第一个MLP层横向切割权重矩阵，那么为了保证 $XA$ 的完整性，需要计算 $X_1A_1+X_2A_2 $ 。 这是因为 $GELU(X_1A_1+X_2A_2) \ne GELU(X_1A_1)+GELU(X_2A_2)$ 。所以我们需要在GELU之前，设置一个**同步点**，让不同的GPU之间交互信息 ---- 这就导致一些GPU等待，造成了GPU资源的浪费。

如果使用第二种方式切割：

![](https://pica.zhimg.com/v2-078d46caadf905588a734cd1ccdf7144_r.jpg)

如果采用**纵向切割**的方式，鉴于 $XA_1$ 和 $XA_2 $ 是通过最后一个维度拼接的，那么我们当然可以先计算 $GELU(XA_1)$ 和 $GELU(XA_2)$ ，然后把 $GELU(XA_1)$ 和 $GELU(XA_2) $ 拼接: $Y = [Y_1,Y_2​​] = [GeLU(XA_1​),GeLU(XA_2​)​]$ . 这不影响最终的结果。可以看到为了计算GELU这个非线性函数，我们不需要设置一个同步点了。

因此，我们使用第二种方法来进行切分，示意图如下：

![](https://pic3.zhimg.com/v2-5755e06c1e58e2f4f40b9fa28e9ee346_r.jpg)

在用上述方法计算完 $Y_1, Y_2$ 之后，继续在GPU1上运行 $Y_1B_1$ ，以及在GPU2上运行 $Y_2B_2$ 。只有到最后计算完毕之后、dropout之前，才需要一个同步点，把两个GPU上分别的计算结果相加在一起（这是一个all-reduce同步点），如上图的右侧所示。

- `f` 的forward计算：把输入X拷贝到两块GPU上，每块GPU即可独立做forward计算。
- `g` 的forward计算：每块GPU上的forward的计算完毕，取得Z1和Z2后，GPU间做一次all-reduce，拼接结果产生Z。
- `g`的backward： $\frac{\partial L}{\partial A_i} = \frac{\partial L}{\partial Z_i} * \frac{\partial Z_i}{\partial A_i} $
- `f` 的backward：因为对于损失L， $X$ 既参与了 $XA_1$ 的计算，也参与了 $XA_2$ 的计算。因此需要把两个梯度相加： $\frac{\partial L}{\partial X} = \frac{\partial L}{\partial X}|1 + \frac{\partial L}{\partial X}|2 $ 。其中 $\frac{\partial L}{\partial X}|i $ 表示第i块GPU上计算到 $X$ 时的梯度。

![](https://picx.zhimg.com/v2-05dec638e94b0a8e435ca9886b138a3b_r.jpg)

```python3
        intermediate_parallel, bias_parallel = self.dense_h_to_4h(hidden_states)

        if self.bias_gelu_fusion:  ##bias+GELU融合算子，可以一起计算
            assert self.add_bias is True
            assert self.activation_func == F.gelu
            intermediate_parallel = bias_gelu_impl(intermediate_parallel, bias_parallel)
        else: ##如果不使用bias+GELU融合算子，就是先加bias，再过GELU
            if bias_parallel is not None:
                intermediate_parallel = intermediate_parallel + bias_parallel
            intermediate_parallel = self.activation_func(intermediate_parallel)
        # [s, b, h]
        output, output_bias = self.dense_4h_to_h(intermediate_parallel)
        return output, output_bias
```

### 2.3 Self-Attention层的计算

对于self-attention模块，可以利用多头注意力操作中固有的并行性，以列并行方式对与K、Q和V相关联的矩阵运算进行分区，从而在一个GPU上本地完成与每个注意力头对应的矩阵乘法。这使我们能够在GPU中分割每个attention head参数和工作负载，每个GPU得到了部分输出。（例如，如果我们有32个注意力头，就可以切成16+16个头，把前16个头放在GPU1上、后16个头放在GPU2上）

其次，对于后续的全连接层，因为每个GPU之上有了部分输出，所以对于权重矩阵B就按行切分，与输入的 Y1​,Y2​ 进行直接计算，然后通过dropout之前的 all-reduce 同步点做加法，得到最终结果。

![](https://pic2.zhimg.com/v2-4f41d29fe2b1991aaedff6c587e25201_r.jpg)
*K1/Q1/V1代表前m个注意力头，K2/Q2/V2代表后m个注意力头*

**Megatron-LM中的实现：**

```python3
class ParallelAttention(MegatronModule):
    """Parallel self-attention layer abstract class.

    Self-attention layer takes input with size [s, b, h]
    and returns output of the same size.
    """

    def __init__(self, config, layer_number,
                 attention_type=AttnType.self_attn,
                 attn_mask_type=AttnMaskType.padding):
        ... ...
        self.query_key_value = tensor_parallel.ColumnParallelLinear( ###列切分矩阵Q，K，V. 注意这里的kv_proj_size在使用GQA时是小于query_proj_size
                config.hidden_size,
                query_projection_size + 2 * kv_projection_size,
                config=config,
                init_method=config.init_method,
                bias=args.add_bias_linear,
                gather_output=False)
       
        self.core_attention = CoreAttention(self.layer_number, config, self.attn_mask_type)
        ... ...
        # Output.
        self.dense = tensor_parallel.RowParallelLinear( ##行切分矩阵B
            query_projection_size,
            config.hidden_size,
            config=config,
            init_method=config.output_layer_init_method,
            bias=args.add_bias_linear,
            input_is_parallel=True,
            skip_bias_add=True)

class CoreAttention(MegatronModule):

    def __init__(self, layer_number, config,
                 attn_mask_type=AttnMaskType.padding):
        super(CoreAttention, self).__init__()
        self.fp16 = config.fp16
        self.bf16 = config.bf16

        self.apply_query_key_layer_scaling = config.apply_query_key_layer_scaling
        self.attention_softmax_in_fp32 = config.attention_softmax_in_fp32 ###由于softmax是精度敏感的操作，所以在softmax时候使用fp32精度
        if self.apply_query_key_layer_scaling:
            self.attention_softmax_in_fp32 = True
        self.layer_number = max(1, layer_number)
        self.attn_mask_type = attn_mask_type
        self.sequence_parallel = config.sequence_parallel

        projection_size = config.kv_channels * config.num_attention_heads

        # Per attention head and per partition values.
        world_size = mpu.get_tensor_model_parallel_world_size()
        self.hidden_size_per_partition = core.utils.divide(projection_size,
                                                           world_size)
        self.hidden_size_per_attention_head = core.utils.divide(
            projection_size, config.num_attention_heads)
        self.num_attention_heads_per_partition = core.utils.divide(
            config.num_attention_heads, world_size)

        coeff = None
        self.norm_factor = math.sqrt(self.hidden_size_per_attention_head) ###根号下dk
        if self.apply_query_key_layer_scaling: ##根号下dk * 层数idx
            coeff = self.layer_number
            self.norm_factor *= coeff

        self.scale_mask_softmax = FusedScaleMaskSoftmax( ##mask-softmax融合算子
            self.fp16, self.bf16,
            self.attn_mask_type,
            config.masked_softmax_fusion,
            attention_mask_func,
            self.attention_softmax_in_fp32, ##softmax是否以fp32精度计算
            coeff)

        # Dropout. Note that for a single iteration, this layer will generate
        # different outputs on different number of parallel partitions but
        # on average it should not be partition dependent.
        self.attention_dropout = torch.nn.Dropout(config.attention_dropout)

    def forward(self, query_layer, key_layer,
                value_layer, attention_mask):

        # ===================================
        # Raw attention scores. [b, np, s, s]
        # ===================================

        # [b, np, sq, sk]
        output_size = (query_layer.size(1),
                       query_layer.size(2),
                       query_layer.size(0),
                       key_layer.size(0))

        # [sq, b, np, hn] -> [sq, b * np, hn]
        query_layer = query_layer.reshape(output_size[2],
                                          output_size[0] * output_size[1], -1)
        # [sk, b, np, hn] -> [sk, b * np, hn]
        key_layer = key_layer.view(output_size[3],
                                   output_size[0] * output_size[1], -1)

        # preallocting input tensor: [b * np, sq, sk]
        matmul_input_buffer = mpu.get_global_memory_buffer().get_tensor(
            (output_size[0]*output_size[1], output_size[2], output_size[3]),
            query_layer.dtype, "mpu")

        # Raw attention scores. [b * np, sq, sk]
        matmul_result = torch.baddbmm( ###计算QK^T / sqrt(d_k)
            matmul_input_buffer,
            query_layer.transpose(0, 1),   # [b * np, sq, hn]
            key_layer.transpose(0, 1).transpose(1, 2),  # [b * np, hn, sk]
            beta=0.0, alpha=(1.0/self.norm_factor))

        # change view to [b, np, sq, sk]
        attention_scores = matmul_result.view(*output_size)

        # ===========================
        # Attention probs and dropout
        # ===========================

        # attention scores and attention mask [b, np, sq, sk]
        attention_probs = self.scale_mask_softmax(attention_scores, ###mask-softmax融合算子，可以直接合并计算
                                                  attention_mask)

        # This is actually dropping out entire tokens to attend to, which might
        # seem a bit unusual, but is taken from the original Transformer paper.
        if not self.sequence_parallel:
            with tensor_parallel.get_cuda_rng_tracker().fork():
                attention_probs = self.attention_dropout(attention_probs)
        else:
            attention_probs = self.attention_dropout(attention_probs)

        # =========================
        # Context layer. [sq, b, hp]
        # =========================

        # value_layer -> context layer.
        # [sk, b, np, hn] --> [b, np, sq, hn]

        # context layer shape: [b, np, sq, hn]
        output_size = (value_layer.size(1),
                       value_layer.size(2),
                       query_layer.size(0),
                       value_layer.size(3))

        # change view [sk, b * np, hn]
        value_layer = value_layer.view(value_layer.size(0),
                                       output_size[0] * output_size[1], -1)

        # change view [b * np, sq, sk]
        attention_probs = attention_probs.view(output_size[0] * output_size[1],
                                               output_size[2], -1)

        # matmul: [b * np, sq, hn]
        context_layer = torch.bmm(attention_probs, value_layer.transpose(0, 1)) ###根据attention score对V加权求和

        # change view [b, np, sq, hn]
        context_layer = context_layer.view(*output_size)

        # [b, np, sq, hn] --> [sq, b, np, hn]
        context_layer = context_layer.permute(2, 0, 1, 3).contiguous()

        # [sq, b, np, hn] --> [sq, b, hp]
        new_context_layer_shape = context_layer.size()[:-2] + \
            (self.hidden_size_per_partition,)
        context_layer = context_layer.view(*new_context_layer_shape)

        return context_layer
```

### 2.4 MLP+self-attention

把MLP层和self-attention层合起来，就得到了一个完整的Transformer Layer：

![](https://pica.zhimg.com/v2-15764468c321866002ef00b053108e5a_r.jpg)

可以看到，每个transformer layer都需要4个all-reduce操作（2个forward，2个backward）。其中forward时的all-reduce操作发生在dropout之前，因为我们需要把不同GPU上算出的结果进行拼接；backward时的all-reduce操作发生在layernorm之后，因为要把不同GPU上的梯度汇总。每次all-reduce都需要GPU之间的通信。如果GPU之间链接是PCIE（传输速率小于NVLink），那么不应将TP设置太高，因为这样会导致大量的GPU之间传输。实测TP=2能够达到最佳的效果。

### 2.5 Embedding层

Embedding层的矩阵维度为 $[V,h]$ 。当词表大小很大时，Embedding矩阵会变得很大，因此需要把Embedding拆分到各个GPU上。

假设我们把词表切成两份，第一块GPU维护词表的前半部分，第二块GPU维护词表的后半部分。当输入X去GPU上查找时，能找到的词，就正常返回词向量，找到不到就把词向量中的全部全素都置0。按此方式查找完毕后，每块GPU上的数据做一次AllReduce，就能得到最终的输入。

```python3
class VocabParallelEmbedding(torch.nn.Module):
    """Embedding parallelized in the vocabulary dimension.

    This is mainly adapted from torch.nn.Embedding and all the default
    values are kept.
    Arguments:
        num_embeddings: vocabulary size.
        embedding_dim: size of hidden state.

    Keyword Arguments:
        config: A megatron.core.ModelParallelConfig object
    """

    def __init__(
        self,
        num_embeddings: int,
        embedding_dim: int,
        *,
        init_method: Callable,
        config: ModelParallelConfig,
    ):
        super(VocabParallelEmbedding, self).__init__()
        # Keep the input dimensions.
        self.num_embeddings = num_embeddings
        self.embedding_dim = embedding_dim
        self.tensor_model_parallel_size = get_tensor_model_parallel_world_size() ### TP size
        # Divide the weight matrix along the vocaburaly dimension.
        (
            self.vocab_start_index,
            self.vocab_end_index,
        ) = VocabUtility.vocab_range_from_global_vocab_size(
            self.num_embeddings, get_tensor_model_parallel_rank(), self.tensor_model_parallel_size
        )
        self.num_embeddings_per_partition = self.vocab_end_index - self.vocab_start_index ##每个分片有的词汇个数

       
        self.weight = Parameter(
            torch.empty(
                self.num_embeddings_per_partition,
                self.embedding_dim,
                device=torch.cuda.current_device(),
                dtype=config.params_dtype,
            )
        )
        if config.perform_initialization:
            _initialize_affine_weight_gpu(self.weight, init_method, partition_dim=0, stride=1)

    def forward(self, input_):
        if self.tensor_model_parallel_size > 1:
            # Build the mask.
            input_mask = (input_ < self.vocab_start_index) | (input_ >= self.vocab_end_index) ##不在这个分片里的mask掉
            # Mask the input.
            masked_input = input_.clone() - self.vocab_start_index ##减去偏移
            masked_input[input_mask] = 0
        else:
            masked_input = input_
        # Get the embeddings.
        output_parallel = self.weight[masked_input] 
        # Mask the output embedding.
        if self.tensor_model_parallel_size > 1:
            output_parallel[input_mask, :] = 0.0
        # Reduce across all the model parallel GPUs.
        output = reduce_from_tensor_model_parallel_region(output_parallel)
        return output

```

如果我们将输入层和输出层共用一套word embedding，那么在backward的过程中，我们在输出层时会对word embedding计算一次梯度，在输入层中还会对word embedding计算一次梯度。在用梯度做word embedding权重更新时，我们必须保证用两次梯度的总和进行更新（这里涉及到梯度的all-reduce）。

## 2.6 Cross Entropy计算

输出层过完embedding得到 $Y_1$ 和 $Y_2$ 。正常的做法是对$Y_1$ 和 $Y_2$做一次All-Gather，把它们concat起来形成 $Y$ ，然后对 $Y$ 的每一行做softmax，再用此概率和ground truth做cross-entropy。但是All-Gather会产生额外的通讯量 $b *s*v $。当词表v很大时，这个通讯开销也不容忽视。针对这种情况，可以做如下优化：

![](https://pic2.zhimg.com/v2-9926c4900f19c8bcca09730c7b870d3b_r.jpg)
*来源：https://zhuanlan.zhihu.com/p/622212228*

这样，就可以把原先的通讯量从$b *s*v $大大降至$b * s + N$，其中N是计算loss时的通讯量。
