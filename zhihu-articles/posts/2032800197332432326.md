DigitalOcean 的 Serverless Inference 平台在 NVIDIA HGX B300（Blackwell Ultra）上部署 vLLM，DeepSeek V3.2、MiniMax-M2.5、Qwen 3.5 397B 三个模型同时上线。据 DigitalOcean 博客自测，DeepSeek V3.2 和 Qwen 3.5 397B 在 Artificial Analysis 已测试的 provider 范围内，输出速度均位列第一；MiniMax-M2.5 团队为其训练了 EAGLE3 draft model，TPOT 提升 23%。这是 vLLM 在 CSP 生产环境一次比较完整的部署案例。

## 部署栈

- **硬件**：NVIDIA HGX B300，288GB HBM3e（相对 B200 显存增加 50%）
- **推理引擎**：vLLM
- **量化**：NVFP4，相对 FP8 显存占用约降低 1.8x
- **投机解码**：EAGLE3 draft model（通过 TorchSpec 训练）叠加 MTP
- **并行策略**：TP4 / TP8（按模型规模选择）

## vLLM 侧的工程要点

- per-model kernel fusion——三个不同架构各做一套算子合并方案，降低显存访问开销
- Programmatic Dependent Launch 让 kernel 之间存在 overlap，低 batch 场景下吞吐提升约 10%
- MiniMax-M2.5 的 EAGLE3 draft model 用 TorchSpec 训练，并设置 `draft_tensor_parallel_size=1`，TPOT 提升 23%
- NVFP4 + MTP 叠加后，端到端时延显著下降

## 性能锚点（DigitalOcean 公布）

- **DeepSeek V3.2 输入 10K tokens**：输出 230 tok/s，TTFT 0.96 秒（TTFT 在 12 个测试 provider 中位列第二）
- **DeepSeek V3.2 与 Qwen 3.5 397B** 输出速度在 Artificial Analysis 已测 provider 中均居首位
- **DeepSeek V3.2** 在 Artificial Analysis 的"延迟 vs 输出速度"象限图中，是仅有的三个落入最优象限的 provider 之一

## 这次合作的几方

DigitalOcean 提供 CSP 生产环境与真实多租户流量；NVIDIA 配合 B300 的硬件特性做调优（包括解决虚拟化环境下的初期 25% 性能损失）；Inferact 团队负责 kernel fusion 与 draft model 训练工作。相关优化都会回流到开源 vLLM 主仓。

## 真实生产案例

Workato（每年处理超过 1 万亿次自动化任务）已经在 DigitalOcean 推理平台上跑生产负载：TTFT 提升 77%，端到端时延下降 79%，推理成本降低 67%。

## 为什么这个案例值得看

单个模型在隔离环境跑出漂亮数字相对容易；要在三个不同架构 + CSP 多租户实流量下，同时拿到两个输出速度第一 + 一个 EAGLE3 优化带来的 23% TPOT 提升，需要把硬件特性 / 量化 / 投机解码 / kernel 层优化拼成一套真正能跑稳的配方。DigitalOcean 博客原文对各层 trade-off 拆得比较细，建议直接读原文。
