## 1.cuda 基本知识（硬件与执行模型）

### 1.1 SM

Streaming Multiprocessors，以 Ampere A100 为例：A100 实际启用 108 个 SM，Ampere 架构一个 SM 分成 4 个子块，每个子块有：

- 16 个 FP32 CUDA Core
- 16 个 INT32 Core
- 8 个 LD/ST Unit
- 4 个 SFU
- 1 个 Tensor Core
- 1个Warp Scheduler

![](https://pica.zhimg.com/v2-719c9d3f854d82905a3317f06d92de62_r.jpg)

### 1.2 grid、block、thread、warp

- grid相当于block阵列
- block是线程组，一般最大1024个thread
- thread是最小执行单元
- warp 是硬件调度单位，每 32 个线程组成一个 warp。这里的 `warpInBlock` 表示该线程在 block 内的 warp 编号，`warpGlobal` 表示在整个 kernel 中的逻辑 warp 编号
- grid、block、thread都是软件概念，并不是硬件概念，warp 是硬件调度单位，实际运行时，GPU 会以 warp 为单位把指令发给线程执行；一个 SM 上可以同时驻留多个 block，而每个 block 内部的线程又会被切分成多个 warp 交替调度。

### 1.3 warp 调度与 resident warp

- Resident Warp：已分配到 SM 上、占用执行槽位并等待或正在被 warp scheduler 调度的 warp
- 每个 SM 的理论最大 resident warp 数 = `maxThreadsPerMultiProcessor / warpSize`，通常为 64（2048/32）
- resident warp个数主要由线程块尺寸、寄存器/共享内存占用、以及每 SM 最大线程块数共同限制，核心公式是“取所有资源约束的最小值”。

```cpp
受 block 数量限制的线程数 = maxBlocksPerSM × blockSize
受寄存器限制的线程数 = regsPerSM / regsPerThread
受共享内存限制的 block 数 = sharedMemPerSM / sharedMemPerBlock,转化为线程数 = block数 × blockSize
理论最大 Resident Warps = maxThreadsPerMultiProcessor / warpSize

```

- 一个 SM 有四个分区，每个分区一个 Warp Scheduler，Warp Scheduler 不是一直拥有固定几个 warp，它每个 cycle 会从自己负责的 warp pool 里面选择 ready warp。每个Warp 怎么绑定到 Partition或者说Warp Scheduler的，目前官方资料并没有解释。

### 1.4 thread 与硬件单元的关系

CUDA thread 是一个逻辑执行单位，没有一一对应的物理实体，它只是维护：thread 的编号、thread 的寄存器状态、program counter（执行位置）、thread 的上下文，然后让硬件调度执行。一个 thread 可能执行：

```text
add
mul
load
branch
```

需要不同硬件，例如：加法，走cudacore， 矩阵乘走tensorcore，内存访问走Load/Store Unit。

### 1.5 block 内部线程通信

block 内部通信的核心机制是 Shared Memory（共享内存） 与 `__syncthreads()` 同步屏障：线程将私有数据写入共享内存，屏障确保所有线程写入完成，再读取其他线程写入的值，从而实现协作计算。除了这种归约模式，共享内存还常用于滑动窗口、矩阵分块转置等需要邻居数据交换的场景；若仅限 Warp 内线程间通信，也可以使用 `__shfl_xxx` 系列指令，性能比共享内存更高。

## 2.Compute Capability

设备的`Compute Capability`由版本号表示，有时也称其“ SM 版本”。比如Ampere架构为SM8X，Volta架构为SM7X。

## 3.nvcc、ptx、sass

- `nvcc`：CUDA 编译器驱动，读取 `.cu` 源文件，分别处理主机代码和设备代码；
- `ptxas `是 NVIDIA CUDA 工具链中的 PTX 汇编器，负责将 PTX 虚拟指令集编译为 GPU 实际执行的 SASS 机器码，是 `nvcc` 编译流程中的核心后端组件。
- `PTX`（Parallel Thread Execution）：虚拟指令集，可移植，不限定 GPU 架构；
- `SASS`：是针对具体 GPU（如 `sm_80`、`sm_90`）生成的真实机器指令，最终由 SM 执行;

```text
.cu 源文件
   │  nvcc 前端（cicc）负责词法、语法、语义分析及设备代码生成
   ▼
.ptx（虚拟指令集，与具体 GPU 架构无关）
   │  ptxas（PTX 汇编器 + 优化器）
   ▼
.cubin（包含 SASS，与具体 GPU 架构强相关）
   │  nvcc 链接器 / host 编译器
   ▼
最终可执行文件（host 代码 + 嵌入的 GPU 代码）
```

## 4.GPU 内存体系

### 4.1 host-device 数据移动

- 对于整个HostMemory内存条而言，操作系统区分为两个大类（逻辑区分，物理上是同一个东西）：Pageablememory可分页内存 、Pagelockmemory（pinnedmemory）页锁定内存
- GPU可以直接访问pinnedmemory，称之为（DMA，Direct Memory Access），而不能访问 pageable memory
- gpu数据和cpu数据传输的过程：Pageablememory上的内存往gpu global memory拷贝的时候（`cudaMemcpy`），其实隐式地先从Pageablememory拷贝到了pinnedmemory，再拷贝到gpu global memory，所以尽量多用PinnedMemory储存host数据，或者显式处理Host到Device时，用PinnedMemory做缓存，都是提高性能的关键。

![](https://pic1.zhimg.com/v2-d4febeb3bd8d01886136a34bdc90a134_r.jpg)

| 函数 | 作用 |
| --- | --- |
| cudaMalloc / cudaFree | 分配/释放设备端 global memory |
| cudaMallocHost / cudaFreeHost | 分配/释放主机端 pinned memory |
| cudaHostAlloc / cudaFreeHost | 更灵活的 pinned memory 分配方式，支持 cudaHostAllocMapped 等标志 |
| cudaMemcpyHostToDevice cudaMemcpyDeviceToHost | 同步拷贝 H2D / D2H |
| cudaMemcpyAsync | 异步拷贝，需要 pinned memory 和 CUDA 流 |
| malloc / new / calloc | 分配/释放主机端 pageablememory |

### 4.2 内存层次总览

![](https://pic4.zhimg.com/v2-c623c4c936941407c0a7367a7a9be50f_r.jpg)

- global memory不在gpu芯片上，但是物理封装的时候每个gpu都有属于自己的global memory，物理位置为显存 DRAM，通过 L2 缓存，sm80 以上可以通过 L2 持久化访问加快访问速度
- Constant Memory常量内存，显存 DRAM上，64KB 大小限制，设备端只读，主机端可写，常量内存有专属的常量缓存（Constant Cache）和广播机制，访问速度取决于具体访问模式：同地址全线程读取时极快，不同地址时反而可能比全局内存更慢。
- Local memory和 Global Memory 在物理上都位于 GPU 的 Device Memory（HBM/GDDR）中，但它们属于不同的 CUDA 地址空间（`.local` 与 `.global`）。Local Memory 没有独立的物理存储区域，它只是 GPU 为每个 Thread 提供的一种私有地址空间。
- l2 cache在gpu上，整个gpu共享
- l1 cache在SM内，SM内的所有thread共享
- Shared memory在SM内，物理上与l1cache共享同一块SRAM，软件上属于block内共享
- register每个thread独享

### 4.3 global memory 管理

cudaMalloc、cudaMallocPitch、cudaMalloc3D 分别用于一维线性、二维对齐、三维对齐显存分配，后两者通过返回的 `pitch`/`cudaPitchedPtr` 支持高效的按行存储与访问。

| 函数 | 适用维度 | 返回结构 | 内存布局 | 典型用途 |
| --- | --- | --- | --- | --- |
| cudaMalloc | 1D | void* | 连续线性 | 普通数组、参数缓冲区 |
| cudaMallocPitch | 2D | void* + size_t pitch | 每行按 pitch 对齐 | 图像、矩阵 |
| cudaMalloc3D | 3D | cudaPitchedPtr（含 ptr + pitch + xsize + ysize） | 每行/每层按 pitch 对齐 | 体数据、3D贴图 |

### 4.4. shared memory

Shared Memory 和 L1 Data Cache 本质上使用的是同一块片上 SRAM（on-chip SRAM），只是逻辑上分成了两种用途。

```text
               SM

        ┌──────────────────────┐
        │      Registers       │
        ├──────────────────────┤
        │                      │
        │  Unified SRAM        │
        │                      │
        │  ← L1 Cache          │
        │  ← Shared Memory     │
        │                      │
        └──────────────────────┘
                │
               L2
                │
              HBM
```

每个 SM 上都有一块 **192 KB 的片上 SRAM**。这块 SRAM 会根据需要划分给：

- Shared Memory
- L1 Data Cache
- Texture Cache（逻辑上也共享这块资源）

1.静态共享内存

编译时大小已经确定，举个例子：

```cpp
__global__ void kernel()
{
    __shared__ float A[256];//256×4=1024 Bytes
    ...
}

```

2.动态共享内存

大小运行时决定，举个例子：编译器不知道buffer 多大,真正大小在Kernel Launch 时指定，shared_size是个变量可以根据程序中的实际情况设置不同大小。

```cpp
kernel<<<grid,block,shared_size>>>();
__global__ void kernel()
{
    extern __shared__ float buffer[];
}

```

3.为什么静态 Shared 超过 48 KB 就不行？

CUDA 为了兼容老架构，静态 Shared 仍然保持 48 KB 的兼容限制，如果希望一个 Block 使用超过 48 KB 的 Shared，需要使用动态Shared Memory并设置参数申请更大的动态 Shared。

```cpp
    // 7. 设置共享内存属性 (>= 48KB 时需要)
    if (smem_size >= (48 << 10)) {//49152
        cudaFuncSetAttribute(
            spconv::conv_kernel,
            cudaFuncAttributeMaxDynamicSharedMemorySize,
            smem_size);//允许smem_size字节的动态Shared Memory，而不是默认的48KB上限
        cudaFuncSetAttribute(
            spconv::conv_kernel,
            cudaFuncAttributePreferredSharedMemoryCarveout,
            100);//尽量把Unified SRAM 划给Shared Memory，而不是L1 Cache
            //100是100%的意思，但具体大小由硬件支持的 carveout 档位决定，不一定正好是 100% Shared
    }

```

4.bank conflict

Shared Memory 虽然很快，但是它不是一整块 SRAM, 为了提高带宽，它被划分成了32个bank，可以同时访问。为什么是32？因为一个warp是32个线程，理想情况下，每个32个线程每个访问一个bank，则一次完成32次访问。每个 bank 每个时钟周期能提供 32 bit / 4 byte 数据，32 banks × 4 bytes = 128 bytes/cycle，这就是 SM 内共享内存的理论带宽。Bank Conflict 是指同一个 Warp 内，多个 Thread 在同一条 Shared Memory 指令中，同时访问同一个 Bank 中的不同地址，导致该 Bank 无法并行服务，只能串行访问。

- 没有bankconflict的情况如下，所有Bank同时工作，耗时1cycle：

```text
__shared__ float A[32];

Warp
T0  -------------> A[0] -------------> Bank0
T1  -------------> A[1] ------------->  Bank1
T2  -------------> A[2] ------------->  Bank2
...
T31 -------------> A[31] ------------->  Bank31
```

- 如果每个Bank来了两个线程，于是Bank只能先服务一个再服务另外一个，举个2-way conflict的例子：

```text
__shared__ float smem[128];
float val = smem[threadIdx.x * 2];

thread 0  → smem[0]   → bank 0
thread 1  → smem[2]   → bank 2
thread 2  → smem[4]   → bank 4
...
thread 15 → smem[30]  → bank 30
thread 16 → smem[32]  → bank 0   ← 和 thread 0 冲突
thread 17 → smem[34]  → bank 2   ← 和 thread 1 冲突
...
thread 31 → smem[62]  → bank 30  ← 和 thread 15 冲突
```

### 4.5 L2 持久化

当一个 CUDA 内核重复访问全局内存中的一个数据区域时，这种数据访问可以被认为是持久化的 (persisting )。 另一方面，如果数据只被访问一次，那么这种数据访问可以被认为是流式的 (streaming )。从 CUDA 11.0 开始，计算能力 8.0 及以上的设备能够影响 L2 缓存中数据的持久性，进而可能对全局内存的访问提供更高带宽和更低延迟。

## 5.C++ 语言扩展

### 5.1 函数执行空间说明符

(Function Execution Space Specifiers ) 表示函数是在主机上执行还是在设备上执行，以及它可被主机调用还是可被设备调用。<br>1.`global` 执行空间说明符将函数声明为内核。 它的功能是：

- 在设备上执行，
- 可从主机调用，

2.`device` 执行空间说明符声明了一个函数：

- 在设备上执行，
- 只能从设备调用。 `global` 和 `device` 执行空间说明符不能一起使用。

3.`device` 和 `host` 执行空间说明符可以一起使用，使其既能在 CPU（Host）上被调用，也能在 GPU（Device）上被调用，这是 CUDA 中避免重复代码的常用写法。函数体内不能使用仅主机端支持的特性（如 `std::vector`、`new`/`delete`、异常等），也不能使用仅设备端支持的特性（如 `__syncthreads()`、`threadIdx` 等）。编译 的时候`nvcc` 会把 `.cu` 文件拆分为两条编译路径：Host 编译路径：将主机端代码交给主机编译器（如 `gcc` / `clang`）编译，最终生成 CPU 机器码。Device 编译路径：将设备端代码（`global`、`device`、`host device` 函数）编译成 PTX / cubin，嵌入最终可执行文件中。

### 5.2 变量内存空间说明符

( Variable Memory Space Specifiers ) 表示变量在设备上的内存位置。

| 说明符 | 存储位置 | 可见范围 | 生命周期 | 读写方式 |
| --- | --- | --- | --- | --- |
| __device__ | 全局内存（Global Memory） | 整个设备端编译单元 | 与程序共存 | 所有线程可读写；主机端通过 cudaMemcpyToSymbol / cudaMemcpyFromSymbol 访问 |
| __constant__ | 常量内存（Constant Memory） | 整个设备端编译单元 | 与程序共存 | 所有线程只读；主机端通过 cudaMemcpyToSymbol 写入 |
| __shared__ | 共享内存（Shared Memory） | 单个线程块内 | 与线程块共存 | 块内所有线程可读写，用于线程间通信和加速 |
| __managed__ | 统一内存（Managed Memory） | 主机端 + 设备端 | 与程序共存 | CPU 和 GPU 均可通过普通指针直接读写，由统一内存自动迁移数据 |

1. `device` 变量：默认放在全局内存，所有块和线程都可以读写。主机端不能直接用指针访问，而是通过 `cudaMemcpyToSymbol` / `cudaMemcpyFromSymbol` 与其交换数据。
2. `constant` 变量：存放在常量内存，对核函数内所有线程是只读的。因为常量内存有专用缓存和广播机制，当所有线程读取同一地址时非常高效。主机端只能通过 `cudaMemcpyToSymbol` 写入。
3. `shared` 变量：在 kernel 内部声明时使用，同一个线程块内的所有线程共享一份，且访问速度远快于全局内存。它常用于块内协调、数据复用和减少全局内存访问。
4. `managed` 变量：由 CUDA 统一内存管理，主机与设备之间通过页面迁移自动同步数据。CPU 可以直接读写，GPU kernel 中也可以直接使用，无需显式 `cudaMemcpy`。

### 5.3 原子函数 Atomic Functions

原子函数对驻留在全局内存或共享内存中的一个 32 位或 64 位字执行读-修改-写原子操作。 例如，`atomicAdd()` 在全局或共享内存中的某个地址读取一个字，向其中加一个数字，然后将结果写回同一地址。 该操作是原子的，因为它保证在不受其他线程干扰的情况下执行。 换句话说，在操作完成之前，没有其他线程可以访问该地址。任何原子操作都可以基于 `atomicCAS()`（Compare And Swap）来实现。<br>CUDA Atomic 的 Memory Scope（内存作用域）：

| Scope | 保证范围 | 典型 API |
| --- | --- | --- |
| Block | Block 内所有 Thread | atomicAdd_block() |
| Device | 整个 GPU 所有 Thread | atomicAdd()（默认） |
| System | GPU + CPU + 其它设备 | atomicAdd_system() |

从 CUDA 11 开始，NVIDIA 更推荐使用 **CUDA C++ 原子库**（基于 C++ 标准风格），例如：

```text
cuda::atomic<int, cuda::thread_scope_block>
cuda::atomic<int, cuda::thread_scope_device>
cuda::atomic<int, cuda::thread_scope_system>
```

### 5.4 地址空间谓词函数 Address Space Predicate Functions

地址空间谓词函数是 CUDA 提供的一组设备端内建函数，用于在运行时判断某个指针指向的是全局、共享、常量还是本地内存空间，从而让代码根据指针所属内存类型执行不同逻辑。<br>如果参数是空指针，则本节中描述的函数具有未指定的行为。

| 函数 | 功能 |
| --- | --- |
| unsigned __isGlobal(const void *ptr) | 指针是否指向全局内存（Global Memory） |
| unsigned __isShared(const void *ptr) | 指针是否指向共享内存（Shared Memory） |
| unsigned __isConstant(const void *ptr) | 指针是否指向常量内存（Constant Memory） |
| unsigned __isLocal(const void *ptr) | 指针是否指向本地内存（Local Memory，即线程私有的局部变量存储） |

注意这里的Local Memory是每个thread私有的，一般是核函数中或者device函数中定义的数组变量。

## 6.warp 原语

### 6.1 warp 投票函数 Warp Vote Functions

用于让 Warp 内所有线程对一个布尔表达式进行投票（Vote），并把投票结果返回给各个线程。关键词只有两个：

- Warp 内（32 个 Thread）
- 投票（Vote）

它们并不会交换数据（data），而是交换**真假（true/false）**。

| 函数 | 含义 | 返回值 |
| --- | --- | --- |
| __all_sync(mask, pred) | 全部线程都满足？ | bool |
| __any_sync(mask, pred) | 是否至少一个线程满足？ | bool |
| __ballot_sync(mask, pred) | 返回所有线程的投票位图 | unsigned int mask |
| __activemask() | 如果调用 __activemask() 时，warp 中的第 N 条通道处于活动状态，则设置第 N 位。非活动线程由返回掩码中的 0 位表示 | 返回调用 warp 中所有当前活动线程的 32 位整数掩码。 |

其中参数中的mask以及__ballot_sync返回的mask，都是按照bit i ⇔ Lane i的对应关系。

### 6.2 warp 匹配函数 Warp Match Functions

比较任意数据值是否相同

```text
unsigned int __match_any_sync(unsigned mask, T value);
unsigned int __match_all_sync(unsigned mask, T value, int *pred);
```

返回 Warp 中所有 value 和自己相同的线程 Mask：

```text
unsigned mask =
__match_any_sync(0xffffffff, value);
```

如果warp中所有lane的value值相同则flag为1，否则为0：

```text
int flag;

unsigned mask =
__match_all_sync(0xffffffff,value, &flag);
```

### 6.3 warp 归约函数 Warp Reduce Functions

Reduce 就是：把多个线程的数据归约（Reduction）成一个结果。<br>`__reduce_sync(unsigned mask, T value)` 内在函数在同步 `mask` 中命名的线程后对 `value` 中提供的数据执行归约操作。 `T` 对于 `{add, min, max}` 可以是无符号的或有符号的，并且仅对于 `{and, or, xor}` 操作是无符号的。

```text
// add/min/max
unsigned __reduce_add_sync(unsigned mask, unsigned value);
unsigned __reduce_min_sync(unsigned mask, unsigned value);
unsigned __reduce_max_sync(unsigned mask, unsigned value);
int __reduce_add_sync(unsigned mask, int value);
int __reduce_min_sync(unsigned mask, int value);
int __reduce_max_sync(unsigned mask, int value);

// and/or/xor
unsigned __reduce_and_sync(unsigned mask, unsigned value);
unsigned __reduce_or_sync(unsigned mask, unsigned value);
unsigned __reduce_xor_sync(unsigned mask, unsigned value);
```

`__reduce_add_sync、__reduce_min_sync、__reduce_max_sync`<br>返回对 `mask` 中命名的每个线程在 `value` 中提供的值应用算术加法、最小或最大规约操作的结果。<br>`__reduce_and_sync、__reduce_or_sync、__reduce_xor_sync`<br>返回对 `mask` 中命名的每个线程在 `value` 中提供的值应用逻辑 `AND、OR 或 XOR` 规约操作的结果。

### 6.4 Warp Shuffle Functions
