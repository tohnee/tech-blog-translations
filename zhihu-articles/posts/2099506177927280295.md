1. **Kubernetes 存储架构**

Kubernetes 通过抽象层管理底层存储，使应用不需要关心存储设备的具体实现。

核心概念：

- Volume：Pod 使用的存储卷。
- PV（PersistentVolume）：集群中的持久化存储资源。
- PVC（PersistentVolumeClaim）：应用对存储资源的申请。
- StorageClass（SC）：定义存储类型及动态供给规则。
- CSI（Container Storage Interface）：Kubernetes 与存储系统之间的标准接口。

### 2. Volume：Pod 存储卷

Volume 是 Kubernetes 提供给 Pod 使用的存储抽象。

常见类型：

| 类型 | 特点 | 使用场景 |
| --- | --- | --- |
| emptyDir | Pod 生命周期内存在 | 临时缓存、共享文件 |
| hostPath | 挂载宿主机目录 | 节点级日志、特殊场景 |
| ConfigMap | 挂载配置文件 | 应用配置 |
| Secret | 挂载敏感信息 | 密码、证书 |
| PersistentVolume | 持久化存储 | 数据库、持久化应用 |

示例：

volumes:

- name: cache

emptyDir: {}

containers:

- name: app

image: nginx

volumeMounts:

- name: cache

mountPath: /cache

### 3. PV：PersistentVolume

PV 是 Kubernetes 集群中的持久化存储资源，由管理员创建或通过 StorageClass 动态创建。

PV 描述了存储的容量、访问模式和底层存储来源。

示例：

apiVersion: v1

kind: PersistentVolume

metadata:

name: pv-demo

spec:

capacity:

storage: 10Gi

accessModes:

- ReadWriteOnce

persistentVolumeReclaimPolicy: Retain

hostPath:

path: /data

PV 生命周期：

Available → Bound → Released

常见回收策略：

- Retain：PVC 删除后保留数据，需要手动处理。
- Delete：PVC 删除后，底层存储资源也可能被删除。
- Recycle：旧式回收方式，已废弃。

### 4. PVC：PersistentVolumeClaim

PVC 是应用对存储资源的申请。

它定义需要多少容量、什么访问模式，以及可选的 StorageClass。

示例：

apiVersion: v1

kind: PersistentVolumeClaim

metadata:

name: app-pvc

spec:

accessModes:

- ReadWriteOnce

resources:

requests:

storage: 10Gi

storageClassName: gp3

Kubernetes 会根据 PVC 的需求寻找合适的 PV，并完成绑定。

核心关系：一个 PVC 绑定一个 PV。

### 5. AccessModes：存储访问模式

| 模式 | 含义 |
| --- | --- |
| RWO | 单个 Node 可读写挂载 |
| ROX | 多个 Node 只读挂载 |
| RWX | 多个 Node 可读写挂载 |
| RWOP | 单个 Pod 可读写挂载 |

注意：RWO 并不意味着只能被一个 Pod 使用，而是限制为一个 Node 进行读写挂载。

具体支持哪些模式，还取决于底层存储和 CSI Driver。

### 6. StorageClass：动态存储供给

StorageClass 定义存储类型和动态创建规则。

当 PVC 申请存储时，Kubernetes 可以通过 StorageClass 自动创建 PV，无需提前手动创建 PV。

例如 AWS EBS：

apiVersion: [http://storage.k8s.io/v1](http://storage.k8s.io/v1)

kind: StorageClass

metadata:

name: gp3

provisioner: [http://ebs.csi.aws.com](http://ebs.csi.aws.com)

parameters:

type: gp3

fsType: ext4

volumeBindingMode: WaitForFirstConsumer

常见绑定模式：

- Immediate：创建 PVC 时立即创建并绑定存储。
- WaitForFirstConsumer：等 Pod 调度后再创建存储，适合有可用区限制的云盘。

### 7. CSI：Container Storage Interface

CSI 是 Kubernetes 与外部存储系统之间的标准接口。

通过 CSI，Kubernetes 可以对接不同厂商的存储系统，例如：

- AWS EBS / EFS
- Ceph
- Longhorn
- OpenEBS

CSI 主要包含：

| 组件 | 作用 |
| --- | --- |
| Controller Plugin | 创建、删除、挂载准备、扩容存储 |
| Node Plugin | 在具体 Node 上执行挂载操作 |
| External Provisioner | 根据 PVC 触发存储创建 |
| External Attacher | 管理 Volume Attach / Detach |
| External Resizer | 处理存储扩容 |

典型挂载流程：

PVC 创建

|

External Provisioner

|

CSI Controller

|

创建底层 Volume

|

PV 创建并绑定 PVC

|

Pod 调度到 Node

|

Attach Volume

|

CSI Node Plugin 执行 Mount

|

容器使用存储

### 8. StatefulSet 与存储

StatefulSet 主要用于有状态应用，例如 MySQL、Redis、Kafka。

它可以通过 volumeClaimTemplates 为每个 Pod 自动创建独立 PVC。

示例：

volumeClaimTemplates:

- metadata:

name: data

spec:

accessModes:

- ReadWriteOnce

storageClassName: gp3

resources:

requests:

storage: 20Gi

例如三个副本会产生三个独立 PVC：

mysql-0 → data-mysql-0

mysql-1 → data-mysql-1

mysql-2 → data-mysql-2

Pod 重建后仍可以重新挂载原来的持久化数据。

### 9. 存储扩容

如果 StorageClass 支持扩容，可以通过修改 PVC 的容量申请实现扩容。

kubectl edit pvc app-pvc

修改：

resources:

requests:

storage: 20Gi

Kubernetes 会通过 CSI Driver 执行底层存储扩容，必要时还会扩展文件系统。

### 10. 常见运维命令

# 查看 PV

kubectl get pv

# 查看 PVC

kubectl get pvc -A

# 查看 StorageClass

kubectl get sc

# 查看 Pod 挂载信息

kubectl describe pod <pod-name>

# 查看 PVC 详情

kubectl describe pvc <pvc-name>

# 查看 CSI Driver

kubectl get csidrivers

# 查看 VolumeAttachment

kubectl get volumeattachment

常见故障：

| 状态/问题 | 可能原因 |
| --- | --- |
| PVC Pending | 没有匹配 PV、StorageClass 配置错误 |
| MountVolume Failed | CSI Node Plugin 异常 |
| AttachVolume Failed | 云盘挂载限制、节点或可用区不匹配 |
| Multi-Attach Error | RWO 云盘被其他 Node 占用 |
| PVC 扩容失败 | CSI 不支持扩容或底层存储异常 |

### 11. 核心概念总结

| 组件 | 核心职责 |
| --- | --- |
| Volume | Pod 使用存储 |
| PV | 定义持久化存储资源 |
| PVC | 申请持久化存储 |
| StorageClass | 定义存储类型和动态供给规则 |
| CSI | 对接底层存储系统 |
| StatefulSet | 管理有状态应用及独立存储 |
