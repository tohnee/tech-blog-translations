## 引言

如果你最近两年关注过大模型发布，会发现几乎所有头部玩家的旗舰都共享同一个关键词：**MoE（Mixture-of-Experts，混合专家）**。但单看某一款模型，你只能看到参数表；比如：DeepSeek V4-Pro 把参数量堆到 1.6T，但每个 token 只点亮其中的 49B——**总参数决定"知识容量"，激活参数决定"推理成本"**，这已经成为业界共识。把八款代表模型摆在一起，你会看到一场完整的架构革命：

| 模型 | 总参数 | 每 Token 激活 | 激活率 | 专家配置 | 注意力方案 |
| --- | --- | --- | --- | --- | --- |
| Qwen3 (30B-A3B) | 30B | ~3B | ~10% | 128 选 8，无共享 | 全层 GQA |
| Gemma 4 (26B-A4B) | 26B | ~4B | ~15% | 128 选 8 + 1 共享 | 滑窗(1024) + 少量全局，5:1 |
| MiniMax M3 | 428B | ~23B | ~5.4% | 128 选 4 + 1 共享 | MSA（索引分支 + 主分支） |
| GLM-5.2 | 744B | 40B | ~5.4% | 256 选 8 + 1 共享 | DSA + IndexShare（4 层复用索引） |
| Xiaomi MiMo-V2.5-Pro | 1.02T | ~40B | ~3.9% | 384 选 8 | 10 全局 + 60 滑窗(128)，1:6 |
| DeepSeek V4-Pro | 1.6T | 49B | ~3.1% | 384 选 6 + 1 共享 | CSA + HCA |
| Kimi K3 | 2.8T | 104B | ~3.7% | 896 选 16 + 2 共享 | 69 KDA + 24 Gated MLA，3:1 |
| Qwen3.8-Flash-Next | 125B | 6B | ~4.8% | 512 选 10 + 1 共享 | 3 GDN + 1 QSA，3:1 |

本文分三部分：先讲清 MoE 的核心机制，再沿时间线拆解八款模型的设计抉择，最后看MoE 工程落地的隐形成本。

## 第一章：MoE 的本质——条件计算

### 1.1 为什么稠密模型走到了尽头

稠密（Dense）Transformer 中，每个 token 都要经过全部 FFN 参数。想让模型"更聪明"，只能加宽加深——FLOPs 和显存带宽随参数线性增长，推理成本直接爆炸。

MoE 的思路很朴素：**把 FFN 层替换成 N 个并行的"专家"网络，每个 token 只路由给 top-k 个**。

```text
Dense FFN:  x → W₂·SiLU(W₁x)                # 全部参数参与
MoE FFN:    x → Router(x) → Top-k 专家 → 加权求和

```

于是模型容量（总参数量）和计算量（激活参数量）解耦了：磁盘和显存里存着一个万亿参数的"知识仓库"，但每次前向只取一小格货架。这也是 "30B-A3B"、"26B-A4B" 这类命名的由来——后面的数字是每 token 的激活参数。

### 1.2 路由机制

每个 MoE 层入口是一个轻量 Router（线性层 + softmax），为 token 对每个专家打分，选出 top-k 并加权聚合：

$y = \sum_{i \in \text{TopK}(x)} g_i(x) \cdot E_i(x) \\$

k 通常很小（1~8），换来的是组合数的爆炸——128 个专家选 8 个，可能的专家组合约 $4.2 \times 10^{10}$ 种。这就是 MoE 表达能力的来源。

### 1.3 负载均衡

Router 有个天然倾向：**强者恒强**。不加约束时，少数热门专家会被喂入大量 token，导致 GPU 负载不均、all-to-all 通信堵塞，冷门专家则训练不充分。

传统做法是加辅助损失惩罚不均衡，但**辅助损失和语言建模主目标互相拉扯，会损伤质量**。DeepSeek 在 V3 时代提出的**无辅助损失负载均衡**成为行业标配：通过给 router logits 加可学习的偏置项，温和地把 token 推向冷门专家，而不引入对抗性损失项。

### 1.4 共享专家

**共享专家（shared expert）**：每层保留 1 个始终参与计算的专家负责通用特征。而被路由的**细粒度专家**专精窄领域。"通用 + 专科"的分工显著提升了专家专业化程度和路由稳定性。

## 第二章：典型的 MoE 模型架构

### 2.1 Qwen3-30B-A3B（2025年4月）

Qwen3-30B-A3B 采用了与旗舰（Qwen3-235B-A22B）同源的细粒度 MoE 设计，30B 总参数，激活约 3B，48 层Transformer，MoE 层 128 个路由专家选 8 个，理论上单一 token 可访问的专家组合超过 $4 \times 10^{10}$ 种，表达容量远超把同等参数切成 8 个大专家的做法。值得注意的是，它没有使用共享专家，负载均衡也仍采用传统的**辅助损失**（auxiliary loss）——即给门控加一项负载均衡惩罚项。30B-A3B还支持**混合推理模式**——同一 checkpoint，开关思维链即可切换"思考/不思考"两种行为。

| 项目 | 规格 |
| --- | --- |
| 总参数 | 30.5B |
| 每 token 激活 | ~3.3B（A3B） |
| 层数 | 48 层 |
| MoE 层 | 128 个路由专家，每 token 选 8 个 |
| 注意力 | GQA（32 查询头 / 8 KV 头） |
| 原生上下文 | 32K（YaRN 可外推至 131K） |
| 预训练数据 | ~36T tokens |

![](https://pic2.zhimg.com/v2-0a69c5729ddd30ac1403a8cb3fdf7489_r.jpg)

### 2.2 Gemma 4-26B-A4B（2026年4月）

Gemma 4 是 Google DeepMind 于 2026 年 3 月 31 日公布、4 月 2 日正式发布的开源模型家族。整个家族从手机到工作站共五个规格：E2B/E4B（端侧）、12B Unified（统一多模态设计）、26B-A4B（MoE） 和 31B Dense 旗舰。26B-A4B 总参数 25.2B，每 token 激活仅 3.8B，激活率约 15%，48 层Transformer。

![](https://picx.zhimg.com/v2-67e9e7dd86cf38c48112a0a968d7d843_r.jpg)

MoE 层有 128 个路由专家，每 token 激活 8 个路由专家 + 1 个共享专家。每个路由专家只有标准 MLP 的 1/3 大（intermediate size 仅 704 维），而共享专家是普通路由专家的 3 倍大，以确保其涵盖必要的通用知识。

![](https://pic2.zhimg.com/v2-a98e90534602b7b1d5fc8a55f2e8c875_r.jpg)

![](https://pic2.zhimg.com/v2-942658abf7e3b2d0896f617c20a15949_r.jpg)

此外， 与Qwen3-30B-A3B相比， Gemma 4 采用混合注意力，在30层中以5:1的比例交错使用滑动窗口注意力（窗口大小1024）和全局注意力。只有 5 层保留全局注意力，且全局层每头仅 2 个 KV 头。效果是 KV cache 成本变得极小且与对话长度几乎无关——256K 满上下文下 KV cache 仅占约 7GB，整张 RTX 4090 就能跑满规格推理。

| 维度 | Qwen3-30B-A3B（2025.4） | Gemma 4-26B-A4B（2026.4） |
| --- | --- | --- |
| 总参 / 激活 | 30.5B / 3.3B（~10%） | 25.2B / 3.8B（~15%） |
| 注意力 | 全层 GQA（32/8） | 25 层滑窗（1024）+ 5 层全局（2 KV 头） |
| 上下文 | 32K 原生（YaRN 131K） | 256K 原生 |
| 模态 | 文本优先 | 原生文本 + 图像 |
| 推理加速 | 混合思考模式（两档"思维路由"） | MTP 投机解码（草稿模型） |
| 路由专家数 | 128 个 | 128 个 |
| 每Token激活专家数 | Top-8 | Top-8 |
| 共享专家 | - | 1 个（始终激活） |

### 2.3 DeepSeek-V4-Pro（1.6T，2026年4月预览，8月正式版）

DeepSeek-V4-Pro 总参数 1.6T，每 token 激活 49B，激活率约3.1%，1M 上下文，MIT 协议开放权重。共有 384 个路由专家（Routed Experts），外加 1 个共享专家（Shared Expert）。每 token 激活 6 个专家。

V4 的突破性不在参数数字，而在架构决策：

- Hybrid Attention（CSA + HCA）——稀疏化从 FFN 扩展到注意力。此前从 V2 到 V3.2 靠 MLA 压缩 KV cache，V4 则更进一步：先对 KV cache 做 token 维压缩，再用 lightning indexer 从压缩表示中选出每步最相关的 top-1024 个条目参与注意力。效果惊人：1M token 上下文的推理 FLOPs 只有 V3.2 的 27%，KV cache 显存只有 10%。 <br>

- 无辅助损失均衡 + 共享专家 + 细粒度专家，组合成成熟的"路由基础设施"。
- 超连接（mHC）与记忆模块。流形约束的残差连接替代标准 residual stream，让信号在超深层网络中稳定传输；Engram 条件记忆把"记忆"做成显式结构。
- 混合精度：权重以 FP4 + FP8 混合精度发布。其中， **MoE 专家参数使用 FP4**，其余大部分参数使用 FP8。这使得一个 1.6T 的模型在 Hugging Face 上的实际存储大小仅约 862B 参数，显著降低了部署门槛。

![](https://picx.zhimg.com/v2-41c5d1b18e91bf62d69f277886221365_r.jpg)

### 2.4 Xiaomi MiMo-V2.5-Pro（1.02T，2026年4月）

Xiaomi MiMo-V2.5-Pro 共有 1.02T 总参数，约 40B 激活，激活率约 3.9%。含 384 个路由专家，每Token激活 8 个。共 70 层 Transformer（1层Dense + 69层MoE）。

![](https://pic1.zhimg.com/v2-54754c225c9f57ec8f6caddfd4035c8e_r.jpg)

采用混合注意力，10层全注意力（GA） + 60层滑动窗口注意力（SWA），比例 6:1；SWA窗口大小为 128 Token，将KV缓存和计算量压缩至全注意力的约 1/7，支持1M上下文。

128个查询Head，采用分组查询注意力（GQA），KV Head数为8。**配备 3层 轻量级MTP模块（使用稠密FFN）**，将推理输出速度提升约 3倍。引入可学习的注意力Sink偏置（Attention Sink Bias），在压缩KV缓存的同时，保持长上下文性能。

![](https://pic2.zhimg.com/v2-823b77954796b8229df6e20951ebc47f_r.jpg)

### 2.5 GLM-5.2（744B，2026年5月）

GLM-5.2 共有 744B 总参数，40B 激活。每层包含 256个专家，但单次前向传播只激活其中的 8个。同时，还有一个始终处于激活状态的共享专家。模型仅调用其 3.1% 的专家，整体上只有约 5.4% 的总参数参与计算。

![](https://pica.zhimg.com/v2-b8e9a629eb168f1bdff7ee1421ef1294_r.jpg)

其架构特点如下：

- GLM-5.2 模型的前 3 层 使用标准的稠密 FFN，之后的 75 层 才采用 MoE 结构。这是一个刻意设计，因为早期层处理的是低级的 Token 表示和位置编码，若在此处引入路由的不稳定性，错误会逐层传播，影响后续所有计算。
- IndexShare 机制：GLM-5.2 在 DeepSeek 稀疏注意力（DSA）基础上提出了 IndexShare 机制。DSA 的每层索引器（indexer）负责为每个查询（query）打分并选择最相关的历史 Key-Value 位置，但其计算量随上下文长度呈二次增长，且在每一层都独立运行，开销巨大。IndexShare 的核心观察是：**相邻稀疏层的 Top-K 选择变化很小**。因此，**它每四层稀疏注意力层才计算一次全新的索引器，其余三层直接复用最近一层的索引结果**。在 1M 上下文长度下，这一设计将每 Token 的 FLOPs 降低了 2.9 倍（即减少了约66%的计算量）。
- MTP 层优化：MTP 层在 GLM-5.2 中同时充当内置的“草稿模型”，用于推测解码。GLM-5.2 对 MTP 层做了多项改进，使其在 Coding 场景的消融实验中，这些改进将 MTP 层的接受长度从 4.56 提升至 5.47，增幅约 20%。 <br>

- 支撑 1M 上下文：GLM-5.2 将最大上下文从约 200K 扩展至 1M Token，即在实际长程 Agent 轨迹中稳定可用，而非仅仅在参数层面支持。为此，训练阶段大幅扩展了 1M 上下文下的 Coding Agent 训练数据，覆盖大规模实现、自动化研究、性能优化和复杂调试等场景

![](https://pic4.zhimg.com/v2-c9e8f8287a3dfae33b65b63b041062fd_r.jpg)

![](https://pic2.zhimg.com/v2-3d3f30a7fe870ea52768c7ff57db8c81_r.jpg)

### 2.6 MiniMax M3（428B，2026年6月）

MiniMax M3 共有 428B 总参数，每 token 激活约 23B，激活率约5.4%。共 60 层，hidden size 6144；**前 3 层 dense FFN，后 57 层 MoE**。每层 128 个 routed experts，每 token 激活 top-4，外加 1 个 shared expert；7 个 multi-token prediction 模块，用于增强自回归训练信号。

![](https://picx.zhimg.com/v2-4ea73e49049cd413f25802de54bcfaf1_r.jpg)

M3 的 核心创新为 MSA（MiniMax Sparse Attention）稀疏注意力，旨在从根本上解决全注意力机制计算复杂度随序列长度平方级增长的“先天缺陷”。在 1M 上下文下每 token 计算量仅为上代的 1/20，prefill 加速 9 倍+、decode 加速 15 倍+，且在多数对照实验中能力与全注意力打平。具体如下：

- 两段式结构：MSA将标准注意力拆分为**索引分支**（Index Branch） 和**主分支**（Main Branch），两者分工明确。 <br>

- 硬件友好的算子设计：以 KV 块为外层循环聚合命中的 query（KV outer gather Q），每块只读一次、访存连续，在 M3 的 Head 配比下计算访存比显著优于通行方案，比 Flash-Sparse-Attention 和 flash-moba 快 4 倍以上
- 与 DSA/MoBA 等方案相比，MSA 对 KV 的分块更精确、有效上下文覆盖更高，同时架构更简洁
- 前 3 层用全注意力，第 4–60 层启用 MSA

![](https://pica.zhimg.com/v2-5d29dffabdd761130388056d12be5e16_r.jpg)

而 M3 的 MoE 层的策略如下：

- 专家数量与激活：包含 128 个路由专家，但每个 token 仅激活其中的 Top-4 专家，外加一个共享专家（Shared Expert），确保了极高的参数效率。
- 路由策略：采用了 DeepSeek-V3 风格的 Sigmoid 路由。在计算路由权重时，会引入专家偏置校正（expert-bias correction），并对归一化后的 Top-k 权重应用 routed_scaling_factor，以优化专家负载均衡与路由稳定性。
- 共享专家：M3 使用了一个独立的 SwiGLU-OAI 共享专家，它与路由专家并行工作，负责处理那些需要被所有 token 共同利用的通用知识

M3 并非在所有层都使用 MoE，而是采用了混合设计。整个模型共 60 层，其中前 3 层是密集（Dense）层，从第 4 层开始才引入 MoE 结构。这种“前密后疏”的设计有助于稳定训练初期的基础特征提取。在 MoE Transformer层内部，模型将稀疏注意力路径（MSA）与 MoE 路径（路由专家 + 共享专家）相结合，形成了高效的稀疏计算单元。

为了匹配其架构需求。所有 MLP 和专家都使用一种名为**SwiGLU-OAI 的激活函数**。其公式为 gate * sigmoid(alpha * gate) * (up + beta)，其中 gate 和 up 投影有特定的截断（clamp）操作，这是一种为 MoE 优化过的激活变体。 模型在每个归一化层都采用了 **Gemma 风格的 RMSNorm**，其公式为 x * (1 + w)，权重 w 以 0 为中心进行缩放，有助于提升训练稳定性。

### 2.7 Kimi K3（2.8T，2026年7月）

Kimi K3 是首个达到 2.8T 参数规模的开源模型。每 token 激活约 104B，激活率约 3.7%。每个层共有 896 个路由专家，外加 2 个共享专家。 896 个路由专家中高效激活 16 个(1.8%)。原生支持视觉理解，上下文窗口 100 万 token。

![](https://pica.zhimg.com/v2-90532053d8d39a68692b12ca20ea6f7e_r.jpg)

Kimi K3 的核心架构围绕三项底层创新展开，分别针对 Transformer 在**序列长度、模型深度和专家宽度**上的扩展瓶颈：

- Kimi Delta Attention (KDA) 解决长上下文带来的 KV Cache 膨胀问题；
- Attention Residuals (AttnRes) 重构深层网络的信息流动方式；
- Stable LatentMoE 则在 896 个专家的极端稀疏配置下维持训练的稳定性与硬件效率。

即 K3 = KDA + MLA + Stable LatentMoE + AttnRes，优化器沿用 Moonlight 版 Muon，但注意力权重改为 Per-Head 形式优化。

![](https://pic4.zhimg.com/v2-4136aad41192c5563cfafeafbc9cefc7_r.jpg)

标准 Transformer 的全量 softmax 注意力在百万级上下文下 KV 缓存和计算成本爆炸。Kimi K3 并未完全替换全注意力，而是采用**混合注意力**策略：在 93 层中，69 层使用 KDA，24 层使用 Gated MLA（Multi-head Latent Attention），大致比例为每 3 层 KDA 后插入 1 层 MLA。

- 3 层 KDA：线性注意力，采用 Delta 规则递归更新，并加入通道级门控（channel-wise gating）精细管理递归记忆——精度接近 softmax，但复杂度随序列线性增长
- 1 层 Gated MLA：保留少量全局注意力，处理需要精确长程检索的位置

其效果是：1M 上下文解码加速 6.3 倍，KV 缓存削减 75%。这也让 1M 上下文从"演示功能"变成可实际部署的能力。官方还开源了配套算子 FlashKDA。

传统 MoE 中，Router 选出专家后，系统需要将 Token 的隐藏状态通过 All-to-All 通信发送到对应 GPU。当专家总数和每 token 激活专家数同时增长时，调度与协调开销会急剧上升，传统 MoE 内核难以维持高硬件利用率。专家负载不均衡也会导致部分专家被过度使用或闲置，影响训练稳定性。

LatentMoE 的核心操作是：不直接把完整隐藏状态发送给路由专家，而是先将其投影到更窄的潜在空间。K3 的主隐藏维度为 7168，路由专家则在 3584 维空间中计算，完成后再将结果恢复到完整隐藏维度。数据流为：down_proj → experts → RMSNorm → up_proj。

降维节省下来的计算预算被用于扩大专家池。K3 原本可以采用“448 选 8”的配置，但引入 LatentMoE 后，最终扩展为 “896 选 16”——两者激活比例相同（约 1.8%），但后者拥有更多可组合的专家。模型可以让多个较窄的专家协同处理一个 Token，而不是依赖少数宽专家完成所有变换，专家分工因此变得更加细致。

潜在空间同时也是一道信息瓶颈。为避免压缩造成关键信息损失，K3 保留了 2 个始终参与计算的共享专家，负责处理语言结构、基础语义和常见推理模式，路由专家则集中学习更细分的能力。

此外，主流方案（如 DeepSeek V3 的 Loss-Free Balancing）通过固定步长逐步调整每个专家的路由偏置。当专家数量达到 896、每 Token 仅激活 16 个时，固定步长很难同时兼顾调整速度与稳定性：步长过大导致路由震荡，步长过小则无法及时纠正负载倾斜。

Stable LatentMoE 通过基于分位数的负载均衡策略（Quantile Balancing（QB）），核心思路是不再逐步试探，而是直接根据路由分数的分布计算偏置。每个 Token 从 896 个专家中选择 16 个，加上当前偏置后排名第 17 的分数，可以视为进入前 16 名的门槛。QB 的目标是让每个专家的这个“门槛分位数”与其目标负载相匹配，从而在单次前向传播中推导出分布驱动的调度偏好。

具体实现上，K3 为每个专家维护一个分箱直方图（binned histogram），从中读取所需的分位数，而非收集数百万 Token 的完整路由分数。同时对估计的分位数维护指数移动平均（EMA），以减少批次间的采样噪声，进一步提升负载均衡的精度。

QB 的偏置更新不参与梯度计算，由均衡机制独立维护，因此不会干扰主任务的优化过程。该方法在理论上可实现完美均衡，较 DeepSeek V3 的固定步长调整更具响应性与稳定性。

### 2.8 Qwen3.8-Flash-Next（125B-A6B， 2026年8月）

一款多模态 MoE 模型，共有 125B 总参数，额外配备 51B 的 N-gram Embedding 参数。每 token 激活 6B 参数，激活率 4.8%。它原生支持 262,144 token 上下文，并可通过 YaRN 扩展至 1,000,000 token。

![](https://pic3.zhimg.com/v2-71b935fb793610e206448f67c6ff9c98_r.jpg)

Qwen3.8-Flash-Next 围绕 Attention、Residual、Embedding 和 Optimization 四个方面对模型进行了系统升级，在提升模型能力的同时，进一步优化计算效率、模型容量和训练稳定性：

- Attention：采用 GDN + QSA Hybrid 架构。**Gated DeltaNet（GDN）高效压缩历史信息**；Qwen Sparse Attention（QSA） 通过压缩式轻量 Indexer 在 micro-block 粒度上筛选重要上下文，显著降低长序列 Attention 开销。每四层中三层使用 Gated DeltaNet（GDN），**将历史信息持续压缩到固定大小的状态中**；另一层保留全局 Attention，**负责精确检索全局信息**。
- Residual：引入 Gated Residual（GR），将 Residual Stream 扩展为 4 条分支，并通过动态 Gate 控制信息读写，增强跨层信息传递和训练稳定性。
- Embedding：**引入 N-gram Embedding，利用局部上下文进行查表，以很少的额外计算扩展模型容量**；Embedding Table 可以卸载到 Host Memory，并通过异步 Prefetch 与模型计算重叠。普通 Embedding 根据单个 token 查表；N-gram Embedding 则结合当前 token 与前几个 token 组成的局部上下文进行查表，为常见短语和局部模式提供额外表示。而N-gram Embedding的核心优势是：**可以增加大量参数，同时几乎不增加每个 token 的计算量**。
- Optimization：**采用 Muon Optimizer**，围绕正交化精度、Muon 与 AdamW 的参数分工以及融合参数拆分等策略进一步优化，并针对新架构重新拟合 Scaling Law。
- 模型采用高度稀疏的 MoE 设计。MoE 层**包含 512 个路由专家，采用 top-10 路由，外加 1 个共享专家**。隐藏维度为 2560，Token Embedding 维度为 248,320。
- Multi-Token Prediction: 包含一个 4B 的多 token 预测（MTP）模块用于推测解码加速。MTP 模块以多步方式训练，保持训练与推理之间的一致性，从而提升实用场景下 speculative decoding 的接受率，同时也提升主干本身的性能。其中的**全注意力层同样被替换为 QSA**。
- 训练稳定性: 保留 Zero-Centered RMSNorm 并对 norm weight 施加 **weight decay、注意力输出门控机制，以及 MoE router 参数初始化的归一化**。这些设计使小规模消融结果更为可靠，也有助于大规模训练平稳进行。

![](https://picx.zhimg.com/v2-3fb572f00db975ea36903b7cc3cc8f63_r.jpg)

在 1M token 上，QSA 的 Attention Kernel 在 Prefill 和 Decode 阶段分别实现最高 7.6× 和 4.9× 的加速。在贴近线上高缓存复用场景的实验设定下（Prefix Cache 命中率为 90%），Qwen3.8-Flash-Next 在 1M 上下文下的 Prefill 吞吐达到 Qwen3.7-Plus 的 8.6 倍。

从以上模型的架构分析，可以看到 LLM 的发展趋势：

- 总参数不断膨胀，激活参数相对克制。竞争瓶颈正从算力转向带宽瓶颈。MoE 解耦的是 FLOPs，解耦不了显存。激活参数决定计算速度，总参数却必须完整常驻显存（或被高效地搬进搬出），权重加载的带宽，而非矩阵乘的算力，正成为推理经济性的第一约束。
- 激活率一路下探【15%（Gemma 4）→ 10%（Qwen3）→ 5.4%（GLM-5.2/M3）→ 3.9%（MiMo）→ 3.7%（K3）→ 3.1%（V4-Pro）】，但存在代价曲线，激活率每降一档，路由难度、训练不稳定性都在上升。
- 稀疏化从 FFN 蔓延到全网络。Qwen3 和 Gemma 4 的稀疏化还只作用于 FFN；而 V4、K3、M3、GLM-5.2、Qwen3.8 的注意力层已全部或部分稀疏化。绝大多数层用便宜的稀疏机制（滑窗、块稀疏、线性递归），少数层保留精确的全局注意力负责长程检索。
- MTP逐渐标配化。它同时解决了训练和推理两个环节的效率问题，且不引入额外部署负担。训练测MTP通过让模型在每个位置同时预测未来多个token，提供了更丰富的监督信号，从而提升样本效率，并改善生成任务的下游性能，且这种增益在模型规模更大时更为显著。推理时可以充当自投机解码器（self-speculative decoder）。与需要额外加载独立草稿模型的传统方案不同，MTP的预测头是主模型的一部分，因此没有额外的显存开销，也避免了草稿模型与主模型之间可能存在的分词器不匹配问题。

## 第三章：工程落地——MoE 的隐形成本

参数表上的 MoE 很美好：3% 的激活率，三十倍的成本压缩。但参数表不会告诉你，省下来的 FLOPs 有多少会在别处还回去。工程上的 MoE 要算**通信账和显存账**。

### 3.1 通信账：All-to-All 是新的性能黑洞

专家并行（EP）下，每个 token 要被发送到它命中的专家所在的 GPU，每层 MoE 需要两次 All-to-All 通信（dispatch 与 combine）。通信量随 batch size、hidden size 和 top-k 增长，与模型参数量无关——这意味着**模型越大、切得越碎，通信占比反而越高**，需要 TP/EP/DP 复合并行策略小心平衡。

在 K3 提到：当专家总数和每 token 激活专家数同时增长时，调度与协调开销急剧上升，传统 MoE 内核难以维持高硬件利用率。LatentMoE 的工程动机一半就来自这里——先把 7168 维隐藏状态压到 3584 维再发送，**通信量直接减半**。

负载不均的代价在推理侧更隐蔽：训练时的均衡机制管的是平均利用率，而在线请求是延迟敏感的——个别热门专家所在 GPU 成为拖后腿者（straggler），整个 batch 的延迟被最慢的那颗芯片拖住。解决该问题，需要从模型训练（路由策略） 和系统部署（资源调度） 两个层面双管齐下。核心思路是从静态的、均质的资源分配，转向动态的、感知负载与硬件差异的智能调度。在实际应用中，通常会组合使用多种策略，例如在训练时用辅助损失进行粗粒度平衡，在推理时用动态专家复制或迁移进行细粒度调整。

### 3.2 显存账：总参数决定下限

激活 3% 不等于显存占用 3%。V4-Pro 把磁盘存储压到约 862B 参数的体积，是了不起的工程成就——但完整装载仍需要数百 GB 级显存，消费级显卡与满血推理无缘。

更根本的问题是 Decode 阶段的算术强度：每生成一个 token，都要把激活专家的权重完整读一遍，每个参与参数只做约 2 次 FLOPs。这让推理速度由**显存带宽**而非算力决定。雪上加霜的是 KV cache 与权重的双重挤压：1M 上下文 + 万亿参数，显存被两头拉扯。回头再看，MSA、CSA+HCA、KDA、GDN 这一整代注意力稀疏技术的真实动机，与其说是省计算，不如说是**省显存**。

缓解手段都有代价：专家卸载到 CPU 带来毫秒级延迟惩罚；专家并行切分则放大通信。

## 结语

从 2025 年的 Qwen3-30B-A3B 到 2026 年的 Kimi K3、Qwen3.8-Flash-Next，八款模型串起的不是一条简单的参数膨胀曲线，而是一场围绕“条件计算”的架构革命。MoE 的起点很朴素：把 FFN 拆成专家，让每个 token 只点亮 top-k，从而把总参数与激活参数解耦。但走到万亿参数、百万上下文时，稀疏化早已越出 FFN，蔓延到注意力、残差、嵌入、优化器和推测解码。模型不再是均匀的稠密网络，而是一套按需点亮、动态调度的计算系统。

这场革命也暴露出核心矛盾：总参数决定知识容量，激活参数决定推理成本，但激活率并非越低越好。从 15% 到 3.1%，每降一档，路由难度、训练不稳定性、负载倾斜和通信开销都在上升。参数表上省下的 FLOPs，往往要在 All-to-All 通信、显存带宽、专家调度和 KV cache 上还回去。DeepSeek V4 的 FP4/FP8、Kimi K3 的 LatentMoE 与分位数均衡、GLM-5.2 的 IndexShare、MiniMax M3 的 MSA、Qwen3.8 的 GDN+QSA 与 N-gram Embedding，本质上都在回答同一个问题：如何让万亿参数的知识仓库，在真实硬件上被低成本、低延迟地取用。

因此，MoE 的终局不是“用 3% 的参数跑出 100% 的效果”这么简单。它更像一场从模型架构到推理系统的联合设计：专家要更细，路由要更稳，注意力要更省，MTP 要更准，并行要更均衡，显存要更聪明。谁能算好通信账、显存账和负载账，谁才能把参数规模真正转化为可部署的智能。下一阶段的竞争，或许不再只是比谁更大、谁更稀疏，而是比谁更懂硬件、更懂系统、更懂在稀疏与稳定之间走钢丝。MoE 打开了条件计算的大门，而门后是一整套需要重新计算的工程账本。
