以前用 AI，最多就是回答错了、文章写得不好，改一下就完了。

但现在不一样了。

像 Codex、Claude Code 这类 Agent，已经能连续执行任务、操作文件，甚至调用外部工具。你给它一个目标，它就会自己往下做，不需要每一步都等你指挥。

问题也跟着来了： **如果 AI 自己把事情做坏了，这个责任到底算谁的？**

最近这个问题越来越现实。美国多州针对 OpenAI 提起诉讼，指控其产品存在用户安全方面的问题；与此同时，AI Agent 造成的安全事故，也让保险行业开始重新考虑怎么承保这类风险。相关指控和风险评估仍在发展中，并不代表所有争议都已经有了结论。

我觉得，这其实是 AI 从聊天工具走向执行工具之后，绕不开的一关。

以前 AI 给你一个错误答案，你可以选择不采纳。

但如果你给了 Agent 文件访问权限，它误删了重要文件；或者让它自动执行一项任务，结果操作超出了预期，事情就没那么简单了。

所以我现在越来越觉得， **AI 越能干活，越不能只关注它有多聪明，还得关注它有多大的权限。**

能只读文件，就别随便给修改权限；能先确认再执行，就不要让它直接操作重要数据。涉及生产环境、资金和用户信息的任务，更应该保留人工确认。

还有一个容易忽略的问题，就是成本。

Agent 连续跑任务时，模型调用和工具使用都可能产生费用。如果同时做几个项目，订阅和 API 账单很容易混在一起。我自己会把不同项目的支出分开记，海外工具有时也会用 Core Gold 虚拟卡单独支付，月底核算起来方便一些。

我并不觉得这些问题意味着 Agent 不值得用。

恰恰相反，正是因为它越来越有用，我们才更需要把权限、成本和责任这些事情提前想清楚。

**未来真正成熟的 AI Agent，不应该只是能自己完成任务，还应该让人知道它做了什么、为什么这么做，以及出了问题该怎么处理。**
