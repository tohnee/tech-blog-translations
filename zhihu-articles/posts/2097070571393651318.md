## 引言

> “The Harness of Harnesses.”

这是"一天一个开源项目"系列的 **第 245 篇** 文章。今天带你了解的项目是 **Raven** （EverMind-AI/Raven）。

最近一年，Claude Code、Codex、OpenCode、Hermes Agent 这类 coding / 通用智能体层出不穷，每个都有自己的 harness（循环、工具、记忆、技能的组合方式）。问题随之而来： **这么多智能体，谁来调度它们？谁来决定哪个任务交给哪个？harness 本身又能不能自己变好？**

Raven 给出的定位很直白：它是一个 **Host Agent** ，把内置智能体和第三方智能体组合起来完成复杂任务，并且通过模块化架构，让 harness 本身也成为可以被迭代改进的对象。

- 如何安装并启动 WebUI

## 项目背景

### 项目简介

Raven 自称"面向递归自我改进（RSI）的多智能体生态"。它做三件事：

1. **宿主与编排** ：作为 Host Agent，协调多个智能体、依赖和并行。
2. **自我改进** ：模块化架构允许迭代改进自身 harness——提出改动、评估、采纳通过验证的改进。
3. **持久记忆** ：记忆层由 EverOS 提供，上下文可以跨会话保留。

## 主要功能

### 核心作用

Raven 想解决的是"多智能体怎么组合、harness 怎么变好"这两个问题：一方面把不同智能体当作可组合的能力单元，由 Host 统一调度；另一方面把 Agent loop 里的关键策略拆开，让它们可以被替换、评测和进化，而不是写死在某个产品里。

### 使用场景

1. **自主深度研究** 

- Raven-Research 输出带可追溯来源的结构化报告。

1. **智能体式软件开发** 

- Raven-Code 负责功能实现、调试、重构，以及数据处理与分析。

1. **视觉设计产出** 

- Raven-Design 生成 PPT、品牌素材、图表、网页界面。

1. **无人值守的长时任务** 

- Raven-Oncall 做实验、优化、持续监控，可以持续数小时甚至通宵。

1. **跨智能体协作** 

- 把 Claude Code、Codex 等已有智能体作为第三方 worker 接入，由 Raven 编排。

### 快速开始

最省事的方式是让你已有的智能体帮你装，把下面这句话交给它：

```text
Read https://evermind-ai.github.io/Raven/quick-start/ and follow it to install Raven, or to update it if it is already installed.

```

手动安装：

```text
# Linux / macOS / WSL2
curl -fsSL https://raven.evermind.ai/install.sh | bash

# Windows PowerShell
irm https://raven.evermind.ai/install.ps1 | iex

```

Docker 方式（需要 Git 和 Docker Compose）：

```text
git clone https://github.com/EverMind-AI/Raven.git
cd Raven
docker compose -f docker/docker-compose.yml up
# 然后访问 http://localhost:18793

```

启动 WebUI：

```text
raven web          # 后台运行并打开浏览器
raven web --stop   # 停止

```

WebUI 支持对话、多智能体协作、工作区管理、查看文件与输出、浏览记忆和技能。

> 安装脚本直接运行为可编辑安装；通过管道执行则安装已发布的 wheel。安装时会让你为每个智能体产品选择：使用其调优模型（需要独立密钥），还是使用 Raven 自身配置的 LLM。

### 核心特性

1. **四个内置智能体** 

- Research、Code、Design、Oncall，覆盖研究、开发、设计、长时自动化。

1. **13 个预设第三方智能体** 

- 通过 ACP、CLI 或 OpenAI 兼容 API 接入：Claude Code、Codex、OpenCode、Hermes Agent、OpenClaw、MiroThinker、GitHub Copilot、Qwen Code、CodeBuddy、Qoder、Grok Build、Kimi Code、Pi。

1. **Evolver：评测驱动的 harness 进化** 

- 诊断失败、测试候选改进，只保留优于基线的改动。

1. **运行时自进化（Curator）** 

- 持续改写 Agent loop 的四个策略模块。

1. **EverOS 跨会话记忆** 

- 保存用户上下文、经验与知识。

1. **SkillForge** 

- 从本地库、EverOS 记忆和 SkillHub 检索技能（项目页给出的 SkillHub 规模为 114,190 个技能）。

1. **Proactivity** 

- 事件监控与定时执行，主动提醒和跟进。

1. **Persona** 

- 描述想要的助手，Curator 组装一个主角色加若干专家。

### 项目优势

项目页没有给出与同类项目的正式对比，下面是我基于其定位做的 **定性比较** ，仅供参考：

| 维度 | Raven | 单个编码智能体（如 Claude Code / Codex） |
| --- | --- | --- |
| 定位 | 宿主：编排多个智能体 | 单个智能体产品 |
| harness 可变性 | Agent loop 拆成四个可替换策略模块 | 通常由产品固定 |
| 自我改进 | Evolver 评测驱动，保留优于基线的改动 | 依赖产品方迭代 |
| 记忆 | EverOS 跨会话记忆 | 各产品自带，形态不同 |
| 第三方接入 | 13 个预设，ACP / CLI / OpenAI 兼容 | 通常不以编排其他智能体为目标 |

**为什么值得关注？**

- 它把"harness 是可以被工程化改进的对象"这件事做成了产品形态，而不是停留在论文里。
- 它不要求你放弃手里的 Claude Code / Codex，而是把它们纳入编排。
- 改进有门槛：项目页强调验证前不安装、失败则返工，并且信号通常会剥离参考答案。

## 项目详细剖析

### 整体结构：Host + Workers + 五个系统

Raven 的核心系统可以归纳为五块：

| 系统 | 作用 |
| --- | --- |
| Agent Orchestration | 协调智能体、依赖与并行，沉淀可复用工作流 |
| Evolver | 诊断失败、测试候选改进、保留优于基线的改动 |
| EverOS Memory | 跨会话保存用户上下文、经验与知识 |
| SkillForge | 从本地库、EverOS 记忆及 SkillHub 检索技能 |
| Proactivity | 事件监控与定时执行，主动提醒和跟进 |

### 内置智能体

| 智能体 | 职责 | 项目页提到的评测 |
| --- | --- | --- |
| Raven-Research | 自主深度研究，结构化报告，来源可追溯 | — |
| Raven-Code | 功能实现、调试、重构、数据处理分析 | SWE-bench Pro / Verified、SWE-Refactor；DataAgentBench 上 Opus-5 达到 0.8762 Pass@1 |
| Raven-Design | PPT、品牌素材、图表、网页界面 | 称在 PresentBench 居首 |
| Raven-Oncall | 无人值守工作流自动化，可持续数小时或通宵 | 称在 AI4AI、AI4S 任务上质量和成本均优于 Claude Code |

这些数字来自项目自述，没有经过我独立复现，读者引用前建议回到论文和 benchmarks 目录核对。

共享的 harness 由 **Raven Evolver** 改进。Evolver 是独立工具，以库的方式使用 Raven，用基准评估候选改动。

### Agent loop 的四个解耦模块

这是 Raven 设计里最值得细看的一点。它把 Agent loop 拆成四个策略模块：

- **Memory** ：记什么、怎么取
- **Planning** ：怎么拆解任务
- **Capability** ：有哪些工具、技能
- **Action** ：怎么执行与判断

四块解耦之后，每一块都可以被单独替换和评测。 **Curator** （实验性，随仓库发布，不在安装包内）会持续改写这四处，可以替换工具、技能、流程和判断逻辑。

这和我们在评测系列里反复强调的思路一致：想让一个系统可持续变好，首先要让它的 **可变部分有清晰的边界** ，其次要有 **可信的评测** 来决定改动要不要留下。Raven 的质量保障规则（验证前不安装、失败返工、信号剥离参考答案）本质上就是在给自我改进加评测门控。

### 展示案例

项目页给了三个案例：

1. **THRESHOLD** ：一个 Godot 4 第一人称射击游戏，自主运行约 4 天、42 轮规划/开发/验证，同时产出海报、演示文稿和网站。
2. **Raven RSI** ：对 nanochat 做预训练优化，7 轮共 172 次训练无崩溃，在相同的 20 分钟单 GPU 预算下 `val_bpb` 降低 5.8%；溃坝模拟的超调降低三个数量级；FEA 极限载荷搜索 8 轮二分完成。
3. **产品发布套件** ：网页小游戏（Angry Raven）、16 页概览、中英海报，以及项目 README 本身。

这些是项目方的展示，价值在于说明"长时、多轮、可验证"的任务形态，而不是作为通用性能证明。

### 目录结构

仓库顶层包括 `agents` 、 `benchmarks` 、 `evolver` 、 `experimental` 、 `raven` 、 `plugins-dist` 、 `skills` 、 `ui-tui` 、 `ui-web` 、 `docker` 、 `docs` 、 `schemas` 、 `rpc-schema` 等目录，以及 `AGENTS.md` 、 `CLAUDE.md` 、 `CONTEXT.md` 、 `CONTEXT-MAP.md` 、 `CONTRIBUTING.md` 、 `CHANGELOG.md` 、 `RELEASING.md` 等文件。其中 `experimental` 对应前面提到的实验性能力， `benchmarks` 与 `evolver` 则是自我改进闭环的评测一侧。

### 局限与需要留意的点

- **Curator 为实验性** ，且不在安装包内，自进化的完整能力需要从仓库源码使用。
- **性能数据多来自项目自述** ，需要自行验证在你的任务上的表现。
- **成本** ：多智能体长时运行会叠加模型调用，Oncall 这类通宵任务尤其要提前规划预算。
- **信任边界** ：一键安装脚本是 `curl | bash` 形式，生产环境建议先阅读脚本，或使用 Docker 方式隔离。
- 项目页没有提供配置详解和路线图，深度使用要依赖官方文档。

## 总结与展望

### 核心要点回顾

1. **定位清晰** ：Raven 是 Host Agent，编排内置与第三方智能体，而不是又一个单体智能体。
2. **harness 可进化** ：Agent loop 拆成 Memory / Planning / Capability / Action 四个解耦模块，Evolver 与 Curator 在评测门控下改进它们。
3. **生态完整** ：13 个预设第三方智能体、EverOS 记忆、SkillForge 技能检索、Proactivity 主动执行。
4. **需要审慎看待** ：自进化核心（Curator）仍是实验性，性能数字需要自行验证。

### 适用人群

- 已经在用 Claude Code / Codex 等多个智能体、想把它们统一编排的开发者
- 研究 harness 工程、智能体自我改进（RSI）的研究者和工程师
- 需要长时无人值守任务（实验、监控、批量产出）的团队

### 学习建议

先用 Docker 或安装脚本跑起 `raven web` ，选一个小任务观察 Host 如何调度智能体；再读技术报告和 `evolver` 、 `benchmarks` 目录，理解它如何用评测给自我改进设门槛。
