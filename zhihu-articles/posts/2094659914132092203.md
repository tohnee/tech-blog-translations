### 前言

在学习FlashAttention 的时候发现没有很多复现 FlashAttention 代码的资源，FlashAttention 官方主要是用CUTLASS/CuTe，不少资料也都是主要围绕算法原理的，但到一份实际运行的 CUDA FlashAttention Kernel，中间仍有不少细节需要自己摸索的。本文会配合论文，AI 辅助制作的示意图，讲解如何在 H100 上用手写 CUDA/PTX 实现构建 FlashAttention Forward，聚焦 BF16 Causal Forward。也希望为同样想动手复现 FlashAttention 的读者提供一份参考，本文的 CUDA/PTX 实现已放在 GitHub 仓库 [​fa-h100](https://github.com/jeffaa729/fa-h100/blob/main/kernels/attention/flash_attention/sm90_forward.cu)。

本文会先聚焦一个 Tile 内部的计算与数据布局：Online Softmax 的分块，每个线程如何持有矩阵元素、TMA 如何搬运数据，以及 WGMMA 如何完成 QK 和 PV 两次矩阵乘法。下半部将这些计算模块组织成异步 Pipeline， Warp Specialization、屏障与缓冲区复用、Ping-pong Scheduling，以及数据搬运、矩阵计算和 Softmax 之间的重叠。最后，我们结合实际性能结果，达到FlashAttention 官方的99.1-99.6 %。

### 1. FlashAttention + Attention 基础回顾

先把四代 FlashAttention 回顾：FA1 用 IO-aware Tiling 和 Online Softmax 消除完整中间矩阵的 HBM 往返；FA2 调整 Thread Block / Warp 的分工，减少非 Matmul 工作和线程间通信；FA3 用 Hopper 的 TMA、WGMMA 与 Warp Specialization，把搬运、矩阵乘法和 Softmax 交错起来；FA4 继续优化 Softmax 与调度，并引入面向 Blackwell 的计算和存储机制。我们实现的是 H100 上的 BF16 Causal Forward，以 FA3 的 Hopper 路径为主体，采用部分适合 Hopper 的 FA4 软件策略，但不包含Blackwell 专用的 TMEM、`tcgen05` 或 2-CTA MMA。

先固定一个 Batch、一个 Head，将 Q、K、V 分别看作形状为 $N\times d$ 的矩阵，每一行对应一个 Token 的向量。本实现固定 $d=128$。Query 与 Key 的所有两两点积组成 Score Matrix：

$$ S=QK^T,\qquad S\in\mathbb{R}^{N\times N}. $$

固定的 $\alpha=1/\sqrt{d}=1/\sqrt{128}$，并以 $\mathcal M$ 表示 Causal Mask，得到送入 Softmax 的 Logit Matrix：

$$ \bar S=\alpha S+\mathcal M,\qquad \mathcal M_{ij}=\begin{cases}0,&j\leq i,\\-\infty,&j>i.\end{cases} $$

Softmax 沿 Key 维度逐行计算，随后用归一化权重对 V 加权：

$$ P=\operatorname{softmax}_{\mathrm{row}}(\bar S)\in\mathbb{R}^{N\times N},\qquad O=PV\in\mathbb{R}^{N\times d}. $$

对第 $i$ 个 Query，输出行向量可以展开成：

$$ o_i=\frac{\sum_{j=0}^{i}\exp(\alpha s_{ij})v_j}{\sum_{j=0}^{i}\exp(\alpha s_{ij})}. $$

后文将第一次和第二次 Matmul 简称为“QK 阶段”和“PV 阶段”。在融合 Kernel 中，第二次 Matmul 使用当前块的未归一化权重累加输出分子，归一化留到循环末尾。

加入 Batch 和 Head 维度后，MHA 的数学形状是 $[B,N,H,d]$，LSE 的形状是 $[B,H,N]$，其中`d=128`。Q/K/V/O 使用 BF16，累加和行统计使用 FP32。

Naive 实现把整张 $S=QK^T$ 写到 HBM，Softmax 读出后再写出整个 P，最后算PV 相乘时又把它读回来。仅一张 FP32 Score Matrix，在 $N=8192$ 时就需要 $N^2\times4/2^{20}=256$ MiB。FlashAttention 避免的是完整中间矩阵的 HBM 往返：每次计算一个 Score Tile，立即更新 Online Softmax 状态并累加未归一化的输出，最后统一归一化；Causal Mask 还允许直接跳过完全无效的未来 Key Tile。

### 2. CTA 与 Register Tiling

CTA（Cooperative Thread Array）就是 CUDA 中的一个 Thread Block，其中的线程可以通过 Shared Memory 交换数据，并使用屏障 （Barrier）进行同步。在我们的 Kernel 中，一个 CTA 负责同一 Batch、同一 Query Head 的 128 行 Query，并最终写出 `128×128` 的 Output Tile。CTA 把自己的 Q 读入 Shared Memory，随后每次读入 128 个 Key 和对应的 Value，即固定 Q，沿着 K/V 扫描。这里恰好有三个 128，`BM=128` 是 Query 数，`BN=128` 是一次处理的 Key 数，`D=128` 是每个向量的 Feature 数。注意QK 的结果是 `[Query,Key]`，PV 的结果是 `[Query,Feature]`。Query 和 Key 的 Block 数分别是 $T_r=\lceil N/BM\rceil$、$T_c=\lceil N/BN\rceil$；这里 $T_r,T_c$ 表示 Block 数。用 $a,c$ 标记 Block：$Q^{(a)}\in\mathbb{R}^{B_r\times d}$，$K^{(c)},V^{(c)}\in\mathbb{R}^{B_c\times d}$，于是 $Q^{(a)}(K^{(c)})^T\in\mathbb{R}^{B_r\times B_c}$，输出 Block 则为 $BM\times d$。

下面是整体计算的伪代码，暂不展开线程分工和异步协议：

```cpp
每个 CTA 固定：batch、head、query_start
    Q_tile = Q[query_start : query_start+128, :] // Q0 : 0-127, Q1 : 128-255
    初始化每行的 Softmax 状态
    for 每个K/V tile:
        S = Q_tile @ K_tile.T
        更新指数基准、权重、分母
        用这些权重更新输出分子 U
    O_tile = U / 每行分母

```

注意Causal Mask 让这个循环更短。以 `N=512` 为例，Query 和 Key 各分成四块：Q256–383 只能访问 K0–383，所以 K384–511 整块不必加载。当前实现从对角块开始，逆序访问更早的块：先运行带 Mask 的 Softmax，再进入不需要逐元素 Causal 判断的循环，见下图 ：

到 WGMMA 前，先确定数据的拥有者。我们将每个 CTA 配置为 384 个线程：一个 Producer Warp Group 负责数据搬运，两个 Consumer Warp Group 各计算 64 个 Query Row，并共享 K/V。每个 Consumer 都计算完整的 128 个 Feature，独立保存 Score、Softmax 统计和输出分子 $U$。

`m64n128k16` 为每个 Consumer 产生 $64\times128$ 个 FP32 累加值，分布在 128 个线程中，即每线程 64 个值，源码表示为 `scores[8][8]`。外层索引 `g=0..7` 将 128 列划分为八个 16 列区间，是线程内部的 Register 分组索引。每个 Warp 的 32 个 Lane 则分成八个 Quad，每个 Quad 包含四个相邻 Lane，编号为 `quad=lane/4`。同一 Quad 共同覆盖两行，每个 Lane 持有其中不同的四列。

令 `warp=0..3` 为当前 Consumer 内的 Warp 编号，`lane=0..31` 为 Warp 内的线程编号，则坐标为：

```cpp
int quad = lane / 4;
int r0 = warp * 16 + quad;
int r1 = r0 + 8;
int c  = g * 16 + 2 * (lane & 3);

```

八个 Slot 中，`0,1,4,5` 属于 `r0` 行，`2,3,6,7` 属于 `r1` 行；两行的列坐标均为 `c,c+1,c+8,c+9`。这些坐标相对当前 Consumer，第二个 Consumer 的 CTA 行坐标还需加 64。

### 3. Shared Memory 布局

D128 被拆成两个 D64 Band （HALF_D），每个 Band 保存全部 128 行的半个 Feature 向量。K/V 有两个时间Buffer（STAGES = 2），为异步搬运准备空间。两个 Consumer 则按 Query 行分工。当前实际分配如下：

```cpp
struct SharedStorage {
    alignas(SMEM_ALIGNMENT) bf16 Q[2][BM * HALF_D];
    alignas(SMEM_ALIGNMENT) bf16 K[STAGES][2][BN * HALF_D];
    // O reuses V only after both consumers finish their final PV.
    union {
        alignas(SMEM_ALIGNMENT) bf16 V[STAGES][2][BN * HALF_D];
        alignas(SMEM_ALIGNMENT) bf16 O[2][BM * HALF_D];
    };
};

```

- **Q：`Q[2][BM * HALF_D]`。** 两个 D64 Band，各保存 128 行 Query 的一半 Feature；整个 CTA 只加载一次 Q。
- **K：`K[STAGES][2][BN * HALF_D]`。** `STAGES=2` 表示两个时间 Buffer，每个Buffer保存一个完整的 128×128 Key Tile，用于交替加载和计算；内层 `[2]` 表示两个 D64 Band。
- **V：`V[STAGES][2][BN * HALF_D]`。** 布局与 K 相同，两个时间槽分别保存当前和预取的 Value Tile，供 PV 使用。
- **O：`O[2][BM * HALF_D]`。** 保存归一化并转换为 BF16 的 128×128 Output Tile，供 TMA 写回；通过 Union 复用 V 的空间，在两个 Consumer 完成最后一次 PV 后使用，不额外占用 Shared Memory。

### 4. TMA 数据搬运

![](https://pica.zhimg.com/v2-5608d4dae6b9fbee3882a688179dfb70_r.jpg)

TMA（Tensor Memory Accelerator）是 Hopper 提供的硬件异步搬运机制，可以按 Tile 在 Global Memory 与 Shared Memory 之间传输多维的Tensor，无需线程逐元素计算地址和执行加载。而 Tensor Map 是 TMA 使用的 Descriptor，记录 Tensor 的起始地址、Shape、Byte Stride、搬运 Box 和 Shared Memory Swizzle。Tensor Map 告诉硬件如何跨步读取，并按 SW128 布局写入 Shared Memory，设备端只需指定 Tile 起点和目标地址，即可发起搬运。

原始 Q/K/V 的 Layout 为 `[B,N,H,128]`。为了配合 SW128，我们将 D128 拆成两个 D64 Band，用五维 Tensor Map `[64,N,H,2,B]` 描述，维度按最快到最慢排列。 这里说一下SW128 决定这些数据如何存入 Shared Memory， 对起点按 1024 bytes 对齐、每行 128 bytes 的 Band，每行包含八个 16-byte Chunk，其地址重排为：

```text
physical_chunk = logical_chunk ^ (row & 7);
byte_offset = row * 128 + physical_chunk * 16 + offset_in_chunk;
```

下面是 Host 端 `make_attention_map` 的编码部分 ：

```cpp
CUtensorMap map;
void* address = const_cast<bf16*>(pointer);
const uint64_t global_shape[5] = {
    HALF_D, static_cast<uint64_t>(sequence_length),
    static_cast<uint64_t>(heads), 2, static_cast<uint64_t>(batch_size)
};
const uint64_t global_stride[4] = {
    static_cast<uint64_t>(heads) * D * sizeof(bf16),
    D * sizeof(bf16), HALF_D * sizeof(bf16),
    static_cast<uint64_t>(sequence_length) * heads * D * sizeof(bf16)
};
const uint32_t box_shape[5] = {HALF_D, BM, 1, 2, 1};
const uint32_t element_stride[5] = {1, 1, 1, 1, 1};
const CUresult result = cuTensorMapEncodeTiled(
    &map, CU_TENSOR_MAP_DATA_TYPE_BFLOAT16, 5, address,
    global_shape, global_stride, box_shape, element_stride,
    CU_TENSOR_MAP_INTERLEAVE_NONE, CU_TENSOR_MAP_SWIZZLE_128B,
    promotion, CU_TENSOR_MAP_FLOAT_OOB_FILL_NONE);

```

真正搬运数据的 PTX 是 `cp.async.bulk.tensor.5d.shared::cluster.global.mbarrier::complete_tx::bytes`：根据五维 Tensor Map 异步从 Global 搬到 Shared，完成的字节数归入给定的 `mbarrier`。下面是完整的加载 Helper :

```cpp
template <bool Query = false>
__device__ __forceinline__ void tma_load(
    bf16* destination, const CUtensorMap* map, uint64_t* barrier,
    int token, int head, int batch) {
    constexpr uint64_t cache_hint = Query ? 0x12F0000000000000ULL : 0x14F0000000000000ULL;
    asm volatile(
        "cp.async.bulk.tensor.5d.shared::cluster.global."
        "mbarrier::complete_tx::bytes.L2::cache_hint "
        "[%0], [%1, {0, %3, %4, 0, %5}], [%2], %6;"
        :: "r"(static_cast<uint32_t>(__cvta_generic_to_shared(destination))),
           "l"(map), "r"(barrier_address(barrier)),
           "r"(token), "r"(head), "r"(batch), "l"(cache_hint)
        : "memory");
}

```

参数 `Query` 在编译期选择 L2 Cache Hint：`true` 使用 `0x12F0000000000000ULL`，对应 `EVICT_FIRST`；`false` 使用 `0x14F0000000000000ULL`，对应 `EVICT_LAST`。因为Q 加载到 Shared Memory 后，当前 CTA 不再需要从 Global Memory 重读它，因此选择优先淘汰；K/V 会被不同 Query Tile 的 CTA 重复读取，因此选择尽量保留，而这里设置的是 L2 Eviction Priority。

| 参数 | PTX 操作数 | 作用 |
| --- | --- | --- |
| destination | %0 | Shared Memory 写入起点，例如 shared.K[stage][0] |
| map | %1 | Tensor Map 指针，描述 Global Tensor 地址、Stride、Box 和 Swizzle |
| barrier | %2 | 接收传输完成通知的 Shared Full Barrier |
| token | %3 | Tile 的起始 Token Index |
| head | %4 | 要读取的 Head Index |
| batch | %5 | 要读取的 Batch Index |
| cache_hint | %6 | 编译期选定的 L2 Cache Policy |

`%0` 是 32-bit 的 Shared Address，`%1` 是 64-bit Tensor Map 指针，`%2` 是 Shared Barrier Address，`%3…%5` 是 Tile 坐标，`%6` 是上面说的缓存提示 `cache hint`。

发射前，Producer 用 `mbarrier.arrive.expect_tx` 登记 Arrival 和 32768 个预期完成字节，随后发射 TMA；Consumer 必须等 Full Barrier 完成后才能读取，Q 使用 Evict-first、K/V 使用 Evict-last Hint。我们在第 10 节再解释 Full/Empty Barrier。

### 5. SW128 与 Shared Descriptor

![](https://pic4.zhimg.com/v2-3714037731c32f86049f6c7e29e561ff_r.jpg)

TMA 按 SW128 写入 Sha`red Memory，而WGMMA 必须要用匹配的 Shared Descriptor 读它。一个 D64 Band 的每行有 128 bytes，可以分为八个 16-byte Chunk；当前对齐布局用行号的低三位，对 Chunk 编号做 XOR。Chunk 内的八个 BF16 仍连续，变的是 Chunk 在这一行的位置。Swizzle 通过改变跨行访问的 Bank 分布来减少冲突。

下面两行是 Layout 的等价索引表达式 ：

```cpp
const int physical_chunk = logical_chunk ^ (row & 7);
const int physical_element = row * 64 + (col ^ ((row & 7) << 3));
__device__ __forceinline__ uint64_t encode_descriptor(uint64_t value) {
    return (value & 0x3FFFFU) >> 4U;
}

template <bool MajorMN = false>
__device__ __forceinline__ uint64_t make_smem_descriptor(bf16* pointer) {
    const uint32_t address = static_cast<uint32_t>(__cvta_generic_to_shared(pointer));
    uint64_t descriptor = encode_descriptor(address);
    descriptor |= encode_descriptor(MajorMN ? BN * 128 : 16) << 16U;
    descriptor |= encode_descriptor(1024) << 32U;
    descriptor |= 1ULL << 62U;
    return descriptor;
}

__device__ __forceinline__ uint64_t advance_descriptor(
    uint64_t descriptor, uint32_t offset) {
    return (descriptor & 0xffffffff00000000ULL) | (static_cast<uint32_t>(descriptor) + offset);
}

```

这三个函数分别负责编码 Descriptor 字段、组装完整 Descriptor，以及推进读取位置：

- **`encode_descriptor(value)`**：输入以 Byte 为单位的地址或偏移，保留低 18 位后右移 4 位，转换为 Descriptor 使用的 16-byte 单位。例如，输入 `1024`，输出 `64`。
- **`make_smem_descriptor(pointer)`**：输入 Shared Memory 中某个矩阵 Tile 的指针，输出一个 64-bit WGMMA Shared Descriptor。函数先编码起始地址，再填入 Leading Byte Offset、Stride Byte Offset 和 SW128 模式。
- **`advance_descriptor(descriptor, offset)`**：输入已有 Descriptor 和以 16 bytes 为单位的增量，输出推进后的 Descriptor。

因此，Tensor Map 描述 Global→Shared 的搬运规则，而这里的 Shared Descriptor 描述 WGMMA 如何从 Shared Memory 读取矩阵去计算。

### 6. QK：Shared/Shared WGMMA

![](https://pic2.zhimg.com/v2-e1b275e8ecb0c11a7ec35fa5f4c2a337_r.jpg)

我们用PTX 指令计算矩阵`wgmma.mma_async.sync.aligned.m64n128k16.f32.bf16.bf16` 由一个 Warp Group 的 128 个线程协同执行：两个 BF16 输入，FP32 Accumulation，输出形状 `64×128`，每条指令只沿 Reduction Axis 累加 16 项 ：

```text
wgmma.mma_async.sync.aligned.m64n128k16.f32.bf16.bf16
    {s0, s1, ..., s63}, desc_Q, desc_K,
    ScaleD, 1, 1, 0, 0;
```

| 参数 | 这次 QK 的含义 |
| --- | --- |
| 每线程 64 个输出寄存器 | 看第 2 节 ：每线程持有的 64 个 FP32 累加值，s0 - s63 |
| desc_Q / desc_K | Shared Q 与 Shared K 的 Layout |
| ScaleD | 0：忽略旧 S；1：在旧 S 上累加。它是 MMA Accumulator 控制量，不是 Attention Scale \alpha。 |
| 后面的 1、1 | 两个输入不取负 |
| 最后的 0、0 | 两个输入采用这里的 K-major 解释 |

一个完整 QK Tile 要覆盖 D128，所以需要八条 K16 指令：Band 0 提供 Feature 0–63 的四步，Band 1 再提供 64–127 的四步。两个 Consumer 分别选择 Q 的前后 64 行，但复用同一份 K。每步前进 16 个 BF16 Feature。然后`issue_qk` 把这八条提交成一个异步 Group ：第一次覆盖、后续累加，以及两个 Band 的地址推进 ：

```cpp
__device__ __forceinline__ void issue_qk(
    float (&scores)[GROUPS][8], SharedStorage& shared, int stage, int consumer) {
    fence_scores(scores);
    warpgroup_fence();
    const uint64_t Q0 = make_smem_descriptor(shared.Q[0] + consumer * 64 * HALF_D);
    const uint64_t K0 = make_smem_descriptor(shared.K[stage][0]);
    const uint64_t Q1 = make_smem_descriptor(shared.Q[1] + consumer * 64 * HALF_D);
    const uint64_t K1 = make_smem_descriptor(shared.K[stage][1]);
    wgmma_qk<0>(scores, Q0, K0);
#pragma unroll
    for (int k = 1; k < HALF_D / WGMMA_K; ++k) {
        wgmma_qk<1>(scores, advance_descriptor(Q0, k * 2), advance_descriptor(K0, k * 2));
    }
#pragma unroll
    for (int k = 0; k < HALF_D / WGMMA_K; ++k) {
        wgmma_qk<1>(scores, advance_descriptor(Q1, k * 2), advance_descriptor(K1, k * 2));
    }
    warpgroup_commit();
    fence_scores(scores);
}

```

`fence_scores` 声明编译器 Register 依赖，`warpgroup_fence` 排序硬件操作数访问，`warpgroup_commit` 划定异步组，而`issue_qk` 返回后必须等待相应 WGMMA 完成才能读取 Score。

### 7. Register Softmax

### 7.1 行状态与递推

每行保留一个指数基准、分母 $\ell$ 和输出分子 $U$，不在每块结束时立即归一化。采用 Base-2 坐标：$x_j=\alpha s_j\log_2(e)$，当前基准为 $b$。新块选好基准 $b'$ 后：

$$ \gamma=2^{b-b'},\qquad \widetilde p_j=2^{x_j-b'}, $$

$$ \ell'=\gamma\ell+\sum_j\widetilde p_j,\qquad U'=\gamma U+\sum_j\widetilde p_jv_j. $$

求和只覆盖当前 Key Tile，最后统一做 $O=U/\ell$。$\gamma$ 对同一行的所有 Feature 广播，和固定 Attention Scale $\alpha$ 不同。关键不在于每步做完整的naive Softmax，而在使用同一个基准。

### 7.2 Quad 内归约

记得每个Lane 有2 行，每行32列共64个元素，有一个 Lane 先在自己持有的一行 32 列上求局部最大值，再与同一 Quad 的另外三个 Lane 合并，进行 XOR 1、XOR 2 两次 Shuffle 。比如四个局部最大值 `[4,7,3,6]`，先变成 `[7,7,6,6]`，再变成 `[7,7,7,7]`。注意这里不是直接做整个 Warp 的行归约，因为别的 Quad 对应不同 Query Row。

`__shfl_xor_sync` 从 Lane ID 与 Mask 做 XOR 后的线程读取一个寄存器值。下面摘出第一行的两步归约，第二行执行相同操作：

```cpp
current_max[0] = fmaxf(current_max[0], __shfl_xor_sync(0xffffffff, current_max[0], 1));
current_max[0] = fmaxf(current_max[0], __shfl_xor_sync(0xffffffff, current_max[0], 2));
current_max[1] = fmaxf(current_max[1], __shfl_xor_sync(0xffffffff, current_max[1], 1));
current_max[1] = fmaxf(current_max[1], __shfl_xor_sync(0xffffffff, current_max[1], 2));

```

### 7.3 指数指令与原位更新

PTX `ex2.approx.ftz.f32` 计算近似 FP32 $2^x$。`scale_log2 = scale * LOG2E` 完成换底，`row_max` 保存 Raw-score 单位的基准，FMA 准备指数，`fast_exp2` 把原 Score 原位改成 FP32 未归一化权重：

```cpp
__device__ __forceinline__ float fast_exp2(float value) {
    float result;
    asm("ex2.approx.ftz.f32 %0, %1;" : "=f"(result) : "f"(value));
    return result;
}

// Excerpt from online_softmax: overwrite one score with its weight.
const float exponent = __fmaf_rn(
    scores[group][item], scale_log2, -maximum_scaled[row_id]);
scores[group][item] = fast_exp2(exponent);

```

`"=f"` 表示写入 FP32 Register，`"f"` 表示读取；`__fmaf_rn` 将乘加合成一次舍入。对角 Tile 的未来 Key 使用无效 Score ，使其指数为 0。

### 7.4 条件重缩放

基准不必每轮都等于真实最大值 x_max。本实现仅在候选基准比旧基准高出 8 个 Log2 Unit 时更新，否则保留旧基准，令 `previous_scale=1`，不用重复一直更新基准，跳过不必要的 U 缩放。比如现在基准 10、有新 max =12 时也不更新，要到候选 20 时才更新：

```cpp
float next_max[2] = {current_max[0], current_max[1]};
#pragma unroll
for (int r = 0; r < 2; ++r) {
    previous_scale[r] = 1.0F;
    if constexpr (!First) {
        const float change = (row_max[r] - next_max[r]) * scale_log2;
        if (change >= -8.0F) next_max[r] = row_max[r];
        else previous_scale[r] = fast_exp2(change);
    }
}

```

分母可在 Softmax 中先修正，U 则必须等正在写它的 PV 完成后再缩放，具体顺序见第 12 节。

### 8. 概率打包与 PV

![](https://pic3.zhimg.com/v2-d7b42c6bce43f725d7a6969cbb731a66_r.jpg)

QK 完成后，Softmax 按第 2 节的坐标做 Mask 和行归约，再把 Score Register 原位变成 FP32 指数权重。PV 选择的是 BF16 输入 WGMMA，因此必须把这些权重再转换为 BF16 Pair。`__floats2bfloat162_rn(a,b)` 按 Round-to-nearest-even 转换两个数，a 放低 16 bits，b 放高 16 bits；把结果作为 `uint32_t` 传入 PTX。例如 1.0 和 2.0 的 BF16 位模式分别是 0x3f80、0x4000，Pair 是 0x40003f80。

```cpp
__device__ __forceinline__ void pack_probabilities(
    uint32_t (&P)[GROUPS][4], const float (&scores)[GROUPS][8]) {
#pragma unroll
    for (int group = 0; group < GROUPS; ++group) {
#pragma unroll
        for (int pair = 0; pair < 4; ++pair) {
            const __nv_bfloat162 packed = __floats2bfloat162_rn(
                scores[group][pair * 2], scores[group][pair * 2 + 1]);
            P[group][pair] = *reinterpret_cast<const uint32_t*>(&packed);
        }
    }
}

```

PV 矩阵乘也使用 `m64n128k16` 指令。PV 同样由一个 Warp Group 的 128 个线程协同执行，使用 BF16 输入、FP32 Accumulation。与 QK 不同，左操作数是 Register 中打包后的指数权重，右操作数是 Shared Memory 中的 V。每条指令产生 64×128 的输出，并沿 Key Token 轴累加 16 项：

```text
wgmma.mma_async.sync.aligned.m64n128k16.f32.bf16.bf16
    {u0, u1, ..., u63}, {p0, p1, p2, p3}, desc_V,
    1, 1, 1, 1;
```

| 参数 | 这次 PV 的含义 |
| --- | --- |
| 每线程 64 个输出寄存器 | u0–u63 保存当前线程持有的 64 个 FP32 输出累加值 |
| p0–p3 | 四个 32-bit Register，每个打包两个 BF16 权重，共八个值，采用 WGMMA 要求的 A Operand Layout |
| desc_V | Shared V 的起始地址与 Layout |
| 第一个 1 | ScaleD=1，将当前乘积累加到已有 U；首次 PV 前，U 已初始化为零 |
| 随后的 1、1 | 两个输入不取负 |
| 最后的 1 | transB=1，按这里的 MN-major 布局读取 V，无需生成转置后的 V |

一次指令完成的更新可以写为：

$$ U_{64\times128} \leftarrow U_{64\times128} + \widetilde P_{64\times16}V_{16\times128}. $$

这里的 $\widetilde P$ 是当前 Tile 的未归一化指数权重，因此 U 累加的是输出分子，最终再除以 Softmax 分母。

一个完整 PV Tile 要覆盖 BN=128 个 Key Token，所以同样需要八条 K16 指令，每次选择 16 列权重和 V 中对应的 16 行。对应的 `issue_pv` :

```cpp
__device__ __forceinline__ void issue_pv(
    float (&output)[GROUPS][8], uint32_t (&P)[GROUPS][4],
    SharedStorage& shared, int stage) {
    fence_scores(output);
    fence_probabilities(P);
    warpgroup_fence();
    const uint64_t V = make_smem_descriptor<true>(shared.V[stage][0]);
#pragma unroll
    for (int k = 0; k < BN / WGMMA_K; ++k) {
        wgmma_pv(output, P[k],
            advance_descriptor(V, k * WGMMA_K * HALF_D * sizeof(bf16) / 16));
    }
    warpgroup_commit();
    fence_scores(output);
    fence_probabilities(P);
}

```

| 同一条指令的局部轴 | QK | PV |
| --- | --- | --- |
| M=64 | Query Row | Query Row |
| N=128 | Key Token | Output Feature |
| K=16 | Feature | Key Token |
| 输入位置 | Shared / Shared | Register / Shared |

### 9. Warp Specialization

![](https://picx.zhimg.com/v2-af4afe41ffe914865585fef540d6abd1_r.jpg)
*FA4 原文的forward pipeline*

### 9.1 三层重叠

第一种重叠发生在搬运与计算之间：因为Shared Memory 的两个时间 Buffer，Producer 在发射 TMA，Consumer 可使用另一槽已经就绪的 Buffer里的数据。

第二种发生在两个 Consumer 之间：C0 做 Softmax 时，C1 可以提交自己的 GEMM，这叫 Ping-pong Scheduling。

第三种发生在同一个 Consumer 内：先提交下一块 QK，再提交当前块 PV；只等 QK 完成，就开始下一块 Softmax，让它与尚未结束的 PV 重叠。

### 9.2 Register 配额

384 个线程分成三个 Warp Group，每组 128 个线程。Producer 主要维护地址、槽号和 Barrier，不需要像 Consumer 那样同时保存 64 个 Score、64 个 Output Accumulator 和打包的 P。Hopper 的 `setmaxnreg` 可以动态改变线程的 Register 上限：`dec` 释放配额，`inc` 请求配额。比如这里 Producer 降到每线程 24，Consumer 提高到每线程 240。

```cpp
const int group = threadIdx.x / 128;
const int tid = threadIdx.x % 128;

// Excerpt: role-specific register budgets.
if (group == 0) {
    asm volatile("setmaxnreg.dec.sync.aligned.u32 24;");
    // The producer branch runs here, then returns.
    return;
}
asm volatile("setmaxnreg.inc.sync.aligned.u32 240;");

```

### 10. 异步同步协议

代码里要有三套不能互相替代的同步机制。`mbarrier` 回答“这一buffer有没有装好、能不能覆盖”，Named Barrier 回答“两个 Consumer 谁先提交、谁需要等谁”，WGMMA Wait 回答“本组发射的矩阵计算完成到哪里了”。

| 机制 | 等待对象 | 本实现中的作用 |
| --- | --- | --- |
| mbarrier | Arrival 与异步 Transaction Bytes | Q/K/V 就绪、K/V 槽回收 |
| bar.sync / bar.arrive | 指定数量线程的到达 | Consumer 交接、Epilogue 汇合 |
| wgmma.wait_group | 本 Warp Group 的已提交 MMA Group | 安全读取 S、修改 U、复用 P/V |

### 10.1 Full/Empty 与 Transaction Bytes

每个 K 和 V Buffer都有独立的 Full/Empty Barrier。Full 的 Arrival Count 为 1，因为只有一个 Producer 登记这次加载，同时声明预期的完成字节数量。Empty 的 Count 为 2，因为 C0、C1 都可能还在读这一个Buffer，每组由 `tid==0` 归还一次，收到两次归还才允许覆盖新的数据到一个Buffer。

`mbarrier.init` 设置每一代所需的到达次数，`mbarrier.arrive` 归还一次到达，`mbarrier.arrive.expect_tx` 则把一次到达和预期事务字节登记合并。

```cpp
__device__ __forceinline__ void barrier_init(uint64_t* barrier, uint32_t arrivals) {
    asm volatile("mbarrier.init.shared::cta.b64 [%0], %1;"
        :: "r"(barrier_address(barrier)), "r"(arrivals) : "memory");
}

__device__ __forceinline__ void barrier_arrive(uint64_t* barrier) {
    asm volatile("mbarrier.arrive.release.cta.shared::cta.b64 _, [%0];"
        :: "r"(barrier_address(barrier)) : "memory");
}

__device__ __forceinline__ void barrier_expect_bytes(uint64_t* barrier, uint32_t bytes) {
    asm volatile("mbarrier.arrive.expect_tx.release.cta.shared::cta.b64 _, [%0], %1;"
        :: "r"(barrier_address(barrier)), "r"(bytes) : "memory");
}

```

### 10.2 Ring Buffer与 Parity

![](https://picx.zhimg.com/v2-d0884bbabae9f7c9659283bcaeb553c7_r.jpg)

同一个地址会反复装入不同 Tile，所以“这个 Barrier 曾经完成过”还不够，必须知道等的是哪一代。`stage` 选择 Buffer 的 Shared 地址，`phase` 保存这次等待的奇偶代次。两个槽按 `(0,0) → (1,0) → (0,1) → (1,1)` 轮换；回到Buffer 0 时才翻转 Parity， 而Full 和 Empty 是不同 Barrier，各自按协议推进。

```cpp
__device__ __forceinline__ void advance_stage(int& stage, int& phase) {
    if (++stage == STAGES) {
        stage = 0;
        phase ^= 1;
    }
}
__device__ __forceinline__ void barrier_wait(uint64_t* barrier, int phase) {
    asm volatile(
        "{ .reg .pred done;\n"
        "mbarrier.try_wait.parity.acquire.cta.shared::cta.b64 done, [%0], %1;\n"
        "@done bra wait_done_%=;\n"
        "wait_loop_%=:\n"
        "mbarrier.try_wait.parity.acquire.cta.shared::cta.b64 "
        "done, [%0], %1, 0x989680;\n"
        "@!done bra wait_loop_%=;\n"
        "wait_done_%=:\n}"
        :: "r"(barrier_address(barrier)), "r"(phase) : "memory");
}

```

### 10.3 初始化与可见性

在分支之前，全 CTA 先建立 Shared Storage 与 Barrier。Barrier 初始化后用 `fence.proxy.async.shared::cta` 建立对 Async Proxy 的可见性顺序，再用 `__syncthreads()` 让全部 384 个线程越过初始化边界。

```cpp
extern __shared__ __align__(16) unsigned char storage[];
const uint32_t address = static_cast<uint32_t>(__cvta_generic_to_shared(storage));
const uint32_t aligned = (address + SMEM_ALIGNMENT - 1) & ~(SMEM_ALIGNMENT - 1);
auto& shared = *reinterpret_cast<SharedStorage*>(__cvta_shared_to_generic(aligned));
__shared__ __align__(8) uint64_t query_full, k_full[STAGES], v_full[STAGES],
    k_empty[STAGES], v_empty[STAGES];

if (threadIdx.x == 0) {
    asm volatile("prefetch.tensormap [%0];" :: "l"(&Q_map) : "memory");
    asm volatile("prefetch.tensormap [%0];" :: "l"(&K_map) : "memory");
    asm volatile("prefetch.tensormap [%0];" :: "l"(&V_map) : "memory");
    asm volatile("prefetch.tensormap [%0];" :: "l"(&O_map) : "memory");
    barrier_init(&query_full, 1);
#pragma unroll
    for (int s = 0; s < STAGES; ++s) {
        barrier_init(&k_full[s], 1);
        barrier_init(&v_full[s], 1);
        barrier_init(&k_empty[s], 2);
        barrier_init(&v_empty[s], 2);
    }
    asm volatile("fence.proxy.async.shared::cta;" ::: "memory");
}
__syncthreads();

```

### 10.4 WGMMA Fence、Commit 与 Wait

`wgmma.fence.sync.aligned` 为先前 Register 访问与后续 WGMMA 建立顺序；`wgmma.commit_group` 将已发射的 MMA 划为一组；`wgmma.wait_group` 等待已提交组，只允许给定数量的较新组仍未完成。

```cpp
__device__ __forceinline__ void fence_scores(float (&scores)[GROUPS][8]) {
#pragma unroll
    for (int g = 0; g < GROUPS; ++g) {
#pragma unroll
        for (int i = 0; i < 8; ++i)
            asm volatile("" : "+f"(scores[g][i]) :: "memory");
    }
}

__device__ __forceinline__ void warpgroup_fence() {
    asm volatile("wgmma.fence.sync.aligned;" ::: "memory");
}

__device__ __forceinline__ void warpgroup_commit() {
    asm volatile("wgmma.commit_group.sync.aligned;" ::: "memory");
}

template <int Pending>
__device__ __forceinline__ void warpgroup_wait() {
    asm volatile("wgmma.wait_group.sync.aligned %0;" :: "n"(Pending) : "memory");
}

```

`wgmma.commit_group` 只是把已发射的 MMA 划为一组，`warpgroup_wait<0>()` 才等待全部已提交组完成。

### 11. 加载与流水线启动

### 11.1 Producer 加载顺序

上文说了 Q 在这个 CTA 内不变，只加载一次，K/V 则逆序扫描。Consumer 先用 K 算 QK，经过 Softmax 后再需要 V，因此 Producer 是先准备 `K3`，再按 `K2,V3,K1,V2,K0,V1,V0` 发射。这样给下一轮 QK 提前准备了 K，同时独立的 K/V Empty Barrier 仍限制各自槽位的复用。

下面是 Producer 中 `tid==0` 的实际主体。先装 Q 和首块 K，再在循环里为下一块 K 选择 `next_stage`，最后装当前 V。

```cpp
barrier_expect_bytes(&query_full, 2 * TMA_TILE_BYTES);
tma_load<true>(shared.Q[0], &Q_map, &query_full, start, head, batch);
int stage = 0, phase = 0;
barrier_wait(&k_empty[stage], phase);
barrier_expect_bytes(&k_full[stage], KV_TRANSACTION_BYTES);
tma_load(shared.K[stage][0], &K_map, &k_full[stage], start, kv_head, batch);
#pragma unroll 2
for (int iteration = 0; iteration <= query_block; ++iteration) {
    const int token = (query_block - iteration) * BN;
    int next_stage = stage, next_phase = phase;
    advance_stage(next_stage, next_phase);
    if (iteration < query_block) {
        barrier_wait(&k_empty[next_stage], next_phase);
        barrier_expect_bytes(&k_full[next_stage], KV_TRANSACTION_BYTES);
        tma_load(shared.K[next_stage][0], &K_map, &k_full[next_stage],token - BN, kv_head, batch);
    }
    barrier_wait(&v_empty[stage], phase);
    barrier_expect_bytes(&v_full[stage], KV_TRANSACTION_BYTES);
    tma_load(shared.V[stage][0], &V_map, &v_full[stage], token, kv_head, batch);
    stage = next_stage;
    phase = next_phase;
}

```

### 11.2 Consumer 启动协议

启动时还没有任何“旧 Tile”可消费，也没有 Consumer 自然归还过槽位。代码先让 C0 向自己的 Scheduler Barrier 预到达，再由 C0/C1 各自的 `tid==0` 对所有 K/V Empty Barrier 到达一次：每个 Empty 收到两次到达，Producer 的第一次等待才能放行。

```cpp
if (group == 1) asm volatile("bar.arrive 1, 256;" ::: "memory");
if (tid == 0) {
#pragma unroll
    for (int s = 0; s < STAGES; ++s) {
        barrier_arrive(&k_empty[s]);
        barrier_arrive(&v_empty[s]);
    }
}
barrier_wait(&query_full, 0);

```

接下来两组CTA 各自计算首块 QK。第一次 MMA 使用 `ScaleD=0` 覆盖 Score Register，因此 `scores` 无须先清零，O 却要从零开始，因为 PV 使用累加模式。首块完成后就释放 K，再执行带 Causal Mask 的 Softmax 并打包 P 回BF16。

```cpp
const int consumer = group - 1;
const int query_start = start + consumer * 64;
float O[GROUPS][8] = {};
uint32_t P[GROUPS][4];
float row_max[2] = {-FLT_MAX, -FLT_MAX}, row_sum[2] = {}, factor[2];
const float scale_log2 = scale * LOG2E;
int stage = 0, phase = 0;
barrier_wait(&k_full[stage], phase);
float scores[GROUPS][8];
issue_qk(scores, shared, stage, consumer);
warpgroup_wait<0>();
if (tid == 0) barrier_arrive(&k_empty[stage]);
online_softmax<true, true>(scores, row_max, row_sum, factor, query_start, start, tid, scale_log2);
pack_probabilities(P, scores);
int value_stage = stage, value_phase = phase;
advance_stage(stage, phase);

```

### 12. Consumer 主循环

### 12.1 Consumer Ping-pong

![](https://pic1.zhimg.com/v2-cd46b6a15568530df1168fbf46454216_r.jpg)
*FA3 原文的 Pingpong scheduling*

FA3 提出的 Ping-pong 使两个 Consumer 错开提交矩阵计算与执行 Softmax 的窗口，它们各自拥有 Query 行和 Register 状态，之后还可以叠加同一 Consumer 内的 QK/PV 重叠。

当 C0 的 `group=1`，它等 Barrier 1，发出 QK/PV 后向 Barrier 2 到达，C1 的 `group=2`，恰好反过来。启动阶段 C0 的预到达提供 Barrier 1 的前 128 次，C0 第一次 `bar.sync` 再提供后 128 次，因此它可以先进入。C1 则等 C0 的交棒。之后两边交替。

### 12.2 QK(next) 与 PV(current)

![](https://picx.zhimg.com/v2-7aa0de3541aca5f19545e15545c39a61_r.jpg)
*FA3 原文的 2-stage WGMMA-softmax pipelining*

把注意力暂时收回到同一个 Consumer。当前 P 已经准备好，下一块 K 也可以加载到另一槽，于是先发射 `QK(next)`，再发射 `PV(current)`，分别 Commit 成两组 WGMMA。这样 `wait_group<1>` 可以只保证较早的 QK 完成，留下较新的 PV 仍在进行。接下来 CUDA Core/SFU 就能处理新 Score 的 Softmax，不必先等 PV。下面`issue_qk` 与 `issue_pv` 各自在内部执行一次 `wgmma.commit_group`，所以第一次 Wait 时最多有两个相关 Group：较早的 QK 和较新的 PV。`wait<1>` 之后可以读取 `next_scores`、归还 K，直到 `wait<0>` 之后，才能归还 V、覆盖旧 P、修改 O。

```cpp
#pragma unroll 1
for (int iteration = 1; iteration <= query_block; ++iteration) {
    if (consumer == 0) barrier_wait(&k_full[stage], phase);
    float next_scores[GROUPS][8];
    asm volatile("bar.sync %0, 256;" :: "r"(group) : "memory");
    issue_qk(next_scores, shared, stage, consumer);
    if (consumer == 0) barrier_wait(&v_full[value_stage], value_phase);
    issue_pv(O, P, shared, value_stage);
    asm volatile("bar.arrive %0, 256;" :: "r"(3 - group) : "memory");
    warpgroup_wait<1>();
    if (tid == 0) barrier_arrive(&k_empty[stage]);
    online_softmax<false, false>(next_scores, row_max, row_sum, factor,
        query_start, (query_block - iteration) * BN, tid, scale_log2);
    warpgroup_wait<0>();
    if (tid == 0) barrier_arrive(&v_empty[value_stage]);
    pack_probabilities(P, next_scores);
    scale_output(O, factor);
    value_stage = stage;
    value_phase = phase;
    advance_stage(stage, phase);
}

```

### 12.3 延迟 Rescale 与 Register 生命周期

下一块 Softmax 已经选好了新基准，并更新了 `row_max` 和 `row_sum`，但当前 PV 仍使用旧 P，向 U 加入**旧基准下**的贡献。因此在短暂的重叠窗口中，行统计已经处于新基准，U 尚处于旧基准，在旧 PV 完成之后会统一修正整个 U，再让下一块 PV 累加。

缩放 Helper 先用 `__any_sync` 做 Warp 一致的判断：只要本 Warp 有任意行的 Factor 不为 1，所有 Lane 都进入循环，未改变基准的行仍然只是乘 1。如果所有行都保留旧基准，整个循环跳过。`(item & 2) >> 1` 选择当前 Slot 属于线程持有的哪一行，与第 2 节的 Accumulator Layout 保持一致。

```cpp
__device__ __forceinline__ void scale_output(
    float (&output)[GROUPS][8], const float (&factor)[2]) {
    if (!__any_sync(0xffffffff, factor[0] != 1.0F || factor[1] != 1.0F)) return;
#pragma unroll
    for (int group = 0; group < GROUPS; ++group) {
#pragma unroll
        for (int item = 0; item < 8; ++item)
            output[group][item] *= factor[(item & 2) >> 1];
    }
}

```

### 13. 收尾与输出写回

### 13.1 最后一次 PV

循环结束时，最后一块 P 只是准备好了，最后一次 PV 还没执行。因此 Drain 必须单独补上这次 PV。如果总共只有一个 KV Block，稳态循环执行零次，同一段 Drain 仍能正确完成输出。`finalize_rows` 只读行统计，不读 O，所以可以在最后 PV 运行时先做 Quad 归约、Reciprocal 和 LSE。

```cpp
barrier_wait(&v_full[value_stage], value_phase);
issue_pv(O, P, shared, value_stage);
float inverse[2], lse_values[2];
finalize_rows(inverse, lse_values, row_max, row_sum, scale);
warpgroup_wait<0>();
if (tid == 0) barrier_arrive(&v_empty[value_stage]);

```

### 13.2 行归约与 stmatrix

循环结束时，每个 Lane 仍只有自己负责列的 Partial Row Sum，先通过 Quad 内 XOR 1、XOR 2 合并，再求倒数。比如 `[1,2,3,4]` 先变成 `[3,3,7,7]`，再变成[`10,10,10,10]`。归约前四个 Lane 分别保存 $\ell$ 的一部分，归约后才各自得到完整的行分母。

这里的 `row_max` 是最终保留的 Raw-score 基准，$\ell$ 是与它匹配的完整行和。

```cpp
__device__ __forceinline__ void finalize_rows(
    float (&inverse)[2], float (&lse_values)[2],
    const float (&row_max)[2], float (&row_sum)[2], float scale) {
#pragma unroll
    for (int r = 0; r < 2; ++r) {
        row_sum[r] += __shfl_xor_sync(0xffffffff, row_sum[r], 1);
        row_sum[r] += __shfl_xor_sync(0xffffffff, row_sum[r], 2);
    }
#pragma unroll
    for (int r = 0; r < 2; ++r) {
        asm("rcp.approx.ftz.f32 %0, %1;"
            : "=f"(inverse[r]) : "f"(row_sum[r]));
        lse_values[r] = row_max[r] * scale + __logf(row_sum[r]);
    }
}

```

输出时，先将 U 乘行倒数并转成 BF16，再用 `stmatrix.sync.aligned.x4.m8n8.shared.b16` 写入 Shared O。这条指令让整个 Warp 协作存下四个 8×8 元素矩阵，在这里，它把分散的 Register Fragment 重排成 TMA 所需的 Shared Layout。最后由 Shared-to-global TMA 写回整块 O，LSE 则由每个 Quad 的一个 Lane 单独写回。写 Shared O 前必须确保两个 Consumer 都不再读 V，TMA 读 O 前也必须确保所有 O 都已写好 ：

```cpp
uint32_t packed[4];
#pragma unroll
for (int pair = 0; pair < 4; ++pair) {
    const int r = pair & 1;
    const __nv_bfloat162 value = __floats2bfloat162_rn(
        accumulator[g][pair * 2] * inverse[r],
        accumulator[g][pair * 2 + 1] * inverse[r]);
    packed[pair] = *reinterpret_cast<const uint32_t*>(&value);
}
const int local_row = (start % BM) + (tid >> 5) * 16 + (lane & 15);
const int column = g * 16 + (lane >> 4) * 8;
const int offset = local_row * HALF_D
    + ((column % HALF_D) ^ ((local_row & 7) << 3));
const uint32_t address = static_cast<uint32_t>(
    __cvta_generic_to_shared(shared.O[column / HALF_D] + offset));
asm volatile(
    "stmatrix.sync.aligned.x4.m8n8.shared.b16 [%0], {%1, %2, %3, %4};"
    :: "r"(address), "r"(packed[0]), "r"(packed[1]),
       "r"(packed[2]), "r"(packed[3]) : "memory");

```

### 13.3 Shared O 与 TMA Store

输出阶段复用 V 的 Shared 区域，因此还需要两个不同边界。第一个 `bar.sync 3, 256` 保证两组 Consumer 的最后一次 PV 都结束，快的一组不能覆盖慢的一组仍在读取的 V。写好 Shared O 后，各线程执行 `fence.proxy.async.shared::cta`，再经过第二个同 ID 的 Barrier，保证选中的 TMA Issuer 不会读到只写了一半的 O。Barrier 完成后会进入下一轮，所以同一个 ID 可以用于这两个先后发生的汇合。

`store_output` 内部使用上面的 `stmatrix` 完成 Register 到 SW128 Shared O 的重排。下面继续接上真实的 TMA 写回代码：Bulk Copy 的 Commit/Wait 与 WGMMA Group 是两套独立机制。`cp.async.bulk.wait_group.read 0` 等待 Copy 读完 Shared Source，保护 CTA 结束时的源存储 Lifetime，它不是给任意其他 CTA 发送“Global O 已可无同步读取”的信号，输出仍依赖正常的 Kernel/Stream 顺序交给后续工作。

```cpp
asm volatile("bar.sync 3, 256;" ::: "memory");
store_output(shared, logsumexp, O, inverse, lse_values,
    batch, head, query_start, sequence_length, query_heads, tid);
asm volatile("fence.proxy.async.shared::cta;" ::: "memory");
asm volatile("bar.sync 3, 256;" ::: "memory");
if (group == 1 && tid == 0) {
    asm volatile(
        "cp.async.bulk.tensor.5d.global.shared::cta.tile.bulk_group "
        "[%0, {0, %2, %3, 0, %4}], [%1];"
        :: "l"(&O_map),
           "r"(static_cast<uint32_t>(__cvta_generic_to_shared(shared.O[0]))),
           "r"(start), "r"(head), "r"(batch) : "memory");
    asm volatile("cp.async.bulk.commit_group;" ::: "memory");
    asm volatile("cp.async.bulk.wait_group.read 0;" ::: "memory");
}

```

### 14. CTA 调度与 Kernel 启动

### 14.1 Tensor Map 与缓存策略

Q/O Map 使用 Hq，K/V Map 使用 Hkv，当前 Q/K/V 的 TMA L2 Promotion 为 256 bytes，Output Map 保留默认策略。

```cpp
constexpr auto promotion = CU_TENSOR_MAP_L2_PROMOTION_L2_256B;
const CUtensorMap Q_map = make_attention_map(
    query, batch_size, sequence_length, query_heads, promotion);
const CUtensorMap K_map = make_attention_map(
    key, batch_size, sequence_length, key_value_heads, promotion);
const CUtensorMap V_map = make_attention_map(
    value, batch_size, sequence_length, key_value_heads, promotion);
const CUtensorMap O_map = make_attention_map(
    output, batch_size, sequence_length, query_heads);

```

### 14.2 Head Section

Head Section 使用 32 MiB 的 K/V Working-set Budget，先估算能容纳多少 KV Head，向下取 Power of Two，再乘 GQA 的 Query/KV Head 比例，避免把希望复用的 K/V 挤出缓存。

```cpp
const int kv_head_bytes = sequence_length * 2 * D * sizeof(bf16);
const int kv_head_capacity = 32 * 1024 * 1024 / kv_head_bytes;
int section_heads = 1;
while (section_heads * 2 <= kv_head_capacity) section_heads *= 2;
section_heads *= query_heads / key_value_heads;
if (section_heads > batch_size * query_heads)
    section_heads = batch_size * query_heads;

```

固定 MHA 的话 `B=4,Hq=Hkv=8,D=128` 下，T=8192 的一个 KV Head 包含 K 和 V，共 $8192\times2\times128\times2=4194304$ bytes，即 4 MiB，得到 `section_heads=8`。每个 Head 有 64 个 Query Tile，总 Grid 是 $4\times8\times64=2048$ 个 CTA，分成四个 Section。

### 14.3 LPT 映射

同步解决了 CTA 内部的数据依赖，但不同 CTA 的工作量仍不一样。Query Block 0 只访问一个 KV Block，Query Block 63 却要访问 64 个。若把长任务集中到尾部，其他 SM 已经结束时，最后几块还可能在扫描长 KV。这里采用 FA4 的 Longest-processing-time-first 思路，在每个 Head Section 内把 Query Block 逆序编号，同时交错相邻 Head，兼顾长任务优先和 K/V 的 L2 局部性。

```cpp
const int query_blocks = (sequence_length + BM - 1) / BM;
const int section_tiles = section_heads * query_blocks;
const int section = blockIdx.x / section_tiles;
const int section_tile = blockIdx.x % section_tiles;
const int query_block = query_blocks - 1 - section_tile / section_heads;
const int head_batch = section * section_heads + section_tile % section_heads;
const int start = query_block * BM;
const int head = head_batch % query_heads;
const int batch = head_batch / query_heads;
const int kv_head = head / (query_heads / key_value_heads);

```

用较小的四个 Query Block、两个 Head 举例，逻辑顺序从 `(Q3,H0),(Q3,H1)` 开始，再到 Q2、Q1、Q0。实际固定 MHA 在 `T=8192` 时有 64 个 Query Block；若 `section_heads=8`，前八个 CTA 都处理最后一个 Query Block，分别对应八个 Head。最后一行 `kv_head` 把 GQA/MQA 接到相同的 Tile 计算中：例如 `Hq=8,Hkv=2` 时，Query Head 0–3 使用 KV Head 0，4–7 使用 KV Head 1。Q 的物理 Stride 仍按 Hq 编码，K/V 按 Hkv 编码，改变 Head 选择不等于改变 WGMMA 的 D128 Layout。
