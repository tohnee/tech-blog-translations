说实话，DeepSeek Harness 的生态是真好。DSH 这种模式真的让 DeepSeek 官方省事不少，比如网上什么火了，都不用他们官方自己搞，社区生态的其他开发者就跟风做出来了。如果做得好，官方直接收录推荐；做得不好，也不影响主线产品。所以你会发现 DSH 的插件市场隔三差五就冒出新东西，质量还都不错。

**我最近发现三个插件，感觉很不错，觉得这仨凑在一起刚好把 DSH 日常干活的几个痛点给补上了。一个管上下文可视化，一个管多 Agent 组队，一个管长期 Bot 养成和群聊。今天一篇文章把它们仨聊完，省得你一个一个去翻。**

顺便说一句，这三个插件都是社区开发者贡献的，跟 DeepSeek 官方没有隶属关系，但确实好用。下面我把 DeepSeek Harness 简称 DSH，全名敲起来太费劲了。

## 第一个：dsh-context，把上下文黑盒撬开了

用 DSH 跑任务的人多半都遇到过：聊着聊着 Agent 突然变笨了，你猜是上下文窗口快满了，但具体是哪一步涨上去的、压缩的时候扔掉了什么、那些工具输出占了多大地方，全看不见。

**dsh-context 就干一件事：把上下文可视化。它不动 Agent 的行为，不插手流程，只负责展示。**

![](https://pic3.zhimg.com/v2-ecf3a647db89169706aa224c4b4db026_r.jpg)

装上之后，左侧边栏多一个「上下文洞察」入口，点进去是个跨会话的总览页。最上面一排是选定时间范围内跑了多少会话、烧了多少 token、估算成本多少、缓存命中率多少。下面有用量柱状图和 8 周的活动热力图，哪天用量飙了，点进去就能看到是哪个会话干的。

单个会话里会多一个「上下文」标签页，这个才是平时开得最多的地方。一根七色堆叠条，按比例画出当前窗口的组成：系统提示词、工具 schema、你发的消息、注入的内容，每一类标了 token 数和占比。对话开始变差的时候打开看一眼，是提示词太长还是工具输出糊了一大段进来，条上一目了然。

还有历史趋势图，每次模型请求是一根柱子，发生过压缩或者剪枝的地方会有 ✂ 标记，柱子当场矮下去。每一步的上下文内容都能展开看，七个可折叠的分类，每条带自己的 token 数，旁边还有和上一轮的增减对比。

另外它还能按文件列出 Agent 读过、写过、搜过什么，估算每次编辑增删了多少行，配合 git diff 看很顺手。

> 传送门： [http://github.com/bowenliang123/dsh-context](http://github.com/bowenliang123/dsh-context)

## 第二个：dsh-agent-teams，一句话拉一支队伍干活

以前用 DSH 干活，基本就是一个会话从头聊到尾。任务小的时候没啥问题，但活一大就难受了，上下文越拉越长，开头说好的要求聊着聊着就忘了。

**dsh-agent-teams 解决的就是这个问题。你丢一句话进去，比如「分析最近的 commit，从性能和安全两个角度分工」，当前会话变成「队长」，先拟一份方案：打算拉几个成员、每个人负责什么、任务怎么拆、谁先谁后。方案能在面板里直接改，确认了再启动，团队才真正跑起来。**

![](https://pic3.zhimg.com/v2-9f2b514ae5c0d5c1a16903a0b670e13e_r.jpg)

跑起来以后能随时看进度。标签页里左边是成员名单，右边是任务依赖图，谁在干活、谁在等前面的人做完，一眼就能看明白。点某个成员的头像，能直接进到它的会话里看具体做到哪了。

几个特别的地方值得说一说。先说第一个，团队干完活不会散。临时派出去的子 Agent 交付完就没了，但这个插件里的成员一直在，后面想到新问题追一句话就能把对应成员叫醒接着干。然后第二个，任务之间有先后顺序，前面的没做完后面谁也领不走，成员空下来了会自动去领下一个任务。第三个，成员之间可以直接发消息沟通，不用什么事都经过队长转达。

实用细节也不少：每个成员的模型可以分开配；有「质量门禁」功能，验证没过的任务会自动打回；常用的团队配置能存成模板，下次一句话就拉起来。

拿来干什么？代码审查，让不同成员分头看性能和安全，最后汇总成报告。调研竞品，一个成员看一家，看完互相对信息再由队长汇总。写代码加测试，一个人写实现一个人写测试，测试没过自动打回去改。

> 传送门： [http://github.com/NanmiCoder/dsh-agent-teams](http://github.com/NanmiCoder/dsh-agent-teams)

## 第三个：DS Bot，在 DSH 里养一群专属 Bot

**前面两个插件一个管上下文，一个管任务协作，DS Bot 走的是另一条路：让你在 DSH 里创建自己的 Bot，长期养着，随时聊天干活。**

**最近不是 Grok Bot 特别火吗？DS Bot 就是看到这个热点诞生的，看看这生态多好，别人有了，咱们这里就直接跟上了。**

![](https://pic3.zhimg.com/v2-1e1e7dcb3e96ecd7ecb72ea084fef9d8_r.jpg)

装好之后，系统会给你一个叫 Chief 的主 Bot，权限很高，能帮你管理所有其他 Bot 和群聊。你跟 Chief 说一句话，它就能把新 Bot 建好、群聊拉好。遇到什么问题，找 Chief 就对了。

每个 Bot 可以选不同的模型，可以在一个窗口里完成所有对话和工作，上下文不会丢。有一个不错的功能：Bot 有记忆，它会记住你的偏好，下次干活的时候自动用上。你可以在详情页管理这些记忆，也可以直接跟它说“帮我记一下”或者“把那条记忆删掉”。

群聊也做了。你可以建一个群，拉一个写手 Bot 和一个程序员 Bot 进来一起协作。为了控制 token 消耗，群里要设一个管理员 Bot，你发的消息默认由管理员回复，管理员觉得需要帮忙就自动派给别人。你也可以直接 @ 某个 Bot 让它单独回应。

![](https://pic1.zhimg.com/v2-5be3fc8ee8146ab90ba61f16065bf190_r.jpg)

用量方面，在设置里可以按时间、按 Bot、按模型查看 token 消耗，花了多少一目了然。所有数据都存在你自己电脑上，卸载插件也不会丢。

> 传送门： [http://github.com/FeiZhuLulu/DeepSeek-Bot](http://github.com/FeiZhuLulu/DeepSeek-Bot)

## 三个插件怎么搭配

这三个插件各管一摊，搭在一起用体验最好。

**dsh-context 管的是「看见」：上下文里装了什么、token 花在哪、什么时候压缩了，装上它你对 Agent 的状态心里就有数了。dsh-agent-teams 管的是「协作」：任务太大一个会话扛不住的时候，拆成几个人分头干，有依赖、有进度、有质量把关。DS Bot 管的是「长期陪伴」：你可以养几个固定角色的 Bot，有记忆、能群聊、随时捡起来接着用。**

三个插件的安装方式都一样：DSH 侧栏打开「插件 → 添加插件」，填包名装上就行。注意看一眼版本对照表，插件版本和 DSH 版本对得上再装，免得加载不出来。

还有一点要提醒：这三个都是社区项目，和 DeepSeek 官方没有关系。它们用的是你自己配好的模型额度，多 Agent、多 Bot 的场景下 token 消耗会比平时快不少，按需使用就好。

感兴趣的可以挨个试试，反正装上不好用还能卸掉，没什么成本。
