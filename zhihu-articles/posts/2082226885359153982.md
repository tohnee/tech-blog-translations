# 二、RAG 到底是什么？

RAG 全称：

**Retrieval-Augmented Generation**

中文一般叫：

**检索增强生成。**

第一次看到这个名字的时候，我觉得特别复杂。

实际上拆开以后非常简单：

```text
Retrieval
检索

Augmented
增强

Generation
生成

```

也就是：

```text
先找知识
 ↓
再把知识交给大模型
 ↓
大模型根据知识回答

```

所以：

> **RAG 不是一个模型，而是一套让大模型使用外部知识的工作流程。**

---

# 三、为什么需要 RAG？

这是理解 RAG 最重要的问题。

假设我直接问 Qwen3.5：

> “我的 Obsidian 里关于 JVM G1 的笔记是怎么写的？”

模型并不知道我的 Obsidian 内容。

因为：

```text
我的 Markdown
      │
      ✕
      │
Qwen3.5

```

两者之间没有连接。

即使大模型知道 G1，它知道的也是：

> **训练数据里的知识。**

而不是：

> **我自己的笔记。**

这就是 RAG 要解决的问题。

# 四、RAG 就像给 AI 一本“开卷考试资料”


```text

   ↓
```

> **负责阅读和回答的学生**

而：

```text

```

负责：

> **帮助找到最相关的资料。**

# 二十、完整 RAG 代码

把前面的代码组合起来：

```text
import requests

from pymilvus import MilvusClient

OLLAMA_EMBED_URL = "http://localhost:11434/api/embed"

OLLAMA_CHAT_URL = "http://localhost:11434/api/chat"

EMBEDDING_MODEL = "qwen3-embedding:0.6b"

CHAT_MODEL = "qwen3.5:9b"

DB_PATH = "./data/milvus.db"

COLLECTION_NAME = "knowledge_base"

# ==========================
# 1. 获取用户问题
# ==========================

question = input("请输入问题：")

print()
print("用户问题：", question)

# ==========================
# 2. 问题 Embedding
# ==========================

response = requests.post(
    OLLAMA_EMBED_URL,
    json={
        "model": EMBEDDING_MODEL,
        "input": question
    }
)

response.raise_for_status()

query_vector = response.json()["embeddings"][0]

print("问题向量维度：", len(query_vector))

# ==========================
# 3. 连接 Milvus
# ==========================

client = MilvusClient(DB_PATH)

client.load_collection(
    collection_name=COLLECTION_NAME
)

print("Collection 加载成功")

# ==========================
# 4. 向量搜索
# ==========================

results = client.search(
    collection_name=COLLECTION_NAME,
    data=[query_vector],
    limit=3,
    output_fields=[
        "text",
        "source"
    ]
)

# ==========================
# 5. 整理搜索结果
# ==========================

contexts = []

for result in results[0]:

    score = result["distance"]

    text = result["entity"]["text"]

    source = result["entity"]["source"]

    contexts.append(
        f"""
来源：{source}

相似度：{score}

知识内容：
{text}
"""
    )

context = "\n".join(contexts)

print()
print("================================")
print("检索到的知识")
print("================================")

print(context)

# ==========================
# 6. 构造 Prompt
# ==========================

prompt = f"""
你是一个技术知识助手。

请严格根据下面提供的知识回答用户问题。

如果知识库中没有足够的信息，
请明确告诉用户“知识库中没有足够的信息”，
不要编造答案。

【知识库内容】

{context}

【用户问题】

{question}

请给出清晰、准确、易懂的回答。
"""

# ==========================
# 7. 调用 Qwen3.5
# ==========================

response = requests.post(
    OLLAMA_CHAT_URL,
    json={
        "model": CHAT_MODEL,

        "messages": [
            {
                "role": "user",
                "content": prompt
            }
        ],

        "stream": False
    }
)

response.raise_for_status()

data = response.json()

answer = data["message"]["content"]

# ==========================
# 8. 输出最终答案
# ==========================

print()
print("================================")
print("AI 最终回答")
print("================================")

print(answer)

```

# 二十八、这一篇最值得记住的 6 句话

如果以后面试官问：

> **“你做过 RAG 吗？”**

至少应该能够说清楚：

### ① Embedding

> 将文本转换成向量表示。

### ② Milvus

> 用于存储向量并进行相似度检索。

### ③ Retrieval

> 根据用户问题的向量，从知识库中找到相关知识片段。

### ④ Context

> 将检索到的知识作为上下文提供给大模型。

### ⑤ Generation

> 大模型结合用户问题和检索到的上下文生成答案。

### ⑥ RAG

> **RAG 就是通过“检索外部知识 + 增强上下文 + 大模型生成”的方式，让模型能够利用外部知识回答问题。**

这六句话，已经构成了一个非常基础但完整的 RAG 面试回答。
