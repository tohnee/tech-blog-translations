> 本文是对LLM投机采样/投机解码（speculative decoding）论文阅读后的梳理总结。未亲自实操，可能有些理解不到位的地方，欢迎修正讨论。

投机执行算法的提出，源于常规LLM推理采用的自回归解码过程往往受限于访存，推理速度较慢，在考虑加速方案时，基于两个视角的观察：

- 解码过程中，不同token的预测有“难易”之分：体现在解码输出的Logits分布上，预测有些token时softmax输出的概率分布会集中在某些token上，说明模型有较大的置信度确定下一个输出的token；
- LLM推理阶段的自回归解码过程是访存受限的，算力并没有得到很好的利用，可以通过某种思路提高计算-访存比来实现加速：针对LLM推理，一种可行的方式就是让模型一次推理多个token，但这破坏了LLM推理时自回归解码必须串行推理的约束。

既然不同token的预测有“难易”之分，那么对那些容易预测的样本，使用一个小模型应该也可以获得正确的预测结果。因此，可以先使用小模型按照自回归解码预测多个token，再让原始大模型一次并行验证这多个token的输出是否与预期一致，若一致则接受，不一致则进行修正，即为speculative decoding的推理加速思路，如下图。

### Fast Inference from Transformers via Speculative Decoding

论文[2]为speculative decoding领域经典的论文，提供了完整了算法流程及针对上述几个问题的分析。我们定义小模型为Draft Model $M_q \sim q(x)$ ，原始大模型为Target Model $M_p \sim p(x)$ ， 前缀$prefix$ 可以视为LLM推理时的预填充token。整体算法流程包含三个主要步骤（图示红色框标识）：

步骤一：**Drafting**: Draft Model串行解码 $\gamma$ 个token，同时得到从第 $prefix$ 个token开始，解码每个token时的分布: $q_i(x), \ i=1, \cdots, \gamma$

步骤二：**Parallel Target Model Decoding**: Target Model并行解码，以 $prefix + \gamma$ 个token为输入，得到从 $prefix + 1$ 到 $prefix + \gamma + 1$ 共 $\gamma + 1$ 个token预测的概率分布 $p_i(x), \ i=1, \cdots, \gamma + 1$

- 后续为了讨论，我们针对token的下标和位置均省略 $prefix$

步骤三：**Verification and Correction:**target model选择接受draft model哪些预测的token，需要注意的是，如果target model在第 $i, i \in (1, \gamma)$ 的位置拒绝draft model后，第 $i$ 位置的token需要target model重新采样，一次speculative decoding可以输出的token数目至少为1，至多为 $\gamma + 1$ 。

接受和修正的逻辑：对于每个token $i, i \in (1, \gamma)$ ，按顺序判断 $q_i(x)$ 和 $p_i(x)$ 的关系：

- 若 $q_i(x) < p_i(x)$ ，则接受当前token，继续下一token的判断
- 若 $q_i(x) > p_i(x)$ ，则以 $\frac{p_i(x)}{q_i(x)}$ 的概率接受当前token，以 $1-\frac{p_i(x)}{q_i(x)}$ 的概率拒绝当前token，拒绝之后调整 $p_i(x)$ 的分布为 $p^{'}_i(x) \leftarrow norm(max(0; p_{i}(x) − q_{i}(x)))$ 。图示算法流程的 $n$ 对应target model已接受的token的index，则 $n+1$ 即为第一个taget model拒绝的token，需要进行分布的调整和重新采样。

可以证明，该接受和修正逻辑可以**保证speculative decoding的采样过程与原始target model自回归采样过程等价**。这是一个很重要的性质，从理论上保证了推理过程不影响效果。

![](https://pic3.zhimg.com/v2-5a4534d4ed75f382d5f9706b9ee98ba6_r.jpg)
*论文[2]中提出的投机解码算法流程*

需要注意的是，论文中并不限概率 $p(x)、q(x)$ 的形式，默认基于标准的nucleus sampling，但可以扩展到更特殊的sampling包括argmax, top-k等。

衡量speculative decoding的收益：

- 定义acceptance rate $\beta_{x_{<t}}$ : 给定 $prefix \ x_{<t}$，根据投机采样 逻辑接受 $x_t \sim q(x_t|x_{<t}) $ 的概率
- 假设不同的 $prefix$ 间是相互独立的 (i.i.d)，则平均的接受率 $\alpha =E(\beta)$ 可以作为衡量speculative decoding的定量指标： $\alpha$ 越大说明speculative decoding的效果越接近原始的自回归采样；

$\beta、\alpha$ 与Draft Model和Target Model分布的关系：定义Draft Model和Target Model分布的差异 $D_{LK}$如下

![](https://pic3.zhimg.com/v2-438c98c9d83e4045c475a06a97fcbb34_r.jpg)

当 $p(x)$ 和 $q(x)$ 的分布完全一致时，$D_{LK}(p,q)=0$；完全不一致时， $D_{LK}(p,q)=1$ 。因此， $D_{LK}$ 可以作为衡量Draft Model和Target Model分布的差异程度。根据前面的讨论，我们可以得到 $\beta$ 的解析式，由此可以推导出 $\beta、\alpha、D_{LK}$ 之间的关系：

speculative decoding平均被接受的token数的推导：

- 与接受率 $\alpha$ 和draft model一次生成的总token数 $\lambda$ 有关: $E(\# generated \ tokens) = \frac{1-\alpha^{\lambda + 1}}{1-\alpha}$

关系图示：

![](https://pic1.zhimg.com/v2-cc16a7cff34f2e738fe8f477ffd75ab6_r.jpg)

加速比推导：

- 假设单次draft model推理的时间与target model推理时间的比值为 $c$ (cost coefficient)，则加速比 (论文中称之为expected improvement factor) 为 $\frac{1-\alpha^{\lambda + 1}}{(1-\alpha)(\lambda c +1)}$

### 算法改进思路

后续论文基本是在论文[2]基础上的改进，个人认为核心在于怎么进一步提升接受率$\alpha$。更具体地，提升draft model和target model预测分布的一致性 (Alignment) 从而提升接受率 $\alpha$。总结概述为如下几点：

- 最常见的做法是采用同一系列的模型，使用较小参数量的版本作为较大参数量版本的draft model，但这种方式有一定的局限性，最直接的就是当target model经过垂域SFT时，想获得更好的分布一致性则需要draft model也进行SFT，带来额外的工作量，而且接受率也受限，由此产生后续一系列的改进工作
- **通过distillation提升draft model与target model一致性**：参考论文[4]及[3]中的总结，作者分析对比了不同的KD方案，最优的蒸馏方法很大程度上取决于任务和 Decoding Strategy
- **Tree-based speculative decoding**：类似集成学习，同时使用多个draft model的结果提升接受率（论文claim对于stochastic decoding可以从52-57% 提升至96-97%），并提出了tree-based speculative decoding解决target model如何同时验证多个draft model的结果 [5]
- **Self-drafting**：单独的draft model需要额外的微调或者维护，加速比也受限于draft model本身capacity的上限导致的接受率的上限。一种避免单独维护draft model的思路是使用target model本身作为draft model，同时必须保证draft model一次输出多个预测token提供给target model验证，已知不同的实现方案：

### **Tree-based speculative decoding**

论文[5] 提出的tree-based speculative decoding已经事实上被后续speculative decoding改进方案沿用，它使得同时使用多个draft model的预测结果成为可能。最insighful的莫过于利用casaual attention mask实现了Tree-based Parallel Decoding，更多的细节可以参考下面的总结，这里就不重复了。

[SpecInfer: Accelerating Generative LLM Serving with Tree-based Speculative Inference & Verification](https://zhuanlan.zhihu.com/p/684923217)

作为后续的改进工作，Sequoia [9]进一步做了如下改进：

- 如何构造最优的 token tree (size and depth)：抽象为约束优化问题，通过DP求解optimal token tree

![](https://pic1.zhimg.com/v2-cf29d0a7dab24eb4dcb15c24f268e4e8_r.jpg)

- 改进target model的sampling和verification算法：sampling without replacement from the draft model—thereby preventing the draft model from making the same mistake twice, while maintaining the target model's output distribution
- make it hardware-aware: 更新加速比计算公式，optimal token tree可以根据不同的hardware选取
