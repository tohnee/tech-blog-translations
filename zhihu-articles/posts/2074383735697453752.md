> 大模型推理的投机解码技术，包含Eagle系列、MTP方案、DFlash方案和DSpark方案，它们在延迟、接受率、部署灵活性上各有千秋，实际应用中需根据模型规模、硬件资源和任务特性来选择。

大模型推理的投机解码（Speculative Decoding）是一种通过“小模型草稿 + 大模型验证”来加速自回归生成的技术。它利用一个成本较低的草稿模型（或模块）快速预测多个未来草稿 Token，再由目标大模型一次性并行验证这多个Token，从而在保证生成质量的前提下大幅降低延迟。

目前主流方案可归为四类：

**Eagle 系列：**草稿模型是外挂的独立的小模型，但是自回归生成草稿Token，再由目标模型验证。

**MTP方案：**草稿模型跟随目标模型一起训练的，自回归草稿模块，自回归生成草稿Token，再由目标模型验证。

**DFlash方案：**草稿模型是外挂的独立的小模型，但是并行同时生成多个未来Token，再由目标模型验证。

**DSpark 方案：**草稿模型并行同时生成多个未来Token，再用Markov链实现半自回归修正，再置信度调度得到最终草稿Token，再由目标模型验证。

乍一看，总结性描述是不是很难理解？且听我详细分解介绍：

### Eagle1方案

![](https://pic2.zhimg.com/v2-1aa0c8f7f7c5dced8ac8ea22840ffd93_r.jpg)

如上图，Eagle1 是一种外挂式投机解码方法，草稿模型为轻量级单层 Transformer，采用**标准因果自回归**方式逐个生成草稿 token。无草稿模型预热阶段，KV Cache 在生成过程中逐步累积。

**Step 1：Target Model Prefill 阶段：**

目标模型处理整个 Prompt [A, B, C, D, E]，执行多层 Transformer 前向推理，生成完整 KV Cache。

在最后一个位置（E）采样得到 首Token F。

同时，保存 F 对应的Target Model的最后一层的Hidden States，记为 H_f，Shape为 [1, 4096]。

**Step 1：Draft Model Decode阶段：**

将 H_f 通过投影层 执行Linear计算得到 H_proj，Shape为 [1, 4096]。

将首Token F 先做Embedding操作得到Token嵌入 F_e，Shape为 [1, 4096]。

再将H_proj与F_e逐元素相加，作为草稿模型的初始输入，草稿模型Decode推理得到首个草稿Token：G'。

**Step 2：Draft Model Decode阶段：**

与Step1一样，将G'做Embedding操作，得到G'_e，与H_proj逐元素相加，输入草稿模型。

草稿模型Decode推理得到第二个草稿Token：H'，推理过程中使用Step 1的KVCache。

**Step 3：Draft Model Decode阶段：**

与Step2一样，将H'做Embedding操作，得到H'_e，与H_proj逐元素相加，输入草稿模型。

草稿模型Decode推理得到第三个草稿Token：I'，推理过程中使用Step1、 2的KVCache。

**Step 4：Target Model Decode Verify阶段：**

将 [F, G', H', I'] 送入Target Model做一次前向推理，使用标准因果注意力推理。

逐 token 对比草稿Token与目标模型采样结果，接受最长匹配前缀，得到最终生成的Token。

如图中所示，如果G', H', I'全部被接受，那Step 4一次推理得到了G,H,I,J共4个Token，J是奖励Token。

如果G'被接受，那Step 4一次推理得到了G,H共2个Token，H是奖励Token。

### MTP方案

![](https://pica.zhimg.com/v2-6ad1db554b0147cc0b1f59321645df1c_r.jpg)

如上图，是DeepSeek-R1 的 MTP 推理流程，分为以下几个主要模块：

目标模型 Prefill：输入整个 Prompt，执行Target Model推理，采样得到首Token F。

MTP 输入准备：保存Prefill推理的最后一个Layer的Hidden States，与当前 Token 的嵌入融合。

MTP 自回归生成：MTP Module逐个生成草稿 Token（MTP Moudule自回归串行推理，γ=3时推理3 步）。

目标模型验证：Target Model前向推理，验证线性草稿序列，接受最长匹配前缀。

MTP与Eagle1的关键区别：MTP 不是外挂草稿模型，而是主模型的一部分。MTP Block 与主模型结构相同，共享词嵌入和 LM Head，因此草稿质量极高，但每个草稿 token 的计算量约为主模型单层前向的 1-2%。

**Step 1：Target Model Prefill 阶段：**

目标模型处理整个 Prompt [A, B, C, D, E]，执行多层 Transformer 前向推理，生成完整 KV Cache。

在最后一个位置（E）采样得到 首Token F。

同时，保存 F 对应的Target Model的最后一层的Hidden States，记为 H_f，Shape为 [1, 7168]。

**Step 1：MTP Module Decode阶段：**

将 H_f 通过RMSNorm计算得到 H_norm，Shape为 [1, 7168]。

将首Token F 先做Embedding操作得到Token嵌入 F_e，Shape为 [1, 7168]。

再将H_norm与F_e在特征维度Concat，再做一次Linear线性投影，作为草稿模型的初始输入。

草稿模型Decode推理得到首个草稿Token：G'。

**Step 2：MTP Mudule Decode阶段：**

与Step1一样，将G'做Embedding操作，得到G'_e，与H_Norm做Concat后，再做线性投影，输入草稿模型。

草稿模型Decode推理得到第二个草稿Token：H'，推理过程中使用Step 1的KVCache。

**Step 3：MTP Mudule Decode阶段：**

与Step2一样，将H'做Embedding操作，得到H'_e，与H_Norm做Concat后，再做线性投影，输入草稿模型。

草稿模型Decode推理得到第三个草稿Token：I'，推理过程中使用Step1、 2的KVCache。

**Step 4：Target Model Decode Verify阶段：**

将 [F, G', H', I'] 送入Target Model做一次前向推理，使用标准因果注意力推理。

逐 token 对比草稿Token与目标模型采样结果，接受最长匹配前缀，得到最终生成的Token。

如图中所示，如果G', H', I'全部被接受，那Step 4一次推理得到了G,H,I,J共4个Token，J是奖励Token。

如果G'被接受，那Step 4一次推理得到了G,H共2个Token，H是奖励Token。

### Eagle2方案

![](https://pic3.zhimg.com/v2-2c8d5f08006785928dcfced284fe78de_r.jpg)

如上图，Eagle2 在 Eagle1 基础上引入树状草稿结构：每步保留 top-k（图中为top-2） 候选 token，形成多分支草稿树。目标模型验证时，将树中所有节点展平为一个序列，并使用 Tree Mask Attention 一次并行验证整棵树。

**Step 1 : Target Model Prefill 阶段：**

目标模型处理整个 Prompt [A, B, C, D, E]，执行多层 Transformer 前向推理，生成完整 KV Cache。

在最后一个位置（E）采样得到 首Token F。

同时，保存 F 对应的Target Model的最后一层的Hidden States，记为 H_f，Shape为 [1, 4096]。

**Step 1：Draft Model Decode阶段：**

将 H_f 通过投影层 执行Linear计算得到 H_proj，Shape为 [1, 4096]。

将首Token F 先做Embedding操作得到Token嵌入 F_e，Shape为 [1, 4096]。

H_proj与F_e相加，作为草稿模型的输入，草稿模型Decode推理，做Top-2采样，得到Token：G1'，G2'。

**Step 2：Draft Model Decode阶段：**

将G1',G2'做Embedding操作，得到G1'_e与G2'_e，与H_proj逐元素扩展相加，输入草稿模型。

草稿模型Decode推理得到4个候选草稿Token：H11', H12', H21', H22'，推理过程中使用Step 1的KVCache。

**Step 3：Draft Model Decode阶段：**

将H11', H12', H21', H22'做Embedding操作，得到H11'_e、H11'_e、H21'_e、H22'_e，与H_proj逐元素扩展相加，输入草稿模型。

草稿模型Decode推理得到8个候选草稿Token：I111'，I112'，I121'，I122'，I211'，I212'，I221'，I222'，推理过程中使用Step 1、2的KVCache。

**Step 4：Target Model Decode Verify阶段：**

将 [G1'，G2'，H11'， H12'， H21'，H22'，I111'，I112'，I121'，I122'，I211'，I212'，I221'，I222'] 送入Target Model做一次前向推理，使用标准因果注意力推理。

逐 token 对比草稿Token与目标模型采样结果，接受最长匹配前缀，得到最终生成的Token。

如图中所示，如果G1', H21', I212'全部被接受，那Step 4一次推理得到了G1,H21,I212,J共4个Token，其中J是奖励Token。

如果G', H11'被接受，那Step 4一次推理得到了G,H11,I共3个Token，I是奖励Token。

**目标模型Tree Mask Attention**

![](https://pica.zhimg.com/v2-9e40e3fd33282324a7e5a7c87d028e6a_r.jpg)

如上图，是Eagle2使用Top-2采样生成的Token树，有可能8个路径，也就是有8个Prefix前缀路径待验证。

在Target Model Decode Verify阶段将树展平输入目标模型推理，Attention模块使用Tree Mask Attention。

Tree Mask Attention的核心规则是，

对于展平序列中的每个 Query 节点 i，它允许计算的 Key 节点 j 必须满足：**j 是 i 的祖先节点，或者 j == i**。

对于当前Token Tree来说他的祖先关系表为：

| 节点 | 祖先路径（含自身） |
| --- | --- |
| G1' | F, G1' |
| G2' | F, G2' |
| H11' | F, G1', H11' |
| H12' | F, G1', H12' |
| H21' | F, G2', H21' |
| H22' | F, G2', H22' |
| I111' | F, G1', H11', I111' |
| I112' | F, G1', H11', I112' |
| I121' | F, G1', H12', I121' |
| I122' | F, G1', H12', I122' |
| I211' | F, G2', H21', I211' |
| I212' | F, G2', H21', I212' |
| I221' | F, G2', H22', I221' |
| I222' | F, G2', H22', I222' |

注意：F 不在展平序列中，但它是所有节点的祖先，其信息通过目标模型的 KV Cache 提供。在 Tree Mask 矩阵中，F 对应的列可以视为“全部可见”，但为了方便，我们只在草稿节点之间构造掩码，F 的可见性通过额外的 KV Cache 处理。

如下表格，我们构造一个 `(8, 8)` 的布尔矩阵。行 `i` 表示 Query 节点，列 `j` 表示 Key 节点。`1` 表示可见，`0` 表示不可见：

| Query \ Key | G1(0) | G2(1) | H11(2) | H12(3) | H21(4) | H22(5) | I111(6) | ... |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| G1'(0) | 1 | 0 | 0 | 0 | 0 | 0 | 0 | ... |
| G2'(1) | 0 | 1 | 0 | 0 | 0 | 0 | 0 | ... |
| H11'(2) | 1 | 0 | 1 | 0 | 0 | 0 | 0 | ... |
| H12'(3) | 1 | 0 | 0 | 1 | 0 | 0 | 0 | ... |
| H21'(4) | 0 | 1 | 0 | 0 | 1 | 0 | 0 | ... |
| H22'(5) | 0 | 1 | 0 | 0 | 0 | 1 | 0 | ... |
| I111'(6) | 1 | 0 | 1 | 0 | 0 | 0 | 1 | ... |
| I212'(11) | 0 | 1 | 0 | 0 | 1 | 0 | 0 | ... |

这将这个布尔矩阵作为Mask，输入因果Attention计算，就是Tree Mask Attention，Target Model在推理过程中需要使用Tree Mask Attention来做前向推理。

### Eagle3方案

![](https://picx.zhimg.com/v2-56521695ad36cf82b84da253655b4c2f_r.jpg)

如上图，Eagle3 引入**草稿模型Prefill**与 **Suffix Mask Attention**。Draft Model Prefill阶段为 γ 个固定槽位初始化生成 KV Cache；自回归生成时，每个槽位可跨步参考同槽位的历史 KV Cache，显著提升草稿质量。

**Step 1：Target Model Prefill 阶段：**

目标模型处理整个 Prompt [A, B, C, D, E]，执行多层 Transformer 前向推理，生成完整 KV Cache。

在最后一个位置（E）采样得到 首Token F。

同时，**提取多个中间层**的隐藏状态（如 Layers 1, 9, 17, 25, 33），Concat后经Project Linear 得到上下文特征，Shape为[5, 4096]（5对应A,B,C,D,E 5个Token特征）。

取最后一个目标3个位置（假设草稿模型推理3次，生成3个Token）的特征向量记为H_ctx，Shape为[3,4096]。

**Step 1：Draft Model Prefill阶段：**

将 H_ctx视为长度 3的序列，输入草稿模型（单层 Transformer）执行一次前向推理，不使用 F，只执行一次。

前向推理过程中，Attention使用双向注意力（无因果掩码），因为槽位并列。

输出Prefill的Hidden States，其中Index 0,1,3位置分别为 [h_0, h_1, h_2]，整体Shape为 [3, 4096]。

为每个槽位生成KV Cache，Shape为[3,8,128]，8为Head Num，128为Head Dim，3为Token数。

三个槽位的KVCache分别记为P_KV_0，P_KV_2，P_KV_2，Shape均为[1,8,128]。

**Step 2：Draft Model Decode阶段：**

将 H_0 通过RMSNorm计算得到 H_proj，Shape为 [1, 4096]。

将首Token F 先做Embedding操作得到Token嵌入，再RMSNorm得到特征向量 F_e，Shape为 [1, 4096]。

再将H_proj与F_e沿着特征维度拼接，作为草稿模型的初始输入，推理得到首个草稿Token：G'。

推理使用Suffix Mask Attention：使用Prefill生成槽位 0 的 KVCache:P_KV_0 ，以及当前输入生成KVCache。

同时生成三个槽位的KVCache，Shape为[3,8,128]，记为G_KV_0，G_KV_2，G_KV_2，Shape均为[1,8,128]。

**Step 3：Draft Model Decode阶段：**

与Step 2一样，将G'做Embedding，再RMSNorm得到G'_e，与H_proj沿着特征维度拼接，输入草稿模型。

草稿模型Decode推理得到第二个草稿Token：H'。

Suffix Mask 允许槽位1使用Prefill生成的KVCach：P_KV1，Step 2生成 槽位 1 KVCache：G_KV1，以及 当前推理生成的槽位 0 KVCache 和 当前推理生成的槽位 1 KVCache。

同时生成三个槽位的KVCache，Shape为[3,8,128]，记为H_KV_0，H_KV_1，H_KV_2，Shape均为[1,8,128]。

**Step 4：Draft Model Decode阶段：**

与Step 2一样，将H'做Embedding，再RMSNorm得到H'_e，与H_proj沿着特征维度拼接，输入草稿模型。

草稿模型Decode推理得到第三个草稿Token：I'。

Suffix Mask 允许槽位 2 使用以下KVCache：P_KV2，G_KV2，H_KV2，以及 当前推理生成的槽位 0 KVCache 和 当前推理生成的槽位 1 KVCache，还有当前推理生成的槽位 2 KVCache。

**Step 5：Target Model Decode Verify阶段：**

将 [F, G', H', I'] 送入Target Model做一次前向推理，使用标准因果注意力推理。

逐 token 对比草稿Token与目标模型采样结果，接受最长匹配前缀，得到最终生成的Token。

如图中所示，如果G', H', I'全部被接受，那Step 4一次推理得到了G,H,I,J共4个Token，J是奖励Token。

如果G'被接受，那Step 4一次推理得到了G,H共2个Token，H是奖励Token。

### DFlash方案

![](https://pica.zhimg.com/v2-34432b976d3affd63ed7b1a60d79c4e4_r.jpg)

如上图，DFlash 是一种**完全并行**的草稿生成方案，通过 KVCache 注入与全双向注意力，一次前向生成所有草稿 Token，无自回归依赖。

**Step 1：Targe Model Prefill**

目标模型处理 [A, B, C, D, E]，执行多层 Transformer 前向推理，生成完整 KV Cache，采样得到首Token F。

取中间层隐藏状态（如 Layers 1,9,17,25,33），拼接再Linear 投影，RMSNorm得到 H_ctx，形状 [5, 4096]。

**Step 2 ：Draft Model Decode**

构造草稿模型输入序列：[F, MASK, MASK, MASK]，经过Embedding，得到4个Token特征向量:draft_emb。

输入草稿模型经过5层前向Transformer推理，对每个位置独立采样,一次性得到 G', H', I'三个草稿Token。

（因为各位置互不依赖，可能发生多模态碰撞）

**KV 注入：**

Q = q_proj(draft_emb)

K = concat(k_proj(H_ctx), k_proj(draft_emb))

V = concat(v_proj(H_ctx), v_proj(draft_emb))

其中concat将H_ctx产生的KVCache与draft_emb产生的KVCache在Token维度拼接。

**双向 Attention 计算逻辑：**

- 注意力计算使用 is_causal=False，所有草稿位置（包括 MASK）以及上下文 H_ctx 全部互相可见。
- 由于 MASK 不携带未来信息，双向注意力不会造成信息泄露。
- 每个位置的 Query 可以同时看到全部上下文和所有草稿位置，在一次前向中可以并行计算出所有草稿位置的Hidden States。

**Step 3: Target Model Decode**

将 [F, G', H', I'] 送入Target Model做一次前向推理，使用标准因果注意力推理。

逐 Token 对比草稿Token与目标模型采样结果，接受最长匹配前缀，得到最终生成的Token。

如图中所示，如果G', H', I'全部被接受，那Step 4一次推理得到了G,H,I,J共4个Token，J是奖励Token。

如果G'被接受，那Step 4一次推理得到了G,H共2个Token，H是奖励Token。

### DSpark方案

![](https://picx.zhimg.com/v2-3e0368dec91c966d5e2ba5ac1fb82f55_r.jpg)

如上图，DSpark 在 DFlash 并行骨干基础上，引入 Markov Head 进行Token依赖修正，并利用 Confidence Head 预测接受概率，动态截断验证长度，减少Target Model验证计算量。

这里以 DeepSeek-V4-Flash 为例，其hidden_size=4096，vocab_size=129280，markov_rank=256，block_size=3，草稿长度 γ=3。

**Step 1：Targe Model Prefill**

目标模型处理 [A, B, C, D, E]，执行多层 Transformer 前向推理，生成完整 KV Cache，采样得到首Token F。

取中间层隐藏状态（如 Layers 40,41,42），拼接再Linear 投影，RMSNorm得到 main_x，形状 [5, 4096]。

**Step 2 ：Draft Model Decode**

构造草稿模型输入序列：[F, MASK, MASK, MASK]，经过Embedding，得到4个Token特征向量:draft_emb。

输入草稿模型经过3层前向Transformer推理，再经过LM-Head得到Base_Logits，Shape为[4,129280]。

其中KVCache的注入逻辑与DFLash完全一致，将main_x生成的KVCache，与当前KVCache拼接。

**Step 3：Markov Head**

Markov Head 对并行骨干输出的 base_logits 进行逐 token 自回归修正，注入一阶马尔可夫依赖。

如上图，F经过Embedding，再经过Linear得到F Token针对生成G' Token的Logits的Bias修正。

将Bias修正与Step 2中的Base_Logits索引为1位置的G' Token的原始Logits相加，得到最终Logits。

再采样得到草稿模型最终生成的G'，F经过Embedding输出需要给Confidence Head使用。

使用上述相同的逻辑，G'作为输入得到H'，H'作为输入得到I'，后一个草稿Token生成依赖于前一个草稿Token。

这就是Markov链，也形成Token相互依赖，避免多模态碰撞，论文中称之为半自回归推理。

**Step 4：Confidence Head**

Confidence Head 预测每个草稿 Token 的接受概率，用于动态验证调度。

将Step 2中推理得到的G',H',I'的Base_Logits与Step 3中F,G',H'做Embedding得到Markov嵌入拼接一起。

输入Confidence Head做Linear投影，再Sigmoid计算每个Token概率。

根据阈值或者算力动态截断草稿Token，例如若 G'概率=0.98, H'概率=0.95, I'概率=0.40，阈值 =0.9，则只取 [F, G, H] 送入验证。

**Step 5：Target Model Decode Verify**

仅将截断后的序列（如 [F, G, H]）送入目标模型一次前向，使用标准因果注意力推理。

逐 Token 对比草稿Token与目标模型采样结果，接受最长匹配前缀，得到最终生成的Token。

如图中所示，如果G', H'全部被接受，那Step 4一次推理得到了G,H,I共3个Token，I是奖励Token。

如果G'被接受，那Step 4一次推理得到了G,H共2个Token，H是奖励Token。

### 方案对比总结

| 方案 | 草稿生成方式 | 注意力机制 | 关键创新 | 验证方式 |
| --- | --- | --- | --- | --- |
| Eagle1 | 线性自回归 | 标准因果 | 特征外推 + 线性草稿 | 线性序列，因果掩码 |
| Eagle2 | 树状自回归 | 标准因果（生成）+ Tree Mask（验证） | 树状草稿 + 并行树验证 | 树形掩码 |
| Eagle3 | 自回归 + 预热 | Suffix Mask | 槽位预热 + 跨步同槽位复用 | 线性序列，因果掩码 |
| DFlash | 纯并行一次前向 | 全双向 Attention | KV 注入 + 双向注意力 | 线性序列，因果掩码 |
| DSpark | 并行骨干 + Markov 顺序修正 | 双向（骨干） | Markov Head + Confidence Head | 动态截断后验证 |

各方案在延迟、接受率、部署灵活性上各有取舍，实际应用中需根据模型规模、硬件资源和任务特性选择。
