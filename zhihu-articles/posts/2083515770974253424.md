## CANN 算子挑战赛资源规划

### 1. 评测与成绩规律

平时评测和最终评判成绩不会差太多。

在线打榜的成绩差不多就是初赛提交代码后的获取的成绩，也有少数隐藏实力的队伍，会在最后几天偷偷打榜，让你误以为自己排名靠前。

### 2. 资源与工具准备

- **从哪里入手**：[https://gitcode.com/cann/cann-learning-hub](https://gitcode.com/cann/cann-learning-hub)
- **使用哪些大模型辅助编程**：cannbot + codex + Kimi，具体使用哪些 agent 和 API 接口根据自己情况因地制宜。 > 注：由于时间紧急，尽量不要自己撸代码，用 AI 检索 API 手册去写代码是更高效的方法，但不保证算子性能最优，最低保障算子的正确性，优化性能仍然需要人工调试。
- cannbot 中内置的许多 skill，重点关注环境快速调试、算子正确性验证、性能分析的 skill，将其提取出来，按需加载使用，减少 token 开销。
- 使用性能分析工具分析算子性能，参照硬件理论的极限性能去分析大量的时间去优化，应当投入大量时间。
- **canbot-skill 网址**：[https://gitcode.com/cann/cannbot-skills/blob/master/docs/feature-list.md](https://gitcode.com/cann/cannbot-skills/blob/master/docs/feature-list.md)，用 agent 帮你扫描仓库提取出你需要的 skill。

### 3. 算子优化思路

- 让 host 多计算一些（预计算），怎样减少 Scalar 开销。
- kernal 端少分支，尽量多并行运算。
- 不同 case 数据规模使用不同 TilingKey，然后匹配最合适执行逻辑。
- 选择启动多少核数，使用单缓冲还是双缓冲，可以以性能实测为准。
- 先查看题目属于算子开发的哪个类型，是 Vector 还是 Cube（直接去看 learninghub 中的 notebook 教程），只看题目所属的类型，节省时间。
- [https://gitcode.com/cann/asc-devkit](https://gitcode.com/cann/asc-devkit) 以上仓库有算子一些案例、性能分析工具，同时若有 API 方面的问题也可以查看该仓。
- 对于不同优化方向，可用 git 去做不同分支，每一个分支尝试一个方向，然后设计控制变量法，具体查看每个阶段看性能变化和指令之间并行度是否改变。不要一次上很多优化，逐个优化，逐点优化。

### 4. 解题流程建议

1. 先在单核中验证算子正确性。
2. 正确性被验证后，从单核拓展到多核，再去逐点优化：从 tilingkey、tilingdata 如何设置，分支可以抵消，哪些控制是可以外提，减少循环内部分支判断次数，避免标量控制流打断向量化、流水和指令调度。
3. AI 先写，写完之后再逐行微调。
4. CUDA 的算子优化思路可以参考，但要注意昇腾和英伟达的硬件架构不同，要针对硬件架构进行特定的优化。
5. 学习性能分析工具文档：[https://mindstudio-docs-master.readthedocs.io/zh-cn/latest/msprof/](https://mindstudio-docs-master.readthedocs.io/zh-cn/latest/msprof/)

### 5. 关于分工

一个题目有几个测试点，每个测试点有相应的成绩，然后根据这几个测试点。

**推荐**：根据每个测试点的耗时进行分类，可以根据耗时把测试点分成大、中、小三种不同规模的数据，然后在本地手工构造耗时和远端判别器差不多的数据规模，一个人负责一种数据规模，不同优化方案针对不同数据规模。

### 6. 三个小白如何闯关

- 建议在入门后，就找资料跑第一个算子，把整个流程先串一遍。
- 然后写代码可以交给 AI，先保证算子正确性，保证算子能跑，在此基础上再进行优化。
- 生死有命富贵在天，算子先追求能跑，比赛先追求能完赛，然后追求极致性能和奖项。
