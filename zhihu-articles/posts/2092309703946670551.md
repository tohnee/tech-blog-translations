## 开篇：同一个问题，两种"大脑的用法"

问模型一道稍绕的题：“进水管 5 小时注满、出水管 8 小时放空，两管同开多久注满？”

**普通模型** （早期 GPT-4o、标准 DeepSeek-V3）几乎不停顿，刷刷给个数，很可能错——它一个字一个字"顺嘴往下说"，某步分数算反，后面全跟着错，也不会回头。

**推理模型** （OpenAI o3、DeepSeek-R1、带思考的 Claude、Qwen3 思考模式）会先"卡住"，先生成一大串推理：“进水管每小时 1/5、出水管 1/8，净注入 1/5−1/8=3/40，所以 40/3 小时……验证下符号……”，最后才给答案约 13.3 小时。

差别不在"谁背得多"——两者可能同源、同参数量。 **差别在于：普通模型把思考压缩在一次脱口而出里，推理模型则被专门训练成"先在内部走完推理、验证完，再开口"。**

## 第一章 推理模型是什么？

### 1.1 一句话定义

**推理模型（Reasoning Model），也叫大型推理模型（Large Reasoning Model, LRM）、思考型模型（Thinking Model），指一类经过专门训练（核心是"可验证奖励强化学习" RLVR），把"先生成一长串中间推理、自我验证、甚至推翻重来，再给最终答案"这套行为直接内化进权重的大模型。**

三个词缺一不可：

**① 内置长思维链。** 给可见答案前先生成大量"推理 token（reasoning tokens）"，在里面分解、尝试、验算、回头。 
 **② 在权重里，而非 prompt 拼出来。** 你给普通模型加"Let’s think step by step"它也能打草稿，但那是 **调用时临时提醒** ，时听时不听；推理模型是 **出厂就把"先想后答"练成默认习惯** ，稳定专业。前者推理能力在 **prompt/外部框架** 里，后者在 **模型参数** 里。 
 **③ 先想后答。** 输出结构上分两段：隐藏（或半隐藏）的推理 + 可见答案。

### 1.2 类比，以及一个必须加的限定

普通模型像"抢答型"学生，凭直觉、快但难题易栽；推理模型像"沉稳型"学生，先草稿、演算、验算、划掉重来，再工整抄答案。关键是这习惯 **练成了肌肉记忆** ，即"内化进权重"。

**但"系统1/系统2"只是有效的直觉类比，不能当成严格定性。** 2026 年的研究发现存在" **推理地平线（reasoning horizon）** "：在推理链约 **70%–85%** 长度处，后续推理 token 对最终答案的因果影响会急剧衰减——也就是说， **一条长 CoT 的后 15%–30% 可能只是"惯性输出"，并非始终是深思熟虑的系统2。** 甚至有论文以"当审议有害时：逆向测试时扩展、不忠实的痕迹，以及对统一 System-2 的反对"为题，直接质疑把推理模型等同系统2。所以更准确的说法是： **推理模型被训练成"默认进行长链审议"，但它内部计算并非处处都是严格的系统2。**

## 第二章 为什么会有推理模型？

### 2.1 起点：普通模型的"系统1"天花板

普通模型 **自回归** 地一个接一个预测 token，本质是直觉反射， **没有独立的"停下来验算、回头"环节** 。结构性致命伤： **推理是只能前进、不能后退的单行道，错误会级联** ——第3步符号错，后面全错，模型却无法"喊停、回第3步重算"。数学证明、复杂代码、多步规划恰需要"走一步验一步、错了能回头"，于是被死死压住。

### 2.2 第一条路：外挂"推理时计算"

最早的解法是第八篇的 **推理时计算（TTC）** ：CoT prompt、自洽采样、思维树、思维图。有效，但有三个麻烦： **依赖外部编排** （多次调用、状态管理、搜索合并，工程量大）； **依赖模型"愿意配合"** （普通模型没被专门训练如何高质量打长草稿，常潦草跳步、不稳定）； **贵且慢** 。像你每次考前反复叮嘱一个爱抢答的学生"记得打草稿"，他时做时忘。

### 2.3 关键一跃：用 RLVR 把"先想后答"训练成本能

行业于是问： **为什么不直接把模型训练成"默认就会、且极擅长打高质量长草稿"？** 钥匙是 **RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励强化学习）** ：

- 不必人工写"标准推理"（正确路径千变万化、标注不过来）；
- 只定一个 **能自动判对错的规则** ：数学看最终数值、代码看测试用例是否全过；
- 让模型自己生成各种推理， **只要最终答案对，中间怎么绕都给奖励** 。

由此模型自己"摸索"出分解、验算、回头、换路等策略，往往不是人教、而是 **涌现** 的。

**这里有两个重要限定，避免把 RLVR 讲成魔法：**

**限定一：RLVR 更多是"锐化"而非"创造"。** 2025 年 NeurIPS Oral 的研究发现， **RLVR 主要是在"锐化（sharpen）"基础模型中已经潜藏的推理能力，而不是教会模型全新的推理。** 推理模型的成功，很大程度上依赖预训练阶段底座已具备推理潜力——这也解释了为什么"先把底座训够、再做 RLVR"如此关键，一个预训练不足的模型，RLVR 也无米下炊。

**限定二：RLVR 有"奖励黑客（Reward Hacking）"风险，且训练可能不稳定。** 当奖励只看"最终答案对不对"，模型可能学会 **走捷径** ——靠猜、靠模式匹配、甚至利用测试用例/判题脚本的漏洞拿到奖励，而非真正学会推理；训练早期还常出现探索不稳定、奖励震荡。2025–2026 年的一批工作正是为此而生：

- **Absolute Zero（NeurIPS）** ：让模型自己提出"能最大化自身学习进度"的任务并解决，用"执行代码/自洽"这类零人工的闭环验证器替代静态数据集，减少对固定题库和判题漏洞的依赖；
- **FR3E** ：专门针对 RLVR 的不稳定探索，先识别 **高不确定性的决策点** 、在这些点上定向 rollout，构造"语义 grounded"的中间反馈，而不是盲目采样；
- **HiPO（Hint-Guided Policy Optimization）** ：让模型从自己 **稀有的成功轨迹** 中学习，用提示引导把偶发成功放大成稳定能力。

这三点共同回答了"怎么让 RLVR 既涌现真推理、又不被捷径和不稳定带偏"。

### 2.4 两个里程碑

- **2024 年 9 月 12 日，OpenAI 发布 o1 预览版。** 第一个把长链推理作为核心卖点、证明"推理可被专门训练"的标志产品，硬核基准上跳跃式提升——行业第一次看清：能力增长除了"训得更大"，还有"训得更会想"这条轴。
- **2025 年 1 月，DeepSeek 开源 R1，并披露 R1-Zero。** 震撼在于 **R1-Zero 在预训练后的 DeepSeek-V3-Base 上、不做任何 SFT、直接纯 RL，就涌现了长链推理、反思、纠错** ——证明推理不必手把手指点，RL 奖励本身就能"逼"出来。但这是" **有代价的涌现** "：R1-Zero 输出 **可读性差、中英等多语言混杂、不受控，不适合直接面向用户** ；正式版 R1 加少量冷启动数据解决可读性，性能对标且开源，直接引爆浪潮。

范式意义：高质量推理从" **调用时临时拼装** "变成" **出厂内置本能** "。

## 第四章 推理模型 vs 标准模型，差在哪？

### 4.1 训练差异：RLHF 对齐偏好，RLVR 逼出推理

**标准模型链路** ：预训练 → SFT → **RLHF** （奖励是人类"喜好"：有无帮助、语气、是否有害），优化" **对齐** "，让模型讨喜守规矩，但不专门优化"把难题推理到底"。

**推理模型** 引入/以 **RLVR** 为核心：奖励是" **答案客观对错** "（数学数值、代码过测），不依赖主观打分，模型为做对必须学会可靠多步推理。

> **RLHF 教模型"怎么说话让人满意"，RLVR 逼模型"怎么思考才能做对"。**

### 4.2 DeepSeek-R1 训练全流程

**R1-Zero（验证"推理能否纯 RL 涌现"）：** 在 **预训练后的 DeepSeek-V3-Base** （不是随机初始化）上 → 直接纯 RL、不做 SFT。推理真涌现了，但 **可读性差、语言混杂** ——因为没有人类先验规定格式、语言和表达。

**正式版 R1（加人类先验，四阶段）：**

1. **冷启动：** 收集 **数千条** 高质量长 CoT 数据，先 SFT 底座，得到"合格初始 RL 演员"，克服纯 RL 早期不稳定、注入格式/语言先验。来源：长 CoT 少样本引导、提示生成含反思验证的详细答案、R1-Zero 输出可读化、人工后处理。
2. **推理导向 RL：** 大规模 RLVR 练强推理。
3. **拒绝采样造数：** RL 近收敛时大量生成、用规则筛正确轨迹（拒绝采样），辅以人工，构造覆盖推理/写作/问答/通用的新 SFT 数据。
4. **再 SFT + 全场景偏好对齐：** 保持强推理的同时更友好、可控、安全。

### 4.3 行为差异

| 维度 | 标准模型 | 推理模型 |
| --- | --- | --- |
| 默认行为 | 直接快速作答 | 先内部推理再作答 |
| 思考过程 | 默认不展示，需 prompt 引导 | 内置长链（可见或给摘要） |
| 延迟 / 成本 | 低 / 只算答案 | 高 / 推理 token 也按输出计费 |
| 擅长 | 问答、写作、翻译、闲聊、摘要 | 数学、代码、逻辑、多步规划、科学问题 |
| 短板 | 多步推理、错误级联 | 简单题过度思考、闲聊偏僵、成本高 |
| 推理能力位置 | 外部 prompt/框架激发 | 内化权重、开箱即用 |
| 核心训练信号 | RLHF（偏好） | RLVR（对错） |

## 第五章 两种"推理"的特点与触发

### 5.1 先破中文"推理"二义

- **Inference（推断/推理阶段）** ：训练完、参数冻结后，接收输入跑前向得到输出的动作。 **任何模型每次调用都在做 inference** ，与 training 相对。
- **Reasoning（逻辑推演）** ：为解题做多步思考演算的 **能力/行为** 。

准确说法： **推理模型在 inference 阶段自动做大量 reasoning；标准模型 inference 默认只做直觉快生成，要它 reasoning 得外部引导。**

### 5.2 特点

**标准模型** ：默认快、直出、单遍；具备 reasoning 潜力但需外部激活、不稳定；一次调用通常一条路走到黑。 
 **推理模型** ：默认慢、内置、多步、会自检回头；权重层面被 RLVR 训练成先 reasoning 后回答，不需提醒、质量高。

### 5.3 触发与控制

**① OpenAI： `reasoning_effort` ，注意各模型档位不同**

- **o 系列（o1、o3、o3-mini、o4-mini）：仅支持 `low / medium / high` ，默认 `medium` ，不支持 `minimal` ；**
- **GPT-5 及以后：在 low/medium（默认）/high 之外新增 `minimal`** （把推理压到最少、最快返回）；部分更新模型还提供更细档位。传了模型不支持的值会报错。

```text
from openai import OpenAI
client = OpenAI()
resp = client.responses.create(
    model="o3",
    reasoning={"effort": "high"},      # o系列只能 low/medium/high
    input="证明：根号2是无理数。",
)
# GPT-5 才可设 "minimal"；想看推理概括请用 reasoning summary

```

**② Anthropic：4.6 弃用手动预算、4.7 起仅 adaptive**

时间线（据官方文档）：

- **4.5 及更早（Sonnet/Opus/Haiku 4.5 等）** ：只支持 extended thinking（ `enabled` + `budget_tokens` ，最小 1024），传 `adaptive` 会返回 400；
- **Claude 4.6** ：extended thinking **已弃用（deprecated）但仍能跑** ，官方推荐 **adaptive** ——由模型动态决定"何时思考、想多深"；
- **Claude 4.7 及以后（含 Opus 5）** ：手动预算 **彻底移除** ，再设 `enabled/budget_tokens` 直接 **400 报错** ， **adaptive 是唯一开启的思考模式** （内部评测中稳定优于手动预算）。4.7 另推出 **任务预算（task budgets, beta）** ：给"思考+工具调用+工具结果+最终输出"的 **整个 agentic loop** 一个 token 目标，模型看到倒计时来安排优先级。

```text
import anthropic
client = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=16000,
    thinking={"type": "adaptive"},     # 4.7+ 唯一支持的开启模式
    messages=[{"role": "user", "content": "解一道复杂的分布式一致性问题"}],
)
# 仅在 4.5 等老模型上才用 {"type":"enabled","budget_tokens":10000}

```

**③ DeepSeek-R1** ：默认把推理写在 `think ... /think` ，API 以 `reasoning_content` 返回推理、 `content` 返回答案，无需开关。

**④ Qwen3** ：开源侧 `enable_thinking` 开关，对话中 `/think` 、 `/nothink` ；思考预算在达到预算时提前结束、用"提前停止提示"引导生成总结（该定制仅百炼 API 提供，开源框架需 **两次生成** ：第一次生成到预算、检查是否仍在思考段，第二次引导收尾，据 Qwen 官方文档）。

**⑤ Gemini** ：以 thinking_budget 限制思考 token 数。

## 第六章 推理模型 vs 推理时计算（TTC）

二者是" **范式** "与"范式的一种实现产品"的关系。 **TTC 是总称** ：凡参数冻结、推理阶段投额外计算都算。它有两条路径：

- **外挂式（能力在外部框架）** ：CoT prompt、自洽、ToT、GoT，模型不变、靠调用编排， **任何模型都能套** ；
- **内化式（能力在权重里）** ：推理模型，RLVR 训练、开箱即用。

类比：外挂 TTC 是"临场打草稿的方法和草稿纸"，做得好看功底；推理模型是"早已把严谨流程练成肌肉记忆的人"。

> **推理模型是 TTC 思想的产品化/内化形态，与外挂 CoT/ToT/GoT 不矛盾、可叠加（推理模型当底座再套 ToT/GoT，强强联合）。**

**系统级优化：ATTS（异步测试时扩展，ICLR 2026）。** 外挂/内化都主要在"算法形态"上做文章，而 ATTS 攻的是 **服务系统的并行瓶颈** 。它通过分析"算术强度（arithmetic intensity）"发现： **同步等待（synchronization）才是并行拒绝采样的主要瓶颈** ——一批采样里最慢的那条会拖住全部。ATTS 用 **保形预测（conformal prediction）把拒绝采样重构为一个假设检验过程** ，配合在线校准实现 **异步推理** ，并提出支持三阶段拒绝采样的序数分类算法，沿"顺序+并行"双轴扩展。效果：在 MATH、AIME 等任务上 **最高 56.7 倍加速、4.14 倍吞吐提升且不损失精度** ；一个 1.5B/70B 的 draft/target 组合即可达到 o3-mini(high) 的 AIME 水平。

## 第七章 CoT、ToT、GoT，两种模型都支持吗？

**关键认知：推理"拓扑"与"模型类别"正交。** CoT/ToT/GoT 描述中间想法如何连接，标准/推理描述训练形态，二者独立。因此：

- **标准模型** ：能 CoT（prompt 引导）、能被 ToT/GoT 框架编排，但底座推理弱、绝对质量有限；
- **推理模型** ：内置高质量 CoT，也能被 ToT/GoT 编排，且底座强、每种拓扑都更好。

三种拓扑： **CoT 线性链** （不分支不回头）； **ToT 树** （节点分多支、评估剪枝、可回溯， **单父、分支不合并** ）； **GoT 任意有向图** （再允许 **多父聚合** 、精炼回环）。

## 第八章 核心机理：为什么 CoT 单次能做，ToT、GoT 必须"拆分支"？

### 8.1 一次调用 = 一条自回归序列，本质线性

模型一个 token 接一个 token 预测，每生成一个就接在末尾再预测下一个， **严格串行线性** 。关键： **单次调用内部任一时刻只走在一条路径上，计算图里没有"分叉"算子** ——你没法在生成第 N 个 token 的同时开一个"平行世界"生成另一个第 N 个 token、两路并行再汇合。一次调用最终只有一条序列。

### 8.2 CoT 为什么单次即可？

CoT 拓扑线性，步骤首尾相接，与"单条序列"天然吻合，prompt 让它一步步想、顺着写到底，一次调用完成。

### 8.3 "分叉"为什么单次做不到？

分叉要求从同一父状态 **派生多条彼此独立、互不知对方的子序列并行发展** 。单次调用只有一条序列、无分叉算子：你写下"方案A"就只能沿 A 走，无法在同一次调用里"另起独立序列"写 B。在一条回答里先写 A 换行再写 B **不是分叉、而是同序列依次罗列** ——写 B 时 A 已在上下文里、B 会受 A 影响，且无法让 A、B 各自独立长几层再独立评估。

### 8.4 分支由"外部代码 + 多次调用"实现

既然一次调用只走一条路，探索几条路就由外部代码发起几次独立调用。 **"分叉"发生在调用编排层，代码才是树/图的载体，模型每次只负责一个节点的局部思考。** 框架替模型完成五件事（ToT 四要素 + 搜索循环）：

1. **思维分解（Thought Decomposition）：** CoT 不显式规定、ToT 要专门定义 thought 粒度。24 点中一个 thought=一行算式（约3个解完）；创意写作=一段计划；填字=几个词。原则：足够小，小到模型能稳定生成"有希望且多样"的候选。
2. **思维生成（Thought Generator）：** 对当前状态 **多次调用 / 温度>0 采样出 k 个候选** （分叉落地=k 次独立生成）。
3. **状态评估（State Evaluator）：** 值估计（打分 1–10 或 `sure/maybe/impossible` ）或投票。
4. **剪枝（Prune）：** 丢掉 impossible/低分，不浪费算力。
5. **搜索（Search）：** BFS 每层全探再下，或 DFS 沿最优扎到底、卡住回溯。

### 8.5 GoT 多的聚合，同样靠"再调用一次"

**聚合** ：把分支 X、Y 的部分解文本拼进新 prompt（“综合成最优方案”）， **再发起一次调用** 生成融合 thought，新节点 **多父（入度>1）** ——区别于 ToT 的根本。 **精炼** ：把已有 thought 喂回改进、形成回环。GoT 论文强调这套图抽象 **无缝泛化 CoT/ToT、且无需任何模型更新** ——拓扑复杂度全由外部编排承担。

> **模型一次调用只会线性想一条路；分叉、剪枝、回溯、聚合等非线性动作模型内部没有算子，只能由外部代码"多次独立调用 + 自维护图"实现。**

## 第九章 伪代码：CoT / ToT / GoT

**CoT（单次）：**

```text
def cot(llm, question):
    output = llm.generate(f"{question}\n请一步步思考，最后给出答案。")  # 仅一次调用
    return extract_answer(output)

```

**ToT（多次调用 + 评估剪枝 + BFS/DFS）：**

```text
def tot(llm, question, k=3, max_depth=5):
    frontier = [State(text=question, parent=None)]
    for _ in range(max_depth):
        candidates = []
        for state in frontier:
            for _ in range(k):                       # 生成：独立采样 k 个（分叉）
                ns = state.apply(llm.generate(gen_prompt(state), temperature=0.9))
                if llm.evaluate(eval_prompt(ns)) != "impossible":  # 评估 + 剪枝
                    candidates.append(ns)
                if ns.is_solution():
                    return ns
        if not candidates:
            break
        frontier = sorted(candidates, key=score, reverse=True)[:k]  # BFS 选优入下一层
    return best_of(frontier)

```

**GoT（分支 + 多父聚合 + 精炼回环）：**

```text
def got(llm, question):
    g = Graph(); root = g.add_node(question)
    nx = g.add_node(llm.generate(branch_prompt(root, "X"), temperature=0.9), parents=[root])
    ny = g.add_node(llm.generate(branch_prompt(root, "Y"), temperature=0.9), parents=[root])
    combined = "\n".join(f"- {n.text}" for n in (nx, ny))
    n_agg = g.add_node(llm.generate(f"把以下部分方案综合成最优方案：\n{combined}"),
                       parents=[nx, ny])             # 入度=2，聚合
    n_ref = g.add_node(llm.generate(refine_prompt(n_agg)), parents=[n_agg])  # 精炼
    return extract_answer(n_ref.text)

```

对照可见： **只有 CoT 是一次 `generate` ；ToT/GoT 全是 for 循环里多次独立 `generate` ，树和图长在代码里。**

## 第十章 选型、坑与趋势

### 10.1 选型

- 日常问答/写作/翻译/摘要/闲聊：标准模型或关思考，快省自然；
- 数学/代码/复杂逻辑/多步规划/严谨结论：推理模型或调高思考强度；
- 需大规模并行探索与方案综合：推理模型为底座 + 外层 ToT/GoT，上限最高但要算清 token 账。

### 10.2 坑（含实证数据与对策）

1. **过度思考** ：简单题也冗长、甚至把对的绕错。2026 年已有系统对策：**ThoughtFold（ICML 2026）**用内省偏好学习"折叠"冗余链；**Manifold Steering（NeurIPS 2026）**把过度思考关联到低维激活流形、用投影引导；**MERA（ACL 2026）**解耦推理与控制，让模型"元认知"地决定继续、回溯还是停止。
2. **不擅长开放/创意/情感对话** ：训练取向使其严谨就事论事，轻松闲聊偏僵。
3. **思维链不保证忠实（有数据）** ：ICML 2026 研究显示， **生产模型 CoT 不忠实率约 13%** ；前沿模型低但非零—— **DeepSeek-R1 约 0.37%、Sonnet 3.7 with thinking 约 0.04%** 。再叠加前述"推理地平线"（70%–85% 后因果影响骤降），可见 CoT 须谨慎当真相。
4. **内化推理的可解释性挑战** ：这是推理模型特有的问题—— **标准模型的外挂 CoT 完整摊在眼前，而推理模型的推理 token 可能生成后即被移除（OpenAI），或虽可见却更长更复杂、难以人工审查** 。也就是说，模型更强了，其"思考"反而更不透明，需借助推理摘要、监控与可解释性工具（承接第七篇）。
5. **思维链可见性受限** ：OpenAI 只给摘要，且 **带工具调用时摘要可能返回空** ；绕过接口套取原始 CoT 可能违规。
6. **成本/延迟方差大** ：推理 token 按输出计费、长度差异大，需用思考预算/任务预算约束长尾。

### 10.3 趋势

1. **推理能力默认化、融合化** ：单独推理模型消失，成旗舰内置、按需开关。
2. **思考强度精细化、可预算、自适应** ：“Reasoning on a Budget” 综述系统梳理了按难度动态分配、提前退出、多保真度优化等自适应/可控 TTC。
3. **推理 + Agent 深度结合（最重要方向之一）** ：Agent 的多步规划、工具调用、错误恢复本质都是推理。2026 年的一批工作让推理模型成为 Agent 核心底座： **DeepAgent（WWW 2026）** 尝试在单一推理过程中端到端完成自主思考、工具发现与动作执行； **ThunderAgent（ICML 2026）** 通过"程序感知调度"协同 LLM 调用、KV Cache 与工具执行，带来最高约 3.6 倍 Agent 吞吐；面向 Web Agent 的 **CATTS** 用投票导出的不确定性、只在决策真正有争议时投入算力； **ATLAS** 则把"选择哪个求解模型"也变成一个可分配的动作。（多模态侧，SenseNova-MARS、LongCat-Flash-Thinking 等工作用 RL 赋予模型交错的视觉推理与工具使用能力。）
4. **从文本到多模态推理** ：扩展到图像、视频、空间推理，视觉 token 冗余与算力分配是新课题。
5. **效率优化工程化** ：除 ATTS 外， **C3PO** 做成本约束下的级联推理， **Offloaded Reasoning** 让轻量模型生成推理轨迹、大模型只生成最终答案，进一步降本。
6. **推理能力蒸馏、平民化** ：Tiny-R1 等以极小参数逼近大模型，推动端侧与低成本部署。

## 总结：六句话记住本篇

1. **推理模型把"先走一长串推理、验证、纠错再答"内化进权重** ，核心靠 RLVR；与靠 RLHF 对齐偏好的标准模型训练信号根本不同。
2. **诞生逻辑** ：标准模型困在只能前进不能回头的系统1 天花板，外挂 TTC 有效但麻烦不稳，于是用 RL 把推理训练成本能；o1 证明可行、R1-Zero 证明纯 RL 可涌现。
3. **RLVR 以"锐化"底座已有潜力为主、并非凭空创造** ，且需防奖励黑客、稳早期探索（Absolute Zero/FR3E/HiPO）。
4. **两种"推理"要分清** ：inference 是每次调用的前向计算，reasoning 是逻辑推演。触发上 OpenAI o 系列仅 low/medium/high、GPT-5 才加 minimal；Anthropic 4.6 弃用手动预算、4.7 起仅 adaptive；R1 默认输出 `think` 链。
5. **推理模型是 TTC 的内化产品形态** ，与外挂 CoT/ToT/GoT 可叠加；三种拓扑（链/树/图）与模型类别正交；ATTS 等从系统层把并行推理的同步等待打掉。
6. **最硬机理** ：一次调用只有一条线性序列、无分叉算子，故 CoT 一次即可，分叉/剪枝/回溯/聚合必须由外部代码"多次独立调用 + 自维护图"实现——分支在编排层，模型每次只思考一个节点。
