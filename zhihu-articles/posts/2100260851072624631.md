**pytorch适配**

- torch.library是用于扩展PyTorch核心算子库的API集合。它允许开发者创建新的算子、并为其提供自定义实现。
- Pybind是一个开源的C++和Python之间的桥接工具，它旨在使C++代码能够无缝地集成到Python环境中。

Pybind适用于快速将C++函数暴露给Python，实现高效接口绑定。但其生成的算子无法被PyTorch的算子系统识别，不具备schema定义与图追踪能力，因此不支持torch.compile优化。相比之下，torch.library提供了与PyTorch核心算子系统深度集成的机制，支持算子注册、schema定义和图追踪能力，是支持torch.compile的必要条件。开发者可根据需求选择对应方式。

支持图

```text
import torch

# 假设你在 C++ 中注册了 my_ops::custom_add
# 在 Python 中为它注册 Meta 规则（只计算输出的 Shape，不写实际计算逻辑）
@torch.library.impl("my_ops::custom_add", "meta")
def custom_add_meta(x, y):
    # 检查输入 Shape 是否匹配等
    torch._check(x.shape == y.shape, lambda: "Shapes must match")
    # 返回一个空的、只带有 Shape 和 Dtype 信息的 Tensor
    return torch.empty_like(x)

```

支持反向

```text
# 注册反向传播的导数公式
@torch.library.register_autograd("my_ops::custom_add")
def custom_add_autograd(x, y):
    # 前向逻辑
    out = torch.ops.my_ops.custom_add(x, y)
    
    # 定义反向传播
    def backward(grad_out):
        # 假设加法的导数两边都是 1 * grad_out
        return grad_out, grad_out
        
    return out, backward
```

| 特性 | torch.autograd.Function (经典机制) | torch.library.register_autograd (新版机制) |
| --- | --- | --- |
| 设计定位 | 以自动求导为核心，将前向和反向绑定在一个 Python 类中。 | 以算子注册（Dispatcher）为核心，解耦前向、反向与编译器元信息。 |
| torch.compile 兼容性 | 不友好。容易导致计算图断裂（Graph Break）或引发隐蔽的编译错误。 | 原生支持。配合 Fake Tensor 注册可以完美融入全图编译和图优化流程。 |
| 前反向绑定方式 | 强绑定。在一个类中同时写 forward 和 backward。 | 解耦。先通过 @custom_op 注册前向，再额外注册反向公式。 |
| 上下文管理 | 在前向传播 forward(ctx, ...) 中直接用 ctx 保存。 | 通过独立的 setup_context(ctx, inputs, output) 函数保存。 |
| 高级特性 (vmap等) | 较难直接与 torch.vmap 等高级动态操作组合。 | 极易与 register_fake、register_vmap 等其他算子行为平级组合。 |

`autograd.Function` 的前向传播是一个黑盒，编译器无法知道输入和输出的形状关系（Shape/Meta 信息），因此遇到它时，编译器通常会放弃整图优化，产生 **Graph Break。**为了解决这个问题，PyTorch 推出了 `torch.library` 的统一算子注册生态。它把一个算子拆解为多个维度独立注册： [[1](https://docs.pytorch.org/docs/stable/library.html), [2](https://github.com/pytorch/pytorch/blob/main/torch/library.py)]

1. **前向逻辑**（使用 `@torch.library.custom_op`）
2. **形状推导**（使用 `.register_fake`，告诉编译器这个算子不消耗数据时输出多大）
3. **反向求导**（使用 `.register_autograd`
