最近，AI 圈经常出现一个词：MCP。

很多人在介绍 AI Agent 时，都会提到 MCP，甚至把它称为 AI 连接外部世界的标准接口。

但 MCP 到底是什么？它解决了什么问题？为什么需要它？它和 API、Tool、RAG 又有什么关系？

今天我们不从复杂的技术规范讲起，而是从一个实际问题出发，把 MCP 讲清楚。

![](https://pic4.zhimg.com/v2-ac13222cdda02f12b7412e50decc7fd7_r.jpg)

## 一、AI 很聪明，但它无法天然使用企业里的各种系统

我们先设想一个场景。

一家企业希望开发一个 AI 助手，让它能够：读取本地文件；查询企业数据库；搜索内部知识库；查询客户信息；发送邮件；调用项目管理系统；操作其他业务软件。

这些能力看起来并不复杂。但开发者很快会遇到一个问题：

每个系统都有自己的接口、数据格式、认证方式和调用规则。

连接数据库，需要开发数据库连接逻辑；连接邮件系统，需要适配邮件接口；连接其他业务软件，又需要重新研究它的 API。

如果企业有多个 AI 应用，每个应用又需要连接多个外部系统，就可能出现大量重复的接口开发和维护工作。

问题的本质是：AI 应用与外部系统之间，缺少一套统一的连接和通信方式。

这就是 MCP 想要解决的问题。

## 二、MCP 到底是什么？

MCP，全称 Model Context Protocol，中文通常称为“模型上下文协议”。

简单理解：MCP 是一套标准化的通信协议，让 AI 应用能够按照统一的方式，发现、连接和使用外部工具与数据。

我们可以用一个比喻理解。过去，每个外部系统都像一种不同规格的插头。

AI 应用要连接它们，就需要针对不同插头开发不同的适配器。

MCP 希望提供一种统一的接口规范，让外部系统按照共同的标准提供能力，AI 应用则通过支持 MCP 的客户端与它们通信。

这样，开发者就不必为每一种 AI 应用和每一个外部系统，都重新设计一套完全独立的通信方式。

注意：MCP 并不会让所有系统自动兼容。外部系统仍然需要提供 MCP Server，或者通过适配层把已有 API 包装成 MCP 服务。

## 三、MCP 是如何工作的？

理解 MCP，首先要认识三个核心角色。

1. MCP Host：AI 应用的宿主

Host 就是用户实际使用的 AI 应用。

例如，一个 AI 助手、支持 Agent 的开发工具，或者企业自己开发的 AI 平台。

它负责接收用户请求、协调模型和管理连接。

2. MCP Client：客户端

Client 是 Host 内部负责与 MCP Server 通信的组件。

它按照 MCP 协议发送请求、接收结果，并管理与服务端的连接。

3. MCP Server：服务端

Server 负责把某个外部系统的能力按照 MCP 规范开放出来。

例如：文件系统 MCP Server：提供文件读取能力；数据库 MCP Server：提供数据库查询能力；邮件 MCP Server：提供邮件查询和发送能力；企业业务系统 MCP Server：提供业务数据查询或操作能力。

三个角色之间的关系可以简单理解为：

Host 负责协调，Client 负责通信，Server 负责提供能力。

它们通过统一协议交换信息，让 AI 应用能够使用不同服务提供的能力。

## 四、MCP Server 可以向 AI 提供什么？

MCP 有三个特别重要的概念：Tools、Resources 和 Prompts。

1. Tools：工具Tools 是可以被调用执行的功能。

例如：查询客户信息；读取数据库；创建任务；发送邮件；计算业务数据。

可以把 Tools 理解为 AI 的“手和脚”。

它让 AI 不再只是生成文字，而是可以通过授权调用外部功能。

2. Resources：资源

Resources 是可以提供给 AI 应用读取的上下文数据。

例如：企业文件；数据库中的记录；产品说明文档；业务资料；系统中的其他信息。

可以把 Resources 理解为 AI 可以访问的“外部资料”。

3. Prompts：提示模板

Prompts 是服务端提供的可复用提示模板。

例如：合同审查模板；数据分析模板；客户服务模板；报告生成模板。

它们可以帮助 AI 应用按照预设方式组织任务。

需要注意，Tools、Resources 和 Prompts 是 MCP 定义的三类核心服务能力，但并不是每个 MCP Server 都必须同时提供这三类能力。

## 五、用一个合同审查助手理解 MCP 的价值

假设我们开发一个合同审查助手。

它不仅要读取合同，还需要查询企业内部制度、获取合同模板、调用业务系统，并生成审查结果。

如果没有 MCP，开发者可能需要分别为 AI 应用编写不同系统的接口适配代码。

而使用 MCP 后，可以把不同系统的能力封装成 MCP Server。

例如：

文件服务 MCP Server：提供合同文件读取、文件列表查询等能力。

企业知识库 MCP Server：提供制度检索、合同模板查询等能力。

业务系统 MCP Server：提供客户信息查询、审批状态查询等能力。

邮件服务 MCP Server：提供邮件查询和发送能力。

当 AI 应用连接这些 MCP Server 后，就可以发现它们提供的能力，并在任务需要时调用相应工具。整个过程可以理解为：

用户提出合同审查需求 → AI 理解任务，判断需要哪些外部能力 → MCP Client 获取相关 Server 提供的能力列表 → AI 选择合适的工具，并按照参数要求发起调用 → MCP Server 执行对应操作，返回结果 → AI 根据返回结果继续分析和完成任务。

这样，AI 就有机会把多个外部系统的能力组合起来，完成一个完整的业务任务。

## 六、MCP 与 API、Tool、RAG 有什么区别？

这几个概念很容易混淆。

| 技术 | 主要解决的问题 | 简单理解 |
| --- | --- | --- |
| API | 软件系统之间如何交互 | 系统提供的接口 |
| Tool | AI 可以调用什么功能 | AI 可使用的工具 |
| RAG | AI 如何获取外部知识 | 检索知识再生成 |
| MCP | AI 应用如何标准化连接外部能力 | 统一通信协议 |

这里有一个非常重要的关系：API 和 MCP 不是竞争关系。

API 是软件系统对外提供服务的一种接口方式。MCP 则规定了 AI 应用与 MCP Server 之间如何发现能力、传递参数和返回结果。一个原本只有 API 的业务系统，可以通过 MCP Server 把已有 API 包装成 AI 应用更容易发现和调用的工具。

同样，Tool 也不等于 MCP。Tool 是一种可执行的功能，而 MCP 是一种可以用来提供和调用这类功能的协议。

## 七、为什么 MCP 对 AI Agent 很重要？

我们回到 AI Agent。

一个真正能够完成任务的 Agent，通常需要几种能力：理解用户目标；获取专业知识；调用外部工具；执行工作流程；检查任务结果。

其中，MCP 主要解决的是外部工具和数据的标准化连接问题。

例如，一个 Agent 可能需要同时连接文件系统、企业知识库、数据库和邮件系统。

如果每次都要重新开发一套连接逻辑，开发和维护成本就会不断增加。而 MCP 提供统一的通信规范，让不同服务可以按照相同的协议向 AI 应用开放能力。

它带来的价值主要有三个：

第一，降低集成成本。开发者可以复用符合 MCP 规范的服务，不必为每个 AI 应用重复开发全部连接逻辑。

第二，提高系统扩展能力。当企业需要增加新的数据源或工具时，可以新增相应的 MCP Server，而不一定需要重构整个 AI 应用。

第三，提高能力复用性。同一个 MCP Server，只要兼容性和权限条件满足，就可以被不同的 MCP Host 使用。

这意味着，企业可以逐步建设自己的工具服务体系，让不同的 AI 应用复用这些能力。

## 八、MCP 不是万能的，它也有边界

理解 MCP，不能把它神化。

MCP 解决的是通信和能力连接问题，并不负责替 AI 完成所有事情。

它本身不能保证：AI 一定能正确理解用户需求；AI 一定会选择正确的工具；外部系统返回的数据一定准确；业务流程一定合理；工具调用一定安全。

尤其是企业应用，安全问题非常重要。

例如，AI 如果能够发送邮件、修改数据、创建订单，就必须设计好身份认证、访问权限、操作范围和人工确认机制。

MCP 提供了协议层面的通信与授权机制，但企业仍然需要在 Host、Server 和业务系统中落实权限控制、风险审查、操作日志和数据保护。

连接能力不等于拥有无限操作权限。

## 九、最后理解一个关键问题：MCP 让 AI 的能力更容易组合

我们可以把前面几篇文章的知识体系串起来：

LLM：提供理解和推理能力；

RAG：让 AI 获取外部知识；

MCP：让 AI 应用标准化连接外部工具和数据；

Workflow：组织任务执行的步骤；

Agent：根据目标协调这些能力，完成任务。

它们并不是相互替代的技术，而是解决不同层面的问题。

如果把 AI Agent 比作一名企业员工：

LLM 是大脑，RAG 是知识获取能力，MCP 是连接外部工具和系统的标准通道，Workflow 是工作流程，而 Agent 则负责根据目标组织和执行任务。

这也是为什么我们不能只关注大模型本身。

AI 真正进入企业业务，不仅需要会思考，还需要能够获取知识、连接系统、调用工具，并在规则约束下完成工作。

MCP 的价值，就在于让这些外部能力更容易被 AI 应用连接和复用。

从这个角度看，MCP 不只是一个技术协议，它也是 AI Agent 生态中连接模型能力与现实业务系统的重要基础设施。
