## 大模型分布式推理中的张量并行 TP

内容范围：Linear、SwiGLU MLP、词表 Embedding、MHA、GQA/MQA、KV cache、LM Head 与采样、完整 Decoder，以及 vLLM / SGLang 源码对应关系。

### 0. 范围、符号与张量布局

### 0.1 本文讨论的 TP 基线

以 Llama 类 Dense、Pre-Norm Decoder 的推理前向为主：

- 一个 TP group 内，各 rank 共同处理同一批逻辑请求，执行全部 Decoder 层。
- 主要在线性层内部切分权重与计算；Attention 使用完整 head 为单位的切分。
- 不叠加 Pipeline Parallel、Sequence Parallel、Context Parallel、Expert Parallel。
- 暂时忽略量化、通信计算融合、稀疏 Attention、MLA 等额外机制。
- GQA/MQA 采用普通的 KV-head 分片或复制策略，不将单个 KV head 的序列上下文继续拆开。

TP 并不等于“每卡独立处理一部分请求”。同一条请求的一次前向，需要组内各 rank 共同完成。常见执行组织是一卡一个进程，但进程组织不是 TP 数学定义的一部分。

### 0.2 统一符号

| 符号 | 含义 |
| --- | --- |
| p | TP group 的 rank 数 |
| N | 本次前向实际处理的 token 行数 |
| M | 需要预测词表 logits 的位置数，可小于 N |
| D | 模型 hidden size |
| F | MLP intermediate size |
| V、V_{pad} | 有效词表大小、补齐后的存储词表大小 |
| H_q、H_{kv} | Q heads 数、K/V heads 数 |
| d | 单个 head 的维度；本笔记通常取 D=H_qd |
| n_l | Decoder 层数 |
| T_{cache} | 所有请求实际缓存的 token 总数 |
| b | 单个缓存元素的字节数 |

推理服务常将多条请求的 token 打包为 $[N,D]$。这不表示不同请求可以互相做 Attention；请求边界、位置与有效上下文由 metadata 描述。

### 0.3 必须区分的三种状态

| 状态 | 含义 | 恢复完整结果所需操作 |
| --- | --- | --- |
| 完整副本 | 各 rank 已有相同的完整张量 | 无需再次恢复 |
| 特征 / head 分片 | 各 rank 持有不同位置的最终值 | 需要时拼接 |
| 待求和的局部贡献 | 各 rank 计算了同一输出的不同求和项 | 求和归约 |

**shape 完整，不代表数值完整。** 行并行 Linear 的本地输出已经是 $[N,D_{\mathrm{out}}]$，但仍然只是局部贡献。

### 1. Linear 的 TP：Column Parallel 与 Row Parallel

### 1.1 数学矩阵与 PyTorch 存储方向

先忽略 bias：

$$ Y=XA,\qquad X:[N,D_{\mathrm{in}}],\quad A:[D_{\mathrm{in}},D_{\mathrm{out}}]. $$

PyTorch 的 Linear 权重实际保存为：

$$ W=A^\top:[D_{\mathrm{out}},D_{\mathrm{in}}], \qquad Y=XW^\top. $$

Column / Row 的命名以数学中的 $A$ 为参照，不能直接套在 PyTorch 的 $W$ 上。对普通二维未量化权重：

| 并行方式 | 切分含义 | 数学中的 A | PyTorch 中的 W |
| --- | --- | --- | --- |
| Column Parallel | 切输出特征 | 按列切 | 第 0 维 |
| Row Parallel | 切输入特征 | 按行切 | 第 1 维 |

### 1.2 Column Parallel：不同输出特征，最后按需拼接

按输出维切分：

$$ A=[A_0,\ldots,A_{p-1}], \qquad A_r:[D_{\mathrm{in}},D_{\mathrm{out}}/p]. $$

每个 rank 都使用完整输入 $X$，计算：

$$ Y_r=XA_r. $$

由分块矩阵乘法：

$$ \boxed{Y=[Y_0,\ldots,Y_{p-1}]}. $$

本地结果已经是对应输出特征的正确值，不需要与其他 rank 的值相加。

- 后续需要完整输出：沿输出特征维 AllGather。
- 后续能直接消费分片：保持分片，不立即通信。
- vLLM 的 gather_output 控制是否在列并行层内汇集输出。

### 1.3 Row Parallel：不同输入特征的贡献，最后求和

同时对应切分输入和权重：

$$ X=[X_0,\ldots,X_{p-1}], \qquad A= \begin{bmatrix} A_0\\ \vdots\\ A_{p-1} \end{bmatrix}. $$

每卡计算：

$$ Z_r=X_rA_r. $$

于是：

$$ \boxed{Y=\sum_{r=0}^{p-1}Z_r}. $$

| 内容 | 每卡形状 |
| --- | --- |
| 输入 X_r | [N,D_{in}/p] |
| 数学权重 A_r | [D_{in}/p,D_{out}] |
| PyTorch 权重 W_r | [D_{out},D_{in}/p] |
| 本地贡献 Z_r | [N,D_{out}] |
| AllReduce SUM 后 | [N,D_{out}]，完整副本 |

常规路径使用 AllReduce SUM，让所有 rank 都得到完整输出。

- input_is_parallel：输入是否已经是本 rank 对应的特征分片。
- reduce_results：是否在该层内部完成归约。
- reduce_results=False 不代表数学上不再需要求和；求和可能交给调用方、层边界或融合算子。

### 1.4 bias 只能按数学定义计入一次

列并行的 bias 跟随输出特征切分：

$$ Y_r=XA_r+b_r. $$

行并行的完整 bias 不应在各卡重复加入：

$$ Y=\sum_rZ_r+b. $$

若各 rank 都先加完整 bias 再求和：

$$ \sum_r(Z_r+b)=\sum_rZ_r+pb, $$

就会出错。可在归约后加 bias，或由单个 rank 在归约前加入。所核对的 vLLM 行并行路径支持仅 rank 0 在 GEMM 中加入 bias，也支持延后处理。

### 1.5 非线性与分片的关系

逐元素激活可以直接作用于特征分片：

$$ \phi([Y_0,Y_1])=[\phi(Y_0),\phi(Y_1)]. $$

但通常：

$$ \phi(Z_0+Z_1)\ne\phi(Z_0)+\phi(Z_1). $$

因此，列并行输出可以先本地激活；行并行的局部贡献不能随意先过非线性再求和。

### 2. SwiGLU MLP 的 TP

### 2.1 三个投影的计算

$$ G=XA_g,\qquad U=XA_u, $$

$$ H=\operatorname{SiLU}(G)\odot U,\qquad \operatorname{SiLU}(x)=x\sigma(x), $$

$$ Y=HA_d. $$

其中：

$$ A_g,A_u:[D,F],\qquad A_d:[F,D]. $$

gate 表示对中间通道进行调制，不是 MoE 中选择专家的 router。

### 2.2 gate/up 列并行，down 行并行

将 gate/up 的输出通道对应切分：

$$ G_r=XA_{g,r},\qquad U_r=XA_{u,r}, $$

$$ H_r=\operatorname{SiLU}(G_r)\odot U_r, \qquad H_r:[N,F/p]. $$

同一 rank 的 gate、up 必须对应同一组中间通道，因为它们需要逐元素配对。

down 沿这些中间通道切分：

$$ \boxed{ Y=\sum_r \left[ \operatorname{SiLU}(XA_{g,r})\odot(XA_{u,r}) \right]A_{d,r} }. $$

求和号内部的整个过程都可以本地执行。基础路径只在 down 之后做一次 AllReduce，无需在 gate/up 后先 AllGather。

### 2.3 MergedColumnParallelLinear 的含义

两个分支使用相同输入，可合并本地权重：

$$ A_{\mathrm{merged},r}=[A_{g,r},A_{u,r}], $$

$$ XA_{\mathrm{merged},r}=[G_r,U_r]. $$

**各投影分别确定分片，再组织为本地 packed 权重。** 不能将全局的“完整 gate + 完整 up”简单连续等分，否则某个 rank 可能拿不到配对的两个分支。

| 对象 | 每卡 PyTorch 权重 / 激活形状 |
| --- | --- |
| gate_up_proj.weight | [2F/p,D] |
| 合并投影输出 | [N,2F/p] |
| SiluAndMul 输出 | [N,F/p] |
| down_proj.weight | [D,F/p] |
| down 本地贡献 | [N,D] |

SiluAndMul 将本地输入的前后两半解释为 gate/up，计算前半的 SiLU 与后半的逐元素乘积。

### 3. Vocab Parallel Embedding

### 3.1 切分词表行，保留完整向量

Embedding 表：

$$ E:[V,D]. $$

每行是一个 token 的完整向量。沿词表维切分后，忽略 padding：

$$ E_r:[V/p,D]. $$

各 rank 保存不同 token 集合的完整向量，不是同一向量的不同 hidden features。

### 3.2 全局 ID、本地 ID 与 mask

假设 rank $r$ 负责全局区间 $[s_r,e_r)$。对合法 token ID $t$，定义：

$$ C_r(t)= \begin{cases} E_r[t-s_r,:],&s_r\le t<e_r,\\ \mathbf 0,&\text{否则}. \end{cases} $$

由于每个有效 token 恰好有一个所属 rank：

$$ \boxed{E[t,:]=\sum_rC_r(t)}. $$

基础查表流程：

1. 判断 token 是否属于本卡，建立未命中 mask。
2. 命中位置使用本地索引 $t-s_r$。
3. 未命中位置临时映射到安全索引，例如 0。
4. 执行本地查表。
5. 将未命中位置的查表结果清零。
6. 对 $[N,D]$ 贡献张量做 AllReduce SUM。

查表前改索引是为了合法访问；查表后清零是为了消除占位查表值。索引 0 既可能是真实命中，也可能是占位，不能仅凭索引值判断，应保留 mask。

以上以输入 token ID 合法为前提；分片 mask 不能替代 tokenizer / 输入合法性检查。

### 3.3 为什么是求和而不是拼接

每卡输出已经是 $[N,D]$：所属 token 位置提供完整向量，其他位置贡献零。恢复关系是“向量加零”，不是沿 hidden dimension 拼接。

概念上，可用 one-hot 矩阵 $S:[N,V]$ 表示查表：

$$ X=SE. $$

沿词表维对应切分：

$$ S=[S_0,\ldots,S_{p-1}],\qquad E= \begin{bmatrix}E_0\\\vdots\\E_{p-1}\end{bmatrix}, $$

$$ X=\sum_rS_rE_r. $$

实际实现使用索引和 mask，不构造巨大的 one-hot 矩阵。

### 3.4 存储与输出布局

- 权重：每卡约为 $[V/p,D]$，降低词表权重存储。
- 本地贡献：$[N,D]$。
- 归约后输出：各卡相同的完整 $[N,D]$。
- 通信的是本次输入对应的向量贡献，不是收集完整词表。

实际权重可能按 $V_{\mathrm{pad}}$ 分配，以满足切分与对齐。补齐行不代表新增有效 token。vLLM 还处理原始词表、新增词表及其 padding，因此索引组织可能比单一连续区间更复杂。

### 4. MHA Attention 的 TP

### 4.1 按完整 head 划分计算

标准 MHA 中：

$$ H_q=H_{kv}=H,\qquad D=Hd. $$

第 $j$ 个 head：

$$ O^{(j)} = \operatorname{softmax} \left( \frac{Q^{(j)}K^{(j)\top}}{\sqrt d}+M_{\mathrm{attn}} \right)V^{(j)}. $$

为避免与预测位置数 $M$ 混淆，这里用 $M_{\mathrm{attn}}$ 表示 attention mask。

普通 head TP 将 $H/p$ 个完整 heads 分给每个 rank，要求 $H\bmod p=0$。不切单个 head 的 $d$ 维向量，也不切该 head 所需的历史上下文。

### 4.2 QKV 列并行

每个 rank 从完整输入 $X$ 计算本地 heads：

$$ Q_r=XA_{Q,r},\quad K_r=XA_{K,r},\quad V_r=XA_{V,r}. $$

MHA 下：

$$ A_{Q,r},A_{K,r},A_{V,r}:[D,D/p]. $$

同一 head 的 Q/K/V 必须配套。各卡读取完整 hidden vector，只负责输出其中一部分 heads。

QKV 可合并为一次投影：

$$ A_{\mathrm{QKV},r}=[A_{Q,r},A_{K,r},A_{V,r}]. $$

不能对全局的“完整 Q + 完整 K + 完整 V”直接连续等分；应分别选取本 rank 的 Q/K/V heads，再组成 packed 布局。

### 4.3 本地 Attention 为什么不需要通信

对一个 head：

$$ Q^{(j)}:[B,S_q,d],\qquad K^{(j)},V^{(j)}:[B,S_k,d]. $$

softmax 沿 key 位置 $S_k$ 归一化，不跨 heads 归一化：

$$ P^{(j)}_{t,s} = \frac{\exp(L^{(j)}_{t,s})} {\sum_{u\in\text{有效 key 位置}}\exp(L^{(j)}_{t,u})}. $$

本 rank 拥有本地 heads 的全部有效 K/V，因而能独立完成 QK 点积、mask、softmax 和对 V 的加权。缩放仍为 $1/\sqrt d$，不能改为 $1/\sqrt{D/p}$。

RoPE 在各 head 内根据位置作用于 Q/K，也可以本地完成。所需分量可由后端融合处理；这不改变 head 归属。

Attention kernel 不一定显式生成完整 $[S_q,S_k]$ 分数矩阵，以上形状用于说明数学依赖。

### 4.4 输出投影行并行，避免中间 AllGather

本地 Attention 输出为：

$$ O_r:[N,D/p]. $$

完整多头输出在逻辑上是 $O=[O_0,\ldots,O_{p-1}]$。将输出权重按输入维切开：

$$ A_O= \begin{bmatrix}A_{O,0}\\\vdots\\A_{O,p-1}\end{bmatrix}. $$

由分块乘法：

$$ \boxed{ Y=OA_O=\sum_rO_rA_{O,r} }. $$

因此无需先拼回所有 heads：本地做输出投影，再对 $[N,D]$ 局部贡献 AllReduce SUM，即得到完整 Attention 子层输出。

### 4.5 Prefill 与 decode 的 KV 归属

- Prefill：本地 heads 处理多个 query 位置，并写入对应 K/V。
- Decode：本地 heads 的当前 Q 读取本地这些 heads 的历史 KV，并加入当前 K/V。
- 每层独立产生并保存自己的 KV；不同层的 KV 不可混用。
- 纯 head TP 下，历史 token 位置对本地 heads 保持完整，不必每步去读取其他 rank 的 heads。

标准 MHA 的单层缓存可在逻辑上写成：

$$ K_{\mathrm{cache},r},V_{\mathrm{cache},r}: [B,L,H/p,d]. $$

分页缓存的物理布局可以不同，但 head 归属与逻辑上下文关系不变。

### 4.6 为什么各 rank 产生的 KV cache 保留在本 rank 即可

**在普通 head TP 下，各 rank 为本地 Q heads 准备并保存所需 KV heads 的完整有效历史，因此本地 Attention 不需要额外跨 rank 交换 KV cache。** 这里强调的是 KV cache 的数据依赖，不是整个 Attention 子层都没有通信。

### 4.6.1 数学依赖：一个 head 不使用其他 heads 的 KV

对固定的一条请求和一个 Decoder 层，设 rank $r$ 负责的 MHA heads 集合为 $\mathcal H_r$。处理 token 位置 $t$ 时，各卡已经有完整的本层输入 $x_t$，可以直接计算：

$$ q_t^{(j)}=x_tA_Q^{(j)},\qquad k_t^{(j)}=x_tA_K^{(j)},\qquad v_t^{(j)}=x_tA_V^{(j)},\qquad j\in\mathcal H_r. $$

若使用 RoPE，还需对投影后的 Q/K 按位置做本地变换；后文缓存及 Attention 公式中的 Q/K 应理解为实际进入 Attention 的向量。这一步不改变本地可用的结论。

本地缓存维护这些 heads 的历史：

$$ \mathcal C_r(t) = \left\{ (k_s^{(j)},v_s^{(j)}) \mid j\in\mathcal H_r,\ 0\le s\le t \right\}. $$

设当前 query 允许关注的历史位置集合为 $\mathcal S_t$，则：

$$ o_t^{(j)} = \sum_{s\in\mathcal S_t} \frac{ \exp\!\left(q_t^{(j)}k_s^{(j)\top}/\sqrt d\right) }{ \sum_{u\in\mathcal S_t} \exp\!\left(q_t^{(j)}k_u^{(j)\top}/\sqrt d\right) } v_s^{(j)}. $$

右侧只依赖本地的当前 Q 和同一 head 的有效历史 K/V，不依赖其他 rank 的 heads。因此，将所有 heads 的 K/V AllGather 成完整张量，并不是该计算的必要步骤。

以上缓存集合写的是完整历史的逻辑形式；分页、滑动窗口等可以改变实际保留和访问的有效位置，但必须保证本地所需数据可用。

### 4.6.2 执行生命周期：本地产生、本地追加、本地读取

| 阶段 | rank r 的工作 | 是否需要交换 KV cache |
| --- | --- | --- |
| Prefill / extend | 从本层完整输入计算本地 K/V，将当前位置写入本地缓存 | 普通 head TP 本身不需要 |
| 后续 decode 的 QKV 投影 | 计算当前 token 的本地 Q/K/V | 不需要 |
| 缓存追加 | 将当前 K/V 写入该请求、该层、本地 heads 对应的位置 | 不需要 |
| Attention | 当前 Q 读取本地缓存中的对应有效历史 K/V | 不需要 |
| 下一生成步骤 | 继续复用并追加本地缓存 | 不需要为此交换 KV |

写缓存与读取缓存必须具有正确的设备执行依赖，但这属于本地数据就绪关系，不等于跨设备 KV 通信。后端也可以融合缓存写入与 Attention。

同一条请求的 token 位置在各 rank 上保持逻辑一致；不同 rank 保存不同 heads 的数据。每个 rank 并不是只保存“自己负责的一段历史 token”。

### 4.6.3 GQA / MQA 通过本地分片或副本满足相同条件

GQA 中，本地 Q heads 需要其对应分组的 KV。若这些 KV heads 能均分，就分别保存在对应 rank；若 TP 超过 KV heads 数，则按第 5 节的规则复制 KV 权重和缓存。

复制组内各 rank 从相同输入使用相同的 K/V 投影权重，分别产生并缓存相同的 KV 数据。其目的是让本地 Q heads 能直接读取所需历史，而不是设置一个 KV 持有者、让其他 ranks 每步远程索取数据。

因此：

- 模型内多个 Q heads 共享一个 KV head，不代表需要跨 rank 访问该 head。
- 普通 TP 的跨卡副本策略，以重复存储和部分重复计算换取本地可用。
- MQA 中每个 rank 都可保存唯一 KV head 的本地副本，仍可本地完成相应 Q heads 的 Attention。

这是对当前普通分片 / 复制布局的说明；其他系统也可以选择不同的 KV 所有权与通信策略。

### 4.6.4 输出投影的 AllReduce 不是在同步 KV cache

各卡本地 Attention 完成后，计算：

$$ Z_r=O_rA_{O,r},\qquad Y=\sum_rZ_r. $$

这里汇总的是不同 Q-head 输出对最终 hidden states 的贡献，不是把历史 K/V 交换、合并或同步。

前一层的归约可能是形成当前完整输入 $x_t$ 的必要步骤；这也不等于当前层必须交换 KV cache。应区分“输入 / 输出激活通信”和“KV cache 数据通信”。

### 4.6.5 结论成立的条件与需要通信的例外

本地保留 KV 即可，需要同时满足：

1. 当前 rank 已拥有本地 Q heads 所需的 K/V 投影权重或等价计算能力。
2. 本地已保留这些 KV heads 在全部有效上下文位置上的缓存。
3. 请求、位置、缓存映射和各层状态保持正确对应。
4. 本轮计算没有将所需上下文继续拆到其他 rank 或实例。

| 场景 | 为什么可能需要 KV 相关通信 |
| --- | --- |
| Context Parallel / 某些 Decode Context Parallel 布局 | 所需上下文分布在多个 rank，需采用额外分布式 Attention 算法，例如交换 KV 或合并局部结果；具体通信对象取决于算法 |
| Prefill / Decode 分离 | 生成历史 KV 的实例与消费它的实例不同，需要传输或使目标端可访问所需 KV |
| 请求迁移、KV 重分片、缓存恢复 / 外部缓存加载 | 当前执行设备还没有所需缓存，需要重新放置数据 |

**不能把“普通 head TP 的本地 Attention 不需要交换 KV”扩大为“所有分布式推理场景都不需要 KV 通信”。** 也不能从多卡执行本身推断每个 decode step 都有跨卡 KV 交换。

源码对照可结合第 9 节的 QKV head 分配及 Attention 调用入口，以及 [FlashAttention 的 KV cache 接口](https://github.com/Dao-AILab/flash-attention)：query 与本地 K/V cache 作为计算输入，K/V cache 的 head 维按本地配置确定。

### 5. GQA / MQA、KV 复制与缓存容量

### 5.1 共享关系

| 结构 | head 数关系 |
| --- | --- |
| MHA | H_{kv}=H_q |
| GQA | 1<H_{kv}<H_q |
| MQA | H_{kv}=1 |

一个 KV head 表示对应的一对 K head、V head。设 $H_q$ 可被 $H_{kv}$ 整除，组大小为：

$$ g=H_q/H_{kv}. $$

采用连续分组时：

$$ k(j)=\left\lfloor j/g\right\rfloor, $$

$$ O^{(j)} = \operatorname{softmax} \left( \frac{Q^{(j)}K^{(k(j))\top}}{\sqrt d}+M_{\mathrm{attn}} \right)V^{(k(j))}. $$

多个 Q heads 共享 K/V，但每个 Q head 仍有独立的 query、softmax 和输出。输出 head 数保持为 $H_q$，输出总宽度保持为 $H_qd$。

GQA/MQA 是模型结构的共享关系，不是将任意 MHA 在推理时无损压缩为更少 KV heads 的操作。

### 5.2 普通 TP 的两种 KV 布局

始终要求 $H_q\bmod p=0$。

**情况一：**$H_{kv}\ge p$**，且**$H_{kv}\bmod p=0$**。**

$$ H_{q,\mathrm{local}}=H_q/p,\qquad H_{kv,\mathrm{local}}=H_{kv}/p. $$

Q 和 KV 都可均匀分片。

**情况二：**$p>H_{kv}$**，且**$p\bmod H_{kv}=0$**。**

$$ H_{q,\mathrm{local}}=H_q/p,\qquad H_{kv,\mathrm{local}}=1. $$

每个模型 KV head 在多个 rank 上复制，复制份数：

$$ R=p/H_{kv}. $$

在满足这些整除条件的普通策略下：

$$ \boxed{ H_{kv,\mathrm{local}}=\max(1,H_{kv}/p) }. $$

这不是所有并行 Attention 方案的通用公式；不满足整除条件的配置也不能直接套用。

### 5.3 一个关键映射例子

若 $H_q=8,H_{kv}=2,p=4$，则：

| rank | Q heads | 本地 KV |
| --- | --- | --- |
| 0 | Q0、Q1 | KV0 |
| 1 | Q2、Q3 | KV0 |
| 2 | Q4、Q5 | KV1 |
| 3 | Q6、Q7 | KV1 |

KV0、KV1 各有两份设备副本。复制情况下：

$$ \text{KV head ID} = \left\lfloor\frac{\text{tp rank}}{R}\right\rfloor. $$

vLLM 的 K/V 权重加载通过 tp_rank 除以 num_kv_head_replicas，选择复制组对应的 KV 分片；Q 仍按自己的 TP rank 分片。

这些 rank 通常加载相同 KV 投影权重，从相同输入分别计算 K/V，并写入各自缓存，不需要每步从其他 rank 接收一份 KV。

### 5.4 三种“共享 / 复制”不能混淆

| 现象 | 含义 |
| --- | --- |
| 模型内共享 | 多个 Q heads 使用一个模型 KV head |
| 跨 rank 复制 | 同一个模型 KV head 在不同设备各保存一份 |
| 计算时展开 | 为表达共享关系而逻辑广播或临时重复 K/V |

本地多个 Q heads 共享同一个 KV head，不要求持久缓存按 Q heads 数扩大。参考实现中的 repeat_kv / repeat_interleave 不足以证明缓存也被复制；支持 GQA 的内核可以直接接收较少 KV heads。

MQA 的 $H_{kv}=1$，所以普通 TP 中各卡都需该完整 KV head 的历史。增加 TP 不会继续降低单卡的这份 KV 数据。

### 5.5 KV cache 容量推导

假设各层的 KV head 数、维度与 dtype 相同，忽略分页取整、元数据和量化 scale：

$$ \boxed{ M_{\mathrm{rank}} =2n_\ell T_{\mathrm{cache}}H_{kv,\mathrm{local}}db }. $$

其中 2 对应 K 与 V；应使用本地 KV heads 数，不是 Q heads 数。若所有请求等长，可以用 $T_{\mathrm{cache}}=BL$；不能再重复乘一次 batch size。

普通 TP 下：

$$ M_{\mathrm{rank}} =2n_\ell T_{\mathrm{cache}}db\max(1,H_{kv}/p). $$

所有 ranks 的有效缓存数据量合计：

$$ M_{\mathrm{total}} = \begin{cases} 2n_\ell T_{\mathrm{cache}}H_{kv}db,&p\le H_{kv},\\ 2n_\ell T_{\mathrm{cache}}pdb,&p>H_{kv}. \end{cases} $$

例如 $n_\ell=32,T_{\mathrm{cache}}=8192,H_q=32,H_{kv}=8,d=128,b=2$，一份 KV head 覆盖全部层与这些 token 占 128 MiB：

| TP | 每卡 KV heads | 每个模型 KV head 副本数 | 每卡有效 KV 数据 | 全部卡合计 |
| --- | --- | --- | --- | --- |
| 1 | 8 | 1 | 1 GiB | 1 GiB |
| 4 | 2 | 1 | 256 MiB | 1 GiB |
| 8 | 1 | 1 | 128 MiB | 1 GiB |
| 16 | 1 | 2 | 128 MiB | 2 GiB |
| 32 | 1 | 4 | 128 MiB | 4 GiB |

这是有效数据量，不是框架实际预分配 KV pool 的大小。

### 5.6 Packed QKV 宽度与输出投影

本地 packed QKV 的宽度应分别计算：

$$ dH_{q,\mathrm{local}}+2dH_{kv,\mathrm{local}}. $$

KV 复制时，不能简单用全局 packed 宽度除以 TP。

例如 $H_q=8,H_{kv}=2,d=128,p=4$，每卡 Q/K/V 宽度为 256、128、128，合计 512，而不是全局宽度 1536 除以 4 得到的 384。

Attention 输出仍按本地 Q heads 组织：

$$ O_r:[N,(H_q/p)d]. $$

后续仍是 $Y=\sum_rO_rA_{O,r}$。归约的是不同 Q-head 输出投影的贡献，不是对重复 KV 求和，因此不应除以 KV 复制份数。

### 6. LM Head 与采样

### 6.1 从 hidden states 到词表 logits

选取 $M$ 个预测位置的最终 hidden states：

$$ H:[M,D],\qquad W_{\mathrm{head}}:[V,D]. $$

$$ \boxed{Z=HW_{\mathrm{head}}^\top,\qquad Z:[M,V]}. $$

每个 token 的 logit 是 hidden vector 与对应词表权重行的内积。logits 是未归一化分数。

普通生成中，完成 prefill 后通常只需每条请求最后一个有效位置；decode 通常每请求取当前位置。prompt logprobs、投机验证等可能要求更多位置，不能一概只保留一行。

### 6.2 词表并行与 logits 汇集

沿词表行切分权重：

$$ W_{\mathrm{head}}= \begin{bmatrix}W_0\\\vdots\\W_{p-1}\end{bmatrix}, \qquad Z_r=HW_r^\top:[M,V/p]. $$

因此：

$$ \boxed{Z=[Z_0,\ldots,Z_{p-1}]}. $$

这是列并行：各 rank 已经算出自己词表部分的最终 logits。不同 ranks 的同一本地索引对应不同 token，不能把这些分数直接相加。

| 汇集方式 | 完整 logits 的位置 |
| --- | --- |
| Gather | 指定目标 rank |
| AllGather | 所有参与 ranks |

采样由哪个 rank 执行，必须结合汇集路径和调用方判断，不能默认全部框架都由 rank 0 采样。

对简单连续词表分片，全局 ID 为本地索引加 vocab_start；含新增词表、padding、重排时，要使用实际映射。

### 6.3 与输入 Embedding 的区别及权重共享

| 项目 | 输入 Embedding | LM Head |
| --- | --- | --- |
| 输入 | token IDs | hidden states |
| 计算 | 查表 | 内积投影 |
| 本地结果 | 命中位置的完整向量，其他为零 | 部分词表的完整分数 |
| 恢复完整结果 | 求和 | 拼接 |

启用 tied embeddings 的模型可令 $W_{\mathrm{head}}=E$，各 rank 对应共享本地分片；未启用时，它们是两套不同参数。共享参数不会让查表和输出投影的通信语义变成相同。

### 6.4 随机采样需要考虑全局概率质量

对一行 logits，暂时忽略其他处理：

$$ P(t)=\frac{\exp(z_t)}{\sum_{u=0}^{V-1}\exp(z_u)} $$

局部 softmax 得到的是“已知 token 属于本分片”的条件分布。因此，不能在每卡独立做局部采样，再均匀选择一个 rank；各分片的总概率质量通常不同。

**从数学上，可以通过“先选分片，再在分片内采样”恢复正确的全局分布。** 设词表被划分为互不重叠的分片 $\mathcal V_r$，处理后的候选 logits 为 $\widetilde z$。使用共同的平移值 $m$ 稳定指数计算：

$$ S_r=\sum_{t\in\mathcal V_r}\exp(\widetilde z_t-m), \qquad S=\sum_r S_r $$

先以 $S_r/S$ 的概率选择 rank，再按该 rank 的局部分布采样。对于 $t\in\mathcal V_r$，由条件概率公式：

$$ \begin{aligned} P(T=t) &=P(R=r)\,P(T=t\mid R=r)\\ &=\frac{S_r}{S}\, \frac{\exp(\widetilde z_t-m)}{S_r}\\ &=\frac{\exp(\widetilde z_t-m)}{S}. \end{aligned} $$

因此，该过程与完整词表上的 softmax 采样具有相同分布。零质量分片不会被选中；所有分片合计必须具有非零质量。

这一分解也出现在 [FlashSampling §4.1–4.2](https://arxiv.org/html/2603.15854v1#S4.SS2)：各分片提供局部样本和分片对数总质量，再按分片质量选择最终样本。[arxiv.org](https://arxiv.org/html/2603.15854v1?utm_source=chatgpt.com)

**这里是概念性算法及正确性推导，不表示 vLLM/SGLang 默认采用该路径。** Gather / AllGather 完整 logits 后采样是一种直接实现；专用分布式算法可以只交换必要统计量与候选，无需汇集全部 logits。

若开启 top-k/top-p，还需要先正确确定全局候选集合。上述推导解决的是候选确定后的采样，不能用每卡独立过滤替代全局过滤。

### 6.5 Temperature、过滤与 greedy

随机采样中，$\tau>0$ 时：

$$ P_\tau(t)= \frac{\exp(z_t/\tau)}{\sum_u\exp(z_u/\tau)}. $$

- Temperature 调整分布尖锐程度。
- Top-k 保留全局最高的 $k$ 个候选。
- Top-p 按概率降序保留累计质量达到阈值的候选集合。
- 对过滤后的支持集重新归一化，再随机选择。
- grammar、禁用 token、重复惩罚等可能修改 logits；组合顺序应以框架契约为准。

greedy 则直接计算：

$$ t^*=\arg\max_tz_t. $$

无需 softmax。对固定 logits，除以任意正 temperature 不改变 argmax；temperature=0 通常作为 greedy 的配置约定，不是实际除以零。

原始模型概率与处理后的采样概率需要区分：

$$ P_{\mathrm{raw}}=\operatorname{softmax}(z), $$

$$ P_{\mathrm{sample}} = \operatorname{Normalize} \left( \operatorname{Filter} \left(\exp(z_{\mathrm{processed}}/\tau)\right) \right). $$

返回的 logprobs 采用原始还是处理后的分布，要查看接口配置；不能默认等于实际采样分布。

### 6.6 候选通信优化的边界

- Greedy：每卡取局部最大值及全局 token ID，交换二元组后取全局最大值。须统一 tie-break 规则。
- Top-k：每卡保留本地 top-k，再从合并候选中选全局 top-k；候选不能进入本地 top-k 时，已有至少 $k$ 个本地候选排在其前面。
- Top-p：不能直接把每卡局部 top-p 的结果合并，当作全局 top-p；阈值依赖全局概率质量。
- 复杂 logits processors、logprob 返回等要求可能限制专用优化路径。

vLLM 已核对的 get_top_tokens 具有局部 argmax 二元组汇集入口，但是否启用要查看调用方。

### 6.7 Padding 与 token 一致性

词表补齐位置不是有效 token，必须裁掉或屏蔽为 $-\infty$。即便 padding 权重为零，也可能产生 0 分，超过所有负分的真实 token。

同一请求的下一步 token 必须在 TP 组内保持一致：

- 可由一个 rank 采样，再分发 token IDs。
- 也可在完整 logits 副本上协调采样状态，使各 rank 得到相同结果。
- 相同概率分布并不保证随机结果相同；随机状态、调用顺序及算子行为也必须协调。
- “每步必定广播一次结果”不是所有框架的固定行为。已核对的 SGLang 路径默认依赖一致性，并在指定配置或 grammar 情况下显式同步 token IDs。

刚采样的 token 通常尚未拥有自己的 KV；下一轮实际消费它时，才逐层产生并写入 K/V。

### 7. 串起完整 Decoder

### 7.1 Pre-Norm 层的数学定义

对第 $\ell$ 层：

$$ \widehat X_\ell=\operatorname{Norm}_1(X_\ell), $$

$$ A_\ell=\operatorname{Attention}(\widehat X_\ell), \qquad U_\ell=X_\ell+A_\ell, $$

$$ F_\ell=\operatorname{MLP}(\operatorname{Norm}_2(U_\ell)), $$

$$ \boxed{X_{\ell+1}=U_\ell+F_\ell}. $$

每层两次归一化、两个子层、两次残差相加。

### 7.2 RMSNorm 与完整 hidden states

对单个 token：

$$ \operatorname{RMSNorm}(x)_j = \gamma_j \frac{x_j} {\sqrt{\frac1D\sum_{k=0}^{D-1}x_k^2+\epsilon}}. $$

它依赖该 token 的全部 hidden features，但不依赖其他 token。普通 TP 在这些位置已有完整 hidden states，Norm 权重 $\gamma:[D]$ 也在各卡复制，因此可直接本地计算。

若当前只有行并行的局部贡献，必须先按数学关系完成归约；一般不能对各贡献分别做 RMSNorm 后再相加。

每层的两份 Norm 参数彼此独立，且不同层的 Norm 参数也独立；“复制”指同一参数在 TP ranks 上具有副本，不是各层共用一份参数。

### 7.3 单层布局与通信

| 阶段 | 本地结果 | 状态 / 操作 |
| --- | --- | --- |
| 输入、input RMSNorm | [N,D] | 完整副本 |
| QKV、RoPE | 本地 Q/K/V heads | 分片或所需 KV 副本 |
| 本地 Attention | [N,(H_q/p)d] | 本地 Q-head 输出分片 |
| 输出投影 | [N,D] | 局部贡献 |
| Attention 归约 | [N,D] | AllReduce 得到完整 A_l |
| 残差与第二个 RMSNorm | [N,D] | 本地形成并归一化 U_l |
| gate/up、SwiGLU | [N,F/p] | 中间特征分片 |
| down | [N,D] | 局部贡献 |
| MLP 归约 | [N,D] | AllReduce 得到完整 F_l |
| 残差相加 | [N,D] | 完整下一层输入 |

下一层的列并行 QKV 可以直接读取完整输入，因为上一层子层归约及残差处理已恢复完整布局，不必再为此广播 hidden states。

### 7.4 残差不能在每卡局部贡献上重复计入

正确关系：

$$ U_\ell=X_\ell+\sum_rA_{\ell,r}. $$

若各卡都先加完整残差，再归约：

$$ \sum_r(X_\ell+A_{\ell,r})=pX_\ell+A_\ell, $$

就会重复计入残差。最直接的基线顺序是归约后本地加一次；融合实现可以改变执行组织，但不能改变此数学关系。

### 7.5 vLLM 的 hidden_states / residual 二元组

带 residual 的 Add + RMSNorm 可以按以下语义理解：

$$ r_{\mathrm{new}}=h+r, \qquad h_{\mathrm{new}}=\operatorname{Norm}(r_{\mathrm{new}}). $$

返回的是“归一化后的子层输入”和“未归一化的残差流”。

第一层从 Embedding 输入开始，源码变量含义为：

| 时刻 | hidden_states | residual |
| --- | --- | --- |
| Embedding 后 | X_0 | None |
| input RMSNorm 后 | Norm1(X_0) | X_0 |
| Attention 后 | A_0 | X_0 |
| post-attention Add + RMSNorm 后 | Norm2(U_0) | U_0=X_0+A_0 |
| MLP 后并返回 | F_0 | U_0 |

所以 Decoder 返回时，hidden_states 单独不等于逻辑层输出，两者之和才是：

$$ X_1=F_0+U_0. $$

这个加法可延后到下一层 input RMSNorm 中融合执行。最后一层没有下一层，则由模型末尾 final RMSNorm 完成最后的残差相加及归一化。

**延后残差相加，与延后 TP 归约是两件事。** 在上表所讨论的 vLLM 基线中，$A_\ell,F_\ell$ 已是跨卡归约后的完整子层输出。不要把二元组中的 hidden_states 错认成未归约的局部贡献。

### 7.6 全模型入口与出口

$$ \text{token IDs} \longrightarrow \text{Embedding} \longrightarrow \text{Decoder}_{0\ldots n_\ell-1} \longrightarrow \text{Final Norm} \longrightarrow \text{LM Head} \longrightarrow \text{Sampling}. $$

这里的箭头只描述逻辑数据流，不要求模型 forward 函数在代码里包含采样。vLLM 将模型 hidden-state 前向、compute_logits 和 sampler 分开组织。

### 8. 多 rank 执行契约、权重加载与通信边界

### 8.1 输入与 collective 必须对应

同一 TP group 内，各 rank 必须对同一批逻辑工作达成一致，包括：

- 请求 / token 的行顺序。
- token IDs、positions、序列边界、有效上下文长度。
- 正确的逻辑 KV block / slot 对应关系。
- collective 的参与组、调用顺序及对应张量含义。

AllReduce 只对对应元素进行运算，不知道请求身份。即使 shape 相同，行顺序不一致也会把不同请求的贡献混在一起。

各卡缓存物理地址可以不同，head 内容也可以不同；要求的是每卡的本地存储对应正确请求、层、head 和 token 位置，不要求跨设备地址数值一致。

TP 通信只属于相应 TP group，不应无条件使用整个作业的 world group；与其他并行策略组合时尤其需要区分。

### 8.2 权重通常在加载时分片，前向使用常驻权重

| 参数 | 加载要求 |
| --- | --- |
| 列并行权重 | 选择本地输出特征 |
| 行并行权重 | 选择本地输入特征 |
| QKV | 分别选取 Q/K/V heads；K/V 必要时复制 |
| gate/up | 分别选取相同中间通道，再组织 packed 权重 |
| Embedding / LM Head | 选择本地词表行并正确处理 padding |
| RMSNorm | 同一参数在各 TP ranks 保存完整副本 |

普通前向不是每层重新切分、传输全量权重，而是使用各 rank 已加载的分片。量化、特殊 checkpoint 格式及已分片权重还可能需要专用 loader。

### 8.3 基础通信计数

对 $p>1$、未融合、普通布局的全模型前向：

| 位置 | 逻辑通信 |
| --- | --- |
| Vocab Parallel Embedding | 一次输出求和 |
| 每层 Attention 输出投影后 | 一次求和 |
| 每层 MLP down 后 | 一次求和 |
| LM Head 后 | logits Gather / AllGather，或专用候选 / 统计量通信 |
| 采样结果进入下一轮 | 依赖执行组织保证一致 |

因此基础路径可先记录 $2n_\ell+1$ 次 AllReduce，再单独记录 logits 与 token IDs 相关通信。不要把它当作任意优化配置下的实际 API 或 kernel 调用次数。

集合通信的依赖要求最终消费者看到正确完成的数据，不意味着 Host 必须在每处调用设备全局同步。异步执行、通信流和事件可以表达依赖；不要将逻辑归约边界等同于 CPU 阻塞边界。

### 8.4 Prefill / decode 的共同结构与不同工作量

两者遵守相同的层公式、权重分配与基本归约位置；不同的是 token 行数、Attention 的 query/key 长度和缓存更新量。

- Prefill 通常处理更多当前 token；若复用前缀，还会读取已有缓存。
- 普通 decode 每请求通常处理一个当前位置，读取历史 KV 并追加当前 K/V。
- 逻辑上，每层 K/V 独立保存；跨层可能沿用同一逻辑 block 编号，但数据不是同一份。
- 当前 hidden states 沿层流动，KV cache 跨生成步骤保留。

TP 不保证卡数翻倍就速度翻倍。每卡矩阵规模、通信延迟 / 带宽、token 数、KV 复制、内核效率等共同决定收益。KV 数据量的计算也不等于实际 HBM 读取量或性能加速比。

### 10. 易错点速查

| 易错理解 | 应采用的理解 |
| --- | --- |
| Column Parallel 就是切 PyTorch 权重列 | 名称按数学矩阵定义；普通权重实际切第 0 维 |
| 行并行输出 shape 完整，所以数值已完整 | 本地输出是完整结果的局部求和项 |
| 每个列并行后都要 AllGather | 后续行并行可直接消费分片 |
| gate/up 或 QKV 合并后直接连续均分即可 | 各投影分别分片，再形成正确本地 packed 布局 |
| Embedding 与 LM Head 权重形状相同，通信也相同 | 前者输出求和，后者词表 logits 拼接 |
| 普通 Attention TP 切的是序列 token | 本笔记的普通 TP 切 heads，各 head 保持所需上下文 |
| 多卡 Attention 每步都要交换历史 KV cache | 普通 head TP 的所需 KV 历史在本地分片或副本中可用；输出 AllReduce 汇总的是激活贡献 |
| softmax 必须看到其他卡的 heads | softmax 沿本 head 的 key 位置归一化 |
| 所有 KV cache 都能按 TP 继续缩小 | TP 超过 KV heads 时，普通策略复制 KV |
| 共享 KV 意味着多个 Q heads 的输出相同 | 不同 query 仍产生不同权重与输出 |
| GQA 的 packed QKV 总宽度总能直接除以 TP | 有 KV 复制时，应分别计算本地 Q/K/V 宽度 |
| 各卡局部 softmax 后独立采样即可 | 需要全局概率质量和正确的跨卡选择规则 |
| padding 权重为零就不可能被采样 | 0 分可能超过负分真实 token，必须排除 |
| 同一随机分布保证各 rank 选出同一 token | 还需协调随机状态或显式分发 / 同步结果 |
| Decoder 返回的 hidden_states 单独就是层输出 | 融合残差路径可能需要与 residual 相加解释 |
| Norm 参数复制意味着所有层共用参数 | 是同一层同一参数在不同 TP ranks 上复制 |
| AllReduce 必须在每处让 CPU 全局同步设备 | 正确数据依赖可以由异步流、事件和后端组织保证 |
| 新 token 一经采样就已有 KV | 下一轮消费它时才产生对应 K/V |
