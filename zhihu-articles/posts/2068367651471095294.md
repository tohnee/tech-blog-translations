## 6.1 DDP 原理（梯度同步 / bucket / overlap）

### 6.1.1 DDP 设计目标与定位

DistributedDataParallel（DDP）是 PyTorch 多 GPU 训练的”主力军”，它的设计目标只有一个：**让多 GPU 训练像单 GPU 一样写代码，且接近线性加速**。DDP 的核心假设是：

- 模型参数能完整放进单卡（< 单卡显存的 50%，留空间给 activation / optimizer state）；
- 数据并行（Data Parallelism）：每个 GPU 持有完整模型副本，处理不同 batch；
- 同步 SGD：所有 GPU 在 backward 后同步梯度，保证参数一致性。

![](https://pic2.zhimg.com/v2-182c4beabb23e4c52909b6d44e913105_r.jpg)

DDP 不分片参数——每个 rank 持有完整的 `model.parameters()`。这保证了：

| 维度 | DDP 行为 |
| --- | --- |
| 参数 | 每个 rank 一份完整副本 |
| 梯度 | 每个 rank 各算一份，backward 后 all-reduce 平均 |
| 优化器状态 | 每个 rank 一份（冗余，但无通信） |
| 激活 | 每个 rank 独立（数据并行） |
| 单 step 通信量 | O(参数量 × dtype 字节)（一次 all-reduce） |
| 单 step 显存 | 参数 + 梯度 + optimizer + 激活（无分片） |

### 6.1.2 梯度同步：all-reduce 语义

DDP 的核心操作是 **all-reduce**：N 个 rank 各持有一个梯度张量 `g_i`，all-reduce 后所有 rank 都得到 `g_0 + g_1 + ... + g_{N-1}`。配合 `loss = loss / N`（DDP 自动做 `loss / world_size` 隐含在 backward scaling，但实际是手动 `loss.mean()`），最终 SGD 更新等价于”用 N 个 batch 的平均梯度更新一份参数”。

NCCL 实现的 all-reduce 有两种主要算法：

| 算法 | 拓扑 | 带宽利用率 | 延迟 | 适用规模 |
| --- | --- | --- | --- | --- |
| Ring | 环形 | (N-1)/N 接近 1 | 较高（2(N-1) 步） | 中大规模（≥4 GPU） |
| Tree | 树形 | 较低（汇聚到 root 再广播） | 低（log N 步） | 小规模（2-4 GPU）或最后融合 |
| CollNet | NVSwitch | 接近线性 | 最低 | DGX A100/H100 NVSwitch 拓扑 |

NCCL 自动选择算法，可通过 `NCCL_ALGO=Ring/Tree/CollNet` 强制。Ring 是默认主力：

![](https://pic4.zhimg.com/v2-4cca21f9b69e1c859c9f6a09c14a1115_r.jpg)

Ring all-reduce 分两个阶段：

1. **Scatter-reduce**（N-1 步）：每个 rank 沿环传递分块累加，N-1 步后每个 rank 持有 sum 的一部分；
2. **All-gather**（N-1 步）：每个 rank 把持有的 sum 部分沿环广播，N-1 步后所有 rank 持有完整 sum。

**关键性质**：通信量与 rank 数 N 无关——每 rank 发送 `2(N-1)/N × |grad|` ≈ `2|grad|`。这是 DDP 接近线性加速的数学基础。

### 6.1.3 Bucket 机制：分桶通信

如果把所有参数当成一个超大张量做一次 all-reduce，会浪费宝贵的 overlap 机会——必须等所有参数 grad 都算完才能通信。DDP 的解法是 **bucket**：把参数分成多个桶，**每个 bucket 满了就立即触发 all-reduce，与剩余 bucket 的 backward 计算并行**。

![](https://pic2.zhimg.com/v2-770a6058735ed92b371ae9be51ea293d_r.jpg)

**Bucket 默认大小**：25 MB（`bucket_cap_mb=25`），这是经验值。在 PyTorch 2.5+ 可通过 `DistributedDataParallel(model, bucket_cap_mb=...)` 调整。

**Bucket 调度规则**：

| 规则 | 说明 |
| --- | --- |
| 按参数反向顺序组装 | backward 从后往前算，bucket 也按从后往前组装 |
| 一个 bucket 的所有 grad 都 ready 后才 reduce | 保证一致性，避免部分 reduce |
| 一次 all-reduce 整个 bucket | 减少 NCCL 调用次数，摊薄 launch overhead |
| 不同 bucket 之间串行 | NCCL stream 内串行，但与计算 stream 并行 |

**Bucket 大小 trade-off**：

| Bucket 大小 | 优点 | 缺点 |
| --- | --- | --- |
| 太小（ MB） | 通信启动早，overlap 多 | NCCL 调用次数多，launch overhead 大 |
| 适中（25 MB） | 平衡 | 默认推荐 |
| 太大（>256 MB） | launch overhead 摊薄 | overlap 机会少，峰值通信显存大 |

### 6.1.4 通信反向重叠（overlap）

DDP 最核心的性能优化就是 **通信与反向计算的 overlap**。要理解它，先看不做 overlap 的”naive DDP”长什么样：

```text
# naive 实现（不要这么写）
loss = model(x)
loss.backward()           # 完整 backward，所有 grad 都算完
torch.distributed.barrier()  # 显式同步
all_reduce_all_grads()    # 一次性 all-reduce 所有 grad
optimizer.step()
```

这种实现下，通信时间 T_comm 和反向时间 T_backward 完全串行，step 总时间 = `T_forward + T_backward + T_comm + T_opt`。在大模型上 `T_comm` 接近 `T_backward`，浪费严重。

DDP 的解法是 **autograd hook + bucket**：在 backward 过程中，每个参数 grad 计算完后，DDP 注册的 hook 检查它所在的 bucket 是否”满”——满了就立刻在 NCCL stream 上启动 all-reduce。由于 NCCL stream 与 default compute stream 是两个独立 stream，all-reduce 与剩余 backward 在 GPU 上并行执行：

![](https://pic1.zhimg.com/v2-7b59d09c91f9acffabc09dcff059589e_r.jpg)

可以看到，3 个 bucket 的 all-reduce 几乎完全 overlap 在 backward 内部，**只有第一个 bucket 的等待时间与最后一个 bucket 的收尾时间是串行开销**。在大模型上 overlap 率可达 70-90%。

### 6.1.5 DDP 完整代码示例

下面是生产级 DDP 训练脚本，覆盖 init_process_group、DistributedSampler、DDP wrap、AMP、checkpoint：

```text
# train_ddp.py
import os
import argparse
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data import DataLoader, DistributedSampler
from torch.cuda.amp import GradScaler, autocast  # 2.5+ 推荐用 torch.amp

def setup_distributed():
    """torchrun 会注入 RANK / WORLD_SIZE / LOCAL_RANK 环境变量"""
    dist.init_process_group(backend="nccl")
    local_rank = int(os.environ["LOCAL_RANK"])
    torch.cuda.set_device(local_rank)
    return local_rank

def cleanup():
    dist.destroy_process_group()

class ToyModel(nn.Module):
    def __init__(self, dim=2048, layers=12):
        super().__init__()
        self.embed = nn.Linear(dim, dim)
        self.blocks = nn.ModuleList([
            nn.Sequential(
                nn.Linear(dim, dim * 4), nn.GELU(), nn.Linear(dim * 4, dim)
            ) for _ in range(layers)
        ])
        self.head = nn.Linear(dim, 1000)

    def forward(self, x):
        x = self.embed(x)
        for block in self.blocks:
            x = x + block(x)
        return self.head(x)

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--epochs", type=int, default=10)
    parser.add_argument("--batch-size", type=int, default=64)
    parser.add_argument("--bucket-cap-mb", type=int, default=25)
    args = parser.parse_args()

    local_rank = setup_distributed()
    rank = dist.get_rank()
    world_size = dist.get_world_size()
    device = torch.device(f"cuda:{local_rank}")

    # 模型：先放到本 rank 的 GPU，再 DDP wrap
    model = ToyModel().to(device)
    model = DDP(
        model,
        device_ids=[local_rank],
        output_device=local_rank,
        bucket_cap_mb=args.bucket_cap_mb,
        # find_unused_parameters=True 当模型有未参与 backward 的参数时开启
        # static_graph=True 当计算图静态时开启，提升 overlap 调度
    )

    # 数据：DistributedSampler 保证各 rank 看到不同数据
    dataset = torch.utils.data.TensorDataset(
        torch.randn(10000, 2048), torch.randint(0, 1000, (10000,))
    )
    sampler = DistributedSampler(dataset, shuffle=True)
    loader = DataLoader(
        dataset, batch_size=args.batch_size, sampler=sampler,
        num_workers=4, pin_memory=True, drop_last=True,
    )

    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
    scaler = GradScaler()  # AMP 见 ch7

    for epoch in range(args.epochs):
        sampler.set_epoch(epoch)  # 关键！保证每个 epoch 数据洗牌不同
        model.train()
        for step, (x, y) in enumerate(loader):
            x = x.to(device, non_blocking=True)
            y = y.to(device, non_blocking=True)

            optimizer.zero_grad(set_to_none=True)
            with autocast(dtype=torch.bfloat16):  # 2.5+ 推荐 torch.amp.autocast
                out = model(x)
                loss = nn.functional.cross_entropy(out, y)
            # BF16 不需要 scaler；FP16 才需要
            loss.backward()
            optimizer.step()

            if step % 50 == 0 and rank == 0:
                print(f"epoch {epoch} step {step} loss {loss.item():.4f}")

    # 保存 checkpoint：只 rank 0 保存，避免重复
    if rank == 0:
        torch.save(model.module.state_dict(), "model.pt")
    cleanup()

if __name__ == "__main__":
    main()
```

启动方式：

```text

# 或 mp.spawn（旧式，仍可用）

```

### 6.1.6 static_graph 与 find_unused_parameters

DDP 的两个高级开关：

**`find_unused_parameters=True`**：当模型有**条件分支**导致某些参数在某些 step 不参与 backward 时，必须开启。DDP 会预先跑一次 forward 检测未使用参数，把它们标记为 ready，避免 all-reduce 死锁。

```text
class CondModel(nn.Module):
    def forward(self, x, use_head):
        if use_head:
            return self.head_a(x)
        else:
            return self.head_b(x)  # head_a 在该 step 未使用

# 必须开 find_unused_parameters，否则 DDP 等不到 head_a 的 grad
model = DDP(model, find_unused_parameters=True)
```

代价：每次 forward 额外遍历计算图，有 5-15% overhead。

**`static_graph=True`**（2.0+）：当计算图在所有 step 间**静态不变**时开启。DDP 第一次 backward 后记录 bucket 调度顺序，后续 step 直接复用，省去每 step 的图遍历：

```text
model = DDP(model, static_graph=True)
```

| 场景 | find_unused_parameters | static_graph | 性能影响 |
| --- | --- | --- | --- |
| 静态图，所有参数都参与 backward | False | True（推荐） | 最快 |
| 动态图，部分参数偶尔不参与 | True | False | 慢 5-15% |
| 静态图，部分参数稳定不参与 | False | True（DDP 推断未使用参数） | 较快 |
| 动态图 + 频繁变化 | True | False | 最慢，但安全 |

**注意**：`find_unused_parameters=True` 与 `static_graph=True` **不能同时为 True**（2.5+ 报错）。

### 6.1.7 DDP 性能基线

下面是 H100 80GB SXM × 8 上一个 1B 参数 Transformer 模型的 DDP 训练基线（per step）：

| 配置 | forward | backward | comm (NCCL) | overlap 率 | 总 step |
| --- | --- | --- | --- | --- | --- |
| naive（无 overlap） | 95 ms | 180 ms | 145 ms | 0% | 420 ms |
| DDP 默认（25 MB bucket） | 95 ms | 180 ms | 145 ms | 78% | 230 ms |
| DDP + static_graph | 95 ms | 178 ms | 145 ms | 82% | 220 ms |
| DDP + bucket_cap=128 MB | 95 ms | 180 ms | 142 ms | 71% | 245 ms |
| DDP + BF16（前向后向） | 52 ms | 98 ms | 78 ms | 80% | 135 ms |

可以看到 overlap 让 DDP 接近”通信免费”，BF16 进一步压缩通信量。但**当模型大到单卡装不下时，DDP 失效**——这就是 FSDP 的舞台。

## 6.2 FSDP / FSDP2（参数分片 / prefetch / offload）

### 6.2.1 为什么需要 FSDP：DDP 的显存瓶颈

回到 ch5 的显存构成表，对一个 7B 参数模型（FP16 weight + FP32 optimizer）：

| 组成 | DDP（每卡） | 比例 |
| --- | --- | --- |
| Weights (FP16) | 14 GB | 11% |
| Gradients (FP16) | 14 GB | 11% |
| AdamW m/v (FP32) | 56 GB | 44% |
| Activations | 40 GB | 31% |
| Workspace | 3 GB | 3% |
| 总计 | 127 GB | 100% |

DDP 下每张卡都要装 127 GB，A100 80GB 装不下，H100 80GB 也装不下。即使把 activation checkpointing 砍到 5 GB，仍是 87 GB——**单卡装不下整个模型+优化器**。

FSDP（Fully Sharded Data Parallel）的解法：**把参数、梯度、optimizer state 切片分散到所有 rank 上，每张卡只保存 1/N**。前向/反向时通过 all-gather 临时聚合参数，用完立刻释放。

### 6.2.2 FSDP 原理：参数分片 + all-gather

FSDP 的核心思想与 ZeRO-3 等价（详见 6.3），但 PyTorch 实现上是独立路径。一个 FSDP step 的执行流：

![](https://pic2.zhimg.com/v2-368740b8303ea62b42654f80a83c063d_r.jpg)

**单 step 通信量**：2 次完整参数传递（all-gather + reduce-scatter），是 DDP 的 2 倍。**单卡显存**：参数 + 优化器状态均分到 N 卡：

| 阶段 | DDP（每卡） | FSDP（每卡，N=8） |
| --- | --- | --- |
| Weights | 14 GB | 1.75 GB |
| Gradients（瞬时） | 14 GB | 1.75 GB（shard）+ 14 GB（all-gather 临时） |
| AdamW m/v | 56 GB | 7 GB |
| Activations | 40 GB | 40 GB |
| Workspace | 3 GB | 5 GB（all-gather buffer） |
| 峰值 | 127 GB | ~58 GB |

FSDP 把 7B 模型从 127 GB 降到 58 GB，A100 80GB 轻松装下。

### 6.2.3 FSDP 核心配置：ShardingStrategy

PyTorch 2.5 提供四种 sharding 策略，对应不同的显存/通信 trade-off：

```text
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP, ShardingStrategy

FSDP(model, sharding_strategy=ShardingStrategy.FULL_SHARD)
```

| 策略 | 等价 ZeRO | 分片对象 | 通信量（相对 DDP） |
| --- | --- | --- | --- |
| FULL_SHARD | ZeRO-3 | params + grads + optimizer | 2.0x |
| SHARD_GRAD_OP | ZeRO-2 | grads + optimizer | 1.5x |
| _HYBRID_SHARD_ZERO2 | ZeRO-2 intra-node + DDP inter | 节点内分片，节点间 DDP | 1.2x |
| _HYBRID_SHARD | ZeRO-3 intra-node + DDP inter | 节点内全分片，节点间 DDP | 1.6x |

实战经验：

- **模型小（<2B）**：用 DDP，最简单最快；
- **模型中（2-13B）**：`SHARD_GRAD_OP` 或 `_HYBRID_SHARD_ZERO2`，通信开销小；
- **模型大（13B+）**：`FULL_SHARD`，必要时 `_HYBRID_SHARD` 减少跨节点通信；
- **超大模型（70B+）**：`FULL_SHARD` + TP/PP，见 6.5。

### 6.2.4 Mixed precision 与 FSDP

FSDP 的 mixed precision 配置复杂，分四个独立维度：

```text
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP, MixedPrecision

mp_policy = MixedPrecision(
    param_dtype=torch.bfloat16,        # 前向/反向计算时参数 cast 到的 dtype
    reduce_dtype=torch.bfloat16,       # reduce-scatter 通信时的 dtype
    buffer_dtype=torch.bfloat16,       # non-parameter buffer（如 BN running stats）
    keep_low_precision_grads=False,    # True 时 grad 保持 bf16，省显存但精度损失
)

FSDP(model, mixed_precision=mp_policy)
```

**关键坑**：FSDP 内部始终保留一份 FP32 master weight 用于 optimizer step。`param_dtype` 只影响前向/反向的临时 cast。这意味着 FSDP 的实际显存：

| 组成 | FSDP（param=bf16, optimizer=fp32, N=8） | 大小 |
| --- | --- | --- |
| Param shard (FP32 master) | 7B × 4B / 8 | 3.5 GB |
| Param 临时 (BF16) | 7B × 2B（all-gather 后） | 14 GB |
| Grad shard (BF16) | 7B × 2B / 8 | 1.75 GB |
| Grad 临时 (BF16) | 7B × 2B | 14 GB |
| AdamW m/v (FP32) | 7B × 8B / 8 | 7 GB |
| Activations | 同 DDP | 40 GB |
| 峰值 |  | ~80 GB |

注意峰值仍接近 80 GB，主要来自 all-gather 的临时完整 param + activation。生产环境通常配合 gradient checkpointing 把 activation 压到 5-10 GB。

### 6.2.5 prefetch 与 offload

**prefetch**：FSDP 在 backward 时，**当前 layer 的 all-gather 与上一层 backward 计算并行**——把”通信开销藏到计算里”，类似 DDP 的 overlap。

```text
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp import CPUOffload

FSDP(
    model,
    prefetch_level=2,  # 2=backward 全 prefetch（默认 1）
    forward_prefetch=True,  # 前向也 prefetch 下一层参数
)
```

| prefetch 配置 | 通信重叠 | 显存峰值 | 适用 |
| --- | --- | --- | --- |
| prefetch_level=1（默认） | 部分 overlap | 较低 | 显存紧 |
| prefetch_level=2 | 全 overlap | 高（同时持有 N 层 param） | 显存够 |
| forward_prefetch=True | 前向也 overlap | 更高 | 计算密集型 |

**CPUOffload**：把参数 shard 卸载到 CPU 内存，GPU 显存不够时启用。代价是 all-gather 时需要 H2D 拷贝，慢 3-10 倍。

```text
FSDP(model, cpu_offload=CPUOffload(offload_params=True))
```

| 场景 | CPUOffload | 速度 | 显存 |
| --- | --- | --- | --- |
| 模型 < GPU 显存的 50% | False | 最快 | GPU 全装 |
| 模型 ≈ GPU 显存 | False + gradient checkpointing | 较快 | GPU 装下 |
| 模型 > GPU 显存但 < CPU 内存 | True | 慢 3-10x | GPU 仅装 activation |

### 6.2.6 FSDP 完整代码示例

下面是一个生产级 FSDP 训练脚本，覆盖 sharding strategy、mixed precision、checkpoint、activation checkpointing：

```text
# train_fsdp.py
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.fsdp import (
    FullyShardedDataParallel as FSDP,
    ShardingStrategy, MixedPrecision, CPUOffload,
    FullStateDictConfig, StateDictType,
)
from torch.distributed.fsdp.wrap import (
    size_based_auto_wrap_policy, transformer_auto_wrap_policy,
)
from torch.utils.data import DataLoader, DistributedSampler
from functools import partial
import torch.utils.checkpoint as cp

def setup():
    dist.init_process_group("nccl")
    return int(os.environ["LOCAL_RANK"])

class TransformerBlock(nn.Module):
    def __init__(self, dim=4096, heads=32):
        super().__init__()
        self.norm1 = nn.LayerNorm(dim)
        self.attn = nn.MultiheadAttention(dim, heads, batch_first=True)
        self.norm2 = nn.LayerNorm(dim)
        self.ffn = nn.Sequential(
            nn.Linear(dim, dim * 4), nn.GELU(), nn.Linear(dim * 4, dim)
        )

    def forward(self, x):
        # activation checkpointing
        def attn_ffn(h):
            h = h + self.attn(*[self.norm1(h)] * 3, need_weights=False)[0]
            h = h + self.ffn(self.norm2(h))
            return h
        return cp.checkpoint(attn_ffn, x, use_reentrant=False)

class BigModel(nn.Module):
    def __init__(self, dim=4096, layers=32, vocab=32000):
        super().__init__()
        self.embed = nn.Embedding(vocab, dim)
        self.blocks = nn.ModuleList([TransformerBlock(dim) for _ in range(layers)])
        self.head = nn.Linear(dim, vocab)

    def forward(self, x):
        h = self.embed(x)
        for block in self.blocks:
            h = block(h)
        return self.head(h)

def main():
    local_rank = setup()
    torch.cuda.set_device(local_rank)
    device = torch.device(f"cuda:{local_rank}")

    model = BigModel().to(device)

    # Mixed precision：前向/反向 BF16，optimizer FP32 master
    mp = MixedPrecision(
        param_dtype=torch.bfloat16,
        reduce_dtype=torch.bfloat16,
        buffer_dtype=torch.bfloat16,
    )

    # auto wrap：参数量 > 1M 的 module 单独 wrap 成 FSDP unit
    auto_wrap = partial(size_based_auto_wrap_policy, min_num_params=1_000_000)

    model = FSDP(
        model,
        sharding_strategy=ShardingStrategy.FULL_SHARD,
        mixed_precision=mp,
        auto_wrap_policy=auto_wrap,
        cpu_offload=CPUOffload(offload_params=False),
        forward_prefetch=True,
        backward_prefetch=None,  # 默认 BACKWARD_PRE，等价 prefetch_level=2
        limit_all_gathers=True,  # 防止 all-gather 过多 OOM
        use_orig_params=True,  # 保留原始参数名，便于 state_dict
    )

    dataset = torch.utils.data.TensorDataset(
        torch.randint(0, 32000, (10000, 512)),
        torch.randint(0, 32000, (10000, 512)),
    )
    sampler = DistributedSampler(dataset)
    loader = DataLoader(dataset, batch_size=4, sampler=sampler, pin_memory=True)

    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

    for epoch in range(2):
        sampler.set_epoch(epoch)
        model.train()
        for x, y in loader:
            x = x.to(device, non_blocking=True)
            y = y.to(device, non_blocking=True)
            optimizer.zero_grad(set_to_none=True)
            # BF16 autocast 与 FSDP mixed_precision 配合：autocast 优先
            with torch.amp.autocast("cuda", dtype=torch.bfloat16):
                out = model(x)
                loss = nn.functional.cross_entropy(out.view(-1, out.size(-1)), y.view(-1))
            loss.backward()
            optimizer.step()

    # 保存 checkpoint：FSDP 需要特殊 state_dict 流程
    cfg = FullStateDictConfig(offload_to_cpu=True, rank0_only=True)
    with FSDP.state_dict_type(model, StateDictType.FULL_STATE_DICT, cfg):
        state = model.state_dict()
        if dist.get_rank() == 0:
            torch.save(state, "fsdp_model.pt")

    dist.destroy_process_group()

if __name__ == "__main__":
    main()
```

启动：`torchrun --nproc_per_node=8 train_fsdp.py`。

### 6.2.7 FSDP2：新的架构（per-parameter sharding）

FSDP2 是 PyTorch 2.4+ 引入的全新实现，2.5+ 进入稳定 preview。核心变化：

| 维度 | FSDP（旧） | FSDP2（新） |
| --- | --- | --- |
| 分片单元 | module（FSDP unit） | 单个 tensor（per-parameter） |
| 实现机制 | nn.Module 包装 | DTensor + custom op hook |
| state_dict | 需要 state_dict_type context | 原生支持 |
| torch.compile | 兼容性差 | 原生兼容 |
| memory efficient | 需 use_orig_params=True | 默认 |
| HiP 抽象 | flat param | DTensor |
| API 入口 | FSDP(module) | fully_shard(module) |

FSDP2 的 API 入口是 `fully_shard`，从 `torch.distributed.fsdp` 模块导入：

```text
from torch.distributed.fsdp import fully_shard
import torch.nn as nn

model = BigModel().to(device)
# 逐层 shard：每层是一个 shard unit
for block in model.blocks:
    fully_shard(block)
# 整体 shard
fully_shard(model)
```

FSDP2 的核心优势：

1. **更细粒度的 overlap**：per-parameter 分片，all-gather/reduce-scatter 可以更细粒度地与计算 overlap；
2. **原生 DTensor 集成**：参数本身就是 DTensor，与 TP/PP/SP 等模型并行无缝协作（见 6.5）；
3. **torch.compile 友好**：FSDP1 的 flat param 与 compile 兼容性差，FSDP2 通过 DTensor 与 inductor 良好集成；
4. **更简单的 state_dict**：不再需要 `StateDictType.FULL_STATE_DICT` context，直接 `state_dict()` 即可。

FSDP2 完整示例：

```text
# train_fsdp2.py (PyTorch 2.5+)
import os, torch
import torch.distributed as dist
from torch.distributed.fsdp import fully_shard
from torch.distributed.device_mesh import init_device_mesh

def setup():
    dist.init_process_group("nccl")
    return int(os.environ["LOCAL_RANK"])

def main():
    local_rank = setup()
    torch.cuda.set_device(local_rank)
    device = torch.device(f"cuda:{local_rank}")

    model = BigModel().to(device=device, dtype=torch.bfloat16)

    # 1. 创建 1D device mesh
    mesh = init_device_mesh("cuda", (dist.get_world_size(),))

    # 2. 逐层 fully_shard（细粒度 overlap）
    for block in model.blocks:
        fully_shard(block, mesh=mesh)
    fully_shard(model, mesh=mesh)

    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

    # ... 训练循环与 FSDP1 类似 ...
    # state_dict 直接拿
    state = model.state_dict()
    if dist.get_rank() == 0:
        torch.save(state, "fsdp2_model.pt")

    dist.destroy_process_group()
```

### 6.2.8 FSDP vs FSDP2 选择

| 场景 | 推荐 |
| --- | --- |
| 已有 FSDP1 训练脚本 | 2.5+ 暂保持 FSDP1，等 2.6+ FSDP2 完全稳定再迁移 |
| 全新项目，PyTorch 2.5+ | FSDP2（preview，可用，遇到 bug 报社区） |
| 需要 torch.compile + FSDP | FSDP2（兼容性远好于 FSDP1） |
| 需要 TP/PP/SP 混合并行 | FSDP2（DTensor 原生支持） |
| 模型 < 13B | FSDP1 或 FSDP2 均可 |
| 模型 ≥ 70B | FSDP2（FSDP1 flat param 在大模型上不稳定） |

## 6.3 ZeRO 1/2/3（与 FSDP 对比）

### 6.3.1 ZeRO 论文与三阶段

ZeRO（Zero Redundancy Optimizer）是微软 DeepSpeed 团队在 2019 年提出的显存优化算法（论文 *ZeRO: Memory Optimizations Toward Training Trillion Parameter Models*）。它把 DDP 中”每个 rank 持有完整副本”的冗余拆解为三个独立维度，按需分片：

| 阶段 | 分片对象 | 单卡显存（7B 模型, N=8） | 通信量（相对 DDP） |
| --- | --- | --- | --- |
| ZeRO-0 | 无（不开 ZeRO） | 127 GB | 1.0x |
| ZeRO-1 | Optimizer state | 127 - 56(7⁄8) = 78 GB | 1.0x（通信不变） |
| ZeRO-2 | + Gradient | 78 - 14(7⁄8) = 65 GB | 1.5x |
| ZeRO-3 | + Parameter | 65 - 14(7⁄8) = 51 GB | 2.0x |

ZeRO 的精妙之处在于：**显存省到极致时，通信量也只翻 2 倍，且能被 overlap 大部分吸收**。

### 6.3.2 ZeRO-1：optimizer state 分片

ZeRO-1 只分片 optimizer state（AdamW 的 m/v，FP32），不动 gradient 和 parameter：

![](https://pic4.zhimg.com/v2-3884d8b69e0f8161f303f2e3bd4c5aed_r.jpg)

**通信量**：与 DDP 相同（一次 all-reduce），多了一次 step 末的 all-gather 完整 param（可以异步合并到下一 step 的 forward）。

**PyTorch 实现**：ZeRO-1 不直接通过 FSDP 启用，而是通过 `ShardingStrategy.SHARD_GRAD_OP`（含 ZeRO-2 的部分）或 DeepSpeed 的 `zero_optimization.stage=1`。

### 6.3.3 ZeRO-2：+ gradient 分片

ZeRO-2 在 ZeRO-1 基础上**也分片 gradient**：backward 后不再 all-reduce，而是 **reduce-scatter**——每个 rank 只接收自己负责的 1/N 参数的梯度求和。

![](https://pic3.zhimg.com/v2-ed7f46531e4f30933cf13d020d17f424_r.jpg)

**通信量**：reduce-scatter 是 all-reduce 通信量的一半（只 scatter 不 gather），所以 ZeRO-2 通信量 = `0.5 × all_reduce + 0 × gather = 0.5 DDP`？不对——ZeRO-2 仍需在 backward 后做 reduce-scatter，通信量等于 `all_reduce 的一半`，但 forward 仍需 all-gather 完整 param（如果只分 optimizer state 则不需要）。准确公式：

| 阶段 | DDP | ZeRO-1 | ZeRO-2 | ZeRO-3 |
| --- | --- | --- | --- | --- |
| forward | — | — | — | all-gather param (1.0×) |
| backward | all-reduce grad (1.0×) | all-reduce grad (1.0×) | reduce-scatter grad (0.5×) | reduce-scatter grad (0.5×) + all-gather param (1.0×) |
| optimizer | — | all-gather param (1.0×) | — | — |
| 总通信量 | 1.0× | 2.0× | 1.5× | 2.5× |

注意：ZeRO-1 总通信量是 2.0× 因为多了一次 step 末的 all-gather。实际实现常把它 hide 到下一 step forward，故实测开销接近 1.0×。

### 6.3.4 ZeRO-3：+ parameter 分片

ZeRO-3 把参数也分片，等价于 FSDP 的 `FULL_SHARD`。每层 forward/backward 前 all-gather 完整 param，用完立刻释放。

```text
# ZeRO-3 等价于 FSDP FULL_SHARD
FSDP(model, sharding_strategy=ShardingStrategy.FULL_SHARD)
# DeepSpeed 写法：
# deepspeed.initialize(model, config={"zero_optimization": {"stage": 3}})
```

### 6.3.5 ZeRO 与 FSDP 对照

| 维度 | ZeRO-1 | ZeRO-2 | ZeRO-3 | FSDP SHARD_GRAD_OP | FSDP FULL_SHARD |
| --- | --- | --- | --- | --- | --- |
| 分片 optimizer | ✅ | ✅ | ✅ | ✅ | ✅ |
| 分片 grad | ❌ | ✅ | ✅ | ✅ | ✅ |
| 分片 param | ❌ | ❌ | ✅ | ❌ | ✅ |
| forward all-gather | ❌ | ❌ | ✅ | ❌ | ✅ |
| backward reduce-scatter | ❌ | ✅ | ✅ | ✅ | ✅ |
| PyTorch 原生 | ⚠️（间接） | ✅ | ✅ | ✅ | ✅ |
| DeepSpeed | ✅ | ✅ | ✅ | ❌ | ❌ |

**关键结论**：

- FSDP `SHARD_GRAD_OP` ≡ ZeRO-2
- FSDP `FULL_SHARD` ≡ ZeRO-3
- ZeRO-1 在 PyTorch FSDP 中没有直接对应，可用 `optimizer sharding` 的间接方案

## 6.4 通信重叠与桶调度

6.1 已经介绍了 DDP 的 overlap 大意，本节深入工程细节——这是大模型训练调优最关键的环节。

### 6.4.1 通信与计算 overlap 的物理基础

GPU 上有两个独立 stream：

![](https://pic1.zhimg.com/v2-0232da44011fda502fe4fe0df2208c52_r.jpg)

两个 stream 在 GPU 上由 hardware scheduler 并行调度——只要依赖满足，NCCL kernel 可以与 compute kernel 同时运行。这是 overlap 的硬件基础。但 NCCL kernel 与 compute kernel 都用 SM、HBM 带宽、PCIe/NVLink 带宽，**实际 overlap 率受资源 contention 限制**。

### 6.4.2 NCCL all-reduce 内部：ring vs tree

NCCL 2.x 的集合通信实现细节：

| 算法 | 数据流 | 最优场景 |
| --- | --- | --- |
| Ring | N-1 步 scatter-reduce + N-1 步 all-gather | 大消息（>1 MB），NVLink/IB 拓扑 |
| Tree | 双二叉树，每步双向传递 | 小消息（ MB），低延迟 |
| CollNet | 通过 NVSwitch 直接聚合 | DGX 系统，极大消息 |
| NVLS | 8-GPU NVSwitch 单节点 | 单节点 all-reduce |

NCCL 自动选择，可用环境变量强制：

```text
export NCCL_ALGO=Ring        # 强制 ring
export NCCL_ALGO=Tree        # 强制 tree
export NCCL_ALGO=CollNet     # 强制 collnet
export NCCL_NET=IB           # 网络后端
export NCCL_IB_DISABLE=0     # 启用 IB
export NCCL_DEBUG=INFO       # 调试日志，看实际选了哪个算法
```

**调优 tip**：单节点 8 GPU NVLink 拓扑下，H100 上 CollNet/NVLS 比 Ring 快 1.5-2x；多节点跨 IB 时 Ring 反而更稳。

### 6.4.3 bucket 调度策略

DDP 的 bucket 调度有三个层次：

**层次 1：bucket 分组**——参数按反向顺序分到不同 bucket：

```text
# DDP 内部伪代码
buckets = [[] for _ in range(num_buckets)]
for param in reversed(model.parameters()):  # 反向顺序
    bucket_idx = (param_index // params_per_bucket) % num_buckets
    buckets[bucket_idx].append(param)
```

**层次 2：bucket 触发**——backward hook 检查 bucket 内所有 grad 是否 ready：

```text
# DDP 内部伪代码
def grad_hook(param):
    bucket = bucket_of[param]
    bucket.ready_count += 1
    if bucket.ready_count == len(bucket.params):
        # 所有 grad ready，触发 all-reduce
        launch_all_reduce(bucket.flat_grad)
```

**层次 3：bucket 间调度**——bucket 的 all-reduce 在 NCCL stream 上串行，但与 default stream 并行：

![](https://pic2.zhimg.com/v2-b98e31ca5ec7300bc455d88fe77a5727_r.jpg)

### 6.4.4 backward hook 触发机制

DDP 用 `AccumulateGrad` 机制（ch3 介绍过）注册 hook：每个 `Parameter.requires_grad=True` 的参数，autograd 引擎计算完 grad 后会调用 `param.grad` 的 setter，DDP 在 setter 中触发 bucket 检查。

```text
# 简化的 DDP grad hook 等价逻辑
class DDPGradAccumulator:
    def __init__(self, param, bucket):
        self.param = param
        self.bucket = bucket

    def __call__(self, grad):
        # autograd 把 grad 写入 param.grad，这里被调用
        self.bucket.mark_ready(self.param)
```

**关键限制**：hook 只在 `param.requires_grad=True` 时注册。如果模型有 `requires_grad=False` 的参数（如冻结的 embedding），它的 grad 永远不 ready，DDP 会卡死。解决：

```text
# 方案 1：开 find_unused_parameters
model = DDP(model, find_unused_parameters=True)

# 方案 2：手动跳过 frozen param（PyTorch 2.0+ DDP 自动检测）
for p in model.parameters():
    if not p.requires_grad:
        p.grad = None  # 显式置 None，DDP 不等待
```

## 6.5 DTensor 与并行策略（TP / PP / SP）

DDP/FSDP 都是**数据并行**——每个 GPU 持有完整模型（或完整 shard），处理不同数据。当模型大到 FSDP 也装不下时，必须切**模型本身**：Tensor Parallelism（TP）、Pipeline Parallelism（PP）、Sequence Parallelism（SP）。PyTorch 2.5+ 提供 **DTensor** 作为统一抽象。

### 6.5.1 DTensor：device mesh + placement

DTensor（Distributed Tensor）是 PyTorch 2.x 的核心新抽象之一，2.5+ 进入稳定。它把 tensor 在多 GPU 上的分布方式抽象成 `(local_tensor, device_mesh, placement)` 三元组：

```text
from torch.distributed.tensor import DTensor
from torch.distributed.device_mesh import init_device_mesh
import torch

# 1. 创建 device mesh：4 GPU 一维
mesh = init_device_mesh("cuda", (4,))

# 2. 从 local tensor 构造 DTensor
local = torch.randn(8, 4, device="cuda")  # 每 rank 8 行
# Replicate：所有 rank 持有相同副本
dt_replicate = DTensor.from_local(local, mesh, placements=[Replicate()])
# Shard(dim=0)：每 rank 持有不同行
dt_shard = DTensor.from_local(local, mesh, placements=[Shard(0)])
```

三种 placement：

| Placement | 语义 | 内存 | 通信 |
| --- | --- | --- | --- |
| Replicate() | 所有 rank 持有相同副本 | N 倍冗余 | 改变 placement 时 all-reduce |
| Shard(dim) | tensor 沿 dim 切片分散 | 每卡 1/N | all-gather / reduce-scatter |
| Partial() | tensor 是部分和（未 reduce） | 每卡 1/N | all-reduce 得到完整 |

DTensor 的核心 API：

| API | 作用 |
| --- | --- |
| DTensor.from_local(local, mesh, placements) | local → DTensor |
| dt.to_local() | DTensor → local |
| dt.redistribute(mesh, placements) | 改变 placement，自动插入通信 |
| dt.full_tensor() | 强制 materialize 完整 tensor（all-gather） |

### 6.5.2 Tensor Parallelism (TP)

TP 把单个 op（如 Linear、Attention）的权重矩阵沿某个维度切片，多个 GPU 协作完成一个 op。以 Linear 为例：

**Column Parallel Linear**（按输出维度切）：

![](https://pica.zhimg.com/v2-32a73a21746d52280cc6201e102079cc_r.jpg)

每 rank 持有 W 的 1/N 列，输入 X 是 Replicate，输出 Y 沿 out 维 Shard。**前向无通信**，仅 backward 时 all-reduce 梯度。

**Row Parallel Linear**（按输入维度切）：

![](https://pic3.zhimg.com/v2-39a5cb0f859bd4607b9c65b9ca286a50_r.jpg)

每 rank 持有 W 的 1/N 行，输入 X 沿 in 维 Shard，输出 Y 是 Partial（需 all-reduce 得到完整）。**前向需一次 all-reduce**。

Megatron-LM 的经典设计：**Column Linear → activation → Row Linear**，前向 column 无通信，row 一次 all-reduce，整体通信量与单次 all-reduce 等价。

PyTorch 2.5+ 用 DTensor 实现 TP：

```text
from torch.distributed.tensor.parallel import (
    parallelize_module, ColwiseParallel, RowwiseParallel,
)
from torch.distributed.device_mesh import init_device_mesh

mesh = init_device_mesh("cuda", (8,))

class TPBlock(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.fc1 = nn.Linear(dim, dim * 4)  # column
        self.fc2 = nn.Linear(dim * 4, dim)  # row
    def forward(self, x):
        return self.fc2(torch.nn.functional.gelu(self.fc1(x)))

block = TPBlock(dim=4096).to("cuda")
# parallelize：fc1 column parallel, fc2 row parallel
parallelize_module(
    block,
    mesh,
    {
        "fc1": ColwiseParallel(),  # 输入 replicate, 输出 shard(0)
        "fc2": RowwiseParallel(),  # 输入 shard(0), 输出 replicate（自动 all-reduce）
    },
)
```

### 6.5.3 Pipeline Parallelism (PP)

PP 把模型按 layer 切到多个 GPU，前向逐 stage 流水，反向逐 stage 回流。每个 GPU 只持有 1/N 层，**显存随 N 线性下降**。

![](https://picx.zhimg.com/v2-b85dee9f2a89d6c2412c5c9ea9548bf9_r.jpg)

PP 的核心挑战是 **bubble**：当 stage 0 在 forward layer 1-8 时，stage 1/2/3 都在等。micro-batch 调度可以缓解：

![](https://pic4.zhimg.com/v2-9fd1c3d7683c8b8ae6464c880e5165c9_r.jpg)

**1F1B（One-Forward-One-Backward）**调度：每个 stage 交替做一次前向 + 一次反向，最大气泡 = `(stages - 1) × forward_time`。增加 micro-batch 数 M 可以让气泡占比 = `(S-1) / (M + S - 1)`。

PyTorch 2.5+ 的 PP 实现（torch.distributed.pipelining）：

```text
from torch.distributed.pipelining import SplitPoint, pipeline, PipelineStage, Schedule1F1B

class BigModel(nn.Module):
    def __init__(self, layers):
        super().__init__()
        self.layers = nn.ModuleList([TransformerBlock() for _ in range(layers)])
    def forward(self, x):
        for layer in self.layers:
            x = layer(x)
        return x

# 切分：4 GPU, 每 GPU 8 层
stage_layers = [list(range(0, 8)), list(range(8, 16)), list(range(16, 24)), list(range(24, 32))]

# 1. 每 rank 构造自己的 stage
rank = dist.get_rank()
stage = BigModel(layers=8).to("cuda")
stage_module = PipelineStage(stage, stage_id=rank, num_stages=4, device="cuda")

# 2. 构造 schedule
schedule = Schedule1F1B(stage_module, num_microbatches=4)

# 3. 训练循环
for x, y in loader:
    # micro-batch 切分
    schedule.step(x)
```

### 6.5.4 Sequence Parallelism (SP)

SP 是 TP 的变种，把 **activation 的 sequence 维度**也切分。在 attention 外（LayerNorm、Dropout、残差）每 rank 只处理 1/N 的 sequence，节省 activation 显存；在 attention 内 gather 起来。

![](https://pic1.zhimg.com/v2-7747cf15a074513a59607f51d2023ae4_r.jpg)

SP 的收益：activation 显存降 N 倍（只对 LayerNorm/Dropout 部分，attention 仍需全量）。在大模型长序列训练（Llama-3 32k seq）上 SP 是标配。

PyTorch 2.5+ 通过 `SequenceParallel` 注入：

```text
from torch.distributed.tensor.parallel import (
    ColwiseParallel, RowwiseParallel, SequenceParallel,
)

parallelize_module(
    block,
    mesh,
    {
        "attn_layer_norm": SequenceParallel(),  # 输出 shard(seq)
        "attn": ColwiseParallel(input_layouts=Shard(0)),  # gather seq
        # ... 自动插入 reduce-scatter 回 SP
    },
)
```

### 6.5.5 3D 并行：TP + PP + DP

超大模型（175B+）必须组合三种并行：

![](https://picx.zhimg.com/v2-e0d546575759c9951f26de54c24d1ced_r.jpg)

典型配置（175B 模型，1024 GPU）：

| 并行 | 维度 | 数量 | 作用 |
| --- | --- | --- | --- |
| TP | 注意力头/隐层 | 8 | 单层算子分片 |
| PP | 层 | 16 | 模型深度分片 |
| DP | 数据 | 8 | 数据并行 |
| FSDP | 全部 | intra-DP | 二次显存压缩 |

总 GPU = `8 × 16 × 8 = 1024`，每 GPU 仅持有 `175B / (8 × 16) = 1.36B` 参数。

### 6.5.6 DTensor 3D 并行完整代码示例

```text
# train_3d.py (PyTorch 2.5+)
import os, torch
import torch.distributed as dist
import torch.nn as nn
from torch.distributed.device_mesh import init_device_mesh
from torch.distributed.tensor.parallel import (
    parallelize_module, ColwiseParallel, RowwiseParallel, SequenceParallel,
)
from torch.distributed.fsdp import fully_shard
from torch.distributed.pipelining import PipelineStage, Schedule1F1B

def setup():
    dist.init_process_group("nccl")
    return int(os.environ["LOCAL_RANK"])

class TPBlock(nn.Module):
    def __init__(self, dim, heads):
        super().__init__()
        self.norm1 = nn.LayerNorm(dim)
        self.attn = nn.MultiheadAttention(dim, heads, batch_first=True)
        self.norm2 = nn.LayerNorm(dim)
        self.ffn = nn.Sequential(
            nn.Linear(dim, dim * 4), nn.GELU(), nn.Linear(dim * 4, dim)
        )

    def forward(self, x):
        h = self.norm1(x)
        a, _ = self.attn(h, h, h, need_weights=False)
        x = x + a
        h = self.norm2(x)
        x = x + self.ffn(h)
        return x

def main():
    local_rank = setup()
    torch.cuda.set_device(local_rank)
    world_size = dist.get_world_size()
    assert world_size % 8 == 0  # 假设 TP=8

    # 1. 创建 2D mesh: (DP, TP)
    dp_size = world_size // 8
    mesh_2d = init_device_mesh("cuda", (dp_size, 8), mesh_dim_names=("dp", "tp"))
    tp_mesh = mesh_2d["tp"]
    dp_mesh = mesh_2d["dp"]

    # 2. 构造模型（每 rank 完整，后面 TP 切）
    model = nn.Sequential(*[TPBlock(dim=4096, heads=32) for _ in range(32)])

    # 3. TP 切：每 block 内部并行化
    for block in model:
        parallelize_module(
            block, tp_mesh,
            {
                "norm1": SequenceParallel(),
                "attn": ColwiseParallel(input_layouts=Shard(1)),  # SP → TP
                "norm2": SequenceParallel(),
                "ffn.0": ColwiseParallel(),
                "ffn.2": RowwiseParallel(output_layouts=Shard(1)),  # TP → SP
            },
        )

    # 4. FSDP 切：dp_mesh 维度上 shard 剩余参数
    for block in model:
        fully_shard(block, mesh=dp_mesh)
    fully_shard(model, mesh=dp_mesh)

    # 5. PP 切：略，参考 6.5.3

    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)
    # ... 训练循环 ...

    dist.destroy_process_group()

if __name__ == "__main__":
    main()
```

### 6.5.7 与 Megatron-LM 对照

| 维度 | PyTorch 原生 (2.5+) | Megatron-LM | DeepSpeed |
| --- | --- | --- | --- |

| PP 实现 | torch.distributed.pipelining | Megatron Pipeline | DeepSpeed Pipeline |
| SP 支持 | SequenceParallel placement | Megatron 原生 | 借用 Megatron |
| 3D 并行 | DTensor mesh + FSDP2 | 完整 3D + 通信优化 | 完整 3D + ZeRO |
| FSDP / ZeRO-3 | FSDP2 | Megatron 自己的 DPO | ZeRO-3 |
| torch.compile | ✅ FSDP2 兼容 | ❌ | 部分 |
| 易用性 | API 简洁 | 配置复杂 | 配置中等 |
| 性能 | 接近 Megatron | 最优 | 接近 Megatron |
| 生产案例 | Llama-3 pretrain（Meta） | 大量 | Bloom、GLM |

**实战选择**：

- 全新项目，PyTorch 2.5+，模型 ≤ 70B → **PyTorch 原生 DTensor + FSDP2**
- 模型 ≥ 175B，性能极致 → **Megatron-LM**
- 已有 DeepSpeed 代码 → **保持 DeepSpeed**

### 踩坑表

分布式训练是踩坑密度最高的领域，下面按”症状 → 原因 → 修复”组织：

| # | 症状 | 根本原因 | 修复 |
| --- | --- | --- | --- |
| 1 | DDP 死锁，部分 rank 卡在 backward | 模型有未参与 backward 的参数 | find_unused_parameters=True 或冻结参数 grad=None |
| 2 | DistributedSampler 不 shuffle | 没 sampler.set_epoch(epoch) | 每个 epoch 开头调用 |
| 3 | 4 GPU 训练 loss 不下降 | loss 没 / world_size | loss.mean() 或 loss = loss / world_size |
| 4 | DDP + CPU 模型报错 | DDP 默认 GPU，CPU 模型要特殊配置 | device_ids=None |
| 5 | FSDP state_dict 报错 “flat param” | 没 use_orig_params=True | FSDP1 加 use_orig_params=True，或迁移到 FSDP2 |
| 6 | FSDP OOM 在 backward | all-gather 太多 param 同时存在 | limit_all_gathers=True |
| 7 | FSDP + compile 报 graph break | FSDP1 flat param 不兼容 | 用 FSDP2 或 compile 只 wrap 非 FSDP 部分 |
| 8 | NCCL 报 “no supported transport” | 多节点 IB 未配置 | 检查 NCCL_NET=IB，IB 驱动 |
| 9 | NCCL 超时 timeout | ring 拓扑断裂或某 rank hang | NCCL_DEBUG=INFO 看哪步停；加 TORCH_NCCL_ASYNC_ERROR_HANDLING=1 |
| 10 | 多节点训练慢，单节点快 | 跨节点 IB 带宽不够 / 路由不对 | NCCL_NET_GDR_LEVEL=PHB，检查 RoCE 配置 |
| 11 | FSDP checkpoint 加载到 DDP 报 shape mismatch | FSDP shard 形状与 DDP 完整不同 | 用 StateDictType.FULL_STATE_DICT 转 full 再加载 |
| 12 | TP 报 “shape mismatch on attn” | TP 切分维度与 attention head 数不匹配 | TP size 必须整除 head 数 |
| 13 | PP bubble 占 50% 时间 | micro-batch 数太少 | num_microbatches >= 4 * num_stages |
| 14 | PP 反向死锁 | schedule 选错 | 用 Schedule1F1B 或 ScheduleGPipe，注意 stage_id 顺序 |
| 15 | DTensor redistribute 报错 | mesh 不匹配 | 检查 dt.device_mesh == target_mesh |
| 16 | FSDP2 fully_shard 报 “not a leaf module” | 子 module 已被 shard | 按外到内顺序 fully_shard |
| 17 | 梯度累积 + DDP 梯度错 | DDP 默认每 step 都 all-reduce | model.no_sync() 在累积 step 内跳过 |
| 18 | BF16 训练 loss NaN | 梯度溢出，FSDP reduce_dtype=fp32 | 改用 BF16 + GradScaler（仅 FP16）或换 FP32 master |
| 19 | torchrun 报 “RANK not set” | 用了 python train.py | 改用 torchrun --nproc_per_node=N train.py |
| 20 | H100 上 FP8 训练报”not supported” | FSDP + FP8 兼容性差 | 2.5+ 用 FSDP2 + FP8，或 eager + FP8 |

### 6.x 全章要点表

| 小节 | 核心结论 | 关键 API / 配置 |
| --- | --- | --- |
| 6.1 DDP | 副本参数 + all-reduce，通信最小，单卡显存最大 | DistributedDataParallel |

| 6.5 SP | 切 sequence 维度，LayerNorm/Dropout activation 显存降 N 倍 | SequenceParallel |
