## **MCP Server 是什么？**

MCP（Model Context Protocol，模型上下文协议）是一套连接 AI 应用与外部工具、数据源的开放协议。通过统一的接口，AI 可以调用浏览器、数据库、开发工具和命令行等能力，直接获取信息或执行任务，减少不同工具之间的适配成本。MCP 的能力取决于所连接的服务及其权限，因此在使用前应明确访问范围，并谨慎开放写入、删除或执行命令等高风险权限。

### **浏览器操作**

### **1. Puppeteer**

Puppeteer MCP 提供了浏览器导航、截图、点击、表单填写、页面 JavaScript 执行和控制台日志读取等能力。

它体现了浏览器类 MCP 的基本工作方式：AI 接收任务后，通过浏览器打开页面、操作元素、读取结果，并把结果返回给开发者。

Puppeteer MCP 默认以无头模式（headless: true）启动 Chromium，浏览器进程在后台跑、没有可见窗口。若要展示可见窗口，需在指令中明确指定 headless: false。

> **❗注意：** Puppeteer MCP 的项目文档明确提示，它运行的浏览器可能访问本地文件和内网地址。

- **如何添加 Puppeteer MCP：**

1. 在 TRAE 中，前往 **设置 > MCP** 。

b. 点击 **添加 > 从市场添加** ，然后在 MCP 市场中搜索并找到 Puppeteer。

![](https://picx.zhimg.com/v2-48a5c5effa503dec843fca5f21d4aba3_r.jpg)

c. 点击 **+** ，然后直接点击弹窗右下角的 **确认** 按钮，完成添加。该 MCP 无需手动填写自定义 JSON 配置，使用弹窗中的默认配置即可。

- **使用案例：**

使用以下提示词，让 TRAE 调用 Puppeteer MCP 测试鲜达超市页面。

```text
用 Puppeteer MCP 测试鲜达超市页面，验证 “搜索 > 加购 > 计价” 这一核心链路。

页面：~/Downloads/Puppeteer/鲜达超市.html

需要展示可见窗口，即 `headless: false`。

执行：
打开页面，截取首屏
在搜索框输入"苹果"，点击搜索按钮
点击第一张商品卡片的"加入购物车"按钮
读取页面状态：购物车角标数量（应为 1）、商品小计、合计金额
截图保存购物车最终状态

输出：一句话结论（通过/失败）、实际读到的角标与合计金额、两张截图路径。
```

收到指令后，TRAE 先读源码定位关键选择器并推算预期值，然后用 Puppeteer（headless: false）依次完成：打开页面截首屏 >  输入"苹果"并搜索 >  点击加购 >  读取角标、小计、合计 > 截终态图，最终核对数据全部符合预期，给出 “通过” 结论。

### **2. Playwright**

Playwright MCP 可以让 AI 在真实浏览器中打开网页、点击元素、填写表单、截取页面图片和执行 JavaScript。它还支持不同浏览器和多种设备的模拟。

Playwright MCP 会在本机启动由 Playwright 管理的浏览器实例，用于执行测试、截图和页面交互；默认情况下，它与用户日常使用的浏览器环境相互隔离。

它适合前端开发、端到端测试和产品验收等场景。开发者修改页面后，可以让 AI 完成一次完整的操作流程，并根据页面的实际操作结果判断功能是否正常。

> **❗注意：** 使用时应注意页面中的账号、订单和表单数据。执行涉及提交、删除或修改数据的操作时，应当要求 AI 在执行前确认。

- **如何添加 Playwright MCP：**

a. 在 TRAE 中，前往 **设置 > MCP** 。

b. 点击 **添加 > 从市场添加** ，然后在 MCP 市场中搜索并找到 Playwright。

![](https://pic4.zhimg.com/v2-16c5568c1a3867a2ffac4a20291c6e25_r.jpg)

c. 点击 **+** ，在弹窗中输入以下 JSON 配置，然后点击 **确认** 按钮。

```text
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@executeautomation/playwright-mcp-server"]
    }
  }
}
```

### **3. Chrome DevTools MCP**

Chrome DevTools MCP 将 Chrome DevTools 的能力提供给 AI。AI 可以查看并分析控制台日志、网络请求和性能信息，对页面进行截图，也可以运行 Lighthouse 的无障碍、SEO 和性能检查。

它适合前端和全栈开发者排查页面问题。例如，用户反馈 “点击保存后没有反应” 时，AI 可以检查浏览器控制台中的报错、接口的请求和响应，以及页面状态的变化。

Chrome DevTools MCP 默认会启动一个本机 Chrome 实例。经过配置后，它也可以连接到正在运行的 Chrome，用于检查页面、网络请求和控制台信息。

> **❗注意：** 需要注意的是，Chrome DevTools MCP 可以读取浏览器中的页面内容和 DevTools 数据。在包含敏感账号、内部管理后台或生产环境权限的浏览器配置中，应在谨慎评估后再决定是否使用该 MCP。

- **如何添加 Chrome DevTools MCP：**

a. 在 TRAE 中，前往 **设置 > MCP** 。

b. 点击 **添加 > 从市场添加** ，然后在 MCP 市场中搜索并找到 Chrome DevTools MCP。

![](https://picx.zhimg.com/v2-b7c35c2d41f053da45f0bf279bd03c77_r.jpg)

c. 点击 **+** ，在弹窗中输入以下 JSON 配置，然后点击 **确认** 按钮。

```text
{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest"]
    }
  }
}
```

- **使用案例：**

使用以下提示词，让 TRAE 调用 Chrome DevTools MCP 测试鲜达超市页面。

### **4. 数据库操作**

**MySQL Server**

MySQL Server 可以让 AI 查看数据库中的表、读取表结构、抽样查看数据，以及执行 SQL 查询。它支持本地运行，也支持通过 HTTP 或 SSE 的方式部署。

它适合后端、数据开发和排障场景。许多问题不能只通过代码定位，例如订单没有生成、字段没有写入、数据统计不一致等。此时，AI 可以先查看表结构和数据样本，再根据实际数据编写 Query。

这个 MCP 的重点不只是让 AI 生成 SQL，而是让 AI 根据数据库中的真实结构和查询结果继续分析问题。

> **❗注意：** 需要特别注意权限。该项目支持 INSERT、UPDATE 和 DELETE 等写操作。生产环境应使用只读账号；如果确实需要写权限，也应让 AI 在执行前展示 SQL 并等待确认。数据库连接信息应通过环境变量或安全的配置方式提供，不应写入 Prompt 或提交到代码仓库。

- **如何添加 MySQL Server：**

a. 在 TRAE 中，前往 **设置 > MCP** 。

b. 点击 **添加 > 从市场添加** ，然后在 MCP 市场中搜索并找到 MySQL Server。

![](https://pic2.zhimg.com/v2-8f5a1692456b328f54ccf04f5a347cad_r.jpg)

c. 点击 **+** ，在弹窗中输入以下 JSON 配置，然后点击 **确认** 按钮。

```text
{
  "mcpServers": {
    "MySQL Server": {
      "command": "mysql_mcp_server",
      "args": [],
      "env": {
        "MYSQL_DATABASE": "",       // 要连接的 MySQL 数据库名称
        "MYSQL_HOST": "localhost",  // MySQL 服务器的主机地址
        "MYSQL_PASSWORD": "",       // MySQL 用户的密码
        "MYSQL_PORT": "3306",       // MySQL 服务器的端口号，默认为 3306
        "MYSQL_USER": ""            // 用于连接 MySQL 的用户名
      }
    }
  }
}
```

**5. DBX**

DBX 是一款轻量级的跨平台数据库客户端，支持 MySQL、PostgreSQL、SQLite、Redis、MongoDB 等多种数据库和中间件。

**DBX MCP** （ [https://github.com/t8y2/dbx#ai-agent-integration-mcp](https://github.com/t8y2/dbx#ai-agent-integration-mcp) ） 是 DBX 提供的 MCP Server。它让 TRAE 等 AI 工具使用 DBX 中已经配置好的数据库连接，执行查询、查看表结构和浏览数据。

它适合同时管理多个数据库的开发者。你不需要为 MySQL、PostgreSQL、Redis 或 MongoDB 分别配置不同的 MCP；在 DBX 中完成连接配置后，可以选择哪些连接允许 AI 访问。

DBX 还提供三种权限模式：只读、允许数据读写和完全访问。开发者可以先给 AI 分配只读权限，用它查看表结构、分析数据和验证 SQL；在确有需要时，再单独开放写权限。

**5. PostgreSQL**

**PostgreSQL MCP** （ [https://github.com/modelcontextprotocol/servers-archived/tree/main/src/postgres](https://github.com/modelcontextprotocol/servers-archived/tree/main/src/postgres) ） 是一个面向 PostgreSQL 的 MCP Server。它允许 AI 查看数据库中的表结构，并执行只读 SQL 查询；所有查询都会在只读事务中运行，因此不会修改数据库中的数据。

它适合数据排查、业务分析和 SQL 验证等场景。对于团队来说，先接入只读数据库 MCP，通常比直接开放写操作更容易控制风险。

- **如何添加 PostgreSQL MCP：**

### **6. 2D/3D 应用开发**

**unityMCP**

Unity 是一款常用于游戏、实时 3D 应用和交互式内容开发的引擎。开发者可以通过 Unity 编辑器管理场景、游戏对象、资源和 C# 脚本。

unityMCP 是一个连接 Unity 编辑器与 AI 工具的 MCP 项目。它可以让 AI 获取当前的场景层级、选中的对象和运行状态，读取 Unity 的日志，并在编辑器中执行 C# 命令。

例如，开发者可以让 AI 检查当前场景中的对象结构，定位 Console 中的报错，或创建一个基础的游戏对象。

> **💡提示：** UnityMCP 可以直接在 Unity 编辑器中执行 C# 代码，包括创建和修改游戏对象。建议先在测试项目中使用。对于会修改场景或资源的命令，应在执行前确认。

- **前置条件：**

1. Unity 2022.3+
2. Node.js 18+
3. npm 9+

- **安装并设置 UnityMCP：**

**第一步**

配置 Unity 插件：

1. 获取仓库：git clone [https://github.com/jackwrichards/UnityMCP.git](https://github.com/jackwrichards/UnityMCP.git) 。
2. 将仓库中的 UnityMCPPlugin 文件夹复制到 Unity 项目的 Assets 目录中。
3. 打开 Unity Editor，等待编译完成。
4. 在顶部菜单栏中，选择 **UnityMCP > Debug Window** ，打开插件的调试窗口。

**第二步**

配置 MCP Server：

1. 打开终端。
2. 切换到 unity-mcp-server 目录：cd unity-mcp-server。
3. 安装项目依赖：npm install。
4. 构建项目：npm run build。
5. 确认构建产物存在：ls build/index.js

**第三步**

在 TRAE 中连接 Unity MCP：

1. 在 TRAE 中，前往 **设置 > MCP** 。
2. 点击 **添加 > 手动配置** 。
3. 在弹窗中，输入以下 JSON 配置，然后点击 **确认** 按钮。

```text
{
  "mcpServers": {
    "unityMCP": {
      "command": "node",
      "args": ["/绝对路径/UnityMCP/unity-mcp-server/build/index.js"]
    }
  }
}
```

**第四步**

在 Unity 中保持 MCP 连接：

1. 打开 Unity 项目（Editor 需处于运行状态）。
2. 在顶部菜单栏中，选择 **UnityMCP > Debug Window** ，打开 UnityMCP 调试窗口。
3. 插件将自动尝试连接 MCP Server。
4. 在窗口中通过 Connection Status 确认连接情况并排查问题。

- **提示词示例：**

单场景提示词：

```text
列出当前场景的完整层级结构，并标出我选中的物体。

列出当前项目里所有脚本文件的路径。

在场景原点创建一个立方体，命名为 Ground。

把场景中名为 Ground 的物体移动到 (0, 1, 0)，并绕 Y 轴旋转 45 度。

进入播放模式。

列出 Console 里最近的报错，只保留消息内容和时间戳。
```

先检查场景里有没有名为 Ground 的物体；如果没有，就在原点创建一个立方体并命名为 Ground。

先列出场景里所有名字包含 Cube 的物体，等我确认后把它们全部删除。

进入播放模式，然后读取 Console 日志，最后退出播放模式并汇总日志。

**godot-ai**

### **7. 命令行**

**Windows CLI**

Windows CLI MCP 是一个面向 Windows 的命令行 MCP Server。它可以让 AI 使用 PowerShell、CMD 和 Git Bash 执行命令，也可以通过 SSH 管理已配置的远程服务器。

项目支持设置允许操作的目录、禁止执行的命令、命令超时和 SSH 连接范围，用于限制 AI 的命令执行权限。由于它可以访问文件、环境变量和远程系统，使用时需要谨慎配置路径和 SSH 权限。

- **如何添加 Windows CLI MCP：**

a. 在 TRAE 中，前往 **设置 > MCP** 。

b. 点击 **添加 > 从市场添加** ，然后在 MCP 市场中搜索并找到 Windows CLI MCP。

![](https://pic4.zhimg.com/v2-bf5dcfd6d08ee07b9cdb5e234b36889b_r.jpg)

c. 点击 **+** ，在弹窗中输入以下 JSON 配置，然后点击 **确认** 按钮。

```text
{
  "mcpServers": {
    "windows-cli": {
      "command": "npx",
      "args": ["-y", "@simonb97/server-win-cli"]
    }
  }
}
```

- **使用案例一：排查本地项目的启动问题**

开发者在 Windows 上运行项目时，常常需要检查 Node.js、Python、Git、环境变量、端口占用和日志文件。Windows CLI MCP 可以让 AI 在指定项目目录中执行这些检查，并汇总结果。

```text
在 C:\Projects\demo-app 中检查项目为什么无法启动。

请依次执行以下操作：
查看 package.json 中的 scripts；
检查 Node.js、npm 和 Git 的版本；
检查 3000 端口是否被占用；
执行 npm install 和 npm run dev；
如果启动失败，读取错误输出并说明原因。

不要修改 package.json、删除文件或结束任何进程。
```

这个案例适合新成员配置开发环境，也适合处理本地项目无法运行之类的常见问题。配置时只需要将 C:\Projects 加入允许操作的目录。

- **使用案例二：检查远程测试服务器的服务状态和日志**

如果已经在 Windows CLI MCP 中配置了 SSH 连接，AI 可以通过 SSH 执行只读的巡检命令，例如检查服务状态、磁盘空间、最近的错误日志和端口监听情况。

```text
使用名为 staging-server 的 SSH 连接检查测试环境。

请执行以下操作：
查看应用服务的运行状态；
查看磁盘使用率和内存使用情况；
查看最近 30 分钟的错误日志；
检查应用端口是否正在监听；
按“正常项、异常项、建议处理方式”输出结果。

不要重启服务、修改配置、删除日志或执行部署操作。
```

这个案例适合测试环境的日常巡检和问题初步定位。建议为 SSH 连接配置权限受限的账号，并将服务重启、部署和文件删除等命令加入禁止列表。
