InfiniBand是光纤交换机吗？RDMA是怎么做到让光纤交换机，直接读写内存的？NVLink硬件上是什么？也是集成电路主板吗？

通俗拆解：InfiniBand、RDMA、接口、NVLink

先纠正最关键一点：不是交换机直接读写内存！是两端的IB网卡（HCA）硬件完成读写，交换机只负责转发数据包，不碰内存数据 。

1、InfiniBand 是光纤交换机吗？

InfiniBand（IB）是一整套完整通信标准，不单单指交换机。

整套InfiniBand由三样东西组成：

1. IB网卡 HCA：插在服务器PCIe插槽上的板卡（类似网卡），是实现RDMA的真正硬件；

2. IB交换机：专门的交换机设备；

3. 线缆：可以用光纤（机柜之间远距离），也可以用高速铜缆（机柜内部短距离）。

IB的网络端口是 QSFP/OSFP 接口，绝对不是USB，USB带宽、架构完全不适合，两者毫无关系 。

服务器内部：IB网卡插主板的 PCIe插槽，和普通显卡插槽一样。网卡外侧露出QSFP口，插上光纤，连到IB交换机。

2、RDMA到底怎么“读写远端机器内存”？（重点，破除误解）

❌误区：光纤交换机拥有读写内存的能力。

✅真相：交换机只负责转发数据包，完全看不懂内存地址；读写内存是两端服务器上的IB网卡硬件干的活。

普通网卡TCP通信流程（家里电脑上网）

服务器A CPU → 拷贝数据到操作系统内核 → 拷贝到网卡 → 网络 → 对端网卡 → 对端CPU接收，拷贝到内存。

每一步都要CPU干活，多次复制数据，开销大、延迟高 。

RDMA工作流程（InfiniBand）

1. 软件提前告诉本地网卡、远端网卡：把哪一块内存区域开放，分配一把访问密钥（内存注册）。

2. 本地IB网卡硬件生成指令： 把我这边内存地址X的数据，写到对面机器内存地址Y，带上密钥 。

3. 数据包经过IB光纤交换机，交换机只是把包转发过去，看不懂内存地址。

4. 远端IB网卡硬件收到数据包，校验密钥合法之后，直接通过PCIe总线DMA，把数据写入远端内存。

👉 远端的CPU、操作系统内核全程不参与搬运数据，甚至CPU此时正在满负荷跑计算，完全不知道有数据写入自己内存 。

简单比喻：

- IB网卡 = 两个大楼里的专用快递机器人；

- IB光纤交换机 = 楼道，只负责传递快递包裹；

- RDMA = 机器人拿到授权密钥，可以直接把包裹放进对方大楼指定房间柜子里，不用叫对方大楼保安（CPU）来接手搬运。

注意安全：不能随便乱读内存，必须提前注册内存+密钥，没有密钥网卡拒绝访问，不会随便乱扫内存。

3、NVLink硬件上是什么？

NVLink是英伟达GPU之间专属高速互联总线，只工作在同一台服务器机箱内部，不能跨机器 。

两种物理形态：

1. 消费级PCIe显卡：显卡顶部有金手指接口，插上一块小小的PCB电路板，叫NVLink桥接器（类似老SLI桥），铜质电路板，导线直接连通两张GPU芯片引脚。

2. AI服务器DGX（SXM GPU模块，主流）：

GPU是像内存条一样的模块，插在一块特殊高密度PCB载板（基板）。NVLink的高速导线直接印刷在这块载板电路板内部，同时板上还有一颗芯片叫 NVSwitch（GPU交换机芯片，集成电路），8张GPU全部接到NVSwitch芯片，实现全部GPU两两高速互通。

NVLink和PCIe、InfiniBand对比

- NVLink：机箱内部GPU↔GPU，板载PCB走线/桥接PCB，带宽极高TB/s级别，距离很短，不能出机箱；

- InfiniBand：服务器↔服务器跨机柜，网卡+光纤+IB交换机；

- PCIe：服务器主板通用总线，CPU接显卡、接IB网卡、接硬盘。

一台DGX服务器完整链路：

机箱内部GPU之间：NVLink + NVSwitch芯片；

这台服务器和另一台服务器通信：IB‑HCA网卡 → 光纤 → InfiniBand交换机。两者配合使用，各司其职。

4、把整套流程串一遍（AI集群两台服务器通信）

服务器1（8张GPU，内部NVLink全互联） ↔ PCIe插槽插IB网卡 ↔ QSFP光纤线 ↔ InfiniBand交换机 ↔ 光纤 ↔ 服务器2 IB网卡 ↔ PCIe ↔ 服务器2内部NVLink连接8张GPU。

1. 服务器1里GPU要发梯度数据；

2. GPUDirect‑RDMA允许IB网卡直接读GPU显存，绕开本机CPU；

3. IB网卡组装RDMA写指令，数据包经光纤交换机转发；

4. 服务器2 IB网卡硬件收到包，校验密钥，直接把数据写入服务器2的GPU显存；

5. 两台服务器CPU全程几乎不参与数据搬运。

交换机从头到尾只做转发，完全不理解内存地址，读写内存能力全部在两端的网卡硬件上。
