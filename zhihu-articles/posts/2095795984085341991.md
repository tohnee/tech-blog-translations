自从 openai 削弱了 pro 的用量，现在 200 美元的订阅都不够用了。

前两天刚刚重置的周期，现在已经见底了……

我这可是 200 美元的订阅，我感觉 openai 削了不止一半的用量。

![](https://pic4.zhimg.com/v2-d8e2a9097f07a93d6236ed5adf15f175_r.jpg)

我实在舍不得升级 500 刀的，所以只能用 DeepSeek 挺过这一段窗口期了。

## DeepSeek 像回家一样

心血来潮之下，我试着把 DeepSeek 接入了 codex。DeepSeek 模型原生就支持 openai 和 messages 协议，所以可以无缝使用。

试了一下，像是游子归乡一样，完全没有见外的感觉。大家可以看下下面的截图，从整个执行链上来看，和 openai 的原生模型的体感是完全一致的。

![](https://pic1.zhimg.com/v2-fbf9a742d99939bbad7998cd467a692c_r.jpg)

而且在 codex 的强项——computer use 上，DeepSeek 也衔接地很好，调用浏览器、命令行等等工具，丝毫没有阻碍。

既然在 codex 里能丝滑流畅，那么在 Claude code 里是不是也会有类似表现呢？

我也尝试了一下， **答案是一致的** 。

![](https://pic4.zhimg.com/v2-e69f4a97ee8311e9f9b57faf3e735e53_r.jpg)

不论从整个执行的过程，还是工具调用的情况，还是语言对话的风格，基本上也和 Claude 原生模型非常相似。

所以如果 Claude token 紧缺，拿来当个平替版本的 opus-5 来用，也没多大问题。

可能会有些人觉得这不是理所当然的事情吗？肯定是 DeepSeek 针对 Claude code 和 codex 的使用体验做了优化。

确实没错，可是优化说起来简单，真正实现却并不容易。

我找到了之前在 codex 中使用另外一款 sota 国模的记录，大家可以看下截图感受一下差别。

![](https://pic4.zhimg.com/v2-9e5557deb7d2bdf2d6ff8f9df894623f_r.jpg)

## DeepSeek Harness

DeepSeek Harness 桌面版的正式发布是 9 月 30 日。

![](https://pic3.zhimg.com/v2-e63aa6959d99443248a3cdd7a096385a_r.jpg)

算到今天也就半个多月时间，这半个多月的时间，DeepSeek Harness 升级了好几个版本。

9 月 28 日的抢先版是 0.1.7-rc.1，现在最新的版本是 0.2.1-rc.2，从 0.1.7 到 0.2.1，至少跨过了 4 个版本。

![](https://pica.zhimg.com/v2-c49653390e7e733bd40954ba87bbf5cc_r.jpg)

这 4 个版本当中，感觉 DeepSeek Harness 吃了好几个 codex，使用体验有了质的飞跃。

我在抢先版本里做网站开发的时候，它的使用体验更类似于终端里的 Claude code，有一定的 computer use，但是显示很单薄，只能吐出文本信息。

我印象很深刻，我在 codex 里开发的时候，最好用的一点就是它可以帮我把整条链路走完。比如开发完成会自动帮我关联上 cloudflare 的域名、用上 cloudflare 的服务，把代码 push 到 github 里，然后执行线上部署。

当时版本的 DSH（DeepSeek Harness）是做不到的。

而在当前的最新版本里，本地浏览器，丰富的 computer use，这些都有了。

![](https://picx.zhimg.com/v2-6f05e8ed8f48e0ac760c29c5702ea4df_r.jpg)

它能直接关联 cloudflare 和 github，直接上线了。

![](https://picx.zhimg.com/v2-7416f9180c2f7cc4caa280ec43e7a777_r.jpg)

它也能直接 ssh 连上服务器，帮我在里面改配置。

虽然 DeepSeek 在 Claude code 和 codex 里的使用体验都不错，可是我还是最喜欢在 DSH 里用它。

可能我更喜欢原汤化原食的感觉，也可能是因为 DSH 里有一个功能我很喜欢，它可以实时看到当前 token 的消耗以及缓存命中率。

![](https://pica.zhimg.com/v2-4736c331e207be9d3b71edc8c1b4ad6a_r.jpg)

安装专门的上下文插件 dsh-context，还能看到当前 agent 的上下文占比情况：

![](https://pic4.zhimg.com/v2-ad1ecdc9f5c1d1f177c782019deff2cd_r.jpg)

并且还能查看系统提示词、工具定义、技能注入等每个模块具体的内容。

![](https://pic4.zhimg.com/v2-2016fb2ef469796bcfa0c9b9e30830f1_r.jpg)

好不好用不说，这种所有过程和结果都可以查看，代码和模型全部开源，给我一种无比敞亮的感觉。

目前国内外所有的 AI 大模型公司， **能做到这点的只有 DeepSeek** 。

## 题外话

最后聊点题外话。

国庆假期的时候，我还在 X 上看到有用户吐槽说 DSH 不好用，不如 codex 远矣。可是短短十来天的时间，DSH 迭代了几个版本， 使用体验直线提升，加上 codex 龟速的问题迟迟没有解决，我个人觉得 DSH 已经不在 codex 之下了。

而且这一波 DeepSeek 模型更新，各大厂商的动作都明显快了很多。

之前新模型推出往往需要等好几天，DeepSeek 这一波更新一两天就已经跟进了。

另外，这一波我也拿到了非常不错的价格，可以继续 5 折供应给各位。有需要的伙伴，可以移步 kimiseek.app 一观。
