## 什么是EP、PP、TP、DP

### PP：流水线并行

PP 就是流水线并行，核心思路就是按层切分模型。把神经网络的不同层（或连续多层）分配到不同的 GPU 上，数据像流水线一样依次流过这些 GPU。

- **解决什么问题**：单张 GPU 显存装不下整个模型的所有层。
- **主要挑战**：存在“气泡”空闲时间。因为后面的 GPU 必须等前面的 GPU 算完才能开始，为了解决这个问题，通常会把数据切成更小的 **micro-batch** 来尽量填满空闲时间。
- **适用场景**：模型层数极多，单卡显存无法容纳完整权重。

### EP：专家并行

EP就是专家并行，核心思路就是按照专家切分模型，专门用于**MoE（混合专家）** 架构。MoE 模型里有很多个“专家”子网络（通常是 FFN），EP 就是把这些专家分散放到不同的 GPU 上。

- **解决什么问题**：MoE 模型虽然每次只激活少数专家，但总参数量巨大，单卡放不下所有专家。
- **工作方式**：通过路由网络决定每个 token 送给哪些专家，数据需要在 GPU 间进行 **All-to-All** 通信，把 token 发送到持有对应专家的 GPU 上处理，再整合回来。
- **主要挑战**：容易出现**负载不均衡**（某个专家太忙，其他专家闲着），以及 All-to-All 通信开销较大。

### TP: 张量并行

TP就是张量并行，核心思路就是按照**层内矩阵**切分模型，把单个大的矩阵乘法拆到多张 GPU 上协同计算，专门用于**单层参数太大、单卡放不下**的场景。

- **解决什么问题**：Transformer 每层都有大矩阵（如 FFN 的 `W1: [H, 4H]`、`W2: [4H, H]`，`H` 可达 8192），单卡显存放不下整层权重，或单卡算力算不动这么大的矩阵乘法。

**DP：数据并行**

DP 就是数据并行，核心思路就是**复制模型、切分数据**，每张 GPU 持有一份**完整的模型副本**，各自处理不同的数据子集，最后同步梯度，此时也叫分布式同步训练。

- **解决什么问题**：单卡算力有限，训练太慢；或者 batch 太大，单卡显存放不下所有中间激活。DP 通过多卡并行处理不同数据来提升吞吐，同时每卡只需处理一小批数据，显存压力也降低。
- **工作方式**：**复制模型**，每张 GPU 都有一份完整的模型参数（所有层、所有专家，不切分）。**切分数据**，global batch 被切成 `DP` 份，每个 DP rank 拿到一份。每张 GPU 独立用自己的数据算前向和反向，得到**本地梯度**。**All-Reduce 梯度,**所有 DP rank 的梯度做 All-Reduce（求和取平均），保证每张卡拿到**相同的全局梯度。各自更新参数，**每张 GPU 用同步后的梯度更新自己那份参数，由于梯度相同，**所有副本保持同步**。
- **主要挑战**：**显存冗余**：每张 GPU 都存一份完整模型，`DP` 越大，总显存浪费越多。模型越大，DP 越不划算（所以大模型要配合 PP/TP/EP 先把单卡模型变小）。**All-Reduce 通信量大**：梯度大小 = 模型参数量，每 step 要同步一次全量梯度。模型越大、DP 越大，通信开销越高。**同步等待**：所有 DP rank 必须算完才能 All-Reduce，最慢的卡拖累整体（straggler 问题）。

把四种不同并行策略整理成一个表格来做对比：

**与 PP/TP/EP 的对比**：

| 维度 | DP | PP | TP | EP |
| --- | --- | --- | --- | --- |
| 切什么 | batch（数据） | 层（深度） | 层内矩阵/head | MoE 专家 |
| 每卡模型 | 完整 | 部分层 | 部分矩阵/head | 部分专家 |
| 通信 | All-Reduce 梯度 | Send/Recv 激活 | All-Reduce 激活 | All-to-All token |
| 频率 | 每 step 1 次 | 每 micro-batch 多次 | 每层多次 | 每 MoE 层 2 次 |
| 范围 | 可跨机 | 可跨机 | 通常单机 | 可跨机 |
| 解决 | 吞吐/显存（数据侧） | 模型太深 | 单层太大 | 专家太多 |

关于PP的补充：

PP 不仅解决“装不下所有层”的显存问题，还解决“单卡算得太慢”的算力问题。因为层数多，单卡串行算 100 层太慢，PP 让多张卡并行算不同层（流水线），提升吞吐。

另外，还有ETP， EDP。ETP是专家的TP，一般专家网络也不用TP。 EDP是专家副本数。比如，EP=4，DP=20，专家数是8，EDP= DP /EP = 5。 也就是说，GPU0~GPU3、GPU4~GP7、GPU8~GPU15、GPU12~GPU15、GPU16~GPU19共同组成了5个EP组的专家组副本。每一组都有8个专家，每张卡上2个专家，前向时，就在每组的GPU之间做All-to-All 交换token， EDP组之间做梯度的同步。

## <br>不同并行策略之间关系

为了深度理解不同策略在训练中之间的联系，我以抛问题形式来讲解一下。

### **问题1：**每训练一步，PP切分的不同网络层和EP切分的每个专家是怎么联系起来的？流水之间的不同层又是怎样的前后依赖关系？

PP切分的不同层之间确实有着严格的前后依赖关系，而EP切分的专家之间是并行的，没有前后依赖。两者在一步训练中通过“层内路由+层间流水”的方式协同工作。

理解PP，最核心的点是，PP的层间依赖，**串行但可流水。**PP 把模型按层切成若干 stage，stage 之间有**严格的数据依赖**：<br>stage 0 (layer 0-7) → stage 1 (layer 8-15) → stage 2 (layer 16-23) → ...

**前向传播**：stage 0 的输出必须传给 stage 1 才能开始计算，以此类推。**反向传播**：梯度从最后一 stage 往回传，依赖关系反过来

但是训练一步，不是等stage0全部算完才能启动stage1，标准做法是micro-batch流水线：

```text
时间 →
GPU0: [mb0 前向] [mb1 前向] [mb2 前向] [mb3 前向] ...
GPU1:           [mb0 前向] [mb1 前向] [mb2 前向] ...
GPU2:                     [mb0 前向] [mb1 前向] ...
...
GPU0: [mb0 反向] ...
GPU1:           [mb0 反向] ...

```

每个 micro-batch 仍然满足“层间串行”，但不同 micro-batch 的层计算可以重叠，填满 GPU 空闲时间（减少 bubble）。所以 PP 的层间依赖是“同一 micro-batch 内串行，不同 micro-batch 间流水**”**。

**EP 专家间关系：**一个MOE层有N个专家（FFN），每个 token 只被路由到 top-k 个专家，这些专家之间没有前后依赖，是并行计算的。

```text
token t → router → 选 expert 3 和 expert 7
                    ├─ expert 3 (GPU A) 独立计算
                    └─ expert 7 (GPU B) 独立计算
                    两者结果加权求和 → 输出
```

关键点：**EP 发生在 MoE 层内部，PP 发生在层与层之间**。它们不是同一维度的并行，而是**嵌套**的。

以一层 MoE Transformer 为例：

```text
stage 0: [Attention] → [MoE layer: router → EP 专家并行] → 输出
stage 1: [Attention] → [MoE layer: router → EP 专家并行] → 输出
...
```

**一步训练的数据流**：

1. PP 的 stage 0 收到输入，先算 Attention，再进 MoE 层。
2. MoE 层内部，router 决定每个 token 去哪些专家，触发 EP 的 All-to-All，token 被分发到不同 GPU 上的专家并行计算，结果收回加权求和。
3. stage 0 的 MoE 输出作为PP 的层间激活，传给 stage 1。
4. stage 1 重复 Attention → MoE（EP 并行）→ 输出。
5. 前向走完后，反向传播按相反顺序：stage N 反向 → ... → stage 0 反向。反向时 EP 的 All-to-All 也要反向做一次（梯度回传）。

### **问题2**：训练一步，不是等stage0全部算完才能启动stage1，标准做法是micro-batch流水线，那么当gpu1进行mb0训练的时候，gpu0上多个micro-batch还没训完，此时gpu1上layer层模型训练的参数是正确的吗》不会有staleness现象吗?

首先说结论，不会存在staleness现象。

当 GPU1 在算 mb0 的前向时，GPU0 可能正在算 mb1/mb2 的前向。此时：

- GPU1 用的参数是当前 step 的参数，没有过期。
- GPU0 也在用同一份参数算前向。
- 前向只是“读参数、算激活”，不更新参数，所以不存在“GPU1 用的参数比 GPU0 旧”的问题。

PP 的标准训练流程中，**参数更新是在整个 step 的所有 micro-batch 的前向和反向都完成后，统一做一次 optimizer step**。前向阶段：所有 stage、所有 micro-batch 读同一份参数，无 staleness。反向阶段：梯度按 micro-batch 累积，也不更新参数，直到 step 结束才 `optimizer.step()`。**参数更新**：只在 step 末尾做一次，所有 stage 同步更新。

那你可能又有疑问了，GPU0的mb还没算完，GPU1已经开始，会不会有问题？

不会。因为，GPU1算mb0前向时，只需要mb0在stage0的输出，这个输出已经有GPU0算好传过来了。GPU0同时在算mb1前向，用的是同一个参数，和GPU1无关。GPU1依赖GPU0的mb1的结果，它只依赖mb0 的stage0的输出。 所以 GPU0 和 GPU1 的“时间重叠”是**不同 micro-batch 的流水**，不是“同一 micro-batch 的乱序”。同一 micro-batch 内，stage 之间仍然严格串行。

### **问题3：**EP 的并行发生在同一个 MoE 层内部，不同专家处理不同 token 子集，互不等待。跨 GPU 的通信是 All-to-All：把 token 发给持有目标专家的 GPU，算完再收回来。这里的把token 发给持有目标专家的GPU，算完再收，谁发谁收呢？

假设一个 MoE 层有 `E=4` 个专家，分布在 4 个 GPU 上：

```text
GPU0: expert 0
GPU1: expert 1
GPU2: expert 2
GPU3: expert 3
```

一个 batch 的 token 被切分到 4 个 GPU 上做 Attention 等前置计算，每个 GPU 手上有若干 token：

```text
GPU0 持有 token {t0, t1, t2}
GPU1 持有 token {t3, t4, t5}
GPU2 持有 token {t6, t7, t8}
GPU3 持有 token {t9, t10, t11}
```

Router 决定每个 token 去哪些专家（假设 top-1）：

```text
t0 → expert 2      t3 → expert 0      t6 → expert 3      t9 → expert 1
t1 → expert 0      t4 → expert 3      t7 → expert 1      t10 → expert 0
t2 → expert 1      t5 → expert 2      t8 → expert 0      t11 → expert 2
```

All-to-All 的发与收

**每个 GPU 做两件事**：

1. **发（send）**：把自己持有的 token 中，目标专家不在本 GPU 的，发给持有目标专家的 GPU。
2. **收（receive）**：接收其他 GPU 发来的、目标专家在本 GPU 的 token。

All-to-All 是**对称的**：每个 GPU 都向其他所有 GPU 发送数据，也从其他所有 GPU 接收数据。不是“一个发送方、一个接收方”的单向关系。

第一次All-to-All发完之后，专家算完后，结果按原路返回，再和本地token结果合并。

所以是两次All-to-All通信：

```text
第一次 All-to-All（dispatch）：token → 目标专家所在 GPU
  [专家计算]
第二次 All-to-All（combine）：专家结果 → token 原属 GPU
```

### **问题4：**再加上DP呢，三个并行策略叠加到一块，训练一步是怎样的？

加上 DP 后，三者是**正交嵌套**的关系：**DP 在最外层复制模型，PP 沿深度切分层，EP 在 MoE 层内切分专家**。

```text
DP: 把 batch 切成 D 份，每份一个 DP rank，各自持有完整的模型副本
  └─ PP: 每个 DP rank 内，模型按层切成 S 个 stage，分布到 S 个 GPU
       └─ EP: 每个 PP stage 内的 MoE 层，专家切成 E 份，分布到 E 个 GPU。 这里注意，每个PP 是若干层transfomer
层，Attention、FFN或者MOE的所有专家都是完整的。
```

一个GPU同时属于，某个DP Rank、某个PP的stage、某个EP rank，三者不冲突，是不同维度的切分。

如：8 个 GPU，DP=2, PP=2, EP=2：

```text
DP rank 0:  GPU0(stage0, expert0)  GPU1(stage0, expert1)  GPU2(stage1, expert0)  GPU3(stage1, expert1)
DP rank 1:  GPU4(stage0, expert0)  GPU5(stage0, expert1)  GPU6(stage1, expert0)  GPU7(stage1, expert1)
```

- **DP**：GPU0-3 是 rank0 的模型副本，GPU4-7 是 rank1 的副本。
- **PP**：GPU0/1 是 stage0，GPU2/3 是 stage1。
- **EP**：GPU0 和 GPU1 是 stage0 内 MoE 层的 2 个专家分片；GPU2 和 GPU3 是 stage1 的。

一步训练的完整的数据流

假设 **DP=2, PP=2, EP=2**，batch 切成 2 份（DP），每份再切成 micro-batch（PP 流水线）。

阶段 1：前向传播

**DP 层**：每个 DP rank 拿到不同的数据子集。

```text
DP rank 0: batch 的前一半
DP rank 1: batch 的后一半
```

**PP 层**：每个 DP rank 内，micro-batch 依次流过 stage0 → stage1。

```text
DP rank 0:
  stage0 (GPU0/1): 算 layer 0-7
  stage1 (GPU2/3): 算 layer 8-15

DP rank 1:
  stage0 (GPU4/5): 算 layer 0-7
  stage1 (GPU6/7): 算 layer 8-15
```

**EP 层**：在 MoE 层（比如 layer 4）内部，GPU0/1 之间做 All-to-All。

```text
GPU0 (expert0) ←→ GPU1 (expert1)   All-to-All
GPU2 (expert0) ←→ GPU3 (expert1)   All-to-All   (stage1 的 MoE)
GPU4 (expert0) ←→ GPU5 (expert1)   All-to-All   (DP rank1)
GPU6 (expert0) ←→ GPU7 (expert1)   All-to-All
```

EP的All-to-all只在同一PP stage、同一个DP rank 内的GPU之间发生。 GPU0 不会和GPU2做EP通信（它们在不同stage），也不会和GPU4 做EP通信。（它们在不同DP rank）。

阶段 2：反向传播

PP 层间反向：stage1 → stage0。EP 的 All-to-All 反向再做一次（梯度回传）。DP 之间**不通信**（各自算各自的数据）。

阶段 3：梯度同步

PP 和 EP 的梯度在**模型副本内部**通过 All-Reduce 同步（PP stage 之间传梯度，EP 专家之间传梯度）。**DP 的梯度在 DP rank 之间做 All-Reduce。**

```text
GPU0 的梯度 ↔ GPU4 的梯度   (DP All-Reduce)
GPU1 的梯度 ↔ GPU5 的梯度
GPU2 的梯度 ↔ GPU6 的梯度
GPU3 的梯度 ↔ GPU7 的梯度
```

阶段 4：参数更新

每个 GPU 用同步后的梯度更新自己那份参数。由于 DP All-Reduce 后梯度一致，**所有 DP rank 的模型副本保持同步**。

**关键点**：EP 的 All-to-All 只在同一 PP stage、同一 DP rank 内发生；DP 的 All-Reduce 只在同一模型位置的 GPU 间发生。三者通信组不重叠，可以同时存在。另外，如果再叠加上TP，也是这样的逻辑，TP切的是层间的矩阵，比如Attention、FFN计算，每个GPU算矩阵的一小部分，最后做All-Reduce合并。四者是正交关系，所以一个典型的大模型训练配置 ：总 GPU 数 = DP × PP × TP 。EP是在DP维度上切出来的，用于专家网络。

### **问题5：**GPU0 和 GPU5 拥有一样的Attention，是不是重复了？

不是重复，是各自算不同的 token。因为 DP 把 batch 切开了。两个 GPU 各自对自己的 token 算 Attention，然后各自把 token 路由到自己持有的专家。**Attention 权重是共享的**（同一份参数），但**输入 token 不同**，所以不是重复计算。

### 问题6：EP = DP * TP吗？

不是。EP 不等于 DP × TP。它们是三个正交的并行维度，各自独立切分不同的东西。

`EP` 的大小由 MoE 层的专家总数和切分策略决定，例如：

- 一层有 64 个专家，`EP=8` → 每张卡放 8 个专家；
- 一层有 256 个专家，`EP=64` → 每张卡放 4 个专家。

`DP` 和 `TP` 的大小由 batch 大小、层内矩阵/head 数决定，和专家数没有直接等式关系。

但是在推理时，一般用法是EP=总GPU数，所以就可以由上公式来推另一个变量。

### 问题7：moe做矩阵乘的时候每张卡上的token数，需不需要除以tp？

一般是需要除以 TP。再聊这个之前，先说一下SP（Sequence Parallelism 序列并行），它是TP的补充，TP

只切分了Attention 和MLP里的大矩阵乘法，一层transformer里还有一些操作没有被TP切开：

LayerNorm、dropout、残差相加。如果只有TP的话，这些操作在TP组的每张卡上都完整地重复做一遍，每一张卡都存一份完整的激活值，显存被浪费了。

```text
只有 TP（TP=4，每个 DP 副本 4096 个 token）：

           GPU0        GPU1        GPU2        GPU3
LayerNorm  4096 token  4096 token  4096 token  4096 token   ← 完全重复
Attention  切 1/4 头   切 1/4 头   切 1/4 头   切 1/4 头    ← TP 切分
   ↓ AllReduce
残差/Dropout 4096 token  4096 token  4096 token  4096 token   ← 完全重复
```

SP 把这些重复的部分按 token 切开，每张卡只处理 1/TP 的 token：

```text
TP + SP（TP=4）：

           GPU0          GPU1          GPU2          GPU3
LayerNorm  token 0~1023  1024~2047     2048~3071     3072~4095   ← SP：按 token 切
   ↓ AllGather（拼回完整的 4096 个 token）
Attention  切 1/4 头     切 1/4 头     切 1/4 头     切 1/4 头    ← TP：按矩阵切
   ↓ ReduceScatter（求和后再按 token 切开）
残差/Dropout token 0~1023  1024~2047     2048~3071     3072~4095   ← SP：按 token 切
```

通信量也没有增加。一次 AllReduce 本身就等于 ReduceScatter + AllGather，所以 SP 只是把这两步拆开，放到不同位置，总通信量不变。显存却省下来了：LayerNorm、Dropout 等部分的激活值减少到原来的 1/TP。

所以只要用了 TP，基本都会打开 SP。在 Megatron 里，MoE 和 TP 一起使用时必须开 SP。

传统的tranfomer层都是post-LN， X= LayerNorm( Attention（X）+ X ), 但是从GPT-2 开始，几乎所有大模型都改用pre-LN， 就是 X = X + Attention(LayerNorm(X))

下面，以TP = 4，hidden size h = 512，注意力头数 = 8，每个头 64 维（8 × 64 = 512），每个 DP 副本的 token 数 = 1024，专家不开 TP（ETP = 1）为例

TP=4，所以每张卡分到 8 ÷ 4 = 2 个头。

```text
整层流程图

         [256, 512]  每卡 1/4 的 token
             │
   LayerNorm │ ← SP 区域，无通信
             ↓
  ┌──── AllGather ────┐  通信①
  │      [1024, 512]  │
  │                   │
  │  W_qkv 列并行     │  W 按列切，X 完整，输出 [1024,128]
  │  注意力（2个头）   │  无通信
  │  W_o   行并行     │  W 按行切，输出部分和 [1024,512]
  │                   │
  └── ReduceScatter ──┘  通信②
             │
         [256, 512]
    残差 + LayerNorm   ← SP 区域，无通信
             │
          路由器       ← 每卡独立路由自己的 256 个 token
             │
     All-to-All dispatch  通信③（EP 组内）
             │
        专家 FFN       ← ETP=1，权重完整，无 TP 通信
             │
     All-to-All combine   通信④（EP 组内）
             │
      加权求和 + 残差
             │
         [256, 512]  → 下一层
```
