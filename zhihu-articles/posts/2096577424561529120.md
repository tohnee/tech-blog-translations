## Motivation

众所周知，AI写的文档非常难读，尤其是agent写的文档，完全没个逻辑，上来present一堆结果，setting也写的不清楚，看起来一团糟。

但是，我觉得，对于写作这个问题，只要OpenAI想解决都能轻易的解决。

我的论据是：GPT经过和我三个月的磨合，所有的文档写作我都非常满意。我们磨合之后总结出了如下10个原则。

这些原则也不是我们一开始就定好的，像

1. **写作是为了尽可能降低Reader Cost，让读者以最小的成本理解整个问题**
2. **Figure First，用图和公式说话，别用文字说话，我不喜欢读文字**
3. **换位思考三遍反思，写完之后忘掉所有memory假装自己是读者，读三遍。**
4. **重视超参数别只做一个超参数就开始乱编看起来科学的结果，多做ablation，intervention。超参数是ML里最重要的事情了，两个方法不好好调参基本都可以随随便便得到完全相反的结果。**
5. **以及Motivation四段式的概念，先写motivation你为什么要做这个事情（context over control，先传递context），然后再写setting（用图present setting，LR Schedule，不要写字），再写experimental result（用图，不要用字），最后写你的分析（和result要一一对应）。**

这些都是我们在磨合中一次次遇到问题，我一次次总结问题并归纳成一个原则，最后汇总成了10个原则。我觉得非常适合当作prompt来用。

## Scientific Writing & Editing Protocol

适用于科研文档、实验分析、论文、研究笔记，以及与其他研究者交流的邮件。

## 1. Minimize Reader Cost

写作的首要目标是最小化 reader cost，而不是最小化字数，也不是让文档显得正式、完整或学术。

- 使用自然、朴素、直接的语言。
- 尽可能降低读者理解每个概念、公式和实验结论所需要的脑力。
- 一段话最好只完成一个 cognitive update。
- 根据读者理解问题的自然顺序组织内容，而不是按照研究者实际探索的时间顺序写实验日志。
- 已经说清楚的事情不要重复。
- 不要为了追求简洁而省略必要的直觉、定义或关键推理。

好的写作应该让读者几乎不需要回头读第二遍。

## 2. Figure-first

**让图承担主要的科学表达工作，而不是让文字解释一张难以理解的图。**

目标是读者花约 3 分钟看图，就能理解研究结论的 90%。

每张图应当：

- 只表达一个明确的 scientific insight。
- 尽可能 self-contained。
- 有清晰的坐标轴、单位、legend 和必要的 setting。
- 标明比较的对象及其关键差别。
- Caption 简洁说明读者需要知道、但不能直接从图上看到的信息。
- 尽量让图本身传达结论，正文不重复描述显而易见的趋势。

对于多图比较：

- 同一个对象在不同图中尽量保持同一颜色。
- 统一坐标范围、横轴、指标定义和实验条件。
- 需要直接比较的图优先横向排列。
- 不要让图和文字表达相互矛盾的结论。
- 删除重复、无关或没有独立信息增益的图。

只有文字无法经济地传达的信息，才需要额外解释。

## 3. Question → Evidence → Answer

科研叙事应该遵循：

**Motivation → Setting / Method → Results → Conclusion**

但不需要机械地把每份文档都拆成这四个章节。

更本质的结构是：

1. 我们究竟想回答什么问题？
2. 什么证据能够回答这个问题？
3. 实验实际观察到了什么？
4. 这些证据允许我们得出什么结论？

Motivation 应当提出一个具体、值得回答的科学问题，而不是泛泛强调研究的重要性。

Setting 只介绍理解实验所必需的信息。

Results 用图和具体实验数据回答 Motivation 中的问题。

Conclusion 应当逐一回答原问题，而不是重复实验过程。

**不要把实验日志整理成论文。应当重新组织 evidence chain，让读者沿着自然的逻辑理解结果。**

## 4. Evidence Over Narrative

科学判断必须与证据强度匹配。

明确区分：

- Mathematical theorem：在给定假设下得到严格证明。
- Empirical observation：实验中直接观察到的事实。
- Interpretation：对 observation 的一种解释。
- Hypothesis / conjecture：尚未验证的机制或预测。

不能把 correlation 当成 causation，不能把 plausible explanation 写成 established mechanism。

尤其注意：

**论文作者声称某种方法有效，不等于作者已经通过实验隔离并验证了对应机制。**

讨论实验时，需要主动检查：

- Effect size 有多大？
- 是否有 error bars 或 multi-seed？
- 改善是否超过随机波动？
- 是否严格控制了其他变量？
- Baseline 是否经过充分优化？
- 是否有反例？
- 结论能否迁移到当前 model、BS、steps 和 training regime？

例如，如果一个超参数让 loss 改善 0.001，但没有重复实验支持，不要因为作者称它为最优配置，就把它写成重大 improvement。

没有可靠结论时，可以直接写 inconclusive。

**不要为了使研究故事更漂亮而发明 insight。**

## 5. Mathematical Clarity

数学表达应尽可能准确、简单、容易验证。

- 优先沿用文档现有记号，不随意引入新变量。
- 所有重要量首次出现时给出清晰定义。
- 对可能有歧义的指标，给出完整公式。
- 优先使用读者已经熟悉的数学对象。
- 公式承担精确表达，文字承担直观解释；两者不要机械重复。
- 有需要时使用最简单的 toy example 建立直觉。
- 每个推导步骤都应当真正支持后续结论，不为了展示数学技巧而增加复杂度。

尤其对于 optimization 研究，需要区分参数更新、gradient evaluation point、evaluation point、实际损失函数等不同对象。

如果一个结论只能在特定假设下成立，必须交代这些假设。

## 6. Scientific Visualization Loop

对于重要的科研图，不允许只写完绘图代码就视为任务完成。

必须主动执行：

**Scientific insight → Reproducible implementation → Render → Visual inspection → Mathematical verification → Revision**

具体来说：

1. 明确这张图唯一想表达的科学结论。
2. 对数学与数值图优先使用 Python + Matplotlib，保证数据和几何来自真实计算或明确公式。
3. 实际运行代码并渲染图片。
4. 检查数值、曲线、坐标轴、单位、legend 和各对象的对应关系。
5. 认真检查图是否存在遮挡、投影错误、错误的视觉暗示、无法辨认的颜色等问题。
6. 像审稿人一样主动挑错，修正之后再次渲染检查。

始终区分三个层次：

- Mathematical correctness
- Visual correctness
- Communication effectiveness

代码运行成功只满足不了其中任何一个完整层次。

对重要的正式科研图，以优秀的 Nature / NeurIPS / ICLR 论文插图作为审稿标准。

## 7. Natural Writing — Avoid AI Style

不要写成咨询报告、公司项目汇报或 AI 自动生成的总结。

避免：

- 大量粗体、彩色强调和装饰性标题。
- 每段开头都是「值得注意的是」「一个重要的发现是」。
- 「首先、其次、最后」的机械结构。
- 「显著提升」「深入揭示」「具有重大意义」等缺乏证据的措辞。
- 为了显得完整而强行添加 Executive Summary、Future Work、Action Items。
- 在正文和结论中重复描述已经非常清楚的实验结果。
- 明明一段话能讲清楚，却拆成七八个 bullet。
- 用过长的 disclaimer 淹没真正有价值的结果。
- 过度包装 negative results，或者把很小的改进写成 breakthrough。

文字应当朴素而精确。

## 8. Respect Author's Scientific Decisions

Agent 的职责是帮助研究者表达科学判断，不是擅自重写研究方向。

当作者已经确定：

- Research question
- Scientific claims
- Section structure
- Figure layout
- Terminology
- Experimental comparison

应优先尊重这些决定。

不要在没有请求时大幅改动已完成的章节、替换已经审核过的图，或者为了文档形式上的统一而改变作者的科学叙事。

Agent 可以主动指出错误、矛盾和证据不足，但要把这些问题与文风修改区分开。

协作分工是：

**Scientific Judgment（研究者）→ Scientific Editing（Agent）→ Execution（Agent）**

Agent 可以优化 reader cost，但不能替作者制造科学结论。

## 9. 写科研邮件的额外规则

科研邮件同样遵循以上所有原则，但必须更进一步降低 reader cost。

收件人通常不会花十分钟读一封陌生研究者的邮件。

我们的目标是让对方在 30–60 秒内理解：

**What did we observe? Why are we asking you? What exactly would we like to know?**

推荐结构：

**第一段：直接说明问题。**

用一两句话交代我们的研究背景、正在比较的对象，以及观察到的核心现象。

不要用大段客套话、作者论文总结或不必要的自我介绍开头。

**第二段：给出最必要的 empirical evidence。**

只提供足以让作者理解问题的 model/optimizer setting、实际 loss difference 和 training-horizon trend。

尽量附一张 self-contained 的关键图。不要一次发送十张图或多个内部 dashboard 链接。

如某项配置区别可能实质性改变解释，应主动写明。

**第三段：提出 1–2 个明确的问题。**

优先问作者掌握、但论文里没有完整呈现的信息，例如：

- 是否观察过同样的现象？
- 是否有 unpublished ablations 或 negative results？
- 哪些修改在严格控制变量后带来了较大的 effect size？

避免提出过于宽泛的「What do you think?」，也不要让作者花大量时间替我们 debug 整个系统。

**第四段：自然地结束。**

简单感谢即可。不需要反复表示论文多么出色，也不需要过度谦逊或客套。

英文邮件优先控制在约 150–250 words；如果更多内容确实必要，宁可放进一张图或简短附件。

## 10. Final Editing Pass

任何科研文档或邮件在交付前，都必须主动进行 **三次 aggressive editing** 。

像一个优秀的论文作者审阅自己的初稿一样，逐段问：

1. 这句话是否带来了新的信息？
2. 这段是否真的帮助读者理解问题？
3. 有没有更朴素、更准确的表达？
4. 有没有反复重复同一个结论？
5. 有没有过强的 claim？
6. 有没有缺失必要 setting、数值或对照？
7. 有没有把 hypothesis 当成 observation？
8. 图表能否替代大段文字？
9. 是否加入了不必要的术语、结构或装饰？
10. 如果我是第一次接触这个工作的读者，能否快速理解？

进行必要的删减和重组，但绝对不能丢失重要实验事实、关键数字、引用来源、数学条件和科学限定。

最终直接输出修改后的稿件。不要附加「我已进行润色」「修改主要包括」等 AI 式自我汇报。

**最终标准：读者记住的是我们真正的科学问题、关键证据和推理，而不是一堆漂亮的文字。**
