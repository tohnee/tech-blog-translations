## .NET 开发者如何理解生成式 AI：基础概念与工具选型

最近几年，AI 正在进入 .NET 技术栈的各个层面，从 Visual Studio 到 Azure，再到开发者日常使用的基础库。

但许多 AI 教程默认读者是数据科学家，或者愿意把开发工作迁移到 Python。对于已经使用 C# 构建业务系统的开发者来说，更实际的问题是：生成式 AI 到底是什么？需要理解哪些概念？现有的 .NET 工具分别能解决什么问题？

理解这些问题，不必从训练模型开始。先建立清晰的概念，再选择合适的工具，就能更合理地设计 AI 应用。

### 一、生成式 AI 是什么？

从工程角度看，AI 可以理解为：从数据中学习模式，并利用这些模式进行预测或生成输出的系统。

这个定义既涵盖垃圾邮件过滤器，也涵盖大语言模型。两者的差异在于规模、架构，以及输出的类型。

对于开发者，一个重要区别是：

- 分类型任务：判断这封邮件是不是垃圾邮件。
- 生成型任务：根据指定主题写一封邮件。

生成式 AI 属于后一类。它根据训练过程中学到的模式，生成文本、代码、图像或结构化数据等内容。

理解这一点，有助于避免两个极端：把模型当成无所不知的系统，或者低估它能够承担的任务。

### 二、机器学习、深度学习和大语言模型，有什么区别？

这些术语经常混在一起出现，但它们并不是同义词。

机器学习是其中最广泛的概念。它让系统通过接触数据改善任务表现，而不是依赖开发者逐条编写规则。线性回归、决策树、随机森林和支持向量机，都属于常见的机器学习方法。

在 .NET 生态中， [http://ML.NET](http://ML.NET) 可以用于数值预测、分类、异常检测和推荐等任务，涵盖数据加载、特征处理、训练、评估和部署等环节。

深度学习是机器学习的一个子集，主要使用具有多个层次的神经网络，从图像、音频和文本等数据中学习复杂的表示。

与依赖人工设计特征的方法相比，深度学习的重要特点，是模型能够从数据中学习哪些特征有用。

对于 .NET 开发者，ONNX Runtime 提供了一条运行预训练模型的路径：将兼容的模型导出为 ONNX 格式，再在 C# 应用中执行推理。

大语言模型，也就是 LLM，则是深度学习模型中的一类。主流大语言模型广泛采用 Transformer 架构，并通过大规模数据训练获得语言处理能力。

它们的突出特点是通用性。传统机器学习模型通常面向某个具体任务，而大语言模型可以处理写作、摘要、翻译、代码生成和推理等多种任务。这种通用性使它们强大，也使它们的表现更难预测。

可以把三者的关系理解为： **大语言模型属于深度学习，深度学习属于机器学习。**

### 三、理解 Transformer，需要掌握什么？

使用大语言模型，并不意味着必须先掌握 Transformer 的全部数学原理。但理解它的大致工作方式，有助于减少架构上的误判。

其中一个核心概念是自注意力，也就是 Self-Attention。

以英文单词 `bank` 为例，它既可以表示“银行”，也可以表示“河岸”。要判断具体含义，需要结合周围出现的是 `account` ，还是 `river` 。

自注意力机制让模型能够根据上下文，计算不同 Token 之间的关联程度。

与早期依赖顺序处理的模型相比，Transformer 更便于并行处理输入和执行训练计算，因此能够更有效地利用 GPU。但这不意味着常见的文本生成过程可以一次性并行产生整篇回答。

最初的 Transformer 架构包含两个部分：

- 编码器负责处理输入。
- 解码器负责生成输出。

这种结构适合翻译等任务：先编码源语言，再生成目标语言。

许多现代大语言模型采用仅解码器，也就是 Decoder-only 架构。它们接收一串 Token，并预测接下来应该出现什么。

### 四、Token：模型处理文本的基本单位

大语言模型处理的基本单位并不是日常意义上的单词，而是 Token。

一个 Token 可能是完整单词、单词的一部分、标点，或者单个字符。具体如何切分，取决于模型使用的分词器。

对工程师而言，Token 至少影响三个方面。

第一个是成本。模型 API 通常按照 Token 数量计费。同一段文本，在不同分词器下得到的 Token 数量可能不同。

第二个是上下文限制。模型能够处理的上下文长度通常以 Token 衡量，因此不能直接用字数或文档页数代替。

第三个是模型行为。看起来相似的文本，可能被拆分成不同的 Token 序列，这会影响模型对它们的处理。

常见分词方法包括 BPE，以及 SentencePiece 所支持的相关方法。开发者通常不需要直接实现分词器，但理解 Token 有助于解释定价、上下文限制和部分模型行为。

### 五、上下文窗口：模型当前能使用多少信息？

上下文窗口可以理解为模型当前交互中的“工作记忆”。

模型处理请求所需的信息，需要在其上下文限制内进行安排，同时为输出预留空间；具体输入和输出限制取决于模型及服务。

这意味着，应用不能默认模型会自动记住之前独立发出的 API 请求。需要持续使用的信息，应由应用或平台的会话机制保存和提供。

这一限制会直接影响应用设计。

聊天记录会占用上下文。随着对话变长，应用可能需要删除较早的消息，或者对历史内容进行摘要。

长文档可能需要分块。当文档超过模型能够处理的范围时，就需要拆分、分别处理，再组织结果。是否需要分块，应根据实际 Token 数量判断。

系统提示词同样占用上下文。详细的指令、示例和约束，可能在用户输入问题之前，就已经消耗了一部分容量。

因此，上下文管理是 AI 应用开发中的重要工程问题，需要同时考虑容量、成本和处理方式。

### 六、Embedding：把文本表示为向量

Embedding 是文本的数值表示，通常表现为一组浮点数构成的向量。

它的重要特性是：语义相近的文本，通常会得到相近的向量表示。

例如：

> “如何重置密码？”

以及：

> “我忘记了登录凭据。”

虽然两句话使用的词语不同，但含义相关，因此可以通过向量相似度进行匹配。

这一能力是语义搜索、推荐系统和检索增强生成，也就是 RAG，的重要基础。

Embedding 模型与生成模型承担的任务不同。前者把文本转换为向量，后者负责生成新的内容。

在 .NET 应用中，可以通过相应客户端调用 Embedding 服务，再将向量保存到支持向量检索的存储系统，例如 Azure AI Search、Azure Cosmos DB 或 Qdrant，以便查询时进行相似度搜索。

### 七、为什么 .NET 可以用来构建 AI 应用？

Python 长期占据 AI 领域的重要位置，与模型训练生态密切相关。PyTorch、TensorFlow 和 Hugging Face 等工具，都与 Python 有紧密联系。

但训练模型与使用模型，是不同的工作。

大多数 .NET 开发者并不需要从零训练大模型，而是使用预训练模型：发送提示词、接收生成结果、生成向量，以及组织多步骤流程。

对于这些应用开发任务，.NET 已经提供了相应的工具，并能够结合强类型、依赖注入和现有应用结构使用。

### 八、.NET AI 生态中的工具，分别负责什么？

原文重点介绍了以下几个工具：

| 工具 | 主要用途 | 适用情况 |
| --- | --- | --- |
| Microsoft.Extensions.AI | 提供统一的 AI 服务抽象 | 调用聊天和 Embedding 能力，减少对具体服务商的耦合 |
| Semantic Kernel | 组织 AI 工作流、插件和工具 | 需要多步骤编排或 Agent 类行为 |
| http://ML.NET | 机器学习训练与应用 | 分类、回归、异常检测和推荐等任务 |
| ONNX Runtime | 执行预训练模型 | 在 .NET 应用中运行兼容的本地模型 |
| Azure.AI.OpenAI | 访问 Azure OpenAI 服务 | 直接集成 Azure OpenAI 及相关服务能力 |

Microsoft.Extensions.AI 定义了 `IChatClient` 、 `IEmbeddingGenerator` 等标准接口。

可以把它理解为类似 `ILogger` 的抽象方式：业务代码围绕统一接口组织，再通过相应实现连接具体服务商。

Semantic Kernel 面向更复杂的 AI 应用组织方式，提供插件、工具集成和工作流编排等能力。当需求涉及多个步骤、外部工具或 Agent 类行为时，可以评估它是否能够简化实现。

[http://ML.NET](http://ML.NET) 主要面向传统机器学习任务。如果问题是基于表格数据进行预测或分类，它通常比生成式 AI 框架更值得优先考虑。

ONNX Runtime 用于执行兼容的预训练模型，例如图像分类、目标检测或特定自然语言处理模型，将模型训练与 .NET 推理部署连接起来。

Azure.AI.OpenAI 则提供访问 Azure OpenAI 服务的客户端能力。对于部署在 Azure、需要结合其身份认证和企业服务配置的应用，它是可以考虑的直接接入方式。

### 九、选择满足需求的最轻量抽象

原文给出的核心架构建议是：

> 选择能够满足需求的最轻量抽象层。

如果只是发送提示词并获取回答，Microsoft.Extensions.AI 配合相应模型服务，可能已经足够。

如果需要组织检索、模型调用和外部工具等多个步骤，可以进一步评估 Semantic Kernel。

如果需求是销量预测或分类，应考虑 [http://ML.NET](http://ML.NET) 等机器学习工具；如果要运行特定的预训练模型，则可以考虑 ONNX Runtime。

这些工具解决的问题不同，不需要在每个项目中全部引入。

对于 .NET 开发者，入门生成式 AI 的第一步，是理解模型、Token、上下文和 Embedding 分别意味着什么，再把具体需求映射到合适的工具。接下来，可以继续学习下一 Token 预测、温度和采样机制，进一步理解模型如何生成文本。
