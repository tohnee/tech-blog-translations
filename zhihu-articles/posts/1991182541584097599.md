## Introduction to InfiniBand

### What is InfiniBand

InfiniBand 是业界通行的标准规范，用来定义一种输入/输出（I/O）架构，用于将计算节点、通信基础设施设备、存储系统以及嵌入式系统互联起来，在这套架构中服务器的操作系统是独立的，可以是Linux、Windows or ESXI.

## InfiniBand Key Features

NVIDIA Mellanox 的 InfiniBand 互连方案提供高速、超低时延且可扩展的网络能力，使超级计算机、人工智能（AI）以及云数据中心能够在不同规模下稳定运行，同时降低运维成本并简化基础设施复杂度。凭借这些优势，InfiniBand 成为 AI、深度学习、数据科学等各类加速计算应用首选的互连技术之一。

![](https://picx.zhimg.com/v2-7fb302173b1f4cba35fcd07b0c8b8bef_r.jpg)

### Simplified Management

InfiniBand 常被视为最早把 SDN（软件定义网络）思想落到实处的网络架构之一，因为它的网络控制与管理由子网管理器（SM）统一承担。SM 本质上是一段运行在网络中某台设备/主机上的管理软件，负责整个子网的拓扑发现、路径计算与路由下发，让节点接入后可以自动被识别并快速投入使用（类似即插即用）。如下图所示，在每个 InfiniBand 子网中都会有一个主 SM 负责日常管理；为了避免单点故障，通常还会配置一个备用 SM，在主 SM 出现问题时接管，保证网络持续可用。

![](https://pic4.zhimg.com/v2-2b1bfd955cea7c79ae4136ec1a8acbf9_r.jpg)

### CPU Offloads

InfiniBand 的架构设计让数据传输几乎不需要 CPU 过多参与，从而显著降低开销、提升效率。之所以能做到这一点，主要得益于：

- **硬件实现的传输协议**：把关键的数据传输处理交给网卡/硬件完成，而不是依赖 CPU 进行大量软件处理。<br>
- **内核旁路或零拷贝**：减少甚至避免数据在内核态/用户态之间来回切换和复制带来的性能损耗。<br>
- **RDMA（远程直接内存访问）**：允许数据直接从一个节点的内存读写到另一个节点的内存，全程不需要动用任一方的 CPU 参与数据搬运。

![](https://picx.zhimg.com/v2-7f7e499921627efa54f7d053131af8f5_r.jpg)

### GPU Direct

为了进一步减轻计算节点的负担，NVIDIA 也在 GPU 层面提供了相应的卸载能力。借助 **GPUDirect**，数据可以直接从一块 GPU 的显存传输到另一块 GPU 的显存，无需绕经 CPU 或系统内存，从而带来更低的时延与更高的吞吐表现，更好地释放 GPU 加速计算的性能优势。

![](https://pic1.zhimg.com/v2-30dd53584e4a72632e64cfc632b8aa9e_r.jpg)

### Low Latency

InfiniBand 之所以能做到极低时延，关键在于其架构中将多种**硬件卸载**与**加速机制**组合在一起协同工作，这也是它区别于其他互连技术的核心特点之一。因此，基于 RDMA 的端到端通信时延可低至约 **1000 纳秒**，也就是 **1 微秒**左右。

![](https://pic3.zhimg.com/v2-133b80fed6b0be95c69e380865ea4660_r.jpg)

### Network Scale-Out

InfiniBand 的一大优势在于：在同一个子网内就能容纳多达约 **48,000** 个节点。若规模需要继续扩大，还可以通过 **InfiniBand 路由器**把多个 InfiniBand 子网互联起来，从而轻松突破单一子网的节点数量上限，实现更大规模的扩展。

![](https://pic4.zhimg.com/v2-bae24f55537bac68a7af21dc43a9a7e5_r.jpg)

### Quality of Service

服务质量（QoS）指的是针对不同对象提供不同优先级保障的能力，例如：应用、用户、数据流，对于需要更高优先级的应用，会将其流量映射到单独的端口队列中，使相关数据包在转发时优先发送到网络中的下一跳设备。

![](https://pic2.zhimg.com/v2-28d44873966152f36b9c024c9f0c0f6d_r.jpg)

### Fabric Resiliency

客户最看重的核心能力之一，是网络要足够稳定、尽量避免链路故障；但即便发生故障，业务流量也必须能够迅速恢复。若故障后的流量改道完全依赖子网管理器（SM）的路由算法来重新计算与下发，流量恢复时间可能会达到约 **5 秒**左右。

![](https://pic4.zhimg.com/v2-0cc4d8d87a0f8d0c839199e9e5f3ffed_r.jpg)

### NVIDIA Self-Healing Networking

NVIDIA 交换机具备硬件级的“自愈网络”功能。NVIDIA 的自愈技术直接在 **硬件层面处理**，将时间压缩到 1 毫秒（微秒级感知），应用层几乎察觉不到抖动，从而保证了业务的连续性。该技术能将链路故障恢复速度提升 5000 倍！

![](https://picx.zhimg.com/v2-aeee877df4cd5eca8f9798e83383e53d_r.jpg)

### Load-Balancing

现代高性能数据中心还必须解决另一个核心诉求：如何实现网络效能的最优利用与持续优化。实现这一目标的关键路径之一，是引入高效的负载均衡机制。负载均衡本质上是一种路由策略，它能将数据流量动态分摊到多条可用的物理路径上，从而避免单点拥塞。

![](https://pic4.zhimg.com/v2-5e1922612e6f15f3e6ac1badebd74bf5_1440w.gif)

### Adaptive Routing

自适应路由（Adaptive Routing）是一种用于在交换机各端口之间均衡流量分布的机制，能够动态调节不同端口所承载的流量负载。该功能由 NVIDIA 交换机硬件原生支持，并由自适应路由管理器（Adaptive Routing Manager）进行统一控制与管理。

在启用自适应路由后，交换机内部的“队列管理器（Queue Manager）”会持续监测各个出口端口组的队列占用情况，对端口间的流量负载进行实时对比与分析。基于这些信息，队列管理器动态调整队列负载，将数据流或数据包转发至当前利用率较低的替代端口，从而实现流量的智能分流。

自适应路由可在整个交换网络（Fabric）的所有交换机上启用，支持动态负载均衡，有效避免网络内部拥塞，并最大化网络带宽的整体利用效率。

![](https://pica.zhimg.com/v2-d32c18b04619624571c578505201c1c8_r.jpg)

### SHARP

SHARP（Scalable Hierarchical Aggregation and Reduction Protocol，可扩展分层聚合与归约协议）是一种基于 NVIDIA 交换机硬件并由集中式管理软件统一调度的网络加速机制。该技术将原本由主机 CPU 或 GPU 执行的集合通信（Collective Operations）卸载到网络交换机中完成，从而避免数据在端点之间被多次重复传输。

通过在网络中直接执行聚合与归约操作，SHARP 显著减少了需要在网络中传输的数据量。得益于这一机制，SHARP 能够大幅提升基于 MPI 的加速计算应用性能，在特定场景下性能提升可高达 10 倍。

![](https://pic1.zhimg.com/v2-bbf864df4d3e12136d344ea41809b250_r.jpg)

### InfiniBand Topologies

InfiniBand 支持多种网络拓扑结构，包括：Fat Tree（胖树拓扑）、Torus（环面拓扑）、Dragonfly+、Hypercube（超立方体拓扑）、HyperX 得益于对多样化拓扑结构的良好支持，InfiniBand 能够满足不同客户在高性能计算和数据中心场景下的多样化需求，包括：实现网络的平滑扩展与规模化部署、降低总体拥有成本（TCO）、支持高阻塞比或可控阻塞设计、在网络节点之间实现极低通信时延、支持更远的互联距离。

![](https://pic1.zhimg.com/v2-94c78401b9d579464cb2f0a83a33ee8c_r.jpg)

## InfiniBand Architecture

### Introduction to InfiniBand Architecture

### InfiniBand vs. TCP/IP

如下图所示，InfiniBand 架构采用分层设计，其体系结构可划分为五个层次，在形式上与传统的 TCP/IP 模型类似，但在设计理念、功能实现以及通信机制等方面，InfiniBand 与 IP 网络之间仍存在显著差异。

![](https://picx.zhimg.com/v2-429c390bd3c15952c1f1cc338c54bca1_r.jpg)

### Communication Channels

在传统网络中，应用程序要进行通信，通常需要通过操作系统 **转一手** 来完成。而 InfiniBand 则让应用程序能够更直接地在网络中传输数据，几乎不需要操作系统的参与。这种以应用为核心的通信方式，使 InfiniBand 在性能和效率上明显优于传统网络，也正是它与传统网络最大的不同之处。

![](https://pic1.zhimg.com/v2-46382e8021659eadf3f7aee21fedce66_r.jpg)

### InfiniBand Architecture Layers

接下来，我们将从整体到细节，逐层了解 InfiniBand 架构中各个层次是如何协同工作，从而实现加速计算应用所需的高速、高效数据传输。我们将从最上层，上层协议（Upper Layer）开始介绍。

### Upper Layer

应用程序是 InfiniBand 消息服务的 **使用者**。InfiniBand 架构的最上层定义了应用程序如何调用和使用 InfiniBand 所提供的各种通信服务，也就是规定了应用访问 InfiniBand 能力的方式和接口。

![](https://pic2.zhimg.com/v2-b2238d1fba082c9932ef5f15a443fe77_r.jpg)

在 InfiniBand 中，上层协议为应用程序提供了一套统一、直观的接口，应用可以直接使用这些接口进行高性能通信，而无需经过复杂的操作系统网络协议栈。 相比之下，在传统 TCP/IP 网络中，应用程序通常需要通过操作系统的 TCP/IP 协议栈来完成通信，数据会在内核态和用户态之间多次拷贝，带来额外的延迟和性能开销。

InfiniBand 支持的上层协议包括：

- MPI：用于分布式和并行计算，是高性能计算（HPC）中最常见的通信方式
- NCCL：NVIDIA 提供的 GPU 集合通信库，针对多 GPU、多节点加速计算进行优化
- 基于 RDMA 的存储协议：通过绕过内核实现高速、低延迟的数据读写
- IP over InfiniBand：在需要兼容传统网络应用时，使 IP 应用也能运行在 InfiniBand 网络上<br>

![](https://pic1.zhimg.com/v2-658358a5e78fcda7c742ff1a60e506dc_r.jpg)

### Transport Layer

如下所示，TCP/IP 主要依赖操作系统：数据必须先经过发送端操作系统，再通过网络传输，最后再到达接收端操作系统。这种方式增加了数据传输的延迟和开销。

![](https://pica.zhimg.com/v2-5192d1ca5447741bed303fcde36548f8_r.jpg)

如下图所示， InfiniBand 则提供基于硬件的传输服务，由网络适配器（也称为 HCA，即 Host Channel Adapter）直接在硬件层面处理数据传输，从而绕过操作系统，提高通信速度和效率。

换句话说，当应用程序发出消息传输请求后，数据包会由发送端的硬件直接发送出去。到了接收端，这些数据包会直接被写入接收应用程序的缓冲区，而无需经过操作系统的干预。这种机制大大减少了数据在传输过程中的延迟，使通信更快、更高效。

![](https://pica.zhimg.com/v2-ed842d2f613d0b2960e96698cea677c8_r.jpg)

### Network Layer

InfiniBand 路由器用于连接不同的 InfiniBand 子网（Subnet）。通过路由器，网络可以实现规模扩展、流量隔离，并允许多个子网共享公共资源。在 InfiniBand 架构中，网络层定义了跨子网路由数据包的协议。路由器根据每个节点的网络地址 全局 ID（GID, Global ID 理解为TCP/IP中的IP地址）将数据包准确地转发到目标节点，实现子网之间的通信。这种设计不仅保证了网络的可扩展性，也方便大型数据中心和高性能计算集群的灵活部署。

![](https://pic3.zhimg.com/v2-453e7b1f2c8fb4ee3a1f50034190f266_r.jpg)

### Link Layer

LIDs – Local IDs

在每个 InfiniBand 子网中，每个节点都会被分配一个本地 ID（LID, Local ID），用于在子网内部进行数据通信。这些 LID 由 **子网管理器**（Subnet Manager）统一分配和维护，保证每个节点都有唯一的地址，从而让数据包能够正确地在子网内找到目标节点。

![](https://pic2.zhimg.com/v2-c98f9775639957d171569ce14afe3233_r.jpg)

Switches Forwarding Tables

每个 InfiniBand 交换机都有一张转发表，用于将目的节点的 LID（Local ID） 映射到对应的出口端口。这些转发表的内容由 子网管理器（Subnet Manager）计算生成，然后写入交换机的硬件中，使数据包能够按照预定路径快速转发到目标节点。

![](https://pic3.zhimg.com/v2-318c1816e7f580cfb8df3549b1b0dc82_r.jpg)

Switching InfiniBand Packets

当一个终端节点生成数据包时，数据包中会包含源 LID（发送节点的地址）和目的 LID（接收节点的地址）。当数据包到达交换机时，交换机会查看自己的转发表，根据目的 LID 找到对应的出口端口，然后将数据包发送到正确的方向。

![](https://pica.zhimg.com/v2-75b3a28d91116ef912fa07c4e2c65938_r.jpg)

Flow Control

InfiniBand 的另一个关键机制是链路层流控协议。流控的作用是调节发送端和接收端之间的数据传输速率，确保高速发送方不会淹没慢速接收方。

如下图所示发送节点会动态监控接收节点缓冲区的使用情况，只有在接收方有足够空间时才发送数据。这种机制，使 InfiniBand 成为无丢包网络：在正常运行情况下，数据包不会在网络中被丢弃，从而保证了通信的可靠性和高效性。

![](https://pic4.zhimg.com/v2-66b5ffb890ec8e6ab6b72c97a3093237_r.jpg)

### Physical Layer

虽然上层有各种协议和机制来保证高效通信，但数据最终还是通过物理媒介以比特形式传输。InfiniBand 的物理层定义了：比特如何在传输介质上表示和传送，如何通过信号判定哪些是有效的数据包。

除了定义比特传输和信号协议外，物理层还规定了**铜缆和光纤** 的特性和规格，确保不同类型的物理介质都能可靠地传输数据并兼容 InfiniBand 网络标准。 如下图所示，DAC 在主机与边缘交换机中互联使用，AOC 在边缘交换机和汇聚交换机互联使用。

![](https://pic3.zhimg.com/v2-f009a69fb4522a3bd76ea7de8d5ec65a_r.jpg)

InfiniBand 铜缆通常由多条物理通道（lane）聚合而成，这样可以提供更高的带宽。

![](https://pic4.zhimg.com/v2-bfb45b3f2aa041017f853223edcb5bdb_r.jpg)
