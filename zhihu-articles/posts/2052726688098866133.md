📖 项目简介

这是一个**一键式本地大模型部署工具**，集成了 `llama.cpp` 和 `OpenWebUI`，让您能够在自己的电脑上轻松运行和管理开源大语言模型（如 Qwen、Llama 等）。本工具**无需额外安装 Python 或 Node.js**，所有依赖均可自动下载并配置，真正做到开箱即用。

---

### ✨ 核心特性

| 功能模块 | 说明 |
| --- | --- |
| 🔍 智能环境检测 | 自动检查 Python、Node.js、Git、llama.cpp、OpenWebUI 及 CUDA 运行时的安装状态 |
| 🚀 一键环境修复 | 自动下载并安装缺失组件，支持国内镜像加速，无需手动配置 |
| 🎯 CUDA 版本自适应 | 自动检测系统 CUDA 版本（11/12/13），下载匹配的 llama.cpp 和 cudart 运行时 |
| ⚙️ 灵活的参数配置 | 可视化调整端口、上下文大小、GPU 层数、温度等推理参数 |
| 🌐 一键启动服务 | 顺序启动 llama.cpp 后端和 OpenWebUI 前端，服务就绪后自动打开浏览器 |
| 📋 实时日志输出 | 清晰显示各组件运行日志，便于排查问题 |

### 📥 下载与安装

### 1. 下载启动器

- 从 [Releases](https://gitee.com/yxtt/llama-cpp-launcher./releases/tag/Llama_LauncherV1.00) 页面下载最新版本的 `Lanch.exe`（或 `Lanch.py` 源码）
- 将文件放置于一个**独立的空文件夹**中（例如 `D:\LocalLLM`）

### 2. 首次运行

- 双击 `Lanch.exe` 启动程序
- 程序会自动检测当前环境，并在界面中显示各组件状态

> 💡 **提示**：若使用源码运行，请确保已安装 Python 3.10+，并在命令行执行 `python Lanch.py`

### 🚀 快速开始

### 方式一：一键启动（推荐）

1. 点击 **「环境修复」** 按钮，等待所有组件自动下载安装完成
2. 确保已下载模型文件（`.gguf` 格式），或点击 **「浏览」** 选择模型
3. 点击 **「一键启动 (顺序)」** ，程序将自动启动 `llama.cpp` 和 `OpenWebUI`
4. 等待日志显示 **“OpenWebUI 已就绪，打开浏览器…”** 后，浏览器自动打开 `http://localhost:8080`

### 方式二：分步启动

1. **环境修复** → 确保所有组件状态为 ✅
2. **启动 llama.cpp** → 等待日志显示 `llama.cpp 启动成功`
3. **启动 OpenWebUI** → 等待日志显示 `OpenWebUI 已就绪` 并自动打开浏览器

### 自动下载内容

| 组件 | 来源 | 大小 |

| OpenWebUI | GitHub 镜像（git clone） | ~200 MB（含依赖） |

### CUDA 版本匹配逻辑

1. 程序会通过以下方式检测系统 CUDA 版本：

- `nvidia-smi` 获取驱动版本并映射到 CUDA 版本
- `nvcc --version` 获取 CUDA 编译器版本
- `CUDA_PATH` 环境变量

1. 根据检测结果下载对应的 `llama.cpp` 和 `cudart`：

- CUDA 11 → 下载 `cuda-11.8` 版本
- CUDA 12 → 下载 `cuda-12.2` 版本
- CUDA 13 → 下载 `cuda-13.3` 版本
- 未检测到 → 默认下载 CUDA 13 版本

### 常见问题处理

| 问题 | 解决方法 |
| --- | --- |
| 下载缓慢 | 程序已配置国内镜像，若仍慢可检查网络或更换 DNS |
| Git 未安装 | 程序会提示并打开 Git 下载页面，安装后继续 |
| 依赖安装失败 | 手动在 open-webui\backend 目录执行 pip install -r requirements.txt |
| CUDA 运行时缺失 | 点击「环境修复」会自动检测并补全 |

### ⚙️ 针对配置的优化建议

基于 RTX 4060 Ti 8G 配置，建议在启动器中进行如下参数调整：

| 参数 | 推荐值 | 说明 |
| --- | --- | --- |
| GPU层数 | 25-33 | 8G显存建议 不要超过33层，留出2G显存给系统和其他进程 |
| 上下文大小 | 4096-8192 | 从4096起步，若显存有余量可逐步提升至8192 |
| 批处理大小 | 256-512 | 保持默认512即可，若显存不足可降至256 |

> 💡 **验证方法**：启动后观察日志中的显存占用信息，若接近8G上限（如7.5G+），建议降低GPU层数或上下文大小。

### 🐛 常见问题

### 1. 启动失败，提示端口被占用

- 修改「端口」参数为其他可用端口（如 11001）
- 或关闭占用端口的程序

### 2. OpenWebUI 显示“连接失败”

- 确保 `llama.cpp` 已成功启动（日志显示 `llama.cpp 启动成功`）
- 检查界面「端口」设置是否与 `llama.cpp` 一致
- 尝试点击「停止所有」后重新启动

### 3. 模型加载速度慢或显存不足

- 降低「GPU层数」参数（如设为 20）
- 降低「上下文大小」参数（如设为 4096）
- 使用更小的量化模型（如 Q4_K_M 替换 Q6_K）

### 4. 浏览器没有自动打开

- 检查日志是否显示 `OpenWebUI 已就绪`
- 手动访问 `http://localhost:8080`
- 若无法访问，检查 OpenWebUI 进程是否正常运行

### 5. CUDA 运行时缺失警告

- 点击「环境修复」会自动补全
- 若补全失败，可手动下载对应版本的 `cudart-llama-bin-win-cuda-xx.x-x64.zip` 并解压到 `LlamaCpp` 目录
