上个月，Product Hunt 上有位开发者[发帖](http://producthunt.com/p/vibecoding)问大家：同时开三四个 Claude Code 或 Codex 会话，最先出问题的是什么？他自己的答案是，最费时间的不是写提示词，而是找哪个会话卡在了权限确认上。智能体停下来等他点“允许”，他在另一个窗口里忙，有时十多分钟都没发现。底下有人补充，他那边最先坏的是 Git 工作区：一个会话改了一半的文件，被另一个会话顺手一起提交了。

差不多同一时间，T3 Code 的作者 Theo（网名 t3.gg，做过 T3 Chat 的程序员，也是拥有大量观众的技术视频博主）在项目的常见问题里写：他现在只有不到 5% 的提示词是在自己笔记本上跑的，其余都跑在别的机器上，他用手机和浏览器遥控。

这两段话说的是同一件事的两面。智能体已经能自己干上一整个下午，人却被拴在了终端前面：要么守着，要么想办法把“守着”这件事搬到别处去。

本周 GitHub 的榜单把后一种办法推到了台前。[T3 Code](http://github.com/pingdotgg/t3code)一周涨了一万两千多星，连续第二周过万，总数已超过 5.5 万；同一张榜上还有 [agent-desktop](http://github.com/vercel-labs/agent-desktop)、[dsh-Go](http://github.com/ccch1mneyyy/dsh-Go)、[OpenMausBot](http://github.com/milind-soni/OpenMausBot)。它们都不做智能体本身，做的是围着智能体转的那一层。我们给这一层起了个名字：**智能体控制平面**。

我做软件二十多年，见过的大部分软件都可以分成两层：数据平面和控制平面。数据平面是真正干活的那一层，控制平面决定活怎么干、谁来干、谁说了算。一台路由器里，数据平面把一个个数据包转发出去，控制平面算出该往哪转；一个数据库里，执行引擎扫描数据、算出结果，控制层管元数据、权限和资源分配；一个流处理系统里，算子一条条处理事件，协调者负责分配任务、做检查点、在故障后恢复；一个 Kubernetes 集群（目前最常用的容器编排系统）里，各台机器把容器跑起来，控制平面决定哪个容器跑在哪台机器上、谁有权限做什么。干活的和管活的分开，干活的那部分可以有很多份、可以随时替换，管活的那部分是统一的入口。

智能体其实也不例外。Claude Code、Codex 这些“模型加工具”的循环就是数据平面，它们在终端里读代码、改文件、跑命令。控制平面管的是另外几件事：哪个智能体在哪台机器上跑，人从哪里看见它们，谁批准它们的下一步，各家的账号和密钥放在哪，它们的手能伸到哪里。

这两层通常不是同时长出来的。先有能跑的数据平面，用的人多了、规模大了，管的问题才压过跑的问题，控制平面才单独成形：先有了大量容器，才有了 Kubernetes；路由器先能转发，后来才有人把路由决策整个搬出来集中管理。过去一年，智能体的数据平面已经足够能干，控制平面的问题开始出现。

这篇文章围绕这个概念回答三个问题：为什么智能体现在需要控制平面，这几个项目各自做了控制平面的哪一块，它们是怎么做的。读完四个项目，我的结论是：这一代控制平面解决了“连得上、看得见”，还缺“管得住”那一层。

## 数据平面够强了，问题压到了人身上

Claude Code、Codex 这类编码智能体，本质上是终端里的一个进程：模型想好下一步，调用工具读写文件、执行命令，看结果，再想下一步，如此循环。它们设计时默认了一个前提：人就坐在这台电脑前，看着这个终端。这个前提在过去一年里被几件事接连打破。

第一件是**任务变长了**。智能体一次能跑几十分钟乃至几个小时，人不可能一直盯着；可只要中间有一步需要批准，整个任务就停下来等人。Product Hunt 上丢掉的那十分钟，就是这么来的。

第二件是**数量变多了**。同时开三四个会话已经很常见。每个会话一个终端窗口，谁在等人、谁在跑、谁已经跑完，全靠人脑记。会话之间还会抢同一个代码目录，于是大家给每个会话开一个 Git 工作树（同一个仓库的独立目录副本）。T3 Code 的文档里提到，工作树攒得太快，有用户一次清掉了 500 GB。

第三件是**厂商变多了**。Claude Code、Codex、Cursor、OpenCode、Grok Build，各有各的界面、登录和订阅。不少人同时付着两三家的订阅，每家一个窗口，切来切去。

还有一件方向相反：智能体的手只伸得到终端。想让它在某个桌面软件里点几下，或者在手机上回条消息，终端里的编码智能体做不到。闭源大厂已经在补这一块，OpenMausBot 的说明里列了四款“自带电脑”的个人智能体产品：xAI 的 Grok Bot、Meta 的 Muse、OpenAI 的 dots、Manus 的 Cue，2026 年七周之内相继发布。

把这几件事放在一起，问题就清楚了：**稀缺的不再是模型能力，而是人的在场和注意力**，以及智能体的手能伸多远。而且这些问题都是上一个方案带来的。终端里的单会话智能体太好用，人才会开更多会话、交给它更长的任务，它原本的局限也就变成了人的负担。

换成控制平面的说法，这几件事分别对应四个能力：

- **入口** 人在哪里看见和操作智能体
- **统一接口** 多家智能体能不能用同一套接口驱动，
- **调度** 多个智能体怎么分配和交接工作，
- **执行的边界** 智能体能碰到哪些设备和应用。

单个智能体只顾得上自己那一个循环，这些事它管不了，也不该由它管，于是需要单独的一层。

这类项目其实早就有了，只是今年突然密集起来。

## 四个项目，各做了控制平面的哪一块

我们今天来研究一下最近上github热榜的几个项目

- T3 Code
- dsh-Go
- OpenMausBot
- agent-desktop

![](https://pic3.zhimg.com/v2-a3358f8b65072943ae854da8973de4b8_r.jpg)

T3 Code 想做的是一个完整的控制平面，前三个缺口都在补。人走不开，它就做了手机、网页、桌面多个客户端，遥控你电脑上的智能体；厂商各自为政，它就用一个界面驱动七八家智能体，用的是你自己已有的订阅；会话太多，它就把每个会话做成一条线程，配工作树，甚至能在几台机器之间自动分配新线程。

dsh-Go 主攻“走不开”，但换了个方向。它不只是遥控电脑，而是把 DeepSeek Harness（DeepSeek 八月开源的智能体框架，下称 DSH）整个装进安卓手机里运行，顺带让智能体去操作手机本身。

参考：[DeepSeek Harness 一切皆插件](https://zhuanlan.zhihu.com/p/2073572207448569517)

OpenMausBot 主攻“管不过来”。它把一群智能体做成聊天软件里的联系人，每个有自己的模型、自己的电脑、连好的应用，相互之间还能派活。

agent-desktop 只做最后一件，而且严格说，它不管智能体，它让智能体去操作桌面应用。把它和另外三个放在一起时要注意这一点：前三个处理的是人和智能体之间的边界，它处理的是智能体和电脑之间的边界。如果说前三个项目是控制平面朝向人的那一面，agent-desktop 就是控制平面朝向机器的那一面：它定义了智能体可以怎样、在什么条件下碰桌面上的东西。

## 控制平面怎么搭：执行留在原处，控制搬出去

四个项目做法各异，底下却共用控制平面最基本的一个动作：干活的和管理者的分开，执行留在原处，控制搬出去。T3 Code 的架构文档第一句就是这个意思：智能体在哪台机器上运行、代码在哪台机器上，执行就留在那里；网页、桌面、手机客户端只能通过认证过的远程调用去控制它，远程客户端永远不能拿自己的文件、密钥或机器状态去顶替那台机器的。OpenMausBot 的结构几乎一样：界面只发命令、收一条事件流，所有智能体进程都归本机上的一个服务器管。

![](https://pica.zhimg.com/v2-13ddd84bdf1af298be8a3dce3a12ed80_r.jpg)

### T3 Code：把各家智能体接上同一块交换台

![](https://pica.zhimg.com/v2-5e2a5b7d8c1687d4c31ecbc7165846d0_r.jpg)

各家智能体说的“话”并不一样。Claude 通过 Anthropic 的 Agent SDK 驱动，Codex 有自己的应用服务器，Cursor、OpenCode 等走 ACP（智能体客户端协议，一个让编辑器统一对接各家智能体的开放协议）。T3 Code 在每家前面放一个适配器，把各自的消息翻译成统一的命令和事件，上层根本不知道某条线程背后是谁。Theo 自己打过一个比方：模型是厨师，智能体框架是厨房，T3 Code 是一家允许你自带厨房的餐厅。

手机断线、重连、换个客户端接着看，是遥控场景里的常态。T3 Code 的处理办法是先记账、后干活：用户发出的每个指令，先作为事件写进数据库，和指令回执、待办的副作用放在同一个事务里提交，然后才由后台的工作进程真正去调用智能体、改文件。网络抖一下导致指令重发，也不会被执行两次；客户端重连时，从事件日志里补齐错过的部分。每一轮对话结束，它还用隐藏的 Git 引用给代码拍一个快照，回滚时文件和对话一起退回去。

手机怎么够到家里的电脑？它给了好几条路：官方中继 T3 Connect（在你电脑上起一条 Cloudflare 隧道，中继只负责牵线，不转发会话内容）、局域网配对码、Tailscale 组网、SSH。代码和提示词从你的电脑直接发给模型厂商，不经过 T3 的服务器。

它还开了一个 MCP 服务（模型上下文协议，智能体调用外部工具的通用接口），让 ChatGPT、Claude 这类云端助手也能进来开线程、发消息。到这一步，控制平面本身也成了别的智能体手里的工具：云端的智能体可以通过它，去调度你电脑上的智能体。

### dsh-Go：把引擎直接装进手机

![](https://pic4.zhimg.com/v2-02f73adc9181b82a20b353ead804a061_r.jpg)

dsh-Go 是第三方做的安卓客户端，和 DeepSeek 官方没有关系，建仓 16 天，10 月 30 日登上 Trendshift 全语言日榜第一。它的做法很直接：在应用里用 PRoot（不需要 Root 权限就能在安卓上跑一套 Linux 用户空间的工具）装好 Ubuntu、Node.js 和 DSH，大约占 1 GB。手机本身就是那台“电脑”，不需要另开一台机器挂着。想用电脑上的 DSH，也可以通过 SSH 或社区做的 DSHarness Remote（点对点加密连接）连过去，一键切换。

要注意的是，“本机运行”指的是智能体框架在手机上跑，模型请求照样要联网发给你配置的厂商，并不等于离线。

更值得看的是它怎么让智能体操作手机。它走安卓的无障碍服务读屏幕、点按、输入，确认规则写得很细：默认在进入新应用、发送、删除、付款之前都要问；支付、银行、券商类应用默认“不碰”，微信默认每一步都确认；密码、验证码、系统设置一律交还给人；三分钟没有新动作，任务自动结束；按住屏幕上的悬浮小球一秒就能叫停。

### OpenMausBot：把会话变成同事

![](https://pic3.zhimg.com/v2-3e008bec7d3bd9fc5dc07f75138df8c2_r.jpg)

OpenMausBot 的外形是一个聊天软件。侧边栏里每个联系人是一个机器人，背后是你电脑上装好的 Claude、Codex 或 Grok 命令行，用的是你已有的登录。每个机器人有自己的模型、自己的电脑（赞助商 Boat 提供的云端 Linux 桌面、本地虚拟机，或经你明确同意后的这台 Mac），以及通过 Composio 连好的五百多个应用，邮箱、Slack、GitHub 都在里面。

它和 T3 Code 一样分两层。界面只发命令、收事件；本机 127.0.0.1 上的框架服务器拥有所有智能体进程，把各家的协议统一成一种事件，再由一个“权限中介”把危险动作变成聊天里的“允许 / 拒绝”卡片。

它最下功夫的地方，是机器人之间怎么派活。项目里有一份“运行时合同”：一个机器人交给另一个的每一份工作都是一条记录，记录连成一棵树，走统一的生命周期，排队、运行、等下级、等人回答、结束；每次状态变化都先写进数据库再行动，进程崩了也不丢已经确认的事。派活不能回传给自己的上级，相同的请求只答一次，树有深度和预算上限。权限也有一条统一的规则：取机器人自己的级别和上级“幕僚长”机器人级别中较高的那个，但由外部事件触发的工作什么都不继承。它对外开放的 MCP 接口刻意不给审批、删除、密钥和电脑开关这几项权力。

### agent-desktop：给智能体一双看得懂界面的手

![](https://pic4.zhimg.com/v2-098f4e7407a550f3d4542250313b6c0d_r.jpg)

agent-desktop 出自 Vercel 实验室。大多数“操作电脑”的智能体靠截图加坐标点击，图像一糊、窗口一挪就点错。agent-desktop 改读操作系统的无障碍树，也就是为读屏软件准备的界面结构：每个按钮叫什么、是什么角色、能做什么动作。它把这棵树转成结构化文本，给每个能操作的元素编一个号，智能体按编号点，点完再读一遍确认。它自己不含模型，观察、动作、核对的循环在调用它的智能体里。

有两处设计和“管得住”直接相关。编号绑定在某一次快照上，界面一变，旧编号会被拒绝，报“过期”或“有歧义”，宁可让智能体重新看一遍，也不替它猜着点。它默认也不移动鼠标、不抢窗口焦点，人还能在同一台电脑上接着干活；几个智能体同时操作一台电脑时，用一份“交互租约”保证同一时刻只有一个在输入。11 月 5 日的新版本加了 MCP 接口，任何智能体都可以直接挂上它，这大概也是它本周重新上榜的原因。

## 控制平面缺了策略这一层

先把这几个项目最有力的论证说出来：本地优先，比把密钥交给云端平台安全。上个月有一个现成的反例。10 月 18 日夜里，攻击者闯进了 OpenCode Console 的一个旧系统，这是 OpenCode 的网上平台，部分用户在那里存了给各家模型准备的密钥。约 1.4% 的用户受影响，有人收到了 OpenAI、Anthropic、Google 的扣费提醒，个别人被刷了上千美元，Anthropic 和 Google 随后封掉了泄露的密钥。OpenCode 的命令行工具本身没出事，联合创始人特意澄清：“那些密钥从来不会到我们这里。”出事的是集中保管密钥的那个控制台。把多家的钥匙挂在同一个钩子上，那个钩子就成了靶子。

这几个项目的回答很一致：密钥和代码不离开你的电脑。T3 Code 的中继不经手会话内容；OpenMausBot 的密钥只写不读，界面上只能看到“已配置”；dsh-Go 的 SSH 密码只存在手机上。

可“本地优先”只是把风险从别人的服务器挪到了你自己的机器上，而且多开了一扇门：手机能够着电脑了。那么门后面，智能体被允许做什么？

答案有点出人意料。T3 Code 新线程的默认权限是“完全放开”，执行命令、修改文件都不问。OpenMausBot 的文档写得清楚：每个机器人、每段对话默认都是完全放开，“和 T3 Code 用的默认一样”；选它不弹确认框，在开发环境、命令行和自托管的部署里，连本机脚本或机器人调用接口都算作“你本人”，都能把一个机器人调成完全放开。它连着的邮箱、消息和支付，在完全放开且没设过“代你发送”规则时，发送没有每日上限。

这就绕回了开头。审批是让人走不开的原因，遥控本来是为了让人走到哪都能审批；可审批到了手机上依然是一次打断，于是最省事的办法变成了干脆不审批。在出厂设置下，这一代控制平面做好了“连得上”和“看得见”，管的那份权力本身，被交了出去。

拿 Kubernetes 对照，缺的是哪一块就很清楚了。Kubernetes 的控制平面里，一个请求在真正执行之前，要先过身份认证、权限检查和准入控制，管理员可以写规则规定什么样的容器根本不许跑起来。智能体的控制平面已经有了身份认证（配对码、登录、隧道），有了审批卡片，可在默认设置下，审批被整个跳过，也没有一层按动作后果来分级的规则：改一行代码和发一封邮件，走的是同一档权限。

四个项目放在一起看，还有一个规律：手离钱和真实世界越近，默认就越保守。dsh-Go 动的是手机，默认每步都问，支付和银行应用干脆不碰；agent-desktop 动的是桌面，认不准就拒绝，默认不碰鼠标。T3 Code 和 OpenMausBot 的智能体主要在动代码，代码改坏了可以回滚，所以它们敢放开。这个逻辑对写代码说得通。可一旦机器人连上了邮箱和支付，发出去的邮件、付出去的钱都撤不回来，“能回滚所以放开”的前提就不在了。

还有一层依赖值得说清楚：这些软件活在大厂的容忍度之上。它们能用你的订阅，是因为各家的使用条款允许，或者至少还没禁止。Theo 在 10 月 25 日发帖说，通过 Agent SDK 使用 Claude，会比直接用 Claude Code 更快耗掉五小时额度，他确认是 Anthropic 一侧的问题，已经上报，还在等修。T3 Connect 的免费额度后面也注明，如果账单高到不能接受，可能不得不改做法。T3 Code 的说明里写，它的灵感来自 Codex 桌面应用、Claude 桌面版、Cursor Glass，也就是说，大厂自己都在做这一层。

所以我的判断是有条件的。第三方能长期站住的，是大厂不愿做或做不了的那部分：跨厂商的适配层（没有一家会把对手的智能体接进自己的界面）、开放框架的手机运行时、多个智能体之间的委派规则、操作系统层面的手。如果只是一个更好看的手机遥控器，等官方的遥控做到够用，它的增长就会停下来。如果这个判断对，接下来半年应该看到两件事：一是这些项目开始收紧默认权限，或者像 dsh-Go 的应用名单那样，按动作的后果分级审批；二是关注点从“在哪都能看”，转向“多个智能体怎么分工”和“智能体的手能可靠地伸多远”。

## 握住批准的那根柄

两千多年前，战国末期的法家思想家韩非（他的著作《韩非子》专讲君主如何驾驭臣下）在《二柄》篇的开头写道：

> *明主之所导制其臣者，二柄而已矣。二柄者，刑德也。*

英明的君主用来引导和控制臣下的，不过两个把手：惩罚和奖赏。智能体的控制平面也有两个把手，一个是**看见**，它在做什么、做完没有、卡在哪里；一个是**批准**，它能不能做下一步。本周这几个项目把第一个把手做得越来越好，Product Hunt 上那位开发者十分钟没发现的确认框，现在可以推送到他的口袋里。第二个把手，却被出厂设置悄悄放下了。

同一篇里，韩非还有一句：

> *夫虎之所以能服狗者，爪牙也。使虎释其爪牙而使狗用之，则虎反服于狗矣。*

老虎能制服狗，靠的是爪牙；让老虎放下爪牙交给狗去用，老虎反倒要听狗的。批准权就是人的爪牙。那位开发者真正需要的，恐怕不是在手机上更快地点“允许”，而是清楚哪些事必须自己点、哪些事可以放心交出去，并且让软件替他守住这条线。

控制平面下一步要证明的，不是人能从多远的地方够着智能体，而是够着之后，人手里还握不握得住批准的那根柄。
