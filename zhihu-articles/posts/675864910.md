## v1 tensor并行

v1的主要内容是tensor 并行。这篇文章是和zero同时期的工作，要解决的主要问题都是减少模型占用的显存。

相比于zero3，tensor并行可以切分模型和activation，而zero3只能切分模型。

### tensor并行的做法：

矩阵乘法的行并行、列并行：

![](https://pica.zhimg.com/v2-ce7e13a3b2ea061bcdd44f0d1e39dac2_r.jpg)
*行并行和列并行*

有了底层的行并行和列并行，可以具体对MLP、self-attention做并行切分：

![](https://picx.zhimg.com/v2-bfd0773959abb802ce941a5c9ff6e4b9_r.jpg)
*MLP和SelfAttention中的tensor并行*

如上图，MLP、Self- Attention内的模型权重都被切分到两个不同的卡上。

同时大部分中间计算结果activation也被分到不同的卡上，但是**每张卡上要保存一份重复的输入X和输出Z**。

如下图，一层transformer中，layernorm和dropout层不会被并行切分，而self-attention、MLP是tensor模型并行的部分。

![](https://pic4.zhimg.com/v2-65ca11a5a836f37c1cc4efe60bd3b355_r.jpg)
*transformer中的tensor并行*

通信量分析：一层中forward做2次all-reduce，backward（不考虑activation checkpoint）做2次all-reduce。

### tensor 并行的问题：

**activation占用显存上**：切分了大部分的activation，**layernorm、dropout前后的显存没有切分**。v3的序列并行做的主要事情就是把activation切分彻底。

**通信量大**：不同卡上的结果需要合并，此时会有较大的通信量，通常比数据并行、pipeline并行的通信量要大很多。受限于通信量大，因此tensor并行通常只用于机器内的并行，例如nvidia实验中，多机、每个机器上8张卡，tensor并行最多设置为8。

**模型占用显存上**：切分了主要的模型显存，**layer norm、dropout等占显存小的层没有切分**，原因一个是这类模型参数本来就小，另一个是切分后带来的通信量大。

## v2 3D并行，interleaving pipeline并行优化

v2这篇大部分是在讨论3D并行/PTD-P/combine pipeline, tensor, and data parallelism如何用

对于pipeline并行也做了一些优化。

还有通信优化和fused kernel的优化。

### 3D并行策略

可以直接看takeaway：

- tensor并行的数量需要小于等于机器的卡数
- tensor并行和pipeline并行来将模型参数和activation放在gpu显存上
- 数据并行来利用更多gpu，支持更大的batch size
- activation recomputation通常checkpoint 1层，对显存最优

### pipeline并行优化

朴素的序列并行-> GPipe减少气泡 -> 1F1B pipeline减少activation显存占用 -> interleaving 1F1B 进一步减少气泡

朴素的序列并行：

![](https://pic1.zhimg.com/v2-a6ca5ee73058f0baed468554726fb370_r.jpg)
*普通的pipeline并行*

如上图，表示4卡，单个batch size，一张卡上跑的时候，其他卡都在空闲。

此时的 “空闲和计算” 比例/气泡占比为 $\frac{p-1}{1}$ ，其中p为pipeline模型并行的卡数。空闲比例非常高！

针对这一问题，Gpipe做了优化（ GPipe: Easy Scaling with Micro-Batch Pipeline Parallelism），如下图，将一个batch 分为多个micro batch，“空闲和计算” 比例/气泡占比 为 $\frac{p-1}{m}$ ,m为micro batch的数量。

![](https://picx.zhimg.com/v2-117a20eed5f75a6de0f6b59e39cd4f81_r.jpg)
*Gpipe*

Gpipe的一个问题是activation占显存大，如上图，每张卡上首次backward前需要存储前面m次forward的activation。

1F1B将m个activation降低到p个，通常m>>p。

![](https://pic3.zhimg.com/v2-ca38338875a3551048c2664b3e13352a_r.jpg)
*1F1B*

如上图，在前面3个卡的首次backward前，只有p个forward；在第4/p张卡的首次backwrd前，只有1个forward。

这个论文原图画的不是那么好，因为v2这篇论文的时候相对来说不太关注activation的显存占用。到v3的时候，会提到第2张卡的activation显存占用降低到3个，第3张卡降低到2个。如图中红色箭头所示，将前面的几个forward可以挪到后面。

1F1B相比于Gpipe减少了 activation的显存占用，interleaved 1F1B pipeline则是减少了气泡占比，从 $\frac{p-1}{m}$ 减少到 $\frac{p-1}{mv}$ 。其中v是stage/model chunk的数量。具体咋做的，如下：

![](https://pica.zhimg.com/v2-4829caa8ada4e0cbd55fc9829bf937b4_r.jpg)
*Schedule with Interleaved Stages*

![](https://pic2.zhimg.com/v2-1ff4d2e4572853d627ba30d6e5740a59_r.jpg)
*interleaved 1F1B pipeline*

interleaved的**优点一个是在m不变的情况下，能够成倍减少气泡占比**。

**另一个优点是减少了不同stage间的通信依赖。**图中红框部分，device3上深蓝色7 是第7个micro batch的第一个chuck的forward过程，它依赖device3上的深蓝色7，两个在时间线上不是紧靠的。这样前一个forward做完不需要立刻通信，可以在浅绿色3计算的时候进行通信，通过通信和计算的overlap来节省了一定的时间。

**代价一个是额外引入了成倍的通讯**，本来1F1B只有p个stage间需要按顺序通信传递bsh大小的中间结果，传递p-1次。现在interleaved变成了pv个stage间按顺序传递，传递pv-1次。增加了p(v-1)次的通信量。

**另一个代价是增加了activation的显存占用**，1F1B的时候first stage的activation是A，last stage是A/p，A是一个micro batch时整个模型的activation。interleaved的first stage的activation是 $ A(1+\frac{(p-1)}{pv})$ , last stage是 $A\frac{(pv-p+1)}{pv}$ 。

1F1B的每个块的activation是A/p，first stage有p个块，A=A/p*p，刚好first stage的activation是A。其他情况也可以计算出来。

> In the future, we plan to further reduce the activation memory by resolving the issues arising from memory fragmentation for large microbatches and **non-uniform memory allocation due to pipeline parallelism.**Moreover, we plan to work on methods that can reduce **the memory pressure on the first stage of the pipeline.**

pipeline这个方法最大的优点在于通信少，缺点在于first stage的显存占用 和 气泡。

## **v3** activation优化：序列并行sequence parallel、selective activation recomputation

这篇论文做的主要事情是activation的优化：

- 通过序列并行将tensor并行时的activation分得更彻底，减少了计算量，且没有增加通信的数据量，相当于减少显存也减少时间；
- 提出了selective activation recomputation，比无activation recomputation更加节省显存且增加的计算量不大，比full activation recomputation增加了显存但速度更快。
- 序列并行 + selective activation recomputation，在论文的实验中，相比于无activation recomputation更加节省显存，且更快；比full activation recomputation增加的显存不多且速度更快。

![](https://picx.zhimg.com/v2-97c2a6c8248e41a8db9b1257327f7a81_r.jpg)
*activation的比较*

### 序列并行：

解决的问题是tensor并行对于activation切分不彻底，既然没法在隐向量维度切分，这里改成了从序列维度来切分。

如下图，前面v1的时候我们也提到tensor并行时只对下面两个框内的model state和activation做切分，layernorm和dropout的都没分。

![](https://pica.zhimg.com/v2-6536f974dc0aec69341d2e6c38fa3216_r.jpg)
*tensor并行*

sequence parallel对layernorm和dropout的activation沿着序列维度做切分，因为dropout和layernorm计算的时候仅需要考虑当前隐向量即可计算，这里的bsh大小的中间结果，只有h不能切分。v3是根据sequence length维度切的，你可以沿着batch size维度做切分，搞一个batch 并行出来，或者搞一个batch+sequence并行出来。

![](https://pica.zhimg.com/v2-1b598bbb91895576749d249fa85b0044_r.jpg)
*sequence并行*

dropout本身没有参数，主要是dropout mask矩阵需要占用显存，这个可以切分。

layernorm是有参数的，注意这里layernorm的参数没切分，只切分了activation。

如下表，本来一层的 activation是 $sbh(34+5\frac{as}{h})$ ，这里的 $5\frac{as}{h}$ 是softmax前后用的，34是softmax以外的。

tensor并行能切分 $24+5\frac{as}{h}$ ，不能切分的10是layernorm和dropout的。

tensor并行加上序列并行，还能切分剩下的10。

![](https://picx.zhimg.com/v2-a7ccf953e849923e4c6561dd48d1580f_r.jpg)
*每张卡上每层的activation memory*

后续selective activation recomputation继续讲下面几行。

### selective activation recomputation

前向计算完了需要存下来activation，后向计算还要用到。

full activation recomputation是最常见的方法，就是对每一层只保存输入，做后向前，再做一遍这一层的前向计算。这样需要的activation可以降低到只存输入，2sbh，2是因为fp16占两个字节。当然这一层计算的时候还需要把这一层的activation都算出来，但是论文里把这个算到其他（临时存储）里面去了。

**full activation recomputation的主要问题是多走了一遍前向。**

selective的动机是把模型层分成两种，一种计算量大但是activation小，另一种计算量小但是相对activation大，那他这里就将计算量大但是activation小的存下来。这样只需要花相对少的activation便可以减少较多的计算量。

在gpt3中，论文发现softmax这里需要的activation占三分之二，但是计算量比较小，那这里每次重计算，其他的三分之一的activation就存起来。（当然不同的模型配置下这个activation占比不太一样，但是一般也都在50%以上）

> For GPT-3, a = 96, s = 2048, and h = 12288 and as a result 5as/h = 80. For MT-NLG, a = 128, s = 2048, and h = 20480 so 5as/h = 64.

## 问题

### 三篇论文解决的主要问题？

v1解决的主要问题，是降低显存；v2解决的主要问题是3D并行如何组合；v3解决的问题是降低activation

### 当前的模型并行存在哪些问题？

pipeline并行在不同stage中的显存分布不均匀，first stage的显存成为瓶颈

### 相比于zero3，tensor并行、pipeline并行有什么优势？

显存占用：tensor并行和pipeline并行可以切分activation的显存占用，而zero3只能切分model state。

通信量：pipeline并行的通信是最少的。

对batch size的影响：zero3的batch size只能是卡数的倍数，而pipeline并行的batch size可以比卡数更小，更加灵活。

## 思考、insight、实验

### pipeline并行中不同stage间显存分配不均匀、first stage的显存成为瓶颈：

first stage和last stage可以放到一台机器上，将first stage暂时不用的activation放到last stage卡上，涉及到的通信量较大，需要防在一台机器上。

### 在穷人家，实际使用中网络带宽可能是一大瓶颈，pipeline并行更适合你

在公司机器上实验了一下，单机两卡，卡间通信速度大概只有10G/s。而nvidia同机卡间900G/s，nvidia机器间的速度都有300G/s。就只能选通信量最少的pipeline并行了。
