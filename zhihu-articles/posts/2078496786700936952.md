写在前面

这不是一篇技术大牛的深度解析，也不是评测榜单的罗列。

这是一个差点被一堆术语劝退的普通人，终于在本地跑起大模型的苦瓜小白。

我的电脑配置是：<br>芯片：Apple M2（Mac14,7）<br>内存：16 GB unified<br>GPU：M2 10核图形<br>架构：arm64

- 有一台 M 系列芯片的 Mac
- 想本地跑 AI 模型，但面对 llama.cpp、MLX、GGUF 这些词蒙圈
- 为了省钱想最快用起来，不想当参数调优工程师

那这篇文章就是写给你的。

## 一、为什么要本地跑模型？

说实话，我之前一直用云端 API。DeepSeek、智谱、千问……注册、充钱、拿 Key、填进去，确实方便。

但时间久了有几个问题：

1. 隐私：公司内部的数据、数据库 Schema、代码逻辑，我不想上传到任何云上。哪怕厂商说“不会用于训练”，心里那道坎过不去。
2. 成本：API 是按 token 收费的。写个 SQL、改个配置、审一段代码，一天下来上百万 token 就没了。虽然不贵，但积少成多。
3. 依赖：断网就歇菜。有一次在公司内网环境做演示，API 调不通，当场尴尬。

于是决定——本地跑一个。

二、我的硬件（别怕，很普通）

我手上的设备不是顶配：

就这个配置，现在随便一台 MacBook Air 或 Pro 都在这个水平线以上。

目前体感是：16GB 的 M 系列 Mac，能玩，而且体验不错。

三、第一次尝试：被术语劝退

上网搜“Mac 本地跑大模型”，出来的内容是这样的：

“建议使用 llama.cpp，配合 GGUF 量化，通过 Metal 加速，手动调整 GPU 层数……”

还有这样的：

“MLX 是苹果官方的机器学习框架，性能比 llama.cpp 更好，但需要 Python 环境……”

我当时的表情：🙃

每个字都认识，连在一起完全看不懂。我只是想用 AI 的，都不知道他们之间什么关系，好痛苦。

我咬着牙继续翻教学、问deepseek，在一堆缩略词中蒙圈。

四、第二次尝试：找到最简单的方法

有朋友跟我说：

“你用 Ollama 试试，别管那些。”

第一步：安装<br>curl -fsSL [HTTPS://ollama.com/install.sh](https://ollama.com/install.sh) | sh

第二步：下载模型（选一个你喜欢的）<br>ollama pull qwen2.5-coder:14b

第三步：开始对话<br>ollama run qwen2.5-coder:14b

然后终端就出现了 >>> 提示符。

我输入了第一句话：

“帮我写一个 SQL，查询用户表中最近 7 天的活跃用户。”

几秒钟后，SQL 语句出来了。能用。通顺。格式规整。

那一刻的感觉是：我管它背后是什么引擎，能跑就行。

五、我推荐什么模型？

我试了一圈，基于 16GB 内存的 M2 Mac，以下模型跑得动且好用：

主力推荐：Qwen2.5-Coder-14B（约 8.5GB 内存占用）

- 代码能力强，SQL、正则、配置文件随手就写
- 中文友好，理解准确
- 日常推理够用，速度约 10-15 token/秒

备选：Qwen3.5-9B（约 7GB 内存占用）

- 综合能力更均衡
- 如果觉得 14B 有点卡，换这个会流畅不少

特殊场景：DeepSeek-R1-7B（约 5.5GB 内存占用）

- 复杂逻辑推理很强
- 资源占用更少，跑得飞快

建议：先用 qwen2.5-coder:14b。这是我试下来比较稳的选择。

六、这些模型能干什么？

我是做技术相关工作的，日常大概这些场景：

数据库治理：

- 写 SQL 查询、优化慢查询
- 设计表结构
- 生成数据迁移脚本

代码与规则编写：

- 生成正则表达式
- 写配置文件（NGINX、Docker 等）
- 审查代码、给重构建议

推理与决策：

- 分析日志、找问题根因
- 拆解复杂任务、给执行步骤
- 回答技术问题，当知识库用

实测下来，Qwen2.5-Coder 在 SQL 和代码生成上非常顺手，基本能达到“可用”级别。

七、我要不要也搞个 GUI 界面？

如果你不想一直待在终端里，有几个方法：

1. Open WebUI：一个网页界面，可以对接 Ollama 的 API，长得像 ChatGPT。
2. Chatbox：一个桌面应用，配置非常简单，填个本地地址就能用。
3. 继续用终端：其实习惯了也挺方便的，复制粘贴而已。

我自己的选择是终端 + Open WebUI 混合——写代码用终端，问问题用网页。

八、关于“要不要用更高级的工具”

这篇文章发出后，肯定会有人留言说：

“你为什么不直接用 llama.cpp？性能更好。”<br>“Ollama 有性能开销，不如 MLX 快。”

我的回答是：你说得对，但我不需要。

Ollama 可能不是最快的、不是最灵活的、不是最极客的。但它有一个无可替代的优点：

我是一个真实用户，我的目标是“用起来”，而不是“研究透”。

等哪天我熟练了、觉得 Ollama 不够用了，我自然会去学 llama.cpp。但现在，我只想稳定、简单、能用。

不被技术术语绑架，才是工具该有的样子。

九、给新手的一句话总结

别管什么 llama.cpp、MLX、GGUF、量化、Metal 加速。

先装 Ollama，先跑起来，先用上。

用上之后，你自然会有动力去了解背后的原理。

在那之前，那些名词跟你没关系。

十、一些常见问题（FAQ）

Q：16GB 内存跑得动吗？<br>A：跑 7B-14B 的模型没问题。推荐 14B，占用约 8.5GB，系统还能流畅运行。

Q：速度怎么样？<br>A：Qwen2.5-Coder-14B 大概 10-15 token/秒。打字的速度肯定追不上它，日常对话和代码生成都够用。

Q：会发热吗？<br>A：风扇会转，但不烫手。Mac 的散热设计扛得住。

Q：中文支持好吗？<br>A：Qwen 系列是阿里出的，中文自然没问题。DeepSeek 也不错。别用 LLaMA 系跑中文，那是折磨自己。

Q：Ollama 真的免费吗？<br>A：模型下载后完全本地运行，不联网、不收费。电费你得自己出。
