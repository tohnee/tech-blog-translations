## 一、PagedAttention 算法原理：块级注意力计算

在深入 CUDA 内核之前，先理解 PagedAttention 的数学原理——它如何把传统注意力计算改造成块级版本，让 key/value 可以散布在非连续的物理块中。

### 1.1 传统注意力计算

传统注意力计算中，query $q_i$ 需要和所有之前的 key 向量做点积：

$a_{ij} = \frac{\exp(q_i^\top k_j / \sqrt{d})}{\sum_{t=1}^{i} \exp(q_i^\top k_t / \sqrt{d})}, \quad o_i = \sum_{j=1}^{i} a_{ij} v_j \\$

这要求 key 和 value 向量存储在**连续内存**中，因为要按顺序索引 $k_1, k_2, \ldots, k_i$。

### 1.2 块级注意力：PagedAttention 的改造

PagedAttention 把 key 和 value 组织成固定大小的**块**：

$K_j = (k_{(j-1)B+1}, \ldots, k_{jB}), \quad V_j = (v_{(j-1)B+1}, \ldots, v_{jB}) \\$

注意力计算变成按块进行：

$A_{ij} = \frac{\exp(q_i^\top K_j / \sqrt{d})}{\sum_{t=1}^{\lceil i/B \rceil} \exp(q_i^\top K_t \mathbf{1} / \sqrt{d})}, \quad o_i = \sum_{j=1}^{\lceil i/B \rceil} V_j A_{ij}^\top \\$

**通俗解读**：这个公式把"query 和每个 key 做点积"改成了"query 和每个**块**里的 keys 做点积"。数学上完全等价，但物理上 key/value 可以散布在任何地方——内核通过 block table 间接寻址逐块获取。

![](https://pic4.zhimg.com/v2-07f1d2b569a621beb939ddb8ebf632c1_r.jpg)

> 📊 **原论文 图 5**：PagedAttention 算法图示——key 和 value 向量分散存储在三个非连续物理块中，内核逐块获取并计算注意力<br>

**与普通 attention 的对比**：

```text
普通 attention:  k = k_cache[0:n_tokens]          ← 连续内存，直接索引
PagedAttention:  k = k_cache[block_table[i]]       ← 间接寻址，块不连续

```

这就是 PagedAttention 的核心：多一次间接寻址（查 block table），换来 key/value 的非连续存储能力，从而实现按需分配和灵活共享。下面的 CUDA 内核就是把这个公式在 GPU 上高效实现。

## 二、PagedAttention CUDA 内核：GPU 上的分页注意力

### 2.1 内核总览

PagedAttention 的核心是一个 CUDA kernel：`single_query_cached_kv_attention_kernel`。它负责 decode 阶段的单 token attention 计算——给定一个 query token，通过 block table 遍历所有历史 KV 块，计算注意力。

```text
Grid: (num_heads, num_seqs)     ← 每个 block 处理一个 (head, sequence) 对
Block: 128 threads              ← 分为多个 warp，每个 warp 处理不同的 KV 块

// csrc/attention/attention_kernels.cu

template<typename scalar_t, int HEAD_SIZE, int BLOCK_SIZE, int NUM_THREADS>
__global__ void single_query_cached_kv_attention_kernel(
    scalar_t* __restrict__ out,              // 输出 [num_seqs, num_heads, head_size]
    const scalar_t* __restrict__ q,          // query [num_seqs, num_heads, head_size]
    const scalar_t* __restrict__ k_cache,    // key cache [num_blocks, num_kv_heads, ...]
    const scalar_t* __restrict__ v_cache,    // value cache [num_blocks, num_kv_heads, ...]
    const int* __restrict__ head_mapping,    // GQA/MQA 的 head 映射
    const float scale,                        // 1/sqrt(d)
    const int* __restrict__ block_tables,    // block table [num_seqs, max_num_blocks]
    const int* __restrict__ context_lens,    // 每条序列的上下文长度
    const int max_num_blocks_per_seq,
    ...) {

    // 线程映射
    const int head_idx = blockIdx.x;           // 当前处理哪个 head
    const int seq_idx = blockIdx.y;            // 当前处理哪条序列
    const int thread_idx = threadIdx.x;
    const int warp_idx = thread_idx / WARP_SIZE;
    const int lane = thread_idx % WARP_SIZE;

    // 获取 block table 和上下文长度
    const int* block_table = block_tables + seq_idx * max_num_blocks_per_seq;
    const int context_len = context_lens[seq_idx];
    const int num_blocks = (context_len + BLOCK_SIZE - 1) / BLOCK_SIZE;

```

### 2.2 线程组织：Thread Group 与 Warp

vLLM 的线程组织有两个层级：

```text
一个 Block（128 threads）:
┌────────────────────────────────────────────────────────┐
│  Warp 0 (32 threads)                                    │
│  ├─ Thread Group 0: 协作加载 1 个 key token             │
│  ├─ Thread Group 1: 协作加载 1 个 key token             │
│  ├─ ...                                                  │
│  └─ Thread Group N: 协作加载 1 个 key token             │
│                                                         │
│  Warp 1 (32 threads) → 处理不同的 KV 块                  │
│  Warp 2 (32 threads) → 处理不同的 KV 块                  │
│  Warp 3 (32 threads) → 处理不同的 KV 块                  │
└────────────────────────────────────────────────────────┘

Thread Group Size = MAX(WARP_SIZE / BLOCK_SIZE, 1)
  例: BLOCK_SIZE=16, WARP_SIZE=32 → THREAD_GROUP_SIZE=2
      2 个线程协作加载 1 个 key token 的 head_size 维度

```

**设计原因**：加载一个 key token 需要 `head_size` 个浮点数（如 128 个 float16 = 256 bytes），一个线程加载太慢。用 `THREAD_GROUP_SIZE` 个线程并行加载，利用向量化内存访问（每次 16 bytes）。

### 2.3 加载 Query 到共享内存

```text
    // 加载 query 到共享内存（所有线程共享）
    const scalar_t* q_ptr = q + seq_idx * q_stride + head_idx * HEAD_SIZE;
    __shared__ Q_vec q_vecs[THREAD_GROUP_SIZE][NUM_VECS_PER_THREAD];

#pragma unroll
    for (int i = thread_group_idx; i < NUM_VECS_PER_THREAD; i += NUM_THREAD_GROUPS) {
        const int vec_idx = thread_group_offset + i * THREAD_GROUP_SIZE;
        q_vecs[thread_group_offset][i] =
            *reinterpret_cast<const Q_vec*>(q_ptr + vec_idx * VEC_SIZE);
    }
    __syncthreads();  // 等待所有线程加载完毕

```

query 只有一个 token，体积小，放在共享内存里让所有线程组复用。

### 2.4 核心循环：Block Table 遍历 + QK 点积

这是 PagedAttention 的灵魂——通过 block table 间接寻址，遍历所有物理块：

```text
    // 外层循环：每个 warp 处理不同的 KV 块
    for (int block_idx = warp_idx; block_idx < num_blocks; block_idx += NUM_WARPS) {
        // ★ 关键：通过 block_table 把逻辑块号映射到物理块号
        const int physical_block_number = block_table[block_idx];

        for (int i = 0; i < NUM_TOKENS_PER_THREAD_GROUP; i++) {
            const int physical_block_offset =
                (thread_group_idx + i * WARP_SIZE) % BLOCK_SIZE;
            const int token_idx = block_idx * BLOCK_SIZE + physical_block_offset;

            K_vec k_vecs[NUM_VECS_PER_THREAD];

            // 从物理块中加载 Key
#pragma unroll
            for (int j = 0; j < NUM_VECS_PER_THREAD; j++) {
                const scalar_t* k_ptr = k_cache +
                    physical_block_number * kv_block_stride +  // ← 物理块寻址！
                    kv_head_idx * kv_head_stride +
                    physical_block_offset * x;
                k_vecs[j] = *reinterpret_cast<const K_vec*>(k_ptr + ...);
            }

            // Q·K 点积
            float qk = scale * Qk_dot<scalar_t, THREAD_GROUP_SIZE>::dot(
                q_vecs[thread_group_offset], k_vecs);

            // ALiBi 位置编码
            qk += (alibi_slope != 0)
                      ? alibi_slope * (token_idx - context_len + 1) : 0;

            // 写入 logits，做因果 mask
            if (thread_group_offset == 0) {
                const bool mask = token_idx >= context_len;
                logits[token_idx] = mask ? 0.f : qk;
                qk_max = mask ? qk_max : fmaxf(qk_max, qk);
            }
        }
    }

```

**图解 block table 寻址**：

```text
block_table[seq_idx] = [7, 1, 3, 5, ...]  ← 逻辑块 0→物理块 7, 1→1, 2→3, ...

warp 0 处理 block_idx=0:  block_table[0]=7  → k_cache[7]   ← 物理块 7
warp 1 处理 block_idx=1:  block_table[1]=1  → k_cache[1]   ← 物理块 1
warp 2 处理 block_idx=2:  block_table[2]=3  → k_cache[3]   ← 物理块 3
warp 3 处理 block_idx=3:  block_table[3]=5  → k_cache[5]   ← 物理块 5
    ...                                    ↑ 不连续！但通过 block_table 正确寻址

```

**与普通 attention 的对比**：

```text
普通 attention:  k = k_cache[0:n_tokens]          ← 连续内存，直接索引
PagedAttention:  k = k_cache[block_table[i]]       ← 间接寻址，块不连续

```

### 2.5 Online Softmax：块间累积

标准 softmax 需要两遍扫描（一遍求 max，一遍求 exp 和归一化）。vLLM 用 **online softmax** 在一遍扫描中完成：

```text
    // ===== 第一阶段：计算所有 QK 分数，同时跟踪全局 max =====
    // （上面的循环已经完成，qk_max 是局部最大值）

    // Warp 内归约求全局 qk_max
#pragma unroll
    for (int mask = WARP_SIZE / 2; mask >= THREAD_GROUP_SIZE; mask /= 2) {
        qk_max = fmaxf(qk_max, __shfl_xor_sync(uint32_t(-1), qk_max, mask));
    }
    if (lane == 0) { red_smem[warp_idx] = qk_max; }
    __syncthreads();

    // 跨 warp 求全局最大值
    qk_max = lane < NUM_WARPS ? red_smem[lane] : -FLT_MAX;
#pragma unroll
    for (int mask = NUM_WARPS / 2; mask >= 1; mask /= 2) {
        qk_max = fmaxf(qk_max, __shfl_xor_sync(uint32_t(-1), qk_max, mask));
    }
    qk_max = __shfl_sync(uint32_t(-1), qk_max, 0);

    // ===== 第二阶段：exp 归一化 =====
    float exp_sum = 0.f;
    for (int i = thread_idx; i < context_len; i += NUM_THREADS) {
        float val = __expf(logits[i] - qk_max);  // 减去 max 防溢出
        logits[i] = val;
        exp_sum += val;
    }
    exp_sum = block_sum<NUM_WARPS>(&red_smem[NUM_WARPS], exp_sum);

    // 归一化
    const float inv_sum = __fdividef(1.f, exp_sum + 1e-6f);
    for (int i = thread_idx; i < context_len; i += NUM_THREADS) {
        logits[i] *= inv_sum;
    }
    __syncthreads();

```

### 2.6 Value 加权求和：再次遍历 Block Table

```text
    float accs[NUM_ROWS_PER_THREAD];
    for (int i = 0; i < NUM_ROWS_PER_THREAD; i++) { accs[i] = 0.f; }

    // 再次遍历 block table，这次读 Value
    for (int block_idx = warp_idx; block_idx < num_blocks; block_idx += NUM_WARPS) {
        const int physical_block_number = block_table[block_idx];  // ← 同样的间接寻址
        const int physical_block_offset = (lane % NUM_V_VECS_PER_ROW) * V_VEC_SIZE;
        const int token_idx = block_idx * BLOCK_SIZE + physical_block_offset;

        // 从 logits 中取出 softmax 权重
        L_vec logits_vec;
        from_float(logits_vec, *reinterpret_cast<Float_L_vec*>(logits + token_idx));

        // 从物理块中加载 Value
        const scalar_t* v_ptr = v_cache +
            physical_block_number * kv_block_stride +  // ← 物理块寻址
            kv_head_idx * kv_head_stride;

#pragma unroll
        for (int i = 0; i < NUM_ROWS_PER_THREAD; i++) {
            const int row_idx = lane / NUM_V_VECS_PER_ROW + i * NUM_ROWS_PER_ITER;
            if (row_idx < HEAD_SIZE) {
                V_vec v_vec = *reinterpret_cast<const V_vec*>(v_ptr + ...);

                // 最后一个块：越界保护
                if (block_idx == num_blocks - 1) {
                    scalar_t* v_vec_ptr = reinterpret_cast<scalar_t*>(&v_vec);
                    for (int j = 0; j <= V_VEC_SIZE; j++) {
                        v_vec_ptr[j] = (token_idx + j < context_len)
                                         ? v_vec_ptr[j] : zero_value;
                    }
                }
                // 累加：acc += softmax_weight * value
                accs[i] += dot(logits_vec, v_vec);
            }
        }
    }

```

**最后一个块的越界保护**很重要：如果 `context_len=130`，`BLOCK_SIZE=16`，最后一个物理块只有 2 个有效 token（130 - 128 = 2），但块大小是 16，剩余 14 个位置可能含有垃圾数据。必须显式置零，否则 NaN 会传播到整个输出。

### 2.7 归约并输出

```text
    // Warp 内归约
    for (int i = 0; i < NUM_ROWS_PER_THREAD; i++) {
        float acc = accs[i];
        for (int mask = NUM_V_VECS_PER_ROW / 2; mask >= 1; mask /= 2) {
            acc += __shfl_xor_sync(uint32_t(-1), acc, mask);
        }
        accs[i] = acc;
    }
    __syncthreads();

    // 跨 Warp 归约（树形归约）
    float* out_smem = reinterpret_cast<float*>(shared_mem);
    for (int i = NUM_WARPS; i > 1; i /= 2) {
        int mid = i / 2;
        if (warp_idx >= mid) {
            // 上半部分写入共享内存
            float* dst = &out_smem[(warp_idx - mid) * HEAD_SIZE];
            // ... 写入 accs ...
        }
        __syncthreads();
        if (warp_idx < mid) {
            // 下半部分读取并累加
            const float* src = &out_smem[warp_idx * HEAD_SIZE];
            // ... accs += src ...
        }
        __syncthreads();
    }

    // 写出最终结果
    if (warp_idx == 0) {
        scalar_t* out_ptr = out + seq_idx * num_heads * HEAD_SIZE + head_idx * HEAD_SIZE;
        for (int i = 0; i < NUM_ROWS_PER_THREAD; i++) {
            const int row_idx = lane / NUM_V_VECS_PER_ROW + i * NUM_ROWS_PER_ITER;
            if (row_idx < HEAD_SIZE && lane % NUM_V_VECS_PER_ROW == 0) {
                from_float(*(out_ptr + row_idx), accs[i]);
            }
        }
    }

```

### 2.8 启动器：按 head_size 分派

```text
template<typename T, int BLOCK_SIZE, int NUM_THREADS = 128>
void single_query_cached_kv_attention_launcher(
    torch::Tensor& out, torch::Tensor& query,
    torch::Tensor& key_cache, torch::Tensor& value_cache,
    torch::Tensor& head_mapping, float scale,
    torch::Tensor& block_tables, torch::Tensor& context_lens,
    int max_context_len, ...) {

    int num_seqs = query.size(0);
    int num_heads = query.size(1);
    int head_size = query.size(2);

    // Grid: (num_heads, num_seqs) — 每个 block 处理一个 (head, seq) 对
    dim3 grid(num_heads, num_seqs);
    dim3 block(NUM_THREADS);  // 128 threads per block

    // 按 head_size 编译期分派（模板特化）
    switch (head_size) {
        case 64:  LAUNCH_ATTENTION_KERNEL(T, 64,  BLOCK_SIZE, NUM_THREADS); break;
        case 80:  LAUNCH_ATTENTION_KERNEL(T, 80,  BLOCK_SIZE, NUM_THREADS); break;
        case 96:  LAUNCH_ATTENTION_KERNEL(T, 96,  BLOCK_SIZE, NUM_THREADS); break;
        case 128: LAUNCH_ATTENTION_KERNEL(T, 128, BLOCK_SIZE, NUM_THREADS); break;
        case 256: LAUNCH_ATTENTION_KERNEL(T, 256, BLOCK_SIZE, NUM_THREADS); break;
        default:  TORCH_CHECK(false, "Unsupported head size: ", head_size);
    }
}

```

**为什么按 head_size 分派？** 因为 `head_size` 作为模板参数可以在编译期确定，编译器能做循环展开、寄存器分配优化。不同模型（LLaMA-7B head_size=128, GPT-2 head_size=64）各走各的特化版本。

### 2.9 辅助内核：reshape_and_cache 与 copy_blocks

除了 attention kernel，vLLM 还有两个重要的 CUDA kernel：

**reshape_and_cache**：把模型新算出的 KV 写入物理块

```text
// csrc/cache_kernels.cu — 简化版
template<typename scalar_t>
__global__ void reshape_and_cache_kernel(
    const scalar_t* __restrict__ key,    // [num_tokens, num_heads, head_size]
    const scalar_t* __restrict__ value,
    scalar_t* __restrict__ key_cache,    // [num_blocks, ...]
    scalar_t* __restrict__ value_cache,
    const int* __restrict__ slot_mapping, // 每个 token 的物理槽位
    ...) {
    const int token_idx = blockIdx.x;
    const int slot_idx = slot_mapping[token_idx];

    // 把 key[token_idx] 写入 key_cache 的对应槽位
    // slot_idx = physical_block_number * block_size + block_offset
    for (int i = threadIdx.x; i < numel_per_token; i += blockDim.x) {
        key_cache[slot_idx * ... + i] = key[token_idx * ... + i];
    }
}

```

**copy_blocks**：CoW 时复制物理块数据

```text
template<typename scalar_t>
__global__ void copy_blocks_kernel(
    int64_t* key_cache_ptrs,    // 每层的 key cache 指针
    int64_t* value_cache_ptrs,
    const int* __restrict__ block_mapping,  // [src, dst, src, dst, ...]
    const int numel_per_block) {

    const int layer_idx = blockIdx.x;
    const int pair_idx = blockIdx.y;

    scalar_t* key_cache = reinterpret_cast<scalar_t*>(key_cache_ptrs[layer_idx]);
    int src_block = block_mapping[2 * pair_idx];
    int dst_block = block_mapping[2 * pair_idx + 1];

    // 逐元素复制
    for (int i = threadIdx.x; i < numel_per_block; i += blockDim.x) {
        key_cache[dst_block * numel_per_block + i] =
            key_cache[src_block * numel_per_block + i];
    }
    // value 同理
}

```

## 四、内核开销分析：为什么慢 20-26% 但整体更快？

这个看似矛盾的结果值得深入理解：

```text
端到端延迟 = 调度开销 + Prefill 计算 + Decode 计算 × N_steps
                                ↑                    ↑
                         矩阵乘法为主          Attention 为主
                         (不受影响)          (PagedAttention 慢 20-26%)

但是！vLLM 能塞更多请求进同一个 batch：

传统系统：batch=10 → 每条延迟 = T
vLLM：   batch=30 → 每条延迟 = 1.2T（Attention 慢一点）
         但吞吐量 = 30/1.2T ≈ 2.5 × (10/T) = 2.5× 提升！

```

**核心洞察**：PagedAttention 在单次 attention 计算上稍慢，但它让 batch size 增大了 2-4 倍，整体吞吐量的提升远大于 kernel 本身的开销。这是一个典型的"局部最优 ≠ 全局最优"的案例。

## 五、核心洞察与启发

### 1. 跨学科类比的力量

vLLM 最大的启示不是某个 trick，而是"把成熟领域的方案迁移到新领域"。操作系统的虚拟内存、分页、Copy-on-Write 都是几十年前的经典技术，但没人想到用在 LLM 推理上。

> 当你遇到一个内存管理问题时，先想想操作系统是怎么解决的。<br>

### 2. 瓶颈在"管理"不在"计算"

LLM 推理是内存受限（memory-bound）而非计算受限（compute-bound）的。GPU 算力远未饱和，真正卡住的是 KV Cache 的内存管理效率。

### 3. 按需分配 > 预分配

静态预分配是工程上的偷懒——简单但浪费巨大。vLLM 的按需分页分配证明了：即使增加了一些管理开销（内核慢 20-26%），换来的批处理规模提升（2-4 倍）远大于开销本身。

### 4. 共享是隐藏红利

并行采样、Beam Search、共享前缀等场景下，不同序列的 KV Cache 有大量重叠。块级共享 + Copy-on-Write 让这些重叠从"浪费内存"变成"节省内存"。

### 5. 工程简洁性

vLLM 用 fork/append/free 三个原语统一了所有解码算法的内存管理，LLM 和执行内核只看到物理块 ID 列表，完全不需要知道共享逻辑。这种抽象层设计值得借鉴。

### 6. 间接寻址的代价可控

PagedAttention 通过 block table 做间接寻址，相比连续内存访问有额外开销。但 vLLM 的 CUDA kernel 通过精心的线程映射、向量化加载和共享内存复用，把开销控制在 20-26%。这说明间接寻址的代价是可控的，关键在于 kernel 优化。

## 六、总结与展望

### 核心贡献

vLLM 通过 **PagedAttention** 和分页式 KV Cache 管理，在 LLM 服务中实现了接近零内存浪费和灵活的 KV Cache 共享，将吞吐量提升 2-4 倍。它的核心思想——把操作系统虚拟内存技术应用于 LLM 推理——简单、优雅、有效。

### 三篇系列回顾

| 篇目 | 核心内容 | 关键源码 |
| --- | --- | --- |
| 上篇 | 内存管理与共享机制 | Sequence, BlockAllocator, BlockSpaceManager, CoW/fork 应用 |
| 中篇 | 调度器、Worker 与分布式执行 | Scheduler._schedule(), Worker.execute_model(), CacheEngine |
| 下篇 | PagedAttention 算法、CUDA 内核与实验（本文） | single_query_cached_kv_attention_kernel, copy_blocks_kernel |

### 局限性

- PagedAttention 内核有一定开销（比优化的连续注意力慢 20-26%），在计算受限场景优势较小
- 块大小需要根据场景调优，没有"一刀切"的最优值
- 集中式 Scheduler 的 Python 调度循环在极大规模下可能成为瓶颈

### 可跟进方向

- 将 PagedAttention 思想扩展到其他注意力变体（如 Sliding Window Attention、FlashAttention）
- 探索更智能的 KV Cache 驱逐策略（如基于注意力分数的重要性排序）
- 结合 Speculative Decoding 进一步降低延迟
- Prefix Caching 的进一步优化（vLLM 后续版本已实现 automatic prefix caching）
