## 前言

该文章旨在为您简要介绍InfiniBand。 在最后，你应该对InfiniBand技术、相关术语有所了解，并且学会如何使用ibverbs编写非常简单的RDMA应用程序。

第一部分解释了InfiniBand技术的基本特性/属性以及网络组成的物理部分。 第二部分仔细研究了通信所需的技术逻辑部分。 在第三部分和最后一部分中，我将解释一个简单的ibverbs应用程序的结构， ibverbs是IB功能的抽象表示，您可以将ibverbs视为IB的API。

## 基础知识、网络和终端节点

InfiniBand（IB）是由InfiniBand协会于1999年开发的一种联网技术。它用于高性能计算和企业数据中心。 它的功能包括高吞吐量，低延迟，服务质量(QoS)和failover。

最小且完整的InfiniBand结构（IBA）单元是一个子网。 子网由终端节点（例如服务器），交换机，铜缆或光纤链路和子网管理器组成。 终端节点使用网卡（Channel Adapters，CA）连接到链路，网卡分为本机网卡（Host Channel Adapters，HCA）和目标网卡（Target Channel Adapters，TCA）。 HCA可通过用户应用程序访问，而TCA无法被用户程序访问。 子网管理器对子网有一个全局视角并且管理着整个子网。

![](https://pic3.zhimg.com/v2-44e12c3bfab5cce481b069fe56c6fddc_r.jpg)
*InfiniBand子网*

InfiniBand允许应用程序**直接**与另一个应用程序通信。 这意味着应用程序不需要依赖操作系统来传输消息。

![](https://picx.zhimg.com/v2-8b83f4012218d0f4e7aa4a3095e40229_r.jpg)

## 通信

CA使用**工作队列**相互通信。 有三种类型的工作队列：Send, Receive和Completion。 Send和Receive队列始终一起使用，被称为Queue Pairs (QP)。 网卡中的特定QP是所有消息的目的地或源。 每个QP还具有一个关联的端口，该端口是网卡与链路的连接的抽象。

![](https://pica.zhimg.com/v2-ed9eb7dbf593a6efbe57fcf7863f9e6e_r.jpg)
*网卡中的Queue Pairs (send/receive)*

为了发送或接收消息，可以将Work Requests (WRs)放置到QP上，Work Requests分为发送工作请求和接收工作请求两类。 处理完成后，可以将Work Completion (WC) 放置到与工作队列关联的Completion Queue (CQ)上。

![](https://pic2.zhimg.com/v2-cdca62b41f7df50a65b1d139ac4b985d_r.jpg)

为了定义要在内存中写入或读取的地址，使用了与WR相关联的Scatter/Gather Elements (SGE)，SGE是指向本机网卡可以读取或写入的Memory Region (MR) 的指针，MR是本机网卡向操作系统注册的一组连续的内存区域，注册MR会禁止操作系统在虚拟内存操作中将此区域换出。

内存注册还会创建称为L_Key和R_Key的对象，在访问MR时需要使用它们进行身份验证。 使用L_Key (local Key)访问本地MR，可以将R_Key (remote Key)发送给对等方，以便对等方可以通过RDMA Write和RDMA Read直接访问本地MR， MR又是Protection Domain (PD)的一部分，PD有效地将QP和MR结合以至于可以将他们看作是一个聚合实体。 QP和MR必须在PD的context中定义。

![](https://pic3.zhimg.com/v2-9f0118003c9fd2e6b9bc28b66ee2290a_r.jpg)
*Work Requests, Scatter/Gather Elements, Memory, Memory Regions and Protection Domain的关系*

下面对上述简写进行总结：

| 简写 | 全称 | 功能 |
| --- | --- | --- |
| PD | Protection Domain | 将QP和MR结合在一起 |
| MR | Memory Region | 一块经注册过的且本地网卡可以读写的内存区域。包含R_Key和L_Key |
| QP | Queue Pair | Send work queue和Receive work queue组成的对. Send/receive work requests会被放到QP上 |
| CQ | Completion Queue | WC会被放在CQ上，与QP关联。 |
| WR | Work Request | 包含send work request或receive work request。 指定要处理的动作并将其放入send queue或receive queue（QP）中，参考SGE。 |
| SGE | Scatter/Gather Element | 定义了可以进行读写的地址，必须提供L_Key或R_Key才能访问MR |
| WC | Work Completion | 当WR完成后，WC将交付结果 |

## 简单IB编程

简单介绍一下编程的流程

1. 初始化InfiniBand Context
2. 初始化Queue Pair
3. 使用TCP/IP交换一些控制信息以方便后续使用IB设备，会交换如下控制信息。
4. 将QP的状态改为Ready to Receive (RTR)
5. **（只有server需要）**将QP状态改为Ready to Send (RTS)
6. 进行RDMA write
7. 定义要使用scatter/gather element (SGE)读取的MR
8. 使用work request定义写的目的地址
9. RDMA write操作写到client/receiver的buffer中
