## 1.项目简介

### 1.1 项目概述

简介：MLIR‑TensorRT是NVIDIA基于MLIR构建的多后端混合编译+运行时系统，输入StableHL(JAX、TF 导出)，自动做计算图聚类分片，可调度TensorRT引擎、GPU内核生成器、Host CPU三类后端，输出独立可执行推理产物，属于 TensorRT‑Incubator孵化项目，定位是打通MLIR生态与TensorRT硬件推理栈。

代码：[https://github.com/NVIDIA/TensorRT-Incubator/tree/main/mlir-tensorrt](https://github.com/NVIDIA/TensorRT-Incubator/tree/main/mlir-tensorrt)

版本：当前主分支版本0.4.9，持续迭代

依赖：LLVM/MLIR、StableHLO、TensorRT‑10.x、CUDA、Flatbuffers、Lua5.4/Sol2。

预编译产物：GitHub Releases提供Python wheel二进制包，避免本地编译LLIR‑MLIR巨大工程开销。

五阶段编译流水线：Setup‑Input‑Clustering‑Bufferization‑Lowering

工具集合：mlir‑tensorrt‑compiler、mlir‑tensorrt‑opt、mlir‑tensorrt‑translate、mlir‑tensorrt‑runner、tensorrt‑opt。

### 1.2 核心功能

**1).StableHLO原生推理后端**

JAX、TF通过StableHLO输出，绕开ONNX解析器；ONNX存在版本兼容性、算子丢失问题，MLIR‑TensorRT直接消费MLIR，解决框架到 TensorRT 的转换损耗；

**2).混合多后端协同推理(核心亮点)**

- 优先：子图交给TensorRT(成熟高度调优引擎，适合大算子子图)；
- 次选：Kernel模块生成原生GPU PTX 内核(TensorRT 不支持的新算子、自定义算子)；
- 兜底：Host CPU执行Shape计算、标量逻辑；
- Plan dialect自动打分聚类，自动插入host‑device 数据拷贝，业务层无需手动切分计算图；

**3).多样化输出产物适配不同部署场景**

![](https://pic3.zhimg.com/v2-87acd7ab9ed3c47525590744c5fcf9fe_r.jpg)

**4).动态形状原生支持**

完整处理动态维度模型，聚类阶段提取 shape function，支持动态输入推理；面向 JAX 大模型、生成式 AI。

**5).可嵌入MLIR生态**

独立 TensorRT dialect 可以嵌入 Torch‑MLIR、XLA/OpenXLA 等任意 MLIR 编译器中做子图下沉 TensorRT 加速。

### **2.2 Pass-流水线**

文件：compiler/Pipelines/StableHloCompilerPipeline.cpp

功能：定义整套StableHLO编译流水线，分 5大阶段：Setup、Input、Clustering、 Bufferization、Lowering。

**1).Setup阶段Pass**

- plan‑create‑module‑metadata：插入plan.module_metadata属性，记录目标设备、允许后端集合(trt/kernel/host)、动态 shape 配置。
- -executor‑add‑host‑target‑attr：标记输出目标(executor/emitc/llvm)。

**2).Input 输入规范化Pass(对 StableHLO 做预处理)**

- chlo‑to‑stablehlo：CHLO高阶算子降级为StableHLO基础算子；
- stablehlo‑canonicalize：算子规范化、常量折叠、死代码消除；
- stablehlo‑shape‑refinement：传播 shape，推导动态维度信息；
- convert‑control‑flow‑to‑scf：StableHLO 控制流转SCF方言；
- 输出：干净、shape完备的StableHLO + SCF IR；

**3).Clustering聚类核心Pass(PlanDialect生成)**

文件：compiler/Transforms/Clustering/*.cpp

- plan‑compute‑shape‑functions：提取shape计算逻辑，分离shape算子与数据计算算子；shape算子优先分配host后端。
- plan‑assign‑operators： (1)调用各个后端的BackendCapability接口：判断该 Op 是否可被该后端支持，并返回benefit打分； (2)打分优先级：TensorRT > kernel codegen > host CPU； (3)给每个 Op 附加plan.assignment属性，标记归属后端。
- plan‑form‑clusters：(1)把连续、相同 assignment 的算子聚合为plan.cluster区域，outline为独立plan.cluster_func函数；(2)在cluster边界自动插入plan.copy(host‑device 拷贝)。

本阶段输出IR：StableHLO + PlanDialect完整 IR，整张图被切分为多个cluster函数，每个cluster绑定后端。

**4).BufferizationPass**

- one‑shot‑bufferize：Tensor语义 -> MemRef显式内存语义。
- plan‑bufferize‑copies：把plan.copy转为真实 memref 拷贝操作(cudaMemcpy/host memcpy)。
- buffer‑deallocation：插入buffer释放逻辑。
- 输出：全MemRef IR，无value‑tensor，全部是内存引用。

**5).Lowering分发降级Pass(按cluster 后端分别降级)**

文件：compiler/Transforms/Lowering/*.cpp

- plan‑lower‑clusters：遍历每一个plan.cluster_func，根据其assignment分发到不同的降级流程： (1) assignment=tensorrt：执行convert‑stablehlo‑to‑tensorrt，将cluster内部StableHLO转为tensorrt方言Op。 (2) assignment=kernel：执行convert‑stablehlo‑to‑linalg -> linalg 变换 -> nvgpu codegen pipeline，生成GPU/NVVM IR。 (3) assignment=host：stablehlo直接降级LLVM‑CPU。
- tensorrt‑translate‑to‑blob：把tensorrt dialect翻译为TensorRT C++ API，构建nvinfer::INetworkDefinition，调用TRT builder序列化，把.plan二进制blob嵌入MLIR属性。
- executor‑lower‑to‑target：把多后端混合 IR 转为executor方言； (1) host‑target=executor：生成rtexe flatbuffer； (2) host‑target=emitc：调用EmitC translate，输出C++源码； -(3) host‑target=llvm：降LLVM‑MLIR。

**6).独立工具Pass(mlir‑tensorrt‑opt可单独调用)**

- tensorrt‑verify‑op：校验 tensorrt 方言 Op 合法性，匹配 TensorRT API 约束；
- tensorrt‑fold‑constants：TRT 方言常量折叠；
- nvgpu‑tiling‑matmul：对 linalg matmul 做分块 tiling，生成 nvgpu warpgroup‑mma TensorCore 指令；

**Pass调用入口：**

- mlir‑tensorrt‑compiler 工具：直接调用完整buildStableHloCompilerPipeline()；
- mlir‑tensorrt‑opt：可以单独指定任意Pass做调试。

### 2.3 关键模块

**1). compiler模块**

文件路径：compiler/Backend/，后端能力抽象层，是多后端调度的核心面向对象接口<br>backend基类

![](https://pic2.zhimg.com/v2-161aa87e6660212250c00bb8d8d766a5_r.jpg)

**子类实现：**

- TensorRTBackend：实现TRT算子能力判断，返回很高 benefit；
- KernelBackend：Kernel Codegen后端；
- HostBackend：CPU Host 后端。

**ClusterLowering基类**

每个cluster调用ClusterLowering::lowerCluster()，把cluster_func IR降级到对应后端方言

- TensorRTClusterLowering：stablehlo -> tensorrt dialect；
- KernelClusterLowering：stablehlo -> linalg -> nvgpu -> GPU/NVVM；
- HostClusterLowering：stablehlo -> CPU‑LLVM。

**关键函数**

- plan::assignOperands(...) compiler/Transforms/Clustering/AssignOperators.cpp：遍历所有 Op，调用各个 Backend::getCapability，给 op 附加plan.assignment属性。
- plan::formClusters(...) compiler/Transforms/Clustering/FormClusters.cpp：根据assignment属性，构建cluster区域、cluster_func、插入 plan.copy。

**2).tensorrt 模块**

代码：tensorrt/Translate/TranslateToTensorRT.cpp

功能：TensorRT Dialect + TRT API的桥接

TensorRTBuilder核心类

![](https://pic4.zhimg.com/v2-ba19e06fc60b6f5fdf30275574275105_r.jpg)

**关键函数**

- translateTensorRTDialectToBlob()：入口函数，输入tensorrt dialect模块，输出TRT engine二进制 blob，作为MLIR attribute 保存。
- 重要：tensorrt dialect不直接调用TRT库在编译时执行推理；编译阶段只是构建network 并序列化blob；真正TRT engine执行发生在executor runtime 运行时阶段。

**3).Kernel模块**

代码：kernel/Codegen/

功能：GPU Codegen，nvgpu方言生成TensorCore指令

- -NvgpuTilingPass：对Linalg matmul做 tiling，切分矩阵块，映射nvgpu.warpgroup.mma（Hopper wgmma）； -
- LowerNvgpuToNVVMPass：把 nvgpu 硬件 Op 翻译为 NVVM intrinsic（wgmma.mma_async PTX 内置函数）
- 调用链路：Linalg.matmul -> tiling -> nvgpu.warpgroup.mma -> LowerNvgpuToNVVM -> NVVM dialect -> LLVM‑NVVM IR -> PTX汇编。

**4).executor模块**

代码：executor/Runtime/

功能：运行时对象(rtexe 执行)

- RuntimeModule：加载rtexe flatbuffer；管理资源：TRT Engine blob 句柄、GPU Kernel Cubin、Buffer 内存；
- EngineWrapper：封装nvinfer1::IRuntime、nvinfer1::ICudaEngine、nvinfer1::IExecutionContext；运行时反序列化 blob 得到 TRT engine；
- KernelWrapper：加载PTX/cubin Kernel；
- Executor：主调度类，Lua解释器驱动，按executor dialect描述依次调用TRT engine、gpu kernel、host函数，处理memcpy。

**区分两个阶段：**

- 编译期(编译器二进制 mlir‑tensorrt‑compiler)：MLIR Pass、dialect转换、生成blob嵌入IR；
- 运行期(mlir‑tensorrt‑runner/python binding)：executor runtime，加载blob，真正调用CUDA/TensorRT做推理。

**5).Tools工具**

- integrations/python/：pybind11封装编译器入口；
- integrations/pjrt/：JAX PJRT插件，实现PjRtCompiler，接收StableHLO，调用mlir‑tensorrt编译器，返回PjRt可执行句柄。

### 2.5 对象之间的数据流

**1).编译期间数据流**

- StableHLO MLIR文件 -> PassManager 依次执行 Pass -> IR 不断变换，PlanDialect 作为中间元数据记录分片分配信息；
- 各个 cluster 分别降级；
- TensorRT 子图在编译期序列化为二进制blob，嵌入 IR 属性；
- 最终输出产物(rtexe/C++/LLVM‑IR)。
- 编译期间不执行GPU计算，只做图变换、IR生成、序列化引擎blob。

**2).运行期间数据流**

- 加载编译产物，解析flatbuffer，反序列化TRT engine blob得到真实 ICudaEngine；
- 加载 cubin；Executor 根据 executor IR 描述，调度多后端执行，处理内存拷贝，完成推理。

## 3.技术解析

### 3.1 GPU & TensorCore 指令集接口路径

**NVIDIA GPU TensorCore 硬件指令**

- SM80 (Ampere): mma.sync PTX intrinsic(Warp 粒度 32 线程)
- SM90 (Hopper): wgmma.mma_async Warpgroup(128 线程，异步矩阵乘)
- SM100 (Blackwell): 新一代FP8/FP4矩阵硬件指令

**MLIR‑TensorRT两条路径触达TensorCore 硬件指令**

- TensorRT后端路径：tensorrt dialect 翻译生成 TensorRT serialized engine(.plan)；TensorRT Builder内部tactic选择，自动调用 cuBLASLt、硬件MMA指令；应用层看不到PTX/SASS，黑盒优化。
- Kernel Fallback Codegen路径(不经过 TensorRT 库)： Linalg.matmul -> Transform IR tiling 分块 -> GPU dialect(gpu.subgroup_mma/nvgpu.warpgroup.mma) -> NVVM Dialect -> LLVM‑NVVM IR -> PTX(ptxas 汇编) -> SASS硬件指令(mma.sync / wgmma.mma_async)。

Kernel模块作用：TensorRT尚未支持算子，直接MLIR Codegen生成使用TensorCore硬件指令的PTX内核，补齐算子覆盖；同时HPC场景可以做通用GPU高性能算子生成。

### 3.2 IR生成与完整转换链路

**1).完整端到端IR流程**

- JAX/PyTorch‑MLIR -> StableHLO MLIR 输入 -> MLIR‑TensorRT Compiler Pipeline (5 阶段) -> 多段混合IR(TensorRT dialect + Linalg/GPU dialect + executor dialect) -> 分路径输出产物

**2).编译流水线五大阶段**

compiler模块Plan dialect驱动

**(1) Setup-初始化阶段**

- 模块初始化，ABI包装生成，后端metadata标记，输入校验。

**(2) Input-输入阶段**

- CHLO降级StableHLO，常量折叠，shape精修，控制流转换SCF；完成输入IR规范化。

**(3) Clustering-聚类阶段**

- 提取shape计算函数；每个backend提供可支持判断函数 + benefit分数；TensorRT benefit最高优先分配算子；
- 将连续可分配算子聚合cluster，把cluster outline成独立函数；标记该cluster交由哪个后端处理(TRT/kernel/host)；
- 自动生成跨集群之间的tensor拷贝(host<->device)；Plan dialect表达分片、分配信息。

**(4) Bufferization-分配阶段**<br>tensor语义IR转为memref 显式内存；分配/释放buffer，标记内存空间(host/device)，插入显式cuda memcpy。 <br>**(5) Lowering-降级阶段**<br>各个 cluster 分发到对应后端： - TensorRT cluster：`tensorrt‑translate` pass 将 tensorrt dialect 翻译调用 TensorRT C++ API，序列化 engine 二进制 blob 嵌入最终产物； - kernel cluster：Linalg → NVVM → PTX 模块； - host 集群降级 CPU； - executor dialect 输出 rtexe /emitc C++ / LLVM‑IR。

### 3.3 Model编译&转换链路

**1).传统ONNX-TensorRT**

- 训练框架 -> 导出ONNX -> ONNX Parser解析 -> TensorRT NetworkDefinition -> builder生成plan engine
- 痛点：ONNX格式存在算子表达缺失、动态shape缺陷、版本兼容问题；无法做细粒度混合，整个子图全部交给TRT，不支持原生fallback codegen。

**2).MLIR‑TensorRT路径**

- JAX/Torch‑MLIR -> StableHLO MLIR(原生高级IR) -> MLIR‑TensorRT编译器聚类分片 -> 部分子图TRT engine + 部分子图原生Codegen PTX + host计算 -> 打包到rtexe/C++源码
- 优势： IR原生多级表达，不依赖中间序列化文件； 细粒度算子级聚类，一张计算图同时使用 TensorRT + GPU CodeGen+ Host CPU；深度和JAX生态打通，PJRT插件直接运行，省去文件导出磁盘IO。

### 3.4 计算图性能优化维度

**1).图分片与后端选择优化**

- 基于benefit打分自动分配，大计算密集子图走TensorRT(大量成熟 fusion、tactic 调优)；零散/新算子走Kernel CodeGen；shape标量运算交给host；避免把小算子强行塞进 TensorRT 带来调度开销。

**2).MLIR通用Pass优化**

- 常量折叠、dead code 消除、算子 canonicalize，shape 传播，控制流简化。

**3).Bufferization内存优化**

- tensor‑>memref，复用 buffer，最小化 host‑device 数据拷贝开销，精确管理设备内存分配释放。

**4).TensorRT内部优化**

- 子图进入TensorRT dialect 之后复用TRT全套优化：算子融合、精度降低 FP16/FP8、tactic 搜索、workspace 管理。

**5).Kernel模块Codegen优化**

- Linalg tiling 分块、shared memory 流水线、直接映射 TensorCore WMMA/WGMMA 硬件指令；
- 面向 HPC 矩阵计算的循环变换优化。

**6).运行时优化(executor runtime)**

- flatbuffer二进制格式减少解析开销；
- Lua 轻量解释器调度各个后端；
- 异步执行；

## 4.全栈总结

MLIR‑TensorRT是NVIDIA软件栈中连接上层ML框架(JAX)、MLIR编译器生态、TensorRT推理库、CUDA硬件(TensorCore)的中间关键层，定位介于 ML 编译器框架和底层推理SDK之间。

### 4.1 MLSys视角

**1).MLIR生态补齐NVIDIA推理链路**

Google 主导 StableHLO/OpenXLA，传统 XLA‑GPU 后端生成 CUDA 内核，性能弱于 TensorRT；MLIR‑TensorRT 提供 StableHLO 高性能推理后端，JAX 生态在 NVIDIA GPU 不再二选一（XLA 或者手动转 ONNX‑TensorRT）。

**2).异构多后端混合编译范式**

MLSys领域经典难题 算子覆盖，单一后端很难覆盖全部算子；MLIR‑TensorRT给出方案：成熟算子交给高度工程化TensorRT；小众新算子 MLIR Codegen原生生成内核；标量shape交给CPU。

**3).与 Torch‑MLIR & TensorRT‑LLM关系**

- Torch‑MLIR：PyTorch->MLIR；可以复用MLIR‑TensorRT的tensorrt dialect把部分子图下沉TensorRT；
- TensorRT‑LLM：面向LLM大模型专用库，手写大量transformer kernel；MLIR‑TensorRT偏向通用tensor程序编译，面向通用模型(CV、扩散模型、JAX科学计算模型)，两者互补。

**PJRT插件打通JAX推理部署闭环**

- JAX训练(MaxText等)导出StableHLO直接编译推理，训练推理使用同一份IR，消除精度漂移，属于MLSys训练推理统一IR实践。

### 4.2 AI‑Infra视角

NVIDIA完整软件栈分层： 硬件GPU (TensorCore FP8/WGMMA) -> CUDA、cuBLASLt、NCCL -> TensorRT 库 + MLIR‑TensorRT 编译器 -> JAX/PyTorch 框架 -> Triton 推理服。

- MLIR‑TensorRT 向上对接 OpenXLA/JAX，向下封装 TensorRT 与 CUDA 硬件；作为编译器组件库，可以被上层基础设施调用。
- 输出产物适配生产部署：emitc 生成 C++ 源码适合嵌入式、边缘、数据中心服务；rtexe 二进制适合快速迭代，可直接喂给 Triton Inference Server 做线上推理服务。
- 补全 TensorRT 输入源：TensorRT 原有输入：ONNX、C++ API；新增 MLIR/StableHLO 输入通道，适配现代 ML 编译生态。

### 4.3 HPC视角

- kernel模块的MLIR‑GPU Codegen不仅用于AI推理，也面向HPC科学张量计算，直接生成调用TensorCore矩阵硬件指令PTX内核。
- HPC+AI融合workload：JAX既可以做科学仿真HPC计算，又可以做AI模型；MLIR‑TensorRT统一编译路径，同一套StableHLO IR，既可以跑AI推理，也可以加速科学张量计算，复用GPU TensorCore算力。
- 与HPC软件栈结合：搭配HPC‑X通信库NCCL，executor运行时支持多GPU通信原语；可以处理多设备张量计算任务。

### 4.4 局限性与定位

- MLIR‑TensorRT属于TensorRT‑Incubator 孵化项目，非TensorRT 主线稳定产品；适合研究、原型、JAX 推理场景；生产大语言模型优先 TensorRT‑LLM。
- 不是训练编译器，专注推理编译；
- Kernel模块Codegen能力对比Triton、AITemplate算子库成熟度尚有差距，定位fallback兜底，而非替代 TensorRT。
