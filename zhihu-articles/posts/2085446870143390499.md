## 1. 推理过程与性能瓶颈

### 1.1 Prefill 与 Decode

自回归推理通常分成两个阶段：

| 阶段 | 主要工作 | 常见瓶颈 | 重点指标 |
| --- | --- | --- | --- |
| Prefill，提示词预填充 | 并行处理输入 token，建立各层 KV Cache | 长输入的注意力计算、临时张量与数据搬运 | 首 token 延迟、输入吞吐 |
| Decode，逐 token 解码 | 利用缓存生成后续 token | 权重和 KV 读取、显存容量、串行依赖 | 每 token 延迟、输出吞吐 |

这是一种常见划分，不是硬件瓶颈的固定结论。短上下文、小批量解码可能主要受权重读取限制；长上下文时，KV 读取占比上升；较大批量或投机验证又可能提高计算密度。优化前应通过实际负载分析确认限制因素。

### 1.2 基本计算与缓存模型

单个注意力头可写为：

$$ \operatorname{Attention}(Q,K,V) =\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V $$

其中，因果掩码 $M$ 在可访问位置为 0，在禁止访问位置为负无穷。设层数为 $L$、批量为 $B$、缓存长度为 $T$、KV 头数为 $H_{kv}$、每头 K/V 维度均为 $d$、每元素占 $s$ 字节，则：

$$ M_{KV}=2LBTH_{kv}ds $$

该式不含模型权重、工作区、内存碎片和分配元数据，假设各层维度一致、序列等长，且未考虑设备间分片或复制。变长批量应以各请求缓存长度之和替代 $BT$。KV Cache 的逐层组织和历史复用机制见 [Transformers 官方文档](https://huggingface.co/docs/transformers/main/en/cache_explanation)。

从这个容量公式可以直接看到三条路径：减少 KV 头数，缩小每个 token 的表示，减少保留的 token 数。降低数据精度也是另一条路径，但不属于本图的九种方案。

### 2. 不同方案的综合对比

下表中的“训练”指将现有普通 MHA 模型改造成相应方案时的适配需求。直接部署已经训练好的 MQA/GQA/MLA 模型，无须再次训练。

| 方案 | 核心操作 | 对注意力的改变 | 是否需要训练适配 | 主要收益 | 主要代价或限制 |
| --- | --- | --- | --- | --- | --- |
| FlashAttention | 分块计算、融合算子，减少显存读写 | 不改变数学定义 | 不需要 | 降低临时存储和 IO 开销 | 内核实现复杂，收益依赖形状与硬件 |
| KV Cache | 缓存历史 K/V | 不改变数学定义 | 不需要 | 避免重复计算历史前缀 | 缓存随序列及并发增长 |
| MQA | 所有 Query 头共享一组 K/V | 改变参数结构 | 通常需要 | 大幅减少 KV 容量及读取量 | 表达能力可能受限 |
| GQA | 每组 Query 头共享一组 K/V | 改变参数结构 | 通常需要 | 在缓存规模与质量间折中 | 头数需要选型，不能保证与 MHA 等价 |
| MLA | 通过学习得到低维 KV 潜在表示 | 改变参数结构 | 通常需要 | 压缩每个 token 的缓存 | 依赖位置编码设计和专用实现 |
| Sliding Window Attention | 每层只直接访问局部窗口 | 改变注意力范围 | 视原模型与质量要求而定 | 限制缓存与局部注意力成本 | 远距离直接访问受限 |
| StreamingLLM | 保留注意力汇聚位置及最近窗口 | 改变保留上下文及位置处理 | 基础方案不需要微调 | 以有界缓存持续处理流式输入 | 不提供完整历史检索能力 |
| KV Cache Pruning | 按策略丢弃部分历史 K/V | 改变可访问历史 | 常见推理期方案不需要 | 减少缓存及潜在读取量 | 可能误删关键信息，有选择开销 |
| Speculative Decoding | 草稿生成、目标模型批量验证 | 通常不改变目标模型 Attention | 基础方案不要求重训目标模型；草稿可能需要训练 | 降低目标模型串行调用次数 | 草稿及验证有额外成本，收益依赖接受率 |

### 3. 各个方案原理

### 3.1 FlashAttention：减少数据搬运

普通实现可能将注意力分数矩阵及中间结果写入显存。FlashAttention 将计算分块，在片上存储中结合在线 Softmax 完成运算，避免完整物化二次规模的注意力矩阵。它保留精确注意力的数学语义，不采用稀疏近似，但浮点计算顺序不同可能造成数值差异。[原始论文](https://arxiv.org/abs/2205.14135)

对长度为 $T$ 的稠密注意力，其算术复杂度仍为 $O(T^2d)$；收益来自 IO 和存储组织。它不会自动缩小长期保留的 KV Cache。原图中的“额外运算”需要区分阶段：训练反向传播中的重计算是典型取舍，不能据此断言推理一定增加固定比例的运算。

**实施关注点：** 长提示词通常更能体现注意力内核优化的价值；单 token 解码应选用针对解码形状优化的内核，并检查硬件、数据类型、掩码及缓存布局兼容性。

### 3.2 KV Cache：用显存换取历史计算复用

因果模型中，历史 token 的表示不依赖未来 token，因此其各层 K/V 可以缓存。后续解码只计算新 token 的状态，再用新 Query 访问历史 K/V；历史 Query 通常无需缓存。[官方原理说明](https://huggingface.co/docs/transformers/main/en/cache_explanation)

KV Cache 消除了反复处理整个前缀的成本，但当前 Query 仍需读取可见历史。在完整注意力下，单步注意力随历史长度线性增长，并不会变为与上下文长度无关的常数成本。

**实施关注点：** 保证缓存位置、掩码和模型状态一致；容量规划同时考虑输入长度、输出增长和并发。本文默认缓存不量化、不剪枝；引入这些变换后，应另外评估误差。

### 3.3 Multi-Query Attention（MQA）：共享一组 K/V

标准多头注意力 MHA 的每个 Query 头通常有独立的 K/V 头。MQA 保留多个 Query 头，却共享一组 K/V，将 $H_{kv}$ 降为 1。相同层数、头维度及精度下，其 KV 容量是 MHA 的 $1/H_q$，其中 $H_q$ 为 Query 头数。[MQA 原始论文](https://arxiv.org/abs/1911.02150)

这种共享减少缓存和解码带宽需求，但也减少了独立的 K/V 投影。原图中的“可能明显伤害模型能力”应理解为风险，而非普遍结论：影响依赖模型、训练方式和评测任务。

**实施关注点：** 不能仅修改已训练 MHA 模型的头数配置就宣称得到等价模型。迁移需要权重转换、训练适配和质量验证；实际加速比例也不会简单等于缓存缩小比例。

### 3.4 Grouped-Query Attention（GQA）：按组共享 K/V

GQA 将 Query 头分组，每组共享一组 K/V。设 KV 组数为 $G$，则 $H_{kv}=G$；$G=1$ 对应 MQA，$G=H_q$ 对应 MHA，其间形成缓存容量与表示能力的折中。缓存相对 MHA 的比例为 $G/H_q$。[GQA 原始论文](https://arxiv.org/abs/2305.13245)

原论文给出了从 MHA 检查点转换并继续训练的路径，使用原始预训练计算量约 5% 的适配预算；该数字是论文实验条件，不是所有模型的通用迁移成本。

**实施关注点：** 同时比较业务质量、KV 容量和端到端吞吐。GQA 可以作为模型选型的重要维度，但不能脱离训练数据、模型规模和内核实现，仅凭头数判断优劣。

### 3.5 Multi-head Latent Attention（MLA）：学习低维缓存表示

MLA 通过学习到的低秩联合压缩，将 K/V 的内容信息表示为潜在向量 $c_t^{KV}$。优化实现可吸收部分投影矩阵，避免在解码时反复展开完整历史 K/V。DeepSeek-V2 同时采用解耦的旋转位置编码设计，因此实际缓存还包含位置相关的 Key 分量。[DeepSeek-V2 技术报告，第 2.1 节](https://arxiv.org/html/2405.04434v5)

设潜在维度为 $d_c$，额外位置 Key 维度为 $d_r$，则该类实现的简化缓存估算为：

$$ M_{MLA}\approx LBT(d_c+d_r)s $$

**实施关注点：** MLA 是模型架构设计，不能视为对任意既有 KV Cache 做一次无损压缩。压缩维度、位置编码及内核需要配合；若实现仍展开并长期缓存完整 K/V，预期显存收益会被削弱。模型整体吞吐改善也不能全部归因于 MLA。

### 3.6 Sliding Window Attention（SWA）：限制局部注意力范围

窗口宽度为 $W$ 时，每个 token 在单层中只直接访问窗口内的位置。理想局部实现可将单层预填充的注意力成本从 $O(T^2d)$ 降为 $O(TWd)$，并让纯滑动窗口层的缓存稳定在窗口规模。Mistral 7B 是结合 GQA 与 SWA 的代表案例。[Mistral 7B 论文](https://arxiv.org/html/2310.06825v1)

多层网络可以间接传播窗口外信息，但这不等价于随时直接检索完整历史。混合全局层与局部层的模型，也不能把所有层的缓存都按窗口长度估算。

**是否需要训练：** 原生窗口模型部署时无需额外训练；全注意力模型可以在推理时被强制截断，但质量可能退化。训练适配是否必要，应由长距离依赖任务的验收结果决定。

### 3.7 StreamingLLM：保留注意力汇聚位置

StreamingLLM 观察到，部分初始 token 会承担较高的注意力权重，即 Attention Sinks。其基础方案保留少量初始位置和最近窗口，并配合位置处理，使既有模型无需微调即可进行稳定的长流式处理。[StreamingLLM 原始论文](https://arxiv.org/abs/2309.17453)

若保留 $S$ 个初始位置和 $W$ 个最近位置，缓存规模约随 $S+W$ 而非累计输入长度增长。论文另有训练专用 sink token 的探索，需要与基础免微调方案区分。

**实施关注点：** 持续处理很长的输入不等于保留同样长度的可检索记忆。已经淘汰的中间内容无法再被直接访问。评测应覆盖跨窗口后的指令遵循与事实回忆，不能只观察生成是否流畅。

### 3.8 KV Cache Pruning：按重要性保留历史

缓存剪枝是一类策略，而不是单一算法。它在预算内保留近期位置或被判断为重要的位置，丢弃其他 K/V。例如 H₂O 根据历史注意力贡献保留重要 token，并兼顾最近 token。[H₂O 原始论文](https://arxiv.org/abs/2306.14048)

对普通 K/V 表示，若每层每请求保留 $K$ 个位置，容量估算为 $2LBKH_{kv}ds$。然而，被删除的位置可能在后续问题中突然变得重要，历史注意力较低并不能证明未来无用。

**实施关注点：** 剪枝索引、评分和缓存搬移均有成本。如果为了选 token 而完整提取注意力权重，还可能抵消融合内核的收益。应同步测试长文检索、多跳问答、跨段引用和数值精确回忆。对原生窗口模型依法淘汰窗口外状态，与对全注意力模型近似剪枝，具有不同的语义影响。

### 3.9 Speculative Decoding：先起草，再批量验证

经典投机解码由较便宜的草稿模型连续提出多个 token，再由目标模型通过因果计算一次验证多个候选位置。接受连续通过验证的前缀后，从拒绝位置进行校正；全部接受时还可生成一个额外 token。[投机解码原始论文](https://arxiv.org/abs/2211.17192)

随机采样时，设目标分布为 $p$、草稿分布为 $q$，候选 $x$ 的接受概率为 $\min(1,p(x)/q(x))$；拒绝后从归一化的 $(p-q)_+$ 分布采样。正确校正可保持目标分布，而不是只检查两模型最可能的 token 是否相同。

**实施关注点：** 分布一致不意味着使用相同随机种子时逐字一致；数值精度和采样变换也需保持一致。基础方法无需重训目标模型，草稿模型可以现成或另行训练。草稿过慢、接受率过低或服务已处于高计算负载时，可能没有净加速。

### 4. 理论容量与性能估算

### 4.1 KV 容量示例

以下是按第 1 节公式计算的容量示例，不对应任何特定产品的实测。假设 $L=32$、$B=1$、$T=8192$、$H_q=32$、$d=128$，缓存为每元素 2 字节的 FP16/BF16，且各层配置一致。

| 配置 | KV 头数或缓存维度 | 总 KV 容量 | 相对 MHA |
| --- | --- | --- | --- |
| MHA | 32 个 KV 头 | 4 GiB | 100% |
| GQA | 8 个 KV 头 | 1 GiB | 25% |
| MQA | 1 个 KV 头 | 128 MiB | 3.125% |
| 假设的 MLA 配置 | d_c=512,d_r=64 | 288 MiB | 7.03125% |

MLA 行仅展示容量公式，不能据此断言其质量或速度优于其他行。不同架构的表示能力并不由缓存字节数单独决定。

如果在上述 GQA 配置中，所有层原生采用 $W=2048$ 的纯滑动窗口，稳态 KV 容量进一步变为 256 MiB。如果保留 $W+S$ 个位置，则还应加入 $S$ 个位置的容量。批量扩大到 16，等长且无共享时，表中容量也相应扩大 16 倍。

### 4.2 缓存缩小不等于端到端等比例加速

可将单步延迟粗略分解为：

$$ t_{step}\approx t_{weights}+t_{KV}+t_{compute}+t_{communication}+t_{schedule} $$

这只是分析模型，实际执行可能存在重叠。即使 $t_{KV}$ 明显下降，权重读取、其他网络层和通信也可能限制整体收益。

按 Amdahl 定律，若可优化部分占原延迟的比例为 $f$，该部分加速 $r$ 倍，则总加速比近似为：

$$ S=\frac{1}{(1-f)+f/r} $$

例如，KV 相关部分占延迟 40%，该部分理想加速 4 倍，总体加速也只有约 1.43 倍。该示例说明为何显存缩小比例不能直接充当吞吐提升比例。

### 4.3 投机解码的盈亏条件

设一轮草稿耗时为 $t_d$、目标验证耗时为 $t_v$、校正与调度耗时为 $t_o$，每轮平均提交 $a$ 个 token，普通目标解码单 token 耗时为 $t_b$，则近似加速比为：

$$ S_{spec}\approx\frac{a\,t_b}{t_d+t_v+t_o} $$

只有分子大于分母才有净收益。增加草稿长度可能提高单轮接受数量，也会增加草稿和验证成本，因此应同时记录接受率与“每轮实际提交 token 数”，并按任务和负载调整参数。

### 5. 组合方式与选型建议

以下建议是依据上述机制给出的工程判断，需由目标硬件和业务数据验证。

| 场景 | 建议优先评估 | 判断重点 |
| --- | --- | --- |
| 既有模型，要求保持完整上下文 | KV Cache、高效注意力内核；再评估精确投机解码 | 数值一致性、首 token 延迟、输出延迟 |
| 高并发或长上下文，KV 显存不足 | 原生 GQA/MLA 模型选型 | 质量、总缓存、可服务并发及内核支持 |
| 持续流式输入，主要依赖近期信息 | 原生 SWA 或 StreamingLLM | 窗口边界行为、历史遗忘是否可接受 |
| 固定模型且允许质量与成本折中 | 小幅缓存剪枝，再逐步降低预算 | 最差任务退化及评分开销 |
| 低并发、长输出，目标解码延迟高 | 投机解码 | 草稿成本、接受长度与净延迟收益 |
| 允许训练或继续训练 | 比较 MQA/GQA/MLA | 训练成本、业务质量与部署效率共同验收 |

组合时需要注意：

1. **KV Cache 与 FlashAttention 可以互补。** 前者复用历史，后者优化实际注意力计算；落地需要内核支持相应缓存格式。
2. **MQA/GQA/MLA 通常是架构选项。** 不能把三者的压缩比例直接相乘。使用混合设计需要单独定义模型结构。
3. **窗口与缓存压缩作用于不同维度。** 前者减少位置数，后者减少每个位置的表示大小，但改变窗口可能影响质量。
4. **投机解码可与底层优化组合。** 更快的目标解码也会改变草稿与验证的相对成本，因此需重新测量收益。
5. **精确投机解码不能恢复被剪枝的信息。** 如果目标执行已经因窗口或剪枝改变分布，精确验证保持的是该目标执行的分布，而非原始全上下文模型的分布。
