Gemini 4 Hydrogen 值得拿来试，但别靠发布稿上那几个倍数做迁移决定。谷歌 11 月 12 日发的官方博文里，"编程成绩翻三倍""编造性陈述少五倍""任务快 2.5 倍"，每一个都只在很窄的口径里成立，换成"我的项目会不会好用三倍"，这个问题原文回答不了。

腿子这两天把两篇官方博文从头读了一遍，专门找每个倍数的基线和基准。先说明一句：腿子还没把它接进自己的项目里跑，下面是读发布稿加算账的结论，不是上手评测。

## 能核对的先摆出来：价格、窗口、谁能用

据谷歌官方博文，Gemini 4 Hydrogen 的定位是"每天都在用的 agent 工作流引擎"，和更重的 Carbon、Argon 分工：后两者做深度长程推理，Hydrogen 负责快速执行。API 模型 ID 是 `gemini-4-hydrogen`，几条硬信息如下：

- 价格：每百万输入 token 1.50 美元，每百万输出 token 7.50 美元；
- 上下文：1M token，且整个窗口内单价不变，不分长短档；
- 思考档位：low、medium、high（默认）、xhigh（新增）；
- 开放：Gemini API 和 Google AI Studio 向所有档位开放，Google 搜索向所有用户推出，Antigravity 仅限付费的 AI Pro / Ultra 订阅者。

"免费用户可用"这句要读细。原文说的是免费用户在 Gemini app 里通过自动模型选择获得，也就是 Gemini 觉得这个问题适合它才会用，免费用户能不能手动选，原文没写。另外页面没给速率限制和配额数字。腿子的理解：普通人会在搜索里不知不觉用上它，但写代码的人想稳定用，得走 API 或付费订阅。

还有一个小细节。这次谷歌没有叫它 Flash，名字换成了元素。但博文谈迁移时，对比对象仍是 Gemini 3.8 Flash。命名换了，竞争位置没换，它就是上一代 Flash 档的接班人。

## "编程 3 倍"其实是一个基准的比值

中文报道里"编程能力提升 3 倍"这个说法，腿子在两篇官方博文里一个字都没找到。最接近的一句是：Terminal-Bench 4.1 上得分 57%，对比 18.2%，"more than tripling"。57 除以 18.2，约 3.1 倍，数学没问题。

问题在基线。博文没在这句话里点名对比对象，从上下文看是 3.8 Flash。18.2% 是个很低的起点，说明上一代 Flash 档在这套终端任务上基本跑不通，翻三倍是从"难用"到"能用"，不是从"能用"到"三倍好用"。腿子在 IDE 里盯着 agent 跑任务的时候，最怕的就是中途卡死，所以这个提升对做终端自动化的人很有价值，只是它不能外推成"写业务代码好三倍"。

谷歌引用的其他成绩比较实在，都是第三方榜单或带名字的基准：Artificial Analysis 智能指数默认档 51，高于 Argon 的 50；Vals Tax Agent Bench 52.3%，排第一；arena.ai 的 Agent Arena 排第五。腿子的读法是，第五不是第一，它是个"够用且便宜"的选手，不是全场最强。

## "5 倍"说的是编造性陈述，不是你想的那个幻觉率

原文的措辞是 "cutting fabricated claims by more than 5x"，直译是编造性陈述减少五倍以上。到了中文媒体那里，成了"幻觉减少 5 倍"。两个词不等价。

另一篇面向开发者的博文，只写了 "fewer fabricated claims"，连数字都没有。5 倍这个数字，没有点名基准，也没有写测试方法，腿子没法复核。对写代码的人来说，真正痛的幻觉是这几种：编出一个不存在的 API，引用一个不存在的包，改完说"测试通过了"其实没跑。这些在博文里对应的是另一组数字，比如工具使用与编码评测里的错误行为减少 12 倍、agent 诚实率 94%，同样是谷歌内部评测，也没有公开的测试设置。

腿子对这类数字的态度是：方向可信，幅度打折。厂商自己出的内部评测，方向基本靠谱，幅度要留一半余地。

## "2.5 倍快"快的是完成任务，要连 token 一起算

原文说在默认 high 档，Hydrogen 完成任务比之前快 2.5 倍。注意是 finishing tasks，不是每秒吐多少 token。合作伙伴的早期测试里，在图谱、SQL 和数据密集型企业工作流上，相比 3.8 Flash 快 2 到 2.8 倍，token 用量少 12% 到 23%。这些来自谷歌转述，口径比 2.5 倍更具体，也更可信。

这里有个陷阱：推理模型的速度和思考档位强相关。high 档比 low 档慢，xhigh 更慢，所以你拿 high 档的耗时去和别家的默认档比，输赢取决于对方默认开的是什么。腿子要看的是端到端：一个任务从提交到测试通过，花了多少分钟、多少 token。

算一笔假设账。假设一个 agent 任务读代码、改代码、跑测试，一共吃掉 50 万输入 token、2 万输出 token，按官方价是 0.5 × 1.5 + 0.02 × 7.5 = 0.9 美元。一天跑 10 个这样的任务，9 美元，一个月按 22 个工作日是 198 美元。这是估算，不是实测，但它说明了一件事：单价便宜，不等于账单便宜，token 用量才是大头。

## 腿子的做法：拿 20 个自己的任务，跑一晚上

发布稿上的倍数，进不了选型报告。如果你在团队里要说服别人换模型，被问一句"这个 5 倍怎么测的"，答不上来，方案就站不住。

腿子的办法很土：从自己仓库的历史里挑 20 个真实任务，修 bug、补测试、小重构、改配置各几个，每个都有明确的"过 / 不过"判据。同一批任务，用 Hydrogen 的 high 档和当前在用的模型各跑一遍，记四列：通过率、耗时、token 数、折合成多少钱。20 个任务不算多，足够看出这一类工作里它到底是"能用"还是"好用"。如果通过率差不多，耗时和成本又明显低，换；如果通过率掉了，再快也不换。

腿子今晚就打算这么跑，结果出来再单独写。目前的选择是：Hydrogen 先进自己的候选名单，用它做日常的 agent 执行，重活继续留给更强的模型，不会因为发布稿的三个倍数就全量迁移。

腿腿们，你们团队选模型的时候，是看发布稿、看榜单，还是自己有一套内部回归集？如果有，你们的 20 个任务都是怎么挑的？
