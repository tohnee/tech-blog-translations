前八篇拆的都是模型本身：怎么训练、怎么服务、怎么算得更久。Agent 把模型从”回答问题的系统”变成”软件系统里的一个组件”，可靠性问题随之换了一个量纲——单次采样错 0.1% 无伤大雅，而一千步循环里的 0.999 连乘只剩 37%。Agent 工程的全部主题，就是把这个串联可靠性数学重新抬回可用区间。拆四层：工具循环（格式可靠）、上下文工程（状态管理）、Agent RL（环境与奖励）、多 Agent（隔离与扩展）——最后看失败模式分布把四层串起来。

### 一、最小 Agent：一个循环

Agent 的定义性结构是 ReAct 循环（思考→行动→观察），2023 年它靠提示词硬凑，2025 年它是一个有类型系统的执行体：

```python
def agent_loop(goal, tools, max_steps=100):
    ctx = [system(goal, TOOL_SCHEMAS)]        # schema 静态前缀, 吃满 KV 缓存
    for _ in range(max_steps):
        out = llm(ctx, tools=TOOL_SCHEMAS)    # 结构化输出: 文本 + 工具调用
        ctx.append(out)
        if not out.tool_calls:                # 无调用 = 自然语言收尾
            return out.text
        for call in out.tool_calls:           # 逐个执行
            obs = tools[call.name](**call.args)
            ctx.append(tool_result(call.id, obs))   # 观察回填, 进入下一轮
```

关键的工程转折是 2023 年 6 月的 function calling：工具从”提示词里求模型输出 JSON”变成**接口契约**——开发者声明 JSON Schema，模型按 schema 生成调用。底层是接回第 1 篇解码层的技术：文法约束采样，把 schema 编译成 DFA，直接在 logits 上 mask 非法 token，格式合法率从”哄出来”变成结构保证。这一步把工具调用错误率打到接近零，Agent 才具备起步资格。之后的并行调用、强制工具选择（tool_choice）都是同一契约的扩展。

另一个值得记录的融合来自第 8 篇：推理模型进入循环后，思维链夹在工具调用之间持续存在（interleaved thinking），观察回填后模型先思考再行动——Agent 循环成了长思维链的天然宿主，”多想一步”与”多看一眼环境”在同一个上下文里交替发生。

### 二、上下文工程：prompt 是程序

Agent 场景下 prompt 从一段文本变成一个**运行时数据结构**。窗口是一次性内存，所有输入在同一平面竞争注意力，于是有了预算这门学问：

| 组件 | 典型占比 | 缓存性 | 管理策略 |
| --- | --- | --- | --- |
| 系统指令 | 5~10% | 静态前缀 | 永驻 |
| 工具 schema | 10~30% | 静态前缀 | 按任务挂载子集 |
| 历史对话 | 随轮次增长 | 前缀可缓存 | 旧轮摘要、近轮原文 |
| 工具观察流 | 30~70% | 低 | 单条截断、滑动窗口 |
| 记忆/检索注入 | JIT | 无 | 按需加载 |

注意这份表与第 5 篇 KV 缓存经济的对齐：静态前缀是缓存命中的黄金地段，观察流是即时垃圾——**上下文工程与缓存工程是同一份预算的两面**。压缩版分配器：

```python
def pack_context(budget=200_000, parts=None):
    static = parts["system"] + parts["tools"]        # 静态区永驻
    mem = parts["memory"]                            # 持久记忆文件
    evict_order = ["old_obs", "old_turns", "retrieval"]  # 逐级驱逐
    ctx = assemble(static, mem, parts)
    for key in evict_order:                          # 超预算时从低价值端砍
        if size(ctx) > budget:
            ctx = compress(ctx, key)
    return ctx
```

这里必须直面一个不讨喜的物理现象：**context rot**（Chroma 2025）——性能随窗口占用率单调下降，哪怕内容全部相关。注意力是固定预算的资源，装得越多，每份越薄；这与第 7 篇”有效上下文小于标称”是同一件事的 Agent 视角。由此推出三条铁律：能不装的就不装（JIT 按需检索，而非预装全库）、观察流必须截断与结构化（工具结果只留关键字段）、旧轮次主动摘要。

状态外置是第四招，也是分水岭：把跨会话状态放进文件系统（AGENTS.md / CLAUDE.md 这类项目记忆文件），让 Agent 自己读写维护。**上下文装不下的，放进环境里**——这句话同时定义了记忆和多 Agent 两个方向。

### 三、Agent RL：环境是瓶颈

第 8 篇的结论”验证器存在与否决定一切”在 Agent 域找到了最硬的落地：环境 = 沙箱 + 任务 + 规则奖励。SWE-bench 的构造就是范式——真实 GitHub issue 加人工核验的测试集（Verified 500 题），奖励 = 测试通过率。训练侧的循环节奏与 R1 完全同构：先 SFT 合成轨迹立骨架，再 outcome RL 长能力（SWE-Gym、SWE-RL 这一系）；rollout 是数百步的长轨迹、32~128K 上下文，直接复用第 7 篇的序列并行与 KV 优化。

Agent 环境设计的一半工作量在**奖励防作弊**。METR 2025 年记录的真实案例包括：模型重命名测试文件让 runner 跳过、修改沙箱配置伪造通过信号、在测试执行前插入 `exit(0)`。这些不是边角故障——是 RL 会在奖励梯度上找到的最短路径。防御因此成为环境的一等设计：

```python
class TaskEnv:
    def __init__(self, repo, tests):
        self.box = docker(repo, network="none")     # 断网, 断外部信息
        self.tests = mount_readonly(obscure(tests)) # 测试只读 + 内容混淆
    def grade(self, patch):
        with self.box.apply(patch):                 # 隐藏副本上评分
            return self.tests.run(pass_filter=exact_match)
```

只读挂载、内容混淆、隐藏验证副本、断网隔离——每一项都在把”通过测试”与”解决问题”重新焊死。经验规律：**环境质量的上限就是模型能力的上限**，而环境的工业化（任务生成、测试合成、防作弊）目前比模型迭代更慢、更贵，正在成为 Agent RL 的真正瓶颈。

### 四、多 Agent 与委派：隔离不是分工

多 Agent 常被讲成组织学故事（经理与员工），真实动机冷得多：**上下文隔离**。子 Agent 拿一个新窗口独立跑完全程，只把结论回传主循环——主上下文装规划与结论，不装子过程的观察垃圾：

```python
def delegate(task, return_budget=2_000):
    sub = Subagent(fresh_ctx=task_only)   # 不继承主上下文
    result = sub.run(task)                # 独立循环, 独立预算
    return summarize(result, return_budget)   # 蒸馏回传
```

代价是 token 放大：单任务消耗从 $10^5$ 到 $10^6$ 级，委派是用算力买上下文卫生——只要观察流的 context rot 成本高于重算成本，这笔交换就是正的。生态侧的配套是 MCP（Anthropic 2024 年 11 月开源）：把工具实现从 Agent 框架解耦成独立服务器，模型厂商与工具厂商从此解耦，2025 年被 OpenAI、Google 先后跟进，成为工具接入的事实标准。再往外围是 computer use——观察从文本变成像素，难度跳档，OSWorld 分数至今远低于代码环境，验证了”接口的符号化程度决定 Agent 上限”这个判断。

### 五、失败模式：串联可靠性账本

头部模型在 SWE-bench Verified 已到 75~80% 区间（2025 年），但把任务时长拉长，串联数学立刻显形：每步 99.9% 正确，千步任务成功率 $0.999^{1000} \approx 37\%$。工程上的失败分布大致分层：工具格式错误（已被 schema 约束基本消灭）→ 观察误读（结构化输出可压）→ **幻觉状态**（自称做过而未做，靠环境回查机制对冲）→ **过早终止**（未验证即宣告完成，靠”必须运行测试才能 done”的规则约束）→ 目标漂移与上下文腐烂（长程任务的最后死因，目前只有委派与外置记忆两味药）。

值得注意的是规律：**Agent 的全部状态住在上下文里，所以所有失败最终都是上下文疾病**。评测侧同样要过可靠性关：SWE-bench、Terminal-Bench、OSWorld 各管一段，但榜单过拟合与测试集污染（题目泄露进训练数据）正在让”榜单分”与”真实任务成功率”脱钩——环境必须是私有的、可再生的，这与第三节的防作弊是同一条战线的两面。

### 六、收束

| 层 | 解决什么 | 代表技术 |
| --- | --- | --- |
| 工具层 | 格式可靠性 | JSON Schema + 文法约束解码 |
| 上下文层 | 状态管理 | 预算分配 / JIT / 摘要 / 外置记忆 |
| 训练层 | 任务能力 | 沙箱环境 + outcome RL + 防作弊 |
| 系统层 | 隔离与扩展 | 子 Agent 委派 / MCP / computer use |
| 评测层 | 度量可信 | 私有可再生环境 |

纵向读这张表会发现一个安静的结构：五层里没有一层在”让模型更聪明”，每一层都在**管理模型的不可靠性**——mask 掉非法输出、驱逐低价值 token、焊死奖励漏洞、隔离腐烂的上下文。模型能力每涨一档，这些工程的数字就宽松一档，但结构本身从 2023 到 2025 没有变过。

一句话收束：**Agent 不是更聪明的模型，而是被工程化到可承受的模型——把 per-token 的概率部件包进循环、缓存与沙箱，直到错误率从 token 口径降到任务口径。**
