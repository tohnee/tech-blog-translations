*2026-10-20 DeepInfer 开源事件解读 — 2026-10-21 整理*

### 一句话版本

10 月 20 日，DeepSeek 把它线上在用的推理框架 DeepInfer 以 Apache-2.0 开源了。仓库一天涨到约 1.25 万 stars，HN 首页挂了近 2000 分。发布是真的，料也足：全套自研 kernel（FlashMLA、DeepGEMM、DeepEP、TileKernels）一起打包进来，还首发支持华为 Ascend 950。但请先看 README 里 DeepSeek 自己写的那份”未包含”清单——KV cache 系统没有、Prefill/Decode 分离没有、数据并行负载均衡没有。把”推理引擎”变成”DeepSeek 线上服务”的那三件套，一件都没出门，理由写在 README 里：与内部基础设施紧耦合。

**发动机开源了，油箱留在家里。**

### 开源了什么

仓库 [http://github.com/deepseek-ai/DeepInfer](http://github.com/deepseek-ai/DeepInfer)，逐项核对过：

- **只有一个模型。** 只支持 DeepSeek-V4.1-Flash（默认权重就是 10-17 发的那个 1017 检查点），引擎是围着这个模型的 MLA/SWA 架构特性调的。
- **只有离线推理。** README 原话：这次发布提供的是”离线推理 + 大规模服务所需的核心特性”，没有在线服务层，没有 OpenAI 兼容的 server。
- **全套 kernel 打包。** FlashMLA、DeepGEMM、DeepEP、TileKernels、DeepSelect 加一批 TileLang 自定义 kernel——2025 年开源周陆续放出来的那些零件，现在装进了一个引擎里。并行策略有 Attention DP / 均衡 CP、MoE 专家并行 + EPLB。
- **DSpark 投机解码。** 草稿 token 带置信度估计，用置信度调度验证。DeepSeek 的材料称验证的草稿 token 减少约 30%、生产负载下吞吐 +4–7%——厂商数字，引用时要带这个标签。
- **SWA 有界重放。** prefill 只重放一段有界后缀（默认 KEEP_TOKENS=140），官方称总 prefill 计算量近乎减半。同样是厂商口径。
- 异步零开销批调度（默认开）、batch-invariant 推理和确定性采样（仅英伟达）、结构化输出（正则/JSON schema/EBNF）。
- **硬件：英伟达 SM100（Blackwell，CUDA 13）+ 华为 Ascend 950（CANN 9.2）。** Hopper 及更早的不支持。全网目前没有任何 Ascend 上的 benchmark 数字，README 里所有图表都是 SM100 上测的（prefill 4 卡、decode 64 卡，各自在单个 scale-up 域内）。

同日还发了个配套小仓库 deepseek-recipe（与官方 API 对齐的 token 编解码）。

### 没开源什么——这才是重点

README 自己列了”完整推理服务需要、但本次未包含”的三样：

**第一，KV cache 系统。** HN 讨论里最高赞的评论只有一句话：”Notably missing their kv cache system.“（值得注意：他们的 KV cache 系统没给。）点赞最多的回复把原因说透了：DeepSeek 线上托管的优势，很大一块在缓存层级——KV cache 从显存迁移到主机内存再到非易失存储，缓存寿命以天计（仓库内的部署 Q&A 写明保留超过 72 小时、约 100 PiB 的 SSD 缓存、每 GPU 逻辑上约 14.4 TB），再把请求路由到缓存所在的位置。这套基础设施不在本次发布里。（它底下的存储层 3FS 是 2025 年单独开源过的。）

**第二，Prefill/Decode 分离。** README 承认”大部分所需引擎功能已经实现”——实现了，但不包含。

**第三，数据并行副本之间的负载均衡。**

还有一条藏在部署 Q&A 里（MarkTechPost 转述）：连已发布的 kernel 都不是线上最快版——内部版 FlashMLA decode kernel 比公开版还快 5–10%，端到端差距在 5% 以内。

这不叫虚假开源，这叫**可读的开源**。2025 年 4 月，DeepSeek 在 open-inference 仓库里明确说过：不打算发布完整推理引擎，因为代码是深度定制的早期 vLLM 分叉，和内部集群工具紧耦合，团队小、没精力维护，改为逐个发组件。DeepInfer 等于推翻了那个决定——但推翻的方式恰好证明了 2025 年那段话是对的：耦合最紧的部分，正是这次没出的部分。README 的致谢也写得诚实：”DeepInfer was originally built primarily on vLLM, with additional inspiration from SGLang and TensorRT-LLM.“vLLM 官方还专门在 X 上致谢，说会把 DeepInfer 的思路吸收回自家的 V4.1-Flash 支持里。开源生态该有的样子——同时也说明，引擎这一层已经被所有人共同”商品化”了。

### 数字部分，请把标签贴好

这篇文章里所有数字都来自 DeepSeek 自报，源头是仓库里附带的一份部署 Q&A 文档。截至目前，没有任何第三方复现过其中任何一个数字。

- **单集群日吞吐 155 万亿 tokens。** 这是最需要小心的一个数。”集群”没有定义规模。HN 上有人用 README 自己的图表算了笔账：约 2.6 万 tok/s/GPU 的输出速度，对应一天约 22.5 亿 tokens/GPU，反推”一个集群”大约是 7 万张 GPU 量级。再给个参照：OpenRouter 整个平台上一周的总量是 164 万亿 tokens。这个数字对一个超大规模部署可能成立，但按目前的披露方式，它不可证伪。
- **输入缓存命中率 96%**，平均 TTFT 约 400 ms，生成约 230 tok/s（代码场景最高 300）。缓存命中率尤其不能裸引：它是 DeepSeek 线上流量结构 + 那套没开源的分级缓存基础设施共同作用的结果。你把这个仓库拉下来自己跑，不会得到任何意义上的 96%。
- **每卡每小时收入 38 美元（闲时定价）。** 这是技术数字底下的经济数字，同样自报。
- **decode 图表埋了假设。** 有细读 README 的人指出（Zyvop），decode 的 Pareto 图是按 75% 的逐 token 草稿接受率（τ=3.25）画的，不是原始实测；不同引擎之间比吞吐，必须先对齐 token 的计数口径。代码场景 300 tok/s 是最佳负载下的数字，不可预测文本上收益会缩水。

### Ascend 950：先写定位，别写性能

首发即支持 Ascend 950，有独立的 requirements 文件、CANN 9.2 工具链。战略上这很响亮：出口管制之后的市场，最缺的就是华为硅片上一方维护的生产级推理栈。但今天的证据只有定位、没有性能：没有任何 Ascend benchmark、没有第三方上手报告，HN 讨论里反复出现的反而是可获得性问题——”if only we can buy Huawei Ascends”（要是买得到昇腾就好了）。batch-invariant 和确定性采样还都是英伟达独占。写这段时，定位归定位，性能归性能，别混。

### 时间点，只摆事实

两个事实：美国国土安全部要求联邦文职机构移除 DeepSeek 的命令，7 月 24 日签发、10 月 20 日在《联邦公报》正式刊登；DeepInfer 10 月 20 日宣布。”晚一天”是属实的先后关系。至于”这是对封杀的回应”——那是评论者的推测（The Decoder 也只是说”可能有政治动机”），DeepSeek 没有说明动机。把两个事实并排摆出来，让读者自己连线，别替他连。

### 对后端读者的真正启示

剥掉地缘和 star 数，DeepInfer 是 2026 年”推理护城河到底在哪”最干净的一个教案：

- **不在引擎。** 引擎是 vLLM 的后代，上游刚把它的思路吸收回去。
- **不太在 kernel。** 公开版比内部版慢个位数百分比，规模上重要，但不是护城河。
- **在缓存和流量。** 96% 的输入缓存命中率，才是那套定价（搜索 API 5 块钱一千次、每卡每小时 38 美元）的地基；而它来自三样下载不到的东西：分级存储、多日缓存寿命、感知缓存位置的路由，再加上谁也复制不了的线上流量结构。

接上这半个月的叙事线：先是”开源只是门票，搜索才是收银台”（权重免费、检索收费），DeepInfer 补了基础设施这一节——**引擎可以开源，油箱不行。** 这份大方是真的大方：一个生产级打磨过的单模型引擎加全套 kernel，对任何要部署 V4.1-Flash 的人都是实打实的礼物。只不过它恰好也是一份不要钱的礼物——DeepSeek 收费的那部分，一点没动。

### 还没答案的问题

- 所有性能数字无第三方复现；155 万亿的”集群”未定义。
- 公开代码与线上实际运行代码的重合度未知。
- Ascend 950 无公开性能数据，中国以外硬件可获得性存疑。
- 被扣下的三件套（KV cache、PD 分离、负载均衡）将来发不发，没有官方说法。
