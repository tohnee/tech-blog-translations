## 2.详细展开

### 2.1 triton 例子

下面给出一个简单triton例子。真正的device侧的算子用 @triton.jit来修饰。add_kernel也是我们下面要重点分析的device函数

```text
import torch
import triton
import triton.language as tl

# ---------------- Triton kernel ----------------
@triton.jit
def add_kernel(x_ptr, y_ptr, output_ptr, n_elements,
               BLOCK_SIZE: tl.constexpr):
    pid = tl.program_id(0)                 # 1-D 网格
    block_start = pid * BLOCK_SIZE
    offsets = block_start + tl.arange(0, BLOCK_SIZE)
    mask = offsets < n_elements
    x = tl.load(x_ptr + offsets, mask=mask)
    y = tl.load(y_ptr + offsets, mask=mask)
    tl.store(output_ptr + offsets, x + y, mask=mask)

# ---------------- PyTorch 封装 ----------------
def add(x: torch.Tensor, y: torch.Tensor):
    output = torch.empty_like(x)
    n_elements = x.numel()
    grid = lambda meta: (triton.cdiv(n_elements, meta["BLOCK_SIZE"]),)
    add_kernel[grid](
        x, y, output, n_elements,
        BLOCK_SIZE=1024,
    )
    return output

# ---------------- 运行验证 ----------------
if __name__ == "__main__":
    torch.manual_seed(0)
    size = 98432
    a = torch.rand(size, device="cuda")
    b = torch.rand(size, device="cuda")

    out_triton = add(a, b)
    out_torch  = a + b
    print("最大误差:", torch.max(torch.abs(out_triton - out_torch)).item())
    # 期望输出：最大误差: 0.0
```

我们用python3 vector_add.py 执行，会在～/cache目录产生lower的缓存文件。

add_kernel.json 里面定义了详细信息。**就是 kernel 的“身份证”+“编译参数表”，让 cubin 能被快速匹配、复用、搬运，而不用每次都重走完整编译链。**

| 字段 | 示例 | 作用 |
| --- | --- | --- |
| kernel_name | "matmul_kernel" | Python 端的函数名 |
| num_warps / num_stages / waves_per_eu | 8 / 3 / 0 | 启发式调优参数，影响寄存器、流水线 |
| shared | 32768 | 静态 shared memory 字节数 |
| binary_size / arch | 12345 / "sm_90a" | cubin 大小与目标架构 |
| signature | "*fp16:*fp16:*fp16:i32:i32:..." | 参数类型表，用于运行时绑参数 |
| constants | {3:16, 4:16} | 被 JIT 折叠成常量的位置与值 |

Triton 运行时先读 JSON，确认“签名 + 常量 + 调优参数”完全匹配，就直接把对应 cubin 塞给 CUDA driver，否则重新编译。

## 3.代码分析

下面代码只会贴出关键代码部分。完整的代价可以跑一下2.1章节的例子得到。顺便说一下 nvidia的sass 指令集还不是risc-v，国产的npu的isa大概率是risc-v.

### 3.1 triton文件

1）（Triton ⇄ CUDA ⇄ 硬件）

| Triton 代码 | CUDA 等价 | 硬件寄存器/指令 |
| --- | --- | --- |
| program_id(0) | blockIdx.x | 特殊寄存器 %ctaid.x |
| tl.arange | threadIdx.x 展开成向量 | 向量寄存器 %r<tid> |
| tl.load/store | 向量化 ld.global.v4/st.global.v4 | LDG.128 / STG.128 |
| mask | predicate 寄存器 | 每个 lane 的 p 位 |

device端算子的核心triton代码如下：

```text
def add_kernel(x_ptr, y_ptr, output_ptr, n_elements,
               BLOCK_SIZE: tl.constexpr):

    block_start = pid * BLOCK_SIZE

    mask = offsets < n_elements

    y = tl.load(y_ptr + offsets, mask=mask)
    tl.store(output_ptr + offsets, x + y, mask=mask)
```

2）每行解释

每行的解释：这里并没有用tt的一些计算能力，只用了数据搬运能力。完整的tt能力我后续章节会提一下。

```text
# ---------------- Triton kernel ----------------
@triton.jit
def add_kernel(x_ptr, y_ptr, output_ptr, n_elements,
               BLOCK_SIZE: tl.constexpr):          # 编译时常量：每个程序块处理的元素个数
    pid = tl.program_id(0)                         # 获取当前程序块在 1-D 网格中的编号（类似 CUDA 的 blockIdx.x）
    block_start = pid * BLOCK_SIZE                 # 计算当前块负责的数据区间起始索引
    offsets = block_start + tl.arange(0, BLOCK_SIZE)  # 生成 BLOCK_SIZE 个连续偏移量（向量，长度=BLOCK_SIZE）
    mask = offsets < n_elements                    # 屏蔽越界元素：尾部不足 BLOCK_SIZE 时避免非法读写
    x = tl.load(x_ptr + offsets, mask=mask)        # 按掩码加载 x 向量，越界通道返回 0
    y = tl.load(y_ptr + offsets, mask=mask)        # 同理加载 y 向量
    tl.store(output_ptr + offsets, x + y, mask=mask)  # 按掩码存储逐元素相加结果，越界通道不写入
```

3）对应cuda代码

这部分代码对应的cuda代码如下：

```text
template <int BLOCK_SIZE>
__global__ void add_kernel(const float* __restrict__ x_ptr,
                           const float* __restrict__ y_ptr,
                           float* __restrict__ output_ptr,
                           int n_elements)
{
    // 全局线程索引：blockIdx.x * blockDim.x + threadIdx.x
    int tid = blockIdx.x * BLOCK_SIZE + threadIdx.x;

    // 边界判断，防止越界读写
    if (tid < n_elements)
    {
        float xv = x_ptr[tid];   // 读 x
        float yv = y_ptr[tid];   // 读 y
        output_ptr[tid] = xv + yv; // 写 z
    }
}
```

### 3.2ttir

**TTIR 的能力由 Triton 自己定义，但“载体”是 MLIR 框架；**定义了`tt.load`、`tt.reduce`、`tt.make_range`等所有操作的含义、类型系统、合法性规则。

生成的代码如下：

```text
module {
  tt.func public @add_kernel(
%arg0: !tt.ptr<f32> {tt.divisibility = 16 : i32} loc("vector_add.py":7:0), 
%arg1: !tt.ptr<f32> {tt.divisibility = 16 : i32} loc("vector_add.py":7:0), 
%arg2: !tt.ptr<f32> {tt.divisibility = 16 : i32} loc("vector_add.py":7:0),
 %arg3: i32 {tt.divisibility = 16 : i32} loc("vector_add.py":7:0)) 
attributes {noinline = false} {
    %c1024_i32 = arith.constant 1024 : i32 loc(#loc1)
    %0 = tt.get_program_id x : i32 loc(#loc2)
    %1 = arith.muli %0, %c1024_i32 : i32 loc(#loc3)
    %2 = tt.make_range {end = 1024 : i32, start = 0 : i32} : tensor<1024xi32> loc(#loc4)
    %3 = tt.splat %1 : i32 -> tensor<1024xi32> loc(#loc5)
    %4 = arith.addi %3, %2 : tensor<1024xi32> loc(#loc5)
    %5 = tt.splat %arg3 : i32 -> tensor<1024xi32> loc(#loc6)
    %6 = arith.cmpi slt, %4, %5 : tensor<1024xi32> loc(#loc6)
    %7 = tt.splat %arg0 : !tt.ptr<f32> -> tensor<1024x!tt.ptr<f32>> loc(#loc7)
    %8 = tt.addptr %7, %4 : tensor<1024x!tt.ptr<f32>>, tensor<1024xi32> loc(#loc7)
    %9 = tt.load %8, %6 : tensor<1024x!tt.ptr<f32>> loc(#loc8)
    %10 = tt.splat %arg1 : !tt.ptr<f32> -> tensor<1024x!tt.ptr<f32>> loc(#loc9)
    %11 = tt.addptr %10, %4 : tensor<1024x!tt.ptr<f32>>, tensor<1024xi32> loc(#loc9)
    %12 = tt.load %11, %6 : tensor<1024x!tt.ptr<f32>> loc(#loc10)
    %13 = tt.splat %arg2 : !tt.ptr<f32> -> tensor<1024x!tt.ptr<f32>> loc(#loc11)
```

诸行解释：

```text
// 自动生成的 TTIR（Triton IR）对应 Python 版 vector-add kernel
// BLOCK_SIZE 固定为 1024，所有操作都是 1024-wide 向量并行
module {
  tt.func public @add_kernel(
    // 基址指针 x、y、out，前端已推导出 16 字节对齐
    %arg0: !tt.ptr<f32> {tt.divisibility = 16 : i32},   // x_ptr
    %arg1: !tt.ptr<f32> {tt.divisibility = 16 : i32},   // y_ptr
    %arg2: !tt.ptr<f32> {tt.divisibility = 16 : i32},   // output_ptr
    %arg3: i32  {tt.divisibility = 16 : i32}            // n_elements
  ) attributes {noinline = false} {

    //----------------------------------------------------------
    // 1. 编译期常量：BLOCK_SIZE = 1024
    //----------------------------------------------------------
    %c1024_i32 = arith.constant 1024 : i32

    //----------------------------------------------------------
    // 2. 获取当前程序块编号（= CUDA blockIdx.x）
    //----------------------------------------------------------
    %0 = tt.get_program_id x : i32

    //----------------------------------------------------------
    // 3. 计算当前块的全局起始偏移 block_start = pid * BLOCK_SIZE
    //----------------------------------------------------------
    %1 = arith.muli %0, %c1024_i32 : i32

    //----------------------------------------------------------
    // 4. 生成线程级（元素级）索引向量 offsets = block_start + [0..1023]
    //    4a. 先造范围向量 [0,1,…,1023]
    //    4b. 把标量 block_start 广播成 1024 路
    //    4c. 逐元素相加得到全局索引
    //----------------------------------------------------------
    %2 = tt.make_range {end = 1024 : i32, start = 0 : i32} : tensor<1024xi32>
    %3 = tt.splat %1 : i32 -> tensor<1024xi32>
    %4 = arith.addi %3, %2 : tensor<1024xi32>

    //----------------------------------------------------------
    // 5. 生成掩码向量 mask = offsets < n_elements
    //    尾部不足 1024 时屏蔽越界通道
    //----------------------------------------------------------
    %5 = tt.splat %arg3 : i32 -> tensor<1024xi32>
    %6 = arith.cmpi slt, %4, %5 : tensor<1024xi32>   // slt = signed less than

    //----------------------------------------------------------
    // 6. 加载 x 向量：x = tl.load(x_ptr + offsets, mask=mask)
    //    6a. 基址广播 → 向量指针
    //    6b. 指针 + 偏移
    //    6c. 带掩码向量加载（越界 lane 返回 0）
    //----------------------------------------------------------
    %7 = tt.splat %arg0 : !tt.ptr<f32> -> tensor<1024x!tt.ptr<f32>>
    %8 = tt.addptr %7, %4 : tensor<1024x!tt.ptr<f32>>, tensor<1024xi32>
    %9 = tt.load %8, %6 : tensor<1024x!tt.ptr<f32>>

    //----------------------------------------------------------
    // 7. 同理加载 y 向量
    //----------------------------------------------------------
    %10 = tt.splat %arg1 : !tt.ptr<f32> -> tensor<1024x!tt.ptr<f32>>
    %11 = tt.addptr %10, %4 : tensor<1024x!tt.ptr<f32>>, tensor<1024xi32>
    %12 = tt.load %11, %6 : tensor<1024x!tt.ptr<f32>>

    //----------------------------------------------------------
    // 8. 逐元素相加：x + y
    //----------------------------------------------------------
    %13 = tt.splat %arg2 : !tt.ptr<f32> -> tensor<1024x!tt.ptr<f32>>
    %14 = tt.addptr %13, %4 : tensor<1024x!tt.ptr<f32>>, tensor<1024xi32>
    %15 = arith.addf %9, %12 : tensor<1024xf32>

    //----------------------------------------------------------
    // 9. 带掩码向量存储：tl.store(output_ptr + offsets, result, mask=mask)
    //    掩码为 false 的 lane 不会产生写事务
    //----------------------------------------------------------
    tt.store %14, %15, %6 : tensor<1024x!tt.ptr<f32>>

    //----------------------------------------------------------
    // 10. 函数返回
    //----------------------------------------------------------
    tt.return
  }
}
```

### 3.3 ttgir

TTGIR（Triton GPU IR）是 Triton 编译器在 **TTIR→LLVM** 之间插入的一层 **GPU 专用** 中间表示；它把硬件无关的 `tt.*` 算子进一步实例化为 **CTA/warp/thread** 三级并行模型，并显式管理 **shared memory、MMA 指令、异步拷贝、layout 转换** 等硬件资源。

| --- | --- | --- |

| Shared Memory | ttg.alloc_shared | 静态申请 shared memory tensor |
|  | ttg.insert_slice_async | 异步 global→shared 拷贝，可掩码 |
|  | ttg.async_wait | 等待指定 stage 的 async-copy |
|  | ttg.barrier | CTA 级 __syncthreads() |
| Layout 转换 | ttg.convert_layout | Blocked↔Shared↔MMA↔DotOperand 互转 |

### 3.4 llir

LLIR（Low-Level IR）在 Triton 编译流程里特指 **“LLVM-IR 阶段”**——把 GPU 方言（TTGIR）再往下降到 **标准 LLVM-IR** 的中间快照。它主要承担 4 件事：

1. **线程级展开**<br>将 warp-级 `ttg.mma` / `ttg.load` 等指令拆成 **单线程** LLVM 指令，并算出每个线程要访问的寄存器/地址。
2. **共享内存实体化**<br>`ttg.alloc_shared` 变成 `alloca [… x i8]`，并插入 `llvm.amdgcn.s.barrier` / `llvm.nvvm.barrier0` 同步。
3. **后端特化 & 元数据**<br>按 `sm_80` 或 `gfx90a` 设置 `maxnreg`、`amdgpu-waves-per-eu`、`target-features="+ptx80"` 等属性，供后续 LLVM 后端做指令选择和寄存器分配。
4. **O3 级优化**<br>运行标准 LLVM pass（死代码、循环展开、SROA、指令合并等）并生成 **可交给 NVPTX/AMDGPU 后端的干净 IR**。

```text
;  Triton 生成的 LLVM-IR（已针对 NVVM/CUDA 后端）
;  功能：z[i] = x[i] + y[i]  向量加，长度 = n_elements
;  线程组织：128 线程/CTA（4 warp × 32 thread），每线程处理 8 个 float
;  向量加载：128-bit（v4）事务，掩码屏蔽尾部越界
;  目标：sm_86 （compute capability 8.6）
; -----------------------------------------------------------------------------
source_filename = "LLVMDialectModule"
target datalayout = "e-p6:32:32-i64:64-i128:128-v16:16-v32:32-n16:32:64"

; 入口：add_kernel(x_ptr, y_ptr, out_ptr, n_elements, scratch_ptr)
; scratch_ptr 未使用（readnone），仅占位
define ptx_kernel void @add_kernel(
        ptr addrspace(1) %0,        ; x_ptr
        ptr addrspace(1) %1,        ; y_ptr
        ptr addrspace(1) %2,        ; out_ptr
        i32 %3,                     ; n_elements
        ptr addrspace(1) readnone captures(none) %4) local_unnamed_addr !dbg !6
{
entry:
    ; ----------------------------------------------------------
    ; 1. 取线程块号  blockIdx.x
    ; ----------------------------------------------------------
    %6 = tail call i32 @llvm.nvvm.read.ptx.sreg.ctaid.x(), !dbg !9

    ; ----------------------------------------------------------
    ; 2. 计算当前 CTA 的全局数据起始偏移
    ;    block_offset = blockIdx.x * 1024  (1024 = 128 线程 × 8 elem)
    ; ----------------------------------------------------------
    %7 = shl i32 %6, 10, !dbg !10          ; << 10 = *1024

    ; ----------------------------------------------------------
    ; 3. 取线程号  tid = threadIdx.x
    ; ----------------------------------------------------------
    %8 = tail call i32 @llvm.nvvm.read.ptx.sreg.tid.x(), !dbg !11

    ; ----------------------------------------------------------
    ; 4. 计算线程私有起始索引
    ;    每线程 8 个元素，按 4×2 分组（见下方 v4 加载）
    ;    lane_id   = (tid & 127) >> 2  → 0..31
    ;    vec_group = (tid & 3)       → 0..3  （4 组 v4）
    ;    先算低 4 元素偏移，再算高 4 元素偏移
    ; ----------------------------------------------------------
    %9  = shl i32 %8, 2, !dbg !11          ; tid * 4
    %10 = and i32 %9, 508, !dbg !11        ; 保留 0-507，对齐 4×float
    %11 = or disjoint i32 %10, %7, !dbg !12 ; + block_offset → 低 4 元素索引
    %12 = or disjoint i32 %11, 512, !dbg !12; + 512          → 高 4 元素索引

    ; ----------------------------------------------------------
    ; 5. 生成掩码：判断索引是否越界
    ; ----------------------------------------------------------
    %13 = icmp slt i32 %11, %3, !dbg !13   ; 低 4 元素合法？
    %14 = icmp slt i32 %12, %3, !dbg !13   ; 高 4 元素合法？

    ; ----------------------------------------------------------
    ; 6. 计算低 4 元素地址 & 加载 x 向量（128-bit v4）
    ; ----------------------------------------------------------
    %15 = sext i32 %11 to i64, !dbg !14
    %16 = getelementptr float, ptr addrspace(1) %0, i64 %15, !dbg !14
    %18 = getelementptr float, ptr addrspace(1) %0, i64 %17        ; 高 4 元素地址
    ; 内联 PTX：@pred 为真时执行 ld.global.v4.b32
    %19 = tail call { i32, i32, i32, i32 }
          asm sideeffect "mov.u32 $0, 0x0;\0A\09mov.u32 $1, 0x0;\0A\09mov.u32 $2, 0x0;\0A\09mov.u32 $3, 0x0;\0A\09@$5 ld.global.v4.b32 { $0, $1, $2, $3 }, [ $4 + 0 ];",
          "=r,=r,=r,=r,l,b"(ptr addrspace(1) %16, i1 %13) #1, !dbg !15
    %20 = extractvalue { i32, i32, i32, i32 } %19, 0
    %21 = extractvalue { i32, i32, i32, i32 } %19, 1
    %22 = extractvalue { i32, i32, i32, i32 } %19, 2
    %23 = extractvalue { i32, i32, i32, i32 } %19, 3
    %24 = bitcast i32 %20 to float, !dbg !15   ; x0
    %25 = bitcast i32 %21 to float, !dbg !15   ; x1
    %26 = bitcast i32 %22 to float, !dbg !15   ; x2
    %27 = bitcast i32 %23 to float, !dbg !15   ; x3

    ; ----------------------------------------------------------
    ; 7. 加载高 4 元素 x 向量
    ; ----------------------------------------------------------
    %28 = tail call { i32, i32, i32, i32 }
          asm sideeffect "mov.u32 $0, 0x0;\0A\09mov.u32 $1, 0x0;\0A\09mov.u32 $2, 0x0;\0A\09mov.u32 $3, 0x0;\0A\09@$5 ld.global.v4.b32 { $0, $1, $2, $3 }, [ $4 + 0 ];",
          "=r,=r,=r,=r,l,b"(ptr addrspace(1) %18, i1 %14) #1, !dbg !15
    ...（同上提取 x4-x7）

    ; ----------------------------------------------------------
    ; 8. 同理加载 y 向量（低 4 + 高 4）
    ; ----------------------------------------------------------
    %37 = getelementptr float, ptr addrspace(1) %1, i64 %15
    %38 = getelementptr float, ptr addrspace(1) %1, i64 %17
    %39 = tail call { i32, i32, i32, i32 } ... 加载 y0-y3
    %44 = bitcast i32 %40 to float   ; y0
    ...（y1-y7 同理）

    ; ----------------------------------------------------------
    ; 9. 逐元素相加（8 次 FADD）
    ; ----------------------------------------------------------
    %59 = fadd float %24, %44, !dbg !19   ; z0 = x0 + y0
    %60 = fadd float %25, %45, !dbg !19   ; z1 = x1 + y1
    %61 = fadd float %26, %46, !dbg !19   ; z2 = x2 + y2
    %62 = fadd float %27, %47, !dbg !19   ; z3 = x3 + y3
    %63 = fadd float %33, %53, !dbg !19   ; z4 = x4 + y4
    %64 = fadd float %34, %54, !dbg !19   ; z5 = x5 + y5
    %65 = fadd float %35, %55, !dbg !19   ; z6 = x6 + y6
    %66 = fadd float %36, %56, !dbg !19   ; z7 = x7 + y7

    ; ----------------------------------------------------------
    ; 10. 计算输出地址 & 带掩码向量存储（128-bit v4）
    ; ----------------------------------------------------------
    %57 = getelementptr float, ptr addrspace(1) %2, i64 %15  ; 低 4 元素地址
    %58 = getelementptr float, ptr addrspace(1) %2, i64 %17  ; 高 4 元素地址
    %67 = bitcast float %59 to i32
    ...（打包 z0-z3 为 i32）
    tail call void asm sideeffect "@$5 st.global.v4.b32 [ $4 + 0 ], { $0, $1, $2, $3 };",
          "r,r,r,r,l,b"(i32 %67, i32 %68, i32 %69, i32 %70,
                         ptr addrspace(1) %57, i1 %13) #1, !dbg !20
    ...（同理存储 z4-z7）

    ; ----------------------------------------------------------
    ; 11. 函数返回
    ; ----------------------------------------------------------
    ret void, !dbg !21
}

“这次调用是 尾调用（tail-call） —— 当前函数在调用之后 不再做任何工作，可以直接把被调函数当成自己的‘替身’，允许编译器做 尾调用优化（TCO）。”
```

Triton 的 LLIR（LLVM-IR）阶段 **不新增任何自定义 dialect**，而是直接把 TTGIR 降成 **标准 LLVM-IR**（外加少量 NVPTX / AMDGPU 后端 intrinsic）。

因此“LLIR 支持的操作”= **全体 LLVM-IR 指令集** + **目标后端专用 intrinsic**（CUDA 或 ROCm）。这里列出一些常见指令：

### 3.5 ptx

PTX（Parallel Thread Execution）是 NVIDIA 自己的 **“虚拟 GPU 汇编”** 语言，位于 CUDA 源码与最终硬件机器码（SASS）之间，由驱动里的 JIT 编译器（`ptxas`）在 **运行期或离线时** 汇编成可执行的 cubin。对 Triton 来说，**LLIR → PTX → SASS** 是默认后端路径，因此 dump 出来的 `.ptx` 文件就是你能读到的“最底层人类可读代码”。

**LLVM-NVPTX** 把 **LLVM-IR** → **PTX 文本**（`.ptx`）。下一步经过nv-as就变为了sass指令。

```text
; =============================================================================
;  Triton 最终生成的 PTX 汇编（sm_86，compute=8.6）
;  功能：z[i] = x[i] + y[i]  向量加，长度 = n_elements
;  线程组织：128 线程/CTA（4 warp × 32 thread）
;  每线程处理 8 个 float → 分 2 次 128-bit 向量事务（v4）
;  越界通道用 predicated ld.global.v4 / st.global.v4 屏蔽
; =============================================================================
.version 8.4
.target sm_86
.address_size 64

.visible .entry add_kernel(
	.param .u64 .ptr .global .align 1 add_kernel_param_0,   // x_ptr
	.param .u64 .ptr .global .align 1 add_kernel_param_1,   // y_ptr
	.param .u64 .ptr .global .align 1 add_kernel_param_2,   // out_ptr
	.param .u32 add_kernel_param_3,                         // n_elements
	.param .u64 .ptr .global .align 1 add_kernel_param_4    // scratch（未用）
)
.reqntid 128, 1, 1          // 固定 blockDim.x = 128
{
	.reg .pred 	%p<7>;      // 谓词寄存器（掩码）
	.reg .b32 	%r<33>;     // 通用 32-bit 整数
	.reg .f32 	%f<25>;     // 通用 32-bit 浮点
	.reg .b64 	%rd<11>;    // 通用 64-bit 地址

	// ---------------------------------------------------------------------
	// 0. 调试定位：对应 Python 源文件第 7 行
	// ---------------------------------------------------------------------
	.loc	1 7 0
$L__func_begin0:

// %bb.0:  // 入口基本块
	// ---------------------------------------------------------------------
	// 1. 加载参数
	// ---------------------------------------------------------------------
	ld.param.u64 	%rd7, [add_kernel_param_0];   // x_ptr
	ld.param.u64 	%rd8, [add_kernel_param_1];   // y_ptr
	ld.param.u64 	%rd9, [add_kernel_param_2];   // out_ptr
	ld.param.u32 	%r27, [add_kernel_param_3];   // n_elements

	// ---------------------------------------------------------------------
	// 2. 取硬件内建寄存器
	//     %r25 = blockIdx.x
	//     %r28 = threadIdx.x
	// ---------------------------------------------------------------------
	.loc	1 9 24
	mov.u32 	%r25, %ctaid.x;

	.loc	1 10 24
	shl.b32 	%r26, %r25, 10;          // block_offset = blockIdx.x * 1024

	mov.u32 	%r28, %tid.x;

	// ---------------------------------------------------------------------
	// 3. 计算线程私有元素索引
	//    每线程 8 个元素，按 2 组 v4 存放：
	//      low_idx  = tid*4 + block_offset
	//      high_idx = low_idx + 512
	// ---------------------------------------------------------------------
	shl.b32 	%r29, %r28, 2;           // tid * 4
	and.b32  	%r30, %r29, 508;         // 保留 0-507，对齐 16 字节
	or.b32  	%r31, %r30, %r26;        // low_idx
	or.b32  	%r32, %r31, 512;         // high_idx = low_idx + 512

	// ---------------------------------------------------------------------
	// 4. 生成掩码：判断索引是否越界
	//    %p1 → low_idx  合法？
	//    %p2 → high_idx 合法？
	// ---------------------------------------------------------------------
	.loc	1 12 21
	setp.lt.s32 	%p1, %r31, %r27;
	setp.lt.s32 	%p2, %r32, %r27;

	// ---------------------------------------------------------------------
	// 5. 计算 x 向量地址（低 4 元素 & 高 4 元素）
	// ---------------------------------------------------------------------
	mul.wide.s32 	%rd10, %r31, 4;          // 字节偏移 = idx * sizeof(float)
	add.s64 	%rd1, %rd7, %rd10;       // x_ptr + low_offset
	add.s64 	%rd2, %rd1, 2048;        // x_ptr + high_offset（+512*4）

	// ---------------------------------------------------------------------
	// 6. 带掩码向量加载 x[low..low+3]（128-bit ld.global.v4）
	//    若 %p1 为假，则不产生内存事务，寄存器保持 0
	// ---------------------------------------------------------------------
	.loc	1 13 16
	// 内联 PTX：初始化 4 个输出寄存器为 0
	mov.u32 %r1, 0x0;
	mov.u32 %r2, 0x0;
	mov.u32 %r3, 0x0;
	mov.u32 %r4, 0x0;
	@%p1 ld.global.v4.b32 { %r1, %r2, %r3, %r4 }, [ %rd1 + 0 ];
	// 把 4 个 u32 解释成 float
	mov.b32 	%f1, %r1;   // x0
	mov.b32 	%f2, %r2;   // x1
	mov.b32 	%f3, %r3;   // x2
	mov.b32 	%f4, %r4;   // x3

	// ---------------------------------------------------------------------
	// 7. 加载 x[high..high+3]
	// --------------------------------------------------------------------------
	mov.u32 %r5, 0x0;
	mov.u32 %r6, 0x0;
	mov.u32 %r7, 0x0;
	mov.u32 %r8, 0x0;
	@%p2 ld.global.v4.b32 { %r5, %r6, %r7, %r8 }, [ %rd2 + 0 ];
	mov.b32 	%f5, %r5;   // x4
	mov.b32 	%f6, %r6;   // x5
	mov.b32 	%f7, %r7;   // x6
	mov.b32 	%f8, %r8;   // x7

	// ---------------------------------------------------------------------
	// 8. 同理加载 y 向量（地址基于 y_ptr）
	// ---------------------------------------------------------------------
	add.s64 	%rd3, %rd8, %rd10;       // y_ptr + low_offset
	add.s64 	%rd4, %rd3, 2048;        // y_ptr + high_offset
	// low 4
	mov.u32 %r9, 0x0;
	mov.u32 %r10, 0x0;
	mov.u32 %r11, 0x0;
	mov.u32 %r12, 0x0;
	@%p1 ld.global.v4.b32 { %r9, %r10, %r11, %r12 }, [ %rd3 + 0 ];
	mov.b32 	%f9,  %r9;   // y0
	mov.b32 	%f10, %r10;  // y1
	mov.b32 	%f11, %r11;  // y2
	mov.b32 	%f12, %r12;  // y3
	// high 4
	mov.u32 %r13, 0x0;
	mov.u32 %r14, 0x0;
	mov.u32 %r15, 0x0;
	mov.u32 %r16, 0x0;
	@%p2 ld.global.v4.b32 { %r13, %r14, %r15, %r16 }, [ %rd4 + 0 ];
	mov.b32 	%f13, %r13;  // y4
	mov.b32 	%f14, %r14;  // y5
	mov.b32 	%f15, %r15;  // y6
	mov.b32 	%f16, %r16;  // y7

	// ---------------------------------------------------------------------
	// 9. 逐元素相加（8 次 FADD）
	// ---------------------------------------------------------------------
	.loc	1 15 39
	add.f32 	%f17, %f1,  %f9;   // z0 = x0 + y0
	add.f32 	%f18, %f2,  %f10;  // z1 = x1 + y1
	add.f32 	%f19, %f3,  %f11;  // z2 = x2 + y2
	add.f32 	%f20, %f4,  %f12;  // z3 = x3 + y3
	add.f32 	%f21, %f5,  %f13;  // z4 = x4 + y4
	add.f32 	%f22, %f6,  %f14;  // z5 = x5 + y5
	add.f32 	%f23, %f7,  %f15;  // z6 = x6 + y6
	add.f32 	%f24, %f8,  %f16;  // z7 = x7 + y7

	// ---------------------------------------------------------------------
	// 10. 计算输出地址 & 带掩码向量存储（128-bit st.global.v4）
	// ---------------------------------------------------------------------
	.loc	1 15 35
	add.s64 	%rd5, %rd9, %rd10;       // out_ptr + low_offset
	add.s64 	%rd6, %rd5, 2048;        // out_ptr + high_offset
	// 把 float 重新解释成 u32
	mov.b32 	%r17, %f17;
	mov.b32 	%r18, %f18;
	mov.b32 	%r19, %f19;
	mov.b32 	%r20, %f20;
	// 低 4 元素存储（predicated）
	@%p1 st.global.v4.b32 [ %rd5 + 0 ], { %r17, %r18, %r19, %r20 };
	// 高 4 元素存储
	mov.b32 	%r21, %f21;
	mov.b32 	%r22, %f22;
	mov.b32 	%r23, %f23;
	mov.b32 	%r24, %f24;
	@%p2 st.global.v4.b32 [ %rd6 + 0 ], { %r21, %r22, %r23, %r24 };

	// ---------------------------------------------------------------------
	// 11. 函数返回
	// ---------------------------------------------------------------------
	.loc	1 15 4
	ret;

$L__tmp1:
$L__func_end0:
}
```

; =============================================================================
;  Triton 最终下沉的 SASS 代码（sm_86, 4-warps/CTA, 128-thread）
;  功能：z[i] = x[i] + y[i]  向量加，长度 = n_elements
;  每线程 8 元素 → 2 组 128-bit 向量事务（LDG.E.128 / STG.E.128）
;  越界通道用谓词 @P0 / @P1 屏蔽，无分支
; =============================================================================

        .headerflags    @"EF_CUDA_SM86 EF_CUDA_PTX_SM(EF_CUDA_SM86)"

        /*0000*/                   MOV R1, c[0x0][0x28] ;          // R1 = 内核栈基址（ABI 要求）
        /*0008*/                   S2R R0, SR_TID.X ;              // R0 = threadIdx.x
        /*0010*/                   MOV R15, 0x4 ;                  // R15 = 4（sizeof(float) 常量）
        /*0018*/                   CS2R R16, SRZ ;                 // R16 = 0 （清零，准备接收 x 向量低 4 元）
        /*0020*/                   CS2R R18, SRZ ;                 // R18 = 0
        /*0028*/                   S2R R3, SR_CTAID.X ;            // R3  = blockIdx.x
        /*0030*/                   CS2R R20, SRZ ;                 // R20 = 0 （准备接收 x 向量高 4 元）
        /*0038*/                   CS2R R22, SRZ ;                 // R22 = 0
        /*0040*/                   ULDC.64 UR4, c[0x0][0x118] ;    // UR4 = x_ptr（64-bit 常量缓存加载）
        /*0048*/                   CS2R R4,  SRZ ;                 // R4  = 0 （准备接收 y 向量低 4 元）
        /*0050*/                   CS2R R6,  SRZ ;                 // R6  = 0
        /*0058*/                   CS2R R8,  SRZ ;                 // R8  = 0 （准备接收 y 向量高 4 元）
        /*0060*/                   CS2R R10, SRZ ;                 // R10 = 0

        // ---------------------------------------------------------------------
        // 1. 计算线程私有元素索引
        //    low_idx  = (threadIdx.x & ~3) * 1 + blockIdx.x * 1024
        //    high_idx = low_idx + 512
        // ---------------------------------------------------------------------
        /*0068*/                   SHF.L.U32 R0, R0, 0x2, RZ ;     // R0 = tid >> 2 （ lane_id ）
        /*0070*/                   LOP3.LUT R0, R0, 0x1fc, RZ, 0xc0, !PT ; // R0 = tid*4 & 0x1fc （对齐 16 B）
        /*0078*/                   LEA R0, R3, R0, 0xa ;           // R0 = block_offset + lane_offset = low_idx
        /*0080*/                   ISETP.GE.AND P0, PT, R0, c[0x0][0x178], PT ; // P0 = low_idx >= n_elements ?

        /*0088*/                   IMAD.WIDE R12, R0, R15, c[0x0][0x168] ; // R12 = x_ptr + low_idx*4 （64-bit 地址）
        /*0090*/                   IADD3 R2, R0, 0x200, RZ ;       // R2 = low_idx + 512 = high_idx
        /*0098*/                   ISETP.GE.AND P1, PT, R2, c[0x0][0x178], PT ; // P1 = high_idx >= n_elements ?
        /*00a0*/                   IMAD.WIDE R2, R0, R15, c[0x0][0x160] ; // R2 = y_ptr + low_idx*4 （64-bit）

        // ---------------------------------------------------------------------
        // 2. 加载 x[low..low+3]  （128-bit 向量，谓词 @!P0）
        //    若 P0 为真（越界），则跳过加载，寄存器保持 0
        // ---------------------------------------------------------------------
        /*00a8*/              @!P0 LDG.E.128 R16, [R12.64] ;        // R16-R19 = x0-x3
        /*00b0*/              @!P0 LDG.E.128 R20, [R12.64+0x800] ;  // R20-R23 = x4-x7 （high 组）

        // ---------------------------------------------------------------------
        // 3. 加载 y[low..low+3] / y[high..high+3]  （地址基于 R2）
        // ---------------------------------------------------------------------
        /*00b8*/              @!P0 LDG.E.128 R4,  [R2.64] ;         // R4-R7   = y0-y3
        /*00c0*/              @!P1 LDG.E.128 R8,  [R2.64+0x800] ;   // R8-R11  = y4-y7 （P1 控制 high）

        // ---------------------------------------------------------------------
        // 4. 计算输出地址：out_ptr + offset
        // ---------------------------------------------------------------------
        /*00c8*/                   IMAD.WIDE R14, R0, R15, c[0x0][0x170] ; // R14 = out_ptr + low_idx*4

        // ---------------------------------------------------------------------
        // 5. 逐元素相加（8 次 FADD，并行在 4 个 warp 上）
        // ---------------------------------------------------------------------
        /*00d0*/                   FADD R16, R20, R16 ;   // z0 = x0 + y0
        /*00d8*/                   FADD R17, R21, R17 ;   // z1 = x1 + y1
        /*00e0*/                   FADD R18, R22, R18 ;   // z2 = x2 + y2
        /*00e8*/                   FADD R19, R23, R19 ;   // z3 = x3 + y3

        /*0108*/                   FADD R7, R11, R7 ;     // z7 = x7 + y7

        /*0110*/              @!P0 STG.E.128 [R14.64], R16 ;        // store z0-z3
