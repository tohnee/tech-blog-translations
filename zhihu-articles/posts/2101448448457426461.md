## 前言

先说结论：

这本书不是又一本“从入门到精通”。

它只回答一个问题：

**你写的 Agent，怎么从能跑，变成能扛住真实业务。**

如果你：

- 会调 OpenAI / DeepSeek API，但一上复杂任务就崩
- 被 RAG 检索质量、上下文爆炸、工具调用死循环折磨过
- 想在企业里落地 Agent，但不知道怎么设计权限、审计、恢复、降级
- 有后端、前端、全栈、平台或算法数据背景，想系统补齐 Agent 工程能力

那这本书，大概率能帮你少走一些自己摸索的弯路。

## 为什么写这本书

市面上讲 Agent 的内容大致分两类：

一类是概念科普：什么是 Agent、什么是 RAG、什么是 MCP。<br>读的时候很爽，合上书还是不会写。

另一类是平台教程：教你拖拽 Dify、Coze。<br>跟着做能出 Demo，但换个场景就废，工具一升级书就过期。

我想把 Agent 当成一个正经的软件工程问题来对待。

所以这本书：

- 不堆概念，每章都有可运行代码
- 不讲“能跑就行”，讲怎么让它稳定、可控、可维护、可审计
- 不把离线测试通过写成生产验证，边界写清楚
- 不是 29 个散落 Demo，而是一套逐步长出来的系统

## 【它和市面上的 Agent 书有什么不同】

**1. 它写的是一套系统，不是 29 个互不相干的 Demo。**

全书围绕一套可运行的 Agent 工程系统展开：

模型接入 → 工具调用运行时 → 长任务执行 → 上下文与 RAG → MultiAgent 与评测 → 生产化

每一层都有代码、失败模式和验证命令。

**2. 默认离线可跑，不需要 API Key。**

核心示例使用确定性的 `FakeLLM`，不依赖外部服务、不产生费用、测试可重复。想接真实模型时，再换成 OpenAI 兼容接口。

**3. 不把“能跑”写成“生产可用”。**

书里明确写清边界：哪些是本地验证，哪些需要真实模型验证，哪些只是工程判断。

**4. 关键行为有自动化验证，不是只跑通一个 Demo。**

- 252 个关键行为都有自动化验证：路由、重试、权限、状态恢复、RAG、评测等
- 真实 DeepSeek 端到端联调：对话、流式、工具调用、结构化输出、Agent Loop
- 33 个真实浏览器操作场景已验收：8 个界面、审批恢复、筛选、主题、打印
- Docker Compose 完整启动验证
- 每章都有“本章目标 / 对应代码 / 验证命令 / 踩坑与边界 / 练习”

## 工程质量怎么保证

- 252 个关键行为都有自动化验证，覆盖路由、权限、状态恢复、RAG、评测等
- 真实 DeepSeek 端到端联调：对话、流式、工具调用、结构化输出、多步任务循环
- 33 个真实浏览器操作场景已验收：8 个界面、审批恢复、筛选、主题、打印
- Docker Compose 完整启动验证

- 默认 `FakeLLM` 离线运行，不需要 Key，不产生费用

离线验证和真实联调，解决的是两个问题。

离线验证用 `FakeLLM` 锁住工程逻辑，可重复、不烧 token；真实模型联调只负责证明接口和端到端链路能通。两者分工不同：一个保证工程逻辑可重复，一个保证真实接口能通。
