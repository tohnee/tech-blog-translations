## 「从零到 AI 应用工程师」专栏 · 第 22 篇

---

查表解决「码是什么」；处置步骤仍在手册里——那是 RAG 的活。<br>Agent 不要自己解析 PDF，只做一件事：`httpx` 调冻结契约 `POST /rag/query`。

---

### 一、契约边界（必须遵守）

- 路径、字段以公开的 RAG API 说明为准（版本冻结）；<br>
- Agent **读知识库**走问答接口；<br>
- `answer_source=refusal` 是业务结果，不是 HTTP 失败。

```python
def rag_query(question: str, filter_category: str | None = None) -> dict:
    resp = httpx.post(f"{RAG_BASE_URL}/rag/query", json={
        "question": question[:500],
        "filter_category": filter_category,
        "top_n": 5,
    }, timeout=60)
    data = resp.json()["data"]
    # 归一成 Tool 结果：branch / citations / answer / error
```

---

### 二、分支怎么切

| answer_source / 情况 | Agent 分支 |
| --- | --- |
| 有 citations / llm·fallback | grounded：可采用答案与出处 |
| refusal | refusal：不编造根因 |
| 网络失败 / 非 200 | error：可重试或降级 |
| llm_error | 有限重试，勿死循环 |

离线开发可设 `RAG_MOCK=1`：本地返回假 citation / 拒答，专门验分支。

---

### 三、挂进图

```text
… → lookup → rag → END
```

`rag` 节点用查表得到的 `meaning` 拼问题，例如：`E001单体过压怎么处理`，并映射分类到 `filter_category`。

状态增加：`rag_branch`、`rag_answer`、`rag_citations`。

---

### 四、带走这三条

1. **RAG 是 HTTP Tool，契约冻结，Agent 不重写检索。**<br>
2. **拒答要当合法分支，禁止当异常重试风暴。**<br>
3. **MOCK 验编排，真服务验 citation。**
