**本篇要点**

· 闭卷 vs 开卷：同一个问题、同一个模型，答案为什么差这么远

· RAG 的四个动作：切块 → 检索 → 拼提示词 → 带引用作答

· 跑一遍：一个几十行的迷你 RAG，仍然只用标准库

· 关键不是"它变聪明了"，而是"它说的话能指回哪一段"

第 4 篇结束时，你已经能做一件事：拿一句话去搜，把意思最接近的段落找出来。可光"找出来"没用——你要的是答案。

第 1 篇说得很清楚：模型每一步都在猜下一个 token，它的答案来自训练时吃进去的海量文本，而不是你手边这几篇文献。第 2 篇你也亲眼看过它答偏——你问锂硫正极的核心问题，它答的是"硫的自放电现象"。

它答得流畅、格式也对，就是不准。更要命的是：你没法核对。

这一篇要做的事，一句话说得完： **别让它凭记忆答题，让它开卷。** 把第 4 篇检索到的段落，连同问题一起塞给它，并且要它说出用了哪一段。

**一、它答不准，是因为它在"闭卷"**

把大模型想成一个刚下考场的人。你问他一个很细的问题，他答得头头是道，遣词造句都很漂亮——但你没法知道他这句答案到底是从哪本书第几页背下来的。他可能真记得，也可能只是把几个像样的词拼在了一起。

这就是"闭卷"。模型把整个互联网读成了参数，考试时只带脑子、不带书。像"锂硫电池正极的问题"这种问题，它在训练数据里见过太多相关讨论，于是能接出一段很顺的话——但那段话概括了什么、漏掉了什么、有没有记错，你无从判断。

搞科研最怕的就是这个： **一个看起来很合理的结论，背后没有一处可以对得上的出处。** 你把它写进综述，等着被审稿人翻出来。

**二、RAG 的四个动作**

办法叫 **RAG** （Retrieval-Augmented Generation，检索增强生成）。名字唬人，拆开只有四步，而且其中两步你前三篇已经做完了：

· **切块** ：把文献切成一段一段。（真实流程是"一篇 PDF 切成几十块"，第 7 篇专门讲；这一篇先用手写好的三块）

· **检索** ：把问题变成向量，和每一块比，从高到低排出名次。（第 4 篇已经做过）

· **拼提示词** ：取最像的一两块，连同问题一起写进同一个提示词里。

· **带引用作答** ：要它只能照这些材料说，并且说出用了哪个编号。

前两步是"找料"，后两步是"答题"。这一篇的重点在后两步——尤其是最后那一步。因为 **"说出用了哪一段"才是一切的转折点** ，下面你会亲眼看到。

**三、跑一遍：一个几十行的迷你 RAG**

新建 **rag.py** ，放进 agent-lab。这段代码里， `embed` 、 `cosine` 、 `ask` 三个函数你在第 1、4 篇都见过，这里一字未改，直接复用：

```text
# 三个都是 Python 自带库，不用装新东西；三个函数在第 1、4 篇都已经出现过
import json            # 打包要发出去的内容、解析收回来的内容
import math            # 算平方根，下面比"像不像"要用
import urllib.request  # 负责把网络请求发出去
# 第 4 篇原样搬来：一段文字进去，768 个数字出来
def embed(text):
    data = json.dumps({"model": "nomic-embed-text", "prompt": text}).encode("utf-8")
    req = urllib.request.Request(
        "http://localhost:11434/api/embeddings", # Ollama 的"生成向量"接口
        data=data,
        headers={"Content-Type": "application/json"},
    )
    with urllib.request.urlopen(req) as resp:
        return json.load(resp)["embedding"]
# 第 4 篇原样搬来：两个向量有多像，结果落在 0~1，越大越像
def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    return dot / (na * nb)
# 第 1 篇原样搬来：把一段提示词交给本机模型，温度写死 0（要能复现）
def ask(prompt):
    data = json.dumps({
        "model": "deepseek-r1:7b",        # 负责作答的模型
        "prompt": prompt,                # 要问的那段话（这次不只是问题，还带着材料）
        "stream": False,               # False = 等它全部写完，一次性给我
        "options": {"temperature": 0},  # 抽数据要稳定，不留余地
    }).encode("utf-8")
    req = urllib.request.Request(
        "http://localhost:11434/api/generate", # Ollama 的"生成文字"接口
        data=data,
        headers={"Content-Type": "application/json"},
    )
    with urllib.request.urlopen(req) as resp:
        return json.load(resp)["response"]
# —— 第一步：切块 ——
# 真实流程是"一篇 PDF 切成几十块"（第 7 篇）；这里先假装已经切好，手写三块，
# 每块给一个编号——这个编号，就是以后要引用的"出处"
chunks = {
    "C1": "Sulfur cathodes suffer from the polysulfide shuttle effect: soluble lithium polysulfide intermediates dissolve in the electrolyte and migrate back and forth between the electrodes, causing irreversible loss of active material.",
    "C2": "The polysulfide shuttle leads to rapid capacity fade, low Coulombic efficiency and severe self-discharge in lithium-sulfur batteries.",
    "C3": "Common mitigation strategies include confining sulfur in conductive host materials, engineering functional separators, and optimizing the electrolyte composition.",
}
question = "Why does the capacity of lithium-sulfur batteries fade?"
# —— 对照组：闭卷 ——
# 只把问题丢给它，不给任何材料，看看它凭"记忆"怎么答
print("=== 闭卷：只把问题丢给它 ===")
print(ask("用中文两三句话回答：" + question))
# —— 第二步：检索 ——
# 把问题、每一块都变成向量，比一比谁最像问题，从高到低排队
print()
print("=== 开卷：先检索，再把材料一起给它 ===")
vecs = {name: embed(text) for name, text in chunks.items()}  # 每块只算一次，别重复算
qv = embed(question)
ranked = sorted(vecs, key=lambda n: cosine(qv, vecs[n]), reverse=True)  # 分数从高到低
for n in ranked:
    print(n, round(cosine(qv, vecs[n]), 4))  # 打印名次与分数
# —— 第三、四步：拼提示词、带引用作答 ——
# 取最像的两块，连同问题拼成一段提示词；并明确要求"只能照材料说、要写出依据编号"
context = "\n".join(f"[{n}] {chunks[n]}" for n in ranked[:2])
prompt = (
    "只根据下面的材料回答问题；材料里没有的，就答“材料里没有”。"
    "请先用中文两三句话说明原因，最后单独一行写出依据的编号。\n\n"
    f"材料：\n{context}\n\n问题：{question}"
)
print()
print(ask(prompt))
```

运行：

python rag.py

**四、看结果：同一个问题，同一个模型**

先看 **闭卷** 那段——只把问题丢给它：

![](https://pic1.zhimg.com/v2-9dd777ddecdc722161a68c80349211f2_1440w.jpg)

读起来挺像回事。"硫活性成分逐渐被消耗"不能算错；但"温度、电池设计、存储环境"这一串，是从哪来的？你手上那几篇文献里，找不到任何一处这么说。它不是抄错了，是 **凭印象凑了一段** 。

再看 **开卷** 那段——先把三块材料排个名次，再把最像的两块拼进提示词：

![](https://pic2.zhimg.com/v2-e539a3adcbb43c157736452c5b869b23_1440w.jpg)

三行分数先说明"检索"是有效的——

· **C2 0.8004** ：排第一。它直接写着"多硫化物穿梭导致容量快速衰减"，正是问题在问的那件事。

· **C1 0.7215** ：紧跟其后。它讲的是同一条机制的上游——多硫化物溶解、来回迁移，造成活性物质不可逆损失。

· **C3 0.5947** ：明显掉下来。它讲的是"怎么改善"（包覆、隔膜、电解液），跟"为什么会衰减"不是同一件事。

于是开卷的答案变了：它不再说"温度、存储环境"，而是照着 C2 说出了 **多硫化物穿梭导致容量快速衰减** ，末了还留下一句"依据的编号：[C2]"。同一个模型、同一个温度、同一个问题。变的只有一件事： **你把材料递给了它。**

**五、真正的转折点，是那句"依据的编号"**

对比这两段答案，多数人会盯着"哪个更准"。但对我们搭智能体来说，差别的重心不在准不准，而在 **能不能核对** ：

· 闭卷那段：说得像模像样，却没有出处。它可能对，可能错，你 **没办法知道** ——只能选择信或不信。

· 开卷那段：末了写着"依据 [C2]"。你手上就有 C2 那段话，一条一条对过去——对得上，就用；对不上，就是它读错了，你当场能发现。

注意：RAG 并没有让它变聪明。用的还是那个 7b 的小模型，温度还是 0。它只是把"一个没法核对的答案"，变成了 **一个可以核对的答案** 。这一篇你要带走的，就是这句。

顺手说一句实话：开卷也不保准。这个模型在别的几次实跑里，把原文的 `cathodes` 说成了"硫负极"——材料里明明写的是正极。措辞也时常毛糙。但这正是出处的价值： **它错在哪，你能查出来。** 一个能被查错的答案，比一个漂亮但没法查的答案，可靠得多——这也是第 3 篇那张数据契约要的理由。

**六、这一步做到了什么，还差什么**

· **做到了** ：模型的答案第一次有了可以核对的出处。

· **还差三块** ：材料还是手写的三段（第 7 篇从 PDF 真切）；检索踩坑时答案照错（第 4 篇说的跨语言问题）；出处目前只是个编号，还没和原始文献的页码、原句绑死。

· **先别急着补** ：把这几块补齐、让整条链路能复现、能审计，就是"生产级的最后一公里"，第 9 篇和课程里讲。

到这里，你已经把智能体最核心的一环—— **"从文献里找到证据，再照着证据说话"** ——亲手跑通了一遍。接下来还缺两样：让模型会自己决定"什么时候该去查、该算什么"；以及真正把 PDF 变成带出处的文本块。
