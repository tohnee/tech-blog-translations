> **MCP = Model Context Protocol** （模型上下文协议），Anthropic 推出的通用标准，作用是给大模型统一一套「连接外部网页/API/数据库」的标准化通道，替代零散、各自适配的Function Calling。

### 三层核心架构

1. Host：AI 客户端（Claude Desktop、Cursor 编辑器、IDE AI 助手），内置大模型；
2. MCP Client：协议连接器，读取 mcp.json配置；
3. MCP Server：中转服务，负责访问目标网站/API、携带Token鉴权、把网页数据结构化返回给模型。

### JSON 里写 URL、Token 分别是干嘛的呢？

### 1. url字段：告诉 MCP 去哪里建立远程通道

JSON 中的”url”:“ [http://shturl.cc/GJ0hr2gbw](http://shturl.cc/GJ0hr2gbw) ” 是远程 MCP 服务地址：

• 这个地址不是目标业务网站，是封装了网页爬取/API请求能力的 MCP服务端；

• MCP Client 通过 HTTP/WebSocket 连接这个 MCP Server，建立长连接；

• Server 内部才会转发请求到你真正要访问的业务网站。

最简 JSON 配置示例：

```text
{
  "mcpServers": {
    "web-api": {
      "url": "https://api.xxx-mcp.com",
      "env": {
        "API_TOKEN": "你的网站个人token"
      }
    }
  }
}
```

### 2. env 里的 Token：鉴权凭证，用于网站校验访问权限

绝大多数网页/开放API 不是公开可读，必须携带身份凭证才能拉取私有数据：

• Token 是网站分配给你的唯一身份标识（GitHub Token、云服务 API Key、后台接口鉴权令牌）；

• JSON 的env 环境变量会被 MCP Client 传递给 MCP Server；

• Server 发起HTTP请求访问目标网站时，自动把Token塞进请求头：Authorization: Bearer {token}；

• 网站后端校验Token合法，才返回私有数据，拒绝无 Token 的匿名访问。

### 补充区分两个容易混淆的 URL

1. JSON 配置里的url：MCP 中间服务地址（协议网关）；
2. 工具调用参数里的target_url：真正要爬取的业务网站地址（GitHub、个人后台、网页链接）。

### 完整执行流程（从配置生效到模型拿到网页内容）

`步骤1：Host 加载 mcp.json配置，启动 MCP Client`

打开AI工具时，程序自动读取本地 mcp.json，解析每一组 url 和配套 Token，为每个远程 MCP 服务创建独立 Client 连接实例。

`步骤2：Client 和 MCP Server握手，自动上报鉴权 Token`

1. Client 携带 env 内的 Token 发起 initialize 握手；
2. 远程 MCP Server 校验 Token 合法性，协商协议版本；
3. Server 主动上报自己拥有的能力：比如 web_fetch（抓取网页）、api_query（调用接口），把工具描述传给大模型。

大模型此时知道自己可以调用“访问网页”这个工具，工具参数、用途全部标准化。

`步骤3：用户提问 → 大模型判断需要访问外部网站`

比如问“读取我 GitHub 仓库最新 issue”，模型识别本地知识没有实时数据，生成标准 MCP工具调用指令：

```text
{
  "tool": "web_fetch",
  "params": {"target_url":"https://github.com/api/issues"}
}
```

` 步骤4：Client 转发调用指令给 MCP Server，Server 携带Token访问目标网站`

1. MCP Server 收到抓取指令；
2. 发起 HTTP 请求访问目标业务网站，请求头自动带上你配置的个人 Token；
3. 网站校验 Token，返回网页/接口原始数据（HTML、JSON）。

`步骤5：Server清洗网页数据，结构化回传给大模型`

网页原始 HTML 杂乱，MCP Server 会做清洗：剔除广告、脚本，提取正文、表格、接口返回字段，压缩成简洁文本，沿MCP通道原路返回给Host里的大模型。

`步骤6：大模型结合网页实时数据，生成最终回答`

模型把自身知识库 + 刚拉取的外部网页上下文融合，输出带实时外部信息的答案。

### 核心底层原理拆解（为什么只填 URL + Token 就能打通）

`JSON 配置本质：统一的“路由+凭证”注册表`

url = 网络路由地址：定义 MCP 中间服务的接入点，统一所有外部资源的访问入口，不用为每个网站单独写代码适配；

Token = 身份凭证注入：通过环境变量隔离密钥，不会直接暴露给大模型，仅在 MCP 服务中转层使用，兼顾易用和基础安全。

`MCP 协议标准化，屏蔽网络、鉴权细节`

传统 Function Calling 需要开发者手动写 HTTP 请求、拼接鉴权头、处理跨域、解析返回值；

MCP 把这套逻辑封装在 MCP Server 内部，只需要填地址和密钥，协议自动处理： • 连接握手、重连、超时； • Token 注入请求头； • 网页内容清洗、结构化； • 双向消息传输。

安全关键设计： • 大模型 Host 本身不能直接访问互联网； • 所有网页请求必须经过独立的 MCP Server 中转； • Token 只存在 Client→Server 的传输链路，不会传入 LLM 上下文，避免密钥泄露。

`一个形象的类比`

• MCP = AI的万能USB拓展坞

• JSON里的url = 拓展坞的网线接口地址；

• Token = 登录网站的账号密码；

• MCP Server = 拓展坞内部的芯片，负责转发网络请求、携带你的身份登录网页；

• 大模型 = 电脑主机，只需要通过拓展坞，就能稳定读取外网私有数据，不用自己装网卡、输账号。
