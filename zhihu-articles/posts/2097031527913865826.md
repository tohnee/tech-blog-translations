> 目标：把「模型好不好」变成可判定、可复现、能指导决策的数字。 本层的核心矛盾：评估本身是另一个需要被评估的模型。

### 1. 评估层的五个职责

| 职责 | 输出 | 失败后果 |
| --- | --- | --- |
| 指标定义 | 可计算的量化指标 | 结论无法验证 |
| 评测集构建 | 冻结的、带明确分布的样本集 | 结果虚高 |
| 评估执行 | 可复现的评估报告 | 数字不可信 |
| 统计检验 | 置信区间与显著性 | 把噪声当信号 |
| 在线实验 | 真实流量上的因果结论 | 上线决策靠猜 |

### 2. 指标

### 2.1 指标必须满足三个条件

1. 与业务目标有明确映射。
2. 可计算，定义无歧义。
3. 在固定评测集上可复现。

违反任意一条，指标不可用。

### 2.2 分类任务的四个基本指标

基于混淆矩阵：真正例 TP、假正例 FP、真负例 TN、假负例 FN。

$$ \text{Precision} = \frac{TP}{TP + FP} $$

$$ \text{Recall} = \frac{TP}{TP + FN} $$

$$ \text{F1} = 2 \cdot \frac{P \cdot R}{P + R} $$

$$ \text{AUC} = \int_0^1 \text{TPR}(t)\, d\,\text{FPR}(t) $$

推论：AUC 衡量排序能力，与阈值选择无关。选阈值时用 Precision-Recall 曲线。

### 2.3 类别不平衡下的选择

| 场景 | 正样本比例 | 建议主指标 |
| --- | --- | --- |
| 均衡 | 接近 1:1 | Accuracy 或 F1 |
| 轻度不平衡 | 低于 1:10 | F1 或 AUPRC |
| 严重不平衡 | 低于 1:1000 | AUPRC |
| 极不平衡 | 低于 1:100000 | Recall 在固定 Precision 下 |

AUPRC 的计算：

$$ \text{AUPRC} = \int_0^1 \text{Precision}(r)\, dr $$

推论：不平衡场景下 AUROC 会给出过于乐观的结论。AUPRC 才是有效指标。

### 2.4 生成任务的指标局限

| 指标 | 计算方式 | 局限 |
| --- | --- | --- |
| BLEU | n-gram 精确率的几何平均 | 与人类判断相关性约 0.2 到 0.4 |
| ROUGE | 召回率为基础的 n-gram 重叠 | 忽略语义等价 |
| 困惑度 PPL | 指数化交叉熵 | 高 PPL 不代表回答差 |
| 语义相似度 | 嵌入向量余弦 | 词面相近但事实错误 |

结论：BLEU、ROUGE、PPL 只能作为参考指标。不能作为唯一质量指标。

### 2.5 代码任务必须用可验证指标

代码可执行验证，因此有客观指标。

| 指标 | 说明 |
| --- | --- |
| Pass@k | 生成 k 个候选，至少一个通过的采样估计 |
| 编译通过率 | 代码能否编译 |
| 测试用例通过率 | 功能正确性 |

### 2.6 每个指标的失效边界

指标本身也有失效区间。不知道边界会误判。

| 指标 | 失效场景 | 表现 | 对策 |
| --- | --- | --- | --- |
| Accuracy | 类别极不平衡 | 全部预测多数类也高分 | 换 AUPRC |
| F1 | 正负样本极少 | 方差极大 | 增加样本量或用 F_beta |
| AUC | 预测分数有并列 | 排序不可区分 | 加细分或换指标 |
| AUPRC | 正样本为 0 | 无定义 | 检查数据 |
| BLEU | 参考答案有多解 | 低分但答案正确 | 换语义指标或 LLM 判官 |
| ROUGE | 长文本 | 摘要内容好但召回低 | 换覆盖率指标 |
| PPL | 跨模型比较 | 不可比 | 只在同分词器下比较 |
| NDCG | 点击位置数据缺失 | 无法计算 | 补采集或用代理指标 |
| MAE | 有极端离群点 | 被拉高 | 换分位数损失或 MAPE |
| MAPE | 真实值为 0 | 除零发散 | 改用 sMAPE 或 MAE |

| 指标 | 合理取值范围 | 异常信号 |
| --- | --- | --- |
| AUC | 0.5 到 1.0 | 低于 0.5 说明标签反了 |
| F1 | 0 到 1 | 高于 Precision 与 Recall 是错误 |
| PPL | 大于 1 | 小于 1 说明计算错误 |
| NDCG | 0 到 1 | 超过 1 说明有重复计数 |
| MAE | 大于等于 0 | 小于 0 说明公式用错 |
| pass@k | 0 到 1 | 高于 1 说明重复计数 |

推论：所有指标都有硬边界。指标越界几乎总是计算错误，而不是模型表现好。

### 2.7 指标的最小可信样本量

指标有采样误差。样本太少时差异没有意义。

| 场景 | 最小样本量 | 说明 |
| --- | --- | --- |
| 二分类指标 | 1000 | 正负各 500 |
| AUPRC 稳定估计 | 5000 | 稀有正类需更多 |
| 生成任务人工评测 | 300 | 满足统计显著性 |
| LLM 判官对比 | 500 | 低于此噪声过大 |
| 线上 A/B 实验 | 每组 10000 | 取决于基线与 MDE |

推论：指标差异小于置信区间时，等同于没有差异。不要为噪声调优。

### 3. 代码生成的 Pass@k 无偏估计

HumanEval 的常见做法是在 n 个样本上采 k 个，直接统计成功比例。这是有偏的。正确做法是用无偏估计。

原始估计量：

$$ \hat{p}_{pass@k} = \mathbb{E}_{C} \left[ 1 - \binom{n - C}{k} \bigg/ \binom{n}{k} \right] $$

变量含义：$C$ 为 n 个样本中通过的数量，$n$ 为采样总数，$k$ 为一次提交的数量。

无偏估计量：

$$ \text{pass@k} = \mathbb{E}_{C} \left[ 1 - \frac{\binom{n - C}{k}}{\binom{n}{k}} \right] $$

```python
import numpy as np
from scipy.stats import hypergeom

def pass_at_k(n_samples, n_correct, k):
    """无偏估计 pass@k。n 为采样数，n_correct 为通过数。"""
    if n_correct == 0:
        return 0.0
    if n_correct == n_samples:
        return 1.0
    if k > n_correct:
        return 1.0
    # 1 - (n_correct 以外的全不通过组合数 / 总组合数)
    return 1.0 - hypergeom(n_samples, n_correct, k).pmf(0)
```

变量含义：$n$ 为采样数，$n$ 为通过的样本数，$k$ 为一次提交的候选数。

推论：采样数 n 越大，pass@k 的置信区间越窄。实践中至少采 20 到 200 个样本。

### 4. 评测集构建

### 4.1 评测集的五个要求

| 要求 | 说明 |
| --- | --- |
| 分布代表性 | 反映真实流量的分布 |
| 难度分层 | 覆盖简单到困难 |
| 覆盖边界情况 | 长尾、异常、跨域 |
| 冻结 | 发布后不改，除非明确版本升级 |
| 去污染 | 与训练集无重叠 |

### 4.2 难度分层

| 分层 | 占比参考 | 用途 |
| --- | --- | --- |
| 简单 | 40% | 保证基础可用 |
| 中等 | 40% | 区分模型差异 |
| 困难 | 15% | 拉开上限 |
| 边界 | 5% | 防止崩溃 |

推论：只测简单样本会让所有模型分数都很高，失去区分能力。

### 4.3 评测集的构建来源

| 来源 | 优点 | 风险 |
| --- | --- | --- |
| 线上采样 | 分布真实 | 有偏，缺少失败样本 |
| 人工构造 | 可控，可设计边界 | 分布可能不真实 |
| 专家编写 | 覆盖疑难 | 成本高 |
| 线上采样加人工加权 | 兼顾 | 需要严格控制权重 |

### 4.3.1 评测集内部的重复必须去除

评测集自身重复会同时放大真实能力与噪声。

| 重复类型 | 后果 | 处理 |
| --- | --- | --- |
| 完全重复 | 指标权重偏斜 | 精确哈希去重 |
| 近似重复 | 有效样本量虚高 | SimHash 去重 |
| 同源改写 | 答案泄漏 | 语义相似度去重 |
| 同模板不同参数 | 只测一种能力 | 按模板聚类，每类抽样 |

```python
import numpy as np

def dedup_eval_set(texts, embed_fn, thresholds=(0.99, 0.95, 0.90)):
    """按精确、近似、语义三级去重评测集。"""
    # 第一级：精确去重
    seen, stage1 = set(), []
    for t in texts:
        key = t.strip()
        if key and key not in seen:
            seen.add(key)
            stage1.append(t)

    # 第二级：语义去重
    embeddings = embed_fn(stage1)
    norm = embeddings / (np.linalg.norm(embeddings, axis=1, keepdims=True) + 1e-8)
    sim = norm @ norm.T

    keep = [0]
    for i in range(1, len(stage1)):
        # 与已保留样本的最大相似度
        if sim[i, keep].max() < min(thresholds):
            keep.append(i)

    return [stage1[i] for i in keep]
```

推论：保留每组重复样本中的第一条，会引入位置偏差。应随机保留，或保留难度最高的那条。

### 4.3.2 评测集容量的确定方法

容量由误差容忍度与置信水平共同决定。

| 目标 | 样本量 | 说明 |
| --- | --- | --- |
| 指标误差小于 2% | 约 2500 | 95% 置信，单次比例估计 |
| 指标误差小于 1% | 约 10000 | 95% 置信 |
| 检测 3 个点的差异 | 约 20000 | 需要 MDE 估算 |
| 对比两个模型的胜负 | 约 1000 | 配对检验，可显著降低 |

比例估计的标准误：

$$ \text{SE} = \sqrt{\frac{p(1-p)}{n}} $$

变量含义：$p$ 为该比例的点估计，$n$ 为样本量。

推论：配对检验能用更小样本量达到同等功效。同一批样本评估两个模型，消除了样本难度差异。

### 4.3.3 评测集的四种泄漏来源

| 泄漏来源 | 机制 | 检测方法 |
| --- | --- | --- |
| 训练集泄漏 | 评测样本在训练集中 | n-gram 与 MinHash 比对 |
| 提示泄漏 | 答案在系统提示或示例中 | 检查提示模板 |
| 同源泄漏 | 训练与评测来自同一来源文档 | 按来源分组去重 |
| 参考答案泄漏 | 答案是训练文本的片段 | MinHash 比对答案 |

```python
def check_source_leakage(train_meta, eval_meta, key="source_url"):
    """检测训练与评测是否来自同一源文档。"""
    train_sources = set(train_meta[key].dropna())
    eval_sources = set(eval_meta[key].dropna())
    shared = train_sources & eval_sources

    return {
        "leaked": len(shared),
        "leak_rate": len(shared) / max(1, len(eval_sources)),
        "sample": list(shared)[:10],
    }
```

推论：同源泄漏比 n-gram 泄漏更隐蔽。表述不同但答案相同，n-gram 检不出。

### 4.4 评测集的污染问题

污染指训练数据中包含了评测样本。污染使评测结果虚高。

### 4.4.1 13-gram 重叠检测

对文本语料做 n-gram 集合，交集非空即判定为污染。

```python
from collections import Counter

def ngrams(text, n=13):
    """提取 n-gram 集合。"""
    tokens = text.split()
    return {
        tuple(tokens[i:i + n]) for i in range(len(tokens) - n + 1)
    }

def detect_contamination(train_texts, eval_texts, n=13):
    """检测训练集与评测集的 n-gram 重叠。"""
    train_grams = set()
    for t in train_texts:
        train_grams |= ngrams(t, n)

    contaminated = []
    for t in eval_texts:
        if ngrams(t, n) & train_grams:
            contaminated.append(t)

    return contaminated
```

### 4.4.2 MinHash

13-gram 方法在语料很大时开销高。MinHash 用随机哈希做近似集合比较。

思路：用 64 个哈希函数把集合压缩成 64 维指纹。两集合指纹相近则判定为重叠。

优点：计算量从 O(N × L) 降到 O(文档数 × 64)。

### 4.4.3 去污染流程

1. 用 MinHash 建评测集指纹。
2. 训练数据入库时做指纹匹配。
3. 命中则标记为可疑，人工复核。
4. 复核确认的样本从训练集中排除。
5. 记录污染率，纳入数据质量报告。

### 4.4.4 去污染的边界条件

| 场景 | 问题 | 正确做法 |
| --- | --- | --- |
| 通用知识重叠 | 常见代码模板必然重叠 | 对代码评测集改用语义去重 |
| 数学公式重叠 | 公式片段高度重复 | 用答案级比对，不用 n-gram |
| 多语言评测 | n-gram 跨语言无效 | 分别建索引 |
| 评测集本身较小 | 污染比例高 | 构造评测集时预留干净来源 |
| 已训练模型 | 无法回溯清洗 | 声明污染等级，谨慎解读分数 |

污染等级：

| 等级 | 污染率 | 分数可信度 |
| --- | --- | --- |
| 无 | 0% | 完全可信 |
| 低 | 低于 1% | 基本可信 |
| 中 | 1% 到 5% | 需打折解读 |
| 高 | 高于 5% | 不可信 |

### 5. LLM-as-a-Judge

### 5.1 用 LLM 做判官的优势与限制

| 项 | 状况 |
| --- | --- |
| 与人类判断的相关性 | 0.7 到 0.85 |
| 成本 | 比人工标注低一到两个数量级 |
| 速度 | 比人工快 100 倍以上 |
| 位置偏差 | 存在。倾向选第二个位置 |
| 长度偏差 | 存在。倾向选更长的回答 |
| 自我偏好 | 存在。倾向选同族模型的输出 |

### 5.2 三种偏置的定义与缓解

**位置偏差**：交换两个回答的位置，判断结果发生变化。

缓解方法：

1. 交换位置各判一次，两次结果不一致则判为平局。
2. 多次判取多数。
3. 随机化位置。

**长度偏差**：更长的回答得分更高。

缓解方法：

1. 在提示中明确要求忽略长度。
2. 对长度做归一化处理。
3. 在评估集中平衡长度分布。

**自我偏好**：判官偏好同族模型的输出。

缓解方法：

1. 换用不同厂商的判官模型交叉验证。
2. 混入人工标注作为金标准。
3. 定期校准。

### 5.3 判官校准

```python
def judge_with_calibration(
    judge_llm, pairs, human_labels,
    n_votes=3, calibrate=True,
):
    """判官评估 + 与人工标注校准。"""
    results = []

    for pair in pairs:
        # 消除位置偏差：正反各判一次
        votes = []
        for _ in range(n_votes):
            first = judge_llm(
                prompt=A_template(pair["answer_a"], pair["question"])
            )
            second = judge_llm(
                prompt=A_template(pair["answer_b"], pair["question"])
            )
            # 交换位置后判断，若不一致判平局
            if first == second:
                votes.append(first)
            else:
                votes.append("tie")
        results.append(majority(votes))

    # 校准：与人工标注对比
    if calibrate:
        agreement = mean(
            r["answer"] == h for r, h in zip(results, human_labels)
        )
        return {
            "results": results,
            "agreement_with_human": agreement,
            "usable": agreement >= 0.80,   # 低于 0.8 不可用
        }

    return {"results": results}
```

### 5.4 判官提示词的设计要点

| 要点 | 说明 |
| --- | --- |
| 明确评分维度 | 不要只问「好不好」，要问具体维度 |
| 给出锚点样例 | 每档分给出示例 |
| 限制输出格式 | 强制输出结构化结果 |
| 要求先给理由 | 提升一致性 |
| 分维度打分 | 准确性、完整性、相关性、简洁性 |

### 5.5 判官与人工的配合

| 用途 | 判官 | 人工 |
| --- | --- | --- |
| 日常回归评估 | 主 | 抽检 |
| 上线门禁 | 主 | 关键决策时复核 |
| 建立金标准 | 辅助 | 主 |
| 发现新问题类型 | 探索 | 确认 |

推论：人工标注量应集中在「建立金标准」和「关键决策复核」，不应用来做全量评估。

### 5.6 判官的六种失效模式

判官不是人。它会在特定条件下失效。

| 失效模式 | 触发条件 | 表现 | 缓解 |
| --- | --- | --- | --- |
| 位置偏差 | 强制比较两个回答 | 偏好第二位置 | 交换位置双向判定 |
| 长度偏差 | 两个长度不同 | 偏好长的 | 长度归一化或补齐 |
| 自我偏好 | 判官与被测同族 | 偏好同族输出 | 换判官模型 |
| 权威偏差 | 引用了来源名称 | 偏好可信来源，忽视内容 | 隐藏来源名称 |
| 谄媚偏差 | 被问「这个答案好吗」 | 倾向回答「好」 | 改用选择题格式 |
| 算力幻觉 | 需要精确计算 | 编造数字 | 换成可执行验证指标 |
| 冗长困惑 | 上下文过长 | 前段信息被忽略 | 分段评分后聚合 |

推论：越接近「打分」的用法越可靠，越接近「评价好坏」的用法越不可靠。

### 5.7 打分聚合的三种方式

| 方式 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| 二元比较 | 判 A 或 B 或平局 | 最稳定 | 无法区分「好」与「非常好」 |
| 绝对打分 | 1 到 10 分 | 可比较不同模型 | 有打分漂移 |
| 成对偏好转分数 | 胜率转 Elo | 尺度统一 | 需要足够多的对数 |

二元比较的一致性检验：

| 与人工的一致率 | 判官可靠性 | 使用建议 |
| --- | --- | --- |
| 高于 0.85 | 强 | 可全量使用 |
| 0.75 到 0.85 | 中等 | 可用，需人工抽检 5% |
| 0.65 到 0.75 | 弱 | 仅用于筛选，不可用于决策 |
| 低于 0.65 | 不可用 | 必须换判官或重写提示 |

### 5.8 判官使用的前置检查

```text
判官上线前
  ├─ 抽 300 条人工标注做金标准
  ├─ 算与人工的一致率
  │    ├─ 高于 0.85 → 全量可用
  │    └─ 低于 0.85 ↓
  ├─ 拆分三种偏置的单独测量
  │    ├─ 位置偏差 → 双向判定
  │    ├─ 长度偏差 → 长度配平
  │    └─ 自我偏好 → 换厂商判官
  └─ 重新测量一致率
       └─ 仍低于 0.80 → 判官不可用，不得用于门禁
```

推论：判官一致率是一个需要持续监控的指标。判官模型升级后必须重新校准。

*图 1 · 统计严谨性与四种放量方式*

### 6.1 为什么必须报告置信区间

点估计会误导。同一模型换一批评测样本，指标可能波动 2 到 5 个百分点。

平均值的置信区间：

$$ CI = \bar{x} \pm z_{\alpha/2} \cdot \frac{s}{\sqrt{n}} $$

变量含义：$\bar{x}$ 为样本均值，$s$ 为标准差，$n$ 为样本数，$z_{\alpha/2}$ 为分位数，常取 1.96。

推论：置信区间的宽度与样本数的平方根成反比。要缩窄区间，加倍样本量。

### 6.2 Bootstrap 置信区间

当分布未知或样本量小时用 Bootstrap。

```python
import numpy as np

def bootstrap_ci(values, metric_fn, n_boot=1000, alpha=0.05, seed=42):
    """Bootstrap 置信区间。适用于任意指标。"""
    rng = np.random.default_rng(seed)
    values = np.asarray(values)
    n = len(values)

    stats = []
    for _ in range(n_boot):
        idx = rng.integers(0, n, size=n)
        stats.append(metric_fn(values[idx]))

    stats = np.sort(stats)
    lo = stats[int(alpha / 2 * n_boot)]
    hi = stats[int((1 - alpha / 2) * n_boot)]
    return {
        "point_estimate": metric_fn(values),
        "ci_low": lo,
        "ci_high": hi,
        "n_boot": n_boot,
    }
```

要点：对两组模型做 Bootstrap 时，必须在同一个重采样索引上同时计算两组，然后对差值求区间。

### 6.3 三种统计误用

| 误用 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 看两条 CI 是否重叠 | 判断标准不是 CI 是否重叠 | 对差值做 Bootstrap CI |
| p 小于 0.05 说明重要 | 统计显著不等于业务重要 | 同时报告效应量 |
| 在 20 个切片里挑显著的 | 多重比较导致假阳性 | 预注册主指标 |
| 样本不够也硬做实验 | 检验功效不足 | 先估算 MDE |

### 6.4 样本量估算

给定基线转化率 p、期望提升 Δ，需要的样本量近似为：

$$ n \approx 16 \cdot \frac{p(1-p)}{\Delta^2} $$

变量含义：$p$ 为基线率，$\Delta$ 为绝对提升。

示例：基线转化率 10%，期望提升 1 个百分点。

$$ n \approx 16 \times \frac{0.1 \times 0.9}{0.01^2} = 14400 $$

推论：每组需要约 14400 样本。做实验前必须先算这个数，不能做完再算。

### 6.5 多重比较

做 20 个独立检验，至少一个假阳性的概率：

$$ 1 - 0.95^{20} \approx 64\% $$

推论：跑大量切片后挑显著的那一个，等于随机挑。

对策：

1. 预注册主指标，其余作为护栏指标。
2. 用 Bonferroni 校正阈值。
3. 用 BH 校正控制错误发现率。

### 6.6 配对检验

同一用户同时看到两个版本时，用配对检验。

**McNemar 检验**：用于两个模型在同一批样本上的正确性对比。

| 条件 | 含义 |
| --- | --- |
| b | A 对 B 错 |
| c | A 错 B 对 |
| 统计量 | (b - c)^2 / (b + c)，近似卡方分布 |

推论：McNemar 只看不一致的样本。一致率高时，检验功效显著提升。

### 6.7 评估的边界条件

| 场景 | 常见错误 | 正确做法 |
| --- | --- | --- |
| 评测集只有几十条 | 任何提升都在噪声内 | 扩到千级以上 |
| 指标只有点估计 | 无法判断是否真实提升 | 必须报置信区间 |
| 反复在同一集上调优 | 隐性过拟合评测集 | 保留一份从不触碰的最终集 |
| 对比不同 tokenizer 的 PPL | 数值不可比 | 换可验证指标 |
| 评测集与线上分布不同 | 离线结论不可外推 | 线上采样加人工加权 |
| 多次跑评测挑最好 | 选择性报告 | 固定随机种子，报告单次结果 |
| 生成任务用贪心解码 | 掩盖采样问题 | 固定温度并报告多个种子 |
| 只报最好分层 | 掩盖退化 | 报告全部分层 |

### 6.8 评测集过拟合的检测

在同一评测集上反复调参，会隐性过拟合该评测集。

| 指标 | 含义 | 异常信号 |
| --- | --- | --- |
| 评测集得分 | 调参后的分数 | 持续上升 |
| 留出集得分 | 从未参与调参 | 停滞或下降 |
| 线上得分 | 真实效果 | 低于留出集 |

| 差距 | 判断 |
| --- | --- |
| 小于 1 个点 | 正常 |
| 1 到 3 个点 | 轻度过拟合 |
| 高于 3 个点 | 严重过拟合，评测集已失效 |

对策：

1. 把评测集拆成开发集与留出集。
2. 留出集只在最终决策时使用一次。
3. 评测集更新时同时更新指纹与基线。

推论：评测集也会被过拟合。它是需要维护的资产，不是固定资产。

### 7. 评估的执行

### 7.1 评估流程

1. 加载冻结的评测集，加载指纹。
2. 确认评测集指纹与基线一致。不同则停止。
3. 跑推理，记录原始输出。
4. 计算指标，含置信区间。
5. 与基线对比，做统计检验。
6. 生成分层报告。
7. 人工抽检低分层样本。
8. 归档报告，连同模型版本和数据指纹。

### 7.2 分层报告

| 分层维度 | 常见切分 |
| --- | --- |
| 难度 | 简单、中等、困难 |
| 语言 | 中、英、其他 |
| 类别 | 意图类型、领域 |
| 时长 | 短 prompt、长 prompt |
| 风险 | 普通、敏感、越狱 |

推论：总体分数上升但困难分层下降，说明模型在退化。必须看分层，不要只看总分。

### 7.3 评估报告的最小内容

- 评测集版本与指纹。
- 模型版本与代码 commit。
- 推理配置，含温度、最大 token 数。
- 各指标的点估计与置信区间。
- 与基线的差值与显著性。
- 分层结果。
- 已知的评估局限。

### 8. 在线实验

### 8.1 四种放量方式

| 方式 | 流量 | 能回答什么 | 答不了什么 |
| --- | --- | --- | --- |
| 影子流量 | 全量复制，用户看不到 | 会不会崩、延迟、输出分布差异 | 用户更喜欢谁 |
| 金丝雀 | 1% 到 5% 真实流量 | 极端坏 case、安全拦截、成本异常 | 业务指标因果 |
| A/B 实验 | 按用户随机分流 | 业务指标因果、护栏是否退化 | 极低频的极端 case |
| 蓝绿切换 | 全量切到新环境 | 全量容量是否够、回滚速度 | 质量是否提升 |

### 8.2 放量的正确顺序

影子流量 → 金丝雀 → A/B 实验 → 全量。

每一步回答的问题不同。跳级会失去可归因性。

### 8.3 分流设计

| 设计 | 做法 | 要求 |
| --- | --- | --- |
| 按用户分流 | 对 user_id 取哈希分桶 | 用户体验一致，避免跨组污染 |
| 按请求分流 | 对 request_id 取哈希 | 简单，但同一用户可能看到两个版本 |
| 分层分流 | 按用户属性分层后分层内分流 | 需要保证各层样本量足够 |

推论：必须按用户分流。按请求分流会导致同一用户看到不同版本，产生混淆。

### 8.4 A/B 实验设计

| 项 | 要求 |
| --- | --- |
| 主指标 | 唯一，预先注册 |
| 护栏指标 | 延迟、错误率、成本、投诉率 |
| 最小可检测效应 MDE | 实验前估算 |
| 实验周期 | 至少覆盖一个完整周周期 |
| 样本量 | 按 MDE 估算，不得中途偷看 |
| 停止规则 | 预先定义，不提前停止看结果 |

推论：中途偷看结果并提前停止，会大幅增加假阳性率。这是实践中最常见的错误。

### 8.5 A/B 实验的执行代码

```python
def run_ab_test(
    control_model, treatment_model,
    traffic_split=0.5, min_sample=10000, duration_days=7,
):
    """A/B 实验执行器。"""

    # 1. 分流：按用户哈希，保证用户体验一致
    def assign(user_id):
        return "treatment" if hash(user_id) % 100 < traffic_split * 100 else "control"

    # 2. 收集：至少覆盖 min_sample 和 duration_days
    collect_until(min_sample, duration_days)

    # 3. 计算：只算主指标 + 护栏指标
    primary = compute_metric("primary_conversion", group_by="arm")
    guardrails = {
        "p99_latency": compute_metric("latency_p99", group_by="arm"),
        "error_rate":   compute_metric("error_rate",  group_by="arm"),
        "cost_per_user": compute_metric("cost",       group_by="arm"),
    }

    # 4. 检验：主指标做配对检验，护栏只看方向
    primary_test = paired_test(primary)
    for k, v in guardrails.items():
        check_no_regression(k, v)

    # 5. 决策：只有主指标显著提升且护栏无退化才晋级
    if primary_test.p_value < 0.05 and primary_test.delta > 0 \
       and all(no_regression for no_regression in guardrails.values()):
        return "promote"
    return "rollback"
```

### 9. 红队测试

### 9.1 红队的六个维度

| 维度 | 测试内容 | 典型攻击 |
| --- | --- | --- |
| 越狱 | 绕过安全限制 | 角色扮演、编码绕过、多轮拆分 |
| 有害内容 | 生成违规内容 | 暴力、仇恨、自残 |
| 幻觉 | 捏造事实 | 虚构引用、伪造数据 |
| 隐私泄露 | 泄露训练数据或他人信息 | 提取训练数据、套取他人信息 |
| 提示注入 | 劫持工具或流程 | 文档中埋入指令、工具返回注入 |
| 拒答过度 | 该拒的不拒或不该拒的拒 | 边界测试 |

### 9.2 红队的执行方式

| 方式 | 规模 | 适用 |
| --- | --- | --- |
| 自动化红队 | 每天数千条 | 回归防护 |
| 人工红队 | 每周数百条 | 发现新攻击面 |
| 众测 | 外部研究人员 | 上线前 |
| 专家对抗 | 安全专家针对性测试 | 高风险场景 |

### 9.3 安全评测指标

| 指标 | 说明 |
| --- | --- |
| 攻击成功率 ASR | 攻击成功的比例，越低越好 |
| 拒答率 | 对恶意请求的拒答比例 |
| 过度拒答率 | 对正常请求的误拒比例 |
| 危害等级 | 分级评估严重性 |

推论：只优化攻击成功率会导致过度拒答。两个指标必须同时报告。

### 9.4 护栏的层次

| 层次 | 手段 | 位置 |
| --- | --- | --- |
| 输入过滤 | 关键词、正则、分类器 | 网关 |
| 提示加固 | 系统提示约束 | 应用层 |
| 输出过滤 | 关键词、分类器 | 网关或服务 |
| 工具权限 | 白名单、参数校验 | 工具层 |
| 人工兜底 | 高风险场景转人工 | 业务流程 |

### 11. 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 只看平均分 | 掩盖分层退化 | 必须看分层 |
| 评测集反复调整 | 在评测集上过拟合 | 冻结，另设调参集 |
| 用训练集评估 | 结果虚高 | 严格分离 |
| 忽略置信区间 | 把噪声当提升 | 报告区间与检验 |
| 只用一个指标 | 优化目标错位 | 主指标加护栏指标 |
| 判官不校准 | 结论不可信 | 与人工金标准对齐 |
| 中途偷看实验 | 假阳性率上升 | 预先定停止规则 |
| 多重比较不校正 | 假发现 | 预注册主指标 |
