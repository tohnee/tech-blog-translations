## 概述

首先先明确整体推理业务的完整链路：

```text
Business → Gateway/LB → Harness → Input → Serving → Model → Kernel → Hardware → Output
```

对于不同节点，对应的关注者不同：

| 链路 | 主要关注岗位 | 核心关注点 | 典型技术/问题 |
| --- | --- | --- | --- |
| Business | 业务研发 / AI 应用工程师 | 业务逻辑、模型选择、成本、SLA | RAG、Agent、Prompt、业务 QPS、成本 |
| Gateway / LB | Infra / 云原生 / 平台工程师 | 流量接入、路由、负载均衡、服务治理 | Gateway、Nginx、DNS、Service Mesh、限流、熔断、扩缩容 |
| Harness | 推理平台 / Infra / Benchmark 工程师 | 服务启动、压测、性能测试、监控、Profiling | Benchmark、Load Generator、Metrics、Tracing、Nsight、AI Harness |
| Input | 推理工程师 / Serving 工程师 | 请求预处理、Tokenizer、数据搬运、Prefill 输入 | Tokenizer、Multimodal Preprocess、Input Queue、CPU/GPU pipeline |
| Serving | 推理工程师 / 推理优化工程师 | 请求调度、Batching、KV Cache、并发、SLA | vLLM、SGLang、Scheduler、Continuous Batching、Paged KV Cache |
| Model | 算法工程师 + 推理优化工程师 | 模型结构与推理效率 | Attention、MLA、MoE、GQA、量化、TP/EP/DP/CP |
| Kernel | 算子开发 / 推理优化 / 编译器工程师 | 单算子性能、融合、访存、计算效率 | CUDA、Triton、GEMM、FlashAttention、Fusion、Memory Access |
| Hardware | 芯片 / 硬件 / 底层系统 / 算子工程师 | 硬件利用率、带宽、计算能力、通信 | GPU、NPU、Tensor Core、HBM、SRAM、NVLink、PCIe、NoC |
| Output | Serving / 推理工程师 / Infra | Decode、Detokenization、Streaming、响应返回 | Detokenizer、Streaming、Response Queue、SSE/WebSocket |

（注：推理工程师更偏向如何将模型在平台上正常跑起来，推理优化属于子类，更多关注如何优化。）

在推理优化视角下，需要关注的可以抽象成这个子链路：

```text
Input/Output → Serving → Model → Kernel → Hardware
```
