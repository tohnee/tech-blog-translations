11 月 13 日，AI 技术圈出现两条不同方向的重要进展：一边是本地推理项目 **llama.cpp 正式发布 v1.0.0**，完善底层接口、模型兼容与服务端能力；另一边是 Google 推出 **Gemini 4 Hydrogen**，把新一代模型的重点放在日常编码与多步骤 Agent 的快速执行上。与此同时，Grok Bot 的沙箱权限风险持续引发讨论，GitHub 上的安全审计、上下文图谱与 Computer Use 项目也受到关注。

从近期论文看，研究议题并不限于更大的模型：决策模型是否可靠、世界模型能否保持空间与物理一致性、模型推理与训练能否降低成本，以及 Agent 能否从真实文件中学习完成可验证的任务，都有新的实验结果。

一、模型与技术圈重要动态

01｜llama.cpp 发布 v1.0.0：本地推理工程进入新的版本阶段

**发布日期：2026 年 11 月 13 日｜ggml-org / Hugging Face**

llama.cpp 是基于 C/C++ 的本地大模型推理项目，支持在个人电脑及多种计算硬件上执行模型。v1.0.0 的变化并非单纯将版本号改为 1.0：项目移除了 35 个弃用的公开 API，将 NextN／推测解码相关接口并入 `llama.h`，同时更新底层 `ggml`。**需要特别注意，1.0 本身包含不兼容变更，不等于旧代码无需调整。**

本次还引入 FP8 KV Cache、支持分配 CPU 内存的 MoE 专家缓存、外部 PLE 分片加载，并新增 Kimi K3.1 Pro、Ripple-65B 等模型架构与 Drama-3 语音生成支持。`llama-server `增加兼容 OpenAI 风格的`/v1/audio/speech `接口，同时加强对 SSRF、跨域访问、DNS 重绑定和工具调用取消的处理。对使用嵌入式接口或远程 RPC 的开发者，升级前需要核对 API 与协议兼容性。

原始发布：[HTTPS://GitHub.com/ggml-org/llama.cpp/releases/tag/v1.0.0](HTTPS://GitHub.com/ggml-org/llama.cpp/releases/tag/v1.0.0)

项目仓库：[HTTPS://GitHub.com/ggml-org/llama.cpp](HTTPS://GitHub.com/ggml-org/llama.cpp)

02｜Gemini 4 Hydrogen 正式上线：Google 为 Agent 提供快速执行模型

**发布日期：2026 年 11 月 12 日｜Google DeepMind**

Gemini 4 Hydrogen 与强调深度长程推理的 Carbon、Argon 分工不同，主要面向代码修改、测试、工具调用和日常多模态任务。官方公布其支持文本、图片、音频和视频输入，提供最长约 100 万 Token 的统一上下文窗口，以及 low、medium、high、xhigh 四档思考强度。开发者 API 定价为**每百万输入 Token 1.50 美元、输出 Token 7.50 美元**。

Google 报告：Hydrogen 在 Agents' Last Exam v1.1 得分 **71.6%**，多模态知识工作基准 MKA 得分 **53.4%**；在 Google Antigravity 的 Orchestrator 工作流中，结合 Carbon 与 Hydrogen 的模型切换方案，在 Terminal-Bench 4.0 上接近 Carbon 任务成功率，同时平均减少 **24% 配额消耗**、缩短 **19% 完成时间**。这些是特定模型和工作流条件下的官方结果，并非所有任务都加速相同比例。未核实到与前代 Flash 同条件下“普遍快 2.5 倍”的官方依据。

官方介绍：[HTTPS://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/](HTTPS://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/)

模型卡：[HTTPS://deepmind.google/models/model-cards/gemini-4-hydrogen/](HTTPS://deepmind.google/models/model-cards/gemini-4-hydrogen/)

03｜Grok Bot 沙箱安全报告：提示词注入可能扩大为账户级权限风险

**研究公开：2026 年 11 月 8 日｜Profero；本周持续讨论**

安全公司 Profero 报告称，在其测试的 Grok Bot 云端 Agent 环境中，沙箱内可以访问未认证的 Docker 控制接口，结合其他凭证与管理服务问题，能够从一条被执行的指令取得**同一账户虚拟机**的 root 权限，并威胁该账户中保存的文件、浏览器会话或连接凭证。外部网页中的恶意指令可能成为触发 Agent 执行操作的入口。

研究者表示已于 8 月向相关厂商报告，并在发布前的复测中仍能复现。但截至本次整理，尚缺少厂商公开的最终修复说明；研究也**没有证明能够进入其他客户的虚拟机或底层云主机**。这起案例显示，Prompt 防护之外，Agent 还需要最小权限、控制面鉴权、凭证隔离及可审计的工具执行环境。

原始研究：[HTTPS://profero.io/blog/the-rootkit-built-into-grok-bot](HTTPS://profero.io/blog/the-rootkit-built-into-grok-bot)

独立安全分析：[HTTPS://www.runlayer.com/blog/grok-bot-vulnerability-prompt-injection](HTTPS://www.runlayer.com/blog/grok-bot-vulnerability-prompt-injection)

二、GitHub：6 个开源项目的工程进展

以下 Star 是 11 月 13 日核对 GitHub 仓库时的近似快照，**不是单日增长量**。项目功能以 README 和仓库描述为准。

05｜Modern Web Guidance：把最新浏览器规范变成 Agent Skill

**GoogleChrome｜约 4.4K Stars｜Apache 2.0**

Chrome 等浏览器与 Web 社区共同维护的现代 Web 开发指导库，为 Coding Agent 提供经过整理的浏览器 API、性能、无障碍和兼容性规范。它支持检索指导条目与扫描代码库中的过时实现，帮助 Agent 不仅写出能运行的代码，还能优先使用现代浏览器原生能力。该仓库主要是指导内容的源码与评测项目，并非新的浏览器自动化引擎。

GitHub：[HTTPS://GitHub.com/GoogleChrome/modern-web-guidance-src](HTTPS://GitHub.com/GoogleChrome/modern-web-guidance-src)

06｜Codex Security：将漏洞发现、验证与修复串成工作流

**OpenAI｜约 12.9K Stars｜Apache 2.0**

Codex Security 提供 CLI、TypeScript SDK 和 CI 集成，支持扫描仓库、指定路径或 Git 差异，验证候选漏洞、生成修复补丁并检查修复结果，还能导出 SARIF、JSON、CSV 报告。它强调的是有来源证据和范围说明的审计流程，而不是让模型仅凭代码印象给出风险建议。自动扫描的发现仍需结合验证结果判断，不能据此保证仓库不存在漏洞。

GitHub：[HTTPS://GitHub.com/openai/codex-security](HTTPS://GitHub.com/openai/codex-security)

07｜Semantica：图原生的 Agent 上下文和可追溯推理

**Semantica AGI｜约 14.6K Stars｜MIT**

Semantica 将企业数据导入、语义建模、Context Graph、知识图谱及图分析组合为统一工具链，支持 RDF、属性图以及决策来源追踪。相比只对文本块做向量检索，它更强调实体关系、数据血缘与结构化上下文，适合构建需要解释检索与决策过程的知识助手。工程落地时仍需评估实体抽取误差、图谱更新成本和权限继承。

GitHub：[HTTPS://GitHub.com/semantica-agi/semantica](HTTPS://GitHub.com/semantica-agi/semantica)

08｜OpenBot：给 AI 同事提供独立执行环境

**CopilotKit｜约 12.0K Stars｜MIT**

OpenBot 是可自托管的 AI Coworker 工作空间，允许 Agent 使用浏览器、文件与工具，并展示其操作记录；用户可接管任务或在关键操作前审批。项目同时提供桌面应用和团队部署方案，侧重把执行环境、Agent 接口和人机协作结合起来。需要重点检查工具授权、敏感数据访问范围与多任务环境隔离，而不能把“有操作记录”直接等同于安全。

GitHub：[HTTPS://GitHub.com/CopilotKit/OpenBot](HTTPS://GitHub.com/CopilotKit/OpenBot)

09｜TensorFold：使用 Zig 开发本地模型推理引擎

**ashhart｜约 2.1K Stars｜Apache 2.0**

TensorFold 通过 Zig 二进制文件在 Apple Silicon 和 NVIDIA GPU 上运行语言模型，直接使用 Metal 或 CUDA 内核，无需安装 Python 或 MLX 才能提供服务。仓库另列出 Vulkan 相关方向。适合研究推理引擎如何处理模型加载、量化、Kernel 与跨硬件部署。项目提供的演示和性能结果尚不足以证明其在全部模型或显卡上优于成熟引擎。

GitHub：[HTTPS://GitHub.com/ashhart/TensorFold](HTTPS://GitHub.com/ashhart/TensorFold)

10｜Code-Graph-RAG：用代码知识图谱组织大型仓库上下文

**vitali87｜约 5.4K Stars｜MIT**

项目利用 Tree-sitter、可选的编译器级解析和运行时轨迹，把多语言代码库构造成可查询的实体关系图，再支持自然语言问答、代码定位与修改。面对跨目录的调用关系、类型依赖和大型 Monorepo，这种图谱检索能够补充纯文本搜索，但仍需验证增量索引、动态调用关系和生成式回答的准确性。

GitHub：[HTTPS://GitHub.com/vitali87/code-graph-rag](HTTPS://GitHub.com/vitali87/code-graph-rag)

本节来自近期论文及 11 月 13 日 Daily Papers 收录的研究。**首次提交日期不等于当天榜单收录日期**；实验数字均为作者报告，尚未独立复现。

11｜SO-Arena：决策模型的高分不等于可靠决策

**2026.11.11｜arXiv:2611.15777**

研究问题：不逐 Token 生成文本、直接给出选项或概率的模型，是否能稳定作出正确判断？SO-Arena 构建覆盖 11 个领域、5 类能力的评测，并加入选项扰动与“没有正确答案”的测试。**结果：**在 21 个模型中，总体表现最好的 System One 模型，可靠性仅排第七，反映准确率与稳定性不能混为一谈。

论文：[HTTPS://arxiv.org/abs/2611.15777](HTTPS://arxiv.org/abs/2611.15777)

12｜Actor, Judge, or Teacher：决策模型可以作为强化学习教师

**2026.11.12｜arXiv:2611.17167**

研究问题：决策模型不擅长直接执行 Agent 任务，是否仍能评价动作并提供训练反馈？作者比较其作为执行者、评判者和教师的表现，对完整轨迹的每一步评分。**结果：**以 Jev 提供步骤级奖励训练 Qwen2.5-1.5B，ALFWorld 成功率从 **72.8% 提至 82.9%**，WebShop 从 **56.8% 提至 71.4%**。

论文：[HTTPS://arxiv.org/abs/2611.17167](HTTPS://arxiv.org/abs/2611.17167)

13｜BirdDreams：联合生成驾驶视角与鸟瞰世界

**2026.11.10｜arXiv:2611.14815**

研究问题：仅用驾驶视角视频预测交通变化，容易受到遮挡和外观变化干扰。BirdDreams 通过两个视频扩散 Transformer 联合生成驾驶视角与鸟瞰图，让道路与车辆位置成为生成过程中可预测的空间状态。**结果：**在 PhysicalAI-AV 和 nuScenes 中，作者报告其轨迹跟随及周围车辆行为的合理性优于对照模型；摘要没有统一量化增幅。

论文：[HTTPS://arxiv.org/abs/2611.14815](HTTPS://arxiv.org/abs/2611.14815)

14｜Duo：让世界模型支持全双工实时视听交互

**2026.11.11｜arXiv:2611.15131**

研究问题：世界模型能否一边持续听和看，一边决定如何回应、生成视听内容并处理打断？Duo 把交互中的 Intent 与 Realization 分开建模，通过统一时间轴、同步注意力和双重 Rollout 蒸馏训练。**结果：**论文展示持续交谈、打断、共享真实物体及虚拟场景互动，但摘要未提供统一成功率或端到端延迟数据。

论文：[HTTPS://arxiv.org/abs/2611.15131](HTTPS://arxiv.org/abs/2611.15131)

15｜G-STAR：视觉 Token 深度压缩推动自回归图像生成

**2026.11.08｜arXiv:2611.13004**

研究问题：视觉 Token 过多会拖慢自回归图像生成，而压缩过多会损失细节。G-STAR 结合乘积量化、空间与分组容量协同缩放，以及半自回归解码器。**结果：**作者报告有效 **32～64 倍空间压缩**；在单张 H200 上生成 1024×1024 图片约 **2.5 秒**，相较指定离散自回归基线最高约 **20 倍加速**。

论文：[HTTPS://arxiv.org/abs/2611.13004](HTTPS://arxiv.org/abs/2611.13004)

16｜PhysLoop：让视频生成模型识别并修复物理错误

**2026.11.12｜arXiv:2611.16748**

研究问题：视频模型可能生成视觉逼真却不符合物理规律的动作。PhysLoop 用 LLM 引导视频生成、筛选与局部修复，把物理错误转成训练和推理反馈。**结果：**作者发布约 **10 万段视频**，构建 PhysLoop-Gen 与 PhysLoop-Repair 评测集；公开摘要没有统一的物理一致性提升比例。

论文：[HTTPS://arxiv.org/abs/2611.16748](HTTPS://arxiv.org/abs/2611.16748)

17｜SimpleHC：保留跨层连接能力，减少训练额外开销

**2026.11.04｜arXiv:2611.05984**

研究问题：Hyper-Connections 改善深层 Transformer 信息流，但扩展残差状态和反复访存增加成本。SimpleHC 简化残差混合，通过共享状态读取和延迟写入减少开销。**结果：**最大测试规模下，相比普通残差结构，端到端训练时间仅增加 **2.4%**；在 15B、30B MoE 上保持与 mHC 相近表现。

论文：[HTTPS://arxiv.org/abs/2611.05984](HTTPS://arxiv.org/abs/2611.05984)

18｜WorldDraft：视频生成应负责构建世界，还是渲染世界？

**2026.11.12｜arXiv:2611.16217**

研究问题：如果代码已定义运动轨迹和相机路径，视频模型能否只负责渲染并保持外观一致？WorldDraft 使用 **48 类可执行四维场景、432 个测试案例**，比较 12 个模型的运动约束和外观保持能力。**结果：**精细草稿改善运动结构，却可能损害外观；冲突来源导致错误外观信息泄漏最高 **64%**。

论文：[HTTPS://arxiv.org/abs/2611.16217](HTTPS://arxiv.org/abs/2611.16217)

19｜UniSpark：混合注意力支持多模态理解与图像生成

**2026.11.12｜arXiv:2611.16517**

研究问题：视觉问答与图像生成对上下文处理有不同需求。UniSpark-9B 采用 Mixture-of-Transformer-Experts，结合全注意力与 GatedDeltaNet 线性注意力，并联合训练自回归文本预测和视觉 Flow Matching。**结果：**作者报告 MME-S 为 **2470.3**、GenEval 为 **0.83**，支持最高 2K 图像合成；两项指标不能直接合并比较。

论文：[HTTPS://arxiv.org/abs/2611.16517](HTTPS://arxiv.org/abs/2611.16517)

20｜Agent-R²：从真实文件合成办公 Agent 训练任务

**2026.11.05｜arXiv:2611.08219**

研究问题：办公 Agent 需要理解真实文件并产出符合要求的交付物，但训练数据常缺乏文件和验收标准。Agent-R² 从 **1 万个候选任务筛出 4,000 个**，结合真实多格式附件及细粒度评分规则训练 4B Agent。**结果：**论文指定配置中，GDPval 得分 **51.0%**，对照 Qwen3-235B 为 **48.0%**；OfficeQA 为 **14.8% 对 13.8%**。

论文：[HTTPS://arxiv.org/abs/2611.08219](HTTPS://arxiv.org/abs/2611.08219)
