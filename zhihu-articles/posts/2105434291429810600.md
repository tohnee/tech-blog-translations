## **一、 67% vs 92% —— 被"唯参数论"掩盖的另一半真相**

谈到 AI 编程 Agent，技术圈的争论几乎永远围绕模型本身打转：是 `Claude Fable` 更稳，还是 `GPT` 更强？`Qwen3.8-27B` 这种能塞进单张消费级显卡的开源模型，到底能不能在真实工程里扛起大梁？

2026 年 11 月，*[Data Science Collective 上一篇拆解论文实验的文章](https://medium</i>.com/data-science-collective/same-qwen-model-67-vs-92-on-hard-coding-problems-only-the-harness-changed-cbe8aa168447) 给出了一组颇具冲击力的对照数据：*

*研究者将 **100 道高难度编程竞赛题** 交给单卡即可运行的开源模型 **`Qwen3.8-27B`**：*

- ***裸跑单次生成（Single-shot）**：通过率仅为 **67%**。*
- ***套入极简 Agent 执行框架（Harness）**：同一个模型、同一批题目，通过率直接飙升至 **92%**。*
- ***对照组参考**：同一批题目上，闭源旗舰 **`Claude Fable 5`** 在单次生成（未使用 Harness）下的通过率为 **90%**。*

*模型权重没有改动一个字节，真正改变上限的，是包在模型外面那层工程外骨骼——**Agent Harness**。所谓 Harness，指的是模型之外、负责"规划、拆解、测试与纠错"的执行框架；Cursor、Claude Code 这些编程工具，本质上都是一个 Harness。据原文统计，这套极简 Harness 在 5 轮迭代评测中成功把 **134 次失败（Miss）逆转为通过（Pass）**，而原本能过却被改坏的回退仅发生 **6 次**。*

*这意味着，对于大量因为隐私合规、内网隔离或 API 账单压力而选择本地部署的团队来说，**与其盲目追逐更大的参数量，不如先重构你的 Harness。***

## ***二、 为什么极简 Harness 能榨出 25 个百分点的提升？***

*先说结论：真正榨出这 25 个百分点的，不是重试次数，而是 **3 个反直觉的工程习惯**。很多人把 Harness 误解为"给模型多几次重试机会（Retry）"。重试确实贡献了一部分收益（实验中每题平均交互 6 到 7 轮，每次仅把**第一个失败的公开样例**喂回给模型），但真正让模型在多轮迭代中不至于"把好的改坏、越改越乱"的，是下面这三条：*

1. ***先落盘 `plan.md`，再写第一行代码** 大模型在多轮 Debug 过程中最致命的缺陷是"上下文漂移"——修改到第 4 轮时，早就忘了第 1 轮定的边界条件。Harness 强制模型在动代码前先把整体思路写进本地状态文件，后续每一轮推理都重新锚定该计划。*
2. ***双目标强制拆解（Task Splitting）** 如果一个步骤同时要求"解析复杂输入"和"动态规划状态转移"，小参数模型极易在单步内耗尽注意力预算。Harness 要求将耦合目标拆分为独立子任务，一次只攻克一个微目标。*
3. ***严格限制单步上下文膨胀（Bounded Step）** 不把冗长的全量日志和历史废弃代码一股脑塞回上下文，只保留当前计划 + 核心代码 + **首个报错样例的输入/期望输出/实际输出**。*

## ***三、 本地部署避坑——为什么你的 Ollama 跑不动这套 Harness？***

*在动手写代码之前，必须先解决本地运行时的隐性"杀手"。结合 *[Towards AI 2026 年 11 月 Mac 本地编程大模型选型指南](h</i>ttps://pub.towardsai.net/best-local-llms-for-coding-on-your-mac-in-november-2026-16gb-to-128gb-picks-68625d99becd) 的一线实测经验，本地跑 Agent Harness 最容易踩中以下配置陷阱：**

### ****1. 警惕默认上下文截断（静默杀死 Agent 状态）****

**许多本地推理引擎（如 Ollama）为了节省显存，默认分配的上下文窗口非常保守（往往只有 4K 或 8K）。一旦进入第 3 轮迭代，代码文件 + `plan.md` + Traceback 报错堆栈很容易突破默认上限，引擎会**静默丢弃早期的 System Prompt 和计划文件**，导致 Agent 瞬间"失忆"并陷入死循环。因此在启动本地模型或构建 Modelfile 时，务必显式拉高 `num_ctx`（建议至少设置为 **16384 或 32768**）。**

### ****2. 按硬件内存档位匹配本地主力模型****

| 硬件内存档位 | 推荐部署策略与模型选型 | 适用 Harness 场景 |
| --- | --- | --- |
| 16GB（入门 Mac / 8–12GB 显存） | 优先选择 7B–14B 级别代码特化量化模型，预留足够内存给 num_ctx=16384 的 KV Cache | 单文件脚本编写、函数级单元测试修复 |
| 24GB–48GB（RTX 4090 / L40 / 32–48GB Mac） | Qwen3.8-27B（4-bit/6-bit 量化），实测可在 RTX 4090 与 48GB L40 上流畅运行上述 67% → 92% 的 Harness 闭环 | 复杂算法实现、多模块 Bug 定位与测试驱动迭代 |
| 64GB–128GB（Mac Studio / 大内存工作站） | Qwen3.8-27B 高精度量化或 Flash-Next 系列栈，可同时常驻向量检索与完整项目上下文 | 跨文件重构、全仓库级 CI 自动修复闭环 |

## ****四、 实战——100 行 Python 极简 Coding Agent Harness****

**下面是一套可直接接入本地 Ollama（兼容 OpenAI SDK 接口）的极简 Harness 核心实现。它完整还原了 **"先写 `plan.md` → 编码 → 沙箱执行样例 → 仅提取首个失败用例精准回喂"** 的闭环逻辑：**

```text
import subprocess
import tempfile
from pathlib import Path
from openai import OpenAI

# 连接本地 Ollama OpenAI 兼容端点，务必确保服务端已设置足够大的 num_ctx
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
MODEL = "qwen3.8:27b"

def call_local_llm(messages: list[dict]) -> str:
    resp = client.chat.completions.create(
        model=MODEL,
        messages=messages,
        temperature=0.2,
        # Ollama 扩展参数：防止默认小窗口静默截断 plan.md
        extra_body={"options": {"num_ctx": 32768}},
    )
    return resp.choices[0].message.content or ""

def extract_code(text: str) -> str:
    if "```python" in text:
        return text.split("```python", 1)[1].split("```", 1)[0].strip()
    if "```" in text:
        return text.split("```", 1)[1].split("```", 1)[0].strip()
    return text.strip()

def run_first_failing_test(code: str, test_cases: list[tuple[str, str]]) -> str | None:
    """运行所有公开样例，一旦失败立即停止，只返回第一个失败用例的精准 Diff"""
    with tempfile.NamedTemporaryFile("w", suffix=".py", delete=False) as f:
        f.write(code)
        script_path = Path(f.name)

    try:
        for idx, (stdin_data, expected_out) in enumerate(test_cases, 1):
            proc = subprocess.run(
                ["python3", str(script_path)],
                input=stdin_data,
                text=True,
                capture_output=True,
                timeout=5,
            )
            if proc.returncode != 0:
                return f"样例 #{idx} 运行报错:\n{proc.stderr.strip()[:800]}"
            actual_out = proc.stdout.strip()
            if actual_out != expected_out.strip():
                return (
                    f"样例 #{idx} 输出不匹配:\n"
                    f"输入:\n{stdin_data}\n"
                    f"期望输出:\n{expected_out.strip()}\n"
                    f"实际输出:\n{actual_out}"
                )
        return None
    except subprocess.TimeoutExpired:
        return "执行超时（>5s），请检查是否存在死循环或时间复杂度过高。"
    finally:
        script_path.unlink(missing_ok=True)

def solve_with_harness(problem_desc: str, test_cases: list[tuple[str, str]], max_rounds: int = 6) -> str:
    # Step 1: 强制先落盘规划，禁止直接写代码
    plan_prompt = (
        "你是一位严谨的算法与工程架构师。在写任何代码前，请先输出一份简明的技术方案：\n"
        "1. 拆解问题中的独立子目标；2. 明确边界条件与时间复杂度约束；3. 禁止输出代码。\n\n"
        f"题目描述：\n{problem_desc}"
    )
    plan_text = call_local_llm([{"role": "user", "content": plan_prompt}])
    Path("plan.md").write_text(plan_text, encoding="utf-8")

    # Step 2: 基于 plan.md 进行首次实现
    code_prompt = (
        f"请严格依据以下已确认的技术方案编写完整可运行的 Python 代码（从 stdin 读取，stdout 输出）：\n\n"
        f"【plan.md】\n{plan_text}\n\n【题目】\n{problem_desc}\n\n只输出 ```python 代码块。"
    )
    code = extract_code(call_local_llm([{"role": "user", "content": code_prompt}]))

    # Step 3: 测试驱动的有限轮次闭环（控制上下文不膨胀）
    for round_idx in range(1, max_rounds + 1):
        failure = run_first_failing_test(code, test_cases)
        if failure is None:
            print(f"[Pass] 第 {round_idx} 轮通过全部测试样例！")
            return code

        print(f"[Retry {round_idx}/{max_rounds}] {failure.splitlines()[0]}")
        fix_prompt = (
            f"当前代码未通过测试，请对照原定方案与首个失败样例进行定点修复。\n\n"
            f"【plan.md】\n{plan_text}\n\n"
            f"【当前代码】\n```python\n{code}\n```\n\n"
            f"【首个失败反馈】\n{failure}\n\n"
            "请分析根因并输出修复后的完整 ```python 代码块。"
        )
        code = extract_code(call_local_llm([{"role": "user", "content": fix_prompt}]))

    print("[Warn] 达到最大迭代轮次，返回最后一版代码。")
    return code
```

## ****五、 可以直接塞进 Cursor / Claude Code 的 Harness 规则模板****

**如果你平时直接使用 Cursor、Cline 或 Claude Code，可以把以下规则写入项目根目录的 `.cursorrules` 或 `CLAUDE.md`，立刻在日常开发中复刻同款工作流：**

```text
# 本地编码代理规则
1. **首先制定计划**: 在编辑任何源文件以处理非简单任务之前，请编写或更新 `plan.md` 文件，其中应包含：(a) 拆分为单一目标步骤的子任务，(b) 边界情况，以及 (c) 验证命令。
2. **每回合一个子任务**: 切勿将重构无关模块与修复目标缺陷混为一谈。在转入下一个子任务之前，应先完成并验证当前子任务。
3. **最小化失败反馈**: 当测试失败时，请仅检查第一个失败的测试用例及其根级回溯信息。不要盲目重写正常运行的函数；请根据 `plan.md` 进行修改。
4. **上下文健康**: 如果修复方案连续两次失败，请从磁盘重新读取 `plan.md` 并重置处理方案，而不是在现有补丁上叠加新的补丁.
```

## ****六、 冷静分析与落地建议****

**实施这套方案有两个严谨的实验边界必须交代清楚：**

1. ****与 `Claude Fable 5` 的对比并不对等**：实验中 `Claude Fable 5` 只跑了单次生成（90%），并未接入同一套 Harness；如果同样接入闭环，闭源旗舰的得分大概率还会继续上升。**
2. ****评测集时效性边界**：据原文说明，这 100 道题目源自 2025 年中以前的编程竞赛，后续发布的新模型在预训练阶段可能接触过部分题面。但 **`Qwen3.8-27B` 从 67% 跃升至 92% 的组内对照是完全成立的**：前后两次跑的是同一个模型、同一批题，唯一变量只有 Harness。**

**如果你正在为本地开源模型"写复杂代码总掉链子"而准备花大钱升级显卡或切回昂贵 API，不妨先停下来，把今天这 100 行 Python Harness（或 `.cursorrules` 模板）接入你现有的 27B 本地环境，先跑一遍你手头的测试题。很多时候，限制 AI 编程上限的不是参数量，而是你有没有给它套上正确的工程外骨骼。**
