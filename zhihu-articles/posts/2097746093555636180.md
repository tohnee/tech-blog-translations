现在到了终端百花齐放的状态。先前有一些有特点的终端在极客间流行，但是最近几个月来有爆发的趋势。

比如先前大家用的iterm2、Ghostty、warp、kitty，以及otty、herdr、tern、rex、ELYTerminal、kero等，肯定还有很多，而且每个终端很有特色，比如Ghostty 基于GPU，输入时动画效果很棒。otty 的美观度和友好度非常好， herdr、tern、rex多agent/窗口的管理等。

我最近也在尝试和更换我的终端工具，也曾尝试让AI模仿otty写了一个工具，但是最后选择了基于kero改造的终端。

进一年来我的终端变化历程是 iterm --> ghostty --> otty --> kero。

目前采用 kero， 它是一个Go语言编写的终端工具， 终端组件采用libghostty的封装，界面简洁，这个终端的设计甚合我意，且我比较熟悉Go语言，可以做一些定制化开发，所以最终选择了它。

当然维护一个自己的分支比较痛苦，因为经常会和上游有冲突，且未来如果两边的代码差别比较大的话，合并时解决冲突也是很困难的一件事。目前我也在摸索，在我的main分支保持和上游同步，并在dev上开发新特性，并在claude设置了定时器，定时的检查上游官方是否有新的commit 和 PR, 发送大我的飞书中，自动和半自动的合并新的特性。我渐渐摸索出来一套方法出来，大家感兴趣的话我可以再总结一篇经验出来。

CHAPTER 01

一、官方特性：它解决什么问题

普通终端不知道窗口里跑的是什么。Claude Code 要你确认权限的时候，终端不会告诉你；agent 跑完了、报错了，你也得自己切回去看。

Kero 把会话（session）交给后台进程 kerod 管理，状态直接摆在侧边栏上。

- ● **会话比窗口活得久。** 会话跑在 `kerod` 这个常驻后台的小守护进程里，关掉 Kero 窗口，会话和其中的程序继续运行。重新打开，每个窗格和它的滚动历史都还在。
- ● **状态一眼可见。** 每个窗格处于 working、waiting（需要你）、idle、error 或 exited 之一。按⌘J直接跳到需要你的那个；agent 完成、失败或被卡住时，Kero 会通知你。（我的分支上多加了一个小青蛙精灵，用动画展示状态。）
- ● **按项目分组。** 侧边栏按项目把会话分好组，不用在十几个窗口标题里找。
- ● **命令行可被智能体驱动。** `kero` 命令行能开会话、拆窗格、往里输入、等它结束、读它的屏幕。这是 Kero 与其他终端区别最大的地方，第 4 节单独说。
- ● **远程主机。** 在 Linux 服务器、云主机、Mac、Windows PC 或 WSL 上跑会话，通过 SSH 或 Tailscale 接进来，显示在同一个侧边栏里。笔记本合上，会话照样跑。 ## 二、官方特性：状态和通知

另外几个常用的地方：

- ● **侧面板。** 两个视图： **Changes** 列出 git 工作区里 agent 改了哪些文件、加了多少删了多少； **Files** 浏览会话所在的文件夹。
- ● **浏览器窗格。** 输入一个地址，就在 Kero 里开一个浏览器。写前端、调本地页面，不用切出去。
- ● **应用图标的位置。** 在 **Settings › General › Show app icon** 里，可以选只显示在 Dock、只显示在菜单栏，或者两处都显示。图标显示在菜单栏时，关掉窗口 Kero 继续在那里运行。
- ● **界面语言。** 中英文之外，2.1.14 起也支持日文。
- ● **贴图。** 单独粘贴一张截图时，粘贴的是图片文件的路径，Claude Code 这类 agent 会把它当成图片附件。

CHAPTER 02

三、官方特性：上手

### 1. 下载安装

有两个来源，装哪个取决于你要什么。

**官方版，macOS 上可以用 Homebrew：**

```text
brew install --cask kero

```

cask 指向 `egoist/kero` 的 release，同时把 `kero` 命令链接到 `PATH` ，卸载也干净（ `brew uninstall --cask --zap kero` ）。注意 `--zap` 会一并删掉 `~/.config/kero` 和 `~/Library/Application Support/kero` ，本机的会话历史也在里面。

**分支版，要本文第 5 节讲的补充功能：**

从 smallnest/kero 的 Releases 页面[^2] 下载对应平台的安装包，打开即用。macOS、Windows、Linux 都支持。

两者不要混装。从 `egoist/kero` 的 release 装过的版本不会自动更新到分支版本，需要手动重装一次。

### 2. macOS 的签名和首次打开

两个来源的签名情况不一样：

官方版下载后正常打开就行。第一次启动时 Gatekeeper 会在线查询公证结果，所以需要联网。

分支版第一次打开时，右键（或 Control-点击） **Kero.app** ，选 **打开** ，再确认一次。如果 macOS 仍然拒绝，在终端执行：

```text
xattr -d com.apple.quarantine /Applications/Kero.app

```

### 3. 安装命令行工具

用 Homebrew 装的可以跳过这一步，cask 已经把 `kero` 链接好了。手动安装的话，在菜单里选 **Kero › Install Command Line Tool…** ，把 `kero` 放进 `PATH` 。

### 4. 在别的机器上跑会话（可选）

要在 Linux 服务器、Mac 或 Windows 上跑会话，先在那台机器上装 server 版本。Linux 和 macOS：

```text
curl -fsSL https://github.com/smallnest/kero/releases/latest/download/install-server.sh | sh

```

Windows 的 PowerShell 里：

```text
irmhttps://github.com/smallnest/kero/releases/latest/download/install-server.ps1 | iex

```

然后在 **Settings › Hosts** 里加入这台机器。笔记本合上，那边的会话照样跑。

更多说明见 官方文档[^3]。

四、官方特性：终端可以被智能体驱动

Kero 提供了 `kero` 命令行， **AI agent 自己就能开终端、操作终端** 。这是它和其他终端最不一样的地方。

这些命令对任何在 Kero 里运行的程序都适用，包括 Claude Code。比如：

```text
kero status --json     # 本会话的状态和当前目录

```

装了 Kero skill 的 agent 还能把工作进度汇报回侧边栏： `kero report working --progress 40` 、 `kero report done` 。

一个在 Kero 里运行的 agent，可以通过这些命令驱动别的会话：

```text
kerols# 列出所有会话和窗格
kerosplit<会话> --down -- npm run dev    # 往下拆一个窗格跑 dev server
kero send  <窗格>"npm test"--enter      # 输入并回车
kero prompt <窗格>"run the tests"# 发送 + 回车 + 等待 + 返回屏幕
kerowait <窗格> --exit# 等命令结束，退出码就是命令的退出码
keroread <窗格> -n 40            # 读屏幕
kero new  -n review -- claude         # 另开一个会话

```

这样一来，一个 agent 可以当"工头"：它自己拆窗格、起测试、等结果、读输出。

五、我的分支：补充的特性

Kero 由 egoist 维护，迭代很快。我在它基础上做了 smallnest/kero[^4]，补了几样我每天都要用的东西。 **这些官方版本里没有，装了分支版才能用。**

### 小青蛙精灵

Kero the frog 趴在窗口上沿：有会话需要你时它跳，agent 工作时它跟着看，安静久了就打盹。点它可以打开窗口，也可以在 **Settings › Appearance** 里关掉，或者用快捷键打开和关闭。

Agent 运行的时候，它还会敲自己的肚皮。

### 左面板优化

界面做了调整，另外增加了排序菜单。

### 半透明设置

### 会话历史

Claude Code、Codex、Pi、OpenCode 结束时，它们的对话会出现在侧边栏底部的 **Ended** 区域。点标题栏展开，点一条会话，就在它原来的文件夹里新建会话并恢复对话；不用的可以归档到 **Archived** 。每个主机保留最近 50 条，其他机器上的会话也在里面，带主机名。

这个功能来自上游社区的 PR#240，等不及合入就先用了。

上图是 **Settings › General** 的一部分：退出时结束会话、重启后恢复会话、会话历史，都在这里开关。会话历史默认关闭。

### 目录浏览和面板切换

侧面板的 **Files** 视图可以浏览会话所在的文件夹，点一个文件就在文件窗格里打开，带语法高亮。文件树上方有一行选择"点击文件后做什么"：在树下预览、在文件窗格打开，或用主机的编辑器打开。

键盘操作：

- ●⇧⌘E：打开或关闭侧面板，恢复到上次看的视图；
- ●⌥⌘F：直接切到 Files。

Windows 和 Linux 上对应的是 Ctrl+Shift+E 和 Ctrl+Alt+F。

### 退出和确认框

- ● **`quit-ends-sessions = true`** ：每次退出（点关闭按钮、⌘Q、菜单），都会结束本机的全部会话和其中的程序，并停止 kerod，与"退出并结束所有会话"相同。其他机器上的会话继续运行。
- ● **确认框的取消按钮修好了。** 有程序在运行时，确认框会先问一次，并且不再响应回车——因为回车可能被正在运行的程序读到——只能点击或按 Esc。

六、为什么选择原生终端

同类工具不少，比如 Rex、Herdr、Paseo（之前写过 Paseo 的体验）。Kero 的取舍比较克制：

- ● **不是一套新的 agent 框架** 。Claude Code、Codex、Pi、OpenCode、shell 都能直接跑，它只负责"装"和"管"。
- ● **原生渲染** 。用 libghostty 而不是 Web 技术画终端，滚动、字体、颜色都更接近你熟悉的 Ghostty。
- ● **常驻守护进程** 。会话和窗口解耦，这是它能做到"关掉再打开一切都在"的原因。

Kero 还年轻，有些细节不够完善，比如窗口变窄时侧边栏会被挤压。但方向上它很明确：**终端本身就是智能体的工作台，而不是困住智能体的盒子。**以后的功能还会更多。

七、结语

如果你也同时开着好几个 agent，想先原汁原味地体验 Kero，就装上游版本；想要上面这些补充功能，可以直接装我的分支。第一次用，先试这几件事：

1. 1.在项目目录里开一个 Claude Code 会话；
2. 2.让它在运行时切换到别的会话，看侧边栏状态怎么变；
3. 3.按⌘J跳回需要你的那个；
4. 4.关掉窗口再打开，看看会话是不是还在。
