在 **SWE-bench-Live** 的 Lite 分榜上，登顶全球第一的方案，用的不是 GPT，不是 Claude，是一个开源模型—— **DeepSeek-v4.1-Flash** 。

它的成绩是 **71%** 的问题解决率。

而给它装上眼睛、手和工作习惯的，是联想天禧 AI 自研的代码智能体框架 **TianxiCode** 。

组合通过官方审核，拿到了 "Verified" 认证。

康老板看到这条消息的时候，第一反应不是「联想也能做 AI」，而是—— **我们过去两年可能一直把钱花错了地方。**

---

## 这个榜单为什么不能靠蒙

SWE-bench-Live 和那些考语法、考单函数生成的传统代码测试，完全不是一回事。

它以 **真实 GitHub 项目里的真实问题** 为基础，评估模型或智能体生成补丁、修复故障的能力，并提供可复现的执行环境。

也就是说，它不考「你会不会写快排」，它考「这个开源项目里有个 bug 挂了三个月，你能不能把它修好」。

更狠的是核验机制。官方设了 "Verified" 一关：参评方案必须提交 **全链路的智能体运行轨迹** ，由官方团队严格审查评测输入、信息隔离环境，并彻底排查有没有向智能体泄露标准答案、测试用例或结果。

**你交的不是一份答案，是你整个干活过程的录像。**

TianxiCode 与 DeepSeek-v4.1-Flash 通过了这一关。

## 大脑和手，是两回事

联想给了一个很朴素的比方，康老板觉得说得挺准。

如果把这套系统比作一个软件工程师， **DeepSeek-v4.1-Flash 是大脑** ，负责读代码、理解语义、构思解法； **TianxiCode 是眼睛、手、工具箱和工作流规范** 。

再聪明的大脑，没有能敲代码、查日志的手，没有严谨的工作习惯，在复杂的现实工程里也修不好一个 Bug。

榜单对比数据印证了这一点： **缺乏顶层智能体架构的系统协同，即便调用顶级闭源模型，面对真实工程难题也常常束手无策。**

TianxiCode 具体有三大能力。

**第一，跨文件多跳检索与精准上下文管理。** 像资深工程师一样顺藤摸瓜，在大型代码库里快速定位缺陷根因。同时做上下文剪枝和切片，不让无关代码把上下文撑爆。

**第二，自驱动规划与多轮工具调用。** 遇到 Bug 先列排错计划，主动打开终端跑测试、翻日志、比对修改记录。解决不了会换个思路继续排查，自主推进。

**第三，闭环补丁生成与测试驱动自愈。** 自动在隔离环境里跑代码，一旦发现新代码报错或破坏了其他功能，立刻自我反思和修改，直到补丁通过项目验收。

**这三条，没有一条是模型的本事。全是工程。**

## 三条正在作废的规矩

**第一条，「买更强的模型 = 更强的效果」失效了。**

这次第一用的是开源模型。决定上限的不是模型的智商，是 **你给它配了多少工程约束** 。

康老板一直跟身边人说，AI 编程这件事，模型是发动机，框架是底盘。你现在花大价钱换发动机，却让同一台车跑在烂底盘上，能快到哪去？

**第二条，「自研框架不如买 API」这个账要重算了。**

过去两年，绝大多数团队的选择是：接一个最强的闭源 API，写几句提示词，完事。这套做法在单文件 demo 里看起来很美，一进真实工程就露馅——改不动、查不到、修不对。

SWE-bench-Live 考的就是真实工程。 **在这张卷子上，框架的分值比模型高。**

**第三条，「闭源一定比开源强」在编程赛道上被掀了桌。**

71% 这个数字不是孤例。开源编程生态今年以来涨得极猛，社区驱动的智能体项目月活已经冲到数百万量级。开源模型配自研框架，正在成为一条成本更低、可控性更强的路径。

## 对编程之外的推演

把这件事推到所有行业。

任何一个「用 AI 干活」的场景，都可以拆成两层： **决策层（想什么）和执行层（怎么干到）** 。

过去两年，所有人的钱和注意力都砸在决策层上——谁的模型更强、谁的榜单更高。执行层基本是裸奔的：给个提示词，跑一遍，输出不对就再跑一遍。

**这不叫自动化，这叫碰运气。**

真正能在生产环境里跑起来的东西，靠的是执行层的工程：怎么找、怎么验、怎么回滚、怎么在失败时自愈。

康老板的判断很明确： **AI 落地这件事，2026 年的胜负手已经从「选哪个模型」转向「你有没有一套自己的工作流」。**

模型会越来越便宜、越来越同质化。工作流不会。它是你踩过的坑、修过的 bug、被线上事故教育过的经验。 **这才是别人拿不走的东西。**

再说个更现实的。联想这次把 TianxiCode 明确定位成天禧 AI 生态的代码智能子能力，未来要应用到联想的 AI 硬件产品里。

**一个卖电脑的公司，把自研编程智能体塞进自己的硬件。** 这条路径很值得琢磨——硬件是入口，框架是黏性，模型是水电煤。

## 这事跟程序员有什么关系

三层，说完就收。

**第一层，在职程序员。** 别再比谁提示词写得花了。去学 **怎么给 AI 搭工程环境** ：上下文怎么切、工具怎么接、失败怎么重试、改动怎么验。这套东西现在叫 Agent 工程，两年内会变成和「会用 Git」一样的基础技能。

**第二层，想转行的人。** 这是好消息。做 Agent 框架不需要你去训模型、不需要你懂反向传播，需要的是你做过真实项目、知道 bug 是怎么被修好的。 **工程经验第一次比算法理论更值钱。**

**第三层，小团队和副业选手。** 顶级闭源 API 你按 token 付费，用一次肉疼一次。开源模型 + 自研框架，跑在本地或者便宜的云上，成本差一个数量级。这意味着 **小团队第一次有机会在成本上正面刚大厂。**

**模型是租来的，工作流才是自己的。**
