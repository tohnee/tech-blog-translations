## 背景

之前张量并行和序列并行存在的问题之一就是，如果模型过大，单个节点上4到8个GPU也无法承载，加上节点间的连接带宽较低，将会出现严重的性能下降。可通过流水线并行来解决。

## 流水线并行

将模型的多层拆分到多个GPU上(如有8层和2个GPU，将1到4层放在GPU1上，5到8层放在GPU2上)，这样每个GPU只需要存储和处理模型的一部分层，从而显著降低每个GPU的内存需求；

流水线并行中，每个GPU开始第一次反向传播，都需要先执行PP(流水线并行度)次前向传播；每个GPU只负责整个模型中1/PP的层数，但必须处理PP个微批次才能开始反向传播。因此，最终需要存储的激活内存量为PP*(activs/PP)，约等于activs，即激活内存的总需求与不使用流水线并行时几乎相同。

流水线并行的主要挑战在于如何高效地克服串行特性，以确保所有GPU始终处于忙碌状态，避免出现一个GPU在计算而其他GPU处于空闲等待的情况。

### a）全前向全反向(AFAB)调度

朴素的流水线实现如下：

![](https://pic3.zhimg.com/v2-e526ab534f81a5f6899ea08935e45644_r.jpg)

剩余的空闲时间用灰色表示，通常称为“气泡”(bubble)。通过气泡造成的时间损失来量化流水线并行的效率。

假设 $t_f$ 表示一次前向传播的时间， $t_b$ 表示一次反向传播的时间，常见的假设是 $t_b$ 约等于两倍的 $t_f$ 。如果能做到完全并行化，理想总耗时为 $t_{ideal}=t_f+t_b$ ，然而实际上由于存在流水线气泡，会额外增加一段时间，即 $t_{pb}=(p-1)*(t_f+t_b)$ ，其中p表示流水线并行度(即GPU数量)；

气泡时间占理想时间的比例为：

$r_{bubble}=\frac{(p-1)*(t_f+t_b)}{t_f+t_b}=p-1$

可见，增加流水线并行度(即增加GPU数量)时，气泡时间也会线性增加，因而整体利用率下降。

在最朴素的流水线实现中，气泡可能性非常大，导致训练效率明显下降。将批次划分为更小的、可并行出来的微批次，这样当第二个GPU正在处理微批次1时，第一个GPU就可开始处理微批次2，下面是使用8个微批次的流水线调度示例：

![](https://pica.zhimg.com/v2-635c9087a601b16a705eb78dd62f36b8_r.jpg)

上面称为全前向全反向调度，因为首先完成所有的前向传播，然后再执行所有的反向传播。处理m个微批次的理想总时间为 $t_{ideal}=m*(t_f+t_b)$ ，因此气泡时间相对于理想时间的比例为：

$r_{bubble}=\frac{(p-1)*(t_f+t_b)}{m*(t_f+t_b)}=\frac{p-1}{m}$

可看到，增加微批次数量m，可显著减少流水线中的气泡大小，减少比例约为1/m。换句话说，更多的微批次可提高流水线的利用率；

但需要存储所有激活值所需的内存(必须在前向传播完成后一直保存所有激活，直到对应的反向传播开始)，这会导致激活值内存迅速膨胀。

既然内存爆炸是由反向传播而保存的激活值引起的，可尝试在执行前向计算的同时，就开始执行部分反向传播，这样就可尽早释放部分激活，从而有效缓解内存占用问题。

### b）一前向一反向(1F1B)调度

在中间/稳定阶段，会交替执行一次前向传播和一次反向传播，核心思想是尽可能早地开始执行反向传播，调度执行流程如下：

![](https://pic3.zhimg.com/v2-8bb1d250f7ed74601f24a9ce1e75b232_r.jpg)

仔细观察，发现气泡大小其实依然相同，因此训练效率并没有显著提升。有一个改进就是，只需要p个微批次存储激活值而不是m个微批次，这样大大减少了AFAB出现的激活值内存爆炸问题。

尽管1F1B调度显著减少激活值内存占用，流水线气泡依然是主要的效率瓶颈，由于气泡大小仍然与流水线阶段成正比，意味着仍然大量GPU计算资源处于空闲状态。

### c）交错式调度

将模型的网络层交错放在GPU上，如将奇数层(第1,3,5,7层)放在第一个GPU上，偶数层(第2,4,6,8层)放在第二个GPU上。下图展示了将模型层交错分布到4个GPU上，数字表示微批次ID，对模型的第一层和最后一层使用不同的颜色。

![](https://pica.zhimg.com/v2-c729ccf7ba9d68746c8ac49481fb37e8_r.jpg)

这里需要额外的通信，因为模型对每个GPU需要进行多次计算，而之前仅需一次遍历即可完成。由于能够更好交错前向和反向传播过程，每次前向和反向传播的开销被分摊为原来的1/v，v表示每个GPU上的阶段数(即模型分块数)。

$t_{pb}=\frac{(p-1)*(t_f+t_b)}{v}$

$r_{bubble}=\frac{1}{v}\frac{(p-1)*(t_f+t_b)}{m*(t_f+t_b)}=\frac{p-1}{v*m}$

可通过引入微批次和交错式阶段来减少“气泡”开销，但通信量相应增加v倍。

### d）Zero Bubble

使用更复杂的方法来减少气泡，通过矩阵乘法的反向传播实际上涉及两个独立的操作，对输入的反向操作B和对权重的反向操作W。虽然输入的反向操作B的输出对于执行更低层的反向传播是必需的，但权重的反向操作W则不是，并且通常只需要在优化步骤之前执行。这意味着，W可在与同阶段的B执行之后，灵活地调度到任意为止，使得我们可策略性安排W的执行，以填充流水线中的“气泡”，如下图所示：

![](https://pic3.zhimg.com/v2-dac98c1bd077d844cbcb79351990db32_r.jpg)

### e）DualPipe

从流水线并行两端开始传播数据流，将这两个数据流交错执行，进一步最小化GPU的空闲时间；

## 代码实现

### a）流水线划分

PipelineParallel的初始化将模型各个网络层切分为各个流水线模块，并分配到流水线并行进程上。其中，Embedding层分配给流水线并行进程组的第一个进程(pp_is_first_stage为True)，模型最后的归一化层(final_norm)和投影层(final_proj)则分配给流水线并行进程组的最后一个进程(pp_is_last_stage为True)，中间的Transformer模块按照网络层数均分到各个流水线并行进程上，即每个并行进程分配的网络层数等于总网络层数除以流水线并行总进程数，每个流水线并行进程根据进程编号(即进程rank)获取连续的多个网络层，详见distributed_layers函数。

前向传播过程中，每个流水线并行进程均从前一阶段获取输出(流水线中第一个并行进程则直接获取输入token，并经过Embedding层，将其作为前一个阶段的输出)，意味着流水线中第一个并行进程的输入是input_ids，而其他流水线并行进程的输入是hidden_states；将从前一个阶段的输出作为输入，经过分配该进程的连续的多个网络层，如果是流水线中最后一个并行进程，还需要将其经过final_norm和final_proj，意味着self.embedding对于流水线中第一个进程是真实的Embedding层，self.final_norm和self.final_proj对于流水线中最后一个进程是真实的归一化层和投影层，对于其他进程来说都是一个“虚假层”(即nn.identity)；

反向传播时，如果从下一阶段获取的激活值不为None，则通过retain_grad设置保留该激活值的梯度，如果是流水线并行的最后一个进程(即从前一阶段获取的反向梯度为None)，则将下一个batch的输出梯度设置为全1张量；根据从下一阶段接收到激活值通过torch.autograd.backward计算梯度；如果从下一个阶段获取的激活值不为None，则返回该激活值的梯度；

```text
class PipelineParallel(nn.Module):
    """
    Implements pipeline parallelism by distributing model layers across multiple GPUs.
    Each GPU processes a subset of the model's layers in a pipeline fashion.
    """
    def __init__(self, model, config):
        super().__init__()
        # Determine which layers should be assigned to this GPU
        self.layer_distribution = self.distribute_layers(config.num_hidden_layers)
        # Only first stage has embedding layer, others use Identity
        self.embedding = model.embedding if pgm.process_group_manager.pp_is_first_stage else nn.Identity()
        # Assign relevant decoder layers to this GPU
        self.decoder_layers = nn.ModuleDict({str(i): model.decoder_layers[i] for i in self.layer_distribution})
        # Only last stage has normalization and projection layers
        self.final_norm = model.final_norm if pgm.process_group_manager.pp_is_last_stage else nn.Identity()
        self.final_proj = model.final_proj if pgm.process_group_manager.pp_is_last_stage else nn.Identity()

        self.reset_parameters()
    
    def reset_parameters(self):
        """Initialize or reset all model parameters for this pipeline stage."""
        if pgm.process_group_manager.pp_is_first_stage:
            self.embedding.reset_parameters()

        for layer in self.decoder_layers.values():
            layer.input_layernorm.reset_parameters()
            layer.attention.reset_parameters()
            layer.post_attention_layernorm.reset_parameters()
            layer.mlp.reset_parameters()

        if pgm.process_group_manager.pp_is_last_stage:
            self.final_norm.reset_parameters()
            self.final_proj.reset_parameters()

    def distribute_layers(self, num_layers):
        """
        Distribute model layers across GPUs as evenly as possible.
        Returns the layer indices that should be processed by this GPU.
        """
        # Calculate layers per GPU, handling uneven distribution
        layers_per_gpu = [num_layers // pgm.process_group_manager.pp_world_size + (1 if i < num_layers % pgm.process_group_manager.pp_world_size else 0) for i in range(pgm.process_group_manager.pp_world_size)]
        # Calculate starting layer for this GPU
        start_layer = sum(layers_per_gpu[:pgm.process_group_manager.pp_rank])
        return list(range(start_layer, start_layer + layers_per_gpu[pgm.process_group_manager.pp_rank]))

    def forward(self, input_ids, position_ids, hidden_states):
        """
        Forward pass for this pipeline stage.
        Processes input through assigned layers and passes result to next stage.
        """
        x = hidden_states if hidden_states is not None else input_ids
        x = self.embedding(x)
        for layer in self.decoder_layers.values():
            x = layer(x, position_ids=position_ids)
        x = self.final_norm(x)
        return self.final_proj(x)

    def backward(self, input_tensor, output_tensor, output_tensor_grad):
        """
        Backward pass for this pipeline stage.
        Computes gradients for assigned layers using received gradient from next stage.
        """
        if input_tensor is not None: input_tensor.retain_grad()
        if output_tensor_grad is None:
            output_tensor_grad = torch.ones_like(output_tensor, memory_format=torch.preserve_format)
        # torch.autograd.backward will automatically accumulates gradients in the leaves (cf: https://pytorch.org/docs/stable/generated/torch.autograd.backward.html)
        torch.autograd.backward(output_tensor, grad_tensors=output_tensor_grad, retain_graph=False, create_graph=False)
        return input_tensor.grad if input_tensor is not None else None        
```

上述方法直接按照网络层进行划分，可能会导致流水线上各个阶段的负载不均衡，进而产生的“气泡”更多。一种优化方法是，先计算各个网络层的计算开销，然后计算均摊到每个流水线阶段的计算开销，如nanotron中get_block_compute_costs函数计算网络层的计算开销，build_model函数首先统计整个模型的计算总开销，然后计算均分给每个流水线并行进程的最大计算开销，并根据该最大计算开销依次各个网络层分配给流水线并行进程。

```text
def get_block_compute_costs(self):
    """Computes the compute cost of each block in the model so that we can do a better job of load balancing."""
    model_config = self.config
    d_ff = model_config.intermediate_size
    d_qkv = model_config.hidden_size // model_config.num_attention_heads
    block_compute_costs = {
        # CausalSelfAttention (qkv proj + attn out) + MLP
        LlaMoEDecoderLayer: 4 * model_config.num_attention_heads * d_qkv * model_config.hidden_size
            + 3 * d_ff * model_config.hidden_size,
        # This is the last lm_head
        TensorParallelColumnLinear: model_config.vocab_size * model_config.hidden_size,
    }
    return block_compute_costs

def build_model(
    model_builder: Callable[[], NanotronModel],
    parallel_context: ParallelContext,
    dtype: torch.dtype,
    target_pp_ranks: Optional[List[int]] = None,
    device: Optional[torch.device] = torch.device("cuda"),
) -> NanotronModel:
    """Build the model and set the pp ranks for each pipeline block."""
    # TODO: classes dont take same args
    log_rank(
        "Building model", logger=logger, level=logging.INFO, rank=0, group=parallel_context.world_pg, is_separator=True
    )
    model: NanotronModel = model_builder()

    # If no target pp ranks are specified, we assume that we want to use all pp ranks
    if target_pp_ranks is None:
        pp_size = parallel_context.pp_pg.size()
        target_pp_ranks = list(range(pp_size))
    else:
        pp_size = len(target_pp_ranks)

    # Set rank for each pipeline block
    log_rank("Setting PP block ranks...", logger=logger, level=logging.INFO, rank=0, group=parallel_context.world_pg)
    pipeline_blocks = [module for name, module in model.named_modules() if isinstance(module, PipelineBlock)]
    # "cuda" is already defaulted for each process to it's own cuda device
    with init_on_device_and_dtype(device=device, dtype=dtype):
        # TODO: https://github.com/huggingface/nanotron/issues/65

        # Balance compute across PP blocks
        block_compute_costs = model.get_block_compute_costs()
        block_cumulative_costs = np.cumsum(
            [
                block_compute_costs[module.module_builder] if module.module_builder in block_compute_costs else 0
                for module in pipeline_blocks
            ]
        )

        thresholds = [block_cumulative_costs[-1] * ((rank + 1) / pp_size) for rank in range(pp_size)]
        assert thresholds[-1] >= block_cumulative_costs[-1]
        target_pp_rank_idx = 0
        for block, cumulative_cost in zip(pipeline_blocks, block_cumulative_costs):
            assert target_pp_rank_idx < pp_size
            block.build_and_set_rank(target_pp_ranks[target_pp_rank_idx])

            if cumulative_cost > thresholds[target_pp_rank_idx]:
                target_pp_rank_idx += 1

        model.input_pp_rank = target_pp_ranks[0]
        model.output_pp_rank = target_pp_ranks[target_pp_rank_idx]

    if pp_size > 1:
        model.log_modules(level=logging.INFO, group=parallel_context.world_pg, rank=0)
    return model
```

### b）AFAB

train_step_pipeline_afab完成全前向全反向流水线调度。

首先，执行所有的前向传播，即执行指定的梯度累积步数从流水线前一阶段接收激活值(通信操作为"recv_forward")；通过数据集加载器(MicroBatchDataLoader)加载下一个batch的数据；将从流水线前一阶段接收到的激活值添加到下一个batch的hidden_states字段中；根据下一个batch中的输入(如input_ids、position_ids等)和从前一阶段获取的激活值执行前向传播(详见上面的PipelineParallel的forward函数)，得到下一个batch的激活值；将下一个batch的激活值发送给流水线的下一个阶段(通信操作为“send_forward”)；如果是流水线中最后一个并行进程，则根据下一个batch的激活值以及下一个batch的目标token(即target_ids)计算交叉熵损失，并除以梯度累积步数，得到梯度累积上的损失均值；将从流水线前一阶段接收的激活值以及下一个batch的激活值保存到局部变量input_tensors和output_tensors中；

其次，执行所有的反向传播，即执行指定的梯度累积步数(MicroBatchDataLoader的grad_acc_steps取值为1)。如果是梯度累积步数的最后一步，将模型的require_backward_grad_sync设置为True；从流水线的下一个阶段获取梯度(通信操作为"recv_backward")；从局部变量input_tensors和output_tensors中弹出最开始存入的梯度累积步数的输入激活值和下一个batch的激活值(流水线中只有最后一个并行进程最开始计算梯度)；根据输入激活值和下一个batch的激活值等进行反向梯度传播(详见PipelineParallel的backward函数)；将反向梯度发送给流水线的前一个阶段(通信操作为“send_backward”)；

```python3
def train_step_pipeline_afab(model, data_loader, tensor_shapes, device, dtype):
    """
    Implements All-Forward-All-Backward (AFAB) pipeline parallel training.
    First performs all forward passes, then all backward passes sequentially.
    
    Args:
        model: The pipeline parallel model
        data_loader: Iterator providing training batches
        tensor_shapes: Expected shapes of tensors for communication
        device: Device to run computations on
        dtype: Data type for tensors
    """
    logging_loss: torch.float32 = 0.0
    # Store tensors to recreate computation graph during backward pass
    input_tensors, output_tensors = [], []
    requires_grad_sync = pgm.process_group_manager.cp_dp_world_size > 1

    for _ in range(data_loader.grad_acc_steps): # All forward passes
        # communication: receive the activation from the previous stage
        input_tensor = pipeline_communicate(operation='recv_forward', shapes=tensor_shapes, device=device, dtype=dtype)
        # or fetch from data loader
        batch = next(data_loader)
        batch["hidden_states"] = input_tensor.to(device) if input_tensor is not None else input_tensor
        # forward: pass
        output_tensor = model.forward(input_ids=batch["input_ids"].to(device), position_ids=batch["position_ids"].to(device), hidden_states=batch["hidden_states"])
        # communication: send the activation to the next stage
        pipeline_communicate(operation='send_forward', tensor=output_tensor, device=device, dtype=dtype)
        
        # calculate loss on the last stage
        if pgm.process_group_manager.pp_is_last_stage:
            output_tensor = F.cross_entropy(output_tensor.flatten(0, 1), batch["target_ids"].to(device).flatten(), reduction='mean')
            logging_loss += output_tensor.item() / data_loader.grad_acc_steps

        # Save input/output activations to reconstruct computation graph during backward pass
        input_tensors.append(input_tensor)
        output_tensors.append(output_tensor)

    for ith_microbatch in range(data_loader.grad_acc_steps): # All backward passes
        if requires_grad_sync:
            is_last_iteration = (ith_microbatch == data_loader.grad_acc_steps - 1)
            model.require_backward_grad_sync = is_last_iteration
        # communication: receive the gradient from the next stage
        output_tensor_grad = pipeline_communicate(operation='recv_backward', shapes=tensor_shapes, device=device, dtype=dtype)
        # Retrieve saved input/output activations in FIFO order to match forward pass sequence
        input_tensor, output_tensor = input_tensors.pop(0), output_tensors.pop(0)
        # backward: pass
        input_tensor_grad = model.backward(input_tensor, output_tensor, output_tensor_grad)
        # communication: send the gradient to the previous stage
        pipeline_communicate(operation='send_backward', tensor=input_tensor_grad, device=device, dtype=dtype)

    return logging_loss
```

### c）1F1B

train_step_pipeline_1f1b完成一前向一反向的流水线调度。

首先，计算每个流水线并行进程需要预热的微批次数，即流水线并行进程数减去当前进程rank-1与梯度累积步数的最小值(如流水线并行进程数为4，那么进程0的预热微批次数为3，进程1需要的预热微批次数为2，进程2需要的预热微批次数为1等)；计算执行梯度累积剩余微批次数，即梯度累积步数减去预热微批次数；

接着，执行需要预热的微批次数。从流水线前一阶段获取激活值(通信操作为“recv_forward”)；根据前一阶段的激活值执行前向传播，得到激活值(从数据加载器中获取下一批次的数据集，将前一阶段获取到的激活值更新到下一批次的hidden_states字段中，并根据下一批次的数据执行前向传播，即PipelineParallel的forward函数，如果是流水线的最后一个阶段，则根据目标token和输出的激活值计算交叉熵损失，并除以累积梯度步数)；将激活值发送给流水线的下一个阶段(通信操作为“send_forward”)；将当前阶段的输入激活值和输出激活值更新到局部变量input_tensors和output_tensors中；

再者，如果需要执行梯度累积的剩余微批次数大于0，则等待从流水线的前一阶段获取激活值(通信操作为“recv_forward”)；如果同时执行上下文并行和数据并行，将模型的require_backward_grad_sync设置为false；

然后，执行梯度累积的剩余的微批次数。根据流水线前一阶段获取的激活值执行前向传播(详见_forward_step)，向流水线的下一个阶段发送激活值并从前一个阶段获取反向梯度(通信操作为“send_fwd_recv_bwd”)，将当前阶段的输入激活值和输出激活值更新到局部变量input_tensors和output_tensors中；从局部变量input_tensors和output_tensors中弹出最开始添加进去的微批次输入激活值和输出激活值；如果需要预热微批次数为0且是最后一个微批次，则将模型的require_backward_grad_sync设置为True；根据输入激活值和输出激活值执行反向梯度传播(详见PipelineParallel的backward函数)；如果是最后一个微批次，则将input_tensors设置为None，同时将反向梯度发送给前一个阶段(通信操作为“send_backward”)，否则向流水线的下一个阶段发送激活值并从前一个阶段获取反向梯度(通信操作为“send_fwd_recv_bwd”)；

最后，再次执行预热微批次数。如果是最后一个微批次，将模型的require_backward_grad_sync设置为Trye；从局部变量input_tensors和output_tensors中弹出最开始添加进去的微批次输入激活值和输出激活值；从前一个阶段获取反向梯度(通信操作为“recv_backward”)，根据微批次输入激活值和输出激活值执行反向梯度，将反向梯度发送给流水线的下一个阶段(通信操作为“send_backward”)；

```text
def train_step_pipeline_1f1b(model, data_loader, tensor_shapes, device, dtype):    
    """
    Implements 1F1B (one-forward-one-backward) pipeline parallel training.
    Interleaves forward and backward passes to improve GPU utilization.
    
    Pipeline stages:
    1. Warmup phase: Forward passes to fill pipeline
    2. Steady state: Alternating forward and backward passes
    3. Cooldown phase: Remaining backward passes
    
    Args:
        model: The pipeline parallel model
        data_loader: Iterator providing training batches
        tensor_shapes: Expected shapes of tensors for communication
        device: Device to run computations on
        dtype: Data type for tensors
    """
    # Calculate number of warmup microbatches needed
    num_warmup_microbatches = min(pgm.process_group_manager.pp_world_size - pgm.process_group_manager.pp_rank - 1, data_loader.grad_acc_steps)
    num_microbatches_remaining = data_loader.grad_acc_steps - num_warmup_microbatches
    logging_loss, input_tensors, output_tensors  = 0.0, [], []
    requires_grad_sync = pgm.process_group_manager.cp_dp_world_size > 1
    
    def _forward_step(input_tensor):
        """Helper function to perform a single forward step in the pipeline."""
        batch = next(data_loader)
        batch["hidden_states"] = input_tensor.to(device) if input_tensor is not None else input_tensor
        output_tensor = model.forward(input_ids=batch["input_ids"].to(device), position_ids=batch["position_ids"].to(device), hidden_states=batch["hidden_states"])
        
        # calculate loss on the last stage
        if pgm.process_group_manager.pp_is_last_stage:
            output_tensor = F.cross_entropy(output_tensor.flatten(0, 1), batch["target_ids"].to(device).flatten(), reduction='mean')
            nonlocal logging_loss
            logging_loss += output_tensor.item() / data_loader.grad_acc_steps
        return output_tensor

    # Warmup Phase: Fill the pipeline with forward passes
    for _ in range(num_warmup_microbatches):
        input_tensor = pipeline_communicate(operation='recv_forward', shapes=tensor_shapes, device=device, dtype=dtype)
        output_tensor = _forward_step(input_tensor)
        pipeline_communicate(operation='send_forward', tensor=output_tensor, device=device, dtype=dtype)
        # Store tensors for later backward passes during cooldown phase
        input_tensors.append(input_tensor)
        output_tensors.append(output_tensor)
        #TODO: we should call deallocate_output_tensor as in Megatron-LM
        # During pipeline parallel training, we need to save output tensors for the backward pass.
        # However, between producing an output tensor and using it for backprop, the tensor's data
        # sits idle in memory while only its grad_fn is needed for the computational graph.
        # deallocate_output_tensor replaces the tensor's data with a minimal scalar tensor 
        # (cf https://github.com/NVIDIA/Megatron-LM/blob/main/megatron/core/pipeline_parallel/schedules.py#L115),
        # dramatically reducing memory usage while preserving the ability to do backprop later.

    # Steady State Phase: Alternate between forward and backward passes
    if num_microbatches_remaining > 0:
        input_tensor = pipeline_communicate(operation='recv_forward', shapes=tensor_shapes, device=device, dtype=dtype)
    
    #NOTE: Explanation as to how to make DP and PP work together: https://github.com/huggingface/picotron/pull/5#issue-2629838274
    if requires_grad_sync:
        model.require_backward_grad_sync = False

    for ith_microbatch in range(num_microbatches_remaining):  # 1F1B steady state
        is_last_iteration = (ith_microbatch == num_microbatches_remaining - 1)
        output_tensor = _forward_step(input_tensor)
        output_tensor_grad = bidirectional_pipeline_communicate(operation='send_fwd_recv_bwd', send_tensor=output_tensor, recv_shapes=tensor_shapes, device=device, dtype=dtype)
        # Store current tensors for next backward pass
        input_tensors.append(input_tensor)
        output_tensors.append(output_tensor)
        # Retrieve oldest tensors for current backward pass (FIFO order)
        input_tensor, output_tensor = input_tensors.pop(0), output_tensors.pop(0)
        
        # Trigger gradient sync on the last microbatch but only when last rank (the one that has num_warmup_microbatches = 0) has finished computing its backward pass.
        if num_warmup_microbatches == 0 and is_last_iteration:
            model.require_backward_grad_sync = True

        input_tensor_grad = model.backward(input_tensor, output_tensor, output_tensor_grad)
        
        if is_last_iteration:
            input_tensor = None
            pipeline_communicate(operation='send_backward', tensor=input_tensor_grad, device=device, dtype=dtype)
        else:
            input_tensor = bidirectional_pipeline_communicate(operation='send_bwd_recv_fwd', send_tensor=input_tensor_grad, recv_shapes=tensor_shapes, device=device, dtype=dtype)

    # Cooldown Phase: Complete remaining backward passes
    for ith_warmup_microbatches in range(num_warmup_microbatches):
        if requires_grad_sync:
            is_last_iteration = (ith_warmup_microbatches == num_warmup_microbatches - 1)
            model.require_backward_grad_sync = (ith_warmup_microbatches == num_warmup_microbatches - 1)
        # Process remaining stored tensors from warmup phase in FIFO order
        input_tensor, output_tensor = input_tensors.pop(0), output_tensors.pop(0)
        output_tensor_grad = pipeline_communicate(operation='recv_backward', shapes=tensor_shapes, device=device, dtype=dtype)
        input_tensor_grad = model.backward(input_tensor, output_tensor, output_tensor_grad)
        pipeline_communicate(operation='send_backward', tensor=input_tensor_grad, device=device, dtype=dtype)

    return logging_loss
```
