## GPU结构基础

我们首先介绍一点点GPU的结构 (以Ampere架构为例)

![](https://pic2.zhimg.com/v2-4cf94c4f5198a754c43379750490f7ab_r.jpg)

### SIMT Core

图中四个板块中的每块被称为SIMT Core, 他是CUDA执行模型中最基本的执行单元（在执行过程中会将 Warp 分配到 SIMT core 上，我们下面为了简单起见就先把它叫做warp啦）：

- 计算:
- Warp为一定数量(通常为32)的时钟同步的线程提供计算和存储资源。CUDA多线程执行符合SIMT (Single Instruction, Multiple Threads)模型，每个线程在不同的数据上执行相同的指令。
- 单个Warp配备了不同精度的CUDA Core以及针对特殊函数(如exp)的SFU给线程执行计算。
- 为了实现更高效的矩阵乘法运算，从Volta架构开始，每个warp上配备了Tensor Core(张量核)。Tensor Core能在单个instruction cycle内完成小规模的混合精度矩阵乘法。
- 通信：
- 处于同一warp的threads可以通过特定的操作(e.g. `__shfl_sync`, `__shfl_down_sync`)进行数据交换
- 也可以通过读写shared memory实现数据交换
- 内存：
- 单个Warp内包含了一个L0 instruction cache用于存储频繁使用的instructions
- 每个线程最多可以使用255个32-bit registers。
- 单个Warp可以在一次memory transaction中读取/写入128个连续的byte进Global Memory

### Streaming Processor (SM)

再往上看一层是**Streaming Multi-processor (SM)**。相同Thread Block中所有线程会被调度到相同的SM上被执行。同样以Ampere架构为例:

- 每个SM可以并行执行4个warp并分别为每个warp提供了上述计算和存储资源
- 在同一个SM上的线程共享同一片L1 Cache和Shared Memory。在Ampere架构中Shared Memory最大限制为163 KB。实际上L1 Cache和Shared Memory占用相同的存储硬件，这块内存的总大小为164 KB，其中shared memory可以被开发者手动申请和管理。L1 Cache扮演类似L2 cache的角色，线程上无法被register缓存的数据会依次spill到L1 cache, L2 cache和Global Memory
- 每个SM为4个warp配置了4个warp scheduler和4个instruction dispatch units。 当一个thread block被调度到当前的SM上，其中的线程被划分为warps，每个时钟周期内各个warp scheduler调度warps到物理硬件上被执行。

## CUDA版本Softmax的最简单实现

我们首先用CUDA实现Softmax function，单个thread负责一整行数据，对单行数据做3-pass softmax，每次从Global Memory中读取单个FP32数据并做对应的处理：

```cpp
// CUDA kernel for naive softmax implementation
__global__ void naive_softmax_kernel(float* x, float* y, int batch_size, int hidden_dim) {
    // Each thread processes one row of the input matrix x
    int row_idx = blockIdx.x * blockDim.x + threadIdx.x;
    // Boundary check
    if (row_idx >= batch_size) return;

    // Calculate the maximum value in the row
    float max_val = -FLT_MAX;
    for (int i = 0; i < hidden_dim; i++) {
        float tmp_val = x[row_idx * hidden_dim + i];  // Read from global memory
        max_val = max(max_val, tmp_val);
    }

    // Calculate the sum of exponentials
    float sum_exp = 0.0f;
    for (int i = 0; i < hidden_dim; i++) {
        float tmp_val = x[row_idx * hidden_dim + i];  // Read from global memory
        sum_exp += expf(tmp_val - max_val);
    }

    // Write the softmax output
    for (int i = 0; i < hidden_dim; i++) {
        float tmp_val = x[row_idx * hidden_dim + i];  // Read from global memory
        y[row_idx * hidden_dim + i] = expf(tmp_val - max_val) / sum_exp;  // Write to global memory
    }
}

```

调用这个kernel的代码是这样的，可以理解为kernel写得是循环体，`naive_softmax_kernel<<<dimGrid, dimBlock>>>`是两重循环，循环是并行化的

```cpp
torch::Tensor naive_softmax(torch::Tensor X) {
    cudaSetDevice(X.get_device());

    int batch_size = X.size(0);
    int hidden_dim = X.size(1);
    torch::Tensor Y = torch::empty_like(X, X.options());

    // Thread block size
    const int num_threads = 128;
    // Grid size (= need number of thread blocks)
    int num_blocks = (batch_size + num_threads - 1) / num_threads;

    // Launch the kernel
    const dim3 dimBlock(num_threads);
    const dim3 dimGrid(num_blocks);
    naive_softmax_kernel<<<dimGrid, dimBlock>>>(
        X.data_ptr<float>(),  // Pointer to input data
        Y.data_ptr<float>(),  // Pointer to output data
        batch_size, hidden_dim
    );

    return Y;
}

```

## CUDA版本一个更好的Softmax

### 简单实现的缺点

我们在A100上跑一下这个kernel，发现它非常慢。

![](https://pica.zhimg.com/v2-a5a4161364ad1c8f261363137c3c4bf4_r.jpg)

### 低GPU使用率

在问题设置下仅有8765/128 = 69个线程块被使用，而A100 GPU当中有108个SM，GPU资源没有被完全利用

### 低效内存访问

- 每个warp每个cycle只能发出一次访存指令，单次访存指令最多可以从内存中load出连续的128 bits，而这里访问了32个位于不连续地址的bytes，访存bandwidth没有被完全利用；
- 每个线程只有255个register远小于hidden_dim = 4096，没法将一整行的数据一次性读进registers，使得每次loop都需要重新在Global Memory中读取数据

### 算子优化

### One Warp for one Row & Coalesced Memory Access

针对第一个问题，我们可以让32个线程(一个warp)负责一整行数据，使用更多的线程达到更大程度的硬件利用率。Warp内可以通过`shfl_sync()`进行通信来做reduction。

在我们使用一个warp处理数据时，单个线程只需要负责其中的4096/32=128个元素，使得每个线程可以将所有需要负责的数据读进register当中，而不需要重复地从Global Memory / L2 Cache中读数据。

进一步，考虑到GPU的访存bandwidth是针对连续的128 bytes优化的(如果单次访存需要访问不连续的128B数据会需要多次memory transaction消耗更多的时钟周期)，我们使用**Vectorized Memory Access**， 每个线程一次读取连续的4个FLOAT32数据使得单个warp一次尝试读取连续的32x4=128 Bytes:

```cpp
const int MEM_ACCESS_WIDTH = 4; //每次访问4个float32
const int VALS_PER_THREAD = 128; //每个线程需要访问的float32的个数 hidden_dim / 32 = 128
#pragma unroll //提示编译器展开循环
for (int i = 0; i < VALS_PER_THREAD; i+= MEM_ACCESS_WIDTH){
reinterpret_cast<float4*>(&tmp_val[i])[0] =
            reinterpret_cast<float4*>(&x[row_idx * N + i * WARP_SIZE + lane_idx * MEM_ACCESS_WIDTH])[0];
}

```

### Intra-Warp Reduction by `__shfl_xor_sync`

为了使每个warp计算出其负责的数据范围内的最大值和sum exp，我们使用基于shuffle sync的指令做数据交换实现max和sum的reduction操作，下图展示了max的计算逻辑:

![](https://pic4.zhimg.com/v2-bddbda5534adb9d2c0d35c054645e707_r.jpg)

对应的代码实现如下:

```cpp
float max_val = -FLT_MAX;
#pragma unroll
for (int i = 0; i < VALS_PER_THREAD; i++) {
    max_val = max(max_val, tmp_val[i]);
}
// Reduce the maximum value across all threads in the warp
#pragma unroll
for (int laneMask = 1; laneMask < WARP_SIZE; laneMask <<= 1) {
    max_val = max(max_val, __shfl_xor_sync(WARP_MASK, max_val, laneMask));
}

```

类似地，对于sum exp我们做如下操作:

```cpp
float sum_exp = 0.0f;
#pragma unroll
for (int i = 0; i < VALS_PER_THREAD; i++) {
    tmp_val[i] = expf(tmp_val[i] - max_val);
    sum_exp += tmp_val[i];
}
// Reduce the sum of exponentials across all threads in the warp
#pragma unroll
for (int laneMask = 1; laneMask < WARP_SIZE; laneMask <<= 1) {
    sum_exp += __shfl_xor_sync(WARP_MASK, sum_exp, laneMask);
}

```

我们再跑一下，发现它在小规模的问题设置下和Torch的算子速度相当

![](https://pica.zhimg.com/v2-5133d44d778613bede4f2ca7421573c4_r.jpg)

## 总结

我们最后再回顾一下我们是如何解决上述三个问题的:

### 更高的GPU使用率

每个warp负责一行数据，一个线程块使用了4个warp，线程块数量 = 8765 / 4 >> 108 (A100上的SM数量)。

### 更加高效的内存访问

- 使用一个warp处理单行数据后，每个线程负责更小的数据量可以将数据全部读进register从而避免重复的Global Memory access
- 使用vectorized memory access最大化对访存bandwidth的利用

## Triton版本的Softmax

我们下面介绍这次课程的主角——Triton，以及把CUDA的Softmax Kernel在Triton上重新写一遍~

### Triton简介

Triton可以把它定义的Triton Language编译为CUDA Kernels，一个比较大的好处是更加简洁，增加了可读性，上手成本更低。下面是Triton的编程模型，比CUDA简洁很多。

![](https://pic1.zhimg.com/v2-0b37539f7688b2c6c74e1f439e160dda_r.jpg)

CUDA程序是发生在Thread层面的，而Triton默认最后两层是不可见的。我们定义的每一行的Triton代码是发生在Thread Block层上的，给用户减少了很多的认知负担。我们下面介绍两个基础的特性： - **向量化的编程方式**： - 在Triton里面我们可以用tl.zeros()或者tl.range()定义数组，这些数组会被分配到一个Thread Block的寄存器或者Shared Memory里面的。 - 编译器会根据一些经验公式自动选择一个比较好的并行方式。 - **像Torch一样的函数和张量运算**： - 元素级别的运算：+-*\/ tl.exp() tl.log() - 某个维度上的运算：tl.sum()和tl.max() - 矩阵乘法：tl.dot()

### 如何写一个Triton Softmax Kernel

我们下面讲解如何用Triton改写上面的CUDA Softmax Kernel。在上面的Kernel当中，每个Warp负责一行，但是Triton编程当中看不到Warp这个层面。我们能做到的是定义每个Thread Block（4个Warps）做什么。

对于每一行，我们 - 读取数据 - 做Reduced Max - 做Reduced Sum - 存储数据

具体来说，左边这张图是CUDA Softmax，每个Warp是一行，每个线程是1/32行，右边是Triton Softmax，对于Triton来说你不需要认知这么多，减轻了很多认知负担。

![](https://pica.zhimg.com/v2-09e0b5c2a1b691cae5ed70fe4c02c026_r.jpg)

### 函数签名改写

```cpp
//CUDA Code
template<int VALS_PER_THREAD>  // Each thread (lane) processes VALS_PER_THREAD values
__global__ void better_softmax_kernel(float* x, float* y, int batch_size) {
    // Current warp index in the thread block
    const int warp_idx = threadIdx.x / WARP_SIZE;
    // Current thread lane index within the warp
    const int lane_idx = threadIdx.x % WARP_SIZE;

```

```python3
# Triton Code
@triton.jit
def softmax_kernel(
    x_ptr,  # Pointer to input tensor
    y_ptr,  # Pointer to output tensor
    batch_size,
    hidden_dim,
    BLOCK_SIZE_M: tl.constexpr,  # Block size for M (batch_size) dimension
    BLOCK_SIZE_N: tl.constexpr,  # Block size for N (hidden_dim) dimension
):
    # Equivalent to blockIdx in CUDA
    pid = tl.program_id(0)
```

函数声明里面多了两个参数，BLOCK_SIZE_M是一个Program处理多少条数据，BLOCK_SIZE_N是一个Program处理每条数据当中多大的维度。**这里BLOCK_SIZE_M和BLOCK_SIZE_N一般为2的整数次幂**。

对于CUDA而言，我们可以根据Thread Index找到Warp Index和Lane Index。在Triton当中，Thread和Warp都被隐藏了，我们只能用pid来定位这个函数的Block Index。

### Offset和Boundary Check的改写

接下来是一些Offset的计算和Boundary Check

```cpp
//CUDA Code
// Each warp processes one row
const int row_idx = blockIdx.x * num_warps + warp_idx;
// Boundary check
if (row_idx >= batch_size) return;

// Offset for contiguous memory access in a warp
const int offset = row_idx * (WARP_SIZE * VALS_PER_THREAD) + lane_idx * MEM_ACCESS_WIDTH;
# Triton Code
# Boundary check
start_m = pid * BLOCK_SIZE_M
if start_m >= batch_size:
    return

```

```python3
# Offsets for M and N dimensions
offs_m = start_m + tl.arange(0, BLOCK_SIZE_M)
offs_n = tl.arange(0, BLOCK_SIZE_N)
```

在CUDA程序当中，我们检查每个Thread是否越界。而在Triton当中，我们先检查每个Program是否越界，我们先判断开始的这一行是否大于Batch size，如果大于的话就退出。如果start_m < batch_size，而行号大于batch_size时候，我们就需要加mask了（在第三步改写当中会讲到）。

然后我们去定义一些offset，这些offset会被自动地分配到每一个线程上。因为offset是一个常量，所以它们是不占用寄存器的。

### 读取操作的改写

接下来是关于读取的操作

```cpp
// Allocate VALS_PER_THREAD floats in registers
float tmp_val[VALS_PER_THREAD];

// Load VALS_PER_THREAD values from global memory into registers
#pragma unroll
for (int i = 0; i < VALS_PER_THREAD; i += MEM_ACCESS_WIDTH) {
    // Vectorized memory access using float4
    reinterpret_cast<float4*>(&tmp_val[i])[0] =
        reinterpret_cast<float4*>(&x[offset + i * WARP_SIZE])[0];
    }

```

```text
# Mask invalid M offsets when BLOCK_SIZE_M > 1
mask = offs_m[:, None] < batch_size

# Load input tensor
x = tl.load(x_ptr + offs_m[:, None] * hidden_dim + offs_n[None, :], mask=mask)
```

在CUDA里面，我们需要去定义VALS_PER_THREAD个寄存器去读取我们的输入，但在Python里面，我们只需要去写tl.load，它会注册一个BLOCK_SIZE_M乘BLOCK_SIZE_N的tensor，去对应到寄存器上。

这里的mask去处理线程越界的问题。

[:,None]是把一维数组展开成二维。

### Softmax计算部分的改写

下面是激动人心的时刻，左边一大块是CUDA Softmax Kernel，我们花了很大篇幅去算Thread上的操作和通信。在Triton当中，这些都不需要去考虑，torch怎么写，Triton就可以怎么写。

![](https://pica.zhimg.com/v2-c732b87f14ca3c055c8076c663a71bd2_r.jpg)

### 存储的改写

存储和读取是一样写法。

```cpp
// Write VALS_PER_THREAD values registers to global memory 
#pragma unroll
for (int i = 0; i < VALS_PER_THREAD; i += MEM_ACCESS_WIDTH) {
    // Vectorized memory access using float4
    reinterpret_cast<float4*>(&y[offset + i * WARP_SIZE])[0] =
        reinterpret_cast<float4*>(&tmp_val[i])[0];
}
tl.store(y_ptr + offs_m[:, None] * hidden_dim + offs_n[None, :], y, mask=mask)

```

### Kernel Launch的改写

```cpp
// Number of warps in a thread block
const int num_warps = 4;
// Grid size (= number of thread blocks)
int num_blocks = (batch_size + num_warps - 1) / num_warps;

const dim3 dimBlock(num_warps * WARP_SIZE);
const dim3 dimGrid(num_blocks);
# Program (thread block) size = 4 warps = 128 threads
num_warps = 4

# Each program (thread block) processes 4 rows
BLOCK_SIZE_M = 4
BLOCK_SIZE_N = hidden_dim
assert hidden_dim & (hidden_dim - 1) == 0, "Hidden dimension must be a power of 2" #Block_SIZE 需要是2的整数次幂
//提示编译器编译多个不同形状的Kernel，服务于不同的需求
if (hidden_dim % WARP_SIZE != 0) {
        throw std::runtime_error("Unsupported hidden dimension size.");
    }
    int vals_per_thread = hidden_dim / WARP_SIZE;
    if (vals_per_thread == 4) {
        better_softmax_kernel<4><<<dimGrid, dimBlock>>>(X.data_ptr<float>(), Y.data_ptr<float>(), batch_size);
    } else if (vals_per_thread == 8) {
        better_softmax_kernel<8><<<dimGrid, dimBlock>>>(X.data_ptr<float>(), Y.data_ptr<float>(), batch_size);
    } else if (vals_per_thread == 16) {
        better_softmax_kernel<16><<<dimGrid, dimBlock>>>(X.data_ptr<float>(), Y.data_ptr<float>(), batch_size);
    } else if (vals_per_thread == 32) {
        better_softmax_kernel<32><<<dimGrid, dimBlock>>>(X.data_ptr<float>(), Y.data_ptr<float>(), batch_size);
    } else if (vals_per_thread == 64) {
        better_softmax_kernel<64><<<dimGrid, dimBlock>>>(X.data_ptr<float>(), Y.data_ptr<float>(), batch_size);
    } else if (vals_per_thread == 128) {
        better_softmax_kernel<128><<<dimGrid, dimBlock>>>(X.data_ptr<float>(), Y.data_ptr<float>(), batch_size);
    } else {
        throw std::runtime_error("Unsupported hidden dimension size.");
    }
# Launch the Triton kernel
# Triton是即时编译的，只有在新的BLOCK_SIZE_M和BLOCK_SIZE_N到来的时候才会去编译这么一个Kernel，在这之前是不会编译的
grid = (triton.cdiv(batch_size, BLOCK_SIZE_M), )
softmax_kernel[grid]( #Triton里面只有grid，block是不可见的
    x, y, batch_size, hidden_dim,
    BLOCK_SIZE_M=BLOCK_SIZE_M, BLOCK_SIZE_N=BLOCK_SIZE_N,
    num_warps=num_warps,
)

```
