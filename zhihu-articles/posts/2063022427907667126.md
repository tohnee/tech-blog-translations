## 一、为什么需要 Saddle？

AI 落地从来不是"调一个模型"那么简单。你要做的是：

- 拉数据 → 清洗 → 切分 → 训练 → 评估 → 上线 → 监控 → 漂移检测 → 触发重训
- 加上合规、审计、知识库检索、Agent 编排、PLC 对接……
- 还要让**业务、财务、法务、风控**都能看懂流程、签字背书

传统做法是 Python 脚本 + Jupyter + 各种 CLI，问题是：

| 痛点 | 传统做法 | 用 Saddle |
| --- | --- | --- |
| 一行改错全盘崩溃 | 散落的脚本 | 可视化 DAG，单算子可重跑 |
| 流程只有写代码的人才懂 | 代码评审 | 业务也能看懂"图" |
| 合规/审计靠补文档 | 事后追写 | 节点级审计 + 证据包自动产出 |
| 模型从实验到上线隔一道墙 | 研发自己造 | 同一画布贯穿：探索 → 发布 → 回滚 |
| 接生产设备/工单/MQTT 风险高 | 一不小心真下发 | 默认 dry-run，审批门禁白名单 |

**一句话定位**：Saddle 是一块"画布即流水线"——把数据、模型、Agent、设备、合规全部在同一张可视化图里拉通。

## 二、Saddle 是什么？

**Saddle** 是由 [http://sicurrent.com](http://sicurrent.com) 推出的 **可视化 AI/MLOps 任务流编排平台**：

- 前端：基于 **ReactFlow** 的拖拽式画布，画节点、连算子、编参数、实跑出结果
- 后端：**Go 高性能调度器**，节点级依赖、DAG 并行执行、确定性审计日志
- 模型层：内置 **本地大模型支持**（GPT-2 / Qwen3 / Whisper / OpenMed / YOLO 等），所有项目**离线可跑**，不依赖外网
- 集成层：原生适配 **MQTT dry-run、ERP CSV、PLC Modbus、BM25 知识库、Agent 编排**

**最关键的一点**：你不需要"另外写工程代码"——打开画布，拖算子、连线、配参数、跑，看结果。

## 五、Saddle 的核心价值 — 6 个不可替代的能力

## 1️⃣ 业务可读 — 画布即文档

- 节点就是步骤，连线就是流向，业务/合规/管理都能签字
- 不再是"代码评审才能懂"的暗箱

## 2️⃣ 工程可控 — 单算子可重跑、可恢复

- 任意节点断点续跑，失败回滚到指定节点
- 算子级别版本管理，节点级审计日志

## 3️⃣ AI 全栈 — 数据 → 模型 → Agent → 设备，一画贯之

- 同一画布内同时使用：CSV / SQL / Python / LLM / Agent / 视觉模型 / MQTT / Modbus / BM25
- 涵盖实验与生产，**不必"另起炉灶"做上线**

## 4️⃣ 本地优先 — 内置开源模型，全部离线可跑

- 没有任何"强制联网"节点（即使大模型也支持本地缓存权重）
- 离线 LLM / 离线 Embedding / 离线 Whisper / 离线 YOLO
- 适合**数据不能出网**的合规场景

## 5️⃣ 安全合规 — 默认 dry-run + 审批门禁 + 证据包

- 所有"写"动作（MQTT / PLC / CRM / ERP）默认 **dry-run**
- 真实下发必经：白名单 + 人工确认 + 联锁规则
- 自动产出审计 CSV / 模型卡 / 数据血缘 / 治理证据包

## 6️⃣ 模板即案例 — 73 个真实项目直接可改

- 不是"hello world"演示，是已经在产线上验证过的真实模板
- 打开 → 修改参数 → 替换数据 → 直接跑你的业务
