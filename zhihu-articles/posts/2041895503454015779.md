最近我开始认真准备 AI Infra 方向的暑期实习。

相比单纯刷八股、收藏项目或者零散看视频，我更想用一种能持续约束自己的方式来学习：选择几个和岗位高度相关的项目，一边读代码、做实验、整理笔记，一边把学习过程记录下来。

这个系列不是专家教程，而是一个计科本科生准备 AI Infra 实习的学习记录。我希望它至少完成三件事：

- 帮我把 AI Infra 相关知识真正学清楚，而不是停留在“好像看过”。
- 留下一套可复盘的学习材料，包括源码笔记、实验记录、面试问答和简历项目表达。
- 在投递简历前，形成两个能讲清楚的项目和一套能支撑面试的知识体系。

### 一、我是谁，以及为什么开始写这个系列

我是一名计算机学院大三学生，计划本科毕业后直接就业。

说实话，我对实习这件事的认识有点晚。大一大二的时候，我对职业方向、实习节奏、项目积累这些事情都没有太清晰的概念。直到大三下学期，才真正开始意识到：如果想找一个技术含量比较高的实习，不能只靠临时刷题和临时补知识，必须要有能拿出来讲的项目、实验和技术理解。

一开始我也考虑过 AI 应用开发，比如 Agent、RAG、工作流这些方向。但随着了解得更多，我发现自己对 AI Infra 更感兴趣。

我目前对 AI Infra 的理解还在形成中，但它吸引我的地方在于：它不只是“怎么调用模型”，而是要回答模型如何高效运行、如何服务更多请求、如何降低延迟和显存成本、如何在 GPU 和分布式环境下获得更好的性能。

这背后会涉及推理系统、CUDA、模型服务、分布式通信、性能优化、量化、工程化部署等内容。它对我来说更难，但也更像一个可以长期投入的方向。

### 二、为什么选择用输出倒逼学习

我正式决定把 AI Infra 作为求职方向大概有一个月了，但回头看这一个月，我发现自己真正沉淀下来的东西并不多。

这其实不是第一次出现。大学以来，我经常有一种感觉：看了不少东西，计划也制定过很多，但最后真正能讲清楚、能写下来、能变成项目材料的内容很有限。

我觉得主要有两个原因。

第一是不够持续。上完课以后很容易刷视频、看直播，学习节奏经常被打断。

第二是容易反复换计划。经常刚制定一个学习路线，坚持几天后又觉得有更好的方案，于是重新规划。制定计划的时候会有一种短暂的满足感，好像计划写出来就等于已经完成了一部分。但真正困难的部分其实是持续执行、反复复盘和产出结果。

所以我想尝试用公开输出来约束自己。

如果只学不写，很容易浅尝辄止；如果要写出来，就必须重新组织概念、追代码路径、找证据、回答问题。这个过程会逼着我发现自己到底哪里没懂。

对我来说，输出至少有三个作用：

- 保证学习深度：一个知识点只有能讲清楚，才算真正开始理解。
- 保证学习连续性：每篇文章都是一个阶段性产物，可以减少半途而废。
- 沉淀求职材料：文章、笔记、实验、问答最后都可以反过来支撑简历和面试。

所以这个系列的核心不是“写文章本身”，而是用写作建立一个学习闭环：

```text
读代码 / 做 notebook / 看文档
-> 写 study 笔记
-> 总结面试问题
-> 整理文章
-> 更新简历材料
-> 复盘当前掌握程度
```

### 三、我拆解出的岗位能力

我现在主要参考的是一个大模型推理性能优化相关岗位。这个岗位的职责大致包括：大模型推理性能优化、推理框架设计与开发、CPU/GPU 上的深度优化、异构高性能计算平台、高性能计算库和通信库优化等。

要求里提到的关键词也比较集中：

- C++ / Python / CUDA
- 深度学习框架和推理框架
- FlashAttention、PagedAttention、MoE、Chunked Prefill
- AWQ、GPTQ、投机解码等推理加速技术
- AllReduce、计算通信 overlap
- PD 分离
- vLLM、SGLang、TensorRT-LLM 等推理框架经验

我把这些要求先拆成几类能力：

| 能力方向 | 我需要补的内容 | 对应产出 |
| --- | --- | --- |
| 推理系统 | prefill/decode、KV cache、PagedAttention、continuous batching、chunked prefill、prefix cache、benchmark | 能讲清一次请求在推理系统中的生命周期，能设计吞吐/延迟实验 |
| CUDA / Kernel | thread/block、warp、shared memory、memory coalescing、reduction、softmax、LayerNorm、GEMM | 能讲清 2-3 个算子的 naive 到 optimized 路线 |
| LLM 算法与推理优化 | RoPE、GQA/MQA、MoE、FlashAttention、speculative decoding、量化 | 能把算法机制和推理性能联系起来 |
| 显存与性能分析 | 参数量、FLOPs、KV cache 显存、TTFT、TPOT、throughput、GPU memory | 能用指标描述性能瓶颈，而不是只说“快/慢” |
| 分布式与通信 | Tensor Parallelism、AllReduce、AllGather、通信拓扑、overlap、PD 分离 | 能理解多卡推理和通信瓶颈的基本问题 |
| 工程表达 | README、study 文档、benchmark 表格、简历 bullet、项目讲稿 | 能把学习过程转化成可信的求职材料 |

这里面有些内容我需要做到“能写代码和做实验”，比如推理系统链路、CUDA 算子、benchmark；有些内容短期内先做到“能讲清机制和 trade-off”，比如 PD 分离、多卡通信 overlap、AWQ/GPTQ 的工程细节。

也就是说，我不会一开始就假装自己能完整覆盖整个岗位要求。更现实的目标是：

1. 先做出一个推理系统主项目，能讲清 LLM serving、KV cache、调度和性能指标。
2. 再做出一个 CUDA 算子项目，能证明自己不是只会 Python 调包。
3. 同时用题库和笔记补齐 FlashAttention、PagedAttention、量化、MoE、通信等面试高频知识。

### 四、为什么选择这三个项目

围绕上面的能力拆解，我暂时选择了三个项目作为第一阶段学习材料。它们不是平均分配时间，而是分别承担不同角色。

### 1. mini-infer：推理系统主项目

项目地址：[https://github.com/psmarter/mini-infer](https://github.com/psmarter/mini-infer)

定位：大模型推理系统主项目。

`mini-infer` 是我准备用来理解大模型推理系统的主项目。它覆盖了很多和岗位高度相关的机制，比如：

- OpenAI-compatible serving
- engine / scheduler / model runner
- PagedAttention 和 KV cache 管理
- continuous batching
- chunked prefill
- prefix caching
- speculative decoding
- CUDA graph
- tensor parallelism
- PD 解耦实验

我选择它的原因是：很多推理优化概念如果只看文章，很容易停留在术语层面。比如 PagedAttention、continuous batching、chunked prefill，这些词单独解释并不难，但真正难的是理解它们在一个 serving 系统里怎么配合。

所以我希望通过 `mini-infer` 解决几个问题：

- 一次请求从 HTTP API 进入后，如何经过 engine、scheduler、model runner，最后返回 token？
- prefill 和 decode 在系统里为什么要区分？
- KV cache 如何影响显存占用、吞吐和并发？
- PagedAttention 的 block table 思路如何在系统中落地？
- continuous batching 如何提升吞吐，又会带来什么延迟 trade-off？
- chunked prefill 在长 prompt 场景下解决什么问题？

这个项目最后会服务我的简历第一项目：大模型推理系统学习与性能分析。

我希望最终能产出：

- 一张请求生命周期图。
- 一份 KV cache / PagedAttention 机制笔记。
- 一组 benchmark 表格，至少覆盖 batch size、prompt length、output length、concurrency。
- 一份 5 分钟项目讲稿。
- 若干条可以写进简历的项目 bullet。

### 2. CUDA_Kernel_Learn：底层 CUDA 能力项目

项目地址：[https://github.com/william20001120/CUDA_Kernel_Learn](https://github.com/william20001120/CUDA_Kernel_Learn)

定位：CUDA kernel 底层能力项目。

AI Infra 岗位经常会要求 CUDA、GPU 架构和性能优化。如果只从系统层讲推理，很容易缺少底层支撑。`CUDA_Kernel_Learn` 对我来说就是补这一块的。

这个项目覆盖了从简单到复杂的 CUDA kernel：

- `example/`：CUDA 程序骨架、设备信息、cuBLAS 示例
- `elementwise/`：one-thread-per-element 的基础模型
- `reduce/`：sum、max、softmax、matrix softmax
- `transpose/`：memory coalescing、shared memory、bank conflict
- `gemv/`：矩阵向量乘法
- `sgemm/`：从 naive 到多级优化的矩阵乘法
- `laynorm/`：LayerNorm forward/backward
- `cublas/`：cuBLAS baseline 和工具函数

我不会一开始就追求把每个 kernel 都完全吃透。短期目标是抓住最能支撑面试表达的几条主线：

- 从 elementwise 建立 thread/block 到数据映射的基本模型。
- 从 reduction 理解 shared memory、warp primitive、atomic、同步和访存。
- 从 softmax 连接 Transformer attention 中的核心算子。
- 从 transpose 理解 coalescing 和 bank conflict。
- 从 SGEMM 理解 tiling、register reuse、vectorized access、double buffering。
- 从 LayerNorm/RMSNorm 理解深度学习算子为什么常常是 memory-bound。

我准备采用“三层学习法”来学这个项目：

1. 核心机制：这个目录解决什么 CUDA 问题，训练什么优化模式。
2. 核心代码：有哪些文件、函数、kernel，host 端如何分配内存和 launch kernel。
3. 实现细节：每个线程读写什么数据，global/shared/register 怎么用，哪里需要同步，瓶颈在哪里。

这个项目最后会服务我的简历第二项目：Transformer 关键 CUDA 算子实现与优化。

我希望最终至少能讲清两个算子：

- Softmax：数值稳定、max/sum reduction、warp/shared memory 优化、和 attention 的关系。
- LayerNorm/RMSNorm 或 SGEMM/GEMV：归一化算子或矩阵计算的访存/计算瓶颈。

### 3. llm-algo-leetcode：知识补齐和面试题库

项目地址：[https://github.com/datawhalechina/llm-algo-leetcode](https://github.com/datawhalechina/llm-algo-leetcode)

定位：LLM 算法、推理优化和 Triton/CUDA 题库。

`llm-algo-leetcode` 和前两个项目不太一样。它不是我准备包装成简历主项目的内容，而更像一个系统化知识库和面试训练场。

它对我最有价值的部分包括：

- `01_Hardware_Math_and_Systems`：数据类型、FLOPs、GPU 架构、显存估算、通信拓扑
- `02_PyTorch_Algorithms`：RMSNorm、RoPE、MHA/GQA、MoE、FlashAttention、PagedAttention、speculative decoding、量化、TP
- `03_CUDA_and_Triton_Kernels`：Triton fused softmax、Triton FlashAttention、KV cache/PagedAttention、量化支持、分布式通信

这个项目能补齐很多 JD 点名但不一定能在一周内完整工程落地的内容，比如：

- FlashAttention 为什么减少 HBM 访问？
- PagedAttention 和 FlashAttention 解决的问题有什么不同？
- GQA/MQA 如何降低 KV cache 显存？
- speculative decoding 的 acceptance rate 为什么决定加速效果？
- AWQ/GPTQ/INT4 量化的收益和代价是什么？
- Tensor Parallelism 里的 AllReduce 在哪里出现？
- 计算通信 overlap 到底想隐藏什么开销？

我计划用它做三件事：

1. 补齐概念：把 JD 点名技术整理成自己的速查表。
2. 做 notebook：通过 TODO、测试函数和参考答案理解关键机制。
3. 训练面试表达：把每个主题转化成 30 秒、90 秒和追问版回答。

如果说 `mini-infer` 负责“系统链路”，`CUDA_Kernel_Learn` 负责“底层算子”，那 `llm-algo-leetcode` 负责把知识网络补全。

这三个项目的关系可以概括成：

| 项目 | 负责什么 | 最终产出 |
| --- | --- | --- |
| mini-infer | 推理系统 | 主项目、benchmark、推理链路讲稿 |
| CUDA_Kernel_Learn | CUDA 底层能力 | 算子项目、kernel 优化讲稿 |
| llm-algo-leetcode | LLM 推理优化知识网络 | JD 技术速查表、notebook 笔记、面试问答 |

我的目标不是把三个项目都“学完”，而是让它们互相支撑，最后形成两个能写进简历的项目和一套能应对面试的知识体系。

### 五、我准备怎么学

为了避免再次陷入“计划很多，产出很少”的状态，我会把学习过程拆成可验收的闭环。

每个主题都尽量产出五样东西：

1. 一份 study 笔记。
2. 一篇文章草稿或公开文章。
3. 一组面试问题与回答。
4. 一条可能用于简历的项目表达。
5. 一个当前掌握程度评分。

具体学习流程是：

```text
读代码 / notebook
-> 写 study 笔记
-> 总结面试问题
-> 整理文章
-> 更新简历材料
-> 给自己评分
```

我会尽量用三层方式拆每个模块：

- 第一层，核心机制：它解决什么问题，为什么重要。
- 第二层，核心代码：对应哪些文件、函数、类、notebook、测试。
- 第三层，实现细节：线程怎么映射，tensor shape 怎么变化，内存怎么访问，性能瓶颈在哪里。

这也是我接下来写学习记录时会反复使用的结构。
