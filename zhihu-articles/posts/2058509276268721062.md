### 12.1 本章导读

第 1 章的第三堵墙是”激活墙”：前向产生的中间激活要保存以供反向，其显存正比于 `批量 × 序列 × 隐藏维 × 层数`。前面的并行策略（PP 分摊层、SP/CP 切序列）已经削减了一部分，但还不够。

本章讲三种”用计算/带宽换显存”的正交技术：

1. **激活重计算（activation recomputation / checkpointing）**：前向不存激活，反向时重算——用一次额外前向换取激活显存。
2. **梯度累积（gradient accumulation）**：把大 batch 拆成多个 microbatch 顺序跑，累积梯度——用时间换显存。
3. **CPU/细粒度 offloading**：把暂时不用的激活/状态挪到 CPU 内存——用 PCIe 带宽换显存。

这些是把训练”塞进”有限显存的最后手段，也是每个大模型工程师的日常调参对象。

---

### 12.2 背景介绍：激活为什么占这么多

反向传播需要前向的中间结果。以一层 Transformer 为例，需要保存：attention 的 QKV、注意力分数、softmax 输出、MLP 中间激活、LayerNorm 输入等。粗略地，每层激活显存 ∝ `s·b·h`（乘以一个与结构相关的常数，通常十几到几十）。

`L` 层模型的总激活 ∝ `L·s·b·h`。当 `s=8192, b=4, h=12288, L=96` 时，激活可达数百 GB——远超参数。这就是”激活墙”。

---

### 12.3 问题提出：存还是算

反向需要激活，有两个极端：

- **全存**：前向把所有激活留着，反向直接用。显存爆炸。
- **全不存**：反向时从头重算。计算翻倍。

重计算（checkpointing）是二者的**折中**：只在少数”检查点”保存激活，检查点之间的激活在反向时按需重算。经典结论（Chen 等，2016）：用 `O(√L)` 的显存 + 一次额外前向，就能训练 `L` 层网络。论文（本书翻译稿第 4.2 节）就用了”每层激活重计算”。

---

### 12.4 核心思想：重计算的粒度

Megatron 提供两档粒度，由 `TransformerConfig`（`transformer_config.py:472`）配置：

```text
recompute_granularity: Optional[Literal['full', 'selective']] = None
recompute_method:      Optional[Literal['uniform', 'block']]  = None
recompute_num_layers:  Optional[int] = None
recompute_modules:     Optional[List[str]] = None  # selective 时选哪些子模块
```

### 12.4.1 full：整层重计算

`recompute_granularity='full'`：checkpoint 整个 Transformer 层的输入，反向时重算整层的所有激活。省显存最多，计算开销最大（多一次完整前向）。

两种调度方法（`recompute_method`）：

- **uniform**：把每个 PP stage 的层均分成大小为 `recompute_num_layers` 的块，每块 checkpoint 其输入。
- **block**：只对每个 stage 的前 `recompute_num_layers` 层做重计算，其余层全存激活。更灵活——显存紧张的前几层重算，宽裕时保留后面层的激活。

### 12.4.2 selective：选择性重计算

`recompute_granularity='selective'`：只重算**指定子模块**，`recompute_modules` 默认 `["core_attn"]`。

**为什么默认选 core_attn？** 注意力分数 `[s,s]` 的激活是 `O(s²)`，显存占用大但**重算成本相对低**——这正是《Reducing Activation Recomputation in Large Transformer Models》（arXiv:2205.05198，本书 `megatron_activation_recomputation_中文翻译.md`）提出**选择性激活重计算**时的核心洞察。该论文量化指出：式中 `5as/h` 项来自 `QKᵀ`、softmax、softmax dropout、对 V 的注意力这几个操作，它们**激活大但每元素 FLOP 低**。对 GPT-3（`5as/h=80`）选择性只重算这部分可省 **70%** 激活显存、仅增 **2.7%** FLOP；对 MT-NLG（`5as/h=64`）省 **65%**、仅增 **1.6%**。选择性地只重算 attention，能以很小的计算代价省下最大块的激活。这是”性价比最高”的重计算，也是长序列训练的推荐配置。

`recompute_modules` 可选：`core_attn`、`moe_act`、`layernorm`、`mla_up_proj`、`mlp`、`moe`、`shared_experts`。

---

### 12.5 数学原理：显存-计算权衡

设 `L` 层，每层激活 `A`，每层前向计算 `C`：

| 策略 | 激活显存 | 额外计算 |
| --- | --- | --- |
| 全存 | L·A | 0 |
| full uniform（块大小 k） | (L/k)·A + k·A（检查点 + 块内重算峰值） | ~1 次额外前向 |
| full block（前 n 层） | (L-n)·A + A | n 层额外前向 |
| selective(core_attn) | L·A - L·A_attn（省注意力分数） | 仅 attention 重算 |

**关键权衡：** full 省显存多但计算开销 ~100%；selective 省显存少但计算开销小（通常 <20%）。实践中：**优先 selective，显存仍不够再上 full**。

### 12.5.1 最优检查点数（SC21 论文）

SC21 论文（第 3.5 节）给出了 full 重计算下**检查点数量**的最优解析式。设：

- `A_input`：一层输入激活的大小；
- `A_intermediate`：每层中间激活的大小；
- 一个模型阶段有 `l` 层，设 `c` 个检查点。

则总显存占用为：

$$ M = c \cdot A_{input} + \frac{l}{c} \cdot A_{intermediate} $$

对 `c` 求导取极小，最优检查点数为：

$$ c^* = \sqrt{l \cdot \frac{A_{intermediate}}{A_{input}}} $$

论文指出 `A_intermediate` 通常靠经验测量；**大多数情况下每 1 或 2 个 Transformer 层设一个检查点是最优的**。注意检查点数**不影响吞吐**（重算量由 granularity 决定），只影响显存峰值——这是选择 `c` 的关键前提。

### 12.6 数据结构与源码：checkpointed_forward

`recompute.py` 的 `checkpointed_forward`（`recompute.py:21`）是重计算的核心：

```text
def checkpointed_forward(self, hidden_states, attention_mask, ..., layer_offset=0):
    # 定义一个闭包 cf，跑 [start, end) 范围的层
    def custom_forward(...):
        for layer in layers[start:end]:
            hidden_states = layer(hidden_states, ...)
        return hidden_states

    if self.config.recompute_method == 'uniform':
        layer_idx = 0
        while layer_idx < self.num_layers_per_pipeline_rank:
            chunk_end = min(layer_idx + recompute_num_layers, num_layers_per_pipeline_rank)
            chunk_runner(layer_idx, chunk_end, use_checkpoint=True)   # 每块都 checkpoint
            layer_idx += recompute_num_layers
    elif self.config.recompute_method == 'block':
        for layer_idx in range(num_layers_per_pipeline_rank):
            use_checkpoint = (recompute_skip <= layer_idx < recompute_num_layers + recompute_skip)
            chunk_runner(layer_idx, layer_idx + 1, use_checkpoint)    # 前 n 层 checkpoint
```

### 12.6.1 checkpoint 函数的选择

`recompute.py:113` 根据精度选择 checkpoint 实现：

```text
if use_checkpoint:
    if self.config.fp8 or self.config.fp4:
        hidden_states, context = te_checkpoint(          # FP8/FP4：TE 感知的重计算
            cf, self.config.distribute_saved_activations,
            tensor_parallel.random.get_cuda_rng_tracker,  # RNG 管理
            self.pg_collection.tp, *args)
    else:
        hidden_states, context = tensor_parallel.checkpoint(  # 标准精度
            cf, self.config.distribute_saved_activations, *args)
```

**为什么 FP8 要用 `te_checkpoint`？** FP8 的量化状态（scale/amax）需要在重算时正确恢复，普通 checkpoint 不感知这些，会导致重算结果与前向不一致（第 11 章）。

### 12.6.2 distribute_saved_activations

`distribute_saved_activations` 让 checkpoint 保存的激活也沿 TP 组切分（配合序列并行），进一步省显存——检查点激活本身也不冗余存储。

### 12.7 核心机制：重计算的 RNG 一致性

重计算有一个隐蔽的正确性要求：**重算的前向必须和原始前向产生完全相同的结果**，尤其是 dropout。如果重算时 dropout 用了不同的随机 mask，反向梯度就错了。

第 4 章的 `CudaRNGStatesTracker`（`tensor_parallel/random.py:217`）的 `fork()` 正是为此：

```text
def fork(self, name=_MODEL_PARALLEL_RNG_TRACKER_NAME):
    orig_state = _get_cuda_rng_state()          # 保存当前 RNG
    _set_cuda_rng_state(self.states_[name])     # 切到检查点时的 RNG
    try:
        yield                                    # 重算在此 RNG 下进行
    finally:
        self.states_[name] = _get_cuda_rng_state()
        _set_cuda_rng_state(orig_state)          # 恢复
```

原始前向时记录 RNG 状态，重算时恢复同一状态，保证 dropout mask 一致。这是重计算正确性的基石。

### 12.8 梯度累积：用时间换显存

### 12.8.1 原理

想要大的全局 batch（利于收敛），但大 batch 的激活放不下。解法：把全局 batch 拆成 `num_microbatches` 个 microbatch，**顺序**前向+反向，梯度累加进 `main_grad`（第 6 章），跑完所有 microbatch 才 optimizer.step。

```text
global_batch_size = micro_batch_size × data_parallel_size × num_microbatches
```

`num_microbatches_calculator.py` 据此算出 `num_microbatches`。每个 microbatch 的激活用完即释放，峰值激活只由单个 microbatch 决定——**用更多迭代时间换取更低的激活峰值**。

### 12.8.2 与流水线并行的关系

第 5 章的 1F1B 调度里的 microbatch 就是梯度累积的 microbatch。PP 用它们填充流水线降气泡；梯度累积用它们降激活峰值。二者是同一批 microbatch 的两个视角。

### 12.8.3 与重计算的相互作用

重计算是”每个 microbatch 内部”省激活；梯度累积是”microbatch 之间”不叠加激活。二者正交叠加：更多 microbatch → 每个更小 → 重计算的重算量也更小。

---

### 12.9 CPU / 细粒度 Offloading

`fine_grained_activation_offload.py` 与 `optimizer/cpu_offloading/` 提供更激进的显存手段：

- **激活 offload**：把前向产生、短期不用的激活异步拷到 CPU 内存，反向需要时再拷回。用 PCIe/NVLink-C2C 带宽换显存。
- **优化器状态 offload**：把 fp32 master、动量挪到 CPU（DeepSpeed ZeRO-Offload 思路），GPU 只在 step 时拉回。

**代价：** PCIe 带宽远低于显存带宽，offload 若不能与计算充分重叠，会拖慢训练。细粒度 offload 的价值在于精细选择”哪些激活值得 offload、何时预取”，把带宽开销藏进计算。

---

### 12.10 性能分析

- **selective(core_attn)**：省最大块激活（`O(s²)` 注意力分数），计算开销通常 <20%，性价比最高，长序列首选。
- **full**：省显存最多，但计算开销接近 100%（多一次前向），MFU 下降明显，仅在显存极紧时用。
- **梯度累积**：不增加单步计算，但增加迭代次数（吞吐不变、峰值激活降）；配合 PP 是标配。
- **offload**：显存收益大，但受 PCIe 带宽限制，需与计算重叠才不拖慢。
- **组合**：真实大模型训练常同时开 selective 重计算 + 梯度累积 + PP + SP/CP，逐层削减激活。

### 12.11 与其它框架对比

| 维度 | Megatron | DeepSpeed | PyTorch |
| --- | --- | --- | --- |
| 重计算粒度 | full(uniform/block) + selective(多模块) | 层级 checkpoint | torch.utils.checkpoint |
| RNG 一致性 | CudaRNGStatesTracker | 类似 | checkpoint 内建 |
| 梯度累积 | num_microbatches（与 PP 统一） | ✓ | 手动循环 |
| offload | 细粒度激活 + 优化器 | ZeRO-Offload/Infinity | 需手工 |
| FP8 感知重计算 | te_checkpoint | 借 TE | 实验性 |

Megatron 的 selective 多模块重计算和 FP8 感知重计算是其相对通用 `torch.utils.checkpoint` 的精细化优势。

### 12.12 常见误区

1. **无脑开 full 重计算**。计算开销近 100%，MFU 大跌；优先 selective。
2. **重计算忽视 RNG 一致性**。不用 `CudaRNGStatesTracker`，dropout 重算 mask 不一致，梯度错误。
3. **FP8 用普通 checkpoint**。必须用 `te_checkpoint`，否则量化状态错乱。
4. **把梯度累积当成”变相大 batch 无代价”**。它降激活峰值但增迭代时间，且大 batch 本身可能影响收敛（第 2 章弱扩展讨论）。
5. **offload 不看带宽**。PCIe 带宽有限，不能重叠时反而更慢。
6. **recompute_num_layers 设错**。uniform 下它是块大小、block 下是层数，语义不同，配错达不到预期显存。

### 12.13 本章总结

- 激活墙：激活 ∝ `L·s·b·h`，常超过参数本身。
- 重计算用”额外前向”换激活显存：`full`（整层，省得多算得多）与 `selective`（选子模块，默认 core_attn，性价比最高）。
- `checkpointed_forward` 用 uniform/block 调度；FP8/FP4 下必须用 `te_checkpoint`；`distribute_saved_activations` 让检查点激活也切分。
- 重计算正确性靠 `CudaRNGStatesTracker.fork()` 保证 dropout 重算一致。
- 梯度累积用 `num_microbatches` 把大 batch 拆小，降激活峰值，与 PP 的 microbatch 统一。
- 细粒度 offload 用 PCIe 带宽换显存，需与计算重叠。
- 实战常组合：selective 重计算 + 梯度累积 + PP + SP/CP。
