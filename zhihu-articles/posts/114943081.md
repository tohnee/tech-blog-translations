软件传输Verbs（Software Transport Verbs）

​ 在InfiniBand（IB）中，Verbs为主机提供了一种HCA功能的抽象定义，这些功能是由HCA硬件的通道接口（Channel Interface）来提供的。在RDMA编程中经常使用的libibverbs就是IB协议中软件传输Verbs规定的语义的具体实现。IB协议规定的软件传输Verbs只是对必要的和可选的Verb功能进行了规定和说明，并未对接口的标准进行统一定义。具体实现可以根据协议协议规定的功能来对接口进行定义。接下来，本文将对IB协议中软件传输Verbs的内容进行详细介绍。

## 1 Verbs简介

​ IB Spec从底层硬件的角度，对Verbs所提供的功能进行了抽象的定义，定义了强制的(Mandatory)和可选的(Optional)Verbs，其中，协议规定CI应该支持所有的强制类型的Verbs；根据Verbs消费者可访问性的不同，又可以将Verbs分为两类：特权等级(Privileged)Verbs和用户级(User-Level)Verbs，其中，**特权级消费者**可以使用所有的Verbs，而**用户级消费者**只能使用**用户级**Verbs。

## 3 工作请求处理

### 3.1 QP操作

### 3.1.1 Post Send Request

- 描述：根据消费者提交的WR列表中包含的信息，在指定的QP中为SQ构建**一个或多个**WQE。这些WQE被添加到SQ的末尾，并通知HCA**一个或多个**WQE已经准备好进行处理。

### 3.1.2 Post Receive Request

- 描述：根据消费者提交的WR列表中包含的信息，在指定的QP或SRQ中为RQ构建**一个或多个**WQE。这些WQE被添加到RQ或SRQ的**末尾**，并通知HCA**一个或多个**WQE已经准备好进行处理。注意，在RQ中，唯一有效的操作就是接收操作。

### 3.2 CQ操作

### 3.2.1 Poll for Completion

- 描述：轮询指定的CQ以完成工作。工作完成指示完成了与CQ关联的工作队列的WR。如果存在一个条目，那么CQ头部的工作完成将返回给消费者。

### 3.2.2 Request Completion Notification

- 描述：当将指定类型的下一个完成项添加到指定的CQ时，请求调用CQ事件处理程序。对于特定的CQ，每个请求完成通知调用**最多调用一次**处理程序。在启用中断之前存在的任何CQ条目都**不会**导致对处理程序的调用。<br> ​ Completion Events are one of two types: solicited or unsolicited. A Solicited Completion Event occurs when an incoming Send or RDMA Write with Immediate Data message, with the Solicited Event header bit set causes a successful Receive Work Completion to be added to a CQ; or, when an unsuccessful Work Completion is added to a CQ. An Unsolicited Completion Event occurs when any other successful Receive Work Completion, or any successful Send Work Completion, is added to a CQ.<br>

## 4 事件处理

### 4.1 Set Completion Event Handle

- 描述：将完成事件处理程序与具体CQ关联起来。若HCA支持基本队列管理扩展（Base Queue Management Extension），HCA可以支持超过一个完成事件处理程序。

### 4.2 Set Asynchronous Event Handle

- 描述：注册异步事件的处理程序。注意，每个HCA只能注册一个异步事件处理程序。
