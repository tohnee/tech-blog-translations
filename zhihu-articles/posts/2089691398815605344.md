### 信号

Baseten 的工程师最近做了个实验：他们让 Claude Code（用的 Fable 5 模型）直接把 Qwen 的推理引擎给「造」了出来。结果**单流解码比 vLLM 快 90%，首 token 延迟从 28ms 压到 12ms**。

这不是「AI 帮我把某个函数补全」的小打小闹，而是让 agent**端到端地生产一个原本只有大厂基础设施团队才能搞定的底层组件**。

02

CHAPTER

### 变化

过去我们说「AI 编程」，默认是在 IDE 里让 AI 帮你写业务代码、补几行逻辑。但这个案例把边界往前推了一大步：**AI 编程已经能碰底层推理引擎**——也就是模型真正「跑起来」的那层性能优化。

这正是我最近一直在做的 FDE（前沿部署工程师）在干的事：不是训练模型，也不是只写页面，而是**把 AI 真正落进业务、跑出生产级性能**。一个推理引擎能被 agent 造出来，说明「部署和性能」这件事，正在从少数内核工程师的专利，变成会调 agent 的人也能接的活。

### 普通人机会

你**不用懂 CUDA 内核，也不用读论文**，就能指挥 agent 产出这种原来只有大厂能做的性能优化。

对想用 AI 编程做副业、或者一人公司接商单的人，这意味着一类新需求出现了：**推理加速 / 降本**。现在不少公司模型跑得慢、API 成本高，但养不起专门的推理优化团队。如果你能把「用 AI 编程搭一套更快的推理 / 部署方案」跑通，这就是一个能真金白银接的活。

我自己的判断一直很简单：**客户要的不是「会 AI 概念」，而是「把模糊需求做成能跑、能降本的东西」**。这个案例刚好把这句话又验证了一遍。真正稀缺的从来不是写代码的手，而是把需求问清楚、把边界定明白、把结果验收住的判断力。

### 窗口期

会玩这套的人现在还很少。Claude Code 能造推理引擎，不等于满大街都是能落地它的人。

谁先把「用 AI 编程做推理优化交付」这件事跑通、攒出真实案例，谁就占住一个认知坑——等再过半年，工具更成熟、会的人多了，这个红利就会被摊薄。

窗口期就是现在。你要做的不是去背 CUDA，而是先把 agent 跑长任务、出真实结果这套工作流用熟。**早进场的人吃的不是技术本身，是认知差。**
