## 一、总览

注意力机制很有用。然而，标准 Attention 在计算过程中需要显式构建一个大小为 $N \times N$ 的注意力矩阵，其中 $N$ 为输入序列长度。当序列长度不断增加时，该矩阵不仅带来巨大的显存占用，也显著增加了计算和数据访问开销，成为限制大规模模型训练和推理效率的重要瓶颈。

传统优化方法通常关注减少 Attention 的计算复杂度，例如稀疏 Attention 或线性 Attention，但这些方法往往需要通过减少计算的方式提高速度，可能影响模型效果，是有损加速。研究发现，在现代 GPU 中，Attention 的性能瓶颈不仅来自矩阵计算本身，更来自 GPU 高速计算单元与显存之间频繁的数据读写过程，即 内存访问开销（memory access cost）。

针对这一问题，FlashAttention 提出了一种面向 GPU 硬件特性的 Attention 优化方法。它不改变 Attention 的数学结果，而是通过重新设计计算流程，利用分块计算（tiling）和片上高速存储（SRAM），减少中间注意力矩阵在高带宽显存（HBM）中的读写次数，从而显著提升 Attention 的计算效率并降低显存占用。

## 二、标准 Attention 为什么慢：计算量 vs IO 瓶颈

### 标准 Attention 为什么慢：计算量 vs IO 瓶颈

标准 Attention 的核心计算过程可以表示为：

$$ Attention(Q,K,V)=Softmax(\frac{QK^T}{\sqrt{d}})V $$

### 1. 计算量瓶颈：长序列导致平方增长

对于长度为 $N$ 的输入序列，$QK^T$ 会产生一个大小为： $[ N \times N ] $ 的注意力矩阵。因此，Attention 的计算复杂度为： $[ O(N^2d) ]$ ，其中 $d$ 是隐藏维度。

当序列长度增加时，计算量会平方增长。例如：

- 序列长度 $N=1,024$ 时，注意力矩阵包含约100万个元素；
- 序列长度 $N=32,768$ 时，矩阵元素数量超过10亿。

因此，在大语言模型处理长上下文时，Attention 的二次复杂度占用显存成为重要限制。

### 2. 更关键的问题：GPU中的IO访问瓶颈

虽然 Attention 包含大量矩阵乘法，但现代 GPU 具有强大的矩阵计算能力，真正限制速度的往往不是计算，而是**数据搬运效率**。

GPU内部存在不同层级的存储结构：

- **HBM（High Bandwidth Memory，高带宽显存）**：容量大，但访问速度相对较慢；
- **SRAM（Static Random Access Memory，片上高速缓存）**：容量小，但速度极快，直接连接计算核心。

标准 Attention 的执行流程通常如下：

1. 从 HBM 中读取 $Q,K$；
2. 计算 $S=QK^T$；
3. 将完整的注意力矩阵 $S$ 写回 HBM；
4. 从 HBM 读取 $S$ 进行 Softmax；
5. 将 Softmax 后的矩阵再次写回 HBM；
6. 读取结果并计算与 $V$ 的矩阵乘法。

在这里一部分聪明的小伙伴可能就有疑问了：为什么要将完成的注意力矩阵写回HBM，然后在计算Softmax的时候又加载S，这不是多此一举吗？

答案是：因为注意力矩阵本身太大，在SRAM上根本存不上，需要算一部分就写回一部分到HBM。同样的，在计算softmax的时候也是加载一部分算一部分。

这种方式问题在于，中间产生的 $N\times N$ 注意力矩阵并不是最终需要保存的结果，它只是计算过程中的临时变量，但传统实现仍然需要频繁地在 GPU 显存和计算核心之间读写它。

因此，大量时间消耗在： $[ \text{HBM} \leftrightarrow \text{SRAM} ]$ 之间的数据传输，而不是矩阵计算本身。

基于这一思想，FlashAttention 通过**分块计算（tiling）**避免显式存储完整注意力矩阵，并结合 **online softmax** 保持数学等价，从而在不改变模型效果的情况下大幅降低 IO 开销。

## 三、Flash Attention 的核心思想

Flash Attention 的核心思想是：**不改变 Attention 的数学计算形式，而是重新设计其在 GPU 上的执行方式，通过减少高成本的显存访问（IO）来提升计算效率。**

FlashAttention 提出了一种 **IO-aware Attention** 方法，其核心包括两个关键技术：

### **1.分块计算（Tiling）**

FlashAttention 不再一次性计算并保存完整的注意力矩阵，而是将Q、K、V 划分为多个小块，使每个计算块能够驻留在 GPU 的片上 SRAM 中。计算时，仅加载当前需要的数据块，在片上完成矩阵乘、Softmax 和输出累积，避免生成完整的N×N 注意力矩阵。

例如，将序列划分为两个块： $Q= \begin{bmatrix} Q_0\\ Q_1 \end{bmatrix}$ 其中： $Q_0,Q_1\in R^{L_i\times D}$ 同理： $K= \begin{bmatrix} K_0\\ K_1 \end{bmatrix}$ $V= \begin{bmatrix} V_0\\ V_1 \end{bmatrix}$

每个块只包含部分 token 的表示，但保持完整的特征维度 D。

在完成分块后，FlashAttention 使用两层循环遍历这些块：

- **外层循环：遍历 Query 块**
- **内层循环：遍历 Key/Value 块**

以第一个 Query 块 $Q_0$ 为例。FlashAttention 首先固定一个 Query 块：

$Q_0 \in \mathbb{R}^{L_i \times D}$

然后依次加载对应的 Key 和 Value 块 $(K_j,V_j)$。对于第一个 Key/Value 块 $(K_0,V_0)$，计算局部注意力分数：

$S_{00}=\frac{Q_0K_0^T}{\sqrt{D}}$

其中：

$S_{00}\in \mathbb{R}^{L_i\times L_i}$

该局部注意力矩阵只在 GPU 片上 SRAM 中暂存，并不会写入 HBM。随后，FlashAttention 在片上完成 Softmax 计算，并与对应的 Value 块进行矩阵乘：

$O_{00}=Softmax(S_{00})V_0$

完成第一个 Key/Value 块的计算后，保持 Query 块 $Q_0$ 不变，继续加载下一组 Key/Value 块 $(K_1,V_1)$，计算：

$S_{01}=\frac{Q_0K_1^T}{\sqrt{D}}$

并得到对应输出：

$O_{01}=Softmax(S_{01})V_1$

随后将不同 Key/Value 块产生的结果进行累积：

$O_0=O_{00}+O_{01}$

重复上述过程，直到遍历所有 Key/Value 块：

$(K_0,V_0),(K_1,V_1),...,(K_j,V_j)$

最终得到 Query 块 $Q_0$ 对应的输出：

$O_0=\sum_j O_{0j}$

随后，FlashAttention 继续处理下一个 Query 块 $Q_1$，重复上述计算过程，直到所有 Query 块计算完成。

需要注意的是，上述过程是为了直观展示分块计算思想而进行的简化描述。由于 Softmax 需要在完整 Key 维度上进行归一化，因此实际 FlashAttention 并不会简单地对不同块的 Softmax 输出进行相加，而是通过 Online Softmax 维护中间统计量，使分块计算结果与标准 Attention 保持完全一致。

### 2.Online Softmax（在线 Softmax）

分块计算虽然解决了注意力矩阵无法驻留在 SRAM 中的问题，但也带来了一个新的挑战：Softmax 本身依赖完整的 Key 维度进行归一化。对于标准 Attention，注意力权重计算为：

$$ P_{ij}=\frac{e^{S_{ij}}}{\sum_j e^{S_{ij}}} $$

其中：

$$ S_{ij}=\frac{q_i k_j^T}{\sqrt{D}} $$

可以看到，某个 Query 对应的 Softmax 结果需要知道它与所有 Key 的注意力分数。如果在分块计算中，直接对每个局部注意力块分别执行 Softmax：

$$ Softmax(S_{00}),Softmax(S_{01}) $$

再将不同块的结果进行累加，会导致每个块的归一化范围不同，最终结果无法与标准 Attention 保持一致。

为了解决这一问题，FlashAttention 引入了 Online Softmax，通过维护中间统计量，使 Softmax 可以随着 Key 块的遍历逐步更新，而无需保存完整的注意力矩阵。

对于一行注意力分数：

$$ S_i=[s_1,s_2,...,s_N] $$

标准 Softmax 为：

$$ softmax(S_i)_j=\frac{e^{s_j}}{\sum_k e^{s_k}} $$

为了避免指数计算过程中出现数值溢出，实际计算时通常减去该行最大值：

$$ m_i=\max(S_i) $$

因此：

$$ softmax(S_i)_j=\frac{e^{s_j-m_i}}{\sum_k e^{s_k-m_i}} $$

由此可知，计算 Softmax 时并不需要保存完整的输入，只需要维护两个统计量：当前最大值 $m_i$ 和归一化因子：

$$ l_i=\sum_k e^{s_k-m_i} $$

即可完成后续归一化。

在 FlashAttention 中，Key 和 Value 会被划分为多个块：

$$ K=[K_0,K_1,...,K_j] $$

对应的注意力分数也被划分为：

$$ S_i=[S_{i0},S_{i1},...,S_{ij}] $$

计算过程中，FlashAttention 按照块的顺序依次处理每个 $S_{ij}$。首先计算第一个 Key 块：

$$ S_{i0}=\frac{Q_iK_0^T}{\sqrt D} $$

并得到当前块的最大值：

$$ m_i^{(0)}=\max(S_{i0}) $$

以及对应的归一化因子：

$$ l_i^{(0)}=\sum e^{S_{i0}-m_i^{(0)}} $$

当继续处理下一个 Key 块：

$$ S_{i1}=\frac{Q_iK_1^T}{\sqrt D} $$

时，需要将新的计算结果与已有统计量进行合并。首先更新全局最大值：

$$ m_i^{(1)}=\max(m_i^{(0)},\max(S_{i1})) $$

然后更新归一化因子：

$$ l_i^{(1)} = e^{m_i^{(0)}-m_i^{(1)}}l_i^{(0)} + \sum e^{S_{i1}-m_i^{(1)}} $$

通过这种在线更新方式，FlashAttention 可以在遍历不同 Key 块的过程中持续维护完整 Softmax 所需的信息，而不需要保存之前计算得到的注意力矩阵。

除了 Softmax 统计量之外，输出结果也需要同步更新。对于：

$$ O_i=Softmax(S_i)V $$

FlashAttention 在处理新的 Key/Value 块时，会根据新的归一化因子调整已有输出，并融合当前块贡献：

$$ O_i^{new} = \frac{ e^{m_i^{old}-m_i^{new}}l_i^{old}O_i^{old} + e^{S_{ij}-m_i^{new}}V_j } {l_i^{new}} $$

因此，每处理一个新的 Key/Value 块，FlashAttention 都会更新三个状态：

- 当前最大值 $m_i$
- 当前归一化因子 $l_i$
- 当前输出 $O_i$

当所有 Key/Value 块遍历完成后，最终得到的输出：

$$ O_i=Softmax(Q_iK^T)V $$

与标准 Attention 的计算结果完全一致。

因此，Online Softmax 解决了分块 Attention 中“如何保持 Softmax 数学等价”的问题。结合前面的 Tiling 技术，FlashAttention 在不改变 Attention 计算结果的情况下，避免了生成完整的 $N\times N$ 注意力矩阵，将中间计算过程限制在 GPU 片上 SRAM 中，从而大幅减少 HBM 与计算核心之间的数据搬运开销。

## 四、总结

FlashAttention 的核心并不是减少 Attention 的理论计算量，而是针对 GPU 硬件特点优化计算流程。传统 Attention 虽然能够高效利用 GPU 的矩阵计算能力，但由于需要显式生成并频繁读写 $N\times N$ 注意力矩阵，导致大量时间消耗在 HBM 与片上计算单元之间的数据搬运上。

为了解决这一问题，FlashAttention 提出了两项关键技术：首先，通过 **Tiling 分块计算** 将 $Q、K、V$ 划分为小块，使注意力计算过程能够在 GPU 高速 SRAM 中完成，避免生成完整注意力矩阵；其次，通过 **Online Softmax** 动态维护 Softmax 所需的最大值和归一化因子，使分块计算结果与标准 Attention 保持数学一致。

因此，FlashAttention 本质上是一种 **IO-aware Attention 算法**。它没有改变 Attention 的计算形式，而是通过优化数据访问模式，减少不必要的显存读写，使 GPU 的计算资源得到更加充分的利用。在长序列 Transformer 模型中，这种优化显著降低了显存占用并提升了训练和推理效率，也成为现代大语言模型高效计算的重要基础技术之一。
