## Approximate Speculative Decoding (ASD)

## 1. 基本思路

投机解码是让小模型先预测多个 Token，再让大模型并行检查这些 Token，并在必要时输出修正的 Token。

但是如果我们严格要求大小模型的 Token 必须完全一致，那小模型给大模型减少的开销可能很少。

因此，我们可以考虑允许一定的误差。

## 2. ASD 怎么控制误差？

### 第一步：量化偏差有多大

定义：

r_i=z_i(y_i^*)-z_i(x_i)

其中：

- y_i^*：Target Model 最想输出的 Token。<br>
- x_i：Draft Model 建议的 Token。<br>
- z_i：Target Model 给 Token 的 Logit。<br>

例如：

Target Model 给 A 的 Logit 为 10.0，给草稿 Token B 的 Logit 为 9.9。

那么：

r_i=10.0-9.9=0.1

虽然 A 和 B 不一致，但模型对两者的偏好差距很小，因此 B 有可能被接受。

### 第二步：考虑后续还能复用多少 Token

论文进一步使用 r_i/(K-i+1) 作为局部门槛，让较早发生、潜在可复用后缀更长的偏差有更大接受空间。

论文定义：

\boxed{\frac{r_i}{K-i+1}\leq g}

其中：

- r_i：接受当前错误 Token 的代价（Logit Regret）。<br>
- K：草稿模型一共生成多少个 Token。<br>
- i：当前错误 Token 的位置。<br>
- K-i+1：从当前错误位置到草稿末尾，还剩多少个 Token（包括当前 Token）。<br>
- g：允许的单位潜在复用长度的 Regret 阈值。<br>

为什么要除以 K-i+1？

就是看后面还剩下几个位置。如果错误发生得比较早，后面可能还有很多 Token 可以复用，那么就可以适当放宽对这个错误的容忍度。

但剩余长度不代表后面一定有这么多 Token 可以复用。

### 第三步：限制误差的数量和总量

然后就是加上两个限制：

1. 限定在一个草稿块（Draft Block）里面最多允许多少个不同的 Token（比如说 2 个）。
2. 限定在整个推理过程中，累计允许的 Regret 有多少（比如说总预算为 8）。

注意：第二个限制不是最多允许 8 个不同的 Token，而是所有被接受的错误 Token 的 Regret 之和不能超过 8。

## 3. 另一个问题：第一个 Token 被拒绝后，后面怎么对齐？

还有一个东西需要提一下：

当小模型的第一个 Token 被拒绝了，后面要怎么对齐？

一般是根据大模型修正后的 Token，重新生成后续草稿。

### Carryover Drafting

论文：[Carryover Drafting: Recycling Rejected States for Speculative Decoding](https://arxiv.org/abs/2609.14717)

它不再尝试恢复旧的 Token，而是把旧的 Hidden States 放进小模型下一轮的额外 KV Context，允许小模型自行决定关注哪些信息。

**具体过程：**

1. **第 1 轮：推测失败**<br>

- 小模型 x_1 被拒绝。<br>
- 大模型输出 y_1。<br>

1. **保留信息**<br>

- 使用 y_1 得到修正后的真实前缀。<br>
- 保留被拒绝的 Hidden States。<br>

1. **下一轮 Draft Model**<br>

- 以正确前缀生成。<br>
- 同时通过额外 KV Context 读取上一轮的失败信息。<br>

1. **重新生成和验证**<br>

- 生成新的 x'_2,x'_3,x'_4,\ldots<br>
- 再交给 Target Model 严格验证。<br>

**特别重要的是：**

被拒绝的隐藏状态只是辅助信息，不进入 Target Model 已提交的 KV Cache，旧的验证结果也不会直接当作新前缀下的验证结果。
