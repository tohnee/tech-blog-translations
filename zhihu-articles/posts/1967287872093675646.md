并行策略是大模型部署的要学习的技术，因为单个处理器（GPU/TPU）根本无法容纳或快速处理如此庞大的模型和计算量。

举个例子，比如部署deepseek-72b版本的大模型，需要多少显卡，显存资源。deepseek-72b就是720亿的参数，FP16 精度下，每个参数占用 2 个字节。计算公式：`72,000,000,000 * 2 bytes = 144,000,000,000 bytes = 144 GB`，这还只是模型的权重，运行的时候，**KV缓存（推理时动态占用）**：对于DeepSeek这样的模型，一个4096长度的请求，KV缓存可能需要 **几GB到十几GB** 不等。还有一些比如用VLLM部署的时候，**框架和计算开销**：包括激活值、CUDA上下文、vLLM的PagedAttention机制等，至少需要 **几GB**。

大致计算：**总显存需求（FP16）**：`144 GB (权重) + 10 GB (KV缓存) + 5 GB (开销) ≈ 159 GB`

正常情况下，我们的一张4090 的显卡是24 GB，就算把上面的模型量化成int8, 每个参数占1个字节，一张4090的显卡也还是放不下。这时候，你想到，如果我把模型切成几分，多搞几个4090是不是就行了，这其实就是部署时候的并行思想。

这里一般用DP,TP,PP ，很多刚开始学习的人很容易搞晕，这里逐次每个都分析下；

1. TP (Tensor Parallelism) - 张量并行

- **核心思想**：把模型参数（张量）切开，分散到多个GPU上。
- **解决的核心问题**：**“能跑起来”**。当单个GPU的显存装不下整个模型时，TP是让模型能重新部署的关键。
- **在部署中的角色**：非常关键。对于任何需要多GPU才能运行的模型部署场景，TP都是**不可或缺**的基础技术。像 vLLM、TensorRT-LLM、Hugging Face TGI 等主流推理框架，其多GPU支持的核心就是TP。

### 工作流程（以一个简单的线性层 `Y = XA` 为例）

假设权重矩阵 `A` 非常大，我们把它按列切分成 `[A1, A2]`，分别放在GPU 0和GPU 1上。

1. **输入复制**：输入数据 `X` 被**广播**到所有参与计算的GPU上（GPU 0和GPU 1都有完整的 `X`）。
2. **分片计算**：

- GPU 0 计算 `Y1 = X * A1`
- GPU 1 计算 `Y2 = X * A2`

**结果聚合**：通过一个通信操作（如 `All-Gather`），GPU 0和GPU 1交换它们计算出的部分结果 `Y1` 和 `Y2`。最终，每个GPU都拥有了完整的输出 `Y = [Y1, Y2]`。

这个过程可以逐层应用到整个神经网络中。对于每一层，输入数据都需要在GPU间传递，计算完后再聚合，然后作为下一层的输入。

### 2. DP (Data Parallelism) - 数据并行

- **核心思想**：复制完整的模型到每个GPU，每个GPU处理不同的数据批次。
- **解决的核心问题**：**“跑得快”**（提高吞吐量）。它通过增加并行处理的批次数量来提升总体的QPS（每秒查询率）。
- **在部署中的角色**：**得力助手**。当你已经用TP把模型成功跑起来后，如果发现吞吐量还不够，可以引入DP来进一步提升。
- **掌握必要性**：**重要辅助**。

### 工作流程

1. **模型复制**：将完整的模型副本加载到每一个可用的GPU上。
2. **数据分片**：将一个大的数据批次（Batch）切分成多个小批次，每个GPU分到一个。
3. **独立计算**：每个GPU用自己的小批次数据，独立地进行前向传播，计算出各自的输出和损失。
4. **梯度同步**：

- 每个GPU根据各自的损失，反向传播计算出梯度。
- 通过一个通信操作（如 `All-Reduce`），所有GPU互相交换梯度，并计算出所有梯度的平均值。

**权重更新**：每个GPU都用这个**平均后的梯度**来更新自己的模型权重。因为所有GPU都用了相同的平均梯度，所以更新后，所有GPU上的模型依然保持一致。

### 3. PP (Pipeline Parallelism) - 流水线并行

- **核心思想**：把模型的层（Layers）切开，不同的GPU负责模型的不同部分（比如GPU 0负责前1/3的层，GPU 1负责中间1/3，GPU 2负责最后1/3）。
- **解决的核心问题**：**“能跑起来”** 和 **“减少通信开销”**。PP是另一种解决单卡显存不足的方法。当模型层数极多，或者GPU数量非常多时，TP的跨设备通信会成为瓶颈，PP可以将通信限制在相邻的“流水线阶段”之间。
- **在部署中的角色**：**专家工具**。PP比TP更复杂，它引入了“流水线气泡”问题（即GPU在等待前一阶段输出时会空闲），实现和优化难度都更高。
- **掌握必要性**：**高级可选**。

这里可以先掌握TP,和DP ，先跑通几个简单的案列。那么再分析一下TP和DP 之间的通信方式：

首先：**数据并行：解决“数据太大”的问题。**

### 数据并行 的通信：`All-Reduce`

DP 的通信模式非常清晰和固定，发生在每个训练步骤的**后向传播之后**。

**工作流程：**

1. **前向传播：** 每个 GPU 使用自己独有的数据分片，独立进行前向计算，得到损失。
2. **后向传播：** 每个 GPU 独立进行反向传播，计算出**本地梯度**。此时，每个 GPU 上的梯度都是基于自己那部分数据得出的，存在差异。
3. **通信（关键步骤）：** 所有 GPU 需要交换梯度，并计算出全局的平均梯度。这个操作完美地由 **`All-Reduce`** 通信算子完成。

- **`All-Reduce`** **的作用：** 对所有 GPU 上的张量（这里是梯度）执行一个 `Reduce` 操作（如求和、求平均），然后将最终结果分发给所有 GPU。
- **为什么是** **`All-Reduce`？** 因为每个 GPU 都需要得到最终的平均梯度来更新自己的模型副本。`All-Reduce` 是最高效的方式。

**权重更新：** 每个 GPU 使用收到的平均梯度，独立更新自己的模型权重。由于大家用了相同的平均梯度，更新后的模型权重再次保持一致。

**DP 通信特点：**

- **通信内容：** 梯度张量（大小与模型参数成正比）。
- **通信时机：** 每个训练步骤（Step）结束时。
- **通信模式：** **`All-Reduce`**。
- **通信瓶颈：** 通信量与模型大小成正比。模型越大，每次 `All-Reduce` 的数据量就越大，通信开销也越大。

刚才说的是训练阶段，推理阶段因为模型已经训练好了，没有梯度要更新，也就不需要All-Reduce

- **张量并行：解决“模型太大”的问题。**<br>

简单来说：**在张量并行的推理阶段，你只需要关心前向传播的通信，后向传播的所有通信都完全消失了。**

### 一、回顾：训练阶段的 TP 通信

- **前向传播：** 需要通过 `All-Gather` 来拼接被切分的权重矩阵计算出的部分输出，以得到完整的激活值 `Y`。
- **后向传播：** 需要通过 `All-Reduce` 来同步关于输入 `X` 的梯度 `dX`。

### 二、推理阶段的 TP 通信：只剩下 `All-Gather`

在推理阶段，我们**没有后向传播**，因此所有与梯度相关的通信（如 `All-Reduce`）都自然消失了。但是，前向传播的 `All-Gather` 通信**依然存在**。

我们继续使用 `Y = XA`，权重 `A` 按列切分到两个 GPU 上的例子。

**推理阶段的工作流程：**

1. **数据准备：** 输入 `X` 被广播到两个 GPU。权重 `A` 被切分为 `[A1, A2]`，GPU1 拥有 `A1`，GPU2 拥有 `A2`。（这一步和训练一样）
2. **本地计算：**

- GPU1 计算 `Y_1 = X * A1`
- GPU2 计算 `Y_2 = X * A2`<br>（这一步和训练一样）

**通信（关键步骤）：** 为了得到完整的输出 `Y = [Y_1, Y_2]`，两个 GPU 仍然需要交换它们计算出的部分结果。这个操作**依然由** **`All-Gather`** **完成**。<br>

- **为什么** **`All-Gather`** **在推理时仍然是必需的？**

**得到完整输出：** 通信后，GPU1 和 GPU2 都拥有了完整的 `Y`。然后，它们可以独立地、并行地将这个完整的 `Y` 作为输入，进行下一层的计算。

**推理阶段的后向传播：**<br>**不存在。** 因此，计算 `dA`、`dX` 以及同步 `dX` 的 `All-Reduce` 操作全部消失。
