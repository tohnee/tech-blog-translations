## vLLM PagedAttention全面解析（权威数据版）

### 一、PagedAttention的来源与背景

### 传统静态KV缓存的致命缺陷

在PagedAttention出现之前，所有大模型推理系统都采用**静态连续KV缓存管理方式**：为每个请求预分配一块等于最大上下文长度的连续显存空间。这种方式存在三个无法克服的缺陷，根据UC Berkeley团队2023年发表在SOSP 2023的获奖论文《Efficient Memory Management for Large Language Model Serving with PagedAttention》实测：

1. **严重的内存碎片化**：不同请求的长度差异巨大，释放后会留下大量无法利用的小碎片
2. **过度预留浪费**：大多数请求的实际长度远小于最大上下文长度，预分配的空间大部分从未被使用
3. **无法共享前缀**：即使多个请求有完全相同的系统提示词或对话历史，也需要各自计算和存储一份KV缓存

**论文核心发现**：传统系统中**60%-80%的GPU显存被浪费**，KV缓存的实际利用率仅为**20.4%-38.2%**。这意味着一张A100-40GB GPU上预留给KV缓存的12GB空间，实际只用了2.5-4.6GB。

### PagedAttention的诞生

**PagedAttention（分页注意力）** 由**UC Berkeley天空计算实验室**的Woosuk Kwon、Zhuohan Li等人于2023年6月提出，是vLLM推理引擎的核心技术。该论文获得了**SOSP 2023最佳论文奖**，截至2026年6月已被引用超过3500次。

**核心设计灵感**：借鉴操作系统中成熟的**虚拟内存分页技术**，将KV缓存分割成固定大小的”页”，允许非连续存储和灵活共享，从根本上解决了内存碎片化和浪费问题。

### 二、PagedAttention的基础原理

### 核心思想：KV缓存分页化

PagedAttention将操作系统虚拟内存的管理思想完美移植到GPU显存管理中：

- 操作系统：将程序的虚拟地址空间分割成固定大小的页，映射到物理内存的任意位置
- PagedAttention：将每个序列的KV缓存分割成固定大小的**KV块**（默认16个token/块），映射到GPU显存的任意物理块

这种设计打破了KV缓存必须连续存储的限制，实现了近乎完美的内存利用率。

### 关键概念

1. **KV块（Block）**：内存分配的基本单位，每个块包含固定数量token的Key和Value向量。默认大小为16个token，这是并行效率和碎片率的最佳权衡。
2. **逻辑块**：从单个请求视角看到的连续KV块序列
3. **物理块**：GPU显存中实际存储KV数据的物理内存块
4. **块表（Block Table）**：每个请求维护的映射表，记录逻辑块到物理块的对应关系，类似于操作系统的页表

```text
// 块表的简化数据结构
struct BlockTable {
    int* block_mapping;    // 逻辑块号 -> 物理块号
    int* block_usage;      // 每个物理块中的有效token数量
    int total_length;      // 序列总长度
    int ref_count;         // 引用计数，用于前缀共享
};
```

### 完整工作流程

### 1. 系统初始化

- 将GPU显存中除模型权重外的所有空间分割成固定大小的物理KV块
- 维护一个全局**空闲块池**，记录所有可用的物理块

### 2. 预填充阶段（Prefill）

- 接收用户的prompt，计算所有prompt token的K和V向量
- 按照16个token/块的大小，将K和V向量分割成多个逻辑块
- 从空闲块池申请物理块，将逻辑块映射到物理块
- 将K和V数据写入对应的物理块
- 更新块表记录

### 3. 解码阶段（Decode）

- 每次生成一个新token，计算其K和V向量
- 检查当前序列的最后一个物理块是否已满
- 如果未满，直接将新的K和V写入该块
- 如果已满，从空闲块池申请一个新的物理块，添加到块表中
- 使用块表索引所有历史KV块，计算注意力

### 4. 请求结束

- 将该请求使用的所有物理块归还到空闲块池
- 清空块表，释放资源

### 注意力计算过程

PagedAttention最巧妙的地方在于，它能够高效地对存储在非连续物理块中的KV数据进行注意力计算，而不需要提前将它们复制到连续的内存空间：

1. 当需要计算注意力时，PagedAttention内核首先查询块表
2. 根据块表找到所有需要的物理块地址
3. 直接从这些非连续的物理块中读取K和V数据
4. 在SM寄存器中拼接成逻辑上连续的KV缓存
5. 执行标准的注意力计算

这种设计完全隐藏了非连续存储的开销，注意力计算的性能与连续存储几乎相同。

### 一个具体的内存分配例子

假设我们有4个请求，块大小为16个token：

- 请求A：长度20 → 需要2个物理块（16+4）
- 请求B：长度35 → 需要3个物理块（16+16+3）
- 请求C：长度12 → 需要1个物理块
- 请求D：长度48 → 需要3个物理块

**传统静态缓存**：

- 预分配4块×最大上下文长度（如4096）的连续显存
- 总占用：4×4096×KV大小 = 大量浪费

**PagedAttention**：

- 总共只需要2+3+1+3=9个物理块
- 总占用：9×16×KV大小
- 内存利用率：(20+35+12+48)/(9×16) = 115⁄144 ≈ 80%
- 浪费仅发生在每个序列的最后一个块，总浪费率%

### 三、PagedAttention的核心技术特性

### 1. 零内存碎片化

PagedAttention通过固定大小的块分配和回收，彻底消除了内存碎片化：

- 所有物理块大小相同，分配和回收都是O(1)操作
- 不会留下无法利用的小碎片
- 内存利用率从传统的20-40%提升到**96%以上**
- 浪费仅发生在每个序列的最后一个块，总浪费率不足4%

### 2. 连续批处理（Continuous Batching）

PagedAttention使**连续批处理**成为可能，这是vLLM吞吐量大幅提升的另一个关键原因：

- 传统静态批处理：必须等待一个批次的所有请求都完成后，才能开始下一个批次
- 连续批处理：当一个请求完成时，立即将其占用的物理块归还到空闲池，然后立即添加一个新的请求到批次中
- 不需要等待批次中的慢请求，GPU几乎永远不会空闲

**效果**：连续批处理可以将GPU利用率从传统的30-40%提升到90%以上，吞吐量提高2-4倍。

### 3. 自动前缀共享（Automatic Prefix Caching）

PagedAttention通过**写时复制（Copy-on-Write）**机制，实现了高效的KV缓存共享：

- 多个请求如果有相同的前缀，它们可以共享相同的物理KV块
- 只有当某个请求的序列偏离共享前缀时，才会为其分配新的物理块
- 物理块的引用计数自动管理，当引用计数降为0时才会被回收

**效果**：

- 在多轮对话场景下，首token延迟降低**70%**
- 系统提示词只需要计算一次，所有请求都可以共享
- Beam Search等解码算法的效率提升10倍以上

### 4. 与其他优化技术的完美兼容性

PagedAttention可以与几乎所有主流的大模型优化技术无缝结合：

- **量化**：支持GPTQ、AWQ、INT4/INT8/FP8等多种量化方案
- **FlashAttention**：与FlashAttention 2/3深度集成，进一步提升注意力计算速度
- **张量并行**：支持多GPU张量并行推理
- **流水线并行**：支持超大规模模型的流水线并行
- **MLA**：与DeepSeek的MLA潜在KV缓存完美结合，内存效率再提升50倍

### 四、PagedAttention的作用位置

### 在vLLM软件栈中的位置

PagedAttention是vLLM的核心，位于调度器和模型执行器之间：

```text
vLLM API Server
    ↑
请求调度器（Scheduler）
    ↑
KV缓存管理器（PagedAttention核心） ← 作用位置
    ↑
模型执行器（Model Executor）
    ↑
CUDA Runtime / NCCL
    ↑
GPU硬件
```

**KV缓存管理器的职责**：

- 维护全局空闲块池
- 为每个请求分配和回收物理块
- 管理块表和引用计数
- 实现前缀共享和写时复制

### 在Transformer架构中的作用位置

PagedAttention完全替代了传统的静态KV缓存管理，位于每个Transformer块的注意力层内部：

```text
Transformer Block:
  1. LayerNorm
  2. Multi-Head Attention
     - 输入：当前token的隐藏状态
     - 计算：Q = h @ W_Q, K = h @ W_K, V = h @ W_V
     - 缓存管理：通过PagedAttention将K和V写入物理KV块  ← 作用位置
     - 注意力计算：通过块表索引所有历史KV块，计算注意力
  3. Residual Connection
  4. LayerNorm
  5. Feed Forward Network
  6. Residual Connection
```

### 七、局限性与未来发展方向

### 当前局限性

1. **长上下文的块表开销**：当序列长度达到1M时，块表本身会占用一定的显存空间
2. **预填充阶段优化不足**：预填充阶段仍然需要一次性处理所有prompt token，对于超长prompt可能会出现OOM
3. **与动态稀疏注意力的兼容性**：与Mamba等状态空间模型的兼容性还不够好

### 未来发展方向

1. **动态块大小**：根据序列长度动态调整块大小，进一步减少内部碎片
2. **硬件加速的块表**：将块表存储在GPU的高速缓存中，进一步降低索引开销
3. **统一内存分页**：支持将不常用的KV块交换到CPU内存或SSD，进一步扩展上下文长度
4. **与MLA的深度融合**：针对MLA的潜在KV缓存优化PagedAttention的块大小和索引方式
