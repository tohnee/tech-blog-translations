## **大模型训练的内存开销**

用 **X** 代表这个参数量，在FP16的精度下达到 **2X**，用DeepSpeed论文中Adam+混合精度训练作为例子。模型在训练过程中需要储存自身的参数和梯度（注意这里还不是Adam最后算出来的参数更新量，只是根据loss反向传播得到的原始梯度），这便需要 **2X + 2X** 的内存，同时混合精度fp32训练时，Adam需要一份fp32大小的模型拷贝，momentum和variance去储存模型的优化器状态，这需要 **4X + 4X + 4X** ，最终我们需要 **16X** 的内存用于训练，即对于一个3GB的GPT-2模型，我们训练时需要24GB的内存，对比一张V100的显存为32GB，也就是**模型最终需要的训练内存为模型本身参数量的8倍**

### **ZeRO-DP（ZeRO-1,2,3本质都是在数据并行上做工）**

[https://arxiv.org/pdf/1910.02054](https://arxiv.org/pdf/1910.02054)

### **DP**

每个GPU上保存完整模型参数，只做数据切分

- 前向传播 - 每个GPU拿到自己的1/4数据，用完整模型计算出loss
- 反向传播 - 每个GPU根据自己的loss做反向传播，计算出各自的梯度
- 梯度同步（All-Reduce）-
- 参数更新

![](https://pica.zhimg.com/v2-5dfb825b293e5756ab1f5f5ded68a796_r.jpg)

ZeRO (Zero RedundancyOptimizer)

在数据并行的管线上把模型的参数分配到不同的显卡上，不用所有显卡都装载参数

把训练期间的内存消耗分为三类：

- OS：优化器状态（Adam的 momentum和 variance）
- G：梯度
- P：模型参数

三类数据都可以被切分，区别在于什么时候做reduce-scatter

本质是以时间换空间，分布式意味着需要数据广播的时间，但是可以显著降低单卡的显存占用

### **ZeRO-1：优化器状态分片**

**原理**：ZeRO-1是最基础的优化，它只将**优化器状态**（`2P`）这一项在N个GPU上进行分片。模型参数和梯度仍然在每个GPU上保留完整的副本。

它的工作流程可以概括为：

1. **前向与反向传播**：和传统数据并行一样，每个GPU使用完整的模型参数计算，并产生完整的梯度。
2. **梯度同步**：通过`AllReduce`操作同步所有GPU的梯度，保证每个GPU都有相同的完整梯度。
3. **参数更新**：每个GPU只使用**自己分到的那部分**优化器状态（如动量），来更新**所有**参数中对应的那一片。

**显存与通信**：

- **显存**：单卡显存占用从 `4P` 降至约 `(2 + 2/N)P`。当 `N=8` 时，优化器状态减少87.5%，总显存占用减少约62.5%。
- **通信**：通信量与传统数据并行相同。

**适用场景**：适用于模型参数量在百亿到千亿级别，优化器状态（Adam的动量、方差）是显存主要瓶颈的场景。如果你的模型还没大到让梯度成为主要问题，这是一个性价比很高的起点。

---

### **ZeRO-2：优化器状态 + 梯度分片**

**原理**：ZeRO-2在ZeRO-1的基础上更进一步，将**梯度**（`P`）也进行了分片存储。此时，每个GPU只保存**与自己优化器状态分片相对应的那部分梯度**。

**显存与通信**：

- **显存**：单卡显存占用进一步降至约 `(1 + 3/N)P`。当 `N=8` 时，相比传统数据并行，总显存占用减少约75%。
- **通信**：通信量**依然**与传统数据并行相同。原因就在于它将`AllReduce`拆分成了`ReduceScatter` + `AllGather`。

**适用场景**：ZeRO-2是训练**千亿参数**模型时的主流选择。它在显存节省和通信开销之间取得了很好的平衡，比ZeRO-1提供了更大的显存优化，又没有增加额外的通信成本。

---

### **ZeRO-3：优化器状态 + 梯度 + 参数分片**

**原理**：ZeRO-3是ZeRO的终极形态，它将**模型参数**（`P`）也进行了分片。至此，**优化器状态、梯度、模型参数**这三项模型状态全部被分片存储。

这带来了根本性的变化：每个GPU不再拥有完整的模型。在前向和反向传播过程中，ZeRO-3会动态地**收集（Gather）** 所需的参数分片，计算完成后，再**释放（Partition）** 它们。

**显存与通信**：

- **显存**：单卡显存占用与GPU数量 `N` 成**线性反比**关系，约为 `4P/N`。这使得训练**万亿级别**的模型成为可能。
- **通信**：这是ZeRO-3最主要的代价。由于需要频繁地收集和释放参数，其通信量相比传统数据并行会**显著增加**。有分析指出，通信量可能增加**8倍**之多。

**适用场景**：适用于需要训练**超大规模（万亿参数）** 模型的场景，此时显存是压倒一切的首要矛盾。你愿意接受更高的通信开销来换取最大的显存节省。

**ZeRO-Offload 与 ZeRO-Infinity**

除了这三个核心阶段，DeepSpeed还提供了将显存压力转移到CPU甚至NVMe硬盘的“卸载”（Offload）功能。

- **ZeRO-Offload**：通常与ZeRO-2结合，将优化器状态和梯度卸载到CPU内存。
- **ZeRO-Infinity**：是ZeRO-3的增强版，能将**所有模型状态**（参数、梯度、优化器状态）卸载到CPU或NVMe内存。

这相当于在ZeRO-3的基础上，用**更慢的存储**（CPU内存或硬盘）来**换取更多的显存**，让单卡也能微调数百亿参数的大模型。

**注：理性看待分布式训练，本质是时间换空间，如果模型参数量很小，显存充足那么就不需要切分**

### **总结与对比**

| 特性 | ZeRO-1 | ZeRO-2 | ZeRO-3 |
| --- | --- | --- | --- |
| 分片内容 | 优化器状态 | 优化器状态 + 梯度 | 优化器状态 + 梯度 + 参数 |
| 单卡显存占用 | `(2 + 2/N)P` | `(1 + 3/N)P` | `4P/N` |
| 通信开销 | 与传统DP相同 | 与传统DP相同 | 显著增加 |
| 核心优势 | 简单高效，零额外通信 | 平衡了显存与通信 | 极致显存节省，支持万亿模型 |
| 主要代价 | 显存节省有限 | 实现稍复杂 | 通信成为新瓶颈 |
| 适用模型规模 | 百亿级 | 千亿级 | 万亿级 |

## 三种策略

### **1. 数据并行 (DP)**

为了完整性，简要回顾：

- **切分对象**：**训练数据（Batch）**。
- **模型状态**：每张卡存有模型的**完整副本**（参数、梯度、优化器状态）。
- **核心通信**：反向传播后的**All-Reduce（全规约）**，同步所有卡的梯度。
- **通信量**：每迭代一次约 ( 2\Psi )（( \Psi ) 为参数量）。
- **特点**：计算利用率最高，但显存冗余最大（每张卡都要装下全量模型）。

---

### **2. 流水线并行 (Pipeline Parallelism, PP) —— 纵向切层**

PP 的核心思想是**按网络层（Layer）进行划分**，将模型的不同层放在不同的 GPU 上。

- **切分方式**：假设模型有 40 层，4 张 GPU，则 GPU 0 负责 1-10 层，GPU 1 负责 11-20 层，以此类推。
- **执行流程（微批次）**：为了避免 GPU 空闲（“气泡”），输入数据会被切分成更细的 **Micro-batch（微批次）**。GPU 0 算完微批次 1 的前向，传给 GPU 1，接着马上开始算微批次 2，形成流水线。
- **通信量**：**极低**。只在相邻 GPU 之间传输**激活值（Activation）**和**梯度**，传输的数据量仅为 `Batch_Size * Hidden_Size`，远比模型参数量小得多。
- **显存变化**：单卡只需存储 ( 1/N ) 的层参数，显存压力线性下降。
- **缺点**：存在**“流水线气泡”**（空闲等待时间），且需要精细切分层数，很难做到完美负载均衡。

---

### **3. 张量并行 (Tensor Parallelism, TP) —— 横向切层（切权重）**

TP 的核心思想是**对单层内的矩阵乘法（GEMM）进行拆解**。它不像 PP 切层，而是在**层内**将权重矩阵按行或列切开。

- **切分方式（以列切分为例）**：假设权重矩阵为 ( W )（维度 ( A \times B )），( N ) 张卡分别保存 ( W ) 的 ( 1/N ) 列（即 ( A \times (B/N) )）。输入 ( X ) 分发给所有卡，各自做矩阵乘法，最后通过 **All-Reduce** 将结果拼凑起来。
- **通信量**：**极高且极其频繁**。
- **硬件依赖**：TP 的通信延迟极大，**必须依赖极高速互联**（如 Nvidia NVLink 和 NVSwitch），通常限制在**同一台物理机内的 4-8 张卡**。如果跨机器做 TP，网络延迟会拖垮训练速度。
- **优点**：能切分巨大的权重矩阵，支持单卡装不下的超宽模型（如 MoE 专家并行）。

---

### **4. 三大策略的对比**

| 维度 | 数据并行 (DP) | 流水线并行 (PP) | 张量并行 (TP) |
| --- | --- | --- | --- |
| 切分对象 | 训练数据 | 模型层（纵向） | 层内权重（横向） |
| 通信频率 | 每个迭代一次 | 每层/每微批次一次 | 每一层的前后向都发生 |
| 通信数据量 | 中等（梯度全量，约 ( 2\Psi )） | 很小（仅相邻层激活值） | 极大（全量中间结果） |
| 硬件要求 | 普通以太网/InfiniBand | InfiniBand（高速网卡） | 必须 NVLink（机内互联） |
| 负载均衡 | 完美均衡 | 容易产生空闲“气泡” | 切分粒度细，易均衡 |
| 代码侵入性 | 低（PyTorch DDP 封装好） | 中（需改模型结构成 `Sequential`） | 高（需重写矩阵乘法的切分逻辑） |

### **5. 实际业界是如何组合使用的？（3D 并行）**

在实际训练万亿参数模型（如 GPT-4、Llama 3）时，**没有人单独使用其中一种**，而是采用 **3D 并行**的层次化结构：

1. **第一层（机内）**：在一台 8 卡 A100 服务器内，卡与卡之间通过最快的 NVLink 连接。这里使用 **张量并行（TP）**，通常设为 4 或 8。因为通信延迟最低，适合高频率同步。
2. **第二层（机间）**：跨多台服务器（通过 InfiniBand 网卡）。服务器间通信延迟较高，这里使用 **流水线并行（PP）**，因为 PP 通信量小，能扛住较高的网络延迟。
3. **第三层（跨节点）**：在所有的服务器集群上，使用 **数据并行（DP）**，将海量数据分散到庞大的集群中，仅在每个迭代末尾做一次梯度同步。

典型的业界配置是：`DP * PP * TP = GPU 总卡数`。例如，用 1024 张卡，可能会设 TP=8（机内），PP=8（跨机流水线），DP=16（大规模数据切片）。
