我本来只是想让 GPT 帮我画一套游戏 UI。

结果做到后面有点超出预期：

从几张游戏截图开始，它先自己拆视觉规范，再生成商城、图鉴、活动页；接着把 UI 拆成 Sprite Sheet 和 PSD 图层，最后甚至直接进 Cocos Creator，把场景和代码都搭出来了。

也就是说，这次我基本把一条「参考图 → UI → 切图 → PSD → Cocos 工程」的链路跑通了。

第一步：别急着画，先让 GPT 当美术总监

我现在发现，想让 AI 做出风格统一的游戏 UI，最重要的不是你会不会写一大串提示词。

最简单的办法，是直接把你喜欢的游戏截图丢给它，让它先别画，先拆。

我这次让它从美术风格、色彩、材质、光影、按钮、面板、字体、图标、信息层级等 10 个维度，把参考图整理成一套视觉规范。

有了这套规范之后，再让它做商城、图鉴、活动页，风格就明显稳定很多。

这里我觉得比“单张图画得好看”更重要的是：它开始有能力维持一套产品级 UI 的视觉一致性。

商城、图鉴、活动页虽然功能完全不同，但木质面板、米黄色底色、花卉装饰、按钮材质、字体层级基本都在同一套视觉语言里。

对独立开发者来说，这比偶尔生成一张神图有用得多。

我传了几张《我的花园世界》的截图给它，让大模型自己总结设计规范。

然后根据规范生成了一整套游戏的UI

当然也有局部不满意的地方，你可以局部精修，GPT现在指哪打哪。

这样还不止，你可以进一步要求，把得到的UI图，切图导出图层和PSD文件，这个过程完全不用打开 Photoshop。

除了导出Sprite Sheet外，你还再更进一步要求多更复杂的事情。

让GPT控制Cocos Creator，创建一个项目，将刚刚生成的素材，直接在游戏编辑器里生成场景，右边就是Cocos真实项目的以预览

这次真正让我有感觉的，其实不是 GPT 又能画出更漂亮的图了。

而是以前几个割裂的环节，正在被串起来。

以前做一套小游戏 UI，大概是：

找参考 → 出视觉稿 → 反复修改 → 切图 → PSD → 导入引擎 → 搭界面 → 写代码。

现在我第一次比较完整地跑了一遍：

参考图 → AI 理解视觉规范 → 批量生成 UI → 局部精修 → 素材拆分 → PSD / Sprite Sheet → Cocos Creator 工程。

目前离真正“一句话生成完整游戏”当然还远，尤其是细节修改、交互逻辑、适配和最终工程质量，还是需要开发者自己把关。

但对于我这种自己做小游戏的人来说，这已经不是“AI 帮我画张图”了。

它开始真的进入游戏开发工作流了。
