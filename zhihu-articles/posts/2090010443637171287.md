大家好，我们是 Apple 和 CMU 的研究团队，最近我们的新工作 Selection-based Structured Reasoning (SSR)上线了。这篇文章想和大家聊聊：为什么Small Agent 的推理环节如此"烧钱"，以及如何把每轮推理延迟降低 90% 以上，同时不掉点。

![](https://pic4.zhimg.com/v2-897b4eeb433993e4fe04a16833cde62d_r.jpg)

**一、问题的出发点：小模型的"废话文学"**

这篇工作的出发点其实来自一个非常简单的问题：

Agent 每执行一个 action 之前，真的有必要重新生成一大段自由形式的推理(free-form thinking)吗？

现在很多 Search Agent 都遵循类似 ReAct 的范式：

Observation → Reasoning → Action → Observation → Reasoning → Action → …

例如模型看到一张图片，问题问「这栋建筑里接下来会举办什么展览」。

一个常见的 Agent 可能先生成：

这张图片看起来像某个博物馆……我需要先判断建筑是什么……然后搜索它最近的展览……

接着再生成一个 search query。

对于 2B、4B 这样的小模型，我们观察到一个现象：它们有时会生成相当长的 reasoning，但这些 reasoning 对最终 action 的帮助并不与其长度成正比。换句话说，我们付出了大量 sequential decoding cost，却未必获得对应的决策收益。

**二、核心观察：搜索 Agent 的"高层推理"其实高度重复**

我们分析了大量多模态搜索轨迹后发现一个有趣的现象：虽然每道题的实体、查询、观察结果千差万别，但决定下一步动作的高层推理逻辑是反复出现的。

举个例子：

- 问"某张图里的建筑要办什么展览？"
- 问"LEGO 是哪年成立的？"

这两道题的推理可以是同一条："实体已知但目标信息缺失，用实体名+目标属性去搜索。"

这启发我们：搜索 Agent 需要的推理空间并不覆盖整个自然语言空间。与其每次费力生成，不如预定义好一组可复用的自然语言推理选项，让模型像做选择题一样做推理。

**三、方法：Selection-based Structured Reasoning (SSR)**

3.1 推理库 + 选择式推理

我们构建了一个包含 6 条自然语言推理选项的推理库（全部 benchmark 共享同一套推理库）：

1. 不确定图中实体 → 用以图搜图来识别；
2. 需要具体事实 → 用文本搜索查询；
3. 需要局部细节 → 裁剪/放大图片局部；
4. 证据已收集 → 基于证据作答；
5. 图里就有答案 → 基于图片作答；
6. 常识可答 → 直接作答。

每轮交互时，Agent 不再逐字生成推理，而是从推理库中选一条作为当前轮的推理，再基于选中的推理去生成具体的动作（比如这次搜索该用什么 query、裁剪哪个框）。

3.2 用模型本身打分，不需要额外的分类头

关键问题是：怎么选？我们的做法是直接用 LLM 自己当分类器。对每个推理选项，计算它在当前上下文下的长度归一化对数似然。softmax 之后就是一个定义在推理库上的类别分布，采样即完成推理选择。不需要额外的任务头、不需要 SFT warm start，打分和动作生成共享同一套模型参数和 system prompt。

3.3 Parallel Reasoning Decoding：推理的"并行解码"

这是 SSR 效率优势的来源。因为推理库是提前定义的，我们可以：

- Token 级并行：用 teacher forcing 一次性 prefill 整条选项，所有 token 的似然在一个 batched forward pass 里算完；
- Candidate 级并行：所有候选共享同一份上下文 KV cache，同时打分。

（我们在project page里有一个动图演示这个过程）

也就是说，整个推理过程模型不需要自回归生成任何新 token。

下图有个直观例子：同一道多模态搜索题，free-form thinking生成了 156 个 token、耗时 1821 ms（还因为想太多选错了动作）；SSR 选择 31 个 token 的选项只要 32 ms，并且动作正确。

![](https://picx.zhimg.com/v2-ccc43bc31f72e79a7d410f8b3258c0ff_r.jpg)

3.4 训练：SFT 和 RL 可以直接Plug-in SSR

SSR 是一个通用的reasoning替代方案：

- SFT：基于推理库做选择题的交叉熵损失 + 动作 token 的生成损失，加权联合优化；
- RL（GRPO / GSPO / SAPO）：把自由形式 GRPO 中推理 token 的重要性比率替换成一条推理选择的分类型比率，再加上标准 clipped surrogate 目标即可。

一个额外的好处：因为推理被约束在推理库内，SSR 可以直接用 RL 训练，不需要 SFT warm start。而很多现有工作需要先用 SFT 教会模型"特定的思考方式"才能上 RL。SSR可以减少SFT阶段的数据构造和训练时间，也让行为更可预测、更可控。

**四、实验结果**

Setup：Qwen3-VL 2B/4B，H100 + SGLang 离线推理，7 个多模态搜索 benchmark（MMSearch、HR-MMSearch、FVQA-test、InfoSeek、SimpleVQA、LiveVQA、MAT-Search）。

性能不掉点：

- 4B SSR (GRPO) 平均成功率 61.37%，与同规模 SOTA（TAPO+GSPO 的 61.25%）持平，超过 MMSearch-R1 和 SenseNova-MARS；
- 2B SSR 达到 51.26%，堪比零样本 8B 模型；
- 在 GRPO / GSPO / SAPO / SFT 四种训练目标下，SSR 与对应的free-form thinking成功率相当。

效率大幅提升：

- 每轮推理延迟降低超过 90%；
- 每题模型总推理延迟降低 28–54%；
- 与四个efficiency baseline（Chain-of-Draft、Sketch-of-Thought、效率奖励 RL、Probe & Prefill）相比，SSR 成功率最高，p95 推理延迟仅 0.07 s（baseline 在 0.8–1.9 s）且更加稳定。

**五、消融实验里几个有意思的发现**

5.1 语义很重要：如果只让模型选候选编号（如"[1]"）而不是完整文本，平均成功率下降 3.9%。说明用完整自然语言打分确实在利用模型的语义理解能力做匹配，而不是学一个纯索引分类器。

5.2 推理库规模：从 1 条通用候选增加到 6 条，平均成功率从 37.24% 单调提升到 61.37%。更多样、更细粒度的推理候选能更好地指导动作生成。

5.3 选择是自适应的：同一个 checkpoint 在不同 benchmark 上呈现出不同的选择分。SimpleVQA 上"基于图片作答"占比最高，而高分辨率图片为主的 HR-MMSearch 上"检查图片细节"占比最高。

5.4 对比自回归版本：也可以训练模型用自回归方式"生成"库中候选，但必须依赖 SFT 先教会它遵守格式；仅靠 prompt + 格式奖励的 RL 无法约束它不乱想。而 SSR 从机制上直接保证了推理的结果来自于提前定义好的推理库。

这篇工作真正想讨论的，可能并不只是“怎么让 CoT 更短”，而是一个更基础的问题：Reasoning 的表示方式是否一定要依赖 unrestricted natural-language generation？ 对于开放式数学推理、证明或代码设计，自由生成带来的表达能力非常重要；但在很多 multi-turn search 和 tool-use 场景里，Agent 每一步面对的往往只是少数几类高层决策，例如当前信息是否足够、是否需要识别图中实体、是否需要继续搜索、是否需要放大局部区域等。真正高度依赖具体输入的部分，比如 search query、tool arguments、crop coordinates 和 final answer，仍然可以由模型自由生成，但 strategy-level reasoning 未必需要每次都在完整的自然语言空间里重新生成。因此，我们更愿意把 SSR 看成是把 reasoning space 从一个完全开放的语言空间，重新组织成一个 compact、reusable、semantically meaningful 的 strategy space：模型并不是“不思考了”，而是把一部分原本通过 sequential token generation 完成的 reasoning，转化为了对结构化 strategy space 的选择和推断。
