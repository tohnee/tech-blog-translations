### 基础环境配置

我的基础环境，供参考

- CUDA-12.4
- TensorRT-10.11.0.33
- cudnn-linux-x86_64-9.14.0.64_cuda12-archive
- torch 2.6.0

由于需要用到python中的tensorrt，所以需要先安装一下（下面的whl直接去官网下载即可）

```text
pip install ~/TensorRT-10.11.0.33.Linux.x86_64-gnu.cuda-12.9/TensorRT-10.11.0.33/python/tensorrt-10.11.0.33-cp310-none-linux_x86_64.whl
pip install ~/TensorRT-10.11.0.33.Linux.x86_64-gnu.cuda-12.9/TensorRT-10.11.0.33/python/tensorrt_dispatch-10.11.0.33-cp310-none-linux_x86_64.whl 
pip install ~/TensorRT-10.11.0.33.Linux.x86_64-gnu.cuda-12.9/TensorRT-10.11.0.33/python/tensorrt_lean-10.11.0.33-cp310-none-linux_x86_64.whl
```

### 开始踩坑

然后直接clone上面链接的代码，然后把该库依赖的环境安装好

```text
pip install -U nvidia-modelopt[onnx]
pip install -r requirements.txt

cd TensorRT-Model-Optimizer/examples/onnx_ptq
python download_example_onnx.py --vit --onnx_save_path=vit_base_patch16_224.onnx --fp16
```

运行`download_example_onnx.py`的时候会出现这个问题

```text
TypeError: get_onnx_bytes_and_metadata() got an unexpected keyword argument 'model_name'
```

去看了下这个接口，其实是有这个参数的，那么就是pip install的库有问题，所以我直接没有使用这个pip的库而是直接用了源码,改一下PYTHONPATH即可

```text
export PYTHONPATH=PATH/TensorRT-Model-Optimizer
```

紧接着就是运行下面的指令,生成一个onnx和一个npy

```text
python download_example_onnx.py --vit --onnx_save_path=vit_base_patch16_224.onnx --fp16
python image_prep.py --calibration_data_size=500 --output_path=calib.npy --fp16
```

然后我们开始量化，选择FP8

```text
python -m modelopt.onnx.quantization --onnx_path=vit_base_patch16_224.onnx --quantize_mode=fp8 --calibration_data=calib.npy --calibration_method=entropy --output_path=vit_base_patch16_224.quant.onnx
```

报了个错

```text
onnxruntime.capi.onnxruntime_pybind11_state.Fail: [ONNXRuntimeError] : 1 : FAIL : CopyTensorAsync is not implemented
```

然后去查了下，在这个issue下面有一个解决方案

[issue](https://github.com/NVIDIA/TensorRT-Model-Optimizer/issues/30)

```text
We’ve re-encountered the issue and identified that mixed precision ONNX models 
(e.g., FP32 + FP16 ONNX exported with torch.autocast enabled) fail when multiple execution providers are passed to 
the ONNX Runtime inference session. ModelOpt uses autocast by default during INT8/FP8 ONNX export from PyTorch models.
To avoid the CopyTensorAsync issue, users should specify a single execution provider when calling the quantization API—for example: 
calibration_eps = ["cpu"] or calibration_eps = ["cuda:0"].
```

所以改一下指令即可

```text
python -m modelopt.onnx.quantization --onnx_path=vit_base_patch16_224.onnx --quantize_mode=fp8 --calibration_data=calib.npy --calibration_method=entropy --output_path=vit_base_patch16_224.quant.onnx --calibration_eps cuda:0
```

这个过程会有些长，但看到下面的输出，基本就完成了
