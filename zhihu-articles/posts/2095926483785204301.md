了解了提示词工程的基本方法之后，接下来的问题是：怎样把这些方法用到 Spring AI 应用里？关键是通过 `ChatClient` 组织模型收到的消息，把角色、任务、示例和输出要求写清楚，而不是只向模型丢一句模糊的问题。

下面以一个简单的 Controller 为例。假设项目已经配置了可用的 `ChatModel` ，先创建 `ChatClient` ；后文的方法都可以放在这个 Controller 中。

```java
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.beans.factory.InitializingBean;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/prompt/guide")
public class PromptGuideController implements InitializingBean {

    @Autowired
    private ChatModel dashScopeChatModel;

    private ChatClient chatClient;

    @Override
    public void afterPropertiesSet() {
        this.chatClient = ChatClient.builder(dashScopeChatModel).build();
    }
}
```

以下各节展示的是独立的方法片段，可以分别添加到上述 Controller 类中；所需注解已在上方导入。

### 一、区分系统提示词与用户提示词

Spring AI 的对话接口支持不同角色的消息。通常用系统消息（ `system` ）说明助手的身份、回答方式等，用用户消息（ `user` ）传递本次请求的内容。比如，让助手以科普讲解员的口吻解释一个概念：

```java
@GetMapping("/role")
public String role(@RequestParam("message") String message) {
    return chatClient.prompt()
            .system("你是一位面向初学者的科普讲解员。请用通俗的中文和一个生活中的类比回答问题。")
            .user(message)
            .call()
            .content();
}
```

请求 `/prompt/guide/role?message=什么是向量数据库` 时， `message` 是用户当前的问题， `system(...)` 则负责设定回答的角色和风格。这也是提示词工程中常见的 **角色设定** ：先告诉模型“以什么身份回答”，再提出具体任务。

如果希望多个请求共用同一段设定，可以在创建 `ChatClient` 时使用 `ChatClient.builder(dashScopeChatModel).defaultSystem("...").build()` ；同样，也可以用 `defaultUser(...)` 配置默认用户消息。默认设置适合通用约束，单次请求的具体问题仍应通过 `user(...)` 传入。

### 二、给出少量示例（Few-shot）

当任务的规则或表达风格不容易用一句话讲清楚时，可以在提示词里放入几组“输入—输出”示例，让模型参照示例处理新的输入。例如，我们要将口语化的会议安排改写成简洁的待办事项：

```java
@GetMapping("/shot")
public String shot(@RequestParam("message") String message) {
    return chatClient.prompt()
            .system("""
                    将用户的话改写成一条简短的待办事项，只返回改写结果。
                    示例 1：
                    输入：咱们明天记得把产品首页的按钮文案再检查一下。
                    输出：明天检查产品首页的按钮文案。
                    示例 2：
                    输入：有空的时候把上周的会议纪要发给设计组同学。
                    输出：向设计组发送上周的会议纪要。
                    """)
            .user(message)
            .call()
            .content();
}
```

示例不仅展示了“做什么”，还展示了“答案长什么样”。实际使用时，应选与目标任务相符的示例；模型会参考示例，但输出仍可能因模型和输入不同而有所变化。

### 三、在提示词中约定输出格式

如果下游程序需要消费结果，除了说明内容，还应明确字段名和格式。下面要求模型生成三条虚构活动信息，并以 JSON 数组返回：

```java
@GetMapping("/format")
public String format(@RequestParam("message") String message) {
    return chatClient.prompt()
            .system("""
                    你是活动策划助手。根据用户提供的主题，设计三场虚构的社区活动。
                    只返回合法的 JSON 数组，不要附加说明或 Markdown 代码围栏。
                    数组中每个对象只能包含以下字段：
                    event_name（活动名称）、audience（适合人群）、location（举办地点）。
                    """)
            .user(message)
            .call()
            .content();
}
```

例如传入“城市阅读”，期望得到的结果是包含 `event_name` 、 `audience` 和 `location` 的三个对象，而不是一段散文式的活动介绍。 **提示词约束的是模型的生成行为，不等于程序层面的格式保证** ；需要稳定解析、类型校验时，还应使用 Spring AI 的结构化输出能力。这里先关注如何用提示词表达格式要求。

### 四、把复杂任务拆成明确步骤

一次请求包含多个动作时，可以写出执行顺序和最终交付物，减少遗漏。比如先从一段中文活动说明中提取信息，再翻译摘要，最后返回指定字段：

```java
@GetMapping("/steps")
public String steps(@RequestParam("message") String message) {
    return chatClient.prompt()
            .system("""
                    请按顺序处理用户提供的活动说明：
                    1. 用一句中文概括活动内容。
                    2. 将这句摘要翻译成英文。
                    3. 找出原文中明确出现的人名并统计数量，不要把地名算作人名。
                    4. 最终只返回一个 JSON 对象，包含 chinese_summary、english_summary、num_names 三个字段。
                    不要在最终结果之外展示中间分析。
                    """)
            .user(message)
            .call()
            .content();
}
```

这里的重点是先分解任务，再约定最终只输出什么。步骤是帮助模型完成任务的指令，不必要求它把所有中间过程都打印出来。

### 五、思维链

对于需要计算或多步判断的问题，可以提示模型先核对关键条件、再形成结论。这类写法通常被称为思维链（Chain of Thought）提示。下面把题目作为用户消息，把解题要求放在系统消息中：

```java
@GetMapping("/reason")
public String reason(@RequestParam("message") String message) {
    return chatClient.prompt()
            .system("""
                    你是数学辅导老师。先确认题目中的已知数量和单位，再计算最终结果。
                    回答时只给出简要的计算式和最终答案，不要省略单位。
                    """)
            .user(message)
            .call()
            .content();
}
```

例如用户问：“仓库里有 6 箱纸，每箱 12 包，取走 19 包后还剩多少包？”期望的简要计算是 `6 × 12 - 19 = 53` ，答案为 **53 包** 。引导模型按步骤处理有助于减少漏算，但提示词不能保证每次计算都正确；对准确性要求高的场景，还应在程序中校验结果。

### 小结

在 Spring AI 中，提示词工程并不是一个独立于代码之外的概念：通过 `ChatClient` 的 `system(...)` 、 `user(...)` 等接口，就可以把角色设定、少样本示例、输出格式、执行步骤和推理要求落实到每次请求中。写提示词时，先明确任务和预期结果，再根据任务复杂度补充示例与约束，最后用实际输入检验效果。
