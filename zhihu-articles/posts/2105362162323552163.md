## 上篇回顾

第56篇《性能基准测试与优化指南》给出了 OpenClaw 的性能基线：单机模式下短对话 QPS 约 14.1（100 VU），并发连接舒适区 ≤500，流式输出舒适区 ≤30 VU。经过 6 项优化后 QPS 提升到 42.3——但这是 3 实例负载均衡的结果，单机性能已经触顶。

单机的天花板很明确：1 台 Gateway + 1 台 Ollama = 固定上限。当业务增长到需要多副本、多区域部署时，手动管理多台机器的配置、部署、扩缩容、故障恢复，运维成本会指数级上升。Kubernetes 就是解决这个问题的标准方案。

本文将第56篇的优化配置融入 K8s 部署，实现弹性伸缩和故障自愈。如果你还没读第56篇，建议先了解性能基线数据，因为 K8s 的资源配置（CPU/内存/GPU 请求）直接基于这些数据。

### K8s vs 单机 ROI 对比

**判断标准**：如果你只有 1 个 OpenClaw 实例、<50 并发用户、不需要 7×24 高可用——单机部署性价比更高。当流量增长到需要多实例、故障恢复、自动扩缩容时，K8s 的投入在 3-6 个月内回本。

### 环境自查脚本

部署前运行以下脚本，检查环境是否满足最低要求：

#!/bin/bash

# check-k8s-env.sh — OpenClaw K8s 部署环境自查脚本

echo "========================================="

echo " OpenClaw K8s 部署环境自查"

echo "========================================="

# K8s 版本

K8S_VER=$(kubectl version --short 2>/dev/null | grep Server | awk '{print $3}')

if [ -z "$K8S_VER" ]; then

echo "❌ kubectl 未安装或集群不可达"

else

echo "✅ K8s 版本: $K8S_VER"

fi

# Helm 版本

HELM_VER=$(helm version --short 2>/dev/null)

if [ -z "$HELM_VER" ]; then

echo "❌ Helm 未安装"

else

echo "✅ Helm 版本: $HELM_VER"

fi

# GPU 节点

GPU_NODES=$(kubectl get nodes -o json 2>/dev/null | grep -c '[http://nvidia.com/gpu](http://nvidia.com/gpu)' || echo 0)

if [ "$GPU_NODES" -eq 0 ]; then

echo "⚠️ 未检测到 GPU 节点（Ollama 需要 GPU）"

else

echo "✅ GPU 节点数: $GPU_NODES"

fi

# 节点数

TOTAL_NODES=$(kubectl get nodes --no-headers 2>/dev/null | wc -l)

echo "✅ 集群节点数: $TOTAL_NODES"

# 存储

STORAGE_CLASSES=$(kubectl get sc --no-headers 2>/dev/null | wc -l)

echo "✅ StorageClass 数: $STORAGE_CLASSES"

echo ""

echo "========================================="

echo " 最低要求检查结果"

echo "========================================="

echo "K8s ≥ 1.26: $([ "$K8S_VER" ] && echo '✅' || echo '❌')"

echo "Helm ≥ 3.12: $([ "$HELM_VER" ] && echo '✅' || echo '❌')"

echo "GPU 节点 ≥ 1: $([ "$GPU_NODES" -gt 0 ] && echo '✅' || echo '⚠️')"

echo "集群节点 ≥ 3: $([ "$TOTAL_NODES" -ge 3 ] && echo '✅' || echo '⚠️')"
