## EDG C++ compiler front end开源

说到**EDG C++ compiler front end**，可能很多人都不知道，但您很可能已经在不经意间使用了他们的产品。

**Edison Design Group（EDG，爱迪生设计集团）** 是一家美国公司，专门为 **C++**（以及过去的 **Java** 和 **Fortran**）开发**编译器前端**（包括预处理和语法解析）。C++ Templates这本书的主要作者**David Vandevoorde**就是该公司员工。

![](https://pic4.zhimg.com/v2-3a50d64f6fa01e4fbaac2d58be01d391_r.jpg)

他们开发的前端技术被广泛应用于商业编译器和代码分析工具中。

其用户包括：

- **Intel C++ 编译器**
- **Microsoft Visual C++**（具体用于 **IntelliSense 智能代码分析功能**）
- **NVIDIA CUDA Compiler（nvcc）**
- **SGI MIPSpro**
- **The Portland Group（PGI 编译器）**
- **Comeau C++**

如果您用过以上产品的话，实际上就已经在和EDG的产品打交道了。

## 核心优势

**在 GCC、Clang 等开源 C++ 编译器，以及 MSVC 等商业 C++ 编译器长期占据市场的情况下，EDG 作为一个商业化 C++ 前端供应商，为什么仍然能够生存并保持影响力？**

**答案就是它对C++标准的变态一样的遵从性。**

**举个例子：**

C++98 标准中引入了一个用于模板的关键字叫 `export`。这个特性的实现难度极其反人类，导致当时几乎所有的编译器厂商（包括微软、GNU）都公开抵制，拒绝实现它。

- **EDG 是当时全球唯一一个咬碎牙把 `export` 完整写出来的团队。**
- Comeau C++ 拿到了 EDG 的代码后，将其开启并发布，达成了“**100% 支持 C++98 标准**”的超神成就。
- 而其他使用 EDG 的厂商（比如 Intel），因为自己后端的限制或者觉得这东西太难维护，**在发布时把 EDG 里的 `export` 功能给强行屏蔽了**。
- EDG 团队曾向 C++ 委员会大吐苦水，表示他们仅仅为了实现这一个 `export` 关键字，所花的心血和代码量，比他们团队**从头写一个完整的 Java 编译器还要多**。
- 可惜的是，因为 Intel 强行禁用，加上开源界两大巨头 GCC 和 MSVC（微软）的联合抵制（他们坚决拒绝实现这个关键字），最终 C++ 委员会在 Herb Sutter 等人的推动下，妥协认错。在 **C++11 标准中，`export` 关键字作为模板分离的功能被正式废除。**

它是业界公认对 C++ ISO 标准支持最完美的解析器之一。更夸张的是，为了兼容市面上的旧代码，EDG 甚至内置了“**Bug 模拟器**”——它可以刻意模拟 GCC、Clang 和 MSVC 的各种解析怪癖和历史 Bug，以此来保证代码的顺利编译。

## 为什么选择开源？

### 一、老派创始人要退休

简单的说就是EDG公司即将关闭。EDG 官方在 2025 年正式宣布，公司将于 2026 年停止运营。

与其说 EDG 是一家商业公司，不如说它是一个由几位顶尖 C++ 编译器专家组成的“小作坊”。**到目前这个公司只有六个人**。EDG 早在 1988 年由 **Steve Adamczyk**在美国新泽西州创立。后来加入的 John Spicer 和 Daveed Vandevoorde 也都是 C++ 标准委员会里的绝对元老。

Steve Adamczyk 曾表示，他创立这家公司纯粹是为了“能享受编写编译器的乐趣”，而不是为了把它做大做强从而剥夺这种乐趣。因此，在将近 40 年的时间里，这家公司一直维持着极小的人数规模（几个人）。 如今，这几位大佬都已上了年纪。在 C++ 圈子里，过去十年一直有传言说他们“随时可能退休”。到了 2025 年，他们正式宣布了 2026 年关闭公司的计划，这**其实就是几位老派黑客觉得自己干不动了，准备享受晚年生活**。

他们都已经到了该退休的年纪，公司的关闭是一次计划内的“自然落幕”。既然公司要关门了，如何处置代码资产就成了唯一的问题，而开源是极客们能想到的最体面的告别方式。**这次开源保留了自 1990 年以来的完整 Git / 提交历史，把长达 36 年的完整开发历程全部开放了。而且采用了LLVM的开源协议。**

### **二、市场格局的变化**

**除了团队要退休之外，市场格局的变化也是一个重要的原因。**

在过去的二三十年里，Intel、微软、NVIDIA 等巨头的编译器前端都曾依赖 EDG。但随着 Clang/LLVM 这种极为强大的开源架构在工业界占据绝对统治地位，独立售卖商业闭源 C++ 前端的市场空间已经越来越小。 在 HN 的跟帖中，Daveed Vandevoorde 亲自透露了一个数据：“**据我估计，到最后我们大约只有 50 个左右的客户**。”

连 EDG 最大的客户之一 Intel，在最近几年也逐渐放弃了使用 EDG 前端的经典编译器（ICC），全面转向了基于 LLVM 架构的新一代编译器（ICX/DPC++）。

**还有一个原因就是客户并购导致的客源减少**。科技圈的商业并购也是一个因素。**Daveed Vandevoorde**在论坛透露，EDG 很多时候“失去”客户，并不是因为客户跑去用了别的产品，而是因为两家买了 EDG 授权的公司突然合并成了一家（比如半导体厂商的并购潮），导致原本两份的授权费变成了一份。

于是，他们选择了最极客的做法：在 2026 年 9 月 30 日，将 EDG C++ 前端代码托管给了非营利组织 The C++ Alliance，并在 GitHub 上彻底开源。

三十六年后，EDG 终于走到了故事的终点。几位曾经亲手塑造 C++ 编译器历史的老派程序员选择离开，而他们留下的代码，却将继续运行在后来者的编译器里。**EDG 的开源，是一次体面的告别，也是一个 C++ 编译器时代的谢幕。**
