混合专家模型（Mixture of Experts，MoE）通过稀疏激活机制，在每次前向计算时只选择部分专家参与计算，从而在控制单 Token 计算量的同时扩大模型的总参数规模。DeepSeek、Mixtral、Qwen 等模型采用或探索了不同形式的 MoE 架构，使其成为大规模语言模型的重要技术路线。

然而，MoE 的稀疏计算并不意味着部署成本随之消失。一方面，模型需要存储大量专家权重；另一方面，随着上下文长度和并发请求数增加，Attention 层的 KV Cache 也会占用大量 GPU 显存。此外，专家路由、跨卡通信和动态负载均衡进一步增加了推理系统的复杂度。

模型量化是缓解上述问题的重要手段。与传统 Dense 模型相比，MoE 量化不仅需要降低数值精度带来的误差，还需要处理专家激活分布不均、校准样本偏斜、路由稳定性以及低比特算子的硬件效率等问题。

从优化对象看，MoE 量化主要包括三个方面：

- 权重量化：降低专家网络及其他线性层的参数存储成本。
- 权重与激活联合量化：同时压缩权重和计算激活，争取降低计算、访存和数据搬运成本。
- KV Cache 量化：压缩 Attention 历史 Key 和 Value，提升长上下文支持能力和服务并发度。

在 [大模型的稀疏化革命：MoE的推理技术原理](https://zhuanlan.zhihu.com/p/2093827158036763827) 中粗略讲述了MoE模型量化。而本文围绕以上这三个方向梳理代表性研究工作，分析关键技术挑战，并结合 vLLM、SGLang 等推理框架讨论工程实践。

## 背景

MoE 模型通常由共享网络、路由器（Router）和多个专家网络组成。对典型的 MoE FFN 层，路由器根据输入 Token 的特征选择 Top-K 专家，再将专家输出加权聚合。

与 Dense 模型相比，MoE 的一个重要特点是：**总参数量与每个 Token 实际参与计算的参数量存在明显差异**。

稀疏激活可以降低单次前向计算涉及的专家数量，但通常不能直接消除未激活专家的权重存储需求。在多卡部署场景下，专家还可能分布在不同 GPU 上，带来额外的显存容量和通信成本。

因此，MoE 模型量化至关重要，而 MoE 模型量化的收益则取决于具体的权重格式、Scale 和 Zero-point 元数据、内核实现、专家并行策略，以及是否需要在计算前执行反量化。

## MoE 量化面临的特殊挑战

第一，专家之间的激活频率不均衡。

不同专家接收到的 Token 数量可能相差很大。热门专家可以获得较多校准样本，而低频专家的校准数据可能不足。统一的量化参数未必适合所有专家。

第二，专家内部的激活分布不同。

不同专家可能学习不同的特征，具有不同的激活范围和离群值分布。因此，Dense 模型中表现良好的量化方法，迁移到 MoE 后不一定能够维持相同精度。

第三，量化误差可能影响路由行为。

当路由器或相关计算路径发生精度变化时，专家选择及其权重可能改变，进而影响整个模型的输出。即使专家本身的量化误差不大，路由变化也可能放大端到端误差。

第四，低比特计算不一定带来实际加速。

MoE 推理涉及动态 Token 分发、Grouped GEMM、专家聚合及跨 GPU 通信。如果低比特算子没有得到硬件和软件栈的充分支持，量化与反量化、数据重排等额外开销可能抵消收益。

因此，MoE 量化需要同时考虑算法精度、显存占用和端到端推理效率。

## MoE 权重量化：从统一位宽走向专家感知的混合精度

权重量化通常先对模型权重进行离线量化，推理时根据具体计算内核执行反量化或低精度矩阵乘法。W4A16 是一种典型配置，即权重采用 4 bit，而激活仍使用 FP16 或 BF16。

该方案通常比同时量化权重和激活更容易落地，因为它不必全面改变激活数据的数值表示，但其计算加速取决于是否具备高效的低比特权重访问和矩阵乘法内核。

### MoE 权重量化的基础方法：RTN、GPTQ 与 AWQ

通用大模型后训练权重量化方法是 MoE 量化的重要基础，但在 MoE 场景下，通常需要结合专家路由和专家权重分布进行适配。

| 方法 | 核心原理 | 优势 | 在 MoE 中的局限 |
| --- | --- | --- | --- |
| RTN | 将权重直接舍入到目标精度 | 简单、快速、易于部署 | 难以充分补偿量化误差 |
| GPTQ | 利用近似二阶信息逐步补偿权重量化误差 | 适合离线低比特权重量化 | 校准数据覆盖不均可能影响不同专家的量化效果 |
| AWQ | 利用激活统计识别重要通道，通过缩放降低量化误差 | 能够利用输入分布保护重要权重通道 | 专家分布差异会增加统计与校准难度 |

这类方法主要解决如何将浮点权重映射到低比特表示的问题，但直接套用未必最优，原因是：

- 专家之间校准样本不均衡；
- 专家内部权重分布差异；
- 不同线性层、不同通道的量化敏感性不同。

例如，对所有专家统一执行 INT4 量化，虽然流程简单、存储格式统一，但可能对部分敏感专家造成过大的精度损失。

由此，研究重点逐渐从“如何量化权重”转向“如何为不同专家分配量化精度”。

### MoE 权重量化的代表性研究

### QMoE：面向万亿参数模型的极限压缩

QMoE（2023）研究如何将超大规模 MoE 模型压缩至极低的平均比特数。其技术路线包括定制码本和三值量化等方法，探索通过高度紧凑的权重表示来降低模型存储需求。

与常规 INT4 量化相比，这类方案更强调压缩率的极限。其研究意义在于说明，MoE 权重并不一定要全部以常规定长整数格式存储，也可以通过**专门设计的编码和解码机制**进一步降低平均存储成本。

但极低比特压缩通常会引入**更复杂的编码、解码和计算流程**。定制内核的实现、解码开销、硬件适配能力以及模型精度损失，都会影响其工程实用性。

与常规低比特量化的区别：QMoE 更侧重于极限压缩和紧凑表示，而后续混合精度研究更侧重于在给定存储预算下，为不同专家分配适当的精度。

### MoQE：研究专家子集量化的精度—显存权衡

MoQE（2024）关注一个重要问题：是否需要对所有专家采用相同的量化策略？

MoE 模型具有动态路由特征，不同专家的调用频率和功能并不相同。因此，可以尝试对不同专家子集采用不同的精度配置，研究专家量化范围与模型精度、显存开销之间的关系。

这一研究方向的重要价值在于揭示：MoE 量化不能只从整个模型的平均权重误差出发，还应关注量化误差在不同专家上的分布，以及这些误差对最终模型输出的影响。

它为后续**专家级混合精度量化**提供了研究动机：不是所有专家都必须采用相同位宽，专家选择机制与权重量化策略之间存在值得利用的互补关系。

### MoEQuant：解决专家校准数据不均衡

- 论文：[MoEQuant: Enhancing Quantization for Mixture-of-Experts Large Language Models via Expert-Balanced Sampling and Affinity Guidance](https://arxiv.org/pdf/2505.03804)
- 代码：[https://github.com/chenzx921020/MoEQuant](https://github.com/chenzx921020/MoEQuant)

MoEQuant 将 MoE 权重量化的一个关键问题归纳为两种不平衡：

- 专家间不平衡（Inter-expert Imbalance）：不同专家获得的校准样本数量不同，部分专家缺少充分的数据支持。
- 专家内不平衡（Intra-expert Imbalance）：同一专家接收的不同样本与该专家的关联程度不同，样本对量化误差的贡献并不一致。

针对这两个问题，MoEQuant 提出两项关键技术。

**Expert-Balanced Self-Sampling（EBSS）**

利用 Token 的累计路由概率和专家负载等信息，构建专家分布更加均衡的校准数据集，改善低频专家校准样本不足的问题。

**Affinity-Guided Quantization（AGQ）**

在量化过程中考虑样本与专家之间的关联程度，使量化过程能够更准确地衡量不同样本对相应专家的影响。

论文报告中，该方法在 MMLU、HumanEval、GSM8K 数据集上相较对照方案取得准确率提升。该结果对应特定模型、指标和评测设置，并不代表所有 MoE 模型都能获得同等幅度的收益。

![](https://pic3.zhimg.com/v2-eb1d14dfa1e7a668d85e4484a1a250d6_r.jpg)

技术启示：在 MoE 权重量化中，校准数据的覆盖程度和样本选择方式，会直接影响量化误差估计的质量。改善校准过程，可以成为提升低比特量化精度的重要手段。

### Automated Fine-Grained MoE Quantization：从专家级走向通道级

- 论文：[Automated Fine-Grained Mixture-of-Experts Quantization](https://aclanthology.org/2025.findings-acl.1386.pdf)

如果说 MoEQuant 重点解决专家之间的校准数据不均衡问题，那么这项工作进一步研究了**专家内部不同权重通道的量化敏感性**。

研究发现，不同专家权重矩阵的通道级离群值分布存在差异。论文结合 Fisher 信息矩阵、条件数等角度研究量化敏感性，指出不同投影层对量化误差的承受能力并不相同，其中下投影层（down-projection）通常需要比上投影层更高的精度。

![](https://pic3.zhimg.com/v2-2566567aafac76e03487ff2fd50245de_r.jpg)

其核心方法是自动化通道级位宽分配：**根据不同通道的敏感程度确定量化精度**，避免所有通道采用统一位宽。

论文报告其方法在自然语言理解基准上较已有先进方法提升 3.96%，同时保持较高压缩率。

![](https://pic2.zhimg.com/v2-66f07a507337b7d95c210bbb4ba24673_r.jpg)

技术启示： MoE 权重量化的粒度可以从整个模型下沉到专家、矩阵乃至通道。粒度越细，精度分配的灵活性越强，但量化元数据、实现复杂度和内核调度成本也可能随之增加。

### MxMoE：精度与硬件性能协同设计

- 论文：[MxMoE: Mixed-precision Quantization for MoE with Accuracy and Performance Co-Design](https://arxiv.org/pdf/2505.05799)
- 代码：[https://github.com/cat538/MxMoE](https://github.com/cat538/MxMoE)

MxMoE 的核心思想是：量化方案不能只追求更低的平均位宽，还要考虑不同专家的激活频率、不同线性模块的量化敏感性，以及目标硬件的计算能力。

它主要包含两个方面：

- 混合精度配置优化： 综合参数敏感性、专家激活动态和硬件资源，寻找精度与运行成本之间的合适平衡。
- 混合精度内核生成： 自动生成支持不同精度矩阵乘法的 GroupGEMM 内核，让不同精度的专家计算能够高效执行。

![](https://picx.zhimg.com/v2-1180e8ac7ee557f82e55003ccc0fa8dd_r.jpg)

![](https://pic1.zhimg.com/v2-e8d6fa73606514d1b8641e591e145606_r.jpg)

论文报告中，在 2.25-bit 配置下，相较 GPTQ 的 WikiText-2 困惑度降低 2.4；在特定实验中，推理速度最高达到全精度基线的 3.4 倍。其等精度条件下的性能比较也显示，混合精度方案相较统一量化最高可获得 29.4% 的加速。

![](https://pica.zhimg.com/v2-00fb4dddb2444821e5e1e03dfc25af3a_r.jpg)

MxMoE 的价值在于将专家量化从单纯的数值优化推进到系统级协同优化。例如，即使两个方案拥有相同的平均位宽，如果其中一个方案**需要大量低效的混合精度调度**，另一个方案可以**充分利用硬件支持的低比特矩阵乘法**，那么后者可能具有更好的实际性能。

### MC-MoE：利用专家重要性与冗余实现极限压缩

- 论文：[MC-MoE: Mixture Compressor for Mixture-of-Experts LLMs Gains More](https://arxiv.org/abs/2410.06270)
- 代码：[https://github.com/Aaronhuang-778/Mixture-Compressor-MoE](https://github.com/Aaronhuang-778/Mixture-Compressor-MoE)

MC-MoE 从专家的重要性和冗余性出发，探索极低比特权重量化与动态专家选择的协同压缩。

其静态权重量化部分提出 Pre-Loading Mixed-Precision Quantization，通过线性规划等方式综合不同专家的重要性，为专家分配不同位宽。其公开实现支持约 1.5–2.5 bit 的 weight-only 量化配置。

该研究还提出 Online Dynamic Pruning，在推理时动态筛选重要 Token 和专家，进一步减少激活参数。

![](https://pic1.zhimg.com/v2-fc95c6fd2ccccab41a3582ddd144fb0c_r.jpg)

![](https://picx.zhimg.com/v2-acd0faeb1719737fadec2fe27a98bca3_r.jpg)

因此，从权重量化角度看，MC-MoE 的主要贡献是：通过**专家重要性分析和混合位宽分配**，在给定存储预算下优先保护重要专家，将不重要专家压缩到更低精度。

### GEMQ：全局专家级混合精度量化

- 论文：[GEMQ: Global Expert-Level Mixed-Precision Quantization for MoE LLMs](https://proceedings.mlr.press/v306/deng26t.html?utm_source=chatgpt.com)
- 代码：[https://github.com/jndeng/GEMQ](https://github.com/jndeng/GEMQ)

GEMQ 将专家级混合精度量化推进到全局优化层面。其研究指出，仅在单层或单个专家内部估计重要性，可能忽略不同专家之间的相互影响，也可能忽略量化后路由器行为的变化。在 1.5-bit 量化下，超过 40% 的 token 被路由到不同的专家。

![](https://pic3.zhimg.com/v2-976ec2a593b9a070343df6c3cfc18d16_r.jpg)

GEMQ 的主要设计包括：

- 全局专家重要性建模：通过全局线性规划，在模型范围内统一分配不同专家的位宽，而不是孤立地逐层优化。
- 路由器微调：通过高效的路由器微调，适应量化后专家行为的变化。
- 渐进式量化：迭代优化重要性估计与位宽分配，使精度与存储预算之间的权衡逐步改善。

![](https://pic3.zhimg.com/v2-d4b8c48e8e0a3dc1840f14653661b626_r.jpg)

其目标是在给定内存预算下逼近精度—存储的 Pareto 前沿，并兼顾推理性能。

论文报告中，GEMQ 在相同平均位宽下改善了模型质量。同时，GEMQ 缓解了极低比特（1.5 bpe）下的精度退化。

![](https://pic2.zhimg.com/v2-b33d54e48a50cbe5b48b830761a4cd41_r.jpg)

GEMQ 与 MxMoE 的区别在于：前者更突出**模型全局的专家重要性分配和路由适配**；后者更突出**量化配置与硬件执行性能的协同设计**。

### KBVQ-MoE：面向超低比特的向量量化

- 论文：[KBVQ-MoE: KLT-guided SVD with Bias-Corrected Vector Quantization for MoE Large Language Models](https://arxiv.org/pdf/2602.11184)

与常规逐元素整数权重量化不同，KBVQ-MoE 采用向量量化思路，将权重向量映射到有限的码本表示，并通过专家间冗余分析提高有限码本的利用效率。

其核心包括：

- KLT 引导的 SVD：提取不同专家之间可共享的主要权重成分，减少重复表示。
- 偏差校正：对向量量化引入的专家输出偏差进行通道级仿射补偿，缓解专家聚合后累积的误差。

论文报告，在 Qwen1.5-MoE-A2.7B 的 3-bit 量化实验中，平均准确率达到 67.99，与 FP16 基线的 68.07 接近。

![](https://pic2.zhimg.com/v2-2c0d12c07019f74f56dfa481041b49df_r.jpg)

这项工作体现了 MoE 极低比特量化的另一条路线：除了决定每个专家使用多少 bit，还可以**重新设计权重表示方式**，利用专家间冗余和向量码本进一步压缩。

### MoE 权重量化的发展趋势

**从统一位宽走向专家感知的混合精度**

早期方案通常采用统一 INT4 等配置，便于实现和部署。随着研究深入，越来越多的方法尝试根据专家的重要性、量化敏感性和激活频率分配不同位宽。

其基本原则是：**重要专家尽量保留精度，敏感性较低的专家承担更多压缩任务**。

不过，低频专家不一定不重要，专家激活频率也不能直接替代量化敏感性评估。合理的位宽分配需要综合多个指标。

**从专家级走向矩阵级与通道级**

不同专家内部的 up-projection、gate-projection 和 down-projection 等矩阵，对量化误差的敏感性可能存在明显差异。

进一步细化到通道级，可以根据**离群值和敏感性分配不同精度**，从而在相同存储预算下更好地保护关键参数。

但粒度越细，量化元数据、权重打包、访存模式和内核调度的复杂度越高。因此，细粒度方案必须同时评估压缩收益和执行开销。

**从局部优化走向全局优化**

专家的重要性不仅取决于单个专家自身的重建误差，还与其在整个模型中的作用、其他专家的输出以及路由器行为有关。

GEMQ 等研究进一步探索模型全局的位宽分配，试图避免局部最优导致的整体性能损失。

未来的混合精度量化可能会将**专家重要性、参数敏感性、全局存储预算和硬件成本**统一纳入优化问题。

**从定长整数走向更灵活的权重表示**

QMoE 和 KBVQ-MoE 展示了不同于常规 INT4 的压缩思路：通过专门设计的码本、向量量化或紧凑编码，进一步降低权重平均存储开销。这类方法有望突破常规定长整数格式的压缩限制，但需要**关注解码吞吐、随机访问能力、并行计算效率以及部署框架的支持程度**。

**从单纯追求压缩率走向软硬件协同**

低比特权重不一定意味着更快的推理速度。

实际性能取决于硬件是否支持相应的低比特矩阵乘法、混合精度 GroupGEMM 是否高效、专家是否分布在不同设备上，以及权重加载与通信是否成为瓶颈。

因此，未来的 MoE 权重量化方案需要同时优化精度、存储和实际推理性能。

## MoE 权重与激活联合量化：从 W8A8 走向 W4A4

在降低专家权重存储成本的同时，进一步量化 Expert FFN 的输入激活，使矩阵乘法能够利用更低精度的硬件计算单元，也是一个重要的研究方向。

对于 MoE 模型，虽然每个 Token 通常只激活少数专家，但被选中的专家仍需要执行大量矩阵乘法。随着模型规模扩大，**专家计算、激活搬运以及专家并行通信**都会带来显著的系统开销，权重与激活量化希望同时降低这些开销。

常见方案如下有：

| 量化方案 | 权重精度 | 激活精度 | 核心目标 |
| --- | --- | --- | --- |
| INT8 W8A8 | INT8 | INT8 | 利用整数低精度计算 |
| FP8 W8A8 | FP8 | FP8 | 平衡动态范围、精度与吞吐 |
| MXFP8 W8A8 | FP8 | FP8 | 通过块级缩放处理复杂的数值分布 |
| INT4 W4A4 | INT4 | INT4 | 进一步降低数据表示和搬运成本 |
| NVFP4 W4A4 | NVFP4 | NVFP4 | NVIDIA Blackwell 等平台上的超低精度计算 |
| MXFP4 W4A4 | MXFP4 | MXFP4 | 支持 OCP MX 格式的低精度计算平台 |
| W4A8 | INT4 | INT8 | 降低权重存储，同时压缩激活 |

还有W4AFP8、MXFP4xFP8等。

注意：这里的 WnAm 是概念性表示，并不意味着所有格式都可以直接组合。例如： FP4 与 INT4 的数值表示、缩放方式和算子支持并不相同，具体方案还需要明确量化粒度、Scale 格式和计算路径。

### 为什么 MoE 权重与激活量化更有挑战？

MoE 的难点不只是激活数值范围较大，而是动态路由使不同专家的计算行为存在明显差异。

第一，**专家输入的 Token 数量动态变化**。

在 MoE 层中，Router 根据输入将 Token 分配给不同专家。假设一个批次包含 $T$ 个 Token，第 $i$ 个专家实际接收的 Token 数量为 $T_i$，那么：

$\sum_i T_i \approx kT $

这里 $k$ 是每个 Token 选择的专家数量；实际统计还需要考虑专家分组、路由策略和是否存在丢弃 Token 等因素。

不同专家的 $T_i$ 可能相差很大，甚至为零。这使得**激活量化和矩阵乘法必须适应动态形状**，尤其是在小批次解码阶段，量化开销可能占据不可忽略的比例。

第二，**不同专家的激活分布并不相同**。

不同专家学习到不同的特征处理模式，其输入激活的离群值、动态范围和通道分布可能存在差异。如果统一采用过于粗粒度的缩放参数，部分专家可能出现较大的量化误差。

因此，逐张量、逐 Token、逐通道或分组缩放之间的选择，可能显著影响模型精度和执行效率。

第三，**激活量化可能影响路由决策**。

MoE 的计算结果不仅取决于专家内部的矩阵乘法，还取决于 Router 的选择结果。量化误差若传播到 Router 输入或路由分数计算中，可能改变 Top-k 专家选择，从而引入额外的误差传播。

这也是为什么 MoE 的低比特量化不能简单照搬 Dense 模型的量化流程。

第四，**低精度算力不一定转化为端到端加速**。

MoE 推理包含 **Token 分发、专家矩阵乘法、结果聚合**等多个阶段。即使 FP8 或 FP4 GEMM 更快，如果动态量化、布局转换、专家调度或通信产生额外开销，最终的端到端延迟仍可能没有明显改善。

因此，MoE 权重与激活量化本质上是一个涉及数值算法、专家路由、硬件内核和推理系统的协同优化问题。

### 主要技术路线：INT8、FP8、MXFP8、NVFP4、MXFP4

### FP8 W8A8：兼顾精度与性能的主流路线

FP8 同时降低权重和激活的表示精度，通常能够在较低量化误差与硬件计算效率之间取得较好的平衡。工程实现需要关注缩放粒度、离群值处理，以及专家 GEMM 是否真正执行 FP8 乘法。

FP8 最常见的两种编码格式是 E4M3 和 E5M2。两者都占用 8 bit，但符号位、指数位与尾数位的分配不同。

![](https://pic3.zhimg.com/v2-3e5b70ac938e37b6001e65472c2d2b4e_r.jpg)

![](https://picx.zhimg.com/v2-19458bd2dc8b03c375314eff95167355_r.jpg)

典型 FP8 W8A8 的计算流程可以概括为：

1. 离线量化或加载模型时，将专家权重转换为 FP8。
2. 每次前向计算时，根据激活分布动态确定缩放参数，并将输入激活转换为 FP8。
3. 使用 FP8 GEMM 计算矩阵乘法。
4. 将累加结果转换到所需的输出精度，例如 BF16 或 FP16。

相比仅压缩权重的方案，FP8 W8A8 的关键价值在于激活也进入低精度计算路径。

### MXFP8：利用细粒度缩放改善数值表示

![](https://pic2.zhimg.com/v2-a54c5c8c9f9103e724cd44d599655bdf_r.jpg)

假设一个激活矩阵中，大部分元素的绝对值处于较小范围，但少数元素非常大。如果整张量使用一个统一缩放因子，大数值可能占据大部分有效表示范围，导致小数值的量化分辨率不足。若对每个小块分别缩放，就可以让不同数据块更好地利用 FP8 的表示范围。

OCP（Open Compute Project）的 MX 规范定义了 MXFP8：**每 32 个元素组成一个数据块，使用 E8M0 格式的共享缩放因子**；其中：MXFP8 的元素格式采用 E5M2。E8M0 是一种仅包含指数信息的 8 bit 缩放格式。它主要用于表达二次幂形式的缩放因子，因此缩放值的选择具有离散性。

![](https://pic2.zhimg.com/v2-d08beaa0f59312f994089f243f7bb399_r.jpg)

MXFP8 的优势是：每个数据块能够独立适应自己的数值范围，而且缩放参数可以通过硬件友好的格式存储和处理。但块级缩放也会产生额外开销，包括缩放参数存储、数据布局管理和内核适配。因此，MXFP8 的实际性能优势取决于硬件是否原生支持对应的块级格式与计算路径。

MXFP8 采用微缩放（Microscaling）机制，通常以小数据块为单位共享缩放因子。相比过于粗粒度的统一缩放，这种方式能够更细致地适应不同数据块的动态范围。

### NVFP4：NVIDIA 的细粒度 FP4 量化路线

NVFP4 是 NVIDIA 面向超低精度计算设计的一套 FP4 格式与缩放方案。它不仅定义了 4 bit 浮点数据的编码，还规定了如何通过分层缩放恢复数值范围，并配合相应硬件计算路径执行低精度运算。

NVFP4 使用 E2M1 格式，每个元素由以下位组成：

- 1 bit 符号位。
- 2 bit 指数位。
- 1 bit 尾数位。

它能够表示的有限数值非常少，最大绝对值为 6。以正数为例，其非零可表示值包括：

$[0.5, 1, 1.5, 2, 3, 4, 6]$

这意味着，FP4 本身的数值精度很有限。如果直接用 FP4 表示具有复杂分布的权重和激活，很容易产生较大量化误差。因此，NVFP4 的核心不只是 4 bit 编码，而是利用**两级缩放**，让有限的 FP4 数值能够适应不同范围的数据。

NVFP4 的近似反量化形式为：

$ \hat{x}=q_{\mathrm{FP4}}\cdot s_{\mathrm{block}} \cdot s_{\mathrm{global}} $

其中：

- $q_{\mathrm{FP4}}$：4 bit 的 E2M1 数据。
- $s_{\mathrm{block}}$：每个数据块共享的 FP8 E4M3 缩放因子。
- $s_{\mathrm{global}}$：整个张量共享的 FP32 缩放因子。

默认的典型配置中，每 16 个连续元素共享一个局部缩放因子；权重还可以采用二维分组缩放，以改善矩阵不同方向上的量化效果。

![](https://picx.zhimg.com/v2-f045c3149d4d3f512bb68075c3eaf29b_r.jpg)

两级缩放的意义在于：

1. FP32 全局缩放因子控制整个张量的数值范围。
2. FP8 局部缩放因子适配每个小块的局部数值分布。
3. FP4 数据**负责紧凑存储**，并在相应低精度硬件路径上参与矩阵计算。

与 MXFP4 相比，NVFP4 的局部缩放粒度更细，而且局部缩放因子采用 FP8 E4M3 表示，而不是只使用二次幂指数。

### MXFP4：基于 OCP 微缩放规范的 FP4 路线

MXFP4 同样使用 E2M1 FP4 元素，但其缩放方式遵循 OCP Microscaling（MX）规范。

它与 NVFP4 的主要区别在于：MXFP4 默认以 32 个元素为一组共享 E8M0 缩放因子。**E8M0 只表达指数**，因此缩放值以二次幂形式变化。

MXFP4 的反量化形式可以简化为：

$\hat{x}=q_{\mathrm{FP4}} \cdot 2^e $

其中: $e$ 由数据块的 E8M0 缩放参数决定。实际实现中，还需要遵循格式规范规定的特殊值与舍入规则。

与 NVFP4 相比，MXFP4 的特点是：

- 以 32 个元素为一组共享缩放因子。
- 缩放因子采用 E8M0 指数格式。
- 格式设计遵循公开的 OCP 微缩放规范，有利于不同实现之间建立统一的数据表示约定。

其优势在于格式规范化和硬件实现的简洁性，但二次幂缩放的粒度较粗，局部数据范围无法像 NVFP4 那样通过 FP8 缩放因子进行更细致的调整。

MXFP4 与 NVFP4 的关键差异:

| 对比维度 | MXFP4 | NVFP4 |
| --- | --- | --- |
| FP4 元素编码 | E2M1 | E2M1 |
| 默认局部块大小 | 32 个元素 | 16 个元素 |
| 局部缩放格式 | E8M0 | FP8 E4M3 |
| 全局缩放 | 不采用 NVFP4 这种独立 FP32 全局缩放层级 | FP32 全局 scale |
| 缩放粒度 | 较粗，二次幂缩放 | 更细，浮点局部缩放 |
| 规范与生态 | OCP MX 规范 | NVIDIA 的格式与计算方案 |
| 主要取舍 | 规范化、实现简洁 | 更细粒度缩放，目标是改善低比特精度 |

从技术演进来看，这几条路线并非简单的替代关系。FP8 适合追求成熟的低精度计算路径，MXFP8 进一步探索细粒度缩放，而 NVFP4/MXFP4 则试图在精度允许的情况下进一步降低计算与数据搬运成本。

### 前沿研究：从激活误差控制到精度与性能协同设计

针对 MoE 权重与激活量化，研究重点正在从统一降低位宽，转向同时考虑专家分布、量化误差和实际计算效率。

### EAQuant（ W4A4 / W3A4）

- 论文：[EAQuant: Enhancing Post-Training Quantization for MoE Models via Expert-Aware Optimization](https://arxiv.org/pdf/2506.13329)
- 代码：[https://github.com/darren-fzq1/EAQuant](https://github.com/darren-fzq1/EAQuant)

这项工作直接研究了 MoE 激活量化面临的离群值、路由一致性与专家校准问题，提出三个关键机制：

- Expert-aware smoothing：通过专家感知平滑抑制激活离群值。
- Router logits distribution alignment：对齐路由分数分布，尽量保持专家选择的一致性。
- Expert-level calibration data balance：改善低频专家的校准数据不足问题。

论文报告了多种 MoE 架构上的 W4A4 与 W3A4 实验结果，重点价值在于把激活误差、路由行为和专家校准放入同一个量化框架中。

### MxMoE

- 论文：[MxMoE: Mixed-precision Quantization for MoE with Accuracy and Performance Co-Design](https://arxiv.org/pdf/2505.05799)
- 代码：[https://github.com/cat538/MxMoE](https://github.com/cat538/MxMoE)

MxMoE 的特点是联合考虑算法精度与系统性能，而不是只优化模型的量化误差。

- 根据不同线性模块的敏感度选择精度。
- 结合专家激活频率和硬件资源确定混合精度配置。
- 自动生成支持不同精度的 GroupGEMM 内核。

论文报告，MxMoE（W5A5）相比 W8A8 实现最高 29.4% 的性能提升，同时保持与全精度模型相当的困惑度。这是特定实验条件下的结果，不能直接视为所有 MoE 模型和 GPU 的通用加速比例。

![](https://pic2.zhimg.com/v2-38f36845aba669ca602b630bf57ab181_r.jpg)

研究价值： 将混合精度策略与实际内核执行联系起来，特别适合研究如何把量化收益转化为端到端推理性能。

### CodeQuant：面向 MoE 的离群值感知权重与激活联合量化

- 论文：[CodeQuant: Unified Clustering and Quantization for Enhanced Outlier Smoothing in Low-Precision Mixture-of-Experts](https://arxiv.org/pdf/2604.10496)
- 代码：[https://github.com/SAI-Lab-NYU/CodeQuant](https://github.com/SAI-Lab-NYU/CodeQuant)

CodeQuant 针对 MoE 模型在 4-bit 等低比特量化下容易出现的精度下降问题，提出结合激活离群值平滑、权重聚类和专用推理内核的后训练量化方案。其核心挑战在于：MoE 的权重与激活分布存在离群值，量化误差还可能影响 Router 的专家选择，进而放大模型输出误差。

CodeQuant 主要包含三个技术环节：

1. AOS（激活离群值平滑）：学习旋转矩阵，重新分配激活各通道的数值幅度，降低离群值对低比特量化的影响。
2. ACCF（权重聚类与中心微调）：采用非均匀聚类中心表示权重，并利用校准数据微调聚类中心，以降低量化误差；通过 KL 散度约束，减少量化对 Router 行为的影响。
3. LUT 推理内核：利用聚类索引和预计算查找表执行计算，减少重复乘法操作；POG 权重重排则可作为可选步骤，进一步改善权重分组效果。

![](https://pica.zhimg.com/v2-ee5c612ff630037fe6b6a84c0cac4cf6_r.jpg)

实验结果： 在 DeepSeek-V2-Lite、Qwen3-30B-A3B 和 Mixtral 8×7B 等模型的 A4W4 实验中，CodeQuant 相比 QuaRot 显著改善了困惑度和下游任务准确率。例如，Qwen3-30B-A3B 的 WikiText-2 困惑度从 16.04 降至 10.31，平均下游任务准确率从 58.1% 提升至 69.4%。性能方面，论文报告 GPU 仿真平均加速约 2.63×，CPU 实测最高加速约 4.15×。需要注意的是，GPU 加速结果来自仿真，而非标准 GPU 上的直接实测。

### MoE 权重与激活量化的未来方向

综合来看，这一领域正在沿着三个方向发展。

1. 更低位宽的计算。从 FP8 W8A8 逐步探索 W4A8、W4A4 计算路径，在尽量维持模型精度的前提下，降低数据表示与计算成本。
2. 更细粒度的专家感知量化。 根据专家激活分布、层敏感性、路由行为和校准数据差异，选择合适的缩放方式与精度配置。
3. 算法与系统协同优化。 将量化误差控制、Grouped GEMM、动态形状、专家调度和通信优化联合考虑，使低精度计算真正转化为服务性能收益。

对于实际部署，建议优先验证硬件支持成熟的 FP8 路径，再评估具备完整低精度内核支持的 FP4 方案。如果目标是进一步探索 W4A4 或 W3A4，则需要更加重视激活误差、Router 一致性以及端到端性能。

## MoE KV Cache 量化：面向长上下文与高并发推理

在讨论 MoE 模型量化时，KV Cache 量化（应用于采用相应 Attention 架构的 MoE 模型）同样至关重要。MoE 模型的参数量通常很大，量化 Expert FFN 可以显著减少模型权重占用。但在长上下文、高并发推理场景中，即使模型权重已经压缩到 4 bit，KV Cache 仍可能成为 GPU 显存的重要瓶颈。

但需要准确区分：这些代表性方法大多是面向通用 Transformer 推理提出的，并非专门为 MoE 设计。

对于采用标准全注意力的 MoE 模型，其 KV Cache 大小主要取决于：

- Attention 层数。
- 每层 KV Head 数量。
- 每个 Head 的维度。
- 上下文长度和并发请求数。
- KV Cache 的数据精度。

它通常不直接取决于 MoE 的专家总数，因为**标准 MoE 的路由**一般发生在 FFN 部分，而不是让每个专家分别保存一份完整的 Attention KV Cache。

### KV Cache 量化的代表性研究

### KIVI：非对称 2-bit KV Cache 量化

- 论文：[KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache](https://arxiv.org/pdf/2402.02750)
- 代码：[https://github.com/jy-yuan/KIVI](https://github.com/jy-yuan/KIVI)

KIVI 的重要发现是，Key 与 Value 的数据分布存在差异，适合采用不同的量化粒度：

- **Key：按通道量化（per-channel）**。
- **Value：按 Token 量化（per-token）**。

这种非对称设计可以更好地适配 K/V 的数值分布，并在不进行额外模型微调的条件下实现低比特 KV Cache。

论文报告，在其评测模型和设置中，KIVI 可以降低峰值显存、提高可支持的批次大小，并提升推理吞吐量。

KIVI 是研究 2-bit KV Cache 的重要基础，但论文主要验证的是 Llama、Falcon、Mistral 等模型。

- 论文：[KVQuant: Towards 10 Million Context Length LLM Inference with KV Cache Quantization](https://arxiv.org/pdf/2401.18079)
- 代码：[https://github.com/SqueezeAILab/KVQuant](https://github.com/SqueezeAILab/KVQuant)

KVQuant 主要解决低于 4-bit 时 KV Cache 的量化误差问题，采用多项设计：

1. **Key 按通道量化**：根据 Key 的分布选择合适的量化维度。
2. **RoPE 前量化 Key**：尽量减轻旋转位置编码对量化误差的影响。
3. **非均匀量化**：根据不同层的敏感性选择更适合数据分布的量化表示。
4. **密集值与离群值分离处理**：降低离群值对量化范围的影响。

论文在特定模型和评测条件下展示了 3-bit KV Cache 的可行性，并实现了面向长上下文推理的优化内核。

KVQuant 的主要启示是：KV Cache 的低比特量化不能只依赖统一的线性映射，还需要考虑 K/V 分布差异、层敏感性、离群值和内核效率。

### TurboQuant：面向低比特 KV Cache 的向量量化方法

- 论文：[TurboQuant: Online Vector Quantization with Near-optimal Distortion Rate](https://arxiv.org/pdf/2504.19874)
- 代码： <br>

传统低比特量化需要额外的缩放参数，并且可能影响 Attention 中 Query 与 Key 的内积精度。TurboQuant 由 Google Research 提出，发表于 ICLR 2026，旨在减少 KV Cache 存储开销，同时控制量化失真。

TurboQuant 首先对高维向量进行随机旋转，使各坐标的分布更集中，再使用低比特标量量化器压缩数据；同时利用 1-bit Quantized Johnson–Lindenstrauss（QJL）变换对量化残差进行校正，改善内积估计的偏差。其核心是结合向量几何变换、低比特量化与残差校正，在降低存储成本的同时尽量保持 Attention 计算精度。

原论文在 Llama-3.1-8B-Instruct 的 LongBench 测试中报告，TurboQuant 使用约 3.5 bit/维时，平均得分达到 50.06，与 FP16 基线持平；约 2.5 bit/维时得分为 49.44，表现出较好的压缩与精度权衡。

但是 vLLM 关于的TurboQuant测评[报告](https://vllm.ai/blog/2026-05-11-turboquant)指出， FP8 KV-cache 仍是更稳妥的默认选择。原因是 FP8 不仅存 KV 用 FP8，连 attention 计算也走硬件原生 FP8 路径；而 TurboQuant 只压缩 KV 存储，attention 前再反量化回 BF16。4bit-nc 是 TurboQuant 里最实用的变体，在 KV 显存压力大时再把容量推到约 3.1–3.4x，但要接受中等精度、延迟和吞吐代价。k3v4-nc / 3bit-nc 变体则不适合生产，虽然容量可到约 3.4–4.2x，但推理任务和很长上下文上的精度下降更明显，同时延迟、吞吐恶化严重。

### 动态 KV 量化与混合精度

除了固定的 2-bit、3-bit 或 4-bit 量化，另一条研究路线是根据 Token、Attention Head 或层的重要性分配不同精度。

其基本思路包括：

- 对重要的 Token 保留更高精度，
- 对不同层和 Head 使用不同位宽；
- 对 K 和 V 使用不同量化粒度；
- 在压缩比例、注意力计算误差和内核开销之间进行联合优化。

比如：

**KVTuner**：按层敏感性分配 K/V 位宽

研究不同 Transformer 层对 KV 量化误差的敏感程度，离线搜索每层适合的 K、V 精度组合，再将配置用于在线推理。它还通过剪枝和层聚类降低搜索成本。

实验结果： 在 Llama-3.1-8B-Instruct 的数学推理任务中，论文报告约 3.25 bit 的混合精度 KV Cache 可接近无损；对更敏感的 Qwen2.5-7B-Instruct，约需 4 bit。相较 KIVI-KV8，报告的最高推理吞吐提升为 21.25%。

**KVmix**：梯度敏感性与关键 Token 保精度

使用 Key、Value 投影权重相对于模型损失的梯度范数，评估各层 K/V 的重要性，并为敏感层分配更高位宽。同时，在长上下文中**保留近期关键 Token 的全精度 KV，对较早的缓存进行更激进的压缩**。

实验结果： 论文报告 Key 平均约 2.19 bit、Value 平均约 2.38 bit，实现约 4.9× 显存压缩和最高 5.3× 推理吞吐提升。

**KVC-Q**：按 Token 重要性与 Head 敏感性动态分配精度

结合近期性、注意力重要性和 Head 敏感性进行动态精度分配：近期关键 Token 和重要的历史 Token 保留较高精度，其他 KV 则使用更低位宽。它的特点是尽量保留完整历史，而不是直接淘汰 Token。

论文在 LongBench 上报告，KV Cache 显存占用降低约 70%，同时保留超过 94% 的基线表现，并可在消费级 GPU 上支持超过 4 倍的上下文长度。

**ChanMix**：按 KV 通道敏感性分配位宽

它发现不同 KV 通道的量化敏感性存在显著差异，尤其是离群值通道和长上下文检索敏感通道。因此，为关键通道分配更高精度，为较稳健的通道分配更低精度，并提供 2-bit 量化和自定义 Triton 内核。

![](https://pic1.zhimg.com/v2-5416896174cde5c3b19d247b714fb7e4_r.jpg)

实验结果： 在 Llama、Mistral 和 Qwen 模型的 NIAH、RULER、InfiniteBench 测试中，论文报告 RULER 相较基线至少提升 5 个绝对百分点，并支持约 2.3 倍批次大小和 1.5 倍上下文长度。

**MixKVQ**：根据当前 Query 动态保护关键 Key 通道

- [MixKVQ: Query-Aware Mixed-Precision KV Cache Quantization for Long-Context Reasoning](https://aclanthology.org/2026.acl-long.326.pdf)
- 代码：[https://github.com/ZeroNLP/MixKVQ](https://github.com/ZeroNLP/MixKVQ)

它同时考虑 **Key 通道本身的量化难度**，以及该通道**对当前 Query 的相关性**。算法为重要 Key 通道保留更高精度，对 Value 使用逐 Token 量化，尤其面向长链式推理场景。

![](https://picx.zhimg.com/v2-73c452ebd081ddad266a412e82d35411_r.jpg)

实验结果：论文在复杂推理数据集上报告，能够以显著更低的 KV 显存占用取得接近全精度基线的表现。

## MoE 模型量化的应用

### NVIDIA Model Optimizer

Model Optimizer 是量化工具链，它的突出特点是支持通过 Recipe 指定哪些层量化、使用什么精度，以及 KV Cache 采用什么格式。当前官方 Recipe 已明确提供 MoE 专家专用 NVFP4、FP8 KV Cache 等组合。

### 仅权重量化

- 激活保持 BF16/FP16，只压权重。
- 校准最简单，**直接在权重张量本身上校准**（甚至免校准），不经前向、不依赖 token 是否路由到该专家。
- 精度风险最低，但收益仅限显存与权重读取带宽。

**典型配置**：nvfp4_mlp_weight_only.yaml（NVFP4 W4A16，Blackwell 权重专用）

```text
# QuantizeConfig preset for NVFP4 block-size-32 weight-only quantization on MLP/MoE layers.

# modelopt-schema: modelopt.torch.quantization.config.QuantizeConfig
imports:
  base_disable_all: configs/ptq/units/base_disable_all # 先关掉一切
  default_disabled_quantizers: configs/ptq/units/default_disabled_quantizers # 安全网：router / *mlp.gate.* / 共享专家门控 / lm_head / 视觉分支等全部禁量
  nvfp4_bs32: configs/numerics/nvfp4_bs32 # block-32 NVFP4 

algorithm: max # 校准算法；weight-only 时 num_calib 前向只用于权重 amax 的兜底，不走激活统计
quant_cfg:
  - $import: base_disable_all # 第一步：默认不量化任何东西
  - quantizer_name: '*mlp*weight_quantizer' # 第二步：所有 MLP（含共享专家）的【权重】开 nvfp4_bs32
    cfg:
      $import: nvfp4_bs32
  - quantizer_name: '*block_sparse_moe*weight_quantizer'
    cfg:
      $import: nvfp4_bs32
  - $import: default_disabled_quantizers # 第三步：敏感模块回读 BF16（被 mlp 通配符误选中的）

```

被引用的数值定义 configs/numerics/nvfp4_bs32.yaml：

```text
num_bits: e2m1           # NVFP4 的数据格式：FP4 E2M1
block_sizes:
  -1: 32                 # 每 32 个连续元素共享一个 scale（沿最后一维(-1)分块）
  type: dynamic          # scale 动态计算：无需校准前向，直接从权重本身推出来
  scale_bits: e4m3       # scale 用 FP8 E4M3 表示

```

适用场景：

- 低并发/边缘/端侧：decode 是 memory-bandwidth-bound，压权重即收益。
- 无 Blackwell（没有 NVFP4 tensor core）：W4A16、INT4 AWQ 是唯一现实的 4bit 路径。
- **在有 FP4 kernel 的硬件上，MoE 要吞吐必须上 W4A4**——Qwen3.6-35B 上 W4A16 有 10/12 个 shape 比 BF16 还慢（0.64–0.86×）

### 权重与激活联合量化

- 权重与输入激活一起量化。
- MoE 上默认作用域是"只压路由专家"——专家占参数绝对多数（Qwen3.6-35B 量化张量的 99.2% 是 MoE 专家），而注意力、router、共享专家留在高精度。

**校准**：

W*A 的激活统计要靠校准前向，MoE 的稀疏路由在此制造困难，大体思路：

1. **权重先行**；
2. **层内专家 amax 同步**：把各专家的输入 amax 逐元素取 max 写回——让整组专家共享一个 input scale；
3. **完整性检查**：发现任何 DP/EP/TP rank 上有专家零 token 时直接抛错（"Increase --calib-size"）；
4. **分布式同步**：DP 总是同步 amax；EP 侧区分——路由专家的**权重** amax 默认不跨 EP 同步（各 rank 分片本就不同），激活 amax 总是同步；
5. **抬 top_k 备选**：在校准期把 top_k 临时抬到 `round(num_experts × ratio)`，让更多专家见到 token；开启后禁用层内 amax 同步，且并非所有架构都支持。

**典型配置**：nvfp4_experts_only.yaml

```text
# QuantizeConfig preset for dynamic NVFP4 W4A4 quantization on expert layers only.

# modelopt-schema: modelopt.torch.quantization.config.QuantizeConfig
imports:
  base_disable_all: configs/ptq/units/base_disable_all
  block_sparse_moe_nvfp4: configs/ptq/units/block_sparse_moe_nvfp4
  experts_nvfp4: configs/ptq/units/experts_nvfp4
  default_disabled_quantizers: configs/ptq/units/default_disabled_quantizers

algorithm: max
quant_cfg:
  - $import: base_disable_all
  - $import: block_sparse_moe_nvfp4
  - $import: experts_nvfp4
  - $import: default_disabled_quantizers

```

被引用的数值定义 configs/ptq/units/experts_nvfp4.yaml

```text
# QuantizerCfgList snippet that enables dynamic NVFP4 on weight and input
# quantizers under ``*.experts.*`` paths.

# modelopt-schema: modelopt.torch.quantization.config.QuantizerCfgListConfig
imports:
  nvfp4: configs/numerics/nvfp4
---
  - quantizer_name: '*.experts.*weight_quantizer'
    cfg:
      $import: nvfp4
  - quantizer_name: '*.experts.*input_quantizer'
    cfg:
      $import: nvfp4

```

适用场景：

- 服务端高并发：必须 W4A4（Blackwell）或 W8A8（Hopper+）才能进 tensor core 路径。Qwen3.6-35B：W4A4 在 12 个 shape 里 9 个胜过 BF16、最高 1.30×，checkpoint 67→22 GiB。
- 作用域从窄到宽：`nvfp4_experts_only(MoE 路由专家)` → `nvfp4_mlp_only(所有 MLP/MoE)` → `nvfp4_omlp_only(MLP + o_proj)` → `nvfp4`，每步实测精度。
- PTQ 后精度缺口可用 QAD(量化感知蒸馏) 恢复

### KV Cache 量化

KV Cache 是独立于 MoE 主体结构的压缩维度，量化器挂在 attention 模块上，MoE 模型照常复用。

Model Optimizer 中常用的可选 KV 格式：

| 格式 | 校准 | 特点 |
| --- | --- | --- |
| kv_fp8 | 需要 | FP8 per-tensor，按校准统计 |
| kv_fp8_cast | 免 | 常量 amax 448.0（use_constant_amax），默认方案 |
| kv_fp8_affine | 免 | FP8 + affine |
| kv_nvfp4(_cast/_affine/_rotate) | 视变体 | NVFP4 block 16，约 4.5 有效 bits，Blackwell+ |
| kv_nvfp4_mla（unit） | 免 | MLA：RoPE key FP8 + latent NVFP4（*kv_c_bmm_quantizer/*k_pe_bmm_quantizer） |

Model Optimizer 可以将模型主体和 KV Cache 分别配置。例如：

- `nvfp4_experts_only-kv_fp8`：专家采用 NVFP4 W4A4，KV Cache 使用 FP8。
- `nvfp4_experts_only-kv_fp8_cast`：专家采用 NVFP4 W4A4，KV Cache 使用常量缩放的 FP8 cast 路径。
- `nvfp4_default-kv_nvfp4_cast`：主体采用 NVFP4 W4A4，KV Cache 也采用 NVFP4。

**AutoQuant KV**：逐层混合精度搜索

AutoQuantize 的通用思想：**逐层测量“换成低精度格式会伤害模型多少”，再求一个满足预算约束的最优格式分配**。

- 问题定义：给定候选格式集合，对每个含 KV 量化的注意力层选一个候选格式，使 **KV Cache 平均有效比特 ≤ 用户预算 effective_bits**，同时最小化总精度损失（KL 敏感度之和）。
- **候选层的发现**：遍历 `named_modules`，取同时拥有 `k_bmm_quantizer` 和 `v_bmm_quantizer` 属性的模；K/V 宽度取自 `k_proj/v_proj.out_features`；`disabled_layers` 通配符剔除后**不计入预算**。
- 搜索空间约束： <br>
- 候选校准：对每个候选，**把所有层一次性切到该候选**，用 `mtq.calibrate`（algorithm 只允许 `None` 或 `"max"`）跑校准前向，统计各自 amax；用 `_freeze_existing_quantizers` 把模型里已存在的其它量化器（如前面阶段做过的 GEMM FP8/NVFP4）冻结，避免被重校准。校准产物连同候选选择一起存进检查点——后续打分和重解 LP 全部不再碰数据。
- 敏感度打分：每次试验**只切一层的 K/V 组**，不是全层同时切。打分按 batch 累加、最后除以 `scored_tokens` 归一，存为每层每候选一个分数；NaN/Inf logits 直接报错拒走。
- 全局整数规划：KV 域选用 ILP，是因为 KV 域候选稀少（2-3 个/层）、层间独立、单约束，LP 一次性求全局最优。

### Model Optimizer 中应用建议

如果目标是 MoE 模型压缩且希望尽量保留精度，先从 `nvfp4_experts_only` 开始，再单独测试 KV Cache FP8；只有在显存仍然不足时，再考虑进一步压缩 Attention 或 KV Cache。

### SGLang

对 MoE（混合专家）模型来说量化的收益比 dense 模型更直接：MoE 的参数量 97% 以上都躺在"专家"的 FFN 权重里，而推理 decode 阶段的瓶颈恰恰是把这些权重从显存读进计算单元的速度。**权重读快 4 倍，基本等于 decode 快 4 倍量级**。

SGLang 量化参数：

| 你想压什么 | 用的参数 | 压缩对象 |
| --- | --- | --- |
| 权重（常驻显存的大头） | --quantization | 每个权重从 16-bit 压到 8/4-bit |
| 权重 + 每步计算的激活 | --quantization | 计算过程也进低精度，额外吃到算力红利 |
| KV cache（随对话变长线性增长） | --kv-cache-dtype | 每个 token 写入缓存的 K/V 向量 |

SGLang 有两条使用路径（离线量化还是在线量化）：

- A：加载别人已经量化好的模型（推荐） <br>
- B：把 BF16 模型现场压一遍（在线量化） <br>

建议：**生产用 A，实验用 B。**

### 仅权重量化

仅权重量化只压权重，激活照旧用 BF16/FP16 计算。推理时先把 4-bit 权重解压成高精度再算——多一步解压，但这一步被高效 kernel 融合掉了。 **收益**：显存和权重带宽直接省 3–4 倍（INT4 时），精度损失小、工程风险最低。 **代价**：计算本身没有变快（GEMM 还在做高精度运算）。

优先找 `awq_marlin` / `gptq_marlin` 兼容格式的 checkpoint（Marlin 是 Ampere 及以后硬件上的高性能 kernel 后缀）。仅权重量化适用于**显存吃紧、算力相对富余**的场景（大模型、小并发）。

### 权重 + 激活量化

权重 + 激活量化把权重与激活都压成 8-bit/4-bit，让 GPU 直接在低精度上做矩阵乘法。这时 FP8/FP4 GEMM 不只是省带宽，还省功耗提算力。

直觉上，权重+激活同时量化全面优于仅权重量化，但代价是三个新的坑：

1. **激活是每步动态产生的**，需要实时的缩放系数（scale），kernel 要在"量化的世界"里直接算，对 kernel 和硬件有自己的门槛；
2. **对 MoE 有一层特殊耦合**：专家 GEMM 的执行后端（`--moe-runner-backend`）和量化格式必须匹配。特别是开了专家并行低延迟通信 `--moe-a2a-backend deepep_v2` 时，**后端被强制锁死为 `deep_gemm`，量化也就相应只能选 DeepGEMM 支持的格式（主要是 FP8 block-wise）。记住这个顺序：先定硬件和通信方式，再定量化的格式**；
3. scale 有三种形态（per-tensor / 128 一块的 block-wise / MX 微缩放），block 维度对不上 kernel 预期会直接在加载时报错。

**两个最常用的配方**：

- **Hopper/Blackwell + FP8**：DeepSeek V3/R1 的原生格式，直接加载零参数；想压 BF16 模型就 `--quantization fp8`；
- **Blackwell 极限（W4A4 NVFP4）**：权重和激活都是 4-bit，显存收益最大、算力最快，但只有最新一代卡能原生跑；老卡上 SGLang 会自动 fallback 到 Marlin 4-bit 权重方案。

### KV Cache 量化

对话上下文越长、并发请求越多，KV cache 的显存占用越恐怖——32K 上下文下它常常超过权重本身。通常，长上下文场景会开 KV Cache 量化。

--kv-cache-dtype 可选参数：

| 取值 | 通俗解释 | 适合 |
| --- | --- | --- |
| fp8_e4m3 | 8-bit 带缩放系数，精度最稳 | 默认首选 |
| fp8_e5m2 | 8-bit 不带缩放系数的"粗暴直存版"，实现最简单 | 先跑通再精调 |
| nvfp4 / fp4_mx_block16 | 4-bit 压到极限 | CUDA 12.8+ / PyTorch 2.8.0+ 的最新硬件，官方明示"精度有风险" |

**MoE 模型上想开 FP8 KV，唯一可靠的精度保障是 checkpoint 自带 scale（LLM Compressor/ModelOpt 这类工具量化产物会带）**。 checkpoint 没带 scale 时，SGLang 会把缩放系数默认成 1.0（相当于不缩放直接压），长上下文末尾的 token 精度会肉眼可见地掉。所以 MoE + FP8 KV 上线前先做一轮长文本精度对比。

## MoE 模型量化的评估方法

| 评估维度 | 关键指标 | 关注点 |
| --- | --- | --- |
| 模型精度 | 困惑度、任务准确率、推理基准得分 | 量化是否明显损害模型能力？ |
| 激活误差 | 相对误差、余弦相似度、异常值分布 | 哪些层和专家对激活量化更敏感？ |
| 路由稳定性 | Top-k 专家一致率、Router 分数变化 | 量化是否改变专家选择？ |
| 内核性能 | GEMM 延迟、吞吐、Tensor Core 利用率 | 低精度计算是否真正加速？ |
| 系统开销 | 量化开销、布局转换、专家通信时间 | 辅助操作是否抵消计算收益？ |
| 服务性能 | TTFT、TPOT、并发吞吐量 | 实际在线服务是否获得收益？ |

## 总结

MoE 量化正在从单纯降低专家权重精度，发展为权重、激活、KV Cache 和硬件执行路径的协同优化。

在权重量化方面，MoEQuant 通过专家均衡采样和亲和度引导改善校准，Automated Fine-Grained MoE Quantization 研究更细粒度的位宽分配，MxMoE 则强调混合精度与 Grouped GEMM 性能协同。

在权重与激活联合量化方面，EAQuant 将激活平滑、路由一致性和专家校准结合起来，为 W4A4、W3A4 等更激进的量化配置提供了研究思路。

在 KV Cache 量化方面，KIVI 和 KVQuant 分别展示了非对称 2-bit 量化以及面向超长上下文的低比特量化技术。

总体而言，MoE 量化的核心是如何在模型精度、专家路由、显存预算、低比特计算和服务性能之间取得平衡。未来更有价值的方向，是将专家感知的权重与激活量化、低比特 KV Cache 和推理系统优化纳入统一的端到端设计框架。
