提示词应该怎么写：一次 8 版本迭代总结出的方法论（附完整实验记录）<br><br> 背景实验：GroupMemBench Finance 全量 7 维度（239 题）+ 跨领域验证（Healthcare / Manufacturing / Technology，244+134 题）<br>时间：2026-10-27 ~ 10-28<br>主线：上下文工程总纲「引导大模型固定状态 → 智能体记忆状态」在提示词层的完整长链实践<br>联合署名：山越野人 × 岚客（人类提供意图与判断主线，智能体撰写）<br><br> <br><br> <br> 开头总结：提示词应该怎么写<br><br> 这篇文章的实验里，**模型自由发挥时守手只有 16.7%（该拒的不拒，几乎全崩），最终提示词把它拉到 89.7%（+73pp）** 。但**实验只是效果证据，真正的结论是方法论**——经过 8 个版本、约 10 次全量评测，我们把"提示词应该怎么写"总结成下面几条。前两条最重要，是这轮迭代付了最大代价换来的：<br><br> **第一条：规则可执行性 = 输入里必须有规则引用的信号。**<br>我们最严重的一次翻车：v2.9.4 的规则写得完全正确（deadline 锁定、叙事漂移守卫），冒烟却全失败。查到底才发现，规则引用的字段（decision_type=changed）根本不在模型看到的检索结果里——模型无信号可执行，只能退回叙事直觉。最后靠往输入里注入决策字段才闭环。**结论：写提示词前第一件事是检查——这条规则依赖的信号，真的进了上下文吗？没有信号的规则是死文本。**<br><br> **第二条：压力反噬。威胁、强制、多搜会催化防御性行为。**<br>从早期泄压阀实验到 v2.9 全程，"威胁/强制/多搜"都让模型变得更保守、更防御，成绩不升反降。prompt 层的正确姿势是"**给出口 + 给信号**"——给模型明确的退出路径（如"带引用的拒答严格优于死搜"），给规则可执行的信号，而不是施压。提示词的语气本身也是工程参数，不是修辞。<br><br> **第三条：给判定结构，不给自由发挥。**<br>把"凭直觉回答"改造成集合判定（问题要求什么 / 语料断言了什么 / 断言是否覆盖要求，配判定规则），判断才可判定、可检查、可迭代。这是后面所有规则的地基。<br><br> **第四条：只信断言，不信请求、提议、规则名。**<br>这是本实验里单条收益最大的原则——"该收手"和"该多搜"不是零和，是同一原则在两个维度上的对称应用：该答的答、该拒的拒，都只看消息是否把内容当作既成事实。<br><br> **第五条：收益有语料边界，必须做跨领域验证。**<br>Finance 内 +10.4pp 的收益跨领域不迁移。迭代过程中要随时区分"机制变好了"和"记住了语料"——跨领域验证不是可选动作。<br><br> **效果证据**（实验本身，支撑上面结论）：<br><br>

- **起点对照（震撼在这里）** ：模型自由发挥时守手只有 **16.7%** （该拒的不拒，几乎全崩）→ 最终 **89.7%** （+73pp）；direct 初版有答案 60.4% → 最终 **87.5%** （+27.1pp）。同一套任务，提示词约束把两个维度从崩溃线拉到了历史最优。
- Finance 全量 7 维度 **69.9% → 80.3%（+10.4pp）** ，7 维全升、核心双维度零损伤（守手 86.2%→89.7%，有答案 85.4%→87.5%）。
- 弱维度被大幅拉起：knowledge_update 46.9%→75.0%、term_ambiguity 48.9%→66.7%、temporal_rest 72.0%→84.0%。
- 跨领域 multi_hop 62.7%→61.9%（持平），证明收益语料特化，62% 是检索层天花板。

<br> <br> 故事线：为什么会有这一路<br><br> 先把来龙去脉讲清楚——这一路不是一路向上的，恰恰相反，开头很挫。而且它有一个更早的起因。<br><br> **第零步，起因：abstention 先翻车，造基准时才发现有拒答能力，回头研究。** GroupMemBench（多用户群聊记忆基准）Finance 域自带 abstention 题（29 题，全部应该拒答——语料里根本没有答案）。我们跑的时候**单纯翻车了**：检索增强（DSH）喂了近似语料，正确拒答从 93.1% 崩到 **17.2%（-75.9pp）** ，9 题 8 个变体全错编答——当时以为就是模型不行。<br><br> 后来我们想针对这个现象造一个"自知之明"基准，尝试直答（不给模型检索料、直接问）才发现：**模型其实有拒答能力**——直答能正确拒答，直喂陷阱语料也能拒，它不是没有能力。<br><br> 带着这个矛盾回头研究：一开始归因为**噪音影响**，以为检索喂的杂料干扰了判断；专门做对照才发现不是——**无关噪声不影响，只有近似语料才击穿**：模型把"语料里出现过相关主题"误判成"题干答案存在"。<br><br> **这一步给我们的关键认知**：模型不是没能力（直喂陷阱料也能拒），是**跟着感觉走、没有运用方法论**——在"看起来相关"的近似语料压力下凭叙事直觉答题，而不是先判"这个问题到底有没有答案"。我们做了 8 个协议变体死磕（泄压阀、门控、组合、三段叠加……），最好的也只有 **58.62%** ；最低的"干净基线"只有 20.69%——注意它不是纯记忆侧的对照，那个基线**已经上了常规系统提示词**（常规提示词同样拉后腿，不只是检索喂料的问题）——**prompt 层上限冻结**，光靠措辞改不动这个默认倾向。这份观察发到了 DeepSeek 官方仓库 issue 区（[#1726](https://github.com/deepseek-ai/DeepSeek-V3/issues/1726)，全文含 8 变体逐题数据，公开可复现），有社区志愿者认可了发现，但这不是官方路线，也不会因此改变模型。<br><br> 要根治"跟着感觉走"，只能从外部补上模型缺的那个东西——**判断方法论**：从判断入手（该不该答先判清楚），再谈措辞。这就是我们上下文工程总纲（**引导大模型固定状态 → 智能体记忆状态**）的由来，R-E27 是它在提示词层的完整实践。<br><br> **第一步，常规提示词，确实挺差。** 58.62% 就是我们常规方案（8 变体里的三段叠加，v9）的真实上限——凭直觉措辞，怎么调都顶不上去。这个任务考的是长程对话记忆：给定一大段跨天的团队对话，问"现在这个日期是什么状态/谁负责/最新决定是什么"，还要在语料没有答案时老实拒答。常规提示词下模型凭叙事直觉答，完全不行。<br><br> **第二步，机械约束，按下葫芦浮起瓢。** 不服气，继续研究。先试给检索加机械 harness（检索上限 + 超时），守手从 58.6% 涨到 75.9%（+17.3pp），但有答案维度反而崩——机械限制救了一头压垮另一头，是零和。<br><br> **第三步，换自由循环，差点全崩。** 不死心，再换思路：拆掉机械循环，让提示词自己驱动认知循环（direct 模式）。结果更惨：有答案掉到 60.4%，纯自由发挥的对照版守手只有 16.7%——模型无约束时什么都敢答，该拒的全不拒，几乎全崩。<br><br> **第四步，关键转折：从判断入手，引入集合思维。** 这时候我们停下来想：前面所有版本都在告诉模型"要小心、要多搜、要遵守规则"，但从来没人给模型一个**判断结构**——模型不知道"什么情况下算有答案、什么情况下算没有"，当然只能凭直觉。于是从判断入手：把问题拆成五个集合（Q 问题要求的谓词 / C 候选表达空间 / S 已搜表达 / A **语料中的断言**——命中且真正回答了 Q 的某部分 / M 仅提及未断言），配上两条硬判定规则：**答 ⟺ A⊇Q**（语料断言覆盖了问题要的一切才答）、**拒 ⟺ S⊇C 且 A∩Q=∅**（搜索空间覆盖完、语料断言与问题零交集才拒）。<br><br> 关键在这里：**A 不是"答案集合"，是"语料里的断言集合"** ——判定对象是"语料到底确立了没有"，不是"我手上有没有现成答案"。所以答 ⟺ A⊇Q 不是把答案放进集合再答，而是"语料真的断言了问题要的所有东西，才有资格答"。<br><br> **局面打开了。** v2.1 第一次双维度同时上涨（+3.5/+6.3）——direct 模式从零和变成正和，守手从崩溃线 16.7% 爬回 82.8%。从此一路加固：谓词分叉、断言门控、字段注入，最终 80.3%。<br><br> **这一路真正的转折不是某个规则，而是"从判断入手"这个视角**：与其告诉模型该怎么做，不如给模型一个可以判定的判断结构。这后来成了我们的总纲——固定状态。<br><br> <br> 一、方法论是怎么长出来的：总纲与实验设计<br><br> 上下文工程总纲的核心命题：**大模型有固定状态**（Help 倾向、讨好性、叙事直觉、证明欲），提示词的作用不是"讲道理"，而是把模型固定进一个可判定的认知状态；状态固定后，由智能体/机制层接管记忆状态。<br><br> R-E27 是这条总纲在提示词层最完整的一次长链实验：从 v1 到 v2.9.5，8 个大版本，把"模型自由发挥"逐步改造成"只认断言、只认信号、只认锚点"的固定状态机。<br><br> 三个阶段对应总纲三句话：<br><br>

- **状态成形（v1 → v2.1 集合思维）** ：把判断收敛成 Q/C/S/A/M 五集合判定。
- **状态加固（v2.5 谓词分叉 → v2.8 断言门控）** ：证据聚焦——只信断言，不信请求/提议/规则名。
- **状态特化（v2.8.3 → v2.9.5 字段注入）** ：固定态→记忆态——决策字段成为模型可读的"记忆锚点"。

<br> **实验设计**：上一个版本（R-E26）的机械检索 harness 偏科——守手暴涨 +38pp、有答案普遍 -6~-8pp，零和。于是拆掉机械执行循环，评测直接调 LLM API + 检索工具，让提示词认知循环由模型自己循环（direct 模式）。判断标准：守手 ≥75% 且有答案 ≥77%（不零和）。<br><br> **迭代方法**：每版打补丁 → 冒烟测试关键难例（5-6 题）→ 不合格再补 → 冒烟通过才全量评测。冒烟是质量门，全量是定版依据。<br><br> <br> 二、版本演进全记录（每版改了什么、为什么、效果如何）<br><br> 这一章是实验记录，用于支撑上面的方法论结论；想复现每一步的读者看这里。<br><br> <br><br> v0.4.4 基线（dsh 机械 harness）<br><br> 检索上限 3 次 + timeout 120s。守手 75.9%、有答案 77.1%。**偏科：守手弱**——机械循环救不了"该不该答"。<br><br> v1（DIRECT_LOOP_PROMPT 认知循环 v1）<br><br> 改为提示词自由循环。守手 79.3%、有答案 60.4%。**有答案崩**：自由给守手纪律让路，但多跳题需要的证据拼合能力没有被提示词救起来。<br><br> v2.1 集合思维（状态成形）<br><br> **改了什么**：把"模型凭直觉回答"改造成五集合判定——<br><br>

- Q = 问题要求的答案集合
- C = 问题语境
- S = 语料已确立事实
- A = 候选答案集
- M = 记忆/引用

<br> 判定规则：**答 ⟺ A⊇Q（候选集覆盖问题要求）；拒 ⟺ S⊇C 且 A∩Q=∅（语料确立事实覆盖语境但候选与要求无交集）** 。<br><br> **效果**：守手 82.8%、有答案 66.7%。v2.1 vs v1 是**双维度同时上涨**（+3.5/+6.3）——集合思维让 direct 模式从零和转正和。代价是更慢（单题 40-95s）。<br><br> **关键发现**：multi_hop 16 个错误里，误拒只 4 个、答错 11 个（69%）——守手纪律把误拒压下去了，缺口变成"搜到了选不对"。<br><br> v2.2 ~ v2.4（三轮不合格补丁，每轮修一个"程序只能算影子"的实例）<br><br>

- **v2.2**：S 引用纪律 + 同粒度 + 候选列举。冒烟 multi_hop_3/12 拒错、abstention_9 没修好 → 不合格。
- **v2.3**：gate evidence 标签去权威化 + 模态绑定问题谓词 + 候选谓词过滤。multi_hop_3/12 修好，但 abstention_4 回归坏 → 不合格。
- **v2.4**：决议 vs 提议判别 + 反确认搜索 + phase 非排除理由。abstention_4/9 修好，但 multi_hop_3 回归坏 → 不合格。

<br> **这条链揭示的根因**（每个都是"程序算不了语义只能算影子"的实例）：<br><br>

1. **gate 标签误导**：evidence 分级是关键词匹配强度，不是语义断言强度。模型信标签降级拒了 gold 断言 → 标签去权威化。
2. **模态未对齐**：计划语气 "Data Ops can stamp" 被当落实断言 → 模态绑定谓词。
3. **表面 declarative 的提议**："Compliance owns the exception log" 6 条全在提议方案语境（confirm by EOD / should chase confirmations），从未拍板 → 决议 vs 提议判别。
4. **确认性搜索偏差**：只确认已持候选、不搜互补空间 → 反确认搜索。

<br> v2.5 谓词分叉（状态加固第一刀）<br><br> **改了什么**：按**问题谓词模态**三分——<br><br>

- **PLANNED**：计划语言（"can/will stamp"）算断言
- **DEADLINE**：明确日期绑定（"by/cut-off"）就算
- **OWNER-STATUS**：决议归属，严格判定

- 反确认强制。

<br> **效果**：守手 86.2%（历史新高）、有答案 64.6%。**守手更强、有答案更弱**（差距 21.6pp）。<br><br> **错误结构分析**：<br><br>

- deadline 误拒是**搜索召回问题不是规则问题**——gold 日期在语料里存在但绑定弱，模型搜的词太泛，只返回 mention，没找到明确日期绑定就拒。
- 答错 11 个里 5 个是日期竞争题——语料多个日期、模型凭第一印象选中非 gold。
- 枚举类回归 3 个——问复数清单时，模型按 owner/status 严格规则处理导致不全/拒答。

<br> v2.6（ENUMERATION 段 + deadline 搜索纪律）<br><br> **改了什么**：<br><br>

- ENUMERATION 段：枚举找全——问复数清单必须找全所有值，不要求决议信号，但必须与问题谓词类别对齐。
- deadline 搜索纪律：强制"实体 + 日期格式/截止同义词"搜索（YYYY-MM-DD、July N、by/cut-off/deadline）。

<br> 冒烟通过，未单独全量。<br><br> v2.7（READ FULL HITS + COMPLEMENTARY-SPACE + DEFINITION REQUIRED）<br><br> **改了什么**：<br><br>

- READ FULL HITS：读全命中，不看前几个
- COMPLEMENTARY-SPACE：反确认搜索（搜互补空间，不只是确认已持候选）
- DEFINITION REQUIRED：规则名 ≠ 定义

<br> **效果**：守手 79.3%（-6.9）、有答案 79.2%（+14.6）。**守手被击穿**。<br><br> **4 个 abstention 新回归统一根因**：非断言表述被当事实——待办请求（"please codify 4pm UTC in the spec"）、规则名（"two-match rule" 不算计数断言）、生效表述（"locked from the 4pm UTC stamp today" 不是 stamp 日期断言）、搜索无果仍死搜（超时）。<br><br> v2.8 断言门控（状态加固核心，双维度首次同时历史最优）<br><br> **改了什么（三补丁）** ：<br><br>

1. **EFFECT-START IS NOT A DATE ASSERTION**：相对日期解析只适用于 DEADLINE 谓词（by/until/before/cut-off/due）；"locked from the 4pm UTC stamp today" 是**生效起始表述**——stamp 日期本身从未被命名 → 归 M（记忆），绝不当 A（答案）。
2. **ASSERTION GATE**：枚举只有当消息把 X 的形式当作**既成事实**才算断言（"the triggers are A, B, C"）；请求/提议语言不定 X；规则名不是数值断言。
3. **SEARCH CONVERGENCE**：BFS 搜完非平凡语料子集仍无断言答案 + 近期搜索只返回已见 M 段落 → 收敛拒答并引用 S；明确 DSH_TIMEOUT 算 Incorrect，带引用的拒答严格优于无限搜索。

<br> **补丁链（v2.8.1/2 修 MH_16 回归）** ：<br><br>

- **GATE SCOPE**：断言门控只适用于问"X 本身形式/定义/数值/日期"，不适用于问"谁被要求做 X"（ask 语言本身就是事实）。
- **ASK-SET COMPETITION**：不同消息命名不同团队集合时，直接 ask 集合（"Can Legal, Risk, and data governance confirm"）优先于后续执行步骤消息（"Legal posts the winning clause"）；执行步骤不缩小 ask 集合。

<br> **效果**：守手 86.2%、有答案 85.4%。**首次双维度同时历史最优，维度差距 0.8pp**（v2.5 时 21.6pp）。<br><br> **平衡本质**：断言门控（该收手）+ 搜索纪律（该多搜）不是零和，而是同一套"**只信断言、不信请求/提议/规则名**"原则在两个维度上的对称应用。<br><br> v2.8.3（REQUEST-TO-CODIFY + PENDING-TASK-LIST GATE）→ 其余 5 维度首跑<br><br> **动机**：v2.8 全量中 ABS_4/46 是采样波动（全量错、重跑 Correct）——根因是 prompt 两处未锁死的边界。<br><br> **改了什么**：<br><br>

1. **REQUEST-TO-CODIFY IS NOT A SPEC ASSERTION**（DEADLINE 段）："please codify/note 4pm UTC in the spec" 是请求写入，不是 "the spec sets 4pm UTC"——只有文档内容断言（"the spec sets/codifies X"、"we wrote X into the spec"）才算。治 ABS_46。
2. **PENDING-TASK-LIST GATE**（OWNER 段）："Data Ops to stamp today; Compliance owns the exception log; confirm by EOD" 是待办清单，里面的 declarative 子句不是决议——"owns" 是计划内分配，不是已确认事实。治 ABS_4。

<br> **效果**：ABS_4 ✅、ABS_46 ✅（波动消除）、MH_16 ✅（ASK-SET 无伤）——冒烟 3/3。<br><br> **其余 5 维度首跑（无历史基线）** ：temporal 80.0%（好）、temporal_rest 72.0%（中）、user_implicit 66.7%（中）、term_ambiguity 48.9%（差）、knowledge_update 46.9%（差）。<br><br> **核心发现：提示词覆盖有维度边界**——集合思维 + 谓词类型是 abstention/multi_hop 的甜点区（86.2%/85.4%），对其他维度适配分层：<br><br>

- temporal 沾光：DEADLINE 段的"相对日期解析 + 日期字面搜索纪律"直接适用。
- knowledge_update 缺**时效覆盖**规则（新旧信息竞争取最新）。
- term_ambiguity 缺**多义消解**规则（同一术语多语境、按问题语境取义项）——断言门控反而导致该答拒答/该拒答答。
- user_implicit 缺**人称映射**规则（"我标记的 blocker"需要先解析提问者身份再映射到语料用户角色）。

<br> 结论：不是集合方法论失效，是**谓词×维度矩阵缺行**——每个新维度需要各自的谓词规则，这为 v2.9 指明方向。<br><br> v2.8.3 跨领域泛化验证（244 题）<br><br> **动机**：担心 prompt 过拟合 Finance 评测集。同一 prompt 跑 GroupMemBench 其余 3 领域（Healthcare/Manufacturing/Technology）核心双维度。<br><br> **结果**：<br><br>

- 既成事实 vs 请求/计划/提议：只有消息把内容当作既定事实才算断言；
- 计划语言 vs 落实断言：模态要对齐问题谓词；
- 生效起始 vs 日期断言：相对日期只适用于 DEADLINE 谓词；
- 规则名 ≠ 数值断言；待办清单里的 declarative 子句不是决议。<br>"该收手"和"该多搜"是同一原则的两面，不是零和。

<br> **5. 收益有语料边界，跨领域验证是必做项（机制 vs 过拟合）。**<br>一套规则适配了某个语料的决策结构，不代表通用。Finance 内 +10.4pp、跨领域持平，双重证据说明成绩来自规则覆盖而非语料记忆——但这是验证出来的，不是猜出来的。每次定版前跑一次跨领域，用 abstention 类领域无关维度做"过拟合探针"。<br><br> **6. 边界要明说，不可判就不投入（锚点纪律）。**<br>评测任务里有一类题是语料生成 artifact 造成的不可判竞争（同日批量变体、时间戳同批），任何规则启发都碰不到预设 gold。这类题要判死、明说、不拟合——把规则预算花在可判题上。<br><br> <br> 五、下一步方向<br><br>
