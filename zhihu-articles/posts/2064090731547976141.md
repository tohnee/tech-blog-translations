这里是理解版，源码版在[Megatron-LM TP/SP Backward 源码解析：通信节点在哪里被创建，又在哪里执行？（源码版）](https://zhuanlan.zhihu.com/p/2064108530207137840)

Megatron-LM 的 Tensor Parallel 主要通过两种线性层实现：

```text
ColumnParallelLinear
RowParallelLinear
```

Column Parallel 将权重沿输出维切分，Row Parallel 将权重沿输入维切分。二者通常成对出现：

```text
ColumnParallelLinear
        ↓
中间的本地算子
        ↓
RowParallelLinear
```

开启 Sequence Parallel 后，这一对结构的通信可以概括为：

```text
Forward：
    1 次 All-Gather
    1 次 Reduce-Scatter

Backward：
    2 次 All-Gather
    1 次 Reduce-Scatter
```

Backward 中的三次通信并不是全部串行执行。其中 Column backward 内部存在两组计算通信重叠：

```text
All-Gather 输入
    ||
Column dgrad GEMM

Reduce-Scatter dX
    ||
Column wgrad GEMM
```

本文按照真实执行顺序展开：

```text
Forward：Column → Row

Backward：Row → Column
```

重点说明：

- 行并行和列并行如何切分矩阵；
- 通信具体发生在哪个位置；
- backward 中三次通信分别属于哪个 autograd 节点；
- Megatron 源码如何使用异步 collective 实现 overlap。

## 1. Forward

```text
S：sequence length
B：batch size
H：hidden size
F：中间特征维
P：tensor parallel size
```

Sequence Parallel 下，输入沿 sequence 维切分：

```text
X_sp [S/P, B, H]
```

完整 forward 为：

```text
X_sp [S/P,B,H]
    |
    | Column Parallel
    | ① All-Gather sequence
    v
X_full [S,B,H]
    |
    | Column GEMM
    v
Z_local [S,B,F/P]
    |
    | 中间本地算子
    v
A_local [S,B,F/P]
    |
    | Row GEMM
    v
Y_partial [S,B,H]
    |
    | ② Reduce-Scatter sequence
    v
Y_sp [S/P,B,H]
```

这里正好体现了 Column Parallel 和 Row Parallel 的对偶关系。

### 1.1 Column Parallel：切输出维

Column Parallel 的完整权重为：

```text
W_col [H,F]
```

沿输出维 `F` 切分：

```text
W_col = [W₀, W₁, ..., Wₚ₋₁]
```

每个 TP rank 保存：

```text
W_col_local [H,F/P]
```

因此每个 rank 计算不同的输出特征：

```text
Z_local = X_full W_col_local
```

形状为：

```text
[S,B,H] @ [H,F/P]
    =
[S,B,F/P]
```

不同 rank 得到的是不同输出分片：

```text
rank 0：Z₀ [S,B,F/P]
rank 1：Z₁ [S,B,F/P]
...
```

这些分片不需要求和。

但开启 Sequence Parallel 后，Column 收到的输入只有：

```text
X_sp [S/P,B,H]
```

所以在 GEMM 前，需要先恢复完整 sequence：

```text
X_sp
  |
  | All-Gather
  v
X_full
```

Column forward 的关键逻辑可以概括为：

```text
if sequence_parallel:
    total_input = all_gather(input)
else:
    total_input = input

output = total_input @ weight.T
```

同时，自定义 Linear 保存的是原始输入：

```text
ctx.save_for_backward(input, weight)
```

这里的 `input` 仍然是：

```text
X_sp [S/P,B,H]
```

而不是临时 Gather 出来的 `X_full`。

这点会直接影响后面的 Column backward：为了计算权重梯度，backward 需要再次把保存的 `X_sp` All-Gather 成完整 sequence。

```text
ctx.save_for_backward(input, weight)

if sequence_parallel:
    total_input = gather_from_sequence_parallel_region(
        input,
        ...
    )
else:
    total_input = input
```

### 1.2 Row Parallel：切输入维

经过 Column 和中间本地算子后，每个 rank 拥有：

```text
A_local [S,B,F/P]
```

Row Parallel 的完整权重为：

```text
W_row [F,H]
```

沿输入维 `F` 切分：

```text
W_row =
[
    W₀
    W₁
    ...
]
```

每个 rank 保存：

```text
W_row_local [F/P,H]
```

本地 GEMM 为：

```text
Y_partial =
    A_local W_row_local
```

形状为：

```text
[S,B,F/P] @ [F/P,H]
    =
[S,B,H]
```

与 Column 不同，不同 rank 的 `Y_partial` 不是不同输出分片，而是同一个输出的部分和：

```text
Y =
    Y_partial₀
  + Y_partial₁
  + ...
```

不开 Sequence Parallel 时，这里需要 All-Reduce。

开启 Sequence Parallel 后，不需要让每个 rank 都保存完整 sequence 输出，而是将“跨 rank 求和”和“沿 sequence 切分”合并成一次Reduce-Scatter：

```text
Y_partial [S,B,H]
    |
    | Reduce-Scatter
    v
Y_sp [S/P,B,H]
```

这里有一个容易混淆的细节：

> Row 的 Sequence Parallel 处理发生在本地 GEMM 之后，而不是发生在 Linear 自定义算子内部。

Row 调用本地 Linear 时，输入已经是：

```text
A_local [S,B,F/P]
```

sequence 维是完整的，因此传入：

```text
sequence_parallel=False
```

然后由 `RowParallelLinear` 在 GEMM 外部执行 Reduce-Scatter。

```text
output_parallel = self._forward_impl(
    input=input_parallel,
    weight=weight,
    sequence_parallel=False,
    ...
)

if self.sequence_parallel:
    output_ = reduce_scatter_to_sequence_parallel_region(
        output_parallel,
        group=self.tp_group,
    )
else:
    output_ = reduce_from_tensor_model_parallel_region(
        output_parallel,
        group=self.tp_group,
    )
```

至此前向通信为：

```text
Column forward：
    1 × All-Gather

Row forward：
    1 × Reduce-Scatter
```

## 2. Backward

Forward 是：

```text
Column → 本地算子 → Row
```

所以 backward 按相反方向执行：

```text
Row backward
    ↓
本地算子 backward
    ↓
Column backward
```

完整调用链为：

```text
dY_sp [S/P,B,H]
    |
    | ① Row 输出 RS 的 backward
    |    All-Gather
    v
dY_full [S,B,H]
    |
    | Row dgrad
    | Row wgrad
    | 无 TP 通信
    v
dA_local [S,B,F/P]
    |
    | 中间本地算子 backward
    v
dZ_local [S,B,F/P]
    |
    | ② Column backward All-Gather X_sp
    |    与 Column dgrad 重叠
    v
dX_partial [S,B,H]
    |
    | ③ Column backward Reduce-Scatter dX
    |    与 Column wgrad 重叠
    v
dX_sp [S/P,B,H]
```

下面按这个顺序展开。

### 2.1 先执行 Row backward

Row forward 的最后一个操作是：

```text
Reduce-Scatter
```

因此 backward 首先执行其反向操作：

```text
All-Gather
```

**第一次 All-Gather：恢复完整 dY**

进入 backward 的梯度是：

```text
dY_sp [S/P,B,H]
```

执行：

```text
dY_sp
  |
  | All-Gather sequence
  v
dY_full [S,B,H]
```

这次通信并不属于 Row Linear 自定义算子本身，而属于 Row 输出端那个 Reduce-Scatter autograd 节点：

```text
_ReduceScatterToSequenceParallelRegion.backward
```

其逻辑是：

```text
@staticmethod
def backward(ctx, grad_output):
    return (
        _gather_along_first_dim(
            grad_output,
            ctx.group,
            ...
        ),
        None,
        None,
        None,
    )
```

**计算Row dgrad 和 wgrad**

得到完整：

```text
dY_full [S,B,H]
```

后，Row Linear 执行两个本地 GEMM。先定义普通线性层：

```text
Y = XW
```

backward 中：

```text
dgrad：
    dX = dY Wᵀ

wgrad：
    dW = Xᵀ dY
```

Megatron 源码中通常对应：

```text
grad_input   # dgrad
grad_weight  # wgrad
```

对于 Row Parallel，当前 rank 拥有：

```text
A_local       [S,B,F/P]
W_row_local   [F/P,H]
dY_full       [S,B,H]
```

Row dgrad 为：

```text
dA_local =
    dY_full W_row_localᵀ
```

形状：

```text
[S,B,H] @ [H,F/P]
    =
[S,B,F/P]
```

不同 rank 得到的是不同输入特征分片：

```text
rank 0：dA₀
rank 1：dA₁
...
```

它们不需要求和。Row wgrad 为：

```text
dW_row_local =
    A_localᵀ dY_full
```

将 token 维展平后：

```text
A_local       [SB,F/P]
dY_full       [SB,H]
```

因此：

```text
[F/P,SB] @ [SB,H]
    =
[F/P,H]
```

结果正好对应当前 rank 的权重分片。所以 Row Linear backward 内部没有额外 TP 通信：

```text
All-Gather dY
    ↓
Row dgrad
    ↓
Row wgrad
```

其中第一次 All-Gather 很难用普通 bulk overlap 隐藏，因为 Row dgrad 和 Row wgrad 都依赖完整的 `dY_full`：

```text
AG1 必须完成
    ↓
Row GEMM 才能开始
```

### 2.2 然后执行 Column backward

中间本地算子的 backward 完成后，Column 收到：

```text
dZ_local [S,B,F/P]
```

Column backward 需要计算：

```text
dX
dW_col_local
```

当前 rank 拥有：

```text
dZ_local       [S,B,F/P]
W_col_local    [H,F/P]
保存的 X_sp    [S/P,B,H]
```

这里会发生第二次 All-Gather 和一次 Reduce-Scatter，并形成两组 overlap。

**第二次 All-Gather：为 Column wgrad 恢复输入**

Column 权重梯度为：

```text
dW_col_local =
    X_fullᵀ dZ_local
```

`dZ_local` 已经覆盖完整 sequence：

```text
dZ_local [S,B,F/P]
```

但前向保存的输入只有：

```text
X_sp [S/P,B,H]
```

因此 backward 需要重新执行：

```text
X_sp
  |
  | All-Gather
  v
X_full [S,B,H]
```

注意，这次 All-Gather 的目的不是计算 dgrad，而是为 wgrad 准备完整输入。

**All-Gather 与 Column dgrad 重叠**

Column dgrad 为：

```text
dX_partial =
    dZ_local W_col_localᵀ
```

形状：

```text
[S,B,F/P] @ [F/P,H]
    =
[S,B,H]
```

这个 GEMM 只依赖：

```text
dZ_local
W_col_local
```

并不依赖正在 Gather 的 `X_full`。因此 Megatron 可以：

```text
一边 All-Gather X_sp
一边计算 Column dgrad
```

源码中的关键顺序是：

```text
handle = dist_all_gather_func(
    all_gather_buffer,
    input,
    group=tp_group,
    async_op=True,
)

grad_input = grad_output.matmul(weight)

handle.wait()
```

其中：

```text
input       = 保存的 X_sp
grad_input  = dX_partial
```

代码逻辑是：

```text
1. 异步启动 All-Gather
2. 立即执行不依赖 Gather 结果的 dgrad GEMM
3. 在真正使用 X_full 计算 wgrad 前等待
```

理想耗时约为：

```text
max(
    T_AllGather,
    T_Column_dgrad
)
```

而不是：

```text
T_AllGather + T_Column_dgrad
```

如果 dgrad GEMM 更长，All-Gather 可以被完全隐藏。

**Reduce-Scatter：汇总 Column dX**

每个 TP rank 计算出的：

```text
dX_partial [S,B,H]
```

只是完整输入梯度的一部分贡献。因为 Column 权重按输出维切分：

```text
rank 0：
    dX_partial₀ = dZ₀ W₀ᵀ

rank 1：
    dX_partial₁ = dZ₁ W₁ᵀ
```

完整输入梯度为：

```text
dX =
    dX_partial₀
  + dX_partial₁
  + ...
```

不开 Sequence Parallel 时，这里通常需要 All-Reduce。开启 Sequence Parallel 后，最终要返回：

```text
dX_sp [S/P,B,H]
```

因此 Megatron 使用 Reduce-Scatter，将两步合并：

```text
1. 对不同 TP rank 的 dX_partial 求和
2. 沿 sequence 维切分
```

形状变化为：

```text
dX_partial [S,B,H]
    |
    | Reduce-Scatter
    v
dX_sp [S/P,B,H]
```

**Reduce-Scatter 与 Column wgrad 重叠**

在前一阶段结束后，已经同时得到：

```text
X_full
dX_partial
```

此时可以异步启动 Reduce-Scatter：

```text
handle = dist_reduce_scatter_func(
    sub_grad_input,
    grad_input,
    group=tp_group,
    async_op=True,
)
```

然后计算 Column wgrad：

```text
dW_col_local =
    X_fullᵀ dZ_local
```

两者的数据依赖不同：

```text
Reduce-Scatter 使用：
    dX_partial

wgrad 使用：
    X_full
    dZ_local
```

所以可以并行执行。源码逻辑可以概括为：

```text
handle = async_reduce_scatter(grad_input)

grad_weight = compute_wgrad(
    total_input,
    grad_output,
)

handle.wait()
```

理想耗时约为：

```text
max(
    T_ReduceScatter,
    T_Column_wgrad
)
```

因此整个 Column backward 可以压缩为：

```text
AG(X_sp) || dgrad
        ↓
RS(dX)   || wgrad
```

## 3. 完整 Forward 和 Backward

现在把整条链重新放在一起。

**Forward**

```text
X_sp [S/P,B,H]
    |
    | Column All-Gather
    v
X_full [S,B,H]
    |
    | Column GEMM
    v
Z_local [S,B,F/P]
    |
    | local op
    v
A_local [S,B,F/P]
    |
    | Row GEMM
    v
Y_partial [S,B,H]
    |
    | Row Reduce-Scatter
    v
Y_sp [S/P,B,H]
```

Forward 通信：

```text
1 × All-Gather
1 × Reduce-Scatter
```

**Backward**

```text
dY_sp [S/P,B,H]
    |
    | AG1：Row 输出 RS 的 backward
    v
dY_full [S,B,H]
    |
    | Row dgrad
    | Row wgrad
    v
dA_local [S,B,F/P]
    |
    | local backward
    v
dZ_local [S,B,F/P]
    |
    | AG2：恢复 X_sp
    |      与 Column dgrad 重叠
    v
dX_partial [S,B,H]
    |
    | RS：汇总并切分 dX
    |     与 Column wgrad 重叠
    v
dX_sp [S/P,B,H]
```

Backward 通信：

```text
2 × All-Gather
1 × Reduce-Scatter
```

三次通信分别属于：

| 通信 | 所属位置 | 作用 |
| --- | --- | --- |
| All-Gather 1 | Row 输出 Reduce-Scatter 的 backward | 恢复完整 dY |
| All-Gather 2 | Column Linear backward | 恢复保存的 X_sp，用于 wgrad |
| Reduce-Scatter | Column Linear backward | 汇总各 rank 的局部 dX，并恢复 SP 布局 |

忽略中间本地算子的耗时，backward 的执行顺序为：

```text
AG1
    ↓
Row dgrad
    ↓
Row wgrad
    ↓
AG2 || Column dgrad
    ↓
RS  || Column wgrad
```

理想化耗时可以写成：

```text
T_backward ≈
    T_AG1
  + T_Row_dgrad
  + T_Row_wgrad
  + max(T_AG2, T_Column_dgrad)
  + max(T_RS, T_Column_wgrad)
```

其中：

```text
AG1：
    Row GEMM 直接依赖通信结果，
    普通 bulk overlap 很难隐藏。

AG2：
    可以被 Column dgrad 隐藏。

RS：
    可以被 Column wgrad 隐藏。
```

## 4. 源码如何实现 overlap

Megatron 的这两组 overlap 并不依赖复杂调度器，核心模式只有三步：

```text
1. 使用 async_op=True 启动 collective
2. 执行不依赖通信结果的 GEMM
3. 在真正需要通信结果前 handle.wait()
```

第一组：

```text
handle = async_all_gather(saved_input)

grad_input = grad_output.matmul(weight)

handle.wait()
```

对应：

```text
All-Gather saved input
        ||
dgrad GEMM
```

第二组：

```text
handle = async_reduce_scatter(grad_input)

grad_weight = compute_wgrad(total_input, grad_output)

handle.wait()
```

对应：

```text
Reduce-Scatter dX
        ||
wgrad GEMM
```

最重要的不是 `async_op=True` 本身，而是handle.wait() 被推迟到了真正存在数据依赖的位置。如果异步发起通信后立刻等待：

```text
handle = async_all_gather(...)
handle.wait()

grad_input = ...
```

那么逻辑上虽然使用了异步 API，但实际上并没有 overlap。

### 4.1 为什么要设置 CUDA_DEVICE_MAX_CONNECTIONS=1？

代码调用顺序虽然是：

```text
collective
GEMM
```

但 `async_op=True` 只表示 CPU 不阻塞，并不自动保证 GPU 一定先调度 NCCL collective。Megatron 希望设备侧执行顺序为：

```text
先调度通信 kernel
再调度 GEMM kernel
```

因此源码通常建议设置：

```text
export CUDA_DEVICE_MAX_CONNECTIONS=1
```

这个设置主要影响性能调度，而不是计算正确性。另外，时间线上出现通信和 GEMM 重叠，也不代表通信完全免费。NCCL 和 GEMM 仍可能争用：SM 、HBM 、带宽、 NVLink / NVSwitch、 PCIe、 跨节点网络。所以在 Nsight Systems 中可能看到两个 kernel 同时运行，但 GEMM 本身的时间也可能比单独执行时更长。

### 4.2 Bulk overlap 与 Pipelined overlap

本文主要分析的是 Megatron Linear backward 中直接可见的 bulk overlap：

```text
完整 AG || 完整 dgrad
完整 RS || 完整 wgrad
```

对于 Row backward：

```text
AG1
  ↓
Row GEMM
```

二者存在直接数据依赖，因此普通 bulk overlap 无法隐藏 AG1。更进一步的 Transformer Engine TP communication overlap，可以把张量切成多个 chunk：

```text
Gather chunk 0
    ↓
GEMM chunk 0

Gather chunk 1
    ↓
GEMM chunk 1
```

这种方式属于 pipelined overlap。但从理解 Megatron 原生行列并行 backward 的角度，先掌握下面两组 overlap ：

```text
AG || dgrad
RS || wgrad
```

## 5. 总结

Megatron 的行并行和列并行应该放在同一条执行链上理解。

Forward：

```text
Column：
    SP 输入先 All-Gather
    再执行 Column GEMM

Row：
    先执行 Row GEMM
    再对输出 Reduce-Scatter
```

Backward 按相反顺序执行：

```text
Row：
    先对输出梯度 All-Gather
    再执行本地 dgrad 和 wgrad

Column：
    All-Gather 保存的输入
        ||
    dgrad GEMM

    Reduce-Scatter dX
        ||
    wgrad GEMM
```

在 Sequence Parallel 下的通信数量为：

```text
Forward：
    1 AG + 1 RS

Backward：
    2 AG + 1 RS
```

完整 backward 调用链可以压缩为：

```text
Row 输出 RS backward
    → All-Gather 1
    → Row dgrad
    → Row wgrad

Column backward
    → All-Gather 2 async
    → Column dgrad
    → wait AG
    → Reduce-Scatter async
    → Column wgrad
    → wait RS
```
