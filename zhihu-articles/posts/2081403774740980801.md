今天，**DeepSeek-V4.1-Flash** 正式发布，并具备原生多模态视觉理解能力。如下图所示，相比 DeepSeek-V4-Flash，新模型最核心的升级是：**Prefill 阶段计算量接近减半，Global KV Cache 降至原来的约 $1/4$**，从而显著降低长上下文和 Agent 场景的推理成本。

![](https://pic2.zhimg.com/v2-4dbaf72d1506d50fc5441e8b20cae013_r.jpg)

DeepSeek-V4.1-Flash 是一款拥有 **552B 主干参数**的 MoE 模型。其引入的 **Causal Encoder-Decoder（CED）** 采用非对称计算方式：大部分 Prompt Token 在 Prefill 时主要经过前半部分网络，使每个 Token 的激活参数量从 Decode 阶段的 16B 降至 8B，Prefill 计算量因此接近减半。

与此同时，**CSA2** 通过跨层复用 Main KV、Indexer K 和 Top-K 选择结果，减少重复缓存与索引计算；配合 **FP4 Main KV Cache**，将 Global KV Cache 从 **3514 Bytes/token** 压缩至 **890 Bytes/token**，约为原来的 $1/4$。此外，**Engram** 将知识记忆与主干计算解耦，以较低的激活开销扩展模型的知识容量。

概括来说：**CED 降低 Prefill 计算，CSA2 与 FP4 压缩 KV Cache，Engram 高效扩展知识容量**。这些架构优化共同提升了模型在复杂推理、软件工程和长程 Agent 任务中的效率与能力。

![](https://pic3.zhimg.com/v2-019a1f841273875611a68df21ac4d0d8_r.jpg)
*图1: DeepSeek-v4.1-Flash Kv Cache 大幅降低，性能持续提升*

## 一、背景

随着Agent能力不断增强，模型需要处理的上下文越来越长。

一次复杂的软件工程任务，可能包含数百次工具调用、几十万Token的终端输出和完整代码仓库。Deep Research、GUI Agent 和企业工作流同样需要模型持续保存并利用长时间交互历史。

传统Decoder-only Transformer在这种场景下面临两项主要成本。

**第一是 Prefill 计算**。

模型有 $L$ 层、Prompt 长度为 $N$ 时，每一层都要处理完整 Prompt，主要计算复杂度约为：

$$ O(NL) $$

**第二是 KV Cache**。

传统模型通常为每一层保存独立 KV。随着上下文增长，KV Cache 会持续占用 GPU HBM，并在多轮会话中产生Host Memory、SSD 与网络传输开销。

DeepSeek-V4.1-Flash 的设计目标，就是同时压缩：

- 每个 KV Entry 的大小；
- 真正参与注意力的历史位置数量；
- 不同 Transformer 层之间重复保存的 KV；
- Prefill 阶段实际需要完整执行的网络层数。

最终模型支持最长 1M Tokens 上下文。报告称，其常驻 GPU HBM 中的全局 KV Cache 约为：

$$ 890\ \text{Bytes/Token} $$

这大约是 DeepSeek-V4-Flash 的四分之一。结合 SWA Bounded Replay 后，持久化 KV Cache 进一步降低到上一代的约八分之一。

更直观的变化体现在单Token解码计算量上。

![](https://pica.zhimg.com/v2-56d156acbe32f84b93b1cf892e45a8fe_r.jpg)
*图2: DeepSeek-v4.1-Flash 单 token 解码计算量*

上下文从 4K 增加到 1M，相当于长度扩大 256 倍，但 DeepSeek-V4.1-Flash 的单 Token Decode FLOPs 只增加约 25%。

这并不意味着端到端延迟只增加 25%，因为实际延迟还受到 KV 读取、跨卡通信、Kernel 效率和 Batch 调度影响。但它说明，模型核心解码计算已经不再随上下文长度快速线性增长。

### 2.2 CED：因果编码器—解码器 （Causal Encoder-Decoder）

![](https://pic4.zhimg.com/v2-1cbe13f166c8ac68e868844acaeb0865_r.jpg)
*图4：CED 结构*

CED 的目标是减少长 Prompt 的 Prefill 计算。

**2.2.1 为什么 Prefill 计算量接近减半？**

Prefill 阶段的主要任务，是一次性读取整个 Prompt，建立后续 Decode 所需的内部表示和 KV Cache，并计算出第一个输出 Token 的概率分布。

$$ \text{Prompt} \xrightarrow{\text{Prefill}} \begin{cases} \text{建立历史 KV Cache}\\ \text{得到第一个输出 Token} \end{cases} \xrightarrow{\text{Decode}} y_2,y_3,\ldots $$

假设 Prompt 长度为 $N$。

**传统 40 层模型**

每个 Prompt Token 都要经过全部 40 层：

$$ X\rightarrow H^1\rightarrow H^2\rightarrow\cdots\rightarrow H^{40} $$

并且第 $l$ 层通常根据本层输入隐状态生成自己的 KV：

$$ K^l=H^{l-1}W_K^l,\qquad V^l=H^{l-1}W_V^l $$

因此，对一个长度为 $N$ 的 Prompt，40 层都要处理这 $N$ 个 Token。

$$ \text{Cost}_{\text{normal}}\approx N\times L $$

当 $L=40$ 时：

$$ \text{Cost}_{\text{normal}}\approx 40N $$

**CED**

DeepSeek-V4.1-Flash 把 40 层拆成两部分：

- 第 1～20 层：Causal Encoder
- 第 21～40 层：Decoder

CED 最重要的变化是：Decoder 的 Global KV 不再由 Decoder 各层自己的隐状态生成，而是统一由 Encoder 最后一层输出 $H^{20}$ 投影得到。

论文公式为：

$$ C^l=H^{L/2}W_{KV}^{l}, \qquad Z^l=H^{L/2}W_Z^{l}, \qquad l>\frac{L}{2} $$

在该模型中 $L=40$，因此：

$$ C^l=H^{20}W_{KV}^{l}, \qquad Z^l=H^{20}W_Z^{l}, \qquad l=21,\ldots,40 $$

其中：

- $H^{20}$：Prompt 经过 20 层 Encoder 后的表示；
- $C^l$：为第 $l$ 个 Decoder 层构造的压缩 Global KV；
- $Z^l$：对应的压缩权重；
- $W_{KV}^{l}$、$W_Z^l$：每个 Decoder 层各自独立的投影参数。

注意，虽然所有 Decoder 层都使用同一份 $H^{20}$，但投影矩阵不同，所以不同 Decoder 层得到的 KV 仍然不同：

$$ C^{21}=H^{20}W_{KV}^{21} $$

$$ C^{22}=H^{20}W_{KV}^{22} $$

它并不是让 20 个 Decoder 层共享完全相同的 KV 内容，而是共享同一个 KV 来源。

因此，全量 Prompt 只需要通过前 20 层 Encoder：

$$ N\times\frac{L}{2} $$

然后根据 $H^{20}$ 直接投影出 Decoder 所需的 Global KV，不必让全部 $N$ 个 Token 再完整跑过 20 层 Decoder。

计算复杂度变成：

$$ \text{Cost}_{\text{CED}} = O\left( N\frac{L}{2} \right) $$

注意，这还不是最终复杂度，因为 Prefill 阶段除了生成 KV Cache，还需要生成第一个 Token。

对于 Prompt 末尾的窗口 Token 位置：

$$ N-n_{\text{win}}+1,\ldots,N $$ 这些 Token 除了经过 Encoder，还需要执行 Decoder SWA Bounded Replay，以构建 Decoder 各层的局部 SWA KV。

因此，最后一个 Prompt Token $x_N$ 会经过完整的：

$$ 20\text{层 Encoder}+20\text{层 Decoder} $$

它在第40层得到最终隐状态：

$$ H_N^{40} $$

再经过 LM Head：

$$ \text{logits}_{N+1} = W_{\text{LM}}H_N^{40} $$

最终采样出第一个回答 Token：

$$ y_1 \sim \operatorname{Softmax}(\text{logits}_{N+1}) $$

所以，第一个输出 Token 不是直接根据 $H_N^{20}$ 生成的，而是根据最后一个 Prompt 位置经过 Decoder 后的 $H_N^{40}$ 生成的。

因此，考虑尾部 Prompt 需要经过完整 40 层，那么最终的复杂度为：

$$ \text{Cost}_{\text{CED}} = O\left( N\frac{L}{2} + n_{\text{win}}\frac{L}{2} \right) $$ 当长上下文满足：

$$ N\gg n_{\text{win}} $$

就有：

$$ O\left( N\frac{L}{2} + n_{\text{win}}\frac{L}{2} \right) \approx O\left(N\frac{L}{2}\right) $$

相对于原来的：

$$ O(NL) $$

大约减少一半。

**2.2.2 Decode 阶段的计算量也会减半吗？**

不会。

在 Decode 阶段，生成一个新 Token 时，这个 Token 首先进入 Causal Encoder：

$$ x_t \rightarrow H_t^1 \rightarrow\cdots \rightarrow H_t^{20} $$

然后根据 $H_t^{20}$ 生成 Decoder 各层需要追加的 Global KV：

$$ C_t^l=H_t^{20}W_{KV}^l $$

接着，这个 Token 还需要依次通过第 21～40 层 Decoder，得到最终输出：

$$ H_t^{20} \rightarrow H_t^{21} \rightarrow\cdots \rightarrow H_t^{40} \rightarrow \text{Logits} $$

所以单个生成 Token 仍然要执行：

$$ 20\text{层 Encoder}+20\text{层 Decoder} $$

也就是完整的 40 层前向计算。

这也与论文给出的激活参数量一致：

- Prefill：每个 Prompt Token 平均激活约 8B 参数；
- Decode：每个生成 Token 激活约 16B 参数。

因此，CED 并没有让 Decode 计算量也减半。

> CED 将长 Prompt 的主要计算限制在 20 层 Encoder 中，从而近乎减半 Prefill 计算；但逐 Token Decode 仍执行完整的 Encoder 和 Decoder，CED 本身并不将 Decode 主干计算减半。

### 2.3 CSA2：压缩稀疏注意力

关于 CSA 的原理，可以参考：

[百万 token 上下文 + 开源 SOTA！DeepSeek-V4 技术全拆解](https://zhuanlan.zhihu.com/p/2033630981232535012)

CSA² 从三个维度降低长上下文注意力成本：

- **Entry 维度**：将多头 KV 压缩为低维 KV Latent，减小单个 KV Entry。
- **Sequence 维度**：每 $m$ 个 Token 压缩成一个 Main KV Entry，减少缓存数量。
- **Layer 维度**：跨层共享 Main KV、Indexer Key 和 Top-K 索引，避免每层保存独立缓存。

需要注意，**Top-K 稀疏选择主要降低注意力计算量**；Sequence 维度的存储压缩主要来自每 $m$ 个 Token 合并为一个 Main KV Entry。

每个 CSA² 层仍然计算自己的 Main Query 和 SWA KV，但 Global Attention 使用的 Main KV、Indexer Key 和 Top-K 索引可以跨层共享。

![](https://pic3.zhimg.com/v2-cd3373a2634102343796f3860c01841c_r.jpg)
*图5：CSA2架构*

**Full模式：生成完整 Global KV**

Full 层执行完整的 CSA² 计算路径：

- 生成 Main KV；
- 生成当前层的 Indexer Query；
- 从 Main KV 投影 Indexer Key；
- 扫描完整可见上下文；
- 生成新的 Top-K 索引。

因此，Full 层既创建 Global KV Cache，也执行完整的稀疏索引。

**Reindex模式：复用 KV，重新选择 Top-K**

Reindex 层复用前面 Full 层生成的 Main KV 和 Indexer Key，但使用自己的 Indexer Query 重新计算 Top-K：

$$ I_l=\operatorname{TopK}\left(Q_{\text{index}}^lK_{\text{index}}^\top\right) $$

由于不同层的 Indexer Query 不同，各个 Reindex 层仍然可以关注不同的上下文位置，同时不需要生成和保存新的 Main KV。

**Reuse Mode：同时复用 KV 与 Top-K**

Reuse 层同时复用：

- Main KV；
- Indexer Key；
- 最近一次由 Full 或 Reindex 层生成的 Top-K 索引。

它不再运行 Indexer，而是直接读取已有 Top-K 位置的 Main KV 并执行稀疏注意力。因此，Reuse Mode 同时减少了 KV Cache 存储、索引计算和推理延迟。

**CED 与 CSA² 如何结合**

如果只考虑 CED，每个 Decoder 层都可以基于 Encoder 最后一层的隐藏状态，通过各自的投影矩阵生成不同的 Main KV：

$$ C^l=H_{L/2}W_l^{KV} $$

但结合 CSA² 后，只有 Full Mode 层真正执行这一步。Reindex 和 Reuse 层直接复用 Full 层生成的 Main KV。

DeepSeek-V4.1-Flash 的20个 Decoder 层中，只有第一个 CSA² 层采用 Full Mode：

- 第一个 Decoder 层从 Encoder 第20层的隐藏状态生成 Main KV；
- 后续4个 Reindex 层复用这份 Main KV，但重新选择 Top-K；
- 其余15个 Reuse 层同时复用 Main KV 和最近的 Top-K。

因此，Decoder 的20层只需要保存一份 Global Main KV。不过，每层仍然拥有自己的 Main Query 和 SWA KV，所以各层的注意力输出并不相同。

**相比上一代 CSA 的简化**

CSA² 还进行了以下简化：

- 删除相邻压缩窗口之间的重叠；
- 删除压缩阶段的绝对位置编码；
- 直接从 Main KV 投影 Indexer Key；
- 将 Main KV 共享与 Top-K 索引复用解耦。

这种解耦设计使 Reindex 层能够共享同一份 Main KV，同时根据本层 Query 重新选择关注位置，在缓存效率和逐层表达能力之间取得平衡。

### 2.4 Hierarchical Sparse Indexer：分层稀疏索引器

![](https://pic1.zhimg.com/v2-7f7d2c4d8923532d0ad0ea3de2008d06_r.jpg)
*图6: 分层稀疏索引*

即使采用稀疏注意力，如果每个 Indexer 仍然扫描全部 100万 Token，索引本身也会成为瓶颈。

因此，Decoder 中的第一个 Full 层首先扫描所有可见位置，并同时构建一个较大的候选池。

论文的默认配置为：

$$ 2048\ \text{Blocks} \times 8\ \text{Positions/Block} = 16384\ \text{Candidate Positions} $$

第一个 Full 层会：

- 从完整上下文中选出自己的 Top-512；
- 对每个 Block 取最大 Indexer Score；
- 选出得分最高的 2048 个 Block；
- 将其中 16,384 个位置组成共享候选池。

后续 Reindex 层只在 16,384 个候选位置中打分，再选出本层 Top-512。Reuse 层则不再执行索引。

对于固定候选池，后续 Indexer 每次需要打分的位置数量不再随上下文增长，其计算复杂度由对上下文长度的线性增长变成近似常数。

## 三、高效实现

### 3.1 **Single-Pass mHC**

关于 mHC 原理可以参考：

[残差连接十年新突破！一文吃透 DeepSeek mHC 核心技术](https://zhuanlan.zhihu.com/p/2032501763199214881)

DeepSeek-V4的 mHC 在相邻 Block 之间维护 $n$ 条残差流：

$$ X_{l+1} = B_lX_l+C_lF_l(A_lX_l), \qquad (A_l,B_l,C_l)=\mathcal H(X_l) \tag{2} $$

其中 $A_l$ 负责将多条残差流混合为当前Block输入，$B_l$ 和 $C_l$ 控制残差状态更新。

原始实现必须先根据 $X_l$ 计算出 $A_l$，才能执行输入混合，导致多个 Kernel 重复读取残差状态。

Single-Pass mHC 将输入混合系数向前平移一个 Block：

$$ X_{l+1} = B_lX_l+C_lF_l(A_{l-1}X_l), \qquad (A_l,B_l,C_l)=\mathcal H(X_l) \tag{6} $$

当前 Block 使用上一层已经计算好的 $A_{l-1}$，从而解除输入混合与系数预测之间的数据依赖。

DeepSeek 据此将残差更新、输入混合、系数预测、Pre-Norm 和 FP8 转换融合到 Mega-mHC Kernel中。

原始 mHC 的激活内存流量约为：

$$ (4n+4)d $$

Single-Pass mHC 降低为：

$$ (2n+2)d $$

达到理论读写下界，激活内存流量约下降一半。

### 3.2 Engram

Engram的核心思想可以概括为：

> 对于固定短语、实体名称、代码模式等高度重复的局部知识，没有必要让Transformer每次都通过多层Attention和MoE重新推导，可以直接根据最近几个Token去一个巨大的可训练Embedding Table中查询。

它是一种 Conditional Memory，与 MoE 形成互补：

- MoE 是 Conditional Computation：根据隐藏状态选择少数专家进行动态计算；
- Engram 是 Conditional Memory：根据 Token 组成的 N-gram，直接查出少数记忆向量。

Engram 不是 RAG，不会访问外部文档；也不是训练后的静态词典。它是模型内部参与端到端训练的超大规模参数化记忆表。

DeepSeek-V4.1-Flash 配置了 196B Engram 参数，但每个 Token 只查询极少数 Embedding，因此参数量增加很多，计算量却几乎不随记忆表规模增长。

Engram 来自 DeepSeek 此前的论文[《Conditional Memory via Scalable Lookup》](https://arxiv.org/abs/2601.07372)，DeepSeek-V4.1-Flash 在此基础上做了进一步调整。

**1. 为什么 Transformer 需要 Engram？**

标准 Transformer 只有两种主要知识处理方式：

- Attention：从上下文中动态查找信息；
- FFN/MoE：通过参数计算恢复知识。

例如输入：

> The capital of France is

模型要预测 “Paris”。

没有 Engram 时，前几层需要逐步完成：

1. 识别 “France” 是国家；
2. 识别 “capital of France” 是一个固定知识关系；
3. 从 FFN 或 MoE 参数中恢复 “Paris”；
4. 将结果写入当前隐藏状态；
5. 后续层再基于这个结果继续推理。

但 “capital of France → Paris” 并不是一个需要每次重新求解的动态逻辑问题，更接近静态知识查询。

类似情况还有：

- `United States of`之后常见`America`；
- `import numpy as`之后常见`np`；
- `def __init__(self`之后常见参数结构；
- “中华人民共和国主席”是相对固定的实体关系模式；
- 数学公式、惯用语和 API 调用包含大量稳定局部结构。

传统 Transformer 没有原生 Lookup 模块，只能使用多层神经计算模拟查表。Engram 试图将这部分工作显式拆出来：

$$ \text{局部N-gram} \longrightarrow \text{Hash索引} \longrightarrow \text{Memory Embedding} $$

单次查询复杂度近似为：

$$ O(1) $$

即使记忆表从 10B 参数扩大到 100B 参数，每个 Token 需要读取的槽位数量仍保持不变。

**2. Engram 的完整计算流程**

Engram 可以分成五个步骤：

![](https://pic3.zhimg.com/v2-65e2583a3bb9eb523004fc36cb59b1c2_r.jpg)
*图7: Engram 流程*

**Tokenizer Compression**

标准 Tokenizer 可能为语义上接近的文本分配不同 Token ID，例如：

- `Apple`
- `apple`
- `APPLE`
- Unicode 形式不同但显示相同的字符。

如果直接使用原始 Token ID 构造 N-gram，这些表面差异会占用不同记忆槽位，降低 Memory Table 的有效利用率。

Engram 首先预计算一个映射：

$$ \mathcal P:V\rightarrow V' $$

将原始 Token ID $x_t$ 映射为规范化 ID：

$$ x_t'=\mathcal P(x_t) $$

规范化过程包括：

- Unicode NFKC；
- 大小写归一；
- 部分文本等价形式合并。

原始 Engram 论文中，对一个 128K 词表进行压缩后，有效词表规模减少约 23%。

这并不会修改模型正常使用的 Tokenizer，只用于Engram构造查询键。模型原有的 Token Embedding 和 LM Head 保持不变。

**构造Suffix N-gram**

对于当前位置 $t$，使用规范化后的最近几个 Token 构造后缀 N-gram：

$$ g_{t,n} = (x'_{t-n+1},\ldots,x'_t) $$

DeepSeek-V4.1-Flash 采用：

$$ n\in\{2,3,4\} $$

假设当前序列是：

> the capital of France is

在 “is” 位置可以构造：

$$ g_{t,2}=(\text{France},\text{is}) $$

$$ g_{t,3}=(\text{of},\text{France},\text{is}) $$

$$ g_{t,4}=(\text{capital},\text{of},\text{France},\text{is}) $$

它们分别捕获不同范围的局部模式：

- 2-gram 覆盖最短局部搭配；
- 3-gram 增加关系信息；
- 4-gram 更可能形成明确知识键。

Engram 使用的是后缀 N-gram，不包含未来 Token，因此不破坏因果性。

**Multi-Head Hashing**

所有可能 N-gram 的组合数量极大，不可能为每一种组合分配唯一 Embedding。

Engram 使用 Hash 函数，将 N-gram 映射到固定大小的 Embedding Table：

$$ z_{t,n,k} = \varphi_{n,k}(g_{t,n}) $$

然后查询：

$$ e_{t,n,k} = E_{n,k}[z_{t,n,k}] \\ $$

其中：

- $n$：N-gram 阶数；
- $k$：Hash Head 编号；
- $\varphi_{n,k}$：第 $k$ 个 Hash函数；
- $E_{n,k}$：对应的 Embedding Table；
- $z_{t,n,k}$：最终槽位编号；
- $e_{t,n,k}$：取出的记忆向量。

DeepSeek-V4.1-Flash 为每种 N-gram 配置 8 个 Hash Head：

$$ k=1,\ldots,8 $$

每个 Head 使用不同 Hash 函数和不同质数大小的 Table。最终将所有查询结果拼接：

$$ e_t = \mathop{\Vert}_{n\in\{2,3,4\}} \mathop{\Vert}_{k=1}^{8} e_{t,n,k} \\ $$

为什么需要多个 Hash Head？

因为单一 Hash 一定存在碰撞。例如：

$$ \varphi(g_a)=\varphi(g_b) $$

两个毫不相关的短语可能映射到同一个槽位。

但如果使用 8 个独立 Hash：

$$ (\varphi_1(g),\ldots,\varphi_8(g)) $$

两个 N-gram 在 8 个 Head 中全部发生相同碰撞的概率会大幅降低。即使一个 Head 发生碰撞，其他 Head 仍可能提供正确区分信息。

可以把它类比成使用 8 个不同的书架编号系统查询同一本书。

**3. 查出来的记忆为什么不能直接相加？**

Hash 检索仅由 Token ID 决定，因此取出的 $e_t$ 是一个静态先验，并不知道当前句子的完整语义。

例如，最近的 Token 都是：

> Apple is

但上下文可能分别是：

- “Apple is headquartered in …”
- “An apple is rich in …”
- “Apple is trading at …”

Tokenizer Compression 还可能将`Apple`和`apple`映射到相同规范化 ID。再加上 Hash 碰撞，直接把 Memory向量加入隐藏状态可能产生噪声。

因此，Engram 使用当前 Transformer 隐藏状态进行 Context-aware Gating。

首先将检索到的 Memory 向量投影成 Key 和 Value：

$$ k_t=W_Ke_t $$

$$ v_t=W_Ve_t \\ $$

当前位置隐藏状态 $h_t$ 已经经过前面若干 Transformer层，包含更完整的上下文信息。Engram 将 $h_t$ 作为 Query，计算一个标量 Gate：

$$ \alpha_t = \sigma \left( \frac{ \operatorname{RMSNorm}(h_t)^\top \operatorname{RMSNorm}(k_t) }{ \sqrt d } \right) \\ $$

然后对 Memory Value 进行门控：

$$ \widetilde v_t = \alpha_t v_t $$

其中：

$$ 0<\alpha_t<1 $$

如果当前上下文与查出的 Memory 高度一致：

$$ \alpha_t\rightarrow1 $$

Memory 信息被较强地注入模型。

如果 Memory 来自 Hash 碰撞、歧义词或者与当前语义不一致：

$$ \alpha_t\rightarrow0 $$

检索结果被抑制。

因此，Engram 并不是“查到什么就使用什么”，而是：

> N-gram 负责提供候选记忆，当前隐藏状态负责判断这份记忆是否适用于当前语境。

**4. Engram 如何注入 Transformer？**

原始 Engram 论文在门控结果后加入了一层短因果卷积：

$$ Y = \operatorname{SiLU} \left( \operatorname{Conv1D} \left( \operatorname{RMSNorm}(\widetilde V) \right) \right) + \widetilde V \\ $$

然后通过残差连接注入当前隐藏状态：

$$ H^{(l)} \leftarrow H^{(l)}+Y $$

再进入正常的 Attention 和 MoE：

$$ H^{(l)} \xrightarrow{\mathrm{Engram}} H^{(l)}+Y \xrightarrow{\mathrm{Attention}} \xrightarrow{\mathrm{MoE}} H^{(l+1)} $$

不过，DeepSeek-V4.1-Flash 删除了这层短因果卷积。报告认为，它带来的收益不足以覆盖推理系统复杂度。

因此 V4.1 中的主干可以理解为：

$$ e_t = \operatorname{EngramLookup} (g_{t,2},g_{t,3},g_{t,4}) $$

$$ \widetilde v_t = \operatorname{Gate}(h_t,e_t) $$

$$ h_t' = h_t+\widetilde v_t $$

然后：

$$ h_t' \rightarrow \operatorname{Attention} \rightarrow \operatorname{MoE} $$

这里是结构性的抽象表达；V4.1报告并未重新公开所有融合层的逐算子实现。

**5. mHC 多残差流中如何使用 Engram？**

DeepSeek-V4.1-Flash 使用 Single-Pass mHC，内部有多条残差流。假设共有 $M$ 条分支：

$$ h_t^{(1)},h_t^{(2)},\ldots,h_t^{(M)} $$

Engram 不需要为每条分支维护一份 Memory Table。

所有分支共享：

- N-gram Memory Table；
- Value 投影 $W_V$。

但每条分支使用不同的 Key 投影：

$$ W_K^{(1)},W_K^{(2)},\ldots,W_K^{(M)} $$

第 $m$ 条分支的Gate为：

$$ \alpha_t^{(m)} = \sigma \left( \frac{ \operatorname{RMSNorm}(h_t^{(m)})^\top \operatorname{RMSNorm}(W_K^{(m)}e_t) }{ \sqrt d } \right) \\ $$

分支输出为：

$$ u_t^{(m)} = \alpha_t^{(m)} \cdot (W_Ve_t) $$

也就是说：

- 所有分支查到同一份静态记忆；
- 不同分支可以根据自己的隐藏状态决定使用多少；
- 一个分支可能强烈接受，另一个分支可能基本关闭。

这既避免复制巨大的 Embedding Table，又保留了多分支差异。

**6. 一个完整例子**

假设模型看到：

> The capital of France is

现在需要预测下一个 Token。

第一步：Token规范化

假设原始 Token 经过映射后得到：

$$ [\text{the},\text{capital},\text{of},\text{france},\text{is}] $$

其中`France`被规范化为`france`。

第二步：构造N-gram

当前位置对应三组查询键：

$$ g_{t,2}=(\text{france},\text{is}) $$

$$ g_{t,3}=(\text{of},\text{france},\text{is}) $$

$$ g_{t,4}=(\text{capital},\text{of},\text{france},\text{is}) $$

第三步：24次Hash查询

共有 3 种 N-gram 阶数，每种 8 个 Hash Head：

$$ 3\times8=24 $$

因此，对当前 Token 执行 24 次 Embedding Lookup：

$$ e_{t,n,k} = E_{n,k}[ \varphi_{n,k}(g_{t,n}) ] $$

无论每张表包含100万个还是1600万个槽位，查询数量仍然是24次。

第四步：拼接记忆向量

$$ e_t = e_{t,2,1}\Vert\cdots\Vert e_{t,2,8} \Vert e_{t,3,1}\Vert\cdots\Vert e_{t,3,8} \Vert e_{t,4,1}\Vert\cdots\Vert e_{t,4,8} $$

经过训练后，`capital of france is`对应的组合Memory很可能携带与`Paris`、国家—首都关系及其语言表达相关的信息。

但它不是一个人工可读的 “Paris” 字符串，而是一个分布式向量表示。

第五步：结合全局上下文进行门控

假设前文明确讨论法国地理：

> In this geography question, the capital of France is

隐藏状态 $h_t$ 与检索记忆高度一致，可能得到：

$$ \alpha_t=0.91 $$

则：

$$ \widetilde v_t=0.91v_t $$

Memory 被大量注入。

如果前文是：

> The phrase “the capital of France is” appears five times in the dataset

当前任务只是讨论字符串，并不是真的要求回答首都，隐藏状态与 “Paris” 知识记忆的匹配程度可能较弱：

$$ \alpha_t=0.12 $$

此时 Memory 基本被关闭。

第六步：注入并继续推理

$$ h_t' = h_t+\widetilde v_t $$

经过后续 Attention、MoE 和 LM Head 后：

$$ P(x_{t+1}=\text{Paris}\mid x_{\le t}) $$

得到提升。

关键不是 Engram 直接输出了 Paris，而是它提前向隐藏状态提供了一个高度相关的静态知识先验，使Transformer 不必在前几层反复重建这条关系。

**再看一个代码例子**

输入：

```python
import numpy as
```

在`as`位置，Engram可以构造：

$$ g_{t,2}=(\text{numpy},\text{as}) $$

$$ g_{t,3}=(\text{import},\text{numpy},\text{as}) $$

这些模式通过 Hash 查询得到 Memory 向量。

在 Python 代码上下文中，隐藏状态与该 Memory 高度一致，因此 Gate 可能较大，提升下一个 Token 为 `np`的概率：

```python
import numpy as np
```

但如果输入位于一段自然语言中：

> We import NumPy as an example

即使局部 Token 存在一定相似性，当前隐藏状态不同，Context-aware Gate 会降低对代码模式 Memory 的依赖。

这说明 Engram 存储的是局部模式先验，而不是无条件规则。

**7. DeepSeek-V4.1-Flash中的具体配置**

DeepSeek-V4.1-Flash 拥有 196B Engram 参数，分配到两个模块：

| 项目 | 配置 |
| --- | --- |
| Engram总参数 | 196B |
| 模块数量 | 2 |
| 所在层 | 第1层和第14层，采用零起始编号 |
| N-gram阶数 | 2、3、4 |
| 每阶Hash Head | 8 |
| 每个Head的Table规模 | 约16M Entries |
| 每个阶数总Embedding维度 | 2048 |
| Embedding精度 | FP8 |
| Key/Value Projection精度 | FP8 |
| 推理存储位置 | 主要位于Host Memory |
| 数据传输 | 后台RDMA预取 |

两个模块均位于相对靠前的位置，原因是 Engram 希望尽早替代 Transformer对静态局部模式的重建，让后面的层把深度留给复杂推理。

同时，第二个模块放到第14层，也为 Host Memory 预取提供了更长的通信隐藏窗口。

**8. Engram真正带来的收益是什么？**

Engram 最直接的收益看起来应该是知识记忆，但实验发现，它对推理和长上下文也有帮助。

原因可以分成三层。

**第一，释放早期网络深度**

没有 Engram 时，前几层需要花费计算重建实体和固定短语。加入 Engram 后，这些信息可以更早进入隐藏状态，后续层能够更快进入组合推理。

**第二，释放 Attention 容量**

局部固定依赖交给 N-gram Lookup 后，Attention可以把更多容量用于全局关系，而不是反复关注附近的固定搭配。

原始论文中，Multi-Query Needle-in-a-Haystack 从 84.2 提升到 97.0。

**第三，增加参数但不同比增加计算**

扩大 Memory Table 主要增加存储容量，并不会同比增加每 Token Lookup 次数。因此，它提供了一条不同于扩大Dense 层或 MoE 专家的 Scaling 路径。

Engram 最终不是为了取代 MoE，而是对模型能力进行分工：

$$ \boxed{ \text{Engram负责静态、局部、重复的模式} } $$

$$ \boxed{ \text{Attention负责上下文信息交互} } $$

$$ \boxed{ \text{MoE负责动态、、高阶、组合式计算} } $$

这也是 DeepSeek 所说的两种稀疏性：

$$ \text{Conditional Memory} + \text{Conditional Computation} $$

前者回答“应该从哪里取回记忆”，后者回答“应该调用哪些参数完成推理”。

### 3.4 FP4 Main KV Cache

DeepSeek-V4 已经对 Indexer Query 和 Key 使用 FP4 QAT。DeepSeek-V4.1-Flash 进一步将 FP4 扩展到 Main KV Cache。

其格式为：

- 数值使用 E2M1；
- 每 16 个通道共享一个 E4M3 Scale；
- 不使用第二级全局 Scale；
- 在 RoPE 之后执行量化；
- SWA KV 仍保留FP8。

论文给出的数值范围分析是：RMSNorm 之后，512 维 KV Latent 满足近似边界：

$$ \left\|\mathrm{KV}\right\|_2 \lesssim \sqrt{512} \approx22.6 $$

训练期间实际观测到的最大幅值约为 10，因此没有必要再增加全局 Scale。

FP4 Main KV 几乎将 Main KV 存储量降低一半，同时不要求注意力矩阵乘法原生支持 FP4，因为缓存可以在参与注意力计算前进行反量化。

### 3.5 优化器选择

DeepSeek-V4.1-Flash 使用三类优化器：

| 参数类型 | 优化方法 |
| --- | --- |
| RMSNorm及非矩阵参数 | AdamW |
| Backbone线性矩阵 | Muon |
| Query和Key矩阵 | Head-wise Muon |
| Engram、Embedding、Prediction Head | Momentum + Sinkhorn Balancing |

Head-wise Muon 将 Query 和 Key 矩阵按 Attention Head 拆分，为不同 Head 构造不同预条件器，从而适应不同Head 之间的梯度异质性。

对于参数量巨大的 Engram 和 Embedding，使用 Adam 会引入大量一阶、二阶优化器状态。因此，模型使用Nesterov Momentum 加 Sinkhorn Balancing。

给定 Momentum 梯度 $\widehat G_t$，寻找行列缩放矩阵 $D_r,D_c$：

$$ \Delta_t = \sqrt n\,U^{(K)} = \sqrt n\,D_r\widehat G_tD_c \\ $$

使更新矩阵的行 RMS 和列 RMS 都近似为1：

$$ \frac{1}{n}\sum_{j=1}^{n}(\Delta_t)_{ij}^2\approx1, \qquad \frac{1}{m}\sum_{i=1}^{m}(\Delta_t)_{ij}^2\approx1 $$

该方法只需要一份 Momentum Buffer，可以显著降低超大 Embedding 矩阵的优化器显存。

## 四、KV cache 降低 75%

![](https://pic2.zhimg.com/v2-3350fc26e65809f15167f25cdd3f6e6b_r.jpg)

现在回到文章的标题，为什么说 KV Cache 降低到了原来的 1/4，只有 890 Bytes/token。

论文中明确提出 “KV Cache 显存只有原来的 1/4”，准确地说是：

> DeepSeek-V4.1-Flash 的 global KV cache 为 890 Bytes/token，而 DeepSeek-V4-Flash 为 3514 Bytes/token，因此约为原来的 $1/4$。

$$ \frac{890}{3514}=0.2533\approx\frac14 $$

也就是：

- KV Cache 降低约 $74.7\%$
- 同样显存理论上可容纳约 $3.95\times$ 的上下文
- 不是所有 KV Cache 都缩小到 $1/4$，而是随序列长度增长的 global KV cache

下面详细推导 890 Bytes/token 是怎么来的。

DeepSeek-V4.1-Flash 的一份 Global KV Entry 包含：

$$ \text{Global KV Entry}=\text{Main KV}+\text{Indexer K} $$

**1. Main KV：288 Bytes**

$$ \underbrace{512}_{\text{Main KV 维度}} \times \underbrace{\frac{4\ \text{bit}}{8\ \text{bit/Byte}}}_{\text{FP4：每个数占 4 bit}} + \underbrace{\frac{512}{16}\times1\text{ B}}_{\text{每 16 个数共享一个 E4M3 Scale}} = 256+32 = \boxed{288\text{ B}} $$

**2. Indexer K：68 Bytes**

$$ \underbrace{128}_{\text{Indexer K 维度}} \times \underbrace{\frac{4\ \text{bit}}{8\ \text{bit/Byte}}}_{\text{FP4：每个数占 4 bit}} + \underbrace{\frac{128}{32}\times1\text{ B}}_{\text{每 32 个数共享一个 MXFP4 Scale}} = 64+4 = \boxed{68\text{ B}} $$

**3. 单份 Global KV Entry：356 Bytes**

$$ \underbrace{288\text{ B}}_{\text{Main KV}} + \underbrace{68\text{ B}}_{\text{Indexer K}} = \boxed{356\text{ B}} $$

**4. Encoder：534 Bytes/token**

Encoder 中18个 CSA2 层分成3组，每组只有一个 Full Mode 层保存 Global KV；压缩率 $m=2$，即每2个 token 保存一个 Entry：

$$ \underbrace{3}_{\text{3 个 Full Mode 缓存组}} \times \underbrace{\frac{1}{2}}_{\text{压缩率 }m=2} \times \underbrace{356\text{ B}}_{\text{每份 Global KV Entry}} = \boxed{534\text{ B/token}} $$

**5. Decoder：356 Bytes/token**

Decoder 的20层共享一份 Global KV，且压缩率 $m=1$：

$$ \underbrace{1}_{\text{Decoder 共享 1 份 Global KV}} \times \underbrace{1}_{\text{压缩率 }m=1} \times \underbrace{356\text{ B}}_{\text{每份 Global KV Entry}} = \boxed{356\text{ B/token}} $$

**6. 总 Global KV Cache：890 Bytes/token**

$$ \underbrace{534\text{ B/token}}_{\text{Encoder}} + \underbrace{356\text{ B/token}}_{\text{Decoder}} = \boxed{890\text{ Bytes/token}} $$

合并为一条公式：

$$ \boxed{ \underbrace{ \left(3\times\frac12+1\right) }_{\substack{\text{Encoder：3组，}m=2\\ \text{Decoder：共享1份，}m=1}} \times \underbrace{ \left(288+68\right) }_{\text{Main KV + Indexer K}} = 890\text{ Bytes/token} } $$

相比 DeepSeek-V4-Flash 的3514 Bytes/token：

$$ \underbrace{\frac{890}{3514}}_{\text{V4.1-Flash / V4-Flash}} = 25.3\% \approx \boxed{\frac14} $$

即 Global KV Cache 显存降低约：

$$ \boxed{1-25.3\%=74.7\%} $$

## 五、后训练

### 5.1 可控推理强度

DeepSeek-V4.1-Flash 在任务 Reward 之外，增加了一个与 Reasoning Effort 相关的长度 Reward：

$$ r^{\mathrm{len}}(\ell,b) = -\min \left\{ C_{\max}, k(b)\frac{\ell}{L_{\mathrm{norm}}} \right\} $$

其中，单位 Token 惩罚系数为：

$$ k(b) = k_0 \exp\left( -\frac{b-b_{\min}}{\tau} \right) $$

变量含义如下：

- $b$：Reasoning Effort；
- $\ell$：本次回答使用的 Reasoning Token 数；
- $L_{\mathrm{norm}}$：参考长度；
- $k(b)$：当前 Effort 下的单位长度惩罚；
- $C_{\max}$：最大长度惩罚，防止超长轨迹产生无限大的负 Reward。

总Reward可以简化为：

$$ r_{\mathrm{total}} = r_{\mathrm{task}} + r^{\mathrm{len}} $$

长度 Reward 是负数，越接近 0 越好，越负代表对冗长推理的惩罚越强。

下面使用一组示意参数，假设：

$$ b_{\min}=25,\qquad \tau=25,\qquad k_0=1,\qquad C_{\max}=1 $$

那么不同Effort对应的长度惩罚系数为：

$$ k(25)=1 $$

$$ k(50)=e^{-1}\approx0.368 $$

$$ k(75)=e^{-2}\approx0.135 $$

$$ k(100)=e^{-3}\approx0.050 $$

Effort 每增加 25，单位 Token 惩罚约下降为原来的：

$$ e^{-1}\approx36.8\% $$ 长度 Reward 曲线如下图所示：

![](https://pic4.zhimg.com/v2-9bf67f860f8ab6a5daef9d4408cfebfb_r.jpg)
*图8:长度 reward曲线*

假设：

$$ L_{\mathrm{norm}}=10000 $$

某条回答使用了 10000 个 Reasoning Tokens：

$$ \ell=10000 $$

因此：

$$ \frac{\ell}{L_{\mathrm{norm}}}=1 $$

不同 Effort 对应的长度 Reward 为：

| Effort | k(b) | 长度Reward |
| --- | --- | --- |
| 25 | 1.000 | -1.000 |
| 50 | 0.368 | -0.368 |
| 75 | 0.135 | -0.135 |
| 100 | 0.050 | -0.050 |

对于同样的 10000 个 Token，Effort 25 受到的惩罚是 Effort 100 的约 20 倍：

$$ \frac{1}{0.05}=20 $$

因此：

- Effort 25 强烈鼓励模型尽快结束；
- Effort 50 允许适度推理；
- Effort 75 允许更充分的搜索与验证；
- Effort 100 基本不会因 10000 个 Token 承受很强惩罚。

API 中的对应关系为：

| API档位 | Effort值 |
| --- | --- |
| Low | 50 |
| High | 75 |
| Max | 100 |

### 5.2 异步后训练

异步 RL 主要解决 Rollout 中的长尾问题。

如果等待同一个 GRPO Group 中的所有轨迹完成，一条特别长的 Agent 轨迹就可能让整组 GPU 停下来等待。

DeepSeek 最终采用 Sample-level Dispatch：

- 不按完整 Batch 派发；
- 不等待固定 Prompt 的完整 Group 结束；
- 只要新完成样本数达到下一 Prompt 所需 GRPO Group Size，就继续调度。

异步生成会引入两个问题。

第一是长度偏差。短序列更快完成，因此早期训练 Batch 可能被短样本主导。

系统通过控制各 Dataset 并发数，以及丢弃部分过早返回的短样本进行缓解。

第二是 Off-policy。部分 Token 可能由旧 Checkpoint 生成。

系统限制最大 Off-policy 比例，并 Mask 掉 Staleness 过高 Token 对应的 Loss。

训练开始时，系统可以在任意 Token 边界立即中断 Rollout，保存 KV Cache 和 Expert Routing；新 Checkpoint加载完成后，再从原位置继续生成，无需重新 Prefill。

### 5.3 大规模 On-policy Distillation

最终 OPD 阶段使用了 40 多个 Teacher Model。

不同领域可以使用不同 Teacher，并且这些 Teacher：

- 可能来自不同训练阶段；
- 可能采用不同模型架构；
- 不需要和 Student 结构相同；
- 可以在训练中动态切换。

系统还可以动态修改 Dataset Mixture、Dataset 并发上限和活跃 Teacher，而无需停止正在执行的异步 Rollout。
