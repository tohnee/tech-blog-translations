从 2023 年 9 月开始阅读多模态大模型的相关论文，从 LLaVA 开始，一直到最近的 Kwai Keye-VL 1.5，有两个共识：

- 一是在模型结构范式上，并没有变化多少，整体上还是延续了 Vision Encoder、MLP 和 LLM 的结构，虽然也有一些把 MLP 换成 Q-Former 的结构，但还是少数。在X上看到一个观点是说在数据量少的时候，模型结构设计需要精细一些，Q-Former就比MLP好，但是数据量足够多的时候，Q-Former就没有优势了。
- 二是在训练策略上，进化不少，早期的 LLaVA 还是 Pretraining + SFT 的范式，2024 的有一些论文还会偶尔增加一个步骤，比如 Multi-Task Pretraing 或者 High-Resolution Finetuning，但是一般就是三四个阶段训练。进入 2025 之后，多模态大模型的训练策略设计就很精细了，预训练有包括多个阶段，SFT 也是多个阶段，最后是多个阶段的基于 RL 的 Post-Training，有一些还会有一个额外的训练 Vision Encoder 的步骤，而且会分为多个小阶段。

这一篇杂文就尝试在多篇论文的基础上，罗列一下最新的 MLLM 的训练策略。

## GLM-4.5V

第一篇是智谱的《GLM-4.5V and GLM-4.1V-Thinking: Towards Versatile Multimodal Reasoning with Scalable Reinforcement Learning》。

[HTTPS](https://arxiv.org/pdf/2507.01006)

[HTTPS](https://github.com/zai-org/GLM-V)

模型结构上不做过多的介绍，在 Vision Encoder 这儿用到了目前比较主流的技术，比如 3D-RoPE、Native Resolution 等，主要看一下训练策略，分为三个大的阶段，每一个大阶段里面又有小的阶段：

- 预训练
- 监督微调
- 强化学习

![](https://picx.zhimg.com/v2-7592d86468e655b2327e6310c5376c91_r.jpg)
*GLM-4.5V*

### Pre-Training

第一个阶段是预训练阶段，这一个阶段又分为两个小的阶段：

- 多模态预训练 Multimodal pre-training
- 长文本继续训练 Long-context continual training

在两个小的阶段的训练数据准备方面，文中提到了比较细致的数据构建策略，简要的数据构建方法以及数据类型如下面的表格所示（豆包生成）：

| 数据类型 | 数据来源与处理策略 | 目标能力 |
| --- | --- | --- |
| 图像 - 文本对 | 初始聚合 LAION、DataComp、Wukong 等 10B+ 数据，经 4 步清洗：1. 启发式过滤（分辨率、去重、 caption 长度）2. CLIP 相似度过滤（保留得分≥0.3 的对齐样本）3. 概念平衡重采样（缓解长尾分布）4. 事实导向重描述（用模型优化 caption 精度） | 世界知识覆盖、跨模态语义对齐 |
| interleaved 图文数据 | 1. 网页数据（MINT、MMC4 等）：过滤广告 / QR 码，优先保留学术图表、工程示意图2. 学术书籍（1 亿 + 数字化 STEM 书籍）：深度解析 PDF 提取图文结构 | 复杂图文逻辑理解、领域知识（如公式、图表） |
| OCR 数据 | 3 类数据覆盖场景：1. 合成文档（多样字体 / 背景的渲染文本）2. 自然场景文本（PaddleOCR 提取真实场景文本）3. 学术文档（LaTeXML 转换 arXiv 论文为结构化数据） | 文本识别（印刷体 / 手写体）、文档结构化解析 |
| 视觉定位（Grounding）数据 | 1. 自然图像：GLIPv2 为 LAION-115M 生成 noun phrase 边界框（保留≥2 个框的样本）2. GUI 数据：爬取 CommonCrawl 网页，用 Playwright 提取 DOM 元素与边界框，生成 14 亿 + 问答对 | 像素级定位（物体 / UI 元素）、交互意图理解 |
| 视频数据 | 融合学术 / 网页 / 私有数据源，经人工细标注（动作、场景文本、镜头运动），并通过模态去重（视频 + 文本嵌入相似度过滤） | 时空理解（动作跟踪、时序关系推理） |
| 指令微调数据 | 5000 万样本覆盖 5 类任务：1. 通用视觉感知2. 多模态推理（STEM 解题）3. 长文档理解4. GUI 代理操作5. UI 编码（关键：人工 + 自动化检查避免评测集数据泄露） | 任务泛化能力、指令跟随精度 |

Multimodal pre-training 阶段用到了除了 Video 之外的 5 种类型的数据，序列长度设定为 8192 个 Token；

Long-context continual training 阶段把模型的能力延伸到高分辨率图片、视频和扩展的 contexts，因此这一个阶段的训练会包括 Video Data、超过 8K Tokens 的比较长的图文交织的数据，最终序列长度设定为 32768 个 Token。

### Supervised Fine-Tuning

监督微调作为预训练阶段和强化学习阶段的链接阶段，把基础 VLM 模型升级为具备长思维链推理的模型，也作为后续 RL 训练的更强的 Cold Start。

这一个阶段的训练数据包括 **结果可验证的数据** 以及 **开放式的视觉问答数据** 。Response 的格式如下：

$\text{<think> {think_content} </think> <answer> {answer_content} </answer>}$

训练过程还用到了 **迭代增强策略，** 即将 RL checkpoint 中高质量推理样本回灌到 cold-start 的 SFT 数据，逐步提升数据挑战性与多样性，让模型在训练过程中可以获取在 RL 过程中发现的更有用的推理模式。这一个阶段的序列长度为 32768。

### Reinforcement Learning

RL 阶段结合了 RLVR 和 RLHF 两种方法，在多个领域的数据上进行了 RL 的 Post-Training，包括 STEM 的问题解答（比如数学、物理和化学），grounding，OCR，视频理解，GUI agents，表和文档理解，逻辑推理和指令遵循等。

来看一下 Reward 的设计。

对于 RLVR 来说，需要从模型回答中提取出答案，然后和真实的答案做对比，文中选择了 LLM 来提取答案，为了让 LLM 更好地提取答案，文中也让模型按照特定的格式输出答案，因此设计了下面的模版来制定答案在 response 中的位置：

$\text{<|begin_of_box|>{FINAL_ANSWER}<|end_of_box|>}$

不同数据类型对应的 Reward 设计如下，

![](https://pic2.zhimg.com/v2-d0dcf9568d34dd93c1394d3b60d0063d_r.jpg)
*Reward Design*

为了提高模型学习效率，文中提出了 Reinforcement Learning with Curriculum Sampling(RLCS)策略。具体来说就是在训练之前，让另外的 VLM 或者前面的 RL Checkpoint 基于 **pass@k** 去评估训练样本的难度，然后将训练样本分为从非常简单到非常困难的 level，记为 offline 的 label。在训练的时候对于每一个 rollout，会记录 pass@k 的输出，并将输出映射到对应难度的 level，然后将这些结果和 offline label 进行合并，然后基于难度 level 对不同难度 level 的训练数据的采样比例进行加权，很简单或者很难的的会降低采样比例。

需要注意的是，训练的时候，KL 项目被丢弃了，原因是作者发现 KL loss 会显著约束模型的能力。

## MiMo-VL

《MiMo-VL Technical Report》是小米前不久的技术报告。

[HTTPS](https://arxiv.org/pdf/2506.03569)

[HTTPS](https://github.com/XiaomiMiMo/MiMo-VL)

模型结构方面和 GLM-4.5V 一样，包括 Vison Encoder、MLP 和 LLM 三个部分，同样是采用了 Native Resolution 策略。

![](https://pica.zhimg.com/v2-93c3d43f9365a7d4085f403a6e51ba90_r.jpg)
*MiMo*

训练分为两个阶段：

- Pre-Training  包括 **Projector Warmup、Vision-Language Alignment、Multimodal Pre-training** 和 **Long-context SFT** 四个阶段
- Post-Training 包括 **RLVR、RLHF** 和 **Mixed On-Policy RL** 三个阶段

### Pre-Training

四个阶段的一些简介如下图所示，

![](https://pic1.zhimg.com/v2-a7b7004b485075a4a2053b698eb1ba68_r.jpg)
*Pre-Training*

训练数据包括 Image Caption、图文交错、OCR / Grounding、视频、GUI、合成推理等六种类型的数据。

- Stage 1 冻结 ViT 和 LLM 的参数，用 **Image Caption** 的数据训练 projector。
- Stage 2 用 **图文交错** 的数据训练 ViT 和 Projector
- Stage 3 会训练所有模型组件， 训练数据类型包括 OCR, grounding, video, GUI ，指令微调和合成推理数据，同时也会引入部分 text-only 的数据
- Stage 4 会增强模型的长文本处理能力，所以输入的序列长度从 8K Token 扩展到 32K Token，同时增加了其他的数据类型，比如 long pure text, high-resolution images, long documents, extended videos,和 long reasoning。

得到的模型记为 MiMo-VL-7B-SFT。

### Post-Training

在 MiMo-VL-7B-SFT 的基础之上，基于 Mixed On-policy Reinforcement Learning (MORL) 的框架结合了 RLVR 和 RLHF 对模型进行了 RL 后训练。

对于 **RLVR** 来说，设计了多个结果可验证的推理和感知任务：

- **Visual Reasoning** 从开源社区和专有 K-12 题库中，汇编了各类可验证的 STEM 学科题目，并通过提示词引导 LLM 筛选基于证明的题目，并将答案为数值或符号的选择题改写为开放作答形式，同时剔除那些先进 VLM 无法解答的较难的题目，也排除过于简单的题目，且 MiMo-VL-7B 模型的通过正确率超过 90%；此外，移除即使没有图像输入也能解答的题目；最终构建了一个包含 8 万道题目的视觉推理数据集；并用 Math-Verify 验证答案正确性
- **Text Reasoning** 为了提高模型解决问题的能力，用到了 Mimo 里面的更具挑战性的问题，并用 Math-Verify 验证答案正确性
- Image Grounding 包括广义和 GUI 的 grounding 任务，在 Reward 计算这一块，框的预测用 GIoU 得到 reward，point 形式的预测看 point 有没有在真值框范围之内
- Visual Counting 用到了 R1-V 里面的 counting 数据，Reward 基于模型的 counting 预测的正确性计算得到 reward
- Temporal Video Grounding 模型输出预测时间区间[mm:ss,mm:ss]，然后基于预测和真值时间区间的 IoU 计算得到 Reward

对于 **RLHF** 来说，分别针对文本和视觉推理任务训练了两种类型的 Reward 模型，而为了 Reward 模型的训练，文中收集了 query 以及对应的偏好结果，构成了训练数据集：从开源指令微调数据集和内部人工编写的 query 中收集多模态 query 与纯文本 query，过滤之后，基于 MiMo-VL-7B 模型和其他的 Top-Performing 的模型得到答案，然后会基于另外一个 VLM 进行排序，这样的数据作为 Reward 模型的训练数据。

文本和多模态的奖励模型分别基于 MiMo-7B 和 MiMo-VL-7B 进行训练。

有了 Reward 模型之后，通过 Mixed On-policy Reinforcement Learning(MORL) 策略同时优化 RLVR 和 RLHF 目标函数。

![](https://pica.zhimg.com/v2-105327169163dffa6b4c3e1678030442_r.jpg)
*MORL*

On-Policy RL Recipe 采用了 GRPO 的变体，

$\mathcal{J}_{\text{GRPO}}(\theta) = \mathbb{E}_{q \sim D, \{o_i\}_{i=1}^G \sim \pi_\theta(\cdot|q)} \left[ \frac{1}{\sum_{i=1}^G |o_i|} \sum_{i=1}^G \sum_{j=1}^{|o_i|} A_{i,j} \right]$

$A_{i,j} = \frac{r_i - \text{mean}(\{r_i\}_{i=1}^G)}{\text{std}(\{r_i\}_{i=1}^G)}.$

同时还采取了 **KL Loss 项移除** 、 **动态采样** 、 **简单样本过滤** 和 **重采样** 的策略。

而具体怎么做呢？

就是 Reward-as-a-Service (RaaS），然后设置一个 reward router 基于 query 的任务类型动态选择合适的 reward 函数，每一个 reward 模型/函数部署成为单独的服务，得到的 reward 归一化到 $[0,1]$ 之间，同时移除了 **format rewards** 。

### Pre-Training

预训练的数据包括五类：

- Image Caption Data
- OCR & VQA Data
- Grounding & Counting Data
- Interleaved Text-Image Data
- Video Data

| 数据类别 | 核心任务目标 | 数据来源 | 关键处理手段 |
| --- | --- | --- | --- |
| Image Caption | 建立视觉特征与语言概念的映射 | LAION、DataComp、COCO、内部图像数据 | 1. CLIP 分数过滤（保留相似度 > 0.9 的 pairs）；2. 多 MLLM 生成caption（Qwen2.5-VL 72B、GPT-4o 等） |
| OCR & VQA | 提升细节感知与上下文推理能力 | 开源（Latex 公式、手写文本、街景）、内部合成 | 1. 中文数据合成：字体渲染（多背景 / 字体 / 分辨率）；2. VQA 问题生成：种子问题自演化 + MLLM 扩写 |
| Grounding & Counting | 建立视觉与文本语义的直接关联 | RefCoCo、VisualGenome、PixMo | 1. 三种定位格式：中心点 / 边界框 / 多边形（坐标归一化至 [0,1000)）；2. CLIP 筛选高相似度标注 |
| Interleaved Text-Image | 增强长多模态上下文建模能力 | 学术 PDF、结构化 STEM 数据、内部文档 | 1. 文本 - 图像语义对齐验证；2. 乱码识别 + 低分辨率图像过滤；3. 保留原始文本中图像位置 |
| Video Data | 强化动态时序理解与短视频场景适配 | 开源视频数据集、快手内部高质量短视频 | 1. 视频 - ASR 交错（Qwen2.5-Omni 转语音为文本）；2. 多 FPS 重字幕（0.5/1/2 FPS）；3. 帧级 OCR 标注；4. 推理增强任务（帧重排序、多视频匹配） |
| Pure Text | 保留 LLM 核心语义理解能力 | 开源文本语料、内部高质量文本 |  |

![](https://pica.zhimg.com/v2-65c99a0cab24a3e87cca98b3616ad116_r.jpg)
*Pre-training*

Pre-training分为四个阶段：

- **Stage 0 SigLIP Contrastive Learning** 让视觉Encoder适配内部的数据分布
- **Stage 1 cross-modal alignment** 只优化Projection层的MLP参数
- **Stage 2 multi-task pre-training** 模型的所有参数都更新，训练数据的类型包括Image Captioning, OCR, Grounding, VQA和 interleaved image-text
- **Stage 3 annealing** 在高质量的数据上进行微调，同时采用了 **Model Merging** 策略

### Post-Training

这一个阶段又分为No-Reasoning Training和Reasoning Training，每一个阶段又分为几个小的阶段。

![](https://pica.zhimg.com/v2-7f9039f1ce2de992ef890a13a5042c28_r.jpg)
*No-Reasoning Training*

**No-Reasoning Training** 环节包括SFT和MPO两个环节：

- **Supervised Fine-Tuning** 训练数据包括70k task galaxy, 200k filtered QA pairs, 和 human-annotated image/video captions
- **Mixed Preference Optimization** 训练数据包括400K open-source samples, 50K re-constructed preference samples, 10K self-improvement samples, 90K text-only samples 和 30K human-annotated samples

![](https://pic3.zhimg.com/v2-5ac9f5fbd4c6ebefded9dee96e50f086_r.jpg)
*Reasoning Training*

**Reasoning Training** 包括 **CoT Cold-Start** 、 **Mix-Mode RL** 和I **terative Alignment** 三个环节：

**CoT Cold-Start**

这一阶段通过，通过 “混合推理模式数据”，让模型学会 “何时推理（Auto-Think）、如何推理（Thinking）、何时直接回答（Non-Thinking）”。

其中 **Non-Thinking 数据33 万条【** 与 SFT/MPO 数据分布一致但无重叠，覆盖简单指令（如 “识别图中颜色”），确保模型保留快速响应能力 **】、Thinking 数据23 万条【** 多模态复杂推理：数学（几何证明）、科学（物理实验分析）、图表（折线图趋势预测）、复杂 OCR（公式推导） **】、Auto-Think 数据2 万条【** MMPR、MM-Eureka、OpenR1Math **】、Agentic 数据10 万条和Video 数据10.4 万条。**

**Mix-Mode RL**

用 RL 强化模型在多个维度的推理能力，尤其提升短视频理解的深度（如时序关系、事件因果）。

数据构建聚焦 4 类核心能力：

1. 多模态感知：复杂文本识别、物体计数；
2. 多模态推理：MMPR、MM-Eureka 数据集；
3. 文本数学推理：难数学题（竞赛级几何、代数）；
4. 智能体推理：来自DeepEyes的47,000 samples

这一阶段采用了GRPO的训练策略。

**Iterative Alignment**

这一阶段修正 RL 后的 “异常行为”（如重复推理、逻辑矛盾），让模型输出更符合人类偏好。

在训练数据方面，采集了instruction following, OCR, mathematics, charts, counting, text-only content, safety, 和 cognition方面的数据，然后用 **Mix-Mode RL** 阶段得到的模型采样多个回答，然后通过混合系统得到偏好数据对：

- Rule-based scores 评估回答的客观质量，比如重复性、指令遵循度等（例如format validation, code type verification）
- Model-based scores 基于提示词过程和MLLM对回答的主观认知方面进行打分

训练的时候采样多轮迭代策略，每轮用 MPO 优化模型，之后重新采样生成新偏好对训练数据。

## Kwai Keye-VL 1.5

《Kwai Keye-VL 1.5 Technical Report》是快手最近提出的技术报告，相比于Keye-VL，Keye-VL-1.5在视频处理上增加了Slow-Fast的处理策略，其他的比如Native Resolution、3D-RoPE和Keye-VL是类似的。

[https://arxiv.org/pdf/2509.01563](https://arxiv.org/pdf/2509.01563)

![](https://pic2.zhimg.com/v2-c12a0fbc6e592271adf8786b6b5d0bd9_r.jpg)
*Keye-VL 1.5*

看一下Slow-Fast的策略。

- Slow Pathway 该路径旨在捕捉快速变化帧中的视觉信息，其运行时处理的帧数较少，但分辨率更高。
- Fast Pathway 从相对静态的帧中捕捉视觉信号的细微变化，其处理的帧数更多，但分辨率更低

![](https://pic4.zhimg.com/v2-1944f15f61ae79857ede5b8635ff2c3d_r.jpg)
*SlowFast video encoding*

为了从识别视频中的慢帧与快帧，设计了一种基于Patch的相似度函数来提取这些帧，具体规则如下：

1. 第一帧始终被定义为慢帧；
2. 对于后续的每一帧，若该帧与最新慢帧的Patch相似度超过 95%，则将其标记为快帧；反之，则将其标记为新的慢帧。

获取慢帧与快帧之后后，将快帧的Token Budget设定为慢帧的 30%，以平衡帧数与总Token Budget之间的关系。随后，采用二分查找技术，在总Token Budget限制（例如，Keye-VL-1.5 模型中的 75,000 个Token）下，精确计算每个慢帧的Token数量。

模型的训练也是分为两个大的阶段：Pre-Training和Post-Training，每一个大的阶段分为多个小的阶段。

### Pre-Training

Pre-training分为四个阶段：

- **Stage 0 SigLIP Contrastive Learning** 训练数据包括DataComp、LAION 、CC12M、PD12M、COCO 和 内部数据
- **Stage 1 cross-modal alignment** 只优化Projection层的MLP参数
- **Stage 2 multi-task pre-training** 模型的所有参数都更新，训练数据的类型包括Image Captioning, OCR, Grounding, VQA和 interleaved image-text
- **Stage 3 annealing** 在高质量的数据上进行微调

Stage 1和Stage 2的context长度为8192；Stage 3为131072，LLM的 RoPE inverse frequency从1000000增加到800000；Stage 3的高质量的训练数据包括 long videos, long texts 和 large-scale image。

### Post-Training

后训练阶段分为non-reasoning和reasoning两个阶段阶段，两个阶段又各自分为多个小的阶段。

![](https://pic4.zhimg.com/v2-0784f9d43e461b097459fa5a7e27b4d7_r.jpg)
*Post-Training*

首先来看 **non-reasoning stage** 。

- 首先是在 7.5M multimodal QA 数据上进行SFT
- 之后在250k open-source samples、 150k text-only sample和 26k human-annotated samples上进行MPO训练

接下来看看 **reasoning stage，** 包括三个阶段 **：**

- LongCoT Cold-Start
- Iterative General RL
- Alignment RL

首先是 **LongCoT Cold-Start** 。

- 用精心构建的LongCoT数据进行训练得到LongCoT cold start model
- 为了弥补LongCoT cold start model 在一些domain任务上的性能缺陷，文中在OCR和Math领域的数据上训练了领域专家模型
- 最后采用Model Merge策略融合了LongCoT cold start model和领域专家模型

*LongCoT data generation pipeline*

接下来是 **Iterative General RL** 。

这个阶段的训练数据来自数学、科学&技术、逻辑推理&模糊问题、代码、Chart问答、视觉定位、空间关系和计数多个domain，之后基于GSPO算法进行RLVR的RL训练。 $\mathcal{J}_{\text{GSPO}}(\theta) = \mathbb{E}_{x \sim \mathcal{D}, \{y_i\}_{i=1}^G \sim \pi_{\theta_{\text{old}}}(\cdot | x)} \left[ \frac{1}{G} \sum_{i=1}^G \min \left( s_i(\theta) \hat{A}_i, \text{clip}(s_i(\theta), 1 - \epsilon, 1 + \epsilon) \hat{A}_i \right) \right]$

$\hat{A}_i = r(x, y_i) - \text{mean} \left( \{ r(x, y_i) \}_{i=1}^G \right), \quad \text{std} \left( \{ r(x, y_i) \}_{i=1}^G \right)$

$s_i(\theta) = \frac{\pi_{\theta}(y_i | x)}{\pi_{\theta_{\text{old}}}(y_i | x)} \quad \text{where} \quad s_i(\theta) = \exp \left( \frac{1}{|y_i|} \sum_{t=1}^{|y_i|} \log \left( \frac{\pi_{\theta}(y_{i,t} | x, y_{i,<t})}{\pi_{\theta_{\text{old}}}(y_{i,t} | x, y_{i,<t})} \right) \right)$

在训练过程中，模型很难回答出一些困难样本的答案，为了利用这些样本进行训练，文中提出了一种 progressive hint sampling方法提高这些样本的成功率。

首先需要识别这些难的case（具体来说就是看Keye-VL-1.5是不是在多次尝试之后还是不能给出正确的答案），随后选取参考答案可靠、难度适中且具备合理挑战性的数据，作为progressive hint sampling样本。将提示分为五个层级：

- 第 1 层级（概念 / 观察）：引导模型关注问题的核心概念或图像的关键特征。该层级不得包含任何解题方法或公式。
- 第 2 层级（策略 / 方法）：提出一种或多种可能的解题策略或思路。例如，“从整体角度思考”“尝试分情况讨论” 或 “建立坐标系”。该层级不得提及具体公式或计算步骤。
- 第 3 层级（工具 / 公式）：提示解决问题所需的特定数学定理、公式或工具。例如，“你可能需要使用勾股定理” 或 “考虑使用积分”。该层级不得提供具体计算步骤。
- 第 4 层级（步骤 / 计算）：给出解题过程中第一个具体的操作步骤。
- 第 5 层级（完整解答）：提供完整清晰的最终解决方案，即可作为标准答案的完美解答。

对于每一个hard case，把prompt信息放在query之后，然后从low-level到high-level提供prompt。

看一下Iterative General RL & Cold-Start Enhancement：

- 把cold-start model 作为  initial model，然后开始General RL training
- 基于General RL training之后的模型，在Cold Start 数据上进行ejection sampling，然后用Reward Model对Response进行打分，如果比ground-truth好，则把ground-truth进行替换
- 基于更新之后Cold Start 数据训练新的Cold Start 模型，作为下一轮General RL的 initial model
- 用更新之后的Cold Start 模型过滤General RL的数据，选择采样准确率在0-1之间的样本作为下一轮 General RL training的训练样本

最后看一下 **Alignment RL。**

这一个阶段着重提高模型的指令遵循、格式准确和偏好对齐性质。

Reward函数包括三种：

- Rule-Based Reward 基于规则进行评估
- Generative Reward 用MLLM进行评估
- Model-Based Reward 基于Reward Model进行评估
