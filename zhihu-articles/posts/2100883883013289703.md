qKnow 专业版 V3.1.5 围绕智能应用构建效率进行深度优化，通过扩容工作流编排调用能力并正式上线 Text2SQL 插件，打通了底层元数据与上层编排资产，进一步降低数据类智能应用的搭建门槛。

---

### 从能力调用到数据查询，应用构建还可以更连贯

随着智能应用的业务逻辑逐渐复杂，单一 Agent 或独立工具往往难以满足完整的业务处理需求。

如何复用已经验证的编排资源，如何让不同工具在同一流程中协同工作，以及如何让大模型更准确地理解数据库结构，成为应用构建过程中需要考虑的问题。

### 让已有编排资源更容易复用

在复杂应用构建过程中，Agent 与工作流资源如果缺少便捷的嵌套调用方式，开发人员就需要重复搭建已有逻辑。

对于已经调试、验证过的流程而言，无法直接复用也会增加后续开发与维护成本。

![](https://pic4.zhimg.com/v2-0275969458bcf9d192fa779221e67d73_r.jpg)

### 让不同能力在同一流程中协同

MCP、Skills 和各类工具承担着不同的能力职责，但如果它们只能通过相互独立的入口调用，数据处理任务就容易被拆分成多个环节。

面对需要连续执行多个步骤的业务场景，开发人员还需要额外处理不同能力之间的衔接。

![](https://pic3.zhimg.com/v2-b2bfcc6b9d3b1b31548ecde0b11894bc_r.jpg)

### 让自然语言查询拥有更完整的数据上下文

自然语言查询数据库，不只是将用户的问题转换成 SQL。

模型还需要了解当前数据源中有哪些表、表中包含哪些字段，以及这些结构之间如何关联。

如果缺少数据源、表和字段等元数据信息，大模型就难以充分理解数据库结构，自然语言生成 SQL 时也会受到上下文不足的限制，尤其是在涉及多表关联的查询场景中。

![](https://pic4.zhimg.com/v2-6a19f52564b5ca47bfa5ecb6f18e5e99_r.jpg)

### 减少从零搭建 SQL 能力的工作

SQL 生成、纠错与优化通常涉及多个不同环节。

如果平台缺少可直接使用的 Text2SQL 资产，用户就需要自行搭建相关流程，再根据实际需求组合和调整能力。

![](https://pic1.zhimg.com/v2-b10a5a9d7412746e23518936327ecbaa_r.jpg)

针对这些问题，qKnow 专业版 v3.1.5 围绕工作流调用、MCP 元数据查询及 Text2SQL 能力进行了更新，进一步完善智能应用的编排与数据查询链路。

---

### 本次更新有哪些变化？

### 01 工作流编排能力扩容：已有资源可以继续组合

本次版本扩展了工作流的调用能力，**支持导入并调用**已有的 Agent 和工作流资源。

同时，MCP、Skills 及各类工具也能够在**统一的工作流入口**中进行编排。

这意味着，开发人员可以基于已有资源组织新的业务逻辑，将不同能力串联到同一个工作流中，而不必每次都从头构建完整流程。

![](https://pic3.zhimg.com/v2-28e4ae3a34a7b699d71faf611e4b28aa_r.jpg)

通过对已有资源进行组合，工作流能够承载更复杂的处理逻辑，也有助于减少重复搭建工作，让经过验证的能力在不同应用中得到复用。

![](https://pic4.zhimg.com/v2-6cd017542a1eaa3657f2771454d043ef_r.jpg)

### 02 MCP 元数据查询：为数据查询补充结构信息

本次更新增强了 MCP 的**元数据查询能力**，支持获取数据源、表和字段等信息，并支持执行 SQL。

借助这些能力，Agent 在处理数据查询任务时，可以获得更完整的数据库结构信息。

相比仅根据用户输入理解查询需求，结合实际数据源的表结构与字段信息，有助于为后续 SQL 生成提供必要的上下文。

![](https://pica.zhimg.com/v2-f8159316efe35ac5f5f377b3b09b92c6_r.jpg)

这项能力为自然语言数据查询提供了基础，也为后续将 Text2SQL 与数据库元数据结合使用创造了条件。

### 03 Text2SQL 插件正式上线：覆盖 SQL 处理的多个环节

本次版本正式上线 **Text2SQL 插件资产**。

该插件基于平台 Bot 与工作流编排能力构建，围绕 SQL 处理提供多项能力，减少用户从零搭建相关流程的工作。

**SQL 生成与改写**

Text2SQL 支持 SQL 生成和改写，可用于将查询需求转化为 SQL，或根据新的需求对已有 SQL 进行调整。

![](https://pic3.zhimg.com/v2-c115be657219770825b3f25567e5fb52_r.jpg)

**SQL 纠错与性能优化**

除生成与改写外，插件还覆盖 SQL 纠错和性能优化能力，帮助用户处理 SQL 编写及调整过程中遇到的问题。

![](https://pica.zhimg.com/v2-cfbda5cf05d97d03f3104c970a0b017c_r.jpg)

**SQL 注释生成与续写**

插件还支持 SQL 注释生成和 SQL 续写，进一步覆盖 SQL 编写与完善过程中的相关需求。

![](https://pic4.zhimg.com/v2-c1b0a14e994ed53c35a19fdbcd87acbb_r.jpg)

![](https://pic4.zhimg.com/v2-5a698aefa3d013e126505e0d64bf5efb_r.jpg)

与单独实现各项 SQL 功能不同，Text2SQL 将上述能力组织为可复用的工作流单元，各项 SQL 子能力可以独立使用，也可以根据应用需求组合到其他 Agent 或应用中。

![](https://pic3.zhimg.com/v2-141be6e44c97218e7dbef7430df195b0_r.jpg)

这种组织方式为不同业务场景下的 SQL 能力复用提供了基础，用户可以根据实际需求组合相应流程，而不必将所有能力固定在单一应用中。

### 04 Text2SQL 与 MCP 结合：完善自然语言数据查询链路

当 Text2SQL 与 MCP 的元数据查询能力结合使用时，数据源、表和字段等结构信息可以作为**上下文输入**，为 SQL 生成提供更具体的数据结构依据。

在这一基础上，平台能够更好地支持自然语言转 SQL，并面向复杂多表查询等场景提供能力支撑。

用户也可以根据自身业务需求，进一步构建定制化的数据查询与分析资产。

![](https://picx.zhimg.com/v2-13550bfaa4aa369da80ba88d4b640d21_r.jpg)

从工作流资源复用，到 MCP 获取数据库结构信息，再到 Text2SQL 对 SQL 处理环节的覆盖，本次更新进一步串联了智能应用编排与数据查询相关能力。

### 写在最后

qKnow 专业版 v3.1.5 围绕**工作流编排、MCP 元数据查询和 Text2SQL 插件**进行了针对性完善：

- 工作流支持调用已有 Agent 与工作流资源，并统一编排多类工具；
- MCP 能够获取数据源、表和字段元数据；
- Text2SQL 则覆盖 SQL 生成、改写、纠错、性能优化、注释生成及续写等环节，并支持将各项能力作为工作流单元复用。

这些更新为构建复杂智能应用、组织数据处理流程及开展自然语言数据查询提供了更完整的能力基础。

具体使用方式可结合实际业务需求与应用流程进行配置。

在数字经济时代，企业对于数据资产的盘活与智能化应用有着迫切需求。

qKnow 专业版 v3.1.5 的发布，正是基于企业构建复杂业务智能体时面临的实际痛点进行的精准迭代。

通过资产复用的编排扩容、底层元数据的结构补齐，以及 Text2SQL 插件资产的标准化封装，qKnow 进一步拓宽了数据类智能应用的构建边界。

未来，qKnow 将持续深耕企业级 AI 基础设施，以更专业、更易用的产品能力，助力企业在智能化转型的道路上稳步前行。
