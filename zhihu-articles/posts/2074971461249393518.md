2018 年国际计算机体系结构大会（ISCA）上， **John Hennessy** 与 **David Patterson** 发表了图灵奖演讲： **「计算机体系结构的新黄金时代」** 。

1980 年代，两人完成图灵奖研究时，单线程 CPU 性能每年增长约 52%。到 2018 年，随着 **摩尔定律** 与 **Dennard Scaling** 终结，增速只剩约 3%。

于是需要 **领域专用架构（DSA）** 。他们的范例是已量产的 Google **TPU v1** ：神经网络推理吞吐约为 CPU 的 29 倍，能效约为 80 倍。收尾预言是： **「未来十年将出现新型计算机架构的寒武纪大爆发。」**

预言成真。如今认真推进的架构已有数十种： **GPU** 、 **TPU** 、 **LPU** 、 **NPU** 、 **DPU** 、 **ASIC** 、 **晶圆级引擎** 、 **可重构数据流** 、 **神经形态** 、 **光子** 、 **模拟** 。它们尤其聚焦 AI 计算。

真正落地部署的，目前是： **GPU** （NVIDIA、AMD）、 **脉动阵列加速器** （TPU、Trainium）、 **Cerebras 晶圆级引擎** ，以及 **Groq LPU** 。

**NVIDIA** 明显领先； **AMD** 紧随其后，OpenAI 与 Meta 各自有 6 GW 量级承诺。 **TPU** 训练 Gemini，并将向 Anthropic 提供最多约一百万颗芯片；Anthropic 也在超过一百万颗 **Trainium** 上跑 Claude。 **Cerebras** 已承接 OpenAI 推理； **Groq LPU** 则以约 200 亿美元的 acquihire 并入 NVIDIA。

本文旨在梳理这些路线：各自的 **哲学** 、 **架构** 、 **扩展方式（scale-up / scale-out）** ，以及 **软件栈（如何编程这块芯片）** 。

## 问题本身

AI 计算由 **矩阵乘法** 主导。Transformer 是一串 matmul： **Q/K/V 投影** 、 **attention** 、 **输出投影** 、 **FFN** ——中间穿插逐元素运算：归一化、激活、残差相加。训练前沿模型大约要做 $10^{25}$ 次乘加（matmul 本身就是一串 MAC）。

这些 matmul 的 **形状** 取决于负载。 **训练** 把一批序列推过每一层，反向传播损失并更新权重，同一权重矩阵上同时流过成千上万个 token。 **Prefill** 是推理的提示词摄入阶段：在产出第一个输出 token 之前，整段输入一次穿过模型。训练与 prefill 都把大量 token 叠到同一权重上，因此每层是大规模 **矩阵–矩阵乘（GEMM）** ，算术强度高（算力受限）。 **Decode** 是自回归：一次出一个 token，第 $N+1$ 个必须等第 $N$ 个完成。每步只投影一个 token，matmul 退化成 **矩阵–向量乘（GEMV）** 。产出一个 token 需要扫过模型全部权重，还要为 attention 读完整份 KV Cache。算术强度比 prefill 低几个数量级。

推理系统用批处理把 GEMV 再抬回 GEMM： **continuous batching** 叠多个用户的 decode 步； **speculative decoding** 每请求叠 $K$ 个草稿 token 再一次校验； **multi-token prediction** 把同样手法做进模型内部。这样能提高 matmul 单元利用率，抬高 Ops/B。对 continuous batching 而言，每个用户仍读自己的 KV Cache，因此长上下文 decode 会从「权重带宽受限」转向「KV 带宽受限」。

架构问题是： **把数字搬到 matmul 发生的地方，还要够快** 。这就是 **memory wall（存储墙）** ：算力指数增长，内存带宽没有跟上。

各架构用不同策略赢这场数据搬运。理解一颗芯片可归结为四个问题： **数据住在哪里、如何搬到计算单元、计算单元长什么样、芯片之间如何在规模上通信** 。

## NVIDIA GPU

NVIDIA GPU 是一台 **大规模并行处理器** 。哲学是：一颗可编程芯片、成千上万条线程，由主机 CPU 编排，通过 **CUDA** 暴露，就是跑 **可并行** 负载的正确机器。每一代都在可编程 **Streaming Multiprocessor（SM）** 上加加速原语，而不改编程模型。同一颗芯片训练 Transformer、做推理、渲染图形、跑科学仿真（ **加速计算** ）。

### 架构

NVIDIA GPU 是一组 **吞吐导向核心、一层喂饱它们的深层存储层次，再加上刚好够用的调度硅片，让成千上万条线程同时在飞** 。核心是 **SM** ，每封装复制 100+ 次：V100 80 个、A100 108、H100 132、B200 148、B300 160、Rubin 224。每个 SM 配方相同：四个 **SM 子分区** ，各有 **warp scheduler** 、 **dispatch unit** 、16k×32-bit **寄存器堆** 、标量 **CUDA Core** 通道、做超越函数的 **Special Function Unit** ，以及通往本 SM **Tensor Core** 的私有端口。四个分区共享一块 L1/shared memory，以及 TMA。线程按 32 条组成 **warp** ，SIMT 锁步执行；每个分区驻留数十个 warp，调度器靠切换掩盖访存/算术停顿。

### 计算

**CUDA Core** 是最初的算力吞吐，在 AI 里仍负责一切非 matmul：激活、残差、归一化、地址算术。但一个 Transformer block 约 99% FLOP 是 matmul，所以压倒性吞吐来自 **Tensor Core** 。

这些核心对小矩阵 tile 做 **融合乘加** ：

$$
 D = A \cdot B + C 
$$

完整 matmul 拆成输出 tile：要产出一个输出 tile，kernel 沿共享内维 $K$ 走，从左矩阵取一行带 $A$、从右矩阵取一列带 $B$，把部分积折进累加器。$C$ 是目前部分和，$D$ 是带入下一步的更新值。内循环结束后，$D$ 就是完整输出矩阵的一块成品 tile；整次 matmul 由许多这样的 tile MMA 拼成。

Tile 形状写成 **M × N × K** 。$M \times N$ 是输出 tile 大小，$K$ 是一条指令一次收缩的内维长度；matmul 其余 $K$ 轴由 kernel 内循环走完。累加器在循环间「粘住」：每条 MMA 的输出 $D$ 变成下一条的输入 $C$，方程其实是原地

$$
 C \leftarrow A \cdot B + C 
$$

连续指令把部分积折进同一块存储，直到走完 $K$ 轴。

V100 第一代（每 SM 8 个）做 warp 级 16×16×16 FP16 MMA。A100 第三代加上 TF32、BF16、FP64 matmul 与 2:4 结构化稀疏。H100 第四代加上原生 FP8，并把抽象从 warp 抬到 **warp group** ：128 条协作线程发射异步 `wgmma` ，形状 64×256×16，在后台跑，同时发射 warp 加载下一块 tile。B200 第五代更进一步： **双 SM MMA** 256×256×16，操作数拆到一对 SM 上，原生 FP4，以及每 SM 专用 256 KB **Tensor Memory（TMEM）** 暂存累加 tile，避免挤爆寄存器堆。Rubin 第六代扩展 FP4 吞吐、加上原生 FP6，并配对第三代 Transformer Engine，在硬件里做自适应 NVFP4 微块缩放，把每 tile 量化元数据留在 Tensor Core 路径上，而不是走 CUDA Core。

六代不变的是：matmul 仍活在 **线程/warp 层次** 里，但 **发射** 一条指令所需的线程数在缩小，发射本身也与执行解耦。Volta 的 `mma.sync` 是 warp 集体、同步的：32 条线程一起执行，每条 lane 持有 A、B **以及累加器 D** 的寄存器碎片，warp 阻塞直到完成。Hopper 的 `wgmma.mma_async` 把发射者扩到 128 线程的 warp group，把 B 放进 shared-memory descriptor（A 可选：寄存器 **或** descriptor，由 kernel 决定），并且 **立即返回** ：matmul 在后台跑，warp group 排队下一块 tile，完成用 `wgmma.commit_group` / `wgmma.wait_group` 跟踪。

Blackwell 的 `tcgen05.mma` 完成迁移： **A 也加入 B** ，走 shared-memory descriptor（或 A 直接来自 TMEM），累加器 **D 落在 TMEM** 而不是寄存器堆。所有操作数都离开 lane 后，发射不再需要协调每线程状态，于是 **单条线程** 开火并 **立即返回** ，完成由消费者 warp 等待的 `mbarrier` 发出。warp 其余线程以及发射线程本身，期间可做别的事。 **CTA-pair 变体** 把同一模型扩到两个 SM：配对 cluster 里每个 SM 各有一条线程发射协调 MMA，跨对共享操作数，拼出 256×256×16 双 SM tile；完成仍是异步/ `mbarrier` ，只是升到 cluster 级 barrier，让这一对齐步。

matmul 同时变得更大、对发射线程更轻：一条从 32 条 lane 锁步的指令，如今更接近一条 descriptor 驱动的命令——仍从 warp 模型内部发出，却不再由它执行。

这种解耦让 Transformer attention kernel 在 GPU 上高效。warp 可以在 matmul 飞行时跑 softmax、打 mask、或预载下一块 tile；matmul 与周围逐元素工作的重叠，就是所有现代 attention kernel（FlashAttention-3、FA4）的结构，前提是矩阵指令 **不阻塞** warp。

### 存储

片上层次是 **每一级都有硬件管理的 cache，上面再叠软件 hint** 。片外是 **HBM** ：V100 32 GB HBM2，H100 80 GB HBM3，B200 192 GB HBM3e，B300 288 GB，Rubin 288 GB HBM4。芯片级 **L2** 夹在 HBM 与 SM 之间：V100 6 MB，A100 40 MB，H100 50 MB，B200 60 MB（双 die 封装拆成两个 30 MB bank，带局部性驻留控制，热 tile 可钉在近端 die）。每个 SM 内 256 KB 统一 **L1/SMEM** ，在 kernel launch 时在硬件 L1 与程序员控制的 scratchpad 之间划分。寄存器堆另约每 SM 256 KB，按四分区分片。

Blackwell 加第五层： **TMEM** ，每 SM 256 KB，专给 MMA 累加器，只由 Tensor Core 寻址，把操作数驻留压力从通用寄存器堆挪走。

层间搬运逐步与 warp 解耦。Ampere 之前，加载 tile 是同步的：每条线程自己发 global load，warp 等到所有碎片进寄存器，再拷到 shared memory；每块 tile 都把 warp lane 烧在地址算术和等待上。Ampere 引入 **`cp.async`** ：每线程异步拷贝 HBM → SMEM，完全绕过寄存器；warp 提交在飞拷贝组，只在消费者需要数据时才等。Hopper 换成 **TMA** ，专用 DMA：一条线程提交多维 tile descriptor（基址、leading dimension、swizzle），引擎处理全部地址算术并写入 shared memory，完成由 `mbarrier` 发出。整个 warp 从 load 发射与地址计算中解放；kernel 只需排队 descriptor。TMA 还支持 **cluster 级组播** ：一次 HBM 读扇出到 thread-block cluster 里每个 SM，把过去 N 次独立 load 变成一次。Blackwell 再扩展 TMA：直接载入 TMEM，累加 tile 无需经 SMEM 中转。轨迹是：每一代，warp 每块 tile 少做一件事。

### Warp 特化

Hopper 时代的编程惯用语是 **warp specialisation** ：同一 block 里，一些 warp 当 **producer** ，连续发 TMA load；另一些当 **consumer** ，对刚到的 tile 开火 `wgmma` 。它们之间的同步不再是旧的 SM 级 `__syncthreads()` ，而是 **`mbarrier`** （shared memory 里的 memory barrier）以及挂在 TMA 完成上的异步事务 barrier，允许 warp 粒度而非 block 粒度的精细 producer/consumer 握手。已成为所有现代 attention kernel 参考的配方（FlashAttention-3、 **CUTLASS** ping-pong GEMM、Blackwell FA4）都一样：TMA 驱动的 producer 流水线，经 shared memory 与 TMEM 喂给 `wgmma` consumer 流水线，用 `mbarrier` 握手，再用 **thread-block cluster** （Hopper+）把多个 SM 绑成一个协作计算单元，于是 Blackwell 的双 SM MMA 能自然叠上去。

### 数值

历史上默认 FP32；Volta 带来带 FP32 累加的 **FP16** ，以及让它可训练的 loss scaling；Ampere 加上 **TF32** （FP32 动态范围、FP16 尾数，可直接替换 FP32 matmul）、 **BF16** ，以及让剪枝权重有效吞吐翻倍的 2:4 **结构化稀疏** 。Hopper 引入原生 **FP8** （E4M3 与 E5M2），配对 **Transformer Engine** ，按层自动缩放激活以留在 FP8 动态范围内。Blackwell 精度再减半，用 **FP4** 与 **microscaling MX 格式** （块级共享指数，收回 FP4 丢掉的大部分精度），以及把自动缩放管道改打 FP4 的第二代 Transformer Engine。Rubin 第三代 Transformer Engine 加上 **NVFP4** （NVIDIA 收紧的 FP4 变体）与原生 **FP6** ，稀疏更激进。芯片布局本身也进入数值叙事：B100/B200/B300 是两颗 **光罩极限 die** ，用约 10 TB/s 的 **NV-HBI** 缝在一起，对软件呈现为一颗逻辑 GPU，封装上 8 堆 HBM；Rubin 把 chiplet 配方扩到双 die、约 3360 亿晶体管、8 堆 HBM4。每一代大约用「位数减半 + 更细粒度缩放挽回精度」买约 2× 每瓦吞吐，并且越来越多地把更多硅片键合进同一封装。

### 押注

- **押注 1：可编程性。** 负载是移动靶（attention 变体、新模型架构），所以让每个块都可编程，让开发者写 CUDA。即便专用单元也通过该模型暴露，而不是做成固定功能块。
- **押注 2：用海量多线程藏延迟。** 延迟不可预测且数据相关，所以不用静态调度，而用海量线程超额提交——每 SM 最多 64 个驻留 warp，硬件 warp scheduler 每周期挑一个就绪 warp。
- **押注 3：包在 warp 里的 Matmul。** 矩阵单元是压倒性算力，但必须活在与其他一切相同的 warp/线程抽象后面，于是包成 `mma.sync` → `wgmma` → `tcgen05.mma` ，而不是暴露成固定功能管道。这让单个 kernel 能在一遍里融合 matmul、softmax 与逐元素运算。
- **押注 4：异步存储层次。** 让存储层次显式、由程序员管理，而不是隐式、由编译器调度。保留 L2，但把 SMEM 与 TMEM 暴露为具名 scratchpad，再叠异步机制：TMA 做批量拷贝，TMEM 做 matmul 累加器， `mbarrier` 做 producer/consumer 握手。层次在可编程 kernel 内做软件流水线，而不是编译器对着已知延迟 scratchpad 静态调度。
- **押注 5：摊销 SIMT 税。** 花在 warp scheduler、寄存器堆或一致性 cache 上的每个晶体管，都不是花在 MAC 上的晶体管；接受这笔税，再用两种方式摊薄：Tensor Core 大到足以把 SIMT 机械摊到大得多的 MAC 数量上；以及像 TMEM 这样用一部分通用灵活性换 MAC 密度。

### 扩展

扩展有两种制度： **scale-up** 与 **scale-out** 。

**Scale-up** ：把若干 GPU 绑进一个一致的内存域。任一 GPU 可经 NVLink 以纳秒级延迟直接 load/store 另一颗 GPU 的 HBM：一个地址空间，无需显式传输。

**Scale-out** ：在机柜与集群层把这些域联网。数据经显式 RDMA 以微秒级延迟跨越：分离的地址空间，但每集群可达数万颗芯片。

AI 基础设施两者都用：带宽饥渴的集合通信（张量并行、MoE expert routing）留在 scale-up 域内；数据并行与流水线并行穿过 scale-out 织物。

### Scale-up

Scale-up 栈是 **NVLink** 加 **NVSwitch** 。NVLink 实现 GPU 间的 **cache 一致织物** ，一颗 GPU 上的 load/store 可以打到另一颗的 HBM，地址翻译与一致性由硬件处理。但 NVLink 本身是点对点：一条链路恰好连两颗芯片。NVSwitch 是专用 **crossbar** 芯片，每颗 GPU 都接到它，路由流量使每颗 GPU 能同时与其他所有 GPU 以满 NVLink 带宽通信，非阻塞、全互连。

它们一起定义了 **HGX** 8-GPU 基板：八个 H100 SXM 模块经 PCIe Gen5 配对 x86 主机（AMD EPYC 或 Intel Xeon）。Hopper 还出了配对 Grace 的形态： **GH200 Grace Hopper Superchip** 用 900 GB/s 的 **NVLink-C2C** 把一颗 Grace ARM CPU 与一颗 H100 键合，去掉 PCIe 主机–设备跳。模块再扩成 **GH200 NVL2** 对与机柜级 **GH200 NVL32** 。Blackwell 把配对做成默认。 **GB200** 模块用 NVLink-C2C 融合一颗 Grace 与两颗 B200， **NVL72** 把 36 个这样的模块缝进一个液冷 scale-up 域：72 GPU、36 Grace CPU、13.5 TB HBM 与 17 TB LPDDR5X，作为一个平坦、一致的地址空间。Rubin 分两步走。 **NVL144** 于 2026 年作为 Rubin 代刷新，仍在同一 Oberon 级机柜：72 个 Rubin 封装，按 NVIDIA 新的 die 计数惯例标为 144 GPU，HBM4 与 NVLink 6 把每封装带宽翻倍。真正的机柜级跳跃是 2027 年的 Rubin Ultra： **NVL576** 把 144 个四 die Rubin Ultra 封装装进新的 **Kyber** 机箱，一个一致域里有 576 个 GPU die。

![](https://pic3.zhimg.com/v2-e547dcd651613b9a561a53576285cf0c_r.jpg)
*NVL72：72 颗 Blackwell GPU 坐在一排构成非阻塞 crossbar 的 NVSwitch ASIC 下面，任一 GPU 都能以满 NVLink 带宽寻址另一颗的 HBM。整张织物跑在无源铜背板上：约 5184 根盲插线缆，约 130 TB/s 全互连带宽，相对光学等价方案节省约 20 kW 收发器功耗。*

这种密度靠 **无源铜缆** 撑住。NVL72 的 NVLink 织物经背板盲插 5184 根线缆（每机柜约 2 英里线缆，线内无 retimer，SerDes 活在 GPU 与 switch ASIC 上），在 72 颗 GPU 上承载约 130 TB/s 全互连带宽。NVIDIA 估计相对每条链路都要可插拔光模块的光学方案，铜缆每机柜大约省 20 kW。铜缆让「机柜即一颗 GPU」在经济上可行：亚 2 米距离上，它仍在功耗、成本与每美元信号完整性上获胜；再远，比特就必须上玻璃。

NVL144 仍在 Oberon 内，铜缆继续能用，因为封装数（72）与 NVL72 相同；线缆不必加长，只需在 Gen 6 SerDes 上传得更快。Rubin Ultra 的 NVL576 用重塑机柜保住同一条铜线：新的 **Kyber** 外形大约是 Oberon 两倍高，把全部 576 个 GPU die 装进一个机箱，尺寸专门保证每条 NVLink 路径仍在无源铜可达范围内——即便是 144 个四 die 封装与数万根线缆。

### Scale-out

Scale-out 栈来自收购 Mellanox。与 NVLink 不同，scale-out 织物 **不一致** ：节点保持分离地址空间，数据只经软件发起的显式 **RDMA** 跨越，通常包在 **NCCL** 集合通信（all-reduce、all-to-all）里。参考集群是 **DGX SuperPOD** ：八个 NVL72 机柜经 Quantum-X800 InfiniBand 缝在一起，单个调度器下有 576 颗 Blackwell GPU；训练集群再靠拼接 SuperPOD 继续扩。2026 年的 Rubin SuperPOD 保持同样的 8 机柜图案，用 NVL144（每 SuperPOD 1152 GPU 而非 576）。2027 年 Rubin Ultra 把配方再抬一个数量级：每个 Kyber 机柜 576 个 GPU die，经 Quantum-X Photonics CPO 缝在一起，单个调度器下数千颗 GPU。

![](https://pic4.zhimg.com/v2-8ca1ead5e6c45ee0e1cd812b01e2d135_r.jpg)
*DGX SuperPOD：八个 NVL72 机柜（共 576 GPU）坐在 Quantum-X800 InfiniBand 脊骨下。每 GPU 的 scale-out 是 800 Gbps 的 ConnectX-8 NIC；机柜间跳经 OSFP-RHS 可插拔光模块，付微秒延迟，而不是机柜内 NVLink 的纳秒延迟。*

每颗 GPU 都有自己的 ConnectX NIC 接入该织物。Blackwell 节点每 GPU 跑 ConnectX-8 800 Gbps，比每 GPU NVLink 低一个数量级，延迟从纳秒爬到微秒。Rubin 改到每 GPU ConnectX-9 1.6 Tbps，在每机柜 scale-up 域从 72 扩到 576 GPU 的同时，把每 GPU scale-out 带宽翻倍。每颗 NIC 旁还有 BlueField DPU，用 ARM 核与加速器从主机 CPU 卸载存储、网络与安全。对更喜欢以太网而非 InfiniBand 的客户， **Spectrum-X** 是面向 AI 流量调过的无损以太网替代。

从铜到玻璃的交叉发生在机柜边界。NVL72 内部脊骨是铜；一旦链路要以 800 Gbps 跨机柜，就是 **光学** 。无源铜 DAC 在 200 G/lane 大约顶到 1.5–2 米，远不够跨机柜，所以今天的 SuperPOD 脊骨骑在 **OSFP-RHS** 可插拔收发器上，每个模块自带激光器、调制器、光电探测器与 DSP。一张扇出到数千 GPU 的 SuperPOD 脊骨，从光学上看就是数万个可插拔模块，仅收发器激光就抽数十千瓦。

到了 Rubin，这层光学塌进 switch ASIC。 **Quantum-X Photonics** （InfiniBand）与 **Spectrum-X Photonics** （以太网）用 **共封装光学（CPO）** 替换可插拔模块：激光器、调制器与光电探测器经 TSMC COUPE 键合到 switch 封装上。NVIDIA 声称激光器数量约为 OSFP 可插拔方案的 1/4，链路功耗约低 3.5 倍。把 GPU 变成双 die 封装、把 HBM 叠在旁边的 chiplet 逻辑，如今出现在网络层：计算、存储 **与** 光子在同一衬底上的垂直整合。

**NVLink Fusion** 最近开放了 scale-up 织物本身：第三方 CPU 与 XPU 现在可以加入 NVLink 域，让超大规模厂商围绕 NVIDIA 互连建半定制机柜，而不必从零设计自己的一致性织物。

### 软件

**CUDA** 是 **大规模并行** 处理器的自然编程模型。你写一个 kernel（每条线程执行一次的同一段代码），再把它 launch 到按 block 与 warp 组织的成千上万条线程上；程序员决定它们共享什么、何时同步、各自处理问题的哪一块。这就是抽象十八年几乎没变、以及 2007 年以来每个 CUDA kernel 仍能在 Blackwell 上编译运行的原因。

这种连续性既是护城河，也是约束。每一代都把新硬件（Tensor Core、TMA、TMEM）接到同一套 kernel-and-warps 模型上，在 **PTX** 与 **SASS** 里以 intrinsic 暴露： `mma.sync` 、 `wgmma.mma_async` 等等。NVIDIA 无法激进重思 SM，因为太多代码依赖它；作为回报，每一分 CUDA 软件投入都跨代复利。

PTX 之上是二十年堆起来的栈。 **cuBLAS** 与 **cuDNN** 做数学与 DNN 原语； **CUTLASS** 用模板 C++ 编码数十年 GEMM 经验； **TensorRT-LLM** 做 paged attention、in-flight batching 与 speculative decoding；框架绑定经 **PyTorch** 、 **Triton** 与 **JAX** 。

**FlashAttention** 是现代 AI 最重要的算法改写之一：把 attention 分 tile，避免物化 $O(N^2)$ 矩阵。四代（FA1 到 FA4）各自为最新 NVIDIA 硅片手调（FA3 对 Hopper 异步流水线，FA4 对 Blackwell），移植到其他硬件要落后数月甚至数年。

这套栈大部分不是 NVIDIA 付钱的人写的。护城河不是 CUDA 本身，而是二十年的第三方 kernel、库与工具，以及一路学会这套 API 的数百万开发者。

NVIDIA 还把人一起随硅片出货。他们把数十名自家工程师嵌进前沿实验室与超大规模团队，为每种新模型架构写 kernel，并为每一代新硅片调优。实验室下个月想训的东西，往往在 NVIDIA 上跑顺的速度远快于其他平台。离开 NVIDIA 因此不只是重写 kernel 与库。那是重训整支工程队伍的心智模型，并失去今天就坐在楼里的 NVIDIA 工程师。

## Google TPU

**TPU** 是一台 **矩阵乘法机器** 。哲学是：与其做一颗能跑任何大规模并行负载的可编程芯片，不如聚焦单一原语（在大型脉动阵列上做稠密矩阵乘），让 **XLA** 编译器提前规划每一个周期、每一个字节。没有硬件调度器，没有 cache，没有线程/warp。每一代扩大 pod，经 **ICI** 互连把数千颗芯片织成一台一致的机器。TPU 无意渲染图形或跑科学仿真；它存在是为了比任何通用替代方案更高效地（每瓦）训练与服务 Google 的负载（搜索、翻译、推荐、Gemini）。

### 架构

一颗 TPU 芯片是 **包在刚好够喂饱它的硅片里的 matmul 引擎** 。计算单元是 **TensorCore** ：v2 起旗舰每封装两颗；能效调优芯片（v4i、v5e、v6e）一颗。每个 TensorCore 内是同一套五件套：一个或多个做矩阵的 **MXU** 、做逐元素的 **VPU** 、掌舵的 **Scalar Unit** 、做跨 lane 归约的 **XLU** 、外加 **Transpose/Permute Unit** ，以及喂入/排出 MXU 的累加队列。从 v4 起，每颗芯片还在 TensorCore 外带专用 **SparseCore** 数据流引擎（v4、v5p、Ironwood 每芯片 4 个；Trillium 每芯片 2 个），明确切出来吸收脉动阵列形状不对的 embedding lookup。每个块坐在同一条 VLIW 发射平面上，由 **Core Sequencer** 每周期填满 322-bit bundle 的全部八个功能槽。没有 I-cache miss，没有 warp scheduler，没有乱序引擎，没有分支预测：编译器就是调度器，省下的硅面积拿去堆更多 MAC。

![](https://pica.zhimg.com/v2-571141603261c2e41ddf10d539565b48_r.jpg)
*放大一个 TensorCore：顶部 Scalar Unit 每周期把 322-bit VLIW bundle 打进八个功能槽；VPU 经 2D vector lane 做逐元素；XLU 与 Transpose/Permute 处理跨 lane 归约与布局洗牌；四个 256×256 MXU 做脉动 matmul。累加队列把部分和排进 VMEM——喂入/排出阵列的软件管理 scratchpad。*

### TensorCore

**MXU** 就是脉动阵列。v1 出货一个 256×256 INT8 推理阵列；v2 是第一颗可训练 TPU，引入 128×128 单元做 BF16 乘、FP32 累加（INT8 从 v4 起以等价吞吐回到 MXU）。每 TensorCore 的单元数从此增长：v2 的 1 个 MXU → v3 的 2 个 → v4/v5e/v5p 的 4 个。Trillium 回到 256×256（每阵列每周期 65536 个 MAC 单元），Ironwood、8t、8i 都保持 256×256。

要算 $C = A \times B$，矩阵 B 的值预先每单元装一个权重： **weight-stationary** 数据流——这是 TPU 区别于别处 output-stationary 阵列的选择。激活从左缘进入，每周期推进一列，在每个单元与驻留权重相乘，部分和向下流入底部累加队列。数据一旦进入阵列就不再访存：每个权重被经过的每个激活复用，每个激活沿行复用 128（或 256）次。数据复用焊在硅里，不由 cache 仲裁。计算的主导成本不是乘法本身（几个皮焦），而是读写内存（每次访问贵 100–1000 倍）；脉动阵列从构造上删掉这笔成本。代价是 **填充不足（underfill）** ：256×256 阵列上跑 128×128 matmul 会浪费 75% 硅片，所以 XLA 把维度 tile、pad、调度成 128（或 v6e+ 的 256）的倍数，模型代码也按这些量子来写。

**VPU** 是第二小提琴，但在微架构上往往更有趣：每颗 TPU 是一台 2D 向量机，不是 1D SIMD 机。VPU 的寄存器堆持有 2D **VREG** 。v4/v5p 形状是 `(8, 128)` ：128 个 **lane** 宽、8 个 **sublane** 深，每核 32（v4）或 64（v5p）个寄存器，每个 (lane, sublane) 有 4 个独立浮点 ALU。lane 轴匹配脉动阵列输入宽度，因此 Trillium 与 Ironwood 上 lane 数大概随 MXU 扩到 256；Google 未公布 v5p 之后的 VPU 维度。sublane 轴让 VPU 以每 X 个时钟一次 matmul 的节奏把 tile 流过 MXU（X 是 sublane 维）。现代 TPU 程序大部分加速来自 **VPU/MXU 重叠** ：量化、layernorm、softmax、激活、bias-add 都在 VPU 上跑，同一周期 MXU 在后面跑 matmul。跨 lane 归约（任何 2D 向量 ISA 的别扭情况）由 **XLU** 处理：慢、贵，是已知的编译器热点。与 2D 形状不对齐的布局变换由专用 **Transpose/Permute Unit** 吸收，免得绕一圈内存。

**Scalar Unit** 是最小的块，也可以说最关键：单线程、双发射整数 ALU，32 个 32-bit 寄存器，4 KiB **SMEM** 存控制状态，配对存放程序的 Imem。它是唯一做 instruction fetch 的块；每周期拉一条 322-bit VLIW bundle，本地执行自己的两个标量槽（地址算术、循环计数、分支、sync-register 检查），把其余六槽派给芯片其余部分：2 个向量 ALU（VPU）、2 个向量 load/store（HBM↔VMEM DMA）、2 个矩阵（推/弹 MXU 队列）。块间同步是显式的： **sync flag** 跟踪 MXU 与 VPU 流水线何时忙，编译器插入 barrier 检查，而不是硬件跟踪依赖。Scalar Unit 让 TensorCore 其余部分看起来像固定功能数据流：每周期，一个地方决定八件事发生，没有动态 ROB 去撤销一次坏决定。

### 存储

片上存储层次与计算侧同一思路： **没有 cache，每一级都由软件管理** 。片外是 **HBM** （v2/v5e 16 GB，v3/v4/v6e 32 GB，v5p 95 GB，Ironwood 192 GB，v8 代 216–288 GB），片上是一层层手叠的显式可寻址 scratchpad。离计算最近的是 **VMEM** ，喂给 VPU 与 MXU 输入队列的向量 scratchpad：v4 32 MiB，v5e 128 MiB，推理调优的 v8i 拉到 384 MiB，就是为了把整份 KV cache 放在片上。其上是 **CMEM** ，v4 引入、128 MiB：HBM 与 VMEM 之间更慢、更大的 SRAM 中转区，吸收融合算子中间结果。Scalar Unit 有自己的 **SMEM** （v4 控制状态约 10 MiB）和很小的标量寄存器堆。程序里每个张量在编译期钉在某一层；XLA 的 buffer-assignment pass 跨层调度 DMA，让数据刚好在消费周期前到达。硬件不做 prefetch、不做 eviction、不做一致性；编译器做对了，阵列永不 stall；做错了，没有回退路径。

### SparseCore

打破脉动模具、位于 TensorCore 外的块是 **SparseCore** ，随 v4 引入。推荐与排序模型活在 embedding lookup 上（对巨大表的数十亿次索引），访问模式是稠密 matmul 的反面：不规则、间接、全互连。256×256 脉动阵列恰好是错误形状。SparseCore 是带 16 个计算 tile 与专用 **SPMEM** scratchpad 的 **数据流处理器** ，坐在 TensorCore 旁边，吸收 scatter、gather、segmented-reduce，以及分片 embedding 表产生的数据相关 all-to-all。这在 embedding 重的模型上拿到 5–7× 加速，代价约 5% 的 die 面积与功耗。v4 每芯片 4 个 SparseCore，v5p 保持，Trillium 降到 2，Ironwood 回到 4（双 die 布局每 chiplet 2 个）。v8i（Zebrafish）推理芯片完全去掉 SparseCore，换成 I/O chiplet 上的 **CAE（Collectives Acceleration Engine）** ：不同问题（自回归 decode 期间的集合归约），同一想法（从主核切出一小块加速器，吸收脉动阵列形状不对的负载）。

### 数值

TPU v1 仅 INT8 推理；v2 换成 **BF16** 作为规范训练格式：与 FP32 相同动态范围、一半内存、无需 loss scaling。v4 重新引入原生 INT8。Ironwood 再加原生 **FP8** （E4M3 与 E5M2），同一面积上吞吐约为 BF16 的 2 倍。v8 加原生 **FP4** 以及 MXU 内部的 **block-scale multiplication** ，删掉 Ironwood 仍在付的 VPU 反量化开销。现代每个 TensorCore 都硬件支持 **stochastic rounding** ：用较低尾数位当概率做舍入决策，从而在长训练中保持低精度累加的期望值，也是让 BF16/FP8 贴上 FP32 精度的小细节之一。

芯片边界上坐着 **ICI** 端口本身（2D torus 芯片 v2/v3/v5e/v6e 为 4 口，3D torus 旗舰 v4/v5p/v7/8t 为 6 口），以及做 scale-out 的 DCN NIC。从芯片视角，ICI 端口看起来只是 Core Sequencer 能在 VLIW bundle 里瞄准的另一组 DMA：远端张量 send 与 VMEM-to-HBM 传输是同一指令类，编译器把集合通信当作它为计算与本地内存构建的同一总调度的一部分。

### 押注

- **押注 1：脉动阵列。** Matmul 主导负载，所以把硅花在脉动阵列上。
- **押注 2：软件 scratchpad。** 计算便宜、内存昂贵，所以在阵列的线上复用数据，用软件管理的 scratchpad 替换 cache。
- **押注 3：编译器调度。** 负载静态可预测，所以把调度搬进编译器：VLIW 发射、无推测、无乱序、无动态调度器。
- **押注 4：只留 MAC 的硅。** 功耗比峰值更重要，所以删掉每一个不做乘加的晶体管：每个 cache tag、每个分支预测器、每个 ROB。
- **押注 5：阵列外专用引擎。** 稠密 matmul 阵列对某些真实负载（embedding、集合通信）形状不对，所以切出小型专用引擎（SparseCore、CAE），而不是扭曲主核去迁就它们。

### 扩展

TPU 的 scale-up 故事是 NVIDIA 的反面。NVLink + NVSwitch 让其他 GPU 的 HBM 看起来像本地内存（硬件管理的一致地址空间）；Google 的 ICI 是 **消息传递** 。没有远端 load 语义，没有 cache 一致性，没有 crossbar。每一次多芯片操作都是 **XLA** 编译出的显式集合通信。Scale-up 域不是靠 switch 织物，而是靠 **torus** （芯片直接连邻居并在边缘回绕），并在机柜边界用 **光路交换机** 缝合。

**Scale-up** ：经 ICI 把芯片直接织成 2D 或 3D torus。XLA 发出 SPMD 集合通信，把数千颗 TPU 紧密编排成一个程序。没有一致性，但有低延迟的巨大剖分带宽。

**Scale-out** ：经数据中心织物把 pod 联网：芯片数远超单个 ICI 域，每芯片带宽更低。今天：Virgo 处理东西向 TPU 流量（v8t+），Jupiter 处理南北向。Multislice + Pathways 跨 pod 编排 SPMD。

### Scale-up

ICI 链路直接从 TPU die 出来：高速串行 lane，64 芯片立方体（一个液冷机柜里的 4×4×4）内直接贴铜，立方体之间用光。每芯片合计 ICI 带宽从 v2 的约 250 GB/s 扩到 **Ironwood 双向 1.2 TB/s** ， **v8t** 再 **2×** 。拓扑按代交替：能效调优芯片（v2、v3、v5e、v6e）用 2D torus，旗舰（v4、v5p、v7、v8t）用 3D torus。

没有 NVIDIA 对应物的那一块是 **Palomar OCS** ： **3D-MEMS 光路交换机** ，坐在立方体之间。微小镜子物理旋转，把任意输入光纤映射到任意输出。一个 v4 superpod 用 48 个 Palomar 把 64 个立方体（4096 芯片）织成一个 3D torus；v5p 与 Ironwood 用同一方案放大。重配置是毫秒级而非纳秒级，但这没关系，因为 OCS 是 **电路交换** ：作业开始时选拓扑，跑一周，再为下一个负载重配。三个问题塌进一个组件：按负载重配拓扑（twisted torus 可把剖分带宽提高最多 70%）、按需切 sub-pod，以及 **容错** （芯片死掉时，OCS 光学换入备用立方体，运行继续，不丢失 ICI 域）。

![](https://pic3.zhimg.com/v2-d543d9bcd90e63d34ac9e655999a2dc4_r.jpg)
*TPU Ironwood superpod——左：一个 64 芯片立方体（4×4×4），3D torus，最近邻直接贴铜，每面边缘回绕。右：144 个立方体由 Palomar OCS（按负载重配拓扑的 3D-MEMS 光路交换机）缝成一个一致 ICI 域。*

这让 **superpod** 成为 scale-up 单位：角色等价于 NVIDIA 的 NVL72，规模大两个数量级。v4 是 4096 芯片；v5p 8960； **Ironwood（TPU v7）** 是 9216 芯片，144 个 64 芯片立方体，呈现 **1.77 PB HBM（约 68 PB/s）与 42.5 ExaFLOPS FP8** 作为一个一致 ICI 域。

**TPU 8t（Sunfish）** 拉到 **9600 芯片、2 PB HBM（约 62 PB/s）、121 ExaFLOPS FP4** 。 **TPU 8i（Zebrafish）** 是 **1024 芯片、约 295 TB HBM（8.8 PB/s）、约 10 ExaFLOPS FP4** 。8i 用名为 **Boardfly** 的新分层高基数拓扑替换 torus（4 芯片环 → 8 板组 → 最多 36 组经 OCS 相连），把 all-to-all 延迟砍半。这是为 MoE 推理设计的。3D torus 在集合通信是最近邻时出色（ring all-reduce 每周期用满每条链路），但 MoE expert routing 是相反图案——all-to-all：每颗芯片向其他每颗发送独特碎片，往返延迟由最长跳对决定。1024 芯片 3D torus 直径 16 跳；Boardfly 的 环 → 组 → OCS 层次把它压到 7。

### Scale-out

直到 TPU v7，scale-out 跑在单一织物上： **Jupiter** ，自 2022 年起 **脊骨全光** ，经 **Apollo OCS** ——与 Palomar 同一 3D-MEMS 家族，放大到整栋楼。Google 从机柜到数据中心脊骨每一层都用同一原语（光路交换）；这是别人没有的架构签名。Jupiter 今天每栋楼承载 13 Pb/s 剖分带宽。

到了 **TPU 8t** ，scale-out 拆成两张织物。东西向 TPU-to-TPU 流量迁到 **Virgo** ，专用加速器织物；Jupiter 保留 **南北向** 角色：存储访问、通用计算、跨站点扩展。Virgo 是建在 **高基数** 交换机上的 **平坦、两层、非阻塞** 拓扑：任意两颗 TPU 最多隔两个交换机。一个 Virgo 集群以 47 Pb/s 剖分带宽连接 134000+ 颗 TPU 8t（相对上一代 DCN，每芯片带宽 4×、空载延迟低 40%），带多平面故障隔离与亚毫秒遥测，让调度器在掉队者毁掉一步之前杀掉它们。架构回报是各层可独立演化：scale-up、东西向 scale-out、前端可以按不同节奏迭代，而不必重布其他层。

![](https://pic3.zhimg.com/v2-63fad72f606600cee6b26606cb58b826_r.jpg)
*TPU 8t scale-out——东西向 TPU-to-TPU 流量穿过 Virgo，平坦两层非阻塞高基数织物，任意 TPU 距其他 TPU 最多两跳（134000+ TPU，47 Pb/s 剖分）。南北向——存储、通用计算、跨站点——留在 Jupiter，自 2022 年起脊骨经 Apollo OCS 全光。*

每芯片 scale-out 带宽大约是 **Ironwood 上 100 Gbps** ， **v8t 上 4×** ，但仍比每芯片 ICI 低两个数量级。这个带宽缺口决定划分：张量并行与 MoE expert routing 留在 ICI 内；数据并行与流水线并行穿过 scale-out 织物。

Google 的 **Multislice** 框架接入 **XLA** ，让单个 SPMD 程序跨越不同 pod 里的多个 slice；编译器发出分层集合通信（每个 slice 内 ring all-reduce，之上再跨 slice reduce）。结构正是隐藏 ICI/DCN 带宽缺口的手法：尽可能多的工作留在 slice 内走快速 ICI，只把跨 slice 残差付给慢织物。

其上是 **Pathways** 。NCCL + Slurm + Megatron 式调度器用许多控制器驱动 SPMD；Pathways 用 **一个** 客户端驱动整个作业，并把多个「岛屿」（各有自己 ICI 域的 pod）经 DCN 虚拟化。它做 gang scheduling、弹性训练（slice 失败时 OCS 重塑拓扑，Pathways 在新形状上从上一检查点恢复），以及跨区域编排。 **Gemini Ultra** 是第一个跨多个数据中心训练的前沿模型；Pathways 把它们缝成一个同步 SPMD 作业。

哲学是： **编译器是调度器，torus 是拓扑，光交换机是从机柜到数据中心每一层的通用可重构衬底** 。

### 软件

TPU 栈是 **编译器驱动** 的，而 CUDA 是 **kernel 驱动** 的。在 GPU 上，开发者写 kernel，框架把 kernel 串起来；编译器的工作大多是局部的。在 TPU 上，开发者用 **JAX** 写数值程序， **XLA** 负责其下的一切：哪些运算融合、每个张量住哪、如何在 2D 向量寄存器上布局、HBM 到 VMEM 的 DMA 何时发出、322-bit VLIW bundle 如何调度、程序如何在数千芯片上分片。没有硬件回退：没有 warp scheduler、没有 cache、没有乱序引擎去掩盖坏调度。编译器就是系统。权衡是架构的核心权衡： **XLA 能在不手调的情况下更接近理论上限，但要闭上剩余缺口更难** 。

编译路径是 **JAX → JAXpr → StableHLO → HLO → LLO → VLIW bundle** 。 **JAX** 在 jit 下把 Python 函数 trace 成带类型的函数式 IR（JAXpr），降到 **StableHLO** （OpenXLA 标准化、版本化的约 100 个静态形状原语，所有前端现在都发出它），XLA 作为 **HLO** 摄入并跑 pass 管道： **运算融合** （把逐点 + 归约 + matmul 塌成一个 kernel，中间结果永不打 HBM）、 **布局指派** （决定每个张量的 2D tiling，使其无需转置就流入 MXU：比 1D SIMD 机难得多，因为寄存器与脉动输入都是 2D）、 **buffer assignment** （每个张量钉在 VMEM、CMEM 或 HBM，重叠窗口预先算好）、 **SPMD 划分** ，最后是填满每条 bundle 全部八槽的 VLIW 调度器。HLO 降到 **LLO** （Low-Level Optimizer，TPU 专用 IR），LLO 发出最终 VLIW 流。编得好的程序每周期在同一 bundle 里重叠 MXU 脉动执行、VPU 逐元素数学、以及 HBM↔VMEM DMA。

多芯片执行是 **SPMD** ：一个程序、分片数据、分层集合通信，由 **GSPMD** 发出（正被 **Shardy** 替换——MLIR 原生后继，计划 2026 年初成为默认）。用户用 **Mesh** + **PartitionSpec** 在少数关键张量上声明式表达分片；编译器把分片传播过图的其余部分，并在布局变化处插入 all-reduce、all-gather、reduce-scatter。编译器选错集合通信时， **`shard_map`** 把用户降到 **手动 SPMD** （每设备代码、显式本地形状与显式集合通信），可组合进 `jit` ，于是单个 kernel 可以手划分，而不放弃其他地方的自动划分。这是 PyTorch 惯用语的反面： **FSDP** 与 **DeepSpeed** 用运行时在模块边界发集合通信包住模型；GSPMD/Shardy 把整张图当作编译器问题来划分。

**Pallas** 是逃生口：JAX 的 kernel 语言，大致是 GPU 上 **Triton** 的 TPU 等价物。Pallas kernel 用 JAX 风味的 Python 写，经 **Mosaic** （基于 MLIR 的 TPU 后端）降到 LLO，再作为 custom op 嵌回 HLO。它存在是因为 XLA 并不总能合成新 attention 变体、融合 MoE dispatch、或任何需要手动 VMEM tiling 与 DMA 调度的最优： **FlashAttention 级** 优化，赢在调度而非代数。 **Pallas:Mosaic-GPU** 用同一前端打 H100/Blackwell，于是 kernel 作者可以写一次、降到任一衬底。其上的库层一律 JAX 原生： **Flax NNX** 做模块， **Optax** 做优化器， **Orbax** 做异步分布式检查点， **Grain** 做输入管道， **Tunix** 做后训练/RL， **Qwix** 做量化。Google 的参考训练栈（LLM 的 **MaxText** ，含 DeepSeek-V3 级 MoE；以及 Flux、Wan 2.1 的 **MaxDiffusion** ）坐在顶上，纯 JAX； **Pathways** 坐在下面，以 **pathwaysutils** 暴露给用户，于是单个 Python 客户端可以驱动跨数千芯片、数个 pod 岛屿的作业，而不放弃 JAX 编程模型。

PyTorch 路径真实存在，但是二等公民。 **torch_xla** 用 **LazyTensor** 机制：每个 PyTorch op 记入一张 HLO 图，在下一个 barrier 编译，编译产物按图形状哈希缓存。PyTorch/XLA 2.x 加了 **GSPMD 风格分片标注** 、经 XLA 后端的 **`torch.compile` 集成** 、 **JAX bridge** ，以及（PyTorch/XLA 2.7）C++11-ABI 构建与明显更快的 tracing。与 JAX 的差距是真实的（JAX 原语更干净地映射到 StableHLO，复杂并行策略覆盖更好），这就是为什么 **vLLM TPU** （由 Cloud Next 2025 宣布的 **tpu-inference** 插件驱动）把 **每一个** 模型——无论 JAX 定义还是 PyTorch 定义——都经 **统一的 JAX→XLA 路径** 下降。2026 年 4 月宣布的 **TorchTPU** 是 Google 的回应：带 eager mode、 `torch.distributed` 与经 XLA 的 `torch.compile` 的原生 PyTorch 体验，目标是替换 torch_xla。

相对 CUDA，TPU 生态是 **中心化的，不是蔓延的** 。框架以下几乎一切（XLA、JAX、Flax、Optax、Pallas、MaxText、Pathways、Shardy、Mosaic）都由 Google 自己开源，与硅片同步演化。第三方 kernel 远少于 CUDA 数十年的积累；负载长得奇怪时护城河更薄，长得像 Gemini 时更深。最近的 **Ironwood（v7）「协同设计 AI 栈」** 语言是明确框架：芯片、ICI 织物、OCS、XLA、Pathways、Pallas、MaxText、vLLM 与 Pathways 作为一件产品共发，v8t/v8i 在单一 tpu-inference 下降路径下延续同一模型。 **Triton** 与 **`torch.compile`** 在 NVIDIA 侧收窄差距（kernel 驱动与编译器驱动正在收敛），但哲学两极仍真实： **在 TPU 上编译器是唯一要紧的接口；在 GPU 上编译器只是若干接口之一。**

## AMD GPU

**AMD Instinct GPU** 建立在与 NVIDIA 不同的押注上：NVIDIA 每一代扩大每个 SM **能做什么** ，AMD 自 GCN（2012）以来把 **Compute Unit** 保持保守，把再投资放进封装：自 2021 年起每一代在 HBM 容量上追平或超过同期 NVIDIA 旗舰；第一颗 **3D 堆叠** 数据中心 GPU（CDNA 3）；第一颗一致的 **CPU+GPU APU** （MI300A）；以及 **开放生态** （ROCm、HIP、OCP MX、UALink）。

### 架构

术语对照：

| --- | --- |

NVIDIA 的架构野心活在每个 SM **内部** （每一代新的张量原语、新的异步机械、新的操作数存储）；AMD 的活在 CU **之间** ——能把多少个键合成一个一致封装。CU 本身保守：四个 16-lane SIMD、一个共享标量单元、64 KB Local Data Share、L1 向量 cache、每 SIMD 的 VGPR 文件加 CU 共享的 SGPR 池，以及（自 CDNA 1）跑 MFMA 的 Matrix Core。形状自 2012 年 GCN 以来没有实质变化；缩放的是数量（MI100 120 CU，MI250X 220，MI300X 304，MI355X 256）以及把它们键合的封装。64 线程的 wavefront 用 4 个周期流过 16 条 SIMD lane，每个 SIMD 驻留许多 wavefront，调度器切换以掩盖 stall。这里没有什么稀奇构造；CDNA 有趣的是 CU **外面** 的一切。

计算

CU 内部，SIMD 与 Matrix Core 并排跑。四个 SIMD 处理一切逐元素：激活、归一化、残差、地址算术。Matrix Core 处理 matmul。分裂与 NVIDIA 的 CUDA Core / Tensor Core 相同，但矩阵抽象沿非常不同的曲线演化。

NVIDIA 的 Tensor Core 沿线程层次攀升：Volta 上 32 线程 warp，Hopper 上 128 线程 warp-group，Blackwell 上单线程加可选双 SM cluster。AMD 的 Matrix Core 原地不动。每一代 MFMA（从 2020 的 MI100 到 2025 的 MI355X）都是 wavefront 范围：一个 wave64 发一条矩阵 op（ `V_MFMA_*` ），四个 SIMD 协作驱动，操作数来自 wavefront 的寄存器堆：A 与 B 来自 VGPR，C 与 D 通常来自专用 AGPR 文件。指令更快了，格式集更宽了，但发射者与范围没有变。馈送侧唯一让步来自 CDNA 4：专用的 **从 LDS 做 MFMA 转置加载** ，把操作数按 Matrix Core 想要的布局交过去，精神上接近 NVIDIA 的 TMA，但矩阵 op 本身仍是 wave 发射。

吞吐数字直接讲格式故事。CDNA 1 于 2020 年以每 CU 每周期 256 / 1024 / 512 / 1024 FLOP 推出 FP32 / FP16 / BF16 / INT8，与 A100 同期原生 BF16。CDNA 2 把 FP64 路径加倍成满速率矩阵、每 CU 每周期 256 FLOP：独特属于 AMD，把 MI250X 送进 Frontier 的押注。CDNA 3 在 FP8 上与 H100 持平、4096 FLOP（E4M3 + E5M2），加上 2:4 结构化稀疏，以及一条 TF32 等价路径：截断尾数后以 FP64 矩阵速率跑 FP32 matmul。CDNA 4 再加倍到 FP4 的 16384 FLOP 与带 OCP MX 块缩放的 FP6，并允许一条 MFMA 里可混合的 A/B 精度：例如 FP8 × FP4。同一代把每 CU FP64 吞吐砍半——第一颗 AMD 芯片用 AI 密度换 HPC 密度，而不是两者都出货。

Wavefront 范围决策体现在两种成本上。

**发散。** 半空的 wave64 浪费 32 条 lane，半空的 warp32 浪费 16 条。对大多均匀控制流的负载这是小代价；对不规则负载会疼。

**重叠。** NVIDIA 的异步、descriptor 驱动 matmul 把发射与执行解耦：发射线程开火后继续走；Tensor Core 在后台跑；warp 可以在上一次 matmul 仍在飞时跑 softmax、打 mask、或预载下一块 tile。AMD 的 wavefront 集体 MFMA 不给 wave 等价物：发出 matmul 的同一个 wave 不能在它 pending 时同时做有意义的向量工作。重叠可以跨 **不同** wavefront，但必须用显式 wavefront barrier 在软件里分期，更脆，也消耗更多 wave 槽与寄存器。

这有多要紧取决于负载。 **纯稠密 GEMM** （DGEMM，大批训练的内循环）在 matmul 期间没什么有用的事可做；两边引擎都饱和；异步买不到多少。这些恰好是 AMD 历史上在百亿亿次 HPC 领先的负载（Frontier 上的 MI250X，El Capitan 上的 MI300A）。 **Transformer attention** （FlashAttention-3、FA4）把 matmul 与 softmax、masking、KV-cache 读交错，异步重叠就是那些 kernel 的全部结构。AMD 必须用手重造这条流水线，落后于 NVIDIA 的硬件级支持。 **MoE dispatch、paged attention、speculative decode** 同属一营：地址不规则、想与 matmul 并跑的工作。

NVIDIA 的矩阵指令抽象跨代走得更远（warp → warp-group → 单线程异步 + cluster），AMD 没有跟上。

### 存储

AMD 的存储层次比 NVIDIA **更少** 通用层级，但有一块 NVIDIA 完全没有的巨型 cache。从 CU 向外：64 KB LDS scratchpad（软件管理、32 bank，NVIDIA SMEM 的 AMD 类比）、向量 L1（早期 CDNA 16 KB，MI300X 起 32 KB）、每 XCD 几 MB 的 L2。L2 跨 XCD **不一致** ；一致性发生在 L2 之上一层。

那一层是 Infinity Cache：MI300X 上 256 MB，分布在四个 IOD 上，16 路组相联，测得约 12 TB/s，超过 MI300X 5.3 TB/s HBM3 的两倍。它起源于 RDNA 游戏 GPU，用来补偿窄 GDDR 总线；AMD 在 CDNA 3 上把这套 IP 复用到 AI，attention 的 KV 复用与权重复用异常适合大型 LLC。NVIDIA 押更大的 HBM 带宽（B200 上 8 TB/s，Rubin 上随 HBM4 缩放），AMD 押 cache。

片外，HBM 容量激进增长：MI100 / MI210 / MI250X / MI300X / MI325X / MI350X 上 32 → 64 → 128 → 192 → 256 → 288 GB，自 2021 年起每一代追平或超过同期 NVIDIA 旗舰。押注是：推理负载越来越受容量约束，内存更多的芯片会赢。

### 数值

格式轨迹追随 AI 硅片共享的精度减半模式：FP32 → FP16 → FP8 → FP4，每一步用更细粒度缩放挽回精度。AMD 特有的轴是 **开放** 。CDNA 4 的 FP4 与 FP6 用 **OCP MX block-scale multiplication** ：与 Blackwell 的 MXFP4、TPU v8 的 MXU 同一数值格式，但由 AMD 参与创立的开放联盟（AMD、NVIDIA、Intel、Meta、Microsoft、Qualcomm、ARM）规定，而不是任一单一厂商。MI355X 出货的格式与 B200、TPU v8 相同。

CDNA 4 的拐点值得单独一行：每 CU FP64 吞吐砍半。MI300X 同时服务训练、HPC 与推理；MI355X 首先是一颗 AI 芯片。驱动 Frontier 的满速率 FP64 矩阵押注没有被杀死，但不再扛大梁。

### Chiplet

封装是 CDNA 不再像 NVIDIA、开始成为别的东西的地方。

CDNA 1 的 MI100 是单片 7 nm。CDNA 2 的 MI250X 是 AMD 第一颗多芯片 GPU：两颗 Aldebaran GCD 在 2.5D EFB 有机衬底上并排，由封装内 4 条 Infinity Fabric 以合计 400 GB/s 相连，但对软件呈现为两颗独立 GPU。

CDNA 3 是改变一切的那一步。八颗 **XCD** （TSMC N5，各约 115 mm²）经 **TSMC SoIC** hybrid bonding（亚微米间距 **TSV** ，无 microbump）3D 堆到下面四颗 **I/O die** （TSMC N6）上。IOD 承载 Infinity Cache、HBM3 PHY、Infinity Fabric 链路与 PCIe Gen 5；每个 IOD 上面托管两颗 XCD，旁边两堆 HBM。四个 IOD 由 **Infinity Fabric AP** 以 4.8 TB/s 剖分缝合，于是 1530 亿晶体管的封装对 kernel 看起来像一颗 GPU：cache 与地址空间在 IOD 层统一。NVIDIA 直到 H100 都保持单片，只在 B200 上经 2.5D CoWoS-L 走到两颗光罩极限 die。AMD 早一代走到 3D 堆叠，每 die 面积更小：同一封装前沿上的不同押注。

**MI300A APU** 把押注推得更远。把 8 颗 XCD 中的 2 颗换成三颗 Zen 4 **CCD** ，留下 HBM、Infinity Cache 与 IOD，让 CPU 与 GPU 共享由 HBM3 支撑、硬件一致的同一物理地址空间。没有主机–设备拷贝。没有 pinned memory。路径上没有 PCIe。Zen 4 核与 CDNA 3 XCD 读同一页。NVIDIA 的 Grace-Hopper 经 NVLink-C2C 桥接 **两** 个封装；MI300A 是 **一个** 。 **El Capitan** （11039 个节点，每节点 4× MI300A）是证明它的部署。

CDNA 4 的 MI355X 上，八颗 XCD 仍经 SoIC 3D 堆到底 die，但 XCD 迁到 TSMC N3P，各 32 个活跃 CU（共 256，对比 MI300X 的 304；每 XCD 数量下降是为更大 Matrix Core 与 160 KB LDS 腾面积）。MI300X 的四个 IOD 塌成两个，每个在 TSMC N6 上宽一倍，上面托管四颗 XCD，旁边四堆 HBM3E。每个 IOD 现在携带 256 MB Infinity Cache 的 128 MB 切片、一半 HBM PHY、它那份 Infinity Fabric 链路，以及 PCIe Gen 5。两颗 IOD 之间的 Infinity Fabric AP 以 5.5 TB/s 剖分运行（比 CDNA 3 高约 15%），八堆改为 12-Hi HBM3E，288 GB、8 TB/s，同一引脚数上比 MI300X 多 50% 容量。封装合计 1850 亿晶体管，对 kernel 仍呈现为一颗 GPU。

### 押注

- **押注 1：先 HPC 再 AI。** HPC 与 AI 是同一押注， **直到它们不是** ：从 CDNA 2 到 CDNA 3 出货满速率 FP64 矩阵，然后在推理经济明确偏向低精度时于 CDNA 4 分叉。
- **押注 2：内存容量。** 自 2021 年起每一代在 HBM 容量上追平或超过同期 NVIDIA 旗舰，并加 256 MB 末级 Infinity Cache，吸收 H100 必须打 HBM 才能拿到的复用。
- **押注 3：更早的 3D 堆叠。** 在 NVIDIA 之前把计算 3D 堆到 cache 与 I/O 上：2023 年 TSMC SoIC hybrid-bond 的 XCD 在 IOD 上，而 NVIDIA 直到 2025 年仍是单片。
- **押注 4：一致的 CPU+GPU。** MI300A APU 是有史以来最激进的 chiplet 产品，El Capitan 部署是证明。
- **押注 5：开放的 scale-up 织物。** UALink 与 OCP MX，对抗 NVLink 与专有 FP4。

### 扩展

内存押注有扩展后果：8 颗 MI300X 持有 1.5 TB HBM、8 颗 MI350X 持有 2.3 TB 时，你可以在单个 8-GPU 盒子里用 FP8 装下 405B 参数模型（权重、KV cache，以及更长上下文与更大 batch 的余量），而同一模型在 8× H100（640 GB）上需要仔细分片。对 2024–2025 的推理负载，AMD 的 scale-up 不必在机柜上匹配 NVL72 就能在盒子上竞争。对前沿 **训练** ，它必须匹配，而 AMD 直到 2026 年才有答案。

**Scale-up** ：经 Infinity Fabric 把 GPU 绑进一个一致内存域。到 MI355X 为止，这停在 8-GPU OAM 盒子（每 GPU 896 GB/s mesh）。Helios 经 UALink 扩到 72-GPU 机柜，发布时经以太网隧道（UALoE），2027 年起原生。

**Scale-out** ：经以太网把这些域联网。没有 InfiniBand。Pensando NIC（Pollara 400、Vulcano 800）实现 Ultra Ethernet Consortium 的 UET RDMA 传输；Broadcom Tomahawk 6 提供 switch ASIC 与 CPO。

### Scale-up

到 MI355X，AMD 的 scale-up 意味着经 Infinity Fabric 的 **8-GPU OAM 平台** 。每颗 MI300X 有 7 条 IF 链路（盒子里连到每一个 peer），双向 128 GB/s，在全连接全互连拓扑里给出每 GPU 896 GB/s mesh 带宽。MI350X 把每条链路抬到 153.6 GB/s（每 GPU 约 1075 GB/s），但保持 8-GPU 形状。平台符合 OCP 的 UBB 2.0：与 NVIDIA HGX 基板同一机械插座，于是服务器厂商可以在同一机箱上出货 AMD 或 NVIDIA，而不必重设计系统。

AMD 到 MI355X 没有出货 NVL72 的机柜级等价物。在 MI300X 集群上跑更大模型的客户，经以太网跨多个 8-GPU 盒子扩展，为 NVIDIA 用户能留在 scale-up 内的东西付 scale-out 延迟。这是对训练要紧的缺口，也是 **Helios** 要闭上的缺口。

![](https://picx.zhimg.com/v2-439a0657102ad21a4b42ec1ed9e59fdb_r.jpg)
*AMD Helios：72 颗 MI455X GPU 坐在 Open Rack Wide 机箱里一排 UALink 交换机下，加入一个一致 UALink 内存域。发布时织物跑在 UALoE（Infinity Fabric 经以太网隧道）上，作为 2027 年原生 UALink 交换硅片出货前的权宜。每颗 GPU 外出带一颗 Pensando Vulcano 800 NIC。*

Helios 是 AMD 第一个机柜级 scale-up 域，2026 下半年与 MI455X 一同出货。每机柜 72 GPU，约 31 TB HBM4，1.4 PB/s 合计 HBM 带宽，2.9 ExaFLOPS FP4 / 1.4 ExaFLOPS FP8，260 TB/s scale-up 带宽，43 TB/s scale-out。外形是 **Open Rack Wide（ORW）** （Meta 2025 年提交给 OCP，双宽、液冷），不是 AMD 专有机箱。建立在 Meta 参考设计上而不是从零设计机柜，是故意的 AMD 押注：任何标准化到 ORW 的超大规模厂商都可以部署 Helios，而不必做定制数据中心设施工作。

织物是 **UALink** ：Ultra Accelerator Link，AMD 与 Apple、AWS、Cisco、Google、HPE、Intel、Meta、Microsoft、Synopsys 共同创立的开放联盟标准。UALink 200G 1.0（2025 年 4 月）定义 200 GT/s lane 与每方向 800 Gbps，交换拓扑可扩到每 pod 1024 个加速器。承诺是与 NVLink 可比的 cache 一致互连，但不被独占：任何厂商都能做 UALink 交换机，任何加速器都能讲 UALink，标准属于联盟而不是最强卖家。

但有个代价： **原生 UALink 交换硅片要到 2027 年才大量出货** 。Astera Labs 的 Scorpio，以及 Auradine、Enfabrica、Xconn 的竞争部件，都瞄准 2026 末 / 2027 部署。Helios 发布时用 **UALoE** （Infinity Fabric 经标准以太网隧道）作为权宜，在等待原生 UALink 织物时保住编程模型。原生 UALink 交换随 2027 年的 MI500 到来。发布时，Helios 更接近快速的以太网隧道一致集群，而不是 NVL72 真正 cache 一致的 NVLink 域：时间线上的真实让步，用来换 2026 下半年拿出有竞争力的产品。

### Scale-out

AMD 不出货 InfiniBand。整套 scale-out 栈是以太网，锚定在另一个开放标准： **Ultra Ethernet Consortium（UEC）** 。

UEC 1.0（2025 年 6 月发布）定义 **Ultra Ethernet Transport（UET）** ：标准以太网上的新 RDMA 传输，带 packet spraying、基于 SACK 的选择性重传，以及现代拥塞控制。UET 不是 RoCEv2（后者把 InfiniBand 传输封进以太网帧）；它是为 scale-out AI 织物对 RDMA 语义的干净重设计。AMD 与 Broadcom、Cisco、Meta、Microsoft 同为创始成员。与 UALink 同一招：拥有标准，而不是实现。

![](https://pic3.zhimg.com/v2-5e1be2f1643d34ff40a251f26ef3385a_r.jpg)
*AMD scale-out——Helios 机柜经锚定在开放 Ultra Ethernet（UEC）标准上的标准以太网互谈。UET 用干净重设计的 RDMA 语义替换 RoCEv2。每颗 GPU 带一颗 Pensando Vulcano 800 NIC（PCIe Gen 6、800 GbE、UEC 1.0）；机柜间交换是带共封装光学的 Broadcom Tomahawk 6。AMD 拥有 NIC 层，交换机与光学是合*

NIC 是 **Pensando** ，AMD 2022 年收购的网络创业公司。 **Pollara 400** 是当前 AI NIC：400 GbE、P4 可编程、UEC-ready、PCIe Gen 5，配对 MI300X / MI355X。 **Vulcano 800** 2026 年与 MI455X 一同出货：符合 UEC 1.0、PCIe Gen 6、原生 UALink 接口，每 GPU scale-out 带宽为 Pollara 的 8 倍。 **Salina 400** 是前端 DPU（16× Arm Neoverse-N1，双 400 GbE），做存储 / SDN / 防火墙，等价于 NVIDIA 的 BlueField，区别于 AI 后端 NIC。

但交换机硅片不是 AMD 的。Helios 的 43 TB/s scale-out 织物经 **Broadcom Tomahawk 6** ：102.4 Tbps 以太网 switch ASIC，带共封装光学（「Davisson」）。AMD 没有自家 CPO，也没有自家 switch ASIC；光学层是合作伙伴硅片。NVIDIA 拥有整栈：InfiniBand、Spectrum-X 以太网、ConnectX、BlueField、Quantum-X Photonics CPO，全是自家。AMD 拥有一层（经 Pensando 的 NIC + DPU），并押注开放标准加最佳品种合作伙伴硅片会跑赢垂直整合。

行业已经朝 AMD 的方向走。Dell’Oro 报告 2025 年以太网处理的 AI scale-out 织物量超过 InfiniBand 两倍以上；AWS、Microsoft、Meta、Oracle 与 xAI 都已为基于 AMD 的 AI 集群标准化到以太网。剩下的问题不是以太网能否在 RDMA 语义上匹配 InfiniBand（UEC 闭上那个缺口），而是 Helios 能否足够快地闭上与 NVL72 的 **机柜级** 缺口，以赢得今天默认 NVIDIA 的前沿训练负载。

### 软件

**ROCm** 是 **CUDA** 的开源对位。NVIDIA 的栈专有且垂直整合（cuBLAS、cuDNN、TensorRT-LLM 作为仅 NVIDIA 维护的二进制 blob 出货），ROCm 原生在 GitHub 上，押开放标准（PyTorch、Triton、vLLM、OCP MX）而不是围墙花园库集。与 NVIDIA 的软件差距是真实的，但 AMD 的策略是经开放社区闭上它，而不是从零建一套平行 CUDA 栈。

栈底是 **HIP** ，AMD 的 CUDA 兼容 C++ 运行时。 **hipify** 自动把 CUDA 源译成 HIP。大批 HPC 代码（HACC、Laghos、QMCPack）开箱移植率 80–95%：CORAL-2 数字。现代 AI kernel 移植更差：任何伸手去拿 Hopper 或 Blackwell 专用原语（TMA descriptor、wgmma、 `tcgen05.mma` ）的东西，都没有干净的 ROCm 类比，必须手写重写。

HIP 之上是按名称一对一镜像 NVIDIA 的库层： **rocBLAS** 对 cuBLAS； **hipBLASLt** 对 cuBLASLt； **MIOpen** 对 cuDNN； **RCCL** 对 NCCL； **Composable Kernel** （及其现代 ck-tile DSL）对 CUTLASS；rocprofv3 / rocprof-sys / rocprof-compute 对 Nsight 家族。没有 TensorRT-LLM 的第一方类比。AMD 的答案是支持 **vLLM** 作为开源服务引擎，并出货插入其中的 AMD 专用算子（ **AITER** ）；vLLM 的专用 ROCm CI 在 2026 年初把测试通过率从 37% 拉到 93%。

PyTorch 路径是一等公民。Eager-mode PyTorch 自 2018 年起就在 ROCm 上跑； `torch.compile` 经 Triton 下降，Triton 的 ROCm 后端（以及用于提前编译数学 kernel 的 AOTriton）在上游。没有 XLA 风格中间 IR；ROCm 直接编译到 HIP / Triton / CK。随着 Triton 成为 PyTorch 的默认 kernel 路径，大量移植成本蒸发：经 `torch.compile` 跑的 kernel 无需改源就能在 CUDA 与 ROCm 上工作。这是 AMD 开放策略底下的架构押注：Triton 的 Python DSL 成为跨厂商通用语，绕开对 CUDA 等价 kernel 生态的需求。

**FlashAttention** 是承重案例。 **FA2** 经 Composable Kernel 在 MI300X 上生产；PyTorch 在 ROCm 上默认 CK 或 AOTriton。 **FA3** （Hopper 调优）经 AITER + CK 部分支持，但 Dao-AILab 的规范实现仍仅 CUDA。 **FA4** （Blackwell，2026 年 3 月）完全没有 ROCm 移植。 **HipKittens** ，Hazy Research 对 ThunderKittens 的 MI355X 移植（2025 年 11 月），声称用约 500 行达到与手调 AITER 的前向持平。模式是：开源学术 kernel 在 NVIDIA 之后数月闭上 AMD 尾巴，而不是数年。

生产部署验证了策略。Microsoft Azure 的 **ND MI300X v5** 实例于 2024 年 5 月 GA；OpenAI 在其上跑 GPT 推理。Meta 经 Grand Teton 平台在 MI300X 上出货 Llama 3 / Llama 4 推理。Oracle OCI 的 **BM.GPU.MI300X.8** 于 2024 年 9 月 GA，MI355X 于 2026 年跟上。这些是超大规模的真实服务机队，不是试点。

诚实的差距仍真实。独立基准（Phoronix，2026 年 3 月）把 ROCm 7.2 放在标准 PyTorch / vLLM / SGLang 负载上 **比等价 CUDA 慢 10–25%** ，同等精度、等价硅片。ROCm 7 达到了 **功能对等** ，但不是 **性能对等** 。FlashAttention-4 尾巴（利用 Blackwell 最新原语的研究代码）是 NVIDIA 护城河最耐久的地方；它没有干净的 ROCm 类比，等待手写 AITER kernel 或 HipKittens 级社区移植。NVIDIA 把工程师运进前沿实验室；AMD 经 GitHub 运 kernel。策略在共同负载上收敛（Llama 推理、attention、稠密 Transformer 训练），但新研究代码的长尾仍让 MI300X / MI355X 部署付出 NVIDIA 用户不付的工程时间。

## Cerebras WSE

**Cerebras** 造 **有史以来出货的最大芯片** 。哲学是：存储墙是切开晶圆的后果。晶圆厂在 300 mm 硅上印出数十颗 die 再锯开；行业随后把最尖端的工程（HBM、NVLink、CoWoS、每机柜 5184 根铜缆）花在把碎片以远低于片上带宽的一小部分重新连回去。Cerebras 跳过锯子。 **晶圆级引擎（Wafer-Scale Engine）** 是一整块硅：84 个光罩场、46225 mm²、900000 个数据流核，以及片上每一字节 SRAM 距计算单元一个周期。

| 2021 | WSE-2 | CS-2 | 7 nm：850000 核、40 GB SRAM。Weight streaming 把权重移出晶圆进 MemoryX |
| 2023 | Condor Galaxy | CG-1 | 与 G42 共建的 64 系统集群；训练 Jais 阿拉伯语 LLM 家族 |

### 架构

GPU 是层次：线程在 warp 里、warp 在 SM 里，die 在封装里、封装在机柜里，每个边界有自己的带宽、延迟、编程构造；每台由 die 建成的加速器都继承某种版本。WSE 是一张 **平面** ：900000 个相同核心沿 2D mesh 边对边铺开，没有共享 cache、没有全局内存、一个核与另外 899999 个之间没有任何边界。每个核很小，WSE-2 上约 38000 µm²，大约一半 SRAM 一半逻辑，峰值 30 mW：48 kB 本地 SRAM、十六个通用寄存器、六级流水线、4-wide FP16 FMAC SIMD（WSE-3 上 8-wide），以及进入织物的五端口路由器。执行是 **数据流** ：核空闲直到一个 **wavelet** 到达，wavelet 里的控制位选择哪个 handler 任务开火，八个硬件 **microthread** 随张量操作数到达与排出而逐周期切换。没有 warp，没有 warp scheduler，没有会 miss 的 cache，没有 ROB： **数据的到达就是调度** 。

*放大一个 Cerebras 核——五端口织物路由器，24 色静态路由，喂给跑八个 microthread 的数据流任务调度器；下面是 GPR 与 44 个张量描述符寄存器、八个单周期 bank 里的 48 kB 本地 SRAM 挨着 FMAC SIMD，以及发送侧收割非结构化稀疏的零过滤器。*

晶圆

步进器一次曝光一个光罩，每枪约 850 mm²，这就是为什么每颗常规芯片都活在那道天花板下（也是为什么 NVIDIA 一顶到它，B200 就变成两颗 die）。Cerebras 像 TSMC 的任何其他客户一样，把同一颗约 550 mm² 的 die 印 84 次、排成 12×7，然后——在与 TSMC 共同开发的工艺里——在锯子通常会跑的  mm 划片槽上铺额外高层金属。Mesh 以源同步并行接口跨过每道缝（WSE-3 上每 die 2880 GB/s），整个跨 die 层功耗约 97 W。对软件，接缝不存在：一张均匀 mesh，一颗芯片。

晶圆级以前试过，败在良率：整块晶圆计算机上一个缺陷就杀死整片，这就是 1980 年代埋葬这个想法的原因。Cerebras 的答案是粒度。H100 上一个缺陷禁用整个约 6 mm² 的 SM；WSE 上同一缺陷禁用一个 0.05 mm² 的核。WSE-3 制造约 970000 核，出货 900000：约 7% 备用池，加上冗余织物链路，让硬件绕过每个缺陷重映射，恢复完整逻辑 mesh。

### 核心

核不寻常的不是数据通路；而是一条指令 **是什么** 。十六个通用寄存器旁边坐着 **44 个数据结构寄存器（DSR）** ，每个持有一个张量描述符：基址、范围、步长，最多四维。指令用 DSR 命名操作数，于是一条 FMAC 指令说的是 *把到达的流与这个驻留张量相乘并累加进那个* ，硬件在张量持续期间流过元素。乘法外没有软件循环，每个元素也没有 instruction fetch；循环活在描述符里。NVIDIA 花了五代 Tensor Core 把 matmul 走向单条 descriptor 驱动的命令；在 WSE 核上，张量指令没有别的形态。

定序是织物的工作。一种 color 是编译期绑定 handler 任务的静态路由虚通道，于是在一种 color 上发送 wavelet **就是** 在目的核上调用代码：16 位控制是调用，16 位数据是参数。 **任务调度器** 把在飞的张量运算持在核的八个 microthread 上，每周期按操作数可用性在它们之间切换。这是 warp scheduler 用 64 个驻留 warp 做的同一份藏 stall 工作，用八个上下文完成，因为被藏的延迟是忙的 SRAM bank 或邻居一跳，而不是一次 HBM 往返。

48 kB 本地 SRAM 为数据通路而不是为局部性组织：八个单端口 6 kB bank 每周期交付两次 64-bit 读与一次 64-bit 写，恰好两个 4 元素 FP16 操作数进、一个结果出，即 WSE-2 FMAC 的宽度。256 字节软件管理 cache（WSE-3 上 512 B）把最热的值留在流水线旁。这是这台机器论题的缩影：每个核上，内存带宽与计算精确匹配，晶圆把这种平衡继承 900000 次。

### 计算

晶圆上没有矩阵单元。NVIDIA、Google 与 AMD 都把 FLOP 集中在专用 matmul 引擎（Tensor Core、MXU、Matrix Core），主要差别是如何喂它；Cerebras 从织物组装 matmul。GEMM 作为晶圆范围的编排运行：每个到达的权重沿持有激活的一行核广播，每个核对自己的驻留切片开火乘加（每个权重一次 AXPY），部分和跨 mesh 归约。Tensor Core 从寄存器 tile、MXU 从布线得到的数据复用，WSE 从几何得到：激活永不移动，于是在飞的唯一操作数就是正在相乘的那个。

FLOP 账本需要小心，因为 Cerebras 印出的数字不是用来比较的那个。WSE-3 头条的 **125 PFLOPS 是稀疏 FP16** ：它假设硬件在理想稀疏张量上大约 8× 的跳零回报。稠密大约是 **15.8 PFLOPS FP16** （推导：900000 核 × 8-wide FMAC × 1.1 GHz；Cerebras 没有公布官方稠密数字）。那是真实算力，但不是重点：每瓦，晶圆上的稠密 FLOP 输给每一颗同期 GPU。晶圆从来不是一台 FLOP 机器。它是一台 **带宽机器** ，FLOP 的存在是为了跟上 SRAM。

跳零是数据流赚到饭钱的地方。因为计算由到达的数据触发，零永远不触发任何事： **零在发送侧被过滤** ，接收核看不见它们，也不花那个周期。这是非结构化、元素粒度的稀疏，NVIDIA 的 2:4 结构化稀疏只采样了一般情形。到目前为止，它也是一个未行使的选项。Cerebras 自己的稀疏预训练结果（SPDF：13 亿参数上 75% 稀疏；后续 67 亿）是厂商撰写且低于 70 亿，没有旗舰客户模型被披露为稀疏训练：硬件上最大的一次运行 Jais 2 是稠密的。唯一能收割非结构化稀疏的硅片，尚未出货一个使用它的头条模型。

### 存储

层次只有一层： **核内 48 kB 切片里的 44 GB SRAM，晶圆上再无其他** 。没有 HBM，没有 L2，没有 eviction 策略；每一字节距 FMAC 一个周期。报价带宽是 21 PB/s，这个数字值得打旗：它是 900000 个本地 SRAM 端口的 **总和** ，晶圆上合计，不是点对点链路，也不可与 HBM 数字直接比较。诚实比较是每 FLOP 字节：晶圆能喂约 1.3 字节 / 稠密 FP16 FLOP，B200 从 HBM 得到约 0.002。在那条轴上每颗 GPU 与 TPU 都挨饿；WSE 是唯一平衡的机器。Decode——那个纯带宽问题的阶段（每个 token 完整读一遍权重）——是晶圆原来就长成的形状。

这一层的另一面是它的边缘。晶圆与其他一切的连接是 12×100 GbE： **1.2 Tb/s** ，勉强多于挂在一颗 Blackwell GPU 上的单颗 ConnectX-8 NIC。晶圆上 SRAM 与晶圆外以太网之间隔着 **五个数量级** 。NVIDIA 的层次逐渐下降，每一层比上一层慢几倍；WSE 有两层，中间是悬崖。晶圆是一座岛，岛的超能力与牢笼是同一事实。

而且岛不再长大。SRAM 密度在先进节点上实际上停止缩放：尽管整整缩了一代节点、晶体管数跳了 54%，WSE-3 只比 WSE-2 多 10% SRAM。逻辑继续缩小；六晶体管 SRAM 单元不缩。架构最稀缺的资源，正是下一工艺节点不再买到的那一样。

### Weight Streaming

晶圆上的训练把所有其他人视为理所当然的流向反过来：在 GPU 或 TPU 上，权重驻留、激活流过；在 WSE 上， **激活驻留、权重流过** 。主权重住在 **MemoryX** ，集群旁的 DRAM+闪存设备。一层一层，权重大流过晶圆，对钉在 SRAM 里的激活触发乘加，然后离开；反向时梯度流出，优化器步在 MemoryX 里的 CPU 上跑（权重更新是 $O(\text{参数})$ 的无复用逐元素工作，CPU 级算力跟得上）。晶圆从不存权重，「哪怕暂时也不」（Cerebras 的措辞）。模型大小由 MemoryX 界定，不是 44 GB；44 GB 界定激活与 batch。

这买到的是编程模型。一张晶圆持有一整层激活，于是没有张量并行、没有流水线并行、没有 FSDP 分片：70B 模型写成单设备程序，多系统扩展是经 **SwarmX** 的 **纯数据并行** ——一棵广播/归约树，把一条权重流传到 N 张晶圆，回家路上把梯度加起来。主导 GPU 训练的并行策略表格，根本没有 Cerebras 那一页。

它付出的是规模，用市场自己揭示的偏好衡量。规格表写 2048 台 CS-3；披露过的最大集群是 64（Condor Galaxy 3）。平台上披露过的最大从零训练模型是 **Jais 2，700 亿参数、2.6T token** ，由锚定客户 G42 与嵌入的 Cerebras 工程师训练。自 CS-1 以来七年，没有任何人超过 70B。而 GPU 实验室习以为常公布的利用率（MFU，35–45%），对任何 Cerebras 运行都从未披露。

### 数值

数值一句话说完： **FP16 与 BF16，FP32 累加** ，外加（自 WSE-3）Hot Chips 披露标为定点的 16-wide 8-bit 整数路径。没有 FP8，没有 FP4，没有 microscaling。当其他每个厂商每一代把精度减半、再用块缩放买回精度时，Cerebras 仍用 16-bit 计算，并把它当作品质差异点营销（「原来的 16-bit 权重」）。张力显而易见：SRAM 容量是架构最稀缺的资源，8-bit 权重会把一个模型需要的晶圆数减半。只做 16-bit 是数值信念还是数据通路路线图缺口，是开放问题；没有一份 Cerebras 一手材料在晶圆上显示浮点 8。

### 押注

- **押注 1：不要切开晶圆。** Die 边界是行业其余部分付的税：SerDes、中介层、HBM 堆、线缆、交换机。用金属缝上 84 个光罩场，对手系统里最高带宽的边界根本不存在。
- **押注 2：SRAM 是唯一内存。** 以业内最陡的比例用容量换带宽：44 GB，晶圆上合计 21 PB/s。平衡机器，而不是把不平衡藏在层次后面。
- **押注 3：数据流核，没有矩阵单元。** 900000 个由到达 wavelet 触发的微小核，matmul 由广播、FMAC 与 mesh 归约组装：跳过一个零是免费的，而不是特殊模式。
- **押注 4：权重移动，激活留下。** Weight streaming 把模型大小（MemoryX）与晶圆内存（44 GB）解耦，并把集群扩展塌成纯数据并行。
- **押注 5：卖延迟，不卖吞吐。** 晶圆每个 token 重读整个模型，比任何建在 HBM 上的东西都快；把这种速度定价为溢价产品，而不是在每 token 成本上竞争。

### 扩展

这里的 scale-up 与 scale-out 意味不同。NVIDIA 的 scale-up 问题（让 72 个封装表现得像一台设备）在 WSE 上由光刻解决：一致域从晶圆厂整块出货。剩下的是晶圆边缘以外的一切，没有别的机器这么硬、这么早就撞上自己的边缘。

**Scale-up** ：晶圆本身。一张 2D mesh 上 900000 核：32-bit 链路、单周期跳、24 色静态路由、原生广播、合计织物带宽 214 Pbit/s。被 300 mm 晶圆尺寸钉死在 46225 mm²。

**Scale-out** ：立刻就是以太网：每系统 12×100 GbE（1.2 Tb/s）。训练经 SwarmX 扩展（RoCE 上的数据并行广播/归约）；推理在层边界跨系统分片，流水线并行。

### Scale-up

晶圆内部织物没有 SerDes、没有线缆、没有收发器、没有每链路边际成本：路由是编译的，每跳一个周期，广播是原生织物原语而不是交换机功能。NVL72 花 5184 根铜缆和一盘 NVSwitch ASIC 给 72 GPU 130 TB/s 全互连；WSE 的等价域是单个光刻对象。代价是域大小是常数。NVIDIA 的 scale-up 域每一代长大（三年里从 NVL72 到 NVL576）；晶圆自 2019 年以来就是 46225 mm²，并将停在那里。300 mm 是行业运行的最大晶圆（450 mm 过渡十年前死了），所以 Cerebras 的 scale-up 路线图就是下一节点在密度上给出的东西：再也没有面积可拿。

### Scale-out

训练 scale-out 是 SwarmX，它只做一件事：复制。把权重流广播到 N 张晶圆，回程上归约它们的梯度；batch 随系统数增长，模型大小不增长。声称的 2048 系统天花板（「256 exaFLOPS」，稀疏）从未建成；建成的是 64。

推理完全放弃 weight streaming；算术是致命的。经约 150 GB/s 管道从 MemoryX 为每个解码 token 流过 70B 模型的 140 GB，大约每个 token 要一秒。于是推理 **把权重量停在 SRAM** ，并在层边界跨晶圆分片模型：Llama 70B 在「少至四台」CS-3 上，经以太网流水线并行，每多一张晶圆贡献 44 GB 权重+KV 容量与 23 kW 负载。

速度是真的，且经独立验证。 **Artificial Analysis** 在 2024 年 8 月发布时测得 Llama 3.1 8B 1850 tokens/s、70B 446，Llama 405B 969（首 token 240 ms），2025 年 Llama 4 Maverick 2522，约为当时最佳已公布 Blackwell 数字的 2.4 倍。厂商报价峰值更高（带 speculative decoding 的 70B 上 2100；GPT-OSS-120B 上 3000，现场独立测量更接近 2000）。没有 GPU 提供商在每用户 decode 速度上接近。

经济学是锋利的边。每晶圆 44 GB 意味着前沿规模模型吃掉机队：SemiAnalysis 估计约 24 台 CS-3 才能装下一个在少数 GPU 机柜里就能放下的 1.6T 参数级模型，每系统分析师估计约 45 万美元物料成本，标价约 200–300 万美元（从未官方披露）。Decode 期间晶圆巨大的 FLOP 大多闲着；Cerebras 拒绝披露 batch 大小，也从未公布每系统吞吐。每 token API 定价对同一开源模型大约是 GPU 提供商的 3–5 倍，Llama 405B 被悄悄从 API 拿下，SemiAnalysis 解读为服务经济账没算平。固定 SRAM 也给上下文定价：KV cache 与权重住在同一 44 GB，长上下文偷容量，迫使每个副本更多系统；API 封顶 131K token，而前沿提供商服务 256K–1M。MoE 有在服务（Qwen3-235B 约 1500 tokens/s，厂商报价），但是该格式最坏情况：巨大参数足迹，一次只碰几个 expert，却持在最贵的内存里。

市场诚实地给这定价。Mistral 的 Le Chat（约 1100 tokens/s）、Perplexity Sonar 与 Meta 的 Llama API 都为延迟付钱；2026 年 1 月 OpenAI 签约 **到 2028 年 750 MW 的 CS-3 容量** ，签约时报道超过 100 亿美元，此后涨过 200 亿美元——晶圆级得到过的最大背书。该容量上出货的第一个旗舰是 **GPT-5.6 Sol** ，2026 年 7 月发布，报价 750 tokens/s。

### 软件

栈像 TPU 一样是编译器驱动的，但孔径窄得多：Cerebras 编译器是 **kernel 匹配器** ，不是通用代码生成器。 `cerebras.pytorch` 经 lazy tensor 把训练步 trace 进 Torch-MLIR 与一张图 IR，然后对照手写 kernel 库匹配子图，没有匹配的 op 回退到更慢的自动生成。文档化的约束按 GPU 标准很刺眼：仅静态图、无动态形状、无数据相关控制流、步中无 eager 张量访问，以及钉在上游后面的 PyTorch 版本。最好的独立实践者叙述（荷兰国家计算中心 SURF）报告不支持的层类型，以及标准 PyTorch 代码没有 1:1 移植路径。

而且没有 kernel 逃生口。CUDA 对新 attention 变体的答案是 *写一个 kernel* ；TPU 的是 Pallas；ROCm 的是 Triton。Cerebras ML 栈完全没有用户 kernel 路径：匹配器严重 miss 时，修复是一位 Cerebras 工程师。一门单独的 SDK 语言 **CSL** 暴露原始机器（任务、wavelet、color），并产出过惊人的 HPC 结果（TotalEnergies 的 stencil 代码约 A100 的 228 倍；48 台 CS-2 上的 Gordon Bell 决赛入围），但它是另一个世界，与 PyTorch 流不相连。平台上每个旗舰模型（Jais、BTLM、Med42）都是与嵌入的 Cerebras 员工共同开发的。

这里有一种奇怪的免疫。FlashAttention——GPU 时代的定义性 kernel 谱系——是一种经存储层次给 attention 分 tile 的方案，而 WSE 没有可对着 tile 的层次：那种让 AMD 付出数年移植滞后的优化类别，在这里根本不适用。但免疫与贫瘠是同一事实。在 CUDA 上复利的第三方 kernel 生态，在这里没有可附着的表面；平台史上每一次 kernel 改进都只有一个作者。

那把晶圆留在哪里？诚实赢得一个真实利基：batch-one decode 速度，独立验证，由把延迟标在成本之上的客户付钱。利基周围是硬墙：3–5× 每 token 定价，七年仍是 70B 训练天花板，2025 年收入仍约 86% 集中在两家与阿布扎比相关的客户（据 2026 年 5 月 IPO 前后的 S-1），以及一种刚在模型继续长大时停止缩放的最稀缺资源——SRAM 密度。Hennessy 与 Patterson 许诺寒武纪大爆发；WSE 是其最极端的体型，那个认定存储墙是封装选择、并花 46225 mm² 硅拒绝去做它的体型。

## AWS Trainium

**Annapurna Labs** ——AWS **Nitro** 卡与 **Graviton** CPU 背后的团队——把 **Trainium** 建成一个 **快速跟随者** 。计算核心拿走 TPU 已验证的剧本（128×128 weight-stationary 脉动阵列、软件管理 scratchpad、整程序编译），甚至直接共享 Google 的 **XLA** 编译器。Scale-out 织物是已经承载 AWS 其余部分的 **Nitro** 卸载网络。真正属于 Amazon 的东西窄而刻意：焊在借来的核心上的专用集合通信硅片，以及垂直整合——定价一颗只需要在 **AWS 内部** 打败 NVIDIA 的芯片。

### 架构

另一个专属硅片故事属于 Google，Trainium 最好读成在另一朵云里重建的 TPU 论题。底下的押注相同（从软件管理 SRAM 喂入的脉动阵列，由编译器提前调度，没有 cache，没有线程调度器），但单元组装方式不同。一颗 Trainium 芯片带 **少量** **NeuronCore** （Trn1 上 2 个，Trn2 与 Trn3 上 8 个），每个 NeuronCore 不是一台单体 matmul 引擎，而是一簇 **解耦的专用引擎** ： **Tensor Engine** （128×128 脉动阵列）、做归约的 **Vector Engine** 、做逐点数学的 **Scalar Engine** ，以及八个 512-bit 向量处理器组成的可编程 **GPSIMD Engine** ，吸收另外三者都不适合的东西。周围是搬运者：128 个 **DMA 引擎** 、为传输定序的 **Sync Engine** ，以及（自 Trn2）做集合通信的专用 **CC-Core** 。没有 warp，没有 wavefront；引擎作为静态调度的数据流管道运行，承重设计决策关乎脉动阵列周围是什么，而不是阵列本身。

### 计算

**Tensor Engine** 拥有 matmul FLOP；另外三个引擎拥有其他一切。它是 128×128 处理单元网格（16384 个 MAC），weight-stationary 运行：一块操作数 tile 装进阵列并原地持住（ `LoadStationary` ），另一块流过它（ `MultiplyMoving` ），部分和落在 **PSUM** ——一小块累加 SRAM，引擎可以读-加-写，于是长于 128 的收缩沿 $K$ 轴原地折叠。这是每台 matmul 加速器核心的同一 $D = A \cdot B + C$ tile MMA；但 NVIDIA 把它包在 warp 层次里，Google 从 VLIW bundle 发出它，Trainium 把它暴露为对着具名 scratchpad 的一对显式指令。

阵列物理上三代都固定在 128×128；变的是每个单元装多少个乘积。Trn1 的 NeuronCore-v2 跑带 FP32 累加的 BF16/FP16，FP8 只以 BF16 速率提供（没有加速）。Trn2 的 v3 对 FP8 双泵，呈现有效 256×128 阵列，第一次真正 8-bit 上 2×。Trn3 的 v4 装 microscaling 操作数，呈现有效 512×128，为 BF16 速率的 4×。物理乘加单元数从不移动；数据通路只是喂它们更窄的数。

另外三个引擎让阵列保持忙碌。 **Vector Engine** 处理跨元素归约（layernorm、softmax、pooling）； **Scalar Engine** 处理一进一出逐点运算（激活、GELU）； **GPSIMD Engine** ——八个跑 C 的完全可编程向量处理器——吸收映射不到前面那些的任何东西。编得好的一步重叠全部四个：Tensor Engine 磨 matmul 时，Vector Engine 跑上一块 tile 的 softmax，DMA 引擎分期下一块——与让 TPU 和 GPU attention kernel 高效的同一 producer/consumer 重叠，在这里表达为分离的物理引擎，而不是分离的 warp 或 VLIW 槽。当一层干净地分解到四种引擎类型时设计会回报，Transformer 大体如此。边缘上付税：适合不了任何专用引擎的算子落到可编程 GPSIMD 路径，更慢，也是机器最可能卡住新架构的部分。这是 Trainium 版本的、每个非 GPU 加速器都背的长尾成本。

### 存储

存储层次是应用到存储上的计算哲学： **三层，全部软件管理，任何地方都没有硬件 cache** 。AWS 自己的文档画出对比，指出与 CPU 或 GPU 不同，NeuronCore 没有 cache，「所有内存移动都在程序本身里显式」。片外是 **HBM** （Trn1 32 GB，Trn2 96 GB HBM3，Trn3 144 GB HBM3e）。片上、离引擎最近的是 **State Buffer（SBUF）** ：主 scratchpad，大约 20× HBM 带宽，组织成 128 个分区，每 NeuronCore 大小为 24 MiB（v2）、28 MiB（v3）、32 MiB（v4）。阵列与 SBUF 之间是 **PSUM** ，2 MiB 专给 matmul 输出的累加器。数据走 HBM → SBUF → Tensor Engine → PSUM → SBUF，每一跳由编译器发出；硬件不 prefetch、不 eviction。

这正是 Google 的 VMEM 押注：编译器必须完美调度的显式 scratchpad，没有 cache 掩盖错误，也是 NVIDIA 硬件管理 L2 与 L1 的反面。Trainium 继承随之而来的天花板与脆弱：调度对了引擎永不 stall，错了没有回退路径。设计用慷慨的 HBM 预算对抗谦逊的峰值 FLOP，因此单位算力上 Trainium 比可比 NVIDIA 部件带更多内存。但在 **绝对** 容量上它落后：Trn2 的 96 GB 低于 H200 与 B200，Trn3 的 144 GB（2025）低于它对着出货的 192 GB B200 与 288 GB B300。所以 AWS 论证服务大模型经济账时真正拉动的杠杆不是内存领导，而是 **价格** ：它自己建造并出租的硅片上，单位算力与 HBM 的成本。

### 数值

Trainium 追随与所有人相同的精度减半曲线（FP32 → BF16 → FP8 → FP4），有两处 Trainium 特有褶皱。第一是 **可配置 FP8** ：不像 Hopper 固定 E4M3 与 E5M2，Tensor Engine 接受可调指数偏置，支持 E5M2、E4M3 与 E3M4，让编译器按张量在范围与精度之间交易。第二是 Trn3 的 FP4 **不买额外吞吐** ：OCP MXFP4 操作数在到达阵列前上转换到 MXFP8，于是 FP4 以 FP8 速率跑，只省内存与带宽，不省计算。两代都靠行业的精度挽回手法：Trn3 起的 microscaling 块指数，以及每一代的硬件 **stochastic rounding** 。唯一该不信任的数字是稀疏峰值：AWS 头条一个 4× FP8 数字，而它自己的架构页把它放在稠密 FP8 的 2×（4× 是相对稠密 BF16），于是营销加速与数据通路并不完全一致。

### 硅片里的集合通信

GPU 上没有干净类比的块是 **集合通信核** 。分布式训练与推理把很大一部分墙钟花在集合通信上：每一步梯度都是 all-reduce，每一层 MoE 都是 all-to-all。在 GPU 上那些集合通信作为 NCCL kernel 跑在做数学的同一批 SM 上，于是通信与计算争夺同一硅片，重叠必须在软件里赢。Trainium 把功能切进专用硬件：每颗 Trn2 芯片 20 个 **CC-Core** ，直接接到 **NeuronLink** 端口，在 Tensor 与 Vector 引擎继续跑时执行 all-reduce、all-gather、reduce-scatter 与 all-to-all。这是 Google 对 SparseCore、Cerebras 对核外零过滤器做的同一招：找到主引擎形状不对的负载，花一点面积在旁边做专用块，而不是从核心偷周期。通信变成芯片 **并发** 做的事，而不是它停下来去做的事。

### 押注

- **押注 1：云是产品，芯片是组件。** Annapurna 把芯片、服务器、机柜、Nitro 网络与云 API 设计成一栈，于是 Trainium 只需要在 AWS 内部赢性价比，从不需要在商用硅片规格表上赢。
- **押注 2：借用计算论题，不要重发明。** 128×128 weight-stationary 阵列、软件管理的 SBUF/PSUM scratchpad、整程序编译是 TPU 的押注，复用到共享 Google 的 OpenXLA。省下的力气进网络与机柜。
- **押注 3：集合通信属于硅片。** 专用 CC-Core 在硬件里把 all-reduce 与 all-to-all 与计算重叠，而不是把它们当偷 matmul 单元 FLOP 的 kernel 来跑。
- **押注 4：复用云自己的网络。** Scale-out 是带 SRD 传输的 EFA：已经跑 AWS 其余部分的同一套 Nitro 卸载、packet-spray 的 RDMA。没有 InfiniBand。
- **押注 5：把拓扑移向负载。** Trn1 与 Trn2 抄了 TPU 的 torus；Trn3 的 NeuronSwitch 在 MoE 流量长出最近邻时用交换全互连织物替换它。老实说，这是跟剧本：先跟 Google 的，现在跟 NVIDIA 的。

### 扩展

Trainium 的扩展从 AWS 其余部分继承分裂：紧密耦合的 **NeuronLink** 域给必须表现为一台的芯片，云的通用 **EFA** 织物给以外的一切。Scale-up 域不是 NVLink 那种 cache 一致共享内存；AWS 把 UltraServer 营销成池化的数 TB 内存，但底下是点对点链路上的消息传递，精神上更接近 TPU 的 ICI 而不是 NVSwitch crossbar。

**Scale-up** ：NeuronLink 把芯片绑进一个 UltraServer。到 Trn2，拓扑是 torus（每实例 16 芯片 4×4 2D torus，每 UltraServer 64 芯片 4×4×4 3D torus）；Trn3 用 NeuronSwitch 全互连织物替换。消息传递，不是一致 load/store。

**Scale-out** ：以太网上的 Elastic Fabric Adapter，卸载到 Nitro。SRD 传输把每个流喷到许多路径上，可靠但乱序交付；UltraCluster 经 10p10u 织物达到数十万芯片。

### Scale-up

NeuronLink 是 Trainium 的芯片到芯片织物，角色相当于 NVIDIA 的 NVLink、TPU 的 ICI。到 Trn2，它把芯片织成 **torus** ，正是 TPU 的选择：单个 **trn2** 实例是 16 芯片 4×4 2D torus，每芯片约 1.28 TB/s； **Trn2 UltraServer** 把四个实例连成 64 芯片 4×4×4 3D torus，呈现 83 稠密 FP8 PetaFLOPS 与约 6 TB HBM 作为一个 scale-up 域。第三根 torus 轴故意很细（实例间环每芯片约 256 GB/s，对实例内 1.28 TB/s），这是 torus 的特征交易：便宜布线与巨大最近邻带宽，代价是直径上许多跳。AWS 把 64 芯片 UltraServer 对位 NVIDIA 的 72-GPU NVL72；合计算力在同一档，但 torus 不是 crossbar，两者在非最近邻流量上表现非常不同。

这就是 Trn3 放弃 torus 的原因。 **NeuronSwitch-v1** 是交换 **全互连** 织物，大约把芯片间带宽加倍，更重要的是压平直径，使任意芯片经一跳交换到达任意其他芯片。Trn3 UltraServer 扩到 144 芯片，362 稠密 FP8 PetaFLOPS 与 20.7 TB HBM3e。动机也是把 Google 推向 MoE 推理高基数拓扑的那个：expert routing 是 all-to-all，torus 的最坏情况，交换机把最长跳对变成一次穿越。Trainium 的互连路线图是行业的压缩重演：负载是最近邻时采用 torus，不是时切到 crossbar。

![](https://pic1.zhimg.com/v2-092e4ad628fe20c8988ab2265a2d75bc_r.jpg)
**Trn3 UltraServer scale-up——Trn3 为 NeuronSwitch-v1 放弃 Trn2 torus，这是 NeuronLink-v4 上的交换全互连织物（每芯片约 2 TB/s）。服务器内，芯片经第一级（L1）NeuronSwitch 相连，任意芯片一跳到达任意其他；跨服务器，两个第二级（L2）NeuronSwitch 把 144 芯片 UltraServer 织成一个全互连域*

### Scale-out

Scale-out 不是定制的；它是 AWS 已经在跑的同一张织物。每个 Trainium 实例带一颗 **Elastic Fabric Adapter** NIC 进入数据中心网络（每 Trn2 实例 3.2 Tbps），传输是 **SRD（Scalable Reliable Datagram）** ，卸载到 **Nitro** 卡而不是跑在加速器上。SRD 是 AWS 对 RDMA 的白纸答案：不是 RoCE 或 InfiniBand 的单一有序流，它把每条消息喷到最多 64 条并行路径上，可靠但乱序交付，把重组推到集合通信库，绕开单条拥塞路径会造成的队头阻塞。它是 AWS 为云一般情况建的传输，再挪用到加速器织物。

![](https://pic4.zhimg.com/v2-b4f4b8f5926cc78c231aed075c2f4287_r.jpg)
*AWS Trainium scale-out——UltraServer 经卸载到 Nitro 卡的 Elastic Fabric Adapter NIC 相连，走标准以太网而不是 InfiniBand。SRD 传输把每个流喷到最多 64 条路径，可靠但乱序交付，绕开队头阻塞。10p10u UltraCluster 织物（约 10 petabit/s，低于 10 微秒）把数十万芯片织在一起；Project Rainier*

层次顶端是 **UltraCluster** ，由 **10p10u** 网络缝合（AWS 对数据中心内约 10 petabit/s 带宽、低于 10 微秒延迟的简称），扩到数十万芯片。证明点是 **Project Rainier** ：大约五十万颗 Trainium2 跨多个美国数据中心，2025 年末为 **Anthropic** 上线；到 2026 年初 Claude 已在超过一百万颗芯片上跑——任何外部实验室对非 NVIDIA 训练平台做过的最大承诺。它存在是因为经济账端到端算得平。AWS 声称 Trainium2 比其 Hopper 级 GPU 实例性价比好 30–40%（AWS 数字，对照上一代 NVIDIA 而不是 Blackwell），而且因为 Amazon 拥有从 Nitro 卡到 API 的每一层，那份利润率是 Amazon 自己定的。

### 软件

Trainium 的软件把借用说得很明白： **Neuron SDK** 是 **建在与 TPU 同一 OpenXLA 基础上的编译器优先栈** 。Neuron 编译器（ `neuronx-cc` ）摄入 XLA HLO 图，降到 Neuron 运行时加载到 NeuronCore 上的 **NEFF** 二进制；前端 IR 是 Google 的，Google 自己的 OpenXLA 公告把 Trainium 列为与 TPU 并列的一等 PJRT 设备。 **torch-neuronx** 经 PyTorch/XLA 的 LazyTensor tracing 跑 PyTorch（记录 op，在步边界编译图）， **jax-neuronx** 经 StableHLO 下降 JAX。在一端 kernel 驱动的 CUDA 到另一端整程序 XLA 的光谱上，Trainium 几乎叠在 TPU 上面：编译器就是系统，而且大体是同一编译器。

分叉处是逃生口。XLA 单独并不总能合成新 attention 变体或融合 MoE dispatch 的最优，于是 Neuron 出货 **NKI（Neuron Kernel Interface）** ，一门 Python、tile 级 kernel 语言，直接暴露四个引擎与 SBUF/PSUM scratchpad。它是 Trainium 的 **Pallas** （或它的 **Triton** ）：同一想法——当 kernel 的赢在调度而不在代数时，一门 tile DSL 降到整程序编译器之下。其下， **集合通信库** 把 all-reduce 与 all-to-all 映射到 CC-Core 与 NeuronLink 拓扑（NCCL 类比）， **NeuronX Distributed** 提供分片训练层。

与 CUDA（甚至与 TPU 栈）的差距是成熟度，不是设计。NKI、JAX 路径与分布式库到 2024 年末都仍在 beta；移植的模型只在 AWS 上跑，没有跨厂商回退；vLLM 后端落后于上游项目。最清楚的信号是锚定租户如何工作： **Anthropic** 不只是经 PyTorch 瞄准 Trainium，它与 Annapurna 嵌入，写自己的底层 NKI kernel，并把修复上游进 Neuron 栈。Trainium 在前沿可生产，但在前沿它是共工程的，不是交钥匙：编译器是继承的且优秀，周围生态还年轻。

## Groq LPU

**Groq LPU** 是一台 **确定性** 机器。其他每颗芯片都花硅去容忍不确定性：用 cache 藏内存延迟，用调度器填 stall，用仲裁器解决它无法预测的争用。LPU 删掉这一切。剥掉每一个 **反应式** 组件（没有 cache、没有分支预测器、没有仲裁器、没有 ROB，甚至没有片上 crossbar），把整个调度问题交给编译器，由它把每条指令、每个字节放在精确周期上。剩下的是一颗运行前就知道延迟的芯片。 **TPU** 把调度搬进编译器，但留下 HBM 与动态网络；Groq 去掉最后的非确定性来源：内存全是 SRAM，网络也被调度，于是数百颗芯片作为一个时钟精确的程序运行。

### 架构

场上其余部分由 **复制的核** 建成：把一个 SM、TensorCore、CU 或数据流核铺满 die，把工作分给副本。LPU 反过来建。它拿一个常规核并 **拆开** ：指令控制、向量 ALU、矩阵单元、内存与网络各自成为 **功能切片** ——一整列相同硬件——列在 die 上并排站着。沿每个切片同质，跨芯片异质。数据不坐在寄存器堆里等着被发到单元上；它像装配线上的零件一样水平 **流过** 切片，东与西，每周期一个寄存器跳，同时 VLIW 指令从控制切片向北发出去迎接它。数据通路里没有东西反应：编译器知道每个周期每个操作数在哪，硬件只是转时钟。流就是身份：这套设计以 **Tensor Streaming Processor（TSP）** 推出，直到 2024 年更名为 Language Processing Unit。

![](https://pic1.zhimg.com/v2-07351b3150889d8b92c4e06ce89b0b1a_r.jpg)
*Groq LPU 平面图——die 以中央 VXM 向量切片为轴分成镜像的东、西半球。向外读：边缘是 MXM 矩阵平面，然后是 SXM 交换切片，然后是夹着 VXM 的 MEM SRAM 切片组。指令控制（ICU）沿南缘走，向北把 VLIW bundle 发进每个切片；操作数流在切片间东西流动，每周期一个寄存器跳。320 条 lane 垂直叠成 20*

纵轴是 SIMD 宽度。芯片高 320 lane，组织成 20 个各 16 lane 的 **superlane** （第 21 个是备用，为良率熔掉，对软件不可见），每个切片同时作用于全部 320 lane。横轴是时间。每条 lane 有 64 个逻辑 **stream register** ，32 个向东、32 个向西，每个 tick 每条流沿其方向前进一个切片，直到被消费或掉出 die 边缘。切片从经过的流上读操作数、计算，并把结果写回驶向下一切片的流。die 以中央向量单元为轴镜像成两个半球，于是一次产出的值可被任一侧的切片消费。

### 计算

LPU 保持与其他一切相同的劳动分工：矩阵工作在专用单元上，其余在向量引擎上，但把两者都排成流里的切片。矩阵路径是 **MXM** ：四个独立的 320×320 乘加平面（每半球两个），共 409600 个乘法器，把 INT8 或 FP16 操作数送进 INT32 或 FP32 累加器。权重量装进一个平面（全部不到 40 个周期），然后激活流过、乘积累加。900 MHz 下大约是 **750 INT8 TOPS 与 188 FP16 TFLOPS** ，而且不寻常的是，这个数字没有稀疏星号：TSP 完全拒绝跳零，因为数据相关的跳过会让执行时间数据相关，而确定性是它不愿交易的那一项属性。

向量路径是 die 中央的 **VXM** ：每 lane 16 个 ALU，排成 4×4 mesh，5120 个 32-bit ALU，跑激活、归一化、量化与残差相加。因为计算是 **空间的** 而不是发到共享单元，一个操作数可以在连续周期里穿过一串 VXM ALU 并直进 MXM 平面，不碰内存：GPU kernel 用手建的算子融合，在这里只是切片的物理顺序。第三种切片类型 **SXM** 处理直线流表达不了的移动：lane 移位、320-lane permute、转置，以及芯片到芯片链路都住在这里，于是跨 lane 重排数据是一等操作，而不是绕一圈 SRAM。

### 存储

没有 HBM，没有 DRAM，没有 cache。片上是 **MEM** 切片：88 个切片里 230 MB SRAM（每半球 44 个），每一字节距计算切片一个周期，合计约 80 TB/s。那就是全部层次：一层，平坦，软件寻址，没有任何会引入变延迟访问的 eviction、prefetch 或一致性机械。

后果是架构的定义性约束。230 MB 装不下模型。Llama-2 70B 的 FP16 是 140 GB，所以必须 **跨数百芯片分片** ，权重量铺在整机柜或更多的合计 SRAM 上：部署配置约 576 颗 LPU。GPU 把模型停在少数封装的 HBM 里、让 token 流过它；LPU 把模型铺在集群的 SRAM 里、让 token 流过集群。芯片数由容量而不是算力决定：权重量必须放下。这是 Cerebras 做的同一交易（只要 SRAM，不要 HBM），从相反方向到达：Cerebras 保住一颗巨大 die，放弃每晶圆容量；Groq 保住正常大小的 die，放弃永远在一颗上装下模型。

### 数值

数值是那条没走的路。这里其他每个厂商都在每一代减半精度，FP16 到 FP8 到 FP4，用块缩放买回精度。TSP 停在带 FP32 累加的 **FP16 与 INT8** ，从未在硅片上出货 FP8 或 FP4。它的一个数值想法是 **TruePoint** ：320 元素点积融合成单次舍入步、FP32 累加，于是 FP16 乘法器阵列在归约上落得接近 FP32 精度（Groq 报告相对 FP32 基线最大误差约 0.05%）。

16-bit 是信念还是从未得到低精度刷新的数据通路，很难与第二代芯片从未出货这一事实分开。SRAM 容量是架构最稀缺的资源，8-bit 权重会把一个模型需要的芯片数减半；一台如此受容量约束的机器有一切理由想要 FP8，却没有在硅片上得到它。这是悬在 Cerebras 仅 16-bit 数据通路上的同一开放问题，同一张力：最缺容量的厂商用最宽的精度计算。

### 确定性

其他每台加速器藏延迟；LPU **暴露** 它。ISA 携带每条指令的执行延迟，数据通路从构造上就是固定延迟，于是编译器提前算出每个结果出现的精确周期。硬件里没有东西能扰乱那份调度：没有会 miss 的 cache，没有会 stall 的仲裁器，没有会误预测的分支，没有要回滚的推测。Groq 自己的测量是证明：24240 次 BERT-Large 运行落在约 75 µs 带内，编译器预测延迟距实测 2% 以内。

这是 TPU 的本能（把调度搬进编译器，删掉事后猜测它的硬件）再往前一步。TPU 编译器调度一颗芯片；LPU 编译器调度一个 **系统** ，因为确定性跨网络也成立。它也是 Cerebras 的精确反面：后者的核是 **数据流** ，操作数碰巧到达时开火——WSE 对数据反应，LPU 对它定时。两台机器都删掉调度器；一个用到达替换它，另一个用时钟。

### 押注

- **押注 1：确定性优于容忍。** 删掉每一个反应式组件（cache、仲裁器、预测器、ROB），让编译器拥有每一个周期。
- **押注 2：空间功能切片。** 把核拆成切片并让操作数流过它们，于是融合就是平面图，数据复用活在线上，而不是寄存器堆舞蹈。
- **押注 3：SRAM 是唯一内存。** 任何容量代价下都不要 HBM。用单周期、固定延迟访问换放弃片上装下模型的能力，接受模型必须跨越数百芯片。
- **押注 4：网络也调度。** 让芯片自己当路由器，逐周期编译通信，于是一千芯片集群是一个确定性程序，没有交换机，没有拥塞。
- **押注 5：卖延迟，不卖吞吐。** 为 batch 1 的每用户每秒 token 优化——GPU 最差的制度——并把那种速度定价为产品，而不是在每 token 成本上竞争。

### 扩展

扩展 LPU 与这里其他任何东西都不一样，因为没有单独的 scale-up 织物要建：芯片已经是交换机。每颗 LPU 带最多 16 条芯片到芯片 **RealScale** 链路（卡上露出 11 条），同时充当计算端点与路由器。把芯片直接互连，集群就是 **无胶多处理器** ：没有 NIC，没有 switch ASIC，没有机柜顶交换机。而且因为确定性跨那些链路成立，整个集群跑在一份编译期调度上。

**Scale-up** ：节点：8 颗 LPU 经 RealScale C2C 全连接，形成一个呈现为单个高基数虚拟路由器的 Dragonfly 组。软件调度，无交换机，无一致性。

**Scale-out** ：同一张织物，延长。节点的 Dragonfly：每机柜 9 个（72 芯片，一个节点热备），规格扩到 10440 芯片，每一跳仍在编译的、确定性调度上。

### Scale-up

节点是 8 颗 LPU，全连接：每颗芯片 7 条链路连到另外七颗，于是节点内每颗芯片距其他每颗一跳。每颗芯片剩下的四条链路（节点上 32 条）捆成 ISCA 论文所称的 32 口虚拟路由器，即节点进入更大织物的上行。没有基板交换机，没有一致地址空间；远端操作数不是被 load，而是被 **调度** 到达——由源芯片在编译器选定的周期注入，由目的在它落地的周期消费。

### Scale-out

节点之外，节点织成 **Dragonfly** ：9 个节点做成 72 芯片机柜（第九个热备，于是 64 个活跃），拓扑规格扩到 10440 芯片，任意两个在六跳以内。织物是 **软件调度** 的：路由与流控移到编译期，论文的框架很直白—— *scheduled, not routed* 。没有反压，没有动态仲裁，因为编译器已经证明接收方就绪；链路带前向纠错而不是重传，因为重试会扰乱调度。让一机柜独立时钟的芯片锁步是它自己的问题：链路是 **准同步（plesiochronous）** 的，织物用每 256 周期经生成树交换的 **Hardware-Aligned Counter** 维持全局共识时间，周期性 deskew 指令把每颗芯片 stall 回对齐。Groq 报告的回报是：8 路 all-reduce 在大张量上匹配 A100/NVSwitch 节点，在小张量上胜过它——调度织物不付动态织物的握手延迟。

成本写进内存押注的物理。一个模型副本不是一个盒子，而是一个机柜（或八个）：按一项分析，约 576 芯片上的 Llama-2 70B 带着 144 颗主机 CPU 与 144 TB 主机 RAM 陪着 LPU，而对 8-GPU 服务器是两颗 CPU。每颗芯片下的晶圆便宜（14 nm GlobalFoundries，据报低于 6000 美元，H100 级部件约 16000 美元），但你需要数百颗，而且 decode 期间它们巨大的算力大多闲着，SRAM 在干活。 **SemiAnalysis** 说得很直白：当你为延迟优化时，LPU 赢每 token 物料成本；一旦你做 batch，吞吐每美元大约输给 GPU 一个数量级。架构不在成本上竞争。它在速度上竞争。

### 软件

编程模型是 *编译器就是机器* 的最纯表达。 **没有 kernel** 。你把来自 PyTorch、TensorFlow 或 ONNX 的模型交给 Groq 编译器；它降到一小套张量 op，并静态调度每条指令、每条流、每一次芯片到芯片传输。没有人写 wgmma 或手调 tile，因为没有动态硬件可对着手调。Groq 的演示是不到十人的团队四天拉起 LLaMA，而对同一模型在 GPU 上手调 kernel 要数月。编译器周围的栈（profiler、运行时、 `GroqFlow` 拉起路径）又小又封闭， `GroqFlow` 于 2025 年归档，因为公司停止卖卡、开始卖 token。

那次转向说明架构是干什么的。LPU 从构造上就是 **仅推理** （Ross 的框架是训练是局部游戏、推理是全局游戏），它在一件事上未被击败：单用户 decode 延迟。独立测量支撑该主张， **Artificial Analysis** 把 Groq 计为开源模型上最快的 token/s 提供商之一。对其余部分匹配很差：装不进一机柜 SRAM 的模型、想要大批以换吞吐每美元的负载，或静态调度表达不了的动态控制流。MoE 有在服务，但其数据相关的 expert routing 与想提前知道一切的编译器坐得很别扭，Groq 很少公布如何调和两者。

尾声是：这一切的买家是 NVIDIA。2025 年 12 月 NVIDIA 取得 LPU 技术的 **非独占许可** ，并雇佣 Ross 与大部分团队。按 NVIDIA 自己的 10-K，这不是收购：没有产品、客户合同或股权易手，尽管收盘时支付的大约 130 亿美元让媒体称之为收购。GTC 2026 上技术以 **NVIDIA Groq 3 LPU** 重现：一机柜 256 颗仅 SRAM 的推理芯片坐在 Rubin NVL72 旁，把 Transformer 劈开：GPU 跑 attention，LPU 跑 feed-forward 与 MoE 层，Dynamo 编排交接。AI 里最确定的架构，最后成了最可编程架构内部的延迟协处理器。与此同时 GroqCloud 仍在原来的 14 nm 硅片上服务 token。

### 这张表说明什么

- **每芯片 FP8 已经收敛。** B200（4.5 PF）、Ironwood（4.6 PF）与 MI355X（10 PF）彼此大约在 2× 以内。每芯片军备竞赛接近；机柜与 pod 才是架构分叉处。
- **HBM 容量是 AMD 的持续胜场。** 2023–2025 的 192 → 256 → 288 GB 每一代追平或超过 NVIDIA。NVIDIA 直到 B300（2025 年末）才在 288 GB 追上；Rubin Ultra 于 2026 年以每封装 1 TB 重新夺回领先。
- **机柜级 scale-up 直到 2026 年都是 NVIDIA 的胜场。** GB200 / GB300 NVL72 是 2024–2025 唯一出货的一致机柜级域；AMD 在盒子上 scale-up，直到 Helios 才到机柜级。TPU 绕开这个问题：它的 torus 同时是机柜与集群。
- **TPU pod 在芯片数上使任何 NVIDIA 机柜相形见绌。** Ironwood pod = 9216 芯片、42.5 ExaFLOPS FP8；NVL576 = 576 GPU、约 5 ExaFLOPS FP8。TPU 的「平坦每芯片费率 × 巨大 pod」配方给出每系统更多合计算力，代价是每芯片带宽。
- **每芯片功耗上升很快。** 700 W（Hopper）→ 1000 W（Blackwell、MI325X）→ 1400 W（B300、MI355X）→ 约 1800 W（Rubin Ultra，分析师）。约 1000 W 以上液冷成为必须；风冷实际上随 Hopper 结束。
- **Scale-out NIC 带宽每一 NVIDIA 代翻倍。** 400 Gbps（CX-7，Hopper）→ 800 Gbps（CX-8，Blackwell）→ 1.6 Tbps（CX-9，Rubin）。AMD 落后一代（Pollara 400 → Vulcano 800），反映 Pensando 更小的装机量与更晚的整合。
- **Cerebras 打破表的坐标轴。** 完全没有 HBM：晶圆上 44 GB SRAM，合计 21 PB/s，约 1.3 字节 / 稠密 FLOP，而 GPU 行靠近 0.002。代价在同一行可见：总内存少于单颗 H200，每瓦稠密 FLOP 落后于每一颗同期 GPU，scale-up 列为空，因为一致域就是晶圆本身。
- **Trainium 在经济账上竞争，不在规格表上。** 每芯片它落后（Trn2 的 1.3 PF FP8 大约是 MI355X 的四分之一），但 Trn2 UltraServer 在 2024 年与 NVL72 同期到达 64 芯片机柜级 scale-up，作为消息传递 torus 而不是一致 crossbar，Trn3 转向交换的 NeuronSwitch 织物。AWS 拥有从 Nitro 卡到 API 的每一层，一个锚定租户（Anthropic，超过一百万颗 Trainium2）在前沿规模上验证它。
- **Groq 用容量换 SRAM 带宽，再用芯片数放大内存池。** 第一代 GroqRack 在 64 颗活跃芯片上只露出 14 GB；Groq 3 LPX 把它扩到 256 芯片上 128 GB，合计 SRAM 带宽 40 PB/s。它的 12 TB DDR5 层以及与 Rubin 的配对表明，LPU 是补充而不是替换大内存 GPU 机柜。
