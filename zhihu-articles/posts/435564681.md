**一. 主流的GPU编程接口**

- Cuda：英伟达公司推出，显卡俗称为N卡
- OpenCL ： 开源的gpu编程接口，几乎适用于所有的显卡，相较于cuda难一些
- DirectCompute: 微软开发出来的gpu编程接口，只能用于Windows系统

**二.Cuda: compute unified device architecture, 计算统一设备架构**<br>a. thread<br>b. block: 含有多个thread，可以为1，2，3 维<br>c. grid: 含有多个block，可以1，2维度，一个kernel函数对应一个grid<br>d. SP: streaming processor, 最基本的处理单元(硬件的概念)<br>e. SM : streaming multiprocessor, 多个SP组成一个SM（硬件的概念）<br>f. 每个thread由每个sp执行，每个block由每个SM执行，一个kernel由一个grid执行。

**三. Cuda中的SM，SP，Warp的关系：**<br>SP（streaming Process），SM（streaming multiprocessor）是硬件（GPU hardware）概念。而thread，block，grid，warp是软件上的（Cuda）概念。一块GPU卡中，包含大量的SM，每个SM又包含大量的SP。<br>**硬件上：**<br>SM ：Stream Multiprocessor，流多处理器，基本控制指令单元，拥有独立的指令调度电路，一个SM下所有的SP共享同一组控制指令。<br>SP： Stream Processor，流处理器。基本算数指令单元，没有指令调度电路，只有独立执行的算数电路，包括一个ALU（Arithmetic Logic Unit）和一个FPU（Float Point Unit）。每个SP负责处理固定数量的线程。SP中的线程，共享同一组算数指令，处理不同的数据。这种并行执行的方式，称为SIMD（single intruction multiple data, 单指令多数据）<br>**软件上：**<br>warp：线程束，是cuda中的逻辑概念，每个warp对应一个SP，warp size等于SP中可使用的线程个数，通常为32。<br>一个block对应一个SM, 一个SM可以调度多个block。<br>同一网格（grid）中的所有线程，共享相同的全局内存空间

**五. Cuda编程常识：常见的 host, device, global标识**<br>_ _ host_ _: 程序代码在cpu上执行，与普通的C++无异<br>_ _ device_ _: 程序代码在gpu中的线程执行，不能调用普通的cpu函数<br>_ _ global_ _: cpu调用，gpu执行，常常以foo<<>>(a)的形式调用，不能运行cpu函数<br>不要在.cpp文件中声明_ _ device _ _ 和 _ _ global _ _函数，应该在.cu中声明。kernel函数返回类型必须为void，必须写在.cu的文件中。

**六. Cuda内存模型：2+6**<br>**host内存（2种）**：pageable memory 和pinned memory<br>pageable memory：由os api（malloc，new）分配的内存空间（会用到虚拟内存技术）<br>pinned memory：始终存放于物理内存中，不会被分配到低速虚拟内存中，能够通过DMA技术加速，与设备端进行通信cudaHostAlloc()与cudafreeHost （）来分配和释放pinned memory。 pinned memory如果分配过多，会导致OS用于分页的物理内存变小，导致系统整体性能下降。通常由哪个线程分配，就只有这个线程才能访问权限。<br>**显存（6种）**：constant memory和texture memory，二者都是device只读。texture memory适用于图像，可以很好的加速。kernel中访问纹理存储器的操作，叫做纹理拾取（texture fetching），将显存中的数组与纹理参照系相关联的操作，称为纹理绑定（texture binding）。显存中，可以绑定到纹理的数据有：普通线性存储器和cuda数据。

![](https://pica.zhimg.com/v2-3265c99389175f0925bc6f8c51f4478e_r.jpg)

常量内存与纹理内存，都是device只读，host端都是可读写的。Global Memory没有Cache，访问速度慢，Shared Memory访问速度快，但容量小，对于较大的数组，将其绑定到texture memory是个不错的选择。Texture memory含有cache，而且容量很大。

纹理内存实际上属于全局内存，利用缓存技术（纹理缓存）来减少对全局内存的访问（空间局部性原理），使得程序运行的更快。对于图像中的最近邻插值，双线性插值非常适合。 使用纹理内存的两种方式：**纹理参考（texture reference）**和**纹理对象（cuda texture desc）纹理拾取（texture fetching）**:从cuda的内核函数访问纹理存储器的操作。 **纹理绑定（texture binding）**：纹理拾取使用的坐标与数据在显存中的地址可以不同，二者通过纹理参照系（texture reference）约定从数据的地址到纹理坐标的映射方式。将显存中的数据与纹理参考系关联的操作，称为将数据与纹理绑定。显卡中可以绑定到纹理的数据有两种：普通的线性内存（linear memory）和cuda数组（cuda array）。线性内存只能与一维和二维纹理绑定。cuda array可以与一维，二维，三维纹理绑定。

**七. cuda Stream: GPU操作的一个队列，用于设备重叠，提速。**

通常使用Stream是为了实现以下2点：

同一个操作（例如cpu到gpu的内存拷贝）即便在不同流中，应该也是串行的。这里涉及到引擎Copy engine和kernel engine的问题。<br>cuda流的使用，应该遵循广度优先，而非深度优先。<br>**深度优先**：先向Stream0添加操作，执行完Stream0，再向Stream1添加操作。<br>**广度优先**：向Stream0添加操作，向Stream1添加操作，执行Stream0，再执行Stream1.<br>原因：硬件上没有Stream的概念，而是通过不同的引擎实现的。执行内存拷贝的引擎有一个或两个（cpu到gpu，gpu到cpu），执行核函数的引擎有1个。为了更好的提升性能，2个流之间应该交叉操作，即广度优先。

**八. Cuda 同步函数（同步指的是cpu与gpu）：3种**<br>**cudaDeviceSynchronize()**：该方法将停止CPU端线程的执行，直到GPU端完成之前CUDA的任务，包括kernel函数、数据拷贝等。<br>**cudaStreamSynchronize()**：这个方法接受一个stream ID，它将阻止CPU执行，直到GPU端完成相应stream ID的所有CUDA任务，但其它stream中的CUDA任务可能执行完也可能没有执行完。 **cudaThreadSynchronize()**：该方法的作用和cudaDeviceSynchronize()基本相同，但它不是一个被推荐的方法，也许在后期版本的CUDA中会被删除。<br>**cuda kernel函数**是异步执行的，即kernel函数在调用之后会立即把控制权交换给cpu，cpu接着向下执行。<br>**CudaMemcpyAsync** (这个async指的是： 下一句代码的执行不用等这句copy操作执行)：仅对锁页内存有效，如果传入的是可分页内存的指针，则会返回错误, 锁页内存由cudaHostAlloc分配。

**九. Cuda锁页内存（pinned memory or page locked memory）**<br>对于Cuda架构而言，主机端(Host)的内存被分为2种，一种是可分页内存，一种是锁页内存。<br>**可分页内存（pageable memory）**，由OS API （malloc或new）在主机上分配的，锁页内存由Cuda函数cudaHostAlloc（）在主机上分配。主机的OS不会对锁页内存进行分页与交换，确保该内存始终驻留在物理内存中。

**锁页内存**，不会交换到磁盘中。GPU知道锁页内存的物理地址，可以通过DMA（Direct Memory Access）技术，直接在内存中访问。主机端存在虚拟内存，虚拟内存就是主机端的一部分磁盘空间当作内存来使用。当物理内存不够用时，会产生缺页中断，将一部分内存数据交换到虚拟内存中（磁盘空间），需要该页时，再从磁盘空间加载过来。虚拟内存要比实际的物理内存大一些。

<br>Cuda中，锁页内存的使用，可以用Cuda驱动API（driver API's）cuMemAllocHost（），或者使用Cuda的运行时API（runtime API）中的cudaMallocHost（）。除此之外，还可以用主机上Malloc分配的空间，然后将其注册为锁页内存（使用cudaHostRegister（）函数）。<br>cudaMalloc（）分配的是显存，cudaMallocHost（）分配的是锁页内存。cudaMemcpy函数可以进行device到host端的拷贝 / host到device的拷贝 / device到device的拷贝 / host到host的拷贝。

**十. Cuda原子操作**<br>当一个线程（thread）要对同一个显存变量依次进行“读—计算—写”操作时，该操作必须连贯地执行，中间不能插入其他操作（相当于给显存变量加了锁）。
