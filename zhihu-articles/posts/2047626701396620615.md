## 1. 前言

最近在使用 **ms-swift** 框架微调 **Qwen3.6 35B-A3B** 模型时，发现训练后的模型**不支持 MTP（多 Token 预测）推理**。查阅文档确认：**MTP 推理必须依赖 Megatron 架构 + Megatron-Swift 框架才能支持**。

因此重新搭建并配置了 **Megatron-Swift** 训练环境，但过程中遇到了大量环境依赖、版本冲突、编译报错等问题，踩坑非常多。特此记录完整环境配置与避坑方案，方便后续复用。

## 2. 运行环境

- **显卡**：4 × A800（A800 不支持 fp8 训练）
- **CUDA 版本**：12.8
- **nvcc 版本**：12.8

## 3、环境包安装（踩坑过程就不讲了）

```text
# python 3.12
# 基础依赖
pip install torch==2.8 torchvision==0.23.0 torchaudio==2.8.0 --no-build-isolation

# flash-attn 重装
pip uninstall -y flash-attn

# ms-swift 使用的4.2版本
cd ms-swift-main-v4.2.0.dev0
pip install -e .

# megatron 核心
pip install megatron-core==0.17.1 --no-build-isolation
pip install mcore-bridge==1.4.3 --no-build-isolation

# Transformer Engine（你本地wheel）
# 下载地址：https://github.com/NVIDIA/TransformerEngine/releases
pip install transformer_engine_torch-2.15.0+cu12torch2.8.0+cu129cxx11abiTRUE-cp312-cp312-linux_x86_64.whl --no-build-isolation

# 模型相关库
pip install transformers==5.4.0（训练：5.4.0，推理：5.3.0）
pip install qwen_vl_utils==0.0.14
pip install decord -U

# mistral & flash attention
pip install --upgrade mistral_common==1.11.3 --no-build-isolation
pip install flash-linear-attention==0.5.0
# 下载地址：https://github.com/Dao-AILab/flash-attention/releases?page=2
pip install flash_attn-2.8.3+cu12torch2.8cxx11abiTRUE-cp312-cp312-linux_x86_64.whl
```

## 4、训练启动脚本

### 4.1 启动脚本模板参考：

[https://github.com/modelscope/ms-swift/tree/main/examples/megatron](https://github.com/modelscope/ms-swift/tree/main/examples/megatron)

### 4.2 常用命令解释：

**MoE (混合专家) 专属加速**

| 参数 | 一句话解释 |
| --- | --- |
| --moe_permute_fusion true | 算子融合：将 MoE 路由的 Token 重排操作与矩阵乘法合并，减少显存读写。 |
| --moe_grouped_gemm true | 分组矩阵乘法：将发给同一个专家的 Token 打包一次性计算，大幅提升吞吐量。 |
| --moe_shared_expert_overlap true | 通信与计算重叠：在计算“共享专家”时，异步进行“路由专家”的网络通信，隐藏延迟。 |
| --moe_aux_loss_coeff 1e-6 | 负载均衡惩罚项：强制 Token 均匀分配给各个专家，防止所有计算都挤在一两个专家身上。 |
| --moe_expert_capacity_factor 2 | 专家容量上限：允许每个专家处理的 Token 数达到平均值的 2 倍，防止突发流量导致 Token 被丢弃。 |

**分布式并行策略**

| 参数 | 一句话解释 |
| --- | --- |
| --tensor_model_parallel_size 2 | 张量并行 (TP=2)：将模型的权重矩阵切分到 2 张 GPU 上并行计算。 |
| --expert_model_parallel_size 8 | 专家并行 (EP=8)：将 MoE 的不同专家切分到 8 张 GPU 上（8卡刚好每张卡分担一部分专家）。 |
| --sequence_parallel true | 序列并行 (SP)：配合 TP 使用，将长序列的维度也切分到不同 GPU，进一步节省显存。 |

**显存优化**

| 参数 | 一句话解释 |
| --- | --- |
| --recompute_granularity full | 全量激活重计算：不保存前向传播的中间结果，反向传播时重新计算，用计算时间换大量显存。 |
| --recompute_method uniform | 配合 full 使用，表示均匀地选择需要重计算的层。 |
| --recompute_num_layers 1 | 逐层重计算：每次只重算 1 层，显存占用曲线最平滑，峰值最低。 |
| --cross_entropy_loss_fusion true | 交叉熵融合：不将巨大的 Logits 矩阵写入显存，而是在 Kernel 内即时计算 Loss 并丢弃，省数 GB 显存。 |
| --use_precision_aware_optimizer true | 精度感知优化器：允许优化器状态使用较低精度存储，进一步省显存。 |
| --exp_avg_dtype bf16 | 优化器的一阶动量 (Adam 的 m) 使用 bf16 (2字节) 存储，而非默认的 fp32 (4字节)。 |
| --exp_avg_sq_dtype bf16 | 优化器的二阶动量 (Adam 的 v) 使用 bf16 (2字节) 存储。 |

**Batch 与 训练控制**

| 参数 | 一句话解释 |
| --- | --- |
| --micro_batch_size 1 | 微批次大小：单张 GPU 每次只处理 1 个样本，将单步显存压到最低。 |
| --global_batch_size 4 | 全局批次大小：模型参数更新一次，总共看 4 个样本（通过梯度累积实现）。 |
| --max_length 4096 | 模型处理的最大序列总长度（Prompt + Response 的 Token 总数）。 |
| --packing true | 序列打包：将多个短样本拼接成一个完整的 4096 长度序列，消除 Padding 带来的计算浪费。 |
| --num_train_epochs 1 | 整个数据集只遍历训练 1 轮。 |
| --finetune true | 声明当前为微调模式（加载预训练权重，而不是从头随机初始化）。 |
| --lr 1e-5 | 训练达到的峰值学习率。 |
| --lr_warmup_fraction 0.05 | 前 5% 的训练步数中，学习率从 0 线性增长到峰值，防止初期梯度爆炸。 |
| --min_lr 1e-6 | 训练结束时，学习率衰减到的最低值。 |
