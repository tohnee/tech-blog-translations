面向”改 MCP 本身”：服务器架构、公开 API、协议实现、线程与生命周期模型、配置面、扩展点。


### 7.2 Origin 校验：防 DNS rebinding

Server.cpp:116-210 的规则，按顺序：

| 情况 | 结果 |
| --- | --- |
| "null" | 拒绝 —— 沙箱 iframe、跨源重定向、file:// 都发这个，不能只放行本地文件场景 |
| 无法解析成裸 scheme://host[:port] | 拒绝 —— 浏览器不可能发出的 Origin 就是伪造的 |
| host 是 localhost / 127.0.0.1 / [::1]（大小写不敏感） | 放行 |
| 命中规范化后的 AdditionalAllowedOrigins | 放行 |
| 完全没有 Origin 头 | 放行（非浏览器客户端） |
| Origin 头数量 ≠ 1 | 403 |

拒绝时返回 403 + 警告，但**日志只记配置条目的数量而非内容**（注释：”any page can drive this path at request rate and the list would size the output”），并用 `EscapeControlCharactersForLog` 处理。

CORS 头由 `MakeCorsResultCallback`（:155-173）盖在**每一个响应上，包括 SSE 开流那次写**；`SkipHeaderWrite` 时跳过；否则盖 `Vary: Origin`。

配置项在 `PostInitProperties` / `PostReloadConfig` / `PostEditChangeProperty` 三处校验，**非法条目直接剔除并警告**：

> “…is not a scheme://host[:port] origin and was removed. A browser sends its Origin in that form, so an entry in any other form can never match.”

`EnforceValidAdditionalAllowedOrigins` 会保留一个空行给编辑器的”添加”按钮。`PostEditChangeProperty` 跳过 `EPropertyChangeType::Interactive` —— 注释：”Don’t fight the user while they are still typing”。

**设置头里那段 ToolTip 是整个插件最重要的安全说明**（:72，原文）：

> Origins accepted in addition to localhost, 127.0.0.1 and [::1], each a bare scheme://host[:port] such as “http://192.168.1.10:3000”. The Origin allow-list is what stops a web page reaching this server through DNS rebinding, so every entry here widens that surface. Only loopback origins are verified end to end: a browser applies its own private-network rules on top of CORS when a page from a less private address space reaches this server, and satisfying those is not implemented.

即：**白名单是唯一防线，每加一条都在扩大攻击面；只有 loopback 做过端到端验证，浏览器的 private-network 规则并未实现满足。**

### 7.3 命令行 / 控制台 / CVar

```text
# 命令行
-ModelContextProtocolStartServer          # 无视 bAutoStartServer
-ModelContextProtocolPort=N               # 1-65535，非法则警告并回落设置
-StartModelContextProtocolServer          # 已废弃，会一次性警告

# 控制台（Module.cpp:26-72）
ModelContextProtocol.StartServer [port]   # 校验 1-65535
ModelContextProtocol.StopServer
ModelContextProtocol.RefreshTools
ModelContextProtocol.GenerateClientConfig <Client|All>

# CVar
ModelContextProtocol.WrapPODToolResultsInObject  bool   true   # 1.0 → {"result":1.0}
ModelContextProtocol.AudioResultOggFormat        bool   false  # ogg 而非 wav
ModelContextProtocol.ProgressIntervalSeconds     float  1.0
ModelContextProtocol.PaginationPageSize          int32  0      # 0 = 不分页
ModelContextProtocol.EnableAnalytics             bool   true
```

前四个定义在 ModelContextProtocol.cpp:43-67；**`EnableAnalytics` 单独定义在 ModelContextProtocolAnalytics.cpp:15**，不在同一处。

日志类别：`LogModelContextProtocol`。

**Commandlet 默认跳过自启**（Settings.cpp:51-59），注释解释原因：cook 之类的 commandlet 会和并发运行的编辑器抢监听端口，绑定失败会导致 commandlet 失败。要开必须显式传 `-ModelContextProtocolStartServer`。

`ShouldAutoStartServer()` 的完整判定顺序：

```text
-ModelContextProtocolStartServer      → true
-StartModelContextProtocolServer      → true + 一次性废弃警告
IsRunningCommandlet()                 → false
否则                                   → bAutoStartServer
```

Tool Search 开关走 provider 模式（ModelContextProtocol.cpp:71-89）：`SetToolSearchEnabledProvider(TFunction<bool()>)` 由拥有该项目设置的下游模块安装，`IsToolSearchEnabled()` 读它、否则用 `DefaultToolSearchEnabled`；安装时广播 `OnToolSearchEnabledChanged`。

### 7.4 启动流程

`StartupModule`（Module.cpp:256-278）：

```text
检查非空 → ToolsetRegistryAdapterManager.Initialize()
  → 若 bAutoStartServerExternallyManaged && !IsRunningCommandlet() → 记日志并 return
  → 若 GIsRunning → AutoStartServer()
     否则 hook FCoreDelegates::GetOnPostEngineInit()
```

`AutoStartServer()`（:280-288）在已运行或 `!ShouldAutoStartServer()` 时 no-op。

`StartServer`（:235-243）创建 Server 并订阅 `OnRefreshTools` → `ScheduleToolsListChangedBroadcast`。

### 7.5 客户端配置生成

ModelContextProtocolClientConfig.h：

| 客户端 | 路径 | 行为 |
| --- | --- | --- |
| ClaudeCode | .mcp.json | JSON，合并保留既有条目 |
| Cursor | .cursor/mcp.json | 同上 |
| VSCode | .vscode/mcp.json | 同上 |
| Gemini | .gemini/settings.json | 同上 |
| Codex | .codex/config.toml | TOML，write-once，已存在则报错返回 false |

根目录 `GetRootDirectory(BaseDirectory="")` 默认：**源码版 `FPaths::RootDir()`，安装版 `FPaths::ProjectDir()`**。

API：`GetRelativePath` / `GetFilePath` / `Write(Client, Port, UrlPath, BaseDirectory)` / `WriteAll(...) → int32`。

**一个被忽略的扩展点**：

```cpp
FServerConfiguration{Name, Command, Url}
RegisterServerConfiguration(...) / UnregisterServerConfiguration(...)

```

`Url` 为空时写出 `"type":"stdio"` 条目 —— 也就是说**可以把自己的 stdio MCP 服务器注册进去，让 `GenerateClientConfig` 一并写进客户端配置**。`UnregisterServerConfiguration` 只影响后续生成，**不删已写文件**（注释：”Unregistration leaves saved files intact because generation only updates registered entries”）。
