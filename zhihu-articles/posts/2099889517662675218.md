在验证时通过以何种概率接受投机token？

1、Greedy Search（贪婪搜索）

草稿模型预测一个 Token y。Target 模型对它进行验证，直接看 y 是不是 Target 模型在这一步概率最高 $\arg\max\$ ）的那个 Token。

2、随机采样

拒绝采样的核心公式是看**概率的比值**：接受概率 $\(M = \min\left(1, \frac{P(x)}{Q(x)}\right)\)$

当发生拒绝时，我们不能直接从 P(x) 中重新随机采样，而是必须从**残差分布（Residual Distribution）**中采样.残差分布的直观理解是：**把 Target 分布中，那些已经被草稿模型过度代表（分走）的概率剔除掉，剩下的那部分真正属于 Target 的概率。**如果让 Draft 模型把每一退步的全词表分布 Q(x) 都保存下来并传给 Target 模型，会带来极大的**显存传输带宽瓶颈（Memory Bandwidth BottleNeck）**。只传输 Top-K 或采样到的单词（工业界主流优化）

马尔可夫头是一个**“走一步、算一步、采一步”**的串行循环过程

1. 输入准备

在计算第 t 个位置的最终 Logits 时，马尔可夫头有两个输入：

- $\(L_{base}^{(t)}\)$ ：并行部分（Parallel Backbone）一次性输出的、第 t 个位置的 **Base Logits**（维度为 `[Vocab_Size]`）。它代表了模型纯粹基于历史上下文，对当前位置的“粗略预判”。
- $\(x_{t-1}\)$ ：前一个位置（t-1 位置）刚刚被实际**采样（Sampling）**出来的具体 Token 的 ID。

2. 马尔可夫修正项计算（查表）

马尔可夫头内部维护了一个巨大的**权重矩阵（Embedding Matrix）**，通常称为 $ W_{markov}$ ，其维度是 `[Vocab_Size, Vocab_Size]`。实际计算用低秩分解为两个矩阵

- 这个矩阵本质上编码了**词与词之间的转移概率**（类似于传统统计自然语言处理中的 Bigram 二元语法）。
- 当得知前一个 Token 是 $ x_{t-1}$ 时，马尔可夫头不需要做矩阵乘法，而是直接通过 **Embedding Lookup（查表/切片）**，从 $W_{markov}$ 中取出第 $x_{t-1}$ 行。
- 取出来的这一行，就是针对当前位置词表所有 Token 的**偏差修正向量（Bias/Correction Vector）**，我们记为 $\(\Delta L^{(t)}\)$ （维度同样是 `[Vocab_Size]`）。

3. 融合与最终采样

最后，将并行预判的底座与马尔可夫头的修正项**直接相加**，就得到了该位置最终的 Logits：

$\(\text{Final\ Logits}^{(t)}=L_{base}^{(t)}+\Delta L^{(t)}\)$

得到 $ \text{Final\ Logits}^{(t)}$ 后，系统会立刻进行 Softmax 并采样出第 t 个位置的 Token $x_{t}$ 。而这个新采样出的 $x_{t}$ ，紧接着又会被送入第 t+1 个位置的马尔可夫头计算中，循环往复。
