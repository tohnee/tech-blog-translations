## 一、V4.1 Flash 1017 是什么？

### 1、出身：552B 的「小」模型

先说个反直觉的事：V4.1 Flash 名字里带 Flash（DeepSeek 全系最小尺寸的模型），但它的总参数其实有 **552B** ——之所以敢叫 Flash，靠的是全新的 **Causal-Encoder-Decoder 非对称结构** ：处理输入时只激活 8B 参数，生成输出时只激活 16B。

打个比方：以前的模型像食堂大锅饭，不管你点啥菜，后厨全员出动；V4.1 Flash 则是「看人下菜碟」——读你需求的时候只派一小队人（8B），动笔干活的时候再多叫几个（16B），552B 的家底大部分时间在休息。成本自然就降下来了。

配套的两个硬参数：

- **上下文长度 1M token** ，最大输出 384K——一口气读完几十万行的代码库没问题
- **原生多模态** ，支持图像理解（这次跑分表里就有好几项视觉测试）

另外新架构把 KV Cache（模型工作时存的「草稿纸」）大幅压缩：对显存的需求降到上一代的 1/4，对硬盘的需求降到 1/8。省下来的都是真金白银，这也是敢定低价的底气。

### 2、1017 版到底更新了什么？

一句话概括： **成绩更好，干活更快，价格不变** 。

官方的说法是「性能–费用的帕累托改进」：相比 9 月的 V4.1 Flash 初版，1017 版在各项基准测试里全面涨分，同时任务的运行时间和输出长度反而缩短了——花更少的钱，办更多的事。

这次更新还点名针对 **DeepSeek Harness** 、腾讯 CodeBuddy、WorkBuddy 这几个 Agent 框架做了适配优化。划重点： **Harness 要升级到 0.2.1-rc.1 以上版本** 才有完整适配，小灰后面会实测。

技术上，1017 版用了一种「基于自反馈的强化学习」训练方法，重点提升从零构建完整项目的能力——游戏开发、3D 建模这类「许愿式」任务，就是这次的主打卖点。

### 3、价格和开源

价格完全没变，还是走峰谷定价（高峰是工作日白天，闲时半价）：

|  | 高峰时段 | 空闲时段 |
| --- | --- | --- |
| 输入（缓存未命中） | 2 元 / 百万 token | 1 元 / 百万 token |
| 输入（缓存命中） | 0.04 元 / 百万 token | 0.02 元 / 百万 token |
| 输出 | 8 元 / 百万 token | 4 元 / 百万 token |

作为对比，隔壁 Claude Opus 5 级别的旗舰模型，输出价格是它的十几倍。而且模型权重已经在 HuggingFace 和 ModelScope 上开源（MIT 协议），有卡的大佬可以自己部署。

## 二、官方跑分：11 项里拿了 4 个第一

发布当天，DeepSeek 放出一张跑分表，拉来 Kimi K3、GLM 5.3、GPT 5.6-Sol、Claude Opus 5 陪跑，11 个 benchmark 里 1017 版拿了 4 个第一：

![](https://pic2.zhimg.com/v2-bd09579095695952976f6a4f8f8bda69_r.jpg)

表格很长，小灰挑几个重点：

- **最硬的一项是 DeepSWE v1.1** （模拟真实世界的软件工程任务）：1017 版 77.0 分全场第一，超过 Claude Opus 5 的 74.0 和 GPT 5.6-Sol 的 73.0——「许愿式编程」的底气主要来自这里
- **Agent 类任务全面领先** ：Agents' Last Exam 35.4、Automation-Bench 60.5、Apex Bench 72.1，这三项都是第一
- **相比上一代进步明显** ：Terminal-Bench 从 31.2 涨到 42.3，ProgramBench 从 20.3 涨到 29.1，涨幅都在三四成

要知道这可是一个 Flash 级（小尺寸档）的模型，在软件工程和 Agent 这些硬核项目上压过一圈旗舰大模型，含金量不低。其余项目上各家互有胜负，整体上 1017 版已经稳稳站在第一梯队。

比分数更有意思的是官方另一张图—— **通过率 vs 每任务费用** 。同样是 DeepSWE 测试，1017 版以 77% 的通过率拿下第一，而单个任务的平均费用 **不到 2 块钱** ；通过率相近的 Claude Opus 5 和 GPT-6 Astra，单任务费用要三四十块，差了二十多倍：

![](https://pic2.zhimg.com/v2-5b146ae14266d86b2d07621632e7c6b7_r.jpg)

当然，官方跑分大家都懂，先看看就好。许愿灵不灵，还得亲手试。

接下来我们选取两个真实案例，以此来检验一下 DeepSeek V4.1 Flash 1017 的实际生成效果。

同时，我们也会把同样的提示词发给 GPT-6 Astra 模型，看一看究竟谁更强。

## 三、实测案例一：许愿一个「霓虹赛车游戏」

**提示词如下：**

```text
帮我做一个网页版 3D 赛车游戏，用 Three.js 实现，单个 HTML 文件就能在浏览器里直接玩。要求：霓虹夜景风格的环形赛道，方向键控制赛车转向和加减速，有漂移手感和撞墙减速惩罚，计时显示单圈圈速，画面要有速度感（路面流光、粒子拖尾之类的都可以）。不用过多解释，直接做出来让我玩。
```

### DeepSeek V4.1 Flash 1017：20 分钟交卷，小瑕疵 3 分钟修好

小灰在 DeepSeek Harness 里发出这条 prompt 后，就去泡了杯咖啡。20 分 39 秒后，任务完成——一个名叫《NEON DRIFT · 霓虹环道》的赛车游戏躺在了文件夹里，单个 HTML 文件写了 **1833 行代码** 。

![](https://pic1.zhimg.com/v2-ee03d307bdffb903ba67a1e6458b81f4_r.jpg)

从交付说明看，诚意是足的：方向键加速刹车、左右转向、空格漂移、撞墙减速、单圈计时，甚至还有 **三圈完赛结算** 。模型还特意强调「已实测单圈计时、漂移、撞墙减速、暂停与三圈完赛结算」——看起来是做完功课才交的卷。

先看成品。平心而论，这个画面第一眼相当唬人：粉青撞色的霓虹赛道、城市天际线、路面流光，HUD 上时速、圈速计时、小地图一应俱全，审美这次是真的在线：

![](https://pica.zhimg.com/v2-96a1715ce833e88caf2840d6d5409400_r.jpg)

小灰上手试玩时发现一个小瑕疵：A、D 两个键的左右转向和直觉是反的（WS 前后是正常的）。小灰把问题反馈回去，模型立刻自己定位到了病根——「转向角速度的符号写反了，前轮视觉方向也跟着反了」， **3 分 5 秒就修复完毕** ，刷新即玩：

![](https://picx.zhimg.com/v2-d0dc8fb1928f298a444aafe17751c9a9_r.jpg)

这个环节其实挺能说明 Agent 时代的用法：一次性做到 95 分，剩下 5 分的小瑕疵，你一句话它就秒修。 **从许愿到修好，全程不到 24 分钟。**

修复后再上车，转向、漂移、撞墙减速全部正常。

### GPT-6 Astra：不到 10 分钟交卷，还真的「试玩」了

同样的 prompt 发给 GPT-6 Astra。先把测试条件写清楚：Astra 走的是 ChatGPT 的 **Codex 入口** ，推理强度一共有五档，小灰选的是中间档「 **高** 」——就是下图这个位置，不高不低，也是它默认推荐的档位：

![](https://pica.zhimg.com/v2-36424469f874fe8f316788a6e35a0150_r.jpg)

不到 10 分钟就交付了，速度是 DeepSeek 的两倍。成品同样是霓虹环形赛道、漂移、撞墙减速、圈速计时，Three.js 也直接嵌进了单文件。

Astra 的工作过程有个亮点：从 Codex 的任务记录里能清楚看到，它写完代码后没有直接交卷，而是 **调起浏览器工具，真的打开游戏试玩了一把** ——「正在检查转向与漂移手感、撞墙惩罚，以及检查点和圈速计时」，中间还反复截图查看画面：

![](https://pic3.zhimg.com/v2-788143ebbaab9c5019820670e414ebba_r.jpg)

小灰实际上手开了几圈，转向、漂移、撞墙惩罚全部正常。Astra 版的赛车叫《霓虹弧线·午夜环线》，画风比 DeepSeek 版素一些，但 HUD 信息更密：当前圈数、本圈用时、最佳圈速、检查点进度、挡位全都实时显示：

![](https://pic4.zhimg.com/v2-c917da3c494f81792deefdada1ffa065_r.jpg)

### 案例一小结

|  | DeepSeek V4.1 Flash 1017 | GPT-6 Astra |
| --- | --- | --- |
| 耗时 | 20 分 39 秒（修复再加 3 分 5 秒） | 不到 10 分钟 |
| 代码体量 | 单文件 1833 行 | 单文件，一次成型 |
| 画面风格 | 粉青霓虹，视觉冲击力强 | 深色简约，HUD 信息更密 |
| 交付后 | 转向小瑕疵，一句话 3 分钟修好 | 无需返工 |

这一轮两边都「许愿」成功、一次成型，成品质量说实话在一个水准线上，风格各有所爱。真正的差距在 **成本和速度** ——这个先埋个伏笔，文章后面小灰专门算一笔账，差距大到出乎意料。

## 四、实测案例二：许愿一个「3D 故宫漫游」

**提示词如下：**

```text
帮我做一个可以在浏览器里漫游的 3D 故宫，用 Three.js 实现，单个 HTML 文件就能打开。要求：中轴线上要有午门、太和殿、乾清宫等主要宫殿建筑群（不是只有一幢），红墙黄瓦的配色，支持 WASD 键第一人称漫游和鼠标拖动环视，有天空、光照和简单的动态效果（飞鸟、旗帜飘动之类）。不用过多解释，直接做出来让我逛。
```

### DeepSeek V4.1 Flash 1017：21 分钟，交出整个紫禁城

这次 DeepSeek 用了 21 分 52 秒，交付了一个《紫禁城漫游.html》，Three.js 直接内联进了文件， **离线双击就能逛** ，连网都不用。交付界面长这样：

![](https://pic1.zhimg.com/v2-78c54235b60696119a1955b1c893e646_r.jpg)

先看成色。小灰最担心的「独栋宫殿」问题没有出现——它沿中轴线一口气摆了 **十组建筑** ：午门、太和门、太和殿、中和殿、保和殿、乾清宫、交泰殿、坤宁宫、御花园、神武门，外金水桥也没落下。

配色是对的红墙黄瓦，天上飘着云，有飞鸟掠过，宫殿前的旗帜会随风摆动。下面是中和殿、保和殿一线的实景，重檐、栏杆、门钉这些细节都做了：

![](https://pic1.zhimg.com/v2-ccbc6eba9e200a1e4b06a21d133a2138_r.jpg)

漫游操控也做得挺全：WASD 第一人称走动、鼠标拖动环视、Shift 疾行、R 一键回到午门，右上角还有实时位置提示（走到哪座宫就显示哪座宫的名字），右下角配了一张宫城小地图，左上角一枚「紫禁城 THE FORBIDDEN CITY · 1420」的印章式 Logo，细节审美在线。绕到宫殿背后转了转，建筑都在，没有出现「背面消失」的穿帮。

### GPT-6 Astra：更快，还多了个「鸟瞰模式」

Astra 这边同样不到 10 分钟收工。思路和 DeepSeek 不太一样：它也沿中轴线布置了午门、太和门、三大殿和后三宫，但额外做了两个实用功能—— **右侧小地图可以直接跳转各处** ，以及一个 **鸟瞰切换按钮** ，先看全貌再落地漫游。功能清单里还有碰撞限制（不会穿墙走进宫殿里）、日光与夕照两种光照切换：

![](https://pic4.zhimg.com/v2-e7d26ef9e1cba39a0e8c207814c9b5f5_r.jpg)

和赛车案例一样，它做完后也调起浏览器自己检查了一遍实际画面和移动操作才交卷。小灰实际逛了一圈，漫游、环视都很顺畅。

成品界面信息密度更高：右侧「中轴导览」面板把午门到御花园一路的宫殿全列出来，点击名字直接传送；左下角走到哪座殿，就显示这座殿的名字和一句简介（比如交泰殿是「乾清与坤宁之间的方形宫殿」），有点电子导览机那味儿了：

![](https://pic2.zhimg.com/v2-26e9626d66e33451540c039be7aa6339_r.jpg)

**案例二小结**

|  | DeepSeek V4.1 Flash 1017 | GPT-6 Astra |
| --- | --- | --- |
| 耗时 | 21 分 52 秒 | 不到 10 分钟 |
| 建筑群完整度 | 中轴线十组建筑 + 金水桥 | 中轴线多组宫殿 + 庭院宫墙 |
| 特色功能 | 位置实时提示、宫城小地图、飞鸟旗帜、离线可玩 | 中轴导览传送、鸟瞰模式、日光/夕照切换、宫殿简介 |

这一轮两家都交出了完整的「宫殿群」，画面各有千秋——DeepSeek 胜在光影氛围和动态细节（飞鸟、飘旗、云层都活了），Astra 胜在导览信息设计。从「许愿」的角度，两边都灵。

## 五、算一笔账：两块钱 vs 烧穿的限额

案例比完，最后算一笔账——这可能是两边差距最大的地方。

**DeepSeek 侧** ：按量计费，赛车游戏 + 故宫漫游两个案例，连许愿带修复全部跑完， **总共花了不到 2 块钱** 。没错，就是一瓶矿泉水的价格。而且按量计费意味着想跑几个跑几个，没有额度焦虑。

**Astra 侧** ：小灰用的是 Plus 订阅（20 美元/月）里的 Codex 入口，推理强度「高」。Astra 在 Plus 里走的是限量额度——每 5 小时一个窗口。小灰一开始图快，把赛车和故宫 **两个任务同时开跑** ，结果两个任务都没跑完，5 小时限额就直接到顶了，只能干等窗口刷新后一个一个排队重跑。

也就是说：同样两个「许愿」任务，DeepSeek 花不到 2 块钱随便跑；Astra 在 Plus 里得掐着额度精打细算，一次还只能跑一个。当然得说清楚，这不是 Astra 本身贵——它 API 按量也能用，只是输出每百万 token 要 50 美元，真按量跑这两个案例，花费同样是 DeepSeek 的几十倍。

官方那张「通过率 vs 费用」图里说 1017 版单任务不到 2 块钱、是同级旗舰的二十分之一—— **小灰这次实测下来，这个说法是可信的。**

## 六、总结

测完两个案例，小灰对 DeepSeek V4.1 Flash 1017 的印象可以浓缩成三句话：

1. **「许愿式编程」是真的成了。** 一句话要一个 3D 赛车游戏、一句话要一座能漫游的紫禁城，它都一次成型地交了出来——赛车有漂移、圈速结算和霓虹特效，故宫有完整的中轴线十组建筑、飞鸟旗帜和离线可玩的单文件。要知道一个月前第三方复现官方案例时，DeepSeek 还只会盖「独栋宫殿」，1017 这版的进步是实打实的。 

2. **交互体验很成熟。** 试玩中发现小瑕疵，一句话反馈，3 分钟就定位到「转向角速度符号」并修复——这种人机协作的顺滑度，才是日常使用里最高频的体验。跑分表上 DeepSWE 77 分全场第一、Agent 类三项第一，和实际体感是对得上的。 

3. **便宜到可以随便用。** 两个案例连跑带修不到 2 块钱；同样的事在 Plus 订阅的 Astra 上，5 小时限额都不够烧的。对普通开发者和重度 Agent 用户来说，这个价格就是「许愿自由」。

| 追求极速交付、且不缺额度 | GPT-6 Astra | 交付速度快一倍，自带浏览器自测，但 Plus 额度紧、API 贵 |

作为国产模型，DeepSeek 这一代真的让小灰眼前一亮： **旗舰级的 Agent 能力，白菜价的使用成本，还开源。** 「许愿式编程」这个口号，1017 版算是接住了。
