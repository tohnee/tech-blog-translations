## 前言

大模型逐 Token 自回归生成，瓶颈就一个字：串行。一次只能吐一个词，延迟高，吞吐也上不去。

投机解码（Speculative Decoding）是眼下工业界用得最多的加速方案。思路不复杂：让一个轻量的草稿模块先批量猜几个候选 Token，再让主模型一次性前向把这些候选都验一遍，从而省下大量主模型的推理次数。

方案现在很多，容易看花眼：初代的双模型投机、Medusa 的多头、EAGLE 走到第三代、各家厂商的原生 MTP、还有DFlash + DDTree。很多人搞不清它们底层的差别、时序逻辑，也不知道各自适合什么场景。这篇就把脉络、原理、优劣和选型一次讲清楚，写给想系统搞懂推理加速的算法和工程同学。

### 一、初代基准：原始投机解码（Vanilla，2023 奠基）

### 1. 架构

两个模型分开：一个完整的小草稿 LLM（Drafter），加上主大模型（Target Verifier）。

### 2. 流程

**草稿阶段**：小草稿自回归串行生成 K 个候选 Token，同时把每一步的输出分布 $q_i$ 存下来。

**校验阶段**：把原始上下文和整条草稿拼起来送进主模型，只跑一次完整前向。Transformer 本来就能并行算序列里所有位置，所以一次就能拿到这 K 个新位置上主模型的原生条件分布 $p_i$。

**接不接受，用拒绝采样来判（这是行业统一的标准做法）**：

$$ \alpha(\hat{x}_i)=\min\left(1,\;\frac{p_i(\hat{x}_i)}{q_i(\hat{x}_i)}\right) $$

- 生成一个 0 到 1 的均匀随机数 $u$，若 $u<\alpha$，接受这个草稿 Token，接着验下一位；
- 一旦被拒，当前及之后的草稿全丢掉，从残差分布里重采样一个 Token：

$$ p_{\text{resid}}(x)=\frac{\max\bigl(0,\;p(x)-q(x)\bigr)}{\sum_{x}\max\bigl(0,\;p(x)-q(x)\bigr)} $$

- 如果 K 个草稿全过，再额外用主模型的原生分布多采一个 Token。

这套做法的关键在于它是**无损**的：最后输出的分布，和主模型自己逐 Token 生成完全一致，一点精度都不牺牲。

![](https://pic4.zhimg.com/v2-847abc316cb0f3cc7b92c2737910c61b_r.jpg)
*投机解码4步流程*

### 3. 优缺点

- 优点：不用动基座，词表大小一样的模型随便拼，上手门槛极低。
- 缺点：两个模型都得加载，显存开销很大，分布式部署也麻烦；而且小草稿和主模型的特征分布天然对不齐，草稿一长，接受率就有个明显的天花板。

### 4. 它的位置

后面那些单模型自投机方案（Medusa、EAGLE、各家 MTP），说白了都是在解决同一个问题：双模型的显存冗余。

---

### 二、第一类单模型自投机：并行多头 MTP（Medusa / Gemma / Qwen / GLM-5.2）

特征是多头并行、没有时序依赖。所有预测头共用主干最后一层那同一个隐藏态，所以预测 $t+2$、$t+3$ 的时候，是看不到 $t+1$ 草稿长什么样的。

### 1. Medusa（外挂微调多头，纯加速插件）

![](https://picx.zhimg.com/v2-55463b13d88cdb23cf1b99220c068f6f_r.jpg)
*Medusa架构图*

- 主干冻结，末尾加几个独立的线性 MLP 头，并行预测 $t+1$ 到 $t+K$；
- 基座预训练时没有多 Token 的监督信号，这里只微调新加的几个头，所以它不提升模型本身的能力，纯粹用来加速；
- 致命问题是几个头之间完全独立、互不通信，没有注意力去建模序列的因果关系。一旦超过 3 步，草稿的语义就容易散掉，长路径的接受率掉得很厉害；
- 校验靠笛卡尔积生成一棵简单的候选树，配合 Tree Attention 批量验，只适合短文本、短句的场景。

### 2. 厂商原生并行多头 MTP（Gemma 4、Qwen 3.5+、GLM-5.2）

跟 Medusa 最大的不同在于：预训练阶段主干和多头是一起训的，多 Token 的损失也参与了全局反向传播。这一来一回有两个好处，既能让模型在长上下文、代码推理上更强，又能顺手把 MTP 头拿来做投机草稿。

- 训练损失上，越往后的预测头权重越小，弱化远距离的预测损失；
- GLM-5.2 还额外做了点事：适配 MoE 的稀疏注意力，复用主干的 KV 缓存，把百万上下文场景下草稿的算力开销压下来；
- 共同的短板还是那个，没有时序依赖，长草稿连贯性不行，超长推理场景有上限。

---

### 三、第二类单模型自投机：时序链式自回归草稿（EAGLE 全系列 / DeepSeek 级联 MTP）

这类反过来，草稿严格按自回归因果来生成：预测 $t+i$ 时要用到 $t+i-1$ 的草稿特征。序列天然连贯，长路径表现比并行多头那一类好得多。

### 1. EAGLE-1 / EAGLE-2（特征外推，初代）

![](https://pic3.zhimg.com/v2-e84dc77cf0f12853e001371e83eb41be_r.jpg)
*EAGLE完整流水线*

![](https://pic4.zhimg.com/v2-05b17cd40324ce7b9aadb976d4a398d9_r.jpg)
*EAGLE静态树 vs EAGLE2动态树*

- 底层逻辑是不直接预测 Token，而是用轻量 MLP 递归预测主干倒数第二层的隐藏特征，再借用主模型的 LM Head 输出候选分布；
- EAGLE-1 用固定深度的静态草稿树，不管文本简单还是复杂都生成同样长度的草稿，结果一堆低置信度的分支白白浪费算力；
- EAGLE-2 加了基于置信度的动态剪枝，提前把低概率路径砍掉，同等算力下能再快 20%~40%；
- 两代共通的瓶颈：只用主干单层顶层特征做输入，训练又只喂真值特征，训练和推理之间存在分布 gap，扩数据之后性能很快就饱和了。

### 2. EAGLE-3（通用基座上最好用的外挂加速，2025 的工业主流）

![](https://pic1.zhimg.com/v2-182fbf28bb44d252e42abad39ec77ee6_r.jpg)
*EAGLE-3训练架构图*

这一代做了三件事，把前代几个天花板都拆了：

1. 不再做特征回归这种代理任务，直接预测 Token 分布，L1 特征损失整个删掉，只拿主模型的输出当唯一优化目标；
2. 把主干浅、中、高多层特征一起喂给草稿头，句法、局部语义、全局推理都能兼顾；
3. 训练时完整模拟一遍草稿的自回归推演（他们叫 TTT 范式），提前让模型见识误差累积，长草稿路径的准确率上去了不少。

适配 Llama、Mistral、Qwen 这些没有原生 MTP 的开源基座都没问题，单串低延迟和高并发吞吐两边都能兼顾，草稿接受率一般能稳在 90% 以上。

### 3. DeepSeek V3 / R1 的级联式 MTP（原生内置的时序 MTP）

- 预训练时就原生集成了多级微型 Transformer 级联模块，自回归链式推演，时序依赖是完整的；
- 收益是双向的：多步损失参与预训练，数学、代码这些评测指标会涨；推理时直接把这个模块拿来当草稿；
- 约束也很明确：MTP 只是草稿器，建模容量比完整主干弱，必须经过主模型批量校验，不能直接把它的输出当最终结果。

### 四、第三类创新自投机：DFlash + DDTree（块并行，没有串行草稿）

前面绝大多数方案，草稿阶段都得串行循环生成 K 步候选。DFlash 干脆不串行了，用块掩码做并行预测，专门冲着万亿 MoE 这种超大模型去的。

### 1. DFlash 块并行草稿模块

- 一个 MiMo 模型只配一套 DFlash 小型 Transformer 草稿网络，不搞多副本并行；
- 核心做法是：输入一个全 Mask 的占位块，一次前向就并行输出整块 K 个位置的概率分布，草稿阶段没有循环开销。K 越大，相对 EAGLE 或级联 MTP 省的算力越多；

### 2. DDTree（DFlash 之上的树调度增强，不能单独用）

DFlash 一次会输出每层的多个候选 Token，DDTree 拿全部概率信息去搭一棵最优的多分支树：

- 按路径累积置信度排优先级，用大顶堆优先去扩那些高可信度的长路径；
- 同时卡住 GPU 的树节点预算，自动丢掉那些碎片化、低置信的短分支；
- 再配 Tree Attention，让主模型一次前向就把整棵树验完。同等算力下，单轮能接受的 Token 数能多 20%~40%。
- 一轮完整DDTree推理流程（块长3，每层取top3候选）

```text
【历史上下文 + 上一轮遗留锚点token a（树根）】
↓
深度1（t+1，DFlash第一层分布）
  ┌───────┬───────┐
  token b token c token d
    ↓       ↓       ↓
深度2（t+2，所有分支共用同一套候选[e,f,g]）
┌─┴─┐   ┌─┴─┐   ┌─┴─┐
  e   f   e   f   e   f
  ↓   ↓   ↓   ↓   ↓   ↓
深度3（t+3，所有分支共用同一套候选[h,i]）
┌┴┐ ┌┴┐ ┌┴┐ ┌┴┐ ┌┴┐ ┌┴┐
 h i h i h i h i h i h i
```

- 主干Verifier遍历校验逻辑

根a → 深度1 b(绿色通过) → 深度2 e(绿色通过) → 深度3 h(红色拒绝) ✅ 批量输出：a b e 🔄 下一轮树根：主模型原生重采样token a’

### 五、第四类半自回归 —— DeepSeek DSpark（并行 + 局部串行，2026-06）

DFlash 把串行草稿省了，但并行天生有个病：每个位置独立预测，尾部多模态碰撞、接受率衰减。DSpark（DeepSeek + 北大，挂在 DeepSeek-V4 上）的解法是 —— **并行做主力，再补一个超轻的串行头注入块内依赖**。

### 1. 半自回归：并行 backbone + 轻量串行头

- 并行段用 DFlash 一次前向出整块 base logits；串行段叠一个依赖前缀的偏置 $B_k$，自回归因式分解 $P(X|x_0)=\prod_k p_k$，$p_k=\text{softmax}(U_k+B_k)$。
- 默认 Markov head：只看前一个 token，低秩分解 $B=W_1W_2$（rank 256）。采了「of」就在下一位抬「course」压「problem」，多模态碰撞就这么消了。RNN head 增益小、默认不用。
- 串行头够轻，总草稿延迟仍由并行段主导，速度优势没丢。实测 2 层 DSpark 就能打过 5 层 DFlash —— 一点局部自回归，性价比远高于把并行网络一味堆深。

### 2. 反直觉：并行凭什么反超自回归

位置 1 上，并行草稿器延迟和块长无关（$O(1)$），可以用深得多的网络；自回归（EAGLE-3）$O(\gamma)$ 只能浅。所以位置 1 并行更准（实测 0.88 vs 0.81）。而投机解码是严格前缀存活 —— 首 token 杠杆最高 —— 这点容量优势被放大到全局接受长度，并行就反超了。尾部衰减，交给串行头补。

### 3. 置信度调度验证（系统层，这才是线上关键）

- 验证越多不一定越快：高并发下，验证注定被拒的 token 在抢 batch capacity。DSpark 给每个位置估存活概率 $c_k$，乘上实测的硬件吞吐曲线 $\text{SPS}(B)$，做全局吞吐 $\Theta=\tau\cdot\text{SPS}(B)$ 最大化调度 —— 空闲多验、繁忙少验。
- 两个工程要点：神经置信度过自信（ECE 3%–8%），但调度要的是绝对概率不是排序，所以专门做温度校准（STS）压到 ~1%；无损性要求非预期性，靠 early-stopping 防 selection bias（附录反例：回顾式全局搜索会把目标分布 (0.7, 0.3) 带偏到 (0.85, 0.15)）。

### 六、几条绕不开的规律（对所有投机方案都成立）

### 草稿永远不能直接输出，必须过主模型这一关

不管是 MTP、Medusa、EAGLE 还是 DFlash，草稿模块的建模容量和上下文视野都比完整主干弱得多，多步推演会不断累积误差。只有把草稿拼起来送进主模型、算一遍原生分布 $p$，才能保证输出和原生逐 Token 生成完全一致，不引入逻辑错误、采样漂移，也不掉评测指标。

### Tree Attention 是批量校验的底座

靠自定义的树形因果掩码，主模型一次前向就能并行算出多条分支、所有位置的条件分布。批量校验多路径、长草稿，全靠它撑着。

### 技术路线的分水岭

- 无时序的并行多头（Medusa、GLM / Gemma / Qwen 的多头 MTP）：实现简单、增量参数小，但长多步连贯性差；
- 时序链式或块内建模（EAGLE、DeepSeek 级联 MTP、DFlash）：结构复杂一点，但长路径接受率和加速上限更高。
- 半自回归（DSpark）：并行出 base logits + 轻量串行头补依赖，专治并行的尾部衰减，是前两条路线的折中。

### 两种训练模式的区别

- 外挂插件型（Medusa、EAGLE）：主干训完就冻结，只微调加速头，只用来加速，不提升模型本身能力；
- 原生内置 MTP（DeepSeek、GLM、Gemma、MiMo）：预训练时主干和草稿模块一起优化，精度和速度两头都受益。

### 六、选型速查

| 底座 / 场景 | 推荐 |
| --- | --- |
| Llama、Mistral 这类没有原生 MTP 的通用开源基座 | EAGLE-3（综合最均衡），DSpark也可以尝尝鲜 |
| DeepSeek 系列底座，要原生加速 | 内置级联 MTP |
| 国产稀疏 MoE、百万级长文本 | GLM-5.2 并行多头 MTP |
| 万亿级超大 MoE、云端要极致吞吐 | DFlash + DDTree |
| DeepSeek-V4、高并发线上、要无损 + 严格交互 SLA | DSpark（半自回归 + 置信度调度） |
| 简单闲聊、想最低开发成本、短文本 | Medusa |
| 没有微调算力、要开箱即用 | 原始双模型独立小草稿投机解码 |

### 结尾

整条演进线其实很清楚：从双模型的冗余架构，到单模型外挂多头或时序草稿，再到厂商在预训练里原生集成 MTP，最后走到 DFlash 这种连串行草稿都省了的块并行。再往下，DSpark 又在并行基础上补了一层局部自回归，把并行的尾部衰减解了，重心也从此前的「草稿器设计」挪到了「草稿器 × 系统调度协同」。

没有哪个方案是绝对最优的。怎么选，看你的底座是什么、上下文多长、业务是代码还是推理还是闲聊、显存多少、线上并发压力多大。把这些底层的东西，时序依赖、训练范式、草稿和主干之间的分布差异，想明白了，自然就知道该挑哪一个。
