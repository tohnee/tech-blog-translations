Agent = LLM + Harness

要理解智能体，必须同时理解 LLM 与 Harness。

一、对大语言模型的理解

大语言模型本质上将输入文本转换为输出文本。文本可呈现为字、词、句、段、篇，承载语义；语义传递意图，意图可分为描述性意图与执行性意图。

语言符号是静态的，但语义可以指涉动态执行——静态描述能够指向动态过程，再结合环境交互，便可转化为执行步骤。

LLM 通过一个 token 预测下一个 token，是一种基于注意力机制的概率性输出。这种机制注定了它天然具有语义不确定性。

提升输出准确性有两条路径：基座模型可通过参数调整（训练）来优化；用户则可通过优化提示词来提升输出质量。

二、对智能体的理解

1.智能体是什么

对话机器人只能基于提示词输出文本。这些文本可能包含行为语义或非行为语义，但本质上仍是静态的。然而，动态执行对干预现实具有重大意义。因此，为具有行为语义的文本配备可调用的工具，并通过代码解析输出、基于解析结果调用工具，就能获得改变环境的能力，实现文本触及现实。这种将大模型与工具结合、能够改变现实的系统，就是智能体。

比如：这个查询天气的例子，llm会根据提示词的要求去会输出json格式，代码去解析这个格式，得到参数和工具名就可以去调用这个函数，实现对天气的查询功能。

![](https://pic1.zhimg.com/v2-91f72c414046a07be1c9b71454e9fbbe_r.jpg)

但大模型本身的不确定性与改变现实行为所需的确定性相冲突。因此，需要在文本输入前和输出后构建多种机制，确保智能体将不确定性持续收敛为可验证的步骤，指导其按步骤调用工具、执行行动。

2.智能体的发展阶段

2.1 围绕大模型实现可以解决问题

① toolcall：实现可以调工具toolcall，做到文本可以触及现实，实现的原理是llm会的输出会包含要调用工具的Json串，代码解析完成之后再回给llm，llm再输出，问题是：只是一个步骤，事情通常是多个步骤的；

② 于是就发多几次，模型输出，看看要不要调工具，要就把信息加一个再发回去，反复直到不发工具为止，这就是react，推理行动，再推理再行动…；

③ React并没有对内容进行批判，只是看看有没有调工具的指令，于是再加一个批判，其实就是调一下大模型，加一个提示词，看看这个解决了没，要不要再调用工具，这就是reflection，反思；

④ 到了reflection，这样可以解决问题了，但是大模型特点是长程任务容易遗忘，于是再前面加一个人计划去列出Todo，这就是Plan&Execute；

⑤ 前面已经实现了一个全干工程师，但是开发过程中，一个人做前端，后端，文档，设计，维护，这样也容易发闷，于是就在plan&execute的基础上，再加一个可以去指派给不同subagent执行的步骤，实际和toocall很像，只是把tool外面套了一层agent，就到了到了多智能体阶段，解决问题能力已经解决了。

如何更好解决问题呢？就要围绕上下文怎样去拼装了，工具该给才给，上下文根据目标调整，多了要总结压缩，这就是上下文工程，至此智能体围绕大模型展开的解决问题能力的构建的工程化阶段就达成了，实现了解决问题的高性能。

2.2 上升到系统性阶段

智能体可以解决问题，如何进行约束，让它在限制的范围内工作，于是就要加上枷锁，就是Harness，去解决高可用，高安全，可观测，它需要把上面的都包进来：

· 任务与目标：动态执行首先需要明确任务和目标。

· 多轮循环：目标可能不明确，需通过多轮输入输出循环逐步澄清，形成上下文。

· 上下文装配：上下文包含静态语义和动态语义（如工具 schema、skill），统一装配为 prompt 输入 LLM。

· 能力调用：智能体可生成代码，基于输出语义调用工具和 skill，从而将提示词转化为能力包。

· 权限与记忆：过程中需控制权限，执行前甄别所用技能与工具，并引用历史经验（组织长期记忆）和上下文（短期记忆），还需解决跨窗口信息传递等记忆问题。

以上都被包 Harness之内，即介于人与大模型之间的中介约束层，如同约束马的马具，对其整个过程进行控制和约束。

![](https://pic3.zhimg.com/v2-7d232d099e24876a8c150c32057dd636_r.jpg)

Harness 包括控制能不能做、支撑做的能力，以及运行过程约束三个部分：

① Control（控制层）→ Harness 的“治理面”约束

对应 Control Harness，决定“能不能做、做到什么程度”。核心机制是可许性控制——不是简单的黑名单拦截，而是通过状态机、行为树和规则看门狗的组合，精确定义 Agent 行为的合法空间。例如，Agent 的每一次行为被建模为状态转移，状态机确保它只能沿着合法路径执行。此外还包括权限控制、环境隔离、审批门禁、预算限制等。

② Agency（能动层）→ Harness 的“行为面”控制

对应 Agent Harness，负责“做事”：模型 + 工具调用 + 任务拆解。但 Agency 不直接拥有执行权。模型产生的只是一个“工具调用意图”，Harness 决定这个意图是否被允许成为现实。Agency 在 Harness 划定的合法空间内进行规划、推理和工具选择。

③ Runtime（运行时层）→ Harness 的“执行载体”和管制落实处

对应 Harness 的运行时策略与执行引擎。它管理模型-工具循环、上下文、状态、持久化、重试、委托和停止行为。具体包括：会话管理、工具编排、审批策略、验证、失败恢复、可恢复会话等。

Runtime 是 Control 与 Agency 交汇并落地的地方——控制规则在此被强制执行，能动决策在此被转化为实际动作。

三、为什么要学习Harness

1. 厂内的痛点

我们如果要用Agent来解决厂内的问题，直接用通用智能体，解决不了专业的问题，因为基座大模型围绕通用智能设计，通用智能体的Harness围绕通用问题而设计，它们追求的是全量的智能最优解，好比正态分布的均值；但对 FAB 而言，我们需要的可能是向右偏 2Σ 的位置。因此，实现路径有两条：①微调大模型；②干预 Harness框架。显然，①不现实——基座大模型迭代太快且成本极高，所以，只能选择方案②。

2. 构建FAB的Harness

对 Harness 的干预，可以借鉴对大模型的训练方法。如果大模型是大脑，那么 Harness 相当于小脑，它有使能的一面也有控制的一面；设计这个小脑，可以参考对大脑的训练方式，LLM 使用的语料是全局的，而 Harness 训练的语料则聚焦于该智能体所服务的应用场景。

Harness 由许多组件构成，比如 skill 组件、agent loop 机制、上下文等。基于上述推导，只要往这些组件中注入垂直行业的“语料”，就可以直接影响模型输出，再搭配特定工具配合输出，便能产生对现实环境有影响的行为，例如：hold lot、trigger drb、down tool、csn recipe 等。

因此，问题聚焦于：如何设计出一套包含上述组件、且便于注入垂直经验的 Harness“训练”机制，做到安全可控，同时又高性能的Harness。

在FAB，非结构化知识才是企业经营的运行核心逻辑，结构化数据只是运行的结果，AI要发挥作用就必须理解非结构化知识。非结构化知识存储在文档和代码里。因此，Harness固化厂内知识需要包含结构化和非结构化两个部分的内容。

四、把厂内知识固化为Harness组件或者嵌入组件之内

![](https://pic1.zhimg.com/v2-4a8efac983db0013ef55bf305a860102_r.jpg)

大模型训练是把语料中的规律压缩进模型参数，推理时，注意力权重根据当前上下文动态计算，完成信息加权。大模型输入文本后基于模型参数预测下一个 token，本质是“参数化知识 + 动态推理”。

①FAB 领域知识的工程化也可遵循类似逻辑：把厂内知识和行业经验沉淀为可检索、可计算、可编排、可版本化的领域模型，实现输入一个业务对象，系统就能关联或推导出下一个相关对象与动作。比如：输入 lot OCAP，应能找到对应的 process 机台，并带出相关的 inline、offline chart 等，让这一部分单独成为一个Harness的行业组件，然后注入上下文之中。

②模型会持续演进，FAB模型组件也要持续迭代：支持版本管理、灰度发布、回滚、执行反馈和人工校正，逐步实现自进化。

FAB组件作为“小脑”重要的补充，它不替代大模型，而是把领域知识、控制规则和执行经验固化、编排、迭代起来，让模型能力落地为可执行的业务动作，并随模型和业务一起进化。

半导体的领域知识普遍是七八十年的前的东西，但是日常的运作却高度依赖经验积累，具体工作场景又普遍依赖经验模型进行推理，数据丰富、因果明确、反馈可测，理论上非常适合 AI。随着基模能力不断提升和将厂内知识持续固化成知识层和场景约束，再加上传统的IT安全治理的通用约束，成为FAB的专属Harness。

最终逐步实现Agent帮找 chart、帮关联机台、帮写初判是否加量，到自动写RAD，持续迭代演进。

1、RAG方案

传统RAG只有相似性，没有相关性；只能根据相似度抓取一堆不管有用没用、相关不相关的信息都喂给LLM，输出正不正确全靠LLM算力；只有相似性、没有相关性的信息给LLM，这就造成了不确定性、幻觉；大量无效的知识输入造成巨大的无效算力浪费，在算力越来越贵的预期下，这个问题必将成为企业重点考量因子；要解决这个问题，只有将喂给LLM之前的知识进行精细处理，目前业界使用的是图普方案。

2、本体方案

微软研究院 2024 年提出， **把非结构化文本自动构建知识图谱，用图结构做检索增强生成** ，解决传统向量 RAG 不擅长 **跨文档、多跳推理、全局总结** 的问题。

![](https://picx.zhimg.com/v2-d3350589db9db49181bc1706f0ebcdef_r.jpg)

![](https://picx.zhimg.com/v2-2f855e4bb810fde6e4e93694ee1d43c3_r.jpg)

1. **多跳推理能力：可以串联分散在多篇文档里的事实链；传统 RAG 多个事实分散在不同 chunk 时容易断裂。**
2. **全局归纳能力：可以对整个知识库做主题归纳，传统向量 RAG 很难完成。**
3. **推理路径可追溯：可以输出答案来自哪些实体、哪些关系，合规审计场景友好。**
4. 降低部分幻觉：结构化图谱约束生成空间。
