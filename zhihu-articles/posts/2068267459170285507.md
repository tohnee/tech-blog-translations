## 投机解码（Speculative Decoding）

### 一句话定义

用一个小模型或轻量模块先猜出多个候选 token，再由大模型一次前向并行验证、通过拒绝采样保证输出分布与原模型完全一致的无损解码加速方法。

### 要解决的问题

自回归解码生成 K 个 token 需要 K 次串行前向，每次前向都要把全部模型参数从显存读一遍。解码阶段是内存带宽受限而非算力受限，小 batch 下 GPU 算力大部分时间闲置。

### 核心机制

### 基本框架（draft-then-verify + 拒绝采样）

1. 一个约 10 倍小的 draft model 快速生成 K 个候选 token
2. 大模型（target）一次前向并行验证
3. 用修改过的拒绝采样决定接受最长前缀，并对第一个被拒位置重新采样

关键性质：输出分布与原模型完全一致，加速不改变输出质量、不改模型结构。

### 为什么验证一段短序列 ≈ 生成一个 token

- MLP 层时间由线性层权重加载主导，与 token 数几乎无关
- 注意力层的 KV cache 读取与候选长度无关
- 小 batch 下激活通信是延迟主导而非吞吐主导

### 演进脉络

### 思想渊源：CPU 投机执行

从分支预测 + 回滚借鉴而来。2018 年 Stern 等人的 Blockwise Parallel Decoding 已尝试”并行预测多步、回退到最长已验证前缀”，但需训练专门的 blockwise 模型且主要覆盖 greedy 场景，未成主流。

### 第一轮改进：draft 从哪来

痛点：需额外找、训、部署一个和目标匹配的 draft model，匹配度直接决定加速上限。

| 方案 | 思路 | 关键结果 |
| --- | --- | --- |
| Medusa | 目标模型上加轻量多头，各头预测未来第 k 个 token | 参数增加 %，2.2-3.6x |
| EAGLE | 改在特征空间自回归，复用目标模型顶层特征 | EAGLE-3 最高 6.5x |
| LayerSkip | 训练浅层可早退，推理时浅层当 draft、全模型验证 | 1.8-2.2x，无需第二个模型 |
| Sequoia | 动态规划求最优候选树 + 新采样验证法 | Llama2-7B 4.04x、13B 3.73x、33B 2.27x |

### 第二轮改进：验证成本成为新瓶颈

draft 树变大后，问题从”猜得准不准”转向”验证付不付得起”：

- 每个候选 token 占 batch 一个位置，高并发下验证被拒的尾巴浪费 batch 容量
- MoE 模型里大 draft 树激活大量分散 expert，验证时重新打爆带宽
- 推理模型长 CoT 让 KV cache 带宽成为主要瓶颈

代表证据：

- EcoSpec 把 expert 激活成本纳入 draft 选择，DeepSeek-V3.1（671B）、Qwen3-235B-A22B 上最高 1.62x；MoE-Spec 固定每层 expert 预算，比 EAGLE-3 baseline 吞吐高 10-30%
- DSpark 把验证长度从静态超参变为按请求自适应的调度决策（根据候选前缀存活概率和引擎吞吐特性动态决定验证多长），draft 侧用半自回归架构补回块内依赖；在 DeepSeek-V4 生产环境对比 MTP-1 baseline，每用户生成速度提升 60-85%

### 范式变化：加速内建于训练

DeepSeek-V3 的 MTP（Multi-Token Prediction）把”预测未来第 2 个 token”直接写进预训练目标，推理时 MTP module 就是现成的高匹配 drafter，不再额外花训练成本。vLLM、SGLang、TensorRT-LLM 已原生支持 MTP/EAGLE/Medusa。

### 关键判断

- 解码是带宽问题而不是算力问题，这是整个方向的底层依据
- 拒绝采样保证输出分布无损，是”免费加速”的理论根基
- 两条演进线：猜的手段从独立小模型 → 多头 → 特征空间 → 浅层早退 → 训练内建 MTP → 非自回归一次出整段；验的手段从单序列 → 树注意力 → expert 预算 → 置信度调度验证

### 适用边界

以上加速数字均来自各论文公开报告，具体数值依赖模型规模、batch 大小、QPS 和采样设置，不能直接跨场景外推。落地选择：模型自带 MTP 则优先用 MTP（零额外训练成本）；通用大模型部署选 EAGLE 系；低 QPS 延迟敏感场景收益最大，高 QPS 吞吐场景需配合动态投机和验证长度调度。
