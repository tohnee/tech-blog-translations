用TileLang来写的算子越来越多了，那么TileLang和Triton的算子主要区别是什么呢？这里从3个典型的算子来总结一下，随后便可管中窥豹逐渐贯通。

Triton和TileLang都是用于编写高性能GPU内核的领域特定语言（DSL），但它们在设计哲学和语法上存在显著差异。简单来说，**Triton追求自动化与便捷性，而TileLang则强调精细控制与性能潜力。**

## 典型语法与用法

### Triton

- **内核定义**：使用 `@triton.jit` 装饰器修饰一个Python函数-。
- **编程模型**：以**线程块（Thread Block）** 为基本单位，编译器负责向量化和内存管理。
- **内存管理**：**隐式自动管理**，例如共享内存的分配和同步由编译器在后台处理-。
- **核心操作**：使用 `tl.load` 和 `tl.store` 进行数据加载与存储，使用 `tl.dot` 执行矩阵乘法。
- **控制流**：支持 `if`、`for` 等标准Python控制流。

### TileLang

- **内核定义**：使用 `@T.prim_func` 装饰器定义计算逻辑，外部用 `@tilelang.jit` 进行编译[-15](https://www.tilelang.com/programming_guides/language_basics.html)。
- **编程模型**：基于**分块（Tile）** 的**声明式编程**。Tile是一等公民，可以是Block、Warp或线程级的数据块。
- **内存管理**：**显式控制**。需手动声明数据位置，如 `T.alloc_shared`（共享内存）、`T.alloc_fragment`（寄存器）-。
- **核心操作**：使用 `T.copy` 进行数据移动-，使用 `T.gemm` 执行矩阵乘法。
- **控制流**：支持标准Python `if` / `elif` / `else` 和循环-。

那我们就快速的来看典型的3种算子： 1D算子， 2D算子， SFU算子。跨机器的通信算子需要拓展原语，比如现有的库iris。这里暂时不展开说明。

[https://rocm.github.io/iris/reference/triton/overview.html](https://rocm.github.io/iris/reference/triton/overview.html)

## Add算子Triton和TileLang的说明

例如Add这一类的elementwise算子逻辑十分简单，基本的逻辑就是先计算好kernel每次并行量处理多少数据，根据这个数据量把完整的数据切成若干的Blocks，在kernel中根据pid映射好数据offset，launch kernel并行执行，tilelang在代码上隐藏了offset计算的更多逻辑，更加的简洁。期望未来生态中会有更多的算子支持，并且tune到更好的性能。

```python
import torch, triton, triton.language as tl

@triton.jit
def add_kernel(x_ptr, y_ptr, out_ptr, n_elements, BLOCK_SIZE: tl.constexpr):
    pid = tl.program_id(axis=0)                  # ① 获取 Block 索引
    block_start = pid * BLOCK_SIZE               # ② 计算起始偏移
    offsets = block_start + tl.arange(0, BLOCK_SIZE)  # ③ 生成线程ID序列
    mask = offsets < n_elements                  # ④ 边界掩码
    x = tl.load(x_ptr + offsets, mask=mask)      # ⑤ 加载 X
    y = tl.load(y_ptr + offsets, mask=mask)      # ⑥ 加载 Y
    tl.store(out_ptr + offsets, x + y, mask=mask) # ⑦ 存储结果

def add_triton(x, y):
    out = torch.empty_like(x)
    n = out.numel()
    grid = lambda meta: (triton.cdiv(n, meta['BLOCK_SIZE']),)
    add_kernel[grid](x, y, out, n, BLOCK_SIZE=128)
    return out
```

```python
import tilelang, tilelang.language as T
from tilelang import jit
import torch

# N 用符号整数表示，由外部传入
@T.prim_func
def add_kernel_tile(
    A: T.Tensor((T.symbolic("N"),), "float32"),
    B: T.Tensor((T.symbolic("N"),), "float32"),
    C: T.Tensor((T.symbolic("N"),), "float32"),
):
    N = A.shape[0]                       # 从张量形状获取大小
    with T.Kernel(T.ceildiv(N, 128), 128) as (bx, tx):
        idx = bx * 128 + tx
        if idx < N:
            C[idx] = A[idx] + B[idx]

# jit 编译时需提供具体的 N，但这里我们会从输入张量动态获取
@jit
def add_kernel(A, B, C):
    # 注意：C 必须预先分配好空间（例如 torch.empty_like）
    add_kernel_tile(A, B, C)

def add_tilelang(x, y):
    out = torch.empty_like(x)
    add_kernel(x, y, out)
    return out

x = torch.randn(2048, dtype=torch.float32, device='cuda')
y = torch.randn(2048, dtype=torch.float32, device='cuda')
z = add_tilelang(x, y)   # 现在任意长度都可以
```

elementwise的代码比较简单，就不展开说明了，后面详细看看matmul的实现代码。

## Matmul算子Triton的详解

```python
@triton.jit
def matmul_kernel(a_ptr, b_ptr, c_ptr, M, N, K,
                  BLOCK_M, BLOCK_N, BLOCK_K):
    pid_m = tl.program_id(0)                               # ① 获取 M 方向 Block 索引
    pid_n = tl.program_id(1)                               # ② 获取 N 方向 Block 索引
    rm = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)          # ③ 行索引序列
    rn = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)          # ④ 列索引序列
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)  # ⑤ 累加器（寄存器）
    for k in range(0, K, BLOCK_K):                        # ⑥ K 维循环
        a = tl.load(a_ptr + rm[:, None] * K + (k + tl.arange(0, BLOCK_K))[None, :]) # ⑦ 加载 A 块
        b = tl.load(b_ptr + (k + tl.arange(0, BLOCK_K))[:, None] * N + rn[None, :]) # ⑧ 加载 B 块
        acc += tl.dot(a, b)                               # ⑨ Tensor Core 乘法累加
    tl.store(c_ptr + rm[:, None] * N + rn[None, :], acc)  # ⑩ 存储结果

def matmul_triton(a, b):
    M, K = a.shape; _, N = b.shape
    c = torch.empty((M, N), device='cuda')
    grid = (triton.cdiv(M, 32), triton.cdiv(N, 32))
    matmul_kernel[grid](a, b, c, M, N, K, 32, 32, 16)
    return c
```

```python
rm = pid_m * 32 + arange(0, 32) = [0, 1, 2, ..., 31]
rn = pid_n * 32 + arange(0, 32) = [0, 1, 2, ..., 31]
```

计算核心循环中：

```python
代码：

        b = tl.load(b_ptr + (k + tl.arange(0, BLOCK_K))[:, None] * N + rn[None, :]) # ⑧ 加载 B 块

K = 128，BLOCK_K = 16，所以循环 8 次：
k = 0, 16, 32, 48, 64, 80, 96, 112
```

关于内部的tl.load中地址操作表达式：

### A矩阵加载说明

例如A1小块中一次内部k运算的数据，需要的数据[32x16]，32行，tl.load时首先拿到32个行起始的地址：

```text
rm[:,None] 将 rm 转为列向量，形状 (32,1)，值为 [[0],[1],[2],...,[31]]
乘以 K=128 后，得到每一行的内存起始偏移，，值为 [[0], [128], [256], ..., [31*128]]
```

随后A1矩阵关于列的基地址就是：

```text
列偏移矩阵 (k + tl.arange(0, BLOCK_K))[None, :]
将 [16, 17, ..., 31] 变为行向量，形状 (1, 16)，值为 [[16, 17, 18, ..., 31]]
```

最后例如A1小块的数据加载语句的语义就是:

```text
a = tl.load(a_ptr + rm[:, None] * K + (k + tl.arange(0, BLOCK_K))[None, :]) 
```

基于地址a_ptr加载一个 32x16的数据块，每行元素的首地址偏移：[[0], [128], [256], ..., [31*128]] ， 每列元素的首地址偏移：[[16, 17, 18, ..., 31]] （第2个块）

### B矩阵加载说明

计算核心循环：

```python
代码：
    for k in range(0, K, BLOCK_K):                        # ⑥ K 维循环
        a = tl.load(a_ptr + rm[:, None] * K + (k + tl.arange(0, BLOCK_K))[None, :]) # ⑦ 加载 A 块
        b = tl.load(b_ptr + (k + tl.arange(0, BLOCK_K))[:, None] * N + rn[None, :]) # ⑧ 加载 B 块

K = 128，BLOCK_K = 16，所以循环 8 次：
k = 0, 16, 32, 48, 64, 80, 96, 112
```

例如 B 小块中一次内部`k`运算需要的数据，形状为`[16×32]`，即 16 行、32 列。`tl.load`时首先拿到 16 个行的起始地址：

```text
(k + tl.arange(0, BLOCK_K))[:, None] * N ， N = 96
```

加上 `k=0` 得到 `[0, 1, 2, ..., 15]`，然后 `[:, None]` 将其转为列向量，形状 `(16, 1)`。随后乘以N就得到了每一行B小块的偏移地址。

随后 B 矩阵关于列的基地址就是：

```text
rn[None, :] 
```

以`pid_n = 0`为例，`rn = [0, 1, 2, ..., 31]`，形状`(32,)`。

`[None, :]`将其变为行向量，形状`(1, 32)`

最后A矩阵分块和B矩阵分块做乘法得到C矩阵的partial数据acc， acc进行累加后得到C矩阵分块数据。

和A矩阵加载不同的是：

1. **A 加载的是“行连续、列切片”**：<br>固定 32 行（来自 M 维），在 K 维上取连续 16 列。
2. **B 加载的是“行切片、列连续”**：<br>在 K 维上取连续 16 行，固定 32 列（来自 N 维）。
3. **内存步长不同**：

- A 中乘以 `K`，因为 A 的每一行有 K 个元素（行优先存储）。
- B 中乘以 `N`，因为 B 的每一行有 N 个元素（行优先存储）。

## Matmul算子TileLang的详解

```python
def make_matmul_kernel(M, K, N, BM, BN, BK):
    @T.prim_func
    def kernel(A: T.Tensor((M, K), "float16"),
               B: T.Tensor((K, N), "float16"),
               C: T.Tensor((M, N), "float16")):
        with T.Kernel(T.ceildiv(N, BN), T.ceildiv(M, BM)) as (bx, by):
            A_shared = T.alloc_shared((BM, BK), "float16")
            B_shared = T.alloc_shared((BK, BN), "float16")
            C_local = T.alloc_fragment((BM, BN), "float32")
            
            # 清零累加器（关键！）
            T.fill(C_local, 0.0)

            for k in T.Pipelined(T.ceildiv(K, BK), num_stages=3):
                T.copy(A[by * BM, k * BK], A_shared)
                T.copy(B[k * BK, bx * BN], B_shared)
                T.gemm(A_shared, B_shared, C_local)  # 这里就是累加

            C[by * BM, bx * BN] = C_local
    return kernel

def matmul_tilelang(a, b, M, K, N, BM=32, BN=32, BK=16):
    """a: (M,K), b: (K,N) 均为 torch.Tensor float16"""
    kernel = make_matmul_kernel(M, K, N, BM, BN, BK)
    c = torch.empty((M, N), dtype=torch.float16, device=a.device)
    kernel(a, b, c)   # 实际上 TileLang 会 JIT 编译
    return c

A = torch.randn(1024, 2048, dtype=torch.float16, device='cuda')
B = torch.randn(2048, 1536, dtype=torch.float16, device='cuda')
C = matmul_tilelang(A, B, M=1024, K=2048, N=1536, BM=32, BN=32, BK=16)
```

可以看到tilelang的代码更加简洁。

将核函数完全参数化，通过闭包工厂接收`M, K, N, BM, BN, BK`生成专用核；调用时传入实际形状（如 1024×2048×1536），Grid 由`ceil(N/BN)×ceil(M/BM)`自动确定（本例为 48×32）。每个 Block 分配`32×16`的`A_shared`、`16×32`的`B_shared`和`32×32`的`C_local`（寄存器累加器），**务必先用`T.fill`清零**。K 维循环 128 次，每轮异步拷贝对应的 HBM 切片至共享内存，再执行`T.gemm`完成“累加型”矩阵乘（`C_local += A_shared @ B_shared`），最终将累加完成的`C_local`写回全局`C`的对应`32×32`块，所有 Block 并行拼出完整结果

## Softmax算子Triton和TileLang的详解

```python
import torch
import triton
import triton.language as tl

@triton.jit
def softmax_kernel(out, inp, stride_row, n_cols, BLOCK: tl.constexpr):
    row = tl.program_id(0)
    cols = tl.arange(0, BLOCK)
    mask = cols < n_cols
    x = tl.load(inp + row * stride_row + cols, mask=mask, other=-float('inf'))
    x -= tl.max(x, axis=0)
    out_row = tl.exp(x) / tl.sum(tl.exp(x), axis=0)
    tl.store(out + row * stride_row + cols, out_row, mask=mask)

def softmax(x):
    n, m = x.shape
    BLOCK = triton.next_power_of_2(m)
    y = torch.empty_like(x)
    softmax_kernel[(n,)](y, x, x.stride(0), m, BLOCK=BLOCK, num_warps=4)
    return y
```

```python
import tilelang
import tilelang.language as T
import torch

@T.prim_func
def softmax_kernel(A: T.Buffer, B: T.Buffer):
    M, N = A.shape
    with T.Parallel(M):
        row = T.alloc_fragment((N,), A.dtype)
        T.copy(A[0, :], row)
        max_val = T.reduce_max(row, axis=0)
        exp_row = T.exp(row - max_val)
        sum_exp = T.reduce_sum(exp_row, axis=0)
        T.copy(exp_row / sum_exp, B[0, :])

@tilelang.jit
def softmax(x):
    y = torch.empty_like(x)
    softmax_kernel(x, y)
    return y
```

softmax和Add的elementwise算子十分的相似，也是先确定好一个分块的并行度，随后根据并行下pid值计算好每个块的offset，并行launch kernel开始执行，和Add elementwise不同的是使用到的DSL关键字不同，这里不展开多余了。
