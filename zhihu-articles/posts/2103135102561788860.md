## 前端转 AI 第 40 天：本地模型部署 - 用 Ollama 跑一个自己的大模型

## 昨日回顾

Day 39 做了多模型适配，一套代码能切换所有云端模型。

**但"云端"有几个绕不过去的问题：**

- **数据要发给别人**：隐私敏感的场景不能接受
- **断网就完蛋**：网络挂了服务就挂了
- **持续烧钱**：每次调用都花钱
- **受制于人**：限流、涨价、停服

**今天上本地模型——把大模型跑在自己的机器上。**

**Day 40 目标：用 Ollama 在本地跑一个大模型，并且无缝接入 Day 39 的适配层。**

---

## 一、为什么需要本地模型

### 1. 五大场景

**本地模型不是"备胎"，是"刚需"。**

| 场景 | 为什么必须本地 |
| --- | --- |
| 隐私敏感 | 医疗、法律、金融数据不能出内网 |
| 离线环境 | 工厂、军工、偏远地区没网 |
| 高频调用 | 每天 10 万次调用，云端费用吓人 |
| 定制微调 | 想用自己数据训练专属模型 |
| 学习研究 | 想搞懂模型底层，不想被 API 黑盒 |

### 2. 真实成本对比

**云端 vs 本地，算笔账：**

**场景：** 每天 1000 次调用，平均 2000 token 输入 + 500 token 输出。

**云端（DeepSeek）：**

```text
单次：2000/1M × 0.5 + 500/1M × 2 = ¥0.002
每天：1000 × 0.002 = ¥2
每月：¥60
每年：¥720

```

**云端（GPT-4o）：**

```text
单次：2000/1M × 18 + 500/1M × 72 = ¥0.072
每年：1000 × 0.072 × 365 = ¥26280

```

**本地（一台 4090 机器）：**

```text
机器：¥15000（一次性）
电费：¥100/月
一年总成本：¥16200
两年成本：¥17400（平均 ¥725/月）

```

**结论：**

- **调用量大 + 用便宜模型** → 云端更便宜
- **调用量大 + 用贵模型** → 本地更便宜
- **隐私敏感** → 本地无价

**Break-even 点大约在"日均 5000 次调用 + 用中高端模型"**。

### 3. 本地模型的三个层次

**不是"要么全云端，要么全本地"，而是可以混着用：**

```text
┌─────────────────────────────────────┐
│        完全云端（简单起步）           │
│  API Key → 调用 → 返回               │
├─────────────────────────────────────┤
│        混合模式（推荐）              │
│  简单任务 → 本地小模型               │
│  复杂任务 → 云端大模型               │
├─────────────────────────────────────┤
│        完全本地（极致隐私）          │
│  全部推理在自己机器上                │
└─────────────────────────────────────┘

```

**今天的目标：让"混合模式"成为可能。**

## 三、Ollama 的 API

**Ollama 自带 HTTP API——不只能对话，还能编程调用。**

**验证：**

### 2. 兼容 OpenAI 的 API

**好消息：Ollama 也兼容 OpenAI 格式！**

**base_url：**

```text
http://localhost:11434/v1

```

**API Key：** 随便填（Ollama 不校验）

**这就是 Day 39 适配层的价值——完全不用改代码**，只要换 `base_url`。

### 3. 用 OpenAI SDK 调用

**创建 `day40/ollama_openai.py`：**

```text
"""用 OpenAI SDK 调用 Ollama"""
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",   # 随便填，只是为了过校验
)

def chat(message: str) -> str:
    response = client.chat.completions.create(
        model="qwen2.5:7b",
        messages=[{"role": "user", "content": message}],
    )
    return response.choices[0].message.content

if __name__ == "__main__":
    print(chat("用一句话介绍 Python"))

```

**运行：**

```text
python day40/ollama_openai.py
# Python 是一种简洁易读、功能强大的高级编程语言...

```

**代码和 Day 31 调 DeepSeek 一模一样**，只改了 `base_url` 和 `model`。

**这就是"接口标准"的威力。**

### 4. Ollama 原生 API（功能更全）

**Ollama 原生 API 有一些独有功能：**

```text
import httpx

async def native_chat(message: str):
    async with httpx.AsyncClient() as client:
        response = await client.post(
            "http://localhost:11434/api/chat",
            json={
                "model": "qwen2.5:7b",
                "messages": [{"role": "user", "content": message}],
                "stream": False,
                "options": {
                    "temperature": 0.7,
                    "num_predict": 512,     # 对应 max_tokens
                    "top_p": 0.9,
                },
            },
            timeout=60,
        )
        return response.json()["message"]["content"]

```

**流式：**

```text
async def stream_chat(message: str):
    async with httpx.AsyncClient() as client:
        async with client.stream(
            "POST",
            "http://localhost:11434/api/chat",
            json={
                "model": "qwen2.5:7b",
                "messages": [{"role": "user", "content": message}],
                "stream": True,
            },
            timeout=60,
        ) as response:
            async for line in response.aiter_lines():
                if not line:
                    continue
                import json
                data = json.loads(line)
                if "message" in data:
                    content = data["message"].get("content", "")
                    if content:
                        yield content

```

**原生 API 的优势：**

- **可以精确控制生成参数**（`num_predict` / `top_k` / `repeat_penalty`）
- **可以拉取模型信息**（`/api/show`）
- **可以管理模型**（`/api/pull` / `/api/delete`）
- **支持 embeddings**（`/api/embeddings`）——Day 46 会用到

**日常调用用 OpenAI 格式就行，特殊需求用原生 API。**

## 四、无缝接入 Day 39 的适配层

**关键优势：Ollama 兼容 OpenAI 格式，直接加一个 provider 配置就行。**

### 1. 扩展 `PROVIDER_CONFIGS`

**修改 `llm/openai_compatible.py`：**

```text
PROVIDER_CONFIGS = {
    # ... 云端厂商
    
    # 本地模型
    "ollama": {
        "base_url": "http://localhost:11434/v1",
        "api_key_env": "OLLAMA_API_KEY",     # 可以不用真的设置
        "default_model": "qwen2.5:7b",
        "is_local": True,                     # 标记本地
    },
}

```

### 2. 处理"无需 API Key"的情况

**本地模型不需要 Key。改一下校验逻辑：**

```text
class OpenAICompatibleClient(BaseLLMClient):
    def __init__(
        self,
        provider: str,
        model: str | None = None,
        api_key: str | None = None,
        base_url: str | None = None,
        timeout: float = 60.0,
    ):
        if provider not in PROVIDER_CONFIGS:
            raise ValueError(f"不支持的 provider: {provider}")

        config = PROVIDER_CONFIGS[provider]

        self.provider = provider
        self.model = model or config["default_model"]

        # 本地模型不需要 Key
        if config.get("is_local"):
            api_key = api_key or "ollama"
        else:
            api_key = api_key or os.getenv(config["api_key_env"])
            if not api_key:
                raise ValueError(
                    f"缺少 API Key，请设置环境变量 {config['api_key_env']}"
                )

        self.client = AsyncOpenAI(
            api_key=api_key,
            base_url=base_url or config["base_url"],
            timeout=timeout,
        )

```

## 五、混合模式：本地 + 云端

**真正的威力在于"混着用"。**

### 1. 智能选择策略

**创建 `llm/hybrid.py`：**

```text
"""混合模式：本地 + 云端智能选择"""
from .interface import BaseLLMClient, Message, ChatResponse
from .router import ModelRouter, TaskType, Complexity
from .factory import LLMFactory

class HybridClient(BaseLLMClient):
    """
    混合客户端

    策略：
        1. 检测本地模型是否可用
        2. 简单任务 → 本地
        3. 复杂任务 / 本地不可用 → 云端
    """

    def __init__(
        self,
        local_available: bool = True,
        local_preset: str = "local-balanced",
        fallback_to_cloud: bool = True,
    ):
        self.local_available = local_available
        self.local_preset = local_preset
        self.fallback_to_cloud = fallback_to_cloud

        self.router = ModelRouter()
        self._local_client = None

        if local_available:
            try:
                from .factory import create_client_by_preset
                self._local_client = create_client_by_preset(local_preset)
            except Exception:
                self.local_available = False

    async def _check_local(self) -> bool:
        """检查本地模型是否真的可用"""
        if not self.local_available or not self._local_client:
            return False

        try:
            # 快速调用一次测活
            import httpx
            async with httpx.AsyncClient(timeout=2) as client:
                r = await client.get("http://localhost:11434")
                return r.status_code == 200
        except Exception:
            return False

    async def chat(
        self,
        messages: list[Message],
        task_type: TaskType = TaskType.CHAT,
        complexity: Complexity = Complexity.MEDIUM,
        prefer_local: bool = False,
        **kwargs,
    ) -> ChatResponse:
        """智能选择本地或云端"""

        # 简单任务优先本地
        should_try_local = (
            prefer_local
            or complexity == Complexity.LOW
            or task_type in (TaskType.CLASSIFY, TaskType.EXTRACT)
        )

        if should_try_local and await self._check_local():
            try:
                return await self._local_client.chat(messages, **kwargs)
            except Exception as e:
                if not self.fallback_to_cloud:
                    raise

        # 走云端（路由选择）
        client = self.router.get_client(task_type, complexity)
        return await client.chat(messages, **kwargs)

    async def stream_chat(self, messages, **kwargs):
        """流式（简化：走路由选择）"""
        client = self.router.get_client(TaskType.CHAT, Complexity.MEDIUM)
        async for chunk in client.stream_chat(messages, **kwargs):
            yield chunk

```

### 2. 关键设计

**1. `_check_local`：实时探测**

**不能假设本地模型一直在**——用户可能关掉了 Ollama。

**每次调用前快速 ping 一下（2 秒超时），确认可用。**

**2. 智能判断**

**简单任务优先本地**——省钱、快<br>**复杂任务走云端**——效果好

**3. 优雅降级**

**本地失败 → 云端**<br>**云端失败 → 有 fallback 链**（Day 39）

**层层保障。**

### 3. 使用

```text
hybrid = HybridClient()

# 简单分类 → 自动本地
response = await hybrid.chat(
    messages=[Message(role="user", content="这是好评还是差评：太好了")],
    task_type=TaskType.CLASSIFY,
    complexity=Complexity.LOW,
)

# 复杂推理 → 自动云端
response = await hybrid.chat(
    messages=[Message(role="user", content="证明费马大定理")],
    task_type=TaskType.REASON,
    complexity=Complexity.HIGH,
)

```

**业务代码不关心用哪个，只声明"我要做什么"。**

## 六、性能对比与优化

### 1. 本地 vs 云端

**在同样任务上实测（Qwen2.5-7B vs DeepSeek V3）：**

| 指标 | 本地 7B | DeepSeek V3 | GPT-4o-mini |
| --- | --- | --- | --- |
| 首 token 延迟 | 0.3s | 0.5s | 0.8s |
| 生成速度 | 30 tok/s | 60 tok/s | 80 tok/s |
| 中文质量 | 良好 | 优秀 | 优秀 |
| 推理能力 | 一般 | 强 | 中 |
| 成本 | 电费 | ¥0.5/M | ¥1.1/M |

**本地 7B 的优势：**

- **首 token 快**（不用网络往返）
- **免费**（除了电费）
- **隐私**

**劣势：**

- **质量差一档**
- **推理弱**
- **受限硬件**（长上下文慢）

### 2. 什么时候用本地

**清晰的判断标准：**

**✅ 适合本地：**

- **简单任务**：分类、格式化、抽取
- **高频调用**：每秒几十次
- **隐私数据**：不能出内网
- **离线环境**
- **开发调试**：不花钱随便测

**❌ 不适合本地：**

- **复杂推理**：数学、代码、逻辑
- **长文本**：100K 上下文
- **多模态**：图片、音频
- **极致质量**：客服、内容创作

### 3. 本地模型优化

**跑本地模型，几个技巧：**

**1. 量化版本更省资源**

```text
# 完整版
ollama pull qwen2.5:7b

# 4-bit 量化版（体积小一半，质量略降）
ollama pull qwen2.5:7b-instruct-q4_K_M

```

**效果对比：**

| 版本 | 大小 | 显存 | 质量 |
| --- | --- | --- | --- |
| 原始 | 15GB | 16GB | 100% |
| Q4_K_M | 4.4GB | 8GB | 98% |
| Q4_0 | 4.0GB | 6GB | 95% |

**Q4 量化是最佳平衡点。**

**2. GPU 加速**

**Ollama 自动用 GPU**——但可以调参数：

```text
# 设置 GPU 层数（大模型显存不够时部分用 CPU）
OLLAMA_NUM_GPU=35 ollama run qwen2.5:14b

```

**`nvidia-smi` 可以看 GPU 使用率。**

**3. 保持模型常驻**

**默认 Ollama 5 分钟不活动就卸载模型。频繁调用会反复加载：**

```text
# 保持常驻（单位秒）
OLLAMA_KEEP_ALIVE=-1 ollama serve

# 或单个命令设置
OLLAMA_KEEP_ALIVE=1h ollama run qwen2.5:7b

```

**加载一个 7B 模型约 5 秒**——频繁加载影响体验。

**4. 并发控制**

**Ollama 默认同时只处理 1 个请求。并发高了会排队：**

```text
# 支持 4 个并发
OLLAMA_NUM_PARALLEL=4 ollama serve

```

**但注意：显存要够，否则会 OOM。**

**5. 上下文长度**

**默认上下文是 2048 token。有需要就调大：**

```text
# 调到 8192
ollama run qwen2.5:7b --parameter num_ctx 8192

```

**但更大的上下文需要更多显存。**

## 七、私有化部署方案

**本地模型在企业场景叫"私有化部署"——一套更完整的方案。**

### 1. 架构设计

**企业私有化架构：**

```text
┌─────────────────────────────────────┐
│          用户（内网）                │
└────────────┬────────────────────────┘
             ↓
┌─────────────────────────────────────┐
│         Nginx（内网）                │
└────────────┬────────────────────────┘
             ↓
┌─────────────────────────────────────┐
│       FastAPI 服务                   │
│       (Day 21-30 的代码)             │
└────────────┬────────────────────────┘
             ↓
┌─────────────────────────────────────┐
│         Ollama（GPU 服务器）         │
│         qwen2.5:32b / 70b           │
└─────────────────────────────────────┘

```

**完全离线的运行环境。**

### 2. Docker 化部署

**Dockerfile（Ollama）：**

**`day40/docker-compose.ollama.yml`：**

```text
services:
  ollama:
    image: ollama/ollama:latest
    container_name: ollama
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama
    environment:
      - OLLAMA_KEEP_ALIVE=1h
      - OLLAMA_NUM_PARALLEL=4
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
    restart: unless-stopped

volumes:
  ollama_data:

```

**启动：**

```text
docker compose -f docker-compose.ollama.yml up -d

# 拉模型
docker exec ollama ollama pull qwen2.5:7b

# 测试
curl http://localhost:11434/api/generate -d '{
  "model": "qwen2.5:7b",
  "prompt": "你好"
}'

```

**需要 NVIDIA GPU + 装好 `nvidia-container-toolkit`。**

### 3. 挂到我们的 API

**`docker-compose.prod.yml` 加上 Ollama：**

```text
services:
  api:
    # ... 原有配置
    environment:
      - OLLAMA_BASE_URL=http://ollama:11434/v1
      - LLM_PROVIDER=hybrid
      - LOCAL_MODEL=qwen2.5:7b

  ollama:
    image: ollama/ollama:latest
    volumes:
      - ollama_data:/root/.ollama
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
    restart: unless-stopped

volumes:
  ollama_data:

```

**FastAPI 通过服务名 `ollama` 访问——** 和访问数据库一样。

### 4. 模型预加载

**容器启动后要自动拉模型：**

**创建 `scripts/init-ollama.sh`：**

```text
#!/bin/bash
set -e

OLLAMA_HOST=${OLLAMA_HOST:-http://localhost:11434}
MODEL=${1:-qwen2.5:7b}

echo "等待 Ollama 就绪..."
until curl -s $OLLAMA_HOST > /dev/null 2>&1; do
    sleep 2
done

echo "拉取模型: $MODEL"
curl -X POST $OLLAMA_HOST/api/pull \
    -d "{\"name\": \"$MODEL\"}"

echo "完成"

```

**在 `docker-compose` 里加个初始化容器：**

```text
  ollama-init:
    image: curlimages/curl:latest
    depends_on:
      - ollama
    volumes:
      - ./scripts/init-ollama.sh:/init.sh
    entrypoint: ["sh", "/init.sh"]
    environment:
      - OLLAMA_HOST=http://ollama:11434
    restart: "no"

```

**部署时自动拉模型，省去手动步骤。**

## 八、前端视角：本地模型 vs 前端"离线应用"

**做过前端的你，一定理解"本地"的价值：**

| 场景 | 云端方案 | 本地方案 |
| --- | --- | --- |
| 数据存储 | 云数据库 | IndexedDB / SQLite |
| 计算 | 云函数 | WebAssembly / Service Worker |
| AI | 云端 API | 本地模型 |
| 支付 | 第三方支付 | 微信小程序本地支付 |

**为什么前端也有 PWA、Service Worker、Local-first？**

**因为"本地"有独特价值：**

- **隐私**：数据不出设备
- **速度**：无网络往返
- **离线**：断网也能用
- **免费**：用户设备承担计算

**本地模型就是"AI 版的 PWA"**——把"云端能力"搬到本地。

**前端做过的：**

- **Local-first 应用**（如 Obsidian）
- **PWA 离线缓存**
- **WebAssembly 本地计算**
- **IndexedDB 本地存储**

**这些思路，就是本地模型的思路。**

**“离云端远一点，离用户近一点”**——这是技术演进的一个方向。

## 九、今日踩坑

1. **显存不够硬跑大模型** → 系统卡死或 OOM，先看 `ollama ps` 的显存占用
2. **`ollama run` 后直接退出** → 模型被卸载，下次要重新加载
3. **下载模型断网** → 下载失败要重新下，可以设置代理
4. **Ollama 服务没启动** → 访问 11434 报 connection refused，检查 `ollama serve`
5. **Ollama 端口被占用** → 改端口：`OLLAMA_HOST=0.0.0.0:11435 ollama serve`
6. **用 `localhost` 但服务在容器里** → 容器里要用服务名
7. **量化版本号写错** → 不同量化质量差异大，看清 `q4_K_M` / `q4_0` / `q8_0`
8. **上下文太长 OOM** → 调小 `num_ctx` 或减少 prompt
9. **并发太多没设 `OLLAMA_NUM_PARALLEL`** → 后续请求一直排队
10. **Ollama 模型文件占满磁盘** → 大模型一个 15GB，磁盘要够
11. **忘了设 `OLLAMA_KEEP_ALIVE`** → 每次调用重新加载 5 秒
12. **国内下载慢** → 从 HuggingFace 或 ModelScope 手动下载 `gguf` 文件导入
13. **NVIDIA 驱动版本太老** → Ollama 用不了 GPU，只能 CPU 慢跑
14. **本地模型走 OpenAI 格式但部分参数失效** → 有些参数（如 `response_format`）Ollama 支持不全
15. **不同模型 prompt 格式不同** → 有的要 `<|im_start|>`，Ollama 会自动处理
