先说结论：大的 Agent，普通程序员别想了。

就拿Andrej karpathy的AI使用历程来看，2024年的时候的这个nanoGPT，当时风靡一时，所有的contributor全是真人。

**![](https://pic3.zhimg.com/v2-ce38f50436a590dbec0c32d24434e7a0_r.jpg)**

去年的nanochat，就已经出现Claude Code了。

**![](https://pic4.zhimg.com/v2-b2a5dde6a8b38f2fba50acf338bc7a5b_r.jpg)**

今年他几乎所有的项目，Claude Code基本上都在第二第三位。

**![](https://pic3.zhimg.com/v2-9b6f5fc1aa6b8bc24c2573eabd476f94_r.jpg)**

**可以说现在一线的大佬基本上都在用Claude Code这类型的Agent，ALL in了可以说是。**

所以不是你不够聪明，是这条赛道已经不是「周末开个 repo」能打的了。

OpenAI 在做 Codex，Anthropic 在做 Claude Code，GitHub 在做 Copilot coding agent，Cline 拿了 3200 万美元融资，Lovable 估值已经到 66 亿美元。

不知道你发现区别没有？

像 OpenAI 和 Anthropic，他们的长处在于做大模型专精，可以说是这个领域最难、最硬核的方向。

而 GitHub 其实更多的是接入别人的 AI，作为自己的一个辅助应用。更别说像 Cline 以及 Lovable，他们更多地只是用已有的 AI API 来做些事情。你会发现他们是“墙头草”，什么模型好就用什么，总的来说一直是根据最前沿的大模型来调整自己的应用方向。

但你会发现，他们这种选定一个特定领域，并且搭配最强的模型，反而是这个 AI 时代里面最合适的活法。因为 AI 大模型公司不可能 cover 所有的应用方向。

大厂能做得好，是因为他们在专精大模型这个方向，而应用层他们并不可能所有都 cover 掉。

你一个普通程序员，下班后写两个小时，想做一个通用 Agent 跟这些东西打？

这不是理想主义。

这是没算账。

更现实的做法是反过来：

**不要造另一个** **Codex，用** **Codex。不要造另一个 Claude Code，用 Claude Code。**

这个时代真正的红利，是花一两百刀级别的钱，租用世界上最强的一批 coding agent，然后让它们给你造一个只服务你自己的小系统。

而 Agent 其实最核心的就是大模型。你会发现很多人做 Agent 做不好的原因，就是根本没有了解大模型，以为它是全能的。

实际上，大模型很多时候只是专精于某一方面：

• 比如 DeepSeek 就适合写中文案

• 像 Claude 就适合做长程任务

• 小米的模型则更适合做通用的多模态，而且价格相对来说比较划算

每一个模型都有自己合适的地方。同时，你还得了解像 Workflow（工作流）、RAG、MCP 这些概念。因为有些时候你并不需要复杂的 Agent 架构，反而用最普通的工作流就可以解决。

这个时候，我觉得你是需要系统地了解“大模型开发”大概念的。而掌握这个大概念最好的方式并不是蒙头去学，而是去找一门系统性的课程，带你一步步走完整个流程。我觉得现在有一门非常合适的课程，就是知乎知学堂提供的这门“大模型开发公开课”，它是一门免费的课程。其实重要的并不是说去讲那些特别理论的（比如说什么 Transformer），而是它的一些基础的概念，特别是它提到的一些关于大模型能力不足或者能力限制的地方，这才是你在开发时候最重要的知识点。

特别是这门课结束后的资料，我觉得非常值得仔细看一下。这些资料中涉及到了具体的工作流搭建，你可以通过这部分的学习，将其移植到你自己的工作流中，这样可以做到事半功倍。

![](https://pic4.zhimg.com/v2-118f95b75983413dd8ac60331c9a69a1_r.jpg)

因为流程只是通向结果的一条路，而你修改后的结果，直接体现了什么才算做好。Agent 可以根据任务选择不同的过程，但最后仍然要落到你认可的标准上。

大 Agent 是模型厂和资本的战场。

小 Agent 才是普通程序员的战场。

![](https://pic2.zhimg.com/v2-d72062be41c5db1e892bb1cd7afbc44f_r.jpg)

## 先算四笔账

**第一，价格账。**

Claude 官方 Max 5x 是 100 美元/月，Max 20x 是 200 美元/月。Claude Code 可以接 Pro / Max 订阅，在终端里处理 coding workflow。

OpenAI 的 Codex 已经进入 Free、Plus、Pro、Business、Edu、Enterprise 等计划，用量按套餐和额度走。它本质上就是一个能写、改、review、ship code 的 AI agent。

这意味着：以前你要花几个月攒出来的工程生产力，现在变成了一个月一两百刀级别的订阅。

这才叫红利。

但红利不是买个会员就自动吃到。

**第二，竞争账。**

OpenAI 2025 年 5 月发布 Codex，能在云端沙箱里读仓库、改文件、跑命令、修 bug、写 feature、提 pull request。

GitHub 的 Copilot coding agent 可以接 issue，在 GitHub Actions 环境里工作，往 draft PR 里推 commit，开发者看 logs 后 review。

2026 年 2 月 arXiv 上有篇 AIDev，统计了 932,791 个 agent 写出来的 PR，来自 OpenAI Codex、Devin、GitHub Copilot、Cursor、Claude Code，横跨 116,211 个 GitHub 仓库。

这说明 coding agent 已经不是 demo。

但也说明通用 coding agent 的核心链路正在被大公司吃掉：模型、IDE、GitHub、云端沙箱、企业权限、审计、合规、分发渠道。

所以普通程序员去做「通用大 Agent」，胜算很低。

**第三，高手账。**

别以为只有新手才用 Codex / Claude Code。

恰好相反，越顶级的工程团队，越早把它们当正式生产力。

OpenAI 官方写过一篇《How OpenAI uses Codex》，里面说 Codex 已经被 OpenAI 的 Security、Product Engineering、Frontend、API、Infrastructure、Performance Engineering 等技术团队日常使用，用来理解复杂系统、重构大代码库、补测试、做性能优化、处理紧急 incident。

更狠的是 OpenAI Forum 里有一场分享：Codex 在 OpenAI 技术员工中的采用率超过 92%，会 review 每一个内部 pull request，使用它的工程师合并 PR 数量大约提升 70%。

Andrej Karpathy 那边也是同一个方向。AP 报道里提到，他当初就是用 Cursor Composer + Claude Sonnet 做周末项目时，提出了「vibe coding」这个说法。Scientific American 也提到，Karpathy 到 2026 年已经把这称作软件工程的一次 phase shift。

所以别再觉得「用 Agent 写代码」是偷懒。

顶级程序员都在用。

区别只是：他们不是让 AI 乱写，而是知道怎么给边界、怎么验结果、怎么把它接进自己的工作流。

**第四，价值账。**

你真正缺的不是又一个通用 Agent。

你缺的是一个知道你代码库、你日志、你笔记、你家庭琐事、你长期偏好的小系统。

OpenAI 不知道你项目里哪个服务最容易半夜报警。

Anthropic 不知道你导师几点喜欢发邮件。

GitHub 不知道你妈更关心温度还是降雨。

但你自己的小 Agent 可以知道。

这就是私有 context 的价值。

## 该怎么做

一句话：

**不要造大脑，造手脚。**

大脑已经有人替你训练好了。GPT、Claude、Gemini、DeepSeek、Qwen 都在卷。

你要做的是让这个大脑接上你的手脚：读文件、查日志、搜笔记、记偏好、定时触发、危险动作先问你。

第一版只需要四个零件。

1. **私有 context** 
 代码仓库、日志、日报、论文笔记、错题、收藏链接、家庭日程、客户沟通记录。 
 没有私有 context，Agent 就只是换皮 ChatGPT。
2. **小工具** 
 比如： 
 search_logs(keyword, time_range) 
 read_note(date) 
 list_recent_commits() 
 send_draft_message() 
 工具越小越好控。 
 do_everything() 这种工具，名字就已经说明它会变成灾难。
3. **固定触发器** 
 cron、CLI、GitHub issue、飞书消息、钉钉机器人都行。 
 个人 Agent 最好从 cron 开始：每天早上跑一次、每天晚上跑一次、每周日跑一次。 
 比你随时召唤一个「万能助手」稳定得多。
4. **验证 / 审批机制**

代码类 Agent：跑测试、看 diff、开草稿 PR，不要直接合并。

研究类 Agent：附来源链接，不要只给结论。

内容类 Agent：保留原始素材，不要直接代写发布。

生活类 Agent：涉及花钱、隐私、发消息，第一版都要人工确认。

第一版甚至可以很丑：

一张 SQLite 表：memories(id, source, text, tags, created_at, due_at)

几个 Python 函数：search_files、read_logs、send_message

一个 cron：每天把最近 context 拼给模型

一个 JSON 输出约束

一个 pending 队列：写文件、发消息、花钱前先审批

这就已经是 Agent。

![](https://pic2.zhimg.com/v2-e33f76778e120e2a031f3a476a0bcdf1_r.jpg)

别嫌小。

能每天跑的小系统，比你脑子里那个永远没开工的 SuperAgent 强一万倍。

## 四个最适合做的方向

1. **日志排查 Agent** 
 后端、运维、测试最适合。给它工具：查日志、查错误码、查历史事故、查发布记录。用户丢一段报错，它先判断要查什么，再调用工具，最后给排查路径。 
 这个比聊天机器人有价值得多，因为它真的接进了业务系统。
2. **代码维护 Agent** 
 别上来就做「自动写完整项目」。先做低中复杂度任务：读 issue、定位相关文件、给修改建议、生成 patch、跑测试、开草稿 PR。 
 Git、diff、test 天然就是验证机制。
3. **研究 / 信息流 Agent** 
 每天从 arXiv、GitHub Trending、技术博客、知乎、X 里抓东西，写进 memories 表。 
 早上给你一份「今天值得看的 10 件事」，每条带原始链接和一句理由。 
 注意，第一版只做筛选、聚类、摘要、留引用，不要直接替你写文章。
4. **家庭 / 个人管家 Agent**

天气、日程、快递、账单、学校通知、老人用药提醒。

这类需求看起来不硬核，但很适合个人 Agent，因为它的价值正来自私有 context。

## 最后

知乎高赞回答里反复骂「调包侠」，本质上是在骂一件事：

很多人不是在学习 Agent，是在用 Agent 这个词包装焦虑。

今天收藏 LangChain，明天收藏 MCP，后天收藏多 Agent，最后什么都没做。

如果你连 Agent、Workflow、RAG、MCP、Tool Use 这些边界还没分清，可以先用一两个小时校准一下方向。知乎知学堂有节 0 元《大模型应用开发》公开课，我看过大纲，day1 讲大模型应用、知乎直答原理和 DeepSeek 核心技术，day2 讲知识体系、典型业务场景和岗位分析。

它不是替你写代码的课，但适合用来防止一开始就学歪。

真正要动手，今晚就够了：

![](https://pic3.zhimg.com/v2-0ef089b16d7afc6d9792bbc140e7db9a_r.jpg)

今晚就能开始的最小个人 Agent 路线

打开 Codex 或 Claude Code。

让它帮你新建一个 repo。

建一张 memories 表。

接一个 cron。

写一个最小工具函数。

让它明天早上给你发第一封只属于你的简报。

不用发朋友圈，不用开源，不用证明给别人看。

自己用。

先自己用。

一直自己用。

**普通程序员在 Agent 时代最现实的王道，不是造一个人人看得见的大东西，而是养一个只有你自己离不开的小东西。**
