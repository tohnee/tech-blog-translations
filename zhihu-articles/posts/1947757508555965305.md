最近入坑了端侧大模型推理，在实践过程中发现，要想让模型在端侧高效运行，不仅要理清推理流程，更要精准定位各环节瓶颈并找到适配的优化方案。

本文将以 InternVL3 为例，从架构解析到推理细节，完整拆解 VLM 推理全流程，并调研了一些优化技术，为每个环节匹配实用的方案，助力大家在端侧部署 VLM 时少走弯路。

## 一、InternVL3 架构概览

在拆解推理流程前，我们先明确 InternVL3 的整体架构。作为视觉 - 语言多模态模型，它的核心是通过 “视觉编码器 - 连接层 - 语言模型” 的三层结构，实现图像与文本的跨模态融合。

### 1.1 顶层结构：InternVLChatModel 的三大模块

InternVLChatModel 是模型的入口类，整合了三个关键子模块：

- **视觉编码器（InternVisionModel）**：基于 Vision Transformer（ViT）架构，负责将原始图像转换为结构化的视觉特征向量，是模型 “看懂” 图像的核心。<br>
- **语言模型（Qwen2ForCausalLM）**：处理文本输入与生成，支持对话历史拼接、自回归生成，是模型 “理解” 与 “表达” 的基础。<br>
- **连接层（mlp1）**：本质是多层感知机（MLP），作用是将视觉编码器输出的特征向量，投影到与语言模型相同的维度空间，解决跨模态特征 “维度不兼容” 的问题。

从输入到输出，InternVL3 的推理流程可概括为以下步骤：

1. 输入接收：同时获取用户问题（文本）、图像路径（视觉）与可选对话历史；<br>
2. 视觉处理：图像经预处理后，由视觉编码器提取特征，并通过连接层投影到语言维度；<br>
3. 文本处理：文本经对话模板拼接、Tokenizer 编码、Embedding 转换，生成文本特征；<br>
4. 特征融合：将视觉特征替换文本中预留的图像 Token 位置，形成跨模态融合特征；<br>
5. 生成输出：融合特征输入语言模型，经自回归生成、采样与解码，得到最终回答。<br>

## 二、InternVL3 推理全流程

接下来，我们按照 “输入准备→视觉处理→文本处理→特征融合→语言生成” 的顺序，逐环节拆解 InternVL3 的推理细节，同时标注各环节的核心瓶颈与优化方向。

### 2.1 输入准备与对话模板处理：规范输入格式

输入阶段的核心目标是将 “非结构化” 的用户输入（文本 + 图像），转换为 “结构化” 的模型可处理格式，避免因输入不规范导致后续融合失败。

**处理逻辑**：

1. **图像位置标记**：若用户问题中未包含`<image>`标记，但实际传入了图像，模型会自动在问题开头添加`<image>\n`，明确图像与文本的关联位置；<br>
2. **对话历史拼接**：使用预设的对话模板（conv_template），将历史对话（如用户上一轮问题、模型上一轮回答）与当前问题拼接，形成完整上下文。例如：<br>
3. **图像 Token 预留**：将`<image>`标记替换为`<img> + <IMG_CONTEXT>*N + </img>`序列，其中`N`等于视觉特征的 Token 数量（由图像分块数量决定），确保文本中为视觉特征预留足够空间。<br>

**瓶颈与优化技术**

- **瓶颈**：长对话历史会导致 Prompt 长度激增，增加后续 Tokenize 与 Embedding 的计算量；若多个请求共享相同系统提示（如 “你是图像理解助手”），重复处理会浪费资源。<br>
- **优化技术**：<br>

**缓存持久化（前缀共享）**：将共享前缀（如系统提示、重复出现的对话历史）的 KV 缓存持久化存储，多个请求复用，避免重复计算。例如 RAG 场景中，多个请求引用相同文档片段时，可直接复用该片段的 KV 缓存。

相关论文：[Prompt Cache: Modular attention reuse for low-latency inference (MLSys’24)](https://arxiv.org/abs/2402.09640)、[SGLang: Efficient execution of structured language model programs (2024)](https://arxiv.org/abs/2402.15604)

**选择性重建**：若共享前缀存在细微差异（如 “LLM 推理优化” 与 “优化 LLM 推理”），仅重新计算影响大的 Token（如注意力分数高的前 3 个 Token），其余复用，平衡质量与效率。

相关论文：[CacheBlend: Fast large language model serving for RAG with cached knowledge fusion (2024)](https://arxiv.org/abs/2403.19888)

### 2.2 文本 Tokenizer 编码

Tokenizer 是文本进入模型的 “第一道门槛”，负责将自然语言文本分割为模型可处理的基本单元（Token），并映射为整数 ID（Input IDs）。

**核心流程**

1. **输入**：原始文本（如 “描述这张图片的内容”）与模型词汇表（预训练阶段生成，包含 Token 与对应 ID）；<br>
2. **Token 分割**：采用子词分割算法（如 BPE、SentencePiece），将文本拆分为子词序列。例如 “自然语言处理” 拆分为`["自然", "语言", "处理"]`；<br>
3. **ID 映射**：将 Token 序列映射为词汇表中的整数 ID，例如上述序列对应`[678, 910, 123]`；<br>
4. **词汇表来源**：<br>
5. 预训练生成：基于大规模语料统计，如 Llama 3.2 的 128k 词汇表，从万亿级文本中通过 BPE 学习得到；<br>
6. 领域微调：针对医疗、法律等垂直领域，扩展词汇表（如添加专业术语），提升领域适配性。<br>

**瓶颈与优化技术**

- **瓶颈**：长文本 Token 分割耗时；若多个请求包含相同文本片段，重复 Tokenize 会浪费算力。<br>
- **优化技术**：<br>
- **文本片段缓存**：对高频出现的文本片段（如常见问题、系统提示），提前完成 Tokenize 并缓存其 Input IDs，请求到来时直接调用。<br>
- **批量 Tokenize**：将多个短文本请求批量处理，并行加速分割过程，减少单次请求的 Tokenize 时间。<br>

### 2.3 文本 Embedding：将整数 ID 转换为语义向量

文本经 Tokenizer 得到 Input IDs 后，需通过 Embedding 层转换为低维稠密的语义向量，这一步是模型 “理解” 文本语义的基础。

**核心流程**

1. **Embedding 权重结构**：Embedding 层的权重是一个`[vocab_size, hidden_dim]`的二维矩阵，其中`vocab_size`是词汇表大小，`hidden_dim`是语言模型的隐藏层维度（如 Qwen2.5-7B 的 hidden_dim 为 4096）；<br>
2. **向量生成逻辑**：根据 Input IDs 中的每个整数，找到权重矩阵中对应的行，将该行数据作为该 Token 的语义向量。例如 Input ID 为 678 时，取权重矩阵第 678 行作为 “自然” 的语义向量；<br>
3. **核心作用**：将非结构化的文本转换为结构化的数值向量，且语义相似的文本在向量空间中距离更近（如 “猫” 与 “狗” 的向量距离，小于 “猫” 与 “汽车”）。<br>

**瓶颈与优化技术**

- **瓶颈**：Embedding 权重占用内存大（如 128k 词汇表、4096 维的权重，需 128k×4096×2Byte=1024MB，FP16 精度），且访问频率低，长期占用 内存会导致资源浪费。<br>
- **优化技术**：<br>
- **内存分页（动态加载）**：参考 MNN 框架的优化方式，将 Embedding 权重存储在磁盘，推理时根据 Input IDs 计算偏移，仅加载当前所需行的数据，减少内存占用。<br>
- **量化优化**：将 Embedding 权重从 FP16 量化为 INT8 或 INT4，在保证语义相似度损失小于 5% 的前提下，减少内存占用。例如 INT8 量化后，上述 1024MB 权重可降至 512MB。<br>

### 2.4 图像预处理：动态分块保留细节，避免拉伸失真

与普通神经网络 “直接 Resize 到固定尺寸” 的方式不同，InternVL3 采用动态分块预处理，核心目标是在适配模型输入要求的同时，最大程度保留图像细节。

**核心流程（附关键代码解析）**

图像预处理的核心是 “先匹配宽高比，再分块切割”，具体步骤如下：

1. **计算原始图像宽高比**：设原始图像尺寸为`(orig_width, orig_height)`，宽高比`aspect_ratio = orig_width / orig_height`；<br>
2. **筛选最优分块比例**：从候选比例集合（如 1:1、1:2、2:3 等，由`min_num`和`max_num`控制，默认 1\~12 块）中，选择与原始宽高比最接近的比例。例如原始图像为 800×1300（宽高比≈0.615），候选比例 2:3（宽高比≈0.666）为最优。<br>
3. **缩放与分块切割**：<br>

- 计算目标总尺寸：若最优比例为`(2,3)`，单块尺寸为 448×448，则目标总尺寸为`(2×448, 3×448) = (896, 1344)`；<br>
- 图像缩放：使用 BICUBIC 插值（比线性插值保留更多细节），将原始图像缩放到目标总尺寸；<br>
- 分块切割：按 448×448 的单块尺寸，将缩放后的图像切割为`2×3=6`个分块；<br>
- **添加全局缩略图**：将原始图像直接缩放到 448×448，作为 “全局缩略图” 补充到分块列表中，避免分块仅关注局部细节而丢失整体语境；<br>
- **张量堆叠**：将所有分块（如 6 个分块 + 1 个缩略图）的张量堆叠为`[7, 3, 448, 448]`（批量维度 = 7，通道数 = 3，高 = 448，宽 = 448），作为视觉编码器的输入。<br>

**缺点：** 动态分块会增加输入批量（如 7 个分块 vs 1 个 Resize 图像），导致视觉编码器的计算量上升。

### 2.5 视觉模型前向推理

视觉编码器（InternVisionModel）基于 ViT 架构，负责将预处理后的图像分块，转换为与语言模型兼容的特征向量，核心包含 “嵌入层” 与 “编码器层” 两部分。

**2.5.1 嵌入层：添加位置信息，将像素转换为初始特征**

嵌入层的作用是将图像分块的像素值，转换为包含位置信息的初始特征向量，具体流程如下：

1. **Patch Embedding（卷积分块）**：通过卷积层将 448×448 的分块，分割为更小的 Patch 并转换为向量。例如 Patch 尺寸为 14×14，卷积核大小与步长均为 14，输出维度为`[batch_size, vit_hidden_size, 32, 32]`（32=448/14，vit_hidden_size=768）；<br>
2. **展平与转置**：将卷积输出的空间维度展平，转换为序列格式：`[batch_size, vit_hidden_size, 32×32]` → `[batch_size, 1024, 768]`（1024=32×32，即 Patch 数量）；<br>
3. **Class Token 添加**：新增一个可学习的 Class Token（形状`[1, 1, 768]`），用于聚合全局特征，拼接后序列长度变为 1025（1024 个 Patch Token + 1 个 Class Token）；<br>
4. **位置嵌入（Position Embedding）**：为每个 Token 添加位置信息，确保模型理解 Patch 的空间顺序。<br>

**推理加速技巧**：若推理时所有图像分块尺寸固定，可离线提前完成位置嵌入的插值调整，推理时直接加载预处理后的位置嵌入，避免运行时计算开销。

**2.5.3 解码器层**

由多层 Transformer 编码器堆叠而成，每层包含 “多头自注意力” 与 “多层感知机（MLP”）。这部分结构与语言部分的解码器层类似

1. **多头自注意力（InternAttention）**：将输入特征拆分为多个注意力头，并行计算 Patch 间的关联权重，捕捉局部与全局特征。<br>
2. **MLP 层（InternMLP）**：通过两次线性变换与 GELU 激活函数，对注意力输出进行非线性变换，增强特征表达能力。输<br>
3. **残差连接与层归一化**：每层注意力与 MLP 输出后，均通过残差连接与层归一化。<br>
4. **优化技术**：<br>

该部分一般是最耗时，开销最大的部分，有诸多工作优化MHA和FFN。举例几个：

- FlashAttention：设计专用Attention计算kernel。把 Q、K、V 拆成小 Block（如 256×256），在 GPU 计算单元内 “边加载 Block、边计算、边丢弃临时数据”，同时把 “QK^T→Softmax→V 加权” 融合成一个算子，避免中间结果的内存读写。<br>
- 注意力机制变种：多查询 / 分组查询注意力（MQA/GQA）：“共享 K/V，减少缓存量”——MQA 让所有头共享一套 K/V，GQA 把多个头分成一组，每组共享一套 K/V，在 “内存占用” 和 “性能” 间找平衡。<br>
- 稀疏注意力：传统注意力要计算 每个 token 与所有 token 的相似度。稀疏注意力只计算‘有用’的注意力对，跳过冗余对。把注意力矩阵从 “全连接” 变成 “稀疏连接”，减少计算量（Sparse Transforme、Longformer等）。<br>
- MOE：传统 FFN 是 “dense 结构”—— 每个 token 都要经过所有 FFN 参数，参数多、计算量大。MOE动态激活部分专家，减少计算—— 把 FFN 拆成多个 “专家”（小 FFN），配一个 “路由模块”，每个 token 经路由模块分配给 1-2 个专家，只计算这几个专家，减少参数使用量。<br>

### 2.6 Pixel Shuffle：降低空间分辨率，提升通道维度

视觉编码器输出的特征序列（如`[1, 1025, 1024]`）需经过 Pixel Shuffle 操作，调整空间与通道维度，为后续 MLP 投影做准备。

Pixel Shuffle 的核心是 “降低空间分辨率，同时增加通道数”，通过两次重塑与转置实现，具体步骤如下（以`scale_factor=0.5`为例）：

1. **第一步处理**：输入特征`[n, w, h, c]`（n = 批量大小，w=1024，h=1，c=1024）→ 重塑为`[n, w, h×0.5, c/0.5]` → 转置为`[n, h×0.5, w, c/0.5]`；<br>
2. **第二步处理**：继续重塑为`[n, h×0.5, w×0.5, c/(0.5×0.5)]` → 转置为`[n, w×0.5, h×0.5, c/(0.5×0.5)]`；<br>
3. **维度变化示例**：输入`[1, 1024, 1, 1024]`（移除 Class Token 后）→ 输出`[1, 256, 1, 4096]`，其中空间分辨率从 1024 降至 256（1/4），通道数从 1024 升至 4096（4 倍）。<br>

其可以减少后续 MLP 投影的序列长度（256 vs 1024），降低计算量；

### 2.7 Multimodal Projector（MLP 投影层）：视觉与语言特征的维度对齐

视觉特征经过 Pixel Shuffle 后，维度为 4096，而语言模型的隐藏层维度为 896（如 Qwen2.5-0.5B），需通过 MLP 投影层将视觉特征映射到语言模型的特征空间，实现跨模态维度对齐。

### 2.8 文本与视觉特征融合：替换预留 Token，实现跨模态统一

特征融合是 VLM 推理的核心环节，需将对齐后的视觉特征，替换文本中预留的`<IMG_CONTEXT>`Token 位置，形成包含图像与文本信息的融合特征。

**融合流程**

1. **定位预留 Token 位置**：通过`input_ids == self.img_context_token_id`找到文本中`<IMG_CONTEXT>`对应的位置，生成掩码`selected`（形状`[batch_size×seq_len]`）；<br>
2. **特征替换**：将视觉特征`vit_embeds`直接替换`input_embeds[selected]`的位置；<br>
3. **异常处理**：若`<IMG_CONTEXT>`数量与视觉 Token 数量不匹配（如文本预留 200 个位置，视觉仅输出 256 个 Token），取较小值进行部分替换，确保模型正常运行：<br>

### 2.9 语言模型前向推理：自回归生成回答

融合特征输入语言模型（如 Qwen2.5-0.5B）后，模型通过自回归方式逐 Token 生成回答，核心包含 “解码器层推理”“采样”“终止判断” 三个环节。

**解码器层推理：捕捉上下文关联**

语言模型的解码器层与 ViT 编码器层结构类似。区别是这里要进行KV Cache：

**KV 缓存复用**：生成过程中，缓存已处理 Token 的 Key 与 Value 向量（KV 缓存），后续生成新 Token 时仅计算新 Token 的注意力，避免重复计算。

**优化技术：**

- 分块存储：静态内存分配（为每个请求预分配最大可能的 KV 缓存空间，比如按 2048 token 预分配）会导致内存浪费。把 KV 缓存按 “小块”（比如 64 个 token 为一个块）动态分配，请求需要多少就分配多少块，用 “页表” 记录块的位置。例如vLLM<br>
- 缓存卸载： 把暂时用不到的 KV 缓存转移到 CPU 内存或硬盘，需要时再读回 GPU，就像电脑内存不够时把不常用的文件移到外接硬盘，要用再插硬盘读取。<br>
- 量化：将kv cache存储时量化到低bit，使用时再反量化。<br>

**采样：控制生成多样性与质量**

采样是从模型输出的 Logits（预测概率）中选择下一个 Token 的过程，常用策略如下：

| 采样策略 | 原理 | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- | --- |
| 贪心采样（Greedy） | 每次选择概率最高的 Token | 速度快，生成稳定 | 易重复、逻辑断档（如 “今天天气好，今天天气好”） | 快速生成短文本（如标题） |
| 束搜索（Beam Search） | 保留概率最高的 k 个候选序列，逐步扩展 | 生成质量高，逻辑连贯 | 速度慢，多样性低 | 高质量文本生成（如摘要） |
| 温度采样（Temperature） | 调整 Logits 的 Softmax 温度（如 T=0.7），温度越高多样性越强 | 平衡质量与多样性 | 温度过高易生成无意义文本 | 对话、创意写作 |

**终止判断**

当生成`<eos>`（结束符）或达到预设的最大长度（如 512）时，停止生成，避免无限制输出。

**瓶颈与优化技术**

- **瓶颈**：自回归生成逐 Token 处理，生成 100 个 Token 需运行 100 次语言模型，速度慢；KV 缓存随生成长度增长，内存占用逐渐增加。<br>
- **优化技术**：<br>
- **投机解码（Speculative Decoding）**：先用小模型（如 Qwen2.5-0.5B）快速生成 5 个候选 Token，再用大模型一次性验证，正确则保留，错误则修正，减少大模型运行次数。例如生成 100 个 Token，大模型仅需运行 20 次（100/5），速度提升 3-5 倍。<br>
