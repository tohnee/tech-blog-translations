把一个智能体写成一个巨大的 Prompt一般不会得到稳定结果。真正能长期运行的系统通常需要一组可复用的架构模式，用来拆分任务、调用工具、维护上下文、检查输出质量、处理失败，并在必要让人工来做决定。

本文将介绍 21 种基础的智能体设计模式。它们覆盖规划、工具调用、记忆、恢复、协作与评估等常见问题，并可归入五个实用类别。

1. **提示链（Pipeline）**

![](https://pic2.zhimg.com/v2-bcc0076451d7056809bf4026d4c31df5_1440w.jpg)

复杂任务不需要塞进一个 Prompt。提示链把工作拆成连续的小步骤，每一步留下稳定的中间产物，再交给下一步处理。

1. 定义最终目标（“完成”的判定标准）。
2. 拆分为 2–6 个子步骤，并明确每一步的中间输出。
3. 在每一步强制使用固定结构（项目符号/JSON/表格）。
4. 按顺序执行各步骤，并记录中间输出。
5. 在需要的位置加入验证关卡（schema 检查、必填字段检查）。

### 优点

- 便于调试（可以逐步检查）
- 比一个巨型 Prompt 更可靠
- 适合逐步约束输出结构<br>**缺点**
- 延迟和成本更高
- 前面的错误可能向下游传播<br>**适用场景**
- 多步骤转换：总结 → 提取 → 计算 → 格式化。

### 2) 路由

![](https://pic2.zhimg.com/v2-c998ce6ebcf5009583f4dec6d78f46d5_r.jpg)

当系统里存在多条工作流、多个工具或多个智能体时，需要先决定请求应该交给谁处理。路由就是这一层决策机制，判断依据可以是意图、复杂度或风险。

1. 提取信号（意图、领域、紧急程度、置信度）。
2. 使用规则、分类器或混合逻辑选择路由。
3. 执行选中的工作流。
4. 不确定时采用后备方案（澄清、安全默认方案或升级处理）。

### 优点

- 无需依赖一个巨型 Prompt，也能扩展到多种任务
- 支持专业化，每条路由都可以单独调优<br>**缺点**
- 错误路由会降低质量
- 需要 eval 和标签来调节阈值<br>**适用场景**
- 存在多个工具/智能体，需要自动选择时。

### 3) 并行化

![](https://picx.zhimg.com/v2-630163c706b0444b5744df4e73725b3b_r.jpg)

互不依赖的子任务没有必要串行等待。并行化让这些任务并发执行，最后再把结果汇总。

1. 识别没有依赖关系的独立子任务。
2. 并发运行（异步任务、线程、worker）。
3. 在汇合步骤中合并结果（去重、排序、投票、总结）。

### 优点

- 降低端到端延迟
- 适合多来源检查和批量处理<br>**缺点**
- 追踪和调试更困难
- 合并冲突需要谨慎处理<br>**适用场景**
- “获取 N 个结果，再进行合并”的任务。

### 4) 反思（Generate → Critique → Refine）

![](https://pic3.zhimg.com/v2-61cb0f8f8e9b05b4b13666f604f1ca1e_r.jpg)

第一版输出并不一定直接交付。反思模式让系统经历“生成—批评—修订”的循环，直到结果达到预设质量标准。

1. 生成第一版草稿。
2. 执行一次批评检查（缺失的要求、逻辑漏洞、格式规则）。
3. 根据明确的问题进行修订。
4. 达到 N 次循环，或评分通过后停止。

### 优点

- 质量更高，错误更少
- 适合写作、推理、代码和结构化输出<br>**缺点**
- 延迟和 Token 消耗更高
- 需要停止规则，避免无限循环<br>**适用场景**
- 要求严格，或对写作/代码输出质量要求较高时。

### 5) 工具使用（Function Calling）

![](https://pic2.zhimg.com/v2-2b33daa1aeb820ec6e1aa92e9914a941_r.jpg)

仅靠模型记忆无法覆盖真实数据和外部操作。工具使用让智能体调用 API、DB、计算器或文件操作，拿到准确结果后再继续决策。

1. 定义工具 schema 和权限（allowlist）。
2. LLM 选择工具 + 结构化参数。
3. 工具运行并返回结果。
4. LLM 根据结果回答，或决定下一步。

### 优点

- 可以进行准确计算并访问真实数据
- 把能力扩展到模型记忆之外<br>**缺点**
- 没有严格权限控制时存在安全风险
- 必须处理工具故障<br>**适用场景**
- 任何需要外部真实信息（DB、文件、当前信息）或精确计算的任务。

### 6) 规划

![](https://pica.zhimg.com/v2-114aee7481494c6b4fa3e8b6d275945e_r.jpg)

面对带依赖关系的复杂目标，可以先明确子目标和执行顺序，再逐步推进。规划模式把这套过程显式化。

1. 把请求转化为明确目标和约束。
2. 生成计划：步骤、依赖关系、所需工具。
3. 执行各步骤，并在每一步后检查进度。
4. 出现新信息或失败时修改计划。

### 优点

- 处理复杂目标时更可靠
- 进度可追踪、可审计<br>**缺点**
- 计划可能错误或过于模糊
- 需要更多编排和状态跟踪<br>**适用场景**
- 具有依赖关系的多步骤问题。

### 7) 多智能体协作

![](https://pic2.zhimg.com/v2-b56934a7214e081f0f3c1e1326e101a1_r.jpg)

一个智能体不必承担所有角色。多智能体协作把研究、构建、验证等工作交给不同的专业智能体，再由协调器合并结果。

1. 协调器拆解任务。
2. 把子任务分配给专业智能体。
3. 专业智能体产出工作成果（笔记、代码、批评意见）。
4. 协调器合并结果并解决冲突；必要时继续迭代。

### 优点

- 专业化分工可以改善质量
- 通过审查/验证智能体提高稳健性<br>**缺点**
- 存在协调开销（协议、合并）
- 管理不当时成本和延迟更高<br>**适用场景**
- 任务横跨多种技能/领域时。

### 8) 记忆管理

![](https://pic4.zhimg.com/v2-206ab7a1fcd7f8980d6aac2d588327cf_r.jpg)

跨会话或长任务的一致性依赖记忆管理。系统需要决定哪些信息值得保存、怎样标记，以及当前请求真正需要取回哪些内容。

1. 决定要存储什么（偏好、事实、决策、摘要）。
2. 连同元数据一起存储（时间戳、标签、来源）。
3. 只检索与当前查询相关的内容。
4. 把内容注入上下文，并设置边界（保持简短、清晰分隔）。

### 优点

- 保持连续性并支持个性化
- 减少反复询问用户<br>**缺点**
- 存在隐私/安全问题
- 检索噪声可能让模型混淆<br>**适用场景**
- 助手、项目 copilot、多日工作流。

### 9) 学习与适应

![](https://pic2.zhimg.com/v2-1e57e957e3d0b8f8175ac135443c9f43_r.jpg)

高频使用的智能体会不断积累评分、编辑和成功/失败记录。学习与适应模式把这些反馈转成 Prompt、路由、检索策略或 Fine-tuning 的改动，并在部署前验证。

1. 捕获反馈信号（评分、编辑、成功/失败）。
2. 分析失败情况和常见用户偏好。
3. 更新 Prompt/路由/检索策略（或进行 Fine-tuning）。
4. 部署前通过评估验证改动。

### 优点

- 会随着使用持续改善
- 减少重复出现的错误<br>**缺点**
- 存在漂移或从错误反馈中学习的风险
- 需要治理和 eval 纪律<br>**适用场景**
- 使用量较高、改进收益会持续累积的智能体。

### 10) 模型上下文协议（MCP）

![](https://picx.zhimg.com/v2-ea35c9e8c4605d34a2ac8ae34cc29939_r.jpg)

工具和资源较多时，可以采用标准化连接层统一暴露这些能力。MCP Client 负责发现并调用 MCP Server 提供的工具和资源。

1. 工具/资源托管在 MCP Server 后面。
2. 智能体使用 MCP Client 发现并调用能力。
3. 认证和策略可以集中到 Server 层。

### 优点

- 集成更简洁，减少自定义胶水代码
- 大量工具之间更容易维护<br>**缺点**
- 增加一层基础设施
- 仍然需要严格的访问控制/审计日志<br>**适用场景**
- 工具/资源很多，希望采用标准集成模式时。

### 11) 目标设定与监控

![](https://pic3.zhimg.com/v2-d44651a55569e9e34ef4680a2c64caa2_r.jpg)

自主执行不能只盯着最终目标，还要持续检查进度。目标设定与监控把成功标准显式写出来，并在执行过程中跟踪状态、预算和风险。

1. 定义成功标准（尽量可衡量）。
2. 每一步之后跟踪进度信号。
3. 偏离轨道时调整计划或升级处理。
4. 达到成功标准后停止。

### 优点

- 自主运行更可靠
- 可以更早发现失败<br>**缺点**
- 主观任务很难定义指标
- 监控会增加开销<br>**适用场景**
- 长时间运行的工作流、自主智能体、多步骤计划。

### 12) 异常处理与恢复

![](https://pic1.zhimg.com/v2-ecaa42376a817f4326492921a3ee7ca2_r.jpg)

真实环境里的工具调用一定会失败。异常处理与恢复要求系统预先考虑超时、无效 schema、工具故障等情况，并准备重试、切换路线、回滚或升级处理。

1. 检测错误（超时、无效 schema、工具故障）。
2. 如果是暂时性故障，则进行重试（退避、限制次数）。
3. 切换到替代工具/路由。
4. 必要时修复/回滚状态。
5. 对于高风险或持续性失败，升级处理。

### 优点

- 提高生产环境稳定性
- 避免小型工具故障直接中断工作流<br>**缺点**
- 需要更多工程工作：重试、幂等性、可观测性
- 需要充分测试<br>**适用场景**
- 真实环境中的任何工具型智能体。

### 13) 人工回路（HITL）

![](https://pic1.zhimg.com/v2-16d87f53ba183a3bf22f7bd424d5654a_r.jpg)

敏感操作不适合完全自动执行。HITL 让智能体先提交方案和理由，由人工批准、编辑或拒绝，获批后才真正执行。

1. 智能体起草方案和理由。
2. 人类批准/编辑/拒绝。
3. 只有获批的操作才会执行。
4. 保存反馈，用于改善后续行为。

### 优点

- 高风险操作更安全
- 增强信任和问责<br>**缺点**
- 速度更慢，需要审查 UX
- 依赖人类及时参与<br>**适用场景**
- 法律/医疗/金融、不可逆操作、面向客户的操作。

### 14) 知识检索（RAG）

![](https://pic2.zhimg.com/v2-b94a899916ac8a1fd90b4ff09414431d_1440w.jpg)

模型回答企业文档、政策或合同问题时，外部知识往往比模型记忆更重要。RAG 先检索相关内容，再把这些上下文交给模型生成答案。

1. 构造良好的检索查询（Embedding 或重写）。
2. 从存储中检索 top-k chunks。
3. 可选：进行重排和过滤，提高相关性。
4. 使用检索到的上下文组装 Prompt。
5. 生成有依据的输出；可以选择引用来源。

### 优点

- 回答更符合事实，减少幻觉
- 无需重新训练即可更新知识<br>**缺点**
- 检索质量很难做好（chunking/噪声/缺失数据）
- 会增加延迟 + 索引开销<br>**适用场景**
- 文档 Q&A、企业知识、政策、手册、合同。

### 15) 智能体间通信（A2A）

![](https://pic2.zhimg.com/v2-cd10fdb1e8dca4b56ec7e5d05ea7393f_r.jpg)

多个智能体跨团队或跨框架协作时，A2A 用结构化协议描述能力、任务请求、返回结果和进度更新，支持任务委派与结果回传。

1. 智能体声明自身能力（能做什么）。
2. 调用方向接收方发送结构化任务请求。
3. 接收方返回结果（和/或进度更新）。
4. 调用方合并结果并继续执行。

### 优点

- 支持互操作和模块化生态
- 便于把任务清晰委派给专业服务<br>**缺点**
- 安全/认证是必需项
- 协调错误可能被放大<br>**适用场景**
- 多个智能体/服务跨团队或跨框架协作时。

### 16) 资源感知优化

![](https://picx.zhimg.com/v2-c64eebda2cf53c65e3a7abf7cae8af5f_r.jpg)

资源感知优化会根据复杂度、重要性、风险和 SLA 选择合适的算力等级，在质量、延迟和成本之间做平衡。

1. 估计复杂度/重要性/风险。
2. 选择模型和工作流等级。
3. 减少无效上下文（总结、裁剪、优先排序）。
4. 监控开销/延迟，并调优路由。

### 优点

- 可以在不过度牺牲质量的前提下节省大量成本
- 适合大规模生产环境<br>**缺点**
- 选错等级会降低质量
- 需要监控/eval 来调优<br>**适用场景**
- 请求难度变化较大、模型成本高、SLA 严格时。

### 17) 推理技术

![](https://pic1.zhimg.com/v2-a1af900e0dad566148d6c88fc4277526_r.jpg)

复杂推理任务往往需要先拆解，再借助工具计算或查事实，并对中间结果做约束检查、测试或交叉验证。推理技术把这些步骤组织成可重复的过程。

1. 分解问题，并选择推理策略。
2. 使用工具进行计算/获取事实。
3. 通过约束、测试或交叉检查进行验证。
4. 验证失败时继续迭代。

### 优点

- 处理复杂任务（数学、调试、规划）表现更好
- 验证能够提高可靠性<br>**缺点**
- Token 和延迟更高
- 循环过程需要 guardrails<br>**适用场景**
- 一次性回答经常失败的复杂推理任务。

### 18) 防护栏 / 安全模式

![](https://pic2.zhimg.com/v2-fdcbe7d2fd9b1a4e34e8c3175e8c9847_r.jpg)

生产级智能体需要分层安全控制。输入先做风险检查，工具权限受到限制，输出还要检查策略合规、格式和数据泄漏。

1. 筛查输入中的风险意图和缺失信息。
2. 在 Prompt 和路由中执行策略约束。
3. 限制工具（只读模式、allowlist、sandbox、速率限制）。
4. 验证输出（策略合规、格式、泄漏）。
5. 必要时升级处理/拒绝。

### 优点

- 系统更安全、更可信
- 减少有害结果和数据泄漏<br>**缺点**
- 可能过度拦截，降低可用性
- 需要持续维护<br>**适用场景**
- 任何生产级智能体，尤其是工具型和面向客户的智能体。

### 19) 评估与监控

![](https://pic4.zhimg.com/v2-38be2cffcb33f3bde00f0403a4b05ed7_r.jpg)

评估与监控持续跟踪质量、成本和安全指标，并用生产 traces、eval 数据集和 A/B test 验证改动。

1. 定义指标（准确率、groundedness、延迟、成本、拒绝率）。
2. 构建 eval 数据集（golden answers、对抗案例）。
3. 监控生产 traces 和告警。
4. 全面上线前，对改进方案做 A/B test。

### 优点

- 长期保持系统可靠
- 支持安全迭代和治理<br>**缺点**
- 需要基础设施 + 谨慎的指标设计
- Ground truth 可能很难定义<br>**适用场景**
- 任何生产级智能体；对受监管/高风险领域尤其重要。

### 20) 优先级排序

![](https://picx.zhimg.com/v2-6972a27c6b978691cec7b49279a73ea7_r.jpg)

任务同时涌入时，执行顺序本身就是系统行为的一部分。优先级排序会根据紧急程度、价值、风险和依赖关系给任务打分，并随条件变化重新计算。

1. 把工作转化为明确任务。
2. 使用策略为任务评分（紧急程度、价值、风险、依赖关系）。
3. 执行优先级最高的任务。
4. 条件变化时持续重新评分。

### 优点

- 避免把工作浪费在低价值任务上
- 有助于满足 SLA 和紧急需求<br>**缺点**
- 错误评分可能让重要任务长期得不到处理
- 需要调优和良好信号<br>**适用场景**
- 多用户智能体、长期 backlog、异步任务系统。

### 21) 探索与发现

![](https://pic2.zhimg.com/v2-d3a7a3f27c3f76725c684150e18af249_r.jpg)

有些问题一开始根本不知道正确方向。探索与发现先提出候选假设，再通过搜索、实验或工具调用收集证据，淘汰较弱方案并继续迭代。

1. 生成假设或候选方案。
2. 运行实验/搜索/工具调用，收集证据。
3. 评估结果并淘汰较弱假设。
4. 持续重复，直到达到足够置信度或预算上限。

### 优点

- 适合开放式研究和诊断未知问题
- 可能发现不明显的解决方案<br>**缺点**
- 可能成本很高（多轮迭代）
- 需要停止条件和评估规则<br>**适用场景**
- 调查、调试、创新、探索性分析。<br>**常见模式“配方”（团队实际会交付的组合）**
