当你用起来的时候就知道100万价值在什么地方了！

我想让企业里的 AI，真正进入工作流程。

飞书或企微里收到一条告警，或者同事发来一句“帮我看看这个问题”。以前，往往要先把消息转给我。我再整理背景、复制到 AI 工具，让它执行，最后把结果发回聊天。来回转述、切换工具，离开电脑时，这条链路更容易停下来。

不过，这只是我动手的其中一个原因。真正让我想做一个企业内部工作台的，是四个反复遇到的问题。

## 我为什么做这个工作台：四个真实痛点

**1. 还没开始做事，就先卡在 AI 的接入和配置上。** 公司里不少人不知道怎样安装、配置 Codex、Claude Code、Cursor，或者怎样接入模型。我希望普通员工通过一个统一入口，就能从任务开始。这里想降低的是工具准备和使用门槛，不是说模型调用免费。

**2. 企业的采购、配置和管理太分散。** 开发各自买 Claude、GPT 账号，选模型，再各自配置；报销复杂，也缺少统一的接入流程。企业很难了解 AI 的使用情况和用量。我希望把模型供给、配置和额度管理组织起来，采购报销和真实费用核算也能逐步衔接。

**3. 好经验散在个人环境里，别人很难复用。** 提示、Skills 和操作方法常留在各自的电脑和聊天中。大家用法不同，效果参差不齐，换个人又要从头摸索。我希望把好经验、公用 Skills 和可重复的做法沉淀到平台，让更多同事能够选择和使用，而不只是靠口头传授。

所以，我希望这个工作台能回应这四件事：员工更容易开始，企业更容易统一供给和管理，好方法能持续复用，聊天里的任务能接上执行。Agent Workspace 就是我围绕这些问题做的一次尝试。

工作台首页：从会话、工作流和资源库进入任务，回到最近工作与待处理事项。

## 一、会话：让一件事先推进起来

Session（会话）是日常工作的直接入口。整理方案、分析材料、修改文案，可以先说明目标、附上文件，再围绕回答继续追问。员工从任务开始，管理员提供可用的模型连接和执行组合，需要访问个人账号时再由本人授权。

会话会保留这件事的上下文。输入框旁的加号用于添加材料、选择专家或专家团，并按需选用技能和连接器。专家负责专业方法，技能提供操作步骤，连接器让任务在授权范围内访问外部工具；这些资源可以随具体问题组合使用。

任务详情展示当前状态、执行活动和产物，便于核对 AI 做了什么、得到了什么结果。需要补充条件时，可以在同一会话中继续调整；当某种做法需要反复使用，也可以从会话保存为工作流，再完善目标与入口配置。

## 二、工作流：把目标、资源和触发入口组织起来

Workflow（工作流）适合重复出现、需要持续维护的任务。它保存一个目标和相关配置，并为每次执行留下 Run（运行记录）。同一个工作流可以按使用场景选择手动运行、定时触发、API 调用或消息渠道接入。

工作流拥有持续使用的工作空间，任务所需的文件可以在其中保留。配置好目标和资源后，先检查一次实际执行的结果，再逐步增加触发入口，更容易确认每一步是否符合预期。

### 1. 基本设置：确定任务名称和执行资源

基本信息包括名称、可选专家、目标和指定知识库。名称用于辨认这项工作；专家提供专业步骤与输出约定；知识库提供任务需要参考的资料。没有指定专家时，也可以使用默认助手完成任务。

环境变量用于补充任务需要的配置，普通值与 Secret 分开管理。执行引擎和模型沿用实际执行设置，而不是要求每个员工在每个工作流里重新配置一遍。资源和账号权限准备好后，工作流才具备相应的执行条件。

基本设置整页：名称、可选专家、目标和指定知识库集中配置，下方分别进入环境变量及各类触发入口。

### 2. 设定目标：把要完成的工作写清楚

一个可执行的目标需要说明希望完成什么、输入有哪些、结果以什么形式交付，以及信息不足时怎样处理。目标越明确，后续的定时、API 和聊天输入就越容易沿着同一套要求执行。

例如，分析项目结构时，可以进一步约定输出目录职责、模块关系和待确认问题；整理告警时，可以明确先核对现象，再结合资料与获授权的工具分析，最后给出建议。这些是目标编写思路，具体工具操作仍由已接入的资源决定。

概览页把目标、最近运行状态、运行记录入口和后续接入方式放在一起。每次执行形成独立记录，便于查看输入、结果和执行过程，围绕已有结果继续追问。

目标与运行概览：当前示例的目标为“分析当前项目的结构”，旁边可以查看已有运行记录并进入各项设置。

### 3. 定时触发：让重复任务按节奏执行

对于日报整理、周期检查等重复工作，可以配置每小时、每天或每周触发，并分别设置时刻和时区。任务沿用工作流中保存的目标与资源，每次触发都进入该工作流的运行记录。

例如，可以把每日资料汇总安排在固定时区的上午，把周期检查安排在每周指定时间。配置频率并不代替结果验证，仍需结合任务耗时、资源授权和执行结果确认适用性。

定时触发配置表单：频率、小时、分钟与时区分别设置。

### 4. API 接入：让业务系统提交任务、读取结果

业务系统可以通过 API 把文本或 JSON 输入交给工作流。接入流程包括换取访问令牌、提交任务、获取 Run ID，再按运行状态读取最终结果；需要持续跟踪进度时，也可以订阅运行事件。

工作流按需生成自己的 API Key 与 API Secret，JWT 有效期为 72 小时，接入方可在调用前自动换取。长期凭证保存在业务服务端；重新生成或停用后，旧凭证失效。重复提交可以使用幂等标识，避免业务重试产生重复任务。

这类入口适合把现有系统事件接入 AI 执行，例如由业务系统提交一组待整理的数据，再取回完整结果。凭证只授权当前工作流的调用和结果读取，具体资源访问仍受原有账号授权约束。

API 凭证管理与“如何接入”入口：可查看接入规则并按需生成凭证。

### 5. 消息渠道接入：在聊天里交代任务并接收回复

工作流将保存的目标与聊天消息结合，组织执行并把答案发回原聊天。这样，收到任务、整理背景、转述给 AI、再复制回复的人工链条，就有机会缩短为一个持续的任务入口。

消息渠道与资源库中的连接器承担不同环节：渠道接收任务并返回答案，连接器供执行过程访问工具和业务数据。例如，飞书消息触发工作流后，是否能查询业务资料，仍取决于所选连接器及其账号授权。

消息渠道设置整页：供应商入口、已保存配置与实际连接状态分别展示。

下面保留一条已经真实跑通的最小链路：我在飞书机器人私聊里提交简短任务，工作流接收并执行，29 秒后，机器人回复“收到，消息已由工作台接收”。这次没有调用工具，验证的是接收、执行和回复。

同一次真实收发的结果回看：飞书任务消息 → Workflow 运行成功 → 机器人回执。

进一步用于告警分析时，还要接入对应资料和获授权的业务工具。群消息、机器人告警源与供应商限制需要逐一适配和验证，不能把一条私聊回执扩大为全部告警自动化已经完成。

### 6. Git 配置：为任务准备持续使用的文件空间

这让项目分析、文档整理等任务可以围绕一组固定文件持续工作，而不必在每次对话中重新上传整个项目。工作空间提供目录浏览、支持的文本预览与下载，执行仍受任务权限和隔离边界约束。

Git 凭证属于该工作流，保存后只显示已配置状态，替换时再填写新值。仓库和分支的选择应与任务目标对应；截图中的仓库配置是现有示例，本次没有重新克隆或修改文件。

## 三、资源库：让专业方法、工具和资料能够复用

会话和工作流承接任务，资源库承接执行所需的方法与能力。专家、技能、连接器和知识库分别回答四个问题：按什么专业方法做、采用哪些操作步骤、访问哪些系统，以及依据哪些资料。

### 1. 专家：沉淀专业角色与输出约定

Expert（专家）保存专业工作配置，包括能力介绍、操作步骤、输出标准和注意事项。例如，产品管理专家可以约定需求梳理方式，文案专家可以约定语气、结构与检查标准。使用者选择已有专家，就能复用整理好的方法。

专家可以关联技能和连接器，也可以组织为专家团，由多个成员依次接续工作。平台发布的资源供企业内选择，个人资源保留自己的权限边界；资源可见、配置完整与真实执行结果，需要分别核对。

专家目录整页：专业介绍、来源、可用范围、状态与关联资源数量放在同一张卡片中，按任务选择合适的方法。

### 2. 技能：把操作经验保存为可重复的方法

Skill（技能）把具体做法保存为说明、脚本和配套材料，适合标准流程与反复使用的操作。例如，文档处理、周报生成、前端设计，都可以把步骤、检查项和输出格式沉淀下来，减少每次从头描述的成本。

技能可从 Git 来源或 ZIP 安装包添加，也可作为平台资源提供，再由会话或专家按需选用。目录中的“安装包校验通过”说明资源包已通过检查，具体任务效果仍取决于方法内容、运行环境和输入。

技能目录整页：已有方法、用途说明、来源与安装包校验状态可直接查看，使用者按任务选择。

### 3. 连接器：把执行过程接到工具和业务系统

Connector（连接器）提供对外部系统的操作入口，例如查询文档、读取项目事项、访问设计素材或业务数据。目录按沟通协作、知识文档、项目管理、设计创作等场景组织，便于找到需要的工具。

安装后还需根据供应商完成账号授权或凭证配置，并确认当前能力可用。授权范围决定任务能访问哪些内容、执行哪些操作；需要额外批准的操作仍由拥有者处理。看到目录项或安装状态，不等于所有账户和操作已验证通过。

连接器目录整页：按业务场景组织工具，显示当前安装入口与状态。实际接入条件和权限以各连接器说明及账号授权为准。

### 4. 知识库：让任务依据已有资料作答

知识库用于组织制度、产品说明、项目资料和排障文档。文件进入知识库后需要完成索引，才能在任务中检索；文档管理页可以查看来源、索引状态、更新时间，并进入预览或下载。

工作流可指定一个或多个知识库，智能助手也可以关联资料来源，执行时检索相关内容并保留引用。底层可接入 RAGFlow；这里的用途是提供可追溯的参考资料，不是训练模型。资料权限与索引状态会影响实际可检索的范围。

现有知识库的文档管理页：上传入口、索引状态、来源和更新时间清晰展示。文件名及账号标识已遮挡；本次未上传新文档或执行检索。

以项目检查的配置思路为例，专家约定分析顺序，技能提供检查步骤，连接器按授权查询项目事项，知识库提供架构说明，再由工作流把它们组织到同一个目标下。方法与资料能够复用，个人工作流本身仍遵循现有的个人权限边界。

## 沿着任务，补上应用入口

除了会话、工作流和资源库，工作台也提供智能助手与图片创作。智能助手面向客服和内部问答，配置服务规则、FAQ 与知识库；明确匹配的标准问题可以使用保存的 FAQ 答案，其他被允许的问题再结合检索资料回答，并提供受控分享和网页嵌入入口。

图片创作支持文字描述或参考图创作，按已配置模型选择参数、预览下载，并回看历史结果，为配图、海报等视觉任务提供独立入口。

## 企业统一供给，个人持续工作

底层已统一适配 Claude Code、Codex、PI Agent、Hermes 和 OpenClaw 五种执行引擎。管理员集中管理模型供应商连接、可用模型和经过验证的默认执行组合；员工从任务开始，需要时再选择个人执行配置。不同引擎与模型的能力，以具体组合的验证结果为准。

集中配置也帮助减少各自安装、各自填写密钥和分散使用的负担。平台支持个人与部门 Credits 额度管理，同时保留个人会话的隐私边界；管理员权限不会让管理员直接读取员工的私人对话和结果。

我也想把边界说清楚：当前工作流属于个人；Credits 是产品用量单位，不能等同供应商实际费用；采购报销流程还要结合企业实际完善。检索、渠道账号和不同 Runtime 的能力，仍需在具体实例中验证，例如 PI Agent 的 MCP 组合尚未验证开放。
