大二学年结束，不禁感慨时光飞逝，仿佛昨天还是一个小孩子，现在已经度过了一半的本科生涯。走上科研道路，摸爬滚打，步履蹒跚，在这一年中做出两篇工作，both LLM System infra，在这里宣传推广一下，希望能给大家带来一点思考，或是通过我们工作的不足给领域创造一些新的研究机会。<br><br><br>**[arXiv'26 preprint] PRISM: Fast Online LLM Serving via Scheduling-Memory Co-design**<br>[https://arxiv.org/abs/2605.08581](https://arxiv.org/abs/2605.08581)<br>这篇工作中，我们重新思考了LLM Serving中scheduling和KV-Cache Management的关系。这两者应该是相互耦合，互为因果的。<br>（1）KV Statement影响Scheduling：GPU中的显存状态会影响请求调度。在线服务中，我们可以优先服务前缀缓存已经在GPU中的请求，减小prefill的成本，提升系统整体的吞吐量；此外还要考虑长期驻留的“冷请求”，保证整体的长尾服务效率。<br>（2）Scheduling影响KV Statement：在调度过程中根据具体的策略，排队的请求其实已经实时形成了“潜在的”服务顺序。缓存管理应该接收到未来请求服务的“信号”，来提前保护这些尚在GPU中，但将要服务的请求前缀，减少缓存颠簸。<br>

![](https://pic3.zhimg.com/v2-6e2f491dada164a2282e42e483b9368c_r.jpg)

<br>（3）Scheduling and KV-cache Management是系统的成本的一部分：现有的LLM Serving System不断将调度/内存管理策略复杂化（大规模集群调度、多级缓存等），导致系统开销逐渐不可忽视，CPU-GPU的关系也发生了微妙变化。我们整合了LLM inference和queuing的相关理论，结合具体引擎和硬件条件的分析，提出了**特定条件下系统服务压力的分析框架**。在系统较低压力时，我们几乎不用什么策略（比如SGLang-native的LPM+LRU），就可以实现比较好的效果，或者说加了复杂的策略也没什么用；而在系统高压的情况下，实现一套**精细的scheduling-memory co-design策略**，对系统的整体效率就非常关键。<br>

![](https://pic4.zhimg.com/v2-ca00c5d9c215bb12b3d63a8a4ece9f3d_r.jpg)

<br><br><br>PRISM首先提出online workload-pressure-aware framework；在此基础上，针对高并发的场景，在SGLang的基础上实现**scheduling-memory co-design策略，提升LLM System的cache hit rate/throughput/TTFT P99。**<br>

![](https://pic3.zhimg.com/v2-5b4f97a4aa59e92e1538d5ce1a0d3a2a_r.jpg)

![](https://pic2.zhimg.com/v2-625acd8df95302bea82bf40a7289d9c9_r.jpg)

<br>实验模拟了真实场景的请求到达随时间变化和前缀热点分布的特征，在**多个QPS点下验证了系统效率**：在4B和13B模型下**分别降低了23.3%和37.1%的平均TTFT P99**。<br>这篇工作的意义在于**感知请求到达密度->实时计算系统压力->调整在线服务策略->提升系统服务效率，**但由于资源受限，尚未在大规模场景下得到验证。<br><br><br>**[arXiv'26 preprint] CacheBridge: Efficient Cross-Model KV Cache Transfer**<br>[https://arxiv.org/abs/2609.00891](https://arxiv.org/abs/2609.00891)<br>这篇文章我们关注模型家族中跨模型的KV reuse问题：**旨在使用更加高效，可部署的方法实现efficient multi-model LLM System**。<br>NVIDIA的一篇文章（Cross-Model KV Cache Transfer in LLM Families: A Closed-Form Linear Mapping for Prefill Reuse）提出**非训练手段的闭式解（无梯度下降/反向传播，纯矩阵运算）**得到一个mapper，由原模型KV直接映射到目标模型的KV，实现了高精度的cross-model KV reuse。<br>

![](https://picx.zhimg.com/v2-dee825d289c116120452e24ff5416bb3_r.jpg)

<br>这种方法作为一种新的范式，具有非数据语义依赖、高效在线处理等特点，对提高multi-model system serving efficiency很有前景。<br>我们基于这种方法范式提出四点observations：<br>**（1）转换质量对模型组合高度敏感，本质上反映了方法的架构敏感性。** 以 Ministral 模型家族为例，3B→14B 和 8B→14B 均出现了明显的转换失效。进一步分析发现，即使模型具有相同的 KV 接口，不同规模模型在残差表示和注意力特征上的差异，仍可能改变跨头相关性，使现有映射方法难以稳定迁移。这些现象与架构差异相一致，但其具体因果机制仍有待进一步验证。<br>**（2）Mapper 的优化目标与最终转换目标并不完全一致。** 转换是否成功，关键不在于 Mapper 能否在数值上精确拟合目标 KV，而在于转换后的 KV 能否恢复目标模型原本的 Attention 计算行为。单纯以线性岭回归的拟合误差作为优化目标，可能无法充分约束最终的注意力输出；随着上下文变长，这类误差还会持续累积，带来更明显的精度损失。<br>**（3）现有 Pipeline 的访存与计算模式难以充分发挥 GPU 性能。** Top-k 策略需要从多个 Source Layer 中选取并读取分散的 KV 表示。生成 Target KV 时，会产生大量细粒度计算、跨层数据读取与频繁的数据搬运，难以形成 GPU 擅长的大规模连续矩阵运算，最终造成较低的硬件利用率和转换效率。<br>**（4）在线服务效率与 Mapper 的 Top-k 设置高度相关。** 更大的 Top-k 虽然引入了更多 Source Layer 信息，但也会同步增加 KV 读取、映射计算和结果聚合的成本。当 Top-k 设置过大时，在线转换的延迟甚至可能超过直接 Re-prefill，使 KV Transfer 失去原本的效率优势。<br>这四点观察共同说明：跨模型 KV Transfer 不仅是一个“如何拟合 KV”的问题，还需要同时考虑模型架构、Attention 计算目标、GPU 执行模式以及在线服务成本。<br>针对上述问题，我们提出了 **CacheBridge**。它从映射结构、优化目标和执行方式三个层面重新设计 KV Transfer，同时保持在线阶段仍然是简单的仿射映射。<br>**（1）Head-Local：利用模型结构约束 Head 之间的映射关系。** 现有方法会使用全部 Source KV Heads 预测每一个 Target KV Head。CacheBridge 根据模型的注意力结构，只保留架构对应的 Head 连接，同时继续聚合多个 Source Layers。这样可以减少对不稳定跨 Head 相关性的依赖，并将 Mapper 的参数量和主要映射计算量降低至原来的八分之一。<br>**（2）Attention-Aligned Calibration：让拟合目标更接近真实的 Attention 计算。** 不同位置的 KV 误差，对最终 Attention 输出的影响并不相同。CacheBridge 根据 Target Model 的 Query 和注意力分布，为校准样本设置不同权重，优先减小对 Attention 影响更大的误差。同时，我们限制权重的集中程度，避免少量 Token 主导拟合过程。这一调整只发生在离线校准阶段，不会增加在线转换成本。<br>**（3）Fused Construction：重新组织 Mapper 的 GPU 构建流程。** 由于 Top-k Layer 和 Head 对应关系在拟合前已经确定，CacheBridge 会提前编译数据读取路径，并以分块方式直接构建岭回归所需的统计量。这样可以减少离散 Gather、中间张量生成和频繁的数据搬运，同时保持原有的优化目标、求解器和 Mapper 格式不变。<br>总体来看，CacheBridge 并没有堆叠额外的在线模块，而是重新设计了“使用哪些特征、优化哪些误差，以及如何高效完成拟合”。在线交接时，只需要应用一个更小的仿射 Mapper。<br>我们在 Ministral 3B→14B、Ministral 8B→14B 和 Qwen3 14B→32B 三组跨模型转换上进行了验证。<br>**（1）CacheBridge 恢复了失效模型组合上的转换质量。** 在 HellaSwag 上，现有 Dense 方法在 Ministral 3B→14B 和 8B→14B 上分别只有 52.2% 和 44.4% 的准确率。CacheBridge 将结果提升至 72.6% 和 76.0%，分别恢复了 20.4 和 31.6 个百分点，而原生 Target Model 的准确率为 77.2%。<br>在四项任务的平均 Target Retention 上，两组 Ministral 转换分别由 65.89% 提升至 88.23%，以及由 59.43% 提升至 97.57%。<br>**（2）结构约束是质量恢复的关键。** 在保持 Mapper 容量一致的对照实验中，无论是使用全 Head 的压缩表示，还是打乱 Source 与 Target Head 的对应关系，转换质量都会明显下降。这说明效果提升并不只是来自参数量减少，正确的 Head 对应关系同样重要。<br>**（3）Attention-Aligned 优化进一步改善了长上下文表现。** 加入 Attention-Aligned Calibration 后，普通 KV 拟合指标几乎没有提升，但 HellaSwag Target Retention 增加了 1.25 个百分点，4K 上下文的 NLL 由 2.446 降至 2.350。这进一步说明：更准确地拟合 KV 数值，并不一定等价于更好地恢复模型计算。<br>**（4）在保持质量的同时，Mapper 更小、转换更快。** 在 Qwen3 14B→32B 上，CacheBridge 达到了 99.83% 的平均 Target Retention。与此同时，Mapper 大小由 4.296 GB 降低至 0.538 GB，在线映射速度提升 1.6～3.0 倍，并且上下文越长，效率优势越明显。<br>**（5）Mapper 的离线构建成本也得到明显降低。** 在四张 H800 GPU、500 条校准序列的实验设置下，融合构建流程将 Mapper 构建时间从 92.63 秒缩短至 8.63 秒，实现了 10.7 倍加速，同时保持相同的拟合目标和输出格式。<br>CacheBridge 让跨模型 KV Transfer 从“可以转换”走向“稳定、高效、可部署”。它通过架构感知的 Head 映射和 Attention 对齐优化将方法的泛化性大大增强，并构建专用的GPU kernal加速了pipeline的计算过程。
