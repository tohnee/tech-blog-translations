视频等视觉输入被编码成 token 序列后，可以沿序列切分到多张卡，减少每张卡负责的数据量。但 Attention 仍然需要访问其他卡上的 token，因此必须分清：一张卡负责输出哪些 token，以及为了算出这些输出，它必须取得哪些输入。

“Attention 内部没有看到通信”可能表示数据已经准备好，也可能表示通信在算子外层。仅凭一个算子的调用，无法确定整层的数据是否跨卡流动。

## 1. 序列可以切开，Attention 的依赖仍然连在一起

先固定一个简化示例：一条序列有 8 个 token，编号为 0～7，使用 4 张卡。每张卡负责两个 token，所有 token 可以相互关注。这里的 token 是进入 Transformer 的序列元素，可以来自文本，也可以来自图像或视频。

### 1.1 每张卡负责两个 token，为什么还需要其他六个 token

每个 token 的输入表示经过线性投影，得到 Q (Query, 查询)、K (Key, 键) 和 V (Value, 值)。Q 与 K 用来计算匹配分数，V 是按照这些分数进行加权的内容。下文用 KV 表示 K、V 这两个张量。

令 $X_r$ 表示卡 $r$ 的输入分片，其中 $r=0,1,2,3$。假设每张卡已经持有相同的投影权重 $W_Q,W_K,W_V$，则可以独立计算：

$Q_r=X_rW_Q,\qquad K_r=X_rW_K,\qquad V_r=X_rW_V$

初始分配如下。表内的下标表示**序列分片编号**：

| 卡 | 负责的 token | 本地 Q | 本地 KV | 最终负责的输出 |
| --- | --- | --- | --- | --- |
| 卡 0 | 0、1 | Q₀ | K₀、V₀ | O₀ |
| 卡 1 | 2、3 | Q₁ | K₁、V₁ | O₁ |
| 卡 2 | 4、5 | Q₂ | K₂、V₂ | O₂ |
| 卡 3 | 6、7 | Q₃ | K₃、V₃ | O₃ |

以卡 0 为例，它只负责输出 token 0、1 的结果，但这两个 token 都允许关注整条序列。因此它需要计算：

$O_0=\operatorname{Attention}\left(Q_0,[K_0;K_1;K_2;K_3],[V_0;V_1;V_2;V_3]\right)$

分号表示沿序列方向拼接。这个公式规定了需要覆盖的数据范围，并不要求实现时真的把它们一次性拼到一起。

**输出归属由 Q 决定，输入依赖由 Q 能关注的 KV 范围决定**。

只用本地 $K_0,V_0$，算出来的就是两个 token 内部的局部 Attention，其他六个 token 的影响会丢失。

还要区分模型参数与激活：$W_Q,W_K,W_V$ 是权重参数，$Q_r,K_r,V_r$ 是当前层根据输入生成的激活。本文讨论的 Attention 通信主要搬运这些激活；各卡已有相同权重，也不能独立推导出远端输入对应的 KV。

### 1.2 上下文并行具体切分什么

CP (Context Parallelism, 上下文并行) 把同一条序列沿 token 方向分配给多张卡。每张卡对本地 token 进行投影、归一化和逐 token 的前馈计算；遇到跨 token 的 Attention 时，再通过通信满足远端依赖。

在这个设定下，一层的处理过程是：

```text
本地输入 token
    ↓ 本地归一化与 QKV 投影
本地 QKV
    ↓ 获取远端信息，完成全局 Attention
本地 token 的 Attention 输出
    ↓ 本地输出投影、残差与逐 token 前馈计算
下一层的本地输入 token
```

这里仅考虑 CP 本身。若叠加权重切分或需要跨卡分发 token 的其他机制，还会出现额外通信。CP 主要减少序列激活和对应计算的单卡份额，本身不保证模型权重也被切分。[Megatron Core：Context Parallelism](https://docs.nvidia.com/megatron-core/developer-guide/0.16.0/user-guide/features/context_parallel.html)

解决远端依赖可以保持 Q 的归属，也可以先改变 Q 的分配方式：

| 处理思路 | Q 的归属 | 如何满足远端依赖 |
| --- | --- | --- |
| 保持按序列分片 | 本卡继续负责原来的 token | 把这些 Q 所需的远端 KV 送过来 |
| 转换为按注意力头分片 | 本卡改为负责部分头的全部 token | 先重分布 QKV，让这些头所需的数据都在本地 |

这个区别决定了本地 Attention 是只算部分 query，还是算部分头上的完整序列。先保持原有 token 归属，最直接的办法是收齐所需 KV。

## 2. 先收齐 KV，再做本地 Attention

AllGather (All-Gather, 全收集) 让每张卡都得到通信组内所有卡的数据分片。对 KV 执行这个操作后，各卡继续使用自己的 Q，但都拥有完整 KV。

四卡示例中，收集完成后的布局为：

| 卡 | 本地参与计算的 Q | 已收齐的 KV 对应 token | 得到的输出 |
| --- | --- | --- | --- |
| 卡 0 | 0、1 | 0～7 | 0、1 |
| 卡 1 | 2、3 | 0～7 | 2、3 |
| 卡 2 | 4、5 | 0～7 | 4、5 |
| 卡 3 | 6、7 | 0～7 | 6、7 |

每张卡现在都可以调用一次普通的本地 Attention：

$O_r=\operatorname{Attention}(Q_r,K_{\mathrm{all}},V_{\mathrm{all}})$

其中 $K_{\mathrm{all}},V_{\mathrm{all}}$ 是完整序列的 K、V。**本地 Attention 算子里可以完全没有卡间通信，因为通信已经在调用之前完成**。Transformer Engine 将这种方式明确列为一种 CP 通信实现。[Transformer Engine：cp_comm_type](https://docs.nvidia.com/deeplearning/transformer-engine/api/pytorch.html)

这种方法的代价是完整 KV 的存储。设完整 KV 总大小为 $M$ 字节，四卡均分时每卡原本持有约 $M/4$ 字节；完成收集后，每卡要能容纳约 $M$ 字节的 KV。这里仅计算 KV 数据，不包含 Q、输出和通信缓冲区。

AllGather 的底层传输也可以采用环形拓扑。不过，**先收齐再计算**与**收到一块就计算一块**具有不同的显存和执行特征。要降低完整 KV 的驻留需求，就需要让 KV 分块到达并及时参与计算。

## 3. RSP (Ring Sequence Parallel, 环形序列并行)：固定本地 Q，让 KV 逐块经过

RSP 采用 Ring Attention（环形注意力）：保持按序列分片的 Q 归属，把 KV 块沿各卡组成的逻辑环传递。每张卡逐块处理自己的 Q 与当前 KV 的交互，并把部分结果合并成最终输出。

### 3.1 四张卡如何覆盖完整序列

继续采用相同的四卡分配。约定发送方向为卡 0 → 卡 1 → 卡 2 → 卡 3 → 卡 0，表内 $KV_r$ 代表原本属于卡 $r$ 的两个 token 的 KV。

| 计算轮次 | 卡 0 固定使用 Q₀ | 卡 1 固定使用 Q₁ | 卡 2 固定使用 Q₂ | 卡 3 固定使用 Q₃ |
| --- | --- | --- | --- | --- |
| 第 0 轮 | 处理 KV₀ | 处理 KV₁ | 处理 KV₂ | 处理 KV₃ |
| 第 1 轮 | 处理 KV₃ | 处理 KV₀ | 处理 KV₁ | 处理 KV₂ |
| 第 2 轮 | 处理 KV₂ | 处理 KV₃ | 处理 KV₀ | 处理 KV₁ |
| 第 3 轮 | 处理 KV₁ | 处理 KV₂ | 处理 KV₃ | 处理 KV₀ |

沿任意一列向下看，都会遇到全部四个 KV 块。因此，每张卡最终仍然得到自己两个 token 对整条序列的 Attention 输出。

四轮计算只需要三次跨卡推进：第一轮使用本地 KV，最后一轮结束后无需再取得新块。实际调度可以在计算当前块时，同时发送当前 KV、接收下一块 KV。Q 保持不动，变化的是当前处理的 KV 块。[Ring Attention 原论文](https://arxiv.org/html/2310.01889v4)

这里的“全局”来自**各轮覆盖了全部允许关注的 key**，并不要求全部 KV 同时常驻。实现仍然需要本地 KV 和接收等缓冲区，但无需为计算准备一份完整的全局 KV 拼接张量。

### 3.2 分块计算为什么还能得到全局 Softmax

KV 可以分轮到达，但每个 query 的 Softmax 分母涉及所有 key。要正确合并，除了每块的输出，还必须保留它在全局归一化中应占的权重。

Online Softmax（在线 Softmax）通过维护可合并的归一化状态，让分数块能够逐步参与计算。本地 Attention 也可以返回已归一化的局部输出，以及 LSE（Log-Sum-Exp，指数和的对数）；LSE 记录该分片的对数分母，供外层合并时计算各分片应占的权重。

完整推导见 [Flash Attention 与 Online Softmax：分块计算与归一化推导](https://zhuanlan.zhihu.com/p/2094808572391600965)。其中第 5 章从分子、分母的尺度修正推导局部输出的加权合并，5.4 节说明固定 Q、拆分 KV 后如何用输出与 LSE 跨轮累积。

在上面的四卡示例中，每卡处理当前 KV 后，将局部输出与 LSE 合并进自己的累计状态，再处理下一块 KV。沿环传递的是 KV；累计输出与 LSE 留在负责该 Q 的卡上。四轮覆盖所有有效位置后，得到完整 Attention 的归一化输出。浮点累加顺序变化可能带来舍入差异，不保证逐位一致。

### 3.3 为什么本地算子看起来没有通信

FlashAttention 是在单卡内按块计算 Attention、避免物化完整分数矩阵的算法。公开的 `ring-flash-attention` 实现由外层前向循环先发起下一块 KV 的异步收发，再调用本地 FlashAttention 并合并输出／LSE，随后等待收发完成，才切换到下一块。通信代码因此可以位于 Attention kernel 外部。[Ring Flash Attention 前向实现](https://github.com/zhuzilin/ring-flash-attention/blob/main/ring_flash_attn/ring_flash_attn.py)

以卡 0 为例，下面按两组交替使用的工作缓冲 A、B 展示一种可行的重叠调度。图中块宽不代表实测耗时，橙色表示通信尚未完成时可能出现的等待；同一轮的本地 Attention 包含该轮全部本地 Q 与当前 KV 的计算：

![](https://pic3.zhimg.com/v2-46e9953b50097a315c1e95bf1a40f88a_r.jpg)

卡 0 的 Q、累计输出和 LSE 始终留在本卡；沿环发送的是当前 KV，接收的是下一块 KV。进入下一轮需要同时满足本轮计算与合并完成、收发完成两个条件。复用 A 或 B 前，该缓冲中的旧数据必须已完成本地读取和异步发送；接收完成后，新数据才能交给本地 Attention。异步收发还需及时下发，设备与通信后端支持并行推进时，图中的重叠窗口才可能兑现；等待时间可以缩短到零，四轮覆盖范围保持不变。

计算与通信充分重叠时，通信增加的可见等待时间可能很小，但传输字节数依然存在。在本例的基本实现中，每卡发送三个 KV 块，发送数据量约为 $3M/4$，接收量也约为 $3M/4$。Ring 的主要收益是流式存储和计算通信重叠，不能简单理解为“消除了通信量”。

这种方式一直固定本地 Q。若允许重新分配哪些 Q 由哪张卡计算，还可以利用不同注意力头之间的独立性。

## 4. USP (Ulysses Sequence Parallel, Ulysses 序列并行)：把“部分 token 的全部头”换成“全部 token 的部分头”

USP 基于 DeepSpeed 提出的 DeepSpeed-Ulysses 方法，采用按注意力头重新分配 QKV 的路线：先通过通信准备每个头的完整序列，再在本地计算这些头的 Attention。[DeepSpeed-Ulysses 官方介绍](https://www.deepspeed.ai/tutorials/ds-sequence/)

### 4.1 同一张 token × 头网格的两种归属

为已有的 8-token 示例加入 4 个注意力头，编号为 0～3。一个格子表示“某个 token 在某个头上的 Q、K、V 向量”，其中的数字表示这组数据归哪张卡。

最初按 token 分片，每张卡拥有两行、全部四列：

| token \ 头编号 | 头 0 | 头 1 | 头 2 | 头 3 |
| --- | --- | --- | --- | --- |
| 0 | 卡 0 | 卡 0 | 卡 0 | 卡 0 |
| 1 | 卡 0 | 卡 0 | 卡 0 | 卡 0 |
| 2 | 卡 1 | 卡 1 | 卡 1 | 卡 1 |
| 3 | 卡 1 | 卡 1 | 卡 1 | 卡 1 |
| 4 | 卡 2 | 卡 2 | 卡 2 | 卡 2 |
| 5 | 卡 2 | 卡 2 | 卡 2 | 卡 2 |
| 6 | 卡 3 | 卡 3 | 卡 3 | 卡 3 |
| 7 | 卡 3 | 卡 3 | 卡 3 | 卡 3 |

对 QKV 执行 All-to-All（全互换）：每张卡按头拆分自己的数据，把属于目标头的部分发给目标卡。结果变成每张卡拥有一列、全部八行：

| token \ 头编号 | 头 0 | 头 1 | 头 2 | 头 3 |
| --- | --- | --- | --- | --- |
| 0 | 卡 0 | 卡 1 | 卡 2 | 卡 3 |
| 1 | 卡 0 | 卡 1 | 卡 2 | 卡 3 |
| 2 | 卡 0 | 卡 1 | 卡 2 | 卡 3 |
| 3 | 卡 0 | 卡 1 | 卡 2 | 卡 3 |
| 4 | 卡 0 | 卡 1 | 卡 2 | 卡 3 |
| 5 | 卡 0 | 卡 1 | 卡 2 | 卡 3 |
| 6 | 卡 0 | 卡 1 | 卡 2 | 卡 3 |
| 7 | 卡 0 | 卡 1 | 卡 2 | 卡 3 |

具体看卡 0：它保留本地 token 0、1 的头 0 数据，并从另外三张卡取得 token 2～7 的头 0 数据；自己原本持有的头 1～3 数据则发给其他卡。**Q、K、V 一起改变归属。**

卡 0 现在可以完整计算头 0 的 Attention，因为这个头的全部 QKV 都在本地。其他三张卡分别计算其他头。计算完成后，对输出执行反向 All-to-All，恢复“两个 token、全部四个头”的归属，再继续本地输出投影。

### 4.2 序列完整，不代表张量全部复制

设序列长度为 $S$，注意力头数为 $N$，每个头内向量的特征维长度为 $D$。省略大小为 1 的 batch 维，Q、K、V 的布局变化为：

$[S/4,N,D] \xrightarrow{\text{All-to-All}} [S,N/4,D]$

序列长度变成四倍，头数变成四分之一，单卡元素数仍为 $SND/4$。与完整收集所有头的 KV 相比，Ulysses 通过转移数据归属保留了分片存储。

用一个长序列规模的形状示例验算，取 $S=16384,N=32,D=128$：

$[4096,32,128]\rightarrow[16384,8,128]$

变换前后，每个 Q、K 或 V 张量均有 16,777,216 个元素。这个示例只用于验证布局和元素数，不代表某个模型的实测配置。

因此，纯 Ulysses 的本地 Attention 阶段也可以没有卡间通信；通信发生在它前后的 All-to-All。与 AllGather KV 不同，这里每张卡只拥有部分头的完整序列，且 Q 的归属也改变了。

### 4.3 为什么不能无限增加按头切分的卡数

基础 Ulysses 实现需要把头分给不同卡。在四头示例里，四卡可以每卡一个头；如果直接增加到八卡，就没有八个独立的头可分。实际实现还会受头数的整除关系约束。

本文的示例采用 MHA (Multi-Head Attention, 多头注意力)，Q、K、V 的头数相同。GQA (Grouped-Query Attention, 分组查询注意力) 让多个 Q 头共享一组 KV 头；MQA (Multi-Query Attention, 多查询注意力) 则让所有 Q 头共享一组 KV。它们减少 KV 数据量，也让无需复制 KV 的按头切分受到更少 KV 头数的约束。支持复制或其他重排的实现可以改变这一限制及通信成本，不能只按 Q 头数判断可用并行度。

这些方法只依赖 QKV 的布局，不依赖 token 原本来自文字还是画面。多模态真正改变通信需求的地方，在于不同 Attention 层允许 Q 访问哪些模态，以及哪些数据被复制。

## 5. 多模态中的文本复制，究竟省掉了什么通信

两种多模态注意力结构的区别在于视觉 Q 所需的 KV 范围。Cross Attention（交叉注意力）允许 Q 与 KV 来自不同序列，本例由视觉序列产生 Q、文本序列产生 KV。Joint Attention（联合注意力）把文本和视觉序列放进同一个注意力范围，本例采用全局双向形式，文本与视觉 query 都能访问两种模态的 key。

| 结构 | 视觉 Q 需要的 KV | 每卡有完整文本时，是否还缺远端视觉 KV |
| --- | --- | --- |
| 视觉查询文本的 Cross Attention | 文本 KV | 不需要视觉 KV |
| 文本与视觉的全局 Joint Attention | 文本 KV + 全部视觉 KV | 需要 |

这个区别决定了文本复制能否让当前 Attention 的输入完整。交叉注意力只需满足文本 KV 的依赖；联合注意力还需处理远端视觉 KV 的依赖。

下标 $\mathrm{text}$、$\mathrm{vis}$ 分别标识文本与视觉模态，追加的下标 $r$ 表示卡编号。卡 $r$ 的视觉 query 记为 $Q_{\mathrm{vis},r}$，本地视觉 KV 记为 $K_{\mathrm{vis},r},V_{\mathrm{vis},r}$；完整文本 KV 记为 $K_{\mathrm{text}},V_{\mathrm{text}}$。视觉序列继续按原来的四卡方式切分；由于文本通常比视觉序列短，一种实现选择是每卡保留完整文本表示。

### 5.1 交叉注意力只需要完整文本 KV

在视觉查询文本的交叉注意力中，卡 $r$ 的计算是：

$O_{\mathrm{vis},r}=\operatorname{Attention}(Q_{\mathrm{vis},r},K_{\mathrm{text}},V_{\mathrm{text}})$

只要每张卡都持有当前层所需的完整文本表示与投影权重，就能在本地生成 $K_{\mathrm{text}},V_{\mathrm{text}}$：

| 卡 | 本地视觉 Q | 完整文本 KV | 该次 Cross Attention 的输入是否齐全 |
| --- | --- | --- | --- |
| 卡 0 | 视觉 Q（卡 0） | 文本 K、文本 V | 是 |
| 卡 1 | 视觉 Q（卡 1） | 文本 K、文本 V | 是 |
| 卡 2 | 视觉 Q（卡 2） | 文本 K、文本 V | 是 |
| 卡 3 | 视觉 Q（卡 3） | 文本 K、文本 V | 是 |

这次前向 Attention 的核心计算可以没有额外的 CP 通信。原因是它需要的全部 KV 正好就是已复制的文本 KV。复制数据如何到达各卡，以及模型其他层是否通信，是另外的边界。

### 5.2 联合注意力还需要其他卡上的视觉 KV

在文本与视觉共同参与的全局联合注意力中，视觉 query 的输出变为：

$O_{\mathrm{vis},r}=\operatorname{Attention}\left(Q_{\mathrm{vis},r},[K_{\mathrm{text}};K_{\mathrm{vis},\mathrm{all}}],[V_{\mathrm{text}};V_{\mathrm{vis},\mathrm{all}}]\right)$

下标 $\mathrm{vis},\mathrm{all}$ 表示完整视觉序列。卡 0 已经有 $K_{\mathrm{text}},V_{\mathrm{text}}$ 和本地 $K_{\mathrm{vis},0},V_{\mathrm{vis},0}$，但依然缺少卡 1～3 的视觉 KV，仍需通过完整收集、Ring 或 Ulysses 等方式处理视觉部分。

文本自己的输出也需要注意：若文本 Q 能关注视觉 token，那么即使文本输入完全复制，各卡仍然需要完整视觉信息才能正确更新文本表示。完整文本副本不会自动包含远端视觉的贡献。

### 5.3 文本 KV 本地加入一次，视觉 KV 沿环传递

对“文本复制、视觉分片”的 Joint Attention，可以把本地文本 KV 与流经的视觉 KV 分开处理。假设在第一轮加入文本，卡 0 的处理顺序为：

| 轮次 | 当前参与计算的 KV | 文本处理 |
| --- | --- | --- |
| 第 0 轮 | 本地视觉 KV₀ 与完整文本 KV | 加入一次 |
| 第 1 轮 | 来自卡 3 的视觉 KV₃ | 不再加入 |
| 第 2 轮 | 来自卡 2 的视觉 KV₂ | 不再加入 |
| 第 3 轮 | 来自卡 1 的视觉 KV₁ | 不再加入 |

每轮都按已介绍的 Softmax 统计量合并。完成后，当前 Q 见过一次完整文本和一次完整视觉序列。

文本只加入一次是语义要求。如果每轮都把相同文本加入归一化，文本项在分子与分母中都会重复四次，而视觉项只出现一次，文本相对视觉的注意力权重就被改变了。

xDiT 的 CogVideoX 接入文档给出了“保留完整文本、只切分视觉序列”的方案，其 Ring 实现仍对主序列的 K、V 执行收发，只把复制的文本 KV 加入指定的一轮。这说明文本复制和视觉 Ring 通信可以同时存在。[文本复制方案](https://github.com/xdit-project/xDiT/blob/main/docs/developer/adding_models/adding_model_usp_text_replica.md)、[对应 Ring 实现](https://github.com/xdit-project/xDiT/blob/main/xfuser/core/long_ctx_attention/ring/ring_flash_attn.py)
