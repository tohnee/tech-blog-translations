## 主流模型的MoE推理量化

目前主流模型的MoE推理量化可以归纳为 W8A8、W4A8 和 W4A4 三类。W4A16 更多是一种架构兼容。

1. **W8A8**。GLM-5.2-FP8、Qwen3.5-FP8系列，以及 DeepSeek-V4-Flash/Pro Base 都属于这一类。其专家权重以 FP8 E4M3 保存，activation 在运行时动态量化为 FP8，硬件MMA 是 FP8 activation × FP8 weight。GLM-5.2-FP8 和 Qwen3.5-FP8 使用 fine-grained FP8：weight 通常按 128×128 block 共享 scale，activation 通常按 token、沿 K/128 共享 scale。该 scale 有两种处理方式：
2. **W4A8**，代表是 Kimi K3 和 DeepSeek-V4-Flash/Pro 原始发布版。
3. **NVFP4 W4A4**。主要包括 NVIDIA GLM-5.2-NVFP4、Qwen3.5-NVFP4 和 DeepSeek-V4-Flash-NVFP4。这些 checkpoint 将目标 MoE routed-expert weight 和 input activation 都配置成 E2M1 FP4，并采用 K/16 的 E4M3 block scale，因此属于 W4A4，而不是 W4A8。NVFP4 包含两级scale，第一级E4M3 block scale在tcgen05 block_scale mma中消耗，第二级为 FP32 global scale通常在 accumulator 或 epilogue 中、bias 和非线性操作之前应用。

## 各种wXaX计算方式总结表

MoE的input x weight，核心的计算方式主要为w8a8/w8a16/w4a4/w4a8/w4a16。下表针对不同的wXaX在SM100+硬件上的计算方式做了归纳和总结。

![](https://pic2.zhimg.com/v2-46a301352058678f37c85fa01467cf75_r.jpg)

### w4a4

对于 W4A4，SM100 的 `tcgen05` 原生支持 MXFP4×MXFP4 和 NVFP4×NVFP4 block-scale MMA。FP4 operand 无需先物化成 FP8/BF16，weight、activation 及其 scale factor 可以直接进入 Tensor Core，并累加到 FP32。

使用 warp-level `mma.sync` 时：

- SM120 原生支持 MXFP4 和 NVFP4 block-scale MMA。
- SM100 不支持 FP4 block-scale `mma.sync`，需要先把 FP4 operand 展开为 FP8 或 BF16，再执行普通 FP8/BF16 `mma.sync`。
- NVFP4 展开到 FP8 时，需要在 MMA 前处理其 UE4M3 block scale 和 FP32 global scale，不能将两个不同 K/16 scale 对应的结果先合并，再统一缩放。

### w4a8

对于 MXFP4 weight 和 MXFP8 activation，SM100 的 `tcgen05` 可以原生执行混合 block-scale MMA。两侧均采用 UE8M0、K/32 scale，因此无需 operand dequant：

$\(D= \left(S_AQ_A^{\mathrm{FP8}}\right) \left(S_WQ_W^{\mathrm{FP4}}\right)^T+C\)$

对于 NVFP4 weight 和 FP8 activation，目前没有原生的非对称 NVFP4×FP8 block-scale MMA。主要有两条路径：

1. 在 MMA 前将 NVFP4 weight 解码并应用 UE4M3 block scale 和 FP32 global scale，再生成 FP8/BF16 weight operand。
2. 将 FP8 activation 再量化为 NVFP4，转成fp4 计算。

使用 `mma.sync` 时：

- SM100 不支持 FP4 block-scale `mma.sync`，必须先将 weight 转换为 FP8或BF16。
- SM120 原生支持 MXFP8×MXFP4 block-scale `mma.sync`，物理 operand 为 A=FP8、B=FP4。
- SM120 仍然没有原生 FP8×NVFP4 fused block-scale 路径，因为 NVFP4 使用 UE4M3、K/16 scale，而 MXFP8/MXFP4 混合指令使用 UE8M0、K/32 scale。

### w4a16

无论使用 `tcgen05` 还是 `mma.sync`，目前都没有原生的 BF16/FP16×FP4 block-scale MMA。

常规路径是：

```text
FP4 weight
  → 解码并应用 block scale
  → 展开为 BF16/FP16
  → BF16×BF16 或 FP16×FP16 MMA
```

因此，模型存储层虽然是 W4A16，但物理 Tensor Core 运算实际为 W16A16。FP4 主要保留 weight 存储容量和显存带宽收益，同时需要承担 weight CVT、scale CVT 和 scale multiply 开销。

也可以在 MMA 前动态量化 activation：

- MXFP4 W + A16→MXFP8：物理运算变成 W4A8。
- MXFP4 W + A16→MXFP4：物理运算变成 W4A4。
- NVFP4 W + A16→NVFP4：物理运算变成 W4A4。

在 SM100 上可以使用对应的 block-scale `tcgen05`；在 SM120 上可以使用 block-scale `mma.sync`。但此时不能再把物理计算称为 A16，因为 activation 已在进入 MMA 前量化为 FP8或FP4。

### w8a8

对于 W8A8，需要区分普通 FP8、MXFP8 和其他 fine-grained FP8。

SM100 的 `tcgen05`：

- 普通 E4M3/E5M2 operand 可以直接进入 `tcgen05.kind::f8f6f4`；per-tensor scale 在 accumulator/epilogue 中处理。
- MXFP8 可以直接使用 block-scale `tcgen05`，由硬件在 MMA 内消费 UE8M0、K/32 scale。
- K/128、128×128 等非原生 fine-grained FP8 scale 不能“直接计算”：需要在 partial accumulator 上应用 scale，或者将 scale 复制、转换并重排成 K/32 UE8M0 block-scale layout。

使用 `mma.sync` 时：

- SM100 可以直接执行普通 FP8×FP8 `mma.sync`。
- SM100 的 `mma.sync` 不能在指令内消费 MXFP8 scale，但不要求必须转换到 BF16。可以直接对 E4M3/E5M2 operand 做普通 FP8 MMA，再对每个 K/32 partial 应用 SFA×SFB。
- 将 MXFP8 展开为 BF16，再执行 BF16 `mma.sync`，只是另一条兼容路径。
- SM120 既支持普通 FP8 `mma.sync`，也支持原生 MXFP8 block-scale `mma.sync`。
