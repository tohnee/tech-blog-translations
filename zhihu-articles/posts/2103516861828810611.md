先说一个我经历过的翻车现场。

去年一次大促，投放链路是这样的：3 个触达渠道（短信、公众号菜单、达人私信），5 套内容版本，2 个落地页（新客页 / 老客页）。算下来要 3 × 5 × 2 = 30 条链接。

我用 Excel 拼 UTM，一条条拼，拼了快两个小时，还错了两条——其中一条少了个 &，落地页只收到了第一个参数，等于那个版本一整周的数据都是废的。

更麻烦的是后面。活动第三天，落地页要改文案，但**短信已经发出去了，公众号推文已经发出去了，达人手里的卡片已经发出去了**。物料上的链接不能改，只能后台改跳转目标。如果当初没有做「短链指向可配置」这件事，这次改动就意味着所有渠道重发一遍。

那次之后我给自己定了一条规矩：**投放链路里，凡是会被印在物料上、发在别人手上的链接，一律走短链，而且必须能后台改指向。**

后来短链服务接了 MCP，建链这件事就基本从我的工作流里消失了。下面写具体怎么用。

一、为什么是 MCP，而不是 API

先把这个说清楚，不然后面全是空话。

短链服务基本都提供 REST API。但 API 的隐含前提是：**你得会写代码，或者你团队里有人随时能帮你跑脚本**。对投放和运营来说，这是个硬门槛——为了生成 30 条链接去提个需求、等排期，成本比手工拼还高。

MCP（Model Context Protocol）做的事，是把「这个服务能干什么」直接暴露给 AI 客户端。配一次，之后你在 Claude、Cursor、豆包这类支持 MCP 的客户端里，直接用自然语言说「把这 30 条生成短链」，它就去调了，不用写代码。

两者的差别大概是这样：

|  | REST API | MCP |
| --- | --- | --- |
| 使用门槛 | 会写代码 / 有人帮你跑 | 会说人话就行 |
| 换模型或客户端 | 要重新对接 | 配置一次，多处复用 |
| 适合的角色 | 工程、自动化流水线 | 投放、运营、内容 |
| 出错成本 | 脚本跑错全错 | 可以逐条看、随时纠偏 |

要说明一句：MCP 不是替代 API。你要做系统级集成、要做定时任务、要把建链塞进业务后台，还是得用 API。MCP 解决的是另一件事——**把「一次性、临时性、零散」的建链需求，从工程排期里拿出来，让运营自己就能完成。**

而投放里的建链需求，八成都是这种零散的。

二、接上大概只要三分钟

以支持 MCP 的客户端为例，配置长这样（地址和参数以控制台「API / MCP 接入」页面给出的为准，各家写法略有差异）：

```text
{
  "mcpServers": {
    "shortlink": {
      "type": "http",
      "url": "https://你的服务地址/mcp",
      "headers": {
        "Authorization": "Bearer 你的_API_KEY"
      }
    }
  }
}
```

保存后重启客户端，问一句「你现在能创建短链吗」，它能正常回应就通了。

就这一步。剩下的全是用法问题。

三、我实际在用的三个场景

场景一：一句话批量建链（替代手工 Excel）

把渠道、版本、落地页做成三列表格，丢给 AI，说：

> 读这个文件，按每一行生成一条短链。后缀用「渠道-版本」的拼音，比如 duanxin-a。结果写回第四列，生成失败的单独列出来，不要跳过。

三十条链接，大概十几秒。而且失败的行会被单独拎出来——手工做的时候，你根本不知道哪条错了。

这里有个细节值得单独讲：**后缀规则最好在建链前就定死，并且写进模板里。** 因为短链的后缀生成后不能改，只能重新生成一条。后缀命名有规律，后面看数据的时候才能一眼认出「这条是短信渠道的 A 版本」，不然 30 条随机字符，复盘时你得对着表格一条条核。

我的命名习惯是 渠道-版本-落地页，全小写，不加下划线，长度控制在 12 个字符内。

场景二：复盘时让 AI 自己去取数

以前复盘是这样：登录后台 → 导出 CSV → 打开表格 → VLOOKUP 关联订单 → 手动算 → 写周报。链路长，且每次都要重来一遍。

接了 MCP 之后，我一般直接说：

> 拉最近 7 天这批短链的点击数据，按渠道 × 版本做个交叉表，算每个版本的点击率，标出明显低于中位数的那几条，再结合历史数据给我三个下周可以试的方向。

它会自己去调数据接口，把表拉出来，做交叉分析。**它给的方向不一定对，但它省掉了我「取数 + 做表」这一步，而这一步是我原来最烦的。**

注意一点：AI 做数值计算偶尔会算错，尤其是比值和百分比。所以我的习惯是让它给原始数，公式我自己再核一遍。这不是不信任，是这类工作本来就得有人复核。

场景三：一条主链做分流，少建一半链接

这个用法知道的人不多。投放里经常遇到「同一个活动，iOS 用户要跳 App Store，安卓用户要跳应用市场，其他跳官网」。

不用建三条链接。建一条主链，把分流规则配好（按设备、按地区、按时间），投出去就一条。

好处是：**物料只需要一个二维码。** 线下物料、包装、卡片上印一个码，扫的人是谁、该去哪儿，服务端判断。活动期间规则想调整，后台改，物料不用重印。

代价是：分流逻辑在服务端，属于「看不见的一跳」，出问题不好排查。所以规则上线前一定要自己用不同设备测一遍，特别是 iOS 和微信内置浏览器这两条路径。

四、六个坑，都是我真踩过的

这部分是全文我觉得最该看的部分。工具选谁都一样，坑是共通的。

**1. 别把「免费短链」当成免费通行证**

短链服务的域名信誉是**池化共享**的。同一个免费域名下，只要有人拿它做垃圾推广、诱导分享、跳转违规页面，整个域名在微信、QQ、部分浏览器里的待遇就会一起变差——你那条正经的活动链接也会被连带提示「已停止访问」。

所以做品牌活动、做要花钱投放的链接，**一定绑自有域名**。这是花几分钟配 CNAME 的事，但它决定了你的物料会不会在活动当天集体失效。我现在的做法是：免费池域名只用于测试和内部沟通，对外投放全部走品牌域名。

**2. 多一跳就是多一次流失**

短链本质是 302 跳转，多了一次网络往返。正常情况下感知不到，但在弱网、老机型、微信内置浏览器里，这一跳可能变成 1 秒白屏，也可能变成「打不开」。

我做过对比，一次额外跳转带来的流失大概在个位数百分比区间（具体看渠道和网络环境，不同活动差异很大）。结论是：

- **短信、线下二维码、私信、达人分发这类「链接必须短」的场景，这一跳值得。**
- **信息流广告的主链，不建议套短链。** 平台本身支持 UTM 和点击回传，你再加一跳，一是增加流失，二是归因口径会和平台报表对不上，最后两边数据打架，谁都不服谁。

**3. 目标链接里的参数必须整体编码**

这条我踩过两次。落地页链接长这样：

```text
https://example.com/landing?utm_source=dx&utm_campaign=1111&from=short
```

你要把它作为一个参数传给短链接口时，整个 URL 必须先做 URL encode。不做的话，接口会把第一个 & 之后的内容当成自己的参数，落地页只能收到 utm_source=dx，后面全丢。而且它不报错，你根本发现不了，直到复盘时发现某条链的转化率是 0。

检查方法很简单：建完链，自己点一遍，看落地页拿到的参数齐不齐。养成这个习惯，比什么都强。

**4. 短链后缀一旦生成就不能改**

短链的后缀是主键，不能改；能改的只有它指向的目标。所以命名规则要在建链之前想清楚。我吃过亏——第一批用了「随机短码」，长得好看，但 40 条链摊在表格里，完全分不清谁是谁，复盘时花的时间比建链还多。

**5. 二维码不是「越短越好」，是「越少模块越好」**

短链能压缩字符，但二维码的密度还受字符集影响：混入中文、大小写交替、特殊符号，都会让同长度下的模块数变多，印刷小了就扫不出来。

实操建议：短链全小写、纯字母数字、总长度控制在域名 + 8 位以内；二维码纠错等级用 H（有 logo 遮挡、印刷偏差时容错更高）；线下印刷尺寸不小于 2cm×2cm，包装类物料至少 3cm。

**6. 短链统计的绝对值会虚高**

短链后台的「点击数」，包含预加载、安全扫描器、聊天软件的链接预览抓取。所以它往往比真实到达人数高，尤其发在微信、钉钉里的时候。

用它可以看**趋势和相对高低**，不要拿它当绝对人数用。要比绝对值，就和落地页的访问数、订单数对齐看。

五、什么场景我会劝你别用短链

写产品的人容易有个毛病，觉得自己的工具哪儿都能用。说几个我明确劝退的场景：

- **站内跳转**：本来就是自家域名，缩短没意义，还多一跳。
- **信息流 / 搜索广告的主投放链接**：平台自己带参数和回传，别叠加。
- **需要完整保留 URL 参数做回传的场景**：除非服务明确支持参数透传，否则短链会吞掉一部分查询参数，回传链路会断。
- **需要投放平台审核认领的链接**：有些平台要求落地页域名可验证，多一层跳转会影响审核，具体看各家规则。

六、合规这件事，别等被封了才想

短链最大的风险不是技术，是「它天然适合隐藏真实目标」。所以有几条红线要自己划：

- 不要用它隐藏真实落地页去规避平台审核。这是明确的违规，且现在平台侧的识别能力比想象中强。
- 不要做诱导分享、诱导关注那类跳转。
- 发短信里的链接，运营商和短信服务商对内容有管控，需要报备的要报备，别先发了再说。
- 面向 C 端的服务，做好举报入口和黑名单，别让自己的域名变成别人的基础设施。

最后，一份可以直接抄的清单

如果你也经常做投放建链，把这几条存下来就够了：

1. 对外物料、要花钱的链接，一律绑自有域名，别用公共免费域名。
2. 后缀命名规则先定死：渠道-版本，全小写，12 字符内。
3. 建链前把目标 URL 整体 encode，建完自己点一遍验证参数。
4. 一条主链 + 分流规则，代替多条并行链接（线下场景尤其值得）。
5. 信息流广告主链不套短链。
6. 二维码用短字符集 + H 级纠错 + 不小于 2cm。
7. 看趋势不看绝对值，和落地页访问数交叉验证。
8. 上线前把「改指向」这条路走一遍——活动期间你会用到它的概率，比你想的高。

工具这块，MCP 的意义不在于「省了几个点击」，而在于它把建链这件事从「要排期」变成了「顺手就做了」。真正省下来的不是时间，是**你愿意为一个想法多试一次的意愿**——反正建 30 条链只要十几秒，那就多测几个版本。

以上。配置和用法都可以直接抄，工具用哪家都行，坑是一样的。
