### 摘要

现代 GPU 集成了 Tensor Core 等专用矩阵单元，用于加速深度学习工作负载中的核心操作 GEMM。然而，**现有矩阵单元设计与 SIMT 核紧密耦合，其操作规模受到寄存器文件容量与带宽的限制**。可扩展性上的这一局限，使 GPU 很难同时提高计算吞吐量和能源效率。

为解决这一挑战，我们提出 **Virgo**：一种在 SIMT **核集群层级集成专用矩阵单元**的 GPU 微体系结构。通过将矩阵单元与 SIMT 核解耦，Virgo 消除了核心微体系结构施加的扩展约束。因此，Virgo 能在硬件层面**增大操作粒度**，减少核心指令处理带来的能源开销。物理分离还支持统一的矩阵单元设计，并**将操作数与累加器访问都从寄存器文件中卸载**，从而改善数据复用和能源效率。此外，这种分离**支持 SIMT 核与矩阵单元高效并发执行**，优化融合 DNN 工作负载的映射。

使用可综合 RTL 的评估表明，与 Ampere 风格和 Hopper 风格的核心耦合设计相比，Virgo 的片上活动功耗分别降低 67.3% 和 24.2%。

**关键词：** GPU、微体系结构、加速器、可扩展性、功率与能耗、机器学习。

**CCS 概念：** 计算机系统组织：多核体系结构、单指令多数据、脉动阵列；硬件：功率与能耗。

### 1 引言

近年来，在大语言模型等大规模深度学习应用需求的推动下，GPU 的计算能力以前所未有的速度增长。为更好地满足这些需求，现代 GPU 越来越多地集成 NVIDIA Tensor Core、AMD Matrix Core 等专用矩阵单元。与传统通用 SIMD 单元相比，这些单元能以高得多的计算效率加速深度学习中的 GEMM。

随着算力需求继续增长，专用矩阵单元的集成规模也不断扩大：从 Volta 到 Hopper 的五年间，Tensor Core 达到的 FLOPS 增长了八倍。除 FLOPS 外，功率与能耗也成为现代 GPU 工作负载日益重要的问题。深度学习本身就是 GPU 上高度耗能的工作负载；GPU 还常常受功率上限约束，数据中心会超额配置 GPU 资源，并频繁降频以满足功率预算，进而牺牲性能。

但由于矩阵单元与 GPU SIMT 核紧密耦合，同时满足更高 FLOPS 和更高能源效率正变得越来越困难。矩阵单元通常作为专用功能单元集成在 SIMT 核流水线中，经由标准指令数据通路从寄存器文件接收数据。**寄存器文件的容量与带宽限制了操作规模，因此核心耦合矩阵单元通常只支持细粒度操作，例如 `16×8` 的分块。小粒度不仅限制数据复用，还要求核心流水线处理大量指令，使大量能量消耗在指令调度和地址生成上，而非真正的计算上（问题）**。

![](https://pica.zhimg.com/v2-016071725cd72ca3dcc521c80b0c32c2_r.jpg)

**如图（图 1）：** 现有 GPU 把多个 Tensor Core 紧密耦合进各个 SIMT 核；Virgo 则在集群层面设置统一、物理分离的矩阵单元。

为解决这些问题，我们提出 Virgo。其基石是**把矩阵单元从核心微体系结构中物理分离，在集群层面进行集成，从而消除扩展约束并增大矩阵操作粒度。Virgo 通过减少指令处理、消除冗余寄存器文件访问和提高数据复用，改善系统级能源效率。（解决）**

本文的主要贡献如下：

1. 提出一种新的 GPU 集群级矩阵单元集成方法，通过把加速器与 SIMT 核分离，提高可扩展性和效率。
2. 用可综合 RTL 完整实现所提集群级设计，以及模拟 Volta、Ampere、Hopper Tensor Core 的核心耦合基线，并开发相应的软件编程接口。Virgo 完全开源。
3. 在商用 16 nm 工艺综合结果中，相比 Ampere、Hopper 风格基线，Virgo 的活动功耗分别降低 67.3% 和 24.2%，能耗分别降低 80.3% 和 32.5%。

> **问题：** 寄存器容量与带宽限制–>细粒度–>复用差、频繁产生指令–>能量浪费、效率低 **解决方案：** 分离matrix–>增大力度–>提高复用、减少指令–>高效

### 2 背景与动机

本节概述 GPU 与 Tensor Core 微体系结构，说明**矩阵单元和 SIMT 核紧密耦合所造成的可扩展性与效率局限**，并由此引出 Virgo 在集群层面集成矩阵单元的关键决策。

### 2.1 GPU 集群微体系结构

现代 GPU 由多个连接到共享末级缓存的 SIMT 核集群组成。每个 SIMT 核包含 warp 调度器、寄存器文件，以及 Tensor Core 等紧耦合执行单元。集群内部的 SIMT 核通过集群级片上网络连接到共享内存，即软件管理的暂存存储器。

集群组织有两项主要优势：

1. 多个核心可同时执行彼此独立的 warp 指令，提高硬件并行度。
2. 更多线程可通过共享内存共享数据，提高内核内部的数据共享能力。

这种结构在业界广泛使用，在 NVIDIA 中称为 Streaming Multiprocessor，在 AMD CDNA 中称为 Compute Unit，在 Intel Xe-HPG 中称为 Xe-core。更重要的是，集群是线程块或工作组的硬件分配单位；线程块由一组 SIMT 线程构成，并提供共享内存访问与屏障同步的软件原语。LLM 等现代工作负载需要越来越大的 GEMM，因此**必须在共享内存层面提高数据复用，这正是把矩阵单元集成到集群层面的直接动机**。

### 2.2 最先进的 Tensor Core 集成方式

### 现状：

为满足深度学习快速增长的计算需求，NVIDIA 在 Volta 中引入 Tensor Core。Tensor Core 由多个 SIMD 并行点积单元构成，面向矩阵乘法的高吞吐乘加操作。**它与浮点单元、加载/存储单元一样，直接通过 SIMT 核的寄存器文件接收矩阵操作数。因此，当代 Tensor Core 本质上是紧密耦合进 SIMT 核执行流水线的专用矩阵乘法执行单元**。此前研究主要改善稀疏支持和通用操作，但仍保留核心耦合方式。

| GPU | V100 | A100 | H100 |
| --- | --- | --- | --- |
| 架构 | Volta | Ampere | Hopper |
| Tensor FP16 TFLOPS | 1× | 2.5× | 7.9× |
| CUDA FP32 TFLOPS | 1× | 1.2× | 4.3× |
| Tensor Core 数量 | 1× | 0.7× | 0.8× |
| 每个 Tensor Core 的 MAC 数 | 64 | 256 | 512 |
| 寄存器使用量（上限 255） | 224 | 221 | 168 |
| Warp 占用率 | 12.5% | 10.0% | 14.1% |

**表 1：** NVIDIA 数据中心 GPU 跨代计算能力的扩展趋势，以及 CUTLASS GEMM 内核的占用率。每个 Tensor Core 的 MAC 数由 FLOPS 与时钟频率推算；内核统计使用 V100/A100/H100 上 FLOPS 最高的五组参数组合取平均。

### 趋势：

Tensor Core 的计算能力增长很快，FP16 吞吐量的增长速度超过 CUDA 核的 FP32 吞吐量。增长并不是因为 Tensor Core 数量增加，而是每个 Tensor Core 实例变得更大。这说明未来 GPU **必须继续扩展单个矩阵单元的能力**。

### 2.3 核心耦合方式的局限

紧耦合使矩阵单元难以继续扩展。

首先，现代 GEMM 内核会产生很高的**1. 寄存器压力**，因为多个输入矩阵和累加器数据都要占用大量寄存器空间。专用矩阵单元使问题更严重：**整个输入与累加器矩阵分块必须存放在寄存器文件中，导致寄存器使用量上升、内核占用率下降，甚至把寄存器溢出到栈内存**。对 CUTLASS GEMM 的测量也表明，高寄存器使用量显著限制了 warp 占用率。INTERPRET、Duplo 等工作试图减少寄存器文件中的重复数据，以缓解容量约束。

其次，寄存器文件还带来**2. 带宽约束**。Volta 执行 Tensor Core 操作时**已经把可用寄存器读取带宽用满；扩大操作规模就需要增加寄存器文件带宽**，给设计带来重大挑战。

因此，核心耦合矩阵单元通常只能支持细粒度操作。例如 NVIDIA MMA 对 FP16 支持 `16×8×16`，AMD CDNA2 MFMA 支持 `16×16×16` 和 `32×32×8`。小分块复用有限，导致更多后备存储器数据传输；同时还要处理大量指令并计算额外分块地址，使指令调度逻辑、ALU 和寄存器文件等矩阵单元之外的部件消耗大量功率与能量。

> **容量压力：** 频繁溢出，利用率下降； **带宽压力：** 现已饱和，要增大mma规模，必须增加带宽—>于是只能细粒度操作—>于是频繁传输数据、频繁处理指令

### 2.4 最新进展与剩余挑战

**Ampere** 的 Asynchronous Data Copy 用硬件**把数据从全局内存直接搬到共享内存，绕过核心寄存器文件**。卸载数据复制后，寄存器和指令槽等核心资源可以更高效地用于矩阵操作；数据移动还能与计算异步重叠。作者对 CUTLASS 的分析发现，启用异步复制的 GEMM 内核 warp 停顿减少 36%，指令槽利用率提高 22%。

**Hopper** 的 `wgmma` 进一步允许 **Tensor Core 直接从共享内存读取矩阵操作数**，减少对寄存器文件的依赖。表 1 中寄存器使用量的明显下降，使 Hopper 能继续增加 MAC 数。

然而，Hopper 仍没有彻底解决寄存器压力和能源效率问题。`wgmma` 虽然减少了部分寄存器负载，但**仍把部分和矩阵累加回寄存器文件**，产生显著压力；Tensor Core 也仍与 SIMT 核物理耦合，使**多个核心之间不能共享矩阵单元的数据**。

Virgo 完全把矩阵单元从 SIMT 核中物理分离，在集群层面设为独立实例。它让操作数和累加器都绕过核心寄存器文件，前者直接访问共享内存，后者存入独立、节能的累加器存储器；统一矩阵单元还可最大化处理单元之间的数据复用。

> **Ampere：** 片外global到片内shared、异步传输交叠隐藏延时，但还是要寄存器、无法跨core共享数据； **Hopper：** 直接从shared读数据，绕过reg，但累加还是需要寄存器、没能解决跨core共享数据

### 2.5 术语与建模

| 术语 | 本文含义 | 对应设计 |
| --- | --- | --- |
| 紧耦合矩阵单元 | 矩阵单元位于 SIMT 核内，操作数和结果都严重依赖寄存器文件 | Volta 风格 |
| 带专用 DMA 的紧耦合矩阵单元 | 仍与核心耦合，但由独立 DMA 高效搬运片外到片上数据 | Ampere 风格 |
| 操作数解耦矩阵单元 | 从共享内存直接读取操作数，但矩阵单元仍属于 SIMT 核 | Hopper 风格 |
| 物理分离矩阵单元 | 矩阵单元完全脱离 SIMT 核，在集群外部集成 | Virgo |

### 3 Virgo 微体系结构

如图 2 所示，Virgo 旨在将专用矩阵单元从核心中分离出来，作为集群层面的独立硬件，从而提高可扩展性与能源效率。为了实现这一设计，需要解决若干微体系结构层面的挑战：

1. 建立核心与矩阵单元之间进行通信的**命令接口**；
2. 设计**集群本地共享内存互连**，高效处理核心与矩阵单元的并发访问；
3. 通过**专用 DMA 引擎**实现更高效的矩阵数据移动；
4. 实现跨核心及矩阵单元的**同步机制**。

后续各小节将详细讨论这些组成部分。在此之前，先介绍本文在 RTL 实现中使用的关键开源硬件基础设施。首先，本文使用 **Vortex** [42]。Vortex 是一种使用 SystemVerilog 实现的开源 GPGPU，它通过扩展 RISC-V ISA，支持从硬件到内核开发的完整技术栈。其次，本文使用脉动阵列生成器 **Gemmini** [21]，为 Virgo 生成基于集群的矩阵单元 IP。第 5 节将进一步说明如何修改这些 IP，以构建完整的 GPU 系统。

![](https://picx.zhimg.com/v2-a8d535ae9330ec9d752c9e82c6c3928d_r.jpg)

**如图（图 2）：** Virgo 把基于 Gemmini 的矩阵单元作为集群内独立硬件；虚线模块是评估时可选实例化的核心耦合 Tensor Core。系统需要解决命令接口、异构共享内存访问、高效 DMA 数据移动和集群级同步四项问题。

RTL 实现以两项开源基础设施为基础：Vortex 是用 SystemVerilog 实现、扩展 RISC-V ISA 的开源 GPGPU；Gemmini 是用于生成 Virgo 集群级矩阵单元 IP 的脉动阵列生成器。“Virgo”一名也来自 Vortex 与 Gemmini 的组合。

### 3.1 矩阵单元命令接口（问题一）

Virgo 使用集群本地互连建立核心与矩阵单元之间的 **MMIO 命令接口**。该方案不要求修改 ISA 或核心微体系结构：内核只需对特定地址区间执行普通加载和存储，即可控制矩阵单元；同时，MMIO 寄存器通过轻量级集群本地 NoC 连接，仍具有低访问延迟。

实现时，作者把 Gemmini 原有的 RoCC 接口替换为映射进共享内存地址空间的控制寄存器。软件通过轮询表示加速器忙闲状态的寄存器，使核心线程与 Gemmini 操作同步。执行 GEMM 时，**Gemmini 内的硬件状态机自动遍历 `m`、`n`、`k` 维度，一次调用即可完成大于脉动阵列尺寸的矩阵。状态机从共享内存取操作数，控制脉动阵列，并把结果写入累加器存储器**。

### 3.2 内存系统

Virgo 内存系统必须同时处理核心和矩阵单元对共享内存的异构并发访问，并从全局内存高带宽地取得矩阵数据。

### 3.2.1 共享内存（问题二）

Gemmini 矩阵单元产生宽度为 `4n` 字节的访问，其中 `n` 是脉动阵列维度；SIMT 核的各 lane 则发出 4 字节访问。核心和矩阵单元还必须在不串行化的情况下**并发访问不同矩阵，以支持双缓冲生产者—消费者执行**。

![](https://pica.zhimg.com/v2-326805cb3fd2ad83b82b2b7341b735be_r.jpg)

**如图（图 3）：** Virgo 的共享内存互连采用以下设计：

- **二维Bank：** 地址空间同时**划分为 bank 和 subbank**，使 SIMT lane 可跨 subbank 并行，矩阵单元和核心则可跨 bank 并行。 >(只是提供了更多端口？原先n个串行–>现在用subbank并行；以及方便SIMT读写分离？)
- **统一请求粒度：** 宽矩阵请求被拆成多个字大小子请求，分发至同一 bank 的不同 subbank。核心与矩阵单元冲突时优先服务宽矩阵请求，并在同一周期处理全部子请求。
- **读写路径分离：** 核心发出的读写请求进入独立通道，返回方向再合并，从而支持**生产者与消费者并发**。 >（针对后文）
- **非对齐 SIMT 访问的面积优化：** 不建立从所有 lane 到所有 subbank 的巨大交叉开关，而是筛出非字对齐请求，在进入交叉开关前先串行到一个 lane。被测矩阵搬运大多字对齐，因此影响很小。

> 核心：读写分开、对齐与非对齐分开？

互连使用 TileLink 协议与 Diplomacy 参数协商框架。RTL 综合结果中，共享内存占 SoC 面积 5.5%、功耗 6.8%；与不支持 Gemmini 连接的基线相比，面积只增加 9.6%。

### 3.2.2 累加器存储器

Virgo 的分离式矩阵单元有专**用 SRAM 存储累加矩阵数据**，理由有二。

第一，大容量累加数据不会影响内核并行度。**GPU 寄存器文件按 warp 私有化；核心耦合 Tensor Core 经由 SIMT 寄存器累加并返回结果，因此扩大矩阵单元会增加每 warp 寄存器使用量、提高压力并降低占用率**，尤其会伤害还需执行激活计算的融合 DNN 内核。独立累加器存储器把寄存器压力与矩阵计算规模解耦。

第二，累加数据访问规则，能采用更简单、更节能的存储器。**寄存器文件必须支持发散的 SIMT scatter-gather 访问，而矩阵单元对累加数据是宽且连续的访问**。Virgo 因而使用单 bank SRAM，降低复杂度和每次访问能耗。

### 3.2.3 内存合并器

内存合并**把标量 SIMT 访问转换为宽向量访问**，是获得高有效内存吞吐量的关键。Vortex 原先缺少硬件内存合并，严重限制 SIMT 加载/存储带宽。作者实现的合并器监视核心与 L1 缓存接口之间的 SIMT 访问，伺机把它们合并成与 L1 缓存行同宽的请求，大幅提高从 DRAM、L2、L1 向核心供数的速率和矩阵单元利用率。该合并器用于依靠 SIMT 指令而非 DMA 搬运数据的 Volta 风格配置。

### 3.2.4 使用 DMA 高效移动数据（问题三）

Virgo 还加入**专用 DMA**。Ampere 用 Asynchronous Data Copy 在全局内存与共享内存之间直接搬运，Hopper 的 TMA 则支持灵活的地址生成。本文的 Ampere、Hopper 基线与 Virgo 都在集群内放置 MMIO 可编程 DMA，用于**全局内存和共享内存之间的直接访问**；在 Virgo 中，该 **DMA 还可直接读取矩阵单元的累加器存储器**。

### 3.3 集群级同步（问题四）

集群内 SIMT 核会协作搬运矩阵数据，或对矩阵单元输出做后处理，因此需要跨核心同步。Virgo 在集群内设计**轻量级同步器**，与每个 SIMT 核的 warp 调度器连接。**指定 warp 执行屏障指令时，调度器向同步器发送释放请求；同步器收集其他核心的请求，确认所有相关核心到达屏障后统一响应**。Virgo 复用 Vortex 的 `vx_bar` 指令，让程序员选择参与特定屏障的 warp，并允许内核使用多个屏障。

### 4 Virgo 编程模型

由于矩阵单元在体系结构上与核心分离，它在 Virgo 中作为独立于 SIMT 核的执行线程运行。编程模型遵循两项原则：异步编程接口，以及多个 warp 的协作执行。

### 4.1 异步矩阵单元接口

**核心对矩阵单元 MMIO 接口的访问是非阻塞的**。单个 SIMT warp 可启动矩阵操作，然后继续执行后续指令而不暂停。因此，warp **可在长延迟矩阵操作期间，把下一分块的数据移动或上一结果的激活后处理与之重叠，利用指令级并行**。

现代 GPU 中也有异步矩阵单元，但若没有这种机制，SIMT 核只能依靠多个 warp 的多线程隐藏矩阵延迟，要求高 warp 占用率并让调度器始终有可发射 warp。Virgo 的单 warp 异步接口提供更多延迟隐藏机会；更大的分块也使计算延迟更适合被重叠。

![](https://pic1.zhimg.com/v2-969399c5d097017dea498bcae345fc9a_r.jpg)

**如图（图 4）：** Tensor Core 方案需要各 warp 反复把共享内存数据送入寄存器文件，再发出细粒度 GEMM；Virgo 可让矩阵单元连续执行并累加，同时 DMA 预取下一分块、SIMT 核处理上一输出，从而形成软件流水线。

> SIMT core被解放出来，可以用于激活层计算

### 4.2 Warp 协作执行

GPU 上的 GEMM 需要核心与矩阵单元紧密协调：核心负责片外到片上数据移动，或对结果执行非线性激活等后处理。因此，SIMT 核吞吐量必须与矩阵单元匹配。**Virgo 让多个 warp 共同参与一次矩阵单元操作。例如图 4 中，线程块的所有 warp 一起激活矩阵单元先前计算的 `(M,N)` 输出分块**。由于这些 warp 可能运行在不同核心，执行依赖第 3.3 节的集群级同步。

> 别的架构不行？还是说现在可以同时进行，不需要考虑掩藏延时

### 4.3 API 设计

Virgo API 分为直接暴露硬件启动与同步机制的低层接口，以及帮助表达 GEMM 的高层库。

- `virgo_dma_{load,store}`：启动异步 DMA，在全局内存、共享内存和矩阵单元累加器存储器之间复制分块。参数包括基地址、矩阵维度与内存布局。
- `virgo_compute`：启动异步矩阵乘加，从共享内存读取分块。
- `virgo_fence`：阻塞当前 warp，直到此前所有异步操作完成且结果可见。

这些调用配合集群级屏障，保证参与计算的所有 warp 相对矩阵操作正确同步。

高层库由 C++ 模板构成：给定 GEMM 维度常量后，在编译期实例化专用内核并展开 `(M,N,K)` 循环。程序员可直接调用设备级 GEMM，或编写含 GEMM 的融合内核，不必关心数据如何映射到矩阵单元。与 Composable Kernel、CUTLASS 类似，它在硬件相关分块操作之上构建 API；区别是 Virgo 的不可再分计算原子是线程块/工作组级矩阵乘法，而其他库把细粒度操作映射到 warp 级原子。较大计算单元可改善调度并减少核心指令开销，但会牺牲对小矩阵的灵活性。

### 4.4 GEMM 内核映射

### 4.4.1 线程块分块

传统 GPU GEMM 会在多个层级对输入矩阵分块，以利用不同存储层次的数据复用。**Virgo 的矩阵单元加速第一级线程块分块，利用集群间并行并把分块缓存在共享内存；Tensor Core 则加速第二级 warp 分块**。

当前配置中，一次矩阵单元操作的分块大小为 `128×64×128`，它也决定线程块大小。各线程块沿 `(M,N)` 输出空间划分，并在循环中沿 `K` 维时间累加完成完整 GEMM。Gemmini 将部分和保存在私有累加器存储器，循环结束后写回全局内存，再处理分配给该线程块的下一个 `(M,N)` 输出分块。多个线程块可均分输出空间。

### 4.4.2 软件流水线与双缓冲

Virgo GEMM 使用异步编程接口构成软件流水线：

- **矩阵单元**：计算当前 K 分块 **（消费者流水线）**
- **DMA 或一组 SIMT warp**：**预取下一个 K 分块** **（生产者流水线）**
- **另一组 SIMT warp**：处理**上一结果分块的激活** **（额外消费者流水线）**
- **共享内存**：对并发生产/消费的分块执行**双缓冲**

这样，SIMT warp 与矩阵单元始终有有效工作，最大化集群内各硬件部件利用率。

### 4.5 映射 FlashAttention-3

FlashAttention-3 融合 Transformer 自注意力层，并定义三条可重叠流水线：`Q·Kᵀ` 的 GEMM-1、`P·V` 的 GEMM-2，以及 softmax。Virgo 把两个 GEMM 依次映射到矩阵单元，把 softmax 映射到 SIMT 核，使其并发执行。GEMM 与 softmax 存在生产者—消费者关系，因此使用 fence 和集群级屏障维持顺序，并在共享内存中双缓冲中间分块。

![](https://pic4.zhimg.com/v2-f7d0a5ecadbe35bbb8e9a70b49e16fe9_r.jpg)

**如图（图 5）：** 两个 GEMM 在矩阵单元上流水执行，softmax 的最大值、逐元素指数、求和与缩放在 SIMT 核上并行完成；DMA 同时搬运后续分块。循环间只在必要位置执行 fence 与屏障。

简化伪代码如下：

```text
for (int iter = 0; iter < tiles; iter++) {
  virgo_fence(0);
  threadblock_barrier();
  smem_Pp = (iter % 2) ? smem_P0 : smem_P1;
  smem_Pc = (iter % 2) ? smem_P1 : smem_P0;
  virgo_compute(gmem_Pc, smem_Vc, smem_O, 1); // GEMM-2: O += P*V
  virgo_compute(smem_Qc, smem_Kc, smem_Sp, 0); // GEMM-1: S = Q*K^T
  virgo_dma_load(gmem_K, gmem_V, smem_Kp, smem_Vp, ...);
  online_softmax(smem_Sc, smem_Pp, per_row_scale, ...);
  virgo_fence(2);
  row_rescale(smem_O, per_row_scale);
}
virgo_fence(0);
virgo_dma_store(gmem_O, smem_O);
```

由于 GEMM-2 与 softmax 都访问同一激活分块 `smem_O`，需要额外 fence；它只等待 GEMM-2 完成，不阻碍后续操作。

### 4.5.1 同步开销

作者测量 `virgo_fence` 忙状态轮询循环，平均耗时 260 周期，占总运行时间 2.4%。其余周期中矩阵操作与 SIMT 计算重叠，说明内核确实利用了指令级并行。同步开销还取决于流水线匹配程度：实验中 softmax 略早于 GEMM 完成；若矩阵计算先结束，等待可能更少。

### 5 方法

### 5.1 基线 GPU 设计

### 5.1.1 Volta 风格紧耦合设计

Volta 风格把**矩阵单元紧耦合到核心寄存器文件**。实现参考 NVIDIA GPU 的微体系结构：多个 SIMD 并行点积单元以树形归约执行分块 MAC；输入分块经核心流水线从寄存器文件送入，结果也写回寄存器文件。

作者扩展 Vortex RISC-V ISA，以类似 Volta HMMA SASS 的指令控制矩阵单元。单个分块操作被拆成更细的 `set` 与 `step` 指令。Vortex SIMT 宽度为 8，而 Volta 为 32，因此每个点积单元只实例化 1 个八元组而非 4 个。每 warp 有 1 KiB 寄存器空间，可放下两个 `8×16` FP16 操作数和一个 `8×8` FP32 累加器，故分块为 `(8,8,16)`。寄存器读取带宽把每单元 FP16 MAC 数限制为 32；每条 HMMA step 用 2 周期，Tensor-to-SIMT FLOPS 比为 4:1。

### 5.1.2 带 DMA 的 Ampere 风格紧耦合设计

Ampere 基线使用与 Volta 相同的紧耦合矩阵单元，并额外实例化**专用 DMA**。公开资料没有明确说明 Ampere 是否有与 Hopper 类似的独立 DMA；本文这样建模是为了单独评估数据移动卸载的影响，并逐步加入 Hopper 的操作数解耦。

### 5.1.3 Hopper 风格操作数解耦设计

Hopper 风格允许矩阵单元**直接访问共享内存中的操作数，但累加器仍从寄存器文件读写**。作者把 Volta 风格实现扩展成解耦访问/执行体系结构。

![](https://pic2.zhimg.com/v2-ef04ace09c1bc46e3e7b7b88ac49b8e1_r.jpg)

**如图（图 6:解耦 Tensor Core 的微架构，它模拟了 NVIDIA Hopper 将操作数存储与共享内存解耦的集成方案 [10]。解耦的访问/执行架构有效地将共享内存的访问延迟与计算重叠）：** 访问前端的状态机与地址生成器提前发出共享内存读请求；执行后端用 FIFO 和操作数缓冲区暂存响应，数据就绪后执行 MAC。地址静态确定，因此访问可跑在执行之前，隐藏共享内存延迟。

作者通过模拟 `wgmma` PTX 的 ISA 扩展提供异步接口：warp 用 initiate 指令启动矩阵单元而不暂停，之后用 wait 同步并取得结果。操作数卸载缓解容量限制，但累加器仍占寄存器，因此每 warp 的 1 KiB 空间最多容纳一个 `16×16` FP32 累加分块。`k` 维没有数据复用，故最大分块为 `(16,16,32)`。共享内存带宽把吞吐量限制为每周期 64 个 FP16 操作，Tensor-to-SIMT FLOPS 比为 8:1。该设计也带专用 DMA。

### 5.2 系统实现

作者广泛修改多项开源硬件基础设施。顶层使用 Chipyard SoC 生成框架集成 Vortex SIMT 核、矩阵单元、共享内存、缓存与互连；核心和集群数量、矩阵单元尺寸与数据类型、内存总线宽度等均可参数化。

**Vortex SIMT 核。** 使用 Vortex `vx_core` 构建集群和同步机制，并把 cache bank 调整为位于内存合并器之后的 L1。还修改核心流水线以提高指令与内存吞吐，包括存储 fencing、warp 调度和同步，并加入 Tensor Core。

**基于 Gemmini 的矩阵单元。** 修改 Gemmini，使脉动阵列直接连接集群级共享内存。Virgo 保留累加器存储器以维持满吞吐的单周期累加，但把暂存接口改为经 TileLink 连接共享内存互连。SIMT 核因此可直接把数据写入 Gemmini 使用的共享内存。

### 6 评估

### 6.1 GEMM 内核

| 设计 | 256×256×256 | 512×512×512 | 1024×1024×1024 |
| --- | --- | --- | --- |
| Volta 风格 | 25.6% | 30.3% | 30.3% |
| Ampere 风格 | 37.5% | 45.6% | 52.3% |
| Hopper 风格 | 60.5% | 72.8% | 77.0% |
| Virgo | 66.1% | 77.9% | 86.5% |

**表 3：** GEMM 内核的 MAC 利用率。

### 6.1.1 GEMM 性能

Virgo 在三种 GEMM 上都取得更高 MAC 利用率，主要原因是**增大操作粒度、减少核心流水线必须执行的辅助指令**。Volta 风格的 `8×8` 小分块要求更多 Tensor Core 指令，还需加载与地址生成指令，最终受 SIMT 核指令吞吐量限制。

Hopper 风格通过扩大分块、用微体系结构状态机驱动操作、自动从共享内存取操作数来减少指令。Virgo 再把分块扩大到 `128×64×128`。其退役指令数只有 Volta 风格的 0.5%、Hopper 风格的 8.0%。

### 6.1.2 GEMM 功率与能耗

![](https://pic4.zhimg.com/v2-9400b11fe4e81824d453b245de84ac55_r.jpg)

**如图（图 8）：** 相对 Ampere、Hopper，Virgo 活动功耗分别降低 **67.3%**、**24.2%**。Ampere 功率高于 Volta，是因为 DMA 改善供数后硬件利用率更高。

![](https://pic2.zhimg.com/v2-32662e6ce42dd7118bfa691eaffeb6bd_r.jpg)

**如图（图 9）：** `1024×1024` GEMM 的 SoC 分项功耗显示，Virgo 的**大部分节省来自 SIMT 核，而非矩阵单元本身**。

![](https://pica.zhimg.com/v2-3ad7fdbc52f777a596a4b569750d972c_r.jpg)

**如图（图 10）：** 核心内部功耗下降**主要发生在发射和 ALU 阶段**。更少的动态指令调度降低记分牌、warp 调度器与寄存器访问功耗；更大分块减少地址生成指令。

Volta 风格要从寄存器文件取得矩阵操作数；Hopper 与 Virgo 直接访问共享内存。Hopper 仍从核心寄存器文件读写累加器，Virgo 则把累加器放入单 bank SRAM，并在脉动阵列网格内部完成部分累加。

![](https://pic2.zhimg.com/v2-204fe1876c01f75b9c87a40dd901a881_r.jpg)

**如图（图 11）：** 几种设计的处理单元能耗相近。**Virgo 的主要节能来自大粒度和操作数/累加器卸载**，而非某一种矩阵单元内部结构。

### 6.1.3 共享内存中的数据复用

| 设计 | 分块片段 | 矩阵单元组织 | SMEM 读取量 | 归一化 |
| --- | --- | --- | --- | --- |
| 紧耦合 | 8×8 | 每核心 | 6 MiB | 2.67 |
| 操作数解耦 | 16×16 | 每核心 | 4 MiB | 1.78 |
| 物理分离 | 16×16 | 每集群 | 2.25 MiB | 1.00 |

Virgo 把多个每核心矩阵单元统一成一个集群级实例，避免不同 Tensor Core 重复读取同一输入行或列。Volta/Ampere 必须把共享内存带宽扩为 2 倍，否则利用率受限；Virgo 无需更高带宽即可达到最佳利用率，共享内存活动能耗比操作数解耦设计低 41.0%。

### 6.2 FlashAttention-3 内核

Ampere 基线把每核心 8 个 warp 分成两组，交替调度 GEMM 和 softmax。Virgo 的总 MAC 利用率为 **65.7%**，Ampere 为 **35.1%**。矩阵计算卸载后，warp 可把指令槽和寄存器空间用于 softmax；紧耦合矩阵指令则与 softmax 争夺发射槽和寄存器端口。

![](https://pic3.zhimg.com/v2-e8fed716a7aca9e9dc54da8b11ff6ab2_r.jpg)

**如图（图 12）：** Virgo 通过更大操作粒度和数据卸载降低核心功率；虽然高利用率矩阵单元功率上升，但总运行时间缩短，最终总能耗比 Ampere 低 **50.6%**。

### 6.3 多个异构矩阵单元

作者在一个集群中集成大小不同的两个单元，把 `256³` GEMM 映射到大单元、`128³` GEMM 映射到小单元。两个 GEMM 并行时利用率为 59.5%，分别串行时为 59.7%；按 FLOP 归一化的活动功率只增加 4.3%，表明 Virgo 具有良好扩展性。

### 7 结论

Virgo 在集群层面集成矩阵单元。通过把矩阵单元从核心流水线物理分离，它克服了现有核心耦合 GPU 的可扩展性和能源效率限制。可综合 RTL 的实现与评估表明，Virgo 显著改善 GEMM 的功率与能源效率；解耦体系结构和编程模型还能高效映射融合 DNN 内核。
