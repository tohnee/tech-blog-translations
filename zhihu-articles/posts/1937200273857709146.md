### 背景

30 人的机器人公司，5 人的算法团队，传统的视觉模型需要迭代，缺乏工程化的流程

### 什么是 MLOps

![](https://pic4.zhimg.com/v2-c1fa2b2f9148b5907353cb29d60c3f81_r.jpg)

MLOps 是位于 ML、DevOps &数据工程之间的交叉点的一套实践，其目的是在生产中可靠有效地部署和维护 ML 系统从而提供模型迭代的效率

### 目标

集成开源工具，工程化模型迭代流程，提高效率

### 组件

### Label Studio

[https://github.com/HumanSignal/label-studio/](https://github.com/HumanSignal/label-studio/)<br>标注平台

### FiftyOne

[https://github.com/voxel51/fiftyone](https://github.com/voxel51/fiftyone)<br>数据集管理工具，最常用的功能是将多个数据集合并

### MLflow

[https://github.com/mlflow/mlflow](https://github.com/mlflow/mlflow)<br>用来做模型训练的管理，查看训练相关指标

### Code-server

[https://github.com/coder/code-server](https://github.com/coder/code-server)<br>VS Code in the browser，用来做配置文件的编辑，省去了大量的前端开发量

### Glusterfs

[https://github.com/gluster/glusterfs](https://github.com/gluster/glusterfs)<br>分布式文件系统，存放数据集、训练配置、模型、任务日志、训练产物等

```bash
/mnt/glusterfs
  ├── config/
  ├── datasets/
  ├── models/
  └── tasks/
        └── {taskId}/
                ├── config/
                ├── logs/
                └── artifacts/
```

### docker-py

[https://github.com/docker/docker-py](https://github.com/docker/docker-py)<br>Docker SDK，用来管理训练容器<br>不同类型的训练任务触发不同的训练容器，容器里的训练脚本集成了 MLflow，训练日志会存到 /mnt/glusterfs/tasks/{taskId}/logs 目录下，通过 MLOps server 提供给用户查看

### 飞书 SDK

[https://github.com/larksuite/oapi-sdk-python](https://github.com/larksuite/oapi-sdk-python)<br>用来在流程的关键节点发送通知，如训练任务开始，训练任务完成

### MLOps server

待捯饬好后放到 github 上<br>基于 [https://github.com/fastapi/fastapi](https://github.com/fastapi/fastapi) 构建<br>通过 Label Studio, FiftyOne, MLflow 等SDK，将流程串联起来，提供 API 给前端

### 扩展

- 引入 DVC 进行数据集版本管理
- 支持模型部署，将目标模型转成 engine，推送至目标设备
