### （一）GPU 上的内存层次与计算链路

在理解 FlashAttention 之前，先搞清楚 GPU 上“算一次矩阵乘法，数据实际上是怎么流动的”。

- **HBM（High Bandwidth Memory）**<br>

- **SRAM（片上存储：寄存器 / Shared Memory / L1/L2 Cache）**<br>

因此，一次典型的 GPU 计算（比如一次 GEMM）可以抽象为如下链路：

- **数据计算链路（抽象）：**

HBM → SRAM → 计算单元 → SRAM → HBM

含义是：

1. 从 HBM 中把一小块数据（tile / block）加载到片上 SRAM 中；
2. 在 SRAM 中反复复用这块数据做大量乘加计算（算得越多越“值”）；
3. 将中间或最终结果再写回 HBM；
4. 然后换下一块 tile，如此反复。

**核心约束：**

- HBM 能装下“全局大矩阵”，但访问贵；<br>
- SRAM 够快但太小，只能装下“小块矩阵”，所以所有大规模矩阵运算都必须拆成一个个 tile，在 SRAM 内局部计算完再回写 HBM。

FlashAttention 的关键，就是想办法让 Attention 的所有步骤都能尽可能在小 tile 上完成，**避免产生一个完整的 $(L, L)$ 级别的中间矩阵常驻 HBM 或被反复读写**。

### （二）标准 Attention 回顾

为了简化分析，我们先去掉 batch size 和 head num，只保留序列和特征维：

- **记号与维度：**<br>

- **Scaled Dot-Product Attention：**

$$ S = \frac{QK^\top}{\sqrt{D}} \quad (\text{形状 } L \times L) $$

$$ P = \text{softmax}(S) \quad (\text{对每一行做 softmax，形状 } L \times L) $$

$$ O = PV \quad (\text{形状 } L \times D) $$

其中：

- $S$：每一行对应一个 query 对所有 key 的打分；
- $P$：对每一行做 softmax 后得到的注意力权重；
- $O$：加权求和后的输出。

在数学上没什么问题，但在 GPU 上实现时，如果“老老实实”把整个 $S$ 计算出来并存进 HBM，再去做 softmax，就会立刻遇到 IO 和显存的问题。

---

### 朴素实现 Attention 时的 IO 模型

我们仍然只分析单个 head 的情况，忽略 batch/head 维度，只看 (L, D)。<br>重点看三步：

1. 计算 $S = QK^\top / \sqrt{D}$
2. 对 $S$ 做行 softmax，得到 $P$
3. 计算 $O = PV$

其中第 1 步和第 3 步本质上都是矩阵乘法（GEMM），天然可以拆成小块在 SRAM 中做局部计算，然后把结果逐步写回 HBM——这部分在现代 GPU 上相对“友好”。

**真正棘手的是第 2 步 softmax**：

- 标准做法会先把完整的 $S$（形状 $L \times L$）生成并存到 HBM；
- 然后为了对每一行做 softmax，需要反复访问整个 $S$ 的所有元素；
- 当 $L$ 很大时，$S$ 的尺寸是 $L^2$，远远装不进 SRAM，只能放在 HBM 中，被反复读取。

---

### 朴素 softmax 的两遍扫描实现及 IO 开销

为了说明问题，我们假设：

- 整个 matrix $S$ 存在 HBM 中；
- 我们先对每一行做 softmax，但**遍历顺序按“列”来写伪代码**（前缀和，方便并行）；
- 为了计算 softmax 的分母，我们维护一个长度为 $L$ 的向量 $d$，其中 $d[i]$ 存储第 $i$ 行的 softmax 分母；
- **重要假设**：向量 $d$ 可以完全保存在 SRAM 里（例如寄存器/Shared Memory），所以对 HBM 的读写次数关于 $d$ 是 $O(L)$ 量级，可以忽略不计。

### 伪代码（不考虑数值稳定性）：

```text
# S 存在 HBM 中，形状为 (L, L)
# d 存在 SRAM 中，是长度为 L 的向量，初始为 0
d = zeros(L)  # d[i] 是第 i 行 softmax 的分母

# 第 1 遍：读取 S，计算d
for j in range(L):  # j 是列索引
    # 从 HBM 读入 S 的第 j 列，一个长度为 L 的向量
    S_col = load_S_column_from_HBM(j)      # IO: 读取 L 个标量

    # 在 SRAM 中更新 d：对每一行 i，累加 exp(S[i, j])
    d += exp(S_col)                        # 纯片上计算，无需访问 HBM

# 第 2 遍：再次读取 S，同时写出 P
for j in range(L):
    S_col = load_S_column_from_HBM(j)      # IO: 再次读取 L 个标量

    # 在 SRAM 中计算第 j 列的 softmax 结果
    P_col = exp(S_col) / d                 # 纯片上计算

    # 将第 j 列结果写回 HBM
    store_P_column_to_HBM(j, P_col)        # IO: 写 L 个标量
```

> 说明：这里为了直观，用了两遍扫描 S 的形式；如果考虑数值稳定性，通常会先算每行最大值，再算分母，但依然需要对 S 做一到两遍扫描，IO 量级不变。我们一般会称之为safe softmax

### IO 开销分析（只看和 HBM 之间的标量读写）

- **读 S 的第 1 遍：**<br>
- **读 S 的第 2 遍：**
- **写 P：**
- **读/写 d：**

**因此，总体的 HBM IO 量级为：**

- 读取 $S$：$2L^2$（两遍）
- 写入 $P$：$L^2$
- 读写 $d$：$O(L)$（可忽略）

合计约为：

$$ \text{IO} \approx 3L^2 + O(L) $$

**IO 开销是 $L^2$ 量级的，当 $L$ 很大时，这在显存和带宽上都是巨大的压力**。

回顾三个步骤：

1. $S = \frac{QK^\top}{\sqrt{D}}$：是一个 $(L \times D)$ 乘 $(D \times L)$ 的矩阵乘法；
2. $P = \text{softmax}(S)$：每一行都依赖整行的所有元素；
3. $O = PV$：是一个 $(L \times L)$ 乘 $(L \times D)$ 的矩阵乘法。
