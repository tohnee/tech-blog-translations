## 前言

当前Megatron线上包含两个FSDP的实现，分别对应custom_fsdp和torch_fsdp2。这次主要分析一下两者的代码，看下两者的差异。

抽象来讲，所有框架在实现zero3时，一般可以分为以下几个步骤：（摘自：[GeTLeft：PyTorch FSDP源码分析](https://zhuanlan.zhihu.com/p/19366919145)）

1. **初始化**：接受一个模型，将模型的参数(params)进行切分(shard)，每个rank得到切分过的参数(sharded params)。
2. **前向**：每个rank读入各自的训练数据，将sharded params进行unshard(即all_gather，AG)，并进行前向(fwd)计算，计算完成后，将unsharded params进行reshard。
3. **反向**：将unsharded param进行AG，并进行反向计算(bwd)，反向计算完成后，将unsharded params进行reshard，并将梯度(grad)进行reduce scatter(RS)
4. **优化器step**：基于shard param、reduce scatter的grad，得到updated shard param。

## Custom_fsdp（FullyShardedDataParallel）

功能：实现对模型参数、梯度和优化器状态跨节点切片，可以无缝兼容megatron的TP和EP并行。

支持四种模式：no_shard（无切分）、optim（优化器切分）、optim_grads（优化器和梯度）、optim_grads_params（优化器、梯度和参数）

特点：（1）兼容Megatron的TP、CP和EP并行（2）支持混合精度训练；（3）梯度累加和分桶；（4）激活值重计算，当重计算时，一次性获取相关参数用于重计算和反向梯度计算；（5）兼容Megatron的分布式checkpoint

### __init__

```text
model = GPTModel(config)
model = FullyShardedDataParallel(
        config,
        model,
        ddp_config,
        fsdp_unit_modules = [TransformerLayer, LanguageModelEmbedding],
        ) 
```

fsdp_unit_modules: FSDP 的单元模块list。

### _init_fsdp_param_and_grad_buffer

1）初始化param和grad buffer

2）初始化reduce-scatter的pipeline

3）初始化all-gather的pipeline

### _register_fsdp_hooks

注册一些fsdp hooks，用于构建前言中的数据操作。包含：

1）pre_forward hook: 在前向之前，进行参数unshard化，执行all gather; 实现为：register_forward_pre_hook，对应的函数为_pre_forward

2) post_forward hook: 在前向之后，进行参数reshard，实现为：register_forward_hook，对应的函数为_post_forward

3) pre_backward hook: 反向之前，参数unshard化，执行all gather，实现为：register_full_backward_pre_hook，对应的函数为：_pre_backward

4) post_backward hook: 释放相关资源。实现：RegisterFSDPBackwardFunction，对应函数为：_post_backward

5) 梯度累加hook + reduce scatter：参数reshard，梯度reduce scatter，实现：register_hook，在梯度函数中添加hook：_make_param_hook

## ParamAndGradBuffer

针对DP域，管理参数分组、buffer分配和通信操作；这部分和DistributedDataParallel是极为相似的

功能：

1）基于参数类型和通信组大小，对参数进行分组

2）针对模型参数、梯度和高精度权重，创建连续的缓存

3）处理参数unsharding、梯度reduce和权重同步

4）支持混合精度训练

入参：

1）ddp_config

*2）*module：相关参数需要被分组处理的模型模块

3）bucketing_policy：分通策略

4）data_parallel_group： dp组

5）expert_data_parallel_group： EP组

6）preserve_fp32_weights： 是否保存fp32权重

7）grad_reduce_in_fp32： 是否使用fp32

8）device：buffer所在设备，比如host和device

9）only_create_grad_buffer_and_main_weight_buffer_for_param_requires_grad：是否只创建梯度buffer和针对相关梯度对应的主要权重buffer，默认是True

实现：

1）和Distributed Data Parallel一样，根据参数的执行顺序和特性分组，并分桶；

2）对每个参数group，分配buffer空间（模型参数、梯度和优化器参数），DataParallelBuffer，根据传入参数分配空间大小。分别对应：model_weight_buffer，main_weight_buffer， main_grad_buffer。注意：激活和梯度先不分配空间大小。init_meta_only 为True。

3）_init_optimizer_named_parameters，初始化优化器的命名参数

## AllGatherPipeline

用于all gather对应的参数

### queue_bucket_to_all_gather

执行异步全收集操作，将任务桶排队到一个专用队列（NCCL CUDA流）。该功能是FSDP（完全分片数据并行）的一部分。以基于队列的方式处理全收集操作的实现的方式。它不是立即执行all-gather，而是排队该操作进入任务队列，有助于管理系统资源和避免GPU内存和通信带宽过载。

自己实现了一个队列机制，用于all_gather通信。
