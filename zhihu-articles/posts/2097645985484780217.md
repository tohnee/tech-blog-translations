8 月，我给自己的多智能体系统做了一个对照实验：同样的任务，分别用 1 个、4 个、6 个 agent 来做，各跑 30 次。当时的结论很漂亮： **4 个 agent 最划算** ，比 6 个便宜一半，报告质量还明显好过 1 个。

10 月，我按同一份预注册方案、换了一个模型，又跑了一遍。结果：

- **成立的** ：4 个比 6 个省钱，两次都成立，这次更明显（token 少 60%，成本少 54%，耗时少 49%）。
- **反转的** ：“4 个 agent 的报告质量明显好过 1 个”没能复现，这次反而是 1 个 agent 的问题最少。
- **意外发现** ：6 个 agent 里负责审稿的那个，30 次里有 27 次第一次就没通过自己的格式校验。原因是一条只写在代码里、没写进提示词的限制。补上一句话，因为这条限制失败的次数从 21 降到 3。

![](https://pic3.zhimg.com/v2-d2a34f50ced1e5caae3f94f3acf14150_r.jpg)

如果我只发 8 月那次，这会是一篇“4 个 agent 最优”的漂亮文章，但它在另一个模型上不成立。下面把两次都摊开讲。

## 我在做什么

我在做一个开源项目：输入一篇论文或一个研究主题，输出一份“商业化初筛报告”。报告给技术成熟度（TRL）、制造成熟度、专利、市场分别打分，每个论断都要标出来源。它面向高校技术转移办公室、科研人员和早期投资人，只是初筛草稿，不是尽职调查。

系统分两步：先由普通代码检索论文、专利和市场资料，验证、去重后冻结成一份“来源登记表”；再由 6 个 LLM agent 只在这份登记表里干活。学术、专利、市场三个分析 agent 并行，然后依次是写报告、审稿、打分。

## 实验怎么设计

**先写预测，再花钱。** 跑任何付费实验之前，我把实验方案、判定标准和 4 个预测写成文档提交到仓库（预注册），防止自己看到结果后再调整标准：

- **P1** ：4 个 agent 的写手，第一次就通过报告格式校验的情况比 1 个 agent 多。
- **P2** ：6 个 agent 的报告里，“对不上来源的数字”不比 4 个的多。
- **P3** ：从 6 个砍到 4 个，成本和 token 至少下降 20%。
- **P4** ：1 个 agent 最便宜，但至少有一项质量指标输给 4 个。

**三组对照** ：1 个“全能型” agent 直接写报告；4 个是三个领域专家加一个写手；6 个是线上的完整流程，再加审稿和打分。三组读的是同一批冻结好的证据，用同一套报告格式要求和校验规则。10 个主题（从 CAR-T 细胞疗法到常温超导）× 每组 3 次 × 3 组 = 90 次运行，顺序按拉丁方轮换。

**先说明一点** ：证据是提前冻结的，实验里不检索、不调用搜索 API，所以下文的成本和耗时只算模型节点本身，比线上一次完整分析低得多。另外，只有完整版带打分 agent，所以分数不参与比较。

## 第一次：8 月，DeepSeek

90 次运行总共花了 1.80 美元，约 2.7 小时。当时的主要结果：

- **6 个 → 4 个** ：同主题配对比较，token 少 57%，成本少 47%，耗时少 38%，质量没输。
- **1 个 → 4 个** ：没标引用的论断从 115 处降到 24 处，成本是 1 个的 2.4 倍。
- **审稿 agent 几乎不改稿** ：中位数来看，最终报告保留了初稿 99.998% 的文字。后来做了一次盲评，两位评审在 9 对报告里各有 7 对更喜欢审稿后的版本，所以它不是没用，只是改得少。
- **P1 错了** ：4 个 agent 的写手第一次没通过格式校验 5 次，单体 1 次。

正式实验前，我花了不到 6 美分试跑，还发现记录“校验失败次数”的计数器一直是 0：框架内部调用的是另一个入口，计数器根本没挂上。修好之后才开始正式实验。

## 为什么要重跑

两个月后，线上换了模型，代码也改了很多。我想知道：8 月的结论，换个模型还成立吗？

于是我写了第二份预注册： **4 个预测和全部判定标准原样照抄** ，用同一批冻结证据，换成 qwen3.8-flash。需要说明，这是一个为了免费额度选的小模型，不是线上正在用的模型。

正式开跑前又踩了一个坑：离线检查发现，实验脚本在 4 个和 6 个 agent 组会 **一启动就报错** 。8 月之后，写手和审稿 agent 的提示词模板加了新变量，脚本却没有传入。修复只改了 3 行，并且先离线确认了问题，没有靠付费运行去发现。

这次 90 次运行记录花费 0.64 美元（按价目表上限计算，算上免费额度实际约 ¥3.4），用时约 3.3 小时，中途没有中断。

## 结果一：省钱的结论成立

![](https://picx.zhimg.com/v2-06170594bb3d561eca9231c3990c2255_r.jpg)

4 个比 6 个的配对降幅，8 月是 token 57%、成本 47%、耗时 38%；10 月是 **token 60%、成本 54%、耗时 49%** 。P3 两次都成立，而且这次省得更多。

6 个 agent 这次还多了一个问题：30 次只完成了 23 次。原因在后面的“结果三”。

## 结果二：质量的结论反转了

![](https://picx.zhimg.com/v2-461f91dad7327d66c8bcf18f19c3ef33_r.jpg)

8 月，没标引用的论断是 1 个 agent 115 处、4 个 24 处、6 个 38 处，拆分明显有效。10 月变成了 **39 处、166 处、115 处** 。按格式检查发现的问题做同主题配对比较，单体和 4 个 agent 的 30 对里，有 27 对是单体更好。P4 被证伪，P1 也又错了一次（这次三组都没有第一次就失败的情况）。

但这里有个坑，我是看到结果之后才发现的：

**8 月之后，线上写手的模板新加了一节“决策输出约定”** ，要求写明评估模式、决策负责人、成本和时间（或“未确定”）等。这类句子说明的是一种状态或缺失，本来就没有来源可引，却被筛查算成了“没标引用”。4 个和 6 个 agent 用的是今天的模板，单体用的还是 8 月的旧提示词，没有这一节。

把这类句子单独拿出来：4 个 agent 的 166 处里有 91 处是这种，6 个 agent 的 115 处里有 66 处。剩下的“其他句子”是 **单体 39 处、4 个 75 处、6 个 49 处** 。单体仍然最少，但差距从 4 倍多缩小到不到 2 倍。

另外，核查数字的规则 9 月也改过：系统识别不了单位的数字，现在会被算成“对不上来源”。所以这次的数字核查几乎没有参考价值。

结论是：质量上的反转，一部分来自模型，一部分来自模板，一部分来自尺子本身， **我没法把它们分开** 。

## 结果三：一句没写进提示词的话

![](https://pic4.zhimg.com/v2-b3b3e857c243d393a4899961f15167fd_r.jpg)

这次 6 个 agent 只完成 23 次，问题出在审稿 agent：30 次里有 27 次第一次就没通过自己的输出格式校验，7 次重试后仍然失败。按原因拆开：

- **修改理由超过 300 个字符** ：第一次失败 21 次，重试后仍失败 5 次。
- **修改条数超过 20 条** ：第一次失败 5 次，重试后没有再因为这个原因失败。
- **要替换的原文在稿子里出现不止一次** ：第一次失败 1 次，重试后仍失败 2 次（其中 1 次第一次是别的原因）。

审稿 agent 的提示词里写了“最多 20 条修改”“原文和替换文字不超过 2000 字符”， **唯独没写“理由不超过 300 字符”** ，这条限制只存在于代码的数据结构里。

于是我又单独预注册了一个小实验：只在提示词里补上这一句，其他全部不变，重跑同样的 30 次 6 个 agent（记录花费 0.36 美元）：

- 因理由超长而第一次失败：21 次 → **3 次**
- 第一次失败（任何原因）：27 次 → 6 次
- 重试后仍失败：7 次 → 2 次
- 成功完成：23 次 → 28 次

一个副作用：审稿 agent 每次的修改条数中位数从 9 条降到 5.5 条。是变谨慎了、长理由本来就伴随长修改，还是不同日子的波动，这次实验分不出来，也不能说改少了更好或更差。

顺带一提，同一个审稿 agent 在两个模型上判若两人：8 月它几乎不改稿，10 月它改了 241 处，最终报告保留初稿文字的中位比例是 99.17%。（线上版本里，审稿失败会退回到写手的原稿，报告照样交付；但那就是一次付了钱、什么都没改的审稿。）

## 这些结果说明不了什么

- **不能把差异归因于 agent 数量** ：两次之间，模型、供应商、写手模板、两套核查规则都变了，代码多了 669 个提交。
- **qwen3.8-flash 不是线上模型** ：线上 10 月 23 日用的是 qwen3.7-max-preview。这些结果不代表线上模型的表现。
- **两边的提示词不对称** ：4 个和 6 个 agent 用今天的提示词，单体用 8 月的旧提示词。
- **质量指标是程序筛查** ：只看有没有标引用、数字能不能在来源里找到，没有人工核验报告内容对不对，审稿 agent 的修改也没有逐条评判。
- **样本小** ：10 个主题 × 3 次，只能看效应大小，谈不上统计显著。

## 给同样在做 agent 的人四条建议

1. **数据结构里的每条限制，都要写进提示词。** 我们只补了一句话，因为理由超长而失败的次数就从 21 降到 3。
2. **重跑实验时，要锁住的不只是模型。** 提示词模板和核查规则也要锁住，否则结果变了，你分不清是谁导致的。
3. **先花一点钱试跑，先验证测量工具本身。** 8 月试跑发现计数器是坏的；10 月离线检查发现脚本一启动就会崩。
4. **预注册，然后两次结果都公开。** 只发对自己有利的那次，比什么都不发更误导人。
