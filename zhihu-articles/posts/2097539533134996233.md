# Claude Skills 生态全搜了一遍：真正值得装的 32 个（附全部 GitHub 链接）

大多数人还在把 Claude 当成一个更聪明的聊天机器人，而这场游戏的规则早就换了。

你真正的对手，是那些把 Claude 当成操作系统来用的人：你还在敲一次性提示词，对方已经堆好了专用技能、接上了 API、搭出一个 7×24 转的自动化流水线。

原文作者的说法是：懂不懂自定义技术栈，决定了你是 9.5 万美元的开发者，还是 30 万美元的 AI 架构师。他把整个 Claude skills 生态翻了一遍，替你省下这些时间。

![Claude Skills 生态一览](https://pic1.zhimg.com/v2-55ce0087406350ab11c996b29929808e_1440w.jpg)

## 二、Anthropic 官方 skills：4 个

官方仓库的价值不在功能多，而在于它给了「技能应该长什么样」的标准答案，照它的结构写不会跑偏。

![Anthropic 官方 skills 仓库](https://pica.zhimg.com/v2-5bfec01fc345cbf7536350301a500616_1440w.jpg)

### 1. doc-coauthoring

官方技能，带 Claude 走完「收集上下文 → 迭代打磨 → 用一个新的 Claude 会话做读者测试」这一整套。

- 为什么值得装：它把写作变成流程，而不是一次性提示词。
- 直链： [skills/doc-coauthoring/SKILL.md](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md)

### 2. skill-creator

Anthropic 自己写的「帮你造技能」的技能，按它规定的格式来。

- 为什么值得装：想做内部技能时，这是最正的起点。
- 直链： [skills/skill-creator/SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)

### 3. frontend-design

面向前端设计与界面实现的官方技能。

- 为什么值得装：你要的是 Claude 按界面系统来想问题，而不是拼一堆随机 UI 片段。
- 直链： [skills/frontend-design/SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)

### 4. docx

工作流会碰 Word 文档的话，这是最实用的官方技能之一。

- 为什么值得装：它教 Claude 可靠地拆开、编辑、再打包 DOCX。
- 直链： [skills/docx/SKILL.md](https://github.com/anthropics/skills/blob/main/skills/docx/SKILL.md)

## 三、Alireza Rezvani：把几百个技能打成一个操作层

这个仓库的特点是把大量技能和工具打包成一套宽泛的「操作层」，给所有兼容 Claude 的 agent 用。下面 11 个都出自 [alirezarezvani/claude-skills](https://github.com/alirezarezvani/claude-skills) 。

![Alireza Rezvani 的技能库](https://pic4.zhimg.com/v2-f8f7f766bffc13ae2777eaa98a2e157f_1440w.jpg)

### 5. skill-security-auditor

很 2026 的一个想法：用一个技能去检查别的技能，确认能信再用。

- 为什么值得装：技能经济在快速膨胀，安全审查已经是流程的一部分。

### 6. self-improving-agent

这类技能把 Claude 往「常驻操作者」推。

- 为什么值得装：系统开始改进自己的流程，而不是解完一个孤立任务就停。

### 7. mcp-server-builder

MCP 现在已经是生态里实打实的一层，这个技能教 Claude 照着它开发。

- 为什么值得装：外部集成更顺，胶水代码更少、更不容易碎。

### 8. rag-architect

严肃 agent 工作流里更值钱的模式之一。

- 为什么值得装：检索质量常常比模型本身有多聪明更决定结果。

### 9. observability-designer

从这里开始，Claude 是按基础设施工程师的思路在想问题。

- 为什么值得装：SLO、看板、告警、链路追踪会成为设计过程的一部分。

![Rezvani 库里的性能与发布类技能](https://pic4.zhimg.com/v2-adb876d0d846b40a298a879747fc1779_1440w.jpg)

### 10. performance-profiler

AI 写代码，不专门推一把的话往往不管性能。

- 为什么值得装：它教 Claude 关心瓶颈，而不只是功能能不能跑。

### 11. release-manager

一个意外实用的运维型技能。

- 为什么值得装：发布纪律是产品质量的一部分，不是事后补的东西。

### 12. tech-debt-tracker

大多数 AI 工作流默认每个代码库都是干净的，这个不装傻。

- 为什么值得装：它让 Claude 去推理技术债、优先级和长期维护。

### 13. capture

看起来简单，作用是零散想法变成结构化行动。

- 为什么值得装：日常 AI 操作系统里很好用的一环。

### 14. reflect

跟「输出速度」相反的那一半：复盘、综合、判断力。

- 为什么值得装：好系统需要反思回路，不只是执行回路。

### 15. email

邮件分诊听着无聊，除非你意识到多少真正的工作卡在里面。

- 为什么值得装：收件箱流程是让 Claude 在日常里「真的有用」最快的路子。

![Rezvani 库里的写作与邮箱类技能](https://pic2.zhimg.com/v2-d55e823079f348e7cd0c2b172ada0009_1440w.jpg)

## 九、真正有用的不是单个技能，是叠起来的组合

装一堆随机技能没用，关键是分层。「Jarvis」式组合按用途分成三套，原文给的是这样：

![三套 Jarvis 式组合](https://pica.zhimg.com/v2-262de612758ab6a0a31132aebdd8de20_1440w.jpg)

| 组合 | 成员 | 从成员看主要用在 |
| --- | --- | --- |
| Builder | doc-coauthoring、app-docs、research-skill、skill-creator | 产品文档、设计实现、前期研究 |
| Operator | connect-apps、file-organizer、claude-deep-research-skill、Apollo Automation | 跨应用执行、文件整理、线索挖掘 |
| Knowledge | Skill_Seekers、enhancing-authors、content-research-writer、wondelai skills | 文档转技能、资料补全、写作与业务知识 |

三套拆开看是同一个结构：一个记忆/研究角色，一个执行角色，再加一个产出角色。

![组合起来才是完整的工作流](https://pic1.zhimg.com/v2-4230eeb76de62781f45d39a7002f4368_1440w.jpg)

## 十一、我把哪些东西核了一遍

这篇是整篇翻译，原文的 32 个条目、所有链接和分节都保留了。核验结果如下，方便你自己判断：

- **仓库数据全部重取** ：文中每个星数、许可证、最近推送时间都来自 2026-10-25 的 GitHub API，不是原文的说法。原文只给链接，不给数据。
- **两条链接已失效** ： `aradotso/trending-skills` 和 `ComposioHQ/awesome-codex-skills` 现在都是 301 跳转，正文换成了跳转后的仓库地址； `majiayu000` 注册表里 `enhancing-authors` 的深链已经 404（仓库按 `skills/<分类>/` 重组过），只给到仓库根。
- **官方 4 个技能的 SKILL.md 抽查有效** ：doc-coauthoring、skill-creator、frontend-design、docx 都能取到正文。
- **原文有个自相矛盾的地方** ：推文作者是 @Mr_Buzzoni，文末却写「关注我 @polydao」。这一节按原文照录了，但账号对不上，推广性质明显，转不转关注你自己判断。
- **两个数字要打折** ：9.5 万对 30 万美元的收入对比、以及「绝大多数人还在把 Claude 当聊天机器人」，都是作者的观点陈述，没有给数据来源。
- **技能数量对不上** ：原文说 Rezvani 的仓库「打包了几百个技能」，仓库自述是 380 个 skills、30+ agents（2026-10-23 推送）。我按仓库自述写。

## 十二、真想用起来，按这个顺序

1. 先装官方 4 个：docx、doc-coauthoring、frontend-design、skill-creator。它们定义了技能的标准结构，第三方技能能不能跑顺，也以这套结构为参照。
2. 再装 Skill_Seekers：把手上重复用的文档变成技能记忆。原文把它列在整个生态里「杠杆最高的玩法」之一，这也是我推荐先装它的原因。
3. 然后按日常补 connect-apps（要对外执行）或 research-skill（要长期研究）。
4. 最后再看大盘：VoltAgent 的 1000+ 合集、BehiSecc 的精选清单、trending-skills 的排行。先看大盘的人，通常是收藏了一堆链接，一个都没装。
5. 每隔一两个月重新扫一遍：清单类仓库（travisvn 那个已经四个月没推过）会过时，技能目录被重组也是常事——本文里已经踩到一次 404。

原文的落点是：Claude 变得有意思，来自官方技能、社区大库、细碎注册表和单点专家仓库同时存在——你可以按自己的活，拼一套自己的工作台。
