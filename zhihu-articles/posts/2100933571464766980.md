> 解决一个具体问题：国内到底有哪些服务开放了官方 MCP 或 Skill，分别是什么形态、入口在哪、应该按什么顺序接。

## 背景

2026 年下半年开始，国内厂商集中开放了面向 AI 客户端的接口。流传的清单版本只列了名字，没有形态、入口和能力边界。

花时间做了一下整理，主要说了三件事：每个服务是 MCP 还是 Skill、官方入口地址、接进去实际能干什么。总计 7 个分类、55 个服务。

## 核心内容

### 一、MCP 与 Skill 的区别

- **MCP** 是插座：把一家服务的能力按统一标准接进 AI 客户端，让客户端能调。
- **Skill** 是说明书：一份写好流程和判断的文件，告诉 AI 这家服务该怎么用、什么情况下别用。

两者不冲突。同时给两种形态的服务，通常是厂商认真做过适配的那批。

形态分布如下：

| 形态 | 服务数 | 说明 |
| --- | --- | --- |
| 只给 MCP | 28 | 给了插座，怎么用自己判断 |
| 只给 Skill | 12 | 给了现成流程，走文件分发 |
| 两种都给 | 15 | 最好上手的一批 |
| 额外给命令行 | 2 | 飞书、企业微信 |

## 方法/步骤

### 接入三步

| 步骤 | 做什么 | 注意什么 |
| --- | --- | --- |
| 一、找入口 | 点进官方文档，找 MCP 或 Skill 页 | 认准官方域名或官方仓库 |
| 二、拿凭证 | 申请 API key，或走 OAuth 授权 | 企业类多半要管理员开权限 |
| 三、填进客户端 | MCP 填一段配置，Skill 放进目录 | key 别写进会提交的代码里 |

- MCP 的配置通常是一小段 JSON：启动命令、参数、环境变量里放 key。
- Skill 本质是一份 Markdown 加若干脚本，放进客户端的技能目录即可被识别。

## 我现在怎么用

日常跑得最多的其实只有三类：地图查路线、办公读写文档、云上查资源。

## 注意事项

| 坑 | 表现 | 处理 |
| --- | --- | --- |
| 需装桌面客户端 | 淘宝这类，网页端接不上 | 先装客户端，再接 |
| 付款确认 | 外卖、打车、电商都卡这一步 | 留人工确认，别自动放行 |
| 只读接口 | 多数地图查得到改不了 | 别指望它替写数据 |
| key 过期 | 用一阵突然报错 | 记日历提醒，定期更换 |

1. **桌面客户端坑**：清单里淘宝明确标了「需装桌面端」，很多人照着文档接不通，会误判成自己配置错误。
2. **付款确认坑**：一个外卖订单前九步都能自动化，最后一步是付款确认，目前没有标准答案。稳妥做法是留一道人工确认，只做到「准备下单」。
3. **能力边界**：明确涉及真实资金流转的共 11 个，分别是滴滴、同程商旅、美团、麦当劳、瑞幸、淘宝、飞猪、支付宝、微信支付、银联、巨量引擎。这批不适合交给 Agent 自主执行。

**最后**

清单会越来越长，能立刻用上的不会同步变多。

判断一个服务值不值得接，只看一件事：它最远能替你走到哪一步。三步走完能替你办成事的，留下；只能查的，接一个就够了。

你打算先接哪一个？
