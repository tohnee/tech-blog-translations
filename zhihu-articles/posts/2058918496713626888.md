背景

FSDP2 按层 shard 参数：forward 和 backward 都需要 **all-gather（AG，unshard）**，backward 还要额外做一次 **reduce-scatter（RS，reshard grad）**。PyTorch 为 AG 和 RS 各分配了独立的 CUDA stream，理论上通信可以和相邻层的计算 overlap。

本文针对 **MoE decoder + Expert Parallel（EP）** 的场景。与 dense 模型「一层一个 `fully_shard`」不同，我们把每层拆成三个 FSDP 单元：

| 单元 | 典型内容 | Device Mesh |
| --- | --- | --- |
| block | attention + dense | 主 fsdp_mesh |
| gate | router（常 fp32） | 主 fsdp_mesh |
| experts | MoE experts | 独立 ep_fsdp_mesh |

三者 **参数量级悬殊**，且 experts 运行在独立的 `ep_fsdp_mesh` 上——这一结构特征在后面的 AG、RS 分析里会反复出现。

训练还叠加了 **activation checkpoint**、**reshard after forward**，以及 MoE 的 **token dispatch alltoall**。FSDP 通信和 EP 通信挤在同一条 timeline 上，overlap 比 dense 模型难做很多。

用 torch profiler 观察，最初的问题在 **forward 和 backward 两侧都很明显**：

- compute stream 上大量 `cudaStreamWaitEvent`；
- MoE 层附近 bubble 特别大；
- AG 与相邻层 compute 重叠差；backward 里 RS 等待时间长。

排查下来是两个彼此独立的瓶颈：

```text
瓶颈 1：AG overlap 差（forward / backward 均有）
         →  all2all 在 compute 侧引入同步；三模块体量悬殊使 implicit prefetch overlap 效果差
         →  显式 prefetch（按 block → gate → experts 顺序）

瓶颈 2：RS 等得太久（主要在 backward）
         →  全局 RS wait + 相邻层 / 子模块体量不一致
         →  RS input ring buffer（monkey patch PyTorch）
```

---

### 一、显式 Prefetch：解决 AG Overlap 差

### 1.1 implicit prefetch 怎么工作

FSDP2 把通信和计算拆到不同 stream：

- compute 跑在默认 stream；
- AG 跑在 `all_gather_stream`，RS 跑在 `reduce_scatter_stream`；
- ag -> compute -> ag -> compute -> .... 按自然顺序; 反向按前向记下的顺序逆向 ag

**CPU 侧**的下发顺序是 **compute → AG**——先 dispatch 当前层 compute，再 dispatch 相邻层的 AG。由于 GPU 执行是异步的，且 compute 与 AG 分处不同 stream，**当前层 compute 与相邻层 AG 就能在 GPU 上 overlap**。dense 模型一层一个 FSDP 单元、各层体量接近，这套机制在正反两个方向上通常都够用。

但 MoE 拆成 block / gate / experts 后，AG overlap 明显变差，根因有两个。

### 1.2 原因一：all2all dispatch 带来的同步

一层 MoE 在 forward / backward 里都要经历 FSDP unshard 和 EP alltoall：

**Forward：**

```text
当前层 block forward（unshard block）
  → gate routing
  → experts token dispatch（alltoall）
  → experts forward（unshard experts）
  → experts token combine（alltoall）
  → 下一层 block forward（unshard 下一层）
```

**Backward：**

```text
当前层 block backward
  → experts token dispatch（alltoall）
  → gate / experts / block 各自 post_backward（RS）
  → 上一层 backward（unshard 上一层）
```

alltoall 在正反两个方向都会在 **GPU 侧引入同步**，挤占可用于 overlap 的 compute 窗口：

1. alltoall 虽在独立 stream，但与 compute 之间有 event 依赖——compute stream 必须等 dispatch 完成才能继续；
2. CPU 参与 token 路由和索引准备时，还可能出现 **CPU 等 GPU / GPU 等 CPU**，在 compute stream 上形成空档；
3. 上述同步把当前层 compute **切碎或缩短**；下一层AG 下发到 `all_gather_stream`时，当前层的计算已经基本结束， **没有足够的 compute 去盖住它**。

反映到 trace 上，仍是 `wait_for_unshard` 里的 `wait_event(all_gather_event)`——问题不在于 AG 没发出去，而在于 **compute 被 alltoall 同步打断，overlap 填不满**。

### 1.3 原因二：三模块体量悬殊，implicit prefetch 编排不够细

| 单元 | 体量 | Mesh |
| --- | --- | --- |
| block | 大（attention + dense） | 主 fsdp_mesh |
| gate | 极小（router） | 主 fsdp_mesh |
| experts | 大（MoE experts） | 独立 ep_fsdp_mesh |

implicit prefetch 按 `post_forward_order` 链预取相邻层的 unshard，但 **无法按子模块体量精细编排 AG 的下发顺序**：

- gate AG 极小，很快就结束，**占不满** overlap 窗口；
- experts AG 最大，且在 **独立 communicator** 上，与 block 的 AG 不在同一条 NCCL 流水线里，需单独争取窗口；
- block 与 experts 都需要较长的 compute 来盖住 AG，但三者体量悬殊、mesh 不同，**同一段 compute 窗口很难同时盖住多段体量差异巨大的 AG**。

### 1.4 做法：双向显式 prefetch + 按体量排子模块顺序

FSDP2 提供显式 API，**forward / backward 需成对配置**：

- `set_modules_to_forward_prefetch`：算当前层时，prefetch **下一层**
- `set_modules_to_backward_prefetch`：反传当前层时，prefetch **上一层**

实现分两步：wrap 时记录每层 `_fsdp_modules`；prefetch 时对相邻层调用 API，列表取 `reversed(_fsdp_modules)`。

wrap 顺序为 experts → gate → block，列表为 `[experts…, gate, block]`：

```text
layer._fsdp_modules = []

for expert_mod in expert_mods:
 fully_shard(expert_mod, mesh=ep_fsdp_mesh, ...)
layer._fsdp_modules.extend(reversed(expert_mods))

fully_shard(gate_mod, mesh=fsdp_mesh, mp_policy=fp32_policy, ...)
layer._fsdp_modules.append(gate_mod)

fully_shard(layer, mesh=fsdp_mesh, ...)
layer._fsdp_modules.append(layer)
```

prefetch 时对列表 `reversed`，得到 `block → gate → experts` 的下发顺序：

```text
for layer, next_layer in zip(layers, layers[1:] + [None]):
 if next_layer is None:
 continue
    mods = getattr(next_layer, "_fsdp_modules", [next_layer])
    layer.set_modules_to_forward_prefetch(list(reversed(mods)))

for layer, prev_layer in zip(layers, [None] + layers[:-1]):
 if prev_layer is None:
 continue
    mods = getattr(prev_layer, "_fsdp_modules", [prev_layer])
    layer.set_modules_to_backward_prefetch(list(reversed(mods)))
```

| 顺序 | 体量 | Mesh | 意图 |
| --- | --- | --- | --- |
| block 先 | 大 | 主 fsdp_mesh | 先启动大 AG，与当前层尾部 compute 重叠 |
| gate 其次 | 极小 | 主 fsdp_mesh | 夹在大模块之间，主 mesh 上占用时间短 |
| experts 最后 | 大 | ep_fsdp_mesh | 在 prefetch 列表中排最后，即最先下发；独立链路上尽早启动，整段 compute 窗口用于 experts AG |

建议同时开启 `num_forward_prefetch=1` 与 `num_backward_prefetch=1`。改完后 trace 里两侧 `wait_event(AG)` 明显变短。

### 二、RS Ring Buffer：解决 RS 等得太久

第一节解决的是 AG overlap。prefetch 到位后 AG 已经比较理想，但 backward 里仍有大段 compute 没被 RS 盖住——这是另一类问题，**几乎只出现在 backward**：它由 **全局 RS wait** 引起，又因 MoE **相邻层 / 子模块 RS 体量不一致** 而被放大。

### 2.1 现象

backward 从高层向低层推进（层号从大变小）。以 layer N 为例：

- layer N 的 RS 在 `reduce_scatter_stream` 上执行时，**只能与 layer N−1 的 backward compute 重叠**——更深一层（N−2）的 compute 够不着，因为 N−1 的 RS copy-in 被全局 wait 堵住，流水线传不下去；
- compute stream 长时间 `wait_event(RS)`；
- 每层 RS 分 block / gate / experts 三段，波次多、bubble 累积明显。

与 AG 对比：AG 的 overlap 靠 **提前下发**（prefetch 下一层 / 上一层）；RS 的 overlap 是 **与相邻层 backward compute 并行**，但受全局 wait 限制，**只能覆盖相邻一层**，无法像理想情况那样铺到更深层。

### 2.2 根因

### 全局 `reduce_scatter_state` wait

`post_backward` 里，每层 RS copy-in **之前**：

```text
if self.comm_ctx.reduce_scatter_state is not None:
 self.device_handle.current_stream().wait_event(
 self.comm_ctx.reduce_scatter_state.event
 )
```

单层 RS 流程：

```text
compute stream:        copy-in（pack grad → RS input buffer）
reduce_scatter_stream: wait compute → NCCL reduce_scatter → record event
```

这个全局 wait 是为了防止 **RS input buffer 的数据竞争**：连续两层 `reduce_scatter_comm.allocate()` 可能从 caching allocator 拿到同一块存储，若上一层 RS 还在读 input、下一层就 overwrite，结果会出错。因此 upstream 用 `reduce_scatter_state` **强制相邻层 RS 串行**。

backward 方向下，layer N−1 的 copy-in 必须等 layer N 的 RS 完成：

```text
Layer N:   [copy-in]----[RS================]
Layer N-1:            [wait........][copy-in]----[RS====]
                        ↑ 全局 reduce_scatter_state wait
```

### 相邻层 / 子模块体量不一致，放大等待

RS 同样受 **三模块体量悬殊** 影响，层内、层间叠加：

| 维度 | 表现 |
| --- | --- |
| 层内 | gate RS 极短，block / experts RS 很长；三段 RS 串联，bubble 在一层内就累积 |
| 层间 | layer N 的大块 RS（block / experts）长时间占住 reduce_scatter_stream，N−1 的 copy-in 被堵住；若 N 刚结束的是极短的 gate RS，又 不足以 撑起与 N−1 compute 的有效 overlap |

全局 wait 按「上一次 RS」一刀切地串行，**完全不区分体量**：大 RS 长时间占住通道，小 RS 又填不满窗口——**体量不一致进一步放大了「等 RS」的代价**。

### 2.3 思路：RS input ring buffer

关键观察：**不必等上一层 RS 完全结束才能开始下一层 RS**；只需保证 **当前要写的 buffer 上一次 RS 已读完**。

1. 为 RS **input** 维护 depth-N ring buffer（按 `(size, dtype, device)` 分桶），`torch.empty` 预分配，避开 caching allocator 同址复用；
2. 覆写 slot 前，只 `wait_event` 该 slot 上次 RS 的 event（depth=2 即与两层前的 RS 同步）；
3. `post_backward` 里对选定模块清空 `reduce_scatter_state`，跳过全局 inter-layer wait；
4. RS **output** 仍走原 `allocate`，grad 挂在 `param.grad`，语义不变。

```text
Layer N:   [copy-in slot0]----[RS================]
Layer N-1:      [copy-in slot1]----[RS================]
                 ↑ 只 wait slot1 自己的 event，可与 Layer N RS overlap
```

每层 `_post_reduce_event` 链、`finalize_backward` 和 `optimizer.step()` 前的最终 RS wait 均保留，**只放宽 RS input buffer 的层间重用**。

### 2.4 实现：Monkey Patch

patch 两个入口：

| 函数 | 作用 |
| --- | --- |
| foreach_reduce | 第一次 allocate（RS input）走 ring；第二次（RS output）走原逻辑 |
| FSDPParamGroup.post_backward | 命中模块清空 reduce_scatter_state，跳过全局 wait |

只有 `enable_rs_ring()` 内 wrap 的模块启用 ring。

```text
apply_fsdp2_reduce_scatter_ring_buffer_patch(ring_size=2)

with enable_rs_ring():
 fully_shard(expert_mod, mesh=ep_fsdp_mesh, ...)
 fully_shard(gate_mod, mesh=fsdp_mesh, ...)
 fully_shard(layer, mesh=fsdp_mesh, ...)
```

完整 patch（PyTorch ≥ 2.10）：

```text
import contextlib
import contextvars
from typing import Any, Optional

import torch
import torch.nn as nn

_RS_RING_ELIGIBLE_ATTR = "_rs_ring_eligible"
_rs_ring_mark_on_shard: contextvars.ContextVar[bool] = contextvars.ContextVar(
 "_rs_ring_mark_on_shard", default=False
)
_rs_ring_use_ring_buffer: contextvars.ContextVar[bool] = contextvars.ContextVar(
 "_rs_ring_use_ring_buffer", default=False
)

from torch.distributed.fsdp import fully_shard as _torch_fully_shard

def mark_rs_ring_eligible(module: nn.Module) -> nn.Module:
 setattr(module, _RS_RING_ELIGIBLE_ATTR, True)
 return module

def fully_shard(module: nn.Module, *args: Any, **kwargs: Any) -> nn.Module:
 if _rs_ring_mark_on_shard.get():
 mark_rs_ring_eligible(module)
 return _torch_fully_shard(module, *args, **kwargs)

@contextlib.contextmanager
def enable_rs_ring():
    token = _rs_ring_mark_on_shard.set(True)
 try:
 yield
 finally:
        _rs_ring_mark_on_shard.reset(token)

def _param_group_uses_rs_ring_buffer(param_group: Any) -> bool:
    modules = getattr(param_group, "modules", None) or ()
 return any(getattr(m, _RS_RING_ELIGIBLE_ATTR, False) for m in modules)

class _RingSlot:
 __slots__ = ("buffer", "event")

 def __init__(self, buffer: torch.Tensor) -> None:
 self.buffer = buffer
 self.event: Optional[torch.Event] = None

class _ReduceScatterInputPool:
 """RS input ring，按 (size, dtype, device) 分桶。"""

    _capacity: int = 2
    _rings: dict[tuple, tuple[list[_RingSlot], int]] = {}

    @classmethod
 def configure(cls, capacity: int) -> None:
 cls._capacity = max(2, capacity)

    @classmethod
 def acquire(
 cls,
 size: tuple[int, ...],
 dtype: torch.dtype,
 device: torch.device,
 wait_stream: torch.Stream,
    ) -> tuple[torch.Tensor, _RingSlot]:
        key = (size, dtype, device)
 if key not in cls._rings:
            slots = [
 _RingSlot(torch.empty(size, dtype=dtype, device=device))
 for _ in range(cls._capacity)
 ]
 cls._rings[key] = (slots, 0)
        slots, idx = cls._rings[key]
        slot = slots[idx]
 cls._rings[key] = (slots, (idx + 1) % cls._capacity)
 if slot.event is not None:
            wait_stream.wait_event(slot.event)
 return slot.buffer, slot

def _patch_foreach_reduce_with_ring_buffer(orig_foreach_reduce):
    @torch.no_grad()
 def _wrapped(*args, **kwargs):
        reduce_scatter_comm = args[4] if len(args) > 4 else kwargs["reduce_scatter_comm"]
        device = args[7] if len(args) > 7 else kwargs["device"]
 from torch.distributed.device_mesh import _get_device_handle

        device_handle = _get_device_handle(
            device.type if isinstance(device, torch.device) else torch.device(device).type
 )
        wait_stream = device_handle.current_stream()
        slot_holder: list[_RingSlot] = []
        alloc_calls = [0]
        orig_allocate = reduce_scatter_comm.allocate

 def _ring_allocate(size, *, dtype=None, device=None, **kw):
            alloc_calls[0] += 1
 if alloc_calls[0] == 1 and _rs_ring_use_ring_buffer.get():
                dev = device if isinstance(device, torch.device) else torch.device(device)
                buf, slot = _ReduceScatterInputPool.acquire(
 tuple(int(s) for s in size), dtype, dev, wait_stream
 )
                slot_holder.append(slot)
 return buf
 return orig_allocate(size, dtype=dtype, device=device, **kw)

        reduce_scatter_comm.allocate = _ring_allocate
 try:
            result = orig_foreach_reduce(*args, **kwargs)
 finally:
            reduce_scatter_comm.allocate = orig_allocate
 if slot_holder:
            slot_holder[0].event = result[1]
 return result

 return _wrapped

def _patch_post_backward_skip_global_rs_wait(orig_post_backward):
 def _wrapped(self, *unused):
        use_ring = _param_group_uses_rs_ring_buffer(self)
        token = _rs_ring_use_ring_buffer.set(use_ring)
 try:
 if use_ring:
 self.comm_ctx.reduce_scatter_state = None
 return orig_post_backward(self, *unused)
 finally:
            _rs_ring_use_ring_buffer.reset(token)

 return _wrapped

def apply_fsdp2_reduce_scatter_ring_buffer_patch(ring_size: int = 2) -> None:
 if ring_size <= 1:
 return
 from torch.distributed.fsdp._fully_shard import _fsdp_collectives as coll_mod
 from torch.distributed.fsdp._fully_shard import _fsdp_param_group as pg_mod
 from torch.distributed.fsdp._fully_shard._fsdp_param_group import FSDPParamGroup

    _ReduceScatterInputPool.configure(ring_size)
    patched_foreach = _patch_foreach_reduce_with_ring_buffer(coll_mod.foreach_reduce)
    patched_post_backward = _patch_post_backward_skip_global_rs_wait(
        FSDPParamGroup.post_backward
 )
    coll_mod.foreach_reduce = patched_foreach
    pg_mod.foreach_reduce = patched_foreach
    FSDPParamGroup.post_backward = patched_post_backward
```

对照 upstream：`torch/distributed/fsdp/_fully_shard/_fsdp_collectives.py`（`foreach_reduce`）、`_fsdp_param_group.py`（`post_backward`）。

### 三、小结

| 步骤 | 现象 | 根因 | 手段 |
| --- | --- | --- | --- |
| 1 | forward / backward AG 与 compute overlap 差 | ① all2all 同步缩短 compute 窗口；② 三模块体量悬殊，implicit prefetch 编排不够细 | 双向显式 prefetch，顺序 block → gate → experts |
| 2 | backward RS 仍有 bubble | ① 全局 reduce_scatter_state wait 层间 RS 串行；② 相邻层 / 子模块 RS 体量不一致放大等待 | RS input ring buffer monkey patch |

两类 bubble 的机制并不相同：**AG** 靠提前下发，受 all2all 同步和体量悬殊影响（正反双向都有）；**RS** 靠与相邻层 compute 并行，受全局 wait 和体量不一致制约（主要在 backward，且只能覆盖相邻一层）。在 MoE + 多 FSDP 单元的场景下，两步通常都要做。

**但要注意，overlap 并非越多越好。** 通信与计算同时在 GPU 上跑，会在 **SM、L2 / 显存带宽** 等资源上互相争抢——trace 里 overlap 看着变漂亮了，step 时间却未必线性下降。RS 尤其明显：copy-in 在 compute stream 上跑，NCCL reduce-scatter 本身也占用 SM，与相邻层 backward kernel **抢计算单元**，通信 bound 与 compute bound 叠加成更复杂的争用。所以调优时要以实际 step time 为准，而不是只盯着 trace 上的 overlap 比例。
