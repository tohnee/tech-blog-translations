### 💡 核心导读（省流版）

本文系统梳理了大模型分布式训练的核心理论与工程实践，从底层的“算力/显存账本”到上层的“分布式并行策略”进行硬核拆解，旨在为模型部署与训练预算提供清晰的分析框架。

**全文核心要点概览：**

1. **基础账本（参数、FLOPs与显存）**： 以 7B Decoder-only (SwiGLU) 模型为例，拆解了 Attention 与 FFN 的参数量与计算量（FLOPs）推导公式；明确了**推理显存**（权重+KV Cache）与**训练显存**（权重+梯度+优化器状态+激活值）的本质区别与计算逻辑。
2. **通信原语（并行基石）**： 解析 Broadcast、All-gather、All-reduce、Reduce-scatter 四大原语，并点出核心等价公式：`All-reduce = Reduce-scatter + All-gather`，这是理解后续并行策略通信开销的底层逻辑。
3. **数据并行 (DP)**： 最基础的并行，复制模型、切分数据、同步梯度。针对其通信暴露问题，探讨了计算通信重叠（Overlap）、梯度分桶等优化手段，并厘清了 Global/Micro Batch Size 与梯度累积的调度关系。
4. **ZeRO / FSDP (状态分片)**： 解决“单卡放不下完整模型”的痛点。ZeRO 系列将“复制”改为“切分”：ZeRO-1/2/3 依次切分优化器状态、梯度、模型权重，将参数相关显存降至 1/N；FSDP 是其工程实现，HSDP 则结合节点内分片与节点间复制以优化跨机通信成本。
5. **张量并行 (TP)**： 解决“激活值显存爆炸”与“单层过大”问题。通过将权重矩阵按列/行切分（如 Attention 的 QKV列并行+O行并行，MLP 的 W1列并行+W2行并行），TP 同时切分了参数与激活值。但其通信处于计算关键路径无法隐藏，极度依赖节点内 NVLink 的高带宽。

> **预告**：流水线并行（PP）、序列并行（SP）、上下文并行（CP）、Ring Attention 以及 MoE 专家并行（EP）等进阶内容，将在下篇继续展开。

## 一、计算量、显存、参数量计算方法

写模型部署或训练预算时，最常被问的三个问题是：这个模型有多大？跑一次要多少算力？训练/推理要多少显存？这篇文章用一个具体的 7B 配置把三件事拆开算清楚。

### 1.参数量计算

对标准 Decoder-only Transformer（Llama 系结构，SwiGLU FFN），我们先定义基础的符号，h：hidden size，L：层数，V：词表大小，seq：序列长度。每层参数可以拆成：

**Attention**：Q、K、V、O 四个 `h×h` 投影，共 $4h²$ 。

**FFN（SwiGLU）**：gate、up、down 三个矩阵，约 $3×h×d_f$ 。这里的 $d_f = 8/3*h$

**LayerNorm**：每层两组，共约 $4h$ 。

工程上常用简化估算：**每层约 12h²**（Attention 的 4h² + FFN 的约 8h² 量级）。总参数： $$ N≈L×12h^{2}+2Vh $$ 其中 $2Vh$ 是输入 Embedding 和输出 LM Head。

按照我们假设 $h=4096、L=32、V=32000$ ，计算可得 $N≈6.7×10^{9}$ ，大概是6.7B左右的参数量。

### 2.计算量 FLOPs

FLOPs 要分**前向**和**训练**。一次乘加（MAC）算 2 FLOPs。一个 $m×n$ 的权重矩阵乘一个长度为 $n$ 的向量，计算量是 $2mn$ FLOPs；乘一个 $seq×n$ 的矩阵，计算量是 $2×seq×m×n$ FLOPs。

前向 FLOPs（batch=1，单序列）：

- **Attention**：Q、K、V、O 四个 `h×h` 线性投影；然后 QKᵀ 和 AV 两个分数计算
- **FFN（SwiGLU）**：gate、up、down 三个矩阵，中间维 `d_ff = 8/3·h`
- **LayerNorm、激活、残差**：FLOPs 相对线性层可忽略，通常不计入。

### 2.1 Attention 线性投影（QKV+O）

Q、K、V、O 各是一个 $h×h$ 的矩阵。输入是 $seq×h$ 的矩阵。

**单个投影：**

$2×seq×h×h=2×seq×h^{2}$

为什么？矩阵乘 $(seq×h) @ (h×h)$ 要做 $seq×h $ 次乘加，每次乘加 2 FLOPs，所以 $2·seq·h²$ 。

**四个投影合计：**

$4×2seq×h^{2}=8×seq×h^{2}$

这就是 $8·seq·h²$ 的来源。**它只和 seq 成正比，和 seq² 无关**，因为每个 token 独立地过线性层。

### 2.2 Attention 分数计算（QKᵀ 和 AV）

这部分是 Attention 独有的，**和 seq² 成正比**。

**QKᵀ：** Q 是 $seq×h$ ，Kᵀ 是 $h×seq$ ，相乘得到 $seq×seq$ 的分数矩阵。每个元素是一次长度为 $h$ 的点积： $$ 2×seq×seq×h $$

**AV：** 分数矩阵 $seq×seq$ 乘 V $seq×h$ ，得到 $seq×h$ 的输出。每个输出元素是长度为 $seq$ 的加权和：

$$ 2×seq×seq×h $$ **两项合计：** $$ 4×seq×seq×h $$ 这就是 $4·seq²·h$ 的来源。**它和 seq² 成正比**，因为每个 token 要和所有其他 token 做注意力。seq 越长，这一项占比越高。

### 2.3 FFN（按 d_f= 8/3·h）

SwiGLU FFN 有三个矩阵：gate $h×d_f$ 、up $h×d_f$ 、down $d_f×h$ 。

**gate 和 up 各一个：**$2×seq×h×d_f $

**down 一个：** $2×seq×d_f×h$

**FFN 合计：** $6×seq×h× d_f $

这就是 $16·seq·h²$ 的来源。**它和 seq 成正比**，因为 FFN 是逐 token 的。

### 2.4 每层合计

$F_l ​ =24seq⋅h^{2} +4seq^{2} ⋅h$

### 2.5 全部 L 层 + 输出 LM Head

**L 层：**

$L×(24seq⋅h^2+4seq^2⋅h)$

**输出 LM Head：** 一个 $h×V$ 矩阵，输入 $seq×h$ ：

$2×seq×h×V$

**总计：**

$F≈L(24seq⋅h^2+4seq^2⋅h)+2seq⋅h⋅V$

### 3.显存计算

### 3.1推理显存

推理不需要梯度、优化器状态，只有三块：**权重 + KV Cache + 框架开销**。

权重显存：权重显存=*N*×每参数字节

| 精度 | 每参数字节 | 计算 | 结果 |
| --- | --- | --- | --- |
| FP32 | 4 | 6.7e9 × 4 | 26.8 GB |
| BF16/FP16 | 2 | 6.7e9 × 2 | 13.4 GB |
| INT8 | 1 | 6.7e9 × 1 | 6.7 GB |
| INT4 | 0.5 | 6.7e9 × 0.5 | 3.35 GB |

KV Cache=2×*L*×*seq*×*h*×每元素字节

这里的公式的可以这样理解：<br>L：Transformer 的**每一层**都有自己的 Attention，每一层都会产生自己的 K 和 V。推理时为了不重复计算历史 token 的 K、V，必须把**每一层**的 K、V 都缓存下来。

seq：自回归生成时，第 t 个 token 的注意力要看到前面所有 t 个 token 的 K、V。所以缓存里要存**从第 1 个到当前第 seq 个 token** 的 K、V。每生成一个新 token，KV Cache 就多一行。

h：每一层里，每个 token 的 K 和 V 都是长度为 `h` 的向量（严格说 K、V 的维度是 $d_k = d_v = h / n_h$ ，但所有 head 拼起来正好是 `h`）。所以每个 token 每层的 K 是一个 `h` 维向量，V 也是一个 `h` 维向量。

2：Attention 需要 K 和 V 两份缓存，Q 不需要缓存（当前 token 的 Q 算完就用，不留给未来）。

### 3.2 训练显存

训练时同时存在：**权重 + 梯度 + 优化器状态 + 激活值**。前三个是状态部分，和 batch 无关；激活值和 batch、seq、是否 checkpointing 强相关。

显存计算公式：**显存 = 参数量 × 每个参数所占字节数**。训练时同一个参数可能同时存在多份副本（计算权重、梯度、主权重、优化器状态），每份按自己的精度算字节，再相加。这就是所有显存公式的根源。假设纯 FP32 训练时，所有权重、梯度、优化器状态都是 FP32。

权重显存=*N*×4，在上述的计算中为6.7×109×4=26.8×109 bytes≈26.8 GB

梯度显存=*N*×4。梯度（FP32），反向传播对每个参数求导，得到一个和参数同形状的梯度张量。纯 FP32 下梯度也是 FP32：梯度显存=*N*×4=26.8 GB。**这里为什么和权重一样大？** 每个参数对应一个梯度，形状相同、精度相同，所以字节数相同。简答可以理解梯度是更新参数，所以必须形状一样才可以进行加减的更新。

优化器状态（以 AdamW 为例，FP32）：AdamW 为每个参数维护两个状态：一阶矩 `m`（梯度的指数移动平均）和二阶矩 `v`（梯度平方的指数移动平均），两者都是 FP32、形状和参数相同：优化器状态=*N*×4×2=*N*×8，这里可以计算出具体的显存是：6.7×109×8=53.6×109 bytes≈53.6 GB

激活值：激活值是前向传播中每层的中间结果（Attention 的 Q/K/V、FFN 的中间向量、LayerNorm 输出等），反向传播要用，所以训练时不能释放。

**粗略估算公式：** $激活显存≈B×seq×h×L×k×bytes$ 。

这里说明一下为什么需要激活值的呢？训练时，反向传播要用到前向的中间结果来算梯度。具体说，反向传播算某个线性层 `y = Wx` 的梯度时，需要 `x`（输入）来算 `dW = dy · xᵀ`，需要 `W` 来算 `dx = Wᵀ · dy`。所以**前向传播中每一层的输入、输出、以及 Attention/FFN 内部的中间张量，在反向用到之前都不能释放**。这些就是激活值。

公式解释：一个 batch 里有 B 条序列，每条序列 seq 个 token。每个 token 在每层都会产生一组中间向量。所以 token 总数是 `B × seq`。激活值和 token 数成正比。每个 token 的中间向量长度是 h（hidden size）。比如 LayerNorm 输出、Attention 输出、FFN 中间向量，都是 h 维（FFN 中间是 d_ff 维，但可以折算成 h 的倍数）。每一层都有自己的中间结果要存。`k` 是每层要保存的激活张量个数，`k` 不是精确常数，是**经验折算值**。它表示平均每层、每个 token 需要保存多少个 h 维张量。一层 Transformer 前向要产生很多中间结果，反向可能用到其中大部分。粗略列一下每层典型要存的：

**Attention 部分：**

- LayerNorm 输入/输出
- Q、K、V 三个投影结果（各 h 维）
- QKᵀ 的注意力分数矩阵（seq × seq，不是 h 维，单独算）
- softmax 输出（seq × seq）
- Attention 输出投影的输入/输出

**FFN 部分：**

- LayerNorm 输入/输出
- gate 投影结果（d_ff 维）
- up 投影结果（d_ff 维）
- SwiGLU 激活后的中间结果（d_ff 维）
- down 投影输出

此外还有一个重要降低激活值显存的方案是：gradient checkpointing 。正常训练要存所有层的激活，显存 `O(L)`。Gradient checkpointing的思路：**不存每层的激活，只存少数几个检查点（比如每 √L 层存一个），反向传播需要某层激活时，从最近的检查点重新前向算一遍。这里存在显存和计算量的trade off，也有比较多的内容，这里简单略过。**

额外总结一下：权重、梯度、优化器状态都是**每个参数一份**，大小只和 N 有关；激活值是**每个 token、每层、每个中间张量一份**，大小和 batch、seq、L、h 都有关。这是两类显存的本质区别。

## 二、分布式并行

**大模型训练的核心矛盾是显存不够和通信太慢。并行技术都是在回答两个问题：把什么切到多卡上（权重/梯度/优化器/激活/序列），以及通信怎么藏进计算里。**

**这里大体上可以分为下面几部分**

1. **显存账本**：搞清楚显存到底花在哪，才能知道该切什么。权重/梯度/优化器状态是参数相关、可分片；激活是输入相关、随 batch 线性、随 seq 平方增长。（上面已讲）
2. **通信原语**：理解不同的通信原理的含义及其背后的通信量。
3. **数据并行 DP**：最基础的并行，复制模型、分数据、同步梯度；瓶颈是 all-reduce 通信和单卡放不下模型。
4. **ZeRO / FSDP**：在 DP 基础上切参数、梯度、优化器状态，解决“单卡放不下模型”。
5. **TP / SP / CP / PP**：切矩阵、切序列、切层，解决单卡放不下单层和激活爆炸；CP 引出 Ring Attention 和负载均衡。

### 1.通信原语

通信原语有比较多，我这里先讲解几个在后续会用到的通信原语。分别是**broadcast** 广播，**all-gather** 全收集，**all-reduce** 全归约，**reduce-scatter** 归约-分散

![](https://pic3.zhimg.com/v2-3ef8d38114a079df9882a8e1aad50816_r.jpg)
*广播和全收集*

![](https://pica.zhimg.com/v2-9a199f1679978e13e03b16caaf8c32f2_r.jpg)
*全规约和规约-分散*

**从图中我们可以看出存在一个核心公式：**all-reduce = reduce-scatter + all-gather

**通信量视角：**all-gather / reduce-scatter 只搬一份数据（每卡进/出一份）；all-reduce 相当于先归约分散、再全收集，数据量翻倍。后续可以看到 ZeRO 把 all-reduce 换成 reduce-scatter + all-gather 时省了一次归约的由来。

解释一下，我们定义 ：搬一份数据。设 **N 张卡，每卡持有自己的一个分片，大小为 M**（总数据 = N・M），搬一份数据是指，指**每张卡进出约 N・M 的数据**（把自己的 M 发出去 + 收齐别人的 (N-1) M）。

all-gather：发自己的 M，收齐 (N-1) M，≈ N·M（**一份**），每卡都拿到完整拼接 N・M。<br>reduce-scatter：发自己的 M，收齐 (N-1) M 求和，≈ N·M（**一份**），每卡只留求和的第 i 片 M。<br>all-reduce：= reduce-scatter+all-gather，≈ 2·N·M（**两份**），每卡都拿到完整求和 N・M

**① broadcast（广播）** 只从**一个源**复制到所有人。用于：TP 列并行时把完整输入复制到每张卡（输入完整复制到每一张卡上去 broadcast）。

**② all-gather（全收集）** 各卡持有**不同分片**，结果 = 每卡都拿到**完整拼接**。用于：ZeRO/FSDP 更新完参数后把分片补回完整权重；TP 列并行的输出拼回。

**③ all-reduce（全归约）** 各卡持有**完整的、不同的**数组，结果 = 每卡都拿到**完整求和**（梯度平均就是 sum÷N）。用于：DDP 梯度同步、TP 行输出求和。

**④ reduce-scatter（归约-分散）** 各卡持有完整数组，求和后**每卡只保留不同的一片**（卡 i 留第 i 片）。用于：ZeRO/FSDP 反向时把梯度分片，每卡只留自己的 1/N。

### 2.DP：复制模型、分数据、同步梯度

DP 在 N 张卡上各放一份完整模型，每张卡吃不同的 microbatch，各自前向+反向得到**不同的梯度**，然后通过 **all-reduce 求平均**，让所有副本的梯度一致，再各自 optimizer step，保持副本同步。

基本执行的逻辑：

复制模型：每卡独立算自己的权重，不用跨卡等权重，但是要模型态显存 ×N（不省显存）。<br>分数据：每卡吃不同 microbatch，**避免重复算同一批数据** → 吞吐 ×N，但是要需要同步梯度。<br>同步梯度：N 份副本要收敛成**同一个模型**，必须 step 前把梯度拉齐，但是有通信开销（all-reduce）。

**关键点：all-reduce 在 反向中、 optimizer** **step 前**：optimizer step 要用全局一致的梯度更新参数，所以平均必须发生在 optimizer step 之前；而梯度是反向过程里逐层产生的，所以自然发生在反向中。用前面讲的通信：**all-reduce 平均 = 求和 ÷ N**。

DP 是 **计算并行、状态强一致**，它并行的只有数据，参数是每个副本都要保持一致。

存在问题：通信完全暴露。

串行 `前向 → 反向 → all-reduce → step` 的问题是：反向结束后，GPU 必须**干等** all-reduce 完成才能 step；这段时间 GPU **算力闲置**，利用率 = 计算时间 /（计算 + 通信）。**本质**：通信和计算没有重叠 → 每一轮都把通信时间原样暴露出来。

三个优化方法DP的方法：<br>1.通信和反向重叠：反向从深到浅逐层出梯度，**深层的梯度先就绪先发**，通信段插进 还在算的浅层反向"里，把等待变成流水线。<br>2.梯度分桶：通信次数太多、单次太小。每次通信有固定启动开销；**一个大桶 (比如25MB) 的一次 all-reduce 比 N 次小 all-reduce 高效得多** → 攒够一桶发一次。<br>3.梯度累计下非同步反向：梯度累积下，前 K-1 次反向的跨卡通信**纯属浪费**（因为第 K 次才更新）→ 禁掉，本地累积，只在第 K 次同步一次。

![](https://pic1.zhimg.com/v2-40f2d3ada7889350f63837027131a616_r.jpg)
*DP优化方案*

这里可以额外分享一个思考就是：**独立计算**和**无依赖**是计算通信重叠（Overlap / Hide Latency）的**第一性原理**。这里简单举一些的例子：

1.**无依赖（No Data/Control Dependency）**：**数据依赖**：如果通信的输出是计算的输入，那么**绝对无法重叠**，必须存在同步点（Barrier）。**控制依赖**：如果计算的输出是通信的输入，那么计算必须先于通信。但此时，**第 *i* 层的通信可以和第 i−1层的计算重叠**。<br>2.**独立计算：**为了掩盖通信延迟，系统必须能找到**另一块不依赖当前通信结果**的计算任务来填补 GPU 的空闲时间。比如 DDP 中，第 i层梯度在走 NCCL 网络时，GPU 的 SM立刻去算第 i−1 层的反向传播。<br>3.但是从系统设计角度思考的话，还需要避免硬件资源重叠、粒度与启动开销、显存峰值与 Prefetch 的权衡、拓扑带宽匹配原则。<br>简单说就是：第一点、计算和通信必须在不同的物理硬件单元上执行，否则就是伪重叠。因为硬件角度看这个问题的话，计算占用的是 GPU 的 SM和 Tensor Cores，以及 HBM的读写带宽。通信占用的是独立的 DMA 引擎、NVLink 链路或 RDMA 网卡。这里会有一些约束就是如果当前的计算任务已经把 HBM 的内存带宽吃满了，就是发生了Memory Bound，那么 DMA 引擎在搬运通信数据时就会因为抢不到内存总线而阻塞。所以，实际可能需要做的事情是分析 Kernel 是 Compute Bound 还是 Memory Bound。比如，大矩阵乘法（GEMM）通常是 Compute Bound，此时重叠通信效果极好；而 LayerNorm 或 Element-wise 操作是 Memory Bound，此时如果强行重叠通信，反而会因为总线争抢导致总时间变长。第二点，通信有固定的启动延迟（包括 Kernel Launch、NCCL 握手、路由建立等，通常在几微秒到几十微秒）。上面介绍的梯度分桶（Gradient Bucketing）是这里的一个实际案例，可以作为直接参考。第三点，一般来说，实现无依赖的提前重叠，系统通常需要预取（Prefetching），但这会直接推高显存峰值。比如，dataloader的操作以及在 FSDP (ZeRO-3) 中，为了重叠第 i+1层的权重 All-Gather 和第 i层的前向计算，系统会在算第 i 层时，提前把第 i+1层的权重 Gather 到显存里。但是，显存中同时存在第 i 层和第 i+1 层的完整权重。如果模型极大，这种 Prefetch 会直接导致 OOM。第四点，拓扑带宽匹配原则。重叠的效果，取决于计算速度与通信速度的比值。节点内（NVLink）：带宽高达 900 GB/s，通信极快。此时计算和通信非常容易重叠，甚至通信时间可以忽略不计。节点间（InfiniBand/RoCE）：带宽通常只有 25~50 GB/s（200G/400G 网卡）。通信相对计算非常慢。PP 通过微批次（Micro-batch）的流水线，在时间维度上制造气泡来掩盖延迟。

回到主题，使用了DP需要注意batchsize这个变量，因为加入DP就需要区别global batch size和micro batch size。如果我要需要确定global batch size需要弄清他们之间的关系是什么，表达式是

$global__batch = micro__batch × gradient __accumulation × dp__degree $

这个公式里，需要主要的要点是，DP 是并行、grad_acc 是串行。所以，我们为了训练的效率，选参数的顺序就是 先调micro_batch和dp_degree(在有限的资源下），再用调梯度累计。具体可以参考：先定 global batch ，单卡 micro batch 顶到 OOM**，**用 GPU 数定 DP，最后确定梯度累计数量。

但是DP还是存在一些问题：<br>第一：ring all-reduce 延迟随卡数线性增长，512+ 卡通信无法被计算完全重叠<br>第二：DP 是复制到每卡都是完整模型 + 梯度 + 优化器，加 DP 不省单卡显存**<br>**第三：单卡必须放得下完整模型。

所以，需要新的方法解决，比如FSDP和HSDP。

### **3.Zero/FSDP/HSDP**

DP 的问题是：**每张卡都存完整的一份权重 + 梯度 + 优化器状态**。对 7B 模型、AdamW 混合精度，基于上述的显存计算分析，这部分约 **16 bytes/param ≈ 107GB**，单卡放不下。

ZeRO的观察是**训练的不同阶段用到的数据不一样。前向/反向不需要优化器状态，只有 optimizer step 才需要梯度和优化器状态。**所以没必要每张卡都存完整副本。把权重、梯度、优化器状态这三样按 DP 进程数 `N_d` 切开，每张卡只存 `1/N_d`，需要时再通信拼回来。切的顺序是：优化器状态 → 梯度 → 参数。

ZeRO 的核心思想一句话：**把复制变成切分，每卡只存 1/N，用的时候再 gather 回来。**但 权重 / 梯度 / 优化器状态三样，**不同切分方法推导出**ZeRO-1/2/3 。

ZeRO-1：只切优化器状态<br>思想：有 `N_d` 个并行进程。ZeRO-1 把**完整的优化器状态**（Adam 的 Momentum、Variance、FP32 Master Parameters）等分成 `N_d` 份，每个进程只存其中一份。<br>训练流程：

1. **前向**：每张卡用完整的 BF16 权重计算，得到各自的激活和 loss。
2. **反向**：每张卡算出**完整的梯度**（因为权重完整、数据不同，梯度也不同）。
3. **reduce-scatter**：对所有卡的梯度做 reduce-scatter，求和的同时按 rank 切片，每张卡只保留自己的 `1/N_d` 梯度分片。
4. **optimizer step**：每张卡用自己那份优化器状态（Momentum、Variance、FP32 Master Parameters 的 `1/N_d`）更新自己负责的那 `1/N_d` 参数。
5. **all-gather**：更新后的 FP32 参数转 BF16，通过 all-gather 把各卡的 `1/N_d` 拼回完整参数，供下一步前向。

我们观察一下**优化器状态占多少**。混合精度 + AdamW 下每参数 16 bytes：基于上述显存分析，ZeRO-1 切的是FP32 主权重 + m + v= **12 bytes/param**。切 `N_d` 份后，每卡这部分变成 `12/N_d`。当 `N_d` 很大时，这部分趋近于 0，每卡只剩 BF16 权重 2bytes/param + BF16 梯度 2bytes/param = 4 bytes/param。

这里通信量与数据并行相同，我们计算一下，DP 的通信是反向时一次 **all-reduce**（梯度求平均）。ZeRO-1 的通信是：反向时一次 **reduce-scatter**（梯度求和+切片）和step 后一次 **all-gather**（参数拼回）。

**通信变化**：DP 的 all-reduce → reduce-scatter + 一次 all-gather。这正是上一条讲的恒等式 `all-reduce = reduce-scatter + all-gather`，但注意，ZeRO 里那个 all-gather 是对更新后的权重做的（不是对梯度），而且可以重叠（step 里更新完第一片就开始 gather；前向逐层 gather）。实现需要复杂的 hook + bucketing。**但是需要注意的事情是：严格意义的 ZeRO-1 只分片优化器状态，梯度仍是全量 all-reduce。**

ZeRO-2：切优化器状态+梯度<br>**思想：** ZeRO-1 把优化器状态切成了 `1/N_d`，但每张卡仍存着**完整梯度**（2 bytes/param）。既然每张卡只负责更新 `1/N_d` 的参数，它只需要 `1/N_d` 的梯度，其余梯度用完就可以丢。ZeRO-2 就是把梯度的**存储**也切成 `1/N_d`。<br>执行逻辑<br>1.反向传播逐层算梯度，某一层的完整梯度一算出来，**立刻对这一层做 reduce-scatter**：求和的同时按 rank 切片，每张卡只留自己那 `1/N_d` 分片，完整梯度马上释放。<br>2.整个反向过程中，每张卡任何时刻只持有当前层的完整梯度和已处理层的 `1/N_d` 分片，不再需要一个和完整模型等大的梯度 buffer。边通信边释放。<br>3.梯度只存 `1/N_d` 后，optimizer step 直接用本地分片更新本地参数分片，后续 all-gather 参数分片，流程和 ZeRO-1 一致。

与zero-1的区别：<br>1.ZeRO-1 把 DP 的梯度 all-reduce 换成了 reduce-scatter，但它的梯度 buffer 仍按完整梯度分配，reduce-scatter 前完整梯度实打实占显存。它省的是优化器状态那 12 bytes/param。<br>2.ZeRO-2 的 reduce-scatter 是把梯度存储也改成 `1/N_d` 分片，完整梯度不再常驻。多省的就是梯度这 2 bytes/param。<br><br>**通信量：** 相对于 DP 的 all-reduce，ZeRO-2 仍然是一次梯度 reduce-scatter + 一次参数 all-gather，而 `all-reduce = reduce-scatter + all-gather`，所以总通信量和不切时相同，没有额外通信。这也是实践中默认开 ZeRO-2 而不是 ZeRO-1的原因。<br><br>ZeRO-3 / FSDP：优化器状态+梯度+权重

思想： <br>ZeRO-2 之后，每张卡仍存**完整 BF16 权重**（2 bytes/param），因为前向/反向每一层都要用完整权重。ZeRO-3 把参数也切成 `1/N_d`：每张卡只存一部分参数分片，任何时刻只持有当前正在算的那一层的完整权重，其余层只有分片。<br><br>执行逻辑：

1. 前向：逐层按需 all-gather 当前层的完整权重，算完这一层立刻释放，只留分片。
2. 反向：同样逐层 all-gather 权重来算梯度，产出梯度分片；梯度做 reduce-scatter。
3. optimizer step：每张卡用本地 `1/N_d` 的优化器状态更新本地 `1/N_d` 参数分片。
4. 每卡参数相关显存 ≈ `16 bytes/param / N_d`，和并行度成严格线性反比。

通信代价（相对 ZeRO-2 的增量）：

ZeRO-2 的通信是梯度 reduce-scatter + 参数 all-gather（step 后一次）。ZeRO-3 在此之上多出的是参数 all-gather 的次数：前向：每层 all-gather 一次权重，反向：每层 all-gather 一次权重（算梯度用），首层前向的 all-gather 可以和初始加载/上一步的 all-gather 合并或省去，所以量级是 `2 × num_layers − 1` 次。

优化点：prefetch（预取）：算第 n 层时，提前 all-gather 第 n+1 层（前向）/ 第 n−1 层（反向）的权重，把通信藏进当前层的计算。但是需要满足一些要求：

- 通信延迟/带宽相对于单层计算时间足够小，prefetch 才能把 all-gather 藏住。
- 大规模场景（卡多、跨节点、单层计算相对通信更短）时，不 prefetch 会暴露通信延迟，prefetch 收益明显；小规模、节点内 NVLink 带宽高时，收益有限。
- prefetch 需要额外显存放预取中的下一层权重，所以是用一点显存换通信重叠。

**HSDP**：**跨节点通信贵**，所以，节点之间保留 DDP 的副本式 all-reduce；**节点内NVLink**，用 FSDP 分片省显存。

![](https://pic2.zhimg.com/v2-d984102f46ce157b9f3817784426d8b5_r.jpg)
*zero和HSDP示意图*

总结一下：

1. ZeRO1：对优化器状态进行拆分。显存消耗减少 4 倍，通信量与数据并行相同。
2. ZeRO2：在ZeRO1的基础上，对梯度进行拆分。显存消耗减少 8 倍，通信量与数据并行相同。
3. ZeRO3：在ZeRO2的基础上，对模型参数进行拆分。模型占用的显存被平均分配到每个 GPU 中，显存消耗量与数据并行的并行度成线性反比关系，但通信量会有些许增加。

### 4.TP

ZeRO和FSDP存在的问题：ZeRO/FSDP 把参数、梯度、优化器状态切分了，但激活值一点没动。而激活值随 batch 线性、seq 平方增长，是显存峰值的最大头。TP 的目标就是连激活值一起切。

思想：ZeRO-3 是把权重 gather 成完整副本再算；TP 不 gather 权重而是各卡持有权重的一部分，最后只把结果通信一次。所以 TP 同时切了**参数、梯度、优化器状态，以及激活值**。

张量并行有两种切分权重矩阵的方法，一种是行切分，一种是列切分，如图所示

![](https://pic1.zhimg.com/v2-9090a8bd81bd04a618c98186236fb17e_r.jpg)
*张量切分方法*

图示列切分方法：`X × [W₁|W₂] = [XW₁|XW₂]`，权重按**列**切，X**完整复制**（broadcast 到每卡），各卡算部分**列，使用**all-gather进行通信

**第二行**`[X₁|X₂] × [W₁;W₂] = X₁W₁ + X₂W₂`，权重按**行**切**切分**，W₁, W₂各卡算部分**和，all-reduce**进行通信。

接下来我们我看看TP 在attention和MLP里的应用

可以参考如下图进行分析：

![](https://pic1.zhimg.com/v2-c7865c76a12175a407067dd51c6ad42a_r.jpg)
*Attention的TP通信图*

1. 输入阶段

- 逻辑：输入矩阵 `X` 的形状是 `(B, S, H)`。在进入 Attention 之前，X 是Broadcast到每一张卡上的。TP 不切分输入序列和 Batch，而是切分矩阵乘法中的权重。
- 维度：GPU1 和 GPU2 上的 `X` 都是 `(B, S, H)`。

2. QKV 投影（列并行 Column Parallel）

- 逻辑：权重矩阵 `W_Q`、`W_K`、`W_V` 被按列切分。由于 Attention 是多头的，天然适合按头切分。每张卡只计算属于自己那部分 Head 的 Q、K、V。
- 维度：每张卡上的 `Q`、`K`、`V` 形状变为 `(B, S, H/P)`。
- 通信：无通信。各卡独立完成矩阵乘法 `X * W_Q` 等。

3. Attention 分数计算与上下文聚合

- 逻辑：如粉色框内的标注，`Q` 和 `K` 进行转置相乘得到 `Q·Kᵀ`，然后经过 Softmax 和 Dropout，最后与 `V` 相乘。
- 维度：
- 通信：无通信。因为每一组 Head 的 Q、K、V 都在同一张卡上，Attention 内部的机制（每个 token 跟自己序列里的 token 计算注意力）是局部独立的。

4. 输出投影（行并行）

- 逻辑：Attention 算完后，需要经过输出投影矩阵 `W_O`。此时 `W_O` 采用行并行。各卡拿自己局部的 `Y` 乘以局部的 `W_O`。
- 维度：`Y` 是 `(B, S, H/P)`，局部 `W_O` 是 `(H/P, H)`。相乘后得到局部结果 `Z1`、`Z2`，形状为 `(B, S, H)`。
- 通信：All-Reduce。因为行并行（如上图所示）是将一个完整的矩阵乘法拆分成了多个部分和（Partial Sum），最终完整的输出 `Z = Z1 + Z2`。因此，必须通过一次 All-Reduce 将两张卡上的 `Z1` 和 `Z2` 加起来，使得两张卡都拿到完整的 `(B, S, H)` 的 `Z`。

5. Dropout 与残差连接

- 逻辑：图中明确画出，All-Reduce 得到完整 `Z` 之后，才进行 Dropout。
- 为什么？ 因为 Dropout 需要生成全局一致的随机 mask 掩码。如果各卡只拿到部分 `Z` 就各自做 Dropout，会导致拼接起来的最终结果发生错位。因此，必须 All-Reduce 聚合完完整的 `Z` 之后，再统一做 Dropout。

![](https://pic1.zhimg.com/v2-42e72fa1ceb4a7637bab1094918fc07e_r.jpg)
*MLP的TP图*

假设 `Batch=B, Seq=S, Hidden=H`，MLP 中间维度为 `4H`。

1.**输入 `X`**：形状 `(B, S, H)`。各卡都有一份完整副本（输入是 Broadcast 的）。

2.**第一层 `W1`（列并行）**：权重按列切分。GPU1 拿 `W1_1` `(H, 4H/P)`，GPU2 拿 `W1_2` `(H, 4H/P)`。各卡计算 `X · W1`，得到局部输出 `(B, S, 4H/P)`。*通信量：无*。

3.**激活函数**：对 `(B, S, 4H/P)` 逐元素计算 `GELU/SiLU`。*通信量：无*。极其关键的一点，见后文。

4.**第二层 `W2`（行并行）**：权重按行切分。GPU1 拿 `W2_1` `(4H/P, H)`，GPU2 拿 `W2_2` `(4H/P, H)`。

5.**All-Reduce**：对 `Z1` 和 `Z2` 进行求和，得到完整的 `Z`。

*6.***Dropout**：得到完整 `Z` 后，再进行 Dropout。必须等聚合完再做，因为 Dropout 需要在完整张量上生成一致的随机 Mask，否则各卡各自 Mask 切分的数据，再拼起来就错了。

注意：为什么激活函数决定了只能先列后行？图中的 `gelu/silu` 是**逐元素（element-wise）**操作。也就是说，激活函数 `f(x)` 对向量的每一个元素独立作用：`f(x_1, x_2) = (f(x_1), f(x_2))`。这就意味着：**你可以在切分后的张量上直接做激活，得到的结果和在完整张量上做激活后再切分，是完全等价的。**

- `f([x_1, x_2]) = [f(x_1), f(x_2)]`
- 正因如此，GPU1 和 GPU2 可以在各自的切分片段 `(B,S,4H/P)` 上**独立、无通信**地算激活。

如果一直列并行到 `W2` 会怎样？如果 `W2` 也按列切分（Col），那么 `W2` 的形状将会是 `(4H, H/P)`。

- 要计算 `Activation · W2`，要求 Activation 的最后一维必须是 `4H`（完整的中间维度）。
- 但经过 `W1` 列并行后，每张卡上的 Activation 只有 `4H/P` 维。
- **维度不匹配！** 如果要强行列并行 `W2`，你必须先做一次 `All-Gather` 把激活值拼成完整的 `4H`，这就会引入额外的通信。

如果一开始 `W1` 就用行并行会怎样？如果 `W1` 按行切分（Row），形状是 `(H/P, 4H)`。

- 要计算 `X · W1`，要求 `X` 的最后一维是 `H`（完整）。
- 但行并行要求输入也按对应维度切分，所以 `X` 必须切成 `H/P`。每张卡算出的是部分和。
- 由于 `X · W1` 是线性乘法，部分和必须立刻做 `All-Reduce` 求和，才能得到正确的 `(B, S, 4H)`。
- **问题来了**：求完和之后，激活函数需要作用于完整的 `4H` 维上。如果 `W2` 接在激活后面，为了继续切分，你还要再想办法把激活值切开（Scatter），这就又引入了通信。
- 因此，“行并行-列并行”的顺序会导致**在激活函数前发生一次昂贵的 All-Reduce**，然后还要再切分，极其不划算。

所以，图示的方法：先列并行，再激活，再行并行

- **`W1` 列并行**：不需要输入 `X` 被切分，各卡独立算出切分的局部激活输入。
- **激活函数**：非线性逐元素，局部算没问题（**无 all-gather**）。
- **`W2` 行并行**：正好吃下被切分的激活值，计算出部分和。
- **All-Reduce**：在最后一刻（`W2` 之后）才发生一次，把所有部分和加起来，得到最终完整输出。

通信量与成本计算：MHA vs MLP

我们设 Hidden Size 为 h，Sequence 长度为 seq，Batch 为 B，TP 度数为 P，数据类型字节数为 bytes（如 BF16 是 2 字节）。

1. MHA 的通信账本

- **切分**：QKV 列并行，Output 行并行。
- **前向**：各卡独立算完局部 Attention，经过 Output 的行并行后，产生部分和 Z1,Z2...Zp（形状为 B×seq×h）。此时需要 **1 次 All-Reduce**。
- **通信量**：张量大小为 B⋅seq⋅h。单卡发送/接收量约为 `2 × (P-1)/P × B · seq · h · bytes`。
- **反向**：为了求局部 Output 权重的梯度，需要完整的输入（即 Attention 的输出）。行并行的反向需要先把后续传回来的完整梯度 dZ沿着特征维度切分（Scatter），这对应一次 **All-Gather**（实际上反向的 All-Reduce 也是同理，各卡需要完整的 dZ来算各自的局部权重）。同时，算出的部分梯度需要 **All-Reduce** 才能还原完整的输入梯度。由于这一层的权重按列/行切开了，通常反向包含 **1 次 All-Reduce**（输出梯度）和 **1 次 All-Reduce**（输入梯度）。

2. MLP 的通信账本

- **切分**：W1 列并行，W2 行并行。
- **前向**：W2 行并行结束后产生部分和，需要 **1 次 All-Reduce**。张量大小同样是 B⋅seq⋅h。
- **反向**：与前向对应，反向需要 **2 次 All-Reduce**（一次用来聚合 dW1​ 所需的完整梯度，一次用来聚合传给下层的输入梯度）。

3. 整体 Transformer Layer 的通信总账

一个完整的 Transformer Block（1 个 MHA + 1 个 MLP）：

- **前向**：2 次 All-Reduce。
- **反向**：4 次 All-Reduce。（注：反向的通信量通常是前向的 2 倍，因为既要算输入梯度，又要算权重梯度，且激活梯度张量大小等于前向张量）。
- **总结**：一个 Block 每一次完整的 step，每卡总通信量约为 6 次大小为 B⋅seq⋅h 的矩阵通信。这就是为什么 TP 极度依赖高带宽（NVLink）。

TP存在的一些问题：TP高度依赖NVLink和TP在通信的关键路径上<br>所以，存在以下问题：

- **ZeRO 的通信可以藏起来**：ZeRO 是在优化器更新参数前做 Reduce-Scatter，或者在算某层前做 Prefetch All-Gather。可以用异步通信把时间掩盖过去。
- **TP 的通信藏不起来**：MLP 的 All-Reduce 没做完，后续的 LayerNorm 和残差连接根本没法算！LayerNorm 需要完整的特征维度 h来算均值和方差，一旦你只拿着自己那份切片，这步就卡死了。
- **Megatron 的部分重叠**：图中提到的 FC1 部分矩阵乘结果先发出去，确实有一定缓解，但只要 LayerNorm 还在后面，这个同步点就无法彻底消除。
- **实测悬崖**：这就是为什么图中说 `TP=8` 是个坎。在单机 8 卡 NVLink 内，带宽高达数百 GB/s，算一下只需几毫秒；一旦跨机走 InfiniBand（EFA/IB），延迟和带宽骤降，通信时间可能超过计算时间，导致 GPU 疯狂空转。
