### 写在前面

如果你最近刚开始接触本地部署大模型，大概率会遇到一个经典的“二选一”难题：

网上说用 **Ollama** 好，一条命令就能跑起来；但也有人说现在不用 Ollama 了，推荐用 **llama.cpp**，性能更强。

这篇文章就帮把这事彻底捋一捋。

### 一、先给结论：一个是“整车”，一个是“引擎”

要理解两者的区别，记住一个比喻就够了：

- **Ollama 是一辆“整车”**：你坐上去，踩油门就能走。它把发动机、变速箱、方向盘都给你打包好了，追求的是**开箱即用**。
- **llama.cpp 是一个“引擎”**：它性能强悍、极度灵活，但你需要自己把它装到车上，自己接方向盘和油门。

你听到的“不用 Ollama”的观点，正是源于部分深度用户对**极致性能**和**更高开放性**的追求。

### 二、llama.cpp 到底是什么？

llama.cpp 是一个由 Georgi Gerganov 于 2023 年创建的开源项目。它的核心目标只有一个：**让大语言模型能在各种消费级硬件上高效运行**。

它有几个非常硬核的特点：

1. **极致轻量**：使用纯 C/C++ 编写，没有任何外部依赖。这意味着它在 CPU 和 GPU 上都能跑出顶尖的推理速度。
2. **硬件加速**：支持 Apple Metal、NVIDIA CUDA 等多种硬件加速方案。
3. **量化技术**：通过 GGUF 格式和量化技术，大幅降低模型的内存占用。比如，一个原本需要 14GB 显存的 7B 模型，经过 4-bit 量化后只需要约 4GB。

更重要的是，**llama.cpp 是整个本地 LLM 生态的“地基”**。很多其他工具，包括早期的 Ollama，都是构建在它之上的。

### 三、为什么有人建议“不要再用 Ollama”？

这些批评主要来自对性能和开源生态有更高要求的深度用户，核心观点有三条：

### 1. 性能差距（最核心的痛点）

许多评测显示，直接使用 llama.cpp 比通过 Ollama 运行**要快得多**。有报告称，在相同硬件上，llama.cpp 的每秒 token 生成速度可能比 Ollama 高出 **30% 到 70%**。这是因为 Ollama 的抽象层会带来额外的性能开销。

### 2. “供应商锁定”风险

Ollama 曾一度放弃使用 llama.cpp，转而开发自己的**闭源后端**和**专有模型存储格式**。这导致用户通过 Ollama 下载的模型文件，无法直接被 llama.cpp 或其他工具使用，形成了事实上的“锁定”。

### 3. 开源伦理争议

社区批评 Ollama 在早期未明确致谢其核心依赖 llama.cpp，且其商业化路径（如推出 Ollama Cloud）被认为与“本地优先”的承诺相悖。

此外，Ollama 的默认上下文窗口较小（如 4096 tokens），对于代码生成、Agent 等高级任务可能不够用。

### 四、Ollama vs. llama.cpp：核心对比

| 对比维度 | Ollama | llama.cpp |
| --- | --- | --- |
| 核心定位 | 上层的开发者平台与运行时 | 底层的、高性能的推理引擎 |
| 设计目标 | 易用性和开发效率 | 极致性能、控制和可移植性 |
| 使用体验 | 命令极简（ollama run），开箱即用 | 主要依赖命令行，需要手动配置参数 |
| 模型管理 | 内置模型注册表，自动管理下载 | 需手动下载模型文件（多为 GGUF 格式） |
| 性能 | 因抽象层，速度相对较慢 | 速度更快，资源利用率更高 |

### 五、所以，我到底该怎么选？

这个选择其实是在 **“便利性”** 和 **“性能/控制权”** 之间做权衡。

### 选 Ollama，如果你：

- 是新手，想用最简单的命令快速跑起模型。
- 主要进行原型验证、快速测试或日常聊天。
- 希望有一个集成的模型管理工具。
- 不介意牺牲一点性能来换取便利。

### 选 llama.cpp，如果你：

- 追求**极致的推理速度**和**最低的延迟**。
- 需要对推理过程进行**精细控制**（如调整线程数、GPU 层数等）。
- 希望在边缘设备或低配硬件上**榨干每一分性能**。
- 更偏好**完全开源、无供应商锁定**的方案。
- 愿意花一点时间学习命令行配置，以获得长期的性能回报。

### 六、如何快速上手 llama.cpp？

如果你决定尝试 llama.cpp，可以按以下步骤快速开始：

**1. 安装**

最简单的方式是使用 Homebrew：

```bash
brew install llama.cpp
```

你也可以从 [GitHub 仓库](https://github.com/ggerganov/llama.cpp) 下载预编译的二进制文件或自行编译。

**2. 获取模型**

从 Hugging Face 等社区下载 **GGUF** 格式的模型文件。例如，Qwen2.5-Coder 系列就有对应的 GGUF 版本。

**3. 运行模型**

- **命令行交互**：使用 `llama-cli` 进行对话。

```bash
llama-cli -m /path/to/your/model.gguf -p "你的提示词"
```

- **启动兼容 OpenAI 的 API 服务**：使用 `llama-server` 可以启动一个 HTTP 服务。

```bash
llama-server -m /path/to/your/model.gguf
```

之后，你就可以像调用 OpenAI API 一样，通过 `http://localhost:8080/v1` 来访问你的本地模型了。

### 写在最后

**没有绝对的好坏，只有适不适合。**

Ollama 降低了本地部署的门槛，让更多人能够“先跑起来”。llama.cpp 则提供了更高的上限，让追求极致的人有路可走。

我的建议是：**如果你是新手，先用 Ollama 跑起来。等你觉得不够用了、想折腾了，再去研究 llama.cpp。**

先上车，再换引擎，不迟。
