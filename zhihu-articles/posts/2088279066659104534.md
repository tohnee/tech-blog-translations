**做多模态的同学，这两年最大的感受应该是：论文越来越多，但单纯“做一个更好的 Fusion Module”反而越来越难发了。**

前几年谈多模态，大家最关心的问题还是：

> 图像特征和文本特征到底怎么融合？ 
>  Early Fusion 还是 Late Fusion？ 
>  Cross-Attention 放在哪一层？

但到了 2024–2026 年，多模态研究的中心已经明显发生变化。

今天真正值得讨论的问题越来越像：

> **模型是不是真的“看见”了？** 
>  **不同模态的信息是不是进入了同一个推理过程？** 
>  **长视频到底看哪些帧？** 
>  **推理过程有没有对应的视觉证据？** 
>  **遇到模态冲突，到底相信谁？** 
>  **模型能不能从“看懂”进一步变成“操作电脑、调用工具、控制机器人”？**

所以，如果现在还按照“图像 + 文本 → Attention → Fusion → 分类器”的传统框架理解多模态，很容易漏掉最近三年最重要的变化。本文不按 2024、2025、2026 一年一年堆论文，而是按照 **研究问题是怎么演化的** ，重新梳理最近三年的多模态研究路线。

**时间：** 2024–2026 
 **会议：** CVPR、ICCV、NeurIPS、ICLR、ICML 等 
 **关键词：** MLLM、Multimodal Reasoning、Unified Multimodal Model、Video LLM、Grounding、RL、GUI Agent、Omni Model、World Model

## 一、Motivation：多模态的核心问题已经不是“怎么融合”

传统多模态大致可以写成：

> Vision Encoder + Text Encoder →  Fusion Module → Task Head

研究重点是： **Feature Fusion。**

但是 LLM 出现以后，整个范式变成了：

> Image / Video / Audio →  Encoder / Tokenizer → Multimodal Tokens → Large Language Model → Reasoning / Generation / Action

这时候真正困难的问题已经从： **“两个 Embedding 怎么拼？”**

变成： **“非文本世界怎么进入语言模型，并且真的参与推理？”**

Cambrian-1 就非常典型。它没有再把注意力全部放到 LLM 本身，而是系统比较大量视觉编码器，并提出 Spatial Vision Aggregator，重新强调一个经常被忽视的问题：

> **Vision Representation 本身依然决定了 MLLM 能看到什么。**

Cambrian-1 系统研究了 20 多种视觉编码器，并把视觉表征、Connector、Instruction Data 和 Benchmark 放在一个框架里分析。

因此，如果把最近三年的路线压成一句话，大致是：

> **Fusion → Alignment → Unified Modeling → Reasoning → Grounding → Agent → World Model**

与此同时，还有几个问题一直贯穿其中：

> **Hallucination / Modality Conflict / Missing Modality / Efficiency / Long Context / Evaluation**

下面进行逐条拆解。

## Part 1｜Representation & Alignment：模型到底有没有真的“看见”？

这是最近三年最基础、但也最容易被忽略的一条线。

早期 MLLM 很简单：CLIP / ViT→Projector→LLM。于是大家很自然地以为： Vision Encoder 换一个更强的就行。但很快发现并不是这么简单。

真正的问题包括： **视觉特征需要多高分辨率？一张图片应该变成多少个 Token？视觉空间坐标怎么进入 LLM？LLM 深层是否还保留视觉信息？**

---

### 1.1 Cambrian-1：把研究重点重新拉回 Vision

[Cambrian-1: A Fully Open, Vision-Centric Exploration of Multimodal LLMs](https://arxiv.org/abs/2406.16860?utm_source=chatgpt.com) ， NeurIPS 2024

Cambrian-1 最值得看的地方，并不是单纯提出了一个 SVA 模块，而是它重新问：

> **MLLM 的视觉能力到底来自哪里？**

作者系统比较不同 vision encoder，并提出 Spatial Vision Aggregator，用空间结构感知的方式把高分辨率视觉信息送入 LLM，同时控制视觉 Token 数量。

![](https://pic2.zhimg.com/v2-8d4b1437f5a171ae836ca7b92dfd6d4d_r.jpg)

它纠正了一个常见的误区：LLM 越强 ≠ Multimodal perception 自动越强。

---

### 1.2 Qwen2-VL：Dynamic Resolution + M-RoPE

论文入口： [https://arxiv.org/abs/2409.12191](https://arxiv.org/abs/2409.12191?utm_source=chatgpt.com)

Qwen2-VL 解决了两个特别工程化、但非常关键的问题：

第一， **图片不应该全部强行 resize 到固定尺寸。**

引入 **Naive Dynamic Resolution，** 不同分辨率的图片可以对应不同数量的视觉 Token。

![](https://picx.zhimg.com/v2-8937378cacd3fb4063a80303172b1f4d_r.jpg)

第二，图片、视频、字的位置关系，不能继续直接沿用普通文本的 RoPE。

提出 **Multimodal Rotary Position Embedding（M-RoPE）。** 把文本、图像的二维空间和视频的时间维度统一编码。

![](https://pic4.zhimg.com/v2-f6a375693224fba5280c39f16da9d239_r.jpg)

这条路线后来影响很大，因为它把一个核心问题暴露出来：

> **Multimodal Token 本身就是模型设计的一部分。**

---

### 1.3 LLaVA-OneVision：从单图走向 Multi-image / Video

**LLaVA-OneVision: Easy Visual Task Transfer**

论文入口： [arXiv](https://arxiv.org/abs/2408.03326?utm_source=chatgpt.com) ｜ [PDF](https://arxiv.org/pdf/2408.03326?utm_source=chatgpt.com)

![](https://pic2.zhimg.com/v2-5f59ac057daa10e05e8966735d016d17_r.jpg)

LLaVA-OneVision 一个非常重要的观察是：单图能力，并不一定和视频能力完全割裂。

它统一训练 Single-image、Multi-image 和 Video，并观察到明显的跨场景能力迁移，尤其是 image → video 的 transfer。

这意味着研究问题已经从：“我要不要专门造一个 Video Architecture？”

慢慢变成： **“哪些视觉知识实际上可以跨任务、跨场景迁移？”**

---

### 1.4 InternVL 2.5：Scaling 不只是 Model Scaling

**Expanding Performance Boundaries of Open-Source Multimodal Models with Model, Data, and Test-Time Scaling**

论文入口： [arXiv](https://arxiv.org/abs/2412.05271?utm_source=chatgpt.com) ｜ [PDF](https://arxiv.org/pdf/2412.05271?utm_source=chatgpt.com)

![](https://pica.zhimg.com/v2-1cb6a6b82057d2d970794bd921ab9614_r.jpg)

InternVL 2.5 的价值在于，它把 Scaling 拆得更细了：

> Vision Encoder Scaling、LLM Scaling、Data Scaling、Test-Time Scaling

并且研究了 CoT 等 test-time configuration 对多模态表现的影响。

所以今天再讨论“Scaling Law”，不能只问：参数从 7B 加到 70B 有没有用？

还需要问：

> **算力到底应该加在 Vision、LLM、Data，还是 Inference-time Reasoning 上？**

---

### 1.5 2026：更激进的问题——视觉信息能不能反过来改善语言模型？

![](https://pic1.zhimg.com/v2-9505da496274d1ca4101f442247b9382_r.jpg)

CVPR 2026 Findings 的 **Seeing Helps Reasoning in Language Models** 又往前推了一步。

它不再问：

> 如何让 LLM 看懂图片？

而是问：

> **如果语言模型内部表示和视觉表示对齐，Vision 能不能反过来提升 Language Reasoning？**

论文提出 Cross-Modal Alignment Regularization，让语言模型内部表示和预训练视觉模型的表示进行对齐。

所以这条路线的演化可以概括成：

> Connector →  Better Vision Tokens →  Dynamic Resolution →  Cross-task Transfer →  Representation Alignment → **Vision 是否真正改变 LLM 内部世界表示？**

这可能是比“再换一个 Projector”更值得研究的问题。

## Part 2｜Unified Multimodal Model：理解和生成为什么要用两套模型？

如果说第一条路线讨论：怎么把视觉送给 LLM？

那么第二条路线直接开始挑战模型边界： **为什么 Understanding 和 Generation 必须分开？**

以前两套系统：

> LLaVA：Image → Text 
>  Stable Diffusion：Text → Image

现在希望：

> Image / Text / Video → One Model → Understand + Reason + Generate

---

### 2.1 Chameleon： Everything is Token

**Chameleon: Mixed-Modal Early-Fusion Foundation Models**

论文入口： [arXiv](https://arxiv.org/abs/2405.09818?utm_source=chatgpt.com) ｜ [PDF](https://arxiv.org/pdf/2405.09818?utm_source=chatgpt.com)

Meta 的 Chameleon 是这一波 Unified Multimodal Model 中很重要的工作。

![](https://pica.zhimg.com/v2-ae5b80d191f404b9cf0a4d99b9bad10a_r.jpg)

思路非常直接：

> **文本是 Token，图片也变成 Token。**

然后把二者直接放进一个 early-fusion autoregressive Transformer。

因此它可以处理：

> Text → Image；Image → Text；Image + Text → Image + Text

甚至任意交错的 mixed-modal sequence。

这是： **Everything is Token。**

---

### 2.2 Show-o：为什么图片一定要 Autoregressive？

**Show-o: One Single Transformer to Unify Multimodal Understanding and Generation** ，ICLR 2025

论文入口： [arXiv](https://arxiv.org/abs/2408.12528?utm_source=chatgpt.com) ｜ [ICLR Paper](https://proceedings.iclr.cc/paper_files/paper/2025/hash/45f0d179ef7e10eb7366550cd4e574ae-Abstract-Conference.html?utm_source=chatgpt.com)

![](https://pic2.zhimg.com/v2-4156a6bbdeacc2a1b983f1500315772d_r.jpg)

Chameleon 是： Everything → Autoregressive。Show-o 则认为没必要这么死。

因为：Language 更适合 AR，Image Generation 更适合 Diffusion。

于是提出： **Autoregressive + Discrete Diffusion** 。放进同一个 Transformer。

这一步非常重要，因为 Unified 不等于：

> 所有任务都强行用一种 objective。

---

### 2.3 Janus：真正的矛盾可能出在 Visual Representation

**Janus: Decoupling Visual Encoding for Unified Multimodal Understanding and Generation** ，CVPR 2025

论文入口： [arXiv](https://arxiv.org/abs/2410.13848?utm_source=chatgpt.com) ｜ [CVPR PDF](https://openaccess.thecvf.com/content/CVPR2025/papers/Wu_Janus_Decoupling_Visual_Encoding_for_Unified_Multimodal_Understanding_and_Generation_CVPR_2025_paper.pdf?utm_source=chatgpt.com)

![](https://pic2.zhimg.com/v2-06ca65f6c27e2e7c0d773c857f62a769_r.jpg)

Janus 指出了一个非常漂亮的问题：

> Understanding 和 Generation 真的应该使用同一种视觉表示吗？

理解任务更需要：

**high-level semantic representation**

生成任务更需要：

**fine-grained pixel / spatial representation**

所以 Janus 做的不是把整个模型拆掉，而是：

> **Visual Encoder 解耦，Transformer 统一。**

这样既保留统一模型，又降低 understanding/generation 之间的 representation conflict。

---

### 2.4 JanusFlow：AR + Rectified Flow

**JanusFlow: Harmonizing Autoregression and Rectified Flow for Unified Multimodal Understanding and Generation** ，CVPR 2025

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2025/html/Ma_JanusFlow_Harmonizing_Autoregression_and_Rectified_Flow_for_Unified_Multimodal_Understanding_CVPR_2025_paper.html?utm_source=chatgpt.com)

![](https://pic1.zhimg.com/v2-33d8dd3cdbe2b271991152cc449b4f36_r.jpg)

JanusFlow 延续 Janus 的解耦思想，同时将：

> Autoregressive Language Modeling、Rectified Flow

整合到同一套框架里。

---

### 2.5 Emu3：把路线重新拉回 Next Token Prediction

**Emu3: Next-Token Prediction is All You Need**

论文入口： [PDF](https://arxiv.org/pdf/2409.18869?utm_source=chatgpt.com)

![](https://pic3.zhimg.com/v2-6bbdf1d0e3ee257c3fb0bb604e6dd64e_r.jpg)

Emu3 又走了另外一条路线：

> 图片、视频、文本全部离散 Token 化。

然后：

> **只做 Next-Token Prediction。**

不依赖单独的 diffusion pipeline，也不依赖传统 Vision Encoder + LLM compositional pipeline。

这说明 Unified Multimodal 目前并没有一个确定的答案。

真正的路线博弈是：

| 路线 | 代表模型 | 核心思想 |
| --- | --- | --- |
| 全 AR | Chameleon / Emu3 | Everything is Token |
| AR + Diffusion | Show-o | 不同模态使用不同生成机制 |
| Encoder Decoupling | Janus | 理解/生成视觉表征分开 |
| AR + Flow | JanusFlow | Transformer + Rectified Flow |
| Large-scale Unified Pretraining | BAGEL | 靠大规模 interleaved data 学统一能力 |

---

### 2.6 BAGEL：统一模型开始出现 Emergent Capability

**Emerging Properties in Unified Multimodal Pretraining**

论文入口： [PDF](https://arxiv.org/pdf/2505.14683?utm_source=chatgpt.com)

![](https://picx.zhimg.com/v2-cf247afb072ca6eedaf3a0e165363179_r.jpg)

ByteDance Seed 的 BAGEL 更像是在回答：

> 如果真的把 unified multimodal pretraining 规模做大，会发生什么？

BAGEL 使用 decoder-only architecture，并在大规模 interleaved text、image、video、web data 上训练。

论文报告模型逐渐出现这些能力：

- multimodal reasoning
- image manipulation
- future-frame prediction
- 3D manipulation
- world navigation

所以这一条线最终正在逼近：

> **Multimodal Foundation Model → World Model**

## Part 3｜Multimodal Reasoning：从“识别图片”到“真的做题”

这是 2024–2026 变化最大的一条路线之一。

早期 VQA：

> 图里面是什么？

后来开始变成：

> 根据图表算出答案。 
>  根据工程图推理。 
>  根据化学结构回答问题。 
>  根据几何图完成多步推导。

也就是说：

**Perception 不再是终点，而只是 Reasoning 的输入。**

---

### 3.1 MMMU：多模态开始进入“大学考试”

**MMMU: A Massive Multi-discipline Multimodal Understanding and Reasoning Benchmark for Expert AGI** ，CVPR 2024

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2024/html/Yue_MMMU_A_Massive_Multi-discipline_Multimodal_Understanding_and_Reasoning_Benchmark_for_CVPR_2024_paper.html?utm_source=chatgpt.com)

![](https://pic3.zhimg.com/v2-ad2b287935e4ec8337192ff90321d678_r.jpg)

MMMU 包含约 11.5K 道题，覆盖：

> 30 个学科；183 个子领域； 
>  chart / map / diagram / table / music sheet / chemical structure 等不同视觉类型。

它不再考：Cat or Dog？

而是考： **视觉理解 + 专业知识 + 多步推理。**

MMMU 可以看成一个重要分水岭。从这里以后 Multimodal Understanding，开始越来越明显地转向： **Multimodal Reasoning 。**

---

### 3.2 Vision-R1：DeepSeek-R1 的 RL 思路进入视觉

**Vision-R1: Incentivizing Reasoning Capability in Multimodal Large Language Models** ，ICLR 2026

![](https://pic3.zhimg.com/v2-41095b04eed1eed69bee480ac7531dba_r.jpg)

论文入口： [arXiv](https://arxiv.org/abs/2503.06749?utm_source=chatgpt.com)

DeepSeek-R1 之后，一个很自然的问题就是：

> RL 能不能让 Multimodal Reasoning 也出现类似的能力提升？

Vision-R1 使用 multimodal CoT cold-start 数据，再通过 GRPO 等方式进行 RL。

于是 MLLM 的训练路径逐渐从：

> Pretrain → SFT

变成：

> Pretrain → Multimodal SFT  → Reasoning Cold Start → RL

---

### 3.3 2026：只奖励最终答案已经不够了

这时候又出现一个问题。

传统 RLVR：

> Answer 对了 → Reward +1

但是对于 Multimodal Reasoning：

假设模型：

> **图看错了 → 中间推理也错了 → 最后靠语言先验猜对答案**

这种答案应该奖励吗？显然存在问题。

**Perceptual-Evidence Anchored Reinforced Learning for Multimodal Reasoning（PEARL），** CVPR 2026

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2026/html/Zhang_Perceptual-Evidence_Anchored_Reinforced_Learning_for_Multimodal_Reasoning_CVPR_2026_paper.html?utm_source=chatgpt.com)

![](https://picx.zhimg.com/v2-d11f8433fe0b1a1a704fc27581f311f9_r.jpg)

就开始显式检查：

> **Perception 是否正确？**

只有视觉证据可信，才进一步强化 reasoning。

这是一个很重要的趋势：

> **Reward 从 Answer-level，开始进入 Evidence-level。**

## Part 4｜Video LLM：长视频真正难的不是“看”，而是“该看哪里”

图片只有空间维度。

视频多一个非常麻烦的东西：

> **Time。**

如果一个 1 小时视频按照 2 FPS：

> 7200 Frames

显然不能每一帧全部塞给 LLM。

所以视频问题实际上是：

> **Temporal Understanding + Context Compression + Active Perception**

---

### 4.1 Video-MME：先把视频能力测明白

**Video-MME: The First-Ever Comprehensive Evaluation Benchmark of Multi-modal LLMs in Video Analysis** ，CVPR 2025

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2025/html/Fu_Video-MME_The_First-Ever_Comprehensive_Evaluation_Benchmark_of_Multi-modal_LLMs_in_CVPR_2025_paper.html?utm_source=chatgpt.com)

![](https://pica.zhimg.com/v2-ea67cc97ef10c8b028bc19c075b6c628_r.jpg)

Video-MME 系统覆盖不同长度的视频，并同时考虑：

> Video、Subtitle、Audio

从而评测 MLLM 在不同视频长度和不同模态辅助下的表现。

---

### 4.2 Apollo：Video LLM 终于开始认真研究 Design Space

**Apollo: An Exploration of Video Understanding in Large Multimodal Models** ，CVPR 2025

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2025/html/Zohar_Apollo__An_Exploration_of_Video_Understanding_in_Large_Multimodal_CVPR_2025_paper.html?utm_source=chatgpt.com)

![](https://picx.zhimg.com/v2-24b7da99e47af48a906c114ea2dc6707_r.jpg)

Apollo 很像 Video 版本的 Cambrian。

它没有只造一个新网络，而是系统研究：

> Sampling、Vision Encoder、Token Resampling 
>  Token Integration、Data Composition、Training Schedule

并提出一个特别值得注意的结论：

> 很多在小模型、小数据上的设计决策，可以稳定迁移到更大的 Video-LMM。

论文将这种现象称为 **Scaling Consistency** 。

---

### 4.3 Chain-of-Frames：CoT 终于开始引用“哪一帧”

**Chain-of-Frames: Advancing Video Understanding in Multimodal LLMs via Frame-Aware Reasoning** ，CVPR 2026

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2026/html/Ghazanfari_Chain-of-Frames_Advancing_Video_Understanding_in_Multimodal_LLMs_via_Frame-Aware_Reasoning_CVPR_2026_paper.html?utm_source=chatgpt.com)

![](https://picx.zhimg.com/v2-52fed65d14c5b5bc93af143c4f3d4243_r.jpg)

普通 Video CoT：

> 我认为人物先拿起杯子，然后喝了水……

但是： **你到底是在哪一帧看到的？**

Chain-of-Frames 让模型的推理链显式引用关键帧：

> Frame 17 → evidence 
>  ↓ 
>  Frame 31 → evidence 
>  ↓ 
>  reasoning 
>  ↓ 
>  answer

从而降低时间定位错误。

这是从 **Text CoT** 走向 **Multimodal Evidence Chain。**

---

### 4.4 VITAL：不是一次性看完整个视频，而是主动“回去找”

**Thinking With Videos: Multimodal Tool-Augmented Reinforcement Learning for Long Video Reasoning** ，CVPR 2026

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2026/html/Zhang_Thinking_With_Videos_Multimodal_Tool-Augmented_Reinforcement_Learning_for_Long_Video_CVPR_2026_paper.html?utm_source=chatgpt.com)

这篇论文我认为特别值得关注。

![](https://pic4.zhimg.com/v2-fa6989c571e2e5b9bcb7faf4989a69b9_r.jpg)

传统 Video LLM：

> Frames →  一次性塞给模型→ Answer

VITAL：

> Question → 当前视觉信息不足 → 调用 Visual Tool → 重新采样某个时间段 → 获得新的 Frame → 继续 Reasoning

也就是说： **Video Understanding 开始变成 Agentic Perception。**

它通过工具按需采样视频，并结合多任务 RL 做 long-video reasoning。

这个思想非常重要。未来多模态模型可能并不需要：

> “一次把整个世界塞进 Context。”

而是：

> **需要什么，再主动去看什么。**

---

### 4.5 VideoAuto-R1：每一道题都需要长 CoT 吗？

**VideoAuto-R1: Video Auto Reasoning via Thinking Once, Answering Twice** ，CVPR 2026

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2026/html/Liu_VideoAuto-R1_Video_Auto_Reasoning_via_Thinking_Once_Answering_Twice_CVPR_2026_paper.html?utm_source=chatgpt.com)

![](https://picx.zhimg.com/v2-3b45eea972601d5dbec395c0bd1fbd23_r.jpg)

这是另外一个非常好的问题：

> Easy Question 为什么也要输出几百个 reasoning tokens？

VideoAuto-R1 提出： **Reason When Necessary**

模型先回答一次。如果置信度足够——Direct Answer；如果不够——Trigger Reasoning。

因此它把 Multimodal Reasoning 推向：

> **Adaptive Test-Time Compute。**

论文报告这种策略可以明显减少平均输出长度。

## Part 5｜Grounding & Hallucination：答案对，不代表真的“看对了”

这是我认为 2026 特别值得注意的一条路线。

早期 Hallucination 研究通常问：

> 模型说的东西是不是图片里没有？

但是现在开始进一步问：

> **模型的推理有没有对应视觉证据？**

---

### 5.1 HallusionBench：Vision Hallucination 开始被系统评测

**HallusionBench: An Advanced Diagnostic Suite for Entangled Language Hallucination and Visual Illusion in Large Vision-Language Models** ，CVPR 2024

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2024/html/Guan_HallusionBench_An_Advanced_Diagnostic_Suite_for_Entangled_Language_Hallucination_and_CVPR_2024_paper.html?utm_source=chatgpt.com)

![](https://pic1.zhimg.com/v2-ed25ee93b3e66d9fb4cd15c2eede453a_r.jpg)

HallusionBench 把：Language Hallucination、Visual Illusion、Logical Consistency

放在一起研究。

---

### 5.2 Grounded Chain-of-Thought：推理的每一步都应该有视觉证据

**Grounded Chain-of-Thought for Multimodal Large Language Models** ，CVPR 2026

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2026/html/Wu_Grounded_Chain-of-Thought_for_Multimodal_Large_Language_Models_CVPR_2026_paper.html?utm_source=chatgpt.com)

![](https://picx.zhimg.com/v2-ce617b6cbcad66d6fe347a745d8432ef_r.jpg)

普通 Multimodal CoT：

> Image → Text Reasoning → Answer

Grounded CoT：

> Image → Ground Relevant Region → Reason → Ground Next Evidence → Reason → Answer

并且不只计算 Answer Accuracy，还计算Grounding Accuracy、Answer-Grounding Consistency。

这个变化特别关键。

未来 MLLM 的“正确”可能不应该只有一个维度： **Answer Correctness**

而应该至少拆成：

> Perception Correctness、Evidence Correctness、Reasoning Correctness、Answer Correctness、Evidence–Answer Consistency

---

### 5.3 GETok：Grounding 甚至开始进入 Token Design

**Grounding Everything in Tokens for Multimodal Large Language Models** ，CVPR 2026

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2026/html/Ren_Grounding_Everything_in_Tokens_for_Multimodal_Large_Language_Models_CVPR_2026_paper.html?utm_source=chatgpt.com)

![](https://pic4.zhimg.com/v2-883d994054daea80323a4896c3a954ed_r.jpg)

GETok 的核心问题是：

> 自回归语言 Token 本来是一维序列，怎么准确表达二维坐标？

于是设计：

> Grid Tokens + Offset Tokens

把二维空间关系直接编码成 Token。

所以 Grounding 不只是一个 downstream task。

它开始反过来影响：

> **Vocabulary / Tokenization / Output Space 的设计。**

## Part 6｜Modality Conflict & Missing Modality：现实世界的数据永远不会这么干净

这一条线其实继承自传统多模态研究，但在 MLLM 时代重新变得重要。

真实系统里会出现：

> 摄像头坏了 
>  麦克风没有声音 
>  OCR 和图片冲突 
>  Caption 说 A，Image 明明是 B 
>  一个模态很可靠，另一个模态噪声很大

这时候问题就不是：怎么融合？

而是： **该信谁？**

---

### 6.1 MLA：模态之间也会互相干扰

**Multimodal Representation Learning by Alternating Unimodal Adaptation** ，CVPR 2024

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2024/html/Zhang_Multimodal_Representation_Learning_by_Alternating_Unimodal_Adaptation_CVPR_2024_paper.html?utm_source=chatgpt.com)

![](https://pica.zhimg.com/v2-1488c3889472522812d329f5091fd6b4_r.jpg)

这篇工作指出： **强模态很容易主导 joint training**

于是把 simultaneous multimodal learning 改为：

> alternating unimodal adaptation

降低模态之间的 optimization interference。

---

### 6.2 EAU：不确定性本身也是信息

**Embracing Unimodal Aleatoric Uncertainty for Robust Multimodal Fusion** ，CVPR 2024

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2024/html/Gao_Embracing_Unimodal_Aleatoric_Uncertainty_for_Robust_Multimodal_Fusion_CVPR_2024_paper.html?utm_source=chatgpt.com)

![](https://pica.zhimg.com/v2-fd292f747633d0ed150b9fb34f0f185e_r.jpg)

传统方法：去掉 Noise。

EAU 则认为： **Noise / Uncertainty 本身可以被建模。**

然后根据不同模态的不确定性进行更鲁棒的 Fusion。

---

### 6.3 PCD：Missing Modality 不能靠暴力“补成一样”

**Probabilistic Conformal Distillation for Enhancing Missing Modality Robustness** ，NeurIPS 2024

论文入口： [NeurIPS Paper](https://proceedings.neurips.cc/paper_files/paper/2024/hash/3fb97beb678a1c46bf25f40b3a8c6f98-Abstract-Conference.html?utm_source=chatgpt.com)

![](https://pic4.zhimg.com/v2-f16a717470d9f2f723f36b2ab357e6a5_r.jpg)

很多 Missing Modality 方法喜欢：

> 缺一个模态 → 重构一个 feature → 强行和完整模态 feature 对齐。

但缺失信息本来就不可恢复。

PCD 因此不再做 deterministic point alignment，而是建模： **distribution。**

这是非常值得借鉴的思想： **Missing ≠ Noisy。**

---

### 6.4 MissRAG：缺一个模态，不一定非要生成出来

**MissRAG: Addressing the Missing Modality Challenge in Multimodal Large Language Models** ，ICCV 2025

论文入口： [ICCV Paper](https://openaccess.thecvf.com/content/ICCV2025/html/Pipoli_MissRAG_Addressing_the_Missing_Modality_Challenge_in_Multimodal_Large_Language_ICCV_2025_paper.html?utm_source=chatgpt.com)

![](https://picx.zhimg.com/v2-c9f598968a3edc4ddf0b7f2ad0319f0d_r.jpg)

MissRAG 提出了另外一种思想：缺模态 → Retrieval，而不是：缺模态 → Generate。

它通过 multimodal RAG 补充缺失信息。

这一点特别有意思，因为它开始把 **Multimodal Robustness** 和 **RAG / Memory** 连接起来。

---

### 6.5 2026：同一个事实换一种模态，模型答案居然会变

**Same Content, Different Answers: Cross-Modal Inconsistency in MLLMs** ，CVPR 2026

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2026/html/van_Sprang_Same_Content_Different_Answers_Cross-Modal_Inconsistency_in_MLLMs_CVPR_2026_paper.html?utm_source=chatgpt.com)

![](https://pic4.zhimg.com/v2-cd3eab53292972254b6382a5f805bfbf_r.jpg)

这篇论文构造了一个很有意思的问题：

> 同样的信息：用 Text 给模型，用 Image 给模型，Text + Image 给模型

答案会不会一样？

结果表明当前 MLLM ，仍存在明显 cross-modal inconsistency。

这实际上揭示了一个基础问题： **所谓“统一多模态表示”，可能远没有我们想象中那么统一。**

## Part 7｜Multimodal Agent：模型从“看懂世界”走向“操作世界”

到了这里，多模态和 Agent 基本开始汇流。

因为一个 Agent 操作网页、电脑或者机器人，天然就需要：

> 看屏幕 → 理解状态 → 推理 → 选择动作 → 再看新的状态

也就是：

> **Perception → Reasoning → Action → Observation**

### 7.1 SeeAct：GPT-4V 会规划，但不会点

**GPT-4V(ision) is a Generalist Web Agent, if Grounded** ，ICML 2024

论文入口： [ICML Paper](https://arxiv.org/abs/2401.01614?utm_source=chatgpt.com)

SeeAct 一个特别经典的发现是：GPT-4V 的 high-level planning 已经不错。

但是： **Grounding 到网页里的具体按钮、输入框、坐标非常困难。**

在人工提供 grounding 的条件下，它完成 live-web task 的能力会大幅提高。

于是大家意识到：Agent 的 bottleneck 不一定是 Reasoning。可能是： **Grounding。**

### 7.2 OSWorld：终于不只是在网页 Demo 里测 Agent

**OSWorld: Benchmarking Multimodal Agents for Open-Ended Tasks in Real Computer Environments** ，NeurIPS 2024

### 7.3 UI-TARS：GUI Agent 开始从 Framework 变成 Native Model

UI-TARS 的思路是：

> **直接训练一个 Native GUI Agent。**

Screenshot 输入以后，直接完成 grounding、reasoning 和 action。

## Part 8｜World Model / Embodied：下一站可能不再叫 MLLM

当 Agent 再往前一步，就会进入：

> Physical World。

这时候仅靠：Image → Text Reasoning 已经不够。

模型还要理解：

> 如果我执行 Action A，环境下一步会变成什么？

这就是 World Model。

## Part 9｜Efficiency：视觉 Token 可能正在成为新的“算力税”

多模态还有一个非常现实的问题： **贵。**

一张高分辨率图片可以产生上千个视觉 Token。长视频更不用说。

所以工业界非常关心：

> Token Density、KV Cache、Latency、Throughput、Activated Parameters、Streaming

---

### 9.1 DeepSeek-VL2：Dynamic Tiling + MoE

**DeepSeek-VL2: Mixture-of-Experts Vision-Language Models for Advanced Multimodal Understanding**

论文入口： [arXiv](https://arxiv.org/abs/2412.10302?utm_source=chatgpt.com)

![](https://pic1.zhimg.com/v2-dfedaca2bef86376be99f5bac31cd4c4_r.jpg)

DeepSeek-VL2 使用：

> Dynamic Tiling、DeepSeekMoE、Multi-head Latent Attention

目标非常明确：

> **高分辨率视觉能力不能无限换算力。**

它通过稀疏激活和 KV Cache 压缩提高推理效率。

---

### 9.2 ROSE：甚至不把视觉 Token 塞进 Context

**ROSE: Rotate Your Large Language Model to See** ，CVPR 2026

论文入口： [CVPR Paper](https://openaccess.thecvf.com/content/CVPR2026/html/Yue_ROSE_Rotate_Your_Large_Language_Model_to_See_CVPR_2026_paper.html?utm_source=chatgpt.com)

![](https://pic1.zhimg.com/v2-dfdc663c7a3d108e1eb733f63d9c0dce_r.jpg)

传统方法：Visual Tokens → LLM Context

ROSE 则尝试：Visual Information → Parameter-space Injection

视觉语义被编码成 rotation matrix，直接作用到 LLM 参数空间，从而避免超长视觉输入。论文报告在相近性能条件下，相比其选取的 Qwen2.5-VL-7B 基线明显减少 FLOPs 和 inference latency。

这个工作提出一个很值得想的问题：

> **未来视觉一定要全部变成 Context Token 吗？**

未必。

## 十、工业界实战：大家真正押注的并不是同一条路线

看完学术论文以后，再看工业界，会发现一个很有意思的现象：

**大家都叫“多模态大模型”，但真正下注的位置完全不同。**

---

### 10.1 OpenAI：GPT-4o —— Omni + Real-Time

**GPT-4o System Card**

入口： [OpenAI System Card](https://openai.com/index/gpt-4o-system-card/?utm_source=chatgpt.com) ｜ [PDF](https://cdn.openai.com/gpt-4o-system-card.pdf?utm_source=chatgpt.com)

GPT-4o 的核心不是：再做一个更强的 image encoder。而是： **Omni。**

文本、图像、音频和视频输入进入一个端到端模型，并支持文本、音频和图像输出。

尤其是在语音场景，OpenAI 报告其最低约 232ms、平均约 320ms 的音频响应时间。

所以 OpenAI 的工业路线可以概括为：

> **Multimodal = Native Real-Time Interaction**

---

### 10.2 Google： Gemini —— Long Context

**Gemini 1.5: Unlocking multimodal understanding across millions of tokens of context**

论文入口： [arXiv](https://arxiv.org/abs/2403.05530?utm_source=chatgpt.com) ｜ [PDF](https://arxiv.org/pdf/2403.05530?utm_source=chatgpt.com)

Google 押的一个核心方向非常明确：

> **Long Multimodal Context。**

也就是：

> 一部长视频、一整个代码仓库、大量文档、图片 + Audio + Text

都可以放进统一 Context 中做理解。

Gemini 1.5 的技术报告重点研究的正是 million-token 级长上下文中的跨模态理解。

所以 Google 的思路更接近：

> **如果 Context Window 足够大，模型能不能直接“读完整个世界”？**

---

### 10.3 Alibaba Qwen：从 Dynamic Resolution 走向 Omni

Qwen 的路线特别连续。

### Qwen2-VL

解决：任意分辨率图片 + 视频 position。

[Qwen2-VL arXiv](https://arxiv.org/abs/2409.12191?utm_source=chatgpt.com)

### Qwen2.5-Omni

**Qwen2.5-Omni Technical Report**

入口： [arXiv](https://arxiv.org/abs/2503.20215?utm_source=chatgpt.com) ｜ [PDF](https://arxiv.org/pdf/2503.20215?utm_source=chatgpt.com)

开始统一Text、Image、Video、Audio输入，同时支持：

> Text + Speech Streaming Output。

它设计了 **Thinker-Talker** ：Thinker 负责文本/语义推理，Talker 根据 Thinker 表征生成语音；同时使用 TMRoPE 对齐视频和音频时间。

### Qwen3-VL

2025 年技术报告继续把重点扩展到：

> 更长 interleaved multimodal context。

Qwen3-VL 报告支持最高 256K 的图文视频交错上下文。

所以 Qwen 的路线非常清楚：

> **Perception → Temporal Alignment → Omni → Long Multimodal Context**

---

### 10.4 ByteDance Seed：Reasoning + Agent + Unified Model

字节这条路线同样值得重点看。

### Seed1.5-VL

论文入口： [arXiv](https://arxiv.org/abs/2505.07062?utm_source=chatgpt.com)

Seed1.5-VL 使用：

> 532M Vision Encoder、20B activated MoE LLM

同时把能力重点放在：

> Image、Video、Visual Reasoning、GUI Agent、Game

也就是说，它并没有把“多模态模型”限制在 VQA 领域。

### UI-TARS 则进一步押注：Native GUI Agent。

[UI-TARS arXiv](https://arxiv.org/abs/2501.12326?utm_source=chatgpt.com)

### BAGEL又探索：Unified Understanding + Generation + World Modeling。

[BAGEL arXiv](https://arxiv.org/abs/2505.14683?utm_source=chatgpt.com)

所以 ByteDance 的研究组合实际上很有代表性：

> **MLLM → Reasoning → GUI Agent → Unified Model → World Interaction**

---

### 10.5 Meta：两条路线同时押

Meta 很有意思。

一条是： **Llama 3.2 Vision**

它不是重新从零训练一个 native multimodal model，而是在 Llama 3.1 上增加 vision adapter，通过 cross-attention 把视觉特征注入语言模型，并尽量保留原来的文本能力。

Meta 的官方 Model Card 显示，Llama 3.2 Vision 有 11B 和 90B 两种主要规模，采用 image encoder + cross-attention adapter，并使用约 6B image-text pairs 进行预训练。

这条路线强调：

> **Preserve Language Capability。**

另一条： **Chameleon**

却是：

> Native Early-Fusion Multimodal。

所以 Meta 自己其实也在同时探索 **Adapter-based Multimodalization** 和 **Native Multimodal Pretraining，** 哪一种更适合未来 Foundation Model ？

---

### 10.6 DeepSeek：Efficiency + Unified Generation

DeepSeek 的路线也特别明显：

### DeepSeek-VL2押：

> MoE + High-resolution + Efficient Inference

### Janus押：

> Understanding / Generation Representation Decoupling

### JanusFlow押：

> Autoregressive + Rectified Flow

因此 DeepSeek 的核心问题可以概括为：

> **怎么在保持模型简单和高效的情况下，把多模态能力统一起来？**

---

### 10.7 MiniCPM：端侧是另一条完全不同的路线

大模型公司很容易讨论：

> 70B、100B、million context。

但真正要跑在手机、Pad、端侧设备上，问题完全不一样。

MiniCPM-V / MiniCPM-o 的研究重点就是：

> **小参数 + 高 Token Density + 实时视频 + 实时语音。**

MiniCPM-o 2.6 是约 8B 参数的端到端模型，整合视觉、语音和语言组件，并重点支持实时语音与多模态 live streaming。

这条路线提醒我们：

> **多模态不仅是 Capability Problem，也是 Systems Problem。**

---

## 十三、哪些问题已经比较卷，哪些问题正在发生迁移？

### 1. 单纯 Fusion Module：越来越难

如果工作还是：

> Cross-Attention 改一点，Gate 改一点，Loss 加一项，最后 +0.8%

除非问题场景本身非常特殊，否则很难再单独构成一个有说服力的大故事。

---

### 2. Connector 也开始从“结构创新”转向“信息效率”

真正值得问的是：

> Vision Token 到底应该留下什么？

而不是：

> MLP 换成几层 Transformer？

Cambrian、Qwen2-VL、ROSE 实际上都在用不同方式回答这个问题。

---

### 3. Unified Model 的问题已经从“能不能统一”变成“统一之后会不会互相伤害”

Janus 已经把这个问题暴露得很清楚：

> Understanding 需要 Semantic Information。 
>  Generation 需要 Fine-grained Visual Information。

所以后面非常值得研究：

> **Negative Transfer / Representation Conflict / Task Interference。**

---

### 4. Reasoning 已经从“生成 CoT”进入“验证 CoT”

2025：

> 让模型多想。

2026：

> **你想的依据是什么？**

所以：

> Grounded CoT、Frame-aware CoT、Perception Reward、Evidence Reward

很可能会继续增长。

---

### 5. 长视频正在从 Long Context 走向 Active Perception

第一阶段：

> Context Window 越大越好。

下一阶段：

> **为什么一定要一次读完？**

未来更合理的系统可能是：

> Memory、Retrieval、Active Sampling、Tool Use

需要的时候再回到原始视频找证据。

---

## 十四、我认为接下来尤其值得关注的几个 Open Challenges

### Challenge 1：模型到底有没有使用视觉信息？

这是一个比 Benchmark Accuracy 更底层的问题。

有时候模型答对：

> 是因为看图了吗？

还是：

> 语言先验足够强，直接猜到了？

所以以后需要更多：

> Counterfactual Visual Evaluation、Visual Intervention、Evidence Attribution

---

### Challenge 2：Reasoning 和 Perception 需要拆开评估

目前很多 benchmark：

> Final Answer Correct → Correct

但实际应该拆成：

> Perception → Evidence Selection → Reasoning → Final Answer

只要第一步错了，后面的“漂亮 CoT”都没有意义。

---

### Challenge 3：模态冲突谁说了算？

例如：

> 图片显示红色。

但是 Caption 写：

> “This is a blue car.”

模型到底相信 Image？还是Text？

更进一步：

> 如果 Image 置信度 0.55，Text 置信度 0.95 呢？

这会把问题引向：

> **Uncertainty-aware Multimodal Reasoning。**

---

### Challenge 4：Adaptive Multimodal Compute

不是每一张图片都需要 2000 visual tokens。不是每一个视频问题都需要看 100 Frames。也不是每一道题都需要 2000-token CoT。

更理想的是：

> Easy → 少看、少想、直接答 
>  Hard → 多看、多采样、多推理

也就是：

> **Adaptive Perception + Adaptive Reasoning。**

---

### Challenge 5：Multimodal Memory

这是我认为被明显低估的一条线。

现在很多 Agent 的工作方式仍然是：

> 看 Screenshot → 做一次决策 → Screenshot 丢掉 → 下一轮重新看

但现实中的 Agent 会持续接触：

> Screenshot、PDF、Chart、Video、Audio、Webpage、Table

真正的问题应该是：

> **这些过去看过的多模态证据，怎么变成长期 Memory？**

进一步还需要解决：

> Memory 怎么更新？怎么检索？怎么去重？ 
>  怎么保留 Evidence Provenance？怎么解决不同模态之间冲突？ 
>  怎么只取当前推理真正需要的部分？

这条线会自然连接：

> Multimodal、Agent、RAG / Memory、Grounded Reasoning

相比单纯换一个 Vision Projector，这个问题空间明显更完整。

---

## 十五、最后总结：多模态真正发生了什么？

如果只看模型名字，会感觉这三年的多模态特别乱：

> LLaVA、Qwen-VL、InternVL、Gemini、GPT-4o、Janus、Show-o、BAGEL、UI-TARS……

但如果从研究问题看，其实路线非常清晰。

最开始：

> **怎么把不同模态融合？**

后来：

> **怎么把不同模态对齐到 LLM？**

再后来：

> **能不能用一个模型理解和生成所有模态？**

然后：

> **模型到底能不能基于视觉证据完成复杂推理？**

再往后：

> **如果信息不够，它能不能主动去看、去检索、去调用工具？**

最终开始逼近：

> **模型能不能感知世界、记住世界、预测世界，并在世界里行动？**

所以我更愿意把 2024–2026 的多模态主线概括成：

> **Fusion → Perception → Reasoning → Grounding → Action**

而真正值得继续往后做的，也越来越不是：

> “还能不能再加一个模块？”

而是：

> **现有 Multimodal Intelligence 的哪一个环节还没有闭环？**
