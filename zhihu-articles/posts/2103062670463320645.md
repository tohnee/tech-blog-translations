## SelectionDAGBuilder

输入：IR基本块，输出目标无关的 SDNode 组成的 DAG（instruction.def)

1. 建立SDNode，SDValue

- 一般指令：操作数转换成SValue、DAG 操作码建节点SDNode
- Load/Store 指令：需额外处理 Chain 依赖链

2. 例子：visitStore

store i32 %val, ptr %ptr

- %val：store数据大小；ptr：目标地址；%ptr：源地址；
- ComputeValueVTs()：数据layout（切分数据大小为硬件数据宽度，分n次进行拷贝）
- chain：根据最大并行个数，合并成一个chain；
- 多个chain可以合并成一个store（ISD::TokenFactor，类型为MVT::Other，控制流依赖）
- 多条chain合并成一个store节点（ISD::STORE），和chain边（类型为MVT::Other，以供后续节点串联）

3. 杂项记录

- NodeMap
- ISD::PHI 节点

```text
merge:
  %y = phi i32 [ %y.1, %then ], [ %y.2, %else ]
```

## ScheduleDAGRRList

寄存器分配前（pre-RA）指令调度器

负责把 SelectionDAG 形式的代码变成按序排列的指令队列（MIR；MachineInstr 序列）

DAG 中三种指令关系约束：

- data：数据依赖
- chain：依赖约束两条指令的前后顺序
- Glue 关系约束两条指令必须绑定发射、不能分开

```text
图例：[SUnit A] --Data(lat=2)--> [SUnit B] --Glue--> [SUnit C] 
B依赖A的数据ready延迟2个单位（数据依赖），B与C绑定(glue依赖），A->BC数据链路（chain依赖）
```

## MachineSchedulerImpl

基于机器指令层（MIR）的调度框架

### MachineSchedulerBase::scheduleRegions

接收一个基本块，把基本块切分成若干调度区域，然后对每个区域依次执行实际的调度

基于优先级队列的双向调度算法

- 维护 Top 队列（所有可用的前驱指令）和 Bottom 队列（所有可用的后继指令）
- 通过动态调整队列权重，在最小化延迟与平衡寄存器压力之间取得最优解

调用流程：

- ScheduleDAGInstrs::startBlock()：设置启动block
- getSchedRegions()：通过isSchedBoundary，确定block的调度边界，合入Regions容器，若需TopDown则反向排序
- 循环：每个region

### ScheduleDAGInstrs::buildSchedGraph

3.1.

从 MIR 构建 SUnit 图的入口：把一个调度区域（SchedulingRegion，即一段 MachineInstr 序列）转成带依赖边的 SUnit 图。流程：

SchedulingRegion (MachineInstr 序列)<br> │<br> ▼<br> ┌───────────────────────────────┐<br> │ 1. addSchedBarrierDeps() │ 从 ExitSU 自底向上扫描，按 def-use 建边<br> └───────────────────────────────┘<br> │<br> ▼<br> ┌───────────────────────────────┐<br> │ 2. 逐指令算寄存器压力变化 │ PDiffArray + RPTracker<br> └───────────────────────────────┘<br> │<br> ▼<br> ┌───────────────────────────────┐<br> │ 3. 遍历区域，连各类依赖边 │ 数据 / 输出 / 反依赖 / 内存 / 屏障<br> └───────────────────────────────┘<br> │<br> ▼<br> SUnit 图（带边和压力信息）

寄存器压力配置：

- def：截断寄存器生存期，减轻压力，递减
- use：延伸寄存器生存期，增加压力，递增

连依赖边：

```text
[SUnit A] ──数据依赖(RAW)──> [SUnit B]
       │  ▲                        │
       │  └──反依赖(WAR)───────────┘
       │                           │
       └──输出依赖(WAW)────────────┘

```

- 数据依赖（RAW）：B 使用 A 定义的寄存器，A 必须先于 B。
- 反依赖（WAR）：B 定值、A 使用同一寄存器，A 必须先于 B，否则 B 会覆盖 A 要读的值。
- 输出依赖（WAW）：两条指令写同一寄存器，顺序不能乱。
- 内存依赖：涉及内存操作的指令之间，依据别名分析（AA）判断是否可能冲突，冲突则连边；
- 屏障/特殊依赖：addSchedBarrierDeps() 处理的调度屏障，用来阻止跨屏障的非法重排。

ScheduleDAGMILive::buildDAGWithRegPressure

- initRegPressure：为两个方向的调度分别初始化压力监视器：自顶向下用 TopRPTracker，自底向上用 BotBPTracker；只覆盖尚未被调度的指令；
- 三者都维护 CurrSetPressure 和 MaxSetPressure 两个变量

3.3.postprocessDAG

之前添加 ScheduleDAGMutation 对象：DAG->addMutation

```text
static ScheduleDAGInstrs *createVLIWMachineSched(MachineSchedContext *C) {
  ScheduleDAGMILive *DAG = new VLIWMachineScheduler(
      C, std::make_unique<HexagonConvergingVLIWScheduler>());
  DAG->addMutation(std::make_unique<HexagonSubtarget::UsrOverflowMutation>());
  DAG->addMutation(std::make_unique<HexagonSubtarget::HVXMemLatencyMutation>());
  DAG->addMutation(std::make_unique<HexagonSubtarget::CallMutation>());
  DAG->addMutation(createCopyConstrainDAGMutation(DAG->TII, DAG->TRI));
  return DAG;
}
```

允许目标后端在依赖图建好之后、正式调度之前，向图中补充 TableGen 无法表达的调度约束。

3.4. ScheduleDAGMI::findRootsAndBiasEdges

遍历调度区域内的所有 SUnit，根据每个节点的前驱/后继计数，把节点分别归入自顶向下调度的根节点队列和自底向上调度的根节点队列，为随后初始化就绪队列做准备。

3.4. 调度

initQueues() ：从 EntrySU / ExitSU 扩展出两个方向的就绪队列

调度策略：VLIWMachineScheduler/ConvergingVLIWScheduler ：逐点选点，写入 Sequence；VLIW打包，把排好序的指令按槽位约束装进 bundle，处理 bundle 内部依赖与资源冲突

ConvergingVLIWScheduler::pickNode(IsTopNode )：

- 从就绪队列挑一个 SUnit，IsTopNode 指示自顶向下还是自底向上
- 比较所有就绪节点的 Excess（压力溢出）、CriticalMax、CurrentMax 等指标
- 额外考虑槽位资源和 packet 收敛性

ScheduleDAGMILive::scheduleMI()：把该 SUnit 对应指令落位：自顶向下追加到序列尾部，自底向上插到序列头部，并更新 ScheduleDAGMI 内部指针

ConvergingVLIWScheduler::schedNode()：通知调度策略"这个节点已定"，更新策略候选集/优先级状态

updateQueues()：

- 把 SU 的后继（自顶向下）或前驱（自底向上）的剩余计数减一，计数归零者进入就绪队列
- 维护每个 SUnit 的 NumPredsLeft / NumSuccsLeft
- NumPredsLeft / NumSuccsLeft 是 SUnit（调度单元）上用于跟踪依赖完成进度的两个计数器，分别对应"还有多少个前驱没完成"和"还有多少个后继没完成"

### RPTracker

- 寄存器压力追踪器（Register Pressure Tracker）
- 避免调度决策把寄存器压力推高到导致溢出（spill）的程度
- recede() ：反向移动接口，把追踪器的当前位置从当前指令位置向后（逆调度方向）退一步，同时回滚该位置处寄存器压力状态的更新。
- advance() ：与recede()相对，前者用于自底向上 / 反向遍历，后者用于自顶向下 / 正向遍历。
- 寄存器资源约束

### Region

LiveRegionEnd：边界在活跃区间上的终点

RegionEnd：调度区域本身的边界

## 5. PostRASchedulerLegacy

机器指令级调度器（寄存器分配后post-RA阶段）

5.1. runOnMachineFunction

=> PostRAScheduler::run

=>SchedulePostRATDList Scheduler：MachineInstr序列

- ScheduleDAGInstrs::buildSchedGraph()：建 SUnit 依赖图；初始化 SUnit 与 MI 的映射（MISUnitMap）

- ScheduleDAGDependencyBuilder::buildDeps：建立指令间依赖边，基于 MemOperands 和寄存器使用信息，为依赖图添加真实的寄存器数据依赖、内存依赖、特殊顺序约束；

- AntiDepBreak分支

- postProcessDAG：apply Mutations

- ListScheduleTopDown：关注启发参数：Depth 和 Height（相对关系）；维护AvailableQueue和PendingQueue；模拟真实设备的发射流水线

- EmitSchedule：据此重排基本块内指令顺序，并根据排序时插入的 nop 指令完成最终发射

- Depth 指调度 DAG 入口节点到当前指令节点的最长路径，Depth 值更低的节点应当优先发射，同样能优化流水性能
- Height 指的是从某个 SUnit 节点出发、沿着依赖边一路走到出口节点（exit node）所经过的最长路径长度，也就是该指令之后还有多长的关键依赖链需要等待。
- AvailableQueue：就绪优先级队列，存放当前可以被调度的有效 SUnit 节点。
- PendingQueue：存放操作码已发射、但因操作延迟导致执行结果尚未 ready 的指令；一旦结果可用，对应指令会被移入 AvailableQueue。
- HazardRec->atIssueLimit()：统计当前发射是否已占满 issueWidth（每周期可发射的指令条数上限），占满则跳到下一周期，未占满则继续发射以利用指令级并行。硬件资源冲突时插入空周期，借助 Scoreboard （跟踪寄存器/资源就绪状态的表）精确模拟硬件占用、避免资源浪费

5.2. 调度源码：

```text
for (auto &MBB : MF) {
    Scheduler.startBlock(&MBB);
    MachineBasicBlock::iterator Current = MBB.end();
    unsigned Count = MBB.size(), CurrentCount = Count;
    for (MachineBasicBlock::iterator I = Current; I != MBB.begin();) {
      MachineInstr &MI = *std::prev(I);
      --Count;
      if (MI.isCall() || TII->isSchedulingBoundary(MI, &MBB, MF)) {
        Scheduler.enterRegion(&MBB, I, Current, CurrentCount - Count);
        Scheduler.setEndIndex(CurrentCount);
        Scheduler.schedule();
        Scheduler.exitRegion();
        Scheduler.EmitSchedule();
        Current = &MI;
        CurrentCount = Count;
        Scheduler.Observe(MI, CurrentCount);
      }
      I = MI;
      if (MI.isBundle())
        Count -= MI.getBundleSize();
    }
    Scheduler.enterRegion(&MBB, MBB.begin(), Current, CurrentCount);
    Scheduler.setEndIndex(CurrentCount);
    Scheduler.schedule();
    Scheduler.exitRegion();
    Scheduler.EmitSchedule();
    Scheduler.finishBlock();
    Scheduler.fixupKills(MBB);
}
```

Scheduler.startBlock()：调度器开始处理这个基本块，把它放入调度实例对象中

从 MBB 末尾向前倒序遍历：

- 调用指令或目标相关的调度边界指令（边界）：从该边界到当前游标作为一个 region 交给调度器处理：设置边界结束序号；构建 SUnit 依赖图并做列表调度；退出当前 region 的调度上下文；按调度后的顺序把指令发射回 MBB；

遍历结束后：从 MBB 开头到最近一个边界再单独调度一次（处理最后一个region）

通知调度器该基本块处理完毕；调度重排指令后，修正 kill 标志；
