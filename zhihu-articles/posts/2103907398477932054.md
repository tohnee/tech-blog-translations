用 LangChain、AutoGen、CrewAI 搭过 AI Agent 的开发者都熟悉一个流程：调好 prompt、接好工具，跑起来效果不错，就上线了。但上线之后呢？Agent 还是那个 Agent——它不会因为用得越多而变得越强。

这是当前 Agent 落地的一个结构性矛盾：**Agent 框架负责“搭”，但都不负责“练”**。想上强化学习，主流训练工具又是为单轮对话设计的，处理不了 Agent 固有的多轮交互、多智能体协作和动态上下文。

微软研究院的 Agent Lightning 就是针对这个矛盾做的：一个用强化学习训练任意 AI Agent 的轻量级框架，2026 年 8 月完成 v1.0 重构，核心代码只有约 3500 行，MIT 协议开源。

## 零代码接入：换个地址就能训练

它的接入成本比较低。Agent 不用改业务代码，只要把模型请求的 base_url 指向框架的 API Gateway，所有调用就会被自动记录成训练轨迹。

实现思路是在模型请求的必经之路上做记录：框架启动 Agent 时注入三个环境变量——模型代理地址、reward 上报地址、鉴权 key。每次模型调用经过网关，token id 和 logprob 自动落盘；Agent 跑完上报一个 reward 数字，一条训练轨迹就齐了。

LangChain、AutoGen、CrewAI、OpenAI Agents SDK 都支持；不用框架、直接用 Python + OpenAI SDK 也可以。

## 三大组件，各管一段

整个框架由三个组件构成，通过 HTTP 协作：

![](https://picx.zhimg.com/v2-6c70883cbc81ada1185393c23c3bef43_1440w.jpg)

**Trainer（训练器）**：跑 verl + vLLM，构建训练样本、计算 advantage、更新策略，GPU 上的计算都在这

**API Gateway（网关）**：框架中枢，一个 OpenAI 兼容的模型反向代理，同时存储 rollout 和事件

**Rollout Controller（执行控制器）**：把排队的 rollout 变成真实运行的 Agent，支持本地子进程和 Kubernetes Job 两种模式

三个进程完全解耦，可以独立扩缩容、跨机器部署。K8s 模式下每个 rollout 就是一个 K8s Job，私有化集群可以直接用，不依赖外部沙箱服务。

## 核心问题：单轮RL算法怎么训练多轮Agent

这是框架最值得细看的技术设计。PPO、GRPO 这些算法是为单次对话设计的，直接拿来训练多轮 Agent 会遇到奖励难以分配等问题。Agent Lightning 给出两级轨迹聚合方案：

**transition 级**：每次模型调用作为一条独立训练样本

**trajectory 级**：把多轮连续对话合并成一条样本——前提是下一轮的 prompt 严格以上一轮 context 为 token 前缀，否则拆开单算

奖励分配上，最终 reward 放在每条样本 response 的最后一个 token 上，再配合 rollout 级 advantage 和按 rollout 归一化的损失，把 GRPO 的组内比较对齐到“整个 rollout”的粒度。算法上内置 PPO/GRPO，支持 CISPO、R3（MoE 专家路由回放）与 Megatron，图像输入也能进训练。

## 效果如何

在 SWE-bench Verified（软件工程权威基准）上的验证结果：

![](https://pic1.zhimg.com/v2-2c108bb3fea0ece18f0145f83892fa06_1440w.jpg)

1.8K 样本换来 13.8 个百分点的提升，样本效率表现不错。官方将主要原因归结为“真实 harness 训练”：训练全程用真实的工具调用、真实的代码执行、真实的数据库，而不是简化的仿真环境——训练和部署之间没有分布漂移。

## 三个值得借鉴的设计

即使不直接用它训练模型，这套设计里也有几处值得借鉴：

**1.无侵入数据采集**：在 HTTP 层拦截模型调用轨迹，不侵入框架内部——需要采集 LLM 调用链路的场景都可以参考这个思路

**2.训练与执行解耦**：训练（GPU）、采集（网关）、执行（容器）拆成三个独立进程，各自独立演进，这是 RL 工程化落地的关键一步

**3.真实环境优于仿真**：与其搭仿真环境训练，不如直接在部署级 harness 上练，减少训练-部署的 gap

## 写在最后

Agent Lightning 的价值在于给“Agent 怎么练”提供了一个轻量的开源参考实现。而要让强化学习真正跑起来，光有训练框架还不够——高质量的训练数据从哪来、模型效果怎么评，是同样重要的两环。

360智汇云的AI开发平台也在持续完善这条链路：数据合成与数据抽取解决“训练数据从哪来”，标注平台 TLP 解决“数据质量怎么保证”，模型评测 TEP 解决“效果提升怎么衡量”。框架解决“怎么练”，平台解决“数据和评测怎么跟上”，两者是相辅相成的。
