### Vision Encoder

图生文模型处理图片靠的是正是 Vision Encoder，下面讲解它做的工作。

### picture 预处理

1. 一个图片首先会被 encoder 切分为若干个小 patch，然后一个 patch 会被 flatten 为一个行向量。 举个例子，patch 大小是 [10,10] 的时候，一共有 100 个像素，然后 RGB 三原色意味着一个像素可以用三个数值表示，所以这样的一个 patch 一共有 300 个数字，然后按照行依次拼接到 前一行 前面，就得到了一个维数为 300 的行向量，接着咱们初步处理图像信息，也就是引入可学习的 Linear 线性层，将 patch 展成的行向量投影 到一个新的隐藏维度，至此，咱们得到了一个 patch 对应的 token，本文称之为 graph token。
2. 但这样的 token 显然丢失了图片像素的位置信息，所以咱们还要对得到的 graph token 进行位置编码，这里不展开具体编码手段。
3. 位置编码之后，类似 text token 的传统处理方式，咱们将 graph token 丢入若干个 transformer block 处理图片信息，最后得到和输入形状一致的图片信息矩阵。

至此，Vision Encoder 的任务基本就完成了。

### Adapter

从 最开始的流程图大家能知道接下来 graph token 要进入 LLM 了，但是请注意，Vision Encoder 和 LLM 是相对独立的组件，所以前者和后者的隐藏维度不一定对齐，所以咱们还要在二者之间引入一个可学习的 Linear，形状设置为 [d_graph,d_model]，专门对齐二者的隐藏维度，这就是 Adapter 的工作。

### cross-attn 和 docode-only 的对比学习

现在咱们了解了图生文模型是如何处理图片的，那么 graph token 进入 LLM 之后又是如何处理的呢？和 text token 的关系是什么？

这就要引入两种主流的模型架构：decoder-only 和 cross-attention

### decoder-only 架构

这也是大家熟悉的最常规的 transformer 架构，在这种架构下，graph token 被粗暴地拼接在了 text token 的前面，这样能让注意力掩码形状天然让所有的 text token 都能看到所有 graph token。然后按部就班进入 attention 之类的环节。

请注意这个暴力拼接，后续推理优化设计会考虑到。

### cross-attention 架构

在高人的神秘注意力下发现，graph token 已经在 Vision Encoder 里处理过图片信息了，不一定还要陪着 text token 走完 LLM 里的每一层。于是设计出来了以下流程图：

![](https://pica.zhimg.com/v2-db0f20422b0ae94b7d26d9b9f355518c_r.jpg)

这里画的是方便理解的一段流程，省略了归一化之类的细节。实际模型可以隔若干个 LLM block 插入一次 cross-attention，也可能在新增的 cross-attention block 里配上自己的 FFN 和门控，不要求每一层都长得和图里一模一样。 [Flamingo 的设计](https://arxiv.org/html/2204.14198v1#S3.SS1.SSS2) 就是这样的例子。

**这种架构的优点就是 prefill 计算量往往会比 decode-only 计算量小很多。**

### 两种 token 是如何协同的

text self-attention 先处理文字之间的关系，让文本侧表示带上问题的上下文；接着 cross-attention 根据这些表示，从 graph token 里读取相关的视觉信息。

具体怎么读取呢？还是熟悉的 Q、K、V，只不过来源变了。self-attention 的 Q、K、V 来自同一条序列，而这里的 Q 来自文本侧，K 和 V 来自图片侧。以单个注意力头为例，记 self-attention 之后的文本矩阵为 $H_t$，图片特征矩阵为 $H_g$，那么：

$$
 Q_t=H_tW_Q,\qquad K_g=H_gW_K,\qquad V_g=H_gW_V 
$$

$$
 Z=\operatorname{softmax}\left(\frac{Q_tK_g^\top}{\sqrt{d_k}}\right)V_g 
$$

[原始 Transformer 论文](https://arxiv.org/html/1706.03762v7#S3.SS2) 里的 encoder-decoder attention 也是这种 Q 与 K/V 分别来自两侧的计算方式。

接着看看形状。假设有 $T$ 个 text token、$G$ 个 graph token，那么 $Q_tK_g^\top$ 的形状就是 $[T,G]$，每一行表示一个文本位置对各个视觉位置的关注程度。乘上形状为 $[G,d_v]$ 的 $V_g$ 之后，得到的 $Z$ 是 $[T,d_v]$。

请注意这个结果，输出仍然只有 $T$ 行，并没有变成 $T+G$ 行。多头结果拼接并经过输出投影之后，再通过残差连接融合回文本侧，更新的是 text token 的表示，graph token 并没有因此加入文字主序列，也不会在这一步被文字反向更新。

**这样后续的 text self-attention 虽然只处理文字主序列，处理的却已经是带有视觉信息的表示了。**

### cross-attn 的计算量优点

现在咱们就能解释前面那句“graph token 只需要少量处理”了。准确一点说，它不再作为主序列的一部分，经过 LLM 的每一个 self-attention 和 FFN，但 **图片编码、K/V 投影以及图文之间的 attention** 都还是要算的。 [ModServe 的架构分析](https://arxiv.org/html/2502.00937v1#S2.SS1) 讨论的正是这种处理路径的区别。

先看 prefill，也就是把输入提示一次性处理完的阶段。继续用 $T$ 表示输入文字数量、$G$ 表示图片 token 数量，$d$ 表示 attention 的总隐藏维度。先忽略 batch、多头拆分和常数，只看 $QK^\top$ 以及 attention 权重乘 V 这两部分的计算量：

| 计算部分 | decoder-only | cross-attention 架构 |
| --- | --- | --- |
| text self-attention 的主序列长度 | T+G，图文一起进入 | T，只有文字主序列 |
| self-attention 的核心计算量 | O((T+G)^2d) | O(T^2d) |
| 额外的 cross-attention 核心计算量 | 图文交互已包含在上面 | 每个 cross-attention 层为 O(TGd) |

为什么差距会大呢？把 $(T+G)^2$ 展开就是 $T^2+2TG+G^2$，其中图片 token 之间的交互也跟着进入了 LLM。cross-attention 架构则把这部分视觉内部建模主要交给 Vision Encoder，LLM 后端保留文字内部的 $T^2$ 项和文字读取图片的 $TG$ 项。

举个方便算数的例子，$T=100$、$G=1000$ 的时候，拼接序列的方阵有 $1100^2=1210000$ 个位置；一个文本 self-attention 方阵加一个 cross-attention 矩阵则有 $100^2+100\times1000=110000$ 个位置。

而且 attention 还不是全部。decoder-only 在 prefill 时，图片 token 也要经过每一层的 Q/K/V 投影和 FFN。以中间维度为 $d_{ff}$ 的普通 FFN 为例，这部分计算量是 $O((T+G)dd_{ff})$；cross-attention 架构的文字主干则只需要对 $T$ 个位置做 FFN，对应 $O(Tdd_{ff})$。新增 cross-attention block 如果有自己的 FFN，也要按实际层数另算。

前面的比较只针对 LLM 后端， **Vision Encoder 的计算量并没有被省掉。**

### cross-attn decode 的 graph cashe

需 prefill 完成之后，咱们每次生成一个新的 text token，它依然可以用自己的 Q 去查询图片 K/V。但对于同一次请求中的固定图片， **同一个 cross-attention 层的图片 K/V 不随生成步数变化，所以可以先算好并缓存，后续直接复用。** [Llama 3.2 Vision 的实现](https://github.com/huggingface/transformers/blob/main/src/transformers/models/mllama/modeling_mllama.py) 就区分了图片 K/V 的首次计算和后续缓存读取。

记当前已有的文字上下文长度为 $S$，在使用 KV Cache 的情况下，decoder-only 每一步、每个 self-attention 层的核心计算量约为 $O((S+G)d)$；cross-attention 架构则拆成文字 self-attention 的 $O(Sd)$，以及每个 cross-attention 层读取图片的 $O(Gd)$。

所以到了 decode，二者并不是一个平方、一个线性的区别了。decoder-only 也会缓存图片前缀的 K/V，并不会每生成一个字，就让全部 graph token 重新经过 FFN。cross-attention 的区别主要在于图片只在指定的层被读取，图像缓存和文字缓存也分别归属对应的注意力层；如果每层都读取图片，单看这一部分的渐近复杂度，两者仍然是同一个量级。

至此，咱们就能把两种架构和后续推理优化联系起来了：decoder-only 的图片 token 会撑长 LLM 的 prefill 序列，并占用各层的前缀 KV Cache；cross-attention 则把视觉特征放在独立路径上，文字通过指定的层去读取它。

后面分析计算量、缓存占用和调度的时候，都要先分清图片到底走的是哪条路径。
