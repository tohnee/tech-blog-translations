周6，读书日，本周推荐《大模型实战：从零实现 RAG 与 Agent 系统》。

这两年我被问得最多的一句话，是"我们公司想搭一个知识库 RAG，大概要多少钱、多长时间"。

问的人里有做外贸的、开连锁餐饮的、做医疗器械代理的，还有三四个只有七八个人的小团队。

一开始我还认真算：文档多少份、要不要切分、用哪个 embedding 模型、上线之后谁维护。

后来我不算了，改成先问三个问题：资料现在存在哪几个地方？同一份文件有几个版本？谁负责更新？

三句话之内，八成的人答不上来。

所以先把结论放前面：**90% 的企业不需要"知识库 RAG"这个项目，他们需要的是"把资料整理成机器能读的东西"。**这两件事的开销差十倍，收益也差十倍，而且顺序不能颠倒。

这里顺便给大家普及下基础知识。

什么是知识库？

什么是RAG？

这是2个不同的玩意。

知识库 = 课本、参考书，你存的资料。

RAG = 开卷考试的流程：拿到题目 → 翻书找对应段落 → 结合书本内容写答案

RAG 其实是四个工位。

第一个工位，语料。文档从哪来、干不干净、有没有重复、版本对不对。

第二个工位，切分。把长文档切成能被检索的小块。

第三个工位，检索。把小块变成向量、或者建索引，按问题把相关的内容捞出来。

第四个工位，生成。把捞出来的内容交给大模型，让它组织成一段人话。

**知识库是存储载体；RAG 是调用链路 / 技术方案。**

RAG**通常需要知识库**，但知识库不一定非要用 RAG。

知识库：管好资料，保证资料在、能查到。

RAG：解决大模型幻觉、知识过时、私有资料无法问答的问题。

很多中小企业的内部资料其实很少，并不多，只需要建立知识库，管理好知识库就足够了。

根本就不需要RAG。

现在AI读取资料的速度非常快了，把资料存入知识库，分类整理好就足够了。

大多数公司根本不需要RAG。

RAG 是一套检索 + 拼接生成的流程，有额外的维护成本。资料少的时候，上 RAG 收益很低，纯属多余。

本书缺点：讲RAG的时候应该先讲知识库，这样更容易理解。
