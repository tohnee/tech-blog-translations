## 介绍

第 13 篇：MCP 是什么，为什么值得学

**先看我们已有的工具循环，再看它差在哪**

> 读完你能明白：第 7-9 篇写的工具循环**差了什么**；MCP 怎么补上它（工具独立成 server，写一次谁都能接）；server / client / host 三个词各指谁；一次 MCP 调用 还是你的 loop，只是跨了一扇门——最后给 Claude Code 挂个现成 server，亲眼看 一次真实调用。

## 1｜工具住在 agent 里，只有自己能用

先花三十秒复习第 7-9 篇我们做的东西：给 agent 装了 5 个后台工具，循环是—— `TOOLS_SCHEMA`（工具清单）→ 模型挑一个 → `run_tool()` 调 registry 里的函数 → 结果 喂回模型。

这套东西能干活，但有一个毛病：**工具写在 `agent/tools.py` 里，只有我们的 agent 能 调用**。Claude Code 想用同一个后台？它读不到我们的 `tools.py`，只能自己再写一遍—— 每多一个 agent、每多一个系统，就多一份重复集成（术语叫 **N×M 问题**）。

## 2｜MCP 的解法：工具实现一次，装进独立的 server

**MCP（Model Context Protocol）＝一个”标准接口”**：它把工具从 agent 里**搬出去**， 装进一个叫 **server** 的独立程序；server 公布”我会这些工具”，任何 agent 都能用同一 套规矩连上来**查看、调用**。工具从此实现一次、处处可用：N×M → N+M。

（类比：早期手机各有各的充电头，充电器得各做各的；后来接口统一了，一个充电器所有 设备都能用。MCP 对”agent 用工具”做的就是这件事。）

顺着上面的话，三个角色自然就出来了：

| 角色 | 是谁 | 谁写 |
| --- | --- | --- |
| server | 装工具、提供调用的独立程序 | 我们（第 14 篇）或直接用现成的 |
| client | agent 里负责和 server 连线的那一小段 | SDK 自带，不用自己写 |
| host | agent 本身（Claude Code、我们的 agent） | — |

记法：**host 装着 client，client 连着一个 server。**

## 3｜一次调用长什么样：还是你的 loop，只是跨了一扇门

连上 server 之后，下一次工具调用一共三步：

```text
① 拿清单    server 告诉 agent："我会这些工具"（名字、说明、参数格式）
② 调工具    模型看完清单选一个，agent 替它喊"调 assign_role，参数是……"
③ 拿结果    server 执行完，把结果传回来，模型接着往下想
```

对照第 7 篇的本地 loop——**每一步都有对应物，没有任何新概念**：

| 第 7-9 篇（工具在 agent 内部） | MCP（工具在另一个进程） |
| --- | --- |
| TOOLS_SCHEMA：工具清单 | ① server 自报的清单（协议里叫 tools/list） |
| registry：函数字典、真正执行 | server 进程（就是那些函数） |
| run_tool(name, args) | ② 的调用请求（协议里叫 tools/call） |
| 返回值喂回模型 | ③ 的结果喂回模型 |

唯一的区别：工具住到了**另一个进程**里。这个”搬出去”还白得了一条边界——**server 公布多少工具，调用方至多就能用它多少工具**（第 14 篇会把后台的敏感 token 藏进 server 进程，靠的就是这一条）。

## 4｜动手感受：给 Claude Code 挂一个现成 server

先不用自己写——官方仓库就有很多现成 server（memory / filesystem / git…，社区的在 官方 **MCP Registry** 找）。挂一个 **memory**（记忆工具，正好呼应第 11 篇的长期记忆） 试试（需要 Node.js）：

```bash
claude mcp add memory -- npx -y @modelcontextprotocol/server-memory
```

然后会话里说一句：

> 用 memory 记住：我的教程项目在 tmp/agent-building-tutorial，主题是从零构建 agent。

你会看到一次完整的工具调用块（server 名 + 工具名 + 参数）。**一行代码没写，agent 就 多了一项记忆能力**——这一小块就是第 3 节那三步的完整回放，也是”写一次、谁都能接” 最直观的证据。
