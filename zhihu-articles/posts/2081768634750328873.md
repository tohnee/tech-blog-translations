### 1. 950DT 芯片架构图

### 1.1 芯片整体架构：Chiplet 多 Die 合封 + UMA 统一内存

昇腾 950DT 采用 Chiplet 多 Die 合封设计，封装内集成 **2 个 AI Die、2 个 IO Die 和 4 个高速片上内存模块**，通过 D2D Clink（Die-to-Die 互联）和 Memory Interface 连接为统一访问（UMA）整体。两个 AI Die 之间的 L2 Cache 一致性由硬件维护，软件无感知。

![](https://pic4.zhimg.com/v2-86de62dcc49edeb133b140fa092971df_r.jpg)
*图 1：昇腾 950 芯片架构示意图（来源：《昇腾950 NPU架构白皮书》）*

### 1.2 架构核心组成

950DT 基于第三代达芬奇（DaVinci v3）架构，核心子系统包括：

| 子系统 | 组成 | 关键特性 |
| --- | --- | --- |
| AI 子系统 | 36 Cube Core + 72 Vector Core | 第三代 DaVinci，新增 MXFP4/MXFP8/HiF8/FP8 低精度格式；张量浮点峰值算力提升 4× |
| AI CPU | 4 Cluster × Linx816 | ARMv8-A，物理双线程（8C16T/6C12T），跑 NPU 侧 OS、算子编译 |
| Memory 子系统 | HiZQ 2.0 片上内存 | 144GB / 4TB/s，配 128MB 全局 L2 Cache |
| 互联子系统 | 灵衢（Unified Bus）2.0 | 72 Lane HiLink SerDes，18×112Gbps，峰值 2TB/s |
| 调度 | STARS 2.0 | ns 级调度，支持 2048 条任务流下沉、算力切分 |

### 1.3 AIC/AIV 分离架构

950DT 的 AI 子系统将矩阵计算（AIC，Cube Core）与向量计算（AIV，Vector Core）分离为独立核：

- **AIC（AI Cube）**：类似 NVIDIA Tensor Core，负责稠密矩阵乘（GEMM、matmul、注意力投影、FFN 线性层等）。新增 MXFP4/MXFP8/HiF8/FP8 格式支持，FP8 提供 2× FP16 算力，MXFP4 提供 4× FP16 算力。
- **AIV（AI Vector）**：负责 elementwise/向量运算（激活函数、归一化、masking、reduction）。从 SIMD 升级为双发射 Register-Based SIMD，支持 SIMD/SIMT 混合编程。
- **双主模式**（dual-master mode）：AIC 与 AIV 可独立加载代码段并行执行，而非消息驱动的从属关系。

![](https://picx.zhimg.com/v2-d00d6406a30c95dd76ff09c4c86f61a9_r.jpg)
*图 2：AIC/AIV 分离架构（来源：CANN 文档，SemiAnalysis）*

### 1.4 AI CPU：设备端 ARM64

AI CPU 是直接访问 device 内存的设备端 ARM64 执行单元，承接分支密集控制流、标量逻辑、动态 shape 处理，以及 kernel 运行前所需的 value-dependent 调度/tiling 元数据计算。将这类不规则的控制类工作保持本地化，避免 host CPU 往返延迟。

### 1.5 CCU 通信引擎

950DT 集成专用 CCU（Collective Communication Unit）引擎，处理 AllReduce、All2All 等集合通信，支持 remote-read + reduce + local-write 与 local-read + remote-write 模式，将通信从 AI Core 算力中卸载。

### 2.2 规格差异要点分析

**950DT vs Blackwell B200**：

- **算力差距明显**：B200 的 FP8 dense 算力（4500T）是 950DT（1034T）的 4.3 倍；BF16 差距更大（2250T vs 547T，约 4.1×）。这主要源于制程差距（4NP vs ~7nm）和架构设计差异。
- **显存带宽差距**：B200 的 8TB/s 是 950DT 的 2 倍，但 950DT 的 144GB 容量与 B200 的 192GB 差距小于 910C 与 B200 的差距。
- **互联能力反超**：950DT 的灵衢 2.0 提供 2TB/s 双向带宽，超过 B200 的 NVLink5 1.8TB/s。这是 950DT 的核心优势之一。
- **功耗效率**：950DT 估算 ~600W vs B200 的 1000W，950DT 在单位功耗算力上仍然落后，但差距比绝对算力差距小。

**950DT vs 910C（代际跃迁）**：

- **FP8 从无到有**：910C 不支持 FP8，950DT 新增 FP8/MXFP8/HiF8，并达 1034 TFLOPS——这是质的飞跃。
- **BF16 算力翻倍**：950DT 的 547T vs 910C 单 Die 280T（整卡 560T），提升约 2×。
- **显存带宽提升**：950DT 的 4TB/s vs 910C 的 3.2TB/s，提升 25%。
- **互联跨越**：灵衢 2.0 的 2TB/s vs 910C 的 392GB/s（双向），提升约 5×。
- **L2 从 192MB/Die 到 128MB 全局**：910C 每 Die 独享 192MB L2，950DT 改为 128MB 全局 UMA——容量看似减少，但通过 UMA 实现统一管理，配合 4TB/s 片上内存减少了对 L2 的依赖。

### 3. 计算能力对比：从 K3 模型出发预估 Prefill/Decode 性能

### 3.1 Kimi K3 模型架构简介

Kimi K3 是目前最先进的开源大模型之一，总参数 **2.8 万亿（2.8T）**，采用 **KDA 混合线性注意力 + Attention Residuals (AttnRes)** 架构骨架，配合 **Stable LatentMoE**（896 专家激活 16，激活率 ~1.8%）。K3 从 SFT 阶段即采用 **QAT（MXFP4 权重 / MXFP8 激活）**，原生适配低精度硬件，建议在 **64+ 加速器 supernode** 上部署。

K3 的关键架构特征对硬件的需求：

| K3 架构特征 | 对硬件的需求 |
| --- | --- |
| KDA 线性注意力（O(T) 复杂度） | 降低 KV cache 显存压力，但需要高效矩阵乘 |
| AttnRes（深度方向 softmax 注意力） | 增加跨层访存，对 L2 带宽敏感 |
| 896 专家 MoE（激活率 1.8%） | All-to-all 通信密集，对互联带宽极度敏感 |
| MXFP4 权重 / MXFP8 激活 | 需要原生 FP4/FP8 算力支持 |
| 1M 上下文 | 需要大显存容量 |
| supernode 部署 | 需要大规模高带宽互联域 |

### 3.2 Prefill 性能预估

Prefill 阶段是 **compute-bound**（算力密集型），性能主要取决于芯片的峰值算力。

**算力对比（MXFP4/FP8 dense）**：

| 芯片 | FP8 算力 | MXFP4 算力 | 显存带宽 |
| --- | --- | --- | --- |
| Blackwell B200 | 4500 TFLOPS | 9000 TFLOPS | 8 TB/s |
| 950DT | 1034 TFLOPS | 2007 TFLOPS | 4 TB/s |
| 比值 (950DT/B200) | 0.23× | 0.22× | 0.50× |

**Prefill 性能推导**：

- K3 使用 MXFP4 权重 + MXFP8 激活，Prefill 的主要计算是 GEMM（QK^T、PV、FFN 线性层）。
- B200 的 MXFP4 算力是 950DT 的 ~4.5 倍，因此单卡 Prefill 吞吐约 **950DT : B200 ≈ 1 : 4.5**。
- 但 K3 是 MoE 模型，Prefill 中 MoE dispatch/combine 的 All-to-all 通信不可忽略。950DT 的灵衢 2.0（2TB/s）略超 B200 的 NVLink5（1.8TB/s），可在一定程度上弥补算力差距。
- 综合估算：**单卡 Prefill 吞吐 950DT ≈ B200 的 20%~25%**。

**950DT vs 910C Prefill**：

- 910C 不支持 FP8/FP4，只能跑 FP16，算力 280T (per Die) / 560T (整卡)。
- 950DT FP8 算力 1034T，是 910C FP16 整卡算力（560T）的 ~1.85 倍。
- 加上 950DT 的 MXFP4 能力（2007T），对 K3 的 MXFP4 权重可直接加速。
- **950D T 单卡 Prefill 约为 910C 的 1.8~3.6 倍**（取决于精度路径）。

### 3.3 Decode 性能预估

Decode 阶段是 **memory-bound**（访存密集型），性能主要取决于显存带宽和互联带宽。

**访存能力对比**：

| 芯片 | 显存带宽 | 互联带宽 | 显存容量 |
| --- | --- | --- | --- |
| Blackwell B200 | 8 TB/s | 1.8 TB/s (NVLink5) | 192 GB |
| 950DT | 4 TB/s | 2 TB/s (灵衢 2.0) | 144 GB |
| 比值 (950DT/B200) | 0.50× | 1.11× | 0.75× |

**Decode 性能推导**：

- Decode 的主要开销是权重加载（memory-bound）和 MoE All-to-all 通信。
- **显存带宽差距（2×）** 是核心瓶颈：950DT 的 4TB/s 只有 B200 的一半，意味着相同 batch size 下单卡 decode 吞吐约为 B200 的 50%。
- **互联优势（1.11×）** 可以部分弥补：K3 的 896 专家 MoE 在 EP（Expert Parallelism）部署时需要大量 All-to-all 通信，950DT 的灵衢 2.0 在这方面略占优势。
- **显存容量（144GB vs 192GB）**：950DT 可装载的 KV cache 和并发用户数较少，但在 K3 的 KDA 线性注意力下 KV cache 压力已大幅降低（O(T) vs O(T²)），容量差距影响减小。
- 综合估算：**单卡 Decode 吞吐 950DT ≈ B200 的 45%~55%**。

**950DT vs 910C Decode**：

- 950DT 显存带宽 4TB/s vs 910C 3.2TB/s（整卡），提升 25%。
- 灵衢 2.0 的 2TB/s vs 910C 的 392GB/s（双向），提升约 5×——这对 MoE decode 的 All-to-all 通信是巨大提升。
- **950DT 单卡 Decode 约为 910C 的 1.5~2 倍**（考虑带宽 + 互联双重提升）。

### 3.4 性能对比总结

| 场景 | 950DT vs B200 (单卡) | 950DT vs 910C (单卡) |
| --- | --- | --- |
| Prefill (compute-bound) | ~20%~25% | ~1.8×~3.6× |
| Decode (memory-bound) | ~45%~55% | ~1.5×~2× |
| MoE All-to-all 通信 | 1.11× 优势 | ~5× 优势 |

> **关键结论**：950DT 在单卡绝对算力上与 B200 有 4~5 倍差距（主要受制程限制），但在 Decode 场景下因 MoE 通信密集，灵衢 2.0 的互联优势可缩小差距至 ~2 倍。相比上一代 910C，950DT 实现了 FP8 从无到有、互联带宽 5 倍跃升，代际提升显著。

### 3.5 CANN 生态的 Day 0 能力

值得注意的是，在 DeepSeek V4 发布时，950DT 是仅有的两个提供 Day 0 支持的推理栈之一（另一个是 NVIDIA CUDA）。CANN 团队发布了针对 Ascend 芯片的优化指南与 benchmark 数据，DeepSeek 官方 API 的部分流量自 Day 0 起就跑在华为上。

CANN 的核心技术能力包括：

- **MC²（Merged Compute-Communication）**：融合算子，把通信与计算嵌入同一 kernel，用于 MoE dispatch/combine
- **AI CPU 元数据流**：将稀疏注意力的 value-dependent tiling 元数据计算推到设备端 ARM64，避免 host 往返
- **多流计算/通信重叠**：AIC/AIV 独立调度，shared expert 与 routed expert 100% 重叠

### 4. 超节点对比：950DT vs GB200

### 4.1 超节点规模对比

| 维度 | 昇腾 950DT (Atlas 950 超节点) | NVIDIA GB200 NVL72 |
| --- | --- | --- |
| 超节点规模 | 8192 卡 | 72 卡 (NVL72) |

| 互联域 | 灵衢 2.0 UB 域 | NVLink Switch 域 |
| 单卡互联带宽 | 2 TB/s (灵衢 2.0, 双向) | 1.8 TB/s (NVLink5, 双向) |
| 超节点总互联带宽 | 16.3 PB/s | 130 TB/s (NVLink Switch 域) |
| 时延 | ~3 μs | ~1 μs (NVLink Switch) |
| 组网拓扑 | Full Mesh / Clos / nD-Mesh | NVLink Switch (全互联) |
| 以太网出口 | UBoE 2×400Gbps | ConnectX-7 400Gbps |
| 共享内存 | UB Memory (最高 128TB) | NVLink-C2C (Grace-GPU) |

| 超节点总算力 (FP4) | 16 EFLOPS | 720 PFLOPS |
| 超节点总显存 | ~1170 TB (8192×144GB) | 13.4 TB (72×186GB) |

### 4.2 超节点架构对比分析

**规模差异的本质**：

950DT 超节点 8192 卡 vs GB200 NVL72 的 72 卡，规模相差 **114 倍**。这反映了两种截然不同的技术路线：

- **NVIDIA NVL72 路线**：在单一 NVLink Switch 域内实现 72 卡全互联，追求低时延（~1μs）、高带宽、简单部署。适合 MoE 模型的 All-to-all 通信全部留在 NVLink 域内。但扩展性受限于 NVLink Switch 级数。
- **华为灵衢路线**：通过灵衢 2.0 UB 协议构建 8192 卡的超大规模互联域，用规模补单卡性能差距。支持 Full Mesh / Clos / nD-Mesh 灵活组网，单 IO Die 内可转发，时延 ~3μs 略高。

**通信协议对比**：

| 能力 | 灵衢 2.0 (华为) | NVLink5 (NVIDIA) |
| --- | --- | --- |
| 同步访存 | UB Memory (Load/Store/Atomic) | NVLink-C2C (仅 Grace-GPU) |
| 异步访存 | URMA | NVLink 不可直接对比 |
| 集合通信加速 | CCU 引擎（硬件卸载） | NCCL（软件实现） |
| 以太网接入 | UBoE (UB 协议直入以太网) | 需独立 NIC |
| 内存池化 | UB Memory 最高 128TB 共享 | Grace 统一内存 |

**超节点性能对比（以 K3 模型推理为参考）**：

K3 建议 64+ 加速器 supernode 部署。两种超节点方案对 K3 推理的影响：

| 维度 | 950DT 超节点 (8192卡) | GB200 NVL72 (72卡) |
| --- | --- | --- |
| MoE All-to-all 域 | 8192 卡全在灵衢域 | 72 卡全在 NVLink 域 |
| 专家权重摊薄 | 8192 卡 → 极致摊薄 | 72 卡 → 良好摊薄 |
| EP 宽度 | 可开极宽 EP (EP=256+) | EP=72（NVLink域内） |
| 通信时延 | ~3μs | ~1μs |
| 跨域通信 | 灵衢域内完成 | 超 72 卡需走 scale-out |
| K3 Prefill 性能 | 算力受限（单卡弱），但 EP 宽度优势大 | 单卡算力强，EP 受限于 72 卡 |
| K3 Decode 性能 | 带宽受限但互联域大 | 带宽强但域小 |

### 4.3 超节点功耗与能效

| 指标 | 950DT 超节点 | GB200 NVL72 |
| --- | --- | --- |
| 单卡 TDP | ~600W | ~1200W |
| 超节点总功耗 | ~4.9 MW (8192×600W) | ~86 kW (72×1200W) |
| FP8 算力/功耗 | ~1.6 PFLOPS/kW | ~4.2 PFLOPS/kW |
| FP4 算力/功耗 | ~3.3 PFLOPS/kW | ~8.4 PFLOPS/kW |

> **能效差距**：B200 的每千瓦 FP8 算力约 950DT 的 2.6 倍，这与制程差距直接相关。但 950DT 的超节点用规模把总算力推到 8 EFLOPS（FP8），绝对算力不弱。

### 4.5 关键差异总结

| 维度 | 950DT 超节点 | GB200 NVL72 |
| --- | --- | --- |
| 核心策略 | 用规模补单卡差距 | 用单卡性能 + 小域低时延 |
| 适用场景 | 超大规模 MoE 训练/推理 | 中大规模 MoE 推理 |
| 扩展性 | 8192→128K+ 卡 | 72→576 卡 |
| 时延 | 较高 (~3μs) | 极低 (~1μs) |
| 组网灵活性 | Full Mesh/Clos/nD-Mesh | NVLink Switch 固定拓扑 |
| 通信卸载 | CCU 硬件引擎 | NCCL 软件栈 |
| 内存池化 | UB Memory 128TB | Grace 统一内存 |
| 软件生态 | CANN (Day 0 可用，生态待成熟) | CUDA (生态成熟) |
| 能效 | ~1.6 PFLOPS/kW (FP8) | ~4.2 PFLOPS/kW (FP8) |

> **核心结论**：950DT 超节点的策略是”以规模换性能”——单卡制程受限时，通过 8192 卡的灵衢 2.0 互联域，把总算力推到 8 EFLOPS（FP8）。GB200 NVL72 则是”以单卡性能 + 低时延取胜”——72 卡 NVLink 域内时延极低，适合对延迟敏感的 MoE 推理。两者各有适用场景：950DT 超节点适合大规模训练和吞吐型推理；GB200 NVL72 适合交互式推理和低延迟场景。
