## 一、Docker 是如何工作的？

下图展示了 Docker 的架构以及当运行“docker build”、“docker pull”和“docker run”时它是如何工作的。

![](https://picx.zhimg.com/v2-83f4d1b1e326fde9e341a476490ed7f7_r.jpg)

Docker 架构中有 3 个组件：

- **Docker 客户端**<br>Docker 客户端与 Docker 守护进程进行通信。
- **Docker 主机**<br>Docker 守护进程监听 Docker API 请求，并管理 Docker 对象，如图像、容器、网络和卷。
- **Docker 镜像仓库**<br>Docker 镜像仓库存储 Docker 图像。Docker Hub 是一个公共镜像仓库，任何人都可以使用。

以“docker run”命令为例。

1. Docker 从镜像仓库中拉取镜像。
2. Docker 创建一个新的容器。
3. Docker 为容器分配一个可读写文件系统。
4. Docker 创建一个网络接口，将容器连接到默认网络。
5. Docker 启动容器。

### **1. Docker 核心概念**

学习 Docker 的基本概念，以实现高效的应用部署。

![](https://pic4.zhimg.com/v2-7020f31a7e12189c5fb86403a9ddb70b_r.jpg)

- **Dockerfile**<br>它包含构建 Docker 镜像的指令，通过指定基础镜像、依赖项和运行命令。
- **Docker 镜像**<br>一个轻量级、独立的软件包，包含运行您的应用程序所需的所有内容（代码、库和依赖项）。镜像是从 Dockerfile 构建的，可以进行版本控制。
- **Docker 容器**<br>一个 Docker 镜像的运行实例。容器彼此隔离，并与主机系统隔离，为运行您的应用程序提供了一个安全且可重复的环境。
- **Docker Registry**<br>一个用于存储和分发 Docker 镜像的集中式仓库。例如，Docker Hub 是默认的公共仓库，但你也可以设置私有仓库。
- **Docker Volumes**<br>一种持久化容器生成数据的方式。卷位于容器的文件系统之外，并且可以在多个容器之间共享。
- **Docker Compose**<br>一个用于定义和运行多容器 Docker 应用程序的工具，使管理整个堆栈变得简单。
- **Docker 网络**<br>用于启用容器和主机系统之间的通信。自定义网络可以隔离容器或启用选择性通信。
- **Docker 命令行界面**

与 Docker 交互的主要方式，提供用于构建镜像、运行容器、管理卷以及执行其他操作的命令。

### **2. Docker 最佳实践**

介绍 9 个高效的容器化 Docker 最佳实践。

![](https://pic4.zhimg.com/v2-902739b9befcf78cbdec7008f6581a6b_r.jpg)

1. **使用官方镜像**<br>这确保了安全性、可靠性和定期更新。
2. **使用特定的镜像版本**<br>默认的 latest 标签是不可预测的，并会导致意外行为。
3. **多阶段构建**<br>通过排除构建工具和依赖关系来减小最终镜像的大小。
4. **使用.dockerignore**<br>排除不必要的文件，加快构建速度，并减小镜像大小。
5. **使用最低权限用户**<br>通过限制容器权限来增强安全性。
6. **使用环境变量**<br>提高跨不同环境的灵活性和可移植性。
7. **缓存顺序很重要**<br>将步骤按从最不频繁变化到最频繁变化的顺序排列以优化缓存。
8. **为你的镜像打标签**<br>这有助于组织并方便镜像管理。
9. **扫描镜像**

在安全问题变得更大之前发现它们。

## 二、 什么是 Kubernetes (k8s)？

k8s 是一个容器编排系统。它用于容器的部署和管理。其设计深受 Google 内部系统 Borg 的影响。

![](https://pic3.zhimg.com/v2-be14b4ba860873ad0174ceb1fec6ba4a_r.jpg)

一个 k8s 集群由一组运行容器化应用程序的工作机器（称为节点）组成。每个集群至少有一个工作节点。

工作节点托管应用程序工作负载的组件——Pod。控制平面管理集群中的工作节点和 Pod。在生产环境中，控制平面通常在多台计算机上运行，并且集群通常运行多个节点，以提供容错和高可用性。

**（一）控制平面组件**

- **API 服务器**<br>API 服务器与 k8s 集群中的所有组件进行通信。对 Pod 的所有操作都是通过与 API 服务器进行通信来执行的。
- **调度器**<br>调度器监视 Pod 上的工作负载，并将负载分配给新创建的 Pod。
- **控制器管理器**<br>控制器管理器运行控制器，包括节点控制器、作业控制器、端点切片控制器和服务账户控制器。
- **etcd**<br>etcd 是一个键值存储，用作 Kubernetes 的所有集群数据后端存储。<br>**（二）节点**
- **Pods**<br>Pod 是一组容器的集合，是 k8s 管理的最小单元。Pod 中的每个容器都应用了单个 IP 地址。
- **Kubelet**<br>在每个集群节点上运行的代理。它确保容器在 Pod 中运行。[1]
- **Kube Proxy**

kube-proxy 是在每个集群节点上运行的网络代理。它将来自服务的流量路由到节点。它将工作请求转发到正确的容器。

### **1. Kubernetes服务类型**

下图展示了暴露服务的四种方式。

![](https://pica.zhimg.com/v2-150deb9ed9f53b6d012aafa19c2d520e_r.jpg)

在 Kubernetes 中，服务是一种在集群中暴露网络应用的方法。我们使用服务来使一组 Pod 在网络上可用，以便用户可以与其交互。

Kubernetes 服务有四种类型：ClusterIP、NodePort、LoadBalancer 和 ExternalName。服务规范中的“type”属性决定了服务如何暴露给网络。

- **ClusterIP**<br>ClusterIP 是默认且最常见的服务类型。Kubernetes 会为 ClusterIP 服务分配一个集群内部的 IP 地址。这使得该服务仅在集群内部可访问。
- **NodePort**<br>通过在 ClusterIP 之上添加一个集群范围的端口，将服务暴露在集群外部。我们可以通过 NodeIP:NodePort 来请求该服务。
- **负载均衡器**<br>使用云服务提供商的负载均衡器将服务对外暴露。
- **外部名称**

这将对一个 Service 映射到一个域名。这通常用于在 Kubernetes 中创建一个服务来表示一个外部数据库。

### 2. Kubernetes 部署策略

探索 Kubernetes 部署策略，实现应用程序的无缝更新。<br>

![](https://pic3.zhimg.com/v2-71c5f947fd52698da3ce00e78ab2a4e2_r.jpg)

<br>每种策略都提供了一种独特的方法来管理更新。

| 策略名称 | 描述 | 停机时间 | 使用场景 |
| --- | --- | --- | --- |
| 重新创建 | 所有现有实例将一次性终止，并创建带有更新版本的新实例。 | 是 | 非关键应用程序或初始开发阶段 |
| 滚动更新 | 应用程序实例逐个更新，确保更新过程中保持高可用性。 | 无 | 定期发布 |
| 影子 | 一份实时流量被重定向到新版本进行测试，而不会影响生产用户。这是最复杂的部署策略，涉及建立模拟服务以与部署的新版本进行交互。 | 无 | 在真实环境中验证新版本的性能和行为 |
| 金丝雀发布 | 新版本将在全面部署之前，先向部分用户或服务器发布以进行测试。 | 无 | 对部分用户进行影响验证 |
| 蓝绿部署 | 维护两个相同的运行环境：一个为当前版本（蓝色），另一个为更新版本（绿色）。流量首先从蓝色开始，然后切换到准备好的绿色环境以使用更新版本。 | 无 | 高风险更新 |
| A/B 测试 | 在多个用户上同时测试多个版本，以比较性能或用户体验。 | 不直接适用 | 优化用户体验 |

### **3. Kubernetes 设计模式**

下面**介绍下Kubernetes 的 10 个设计模式**

![](https://pica.zhimg.com/v2-ae00c1e831ba5888855b9d590326b824_r.jpg)

**（一）基础模式**

这些模式是应用程序在 k8s 上自动化的基本原理，无论应用程序的性质如何。

- **健康探测模式**<br>这种模式要求每个容器都必须为平台管理应用程序实现可观察的 API。
- **可预测需求模式**<br>这种模式要求我们声明应用程序需求和运行时依赖项。每个容器都应该声明其资源配置文件。
- **自动放置模式**<br>该模式描述了 Kubernetes 调度算法的原则。<br>**（二）结构模式**<br>这些模式专注于在 Pod 中结构和组织容器。
- **初始化容器模式**<br>这种模式为初始化相关的任务拥有独立的生命周期。
- **边车模式**<br>这种模式在不改变容器的情况下扩展其功能。<br>**（三）行为模式**<br>这些模式描述了 Pod 的生命周期管理。根据工作负载的类型，它可以作为服务或批处理作业运行。
- **批处理作业模式**<br>该模式用于管理隔离的原子工作单元。
- **有状态服务模式**<br>这种模式用于创建分布式有状态的应用程序。
- **服务发现模式**<br>这种模式描述了客户端如何发现服务。<br>**（四）高层模式**<br>这些模式专注于高层应用管理。
- **控制器模式**<br>这种模式监控当前状态，并与声明的目标状态进行协调。
- **操作模式**

该模式以算法和自动化的形式定义操作知识。
