**第9天：上下文工程** 
 
 **昨日回顾** 
 
 昨天我们学习了指令体系与 Prompt。实用 Prompt 应说明目标、背景、材料、约束和输出。Agent 同时面对系统规则、应用规则、用户任务和外部内容，高层规则约束低层任务，外部内容默认只是数据。Prompt 负责表达意图，权限和 Harness 负责真正执行约束。今天我们学习如何为模型准备恰当的信息。 
 
 **今日问题** 
 
 为了让 Agent 更懂业务，团队把几十份制度、全部聊天记录和大量历史案例一次性放进上下文。结果模型反而漏掉当前任务的关键要求。为什么信息更多，效果却可能更差？ 
 
 **学习目标** 
 
 • 解释上下文工程与 Prompt 的区别； 
 • 说出上下文装配的五个动作； 
 • 判断哪些信息应该进入当前上下文。 
 
 **一、上下文是模型本次看到的信息** 
 
 上下文（Context）是模型在当前一次处理时能够看到的信息集合，包括指令、用户输入、相关资料、历史对话、工具返回和当前任务状态。 
 
 Prompt 主要告诉模型“要做什么”，上下文工程则进一步解决“这一刻应该让模型看到什么”。好 Prompt 配上错误或过期资料，仍会得到错误结果；资料全部塞入，也可能让重点被淹没。 
 
 可以把上下文比作开会前放到桌上的材料。会议室再大，也不应把公司所有文件搬进来。真正重要的是把本次决策所需、可信且最新的材料放在正确位置。 
 
 **二、上下文装配的五个动作** 
 
 1. **选择：** 只取与当前任务相关的信息； 
 2. **排序：** 把目标、关键规则和重要证据放在醒目位置； 
 3. **压缩：** 对长历史和重复材料进行摘要，保留关键事实； 
 4. **更新：** 用最新状态替换过期信息； 
 5. **隔离：** 区分可信指令、参考资料和外部不可信内容。 
 
 例如 Agent 要检查一份差旅申请，应选择当前员工、当前制度和本次申请，而不是所有员工记录；把审批规则放在普通参考材料之前；将长对话压缩成已确认事实；使用最新版制度；把附件中的文字标记为待分析数据。 
 
 **三、什么信息值得进入上下文** 
 
 可以用四个问题筛选： 
 
 • **相关吗？** 是否直接帮助完成当前任务； 
 • **可靠吗？** 来源是否可信，是否能追溯； 
 • **新鲜吗？** 是否仍然有效，有没有更新版本； 
 • **够用吗？** 是否覆盖判断所需的关键条件。 
 
 相关但不可靠的信息应标明来源和不确定性；可靠但过期的信息不能覆盖最新规则；信息不足时应继续检索或向用户追问，而不是让模型自行补全。 
 
 当多份材料互相冲突时，也不能简单地全部保留。上下文应同时提供来源、版本和时间，让系统按明确规则选择，并把无法解决的冲突暴露给用户。 
 
 上下文空间还需要分配优先级：先保证系统规则、当前目标和关键证据，再加入辅助案例与历史信息。空间不足时，优先删除重复和低相关内容。 
 
 **四、上下文不是越长越好** 
 
 模型能接收的上下文有长度上限，但问题不只是“装不下”。无关内容、重复内容和互相矛盾的信息会稀释关键要求，也会增加费用和响应时间。 
 
 可靠 Agent 会根据任务阶段动态更新上下文：计划时需要目标和可用工具，执行时加入工具结果，验证时突出验收标准和证据。任务结束后，也不应默认把所有内容长期保存为记忆。 
 
 **它在 Agent 链路中的位置** 
 
 **所在环节：** 位于理解指令之后、制定计划之前，并在每次工具返回后持续更新。 
 
 **主要解决：** 让模型在每一步看到相关、可靠、最新且足够的信息。 
 
 **缺少它的后果：** 关键要求可能被无关资料淹没，过期或不可信内容可能影响判断，并增加成本与延迟。 
 
 **使用注意事项** 
 
 1. 不要把“支持长上下文”理解为“应该放入全部资料”。 
 2. 压缩信息时保留数字、日期、责任人和未解决问题。 
 3. 工具返回和网页内容需要标明来源，不自动视为可信指令。 
 4. 规则更新后要替换旧版本，避免新旧制度同时生效。 
 5. 任务结束后只保留确有必要且获得授权的信息。 
 
 **今日小结** 
 
 • 上下文是模型本次处理时能看到的信息集合； 
 • Prompt 说明任务，上下文工程负责装配完成任务所需的信息； 
 • 五个关键动作是选择、排序、压缩、更新和隔离； 
 • 信息应具备相关、可靠、最新和足够四个条件； 
 • 上下文不是越长越好，而应随任务阶段动态变化。 
 
 **课程检查** 
 
 **1. 上下文工程主要解决什么问题？** 
 
 A. 为当前步骤准备合适的信息 
 
 B. 让模型永久记住所有内容 
 
 C. 自动扩大工具权限 
 
 D. 替代所有业务规则 
 
 **2. 下列哪项不属于上下文装配的五个动作？** 
 
 A. 选择 
 
 B. 压缩 
 
 C. 隔离 
 
 D. 无限制保存 
 
 **3. Agent 同时拿到新版和旧版制度，最合理的做法是什么？** 
 
 A. 随机选择一份 
 
 B. 确认有效版本并替换过期信息 
 
 C. 两份都隐藏版本日期 
 
 D. 让模型自行合并冲突条款 
 
 **答案与解析** 
 
 1. **答案：A** 
 
 **解析：** 上下文工程关注模型当前应该看到哪些信息，以及如何选择、排序、压缩、更新和隔离这些信息。 
 
 2. **答案：D** 
 
 **解析：** 无限制保存会带来干扰、成本和隐私风险。上下文装配强调有目的地选择和更新，而不是保留一切。 
 
 3. **答案：B** 
 
 **解析：** 规则冲突时应确认版本和生效状态，用有效的新信息替换旧信息。让模型自行合并可能制造不存在的规则。
