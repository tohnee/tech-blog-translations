## 为什么开始补端侧AI基础

自己主要是做嵌入式音视频应用开发，最近开始接触端侧AI，在RK3576、BM1688这一类平台上跑模型，实际的Demo已经能把模型跑起来，但不少代码是Codex完成的，遇到Tensor、Letterbox、NMS概念时，只知道代码怎么调用，不理解为什么。因此决定先不研究复杂的神经网络数学，而是先把“一次完整推理流程”梳理清楚。

这篇先不讨论模型内部是怎么提取特征的，只讨论数据如何进入模型，以及模型输出如何最终变成业务结果。

## 模型不能直接“吃”解码出来的视频帧

![](https://picx.zhimg.com/v2-7aa051fc0c0dfacf9093fcb2f100d5f5_r.jpg)

### 从码流到图像

我们知道视频常用H.264/H.265编码，而这里讨论的目标检测模型，通常处理的是一张张图像的数据。接收到的码流经过解码后，一般得到YUV格式的图像，例如NV12，而模型通常要求RGB等格式，因此还需要按模型要求进行颜色转换。另外，图像尺寸也要满足模型的输入要求，本文先以固定输入尺寸640×640为例。最终，图像数据会被组织成**张量（Tensor）**，作为模型的输入。这些处理有时由应用完成，有时由平台的推理接口封装完成。

### Tensor是什么

Tensor可以先理解为用来存放数据的多维数组，模型的输入、内部计算结果和输出都可以用Tensor表示。以采用NCHW布局的输入[1,3,640,640]为例：1表示批次大小，即这次输入一张图片；3表示通道数；两个640分别表示图像的高度和宽度。如果模型要求RGB，那么这三个通道就分别对应R、G、B。这里的[1,3,640,640]叫作shape，也就是张量的形状。需要注意**RGB/BGR 讨论通道顺序，HWC/CHW 讨论维度排列，这是两个不同的要求。** 比如，CHW 也可以按 B、G、R 三个通道依次存放。假设一张RGB图像只有3个像素，数据连续存放，拿它举例：

![](https://pic1.zhimg.com/v2-b65492ec102bd237200ecac16fac4050_r.jpg)

需要注意区分Tensor和Shape的区别：**Tensor 是数据本身的载体；shape 只是描述这个 Tensor 形状的一个属性** [1,3,640,640]只是它的shape，而真正的Tensor里面实际装了1x3x640x640个数。那自然而然就引出了另一个问题，每个数又是什么类型，这就是dtype的作用了。例如，uint8图像数据的取值范围是0～255；有些模型需要先转成float32，再除以255.0，将数值缩放到0～1。所以一个真正的Tensor需要以下内容：

```cpp
Tensor
├── data：里面到底有哪些数值
├── shape：这些数值组织成什么形状
├── dtype：每个数是什么类型
└── layout：各个维度分别代表什么、数据怎样排列
从C++的角度想象可以描述为以下结构体
struct Tensor {
    void* data;          // 真正的数据
    int shape[4];        // [1,3,640,640]
    DataType dtype;      // float32，转成 float32 不会自动把数值缩放到 0～1
    Layout layout;       // NCHW
};

```

## 为什么目标检测常用 Letterbox

假设模型所需尺寸是640×640，而解码后的图像是1920×1080。保持宽高比缩放，将宽度缩到640后，高度就是360。如果再单独把高度拉到640，就会改变原来的宽高比。因此，Letterbox的做法是等比例缩放之后再补边，这个例子中上下各补140像素，得到640×640。

缩放和补边都会改变坐标。如果输出框使用的是这张640×640输入图的像素坐标，那么画回原图之前，就需要先减去补边偏移，再除以缩放比例。这个例子中，横坐标为x原=x输入÷(1⁄3)，纵坐标为y原=(y输入−140)÷(1⁄3)。

## 一次完整目标检测有哪些阶段

前面说到了图像通过预处理得到了模型所需要的Tensor，模型的整个推理过程可以将其看成一个函数，输入是预处理后的Tensor，这个函数的输出是一个或多个Tensor。将输出 Tensor 解析、筛选，并转换成可以使用的检测结果，经过后处理得到了检测到的类别和置信度以及检测物体的坐标；有了这一系列的数据就是和业务挂钩了，可以在GUI中画框显示、告警上报等等

## 示例中的 YOLO 输出为什么可以看成 `[1,8400,84]`？

![](https://pica.zhimg.com/v2-0c7fb1ecd135283543de90d2a868861e_r.jpg)

这组输出张量是如何得到的，1比较好理解，就是指批次大小；这个8400是如何而来呢，其实是来自三个尺度的特征图，可以这样理解，YOLO去预测的时候并不是一个像素点一个像素点去预测的，而是按照特征图的尺寸去预测的，这里的stride可以理解为特征图相对输入图像的下采样倍数。以stride=8为例，640×640的输入对应80×80的特征图，也就是6400个预测位置。同理，stride为16、32时，分别有1600、400个预测位置，加起来就是8400。每个位置并不只看输入图中一个固定的8×8小块。一般来说，较小的stride保留了更密集的空间信息，有利于检测小目标；多个尺度配合，用来兼顾不同大小的目标。当然stride的大小有利于检测目标的大小。

84指每个预测位置输出84个数，自然而然想到检测区域的位置和大小，这可以用4个数来表示，即bbox；剩下的80个数对应80个类别（并非YOLO只能识别80类）的分数，分数越高就表示它越像这个类别。

这8400个位置给出的是候选预测，并不代表图中有8400个物体。先通过置信度阈值过滤掉分数较低的预测，再通过NMS减少重复框。常见做法是按类别优先保留高分框，用IoU（两个框的交集面积除以并集面积）衡量重叠程度，抑制与已保留框重叠过高的其他候选框。最后将坐标还原到原图，得到用于画框或业务处理的检测结果。这些结果仍可能存在误检和漏检。。
