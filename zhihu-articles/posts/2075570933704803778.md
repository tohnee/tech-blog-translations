这两年我们经常听到几个词：

- 大模型
- RAG
- Agent
- LoRA
- SFT
- Fine-tuning
- 模型微调

但对于刚接触 AI 的同学来说，很容易产生一个疑问：

> ChatGPT、DeepSeek、Qwen 这些模型已经这么聪明了，为什么还需要微调？

甚至很多人会把：

```text
Prompt
RAG
微调
训练模型
```

完全混在一起。

所以这篇文章不准备一上来就堆理论。

我们从最简单的问题开始，一步一步搞明白：

```text
1. 什么是模型微调？
2. 为什么要微调？
3. 什么情况下根本不应该微调？
4. 微调到底修改了模型的什么东西？
5. LoRA 为什么可以降低微调成本？
6. 数据集长什么样？
7. 如何真正微调一个小模型？
8. 微调完成以后怎么测试？
9. Ollama 在这个过程中负责什么？
```

最后我们会亲手跑一次小模型微调。

## 一、先理解什么叫模型微调

假设现在有一个已经训练好的大模型：

```text
Qwen
Llama
Gemma
DeepSeek
```

它已经掌握了大量通用知识。

比如你问：

```text
什么是 Redis？
```

它可能回答：

```text
Redis 是一个高性能的内存键值数据库，
常用于缓存、消息队列、分布式锁等场景。
```

这没有问题。

但假设你的公司内部规定：

> 所有技术问题必须用非常简洁的方式回答，并且最后给出一个 Java 示例。

这时候普通模型可能不知道这个规定。

怎么办？

最简单的方法当然是 Prompt。

例如：

```text
你是一名 Java 技术专家。

回答所有问题时：

1. 使用中文。
2. 控制在 300 字以内。
3. 给出 Java 示例。
4. 最后总结三个关键点。
```

这样已经可以改变模型行为。

但是如果你有成千上万个请求，每一次都必须塞一大段 Prompt，就开始有问题了。

例如：

```text
Token 成本增加
Prompt 越来越复杂
输出风格不稳定
不同业务要求越来越多
```

于是我们可能希望：

> 能不能直接让模型“学会”这种回答方式？

这就是微调。

---

## 二、什么是 Fine-tuning？

Fine-tuning 中文一般叫：

```text
微调
```

核心思想非常简单：

> 在已经训练好的模型基础上，用自己的数据继续训练一小段时间。

注意这里有一个非常重要的词：

```text
继续训练
```

不是：

```text
从零训练。
```

例如一个模型原本训练使用了：

```text
几万亿 Token
```

我们不可能重新训练一次。

而是拿已经训练完成的模型：

```text
Base Model
```

然后准备例如：

```text
1000 条
5000 条
10000 条
```

自己的数据。

继续训练。

最终得到：

```text
原始模型
    ↓
自己的数据
    ↓
Fine-tuning
    ↓
定制模型
```

可以简单理解成：

```text
大学毕业生
    ↓
进入公司
    ↓
岗位培训
    ↓
公司的专业员工
```

预训练负责的是：

```text
大学教育
```

微调负责的是：

```text
岗前培训
```

---

## 三、为什么需要微调？

这是学习 Fine-tuning 时最重要的问题。

很多人一看到模型回答得不好，第一反应就是：

> 我要微调。

这是错误的。

微调并不是万能药。

通常微调主要解决下面几类问题。

---

## 四、场景一：让模型形成固定的回答风格

例如普通模型：

```text
用户：Redis 有什么作用？
```

回答可能非常长：

```text
Redis 是一个开源的基于内存的数据结构存储系统，
支持字符串、哈希、列表、集合、有序集合等数据结构……
```

但是你希望自己的模型永远这样回答：

```text
Redis 主要解决三个问题：

1. 缓存
2. 分布式锁
3. 高速数据访问

例如 Java 项目中可以使用 Spring Data Redis。
```

如果你的训练集中存在大量这种回答：

```text
问题
→
固定风格答案
```

模型就会逐渐学会这种输出方式。

这就是微调很典型的作用：

```text
学习输出模式
```

---

## 五、场景二：让模型学会特定任务

例如你正在做一个客服系统。

用户可能输入：

```text
我的订单怎么还没有发货？
```

普通大模型可能回答：

```text
您可以登录订单页面查看物流信息……
```

但是你的业务需要模型输出：

```text
{
  "intent": "query_shipping",
  "priority": "normal"
}
```

再比如：

```text
我要退款
```

需要输出：

```text
{
  "intent": "refund",
  "priority": "high"
}
```

这种任务非常适合微调。

因为本质上它是：

```text
自然语言
    ↓
固定规则
    ↓
结构化输出
```

经过大量训练之后，模型可能非常稳定地输出这种结构。

---

## 六、场景三：学习某个领域的表达方式

例如：

```text
法律
医疗
金融
编程
客服
电商
游戏
```

不同领域都有自己的术语和表达习惯。

比如一个普通模型可能写：

```text
系统出现问题。
```

而一个运维领域模型可能更习惯：

```text
当前故障初步判断为上游服务超时，
建议进一步检查 Nginx upstream 与服务端连接池状态。
```

微调可以让模型：

```text
更像某个领域的人说话。
```

---

## 七、什么情况不要微调？

这里非常重要。

假设你有一本公司产品手册：

```text
product.pdf
```

里面写着：

```text
VIP 套餐价格：399 元
有效期：1 年
```

你希望 AI 能回答：

```text
VIP多少钱？
```

有人会想：

> 把这份 PDF 拿去微调。

其实通常没有必要。

因为价格可能下个月变成：

```text
499 元。
```

难道模型重新训练一次？

显然不合理。

这种场景更适合：

```text
RAG
```

也就是：

```text
用户提问
   ↓
搜索知识库
   ↓
找到相关资料
   ↓
把资料交给模型
   ↓
生成回答
```

因此可以记住一个非常简单的判断原则。

### Prompt

如果只是：

```text
告诉模型怎么回答
```

先使用 Prompt。

---

### RAG

如果是：

```text
告诉模型最新知识是什么
```

优先使用 RAG。

---

### Fine-tuning

如果是：

```text
希望模型改变回答习惯、任务能力或者输出模式
```

再考虑 Fine-tuning。

Hugging Face 官方的 PEFT 文档实际上也建议类似路线：先看看 Prompt 能不能解决，再考虑参数高效微调，而不是所有问题直接训练模型。

简单记：

```text
Prompt = 教模型这次怎么做

RAG = 给模型资料看

Fine-tuning = 改变模型做事的习惯
```

这是理解微调非常关键的一句话。

---

## 八、模型到底是怎么“学习”的？

接下来开始进入原理。

但我们不搞复杂数学。

首先理解一个事实：

> 大语言模型本质上是在预测下一个 Token。

比如输入：

```text
中国的首都是
```

模型内部可能计算：

```text
北京     0.93
上海     0.03
深圳     0.01
广州     0.01
其他     0.02
```

于是最终输出：

```text
北京
```

如果输入：

```text
1 + 1 =
```

模型可能计算：

```text
2      0.98
3      0.01
4      0.005
其他   0.005
```

所以大模型看起来像是在：

```text
思考
```

但从最底层看，其核心过程仍然可以粗略理解为：

```text
输入 Token
   ↓
神经网络
   ↓
计算概率
   ↓
预测下一个 Token
```

然后继续：

```text
Token 1
↓
Token 2
↓
Token 3
↓
Token 4
```

不断预测。

最终形成整句话。

---

## 九、那训练到底是在干什么？

假设训练数据是：

```text
用户：Java 中 HashMap 是线程安全的吗？

助手：不是。
```

模型第一次训练时可能预测：

```text
是
```

但正确答案是：

```text
不是
```

于是系统会计算：

```text
预测结果
vs
正确答案
```

两者之间的差距。

这个差距通常叫：

```text
Loss
```

损失。

例如：

```text
正确答案：不是

模型预测：
是      70%
不是    20%
可能    10%
```

Loss 就会比较高。

训练算法随后调整模型参数。

下一次可能变成：

```text
是      20%
不是    70%
可能    10%
```

继续训练。

最终可能变成：

```text
是       2%
不是    97%
可能     1%
```

整个训练过程其实就是：

```text
输入数据
   ↓
模型预测
   ↓
计算 Loss
   ↓
反向传播
   ↓
调整参数
   ↓
再次预测
```

不断循环。

---

## 十、模型参数是什么？

你可能经常听到：

```text
7B
14B
32B
70B
```

这里：

```text
B = Billion
```

例如：

```text
7B ≈ 70 亿参数
```

可以把参数简单理解成神经网络内部大量的：

```text
数字
```

例如：

```text
0.18372
-0.7281
1.2283
0.00042
……
```

这些数字共同决定：

```text
输入一句话之后，
模型最终认为哪个 Token 的概率最高。
```

训练模型，本质上就是：

```text
不断调整这些数字。
```

---

## 十一、为什么普通人很难做全参数微调？

假设你有一个：

```text
7B
```

模型。

如果我们进行 Full Fine-tuning：

```text
70 亿参数
```

都可能需要参与训练。

训练时除了模型参数以外，还需要保存：

```text
梯度
Optimizer 状态
Activation
训练缓存
```

显存消耗会非常大。

这也是为什么传统全参数微调对普通开发者来说成本比较高。

于是出现了一个非常重要的技术：

## LoRA

全称：

```text
Low-Rank Adaptation
```

低秩适配。

---

## 十二、LoRA 是什么？

LoRA 是目前非常常见的一种参数高效微调方法。

它的思路非常聪明。

原来的模型参数：

```text
W
```

先不修改。

也就是：

```text
冻结。
```

然后旁边增加两个非常小的矩阵：

```text
A
B
```

最终：

```text
W'
=
W + BA
```

其中：

```text
W
```

还是原来的模型。

真正训练的是：

```text
A
B
```

Hugging Face 对 LoRA 的解释也是：冻结原始预训练权重，通过两个较小的低秩矩阵学习权重变化，从而大幅减少真正需要训练的参数数量。

可以把它理解成：

```text
原模型
████████████████████████

LoRA
██
```

我们不重新修改整个模型。

只训练一个：

```text
补丁。
```

因此：

```text
Base Model
+
LoRA Adapter
=
微调后的效果
```

---

## 十三、举一个更加直观的例子

假设原始模型是一个员工。

它已经掌握：

```text
中文
英语
数学
Java
Python
Linux
数据库
```

你并不想：

```text
把他大脑重新训练一次。
```

你只是给他一本：

```text
《公司客服工作手册》
```

告诉他：

```text
以后客服问题按照这个方式回答。
```

LoRA 就有点像：

```text
这本工作手册。
```

原始能力保留。

增加少量新的行为模式。

因此 LoRA 有一个非常大的优势：

```text
一个 Base Model
+
客服 LoRA
+
编程 LoRA
+
法律 LoRA
+
金融 LoRA
```

可以共享一个基础模型。

Hugging Face 的 PEFT 也是围绕这种“只训练少量额外参数”的方式设计的，从而显著降低训练和存储成本。

## 十四、我们现在真正做一次微调

接下来不再只讲理论。

我们真正训练一个模型。

整个流程：

```text
准备模型
   ↓
准备数据集
   ↓
Tokenizer
   ↓
加载 Base Model
   ↓
插入 LoRA
   ↓
训练
   ↓
保存 Adapter
   ↓
加载 Adapter
   ↓
测试模型
```

## 十七、准备训练数据

创建：

```text
train.json
```

例如：

```text
[
  {
    "instruction": "什么是 Redis？",
    "output": "一句话：Redis 是一个高性能内存数据库。\n\n核心用途：缓存、分布式锁、排行榜。"
  },
  {
    "instruction": "什么是 MySQL？",
    "output": "一句话：MySQL 是一个关系型数据库。\n\n核心用途：存储结构化业务数据。"
  },
  {
    "instruction": "什么是 Docker？",
    "output": "一句话：Docker 是一个容器化工具。\n\n核心用途：让应用及其运行环境一起打包和部署。"
  }

```

注意这里。

我们故意让答案保持同一种格式：

```text
一句话：XXX

核心用途：XXX
```

为什么？

因为我们想让模型学习：

```text
回答风格。
```

如果你的训练数据一会儿：

```text
100 字
```

一会儿：

```text
3000 字
```

一会儿中文：

```text
你好
```

一会儿英文：

```text
Hello
```

模型就不知道到底应该学习什么。

## 十八、数据质量比数据数量更加重要

这是做微调非常重要的一点。

不要简单认为：

```text
100000 条垃圾数据
>
1000 条高质量数据
```

很多时候恰恰相反。

训练数据应该做到：

```text
正确
统一
清晰
符合目标
```

例如你希望模型学习：

```text
简洁回答
```

结果训练集中：

```text
80% 都是长篇大论
```

模型当然很难学会简洁。

所以微调之前第一件事情通常不是：

```text
买 GPU。
```

而是：

```text
整理数据。
```

## 十九、把数据转换成对话格式

现在写：

```text
def format_example(example):
    return f"""
用户：{example["instruction"]}

助手：{example["output"]}
"""
```

例如：

```text
用户：什么是 Redis？

助手：一句话：Redis 是一个高性能内存数据库。

核心用途：缓存、分布式锁、排行榜。
```

但是现在的大部分 Instruction Model 都有自己的：

```text
Chat Template
```

所以更推荐使用 tokenizer 自带的：

```text
apply_chat_template()
```

例如：

```text
messages = [
    {
        "role": "user",
        "content": "什么是 Redis？"
    },
    {
        "role": "assistant",
        "content": "一句话：Redis 是一个高性能内存数据库。"
    }
]
```

然后：

```text
tokenizer.apply_chat_template(
    messages,
    tokenize=False
)
```

让模型按照它自己熟悉的聊天格式训练。

## 二十一、Tokenizer 是什么？

这是小白非常容易忽略的一个概念。

模型并不是直接看到：

```text
你好，我是王仕宇。
```

而是先经过：

```text
Tokenizer
```

拆成 Token。

类似：

```text
你好
，
我是
王
仕
宇
。
```

然后再转换成数字：

```text
[8721, 11, 3952, 721, 928, ...]
```

神经网络真正处理的是：

```text
数字。
```

所以流程其实是：

```text
文字
 ↓
Tokenizer
 ↓
Token ID
 ↓
模型
 ↓
Token ID
 ↓
Tokenizer
 ↓
文字
```

继续：

```text
model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    torch_dtype="auto",
    device_map="auto"

```

这里：

```text
device_map="auto"
```

表示让 Transformers 尽量自动选择：

```text

```

等设备。

## 二十三、给模型安装 LoRA

接下来是整个教程最关键的一步。

```text
lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=[
        "q_proj",
        "k_proj",
        "v_proj",
        "o_proj"
    ]
)
```

然后：

```text
model = get_peft_model(
    model,
    lora_config
)
```

查看真正需要训练多少参数：

```text
model.print_trainable_parameters()
```

你会发现：

```text
总参数很多
```

但是：

```text
真正训练的参数非常少。
```

这就是 LoRA 的意义。

PEFT 官方提供的基本使用流程也正是：创建 Base Model、定义 `LoraConfig` 、通过 `get_peft_model()` 包装模型，然后只训练 LoRA 相关参数。

## 二十四、r 是什么意思？

例如：

```text
r=8
```

这里：

```text
r
```

可以简单理解成：

```text
LoRA 的容量。
```

通常：

```text
r 越大
→
可训练参数越多
→
学习能力越强
→
显存占用也会增加
```

学习阶段完全可以从：

```text
8
16
```

开始。

不需要一开始疯狂调参数。

---

## 二十五、读取训练数据

读取：

```text
with open("train.json", "r", encoding="utf-8") as f:
    raw_data = json.load(f)
```

转换：

```text
dataset = Dataset.from_list(raw_data)
```

接下来构造训练文本：

```text
def build_text(example):

    messages = [
        {
            "role": "user",
            "content": example["instruction"]
        },
        {
            "role": "assistant",
            "content": example["output"]
        }
    ]

    text = tokenizer.apply_chat_template(
        messages,
        tokenize=False,
        add_generation_prompt=False
    )

    return {
        "text": text
    }
```

执行：

```text
dataset = dataset.map(build_text)
```

## 二十六、Tokenize 数据

```text
def tokenize(example):

    result = tokenizer(
        example["text"],
        truncation=True,
        max_length=512
    )

    result["labels"] = result["input_ids"].copy()

    return result
```

执行：

```text
tokenized_dataset = dataset.map(
    tokenize,
    remove_columns=dataset.column_names
)
```

这里：

```text
labels = input_ids
```

可以粗略理解成：

> 让模型根据前面的 Token 学习预测后面的 Token。

```text
batch_size

```

就够了。

## 二十八、Epoch 是什么？

假设你有：

```text
1000 条数据
```

模型完整看完：

```text
1000 条
```

叫：

```text
1 Epoch
```

如果：

```text
num_train_epochs=3
```

意味着：

```text
1000 条数据
看 3 遍。
```

也就是：

```text
3000 次左右的数据训练机会
```

当然真实训练过程还涉及：

```text
batch
gradient accumulation
shuffle
```

等机制。

但初学先这样理解即可。

---

## 二十九、Learning Rate 是什么？

Learning Rate：

```text
学习率
```

可以理解成：

> 模型每次修改参数时迈多大的步子。

比如：

```text
学习率太大
```

可能：

```text
一步跨过正确答案。
```

学习率太小：

```text
学习非常慢。
```

所以这是训练中非常重要的参数。

LoRA 经常会使用类似：

```text
1e-4
2e-4
```

这样的数量级开始实验，但具体最佳值仍然需要结合模型、数据和任务验证。

## 三十二、完整训练代码

把上面的代码组合起来，大概就是：

```text
import json

from datasets import Dataset

from transformers import (
    AutoTokenizer,
    AutoModelForCausalLM,
    TrainingArguments,
    Trainer,
    DataCollatorForLanguageModeling,
)

from peft import (
    LoraConfig,
    get_peft_model,
)

MODEL_NAME = "Qwen/Qwen2.5-0.5B-Instruct"

# =============================
# 1. tokenizer
# =============================

tokenizer = AutoTokenizer.from_pretrained(
    MODEL_NAME
)

# =============================
# 2. model
# =============================

model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    torch_dtype="auto",
    device_map="auto"
)

# =============================
# 3. LoRA
# =============================

lora_config = LoraConfig(

    r=8,

    lora_alpha=16,

    lora_dropout=0.05,

    bias="none",

    task_type="CAUSAL_LM",

    target_modules=[
        "q_proj",
        "k_proj",
        "v_proj",
        "o_proj"
    ]
)

model = get_peft_model(
    model,
    lora_config
)

model.print_trainable_parameters()

# =============================
# 4. load dataset
# =============================

with open(
    "train.json",
    "r",
    encoding="utf-8"
) as f:

    raw_data = json.load(f)

dataset = Dataset.from_list(raw_data)

# =============================
# 5. build chat
# =============================

def build_text(example):

    messages = [

        {
            "role": "user",
            "content": example["instruction"]
        },

        {
            "role": "assistant",
            "content": example["output"]
        }

    ]

    text = tokenizer.apply_chat_template(

        messages,

        tokenize=False,

        add_generation_prompt=False

    )

    return {
        "text": text
    }

dataset = dataset.map(build_text)

# =============================
# 6. tokenize
# =============================

def tokenize(example):

    result = tokenizer(

        example["text"],

        truncation=True,

        max_length=512

    )

    result["labels"] = result[
        "input_ids"
    ].copy()

    return result

tokenized_dataset = dataset.map(

    tokenize,

    remove_columns=dataset.column_names

)

# =============================
# 7. training args
# =============================

training_args = TrainingArguments(

    output_dir="./output",

    num_train_epochs=3,

    per_device_train_batch_size=1,

    gradient_accumulation_steps=4,

    learning_rate=2e-4,

    logging_steps=1,

    save_strategy="epoch",

    report_to="none"

)

# =============================
# 8. trainer
# =============================

trainer = Trainer(

    model=model,

    args=training_args,

    train_dataset=tokenized_dataset,

    data_collator=DataCollatorForLanguageModeling(

        tokenizer=tokenizer,

        mlm=False

    )

)

# =============================
# 9. train
# =============================

trainer.train()

# =============================
# 10. save LoRA
# =============================

model.save_pretrained(
    "./my-lora"
)

tokenizer.save_pretrained(
    "./my-lora"
)
```

执行：

```text
python train.py
```

我们的第一次微调就开始了。

## 三十三、怎么判断模型到底有没有学会？

训练完成绝对不等于：

```text
成功。
```

还需要测试。

而且测试的时候最好准备一批：

```text
训练集中没有出现过的问题。
```

比如训练集中有：

```text
什么是 Redis？
什么是 MySQL？
什么是 Docker？
```

测试时问：

```text
什么是 Kafka？
```

看看它是否依然使用：

```text
一句话：XXX

核心用途：XXX
```

这样的格式。

如果能做到：

```text
模型不是简单背答案
```

而是：

```text
学会了一种回答模式。
```

这才是我们真正想要的东西。

## 三十四、微调之前一定要做 Baseline

这里给大家一个非常实用的建议。

千万不要：

```text

→

→

→

```

```text
微调前输出

```

然后再让 Fine-tuned Model 回答。

最后比较：

```text
Base Model

```

至少观察：

```text
格式正确率
回答准确率
风格一致性
幻觉情况
回答长度
```

这样才能知道：

> 微调到底有没有产生真正的价值？

## 三十七、Ollama 的 Modelfile

Ollama 有一个非常重要的文件：

```text
Modelfile
```

有点像：

```text
Dockerfile
```

例如：

```text
FROM llama3.2:1b

SYSTEM """
你是一名技术老师。

回答问题时：
1. 使用中文。
2. 先给一句话定义。
3. 再列出三个核心用途。
4. 不要写无关内容。
"""

PARAMETER temperature 0.3
```

然后：

```text
ollama create javapub-tech -f Modelfile
```

运行：

```text
ollama run javapub-tech
```

Ollama 官方把 Modelfile 定义为创建、定制和分享模型的“蓝图”，可以配置 Base Model、SYSTEM、PARAMETER、TEMPLATE 和 Adapter 等内容。

但是注意：

> 这仍然不是 Fine-tuning。

因为：

```text
模型权重没有发生训练。
```

只是：

```text
给模型添加了 System Prompt。
```

## 三十八、Modelfile 和 Fine-tuning 的区别

很多人容易把这两个搞混。

例如：

```text
SYSTEM """
所有问题必须简短回答。
"""
```

这叫：

```text
Prompt Engineering
```

而：

```text
10000 个样本
    ↓
Trainer
    ↓
Loss
    ↓
Backpropagation
    ↓
修改 LoRA 参数
```

这个才叫：

```text
Fine-tuning
```

判断标准非常简单：

> 有没有通过训练数据和梯度更新参数？

如果没有：

```text
就不是传统意义上的微调。
```

## 三十九、Ollama 怎么加载 LoRA？

Ollama 支持：

```text
FROM <base-model>

ADAPTER /path/to/adapter
```

例如：

```text
FROM llama3.2

ADAPTER ./my-lora
```

然后：

```text
ollama create my-model
```

运行：

```text
ollama run my-model
```

不过这里必须注意一个非常重要的问题。

Ollama 官方明确提醒：

> Adapter 必须与训练时使用的 Base Model 对应，否则可能产生异常结果。

所以实际项目中不能：

```text
随便训练一个 Qwen LoRA
+
随便找一个 Llama
```

直接组合。

必须保证：

```text
Base Model
```

一致并且格式、架构兼容。

因此对于第一次学习微调的人，我建议：

```text
第一阶段：
Transformers + PEFT 完成训练和测试

第二阶段：
模型合并 / 转换

第三阶段：
接入 Ollama
```

不要一开始同时折腾：

```text
训练
量化
GGUF
Ollama
CUDA
LoRA
模型格式转换
```

否则非常容易把自己绕晕。

## 四十、QLoRA 又是什么？

学习 LoRA 后你很快还会碰到：

```text
QLoRA
```

可以简单理解成：

```text
Quantization
+
LoRA
```

也就是：

```text
量化基础模型
+
训练 LoRA
```

例如原始模型可能使用：

```text
16 bit
```

QLoRA 可以把基础模型量化到更低位宽，让显存占用进一步降低。

同时：

```text
LoRA Adapter
```

继续负责训练。

所以可以粗略理解为：

```text
Full Fine-tuning
↓
太贵

LoRA
↓
只训练少量参数

QLoRA
↓
基础模型再量化
↓
进一步降低显存
```

Hugging Face 当前 PEFT 文档同样支持 QLoRA 风格训练，并可以把 LoRA 应用于 Transformer 中的线性层。

但第一次学习：

> 我建议先把 LoRA 搞懂，再学习 QLoRA。

## 四十二、微调最重要的不是参数，而是数据

很多刚开始微调的人容易天天研究：

```text
r=8 还是 r=16？

learning_rate=1e-4 还是 2e-4？

训练 3 Epoch 还是 5 Epoch？
```

当然这些参数很重要。

但是在实际项目里更重要的往往是：

```text
训练数据到底对不对？
```

垃圾数据：

```text
↓
再好的 GPU
↓
再好的参数
↓
依然得到垃圾模型
```

高质量数据：

```text
↓
正确的训练方式
↓
才有可能产生高质量模型
```

这其实对应机器学习领域一句非常经典的话：

```text
Garbage In,
Garbage Out.
```

输入垃圾，输出垃圾。

---

## 四十三、是不是训练数据越多越好？

不一定。

例如你想训练：

```text
一个固定 JSON 输出模型
```

如果：

```text
5000 条
```

高质量数据已经覆盖绝大部分情况。

再加入：

```text
50000 条
```

质量很差的数据，反而可能降低效果。

所以训练数据最重要的三个指标：

```text
质量
覆盖率
一致性
```

而不是单纯追求：

```text
数量。
```

---

## 四十四、微调会不会让模型学会新知识？

可以，但要谨慎理解。

例如训练集中出现：

```text
JavaPub 是一个技术内容品牌……
```

模型确实可能记住。

但是：

```text
Fine-tuning
```

通常并不是动态知识库最理想的解决方案。

假如数据经常变化：

```text
价格
库存
订单
新闻
公司制度
产品文档
```

更推荐：

```text
RAG
```

因为 RAG 可以随时更新数据库。

而微调更适合：

```text
行为
风格
格式
任务模式
领域能力
```

## 四十五、RAG 和 Fine-tuning 可以一起用吗？

当然可以。

实际上这是一种非常常见的架构：

```text
用户问题
   ↓
RAG
   ↓
搜索公司知识库
   ↓
找到资料
   ↓
Fine-tuned Model
   ↓
按照公司规定格式回答
```

这里：

```text
RAG
```

负责：

```text
知道什么。
```

而：

```text
Fine-tuning
```

负责：

```text
怎么回答。
```

两者并不冲突。

甚至经常一起出现。

## 四十六、再加入 Agent 会怎么样？

继续往上搭：

```text
Fine-tuned Model
+
RAG
+
Tools
+
Agent
```

例如：

```text
用户：
我的订单怎么还没到？
```

Agent：

```text
↓
判断用户意图

↓
调用订单 API

↓
获取订单号

↓
调用物流 API

↓
获取物流状态

↓
RAG 查询售后规则

↓
模型生成最终回复
```

这时候模型已经不仅仅是：

```text
聊天机器人
```

而开始变成：

```text
Agent。
```

所以你会发现：

```text
Prompt
RAG
Fine-tuning
Tool Calling
Agent
```

其实不是互相替代。

而是 AI 应用架构中的不同层。

如果一定让我用一句最简单的话解释 Fine-tuning：

> **模型微调，就是拿一个已经会很多东西的模型，用自己的数据继续训练，让它逐渐形成我们想要的行为。**

而 LoRA 做的事情是：

> **不重新修改整个模型，而是在模型旁边训练一个很小的“能力补丁”。**

所以：

```text
Base Model
+
Dataset
+
LoRA
+
Training
=
Customized Model
```

这就是模型微调最核心的逻辑。

```text
大模型应用
                       │
             ┌─────────┴─────────┐
             │                   │
          模型不会              模型不知道
        按要求回答              最新资料
             │                   │

      仍然不够稳定？             │
             │                   │
             ↓                   │
       Fine-tuning               │
             │                   │
             └─────────┬─────────┘
                       ↓
                     Agent
                       │
             ┌─────────┼─────────┐
             ↓         ↓         ↓
            API      Database   Tools
```

面对一个 AI 项目时，不要看到问题就说：

```text
我要微调模型。
```

先问自己三个问题：

```text
只是想控制回答方式？
→ Prompt

只是需要补充外部知识？
→ RAG

真的需要模型学习新的行为模式？
→ Fine-tuning
```

如果这三个问题已经能判断清楚，你对模型微调的理解，其实已经超过了很多刚刚开始做 AI 应用的人。
