> 本文以 Llama-2 7B 为例，从 HuggingFace（HF）Checkpoint 出发，不依赖 Megatron-Bridge，逐步理解并实现一个简化版的 HF → Megatron 模型格式转换器。<br> 本文的重点不是教你运行一个现成的 checkpoint conversion 脚本，而是理解一个更本质的问题：<br> **一个 HuggingFace 中的 global Tensor，如何经过模型结构映射、参数合并/拆分以及 Tensor Parallel、Pipeline Parallel 等分布式切分，最终变成 Megatron 各个 rank 上的 local Tensor？**<br>**完整代码：**[https://github.com/everwind/learn_megatron/blob/main/llama_hf_to_megatron_single.py](https://github.com/everwind/learn_megatron/blob/main/llama_hf_to_megatron_single.py)

### 1. 为什么需要 HuggingFace → Megatron 转换？

目前大量开源大模型首先以 HuggingFace Transformers 格式发布，例如：

- Llama
- Qwen
- Mistral
- DeepSeek
- Gemma

而在大规模预训练场景中，Megatron-LM / Megatron-Core 是非常重要的训练框架。

因此实际工作中经常遇到这样的需求：

```text
HuggingFace Checkpoint
        │
        │
        ▼
Megatron Checkpoint
        │
        ▼
Megatron Training / Continued Pretraining / Fine-tuning
```

反过来也一样：

```text
Megatron Checkpoint
        │
        ▼
HuggingFace Checkpoint
        │
        ▼
Transformers / vLLM / Deployment
```

NVIDIA 目前已经提供 Megatron-Bridge，用于 HuggingFace 与 Megatron-Core 之间的双向转换。其核心设计包括模型配置映射、参数映射以及 TP/PP/EP 等并行维度下的参数分片。

但是，如果只是会运行：

```bash
python convert.py ...
```

并不意味着真正理解了 checkpoint conversion。

真正需要理解的是：

```text
HF Model
   │
   ├── Model Config
   │
   ├── Model Architecture
   │
   └── State Dict
   │
   ▼
Parameter Mapping
   │
   ├── QKV Mapping
   ├── MLP Mapping
   ├── Embedding Mapping
   └── Norm Mapping
   │
   ▼
Parallel Sharding
   │
   ├── Tensor Parallel
   ├── Pipeline Parallel
   └── Expert Parallel
   │
   ▼
Megatron Checkpoint
```

因此，本文从最底层开始实现。

## 2. 先理解：HF 和 Megatron 到底有什么不同？

一个 Transformer 在数学上是一样的，但是**参数组织方式并不一定一样**。

例如 HuggingFace Llama 的 Attention 通常是：

```text
q_proj
k_proj
v_proj
o_proj
```

而 Megatron 中通常会把 Q/K/V 合并成：

```text
linear_qkv
```

同样，Llama 使用 SwiGLU：

```text
gate_proj
up_proj
down_proj
```

而 Megatron 中通常会把：

```text
gate_proj + up_proj
```

合并成：

```text
linear_fc1
```

所以：

```text
HF Parameter Layout
        ≠
Megatron Parameter Layout
```

这就是 checkpoint conversion 的核心。

## 3. Llama-2 7B 模型结构

本文选择 Llama-2 7B 作为示例。

它的核心配置可以简化为：

```text
hidden_size             = 4096
num_hidden_layers       = 32
num_attention_heads     = 32
num_key_value_heads     = 32
intermediate_size       = 11008
vocab_size              = 32000
max_position_embeddings = 4096
```

模型结构：

```text
Embedding
    │
    ▼
┌─────────────────────────┐
│ Transformer Layer × 32  │
│                         │
│ RMSNorm                 │
│    ↓                    │
│ Self Attention          │
│    ↓                    │
│ Residual                │
│    ↓                    │
│ RMSNorm                 │
│    ↓                    │
│ SwiGLU MLP              │
│    ↓                    │
│ Residual                │
└─────────────────────────┘
    │
    ▼
Final RMSNorm
    │
    ▼
LM Head
```

Llama-2 7B 的 Attention 使用 32 个 Q、K、V heads，因此作为第一个 checkpoint converter，它比后面的 GQA、MoE 模型更加容易理解。

## 4. 第一层：理解 HuggingFace State Dict

首先不考虑 Megatron。

直接加载 HuggingFace Llama：

```python
from transformers import LlamaForCausalLM

    "meta-llama/Llama-2-7b-hf",

state_dict = model.state_dict()

```

你会看到类似：

```text

model.layers.0.self_attn.q_proj.weight
model.layers.0.self_attn.k_proj.weight
model.layers.0.self_attn.v_proj.weight
model.layers.0.self_attn.o_proj.weight

model.layers.0.post_attention_layernorm.weight

model.layers.0.mlp.gate_proj.weight
model.layers.0.mlp.up_proj.weight
model.layers.0.mlp.down_proj.weight

...

model.norm.weight
lm_head.weight
```

这里最重要的是建立一个认知：

> **HF checkpoint 本质上就是一个 parameter name → Tensor 的映射。**

例如：

```python
state_dict[
    "model.layers.0.self_attn.q_proj.weight"

```

得到：

```text
Tensor [4096, 4096]
```

Converter 的第一项工作，就是把这些 Tensor 重新组织。

## 5. 建立 HF → Megatron 参数映射表

我们先不考虑 TP 和 PP。

只考虑：

```text
HF Model
   ↓
完整 Megatron Model
```

可以建立如下映射：

| HuggingFace | Megatron |
| --- | --- |
| model.embed_tokens.weight | embedding.word_embeddings.weight |
| model.layers.*.input_layernorm.weight | decoder.layers.*.input_layernorm.weight |
| q_proj.weight | linear_qkv.weight |
| k_proj.weight | linear_qkv.weight |
| v_proj.weight | linear_qkv.weight |
| o_proj.weight | linear_proj.weight |
| post_attention_layernorm.weight | pre_mlp_layernorm.weight |
| gate_proj.weight | linear_fc1.weight |
| up_proj.weight | linear_fc1.weight |
| down_proj.weight | linear_fc2.weight |
| model.norm.weight | decoder.final_layernorm.weight |
| lm_head.weight | output_layer.weight |

注意这里已经出现了两种重要情况：

```text
一对一 Mapping

HF Parameter
     │
     ▼
Megatron Parameter
```

以及：

```text
多对一 Mapping

Q ─────┐
K ─────┼──► linear_qkv
V ─────┘
```

还有：

```text
多对一 Mapping

gate_proj ──┐
             ├──► linear_fc1
up_proj   ──┘
```

因此 checkpoint conversion 并不是简单的“改参数名字”。

## 6. QKV Mapping：第一个核心问题

HF 中：

```text
q_proj.weight
k_proj.weight
v_proj.weight
```

分别是：

```text
Q = XWq
K = XWk
V = XWv
```

Llama-2 7B：

```text
Wq = [4096, 4096]
Wk = [4096, 4096]
Wv = [4096, 4096]
```

而 Megatron 通常将它们组合：

```text
Wqkv = [12288, 4096]
```

因此最简单的转换就是：

```python
qkv = torch.cat(
    [
        q_proj,
        k_proj,
        v_proj,
    ],
    dim=0
)
```

也就是说：

```text
HF

Q [4096, 4096]
K [4096, 4096]
V [4096, 4096]

        │
        │ cat(dim=0)
        ▼

Megatron

QKV [12288, 4096]
```

这就是第一个非常典型的：

**Many-to-One Parameter Mapping**

---

## 7. SwiGLU Mapping

Llama 使用 SwiGLU MLP。

其计算可以简化为：

```text
gate = gate_proj(x)
up   = up_proj(x)

hidden = SiLU(gate) * up

output = down_proj(hidden)
```

也就是：

```text
┌── gate_proj ── SiLU ──┐
x ────────────────┤                       × ──► down_proj
                  └── up_proj ────────────┘
```

HF 保存：

```text
gate_proj.weight
up_proj.weight
down_proj.weight
```

Megatron 通常把前两个合并：

```text
linear_fc1
linear_fc2
```

因此：

```python
fc1 = torch.cat(
    [
        gate_proj,
        up_proj,
    ],
    dim=0
)
```

尺寸：

```text
gate_proj = [11008, 4096]
up_proj   = [11008, 4096]

fc1       = [22016, 4096]
```

因此：

```text
HF

gate_proj
up_proj
down_proj

        │
        ▼

Megatron

linear_fc1
linear_fc2
```

这就是第二种典型的 Many-to-One Mapping。

## 9. 实现第一个 Layer Converter

可以先写一个最小版本：

```python
def convert_layer(hf_layer):

    qkv = torch.cat([
        hf_layer.self_attn.q_proj.weight,
        hf_layer.self_attn.k_proj.weight,
        hf_layer.self_attn.v_proj.weight,
    ], dim=0)

    fc1 = torch.cat([
        hf_layer.mlp.gate_proj.weight,
        hf_layer.mlp.up_proj.weight,
    ], dim=0)

    return {
        "linear_qkv.weight": qkv,

        "linear_proj.weight":
            hf_layer.self_attn.o_proj.weight,

        "input_layernorm.weight":
            hf_layer.input_layernorm.weight,

        "pre_mlp_layernorm.weight":
            hf_layer.post_attention_layernorm.weight,

        "linear_fc1.weight":
            fc1,

        "linear_fc2.weight":
            hf_layer.mlp.down_proj.weight,
    }
```

这段代码已经实现了：

```text
HF Transformer Layer
          │
          ▼
Megatron Transformer Layer
```

## 13. Tensor Parallel 是什么？

假设：

```text
hidden_size = 4096
TP = 4
```

一个 Linear Weight：

```text
W = [4096, 4096]
```

在 Tensor Parallel 下不会让每个 GPU 都保存完整 Tensor。

例如 Column Parallel：

```text
GPU0: [1024, 4096]
GPU1: [1024, 4096]
GPU2: [1024, 4096]
GPU3: [1024, 4096]
```

所以：

```text
Global Tensor
      │
      ├── TP0
      ├── TP1
      ├── TP2
      └── TP3
```

这意味着 Converter 不仅要解决：

```text
HF parameter
       ↓
Megatron parameter
```

还必须解决：

```text
Megatron global parameter
       ↓
Megatron local parameter
```

---

## 14. Column Parallel Linear

对于：

```text
Y = XW
```

Column Parallel 将 Weight 按输出维度切分。

例如：

```text
W = [4096, 4096]
```

TP=4：

```text
W0 = [1024, 4096]
W1 = [1024, 4096]
W2 = [1024, 4096]
W3 = [1024, 4096]
```

代码：

```python
def split_column(
    weight,
    tp_rank,
    tp_size
):
    chunks = torch.chunk(
        weight,
        tp_size,
        dim=0
    )

    return chunks[tp_rank]
```

核心：

```text
Column Parallel
       ↓
dim = 0
```

---

## 15. Row Parallel Linear

另一种是 Row Parallel。

仍然：

```text
W = [4096, 4096]
```

TP=4：

```text
W0 = [4096, 1024]
W1 = [4096, 1024]
W2 = [4096, 1024]
W3 = [4096, 1024]
```

代码：

```python
def split_row(
    weight,
    tp_rank,
    tp_size
):
    chunks = torch.chunk(
        weight,
        tp_size,
        dim=1
    )

    return chunks[tp_rank]
```

核心：

```text
Row Parallel
      ↓
dim = 1
```

## 16. Llama 中哪些层使用 Column / Row Parallel？

在一个典型 Megatron Llama 实现中，可以抽象成：

```text
Attention:

QKV projection
       ↓
Column Parallel

Output projection
       ↓
Row Parallel
```

MLP：

```text
FC1
 ↓
Column Parallel

FC2
 ↓
Row Parallel
```

因此：

```text
linear_qkv
linear_fc1
```

通常沿：

```text
dim=0
```

切分。

而：

```text
linear_proj
linear_fc2
```

通常沿：

```text
dim=1
```

切分。

## 17. QKV + Tensor Parallel

现在进入 converter 中最容易出错的地方。

假设：

```text
num_heads = 32
head_dim = 128
TP = 2
```

那么：

```text
32 / 2 = 16 heads / GPU
```

HF：

```text
Q = [4096, 4096]
K = [4096, 4096]
V = [4096, 4096]
```

首先按照 head 切分：

```text
Q0 ... Q15
Q16 ... Q31

K0 ... K15
K16 ... K31

V0 ... V15
V16 ... V31
```

然后：

```text
TP0:

Q0-15
K0-15
V0-15

TP1:

Q16-31
K16-31
V16-31
```

可以实现成：

```python
def shard_qkv(
    q,
    k,
    v,
    tp_rank,
    tp_size
):

    q_chunks = torch.chunk(
        q,
        tp_size,
        dim=0
    )

    k_chunks = torch.chunk(
        k,
        tp_size,
        dim=0
    )

    v_chunks = torch.chunk(
        v,
        tp_size,
        dim=0
    )

    return torch.cat(
        [
            q_chunks[tp_rank],
            k_chunks[tp_rank],
            v_chunks[tp_rank],
        ],
        dim=0
    )
```

这里的关键思想是：

> **Q、K、V 应该在 head 维度上进行对应的 TP 切分，然后在 local rank 内重新组合。**

不能简单地认为：

```python
torch.cat([Q, K, V], dim=0)
torch.chunk(..., TP)
```

在所有 Attention 实现中都一定正确。

不同 Megatron Attention layout 必须具体分析。

## 18. SwiGLU + Tensor Parallel

同样处理 MLP。

HF：

```text
gate_proj = [11008, 4096]
up_proj   = [11008, 4096]
```

TP=2：

```text
gate0 = [5504, 4096]
gate1 = [5504, 4096]

up0 = [5504, 4096]
up1 = [5504, 4096]
```

然后：

```text
TP0:

gate0
up0

TP1:

gate1
up1
```

实现：

```python
def shard_fc1(
    gate,
    up,
    tp_rank,
    tp_size
):

    gate_chunk = torch.chunk(
        gate,
        tp_size,
        dim=0
    )[tp_rank]

    up_chunk = torch.chunk(
        up,
        tp_size,
        dim=0
    )[tp_rank]

    return torch.cat(
        [
            gate_chunk,
            up_chunk
        ],
        dim=0
    )
```

这就是一个简化版的 Gated MLP Mapping。

## 19. 一个真正的 TP-aware Layer Converter

现在可以把前面的代码组合起来：

```python
def convert_layer(
    hf_layer,
    tp_rank,
    tp_size
):

    qkv = shard_qkv(
        hf_layer.self_attn.q_proj.weight,
        hf_layer.self_attn.k_proj.weight,
        hf_layer.self_attn.v_proj.weight,
        tp_rank,
        tp_size,
    )

    fc1 = shard_fc1(
        hf_layer.mlp.gate_proj.weight,
        hf_layer.mlp.up_proj.weight,
        tp_rank,
        tp_size,
    )

    o_proj = split_row(
        hf_layer.self_attn.o_proj.weight,
        tp_rank,
        tp_size,
    )

    fc2 = split_row(
        hf_layer.mlp.down_proj.weight,
        tp_rank,
        tp_size,
    )

    return {
        "linear_qkv.weight": qkv,

        "linear_proj.weight":
            o_proj,

        "input_layernorm.weight":
            hf_layer.input_layernorm.weight,

        "pre_mlp_layernorm.weight":
            hf_layer.post_attention_layernorm.weight,

        "linear_fc1.weight":
            fc1,

        "linear_fc2.weight":
            fc2,
    }
```

此时我们已经实现了：

```text
HF
 ↓
Architecture Mapping
 ↓
TP Sharding
 ↓
Megatron Local Parameters
```

## 20. Pipeline Parallel

Tensor Parallel 是：

```text
一个 Layer
   ↓
多个 GPU
```

Pipeline Parallel 则是：

```text
不同 Layer
   ↓
不同 GPU
```

例如：

```text
32 Transformer Layers
PP = 2
```

可以划分成：

```text
PP0:

Layer 0
Layer 1
...
Layer 15

PP1:

Layer 16
Layer 17
...
Layer 31
```

简单实现：

```python
def get_pp_range(
    num_layers,
    pp_rank,
    pp_size
):

    layers_per_stage = (
        num_layers // pp_size
    )

    start = (
        pp_rank *
        layers_per_stage
    )

    end = (
        start +
        layers_per_stage
    )

    return start, end
```

然后：

```python
start, end = get_pp_range(
    32,
    pp_rank,
    2
)

for layer_id in range(
    start,
    end
):

    ...
```

真实 Megatron 还需要考虑 embedding、final layernorm、output layer、VPP 以及 uneven pipeline partition 等问题，因此这里的代码主要用于理解 PP 原理。

## 21. TP + PP 后的 Rank

假设：

```text
TP = 2
PP = 2
```

那么 Model Parallel Rank 数量为：

```text
2 × 2 = 4
```

可以抽象成：

```text
PP0          PP1

TP0          rank0        rank2

TP1          rank1        rank3
```

于是一个完整模型：

```text
Global Model
     │
     ├── PP0
     │     ├── TP0
     │     └── TP1
     │
     └── PP1
           ├── TP0
           └── TP1
```

最终 checkpoint 不再是一个简单：

```text
model.pt
```

而是多个 rank 的模型 shard。

## 22. 为什么建议不要一开始实现 Distributed Checkpoint？

因为这样会同时引入：

```text
Transformer Architecture
+
Parameter Mapping
+
Tensor Parallel
+
Pipeline Parallel
+
PyTorch Distributed
+
Distributed Checkpoint
```

debug 难度会急剧上升。

推荐按照下面的顺序：

```text
Version 1

TP = 1
PP = 1
```

先完成：

```text
HF → Megatron State Dict
```

然后：

```text
Version 2

TP = 2
PP = 1
```

再实现：

```text
Global Tensor
     ↓
TP Shard
```

然后：

```text
Version 3

TP = 2
PP = 2
```

最后：

```text
Version 4

Megatron Distributed Checkpoint
```

这样每一步都能独立验证。

## 23. Checkpoint Conversion 的核心抽象

到这里，可以把整个过程抽象成三个步骤。

### 第一步：Architecture Mapping

```text
HF Architecture
       ↓
Megatron Architecture
```

例如：

```text
q_proj + k_proj + v_proj
            ↓
       linear_qkv
```

---

### 第二步：Tensor Mapping

```text
HF Tensor
    ↓
Megatron Global Tensor
```

例如：

```text
gate_proj + up_proj
          ↓
       linear_fc1
```

---

### 第三步：Parallel Mapping

```text
Megatron Global Tensor
          ↓
 ┌────────┼────────┐
 ▼        ▼        ▼
TP0      TP1      TP2
```

最终：

```text
Global Model
     ↓
Distributed Model
```

所以：

> **HF → Megatron Conversion 本质上就是 Architecture Mapping + Parameter Mapping + Parallel Sharding。**

## 27. 最好的 Debug 方法：Layer-by-Layer 对比

如果：

```text
HF logits != Megatron logits
```

不要直接怀疑 TP。

推荐按照下面的顺序：

```text
1. Config
       ↓
2. Embedding
       ↓
3. Input LayerNorm
       ↓
4. QKV
       ↓
5. RoPE
       ↓
6. Attention
       ↓
7. O Projection
       ↓
8. MLP
       ↓
9. Final LayerNorm
       ↓
10. LM Head
       ↓
11. TP
       ↓
12. PP
```

最好比较：

```text
HF layer 0 output
        vs
Megatron layer 0 output

HF layer 1 output
        vs
Megatron layer 1 output
```

例如：

```text
Layer 0     OK
Layer 1     OK
Layer 2     OK
Layer 3     ERROR
```

那么 bug 基本就在：

```text
Layer 3
```

或者更早的位置。

这种逐层验证对于 checkpoint converter 的开发非常重要。

## 30. 最终 Converter 的代码架构

最终可以抽象成：

```python
def convert_hf_to_megatron(
    hf_model,
    tp_size=1,
    pp_size=1,
):

    config = parse_hf_config(
        hf_model.config
    )

    checkpoint = {}

    # Embedding
    checkpoint["embedding"] = \
        convert_embedding(
            hf_model,
            tp_size
        )

    # Transformer layers
    for layer_id in range(
        config.num_layers
    ):

        if not belongs_to_pp(
            layer_id,
            pp_size
        ):
            continue

        layer = hf_model.model.layers[
            layer_id
        ]

        converted = convert_layer(
            layer,
            tp_size=tp_size,
        )

        checkpoint.update(
            converted
        )

    # Final norm
    checkpoint["final_norm"] = \
        hf_model.model.norm.weight

    # LM head
    checkpoint["lm_head"] = \
        hf_model.lm_head.weight

    return checkpoint
```

可以把整个 converter 理解成：

```text
HF Model
                        │
                        ▼
                ┌──────────────┐
                │ HF Config    │
                └──────┬───────┘
                       │
                       ▼
                Architecture
                  Mapping
                       │
                       ▼
                Parameter Mapping
                       │
          ┌────────────┼────────────┐
          │            │            │
         QKV          MLP       Embedding
          │            │            │
          └────────────┼────────────┘
                       ▼
                Global Megatron
                    Tensor
                       │
                       ▼
                Parallel Sharding
                       │
             ┌─────────┼─────────┐
             ▼         ▼         ▼
            TP        PP        EP
             │         │         │
             └─────────┼─────────┘
                       ▼
              Megatron Checkpoint
                       │
                       ▼
                 Validation
                       │
                       ▼
              HF logits ≈ MG logits
```

## 31. 从 Llama 进一步扩展到 Qwen 和 DeepSeek

当你真正理解 Llama converter 后，再研究 Qwen、DeepSeek，会发现很多问题只是 Mapping 规则发生变化。

例如：

```text
Llama
 ↓
标准 Dense Transformer
 ↓
QKV + SwiGLU
```

然后：

```text
Qwen
 ↓
GQA
 ↓
不同 RoPE / embedding / architecture details
```

再到：

```text
DeepSeek
 ↓
MoE
 ↓
Expert Parallel
 ↓
更复杂 Attention
```

尤其是 MoE：

```text
HF:

experts.0
experts.1
experts.2
...
experts.N

       ↓

Megatron:

Expert Parallel
       ↓
EP0
EP1
EP2
...
```

此时 converter 不再只是：

```text
TP × PP
```

而变成：

```text
TP × PP × EP
```

这也是为什么理解 Llama converter 是学习 DeepSeek / Qwen MoE checkpoint conversion 的一个很好的起点。

## 32. Megatron-Bridge 到底做了什么？

理解到这里，再回头看 Megatron-Bridge 就会非常清楚。

我们前面自己实现的：

```text
QKV Mapping
Gated MLP Mapping
Embedding Mapping
TP Sharding
PP Handling
Config Mapping
Validation
```

实际上就是一个简化版的 Megatron-Bridge。

现代 Megatron-Bridge 将这些能力抽象成：

```text
HF Model
     │
     ▼
Model Provider
     │
     ▼
Parameter Mapping
     │
     ├── QKVMapping
     ├── GatedMLPMapping
     ├── RowParallelMapping
     ├── ColumnParallelMapping
     └── ...
     │
     ▼
Megatron Core Model
     │
     ▼
Distributed Checkpoint
```

因此 Megatron-Bridge 的核心价值并不是“帮你写了一个转换脚本”，而是：

> **把不同模型的 checkpoint conversion 抽象成了一套可扩展的 Parameter Mapping Framework。**

当新增一个模型架构时，本质上就是回答几个问题：

```text
1. HF Config 如何映射到 Megatron Config？

2. HF Parameter 如何映射到 Megatron Parameter？

3. 哪些参数需要 concat / split / reshape？

4. 哪些参数属于 Column Parallel？

5. 哪些参数属于 Row Parallel？

6. TP / PP / EP 下如何进行 shard？

7. 如何验证转换后的模型？
```

## 33. 总结：HF → Megatron 到底难在哪里？

表面看：

```text
HF checkpoint
       ↓
Megatron checkpoint
```

似乎只是文件格式转换。

实际上至少包含三个层次：

### 第一层：模型结构

```text
Llama
Qwen
DeepSeek
Mistral
...
```

必须理解模型到底由什么组成。

### 第二层：Parameter Mapping

```text
q_proj
k_proj
v_proj
      ↓
linear_qkv
```

以及：

```text
gate_proj
up_proj
      ↓
linear_fc1
```

### 第三层：Distributed Sharding

```text
Global Tensor
      ↓
TP
      ↓
PP
      ↓
EP
      ↓
Rank-local Tensor
```

因此可以用一句话概括：

> **HuggingFace → Megatron Converter，本质上不是文件格式转换，而是一次“模型参数语义 + Tensor Layout + Distributed Parallelism”的转换。**
