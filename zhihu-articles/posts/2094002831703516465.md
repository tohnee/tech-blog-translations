10 月 7 日，Anthropic 在帮助中心和开发者文档里加了一条：Claude Max 和 Team 计划每月附带一笔 API 额度，Max 5x 是 100 美元，Max 20x 是 200 美元，正好等于订阅月费。这几天中文圈的标题是”Claude 彻底解禁第三方应用”，对照官方文档看，实际范围比标题窄：Anthropic 没有放开”用订阅账号登录第三方产品”，只是给订阅用户发了一笔只能在 Claude Platform 上花的 API 钱。

下面把规则、来龙去脉和容易踩的坑理一遍。规则以 2026 年 10 月 15 日能查到的 Anthropic 官方页面为准，后续可能调整。

### 一、它是什么

| 项目 | 内容 |
| --- | --- |
| 生效日期 | 2026-10-07（帮助中心更新说明），额度分几天陆续开放 |
| 适用计划 | Max 5x、Max 20x、Team（含 Nonprofit、Scientists 折扣版） |
| 不适用 | Free、Pro、Enterprise |
| 每月额度 | Max 5x：100 美元；Max 20x：200 美元；Team：标准席 20 美元/席、高级席 100 美元/席，合并成一个池子，上限 500 美元 |
| 能用在哪 | Claude API（Messages、Message Batches）、Claude Managed Agents、Claude Agent SDK、Console Playground |
| 不能用在哪 | Claude Code（交互式，终端、IDE、桌面、网页都算）、Claude 应用里的 Extra usage、AWS 上的 Claude Platform、Bedrock、Google Cloud、Microsoft Foundry |
| 有效期 | 每个账单周期发一次，周期结束作废，不结转；年付按月发 |
| 怎么领 | 在 claude.ai 的账单设置里关联一个 Claude Console 组织，不需要绑卡 |

Team 的算法官方给了例子：3 个标准席加 2 个高级席，每月 260 美元；再加 1 个高级席，下个月变成 360 美元。

### 二、来龙去脉：半年里改了四次

只看这一条更新容易误读，前面几次调整要一起看：

| 时间 | 发生了什么 | 来源 |
| --- | --- | --- |
| 2026-04-04 | Claude Code 负责人 Boris Cherny 在 X 上宣布，第二天起订阅不再覆盖 OpenClaw 这类第三方工具的用量 | VentureBeat、Yahoo Finance 等转述 |
| 2026-05-13 | @ClaudeDevs 宣布所有付费计划另给一笔「Agent SDK credit」（Pro 20 美元起），专门给 claude -p、GitHub Actions 和第三方工具用，按 API 价格扣，用完即停 | VentureBeat |
| 2026-06-15 | 帮助中心：上面这项调整暂停，Agent SDK、claude -p 和第三方应用照旧消耗订阅本身的用量 | Anthropic 帮助中心 |
| 2026-10-07 | Max 和 Team 附带每月 API 额度；6 月那笔 Agent SDK credit 不再提供 | Anthropic 帮助中心、开发者文档 |

5 月的方案在社区反响很差。VentureBeat 引用了 Theo Browne 的说法：T3 Code、Conductor、Zed 这类工具能用的量”等于砍了 25 倍”。原因是订阅额度原来能跑出远高于月费的 token，换成按 API 价格扣的 20 美元，量差了一个数量级。

10 月这次和 5 月比，有两处不同：

1. **不再拿 API 额度替换订阅用量** 。帮助中心原话是，你”仍然可以”用订阅额度跑 Agent SDK、 `claude -p` 和第三方应用。API 额度是额外加上的。
2. **Pro 不在里面了** 。5 月方案 Pro 也有 20 美元，这次只给 Max 和 Team。

### 三、为什么要这样设计

### 1. 两条计费轨道，按认证方式分流

这次更新的关键在于”你用什么身份发请求”。同一个 `claude -p` ，换一种认证方式，扣的就是另一本账：

```text
┌─ 用 claude.ai 订阅登录 ──────→ 扣订阅用量（5 小时 / 每周限额）
claude -p ──────┤
Agent SDK       └─ 用关联组织的 API key ───────→ 扣每月 API 额度 → 再扣已购额度 → 停

交互式 Claude Code ─────────────────────────────→ 只扣订阅用量，API 额度不覆盖
GitHub Action / IDE 扩展 / 桌面应用发起的 -p ───→ 算 Claude Code 用量，同样不覆盖
```

帮助中心 FAQ 写得很细： `claude -p` 和 Agent SDK 只有在 **你自己用关联组织的 API key 运行** 时才走 API 额度；用订阅账号登录跑，扣的是订阅；通过 GitHub Action、IDE 扩展或桌面应用发起的，”即使带了 `-p` “也算 Claude Code 用量。

### 2. 为什么不直接放开订阅给第三方

据 VentureBeat 报道，Anthropic 给的理由一直是容量和成本：有些用户月付 20 到 200 美元，却通过自动化 Agent 跑掉几百甚至几千美元的 token。报道还提到一个技术原因：Claude Code、Cowork 这些官方工具会尽量复用缓存好的提示词前缀，很多第三方工具常常跳过这层优化。

订阅的限额是按”人在交互”估算的，一个人一天能看多少回复是有上限的；无人值守的 Agent 没有这个上限。所以 Anthropic 的做法是：交互式用量留在订阅里，程序化用量引到 API 上，按 token 计价、有支出上限、有速率分级，成本可控。

### 3. 为什么额度等于月费

官方没解释，以下是我的推测：对用户，交互式用量照旧，API 额度额外给，这是在回应 5 月”变相降额”的批评；对 Anthropic，这笔钱只能花在 Claude Platform 上，要先建 Console 组织、建 key，原来只用 Claude Code 的订阅用户会被引到 API、Managed Agents 和 Agent SDK 上，而月底作废的部分不产生成本。

### 4. “解禁第三方应用”到底解了什么

中文标题容易让人理解成”第三方 App 可以直接用我的 Claude 账号登录了”。

- Agent SDK 官方文档（2026 年 10 月版）仍然写着：除非事先获批，Anthropic **不允许第三方开发者在自己的产品里提供 claude.ai 登录或使用订阅限额** ，包括基于 Agent SDK 做的 Agent，应当使用 API key 认证。
- 帮助中心又写着订阅用户”仍然可以”用订阅额度跑第三方应用。

两处放在一起看，我的理解是：你自己在本机用订阅账号跑开源工具，官方暂时没有收紧；但做产品的一方，不能把”用你的 Claude 订阅登录”当卖点。这次新加的 API 额度，才是第三方应用最干净的接入路径：应用让你填 API key，扣的是你那 100 或 200 美元。各页面措辞不完全一致（SSD Nodes 也指出了这一点），以后可能再改，做产品前建议以官方条款为准，必要时直接问 Anthropic。

### 四、这笔钱够干什么

按 2026 年 10 月官方价格表（美元 / 百万 token）：

| 模型 | 输入 | 输出 | 缓存命中 | Batch 输入 / 输出 |
| --- | --- | --- | --- | --- |
| Claude Opus 5.5 | 4 | 20 | 0.20 | 2 / 10 |
| Claude Sonnet 5.5 | 2 | 10 | 0.10 | 1 / 5 |
| Claude Haiku 5.5（提示 ≤ 10 万 token） | 0.10 | 0.50 | 0.01 | 0.05 / 0.25 |
| Claude Haiku 5.5（提示 > 10 万 token） | 0.50 | 2.50 | 0.05 | 0.25 / 1.25 |

Managed Agents 另外按会话运行时间收费，每会话小时 0.08 美元，只在 `running` 状态计时。

粗算一下 100 美元：全用 Sonnet 5.5 的话，大约是 5000 万输入 token，或 1000 万输出 token；换成短提示的 Haiku 5.5，是 10 亿输入或 2 亿输出。

再算个实际一点的场景：每天跑一个 PR 审查脚本，用 Sonnet 5.5，假设每次 5 万 token 写入缓存、10 万 token 命中缓存、输出 8000 token：

```text
缓存写入  50k × $2.50/M  = $0.125
缓存命中 100k × $0.10/M  = $0.010
输出       8k × $10/M    = $0.080
单次约 $0.22，100 美元大约能跑 450 次
```

这只是按价格表算的估算，实际用量取决于上下文多大、Agent 绕了几圈，本文没有实测。能离线跑的任务放到 Message Batches API 上，价格减半，额度能多用一倍。

### 五、怎么用上

### 1. 领额度

1. claude.ai → Settings > Billing（Max）或 Organization settings > Billing（Team）。
2. 在 API credits 区域选一个 Console 组织关联，接受条款。
3. 去 Console 的 Billing 页面，额度显示在 Promotional credits 里，带金额和到期日。

前提：你得是 Max 订阅者本人，或 Team 的 Primary Owner / Owner，同时在 Console 组织里是 Owner、Admin 或 Billing 角色。新订阅要满 7 天才能领。

### 2. 用 API key 跑 `claude -p`

在 Console 里建好 key 之后，用 `--bare` 模式跑。官方文档说明，bare 模式不读 OAuth 凭据和系统钥匙串，只认 `ANTHROPIC_API_KEY` ，这样能确定扣的是 API 额度而不是订阅：

```bash
export ANTHROPIC_API_KEY=your-api-key
claude --bare -p "Summarize README.md" --allowedTools "Read"
```

加 `--output-format json` 后，返回里有 `total_cost_usd` ，可以用来粗略记账（这是客户端估算，以账单为准）。

### 3. 用 Agent SDK

Python 装 `claude-agent-sdk` ，TypeScript 装 `@anthropic-ai/claude-agent-sdk` 。SDK 从运行进程的环境变量里读 `ANTHROPIC_API_KEY` ，不会自动加载 `.env` 文件，所以同样设好环境变量就会走 API 额度。示例代码见官方 Quickstart。

### 六、局限和坑

| 坑 | 说明 |
| --- | --- |
| 交互式 Claude Code 不能用 | 组织里只有这笔额度时，在 Claude Code 里用它的 key 会提示 Credit balance too low · Add funds，哪怕额度没动过 |
| 关联不能自己改 | 一个计划只能关联一个组织，一个组织只能接一个计划的额度，改要找客服。先想好在哪个组织开发 |
| 整个组织共用余额 | 组织里所有 key、所有 workspace 扣同一个池子。一个 key 泄露就能把额度刷光，建议每个项目单独建 workspace 并设支出上限 |
| auto-reload 不看赠送额度 | 自动充值只看已购余额，赠送额度还有剩时也可能触发充值 |
| 两个周期不同步 | 额度按账单周期刷新，组织的月度支出上限按自然月 1 号重置 |
| 速率分级 | 关联后组织至少升到 Start 级；额度超过 200 美元才到 Build 级。Max 20x 正好 200，只到 Start |
| 没公布截止时间 | 官方没说这项福利持续多久 |

额度用完后：组织里有已购额度就接着扣，没有就停，等下个月额度到账，不会扣到订阅账单上。走销售开票的组织照常计费。

### 七、我的判断

1. **对 Max 用户是实打实的加量** 。交互式用量没动，多出 100 或 200 美元的 API 钱。以前写个夜间跑的小脚本还得单独充值、单独绑卡，现在可以直接用。不用就作废，所以值得领。
2. **对 Pro 用户没有好处** 。5 月方案里 Pro 有 20 美元，这次没有。想用 API 跑自动化的 Pro 用户，要么升 Max，要么自己充值。
3. **“解禁第三方”是被放大了的说法** 。官方文档仍然不允许第三方产品提供 claude.ai 登录。这次真正的变化是给第三方应用一条合规又不额外花钱的路：填 API key，花的是订阅附带的额度。做产品的团队不要据此去接订阅登录。
4. **方向上，Anthropic 在把”人用”和”机器用”分开计价** 。从 4 月切断，到 5 月改额度，再到 6 月暂停，到 10 月加额度，摇摆了半年，但大方向没变：交互式的走订阅，程序化的走 API。我预计以后规则还会收紧，比如订阅跑第三方应用这条口子。现在就把自动化任务迁到 API key 上，比继续依赖订阅登录稳妥。
