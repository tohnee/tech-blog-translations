## 多模态评测专栏计划：从读懂榜单到搭建自己的评测体系

### 一、专栏定位

这套专栏不准备做成“Benchmark 名词解释合集”，也不只复述模型技术报告里的分数。

它要回答四个更有用的问题：

1. 最新多模态模型为什么选择这些 Benchmark？
2. 一个分数究竟测到了感知、OCR、知识、推理、时序，还是答题技巧？
3. 不同论文中的同名分数是否真的可比？
4. 怎样把公开 Benchmark 转化成自己的产品评测集和回归体系？

目标读者包括：

- 大模型评测、算法和数据工程师；
- 多模态产品、Agent、机器人与端侧应用从业者；
- 希望读懂模型报告和排行榜的技术产品经理；
- 想系统进入多模态评测领域的研究者和学生。

专栏读完后的预期收获不是记住几十个榜单，而是形成一套判断框架：

```text
任务场景
  ↓
需要哪些模态与能力
  ↓
哪些 Benchmark 能提供证据
  ↓
评测协议是否公平、可复现
  ↓
公开分数与真实业务之间还差什么
```

---

### 二、为什么现在适合系统写多模态评测

多模态评测已经从“图片问答”进入更复杂的阶段：

- 通用视觉题逐渐饱和，MMMU 开始让位于 MMMU-Pro 等加固版本；
- 模型报告从单图扩展到文档、长视频、音频、屏幕、GUI 和真实空间；
- 同一个模型的成绩会受到图片分辨率、抽帧策略、推理预算和工具使用显著影响；
- 视觉模型开始直接执行任务，评测对象从“回答”变成“轨迹和环境结果”；
- 图像、视频生成与编辑需要同时评价指令遵循、质量、一致性和安全性；
- 公开数据污染、评测集饱和、LLM-as-a-Judge 偏差变得越来越突出。

截至计划截点，官方资料已经体现出这种变化：

- OpenAI 的 GPT-5.4 多模态实践把文档理解拆为图像细节、转录忠实度、推理预算、定位和工具辅助等变量；
- Google 的 Gemini 3 Pro 官方视觉报告按文档、空间、屏幕和视频四个能力域组织评测；
- Google 对 Gemini 4 Argon 的公开披露已使用 LVBench 衡量长视频理解，而不再只依赖单图综合分；
- 最新模型报告仍引用 MMMU-Pro 等通用基准，但越来越依赖场景化、长上下文和端到端任务评测。

所以，本专栏的主线应从“谁的总分最高”转向：

> 多模态能力应如何被拆分、测量、复现和解释？

### 三、模型观察池：首篇建立，后续滚动更新

“最新模型”不是固定名单。专栏首篇建立模型观察池，之后每篇锁定发布时实际可用的精确版本。

初始观察池按阵营组织：

| 阵营 | 初始观察对象 | 关注重点 |
| --- | --- | --- |
| OpenAI | GPT-5.4，以及发布时更新的最新视觉/实时/图像模型 | 文档理解、空间定位、视觉推理、工具辅助、生成与编辑 |
| Google | Gemini 4 Argon、Gemini 3.x 系列及发布时最新版本 | 长视频、屏幕、空间、文档、原生多模态与长上下文 |
| Anthropic | 发布时可用的最新 Claude Opus/Sonnet/Haiku 或预览模型 | 视觉推理、计算机使用、文档、Agent 场景 |
| xAI | 发布时可用的最新 Grok 多模态模型 | 实时信息、视觉推理、Agent 与生成能力 |
| 中国闭源模型 | 豆包、混元、文心、Kimi、GLM 等发布时最新多模态版本 | 中文 OCR、文档、视频、端到端产品体验 |
| 开放权重模型 | Qwen-VL、InternVL、GLM-V、MiniCPM-V、Llama 多模态系列等最新版本 | 可复现性、部署成本、输入协议与开源评测脚本 |

每次引用模型成绩必须记录：

- 精确模型 ID 与发布日期；
- API、网页产品还是本地权重；
- reasoning/thinking 档位；
- 图片分辨率、图片数量或视频抽帧策略；
- 是否允许 OCR、代码执行、搜索或裁剪工具；
- prompt、采样参数、评测脚本版本；
- 分数来自厂商自报、论文复现还是独立榜单。

厂商自报成绩只作为“模型报告选择了什么证据”，不能直接当作独立结论。

### 四、多模态 Benchmark 地图

| 能力域 | 核心问题 | 代表 Benchmark |
| --- | --- | --- |
| 通用视觉理解 | 模型能否结合图像、知识和推理答题 | MMMU、MMMU-Pro、MMBench、MMStar、RealWorldQA |
| 数学与科学图解 | 能否读取图表、几何图和公式并完成多步推理 | MathVista、MathVerse、MathVision、AI2D、ScienceQA |
| OCR 与文档 | 能否识别文字、版面、表格、图表并跨页推理 | OCRBench、OCRBench v2、DocVQA、InfoVQA、ChartQA、CharXiv、OmniDocBench |
| 视觉幻觉 | 回答是否真正受图像约束，会不会编造对象或关系 | POPE、HallusionBench、MMHal-Bench |
| 空间与指代 | 能否定位、计数、理解深度、方向和对象关系 | RefCOCO 系列、BLINK、CV-Bench、VSI-Bench、ScreenSpot-Pro |
| 视频理解 | 能否理解事件、动作、字幕、音频和跨时间关系 | Video-MME、Video-MMMU、MVBench、MLVU、EgoSchema、TempCompass |
| 长视频 | 能否在长时上下文中定位证据并推理 | LongVideoBench、LVBench、MLVU、Video-MME 长视频子集 |
| 音频与语音 | 能否理解声音事件、语音、音乐及其组合 | MMAU、AudioBench、VoiceBench、BigBench Audio |
| 屏幕与 GUI Agent | 能否从截图定位控件并完成真实交互任务 | ScreenSpot-Pro、OSWorld、AndroidWorld、VisualWebArena |
| 图像生成 | 是否遵循组合指令，图像质量和文字渲染如何 | GenEval、DPG-Bench、T2I-CompBench、DrawBench、PartiPrompts |
| 图像编辑 | 是否只改该改的区域，并保留身份、布局与细节 | GEdit-Bench、PIE-Bench，以及任务化人工评测 |
| 视频生成 | 动作、物理、主体和镜头能否跨帧保持一致 | VBench、VBench-2.0、MovieGenBench，以及人工偏好评测 |
| 多模态安全 | 图像或音视频是否绕过安全边界，模型是否过度拒绝 | MM-SafetyBench、JailbreakV-28K、SIUO、MLLMGuard |
| 端到端产品能力 | 能否在真实输入、成本和延迟约束下稳定完成任务 | 自建场景集、在线 A/B、人工盲评、轨迹与环境结果检查 |

这张表不是最终清单。首篇会进一步制作“模型 × Benchmark × 模态 × 评测设置”的可更新矩阵。

### 五、核心季：12 篇正式目录

核心季优先覆盖最常出现在最新模型报告中、也最值得评测从业者掌握的内容。

### 第 0 篇：2026 多模态评测全景图——最新模型到底在比什么？

回答整个系列的入口问题：

- 什么才算多模态：图像输入、音视频理解、跨模态生成是否应放在一起？
- 最新模型报告常用哪些 Benchmark？
- 哪些基准正在饱和，哪些正在成为新标准？
- 厂商自报、公开排行榜、第三方复现为什么经常对不上？

核心产出：

- 一张模型 × Benchmark 矩阵；
- 一张多模态能力树；
- 一份“看到新模型报告先检查什么”的十问清单。

### 第 1 篇：多模态分数是怎样产生的？

讲清评测协议，而不是具体数据集：

- zero-shot、few-shot、Direct、CoT 和 agentic setting；
- 图片缩放、切图、拼图、多图顺序与视觉 token；
- 视频抽帧、字幕、音轨和最大上下文；
- exact match、accuracy、ANLS、IoU、LLM Judge 与人工偏好；
- parser、拒答、超时、失败重试怎样影响最终分数。

### 第 2 篇：拆解 MMMU——大学级多学科视觉推理是怎样测出来的？

重点介绍 MMMU 的领域、题型、图像类型、指标和局限，并解释它为什么成为近几年模型报告的通用入口。

### 第 3 篇：拆解 MMMU-Pro——当模型不能再靠文字线索和四选一猜题

直接采用现有 `mmmu-pro-blog.md` 作为正式样板篇，发布前只做一次时效性复核和图表补充。

### 第 4 篇：MMBench、MMStar 与 RealWorldQA——通用视觉榜单为何不能只看一个？

用横向比较解释：

- 数据覆盖和难度来源不同；
- 选择题、开放问答和真实图像的评价差异；
- 中文、英文和双语设置是否公平；
- 为什么多个通用基准仍不能合成一个“视觉智商”。

### 第 5 篇：MathVista、MathVerse 与 MathVision——模型真的会看图做数学吗？

重点拆开：

- OCR 错误与数学推理错误；
- 几何图、函数图、表格、统计图和科学插图；
- 答案正确但推理链错误的问题；
- 使用代码解释器后，测到的还是不是同一种能力。

### 第 6 篇：OCRBench v2 与文档理解评测——从“识字”到理解一份复杂报告

串联 OCRBench、DocVQA、InfoVQA、ChartQA、CharXiv、OmniDocBench，回答：

- OCR、版面分析、表格还原、图表推理如何分层；
- 单页正确率为什么不能代表长文档能力；
- 高分模型是否忠实保留文本、结构和坐标；
- 扫描件、手写体、小字号和多语言怎样改变结论。

### 第 7 篇：POPE 与 HallusionBench——多模态模型为什么“看见”不存在的东西？

重点讨论：

- 对象幻觉、属性幻觉、关系幻觉；
- yes/no 数据偏置与拒答策略；
- 感知失败、语言先验和迎合用户如何区分；
- 产品中如何把幻觉率转化为可接受风险。

### 第 8 篇：Video-MME——视频评测为什么不只是“多放几张图片”？

拆解短、中、长视频、字幕与音轨设置，讲清：

- 抽帧策略如何改变成绩；
- 看懂单帧和理解事件的区别；
- 字幕泄题、音频缺失与时间定位问题；
- 视频 API 的成本、吞吐和复现难点。

### 第 9 篇：Video-MMMU、LongVideoBench 与 LVBench——长视频真正难在哪里？

横向比较知识型视频、长时记忆、证据定位和跨片段推理，并讨论百万 token 上下文是否等于长视频理解。

### 第 10 篇：VSI-Bench、BLINK 与视觉定位——模型有“空间感”吗？

覆盖：

- 2D 指代与坐标定位；
- 深度、方向、遮挡和视角变化；
- 多视图空间推理；
- 机器人、AR 和 GUI 场景对空间评测的不同要求。

### 第 11 篇：ScreenSpot-Pro 与 OSWorld——从看懂屏幕到真正操作电脑

把静态 grounding 与动态 Agent 任务连起来：

- 找到按钮不等于完成任务；
- 坐标、DOM、视觉输入的公平性；
- 成功率、步骤数、恢复能力和副作用；
- 环境版本和应用状态为什么是 Benchmark 的一部分。

### 六、扩展季：8 篇进阶目录

### 第 12 篇：MMAU、AudioBench 与 VoiceBench——怎样评测“听得懂”

区分语音识别、音频事件、音乐、说话人、情绪、空间声学与音频推理，并讨论转写文本捷径。

### 第 13 篇：实时多模态评测——延迟、打断、轮次和音画同步

围绕实时语音与视频助手建立新的指标：首 token 延迟、可打断性、端点检测、重叠说话、画面变化响应和长会话稳定性。

### 第 14 篇：GenEval、DPG-Bench 与 T2I-CompBench——图像生成怎样从“好看”走向“可测”

讨论对象数量、颜色、位置、属性绑定、文字渲染、组合遵循，以及 CLIP 类指标为何不等于人类偏好。

### 第 15 篇：图像编辑评测——怎样证明模型只改了该改的地方？

关注指令遵循、局部保持、身份一致、背景稳定、文字与布局保持，并比较自动指标、视觉 Judge 和人工盲评。

### 第 16 篇：VBench 与视频生成评测——好视频为何比好图片更难定义？

覆盖主体一致、动作完整、物理合理、镜头语言、音画同步、指令遵循和跨帧伪影。

### 第 17 篇：MM-SafetyBench 与视觉越狱——图片如何绕过模型安全边界？

同时评测攻击成功率、正常任务保持率和过度拒绝，避免把“全部拒答”误判为安全。

### 第 18 篇：公开 Benchmark 为什么会失效？

系统讨论：

- 训练污染与测试集泄漏；
- 数据饱和和版本漂移；
- prompt overfitting；
- LLM Judge 的位置偏差、风格偏差和自偏好；
- 私有集、动态集、对抗集和时间切片。

### 第 19 篇：实战——为一个多模态产品搭建最小可用评测系统

以真实业务为例完成闭环：

```text
能力拆解
  → 样本与标注规范
  → 运行器与适配器
  → 自动指标 + 人工复核
  → 失败归因
  → 成本/延迟/质量联合报告
  → 版本回归门禁
```

最终交付一套可复用模板，而不是只给概念。

### 七、每篇文章的固定结构

为了让读者形成稳定预期，每篇尽量沿用现有 MMMU-Pro 样板：

1. 一个真实、容易误判的开场案例；
2. Benchmark 想解决的核心问题；
3. 数据来源与构造流程；
4. 输入、任务和数据 schema；
5. 评测设置与指标公式；
6. 官方 baseline 与最新模型为何选用它；
7. 最小复现实验；
8. 一个容易踩坑的实现细节；
9. 失败案例与能力归因；
10. 数据污染、饱和与公平性问题；
11. 对产品评测的可迁移设计；
12. “看到这个高分时应该问什么”；
13. 结论与参考资料。

每篇至少包含四类可带走的内容：

- 一张结构图或构造流程图；
- 一张与相邻 Benchmark 的比较表；
- 一个可运行或伪代码级的评测示例；
- 一份复现与读榜检查清单。

### 八、统一的研究与事实核验标准

### 8.1 来源优先级

```text
Benchmark 原论文 / 官方仓库 / 官方数据集
  > 模型技术报告与系统卡
  > 独立复现与公开排行榜
  > 高质量二手解读
```

### 8.2 分数分级标注

文章中对成绩使用明确标签：

- **厂商自报** ：来自模型官方博客、技术报告或系统卡；
- **论文实验** ：来自 Benchmark 论文的统一协议；
- **独立复现** ：由第三方在公开设置下运行；
- **不可直接比较** ：prompt、输入、工具或脚本版本存在关键差异。

### 8.3 复现最低要求

- 固定数据 revision 和脚本 commit；
- 保存完整 prompt 与模型原始输出；
- 记录不可解析率、超时率和缺失样本；
- 报告图片预处理与视频抽帧设置；
- 区分原生最佳设置与受控公平设置；
- 小样本复现必须给置信区间，不把随机波动写成确定结论。

### 8.4 时效策略

- 每篇动笔前重新核验最新模型报告；
- 不在标题中永久绑定某个“最强模型”；
- 模型矩阵按月更新，正文保留截点日期；
- Benchmark 出现 v2、Pro 或修订版时，明确说明迁移关系；
- 已饱和基准不删除，而是解释它为何失去区分度。

### 九、写作与发布节奏

### 第一阶段：先建立共同语言（第 0—3 篇）

目标是让读者能读懂任何一张多模态榜单。第 3 篇 MMMU-Pro 已有完整初稿，可作为系列深度和风格基准。

### 第二阶段：覆盖高频输入能力（第 4—11 篇）

按通用视觉、数学、文档、幻觉、视频、长视频、空间和屏幕 Agent 逐层展开。

### 第三阶段：补齐原生多模态与生成（第 12—17 篇）

扩展到音频、实时交互、图像与视频生成、安全。

### 第四阶段：形成自己的评测方法（第 18—19 篇）

把前面的 Benchmark 知识收束为私有集、回归体系和产品决策方法。

建议不要一次写完再发布。更适合采用：

```text
发布 1 篇
  → 收集读者疑问
  → 更新模型-Benchmark 矩阵
  → 把高频疑问加入下一篇
```

### 十、核心季的完成标准

核心 12 篇完成后，这套专栏应能让读者：

- 解释最新模型报告为什么选用某组多模态 Benchmark；
- 判断两个公开分数能否直接比较；
- 将错误归因到 OCR、感知、知识、推理、时序、定位或执行；
- 复现至少一个图片和一个视频 Benchmark 的子集；
- 为自己的产品选出公开基准、私有集与人工评测的组合；
- 不再把单一总分当作“多模态智能”的完整证明。

---

### 十一、建议的启动顺序

1. 先写第 0 篇“2026 多模态评测全景图”，建立最新模型 × Benchmark 矩阵；
2. 再写第 1 篇“分数是怎样产生的”，统一后续术语和协议；
3. 补齐 MMMU 基础篇；
4. 发布现有 MMMU-Pro 深度篇；
5. 根据读者反馈，在通用视觉、文档和视频三条线中选择最受关注的一条继续。
