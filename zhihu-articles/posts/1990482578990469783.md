## 一、NVIDIA GPU 架构发展演进

针对数据中心（Data Center）领域，NVIDIA 的架构演进主要围绕 **计算单元（Compute Unit）**、**显存（Memory）** 和 **互联（Interconnect）** 三大方向。 以下主要对 NVIDIA 的数据中心级别 GPU 核心架构从“AI 爆发前夜”到“大模型时代”的迭代演进进行梳理。

![](https://picx.zhimg.com/v2-2027da620525581749cf26f0ff45dcf5_r.jpg)
*NVIDIA GPU 近十年算力千倍增长*

### 1. Pascal 架构 - AI 计算的黎明

帕斯卡（Pascal）架构 于 2016 年发布，是 GPU 发展史上的重要里程碑。它标志着 NVIDIA 从纯图形渲染向高性能计算（HPC）与人工智能（AI）领域的战略转型。

### 1. 诞生背景

在帕斯卡架构问世前，随着深度学习兴起，市场对数据中心算力和显存带宽的需求呈爆炸式增长。前代 Maxwell 架构在能效比上虽有突破，但在大规模并行计算和高速互连方面仍显不足。

### 2. 代表产品

• 消费级： 经典的 GTX 10 系列（如 GTX 1080⁄1080 Ti），凭借极高的主频和能效比，被玩家誉为“一代神卡”。

• 专业级： Tesla P100，这是首款专为数据中心和 AI 训练打造的加速卡。

### 3. 关键更新特点

• **16nm FinFET 工艺**： 相比 28nm 工艺，晶体管密度和能效大幅提升，核心频率首次突破 2GHz 门槛。

• **支持 FP16 半精度计算**： 专门针对深度学习优化，使训练速度相比单精度（FP32）大幅提升。这是混合精度训练的雏形。

![](https://pic3.zhimg.com/v2-e0f993198b683360efa9102fad0ff434_r.jpg)
*P40 采用FP16精度运算*

• **HBM2 高带宽显存**： 首次在 Tesla P100 上应用，解决了传统显存的带宽瓶颈，带宽从 GDDR5 的几十 GB/s 暴涨到 732 GB/s。这是解决 Memory-bound 的里程碑。

• **NVLink 互连**： 引入了全新的高速互连技术，允许多个 GPU 之间以远超 PCIe 的速度交换数据。

![](https://picx.zhimg.com/v2-4dda190c0b93d055ffe2f42d85f9a77b_r.jpg)
*第一代 NVLink*

### 2. Volta 架构 - 里程碑 Tensor Core 的诞生

如果说帕斯卡架构是向 AI 的“试水”，那么 2017 年发布的 伏特（Volta）架构 则是 NVIDIA 彻底统治 AI 算力市场的“核武”。

### 1. 诞生背景

随着大模型（如早期的 Transformer）对算力需求的渴求，矩阵乘法（GEMM）占据了神经网络 90% 以上的计算量，传统的 CUDA Core（标量/向量单元）已捉襟见肘。NVIDIA 意识到需要一种专门针对**张量运算**（Tensor Operations）的硬件单元，于是 Volta 应运而生，目标直指深度学习的最前线。

### 2. 代表产品

• 计算卡： Tesla V100，当时全球最强大的 AI 加速器。

• 顶级显卡： TITAN V，被戏称为“披着马甲的计算卡”，主要面向研究人员。

### 3. 关键更新特点

• **Tensor Core**（张量核心）首次亮相： 这是 Volta 的灵魂。它专门用于处理深度学习中的矩阵乘法，使 AI 训练性能比帕斯卡架构提升了 12 倍。

![](https://pic1.zhimg.com/v2-e46e1e8c605a9e8bf804fff3de1b8eba_r.jpg)
*Tensor Core in GeMM*

![](https://pic4.zhimg.com/v2-a8bf2dcf964857ca1b3a190beb843ad3_r.jpg)
*Volta 架构相对比 Pascal TensorCore加速*

• 台积电 12nm FFN 工艺： 在晶体管规模上实现了巨大飞跃（V100 拥有 211 亿个晶体管）。

• **NVLink 2.0**： 带宽进一步升级，单链路速度更快，支持更复杂的 GPU 集群互连。

• **L1 缓存与共享内存统一**： 虽然还没完全分离，但改进了缓存结构，提升了 SM (Streaming Multiprocessor) 的利用率，显著降低了编程难度并提升了数据读取效率。

### 3. Ampere 架构 - 易用性与稀疏化

2020 年发布的 安培（Ampere）架构 是 NVIDIA 历史上跨度最大的架构之一，它不仅统一了数据中心与消费级市场，更在疫情背景下掀起了算力的全球狂潮。

### 1. 诞生背景

随着 GPT-3 等超大规模参数模型的出现，AI 训练对显存容量和互连带宽的要求达到了近乎苛刻的程度。同时，光线追踪（Ray Tracing）在游戏领域的普及，也需要硬件能在大分辨率下保持流畅，安培架构正是为此“暴力性能”需求而生。

### 2. 代表产品

• 消费级： RTX 30 系列（如 RTX 3080/3090），性能相比前代实现翻倍增长。

• 数据中心： NVIDIA A100，它成为了随后几年全球 AI 企业抢购的核心战略资源。

### 3. 关键更新特点

• **第三代 Tensor Core**： 支持全新的 **TF32** （19位范围，10位精度）数据格式，无需修改代码即可获得加速，并引入了“结构稀疏性” (Structured Sparsity)技术，将 AI 计算效能进一步翻倍。

![](https://pica.zhimg.com/v2-c385eb058cbb98c1d11c24e534d9c994_r.jpg)
*TF32 （FP19）混合精度*

• 多实例 GPU（MIG）技术： 允许将一个 A100 物理核心切分为 7 个独立实例，极大提高了云端算力的利用率。这对于云厂商卖算力非常重要。

• **双精度（FP64）性能跃升**： 让 GPU 在科学计算（气象模拟、药物研发）领域也变得异常强大。

![](https://picx.zhimg.com/v2-8cfc5e7cd4cbef3de36a812aed333173_r.jpg)
*TensorCore in Ampere*

### 4. Hopper 架构 - 为 Transformer 而生

2022 年发布的 Hopper架构是 NVIDIA 专为生成式 AI 大模型革命量身定制的加速引擎，其命名致敬了计算机科学先驱 Grace Hopper。它正式开启了万亿级参数大模型的“分钟级”训练时代。

### 1. 诞生背景

随着 ChatGPT 等 Transformer 模型引爆全球，AI 领域进入了“暴力美学”阶段。为了应对海量的浮点运算和数据吞吐，NVIDIA 需要一种能跳出传统 GPU 设计思维，直接从硬件底层加速 Transformer 计算的新架构。

### 2. 代表产品

• 核心旗舰： NVIDIA H100（及其升级版 H200），成为全球科技巨头竞相储备的“数字黄金”。

• 超级芯片： Grace Hopper (GH200)，将 CPU 与 GPU 通过高速 NVLink-C2C 互连。

### 3. 关键更新特点

• **Transformer 引擎（Transformer Engine）**： 能够动态切换精度（如全新的 FP8），在不损失精度的前提下，将大模型的推理速度提升了 30 倍。

![](https://pic3.zhimg.com/v2-a9c0f740056fdb020d0d123206d279bc_r.jpg)
*Transformed Engine*

![](https://pic4.zhimg.com/v2-9d526137279cf5c2c801f018a8cc4cbf_r.jpg)
*FP8 混合精度*

![](https://pic2.zhimg.com/v2-dbcd2df846baba79f12d800bdbeb8555_r.jpg)
*FP8 相对Ampere提升6倍吞吐*

• **Tensor Memory Accelerator (TMA)**：解放 CPU 和 SM。这是一个超级 DMA，可以自动把数据从 Global Memory 搬到 Shared Memory，甚至处理地址计算，SM 只需要等着算就行。这是写 H100 高性能算子的关键。

![](https://pic2.zhimg.com/v2-441a91c0b88386bf501d060f27c4e7f9_r.jpg)
*TMA*

• 台积电 4N 工艺： 单芯片集成了 800 亿 个晶体管，性能与能效比达到惊人高度。

• 第四代 NVLink 与外部交换机： 允许数万个 GPU 像单颗芯片一样协同工作，突破了单机算力的极限。带宽达到 900 GB/s，让 8 卡 H100 像一块大显卡一样工作。

Hopper 架构基本确立了 NVIDIA 在数据中心的霸主地位。

### 5. Blackwell 架构 - 芯片互联与低精度极限

2024 年发布的 Blackwell 架构 是 NVIDIA 应对万亿参数级大模型（LLM）算力饥渴的巅峰之作，被黄仁勋称为“推动新一次工业革命的引擎”。

### 1. 诞生背景

随着生成式 AI 进入“万亿参数”时代，单颗芯片的物理极限已无法满足庞大的训练与推理需求。为了追求摩尔定律之外的突破，Blackwell 彻底放弃了单芯片方案，转而采用双芯片（Dual-die）拼合技术，旨在将 AI 成本和能效降低一个数量级。

### 2. 代表产品

• AI 旗舰： B100 / B200，单芯片拥有 2080 亿个晶体管。

• 超级芯片： GB200，将两颗 B200 GPU 与一颗 Grace CPU 结合，推理性能提升 30 倍。

![](https://picx.zhimg.com/v2-d3cec7d5a6cc2965b8e44beb80531025_r.jpg)
*GB200*

• 消费级： RTX 50 系列（基于 Ada 演进后的 Blackwell 变体），引入了 DLSS 4 等更强的图形技术。

### 3. 关键更新特点

• **双芯片统一架构**： 又称之为Chiplet (小芯片) 设计，通过 10TB/s 的高速接口将两块硅片连为一体，开发者无需修改代码即可将其视为单颗 GPU 调用。

![](https://picx.zhimg.com/v2-42b8168744fbc51f84150fe1fa110d45_r.jpg)
*Blackwell Dual Die*

• **第二代 Transformer 引擎**： **引入了 FP4**（4位浮点，4-bit Floating Point） 精度。在不牺牲模型精度的前提下，将显存容量翻倍，推理速度最高提升 30 倍。

![](https://pic1.zhimg.com/v2-157bb5779691353d91a9e54f7ba135a8_r.jpg)
*Tensor Core evolution*

• 第五代 NVLink： 实现了单芯片 1.8TB/s 的惊人带宽，支持构建包含 576 个 GPU 的超巨型计算集群。

### 小结

汇总整理了这几代架构在 AI infra 方向的发展要点：

| 架构 | 代表显卡 | 核心硬件特征 | 对 Infra 开发者的影响 (Key Takeaway) |
| --- | --- | --- | --- |
| Pascal | P100 | HBM2, FP16 | 开始关注混合精度训练，关注显存带宽。 |
| Volta | V100 | Tensor Core (v1) | 掌握 WMMA API (Warp-level Matrix Multiply Accumulate)，矩阵乘法从标量变为矩阵指令。 |
| Ampere | A100 | TF32, MIG, 异步拷贝 | 掌握异步拷贝指令；利用 TF32 偷懒（不需要转 FP16 也能加速）。 |
| Hopper | H100 | FP8, TMA, DPX | 学习 TMA 编程（解放寄存器）；FP8 量化算子开发；分布式通信优化。 |
| Blackwell | B200 | FP4, Chiplet | 极低精度推理优化；超大规模集群通信（NVL72）与拓扑感知。 |

## 二、Ascend 昇腾芯片发展对标

华为昇腾（Ascend）系列 NPU 的发展路径与 NVIDIA 走过了截然不同的技术路线。NVIDIA 是从通用 GPU 逐步演化为 AI 加速器，而昇腾从诞生之初就是为了 AI 矩阵运算设计的 **DSA**（领域特定架构）。

其核心演进逻辑围绕着**达芬奇**（Da Vinci）架构的迭代，以及配套软件栈 **CANN**（Compute Architecture for Neural Networks） 的成熟。

### 1. 昇腾 NPU 架构演进历程

昇腾 NPU 的核心是“达芬奇架构”，其最显著的特征是 **3D Cube**（立方体计算单元）。这与 NVIDIA 的 Tensor Core 异曲同工，但在设计上更加激进，追求极致的矩阵运算吞吐量。

![](https://pic3.zhimg.com/v2-9a000e89c70d58314f2daa36401566c0_r.jpg)

### 1. 达芬奇 1.0 (Ascend 910⁄310)

- 发布时间： 2018-2019年
- 核心代表： 昇腾 910 (训练)、昇腾 310 (推理)
- 特点： 首次提出 3D Cube 设计。910 采用当时领先的 7nm 工艺（TSMC），FP16 算力达到 **256-320 TFLOPS**，在当时直接挑战了 NVIDIA 的 Volta 架构（V100）。

### 2. 达芬奇 2.0 (Ascend 910B)

- 发布时间： 2022-2023年
- 核心代表： 昇腾 910B 系列
- 特点： 这一代是目前国内大模型训练的主力。它在 1.0 的基础上大幅强化了算子覆盖度和显存带宽（HBM），解决了前代在大模型场景下通信带宽和内存容量不足的痛点。
- 地位： 被广泛认为是国内最能接近 NVIDIA A100 实际表现的国产芯片。

### 3. 达芬奇 3.0 (Ascend 910C/D)

- 发布时间： 2024-2025年
- 核心代表： 昇腾 910C、910D
- 特点： 引入了更先进的片上互联技术（HCCS）和更高效的指令集。根据最新的评测（如 DeepSeek 等厂商的实测），910C 在大模型推理上的性能已能达到 NVIDIA H100 的 60% 甚至更高。

### 2. 昇腾与 NVIDIA 的对标关系图

为了直观理解华为在不同阶段追赶的位置，我们可以参考下表，以下表是行业内公认的 **“代际对标”** 关系：

| 昇腾产品 (Ascend) | 对标 NVIDIA 产品 | 状态与定位 | 核心评价 |
| --- | --- | --- | --- |
| Ascend 910 (第一代) | Tesla V100 | 早期产品 | 理论算力强（FP16 甚至超过 V100），但显存较小 (32GB)，生态不成熟，难以跑大模型。 |
| Ascend 910B (主力军) | A100 (40GB/80GB) | 当前主流 | 这是目前国内训练大模型的主力。在算力、显存带宽上高度对标 A100。部分算子性能可达 A100 的 80%-120%，但集群通信和生态易用性有差距。 |
| Ascend 910C (即将/内部) | H100 | 追赶者 | 目标是对标 H100。重点提升了互联带宽（解决集群瓶颈）。 |
| Ascend 310系列 | Tesla T4 / L4 | 边缘推理 | 低功耗推理卡，用于安防、端侧设备。 |

### 3. 硬件架构层面的深度对标 (Infra 视角)

作为 Infra 工程师，不能只看产品性能型号，以下我们从“**计算-访存-互联**”的三维对比 **昇腾 910B** 和 **NVIDIA A100** 的两款产品。虽然两者都能处理万亿级参数模型，但实现路径大相径庭。

### 1. 计算单元：DSA 专用矩阵计算 vs. 通用流处理器

NVDIA 和 昇腾 在架构哲学存在根本区别。

NVIDIA A100 的计算核心，依靠 **Tensor Core** (第三代)。核心是 **SM (Streaming Multiprocessor)** ，每个计算核心分为两个部分 **CUDA Core** (标量/向量) + **Tensor Core** (矩阵)。在保持通用性的同时增强了矩阵运算。其优势非常灵活，除了 AI 矩阵运算，它还能处理科学计算（FP64）和复杂的逻辑分支，Tensor Core 负责加速 $4 \times 4$ 或 $8 \times 8$ 矩阵乘。对于非标准形状的算子（Operators），A100 的适应性更强。算力方面，理论上 FP16 理论峰值为 **312 TFLOPS**（开启 Sparsity 稀疏化计算 可达 624 TFLOPS ）。

![](https://pic3.zhimg.com/v2-ba2d231b96d7925a4dc56e54977392f0_r.jpg)
*A100 inside*

昇腾 910B 遵循自研的 **达芬奇 2.0 架构**，计算核心由三个部分组成，**Cube Unit (矩阵单元)** + **Vector Unit (向量单元)** + **Scalar Unit (标量单元)**。它的核心依靠 **3D Cube** (立方体计算单元)，一次性计算 $16 \times 16 \times 16$ 的分形矩阵（Fractal）。这是一种典型的 DSA（领域特定架构），专门为矩阵乘加运算设计。在处理大规模平整矩阵（Large Batch Size）时，3D Cube 的数据重用率极高，单位功耗下的矩阵算力极强。910B FP16 理论峰值约为 **320 TFLOPS**，在纸面参数上微优于 A100。

![](https://pic3.zhimg.com/v2-ce9674bc311b6580b3afff94601f3a58_r.jpg)
*Da Vinci inside*

### 2. 显存系统：容量与带宽上基本持平

在大模型训练中，显存往往比算力更先遇到瓶颈。

| 特性 | NVIDIA A100 (SXM版) | 昇腾 910B | 分析 |
| --- | --- | --- | --- |
| 显存类型 | HBM2e | HBM2e / HBM3 | 910B 后期型号采用了规格更高的显存。 |
| 显存容量 | 80 GB | 64 GB / 96 GB | 910B 的大容量版本在加载超大模型参数时有优势。 |
| 显存带宽 | 2.0 TB/s | 约 1.2 TB/s | A100 胜出。数据搬运速度更快，意味着计算单元“断粮”的时间更短。 |

对比结论： 华为在 910B 上提供了更大的显存容量（最高 96GB），这对节省多卡拆分模型的复杂度很有帮助；但 NVIDIA 在显存吞吐效率（带宽）上依然保持着传统优势。

### 3. 互联技术：HCCS 与 NVLink 有较大差距

单卡算力再强，跑不动万卡集群也是徒劳。互联技术是决定大模型训练效率的关键。 A100 采用 NVIDIA NVLink (第三代) 技术，双向带宽： **600 GB/s**。配合 NVSwitch，可以实现 8 张卡之间的全互联。NVIDIA 的集群通信协议（**NCCL**）极度成熟，几乎零损耗。

![](https://pic1.zhimg.com/v2-e1ab62c23846cb4e305a2739692c8e68_r.jpg)

华为 **HCCS (Huawei Cache Coherence System)**，双向带宽理论值推测约 392 GB/s （具体数值不可知) 。它是华为自研的高速互联协议，支持 8 卡全互联。虽然单通道带宽略逊于 NVLink 3.0，但华为在集群组网（使用其自研的 RoCE 网络交换机）方面有深厚积累。昇腾集群通常采用 **“胖树 (Fat-Tree)”** 或特定的环状拓扑，通信效率（Linearity）在大规模集群（千卡级别）下比 NVIDIA 弱。**这需要 Infra 工程师手动优化通信算子（AllReduce）来规避拥塞**。在最新的 CANN 8.0 版本中已经大幅优化。

总结一下，从**单卡效能**角度，昇腾 910B 的 FP16 原始算力与 A100 处于同一水平线，甚至在某些纯矩阵运算场景下依靠 **3D Cube** 的暴力输出能实现 20% 的超越。从**软件生态**角度， A100 完胜。CUDA 生态意味着“拿来即用”；昇腾则需要通过 **CANN** 进行算子转换，虽然华为已经搞定了 PyTorch 的深度适配，但对于一些前沿、冷门的算法，开发者仍需手动调优。从**交付现状**来看， A100 受进出口管制，而 910B 是目前国内唯一能大规模稳定供应、且能支撑万亿参数模型训练的 A100 等级替代品。

### 4. 软件生态对标 (软件工程师视角)

华为使用的 **CANN (Compute Architecture for Neural Networks)** 工具链，在 NVIDIA 都有对应组件：

| 功能模块 | NVIDIA (CUDA 生态) | 华为昇腾 (CANN 生态) | 作用描述 |
| --- | --- | --- | --- |
| 编程语言/接口 | CUDA C/C++ | Ascend C | 开发者直接编写硬件核心（Kernel）代码的方式。 |
| 基础算子库 | cuBLAS / cuDNN | L0 算子库 (ACLNN) | 预制的矩阵乘法、卷积等 AI 常用数学函数。 |
| 集群通信库 | NCCL | HCCL | 负责多卡、多机之间的数据交换（如 AllReduce）。 |
| 统一编程接口 | CUDA Runtime API | AscendCL (ACL) | 应用程序调用硬件资源的统一入口（内存申请、流管理）。 |
| 图编译器 | TensorRT / XLA | Graph Engine (GE) | 将 AI 模型转换成硬件能识别的“计算图”。 |
| 算子开发工具 | Triton / CUTLASS | TBE / Ascend C | 帮助开发者自定义编写特殊算法的工具。 |
| 性能分析工具 | Nsight Systems | Ascend Insight (Profiling) | 查找代码运行瓶颈、分析耗时的工具。 |

## 三、深入挖掘硬件细节对比

我们仍然以 **NVIDIA A100** 为基准，对比 NVIDIA GPU 和 Ascend NPU的技术细节。

### 1. 宏观层级：从 Device 到 SM

在昇腾架构里，核心计算单元叫 **AI Core**，在 NVIDIA 里，核心计算单元叫 **SM (Streaming Multiprocessor，流式多处理器)**。 DaVinci架构中单个Device 的 AI Core 数量按照其芯片的配置从几个到数十个不等，追求**数据流的高效处理**，同一块数据会被切分成不同块，搬运到不同AI Core上进行并行计算。

![](https://pica.zhimg.com/v2-4f379ef1cf62e2b2ba6c0cee509a1c4a_r.jpg)
*AI core and AI vector*

**NVIDIA**的GPU 分为多个层级架构，GPC (图形处理簇）是芯片最顶层的划分，每个 GPC 包含多个 TPC(纹理处理簇) ，每个TPC又分为多个 **SM** ，在A100 芯片中有 108 个 SM。

![](https://picx.zhimg.com/v2-e7301af4ed5714b856ca465822dea155_r.jpg)
*NVIDIA A100 GPU*

**SM** 是 NVIDIA GPU 的心脏。工程师写的 CUDA Kernel 中的一个 Block（线程块）通常会被调度到一个 SM 上执行。

### 2. 微观层级：SM 内部详解 (Deep Dive into SM)

一个 SM 内部并不是“铁板一块”，而是被物理分割成了 **4 个分区 (Partitions / Sub-Cores)**。每个分区可以独立执行指令。我们将 SM 内部组件与 DaVinci 架构进行一一映射：

### A. Tensor Core (对应 DaVinci Cube Unit)

这是 NVIDIA 的矩阵计算引擎。 NVIDIA 的 **Tensor Core**，内部被切分成四个分区，每个 SM 有 4 个 Tensor Core（每个分区 1 个）。A100 的 Tensor Core 基础粒度是 $8 \times 4 \times 8$ (FP16)。它不像 Cube 那样一次算一大块，而是通过多个 Tensor Core 并行，并在多个时钟周期内拼凑出大矩阵的计算。

![](https://picx.zhimg.com/v2-924ddd2c0b822458ceb6ecc9b499bfb1_r.jpg)
*NVIDIA A100 SM*

**DaVinci Cube** 是一个巨大的 $16 \times 16 \times 16$ 阵列。下图以分离架构为例，分离架构将AI Core拆成矩阵计算（AI Cube，AIC）和向量计算（AI Vector，AIV）两个独立的核，与耦合架构相区别。

![](https://pic3.zhimg.com/v2-53f94f78b576bca4a5f4b0c1a61fc320_r.jpg)

### B. CUDA Core (对应 DaVinci Vector Unit)

这是处理向量运算（Add, Mul, Div）的地方，一个 CUDA Core 通常是指一个能执行 **单精度浮点运算 (FP32)** 或 **整数运算 (INT32)** 的流水线（ALU），是SM内部的最小计算单元。**NVIDIA CUDA Core** 中 **FP32 Core**: 专门算 `float`，**INT32 Core**: 专门算 `int` (通常用于地址计算，loop 索引)，**FP64 Core**: 算双精度 (HPC 领域用，AI 用得少)。**A100 配置** 中每个 SM 有 64 个 FP32 Cores，64 个 INT32 Cores。

**DaVinci Vector** 使用Vector Unit计算向量，算力非常强劲，专门处理非矩阵运算。

### C. SFU (Special Function Unit, 对应 DaVinci Vector 的部分功能)

在 **NVIDIA SFU** 里有专门的硬件单元处理超越函数（sin, cos, exp, log, rsqrt）。SFU 的数量通常比 CUDA Core 少（A100 每个 SM 只有 16 个 SFU），所以算 `Softmax` 里的 `exp` 是昂贵的操作。**DaVinci** 一般在 Vector Unit 中计算 `exp`, `log`, `1/x`。

### D. Warp Scheduler (对应 DaVinci Scalar Unit 的调度职能)

**NVIDIA Warp Scheduler** 在NVIDIA架构中， 控制核心是 **Warp (线程束)**。一个 Warp 包含 32 个线程 (Threads)，Scheduler 每周期从 Warp 中挑选指令发射给 CUDA Core 或 Tensor Core 执行。 **DaVinci Scalar**计算单元负责控制流（if/else/loop）和地址生成。

![](https://pica.zhimg.com/v2-49555a0f6da7b122de6264efbf485258_r.jpg)
*Scarlar*

可以理解为 DaVinci 是显式地写指令控制 Cube；NVIDIA 是通过调度 32 个线程的集体行为来驱动硬件。

### 3. 存储层级 (Memory Hierarchy)

NVIDIA A100 和昇腾 DaVinci 910B 的存储层级设计体现了“**通用缓存体系**”与“**显式缓冲区体系**”的对比。A100 依赖巨大的统一 L2 缓存和硬件调度来简化编程；而 910B 则通过精细化的专用缓冲区（Buffer）和手动控制数据流来换取极高的 AI 计算能效比。

### A. NVIDIA A100：多级缓存（Cache）体系

A100 的设计核心是尽可能减少对 HBM 的访问，利用大容量统一 L2 作为所有 SM 核心的“中央仓库”。

- 寄存器堆 (RF): 每个 SM 拥有 256KB，总量惊人（约 27MB），用于存储瞬时运算变量。
- L1 Cache / Shared Memory: 每个 SM 拥有 192KB。这块区域既可以由硬件自动管理（Cache），也可以由程序员手动划定（Shared Memory），用于线程间通信。
- L2 Cache (统一存储): 40MB。这是 A100 的关键，所有 SM 共享，极大地缓解了从 HBM 读取数据的延迟。
- HBM2e: 80GB，提供 2TB/s 的带宽。

### B. 昇腾 910B：专用缓冲区（Buffer）体系

910B 采用的是达芬奇架构典型的“**存算分离**”设计。它没有通用的大型 L2 Cache 概念，而是为不同的计算单元设计了专用的“小仓库”。

- L0 缓冲区 (L0A, L0B, L0C): 紧贴 Cube 单元。L0A/B 存储矩阵输入，L0C 存储累加结果。大小通常在 KB 级别，确保计算单元每个周期都能拿到数据。
- Unified Buffer (UB): 每个 AI Core 拥有一个约 256KB-512KB 的统一缓冲区，由 Vector 单元共享，用于存放向量计算数据或临时变量。
- L1 Buffer: 约 1MB-2MB 左右，作为显存与 L0/UB 之间的中转站，由 MTE 管理。
- HBM3/2e: 64GB/96GB，提供数据持久化存储。

以下是存储单元数量与大小 (估算对比)

| 存储层级 | NVIDIA A100 (SXM 80GB) | 昇腾 910B (典型值) | 差异点分析 |
| --- | --- | --- | --- |
| 最快层级 (寄存器/L0) | 每个 SM 256KB (共 ~27MB) | 每个 AI Core 拥有独立的 L0A/B/C | 华为将空间划分为专用矩阵区，NVIDIA 是通用的寄存器堆。 |
| 中层缓存 (L1/Shared/UB) | 192KB / SM | 256KB - 512KB (UB) / Core | 华为的 UB 空间更大，适合处理复杂的 Vector 算子。 |
| 全局缓存 (L2/L1 Buffer) | 40MB (统一 L2) | 约 1MB - 2MB (L1 Buffer) / Core | 最大差异点：NVIDIA 靠巨型 L2 自动命中；华为靠各核心独立的 L1 显式搬运。 |
| 底层显存 (HBM) | 80GB (2.0 TB/s) | 64GB/96GB (1.2-1.6 TB/s) | 华为容量占优，NVIDIA 带宽占优。 |

由于硬件架构的区别，导致在实际开发中，考虑的数据流向也存在巨大的差异。

NVIDIA A100 的数据流 以硬件为主，数据路径相对垂直：HBM ↔ L2 ↔ L1/Shared ↔ Register。

- 自动机制： 当代码请求一个变量时，硬件自动检查 L1、L2 是否命中。
- 优化手段： 开发者使用 Async Copy 将数据从 HBM 直接推入 Shared Memory，绕过寄存器以节省功耗。

昇腾 910B 的数据流 以MTE 驱动，数据路径横向且高度解耦，依赖 MTE (存储搬运单元) 执行：

- HBM → L1 Buffer: MTE2 将原始数据读入 AI Core。
- L1 Buffer → L0A/B (矩阵) 或 UB (向量): MTE1 根据算子需求，将数据分发到指定的计算等待区。
- L0C / UB → HBM: MTE3 将结果写回。

![](https://pic4.zhimg.com/v2-9bcbe3aba7974666c40743fc8941d95b_r.jpg)
*MTE*

由于昇腾的数据流在搬运过程中（MTE2）往往伴随着 ND 转 Fractal (分形) 的格式重组，这让计算单元拿到数据后可以直接进行 3D 卷积/矩阵运算，无需二次转换。

### 注意：与CPU 存储层级联系与区别

**GPU 的存储系统也是一个典型的“金字塔”架构**，其核心逻辑与 CPU 极其相似——即通过牺牲容量来换取速度，或者通过牺牲速度来换取容量。

![](https://pic2.zhimg.com/v2-a36363ca0898d0ed208ba1ac8266db73_r.jpg)
*GPU memory Arch*

不过，由于 GPU 是为了“吞吐量”设计，而 CPU 是为了“延迟”设计，它们在细节上存在非常有趣的差异。具体对比如下表格：

| 维度 | CPU (Latency Oriented) | GPU (Throughput Oriented) |
| --- | --- | --- |
| 金字塔顶端 | 追求极低延迟。L0/L1 必须在几个时钟周期内返回数据，否则 CPU 核心就会“空转”。 | 追求极高带宽。GPU 不怕延迟，它通过同时运行更多线程来“隐藏”延迟。 |
| 寄存器规模 | 小而精。每个核心只有几十个寄存器。 | 大而多。为了支撑成千上万线程并发，寄存器单个只有KB级别，但是总量极大。 |
| L3 缓存 | 标配。通常有巨大的 L3 Cache（几十 MB）来减少对内存的访问。 | 通常没有 L3。GPU 只有 L1 和 L2，因为 GPU 的任务通常是流式数据，L3 这种大容量缓存的性价比不高。 |
| 主内存 | DDR 内存。容量大（TB级），延迟低，但带宽窄（几百 GB/s）。 | HBM (高带宽显存)。容量较小，但带宽恐怖（TB/s级），专门处理海量并行数据。 |

### 4. 数据搬运引擎：MTE 的 NVIDIA 孪生兄弟

DaVinci 靠 **MTE (Memory Transfer Engine)** 搬运数据。NVIDIA 中并没有一个名为“MTE”的单一独立硬件模块，但其功能由 **LSU (Load/Store Unit)** 和 **DMA/Copy Engine** 共同承担。

| 功能维度 | 昇腾 MTE (Memory Transfer Engine) | NVIDIA A100 对应组件 |
| --- | --- | --- |
| 微观层级 (指令级) | MTE 1/2/3 (专职搬运工) | LSU (Load/Store Unit) |
| 宏观层级 (显存间) | DMA / Copy Engine | Copy Engine / DMA |
| 地址转换 | SMMU (System MMU) | GMMU (GPU MMU) |

### A. 昇腾 MTE

达芬奇架构的设计哲学是“存算分离”。由于 **Cube（矩阵单元）** 算力极强，它对数据的连续性要求近乎苛刻。MTE 的存在就是为了把数据从外部显存（DDR/HBM）搬运到内部的高速缓存（L1/L0 Buffer）中。

- **MTE1 (L1 -> L0A/B):** 针对矩阵运算，将数据切片并搬运到专门的 A/B 矩阵缓冲区。它不仅搬运，还能在搬运过程中完成**格式转换（如降维、Padding、转置）**。
- **MTE2 (HBM -> L1/UB):** 负责将外部显存数据搬运到一级缓存
- **MTE3 (UB -> HBM)**: 将计算好的结果搬回显存。

### B. NVIDIA LSU

在 NVIDIA 的 SM（流处理器）中，数据搬运主要由 **LSU (Load/Store Unit)** 负责。

- **工作模式：** 当 Warp（一组线程）执行加载指令时，LSU 负责计算内存地址并从 L1/Shared Memory 或 L2 中抓取数据。
- **对比 MTE：** 其通用性非常灵活，支持各种不规则的内存访问（如随机存取、合并访问）。
- **耦合度：** LSU 与算术逻辑单元（ALU）在同一个 SM 内紧密耦合。虽然 A100 引入了 **Async Copy（异步拷贝指令）** 允许数据直接从显存绕过寄存器进入共享内存，这在功能上非常接近昇腾的 MTE 异步搬运。

![](https://pica.zhimg.com/v2-8c7428890805e1d80945a2c9135e03c2_r.jpg)

### 总结：Ascend vs NVIDIA 硬件对照表

| 组件功能 | 华为 Ascend (DaVinci) | NVIDIA GPU (Ampere/Hopper) | 备注 |
| --- | --- | --- | --- |
| 顶级计算簇 | AI Core | SM (Streaming Multiprocessor) | 调度的基本单位 |
| 矩阵计算 | Cube Unit (16x16x16) | Tensor Core (4x4 / 8x8) | 昇腾单核矩阵更强，NVIDIA 靠多核堆叠 |
| 通用/向量计算 | Vector Unit | CUDA Core (FP32/INT32) |  |
| 超越函数 | Vector Unit | SFU (Special Function Unit) | 算 exp/log 的地方 |
| 片上高速缓存 | Unified Buffer (UB) | Shared Memory (+ L1 Cache) | 程序员必须手动管理的缓存 |
| 数据搬运 | MTE (Memory Transfer Engine) | Async Copy (A100) / TMA (H100) | 实现计算与通信重叠的关键 |
| 执行模型 | Single Core Instruction | SIMT (Warp = 32 Threads) | 昇腾是显式指令，NVIDIA 是线程束 |
| 原子操作 | Atomic Unit | Atomic Unit in L2/Memory | 用于多核同步/累加 |

## 四、双栈对比法

从 AI infra 视角来看，不管硬件架构如何，在适配不同计算平台的时候，都要掌握核心技能，因此，笔者暂且称之为 **双栈对比学习法**。

### 1. 即时翻译(translate right now)

当学习 NVIDIA 架构时，**立刻**去思考昇腾（Ascend）的对应设计：

- **V100 Tensor Core** $\leftrightarrow$ **Ascend Cube Unit**（都是做矩阵加速，Ascend 是 $16 \times 16 \times 16$ 的分形）。
- **H100 TMA (异步搬运)** $\leftrightarrow$ **Ascend MTE (Memory Transfer Engine)**（专门负责搬运的流水线单元）。
- **NVLink** $\leftrightarrow$ **HCCS**（华为的片间互联协议）。 理解了硬件的演进逻辑（为了更快地算矩阵、更快地搬数据），就理解了所有 AI 芯片的设计初衷。

### 2. 类比思维

例如，当在看 NVIDIA 架构，**不要**把它看作“几千个 CUDA Core”，而要把它看作 **“108 个（A100）具备 MTE 能力、Shared Memory 能力和 Tensor Core 能力的小 AI Core”**。

- 当在 DaVinci 上做的 **Tiling (切块)**，在 NVIDIA 上就是把大矩阵切成适合 Shared Memory 大小的块。
- 当在 DaVinci 上做的 **Double Buffer (MTE 流水线)**，在 NVIDIA 上就是用 `cp.async` 或 TMA 实现 Global -> Shared 的流水线。 本质完全一样，只是 API 变了（Ascend C -> CUDA C/Triton）。
