什么是重计算？LLM训练过程中，会产生许多激活值，由于这些激活值需要在反向过程中参与梯度计算，所以在梯度计算完成之前，整个前向过程中的激活值都需要临时积存着，这会产生比较高的显存占用，特别是序列长度较长时，很可能触发 OOM 等问题。重计算的目的就是在前向时不保存这些激活值，而是在反向计算梯度时按需要重新进行计算，即通过冗余计算（时间）来换取显存降低（空间）。

---

Megatron 中，重计算的基础是继承 `torch.autograd.Function` 的 `CheckpointFunction`类，其可以控制一个 module 的前向与反向过程。代码逻辑如下：

- forward 过程：（1）保存 module 前向的计算逻辑以及前向时的各种随机数生成器（RNG）状态；（2）禁用梯度来执行 module 的前向过程，即不构建计算图，不保存该过程中产生的激活值；（3）保存输入等信息以用于反向过程，返回输出。
- backward 过程：（1）暂存反向时的各种 RNG 状态，用前向的 RNG 状态来重新设置当前 RNG 状态，从而避免随机性带来的不一致；（2）启用梯度以再次执行前向过程，构建一个临时的计算图，得到中间激活值；（3）恢复反向时的各种 RNG 状态；（4）在临时计算图上进行反向传播，得到原始输入的梯度并返回。值得注意的是：重计算之前对 inputs 进行了 detach，目的是将 inputs 脱离原始计算图，避免反向传播时进入到 inputs 上游的图中。

```python3
class CheckpointFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, run_function, distribute_saved_activations, *args):
        # 保存前向计算逻辑
        ctx.run_function = run_function
        ctx.distribute_saved_activations = distribute_saved_activations

        # 获取并保存前向时的 RNG 状态
        ctx.fwd_cpu_rng_state = torch.get_rng_state()
        ctx.fwd_cuda_rng_state = _get_cuda_rng_state()
        ctx.fwd_cuda_rng_state_tracker = get_cuda_rng_tracker().get_states()
        
        # 执行前向；禁用梯度，不保存计算图（即不保存激活值）
        with torch.no_grad():
            outputs = run_function(*args)
        
        # 将 inputs[0] 分块存储到各个 TP Rank 上
        if distribute_saved_activations:
            ctx.input_0_shape = args[0].data.shape
            safely_set_viewless_tensor_data(
                args[0], split_tensor_into_1d_equal_chunks(args[0].data, new_buffer=True)
            )
        
        # 只有输入被保存
        ctx.save_for_backward(*args)
        return outputs
        
    
    @staticmethod
    def backward(ctx, *args):
        inputs = ctx.saved_tensors
        # 在 TP Rank 上执行 AllGather 来获取完整的 inputs[0]
        if ctx.distribute_saved_activations:
            safely_set_viewless_tensor_data(
                inputs[0], gather_split_1d_tensor(inputs[0].data).view(ctx.input_0_shape)
            )
        
        # 获取反向时的 RNG 状态
        bwd_cpu_rng_state = torch.get_rng_state()
        bwd_cuda_rng_state = _get_cuda_rng_state()
        bwd_cuda_rng_state_tracker = get_cuda_rng_tracker().get_states()
        
        # 用前向的 RNG 状态来设置当前 RNG 状态
        torch.set_rng_state(ctx.fwd_cpu_rng_state)
        _set_cuda_rng_state(ctx.fwd_cuda_rng_state)
        get_cuda_rng_tracker().set_states(ctx.fwd_cuda_rng_state_tracker)
        
        # 通过 detach 避免干扰原始计算图
        detached_inputs = detach_variable(inputs)
        # 执行前向；启用梯度，临时构建计算图
        with torch.enable_grad():
            outputs = ctx.run_function(*detached_inputs)
        
        # 重新恢复反向时的 RNG 状态
        torch.set_rng_state(bwd_cpu_rng_state)
        _set_cuda_rng_state(bwd_cuda_rng_state)
        get_cuda_rng_tracker().set_states(bwd_cuda_rng_state_tracker)
        
        if isinstance(outputs, torch.Tensor):
            outputs = (outputs,)
        # 过滤掉非张量的输出
        outputs, args = zip(
            *filter(lambda x: torch.is_tensor(x[0]) and x[0].requires_grad, zip(outputs, args))
        )
        # 反向传播：计算 detached_inputs 的梯度
        torch.autograd.backward(outputs, args)
        grads = tuple(inp.grad if isinstance(inp, torch.Tensor) else inp for inp in detached_inputs)
        return (None, None) + grads
```

在此基础上，模型层面的重计算逻辑十分简单。我们结合重计算相关的配置参数对代码进行解释。

```python3
def _checkpointed_forward(self, hidden_states: Tensor, ...):
    # 返回 forward 函数对象来作为 checkpoint_handler 的参数
    def custom(start: int, end: int):
        def custom_forward(hidden_states, ...):
            for index in range(start, end):
                layer = self._get_layer(index)
                hidden_states, context = layer(hidden_states=hidden_states, ...)
            return hidden_states, context
        return custom_forward
    # 对 CheckpointFunction 的函数封装
    def checkpoint_handler(forward_func):
        return tensor_parallel.checkpoint(
            forward_func,
            self.config.distribute_saved_activations,
            hidden_states, ...)
    if self.config.recompute_method == 'uniform':
        layer_idx = 0
        while layer_idx < self.num_layers_per_pipeline_rank:
            # 一次是对 recompute_num_layers 层进行 checkpoint 处理
            hidden_states, context = checkpoint_handler(
                custom(layer_idx, layer_idx + self.config.recompute_num_layers)
            )
            layer_idx += self.config.recompute_num_layers

    elif self.config.recompute_method == 'block':
        for layer_idx in range(self.num_layers_per_pipeline_rank):
            # 一次是对 1 层进行 checkpoint 处理
            if layer_idx < self.config.recompute_num_layers:
                hidden_states, context = checkpoint_handler(custom(layer_idx, layer_idx + 1))
            else:
                hidden_states, context = custom(layer_idx, layer_idx + 1)(
                    hidden_states, attention_mask, context, context_mask, rotary_pos_emb
                )
    else:
        raise ValueError("Invalid activation recompute method.")
    return hidden_states
```

一、**recompute-method**：取值为 uniform 或 block；**recompute-num-layers**：设值为 N。

（1）当 `recompute-method` 为 uniform 时，表示在每个 PP Stage 上将每 N 层 transformer layer 作为一组，依次对每个组进行 checkpoint 处理（即前向结束时，只保存了最前面的输入以及最后的输出，其他所有的激活值均在反向时重新计算）。举个例子，假如模型的 num_layers 为 8，用两张卡来做 PP，`recompute-num-layers = 2`，那么 rank-0 依次对 layer0-1 和 layer2-3 进行 checkpoint 处理，rank-1 则依次对 layer4-5 和 layer6-7 进行 checkpoint 处理。需要注意的是，N 不能超过 `num_layers_per_pipeline_rank`，否则 `layer = self._get_layer(index)`就会发生越界行为。可以看到，N 取 1 以及 `num_layers_per_pipeline_rank` 是两个极端值。理论上，N 越大前向保存的激活越少，显存降得最多，但是反向时 N 大意味着进行重计算的 DAG 很大，会导致很高的峰值显存。

（2）当 `recompute-method` 为 block 时，表示在每个 PP Stage 上对前 N 层 transformer layer 进行 checkpoint 处理，剩余的层不启用重计算。注意，从代码实现看，block 并不是和 uniform 一样对 N 层 layer 调一次 checkpoint_handler，而是一层一层地进行，即`custom(layer_idx, layer_idx + 1)`。由于每一次 checkpoint 处理都会保存输入输出，因此 block 相比 uniform 保存的激活值也会更多。

二、**recompute-granularity**：取值为 full 或 selective；前者表示重计算是作用于整个 transformer layer 中的激活值；后者表示重计算只作用于 attention 模块，mlp 部分则不考虑。

三、**recompute-activations**：一个容易误人的冗余的参数，添加后 `recompute-granularity` 将被强制设置为 selective，没有其他作用。对应的代码如下：

```text
if args.recompute_activations:
    args.recompute_granularity = 'selective'
del args.recompute_activations
```

四、**distribute-saved-activations**：添加该参数后，从 `CheckpointFunction` 的代码可以看到，forward 中保存 inputs 时会在 TP Rank 上进行拆分，即进一步降低单卡显存占用。同样地，backward 中重新获取 inputs 时就需要在 TP Rank 上执行 AllGather 来获取完整的 inputs。
