今天的问题（issue 场景）：SGLang 的 PD 分离部署里，客户端在长 prompt 传输中途断开，或 prompt 超过 KV pool 被拒；随后另一个用户的请求返回了前一个会话的内容——HTTP 200、token 数对得上、日志无错。v0.4.x 到 v0.5.21 的 PD 默认配置受影响，修复合入 #35049。

一句话回答：free 有两个定义——allocator 标为空闲，和"没有任何远端写者还能碰到它"。两者之间那段窗口就是跨请求污染；已 post 的 RDMA 写撤销不了，唯一安全的反应是等。

四步连锁

A 传输中被 abort（断开、被拒、故障），至少一个写已 post 未落地 → decode 立刻释放 A 的 slot → slot 分给 B → A 的写落进 B 的 KV，B 用别人的 keys/values 正常解码，静默出错，零日志。

为什么撤销不了

work request 一旦 post 进 NIC 队列就不能 revoke；Python 中断不了阻塞中的 batch_transfer_sync；one-sided WRITE 绕过接收端 CPU，decode 收不到逐写事件。换成 pull 式 READ 也一样，abort 后它自己已 post 的 READ 仍会落进刚释放的 slot。

修法：延迟释放

不变量是 T_hold > t_abort传播 + t_剩余chunk + t_在飞调用：abort 时 decode 通知所有 prefill rank 丢掉未发的 chunk；decode 先 hold 住 slot 与元数据，等每个 rank 把已出队 chunk drain 到 0 回 ABORT_ACK；全部 ack 或 30 秒超时才 release（超时是兜底不是证明），释放的页不回插 radix tree，直接隔离丢弃。同一披露里的 admission 一处：被拒请求仍进 decode，8 页有 7 页是旧内容，修法是在 bootstrap 前拒绝（#38935）。

三种常见错误回答

· "释放前加锁就行。" 锁只防同节点，防不了另一台机器 NIC 队列里的已 post 写。

· "abort 时通知对端取消。" 只能停掉尚未启动的 chunk。

· "这是 SGLang 的 bug，与我们无关。" 任何 PD 分离加异步 DMA 的栈都要回答"slot 何时可复用"。

好回答的四层

· 定义层：free 的第二条件。

· 机制层：不可撤销性，push 与 pull 都逃不掉。

· 工程层：deferred release + drain ack + 有界超时 + 隔离不回插。

· 观测层：默认零日志，靠 #41128 指标与 checksum 验证，不能看"没报错"。

加分反问：checksum 为何不能兜底？它只能事后发现，那时已答完；正解是让"可复用"本身带证据。
