## **1）cutlass的算子融合**

cutlass的三步骤：

Prologue（预取/填充)->Mainloop（计算主体）->Epilogue（结果写回与后处理）。

另外CUTLASS 的“执行三部分”≈Prologue（预取） → Mainloop（计算） → Epilogue（写回）这与硬件 pipeline 的 global load → shared load → mma → shared store → global store 一一对应。

等于借助cutlass可以把多个算子融合为一个算子。这就是典型的“算子融合”（operator fusion）——更确切地说，是 GEMM + 逐元素/归约算子的 Kernel Fusion。

## **<br>2）按照融合位置的算子融合**

| 发生位置 | 代表实现 | 融合粒度 | 典型收益 |
| --- | --- | --- | --- |
| 框架前端 | PyTorch JIT / TorchDynamo / ONNX Runtime | 计算图级 | 去掉 Python 调度，< 1 µs kernel launch → 0 |
| AI 编译器 | TVM、XLA、MindSpore Apollo | Loop/IR 级 | 消除中间 tensor，↓30 % 访存 |
| 硬件 SDK | cuDNN, cuBLASLt, CUTLASS, Ascend CANN | Kernel 级 | 寄存器内接力，↓50 % 带宽 |
| 手写 kernel | Flash-Attention、Fused-Adam、Fused-Layernorm | 指令级 | 1 个 kernel 完成整条链，↑2-4× |

## **3)按算子类型分（常见可融合对）**

| 融合模式 | 例子 | 场景 | 额外说明 |
| --- | --- | --- | --- |
| Conv + BN + ReLU | ResNet 基本块 | 推理 | 合并 γ/β/μ/σ 到 conv 权重，1 kernel 完成 |
| MatMul + BiasAdd + GELU | Transformer FFN | 推理/训练 | CUTLASS Epilogue 实现 |
| Multi-Head Attention | Flash-Attention | 训练 | 把 QK^T、Scale、Mask、Softmax、Dropout、AV 融成一个 kernel |
| LayerNorm + Residual + Dropout | BERT | 训练 | 反向传播也融合，省 2 次写回 |
| GEMM + GEMM | 连续 SGEMM | 小矩阵链乘 | 用 cublasLtMatmulDescSetAttribute(CUBLASLT_MATMUL_DESC_EPILOGUE) 融合 |
| Elementwise 链 | Add + Mul + Sigmoid | 通用 | TVM/XLA 自动合并成 1 个 CUDA kernel |
| 稀疏化 + 量化 | SpMM + Dequant + ReLU | 端侧 | 一次 kernel 完成推理 pipeline |

## 4）**GEMM/Conv 之外的逐元素、归约、形状变换、控制流** 等轻量级算子融合

- **前端图级融合（零代码改动）**

| 框架 | 触发方式 | 可融合的典型普通算子链 | 收益 |
| --- | --- | --- | --- |
| PyTorch 2.x | torch.compile()（TorchDynamo + NVFuser） | add → mul → relu → dropout → view | 0 → 1 kernel，< 1 µs |
| TensorFlow 2.x | tf.function(jit_compile=True) + Grappler | cast → expand_dims → broadcast → sub | 省 30 % 访存 |
| ONNX Runtime | OrtGraphOptimizationLevel::ORT_ENABLE_ALL | concat → split → reshape → squeeze | 推理延迟 ↓20 % |

- **编译器 IR/Loop 级融合（自动重写）**

| 编译器 | 融合机制 | 支持算子类型 | 备注 |
| --- | --- | --- | --- |
| TVM / Ansor | schedule + compute_inline | elemwise, reduce, transpose, pad | 可在 CUDA kernel 内 inline 成一条 for-loop |
| XLA (GPU) | fusion pass | 任意 elementwise、reduce、broadcast、concat | HloFusionInstruction 生成单一 thunk |
| MLIR (Linalg) | tile + fuse | linalg.generic, linalg.reduce, linalg.fill | 可多级融合，CPU/GPU 统一 |

- **手写融合 kernel（极致性能）**

| 场景 | 融合内容 | 手写技巧 | 实际效果 |
| --- | --- | --- | --- |
| LayerNorm 融合 | variance + add + rsqrt + mul + add + residual | warp-level reduce + shared memory | 端到端 2× 加速 |
| Softmax 融合 | max → exp → sum → div | warp shuffle + log-sum-exp trick | Transformer 推理 ↓20 % 延迟 |
| Activation + Dropout | gelu → dropout(mask) | fused bitmask RNG in register | 省一次写回，↑15 % 吞吐 |
| Shape 变换链 | reshape → permute → contiguous | 直接计算线性索引，无显式搬数据 | 零开销 |
| 量化反量化 | dequant → add → requant | int8→fp32→int8 inline | 减少 2× 访存带宽 |

普通算子（elementwise、reduce、reshape、quantize 等）早就被“卷”进融合体系：

前端帮你自动融合（PyTorch compile、XLA）；

编译器用 IR 内联（TVM、MLIR）；

手写还能再榨 2-4× 性能（LayerNorm、Softmax、Dropout）。

只要算子链是“逐元素或相邻 reduce”，几乎都能融合成 一条 CUDA kernel。

## 5）计算图融合

计算图融合 ≈ “算子融合的决策阶段”，<br>算子融合 ≈ “计算图融合的最终落地阶段”。

**一个完整的工具链通常先后执行：**

前端图 → 计算图融合 → 生成新节点 → 后端编译 → 算子融合生成 kernel

计算图融合 负责“决定合并哪些节点”；算子融合 负责“实际把它们编译成 1 个能跑的 kernel”。

## 6）计算图融合与算子优化的区别

计算图融合 = “把图里几个节点捏成一个节点”——结构级优化（Graph-level）。

算子优化 = “把一个节点（或一个 kernel）本身跑得快”——实现级优化（Kernel-level）。

**算子优化到底在做什么？**

| 维度 | 优化内容 | 举例 | 效果 |
| --- | --- | --- | --- |
| 算法 | 换复杂度更低的算法 | Winograd Conv 3×3 → GEMM | FLOPs ↓2.25× |
| 数据布局 | 调整 tile/block 形状，使访存连续 | NHWC → NC4HW4，或 CUTLASS 的 Swizzle | 带宽利用率 ↑ |
| 并行度 | 调整 thread-block / warp 数量 | 128-thread → 256-thread 以隐藏延迟 | 吞吐 ↑ |
| 指令级 | 选用更快的指令 | Tensor Core MMA vs SIMT FP32 | 峰值算力 ↑8× |
| 流水线 | 双缓冲、异步 copy | cp.async + pipeline | 延迟隐藏 |
| 内存层次 | 用 shared memory / L2 cache 缓存 | Shared Memory Swizzling | 带宽 ↓50 % |
| 量化精度 | FP32→FP16/BF16/INT8/FP8 | cuBLASLt INT8 GEMM | 带宽 ↓4× |
| 稀疏 | 2:4 稀疏计算 | cuSPARSElt | 有效 FLOPs ↑2× |

## 7）cutlass是不是即做了算子融合又做了算子优化

CUTLASS 同时承担了 **“算子融合”** 与 **“算子优化”** 两种角色，只是发生在不同抽象层：

1. 算子融合（Operator Fusion）<br>• **Epilogue Visitor Tree**：把 GEMM/Conv 后的 Bias、ReLU、量化、Layout-Reformat 等普通算子全部塞进同一条 CUDA kernel，实现 **kernel 级融合**。<br>• **Super-Conv 模式**：MegEngine / TensorRT 用 CUTLASS 把 “Conv → Reformat → Elemwise” 整链融成单个 **Super Conv** 算子，省掉中间 global memory round-trip。
2. 算子优化（Kernel Optimization）<br>• **Tile/线程层次调优**：block→warp→thread→Tensor Core 四级分块，自动搜索最佳 shape。<br>• **内存层次优化**：shared-memory swizzling、double-buffer cp.async、Tensor Core pipeline 排布等。<br>• **数据类型与指令**：FP8/INT8/FP4 低精度路径，稀疏 2:4 计算路径，都是 CUTLASS 模板参数一键切换。

**结论**：<br>CUTLASS **既做融合（把多个算子压成一个 kernel），也做优化（让这个 kernel 跑得更快）**，两者在同一套 C++ 模板体系里完成。
