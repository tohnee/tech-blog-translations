这篇论文是 **LLM 推理系统领域最重要的论文之一**，因为它提出了：

> **PagedAttention + vLLM**

几乎所有现代推理框架（vLLM、LightLLM、LMDeploy 等）都受它影响。

## 一、论文解决了什么问题

## 1 论文要解决什么问题

LLM 在线推理最大的瓶颈之一是：KV cache 内存管理，在 LLM 推理中，每个 token 都会产生：Key、 Value 并存储在 **KV cache** 中用于后续 attention。

问题是：

- KV cache 随 token 数量增长
- 每个请求长度不同
- 请求动态加入 / 结束

这导致：显存碎片 + 显存浪费

论文指出：在一个 **13B 模型 + A100 GPU** 场景中：

- 模型权重约 **26GB**
- KV cache 占 **>30% 显存**

如果 KV cache 管理不好，batch size 会被严重限制

从而导致：GPU利用率下降 和 throughput下降

## 2 为什么这个问题在 LLM 推理中很重要

LLM 服务通常是：多用户并发

例如：用户A 、用户B 、用户C

为了提高 GPU 利用率，系统需要：batching

但 batch 越大，KV cache 占用越大

如果 KV cache 管理效率低，GPU 显存很快被耗尽。GPU 显存很快被耗尽。

因此：

> **LLM serving 的核心问题其实是 KV cache memory management**

## 3 现有方法有什么瓶颈

论文指出传统推理系统的问题：

### 1 静态内存分配

很多系统为每个请求预先分配最大 KV cache

例如：max_length = 2048

但实际很多请求提前结束 ，导致：大量显存浪费

### 2 连续内存要求

传统 KV cache占用连续内存，如果显存碎片化，即使 GPU 还有空间，也无法分配

### 3 KV cache 无法共享

例如：prompt 相同，但系统仍然，重复存储 KV cache，造成额外开销。

## 二、一句话总结论文核心贡献

论文核心贡献可以总结为三点：

1️⃣ **提出 PagedAttention：一种分页式 KV cache 存储机制**

2️⃣ **设计 vLLM 推理系统，实现高效 KV cache 管理**

3️⃣ **显著提高 LLM 推理吞吐量（24×）**

## 三、背景知识（理解论文必须知道）

## 1 Transformer 推理流程

LLM 推理分两个阶段：

### Prefill

处理 prompt：输入全部 token

计算：O(n²)

### Decode

逐 token 生成：token1、 token2、 token3....

每次生成：attention(query, KV cache)

## 2 KV Cache

KV cache 用于保存：Key 、Value，避免重复计算。否则每个 token 都要重新计算所有 attention<br>复杂度：O(n²)

使用 KV cache 后：O(n)

## 3 KV Cache 内存结构

KV cache tensor：[layer, head, token , dim]

随着 token 增长，KV cache 不断变大

例如：context = 4096

KV cache 可能占数 GB

## 四、论文整体方案

论文核心思想：

> **用操作系统的“分页机制”管理 KV cache**

具体思路：

```text
KV cache → 分成 blocks
blocks → 存储在任意显存位置
```

类似操作系统虚拟内存论文称为：PagedAttention

其核心思想：逻辑地址与物理地址分离。

```text
logical blocks
↓
block table
↓
physical blocks
```

逻辑地址与物理地址分离。

## 五、核心技术拆解（重点）

## 技术1：KV Block

论文将 KV cache 划分为：KV blocks

每个 block包含 B 个 token

例如：block size = 16

KV cache 结构：

```text
Block0 → tokens 0-15
Block1 → tokens 16-31
Block2 → tokens 32-47
```

## 技术2：非连续显存存储

传统 KV cache：连续显存

PagedAttention：非连续显存

例如：

```text
Block0 → GPU address 100
Block1 → GPU address 450
Block2 → GPU address 900
```

Attention kernel 会：按 block 读取

论文说明：PagedAttention kernel 会分别加载不同 KV block 并进行 attention 计算

## 技术3：Block Table

PagedAttention 使用：block table

记录：logical block → physical block

例如：

```text
logical block 0 → physical block 9
logical block 1 → physical block 2
logical block 2 → physical block 17
```

类似：操作系统页表

## 技术4：动态 KV cache 分配

传统系统：一次分配全部 KV cache

vLLM：按需分配 block

随着 token 生成逐渐分配 KV block

## 技术5：KV cache 共享

PagedAttention 支持：prefix sharing

例如：

```text
prompt1: Hello world how
prompt2: Hello world what
```

前缀：Hello world 可以共享 KV cache。

## 六、系统架构 / 推理流程

论文提出完整推理系统：vLLM

系统流程：

```text
User request
↓
Scheduler
↓
Batching
↓
GPU workers
↓
KV cache manager
↓
Token generation
```

GPU worker 执行模型前向计算，并通过 block table 访问 KV cache

## 七、性能提升来自哪里

vLLM 提升性能的原因主要有：

### 1 减少显存浪费

PagedAttention：几乎零碎片

### 2 支持更大 batch

显存利用率提高：更多请求并行

### 3 KV cache 共享

相同 prompt：无需重复存储

### 4 动态内存管理

只分配需要的 block：减少浪费

## 八、实验结果怎么看

论文实验显示：

vLLM 相比传统系统：吞吐提升 24倍，并且，随着模型更大、序列更长，提升更明显。

## 九、论文局限

### 1 不解决 attention 计算成本

PagedAttention 只优化：内存管理

不减少：attention FLOPs

### 2 访问模式不规则

分页 KV cache 会导致：非连续 memory access 需要额外 kernel 优化。

### 3 依赖 GPU kernel

需要自定义：attention kernel

## 十、总结

读完这篇论文，个人认为最值得关注的几点是：

### 1 推理系统瓶颈不是计算

而是：memory

### 2 KV cache 是 LLM serving 的核心

几乎所有推理优化都围绕：KV cache

例如：

```text
PagedAttention
KV compression
Prefix cache
```

### 3 推理框架其实像操作系统

PagedAttention 的设计思想完全来自：OS virtual memory

即：

```text
page
page table
memory mapping
```

### 4 vLLM 的成功来自系统设计

vLLM 并没有改变Transformer，它改变的是：推理系统架构
