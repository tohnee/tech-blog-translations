## 概述

Gastown（Gas Town）是一个专为 Claude Code 设计的**多智能体编排系统**和**工作空间管理器**。它通过 git 支持的钩子（hooks）实现持久化工作追踪，使得多个 AI 代理可以协同工作而不会在重启时丢失上下文。

### 为什么需要 Gastown？

在使用 AI 编码助手时，我们经常遇到以下挑战：

| 挑战 | Gastown 解决方案 |
| --- | --- |
| 代理重启后丢失上下文 | 通过 git 支持的 hooks 持久化工作状态 |
| 手动协调多个代理 | 内置邮箱、身份标识和任务交接机制 |
| 4-10 个代理变得混乱 | 轻松扩展到 20-30 个代理 |
| 工作状态存储在代理内存中 | 工作状态存储在 Beads 账本中 |

## 核心架构

Gastown 采用分层架构设计，每个组件都有明确的职责：

### 关键组件

- **The Mayor（市长）** 🎩<br>主要的 AI 协调者，是一个具有完整工作空间上下文的 Claude Code 实例。这是你与系统交互的主要界面。
- **Town（城镇）** 🏘️<br>工作空间目录（如 `~/gt/`），包含所有项目、代理和配置。
- **Rigs（装置）** 🏗️<br>包装 git 仓库的项目容器，为项目提供隔离的工作环境。
- **Crew Members（成员）** 👤<br>Rig 中的个人工作空间，支持多人协作。
- **Polecats（臭鼬）** 🦨<br>短暂的工作代理，它们会生成、完成任务然后消失。
- **Hooks（钩子）** 🪝<br>基于 git worktree 的持久化存储，用于保存代理工作状态。
- **Convoys（车队）** 🚚<br>工作追踪单元，将多个 bead（任务）打包并分配给代理。

## Beads：任务追踪系统

Gastown 依赖 **Beads** 作为其任务追踪后端。Beads 是一个专为 AI 编码代理设计的分布式、git 支持的图式问题追踪器。

### Beads 核心特性

1. **Git 作为数据库**

- 问题以 JSONL 格式存储在 `.beads/` 目录
- 完全版本化，可以分支和合并
- 支持多代理、多分支协作
- **为代理优化**
- JSON 输出格式便于解析
- 依赖关系追踪系统
- 自动检测”就绪”任务（没有阻塞者的任务）
- **零冲突架构**
- 基于哈希的 ID（如 `bd-a1b2`）防止合并冲突
- 多代理和多分支工作流安全
- **语义记忆衰减**
- 通过压缩实现自动汇总
- 节省上下文窗口空间

### Bead ID 格式

Beads 使用前缀 + 5 字符字母数字格式：

- `gt-abc12` - Gastown 任务
- `hq-x7k2m` - 总部任务
- `bd-a1b2` - 通用 Bead

## 安装与配置

### 系统要求

- **Go** 1.23+
- **Git** 2.25+（用于 worktree 支持）
- **beads (bd)** 0.44.0+
- **sqlite3**（通常已预装）
- **tmux** 3.0+（推荐）
- **Claude Code CLI**（默认运行时）
- **Codex CLI**（可选运行时）

### 安装步骤

```text
# 方法 1: 使用 Homebrew（推荐 macOS）
brew tap steveyegge/gastown
brew install gt

# 方法 2: 使用 npm
npm install -g @gastown/gt

# 方法 3: 从源码编译
go install github.com/steveyegge/gastown/cmd/gt@latest

# 如果使用 go install，需要添加到 PATH
export PATH="$PATH:$HOME/go/bin"
```

### 初始化工作空间

```text
# 创建工作空间并初始化 git
gt install ~/gt --git

# 进入工作空间
cd ~/gt

# 添加你的第一个项目
gt rig add myproject https://github.com/you/repo.git

# 创建你的成员工作空间
gt crew add yourname --rig myproject
cd myproject/crew/yourname

# 启动市长会话
gt mayor attach
```

### 快速开始

最简单的方式：

```text
gt install ~/gt --git && \
cd ~/gt && \
gt config agent list && \
gt mayor attach
```

然后直接告诉 Mayor 你想构建什么！

## 工作流模式

### 1. MEOW 模式（推荐）

**Mayor-Enhanced Orchestration Workflow**（市长增强编排工作流）是推荐的工作模式：

```text
1. 告诉 Mayor 你的需求
   ↓
2. Mayor 分析并分解任务
   ↓
3. 创建 Convoy 并生成 beads
   ↓
4. Mayor 生成合适的代理
   ↓
5. 通过 hooks 将 beads 分配给代理
   ↓
6. 通过 convoy 状态追踪进度
   ↓
7. Mayor 汇总结果
```

**示例：**

```text
# 启动 Mayor
gt mayor attach

# 在 Mayor 会话中描述需求
# "我需要为应用添加用户认证系统，包括登录、注册和密码重置功能"

# Mayor 会自动：
# 1. 创建 convoy
# 2. 分解为多个 beads
# 3. 生成工作代理
# 4. 分配任务
# 5. 监控进度
```

### 2. 功能开发工作流

适用于复杂的多任务功能开发：

```text
# 步骤 1: 启动 Mayor
gt mayor attach

# 步骤 2: 在 Mayor 会话中创建 convoy
gt convoy create "认证系统" gt-x7k2m gt-p9n4q --notify

# 步骤 3: 追踪进度
gt convoy list

# 步骤 4: 监控代理
gt agents

# 步骤 5: 查看 convoy 详情
gt convoy show <convoy-id>
```

### 3. 最小模式（无 tmux）

适用于简单任务或者不想使用 tmux 的场景：

```text
# 创建 convoy
gt convoy create "修复 bug" gt-abc12

# 分配给工作代理
gt sling gt-abc12 myproject

# 代理读取邮件并执行工作
claude --resume

# 检查进度
gt convoy list
```

### 4. Beads Formula 工作流

适用于可重复的预定义流程：

```text
# 列出可用的 formula
bd formula list

# 运行 formula 并传递变量
bd cook release --var version=1.2.0

# 创建 formula 实例用于追踪
bd mol pour release --var version=1.2.0
```

## 核心命令参考

### 工作空间管理

```text
# 初始化工作空间
gt install <path>

# 添加项目
gt rig add <name> <repo>

# 列出项目
gt rig list

# 创建成员工作空间
gt crew add <name> --rig <rig>

```

### 代理操作

```text
# 列出活跃代理
gt agents

# 分配工作给代理
gt sling <bead-id> <rig>

# 使用特定代理运行时
gt sling <bead-id> <rig> --agent cursor

# 启动 Mayor 会话
gt mayor attach

# 使用特定代理运行 Mayor
gt mayor start --agent auggie

# 上下文恢复
gt prime
```

**内置代理预设：** `claude`, `gemini`, `codex`, `cursor`, `auggie`, `amp`

### Convoy（工作追踪）

```text
# 创建 convoy 并添加问题
gt convoy create <name> [issues...]

# 列出所有 convoy
gt convoy list

# 显示 convoy 详情
gt convoy show [id]

# 向 convoy 添加问题
gt convoy add <convoy-id> <issue-id>

# 刷新 convoy 状态
gt convoy refresh <convoy-id>
```

```text

# 列出就绪任务

bd dep add <child> <parent>

# 查看任务详情
bd show <id>

# 列出所有任务
bd list

# 更新任务状态
bd status <id> done
```

### 配置管理

```text
# 设置代理配置
```

## 实战案例

### 案例 1：构建 REST API

```text
# 启动 Mayor
gt mayor attach

# 告诉 Mayor
"我需要构建一个用户管理 REST API，包括：
1. 用户注册和登录
2. JWT 认证
3. 用户资料管理
4. 角色权限系统
请使用 Node.js 和 Express"

# Mayor 会自动：
# - 创建 convoy "用户管理 API"
# - 分解为 beads：
#   * gt-auth1: 设置 Express 和基础结构
#   * gt-auth2: 实现 JWT 认证
#   * gt-auth3: 用户注册和登录端点
#   * gt-auth4: 用户资料 CRUD
#   * gt-auth5: 角色权限系统
# - 生成工作代理并分配任务
# - 监控进度并报告
```

### 案例 2：重构遗留代码

```text
gt mayor attach

# 在 Mayor 中
"分析 src/legacy/ 目录中的代码，并提出重构计划。
重点关注：
- 移除重复代码
- 改进错误处理
- 添加类型注解
- 编写单元测试"

# Mayor 会创建 convoy 并协调多个代理：
# - 一个代理分析代码
# - 一个代理进行重构
# - 一个代理编写测试
```

### 案例 3：并行功能开发

```text

# 分配给不同的 rig
```

## 最佳实践

### 1. 始终从 Mayor 开始

Mayor 是设计用来作为主要界面的。不要直接操作代理，让 Mayor 来协调。

```text
# 好的做法
gt mayor attach
# 然后告诉 Mayor 你的需求

# 不推荐的做法
gt sling gt-abc12 myproject  # 手动分配任务
```

### 2. 使用 Convoy 进行协调

Convoy 提供了跨代理的可见性和协调能力：

```text
# 创建 convoy 时提供清晰的描述
gt convoy create "用户认证系统" gt-auth1 gt-auth2 gt-auth3 --notify

# 定期检查 convoy 状态
gt convoy list
```

### 3. 利用 Hooks 实现持久化

工作状态存储在 hooks 中，不会消失：

```text
# 查看 hooks
gt hooks list

# 修复损坏的 hooks
gt hooks repair
```

### 4. 创建可重复任务的 Formulas

对于重复性任务，使用 Beads formulas：

```text
# 创建 formula
bd formula create deploy

# 下次直接运行
bd cook deploy --var env=production
```

### 5. 监控仪表板

定期查看仪表板获得实时可见性：

```text
gt dashboard --port 8080
```

### 6. 让 Mayor 进行编排

Mayor 知道如何管理代理。信任它的判断：

```text
# 不要：
"创建 3 个代理，分别做 X、Y、Z"

# 要：
"我需要实现功能 X，它需要前端、后端和测试"
# Mayor 会自动决定需要多少代理
```

## 故障排除

### 代理失去连接

```text
# 查看 hooks 状态
gt hooks list

# 修复 hooks
gt hooks repair

# 检查代理状态
gt agents
```

### Convoy 卡住

```text
# 刷新 convoy
gt convoy refresh <convoy-id>

# 查看详细信息
gt convoy show <convoy-id>

# 如果需要，手动干预
gt sling <bead-id> <rig>
```

### Mayor 无响应

```text
# 分离 Mayor
gt mayor detach

# 重新连接
gt mayor attach

# 如果问题持续，检查日志
gt logs mayor
```

### Beads 同步问题

```text
# 检查 Beads 状态
bd status

# 手动同步
bd sync

# 重建缓存
bd rebuild
```

### 工作空间损坏

```text
# 验证工作空间
gt verify

# 修复配置
gt repair

# 最后手段：重新初始化
gt install ~/gt --force
```

```text

  - name: Install Gastown

      npm install -g @gastown/gt
```

## 常见问题

### Q: Gastown 和普通的 Claude Code 有什么区别？

A: Gastown 是一个编排层，它：

- 协调多个 Claude Code 实例
- 提供持久化工作状态
- 支持复杂的多任务工作流
- 实现代理间通信

### Q: 我需要 Beads 吗？

A: 是的，Gastown 依赖 Beads 进行任务追踪。Beads 提供了：

- 持久化任务存储
- 依赖关系图
- 版本控制集成

### Q: 可以在现有项目中使用吗？

A: 可以！只需：

```text
cd existing-project
bd init
gt rig add existing .
```

### Q: 支持哪些 AI 模型？

A: Gastown 支持任何提供 CLI 的 AI 编码助手：

- Claude Code（默认）
- Codex
- Cursor
- Gemini
- 以及任何自定义实现

### Q: 如何扩展到更多代理？

A: Gastown 设计可扩展。你可以：

- 创建更多 convoys
- 增加 polecats
- 使用多个 rigs
- 系统可舒适地处理 20-30 个代理

### Q: 数据存储在哪里？

A: 所有数据存储在 git 仓库中：

- Beads 数据在 `.beads/`
- Hooks 作为 git worktrees
- 配置在 `settings/`
