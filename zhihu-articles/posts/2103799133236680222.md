## 问题 1：一个知识齐全的基座模型，为什么你问它问题，它却在"续写"？

因为它学到的是"文本如何接续"，而不是"请求需要被执行"。知识都在，但没人告诉它"有人提问时要回答"——SFT 就是那场入职培训。

先看清 SFT 与预训练的唯一区别（这是本课最容易被忽略的一条）：

| 维度 | 基座模型 | SFT 之后 |
| --- | --- | --- |
| 训练目标 | 预测下一个 token | 完全相同（仍是预测下一个 token） |
| 训练数据 | 万亿级网页 | 数万条指令-回答对 |
| 数据量级 | 15.6T token | 约几十 M token（小 5~6 个数量级） |
| 行为 | 续写文本 | 把输入当任务执行 |

为什么"教行为"比"堆规模"更划算，InstructGPT（Ouyang et al., arXiv:2203.02155）给了量化答案：

| 对照 | 参数量 | 结果 |
| --- | --- | --- |
| InstructGPT | 1.3B | 人类偏好优于 175B 基座 GPT-3 |
| 参数量对比 | 1.3B vs 175B | 约 1/135 |
| SFT 数据量 | 约 13,000 条示范 | 相对预训练语料可忽略 |

量级比更直观：预训练 15.6T token，SFT 约 10M~100M token，15.6T ÷ 约 50M ≈ **3 × 10⁵ 倍**。SFT 通常只跑 1~3 轮、几小时就结束。

**一句话结论：SFT 和预训练用的是同一个目标函数，唯一区别是数据——"答不好"不是知识不够，而是行为没被教过。**

## 问题 2：指令数据只有几万条，那"质量"具体指什么？

SFT 样本直接示范"什么样的回答是好的"，所以样本的风格就是模型的上限。三种来源的质量与成本递减：

| 来源 | 质量 | 规模量级 | 典型代表 |
| --- | --- | --- | --- |
| 人类专业撰写 | 最高 | 约 1 万条级 | InstructGPT（约 13,000 条） |
| 强模型蒸馏 | 高 | 约 5 万条级 | Alpaca（52,000 条） |
| 社区 / 开放集 | 参差 | 几十万条级 | 各类开源指令集 |
| 精挑极少样本 | 极高 | 1,000 条 | LIMA |

最后一行是反直觉的关键：LIMA（Zhou et al., arXiv:2305.11206）仅用 1,000 条精心策展的样本，就得到有竞争力的指令遵循能力——**规模不是决定因素**。

| 对比 | 样本数 | 学到的东西 |
| --- | --- | --- |
| 少量精品 | 1,000 条 | "好答案的标准" |
| 大量杂样本 | 100,000 条 | 各种风格的平均值（含大量低质模式） |

机理是最大似然会去拟合样本分布：样本里有多少比例是"敷衍回答"，模型就有多少概率学会敷衍。质量由五项构成——正确性、格式、风格一致、多样性、以及最隐蔽的**无泄漏**（把评测题混进训练集会虚高分数，即数据污染）。

**一句话结论：指令数据的质量压过数量——筛数据比堆数据更重要，因为模型学的是样本里"敷衍、编造、格式错乱"的占比。**

## 问题 3：为什么算损失时要"假装看不见"问题部分？

因为如果问题部分也计入损失，模型会被训练去"复述问题"而不是"回答问题"。这叫 **loss masking（损失掩码）**：只对回答部分算交叉熵，问题部分标签置 -100（PyTorch 的 ignore_index）。

先算一条短样本的 token 构成：

| 部分 | 典型长度 | 是否计入损失 |
| --- | --- | --- |
| 系统提示 + 用户问题 | 约 80 token | 否（置 -100） |
| 助手回答 | 约 20 token | 是 |
| 合计 | 约 100 token | — |

不掩码会怎样：

| 方案 | 损失覆盖的 token | 梯度去向 |
| --- | --- | --- |
| 不掩码 | 100 个（含 80 个问题 token） | 约 80% 用于"复述问题" |
| 正确掩码 | 20 个（只回答） | 100% 用于"生成回答" |

100 ÷ 20 = **5 倍**：不掩码时模型每学 1 份"如何回答"，就顺带学 4 份"如何复述问题"。

关键区别：**掩码只作用于损失，不作用于注意力**——回答仍然能看到问题（input_ids 没变），只是不被训练去模仿它。这正是我们想要的：条件于问题，但不复述问题。

**一句话结论：SFT 要模型"生成回答"，就只对回答算损失；被浪费的梯度比例 = 问题 token 占比（示例中约 80%，即 5 倍）。**

## 问题 4：多轮对话和多个角色，模型怎么知道谁在说话、话说完了没？

朴素拼接会让模型分不清"哪句是用户说的、哪句是自己该说的、说到哪停"。**Chat template** 用一组特殊 token 显式标出角色与边界。以 Llama 3 为例：序列以 `<|begin_of_text|>` 开头，每一轮用 `<|start_header_id|>`角色名`<|end_header_id|>` 起头，用 `<|eot_id|>`（end of turn）收尾。

一条单轮样本的实际结构：

| 片段 | 作用 |  |  |  |  |
| --- | --- | --- | --- | --- | --- |
| `< | begin_of_text | >` | 序列起点 |  |  |
| `< | start_header_id | >system< | end_header_id | >` + 正文 | 声明系统角色 |
| `< | eot_id | >` | 本轮结束 |  |  |
| user 段 + 正文 + `< | eot_id | >` | 用户输入 |  |  |
| assistant 段 + 正文 + `< | eot_id | >` | 要学的那一段 |  |  |

多轮样本里损失落在哪几段，规则很统一：**所有 assistant 段计入损失，其余全部屏蔽**。

还有一个工程细节——短样本打包：

| 方案 | 利用率 | 风险 |
| --- | --- | --- |
| 一条样本一个序列，不足则填充 | 低（大量 padding 浪费） | 无 |
| 打包：多条短样本拼进同一序列 | 高 | 需保证跨样本不互相注意 |

示例：4 条 1000 token 的样本打包成 4000 token，省约 4 倍序列数。但打包时必须在样本边界加注意力隔离，否则第二条样本会"看到"第一条，制造假的多轮对话。

**一句话结论：Chat template 把"谁在说话、说到哪停"变成可学习的显式信号——没有 `<|eot_id|>`，模型学不到"该我停下来了"，这也是"模型不会停、一直续写"的主因之一。**

## 问题 5：全参微调要多少显存？LoRA 和 QLoRA 省在哪？

全参微调要存完整的权重、梯度和优化器状态。以 7B 为例算显存账：

| 项目 | 每参数字节 | 7B 总计 |
| --- | --- | --- |
| BF16 权重 | 2 | 14 GB |
| BF16 梯度 | 2 | 14 GB |
| Adam 优化器状态 | 12 | 84 GB |
| 合计 | 16 | ≈ 112 GB |

还没算激活值——所以单张 24GB 消费卡完全不可能跑 7B 全参微调（Adam 状态 84GB 是权重 14GB 的 6 倍）。

LoRA（Hu et al., arXiv:2106.09685）冻结原权重，只注入低秩矩阵 ΔW = BA：

| 项目 | 计算 | 结果 |
| --- | --- | --- |
| 注入位置 | q/k/v/o 四个投影 × 2 个矩阵 | 8 个矩阵/层 |
| 单个矩阵参数（A：4096×16） | 4096 × 16 | 65,536 |
| 32 层合计 | 524,288 × 32 | ≈ 16.8M |
| 占 7B 的比例 | 16.8M ÷ 7000M | ≈ 0.24% |

只需为这 0.24% 的参数存梯度与优化器状态，基座只占 14GB（冻结），所以 7B 的 LoRA 微调约 16GB 就够。

QLoRA（Dettmers et al., arXiv:2305.14314, NeurIPS 2023）再把基座压到 4-bit：

| 方案 | 7B 需要显存 | 65B 需要显存 |
| --- | --- | --- |
| 全参微调（BF16） | ≈ 112 GB | > 780 GB |
| LoRA（基座 BF16） | ≈ 16 GB | ≈ 130 GB（仅基座权重） |
| QLoRA（基座 4-bit） | ≈ 6 GB | < 48 GB（含适配器训练态） |

从 780GB 到 48GB 是 16 倍的压缩——这是 QLoRA 让"单卡微调大模型"成为现实的原因。

选型判据很简单：

| 场景 | 建议 |
| --- | --- |
| 基座能装进显存、追求最好效果 | LoRA |
| 基座装不下或显存紧张 | QLoRA |
| 需要改变模型"底子" | 全参微调 |

**一句话结论：三档本质是"训练哪些参数、以什么精度存基座"——基座装得下用 LoRA，装不下用 QLoRA，需要改底子才上全参。**

## 问题 6：微调之后，怎么知道模型没有把原来的本事弄丢？

这就是**灾难性遗忘（Catastrophic Forgetting）**：在新数据上继续训练，会让模型在原有任务上的能力下降。发现它的唯一方法是**微调前后都测同一套基准**：

| 时间点 | 测什么 | 作用 |
| --- | --- | --- |
| 微调前 | 通用能力基准 + 验证集 perplexity | 建立基线 |
| 微调后 | 同样的基准 + 目标任务评测 | 净变化 = 后 − 前 |
| 只看微调后 | 只有目标任务分数 | 无法发现遗忘 |

四条缓解手段可以叠加：

| 手段 | 做法 | 代价 |
| --- | --- | --- |
| 用 LoRA | 只训练 0.24% 参数 | 表达能力受低秩约束 |
| 控制学习率 | 全参 1e-5~2e-5 / LoRA 1e-4~2e-4 | 收敛更慢 |
| 减少轮数 | 1~3 轮 | 可能欠拟合 |
| 混合通用数据 | 掺入通用语料做重放 | 稀释任务信号 |

为什么轮数通常只有 1~3 轮（下表为经验区间示意，拐点随数据量与任务而变）：

| 轮数 | 训练损失 | 通用能力 |
| --- | --- | --- |
| 1~3 | 下降 | 基本保持 |
| 5~10 | 继续下降 | 开始退化 |
| > 10 | 很低 | 明显退化 |

机制是样本量太小：几万条样本重复多轮，模型从"学规律"滑向"记样本"——损失继续降，但泛化在变差。

**一句话结论：只报目标任务的提升、不报通用能力的变化，是最常见的自欺；默认组合是"LoRA + 受控学习率 + 1~3 轮"，共同逻辑都是尽量少动原权重。**

| 问题 | 结论 | 一个数字 |  |  |

| 为什么不听话 | 目标函数相同，只差数据 | 数据量小 3×10⁵ 倍 |  |  |
| 质量指什么 | 质量压过数量 | LIMA 仅 1,000 条 |  |  |

| 显存怎么省 | LoRA 0.24% 参数，QLoRA 4-bit 基座 | 65B 从 780GB 到 <48GB |  |  |
