## **二、当前最值得关注的五个方向**

### **1. Agentic AI：从回答问题到执行任务**

传统大模型主要完成：

输入问题 → 模型推理 → 输出答案。

Agent 则可以实现：

用户目标 → 任务规划 → 工具调用 → 执行 → 验证 → 调整 → 完成任务。

目前核心研究包括：

- 长任务规划与执行
- 多智能体协作
- 工具调用优化
- Agent Memory
- Agent 自我纠错
- Agent 强化学习

2026 年 10 月发表的一篇综述指出，Agentic AI 正在从单轮提示交互，向自主规划、工具使用和长期任务执行转变，但可靠性与安全性仍是关键挑战。 [https://link.springer.com/article/10.1007/s44163-026-02342-5](https://link.springer.com/article/10.1007/s44163-026-02342-5) ?

**2. Test-Time Scaling：推理阶段增加计算**

传统模型主要通过扩大训练规模提高性能。

现在的另一条技术路线是： **让模型在回答困难问题时投入更多推理计算资源。**

例如：

- 简单问题直接回答。
- 中等难度问题进行多步推理。
- 复杂问题生成多个候选解并验证。
- 极难问题使用多智能体并行探索。

2026 年 ACL 的相关研究比较了多种推理阶段扩展策略，发现不同策略存在明显的准确率与计算开销权衡。

### **3. 高效推理：降低大模型运行成本**

这个方向主要面向系统和基础设施工程师。

核心技术包括：

| 技术 | 优化目标 |
| --- | --- |
| PagedAttention | 提升 KV Cache 内存管理效率 |
| Prefix Cache | 减少重复上下文计算 |
| Speculative Decoding | 加速 Token 生成 |
| Continuous Batching | 提高 GPU 利用率 |
| Disaggregated Prefill/Decode | 优化推理资源调度 |
| MoE Expert Parallelism | 提升稀疏模型执行效率 |
| Quantization | 降低模型显存占用 |
| KV Cache Compression | 降低长上下文内存成本 |

这个方向与分布式计算、向量化执行和高性能计算引擎有很强的技术关联。

### **4. 长上下文与 Agent Memory**

当前重要问题不仅是模型能处理多少 Token，还包括：

**如何在长期任务中保留真正重要的信息，同时减少不必要的计算。**

研究方向包括：

- 动态上下文压缩
- 层次化记忆
- 长期记忆检索
- 上下文缓存复用
- Agent 工作记忆管理

例如，ICML 2026 的 Context Folding 研究提出，通过动态折叠中间执行轨迹来压缩上下文，在其测试的长期任务中，活跃上下文最多可减少约 10 倍。 [Scaling Long-Horizon Agent via Context Folding](https://proceedings.mlr.press/v306/sun26x.html) ?

### **5. Agentic RL：强化学习与智能体融合**

这是很值得持续关注的方向。

传统强化学习更多关注模型最终答案是否正确。

Agentic RL 则进一步考虑：

- 工具是否选择正确
- 执行步骤是否合理
- 是否能够根据环境反馈调整
- 是否可以自动恢复执行错误
- 如何对长任务进行奖励分配

2026 年 10 月的研究已经将高效率 Agentic RL 训练框架作为重要方向。

## **三、如果从技术研发和论文方向考虑**

结合分布式计算与高性能执行引擎的技术背景，我认为可以重点关注下面几个交叉方向。

| 研究方向 | 可以研究的具体问题 | 工程价值 | 论文潜力 |
| --- | --- | --- | --- |
| LLM 推理调度优化 | Prefill/Decode 动态资源分配 | 高 | 高 |
| KV Cache 智能管理 | 缓存复用、压缩、卸载 | 高 | 高 |
| Agent 执行引擎 | 并行任务调度、执行优化 | 很高 | 很高 |
| LLM + SQL Optimizer | 利用大模型优化查询计划 | 很高 | 很高 |
| AI 驱动增量计算 | 自动识别可增量化的 SQL | 很高 | 很高 |
| 多模态数据处理引擎 | 大规模向量化与批处理优化 | 很高 | 高 |

其中，我尤其建议关注：

**方向一：LLM 驱动的 Spark SQL 自动优化**

让大模型分析历史执行计划、运行指标和 SQL 特征，辅助优化 Join、Shuffle、数据倾斜及资源配置。

**方向二：面向 Agent 的高性能执行引擎**

借鉴 Spark DAG Scheduler 的思想，将 Agent 任务表示为 DAG，实现并行调度、失败重试、任务复用和计算资源优化。

**方向三：LLM + 增量计算**

利用大模型辅助分析 SQL 依赖关系和增量化可行性，再由确定性的规则与执行引擎完成增量计划生成及正确性验证。

这三个方向都可以结合现有的 Spark、Gluten、Velox 技术体系开展研究。

## **四、未来判断**

未来一到两年，值得重点跟踪的技术主线是：

**大模型能力提升 → Agent 自主执行 → 高效推理基础设施 → 智能化计算系统。**

如果你的目的是 **寻找技术创新方向、团队研发课题或者能够发表 CCF 论文的研究点** ，建议进一步深入三个领域：

1. **大模型推理引擎** ：研究 vLLM、SGLang、KV Cache 和分布式推理优化。
2. **Agent Runtime** ：研究智能体任务调度、内存管理、执行计划优化。
3. **AI + 数据计算引擎** ：研究 LLM 如何帮助 Spark 优化 SQL、增量计算和资源调度。

其中第三个方向最容易与已有分布式计算技术积累形成差异化优势。
