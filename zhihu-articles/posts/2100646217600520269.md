## 0. 一个反直觉的观察

很多团队的第一反应是这样的：训练慢？加卡。推理延迟高？加卡。集群利用率低？再加卡。

但真实世界里，**多买 GPU 往往不解决问题，甚至让问题更隐蔽**。原因很简单——GPU 不是孤立的计算单元，它前面有喂数据的显存，旁边有连兄弟卡用的 NVLink，身后有供给数据的存储，头顶还有决定"放哪、放多久"的调度器。这五个东西串成一条**性能传导链**：系统有效吞吐等于其中最慢一环，任一层掉链子，全链退化。

这就是我这些年做 GPU 集群调度最深的体会：**瓶颈从来不在你盯着的那一层**。本文用这条"短板链"作主线，分别走一遍训练和推理，再在一个特殊场景——RL 后训练——里看它们如何撞到一起。

## 1. 先立地基：五层，和它们的带宽量级差

把链路从硅片往外放大，正好五层：

决定一切的物理事实是**带宽量级差**：

| 层级 | 典型带宽 | 含义 |
| --- | --- | --- |
| 显存 HBM3 (H100) | ~3.35 TB/s | 卡上，最快 |
| NVLink 4.0 (卡间) | ~900 GB/s | 同节点多卡协同 |
| PCIe 5.0 x16 | ~128 GB/s | 跨 CPU/GPU 边界，第一个大坑 |
| 主机 DDR5 / IB 400G | ~50 GB/s | 主机侧与机间同量级 |
| NVMe SSD | ~7 GB/s | 持久化，最慢 |

一句话：**显存比 PCIe 快约 26 倍，比 NVMe 快约 480 倍**。数据每跨一个边界就掉一个数量级。于是所有优化第一性原理只有一句——**就近计算、减少跨界**。这一句，训练和推理都逃不掉。

## 2. 训练视角：瓶颈藏在"通信"和"显存峰值"里

训练是这条链上最"重"的负载。我们顺着五层看它怎么被卡住。

![](https://pic3.zhimg.com/v2-b0bd944f6815964f96dfa410930377ea_r.jpg)

### 2.1 GPU 与显存：算力的敌人是访存墙，不是算力本身

DL 算子（激活、归一化、element-wise）大多 **memory-bound**，因为算力增长远快于带宽。优化第一原则是"提高访存效率"，不是"少算"。而训练的**显存峰值**由四块叠成：权重 + 优化器状态（Adam 下每参数约 12 字节：fp16 权重/梯度 + fp32 主副本/动量/方差）+ 梯度 + 激活。这也是为什么大模型训练第一道坎是"一张卡根本放不下"。

### 2.2 NVLink：切分策略决定了它必须锁域

为放进显存、提吞吐，训练必须切分。四种并行策略各有通信模式：

- **TP（张量并行）**：每层激活/梯度 AllReduce，**每 layer 一次**，量级 ~4·b·s·h·L——通信最重、最延迟敏感，必须同机同 NVLink 域连续卡；
- **PP（流水线并行）**：相邻 stage 点对点，可跨机走 RDMA，但有流水线气泡；
- **DP（数据并行）**：每 step 一次梯度 AllReduce，量级 ~2·Φ（模型大小），最稀疏、最易扩展（再叠 ZeRO/FSDP 分片显存，就是今天主流的"ZeRO 化 DP"）；
- **EP（专家并行，MoE）**：all-to-all 突发，对网络对称性极敏感。

真正决定性能的是**通信模式，不是距离**。TP 一旦跨机，PCIe/网络延迟直接把吞吐压垮一个数量级——这就是调度器要做拓扑感知放置的数学原因。

### 2.3 存储与调度：喂不饱，前面全白搭

训练的数据管线（dataset → host → GPU）若跟不上，GPU 就饿着。更关键的是**调度**：原生 kube-scheduler 把 GPU 当"一块不可分的计数"，既无显存/拓扑维度、也无 Gang。于是多卡训练必须靠 Scheduler Framework 的 Filter（硬约束：显存/代际/NVLink 域）→ Score（binpack/成本/拓扑）→ Reserve+Permit（Gang 整组原子，防"部署一半"死锁）→ Bind（写 GPU UUID）一层层补出来。

> 训练的痛点总结：**显存放不下 → 靠切分；切分 → 靠 NVLink 锁域；锁域 → 靠调度拓扑感知。** 五层环环相扣。

## 3. 推理视角：瓶颈切换到了"显存里的 KV Cache"和"延迟"

同一套五层链，到了推理，主瓶颈**挪了位置**。

### 3.1 显存：KV Cache 才是大头

训练时显存被优化器状态占据；推理时没有优化器，但**自回归生成要把每层的 K/V 缓存下来**。长上下文下 KV Cache 轻易压过模型权重本身，成为推理显存的主导。优化方向也从"省显存"变成"管好 KV"——PagedAttention（分页显存）、RadixAttention（前缀 KV 复用）都是冲着它去的。

### 3.2 NVLink：只在"大模型serving"时上场

小模型单卡就能跑，NVLink 用不上。一旦模型大到必须多卡 TP serving，NVLink 域又成了硬约束——请求要被路由到同一 NVLink 域的卡组上。这和服务部署的"亲和性"直接挂钩。

### 3.3 GPU 与指标：吞吐 vs 延迟

推理要同时看两个量：吞吐（tokens/s，决定成本）和延迟（TTFT 首 token、TPOT 每 token 间隔，决定体验）。这里有个坑：**`nvidia-smi` 的 Util=100% 不代表算力用满**——它只是"有没有 kernel 在跑"的占空比。空转等 KV、等网络照样 100%。要看 SM 活动率、显存带宽利用率才准。

### 3.4 调度与隔离：MIG/MPS 的用武之地

推理的强项是**可共享、要多租户隔离**。MIG 做硬件级显存+故障隔离（跨租户生产首选），MPS 做弹性算力配比（同租户波动场景），Time-Slicing 只给开发测试。在线+离线混部更是把"潮汐"玩到极致：白天给在线、夜间借给训练，早高峰前留驱逐窗口让训练有序 checkpoint 退出。

> 推理的痛点总结：**KV Cache 主导显存、延迟压倒吞吐、共享要求隔离**。同一套五层链，训练在和"显存峰值+通信"搏斗，推理在和"KV+延迟+隔离"搏斗。

## 4. 当训练和推理在同一张卡上相遇：RL 后训练

最有意思的，是有一个场景让训练与推理**必须共存于同一组 GPU**——RL 后训练（以 GRPO 为代表）。它每轮包含两段：

- **Rollout（生成）**：policy 自回归采样，本质是**推理**；
- **Update（训练）**：用采到的数据算梯度更新，本质是**训练**。

于是五层链在这里正面碰撞，两种负载争夺同一时空资源：

| 层 | Rollout（推理侧） | Update（训练侧） | 冲突 |
| --- | --- | --- | --- |
| 显存 | 峰值 = 权重 + KV Cache | 峰值 = 权重 + 优化器 + 梯度 + 激活 | 两峰叠加，Colocated 最大痛点 |
| NVLink | 同域 TP serving | 权重同步（同节点 CUDA IPC / 跨节点 NCCL 广播） | Decoupled 每 step 一次权重广播，70B 可达数秒 |
| 存储 | 生成的 GB 级 trajectories | offload / RadixAttention 前缀复用 | 零拷贝（Ray Object Store / GPU Direct）决定衔接效率 |
| 调度 | 生成集群 | Gang 起训练、拓扑放置、MIG/MPS 共享 | 放错拓扑=全局退化 |

这就引出了 RL Infra 的核心架构抉择，**本质都是五层之间的权衡**：

- **Colocated（同卡）**：权重常驻显存，零参数搬运；代价是显存两峰叠加，要靠 offload / PagedAttention / 动态分配硬扛。
- **Decoupled（分集群）**：生成与训练各管各的，显存隔离干净；代价是训练每 step 拉一次权重（参数搬运 + 空泡）。
- **异步 Disaggregated（如 slime）**：把时序也解耦，用 staleness 容忍换吞吐。

**这恰好印证了总纲：训练和推理不是两套系统，而是同一条短板链上，主瓶颈不同的两种负载；RL 后训练让它们在同一组卡上争夺同一套资源。**

## 5. K8s：把这条链从"芯片"缝到"集群"的那只手

无论训练还是推理，最后都要靠 K8s 落地。它的精髓是**两层解耦**：

- **控制面（调度器）**只决定"资源给谁、放哪"：Filter 硬约束 → Score 软偏好 → Reserve+Permit 做 Gang → Bind 写 GPU UUID。
- **数据面（kubelet / Device Plugin / 驱动）**才做真实隔离：Device Plugin 的 Allocate 注入 `CUDA_VISIBLE_DEVICES`、分配 MIG 实例、挂 Hook。

调度器原生不懂"哪块卡、什么拓扑"，所以 Extended Resources 暴露资源、Device Plugin 做发现与注入、Scheduler Plugin 做细粒度决策——三层补齐，GPU 才从"一块计数"变成可编排的一等公民。

## 6. 给工程师的心智模型

如果只带走三句话：

1. **永远先找短板，别盯着手里的 GPU。** 系统吞吐 = 五层最慢一环。加卡解决不了"数据喂不饱"或"放错拓扑"。
2. **训练与推理共用一条链，主瓶颈不同。** 训练搏"显存峰值 + 通信"，推理搏"KV Cache + 延迟 + 隔离"；RL 后训练让两者同卡相争。
3. **K8s 是缝合层，不是黑盒。** 控制面管"放哪"，数据面管"怎么隔离"，理解了两层解耦，GPU 调度才算真正入门。
