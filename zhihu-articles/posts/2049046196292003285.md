操作系统需要进程调度，最根本的原因在于计算机中的 CPU 资源是有限的，而需要运行的进程通常是远多于 CPU 数量的。通俗地说就是资源是有限的，而需求是无限的。如果没有调度，系统将无法有效分配 CPU 时间，导致混乱和低效。所以进程调度解决的就是如何合理的把有限的资源分配到无限的需求上去，注意是合理分配，不是公平分配，这个世界上是不存在绝对的公平的。

本文我们从下面几点来说明一下为什么我们需要进程调度。

**1. 对每个 CPU 时分复用，营造并发假象**

现在操作系统都是多任务的，为了让用户感觉多个程序（如浏览器、播放器、文档编辑器）在“同时”运行，CPU 必须极快地在不同进程间切换。调度器负责决定每个进程能运行多久（时间片），然后切换下一个。在高速切换下，即使只有一个 CPU，用户也能获得并发运行的体验。关于进程之间是如何切换的，我前面写过一篇 [Linux 内核进程切换机制剖析](https://mp.weixin.qq.com/s?__biz=MzkzMTk4OTIwNg==&mid=2247485231&idx=1&sn=adddad9d87407fbc0979886d90680764&scene=21#wechat_redirect)，感兴趣的童鞋可以看看。

**2. 合理分配 CPU 时间**

如果没有调度，可能会出现一个进程“霸占” CPU 不放的情况，其他进程（包括系统关键服务）将永远得不到运行机会，系统会卡死或响应迟钝。调度算法会尽力保证每个进程都能获得合理的执行时间份额。这里说的合理指的是基于优先级的平等，每个进程不可能都获得同样长的 CPU 时间片，大家都是根据优先级来分配在 CPU 上的执行时间的。

**3. 提高资源利用率和系统吞吐量**

一个进程在运行中经常需要等待某些事件（如等待用户输入、读取磁盘数据、等待网络包到达）。在等待期间，这个进程并不需要 CPU。如果没有调度，CPU 就会空闲下来，造成巨大浪费。调度器可以在这个时候暂停等待中的进程，立刻让另一个就绪的进程运行，从而让 CPU 始终忙碌，提高单位时间内完成的任务数量（即吞吐量）。

**4. 支持优先级，保证实时响应**

不同进程的重要性不同。比如，你移动鼠标、敲击键盘时的响应进程，优先级远高于后台的日志清理程序。调度器支持优先级机制，能优先运行对响应时间要求高的交互式进程或实时任务（如自动驾驶控制程序），保证关键任务得到及时处理，避免出现界面“卡死”或控制失效。

**下面我们来看一个通俗的例子：**

把 CPU 想象成一个可以快速处理任务的工人，而进程是一堆需要完成的任务。工人只有一个，但任务可能有几十个。

无调度：工人可能只做第一个任务，其他任务永远被搁置。或者当第一个任务停下来“等待材料”时，工人也跟着发呆，不理会其他可以做的任务。

有调度：工人有一个“任务清单”和一套规则，他会让每个任务都做一小会儿，然后迅速轮换；当有任务在“等材料”时，他立刻去做别的就绪任务；如果老板（用户）有急事，他会优先处理紧急任务。这样，所有任务看起来都在推进，工人从不闲着，而且重要事情总能快速响应。

写到这儿，我突然想起来小学语文书上的一篇华罗庚的文章，讲的是统筹方法。下面是一段原文，比较适合拿来解释进程调度。

> 统筹方法，是一种安排工作进程的数学方法。它的实用范围极广泛，在企业管理和基本建设中，以及关系复杂的科研项目的组织与管理中，都可以应用。<br><br>怎样应用呢？主要是把工序安排好。<br><br>比如，想泡壶茶喝。当时的情况是：开水没有；水壶要洗，茶壶，茶杯要洗；火已生了，茶叶也有了。怎么办？<br><br>办法甲：洗好水壶，灌上凉水，放在火上；在等待水开的时间里，洗茶壶、洗茶杯、拿茶叶；等水开了，泡茶喝。<br><br>办法乙：先做好一些准备工作，洗水壶，洗茶壶茶杯，拿茶叶；一切就绪，灌水烧水；坐待水开了泡茶喝。<br><br>办法丙：洗净水壶，灌上凉水，放在火上，坐待水开；水开了之后，急急忙忙找茶叶，洗茶壶茶杯，泡茶喝。<br><br>哪一种办法省时间？我们能一眼看出第一种办法好，后两种办法都窝了工。<br><br>华罗庚，统筹方法

这段话描述的是“如何合理安排工序以提高效率”，它恰好是操作系统进程调度核心思想的生动比喻。

**我们将“人”比作 CPU，将“各项任务”比作进程/线程。**

- 人 = CPU（唯一执行资源的抽象）
- 洗水壶、灌水、烧水、洗茶壶、洗茶杯、拿茶叶、泡茶 = 多个就绪的进程或线程
- 等待水开 = 进程进入 I/O 阻塞状态（例如等待磁盘读写、网络数据或用户输入，此时不占用 CPU）

**华罗庚在原文中说的三种办法其实对应三种调度策略。**

![](https://pic4.zhimg.com/v2-423ca630a6d75bbb6658eded647247dd_r.jpg)

**如何用进程调度的术语解释“窝了工”**

- 办法乙中，CPU 在做“洗茶杯”等计算任务时，烧水这个 I/O 操作还没有开始，导致烧水和洗杯子完全串行，总时间等于两者之和。这类似于没有利用I/O重叠，资源利用率低。
- 办法丙中，CPU 在烧水期间什么也不做（空等），这就是典型的 CPU 空闲等待 I/O，严重浪费计算资源。
- 办法甲则实现了 I/O 操作与计算操作的重叠：烧水（I/O）期间，CPU 去执行洗茶杯等计算任务。这正是进程调度的核心价值——当某个进程因为等待 I/O 而阻塞时，立即将 CPU 分配给另一个就绪进程，从而让CPU 始终忙碌，缩短整体完成时间。

这段话直观地说明了**为什么操作系统需要进程调度**：如果不调度（办法丙），CPU 会在等待 I/O 时闲置；如果调度不当（办法乙），无法重叠执行；只有合理的调度（办法甲）才能充分利用等待时间，提高吞吐量和响应速度。

在操作系统中，这个原理被称为**“调度与 I/O 重叠”** 或 **“多道程序设计”**，其根本目的就是“把工序（进程）安排好”，让 CPU 这个“人”永不闲着，像办法甲一样高效地完成所有任务。

**最后我们总结一下：**

进程调度是操作系统的核心职责之一。它的存在是为了在有限的 CPU 资源和众多相互竞争、类型不同（交互/计算/实时）的进程之间，实现高效、合理、响应迅速且有序的并发执行。没有调度，现代计算机的多任务能力、交互体验和资源利用率都将无从谈起。
