## 前言

<br>大模型推理引擎，侧重**在线服务、离线批量、本地单机、GPU 硬件加速**，覆盖从云端集群到个人 PC / 嵌入式场景。vLLM 、 SGLang、TensorRT-LLM、llama.cpp是目前比较通用的大模型推理引擎<br>**vLLM**：PagedAttention 开山之作，通用生产首选；兼容性最强，开箱即用的高并发服务引擎，主打高吞吐在线推理，算力卡厂商都会开源对应的vllm版本

- **SGLang**：RadixAttention索引缓存，对对多轮对话、长对话更加友好；信创场景落后于vLLM发展
- **TensorRT-LLM**：基于PagedAttention实现的推理加速，需要进行源码编译安装，官方提供docker安装部署，只能在特定架构显卡，不如vLLM适用性强，特定的配置需要重新编译，灵活性不足
- **llama.cpp**：cpp原生，支持跨平台本地 /边缘推理，更适用于并发、吞吐不高的私有化部署场景

### <br><br>核心技术对比<br>

| 维度 | vllm | sglang | TensorRT-LLM | llama.cpp |
| --- | --- | --- | --- | --- |
| Kv cache | PagedAttention 固定block通过hash算法进行匹配 | RadixAttention，根据 | Paged KV Cache，编译期预分配 KV 池 | Slot 式 KV 缓存，每个请求独立 slot；仅单实例内有限复用 |
| 并行策略 | TP 张量并行、PP 流水线并行、DP 数据并行、EP专家并行 | TP 张量并行、PP 流水线并行、DP 数据并行、EP专家并行 | TP 张量并行（固定大小）、PP 流水线并行（固定大小）、EP专家并行（固定） | TP 张量并行、EP专家并行 |
| PD分离 | 有（默认不开启） | 成熟（大规模推荐开启） | 无 | 无 |
| 代码底层语言 | C++、Pythonpytorch库 | Rust、 C++、Pythonpytorch库 | c++ | C/C++ |
| 硬件 | NVIDIA、AMD、TPU、Ascend等 | NVIDIA 、 部分AMD、Ascend、XPU | 仅NVIDIA | NVIDIA 、 部分AMD、Intel GPU（不适用信创） |
| 模型覆盖 | 最广 | 广 | 有限 | 较广 |

<br>高并发、独立请求：TensorRT-LLM > SGLang ≈ vLLM >> llama.cpp<br>目前行业内通用任务优选vllm，云厂商长对话选择SGLang的更多。TensorRT-LLM灵活性比较差。

<br>PD分离（Prefill-Decode Disaggregation）<br>PD 分离核心：Prefill（计算密集，优化 TTFT）、Decode（显存带宽密集，优化 TPOT）拆成独立 GPU 池**，可以独立扩缩容，可以使用混合架构，根据需求选型硬件，降低算力成本；需要RDMA支持。**<br>集群配置<br>

| 角色 | vLLM | SGLang | 说明 |
| --- | --- | --- | --- |
| prefill | kv_producer | prefill | Prefill |
| decoder | kv_consumer | decoder | 解码器 |
| router | 无内置router | 内置router | vLLM无需单独router，SGLang需单独Router进行调度 |

### SGLang PD启动参数demo

```bash

# Prefill
python -m sglang.launch_server \
  --model-path meta-llama/Llama-3.1-8B-Instruct \
  --disaggregation-mode prefill \
  --port 30000 \
  --disaggregation-ib-device mlx5_roce0 \
  --tp-size 8 

# Decode
python -m sglang.launch_server \
  --model-path meta-llama/Llama-3.1-8B-Instruct \
  --disaggregation-mode decode \
  --port 30001 \
  --base-gpu-id 1 \
  --disaggregation-ib-device mlx5_roce0 \
  --tp-size 4 \
  --max-running-requests 128
#P:D = 8:4卡
# Router 通过router进行分发
python -m sglang_router.launch_router \
  --pd-disaggregation \
  --prefill http://127.0.0.1:30000 \
  --decode http://127.0.0.1:30001 \
  --host 0.0.0.0 --port 8000

```

## 总结

在生产环境中，选择vLLM 和或SGLang 综合“通用稳定”与“极致性能”的权衡。 vLLM 拥有最成熟的生态和极低的入门门槛，适合绝大多数标准场景；而 SGLang 在长上下文、高并发或复杂 Agent 编排等特定负载下，能通过更激进的调度策略榨取更高的硬件吞吐。 在国产信创环境中SGLang不是特友好，也是技术选型的一个重要指标。
