 DeepSeek 今日官宣，在此前开源一系列大模型、TileLang 编译工具及推理算子库的基础上， **决定进一步将内部推理框架 DeepInfer 全面开源** 。

DeepSeek 官方表示，大模型的能力边界由模型本身划定，但如何以合理成本提供超大规模的模型服务，还取决于一个长期未被公众了解的中间层： **推理框架** 。

训练使模型学有所成，推理则让模型为人所用。面对如今海量的用户调用，推理框架负责统筹调度庞大的算力集群，其效率直接决定了 AI 服务的算力成本与电力消耗。

DeepSeek 希望通过分享内部的部署经验， **帮助开发者与企业组织优化大规模推理的吞吐与延迟** ，从而高效构建私有化及公有云部署，降低算力成本、减少能源消耗，让智能以更低的价格触达更广泛的人群， **实现真正的大模型普惠** 。

基于 DeepInfer，DeepSeek 官方已实现 DeepSeek V4.1 Flash 高吞吐、低延迟的大规模推理服务。未来，DeepSeek 新模型的推理代码及后续优化也将在此持续更新。

- **DeepInfer 推理框架** ：集成高性能算子与深度优化的推理引擎，支持分布式推理、推测解码、SWA Bounded Replay、结构化输出等能力，兼容英伟达与华为昇腾平台。
- **deepseek-recipe 编解码组件** ：同步开源的生产级 Token 编解码组件，与 DeepSeek 官方 API 处理逻辑完整对齐，确保社区获得与官方部署一致的 API 体验。

开源地址如下：

 DeepInfer is the high-performance inference framework that powers DeepSeek's large-scale production services. This open-source release provides offline inference with the core features needed for serving at scale.

Supported models:

- DeepSeek-V4.1-Flash

Supported features:

- Optimized kernels, model and sampler runtime
- Parallelism: Attention DP / balanced CP, MoE EP + EPLB
- DSpark and confidence-scheduled verification
- SWA bounded replay
- Asynchronous scheduling (zero-overhead batch scheduler)
- Batch-invariant inference
- Deterministic sampling
- Structured outputs

Feature details and configuration

- **Optimized kernels:** <u>[FlashMLA](https://github.com/deepseek-ai/FlashMLA)</u> , <u>[DeepGEMM](https://github.com/deepseek-ai/DeepGEMM)</u> , <u>[DeepEP](https://github.com/deepseek-ai/DeepEP)</u> , <u>[TileKernels](https://github.com/deepseek-ai/TileKernels)</u> , <u>[DeepSelect](https://github.com/deepseek-ai/DeepSelect)</u> , and custom <u>[TileLang kernels](https://github.com/deepseek-ai/DeepInfer/blob/main/deepinfer/model_executor/layers/tilelang_ops)</u> .
- **DSpark and confidence-scheduled verification:** accelerate decoding with draft tokens and use confidence estimates to schedule verification. Set `DEEPINFER_ENABLE_MTP_VARLEN=1` ; `DEEPINFER_USE_NEXTN_DECODE` controls the maximum draft length (default: 5).
- **Decoder SWA bounded replay:** reduce decoder prefill work by replaying only a bounded suffix. Set `DEEPINFER_YOCO_PREFILL_TRUNCATION_MODE=compact` and `DEEPINFER_YOCO_PREFILL_KEEP_TOKENS=140` for the default V4.1 settings; the retained suffix must cover the SWA window plus the maximum backtracking length.
- **Asynchronous scheduling:** overlap CPU batch scheduling with device execution. Enabled by default.
- **Batch-invariant inference:** keep model results identical across different batch compositions. Enable with `DEEPINFER_BATCH_INVARIANT=1` (NVIDIA only).
- **Deterministic sampling:** produce identical outputs for identical input tokens and sampling parameters. Set `DEEPINFER_BATCH_INVARIANT=1 DEEPINFER_ENABLE_MTP_VARLEN=0` and pass a fixed `seq_seed` to `SamplingParams` (NVIDIA only).
- **Structured outputs:** constrain generation to a regex, JSON schema, or EBNF grammar. Pass `so_args={"schema_type": ..., "schema": ...}` to `SamplingParams` ; see <u>[examples](https://github.com/deepseek-ai/DeepInfer/blob/main/examples/_structured_output.py)</u> .

Supported hardware:

- NVIDIA SM100 GPUs
- Huawei Ascend 950 NPUs

Required for a complete inference service (not included in this release):

- A KV cache system
- VE/Prefill/Decode disaggregation (most required engine functionality is already implemented)
- Load balancing across data-parallel replicas for both prefill and decode 
 
 deepseek-recipe 包含一套 Rust 库以及对应的 Python bindings：支持将不同格式的 API 请求统一转换为 Conversation 格式，将对话渲染为适用于 DeepSeek 模型的 prompt，通过附加的 tokenizer 将对话编码为 token IDs，并支持将模型输出转换为对应格式的响应。 可用于把推理后端接入兼容多种格式的 API 服务；调用方必须提供模型推理、工具执行和 HTTP 传输。 
 
 支持范围 

- **请求/响应格式：** Messages、Chat Completions 与 Responses 的请求转换、 <u>[流式响应](https://github.com/deepseek-ai/deepseek-recipe/blob/main/docs/streaming.zh.md)</u> 和完整响应，支持文本、图片、思考模式、客户端工具调用和 Chat Completions 的 `prefix` 续写。
- **Prompt：** 支持将 DeepSeek V4 与 V4.1 的对话渲染为 prompt，并通过附加的 tokenizer 将对话编码为 token IDs。
- **生成参数：** 思考模式、reasoning effort、 `temperature` 、 `top_p` 和输出 token 上限。调用方编码 prompt 之后， `ConversationRequest::resolve_max_tokens` 按上下文长度检查 prompt 与 `max_tokens` ，并给未指定的 `max_tokens` 取默认值：非思考模式 8192，思考模式 65536，思考模式且 `max` effort 时 131072。
- **输出解析：** reasoning 内容、工具调用、JSON object 输出和 stop sequence。流式处理器附加 tokenizer 后，usage 会给出 `reasoning_tokens` ：processor 用该 tokenizer 编码 reasoning 内容来计数。
- **结构化输出：** Chat Completions 的 `response_format` （ `json_schema` 与 `regex` 类型）和 Responses 的 `text.format` （ `json_schema` 类型）。转换会校验 JSON Schema，渲染时把它写入 prompt；正则表达式以 `ResponseFormat::Regex` 透传。转换还会选出 `InferenceOptions` 的 `OutputConstraint` ：带工具且 tool choice 不为 `none` 的请求是工具调用块，否则是 response format 对应的 JSON、JSON Schema 或正则。是否由后端以约束解码执行，由调用方决定。
- **图片：** 支持以 base64 或外部 URL 传入，由图片组件基于 OpenCV 完成 DeepSeek V4.1 的预处理。DeepSeek V4 不接受图片，转换把 V4 请求中的每张图片替换为文本 `[Unsupported Image]` 。图片组件的 `ReqwestImageFetcher` 默认不限制连接的地址，因此如果服务会拉取不受信任请求中的 URL，应为它安装 `DestinationFilter` 。
- **工具定义：** 函数工具；Responses 还支持工具命名空间和 `apply_patch` 自定义工具。V4.1 支持 Messages 的工具延迟加载和 Responses 的客户端工具搜索。
- **Log probability：** Chat Completions 的 `logprobs` 、 `top_logprobs` 以及 Responses 的 `top_logprobs` 会转换到 `InferenceOptions` 。调用方在 `InferenceChunk::Tokens` 中提供后端的值；附加 tokenizer 后，Chat Completions 与 Responses 的 adapter 会输出这些值。本库不计算概率。
