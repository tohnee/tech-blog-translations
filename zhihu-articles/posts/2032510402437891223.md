## 引言

之前实习时mentor曾给我布置过Nvidia GPU架构的演进调研的任务，那时还是个刚入门的小白，只能浅显的搜集些资料，毫无重点，自己体会的也不会深刻。但是现在才意识到，GPU 架构对算子开发的影响远不止更高的算力和更大的内存，它还带来了全新的开发范式——比如 TMA、FP8 数据格式，以及更大的RF和SMEM大小。这些硬件特性的变化，往往也会影响算子的最优形状和数据排布。

FlashAttention V3 和 V4分别是针对Hopper和Blackwell架构的优化方法，因为其利用的是架构升级所带来的新特性，所以以往的旧架构并不适用。但是其优化思路和 V2 相比变化不大。下面会结合GPU架构讲一下 V3 和 V4 分别优化了哪些地方。

## **NVDIA's Hopper architecture**

Hopper 于 2022 年第三季度发售，在 Ampere 的基础上进一步改进，直到今天依然广泛用于 LLM 等计算任务。Hopper 架构规格如下：

- 80GB 高带宽显存（HBM），带宽可达 3.35 TB/s
- 132 个 SM
- 50MB 所有 SM 共享的 L2 Cache
- 每个 SM 内，具有：
- **每个SM内新增TMA(Tensor Memory Accelerator)**
- **支持 FP8 数据格式**
- 不向前兼容（使用到 Hopper 架构特性的代码，不保证能在下一代架构 Blackwell 上运行）

![](https://picx.zhimg.com/v2-92b847a8abc47d95223fae1ecf673397_r.jpg)

**Thread Block Clusters（线程块集群）**

它允许一组 CTA 作为一个整体被调度，并允许它们直接交换 Shared Memory 中的数据（Distributed Shared Memory），从而减少了频繁启动新 CTA 或结束 Kernel 的需求。（但是FA3并未用到该特性）

![](https://pic2.zhimg.com/v2-2f8da0776bab941322e220557011f5a9_r.jpg)

**TMA 数据访问**

通过 TMA 计算访存地址，无需消耗 Thread 和 Register 资源；

TMA作为生产者访存加载数据，Thread 作为消费者进行计算，二者是异步的，可以互相掩盖。

![](https://pic1.zhimg.com/v2-86d52213d585e2ffe96eee10ed0f5eda_r.jpg)

**WGMMA (Warpgroup MMA)**

Warpgroup 指的是 4 个连续的 warps，共 128 个连续的 threads，正好对应了一个 SM 最多可并行计算的线程数。在 H100 上，我们可以以 Warpgroup 为粒度调度 GEMM 运算。下面说明了 A100 和 H100 调度 GEMM 的 API 的区别：

- A100上，`wmma.mma.sync` (warp-level) 和 `mma.sync`(thread-level) 均为调用 Tensor Core 计算的同步 API，也就是必须等到结果计算出来，线程才能继续执行下一个指令；
- H100上，新增的 `wgmma.mma_async`(warpgroup-level) 可以异步运行 Tensor Core，也就是可以与其他单元并行计算（例如 CUDA Core）。WGMMA operand A 可以从 RMEM/SMEM 读取，operand B 只能从 SMEM 读取，更多关于 WGMMA 指令的数据类型、shape 要求和数据排布等细节，可参考 [PTX 相关文档](https://docs.nvidia.com/cuda/parallel-thread-execution/#asynchronous-warpgroup-level-matrix-instructions)。

> 在 FA3 论文的算法中将 GEMM 分为两类，其中 RS-GEMM 表示 operand A 在 RMEM 上，SS-GEMM 表示 operand A, B 均在 SMEM 上。

### Pre-Ampere optimization：**Warp Specialization**

通过在**不同warp间**切换来掩盖通信延迟

- 指定部分warp 做数据传输(producer)
- 其他 warp 做计算(consumer)
- 通过 barrier 同步数据依赖
- warp上下文保存在register file，切换开销极小(~1周期)

### Ampere optimization：**Multistage (cp.async)**

在**同一warp 内**，通过流水线（多stage）实现通信与计算的overlap

- 使用cp.async 将数据从全局内存异步拷贝到 shared memory
- 同一warp 先计算当前块，再等待下一块数据（stage 流水)
- 通常使用**至少2个stage(double buffer)**，更多 stage 需要更多buffer

### Hopper optimization

Warp Specialization（跨warpgroup）+Intra-warpgroup overlapping（组内）

- TMA硬件异步传输，只需1个线程发起
- WGMMA提供 warpgroup级异步计算能力
- 给producer分配最少资源，consumer分配更多资源，最大化有效算力
- 在consumer warpgroup内部，GEMM与Softmax等计算可重叠

![](https://pic4.zhimg.com/v2-fbccdf29cf903d5630236b77fb1eaf09_r.jpg)

## Flash-Attention-V3

### Asynchrony: Overlapping GEMM and Softmax

对于 Hopper 而言，由于 WGMMA 指令的异步性，我们可以同时进行 Tensor Core 和 CUDA Core/SFU 的计算，通过合理地安排 Warpgroup 的调度策略，就可以使 Softmax 的运算时间被 GEMM overlap。<br><br>**Inter-warpgroup overlapping with pingpong scheduling**<br>Ping-pong scheduling **主要发生在两个 consumer warpgroup 之间**。由于 WGMMA 的异步性，我们可以同时运行 softmax 和 GEMM 计算，按照下图的调度并用`bar.sync`在虚线处同步，可以**让两个 warpgroup 轮流交替进行 GEMM 计算**，以实现更高的 Tensor Core 算力利用率。

![](https://pic2.zhimg.com/v2-ddc48f4ee2ac151f4b88b904b333cc55_r.jpg)

**Intra-warpgroup overlapping of GEMM and Softmax**<br>FlashAttention 的计算不是单一 GEMM，而是：<br>QK^T → Softmax → PV<br>但是Softmax 依赖 QK^T 的输出，如果串行执行，会有 pipeline stall

在同一个 warpgroup 内：

```text
时间 →
Tile k:     GEMM(QK)
Tile k-1:         Softmax
Tile k-2:              GEMM(PV)
```

在同一个 warpgroup 内部，可以按照下图编排流水线的方式，实现 GEMM 和 softmax 的计算重叠。下图展示的是 2-stage 流水线方案。

### Low-precision: reduce quantization error with incoherent processing

FP8 在 attention 中的主要问题是 activation 存在 outliers，导致量化 scale 被极端值主导，从而产生较大误差。

FlashAttention v3 采用了 incoherent processing，在量化前对 Q 和 K 施加一个随机正交变换，将 outliers 的能量分散到各个维度，从而使数据分布更加均匀。

```text
Q' = Q · R
K' = K · R
其中R是随机正交矩阵 → R R^T = I
(QR)(KR)^T = Q R R^T K^T = Q K^T
```

这样数学上矩阵的结果不变，但可以减少量化前 A, B 矩阵的 outliers，进而减少量化损失。

> 实际上，论文中的 M 是通过一个随机的只包含 {-1, 1} 的对角矩阵乘上一个 Hadamard 矩阵来生成一个随机的正交矩阵的，这个生成的计算复杂度可以从 O(d^2) 降低至 O(d log d)，而且可以和 rotary embedding fuse

load Q → rotary → hadamard → store可以在一次memory pass 完成，几乎没有额外开销

![](https://pic3.zhimg.com/v2-84383938c6e0a03749d95e298152ee80_r.jpg)

## **NVIDIA's Blackwell architecture**

Blackwell 是 NVIDIA 最新的架构，也是目前 LLM 部署的最佳架构。它在 Hopper 和 Ampere 的基础上进行了改进，提高了计算能力，并提供了一些关键特性以实现更快的执行速度：

- 7.672 TB/s 高带宽显存
- 148 个 SM
- 192MB 所有 SM 共享的 L2 Cache
- 每个 SM 内，具有：
- 第五代 Tensor Core 架构
- **256KB** **Tensor Memory**
- **支持NVFP4数据结构**

![](https://pica.zhimg.com/v2-e6f8865508659791b07dfe2ba44a68b8_r.jpg)

**Tensor memory (TMEM)**: 在 B200 上，每个（共 148 个）SM 都配备了 256KB 的 TMEM。这是一种片上 scratchpad（临时存储），直接连接到 tensor cores，用于 warp 同步的中间结果存储。

**Fully asynchronous 5th gen tensor cores**: `tcgen05.mma` 是异步执行的，并且将累加结果存储在 TMEM 中。对于 BF16 和 FP16，单个 CTA 的最大 UMMA tile 是 128×256×16，大约是 Hopper 架构中最大 WGMMA 单元的 2 倍。

**UMMA 由单个线程发起**，降低了寄存器压力，使得更大的 tile 和更深的流水线成为可能，同时避免了 Hopper 的 warpgroup MMA 中常见的寄存器溢出问题。这也让 warp specialization更可行：一些 warp 负责搬运数据块，而另一些 warp 发起 MMA，从而实现矩阵乘加、softmax 和内存访问之间的重叠执行。`tcgen05.mma` 还可以直接从 TMEM 中读取操作数 A。

**2-CTA MMA**: Blackwell 可以在同一个 cluster 内，让一对 CTA 共同执行一个 UMMA，使用两个 CTA 的 TMEM。由主 CTA（leader CTA）中的一个线程发起 MMA，但在执行过程中，两个 CTA 都必须保持活跃。通过在两个 CTA 之间拆分 M 和 N 维度，tile 尺寸可以扩展到 256×256×16，从而减少冗余数据传输，并降低每个 CTA 的资源占用。在一个 kernel 中，CTA 组大小（1 或 2）必须在 TMEM 和 tensor core 操作中保持一致。

![](https://pic1.zhimg.com/v2-27d4d54ca7ed8763457ada78e8ab4702_r.jpg)

## Flash-Attention-V4

Blackwell架构反映了一个关键趋势：**张量核心吞吐量的增长速度远超其他功能单元**。Blackwell的FP16/BF16张量核心吞吐量相比Hopper翻倍（每GPU 2.25 PFLOPS对比1 PFLOPS），但共享内存带宽和指数运算单元吞吐量保持不变或增长较慢。这种不平衡使性能瓶颈从矩阵乘法转移到了：

(a) Forward 阶段 SFU 与 Softmax 指数运算的瓶颈

(b) BWD 阶段：共享内存访存压力（带宽）

后面的FA4优化也是针对以上bottleneck的

![](https://pic2.zhimg.com/v2-e9013a8fc3bcf1606c36d178a0ef8c83_r.jpg)

### Forward pass

**The FWD pass in short：**

- **乒乓调度，每个 CTA 使用 2× Q 和 2× O 图块**：最大化 MMA 和 softmax 之间的重叠
- **2×softmax warpgroups**：每个 tile 执行 softmax 操作，并在计算指数函数时进行同步以避免重叠。
- **软件模拟** 2x：将指数计算分布到硬件的MUFU和FMA上模拟的软件中
- **分阶段将 P 存储在 TMEM 中**：缓解寄存器压力
- **修正线程组**：指定“修正”线程组，用于执行重新缩放操作，以将其从关键路径中移除。
- **在线 softmax（条件）缩放**：降低缩放频率以减少非矩阵乘法操作

![](https://pic2.zhimg.com/v2-2b2d5db207db639b76da82eb9add335d_r.jpg)

### Pipeline: Ping-pong Q tiles plus a dedicated correction stage

为了充分压榨 Blackwell 硬件性能，FA4 重新设计了计算流水线：

- Ping-pong 调度： 每个 CTA（协作线程阵列）同时处理两个 Query 块（$Q^H$ 和 $Q^L$），并以乒乓方式交替调度。
- MUFU 竞争消除： 显式同步两个负责 Softmax 的 Warpgroup，确保它们不同时执行指数运算，从而减少对硬件 MUFU 单元的争抢。
- 分阶段存储： Softmax 结果 $P$ 会分阶段存回 Tensor Memory，而不是一次性全部保存在寄存器中，这有效缓解了寄存器压力。
- 提前触发后续计算： 在 $P$ 块存储完成约 3⁄4 时，就提前触发后续的 $PV$ 矩阵乘法，以重叠计算与访存开销。

### 条件性softmax重缩放优化

FlashAttention的在线softmax算法**在处理分块时维护运行统计信息以保证数值稳定性**。当计算第j个分块时，算法跟踪**运行最大值和指数和**。重缩放步骤需要向量乘法，但研究团队发现两个关键观察：

- **重缩放仅在发现新的更大值时才必要**；
- 可以容忍一定的重缩放松弛，仅当最大值变化超过阈值时才进行重缩放。

$$ O_j = \begin{cases}\exp(m_{j-1}-m_j)\,O_{j-1} + \exp(S_j-m_j)\,V_j, & \text{if } m_j - m_{j-1} > \tau,\\O_{j-1} + \exp(S_j-m_{j-1})\,V_j, & \text{otherwise.}\end{cases} $$ FlashAttention-4修改了算法，**当最大值变化不超过阈值时跳过更新**，继续使用之前的最大值。这保持了正确性，因为在计算结束时，所有累积值都会被真正的最终最大值和最终归一化因子重新归一化。

$$ O_{\text{final}} = \frac{O}{l_{\text{final}}} $$ 这一修改显著减少了重缩放操作次数，同时保持数值精度。实践中，为避免warp分歧，当warp中任何线程需要重缩放时都执行重缩放。

### Faster exponential: Distribute 2^x across MUFU.EX2 and FMA

Softmax 涉及大量的指数运算，而硬件 MUFU.EX2 指令的吞吐量远低于 Tensor Core。

FA4 通过以下方式提升了有效的指数运算吞吐：

- 分流计算： 将指数运算分布在硬件 MUFU.EX2 路径和软件仿真的 FMA（融合乘加）单元上并行执行，利用了原本在此时会被闲置的 FMA 算力。
- 软件仿真流程：范围缩减 (Cody-Waite)： 将 $2^x$ 分解为整数部分 $n$ 和小数部分 $f$。

$$ 2^x = 2^{n} \cdot 2^{f} $$

- 多项式逼近 (Horner’s Method)： 使用三阶多项式逼近计算 $2^f$，系数经过专门优化以最小化误差。

$$ 2^{x_{\text{frac}}} \approx p_0 + p_1 x_{\text{frac}} + p_2 x_{\text{frac}}^{2} + p_3 x_{\text{frac}}^{3} $$

位移与合并： 利用 IEEE 754 浮点数格式，将整数 $n$ 移入阶码字段（Exponent field），直接与 $2^f$ 的尾数位（Mantissa bits）合并，完成最终计算。
