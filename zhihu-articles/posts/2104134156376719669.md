## TL;DR

自回归大模型推理只能逐 token 串行解码，每一步都要把整个模型的权重读一遍，GPU 大量时间在等显存。投机解码（用小模型先猜几个 token，再让大模型并行验证）是最主流的加速手段。但它的草稿模型**本身也是自回归的**：EAGLE-3 每猜一个 token 就要跑一次前向，草稿层还必须做得极浅（单层 Transformer）才不至于把延迟吃回去。草稿质量上不去，平均接受长度 τ 卡在 3 附近，加速比三年了都停在 2–3×。

DFlash 把草稿阶段换成了**块级扩散**：一次前向并行生成整个 16-token 的块，并把目标模型中间层的隐藏状态**注入到草稿模型每一层的 KV cache** 里作为条件。核心洞察可以概括成一句话——**the target knows best**：自回归大模型的隐藏特征本身已经隐含了未来若干 token 的信息。草稿模型不需要从零推理，只需要做一个「目标特征 → 未来 token」的适配器。

结果：Qwen3-8B 上 GSM8K 5.15×、MATH-500 6.08×、AIME25 5.62×，平均 4.86×（greedy），是同设定下 EAGLE-3 的 2.4 倍（换到 LLaMA-3.1 的同条件对照则是 1.2–1.4 倍，见 5.2）；thinking 模式仍有 4.2–4.6×；SGLang 上单路吞吐 7–15×，32 并发保留 2.3–3.1×。额外开销只有约 42 MB 投影参数，**目标模型完全冻结**。

## 1. 引言

### 1.1 投机解码为什么卡在 2–3 倍

解码的瓶颈在内存带宽，不在算力。自回归生成每个 token 都要做一次完整前向：把所有层、所有矩阵的权重从 HBM 读进计算单元，可真正参与「算术」的只有最后一步的 logits。batch=1 的交互式场景里，GPU 算力利用率往往不到 5%。

投机解码把「猜」和「验」分开：小模型猜 γ 个 token，大模型一次前向并行验证。验证时 γ 个位置的注意力可以并行算，读一遍权重的成本就摊到了 γ 个 token 上。理论收益上限是

$$ T_{\mathrm{total}} = \frac{T_{\mathrm{draft}} + T_{\mathrm{verify}}}{\tau}, \qquad \eta = \frac{L_{\mathrm{target}}}{L} $$

其中 T_draft 是起草耗时，T_verify 是验证耗时，τ 是每轮被接受的 token 数。提速只有两条路：**把 τ 做大**，或者**把 T_draft 压小**。

### 1.2 现有路线：树状草稿把「猜」做到了极限

EAGLE 系列用一棵**草稿树**代替单链：一次前向同时给出多条候选路径，验证时用树形注意力掩码一次并行验证。EAGLE-3 又把 tree size 加到 60，接受长度确实上去了，验证成本也跟着涨。更关键的是结构上的两难——

$$ T_{\mathrm{draft}} = \gamma \cdot t_{\mathrm{step}} $$

γ 是草稿长度。**想猜更多 token，就要更多次前向**；想控制延迟，只能把草稿模型做薄。EAGLE-3 最终就是单层，这决定了它再怎么改训练目标、再怎么调树宽，τ 都只能在 3 附近饱和，加速比上限就在 2–3×。

用扩散做草稿，之前也没走通。DiffuSpec、SpecDiff-2 用 7B 级的扩散草稿模型，质量上去了，但起草延迟把收益全吃掉，只剩 3–4×；PARD 让小的自回归模型模仿扩散式并行生成，模型容量不够，上限约 3×。

于是问题就变成了：**能不能有一个既轻量、又准确的扩散草稿器？**

### 1.3 本文的切口：草稿只需要做「适配」

草稿模型不必从零推理，它可以直接借用目标模型已有的特征。目标模型在 prefill 阶段产生的隐藏状态，**已经包含了关于未来 token 的信息**；解码器在每一层都要对「下一个 token 是什么」做出隐含预测，这些信息可以被草稿模型直接拿来用。

从这个角度看，草稿模型不需要是一个「会生成的小模型」，而是一个**把目标模型的特征翻译成未来 token 的适配器**。适配器可以很小、可以并行、也可以很深——只要目标特征在每一层都拿得到。

DFlash 的整个设计就是围绕这句话展开的。

## 2. 问题：并行草稿为什么之前不 work

先看一组干脆的对照实验：训练一个 5 层块扩散草稿模型，**完全不给任何目标模型上下文**，在数学基准上测。

| 温度 | GSM8K | Math500 | AIME24 | AIME25 |
| --- | --- | --- | --- | --- |
| 0 | 2.83× / τ=3.38 | 3.73× / τ=4.61 | 3.43× / τ=4.12 | 3.35× / τ=4.07 |
| 1 | 2.76× / τ=3.29 | 3.31× / τ=4.12 | 2.66× / τ=3.23 | 2.65× / τ=3.24 |

并行确实把 T_draft 压下来了，这正是块扩散的好处。但接受长度只有 3–4.6，加速停在 2–3.7×，**和 EAGLE-3 处在同一档，没有任何优势**。

**根因是没有上下文指导。** 草稿模型看不到目标模型的内部表征，只能从 token 层面从零猜未来。token 层面的信息量远不够：给定 prompt，下一个 token 的分布很宽；但如果知道「大模型此刻在想什么」，分布会窄得多。

方向由此锁死：草稿模型可以小，但必须拿到目标模型的深层特征。而且这份特征**要在整个草稿模型里持续有效**，不能随着层数加深被稀释掉。

## 3. 核心方法

DFlash 的设计拆成两块：**特征从哪来、怎么喂进去**（决定质量），和**怎么并行生成**（决定速度）。

![](https://pic4.zhimg.com/v2-46c03ab9451477e0709cdf5637f236eb_r.jpg)
*图 1 · DFlash 的推理结构。左侧：目标模型在 prefill 阶段取 5 层隐藏状态，经共享投影 W_c 融合成上下文特征；右侧：该特征注入草稿每一层的 KV cache，草稿阶段一次并行输出整块 mask token，再由目标模型验证并产出下一个轻推 token*

### 3.1 先补课：块扩散（Block Diffusion）是什么

DFlash 的草稿模型不是自回归模型，也不是纯粹的扩散模型，而是**块扩散**。这个中间形态决定了它为什么能一次前向出一整块，又不会像纯扩散那样没法接投机解码。先把这个前提说清楚，后面的 KV 注入和训练改动才有落点。

**自回归模型**把整段文本拆成一串条件概率：p(x₁:L) = prod_ell p(x_ell mid x_&lt;ell)。每个位置只见左边，生成必须一个一个来。**离散扩散模型**反过来：它在整段上定义一组「加噪（把 token 换成 [MASK]）→ 去噪」的过程，一次前向可以同时预测所有被 mask 的位置，但它们互相可见，没有因果结构。

**块扩散**（Block Discrete Denoising Diffusion，BD3-LM，ICLR 2025）把两者缝起来：**块之间是自回归的，块内部是扩散的**。

$$ p(x_{1:L}) = \prod_{b} p\big(x^{[b]} \mid x^{[1:b-1]}\big) $$

每个块 x^[b] 是一段固定长度的 token，它的条件分布由一次离散去噪给出——把块内的若干位置换成 [MASK]，让模型看着「前面的块 + 块内没被 mask 的位置」并行把 mask 补上。

这个定义里藏着三个对投机解码极其重要的性质：

1. **块大小是个插值旋钮**。块长取 1，块扩散退化成普通的自回归模型；块长取整段长度，退化成纯扩散。中间任意长度都是合法模型。这就是「Interpolating Between Autoregressive and Diffusion Language Models」这个标题的意思。 2. **块间有因果结构，所以能 KV cache**。纯扩散因为块内双向可见，前面算过的 KV 没法复用；块扩散的块与块之间是严格因果的，前面块的 KV 可以缓存下来——**推理成本和普通解码器一样是分摊的**，这是它能进生产的前提。 3. **块内是双向的，所以能一次出整块**。同一个块里的所有 mask token 互相可见，一次前向就全都预测出来，不需要像自回归那样跑 γ 次。

这三点合起来，正好是投机解码草稿阶段需要的形状：**一条能并行、能缓存、又能按需调整块长的生成路径**。BD3-LM 原文解决的是「扩散模型 perplexity 追不上自回归」和「不能生成变长序列」这两个问题；DFlash 拿去解决的是第三个问题——草稿太慢。

代价也要说清楚：块内双向意味着**块内位置之间没有先后依赖**，第 k 个位置不知道第 k−1 个位置选了什么。对一个普通的语言模型这是缺陷（生成不连贯），对投机解码的草稿来说这是**必须在训练和验证侧补回来**的约束。后面几节里，3.5 的锚点采样和位置加权损失，本质上都在补这一块。

### 3.2 目标上下文特征：跨层融合

目标模型先做一次标准 prefill，顺手把中间层的语义抽出来。这次前向本来就要做，不额外收费。期间从**第二个层到倒数第三层之间均匀采样 5 层**的隐藏状态，拼接后过一次投影，压成紧凑的目标上下文特征：

$$ H_t = \mathrm{RMSNorm}\left(W_c \left[H^{(l_1)}; \dots; H^{(l_5)}\right]\right) $$

逐项来看：

- H^(l_k) 是目标模型第 l_k 层的隐藏状态，形状 [L × D]，L 是序列长度；
- [·;·] 是沿特征维拼接，5 层拼起来是 [L × 5D]；
- W_c in mathbbR^D × 5D 是新增的全部可训练参数，所有草稿层共享；
- RMSNorm 让输出尺度与草稿模型内部一致，避免注入后激活分布漂移。

**为什么取中间层？** 浅层偏语法、深层偏输出，中间层携带的是「任务级」的语义——长程依赖、当前在解什么题、下一步大概往哪走。论文的说法是，中间层隐藏状态既包含当前 token 的语义，也隐含了多个未来 token 的走向。把 5 层拼起来，等于让草稿模型同时看到局部语法和整体意图。

**为什么是 5 层而不是 3 层？** 见 6.3 的消融：3 层 x 5 层的差距在 Math500 上是 4.49× x 4.69×。更多层提供更丰富的语义，代价在训练侧——离线缓存目标隐藏状态，存储随特征数线性增长。

### 3.3 KV 注入：和 EAGLE-3 的本质区别

这是全文最值得注意的设计，也是很多论文解读会一笔带过的地方。

EAGLE-3 也用了目标模型特征，但它是把特征与草稿模型的 **token embedding 融合，作为输入喂进去**。这个做法有一个隐性代价：草稿模型层数加深时，这份外部信息在每一层的自注意力和 FFN 里被反复混合、逐渐稀释。上一节说的「加层收益迅速递减」，本质上是**信息在传递中衰减**。

DFlash 换了做法——把投影后的目标特征当作**持久上下文**，注入到草稿模型每一层的 Key 和 Value 投影里：

$$ Q_i = W^Q_i H_d,\quad K_i = \left[W^K_i H_t;\ W^K_i H_d\right]_{\mathrm{seq}},\quad V_i = \left[W^V_i H_t;\ W^V_i H_d\right]_{\mathrm{seq}} $$

逐项来看：

- H_d 是第 i 层草稿 token 的隐状态，H_t 是 3.1 算出来的目标上下文；
- Q 只由草稿自己的隐状态投影得到——**目标特征是「被查询方」，不是「查询方」**；
- K 和 V 都做序列维拼接：目标特征在前、草稿特征在后；
- 下标 seq 表示沿序列维拼接，所以第 i 层的草稿 token 在算注意力时，除了看到草稿内部，还能看到全部 L 个目标上下文位置。

这个设计有三个直接后果：

1. **信息绕过所有非线性**。目标特征只进 K/V，不经过 Q 投影、输出投影、自注意力更新和 FFN——每一层的草稿 token 查询时都能拿到一份**未经污染**的目标上下文。 2. **可以跨迭代复用**。这份 KV 是 prompt 的确定性函数，算一次就存在草稿模型的 KV cache 里，后续每个解码块直接复用，不增加每块的开销。 3. **草稿加深不再衰减信息**。每层都直连同一份目标特征，加深只是增加适配容量，不会稀释信号。

收益直接体现在消融上（Qwen3-4B，5 层草稿，block size 8，数字为 τ x 加速比），这是全文最能说明问题的一张表：

| 草稿方式 | 注入方式 | GSM8K | HumanEval | MT-Bench |
| --- | --- | --- | --- | --- |
| 自回归 | EAGLE-3 输入融合 | 4.2 / 2.1× | 4.3 / 2.2× | 3.1 / 1.4× |
| 自回归 | DFlash KV 注入 | 4.8 / 2.4× | 4.6 / 2.3× | 3.4 / 1.5× |
| 块扩散 | 输入融合 | 3.5 / 2.9× | 3.5 / 2.9× | 2.6 / 2.0× |
| 块扩散 | KV 注入 | 4.2 / 3.3× | 4.0 / 3.2× | 3.0 / 2.2× |

这张 2×2 的对照信息量很大：

- **行方向看注入方式**：同样 5 层，KV 注入在每种草稿方式、每个任务上都高出一截。自回归草稿 2.1× → 2.4×，块扩散草稿 2.9× → 3.3×。注入方式的改进是**与草稿结构正交**的，这一点很关键——说明 EAGLE-3 也能吃这个红利。
- **列方向看草稿方式**：用输入融合时，块扩散（2.9×）反而比自回归（2.1×）好，因为并行起草省了时间。加上 KV 注入之后，自回归的 τ 还是更高（4.8 vs 4.2）——**但块扩散的起草成本低得多**，净加速比 3.3× 反超 2.4×。这条差异很关键：τ 高不等于快，草稿成本必须一起算。
- **对角线看组合**：块扩散 + KV 注入同时拿到了并行的速度和持续的上下文，是四组里在两个维度上都不吃亏的那一组。

这也解释了为什么接受长度能**随草稿层数继续增长**（6.1），而 EAGLE-3 加深层的边际收益很快消失。

**代价有多大？** 多出的可训练参数只有共享投影 W_c。以 Qwen3.5-35B-A3B 为例，D=2048、BF16：

$$ 5 \times 2048 \times 2048 \times 2 \approx 42\ \mathrm{MB} $$

相对约 70 GB 的目标模型可以忽略。激活开销同样小：batch=1、序列 2048 时，投影的输入输出约 40 MB 与 8 MB；解码 block size 16 时临时激活不到 400 KB。换句话说，**这个设计几乎是免费的质量提升**。

### 3.4 块扩散并行草稿

草稿阶段用块级扩散：一个 block 里所有被 mask 的位置**在一次前向里同时解码**。于是

$$ T_{\mathrm{draft}} = t_{\mathrm{parallel}}, \qquad t_{\mathrm{parallel}} \ll \gamma \cdot t_{\mathrm{step}} $$

这里 t_parallel 是一次前向的时间（与块大小基本无关），t_step 是自回归草稿单步前向的时间。16 个 token 一次出，相当于把起草耗时除以 16。

容易被忽略但有第二层效应：**草稿耗时不再随长度线性增长后，草稿模型就可以做得更深**。实测 5 层 DFlash 生成 16 个 token，延迟比 1 层 EAGLE-3 生成 8 个还低（见 6.1 的图 4）。并行不只省掉 7/8 次前向，还把草稿模型从「必须浅」的约束里解放了出来——**质量与速度第一次不再互斥**。

一个容易忽略的细节：块扩散的训练目标与推理过程必须对齐。推理时草稿总是从一个「干净 token」（上一轮验证产出的 bonus token）出发预测下一块，所以训练时也要以干净 token 为锚点，这正是 3.5 第一条修改的动机。

### 3.5 训练上的四处关键修改

块扩散要真正接上投机解码，训练侧还必须解决四个问题。

![](https://pic4.zhimg.com/v2-6a9167b3dbc1c8a89b244caabdcfe8a7_r.jpg)
*图 2 · 训练时的注意力结构。蓝色目标特征对所有草稿 token 可见；黄色锚点是块首的干净 token；绿色 mask token 并行预测；白色区域是被屏蔽的注意力，块与块之间禁止互相看*

**（1）锚点随机采样建块。** 标准块扩散把回复均匀切块再随机 mask；DFlash 在回复里**随机采样「锚点 token」**，以锚点为块首，mask 其余位置，让模型并行预测后 block size − 1 个 token。

这个构造精确匹配推理时的情形——草稿模型总是从一个干净 token 出发预测下一块。随机锚点还顺带扩充了样本覆盖：每个 token 都有机会成为块首。消融显示，标准切块 4.13× / τ=4.94，改成锚点采样后 4.69× / τ=5.64，单项提升 13%。

**（2）稀疏注意力掩码 + 多块联合训练。** 所有块拼成一条序列：块内双向注意力、每个块都能看到自己对应的目标特征；**块间禁止互相看**。这既保证了因果一致性（后面的块不能「偷看」答案），也让一次前向-反向能同时训练多个草稿块。实现上配合 Flex Attention 的高效稀疏掩码。

**（3）位置加权损失。** 我认为这是全文最懂投机解码的一条设计。

投机解码的接受规则是「前缀连续匹配」：一个块里**第 k 个位置的错误会让后面所有 token 全部作废**。也就是说，早期位置的错误代价是不成比例的——位置 1 错了，后面 15 个白猜；位置 12 错了，只损失 4 个。标准扩散损失对每个位置一视同仁，和接受长度的目标完全错位。

论文用指数衰减权重把这个不对称直接写进损失：

$$ w_k = \exp\left(-\frac{k-1}{\gamma}\right) $$

w_k 是块内第 k 个位置的损失权重，γ 控制衰减速度（block 16 取 7，10 取 5，8 取 4）。**块越大，衰减越慢**——因为大块里「后面还剩多少 token」本身更多。实测带 loss decay 收敛更快、接受长度更高。

这条设计的普遍意义在于：**投机解码的训练目标不该等价于语言建模的训练目标**。语言建模关心整个序列的似然，投机解码关心的是「前缀不崩溃」的概率，两者在块内位置上的敏感度完全不同。

**（4）共享 embedding 与 LM head。** 复用目标模型的 token embedding 和输出头并冻结，只更新草稿 Transformer 层。这既减少了可训练参数，也让草稿模型在表示空间里与目标模型天然对齐——它本来就是一个轻量的扩散适配器，不需要自己重新学一套词表映射。

**训练配置**：6 epoch，AdamW，学习率 6×10^-4，梯度裁剪 1.0，cosine 调度 warmup 0.04；最大序列长度 3072（Qwen3-Coder 4096），每条序列随机采 512 个锚点位置。数据约 80 万条（Nemotron Post-Training V2 + CodeAlpaca），**回复由目标模型重新生成**以保证分布对齐。

## 4. 实验设置

### 4.1 模型与基准

- **目标模型**：LLaMA-3.1-Instruct-8B、Qwen3-4B / 8B / Coder-30B-A3B-Instruct，另测 Qwen3.5 系列与 GPT-OSS-20B / 120B
- **基准**：数学（GSM8K、MATH-500、AIME25）、代码（HumanEval、MBPP、LiveCodeBench）、对话（MT-Bench、Alpaca）；长上下文用 LongBench（hotpotqa、qasper、gov_report）
- **指标**：平均接受长度 τ、相对自回归的端到端加速比
- **硬件**：训练与主实验 H200；SGLang 部署单卡 B200 + FlashAttention-4

### 4.2 基线

- **自回归解码**（无投机），作为加速比的分母
- **EAGLE-3**，tree size 16 与 60 两档。选 60 是给基线最有利的设定——它用更大的验证开销换更长的接受
- 由于缺少开源实现，未与 TiDAR、DiffuSpec、SpecDiff-2、PARD 做同条件对比（见 7.1）

### 4.3 实现细节

- 草稿 5 层（Qwen3-Coder 用 8 层），block size 16（LLaMA-3.1 为 10）
- 目标特征取 5 层，共享投影 W_c
- 主实验贪心解码、关闭 thinking、最多生成 2048 token，以排除采样随机性

四个值得拆开看的点：

- **数学和代码提速最猛（5–6×），MT-Bench 只有 2.75×。** 差距来自任务本身的确定度：数学推理的下一步几乎被前文锁定，代码的语法约束也很强，草稿模型容易猜准；闲聊文本熵高、分支多，草稿的命中率天然低。这个差异不是方法缺陷，而是投机解码的固有属性——**它加速的是「有约束的生成」**。
- **EAGLE-3 把 tree size 从 16 加到 60，平均只从 1.76× 涨到 2.02×。** 多 44 个候选节点，换来的加速不到 15%，因为验证成本同步涨了。这说明它的瓶颈在草稿质量，不在树宽——2× 附近是结构性上限。
- **DFlash 的 τ 是 6.49，EAGLE-3 (60) 是 3.40。** 加速比 4.86 / 2.02 ≈ 2.4 倍，基本等于接受长度之比——说明两者的起草和验证成本结构接近，差异几乎全部来自草稿质量。
- **温度 1 时 DFlash 平均 4.03×（Q3-8B），EAGLE-3 (60) 是 1.88×，仍有 2.1 倍优势。** 收益不只在高接受率的贪心解码下成立。

### 5.2 一个必须说清的口径：这里的 EAGLE-3 只有 2.02×

**这一节里的 EAGLE-3 加速比（平均 2.02×）和 EAGLE-3 自己论文报的数字（Vicuna 13B 六任务平均 5.51×）差了近 3 倍。** 这不是谁造假，是两组实验的设定根本不同：

- **目标模型不同**：EAGLE-3 原论文的主战场是 Vicuna 13B、LLaMA-Instruct 3.1 8B / 3.3 70B。DFlash 比的是 **Qwen3 4B / 8B / Coder**。
- **草稿权重来源不同**：DFlash 用的是 AngelSlim（腾讯）发布的 Qwen3 版 EAGLE-3 checkpoint——**那是第三方按 EAGLE-3 方法在 Qwen3 上重训的**，不是 EAGLE-3 作者自己训的。论文在 5.5.1 节的同条件对照里才用官方权重。
- **推理框架不同**：DFlash 主表跑的是 Transformers backend，EAGLE-3 原论文跑的是自己的实现。

**所以「DFlash 4.86× vs EAGLE-3 2.02×」这个比值，比的是「两套完整系统在 Qwen3 上」，不是「两种方法在论文最优条件下的能力」。** EAGLE-3 在它自己最擅长的模型上能到 5.5×，这一点不应该被这张表掩盖。

**好消息是论文自己在附录里给了同条件对照**（5.5.1 节）：目标模型换成 LLaMA-3.1-8B-Instruct，**DFlash 用与 EAGLE-3 完全相同的训练数据（UltraChat + ShareGPT）重训，EAGLE-3 用官方发布的权重**，两者跑在同一个 SGLang 后端、同一张 B200 上。这组数据才能回答「方法本身谁更强」：

| LLaMA-3.1-8B（SGLang，单路） | EAGLE-3 (60) | DFlash (10) |
| --- | --- | --- |
| GSM8K | 1.9× | 2.4× |
| HumanEval | 2.0× | 2.8× |
| Alpaca | 1.8× | 2.2× |
| 32 并发（GSM8K） | 0.6× | 1.6× |

**这组对照把差距从「2.4 倍」压到「1.2–1.4 倍」，但方向没变**：同等条件下 DFlash 仍然领先，而且**并发越高领先越多**——32 并发时 EAGLE-3 已经掉到 0.6×（比不开投机采样还慢），DFlash 还有 1.6×。

我自己对这两组数字的判断：

- **DFlash 的优势方向是可信的**，因为它同时拿出了 τ 和草稿延迟两个独立证据，KV 注入的消融（3.2 节）证明收益来自机制而不是调参，附录的同条件对照又排除了「基线没调好」这个解释。
- **「2.4 倍」这个倍数只属于 Qwen3 那组设定**，不应单独引用。要引用倍数，用 LLaMA-3.1 同条件那组的 **1.2–1.4 倍**更稳。
- **EAGLE-3 在它自己的主场（Vicuna 13B、LLaMA-Instruct 3.1/3.3）上仍有 4–5.5×**，DFlash 没有在这些模型上做同条件对比——这是论文没覆盖的空白。

### 5.5 长上下文：1.6K 样本微调即可适配

基础草稿只在 4K 上下文训练。用 LongAlign-10K 的 **1.6K 条样本微调 3 个 epoch**，LongBench 上：

| 上下文 | hotpotqa 基础/微调 | qasper 基础/微调 | gov_report 基础/微调 |
| --- | --- | --- | --- |
| 4K | 4.91 / 5.41 | 5.17 / 5.80 | 3.93 / 4.25 |
| 8K | 4.46 / 5.76 | 4.17 / 5.62 | 3.32 / 4.04 |
| 16K | 3.61 / 6.05 | 3.57 / 6.00 | 2.67 / 3.81 |
| 32K | – | – | 2.09 / 3.56 |

基础模型从 8K 开始明显退化（hotpotqa 4.91 → 4.46 → 3.61），微调后不仅守住，**16K 的接受长度甚至比 4K 还高**（6.05 vs 5.41）。

这个反常现象值得解释：长上下文里，目标模型的注意力已经收敛到少数关键段落，预测分布更集中；同时目标特征覆盖了整个上下文，草稿模型拿到的条件信息更丰富。换句话说，**上下文越长，目标特征越「值钱」**。

工程意义：对做长文档 RAG 和长对话的人，**不用重训草稿模型**，1.6K 样本微调就能把草稿适配到 32K。

## 6. 深入分析

### 6.1 草稿层数：更深不等于更快，5 层是最佳平衡

| 配置 | Math500 | HumanEval | MT-Bench |
| --- | --- | --- | --- |
| 3 层 | 4.69× / τ=5.64 | 3.90× / τ=4.61 | 2.38× / τ=3.18 |
| 5 层 | 4.71× / τ=5.99 | 3.96× / τ=4.94 | 2.35× / τ=3.37 |
| 8 层 | 4.64× / τ=6.33 | 3.96× / τ=5.29 | 2.23× / τ=3.50 |

![](https://pic4.zhimg.com/v2-b6f72fedf018ecde44b3c033d72f843f_r.jpg)
*图 4 · 起草耗时对比：1 层 EAGLE-3 串行起草 8 个 token，比 5 层 DFlash 并行起草 16 个还慢*

**接受长度随层数单调上升（5.64 → 5.99 → 6.33），加速比却在 5 层饱和甚至回落。** 三个数字放在一起看很有说服力：

- 8 层的 τ 比 5 层高 5.7%，但起草延迟涨得更多，净加速反而更低；
- 这说明存在一条 **Pareto 前沿**（性能与代价的取舍边界），由 KV 注入撑开：每加一层，质量提升，延迟也上升。前沿足够平缓，5 层附近是性价比最高的点；
- 反过来，如果用输入融合，加层的收益会在两三层后就消失。前沿会陡峭得多，根本不存在「选点」的余地。

### 6.2 block size 的跨尺度泛化：大块可以跑小块

| 训练块 → 推理块 | Math500 | HumanEval | MT-Bench |
| --- | --- | --- | --- |
| 16 → 16 | 4.64× / τ=6.33 | 3.96× / τ=5.29 | 2.23× / τ=3.50 |
| 16 → 8 | 3.87× / τ=5.09 | 3.39× / τ=4.44 | 2.12× / τ=3.18 |
| 8 → 16 | 3.78× / τ=5.02 | 3.24× / τ=4.28 | 2.09× / τ=3.09 |
| 8 → 8 | 3.97× / τ=5.21 | 3.53× / τ=4.61 | 2.22× / τ=3.29 |

16 训练降到 8 推理几乎不掉（τ 6.33 → 5.09，但仍高于 8→8 训练的 5.21），反过来不行（8→16 掉到 5.02）。原因很直白：**大块训练的模型见过更难的任务**。它必须在整块里正确预测更多 token，能力天然覆盖小块；反过来，小块训练的模型没遇过长程依赖，处理大块时前缀一致性撑不住。

一个有意思的细节：Math500 的接受长度直方图显示，block 8 有 **35.7% 的情况整块全接受**。这说明 8 对数学任务常常不够用，大块的空间还没吃满。

实际意义：**推理时可以动态调 block size**。大 batch 下验证是 compute-bound（受算力限制），把块调小反而整体更快；小 batch 下用大块吃满接受长度。作者把自适应调度留作后续工作，但数据说明这条路是通的。

### 6.3 训练目标特征数：5 层优于 3 层，但代价是存储

| 目标特征数 | Math500 | HumanEval | MT-Bench |
| --- | --- | --- | --- |
| 3 层 | 4.49× / τ=5.38 | 3.80× / τ=4.47 | 2.32× / τ=3.07 |
| 5 层 | 4.69× / τ=5.64 | 3.90× / τ=4.61 | 2.38× / τ=3.18 |

5 层比 3 层在三个任务上都有提升（Math500 τ +0.26），收益不大但方向一致。代价在训练侧：目标隐藏状态要离线缓存，**存储随特征数线性增长**。论文没有继续往更多层试，推测是存储和带宽成了新的瓶颈，而不是质量。

这也暴露了 DFlash 的一个隐性依赖：训练必须能拿到目标模型的内部激活。这意味着**目标模型和草稿模型必须在同一套代码路径里训练**。对已经上线的模型，这一步需要额外搭基础设施。

## 7. 讨论与判断

### 7.1 局限：论文自己承认的与没说的

**缺少同条件对比。** 论文明确说明，因缺少开源实现，没有和 TiDAR、DiffuSpec、SpecDiff-2、PARD 做直接对比。论文对它们的缺陷有清晰论证：7B 草稿太重，小自回归草稿容量不足。但少了一组同条件对照，读者无法判断「4.86×」里有多少来自方法、多少来自实现。

**收益高度依赖场景。** 数学和代码 5–6×，MT-Bench 只有 2.75×；32 并发降到 2.8×；vLLM 下低到 1.3–2.1×。如果线上负载是闲聊、高并发，能吃到远低于 6×。

**训练侧有隐性成本。** 离线缓存目标隐藏状态、目标模型与草稿同路径训练，这两点论文都一笔带过。对没有训练基础设施的团队来说，这不是小工程。

**block size 固定。** 作者自己也说自适应调度是后续工作。现在的实现在大 batch 下可能不是最优。

### 7.2 判断：这个工作真正的贡献

**它真正的贡献不是一个更快的解码器，而是一次视角切换。**

过去几年扩散语言模型（LLaDA、Block Diffusion、SDAR）的主线是「能不能在端到端生成质量上追平自回归」，卷得很辛苦。DFlash 给出另一条路：**把扩散放回它真正擅长的地方——并行吞吐**，质量交给目标模型的验证来兜底。扩散模型的劣势被制度性地消除，不要求它写得对；优势被直接兑现，一次出整块。

这个思路可能比论文本身的数字更有迁移价值。任何「猜测 + 验证」的架构——speculative decoding、draft-then-edit、树搜索的初始展开——都可以问同一个问题：**草稿能力要求的到底是「会生成」还是「会适配」？**

### 7.3 工程落地：成本低是很大的优点

- 草稿 5 层、每次推理多花 42 MB，目标模型完全冻结；
- 已合入 SGLang 和 vLLM，不需要改推理框架；
- 长上下文只需 1.6K 样本微调；
- 相比要改模型架构的 MTP（multi-token prediction，多词元预测），它更像一个**外挂**。

对正在做推理优化的团队，这是目前「投入产出比」最高的投机解码方案之一。

### 7.4 后续值得跟的方向

1. **推理时自适应 block size 调度**。6.2 的数据说明大 batch 下调小反而更快，这块直接能多吃一截。 2. **位置加权损失的一般化**。它揭示的思路是「训练目标应直接优化前缀不崩溃的概率」，这个原则可以推广到所有块式生成器的训练。 3. **目标特征的压缩与缓存**。5 层已经是存储瓶颈。如果能用更少层数或低精度缓存达到同样效果，训练门槛会低很多。 4. **与树状验证结合**。DFlash 现在给的是单条 16-token 链。如果块扩散与 EAGLE 的树形验证结合，接受长度还有空间。

**结论**：在「不改变目标模型、不引入大草稿模型」的前提下，DFlash 目前是投机解码质量-延迟 Pareto 前沿上最靠左的一个点，把加速比从 2–3× 这一档实打实推到了 5–6× 这一档。它最适合的，正是当下最花时间的那类请求。

## 附：问答

> 10 个问题，从训练方式、注意力的 Q/K/V 到底是什么，一路问到并行惩罚和与 DSpine 的路线差异。

**问题 1：DFlash 是怎么训练的，也是 TTT（Training-Time Test）吗？**

回答 1：不是。DFlash 用的是「随机锚点采样 + 带位置衰减的块级交叉熵」，本质上是 Teacher Forcing：目标模型先把完整回复跑一遍，抽出各位置的隐藏特征，草稿模型看着这些特征和锚点去补全被 mask 的位置，损失直接和真实 token 比。TTT 的存在意义是消除「训练时见真值、推理时见自己输出」的暴露偏差，而 DFlash 的条件信息来自**冻结的目标模型**，草稿输出不会回流成下一步的输入，也就没有这条偏差来源。所以它不需要 TTT，训练成本也因此低得多——这也是它能把长上下文训练做便宜的原因。

**问题 2：Target Model 的融合隐藏层和 DFlash 的隐藏层是怎么融合的？**

回答 2：不是在输入端相加或拼接，而是**注入到 KV**。5 层目标隐藏状态先沿特征维拼成 [L × 5D]，过一次共享投影 W_c 加 RMSNorm，得到目标上下文 H_t；到草稿每一层，H_t 分别过该层的 Key、Value 投影，再和草稿自己的 K_d, V_d 沿序列维拼起来。融合发生在注意力的「被查询」侧：草稿 token 作为 Query 去查一份「目标特征 + 草稿内部」的联合记忆。目标特征全程不经过 Q 投影、输出投影和 FFN，因此不会被非线性反复揉碎。

**问题 3：DFlash 不是扩散模型吗，块内是怎么做双向注意力的？**

回答 3：它是块扩散（Block Diffusion），块内做的是**掩码语言建模式的完形填空**，注意力是非因果的。同一块里所有待预测位置互相可见，也都能看到块首那个干净锚点和全部目标上下文，然后大家一起并行填空。块与块之间则严格因果——后面的块不能看前面的答案之外的未来块。所以准确说法是「块间因果、块内双向」，不是「整段双向」。

**问题 4：DFlash 注意力里的 Q、K、V 分别是什么？**

回答 4：Q 只来自草稿块自身的隐状态 H_d，过草稿该层的 W^Q；K 和 V 是两段的序列拼接——前段是目标上下文 H_t 过该层的 W^K/W^V，后段是草稿隐状态 H_d 过同一组投影。换句话说，**草稿提问，目标特征和草稿自己一起作答**。这个不对称是有意的：如果让目标特征也参与 Q，它就变成了一个会随层数被改写的普通输入，跨层注入的「不变性」就没了。

**问题 5：DFlash2 每个位置选 Top-16 个候选词，等于每轮验证 16 个草稿 token，验证长度不会太高吗？**

回答 5：这里有个容易混淆的口径。**本篇论文里的 16 是块大小**，即一次前向顺序铺开 16 个位置、每个位置出一条链，送去验证的就是这 16 个位置的一条前缀，不是 16 条互不相干的候选。每位置 Top-16 候选池、再由路径选择器挑一条连贯路径，是后续 DFlash2 一类的做法；那份材料我没能拿到原文核对，只能按机制说：候选池宽度 K 和验证长度 L 是两回事，K 只影响「每个位置保留几个可能」，真正的验证长度由选出来的那条路径决定，通常还会按边际收益截断。把 K 误读成验证长度，会得出「验证成本爆炸」的错误结论。

**问题 6：整块并行预测时，如果这 8 个 token 的联合概率被扭曲、被大面积拒绝，「并行加速」会不会变成「并行惩罚」？**

回答 6：会，而且这是块式草稿最本质的风险。投机解码只接受连续前缀，块里第 1 个位置错了，后面全部作废——自回归草稿至少每步都产出一个可用 token，块扩散草稿可能一次前向颗粒无收。DFlash 用两条设计对冲：训练侧的位置加权损失 w_k=exp(-(k-1)/γ) 把「越靠前越不能错」直接写进目标函数，γ=7 时第 8 个位置的权重已经降到约 0.37；推理侧则是块大小与截断的取舍——6.2 的跨尺度实验说明大块可以降块推理，本质就是按当时的接受情况缩短「可能被浪费的尾巴」。**并行惩罚没法消除，只能把它的期望压下去。**

**问题 7：块内是双向注意力，推理时温度、Top-p 这类采样参数怎么处理？**

回答 7：这是论文没展开的一块，需要说清楚边界。正文的主实验是贪心解码（温度 0），每个位置取 argmax，不存在「联合采样」的问题；温度 1 的结果也报了（Qwen3-8B 平均 4.03×），但论文没有描述具体的逐位置采样细节。机制上的难点是明确的：块内没有因果依赖，每个位置各采各的 Top-p，很容易拼出一组「单词都对、连起来不通」的组合，联合概率远低于各自概率。常规解法是把每个位置的概率当成候选池，交给路径选择或束搜索按联合得分挑一条，而不是独立采样。注意这只影响接受长度，不影响正确性——验证阶段的接受/残差重采样规则没变，输出分布仍然等于目标模型。

**问题 8：高并发下反复抽取目标模型 5 个中间层的隐藏特征，会不会变成显存带宽杀手？**

回答 8：会，这是这类架构上线时最该盯的成本，而论文只给了 batch=1 的乐观数字。需要搬的东西有三份：prefill 时 5 层激活（[L × 5D]，序列 2048、D=2048 约占 40 MB）、投影前后的一次读写、以及注入后存在草稿 KV cache 里的那份目标特征——后者按「序列长度 × 层数 × 2」随上下文增长，长上下文场景是主要显存项。batch=1 时论文测到临时激活不到 400 KB，但那是解码块的量；batch 放大后，抽取和拼接的开销按请求数线性叠加，而这一步是纯带宽操作、不产生算力收益。工程上的缓解是 kernel 融合（把抽取、拼接、投影合成一个 pass）、CUDA Graph 固定形状、以及只在必要的层上抽特征。

**问题 9：DFlash2 的路径选择器如果用 DP 全局打分，打分函数到底长什么样？**

回答 9：先说边界：**本篇论文没有路径选择器**，它输出的是单条链；这里是按后续工作的通用形态回答，具体公式我没能核对原文。典型写法是在 L × K 的候选网格上做 Viterbi：状态是「第 i 个位置选第 k 个候选」，转移分数由相邻两个候选的亲和度给出（隐状态相似度，或条件概率 log p(c_i+1mid c_i)），再加上每个候选自己的 log p，路径得分就是逐项累加。递推只保留「到达当前节点」的最优前驱，复杂度从穷举的 O(K^L) 降到 O(LK²)；L=16、K=16 时是四千次级别的乘加，在 GPU 上就是一个小矩阵连乘，微秒量级。它的作用不是提升单点准确率，而是把「各自看起来都不错、连起来不通」的组合筛掉。

**问题 10：把 DFlash（块并行）和 DSpark（时序头）结合起来，与 DSpine 的「层间因果注入」本质区别在哪？**

回答 10：区别在**因果信息注入的时机和位置**。DFlash + DSpark 是「先无因果地算，再在末端修」：块扩散用双向注意力一口气把整块填完，DSpark 那类轻量时序头（RNN 或马尔可夫式）在输出端从左到右把序列捋一遍，按前一个 token 修正后一个的分布。这属于后处理——错误已经形成，只能改概率，改不了特征。DSpine 是「在特征形成过程中就保证因果」：每一层 Transformer 内部用门控相邻注入把前驱特征传给后继，因果性从表示层就成立，不依赖末端修补。代价也在这里——后处理可以外挂、可以单独训练，层间注入要改草稿的每一层结构，训练和推理都更重。所以预期是 DSpine 的接受长度更高、DFlash + DSpark 的工程成本更低，这条取舍和 EAGLE-3 与 DSpark 在置信度上的分歧是同一个形状：**要「事后纠偏的便宜」还是「事前正确的贵」。**
