今天再来写写投机推理。

投机推理卷完大语言模型，去卷多模态领域是顺理成章的。我们今天就简单通过几组论文来聊聊文本+图像（图片视频等）为输入，文本输出的多模态大模型的投机推理工作。因为还是文本输出，所以本质上模型还是自回归模型，投机推理方法还是原来的投机推理范式，即草稿小模型输出草稿 token 再由目标大模型进行验证。

多模态领域做投机推理也是面临着不少 **挑战** 的，比如：1）视觉信息让 “草稿模型” 难以完成和语言模型一样的预测过程，核心问题在于 **模态语义差** 问题，小模型很难学到和大模型一致的扩模态 **对齐能力** ，使得草稿和验证模型的分布差异大，接受率低，最终使得投机加速效果打折扣。2）图像特征计算昂贵，拖慢整体速度，如果草稿模型也要编码图像，等于 **双倍视觉计算** ，纯文本草稿模型虽然快，但又 **看不到图** ，预测更不准，同时投机解码本身就是 **带宽敏感型算法** ，多模态进一步放大瓶颈。3）长视觉序列带来更长的依赖链，图像会被切成大量 patch 特征，序列长度远大于文本。自回归生成时，小模型还捕捉不到深层视觉语义，视觉依赖更长、更难预判。

我们今天根据草稿模型对视觉信息的依赖程度，将论文分为四种主要范式：一是全视觉输入范式，草稿模型需接入完整的视觉输入，目的是通过强化草稿模型的视觉感知能力来提升候选 token 的接受率；二是关键视觉输入范式，草稿模型仅依赖于提取的关键视觉信息，从而在保留必要多模态语义的同时显著降低计算开销；三是 **无视觉输入范式，即草稿模型完全不使用任何视觉 token（今天的重头部分）；** 是动态适配输入范式，系统可根据任务场景实时选择最优的视觉输入策略，实现自适应推理。此外，依据所处理视觉序列的长度不同，这些方法还可进一步划分为两类应用场景：面向短视觉序列（如单帧图像）的投机推理加速，和面向长视觉序列（如视频）的投机推理加速。

那么现在就主要以四种范式进行分类解读（ **全/关键视觉信息输入我认为可以作为无视觉信息输入范式的一个铺垫，被降维打击了** ，省时间的话可以直接去看 **无视觉信息输入** ）：

## 全视觉信息输入

该范式认为，投机推理在多模态模型中表现不佳的核心原因在于草稿模型与目标模型对视觉信息的感知不一致。因此，该类方法要求草稿模型接入完整的视觉输入，通过强化草稿模型的视觉感知能力来提升候选 token 的接受率。 所以可以认为这一类方法是以提高算法能力为目标，对齐模态就成为了这一类方法的核心。

- MSD: Speculative Decoding Reimagined for Multimodal Large Language Models, [arXiv 2505.14260](https://arxiv.org/pdf/2505.14260)
- Spec-LLaVA: Spec-LLaVA: Accelerating Vision-Language Models with Dynamic Tree-Based Speculative Decoding, [arXiv 2509.11961](https://arxiv.org/pdf/2509.11961)
- MASSV: Multimodal Adaptation and Self-Data Distillation for Speculative Decoding of Vision-Language Models, [arXiv 2505.10526](https://arxiv.org/pdf/2505.10526)

### MSD

作者主要来自厦门大学、上海创新研究院。

MSD 核心思想在于“解耦处理”与“渐进式能力习得”，而其整体框架流程则基本沿用了和 eagle 类似的 feature-wise 投机推理方法（图都一样）。 MSD 认为 **文本 token 具有强序列依赖性而视觉 token 具有全局关联性** ，因此在草稿模型中对二者实施差异化处理：对于文本 token，沿用传统投机推理中将隐藏状态与下一 token 嵌入拼接的方法以建模时序关系；而对于视觉 token，则直接使用其原始嵌入并避免拼接操作，从而保护了视觉语义的完整性，防止因强制时序化导致的视觉信息失真。

![](https://pic3.zhimg.com/v2-db0e3a686d11cefa572a757aebdc7d3c_r.jpg)

为了进一步提升草稿模型的能力，在训练策略方面，MSD 设计了严密的二阶段流水线以兼顾语言建模与视觉感知能力：第一阶段通过纯文本指令微调夯实草稿模型的通用生成基础，减少非视觉相关的生成错误；第二阶段则实施渐进式多模态混合训练，使视觉指令数据的占比随训练轮次逐步提升，这种由浅入深的策略让草稿模型在保留语言能力的同时逐步习得视觉感知，从而能够精准对齐目标模型在视觉约束下的预测分布，显著提升了候选 token 的接受率。

### Spec-LLAVA

作者主要来自：CMU、诺丁汉大学、香港大学、香港理工大学、哥伦比亚大学、UC Berkerly。中的是 TTODLer-FM Workshop at ICML 2025。

Spec-LLaVA 充分利用了 **视觉输入带来的“强语义约束”效应** ，通过深度共享架构与动态验证机制最小化草稿与目标模型间的表征差异。在架构层面，它为 7B/13B 的目标模型配备了仅 68M/160M 的轻量化草稿 VLM，二者通过共享 CLIP ViT-L/14 视觉编码器确保了输入特征的绝对一致，并结合知识蒸馏技术最小化二者间的 KL 散度，使草稿模型在极小参数量下实现对大模型输出风格的高度仿生。在推理算法上，Spec-LLaVA 引入了动态树基验证方案，依据草稿 token 级的置信度实时动态调整推测树的分支因子：当置信度高时构建窄深的单分支树，置信度低时则探索多分支的 top-b 路径，并配合目标模型进行由叶到根的并行验证，一旦匹配成功即可一次性接受多个 token。这种设计不仅确保了推理过程的无损性，更通过自适应的搜索策略极大提升了在描述性任务中的 token 接受长度，有效缓解了 复杂多模态场景下的加速瓶颈。

### MASSV

作者团队来自加州一个AI 硬件与系统公司，Cerebras。

MASSV 针对从头训练多模态草稿模型成本过高及分布难以对齐的挑战，提出 **通过架构适配与自蒸馏技术将现有纯文本小语言模型高效转化为多模态草稿模型** 。在架构实现上，它利用轻量级 MLP 投影器将目标 VLM 的冻结视觉编码器与 SLM 相连，通过精准的维度映射使原本仅具备文本能力的 SLM 能够直接处理目标模型所见的完整视觉信息，从而在底层架构层面实现对齐并消除冗余计算。 

![](https://pic2.zhimg.com/v2-253816554d3ff7a67e77312a8b4e2e25_r.jpg)

在训练策略上，MASSV 引入了两阶段自数据蒸馏方案：首阶段仅训练投影器以建立基础视觉关联；次阶段实施自蒸馏视觉指令调优（SDViT），由目标 VLM 针对视觉指令提前离线生成响应作为训练标签，而非依赖人工标注的静态数据集，通过同步微调投影器与 SLM 骨干，使草稿模型的预测分布高度逼近目标 VLM 的真实输出。这种“以目标模型为金标准”的对齐机制，从根本上解决了分布错位导致的接受率低下问题，在多模态语境下实现了极佳的加速表现。

## 关键视觉信息输入

该范式主张 **草稿模型无需处理全部原始视觉 token** ，而是仅依赖经筛选或压缩后的关键视觉信息，从而在保留必要多模态语义的同时显著降低计算开销。 所以可以认为这一类方法是以提高加速为目标，如何获取关键信息就成为了这一类方法的核心。不过后续的无视觉输入方法则更为激进，这并不是什么民科做到完全的 zero-shot，因为目标模型在 prefill 的时候已经看过了图像了，所以草稿模型不需要再看一点了。

- ViSpec: Accelerating Vision-Language Models with Vision-Aware Speculative Decoding, [arXiv 2509.15235](https://arxiv.org/pdf/2509.15235)
- Sparse-to-Dense: A Free Lunch for Lossless Acceleration of Video Understanding in LLMs, [arXiv 2505.19155](https://arxiv.org/pdf/2505.19155)
- SpecVLM: EnhancingSpeculative Decoding of Video LLMs via Verifier-Guided Token Pruning, [arXiv 2508.16201](https://arxiv.org/pdf/2508.16201)
- HIPPO: Accelerating Video Large Language Models Inference via Holistic-aware Parallel Speculative Decoding, [arXiv 2601.08273](https://arxiv.org/pdf/2601.08273)

### DREAM

作者主要来自：纽约大学、Cerebras 系统公司、宾夕法尼亚大学。和前面 cerebras 公司的 massv 方法的作者还不完全重合。

DREAM 认为多模态推理时存在着视觉特征丢失等结构化融合难题，在特征融合环节设计了专属交叉注意力层，将草稿模型中间特征与目标模型特征做交叉注意力查询融合，还引入基于注意力熵的自适应特征选择机制，选取语义稳定性最优的目标模型中间层特征作为监督信号，优化草稿模型的训练效果。

其中尤为关键的是视觉 token 压缩策略，该策略依据目标模型最后一层的注意力权重计算视觉 token 重要性，仅保留高信息密度的视觉 token（如前 75%），能在几乎不损失推理精度的前提下，大幅削减草稿模型处理视觉信息的计算开销。这个方法看起来并没有太出奇的地方，其本质就好比 kv cache 压缩，并不很新奇。

### ViSpec

作者主要来自：北大和华为

ViSpec 首先指出了将投机推理直接应用于 VLM 效果不佳（加速比不足 1.5 倍）的根本症结，即图像与文本数据的本质差异：文本高度抽象且信息密集，而图像则充斥着如大片空白或重复纹理等海量冗余（low level feature）。这种信息密度不对称导致容量有限的小型草稿模型难以复现大型目标模型在深层处理中有效过滤视觉冗余并兼顾语言理解的能力。

针对这一核心矛盾，ViSpec提出了基于“压缩与注入”的解决方案。在架构设计上，它引入受 Q-Former 启发的轻量级视觉适配器，将上千个原始图像词元极简压缩为 1–4 个高信息密度词元，在保留位置信息的同时显著减轻了冗余负担；为缓解生成过程中的 Lost-in-the-Middle 问题，该方法进一步提取代表全图语义的全局特征向量，并将其持续注入到每一个后续文本 Token 的隐藏状态中，确保了草稿模型在整个生成周期内都能访问完整的视觉上下文。此外，针对公开数据集回复过短的局限，ViSpec 通过构建专用的长回复合成数据集并配合多词元预测策略，有效避免了模型的“捷径学习”，从数据与推理机制双层面显著提升了草稿模型的长序列推测精度。 

![](https://pica.zhimg.com/v2-8ff4ed712ee34fc712c3a01af6e14b96_r.jpg)

前面两篇的输入是以单张图，

而 **当输入数据由静态图像拓展至动态视频** 时，视频帧被编码为海量的视觉 Token（例如，LLaVA-OneVision 模型会将每一帧视频编码为 196 个Token，这意味着一段帧率为 60 帧 / 秒的两分钟视频，若不进行任何Token精简处理，默认情况下生成的Token数量会超过 100 万个），这引发了严重的计算瓶颈：预填充阶段的注意力计算开销呈二次方增长，解码阶段自回归生成的KVCache 持续膨胀，成为显存占用的核心痛点。然而，现有的 token 剪枝方法往往导致不可逆的信息损失，而通用的长上下文投机推理方法由于缺乏模态感知能力，无法适配视频 token 的高冗余性与独特注意力模式，导致加速效果受限。所以后边三篇论文分别从 **稀疏注意力机制** 、 **双阶段剪枝策略** 及 **全感知并行架构** 三个维度提出了解决方案。

### **Sparse-to-Dense**

作者主要来自新加坡管理大学、Sea人工智能实验室、新加坡国立大学

针对因海量 token 导致的推理高延迟与内存带宽瓶颈，以及引入额外草稿模型成本过高的问题，STD 利用模型解码时的显著稀疏性实现了无损加速。研究基于 Qwen2-VL-7B 在 MLVU 和 VideoMME 数据集上的实验发现，仅保留注意力权重最高的 Top-K KV 缓存，模型即可对约 95% 的 Token 做出与原模型一致的预测，虽连续生成的准确率随数量下降（如 5 个 token 约 77%），但这足以证明稀疏注意力具备作为草稿生成器的潜力。在稀疏与密集协同架构上，STD 让大模型自身充当草稿模型，构建了参数共享的稀疏模块与密集模块：首先利用稀疏注意力快速生成 γ 个候选 token，而密集模块则利用全量 KV 缓存通过一次并行验证所有候选并额外“免费”生成一个 token，验证后的序列随后被拼接回输入进入下一轮循环。针对视觉 token 占据显存主导地位的问题，STD 设计了文本引导的视觉压缩，在预填充阶段计算文本对视觉 token 的平均注意力分数，仅保留每层或每个注意力头中分数最高的 Top-K 视觉 KV 对，通过这种动态且独立的层级筛选机制，在无需额外显存的情况下显著降低了计算开销。

### **SpecVLM**

这个名字和后边一篇创车了，作者主要来自：浙江大学、滨江实验室、香港理工大学、北京邮电大学。

论文的核心关键规律发现：投机推理中草稿模型的推测对视频 token 剪枝的敏感度较低，低比例（≤50%）随机剪枝不仅不会显著降低草稿模型的平均接受长度，甚至会因剔除冗余 Token、让模型聚焦关键信息而略有提升，这为通过 Token 剪枝优化草稿模型 KV 缓存、提升投机推理效率奠定了基础。基于此，SpecVLM 提出了一种验证器（目标模型）引导的无训练投机推理框架，其核心策略是对草稿模型的视频 Token 进行分阶段剪枝，从而大幅缩减其 KV 缓存规模，而目标模型保持完整以确保无损生成。该方法具体通过双阶段策略实施：第一阶段（语义保留）提取目标模型中语言到视频的跨层平均注意力分数，利用其长尾分布特征进行 Top-P 过滤，优先保留富含关键语义的高分 Token；第二阶段（结构保留）针对剩余注意力分数低但具备空间连续性的 Token，按固定空间间隔进行均匀保留。这种双阶段策略既通过剔除冗余让草稿模型聚焦关键信息，又保留了视频的空间结构，有效避免了随机剪枝在高比例下丢失关键语义的风险，实现了 KV 缓存的高效优化。

### **HIPPO**

作者主要来自：中国科学技术大学、上海人工智能实验室、清华大学

HIPPO 旨在解决现有剪枝方法因“位置偏差”导致的语义丢失（如过度保留无实际语义边界 token）问题，和草稿与目标模型串行执行导致的无法并行（串行依赖）等问题。

针对语义丢失，它提出了语义感知的视觉 token 保留方法，摒弃了单一的注意力分数剪枝，而是融合了全局语义相关性（通过文本-视频跨模态注意力识别与提示词相关的 token）、帧间时间冗余（通过计算相邻帧余弦相似度以保留动态变化显著的 token）以及帧内空间冗余（通过局部区域相似度方差保留空间复杂度高、信息量大的 Token）三大维度对每个视频 Token 进行综合打分，通过归一化融合后选取 Top-K token，从而有效缓解了位置偏差问题；

针对串行依赖，HIPPO 引入了视频并行推测解码算法，在同步预填充阶段利用目标模型预填充耗时远长于草稿模型的特点，使草稿模型同步进行自回归解码以生成初始候选，并在解码阶段根据上一轮验证结果在乐观解码（全被接受时让草稿模型并行生成下一批次）与保守解码（出现拒绝时先行验证首个 Token 以避免无效计算）之间自适应切换，通过打破生成与验证的串行依赖实现了计算重叠，最大化地隐藏了草稿模型的推理开销。

## 无视觉信息输入

当我第一次意识到草稿模型可以完全不依赖视觉信息的时候，我一度认为这是一种民科发现，不看就能生成新信息？其实确实是可以的，因为首先这里只是草稿模型不看，目标模型还是看过的，不是完全的空穴来风，因为其在 prefill 阶段已经处理过这些信息了。换一种更深入的表达，就是在视频大模型的深层交互中，核心视觉语义已被隐式编码至文本隐藏状态中了。草稿模型可完全复用目标模型文本侧已隐式编码视觉语义的隐藏状态，从而在规避视觉计算开销的同时获取必要的语义上下文，在这 HiViS 与 Sparrow 中都进行相应深入的探讨。

- SPD: On Speculative Decoding for Multimodal Large Language Models [arXiv 2404.08856](https://arxiv.org/pdf/2404.08856) , CVPR 2024 Workshop
- HiViS: Hiding Visual Tokens from the Drafter for Speculative Decoding in Vision-Language Models, [https://arxiv.org/pdf/2509.23928](https://arxiv.org/pdf/2509.23928)
- Sparrow: Text-Anchored Window Attention with Visual-Semantic Glimpsing for Speculative Decoding in Video LLMs, [https://arxiv.org/pdf/2602.15318](https://arxiv.org/pdf/2602.15318)

为了先打破大家对于这个 zero-shot 方法的民科嫌疑，我先把 sparrow 论文中对于视觉语义内隐化（Visual Semantic Internalization）现象进行的实验进行一些介绍。如图 3(a) 和图5所示，LLaVA-OneVision-7B 和 Qwen2.5-VL-7B 等主流的Vid-LLMs 内部的信息流，结果显示出明显的阶段性依赖：虽然在网络早期阶段显式视觉信号不可或缺，但当模型推理跨越第 20 层后，即使完全移除视觉流并仅依赖文本隐藏状态，预测性能依然保持稳健。这一结果可以证明随着网络深度的增加，视觉语义已逐渐融合并编码至文本隐藏状态中，使得原始视觉令牌在深层推理中变为了结构性冗余。

![](https://picx.zhimg.com/v2-abbde6180e04976eec252a14d005708f_r.jpg)

类似地，HiViS 通过可视化 VLM 各层隐藏状态的幅值分布（Figure 2），观察到视觉与文本令牌的表征空间未完全对齐，视觉特征的幅值和方差显著大于文本特征，但随模型层深增加，视觉特征的贡献逐步减弱，文本表征占据主导，这进一步说明目标 VLM 会将视觉语义逐步整合到语言空间的隐藏表征中。

### SPD

SPD 发布的时间比较早了，是 24 年的。作者主要来自高通。

SPD 通过从头训练一个仅 115M 参数的轻量级语言模型，成功实现了多模态模型的高效加速。

该研究设计并对比了两类草稿模型架构：一类是集成图像适配器的多模态模型，另一类是完全不处理视觉数据、仅依赖文本信息的纯语言模型。关键发现表明，纯文本草稿模型在几乎不增加计算开销的前提下，显著提升了多模态大语言模型（MLLMs）的推理效率，且在多项视觉任务上的性能与融合图像特征的多模态草稿模型持平。这一结论有力证明了在投机采样阶段，无需引入复杂的图像处理环节，仅凭轻量级文本模型即可利用上下文中的隐式信息实现多模态模型的高效推理。不过笔者认为这篇论文虽然实现了视觉隔离推理，但也因缺乏跨模态引导而导致加速收益受限。

### HiViS

作者主要来自：中国科学院自动化所、中国科学院大学、人工智能与数字经济广东省实验室（AIRIA）、香港城市大学

本文旗帜鲜明的在题目中就提出： **Hiding Visual Tokens from the Drafter** ，草稿模型是可以不给它视觉 token 的。

本文发现 VLM 的视觉 token 存在高度冗余， **核心语义在预填充阶段便已融入隐藏表示** ，且模型在后续解码过程中对原始视觉信息的注意力极低，基于这一观察，HiViS 提出了让草稿模型完全避开视觉 token 处理的方法，首先是视觉令牌隐藏与语义融合机制，即利用目标 VLM 的跨模态自注意力能力作为天然的语义融合器，提取其预填充阶段融合了视觉信息的文本特征，并与原始文本嵌入进行线性组合，生成视觉注入文本嵌入作为草稿模型的唯一输入，这一设计使草稿模型的预填充序列长度与纯文本一致，在彻底消除视觉 token 计算开销的同时确保了草稿模型能够获取完整的跨模态上下文；其次是时间步感知的残差对齐训练，针对草稿模型在自回归生成过程中无法实时同步目标模型语义更新的问题，引入了可学习的步依赖偏差校正残差，在每个解码步骤中动态修正表示偏差，并配合“两阶段训练+动态 Top-K 过滤”策略——即从第一阶段的单步预测基础训练过渡到第二阶段模拟独立解码的多步训练，辅以早停机制过滤无效样本，显著提升了训练效率与多步生成的语义一致性；最后是多损失函数联合优化，通过集成表示对齐损失、分布对齐损失以及 Top-K 排序损失，实现了草稿模型与目标模型在隐藏状态空间与 token 预测分布上的高度对齐，这种深度对齐机制弥补了轻量级草稿模型在跨模态特征处理能力上的天然短板，使其在不直接接触视觉 token 的情况下仍能精准预测目标模型的输出分布。 

![](https://pic4.zhimg.com/v2-c4f7b642f71f48dab75b37628168c151_r.jpg)

### Sparrow

本文首先立足于视觉语义内隐化这一关键发现：在视频大模型的深层交互中，核心视觉语义已被隐式编码至文本隐藏状态中，这使得深层推理阶段的原始视觉输入存在严重的结构性冗余。基于此，Sparrow 旨在通过 **将密集的视觉处理任务完全卸载至目标模型** ，使草稿模型仅依赖融合视觉语义的文本表征进行预测。

首先是基于隐藏状态复用的文本锚定窗口注意力模块。该模块通过隐藏状态复用机制，使草稿模型不再处理原始的长视觉序列，而是直接复用目标模型深层融合后的文本隐藏状态，通过投影层构建增强输入，实现对海量视觉流的高效瞥见，从物理层面完成了视觉计算卸载。配套的文本锚定窗口注意力则彻底舍弃了视觉 KV 缓存，将注意力机制严格限制在文本域内，大幅降低了计算复杂度，同时由于文本位置已承载了跨模态融合特征，确保了草稿模型在无视觉 Token 输入下仍具备精准的视觉感知能力。其次是中间层视觉状态桥接模块。 针对草稿模型难以处理低层级视觉噪声的问题，Sparrow 从目标模型中视觉-文本交互最活跃的中间层提取纯化后的视觉隐藏状态。该状态过滤了原始输入的低级冗余，同时保留了关键的细粒度细节。通过将此纯化状态与文本嵌入、目标模型隐藏状态深度融合，该模块为草稿模型构建了适配的语义初始表征，有效缓解了跨模态对齐过程中的信息失真，实现了高效的语义对齐。最后是多 Token 预测递归训练策略。 为了消除训练与推理之间的分布偏移（即暴露偏差），Sparrow 构建了递归训练流水线。在训练过程中，草稿模型被要求依赖自身生成的历史状态而非目标模型的“完美状态”进行后续预测，并持续复用高质量的视觉锚点作为参考。这种训练模式强制草稿模型在动态生成的路径中保持语义稳定性，显著提升了其在处理超长视频序列时的投机准确率与鲁棒性。 

![](https://pic1.zhimg.com/v2-81e8991ac9f99ead7525ea36bf6c9006_r.jpg)

而 HiViS 和 Sparrow 两者的差异在于：在应用领域上，HiViS 侧重于短序列任务的冗余压缩，而 Sparrow 则针对长视频场景，旨在通过视觉计算卸载来攻克超长序列中因注意力稀释引起的“视觉负增益”难题，同时解决草稿模型预训练上下文窗口与超长视频序列长度不匹配的核心矛盾，确保模型在复杂长时序背景下仍能实现精准且高效的投机预测。在训练策略上，HiViS 坚持在训练与推理全生命周期中摒弃视觉 Token 以追求极简架构，而 Sparrow 则在训练阶段保留视觉 Token 以提供必要的监督信号，仅在推理时将其掩蔽以平衡精度与速度；

## 动态适配输入

这个范式主要想解决的问题是，MLLMs 面临的输入场景及任务难度差异巨大，单一的视觉输入策略都难以在推理延迟与预测精度之间取得普适的最优平衡。因此，主张视觉输入的自适应分配与策略动态协同，通过实时评估输入特征或任务需求，动态调整视觉信息的粒度或融合多种预测分布。

这里的“任务场景”在 ibed 中主要是指输入的图像数量（单图、2 图或多图），系统会针对不同图片数量场景，通过集成多策略的概率分布适配最优处理方式；而 SpecVLM 的 “任务场景” 则聚焦于任务对图像的依赖程度 —— 即结合文本问题难度、图像与文本的相关性，动态选择剪枝、池化等不同视觉 token 压缩策略。这里并不是针对不同的数据集所定义的任务。

- In-batch Ensemble Drafting: Toward Fast and Robust Speculative Decoding for Multimodal Language Models, [openreview (iclr25, withdraw)](https://openreview.net/forum?id=8o7131Lm83#discussion) [openreview](https://openreview.net/pdf?id=ffDhpmwqdu) 应该是最后中了 workshop SCOPE ICLR 2025
- SpecVLM: Fast Speculative Decoding in Vision-Language Models, [arXiv 2509.11815](https://arxiv.org/pdf/2509.11815)

### IbED

针对不同草稿生成策略（如多模态（M）、纯文本（T）、图像池化（P）、图像描述（C））在单图与多图场景下性能差异巨大且缺乏统一最优解的挑战，IbED (In-batch Ensemble Drafting) 提出了一种动态适配输入的创新方案，深度契合动态适配输入范式核心逻辑。多模态策略虽保留完整视觉细节但在多图场景下鲁棒性不足，而纯文本策略鲁棒性强却缺乏视觉感知，单一策略无法覆盖所有正确 Token。为此，IbED 构建了自适应的批内集成机制，通过在草稿生成阶段并行执行多种策略（支持 MT、MTC、MTCP 等灵活组合），并融合其概率分布以动态适配不同视觉输入场景的需求，平衡各类策略的优势。该方法利用 MLLM 解码阶段 “内存受限而非计算受限” 的特性，让所有策略复用同一个基于 LLaMA 微调的 68M 轻量级草稿模型，通过小批量（Batch Size ≤ 4）推理在几乎零额外延迟（<0.1ms）的前提下，实现了对单图、多图等不同视觉输入场景的精准适配。这种通过等权平均概率分布进行集成的手段，有效利用了不同策略间的 Token 互补性，无需手动切换策略，即可自然适配场景差异，显著提升了在复杂多模态场景下的验证通过率与泛化能力。

![](https://pic3.zhimg.com/v2-5d86fc59ad482b8fdb87d4545b75a1ca_r.jpg)

### 
 SpecVLM

重名的另一篇 SpecVLM，作者主要来自：超威半导体公司、和西安交通大学

SpecVLM-1 同样遵循动态适配输入范式，通过深度协同设计解决了视觉 Token 过载带来的计算与内存负担。该框架首先构建了基于 EAGLE-2 架构的强基线 EagleVLM，在该基线之上，SpecVLM引入了两大核心实验创新：其一是弹性视觉压缩器 (Elastic Visual Compressor)，该组件首次集成了剪枝、池化、卷积及重采样四种压缩原语，设计了加权专家融合、多粒度特征拼接、动态专家选择三种自适应模式，还加入纯文本分支，可根据输入问题难度、图像-文本相关性动态选择或融合压缩策略，大幅减少了草稿模型预填充的计算与内存开销，降低了解码阶段的KV缓存流量。其二为在线对数蒸馏协议，该协议摒弃传统离线蒸馏的大规模数据集预计算与存储，提出实时在线蒸馏方式，训练时由目标模型实时生成token级对数和倒数第二层特征，让草稿模型对齐这些信息，并通过交叉熵损失与Smooth L1损失的联合损失进行优化，无需离线数据预处理和存储，计算效率更高，同时还发现了训练时间缩放效应，即更长的在线训练会单调提升草稿模型的平均接受长度，进一步提升推测解码效率。SpecVLM将EagleVLM、弹性视觉压缩器、在线对数蒸馏进行深度协同，推理时由目标模型特征指导压缩器选择最优策略，且让目标与草稿模型共享文本嵌入和输出头层，以此保证特征对齐，减少模型失配。
