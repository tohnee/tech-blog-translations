可以把 **Speculative Decoding（投机解码）** 理解成：

> **让一个“小模型”负责“猜”，让“大模型”负责“一次性验收很多个猜测”。**<br> 如果小模型猜得准，大模型就可以一次接受多个 token，而不是一个 token 一个 token 地生成，因此整体速度提升。

---

## 1. 传统 LLM 为什么慢？

假设我们要生成：

> 今天天气很好，适合出去散步。

大模型自回归生成通常是：

```text
输入
 ↓
大模型
 ↓
"今天"
 ↓
大模型
 ↓
"天气"
 ↓
大模型
 ↓
"很"
 ↓
大模型
 ↓
"好"
 ↓
...
```

也就是说：

**每生成 1 个 token，都要完整跑一次大模型。**

假设：

- Target Model（大模型）推理一次 = 100 ms
- 生成 10 个 token

那么粗略就是：

```text
10 × 100 ms = 1000 ms
```

问题不是大模型算得“不够快”，而是：

> **自回归生成存在严重的串行依赖。**

---

## 2. Speculative Decoding 的核心思想

增加一个小模型：

```text
┌── 小模型：负责猜
              │
输入 ─────────┤
              │
              └── 大模型：负责验证
```

例如小模型一次猜 5 个 token：

```text
小模型：

今天 → 天气 → 很 → 好 → ，
```

然后把这 5 个 token **一次性送给大模型**：

```text
┌─ 今天
              ├─ 天气
输入 ── 小模型 ┤─ 很
              ├─ 好
              └─ ，
                    ↓
                 大模型
                    ↓
              一次验证 5 个
```

假设大模型验证结果：

```text
今天 ✓
天气 ✓
很   ✓
好   ✓
，   ✗
```

那么：

```text
原来：
大模型 × 5 次

现在：
小模型生成 5 个
+
大模型验证 5 个（一次 forward）
```

于是可能从：

```text
5 次大模型 forward
```

变成：

```text
1 次小模型自回归生成
+
1 次大模型验证
```

这就是它为什么能加速。

---

## 3. 最关键的一点：为什么“大模型一次可以验证多个 token”？

这是理解 Speculative Decoding 最重要的地方。

很多人第一次接触会疑惑：

> 大模型不是只能一个 token 一个 token 预测吗？

实际上：

**训练阶段的大模型本来就是一次计算整个序列的。**

例如：

```text
我 喜欢 吃 苹果
```

Transformer 可以并行计算：

```text
位置1 → prediction
位置2 → prediction
位置3 → prediction
位置4 → prediction
```

真正限制推理速度的是 **causal mask + 已生成 token 的依赖关系**。

Speculative Decoding 利用了一个非常巧妙的事实：

> **如果前面的 token 已经被小模型猜出来，那么大模型可以把这些 token 当作已知上下文，一次性计算它们后面的概率。**

例如小模型已经猜：

```text
A B C D E
```

大模型一次 forward 可以得到：

```text
P(B | A)
P(C | A B)
P(D | A B C)
P(E | A B C D)
P(F | A B C D E)
```

注意：

这些概率在 **一次 Transformer forward** 中就可以并行计算。

所以：

```text
传统：

A
 ↓
LLM → B

A B
 ↓
LLM → C

A B C
 ↓
LLM → D

A B C D
 ↓
LLM → E
```

变成：

```text
A
 ↓
Draft Model
 ↓
A B C D E
 ↓
Target Model
 ↓
一次性验证 B C D E
```

这就是核心加速来源。

---

## 4. 一个非常直观的例子

假设目标模型每次 forward：

```text
100 ms
```

小模型每个 token：

```text
10 ms
```

我们希望生成 10 个 token。

### 普通生成

```text
10 × 100 ms
= 1000 ms
```

### Speculative Decoding

假设 draft model 每轮猜 5 个：

```text
小模型：
5 × 10 ms = 50 ms

大模型：
100 ms
```

一轮大约：

```text
150 ms
```

如果 5 个猜测平均能接受 4 个：

```text
10 token
≈ 3 次 speculative rounds
```

大约：

```text
3 × 150
= 450 ms
```

相比：

```text
1000 ms
```

理论上就获得了：

```text
≈ 2.2 ×
```

的加速。

实际速度取决于：

- draft model 大小
- draft model 速度
- acceptance rate
- batch size
- KV Cache
- GPU
- sequence length
- target model架构

所以实际可能是 **1.2×～3×甚至更高**，但并不是固定的。

## 5. 草稿模型到底是什么？

这里有一个非常重要的概念：

> **Draft Model 并不是一个“专门预测 token 的算法模块”，本质上就是一个小型语言模型。**

例如：

```text
Target Model
Llama 70B

Draft Model
Llama 1B
```

或者：

```text
Target
Qwen 72B

Draft
Qwen 0.5B / 1.5B
```

两者通常需要：

### ① tokenizer 相同

这是非常重要的。

因为 draft model 产生的 token 必须能够直接交给 target model。

例如：

```text
Draft tokenizer
      ↓
token IDs
      ↓
Target model
```

如果 tokenization 完全不同，就不能直接这么做。

---

## 6. 草稿模型需要重新训练吗？

答案是：

> **不一定。**

这是 Speculative Decoding 很有意思的地方。

大致可以分成三种方案。

---

### 方案 A：直接使用一个已有的小模型

最简单。

例如：

```text
Target:
Llama 70B

Draft:
Llama 1B
```

两个模型：

- tokenizer 相同
- vocabulary 相同
- 架构兼容

直接拿来做 speculative decoding。

这种情况下：

> **不需要重新训练。**

---

## 7. 方案 B：专门训练一个 Draft Model

这是更常见的优化方向。

目标是：

> **让小模型尽可能模仿大模型的输出分布。**

例如：

```text
Teacher
  ↓
70B Target Model
  ↓
产生 logits / tokens
  ↓
训练
  ↓
1B Draft Model
```

这其实就很像：

**Knowledge Distillation（知识蒸馏）**

训练目标可以是：

```text
P_draft(x)
      ≈
P_target(x)
```

也就是：

> 小模型尽可能学会大模型“下一步会说什么”。

---

## 8. 用什么数据训练 Draft Model？

一个很重要的结论：

> **通常不需要特殊的数据集。**

可以使用普通的：

- WebText
- Wikipedia
- Common Crawl
- instruction tuning 数据
- 对话数据
- 代码数据
- 自己业务领域的数据

但如果目标模型已经训练好了，更理想的方法是：

### 用 Target Model 生成训练信号。

例如：

```text
原始数据

"请解释一下什么是量子计算"

        ↓

Target Model

"量子计算是一种利用量子力学..."
        ↓

训练 Draft Model
```

甚至可以直接让 Target Model 提供：

```text
logits
probability distribution
hidden states
generated tokens
```

然后训练 Draft Model。

---

## 9. 更准确地说：Draft Model 的目标不是“回答得好”

这是一个特别容易误解的地方。

普通小模型训练：

> 希望模型回答正确。

Speculative Decoding 的 Draft Model：

> **希望模型尽可能预测 Target Model 会生成什么。**

这两个目标不完全一样。

例如：

```text
Target：

北京是中国的首都。
```

Draft：

```text
北京是中国的首都。
```

很好。

但如果：

```text
Target：

北京是中华人民共和国的首都。
```

Draft：

```text
北京是中国的首都。
```

虽然语义完全正确，但是：

> **Speculative Decoding 不一定能接受。**

因为 target model 的 token 概率分布不同。

所以 Draft Model 追求的是：

> **token-level agreement**

而不是单纯：

> semantic correctness。

---

## 10. 因此出现了“Speculative Distillation”

这就产生了一个非常自然的训练方法：

```text
Target Model
                   │
                   │ teacher
                   ↓
              Distillation
                   │
                   ↓
              Draft Model
                   │
                   ↓
         Speculative Decoding
```

训练过程中，让 Draft Model 尽可能逼近 Target Model。

例如 Target 输出：

```text
P("今天") = 0.72
P("现在") = 0.12
P("我们") = 0.06
...
```

Draft：

```text
P("今天") = 0.68
P("现在") = 0.15
P("我们") = 0.05
...
```

两者非常接近。

那么 Draft Model 猜中的概率就很高。

---

## 11. Acceptance Rate 才是 Speculative Decoding 的核心指标

假设：

```text
Draft 每次猜 5 tokens
```

如果：

```text
平均接受：

1 token
```

那就没什么意义。

但如果：

```text
平均接受：

4.5 tokens
```

效果就非常好。

因此 Speculative Decoding 实际优化的是：

> **Acceptance Rate / Accepted Tokens per Target Forward**

例如：

| Draft | Target | 每轮 Draft | 平均接受 | 加速潜力 |
| --- | --- | --- | --- | --- |
| 0.1B | 70B | 5 | 1.2 | 低 |
| 1B | 70B | 5 | 3.0 | 较高 |
| 7B | 70B | 5 | 4.2 | 高，但 Draft 也慢 |
| 1B | 70B | 8 | 6.5 | 很高 |

所以这里存在一个非常关键的 trade-off：

```text
Draft Model 越小
       ↓
速度越快
       ↓
但预测越不准
       ↓
Acceptance Rate ↓
```

反过来：

```text
Draft Model 越大
       ↓
预测更准
       ↓
Acceptance Rate ↑
       ↓
但 Draft 本身变慢
```

所以并不是：

> Draft Model 越小越好。

而是要找一个最优点。

## 12. 为什么不直接让大模型一次生成 5 个？

这个问题特别关键。

你可能会问：

> 既然 Transformer 可以一次算 5 个 token，那为什么大模型自己不能直接预测未来 5 个？

因为：

```text
Token 2 依赖 Token 1
Token 3 依赖 Token 2
Token 4 依赖 Token 3
...
```

所以标准自回归模型：

```text
P(x1,x2,x3,x4)
=
P(x1)
P(x2|x1)
P(x3|x1,x2)
P(x4|x1,x2,x3)
```

无法直接知道：

```text
x2、x3、x4
```

到底是什么。

而 Draft Model 做了一件事：

> **先大胆猜出来。**

然后 Target Model：

> **一次性检查这些猜测。**

这就绕开了自回归推理的主要瓶颈。

---

## 13. Speculative Decoding 的真正本质

可以把它总结成：

```text
普通生成

              Target LLM
                  ↓
                 Token
                  ↓
              Target LLM
                  ↓
                 Token
                  ↓
              Target LLM
                  ↓
                 Token

                 Speculative

               Draft LLM
                   ↓
          ┌── A B C D E ──┐
          │               │
          ↓               ↓
                   Target LLM
                        ↓
                一次验证 A~E
                        ↓
                 接受 A B C D
                        ↓
                 继续生成
```

所以：

> **Speculative Decoding 并没有降低大模型计算量，而是减少了“大模型必须进行多少次串行 forward”。**

这是最核心的一句话。

---

## 14. 后来还有一个非常重要的方向：无独立 Draft Model

这也是 2024–2026 年 Speculative Decoding 很重要的发展方向。

因为大家发现：

> **训练/部署一个独立 Draft Model 其实也挺麻烦。**

于是出现了：

### Self-Speculative Decoding

让：

> **Target Model 自己给自己做 Draft。**

例如：

```text
一个 70B 模型

浅层：
Layer 1~20
    ↓
Draft

深层：
Layer 1~80
    ↓
Verification
```

或者：

```text
Early Exit
```

让模型中间层快速预测：

```text
Draft
  ↓
完整模型
  ↓
Verify
```

这样：

```text
不需要额外的 1B 模型
```

## 15. 还有一个更适合 TTS 的方向

结合你最近关注的 **TTS 加速**，Speculative Decoding 在 TTS 中尤其值得关注。

例如：

```text
Text
 ↓
Semantic / Acoustic Token LM
 ↓
Token 1
 ↓
Token 2
 ↓
Token 3
...
```

如果 TTS 是：

```text
autoregressive acoustic token generation
```

那么完全可以：

```text
Draft TTS
                 ↓
        acoustic tokens
        [a1 a2 a3 a4 a5]
                 ↓
             Target TTS
                 ↓
           parallel verify
```

例如：

```text
Target：
1 token / step

Speculative：
5 tokens / step
```

如果平均接受：

```text
4 tokens
```

理论上就可以把：

```text
100 autoregressive steps
```

降低到大约：

```text
25 target verification steps
```

这也是为什么你前面关注的 **F5-TTS、CosyVoice、Qwen3-TTS、MOSS-TTS 等模型的加速**，需要首先判断一个问题：

> **它的核心生成过程是不是存在明显的 autoregressive token-by-token bottleneck？**

如果是，那么 Speculative Decoding / Multi-Token Prediction / Distillation 就非常值得研究。

## 16. 最后用一张表总结

| 问题 | 答案 |
| --- | --- |
| Speculative Decoding 是什么？ | 小模型猜，大模型批量验证 |
| 为什么能加速？ | 减少 Target Model 串行 forward 次数 |
| 大模型是不是少算了？ | 不一定，主要是少了串行调用 |
| Draft Model 是什么？ | 一个小型语言模型 |
| 一定要重新训练吗？ | 不一定 |
| 可以直接拿现成小模型吗？ | 可以，但 tokenizer/架构兼容很重要 |
| 最理想怎么获得？ | 对 Target Model 做蒸馏/专门训练 |
| 用什么数据？ | 普通预训练/指令/领域数据都可以 |
| 最重要的训练目标？ | 模仿 Target Model 的 token 分布 |
| 最重要的效果指标？ | Acceptance Rate / Accepted Tokens per Step |
| Draft 越小越好吗？ | 不一定，存在速度与准确率 trade-off |
| 可以没有 Draft Model 吗？ | 可以，Self-Speculative / Early Exit 等 |
| TTS 能用吗？ | 非常适合 AR acoustic/semantic token generation |

**一句话理解：**

> **Speculative Decoding = 用便宜的小模型把未来几个 token “提前猜出来”，再让昂贵的大模型一次性批改这些答案；只要小模型猜得足够准，就能把“大模型逐 token 串行生成”变成“大模型少量批次验证”。**
