周五的时候才写文章说 DeepSeek 上次的故障可能是为了新模型做测试，没想到大的真的来了！

昨天也就是 10 月 17 日，DeepSeek-v4.1-flash 模型推出了新版本！后缀是象征发布日期的 1017。

官方表示和上一个版本 0731 相比，新模型在 **各方面** 的测试当中都有了 **长足** 的进步。

那么这个长足的进步究竟有多长足呢？

长到能和 opus-5 掰手腕的程度！下面来看官方的评测数据。

![](https://pica.zhimg.com/v2-a23c525abd71f2a9d60519ec94ee7796_r.jpg)

我们可以看到在 DeepSWE、Automation-Bench V1.0.6、Agent's Last Exam、Apex Bench v1.1、Chartography 等多项测试中，指标超过了 claude-opus-5。

我特意问了一下 AI，这五项指标分别指的是： **长时间、原创的软件工程能力、跨应用业务流程自动化、极端困难、高经济价值的专家级任务、专业服务领域的深度工作能力、专业级图表理解能力** 。

相比于传统的考察模型知识全面性和记忆力的指标，这些指标更加侧重实战和应用。基本上也是模型智力的最直观体现，没有之一。

官方非常不谦虚地表示：

> 在提升性能的同时，我们还缩短了模型的任务运行时间与输出长度，让用户能够以更低成本、更快速度完成任务（如下图所示），在多个 Harness 下达到了新的性能-费用帕累托最优。

“费用帕累托最优”可以简单理解成在单位成本最优，简单来说，就是无敌性价比。

官方同样也贴了一张性价比展示图。 **横轴是成本，纵轴是性能** 。越靠近左上角，说明性价比越高，反之越靠近右下角，说明性价比越低。

![](https://pic4.zhimg.com/v2-8cf5ad68cfafa38ba6a661e878cd33d1_r.jpg)

低价性价比的模型有哪些呢，好难猜啊。

就在 DeepSeek 新版引起广泛关注的时候，无人在意的角落，openai 再次送出了额度重置……

![](https://pic1.zhimg.com/v2-01a31449b9e57a0496b0407efcdd8876_r.jpg)

但是很遗憾，在 DeepSeek 新模型如此价格面前，小甜甜也只能变回牛夫人了。

## 实战开发

不过看到这里，相信很多朋友还是有些困惑的。

参数每个厂商都会列，可是往往模型实际的表现能力并不一定完全符合参数。

这次的新模型，我打算实战一个需求，来实际体验一下它的聪明程度以及对应的 token 开销。

我选择的任务是 **鹈鹕测试** 。

鹈鹕测试，就是让模型生成一个鹈鹕骑车的动态网页。通过最终模型生成的效果来反推模型对任务理解、开发和调试的能力。

![](https://picx.zhimg.com/v2-2297dde52e4c1123d85a44d5b629c2b1_1440w.jpg)

不过这一次我们不只是让模型来简单进行一下鹈鹕测试，而是让它在 kimiseek 里增加一个在线鹈鹕测试的功能，让每个人都能测试自己的 llm 渠道。

这次选择的开发环境是 DeepSeek Harness + DeepSeek-v4.1-flash-1017.

我之前用过 DeepSeek Harness + 各种国模，对 Claude code 和 Codex 的开发体验也非常熟悉。因此在这次开发的过程当中，有一些点感受非常明显。

### 交互更好了

这是我的提示词：

> 我想要在本站当中新增一个鹈鹕测试的功能，用来测试 llm 的智商。 
>  简单来说实现一个 agent，能够使用用户填写 llm 的配置信息（baseurl， apikey），调用编程和调试功能，生成鹈鹕骑车的网页，在线显示效果给用户。

输完提示词之后，我马上就感觉到了和从前不一样。

因为 **它主动问了我三个问题** 。

之前版本的 DeepSeek 似乎不太会问问题，GPT-6-astra 问题也很少，经常需要我手动打断纠正，印象里只有 Claude 连续问过两个以上的问题。

某种程度上来说问题多其实是模型有思考有智商的体现， **明明提示词写得很简短，模型啥也不问上来就干活是很恐怖的** 。

除非你一直盯着执行结果，否则谁也无法保证中间哪个环节会跑偏。

### 性价比之王

第一个版本，一共用了 37 分钟。

消耗了 26M 的 token。

![](https://pica.zhimg.com/v2-616b702dc02e0affe1c0134fcaed6774_r.jpg)

我登上账号一看，这么一个中等规模的任务，居然只花了两块五！

![](https://pic4.zhimg.com/v2-a3bc8b0d6e676101e998dc9106b96ba3_r.jpg)

代码质量非常高，第一个版本就完整实现了功能，没有任何运行 bug。

并且我的提示词里是没有任何关于前端页面设计的内容的， **它不仅知道要参考之前的页面风格，而且参考得非常好** 。

我之前的前端代码都是 GPT-6-astra 写的，现在 DeepSeek 新增的页面，完全看不出来出自两个不同的模型。

就凭这一点就让我相信，这一版的 DeepSeek 无论是研发能力，还是前端设计能力都远超从前。

![](https://pic4.zhimg.com/v2-d8fc2a92a717f99719f078faf1e5c5b3_r.jpg)

功能上，我只经过了两轮调试，就得到了满意的结果。

此时 token 的总开销是 5 块。

![](https://pic2.zhimg.com/v2-dda5b1f3719f85a8ea4951f0022faf9f_r.jpg)

此时代码生成量已经来到了 5 千行，平均一千行代码一块钱。

![](https://picx.zhimg.com/v2-bffb9b137f5bc25019104ee5801abb63_r.jpg)

换成 Claude 我随便做点 code review，都能用掉好几十刀，在 DeepSeek 的衬托下，Claude 性价比已经趋近于 0。

### 代码质量

当然代码质量不能只看前端表现，后端看不见的后端逻辑也非常重要。

关于这点，我给出的答案是： **它已经接近 GPT-6-astra 了** 。

测试一个模型代码能力和质量的最好方法，就是 **让另外一个旗舰模型来做 review** ，给出参考意见。

通过另外一个模型的描述，以及两者之间交互的过程，我们大致能够看得出来模型的能力高低。

模型越聪明，能 review 出的 bug 就越少，反之 bug 和缺陷越多，说明模型越“笨”。

这次我选择来当裁判的模型是 GPT-6-astra， **思考预算极高** 。

GPT-6-astra 给它的表现打分是 7.5-8 分。

我让 gpt-6 做了严格的 code review，确实发现了一些隐患和潜在问题，但完全没有功能 bug 。

进行了三四轮「修复-review-再修复-再 review」的循环之后，就再也挑不出问题了。
