### Triton 编程模型

![](https://pic3.zhimg.com/v2-9d1b2b31c1430a27da772c53132de1dc_r.jpg)

在编程模型的角度上来看，Triton的是SPMD (Single Program, Multiple Data) 编程模型，CUDA是SIMT (Single Instruction, Multiple Threads) ，具体如上图所示。

CUDA每一个Thread就取几个scalar进行操作，正如我之前写的Parallel Scan（[https://zhuanlan.zhihu.com/p/13819855451](https://zhuanlan.zhihu.com/p/13819855451)），单个Thread内，单次运算，就是scalar运算，也许有一个循环范围取值，但是每次就是取的单个数值。

而对于Triton来说，则是一次对一个小的矩阵组进行操作，每次计算都是一批小矩阵乘法。

### Matrix Multiplication

### Code Snap

```python
@triton.autotune(
    configs=get_autotune_config(),
    key=['M', 'N', 'K'],
)
@triton.jit
def matmul_kernel(
        # Pointers to matrices
        a_ptr, b_ptr, c_ptr,
        # Matrix dimensions
        M, N, K,
        # The stride variables represent how much to increase the ptr by when moving by 1
        # element in a particular dimension. E.g. `stride_am` is how much to increase `a_ptr`
        # by to get the element one row down (A has M rows).
        stride_am, stride_ak,  #
        stride_bk, stride_bn,  #
        stride_cm, stride_cn,
        # Meta-parameters
        BLOCK_SIZE_M: tl.constexpr, BLOCK_SIZE_N: tl.constexpr, BLOCK_SIZE_K: tl.constexpr,  #
        GROUP_SIZE_M: tl.constexpr,  #
        ACTIVATION: tl.constexpr  #
):
    """Kernel for computing the matmul C = A x B.
    A has shape (M, K), B has shape (K, N) and C has shape (M, N)
    """
    # -----------------------------------------------------------
    # Map program ids `pid` to the block of C it should compute.
    # This is done in a grouped ordering to promote L2 data reuse.
    # See above `L2 Cache Optimizations` section for details.
    pid = tl.program_id(axis=0)
    num_pid_m = tl.cdiv(M, BLOCK_SIZE_M)
    num_pid_n = tl.cdiv(N, BLOCK_SIZE_N)
    num_pid_in_group = GROUP_SIZE_M * num_pid_n
    group_id = pid // num_pid_in_group
    first_pid_m = group_id * GROUP_SIZE_M
    group_size_m = min(num_pid_m - first_pid_m, GROUP_SIZE_M)
    pid_m = first_pid_m + ((pid % num_pid_in_group) % group_size_m)
    pid_n = (pid % num_pid_in_group) // group_size_m

    # ----------------------------------------------------------
    # Create pointers for the first blocks of A and B.
    # We will advance this pointer as we move in the K direction
    # and accumulate
    # `a_ptrs` is a block of [BLOCK_SIZE_M, BLOCK_SIZE_K] pointers
    # `b_ptrs` is a block of [BLOCK_SIZE_K, BLOCK_SIZE_N] pointers
    # See above `Pointer Arithmetic` section for details
    offs_am = (pid_m * BLOCK_SIZE_M + tl.arange(0, BLOCK_SIZE_M)) % M
    offs_bn = (pid_n * BLOCK_SIZE_N + tl.arange(0, BLOCK_SIZE_N)) % N
    offs_k = tl.arange(0, BLOCK_SIZE_K)
    a_ptrs = a_ptr + (offs_am[:, None] * stride_am + offs_k[None, :] * stride_ak)
    b_ptrs = b_ptr + (offs_k[:, None] * stride_bk + offs_bn[None, :] * stride_bn)

    # -----------------------------------------------------------
    # Iterate to compute a block of the C matrix.
    # We accumulate into a `[BLOCK_SIZE_M, BLOCK_SIZE_N]` block
    # of fp32 values for higher accuracy.
    # `accumulator` will be converted back to fp16 after the loop.
    accumulator = tl.zeros((BLOCK_SIZE_M, BLOCK_SIZE_N), dtype=tl.float32)
    for k in range(0, tl.cdiv(K, BLOCK_SIZE_K)):
        # Load the next block of A and B, generate a mask by checking the K dimension.
        # If it is out of bounds, set it to 0.
        a = tl.load(a_ptrs, mask=offs_k[None, :] < K - k * BLOCK_SIZE_K, other=0.0)
        b = tl.load(b_ptrs, mask=offs_k[:, None] < K - k * BLOCK_SIZE_K, other=0.0)
        # We accumulate along the K dimension.
        accumulator = tl.dot(a, b, accumulator)
        # Advance the ptrs to the next K block.
        a_ptrs += BLOCK_SIZE_K * stride_ak
        b_ptrs += BLOCK_SIZE_K * stride_bk
    # You can fuse arbitrary activation functions here
    # while the accumulator is still in FP32!
    if ACTIVATION == "leaky_relu":
        accumulator = leaky_relu(accumulator)
    c = accumulator.to(tl.float16)

    # -----------------------------------------------------------
    # Write back the block of the output matrix C with masks.
    offs_cm = pid_m * BLOCK_SIZE_M + tl.arange(0, BLOCK_SIZE_M)
    offs_cn = pid_n * BLOCK_SIZE_N + tl.arange(0, BLOCK_SIZE_N)
    c_ptrs = c_ptr + stride_cm * offs_cm[:, None] + stride_cn * offs_cn[None, :]
    c_mask = (offs_cm[:, None] < M) & (offs_cn[None, :] < N)
    tl.store(c_ptrs, c, mask=c_mask)
```

### Pseudo Code

首先给出如下伪码（Python 风格）。

```python
# Do in parallel
for m in range(0, M, BLOCK_SIZE_M):
   # Do in parallel
   for n in range(0, N, BLOCK_SIZE_N):
       acc = zeros((BLOCK_SIZE_M, BLOCK_SIZE_N), dtype=float32)
       for k in range(0, K, BLOCK_SIZE_K):
           a = A[m : m+BLOCK_SIZE_M, k : k+BLOCK_SIZE_K]
           b = B[k : k+BLOCK_SIZE_K, n : n+BLOCK_SIZE_N]
           acc += dot(a, b)
       C[m : m+BLOCK_SIZE_M, n : n+BLOCK_SIZE_N] = acc
```

上述矩阵乘法符合下述形式： $ A \in \mathbb{R}^{M \times K}, B \in \mathbb{R}^{K \times N}, C \in \mathbb{R}^{M \times N} \\ C = AB $ 在外部设定BLOCK_SIZE_M，BLOCK_SIZE_N，BLOCK_SIZE_K。在函数内部，每步运算中 A仅取BLOCK_SIZE_M大小的块，B仅取BLOCK_SIZE_N大小的块，计算出一个BLOCK_SIZE_M x BLOCK_SIZE_N大小的子块。

子块本身的计算也要分块，每一步仅用BLOCK_SIZE_K长度的子矩阵进行计算。

### PID构建

示例中基于下述方式进行指针构建

```python
pid = tl.program_id(axis=0)
num_pid_m = tl.cdiv(M, BLOCK_SIZE_M)
num_pid_n = tl.cdiv(N, BLOCK_SIZE_N)
num_pid_in_group = GROUP_SIZE_M * num_pid_n
group_id = pid // num_pid_in_group
first_pid_m = group_id * GROUP_SIZE_M
group_size_m = min(num_pid_m - first_pid_m, GROUP_SIZE_M)
pid_m = first_pid_m + ((pid % num_pid_in_group) % group_size_m)
pid_n = (pid % num_pid_in_group) // group_size_m
```

首先给出pid (program id)，总共m的pid数量num_pid_m是`tl.cdiv(M, BLOCK_SIZE_M)`这个函数的意思是向上取整，整除的时候无所谓，但是如果不整除则需要向上多方一个block，做一些padding来保证并行。num_pid_n的原理则同理于num_pid_m。

这里出现了之前没有提到的group的概念，以下图为例，若GroupSize = 8，则包含8个Block，每个Block又包含若干个row。

**据佬 [@浪子不回头](https://www.zhihu.com/people/2dc63e562535fa4ad50fee75f06110bf) 提醒，我在这里声明一下，以免造成混淆。下图为了方便我没有将GROUP_SIZE设置为8，而是4。**

![](https://pic3.zhimg.com/v2-5a0f9b7b164cc62658f091e4dfb56108_r.jpg)

**那为何计算group中的pid是如下这样计算呢？**

```python
num_pid_in_group = GROUP_SIZE_M * num_pid_n
```

实际原因如上图所示，按照官方给出的示例，我们仅在左矩阵分组，一个Group内就是n个块，按照上图，就是4个块，而右矩阵不分组，所以是所有的num_pid_n。两者再度构成矩阵，矩阵元素量正好就是`GROUP_SIZE_M * num_pid_n`。

随后Group_id正好就是当前pid整除组内pid数量：

```python
group_id = pid // num_pid_in_group
```

因此此时首位pid就如下：

```python
first_pid_m = group_id * GROUP_SIZE_M
```

随后选择当前的group_size_m：

```python
group_size_m = min(num_pid_m - first_pid_m, GROUP_SIZE_M)
```

选择其中较小的作为选用的group_size，实现padding操作。

最后，选取当前两个矩阵分别的pid如下：

```python
pid_m = first_pid_m + ((pid % num_pid_in_group) % group_size_m)
pid_n = (pid % num_pid_in_group) // group_size_m
```

其中pid_m的解释如下：

- **`pid % num_pid_in_group`**： 计算当前程序在组内的局部 ID。因为 `num_pid_in_group` 是每个组的程序块总数，取模运算可以得到当前程序在组内的相对位置。
- **`(pid % num_pid_in_group) % group_size_m`**： 进一步计算当前程序在 `M` 方向上的局部偏移。`group_size_m` 是当前group在 `M` 方向上的实际程序块数量，取模运算可以确保偏移量在 `group_size_m` 范围内。
- **`first_pid_m + ...`**： 将局部偏移加上当前组的第一个 `M` 方向程序块 ID，得到当前程序在全局 `M` 方向上的索引。

pid_n则如下：

- **`pid % num_pid_in_group`**： 计算当前程序在组内的局部 ID，与 `pid_m` 的计算相同。
- **`(pid % num_pid_in_group) // group_size_m`**： 将局部 ID 除以 `group_size_m`，得到当前程序在 `N` 方向上的局部索引。因为每个组在 `M` 方向上有 `group_size_m` 个程序块，所以除法运算可以得到 `N` 方向的偏移。

### 为何分组？优化L2 Cache访存！

将pid映射到它应计算的C代码。这是通过分组排序来完成的，以促进L2缓存的数据重用。

下面直接用DeepSeek翻译Triton官方教程，原文地址如下：

[https://triton-lang.org/main/getting-started/tutorials/03-matrix-multiplication.html#sphx-glr-getting-started-tutorials-03-matrix-multiplication-py](https://triton-lang.org/main/getting-started/tutorials/03-matrix-multiplication.html#sphx-glr-getting-started-tutorials-03-matrix-multiplication-py)

如上所述，每个程序实例会计算一个大小为 `[BLOCK_SIZE_M, BLOCK_SIZE_N]` 的 C 矩阵块。需要特别注意的是，这些块的计算顺序确实非常重要，因为它会直接影响我们程序的 L2 缓存命中率。遗憾的是，仅仅采用简单的行主序排列（row-major ordering）是远远不够的。

```python
pid = tl.program_id(axis=0)
grid_n = tl.cdiv(N, BLOCK_SIZE_N)
pid_m = pid // grid_n
pid_n = pid % grid_n
```

一种可能的解决方案是以一种能够促进数据重用的顺序来启动块。这可以通过在切换到下一列之前，将块按 `GROUP_M` 行进行“超分组”来实现 (这一段和我上面分析的一样)：

```python
# 程序 ID
pid = tl.program_id(axis=0)
# 沿 M 轴的程序 ID 数量
num_pid_m = tl.cdiv(M, BLOCK_SIZE_M)
# 沿 N 轴的程序 ID 数量
num_pid_n = tl.cdiv(N, BLOCK_SIZE_N)
# 每组中的程序数量
num_pid_in_group = GROUP_SIZE_M * num_pid_n
# 当前程序所在的组 ID
group_id = pid // num_pid_in_group
# 组中第一个程序的行 ID
first_pid_m = group_id * GROUP_SIZE_M
# 如果 `num_pid_m` 不能被 `GROUP_SIZE_M` 整除，最后一组会较小
group_size_m = min(num_pid_m - first_pid_m, GROUP_SIZE_M)
# *在组内*，程序按列主序排列
# 程序在 *启动网格* 中的行 ID
pid_m = first_pid_m + ((pid % num_pid_in_group) % group_size_m)
# 程序在 *启动网格* 中的列 ID
pid_n = (pid % num_pid_in_group) // group_size_m
```

例如，在下面的矩阵乘法中，每个矩阵由 9 个块乘以 9 个块组成。我们可以看到，如果按行主序（row-major ordering）计算输出，则需要将 90 个块加载到 SRAM 中以计算前 9 个输出块；但如果采用分组排序（grouped ordering），则只需加载 54 个块。

![](https://pic4.zhimg.com/v2-2c641afc8e0c76d989bb50afd6b94839_r.jpg)

在实际应用中，这种优化可以在某些硬件架构上将矩阵乘法核的性能提升超过 10%（例如，在 A100 上从 220 TFLOPS 提升到 245 TFLOPS）。

**我有一些问题**，就是这里他给的图中示例想要表明的是，同样的计算结果数量（9个），用group方法可以减少存取MAC，但是实际他写的代码里没有给B做分组，也许是我理解错了。

### 取值

无论是在torch中的数据存储方式，还是基于torch的Triton取值方式，不管前端设置为任何维度，后端都是顺序模式一维存储的。在PyTorch中，一个张量tensor的实例分为头信息区（Tensor）和存储区（Storage）；信息区主要保存着tensor的形状（size）、步长（stride）、数据类型（type）等信息。而真正的数据也保存成了连续的**一维数组**，存储在存储区。

行主序的数组取值，以二维数组X为例:

```python
&X[i, j] = X + i * stride_i + j * stride_j
```

对于先前例子中的矩阵情况，若类似CUDA中的取值风格，以A为例，仅取首位、末位元素，取值方式如下：

```python
&A[m, k] = a_ptr + m * A.stride(0) + k * A.stride(1); 

&A[m + BLOCK_SIZE_M, k + BLOCK_SIZE_K] = a_ptr + (m + BLOCK_SIZE_M) * A.stride(0) + (k + BLOCK_SIZE_K) * A.stride(1);
```

而以Triton的取值风格，以A和B为例，取值方式如下：

```python
&A[m : m + BLOCK_SIZE_M, k : k + BLOCK_SIZE_K] = a_ptr + (m : m + BLOCK_SIZE_M)[:, None] * A.stride(0) + (k : k + BLOCK_SIZE_K)[None, :] * A.stride(1); 

&B[k : k + BLOCK_SIZE_K, n : n + BLOCK_SIZE_N] = b_ptr + (k : k + BLOCK_SIZE_K)[:, None] * B.stride(0) + (n : n + BLOCK_SIZE_N)[None, :] * B.stride(1);
```

实际代码如下：

```python
offs_am = (pid_m * BLOCK_SIZE_M + tl.arange(0, BLOCK_SIZE_M)) % M
offs_bn = (pid_n * BLOCK_SIZE_N + tl.arange(0, BLOCK_SIZE_N)) % N
offs_k = tl.arange(0, BLOCK_SIZE_K)
a_ptrs = a_ptr + (offs_am[:, None] * stride_am + offs_k[None, :] * stride_ak)
b_ptrs = b_ptr + (offs_k[:, None] * stride_bk + offs_bn[None, :] * stride_bn)
```

此处的关键点在于tl.arange()，其生成方式和numpy中的arrange一样，给定一个范围，给出一个既定数值范围内的步长为一的离散序列。

如下：

```text
tensor([0, 1, 2, 3, ..., BLOCK_SIZE_M - 1])
```

```python
def matmul(a, b, activation=""):
    # Check constraints.
    assert a.shape[1] == b.shape[0], "Incompatible dimensions"
    assert a.is_contiguous(), "Matrix A must be contiguous"
    M, K = a.shape
    K, N = b.shape
    # Allocates output.
    c = torch.empty((M, N), device=a.device, dtype=torch.float16)
    # 1D launch kernel where each block gets its own program.
    grid = lambda META: (triton.cdiv(M, META['BLOCK_SIZE_M']) * triton.cdiv(N, META['BLOCK_SIZE_N']), )
    matmul_kernel[grid](
        a, b, c,  # [512, 512], [512, 512], [512, 512]
        M, N, K,  # 512, 512, 512
        a.stride(0), a.stride(1),  # (512, 1)
        b.stride(0), b.stride(1),  # (512, 1)
        c.stride(0), c.stride(1),  # (512, 1)
        ACTIVATION=activation  # ''
    )
    return c
```

### 什么是stride?

stride就是步长，因为向量是单维存储的，高纬数组需要和CUDA一样用复杂的取值计算取值，和此处照应之前的指针取值部分。

比如一个 8 x 128 x 128的矩阵：

0维步长就是8，1维步长就是128，2维步长则为1。

三维数组，0维是面，1维是行，2维则是点，总体是一个立方体。

那么过一个面需要8步，一行需要128步，点则是1步。

### 回到取值

```python
offs_am = (pid_m * BLOCK_SIZE_M + tl.arange(0, BLOCK_SIZE_M)) % M
offs_bn = (pid_n * BLOCK_SIZE_N + tl.arange(0, BLOCK_SIZE_N)) % N
offs_k = tl.arange(0, BLOCK_SIZE_K)
a_ptrs = a_ptr + (offs_am[:, None] * stride_am + offs_k[None, :] * stride_ak)
b_ptrs = b_ptr + (offs_k[:, None] * stride_bk + offs_bn[None, :] * stride_bn)
```

为了方便参考，我还是把调用放在下面。

```python
matmul_kernel[grid](
    a, b, c,  # [512, 512], [512, 512], [512, 512]
    M, N, K,  # 512, 512, 512
    a.stride(0), a.stride(1),  # (stride_am, stride_ak) = (512, 1)
    b.stride(0), b.stride(1),  # (stride_bk, stride_bn) = (512, 1)
    c.stride(0), c.stride(1),  # (stride_cm, stride_cn) = (512, 1)
    ACTIVATION=activation  # ''
)
```

首先对于基本的offset取值：

```python
offs_am = (pid_m * BLOCK_SIZE_M + tl.arange(0, BLOCK_SIZE_M)) % M
offs_bn = (pid_n * BLOCK_SIZE_N + tl.arange(0, BLOCK_SIZE_N)) % N
```

可见形式如下：

```text
offs_am.shape = [constexpr[128]]
offs_bn.shape = [constexpr[256]]
```

给定的pid_m/n按步长扩展，作为偏置项。为了防止超出，对完整长度取了模。

随后是k的偏置向量：

```python
offs_k = tl.arange(0, BLOCK_SIZE_K)
```

形式如下：

```text
offs_k.shape = [constexpr[64]]
```

利用外部给出的stride分别扩张offsets，

```python
a_ptrs = a_ptr + (offs_am[:, None] * stride_am + offs_k[None, :] * stride_ak)
b_ptrs = b_ptr + (offs_k[:, None] * stride_bk + offs_bn[None, :] * stride_bn)
```

a_ptr和b_ptr就是两个矩阵（的首地址），而a_ptrs和b_ptrs就是取出的用于计算的子块。

形状如下：

```text
(offs_am[:, None] * stride_am).shape = [constexpr[128], constexpr[1]]
(offs_k[None, :] * stride_ak).shape = [constexpr[1], constexpr[64]]
a_ptr = array([128839616], dtype=uint64)

a_ptrs.shape = [constexpr[128], constexpr[64]]
```

基于广播机制输出了一个块矩阵a_ptrs。

```text
b_ptrs.shape = [constexpr[64], constexpr[256]]
```

### Kernel Core

```python
accumulator = tl.zeros((BLOCK_SIZE_M, BLOCK_SIZE_N), dtype=tl.float32)
for k in range(0, tl.cdiv(K, BLOCK_SIZE_K)):
    # Load the next block of A and B, generate a mask by checking the K dimension.
    # If it is out of bounds, set it to 0.
    a = tl.load(a_ptrs, mask=offs_k[None, :] < K - k * BLOCK_SIZE_K, other=0.0)
    b = tl.load(b_ptrs, mask=offs_k[:, None] < K - k * BLOCK_SIZE_K, other=0.0)
    # We accumulate along the K dimension.
    accumulator = tl.dot(a, b, accumulator)
    # Advance the ptrs to the next K block.
    a_ptrs += BLOCK_SIZE_K * stride_ak
    b_ptrs += BLOCK_SIZE_K * stride_bk
```

按k维度分块串行运算，此时BLOCK_SIZE_K = 64，总共分8块。

然后load矩阵：

```python
a = tl.load(a_ptrs, mask=offs_k[None, :] < K - k * BLOCK_SIZE_K, other=0.0)
b = tl.load(b_ptrs, mask=offs_k[:, None] < K - k * BLOCK_SIZE_K, other=0.0)
```

其中`offs_k[None, :] < K - k * BLOCK_SIZE_K`构造掩码矩阵保证不会越界。

此时分别的大小如下：

```python
a.shape = [constexpr[128], constexpr[64]]
b.shape = [constexpr[64], constexpr[256]]
accumulator.shape = [constexpr[128], constexpr[256]]
```

计算完成之后，a_ptrs和b_ptrs按照给定步长向前推进一步。

计算完成后，局部存储到原始矩阵对应地址处，这里就不赘述了，之前都讲过了。

```python
offs_cm = pid_m * BLOCK_SIZE_M + tl.arange(0, BLOCK_SIZE_M)
offs_cn = pid_n * BLOCK_SIZE_N + tl.arange(0, BLOCK_SIZE_N)
c_ptrs = c_ptr + stride_cm * offs_cm[:, None] + stride_cn * offs_cn[None, :]
c_mask = (offs_cm[:, None] < M) & (offs_cn[None, :] < N)
tl.store(c_ptrs, c, mask=c_mask)
```

### Triton Debug

首先需要定义os.environ['TRITON_INTERPRET'] = '1'，其次需要在"cpu"上计算时才能debug。

可以把代码入口定义argument parsing，在vs code的launch.json中写--debug，然后在代码内部自动引入，然后自动将所有数据detach到cpu。

这样就可以保证用debug模式的时候都在cpu运行，实际运行用cuda设备。
