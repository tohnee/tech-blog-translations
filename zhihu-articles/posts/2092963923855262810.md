训练模型时，大家可能都遇到过显存不足的问题：模型参数能够放进显存，但训练启动后，梯度、优化器状态和中间激活带来的额外开销就可能导致显存溢出（Out of Memory，OOM）。随着大模型训练向更大的模型规模、更大的 batch size 和更长的输入序列，训练所需的显存也持续增长，进一步加剧了显存容量与训练需求之间的矛盾。

## 一、为什么需要系统梳理 GPU 显存优化？

目前，针对 DNN 训练显存瓶颈，已有研究提出了多种优化技术（下文进行分析）。这些技术的实际效果与模型结构、训练配置、硬件特征密切相关：同一种方法在不同场景下，可能带来不同的显存收益，以及计算、通信或精度方面的代价。因此，**如何根据具体训练需求选择合适的显存优化技术，成为训练系统设计中的一个重要问题**。

基于此，我们希望通过这篇综述，**对现有技术进行系统分类，梳理各类方法的核心机制、优势与局限，以及适用的模型、工作负载和硬件条件，帮助训练系统的设计与搭建者快速定位适合目标场景的技术，并理解不同方法组合使用时的取舍**。

此外，综述结合上层模型的演进与底层硬件架构的发展，**讨论这一领域未来的研究趋势，分析新型模型结构、内存层级和互连架构为显存优化带来的挑战与机会**。

## 二、综述的组织方式：技术类别—核心挑战—解决思路

我们将 GPU 显存优化方法划分为五类：

1. **数据卸载（Data Offloading）**
2. **激活重计算（Activation Recomputation）**
3. **数据压缩（Data Compression）**
4. **分布式 GPU 显存优化（Distributed GPU Memory Optimization）**
5. **其他优化（Other Optimizations）**

## 三、数据卸载：如何利用 CPU 内存和 SSD，同时降低搬运开销？

数据卸载的基本思路是，将暂时不需要的数据移出 GPU，存放到 CPU 内存或 SSD 等容量更大的存储层级中，等到需要时再传回 GPU。

![](https://pic3.zhimg.com/v2-94443348fa1e2507fd3fc26f2a9d2434_r.jpg)
*GPU内数据卸载示意图*

这一方向的核心挑战是**数据迁移开销**。如果数据没有及时传回，GPU 就需要等待；如果迁移过于频繁，节省显存的同时也可能明显拖慢训练。

围绕这一问题，综述将现有工作归纳为四个角度。

**第一，隐藏迁移延迟。** 利用张量的使用时机，提前预取数据，并将传输与 GPU 计算重叠。这里需要判断哪些数据可以移出、何时需要传回，以及是否存在足够的时间窗口完成迁移。

**第二，CPU–GPU 混合执行。** 一些方法进一步让 CPU 承担部分训练计算，例如优化器更新，以减少相关数据的往返搬运。这要求系统同时考虑 CPU 计算能力、互连带宽和 GPU 执行节奏。

**第三，联合其他显存优化。** 将卸载与重计算、压缩等方法结合，根据张量的大小、生命周期、迁移成本和重计算成本决定处理方式。不同张量适合不同策略，因此联合决策成为一个重要研究问题。

**第四，优化数据路径。** 面向 GPU、CPU 内存和 SSD 构成的存储层级，改进传输路径、缓冲和调度，减少数据搬运过程中的额外成本。

## 四、激活重计算：如何节省激活显存，并控制额外计算？

反向传播需要使用前向传播中的部分中间激活。激活重计算通过减少这些激活的保存量，在反向传播需要时重新执行相应计算，从而降低显存占用。

![](https://pic1.zhimg.com/v2-d124240316760774f3855392db133a98_r.jpg)
*重计算示意图与重计算带来的计算与存储的影响*

这一方向主要有两个问题：**如何控制重计算开销，以及如何高效找到合适的重计算策略。**

针对计算开销，已有工作主要从两个角度展开。

一是**自适应重计算**。根据显存预算、模型结构、流水线阶段和运行状态，选择需要保留或重新计算的激活。不同层和算子的计算成本、显存占用存在差异，细粒度决策能够更充分地利用这些差异。

二是**隐藏重计算开销**。利用流水线空闲时间或可重叠的执行窗口安排重计算，减少它对训练关键路径的影响。这要求系统同时理解数据依赖和训练调度。

针对策略搜索，综述进一步区分了**启发式方法**和**基于整数线性规划的全局方法**。前者借助结构规律和代价估计，以较低搜索成本获得可用方案；后者将张量依赖、显存约束和计算成本纳入统一优化模型，但也需要面对大规模计算图上的求解成本。

## 五、数据压缩：如何减少存储量，同时保持精度和处理效率？

数据压缩通过低精度表示、量化、稀疏编码或低秩表示等方式，减少激活、优化器状态以及其他训练数据的存储需求。

![](https://pic1.zhimg.com/v2-52c1318df4acd2ea7a5feeac16fa7a66_r.jpg)
*低精度表示与低秩表示的压缩示意图*

这一方向需要同时处理两类挑战：**模型精度保持**和**压缩开销降低**。

在精度保持方面，综述讨论了两个主要角度。

**自适应低精度压缩**关注不同数据对数值误差的敏感程度，通过选择合适的精度、缩放方式或量化策略，在节省显存的同时控制误差及其累积。

**误差可控的低秩压缩**利用数据的低秩结构减少存储量，并通过投影、秩选择或约束设计，控制近似误差对训练过程的影响。

在运行开销方面，已有研究一方面采用**选择性压缩**，优先处理显存收益较高、精度风险和处理成本较低的数据；另一方面设计**高效压缩算法**，减少编码、解码、格式转换和元数据带来的负担。

## 六、分布式显存优化：多张 GPU 如何共同承担显存压力？

多 GPU 训练通过划分模型、训练状态和计算任务，将显存压力分摊到不同设备。但不同并行方式也面临各自的显存问题：数据并行存在训练状态冗余，流水线并行可能使激活长时间驻留，而模型划分和动态任务分配又可能导致设备间显存负载不均衡。综述围绕这三个问题，梳理了现有工作的主要解决角度。

![](https://pic3.zhimg.com/v2-55107dbff3a1314527bdce57a80d8e06_r.jpg)
*分布式训练，将模型参数与部分中间数据分布到不同设备上存储*

### 6.1 数据冗余：如何减少重复保存的训练状态？

传统数据并行通常在每张 GPU 上保存完整的模型参数、梯度和优化器状态。随着模型规模增长，这些重复保存的训练状态会占用大量显存，使增加 GPU 数量难以直接降低单卡的存储压力。

针对这一问题，现有方法主要采用**细粒度数据分片**：将参数、梯度和优化器状态分散到不同设备，每张 GPU 仅保存其中一部分，并在计算需要时通过通信获取相应数据。ZeRO 和 FSDP 是这一方向的重要代表。分片减少了状态冗余，也引入了额外通信，因此相关研究进一步通过优化通信时机、控制数据聚合规模，以及重叠计算与通信，降低分片对训练效率的影响。

### 6.2 激活生命周期：如何减少流水线中的长期占用？

在流水线并行中，一个阶段完成前向计算后，往往需要等待后续阶段执行，才能进行对应的反向计算。在这段等待时间内，反向传播所需的激活持续占用显存；随着多个微批次（micro batch）进入流水线，尚未释放的激活不断累积，推高显存峰值。

针对这一问题，现有方法主要从**调度优化**和**结合其他显存优化技术**两个角度展开。调度优化通过调整前向与反向计算的执行顺序，使激活更早被使用和释放，减少同时驻留的激活数量；另一类方法则结合重计算与卸载，将部分激活丢弃后按需重新生成，或暂时迁移到其他存储设备。两类方法都需要在显存节省、流水线空闲时间和额外计算或通信开销之间进行权衡。

### 6.3 显存负载不均衡：如何充分利用所有设备？

多 GPU 训练中的显存需求往往分布不均。不同流水线阶段保存的激活数量可能不同，模型各层的参数和计算规模也存在差异；在 MoE 训练中，动态路由还可能使部分专家所在设备承担更多任务。因此，即使其他 GPU 仍有空闲显存，负载较重的设备也可能率先达到容量上限，限制整个训练任务的规模。

针对这一问题，现有工作主要从四个角度解决。**负载重分配**通过调整模型划分或跨设备迁移激活，将部分显存压力转移到空闲设备；**结合卸载与重计算**根据各阶段的显存需求，采用不同强度的优化策略，降低高负载阶段的占用；**算法层面的负载均衡**通过改进 MoE 的路由机制或引入负载均衡目标，缓解专家任务分配不均；**显存感知的并行编排**则在选择并行配置、划分模型和放置专家时，将设备显存占用纳入决策，从整体上提高集群显存利用率。

## 七、其他优化：显存碎片和临时缓冲区也值得关注

训练显存还受到内存分配方式和算子实现的影响。综述将这部分工作归纳为**显存碎片整理**和**临时缓冲区缩减**。

在碎片整理方面，反复分配和释放不同大小的张量，可能使空闲空间分散，降低后续分配的可用性。已有工作通过静态分区、预规划分配和运行时碎片管理，改进张量布局与内存复用。

在临时缓冲区方面，算子计算和计算图执行可能产生较大的中间结果或工作空间。现有研究通过算子重设计、计算分块、算子融合，以及计算图调度和内存布局优化，降低峰值占用。

## 八、未来研究趋势：模型、硬件与集群演进带来的新问题

显存优化面临的问题会随着模型结构、硬件能力和训练集群的变化而不断演进。综述从这三个角度出发，讨论了未来值得关注的研究方向：**面向模型架构的优化、面向多层次存储的优化，以及面向集群拓扑的全局显存协同。**

### 8.1 面向新型模型架构：如何适应动态、稀疏和异构的显存需求？

许多显存优化方法依赖相对稳定的执行过程，例如可预测的张量生命周期、固定的计算图和较为稳定的显存峰值。但新型模型正在改变这些前提。

在 MoE 模型中，被激活的专家随输入和训练迭代变化，使计算任务和显存需求具有动态性；线性注意力、稀疏注意力等机制改变了注意力模块的计算与存储特征，也改变了卸载、重计算和压缩的收益；多模态模型则包含编码器、投影模块和解码器等不同组件，各部分的显存占用和计算模式存在差异，参数冻结与分阶段训练又进一步增加了执行过程的复杂性。

因此，未来需要研究**能够感知模型结构与运行行为的显存优化方法**：根据不同模块的特征选择优化策略，并随执行状态调整决策，使优化更好地适应动态专家激活、新型注意力机制和异构模块组合。

### 8.2 面向新型硬件与存储层级：如何协同数据放置和计算位置？

数据卸载的效果很大程度上取决于数据迁移成本。CPU–GPU 高带宽互连、CXL 扩展内存等技术，为更高效地使用 GPU 外部存储提供了机会，也使传统的卸载策略需要重新评估。

这一变化带来的研究问题是：**哪些数据适合放在 GPU 显存、主存、扩展内存或 SSD 中？何时迁移？计算应当在哪里执行？** 当不同存储层级的容量、带宽和访问延迟发生变化时，卸载与重计算之间的成本关系也可能随之改变。

存内计算和近数据计算还提供了另一种可能：将部分计算安排在数据所在的位置附近，减少跨层级搬运。例如，未来可以探索将部分训练状态放到具备计算能力的内存设备中，并在附近执行相关操作。

因此，这一方向需要更加统一地考虑**数据放置、迁移调度与计算位置**，协调不同存储层级的能力，在扩展有效显存容量的同时控制训练开销。

### 8.3 面向新型训练集群：如何实现跨设备的全局显存协同？

在异构 GPU 集群中，不同设备的计算能力、显存容量和通信条件可能存在明显差异。计算能力较强的设备未必拥有更大的显存，而按计算性能划分任务，也未必能实现合理的显存分配。未来的优化需要共同考虑计算与显存约束，为不同设备选择合适的任务规模和优化策略。

另一方面，高带宽互连的超节点架构降低了部分跨 GPU 数据移动的成本，为跨设备迁移、放置和共享张量提供了新的空间。系统可以探索将高负载设备上的部分数据转移到有空闲容量的设备，但也需要判断迁移收益是否足以抵消通信和同步开销。

因此，未来需要研究**感知集群拓扑的全局显存协调方法**：根据设备容量、计算能力和互连条件，联合优化模型划分、张量放置与迁移，使整个训练系统的显存资源得到更充分的利用。

## 九、综述能提供什么？

这篇综述希望帮助读者把分散的技术工作放到同一个框架下理解：从显存开销的来源出发，判断不同方法能够解决什么问题，再比较它们引入的计算、通信、数值误差和系统复杂度。

对于实际训练任务，可以先分析显存峰值由哪些数据构成，再选择优化手段。对于研究工作，则可以沿着各个方向尚未解决的开销和适用性问题，进一步寻找研究切入点。
