## **拒绝采样**

拒绝采样是一种蒙特卡洛方法，和重要性采样一样，都是在原始分布难以采样时，用一个易于采样的建议分布进行采样。拒绝采样只是为了解决目标分布采样困难问题，它需要原始分布是已知的。这里我想再次强调，是 **采样困难** ，不是分布未知，也不是分布计算困难。 拒绝采样的形式化描述是这样的：

假设已知原始分布为 $p(x)$ ,但是从 $p(x)$ 采样较为困难，我们可以找到一个容易采样的建议分布 $q(x)$ 。再确定一个常数 $C \geq1$ ，确保任取x满足 $p(x) \leq C\cdot q(x)$ 。然后从 $q(x)$ 中采样，以 $\frac{p(x)}{C\cdot q(x)}$ 的概率保留这个样本，得到的采样结果就是服从 $p(x)$ 的样本。

对比来看看拒绝采样和重要性采样，重要性采样的目的是通过易采样的建议分布估算原始分布的期望，目的是为了数值计算，而拒绝采样是为了采样出一批样本。下面举个具体的拒绝采样的用例。

### **具体例子**

举个具体点的例子，假设现在有已知的分布 $F(x)$ 的概率密度函数 $f(x)$ 如下：

$f(x) = \frac{1}{\sqrt{2\pi}}e^{-\frac{x^2}{2}}  ⋅(1+0.5sin(5x)) $

任取 $x$ 我们都可以直接计算出 $f(x)$ 的值，我们也可以画出函数图像。

![](https://pic3.zhimg.com/v2-86b7100ac78febf44f220ed3f7901d06_r.jpg)

```text
import matplotlib.pyplot as plt
import numpy as np

def func(x):
    y = 1 / np.sqrt(2 * np.pi) * (np.e ** (- x ** 2 / 2)) * (1 + 0.5 * np.sin(5 * x))
    return y

x = np.arange(1000) / 100 - 5
y = func(x)

plt.plot(x,y)
plt.show()
```

现在要采样出5000个服从 $f(x)$ 分布的随机样本。python肯定是没有直接从这个分布采样的函数，我们可以用拒绝采样来实现这个函数。因为 $f(x)$ 中 $x$ 的取值范围是 $(-\infty,+\infty)$ ，我们找到建议分布也要满足这个要求。我们在 $f(x)$ 中观察到一个正态分布的影子，而python正好也能生成正态分布，那我们就用一个正态分布作为建议分布：

$g(x) = \frac{1}{\sqrt{2\pi}}e^{\frac{x^2}{2}}$

现在需要确定常数C，注意到：

$\frac{f(x)}{g(x)} = (1+0.5\sin(5x))$

最大值是1.5，那么C取1.5就能保证分母恒大于等于分子。接下来实现这个采样函数：

```text
def proposal_func(x):
    y = 1 / np.sqrt(2*np.pi) * (np.e ** (- x **2 / 2))
    return y

def rejection_sampling(size):
    samples = []
    while len(samples) < size:
        x = np.random.randn()
        if func(x) / (1.5 * proposal_func(x)) > np.random.random(): # 所有“以 x 概率保留”操作在代码实现都是判断 x 是否大于一个0-1随机数
            samples.append(x)
    return samples

samples = rejection_sampling(5000)
```

把采样结果的直方图画出来看看是否服从我们的原始分布：

```text
plt.plot(x,y)
plt.hist(samples, bins=60, density=True, alpha=0.5)
plt.show()
```

![](https://pic3.zhimg.com/v2-9afdbff93f2b8c8bc02bcb91b0a0feae_r.jpg)

如果疑惑为什么用 $\frac{f(x)}{C\cdot g(x)}$ 作为接受概率就能够模拟原始分布，可以去问o1，它能给出完整的证明。

## **拒绝采样的应用**

上面的案例是纯从统计学的角度使用拒绝采样，那在LLM的场景中，什么时候会用到拒绝采样呢？在深度学习中我们判别模型一般就可以当作 $f(x)$ ，而训练或推理数据就是样本x。也就是说当我有了一个模型，想要数据的时候，就会用到拒绝采样。换句话说，拒绝采样就是曲线救国，让判别模型发挥生成模型的功能。

### 小玩具

上一篇CP提到，在拿不到开源模型pretrain训练数据的情况下，我们用模型在自有数据上的概率+重要性采样来调整loss权重。那这一次就用模型在自有数据上的概率+拒绝采样直接估算pretrain训练数据的分布。我这次拿开源的Qwen2-72B和Qwen2.5-72B作为实验对象。分别以Qwen模型计算出的句子概率作为原始分布，用在我司之前某个版本数据训练的模型作为建议分布，使用拒绝采样看看qwen模型各数据的偏差：

### **拒绝采样训练 RST**

更重要的应用，当然还是把拒绝采样用在LLM训练上，是NLPer在追寻 $\pi^*$ 路上的又一种新尝试。虽然重要，且有效，但RST的逻辑非常简单，它并没有改变SFT训练loss，你可以把它当作一种数据增强的手段，当然它又不仅仅是数据增强这么简单。offline RST的一般流程如下：

1. 用经过SFT 的模型或few shot的 pretrain 模型回答 SFT 所有训练数据的问题，得到模型answer。
2. 用奖励模型对SFT数据中原始的answer和模型生成answer进行打分
3. 得分 top1 的answer 去替换SFT数据中的原始answer，产生新的一版训练数据。
4. 新的数据去训练1中用来生成answer的模型。
5. 重复1-4：模型回答SFT数据->打分->top1替换得到新版数据->训练模型->模型回答SFT数据->打分->....

如果不是以epoch为单位生成answer，而是每个step或每几个step就用当前训练的模型实时生成answer，就是online RST。RST最需要注意的就是 reward 模型的 OOD 问题，如果 RS 用的 prompt 是从 reward 模型的训练数据里摘出来的，一般没什么问题。但是如果不一致，一般都会 OOD，导致错误结果分高，模型越训越烂。如果 SFT 和强化是分开迭代的，或者 reward 数据用开源的可能会遇到这个问题。RS 和 reward 尽量用同分布的数据，不行的话最好也对训练数据做一个聚类或者分类，对不会 OOD 的数据用 RS，其他还是正常训练。或者也可以引入一个verifier模型，先判断answer对不对，仅在正确的answer中取reward分数最高的。

在哪里使用RST？在数学上使用RST应该是一个无脑涨点的方案，因为数学的标准答案很明确，很好判断，reward模型相对好训练，就算是用规则模型也更容易实现。除此之外，我用RST的准则就是判断模型在某一领域pass@5、pass@10是否明显大于pass@1，理由也很明显，如果多次采样性能并没有提高，就说明sample出来的都是错的，RST并不能利用负例，所以也就无法学到什么。

另外奖励模型的训练其实有很多可以说的，比如生产奖励模型的训练数据（人工标注、模型标注、先验规则、MCTS）和奖励模型的训练（判别式、生成式、ORM、PRM），但是本文并不想发散到那么远。本文更想简答讨论一下SFT、DPO、RST、PPO之间的联系和差异。

## **对比几种训练方式的异同**

### **SFT**

首先是SFT，用的是next token loss或者叫lm loss，这是现代语言模型最原始、最直接的训练方式：

$\mathcal{L}_{lm} = -\frac{1}{T}\sum_{t=1}^T logP(x_t|x_{<t})$

其中 $P(x_t|x_{<t})$ 表示当给定 $x_1,x_2,...,x_{t-1}$ 这个token序列时，第t个token是 $x_t$ 的概率。这是个性质相当好的loss，它优化的是 $x_1,...x_T$ 的联合概率，也就是说它是一个生成模型的loss：

$\mathcal{L}_{lm}=-\frac{1}{T}\sum_{t=1}^T logP(x_t|x_{<t})=-\frac{1}{T}log\prod_{t=1}^TP(x_t|x_{<t})=-\frac{1}{T}logP(x_1,...,x_T)$

这个loss给pretrain用一点问题没有，因为pretrain的目的就是知识注入，理想的pretrain应该能通过采样还原出所有学过的文字知识，但是给SFT用似乎有一点问题。知乎有一个关于为什么要做RLHF的问题： [为什么需要RLHF？SFT不够吗？](https://www.zhihu.com/question/651021172) 。各方向大佬在里面分享了各种前沿的研究成果和动机，看完令人受益匪浅，推荐加入必读。但是通篇看完感觉并不能说服我SFT为什么不行。我在各种文章、现实工作中听到的最多的观点一般都会从在线、离线学习的角度分析SFT的不足。这确实是很重要的一点，但是离线学习也是学习，假设加入SFT数据集的数据就是最好最理想的数据，就包含期望的answer，模型怎么还是学不会？大多数人的成长似乎也都是读书上大课，也没有很多老师来因材施教，模型怎么就不行。或者说我的疑惑是，在LLM训练上，在线学习优于离线学习的本质原因是什么？我认为是因为训练和推理有gap。和pretrain相比，SFT的侧重点已经从忠实的反应训练数据分布变成了按照人的预期进行生成。但是语言模型loss低 $\neq$ 能生成。假如使用贪婪的方式采样，能生成意味着所有目标token的概率都是top1。也就是说lm loss应该改成类似下面的这种形式:

$\mathcal{L}_{slm} = -\frac{1}{T'}\sum_{t=1}^T logP(x_t|x_{<t})I(x_t)$

$I(x_t)$ 是个指示函数，当 $x_t$ 不是top1 token的时候为1，否则为0。举个具体的例子的话就是"中国的首都是哪里？是北京"，"是"、"北"、"京"的概率提高都能使loss降低，但是这句话能不能说对的关键是"北"的概率是不是top1，"京"的概率再高，"北"采不出来也还是不对。当然这个公式只是个示意，没有做严谨推导，梯度是稀疏的，估计最终效果很差，或许真正需要的是一个软标签指示函数或者噪声指示函数。

### DPO

看完SFT再来看看DPO，DPO优化的损失函数是：

$\mathcal{L}_{DPO}=-\mathbb{E}\left[log \sigma\left(\beta log \frac{\pi_{\theta}\left(y_{w} | x\right)}{\pi_{ref }\left(y_{w} | x\right)}-\beta log \frac{\pi_{\theta}\left(y_{l} | x\right)}{\pi_{ref }\left(y_{l} | x\right)}\right)\right]$

其中 $\pi_\theta,\pi_{ref}$ 分别表示正在训练的模型和冻住不训的参考模型， $x,y_l,y_w$ 分别表示prompt，较差的answer和较好的answer。当初第一眼见DPO时觉得这个抛弃奖励函数和PPO直接优化语言模型的设计非常巧妙，所以立马造了一批数据试验了一下，结果第一下就给模型训崩了。这有点不符合我的直觉，在我的惯性认知里这种连续的loss不会这么不稳定。后来仔细思考了下DPO的loss函数，我发现它的优化目标是最大化给定 $x,y_l,y_w$ 下，好answer优于坏answer的概率：

![](https://pic4.zhimg.com/v2-8cc814342cd13761c7d36895556a66d1_r.jpg)

这不是个生成模型loss，这是判别模型的loss。它的最直接作用是增大 $y_w$ 和 $y_l$ 的差距，并不保证 $y_w$ 还依旧能被采样出来，这个loss甚至还把上面提到的SFT的问题给放大了。DPO设计的时候是通过PPO的显式解得出来的，也就是说loss中是隐含了KL的，为什么没有生效呢？原因就是DPO是off-policy算法。在on-policy的算法里，如果模型训崩了，sample出一些不符合语言模型的answer，reference可以给出一个很大的KL loss来约束。但是在DPO这里没有sample的过程，在优化计算效率时 $\pi_{ref}(y|x)$ 甚至是训练之前就算好存下来的，因此就算模型开始说胡话，reference也不知道模型已经崩了，也给不出足够的约束。

目前工业界稳定跑通的DPO，很多用的都是下面这个公式：

$\mathcal{L}_{DPO}=-\mathbb{E}\left[log \sigma\left(\beta log \frac{\pi_{\theta}\left(y_{w} | x\right)}{\pi_{ref }\left(y_{w} | x\right)}-\beta log \frac{\pi_{\theta}\left(y_{l} | x\right)}{\pi_{ref }\left(y_{l} | x\right)}\right) + \alpha log \pi_\theta(y_w|x)\right]$

也就是把好样本的语言模型loss加上，给这个loss多一些生成的成分。在这个训练范式下，DPO的作用更多是拿来打压一下生成过程中明确遇到的一些负例。另外额外提一嘴，DPO训练的时候 $\pi(y|x)$ 是 $\sum_{t=1}^TP(y_t|x_{\lt t})$ ，而不是 $\frac{1}{T}\sum_{t=1}^TP(y_t|x_{\lt t})$ ，这个原理我没有细究，因为我用的也不多。

### RST

我们希望充分利用偏好对训练出来的$\pi^*$模型，但是$\pi^*$又是个判别模型。既然判别模型做不了生成，那就找个生成的模型来采样，判别模型负责拒绝就可以了，于是也就有了拒绝采样的训练。拒绝采样保证了训练的模型依旧是一个生成模型（理论上），因为这个模型的loss还是语言模型loss。然后靠reward模型拒绝采样，改变训练数据的分布来拟合 $\pi^*$ 。但是reward+top1的拒绝采样也不是一劳永逸的。首先是不连续的loss + reward模型OOD导致模型越训越烂的问题，其次就是这个topn采样并不是无偏的，没有完全依照$\pi^*$的概率去采样。所以很多优化是从这方面入手，有根据 reward阈值的拒绝采样（但是reward在不同domain阈值差别很大，不好确定阈值超参）、归一化reward分数当作概率采样或者reward+规则等等。但是这些大部分都做不到无偏。

### **PPO**

RST还是有个问题，就是没有充分利用bad answer，好的answer要鼓励，坏的answer最好也能打压。GRPO、PPO这一类算法就是再升级版。首先延续了拒绝采样的优点，算法是on-policy的，有sample过程，确保了模型保持生成模型的特性。使用归一化reward分数、减baseline等方差，在一定程度减小了估计$\pi^*$的偏差。并且正负例都拿来计算loss，充分利用负例。如此集众人之作长，代价就是引入了太多的离散变量，训练相对不那么稳定，每个地方都需要做clip。
