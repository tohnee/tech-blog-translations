## dma-buf 定义

dma-buf 目的:解决各个驱动之间 buffer 零拷贝共享的问题。

dma-buf是 fd + buffer 的结合体，fd 用于标识和管理 buffer,同时 控制访问权限,buffer 是实际的内存区域。

buf由设备驱动预先分配并导出，与一个 FD 结对，形成一个 DMA BUF。使用者可以通过 FD 符将 buf 映射到自己的地址空间，从而实现buf的访问。

（说明，1: 这个 buffer可能属于不同设备（如 GPU 显存、网卡 DMA 区域），而不仅是 CPU 内存。2：fd 不关联实际文件，仅作为安全令牌）

分配 buffer 的模块：称为 exporter

使用 buffer 的模块：称为 importer 或 user。（本文中，importer 特指内核空间的使用者，user 特指用户空间的使用者。)

### PPT 个人梳理：

**GPU 的设备内存是归 GPU 硬件本地独占的地址空间，并非系统通用内存**， 因此现有的 NIC 驱动无法直接访问 GPU 内存。

早期由于 RDMA core 没有标准方式处理 GPU 显存，Mellanox 在 MOFED (OFED 是 OFA 维护的 RDMA 软件栈发行包,MOFED 既 mellanox OFED,是Mellanox 基于 OFED 的厂商增强版) 中引入了 Peer‑Direct 插件接口，GPU 驱动通过 peer‑mem client（如 nv_peer_mem/nvidia_peermem）与 RDMA core 协作，从而实现 RDMA NIC 访问 GPU 显存。但这条路是厂商私有且只在 MOFED 生效，其他 GPU 驱动若不实现该插件接口，就无法配合。

因此OFA(OpenFabrics Alliance RDMA 生态与软件栈社区组织）组织会议上演讲者 提出用Linux 内核早已有的通用跨设备共享机制 **dma‑buf 作为上游标准接口**，把“RDMA/NIC 访问 GPU 显存”纳入统一的跨设备共享框架，让 “RDMA 访问 GPU 显存” 成为跨设备共享的通用场景之一，从而避免 MOFED 私有插件路径。

### 为什么不直接使用共享内存或物理地址共享 buffer？

各个设备之间为什么不直接使用共享内存或物理地址共享 buffer？而要使用 DMA BUF 这种通过 文件描述符（fd）的方式？

1，前面说了这个 buffer可能属于不同设备（如 GPU 显存、网卡 DMA 区域），而不仅是 CPU 内存，不同硬件设备（NVIDIA GPU、Intel 网卡）的驱动可能对内存布局有不同要求。所以不能用当前 linux 的传统共享内存（如 `shmget`/`mmap`）机制共享。

2，直接给物理地址？X 不安全！设备可能误操作或越界访问。

而DMA BUF 就是为了解决上面的问题：

1. 传统共享内存（如 `shmget`/`mmap`）机制共享无法统一管理GPU 显存、网卡 DMA 区域 ，CPU 内存，那就创建一个统一的标准和接口：DMA BUF

- `屏蔽差异：`异构系统（如 ARM CPU + NVIDIA GPU）中，物理地址可能在不同设备上有不同映射方式。DMA BUF 的 `fd` 抽象屏蔽了底层差异
- 统一接口： DMA BUF 的 `begin_cpu_access`/`end_cpu_access` 等接口能主动同步缓存。
- 权限控制和同步：`fd` 除了抽象屏蔽了底层差异，还提供安全的访问句柄（而非直接暴露地址），和同步（通过 `fence`）。

### 总结

DMA BUF 的核心本质

它定义了如何安全共享内存（通过 `fd`）、如何同步（通过 `fence`）、如何跨设备兼容（通过标准化接口）。

dma-buf的核心特性：

- 标准化接口：通过统一的dma_buf_ops结构体提供跨设备访问
- 内存类型无关：支持显存、设备内存、CMA区域等多种存储类型
- 同步机制：通过dma_fence实现设备间执行依赖

## 生命周期和例子

### **1. GPU 和 CPU 之间的 DMA-BUF 生命周期**

> 1 内存分配<br>导出者： GPU 驱动分配显存，并调用 `dma_buf_export()` 将其注册为 DMA BUF。<br>2 传递 fd<br>将 DMA-BUF 的 `fd` 传递给用户态或 CPU 驱动。（通过 IPC 或内核接口）。<br>3 内存访问<br> 使用者：CPU 通过 `mmap` 或 `dma_buf_map_attachment` 获取访问权限。<br>4 同步<br>导出者 GPU 数据处理完成后，通过 `dma_fence` 通知使用者 CPU“数据就绪”。<br>5 释放<br>使用者 CPU 使用完成后释放 `fd`（`close(fd)）`，导出者 GPU 驱动回收显存。

## **2. 代码示例（AMD GPU + CPU 同步）**

使用 DMA-BUF 在 GPU 和 CPU 之间共享内存时，主要有基于 `libdrm`（通用 GPU 设备）和基于 ROCm 工具链（AMD GPU 专用）

两种典型的实现方式，分别针对不同的使用场景和开发需求：

### **(1) 基于** **`libdrm`（通用 GPU 设备）**

### **特点**

- 通过 Linux DRM 子系统直接操作 GPU 显存。
- 需要手动处理 内存分配、导出、映射、同步。
- 适用于需要精细控制或非 AMD 设备的场景（如 NVIDIA 或 Intel GPU）。

```text
#include <xf86drm.h>
#include <xf86drmMode.h>
#include <stdlib.h>
#include <stdio.h>

int main() {
    // 1. 打开 DRM 设备
    int drm_fd = open("/dev/dri/renderD128", O_RDWR);
    if (drm_fd < 0) {
        perror("Failed to open DRM device");
        return -1;
    }

    // 2. 分配 GPU 显存
    struct drm_mode_create_dumb create_arg = { .width = 1024, .height = 1024, .bpp = 32 };
    if (drmIoctl(drm_fd, DRM_IOCTL_MODE_CREATE_DUMB, &create_arg) < 0) {
        perror("Failed to create dumb buffer");
        close(drm_fd);
        return -1;
    }

    // 3. 导出为 DMA-BUF fd
    struct drm_prime_handle prime_arg = { .handle = create_arg.handle, .flags = DRM_CLOEXEC, .fd = -1 };
    if (drmIoctl(drm_fd, DRM_IOCTL_PRIME_HANDLE_TO_FD, &prime_arg) < 0) {
        perror("Failed to export DMA-BUF");
        drmModeRmFB(drm_fd, create_arg.handle);
        close(drm_fd);
        return -1;
    }
    printf("DMA-BUF fd: %d\n", prime_arg.fd);

    // 4. CPU 映射显存（需 begin_cpu_access 同步缓存）
    void *ptr = mmap(NULL, create_arg.size, PROT_READ | PROT_WRITE, MAP_SHARED, prime_arg.fd, 0);
    *(int *)ptr = 0x12345678;  // 写入数据

    // 5. 清理资源
    munmap(ptr, create_arg.size);
    close(prime_arg.fd);
    drmModeRmFB(drm_fd, create_arg.handle);
    close(drm_fd);
    return 0;
}
```

### **基于 ROCm 工具链（AMD GPU 专用）**

### **特点**

- 使用 AMD 的 HIP 或 OpenCL 运行时 API，自动管理 DMA-BUF。
- 适合深度学习、科学计算等高性能场景。
- 无需手动处理 `ioctl`，但依赖 ROCm 驱动环境。

```text
#include <hip/hip_runtime.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    // 1. 初始化 HIP
    hipInit(0);

    // 2. 分配 GPU 显存
    float *gpu_ptr;
    hipMalloc(&gpu_ptr, 1024 * sizeof(float));

    // 3. 导出为 DMA-BUF fd
    int fd;
    hipMemGetHandle((void*)&fd, gpu_ptr);
    printf("DMA-BUF fd: %d\n", fd);

    // 4. 传递 fd 给其他进程（或 CPU 映射）
    close(fd);
    hipFree(gpu_ptr);
    return 0;
}
```

草稿堆：

在 Linux 系统中，文件描述符（fd）并不一定非要关联实际的磁盘文件才能使用标准的文件操作函数，这得益于 Linux 系统设计的高度抽象性，下面为你详细解释为何能通过文件描述符对 DMA - buf 进行 `mmap` 操作：

### 1. Linux 的文件抽象模型

Linux 采用了“一切皆文件”的设计理念，它将各种不同类型的资源（如磁盘文件、设备、网络套接字、管道等）都抽象成文件的概念。对于内核而言，这些资源都可以通过统一的文件操作接口进行管理和访问，例如 `open()`、`read()`、`write()`、`mmap()` 等。

文件描述符是一个非负整数，它是进程与内核中打开文件对象的一个索引。当进程打开一个文件或其他资源时，内核会创建一个对应的文件对象，并返回一个文件描述符给进程。进程后续就可以使用这个文件描述符来操作该文件对象。

### 2. DMA - buf 的文件对象抽象

当设备驱动创建并导出一个 DMA - buf 时，内核会为这个 DMA - buf 创建一个对应的文件对象，并将其与一个文件描述符关联起来。这个文件对象实现了一组特定的操作方法，这些方法定义了如何对 DMA - buf 进行各种操作，包括内存映射（`mmap`）。

虽然这个文件对象并不对应实际的磁盘文件，但它遵循了 Linux 文件系统的抽象接口，因此进程可以像操作普通文件一样使用文件描述符对 DMA - buf 进行操作。

### 3. mmap 操作原理

`mmap()` 函数的作用是将文件或其他对象的内容映射到进程的地址空间中，这样进程就可以直接通过内存访问的方式来读写文件内容，避免了频繁的 `read()` 和 `write()` 系统调用。

当对 DMA - buf 的文件描述符调用 `mmap()` 时，内核会执行以下操作：

- 查找文件对象：内核根据传入的文件描述符找到对应的文件对象。
- 调用文件对象的 mmap 方法：文件对象中实现了 `mmap` 方法，内核会调用该方法来完成具体的映射操作。对于 DMA - buf 来说，这个 `mmap` 方法会将 DMA - buf 所对应的物理内存区域映射到进程的虚拟地址空间中。
- 返回映射地址：如果映射成功，`mmap()` 函数会返回一个指向映射区域的指针，进程就可以通过这个指针直接访问 DMA - buf 的内存。

### 4. 示例代码

以下是一个简单的示例代码，展示了如何使用 `mmap()` 函数通过文件描述符对 DMA - buf 进行内存映射：

```text
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>

#define BUFFER_SIZE 4096

int main() {
    int fd;
    void *buffer;

    // 假设 fd 是一个有效的 DMA - buf 文件描述符
    fd = open("/dev/dma_buf_device", O_RDWR);  // 这里只是示例，实际获取方式不同
    if (fd == -1) {
        perror("open");
        return 1;
    }

    // 使用 mmap 将 DMA - buf 映射到进程的地址空间
    buffer = mmap(NULL, BUFFER_SIZE, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (buffer == MAP_FAILED) {
        perror("mmap");
        close(fd);
        return 1;
    }

    // 现在可以像操作普通内存一样操作 buffer
    // 例如写入数据
    sprintf((char *)buffer, "Hello, DMA - buf!");

    // 解除映射
    if (munmap(buffer, BUFFER_SIZE) == -1) {
        perror("munmap");
    }

    // 关闭文件描述符
    close(fd);

    return 0;
}
```

### 1. `open` 函数的基本功能

在 Linux 系统里，`open` 函数的主要作用是打开或创建一个文件、设备文件、管道等资源，并返回一个文件描述符（fd）。它是一个通用的系统调用，用于建立进程与内核中文件对象的关联。其原型如下：

```text
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>

int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);
```

其中，`pathname` 是要打开的文件或设备的路径名，`flags` 是打开的方式（如只读、读写等），`mode` 用于指定新创建文件的权限。

### 2. DMA - buf 的导出过程

DMA - buf 的导出通常是由设备驱动来完成的。设备驱动在分配好内存缓冲区后，会调用内核提供的相关函数将该缓冲区封装成一个 DMA - buf 对象，并生成一个与之关联的文件描述符。这个过程一般涉及到内核内部的一些特定接口，而不是 `open` 函数。

例如，在 Linux 内核中，驱动可以使用 `dma_buf_export` 函数来导出一个 DMA - buf，该函数会返回一个文件描述符：

```text
#include <linux/dma - buf.h>

struct dma_buf *dma_buf_export(struct dma_buf_attachment *attach,
                               enum dma_buf_export_flags flags);
```

### 3. `open` 函数在 DMA - buf 使用中的作用

虽然 `open` 函数不用于导出 DMA - buf，但它在后续使用 DMA - buf 时非常重要。通常，设备驱动会创建一个对应的设备文件，应用程序或其他驱动可以通过 `open` 函数打开这个设备文件，从而获取与 DMA - buf 关联的文件描述符。

例如，某些设备驱动会在 `/dev` 目录下创建一个特殊的设备文件，用户空间的程序可以通过 `open` 函数打开这个设备文件，然后通过文件描述符对 DMA - buf 进行操作，如使用 `mmap` 进行内存映射：

```text

#include <fcntl.h>
#include <sys/mman.h>

#define BUFFER_SIZE 4096

int main() {
    int fd;
    void *buffer;

    // 打开与 DMA - buf 相关的设备文件

        perror("open");

    }

    // 使用 mmap 映射 DMA - buf
    buffer = mmap(NULL, BUFFER_SIZE, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);

        close(fd);
        return 1;
    }

    // 操作 buffer...

    // 解除映射
    munmap(buffer, BUFFER_SIZE);
    // 关闭文件描述符

    return 0;
}
```

```text
void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
```

这里的 `addr` 一般设为 `NULL` 让内核自动选择映射地址；`length` 是要映射的内存长度；`prot` 表示映射区域的访问权限（如 `PROT_READ`、`PROT_WRITE` 等）；`flags` 控制映射的行为（如 `MAP_SHARED` 表示共享映射）；`fd` 是文件描述符；`offset` 是文件偏移量。

### 用户空间程序部分

```text
#include <stdio.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <unistd.h>

#define BUFFER_SIZE 4096

int main() {
    int fd;
    void *buffer;

    // 打开设备文件
    fd = open("/dev/my_dma_buf_dev", O_RDWR);
    if (fd == -1) {
        perror("open");
        return 1;
    }

    // 进行内存映射
    buffer = mmap(NULL, BUFFER_SIZE, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (buffer == MAP_FAILED) {
        perror("mmap");
        close(fd);
        return 1;
    }

    // 读写操作示例
    sprintf((char *)buffer, "Hello, DMA - buf!");
    printf("Read from buffer: %s\n", (char *)buffer);

    // 解除映射
    if (munmap(buffer, BUFFER_SIZE) == -1) {
        perror("munmap");
    }
    // 关闭文件描述符
    close(fd);

    return 0;
}
```
