昇腾的预编译包没了，从今年五月开始到现在。同一批被停的语气还有 Intel 的 SYCL 那一栏，而那一栏在十一月一号回来了。

![](https://pica.zhimg.com/v2-5a42a51d625b91e8e639119c15647aac_r.jpg)

## 发布页就是一张支持表

llama.cpp 的 GitHub 发布页每天推好几个 b 版本。写作时最新的三条是 b12063，十一月三号凌晨一点三十九分出的，再往前是 b12061 和 b12060，两条隔了四十分钟。三条都标记为 Pre-release。

每个版本下面挂着一长串下载包，按操作系统与加速后端分开。Linux 一栏里有 CPU、Vulkan、CUDA 12、CUDA 13、ROCm 10.0、OpenVINO、SYCL，Windows 一栏也有对应的 CUDA 12、CUDA 13、Vulkan、ROCm 10.0、SYCL。

判断某个后端在不在，不需要查文档，看这一栏有没有包就够了。

## openEuler 一栏只有 DISABLED

最下面那一栏是 openEuler，没有下载地址，正文写着 DISABLED，指向 pull 23705。链接下面列着四个条目，x86 310p、x86 910b 的 ACL Graph、aarch64 310p、aarch64 910b 的 ACL Graph。

310p 是昇腾的推理卡，910b 是训练卡，ACL Graph 是昇腾在主机侧的一种图执行方式。四个条目覆盖了主机架构与卡型的组合，一个都不给下载。

## 停掉的理由写在合并请求里

pull 23705 在五月二十六号合并，标题是「ci 精简，停掉 SYCL 与 CANN 的构建与发布」。

正文的原话大意是，最近把 GitHub Actions 的缓存消耗得太厉害，导致整体 CI 变慢，这个请求打算先停掉一部分构建，把缓存和 runner 的压力降下来。

其中 SYCL 那部分单独占了总缓存的百分之三十以上，作者认为不合理，先关掉，要重新打开得先备专用的 runner。openEuler 那一栏不占缓存，但会挤占 GitHub 托管的 runner。

在这个请求的讨论里还留了几条信息。一条是 SYCL 维护者说自己可以把这个流水线挪到专用 runner 上，另一条是问 ROCm 是否也一并处理，作者的回复是暂时保留，如果再慢就一起处理。

## 同一个请求停的两件事，只回来一件

这一点很多人没注意。

SYCL 与 CANN 是同一个请求里一起停的，理由是共用的。可是到了十月三十一号与十一月一号的发布页，SYCL 的包已经重新出现，Linux x64 有 FP32 与 FP16 两个，Windows x64 有一个。

CANN 那一边，同一个请求的评论区里有人提到，最后一次构建停在 b9334。

所以「CI 资源不够」这个理由只解释了起点，没有解释为什么两件事解绑了。要判断这条线会不会恢复，得盯 openEuler 那一栏，而不是盯某一次合并。

## 代码在，产物不在

这是整件事最容易被误读的一处。

代码没有被删。仓库里 CANN 后端的源码还在，构建脚本也在，只是工作流里的任务被停掉了。这两者的区别决定了自己动手的人要怎么走。

产物没了，意味着你得自己编。要装对应的 toolkit，打开后端的编译开关，还要跟上游对齐版本。上游只要动到 ggml 的算子，这边的补丁就得跟着动，否则编出来就是坏的。在昇腾这条线上，这比装 CUDA 要麻烦，因为依赖的层次更多。

## 下游仓库的处理方式说明了什么

几个从 llama.cpp 拉过去做自己版本的仓库，提交说明里把机理写得很清楚。

build-cann.yml 这个工作流文件里的任务被全部注释掉，而 GitHub 对没有任务的工作流文件是按加载失败来处理的。结果是每次推送都会记一条零任务的失败，一条几十秒就结束的红色叉。

这几条提交的说明里还有一句更实用的观察，说这个叉跟代码质量没关系，纯粹是文件形态的问题。他们的处理是把这个文件删掉，而不是等上游修。

## 这件事该怎么归类

我倾向于把它归到「项目产能的取舍」，而不是「对某种硬件的态度」。

依据是合并请求的正文与讨论。如果是对昇腾本身有意见，正常的路径是删后端、标实验、或者在文档里写清楚适配范围。现在这三样都没有，只停产物。

但归类归得再准，也改不了用它的人的成本。预编译包是开源项目给普通用户最大的便利，它意味着你不必是编译者也能用上。它一旦撤回去，门槛立刻从「下载解压」变成「装环境、编、追版本」。

同时也该承认另一面，开源项目的 CI 资源是有限的，托管 runner 的额度与缓存都是硬约束，一个项目要维持十几个后端每天出包，取舍是必然的。

## 手上是昇腾的话，怎么判断

第一步，看发布页上 openEuler 那一栏有没有新 tag。还是 DISABLED，就是没有官方产物。

第二步，看你要跑的东西是不是必须走 llama.cpp。昇腾生态里另有一套推理栈，llama.cpp 只是其中之一，别把一栏的停摆当成整条生态的停止。

第三步，真要自己编，把频次算进去。按天对齐上游的成本，和一个季度编一次的成本不一样，先想清楚自己在哪一种节奏里。
