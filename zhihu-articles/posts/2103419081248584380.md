“把这份 Excel 里的 Sheet2 到 Sheet6 合并成一张表，翻译成中文，去掉重复行，写回数据库。”

你按下回车，去倒了杯咖啡。

回来时：一万多行数据已合并写入目标库——其中翻译环节直接复用了你上个月沉淀的技能；质量检查跑完，发现的问题已自动修复；血缘记录完毕，上下游一查便知。全程没写一行 SQL，没拖一个节点，没打开过任何配置后台。

这是我们在 DataCrab 上反复打磨的日常。新一代的数据智能体长什么样？我们的答案是七个画像。

## **画像一：只有对话，没有 Workflow**

![](https://pic2.zhimg.com/v2-1fc14968d8d5f508a321ee51779aca59_r.jpg)

打开一个传统数据平台，最先看到什么？一块画布。左边节点面板，中间连线，右边参数表单。你要做的第一件事是“设计工作流”：把数据源拖进来，接上清洗节点，连好转换规则——每个节点点开，是一排待填的参数。

DataCrab 把这块画布，整个删掉了。**数据处理和分析只保留一个入口：对话框。**

这不是偷懒，是判断：

**画布的每一根连线，都是在替机器补偿智商。** 执行器不够聪明，只好靠人预先编排每一步——所谓“低代码”，很多时候只是换了个形式的高负担：你依然在做翻译官，把业务意图翻译成节点和参数。

**业务的变化速度，永远快于画布。** 口径一变，回画布重新梳理连线；新需求一来，祖传工作流图没人敢动。画布越画越复杂，最后成为企业里最昂贵的“死文档”。

删掉入口，不等于没有链路——链路不再是“画”出来的，是“长”出来的：

- 一次成功的对话处理，沉淀为一个**技能**：说明文档 + 脚本 + 专属检查规则
- 技能调试通过，一键**转为流程**——不是 DAG 图，是一个可直接执行的 Python 主函数
- 流程挂上定时调度，到点自动运行，运行时自修复：检测到异常自动触发修复
- 八类资产一键打包，整套数据体系可搬去另一台机器

中途改需求？在画布时代，这意味着改节点、重连线、重跑一遍，丢掉已执行的进度；在 DataCrab 里，插一句“只要 2023 年之后的数据”，任务带着新指示继续跑。**改需求的成本，从“重新画一遍”降到“说一句话”。**

## **画像二：人人都是数据工程师**

![](https://pica.zhimg.com/v2-a9eea91f93ad06e1d200530598c801ac_r.jpg)

注意：不是“人人都要学数据工程”，而是**每个会说话的人，都拥有了一个随叫随到的数据工程师**。

这个工程师不是聊天框套壳，而是四个分工明确的智能体：**DataProcessor**（处理）、**DataInspector**（检查）、**DataAnalyst**（只读分析）、**ChatAgent**（对话）。你说业务语言——“帮我合并、去重、翻译、写回库”；它干工程活：

write_script 写脚本 → run_script 执行 → 看到报错<br>→ grep 定位 → read 看上下文 → edit 修改 → 再跑

这套 read / grep / edit / run 编辑原语，对齐的是顶级 AI 编程工具的工作流：报错自己看，代码自己改，改完自己跑。脚本内可调用 41 个平台工具——查数、写库、调大模型、联网搜索、图像生成——一次执行完成多步逻辑。

工程师的工具箱它都有：PostgreSQL / MySQL / Excel / CSV / HDFS / 对象存储 / 向量库，9 种数据源即连即用；视频抽帧、图片理解、图像生成、PDF / Word 解析，多模态是标配；数据量大了，接 Ray 集群分布式跑。它还有预算意识：执行连续失败有止损线，轮次有上限，不烧着 API 费用空转。

过去，“数据工程能力”是部门的、职位的、稀缺的；现在，它是每个对话框里的默认配置。

## **画像三：保证数据正确，是天生的**

![](https://picx.zhimg.com/v2-d667ff06be27f19586752a5ed1a78f2f_r.jpg)

“天生”的意思是：正确性不是可选模块、不是增值服务、更不是事后再说——它写在智能体的出厂设置里。

在 DataCrab，**产出即检查**是本能反应：数据写入成功的那一刻，DataInspector 自动接管——30 余条确定性规则（主键唯一性、必填完整性、枚举合法性、数值边界、PII 未脱敏……）外加语义复核。发现严重问题？自动回交 DataProcessor 修复，修完再查，闭环直到干净。

> 别人的逻辑是：“结果给你了，对不对自己看。”<br>它的逻辑是：“**我验完货，才敢交。**”

正确不只靠检查，还靠记忆和透明：

- 每次写入自动记录**血缘**，出问题链式召回上下游，逐跳定位根源
- 检查对象精确到“数据源 → 表”，多数据源同名表不会查错对象
- 每一步的推理过程、代码变更、执行日志在对话流里实时可见——你看到的是“它正在做什么”，不是“你以为它会做什么”

天生正确，也天生安全：脚本跑在沙箱里——危险模块拦截、文件访问白名单、内存 / CPU / 输出限额；密钥不出进程，API Key 永不进沙箱；PII 识别、脱敏核查内嵌在质检环节，是常规项，不是插件。

## **画像四：数据是演进出来的，不是治理出来的**

![](https://pic2.zhimg.com/v2-cca8048646e84a9bd91da087cba447e5_r.jpg)

传统数据治理长什么样？标准委员会、评审会、规范文档、事后补录元数据——本质是**用“管”的方式，把秩序强加给数据**。而业务永远跑在治理前面：等规范评审通过，口径已经变了三回。于是治理成了一场和业务自然状态的对抗赛：人力密集、事后补录、经验孤岛、架构僵化——越治越累，越治越僵。

DataCrab 换了个思路：**与其治理，不如让它生长。**

- 每次数据操作，系统先智能匹配已有的数据资产、流程与技能——能复用的绝不重算，数据烟囱不是被“禁止”，而是自然失去存在的理由
- 每次成功沉淀为技能与流程，业务口径和加工逻辑留在系统里，而不是散在某个人脑里
- 每次失败记为反例、修好后记为正例——**失败成为进化的选择压力**，好链路被自然筛选、复用
- 血缘自动记录，数据架构图谱是使用的副产品，不是事后的作业

在 DataCrab 里，“元数据”是广义的：技能、流程、正反例经验、数据描述，共同构成 Agent 自主运行的养料。**数据架构不是设计文档定格的，是真实业务用出来的。**

而演进不是放任自流：产出即检查是它的护栏——每一次“变异”都要过验收，不合格的链路活不到下一次复用。

传统治理还把手段当成了目标——机械地审核流程与血缘；而治理真正的目标只有一个：结果正确。数据演进不追求设计出来的完美终点，它承认架构是活的：业务长，它就长。

## **画像五：把数据全交给 AI，它会越来越聪明**

![](https://pic4.zhimg.com/v2-5d0ecf40ea5b0bf74143914165ff1509_r.jpg)

市面上的 AI 数据工具有个通病：每次对话都像初见。你上周教它的口径、上个月处理过的表、上次踩过的坑，全散落在聊天记录里，风一吹就没了。

DataCrab 把“越用越聪明”做成了机制，而不是话术：

- **失败记反例，修好记正例。** 每一次报错和修复都进经验库，归纳成“常见错误 + 成功模式”，注入后续每一次任务——你踩过的坑，它不再踩。
- **好用的活会被固化。** 同类请求重复出现，系统主动建议：“要不要把这类活沉淀成技能？”从此聪明不只靠模型，更靠资产的复利。
- **它甚至自省。** 哪个技能总在失败、哪类任务总在返工，系统的学习巡检器盯着这些指标，主动提醒：该更新它了。
- **你喂给它的数据，就是它的养料。** 血缘、口径、数据描述、正反例经验——用得越久，它对你业务的理解越厚，猜得越准、干得越快。

而这一切生效只有一个前提：**把数据全交给它。** 只让它查个数，它永远是个陌生人；完整托付——让它处理、检查、记录、沉淀——每个动作才都变成学习的素材。

传统工具用十年，还是那个工具；它跟你干三个月，就是你团队的人。**你不是在用软件，你是在养一个同事。**

## **画像六：你不在的时候，它还在干活**

![](https://pic1.zhimg.com/v2-5f2c15a502b56c18611b977d84d239a0_r.jpg)

AI 产品最难的从来不是“答得对”，是“靠得住”。

- **长活不吓退它。** 二十分钟的任务说跑就跑：异步执行，启动即回应；期间你随时插话改条件，结果回来自动续上。
- **半路不死。** 进度每 3 秒落库，浏览器关了、页面刷了、后端重启了——回来任务还在原地，接着干；中断的会被标记，随时可恢复。
- **到点自己跑。** 技能转流程、流程挂调度——Cron、固定间隔、手动三种方式，晚上十点的数据同步不需要任何人守着。
- **还有个值班的。** 一只叫“寄居蟹”的体外巡检器，每分钟巡一遍系统：卡死的任务被拉起，静默的执行被标记，跑飞的后台任务逃不过它。

玩具在 Demo 里跑得飞快；工具在生产里扛得住事。**白天你指挥它，夜里它自己值班。**

## **画像七：它的能力边界，一句话就能扩展**

![](https://pic1.zhimg.com/v2-306f9c5d4c071b0662a7ee0409b351ae_r.jpg)

别的产品，能力边界由产品经理画在路线图里；DataCrab 的能力边界，长在你的对话里。

- **接一个系统没见过的数据源**：告诉它协议和接入信息，Agent 自动生成连接器代码——今天还不支持的数据源，明天就能用。
- **换一个新出的模型**：自然语言刷新模型列表，或上传一个适配器——任何 OpenAI 兼容的端点都能接进来。
- **连“性格”都可以谈**：助手的身份与风格定义在一份你随时可以改写的文档里；数据标准、质量、安全规则库同样全部开放编辑。

当然，它有红线：**AI 只动你的数据，绝不动平台自身**——对话能扩展的是它处理数据的能力，不是它的安全边界。

**别的产品等版本更新，它等你一句话。**

## **结尾**

回到开头的问题：新一代的数据智能体长什么样？

它只有对话，没有 Workflow——因为链路会长出来，不需要人画；它让人人都是数据工程师——因为工程能力变成了对话框里的默认配置；它天生保证数据正确——因为验收写在出厂设置里，不靠人兜底；它让数据演进，而非治理——因为秩序从使用中长出来；它把你的托付酿成聪明的复利——越交越多，越用越懂；你不在的时候，它还在干活——白天受指挥，夜里自己值班；它连自己的能力，都长在对话里——等你一句话，就能扩展。

数据工作的终点，不是“人人都会拖节点”，而是——

**让“把数据变干净、变可用”这件事的成本，降到一句话。**

就像螃蟹长大了要蜕壳——数据长大了，也该换一种活法。

这就是 DataCrab。
