## 一、先看结果

### 1.1 速度

![](https://pic1.zhimg.com/v2-b8ca3c785f26ac92c06be2aeaac0ce5e_1440w.jpg)

三组柱子，每组左边蓝色是这套 C++ 实现，右边橙色是 ultralytics 官方 Python 推理。测试片段是 1912×1080 的视频，imgsz 640，C++ 这边 batch=2 折算到每帧，Python 那边 batch=1：

| 阶段 | Python | 本仓库 | 倍数 |
| --- | --- | --- | --- |
| 预处理（5 步合一 kernel） | 1.380 ms | 0.043 ms | 31.8× |
| 推理 | 19.685 ms | 1.398 ms | 14.1× |
| 后处理 | 0.446 ms | 0.061 ms | 7.3× |
| 合计（不含搬运） | 21.512 ms | 1.502 ms | 14.3× |
| 合计（含 H2D） | 21.512 ms | 2.248 ms | 9.6× |

Python 那边是 CPU 版 torch，不是显卡没跑起来，是我故意用 CPU 版对拍的。拿 GPU 版 torch 比，后处理那栏它反而会好看一些（NMS 在 GPU 上做），预处理和推理还是差一个量级。

图上的柱子是纯计算，不含数据搬运。C++ 这边上传的是一整张 1912×1080 的原图，一帧 6.19 MB，走的还是 pageable 内存，光这一步就 0.68 ms，比预处理 kernel 本身贵十几倍。等后面接了 GStreamer 让解码直接落显存，这 0.68 ms 就没了，这也是下一阶段性能提升最大的一块。

还有一点得说明白：2.248 ms 折下来 445 fps，是算上那 0.68 ms 搬运的上限。真跑视频的时候达不到，瓶颈在解码线程，实测整条流水线大概 240 fps 上下（GPU 利用率只有三成左右，活都在 CPU 解码上）。别看到 445 就以为写进播放器能跑 445。

## 二、Windows环境准备

### 2.1 版本清单

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Visual Studio | 2022（17.x） | 工作负载勾“使用 C++ 的桌面开发” |
| CMake | ≥ 3.25 | 工程里写死了这个下限 |
| 显卡驱动 | 跟 CUDA 12.9 配套 | 太旧的话 CUDA 装不上 |
| CUDA Toolkit | 12.9 | 只装 Toolkit，不用装驱动 |
| OpenCV | 4.8.1 | 官方 exe 自解压包 |
| TensorRT | 10.16.1.11 | Windows amd64 zip 包 |

### 2.2 装 VS2022 和 CMake

从官网下 Community 版就行，安装器默认停在“工作负载”那一页，只需要勾一个：

![](https://pica.zhimg.com/v2-285bcf68bae14bbad2058e5de3fcb6f8_1440w.jpg)

就是图上红框那个“使用 C++ 的桌面开发”。右侧默认组件里已经带了 MSVC v143 和 Windows 10/11 SDK，不用额外加。装完重启一次。CMake 直接去官网下，版本要求 3.25 以上。

### 2.3 装 CUDA 12.9

NVIDIA 官网的 CUDA Toolkit Archive 页面找 12.9，下载 `exe (local)`，三个多 G，装的时候选“自定义”，只留 CUDA 那一组组件，Visual Studio Integration 一定要勾上。

装完开个新的 PowerShell：

```text
nvidia-smi
nvcc -V

```

`nvidia-smi` 右上角会显示驱动支持的最高 CUDA 版本，`nvcc -V` 打出 12.9 就对了。新开的窗口才能读到 `CUDA_PATH`，装完不重开窗口可能会说找不到，别急着怀疑装坏了。

### 2.4 解压 OpenCV 4.8.1

下载 `opencv-4.8.1-windows.exe`，双击，解压路径填：

```text
D:\ThirdParty

```

**不要勾 “Add to the system PATH”**。这一步只是解压，不写注册表、不改环境变量。

解压完的目录长这样：

```text
D:\ThirdParty\opencv\build\x64\vc16\
    ├── bin\      opencv_world481.dll 等
    └── lib\      opencv_world481.lib + OpenCVConfig.cmake

```

后面配置时 `-DOpenCV_DIR` 要指到 `D:\ThirdParty\opencv\build\x64\vc16\lib` 这一层，也就是 `OpenCVConfig.cmake` 所在的那层。指到 `opencv` 根目录会报 `Could not find OpenCV`，这是最常见的错。

`vc16` 是 VS2019/2022 的 ABI，MSVC 从 19.2 到 19.4 都是这个目录，VS2022 直接用没问题。

### 2.5 解压 TensorRT 10.16.1.11

下载 `TensorRT-10.16.1.11.Windows.amd64.cuda-12.9.zip`，解压到 `D:\ThirdParty`，得到：

```text
D:\ThirdParty\TensorRT-10.16.1.11\
    ├── bin\      nvinfer_10.dll、trtexec.exe
    ├── include\  NvInfer.h
    └── lib\      nvinfer_10.lib、nvonnxparser_10.lib

```

同样不跑安装程序、不加 PATH，这个版本的 TensorRT 就是绿色包。OpenCV 和 TensorRT 都别手动往系统环境变量里塞，后面 `DeployRuntime.cmake` 会把 dll 拷到 exe 旁边。

### 3.5 编译期常见错误

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| Could not find OpenCV | OpenCV_DIR 指错层 | 指到 ...\build\x64\vc16\lib |
| Could not find TensorRT | TensorRT_ROOT 里没有 include/NvInfer.h | 检查是否多套了一层目录 |
| C1083: 无法打开 cuda_runtime_api.h | 没装 CUDA，或装完没重开窗口 | echo $env:CUDA_PATH 是否有值 |
| MSB6001: 字典中已添加相同键 | 环境里同时有 HTTPS_PROXY 和 https_proxy 两个键 | 跑 CMake 之前先把小写那份清掉，Git Bash 里 unset https_proxy，PowerShell 里 Remove-Item Env:https_proxy；这机器上确实会撞 |
| 未找到 nvinfer_10.lib | TensorRT 还是 8.x 的包 | TRT 10 的库名带 _10 后缀，装错版本了 |

## 四、准备模型

### 4.0 直接onnx 文件可以自己导出，也可以直接下载我提供的载我提供的，在页面链接最下：

[https://github.com/FeiYull/TensorRT-Alpha/releases/download/v1.0.0/yolo26n.onnx](https://github.com/FeiYull/TensorRT-Alpha/releases/download/v1.0.0/yolo26n.onnx)<br>或者你也可以按照如下步骤自己导出模型。

### 4.1 手动导出onnx

Python 的 yolo 环境，一句指令的事情：

```text
pip install ultralytics

# FP32，精度对齐用这个
yolo export model=yolo26n-pose.pt format=onnx imgsz=640 batch=2 opset=17 simplify=True

```

导出文件默认落在权重旁边，叫 `yolo26n-pose.onnx`。

### 4.2 量化导出（FP16 / IN注意：TensorRT 10.x 版本后续会移除量化工具，官方建议是：用户自己在 PyTorch 端自行量化，然后导出量化版本的 onnx，最后直接用 TensorRT 进行序列化就行（这条指令后续会说）。但是，这里我还是会说，最简单的，也是最不靠谱的 PTQ 量化方式如下，ultralytics 还有更简单的 QAT 量化方法，自己可以搜下（QAT 现在是业界主流）：界主流）：

```text
yolo export model=yolo26n-pose.pt format=onnx imgsz=640 batch=2 opset=17 simplify=True quantize=16

```

文件名还是 `yolo26n-pose.onnx`，跟前一份重名，自己改成 `yolo26n-pose_fp16.onnx`。

INT8 要校准集，导出的是 Q/DQ 图，文件名自动带 `_int8` 后缀：

```text
yolo export model=yolo26n.pt format=onnx imgsz=640 batch=2 opset=17 simplify=True quantize=8 data=coco8.yaml

```

`data` 给一份 yolo 格式的 yaml，校准用的就是里面的图。coco8 只有 8 张，够跑通流程，真要上生产还是拿自己的数据集校准。

### 4.3 转成 engine

`trtexec.exe` 在 TensorRT 的 `bin` 目录里。先切过去，再执行：

```text
cd D:\ThirdParty\TensorRT-10.16.1.11\bin

# FP32，精度对齐用这个
.\trtexec.exe --onnx=D:\models\yolo26n_pose.onnx --saveEngine=D:\VS2022_Project\TensorRT-Alpha\engines\yolo26n_pose.trt --noTF32

```

`--noTF32` 是给 FP32 引擎用的，把 TF32 关掉，这样 fp32 结果不会漂。只有精度基准才需要它。

FP16 更快，引擎也小一圈。量化本身在 Python 端就做完了，这边只是换个 flag：

```text
.\trtexec.exe --onnx=D:\models\yolo26n_pose.onnx --saveEngine=D:\VS2022_Project\TensorRT-Alpha\engines\yolo26n_pose_fp16.trt --fp16

```

### 4.4 引擎文件放哪

`configs/yolo26n_pose.ini` 里已经写好了各自的引擎路径，文件名对得上就不用改：

```text
configs/yolo26n_pose.ini        -> engines/yolo26n_pose.trt

```

引擎想放别处也行，两种办法：改 ini 里的 `engine =`，或者运行时 `--engine` 指过去。`--engine` 优先级最高，会盖掉 ini 和 `--config`。

## 六、部署自己训练的模型

训练部署一个模型：假设我们使用utralyrics训练一个目标检测模型(使用别的框架训练也是同理)，有四个类别，<br>只是举个例子，流程就是这个流程。

### 6.1、训练

训练代码如下：

```text
from ultralytics import YOLO

def main():
    model = YOLO("yolo26n.pt")
    results = model.train(data="african-wildlife.yaml", epochs=100, imgsz=640)

if __name__ == '__main__':
    main()

```

训练好之后，得到权重文件：my_det_task_cls_num_4.pt

### 6.2、导出onnx

```text
from ultralytics import YOLO

model = YOLO(r"runs\detect\train-3\weights\my_det_task_cls_num_4.pt")
model.export(
    format="onnx",
    batch = 2, # 仓库代码支持多batch推理，这里设置batch为2
    imgsz=640,
    dynamic=False, 
    simplify=True,
    opset=17,
    nms=None,      # 用默认 one-to-many 头，one-to-to精度略有下降，并且本仓库的decode+nms使用cuda c实现，足够快
)

```

然后导出对应的onnx，得到：my_det_task_cls_num_4.onnx

### 6.3、使用trtexec序列化

```text
.\trtexec.exe --onnx=my_det_task_cls_num_4.onnx --saveEngine=my_det_task_cls_num_4.trt --noTF32

```

得到：my_det_task_cls_num_4.trt文件

### 6.4、新建ini格式配置文件

在仓库TensorRT-Alpha目录下

1. 将上述my_det_task_cls_num_4.trt拷贝到engines文件夹下
2. 在data/classes/目录下新建：african-wildlife.txt，用于设置我们训练时候的任务类别，我们这里是4个类别，具体类型信息如下：<br>注：buffalo 255 0 255分别表示：name of label, B, G, R；其中BGR适用于渲染时的颜色。<br>buffalo 255 0 255<br>elephant 255 0 0<br>rhino 0 255 255<br>zebra 0 255 0<br>
3. configs文件夹下新建：my_det_task_cls_num_4.ini

具体如下：注意根据情况修改：engine、class_names_file、num_class、batch_size等变量

```text
[model]
engine = engines/my_det_task_cls_num_4.trt
class_names_file = data/classes/african-wildlife.txt
num_class = 4

[input]
layout = nchw
batch_size = 2

[postprocess]
conf_thresh = 0.25
iou_thresh = 0.7
top_k = 300

```

### 6.5、执行
