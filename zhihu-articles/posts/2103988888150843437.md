我们需要的是注意力，而模型的注意力无疑是宝贵的。上下文工程和 Agent Loop 通过结构化地规范上下文的组织和生成，在时间上模拟出了不连续的智能过程。

为了让 LLM 能操作文件和指令，工具系统是这些 Agent 必不可少的一环，也是长任务中上下文占用的绝对大头。尽管工具调用返回的结果大部分是无用的，且少部分有用信息也会逐渐失去时效性，LLM 的机制本身却不允许它像人类一样方便地遗忘或淡化掉不再重要的内容。

我思考着是否能通过优化上下文生成的机制来模拟这样一类过程，适时地丢弃不再重要的信息。实际上，我希望在每一次调用主模型时，所输入的内容都预先重新组织过，以更利于工作推进，这样模型就能更好地聚焦于关键，同时也省去了因多步调用重复输入过时和无效信息造成的无意义浪费。

八月，DeepSeek Harness 发布之后，得益于它自由灵活的架构，我得以方便地开始构建相关的测试。

改动上下文不可避免地面临着缓存命中失效的问题，在早期的测试中，我选择忽略这个问题。

如果在每一轮结束后，把之前的会话记录整理成一份当前状态，连同下一次用户输入一起发给模型，并用这个状态替换此前的对话。这实际上是以更小的粒度执行常见的 compaction 命令，将直接导致迅速的记忆漂移。此外，模型对之前发生过的工具调用没有具体的格式化参照，无法在 DSH 框架下正常执行连续任务。这种方法下实测的缓存命中率平均是 41.4%，并且随会话变长持续下降，经济性算下来更差。

上面的失败我一开始认为是状态快照本身的结构问题，模型摘要也许无法良好地复现实际的任务结构和进展，无法支持活跃工作记忆和潜在的记忆之间的关系。因此我尝试固定它的结构，通过并行 LLM 分段生成当前目标、活跃任务、已完成要点、最近推进、已阻塞任务等条目。为了表示这些条目之间的结构关系，使用树形拓扑来呈现，但是随即遇到了树的维护问题。并行模型无法推断出新增分支该挂载在哪个父节点上，同时每个新增段的生命周期维护本身就依赖完整的历史理解，当前活跃的节点和新一轮对话的界限无法区分。无论使用什么规则约束或者模型分析路径都无法根本地改善这个问题。

在这些尝试中，我逐渐意识到高缓存命中率和彻底的上下文重整是相互矛盾的，工具链精简和工具记忆在缓存命中的前提下也是矛盾的。任务本身的分支结构和为了维持缓存命中而只能进行的线性后缀增加方式同样是矛盾的。约束之下，我大量地舍弃 DSH 的原生上下文流，对所有事件进行选择性遮蔽和重整。遮蔽并重整的更优结构将以仅后缀方式加入独立的状态记录文件，每轮从这个记录里编译出一份当前状态，用状态取代原生上下文。这种模式下，缓存命中率能正常地趋近 99%，上下文占用率的增长速度也大大降低，部分地实现了一开始的目标。

目前而言，插件包 rcs-context 包括上下文折叠、外部推理、转录日志和外部记忆四个插件。

上下文折叠：遮蔽原生事件，在轮次结束后识别出工具链中下一轮不必要的信息，保留指针，主模型如需要详细信息可以通过注册的相应工具展开。对每轮的主模型输出，调用并行轻模型进行语义压缩，去除为人类理解优化的结构和措辞，保留完整任务信息和关键值。

外部推理：当选择推理强度 OFF 时，在每轮主模型回复前自动 fork 一个子代理进行事先调查，以较低成本丰富主模型在无思考下的任务背景和预推理信息。

转录日志：服务于上下文折叠，为溯源提供事实依据。

外部记忆：仿照 openviking，依托数据库文件为同工作区的会话提供必要的三层外部记忆。

实测

最长的测试会话共 1,493 步，工具输出和模型回复累计 20.52 MB，会话的上下文占用中位数是 14.0%，九成时间在 22.3% 以下，峰值 44.5%。若不使用此插件，在 1M 上下文下，DSH 自带的原生压缩将已多次触发，而在插件作用下并未触发。若看所有的 62 个测试会话、总共 13,150 步，累计 157.56 MB，折叠后留在上下文里共 5.59 MB，压缩比 28 倍。按中英混排大约 3.5 字节一个 token 折算，约 4,500 万 token，相当于 45 个百万 token 窗口的内容，折叠之后占 1.6 个窗口。每个会话的中位数九成在 8.6% 以下。这意味着的确实现了更长的有效上下文窗口。

另外，如果收窄到单层语义压缩模式下，12 个测试会话共 2,869 步，50.18 MB 压到 0.96 MB，52 倍。其中最长的一个 1,482 步、24.54 MB 压到 0.68 MB，36 倍，上下文峰值 59.6%；最短的一个 333 步、8.36 MB 压到 0.03 MB，约 260 倍。

失效模式：DSH原生压缩对独立的转录日志无效，因此在触及DSH设计的压缩阈限后，遮蔽和注入原样进行，DSH的原生压缩相当于不起效。
