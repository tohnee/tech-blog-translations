模型的性能优化离不开profiling序列图分析，采集到profiling后如何阅读？在多种硬件、多类模型、不同阅读工具条件下分析profiling过程存在差异。本文主要通过两个场景帮助读者**初步了解/阅读profiling**，从而进一步去做模型训&推性能优化。

以下主要讲解推理场景下大语言基模型的profiling，相关变量：

- **硬件设备**：NPU（华为昇腾）、GPU（NVIDIA）
- **LLM模型**：Qwen（Dense）、DsV3（MoE）
- **工具**：浏览器(tracing)、Nsight(GPU)/Insight(NPU)

这些变量可以产生多种分析组合，这里挑选两种场景：

**场景一**：GPU + Qwen2.5(Dense) + tracing

**场景二**：NPU + DSV3（MoE）+ Insight(NPU)

内容包括：

1. profiling分析性能的案例。
2. 多流并行在profiling上面是如何体现？
3. 计算与通信掩盖如何分析？

## 1 GPU场景

GPU + Qwen(Dense) + tracing场景。

### 1.1 数据采集与导入

用vLLM框架运行收集profiling，示例代码如下：

```python
from vllm import LLM, SamplingParams
import torch
import torch.profiler as profiler
import os
os.environ["VLLM_WORKER_MULTIPROC_METHOD"] = "spawn"

if __name__ == "__main__":
    with profiler.profile(
        activities=[profiler.ProfilerActivity.CPU, profiler.ProfilerActivity.CUDA],
        record_shapes=True,          # 记录张量形状
        profile_memory=True,         # 记录内存分配/释放
        with_stack=False              # close 调用栈
        ) as prof:
        model_name = "/home/kaiyuan/models/Qwen2.5-7B-Instruct" 
        llm = LLM(model=model_name, dtype='float16', tensor_parallel_size=4)
        prompts = [
        "Hello, my name is",
        "The capital of France is",
        "The future of AI is",
        "Please introduce vLLM framework"
        ]
    # 设置采样参数
        sampling_params = SamplingParams(
        temperature=0.8,  # 控制生成文本的随机性，值越高越随机
        top_p=0.95,  # 控制采样范围，值越高生成文本越多样化
        max_tokens=50,  # 生成的最大 token 数量
        n=1
        )

        outputs = llm.generate(prompts, sampling_params)
    prof.export_chrome_trace("trace.json")
```

正常运行后，能够获得"trace.json"文件，直接拖拽到浏览器的[https://ui.perfetto.dev/](https://ui.perfetto.dev/) （推荐）、如果是chrome浏览器可用chrome://tracing/

![](https://pic3.zhimg.com/v2-0dbb194ba44c91498c9fde3a1907193c_r.jpg)

### 1.2 profiling阅读

profiling导入之后，可找到主机端（python层）的执行时序、GPU端（stream）的执行时序：

![](https://picx.zhimg.com/v2-db9bb573c6c147c37ab64a18385cbcc9_r.jpg)

先看一下python层执行情况。在profiling中找到序列图进行放大，我们可以定位一个完整的层的位置，比如用耗时较长的attention进行隔断，截取一段内容进行分析

![](https://pica.zhimg.com/v2-a6864c4f8dff555c6b44acf0f2dd0522_r.jpg)

Qwen2.5 dense的模型主体是**GQA+FFN**，这些层的运算在profiling中可找到对应的位置。

![](https://pic3.zhimg.com/v2-60f34097b2f9c4e70d947e85e46395e4_r.jpg)

通过放大profiling，找到GAQ在python中的时序图位置。有几个细节：

- 时序条的操作与操作之间存在空白，这并不代表执行不连续。
- 在O linear计算完成后有个all reduce操作，这是因为开启**TP并行，即**OKV矩阵运算时的权重W进行了列切分、O矩阵运算采用W行切分，最后结果需要一个all reduce校正结果。

![](https://pic3.zhimg.com/v2-c4b306e6ab93f6c94713df3f634a2362_r.jpg)

- QKV共用一个线性层，所以后面有个split操作；Q与K在算attention前需要进行RoPE运算。

![](https://pica.zhimg.com/v2-f0bcb6418c83f4dab116f017ced0b4d0_r.jpg)
*RoPE*

放大attention（图片中的unified attention）会看到许多细节操作，比如split、view、empty等，也能找到两个主要操作：KV cache保存、paged attention运算。

![](https://pica.zhimg.com/v2-aa5fb11ca1606a6c3dd238dcdf1a4476_r.jpg)

FFN层是在attention计算之后，找到RMS Norm并进行放大，看到的细节：

- 向上投影Up和门控Gate是一个线性运算；
- 由于开启了TP并行，Up&Gate的权重列切、Down的权重行切，所以需要一个all reduce操作。

![](https://picx.zhimg.com/v2-4ce2b8abb24a44310120c939f38f49a3_r.jpg)

stream层的执行情况主要是反映GPU的kernel下发下去之后的执行逻辑，通过放大同样能够找到每个上层模块触发的底层操作。如下所示为FFN的线性运算的kernel时序。

![](https://pic1.zhimg.com/v2-ed2eecaf77c02780a5d0e4f3b49f85e0_r.jpg)

- 线性层的计算调用的是cutlass的kernel：

![](https://picx.zhimg.com/v2-f0eca273d4083aa6572372e3ebbce351_r.jpg)

- silu的计算kernel如下所示，可看到输入数据的类型。

![](https://picx.zhimg.com/v2-bf941b61ce6f63cef7798aee3935858f_r.jpg)

通过测算可以捕获多个层的执行时间，如下所示捕获到一个GQA+FFN在python层的总执行耗时近七百多us。

## 2 NPU场景

NPU是华为昇腾的芯片，搭配看profiling的专用工具是Insight，GPU有对应的Nsight。用专用工具的能够看到更加细粒度的时序信息。在Insight中导入一份Profiling后可以显示多个层的时序：

- Python：上层host侧的执行情况；
- CANN：算子API执行情况（类似CUDA层）；
- AscendHardware：是NPU芯片层的情况；

还有辅助的时序：通信层Communication、通算重叠度OverlapAnalysis、AI core Freq、HBM、LLC、QoS等。

![](https://pic2.zhimg.com/v2-d587511892d36e96b0840684176a4cd1_r.jpg)

### 2.2 优化项观测

当完成一些优化后，我们可以利用时序图比照优化前后的计算差异。

**操作优化**：比如，在MoE计算完成后如果有一个AllReduce操作，能够拆解为Reducescatter + allgather，并且allgather位置可以移动到比较靠后的位置。

![](https://pica.zhimg.com/v2-78db7a247d586809cc3255789859d750_r.jpg)

**重叠度优化**：在硬件层观测时，可以看到一些优化手段带来的时序变化，这里以micro batch双流运算示例，能够看到两个stream分别执行了完整的MoE+MLA，只是时间上面有错位。

![](https://picx.zhimg.com/v2-74816f620b7b69821ad0aff775606707_r.jpg)

这样带来的好处是计算通信掩盖比例得到提升，通过Overlap Analysis时序能够看到变化：

![](https://pic2.zhimg.com/v2-6689948fd1d6df5d380dc61676a79c75_r.jpg)

### 2.3 其他辅助分析

Insight工具除了提供时序（timeline）分析，还可看更详细的内存占比、操作占比等分析，随着分析的进行，这些数据都能够比较好的帮助开发人员更好的挖掘一款硬件的潜力、或者调整模型算法的设计。

**写在最后：**

- 采集profiling会有时间膨胀问题，即某些步骤采集的执行时间会更久。
- 浏览器版的tracing的特点是方便快捷，Nsight工具特点是拆解更加详细，实践中可以根据情况选择工具。
- 本文提供的是简单阅读引导，进一步分析profiling价值信息需要有一定的模型+硬件基础，比如NPU的profiling中看到SDMA、AIV等被激活时表示什么含义，需要大致了解NPU的架构模块。
- 在性能优化是一个持续迭代过程：从粗粒度的指标(如，训练samples/s；推理tps）对比性能 -> 采集profiling，分析profiling -> 优化瓶颈点 -> 重新观测指标。 在这个迭代过程中用好profiling，发现收益最大的地方优先解决。
