## 多模态大语言模型综述 精读笔记

> 论文：A Survey on Multimodal Large Language Models <br>作者：Shukang Yin、Chaoyou Fu、Sirui Zhao、Ke Li、Xing Sun、Tong Xu、Enhong Chen <br>发表：IEEE 期刊稿件（原文首页未标注具体期刊、卷期与年份） <br>arXiv：原文未给出 | 资源：[BradyFU/Awesome-Multimodal-Large-Language-Models](https://github.com/BradyFU/Awesome-Multimodal-Large-Language-Models)

### 写在前面

如果你已经熟悉 CLIP、Transformer 和“指令微调”这三个词，可以直接从第二章的架构图看起；如果只是刚听说 GPT-4V，建议先把第一章的例子读完，再往下走。这篇综述要回答的问题很朴素：**一个能看图的聊天模型，到底是由哪些零件拼起来的、这些零件怎么训练、又该怎么评价它？**

它要解决的核心痛点有两个。第一，语言模型很强但“看不见”，视觉模型“看得见”却不太会推理，两者必须找一个接口接起来；第二，接起来之后，零件选择、训练阶段、数据配比、评测方式全都高度分散，初学者很容易被 Q-Former、MLP 投影、视觉专家、RLHF、DPO 这一串名词淹没。这篇综述的价值，就是把这些散落的零件放回同一张工程图纸上。

需要提前说明：这是一篇综述，不是方法论文，所以本笔记不写 PyTorch 实现，而是把公式、表格和分类体系讲透；这一点也会在最后的复查记录里交代。

### 一、预备知识：MLLM 到底是什么

### 1.1 一个生活中的例子

想象一场“图文同声传译”会议。台上是一位只会说中文的专家（大语言模型），台下递上来一张英文照片（图像）。专家既看不懂英文，也看不见照片，于是会议需要三个人：

1. **视觉编码器**：像一双眼睛，把照片“看”成一串机器能处理的数字特征；
2. **模态接口（connector）**：像同声传译员，把视觉特征翻译成专家能懂的语言 token；
3. **大语言模型**：像大脑，接收翻译后的内容，结合你提的问题，逐字写出回答。

有些系统还会在最后接一个**生成器**，让模型不只输出文字，还能输出图像或音频。理解了这个三人小组，你就能理解综述里绝大多数模型名：它们本质上都在换“眼睛”、换“翻译员”或换“大脑”。

这里有个很关键的类比：**Q-Former 像“摘要员”**，它用一组可学习的 query 去视觉特征里抽取重点，只把少量摘要交给大脑；**MLP 投影像“逐字直译”**，它把每个视觉 token 都线性变换后原样送进去，信息保留得多，但也没有人教它“哪些该留、哪些该丢”。后面你会看到，这个区别直接决定了幻觉表现。

### 1.2 数学表达

先把最朴素的流程写出来。给定一张图 $I$ 和一句文本指令 $T$：

```text
z = E(I)            # 视觉编码器把图像压成特征
H = C(z)            # 连接器把视觉特征映射成 LLM 可读的 token
R ~ p(R | H, T; θ)  # LLM 以视觉 token 和指令为条件，自回归生成回答
```

其中 $E$ 是编码器，$C$ 是连接器，$\theta$ 是 LLM 参数。综述把“模型给出答案”这件事写成：

```text
A = f(T, M; θ)                                  （式 1）
```

$T$ 是指令（instruction），$M$ 是多模态输入（multimodal input），$A$ 是预测答案。这个式子的意思是：**答案不是从图像直接“分类”出来的，而是在“指令 + 多模态输入”的条件下生成出来的**。这正是 MLLM 与传统视觉模型最不一样的地方。

训练时，模型要最大化标准答案 $R$ 的似然，也就是最小化负对数似然：

```text
L(θ) = - Σ_{i=1}^{N} log p(R_i | Z, R_{<i}; θ)   （式 2）
```

$N$ 是答案长度，$R_{<i}$ 是第 $i$ 个 token 之前已经生成的 token，$Z$ 是包括视觉 token 在内的上下文。**逐字解释**：模型每预测一个词，都要在“已经看到的历史”和“图像上下文”条件下给出概率；把所有词的概率取对数再相加，就是整段回答的得分；取负号就变成越小越好的损失。

到了对齐阶段，综述给了三个式子。奖励模型要学会给人类偏好的回答 $y_w$ 更高分、给不被偏好的 $y_l$ 更低分：

```text
L(θ) = - E[ log σ( r_θ(x, y_w) - r_θ(x, y_l) ) ]   （式 3）
```

$\sigma$ 是 sigmoid，把“两个回答的分数差”压到 0 到 1 之间。差得越大，损失越小。接着用 PPO 优化策略，并加一个 KL 惩罚，防止模型为了拿奖励而偏离原模型太远：

```text
L(φ) = - E[ r_θ(x, y) - β · KL( π_φ^RL(y|x) || π^REF(y|x) ) ]   （式 4）
```

$β$ 控制“听话”和“别跑偏”的平衡。DPO 则跳过显式奖励模型，直接拿偏好对做二分类式的优化：

```text
L(φ) = - E[ log σ( β log(π_φ^RL(y_w|x) / π^REF(y_w|x))
                 - β log(π_φ^RL(y_l|x) / π^REF(y_l|x)) ) ]   （式 5）
```

你不需要背下这三个式子，只要记住它们各自回答的问题：**式 3 学“什么是好回答”，式 4 学“怎么生成好回答但别忘本”，式 5 把这两步压成一步。**

### 二、领域脉络与分类体系：一张图纸看全 MLLM

### 2.1 整体架构

![](https://pic1.zhimg.com/v2-5f4993c584b5f19823b3f16ab5f118bc_r.jpg)

**图 2 解读**：从左到右看，最左边是图像/音频/视频输入，经过**编码器**变成特征；中间是**连接器**，图里画了三种典型结构——MLP 投影、Q-Former 查询、多头注意力融合；右边是**LLM**，最后还可以挂一个可选的**生成器**。图下方强调了一件重要的事：前两种连接器属于 **token-level fusion**，即把视觉特征变成 token，和文本 token 拼在一起送进 LLM；第三种属于 **feature-level fusion**，即把视觉特征作为额外的一路，在 LLM 内部与文本特征做交叉注意力。你只要盯住“视觉信息是在 LLM 外面拼好再进去，还是在 LLM 里面逐层融合”，就能快速判断一个模型属于哪一类。

### 2.2 模块一：模态编码器

综述先给了一张常用图像编码器表（原文 Table 1）。我把关键列整理如下：

| 编码器 | 预训练语料 | 分辨率 | 样本量（B） | 参数量（M） |
| --- | --- | --- | --- | --- |
| OpenCLIP-ConvNext-L | LAION-2B | 320 | 29 | 197.4 |
| CLIP-ViT-L/14 | OpenAI WIT | 224⁄336 | 13 | 304.0 |
| EVA-CLIP-ViT-G/14 | LAION-2B、COYO-700M | 224 | 11 | 1000.0 |
| OpenCLIP-ViT-G/14 | LAION-2B | 224 | 34 | 1012.7 |
| OpenCLIP-ViT-bigG/14 | LAION-2B | 224 | 34 | 1844.9 |

**几个关键观察**：

- **编码器不是越大越好，分辨率往往更值钱。** 原文明确说，很多工作经验性地验证了提高输入分辨率能带来显著收益，而参数规模和预训练数据组成的重要性反而低于分辨率（原文引用 MM1 等工作的结论）。
- **“预对齐”能省很多事。** CLIP 系列在图文对上预训练过，视觉特征已经和文本语义对齐，所以后面只需要较少的对齐预训练就能接上 LLM；这也是为什么大量 MLLM 直接拿 CLIP/EVA-CLIP 当眼睛。
- **架构不只有 ViT。** Osprey 用卷积式的 ConvNext-L 换取更高分辨率和多层级特征；Fuyu-8B 干脆不要独立编码器，把图像 patch 直接投影后送进 LLM，从而天然支持灵活分辨率。这说明“眼睛”的形态仍在演化。

分辨率扩展有两条路线，综述讲得很清楚：**直接放大**（把更高分辨率图直接喂给编码器，或换更高分辨率的预训练编码器；CogAgent 用高低分辨率双编码器，高分辨率特征通过交叉注意力注入低分辨率分支）和**切块**（Monkey、SPHINX 把大图切成小 patch，再把子图与一张降采样全图一起送入编码器，分别捕捉局部与全局）。这两种路线的共同点是：不改变 LLM，只改变“眼睛看到多少细节”。

### 2.3 模块二：预训练 LLM

第二张表是常用开源 LLM（原文 Table 2）：

| 模型 | 发布 | 预训练数据 | 参数（B） | 语言 | 架构 |
| --- | --- | --- | --- | --- | --- |
| Flan-T5-XL/XXL | 2022-10 | 原文未给 | 3⁄11 | en、fr、de | Encoder-Decoder |
| LLaMA | 2023-02 | 1.4T tokens | 7/13/33/65 | en | Causal Decoder |
| Vicuna | 2023-03 | 1.4T tokens | 7/13/33 | en | Causal Decoder |
| LLaMA-2 | 2023-07 | 2T tokens | 7/13/70 | en | Causal Decoder |
| Qwen | 2023-09 | 3T tokens | 1.8/7/14/72 | en、zh | Causal Decoder |

> 数据来源：原文 Table 2。

**几个关键观察**：

- **因果解码器是绝对主流。** 除 Flan-T5 外，表里的模型都跟随 GPT-3 的 causal decoder 路线；BLIP-2、InstructBLIP 是较早使用 Flan-T5 的代表，而 LLaMA/Vicuna 系列则支撑了学术界大量开源 MLLM。
- **语言覆盖是一个现实约束。** LLaMA 和 Vicuna 主要在英文语料上预训练，中文能力有限；Qwen 是中英双语，所以很多中文 MLLM 选它当大脑。
- **放大 LLM 仍然有收益。** 原文引用的实验显示，从 7B 提到 13B 能在多个 benchmark 上全面提升；用到 34B 时，即使只用英文多模态数据训练，模型也出现了零样本中文能力；从 13B 提到 35B/65B/70B 也有一致增益。这说明“大脑”的规模红利还没有完全消失。
- **小模型和 MoE 是两条支线。** MobileVLM 用 1.4B/2.7B 的 MobileLLaMA 面向移动端；MM1 和 MoE-LLaVA 则用稀疏专家，在不显著增加计算量的前提下扩大总参数，并在几乎所有 benchmark 上优于稠密 counterpart。

### 2.4 模块三：模态接口

这是全篇最值得反复看的一节，因为“接口怎么设计”直接决定模型能不能保住细粒度信息。综述把它分成两大类：

| 类型 | 代表做法 | 信息流 | 优点 | 代价 |
| --- | --- | --- | --- | --- |
| Token-level，查询式 | BLIP-2、InstructBLIP 的 Q-Former | 用一组可学习 query 从视觉特征中抽取少量向量 | 压缩率高，视觉 token 少 | 查询会丢细粒度信息 |
| Token-level，投影式 | LLaVA 的一层/两层线性 MLP | 每个视觉 token 线性投影后与文本拼接 | 实现简单，信息保留多 | 投影特征缺少监督，分布可能对不齐 |
| Feature-level | Flamingo 的 cross-attention、CogVLM 的 visual expert、LLaMA-Adapter 的 prompt | 在 LLM 内部插入模块，让视觉与文本逐层交互 | 融合更深，表达更强 | 结构复杂，超参更难调 |
| 专家模型转换 | VideoChat-Text 等 | 先用外部模型把视频/图像转成文字 | 不需要训练接口 | 转换会丢信息，时空关系会被扭曲 |

**几个关键观察**：

- **接口参数量通常很小。** 以 Qwen-VL 为例，Q-Former 约 0.08B，占整体不到 1%；编码器约 1.9B，占 19.8%；LLM 约 7.7B，占 80.2%。所以“接口设计”不是靠堆参数取胜，而是靠信息路由方式。
- **“适配器类型”可能没有你想的那么重要。** MM1 的消融发现，在 token-level 融合里，适配器类型远不如**视觉 token 数量**和**输入分辨率**重要。换句话说，给模型更多、更清晰的视觉 token，往往比换一个更花哨的投影器更有效。
- **token-level 与 feature-level 谁更好，原文没有一边倒。** Zeng 等的实验显示 token-level 在 VQA 类 benchmark 上更好；作者推测 cross-attention 类模型需要更复杂的超参搜索才能达到可比性能。这是一个“工程调参 vs 结构上限”的典型争论，读的时候不要把它当成定论。
- **“转成文字”是最省事但最不灵活的路。** VideoChat-Text 用预训练视觉模型抽取动作等信息，再用语音识别模型丰富描述；好处是不用训练接口，坏处是视频转文字会扭曲时空关系。这解释了为什么后来大家都转向可学习连接器。

### 2.5 训练三阶段：预训练、指令微调、对齐微调

综述把完整训练配方拆成三个阶段，每个阶段解决不同问题。这个划分非常重要，因为很多“模型效果不好”的问题，其实是阶段目标错配。

**第一阶段：对齐预训练。** 目标是让不同模态对齐，并注入多模态世界知识。最常见的数据是 caption 对，模型看着图像自回归预测描述，用标准交叉熵。原文 Table 3 给的模板极简：

```text
Input: <image>
Response: {caption}
```

关键细节是：**只对回答部分计算损失**，图像 token 不参与 loss。工程上通常冻结视觉编码器和 LLM，只训练连接器；也有工作解冻视觉编码器以换取更强的对齐。原文还给了一个很实用的经验：短而噪声大的 caption 可以用较低分辨率（如 224）加速训练；更长、更干净的数据则适合更高分辨率（如 448 以上）来减轻幻觉。ShareGPT4V 还发现，预训练阶段用高质量 caption 时，解冻视觉编码器能带来更好的对齐。

预训练数据分粗粒度与细粒度两类（原文 Table 4）：

| 数据集 | 样本量 | 时间 |
| --- | --- | --- |
| CC-3M | 3.3M | 2018⁄2020 |
| CC-12M | 12.4M | — |
| SBU Captions | 1M | 2011 |
| LAION-5B | 5.9B | 2022-03 |
| LAION-2B | 2.3B | 2022-03 |
| LAION-COCO | 600M | 2022-09 |
| COYO-700M | 747M | 2022-08 |
| ShareGPT4V-PT | 1.2M | 2023-11 |
| LVIS-Instruct4V | 111K | 2023-11 |
| ALLaVA | 709K | 2024-02 |
| MSR-VTT（视频-文本） | 200K | 2016 |
| WavCaps（音频-文本） | 24K | 2023-03 |

> 数据来源：原文 Table 4。

**几个关键观察**：

- **粗粒度数据靠“量”，细粒度数据靠“质”。** CC、SBU、LAION 系列动辄百万到十亿级，但 caption 多来自网页 alt-text，短且噪声大；ShareGPT4V-PT、LVIS-Instruct4V、ALLaVA 则是用强 MLLM（如 GPT-4V）生成的长描述，量小但更准确，能带来更细粒度的对齐。
- **清洗策略决定了数据能不能用。** 例如 CC-3M 会过滤不合适内容/长宽比、用 NLP 工具做文本标注、再用分类器检查图文标签是否重叠；LAION 会用 CLIP 相似度过滤低质量图文对；COYO-700M 还会用 pHash 去重，避免和 ImageNet、MS-COCO 重叠。这些细节说明“数据规模”从来不是唯一变量。
- **成本换质量是有上限的。** 用商业 MLLM 生成细粒度 caption 成本高、数据量小；ShareGPT4V 的折中办法是先用 GPT-4V 生成 10 万条训练一个 captioner，再用这个 captioner 把数据扩到 1.2M。这是一个很值得借鉴的“教师模型蒸馏数据”的工程套路。

**第二阶段：多模态指令微调。** 目标是教模型“听懂任务”，从而泛化到没见过的指令。综述用图 3 对比了三种学习范式：

![](https://pic3.zhimg.com/v2-ddb6c171951935dc1a3282d35616239c_r.jpg)

**图 3 解读**：左边是传统的“预训练 + 任务特定微调”，每个任务都要单独训练一个模型；中间是“提示学习”，不更新或少量更新参数，靠 prompt 把任务描述给模型；右边是“指令微调”，用大量“指令—输入—输出”样本训练，让同一个模型学会跟着新指令走。图想表达的是：指令微调不是拟合某一个任务，而是学习“如何理解任务”这件事本身。

指令样本通常写成三元组 $(I, M, R)$：指令、 多模态输入、标准回答。训练目标还是式 2 的自回归损失。综述给了几个模板（原文 Table 5、Table 6），核心格式是：

```text
Below is an instruction that describes a task.
Instruction: <instruction>
Input: {<image>, <text>}
Response: <output>
```

VQA 数据的模板则更短，例如 `<Image> Question: {Question}`、`<Image> Q: {Question} A:`。这里有个容易忽略的坑：**原始 VQA/caption 答案通常很短，直接拿来指令微调会把模型的输出长度“压短”**。有两种补救：在指令里明确写“简短回答”或“一句话”，或者像 M³IT 那样用 ChatGPT 把原答案改写成更长的版本。

指令数据的收集有三条路：**数据适配**（把现有 VQA/caption 数据集改写成指令格式）、**自我指令**（用少量手写样例提示 ChatGPT/GPT-4 生成更多数据；LLaVA 先把图像转成 caption 和 bounding box，再让纯文本 GPT-4 生成多模态指令）、**数据混合**（把纯语言对话数据和多媒体指令数据混在一起，提升对话能力）。常用数据集见原文 Table 7：

| 数据集 | 样本量 | 模态 | 来源 | 组成 |
| --- | --- | --- | --- | --- |
| LLaVA-Instruct | 158K | 图+文→文 | MS-COCO | 23K caption + 58K 多轮 QA + 77K 推理 |
| LVIS-Instruct | 220K | 图+文→文 | LVIS | 110K caption + 110K 多轮 QA |
| ALLaVA | 1.4M | 图+文→文 | VFlan、LAION | 709K caption + 709K 单轮 QA |
| Video-ChatGPT | 100K | 视频+文→文 | ActivityNet | 7K 描述 + 4K 多轮 QA |
| VideoChat | 11K | 视频+文→文 | WebVid | 描述、总结、创作 |
| Clotho-Detail | 3.9K | 音频+文→文 | Clotho | caption |

> 数据来源：原文 Table 7。

**几个关键观察**：

- **LLaVA-Instruct 的配比很有代表性。** 158K 里只有 23K 是 caption，剩下的 135K 是多轮 QA 和推理数据；这说明指令微调的重点不是“描述图像”，而是“用图像完成任务”。
- **数据质量可能比数量更重要。** 原文引用 Lynx 的发现：在大规模但有噪声的图文对上预训练的模型，表现不如在更小但更干净的数据上训练的模型；也有工作发现更少但更高质量的指令数据能取得更好效果。
- **提示多样性和任务覆盖是两个独立维度。** Lynx 验证了多样化 prompt 能提升性能和泛化；Du 等发现视觉推理任务比 caption/QA 更能提升模型表现，而且**提高指令复杂度可能比增加任务多样性、加入细粒度空间标注更有益**。这条结论对实际做数据配比很有指导意义。

**第三阶段：对齐微调。** 目标是让模型行为符合人类偏好，典型应用是减少幻觉。两条技术路线是 RLHF 和 DPO，公式就是前面的式 3、4、5。RLHF 分三步：监督微调得到策略模型、用偏好对训练奖励模型、用 PPO 加 KL 惩罚优化策略；DPO 则直接用偏好对做二分类式优化，省掉显式奖励模型。对齐数据通常比前两个阶段少得多（原文 Table 8）：

| 数据集 | 样本量 | 模态 | 来源 |
| --- | --- | --- | --- |
| LLaVA-RLHF | 10K | 图+文→文 | 人类反馈 |
| RLHF-V | 5.7K | 图+文→文 | 人类细粒度反馈 |
| VLFeedback | 380K | 图+文→文 | GPT-4V 评分 |

> 数据来源：原文 Table 8。

**几个关键观察**：

- **对齐数据的“粒度”在变细。** LLaVA-RLHF 是 10K 人类偏好对，主要针对诚实性和有帮助性；RLHF-V 只有 5.7K，但是 segment-level 的幻觉纠正，做的是更稠密的 DPO；VLFeedback 则用 GPT-4V 从 helpfulness、faithfulness、伦理三个维度打分成 380K 比较对。数量从 10K 到 380K，但“谁给的反馈、反馈有多细”才是关键变量。
- **对齐阶段的数据量远小于预训练。** 这符合直觉：预训练学“世界知识”，指令微调学“任务格式”，对齐微调只学“偏好方向”，不需要海量数据。
- **对齐不是万能药。** 综述在后面讨论幻觉时也指出，MLLM 的训练流程里常常缺少 RLHF 阶段，这是幻觉的成因之一；但有了 RLHF 也不代表幻觉消失，因为奖励模型本身也可能被语言先验带偏。

### 三、代表性方法对比：同一张图纸上的不同选择

把前面的零件组合起来，就能得到一张“方法对比表”。下表只填综述明确提到的结构特征，不补充原文没有的参数：

| 方法 | 视觉编码器 | 连接器 | LLM | 关键特点 |
| --- | --- | --- | --- | --- |
| BLIP-2 | CLIP/EVA-CLIP 类 | Q-Former（查询式） | Flan-T5 等 | 用少量 query 压缩视觉 token，是查询式接口的代表 |
| InstructBLIP | CLIP/EVA-CLIP 类 | Q-Former | Flan-T5/LLaMA 类 | 在 BLIP-2 上做指令微调，强调指令感知的视觉特征提取 |
| LLaVA | CLIP-ViT-L/14 | 一层/两层线性 MLP | Vicuna | 投影式接口的代表，结构极简、数据驱动 |
| MiniGPT-4 | EVA-CLIP ViT-G/14 | Q-Former | Vicuna | 用更强的视觉编码器 + 查询式接口 |
| mPLUG-Owl | ViT | visual abstractor | LLaMA 类 | 用可学习 abstractor 压缩视觉信息 |
| Flamingo | 视觉编码器 | 交叉注意力层（feature-level） | 冻结 LLM | 在 LLM 层间插入 cross-attention，支持多图/视频上下文 |
| CogVLM | 视觉编码器 | visual expert（feature-level） | 预训练 LLM | 每层插入视觉专家，QKV 从 LLM 初始化，深层次双向融合 |
| LLaMA-Adapter | 视觉编码器 | 可学习 prompt（feature-level） | LLaMA | 把视觉知识嵌入 prefix prompt，轻量适配 |
| Qwen-VL | 视觉编码器 | Q-Former（约 0.08B） | Qwen-7.7B | 接口占比不到 1%，中英双语 |
| MM1 | 视觉编码器 | token-level 适配器 | MoE LLM | 系统消融显示 token 数与分辨率比适配器类型更重要 |
| MobileVLM | 轻量编码器 | 轻量投影 | MobileLLaMA 1.4B/2.7B | 面向移动端部署 |

**几个关键观察**：

- **“极简接口 + 大模型 + 好数据”是被验证得最充分的一条路。** LLaVA 只用线性 MLP，却因为指令数据和训练配方成为影响力最大的开源基线之一；这说明接口复杂度不是护城河，数据和训练策略才是。
- **feature-level 融合更像“深度改造大脑”。** Flamingo 和 CogVLM 都要在 LLM 内部插入新模块，CogVLM 还特意把视觉专家模块的 QKV 从预训练 LLM 初始化，以保住语言能力。这类方法上限可能更高，但工程复杂度和调参成本也更高。
- **接口占比小，不代表作用小。** Qwen-VL 的 Q-Former 只占不到 1% 参数，却决定了视觉信息以什么粒度进入 LLM；这提醒我们看模型时不要只数参数量，要看“信息在哪儿被压缩、在哪儿被丢掉”。

### 四、“完整模型”的配方：如果让你从零搭一个 MLLM

综述没有给端到端代码，但把配方讲得很完整。把它翻译成工程步骤，大致是：

1. **选眼睛**：优先选已经和文本对齐过的编码器（CLIP/EVA-CLIP），先确定分辨率预算；如果任务需要细粒度小字、图表，优先考虑高分辨率或切块方案，而不是一味换更大的编码器。
2. **选接口**：想要视觉 token 少、推理便宜，用 Q-Former 查询式；想要信息保留多、实现简单，用 MLP 投影；想要更深融合，再考虑 cross-attention 或 visual expert。
3. **选大脑**：英文场景 LLaMA/Vicuna 系生态最全；中文场景优先 Qwen；移动端看 MobileLLaMA；想扩参不增算力，考虑 MoE。
4. **第一阶段对齐预训练**：冻结编码器和 LLM，只训接口；数据从粗粒度 caption 起步，逐步混入高质量细粒度 caption；短噪声数据用低分辨率，长干净数据用高分辨率。
5. **第二阶段指令微调**：把 VQA/caption 数据改写成指令格式，混入多轮对话和推理数据；注意答案长度偏差，必要时改写或扩写答案；控制 prompt 多样性和任务覆盖。
6. **第三阶段对齐微调**：如果目标是减少幻觉或提升有用性，收集偏好对，用 RLHF 或 DPO；数据量不必大，但反馈要细。
7. **评测**：闭集任务看 Accuracy/CIDEr 等指标，开集任务看人工评分、GPT 评分和 case study；不要只用单一 benchmark 下结论。

这个配方最容易被忽略的是第 4 步和第 5 步之间的“数据质量闸门”。综述反复强调：**预训练数据决定模型“看得清不清”，指令数据决定模型“会不会做事”，对齐数据决定模型“说不说真话”**。三个阶段的目标不同，不能用同一套数据一锅炖。

### 五、评测、幻觉与扩展技术：综述的三条延长线

### 5.1 评测：闭集与开集

综述把评测分成两类。**闭集（closed-set）** 是答案选项有限的任务，比如 ScienceQA 的准确率、NoCaps/Flickr30K 的 CIDEr；评测设置可以是零样本，也可以是微调。**开集（open-set）** 是聊天式、答案自由的任务，评判方式包括人工评分、GPT 评分和案例研究。

几个关键点：

- **MME** 包含 14 个感知与认知任务，所有指令—答案对人工设计，以避免数据泄漏；
- **MMBench** 用 ChatGPT 把开放式回答匹配到预定义选项，从而把开集回答转成可计算的分数；
- **POPE** 专门评对象幻觉，把“图里有没有这个物体”变成是/否二分类；
- **GPT 评分有一个硬伤**：纯文本 GPT-4 看不到图，只能基于 caption 或 bounding box 评判，把它当性能上界是有问题的；GPT-4V 出现后，Woodpecker 等工作改用能看图的 GPT-4V 做评判，才部分缓解了这个问题。

这段对我的提醒是：**评测方式本身会改变结论**。同一组模型，用闭集准确率排和用 GPT 评分排，名次可能不一样；读 benchmark 数字时一定要看“谁在评、看没看到图”。

### 5.2 幻觉：三类表现、三阶段缓解

综述把多模态幻觉分成三类：**存在幻觉**（说了图里没有的物体）、**属性幻觉**（物体类别对，但颜色/形状/材料等属性错）、**关系幻觉**（物体都在，但位置或交互关系错）。评测方法包括 CHAIR、POPE、MME、HaELM、Woodpecker、FaithScore、AMBER 等；缓解方法可以按干预时机分成三阶段：

| 干预时机 | 代表方法 | 做法 |
| --- | --- | --- |
| 纠正前（pre-correction） | LRV-Instruction、LLaVA-RLHF | 用负样本指令或人类偏好数据，让模型提前学会“不要乱说” |
| 生成中（in-process） | HallE-Switch、VCD、HACL | 在解码或前向过程中对比、校准、抑制语言先验 |
| 纠正后（post-correction） | Woodpecker、LURE | 生成完再检测、定位、改写幻觉内容 |

**几个关键观察**：

- **“负样本”是最便宜的纠偏手段。** LRV-Instruction 在指令数据里加入“图里没有这个物体”的负向指令，直接教模型识别不存在的东西；这比事后检测简单得多。
- **解码时对比很流行，但依赖一个“坏参照”。** VCD 用原图和失真图做对比解码，本质是放大“只有看到原图才会产生的 token”；这类方法不需要训练，但参照图怎么构造会显著影响效果。
- **事后纠正适合做“最后一道闸”。** Woodpecker 用关键概念抽取、问题生成、视觉知识验证、视觉 claim 生成、幻觉纠正五个阶段，把检测和改写拆开；LURE 则训练一个专门的 revisor。它们的共同缺点是增加了推理链路和延迟。

### 5.3 扩展技术与挑战

综述最后讲了三项扩展技术：**M-ICL**（多模态上下文学习，把示例图文对放进 prompt 提升少样本性能）、**M-CoT**（多模态思维链，分单链/树状、自适应/预定义长度、infilling/predicting 等配置）、**LAVR**（LLM 辅助视觉推理，把 LLM 当控制器、决策者或语义精炼器）。这三者都不是新架构，而是“怎么用模型”的方法论。

挑战部分列了长上下文、复杂指令遵循、M-ICL/M-CoT 仍弱、具身智能、安全等问题。站在今天回看，这些方向在 2024 年之后确实都成了热点，说明综述的判断是准的。

### 六、深度思考：这篇综述为什么重要，又漏了什么

### 6.1 它 vs 传统多模态模型：本质差异在哪

1. **优化目标从“判别”变成“生成”。** CLIP 这类模型学的是图文匹配，输出是相似度；MLLM 学的是在指令条件下逐 token 生成答案。前者像选择题，后者像问答题，后者能表达的东西多得多，但也更容易“编”。
2. **知识来源从“任务数据”变成“预训练世界知识”。** MLLM 的很多能力不是从多模态数据里学来的，而是从 LLM 的文本预训练里带出来的；这解释了为什么 34B 模型只用英文多模态数据也能冒中文能力，也解释了为什么语言先验会压过视觉证据。
3. **训练范式从“单阶段监督”变成“三阶段配方”。** 对齐预训练、指令微调、偏好对齐各有各的目标和数据，任何一段缺失或错配都会在最终表现里留下痕迹。传统 VLM 很少需要这么长的流水线。

### 6.2 历史定位

这是较早系统梳理 MLLM 的综述之一（原文自称“据我们所知是第一篇 MLLM 综述”），它提出的“编码器—连接器—LLM”三模块框架、三阶段训练划分、以及“粒度/模态/语言/场景”四类扩展，后来被大量论文和博客沿用。它的价值不在于提出某个新方法，而在于**给了一个能容纳快速演化方法的稳定坐标系**：新模型出来时，你可以很快判断它换的是眼睛、接口还是大脑，改的是哪个训练阶段。

### 6.3 局限与遗留问题

- **领域变化太快，综述天然滞后。** 文章覆盖到 2024 年初，之后出现的原生多模态、统一理解生成、超长视频等路线只能部分映射到它的分类里。
- **缺少定量元分析。** 它汇总了表格和结论，但没有做跨论文的统一复现或统计比较；很多“某方法更好”的结论来自不同实验设置，不能直接横比。
- **连接器之争没有定论。** token-level vs feature-level、Q-Former vs MLP 的优劣，原文给的是“取决于任务和调参”的开放结论，读者如果只记住“MLP 更简单”可能会误判。
- **评测章节偏“地图”，偏“裁判”。** 它列了 benchmark，但没有深入讨论 benchmark 本身的偏差、污染和饱和问题；这个问题在评测综述里才被系统展开。
- **安全、具身、长上下文只点到为止。** 这些方向在原文写作时刚起步，综述只能给方向，不能给答案。

### 七、对我的启发

1. **先定“信息在哪儿丢”，再定结构。** 如果你的任务需要读小字、看图表，优先提高分辨率或切块，而不是换更大的 LLM；如果任务需要复杂推理，优先换更强的大脑；接口只在“视觉 token 预算”和“融合深度”之间做取舍。
2. **把数据质量当成一等公民。** 综述里 Lynx 的结论很值得贴在墙上：大规模噪声数据不如小规模干净数据。做指令微调时，先做数据清洗和去重，再谈扩量。
3. **负样本是低成本的幻觉疫苗。** 与其等模型生成后再纠，不如在指令数据里主动加入“图里没有 X”“这个属性不对”的样本，让模型学会说“不”。
4. **评测要交叉验证。** 闭集分数、GPT 评分、人工 case study 各看一面；尤其是 GPT 评分，要确认裁判是否真的看到了图。
5. **别把综述的分类当教条。** 三阶段、三模块是很好的沟通框架，但真实模型经常跳过某个阶段或混用多种接口；读论文时要回到它的训练细节，而不是只看它自称属于哪一类。

| 术语 | 英文 | 一句话解释 |
| --- | --- | --- |
| 多模态大语言模型 | MLLM | 以 LLM 为大脑、能接收并推理多模态信息的大模型 |

| 交叉注意力 | cross-attention | 让文本特征在 LLM 内部逐层关注视觉特征的融合方式 |

| 对齐微调 | alignment tuning | 用人类偏好数据让模型行为符合期望的阶段 |

| 闭集/开集评测 | closed-set / open-set | 答案有限可选 vs 自由生成的两类评测设置 |

### 九、延伸阅读

1. **BLIP-2**：Q-Former 查询式接口的源头，理解“少量 query 如何压缩视觉信息”必读。
2. **LLaVA**：极简 MLP 投影 + 指令数据的代表，是大多数开源 MLLM 的起点。
3. **Flamingo**：feature-level 交叉注意力的代表，理解“在 LLM 内部融合”这条路线。
4. **MM1**：系统消融了编码器、连接器、token 数、分辨率等设计，本文很多“哪个因素更重要”的结论来自这类工作。
5. **LLaVA-RLHF / RLHF-V**：多模态偏好对齐的两个关键节点，分别代表“人类偏好对”和“细粒度幻觉纠正”。
