## TensorRT是什么

可以把TensorRT看成只有前向传播的深度学习框架，只能用来推理

TensorRT 的流程大致分为两个阶段：<br>首先是构建和优化阶段，在此期间会对模型进行一系列优化并将其序列化为 engine 文件；<br>其次是推理阶段，在这里我们会加载 engine 文件，创建运行时环境，并执行推理操作。这种方法确保了即使在资源受限的环境中也能高效地运行深度学习模型。

### 1. 模型导入和解析

加载 ONNX 模型，并通过 TensorRT 的 ONNX 解析器将其解析为网络定义。

```cpp
#include <NvInfer.h>
#include "NvOnnxParser.h"
#include <fstream>
#include <iostream>

using namespace nvinfer1;

// 定义日志记录器
class Logger : public ILogger {
public:
    void log(Severity severity, const char* msg) noexcept override {
        if (severity != Severity::kINFO)
            std::cout << msg << std::endl;
    }
} gLogger;

void checkStatus(bool status, const std::string& message) {
    if (!status) {
        std::cerr << "Error: " << message << std::endl;
        exit(-1);
    }
}

int main() {
    // 创建构建器和网络定义
    IBuilder* builder = createInferBuilder(gLogger);
    INetworkDefinition* network = builder->createNetworkV2(0U);
    checkStatus(builder != nullptr && network != nullptr, "Failed to create builder or network.");

    // 创建 ONNX 解析器并加载 ONNX 模型
    IOnnxParser* parser = createParser(*network, gLogger);
    checkStatus(parser != nullptr, "Failed to create parser.");

    std::ifstream file("model.onnx", std::ios::binary | std::ios::ate);
    long size = file.tellg();
    file.seekg(0, std::ios::beg);
    std::vector<char> modelStream(size);
    checkStatus(file.read(modelStream.data(), size), "Failed to read model file.");
    file.close();

    parser->parseFromBuffer(modelStream.data(), size);
    parser->destroy();

    // 确保网络中至少有一个输入和一个输出
    checkStatus(network->getNbInputs() > 0 && network->getNbOutputs() > 0, "Invalid network configuration.");

```

### 2. 构建优化器 (Builder)

配置构建器以适应目标硬件平台，根据具体需求和硬件环境，选择合适的优化策略和参数，如设置精度模式（FP32、FP16 或 INT8）、选择优化算法等，构建 TensorRT 优化器。

```cpp
    // 设置优化配置
    builder->setMaxBatchSize(1); // 根据实际需求调整批处理大小
    IBuilderConfig* config = builder->createBuilderConfig();
    checkStatus(config != nullptr, "Failed to create builder config.");

    // 设置最大工作空间大小
    config->setMaxWorkspaceSize(1 << 30); // 例如，1GB的工作空间

    // 启用 FP16 精度（如果 GPU 支持）
    #if defined(__CUDA_ARCH__) && __CUDA_ARCH__ >= 700
    config->setFlag(BuilderFlag::kFP16);
    #endif

    // 如果需要 INT8 精度，请确保你有校准数据集，并相应地配置量化参数
    // config->setFlag(BuilderFlag::kINT8);
    // ICudaEngine* engine = builder->buildEngineWithConfig(*network, *config, calibrator);

    // 构建引擎
    ICudaEngine* engine = builder->buildEngineWithConfig(*network, *config);
    checkStatus(engine != nullptr, "Failed to build engine.");

```

### 3. 序列化优化后的模型 (Engine 文件)

一旦构建完成，优化后的模型会序列化保存为所谓的“engine”文件。engine 文件包含了经过优化后的模型结构、参数以及针对当前设备和环境的特定执行信息，可以在以后快速加载并用于推理。因为优化过程是计算密集型的，所以通常只会在部署前执行一次，并将结果保存下来。

```cpp
    // 序列化引擎并保存到磁盘
    IHostMemory* modelStream{nullptr};
    checkStatus(engine->serialize(&modelStream), "Failed to serialize engine.");
    std::ofstream p("model.engine", std::ios::binary);
    checkStatus(p.write(static_cast<char*>(modelStream->data()), modelStream->size()), "Failed to write engine file.");
    modelStream->destroy();

    // 清理资源
    network->destroy();
    config->destroy();
    engine->destroy();
    builder->destroy();
}

```

### 4. 反序列化与创建运行时环境

在进行推理时，首先从硬盘上读取之前保存的 engine 文件，并进行反序列化操作，将其还原为可执行的模型结构和参数，同时创建 runtime 运行时引擎。这个运行时引擎是 TensorRT 在当前设备上进行高效推理的核心组件，它包含了针对该设备的优化后的计算图和执行计划。

在实际应用中，我们会从磁盘读取之前保存的 engine 文件，并反序列化回内存中的 CUDA 引擎对象。然后使用 TensorRT 的 `IRuntime` 接口创建运行时环境，准备执行推理任务。

```cpp
int main() {
    // 加载序列化的引擎文件
    std::ifstream file("model.engine", std::ios::binary);
    file.seekg(0, file.end);
    long fsize = file.tellg();
    file.seekg(0, file.beg);
    std::vector<char> modelStream(fsize);
    checkStatus(file.read(modelStream.data(), fsize), "Failed to read engine file.");
    file.close();

    // 创建运行时并反序列化引擎
    IRuntime* runtime = createInferRuntime(gLogger);
    ICudaEngine* engine = runtime->deserializeCudaEngine(modelStream.data(), modelStream.size(), nullptr);
    checkStatus(engine != nullptr, "Failed to deserialize engine.");

    // 创建执行上下文
    IExecutionContext* context = engine->createExecutionContext();
    checkStatus(context != nullptr, "Failed to create execution context.");

```

### 5. 执行推理

将预处理后的输入数据传入创建好的 runtime 运行时引擎中，引擎会按照优化后的计算图和执行计划在 GPU 上高效地执行推理计算，得到输出结果。

TensorRT 支持异步推理，这意味着可以并行处理多个推理请求，从而提高吞吐量。

```cpp
    // 准备输入输出缓冲区（假设已知输入输出形状）
    float input[INPUT_SIZE]; // 输入数据，需要根据实际情况填充
    float output[OUTPUT_SIZE]; // 输出数据，用于存储推理结果
    void* buffers[] = {input, output};

    // 执行推理
    checkStatus(context->executeV2(buffers), "Failed to execute inference.");

    // 清理资源
    context->destroy();
    engine->destroy();
    runtime->destroy();

    return 0;
}

```

## 环境配置

需要安装4个：<br>cuda、cuDNN、cuda driver、tensorRT

### 什么是 CUDA Driver

CUDA Driver 是 NVIDIA 提供的一套底层 API，用于在支持 CUDA 的 GPU 上执行计算任务。它为开发者提供了一种与 GPU 进行交互的方法，使得应用程序能够利用 GPU 的并行计算能力来加速各种计算密集型任务。

**CUDA Driver 的主要功能包括：**

1. **管理 GPU 资源**：负责初始化和配置 GPU 设备，分配和释放设备内存等资源管理任务。
2. **加载和执行 CUDA 代码**：编译后的 CUDA 程序（通常是 PTX 或者 cubin 格式）需要通过驱动程序加载到 GPU，并由驱动安排执行。
3. **处理上下文管理**：每个 CUDA 应用程序运行时都需要一个或多个上下文，这些上下文包含了执行环境的信息，如使用的流、分配的资源等。驱动程序负责创建、切换和销毁这些上下文。
4. **同步和事件管理**：提供了同步机制以确保 CPU 和 GPU 之间的协调工作，以及事件接口来测量时间或者等待特定条件的发生。
5. **错误处理**：当遇到硬件故障或其他问题时，驱动程序会返回适当的错误码给应用程序，以便可以采取相应的措施。

**CUDA Driver vs CUDA Runtime**

注意，NVIDIA CUDA 开发环境中还存在另一个重要的组件，即 CUDA Runtime。这两者之间有明显的区别：

- **CUDA Driver**是一种更底层的编程接口，它提供了对 GPU 的直接控制，但要求开发者自己管理更多的细节，例如显式地管理模块加载、函数调用等。它的优点是可以更好地优化性能，但也增加了编程复杂度。
- **CUDA Runtime**是在 CUDA Driver 的基础上构建的，它对 CUDA Driver 的功能进行了进一步的封装和简化，简化了开发过程，隐藏了许多底层操作。大多数 CUDA 编程任务都可以使用 CUDA Runtime 来完成，并且对于多数应用来说已经足够强大和灵活。

**TensorRT编程**

TensorRT分两个阶段运行

- 构建（`Build`）阶段：向TensorRT提供一个模型定义，TensorRT为目标GPU优化这个模型。这个过程可以离线运行。
- 运行时（`Runtime`）阶段：使用优化后的模型来运行推理。

## 构建阶段

**简单来说定义network和config，生成engine，将引擎序列化后保存为.engine文件**

### 创建构建器（builder）对象

`Builder`负责优化一个模型。通过如下接口创建一个`Builder`

```cpp
TRTLogger logger;
nvinfer1::IBuilder* builder = nvinfer1::createInferBuilder(logger);

```

再用 Builder 创建`Engine`。要生成一个可以进行推理的`Engine`，一般需要以下三个步骤：

- 创建一个网络定义
- 填写`Builder`构建配置参数，告诉构建器应该如何优化模型
- 调用`Builder`生成`Engine`

### **创建网络定义**

将模型转移到TensorRT的最常见的方式是以ONNX格式从框架中导出（将在后续介绍），并使用TensorRT的ONNX解析器来填充网络定义。 <br>也可以使用TensorRT的Layer和Tensor等接口一步一步地进行定义。这里介绍通过接口来定义网络：

input(1,3,1,1)-->fc1-->relu-->output(2)

**使用`NetworkDefinition`接口用来定义模型：**

```cpp
// kEXPLICIT_BATCH（显性Batch）为0，1U << 0 = 1
// static_cast：强制类型转换
const auto explicitBatch = 1U << static_cast<uint32_t>(nvinfer1::NetworkDefinitionCreationFlag::kEXPLICIT_BATCH);
nvinfer1::INetworkDefinition* network = builder->createNetworkV2(explicitBatch);

// 其实上面两句就等价下面一句：
nvinfer1::INetworkDefinition* network = builder->createNetworkV2(1);

```

*其中createNetworkV2(1)表示采用**显性batch size**，新版tensorRT(>=7.0)时，不建议采用0非显性batch size*

**隐性 Batch Size 在推理时固定**：必须在构建引擎（`ICudaEngine`）时通过`IBuilderConfig`显式指定，且**一旦确定就无法更改**。

**添加输入层**

```cpp
//输入指定数据的名称、数据类型、完整维度，将输入层添加到网络
nvinfer1::ITensor* input = network->addInput("data", nvinfer1::DataType::kFLOAT, nvinfer1::Dims4{1, input_size, 1, 1});

```

**添加全连接层**

```cpp
// 读取权重的的函数
std::vector<float> loadWeights(const std::string &filename)
{
    std::ifstream infile(filename, std::ios::binary);
    assert(infile.is_open() && "load weights failed");

    int size;
    infile.read((char *)&size, sizeof(int)); // 读取权重的大小
    std::vector<float> data(size); // 创建一个vector，大小为size
    infile.read((char *)(data.data()), size * sizeof(float)); // 读取权重的数据
    infile.close();
    return data;
}

// 读取权重
auto fc1_weight_vec = loadWeights("model/fc1.wts");
auto fc1_bias_vec = loadWeights("model/fc1.bias");
// 转为TensorRT 中用于表示权重或偏置数据的数据结构
nvinfer1::Weights fc1_weight{nvinfer1::DataType::kFLOAT, fc1_weight_vec.data(), fc1_weight_vec.size()};
nvinfer1::Weights fc1_bias{nvinfer1::DataType::kFLOAT, fc1_bias_vec.data(), fc1_bias_vec.size()};
// 调用addFullyConnected创建全连接层, 注意对input进行了解引用
nvinfer1::IFullyConnectedLayer* fc1 = network->addFullyConnected(*input, output_size, fc1_weight, fc1_bias);

```

**添加激活层**

```cpp
// *(fc1->getOutput(0)) 即对getOutput返回的指针进行解引用
// nvinfer1::ActivationType::kRELU 参数指定激活层
nvinfer1::IActivationLayer* relu1 = network->addActivation(*fc1->getOutput(0), nvinfer1::ActivationType::kRELU);

```

无论选择哪种方式，必须**定义哪些张量是网络的输入和输出【输入在上面已经指定了】**。没有被标记为输出的张量被认为是瞬时值，会被构建者优化掉。输入和输出张量必须被命名，以便在运行时，TensorRT知道如何将输入和输出缓冲区绑定到模型上。示例代码如下：

```cpp
// 设置输出名字
relu1->getOutput(0)->setName("output");
// 标记输出
network->markOutput(*relu1->getOutput(0));  // 将上面激活层输出的结果标记为输出

```

### 配置参数

添加相关`Builder`的配置，用来指定TensorRT应该如何优化模型。<br>通过`createBuilderConfig`接口来指定：

```cpp
nvinfer1::IBuilderConfig* config = builder->createBuilderConfig();

```

示例代码如下（仅配置了`workspace`（workspace 就是 tensorrt 里面算子可用的内存空间 ）大小和运行时`batch size` ）

```cpp
// 配置运行时batch size参数
builder->setMaxBatchSize(1);   // 推理时 batchSize = 1 
// 配置运行时workspace大小，单位是字节
config->setMaxWorkspaceSize(1 << 28);   // 256MB

```

- **`setMaxBatchSize`**：这个函数用于设定推理过程中允许的最大批量大小。批量大小决定了每次推理处理的数据量。
- **参数** **`1`**：这里设置为1，意味着一次只处理一个样本。这适用于实时应用或当输入数据流是逐个到来的情况。如果希望一次性处理多个样本以提高效率（尤其是在GPU上），可以将此值设为更大的数。
- **`setMaxWorkspaceSize`**：该方法用来指定构建引擎时可用的最大临时内存空间（workspace）。这个空间主要用于存储中间计算结果和其他临时数据。
- **`(1 << 28)`**：这是一个位移操作，等同于228228字节，即256 MB。（通过这种方式来表达较大的数值是编程中的常见做法）

### 保存为模型文件

```cpp
// 序列化 
nvinfer1::IHostMemory* engine_data = engine->serialize(); 
// 保存
std::ofstream engine_file("mlp.engine", std::ios::binary);    // 创建文件对象并以二进制模式打开文件.文件名没有后缀要求，因为是保存为二进制文件
engine_file.write((char*)engine_data->data(), engine_data->size());  // 将序列化的数据写入到打开的文件中

```

`"mlp.engine"` 是传递给 `std::ofstream` 构造函数的第一个参数，它定义了将要创建或写入的文件的名称。

在 TensorRT 中，并不强制要求模型文件必须命名为`.engine`后缀，但通常建议使用`.engine`作为后缀来命名存储 TensorRT 引擎的文件，主要有以下原因：<br>约定俗成与可读性（在 TensorRT 的开发社区和相关文档中，普遍采用`.engine`后缀来命名 TensorRT 引擎文件）、<br>部分功能或工具的默认设置（某些 TensorRT 的 API 函数在处理文件时，可能会默认查找或期望文件具有`.engine`后缀）

## 运行时阶段

使用`Runtime`时，通常会执行以下步骤：

- 反序列化一个计划以创建一个`Engine`。
- 从引擎中创建一个`ExecutionContext`。

然后，重复进行：

- 为Inference填充输入缓冲区。
- 在`ExecutionContext`调用`enqueueV2()`来运行Inference

### 创建运行时（runtime）对象

```cpp
 // 执行推理前，需要创建一个推理的runtime接口实例。与builer一样，runtime需要logger
TRTLogger logger;
nvinfer1::IRuntime *runtime = nvinfer1::createInferRuntime(logger);

```

### 反序列化并生成Engine

读取磁盘上的刚刚保存的模型文件，利用runtime反序列化恢复成`Engine`

```cpp
// 加载模型
std::vector<unsigned char> loadEngineModel(const std::string &fileName)
{
    std::ifstream file(fileName, std::ios::binary); // 以二进制方式打开文件
    assert(file.is_open() && "load engine model failed!"); // 确保文件已成功打开

    file.seekg(0, std::ios::end); // 定位到文件末尾
    size_t size = file.tellg(); // 获取文件大小

    std::vector<unsigned char> data(size); // 创建一个 vector，大小为文件大小
    file.seekg(0, std::ios::beg); // 定位到文件开头
    file.read((char *)data.data(), size); // 读取文件内容到 data 中
    file.close(); // 关闭文件

    return data; // 返回读取的数据
}

// 读取序列化引擎数据到 engine_data
auto engineModel = loadEngineModel("./mlp.engine");    // loadEngineModel为自己实现的函数
// 反序列化引擎
nvinfer1::ICudaEngine *engine = runtime->deserializeCudaEngine(engine_data.data(), engine_data.size(), nullptr);

```

`engine_data.data()` 是 C++ 标准库中 `std::vector` 类的一个成员函数。它返回一个指向向量内部存储的第一个元素的指针。对于 `std::vector<unsigned char>` 类型的 `engine_data`，`data()` 函数将返回一个类型为 `unsigned char*` 的指针，这个指针可以用来直接访问向量中的数据。<br>当调用 `engineModel.data()` 时，它返回一个指向该向量中第一个字节的指针，这正是 `deserializeCudaEngine` 方法所需要的参数之一，以便它可以读取这些字节并重建 CUDA 引擎对象。

在CPU和GPU上分配输入输出内存（因为数据的流转为CPU->GPU->inference->GPU->CPU），并将输入数据从CPU拷贝到GPU上。

```cpp
// 输入数据
float* host_input_data = new float[3]{1.4, 3.2, 1.1};
int input_data_size = sizeof(float) * 3;
float* device_input_data = nullptr;
// 输出数据
float* host_output_data = new float[2]{0.0, 0.0};
int output_data_size = sizeof(float) * 2;
float* device_output_data = nullptr;
// 申请GPU上的内存
cudaMalloc(&device_input_data, input_data_size);
cudaMalloc(&device_output_data, output_data_size);
// 拷贝数据，异步拷贝    CPU->GPU    参数分别为：目标地址、源地址、数据大小、拷贝方向、流
cudaMemcpyAsync(device_input_data, host_input_data, input_data_size, cudaMemcpyHostToDevice, stream);
// 把输入输出的内存地址放到 bindings 这个数组中，告诉 context 输入输出数据的位置
float* bindings[] = {device_input_data , device_output_data };

```

**为什么需要bindings**

TensorRT 引擎的输入和输出都是**GPU 内存地址**。当你调用`context->enqueueV2()`执行推理时，TensorRT 会直接在这些地址上进行数据读写：

- **输入**：从 `bindings[0]` 读取数据
- **输出**：将结果写入 `bindings[1]`、`bindings[2]` 等（根据输出数量）

TensorRT 根据`bindings[0]`读取输入数据，计算结果写入`bindings[1]`（输出位置）等。`bindings`直接传递设备指针（如`device_input_data`），这种避免了不必要的数据拷贝，最大化推理效率。

| ​步骤​ | 传统流程 | TensorRT + Bindings | ​优化点​ |
| --- | --- | --- | --- |
| ​输入准备​ | Host → 内核缓冲 → Device (2次拷贝) | Host → Device (1次DMA异步拷贝) | 跳过内核缓冲区的CPU拷贝 |
| ​推理过程​ | Device内部多次中转拷贝 | ​**直读 bindings[0]，直写 bindings[1]**​ | 避免临时显存复制 |
| ​输出回传​ | Device → 内核缓冲 → Host (2次拷贝) | 按需回传（1次DMA异步拷贝） | 减少50%的CPU参与拷贝 |

### 调用enqueueV2来执行推理

上面将数据从CPU中拷贝到GPU上后，便可调用enqueueV2 进行推理

```cpp
// 执行推理
bool success = context->enqueueV2((void**)bindings, stream, nullptr);
// 把数据从GPU拷贝回CPU
cudaMemcpyAsync(host_output_data, device_output_data, output_data_size, cudaMemcpyDeviceToHost, stream);
// stream同步，等待stream中的操作完成
cudaStreamSynchronize(stream);
// 输出
std::cout << "输出信息: " << host_output_data[0] << " " << host_output_data[1] << std::endl;

```

`bindings` 数组原本是 `float*` 类型的数组，但在传递给 `context->enqueueV2` 方法时，它被转换为 `void**` 类型。这是因为 `enqueueV2` 方法需要一个通用指针数组来接收输入和输出张量的设备内存地址，而不关心这些数据的具体类型。

- **`void*`**：这是一个通用指针，它可以存储任何数据类型的地址。由于 `void*` 不关联任何特定的数据类型，因此在使用时通常需要被转换回原来的类型。
- **`void**`**：这是指向 `void*` 指针的指针。换句话说，`void**` 是一个可以用来存储 `void*` 类型变量地址的指针。这种类型的指针允许你修改原始 `void*` 指针所指向的位置。
