在优化模型推理性能时，我们经常会用到低精度量化、算子融合、Sol-Attn、Cache-DiT 等方法。但用上这些方法，推理不一定就会更快。

拿量化来说，数据从 16 bit 变成 8 bit，并不意味着推理时间就能减半。实际效果还取决于硬件使用的计算指令、数据读写量，以及格式转换的开销。如果硬件无法直接以这种低精度格式计算，就可能需要先转换回较高精度；当转换成本抵消了收益，推理甚至会变慢。多卡并行也是一样：把模型拆到更多卡上，虽然分担了计算，却也增加了通信和同步的成本。

因此，这篇文章先不深入某一种算法的具体实现，而是从**分得合理、算得便宜、执行高效、做得更少、避免重算**五个角度，梳理推理加速的底层逻辑。这五个角度并不互斥，一种方法可能同时涉及其中几个方面。这样划分，是希望把看似不同的优化方法联系起来，理解它们为什么能够带来加速。

## 1. 分得合理：让计算任务匹配硬件资源

**“分得合理”，就是根据计算任务的特点和硬件条件，决定工作交给谁、如何划分，以及彼此怎样协作。** 在硬件配置已经确定，我们仍然有不少选择：一段计算交给哪个执行单元，一个模型如何拆分到多张卡上，一个请求应该发给哪个实例。这些选择都在决定工作放在哪里，以及资源如何配合，合理安排这些分工，才能充分地利用计算资源，提升推理性能。

### 芯片内部有分工

一颗芯片里，不同计算单元擅长的工作并不一样。比如 NVIDIA GPU 上的 Tensor Core 主要处理矩阵乘加，CUDA Core 等单元承担通用算术和逐元素计算。高通 Hexagon 上的 HMX、HVX 和标量单元，则分别适合矩阵运算、向量运算和控制逻辑等工作。

模型推理包含矩阵乘法、归一化、激活函数、数据转换等操作，需要根据各自的特点选择合适的执行单元。例如，将矩阵乘法交给矩阵单元，把适合的前后处理交给向量单元。

因此，***做底层算子和编译器优化时，需要结合芯片架构考虑任务分工***：既要发挥各类计算单元的能力，也要避免数据搬运或某个处理环节拖慢整个执行过程。

### 多卡并行，要结合通信拓扑来分工

把模型拆到多张 GPU 上，可以分担计算，但也需要在卡之间交换数据。不同并行方式的通信频率、数据量和通信对象各不相同，因此***选择并行配置时，需要把 GPU 的连接方式一起考虑进去*。**

以四张 GPU 为例，假设 GPU 0、1 之间和 GPU 2、3 之间通信较快，而两组之间较慢。

![](https://picx.zhimg.com/v2-df0c94b7c0b25dc5372342c6771cf539_r.jpg)

在这种拓扑下，可以考虑让 GPU 0、1 组成一个 TP 组，GPU 2、3 组成另一个 TP 组，再将这两个组作为两个 PP 阶段，分别处理模型的前后两部分。这样，频繁的层内通信留在组内，两个组之间主要传递阶段边界的激活数据。

不过，这种配置是否更快，还要看两个阶段的负载是否均衡，以及是否有足够的请求或微批次填满流水线。如果阶段之间等待过多，节省的通信时间也可能被抵消。因此，**拓扑决定了哪些卡之间通信更方便，而具体采用哪种并行组合，还要结合通信量、通信频率，以及通信能否与计算重叠来判断。**

### 请求发给哪个实例，也会影响推理耗时

同一个请求，发给不同实例，耗时也可能不同。例如，一个实例已经缓存了请求前缀对应的 KV，就可以复用这部分结果，减少前缀计算。但如果它正在处理大量请求，排队等待的时间也可能抵消缓存带来的收益。

因此，分配请求时，需要同时考虑能复用多少缓存，以及需要等待多久。缓存命中更多的实例未必总是更快，负载较轻的实例也未必总是更合适。

从芯片内部的计算分工，到多卡之间的并行划分，再到请求的分配，“分得合理”考虑的都是同一件事：**结合任务特点和资源状况，把工作安排到合适的位置，让计算、通信和等待的总耗时更短。**

## 2. 算得便宜：让数据表示更适合硬件计算

**“算得便宜”，就是通过调整精度、数据布局和计算方式，降低完成同一份工作的成本。** 比如，同样是矩阵乘法，使用 FP16 还是 INT8，数据是否连续、是否需要重新排列，都会影响实际耗时。量化和数据布局优化，就是这一思路的两个例子。

### 量化：减少数据读写，利用低精度计算能力

量化的收益主要来自两个方面：**数据占用更小，以及硬件可能算得更快。**

**先看数据读写。** 相同数量的元素，用 INT8 存储所需的空间是 FP16 的一半。即使算上缩放因子等额外信息，整体数据量通常也会减少。对于主要受内存带宽限制的任务，需要搬运的数据更少，就有机会缩短耗时。

这种收益不要求乘法本身采用低精度计算。例如，权重可以用低精度存储，读取后再反量化，以较高精度参与计算。只要省下的读取时间超过反量化开销，即使乘法本身没有变快，整体推理仍然可能加速。

**再看计算吞吐。** 如果硬件提供了吞吐更高的低精度指令，就有机会更快地完成相同规模的运算。对于主要受计算能力限制的任务，这是量化提速的主要来源。不过，硬件支持只是前提，算子还需要实际使用这些指令，矩阵形状和数据布局也会影响执行效率。

因此，判断量化能否提速，需要先看任务的瓶颈在数据读写还是计算，再看低精度存储或计算带来的收益，能否覆盖量化、反量化等额外开销。同时，还需要验证量化误差是否会影响结果质量。

### 数据布局：把数据排成硬件更容易处理的样子

除了用多少位表示一个数，数据在内存中的排列方式，也会影响读取和计算的效率。

以卷积为例，channels-last 布局将同一空间位置的各个通道数据连续存放，更适合某些卷积内核的访问和计算方式，从而有机会缩短执行时间。

不过，布局转换本身也需要时间。如果后续算子都能沿用这种布局，转换成本就更容易被摊薄；如果算子之间需要反复转换布局，省下的时间也可能被抵消。因此，**布局是否合适，要看整段计算的耗时，而不只是某一个算子快了多少。**

分块存储、内存对齐和权重预打包也遵循类似的思路：按照内核的访问和计算需求组织数据，减少执行时的重排，提高访存和计算效率。**需要完成的计算没有减少，但数据更容易被硬件高效地处理。**

## 3. 执行高效：减少中间搬运、启动和等待

**同样的计算，执行方式不同，耗时也可能不同。** 模型推理除了要完成运算，还需要启动 GPU kernel、读写中间结果，以及等待数据和其他计算完成。这些开销不会直接体现在模型的 FLOPs 中，却会影响实际推理速度。

图优化、算子融合、FlashAttention、CUDA Graph，以及计算与通信重叠，都体现了这一思路：**通过优化执行过程，减少数据搬运、操作启动和同步等待，让同样的计算更快完成。**

## 4. 做得更少：减少需要处理的信息和求解步骤

**除了让每一步执行得更快，还可以减少需要完成的工作。** 比如，是否需要保存这么多 KV Cache，是否所有位置都需要计算注意力，是否必须经过这么多次去噪才能得到满足要求的结果？

MQA、GQA 通过共享 KV 头，MLA 通过压缩 KV 表示，减少需要保存和读取的数据；SWA（滑动窗口注意力）限制每个 token 关注的范围，减少注意力计算；Sol-Attn、Skip-Softmax 等方法则通过近似或跳过部分计算，进一步降低计算开销。

对于扩散模型，反复调用模型进行去噪是主要工作之一。快速采样器和少步蒸馏尝试用更少的步骤完成生成，从而减少模型调用次数。Token 合并、结构化剪枝和提前退出，也是在不同位置减少需要处理的内容或执行的计算。

这一类优化需要同时考虑结果质量和实际执行成本。有些方法需要调整模型结构或重新训练，有些会引入近似误差。而理论上少算，也不一定会更快：如果只是把数值置零，却仍执行完整的矩阵乘法，计算并没有被省掉；筛选和索引等操作也会增加开销。**真正有价值的是，在结果质量满足要求的前提下，让硬件实际执行的工作更少，推理耗时也随之下降。**

## 5. 避免重算：复用已经得到的结果

不同请求或不同推理步骤之间，往往存在相同或相近的计算。**可以利用这种重复性，让一次计算的结果服务于多次使用，从而减少重新计算的次数。**

例如，SGLang 的前缀缓存可以在模型、前缀内容、位置等相关条件一致时，让不同请求复用已有的前缀 KV，省去相同前缀的计算。

扩散模型中的缓存则利用了特征的相似性。去噪过程中，输入和时间步不断变化，中间结果通常并不完全相同，但部分特征在相邻步骤之间变化较小。Cache-DiT 等方法利用这一特点，按策略复用部分中间特征，并在需要时重新计算、更新缓存，减少部分计算块的执行。

因此，**复用的依据可以是结果相同，也可以是结果足够接近。** 前者需要保证影响结果的条件一致，后者则需要验证近似误差是否在可接受范围内，不能将所有缓存都视为无损优化。

当然，保存和使用缓存也有成本。命中率低，保存的结果就很少派上用场；读取代价过高，可能不如重新计算；占用过多显存，还可能限制并发。判断缓存是否有效，需要比较省下的计算时间与保存、查找、读取结果的开销，同时考虑它对显存和结果质量的影响。

## 总结：

| 类别 | 最核心的问题 |
| --- | --- |
| 分得合理：让计算任务匹配硬件资源 | 工作交给谁、如何划分，才能更好地利用计算和通信资源？ |
| 算得便宜：改变数据表示和计算路径 | 能否通过精度、布局和计算方式的调整，降低每份工作的成本？ |
| 执行高效：减少中间搬运、启动和等待 | 同样的计算，能否减少执行过程中的额外开销？ |
| 做得更少：减少需要处理的信息和求解步骤 | 在结果满足要求的前提下，哪些信息、计算或步骤可以减少？ |
| 避免重算：复用已经得到的结果 | 哪些结果可以直接复用，哪些可以在误差可接受时近似复用？ |
