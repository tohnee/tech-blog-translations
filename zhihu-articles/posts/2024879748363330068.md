今天的主角是**昇腾910B2**配上**Qwen3.5-27B**，这是目前最受关注的国产大模型部署组合之一。Qwen3.5系列在推理能力上有显著提升，配合昇腾910B2的64GB显存，刚刚好能塞进去跑起来。

昇腾官方提供了`vllm-ascend`插件，经过深度优化后的PagedAttention机制在910B上表现相当出色。而且v0.17.0版本首次支持了Qwen3.5-27B，这响应速度是真的快。

## 环境准备：细节决定成败

### 硬件与系统要求

先说硬件，昇腾910B2的基本配置：

- **NPU**：单卡910B2 或 Atlas 800 A2（8×910B2）<br>
- **设备路径**：`/dev/davinci[0-7]`（A2系列）<br>
- **操作系统**：Linux，ARM64架构<br>
- **内存**：越大越好，大模型加载很吃内存<br>

### 软件依赖版本对照表

这是最容易踩坑的地方——昇腾环境对版本匹配要求非常严格，版本对不上轻则跑不起来，重则报一堆莫名其妙的错误。

| 软件 | 版本要求 | 备注 |
| --- | --- | --- |
| CANN | 8.5.1 | 核心计算架构，必装 |
| torch | 2.9.0 | PyTorch主包 |
| torch-npu | 2.9.0 | 昇腾适配包，会自动装 |
| NNAL | 8.5.1 | libatb.so必需 |
| Python | 3.10~3.11 | 3.12暂不支持 |

建议用conda创建独立环境，避免和系统Python打架：

```text
conda create -n vllm-ascend python=3.10 conda activate vllm-ascend
```

安装完CANN后，记得source环境变量，这一步90%的人会忘：

```text
source /usr/local/Ascend/ascend-toolkit/set_env.sh
```

可以用`npu-smi info`检查NPU是否识别正常。

## 两种安装方式：总有一款适合你

这是整个部署流程中最关键的部分，昇腾官方提供了两种安装方式，各有优劣。

### 方式一：Docker部署（推荐新手）

这是最省心的方式，一条命令就能把环境问题全部搞定。

**拉取镜像：**

```text
# Atlas 800 A2
docker pull quay.io/ascend/vllm-ascend:v0.17.0rc1

# 如果用A3，注意使用对应的镜像
# docker pull quay.io/ascend/vllm-ascend:v0.17.0rc1-a3
```

**启动容器：**<br>

```text
export IMAGE=quay.io/ascend/vllm-ascend:v0.17.0rc1
export NAME=vllm-ascend

docker run --rm \
--name $NAME \
--net=host \
--shm-size=1g \
--device /dev/davinci0 \
--device /dev/davinci1 \
--device /dev/davinci2 \
--device /dev/davinci3 \
--device /dev/davinci4 \
--device /dev/davinci5 \
--device /dev/davinci6 \
--device /dev/davinci7 \
--device /dev/davinci_manager \
--device /dev/devmm_svm \
--device /dev/hisi_hdc \
-v /usr/local/dcmi:/usr/local/dcmi \
-v /usr/local/Ascend/driver/tools/hccn_tool:/usr/local/Ascend/driver/tools/hccn_tool \
-v /usr/local/bin/npu-smi:/usr/local/bin/npu-smi \
-v /usr/local/Ascend/driver/lib64/:/usr/local/Ascend/driver/lib64/ \
-v /usr/local/Ascend/driver/version.info:/usr/local/Ascend/driver/version.info \
-v /etc/ascend_install.info:/etc/ascend_install.info \
-it $IMAGE bash
```

进入容器后就可以直接使用vllm命令了，环境已经配置好。

### 方式二：源码编译安装（适合深度定制）

如果你需要修改源码或者用最新的commit，可以从源码编译：

```text
# 安装依赖
pip install torch==2.9.0
pip install torch-npu==2.9.0

# 克隆源码
git clone https://github.com/vllm-project/vllm-ascend.git
cd vllm-ascend

# 编译安装
pip install -r requirements.txt
pip install -e .
```

验证安装：

```text
python -c "import vllm; print(vllm.__version__)"
python -c "import vllm_npu; print('vllm-ascend loaded!')"
```

## 模型准备：下载与配置

Qwen3.5-27B有两个版本可选：

| 版本 | 说明 | 下载链接 |
| --- | --- | --- |
| Qwen3.5-27B (BF16) | 原版，需多卡 | ModelScope |
| Qwen3.5-27B-w8a8 | INT8量化版，单机可用 | ModelScope |

如果只有单台910B2（64G×8），建议用量化版本`Qwen3.5-27B-w8a8`，内存压力小很多。

**从ModelScope下载（推荐国内用户）：**

```text
# 设置使用ModelScope加速下载
export VLLM_USE_MODELSCOPE=true

# 量化版本
git clone https://www.modelscope.cn/models/Eco-Tech/Qwen3.5-27B-w8a8-mtp.git
```

## 启动服务：见证奇迹的时刻

终于到最激动人心的环节——启动vLLM服务！

### 环境变量优化

在启动前建议设置一些优化参数，可以减少内存碎片、避免OOM：

```text
# 减少内存碎片，避免OOM
export PYTORCH_NPU_ALLOC_CONF=expandable_segments:True
export HCCL_BUFFSIZE=512
export OMP_PROC_BIND=false
export OMP_NUM_THREADS=1
export TASK_QUEUE_ENABLE=1
```

### 启动命令

**量化版本（推荐单卡使用）：**

```text
export VLLM_USE_MODELSCOPE=true
export PYTORCH_NPU_ALLOC_CONF=expandable_segments:True
export HCCL_BUFFSIZE=512
export OMP_PROC_BIND=false
export OMP_NUM_THREADS=1
export TASK_QUEUE_ENABLE=1

vllm serve Eco-Tech/Qwen3.5-27B-w8a8-mtp \
--host 0.0.0.0 \
--port 8000 \
--data-parallel-size 1 \
--tensor-parallel-size 1 \
--seed 1024 \
--quantization ascend \
--served-model-name qwen3.5-27b \
--max-num-seqs 16 \
--max-model-len 32768 \
--max-num-batched-tokens 4096 \
--trust-remote-code \
--gpu-memory-utilization 0.90 \
--no-enable-prefix-caching \
--speculative_config '{"method": "qwen3_5_mtp", "num_speculative_tokens": 3, "enforce_eager": true}' \
--compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY"}' \
--additional-config '{"enable_cpu_binding":true}' \
--async-scheduling \
--enable-auto-tool-choice --tool-call-parser qwen3_coder
```

**原版BF16（需要多卡）：**

```text
vllm serve Qwen/Qwen3.5-27B \
--host 0.0.0.0 \
--port 8000 \
--tensor-parallel-size 8 \
--trust-remote-code \
--max-model-len 32768 \
--gpu-memory-utilization 0.90
```

### 关键参数解读

- `--tensor-parallel-size`：张量并行度，A2建议设为2<br>
- `--quantization`：设为ascend启用量化，可大幅节省显存<br>
- `--max-model-len`：最大上下文长度，Qwen3.5支持到128k+<br>
- `--gpu-memory-utilization`：HBM使用比例，0.9比较稳妥<br>
- `--speculative_config`：投机推理配置，可提升生成速度<br>

### 验证服务

服务启动后，测试一下是否正常：

```text
curl http://localhost:8000/v1/completions \
-H"Content-Type: application/json" \
-d'{
"model": "qwen3.5",
"prompt": "请用三句话解释量子计算",
"max_completion_tokens": 100,
"temperature": 0
}'
```

能返回结果就说明部署成功了！

```text
--save-result \

```

## 避坑指南：血泪经验总结

在结束之前，把部署过程中踩过的坑整理一下：

**坑一：版本不匹配**

这是最容易遇到的问题。CANN、torch、torch-npu、NNAL的版本必须严格对应，差一点都不行。如果遇到算子不支持的错误，首先检查CANN版本是否正确。

**坑二：Docker设备映射不全**

启动Docker时记得映射所有必要的设备，包括`/dev/davinci[0-7]`、`/dev/davinci_manager`、`/dev/devmm_svm`、`/dev/hisi_hdc`等，缺任何一个都可能导致问题。

**坑三：显存不够OOM**

910B2单卡跑BF16确实紧张，建议先用量化版本验证流程，确认没问题再考虑多卡部署BF16。

**坑四：网络问题下载不了模型**

建议设置ModelScope镜像源，下载速度会快很多：

```text
export VLLM_USE_MODELSCOPE=true
```

**坑五：忘了source环境变量**

每次开新shell记得先source一下，否则npu-smi能运行但Python访问不了NPU。

部署大模型到国产硬件上这条路，确实比直接用NVIDIA生态多了些折腾成本。但从另一个角度看，每一次踩坑都是对昇腾生态的理解加深——它的文档在变完善，它的工具链在变丰富，它的社区在变活跃。

Qwen3.5-27B配合昇腾910B2这套组合，对于正在做国产化适配的企业来说，是一个值得认真考虑的方案。而且v0.17.0版本的支持速度确实快，Qwen3.5刚发布就能跑起来，这效率值得点赞。
