## 总结

### Torch FSDP2

*PyTorch FSDP2 采用 **Hook 钩子驱动**的实现方式，在模型前向和反向阶段注册钩子，通过钩子触发**all-gather 和 reduce-scatter 通信**，完成前向参数聚合和反向梯度归约。参数用 DTensor 分片存储，通信逻辑在计算**图外执行**。这套方案的优点是方案成熟 (与 Deepspeed Zero 思路一致)，加上参数组粒度的存储管理、显存效率高 (FSDPParamGroup)；缺点是 Hook 内部逻辑无法被图捕获追踪，会产生**Graph Break**，计算与通信的依赖**人工预取**做粗粒度重叠，无法被全局调度优化，大规模分布式训练性能受限。*

### TorchTitan SimpleFSDP

*TorchTitan SimpleFSDP 抛弃 Hook，采用**参数化拦截 (parameterize) +DTensor**的实现方式，在参数访问时自动触发分布式通信 (DTensor.redistribute 执行 all-gather 和 reduce-scatter)。核心优势在于通信算子在 Dynamo 图捕获阶段就直接进入计算图，不会引入 Graph Break；AOT 阶段可以自动生成前向和反向对应的完整通信算子 (Redistribute 有反向 op)；Inductor 后端编译阶段，能够自动执行通信分桶、算子重排、通信预取等深度的编译优化能力，实现计算与通信的细粒度重叠，有效掩盖通信延迟。FSDP 流程与 Torch.compiler 编译栈天然兼容，在分布式训练中性能扩展性优于 FSDP2。*

*通过 torch.nn.parameterize 拦截参数访问，底层依赖 DeviceMesh 定义集群拓扑，参数调用时自动触发 Redistribute 完成通信。实测卡数越多、SimpleFSDP 性能越优。*

*Deepspeed ZeRO与FSDP2方案类似，Offload支持内存和SSD（FSDP2只支持内存），Zero1/2/3参数并行依次是优化器参数 -> 梯度 -> 权重。*

### DeepSpeed ZeRO

*通过三级分片优化器状态、梯度、参数降低显存，采用全局统一内存池，支持 CPU/SSD 卸载与动态均衡分片，搭配层级异步预取与自研通信调度；优点是显存优化极致、支持弹性训练与分片重平衡，内存与卸载能力全面，缺点是 Hook 多导致 Graph Break 严重，不支持整图编译，架构自研与 PyTorch 原生生态兼容性弱。*

### Megatron FSDP

*Megatron FSDP，对比FSDP2性能优势集中在两点：1）**通信内存提前注册 (UserBuffer)**：通过ncclMemAlloc预分配并向 NCCL 注册，NVLink 硬件直接做地址映射（VA->PA->IOVA），降低通信占用的 GPU SM (pack/unpack kernel)，计算和通信才能在硬件层面真正同时跑，而不是名义上两个 stream、实际上争 SM 排队；2）**持久化的双缓冲区 (FixedPoolAllocator)**：这块注册内存做成固定 2 个 slot 循环复用，每步通信没有动态分配开销，UBR 本身也强制要求持久内存、两者分离；3）**通信粒度**：bucket_size 默认 40M，可以跨多层 / 参数组。*

### FSDP2与Megatron通信对比

***默认 NCCL（FSDP2/DDP）：发送端2 次拷贝 + SM高占用**。流程：用户数据Tensor → 拷贝到 8MB bounce buffer（NCCL默认中转缓冲区） → pack kernel → 第二次拷贝（从bounce buffer到NIC可识别的物理地址） → DMA跨卡搬运。如果通信数据大于8M，会重复多次，这也是大Tensor耗时长的原因。*

***Megatron 优化：发送端1次拷贝，无 pack、无二次拷贝、双缓冲流水线**。流程：用户数据Tensor → 1 次拷贝到 注册的40MB UserBuffer（初始化阶段完成了VA->GA->IOVA的映射） → DMA跨卡搬运。*

## PyTorch FSDP2

核心是 **DTensor存储 + Hook通信 + Prefetch + 全新内存管理**（FSDPParamGroup），彻底抛弃 FSDP1 的 FlatParameter。下面从架构、核心组件、执行流程、分片策略、内存与通信、关键改进 6 方面讲内部实现。

### 一、核心架构与设计目标

- **完全重写**：移除 FSDP1 的 FlatParameter（扁平化参数）
- **基于 DTensor**：分布式张量抽象，统一分片语义
- **逐参数分片**：每个参数独立在 dim-0 分片
- **钩子驱动**：用 pre-forward /post-forward/pre-backward 钩子控制生命周期
- **低显存、确定性内存、无 record_stream**
- **对标 ZeRO**：支持参数 / 梯度 / 优化器状态三级分片

### 二、核心内部组件（C++/Python）

**1. FSDPModule**

- `fully_shard(module)` 生成的包装类（如 `FSDPTransformer`）
- 动态替换原 module 的 forward，注入 FSDP 逻辑
- 管理子模块分片、参数组、状态、钩子

**2. FSDPState**

- 模块级元数据中心：参数、分片策略、通信组、混合精度、预取配置
- 全局状态同步、钩子注册、执行流协调

**3. FSDPParam**

- 单参数包装：持有 **DTensor（分片本地片）**
- 管理：all-gather（解分片）、free（释放全量）、reduce-scatter（梯度分片）

**4. FSDPParamGroup（桶）**

- 把多个参数绑为一组，**统一通信**（减少集体通信次数）
- 前向 / 反向时整组 all-gather /reduce-scatter

**5. DTensor（底层基石）**

- `DTensor` = local_tensor + placements + mesh
- FSDP2 固定：`placements=(Shard(0),)`（第 0 维分片）
- 支持：`to_local()`、`full_tensor()`、分布式算子自动下分发

### 三、生命周期与执行流程（前向 + 反向）

**1. 初始化（分片）**

1. `fully_shard(layer)` → 为模块创建 FSDPState
2. 遍历参数 → 每个参数转为 **Shard (0) 的 DTensor**
3. 按策略分组（FSDPParamGroup）
4. 注册 pre-forward /post-forward/pre-backward 钩子

**2. 前向传播（forward）**

- **pre-forward 钩子**：
- **post-forward 钩子**（默认 reshard_after_forward=True）：

**3. 反向传播（backward）**

- **pre-backward 钩子**：
- 自动微分计算本地梯度（未分片）
- **梯度同步**：
- 优化器只更新 **分片参数** → 优化器状态也分片

**Hook机制**：通过**前向/反向钩子**显式管理通信

```python3
class FSDP2Module(nn.Module):
    def __init__(self, module, mesh):
        # 注册三种关键钩子
        self._register_forward_pre_hook()   # 前向传播前
        self._register_forward_hook()      # 前向传播后
        self._register_backward_hook()     # 反向传播后
```

**Prefetch机制：**在前向传播后，预取i+1层（或i+k层）参数

```text
def _post_forward_hook(module, inputs, outputs):
    # 前向传播后：预取下一层参数
    next_param_group.prefetch()  # 异步启动
    # 释放当前层完整参数内存
    current_param_group.free_unsharded()
```

### **执行流程图**

```text
层i pre-forward hook: wait(层i参数)
|--------------------------------|
层i forward: 计算
|--------------------------------|
层i post-forward hook: prefetch(层i+1参数) + free(层i)
    ↓
层i+1 pre-forward hook: wait(层i+1参数)  ← 可能已预取完成
|--------------------------------|
层i+1 forward: 计算
```

### 优点

1. **通信与计算重叠**。通信提交到comm stream（NCCL专用流）
2. 内存高效管理。显式内存池复用，及时释放不再需要的完整参数副本。
3. 生产级性能。支持大规模分布式训练。

### 缺点

- **Graph Break问题**

```text
# 钩子导致计算图断裂 [计算块1] ← graph break → [计算块2] ← graph break → ...
# torch.compile 优化受限 
model = torch.compile(model)  # 无法捕获完整计算图
```

### FSDP2 示例

**sharding_strategy 策略支持HSDP模式（Hybrid Shard）**

- **FULL_SHARD**（默认，推荐）：参数 + 梯度 + 优化器状态全分片（ZeRO-3），显存最低
- **HYBRID_SHARD**：节点内 FULL_SHARD、节点间 DDP（ZeRO-3+DP），适合多机
- **SHARD_GRAD_OP**：仅分片梯度 + 优化器（ZeRO-2），参数不分片，通信更少
- **NO_SHARD**：关闭分片，仅做混合精度 / 通信管理

```text
# 1. 定义模型（如Llama/Transformer）
class TransformerBlock(torch.nn.Module): ...
class Transformer(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = torch.nn.ModuleList([TransformerBlock() for _ in range(8)])
        self.lm_head = torch.nn.Linear(...)

model = Transformer()

# 2. 逐层包裹TransformerBlock（分片粒度：层）
for layer in model.layers:
    fully_shard(
        layer,
        sharding_strategy=ShardingStrategy.FULL_SHARD,  # 核心分片策略
        mixed_precision=MixedPrecision(
            param_dtype=torch.bfloat16,
            reduce_dtype=torch.bfloat16,
            buffer_dtype=torch.float32
        ),
        backward_prefetch=BackwardPrefetch.BACKWARD_PRE,  # 反向预取
        reshard_after_forward=True  # 前向完立即重分片，省显存
    )

# 3. 包裹根模型（剩余参数：embedding、head）
fully_shard(
    model,
    sharding_strategy=ShardingStrategy.FULL_SHARD,
    mixed_precision=...  # 同层配置
)

# 4. 初始化优化器（包裹后再建优化器！）
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5)

```

**梯度裁剪，直接用原生接口，无需FSDP专用**。

```text
model.train()
for batch in dataloader:
    optimizer.zero_grad()
    loss = model(**batch).loss
    loss.backward()
    # 梯度裁剪（直接用原生，无需FSDP专用）
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    optimizer.step()
```

**dense保存/加载支持分布式（训练）或单机（推理）2种模式：**

```text
# 保存分片状态（省带宽，推荐）
from torch.distributed.fsdp.api import StateDictType, ShardedStateDictConfig
with fully_shard.state_dict_type(model, StateDictType.SHARDED_STATE_DICT):
    torch.save(model.state_dict(), "sharded_ckpt.pt")

# 保存全量状态（rank0保存，适合推理）
with fully_shard.state_dict_type(model, StateDictType.FULL_STATE_DICT):
    if dist.get_rank() == 0:
        torch.save(model.state_dict(), "full_ckpt.pt")

# 加载
model.load_state_dict(torch.load("sharded_ckpt.pt"))
```

**FSDP2实践**

- **分片粒度**：按**Transformer 层**包裹，不要包太小（如 Linear）或太大（整个模型）
- **精度**：优先 BF16，避免 FP16 溢出；缓冲区保持 FP32
- **显存**：`reshard_after_forward=True` + 梯度检查点（`torch.utils.checkpoint`），可训 70B + 模型
- **混合并行**：FSDP2 + TP（张量并行），用`DeviceMesh`组合，适合超大模型。

### 与FSDP1区别

| 维度 | FSDP1（Flat 物理压平） | FSDP2（DTensor 单参数 + 桶分组） |
| --- | --- | --- |
| 通信极致带宽 | 理论略优（大包无碎片） | 接近，流水线重叠后反超 |
| Tensor 语义完整性 | 破坏、侵入模型结构 | 完全保留原生 nn.Parameter |
| dtype / 稀疏 / 冻结支持 | 极差 | 原生完美支持 |
| 显存峰值确定性 | 差、碎片多 | 严格确定性、无滞留 |
| 分层预取 & 流水线 | 全局粒度，无法细粒度 | 层 / 桶级精细流水线 |
| Checkpoint 分布式读写 | 需要全量聚合，慢 | 直接读写分片，零通信 |

## TorchTitan SimpleFSDP

### 核心技术：参数化 + DTensor

**参数化机制** (Parametrization)

**参数化**：PyTorch中一种对参数可编辑的技术，可以改动参数获取逻辑，在这里的作用是透明拦截参数访问，在访问时触发通信。使用了**python元编程技术-property和type**，property优先级高，因此是**“拦截访问”**。

```text
def _register_parametrization(module, param_names, parametrization):
    # 通过动态创建类重写参数访问
    param_name_to_property = {
        param_name: property(
            lambda self, pn=param_name: parametrization(self._parameters[pn])
        )
    }
    module.__class__ = type(
        f"SimpleFSDP{module.__class__.__name__}",
        (module.__class__,),
        param_name_to_property,
    )
```

**DTensor 和 redistribute**

```text
class ReplicateComputation(torch.nn.Module):
    def replicate_compute(self, x: DTensor):
        # 通过 redistribute 内部实现 all-gather
        output = x.redistribute(
            placements=self.compute_placements,  # [Replicate()] * ndim，复制模式
            forward_dtype=self.param_dtype,
            backward_dtype=self.reduce_dtype,
        )
        return output.to_local(grad_placements=self.grad_placements)
```

- **DTensor**：分布式张量，知道如何在设备间分布
- **redistribute**：转换张量分布状态（如分片→复制）
- **自动通信**：根据 placements 自动处理 all-gather/reduce-scatter

**Mesh 与参数分布**

```text
def data_parallel(model, device_mesh, mode="hybrid_shard"):
    # 根据模式确定参数分布策略
    if mode == "hybrid_shard":
        param_sharding = (Replicate(), Shard(shard_dim))  # 2D mesh
        # 维度0: host间复制, 维度1: host内分片
```

**Mesh (设备网格)**

- **作用**：多维设备阵列，描述**参数在分布式下的拓扑逻辑**，支持DP/TP/EP/CP等多种并行策略任意组合。
- **维度映射**：每个维度对应一种并行策略
- **示例**：2D mesh `[4, 8]` = 4 个 host × 每个 host 8 卡

### 初始化过程

```python3
data_parallel(model, device_mesh, mode)
↓
确定 param_sharding（Replicate/Shard/Hybrid）
↓
遍历所有子模块
↓
对每个参数:
- 普通Tensor → distribute_tensor → DTensor
- DTensor → _distribute_dtensor → 嵌套DTensor （组合并行，如TP/EP与FSDP）
↓
_register_parametrization
↓
动态创建新类(python元编程)，添加 property
新类 = type(new_name, old_class, property)
↓
module.__class__ = 新类
↓
返回包装后的模型
```

### 前向过程

这里注意 redistribute 和 to_local 分别对应 Autograd.Function 实现，反向有梯度通信的逻辑。

```text
model(input)
↓
module.weight（参数访问）
↓
property getter 触发
↓
ReplicateComputation.forward(dtensor)
↓
_active_parametrization 检查
↓

│      from_local (TP/EP mesh)                                       │
└─────────────────────────────────────────────────────────────────────┘
↓
返回完整参数副本
↓

```

### 反向过程

```python3

↓

↓
```

### redistribute和to_local

```text
# 前向传播：
Shard(参数) ——redistribute.forward——→ Replicate
       └─ all_gather_into_tensor()
Replicate ——to_local.forward——→ local_tensor
       └─ 直接提取，无通信

# 反向传播：
grad_output ——to_local.backward——→ Partial(梯度)
           └─ reduce_scatter_tensor() 或 all_reduce()
Partial(梯度) ——redistribute.backward——→ Shard(梯度)
            └─ 与前向相反的通信
```

### 优点

- **整图编译友好**。没有hook，全部在Module.forward内执行

```text
# 通信在 forward() 内, 编译器能看到完整计算图
model = torch.compile(model, fullgraph=True)  # 可以: 算子融合、内存优化、静态调度
```

- **DTensor 自动管理。**自动处理分布式布局；简化通信逻辑；与 PyTorch 生态深度集成；
- 代码简洁透明。约 300 行代码；易于理解和修改；参数化机制透明。

### 缺点

- **同步通信。**无法prefetch，需要借助参数分桶（torch2.10才支持）和torch.compiler的静态调度（实现计算与通信 异步）。

```text
# 访问参数时立即触发同步通信 module.weight  # → 同步 all-gather # 无法预取, 无法重叠
```

## 技术对比：FSDP2与Simple FSDP

| 维度 | FSDP2 | Simple FSDP |
| --- | --- | --- |
| 通信调度 | 异步，支持预取和重叠 | 同步，无重叠 |
| 编译优化 | Graph break，优化受限 | 整图编译友好，可实现通信异步 |
| 内存管理 | 显式内存池，高效复用 | DTensor 自动管理 |
| 代码复杂度 | 高（模块化设计） | 低（~300 行） |
| 适用场景 | 生产训练，性能优先 | 教学 / 实验，理解原理 |
| 通信隐藏 | ✅ 通过预取部分隐藏 | ❌ 无法隐藏 |
| torch.compile | ⚠️ 部分支持 | ✅ 完全支持 |

## 技术对比：FSDP2与DeepSpeed Zero

注意点：

1. FSDP2的内存管理是**参数组**粒度的，且仅支持CPU offload（HBM->MEM，**不支持offload到SSD**）
2. Zero是全局统一内存池管理内存，支持跨层/跨组。

| 对比维度 | DeepSpeed Zero (v0.14+) | PyTorch FSDP2 (2.4+) |
| --- | --- | --- |
| 核心架构 | 手动 Hook + 优化器封装 + 全局内存池 | 手动 Hook + 参数组管理 + 分组内存池 |
| DTensor 依赖 | 无（完全自研分片逻辑） | 可选集成（非核心） |
| 分片策略 | 1. 按参数大小动态均衡分片（全局最优）2. 支持按参数 / 层 / 模块分片 | 1. 按参数组静态分片（按层划分）2. 仅支持按维度分片（最后一维 / 第一维） |
| 通信机制 | 1. 层级异步预取 + 通信优先级调度2. 自研异步通信队列 | 1. 参数组级异步预取2. 复用 PyTorch 异步通信原语 |
| 内存管理 | 1. 全局统一内存池（跨层 / 跨组复用）2. 支持 CPU/SSD 卸载（参数 / 优化器）3. 优化器状态分片独立管理 | 1. 参数组级内存池（组内复用）2. 仅支持 CPU 卸载（参数）3. 优化器状态分片与参数组绑定 |
| 编译优化 | 1. Hook 多，Graph Break 严重2. 不支持 fullgraph 编译 | 1. Hook 减少，Graph Break 减轻2. 支持 torch.compile，但不支持 fullgraph |
| 容错 / 弹性 | 1. 原生支持弹性训练2. 分片自动重平衡 | 1. 依赖 PyTorch Elastic，无原生支持2. 分片布局固定，无法动态调整 |
| 易用性 | 配置文件驱动，无代码侵入 | 代码级配置，需手动封装模型 / 划分参数组 |

## FSDP相关概念

### HSDP

Hybrid Shard Data Parallel， 比如参数在host间复制，host内分片，就是混合Shard模式，即2D mesh [4, 8] = 4 个 host × 每个 host 8 卡

### Zero机制

1. **Zero 核心**：通过分片优化器状态、梯度、参数（Stage 1/2/3）降低单卡内存占用，内存节省比例约为 1/N（N 为并行进程数）；
2. **适用场景**：超大模型训练、显存受限场景、混合并行训练，小模型 / 单卡训练不建议使用；
3. **核心权衡**：内存节省与通信开销的平衡，Stage 3 内存优化最极致但通信开销最大；
4. **主流实现**：官方用 PyTorch FSDP/FSDP2 （主要实现了stage2/3），开源首选 DeepSpeed（功能最全），超大规模模型可选 Megatron-LM（参数多、易用性差）。
5. 可优化方向：**Hook支持图捕获**，降低Graph Break影响。

## FSDP最佳实践

1. **优先使用FSDP2**，对比FSDP1 功能更灵活，与精度一致，对比TorchTitan SimpleFSDP性能更优（虽然引入Graph Break，但通信能被掩盖）。
2. TorchTitan SimpleFSDP配合**参数分桶（torch2.10引入）+ Torch.Compile静态调度**，可以实现通信异步。
3. **与torch.compile混合使用，只能用mode=default模式，不支持整图fullgraph=true**，其它模式reduce-overhead/max-autotune性能极差（单step cost从 0.x s -> 几十s）。
4. **torch.compile切分模式，选择Zero3即可**，即权重、梯度、优化器状态3类参数全部分片。
5. **优先关闭混合精度**。FSDP卡间通信store和reduce dtype优先选择float32，避免bf16/fp16损失精度，尤其是GR推荐模型场景。

## DP与DDP

DP与DDP的关系，总结如下：

1）架构差异。**DP是单进程中心化（Master-Slave）架构**，权重存在卡0，其它卡只做前/反向计算，不做参数更新，从卡0拿参数，早期的DMLC rabit mpi架构；**DDP是无中心节点、全对称架构**，权重全卡副本对称设计，走独立的参数更新（GPU MPI架构模式）。

2）梯度逻辑。DP梯度收拢到卡0更新；DDP Allreduce全局规约，各卡自主更新。

3）数据分发。DP由卡0切分batch数据给其它卡，卡0同时训练+调度，已成为瓶颈；DDP各卡通过DistributeSampler自己拿batch数据。
