### 核心方法论：三步闭环，每轮只消一个瓶颈

> “先做性能测试，然后根据结果做性能优化，然后做性能验证，把这三个步骤轮着做循环，逐次把瓶颈一点一点消除。”

关键在于**瓶颈会转移**：算力墙 → 访存墙 → 通信墙（PD 分离之后，KV transfer 正在变成新瓶颈）→ 故障墙（稳定性）。因此，达标不代表结束；达标后要回到测试，找下一个瓶颈。

### 实施步骤（八步）

**① 先定场景，再定参数。** 讲者反复强调“不能说我是 AI coding 场景，一定要具体到参数”。他给出了参数表：

| 场景 | 输入 | 输出 | 并发 | 缓存命中 |
| --- | --- | --- | --- | --- |
| 交互对话 | 2K–8K | <1K | 16–64 | 一般 |
| 长上下文 Agent | 32K+ | 2K–8K | 视业务 | 高 |
| AI Coding | 长上下文多轮 | 中等 | 中高 | 80%+ |
| 1M 上下文新模型 | 超长 | 视业务 | 视业务 | ~95% |

**② 锁定环境。** 硬件、驱动、框架、精度、并行、拓扑全部记录成实验因子。他给了一个教训：跑 benchmark 全部通过，大规模上线后才发现不同版本的组合会影响线上性能和精度。

**③ 建立 Baseline。** TTFT、TPOT、TPS、命中率、SM/HBM 利用率，优化前全部留存，否则无法证明手段有效。

**④ 压测 + Profiling。** 宏观压测（按场景参数）、微观 profiling（Nsight）、通信体检（单机 NCCL、跨机 IB）。

**⑤ 五层归因（方法论的核心）。** 把数据拆到：模型算法层 → 算子/Kernel 层 → 显存/带宽层 → 并行/通信层 → 调度层，找出占比最大的那一层。

这里有个非常重要的判断：**“最上层、最粗粒度的优化往往收益最大；算子层面的优化实际占比很小——因为大家把重点都放在了更粗粒度的优化上。”** 实践含义是：先看调度和并行，再看算子和指令，顺序反了会白干。

**⑥ 从瓶颈到假设。** 针对占比最大的层，提出一个可验证的假设（排队严重 → 改批处理/PD 配比；通信占比高 → 换拓扑/做 overlap；显存不足 → HiCache/量化；算子热点 → 融合/换 kernel）。

**⑦ 单变量优化。** 一次只改一处。

**⑧ 验证（性能 + 精度双通过）。** 五条原则：同一 workload、单一变量、prefill/decode 分阶段看、先定 p50 还是 p99、对照 baseline。他强调每改一次都要同时跑性能和精度，“整个流程非常漫长、非常耗时”。

### 七个优化维度

| 维度 | 手段 | 讲者的判断 |
| --- | --- | --- |
| 芯片选型 | 比显存、带宽、算力；用“理论性能 + 单模型实测”外推 | 长上下文模型大概率 B300 性价比最高 |
| 框架选型 | SGLang / vLLM / TensorRT-LLM | 线上“主要以 SGLang 为主” |
| 并行策略 | TP/PP/DP/EP/CP | 大规模推理基本都是混合并行，关键是找到最佳配比 |
| 计算优化 | MHA/GQA/MLA、DSA index cache、MoE 全链路（分发→专家→DeepGEMM→combine） | 逐算子看 |
| 缓存优化 | PagedAttention、RadixAttention、HiCache、KV 量化 | 四个衡量点：碎片、池大小、命中率、量化无损 |
| 通信优化 | 拓扑+算法、计算通信重叠、减少拷贝、用计算单元通信 | 上线前就要测出最优组合 |
| 调度优化 | 批处理、PD 干扰抑制、分时、KV 传输开销、排队优先级、负载均衡 | 粒度最粗，收益往往最大 |

### 三个案例

- **DeepSeek 3.2 大客户**：用户要求 → 多轮 workload 测试 → 宏观压测 → 微观 profiling → 假设 → 优化，环境 H200 + EP + PD 分离，完整推敲下来。
- **MoE 逐轮调优**：方案 1 时延 −7.5%，方案 2 再 −15.2%，同时 TPOT 降、TPM 升——优化是逐次下探的过程。
- **多层 index cache 去重（已开源）**：token/s **+13.7%**，多项指标降 10%+——这是算子/缓存层少见的可观收益，前提是先归因到它。

### 两个贯穿全篇的洞见

1. **墙会转移**：算力 → 访存 → 通信（KV transfer）→ 故障。上次有效不代表这次还该优化那里。
2. **请求生命周期要拆到 8 段**：客户端 → HTTP server → 推理端 → 返回，推理内部再分 prefill/decode 共 6–7 个子阶段；每段都有独立耗时和独立手段，不拆就无法定位。

### 一句话

**“先测量、再分层、后单点、必验证”——优化的效率不取决于你知道多少技巧，而取决于你能不能快速判断“现在该动哪一层”。**
