## 1. 张量并行：单层内部的「手术刀式」切分

流水线并行是把层分到不同 GPU。但如果单层的矩阵乘法本身就大到塞不进单卡呢？这时候需要**张量并行**——在单层内部切分计算。

论文使用了 Megatron（Shoeybi et al., 2019）的分区策略。一个 Transformer 层由两部分组成：

![](https://pica.zhimg.com/v2-bae1e6775f41788452dbbc64d73650ce_r.jpg)

> 📊 **原论文 图 5a** ：MLP 块的张量并行分区。权重矩阵 A 按列切分为 [A₁, A₂]，B 按行切分。f 和 g 是一对共轭算子，每层仅需 2 次 all-reduce。<br>

### MLP 块的分区

MLP 的计算为：

$ Y = \text{GeLU}(XA), \quad Z = \text{Dropout}(YB) $

**关键技巧** ：把 A 按列切分成 $[A_1, A_2]$：

$ [Y_1, Y_2] = [\text{GeLU}(XA_1), \text{GeLU}(XA_2)] $

为什么按列而不是按行？因为 **GeLU 是非线性的**。如果按行切 A，GeLU 之后还需要一次同步才能继续。按列切则每个分片独立计算 GeLU，完全不需要通信。

B 矩阵按行切分，最后做一次 all-reduce（论文中称为 **g 算子**）汇总结果。

这里相当巧妙地，利用MLP这里计算的AB矩阵计算的特点，对A进行列拆分，对B进行行拆分，只需要一次all-reduce。

### Self-Attention 块的分区

![](https://pic2.zhimg.com/v2-ea344f3d1b5a8195935470a589cb8cc9_r.jpg)

> 📊 **原论文 图 5b** ：Self-Attention 块的张量并行分区。K、Q、V 按列切分（多头天然可拆分），输出线性层按行切分。<br>

Attention 的多头机制天然适合并行：

- K、Q、V 矩阵按列切分，每个 GPU 负责一部分 attention head
- 各 GPU 独立计算自己负责的 head
- 输出线性层的权重按行切分，最后 all-reduce

**通信开销** ：每个 Transformer 层的前向需要 2 次 all-reduce（g 算子），反向需要 2 次（f 算子）。论文用几行代码就实现了 f 和 g 算子。

### 张量并行的通信量

对于每个 microbatch，单设备张量并行的总通信量为：

$ l_{\text{stage}} \cdot \left(8bsh \cdot \frac{t-1}{t}\right) $

其中 $l_{\text{stage}}$ 是当前 stage 的层数，$b$ 是 microbatch size，$s$ 是序列长度，$h$ 是隐藏维度，$t$ 是张量并行度。

关键观察：通信量与 $(t-1)/t$ 成正比——**t 越大，每张卡的通信量趋近但不超过上限**。但 t 超过单机 GPU 数后，all-reduce 要走跨机 InfiniBand，延迟剧增。

> **问题**：这里的8是什么？<br>8 = 2 × 2 × 2：<br>2：每个 Transformer Layer 有 2 处通信点（Attention 的 f/g + MLP 的 f/g）<br>2：前向 + 反向各一次<br>2：all-reduce 的通信系数（发送数据量 + 接收数据量 = 2× 原始张量大小）<br>

## 2. 性能分析：三种并行的数学博弈

用数学公式解释不同并行配置如何影响吞吐量。

### 符号约定

- $(p, t, d)$：流水线并行度、张量并行度、数据并行度
- $n$：总 GPU 数，满足 $p \cdot t \cdot d = n$
- $B$：全局 batch size
- $b$：microbatch size
- $m = \frac{B}{b \cdot d}$：每个流水线的 microbatch 数

### 2.1 张量与流水线的博弈

固定 $d = 1$（无数据并行），则 $t \cdot p = n$。Bubble 占比用 $t$ 表示为：

$ \frac{p-1}{m} = \frac{n/t - 1}{m} $

**结论** ：增加张量并行度 $t$ → 减少流水线并行度 $p$ → bubble 减小↓，但 all-reduce 通信量增加 ↑。

### 2.2 数据与流水线的博弈

固定 $t = 1$，bubble 占比为：

$ \frac{p-1}{m} = \frac{n/d - 1}{b'/d} = \frac{n-d}{b'}, \quad b' = B/b $

![](https://pic3.zhimg.com/v2-8ba5294821eca7025d48a07b33e120aa_r.jpg)

> 📊 **原论文 图 6** ：Pipeline bubble 占比随数据并行度 d 的变化。d 增大时 bubble 减小，但受限于单卡显存容量。<br>

**结论** ：增加数据并行度 $d$ → bubble 减小 ↓，同时梯度同步频率也降低 ↓。但单卡必须能装下整个模型（含优化器状态）。

### 2.3 Microbatch Size 的最优值

![](https://pic3.zhimg.com/v2-132cd285b29e3f5ddeda5733714330e6_r.jpg)

> 📊 **原论文 图 7** ：单 GPU 吞吐量随 microbatch size 的变化。microbatch 从 1 增到 8，吞吐量提升约 1.3 倍。<br>

microbatch size $b$ 对性能有双向影响：

$ \text{总时间} = \left(\frac{b'}{b} + p - 1\right) \cdot (t_f(b) + t_b(b)) $

- **增大 b** → 矩阵乘法更大 → GPU 利用率更高 → $t_f(b), t_b(b)$ 非线性降低 ↓
- **增大 b** → microbatch 数 $m$ 减少 → bubble 占比 $(p-1)/m$ 增大 ↑

![](https://pic1.zhimg.com/v2-d38160a0a17ff660ca6d5ec5ce7dfe42_r.jpg)

> 📊 **原论文 图 8** ：归一化估计吞吐量随 microbatch size 的变化。对于 (p, t) = (8, 8) 配置，batch size 为 128 和 512 时，最优 b 均为 4。<br>

**这两个效应是矛盾的**，最优值依赖具体模型。论文建议用上面的公式做代理模型来选择。

## 3. 三条黄金配置法则

论文从以上分析中提炼出三条启发式原则：

### 法则 #1：张量并行不超过单机 GPU 数

> 张量并行应限制在**单台多 GPU 服务器内部**（如 DGX A100 是 8 卡）。超出后改用流水线并行跨节点扩展。<br>

原因很简单：all-reduce 走 NVLink 极快（900 GB/s），走 InfiniBand 就慢了不止一个数量级。

### 法则 #2：模型并行度 M = t × p 要撑住显存

> 总模型并行度 $M = t \cdot p$ 需要足够大，使得模型参数 + 中间激活能放进 GPU 显存。剩下的 GPU 用数据并行填满。<br>

数据并行虽然通信开销低，但不能独立用于超大模型——GPT-3 的 batch size 只有 1536，这意味着纯数据并行最多扩展到 1536 张卡。

### 法则 #3：microbatch size 没有万能最优值

> 最优 microbatch size 取决于模型的计算特性、流水线深度 p、数据并行度 d 和 batch size B。<br>

论文实验中，不同模型的最优 b 在 1 到 4 之间。增大 b 提升 GPU 利用率的收益，需要与 bubble 增大的代价做权衡。
