## 投机解码：从 DFlash 到 Domino、DSpark 与 DSpine

- DFlash：并行 block drafting 的代表方案。
- Domino：在并行 backbone 后增加 GRU causal encoder 和 logits residual correction。
- DSpark：用轻量 Markov/RNN correction，并进一步做硬件感知的验证调度。
- DSpine：把前驱预测特征注入每一层 backbone，并用统一特征空间和 transition cache 完成最终的前驱条件化选择。

文中把“target model”称为目标模型，把用于提出候选的模型称为 draft model 或 drafter。除非特别说明，$x_i$ 表示实际提出的 draft token，$y_i$ 表示训练时的目标 token。

本文中“backbone”默认指 **draft backbone**，不是 target。$x_0$ 表示 target 提供的已知 anchor，$x_{1:m}$ 是随后提出的 $m$ 个候选；$y_i$ 是监督序列里的 token，并不保证事实正确。$L_i$ 或 $U_i$ 表示 logits，花体 $\mathcal L$ 表示 loss。不同论文原始符号有重用，下文在每个局部公式中单独定义。

### 1. 投机解码到底在优化什么

普通自回归解码每一步都由目标模型计算：

$$ p(x_i\mid x_{<i},c), $$

其中 $c$ 是 prompt 和已经确认的上下文。这样因果依赖是完整的，但每生成一个 token 都要调用一次昂贵的目标模型。

投机解码把工作拆成两部分：

1. **drafter 提议一段候选** $x_{1:m}$；
2. **target 一次验证这段候选**，保留通过验收的连续前缀，并在首次拒绝处使用目标分布进行修正采样。

若 draft 分布为 $q$，target 分布为 $p$，标准无损验证在随机采样情形下使用：

$$ \alpha_i=\min\left(1,\frac{p_i(x_i)}{q_i(x_i)}\right). $$

首次拒绝后，从归一化的残差分布

$$ \frac{[p_i-q_i]_+}{\sum_v[p_i(v)-q_i(v)]_+} $$

采样；如果整段候选全部通过，再由 target 产生一个 bonus token。这样保持的是 **target 的输出分布**，不是让 target 变得更聪明，也不是保证每个 draft token 事实正确。

这里 $p_i(v)=p(v\mid c,x_{<i})$，$q_i$ 必须是**实际用于提出候选的分布**，包含温度或候选截断等采样变换；$[a]_+=\max(a,0)$。不能在修正前的 logits 上计算 $q_i$，却拿修正后的分布去采样。贪心 target 则按相同前缀下的 argmax 逐位置匹配；随机采样时“接受”不等于必须命中 target 的最大概率 token。

**为什么 target 验证也能一次前向？** 此时整段候选已经给定，causal attention 可以并行计算每个位置的 $p_i$。采样验收按前缀顺序进行，但不需要每接受一个 token 就重新调用 target。若第 $i$ 位被拒绝，其后的验证结果废弃，后续轮次从修正后的前缀继续。

一个有用的速度近似是：

$$ \text{TPOT}\approx \frac{T_{\text{draft}}+T_{\text{verify}}}{\tau}, $$

其中 $\tau$ 是一轮最终推进的 token 数，通常包含已接受的 draft token 和一个 correction/bonus token。因而接受长度变长不一定自动带来更高端到端速度；draft 主干、LM head、验证、调度和 kernel 开销都要算进去。

### 1.1 “并行预测的问题不是排序”

一个 block 通常已经有明确位置：

```text
已确认上下文 → [位置1] [位置2] [位置3] ...
```

问题不是 token 不知道放在哪个位置，而是位置 2 在自己的候选生成时，还没有看到位置 1 **实际选出的 token**。DFlash 可以一次得到多个位置的 hidden 和 logits，但它缺少：

$$ x_{i-1}\text{ 被实际选出后，如何改变当前位置 }i\text{ 的预测} $$

因此应该把问题表述为：

> 并行 draft 降低了重复前向成本，但削弱了 block 内的条件依赖；后续方法要在不重跑完整 backbone 的前提下补回这种依赖。

这与“贪心是否正确”是两件事。贪心自回归仍然可以计算

$$ x_i=\arg\max p(x_i\mid x_{<i},c). $$

DFlash 的缺口是位置 $i$ 没有显式使用本轮已经采样的 $x_{<i}$，而不是贪心算法本身。

### 2. 统一视角：因果信息被放在哪里

四个方法可以按“因果依赖注入的位置”理解：

| 方法 | 因果信息主要注入的位置 | 直观特点 |
| --- | --- | --- |
| DFlash | 没有显式的本轮已采样前缀反馈 | 一次 block-parallel draft，吞吐好，但后缀容易不协调 |
| Domino | backbone 之后的 GRU + logits residual | GRU 记住当前块累计前缀 |
| DSpark | backbone 之后的 Markov/RNN correction | 默认只补前一个 token，分支更轻 |
| DSpine | backbone 每一层的 hidden stream，最后再做局部硬前驱修正 | 因果信息沿深度传播，位置在每层仍并行 |

可以把四者按设计轴排列；这不是在断言它们有严格的发表先后或相互继承关系：

```text
DFlash
  并行 backbone → 并行 logits

Domino
  并行 backbone → base logits → GRU 前缀状态 → logits residual

DSpark
  并行 backbone → base logits → 前一 token 的低秩转移 bias
                          └→ confidence head → target 验证预算调度

DSpine
  每层 backbone：hidden → 前驱预测特征注入 → 下一层 hidden
  最后：top-K transition cache → 按已选前驱查表选择
```

一个重要的成本结论是：三种改进方案都没有为 $m$ 个 draft token 重跑 $m$ 次完整 draft Transformer。DSpine 的循环主要遍历 backbone 层；Domino/DSpark 的循环是轻量 correction chain。

### 3. DFlash：一次 block-parallel draft

### 3.1 架构

DFlash 的目标是用一次 block-level forward 直接提出一段候选。它取目标模型已处理的上下文特征，和 anchor + MASK block 一起送入一个轻量 draft backbone。典型流程是：

下图取自 DFlash 论文 Fig. 2：左侧是 target model 提供的多层 hidden context，中央是 draft layers 中重复使用的 KV injection，右侧是一次 target LM head 投影。要强调“target context 被注入每个 draft layer”，以及“所有 mask 位置在同一 block forward 中处理”。

![](https://pic2.zhimg.com/v2-951bebce66cc2ec3673f1fcfaa02e08d_r.jpg)

```text
target 已确认上下文
        ↓ 取多层 target hidden，拼接/投影/RMSNorm
上下文特征 C_t ───────────────┐
                              ↓ K/V 注入 draft 每层
anchor + [MASK] ... [MASK] → draft backbone
                              ↓
                         H1 ... Hm
                              ↓ frozen target LM head
                         L1 ... Lm
                              ↓
                         draft tokens
```

如果用公式表示：

$$ H_{t:t+B-1} =\operatorname{Backbone} \big(C_t,\operatorname{Embed}(\tilde x_{t:t+B-1})\big), $$

$$ L_i^{\text{base}}=\operatorname{LMHead}(H_i). $$

target hidden 作为 K/V 注入 draft 层；这不是直接复用 target 原始 KV cache，也不是把 draft query 送回 target FFN。target embedding 和 LM head 通常冻结并共享。

图中的蓝色向量来自 target 的多个 hidden 层，经过融合后再由 draft 层自己的 K/V 投影使用；draft 的 query 和 FFN 主要处理较短的 anchor/MASK block。论文常用 block size 16，指 **1 个 anchor + 15 个待预测位置**，阅读不同表格时要核对是否把 anchor 计入。

论文将其称作 block diffusion 风格的 draft，但这里的推理 draft 是一次 denoising forward，不是进行许多轮扩散迭代。

### 3.2 它解决了什么，没解决什么

DFlash 把昂贵的逐 token draft 计算变成一次 block 计算。位置之间并非完全没有信息交流：draft hidden 可以在 block 内通过 attention 交流。但在位置 2 采样时，位置 1 的**最终离散采样结果**尚未可用。

因此不同位置可能各自选择了合理 token，却组合成不协调的序列。例如 `of course` 和 `no problem` 都是合理续写，但并行选择可能混成 `of problem`。target 验证会拒绝这类组合，后缀也会随之失效。

这个例子把词当作 token 方便说明，不要求实际 tokenizer 恰好这样切分。验证不在做语法判错；随机模式下组合仍可能被接受，其概率由 $p/q$ 决定。核心是：不协调的 proposal 往往与 target 条件分布重叠更少，导致接受率下降。

### 3.3 训练要点

- 随机抽取 anchor 和 masked blocks；target 先生成训练序列或提供目标特征。
- block 内使用隔离 attention，避免训练时不同 block 互相泄漏。
- 位置损失采用指数衰减，较早 token 权重更高，因为早期拒绝会阻断整个后缀。
- draft backbone、融合模块等可训练；target 和共享的 embedding/LM head 冻结。

若 $q_k$ 是第 $k$ 个 masked position 的 draft 分布、$y_k$ 是目标 token，位置加权目标可写成下面的形式。这里 $m$ 是候选个数，$\gamma_{\mathrm{decay}}$ 是衰减超参数，二者不要混为同一个量：

$$ \mathcal L_{\text{DFlash}} = -\sum_{k=1}^{m} \exp\left(-\frac{k-1}{\gamma_{\mathrm{decay}}}\right) \log q_k(y_k). $$

DFlash 的核心贡献是把并行 block draft 做成可用的低延迟模块；后续论文主要在“怎样恢复 block 内前缀依赖”上继续推进。

### 4. Domino：GRU causal encoder + logits residual

### 4.1 核心思想

Domino 保留 DFlash 式的并行 backbone，但在它之后增加一条很轻的串行因果链：

下图取自 Domino Fig. 3：左侧 parallel backbone 同时产出 $h_i$ 和 base LM logits；右侧绿色 Causal Encoder 沿 $d_0\rightarrow d_1\rightarrow\cdots$ 更新 $S_i$，黄色 MLP 产生 correction logits $c_i$，最后根据 $l_i+c_i$ 选择 $d_i$。图中的串行链属于 draft generation，不是 target verification。

![](https://pic4.zhimg.com/v2-cfe676bc9e41c67ddc280bb7e0c7a92b_r.jpg)

```text
一次并行 backbone：
    H1, H2, ... , Hm
          ↓ frozen target LM head
    L1_base, L2_base, ... , Lm_base

轻量串行 correction：
    anchor → GRU → correction_1 → 采样 x1
    x1     → GRU → correction_2 → 采样 x2
    x2     → GRU → correction_3 → 采样 x3
```

这里的串行发生在 draft 生成阶段，不是 target 验证阶段。草稿整段生成后，target 仍然一次验证整块。

### 4.2 Causal state 是怎么来的

令 $E(x_j)$ 为 token embedding，GRU 状态递推为：

$$ S_{i-1}=\operatorname{GRU}(E(x_{i-1}),S_{i-2}) $$

或简写为：

$$ S_{i-1}=\operatorname{GRU}(E(x_{<i})). $$

它只读取当前位置之前的 draft token，因此称为 causal encoder/state。这个状态是当前块前缀的压缩表示，不保证保留完整历史；有用信息是通过预测损失学出来的，不是 GRU 因为名字就自动理解语言关系。

更直观地，GRU 用更新门决定保留多少旧状态，用重置门参与构造新候选状态，再把两者混合。作为原理示意，可以写成 $S_j=(1-a_j)\odot S_{j-1}+a_j\odot\widetilde S_j$，其中 $a_j$ 和 $\widetilde S_j$ 都由当前 embedding 与旧状态经过可训练映射计算。不同实现对门的命名/互补约定可能不同，但关键是：每读一个 token，只更新固定宽度的记忆，不重跑整个 Transformer。这里的 $a_j$ 只是 GRU 示意门值，不是 DSpark 的前缀生存率。

### 4.3 从 hidden 到修正 logits

并行 backbone 已经产生位置 $i$ 的 hidden $H_i$，并通过冻结 target LM head 得到：

$$ L_i^{\text{base}}=\operatorname{LMHead}(H_i). $$

Domino 把 $H_i$ 和 $S_{i-1}$ **拼接**，而不是直接相加：

$$ \Delta L_i= W_2\operatorname{SiLU}\left(W_1[H_i;S_{i-1}]\right). $$

其中 $W_1$ 把拼接后的表示压到较窄的中间维度，SiLU 提供非线性，$W_2$ 再映射到词表维度。于是每一个词表 token 都得到一个修正值：

$$ L_i=L_i^{\text{base}}+\Delta L_i, \qquad q_i=\operatorname{softmax}(L_i). $$

这不是修改 $H_i$ 本身，而是直接在 logits 空间加残差。这样做的关键是：昂贵的完整 LM head 已经对整块并行算过，串行分支不必每生成一个 token 都重新执行完整 LM head。论文实现中 GRU hidden size 为 1024，correction bottleneck 为 256。

### 4.4 训练：teacher forcing、base loss、final loss

训练时使用目标模型重新生成的序列作为 teacher 序列：

$$ y_1,y_2,\ldots,y_m. $$

预测位置 $i$ 时，GRU 读取 $y_{<i}$，而 $y_i$ 只作为当前标签；预测完 $y_i$ 后，它才会进入下一位置的 GRU。这样避免标签泄漏。

对同一个位置计算两种 CE：

$$ \mathcal L_{\text{base}} =\sum_i w_i\operatorname{CE}(L_i^{\text{base}},y_i), $$

$$ \mathcal L_{\text{final}}= \sum_i w_i\operatorname{CE}(L_i,y_i). $$

总损失为：

$$ \mathcal L= \lambda_t\mathcal L_{\text{base}} +(1-\lambda_t)\mathcal L_{\text{final}}, $$

其中 $\lambda_t$ 从 1 线性退火到 0。

这里 $t$ 是训练步数，和 token 位置索引无关。论文的早位权重写作 $w_k=\exp(-k/\gamma)$。损失在 batch/位置上的求和或平均只影响尺度，复现时要与学习率一并核对。

在 $\lambda_t=1$ 的起点，只有 base loss，GRU 和修正头尚无来自 final loss 的梯度；随后它们逐步参与。最终 loss 的梯度也会通过 base 分支和 correction 对 $H_i$ 的依赖更新 backbone。**冻结 LM head 的参数，不等于把这条计算图放进 no_grad；仍需要梯度穿过冻结投影传回**$H_i$**。**

- base loss 让并行 draft backbone 自己形成较强的基础预测能力。
- final loss 训练 GRU 和 correction MLP 学会利用前缀修正预测，也会通过 $H_i$ 回传到 draft backbone。
- target、target LM head 和共享的冻结参数不更新；draft backbone、GRU、correction head 联合训练。
- 这里没有“正确 causal state”的单独标签，也不是对离散采样求导；teacher-forced token 是固定输入，梯度沿 GRU 的时间展开传播。

teacher forcing 的动机不是模拟所有错误 rollout，而是聚焦 speculative verification 真正有价值的区域：位置 $i$ 只有在前缀都被 target 接受时才贡献 accepted length。论文也用 base-anchored curriculum 防止 correction 分支在干净 teacher prefix 上走捷径、导致并行 backbone 学弱。

### 4.5 Domino 的取舍

优点：

- 只在轻量 GRU/correction branch 中恢复串行依赖。
- GRU 记住当前 draft block 的累计前缀，比只看前一个 token 更丰富。
- logits-space residual 避免在串行链上重跑完整 target LM head。

局限：

- 仍有一条串行 GRU 链，kernel launch 和小矩阵开销需要融合；论文用 Triton 和 CUDA Graphs 将报告设置下的 head latency 从 2.64 ms 降到 1.20 ms。
- GRU 状态是压缩记忆，不等于重新对完整 prefix 做 Transformer attention。
- 主表部分 baseline 使用公开 checkpoint、训练数据不同；同数据消融更适合解释结构收益。
- 论文主要验证 Qwen3-4B/8B 和 A100-SXM4-80GB，不能直接推出 NPU、超大 MoE 或其他 serving engine 的收益。

### 5. DSpark：Markov correction + confidence-aware scheduling

DSpark 同时做两件事：

1. 在 draft 生成阶段，用轻量 head 补回前一个实际 token 对后一个位置的影响。
2. 在 target 验证阶段，预测哪些 prefix 值得验证，并按系统负载分配验证预算。

下图取自 DSpark Fig. 1：先由 target 生成 anchor，再由 parallel block 一次产生基础 logits，Sequential Block 依次得到草稿 token 和 confidence，Hardware-Aware Prefix Scheduler 截短待验证 prefix，最后由 target 并行验证。

![](https://pic2.zhimg.com/v2-c6477a0606e437479ac864eb1ef5a535_r.jpg)

### 5.1 默认 Markov head

并行 backbone 先一次得到基础 logits：

$$ U_1,U_2,\ldots,U_m. $$

当前位置的 proposal 分布是：

$$ q_i= \operatorname{softmax} \left(U_i+W_1[x_{i-1}]W_2\right). $$

假设词表大小为 $V$，低秩维度为 $r$：

$$ W_1\in\mathbb R^{V\times r}, \qquad W_2\in\mathbb R^{r\times V}. $$

具体步骤是：

```text
x_{i-1}
  ↓ 查 W1 的一行
r 维前驱向量
  ↓ 乘 W2
V 维 logit 修正 ΔU_i
  ↓
U_i + ΔU_i
  ↓ softmax / greedy / sampling
q_i 或 x_i
```

所谓 Markov，不是额外训练了一个独立的马尔科夫概率模型，而是说这条 correction 分支只显式依赖最近一个 token：

$$ \Delta U_i=T[x_{i-1},:], \qquad T=W_1W_2. $$

每一行 $T[x_{i-1},:]$ 可以理解成“前一个 token 为 $x_{i-1}$ 时，对下一个词表候选的低秩分数修正”。完整分布仍同时依赖并行 backbone 的上下文表示 $U_i$：

注意 $T$ 是 logit bias 表，不是行和为 1 的概率转移矩阵；完整的 softmax 之后才得到概率。默认 Markov 分支对同一个前驱 token 产生相同 bias，具体上下文差异由 $U_i(C)$ 承担。这一点比 Domino 的 $\operatorname{MLP}([H_i;S_{i-1}])$ 更简单：Domino 的修正量本身也依赖当前位置 hidden。

$$ q_i(x_i\mid C,x_{i-1})= \operatorname{softmax} \left(U_i(C)+W_1[x_{i-1}]W_2\right). $$

因此 DSpark 默认版本不是完整的自回归 Transformer，也不是只由 Markov matrix 生成语言；它是并行上下文预测加一阶局部转移修正。

“一阶 Markov”描述在固定上下文和位置条件下，只显式依赖最近的已选 token；不需要引入强化学习中的 action 或 MDP。$W_1,W_2$ 在位置之间共享，串行的是推理时“选出前驱 → 修正下一位置”的依赖链。

图 1 还有一个位置对齐差异：DSpark 用 anchor 所在位置预测第一个新 token，因此 anchor + $\gamma-1$ 个 MASK 能产生 $\gamma$ 个草稿；DFlash 的原始描述只预测 MASK 位置。

### 5.2 RNN 变体

DSpark 也研究了带小型 recurrent state 的 RNN head，使 correction 可以累计块内更长前缀。这个方向在表达能力上接近 Domino 的 GRU，但默认 Markov 版本更简单、部署更轻；论文报告 RNN 额外收益有限，因此选择 Markov head 作为默认方案。

### 5.3 Confidence 不是 verifier

DSpark 另外训练 confidence head，估计在前缀已正确时当前位置通过 target 验证的概率：

$$ c_i= \sigma\left(w^T[h_i;W_1[x_{i-1}]]\right). $$

训练软标签可写成：

$$ c_i^*= 1-\frac12\lVert q_i-p_i\rVert_1. $$

这表示 draft 分布 $q_i$ 和 target 分布 $p_i$ 的重叠质量。它不是 verifier，也不是直接判断某个已采样 token 的真假；target 仍然执行标准 lossless verification。

这个标签来自标准验收率的恒等式：

$$ \mathbb E_{x\sim q_i}\!\left[\min(1,p_i(x)/q_i(x))\right] =\sum_v\min(p_i(v),q_i(v)) =1-\tfrac12\lVert p_i-q_i\rVert_1. $$

$c_i$ 在当前位置 token 采样前即可计算，因为它只读取 $h_i$ 和前驱 token。若它读取了当前已抽出的 token，再用来决定是否保留该抽样，必须额外处理选择偏差。

前缀存活概率估计为：

$$ a_j=\prod_{i\le j}c_i. $$

### 5.4 硬件感知的验证调度

对多个请求 $r$，如果第 $r$ 个请求保留 $\ell_r$ 个候选，验证 batch token 数可表示为：

$$ B=\sum_r(1+\ell_r). $$

预计每轮推进量为：

$$ \hat\tau= \sum_r\left(1+\sum_{j\le\ell_r}a_{r,j}\right). $$

DSpark 通过引擎 profile 得到的 $\operatorname{SPS}(B)$ 估计整体吞吐：

$$ \hat\tau\times\operatorname{SPS}(B). $$

于是调度器不是简单地“每个请求 confidence 大于 0.8 就验证”，而是在全局负载下决定每个请求应该验证多长的 prefix。负载轻时可以验证更长，负载重时更积极地截短，把 target 算力给更有收益的 prefix。

### 5.5 DSpark 的 lossless 陷阱

如果 scheduler 先生成了完整 draft，再用后面才产生的 confidence 回头决定是否保留前面的样本，就可能产生 selection bias，破坏 target 分布。论文给出的反例是：如果 draft 抽到 A 时保留，抽到 B 时直接让 target 重采样，那么最终输出概率会偏离 target 的原始分布。

把附录反例具体化：target 有 $p(A)=0.7$，draft 有 $q(A)=0.5$。抽到 A 时保留并验收，抽到 B 时放弃该 draft、让 target 重采样，则最终

$$ P(\text{输出 A})=0.5+0.5\times0.7=0.85, $$

已经偏离原来的 0.7。

理论 scheduler 在预测吞吐首次不再增加时停止；要同时获得全局最优，还需要吞吐目标沿候选加入路径呈单峰。实际硬件的容量曲线有台阶，论文的生产实现用**两步之前的历史 confidence**选择本轮总容量，再用当前 confidence 排序连续前缀。历史容量决定和当前样本分离，服务于概率正确性和 CUDA Graph/ZOS 的提前排程。

此外，confidence 还需要校准。论文使用 Sequential Temperature Scaling，按位置校准累计前缀生存率；confidence 准确度主要影响资源分配效率，调度是否遵守合法信息时序则影响分布正确性。

### 5.6 DSpark 训练与边界

DSpark 冻结 target，训练 draft backbone、Markov/RNN head 和 confidence head。论文的主要损失包括：

$$ \mathcal L= 0.1\mathcal L_{CE} +0.9\mathcal L_{TV} +1.0\mathcal L_{conf}, $$

三个子损失都采用 $w_i=\exp(-(i-1)/\gamma)$：

$$ \mathcal L_{CE}=-\sum_i w_i\log q_i(y_i), $$

$$ \mathcal L_{TV}=\sum_i w_i\lVert q_i-p_i\rVert_1, $$

$$ \mathcal L_{conf}=-\sum_iw_i\left[c_i^*\log c_i+(1-c_i^*)\log(1-c_i)\right]. $$

论文将第二项命名为 TV loss，但 Eq. 10 实际写的是 L1 距离，即数学定义 TV 的两倍；复现默认系数 0.9 时应遵循原式，不应额外乘半。第三项是软标签 BCE。

共享 target embedding/LM head 同样冻结。论文没有像 Domino 那样详述 sequential head 的 teacher-forcing 与 on-policy 前缀喂法，不能据本文公式补写为“训练过程完全相同”。

DSpark 自己的离线主表关闭 scheduler，固定 $\gamma=7$、温度 1、non-thinking、chain drafting；EAGLE3 使用 1 层，DFlash/DSpark 使用 5 层，同数据重训。它报告 $\tau$，不能直接换算成端到端加速。

生产版本另用 3 层 MoE + mHC + 128 sliding window、$\gamma=5$，配合动态 scheduler；不能和离线 Qwen 配置混为一套。论文没有公开生产 GPU 型号/卡数，不能直接外推 NPU/vLLM 性能。

调度器也有成本边界：它截短的是 target 的验证长度，parallel draft backbone 在此之前已经计算了整块。草稿很难被接受时，这笔固定 draft 成本无法回收。把 SPS 仅建模成验证 token 数的函数也是部署相关的简化，换模型、上下文长度分布或引擎后需要重新 profile。

### 6. DSpine：把因果依赖放进每一层 hidden stream

### 6.1 Novelty 的一句话

Domino/DSpark 主要是：

```text
并行 backbone → base logits → backbone 后的 correction branch
```

DSpine 则是：

```text
每一层 backbone：
当前位置 hidden + 前驱预测特征 → 更新当前位置 hidden
```

它仍然只做一次 block-parallel backbone forward，但把前驱信息沿网络深度传播，而不是等 backbone 完成后只在 logits 端补一次。

下图取自 DSpine Fig. 3：左半图绿色路径表示每层的 predecessor-feature injection，橙色路径表示最后的 transition-cached decoding；右半图把一层 injection 展开为特征投影、gate、message、写回 residual，以及训练时的 cosine alignment 和正确前驱替换。

![](https://picx.zhimg.com/v2-8719f587081bc008cf8c8425cdae5007_r.jpg)

### 6.2 符号先对齐

对于第 $\ell$ 层、位置 $t$：

| 符号 | 含义 |
| --- | --- |
| u_{\ell,t} | 第 \ell 层注入前的 hidden state，维度为 backbone hidden size d |
| R_\ell | 把 hidden 映射到统一 transfer space 的层专属投影 |
| z_{\ell,t} | 由 u_{\ell,t} 产生的低维预测特征，不是 logits |
| A z_{\ell,t-1} | 前驱要发送给当前位置的 message |
| g_{\ell,t} | 每个 message 通道的 gate |
| W_\ell | 把 message 写回 hidden/residual stream 的层专属矩阵 |
| h_{\ell,t} | 注入后的 hidden state，会进入下一层 |

预测特征为：

$$ z_{\ell,t}= \sqrt r\,\operatorname{normalize}(R_\ell u_{\ell,t}), $$

其中 normalize 是 L2 normalization，$r$ 是 transfer space 维度。$z$ 不是 $V$ 维 logits，不经过中间全词表 softmax。

### 6.3 两条注入公式逐项解释

论文先算 gate：

$$ g_{\ell,t}= \sigma \left( G_qz_{\ell,t} +G_pz_{\ell,t-1} +b \right). \tag{DSpine-4} $$

其中：

- $z_{\ell,t}$：接收者自己的预测特征；
- $z_{\ell,t-1}$：紧邻前驱的预测特征；
- $G_q$：把接收者特征投影到 gate 空间；
- $G_p$：把前驱特征投影到 gate 空间；
- $b$：偏置；
- $\sigma$：逐元素 sigmoid；
- $g_{\ell,t}$ 的每个分量通常在 $0$ 到 $1$ 之间，表示对应 message 通道通过多少。

接着生成前驱消息并写回 hidden：

$$ m_{\ell,t}=A z_{\ell,t-1}, \tag{message} $$

$$ h_{\ell,t}= u_{\ell,t} +\operatorname{RMS}(u_{\ell,t})W_\ell \left(g_{\ell,t}\odot m_{\ell,t}\right). \tag{DSpine-5} $$

逐步解释：

1. $A$ 把 $r$ 维前驱特征投影成 message 维度。
2. $g\odot m$ 是逐元素乘法，按通道筛选前驱消息。
3. $W_\ell$ 把筛选后的 message 投影回 hidden 维度 $d$。
4. $\operatorname{RMS}(u_{\ell,t})$ 按公式的维度应理解为由当前位置 hidden 提供的标量 RMS 幅度缩放因子，用于调节写入强度；它不是完整向量 RMSNorm、logits 或概率。论文正文没有单独展开这一 RMS 的具体实现，因此不应据此断言 epsilon 或是否 detach。
5. 最后和原始 hidden $u_{\ell,t}$ 做 residual addition，得到 $h_{\ell,t}$。

在论文的 Qwen3-8B 配置中，hidden size 为 4096，transfer feature 维度为 1024，message 维度为 512。$A,G_q,G_p,b$ 跨层共享，$R_\ell,W_\ell$ 每层独立。

用 $a=512$ 表示 message 宽度，矩阵形状是：

$$ R_\ell\in\mathbb R^{r\times d},\quad A,G_q,G_p\in\mathbb R^{a\times r},\quad b,g_{\ell,t},m_{\ell,t}\in\mathbb R^a,\quad W_\ell\in\mathbb R^{d\times a}. $$

因此写回是“标量 × $d$ 维向量”，才能与 $u_{\ell,t}$ 相加。sigmoid gate 调节的是消息通道，不是词表 token 的接受概率；它也不是 attention 的 Q/K 点积。

伪代码是：

```python
z_prev = sqrt(r) * l2_normalize(R_layer @ u_prev)
z_cur  = sqrt(r) * l2_normalize(R_layer @ u_cur)

gate = sigmoid(Gq @ z_cur + Gp @ z_prev + b)
msg  = A @ z_prev

h_cur = u_cur + rms(u_cur) * (W_layer @ (gate * msg))
```

### 6.4 为什么不会因为 $m$ 个 token 重跑 $m$ 次 backbone

DSpine 的循环主要是层循环：

```python
for layer in range(L):
    u = layers[layer](h, target_context_kv, block_causal_mask)
    z = project[layer](u)             # [block_positions, r]，读取注入前状态
    z_prev = concat(token_feature(anchor), z[1:-1])
                                      # 与候选位置 1..M 对齐的前驱特征
    h_next = u.clone()
    h_next[1:] = inject[layer](u[1:], z[1:], z_prev)
    h = h_next                       # 注入后的整块 hidden 进入下一层
```

同一层所有位置使用注入前的 $u/z$，因此层内不需要先更新 $t-1$ 再更新 $t$。下一层接收上一层已经写入的信息，因果链沿 depth 展开。DSpine 还使用 block-causal attention，让位置只看 target context 和 block 中不晚于自己的位置，避免训练时正确前驱信息倒流到更早位置。

因此它是一次真正的 block-parallel backbone forward，并不是为每个 draft token 做一次完整前向。

这里 $h$ 初始为 anchor/MASK 的输入表示；伪代码只表达数据依赖，省略 batch、缓存和融合 kernel。anchor 自身不接受前驱注入。

例如，位置 $t-2$ 的信息在第 $\ell$ 层先影响 $t-1$，经后者的下一层计算后，再在第 $\ell+1$ 层影响 $t$。同时，block-causal attention 仍能访问更早位置，不能把整个模型的感受野误说成“只有层数这么多的相邻位置”。

我们讨论中曾用“模拟前向”辅助理解。宣讲时更准确的术语是：**一次真实并行前向中的近似前驱条件化**。它传播的是尚未确定 token 的预测特征，不是已采样完整前缀下的精确自回归前向。

### 6.5 Unified transfer space

DSpine 需要让两种东西走同一个注入接口：

- token 尚未决定时：前驱位置发送预测特征 $z_{\ell,t-1}$；
- token 已决定时：前驱位置发送真实 token 的特征 $\sqrt r C_{x_{t-1}}$。

固定表 $C$ 来自 target LM head 的 output embeddings：行向量归一化、中心化、PCA whitening、保留 $r$ 个方向、再次归一化。

这不是每层都做一次完整词表解码，而是把预测特征和真实 token 映射到同一个低维 transfer space。训练再用 cosine alignment，让中间层的预测特征靠近正确 token 的 $C_y$。

### 6.6 Last-write refinement 与 transition cache

backbone 最后得到各位置 hidden，并通过共享 LM head 得到每个位置的 initial top-$K$ candidates。实际选择前驱 token $s$ 后，DSpine 用 $\sqrt r C_s$ 替换前驱预测特征，重新执行最后一层的局部 write：

$$ z_{L,t-1}\rightarrow \sqrt r C_s. $$

它使用缓存的最终层注入前 $u_{L,t}$，不用重跑整个 Transformer layer。然后用 LM head 对当前位置候选重新打分。

如果直接按位置顺序重算，每个位置都需要等待前驱选择。DSpine 预先对相邻位置所有 top-$K$ 候选组合并行算分：

$$ T_t[i,j]= S_t(v_{t-1,i},v_{t,j}). $$

有了 $K^2$ transition cache，实际顺序选择只需要：

![](https://pic1.zhimg.com/v2-862d142c53384cc5b87883952b6251a6_r.jpg)

```text
已选前驱 → 查对应行 → 选择当前位置候选
```

这不是完整 $K^m$ 搜索树，也不是 Viterbi 全局路径搜索；它是局部相邻转移的并行预计算。

温度为 1 时，DSpine 在每个位置的 top-$K$ 候选集合上对 transition-cache 分数重新归一化，得到实际 proposal 分布 $q_i$，再把这个截断 proposal 交给标准 rejection sampling。target 的 residual correction 仍在完整词表上计算。因此 top-$K$ 截断影响效率和接受率，但“无损”依赖于使用正确的截断 $q_i$ 与完整 target residual；不能把 top-$K$ 后的分数直接当作未截断的 proposal 概率。

### 6.7 DSpine 训练

target、共享 input embedding 和 LM head 冻结。训练同时监督：

1. 普通 final-layer output：生成全词表分布和 top-$K$ 候选；
2. last-write refinement output：使用正确前驱 token，针对候选集合生成条件分布。

对 draft 分布 $q_i$ 和 target 分布 $p_i$，位置损失采用 CE 与 L1 分布距离混合：

$$ \mathcal L_{\text{dist}}= \sum_i w_i \left[ -\alpha\log q_i(y_i) +(1-\alpha)\lVert q_i-p_i\rVert_1 \right]. $$

last-write 输出也使用同一形式，只在 top-$K$ 候选上计算，并把 target 分布重归一化到该候选集合。普通输出与 last-write 两路 loss 等权相加，$\alpha=0.1$。附录还限定：只有正确 token 位于 top-$K$ 时计算该位置的 refinement CE；只有候选集合的 target 概率质量超过 $10^{-4}$ 时计算其 L1 项。这避免把不在候选中的标签硬塞进候选 softmax。

另有 layer-wise embedding alignment：

$$ \mathcal L_{\text{emb}}= \sum_{\ell,i}w_i \left[1-\cos(e_{\ell,i},C_{y_i})\right], $$

其中 $e_{\ell,i}=f_\ell(h_{\ell,i})$ 从 **post-injection hidden** 读出；真正传递的 $z_{\ell,i}=f_\ell(u_{\ell,i})$ 则来自 **pre-injection hidden**。两者使用相同 readout，但输入时刻不同。cosine loss 只约束低维投影方向，不强迫完整 hidden 只保存 token 身份。总目标为：

$$ \mathcal L= \mathcal L_{\text{dist}} +\lambda\mathcal L_{\text{emb}}. $$

训练早期预测特征不可靠，因此对每个 block 做一次共享的随机选择，在第 1–3 层以概率 $p$ 把前驱输入替换为 $\sqrt r C_{y_{t-1}}$；receiver feature 始终由模型产生。前 1⁄6 训练中 $p=0.5$，随后线性下降，在 1⁄3 训练时变为 0。final last-write 始终使用正确前驱。

$W_\ell$ 和 $G_p$ 零初始化、$b=0$，使注入从 identity residual 开始。附录的 embedding loss 权重写为 $\lambda=\beta_t\,\mathrm{sg}(CE_{\mathrm{bb}})$，其中 $\mathrm{sg}$ 表示停止梯度（不是 sigmoid），$\beta_t$ 在前 146 步升到 0.5；这是一种随 backbone CE 尺度调整的辅助损失权重，不能误写成固定常数。

### 6.8 DSpine 的边界

- 软预测特征不是实际已采样 token，因此它不是精确 AR 被免费并行化。
- 最终实际 token 只显式参与局部 last-write；完整已选 prefix 不会重新进入 backbone。
- top-$K$ 截断影响 proposal 质量和效率；只要使用正确 proposal 概率与完整 residual correction，候选漏掉的 token 可以通过 target residual sampling 恢复分布。
- $K^2$ transition scoring、fused kernels 和 CUDA Graphs 是性能的一部分，朴素 PyTorch 复刻不应直接预期论文时延。
- 统一实验固定 15 个 draft token；它适合比较该配置下的 drafter 结构，不覆盖 DSpark 完整动态 scheduler 的线上收益。
- 主要证据是 Qwen3-4B/8B、非 thinking、单 GPU、并发最多 32；论文未给出 NPU、超大 MoE 或 Qwen3.8 Flash Next 的证据。

### 7. 四种架构的横向对比

| 维度 | DFlash | Domino | DSpark | DSpine |
| --- | --- | --- | --- | --- |
| 重型 draft backbone | 一次 block-parallel | 一次 block-parallel | 一次 block-parallel | 一次 block-parallel，层内增加 injection |
| 因果补偿位置 | 无显式实际前缀反馈 | backbone 后 | backbone 后 | backbone 内每层 + 最终 local refinement |
| 前缀信息 | 主要是并行 hidden | GRU 累计状态 | 默认最近前驱 token；另有 RNN | 每层前驱预测特征，最终硬前驱 |
| 修正空间 | 直接 base logits | logits residual | logits bias | hidden/residual stream，最后 LM head |
| draft 中的串行部分 | 无本轮已选 token 的逐位置反馈链 | GRU + correction + sampling | Markov/RNN correction + sampling | transition cache 后的顺序查表/选择 |
| 训练特色 | block diffusion 风格、早位权重 | teacher forcing + base/final curriculum | CE + distribution matching + confidence | CE/L1 + layer-wise embedding alignment + early replacement |
| 主要优势 | draft 成本低、并行度高 | 前缀记忆丰富，结构清楚 | correction 轻，调度也优化 | 因果信息较早进入 backbone，前驱条件化更充分 |
| 主要代价 | 后缀条件一致性弱 | 串行 GRU 开销 | 只看前驱的默认 head 表达较窄 | 训练/内核/候选 cache 更复杂 |

一个简化的判断是：

```text
DFlash 解决“如何一次并行提出很多候选”
Domino 解决“如何用累计前缀状态修正候选”
DSpark 解决“如何用更轻的局部修正，并按负载决定验证预算”
DSpine 解决“如何把前驱预测信息提前送进每层 backbone，再做真实前驱的局部校正”
```

### 8. 训练和推理中最容易混淆的概念

### 8.1 logits、概率、loss 不是一回事

hidden 经过 `lm_head` 得到词表分数：

$$ L=W_{\text{vocab}}h+b. $$

这些分数叫 logits。softmax 只是把 logits 变成概率：

$$ p=\operatorname{softmax}(L). $$

如果正确标签是 $y$，交叉熵才是：

$$ \operatorname{CE}(L,y)=-\log p(y). $$

softmax 本身不是 loss。贪心解码可以直接对 logits 做 argmax；随机采样才需要用 softmax 概率。

### 8.2 普通 LLM 的 `lm_head`

Transformer 的最终 hidden 通常经过 RMSNorm/LayerNorm，再通过一个线性 `lm_head` 映射到词表：

$$ L=W_{\text{vocab}}h. $$

`lm_head` 通常是线性层，不是 Transformer block 内部的 FFN/MLP。它属于模型参数；如果输入 embedding 与输出头 weight tying，则两者共享参数，不会重复计数。

### 8.3 target 验证不是 Domino/DSpark/DSpine 的 correction

- Domino 的 GRU：在 draft 生成阶段，根据前面已经选出的 draft token 修正后续 draft logits。
- DSpark 的 Markov head：同样在 draft 生成阶段，根据前一个 draft token 生成 logit bias。
- DSpine 的 injection：在 draft backbone 内传播软前驱特征，最后做局部真实前驱 refinement。
- target verification：在草稿完成后，用目标模型验证 block；它不是这些 correction head 的工作。

### 8.4 teacher forcing 不是把 target LM 每一步在线重跑

Domino 的 teacher forcing 是：预测位置 $i$ 时，用训练序列中的真实/target-generated 前缀 $y_{<i}$ 作为 GRU 输入，$y_i$ 作为标签。它不是让目标模型逐位置在线重新生成 teacher token，也不是把 $y_i$ 提前喂进 GRU。

这些数字适合说明：在该统一训练和固定 proposal budget 下，DSpine 的 draft accepted length 更高。但不要把它读成“DSpine 在所有部署场景一定最快”，原因包括：

- 温度 1 时，DFlash/Domino 仍用 greedy proposal，DSpark/DFlash2/DSpine 用 sampled proposal + rejection sampling；该列的差异包含 proposal policy，不能全部归因于网络结构。
- 固定 15 proposal 的统一实验不包含 DSpark 完整动态 scheduler 的所有线上收益。
- accepted length 不是端到端速度；验证、draft kernel、top-$K$ scoring、transition cache 和并发都会影响结果。
- Domino 的部分 headline 数字来自不同训练 checkpoint/数据设置；同数据表和独立消融更适合做结构归因。
- 论文的 GPU、模型尺寸和 serving backend 范围有限，不能直接外推到 NPU、vLLM-Ascend、超大 MoE 或多模态模型。

DSpark 的线上数字也需要限定：生产 preview engine 与旧 MTP-1 baseline 的收益，不能简化成普遍适用于任何目标模型和硬件的固定 speedup。严格 SLA 下的巨大百分比提升部分来自 baseline 接近吞吐塌陷区间。

另一个便于讲成本权衡的例子来自 Domino Fig. 1：同数据、Qwen3-8B、A100、GSM8K、context 1024、16-token budget，EAGLE3 的 $\tau=4.86$、加速 3.28×；DFlash 为 4.03、3.42×；Domino 为 4.70、3.84×。接受长度最高的方案未必最快。

Domino 摘要声称 SGLang 最高 5.8×，但当前 PDF Table 2 可核对最高是约 5.1×，两者口径未解释，本文不用 5.8× 作比较依据。DSpine 的吞吐实验单实例为 TP=1、BF16、FA3 和 CUDA Graphs，论文没有给出具体 GPU 型号；不能自行补成 H100/H200。

DSpine 自己的端到端吞吐数字也有不同参照系：摘要报告相对 DFlash 平均高 23.3%；正文报告 Qwen3-8B 相对最强 DFlash2 平均高 11.1%，Qwen3-4B 高 6.5%，并可达到约 4.0× AR speedup。Qwen3-8B 的模块拆解中，每轮约 7.14 ms，对比 DFlash2 的 7.19 ms；按生成 token 归一化后下降约 10.9%。这些是 SGLang 固定实验条件下的端到端或模块级数字，不能从 accepted length 表直接推出。

常见训练配置可作为复现入口，而不是等预算比较：

| 方法/设置 | 数据与规模 | 训练与结构 |
| --- | --- | --- |
| DFlash 原论文 | 约 80 万条 target 重生成的 Nemotron + CodeAlpaca 混合样本 | 常用 5 层、block 16；早位加权 CE |
| Domino 主实验 | target 重生成的 PerfectBlend，约 142 万样本 | 3 epochs，8×A100-80GB，全局 batch 16，最大长度 3072，AdamW 峰值 LR 6\times10^{-4}，GRU 1024、瓶颈 256 |
| DSpark 离线 | 约 130 万条 Open-PerfectBlend prompts，target 重生成回答 | 10 epochs，5 层、\gamma=7、non-thinking；独立于生产 MoE 配置 |
| DSpine 统一实验 | target 重生成 ShareGPT，关闭 thinking | 6 epochs/3655 步，全局 batch 112，最大长度 3072，峰值 LR 6\times10^{-4}，5 层、top-K=16 |

这里的“层数/预算/数据”必须一起读；不能用某篇训练 10 epochs 的 accepted length 和另一篇训练 3 epochs 的速度直接给结构排序。

### 10. 研究 insight：接下来真正值得优化的地方

### 10.1 结构设计的主矛盾

并行化越彻底，draft 成本越低，但前缀条件依赖越弱；串行修正越强，接受率可能越高，但关键路径和 kernel 开销越大。可把目标写成：

$$ \max \frac{\text{expected accepted/bonus tokens}} {\text{draft cost}+\text{verify cost}+\text{serial correction cost}}. $$

不能只优化 accepted length，也不能只优化单个 head 的 latency。

### 10.2 依赖信息的表示层级

四篇论文形成了一个自然的层级：

```text
没有实际前缀反馈
  → 前一个 token 的低秩 logits bias
  → GRU 压缩的当前块累计前缀
  → 每层 hidden 的软前驱传播 + 最终硬前驱 refinement
```

更强的表示未必总是更快。DSpark 的默认 Markov head 就体现了一个工程判断：如果一阶局部 correction 已经能显著改善后缀 acceptance，那么更复杂的 RNN 记忆可能不值得付出部署代价。

### 10.3 软前驱和硬前驱的统一接口

DSpine 的 unified transfer space 给出一个很有启发性的设计：

```text
未决定：预测特征 z
已决定：真实 token embedding C_x
两者进入同一 injection path
```

这比把“预测阶段”和“实际选择阶段”设计成两套完全独立网络更容易共享训练信号，也更容易做 last-write refinement。

### 10.4 调度本身也有概率因果性

DSpark 最值得注意的不只是 confidence head，而是它指出：即使 verifier 本身是 lossless，scheduler 如果偷看当前样本的未来 confidence 再回头决定是否验证，也可能造成 sampling selection bias。

因此“概率正确性”有两层：

1. draft/target 的 accept-reject-residual 公式是否正确；
2. scheduler 的选择过程是否使用了合法的信息时序。

### 10.5 一个可检验的组合假设

一个值得实验、但不能直接宣称已被论文验证的组合是：

> 用 DSpine 的层内预测特征传播提高 draft 条件一致性，再用 DSpark 的 confidence scheduler 依据负载动态决定 target 验证长度。

这不是把两个 headline speedup 相乘。组合后必须重新测量：

- draft backbone 增量成本；
- scheduler 是否改变有效 batch size；
- transition/cache 与动态 budget 的兼容性；
- accepted length、end-to-end TPOT、SPS 曲线和 tail latency；
- 在高拒绝率时固定 draft 成本是否抵消 scheduler 收益。

### 11. 互动问题

**互动问题 1：** 给 DFlash 加 causal attention mask，是否就等于读取了前面实际采样 token？答案是否定的；输入仍是 anchor/MASK，mask 控制能看哪些位置，不会凭空提供尚未选出的 token。

**互动问题 2：** 在 GRU 或 injection 后加一个 MLP，为什么就能修正候选？因为训练损失把“前驱条件 → 有用状态/消息 → 候选分数”整条可微路径一起训练；不是手写规则，也没有单独的“正确 residual”标签。

**互动问题 3：** 投机解码的 verifier 会不会像 benchmark verifier 一样被 hack？标准投机验收的目标是严格保持给定 target 分布，关注的是概率实现正确性；它不是通用事实核查或能力评测，不能把保持分布等同于答案更可靠。

> DFlash 把 draft 生成从逐 token 改成 block-parallel，但多个位置之间缺少本轮已采样前缀的显式反馈。Domino 在 backbone 后用 GRU 维护块内累计前缀，并通过低秩 MLP 在 logits 空间做残差修正；DSpark 默认只用前一个 token 的低秩 Markov bias，另外用 confidence scheduler 决定 target 验证多少 token；DSpine 则把前驱的预测特征提前注入每一层 hidden stream，让因果依赖沿网络深度传播，最后再用真实前驱 token 做局部 last-write 和 transition-cache 选择。它们共同追求的是：用最小的串行成本恢复尽可能多的因果一致性。
