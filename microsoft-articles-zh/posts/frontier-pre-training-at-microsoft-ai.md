# Microsoft AI 的前沿预训练

> 原文：[Frontier Pre-training at Microsoft AI](https://microsoft.ai/news/frontier-pre-training-at-microsoft-ai/) · Microsoft AI

今年六月，我们发布了 [MAI-Thinking-1](https://microsoft.ai/wp-content/uploads/2026/06/main_20260602_2.pdf)，这是一个在 MAI-Base-1 之上完成后训练的通用基座模型，具备强大的推理性能。我们最近完成了对全新最先进模型 MAI-Base-2 的预训练，这是一个拥有 800 亿活跃参数、2.8 万亿总参数的 MoE 基座模型。

在我们的留出评测集上，MAI-Base-2 优于我们测试过的所有开放权重模型。它的预训练 FLOPs 效率比最强的开放基座模型 DeepSeek-V4-Pro-Base 高出 4-12 倍（见下文图 3），而我们把省下的算力投入到了训练一个更大的模型中。

图 1 展示了 MAI-Base-2 与其他总参数量至少为一万亿的模型在一系列预训练评测上的表现（数值越低越好）。

端到端地掌控我们的模型流水线，使微软能够为客户提供独具特色的服务。微软对进入模型的训练 token 拥有强有力的数据来源合规保障。我们的预训练建立在有机数据之上，不涉及对其他模型的蒸馏。这使我们能够通过 Foundry 向受信任的合作伙伴授予模型权重许可，从而为企业提供满足其需求的世界一流智能的可信来源。

掌控全栈使我们能够把模型与基础设施放在一起调优，以最低的成本实现最佳性能——首先用于我们自己的产品，然后服务于 Foundry 客户。MAI-Base-2 目前正在进行后训练，我们期待很快分享更多结果。

## **MAI-Base-2 的表现对比**

当我们完成 MAI-Base-1 的训练时，预训练的前进方向十分明确：扩大规模。尽管 MAI-Base-1 就其规模而言已经是一个很强的模型，但它比处于前沿的开放权重模型和专有模型都要小。

以下三项举措对 MAI-Base-2 的成功预训练尤为重要：

- 缩放科学：考虑重复训练数据的缩放阶梯，以及经验性超参数缩放定律。
- 模型-基础设施协同设计：改进的 MoE 与 Muon 实现，以及激活梯度裁剪。
- 数据规模化：扩展的数据流水线与视觉数据的整合。

MAI-Base-2 是一个比 MAI-Base-1 更大、更稀疏的模型，训练所用的数据也更多。我们于 2026 年 8 月至 9 月在 16k 块 GB200 GPU 上训练了 38 天。整个训练过程中，平均 MFU（模型 FLOPs 利用率）为 21%，goodput（训练正常推进的时间占比）为 89%。我们的 MFU 以 2.5 PFLOPS（GB200 在 BF16 下的理论峰值）为基准归一化，且不包含重计算和优化器的 FLOPs。

我们在留出文本上使用每字节比特数（bits-per-byte，BPB）比较预训练模型，该指标与各模型所用的分词器无关。留出代码评测使用 MAI 自己的代码库，而 STEM、数学和问答评测则委托外部供应商提供，以降低训练集污染的风险。此外，我们还针对我们的训练数据对所有评测集做了去污染处理。

我们将 MAI-Base-2 与 2026 年 10 月之前可获取的前沿检查点进行比较：

- DeepSeek-V4-Pro-Base 是能力最强的开放权重基座模型。
- Kimi K3、Qwen3.8-2.4T-A95B 和 MiMo-V2.6-Pro-RL 是能力很强的开放权重模型。这些模型只有后训练检查点可用。我们报告其结果时需注意，后训练可能会影响这些评测。

在所有这些留出评测上，MAI-Base-2 都取得了比我们测试的其他模型更低的 BPB。下面，我们深入介绍促成这一结果的部分进展。

## **稳健的缩放阶梯**

我们使用缩放阶梯来评估模型改动：即采用固定训练配方、由不同规模的模型组成的模型家族。阶梯的每一级以其层数 \( L \) 命名，仅凭 \( L \) 即可确定其余架构。例如，隐藏层大小为 \( (256/3) \cdot L \)，query 头数为 \( L \)（四舍五入到最接近的 16 的倍数）。我们在保持单位活跃参数训练 token 数（TPP）不变的同时，训练规模递增的模型。

为了考虑较小规模下的多轮（multi-epoch）训练，我们使用一种称为 *source scaling* 的技术。在缩放阶梯的较低层级上，source scaling 人为限制模型训练所用的去重样本集合，使得无论训练跨度多长，每个数据集都被重复相同的次数。例如，如果某个数据集在完整的 50T token 训练中重复 8 次，那么 5T token 的训练将只对该数据集的 1/10 循环 8 次。

在固定的 TPP 下，source scaling 实际上使去重数据与参数之比保持恒定，这有助于确保结果在各规模之间平滑迁移。如果不做 source scaling，较小规模的实验可能偏向正则化不足的架构和超参数选择，而这些选择在更大规模上会过拟合。把 source scaling 纳入我们的阶梯，是我们能够可靠地扩展到 2.8T 参数模型的关键。图 2 演示了如何利用缩放阶梯准确预测 MAI-Base-2 的性能。

## **将建模效率与算力分离**

模型之间的直接比较会把训练配方的质量与模型规模及训练算力的差异混为一谈。为了单独考察配方，我们估计我们的配方需要多少算力才能追平一个强大的外部基座模型。我们以 DeepSeek-V4-Pro-Base 为参照：它是唯一已发布的参数量超过一万亿的基座预训练检查点，不过其训练 FLOPs 仍显著少于 MAI-Base-2。

针对图 1 中的四项留出评测，我们分别独立拟合 BPB 相对训练 FLOPs 的缩放定律，并估计我们阶梯上的模型追平 DeepSeek-V4-Pro-Base 的 BPB 所需的算力。MAI-Base-2 的最终性能是已知的，我们将其纳入拟合，因此匹配点落在已拟合模型的范围之内而非之外。将这些估计值与 DeepSeek-V4-Pro-Base 的训练算力相比，我们发现我们的配方在 FLOPs 效率上高出 4.2–12.3 倍，如图 3 所示。我们还与 MAI-Base-1 进行了比较，发现自该模型今年 6 月发布以来，我们的进步带来了 6.3-12.7 倍的 FLOPs 效率提升。我们将 MAI-Base-2 的 FLOPs 效率归因于数据的质量与相关性，以及建模选择带来的效率增益，下文各节将分别介绍。

## **超参数的缩放定律**

为大型训练任务选择最优超参数十分复杂，因为超参数优化是一个组合空间，改动一个超参数可能影响其他超参数的最优取值。针对 MAI-Base-2，我们重新审视了解决这一问题的方法。

我们联合扫参学习率（\(LR\)）与权重衰减（\(WD\)），因为二者对训练的影响是耦合的。模型性能对 \(LR\) 与 \(WD\) 的乘积最为敏感，因此好的配置位于 \((\log{LR}, \log{WD})\) 平面中一条狭窄的对角带内。在 \((\log{LR}, \log{WD})\) 上使用矩形网格对这条带采样效率很低，因此我们改为在 \((\log{LR}, \log{(LR \times WD)})\) 上扫网格。

针对若干种模型规模与 TPP 的组合，我们沿搜索网格训练模型，并在我们的预训练评测上评估它们。我们对评测结果拟合二维二次函数，并提取其解析最小值 \((LR^\*, LR^\* \times WD^\*)\)。图 4 展示了该实验的几个切片。

随后，我们把 \(\log{(LR^\* \times WD^\*)}\) 与 \(\log{LR^\*}\) 建模为模型规模、TPP 或其他特征（如对数步数）的函数。通过模型选择，我们发现 \(LR^\* \times WD^\*\) 主要取决于训练步数，而 \(\log{LR^\*}\) 还额外取决于 \(\log{TPP}\)。\(LR^\* \times WD^\*\) 相对步数的经验指数非常接近 −1，这与"解耦的权重衰减时间尺度（\(\dfrac{1}{LR \times WD}\)）应当是训练时长的固定比例"这一观点相符。LR 相对步数的经验指数接近 −0.5，这与广为使用的经验法则一致：批次大小加倍时，学习率应乘以 \(\sqrt{2}\)。我们最终得到的 \(LR^\*\) 与 \(WD^\*\) 缩放定律为：

\[LR^\* \times WD^\* = 17.04 / \text{steps}\] \[\log{LR^\*} = -1.51 + 0.175\log{\text{TPP}} - 0.573\log{\text{steps}}\]

采用类似方法，我们还推导出如下 dropout 缩放定律：

\[\small \mathrm{Dropout}=\operatorname{sigmoid}\big(0.526\,(\log \mathrm{ActiveParams}-27.2)\big)\]

我们在小规模实验中估计出这些新的缩放定律，然后在中等规模上加以验证——在该规模下，它们的表现持续优于以往的经验法则。这些定律确定了 MAI-Base-2 的超参数。

## **基础设施与 MAI-Base-2 的协同设计**

在算力预算内训练前沿模型，需要围绕评测质量与计算效率对模型和基础设施进行协同设计。我们使用效率增益（efficiency gain，EG）指标来辅助决策：即候选方案为达到与基线相同的评测损失所需算力的比值。算力可以按 FLOPs 度量（EGFLOPs），也可以按挂钟时间度量（EGtime），二者互为补充。我们主要依赖 EGtime，因为它反映我们基础设施的当前状态。EGFLOPs 则衡量原型的潜力，并指导未来的基础设施建设：一个在 FLOPs 上占优但在挂钟时间上落败的改动，会告诉我们该往哪里投入。建模与基础设施的这种联合优化体现在下文的若干设计选择中。

## **扩展 MoE**

我们过去的建模实验表明，每一层都使用 MoE 相比稠密 FFN 层与 MoE 层交替排布具有一致的 EGFLOPs 优势。然而，由于我们的 MoE 实现存在低效环节，对 MAI-Base-1 而言每隔一层使用 MoE 才是 EGtime 最优的。针对 MAI-Base-2，我们找出了导致 MoE MFU 不理想的两处低效：

1. 动态路由加剧了内存碎片化，并为罕见、极端的专家负载不均占用更多内存，而这些内存本可用于减少激活重计算。
2. 增加更多、粒度更细的专家抬高了单专家开销。

解决这些低效问题后，我们 MoE 层的 MFU 从 24% 提升到 35%，这使 MAI-Base-2 能够在每一层都采用 MoE。

***具有可调、固定大小内存占用的无丢弃 MoE***

在 MoE 层中，每个专家接收的 token 数量是可变的。这带来了 GPU 内存方面的挑战：过载的专家可能耗尽内存。一种解决方案是为每个专家设置固定阈值，超出的 token 被丢弃。我们的实验发现，丢弃 token 会导致性能变差。朴素的做法是干脆为每个专家分配足以应对最大不均衡的内存，但这在正常负载下会导致内存使用低效。如图 6 所示，我们的多轮无丢弃 MoE 在任意路由不均衡下都能实现固定的内存占用，从而消除碎片化和内存溢出崩溃。

我们把每个专家并行 rank 上的专家划分成一个或多个大小可配置的组。每个专家组以固定的单专家 token 容量执行一轮或多轮 *dispatch → compute → collect*。如果某个专家接收到的 token 超出其容量，专家组会在额外的轮次中处理这些溢出 token。为减少额外轮次，我们允许过载专家使用同组内其他专家未被占用的 token 容量。在反向传播中，我们按照类似的多轮调度对每个专家组执行细粒度重计算。这样无论 token 分布如何不均，内存占用都保持不变。token 容量是可配置的：容量更大意味着内存更多，容量更小则意味着可能的轮次更多、计算量更大。实践中，容量被配置为在稳定状态下维持单轮运行。

*Dispatch*、*compute* 与 *collect* 在所有专家组的所有轮次之间做流水线化，使得除第一个 *dispatch* 和最后一个 *collect* 之外的所有阶段都与专家计算重叠。在前向传播中，权重量化与共享专家计算同暴露的通信重叠。在反向传播中，所有专家通信都被完全重叠：暴露的输入 *dispatch* 与同一层的重计算重叠，暴露的梯度 *collect* 与权重梯度计算重叠。

***降低单专家开销***

我们通过四种方式降低单专家开销。第一，通过对每个专家组的计算与通信进行分组，提高 GEMM 与 NVLink 效率，从而减少 kernel 启动开销和尾效应。第二，使用驻留在设备上的 token 元数据并直接从 GPU 发起 all-to-all 通信，以减少主机-设备同步。第三，利用对称内存进一步优化 all-to-all，直接通过 NVLink 交换 token 而无需中转拷贝，提高通信吞吐量，并降低并发执行 GEMM 时的 HBM 争用。最后，我们跨层批处理负载均衡损失，用一次覆盖所有层的批量归约取代逐层 all-reduce。这些优化使我们能够训练更稀疏的模型而不显著降低 MFU。

## **扩展 Muon**

在扩展到 MAI-Base-2 时，我们发现 Muon 相比 AdamW 带来了更稳定的训练动态和显著的效率增益。要在我们最大的模型中采用 Muon，需要降低其每步开销。

Muon 用 Newton–Schulz 对每个权重矩阵的动量做正交化，这是一个由若干次矩阵乘法组成的迭代算法。这要求完整的矩阵，与 ZeRO 沿数据并行维度对动量分片的做法相冲突。沿袭先前的工作，我们在优化器步骤中对动量重新分片。每块 GPU 更新其本地的 FP32 动量分片并转换为 BF16。随后，一次按相同形状参数批量进行的 all-to-all 交换，使每块 GPU 拥有若干完整动量矩阵的所有权。每块 GPU 在本地用对称感知的 Newton–Schulz kernel 对其完整动量矩阵做正交化。第二次 all-to-all 把更新送回各自的原分片，再转换回 FP32 并应用于权重。

我们进一步应用了若干有益于 16K GPU 训练效率的优化：

- 通过预取多个批次来重叠通信与计算。
- 缓存并复用重分片元数据，避免重复的索引逻辑。这在拥有数千个相同形状参数的稀疏 MoE 模型中尤其有用。
- 部分选定的权重（例如 MoE 路由器权重）在 GPU 间复制而非分片。此时会跳过第一个通信阶段，改为在 Newton-Schulz 之后发起一次 all-gather 集合通信，以获得完整的复制更新集合。

优化之后，Muon 占 MAI-Base-2 平均训练迭代时间的 2.1%（165 ms）。我们借助大规模与小规模测试环境跟踪实现质量，并依据性能剖析结果确定改动的优先级。我们把测试测得的数据与理论峰值性能进行比较——对于 MAI-Base-2 的最终训练配置，我们估计理论峰值为 55 ms，瓶颈在通信。我们把理论与实测性能之间的差距归因于慢节点、kernel 分发开销、负载不均以及重分片期间的内存拷贝/分配。

## **激活梯度裁剪**

梯度裁剪是稳定训练的常用方法，通过削弱离群梯度的影响来实现。标准梯度裁剪作用于整个批次权重梯度的全局范数。然而，离群梯度通常由批次内一小部分数据引起。因此，一个离群样本可能导致整个批次的梯度被缩小，其中包括本来表现良好的样本的贡献。作为一种更有针对性的缓解手段，我们在网络中选定的位置对激活的梯度进行裁剪。与 Muon 配合，这使得 MAI-Base-2 的梯度范数保持在比 MAI-Base-1 紧得多的范围内（图 7）。

激活梯度裁剪还让优化更加稳定，且其收益随规模增长而扩大，如图 8 所示。相比之下，我们测试过的大多数改动在各规模上带来的效率增益大致恒定。

我们还把激活梯度裁剪用作验证训练数据的诊断工具。图 9 展示了一个被激活梯度裁剪识别出的畸形训练样本。在我们的代码数据的一个 pull request 中，一段许可证头部在一句话中间被突然截断。回溯这个被裁剪的样本，我们发现预处理流水线中的一个 bug，目前已修复。

## **数据规模化**

MAI-Base-2 沿用了与 MAI-Base-1 相同的数据原则：我们通往前沿性能的路径建立在有机数据之上，而非对其他模型的蒸馏。对自有数据流水线的持续投入不断带来回报，我们在内部处理了每一个训练 token。以去重训练 token 计，我们的语料库从 MAI-Base-1 到 MAI-Base-2 增长了约 36%（见图 10）。

自 MAI-Thinking-1 以来，我们改进了质量分类、主题分桶、网页解析、去重和评测去污染。针对 MAI-Base-2，我们扩展了流水线以处理多得多的网页内容1，知识截止时间为 2026 年 3 月。我们还使用基于嵌入的多样性采样来优先纳入新数据、减少重复内容。我们的实验表明，这些方法显著提升了模型性能。

与 MAI-Base-1 不同，MAI-Base-2 采用无编码器的 VLM 架构，原生融合视觉进行预训练。为此，我们大力投入扩展 VLM 语料库，涵盖图文对以及文本与图像交错的文档。语料覆盖的任务包括网页图像描述生成、图表理解、视觉定位、空间推理、医学理解、计算机使用、乐谱阅读，以及其他我们预计用户会觉得有用的领域。我们的 VLM 语料包含 4.5T 去重 token；计入重复后，VLM 数据在 50T token 训练混合中占 18%。

## **接下来**

MAI-Base-2 是我们下一代模型的基石，我们很期待很快分享更多相关内容。在 MAI-Base-2 进行后训练的同时，MAI-Base-3 的准备工作已经启动。我们所有的模型都遵循自 MAI-Base-1 以来一直指引我们的相同原则：

- 智能应当从第一性原理中学习。
- 简单的方法最具扩展性。
- 科学严谨高于捷径。

我们坚信，这些原则将带领我们持续向前沿迈进。训练前沿 AI 需要建模、数据和基础设施领域的研究人员与工程师像一个团队一样协作。如果你对此心向往之，[欢迎加入我们](https://microsoft.ai/careers/)！
