# 第 2 周：编程基础

课堂议程

- 课时：9 月 28 日与 30 日，上午 10:30–11:50
- 主讲：Shurui Liu 与 Fred Rajasekaran

## 课前准备

- 安装 ChatGPT 桌面应用和 Visual Studio Code（VS Code）。
- 创建一个 GitHub 账号，并确认你能够登录。
- Windows 用户：按照 WSL 安装指南操作。
- 在第 2 天上课前，确认你可以使用 SUNet ID 和斯坦福两步验证（Stanford two-step authentication）访问 FarmShare。参见 Getting Connected。

## 第 1 天：从编程智能体到 GitHub 仓库

9 月 28 日，星期一 · 80 分钟

目标：用一个编程智能体构建一个小程序，理解它的工作原理，并用 Git 和 GitHub 对其进行跟踪与分享。

| 时间 | 活动 |
| --- | --- |
| 0–5 分钟 | 热身与设置。完成上述准备工作，并解决初始配置问题。 |
| 5–10 分钟 | 什么是编程智能体？讨论智能体如何读取、编辑和运行代码，以及人工审查在其中处于什么位置。 |
| 10–20 分钟 | 设置一个编程智能体。安装一个桌面智能体，选择一个模型，并熟悉其界面。有经验的参与者可以使用自己惯用的工具。 |
| 20–30 分钟 | 第一个项目。创建项目文件夹。让 Codex 实现一个素数筛和一个素数计数函数，然后解释这段代码。检验几个小例子，并生成一张图，第 2 天会复用。 |
| 30–35 分钟 | 讨论。哪里出了问题？你是怎么检查输出的？智能体的解释澄清了什么？ |
| 35–55 分钟 | 终端与 Git 现场演示。Shurui 在一位志愿者的笔记本电脑上完整走一遍工作流，从一个全新的项目文件夹开始。练习导航、创建仓库、提交（commit）以及推送到 GitHub。 |
| 55–80 分钟 | 命令行智能体与 LaTeX。安装 Codex 或 Claude Code CLI，并讨论为什么 CLI 在远程服务器上很有用。用一个可公开访问的项目演示 Overleaf–Git 工作流，然后让智能体针对笔误或数学错误提出修改建议。审查它的建议。 |

### 终端与 Git 主题

- 用 `cd` 导航、用 `ls -alh` 查看文件；介绍 `apt` 和 Homebrew 等包管理器。
- 练习 `git init`、`git add`、`git rm`、`git commit`、`git status` 和 `git log`。
- 讲解 `git fetch`、`git merge`、`git pull` 和 `git push`。pull 会拉取远程更改，并按照仓库的配置将其整合进来。
- 审查更改后要有意识地提交。解释为什么强制推送（force-push）可能覆盖共享历史。

**第 1 天检查点**：创建一个本地仓库和一个私有 GitHub 仓库；推送筛法代码；亲手写一个简短的 `README.md`，然后提交并推送。

## 第 2 天：在斯坦福 FarmShare 上运行代码

9 月 30 日，星期三 · 80 分钟

目标：连接到一台远程机器，在机器之间搬运代码和结果，并理解什么时候应使用调度提交的计算作业。

| 时间 | 活动 |
| --- | --- |
| 0–5 分钟 | 热身与讨论。有哪些计算资源可用？什么时候一台笔记本电脑就够用了？ |
| 5–15 分钟 | 用 SSH 连接。登录 FarmShare，辨认远程机器和当前目录，并区分远程 shell 与本地 shell。 |
| 15–30 分钟 | 用 SCP 传输文件。把一个练习文件从笔记本电脑复制到 FarmShare，验证传输成功，然后只删除那份练习副本。 |
| 30–45 分钟 | 用 Git 克隆项目。设置 GitHub 认证，并在 FarmShare 上克隆那个私有仓库。不要把凭据放进仓库里。 |
| 45–55 分钟 | 运行筛法。跑一个小而快的例子并检查输出。讨论共享系统上的文件权限、隐私，以及 CPU 和内存的使用。 |
| 55–65 分钟 | 把结果带回来。把生成的图从 FarmShare 复制回笔记本电脑，并在本地打开。 |
| 65–70 分钟 | Slurm 入门。讲解登录节点与计算节点的区别，并演示提交一个小型批处理作业。用 `top` 或 `htop` 查看资源使用情况。 |
| 70–80 分钟 | 故障排查与可选工具。解决配置问题。如果时间允许，介绍 FarmShare 上的 `tmux`、Python 3、`uv` 或某个 CLI 智能体，包括内存占用、设备认证和登出。 |

**在哪里运行代码**：在登录节点上的工作要保持简短，并遵守共享资源限额。长时间运行或 CPU/内存密集的计算应使用 Slurm 作业。参见 FarmShare 概览与 Running Jobs。

**第 2 天检查点**：在 FarmShare 上克隆并运行你的项目，取回一张图，并说明你会如何通过 Slurm 提交一个更大规模的计算。

## 练习

1. 提出一个项目。想一个你真正想用的软件项目。在课程 Slack 里发一段简短描述，包括它的目的和一个可以实现的第一阶段里程碑。
2. 用智能体探索一个代码库。选择一个仓库，阅读它的 `README.md`，克隆它，并让智能体解释它的结构和预期工作流。总结其主要组件、所需依赖，以及你现在已理解的某一部分代码。例子包括 `rethlas` 或 `danus` 这类数学推理智能体，或 `deepseek-harness`、`opencode` 这类编程智能体项目。想要更大的挑战，可以探索 Mathlib（需配 Lean 工具链）或 `verl`（需装其强化学习依赖）。
